# PIDs

So we now have a target for what the quadcopter to do, and 06 an input for what it's doing, some motors to close the gap between the two; all we need is a way to join these together. A direct mathematical algorithm is nigh on impossible – accurate weight of the quadcopter, power per rotation of each blade, weight imbalance etc would need to be incorporated into the equation. And none of these factors are stable during flight (and crashes), subtracts the weight of the copter, humidity and moisture would need to be accounted for. Hopefully this approach simply won't fail.

Instead, an estimation method is used with feedback from the sensors to tune that estimate. Because the estimation/feedback code loop runs every 100 times a second, this approach to errors very quickly indeed, and it knows nothing about all the factors it is compensating for - that's all handled blindly by the feedback; this is the PID algorithm. It takes the target, subtracts the feedback, resulting in the error. The error is processed via a Proportional, Integral and a Differential algorithm to produce the output.

These ESC-specific outputs are converted to a PWM signal to feed the hardware ESCs with the updated propeller/motor speeds

Although the article focuses on a very basic background in the hardware it is necessary to provide context. A quadcopter points upwards (hence the name) with each attached to its own brushless DC motor arranged square. Two motors spin clockwise, two counter-clockwise to minimize the momentum of the quadcopter.

Each motor is driven by an electronic speed controller (ESC). The quadcopter has four sets of coils (phased, clockwise and counter-clockwise) with PWM control from the software. High-current output drives the motors at a speed that matches the signal.
