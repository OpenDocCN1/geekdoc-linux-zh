# Interpreter

# Axes

01 The command interpreter converts a series of commands from radio or programmed into the code. The commands combine the direction and speed compared to the horizon the user wants the quadcopter to follow. The code converts these into a series of targets for speed, horizontal speed and yaw speed – any command from the joysticks can be broken down into one set of targets.

02 The inputs to the quadcopter come from a series of electronic sensors providing information about its movement in the air. The main two are accelerometer measures acceleration (gravity) in the three axes, and gyroscope measures the angular speed with which quadcopter is pitching (nose/tail up), rolling (left/right) and yawing (spinning clockwise and anticclockwise around the central axis of quadcopter).

03 The accelerometer is relative to the orientation of quadcopter axes, the targets are relative to the Earth's axes – the horizon and gravity. To convert the output between the quadcopter axes and the Earth requires a use of trigonometry. You also need to know the roll and pitch angles of the quadcopter with respect to the Earth. It's pretty complicated stuff, but the diagrams on these pages help you understand the logic.

04 Both the accelerometer and gyro can provide this angle information, but both have flaws. The accelerometer output can be used to calculate the angle using the Euler algorithm. However, the accelerometer output is plagued by noise from the motors/propellers, meaning a single reading can be huge on the side, the average reading remains inaccurate over time. In contrast, the gyro-output does not suffer from the noise, but since it is an angular sensor it needs to be integrated over time to find the absolute angle of the quadcopter in comparison to the horizon. Rounding errors lead to ever increasing errors over time, ultimately limiting the maximum length of flight.

Filter

05 Although they are both flawed, they can be merged mathematically that each compensates for the flaws resulting in a noise-free, long-term accurate reading. There are many versions of these mathematical noise/drift filters. The best common one is Kalman: which is slightly less accurate but easier to understand and refine. With an angle in hand it is possible to convert sensor data to inputs relative to the Earth's axes and work out how the quadcopter is moving up, down, left, right and forwards and backwards compared to the targets that have been set.

# PIDs

So we now have a target for what the quadcopter to do, and 06 an input for what it's doing, some motors to close the gap between the two; all we need is a way to join these together. A direct mathematical algorithm is nigh on impossible – accurate weight of the quadcopter, power per rotation of each blade, weight imbalance etc would need to be incorporated into the equation. And none of these factors are stable during flight (and crashes), subtract the weight of the copter, humidity and moisture would need to be accounted for. Hopefully this approach simply won't fail.

Instead, an estimation method is used with feedback from the sensors to tune that estimate. Because the estimation/feedback code loop runs every 100 times a second, this approach to errors quickly indeed, and it knows nothing about all the factors it is compensating for - that's all handled blindly by the feedback; this is the PID algorithm. It takes the target, subtracts the feedback, resulting in the error. The error is processed via a Proportional, Integral and a Differential algorithm to produce the output.

# Understanding quadcopters...

# Blender

07 The outputs are assigned to each ESC in turn: the vertical speed is applied the pitch rate is split 50/50 subtracting from the front blades and adding to the back, producing the pitch. Roll is handled randomly. Yaw was also in a simple way, but applied to diagonal blades which spin in the same direction.

These ESC-specific outputs are converted to a PWM signal to feed the hardware ESCs with the updated propeller/motor speeds

Although the article focuses on a very basic background in the hardware it is necessary to provide context. A quadcopter points upwards (hence the name) with each attached to its own brushless DC motor arranged square. Two motors spin clockwise, two counter-clockwise to minimize the momentum of the quadcopter.

Each motor is driven by an electronic speed controller (ESC). The quadcopter has four sets of coils (phased, clockwise and counter-clockwise) with PWM control from the software. High-current output drives the motors at a speed that matches the signal.
