In this instance, the script dopppp (made executable with chmod +x ) would contain the following:

```
exec /usr/sbin/pppd -detach
```

Using this approach, pppd will start automatically after the ppp dial-in you connects and logs in (using the ppp-on scripts or other clients, such as netcfg or kpppp).

You can also edit the file options over the /etc/ppp directory to include general dial-in options for PPP service on your system and create specific options files (such as options.tty8 for this example) for each enabled dial-in port. For example, /etc/ppp/ options could contain

```
asyncmap 0
netmask 255.255.255.0
proxyarp
lock
crtscts
modem
```

The asyncmap, lock, crtscts, and modem values are enabled in the default SuSE Linux options file. The other values, netmask and proxyarp, are present but must be uncommented by removing a leading pound (#) sign.

There are many approaches to providing PPP service. You may want to assign IP addresses dynamically or assign static IP addresses for your user. You should probably have DNS enabled, allowing hostname names via /etc/hosts and providing static address assignment by using options.ttyX (where X is the serial port). You might the getty command to handle remote logins for example, /etc/ppp/options.tty8 could contain

```
IPofPPPserver:assignedIPofdialinuser
```

After you set up /etc/ppp/options and /etc/ppp/options.ttyS, dial from a remote computer (perhaps using wdial or the ppp-on script). If your chat script uses pppd's debug option, you can track the progress of your connection using the tail command on /var/log/messages:
