# Networking and Internet Services
PART II

| Option | Function |
|---|---|
| -c count | Only sends count number of packets instead of pinging forever. displays numeric addresses instead of hostnames. Useful when you can't get to the DNS server or when DNS queries take too long. |
| -r | Record route. Sends an option in every packet that instructs every host from the source and the target to store their IP address in the packet. This way you can see which hosts a packet is going through. However, the packet size is limited to nine hops. Besides, systems disregard this option. Because of this, it is better to use traceroute. |
| -q | Quiet output. Outputs just the final statistics. |
| -v | Verbose. Displays all packets received, not just ping responses.

When troubleshooting network problems, you should first ping the IP address of the source itself. This verifies that the originating network interface is set up correctly. After that, you should try pinging your default gateway, your default gateway's gateway (the next hop out), and until you reach the destination. That way you can easily isolate where a problem lies. However, once you've verified that you can get to the default gateway, it is better to use the traceroute program (which is described in "traceroute,") to automate the process.

> Note
All TCP/IP packets have a field called Time-To-Live, or TTL. This field is decremented once by each router on a network. The packet is discarded the moment it reaches e. While ping uses a default TTL of 255 (the maximum value), many programs such as telnet and ftp use a smaller TTL (usually 30 or 68). That means that you might be able to ping a host, but not telnet or FTP into it. You may use the -t ttl option to ping to set the TTL of the packets it outputs.

# traceroute

The traceroute program is the workhorse of TCP/IP troubleshooting. It sends UDP packets with progressively larger TTLs and detects the ICMP responses sent by gateways when they drop the packets. In the end, this maps out the route a packet takes when going from the source host to the target host.
