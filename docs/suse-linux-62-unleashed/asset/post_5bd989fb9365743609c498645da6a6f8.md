
## Changes to mtx

Add the following zones to /etc/named.conf on server mtx:

```conf
zone "42.168.192.in-addr.arpa" {
    type slave;
    file "slave.192.168.42";
    masters {192.168.42.1};
}
nzone "domain.cxm" {
    type slave;
    file "slave.domain.cxm";
    masters {192.168.42.1};
};
```

On each one, the statement names the file in which to write data obtained from the master and which to answer queries. `masters {192.168.42.1};` statement (and exactly) tells named to acquire data from 192.168.42.1 whenever the refresh time is exceeded or whenever it hits with a NOTIFY 192.168.42.1, whichever comes first. The `type slave` statement that this zone is allowed to do zone transfers to obtain the data from 192.168.42.1.

Notice that the files start with the word slave instead of master. This convention allows the administrator to refresh all slave zones with a master restart command. Unlike the master zone, these slave data files are not maintained and can be regenerated by the server. This conflict with deleting a master's data would be disastrous. Of course, if the master is down, deleting the slave zone would be equally disastrous, so take care before you delete any slave file.

After the slave zones have been added, simply restart the master with the command:

```bash
/sbin/init.d/named restart
```

The named daemon will create the slave data files, and will act as a slave server except for receiving NOTIFY statements (the master doesn't know about this slave). So it's perfectly possible to set up a slave without the master knowing it. Due to the extra traffic placed on the master, this is not proper DNS. The administrator of the master should be informed of all slaves.

The master can defend itself against unauthorized slaves by limiting the servers that can receive zone transfers. Just put one of the following statements in named.conf's section, or in the global section:

```conf
allow-transfer {192.168.42.2};  # only mtx can be slave
```

or

```conf
allow-transfer {192.168.42.2; 192.168.42.1};  # both
```

or

```conf
allow-transfer {192.168.42.0/24};  # only hosts on subnet
```

Verify the existence of files /var/named/domain.cxm and /var/named/slave.192.168.42. If they exist, verify that the following list of commands gives the expected output:

```bash
nslookup numark 192.168.42.2
nslookup mtx 192.168.42.2
nslookup numark.domain.cxm 192.168.42.2
nslookup domain.cxm 192.168.42.2
nslookup 192.168.42.1 192.168.42.2
nslookup 192.168.42.2 192.168.42.2
```
