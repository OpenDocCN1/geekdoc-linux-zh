# SuSE init, Startup, and Shutdown Scripts

The yast command is designed to insulate you from what is going on under the hood. But
You should have awareness of what is really happening—even if you do not tamper
it with yourself. In Chapter 2, “Installing SuSE Linux,”you learned how to install Linux,
and Chapter 3, “Boot Management,”you found out how to install and use different
loaders for different computers.

A number of ways exist to start Linux with different computers, and there are different
ways to load the Linux kernel. Intel users will most likely use LILO, LOLOAD,
SYSLUX, BOOTLIN, or commercial alternatives, as System Commander or
BootMagic. SPARC users will use SILO, and Alpha users will probably use MILO.

PCs start by loading the first sector of the first cylinder of the boot drive and then trying
to load and execute code found (there is one which LILO can run, as explained in
Chapter 3). This is also the case with other (but not all) hardware systems and versions of
UNIX. You should be able to set the order in which your PC looks for the boot drive,
usually through a BIOS change in a setup menu you can invoke when you first turn on the
machine (usually accomplished by pressing F1, F2, or en DEL). Setting the order can be
handy if you never use a boot floppy disk; for example, laptop users with an external
floppy drive can speed up the boot process by connecting the computer to look first at the
in hard drive or CD-ROM.

You can also start Linux over a network and run a diskless Linux box. For more
information on how to do this, see Nemkin’s Diskless Linux mini-HOWTO, under
/usr/doc/howto/en/mini. Although Linux shares many similar traits with both System V
and BSD UNIX, Linux is closer to the former in the case of booting and starting the
system. This means Linux uses the init command and a similar directory structure of
associated scripts to start running the system and loading processes.
