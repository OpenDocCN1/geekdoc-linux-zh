Unfortunately, SIOG doesn't tell you which numbers correspond to sections of code. Instead, the author suggests keeping such documentation current is a lot of work (which it is), and you should look at the code to discover the correct debugging formulas.

The function tTd() is the one to look for. For example, suppose you want to turn on debugging in sendmail's address-parsing code. The source file parseaddr.c contains most of this code, and the following command finds the allowable debugging levels:

```
$ egrep tTd parseaddr.c
if (tTd(20, 1))
[...
if (tTd(24, 4))
if (tTd(22, 11))
```

[etc.].nThe egrep output shows that debugging specifications such as -d20.1, -d24.4, and d22.11 (others) will make sense to sendmail.

If perusing thousands of lines of C code doesn't appear to you, the O'Reilly book sendmail 2nd Ed., documents the debugging flags for sendmail. Note the book only carries up to sendmail-8.8; small differences in detail could exist but it is still a good reference.

The -c option enables you to test new configuration files before you install them, which is always a good idea. If you want to test a different file, use -C/path/to/the/file. You can combine it with the -bt and -d flags. For an example, a common invocation for testing new configuration files is

```
/usr/sbin/sendmail -Ctest.cf -bt -d21.12
```

> Caution
For security, sendmail drops its superuser permissions when you use the -c option. You should perform final testing of configuration files as the superuser to ensure your testing is compatible with sendmail's normal operating mode.
