# Note

The localhost, loopback, and dummy interface all refer to the use of the IP address 127.0.0.1 to refer to the local machine. The term loopback interface indicates that to the networking drivers, it looks as though the machine is talking to a network that consists of only one machine. In internal terms, the kernel sends network traffic out the port and back to another on the same machine. Dummy interface indicates that the interface doesn't really exist to the outside world, only to the local machine.

127.0.0.1 is a special IP address reserved for the local machines on all networks. Every networked Linux machine has this IP for its localhost. If you display the contents of your /etc/hosts file and this line already exists, the dummy interface is set up for you and you can skip this section. If the /etc/hosts file doesn't exist or this line is not in the file, you have to set up the interface yourself. If your machine has an IP address other than 127.0.0.1 in your /etc/hosts file, and the interface 127.0.0.1 is not there, you do not have the localhost interface set up.

# Note

When you installed SuSE Linux, you may have chosen to install and support networking. If you did, the dummy interface was probably set up. To create the dummy interface, your Linux system needs the networking software installed. The installation happens automatically with boot images even if the network interfaces are not configured. Begin the dummy interface setup by editing (or creating) the /etc/hosts file, and add the following line:

```
127.0.0.1 localhost
```

The number of spaces between the IP address and the name does not matter, as long as there is at least one space between the parts of the dotted-quad notation.

# Networking and Internet Services
PART II

If you already have an IP address in /etc/hosts file for your local machine but no localhost entry with this IP address, you still need to add this line. After updating the /etc/hosts file, you need to tell TCP/IP about the new interface. To set up the dummy interface, use the following commands when you are logged in as root:

```
# ifconfig 127.0.0.1
# route add 127.0.0.1 lo
```

The dummy command and a sample output keep the following:

```
# ifconfig lo
lo encap:Loopback
inet:127.0.0.1 Mask:255.0.0.0
UP MTU:1524 Metric:1
RX packets:0 dropped:0 frame:0
TX packets:0 dropped:0 carrier:0
collisions:0 txqueuel:0
```

The first command tells the system to add an interface called localhost (lo) with an IP address of 127.0.0.1. The second command adds the IP address 127.0.0.1 to internal table that keeps track of routes to different addresses. After you have issued these two commands, the dummy interface should be created and ready to use. To test the dummy interface, use the ifconfig command with the name of the interface (lo) to get statistics about the interface (or just use ifconfig to see all interfaces). This output shows that the localhost is active and running, that it has assigned the IP address 127.0.0.1, and the broadcast mask of 255.0.0.0 is used, and that the interface hasn't had much traffic. Don't worry about the errors in the last couple lines: you haven't used the interface yet, so there are no meaningful available. As a check that your kernel knows about the interface and your machine responds to the IP address 127.0.0.1 and the name localhost (defined in your system's /etc/hosts file), you can use the ping command to check that the interface is responding properly:

```
# ping localhost
PING localhost (127.0.0.1): 56 data bytes
64 bytes from 127.0.0.1: icmp_seq=0 ttl=255 time=0.304 ms
64 bytes from 127.0.0.1: icmp_seq=1 ttl=255 time=0.200 ms
64 bytes from 127.0.0.1: icmp_seq=2 ttl=255 time=0.191 ms
64 bytes from 127.0.0.1: icmp_seq=4 ttl=255 time=0.195 ms
64 bytes from 127.0.0.1: icmp_seq=5 ttl=255 time=0.191 ms
--- localhost statistics ---
6 packets transmitted, 6 packets received, 0% packet loss
round-trip min/avg/max = 0.191/0.212/0.304 ms
```

To stop the output from the ping command, press Ctrl+C (or you can limit the number of iterations with -c or count option, followed by a number, such as 6). You should get similar results using either the name localhost or the IP address 127.0.0.1 (because they both refer to the exact same interface according to the /etc/hosts file).

If you get the following message, the interface is not set up properly and you should check the /etc/hosts file and the ifconfig command to make sure you installed the interface properly:

```
# ping host
unknown host
```

Repeating the installation steps should correct the problem. After you complete those simple steps and tests, the dummy interface is ready to be used by your system, applications, and by PPP and SLIP.

# Setting Up PPP

Most ISPs today use PPP instead of SLIP. PPP is good for you because PPP is a faster and more efficient protocol. PPP and SLIP are both designed for two-way networking; in other words, your machine talking to one other machine—usually ISP—and no other machines at the time (although it is possible to communicate with computers on your internal network). PPP is not a replacement for a LAN protocol such as TCP/IP, but PPP can coexist with TCP/IP (which provides a transport protocol for data).

One of the major hurdles Linux users face is setting up PPP and connecting to the Internet. If you're new to Linux, you don't have to understand the intricacies of the protocol to use PPP, and setting PPP on your system is not as scary as you might. You can set up PPP manually from the command line or by using scripts. Both approaches produce the same results. PPP uses two components on your system. The first is a daemon called pppd, which controls the use of PPP. The second is a driver called the high-level data control (HDLC), which controls the flow of information between two machines. A third component of PPP is a routine called chat, which dials the other end of the connection.

# Installing PPP

PPP was most likely installed when you installed SuSE Linux. If it wasn't, you need to load the package before you can configure the system for PPP use. The PPP library and files are included with practically every CD-ROM distribution of Linux, and you can obtain the most recent versions from the usual Linux and FTP sites.

If some reason PPP is not installed on your system, use the yum command to install the PPP package.

# Setting Up PPP Using the PPP Scripts

PPP support for Linux is found in the form of loadable kernel modules named syncpp. These modules are located under the /lib/modules/2.2.10/net directory and will be loaded automatically when needed.

The chat program, found under the /usr/sbin binary, is part of the ppp daemon software package. The chat utility takes a lot of its features from the UCCP program, which makes it familiar for many veteran system administrators. The chat utility requires a command line that tells it what to connect to your ISP and what types of line responses are required. All of this information is usually placed on a single-line chat script. These lines are often stored in files to prevent you from having to type the commands every time you want to access the Internet. The chat program is used during the dialing process to dial out and connect to your ISPs modem. For example,

+   * ATZ OK ATDT2370400 CONNECT ** ogin: ppp word: guessme
