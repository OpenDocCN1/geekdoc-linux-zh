# Security

The second thing we want to discuss is how file permissions get translated between Windows and Samba. Under Windows NT, you must have a username and password to log in the machine. When you create files on an NTFS-based system, the files are owned and accessible by you and no other user. Under Windows 95 and 98, although you may type in a username and password on startup (the Microsoft Windows Networking dialog box appears), files on the local hard drive can be modified by anyone. There are clearly vast differences among Windows products when it comes to security; but how does Samba handle security?

Under Samba, there are different security levels, but the one we will focus on in this chapter is called "user-level" security and the one that Samba uses by default. When a Samba machine is using user-level security, it will require a valid username and password to access a particular share. Samba shares can be "locked down" to only allow certain users; this can be handy when using Samba to export home directories and prevent "locked out" users from accessing a particular share—even if they supply a valid username and password.

The username and password that you type into the Windows Networking dialog box (or the Windows Login dialog box under NT) will be used by Windows to attempt to gain access to a Samba share. This will happen automatically without requiring you to type this username and password again. If, however, access is denied by the Samba server, Windows will prompt you to enter a username and password for the share. Keep this in mind as you test your initial Samba configuration.

# File Permissions and User Accounts

Let's say that you log in to a Windows NT as drobbins, beginning access a Samba share, and create a few files. You may wonder what UNIX permissions Samba assigns to these files—after all, because Samba resides on a UNIX file system, each file must have a default user ID and group ID. The answer is that Samba requires that you have Linux users that correspond exactly to the usernames on your Windows machines. This means that in effect, Samba will expect to find the username drobbins in the /etc/passwd file. Linux user. Keep is this in when configuring Samba, and remember that if you are accessing shares from NT, you will most likely need a Linux administrator account entered in /etc/passwd for the permissions to work properly. And all Samba systems will need to have an account in /etc/passwd called guest. Why don't take some time now to add the required user accounts to your system, if they do not already exist?
