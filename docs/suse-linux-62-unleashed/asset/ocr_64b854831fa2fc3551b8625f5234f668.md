# Networking and Internet Services
PART II

> Caution
> Using testparm is not a guarantee that the services specified in the configuration
file will be available or will operate as expected. This kind of testing guarantees
only that Samba is able to read and understand the configuration file.

testparm has the following command line:
testparm [configfile] [hostname]
configfile indicates the location of the smb.conf file if it is not in the default location
(etc/smb.conf). The hostnameIP optional will be unpredictable.

The following illustrates sample output from testparm. If there are any errors, the
program reports them, along with a specific error message:

```
[root@etc]# testparm smb.conf 209.42.203.236
Load smb config files from smb.conf
Processing section "[homes]"
Processing section "[printers]"
Loaded files OK.

Allow connection from ntackett (209.42.203.236) to homes
Allow connection from ntackett (209.42.203.236) to printers
Allow connection from ntackett (209.42.203.236) to lp
```

# Testing with smstatus

The smstatus program reports on current Samba connections. smstatus has the
command line:

smstatus [-d] [-p] [-s configfile]

configfile is by default /etc/smb.conf. -d provides verbose output, and -p provides a
list of current SMB processes. The -p option is useful if you are writing shell scripts using
smstatus. Following is sample output:

```
[root@linuxhost everyone]# smstatus

Samba version 2.0.3
Service uid gid pid machine

spec_dir myuid myuid 4381 p2300 (192.168.100.201)
- May 6 22: 18:31 1999
```
