The standard resource for all kernel issues is the linux-kernel mailing list, where luminaries such as Alan Cox and Linus Torvalds show remarkable patience in fielding kernel questions among the day-to-day business of building and improving Linux. You can find the linux-kernel archives and instructions on joining the list through de-mail.kernel.org Web site.

The final authority on the Linux kernel is the source itself. For many questions, you do not need to be highly proficient in kernel programming to go wandering through the kernel source tree. Programmers are a notorious lot being lax to produce formal documentation files, but to include README files and informative comment headers within their code directories. In the Linux sources, many video driver problems, SMP issues, and other topics that may vary rapidly are tracked in small text files in the driver directories. You have the source; don't be afraid to use it.

## Summary

Linux is the kernel, and the kernel is Linux. Linus Torvalds wrote that he never expected Linux to become the size of Emacs, but he is quick to point out that "at least Linux has the excuse that it needs to be." The development of this beast over the past eight years has been meteoric. We have probably left some broken hearts along the way, but the result of this experiment in community cooperation now stands as a major contender in the operating systems marketplace, and has cemented the worth of open source into the public psyche. While it may have been true that keeping up with the Linux kernel-of-the-day was akin to dancing with death, 2.2 has proven to be a worthy successor to 2.0, and the roller coaster of 2.1 has slowed to the steady whirl of 2.3.

As with Linux and X11 installation, configuring an optimal kernel does require planning, preparation, and some knowledge of the target machine to ensure an exact fit. Given the great improvement in Linux installation programs, it is not unreasonable to expect that today the Linux kernel will be largely self-configuring (IRIX has done this for years). Although kernel configuration is nowhere as frightening as it was even a year ago, for the foreseeable future it will still demand a certain amount of attention and a small measure of sysadmin savvy.

If you have made it far, you now know what the Linux kernel is and how it works. You know how to interpret and select from kernel version numbers and how to prepare for, select, and execute a new kernel configuration. You also learned the following:

- How to configure LILO for convenient installs and backups of prior kernels.
- How to recognize and recover from kernel configuration problems.
- How to obtain, install, and patch kernel sources.
- How to compile and install the kernel and modules in one command.
- How to build and install kernels for remote machines and tune the kernel for special purposes, such as routers, Web servers, or low-memory systems.
- How to modify the running kernel through the sys interface, and how to set module parameters through /etc/lilo.conf or /sbin/insmod.
- How to effect selective Y2K testing on a Linux machine.

Most importantly, I hope you have learned that building the Linux kernel is not a rite of passage or a task to be feared. Kernel building just takes some common sense, care, and attention, and it's yet another of the reasons you chose to run Linux in the first place.

This chapter shows you how to configure and use your printer with SuSE Linux. Many different programs, files, and directories are essential to supporting printing under Linux, but you'll find that with little effort, you will be able to get to print nicely formatted documents and graphics.

If you can print to your printer from DOS, Windows 98, or Windows NT, don't worry! Chances you'll be able to print under Linux, and you'll be pleasantly surprised by the capabilities.

Under Linux, each piece of your computer's hardware is abstracted to a device file. Some of these devices, traditionally named, are shown in Table 24.1.

| Device Name | Printer | Address |
| :--- | :--- | :--- |
| /dev/lp0 | First printer | ø278 |
| /dev/lp1 | Second printer | ø378 |
| /dev/lp2 | Third printer | ø3f |

Serial devices are assigned to /dev/tty, where X is a number from 0 to 3. In some special cases, such as using a LaserWriter, you must define an entry in your /printcap database. For example, here's a 10-year-old trick, posted to comp.laser, for increasing the port speed.

```postscript
%!
0000 % Server
statusid begin
25 scbatch 0 ne 19200 ne
server begin
pop end) ifelse
statusid begin
```

A PostScript printer is the best printer to use with Linux because many programs and text utilities used with Linux and other UNIX systems output graphics and text as PostScript. However, another great reason to use Linux, and SuSE's distribution of Linux, is that through the magic of software, your $129 inkjet printer can also print PostScript duments—even in color. That's a bargain!
