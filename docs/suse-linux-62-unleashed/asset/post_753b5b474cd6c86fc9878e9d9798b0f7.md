Other files in /proc/parport/x include the devices file where parport will record the attached devices and flag those currently using the port, as well as the irq file. irq can be used to query the IRQ number of the port and also to set this value by echoing either the number or "none" to that file.

To use parport, modules that require the parallel port can be given options to direct the module to a particular port. For example:

```bash
# insmod lp.0 parport=2
```

This will install the printer module on ports 0 and 2, rather than the default action of installing the module on all available ports. You can also do this by adding lp=parport,l1=parport2 to the boot prompt or in /etc/lilo.conf.

A common use of parport modules is to share a parallel port between several devices by dynamically inserting device support and then removing device before inserting the module for an alternate device. For example, you could share the printer port with a parallel port camera, a zip drive, or PLIP (parallel port-based network connection) by scripting each facility to first remove the other module before installing itself.

> In many instances, you can assign many modules to a parport simultaneously without needing to first remove the prior module. When conflicts occur, however, modules can be removed and inserted as needed.

# Advanced Power Management (APM) Support

Advanced Power Management (APM) does not power down hard drives or trigger "green" monitors to go into sleep mode. The Linux APM system is almost exclusively restricted to battery-powered computers such as laptops. Although APM is a very good idea in principle, there are many different interpretations of the standard among laptop manufacturers. As a result, APM support is a prime suspect when you're debugging laptop kernel problems. In doubt, turn off all APM options and enable each one after you've verified that it is either useful or benign.

# Watchdog Support

Detailed support for hardware-based watchdog systems is set further down, but the general options also allow for a software-based watchdog. With this option, the kernel will monitor and periodically update /dev/watchdog and will force a reboot if the updates fail to occur.

This can be useful for small ISPs and other applications where the machine may be unattended and must be rebooted if any crash occurs. This support is embedded in the kernel, so there's a slightly better chance that it will do its job even if all other processes have been halted or are being blocked. If you are using the software watchdog, you may also want to panic=60 as a boot argument (as in /etc/lilo.conf).

Alan Cox has included information on watchdog hardware manufacturers and source code for creating a software watchdog update program, which can be found in Documentation/watchdog.txt.

# Floppy Disk Driver

Because of its use for other devices (such as tape backup units) and its capability to run multiple disk controllers, the floppy disk driver is also be configured through boot commands by using the following options:

- floppy=daring for well-behaved (usually all-modern Pentium systems) controllers. This option allows for optimizations that can speed up floppy access, but may fail on incompatible systems.

- floppy=one_fdc tells the driver that only one controller is available. This is the default setting for the FDC driver.

- floppy=two_fdc or floppy=address,two_fdc tells the driver to use two controllers, with the second at the specified address. The default address is 0x370, or will be taken from CMOS memory if the cmos option is selected.

- floppy=think alerts the driver to the inverted convention for the disk change line that's used.

- floppy=nomad tells the kernel that no floppy controller is present, which is useful on systems without floppy drives.

# Enhanced IDE Support

Linux will support up to eight IDE drives. Many options for tuning the runtime performance of the IDE drives can be set using the hdparam utility. With Linux 2.1/2.2, support has also been added for IDE ATAPI floppy drives, tape drives, and CD-ROM drives with auto-detection of interfaces, IRQs, and disk geometries. The new driver also supports for PIO modes on OPTi chips, SCSI host adapter emulation, and PCI Busmaster DMA, as well as experimental support for many chipsets.

The driver also detects buggy PCI IDE systems, such as the prefect feature of the RZ1000 or "IRQ unmasking" on the CMD640. Full details of the IDE driver and supported systems can be found in linux/Documentation/ide.txt.
