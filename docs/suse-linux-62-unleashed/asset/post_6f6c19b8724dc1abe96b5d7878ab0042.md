## Starting the Daemons on Boot

To start the NIS server automatically at boot time, you need to create a symbolic link from the runlevel 3 startup directory. By default these are already created, but the following is how you would create them if needed:

```
[client@root#]# cd /sbin/init.d/rc3.d
[client@rc3.d]# ln -s ../ypmavers $15ypasswdd
```

The ypasswd daemon allows users from NIS clients to change their passwords on the NIS server. By default these are already created, but the following is how you would create them if needed:

```
[client@root#]# cd /sbin/init.d/rc3.d
[client@rc3.d]# ln -s ../bypasswdd $15ypasswdd
```

If you want to start the daemons by hand so you don't need to reboot, simply run the following:

```
[client@root#]# /sbin/init.d/ypserv start
[client@root#]# /sbin/init.d/bypasswd start
```

Now you have a NIS master server. Time to test the work with an NIS.

## Configuring an NIS Client

Compared to configuring NIS server, NIS clients are trivial. You must deal with only four files, one of which is only one line long.

Begin by editing the /etc/yp.conf file. The entries in this file are used for the initial binding. Use one of the following valid entries:

- - domain NISDOMAIN server HOSTNAME

Use server HOSTNAME for the domain NISDOMAIN. You could have more than one entry of this type for a single domain.

- - domain NISDOMAIN broadcast

Use broadcast on the local net for domain NISDOMAIN.

- - ypserver HOSTNAME

Use server HOSTNAME for the local domain. The IP address of the server must be listed in /etc/hosts.

The next step is to add the NIS name for boot time, which you've done for the NIS server by using YaST and setting the YP_DOMAIN. Make sure the domainname is the same as specified in the /etc/yp.conf file (in this case, audient.domain.com).

The last file that needs to be changed is /etc/nsswitch.conf. This is slightly more involved than the previous files; however, a default file comes with the Su installation. This file is used to configure which services are used to determine information such as hostnames, password files.

Begin by opening /etc/nsswitch.conf with your favorite editor. Scroll past the comments (those lines beginning with #). You should see something like:

```
password: compat
group: compat
hosts: compat
services: compat
```

## Configuring an NIS Secondary Server

As you've decided to configure a machine as an NIS secondary server, you start by configuring it as an NIS client. Verify that you can access the server maps via the ypcat command.

Now you are ready to tell the master server that a slave server exists. To do this, edit the /var/yp/ypmavers file so that the slave server you are setting up is included in the list. If you configured your master server with the name of the slave server during the ypinit -m phase, you do not need to do this.

You can now initialize the slave server by running the following command:

```
/usr/lib/yp/ypinit -s master
```

where master is the hostname for the NIS master server. In this example, it is vestast. The output should look something like the following:

## Testing the Client

With the client and server configured, you are ready to test the work. To see if you can communicate with the server, start by setting the domainname by hand. You can do so with the following command:

```
[client@root]# domainname
```

domainname is the domain name. In this case, it is audient.domain.com. Start the NIS daemon with the following:

```
[client@root]# /sbin/init.d/ypclient start
```

If your configuration is working, use:

```
ypcat passwd
```
