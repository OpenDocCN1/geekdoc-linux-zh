# Caution

When you're configuring binfmt_misc support, the register control string may not exceed 255 characters, the magic cookie must be within the first 128 bytes of the file, offset=size(magic) must be less than 128, and the interpreter string may not exceed 127 characters.

For more information about binfmt_misc and creating the cookie patterns, see Richard Gnther's binfmt_misc homepage at http://www.anatom.tuebingen.de/-richi/linux/binfmt_misc.html.

# Parallel Ports

One change between the 2.0 and 2.2 kernels is the introduction of the deport module, an abstract representation of the parallel ports. This separates architecture-dependent code from the parallel interface and allows you to share the same physical parallel port between many devices. For example, you can use the same port for both a printer and a zip drive or Qcam video camera.

Parallel ports are dangerous beasts to probe, especially when many onboard ports may be fixed at IRQ numbers that can conflict with sound and network cards. It is best to avoid probing and specify the port addresses and IRQ settings of the parallel port hardware, either by appending the parameters to the boot command or by loading the deport as module. By default, the deport module does not probe for IRQs and will initialize all parallel ports in polling mode.

The new deport modules split parallel port control into two modules: the basic deport to manage port sharing, and an architecture-dependent layer (such as the deport_pc module). Either may be compiled into the kernel or as a module and loaded as needed, but in both cases you will probably need to add port configuration details to the boot or insmod command line. For example, to load deport and deport_pc modules, you may use the following command lines:

```
# insmod deport.o
# insmod deport_pc.o io=0x3bc,0x378,0x278 irq=none,7,auto
```

This would install three parallel ports: the first in polling mode, the second on IRQ7, and the third probed for the current values.
