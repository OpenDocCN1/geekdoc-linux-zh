# Networking and Internet Services
PART II

You don't often want to see all the packets, especially in medium to large networks.
Sometimes you want to see all the packets going between two specific hosts, even those that use a specific service. tcpdump takes as a parameter an optional filter expression that will select only packets.

tcpdump's filter expressions consist of one or more primitives joined by the keywords and, or not. Each primitive consists of a qualifier followed by an ID. A qualifier consists of one or more keywords, the most common of which are shown in Table 7.5. The ID specifies the value the corresponding field must have to match the filter.

# Table 7.5 Most Common tcpdump Qualifiers

| Qualifier | Matches |
|---|---|n| src host | The IP address of the host from where the packet comes. |
| dst host | The IP address of the host to which the packet is going. |
| host | The source or the destination host. |
| src port | The packet is coming from. |
| dst port | The packet is going to. |
| port | The source or the destination port. |
| tcp, udp, or icmp | The packet's protocol is specified. |

> One common mistake is to run topdump through a remote connection, such as when connected through telnet or ssh, with a filter that includes all the telnet or ssh packets. An example is including host thishost, where thishost is the host on which topdump is running. In that case you end up with an incredible amount of output. This is because the first packet that comes through generates output, which is transmitted through the network and captured by tcpdump, which generates more output, which is also transmitted through the network, and so on.
To prevent that, be more specific in your filter expressions. For example, you might include the primitive not port 22 to filter out ssh packets.
