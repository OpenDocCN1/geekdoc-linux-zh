
# Linux and Newsgroups

There are three main ways to download newsgroups over your Linux system: INN, C-News, and NNTPCache. INN implements NNTP, which stands for Network News Transfer Protocol. NNTP is widely used over TCP/IP connections to ISPs or the Internet. INN (Internet News) is the most flexible and configurable method of downloading newsgroups and works especially well on larger sites that have high-speed connections to the Internet or sites where a lot of news is transferred (for example, large educational institutions). C News was designed for downloading news through UUCP (UNIX to UNIX Copy). NNTPCache is probably the best choice for most sites, especially those that do not have the bandwidth to download all the news that your organization requires. Because INN is developed with most Linux systems, that's the choice discussed first; a discussion about using NNTPCache as a money-saving alternative to provide news for your users follows.

Rich Salz developed INN to provide a Usenet package in one package. One of INN's attractions is that it doesn't care whether you are using TCP/IP or UUCP to transfer your newsgroups. INN handles both methods equally. INN handles the NNTP protocol for transferring news and provides newsreading services as a separate server nntpd, which is executed when it detects a connection on TCP/IP.

## How a Newsfeed Works

Usenet newsgroup postings are sent from machine to machine across the Internet all the time. To send from one system to another Usenet uses a technique called flooding. Flooding happens when one machine connects to another and essentially transfers all the postings in the newsgroups as one big block. The receiving machine connects to another machine and repeats the process. In this way all the postings in the newsgroups are transferred across the entire Internet. This is much better than maintaining a single source of information on a server located somewhere on the Internet. Each machine that participates in flooding has a list of all the machines that can send or receive postings Each connection is called a newsfeed. When you connect to ISP and download newsgroup postings, you are creating a newsfeed between your machine and the ISP's.

Every time a new posting is added (or posted) to a newsgroup, the newsfeeds are used to transfer that posting. Each article has a list of all the machines that have received the posting, so it is easy to avoid transferring the same posting to every machine on the Internet many times. Each posting also has a unique message ID which prevents duplicate postings.

## Preventing Duplicate Postings

When you connect to ISP and request newsgroup updates, one of two methods is often used to ensure you don't duplicate postings when you use a newsreader. The most common technique is called fetch/sendme, which informs the machine at the other end of the newsfeed (such as your ISP's server) which message IDs you already have which are lacking. At that point only missing postings are transferred to your Linux machine.

The fetch/sendme protocol is excellent for updating a few newsgroups but starts dramatically when handling very large volumes of news. For this reason a method called batching is used to transfer large newsfeeds. With batching everything on one end of the newsfeed is transferred as a block. Your machine then sorts through the download discarding any duplicates. Batching adds more overhead to your Linux machine than fetch/sendme but involves a lot less messaging between the two ends of newsfeeds.

## Pushing and Pulling the News

Two other terms are used to describe the transfer of newsgroup postings from one machine to another, and these terms apply especially to smaller systems that don't download the entire newsfeed every day. Your system can download articles from the newsfeed using the fetch/sendme protocol, a technique called pushing. Alternatively, your machine can request specific postings or entire newsgroups from the newsfeed based on the arrival date, a technique called pulling.

## Alternative Methods to Downloading Newsgroups

Before looking at how to download Usenet newsgroups to your machine, there is one alternative you might want to consider. If you don't use Usenet a lot or have limited connection time to the newsfeed, consider interacting with a news server on a remote network. This method lets you read the postings there instead of downloading them to your machine. Many ISPs allow you to choose whether to download newsgroups to your machine or to read them on their news server. Obviously, if you are reading on the server you must be connected all the time. This might be a better choice however if you don't often surf Usenet or have limited disk space on your machine. Another alternative is to read news via the Web at http://www.deja.com. This very powerful Web site contains almost all the newsgroups around the world and offers a strong search facility. If you are looking for a particular problem, chances are you will find an answer if you do a search there.

## INN Hardware and Software Requirements

INN doesn't impose too many hardware requirements; most Linux-capable hardware is sufficient to run INN. If you download a lot of newsgroup postings, slow processors will be affected. Because INN often works in background, your foreground tasks get slower while INN crunches in background. This is usually not a problem with 8046 or better CPUs running SuSE Linux.

There are no RAM requirements for INN, although the more RAM the better to avoid swapping. If you download only a dozen newsgroups a day, Linux needs no extra RAM. You should have space allocated on your system as RAM overflow, but there is no need to expand swap space for INN unless the existing swap space is very small (less than half of your physical RAM, for example).

Disk space may be a problem if you don't have a lot to spare. Downloading newsgroups can eat up disk space at an alarming rate, even if you download only a few groups a day. Because group postings are not automatically deleted after you read them, the effect is cumulative. This is especially a problem with newsgroups that contain binary information such as compiled programs or pictures. A typical newsgroup download can range from a few kilobytes to several megabytes. Some of the newsgroups get many megabytes daily, all of which accumulate over a week or so to huge amounts of disk space. It is not unusual for a day's complete download of all the newsgroups to take up quite a few gigabytes of disk space so you must be careful about which newsgroups you select to download.

Modems are another issue, and the speed of your modem directly affects how many newsgroups you can download in a reasonable amount of time. Obviously, the faster modem the better. A 56Kbps modem will download much more data in a minute than a 9,600bps modem. That doesn't mean you need a faster connection if you download less than a day, a 9,600bps modem is fine. When you start downloading megabytes, a 56Kbps modem will suit your purposes. The determining factor for your connection is the amount of data you should look at faster connections such as DSL ISDN (128Kbps), T1 (1.544 Mbps), T3 (45 Mbps).

## Introduction to INN

INN was designed for handling news on large systems with complex connections and configuration problems. INN contains an NNTP component but is noticeably faster when downloading newsgroups than NNTP alone. Frankly, INN can be quickly configured for most Linux setups. However setting up INN on a typical Linux system using a dial-up connection to an ISP using TCP/IP is the most common configuration. One problem with INN is a lack of good documentation. To date, no one has spent the time to produce a good public-domain how-to file about configuring and maintaining INN on Linux systems, but there is an INN FAQ, among other things, available from the INN home page at http://www.isc.org/inn.html.

INN uses a daemon ind to control its behavior. Another daemon, nntpd, is used to providereader services. When you boot your machine, ind usually starts right away. Every time a user launches a newsreader, a copy of nntpd is started.

## Installing INN

To install INN, you can start with either the source code (usually obtained from a Web or FTP site) or a precompiled binary included in the SuSE INN package. Precompiled binaries are easier because they save several steps and some disk space in producing the binary from source code.

> Note If you are working with INN source code instead of a precompiled binary, you should carefully read any readme files in the source distribution. They describe the steps involved in compiling the INN software for your system. A make accompanies the source code and will almost certainly need modification to suit your system. With the latest INN distribution, however, a configure script runs before compilation, which takes care of most configuration.
