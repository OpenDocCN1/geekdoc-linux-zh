# Apache Server CHAPTER 11

Name-based virtual hosts require just one additional step than IP-based virtual hosts. You first need to indicate which IP address has the multiple DNS names on it. This is done with the NameVirtualHost directive.

VirtualHost 192.168.204.24

You then need to have a section for each name on that address, setting the configuration for that name. As with IP-based virtual hosts, you only need to set those configurations that need to be different for the host. You must set the ServerName directive because that is the only thing that distinguishes one host from another:

```
<VirtualHost 192.168.204.24>
ServerName bugserver.database.com
ServerAlias bugserver
DocumentRoot /usr/local/httpd/htdocs/bugserver/htdocs
ScriptAlias /usr/local/httpd/htdocs/bugserver/cgi-bin
TransferLog /var/log/www/bugserver/access_log
</VirtualHost>
```

```
<VirtualHost 192.168.204.24>
ServerName pts.database.com
ServerAlias pts
DocumentRoot /usr/local/httpd/htdocs/htdocs
ScriptAlias /usr/local/httpd/htdocs/pts/cgi-bin
TransferLog /var/log/www/pts/access_log
ErrorLog /var/log/www/pts/error_log
</VirtualHost>
```

> Tip: If you are hosting Web sites on an intranet or internal network, there is often a chance that users will use the shortened name of the machine rather than the fully qualified domain name. For example, they might type http://bugserver/index.html in their browser location field, rather than http://bugserver.database.com. In that case, Apache will not recognize that those addresses should go to the same virtual host. You could get around this by setting up VirtualHost directives for both bugserver and bugserver.database.com, but this very easy way is to use the ServerAlias directive, which lists all valid aliases for the machine:
ServerAlias bugserver
