## PART III

Frame buffers have an alternate means to control the graphic system via a dedicated device (/dev/fb0), and they're mostly an issue when you're compiling a kernel to run on platforms other than the Intel x86 or when you're using a Matrox Millenium or similar PC graphics card. To use frame buffers, your X-server must be aware of the feature. Although you can include FB support on an Intel platform (see Documentation/fb/vesaf.txt), be aware that using software that talks directly to the hardware but is unaware of this method may cause a system crash.

Intel Binaries for the XFree-3.3.3 with Framebuffer support are available through http://www.in-berlin.de/User/kraxel/fb.html and more information on framebuffers can be found in the FB HowTo at http://www.tahallah.demon.co.uk/programming/prog.html or read Documentation/fb/framebuffer.txt.

## Sound

The Linux sound driver was derived from the OSS/Free driver by Hann Sauvainen. The current kernel driver is the result of work by Red Hat, and this should be taken into consideration when you're reporting problems. For very new and/or obscure sound card support, you may need to obtain the commercial edition of the OSS drivers (see http://www.opensound.com/).

The first option in the sound configuration section is a master switch for enabling sound support. If this option is switched off in a kernel previously configured for sound, all options are preserved in the .config file, but the sound module will not be included in the resulting kernel. This is sometimes useful when you're experimenting with sound system options, or when you suspect an IRQ conflict between the sound system and some other device, such as a printer (IRQ 7) or a network card (IRQ 10).

Most of this option is what you might expect. You will need the IRQ numbers, DMA channels, and port addresses of your audio hardware. If you're in doubt, the HELP option will offer some advice on the compatibility of various options. There are a few items that provoke misunderstandings, such as enabling MIDI vs. enabling emulation in a Soundblaster card, but all of these issues are explained in the HELP pages.

Linux includes support for a wide array of cards, from legacy AdLib cards to 2.2 kernel, OSS/Free now provides a software wavetable engine to bring realistic MIDI to other 8-bit sound cards. This wavetable support allows samples from 8kHz and 44kHz up to 32 voices. The sampling rate and the number of voices your system can handle depend on your RAM and CPU speed, but eight voices runs quite comfortably on 486.

## Kernel Management CHAPTER 23

Most frequently, mishaps in configuring sound cards are due to IRQ or DMA and port conflicts from configuring a clone card as “Soundblaster-compatible” (SB-compatible) or due to plug-and-play problems. Detailed information on compatibility and tips on troubleshooting can be found in Documentation/sound/README.

### Tip

Most modern plug-and-play (nP) sound cards have very little trouble with Linux, and some modern machines will assign PNP values through the BIOS when the system boots, but in some situations you may need to experiment with PNP to generate and load acceptable settings into the card before you can use the sound system. In this situation, the sound card must be compiled as a module to allow using PNP to set the device.

To configure PNP devices, you first need to obtain the possible settings using the config utility:

```bash
config > /etc/devices.conf
```

This will create a long text file of configuration options for all PNP devices. You must then edit this file to uncomment the settings that will work with your configuration:

```bash
vi /etc/devices.conf
```

If you have a Windows partition or access to a machine where you can test the card, you can obtain the correct (or likely) settings by using the Control Panel. Once you have set this configuration file to be compatible with your system, you can then add the lines to your boot scripts to first load the configuration and the driver:

```bash
insmod sound -c /etc/devices.conf
```

In rare circumstances, this technique will not work because the card needs to be initialized by Windows before it can accept any requests. The only way around this, outside of lobbying the manufacturer to be more friendly, is to boot your system under Windows and then use the DOS-based loader to switch to Linux.

## Kernel Hacking

In the 2.2 kernel, Kernel Hacking contains only one option: the flag to enable the SysRQ interrupt keys. SysRQ support adds several useful commands for recovering from a hung system through binding several critical operations to Ctrl+Alt+SysRq. For example, when you're using a development kernel or experimenting with kernel options the console or X-server becomes locked out because some rogue process is blocking I/O, you might try to telnet to the machine to open a superuser shell to kill the process or reboot the machine. If you cannot start a login shell, SysRQ commands can be used to sync and unmount the filesystems and force a reboot. See Table 23.2.

> Caution: Production machines should not leave SysRQ enabled, and you also want to disable the Ctrl+Alt+Backspace command to exit X-Windows. This prevents novice (or knowledgeable) users from bringing down the machine without authorization. In /etc/initab, you can also customize the handling of the Ctrl+Alt+Del interrupt, such as to give the machine a longer grace period or to disable the command entirely.

### TABLE 23.2 SysRQ Commands
| Command | What it Does |
| --- | --- |
| r | Turns off keyboard raw mode and sets it to XL. This is useful when the console or the X-Server is hung. |
| k | Kills all programs on the current virtual console, such as to shut down a locked X-server. |
| b | Immediately reboots the system without syncing or unmounting all filesystems. This command may corrupt your filesystem if you have not already synced and unmounted your disks. |
| 0 | Shuts off system power via APM (if configured and supported). |
| s | Attempts to sync all mounted filesystems to minimize the filesystem corruption that may occur from an ungraceful shutdown. |

### Load/Save Configuration

The load and save options are a convenience for those who need to maintain several alternate configurations. For example, one machine may need to compile kernels for several different machines, or the machine may need alternate kernels for different purposes. As you would expect, this option pops up a dialog asking for the filename and then saves the .config file to the named location.

### Saving Your Configuration

Once the kernel is configured, the save and exit option will create the .config file, and if the kernel has been configured for sound, it will generate linux/include/autoconf.h. The kernel is now primed and ready for building.
