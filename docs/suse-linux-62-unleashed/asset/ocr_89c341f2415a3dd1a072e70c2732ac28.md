# Networking and Internet Services
PART II

The -v option tells sendmail to be verbose so you can see what's happening. Depending on whether the delivery is local or remote, you can see something as simple as joe... Sent or an entire SMTP dialog. The -o sets an option that overrides what is in the sendmail.cf file. You can use -o for long options.

The -o/tmp tells sendmail to use /tmp as its queue directory. Using this option is necessary because sendail drops its superuser permissions when run with the -C option and can't write queue files into the normal queue directory. Because you are using the -C and -o options, sendmail also includes the following warning headers in the letter to help alert the recipient of possible mail forgery: /tmp

X-Authentication-Warning: gonzo. Processed from queue /tmp
X-Authentication-Warning: gonzo. Processed by joe with -C svrr.cf

sendmail also inserts the header Apparently-to: joe because, although you specified a recipient on the command line, none was listed in the body of the letter. In this case, the letter's body was taken from the empty file /dev/null, so no To: header was available. If you are testing it as the superuser, you can skip the -oQ argument and sendmail won't insert the warning headers. You can avoid the Apparently-to: header by creating a file like

To: recipient

testing

and using it as input instead of /dev/null.

The recipient should be you, so you can inspect the headers of the letter for correctness. In particular, return address lists must include an FQDN for SMTP mail. That is, a header as From: joe@gonzo is incorrect because it doesn't include the domain part of the name, but a header as From: joe@gonzo.gov is fine.

You should repeat this testing for the same variety of addresses you used in the first tests. You might have to create special alias that point to you for some of the testing.

The amount of testing you do depends on the complexity of your site and the amount of experience you have, a beginning system administrator should test very thoroughly, even for apparently simple installations.

When you are absolutely sure that the sendmail.cf file is correct, you can copy it into place in the /etc directory:

```
[root@gonzo cf]# cp /etc/sendmail.cf /etc/sendmail.cf.bak
[root@gonzo cf]# cp gonzo.cf /etc/sendmail.cf
```
