## PLIP, PPP, and SLIP Dialup Networking Support

PLIP is a means to network two Linux machines over a null-printer (Turbo Laplink) cable, using it to provide a relatively high speed (compared to data) channel between two machines, and is often used as a NFS-install to a laptop where there is no CD-ROM. Wiring for this cable is described in Documentation/networking/PLIP.txt, and the connection can be up to 15 meters long. Russell Nelson has also created MS-DOS drivers for PLIP to enable networking of DOS-based machines (such as that old PL/5 space header I keep in the workshop).

Linux 2.2 requires an update for the pppd tools, or a patch applied to the pppd-2.2.0 package, as is outlined in Documentation/networking/ppp.txt. The usual symptom of this problem is ppp crashing from a fatal error after using an ioctl operation.

SLIP is the ancestor of PPP, and although 99.9% of all ISPs will only offer PPP connections, SLIP has some very viable uses. SLIP is essential as an intermediary device in the Dialed demand dialer or to gain a network connection over a telnet session (using ShRP).

## Amateur Radio and Wireless Support

Another low-cost solution to nearly impossible remote access requirements is the Amateur Radio Support. By encoding packets over shortwave radio, Linux systems have been used to provide as much as 64Kb of bandwidth to remote regions. For example, see the Wireless Papers at http://www.ictp.trieste.it/radionet/papers/ or the archives of the Linux-borders archive at http://www.tux.org(), or visit the Packet Radio Homepage at http://www.tapr.org/tapr/html/pkthome.html.

A related feature of interest to campus or development projects is the support for Wireless LAN and the AT&T WaveLAN and DEC RoamAbout DS (see Documentation/networking/wavelan.txt). There is also support for the MosquitoNet StarMode Radio used by many laptop owners (see http://mosquitonet.stanford.edu/).

## Kernel Management CHAPTER 23

### IrDA Subsystem and Infrared Port Device Drivers

The Infrared Data Association protocols provide wireless infrared communications between laptops and PDAs at speeds up to 4Mbps. With the Linux driver, supported devices will be transparent to the networking system. More information on this support, and on the utility programs for IrDA, can be found in the /usr/doc/howto/en/IR-HOWTO.gz file, from ftp: http://metalab.enc.edu/pub/linux/docs/HOWTO, or from the Linux IrDA home page at http://www.cs.uit.no/linux-irda.

### ISDN Subsystem

Using the ISDN subsystem requires the isdn4k-utils programs from ftp://ftp.franken.de/pub/isdnlinux/. When the module is loaded, isdn.o can support up to 64 channels (you can add more by changing the isdn.h file directly). Each channel will be given read/write access to the D-Channel messages and ioctl functions, with non-synchronized read/write to B-Channel and 128 tty-devices. Modem emulation provides a standard AT-style command set that is compatible with multiple dial tools, such as minicom, PPP, and mgetty.

The second step in configuring ISDN is to select your specific ISDN modem card. Some ISDN cards will require initialization before the vendor-independent setup. Details about this can be found in the appropriate README file under linux/Documentation/isdn.

### Old CD-ROM Drivers (Not Scsi or IDE)

Old CD-ROM drivers include the early SoundBlaster Matsushita and Panasonic-style CD-ROMs that were included as part of 16-bit sound cards. If you have a clone with a socket for a CD-ROM drive and it was made before 1994, it is likely to be one of these interfaces. If it's newer, it could still be an IDE-type CD-ROM.

### Character Devices

Character devices communicate with the kernel via a stream of characters. These devices include terminals, serial ports, printers, and also some special-purpose devices such as the CMOS memory and the watchdog. If you're working with most desktop installations, these options will simply be a matter of adding or removing printer support. On the other hand, you'll find these options very interesting if you're working with applications such as data acquisition projects.

### Terminals and Consoles

Most applications will configure the kernel for at least one console. There are some embedded applications in which this code will not be needed, but for most people, having multiple virtual consoles mapped to the Alt+Fn keys is very useful.

Another useful feature is that you can have console messages sent to the console.

### Serial Ports

In addition to de-tty, Linux supports serial ports. These can be used to connect to terminals, modems, and other devices. The use of serial ports in Linux is not restricted to terminal access; they can also be used for any type of communication.

### PTY

The PTY (pseudo-terminal) system allows a program to act as a terminal. This is particularly useful for applications like SSH and telnet, which need to provide a terminal interface to the user.

### Parallel Printer

You will need the parallel port if you plan to use a parallel printer. The port is also used to connect other devices, such as scanners and external drives.

### Mice

Linux supports many types of mice, including PS/2 and USB mice. Most modern mice will work out of the box, but some may require specific drivers or configuration for advanced features.

### Watchdog, NVRAM, and RTC Devices

The watchdog timer is used to reboot the system if it hangs or crashes. It is often used in embedded systems where high availability is critical.

The NVRAM provides a way to store non-volatile data. This can be used to store system settings that persist across reboots.

The RTC (real-time clock) is used to keep track of the time and date. It is usually backed by a battery on the motherboard.

### DoubleTalk Speech Synthesizer

No surprises here, but users of speech synthesizers may also be interested in the Blinus (distribution for the blind) and Emacspeak. Linux stands alone as the O/S that can grant blind users total access to all functions of their computers and to all services on the Internet.

### VideoLinux

Video4Linux (V4L) grew out of a plethora of different interfaces and now provides a common programming API for audio/video capture or overlay cards, radio tuning sources, teletext, and other TV-related VBI data. V4L support is needed if you plan to use any of the current TV/FM cards, and V4L can be used for videoconferencing cameras such as the Connectix Qcam. To use these services, you will need v4laware applications. A few applications are currently archived at ftp://ftp.uk.linux/pub/linux/video4, and a few more, including Webcam capture and applications, are listed at Room Three Web site at http://roadrunner.swansea.linux.org/v41.shtml.
