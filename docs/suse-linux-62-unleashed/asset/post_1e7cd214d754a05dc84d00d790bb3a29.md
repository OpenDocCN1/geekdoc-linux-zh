> Note
One of the defaults for filesystems is that they are mounted async. This matters in that the operating system will return control before it reads or writes a file. Many Linux users have erred by pulling a diskette out of the drive too soon, causing a read or write to be aborted and errors to occur. Options are processed by the mount command in the order they appear on the command line (or in /etc/fstab). Thus it is possible to allow users to mount a filesystem and then run executables by using the options user. Using them in reverse order wouldn't work because the user option would turn off again. Many other options available are specific to particular filesystems. The valid options for mount are detailed in its manual page. An example is the umask flag which allows all files on Windows partitions readable (or even writable if you prefer)

## Configuration with yast Command

The yast command can be used to reconfigure your system's hardware; for example, if you replace your old CD-ROM (perhaps an EIDE unit) with a new SCSI unit.

1. Start yast command from the console or command line of a terminal window.
2. Scroll down and select the System Administration item.
3. Select Integrate Into System.
4. In the resulting pop-up menu, select CD-ROM Configuration and click Enter. You'll see the dialog box shown in Figure 18.1.

Scroll through the list devices, as shown in Figure 18.2, and select a device that matches your new hardware. Press Enter to select this device. The yast command will then attempt to recognize your device and, if successful, will use your new CD-ROM as the source media for future updates and software maintenance.

## Editing /etc/fstab Manually

The filesystem table /etc/fstab is a text file; it is designed to have a specific format that is readable by humans and not just computers. It is separated into columns by tabs or spaces (It doesn't matter which you use.). You can edit it with your favorite text editor; it doesn't matter which. You must take care, however, if you modify it by hand removing or corrupting an entry will make the system unable to mount that filesystem the next time it boots. For this reason, I make a point of saving previous versions of this file using the Revision Control System (a very useful program; see the manual page for rcs).

A sample /etc/fstab looks like the following:

```
/dev/hda6      swap            defaults 0 0
/dev/hda1               ext2             1 1

/dev/hdc       cdrom           iso9660        ro,noauto,user 0 0
/dev/fd0       /floppy         auto            noauto,user 0 0
none            proc            defaults 0 0
# End of YaST-generated fstab lines
```

The first line is for the Linux swap partition, which uses /dev/hda6 for virtual memory. The second line shows that this system has a single root filesystem, residing on the /dev/sda partition. Following this is the table entry for the system's CD-ROM drive, /dev/hdc, which will be mounted at /cdrom. When Linux is booted, the root filesystem is mounted first; all the local (that is, non-network) filesystems are mounted next. Filesystems appear in /etc/fstab in the order they are mounted. If you split your Linux system across various partitions, /usr must appear before /usr/src, for example, because the mount point for CD-ROM and floppy are removable, and they have the noauto option so that they are not automatically mounted at boot.
