# A Brief History of Internet Email Standards

Electronic mail or email is arguably the most useful application of the Internet, even so than the relatively young World Wide Web. Since the Internet's inception, there have been many public standards, which are called Requests for Comments (RFCs). Many of these RFCs started with Mail Transfer Protocol in 1980, evolved into Simple Mail Transfer Protocol (SMTP) in 1981, and since have been enhanced into the protocols we know today (See http://www.ietf.org/).

# Introduction to sendmail

During this time of rapid change in email protocols, one package emerged as a standard for mail transfer. sendmail, written by Allman at Berkeley, was an unusual program for its time because it saw the problem in different light. Instead of rejecting email from different networks, sendmail managed the message and fixed it so it could be passed to its destination. The tradeoff for this level of flexibility has been that for most administrators, this is overkill. However, sendmail was and is still open source, which means that all source code is freely available and can be freely distributed. Eric has now established a company (http://www.sendmail.com), which provides commercial products and add-ons for sendmail. However, the core protocol will always remain free.

# The Post Office Protocol (POP)

With the advent of larger, heterogeneous networks, the need for mail readers that worked on clients and connected to designated mail servers gave way to the Post Office Protocol (POP). POP has undergone many revisions since its inception. The latest revision of the protocol is POP3, which has been updated a number of times since 1998. POP readers have flourished: Client software is available for every imaginable platform, and there is server software for not only UNIX implementations but for other operating systems as well.

POP3 does have its fair share of limitations, the main one being that it can access messages in only one mailbox (generally the user's incoming mailbox on the server). When you read email with a client program on Linux, such as pine, you can create folders to manage your messages. When you are using a POP3 client, you can also create folders to organize your messages, but those folders will only exist on the machine that the POP3 client is running. For example, if you run the Eudora client on a Windows machine and access your mail via POP3 on a Linux server, you can save messages to Eudora folders, but these folders generally will be located on the Windows hard drive. If you use another PC to access your email with a POP3-compatible client, you will not be able to access those folders you created on the first machine.

# The Internet Mail Access Protocol (IMAP)

A protocol called Mail Message Access Protocol (IMAP) was developed to be an improvement over POP3. Its first RFC was based on version 4, so it is generally referred to as IMAP4. IMAP4 overcomes some of the limitations of POP3. The major feature is that a user can have multiple folders on the server to save their read. Wherever you access your email using IMAP, you have full access to previously saved messages.

Another limitation of the POP3 protocol is that it does not keep the state of messages in mailboxes—different messages can have different states, such as read, unread, or marked for deletion. Most POP3 clients download all the messages in the user's mailbox. IMAP4 overcomes this problem by downloading all mail items and ordering, depending on which message is selected, downloading only that particular message. Again, there are implementations of IMAP4 servers for most major network operating systems today.

The Simple Mail Transfer Protocol (SMTP) is the established standard for transferring mail over the Internet. The sendmail program provides the services needed to support SMTP connections for Linux.

# Caution

As with any large software package, sendmail has its share of bugs. Although the bugs that cause sendmail to fail or crash the system have been almost completely eliminated, security holes that provide root access are still found from time to time.

When you're using any software that provides network connectivity, you must keep track of security announcements from the Computer Emergency Response Team (CERT) by ever visiting its Web page at http://www.cert.org, joining its mailing list, or reading its moderated newsgroup, comp.security.announce.
