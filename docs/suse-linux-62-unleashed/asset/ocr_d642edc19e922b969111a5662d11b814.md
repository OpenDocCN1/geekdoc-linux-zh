# Caution

If you are experimenting with kernel options, remember to set the LILO delay parameter to give you some grace time to select an alternate kernel. If your production system has a delay of zero seconds, the only way you can preempt loading the default kernel is to hold down the left shift key immediately after the computer starts up. For more dangerous experiments, the delay parameter also accepts a value of -1 which will cause the boot process to wait indefinitely for a boot parameter.

I remember sitting in a Linux User Group meeting one evening and complaining about wanting to set some kernel option one but letting it slip by or setting it wrong, and having to abort the program and start again. Everyone looked at me rather strangely I had been using the command-line interface for so long that I hadn't even considered that other methods might have been introduced in the intervening years.

Why have a command-line interface? Suppose you had an autonomous robot submarine, or perhaps a space probe, that you had in the midst of maneuvers and needed a fast kernel config. Simple dumb terminal interfaces go places where other interfaces cannot go. Keep this in mind if you plan to read your email or news from some GUI-only package!

That said, other using the oldconfig option for generating an updated configuration from a previous .config file, I don't have I used the command-line interface since that. Without a doubt, the X11/tk interface is the most elegant and appealing, although it requires that tk and X11 are both working. X11 sometimes isn't practical to use, as if you're doing remote administration over a slow telnet connection.

This leaves the Linux nurses configuration as the main workhorse of Linux configuration, with the vehicle of choice when possible. Both the X11 and the nurses configuration tools offer the same options in the same order, and they have roughly the same capability to navigate backward and forward through the configuration options.
