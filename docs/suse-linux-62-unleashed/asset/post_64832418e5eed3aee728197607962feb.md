
## VMware for Linux and Windows

VMware from VMware, Inc. is a software package for Linux, and others that you can use to install and run an operating system into a virtual filesystem on your computer. This approach, similar to the hard drive image used by DOSEMU, can be used to install and run Linux under a Win32 operating system without partitioning the hard drive, or to install and run a Win32 operating system under Linux.

Unlike the free AT&T Laboratories virtual network software (discussed in "Windowing Clients") in this chapter, VMware is a commercial software package. This section discusses installing and running VMware under Linux, although VMware is available for other platforms. For details, browse to http://www.vmware.com.

The VMware software for Linux is distributed at a 3.5MB compressed archive, and requires at least a 266Mhz processor, 64MB RAM and the X Window System.

## Installing VMware for Linux

To install VMware under Linux, download the package and then decompress the archive with the tar command like this:

```bash
# tar xzvf vmware*.gz
```

Next, navigate to the vmware-dist directory, and run (as root) the file install.pl like this:

```bash
./install.pl
```

The installation script starts, and you are asked to read a license agreement file and answer questions. The script will check your system, build any required software modules, and then ask whether or not you would like a closed or working networking configuration (whether or not to allow the installed operating system to communicate with other computers). If you need networking support for your intended operating system, answer the script to enable networking support. If you choose a "host-only" configuration, the VMware install script will pick an unreachable network number for its configuration.

## Starting and Configuring VMware

After you choose your configuration, the script installs the VMware software under /usr/local/bin directory, and exits. In order to run VMware, you must have a license file from VMware, Inc. This license may be obtained by registering at the VMware home page, and will be emailed to you. When you receive the license, save the email message as a text file license.

Next, use the mkdir command to create a directory in your home directory named .vmware, then copy the license into the .vmware directory like this:

```bash
# mkdir .vmware ; cp license .vmware
```

To first start VMware, type vmware at the command line of your terminal window. (You do not need to be logged in as the root operator, but you will need read and write permission for the device /dev/zero). The VMware configuration window and dialog box appears, as shown in Figure 29.3.

## Installing Your Operating System

To start the installation process, insert a diskette or CD-ROM into your computer and click the Power On button in the VMware window. The software then boots, as shown in Figure 29.8. Continue through and finish your operating system installation. The next time you start VMware, you are asked to select a desired configuration, usually found under the vmware directory. The configuration file has a name ending in .cfg in your home directory. To start your session, select the file, and then click the Power On button. Your operating system boots, as shown in Figure 29.9. ![](img/cbac72550c7126a2216e94d1a0c360_955_0) Power on with an inserted floppy or CD-ROM disk to install your new operating system. ![](img/cbac72550c7126a2216e94d1a0c360_955_1)

The VMware software supports many types of operating systems, even outdated "legacy" operating systems. If you use VMware to run a virtual filesystem, be sure to browse to VMware's home page and download the vmtools.tar.gz file. This file contains special software, specifically tuned for Linux, to offer better graphics performance. To release the mouse, press Ctrl+Alt+Esc. When you've finished working with VMware, make sure to properly shut down the running operating system, and then click the Power Off button in the VMware window.

## The mtools Package

The mtools package, originally by Emery P. Gray, and now maintained by Alain Knaff and David Niemi, is a public-domain set of programs you can use for just-in-any operation on MS-DOS floppies. These commands are useful because you don't need to mount the floppy in order to read, write, or change the floppy's contents. Table 29.1 lists the tools included in the package.

### Table 29.1 mtools Package Contents

| :--- | :--- |
| mattr | Changes file attributes |
| mbadlocks | Floppy testing program |
| mcd | Changes directory command |
| mcheck | Checks a floppy |
| mcopy | Copies files to and from diskette |
| mdel | Deletes files on diskette |
| mdtree | Recursively deletes files and directories |
| mdir | Lists contents of a floppy |
| mformat | Formats a floppy |
| minfo | Categorizes, prints floppy characteristics |
| mkmanifest | Restores Linux filenames from floppy |
| mlabel | Labels a floppy |
| mmd | Creates subdirectory |
| mmount | Mounts floppy |
| move | mv command for floppy files, directories |
| partition | Makes DOS filesystem as partition |
| mrd | Deletes directories |
| mren | Renames a file |
| mtoolstest | Tests mtools package installation |
| mtype | Types (lists) a file |

## Graphics, Multimedia, and Productivity Tools

Generally, the mformat, mdir, mcopy, and mdel commands are the most often used. The mformat command formats nearly any type of floppy disk. One nice feature of this software is that you don't have to remember the specific names of floppy devices, such as /dev/fd0, and you can use the (possibly) familiar A: or B: drive designations. This is possible because of mtools' use of the /etc/mtools.conf configuration file, /etc/mtools.conf.

Entries for different disk devices are listed in the file. You can edit the file (as root) to configure mtools for your system having to rebuild the software (although if you need the source, you can readily find a copy on your favorite Linux site, or at ftp://ftp.tux.org/pub/knaff/mtools, along with numerous addons and utilities). If you examine the /etc/mtools.conf file, you'll see entries for different devices, and configurations for other operating systems. For example the floppy device entries like this:

```
drive a: file="/dev/fd0" exclusive mformat_only cylinders=80 heads=2-18
drive b: file="/dev/fd1" exclusive mformat_only cylinders=80 heads=2-18
```
