# Managing Filesystems
CHAPTER 18

When you mount a filesystem, the point at which it is to be mounted (that is, the point) must be a directory. This directory doesn't have to be empty, but after the filesystem is mounted, anything underneath is inaccessible. Linux provides a singly rooted filesystem, which is in contrast to operating systems that give each filesystem a separate drive letter. Although this might seem less flexible, it is more flexible because the size of each block device (hard disk or whatever) is hidden from programs, and things can be moved around. For example, if you have some software that expects to be installed in /opt/umps you can install it in /big-disk/stuff/umps and make /opt/umps a symbolic link. There is also no need to edit a myriad of configuration files that are using the wrong drive letter after you install a new drive, for example.

Many options govern how a mounted filesystem behaves; for example, it can be mounted read-only. Additionally, there are options for filesystems such as mdos don't have any concept of users. The filesystem table entries you to give each file a particular mode (for security or to access by everyone). Other filesystems offer even more options; when you mount a filesystem, there is such flexibility available that the options have a separate manual page (man nfs command), although the defaults are perfectly reasonable.

Table 18.1 contains options useful for mount in alphabetical order. Unless otherwise, these options are valid for all filesystems, although asking for asynchronous writes to a CD-ROM is not. Options applicable only to NFS filesystems are not listed here; refer to the nfs command page for those.

| Option | Description |
| async | Write requests for the filesystem normally should wait until the data has reached the hardware; with this option, the program continues immediately. This means that the system is slightly more prone to data loss in the event of a system crash, but on the other hand, crashes are rare with Linux. This speeds up NFS filesystems to a startling extent. |
| auto | Indicates to mount that it should mount the device when given the a flag. This flag is used by the startup scripts to make sure that all the required filesystems are mounted at boot time. The opposite of this option is sync. |
| defaults | Turns on the options rw, sudo, dev, exec, auto, nouser, and async. |
| dev | Allows device nodes on the system to be used. Access to devices is completely determined by access rights to the on-disk device node. Hence, if you mount an ext2 filesystem on a floppy and you have previously placed a writable /dev/km device on the disk, you've just gained read/write access to kernel memory. System administrators generally prevent this from happening by mounting removable filesystems with the nodevmount option |
