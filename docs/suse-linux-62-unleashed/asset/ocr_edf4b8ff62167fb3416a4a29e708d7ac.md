After you're done modifying the line, type **init q** to cause it to reconfigure itself based on the new /etc/inittab settings. mgetty will then be launched and provide a connection to your system via a modem on your serial port.

The ppp daemon is called, appropriately enough, pppd. It is configured by editing the /etc/ppp/options file. Note that /etc/ppp/options should contain options that apply to all PPP connections, incoming and outgoing. Here's a useful /etc/ppp/options file that should work for any connection:

```
asyncmap 0
netmask 255.255.255.0
proxyarp
lock
crtscts
modem
```

asyncmap sets control characters which should be escaped. Some modems have problems with some characters (notably Ctrl+S and Ctrl+Q), so those characters should be escaped. The parameter to asyncmap is a 31-bit number in which each bit represents one of the 31 control characters (from ASCII 0 to ASCII 31).

netmask sets the netmask for the PPP interface.

proxyarp tells the host to answer ARP (Address Resolution Protocol) queries on behalf of the remote system. An ARP query is sent by a host on a local network, effectively saving all other hosts which can handle a particular IP address. A proxy ARP means that this tells all hosts on its LAN that it "owns" the remote host's IP address, thereby allowing other hosts on the LAN to reach the remote host.

lock tells pppd to create a lockfile so that no other process will try to use the serial port.

crtscts tells pppd to use hardware handshaking through the serial port. All modern modems and modem cables support hardware handshaking.

modem tells pppd to use all other modem control signals, as carrier detect, in its operation.

Once the default /etc/ppp/options file has been set, you should set up a file /etc/ppp/options.ttyXX for each serial port you want to have a PPP server on.
