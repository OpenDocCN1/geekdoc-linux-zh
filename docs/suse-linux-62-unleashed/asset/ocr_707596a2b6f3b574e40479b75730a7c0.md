# SuSE System Administration
Part III

The daemon is started by the cron script under the /etc/rc.d/init.d directory
when you boot SuSE Linux. This daemon checks your system's /etc/crontab file as well
as your users' crontabs every minute, looking for any tasks that are scheduled to run. As a
system administrator, you can schedule system tasks in /etc/crontab or in root's own
crontab. It's important to note that these are two distinct files. /etc/crontab (the system
contab) initially contains several entries:

```
SHELL=/bin/sh
PATH=/usr/bin:/usr/sbin:/sbin:/bin:/usr/lib/sbin/news/bin
MAILTO=root

* * * * root test -x /usr/sbin/atrun && /usr/sbin/atrun
0 21 * * * root test -x /usr/sbin/faxclean && /usr/sbin/faxclean
5 22 * * * root test -x /usr/sbin/texpire && /usr/sbin/texpire
25 23 * * * root test -e /usr/sbin/facron
&& sh /usr/sbin/facron | mail FaxMaster
```

```
#

0 0 * * * root rm -f /var/cron/lastrun/cron.daily
0 0 * * 6 root rm -f /var/cron/lastrun/cron.weekly
0 0 1 * * root rm -f /var/cron/lastrun/cron.monthly
```

example, 3-10, which would cause a cron job to run from 3 minutes to 10. There are
other shortcuts to specifying cron entries; type man 5 crontab for more details.

de of week (0-7). Cron will logically "and" these conditions to determine
when to run a particular script. The only exception is if a day of month and day of
week are specified, it will "or" these two fields. In all other cases, replacing a*
a a numeric value limits the times that a particular command will execute.
