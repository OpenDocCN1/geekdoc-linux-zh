What is a sysadmin to do? Use only the console? What about remote sites that are connected via the Internet?

Enter the Secure SHell, also known as SSH. SSH is a suite of programs that allow you to log on to remote servers and transfer files in a secure manner. It is meant to be a replacement for login, telnet, and rep, which are insecure because they don't encrypt the data they transfer as it moves from one to another. SSH, on the other hand, scrambles the data that goes through the network so it is indecipherable to someone using a sniffer. A full discussion of security and encryption technologies is beyond the scope of this book; however, an excellent reference is Internet Security Professional, Second Edition (New Riders Publishing, ISBN 1-5620-5760-X).

With SSH, each host and user has a private key and a public key. The public key is stored on the server, where the private key is kept on the client. Data encrypted with one can only be decrypted with the other, and vice versa. This means that SSH can be used for secure communications and for strong authentication, where you need to be sure that the host on the other side of the connection is actually what it claims to be.

Because SSH contains encryption technology, it is illegal to export it from the U.S. Why not it isn't included in the SoSE Linux 6.2 distribution. To get SSH, you must download it from the Internet. The master site for the SSH RPM is http://www.replay.com/redhat/ssh.html. There are four RPMs: ssh, ssh-server, ssh-clients, and ssh-crypt. (Version numbers aren't mentioned here because they might change over time; get the latest 1.x versions available.) ssh-server must be installed on the servers (the hosts you are logging on to), ssh-clients on the clients (the hosts you are logging on), and ssh from both; ssh can be optionally installed on one or both. It is also best to install all packages on all hosts.

The ssh-server package contains default /etc/ssh/sshd_config and /etc/ssh/ssh_config that work well for most purposes. It also contains an /etc/rc.d/init.d/sshd script for starting the ssh daemon when you boot the host. To start the ssh daemon manually, run /etc/rc.d/init.d/sshd start. It starts automatically when you boot the servers, create an appropriate softlink in the /etc/rc.d/rc? directory that corresponds to your server's initlevel default.

The ssh and ssh-clients packages contain several programs. The most useful are ssh and scp. ssh allows you to log on to a remote host, execute remote programs, and redirect ports from the local host to the remote host and vice versa. scp, allows you to copy files securely from one host to another, is a replacement for the rep program.
