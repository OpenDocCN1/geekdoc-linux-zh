# The Description of ftpconversions

The last parameter of ftpconversions, the description of the conversion, is a free-form entry in which you can describe the type of conversion.

# Example of an ftpconversions Entry

The following is a sample entry that contains files using gzip on demand. This allows someone who wants to get the file orb_discography.tar to instead request the file orb_discography.tar.gz and have the server compress the file by gzip before sending it. The configuration line that does this follows:

```
: ..gz:/bin/gzip -9 -c s:$T_REG:0_COMPRESS:$GZIP
```

The first two parameters are not necessary because you don't want to remove anything from the filename before sending it to the requester. The third parameter is empty because you don't want to add any strings to the beginning of the filename before sending it. The fourth parameter, though, does the string .gz suffix to the filename before sending it. The fifth parameter is the actual command used to compress the file. The -9 option tells gzip to compress the file as much as it can; -c sends the compressed file to the standard output; and % is replaced by the server from which the filename is requested (for example, orb_discography.tar). T_REG in the sixth parameter tells the server to treat the file as a normal file rather than an ASCII file or directory. The second-to-last parameter, O_COMPRESS, tells the server that the action being taken is compression. The parameter is simply a comment for the administrator so he or she can quickly determine the action being taken.

A daunting, isn't it? Don't worry, the sample ftpconversions file that came with the server package provides additional examples of using tar and gzip. In fact, many sites never need to add to this file because it covers the most popular conversion requests made.

# Configuring Host Access—The ftphosts File

The ftphosts file establishes rules on a per-user basis, determining which users are allowed to log in from specific hosts.

Each line in the file can be one of two commands:

```
allow <username> <addrglob>
```

```
deny <username> <addrglob>
```
