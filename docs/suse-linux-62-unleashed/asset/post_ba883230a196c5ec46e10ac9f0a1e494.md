If you allow other machines on your local area network or machines connecting through a remote access server on your machine to read news collected by your system, you need to add their names to the /etc/news/nnrp.access file. This file is read when the nnrp daemon starts for each person invoking a newsreader. The nnrp.access file contains a list of all the machines that are allowed to read news from your server and follows this syntax:

```
name:perms:password:newsgroup
```

name is the address of the machine that you are allowing to read news. You can use wildcards to allow entire subsets. perms is the permissions and one of the following values: Read (for read-only access), Post (to allow posting of messages), or Read Post (for both Read and Post). user authenticates a username before it is allowed to post, and password accomplishes the same task. To prevent a user from posting messages through your server, leave user and password as spaces so they can't be matched.

newsgroup is a pattern of newsgroup names that can be either read or not read, depending on how you set up the contents. Access to newsgroups uses wildcards, comp* allows access to all newsgroups starting with comp, where sex disables access to any newsgroups starting with the word sex. The default setting in the nnrp.access file is to prevent all access. To allow all users in the domain tpci.com to read and post news with no authentication required, add the following line to:

```
*tpci.com:Read Post::*
```

To open the news system to everyone on your system regardless of domain name, use an asterisk of a domain name.

# Introduction to NNTPCache

As mentioned before, many companies and individuals run NNTPCache instead of getting a full newsfeed. This is because NNTPCache saves money. The NNTPCache described in this chapter is probably the most popular. At the time of writing, NNTPCache was not shipping with SuSE Linux, but it is easily downloadable from http://www.nntpcache.org. it should be noted that NNTPCache is free for individuals and non-profit organizations, but it should be licensed for commercial environments. See the LICENSING file in the directory for more information.

# How NNTPCache Works

NNTPCache was designed to look a regular NNRP-based server that any newsreader can connect to—but with a difference. If you are configuring the default news server that NNTPCache gets its articles from; this is normally your ISP's news server. For example, if you are reading the comp..linux.advocacy newsgroup each article you choose to read is retrieved from your default news server and a copy is kept on your NNTPCache server—this process is called caching the articles.

Not only articles are cached, but the news server's active lists are as well. An active list is the current newsgroup listing for that particular news server. This is useful because the list doesn't have to be refreshed every time you open your newsreader.

Another NNTPCache feature is that it can connect to multiple news servers. There are a number of public news servers that are usually related to a particular topic. For example Microsoft provides a news server called msnews.microsoft.com and has specific newsgroups on Microsoft-related topics (Newsgroups are named microsoft.*) SuSE has a news server, but it is not publicly accessible. To make full use of this neat feature, configure NNTPCache to talk to specific servers and link newsgroups with these servers. When you are at the reader, it makes browsing through all the different news servers transparent, and it caches all for you.

Obviously, make full use of NNTPCache's caching abilities, you will need a reasonably permanent internet connection and many people using your NNTPCache. Even if you use casual dial-up connections, it is still of use. You might, however, want to configure NNTPCache to a smaller amount of disk space for its cache, or turn off altogether.

# Downloading and Configuring NNTPCache

NNTPCache is not part of the standard SuSE 6.2 distribution, you have to download it. This is a pretty simple process because the source can be downloaded from the NNTPCache Web site. Go to http://www.nntpcache.org/source.html and scroll down to where it mentions the source for 2.3.3; download it onto your machine. The RPM is not suitable as it is designed for Red Hat rather than SuSE.

Once you have the NNTPCache RPM downloaded, you need to install it with the following commands:

```
tar zf nntpcache-2.3.3.tar.gz
cd nntpcache-2.3.3
./configure ; make
```

As root, do the following:

```
make install
```

This installs the configuration files under /etc/nntpcache, some documentation in /usr/doc/nntpcache-1.0.7.1-1, and the NNTPCache server that does all the work in /usr/bin. Of course, the appropriate startup files are installed in the /sbin/init.d tree.

After this, you can delete the sources:

```
rm -r nntpcache-2.3.3*
```

Getting up and running should not take very long. Go into the /etc/nntpcache directory and enter the ls command:

```
root@nntpcache]# ls -l
total 26
-rw-r-- 1 news 3584 Apr 27 23:05 access
-rw-r-- 1 news 9315 Apr 27 23:04 config
-rw-r-- 1 news 862 Apr 30 22:11 servers
-rw-r-- 1 news 998 Jan 21 spam.filter
```

There are three main configuration files: access, config, and servers. There is another file, spam.filter, which contains special strings that help filter out junk. The first file to configure is the access file. Hosts that are allowed to use NNTPCache are named here. You can specify permissions for the hosts specified here.
