Although strictly DocBook-related, it's still worth mentioning that using unencrypted methods to move files about is a Very Bad Idea as a general rule. FTP is a very insecure method of transport these days. If you need to use FTP instead of SSH and SCP, use logins and passwords that are exclusive to FTP.

For instance, if your system login is bobsmith, you don't want to use that for FTP. Instead, set up (or have your system administrator set up) an account as book or editor for FTP files back and forth. The permissions for the FTP account should be such that they are allowed to do only FTP. If someone snoops the FTP password, he or she cannot, without further effort, log in to a shell on the system.

You should always remember that revision control is a great substitute for e-mailing code or copy back and forth, but it is not a substitute for good communication. For best practice purposes, when planning a revision control system, set up a regular communication schedule to discuss any major issue between your contributors.

Another item to consider if you choose to implement a version control system. RCS and CVS were both developed to deal specifically with text files. If your project includes graphical figures, you will have to design or implement a different system to manage them. CVS can also handle binary files allowing you to manage multiple revisions with the only limitation being you cannot diff against the files.

# Revision Control for Group Projects

As we've already discussed, the benefits of version control systems are aimed at large projects, typically with multiple contributors. Whether you opt for the simple, direct solution of RCS, allowing you to simply manage the project files, or a more complex solution with CVS, allowing you to have multiple people working from multiple branches of code simultaneously, in the long run you will have more efficiently completed your project.
