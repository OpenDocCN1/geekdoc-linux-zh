# Fun with Errors

Okay, computer errors usually aren't fun. Sometimes it's amusing when they happen to someone else, but they're never fun when they happen to us. It's a fact of life, though, occasionally when you're working with computers you're going to get some type of error message. Life is a little better if the documentation that comes with software actually covers the possible errors and explains what they mean, instead of a cryptic and undocumented error code that makes the users scratch their head and wonder why they didn't buy their competitor's software.

DocBook has few elements that are concerned with errors, namely the ErrorCode, ErrorName and ErrorType elements. The ErrorCode element is used to hold the error code, usually a numeric code. The ErrorName element is kind of misleading; not necessarily the name of the error, but the message that the user sees. The ErrorType element can be used to indicate the kind of error, whether it is critical or if it can be ignored or somewhere in. Here is an example of using DocBook markup to describe an error.

```
<para>If you try to use <command>apt-get</command> when logged in as a regular user you will get the following error message:</para>
<para><computeroutput><errname>E: Could not open lock file /var/lib/dpkg/lock - open (13 Permission denied)</</errname></computeroutput></para>
<para><computeroutput><errname>E: Unable to lock the administration directory, where you root</</errname></computeroutput></para>
<para>The <code>-13 Permission denied</</code> is <errortype>recoverable</errortype>. You can avoid the <command>sudo</command> to log in as root before trying to use <command>apt-get</command>.</para>
```
