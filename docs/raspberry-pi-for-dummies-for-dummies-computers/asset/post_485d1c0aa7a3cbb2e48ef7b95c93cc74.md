You can get NeoPixels in conventional LED packages – not the surface mount type, in other words as well as the DotStar's 5mm-square packages. Both are available as individual parts as well as long strips of LEDs. The major difference between the two lies in how they take their commands from the computer. The NeoPixel requires one signal wire, and the DotStar requires two. Given that fact, you might be forgiven for thinking that NeoPixels are easier to use. The problem is twofold:

- This signal wire needs to be controlled to give a precisely timed pulse.
- The Raspberry Pi, with its Linux operating system, is not good at precise timing.

There are ways around this with the help of various libraries, but around comes at a price. The library from Adafruit works with the original Model 1 Raspberry Pi as well as the Pi Zero, and the one from Pimoroni, working on all models of Pi, uses the hardware that normally generate the audio for the jack socket. (You can still get sound from the HDMI connector, but not from the audio jack because it can cause the LEDs to flash randomly.)

The DotStar requires two signals and uses the sequence of transitions for the data transfer process. This is ideal for system like the Raspberry Pi, because of Linux, there might be a longer-than-expected delay before the next line of code is executed. The APA102C LEDs are wired together in a chain, with the signals regenerated by each LED. The signals never "get tired," or as we say in electronics, degrade.

![](img/df9a01bf057d58c2401b5edabd6e8829_379_0.png)

Each LED has a Data In and a Data Out line as a Clock In and Clock Out. The inputs of the first chip are all connected to the GPIO pins of the Raspberry Pi. Both types of LED work on the principle that an LED has received and stored its data, any data it receives is passed to the next LED. So, after the first set of data is sent to the first LED, there has to be sort of reset condition in order to regulate situations where new data is meant for the first LED and not just data for LEDs down the chain. The reset is done by passing the data stream for 5us (microseconds) on the WS2812b LEDs and sending a stream of start and end pulses in the case of the APA102C LEDs. (The wiring of the WS2812b is very similar to the wiring of the APA102C except that there's only one data in and out.)

Figure 17-6 shows the timing diagram for each LED — a picture of how logic signal will change to indicate one logic, logic zero or the end of a data set.

![](img/df9a01bf057d58c2401b5edabd6e8829_379_1.png)

For the WS2812b, in order for the single wire to write a Logic One to the LED, the signal makes a jump to a Logic One and stops for 3.5uS before jumping down to a Logic Zero for 0.9uS. For a Logic Zero, the signal jumps to a one for 0.9uS and then drops to 3.5uS. This repeats until all the data has been transferred to the LEDs. The end of the data transmission is signaled by a zero held for at 50us. These times have to be +/- 0.15uS to ensure correct operation.

The APA102C, on the other hand, has two signals, clock and data, which can go at any speed. The important point is that when the clock signal rises transitions from zero to a one, in other words — whatever level on the data input at that moment is treated as the logic input. Doing this requires special being about the timing; you have to put the GPIO pins at the correct levels in the right order.

Programmers have a special name they use implementing a protocol like this — is bit-banging.(The technical term for this protocol is SPI, or Serial Peripheral Interface.) There's some hardware on the processor chip to do this, but it requires a specific set of pins running in one of the alternative methods. The great thing about bit-banging is that you can use any pins. Let's see how we can bit-bang this protocol on the GPIO bus.

## Bit-banging the APA102C protocol

The LEDs used in our example are connected together in a string, where one LED takes its input from the output of the previous one. The first LED in the string takes its data from the Pi. Each LED the string can be thought of as having a number or address. When we send out data, we send it to all the LEDs, but we need to change the data for those LEDs that we want to. If the data for an individual LED is the same as last, it will not change. That way, we can change individual LEDs by changing the data for those LEDs we want to and leaving the data for the others, same as last.

The APA102C — in addition to the normal red, green, and blue values, which controls the brightness — has another brightness-controlling number, which controls the current down the LED. Valid brightness numbers range from 0 to 31. Each LED needs data to be stored in the computer in what is known as a buffer. In Python, we can implement this buffer as a list. We can then manipulate this list, in other words — to reflect what we want on each LED. When we're good and ready, we fire out the whole buffer to the string of LEDs.

Let's look at what to put in this buffer. A complete message has a header used to warn the LEDs that data is coming. That header contains 32 bits of zero, which means the data pin needs to be set at zero and the clock pin to be pulled up and down 32 times. The data is pulled out of the list, one number at a time. This is a 32-bit number—each bit in turn is placed on the output pin and the clock signal is set to High. When all the LEDs have been fed, another series of zeros, known as a footer, are sent. This needs to consist of at least 32 plus half the number of LEDs, to be precise. The code using it is a fragment that would do this:

LISTING 17-2: Bit-Banging the Data to the LED

```python
io.output(da,LOW) # set data pin low
for i in range(0,32): # send header
io.output(ck,LOW) # pulse the clock pin
io.output(ck,HIGH)
for i in range(0,numLeds): # send data
    d = ledArray[i] # get a single LED's worth of data
    for j in range(0,32):
        io.output(ck,LOW)
        if d & 0x8000000:
            io.output(da,HIGH)
        else:
            io.output(da,LOW)
        d = d << 1
        io.output(ck,HIGH)
for i in range(0,32+(numLeds/2)): # send footer
io.output(ck,LOW)
io.output(ck,HIGH)
```

Note that this is a fragment and not a complete program. Note also that this code uses the shift operator (<<), which moves the data word, or pattern, to the left so that the next byte to send is in the most significant bit of the word. This is the same technique we show how to use in forming the pattern in Chapter 16.

## Creating a class

The bit-banging code is so useful that it could be included in all programs where you want to use these LEDs. However, in order to make it convenient to use, we can make this code into a class you don't have to keep including these lines in your programs. This is just like the RPi.GPIO library, which is written as a class installed in Python. You can write your own classes and have them included in the language or, as we do here, just have the class file in the same folder as the program that uses it and then call it at the start of the program. As well as putting the data to the GPIO pins, we can bundle other useful stuff in the class, ways to set the brightness, set an LED's color, and set the data buffer. Functions of a class are known as *methods* and can be simply invoked. Listing 17-3 shows the implementation of a bit-banging class for the APA102 LED. Save it in a file called `apa102.py` along with the other code from the rest of the chapter.

LISTING 17-3: Bit-Banging the APA102 Class

```python
#!/usr/bin/env python3
# Class for driving APA102 LEDs
# By Mike Cook

import RPI.GPIO as io
io.setwarnings(False)

class APA102bang(): # Define our class
    def __init__(self,numLeds,data,clock,bright):
        self.setBrightness(bright)
        self.da = data
        self.ck = clock
        self.numLeds = numLeds
        io.setmode(io.BCM)
        io.setup(self.ck, io.OUT)
        io.setup(self.da, io.OUT)
        io.output(self.ck, io.HIGH)
        io.output(self.da, io.HIGH)
        self.ledArray = [self.br<<24 for i in range(0,self.numLeds)]

    def setBrightness(self,bright):
        if brightness > 31:
            brightness = 31
        if brightness < 0:
            brightness = 0
        self.br = brightness | 0xE0

    def setLed(self,pos,col):
        if pos < self.numLeds and pos >= 0:
            self.ledArray[pos] = (self.br<<24)|(col[2]<<16)|(col[1]<<8)|col[0])
```
