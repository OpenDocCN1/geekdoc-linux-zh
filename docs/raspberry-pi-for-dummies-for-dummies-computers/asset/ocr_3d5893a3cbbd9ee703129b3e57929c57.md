For the WS2812b, in order for the single wire to write a Logic One to the LED, the signal makes a jump to a Logic One and stops for 3.5uS before jumping down to a Logic Zero for 0.9uS. For a Logic Zero, the signal jumps to a one for 0.9uS and then drops to 3.5uS. This repeats until all the data has been transferred to the LEDs. The end of the data transmission is signaled by a zero held for at 50us. These times have to be +/- 0.15uS to ensure correct operation.

The APA102C, on the other hand, has two signals, clock and data, which can go at any speed. The important point is that when the clock signal rises transitions from zero to a one, in other words — whatever level on the data input at that moment is treated as the logic input. Doing this requires special being about the timing; you have to put the GPIO pins at the correct levels in the right order.

Programmers have a special name they use implementing a protocol like this — is bit-banging.(The technical term for this protocol is SPI, or Serial Peripheral Interface.) There's some hardware on the processor chip to do this, but it requires a specific set of pins running in one of the alternative methods. The great thing about bit-banging is that you can use any pins. Let's see how we can bit-bang this protocol on the GPIO bus.

# Bit-banding the APA102C protocol

The LEDs used in our example are connected together in a string, where one LED takes its input from the output of the previous one. The first LED in the string takes its data from the Pi. Each LED the string can be thought of as having a number or address. When we send out data, we send it to all the LEDs, but we need to change the data for those LEDs that we want to change. If the data for an individual LED is the same as last, it will not change. That way, we can change individual LEDs by changing the data for those LEDs we want to change and leaving the data for the others, as same as last time.

The APA102C — in addition to the normal red, green, and blue PWM values, which controls the brightness — has another brightness-controlling number, which controls the current down the LED. This is the equivalent of changing the resistor value. Valid brightness-control numbers range from 0 to 31. Each LED needs data consisting of four numbers: brightness plus red, green, and blue values. Data needs to be stored in the computer in what is known as a buffer. In Python, we can implement this buffer as a list. We can then manipulate this list — change the numbers in it, in other words — to reflect what we want to see on each LED. When we're good and ready, we fire out the whole buffer to the string of LEDs.
