## Using lists to make a random chat program

After you've mastered the list structure, you can create a simple chat program. For this first version, you take some input from the user, display a random response, and then replace random response with whatever the user types.

Here's the program that does that. It introduces a few new ideas, but we will talk through them shortly:

- Chatbot – random-only version
- Example program from Raspberry Pi For Dummies

```python
import random

random_replies = ["Oh really?",
"Are you sure about that?",
"Hmmmmm",
"Interesting...",
"I'm not sure I agree with that...",
"Definitely!",
"Maybe!",
"So what are you saying, exactly?",
"Meaning what?",
"You're probably right.",
"Rubbish! Absolute nonsense",
"Anyway, what are your plans for tomorrow?",
"I was just for the computer to display.

The next part of the program creates a list `random_replies`, which contains statements the computer output in response to whatever the user enters. You can personalize this by changing the responses or by adding more. The more responses there are, the more effective the illusion of intelligence is, but for this, we've kept the light fairly short. It doesn't matter what the responses are in, but keep an eye on those commas at the end of each line. After printing a short line that invites the user to chat with the computer with what's on their mind, you request input from them using the `input()`. Whatever the user enters is stored in a variable called `user_says`. The next line picks an index for the random response. To understand how this works, it helps to break it down. First, you need to know how to generate random numbers. You give the `randint()` function two integers to work with (or arguments). The two numbers specify how big you want your random number to be: The first is the lowest possible value, and the second is the highest possible number. For example, if you want to display a random number between 1 and 10, you would

```python
print(random.randint(1, 10))
```

You can run this multiple times to confirm that it works. Sometimes the numbers repeat, but that's the nature of random numbers. It's like rolling the dice in Monopoly: Sometimes you're stuck in jail, and sometimes you throw doubles.

The range of numbers you want to use for the random number is the size of the `random_replies` list. You can use the `len()` function to see what this is, so you can add things to your list or remove them without having to worry about updating your program. In the `random.randint()` statement, you replace the second number with the length of the list:

```python
print(random.randint(1, len(random_replies)))
```

You don't want to just print the result onscreen, however so you store the number chosen in a variable called `reply_chosen`.

There's one, final twist: Because list indices start at 0, you need to subtract 1 from the random number. Otherwise, the program would never choose the first list item, and would want instead to choose one at the end of the list that isn't there. Here's the final command:

```python
reply_chosen = random.randint(1, len(random_replies)) - 1
```

The two lines print the randomly selected item and then replace that list item with whatever the user entered:

```python
print(random_replies[reply_chosen])
random_replies[reply_chosen] = user_says
```

You can run the program to test it, but one thing is missing. At the moment, it gives you one line before finishing. To fix that, you need to master the while loop.

## Adding a while loop

Previously, we showed you how to use the for loop to repeat a code of set number of times. To repeat a block as long as a condition is true, we use the while loop. In our chatbot, we want the conversation to continue until the user types bye. To do this, we add a while loop to the following code:

```python
user_says = ""
while user_says != "bye":
    user_says = input("Talk to me: ")
    reply_chosen = random.randint(1, len(random_replies)) - 1
    print(random_replies[reply_chosen])
    random_replies[reply_chosen] = user_says
```

The while command tells Python to repeat the indented block as long the second half of the while command is true. The `!=` operator means not equal to. In our chatbot, the second half of the while command is `user_says != "bye"`, which means the block below should keep repeating as long the contents of `user_says` are not equal to bye. To use `user_says` variable in the while command, you need set it up before it triggers an error. Immediately before the while command, you create the variable and give it a blank value `user_says = ""` just to get the program past the while command and into the loop. Almost immediately, it changes when the user types something — but that doesn't matter.

If you run the program now, you should find that the conversation rambles until you type bye. Remember that you can improve the quality of the experiment by adding more sayings in the program's list of replies.

## Using a loop to force a reply from the user

Another trick you can perform with the while loop is to make sure the user doesn't press Enter without putting anything in, either accidentally or deliberately. That protects the extremely high quality of the random list (achem!) in more complex programs, preventing entries from being added to it. A quality-check like this one can be essential for preventing errors.

You can put loops inside loops, which are nested. In this case, we'll have a small loop that keeps asking for input until it receives, running inside the bigger loop that repeats the whole process until the user enters bye.

To see whether something is equal to something else, use two equals signs together (`==`). This can be confusing to new programmers, but a single equal sign is only used to assign a value to something, such as when putting a value into a variable. When you want to compare the value of two things to see whether they're the same, you use two equal signs. In English, we use the word, but they're completely different ideas when you think about it, and Python considers them as separate and unique concepts.
