# Deleting Files

After experimenting with creating files and directories, you probably have odd bits of file and meaningless directories all over the place, so it's time to tidy up.

To delete files in Linux, you use the rm command, short for remove. Use it carefully. There's no trash or recycle bin to recover your file from again, when it's gone, it's gone. Actually, Linux users might be able to get it back using specialized software and huge amounts of time and patience, so it's not a secure deletion. But for an average user without access to such software and expertise, when you tell Linux to remove a file, it acts fast and decisively.

The rm command has this format:

```
rm options filename
```

As mkdir, the command doesn't tell you what it's doing unless you use the verbose option (-v). As an example, you could remove a file called letter.txt using

```
pi@raspberry ~ $ rm -v letter.txt
removed 'letter.txt'
```

Like mkdir, running the rm command can take several arguments, which means it can remove several files at once if you list all of them, names: for:

```
pi@raspberry ~ $ rm -v letter.txt letter2.txt
removed 'letter.txt'
removed 'letter2.txt'
```

This is where to be extremely careful. Imagine that you have two files called old.index and index.html. The latter is your new home page, which you've toiled over all weekend. (You can see where this is going, can't you?) You want to clear out the old development file, so use this command:

```
pi@raspberry ~ $ rm -v old index.html
rm cannot remove 'old': No such file or directory
removed 'index.html'
```

Arrrrgh! Because of that space in the old index.html filename, the rm command thinks that you wanted to remove two files — one old called and the other called index.html. It tells you it can't find the file called old, but goes right ahead and wipes out index.html. Nasty!
