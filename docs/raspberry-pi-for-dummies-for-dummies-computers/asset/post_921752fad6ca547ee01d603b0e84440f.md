
# Raspi-config can help with

- **Keyboard configuration:** Under Internationalisation Options, you can select your keyboard type. You can also use the Localisation options in the Raspberry Pi Configuration tool, as described in Chapter 3.

- **Camera problems:** Ensure the camera is enabled in Raspi-config. You can also enable the camera from the Interfaces section of the Raspberry Pi Configuration tool. (See Chapter 3.)

- **Audio problems:** In Advanced Options, you can force the audio to use the headphone jack or HDMI output.

- **Missing space on the card:** If you created your card by *imaging*, a different process to NOOBs involves copying a snapshot of the software to the card, you might need to expand the file system to use all the space available. Under Advanced Options, choose Expand Files.

The shell is covered in Chapter 5, but in brief, it is the way of giving instructions to your Raspberry Pi. You can open the shell by clicking the Terminal icon at the top of the screen in the desktop environment.

Raspi-config and the Raspberry Pi Configuration tool can make changes for you without having to edit any configuration files, so it's more convenient than editing `config.txt` yourself, and there is less risk of error too. If the option isn't configured on the Raspi-config menu, you need to edit the configuration file manually.

Before you start tampering with the `config.txt` file, make sure you've backed up any important data on your Raspberry Pi. (See "Mounting External Storage Devices" in this appendix and the section about backing up your data in Chapter 4.) There is a risk that you could, for example, render the screen display unreachable, which would make it difficult to use the Raspberry Pi to access your files.

# Using Nano to edit config.txt

To open the `config.txt` file in the Nano editor, enter the following command in the shell, all in lowercase:

```
sudo nano /boot/config.txt
```

The Nano text editor, with `config.txt` open, looks like Figure A-1.

![](img/df9a01bf057d58c2401b5edabd6e8829_465_0.png)

# FIGURE A-1:
The Nano text editor with the config.txt file open.

Use the cursor keys to move around the document. At the bottom of the window is a menu explaining Nano's controls, where the upward arrow represents the Control key. The shortcuts here are different from what you might be used to, but the main ones you should know about:

- **Ctrl+W:** Search for a word or phrase. This option (short for Where Is?) enables you to jump straight to the configuration option you want to edit.
- **Ctrl+V:** Next page.
- **Ctrl+K:** Cut the current row of text.
- **Ctrl+U:** Uncut text, which means paste the text you previously cut at your cursor's location.
- **Ctrl+G:** Get help, which provides more detailed instructions.
- **Ctrl+O:** Write out, or save, the current file.
- **Ctrl+X:** Exit Nano and return to the shell.

The first thing you'll notice about config.txt is that the # (hash symbol) is used at the start of many lines. This symbol has a special meaning to the computer, which "Ignore the rest of this line." You might wonder why anyone would enter information into a computer enough, he wants it to ignore, but this concept is often used (not often enough, some would say) to help the human users of a particular program or file. Any line with a = symbol at the start of it isn't actually doing anything, but it's there to guide you as you edit config.txt. Lines like these are called comments. (They are also used in Python, as you see in Chapter 11).

The first two lines in config.txt say:

```
# uncomment if you get no picture on HDMI for a =
#default="safe" mode
#hdmi_safe=1
```

The first line is obviously intended for you to read, but the second line shows the settings you need to use the HDMI Safe mode on. This takes the form that all settings in config.txt do — namely:

```
setting_name=value
```

Each setting needs a line of its own. If you wanted to turn the HDMI Safe mode on, you would remove the comment symbol (the hash mark) from the second line, or "uncomment" line, that the first two lines now read:

```
# uncomment if you get no picture on HDMI for a =
default="safe" mode
hdmi_safe=1
```

Don't remove the = symbol from the line of instructions. It remains a comment that's intelligible only to human readers. You should remove the = symbol from lines you want the computer to do with something.

![](img/df9a01bf057d58c2401b5edabd6e8829_466_0.png)

Just taking out that single hash mark makes all the difference! Save the file (Ctrl+O) and reboot the computer, and Safe mode is activated. You can reboot the Raspberry Pi with the following command:

```
sudo reboot
```

If you need to disable a setting, you can just put a # symbol in front of it to turn your line into a comment. You can add your own comments too. It's a good idea to add a line starting with a # to remind yourself what you changed and in case you need to change the settings back.

# Troubleshooting screen display

The Raspberry Pi can be used with a wide variety of TVs and monitors, which means the computer should automatically adjust its output to the screen, but there might be times when you want to fine-tune its settings, override defaults, or force your preference. If you're experiencing difficulties getting a consistent and clear image, try adjusting one or more of the settings in Table A-1.

### Table A-1 Troubleshooting Screen Issues

| Symptom or Issue | Setting to Change | Values Use |
| :--- | :--- | :--- |
| Image spills off left of screen. | overscan_left | Overscan is a feature that changes the size of the image to fill the screen. The overscan settings are all set using pixels, for example, overscan_left=0 |
| Image spills off right of screen. | overscan_right | The overscan is using pixels, for example, overscan_right=50. |
| Image spills off top of screen. | overscan_top | The overscan is using pixels, for example, overscan_top=50. |
| Image spills off bottom of screen. | overscan_bottom | The overscan is using pixels, for example, overscan_bottom=50. |
| Image has a black border around it. | disable_overscan | Use a value of 1 to disable overscan, like: disable_overscan=1. |
| Text or other content is too small. | framebuffer_width / framebuffer_height | See "Adjusting the screen display," later in this appendix. |
| Text or other content is too big. | framebuffer_width / framebuffer_height | See "Adjusting the screen display," later in this appendix. |
| Picture fails using an analog TV. | tv_mode | The composite video output is NTSC by default, which is used in North America. You may need to change this setting for use in other regions. Valid values are 0 for NTSC, 1 for NTSC-j for Japan, 2 for PAL-M (used in the U.K. and most of Europe), or 3 for PAL-M (used in Brazil). For example, tv_mode=2. |
| Picture is stretched or squashed on TV. Aspect ratio looks wrong. | tv_aspect | The aspect ratio of the image is the ratio between the width and height of the image. There are three valid values for this setting: 1 (for the aspect ratio 4:3), 2 (for the aspect ratio 14:9), and 3 (for the aspect ratio 16:9). Usage example: tv_aspect=2. |
| HDMI screen is blank. | hdmi_force_hotplug | If the Raspberry Pi can't detect a HDMI monitor, you can force it out through the HDMI connector by setting this value to 1, like: hdmi_force_hotplug=1. |
| DVI monitor is snowy or blown out. | hdmi_drive | This setting adjusts the output of the HDMI port. If you're using a DVI monitor, try a value of 1. If you're using an HDMI monitor, use a value of 2. Example: hdmi_drive=1. |
| No audio through computer monitor. | hdmi_drive | Use value of 2 for HDMI mode and define how audio down the HDMI cable, like: hdmi_drive=2. |
| Picture blanks, interference, or is missing. | config_hdmi_boost | Typical ranges from 1 to 7 and define how much power is output through the HDMI port. Increasing the value progressively. The HDMI safe mode uses a value of 4 for this setting. If you're using a long cable, you can use the maximum value of 11, avoid using high values unless strictly required. Usage example: config_hdmi_boost=4. |
| Any problems using HDMI monitor. | hdmi_safe | If you experience problems using an HDMI monitor, try using Safe Mode. Set hdmi_force_hotplug to 0 to force output to the HDMI port, set config_hdmi_boost to 4 to boost the power, and set the hdmi_mode and hdmi_group settings to a generally safe combination. These settings are used to override the HDMI screen resolution. For more details on the settings, use http://elinux.org/RPI_config.txt. To enable HDMI Safe mode, use: hdmi_safe=1. |
