given X and Y are the coordinates you want to get the LED number for and that Xmax is the number of LEDs in a row. Of course, this assumes that both coordinates are within the confines of the matrix. In practice, it is necessary to check the coordinates before calculating the LED number.

The serpentine row is physically easier to wire up, but a little more complicated to work out an LED number. This is because the preceding conversion works on odd-numbered rows. For even-numbered rows, you need to use this:

```
LEDNumber = (Xmax - X - 1) + (Y * Xmax)
```

That means any routine must first test to see if the y-coordinate is indicating an odd or even row before choosing the formula to use. This is simply by looking at the least significant bit — the right hand bit in the number of the y-coordinate.

Other graphics can help you draw things on a matrix. Perhaps the most fundamental is *drawing*, given a start and an end coordinate pair, you can draw a line of lit LEDs between them. Of course, on a small matrix, horizontal, vertical, and 45-degree diagonal lines will look good; all other lines will be stepped, or jagged. The trick is to work out the difference between the start and end points; the axis with the biggest difference is given an increment value of the smaller size over the longer length. Then the x-coordinate to plot starts at the initial point of the line, and subsequent points are found by repeatedly adding the increments to the respective coordinates. One of the increments will be 1, and another fractional value. It is only when the size of this fractional coordinate exceeds a whole that the coordinate is changed.

We could have used the line primitive to implement these two functions, but drawing horizontal and vertical lines is much quicker with a simple loop because division is needed.
