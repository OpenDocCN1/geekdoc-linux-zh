
## Adjusting the screen display

You can adjust the width and height of the screen display, measured in pixels. When the width and height values are smaller, the onscreen content appears bigger. The screen display is adjusted using the framebuffer_width and framebuffer_height. To change the screen display size to 1024×768, for example, use

```
framebuffer_width=1024
framebuffer_height=768
```

There is a concern for these settings in the config.txt file, you can edit the lines that are already there. As well as changing values to your chosen width and height, don't forget to remove the # symbol at the start of both lines to activate these settings.

These settings can also be adjusted from the desktop using the Raspberry Pi Configuration tool (see Chapter 3). Select Set Resolution.

## Exploring more advanced settings

There are many settings you can control on the Raspberry Pi through the config.txt file, but we don't have space to document them all. You can find a more detailed list at http://linux.org/RPI_config.txt.

## Fixing Audio Problems

In the desktop environment, you can use the Speaker icon in the top right to adjust the volume of sound and mute or unmute it. In the command line, you can call up a utility to adjust this sound:

```
sudo alsamixer
```

Use the cursor or the mouse scroll wheel to adjust the volume.

The sound output device is automatically detected. Note that if you're using HDMI to connect to a speaker, the audio be directed there by default, even if the monitor does not have speakers. You can use the audio options in Rasp-config (found under Advanced Options) to direct the audio to the headphone jack or the HDMI cable. In LibreLEC (see Chapter 8), you can click the cogwheel at the top of the menu to go into Settings, choose System Settings, and click Audio to find the option to change the output device.

## Mounting External Storage Devices

When you plug in an external storage device such as a USB key or flash drive, the desktop environment recognizes it automatically and opens it in File Manager for you. Not when using the shell. You need to mount the device, which means you need to connect the device to a folder in the directory tree where you want to browse its contents.

![](img/df9a01bf057d58c2401b5edabd6e8829_470_0.png)

If your only goal is to back up your data to an external storage device, it's probably easier to use File Manager or the SD Card Copier application in the desktop environment. (See Chapter 4.)

To use external storage in the shell, you first need to create a directory that will be the mount point for the USB key, which means when you look in that directory, you are actually looking at the contents of the external storage device. You can reuse this directory, the first time you mount a device, you need to create the directory. You can create this directory anywhere (inside your home directory), but to contain temporary devices in the /mnt directory:

```
sudo mkdir /mnt/usbdrive
```

Next, you need to investigate the device you're connecting. To do that, consider your storage device and then enter this command:

```
sudo fdisk -l
```

The last character of this command is a letter l! (lowercase l), and not a number 1. The output should look something like this:

| Device | Start | End | Blocks | ID | System |
|---|---|---|---|---|---|
| /dev/mmcb1p0 | 8192 | 122879 | 57344 | c | W05 FAT32 (LBA) |
| /dev/mmcb1p2 | 122880 | 7862271 | 3896996 | 83 | Linux |

Disk /dev/sda: 16.0 GB, 1603769920 bytes
32 heads, 63 sectors/track, 15537 cylinders, total 31324160 sectors
Units = sectors of 1 * 512 = 512 bytes
Size (logical/physical): 512 bytes / 512 bytes
I/O size (minimum/optimal): 512 bytes / 512 bytes
Disk identifier: @0x1707000e

| Device Boot | Start | End | Blocks | Id | System |
| /dev/sda | * | 63 | 3132591 | 1566264+ | c | W05 FAT32 (LBA) |

This lists the different storage devices that are connected to the Pi. In the example, you can see the first disk (/dev/mmcblk0) is 4025 MB, which is a 4GB SD card, and the second one (/dev/sda) is 16GB, which is a USB key we connected. The important information we need is from this device and the partition number, which is shown at the bottom of the output and is sda1.

To mount the driver for the user pi (uid=pi) and the group pi (gid=pi), we then use

```
sudo mount -o uid=pi,gid=pi /dev/sda1 /mnt/usbdrive
```

To view the contents of the USB key, you can then use

```
ls
```

To view the contents of the USB key, you can then use

```
ls /mnt/usbdrive
```

## Connecting Using SSH

If your Raspberry Pi has a network connection, you should be able to access it with another computer using Secure Shell (also known as SSH), which is a way to make a secure connection between computers. This can help if you have set your Pi to headless (without a screen). Here's how to set it up:

- 1. Change your password. To prevent unauthorized access to Raspberry Pi after a remote connection is enabled, start by changing your password. You can use the Raspberry Pi Configuration tool (see Chapter 3), or see Chapter 5 for instructions on changing the password in the command line.
- 2. Enable SSH on your Pi. Use the Raspberry Pi Configuration tool (see Chapter 3) to enable SSH on the Interfaces tab. Alternatively, use this instruction to create an empty file in the boot directory called ssh and reboot your Pi:
- 3. Get your Pi's IP address. Use ifconfig in the command line to get your Raspberry Pi's IP address (shown as inet.).
- 4. Connect from your other device. On a Windows PC, for example, you'll need to download an SSH client like Putty. In Putri, input the IP address of your Raspberry Pi and click the Open button. You can then use the command line on the Raspberry Pi to manage and fix files, viewing it through your PC screen and using your keyboard. Clients are also available for the iPhone/iPad and Android. The Mac does not need any additional software, but works through the terminal. You can find fuller instructions for SSH on your other machine at www.raspberrypi.org/documentation/remote-access/ssh.

```
sudo touch /boot/ssh
```

> You can only use SSH to access the Raspberry Pi command line, not the desktop.
