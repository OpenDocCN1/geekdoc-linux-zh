## The project

When doing any project, no matter how small, it pays to take one step at a time and test as you go. So, the first thing to do is to test your hardware before you get into anything fancy. You can simply extend the LED blink program to blink all the LEDs or, if you're not up to that, simply take the LED blink program and change the GPIO number to one you're using here. Run and see if the correct LED flashes, then stop the program and change to another number. Repeat until all the LEDs (as well as the push button) have been tested.

The project splits up into two parts: Generate the random number between 1 and 6 and then display it.

## The numbers

There are two ways to generate the random numbers: Use the computer's random-number generator or use some random event. The problem with the random-number generator is that it's not really a random-number generator. It's a pseudo random-number generator — the sequence of numbers is fixed and will repeat every time you run the program, unless you use it by picking a random starting point in this sequence. Because the sequence is very long, this approach will appear to be a random number. (The Python random-number generator uses as the seed the length of time the system has been powered on.)

However, a better way is to use something that is by its nature random: In this case, we use the length of time the user has pressed the button, indicating a new throw. You might not think this is random, because the user could just make a long press or a short press that would influence the number's produced. However, this doesn't take into account that the timing of a press can be very accurate and all six numbers are cycled through thousands of times a second. Controlling a button press with microsecond accuracy is simply not possible for slow humans, but it’s a good source of random numbers. Therefore, in our project, the number is generated by counting 1 to 6 while a push button is held down.

When a push button is first pushed, the contacts come together and bounce apart and then come together in a rapid sequence of contact make-and-break, rather like a ping-pong ball falling onto a table. This happens on all mechanical switches, but some designs are worse than others. A lot of the time in programming, this isn’t important because other stuff happens after a contact is first made. Other times, it could be a problem, but the solution can be quite simple—just delay for a few milliseconds after the first contact before looking at the input again. This strategy—known debouncing an input—is how we show you how to do in project.

## The display

Once you have generated a number, it must be displayed in the pattern of a conventional device. This involves turning on a specially selected pattern of LEDs. This pattern is, of course, for each number. Now, you could use a series of statements to test for each number, and when you find a match, write a series of statements to turn on and off the appropriate LEDs. An example of this for one number using the GPIO library would look like the code in Listing 16–7.

LISTING 16–7 Fragment of Code to Set a Pattern

```python
# the variable dice_number contains the number to display
if dice_number == 3: # make the three pattern
    led0.off()
    led1.off()
    led2.off()
    led3.off()
    led4.off()
    led5.off()
    led6.off()
if dice_number == 4: # if the number is four then
    led0.off()
    # ...... and so on
```

You can see that this listing is easy to read, but contains the most awful, turpis, repetitive code and is much longer than necessary. (This is typical of what a beginner might produce).

Turgidity is not confined to the GPIO Zero library — you can write bad code like this with any library.

You might wonder why it matters, as long as the code works. Well, if you can understand the concepts of doing it properly, you can apply them in situations where code will not work or is far too long. So even, before you begin to write any code, you need to know what LEDs to turn on and off to display each number. 16–12 shows the patterns we use to represent the dice pattern. Note that the main choice is which pattern is diagonal to use for representing 3 and 2. We think it's using the opposite diagonal for the numbers, but we have no preference for diagonal to use.
