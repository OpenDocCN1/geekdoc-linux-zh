## Enabling a sprite to control another sprite

In programming, you can choose between several ways to achieve the same effect. The game's firing mechanism is one such example. You could sense the spacebar (the Fire key) being pressed using a script on the fireball, for example, and then use that to trigger the fireball's ascent.

We use the firing mechanism as an opportunity to show how you can make one control sprite another, however. You can't actually make the ship move the fireball, but you can send a message to the ship to tell the fireball to move itself.

There are two parts to this: The first is that you need to use the Broadcast block on the ship to send a message to all the other sprites. You want to do this when the spacebar (the Fire button in this game) is pressed, so you need to drag an If block to the Scripts Area of your ship, add a Diamond sensing block to check whether the spacebar is pressed, and finally, put the Broadcast block inside the ship's rocket.

The Broadcast block, which is one of the Control blocks, has a menu built into it. Click the menu and click New to create a new message. We've called this *fire*.

This approach has a couple of advantages. First, you can keep all your game sprites on one sprite (the ship), which makes the program easier to manage. Second, it's an efficient way to coordinate multiple sprites. We could, for example, make our alien look terrified when the Fire button is pressed, by just changing its costume, and that requires only two blocks: A Control block for the message

fire is received, the block to change to a new costume which shows the alien looking scared. It's much more efficient than having to look out for the Fire button on the alien, too.

## Random Numbers

Scratch wouldn't be much fun if they were exactly the same, so Scratch enables you to use random numbers in your scripts. To keep players on their toes, you can make the alien appear at a random X position to the top of the screen.

Click your alien in the Sprite List, and drag in the Green Flag Control block. As with the other sprites, you need to create a script that resets the alien to its starting position. In the case of the alien, the sprite switches to a different costume when it's hit, so you should make sure it is using its normal costume at the start of a new game and that it is visible onscreen.

For its screen position, the alien needs to have a Y coordinate of 150, which is near the top of the screen. You don't want to use the full width of the Stage, because it looks odd when half the alien is off the edge of the Stage. ## Introducing Variables

Variables are a way of storing information in a program so that you can refer back to it or reuse it. You give that piece of information a name, and you can refer to it by that name. For example, if you want to keep a tally of the score, you use a variable to do that. They're called *variables* because their values can change over time. The score is at the start of the game, for example, and it goes up when the player hits an alien out of the sky.

You can tell your script to reset the score to zero when an alien is hit and display the score at the end. To create a variable, click the Variables button above the Blocks Palette. In the Blocks Palette itself is a button called Make Variable. Click that, and you will be asked to enter a name for the variable — in this case, use **score**.

You're also asked whether this variable is for all sprites or only the sprite you're working on. It's important to get this right. For the score, you want to make a variable that all your sprites can use. If you have a variable that's used by only one sprite, it's better to create a variable that's only for that sprite, it stops other sprites from being able to interfere with it. When you duplicate a sprite, you might find that you have sprites that use variables sharing the same name, but that you want to use independently of each other. You see an example of this later in this chapter, when we tell you how to add extras.
