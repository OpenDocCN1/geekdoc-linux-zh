Stepping through this program, first note that the GPIO pins are initialized and each pin in the list is given its own name. This makes the program easy to to read, although we could have used a “magic number” — a number that appears for no immediately apparent reason — an index in the GPIO list. In the infinite loop in the main function, traffic activity is measured and then the Cross button is looked at. The function checkRequest returns a value of True if the button is pressed. That means the function can be called directly inside if statement — there’s no need for intermediate variables. Also, if statement to see if a cross sequence is in operation by looking at the state variable (It's 0 if nothing is running). If a cross request has been made, the delay occurs if has been traffic activity in the last ten seconds, and then the state variable is changed to a value of 1.

In the next main loop, the crossSequenceFunction is called, which only returns if the state variable is 0; otherwise, the function looks to see if it's time to change the state. In the main loop, the bleep variable was looked at because it controls when the sounder should make a noise. This variable is set at State 3 of crossSequence and cleared at State 4. The crossSequenceFunction, for most steps, simply turns on or off various lights according to the required sequence. The exception to this is in State 5, where the cross and amber light need to flash. We do this by toggling the lights (Toggling means turning off a light that is on, and turning on a light that is off.) Rather than using variable to tell you set the light on or off, you can use a trick: Read the state of a GPIO output pin. The line
```python
io.output(amber,not(io.input(amber)))
```
sets the amber to the opposite of its current state. Before you can get out of State 5 and advance it to State 6, you must have flashes of the lights. Finally, in State 7, you set the traffic lights to green and return the state machine back to State 0, which indicates that the cross sequence is longer in progress.

## Chapter 17 Lots of Multicolored LEDs

Chapter 16 shows you how to control LEDs in terms of both patterns and sequences. We're going to get colorful and look at multicolored LEDs. We use different colors of LED in Chapter 16's Pedestrian Crossing project where each LED has its own color. Another type of LED contains three different colored LEDs in the same package. This type is known as an RGB LED because the three colors are red, green, and blue.

RGB LEDs come in three basic forms: common anode, common cathode, and separate. This last type, the least common, only comes in a small, 6-pin, surface-mount package (This type is used in the Pimoroni Sense HAT, mentioned in Chapter 15.). The internal configuration of the three types is shown in Figure 17-1.

### Common Anode

The dotted box around each LED is a schematic that shows they're all in one package. Note that the common anode and common cathode types have four wires going into them instead of the normal two for a single-color LED. Each LED can be treated by the software as a separate LED. To use common LEDs, you have to wire them up so that the GPIO pins act as current sinks, that is making the connection to ground. The wiring for the two types is shown in Figure 17-2.
