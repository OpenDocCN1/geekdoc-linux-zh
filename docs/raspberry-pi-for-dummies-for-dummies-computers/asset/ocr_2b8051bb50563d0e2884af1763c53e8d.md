the state, and returns if it isn't. Finally, in the main loop, the bleep variable was looked at because it controls when the sounder should make a noise. This variable is set at State 3 of the crossSequenceFunction and cleared at State 4. The crossSequenceFunction, for most steps, simply turns on or off the various lights according to the required sequence. The exception to this is in State 5, where the cross light and the amber light need to flash. We do this by toggling the lights. (Toggling means turning off a light that is on, and turning on a light that is off.) Rather than using a variable to tell you you set the light on or off last, you can use a trick: Read the state of a GPIO output pin. This gives you the value you set it to, and you know you want to use the inverse of this state. There-the line

```
io.output(amber,not(io.input(amber)))
```

sets the amber to the opposite state to its current state. Before you can get out of State 5 and advance it to State 6, you must have ten flashes of the lights. Finally, in State 7, you set the traffic lights to green for go and return the state machine back to State 0, which indicates that the cross sequence is longer in progress.

# Taking it further

There are a print statements we have commented out, to show the state of the cross sequence; you might like to uncomment them to see what is going on, although the LEDs should tell you. You can go and measure the times on an actual crossing and replace the times used in the program with realistic times. You can extend the program so that there's a more intelligent traffic-control system, by counting the cars over a set interval — say, the last 20 seconds — and graduating Wait Before Crossing sequence delay is lengthened accordingly.
