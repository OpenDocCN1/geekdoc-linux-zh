pub  1024D/4F2A6FD2 2003-10-27 Fedora Project <fedora@redhat.com>
sub  1024g/F8939E34 2003-10-27

The next step is to check the fingerprint of the new key. I type the following command to get the fingerprint of the Fedora key:

```
gpg --fingerprint fedora@redhat.com
```

GPG prints the fingerprint:

```
pub  1024D/4F2A6FD2 2003-10-27 Fedora Project <fedora@redhat.com>
key fingerprint: CA84 4899 6F27 744E 8612 7C0F 8442 690D 4F2A 6FD2
sub  1024g/F8939E34 2003-10-27
```

At this point, you need to verify the key fingerprint with someone at Red Hat. For a large project such as Fedora, you can verify the fingerprint from the Fedora Web page (fedora.redhat.com/about/security/). If you think the key fingerprint is good, you can sign the key and validate it. Here’s the command you use to sign the key:

```
gpg --sign-key fedora@redhat.com
```

GPG displays a message and prompts you on the level of key verification you have performed:

```
gpg: checking the trustdb
gpg: checking at depth 0 signed=0  tt=(q-/n/m/f/u)=0/0/0/0/0/1
pub  1024D/4F2A6FD2  created: 2003-10-27  expires: never    trust: -/-
sub  1024g/F8939E34  created: 2003-10-27  expires: never
(1) Fedora Project <fedora@redhat.com>

pub  1024D/4F2A6FD2  created: 2003-10-27  expires: never    trust: -/-
  Primary key fingerprint: CA84 4899 6F27 744E 8612 7C0F 8442 690D 4F2A 6FD2

  Fedora Project <fedora@redhat.com>

How carefully have you verified the key you are about to sign actually belongs to the person named above?  If you don’t know what to answer, enter "0".

(0) I will not answer. (default)
(1) I have not checked at all.
(2) I have done casual checking.
(3) I have done very careful checking.

Your selection?
```

After you answer and press Enter, GPG asks for confirmation and then prompts you for your passphrase. After that GPG signs the key.

Because the key verification and signing is a potential weak link in GPG, be careful about what keys you sign. By signing a key, you basically say that you trust the key to be from that person or organization.
