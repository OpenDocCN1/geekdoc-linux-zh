On most systems, the default effect of the keyboard abort sequence is to suspend the operating system and enter the debugger or monitor. The abort sequence on systems is L1-A or STOP-A on the keyboard and Break on the serial input device.
A Break originates from an erroneous electrical signal cannot be distinguished from one deliberately by remote DCE. As a remedy, superuser can use the -a alternate option (Alternate Break)—in the Solaris 8 release–to switch break interpretation. Because of the risk of incorrect sequence interpretation, binary protocols as PPP, SLIP, and others should not be run over the serial console port when Alternate Break sequence is in effect. The Alternate Break sequence has no effect on the keyboard abort. See zs(TD), se(TD), and asy(TD) for more information on the Alternate Break Sequence.
