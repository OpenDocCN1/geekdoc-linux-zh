# getoptcvt — Convert to getopt to Parse Command Options

## Synopsis

```
/usr/lib/getoptcvt [-b] filename
/usr/lib/getoptcvt
```

## Description

Use /usr/lib/getoptcvt to convert getopt output to use getopts instead. getoptcvt reads the shell variable filename, converts it to use gets instead of getopt, and writes the results on the standard output.

getopt is a built-in shell command that parses positional parameters and checks for valid options. See man(1). getopt supports all applicable rules of the command syntax standard (Rules 3–10, intro(1)). You should use getopt instead of the getopt command. The syntax for the shell's built-in getopt command is:

```
optstring name [argument...]
```

optstring must contain the letters recognized by the command using getopt; a letter is followed by a colon, the option is expected to have an argument or group of arguments that must be separated from it by white space.

Each time you invoke getopt, gets puts the next option in the shell variable name and the index of the next argument to be processed in the shell variable OPTIND. Whenever you invoke the shell or shell script, OPTIND is initialized to 1. When an option encounters an option-argument, gets puts it in the shell variable OPTARG. If the end-of-option is encountered, getopt exits with a non-zero exit status. You can use the special option -- to delim the end of options.

By default, gets parses the positional parameters. If you specify extra arguments (argument...) on the command line, gets parses them indeed so that all new commands adhere to the command syntax described in intro(1), they should use getopt to parse positional parameters and should check for options that are valid for command.

Although relax of the following command syntax (see intro(1)) are permitted under the current implementation, you should not use them because they may not be supported in future releases of the system.

## Options

- -b Make the converted script portable to earlier releases of the Solaris Operating Environment./usr/lib/getoptcvt modifies the shell script in filename so that when the resulting shell script is executed, it determines at runtime whether to invoke getopt.

## Examples

The following fragment of a shell program shows how you might progress the arguments for a command that can take options a or b, as well as the option c, which requires an option-argument.

```
while getopt do
  case $c in
    a | b) FLAG=$c;
    \ARG $?) echo echoAGE; exit 2;
  esac
done
shift 1
```

This code accepts any of the following as equivalent:

```
cmd -a -b "xxx yy" filename
cmd -a -b "xxx yy" -- -o z,yy filename
```

Note that a and b are options, and the option c requires an option-argument. The following example violates Rule 5: options with option-arguments must not be grouped with other options.

```
cmd$ -abox filename
```

The following example violates Rule 6: there must be white space after an option that takes an option-argument.

```
cmd$ -oxox filename
```

Changing the value of the shell variable OPTIND or parsing different sets of arguments can lead to unexpected results.

# getopts — Parse Utility Options

## Synopsis

```
/usr/bin/getopts optstring name [arg...]
sh getopts optstring name [argument...]
sh getopts optstring name [arg...]
```

## Description

//usr/bin/getopts
You can use the getopts command to process command-line arguments and check for legal options. You use the getopts command in shell loops to ensure standard syntax for command-line options.

Each time it is invoked, the getopts command puts the value of the next option in the shell variable specified by the name operand and the index of the next argument to be processed in the shell variable OPTIND. Whenever it is invoked, OPTIND is set to 1. When the option requires an option-argument, the getopts command puts it in the shell variable OPTARG. If no option is found or if the option found does not have an option-argument, OPTARG is unset.

If an option character not contained in the optstring operand is found where an option is expected, the shell variable specified by name is set to the question-mark (?). If the first character in optstring is a colon (:), the shell variable is the option character found but no output is written to standard error; otherwise, the shell variable OPTARG and a diagnostic message is written to standard error. This condition is considered to be an error detected in the ways arguments were presented to the invoking application but is not an error in getopts processing.

If an option-argument is missing, getopts handles it in the following:

- If the first character of optstring is a colon, the shell variable specified by name is set to the colon character and the shell variable OPTARG is set to the option found
