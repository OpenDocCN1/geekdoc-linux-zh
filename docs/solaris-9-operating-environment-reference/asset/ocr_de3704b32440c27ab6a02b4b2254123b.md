# zip, zipcloak, zipnote, zipsplit 1591

On OS/2, zip cannot match some names, such as including an exclamation mark or hash sign. This is on OS/2 itself: the 32-bit DosFirst/Next doesn't find such names. Other programs such as GNU zip are affected by this.

Under OS/2, the amount of Extended Attributes displayed by DIR is (for compatibility) the amount returned by the 16-bit version of QueryPathInfo(). Otherwise, OS/2 1.2.0 would report EA sizes when using the command on a file. The structure layout returned by the 32-bit QueryPathInfo is a bit different; it uses extra padding and link pointers (it's a linked list) to have all 4-byte boundaries for portability to future RISC OS/2 versions. Therefore, the value returned by zip (which uses this32-bit-mode size) differs from the 16-bit MS-C compiled version on OS/2 1.3, and even this one shows the

32-mode size.
