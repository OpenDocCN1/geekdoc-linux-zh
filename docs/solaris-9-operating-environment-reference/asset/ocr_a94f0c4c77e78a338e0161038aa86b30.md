# eject

# Nickname Path

| Nickname | Path |
| --- | --- |
| diskette0 | /dev/diskette0 |
| diskettel | /dev/diskettel |
| rdiskette | /dev/rdiskette |
| rdiskette0 | /dev/rdiskette0 |
| diskettel | /dev/diskettel |
| floppy | /dev/rdiskette |
| floppy0 | /dev/rdiskette0 |
| floppy1 | /dev/diskettel |

Do not physically eject media from a device that contains mounted file systems. eject automatically searches for any mounted file systems that reside on the device and tries to unmount them before ejecting the media (see mount(1M)). If the eject operation fails, eject prints a warning message and exits. You can use the -f option to specify an eject even if the device contains mounted partitions; this option works only if Volume Management is not running.

If you have inserted a diskette, you must use vol(1) before ejecting the medium, to inform Volume Management of the diskette's presence.

# Bugs

There should be a way to change the default on a per-user basis. If Volume Management is not running, it is possible to eject a volume that is currently mounted (see mount(1M)). For example, if you have a CD-ROM drive at /dev/dsk/c0t3ds2 mounted on /mnt, the following command (without Volume Management running) ejects the CD-ROM because both slices s0 and s2 reference the whole CD-ROM drive.

```
castle# eject /dev/dsk/c0t3ds0s
```

# Options

+   -d Display the name of the default device to be ejected.
-f Force the device to eject even if it is busy, by Volume Management is not running.
-n Display the nickname to the device name translation table.
-p Do not try to call the eject_popup program.
-q Query to see if the media are present.

# Operands

| device | Specify which device to eject, by the name in the /dev directory |
| nickname | Specify which device to eject, by its nickname as known to this command.
