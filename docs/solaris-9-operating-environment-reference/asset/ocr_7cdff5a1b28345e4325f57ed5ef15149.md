Print the floating-point register set of the representative thread. When you specify thread-new in the Solaris 9 release—the floating-point registers of that thread are displayed. The thread expression should be one of the thread identifiers described in “Thread Support” on page 834.

+   ::formats List the available output format characters for use with the /, \, ?, and = formatting dcmds. The formats and their use are described in “Formatting dcmds” on page 830.

+   ::grep command Evaluate the specified command string and print the old value of dot if the new value of dot is non-zero. When the command contains whitespace or metacharacters, you must quote it. You can use :grep dcmd in pipelines to filter a list of addresses.

+   ::help [dcmd-name] With no arguments, the :help dcmd provides a brief overview of the facilities available in mdb. When you specify dcmd-name, mdb prints a usage summary for dcmd.

+   signal :i If the target is a live process, ignore the specified signal and allow it to be delivered transparently to the target. Delete all event specifiers that are tracing delivery of the specified signal from the list of traced events. By default, the set of ignored signals is initialized to the complement of the signals that dump by default (SIGHEAD), except SIGINT, which is traced by default. New in the Solaris 9 release.

+   $I Display the list of signals that are ignored by the debugger and are handled by the target. You can obtain more information on traced signals with :events dcmd. New in the Solaris 9 release.

+   ::kill Forcibly terminate the target if it is a live process. The target is also forcibly terminated when the debugger exits if it was created by :run. New in the Solaris 9 release.

+   $L Print the LWPID of the representative thread if the target is a user process. New in the Solaris 9 release.

+   $L Print the LWPIDs of each SPW in the target if the target is a user process. New in the Solaris 9 release.

+   ::load [-s] module-name Load the specified dcmd. You can specify the module name as an absolute or relative path. If module-name is a simple name (that is, does not contain a /), mdb searches for it in the module library path. You cannot load with conflicting names; you must first unload the existing module. When you specify the -s option—new in the Solaris 9 release—mdb remains silent and not issue any error messages if the module is not found or could not be loaded.
