This condition is considered to be an error detected in the way arguments were presented to the invoking application but not an error in getopts processing; a diagnostic message is written as stated, but the exit status is 0.

When the end-options are encountered, the getopts command exits with a return value greater than zero; the shell variable OPTIND is set to the index of the first non-option argument, where the first -- argument is considered to be an option-argument if no other nonoption arguments appear before it, or the value $ +1 if there are non-option arguments; the name variable is set to the question-mark character. Any of the following identify the end-options:

+   * The special option --

+   * Finding an argument that does not begin with a -

+   * Encountering an error.

The shell variables OPTIND and OPTARG are local to the caller of getopts and are not exported by default.

The shell variable specified by the name operand, OPTIND, and OPTARG affects the current shell execution environment.

If the application sets OPTIND to the value 1, a new set of parameters can be used: either the current positional parameters or new argv. Any other attempt to invoke getopts multiple times in a single-shell execution environment with parameters (positional parameters or operands) that are not the same in all invocations, or with an OPTIND value modified to a value other than 1, produces unspecified results.

# Bourne Shell

getopts is a built-in Bourne command that parses positional parameters and checks for valid options. See sh(1). It supports all rules of the command syntax (see Rules 3–10, intro(1)). You should use it to get the command command

parsing the option letters recognized by the command getopts; if a letter is followed by a colon, the colon is expected to have an argument or group of arguments that must be separated by white space.

Each time getopts is invoked, it puts the next argument in the shell variable name and the index of the next argument to be processed in the shell variable OPTIND. Whenever the shell or a shell script is invoked, OPTIND is initialized to 1. When an option requires an option-argument, it puts it in the shell variable OPTARG.

When the end-options are encountered, getopts exits with a non-zero exit status. You can use the special option -- to delimit the end of the options.

By default, getopts parses the positional parameters. If arguments (...) are not given on the getopts command line, getopts parses them.

/usr/lib/getopts.sh creates the script in Filename, converts it to getopts instead of getopt, and writes the shell script to standard output.
