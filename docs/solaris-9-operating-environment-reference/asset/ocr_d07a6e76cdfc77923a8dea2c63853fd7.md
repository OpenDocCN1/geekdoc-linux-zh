Some of the commands use a hold space to save all or part of the pattern space for subsequent retrieval. The pattern and hold spaces are each able to hold at least 8,192 bytes.

# sed Addresses

An address can have the following contents:

+   - Empty.
- A decimal number that counts input lines cumulatively across lines.
- A $ that addresses the last line of input.
- A context address consists of a /regularexpression/, as described on the regexp(5) manual page.

A command line with no addresses selects every pattern space.
A command line with one address selects each pattern space that matches the address.

A command line with two addresses selects the inclusive range from the first pattern that matches the first address through the next pattern space that matches the second address. Thereafter, the process is repeated, looking again for the first address. If the second address is a number less or equal to the number selected by the first address, only the line corresponding to the first address is selected).
Typically, addresses are separated from each other by a comma ( , ). They can be separated by a semicolon (;).

# sed Regular Expressions

sed supports the basic regular expressions described on the regexp(5) manual page, with the following addresses:

\c In a context address, the construction \c; where c is any character other than a backslash or newline character, is identical to /RE/. If the character designated by c follows a backslash, it is considered to be that literal character and does not terminate the RE. For example, in the context \abc\xdef, the second x stands for itself, so that the regular expression is abcdef.

\n The escape sequence \n matches a newline character in the pattern space. You must not use a literal newline in the regular expression of a context address or in the substitute command.

Editing commands can be applied only to nonselected pattern spaces by use of the negation command ! (described below).
