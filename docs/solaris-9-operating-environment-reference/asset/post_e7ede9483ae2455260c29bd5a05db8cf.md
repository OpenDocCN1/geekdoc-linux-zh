# SCCS

deletit [-s] [-y[comment]]

Equivalent to an sccs delta and then an sccs edit. The deletit subcommand checks in a delta and checks the file back out again but leaves the current working copy of the file intact.

- -s Do not report delta numbers or statistics.
- -y[comment] Omit a comment for the delta commentary. If you omit -y, delta prompts for a comment. A null comment results in an empty comment field for the delta.

delget [-s] [-y[comment]]

Perform an sccs delta and then an sccs get to check in a delta and retrieve read-only copies of the resulting new version. The deletit subcommand for a description of -s and -y. sccs performs a delta command on all the files specified in the argument list and then a get on all the files. If an error occurs during the delta, the get is not performed.

delta [-s] [-y[comment]]

Check in pending changes. Read the line-by-line changes introduced while the file was checked out. The effective user ID of the person who has the file checked out. See sccs-delta(1). The deletit subcommand for a description of -s and -y.

diffs [-C] [-I] [-cdatetime] [-rsid] diff-options (/usr/ccs/bin/sccs) diffs [-C] [-I] [-cdatetime | -c date-time] [-rsid | -r sid]

diff-options [-y] Compare in diff(1) format the working copy of a file that is checked out for editing, with a version from the SCCS history. Use the most recent checked-in version by default. The deletit subcommand accepts the options as diff.

Any -r, -c, -i, and -ot options are passed to the get subcommand. Any -1, -s, -e, -f, -h, and -options are passed to the diff command. A -C is passed to diff as -c. An -I is passed to diff as -i.

-cdate-time [/usr/ccs/bin/sccs -c date-time | -cdate-time (/usr/xpg4/bin/sccs)]

Use the most recent version checked in in the indicated date and time for comparison. date-time takes the form yy[mm[dd[hh[[mm][ss]]]]]]. Omitted units default to their maximum possible values; that is, -c7502 is equivalent to -c750228232959.

Revise a (leaf) delta. Remove the indicated delta from the SCCS history, leaving a writable copy of the current version in the directory. This subcommand is useful for incorporating tribal updates for which you need no audit record or for revising the delta commentary. You must follow with a -r option to specify the sid of the delta to remove. The indicated delta must be the most recent (leaf) delta in the branch. Use with caution because it does not leave an audit trail of differences (although the previous copy remains within the history file).

# Examples

The following example checks out a file, edits it, and checks it back in again.

```
castle% sccs edit program.c
1.1
new delta 1.2
14 lines
castle% vi program.c
ynyour editing session
castle% sccs delget program.c
comments? clarified cryptic diagnostic
1.2
3 inserted
2 deleted
12 unchanged
1.2
15 lines
castle%
```

The following example defines the root portion of the command path name.

```
castle% sccs -d/usr/src/include get stdio.h
/usr/ccs/bin/get /usr/src/include/SCCS/s.stdio.h
castle%
```

The following example redefines the resident subdirectory.

```
castle% sccs -pprivate get include/stdio.h
/usr/ccs/bin/get include/private/s.stdio.h
castle%
```
