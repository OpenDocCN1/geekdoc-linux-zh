## 1447

## truss

- -u [!]lib,...[:[:] [!]func,...

Specify user-level function call tracing. Specify lib,... as a comma-separated list of dynamic library names excluding the .so.n suffix. Specify func,... as a comma-separated list of function names. In both cases, the names can include name-matching metacharacters ?, (with the same names as those sh but applied to the library/function namespaces, not files. An empty library or function defaults to *, that is, trace all libraries or functions in a library. A leading ! on either list specifies an exclusion list, names of libraries or functions not to be traced. Excluding a library excludes all functions in that library; ignore any function list following a library exclusion list.

A single : separating the library list from the function name means calls into the libraries from outside the libraries or omit calls made to functions from other functions in the same library. A double :: means trace all calls, regardless of origin.

Library patterns do not patch the executable file or the dynamic linker unless there is an exact match (* does not match ld.so.). To trace functions in of these objects, you must specify the names exactly, as in truss -a -out -ud... Use as the literal name for this purpose. It does not stand for the name of the executable file. Tracing a.out function implies all calls (default is ::).

You can specify multiple -options, and they are honored to right. If the process is linked with -thread, the ID of the thread that performed the function call is included in the trace output for the call. truss searches the dynamic symbol table in each library to find function names and also searches the standard symbol table if it has not been stripped.

- -U [!]lib,...[:[:] [!]func,...

Specify user-level function calls that stop the process. Add the specified functions to the set specified by -u. If one of the specified functions is called, leave the process stopped and abandoned (see the -Option).

- -v [!]syscall,...

Show the contents of any structures passed by address to the specified system calls (if traced). Show input values as well as values returned by the operating system. For any field used as input and output, show only the output value. Default is -vall.

- -w [!]fd,...

Show the contents of the I/O buffer for each write() on any of the specified file descriptors (see -r). Default is -wall.

- -x [!]syscall,...

Display the arguments to the specified system calls (if traced) in raw form, usually hexadecimal, instead of symbolically. This option is for unredeemed hackers who must see the raw bits to be happy. Default is -xall.

## 1448

## truss

See intro(2) for system calls accepted by the -t, -v, and -x options. System call numbers are also accepted.
If you use truss to initiate and trace a command, and if the use -o option or standard error is redirected to a nonterminal file, then truss runs with hangup, interrupt and quit signals ignored. This behavior facilitates tracing of interactive programs that catch interrupt and quit signals from the terminal.
If the trace output remains directed to the nonterminal or if processes are traced (the -p option), then truss responds to hang, interrupt, and quit signals by releasing all traced processes and exiting. This behavior enables you to terminate excessive trace output and to release previously existing processes. Released processes continue normally as though they had never touched.

The following example produces a trace of the shell (truss 1) command in the file truss.out.

```
castle# truss -f -o truss.out spell -1
spell
more truss.out
execve("/usr/bin/spell", 0xEFFFF524, 0xEFFFF34) argc = 3
open("/dev/zero", O_RDONLY) = 3
mmap(0x00000000, 4096, PROT_READ|PROT_WRITE, MAP_PRIVATE, 3, 0) = 0xEF7C000
open("/usr/lib/socket.1", O_RDONLY) = 4
fstat(4, 0xFFFCBC) = 0
mmap(0x00000000, 4096, PROT_READ|PROT_WRITE, MAP_PRIVATE, 4, 0) = 0xEF7B000
mmap(0x00000000, 102400, PROT_READ|PROT_WRITE, MAP_PRIVATE, 4, 0)
munmap(0xEF79000, 614400) = 0
mmap(0xEF7A000, 6977, PROT_READ|PROT_WRITE, MAP_PRIVATE|MAP_ED, 4, 28672) = 0xEF7A000
... (More information shown)
```

spell is a shell script, so you need the -f option to trace not only the shell but also the processes created by the shell. (The shell script runs a pipeline of eight processes.)

Note — When tracing more than one process, truss runs as one controlling for each process being traced. In the shell command example, itself uses 9 slots, for the shell and 8 for the 8-member pipeline, while truss adds 9 processes, for a total of 18.

In the following (boring) example, 97 percent of the output reports seek(), read(), and write() system calls.

```
$ truss roff -mm document >nroff.out
```

You can use the following to abbreviate the output.

```
$ truss -t !seek,read,write roff -mm document >nroff.out
```

The following example traces all user-level calls to any function in the C library from outside the C library.

```
$ truss -u libc..
```

## 1450

## tset, reset

The following example includes example to calls made to functions in the C library from within the C library itself.

```
example$ truss -u libc:...
```

The following example traces all user-level calls made to any library other than the C library.

```
$ truss -u '*' -u libc...
```

The following example traces all user-level calls to functions in the printf and scanf family contained in the C library.

```
$ truss -u libc:*printf, scanf*...
```

The following example traces every user-level function call from anywhere to anywhere.

```
$ truss -u a.out -u ld:- -u :...
```

The following example verbely traces the system call activity of process #1, init(1) (if you are superuser).

```
# truss -p -v all 1
```

Interrupting truss returns init to normal operation.
