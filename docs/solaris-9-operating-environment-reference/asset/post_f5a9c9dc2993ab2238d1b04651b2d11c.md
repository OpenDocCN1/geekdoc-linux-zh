# uptime — Show How Long a System Has Been Up

# Synopsis

/usr/bin/uptime

# Description

The uptime command prints the current time, the length of time the system has been up, and the average number of jobs in the run queue over the last 1, 5, and 15 minutes. It is, essentially, the first line of a(1) command.

> Note — You can use the who -b command to display the time the system was last booted.

# Example

The following example shows the output of uptime.

```
castle@ uptime
10:47am up 27 day(s), 50 mins, 1 user, load average: 0.18, 0.26, 0.20
castle@
```

# users — Display a Compact List of Logged-In Users

# Synopsis

/usr/ucb/users [filename]

# Description

users lists the login names of the users currently on the system in a compact, one-line format. Specifying filename tells users where to find its information; by default, it checks /var/adm/utmpx.

The users command is equivalent to typing who -q.

# uucp, uulog, uaname — UNIX-to-UNIX System Copy

# Synopsis

```
/usr/bin/uucp [-c] [-C] -d [-f] [-grade] [-jmr] [-user] [-sfile] [-xdebug-level]
source-file destination-file
/usr/bin/uulog [-ssys] [-f system] [-x] [-number] system
/usr/bin/uaname [-c -1]
```

# Description

The uucp (UNIX-to-UNIX copy) suite of commands is part of a data communications subsystem that enables you to transfer ASCII and binary files between systems, execution of commands, queue jobs for later transfer, and automatically retry when transfer fails. The complete uucp suite of commands includes user commands and functions, security features, logging and debugging tools, and a number of data transfer protocols. This section describes the uucp, uulog, and uan commands.

# uucp

uucp copies files named by the source-file arguments to the location specified by the destination-file argument.

# uulog

uulog queries a log file of uucp or uuxqt transactions in file /var/uucp/.Log/uucico/system or /var/uucp/.Log/uxxqt/system.

# uaname

uaname lists the names of systems known to uucp.

# uucp, uulog, uuname

For security reasons, the domain of remotely accessible files may be severely restricted. You probably cannot access files by path name; ask a responsible person on the remote system to send them to you. For the same reasons, you probably cannot send files to arbitrary path names. As distributed, the remotely accessible files are those whose begin /var/spool/uupublic (equivalent to ~). All files are received by uucp.

Protected files and files that are in protected directories are owned by the requester can be sent by uucp. However, if the requester is root and the directory is not searchable by other or the file is not readable by other, the request fails.
Strings that are passed to remote systems may not be evaluated in the same locale as the one in by the process that invoked uucp on the local system.
Configuration files must be treated as C- (or POSIX-) text files.

# Options

# uucp

- -c
  - Do not copy local files to the spool directory for transfer to the system (default).
  - Force the copy of local files to the spool directory for transfer.
  - Make all necessary directories for the file copy (default).
  - Do not make intermediate directories for the file copy.
-grade
  - Specify the grade as a single letter, number, or a string of alphanumeric characters defining a service grade. The uuglist command to determine whether it is appropriate to use the single letter, number, or a string of alphanumeric characters as a service grade. The output from the uulist command is a list of service grades that are available or a message that says to use a single letter or number as a grade of service.
-j
  - Print the uucp job identification string on standard output. This job identification can be viewed by uustat to obtain the status of a uucp job.
-m
  - Send mail to the requester when transfer.
-n
  - Notify the user that transfer is complete.
-r
  - Queue the job for transfer.
-sfile
  - Report the status of the transfer.
-xdebug-level
  - Debugging output, a number between 0 and 9.
-x
  - Debugging information.
