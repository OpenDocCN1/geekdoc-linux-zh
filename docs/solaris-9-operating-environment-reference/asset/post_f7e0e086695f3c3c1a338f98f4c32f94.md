On OS/2, zip cannot match some names, such as including an exclamation mark or hash sign. This is on OS/2 itself: the 32-bit DosFirst/Next doesn't find such names. Other programs such as GNU zip are affected by this.

Under OS/2, the amount of Extended Attributes displayed by DIR is (for compatibility) the amount returned by the 16-bit version of QueryPathInfo(). Otherwise, OS/2 1.2.0 would report EA sizes when using the command on a file. The structure layout returned by the 32-bit QueryPathInfo is a bit different; it uses extra padding and link pointers (it's a linked list) to have all 4-byte boundaries for portability to future RISC OS/2 versions. Therefore, the value returned by zip (which uses this 32-bit-mode size) differs from the 16-bit MS-C compiled version on OS/2 1.3, and even this one shows the 32-mode size.

# zipinfo

# zipinfo — List Detailed Information About a Zip Archive

# Synopsis

```
usr/bin/zipinfo [-12smlvhMTtz] file[.zip] [file(s)...] [-x xfile(s)...]
/usr/bin/unzip -Z [-12smlvhMTtz] file[.zip] [file(s)...]
-x xfile(s)
```

# Description

Note zipinfo is the same program as unzip (under UNIX, a link to it); on systems, however, zipinfo support may be omitted when unzip was compiled.

zipinfo lists technical information about files in a ZIP archive. Such information includes file permissions, encryption status, type of compression, version, and the operating or file system of compressing program. The default behavior (specifying file with no options) is to single-line entries for each file, with header and totals providing summary information for the entire archive. The format is a cross between UNIX ls -l and unzip -v output, as shown in the following example:

| castle%zipinfo.zip 106272 bytes 4 files |
| -rw-a-- 2.0 fat 76800 t-def 18-Aug-98 21:55 085X01.DOC |
| -rw-a-- 2.0 fat 67072 b-def 22-Aug-98 01:39 085X042.DOC |
| -rw-a-- 2.0 fat 95232 t-def 31-Aug-98 20:29 085X042.DOC |
| -rw-a-- 2.0 fat 63488 t-def 4-Oct-98 20:24 085X04E.DOC |
| 4 files, 302592 bytes uncompressed, 105898 bytes compressed: 65.0% castle$ |

Note You may find convenient to define an alias for zipinfo on systems that allow others. You can copy and rename the executable, create a link, or create a command file with the name ii. The ii parallels the common 11 aliases for long listings in UNIX. The similarity between the outputs of the two commands was intentional.

# Detailed Description

zipinfo has a number of modes, and its behavior can be difficult to fathom if you are familiar with the ls(1) command. The default behavior is to list files in the format shown.

```
-rw-rw---- 1.9 2802 11-Aug-91 13:48 per.2660
```

This example is for a ZIP file generated on a UNIX system. It comes from UNIX, the file permissions at the beginning of the file in this example are printed in UNIX format.

The second and third fields indicate that the file was zipped under UNIX with version 1.9 of zip. The fourth field shows the uncompressed file size (2802)
