# Resolving Conflicts

When files on both sides have changed, filesync tries to determine which version should be chosen. If filesync cannot automatically determine which version should be selected, it prints out a warning message and leaves the two incompatible versions of the file unreconciled.

In these cases, you must either resolve the differences or tell filesync how to choose which file should win. Use the -o and -f options to tell filesync how to resolve conflicts.

Alternatively, for each conflicting file, you can examine the two versions, determine which one should be kept, and manually bring the two versions into agreement (by copying, deleting, or changing the ownership or property to be correct). You can then rerun filesync to see whether any other conflicts remain.

# Packing Rules File

The packing rules file $HOME/.packingrules contains a list of files to keep synchronized. The syntax of this file is described in packingrules(4).

If you invoke filesync with filename argument, the $HOME/.packingrules is automatically created. By using filesync options, you can augment the packing rules in $HOME/.packingrules.

Many users choose to create the packing rules file manually and edit it by hand. You can edit $HOME/.packingrules (using any editor) to permanently change the $HOME/.packingrules file or gain access to more powerful options that are not available from the command line (such as IG commands). By editing the $HOME/.packingrules file, you can easily enter complex wild-card expressions.

# Baseline Files

$HOME/.filesync-base is the filesync baseline file, filesync uses the $HOME/.filesync-base to identify the differences between files during reconciliation and synchronization. You do not create or delete the baseline file. It is created automatically by filesync and records the last-known state of agreement between all of the files being maintained.

# Multiple filesync Commands

Over time, the files you want to keep synchronized can change. It is common, for instance, to keep files pertaining to only a few active projects on your notebook. If you continue to synchronize files associated with every project you have worked on, your notebook's disk will fill up with old files. In addition, each filesync command would waste a lot of time updating files you no longer care about.

If simply delete the files from your notebook, filesync wants to perform the corresponding deletes on the server, which is not what you want. Instead, you can tell filesync to stop synchronizing in one of the following ways:

+   - Edit $HOME/.packingrules and delete the rules for the files that you want to delete from your notebook.
- Delete $HOME/.packingrules. Then, use the filesync command to specify the files that you want synchronized.

Either way works, and you can choose the one that seems easier to you. For minor changes, it is possibly easier to edit $HOME/.packingrules. For major changes, it is possibly easier to start from scratch

Once filesync is no longer synchronizing a set of files, you can delete them from your notebook without affecting the files on the server.
