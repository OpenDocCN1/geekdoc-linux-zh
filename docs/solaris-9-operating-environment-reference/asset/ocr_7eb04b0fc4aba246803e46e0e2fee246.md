Description
The advantages of the tar command is that it is available on UNIX operating systems and that public domain versions are readily available. The disadvantages of the tar command are that it is not aware of file-boundaries, full path-name cannot exceed 255 characters, it does not copy empty directories or special files such as device files, and it cannot be used to create multiple volumes.

The tar command creates archives from a single file called a tarfile.
A tarfile is usually magnetic bucket but it can be used. tar with the key argument, which is a set of characters containing exactly one letter–c (create), r (replace), t (table of contents), u (update), or x (extract)—and zero or more function modifiers (letters or digits), depending on the letter used. The key string contains no space characters. Function modifiers are listed in the command line in the order as their corresponding function modifiers appear in the key string.

-I include-file, -C directory file, and filearguments specify which files or directories are to be archived or extracted. In all cases, appearance of a directory name refers to files and (recursively) subdirectories of that directory. Arguments appearing within braces ({()) that you must specify one of the arguments.

# Notes

When the Volume Management daemon is running, accesses to disk devices through the conventional device names (for example, /dev/rdiskette) may not succeed. See void(1) for further details.

The tar archive format allows UIDs and GIDs up to 2097151 to be stored in the archive header. Files with UIDs and GIDs greater than this value are archived with the UID and GID of 60001 (nobody).

If you create an archive that contains files whose names are created by processes running in multiple locations, use a single local with a 8-bit codeset (for example, us local) to both create the archive and extract files from it.
