# chkey — Change User's Secure RPC Key Pair

# Synopsis

/usr/bin/chkey [-p] [-s nisplus | nis | files] [-m mechanism]

# Description

Use chkey to change a user's secure RPC key and secret key. chkey prompts for the old secure RPC password and verifies that it is correct by decrypting the secret if the user has not already logged in, chkey registers the secret with the local keyserver(1M) daemon. If the RPC password does not match the login password, chkey prompts for the login password. chkey uses the login password to encrypt the user's Diffie-Hellman (192-bit) cryptographic key.

chkey ensures the login password and the secure RPC password are kept the same, enabling password shadowing (see shadow(4)).

The key may be stored in the /etc/publickey file, (see publickey(4)), NIS public key map, or the NIS+org_dir file. If a new key is generated, it is registered with the local keyserver(1M).

You can change or replace secret mechanisms with the -option followed by the authentication mechanism name. You can use multiple -options to change one or more keys. However, only mechanisms configured in nsswitch.conf(1M) can be changed with chkey.

If you do not specify the source of the public key with the -s option, chkey consults the public key entry in the name service switch configuration file (conf). If the entry specifies only one source, then chkey changes the key in the specified service name. However, if multiple services are listed, chkey cannot decide which source to use and displays an error message.

Specify the source explicitly with the -s option.

Non-root users are not allowed to change their key pair in the files database.
