# Environment Variables

The default environment variable name is UNZIP for all operating systems except VMS. For VMS systems, the environment variable is UNZIP_OPTS because the symbol used to install unzip as a foreign command would otherwise be confused with the environment variable. For compatibility with zip, UNZIPOPTS is also accepted (don't ask). If both UNZIP and UNZIPOPT are defined, UNZIP takes precedence. - Always overwrite or never overwrite files as they are extracted (-o or -n).

# unzip

For example, to make unzip act as quietly as possible, reporting only errors, you could use one of the following commands.

```
UNZIP=-qq; export UNZIP      UNIX Bourne shell.
setenv UNZIP -qq             UNIX C shell.
set UNZIP=-qq               OS/2 or MS-DOS.
define UNZIP_OPTS "-qq"    VMS (quotes for lower case).
```

Environment options are just like any other command-line options except that they are effectively the first options on the command line. You can use the minus operator to remove it. For example, to override one of the quiet-flags in the example above, use the following command.

```
castle% unzip -q[other-options] file
```

The first dash is the switch character, and the second is a minus sign acting on the q option. The effect is to cancel one quantum of quiet. To cancel both options, you can use two (or more) minuses.

```
castle% unzip -t-q file
castle% unzip --q file
```

The two commands are equivalent. This syntax may seem awkward or confusing, but it is intuitively obvious. After the first dash, any other dash signifies a negative option. This syntax is consistent with the behavior of the nice(1) command.

# Decryption

Encrypted archives are fully supported by Info-ZIP software, but because of U.S. export restrictions, the encryption and decryption sources are not packaged with the regular unzip and zip distributions. The sources were written by Europeans, however, they are freely available at sites throughout the world:

```
http://www.cdrom.com/pub/infozip/doc/WHERE
```

OR WHERE the first in any Info-ZIP source or binary distribution for locations both inside and outside the United States.

Because of the separate distribution, not all compiled versions of unzip support decryption. To check for crypt support, try to test or extract an encrypted archive or check the unzip diagnostic screen (see the -v option for [decryption]) as one of the special compilation options.

You can use the -P option to supply a password on the command line, to decrypt normally; if a file is encrypted, unzip prompts for the password without echoing; unzip continues to use the same password as long as it appears to be valid by a 12-byte header on each file. The record password always checks against the header, but there is a 1-in-256 chance that an incorrect password may work (This is a security feature of the PKWARE zipfile format; it prevents brute-force attacks that might otherwise gain a speed advantage by testing the one password). When you have an incorrect password that passes the header anyway, either a CRC is generated for the extracted data or unzip fails during the extraction because the decrypted bytes do not constitute a valid compressed stream.

Dates, times and permissions

[MS-DOS] When extracting or testing files from an archive on a diskette, if you choose the Fail from the DOS abort. Retry. Fail? Older versions of unzip may hang the system, or reboot. This problem appears to be fixed. You can use Control-C (Control-Break) to terminate unzip.

Under DEC, unzip fails on long files (bad CRC, not always reproducible). This problem was apparently because of either a hardware (cache memory) or an operating system (improper handling of page faults?). Ultra was abandoned in Digital UNIX (OSF/1), which may no longer be an issue.

UNIX special files as FIFO buffers (pipes), block devices, and character devices are not restored if they are somehow represented in the file, or hard-linked files linked. The only file types restored by unzip are regular files, directories, and (soft) links.

[OS] Extended attributes for extracting are updated only if you specify the -overwrite (all) option. This is a limitation of the operating system; because only attributes have a creation time associated with them, unzip has no way to determine whether the stored attributes are newer or older than those. In practice, you may need to take a two-phase approach: first unpack the archive normally (with without refreshing/updating files), then overwrite the directory entries (for example, unzip -o foo *).

[VMS] When extracting to another directory, the [ f ] syntax is accepted for the -d option; the unique Unix foo syntax is silently ignored (as is the less common VMS foo.dir syntax).

[VMS] When the file being extracted already exists, unzip queries only skipping, overwriting, or renaming. The overwrite creates a new version of the file; the old version is not overwritten or deleted.
