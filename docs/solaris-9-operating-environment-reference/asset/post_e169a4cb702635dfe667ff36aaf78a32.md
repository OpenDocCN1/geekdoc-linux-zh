# Description

A recipient is usually a user name recognized by login(1). When you specify recipients, mail assumes a message is being sent. It reads from the standard input to an end-of-file (Control-D) or, if reading from a terminal device, until it reads a line consisting of just a period. When either of those indicators is received, mail adds the letter to the mail file for each recipient.

A letter is composed of some header followed by a blank line followed by the message content. The header lines sections of the letter consists of one or more UNIX postmarks.

From sender-date-time [remote from remote-system-name]

followed by one or more standardized message header lines of the form:

keyword-name: [printable text]

where keyword-name consists of any primitive, non-white-space characters other than colon (:). A Content-Length: header line indicating the number of bytes in the message content is always present unless the letter consists of only header lines with no message content. A Content-Type: header line that describes the type of the message content (such as text, binary, or multipart) is also present unless the letter consists of only header lines with no message content. Header lines can be continued on the following line if that starts with white space.

# Options

# Sending Mail

- -m message-type

Add a Message-Type: line to the message header with the value of message-type.

- -t

Add To: line to the header for each of the intended recipients.

- -w

Send a letter to a remote recipient without waiting for the completion of the remote transfer program.

If a letter is found to be undeliverable, it is returned to the sender with diagnostics that indicate the location and nature of the failure. If mail is interrupted during input, the message is saved in the file dead letter allows editing and resending. dead.letter is always appended to, thus preserving any previous contents. The initial attempt to append to (or create) dead.letter is in the current directory. If this attempt fails, dead.letter is appended to (or created in) the user's login directory. If the second attempt also fails, no dead.letter processing is done.

# mail, rmail 757

rmail permits only the sending of mail; uucp(IC) uses rmail as a security precaution. Any application programs that generate mail messages should be sure to invoke rmail instead of mail for message transport and/delivery.

If the local system has the Basic Networking Utilities installed, you can send mail to a recipient on a remote system. There are numerous ways to address mail recipients to remote systems, depending on the transport mechanisms available to the local system. The two most prevalent addressing schemes are design mail and UUCP style. Consult your local system administrator for details on which addressing conventions are available on the local system.

# Domain-Style Addressing

For domain-style addressing, you specify remote recipients by appending an and domain (and possibly subdomain) information to the recipient name (such as user@sf.att.com).

# UUCP-Style Addressing

For UUCP-style addressing, you specify remote recipients by prefixing the recipient with the remote system name and an exclamation point, such as sys!user. csh(1) is the default shell, you can use a series of system names separated by exclamation points to direct a letter through an extended network (such as sys!sys!user@sysb!sys!user).

# Reading Mail

- -l Do not print mail. Return an status of 0 if the user has mail; otherwise, return an status of 1.

- -t file Use file(such as mbox) instead of the default mail file.

- -h Initially display a window of headers of the latest message. The display is followed by the prompt.

- -p Print all messages without prompting for disposition.

- -q Print all messages with header lines displayed instead of the default selector header line.

- -r Print messages in first-in, first-out.

mail, unless otherwise influenced by command-line arguments, prints mail in last-in, first-out. The default mode for printing messages is to display only those lines of immediate interest. These include, but are not limited to, the Unix From andFrom posts, Date; Subject; and Content-Length: header, and any recipient header lines as To:, Bcc:, and so after. After the header lines have been displayed, mail displays the (body) of the message if it contains no unprintable characters. Otherwise, mail issues a warning statement about the message having binary content and does not display the content. (You can override this feature with a p command.)

For each message, you are prompted with a ? and a line is read from the input. The following commands are available to determine the disposition of the message.

# mail, rmail

- + # Print the number of the current message.

- + Print previous message.

- newline | + n Print the next message.

- + ! command Escape to the shell to execute command.

- + a Print message that arrived during the mail session.

- + d | dp Delete the current message, and print the next message.

- + d n Delete message number n. Do not go on to next message.

- + dq Delete message and quit mail1.

- + h Display a window of headers around current message.

- + h n Display a window of headers around message number n.

- + h a Display headers of all messages in your mail file.

- + h d Display headers of messages scheduled for deletion.

- + m [persons] Mail (and delete) the current message to the named persons.

- + n Print message number n.

- + p Print current content, again avoiding any indications of binary (that is, unprintable) content.

- + P Override default brief mode, and print current message, again displaying all header lines.

- + q Control-D Puted mail back in the mail file, and quit mail.

- + r [users] Reply to the server and other users, then delete the message.

- + s [files] Save message in the named files (mbox is the default), and delete the message.

- + u [n] Undelete message number n(default is last read).

- + w [files] Save message content without any header lines in the named files (mbox is the default), and delete the message.

- + x Put all mail back in the mail file unchanged, and exit mail.

- + y [files] Same as the -w option.

When you log in, mail informs you if you have any mail. It also notifies you if new mail arrives while you are using.

You can manipulate the permissions of the mail file with chmod(1) in two ways to alter the function of mail. The permissions of others can be read-write (066), read-only (064), or neither nor write (060) to permit different levels of privacy. If you change others permissions to anything besides the default (066), the file is preserved when empty.(The administrator can override this file with the DEL_EMPTYFILE option of mailcnf.)

# Debugging

The following command-line argument provides mail debugging information.
-x debug-level

Create a trace file named /tmp/MLDBprocess_id that contains debugging information relating to how mail processed the message. The absolute value of debug-level controls the verbosity of the information. 0 implies no debugging. If debug-level is greater than 0, the debug file is retained only if mail encountered s problem while processing the message. If debug-level is less than 0 the debug file is always retained. The debug-level specified with -x overrides any specification of DEBUG in /etc/mail/mailcnf. The information provided by the -x option is esoteric and probably useful only to system administrators.

# Delivery Notification

mail provides several forms of notification, including one of the following lines in the
message header:

+ Transport-Options: [/options]
+ Default-Options: [/options]
>To: recipient [/options]

where the /options can be one or more of the following.

+ /delivery Inform the sender that the message was successfully delivered to the
recipient's mailbox.
/nelivery Do not inform the sender of successful deliveries.
/ignore Do not inform the sender of failed deliveries.
/return Inform the sender if mail delivery fails. The returned failed message to

Same as /return except that the original message is not retained.

The default is /nelivery/return. If you use contradictory options, the first is
recognized and any later, conflicting, terms are ignored.

# Notes

The interpretation and resulting action taken because of the header lines described in
the Delivery Notification section occurs only if this version of mail is installed on
system on which the delivery (or failure) happens. Earlier versions of mail may not
support any types of delivery notification.

Conditions sometimes result in a failure to remove a lock file.
After an interrupt, the next message may not be printed; you can force printing by
typing p.
