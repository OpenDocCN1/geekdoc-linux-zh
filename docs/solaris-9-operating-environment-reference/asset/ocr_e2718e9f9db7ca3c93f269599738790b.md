All macros except $? can have alternative forms. When you append an uppercase D or F to any of the four macros, the meaning is changed to "directory part" for D and "file part" for F. Thus, ($D) refers to the directory part of the string $. If there is no directory part, then ./ is generated.

# Suffixes

Certain names (for instance, those ending with .o) have inferable prerequisites such as .c, .s, and so forth. If no update command for a file appears in makefile and if an inferable prerequisite exists, that is used to make the target. In case, make inference rules that enable it to build files from other files by examining the suffixes and determining an appropriate inference rule to use. The current default inference rules are:

+   -c .c~ -f f ~f f~ ~s s~ ~sh sh~ ~h h~ ~C C~
.a a~ .a a~ .c c~ .o o~ .f a~ .o o~ -f a~ .f f~ -o o~
-h h~ .l l~ .1 1~ -l l~ .o o~ .s s~ -a a a~
-s s~ .sh sh~ .y y~ .y c~ -y-o y-o -y y~ .C C~ -a a~
-C C~ .l l~ .L L~ -L C~ -l l~ .Y Y~ -o o o~

The internal rules for make are contained in the source file. Rules for the program can be locally modified. To print the rules compiled into the make file in a form suitable for compilation, use the following command:
`make -pf 2>/dev/null`

A tilde in the above rules refers to an SCCS file (see sccsfile(4)). Thus, the rule c~o would transform SCCS source file into an object file (.o). Because the s of the SCCS files is a prefix, it is incompatible with the make suffix point of view. Hence, the tilde is a way of changing any reference to an SCCS file reference.

A rule with only one suffix (for example, .c) is the definition of how to build x from x.c. In effect, the other suffix is null. This feature is useful for building targets from only one source file, for example, shell procedures and C programs.

Additional suffixes are given as the dependency list for. SUFFIXES is significant: the first possible name for both a file and a rule is inferred as a prerequisite. The default list is:

```
SUFFIXES: .o .c ~y y~ .1 1~ -s s~ ~sh~ .sh sh~ .h h~ .f f~ .C C~
.Y Y~ .L L~
```

Here again, the command for printing the list of suffixes implemented on the current machine. Multiple lists accumulate:
SUFFIXES: with no dependencies clears the list of suffixes.

# Inference Rules

The first example can be done more briefly.

```
pgm: a.o b.o cc a.o b.o -o pg
```

```
a.o b.o: incl.h
```

This abbreviation is possible because make has a set of internal rules for building files. You can add rules to this list by simply putting them in the makefile.
