# nca, snca — Solaris Network Cache and Accelerator (NCA)

# Description

The Solaris Network Cache and Accelerator (NCA), new, in the Solaris 8 Operating Environment, is a kernel module that provides improved Web server performance. The kernel module, ncakmod, services HTTP requests.

To improve the performance of serving HTTP requests, the NCA kernel module maintains an in-kernel cache of Web pages. If the NCA kernel module cannot serve the request itself, it passes the request to the HTTP daemon (htptpd). The NCA uses either a sockets interface, with family designed PF_NCA, or a private Solaris interface based on the Solaris RPC mechanism, to pass the request.

To use the sockets, the Web server must open a socket of family type PF_NCA. The PF_NCA family supports SOCK_STREAM and protocol 0; otherwise, an error occurs.

The following features are presently not supported.

+   * You cannot initiate a connection from a PF_NCA socket type. The connect(SOCKET) interface on PF_NCA fails.

+   * System calls associated with SO_DGRAM, which send(), sendto(), sendmsg(), recv(), recvfrom(), and recvmsg() fail. In the Solaris 9 release,

+   * You cannot set TCP or IP options on a PF_NCA type socket through setsockopt(SOCKET).

+   * For configuration information, see System Administration Guide, Volume 3

+   * When PF_NCA socket does not exist in the Web server, you must use the ncad_addr(4) interface to provide NCA socket on that Web server.

+   * NCA is intended to be run on a dedicated Web server. Running other large while running NCA can result in undesirable behavior.

Starting with the Solaris 9 release, NCAs support the logging of in-kernel cache hits. See nalogd.conf(4). NCA stores logs in a binary format. Use the ncab2clf(1) to convert the log from binary format to the Common Log File format.
