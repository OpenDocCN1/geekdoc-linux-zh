# ctags — Create a Tags File for Use with ex and vi

# Synopsis

```
/usr/bin/ctags [-aBFtuvwx] [-f tagsfile] file...
/usr/xpg4/bin/ctags [-aBFuvvwx] [-f tagsfile] file...
```

# Description

The ctags command makes a tags file for ex(1) from the specified C, C++, Pascal, FORTRAN, yacc(1), and lex(1) sources. A tags file gives the locations of specified objects (in this case, functions and typeddefs) in a group of files. Each line of the tags file contains the object name, in the file in which it is defined, and an address specification for the object definition. Functions are searched with a pattern, typeddefs with a line number are searched in separate fields in separated by space or Tab characters. Using the tags file, ex can quickly find these object definitions.

Normally, ctags places the tag descriptions in a called tags file; you can override this default by using -f option.

Files with names ending in .c or .cc are assumed to be either C or C++ source files and are searched for C/C++ routine and macro definitions. Files with names ending in .cc, .C or .cxx are assumed to be C++ source files. Files with names ending in .y are assumed to be yacc files. Others are first examined to see if they contain any Pascal or FORTRAN routine definitions; if not, they are processed again, looking for C definitions.

The main tag is specially treated in C or C++ programs. The tag is formed by prepending M to file, with a trailing .c, .cc, .c or .c removed, if any, and leading path-name components also removed. This behavior makes use of ctags practical in directories with more than one program.

# Options

When printing, specify first -x and -v options, then the remaining options.

-   -a Append out to an an existing tags file.

-   -B Use backward searching patterns (...?).

-   -f tagsfile Place the tag descriptions in a called tagsfileinstead of tags.

-   -F Use forward searching patterns (/.../...) (default).

-   -t Create tags for typeddefs. /usr/xpg4/bin/ctags creates tags for typeddefs by default.

-   -u Update the specified files in tags, that is, delete all references to them, and append the new values to the file. Because: This option is implemented in a way that is rather slow; it is usually faster to rebuild the tags file.

-   -v Produce on the standard output an index listing the function name, file name, and page number (assuming 64-line pages). Because the output is sorted into lexicographic order, you may want to run the output through -f.

-   -w Suppress warnings diagnostics.

-   -x Produce a list of object names, the line number, and file name on which each is defined, as well as the text of that line and print it on the standard output. This list provides a simple index that can be printed as an off-line readable function index.

# Operands

-   -file.c Treat files with basenames ending with the .c suffix as C-language source code.

-   -file.h Treat files with basenames ending with the .h suffix as C-language source header files.

-   -file.f Treat files with basenames ending with the .f suffix as FORTRAN-language source code.

# Usage

The -v option is used mainly with vgrind, which is part of the optional BSD Compatibility package.

# Notes

Recognition of functions, subroutines, and procedures for FORTRAN and Pascal is done in a simple-minded way. No attempt is made to deal with block structure; if you have two Pascal procedures in different blocks with the same name, you lose.

The method of deciding whether to look for C or Pascal and FORTRAN functions is a hack.

The ctags command does not know about #ifdefs. ctags command should know about Pascal types. It relies on the input being used to detect typedefs. of -tx shows only the last line of typedefs.

# Examples

Using ctags with the -v option produces entries in an order that may not be appropriate for vgrind. To produce results in alphabetical order, you may want to pipe the output through sort -f, as shown in the following example

```
ctags -v ctags filename.h | sort -f > index
```

```
ctags% vgrind -x index
```

To build a tags file for C sources in a directory hierarchy rooted at sourdir, create an empty tags file, then run find(1), as shown in the following example

```
ctags$ cd sourdir; rm -f tags; touch tags
```

```
ctags$ find . \ -name SCCS -pr
```

# cu — Call Another System

# Synopsis

```
/usr/bin/cu [-aBFtuvwx] [-f tagsfile] file...
/usr/xpg4/bin/cu [-aBFuvvwx] [-f tagsfile] file...
```

# Description

cu calls another UNIX system, a terminal, possibly. It manages operating in two phases. The first phase is the connection phase in which connection is established. cu then enters the conversation phase. The -d option is the only one that applies to both phases.

# Options

The -c, -l, and -s options play a part in selecting the medium; the remaining options are used in configuring the line.

-   -b bits
    Force bits to be the number of bits processed on the line. bits is either 7 or 8. This option enables connection between systems with different character sizes. By default, the character size of the line is set to that of the terminal.

-   -c device
    Use entries only in the Type field (the first field in /etc/uucp/Devices) that match the user-specified device, usually the name of a local area network.

-   -C local-cmd
    Run the local-cmd specified at the end of the line instead of entering interactive mode. The standard in and standard out of the command refer to the remote connection.

-   -d
    Print diagnostic traces.

-   -e
    Set an EVEN data parity for data sent to the remote.

-   -h
    Set communication mode to half-duplex. This option emulates local echo to support calls to other systems that expect terminals to be set to half-duplex.

-   -H
    Ignore hangup. This option enables the user's system to remain in the remote machine disconnects and places a call back to the local machine Use this option when connecting to systems with callback or dialback modems. Once the callback occurs, subsequent hangups terminate. You can specify this option more than once. For more information about dialback configuration, see remote(4).

-   -l line
    Specify a device name to use as the communication line. You use this option to override the search that would otherwise take place for the first available line with the speed. When you use the -l option without the -s option, the speed of a line is taken from the /etc/uucp/Devices file which matches the second field (the Line). When you use the -l and -s options, cu searches the /etc/uucpeed file to check whether the requested speed for the requested line is available. If, the connection is made at the requested speed; otherwise, an error message is printed and the call is not made.

-   -l Go through the login chat sequence specified in /etc/uucp/Systems file. For more information about the chat sequence, see TCP/IP and Data Communications Administration Guide.
