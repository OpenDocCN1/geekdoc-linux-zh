# rup — Show Host Status of Remote Systems (RPC Version)

# Synopsis

```
/usr/bin/rup [-hlt]
/usr/bin/rup [host...]
```

# Description

The rup command to find out how long a system has up and to display the load average. rup gives a status similar to uptime for remote systems. It broadcasts on the local network and displays the responses it receives.

Normally, the listing is in the order that responses are received, but you can change this order by specifying one of the options listed below.

When you specify host arguments, instead of broadcasting, rup queries only the list of specified hosts.

A remote host responds only if it is running the statad daemon, which is normally started from inetd(8).

# Options

- -h Sort the display alphabetically by host name.
- -l Sort the display by load average.
- -t Sort the display by uptime.

# Examples

The following example shows the uptime and load average for the system castle.

```
castle% rup castle
    castle      up      3:55      load average: 0.06, 0.02, 0.01
castle%
```

# ruptime — Show Host Status of Local Systems

# Synopsis

```
/usr/bin/ruptime [-ar] [-l | -t | -u]
```

# Description

Use the uptime command to view a status line like uptime for each system on the local network; these statistics are formed from packets broadcast by each host on the network once a minute.

Systems for which no status report has been received for 5 minutes are shown as being down.

Normally, the listing is sorted by host name, but you can change this order by specifying one of the options listed below.

# Options

- -a Count even those users who have been idle for an hour or more.
- -l Sort the display by load average.
- -r Reverse the sorting order.
- -t Sort the display by uptime.
- -u Sort the display by number of users.

The -l | -t | -u options are mutually exclusive. The use of one overrides the previous one(s).

# usage — Print Resource Usage for a Command

# Synopsis

```
/usr/ucb/rusage command
```

# rusage

# Description

The rusage command is similar to time(1). It runs the command, which you must specify; that is, command() is not optional as it is in the C shell timing facility. When the command is complete, rusage displays the real (wall clock), the system CPU, and the user CPU times that elapsed during execution of the command, plus other fields in the rusage structure, all on one long line. Times are reported in seconds and hundredths of a second.

# Examples

The following example shows the format of rusage output.

```
castle# rusage wc /kookaburra-1
      9 47 264 kookaburra-1
0.07 0.02 user 0.03 sys 0 pf 0 sw 0 rb 0 wb 0 vcx 0 icx 0 mx 0
ix 0 id 0
cast#
```

Each of the fields identified corresponds to an element of the rusage structure, described in getrusage(3C), as follows:

| real elapsed time |
| :--- |
| user ru_utime user used |
| sys ru_stime system time used |
| pf ru_majflit page faults requiring physical I/O |
| pr ru_minflt page faults requiring physical I/O |
| sw ru_nswap swaps |
| rb ru_inblock block input operations |
| wb ru_oublock block output operations |
| vcx ru_nvcsw voluntary context switches |
| icx ru_nivcsw involuntary context switches |
| mx ru_maxrss maximum resident set size |
| ix ru_idrss currently 0 |
| id ru_idrss integral resident set size |
| is ru_isrss currently 0 |

# rusers — Display Who Is Logged In on Remote Systems

# Synopsis

/usr/bin/rusers [-hilu]

# Description

The rusers command produces output similar to who(1), but for remote systems. The listing is in the order that responses are received, but you can change this order by specifying one of the options listed below. The default is to print the names of users logged in. When you specify the -l option, additional information is printed for each user. If hostname is not idle, the idle time is not displayed. A remote host responds only if it is running the statad daemon, which is started from inetd(8).

# Options

- -a Report all users whether or not they have typed to the system in the past hour.
- -h Sort alphabetically by host name.
- -i Sort by idle time.
- -l Display a longer listing in the style of who(1).
- -u Sort by number of users.

# Examples

The following example shows the output of rusers for a small network.
castle% rusers
Sending broadcast for rusers version 3...
castle winsor
seach g
castle% winsor:console Mar 30 08:04 :0
castle%

# rwho — Display Who Is Logged In On Local Systems

# Synopsis

```
/usr/bin/rwho [-a]
```

# Description

Use the rwho command to display a list of the users logged in to all systems in your network with the login TTY port and the date and time. who is similar to who(1). If no report has been received from a system for 5 minutes, rwho assumes the system is down and does not report users last known to be logged in that system. If a user has not typed to the system for an hour or more, rwho reports this idle time. If a user has not typed to the system for an hour or more, the user is omitted from the output of rwho unless you specify the -option.

# Notes

rwho does not work through gateways. The directory /var/spool/rwho must exist on the host from which you run rwho. This service takes up progressively more network bandwidth as the number of hosts on the local net increases. For large networks, the cost becomes prohibitive. The rwho daemon, in.rwhod(1M), must be enabled for this command to return useful results.

# Options

- -a Report all users whether or not they have typed to the system in the past hour.
