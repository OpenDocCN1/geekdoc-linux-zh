# deroff — Remove nroff/troff, tbl, and eqn Constructs

# Synopsis

```
/usr/bin/deroff [-m [m | s | 1]] [-w] [-i] [filename...]
```

# deroff Description

deroff reads each of the file names in sequence; it removes troff(1) requests, macro calls, backslash constructs, eqn(1) constructs between .EQ and .EN between lines and delimiters), and tbl(1) descriptions, perhaps replacing them with white space (blanks and blank lines). Then, deroff writes the remainder of the file on the standard output. deroff follows chained included files (.so and .nx commands); if a file has already been included, a .so naming that is ignored and a .nx naming file terminates execution.

If you provide no input file, deroff reads the standard input.

> Note — deroff is not a complete troff interpreter, so it can be confused by subtle constructs. Most such errors result in much instead of too little

# Options

+   -m You can follow the -m option with an m, s, or 1. The -mm option interprets the macros so that only running is output (that is, no text from macro lines). The -ml option forces the -mm option and also deletes lists associated with the mm macros. Note that the -ml option does not handle nested lists.

+   -w Output a word, one per line, and delete all other characters. In text, a word is any string that contains at least two letters and is composed of letters, digits, ampersands (&), and apostrophes (‘); in a macro call, however, a word is a string that begins with at least two letters and contains a total of at least three letters. Delimiters are any characters other than letters, digits, apostrophes, and ampersands. Trailing apostrophes and ampersands are removed from words.

+   -i Ignore troff .so and .nx commands.

# Examples

The following example uses the more command to display the beginning lines of the deroff.1 manual page, then uses the deroff command to remove formatting constructs.

```
castle% deroff.1

# dhcpinfo — Display Value of Parameters Received with DHCP

# Synopsis

```
/sbin/dhcpinfo [-c] [-i interface] [-n limit] code
/sbin/dhcpinfo [-c] [-i interface] [-n limit] identifier
```

# Description

DHCP (Dynamic Host Configuration Protocol) permits a client to establish an endpoint
communication with a network by delivering an IP address of one or more of the
client's network interfaces and a "lease" on that address. The dhcpinfo command to
print the value(s) of the parameter requested on the command line as specified by the
protocol. If the DHCP protocol implies more than one value (that is, a list of
ways), the values are printed, separated by newline characters. The parameter can be
identified by its numeric value in the DHCP protocol, or its mnemonic
identified by its long name. This is intended to be used in command
substitutions in the shell scripts invoked by init(1) at system boot, init first contacts
the DHCP agent daemon dhcpagentinit(1) to verify that DHCP has successfully
completed. When a particular interface is used with the -o option, the daemon verifies
fully DHCP configuration of that specific interface; otherwise, the client verifies
the interface marked as the "primary" has successfully configured and supplies the
ame of that interface back to dhcpinfo. You should not return values echoed by dhcpinfo without checking the exit status.

# Output Format

In New Solaris 8, the release from dhcpinfo consists of one or more lines of
ASCII text. The format of the output depends on the requested parameter. The number
of values returned per line is determined by the parameter's granularity. The total
of lines output for a given parameter is determined by the parameter's
maximum values as defined by dhcp_inittab(4).

The format of each individual value is determined by the data type of the option, as
determined by dhcp_inittab(4).
