When the database is a valid database name defined in the nswitch.conf file, the ldap command uses a predefined attribute type, as specified in the following table. When the database name is invalid, the ldaplist command uses cn as the attribute type.

The ldaplist command relies on the Schema defined in RFC 2307bis.

> Note — RFC 2307bis is an IETF experimental document, in draft stage, that defines an approach for using LDAP as a Network Information Service.

The data stored on the LDAP server must be stored in accordance with this Schema unless the profile contains schema mapping definitions (new in the Solaris 9 release). The following table lists the mapping from the database names to the container, the LDAP object class, and the attribute used if not defined in the key. Databases in the Solaris 9 release are shown with the New icon in the margin.
