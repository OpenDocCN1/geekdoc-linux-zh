# proc tools

pstop
Stop each process (PR_REQUESTED stop).

ptime
Time a command, such as the time(1) command, but using microsecond
accounting for reproducible precision.

ptree
Print the process trees containing the specified pid or users, with child
processes indented from their respective parent processes. Take an
argument of all digits to a process ID; otherwise, assume it is a user
login name. Default is all processes.

pwait
Wait for all of the specified processes to terminate.

pwdx
Print the current working directory of each process.

The pfiles, pldd, pmap, and pwdx commands stop their target processes
while inspecting them and reporting the results. While a process is stopped, it can do
nothing.

# Options

+   -a
(ptree only) Include children of process 0.

+   -a
(pargs only) Print process arguments as contained in argv[]. New in the
Solaris 9 release

+   -e
(pargs only) Print process environment variables and values. New in
the Solaris 9 release

+   -F
Force a grab of the target process even if another process has control.

+   -l
(pmap only) Print unresolved dynamic linker maps.

+   -n
(psig only) Display signal handler addresses instead of name. New in the
Solaris 9 release

+   -r
(plags only) If the process is stopped, display its machine registers.

+   -r
(pmap only) Print the process's reserved addresses.

+   -s
(pmap only) Print page size of hardware translations used. New in the
Solaris 9 release

+   -v
(pwait only) Report each termination to standard output.

+   -x
(pmap only) Print process resident/shared/mapping details.

+   -x
(pargs only) Print process auxiliary vector. New in the Solaris 9
release

# Usage

The pfiles, pldd, pmap, and stack proc tools stop their processes while
inspecting them and reporting the results. A process can do nothing while it is stopped.
For example, if the X server is inspected by one of these proc running in a
window under the X server's control, the whole system can become deadlocked
because the proc tool would be trying to print its results to a window that cannot be
logged. Logging from another system with rkill(1) and killing the offending proc
tool would clear the deadlock in this case.
