# jobs, fg, bg, stop, notify

# Description

Job control enables you to move currently executing commands into the background and to stop, suspend, restart them as needed. There is always one job in the foreground, which is the job that accepts your keyboard input. The foreground job may be a shell or another command as an editor that accepts keyboard input.

When you execute a command line or start a job in the foreground, input to the terminal window is blocked and you cannot execute additional commands until that job completes. You can use the job control commands to push that job into the background or bring it back to the foreground so you can control it or enter data from the terminal window. Job control enables you to perform these actions within the current layer or order.

Each command or pipeline that you enter at a terminal window is assigned a positive job id. The shells keep track of current and previous jobs. The current job is the most recent job to be started or restarted. The previous job is the first noncurrent job. All jobs exist in one of the following states:

+   - A foreground job has read and write access to the controlling terminal.
- A background job is denied read access and has conditional write access to the controlling terminal ( SIGTY1).
- A stopped job is a job that has been placed in a suspended state, usually as a result of a SIGTSTP signal (see signal).

The Korn and C shells have the jsh job control shell of the Bourne shell all support job control.

# Output

For all of the shells, if you specify no options, the output is a series of lines of the following form.

```
[%d] %c %s\n, job-number, current, state, command
```

The fields are described below.

| job-number | A number used to identify the process to wait, fg, bg, and kill commands. With these commands, you can identify the job by prefixing the job with % |
| current | The - identifies the job that would be used as a default for the fg or bg commands; you can also specify this job with job-id+ or % %. The character identifies the job that would become the default if the current default job were to exit; you can also specify this job with job-id -. For other jobs, this is a space character. You can identify one job + and one job with -. If there is any suspended job, then the current job is a suspended job. If there are at least two suspended jobs, then the previous job is also a suspended job. |
| state | Running | The job has not been suspended by a signal and has not exited. |
|  | Done | The job completed and returned exit status 0. |
