The default output of a prior invocation of umask on the same system with no operand is also recognized as a umask operand. The use of an operand obtained in this way is not obsolescent, even if it is an octal number.

# Output

If you specify no umaskarguments, the umask command writes a message to standard output that can later used as a umask mask operand.
If you specify -S for /usr/bin/umask, the output is displayed in symbolic format, as shown in the following example.

```
castle$ /usr/bin/umask -S
u=rwx,g=rx,o=rx
cast$
```

The three values are combinations of letters from the set r, w, x; the presence of a letter indicates that the corresponding bit is clear in the file-mode command syntax. The symbolic syntax in the previous example is equivalent to an octal mask of 022.

```
castle$ /usr/bin/umask
022
castle$
```

If you specify a umask operand, no output is written to standard output.

# Examples

Either of the following commands sets the mode mask so that subsequently created files have their S_IWOTH (others) bits cleared.

```
umask a=rx,ug+w
umask 002
```

After setting the mode mask with either of the above commands, you can use the umask command to display the current value of the mode mask.

```
castle$ ksh
$ umask 002
$ umask
02
$ umask -S
u=rwx,g=rx,o=rx
$
```

> Note — The output format is unspecified, but historical implementations use the obsolete octal integer format.

You can then use either of these outputs as the mask operand to a subsequent invocation of the umask command.

Assuming the mode mask is set as above, the following command sets the mode mask so that subsequently created files have their S_IWGRP (group) and S_IWOTH (others) bits cleared.

```
$ umask g-w
$ umask
022
$
```
