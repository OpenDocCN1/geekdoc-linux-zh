# Options

- -c Display the output in a canonical format. This format is identical to the OCTET format with a granularity of 1. New in the Solaris 8 release.

- -i interface In general, you should need to use this option on hardware with two or more interfaces configurable by DHCP, and for a parameter that is interface specific.

- -n limit When the tag is one with a list of values, limit the number printed.

# Operands

- -code Numeric code for the requested DHCP parameter as defined by the DHCP specification. Vendor options are specified by adding 256 to the actual vendor code. New in the Solaris 8 release.

- -identifier Mnemonic request for the DHCP parameter as listed in dhcp_inititab(4).

# Exit Status

- -0 Successful operation.
- -2 DHCP was not successful. The DHCP agent may not be running, the interface might have failed to configure, or no satisfactory DHCP responses received.
- -3 Bad arguments.
- -4 A timer was set with wait (see ifconfig(1)), and the interface had not configured before it expired.
- -6 Some system error (should never occur).

# diff — Display Line-by-Line Differences between Pairs of Text

## Files

# Synopsis

```
/usr/bin/diff [-bitw] [-c | -e | -f | -h | -n | -u] file1 file2
/usr/bin/diff [-bitw] [-C number | -U number] file1 file2
/usr/bin/diff [-bitw] [-D string] file1 file2
/usr/bin/diff [-bitw] [-c | -e | -f | -h | -n] [-1] [-r] [-S name]
file1 file2
```

# Description

The diff command compares the contents of file1 and file2 by line and produces
a complete index of all of the lines that differ between the two files, along with their line
numbers. It also reports what must be changed to make the files match. No output is
produced if the files are identical.

The example illustrates the diff output for two simple files.
```
caste$ diff kookaburra1 kookaburra2
4c4
< Gay your life must be.
----
> Glad your life must be.
caste$
```

Each section of the diff output begins with a code that indicates what kinds of
diff the following lines refer to. In the previous example, the 4c4. This code tells you that there is a change (c) between line 4
in the first file and line 4 in the second file. Lines containing text only in the first
file begin with < . Lines containing text found only in the second file begin with >. The
dashed line separates parts of the output that refer to different sections of the file.
The normal output contains lines of these forms:

```
n1 a n3,n4
n1,n2 d n3
n1,n2 c n3,n4
```

where n1 and n2 represent lines in file1 and n3 and n4 represent lines in file2. The a (append) code indicates that a line is added following the line in the first file. The d (delete) code indicates that lines are found in one file but not in the other. The c (change) code indicates that there is a change between the lines in the two files.

These resemble ed(1) or vi(1) commands to convert file1 to file2. By exchanging a d and reading backward, you can convert file2 to file. As in, identical pairs, where n1=n2 or n3=n4, are abbreviated as a single number.

Following each of these lines comes all the lines in the first file that are affected flagged by < , then the lines that are affected in the second file flagged by >.

> Note — Editing scripts produced under the -e or -f options are naive about creating lines consisting of a single period (.).

A missing newline at end-of-file indicates that the last line of the file did not have a newline. If the lines are different, they are flagged and output, although the output seems to indicate they are the same.

List differences with three lines of context. The output is similar to the -c option except that the context is unified.
```

 -n1,n2+n3,n4 @@
```
This option is new in the Solaris 9 release.

List differences in the same way as the -u option with numbered lines of context. This option is new in the Solaris 9 release.
The identification of file1 and file2 is different, with --- used instead of n-c option and +++ instead of the -c option ---. Each option is separated by a line of the following form.

```
@@ -n1,n2+n3,n4 @@
```
