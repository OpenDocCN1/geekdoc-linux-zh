sccs-admin, admin

1219

-z

Recompute the file checksum, and store it in the first line of the s. file.
Caution: It is important to verify the contents of the history file (see sccs-val(1) and the print subcommand in sccs(1)) because using -z
on on a truly corrupted file can prevent detection of the error.

# Warnings

The last component of all SCCS files must have the s. prefix. New SCCS files arengiven permission mode 444 (see chmod(1)). All writing by admin is to a temporary
file with an x. prefix, created with mode 444 for a new SCCS file or with the same mode
as existing SCCS file. After successful execution of admin, the existing s. file
removed and replaced with the x file. This sequence ensures that changes are made to
t SCCS file only when no errors occurred

It is recommended that directories containing SCCS files have permission 755
and the s. files have mode 444. The mode for directories allows only the
row to modify the SCCS files contained in the directories, and the mode of the s. files
prevents all modifications except those performed with SCCS commands.

If you need to patch an SCCS file for any reason, the owner can change the mode to
444 to use of a text editor. However, take extreme care when editing an SCCS file.
Always process the edited file with an admin -h to check for corruption, followed by an
admin -z to generate a prefix checksum. Another admin -h is recommended to ensure
t the resulting s. file is valid

admin also uses a temporary lock file, starting with the s. prefix, to prevent
simultaneous updates to the s. file. See sccs-get(1) for further information about the
z. file.
