Programs generated by lex need the -e or -w option to handle input that contains EUC characters from supplementary codets. If you specify neither of these options, yytext is of the type char[], and the generated program can handle only ASCII characters.

When you use the -option, bytes yytext is of the type unsigned char[] and yyleng gives the total number of bytes matched. With this option, the macros input(), input(c), and output(c) should do a byte-based I/O in the same way as with regular ASCII. Two more variables are available with the -option--yytext and yyleng behave the same as would yytext and -w.

When you use the -w option, yytext is of the type char_t[] and yyleng gives the total number of characters matched in the string. If you supply your own input(), input(c), or output(c) macros with this, they must return or accept EUC characters in the form of wide character (wchar_t). This enables a different interface between your program and the lex externals to expedite some programs.

# Rules in lex

The Rules source files are a table in which the left column contains regular expressions and the right column contains actions (C-program fragments) to be executed when the expressions are recognized.

```
ERE action
ERE action
```

The extended regular expression (ERE) portion of a row is separated from action by one or more blank characters. A regular expression containing blank characters is recognized under one of the following conditions:

+   - The entire expression appears within double quotes.
- The blank characters appear within double quotes.
- Each character is preceded by a backslash character.

# Regular Expressions in lex

The lex command supports the set of Extended Regular Expressions (EREs) described in regex(5) with the following additions and exceptions to the syntax.

Any string enclosed in double quotes represents the characters within the double quotes as themselves, except that backslash escapes (appear in the following table) are recognized.
