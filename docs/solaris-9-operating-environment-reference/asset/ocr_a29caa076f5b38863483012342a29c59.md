# mdb 821

mdb provides a completely customizable environment for debugging and scenarios, including a dynamic module facility that you can use to implement your own debugging commands to perform program-specific analysis. You can use each mdb module to examine the program in several different contexts, including live and postmortem.

# Defitions

The target is the program being inspected by the debugger. mdb currently supports the following types of targets.

+   * User processes.
* User process corefiles.
* The live operating system (through /dev/kmem and /dev/ksym).
* Operating system crash dumps.
* User process images recorded inside an operating system crash dump.
* ELF objectfiles.

Each target has a standard set of properties, including one or more addresses, one or symbol tables, a set of load objects, and a set of threads that can be examined with the debugger commands below.
A debugger, or demd (pronounced dee-command) in mdb terminology, is a router in the debugger that can access any of the properties of the current target. mdb parses commands from standard input and executes the corresponding demands. Each demd can also accept a list of string or numerical arguments, as shown in "Syntax" on page 821. mdb contains a set of built-demands, described in "Commands" on page 822, which are always available. You can extend the capabilities of mdb itself by writing your own demands, as described in the Solaris Modular Debugger Guide.
A walker is a set of routines that describe how to walk—or iterate—through the elements of a particular data structure. A walker encapsulates the structure's implementation from demands and mdb itself. You can use walkers interactively or as primitives to build other demands and walkers. With demands, you can extend mdb by implementing your own walkers as part of a debugger module.
A module, or demd (pronounced dee-command), is a dynamically loaded library that contains a set of demands and walkers. During initialization, mdb tries to load demands corresponding to the objects present in the target. You can subsequently load or unload demands at any time while running mdb. mdb ships with a set of static demands for debugging the Solaris kernel. The Solaris Modular Debugger Guide contains more information on developing demands.
A macro file that contains a set of commands to execute. Macro files are typically used to automate the process of displaying a simple data structure. mdb provides complete backward compatibility for the execution of macro files written for adb(1), and the Solaris installation includes a set of macro files for debugging the Solaris kernel that you can use with either.

# Syntax

The debugger processes commands from standard input. If standard input is a terminal, mdb provides terminal editing capabilities. mdb can also process commands from file and demd, as described in "demd Pipelines" on page 828.
