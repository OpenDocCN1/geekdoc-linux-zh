# ed, red — Text Editor

# Synopsis

```
/usr/bin/ed [-s -] [-p string] [-x] [-C] [file]
/usr/xpg4/bin/ed [-s -] [-p string] [-x] [-C] [file]
/usr/bin/ed [-s -] [-p string] [-x] [-C] [file]
```

# Description

The ed command is the standard text editor. If you specify a file, ed reads the file into ed's buffer so that it can be edited.

> Note — Although we have supersed ed as a line editor, commands such as diff continue to use ed.

The ed command operates on a copy of the file it is editing; the original file remains unchanged until you use a [write] command. The copy of the text being edited resides in a temporary file called the buffer. There is only one buffer.

Unlike vi and ex commands, ed does not display any of the text in its buffer unless you ask for it. As a result, it is difficult to keep track of the current contents of the buffer.

The red is restricted to standard ed. It allows editing of files in the current directory only. It prohibits executing shell commands using the !shell command. Attempts to bypass these restrictions result in an error message (restricted shell).

Both ed and red support the spec(4) formatting capability. The default mode is either stty -tabs or stty, where Tabs stop at eight columns (see stty(1)). If however, the first line of file contains a format specification, that specification overrides the default mode. The following example of the first line of a file Tabs stops at 5, 10, and 15, and a maximum length of 72.

```
<t:5,10,15>:
```

Commands to ed have a simple and regular structure: zero, one, or two addresses followed by a single-character command, possibly followed by parameters to that command. The addresses specify one or more addresses in the buffer. Every command that requires default addresses, so you can often omit the addresses. In general, you can specify only one command per line.

ed has separate input modes. If you enter an invalid command, ed writes the string with ? (followed by an explanatory message if you have enabled help mode with the H) to output and continues in command mode with the current line number unchanged.

Certain commands allow the input of text. This is put in the appropriate place in the buffer. While ed is accepting text, it is said to be in input mode. In this mode, ed recognizes no commands; it merely collects all input. You leave input mode by typing a period (.) at the beginning of a line, followed immediately by a Return.

> Note — If the editor is coming from a command file (for example, ed file < ed-cmd-file), the editor exits at the first failure.
