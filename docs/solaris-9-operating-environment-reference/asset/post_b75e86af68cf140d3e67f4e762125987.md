## pkgparam — Display Package Parameter Values

### Synopsis

```
/usr/bin/pkgparam [-v] [-d device] [-R root-path] pkginst [param...]
/usr/bin/pkgparam -f filename [-v] [param...]
```

### Description

Use the pkgparam command to display the value associated with the parameter or parameters requested on the command line. The values are located in either the pkginfo(4) for pkginst or from the specific file named with the -f option.

One value is shown per line. Only the value of a parameter is given unless you use the -v option. With the -v option, the output of the command is in the following format.

```
parameter1=value
parameter2=value
parameter3=value
```

The following example shows the output of the -v option for the SUNwith package.

```
castle $ pkgparam -v SUNwith
CLASSES='base docs runtime
BASEDIR='/usr'
```

## pkgproto — Generate Prototype File for Input to pkgmk

### Synopsis

```
/usr/bin/pkgproto [-i] [-c class] [path1]
/usr/bin/pkgproto [-i] [-c class] [path1=path2...]
```

### Description

pkgproto scans the indicated paths and generates prototype(4) file entries that can be used as input to pkgmk(1).

If you specify no paths on the command line, standard input is assumed to be a list of paths. If the path name listed on the command line is a directory, the contents of the directory are searched. However, if input is read from standard input, a directory specified as a path is not used.

By default, pkgproto creates symbolic link for any symbolic link (ftime). When you use the -i option, pkgproto creates a file for symbolic links (ftime). You would have to edit the prototype(4) file to assign types as v (volatile), e (editable), or x (exclusive directory). pkgproto detects linked files. If multiple files are linked together, the first path is considered the source of the link.

By default, pkgproto prints prototype entries to the standard output. However, you should save the output in a file (named prototype) to be used as input to pkgmk(1).

### Options

- **-i** Ignore symbolic links, and record the paths as f (a file) or l (a symbolic link).
- **-c class** Map the class of all paths to class.

### Operands

- **path1** Path name where objects are located.
- **path2** Path name that should be substituted on output.

### Examples

The following examples show uses of pkgproto and a partial listing of the produced:

```
castle% pkgproto /bin=bin /usr/bin=usr /etc=etc
```

## pkgptrans — Translate Package Format

### Synopsis

```
/usr/bin/pkgptrans [-i] device1 device2 [pkginst...]
```

### Description

The pkgptrans command translates an installable package from one format to another. It performs the following translations:

- A file-system format to a datastream
- A datastream to a file-system format
- One file-system format to another file-system format.

Device specifications can be either the node name (for example, /dev/diskette) or a device alias (for example, diskette). The device specify indicates the default pool directory. Source and destination devices cannot be the same.

By default, pkgptrans does not translate any instance of a package if any instance of that package already exists on the destination device. Using the -n option creates a new instance if an instance of this package already exists. Using the -o option overwrites an instance of this package if it already exists. Neither of these options is useful if the destination device is a datastream.

## pkgtrans 1061

### Options

Copy only the pkginfo(4) and pkgmap(4) files.

- **-i** Create a instance of the package on the destination device if any instance of this package already exists, up to the number specified by the MAXINST variable in the pkginfo(4) file.
- **-n** Overwrite the same instance on the destination device if it already exists.
- **-o** Write the package to device2 as a datastream instead of as file system. The default behavior is to write a file-system format on devices that support formats.
- **-s**

### Operands

- **device1** The source device. The package or packages on this device are translated and placed on device2.
- **device2** The destination device. Translated packages are placed on this device.
- **pkginst1** Specify which package instance or instances on device1 should be translated. You can use the token all to indicate all packages. You can use pkginst.* to indicate all instances of a package. If no packages are defined, a prompt shows all packages on the device and asks to translate.

The asterisk (*) is a special character to some shells and may need to be escaped. In the C shell, you must surround * with single quotes (''') or precede it with a backslash (\).

### Examples

The following example translates all packages on the diskette drive /dev/diskette and places the translations on /tmp.

```
castle% pkgtrans /dev/diskette /tmp all
```

The following example translates packages pkg1 and pkg2 on /tmp and puts their translations (that, is, datastream) on the 9track1 output device.

```
castle% pkgtrans /tmp /track1 pkg1 pkg2
```

The following example translates pkg1 and pkg2 on /tmp and puts them on the diskette as datastream format.

```
castle% pkgtrans -s /tmp /dev/diskette pkg1 pkg2
```
