# Escape Description Meaning

| \ | Backslash slash.

| | Slash character.

| \ddd | A backslash character followed by the longest sequence of one-, two-, or three-digit octal characters (01234567). If all of the digits are 0 (null character), the behavior is undefined.

| | The character encoded by the one-, two-, or three-digit octal integer. Multbyte characters concatenated escape sequences, including the leading \ for byte.

| \c | A backslash character followed by any character not described in this table or the special characters \\, \a, \b, \f, \n, \r, \t, \v.

| | Undefined.

A regular expression can be matched against a specific string or by one of the two regular expression matching operators to interpret their right-hand operand as a regular expression and their left-hand operand as a string. If the regular expression matches the string, the expression evaluates to 1, and the regular expression does not match the string, the expression evaluates to 0, and the !! expression evaluates to the value 1. If the right-hand operand is a string rather than the lexical token, the string value of the expression is interpreted as an regular expression, including the escape conventions described above. Note that same escape conventions are also applied in defining the value of a string literal (the lexical STRING) and applied a second time when a string literal is used in this context.

When an ERE appears in any context other than the right-hand side of the ~ operator or as of the built-in function arguments described below, the value of the resulting expression is equivalent of $0 ~ /ere/. The argument to the gsub, match, and sub functions and the FS argument are interpreted as regular expressions. These ERE are interpreted in the same manner as the right-hand side of the ~ or !! operator.

An extended regular expression can separate fields using the -F ERE option by assigning a string containing the expression to the built-in variable FS. The default value of the FS variable is a single-space character FS behaves in the following way:

  * Otherwise, if FS is any other character c, fields are delimited by each single occurrence of c.
2. Otherwise, the string value of FS is considered an extended regular expression. Each occurrence of a sequence matching the extended regular expression limits fields.

Otherwise, the string value of FS is considered an extended regular expression. Each occurrence of a sequence matching the extended regular expression limits fields.
