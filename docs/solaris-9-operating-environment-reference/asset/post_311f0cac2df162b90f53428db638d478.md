
$(parameter- word)

If parameter is set and is non-null, substitute its value; otherwise substitute word

$(parameter:= word)

If parameter is not set or null, set it to word; otherwise, substitute the value of the parameter. You cannot assign positional parameters in this way.

$(parameter?: word)

If parameter is set and is non-null, substitute its value; otherwise, print word and exit from the shell. If you omit word, print the parameter null or not set.

$(parameter+ word)

If parameter is set and is non-null, substitute word; otherwise, substitute nothing. In the above, word is not evaluated unless it is to be used as the substituted string, so in the following example, pwd is executed only if d is not set or null:

```
echo $(d:-`pwd`)
```

If you omit the colon (:) from the above expressions, the shell checks only whether parameter is set or not.

The following parameters are automatically set by the shell:

- The number of positional parameters in decimal.
- Options supplied to the shell on invocation or by set command.
- The value returned by the last executed command.
- The process number of the last background command.
- The process number of the shell invoked.

The following parameters in this section are also referred to as environment variables:

- HOME: The default argument for the cd command, set to the user's login directory (see passwd).
- PATH: The search path for commands (see Execution).
- CDPATH: The search path for the cd command.
- MAIL: If this parameter is set to the name of a file and MAILPATH parameter is not set, the shell informs you of the arrival of mail in the file.
- MAILCHECK: Specify how often (in seconds) the shell checks for the arrival of mail in the files specified by MAILPATH parameters. The default value is 60 seconds. If set to 0, the shell checks before prompt.
- MAILPATH: A colon-separated list of file names. If this parameter is set, the shell informs the user of arrival of mail in any of the specified files. Each file name can be followed by % and a message that is printed when changes.
- PS1: Primary prompt string; by default, $.
- PS2: Secondary prompt string; by default, >.
- IFS: Internal field separators, normally space, Tab, and newline (see Blank Interpretation).
- SHACCT: If this parameter is set to the name of a file writable by the user, write an accounting record in the file for each procedure executed.
- SHELL: When the shell is invoked, it scans the environment for this name.
- LC_TYPE and LC_MESSAGES: affect the execution of sh. The shell gives default values to PS1, PS2, and IFS. Default values for HOME and MAIL are set by login.

# Blank Interpretation

After parameter and command substitution, the results of substitution are scanned for internal separator characters (those found in IFS) and split into distinct arguments where such characters are found. Explicit null arguments ('') are retained. Implicit null arguments (resulting from parameters that have values) are removed.

# Input/Output Redirection

You can redirect the input and output of a command by using special notation interpreted by the shell. The following constructs can appear anywhere in a command or can precede or follow a command and are not parsed as arguments to the invoked command. Parameter and command substitution occurs before word is used:

```
< word Use file word as standard input (file descriptor 0),
> word Use file word as standard output (file descriptor 1). If the file does not exist, create it; otherwise truncate to zero length.
>> word Use file word as standard output. If the file exists, append to it (by first seeking to the end-of-file); otherwise, create the file.
<> word Open file word for reading and writing as standard input.
<< word After parameter and command substitution is done on word that literally matches the resulting word, or up to the first line of end-of-file. If, however, it is appended to <<:
- Strip tabs from word before reading the shell input (but after parameter and command substitution is done on word).
- Strip leading Tabs from the shell input as it is read and before line is compared with word.
- Read shell input up to the first line that literally matches the resulting word, or to an end-of-file.

If any character of word is quoted, do not perform additional processing to the shell input. If no characters of word are quoted:

- Do parameter and command substitution.
- Remove (escaped) newlines.
- Use \ to the characters \, $, and `.

The resulting document becomes the standard input.

```
<digit
Use the file associated with file descriptor digit as standard input. Similarly for the standard output, use &digit.
```
<-
Close the standard input. Similarly for the standard output, use >-.
```

If any of the above is preceded by a digit, the file descriptor that is associated with the file is specified by the digit (instead of 0 or 1). For example, the following statement associates file descriptor 2 with the file currently associated with file descriptor 1:

```
... 2>&1
```

The order in which you specify redirections is significant. The shell evaluates redirections left-to-right. For example, the following statement first associates file descriptor 1 with file xxx. It associates file descriptor 2 with the file associated with file descriptor 1 (that is, xxx).

```
... 1>&1
```

If the order of redirection were reversed, file descriptor 2 would be associated with the terminal (assuming file descriptor 1 had been so associated) and file descriptor 1 would be associated with file xxx.

Using the terminology introduced under "Commands", if a command is composed of several simple commands, redirection is evaluated for the entire command before it is evaluated for each simple command.

# File-Name Generation

* Match any string.
? Match any single character.
[...] Match any one of the enclosed characters.
! Match any character except the enclosed.
If the first character following [ is a ], the word is regarded as literal.

# Quoting

The following characters have a special meaning to the shell unless quoted: ; & | ^ < newline

You can quote or escape a character (that is, make it stand for itself) by preceding it with a backslash (\) or by inserting it between a pair of quote marks (''). During processing, the shell can quote certain characters to prevent them from having a special meaning. Backslashes used to quote a single character are removed from the word before the command is executed.

All characters enclosed between a pair of single quotes ('') except a single quote, are quoted by the shell. Backslash has no special meaning inside a pair of single quotes. You can quote a single quote inside a pair of double quotes (").

Inside a pair of double quotes ("), parameter and command substitution occurs and the shell quotes the results to avoid blank interpretation and file-name generation. If $* is within a pair of double quotes, the positional parameters are substituted and quoted, separated by spaces ("$1 $2..."); however, if $ is within a pair of double quotes, the positional parameters are substituted and quoted, separated by unquoted spaces ("$1 "$2...") quotes the \, and $. The pair \newline is removed before parameter and command substitution.

# Prompting

When used interactively, the shell prompts with the value of PS1 before reading a command. If at time you press newline and further input is needed to complete a command, the secondary prompt (that is, the value of PS2) is displayed.
