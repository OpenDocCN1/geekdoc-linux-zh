# msgfmt - Create a Message Object from a Message File

# Synopsis

```
/usr/bin/msgfmt [-D dir --directory=dir] [-f --use-fuzzy] [-g]
[-v] [-o output-file --output-file=output-file] [-s] [--strict]
[-v] [--verbose] filename.po...
```

# Description

msgfmt creates message objects from portable objectfiles(filename.po), without changing the portable objects.

The po file contains messages displayed to users by system commands or application programs. You can edit .po files and rewrite the messages in them in any language supported by the system.

You can use the xgettext(1) command to create .po files from scripts or programs. msgfmt interprets data as characters according to the current setting of the LC_CTYPE locale.

> Note — Neither msgfmt nor any gettext() routine imposes a limit on the total length of a message. However, each line in the .po file is limited to MAX_INPUT(512) bytes.

Installing message catalogs using the C language is pointless because they are ignored for the sake of efficiency.

# Portable Objectfiles

Formats for all .po files are the same. Each .po file contains one or more lines, with each containing either a comment or a statement. Comments start the line with a pound sign (#) and end with the newline character. All comments (except special comments described later) and empty lines are ignored. The format of a statement is:

```
directive value
```

Each directive starts at the beginning of the line and is separated from value by
white space such as one or more spaces or Tab characters. value consists of one or more
quoted strings separated by white space. Use any of the following types of directives for
Solaris message file.

```
domain domain
msgid message_identifier
msgstr message_string
```

Starting with the Solaris 9 release, for a GNU-compatible message file, use any of the
following types of directives.

```
domain domain
msgid message_identifier
msgid_plural translated_string_plural
msgstr message_string
msgstr[n] message_string
```

The behavior of the domain directive is affected by the options used. See "Options" on
page 884 for the behavior when you specify the -o or --output-file option. (The
--output-file option is new in the Solaris 9 release.) If you do not specify the -o or
--output-file option

- If you use the Solaris message catalog file format-new in the Solaris 9
release to generate the message object or specify the --strict option, then
put all msgs from the beginning of each .po file to the first domain directive into
a default message object, messages.mo. Otherwise, the default object is
named messages.mo

- When msgfmt encounters a domainname directive in the .po file, put all
following msgs until the next domain directive into the message object
domainname.if you use the Solaris message catalog file format-new in the
Solaris 9 release to generate the message object or if you specify the --strict
option. Otherwise, put the msgs into the message object named domainname.

- Define duplicate msgs in the scope of each domain. That is, a msgid is considered
duplicate only if the identical msgid exists in the same domain.

- Ignore all duplicates

The msgid directive specifies the value of a message identifier associated with the
directive that follows it. The msgid_plural-directive in the Solaris 9
release specifies the plural form message to the message handling functions ngettext(), dgettext(), or dngettext(). The message_identifier identifies a string to be used at retrieval time. Each statement
a msgid directive must be followed by a statement containing a msgstr directive or
msgstr(n).

The msgstr directive specifies the target string associated with the
message_identifier declared in the immediately preceding msgid directive.
The msgstr[n]-directive in the Solaris 9 release-where n = 0, 1, 2...
specifies the target string to be used with plural form functions ngettext(),
dgettext(), and dngettext().

Message strings can contain the escape sequences \n for newline, \t for Tab, \v for
vertical Tab, \r for Return, \f for formfeed, \\ for backslash, \" for
double quote, \ddd for octal bit pattern, and \xdd for hexadecimal bit pattern.

# GNU-Compatible Message Files

Use one of the following formats for comments for a GNU-compatible message file (the
msfmt command ignores these comments when processing Solaris message files).

```
# translator-comments
# automatic-comments
# reference...
# flag
```

The #: comments indicate the location of the msgstr string in the source files in
filename: line format. The #, #., and #, comments are informative only and
silent ignored by the msfmt command. The #, comments require one or more flags
separated by the comma. You can specify the following flags.

fuzzy

The translator can insert fuzzy to show that the msgstr string might
be a correct translation. Only the translator can judge if
t translation requires further modification or is acceptable as is.
Once satisfied with the translation, the translator removes the fuzzy
flag. If this flag is specified, msfmt does not generate the entry for the
immediately following msgstr in the output message catalog.

c-format

no-c-format

> The c-format flag indicates that the msgid string is used as a format
string by printf-like functions. The c-format flag is given for a
string, the msfmt command does some more tests to check the validity
of the translation.

In the GNU-compatible message file, the msgid with empty string (**) is called
the header entry and treated specially. If the message string for the header entry
contains plural=value, the value indicates the number of plural forms. For example,
plural=4 means there are four plural forms. If plural is defined, the
line should contain plural-expression, separated by a semicolon character.
The expression is a C language expression to determine which version of msgstr[n] is to
be used, based on the value of n; the last argument of gettext(), gettext(), or
dgettext(). For example.

```
n=2; plural = n == 1 ? 0 : 1
```

indicates that there are two plural forms in the language. msgstr[0] is used if n == 1;
oror msgstr[1] is used if n == 2. In another example,

```
n=3; plural = n == 1 ? 0 : 2
```

indicates that there are three plural forms in the language. msgstr[0] is used if n == 1,
and msgstr[1] is used if n == 2; msgstr[2] is used.

If the header entry contains a charset=charset string, codet specifies the
to encode the message strings. If the output string charset is different from
the message string's codet, conversion from the message string's codet to
theoutput string's codet is performed on the call of gettext(), dgettext(),
dgettext(), ndgettext(), andtext() for the GNU-compatible
message catalogs. The output string's charset is determined by the current locale's

codeset (the return value of nl_langinfo (CODESET)) by default and can be changed by the call of bind_textdomain_codeset ().

# Message Catalog File Formats

Starting with the Solaris 9 release, the msgfmt command can generate the message object both in Solaris message catalog format and in GNU-compatible message catalog format. If you specify the -s option and the input file is a Solaris .po file, the msgfmt command generates the object in Solaris message catalog format. If you specify the -g option and the input file is a GNU .po file, the msgfmt command generates the object in GNU-compatible message catalog format. If you specify neither -s nor theg option, the msgfmt command determines the message catalog format as follows:

- The .po file contains a valid header entry (having an empty string for msgid), the msgfmt command uses the GNU-compatible message catalog format.
- Otherwise, the msgfmt command uses the Solaris message catalog format. If the msgfmt command determined that the Solaris message catalog format is used, as above, but found that the .po file contains directives that are specific to the GNU-compatible message catalog format, such as msgid_plural and msgstr[n], the msgfmt command handles those directives as invalid specifications.

# Options

- -D dir
  --directory=dir

Add dir to the list for input file search. New in the Solaris 9 release.

- -f
  --use-fuzzy

Generate fuzzy entries in output. If you do not specify this option, fuzzy entries are not included into the output. These options are ignored if Solaris message catalogs are processed. New in the Solaris 9 release.

- -g

Generate the GNU-compatible message catalog file. You cannot specify this option with the -s option. New in the Solaris 9 release.

- -o output-file
  --output=output-file

Specify the output file name as output-file. All domain directives and duplicate msgid in the .po file are ignored. The --output option is new in the Solaris 9 release.

- -s

Generate the Solaris message catalog file. You cannot specify this option with the -g option. New in the Solaris 9 release.

- -strict

Append the .mo suffix to the generating message object file if it doesn't have this suffix. This option is ignored if Solaris message catalogs are processed. New in the Solaris 9 release.

- -v--verbose

List duplicate message identifiers if Solaris message catalog files are processed. Message strings are not redefined.
