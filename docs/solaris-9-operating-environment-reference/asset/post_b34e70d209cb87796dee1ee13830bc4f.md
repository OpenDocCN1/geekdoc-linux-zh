# Description

When you create a file or directory, the default file permissions assigned to the file or directory with the mask are controlled by the user mask. You set the user mask with the umask command in a user initialization file such as /etc/profile or .cshrc. You can display the current value of the user mask by typing umask and pressing Return.

You set the user mask with a three-digit octal value such as 022. The first digit permissions for the user, the second for the group, and the third for others. To set the umask to 022, type

File permissions of 666 read and write permissions to the user, group, and others. Directory permissions of 777 grant read, write, and execute permissions to the user, group, and umask. The value assigned is subtracted from these values. To determine the umask value you want to set, subtract the permissions you want from 666 (for a file) or 777 (for a directory). The remainder is the value to use with the umask command. For example: suppose you want to change the default mode for files to 644 (rw-r----). The difference between 666 and 644 is 022, which is the value to use as an argument to the umask command.

Setting the umask value denies permissions in the same way that the chmod command grants them. For example, the chmod 022 grants write permission to group and others, umask 022 denies permission for group and others.

```
/usr/bin/umask
```

The umask command sets the file-mode creation mask of the current shell execution environment to the value specified by the umask oper. This mask affects the initial value of the file permission bits of subsequently created files. If umask is called in a subshell or separate command execution environment, as one of the following,

(umask 002)
nohup umask...
find . -exec umask...

it does not affect the file-mode creation mask of the caller's environment. For this reason, you cannot use /usr/bin/umask to change the umask in an ongoing session. Its usefulness is limited to checking the caller's umask. To change the umask of an ongoing session, use one of the shell built-ins.

If you do not specify the umask order, the umask command displays to standard output the value of the invoking process file-mode creation mask.

## Bourne and C Shells

Set the file-mode creation mask for ooo. The three octal digits refer to read/write/execute permissions for owner, group, and other (see chmod(1), chmod(2), and umask(2)). The value of each digit is subtracted from the corresponding digit specified by the system for the creation of a file (see create(2)). For example, umask 022 removes write permission for group and other (file created with 777 become 775; files created with 666 become 644).

- - If you omit ooo, the current value of the mask is displayed.
- umask is recognized and executed by the shell.
- To automatically set the permissions on created files or directories, you can include umask in your .profile for the Bourne shell (see profile(4)) or in your .shrc file for the C shell. These initialization files are invoked at login.

## Korn Shell

Set the file-mode creation mask for mask. mask can either be an octal number or a symbolic value as described in chmod(1). If you omit umask, the current value of the mask is printed.

## Options

- -S own umask as a symbolic argument.

The default output style is unspecified but recognized in a subsequent invocation of umask on the same system as a umask operand to restore the previous file-mode creation mask.

## Operands

mask A string specifying the new file-mode creation mask. The string is treated in the same way as the mode operand described in the chmod(1) manual page.

For a symbolic-value, the new value of the file-mode creation mask is the logical complement of the file bits bits of the file mode specified by the symbolic-string.

In a symbolic-mode value, the permissions + and - are interpreted relative to the current file-mode creation mask; + clears the indicated permissions in the mask; - sets the bits of the indicated permissions in the mask.

The interpretation of mode values that specify file bits other than the file permission bits is unspecified.

The file-mode creation mask is set to the resulting numeric value.

## Output

If you specify umask, the output is in symbolic format. The default output style is unspecified but recognized in a subsequent invocation of umask on the same system as a umask operand to restore the previous file-mode creation mask.

The three values are combinations of letters r, w, x; the presence of a letter indicates the corresponding bit is clear in the file-mode creation.

## Examples

Either of the following commands sets the mode mask so that subsequently created files have their S_IWOTH (others) bits cleared.

```
umask a=rx,ug+w
umask 022
```

After setting the mode mask as above, the following command sets the mode mask so that subsequently created files have their S_IWGRP (group) and S_IWOTH (others) bits cleared.

```
$ umask g-w
$ umask 022
```

The following command sets the mode mask so that subsequently created files have all their write bits cleared.

```
$ umask -w
$ umask 022
```

> Note — You must precede mask operands r, w, x, or anything beginning with a dash (-) with two dashes (--) to prevent them from being interpreted as an option.

umask 022
```

After setting the mode mask as above, the following command sets the mode mask so that subsequently created files have their S_IWGRP (group) and S_IWOTH (others) bits cleared.

```
$ umask g-w
$ umask 022
```

The following command sets the mode mask so that subsequently created files have all their write bits cleared.

```
$ umask -w
$ umask 022
```

> Note — You must precede mask operands r, w, x, or anything beginning with a dash (-) with two dashes (--) to prevent them from being interpreted as an option.
