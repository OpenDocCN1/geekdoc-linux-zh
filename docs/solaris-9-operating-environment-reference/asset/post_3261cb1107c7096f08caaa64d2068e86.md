## Dynamic Macros

Several dynamically maintained macros are useful as abbreviations within rules. They are shown here as references. If you define them, make simple overrides the definition.

- $* The basename of the current target, derived as if selected for use with an implicit rule.
- $<: The name of a dependency file, derived as if selected with an implicit rule.
- $@: The name of the current target. This macro is the only one whose value is strictly determined when used in a dependency list (in which case, it takes the form $$).
- ?: The list of dependencies that are newer than the target. Command dependency checking is automatically suppressed for lines that contain this macro just as if you had prefixed the command with a ?. You can force this check with the !command-prefix.
- $$: The name of the library member being processed. (See "Library Maintenance" on page 807).

To refer to the $$ dynamic macro within a dependency list, precede the reference with an additional $ character (as in, $$). Because make assigns $ and $$ as it would be unreliable (according to the suffixes list and the directory contents), they may be unreliable when used within implicit targets.

You can modify these macros to apply either to the file-name part (F) or the directory part (D) of the strings they stand for, by adding an uppercase F or D (@D) and enclosing the resulting name in parentheses or braces. Thus, $(D) refers to the directory part of the string $; if there is no directory part, it is assigned. $(F) refers to the file-name part.

## Conditional Macro Definitions

A macro definition of the following form indicates that when processing any of the targets listed and their dependencies, macro is to be set to the value supplied.

```
target-list := macro = value
```

- — If a conditional macro is referred to in a dependency list, the $ must be delayed ($$ include). Also, target-list can contain a % pattern, in which case the macro is conditionally defined for all targets encountered that match the pattern. You can use a pattern-replacement reference within the value.

You can temporarily append a macro's value with a conditional definition of the following form.

```
target-list := macro += value
```

## Implicit Rules

When a target has no entry in makefile, make tries to build this class (if any) and apply the rule for that. An implicit rule describes how to build any target of a given class from associated dependency file. In addition to a predefined set of implicit rules, make enables you to define your rules, either by pattern or by suffix.

## Pattern-Matching Rules

A target of the following form is a pattern-matching rule where tp is a target prefix, ts a target suffix, dp is a dependency prefix, and ds is a dependency suffix (any of which can be null).

```
tpts: dpds dpds
```

The % stands for a basename of zero or more characters that are matched in the target and is used to construct the name of a dependency. When make encounters a match in its search for an implicit rule, it uses the rule in that entry to build the target from the dependency file. Pattern-matching implicit rules typically use the $ and $ dynamic macros as placeholders for the target and dependency names. Other, regular dependencies can occur in the dependency list; however, none of the regular dependencies contain %. An entry of the following form is a valid pattern-matching rule:

```
tpts: {dependency...} dpds {dependency...}


## Suffix Rules

When no pattern-matching rule applies, make checks the target name to see if it ends with a suffix in the known suffixes list. If so, make checks for any suffix rules, as well as a dependency file with the same root and another recognized suffix, from which to build it.

The entry for a suffix rule takes the following form:

```
Dts: rule
```

where Ds is the suffix of the dependency file, Ts is the suffix of the target, and rule is the rule for building a target in the class. Both Ds and Ts must appear in the suffixes list. (A suffix need not begin with a . to be recognized.)
