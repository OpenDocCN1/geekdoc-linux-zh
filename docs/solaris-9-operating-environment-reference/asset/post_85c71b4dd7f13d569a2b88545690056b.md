# ex — Display-Based Text Editor

# Synopsis

```
/usr/bin/ex [- | -s] [-1] [-L] [-R] [-r [file]] [-t tag] [-v] [-V] [-x] [-wm] [+command] [-c command] file...
/usr/xpg4/bin/ex [- | -s] [-L] [-R] [-r [file]] [-t tag] [-v] [-V] [-X] [-wm] [+command] [-c command] file...
```

# Description

The ex command is the root of a family of editors: ex, edit, and vi is a superset of ed(1), with the most notable extension being a display-editing facility. Display-based is the focus of vi.

If you have used a terminal, you may want to use a display-based editor; in this case, see vi(1), which is a command that focuses on the display-editing portion of ex.

If you have used ed, you will find that, in addition having all of the ed commands available, ex has a number of additional features useful with CRT terminals. Intelligent terminals and high-speed terminals are very pleasant to use; the editor uses more of the capabilities of terminals than ed does. The editor uses the terminal capability database (terminfo(4)) and the type of terminal you are using from the environment variable TERM to determine how to drive your terminal efficiently. The editor makes use of such features as "insert and delete character and line" in its visual command (the vi command).

The ex contains a number of features to allow easy viewing the text of a file command gives easy access to windows of text. Entering Control- scrolls half-window of text and is more useful for quickly stepping through a file than just pressing Return. Of course, the screen-oriented visual mode gives constant access to editing content.

The ex command helps when you make mistakes. The undo (u) command enables you to reverse any change that goes astray. ex gives you a lot of feedback, normally changed lines, and indicates when more than a few lines are affected by a command so that it is easy to detect when a command has affected more lines than it should have.

The editor also normally prevents overwriting existing files, unless you edited them, so that you do not accidentally overwrite a file other than the one you are editing. If the system (or) editor crashes or you accidentally hang up the telephone, you can use the editor recover command. This facility gets you back within a few lines of where you left off.

The ex command has several features for dealing with more than one file at a time. You can give a list of files on the command line and use the next (n) command to get each in turn. You can also give the next command of file names, or a pattern used by the shell, to specify a new set of files to deal with. In general, you can format file names in the editor with shell syntax. The metacharacter % is also available in forming file names and is replaced by the name of the current file.

The editor has a group of buffers whose names are the ASCII lowercase letters (a-z). You can place text in these buffers, where it is available to be inserted elsewhere in the file. The contents of these buffers are available to be used in a variety of ways. For example, the `a` command allows you to append the text of a buffer to the current line. The `b` command allows you to replace the current line with the text of the buffer. The `c` command allows you to change the current line to the text of the buffer. The `d` command allows you to delete the text of the buffer. The `e` command allows you to move to the end of the word. The `h` command allows you to move to the beginning of the line. The `i` command allows you to insert the buffer before the current line. The `j` command allows you to move to the next line. The `k` command allows you to move to the previous line. The `l` command allows you to move to the next character. The `n` command allows you to move to the next occurrence of a search. The `p` command allows you to paste the buffer after the current line. The `q` command allows you to quit the editor. The `r` command allows you to replace a character with the buffer. The `s` command allows you to search for a string. The `t` command allows you to search for a character in a string. The `u` command allows you to undo a change. The `v` command allows you to enter visual mode. The `w` command allows you to move to the start of the next word. The `y` command allows you to copy the text of the buffer.

# ex

+command | -c command

Begin editing by executing the specified editor command (usually a search).

-C Simulate the C command. The C command is like the X command, except that all text read is assumed to have been encrypted.

-L Set up for editing LISP programs.

-L List the name of all files saved as the result of an editor or system crash.

-R Set the read-only flag to prevent accidental overwriting of file.

-r file Edit afterlife an editor or system crash. (Recover the version of file that was in the buffer when the crash occurred.) Note that the message too large to recover with -r option indicates you can successfully edit and save the file. However, if the editing session is lost, you cannot recover the file.

-t tag Edit the file containing the tag, and position the editor at its definition.

-V Start up in display-editing state using vi. You can achieve the same effect by simply typing the vi command.

-V When commands are read by means of standard input, echo the input to standard error. This verbose option can be useful for processing ex commands within shell scripts.

-wn Set the default window size to n. This option is useful when you are using the editor over a slow-speed line.

-X Simulate the X command, and prompt for an encryption key. This key encrypts and decrypts text using the algorithm of the crypt command. The X command makes an educated guess to determine whether text read is encrypted or not. The temporary buffer file is encrypted also, using a transformed version of the key typed in for -x option.

Note Although the following options continue to be supported, they have been replaced in the documentation by options that follow the Command Syntax Standard (using incr(1)). The option has been replaced by -si -r option that is not followed by an option- has been replaced by -L, and +command has been replaced by -c command

If you specify the bo-t tag and -c command, the -t tag is processed first. That is, the file containing tag is selected by -t and then the command is executed.

Note The Solaris version of ex will be replaced by the POSIX.2-conforming version (using standards(5)) in the future. Scripts that use the ex family of addressing and features should use the /usr/xpg4/bin version of these commands.
