```

```

Send either TERM (terminate) signal, by default, or the signal specified, to the specified process ID, the job indicated, or the current job. Give signals by number or by name. Typing kill does not send a signal to the current job. If the signal being sent is CONT (terminate) or HUP (hang), then the job or process is sent a CONT (continue) signal as well.

```
limit [-h] [resource [max-use]]
```

Limit the consumption by the current process or any process it spawns, each not to exceed max-use. Print the current limit; if you omit max-use, display all limits. (Run the sysdef(1) command to obtain the maximum possible limits for your system. The values reported are in hexadecimal, which can translate them into decimal numbers by using the bc(1).

Use hard limits instead of current limits. Hard limits impose a ceiling on the values of the current limits. Only superuser can raise the hard limits.

resource can be one of the following values:

- cptime Maximum CPU seconds per process.
- filesize Largest file size allowed; limited to the size of the file system. See df(1).
- datasize Maximum data size (including stack) for the process; the size of your virtual memory. See swap(1M).
- stacksize Maximum stack size for the process. See swap(1M).
- coresize Maximum size of a core dump (file); limited to the size of the file system.
- descriptors Maximum number of file descriptors. Run sysdef(1).
- memoryize Maximum size of virtual memory.


Increment the process priority value for the shell or for command by n
The higher priority value, the lower priority of a process and

```
onintr [-label]
```

Control the action of the shell on interrupts. With no arguments,
restore the default action of the shell on interrupts. (The shell
terminates shell scripts and returns to the terminal command input
level.) With the argument, the shell ignores all interrupts. With a
label argument, the shell executes a goto label when it receives an
interrupt or a child process terminates because it was interrupted.

popd [+n] Pop the directory stack and change to the new top directory. The elements of the directory stack from 0, starting at the top. When you specify +n, discard the n-th entry in the stack.

pushd [+n] dir Push a directory onto the directory stack. With no arguments, exchange the top two elements. When you specify +n, rotate the n-th entry to the top of the stack and change to it. With dir-argument, push the current working directory onto the stack and change to dir.

rehash Recompute the internal hash table of the contents of directories in the path variable to account for new commands. Recompute the internal hash table of the contents of directories listed in the cpath variable to account for new directories.

repeat command Repeat command count times. command is subject to the same restrictions as with the one-line if statement.

set [var = value]

set var[n] With no arguments, display the values of all shell variables. Display multiword values as a parenthesized list. With the argument alone, assign an empty (null) value to the var variable. With arguments of the form var = value, assign value to var, where value is of:

- word A single word (or quoted string).
- (wordlist) A space-separated list of words enclosed in parentheses.

Values are command and file-name expanded before being assigned. The set var[n] = word replaces the n-th word in a multword with word

setenv [VAR] With no arguments, display all environment variables. With the VAR argument, set the environment variable VAR to have an empty (null) value. By convention, environment variables are normally given uppercase names. With both word and VAR arguments, set the environment variable NAME to the value which must be either a single word or a quoted string. The most commonly used environment variables, USER, TERM, and PATH, are automatically imported to and exported from the csh variables, term, and path; you do not need to use setenv for these. The shell sets PWD variable whenever latter changes.
