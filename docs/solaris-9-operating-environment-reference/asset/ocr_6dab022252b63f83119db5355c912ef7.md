# test

**Note** — In test, -a has higher precedence than -o, and && and || have equal precedence in the shell.

You can use parentheses or braces in the shell command language for grouping.
You must escape parentheses when using sh; for example,

```
test \( expr1 -a expr2 \) -o expr3
```

This command is not always portable outside XSI-conant systems. Instead, we can use the following:

```
( test expr1 && test expr2 ) || test expr3
```

The following two commands could not be used reliably on some historical systems.

```
test "$1"
test ! "$1"
```

Unexpected results occur if such a string condition is used and $1 is expanded to !, (\, or a known unary primary. Better constructs are

```
test -n "$1"
test -z "$1"
```

Historical systems have also been unreliable given the common construct

```
test "$response" = "expected string"
```

One of the following is a more reliable form.

```
test "Xresponse" = "Expected string"
test "expected string" = "$response"
```

Note that the second form assumes that "expected string" could not be confused with any unary primary. If "expected string" starts with -, (, or even =, use the first form instead. When the preceding rules work without the marked extensions, any of the three comparison forms are reliable, given any input. However, that the strings are quoted in all cases.

Because the string-comparison binary primitives = != have a higher precedence than any unary primary in the >4 argument case, unexpected results occur if arguments are not properly prepared. For example, in the following construct, if $1 evaluates to a possible directory name of -, the first three arguments are considered a string comparison, and a syntax error is displayed when the second -d is encountered.

```
test -d $1 -o -d2
```

One of the following prevents this problem; the second is preferred.

```
test \ -d "$1" \). -o \ -d "$2" \
test -d "$1" || test -d "$2"
```
