
# Options

- -d
Display the reasons why make chooses to rebuild a target. Display any and all dependencies that are newer. In addition, display options read in from the MAKEFLAGS environment variable.

- -dd
Display the dependency check and processing in vast detail.

- -D
Display the text of the makefiles read in.

- -DD
Display the text of the makefiles, make.rulesfile, the state file, and all dependency reports.

- -e
Specify that environment variables override assignments within makefiles.

- -f makefile
Use the description file. A (-) as makefile argument denotes the standard input. The contents of makefile, when present, override the standard set of implicit rules and predefined macros. When you specify more than one -f makefile argument, use the concatenation of those files in order of appearance.

- -i
Ignore error codes returned by commands.

- -k
When a non-zero status is returned by a rule or make cannot find a rule, abandon work on the current target but continue with other dependency branches that do not depend on it.

- -K
Use statefile. A dash (-) as statefile argument denotes the standard input. The contents of statefile, when present, override the standard set of implicit rules and predefined macros. When you specify more than one -K statefile argument, use the concatenation of those files in order of appearance.

- -n
Merely report dependencies instead of building them.

- -p
Print the complete set of macro definitions and target descriptions.

- -P
Return a 0 non-zero status depending on whether the target file is up-to-date.

- -r
Do not read the default Makefile.

- -s
Do not print command lines before executing them. Equivalent to SILENT.

- -S
Undo the effect of the -k option. Stop processing when a command returns a non-zero exit status.

- -t
Touch the target (bringing them to-date) instead of performing their rules. This option can be dangerous when files are maintained by more than one person. When the .KEEP_STATE appears in the Makefile, update the target file as if the rules had been performed.

- -V
Put make into SysV mode. Refer to sysmake(1) for details.

# Operands

- target
Target names.

- macro=value
Macro definition. This definition overrides any regular definition for the specified macro within the Makefile itself or in the environment. However, you can override this definition with conditional macro assignments.

# Usage

Refer to make in Programming Utilities Guide for tutorial information.

# Reading Makefiles and the Environment

When make starts, it reads the MAKEFLAGS environment variable to obtain any of the following options specified in value: -d, -D, -e, -i, -k, -n, -p, -q, -r, -s, -S, or -t. Because of the implementation of POSIX.2 (see POSIX.2(5)), the MAKEFLAGS values contain a leading character. The make command reads the command line for additional options, which also take effect.

Next, make reads a default Makefile that typically contains predefined macro definitions, target entries for implicit rules, and additional rules such as the rule for retrieving SCCS files. If present, make uses the file rules in the current directory; otherwise it reads the file /usr/share/lib/make/make.rules, which contains the standard definitions and rules. Use the following directive in your local make.rules file:

```
include /usr/share/lib/make/make.rules
```

Next, make reads variables from the environment (unless you specify the --option), and treats them as defined macros. Because make uses the most recent environment it encounters, a macro definition in the makefile normally overrides environment variable of the same name. When you specify -e, however, environment variables are read after all makefiles have been read. In that case, the environment variables take precedence over the makefile.

Next, make reads any makefile you specify with -f one of makefile described above, and then uses the file in the directory if it exists. If the makefile contains a KEEP_STATE_FILE, then make reads the state file that follows the target. For special target, See KEEP_STATE_FILE for details.

Next (after reading the environment if you specify -e), make reads in any macro definitions supplied as command-arguments. Macro definitions override macro definitions both in the makefile and in the environment. However, if a command line contains a reference to the $(MAKE) macro, always execute that line. When in POSIX mode, execute lines beginning with (+).

If there is a named Makefile in the working directory, use that file. If an SCCS history file (SCCS/makefile) is newer, try to retrieve and use the most recent version. In the absence of the above files, if a named Makefile is present in the working directory, try to use it. If an SCCS history file (SCCS/makefile) is newer, try to retrieve and use the most recent version.

When you specify no Makefile, make tries the following in sequence, except in POSIX mode (see the "Special-Function Targets" on page 793):

- /usr/share/lib/make/make.rules
- .makefile
- Makefiles
- s.makefile

# Special Characters

This section lists global special characters and targets.

# Global

- # Start a comment. The comment ends at the next newline. If the # follows the Tab in a command, pass that line to the shell (which also treats # as the start of a comment).

```
filename
```

If the word include appears as the first seven letters of a line and is followed by a space or Tab, take the string that follows as file name. You can nest files to a depth of no more than 16. If filename is a macro reference, expand it.

# Targets and Dependencies

- : Target list terminator. Add words following the colon to the dependency list for the target. If you name a target in more than one colon-terminated target entry, add the dependencies for all its entries to form that target's complete dependency list.

- :: Target for alternative dependencies. When used in place of ;, the colon enables a target to check and update from alternative dependency lists. When the target is out-of-date with alternative dependencies listed in the first alternative, build it according to the rule for that entry. When out-of-date with dependencies in another alternative, build it according to the rule in that other entry. Implicit rules do not apply to double-colon targets; you must supply a rule for each entry. If you specify no dependencies, the rule is always performed.

```
target [+...]
```

Use the rule in the target entry to build all the indicated targets as a group. It is normally performed once per make run but is checked for command dependencies every time a target in the group is encountered in the dependency scan.

- % Match any string of zero or more characters in a target name or dependency, in the target portion of a conditional macro definition, or within a pattern-replacement macro reference.(Like the * wild-card). Note that a target, dependency name, or pattern-replacement macro reference can have only one %.

```
./pathname
```

Ignore the leading . characters from targets with names as path names relative to dot (the working directory).
