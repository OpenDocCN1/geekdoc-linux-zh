# isainfo — Describe Instruction Set Architectures

# Synopsis

/usr/bin/isainfo [-v] [-b | -n | -k]

# Description

Use the isainfo command to identify various attributes of the instruction set architectures supported on the currently running system. Among the questions isainfo can answer whether 64-bit applications are supported, or whether the running kernel uses 32-bit or 64-bit device drivers.

When invoked isainfo prints the name(s) of the native instruction sets for applications supported by the current version of the operating system. These names are a subset of the list returned by isalist(1). The subset corresponds to the basic applications environments supported by the currently running system.

# Options

- -b The number of bits in the address space of the native instruction set.
- -k The name of the instruction set(s) used by the operating system kernel such as device drivers and STREAMS modules.

- -n Print the name of the native instruction set used by portable applications supported by the current version of the operating system.

- -v Print more detailed information about the other options.

# Examples

The following are examples of invoking the isainfo command on different operating systems.

```
On a system running the 32-bit operating system on a 64-bit SPARC processor,
% isainfo -n
sparc
% isainfo -v
32-bit sparc applications
% isainfo -kv
32-bit sparc kernel modules
```

```
On a system running the 64-bit operating system on a 64-bit SPARC processor,
% isainfo
parcv9
% isainfo -n
spparcv9
% isainfo -vk
64-bit sparcv9 applications
64-bit sparcv9 kernel modules
```

# Exit Status

Non-zero Options are either not specified correctly, or the command is unable to recognize attributes of the system on which it is running. An error message is printed to standard error.

# isalist — Display the Native Instruction Sets for This Platform

# Synopsis

```
/usr/bin/isalist

```

# Description

isalist prints the names of the native instruction sets executable on this platform on the standard output, as returned by the SI_ISELIST command of sysinfo(2).

The names are space-separated and ordered in the sense of best performance. That is, earlier-named instruction sets may contain more instructions than later-named instruction sets; a program that is compiled for an earlier-named instruction most likely runs faster on this machine than does the same program compiled for a later-named instruction.

Programs compiled for instruction sets do not appear in the list most likely experience performance degradation or do not run at all on this machine.

The instruction sets known to the system are listed in isalist(5). These names may or not match predefined names or compiler options in the C-language compilation system.

# Example

The following example runs isalist on a SPARCstation 10.

```
castle% isalist
sparcv8 sparcv8-fsmuld sparcv7 sparc
cast%
```

# jobs, fg, bg, stop, notify

# Description

Job control enables you to move currently executing commands into the background and to stop, suspend, restart them as needed. There is always one job in the foreground, which is the job that accepts your keyboard input. The foreground job may be a shell or another command as an editor that accepts keyboard input.

When you execute a command line or start a job in the foreground, input to the terminal window is blocked and you cannot execute additional commands until that job completes. You can use the job control commands to push that job into the background or bring it back to the foreground so you can control it or enter data from the terminal window. Job control enables you to perform these actions within the current layer or order.

Each command or pipeline that you enter at a terminal window is assigned a positive job id. The shells keep track of current and previous jobs. The current job is the most recent job to be started or restarted. The previous job is the first noncurrent job. All jobs exist in one of the following states:

- A foreground job has read and write access to the controlling terminal.
- A background job is denied read access and has conditional write access to the controlling terminal (SIGTYIN).
- A stopped job is a job that has been placed in a suspended state, usually as a result of a SIGTSTP signal (see signal).

The Korn and C shells have the jsh job control shell of the Bourne shell all support job control.

# Output

For all of the shells, if you specify no options, the output is a series of lines of the following form.

```
[%d] %c %s\n, job-number, current, state, command
```

The fields are described below.

| job-number | A number used to identify the process to wait, fg, bg, and kill commands. With these commands, you can identify the job by prefixing the job with % |
| current | The - identifies the job that would be used as a default for the fg or bg commands; you can also specify this job with job-id+ or % %. The character identifies the job that would become the default if the current default job were to exit; you can also specify this job with job-id -. For other jobs, this is a space character. You can identify one job + and one job with -. If there is any suspended job, then the current job is a suspended job. If there are at least two suspended jobs, then the previous job is also a suspended job. | state | Running | The job has not been suspended and has not exited. | Done | The job completed and returned exit status 0. | Done (code) The job completed normally and it exited with the specified non-zero exit status, code. | Stopped (SIGTSTP) The job was suspended by the SIGTSTP signal. | Stopped (SIGSTOP) The job was suspended by the SIGSTOP signal. | Stopped (SIGTIN) The job was suspended by the SIGTIN signal. | Stopped (SIGTTO) The job was suspended by the SIGTTO signal. The implementation may substitute the string Suspended in place of Stopped. If the job was terminated by a signal, the format of state is unspecified but it is visibly distinct from all the other state shown here and indicates the name or description of the signal that terminated the job. | command The associated command that was given to the shell. |If you specify the -l option, a field containing the process group ID is inserted before the state field. Also, more processes in a process group may be output on separate lines, using only the process ID and command fields.

For jsh and ksh, if you specify the -p option, the output consists of one line for process ID. The following jsh example lists two jobs.

```
$ jobs
[1] - Running spider
[2] + Done (0) find -name core -print
$ 
```

Bourne Job Control Shell
The Bourne job control jsh provides all of the functionality of sh in addition to the built-in job commands. Typically, you use jsh only as an interactive shell; noninteractive shells typically do not benefit from the additional functionality of job control.

The jsh built-in command reports all jobs that are stopped or executing in the background. If you use %job-id the jsh command reports all jobs that are stopped or running in the background. The following options modify or enhance the output of jobs.

- -1 Report the process group ID and the working directory of the jobs.
- -p Report only the process group ID of the jobs.
- -x Replace any job-id in command or arguments with the corresponding process group ID, and execute command, passing its arguments.
