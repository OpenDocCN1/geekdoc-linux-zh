# wait — Await Process Completion

# Synopsis

```
sh
wait [pid]
/bin/jsh, /bin/ksh, /usr/xpg4/bin/sh
wait [pid]
wait [@job-id...]
/bin/csh
wait
```

# Description

When writing scripts, you will occasionally want to program the script to run simultaneous processes and wait for their conclusion before proceeding with other commands. The wait command provides shells with some of the job control features. It waits for all background processes to complete and reports their exit status.
The shell executes wait without creating a new process. If you get the error message "cannot fork, too many processes", try to clean up your background processes. If this doesn't help, the system table is probably fully or you have many active foreground processes. (There is a limit to the number of process IDs associated with your login and to the system can track.)
Not all the processes of a pipeline with three or more stages are children of the shell and, thus, they cannot be waited.

# Bourne and Job Control Shell

The wait command waits for a background process whose ID is pid and reports its exit status. If you omit pid all the shell's currently active background processes are waited for and the return code is 0. wait accepts a identifier when job control is enabled (jsh) and precede the job-id argument with a percent sign ().
If pid is not an active process, the wait command returns immediately and the exit status is 0.
