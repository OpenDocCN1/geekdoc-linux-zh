# Variables

A variable name, a corresponding integer value, and a set of attributes.
variable name is a sequence of letters, digits, underscores, or periods. You can assign a
variable with the value with : dcm or :typeset dcm and manipulate its attributes with
the : :typeset dcm. Each variable's value is represented as a 64-bit unsigned integer.
A variable can have one or more of the following attributes.

+   * Read-only (cannot be modified by the user)
* Persistent (cannot be unset by the user)
* Tagged (user-defined indicator).

The following variables are defined as persistent.

0 The most recent value printed using the /, \, ?, or = dcm.
9 The most recent count used with the $<dcm.
b The virtual address of the base of the data section.
d The size of the data section in bytes.
e The virtual address of the entry point.
m The initial bytes (magic number) of the target's primary objectfile, or
zero if no objectfile has been read yet.
t The size of the text section in bytes.
hits The count of the number of times the matched software specifier
has measured. "Event Callbacks" on page 834. New in the
Solaris 9 release.
thread The identifier of the current representative. The value of
identifier depends on the threading model used by the current
target. See "Thread Support" on page 834. New in the Solaris 9 release.

In addition, the mdb kernel and process tasks export the current values of
representative's register set as named variables. Many of these variables
depend on the target's name and instruction set architecture.

# Symbol Name Resolution

As explained in "Syntax" on page 821, a symbol identifier present in an expression
context evaluates to the value of this symbol. The value typically denotes the virtual
address of the storage associated with the symbol in the target's virtual address.
A target can support multiple symbol tables including, but not limited to, a primary
executable symbol, a dynamic symbol table, a runtime line-editor
