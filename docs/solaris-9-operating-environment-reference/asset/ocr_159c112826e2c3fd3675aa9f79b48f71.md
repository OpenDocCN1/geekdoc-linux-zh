```
cdc -rsid [-y[comment]] / (usr/ccs/bin/sccs)
cdc -rsid -rsid [-y[comment]] | (/usr/xpg4/bin/sccs)
```

Annotate (change) the delta commentary. See sccs-cdc(1). You can use
the subcommand to replace the delta instead of merely annotating
the existing commentary.

```
-rsid (/usr/ccs/bin/sccs)
-r rsid | -rsid (/usr/xpg4/bin/sccs)
```

Specify the SCCS delta ID (sid) to which the change
notation is to be added. The sid for a given delta is
number, in Decimal format, composed of two or
fields: the release and level fields and, for branch
deltas, the branch and sequence fields. For instance,
sid for the initial delta is 1.1.

```
-y[comment] Specify the comment with which to annotate the
commentary. If you omit -y, prompt for a comment. A
null comment results in an empty annotation.
```

```
check [-b] -u[username] (/usr/ccs/bin/sccs)
check [-b] -u[username] | -U (/usr/xpg4/bin/sccs)
```

Check for files currently being edited. Like info and tell, but return
an exit code instead of producing a listing of files. check returns a
non-zero exit if anything is being edited.

```
-b Ignore branches.
-u[username] (/usr/ccs/bin/sccs)
-u [username] | -U (/usr/xpg4/bin/sccs)
```

Check only files being edited by you. When you specify
username, check only files edited by that user.
For /usr/xpg4/bin/sccs, the -U option is equivalent
to -ucurrent-user.

Remove entries in the current directory that can be retrieved from
SCCS history. Do not remove files that are being edited.

```
-b Do not check branches to see if they are being edited.
clean -b is dangerous when branch versions are kept
the same directory.
```

Generate scripts to combine deltas. See sccs-comb(1).

Create (initialize) history files. create performs the following:

+   * Renames the original file to ,program.c in the current
directory.
* Creates the history file called s.program.c in the SCCS
directory.
* Performs an sccs get on program.c to retrieve a read-copy of
the initial version.
