
+   The interrupt or end-of-file characters write an appropriate message (EOT\n in the C locale) to the recipient's terminal and exit.

+   Characters from LC_TYPE classifications are sent to the recipient's terminal.

+   When only the stty iext local mode is enabled, additional special characters and multibyte or single-byte characters are processed as printable characters if their wide-character equivalents are printable.

+   Other nonprintable characters are written to the recipient's terminal as follows: control characters appear as a ^ followed by the appropriate ASCII character, and characters with the high-order bit set appear in notation (M-char). \003 is displayed as ^C, and \372 as M-z.

To write to a user who is logged in more than one place, you can use the terminal argument to indicate which terminal to write to; otherwise, the recipient's terminal is the first writable of the user found in /usr/adm/tmp, and the following informational message is written to the sender's standard output, indicating which terminal was chosen:

+   user is logged on more than one place.
You are connected to terminal.
Other locations: terminal.

You can deny or grant permission to be a recipient of a write message with the message command. However, a user's privilege may further constrain the domain of accessibility of other users' terminals. The write command fails when the user lacks the appropriate privileges to perform the requested action.

If you use a character at the beginning of a line, write calls the shell to execute the rest of the line as a command.

write runs setgid(setuid(2)) to the group tty to give write permission on other users' terminals.

The following protocol is suggested for using write: when you first write to another user, wait for him to write back before starting to send. Each person should end a message with a distinctive signal (such as, (o) for over) so that the other person knows when to reply. The signal (!) (for over and out) is suggested when conversation is terminated.

You can also redirect a-message from a file with the write command by using the following syntax:

```
write username < filename
```

+   terminal Terminal identification in the same format provided by the who command.

## xargs — Construct Argument Lists and Invoke Command

## Synopsis

```
/usr/bin/xargs [-t] [-p] [-e[ofstr]] [-E eofstr] [-I replstr
[-i[replstr]] [-L number] [-l[number]] [-n number [-x]
[command [argument...]]
```

## Description

xargs is a shell programming tool that enables you to use the output of one command to define the arguments for another. The xargs command constructs a line consisting of the specified command and argument operands followed by as many arguments in sequence from standard input as fit in the length and number constraints specified by the options. The xargs command invokes the constructed command line and waits for it. This sequence is repeated until an end-of-file line is detected on standard input or an invocation of a constructed command line returns an exit status of 255.

Separate arguments to the standard input by unquoted blank characters, unescaped blank characters, or newline characters. You can quote a string of zero or more non-double-quote characters by enclosing them in double quotes. You can quote a string of zero or more non-apostrophe ('') and non-newline characters by enclosing them in apostrophes. You can escape any unquoted character by preceding it with a backslash (\). The command is executed one or more times until the end-of-file is reached. If the command tries to read from its standard input, the results are unspecified.

The generated command-line length is the sum of the size in bytes of the command name and each argument treated as a string, including a null byte terminator for each
of these strings. the xargs command limits the command-line length so that when
command line is invoked, the combined argument and environment lists do not exceed
(ARG_MAX)-204

## Options

-   e[ofstr] Use eofstr as logical end-file. The -n and -s options are mutually exclusive.
-   E eofstr Read standard input until either-offile is encountered.
-   I replstr Replace {} with replstr.
-   i[replstr] If you omit -I, {} is assumed.
-   L number Execute command for each number lines. The -n and -l options are mutually exclusive.
-   l[number] If you omit -L, number is assumed.
-   n number Invoke command using many arguments as possible. The -s and -x options are exclusive.
-   p Terminate if a command line containing number arguments do not fit in the specified size.
-   s size Invoke command using many arguments as possible and yielding a-line. own-   t Enable trace each command to standard error before invocation.
-   x Terminate if a command line containing number arguments (see the -n option) or number lines (see the -L option) do not fit in the specified size.

## Operands

command The name of the command to be invoked, found by search path with the PATH environment variable; environ(5). If you omit command, the default is the echo(1) command.

argument An initial option or operand for the invocation of command.

## Usage

The 255 exit status enables a command to use xargs xargs to terminate if it knows that no further invocations using the current data stream will succeed. Thus, commandshould explicitly use with an appropriate value to avoid returning 255.

Input is parsed as lines; blank characters separate arguments. If xargs is used to bundle the output of commands like find -print or into commands to be executed, unexpected results are likely if files contain any blank characters or newline characters. You can fix this by using find to call a script that converts each file into a quoted string that is piped to xargs.

> Note — The quoting rules used by xargs are not the same as those in the shell. They were not consistent here because existing applications depend on the current rules and the shell syntax is not fully compatible.
