# ld

# 627

# Description

The ld command is the link-editor for object files. It is often automatically invoked by compiler commands as cc.

The ld command combines relocatable object files, performs relocation, and resolves external symbols. ld operates in two modes, static or dynamic, as governed by the -d option. Specify -dn for static mode and -dy for dynamic mode. In all cases, the output of ld is left in a_out. by default.

> Note — Default options by ld are maintained for historic reasons. In today's programming environment where dynamic objects dominate, alternative defaults would often make more sense. However, historic defaults must be maintained to ensure compatibility with existing program developments. Historic defaults are called out whenever possible. For a description of the current recommended options, see the "Link-Editor Quick Reference" in Linker and Libraries Guide.

If the file being created exists, it is truncated after all input files have been processed and is overwritten by the new file contents. ld does not create a temporary file as part of the link-edit because multiple instances of large files frequently exhaust system resources. The drawback of overwriting an existing file occurs if the file is in use by a running process. In this case, the process may be prematurely terminated as the output image is created. You can avoid this situation by removing the output file before performing the link-edit. This removal is detrimental to the running process, as it frees up the system namespace, not the actual disk space, for the new output file creation. The disk space of the file is free when the last process referencing the file terminates.

In static mode, relocatable object files specified as arguments are combined to produce an executable object file. If you specify the -r, relocatable object files are combined to produce one relocatable object file.

In dynamic mode (the default), relocatable object files you specify as arguments are combined to produce an executable object file that is linked at execution with shared object files you specify as arguments. If you specify the -G, relocatable object files are combined to produce a shared object. In all cases, the output of ld is left in a_out by default.

If any argument is a library, ld searches exactly once at the point it encounters the library list. The library can be either a relocatable archive (see HERE) or a shared object.

For an archive, ld loads only those routines that find an unresolved external reference. ld searches the archive symbol table sequentially with many passes as needed to resolve external references that can be satisfied by library members. Thus, the order of members in the function is unimportant unless multiple libraries exist that define the same external symbol. Archive libraries may require multiple command-line definitions or use the -z rescan option, which is new in the Solaris 9 release.

A shared object consists of an individual, whole unit that has been generated by a previous link-edit of one or more files. The link-editor processes a shared object, the entire contents of the shared object become a logical part of the resulting output file. The shared object is not physically copied during the link-edit because its actual inclusion is deferred until process execution.
