$ (MAKE) ...

You can use make -n to test an entire hierarchy of makefiles. For compatibility with the 4.2 BSD make, the MFLAG macro is set from the MAKEFLAGS variable by prepending a -; MFLAG is not automatically updated.

The SHELL, when set to a single-word value as /usr/bin/sh, indicates the name of an alternate shell to use. The default is /bin/sh. Note that make executes commands that contain no shell characters. Built-in commands, such as dirs in the C, are not recognized unless the command line includes a metacharacter (for instance, a semicolon). This macro is neither imported from, nor exported to the environment, regardless of -e. To be sure it is properly set, you must define this macro within every Makefile that requires it.

The following macros are provided for use with cross-compilation.

+   HOST_ARCH The machine architecture of the host system. By default, the output of the arch(1) command prepended with -. In normal circumstances, you should never alter this value.

+   HOST_MACH The machine architecture of the host system. By default, the output of the mach(1), prepended with -. In normal circumstances, you should never alter this value.

+   TARGET_ARCH The machine architecture of the target system. By default, the output of mach, prepended with -.

# Dynamic Macros

Several dynamically maintained macros are useful as abbreviations within rules. They are shown here as references. If you define them, make simple overrides the definition.

+   $* The basename of the current target, derived as if selected for use with an implicit rule.

+   $< The name of a dependency file, derived as if selected with an implicit rule.

+   $@ The name of the current target. This macro is the only one whose value is strictly determined when used in a dependency list (in which case, it takes the form $$).

+   $? The list of dependencies that are newer than the target. Command dependency checking is automatically suppressed for lines that contain this macro just as if you had prefixed the command with a ?. You can force this check with the !command-prefix.

+   $$ The name of the library member being processed. (See "Library Maintenance" on page 807).

To refer to the $$ dynamic macro within a dependency list, precede the reference with an additional $ character (as in, $$). Because make assigns $ and $$ as it would be unreliable (according to the suffixes list and the directory contents), they may be unreliable when used within implicit targets.
