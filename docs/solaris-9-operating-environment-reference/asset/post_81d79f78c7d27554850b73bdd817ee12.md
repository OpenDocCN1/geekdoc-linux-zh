
# alias, unalias

# Examples

## C Shell

The following example creates an alias for the alias command and uses the alias shortcut to create an alias for the history command and to create a more alias for the more command.

```
castle% alias a alias
castle% a h history
castle% a moer more
```

The following example lists aliases that are set in the .cshrc file.

```
castle% alias
G3 172.16.8.21
a alias
c clear
history
mac 172.16.8.20
caste%
```

## Korn Shell

The following alias changes ls to give a more annotated output in columnar format.
`alias ls="ls -CF"`

The following alias creates a simple redo to repeat previous entries in the command history file.
`alias r='fc -s'`

The following alias uses 1-kilobyte units for du.
`alias du="du -k"`

Alternatively, you can create the alias in the following form, using a backslash to escape the space character and omitting the double quotes around the command.
`alias du\=du -k`

The following alias sets up nohup so that it can deal with an argument that is itself an alias name.
`alias nohup="nohup `

The following example lists the default aliases that are set for the Korn Shell.

```
$ alias
autoload='typeset -fu'
command='command '
functions='typeset -f'
history='fc -1'
integer='typeset -i'
local=typeset
nohup='nohup '
r='fc -e -'
```

# allocate — Device Allocation

# Synopsis

```
/usr/sbin/allocate [-s][-U name] device
/usr/sbin/allocate [-s][-U name] -g dev-type
/usr/sbin/allocate [-s][-U name] -F device
```

# Description

Use the allocate command, new in the Solaris 9 Operating Environment, to manage the ownership of devices with its allocation mechanism. The allocate command ensures that each device is used by only one qualified user at a time.

> Note — The functionality described in this manual page is available only if the Basic Security Module (BSM) has been enabled. See bsm(1) for more information.

The Solaris 9 Operating Environment provides a device-allocation method—with the allocate(1), dminfo(1), and devices(1)—commands— fulfills the Trusted Computer System Evaluation Criteria (TCSEC) object-requirement for computing systems at C2 level and above. The device allocation mechanism prevents simultaneous access to a device, prevents one user from reading by another user, and prevents one user from accessing any information from the device or driver internal storage after another user is finished with the device.

For example, several users share a single tape drive that may not be located at an individual user's location. If the tape drive is located remotely, some time can elapse between the time the user loads a tape in the drive and the user invokes a command to access the tape drive. Because other users could access the drive while the tape is unattended, another user could access or overwrite the data on the tape. With the device allocation mechanism, you can ensure that one user at a time has access to a specific tape device.

To preserve the integrity of the device, the allocate operation is executed on all the device special files associated with that device.

Only authorized users can allocate a device. The required authorizations are specified in device_allocate(4).

# Options

- -g dev-type

Allocate a nonallocated device with a device type matching dev-type. Use the dev-type argument to specify the type of device. You can determine the type of device from the output of the list_devices -1 command. See "Examples" for an example.

- -s

Suppress diagnostic output.

- -F device

Reallocate a device to another user. This option is often used with -U to reallocate a specific device to a specific user. Only a user with the solaris.devices.revoke authorization is permitted to use this option.

Use the device argument to specify the device to be manipulated, example st0 for a streaming tape device. You can display a list of available devices with the -1 option to the list_devices(1) command, also new in the Solaris 9 Operating Environment. See "Examples" on page 685 for an example of the output from list_devices -1. The default allocation operation allocates the device special files associated with the UID of the current process.

When you specify the -F option, the device-cleaning program is executed when performed. In /etc/security/lib. The name of this program is found in the device_allocate(4) entry for the device in the dev-exec-fd.

- -U uname

Use the user ID uname instead of the user ID of the current process when performing.

# Examples

The following example allocates a tape drive.

```
mokoke% allocate st0
mokoke%
```

The following example allocates audio files by type.

```
mokoke% allocate -g audio
mokoke%
```

# amt — Run Abstract Machine Test

# Synopsis

```
/usr/bin/amt [-s]
```

# Description

The amt command, new in the Solaris 9 Operating Environment, for a Common Criteria certified system. Use the command to verify that the low-level functions necessary to enforce the object reuse requirements of the Controlled Access Profile are working correctly. /usr/bin/amt is a shell script that executes tests to your system. For a 32-bit system, the tests run as 32-bit application. For a 64-bit system, the tests run twice; once as a 32-bit application and once as a 64-bit application.

# amt

amt lists test results with a PASS or FAIL for each test it performs unless you suppress output with the s option.

# Options

-s Suppress output.
