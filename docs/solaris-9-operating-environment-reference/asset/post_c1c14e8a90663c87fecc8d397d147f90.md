
The system CPU time, equivalent to the sum of the tms_stime and tms_cstime returned by the times() function for the process in which command is executed.

When time is used as part of a pipeline, the times reported are unspecified when it is the sole command within a grouping command in that pipeline. For example, the following commands are unspecified.

```
time a | b | c
a | b | time c
```

The following commands report on commands a and c.

```
{ time a | b | c
a | b | (time c)
``````

> Note — When you run the time command on a multiprocessor system, the total of the values printed for user and sys can exceed real because, on a multiprocessor system, it is possible to divide the task among the various processors.

When the command being timed is interrupted, the timing values displayed may not always be accurate.

## Options

- -p Write the timing output to standard error in the following format.
  `real %f\user %f\nsys %f\n real-seconds, user-seconds, system-seconds`

## Operands

- command The name of the command to be invoked.
- argument Any string to be supplied as an argument when invoking command.

## Usage

The command returns exit status 127 if an error occurs so that applications can distinguish "failure to find a command" from "invoked command exited with an error indication." The value 127 was chosen because it is not commonly used for other meanings; most commands use small values for normal conditions, and the value above 128 can be confused with termination because of receipt of a signal. The value 126 was chosen in a similar manner to indicate that the command could be found but not invoked.

## Examples

If you want to apply time to pipelines or lists of commands, you can do so by putting pipelines and command lists in a single file. You can invoke this file as a command, and the time applies to everything in the file.
Alternatively, you can use the following command to apply time to a complex command.

```
castle% time sh -c 'complex-command-line'
```

## Environment Variables

See environ(5) for descriptions of the following environment variables that affect the execution of time: LC_TYPE, LC_MESSAGES, LC_NUMERIC, NLSPATH, and PATH.

## Exit Status

If command is invoked, the exit status of time is the exit status of command; otherwise, the time command exits with one of the following values.

- 1-125 An error occurred in the time command.
- 126 command was found but could not be invoked.
- 127 command could not be found.

## Bugs

Elapsed time is accurate to the second, whereas the CPU times are measured to the 100th second. Thus, the sum of the CPU times can be up to a second larger than the elapsed time.

## Synopsis


## Description

The timex command used to report the time usage of a process. The system CPU time, equivalent to the sum of the tms_stime and tms_cstime returned by the times() function for the process in which command is executed.

When time is used as part of a pipeline, the times reported are unspecified when it is the sole command within a grouping command in that pipeline. For example, the following commands are unspecified.

Note — When you run the time command on a multiprocessor system, the total of the values printed for user and sys can exceed real because, on a multiprocessor system, it is possible to divide the task among the various processors.

When the command being timed is interrupted, the timing values displayed may not always be accurate.

## Options

- -p Write the timing output to standard error in the following format.
  `real %f\user %f\nsys %f\n real-seconds, user-seconds, system-seconds`

## Usage

The timex command, provided as of package, provides better diagnostic information than time, especially for scripts. When establishing the connection, timex sends a connection message to the remote system. You can find the default value for this message in the remote file.

When you specify device, timex tries to open the device with exclusive-open. ioctl(2) thus, only one user at a time can access a device. This restriction prevents multiple processes from sampling the terminal line. In addition, timex honors the locking protocol using uucp.

When timex starts up, it reads commands from the .tirc file in your home directory.

## Options

- -v Display commands from the .tirc file as they are executed.

## Usage

Typed characters are normally transmitted directly to the remote system (which also does the echoing). Any time that timex prompts for an argument (for example, during setup of a file transfer) you can edit the typed line with the standard erase and kill characters. A null line in response to a prompt or an interrupt aborts the dialogue and returns to the remote system.

## Commands

A ~ as the first character of a line acts as an escape signal that directs tip to perform some special action. tip recognizes the following escape sequences:

- ~D Drop the connection, and exit (you may still be logged in on the remote system).
- ~c [name] Change directory to name. (No argument implies change to your home directory).
- ~! Escape to an interactive shell on the local system. (Exiting the shell returns to tip.)
- ~> Copy file from remote to local.
- ~< Copy file from remote to local.
