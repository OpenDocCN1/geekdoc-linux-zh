# Output

When you do not specify the -l option, the standard output is not used. When you specify the -l option, the symbolic name of each signal is written in the following format:

```
%s&c, separator
```

where the signal is in upper case, without the SIG prefix, and the separator is either a newline or a space. For the last signal written, separator is a newline.

When you both specify the -l option and exit-status operate for /usr/bin/kill, the symbolic name of the corresponding signal is written in the following format:

```
%sn, signal
```

# Examples

The following example uses the -l option to list the available signals for /usr/bin/kill.

```
castle$ /usr/bin/kill -1
HEX H INT QILL TRAP ABRT FPE KILL SIG SYS SEGV PIPE ALRM TERM
USR1 USR2 CL PWR WINCH URG POLL STOP TST TPP TTIN TTU VLARM
XCFU XFS WAITING WINCH FREE THAW CANCEL LOST RMIN RTMIN+1 RTMIN+2
RTMIN-3 RTMAC-3 RTMAX-2 RTMAX-1
cast$
```

If the sending process has permission to send the signal, any of the following commands sends the SIGKILL to an existing process whose ID is 100 and to all existing processes whose group ID is 165.

```
# kill -9 100 -165
# kill -s kill 100 -165
# kill -s KILL 100 -165
```

To avoid an ambiguity of an initial negative number argument specifying either a signal number or a process group, the signal number is always specified. Therefore, to send the default signal to a process group (for example, 123), an application should use a command similar to one of the following:

```
# kill -TERM -123
# kill -- -123
```

The following example uses the ps command to find the process ID for the game spider and then uses the kill command to kill it by process.

```
castle$ -ef grep spider
winsor 544 419 0 15:44:35 pts/3 0:00 spider
winsor 542 419 1 15:45:35 pts/3 0:00 spider.exe
castle kill 542
```

```
[1] Exit 1
spider
castle$
```

The following example uses the jobs command to find the job number for the game spider and then uses the kill command to kill it by ID.

```
castle$ jobs
[2] + Running
castle kill %2
```

spider
