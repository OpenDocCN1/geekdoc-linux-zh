If you use it explicitly, getopt recognizes it; otherwise, getopt generates it; in either case, getopt puts it at the end of the options. The positional parameters ($...) of the shell are reset so that each option is preceded by a and is in its own positional parameter; each option argument is also parsed into its own positional parameter.

Reset optind to 1 when rescanning the options.
getopt does not support the fact of Rule 8 of the command syntax standard (see intro(1)) that permits groups of option-arguments following an option to be separated by white space and quoted. For example:

```
cmd - a - b - o "xxx z yy" filename
```

is not handled correctly. To correct this deficiency, use the getopts command in place of getopt.

# Examples

The following code fragment shows how you might process the arguments for a command that can take the options a b, as well as the option o, which requires an argument.

```
set -- 'getopt abo:*
if [ $? != 0 ];
then
  echo USAGE
  exit 2
fi
for i in $@
do
  case $i in
    -a |-b) FLAG=$i; shift;
    -o) OARG=$2; shift 2;
    --) shift; break;
  esac
done
```

This code accepts any of the following equivalent:

```
cmd - aoarg filename filename2
cmd - a - oarg filename filename2
cmd - oarg - a filename filename2
cmd - a - oarg - filename filename2
```

> Note — If an option takes an option-argument is followed by a value that is the same as one of the options listed in optstring,

```
cmd - o - a filename
```

getopt always treats - a as an option-argument to o; it never recognizes - a as an option. For this case, the loop in the example shifts past the filename argument.
