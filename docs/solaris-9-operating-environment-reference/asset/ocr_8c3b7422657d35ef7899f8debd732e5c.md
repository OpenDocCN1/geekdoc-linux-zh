# nismatch, nisgrep — Search NIS+ Tables

# Synopsis

```
/usr/bin/nismatch [-AchNoPV] [-s sep] key tablename
/usr/bin/nismatch [-AchNoPV] [-s sep] colname=key... tablename
/usr/bin/nismatch [-AchNoPV] [-s sep] indexedname
/usr/bin/nisgrep [-AchNoPV] [-s sep] keypat tablename
/usr/bin/nisgrep [-AchNoPV] [-s sep] colname=keypat... tablename
```

# Description

Use the nismatch and nisgrep commands to search NIS+ tables. The nisgrep command differs from the nismatch command in its ability to accept regular expressions keypat for the search criteria instead of simple text matches.
Because it uses a callback function, it is not constrained to searching only those columns that are specifically searchable at the time of table creation. It is slower but more flexible than nismatch.
With nismatch, the server does the searching; with nisgrep, the server returns all the readable entries and the client does the matching.
With both commands, the parameter tablename is the NIS+ name of the table to be searched. If you specify only one key or pattern without the column name, then the first column is searched. You can search specific named columns using the colname=keysyntax. When you search multiple columns, only entries that match in all columns are returned. This is the equivalent of a logical join operation.

+   - nismatch accepts an additional form of search criteria, indexedname, which is an NIS+ indexed name of the form:
- [colname=value,...], tablename

# Options

+   -A Return all data within the table and all of the data in tables in the initial table's concatenation path.
