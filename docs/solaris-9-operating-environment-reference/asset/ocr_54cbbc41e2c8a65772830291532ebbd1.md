Retrieve a version of the file for editing. Extract a version of the file
that is writable by you; create a p.file in the SCCS subdirectory as a
lock on the file history so that no one else can check that version or
Retrieve ID keywords in unexpanded form. edit accepts the same
options as get. See sccs-get(1) for a list of ID keywords and their
definitions.

Similar to create, but omit the final sccs get. You can use this
subcommand if you are performing an sccs edit immediately after
initializing the history file.

```
-rsid (/usr/ccs/bin/sccs)
-r sid | (/usr/xpg4/bin/sccs)
```

Revise a (leaf) delta. Remove the indicated delta from the SCCS
history, leaving a writable copy of the current version in the directory.
This subcommand is useful for incorporating tribal updates for which
y need no audit record or for revising the delta commentary. You
must follow with a -r option to specify the sid of the delta to
remove. The indicated delta must be the most recent (leaf) delta in the
branch. Use with caution because it does not leave an audit trail of
differences (although the previous copy remains within the
history file).

```

```

Retrieve a version from the SCCS history. By default, this copy is a
read-only copy of the most recent version; ID keywords are in
expanded form. See sccs-get(1) for a list of ID keywords and their
definitions.

+   -e
-G newname
Use newname as the name of the retrieved version. New
in the Solaris 9 release.
-k
Retrieve a version for editing. Same as sccs edit.
-m
Precede each line with the sid of the delta in which it
was added.
-p
Produce the retrieved version to the standard output.
Direct reports that would normally go to the standard
output (delta IDs and statistics) to the standard error.
