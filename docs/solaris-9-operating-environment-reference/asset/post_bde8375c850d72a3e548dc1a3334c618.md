## Definitions in lex

Definitions in lex appear before the first % delimiter. Any line in this section not contained within % { and } lines and not beginning with a blank character is assumed to define a lex substitution string. The format of these lines is:

```
name substitute
```

If name does not meet the requirements for identifiers in the ISO C standard, the result is undefined. The string replaces the string { name } when it is used in a rule. The name string is recognized in this context only when the braces are provided and when it does not appear in a bracket expression or within double quotes.

In the Definitions section, any line beginning with a % (percent character) followed by a word beginning with s or $ defines a set of start conditions. Any line beginning with either x or X defines a set of exclusive start conditions. When the generated scanner is in a %s state, patterns with no state are also active; in a $ state, patterns are not active. The rest of the line after the % word is considered to be one or more blank-character-separated names of start conditions. Start condition names are constructed in the same way as definition names. Start conditions can be used to restrict the matching of regular expressions to one or more states.

Implementations accept either of the following mutually exclusive declarations in the Definitions section:

- *array Declare the type of yytext to be a null-terminated character array.
- *pointer Declare the type of yytext to be a pointer to a null-terminated character string.

> Note — When using the %pointer option, you cannot use the yyles function to alter yytext.

*array is the default. If you specify %array (or do not specify either %array or %pointer), the correct way to make an external reference to yytext is with a declaration of the following form:

```
extern char *yytext;
```

If you specify %pointer, the correct way to make an external reference to yytext is with a declaration of the following form.

```
extern char *yytext;
```

Programs generated by lex need the -e or -w option to handle input that contains EUC characters from supplementary codets. If you specify neither of these options, yytext is of the type char[], and the generated program can handle only ASCII characters.

When you use the -option-bytes, bytes yytext is of the type unsigned char[] and yyleng gives the total number of bytes matched. With this option, the macros input(), input(c), and output(c) should do a byte-based I/O in the same way as with regular ASCII. Two more variables are available with the -option--yytext and yyleng behave the same as would yytext and -w.

When you use the -w option, yytext is of the type char_t[] and yyleng gives the total number of characters matched in the string. If you supply your own input(), input(c), or output(c) macros with this, they must return or accept EUC characters in the form of wide character (wchar_t). This enables a different interface between your program and the lex externals to expedite some programs.

## Rules in lex

The Rules source files are a table in which the left column contains regular expressions and the right column contains actions (C-program fragments) to be executed when the expressions are recognized.

```
ERE action
ERE action
```

The extended regular expression (ERE) portion of a row is separated from action by one or more blank characters. A regular expression containing blank characters is recognized under one of the following conditions:

- The entire expression appears within double quotes.
- The blank characters appear within double quotes.
- Each character is preceded by a backslash character.

## Regular Expressions in lex

The lex command supports the set of Extended Regular Expressions (EREs) described in regex(5) with the following additions and exceptions to the syntax.

Any string enclosed in double quotes represents the characters within the double quotes as themselves, except that backslash escapes (appear in the following table) are recognized. Any backslash-escape sequence is terminated by the closing quote. For example, "\11" represents a single string; the octal value 1 followed by a character 1.

Match the regular expression r only when the program is in one of the start conditions indicated by state, state1, and so forth. (As an exception to the typographical conventions of the rest of this document, in this case <state> does not represent a metavariable, the literal angle-bracket characters surrounding a symbol.)
