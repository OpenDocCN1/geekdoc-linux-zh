# jobs, fg, bg, stop, notify

%j Refer to jobs in: kill -9 %j can be a job number or a string that
uniquely specifies the command line that started; for example, fg
%vi might bring a stopped vi job to the foreground.

?string Specify the command-line job that uniquely contains string.

A job running in the background stops when it tries to read from the terminal.
Background jobs can normally produce output, but you can suppress this feature with the
stry tostop command.

The following list describes the C shell built-in job control commands.

+   - fg Bring the current or specified job-id into the foreground.
- bg Run the current or specified jobs in the background.
- stop Stop the execution of a background job(s) by using its job-id, or
any process using its pid ps(1).
- notify Notify you asynchronously when the status of the current job or
schanged changes.

# Korn Shell

The Korn built-in jobs command displays the status of the jobs that were started
in the current shell environment. When jobs reports the termination status of a job, it
removes its process ID from the list of those known in the current shell execution\environment.

The following options modify or enhance the output of jobs.

+   - l (The letter ell.) Provide more information about each job list. This
information includes the job number, current job, process group ID,
state, and the command that formed the job.
- n Display only jobs that have stopped or exited since you were last
otified.
- p Display only the process IDs for the process group leaders of
selected jobs.

By default, jobs displays the status of all the stopped jobs, running background jobs,
and any job whose status has changed and has not been reported by the shell.
If the monitor of the set command is turned on, an interactive shell associates
a job with each pipeline. It keeps a table of current jobs, printed by the jobs command,
as assigns them a line that looks like [1] 567, indicating that the job that was started
asynchronously by job number 1 and has one (top-level) process, which process ID is
567.

If you are running a job and want to do something else, you can use the ^Z (Control-Z)
key combination to send a stop signal to the current job. The shell normally indicates
t the job has been stopped and displays another prompt. You can manipulate
t state of this job, putting it in the background with the bg command, or you can run
sother commands and then eventually bring the job back into the foreground with the
fg command. A ^Z takes effect immediately and is an interrupt in pending
output and unused input are discarded.

You can refer to jobs in the shell by their process ID or by any of the following.

+   - number The job with the given number.
