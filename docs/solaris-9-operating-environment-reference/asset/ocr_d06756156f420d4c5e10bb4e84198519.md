# perl 1039

+   - Regular expression enhancements.

You can now specify nongready quantifiers. You can now do grouping without creating a back reference. You can now write expressions with embedded whitespaces and comments for readability. A consistent extensibility mechanism has been added that is upwardly compatible with all old regular expressions.

+   - Inumerable unboundled modules.

The Comprehensive Perl Archive Network described in the perldolib manual page contains hundreds of plug-and-play modules full of reusable code. See http://www.perl.com/CPAN for a site near you.

+   - Compilability.

While not yet full in production mode, a working Perl-to-C compiler does exist. It can generate portable byte-code, simple C or optimized C.

# Diagnostics

The -w option produces some diagnostics.

See the -w manual page for explanations of all Perl diagnostics. The use diagnostics automatically turns Perl's normally terse warnings and errors into these longer forms.

Compilation errors tell you the line number of the error, with an indication of the token or code type that was to be examined. (In the case of a script passed to Perl by -e options, each -e is counted as one line.)

Setuid scripts have additional constraints that can produce error messages such as Insecure dependency. See the persec manual pages.

Did we mention that you should consider using the -w option?

# Bugs

The -w option is not mandatory.

Perl is at the mercy of your machine's definitions of various operations as type casting, atof(), and floating-point output with sprintf().

If your standard input/output requires a seek or EOF before reads and writes on a particular stream, so does Perl. (This doesn't use sysread() and write().).

While some of the built-in types have arbitrary array size limits (apart from memory), a few binary limits still remain: a variable name cannot be longer than 251 characters. Line numbers displayed by diagnostics are internally stored as short integers, so they are limited to a maximum of 65,535 (higher numbers are usually affected by wrap around).

You may mail your bug reports (be sure to include full configuration information as output by myconfig program in the Perl source tree or by perl -V) <perl@perl.com. If you've succeeded in compiling Perl, you can use the perbug script in the utils/ subdirectory to help in a bug report.
