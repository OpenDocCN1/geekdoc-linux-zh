## echo — Write Arguments to Standard Output

## Synopsis

/usr/bin/echo [string...]
/usr/ucb/echo [-n] [string...]

## Description

The echo command writes its arguments, separated by blanks and terminated by a newline, to the standard output. If you provide no arguments, only the newline character is written.

echo is useful for producing diagnostics in command files, sending known data into a pipe, and displaying the contents of environment variables.

The C shell, the Korn shell, and the Bourne shell all have built-in commands, which, default, are invoked if you call echo without a full path name. See shell-builtins(1).

The sh echo, ksh echo, and /usr/bin/echo commands understand the backslashed escape characters, except that the sh echo command does not understand \a as the alert character. In addition, the ksh echo command does not have an -n option. The sh echo and /usr/bin/echo have an -n option only if the SYS3 environment variable is set. If it is, none of the backslashed characters mentioned above are available. The csh echo and /usr/ucb/echo commands, on the other hand, have an -n option but do not understand the backslashed escape characters.

## echo

## Options

/usr/ucb/echo
-n Do not add the newline to the output.

> Note — The n-option is provided for transition for BSD applications and may not be supported in future releases.

## Operands

string A string to be written to standard output. If any operand is -n, it is treated as a string, not an option.

/usr/bin/echo
The following character sequences are recognized within any of the arguments:

- \a Alert character.
- \b Backspace.
- \c Print line without newline.
- \f Formfeed.
- \n Newline.
- \r Return.
- \t Tab.
- \v Vertical tab.
- \ll Backslash.
- \0n Where n is the 8-character character whose ASCII is the 1-, 2-, or 3-digit octal number representing that character.

When an 8-character character is represented by the escape convention \0n, the n must always be preceded by the digit zero (0).
For example, the following command prints the phrase WARNING: and sounds the bell on your terminal.

```
$ echo 'WARNING:\007 '
WARNING:
$
```

The single (or double) quotes (or two backslashes) are required to protect the backslash that precedes 07.
Following the \0, you can use up to three digits in constructing the output character. If following the \0n, you want to echo additional digits that are not part of the octal representation, you must use the full 3-digit n. For example, if you want to echo ESC 7, you must use the three digits 033 instead of just the two digits 33 after the \0.
This example shows that using only two digits after it is incorrect.

```
$ echo "0337" | od -xc
000000 df0a
337 \n
000002 $
```

## echo

The following example shows that the 3-digit syntax produces the correct results.
$ echo "\00337" | od -xc
000000 0000 0337 \n
000002 $

For octal sequences of each character, see ascii(5).

## Usage

Portable applications should not use -n (as the first argument) or escape sequences. The printf(1) command can be used portably to emulate any of the traditional behaviors of echo command as follows:

Solaris /usr/bin/echo is equivalent to:
printf "%b\n" "$*"

/usr/ucb/echo is equivalent to:
if [ "$1" = "-n" ];
then
  shift
  printf "%s" "$*"
else
  printf "%s\n" "$*"
fi

New applications are encouraged to use printf instead of echo.

## Examples

You can use the echo command to display the value for a variable by preceding name with a dollar sign ($). The following example displays the values for PATH environment variable.

```
$ echo $PATH
/usr/bin:/bin:/sbin:/etc:/opt/bin:/local/games```

The following example shows how you can use the echo command in combination with tr and wc commands to determine how many subdirectories are between / and your current directory. The example has the following parts:

- Echo the full path of your working directory.
- Pipe the output through tr to translate the path's embedded slash into space characters.
- Pipe that output through wc -w for count the names in your path.

```
$ echo / | tr '/' ' ' | wc -w
```

See tr(1) and wc(1) for their functionality.

## ed, red — Text Editor

## Synopsis

```
/usr/bin/ed [-s] [-p string] [-x] [file]
/usr/bin/ed [-s] [-p string] [-x] [file]
/usr/bin/ed [-s] [-p string] [-x] [file]
```

## Description

The ed command is the standard text editor. If you specify a file, ed reads the file into ed's buffer so that it can be edited.

> Note — Although we have superseded ed as a line editor, commands such as diff continue to use ed.

The ed command operates on a copy of the file it is editing; the original file remains unchanged until you use a write command. The copy of the text edited resides in a temporary file called the buffer. There is only one buffer.

Unlike vi and ex commands, ed does not display any of the text in its buffer unless you ask for it. As a result, it is difficult to keep track of the contents of the buffer.

The red is restricted to standard ed. It allows editing of files in the current directory only. It prohibits executing shell commands using the ! command. Attempts to bypass these restrictions result in an error message (restricted shell).

Both ed and red support the spec(4) formatting capability. The default mode is either stty tabs or stty, where Tabs stop at eight columns (see stty(1)). If however, the first line of file contains a format specification, that specification overrides the default mode. The following example of the first line of a file stops at 5, 10, and 15, and a maximum length of 72.

```
<t:5,10,15>:
```

Commands to ed have a simple and regular structure: zero, one, or two addresses followed by a single-character command, possibly followed by parameters to that command. The addresses specify one or more addresses in the buffer. Every command requires default addresses, so you can often omit the addresses. In general, you can specify only one command per line.

ed has separate input modes. If you enter an invalid command, ed writes the string with ? (followed by an explanatory message if you have enabled help mode with the H) to output and continues in command mode with the current line number unchanged.

Certain commands allow the input of text. This is put in the appropriate place in the buffer. While ed is accepting text, it is said to be in input mode. In this mode, ed recognizes no commands; it merely collects all input. You leave input mode by typing a period (.) at the beginning of a line, followed immediately by a Return.

> Note — If the editor is coming from a command file (for example, ed file < ed-cmd-file), the editor exits at the first failure.
