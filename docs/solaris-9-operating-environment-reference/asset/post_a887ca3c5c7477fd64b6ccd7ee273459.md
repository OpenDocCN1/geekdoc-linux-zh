
# Nomadic Machines

When using filesync to keep files synchronized between nomadic machines and a server, store the packing files and baseline files on the nomadic machines, not the server. If you are logged into your notebook, the HOME environment variable does not normally point to a directory in your notebook, you can use the FILESYNC environment to specify an alternate location for the packing files and baseline files.

Each nomadic machine carries its own packing files and baseline rules. Incorrect file synchronization can result if a server carries a baseline file and multiple nomadic machines attempt to reconcile the server's baseline file. In this case, a nomadic machine could be using a baseline file that does not accurately describe the state of its files, which might result in incorrect reconciliations.

To safeguard the dangers associated with a single baseline file being shared by more than two machines, filesync adds a default rule to each new packing file. This default rule prevents the packing rules and baseline files from being copied.

# Options

- -f Force the checking of Access Control Lists (ACLs), and try to make them agree for all new and changed files. If it is not possible to set the ACL for a particular file, filesync stops synchronization for that file.
- -o Some systems do not support ACLs. It is not possible to synchronize ACLs between systems that support ACLs and those do not; trying to do so results in numerous error messages.
- -s Specify the directory on the destination system into which filename is to be copied. Use with the source-direction and filename operand.
- - Flag all differences. It may not be possible to resolve all conflicts involving modes and ownership (unless filesync is being run with root privileges). If you change the ownership or protections on a file, filesync ignores conflicts in ownership and protection. If you specify the -e (everything must agree) flag, filesync flags these as differences.
- - Specify how to resolve conflicting changes. If a file has been changed on both systems and you specify the -f option, retain the changes made on the favored system and discard the changes made on the unfavorable system.
- -f src to favor the source system. Specify -f dst to favor the destination system. Specify -f old to favor the older version of the file. Specify -f new to favor the newer version.
- You can combine the -f and -o options if both specify the same preference (src or dst). If -f and -o conflict, ignore the -f option.
- -h Halt on error. Normally, if filesync encounters a read or write error while copying files, it notes the error and continues reconciling other files. If you specify the -h option, filesync immediately halts when one of these errors occurs and does not process any files.
- -m Ensure that both copies of the file have the same modification time. Set the modification time for newly copied files to the time of reconciliation. Order file changes by increasing modification times so that propagated files have the same modification time. There is usually some time skew between two systems, and transferring modification times from one system to another occasionally produces strange results. filesync to update some (but not all) files in a directory conflicts, as a changed file may show up with a modification time from a previous version.
- -n Display the reconciliation information on standard output, and not make the changes. Specifying both the -n and -o options analyzes the prevailing system and reports the changes that have been made on system. Using -n and -o in combination is useful if your machine is disconnected (and you cannot access the server) but you want to know what changes have been made on the local machine.
- -o src | dst Force a one-way reconciliation, favoring either the source system (src) or destination system (dst), filesync aborts if it cannot access source or destination directory. Specify -o src to propagate changes from the source system to the destination system. Ignore changes made on the destination system. Specify -o dst to propagate changes only from the destination system to the source system. Ignore changes made on the source system. Specifying both the -n and -o options analyzes the prevailing system and reports the changes that have been made on system. Using -n and -o in combination is useful if your machine is disconnected (and you cannot access the server) but you want to know what changes have been made on the local machine.
- -q Suppress the filesync messages that describe each reconciliation action as it is performed. The standard filesync message describes each reconciliation action in the form of a shell command (for example, mv, cp, rm, chmod, chown, chgrp, setfacl, and forth).
- -r directory Limit the reconciliation to directory. Specify multiple directories with -r.
- -s source-dir Specify the directory on the source system from which the filename is located. Use with the -d option and the filename operand.
- -v Display additional information about each file comparison as it is made on the standard output.
- -Y bypass safety checks. Nomad machines occasionally move between domains, and many of the files on which filesync are expected to be accessed by NFS. It is possible that you could ask filesync to reconcile local changes against the wrong file system in a large number of inappropriate copies and deletions. To prevent such mishap, filesync performs a few safety checks before reconciliation. If large numbers of files are likely to be deleted or high-level directories have changed their inodes, filesync prompts for a confirmation before reconciliation. If you know that this is likely and do not want to prompt, use the -y (yes) option.

# Operands

- filename The name of the ordinary file, directory, symbolic link, or special file in the specified source directory (source-dir) to be synchronized. Specify multiple files by separating filename by spaces. Use the filename operand with the -s and -d options. If filename is an ordinary file, replicate that ordinary file (with the same filename) in the specified destination directory (dest-dir). If filename is a directory, replicate that directory and all of the files and subdirectories under it (recursively) in the specified destination directory (dest-dir). If filename is a symbolic link, replicate a copy of symbolic link in the specified destination directory (dest-dir). If filename is a special file, replicate a special file with the same major or minor device numbers in the specified destination directory. Only superusers can use filesync to create special files. Files created in the destination directory (dest-dir) have the same owner, group, and other permissions as the files in the source directory.

# filesync

If filename contains shell wild-card characters, filesync stores the wild-card characters in $HOME/packingrules and evaluates them each time you run the command. For example, the following command makes sure that the specified files, currently in $RHOME, are replicated in $HOME:
filesync -s $RHOME -d $HOME a.c b.c

The following example ensures that all the .c files in $RHOME are replicated in $HOME, even if those files are not created later:
filesync -s $RHOME -d $HOME '*.c'

If any of the destination files already exist, filesync ensures that they are identical and issues warnings if they are not. Once files have been copied, the distinction between the source and destination is a relatively arbitrary one (except for its use in the -o and -f switches).

# Environment Variables

FILESYNC: Specify the default location of the filesync packing rules and baseline files. The default value for this variable is $HOME. The .packingrules and filesync-base are appended to the names of the packing rules and baseline files.

LC_MESSAGES: Determine how diagnostic and informative messages are presented. In the C locale, the messages are presented in the default form found in the program itself (in most cases, U.S. English).

# Exit Status

Normally, if all files are already up-to-date or if all files are successfully reconciled, filesync exits with a status of 0. However, if you specify the -n option or any errors occurred, the exit status is the logical OR of the following:

| Status | Description |
| :--- | :--- |
| 0 | No conflicts, all files up to date. |
| 1 | Some conflicts. |
| 2 | Some conflicts requiring manual resolution. |
| 4 | Some specified files did not exist. |
| 8 | Insufficient permission for some files. |
| 16 | Errors accessing packing rules or baseline files. |
| 32 | Invalid arguments. |
| 64 | Unable to access either or both of the specified source or destination directories. |
| 128 | Miscellaneous other failures. |
