# tip

tip currently supports the Ventel MD-212+ and DC Hayes-compatible modems. When tip initializes a Hayes-compatible modem for dialing, it sets the modem to auto-answer. Normally, after the conversation is complete, tip drops DTR, which hangs up the modem.

Most modems can be configured so when DTR drops, they reinitialize themselves to a preprogrammed state. You can use this feature to reset the modem and auto-answer.

Additionally, it is possible to start the phone number with a Hayes S command that you can configure the modem before dialing. For example, to disable auto-answer, set up all phone numbers in /etc/remote by using something like pn=S0DT5512122. The S=0 disables auto-answer.

# Remote Host Description

Descriptions of remote hosts are normally loaded in the systemfile /etc/remote. However, you can maintain personal description files (and phone numbers) by defining and exporting the REMOTE variable. The remote file must be readable by tip, but you can maintain a secondary file describing phone numbers readable only by you. Your secondary phone number is /etc/phones unless the shell variable PHONES is defined and exported. The phone number file contains lines of the following form:

system-name phone-number

Each phone number for a system is tried until a connection is established or an end-of-file is reached. Phone numbers are constructed from 0123456789=-*, where the = and indicate to wait for a second dial tone (ACU dependent).

# tip Internal Variables

tip maintains a set of variables that are used in normal operation. Some of these variables are read-only (root is allowed to change anything of interest). You can display and set variables with the -s escape. The syntax for variables is matched after vi(1) and mail(1). Supplying all as an argument to the -s escape displays all variables that you can read. Alternatively, you can request of a particular variable by attaching a ? to the end. For example, -s displays the current escape state.

Variables are numeric(num), string(str), character(char), or Boolean(bool) values. You set Boolean variables by specifying their name. You can reset them by prepending a ! to the name. You set other variables by appending an = and the value. The entire assignment must not have any blanks in the home directory. You can use a single set command to interrogate it as well as set a number of variables.

You can initialize variables at runtime by putting commands (without the -s prefix) in a home directory .tiprc file with a #. The -v option displays the sets as they are made. You can precede comments in the .tiprc file with a #.

Finally, you must either specify the variable names or use an abbreviation. The following list details variables known to tip:

+   - beautify (bool) Discard unprintable characters when a session is being scripted; if the nb capability is present, initially set beautify to off; otherwise, initially set beautify to on.
