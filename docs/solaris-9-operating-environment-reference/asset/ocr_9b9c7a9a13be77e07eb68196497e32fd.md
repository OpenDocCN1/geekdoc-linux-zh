# ld.so.1

# 665

You can specify each environment variable with a _32 or _64 suffix that makes the environment variable specific to 32-bit or 64-bit processes and overrides any unsixed version of the environment variable that may be in. New in the Solaris 8 release.

Note — Environment-variable names beginning with the characters LD_ are reserved for possible future enhancements to ld and ld.so(1).

# Security

For the prevention of malicious dependency substitution or symbol insertion, some restrictions may apply to the evaluation of the dependencies of secure processes.

The runtime linker categorizes a process as secure if the user is not a superuser and the real user and effective user identifiers are not the real group or effective group identifiers are not equal. See getuid(2), getegid(2), getgid(2), and getid(2).

The default trusted directory to the runtime linker is /usr/lib/secure/64 for 64-bit objects. You can use the crel(1) command to specify additional trusted directories to secure applications. Administrators who use this technique should ensure that the target directories are sufficiently protected from malicious intrusion. New in the Solaris 8 release

If an LD_LIBRARY_PATH environment variable is used for a secure process, only trusted directories specified by this variable are used to augment the linker's search rules. Presently, the only trusted directory to the runtime linker is /usr/lib or /usr/lib/sparcc6 for 64-bit SPARCV9 objects.

In a secure process

In a secure process, the expansion of the SORORIG string is allowed only if it expands to a trusted directory. New in the Solaris 8 release

You can load additional objects with a secure process by using the PRELOAD or LD_AUDIT environment variables. You can specify these objects as full path names or simple file names. Full paths with no / in the name are located to search the path restrictions previously described and, resolve only to known trusted directories. New in the Solaris 8 release

In secure process, any dependencies that consist of simple file names are processed with the path-name restrictions previously described. Dependencies that are full or relative path names are used as there. The developer of a secure process should ensure that the target directory referenced as a full or relative path-name dependency is sufficiently protected from malicious intrusion. New in the Solaris 8 release

When creating a secure process, it is recommended that you not use relative path names for dependencies or to construct dlopen(3DL) path names. This restriction should be applied to the application and all dependencies. New in the Solaris 8 release

# Examples

The following example uses the LD_FLAGS environment variable to group environment variable information.

```
example% LD_FLAGS_32=bind_now,library_path=/lib/one:/lib/two
example$ LD_FLAGS_64=library_path=/lib/64,preload=foo.so
```
