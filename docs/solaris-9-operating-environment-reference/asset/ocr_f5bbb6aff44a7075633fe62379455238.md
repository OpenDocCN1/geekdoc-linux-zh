rpcgen

```
/usr/bin/rpcgen [-s netype] [-o outfile] [infile]
/usr/bin/rpcgen [-n netid] [-o outfile] [infile]
```

# Description

The rpcgen command is a tool that generates C code to implement a Remote Procedure Call (RPC) protocol. The input to rpcgen is a C-like language known as RPC Language (Remote Procedure Call Language).pcgen is normally used in the first synopsis where it takes an input file and generates output files. If the infile named proto.x, then rpcgen generates a header in proto.h, XDR runs over proto_xdr, server-side stubs in proto_svc.c, and client-side stubs in proto_clnt.c. With the -T option, rpcgen also generates the dispatch table in proto_tbl.i.pcgen can also generate sample client and server files that can be customized to a particular application. The -c, -s, and -o options generate sample client, server, and makefile. The -a option generates all files, including sample files. If the infile is proto.x, then the client-side sample file is written to proto_clnt.c, the server-side sample file to proto_svc.c, and the sample makefile to makefile.proto.
The server can be started by both the port monitors (for example, inetd or by itself). When the server is started by a port monitor, it creates servers for the transport for which the file descriptor was passed. You must specify the name of the transport by setting the PM_TRANSPORT environment variable. When the server generated by rpcgen is invoked, it creates server handles for all the transports specified in the NETPATH environment variable or, if absent, creates server handles for all visible transports from the /etc/netconf file.

> Note — The transports are chosen at runtime and not at compile time. When the server is self-started, it puts itself in background by default. When you use the special symbol, rpc_SVC_FG, to run the server process in foreground.

The second synopsis provides special features that enable the creation of more sophisticated RPC servers. These features include support for user-provided #defines and RPC dispatch tables. The entries in the RPC dispatch table contain:

+   - Pointers to the service routine corresponding to that procedure.
- A pointer to the input and output arguments.
- The size of these routines.

A server can use the dispatch table to check authorization and then execute the service routine; a client library can use the dispatch table to deal with the details of storage management and XDR data conversion.
The other three synopses are used when you want to generate a particular output file. See "Examples" on page 1158 for rpcgen usage. When you execute rpcgen with the -s option, rpcgen creates servers for that particular class of transports. When you execute rpcgen with the -n option, it creates a server for the transport specified by netid. If you use no infile, rpcgen accepts the standard input.
You can use all the options mentioned in the second synopsis with the other three synopses, but the changes are made only to the specified output file.

The preprocessor cc -E is run on the input file before it is interpreted by rpcgen. For each type of output file, rpcgen defines a special preprocessor symbol for use by the rpcgen programmer.

| RPC_HDR | Defined when compiling into headers |
| RPC_XDR | Defined when compiling to XDR routines |
