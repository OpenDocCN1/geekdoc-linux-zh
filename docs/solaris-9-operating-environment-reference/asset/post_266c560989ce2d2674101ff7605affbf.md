# install

# Description

The install command is most commonly used in makefiles (see make(1)) to install a file in a specific location or to create directories within a file system. Each file is installed by being copied into the appropriate directory.

install uses no special privileges to copy files from one place to another. The implications of this are:

- * You must have permission to read the files to be installed.
- You must have permission to copy into the destination directory.
- * You must have permission to change the modes on the final copy of the file if you want to use the -option.
- * You must be superuser if you want to specify the ownership of the installed file with the -u or -g options. If you are not the superuser, the installed file is owned by you, regardless of who owns the original.

install prints messages telling you exactly it is replacing or creating and where they are going.

If you specify no options or directories (dirx...), install searches a set of default directories (/bin,/bin,/etc,/lib,/usr/lib, in that for a file with the same name as file. When it finds the first occurrence, install issues a message saying that it is overwriting that file with file proceeds to do so. If the file is not found, the program starts and exits.

If you specify one or more directories (dirx...) after file, those directories are searched before the default directories.

# Options

- -c dira Install file in the directory specified by dira if file does not exist. If it is found, issue a message saying that the file already exists and exit without overwriting it.

- -d Create a directory. Missing parent directories are created as required in mkdir -p. If the directory already exists, set the owner, group, and mode to the values given on the command line.

- -f Force file to be installed in the given directory, even if the file already exists. If the file is being installed does not exist, set the mode to 755 and the owner to bin. If the file already exists, the mode and owner are those of the existing file.

- -g group Set the group ID of new file to group Only available to the superuser. Set to bin by default.

- -i Ignore default directory list, searching only through the given directories (dirx...).

- -m mode Set the mode of the new file to mode. Set to 0755 by default.

- -n dirc If file is not found in any of the searched directories, put it in the directory specified by dirc. Set the mode of the new file to 755 and the owner to bin.

- -O If file is found, save the found file by copying it to OLFILE in the directory in which it was found. This option is useful for installing a frequently used file, such as /bin/sh/or /lib/saf/ttym, from which you cannot remove the existing file.

- -S Suppress printing of messages other than error messages.

- -u user Set the owner of the new file to user. Only available to the superuser. Set to bin by default.

# Manual Page Command Syntax

Unless otherwise noted, commands described in the Synopsis section of a manual page accept options and other

```
name [-option...] [cmarg...]
```

- name Specify the name.
- [-option...] Indicate options.
- [cmarg...] Indicate arguments.

# Command Syntax: Rules

The enforcement of these rules must be done by the command.

- 1. Command names (name) must be between two and nine characters.
- 2. Command names must include lowercase letters and digits.
- 3. Option names (option) must be one character.
- 4. All options must be preceded by a dash (-).
- 5. Options with no arguments may be grouped after a single dash (-).
- 6. The first option-argument (optarg) following an option must be preceded by a Tab or space character.
- 7. Option-arguments cannot be optional.
- 8. Groups of option-arguments following an option must be separated by commas or separated by space character.
- 9. All options must precede operands (cmargabove) on the command line.
- 10.You can use a double dash (--) to indicate the end of options.
- 11.The order of the options relative to one should not matter.
- 12.The relative order of the operands (cmargabove) may affect their significance in ways determined by the command.

# Diagnostics

On termination, each command returns two bytes of status, one supplied by the system and giving the cause for termination, and (in the case of "normal" termination) one supplied by the program [see wait(3B) and exit(2)]. The former byte is 0 for termination; the latter is customarily 0 for successful execution and non-zero to indicate troubles such as erroneous parameters, or bad or inaccessible data. It is called variously "exit code," status," or "return code," and is described only when special conventions are involved. In this book, the Exit Status section for each command describes the values returned on termination.

# Warnings

Some commands produce unexpected results when processes containing null characters. These commands often treat text input as strings and therefore become confused on encountering a null character (the string terminator) within a line.
