# Idap - LDAP as a Naming Repository

## Description

LDAP refers to the Lightweight Directory Access Protocol Protocol, new in the Solaris 8
Operating Environment, which is emerging as an industry standard for accessing
directory servers. Changes in the Solaris 9 release are shown with the New icon in the
margin. By initializing the client with the ldapclient(M) command and using the
LDAP keyword in the /etc/nswitch.conf name service switch, Solaris clients can
obtaining information from an LDAP server. Information such as users, host
names, and passwords are stored on the LDAP server in the form of a tree structure
Directory Tree or D. The D contains entries that, turn, are composed
of attributes. Each attribute has a type and one or more values.

Solaris clients use the LDAP v3 protocol to access naming information from
LDAP servers. The LDAP server must support the object classes and attributes defined
in RFC2307bis(draft), that maps the Naming Information service onto LDAP.

As an alternative to using the schema defined in RFC2307bis(draft), you can
configure the system to use other schema; the schema mapping feature is
configured to map between the two. Refer to the System Administration Guide: Naming
and Directory Services (DNS, NIS, and LDAP) for more details.

## Configuration Information

You can use the ldapclient(M) command to update the appropriate directories and
configuration information to make a Solaris machine an LDAP client. The LDAP clients
cache this configuration in local cache files. This configuration information is
accessed with the ldap_cachemgr(M) daemon. This daemon refreshes the
information in the configuration files from the LDAP server, providing better
performance and security than that of other nameservices. The ldap_cachemgr
run at all times for the proper operation of the naming services.

LDAP uses two kinds of configuration information: the information available
through a profile and the information configured per client. The profile contains all
information about how client accesses the directory. The credential information for
proxy user is configured for each client and is not downloaded through the profile.

The profile contains server-specific parameters that are required by all clients
to locate the servers for the desired LDAP domain. This information could be the server's
IP address and the search base Distinguished Name (DN), for example. The profile is
configured on the default profile client during initialization, and the
ldap_cachemgr daemon updates the profile when the expiration time has elapsed.

A client profile is stored in the LDAP server, and the ldapclient command uses
to initialize an LDAP client. The client profile provides the easiest way to
configure a client machine. See ldapclient(M).

## Credential Information

Credential information includes client-specific parameters that are used by a client. This information could get the Bind DN (LDAP "login" name) of the client and the password. If these parameters are required, they are manually defined during the initialization through ldapclient(LM).

## Naming Information

The naming information is stored in containers on the LDAP server. A container is a nonentry in the DIT that contains service information. Containers are similar to maps in NIS and tables in NIS+. The mapping between Network Information Service (NIS) databases and tables in NIS+ is shown below.

## Client Authentication

The security model for clients is defined by a combination of the credential level to use, the authentication method, and the PAM module to be used—that is, pam_unix or pam_ldap. The credential level defines what credentials the client should use to authenticate to the server. The authentication method defines the method by which authentication is accomplished. Both can be set with multiple values. The Solaris client supports the following values for credential level.

- * anonymous
- proxy
- simple
- sasl/CRAM-MD5
- sasl/DIGEST-MD5
- tls:simple
- tls:sasl/CRAM-MD5
- tls:DIGEST-MD5

The form of access control provides different levels of protection, enabling the server to grant access for certain containers/entries. You specify access control in the form of access lists (ACLs). Each ACL specifies one or more directory objects (for example, the cn attribute in a specific container), one or more clients to which you grant or deny access, and one or more access rights determines what the clients can do with the objects. Clients can be users or applications. Refer to the System Administration Guide for restrictions on ACLs using LDAP.

## Network Switch File

A nswitch.conf(4) file named nswitch.ldap is available in the /etc directory. This file is copied to /etc/nswitch.conf by the ldclient(1M) command. The nswitch.ldap file uses ldap for the different databases in the nswitch.conf file. The default nswitch.ldap is shown below.

```
# /etc/nswitch.ldap

# An example file that could be copied over to /etc/nswitch.conf; it
# uses LDAP in conjunction with files.

# "hosts": and "services": in this file are used only if
# /etc/netconfig file has a "-" for nametoaddr_libs of "inet" transports.

# The two lines obligate the "*" entry in /etc/passwd and /etc/group.
passwd: files ldap
group: files ldap

# consult /etc "files" only if ldap is down.
hosts: ldap [NOTFOUND]=return files
ip: files

# Uncomment the following line and comment out the to resolve
# Both IPv4 and IPv6 addresses from the ipnodes databases. Note that
# IPv4 addresses are searched in all of the ipnodes databases before
# searching the hosts databases. Before turning this option on, consult
# The Network Administration Guide for more details on using IPv6.
```
