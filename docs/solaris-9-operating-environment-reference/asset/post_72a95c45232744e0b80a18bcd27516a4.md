# Escape Description Meaning

| Escape | Description |
| :--- | :--- |
| \ | Backslash. |
| / | Slash character. |
| \ddd | A backslash character followed by the longest sequence of one-, two-, or three-digit octal characters (01234567). If all of the digits are 0 (null character), the behavior is undefined. |
| | The character encoded by the one-, two-, or three-digit octal integer. Multbyte characters concatenated escape sequences, including the leading \ for byte. |
| \c | A backslash character followed by any character not described in this table or the special characters \\, \a, \b, \f, \n, \r, \t, \v. |
| | Undefined. |

A regular expression can be matched against a specific string or by one of the two regular expression matching operators to interpret their right-hand operand as a regular expression and their left-hand operand as a string. If the regular expression matches the string, the expression evaluates to 1, and the regular expression does not match the string, the expression evaluates to 0, and the !! expression evaluates to the value 1. If the right-hand operand is a string rather than the lexical token, the string value of the expression is interpreted as an regular expression, including the escape conventions described above. Note that same escape conventions are also applied in defining the value of a string literal (the lexical STRING) and applied a second time when a string literal is used in this context.

When an ERE appears in any context other than the right-hand side of the ~ operator or as of the built-in function arguments described below, the value of the resulting expression is equivalent of $0 ~ /ere/. The argument to the gsub, match, and sub functions and the FS argument are interpreted as regular expressions. These ERE are interpreted in the same manner as the right-hand side of the ~ or !! operator.

An extended regular expression can separate fields using the -F ERE option by assigning a string containing the expression to the built-in variable FS. The default value of the FS variable is a single-space character FS behaves in the following way:

- 1. If FS is a single character,
  - Skipping delimiter and trailing blank characters; fields are delimited by sets of one or more blank characters.
  - Otherwise, if FS is any other character c, fields are delimited by each single occurrence of c.
- 2. Otherwise, the string value of FS is considered an extended regular expression. Each occurrence of a sequence matching the extended regular expression limits fields.

Otherwise, the string value of FS is considered an extended regular expression. Each occurrence of a sequence matching the extended regular expression limits fields.

Except in the gsub, match, split, and sub-built functions, regular expression matching is based on input records; that is, record separator characters (the first character of the value of the RS, a newline character) cannot be embedded in the expression, and no expression matches the record separator character.

If the record separator is not a newline character, newline characters embedded in the expression can be matched. In these four built-in functions, regular expression matching is based on text strings. so, any character (including the newline character \ and the record separator) can be embedded in the pattern, and an appropriate pattern matches any character. However, in awk regular expression matching, the use of one or more null characters in the pattern, input record, or text string produces undefined results.

# Patterns

A pattern is any valid expression, a range specified by two expressions separated by comma, or one of the two special patterns, BEGIN or END.

# Special Patterns

The awk recognizes two special patterns, BEGIN and END. Each BEGIN pattern is matched once and its associated action executed before the first record of input is read (except possibly by use of the getline function in a prior BEGIN action) and before command-line assignment is done. Each END pattern is matched, and its associated action is executed after the last record of input has been read. These two patterns have associated actions.

BEGIN and END do not combine with other patterns. Multiple BEGIN and END patterns are allowed. The actions associated with the BEGIN patterns are executed in the order specified in the program, as are the END actions. An END pattern can precede a BEGIN pattern in a program.

If a nauk pattern consists of only actions with the pattern BEGIN and the BEGIN action contains no getline function, nauk exits without reading its input when the last statement in the last action is executed. If a nauk pattern consists of only actions with the pattern END or only actions with the patterns BEGIN and END, the input is read before the statements in the END actions are executed.

# Expression Patterns

An expression pattern is evaluated as if it were an expression in a Boolean context. If t result is true, the pattern is considered to match and the associated action (if any) is executed. If the result is false, the action is not executed.

# Pattern Ranges

A pattern range consists of two expressions separated by a comma. In this case, the action is performed for all records between a match of the first expression and the following match of the second expression, inclusive. At this point, the pattern range be repeated, starting at input records subsequent to the end of the matched record.

# Actions

An action is a sequence of statements. A statement can be one of the following.

```
if ( expression ) statement [else statement]
while ( expression ) statement
do statement while ( expression )
for ( expression ; expression ; expression ) statement
for ( var in array ) statement
delete array[substring] #delete an array element
break
continue
```

```
[statement] ... \
expression # commonly, variable = expression\
print [expression-list] [<expression]\nprintf format [, expression-list] [<expression]\nnext # skip remaining patterns on this input line\nexit [expr] # skip the rest of the input; exit status is expr\nreturn [expr]
```

You can replace any statement with a statement list enclosed in braces. Terminate statements with newline characters or semicolons. Statements are executed sequentially in the order in which they appear.
The next statement abandons all further processing of the current input record. The behavior is undefined if a next statement appears or is invoked in a BEGIN or END action.
The exit statement invokes all END actions in the order in which they occur in the program source and terminates the program without reading input. An exit statement END terminates the program without execution END actions. If an expression is specified in an exit statement, its numeric value is the exit status of nawk unless subsequent errors are encountered or a subsequent statement with an expression is executed.

# Output Statements

Both print and printf write to standard output by default. The output is written to the location specified by output redirection if one is supplied, as follows:

- > expression
>> expression
| expression

In all cases, the expression is evaluated to produce a string that is used as a full path to name into (for or >>) as a command to be executed (|). The first two forms, if the file name is not currently open, it is opened. If necessary, it is created. With the first form, the file is truncated. The output is appended to the file. As long as the file remains open, subsequent calls in expression evaluates to the same value simply append to the file. The file remains open until the close function is called with an expression that evaluates to the same value.
The third form writes output onto a stream piped to the input of a command. The stream is created if no stream is currently open, with the value of expression as the command name. The stream is created with one created by a call to the popen(S), with the value of expression as the command argument and a value of w as the mode argument. As the stream remains open, subsequent calls, in which expression evaluates to the same value, write output to the existing stream. The stream remains open until the close function is called with an expression that evaluates to the same value. At that time, the stream is closed by a call to | close.
The output statements take a comma-separated list of expressions referred to in the grammar by the numerical symbols list_print, print_expr_list, or print_expr_opt. This list is referred to here as the expression list, and each member is referred to as an expression argument.
The print statement writes each expression argument separated by the current output field separator (see variable ORS). All expression arguments are taken as strings, converted if necessary; with the exception that the print format in printf is used instead of conv. An expression list stands for the whole input record (50).
