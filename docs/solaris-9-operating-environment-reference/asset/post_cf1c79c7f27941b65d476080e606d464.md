# nuhup — Run a Command Immune to Hangups

# Synopsis

```
/usr/bin/nuhup command [argument...]
/usr/xpg4/bin/nuhup command [argument...]
```

# Description

The nuhup command to run background jobs that keep running even if you log out. The nuhup command invokes the named command with the arguments supplied. When the command is invoked, nuhup arranges for the SIGHUP signal to be ignored by the process.

When a shell exits, the system sends its children SIGHUP signals which, by default, kill them. You can use the nuhup command when you know that command takes a long time to run and you want to be able to log out of the terminal without interrupting the command. When you precede a command invocation with the nuhup command (or if the process programmatically has chosen to ignore SIGHUP), all stopped, running, and background jobs ignore SIGHUP and continue running.

nuhup automatically sends command output, including standard error, to the nuhup.file.

# nohup

/usr/bin/nohup

Processes run by /usr/bin/nohup are immune to SIGHUP (hangup) and SIGQUIT (quit) signals.

/usr/xpg4/bin/nohup

Processes run by /usr/xpg4/bin/nohup are immune to SIGHUP. The nohup command does not arrange to make processes immune to a SIGTERM (terminate) signal, so they receive it unless you arrange for the processes to be immune to SIGTERM unless the shell makes them immune to SIGTERM.

If nohup.out is not written in the current directory, output is redirected to $HOME/nohup.out. If a file is created, the file has read and write permission (600, see chmod(1)). If the standard error is a terminal, output is redirected to the standard output; otherwise, it is not redirected. The priority of the process run by nohup is not altered.

# Warnings

If you are running the Korn shell (ksh(1)) as your login and have nohup'ed jobs running when you attempt to log out, you are warned with the message:

You have jobs running.

You need to log out a second time to actually log out; however, your background jobs continue to run.

# Notes

The C shell (sh(1)) has a built-in nohup command that provides immunity from SIGHUP but does not redirect output to nohup.out. Commands executed with & are automatically immune to HUP signals in the background.

nohup does not recognize command sequences. In the case of the following command, the nohup command applies only to command1.

```
$ nohup command1; command2
```

The following command is syntactically incorrect.

```
$ nohup command1; command2
```

# Operands

| command | The name of a command that is to be invoked. If the command_operand names any of the special shell_builtins(1) commands, the results are undefined. |
| argument | Any string to be supplied as an argument when invoking the command operand. |

# Examples

It is frequently desirable to apply nohup to pipelines or lists of commands. You can do this by placing pipelines and command lists in a single file, called a shell script. You run the script with the following command, then nohup applies to everything in the file.

```
$ nohup sh file
```

If the shell script file is to be executed often, you can eliminate the need to type sh by giving file execute permission.

When you add an ampersand, the contents of file are run in the background with interrupts also ignored (see sh(1)).

```
$ nohup file &
```

HOME Determine the path name of the user's home directory. If the output file nohup.out cannot be created in the current directory, the nohup command uses the directory named by HOME to create the file.

# Exit Status

- 126 Command was found but could not be invoked.
- 27 An error occurred in nohup, or command could not be found.

Otherwise, the exit values of nohup are those of the command operand.

# Files

nohup.out The output file of the nohup execution if standard output is a terminal and if the current directory is writable.

$HOME/nohup.out The output file of the nohup execution if standard output is a terminal and if the current directory is not writable.

# nroff — Format Documents for Display or Line Printer

Synopsis

```
/usr/bin/nroff [options] [file]
```

Description

nroff formats text for display or line printer. See troff(1).

The nroff command processes a file and produces a formatted output. If no file is specified, nroff reads from standard input. If no output file is specified, output is sent to standard output.

The output of nroff can be directed to a file, a printer, or a terminal.

Options

The nroff options control various aspects of the formatting:

- -e Use the default font set.
- -h Do not print the header.
- -f Use the specified font.
- -i Read the standard input after the input files are exhausted.
- -mname Prepend the macro file to the input files.
- -nW Number the first N generated pages.
- -q Do not print output that was from an .rd request.
- -raN Set register a (one-character) to M.
- -sN Stop over N pages (default N1) to allow page loading or changing.
- -Tname Prepare output for a device of the specified name. Known names are:

| 37 | Teletype Corporation Model 37 terminal (the default) |
| lp | tn300 | GE Any line printer or terminal without half-line capability. |
| 300 | DASI-300. |
| 300-12 | DASI-300–12-pitch. |
| 300S | DASI-300S. |
| 300S-1 | DASI-300S. |
| 382 | DASI-382 (fancy DTC 382). |
| 450 | DASI-450 (Diablo Hyterm). |
| 450-12 | DASI-450 (Diablo Hyterm)–12-pitch. |
| 832 | AJ 832. |

Notes

The nroff command is part of the troff suite. It is used for formatting documents for display or for line printers. The troff command is used for more advanced formatting. See troff(1).

# Examples

The following example formats user.guide, using the -me macro package and stopping every pages.

```
castle@ nroff -s4 -me users.guide
```
