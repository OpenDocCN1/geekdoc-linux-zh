# Command Substitution

The standard output of a command enclosed in parentheses preceded by a dollar sign $(command) or a pair of grave accents ` ` can be used as part or all of a word; trailing newlines are removed. In the second (aic) form, the string between the quotes is processed for special quoting characters before the command is executed. ("Quoting Characters" on page 602). The command substitution $(cat file) can be replaced by the equivalent $(file). Command substitution of most special commands that do not perform input/output redirection are carried out without creating a separate process. Command substitution enables the output of a command to be substituted in place of the command name itself. Command substitution occurs when the command is enclosed as follows:

```
$(command)
```

or (backquoted version):

```
`command
```

The shell expands the command substitution by executing command in a subshell environment and replacing the command substitution (the text of command$( ) or backquotes) with the standard output of command, removing sequences of one or more newlines at the end of the substitution. not removed; however, they can be treated as delimiters and eliminated during field splitting, depending on the value of IFS and quoting that is in effect.

Within the backquoted form of substitution, backslash retains its literal meaning, except followed by $(dollar sign, quote, backslash). The search for the matching backquote is justified by the first backquote without a preceding backslash; during this, if an uned backquote is encountered within a shell command, a here-document, an embedded command substitution of the $(command) form, or a quoted string, then undefined results occur. A single- or double-quoted string that begins but does not end within the ` sequence produces undefined results.

With the $(command) form, all characters following the opening parenthesis to the matching closing constitute the command. Any valid script can be used for command; however,

- A script consisting solely of redirections produces unspecified results.
-- See the restriction on single subshells described below.

The result of command substitution is that field splitting and path-name expansion are processed for furthertilde expansion, parameter expansion, command substitution, or arithmetic expansion. If a command substitution occurs inside double quotes, it is not performed on the result of the substitution.

Command substitution can be nested. To specify nesting within the backquoted version, precede the inner backquotes with backslashes; for example:

```
\`command\`
```

The $ ( ) form of command substitution solves a problem of inconsistent behavior when backquotes are used. For example:

| Command | Output |
| :--- | :--- |
| echo \$x | \$x |
| echo `echo \$x` | $x |
| echo $(echo \$x) | \$x |

Additionally, the backquoted syntax $() has historical restrictions on the contents of the embedded command. Whereas the new $() can process any kind of valid embedded script, the backquoted form cannot handle some valid scripts that include backquotes. For example, these otherwise valid embedded scripts do not work in the left column, but do work in the right:

```
echo $(
cat <<eof
cat <<eof
a here-doc with `
a here-doc with )
eof
`)
echo $(
echo abc # a comment with `
echo abc # a comment with )
)
echo $(
echo `'\necho ')')
```

Because of these inconsistent behaviors, the backquoted variety of command substitution is not recommended for new applications that nest command substitutions or attempt to embed complex scripts.

# Input/Output

Before a command is executed, you can redirect its input and output by using a special
notation interpreted by the shell. The following syntax can be used anywhere in a simple
command or precede a command without being passed on the invoked
command. Command and parameter substitution occur before word digit is used
except as noted below. File-name generation occurs if the patterns matches a single
file, and blank interpretation is not performed.

```
<word
```

Use word as standard output (file descriptor 1). If the file does
not exist, then create it. If the file exists and the noclobber option
is on, an error occurs; otherwise, truncate it to length 0.

```
>word
```

Same as >, except override the noclobber option.

```
|word
```

Use word as standard output. If the file exists, then seek to EOF and append to it; otherwise, create the file.

```

```

# Execution
Each time a command is executed, the above substitutions are carried out in the following sequence.

- If the command matches one of the special commands, it is executed in the current process.
- The command name is checked to see if it matches one of the user-defined functions. If so, the positional parameters are saved and then reset to the arguments of the call. When the function completes or issues a return, the positional parameter list is restored and any trap set on EXIT the function is executed. The value of $ is the value of the last command. It is also executed in the current process.
- If a command is not a special command or a user-defined function, a process is created and an attempt is made to execute the command with exec(). The shell variable PATH searches the path for the directory containing the command. Alternative directory names are separated by a colon (:). The default path is /bin:/usr/bin and the current directory, in order). The current directory can be specified by two or more colons or a colon at the beginning or end of the path. If the command name contains a /, the search path is not used. Each directory in the path is searched for an executable file. If the file execute permission but is not a directory or an .out it is assumed to be a file containing shell commands. A subshell is spawned to read. All nonexported aliases, functions, and variables are removed in this case. A parenthesized command is executed in a subshell without removing nonexported.

# Arithmetic Expansion

An arithmetic expression enclosed in double parentheses preceded by a dollar sign $((arithmetic-expression)) is replaced by the value of the arithmetic expression within the double parentheses. Arithmetic expansion provides a mechanism for evaluating an arithmetic expression and substituting its value. The format for arithmetic expansion is as follows:

$((expression))

The expression is treated as if it were in double quotes, except that a double-quote inside the expression is not treated specially. The shell expands all tokens in the expression for parameter expansion, command substitution, and quote removal.
Next, the shell treats the expression as an arithmetic expression and substitutes the value. The arithmetic expression is processed according to the rules of the ISO C with the following exceptions:

* Only integer arithmetic is required.
* The sizeof() operator and the prefix ++ and -- operators are not required.
