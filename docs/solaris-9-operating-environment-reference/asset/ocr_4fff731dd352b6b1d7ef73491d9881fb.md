# 856 mdb

showmid mdb provides support for symbol naming and identifications in user applications that make link of maps other than LM_ID_BASE and LM_ID_LDSO, as described in “Process Attach and Release” on page 852. Symbols on link maps other than LM_ID_BASE or LM_ID_LDSO are shown as Lmid symbol, where Lmid is the link-map ID in the default output radix (16). You can optionally configure mdb to show the link-map ID scope of all symbols and objects, including those associated with LM_ID_BASE and LM_ID_LDSO, enabling the showmid option. Built-in dems that that objectfile names display link-map IDs according to the value of showmid, including :nn, :mappings, $m, and :objects.

+   -R Set root directory for path-name expansion. By default, the root directory is derived from the path name of the mdb executable itself. The root directory is substituted in place of the & token during path-name expansion.

+   -s distance Set the symbol-matching distance for address-to-symbol conversions to the specified distance. By default, mdb enables a smart-matching mode by setting the distance to zero. Each ELF symbol table entry contains a value V and size s. In smart mode, mdb matches an address with the given symbol if A is in the range [v, v+v]. If you specify any non-zero distance, the same algorithm is used by v in the expression above is always the specified absolute distance and the symbol size is ignored.

+   -S Suppress processing of the user’s ~/.mdbrc. By default, mdb reads and processes the .mdbrc macro file if one is present in the user’s home directory, defined by $HOME. Specifying the -S option prevents this file from being read.

+   -u Force user debugging mode. By default, mdb tries to infer whether the object and corefile operands refer to a user executable and core dump or to a pair of operating system crash files. The -u option forces pdb to assume these files are not operating system crash dumps.

+   -V dis-version Set the disassembler version. By default, mdb tries to infer the appropriate disassembler for the debug target. You can explicitly set the disassembler with the -V option. The ::disasms dcmd lists the available disassembler versions.

+   -w Open the specified object and corefiles for writing.
