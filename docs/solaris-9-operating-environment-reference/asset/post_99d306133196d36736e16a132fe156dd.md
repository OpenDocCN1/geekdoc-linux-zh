You can specify each environment variable with a _32 or _64 suffix that makes the environment variable specific to 32-bit or 64-bit processes and overrides any unsixed version of the environment variable that may be in. New in the Solaris 8 release.

Note — Environment-variable names beginning with the characters LD_ are reserved for possible future enhancements to ld and ld.so(1).

## Security

For the prevention of malicious dependency substitution or symbol insertion, some restrictions may apply to the evaluation of the dependencies of secure processes.

The runtime linker categorizes a process as secure if the user is not a superuser and the real user and effective user identifiers are not the real group or effective group identifiers are not equal. See getuid(2), getegid(2), getgid(2), and getid(2).

The default trusted directory to the runtime linker is /usr/lib/secure/64 for 64-bit objects. You can use the crel(1) command to specify additional trusted directories to secure applications. Administrators who use this technique should ensure that the target directories are sufficiently protected from malicious intrusion. New in the Solaris 8 release.

If an LD_LIBRARY_PATH environment variable is used for a secure process, only trusted directories specified by this variable are used to augment the linker's search rules. Presently, the only trusted directory to the runtime linker is /usr/lib or /usr/lib/sparcc6 for 64-bit SPARCV9 objects.

### In a secure process

In a secure process, the expansion of the SORORIG string is allowed only if it expands to a trusted directory. New in the Solaris 8 release.

You can load additional objects with a secure process by using the PRELOAD or LD_AUDIT environment variables. You can specify these objects as full path names or simple file names. Full paths with no / in the name are located to search the path restrictions previously described and, resolve only to known trusted directories. New in the Solaris 8 release.

In secure process, any dependencies that consist of simple file names are processed with the path-name restrictions previously described. Dependencies that are full or relative path names are used as there. The developer of a secure process should ensure that the target directory referenced as a full or relative path-name dependency is sufficiently protected from malicious intrusion. New in the Solaris 8 release.

When creating a secure process, it is recommended that you not use relative path names for dependencies or to construct dlopen(3) path names. This restriction should be applied to the application and all dependencies. New in the Solaris 8 release.

## Examples

The following example uses the LD_FLAGS environment variable to group environment variable information.

```
example% LD_FLAGS_32=bind_now,library_path=/lib/one:/lib/two
example$ LD_FLAGS_64=library_path=/lib/64,preload=foo.so
```

# let — Shell Built-In Function to Evaluate One or More Arithmetic Expressions

## Synopsis

```
ksh
let "arg"...
```

## Description

ksh
The let command to perform integer arithmetic as specified by one or more arguments. Each arg can contain numbers, operators, constants, and shell variables to define a separate arithmetic expression to be evaluated. Use double quotes with any arguments that contain spaces or other special characters. You can also use double parentheses (( )) instead of double quotes for arguments that contain white space.
The exit status is 0 if the value of the last expression is non-zero, and 1 otherwise.
```

## Examples

The following example sets the variable X to the sum of 1 + 1.

```
$ let "X=1 + 1"
$ print $$
2
$
```

# lex — Generate Programs for Lexical Tasks

## Synopsis

```
/usr/ccs/bin/lex [-cntv] [-e |w] [-V -Q [y | n]] [file]...
```

## Description

The lex command generates C programs to be used in lexical processing of character input that can also be used as an interface to yacc. The C programs are generated from lex source code and conform to the ISO C standard. Usually, the lex command writes the program it generates to the file lex.yy; the state of this file is unspecified if lex exits with a non-zero exit status.

## Options

- -c Indicate C-language action (default option).
- -e Generate a program that can handle EUC characters (cannot be used with the -w option). yytext [] is of type unsigned char [].
- -n Suppress the summary of statistics usually written with the -v option. If table sizes are specified in the lex source code and do not specify the -v option, then -n is implied.
- -Q[y | n] Print version information. If table sizes are specified in the lex source code and do not specify the -v option, then -n is implied.
- -t Write the resulting program to standard output instead of lex.yy.
- -v Write a summary of statistics to standard error.
- -w Generate a program that can handle EUC characters (cannot be used with the -e option).

## Operands

- file A name of an input file. If you specify more than one file, concatenate all files to produce a single file. If you specify no file or if file is -, use the standard input.

## Output

### Standard Output

If you specify the -t option, the output is standard output.

### Standard Error

If you specify the -t option, informational and warning messages concerning the contents of lex input are written to standard error. If you do not specify the -t option:
- Informational error and warning messages concerning the contents of lex code are written to standard output.
- If you specify the -v option and do not specify the -n option, statistics are also written to standard error.

## Output Files

A text file containing source code is written to lex.yy.

## Extended Description

Each input file contains lex source, which is a table of regular expressions with corresponding actions.

When lex.yy.c is compiled and linked with the lex library (by use of -l), the resulting program reads character input from standard input and puts it into strings that match the expressions.
When an expression is matched, the following actions occur:
- The input string that is matched is left in yy as a null-terminated string; yy is an external character array or a pointer to a character string. You can explicitly select the type with %array or %pointer. The default is %array.
- The external yyleng is set to the length of the matching string.
- The expression's corresponding program fragment, or action, is executed.
During pattern matching, lex searches the set of patterns for the single longest match. The rule given first is chosen from the rules that match the same number of characters.

The general format of lex source is:

```
Definitions %%
Rules %
User routines
```

The first %% is required to mark the beginning of the rules (regular expressions and actions); the second %% is required only if user uses subroutines.
Any line in the Definitions section beginning with a blank character is assumed to be a C-program fragment and is copied to the external definition area of the lex.yy.c file. Similarly, in the Definitions section included between delimiter lines containing only {% and %} is also copied unchanged over the external definition area of the lex.yy.c.

Any input (beginning with a blank character or with { and %) delimiter lines appearing at the beginning of the Rules section before any rules is written to lex.yy.c after the declarations of variables for the yylex function and the first line of code in yylex. Thus, variables local to yylex can be declared here, as an application code to execute on yylex.
