## Environment Variables

If ssh-add needs a passphrase, it reads the passphrase from the current terminal if the command was run from a terminal. If not have a terminal associated with it but DISPLAY and SSH_ASKPASS are set, ssh-add executes the program specified by SSH_ASKPASS and opens an X11 window to read the passphrase. This capability is particularly useful when ssh-add is called from a .Xsession or related script.

- DISPLAY
- SSH_ASKPASS

- 0 Successful completion.
- 1 An error occurred.

## ssh-agent — Authentication Agent

## Synopsis

```
/bin/ssh-agent [-c] [-k] [command [...]]
```

## Description

Use the ssh-agent program, new in Solaris 9 Operating Environment, to hold private keys used for authentication (RSA, DSA). ssh-agent is often started at the beginning of a login session. All other windows or programs started as clients use the ssh-agent program. Through use of environment variables, the agent can be located and automatically used for authentication when you log in to other machines with ssh(1). (See "Using Shell (Task Map)" in System Administration Guide: Security Vertices.) If you specify a command, it is executed as a subprocess of the agent. When the command dies, so does the agent. The agent initially does not have any keys. Keys are added with ssh-add(1), which sends the identity to the agent. Several identities can be stored in the agent; the agent can automatically use any of identities. The ssh-add -l option to display the identities currently held by the agent.

## ssh-agent

The SSH_AGENT_PID environment variable holds the agent's PID. The agent exits automatically when the command given on the line terminates. A UNIX-domain socket is created (/tmp/ssh_XXXXXX.agent.pid), and the name of this socket is stored in the SSH_AUTH_ variable. The socket is accessible only to the current user. This method is easily abused by root or another instance of the same user.

## Options

- Generate C-shell commands on standard output, the default if SHELL indicates a csh-style shell.
- Kill the current agent (given by the SSH_AGENT_PID environment variable).
- Generate Bourne shell commands on standard output, the default if SHELL does not indicate it is a csh-style shell.

## Examples

The following example invokes an ssh-agent with the Bourne, Korn, or BASH shells. You can later load your private keys into it with ssh-add(1).

```
$ eval ssh-agent -s
Agent pid 357
```

The following example invokes an ssh-agent with the C shell. You can later load your private keys into it with ssh-add(1).

```
% eval `ssh-agent -c`
Agent pid 25235
%
```

You can use this eval in your shell's .profile (Bourne/Korn/BASH shells) or .login (C shell) file to start up the agent when you log in.

## Exit Status

- 0 Successful completion.
- 1 error occurred.

## Files

/tmp/ssh-XXXXXXXX/agent.pid
UNIX domain sockets used to contain the connection to the authentication agent. These sockets should be readable only by the owner. The sockets are removed when the agent exits.

## ssh-http-proxy-connect — Secure Shell Proxy for HTTP

## Synopsis

```
/user/lib/ssh/ssh-http-proxy-connect [-h http_proxy_host]
[-p http_proxy_port] connect_host connect_port
```

## Description

Use the ssh-http-proxy-connect command, new in the 9 Operating Environment, as a proxy command for ssh(1) that uses HTTP CONNECT. Typical use is for connections external to a network that are allowed only through a proxy Web server.

## Options

- -h http_proxy_host
Specify the proxy server through which to connect. Override HTTPPROXY and http_proxy environment variables if they are set.
- -p http_proxy_port
Specify the port on which the proxy server runs. If not specified, assume port 80. Override HTTPPROXYPORT and http_proxy environment variables if they are set.

## Operands

http_proxy_host
The host name or IP address (IPv4 or IPv6) of the proxy.

http_proxy_port
The numeric port number to connect to on http_proxy_port.

connect_host
The name of the remote host to which the proxy server is to connect.

connect_port
The numeric port of the proxy Web server to connect to on http_proxy_host.

## Examples

The recommended way to use a proxy command is to configure ProxyCommand in ssh_config(4) as shown in the first two examples. The third example shows how the proxy command can be specified on the command line when you run ssh(1).

The following example configures ssh-http-proxy-connect in the /etc/ssh/ssh_config(4) file when the proxy is set from the environment.

```
Host playtime.foo.com
ProxyCommand /usr/lib/ssh/ssh-http-proxy-connect playtime.foo.com 22
```

The following example configures ssh-http-proxy-connect in the /etc/ssh/ssh_config(4) file to override (or to set if not set) proxy environment variables.

```
Host playtime.foo.com
ProxyCommand /usr/lib/ssh/ssh-http-proxy-connect -h webcache -p 8080
playtime.foo.com 22
```

The following example uses ssh-http-proxy-connect from the ssh(1) command line.

```
example5 ssh -o'ProxyCommand=/usr/lib/ssh/ssh-http-proxy-connect
-h webcache -p 8080 playtime.foo.com 22'
```
