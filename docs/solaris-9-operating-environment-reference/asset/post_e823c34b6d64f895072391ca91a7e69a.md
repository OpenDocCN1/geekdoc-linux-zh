# cp — Copy Files

Synopsis

```
/usr/bin/cp [-fip@] source_file target_file
/usr/bin/cp [-fip@] source_file... target
/usr/bin/cp -r [-R [-fip@] source_dir... target
/usr/xpg4/bin/cp [-fip@] source_file target_file
/usr/xpg4/bin/cp [-fip@] source_file... target
/usr/xpg4/bin/cp -r | -R [-fip@] source_dir... target
```

Description

With the command, you can do the following actions:

- Make copies of individual files and assign new names to them.
- Copy one or more files into a different directory, keeping the existing file names.
- Recursively copy an entire directory structure to another directory.
- Copy extended file attributes.

In the Solaris 9 Operating Environment, the UFS, NFS, and TMPFS file systems are enhanced to include extended file attributes. These file attributes enable application developers to associate specific attributes with a file. For example, a developer of a file management application for a windowing system might choose to display a icon with a file.

In the first synopsis, neither source_file nor target_file are directory files, nor can they have the same name. The cp command copies the contents of source_file to the destination path named by target_file.

If target_file exists, it is overwritten, but the mode (and access control list (ACL) if applicable), owner and group status associated with it are not. The last modification time of target_file and the last access time of source_file are set to the time the copy was made.

When you make a copy of source_file, target_file is created if it does not exist. The target_file has the same owner, and modes as source_file, except that the sticky bit is not set unless the user is superuser. In this case, the owner and group of target_file are those of the user unless the set bit is on the directory containing the newly created file. If the directory set bit is set, the newly created file belongs to the group of directory instead of the creating user.

If target_file is a link to another file with same name, the other links remain and target_file becomes a new name.

In the second synopsis, one or more source_files are copied to the directory specified by target. For each source_file, a new file with the same name (mode and ACL if applicable) is created in target; the owner and group are those of the user making the copy. It is an error if any source_file is a file of type directory or if target does not exist or not a directory.

In the third synopsis, or more directories specified by source_dir are copied to the directory specified by target. You must specify either -r or -R. For each source_dir, cp -r|-R recursively copies all files and subdirectories.

You can use a double-dash ( to explicitly mark the end of any command-line options to recognize file-name arguments with a dash (-).

# Options

The following options are supported for /usr/bin/cp and /usr/xpg4/bin/cp.

- - Preserve extended attributes. cp tries to copy all attributes of the source file along with the data to the destination file. Extended attributes are new in the Solaris 9 release.

- - If a file descriptor for a destination file cannot be obtained, to unlink the destination file and proceed.

- - Interactively prompt for confirmation when the copy would overwrite an existing target. Any answer means proceed with the copy. Any other answer prevents overwriting target.

- - Recursively copy the directory and all its files, including any subdirectories and their files, to target.

- - Same as -r, except replicate pipes.

The following options are supported for /usr/bin/cp only.

- -p Duplicate not only the contents of source-file, but also preserve ID, permission modes, modification and access time, and ACLs if applicable. Note that the command may fail if you copy ACLs a file system that does not support them. The command does not fail if unable to preserve owner and access time or permission modes. If unable to preserve owner and group ID, cp does not fail and clears S_SUID and S_IGID bits in the target. Print a diagnostic message to standard error and return a non-zero exit status if unable to clear these bits.

To preserve the owner and group ID, permission modes, and modification access times, users must have the appropriate file permissions; this includes being superuser or the same owner ID as the destination file.

The following option is supported for /usr/xpg4/bin/cp only.

- -p Same as -p, above, except the command fails if unable to duplicate the modification and access time or the permission modes. Print a diagnostic message to standard error and return a non-zero exit status.

# Operands

- source-file A path name of a regular file to be copied.
- source-dir A path name of a directory to be copied.
- target-file A path name of an existing or nonexistent file, used for the output when a single file is copied.
- target A path name of a directory to contain the copied files.

# Usage

See largefile(5) for the description of the behavior of cp when encountering files greater than equal to 2 Gbytes (*31 bytes).

# Examples

The following example copies a file.

```
castle$ cp goodies goodies.old
castle$ ls goodies*
goodies goodies.old
castle$
```

The following example copies all of the files in one directory to a destination directory.

```
castle$ cp -src/* /tmp
```

The following example copies a directory, first to a new, and then to an existing destination directory.

```
castle% ls - /bkup
/usr/example/fred/bkup not found
cast% cp -r /src ~/bkup
castle% ls -R ~/bkup
x.y c.y. z.sh
cast% cp -R /src ~/bkup
cast% ls -R ~/bkup
src:
x.y c.y. z.sh
cast%
```

# cpio - Copy File Archives In Out

# Synopsis

```
/usr/bin/cpio -i [bbcdfkmPrStuvV60] [-C bufsize] [-E file]
[-H header] [-I -M message] [-R id] [pattern...]
/usr/bin/cpio -o [aAbcPV@] [-C bufsize] [-H header] -O 0 file
[-M message]
/usr/bin/cpio -p [adlmPuvV60] [-R id] directory
```

Use the cpio command to copy files, special files used to represent peripheral devices attached to a system; and file systems that require multiple tape volumes. cpio provides compatibility for copying files from SunOS 5.x systems to SunOS 4.x systems. Advantages of using the cpio command are that it packs data onto tape more efficiently than the tar command, skips over any bad spots on tape when restoring files, provides options for writing files with different header formats (tar, ustar, crc, odc, bar) for portability between different system types, and creates multiple tape volumes.
cpio command, when used to create an archive, takes a list of files or path names from standard input and writes to output. The output is almost always redirected to a file or device.
You use the -i (copy in), -o (copy out), or -p (pass) option to choose the actions to perform.

> Note - cpio assumes 4-byte words. When writing to a character device (-o) or reading from a character device (-i), cpio reaches the end of the medium (as the end of a diskette) and you do not use the -0 and -I options, cpio prints the following message: To continue, type device/file name when. To continue, you must replace the device and type the character special name (/dev/rds, for example) and press Return. You may continue by directing cpio to use a different device. For example, if you have two disk drives, you may want to switch between so cpio can proceed while you are changing the disksettes. (Simply pressing Return exits cpio.)

In the Solaris 9 Operating Environment, the UFS, NFS, and TMPFS file systems are enhanced to include extended file attributes. These attributes enable developers to associate specific attributes with a file. For example, a developer of file management application for a windowing system might associate a display icon with a file. You can use the new -e option to copy extended file attributes.

# Copy-In Mode

cpio -i (copy in) extracts files from the standard input, which is assumed to be the product of a previous cpio -o. Only files that match patterns are selected.
Extracted files are conditionally created and copied into the current directory, the permissions of the files are those of the previous cpio -o. Owner and group are the same as the current user unless the current user is superuser. If the user is supervisor, owner and group are the same as those resulting from the previous cpio -o.
