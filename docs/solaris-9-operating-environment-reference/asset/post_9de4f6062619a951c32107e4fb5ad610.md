# Kernel Mode

Invoking pre with the -k flag runs in kernel mode. In kernel mode, pre controls probes the Solaris kernel. See tnf_kernel_probes(4) for a list of available probes in the Solaris kernel. A few pre commands are unavailable in kernel mode; many other commands are valid only in kernel mode.

The -l, -o, and -p are not valid in kernel mode (that is, you cannot combine them with the -k option).

The rest of this section describes the differences in the pre command language when pre runs in kernel mode.

# pre Does Not Stop the Kernel

When pre attaches to a running user program, it stops the user program. Obviously, it cannot do so attaching to the kernel. Instead provides a tracing master switch: no probes have effect unless the tracing master switch is on. This switch enables you to iteratively select probes to enable, then enable them all at once by turning on the master switch.

Using the following command to inspect and set the value of the master switch.

```
ktrace [on | off]
```

Without an argument, pre reports the current state of the master switch. Because pre does not stop or kill the kernel, the quit resume and kill commands are not valid in kernel mode.

# No Functions Can Be Attached to Probes in the Kernel

The debug function is not available in kernel mode.

# Trace Output is Written to an In-Kernel Buffer

In kernel mode, a trace output file is not generated directly to enable probes to be placed in time-critical code. Instead, trace output is written to an in-kernel buffer and copied out by a separate process, tnfract(1).

The in-buffer is not automatically created. The following pre command controls buffer allocation and deallocation.

```
buffer [alloc [size] | dealloc]
```

Without an argument, the buffer command reports the state of the currently allocated buffer if any. With an argument of alloc [size], pre allocates a buffer of size in bytes, with an optional flag of k or specifying a multiple of 1,024 or 1,048,576. If you specify the size the kernel line with the -s option is used as a default. If you do not use the -s option, the default is 384 kilobytes.

pre dealloc rejects the trace buffer on turning the tracing switch when no buffer is allocated and to deallocate the buffer when the tracing master switch is on. pre refuses to allocate a buffer when one is already allocated; use buffer dealloc first.

pre does not allocate a buffer larger than one-half of physical memory.

# pre Supports Per-Process Probe Enabling in the Kernel

In kernel mode you can choose a set of processes for probes are enabled. No trace output is written when other processes traverse these probe points. This mode is called

"process filter mode." By default, process filter mode is off, and all processes generate trace records when they hit an enabled probe.

Some kernel events as interrupts cannot be associated with a particular user process. By convention, these events are considered to be generated by process ID 0. prev provides commands to turn process filter mode on and off off, to get the current status of the process filter mode switch, to add and delete processes (by process ID) from the process filter set, and to list the current filter set.

The process filter set is maintained when process filter mode is off but has no unless process filter mode is on.

When a process in the process filter set exits, its process ID is automatically deleted from the process filter set.

The following command controls the process filter switch and process filter set membership.

```
pfil {on | off | add pidlist | delete pidlist}
```

With no arguments, pfil prints the current process filter set and the state of the process filter mode switch. on or off sets the state of the process filter mode switch.

```
add pidlist
delete pidlist
```

add or delete processes from the process filter set. pidlist is a comma-separated list of one or more process IDs.

# Examples

See tracing(TNF) for complete examples showing, among other things, the use of perf for simple probe control.

When the process or kernel is started, all probes are disabled.

```
# Set the current and list setting
create sout name=/out/
# Sout = probes with "out" in
# value of "name" attribute
create sfoo /page/name-blionode # sfoo = union of
# probes with "page" in value of keys attribute
# probes with "page" as value of "name" attribute
# list the defined sets
list sets # list the defined sets
list fcns # list the defined probe fcns
```

```
# Commands to trace and connect probes
trace foobar='on'
# exact match on foobar
trace $all
# trace all probes (defined set $all)
connect &debug $foo
# connect debug func to probes $foo
```

```
# Commands to enable and disable probes
enable $all # enable all probes
enable /vm/ name-alloc # enable the specified probes
disable $sfoo # disable probes in set $foo
list history # list probe control commands
```

```
# Process control
continue # resumes the target process
```

```
^C
quit resume
# stop target; give control to prex
# exit prex, leave process running
```

# Bugs

prex:should issue a notification when a process ID has been automatically deleted
the filter set.
A known bug in prex can result in the message:
Tracing shut down target due to an internal
error - Please restart prex and target

When you run prex as root, the target process is not root and you put the tracefile in
a directory where it cannot be removed and recreated (such as a directory /tmp with
the sticky bit on), then the target process is not able to open the tracefile when it needs
disabling.

Changing any of the circumstances above fix the problem. Either doesn't
run prex as root, the target as root, or specify the tracefile in a directory
other than /tmp.

# print — Shell Built-in Function to Output Characters to the Screen or Window

# Synopsis

```
ksh
print [-Rmprsu [n]] [arg...]
```

# Description

Korn built-in function is the mechanism used by the Shell to display arg. With no options or with -- -- the arguments are printed on standard output as described by echo(1). The exit status is 0 unless the output file is not open for writing.

# Options

- -n Suppress newline from being added to the output.
-R -r Ignore the escape conventions of echo. The -R option prints all subsequent arguments and options other than -n.
-p Write the arguments onto the pipe of the process spawned with | instead of standard output.
-s Write the arguments into the history file instead of standard output.
-u [n] Use the n argument to specify a one-digit file descriptor unit on which the output is placed. The default is 1.
