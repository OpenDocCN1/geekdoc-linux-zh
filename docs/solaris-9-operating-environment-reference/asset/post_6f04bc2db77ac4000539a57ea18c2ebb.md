
# Description

Use the ls command to list the contents of a directory and display permissions, links, ownership, group, size (in bytes), modification date and time, and name for files.

For each file that is a directory, ls lists the contents of the directory; for each file that is an ordinary file, ls repeats its name and any other information requested. The output is sorted alphabetically by default. When you specify several arguments, ls lists the contents of the current directory. The arguments are first sorted appropriately, with file arguments before directories and their contents.

ls has three major listing formats.

- The default format for output directed to a terminal is multicolumn with entries sorted down the columns.
- The -l option displays single-column output.
- The -m option displays stream format. Files are listed all on the same line separated by a comma and a space.

To determine output format for the -C, -x, and -m options an environment variable, COLUMNS, is used to determine the number of character positions available on one output line. If this variable is not set, the terminfo(4) database is used to determine the number of columns, based on the environment variable TERM. If this information cannot be obtained, 80 columns are assumed.

The mode printed with the -l option consists of ten characters. The first character is one of the following:

- d The entry is a directory.
- D The entry is a device.
- l The entry is a symbolic link.
- b The entry is a block special file.
- c The entry is a character special file.
- p The entry is a FIFO (or named pipe) special file.
- s The entry is an AF_UNIX address family socket.
- - The entry is an ordinary file.

The next nine characters are interpreted as three sets of three bits each. The first set refers to the user's permissions; next to permissions of others in the user-group of the file; and to all others. Within each set, the three characters indicate permission to read, write, and execute the file as a program. For a directory, execute permission is interpreted as search the directory for a specified file.

For user and group permissions, the third position can be occupied by x (execute), + (deny access), or s (set user ID). The s permission designation refers to the state of the set-ID bit, whether it be the user's or the group's. For example, the ability to assume the same ID as the user during execution is used during login where you begin the process as root then assume the identity of your user login.

For group permissions, the third position can be occupied by 1 refers to mandatory file and record logging. This permission describes a file's attribute to allow others to lock its reading or writing access.

For other permissions, the third position can be occupied by t or T. These refer to the state of the sticky bit and execution permissions.

The permissions are indicated as follows.

ls -1 (the long list) prints its output as follows for the POSIX locale: -rwwxrxrwx winsor staff 10876 May 16 9:42 part2

Reading from left, the current directory holds one file name, part2. The last time that file's contents were modified was 9:42 a.m. on May 16. The file contains 10,876 characters or bytes. The owner of the file, the user, belongs to the group staff, and the login name is winsor. The number, in this case, 1, indicates the number of links to file part2 (see cp(1)). The plus sign indicates that there is an access control list (ACL) associated with the file.

# Operands

-   file A path name of a file to be listed. If the specified file is not found, display a diagnostic message on standard error.

# Usage

ls(5) for the description of the behavior of ls when encountering files greater than or equal to 2GB (**31).

# Examples

The following example of file permissions describes a file that is readable, writable, executable by the user and readable by the group and others.

```
-rwxr-xr-x
```

The following example describes a file that is readable, writable, executable by the user, readable and executable by the group, and enables its user ID to be assumed, during execution, by the user presently executing.

```
-rwsr-xr--
```

The following example describes a file that is readable only by the user and the group that can be locked during access.

```
-rw-r--r--
```
