# which

# Bugs

Only aliases and paths from ~/.cshrc are used; importing from the current environment. The which command must be executed by csh(1) because only csh knows about aliases.

To compensate for ~/.cshrc files in which aliases depend on the prompt variable being set, which sets this variable to null. The which produces output for input when the prompt is set, which may produce some strange results.

# Examples

In the following example, the which command cannot locate the which command. Instead, it displays the search path that it used to locate the command.

```
castle@ which whence
no whence in /usr/openwin/bin /usr/dt/bin /usr/bin /usr/sbin
/usr/ucb/etc /usr/proc/bin /opt/hpnnp/bin /usr/local/games
/usr/ccs/bin .
caste%
```

In the following examples, the which command displays the location of the which and where commands.

```
castle% which which
/bin/which
caste% which where
/usr/ucb/where
caste%
```
