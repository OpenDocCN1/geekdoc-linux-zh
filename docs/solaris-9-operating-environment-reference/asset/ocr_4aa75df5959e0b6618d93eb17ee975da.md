# Basic prex Commands

| Command | Result |
| --- | --- |
| % prex a.out | Attach prex to your program, and start prex. |
| prex> enable $all | Enable all the probes. |
| prex> quit resume | Quit prex, and resume execution of the program. |

# Control Search Path

You can communicate with prex in two different ways:

+   - By specifications in a control file. During startup, prex searches for a file named .prex in the directories specified below. prex does not stop at the first file it finds. You can use the control file to override any defaults. The search order is:
  $HOME/.
- By typing commands at the prex prompt

The command language for both methods is the same and is used in "Usage" on page 1097. The commands that return output do not make sense in a control file. The output goes to standard output.

When prex is used to analyze a process, the target is in one of two states: running or stopped. You can detect the state by the presence or absence of the prex prompt. If the prompt is absent, it means the target process is running. Turning Control-C stops the target and returns. There is no guarantee that Control-C returns to a prex prompt immediately. For example, if the target is stopped on a job control stop (SIGSTOP), Control-C in prex waits until the target has been continued (SIGCONT). See "Signals to Target Program" on page 1100 for more information on SIGCONT.

# Notes

Currently, the only probe that is available is the &debug function. When this function is executed, it returns the sum&debug attribute in the probe as well as the value associated with the debug field (if any) to standard error. For example, for the following probe:

```
TNF_PROBE_2(input_values, "testapp main",
"sum&debug "have read input values successfully",
tnf_long, int_input, x,
tnf_string, string_input, input);
```

if x was 100 and input was the string "success", then the output of the debug function would be

```
probe input_values; sum&debug "have read input values successfully";
int_input=100; string_input="success";
```
