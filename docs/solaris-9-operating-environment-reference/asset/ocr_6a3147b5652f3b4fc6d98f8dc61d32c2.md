You cannot trap or reset signals that were ignored on a noninteractive shell, although no error be reported when an attempt is made to do so. An interactive shell may reset or catch signals on entry. Traps remain in place for a shell until changed with another trap command. When a subshell is entered, traps are set to the default args. This does not imply that you cannot use the trap command within the subshell to set new traps. The trap command with no arguments writes to standard output a list of commands associated with each sig. The format is:

```
trap -- %s %... arg, sig...
```

The shell formats the output, including the proper use of quoting, so that it is suitable for rerun to the shell as commands that achieve the same trapping results. For example:

```
save_traps=$ (trap)
```

```
eval "$save_traps"
```

If the trap name or number is invalid, return a non-zero exit status; otherwise, return 0. For both interactive and noninteractive shells, invalid signal names or numbers are not considered a syntax error and do not abort the shell. Traps are not processed while a job is waiting for a foreground process. Thus, a trap on CHLD won't be executed until the foreground job terminates.
