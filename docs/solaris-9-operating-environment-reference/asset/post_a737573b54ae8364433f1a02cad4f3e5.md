directory cache and alternative object features are typically usable to user applications and shared objects.

crle alternative objects for the shared objects discovered by calls to dldump(3) when the -I and -G options are used. The alternative object is created in the directory specified by the preceding -o option or defaults to the directory in which the configuration file is created. The flags used for the dldump() are specified with the -f option, or they default to RTLD_REL_RELATIVE.

# Options

- -64 Process 64-bit objects, the default is 32.
- -n name Add an alternative to name to the configuration file. You must supply the actual alternative name. You can use this option multiple times. If name is a directory, each shared object within the directory is added to the cache. If name does not exist, it is marked in the cache as a nonexistent file.
- -conf Use the configuration file name conf. If you do not specify this option, the default configuration file is used.
- -flags Provide the symbolic flags argument to the dumpfile(3) calls used to generate alternative objects. You can use any of the RTLD_REL flags defined in /usr/include/dlcn.h. You can use OR flags with the character and, in this case, you should quote the string to avoid expansion by the shell. If you specify no flags values, the default flag is RTLD_REL_RELATIVE.
- -i name Add an individual name to the configuration cache. You can specify this option multiple times. name can be a shared object or a directory. If name is a directory, crle adds each shared object within the directory to the cache: If name does not exist, it is marked in the cache as a nonexistent directory.
- -i name The same as -i, and in, any shared objects have alternatives created by dldump(3). If -f flag contains RTLD_REL_EXEC, then name can be a dynamic executable for which an alternative is created. You can specify only one dynamic executable in this way because the cache created specific to this application.
- -g name Add the group name to the configuration cache. Each object is expanded to determine its dependencies. You can specify this option multiple times. name can be a dynamic executable, shared object, or a directory. If itself is a shared object, its dependencies and its dependencies are added to the cache.
- -g name The same as -g, and in, any shared objects have alternatives created by dldump(3). If name is a dynamic executable and the -f flag contains RTLD_REL_EXEC, then crle creates an alternative for the dynamic executable. You can specify only one dynamic executable in this way because the cache created specific to this application.

- -l dir

Specify a new default search directory dir for ELF or AOUT. You can specify this option multiple times. The type of object applicable to the search is either specified by the preceding -t option or defaults to ELF.

The system default search path for ELF is /usr/lib/64 for 64-bit objects. The system default search paths for AOUT objects is /usr/4ib, /usr/lib, and /usr/local/lib.

This option replaces the default search path, and you must normally use an -l option to specify the original system default in relation to any new paths being applied. However, if you specify the -u option and a configuration file does not exist, the system defaults are added to the new configuration file before the new paths specified with -l.

- -o dir

Specify the directory dir in which alternate objects are created. Without this option alternate objects are created in the directory which the configuration file is created. You can specify this option multiple times; the directory dir is used to locate alternates for any following command-line options. Alternate objects are not permitted to override their associated originals.

- -s dir

Specify a new trusted dir for secure ELF or AOUT objects. See “Security” on page 665 in ld.so(1) for a definition of secure objects.

You can specify this option multiple times. The type of object applicable to the search is either specified by the preceding -t option or defaults to ELF.

The system default trusted directory for secure ELF is /usr/lib/secure for 32-bit objects and /usr/lib/secure/64 for 64-bit objects. The system default trusted directories for secure AOUT objects are /usr/4ib, /usr/lib, /usr/uclib, and /usr/local/lib.

Because this option replaces the system default trusted directories, you are normally required to use the -s option to specify the original system default in relation to any new directories being applied. However, if you specify the -u option and a configuration file does not exist, the system defaults are added to the new configuration file before the new directories specified with the -s.

- -t ELF | AOUT

Toggle the object type applicable to any -l or -s options that follow. The default object type is ELF.

- -u

Update a configuration file, possibly with the addition of new information. Without other options, any existing configuration file is inspected and its contents recomputed. Additional arguments allow information to be appended to the recomputed contents.

The -u option version 2 of crle contains the version level. You can display it with the crle command.

# crle 187

example% crle
Configuration file [2]: /var/ld/ld.config....

With a version 2 configuration file, crle can construct the command-line arguments required to regenerate the configuration file and to provide full update capabilities. Although the update of a version 1 configuration file is possible, the contents of the configuration file may be insufficient for crle to compute the entire requirements.

If a configuration file does not exist, it is created as directed by the other arguments. In the case of the -l and -s options, any system defaults are first applied to the configuration file before the directories specified with these options.

- -v
Verbose mode. When creating a configuration file, write a trace of the files being processed to the standard out. When printing the contents of a configuration file, crle provides more extensive directory and file information.

By default, the runtime linker tries to read the configuration file /var/ld/ld/64.config for each 32-bit application it processes, or /var/ld/ld.config for each 64-bit application. When processing an alternative application, the runtime linker uses $ORIGIN/ld.config.app-name configuration file if present. Applications may reference an alternative configuration file either by setting the LD_CONFIG environment variable (see ld.so(1)), or by recording a configuration name in the application at the time it is built with the link-editor -c option.

# Examples

The following example updates and displays a new search path for ELF objects.

example% crle -u -l /local/lib
example% crle
Configuration file [2]: /var/ld/ld.config
Default Library Path (ELF): /usr/lib:/local/lib
Trusted Directories (ELF): /usr/lib/secure

# Command line:
crle -l /usr/lib:/local/lib
example% crle
Configuration file [2]: /var/ld/ld.config
Default Library Path (ELF): /usr/lib:/local/lib
Trusted Directories (ELF): /usr/lib/secure

In the above example, the default configuration file did not exist, and thus the new search path /local/lib is appended to the system default. The next update appends the search path /local/lib to those already established in the configuration file.

The following example creates and displays a new default search path and trusted directory for ELF objects.

example% crle -l /local/lib -s /local/lib
example% crle
Configuration file [2]: /var/ld/ld.config
Default Library Path (ELF): /local/lib:/usr/lib
Trusted Directories (ELF): /usr/lib/secure

# Command line:
crle -l /local/lib -s /local/lib

> Note — This example replaces the system default cache for ELF objects.

The following example creates a directory cache for ELF objects.

```bash
crle -i /usr/dt/lib -i /usr/openwin/lib -i /usr/lib -c config
example% ldd -s /main
find object=libc.so.1; required by ./main
search path=/usr/dt/lib:/usr/openwin/lib (RPATH ./main)
trying path=/usr/dt/lib/libc.so.1
trying path=/usr/openwin/lib/libc.so.1
search path=/usr/lib (default)
trying path=/usr/lib/libc.so.1
libc.so.1 = /usr/lib/libc.so.1
```

```
example% LD_CONFIG=config ldd -s /main
```

With this configuration, the cache reflects the system library libc.so.1 does not exist in the directories /usr/dt/lib or /usr/openwin/lib. The search for this system file ignores these directories unless the application's runpath indicates they should be searched.
