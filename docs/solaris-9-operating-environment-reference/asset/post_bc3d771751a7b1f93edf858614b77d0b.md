
# asa — Convert FORTRAN Carriage-control Output to Printable Form

# Synopsis

/usr/bin/asa [-f] [file...]

# Description

The command writes its input files to standard output, mapping carriage-control characters from the text files to line-printer control sequences.

The first character of every line is removed from the input, and the following characters are performed.

- When the Character is a:
    - space Then: Output the rest of the line without change. Replace it by a newline control sequence followed by the rest of the input line.
    - 0 Replace it by a newpage control sequence followed by the rest of the input line.
    - 1 Replace it by a control sequence that returns to the first column of the previous line, where the rest of the input line is printed.
    - <blank> Replace it by a control sequence that returns to the first column of the previous line, where the rest of the input line is printed.

For any other character in the first column of an input line, asa skips the character and prints the rest of the line unchanged. If you call asa without providing a file name, the standard input is used.

# Options

- -f Start each file on a new page.

# Operands

- -file A path name of a text file used for input. If you specify no file operands or specify -, then use the standard input.

# Examples

You can use asa as a filter to view the output of FORTRAN programs that use ASA carriage-control characters so that they are displayed in normal form. The following example properly formats and paginates the output then directs it to a line printer.

```
castle@ a.out | asa | lp
```

You can view FORTRAN output previously sent to the file on a terminal screen with the following command.

```
castle@ asa output
```

# at, batch

# at, batch — Execute Commands at a Later Time

# Synopsis

- /usr/bin/at [-c|-k|-s] [-m] [-f] [-p project] [-q queename] time
- /usr/bin/at [-c|-k|-s] [-m] [-f] [-p project] [-q queename] timespec...
- /usr/bin/at -l -p project [-q queename]...
- /usr/bin/batch -r at-job-id...
- - [-p project]

# Description

### at

Use at to schedule jobs for later execution. You can queue any command or shell script. The at command reads commands from standard input and groups them together as at-job to be executed at a later time. The at-job is executed in a separate invocation of the shell, running in a separate process with no terminal, except that the environment variables, working directory, file mask (see umask(1)), and system resource limits (for sh and ksh, use limit(1)) in effect when the at command is executed are retained and when the at-job is executed.

When you submit at-job, the system assigns a unique at-job-id when you schedule it. The at-job-id consists of alphanumeric characters. You can also display a list of currently scheduled jobs using the -l command. See the -command for description of user notification and processing of the job's standard output and error.

Users are permitted to use at and batch if their name appear in /lib/cron/at.allow. If the file does not exist, /lib/cron/at.deny is checked to determine if the user should be denied access to at. The at.allow and at.deny files list one username per line. Starting Solaris 8, if neither at.allow exists, only a user with at.deny is permitted to submit a job. Regardless of the used cron, cron has a limit of 100 jobs in execution at any time. There can be delays in cron execution. In some cases, these delays can compound to the point that job processing seems hung. All jobs are executed eventually. When the delays are excessive, the only workaround is to kill cron and restart it.

### batch

The batch command reads commands to be executed at a later time. It is the equivalent of the command at -q b, where queue b is a special queue for batch jobs. Batch jobs are submitted to the batch queue for execution.

# Options

If you do not use the -c, -k, or -s options, the SHELL environment variable determines which shell is used.

- -c Use C shell, csh(1), to execute the at-job.
- -k Use Korn shell, ksh(1), to execute the at-job.
- -s Use Bourne shell, sh(1), to execute the at-job.
- -f file Specify the path of a file to be used as the source of the at-job, instead of standard input.
- -l Report all jobs scheduled for the invoking user if you specify no at-job operands. If you specify at-job-ids, report information only for these jobs.
- -m Send mail to the invoking user after the at-job has run, announcing its completion. Mail standard output and standard error produced by the at-job to the user unless redirected. Send mail if the job produces output. If you do not use -m, the job's output and standard error are mailed to the user unless they are redirected; if there is no output, the user is not notified of the job's completion.
- -p project Starting with Solaris 8 release, specify under which project the at job is run. When with the -l option, limit the search to that particular project. Values for project are interpreted as a project name and as a possible project ID if numeric. By default, the user's current project is used.
- -q queuename Specify the queue to schedule a job for submission. When with the -l option, limit the search to that particular queue. Values for queuename are limited to the lowercase letters a to z. By default, at-jobs are scheduled in queue a. In contrast, queue b is reserved for batch jobs. Because queue c is reserved for cron jobs, you cannot use it with the -q option.
- -r at-job-id Remove the jobs with the time specified by at-job operands that were previously scheduled by the at command.
- -t time Submit the job to be run at the time specified by the time option argument, which has the decimal [[CC] YYYY MMDDHHmm[.SS]], where each two-digit represents the following:
    - MM The month of the year [01-12].
    - DD The day of the month [01-31].
    - hh The hour of the day [00-23].
    - mm The minute of the hour [00-59].
    - CC The first two digits of the year.

# Operands

at_job_id The identification number for a scheduled at-job.

timespec Submit the job to be run at date and time. All of the timespec operands are interpreted as if separated by spaces and concatenated. The date and time are interpreted as being in the time zone of the user (as determined by the TZ variable) unless a time zone name appears as part of time.

In the C locale, the following describe the three parts of the time specification. All of the values from the LC_TIME categories in the C locale are insensitive.

time You can specify the time as one, two, or four digits. One and two-digit numbers are interpreted as hours. Four-digit numbers are interpreted as hours and minutes. Alternatively, you can specify the time as two numbers separated by a colon, meaning hourminute. You can indicate an a.m./p.m. (one of the values from the am keywords in the LC_TIME locale category). This value can follow the time. A 24-hour clock is understood. A time zone name of GMT, UCT, or Zulu (case insensitive) can follow to specify that the time is in Coordinated Universal Time. You can specify other time zones by using the TZ variable. The time field can also be one of the following tokens in the C locale:

- midnight Indicates the time 12:00 a.m. (00:00).
- noon Indicates the time 12:00 p.m.
- now Indicate the current day and time. Invoking at now submits an at-job for potentially immediate execution (that is, subject only to unspecified delays).

date You can specify an optional date as either a month name (one of the values from the mon or abb keywords in the LC_TIME locale category) followed by a day number (and possibly year number preceded by a comma) or a day of the week (one of the values from the day or abday keywords in the LC_TIME locale category). Two special days are recognized in the C locale:

today The current day.
