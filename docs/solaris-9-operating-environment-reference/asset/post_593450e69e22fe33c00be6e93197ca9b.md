# Copy-Out Mode

cpio -o (copy out) reads the standard input to obtain a list of path names and copies those files into the standard output together with path name and status information. Output is padded to a 512-byte boundary by default, to the block size specified by the -B -C options, or to some device-dependent block size when necessary (as with the CTC tape).

# Pass Mode

cpio -p (pass) reads the standard input to obtain a list of path names of files that are conditionally created and copied into the destination directory tree, based on the options described below.

# Notes

The maximum path-name length allowed in a cpio archive is determined by the header type. The following table shows the proper value for each supported archive type.

| Type | Command-Line Options | Maximum Path Name Length |
| :--- | :--- | :--- |
| BINARY | -o | 256 |
| POSIX | -OH od | 256 |
| ASCII | -oc | 1023 |
| CRC | -OH crc | 1023 |
| USTAR | -OH ustar | 255 |

When you specify the command-line options -H tar, the archive is created of USTAR, which means that it is an error to read the archive with the command-line options -i -H tar. Instead, read the archive with the command-line options -i -H ustar. The options -i -H tar refer to an older tar format. The changes are new in the Solaris 9 release.

Only super can copy special files.

Blocks are reported in 512-byte units.
If file has 000 permissions, contains more than 0 characters of data, and the user is not root, the file is not saved or restored.

The node number is stored in the header (/usr/include/archives.h) is an unsigned short, which is 2 bytes. This restriction limits the range of node numbers from 0 to 65535. Files that are hard-linked must fall in this range, which can be a problem when moving cpio archives between different vendors' machines.

When the Volume management daemon is running, access to diskettes through the device names (for example, /dev/rdiskette) may not succeed. See man(1) for further details.

You must use the same blocking factor when you retrieve or copy files from the hard disk as you did when you copied files from the hard disk to the tape. Therefore, you must specify the -B option.

# Options

# Options

- -i Copy in. Extract files from the standard input.
- -o Copy out. Read the standard input to obtain a list of path names and copy those files onto the standard output.
- -p Read the standard input to obtain a list of path names of files.

You can append the following options in any sequence to -o, -i, or -p option.

- @ Include extended attributes in archive. By default, cpio does not put extended attributes in the archive. With this option, cpio looks for extended attributes on the files to be placed in the archive and adds them, as regular files with special type. Using the -H option with -i or -p instructs cpio to restore extended attribute data along the normal file data. Attempts to extract attribute records are ignored. Extended file attributes are new in the Solaris 9 release.
- -a Access times of input files after they have been copied. Access times are not reset for linked files (mutually exclusive with -m).
- -A Append files to an archive. The -A option requires the -H option. Valid only with archives on hard disk partitions.
- -b Reverse the order of bytes within each word. (Use only with -i option.)
- -B Block input/output 512 bytes to the record. The default buffer size is 512 bytes when you do not use this and the -C option. -B does not apply to pass option; -B is meaningful only with data directed to or from a character device, for example, /dev/rmt.
- -c Read or write header information in ASCII form for portability. There are no UID or GID restrictions associated with this header. Use this option for SVR4-based machines, or -H unknown. The -c option implies the use of expanded device numbers, which are only supported on SVR4-based systems. When transferring files between Solaris 1.x or interactive UNIX, use -H unknown.
- -C bufsize Block input/output bufsize bytes to the record, where bufsize is replaced by a positive integer. The default buffer size is 512 bytes when you do not use this and the -B option. -C does not apply to pass option;-C is meaningful only with data directed to or from a character device, for example, /dev/rmt.
- -d Create directories as needed.
- -E Specify an input file (file) that contains a list of file names to be extracted from the archive (one file per line).

- -f Copy in all files except those in patterns.
- -H header Read or write header information in format. Always use this option or the -c option when the origin and the destination machines are different (mutually exclusive with -f). Available header formats are listed below.
- -bar Bar format. Use only with -i option (read only).
- -crc ASCII header with expanded device numbers and an additional checksum per file. No UID or GID restrictions are associated with this header format.
- -od ASCII header with small device numbers. This is the IEEE/1003 Data Interchange Standard cpio header and format. It has the widest range of portability of any of the header formats. It is the official format for transferring files between POSIX-forming systems (see standards(5)). Use this format to communicate with Solaris 1.x and interactive UNIX. This header enables UIDs and GIDs up to 2^31 to be stored in the header.
- -tar tar header and format. This header enables UIDs and GIDs up to 209715 to be stored in the header.
- -ustar IEEE/1003 Data Interchange Standard tar header and format. This header enables UIDs and GIDs up to 209715 to be stored in the header.

Files with UIDs and GIDs greater than the limit stated above are archived with the UID and GID of 0.

To transfer a file (greater than 8 GB), the header format can be tar | TAR, ustar | USTAR, or odc.

- -file Read the contents of files as an input archive. If file is a character special device and the current medium has been completely read, you should replace the medium and press Return to continue the next medium. Use this option only with the -i option.
- -k Try to skip corrupted file headers and I/O errors that may be encountered. If you want to copy files from a medium that is corrupted or out of sequence, this option lets you read only those files with good headers. (For cpio archives that contain other cpio archives, if an error is encountered, cpio may terminate prematurely, find the next good header, which may be one for a smaller archive, and terminates when the smaller archive's trailer is encountered.) Use only with the -i option

- - Whenever possible, link files instead of copying them. (Use only with the -p option).
- -L Follow symbolic links. The default is not to follow symbolic links.
- -m Retain previous file modification time. This option is effective on directories that are being copied (mutually exclusive with -a).
- -message Define a message to use when switching medium. When you use the -O or -I options and specify a character device, you can use this option to define the message that is printed when you reach the end of the medium. You can put one %d in message to print the sequence number of the next medium needed to continue.
- -O file Direct the output of cpio to file. If the file is full, you should replace the medium and press Return to continue the next medium. Use only with the -o option.
- -P Preserve access control lists (ACLs). If the option is for output, writing ACLs with other attributes to the standard output. ACLs are created as special files with a special type. The option is used for output, extract ACLs with other attributes from standard input. The option recognizes that errors occur if a cpio archive with ACLs is extracted by previous versions of cpio. Do not use this with the -c option because ACL support may not be present on all systems and hence is not portable. Use ASCII headers for portability.
- -r Interactively rename files. Use a Return to skip the file and a dot (.) to retain the original path name. (Not available with cpio -p).
- -R id Reassign ownership and group information for each file to user ID (ID must be a valid login ID from //passwd), This option is valid only for the superuser.
- -s Swap bytes within half-word.
- -v Swap halves within each word.
- -t Print a table of contents of the input. No files are created (mutually exclusive with -V).
- -u Copy unconditionally (normally, an older file does not replace a newer file with the same name).
- -v Print a list of file names. When you use the verbose option, the table of contents looks like the output of ls -1 command.
- -V Print a dot for each file read or written. This special verbose option is useful to assure you are working without printing out all file names.
- -6 Process a UNIX System Sixth Edition archive format file. Use only with the -i option (mutually exclusive with -c and -H).
