# Event Callbacks

Starting in the Solaris 9 release, the ::evset dmcmd and event tracing dmcmds enable you
to associate an callback (with the -c option) with each event specifier. The event
callbacks are strings that represent mdb commands to execute when the corresponding
event occurs in the target. These commands are executed if they have been typed by
t command prompt. Before each callback is executed, the dot variable is set to the
value of the representative target's program counter and the hits variable is set to
number of times this specifier has matched, including the current match.
If the event callbacks contain one or more commands to continue the
target (for example, :cont or :step), these commands do not immediately continue
target and wait for it to stop. Inside, the event callback, the continue
dmd notes that a continue operation is now pending and return immediately.
Therefore, if multiple demcds are included in an event callback, the step or continue
dmd should be the last command specified. Following the execution of all event
callbacks, the target resumes execution if matching event callbacks
requested a continue. Conflicting continue operations requested, the operation with
the highest precedence determines which type of continue. The order of
precedence from highest to lowest is step, step-over(next), step-out, continue.

# Thread Support

Starting in the Solaris 9 release, mdb provides facilities to examine the stacks and
registers of each thread associated with the target. The persistent thread variable
contains the representative thread identifier. The format of the thread identifier
dends on the target. You can use the :regs and :fregs commands to examine the
register set of the representative thread or another thread if its register is
currently available. In addition, the register set of the representative thread is exported
as a set of named variables. You can modify the value of one or more registers by
applying the demd to the corresponding named name.

The mdb kernel exports the virtual address of the corresponding internal
thread structure for a given identifier. The Solaris Modular Debugger
Guide provides more information on debugging support for threads in the Solaris
kernel. The mdb process target provides support for examination of
ithreaded processes that use the native lwp_,
/usr/lib/libthread.so or /usr/lib/libthread.so. When debugging a live user
process, mdb detects when a single-threaded process opens or chooses libthread and
automatically adjusts its view of the threading model on-the-fly. The process target
thread identifiers correspond to either the lwpid_thread_t, or pthread_t of
resentative thread, depending on the threading model used by the application.
