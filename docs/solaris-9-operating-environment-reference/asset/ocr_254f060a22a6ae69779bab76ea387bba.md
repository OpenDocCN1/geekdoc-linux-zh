# vi, view, edit

set options such as automatically numbering lines and automatically starting a new
output line when you press Return.

When using vi, changes you make to the file are reflected in what you see on
terminal screen. The position of the cursor on the screen indicates the position within
the file.

The view invocation is the same as vi except that the read-only flag is set.
The view invocation is intended for beginners. It is the same as vi except that the
report flag is set to i, the showmode and novice flags are set, and magic is turned off.
These preset defaults make it easier to learn vi.

# Notes

Tampering with entries in /usr/share/lib/terminfo/?*/ or
/usr/lib/terminfo/?* (for example, changing or removing an entry)
affect programs as vi that expect the entry to be present and correct. In particular,
removing the dumb terminal may may cause unexpected problems.

Software Tabs work only after an autodient.
Left and right shifts on intelligent terminals do not make use of insert and delete
character operations in the terminal.

The standard Solaris version of vi will be replaced by the POSIX 2-conforming
version (see standards5) in the future. Scripts that use the exe file of addressing and
features should use /usr/xp4/bin version of these commands.

# Options

+   -S Suppress all interactive user feedback. This option is useful when
processing editor scripts.
-C Same as the -x option simulate the C command of ex. The C
command is the x command of ex, except that all text read in
assumed to have been encrypted.
-1 Set up for editing LISP programs.
-L List the name of all files saved as the result of an editor or system
crash.
-r filename filename after an editor or system crash. (Recover the version of
filename that was in the buffer when the crash occurred.) The file
too large to recover with -r option message that you may see
when you load a file indicates that the file can be edited and saved
successfully, but if the editing session is lost, the file is not
possible with the -r option.
-R Set the read-only flag to prevent accidental overwriting of the file.
-S Use in conjunction with the -t caption to tell vi not to sort the tags
file. If the binary search (which relies on a sorted tag for tag fails
to find it, do a much slower, linear search. Because the linear search is
slow, for large files, ensure that the tags files are sorted instead of
using this option. Creation of tags normally produces sorted tags
files. See ctypes(1) for more information on tags files.
-t tag Edit the file containing tag, and position the editor at its definition.
