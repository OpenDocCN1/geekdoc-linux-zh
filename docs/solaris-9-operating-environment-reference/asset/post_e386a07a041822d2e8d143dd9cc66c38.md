
## Appending Text

If you start with an empty file or want to add some new lines, use the append(a) command. After you execute this command (pressing a Return after the word append), edit reads lines from your terminal until you a line consisting of just a dot (.), edit places these lines after the current line. The last line you type then becomes the current line.

The insert(i) command is like append but places the lines you type before, instead of after, the current line.

## Changing Text

You can make a change to some text within the current line by using the substitute(s) command: old/new, where old is the string of characters you want to replace and new is the string of characters you want to replace old with.

The filename command tells you how many lines are in the buffer you are editing and displays [Modified] if you have changed the buffer.

By using the d and a commands giving line numbers to see lines in the file, you can make any changes you want. You should learn at least a few things more, however, if you use edit more than a few times.

The change(c) command changes the current line to a sequence of lines you supply (as in append, you type lines up to a line consisting of only a dot (.). You can tell edit to change more than one line by giving the line numbers of the lines you want to change, for example, 3,5c.

## Saving and Quitting the Editor

After modifying a file, you can save the contents of the file by executing a w(q) command. If you run edit on a file but not change the file, you need not (it does no harm) write the file back. If you try to quit edit after modifying the buffer without writing it out, you receive the message No write since last change (:quit: overrides), and edit waits for another command. If you do not want to write the buffer, issue the quit command and it is irrevocably discarded, the shell returns followed by an exclamation point (q!).

The undo(u) command reverses the effect of the last command you executed that changed the buffer. Thus, if you execute a substitute command that does not do what you want, type u and the old contents of the line are restored. You can also undo an undo command. edit warns when a command affects more than one line of the buffer. Note that you cannot undo commands as write and quit.

## Displaying Lines in the Buffer

edit provides the current line number by typing different commands that enable you to display what's in the buffer.

- Use the current line number by typing. =
- Use the print command to display a set of line numbers: 1,23p prints the first 23 lines of the file, 1sp prints the complete file, and .sp prints the current line plus the rest of the lines in the file.
- Use the (nu) command to display the contents of the buffer with line numbers. You can find the number of the current line (nu), a range of lines (for example, 5,10nu displays numbered lines 5 through 10), or all of the lines in the file (1,$pnu).
- To look at the next line in the buffer, press Return.

To look at a number of lines, enter Control-D (while holding down the Control key, press the d key) instead of Return. This key sequence shows you a half-screen of lines on a CRT or 12 lines on a hard terminal. You can look at nearly text by executing the z command. The current line is displayed in the middle of the text displayed, and the last line displayed you get back to the line you were before you executed the z command by typing '.'. The z command has other options: z- prints a screen of (or 24 lines) ending where you are; z+ prints the next screen. If you want a less screen of lines, z-11 displays lines before and five after the current line. (Typing z-n when n is an odd number, displays a total of n lines, centered around the current line; when n is an even number, it displays n lines, so that the lines are centered around the current line.) You can give counts after other commands; for example, with the command d5 you can delete 5 lines with the current line.

You can also do arithmetic with lines. Thus, the line -5 is the fifth before the last and +20 is 20 lines after the current line.

> Note - edit has a vi mode that enables you to view the contents of the file as you edit. For more information on the vi mode, see ex(1).

## Finding Text

To find things in the file, you can use line numbers. You can also search backward and forward in the file for strings by using the commands of form /text/ to search forward for text or ?text to search backward for text. If a search reaches the end of the file without finding it, it wraps and continues to search back to the line where you are. A useful feature is to search for a search of form /text which searches for text at the beginning of a line. Similarly, /texts/ searches for text at the end of a line. You can omit the trailing / in these commands

## Copying or Moving Text

You can copy or move text within the file by using the copy(c) or move(m) commands. You specify the line or range of lines you want to move, followed by the command and then the line after which you want the text to be placed. For example, the command 5,10c 20 makes a copy of 5 lines through 10 and inserts it into line 20 in the buffer. The symbolic dot (.) syntax, which represents the current line, is most useful in a range of lines. To move the line in the file, you can refer to it by its symbolic name s. Thus, the command dd deletes the line in the file, no matter what the current line is, and the command 10,20m moves 10 lines through 20 to the end of the file.

## Using the Internal Buffers

The edit command has 26 internal buffers, named a through z, that you can use as temporary clipboards for copying or moving text from one file to another. Before you begin your copy or move, find the first and last line numbers you want to copy or move. For example, move lines 10 through 20, type 10,20a and press Return. The lines are deleted from the file and put into a buffer named a. To put the contents of a buffer after the current line, type put and press Return. If you want to copy these lines to another file, first copy the yank (y) command, then type filename and press Return, where filename is the name of the other file you want to edit, for example, chapter.2.

Note — The contents of the a z buffers are not preserved if you exit edit. When you use the e or q commands, edit does not warn you when these buffers contain text.

The /usr/xpg4/bin/edit command is identical to /usr/bin/edit.

## Options

You can turn the following options on or off by using the set command in ex(1).

- -s Suppress all interactive user feedback. This option is useful when processing editor scripts.
- -C Simulate the C command of ex, which assumes that all text read has been encrypted.
- +command -command Beginning editing by executing the specified editor command (usually a search or positioning command).
- -1 Set up for LISP programs.
- -L List the names of all files saved as the result of an editor or system crash.
- -R Set the read-only flag to prevent accidental overwriting of the file.
- -r filename Recover the version of filename that was in the buffer when a system crash occurred.
- -t tag Edit the file containing tag, and position the editor at its definition.
- -V Start up in displaying-edit state using vi. You can achieve the same effect by simply typing the vi command.
- - Verbose. When commands are read by means of standard input, the input is echoed to standard error. This option is useful for processing commands within shell scripts.
- -wn Set the default window size to n. This option is useful when you are using the editor over a slow-speed line.
- -x Simulate the encryption command of ex, and prompt for a key. This key encrypts and decrypts text, using the algorithm of the crypt command. The command makes an educated guess to determine whether text read is encrypted or not. The temporary buffer file is encrypted also, using a transformed version of the key typed in for the -x option. Note that the encryption options are provided with the Security Administration Utilities package, which is available only in the United States.

The filename argument indicates one or more files to be edited.
