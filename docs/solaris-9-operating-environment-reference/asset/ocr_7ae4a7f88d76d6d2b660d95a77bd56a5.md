# Manual Page Command Syntax

Unless otherwise noted, commands described in the Synopsis section of a manual page accept options and other arguments according to the following syntax and should be interpreted as explained below.

```
name [-option...] [cmarg...]
where Surround an option or cmarg that is not required.
```

+   - [] Indicate multiple occurrences of the option or cmarg.
- name Specify the name of an executable file.
- {} Indicate independent options and/or arguments, so that everything is enclosed as a unit.

+   option Always preceded by a dash (-) noargletter or argletter
optarg(...),

+   noargletter A single letter represents an option without an option-argument. Note that you can group more than one noargletter option after one dash (-) (Rule 5, below).

+   argletter A single letter represents an argument that requires an option-argument. An option-argument (character string) that satisfies a preceding argletter: Note that groups of optargs following an argletter must be separated by commas or separated by a Tab or space character and quoted (Rule 8, below).

+   cmarg Specify a path (or other command argument) not beginning with a dash (-) - or by itself, indicating the standard input.

# Command Syntax Standard: Rules

These command syntax rules are not followed by all current commands, but all new commands obey them. All procedures should use getopts(1) to parse parameters and to check for legal options. getopts supports Rules 3–10 below. The enforcement of the other rules must be done by the command itself.

+   1. Command names (name) must be between two and nine characters long.
2. Command names must include only lowercase letters and digits.
