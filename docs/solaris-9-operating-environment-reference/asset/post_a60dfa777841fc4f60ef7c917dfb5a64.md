
# Message Text Source File Format

The format of a message text source file is described below.

> Note - The fields of a message text source line are separated by a single ASCII space or Tab character. Any other ASCII spaces or Tabs are considered as part of the subsequent field.

```
$set n comment
```

Specify a set identifier, where n specifies the set identifier of the following messages until the next $set, $delset, or end-of-file. n must be a number in the range (1-NL_SETMAX). Identifiers within a single source file need not be contiguous. Treat any string following the set identifier as a comment. If you specify no $set directive in a message text source file, locate all messages in the default message set NL_SETD.

```
$del n comment
```

Delete set n from an existing message catalog. Treat any string following the set number as a comment. (Note: if n is not a valid set, it is ignored.)

```
$ comment
```

Treat a line beginning with a dollar $ followed by an ASCII space or Tab character as a comment.

```
m message-text
```

The m denotes the message identifier, a number in the range (1-NL_MSGMAX). Store message-text in the message catalog with the set identifier specified by the last $set directive and with message identifier m. If message-text is empty and an ASCII space or Tab separator is present, store an empty string in the message catalog. If a source line has a message number but neither a field separator nor message text, delete the existing message with that number (any) from the catalog. Message identifiers need not to be contiguous. The length of message-text must be in the range (0-NL_TEXTMAX).

```
$quote c
```

Specify an optional character c that can be used to surround message-text so trailing spaces or null (empty) messages are visible in a message source line. By default or if you specify any $quote directive, no quoting of message-text is recognized.

Empty lines in a message text source file are ignored.

Text strings can contain the special characters and escape sequences defined.

| Description | Symbol | Sequence |
| :--- | :--- | :--- |
| Newline | NL(LF) | \n |
| Horizontal tab | HT | \t |
| Vertical tab | VT | \v |
| Backspace | BS | \b |

The escape sequence \ddd consists of backslash followed by 1, 2, or 3 octal digits, which are taken to specify the value of the desired character. If the character following a backslash is not one of those, the backslash is ignored.

You can also use a backslash followed by an newline character to continue a string on the following line. Thus, the following two lines describe a single message:

+ 1 This line continues \
nto the next line

is equivalent to:

+ 1 This line continues to the next line

# geniconvtbl - Generate iconv Code Conversion Tables

# Synopsis

/bin/geniconvtbl [-fnq] [-o outputfile] [-p preprocessor] [-W arg] [-DName] [-Dname=def] [-Idirectory] [-lname] [-infile...]

# Description

The geniconvtbl command, new in the Solaris 8 Operating Environment, accepts code conversion rules defined in flat text file(s) and writes code conversion binary table file(s) that can be used to support user-defined iconv code conversions (see iconv(1) and iconv(3C)) for more detail on the iconv code conversion.

# Options

+ -f Overwrite output file if the output file exists.
-n Do not generate an output file. This option is useful to check the contents of the input file.
-o outfile Specify the name of the output file.
-p preprocessor Use specified preprocessor instead of the default preprocessor, /usr/lib/cpp.
-q Quiet suppress warning and error messages.
-W arg Pass the argument arg to the preprocessor. If you specify this more than once, pass all arguments to the preprocessor.

+ -DName
-Dname=def
-Idirectory
-Uname

Pass these options and own arguments to the preprocessor.

# Operands

+ -infile

A path name of an input file. If you specify no input file, geniconvtbl reads from the standard input stream. You can specify more than one input file.

# Output

Output is from the standard input stream, geniconvtbl writes output to the standard output stream. If you specify one or more input files, geniconvtbl reads from each input file and writes to a corresponding output file. Each of the output file names is the same as the corresponding input file with .bt appended.

You must move the generated output files to the following directory before using the iconv(1) and iconv(3C) code conversions.

/usr/lib/iconv/geniconvtbl/binaries/

Start the output file name with one or more ASCII characters as the fromcode name followed by a percent sign (%), followed by one or more ASCII characters as the tocode name, followed by the suffix .bt. The fromcode and tocode names are used to identify the iconv code conversion at iconv(1) and iconv_open(3C). Place the properly named output file in
/usr/lib/iconv/geniconvtbl/binaries/.

Note — The generated and correctly placed output files
/usr/lib/iconv/geniconvtbl/binaries/*.bt are used in both 32-bit and 64-bit environments.

# Examples

The following example uses the UTF-8_to_ISO88859-1.src example file in /usr/lib/iconv/geniconvtbl/srcs/ to generate the properly named binary version of the conversion.

```
$ cd /tmp
$ geniconvtbl -o UTF-8%ISO88859-1.bt
/usr/lib/iconv/geniconvtbl/srcs/UTF-8_to_ISO88859-1.src
$ 
```

The UTF-8%ISO88859-1.bt file is created in /tmp, which is the current directory. To use this binary table, copy it to /usr/lib/iconv/geniconvtbl/binaries/.

The following example generates two code-conversion binary tables with output files test1.bt and test2.bt.

The following example generates a code conversion binary table once the specified preprocessor has processed the input file.

```
example geniconvtbl -p /opt/sunw/bin/cc -W -E convertB2A
```

To use the binary table created in the first example as the engine of the conversion from ABC to DEF, become superuser and rename the output file and put it in the following directory.

```
example mv convert2B.bt
/usr/lib/iconv/geniconvtbl/binaries/ABC%DEF.bt
```

# genlayouttbl — Generate Layout Table for Complex Text Layout

# Synopsis

```
/bin/genlayouttbl [-o outfile] [infile]
```

# Description

The genlayouttbl command is new in the Solaris 8 Operating Environment. You can specify a locale's layout definition in a flat text file; the genlayouttbl command then writes a binary layout table file that can be used in the complex text layout of the locale.
