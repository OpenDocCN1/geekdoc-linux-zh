# chmod 143

permissions Any compatible combination of the following letters:

+   - l Mandatory locking.
- r Read permission.
- s User or group set-ID.
- t Sticky bit.
- u,g,o Take permission from the current user, group, or other mode.
- w Write permission.
- x Execute permission.
- X Execute permission if the file is a directory or if one of the other classes has execute permission. New in the Solaris 9

Permissions to a file can vary depending on your user identification number (UID) or group identification number (GID). The following example shows the access class for each group of permissions and themselves. It gives user, group, and others to read, write, and execute a given file.

User Group Other
rwx rwx rwx

The s is meaningful with u or g, and t works only with u.
Matory file and record locking refers to a file's ability to have reading or writing permissions while a program is accessing that file.
In a directory that the set-group-ID bit (reflected as either ---s--- or 1----) in the output is -1d), files and subdirectories are created with the ID of the parent directory, not that of current process.
You cannot permit group execution and enable a file to be locked on execution at the same time. In addition, you cannot turn on the set-group-ID bit and enable a file to be locked on execution at the same time. The following examples, therefore, are invalid and result in error messages.

```
chmod g+x, +1
chmod g+s, +1
```

Only the owner of a file or directory (or the superuser) can change the sticky bit on a nondirectory file. If you are not superuser, chmod masks the sticky bit but does not return an error. To turn on a file's set-group-ID bit, your own group ID must correspond to that of the file and group execution must be.

# Notes

Absolute changes do not work for the set-group-ID bit of a directory. You must use g+s or g-s permits you to produce useless modes as long as they are not illegal (for instance, making a file executable). chmod does not check the file type to see if mandatory locking is meaningful.

If the file system is mounted with the nosuid option, setuid(2) execution is not allowed.
