Archives encrypted with 8-bit passwords (for example, passwords with accented European characters) may not be portable across systems and/or other archives. The problem stems from the use of multiple encoding methods for such characters, including Latin-1 (ISO 8859-1) and OEM code page. PKZIP 2.0g uses the OEM code for Windows; PKZIP 2.5 uses Latin (and is therefore incompatible with DOS ZIP); Info-ZIP uses the OEM code on DOS, and Win3 ports Latin everywhere; and Nick Mac's Unix 6.x does not offer 8-bit passwords at all. Unzip 5.3 tries to use the default Latin-1 character set first, by the alternative (OEM code page) to test passwords. On EBCDIC systems, if EBCDIC encoding is tested as a last resort (Because there are no known archives that encrypt using EBCDIC encoding, EBCDIC is not tested on non-EBCDIC systems). ISO encodings other than Latin-1 are not supported.

# Bugs

Multipart archives are not yet supported, in conjunction with zip. To fix concatenate archives in order and then unzip -F on the concatenated archive. This problem will definitely be corrected in the next release.

Archives read from standard input are not yet supported, except with funzip, and then you extract only the first item in the archive.

Archives encrypted with 8-bit passwords (that is, passwords with accented European characters) may not be portable across systems and/or other archives. Times of stored directories are not restricted under unzip.

Dates, times and permissions

[MS-DOS] When extracting or testing files from an archive on a diskette, if you choose the Fail from the DOS abort. Retry. Fail? Older versions of unzip may hang the system, or reboot. This problem appears to be fixed. You can use Control-C (Control-Break) to terminate unzip.

Under DEC, unzip fails on long files (bad CRC, not always reproducible). This problem was apparently because of either a hardware (cache memory) or an operating system (improper handling of page faults?). Ultra was abandoned in Digital UNIX (OSF/1), which may no longer be an issue.

UNIX special files as FIFO buffers (pipes), block devices, and character devices are not restored if they are somehow represented in the file, or hard-linked files relinked. The only file types restored by unzip are regular files, directories, and (soft) links.

[OS] Extended attributes for extracting are updated only if you specify the -overwrite (all) option. This is a limitation of the operating system; because only attributes have a creation time associated with them, unzip has no way to determine whether the stored attributes are newer or older than those. In practice, you may need to take a two-phase approach: first unpack the archive normally (with without refreshing/updating files), then overwrite the directory entries (for example, unzip -o foo *).

[VMS] When extracting to another directory, the [ f ] syntax is accepted for the -d option; the unique Unix foo syntax is silently ignored (as is the less common VMS foo.dir syntax).

[VMS] When the file being extracted already exists, unzip queries only skipping, overwriting, or renaming. The overwrite creates a new version of the file; the old version is not overwritten or deleted.
