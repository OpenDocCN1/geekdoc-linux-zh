# arch — Display the Architecture of the Current Host

# Synopsis

/usr/bin/arch [-k | archname]

# Description

Systems can be broadly classified by their architectures, which define what executables run on which machines. You can make a distinction between kernel architecture and application architecture (or, commonly, just architecture). Systems that run different kernels because of underlying hardware differences may be able to run the same programs.

arch displays the application architecture of the current host system. Because of extensive use of this command without any options, all SunOS 5.x SPARC-based systems return sun4 as their application architecture.

This command is provided for compatibility with previous releases and its use is discouraged. Instead, use the uname(1) command. See uname for usage information.

# Options

-   -k
Display the kernel architecture, such as sun4m, sun4c, and so forth. This option defines which specific SunOS kernel runs on the system and has implications only for programs such as ps(1) that depend on a specific kernel architecture.

# Operands

-   archname
Use archname to determine whether the application binaries for this architecture can run on the current host system. The archname must be a valid application architecture, such as sun4, i86pc, and so forth. If application binaries for archname can run on the current host system, return true (0); otherwise, return false (1).

# Examples

The following example shows the value arch command returns on a SPARCstation 10.

```
castle$ arch
sun4
castle$ 
```

# Description

The command creates objects from assembly language source files.

> Note — If you use the -m m4(1) (macro processor) option, you cannot use keywords for m4(1) as symbols (variables, functions, labels) are in the input file because m4(1) cannot determine which keywords are assembler symbols and which keywords are real m4(1) macros.

Whenever possible, access the assembler through a compilation system interface such as cc(1).
All undefined symbols are treated as global.

# Options

The following options for the as command common to both SPARC and IA. You can specify the options in any order.

# as

-   -b
Generate extra symbol table information for the Sun Source Browser.

-   -Dname
When the -P option is in effect, pass these options to the cpp(1)
preprocessor without interpretation by the as command; otherwise,
ignore them.

-   -Ipath
When the -P option is in effect, pass this option to the cpp(1) C
preprocessor without interpretation by the as command; otherwise,
ignore it.

-   -K PIC
Generate position-independent code.

-   -L
Save all symbols in the ELF symbol table, including temporary labels
that are normally discarded to save space.

-   -m
Run the m(1) max processor on the input to the assembler.
-   n
Suppress all warnings while assembling.

-   -o output
Put the output of the assembly in outfile. By default, format the output
file name by removing the .s suffix, if there is one, from the input file
name and appending an .o suffix.

-   -P
Run cpp(1), the C preprocessor, on the files being assembled.
preprocessor is run separately on each input file, not on
concatenation. Pass the preprocessor output to the assembler.

-   Q y | n
If you specify the n option, produce the assembler version information
in the comment section of the object object file. If you specify the y
option, suppress the information.

-   -s
Place all st in the .stabs section. By default, put st in
stabs.ex sections, which are stripped out by the static linker, ld(1)
during final execution. When you use the -s option, st remain in the
final executable because .stabs sections are not stripped by the static
linker.

-   -S [ a | b | c | 1 | A | B | C | L]
Produce a disassembly of the emitted code to the standard output.
Adding each of the following characters to the -s option produces:

+   a\ Disassemble with address.
+b\ Disassemble with .bof.
+c\ Disassemble with comments.
+   1\ Disassemble with line numbers.

-   -T
Capital letters turn the switch off for the corresponding option.
Interpret symbol names in 4.x assembly files as 5.x symbol names. This
option is for 4.x assembly files to be assembled on 5.x systems.

-   -Uname
When the -P option is in effect, pass this option to the cpp(1)
preprocessor without interpretation by the as command; otherwise,
ignore it.

-   -V Write the version number of the assembler being run on the standard error output.

-   -XF Generate additional information for performance analysis of the executable, using SunShop analyzer. If the input file does not contain any stabs (debugging directives), then the assembler generates some default faults that are needed by the SunWork analyzer. Also, see the dbx manual page available with SunWork.
