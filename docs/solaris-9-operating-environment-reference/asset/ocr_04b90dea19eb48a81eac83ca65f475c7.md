For example, a table cannot grant access to a client performing an nis_list(3NSL) operation on the table. However, the access fields of entries within that table can grant read access to the client. Note that access rights in an entry are granted to the owner or group owner of the entry and not the owner or group of the table. When the list operation is performed, all entries to which the client has read access are not returned. Those entries that do not grant read access the search criteria grant access to the client making the request, no entries are returned and the result status NIS_NOTFOUND error code.

Access rights are granted by the fields in an entry are granted for the entry. However, in the table object, an additional set of access rights is maintained for each column in the table. These rights apply to the equivalent column in the entry. The rights are used to grant access when neither the owner nor the entry grants access. The access rights in a column specification apply to the owner or group owner of the entry instead of the owner and group owner of the table object.

When a read operation is performed, if read access is not granted by the table and is not granted by the entry but is granted by access in columns, that entry is returned with the correct values in columns and the string *NP in columns where read access is not granted.

Each entry object that satisfied the search criteria by the client is examined to see if it grants read access to the client. If it does, it is included in the returned result. If it does not, then each column is checked to see if it grants read access to the client. If any columns grant read access data in columns are returned. Those that do not grant read access have their contents replaced by the string *NP. If none of the columns grant read access, then the entry is not returned.

# Protocol Operation Authorization

NIS+ operations have implied access control through the permissions on the objects that they manipulate. For example, to read an entry in a table, you must read permission on that entry. However, NIS+ operations by default perform no access checking at all and so are allowed for everyone.
