# ctags — Create a Tags File for Use with ex and vi

# Synopsis

```
/usr/bin/ctags [-aBFtuvwx] [-f tagsfile] file...
/usr/xpg4/bin/ctags [-aBFuvvwx] [-f tagsfile] file...
```

# Description

The ctags command makes a tags file for ex(1) from the specified C, C++, Pascal, FORTRAN, yacc(1), and lex(1) sources. A tags file gives the locations of specified objects (in this case, functions and typeddefs) in a group of files. Each line of the tags file contains the object name, in the file in which it is defined, and an address specification for the object definition. Functions are searched with a pattern, typeddefs with a line number are searched in separate fields in separated by space or Tab characters. Using the tags file, ex can quickly find these object definitions.

Normally, ctags places the tag descriptions in a called tags file; you can override this default by using -f option.

Files with names ending in .c or .cc are assumed to be either C or C++ source files and are searched for C/C++ routine and macro definitions. Files with names ending in .cc, .C or .cxx are assumed to be C++ source files. Files with names ending in .y are assumed to be yacc files. Others are first examined to see if they contain any Pascal or FORTRAN routine definitions; if not, they are processed again, looking for C definitions.

The main tag is specially treated in C or C++ programs. The tag is formed by prepending M to file, with a trailing .c, .cc, .c or .c removed, if any, and leading path-name components also removed. This behavior makes use of ctags practical in directories with more than one program.

# Options

When printing, specify first -x and -v options, then the remaining options.

+   -a Append out to an an existing tags file.

+   -B Use backward searching patterns (...?).

+   -f tagsfile Place the tag descriptions in a called tagsfileinstead of tags.

+   -F Use forward searching patterns (/.../...) (default).

+   -t Create tags for typeddefs./usr/xpg4/bin/ctags creates tags for typeddefs by default.

+   -u Update the specified files in tags, that is, delete all references to them, and append the new values to the file. Because: This option is implemented in a way that is rather slow; it is usually faster to rebuild the tags file.

+   -v Produce on the standard output an index listing the function name, file name, and page number (assuming 64-line pages). Because the output is sorted into lexicographic order, you may want to run the output through -f.

+   -w Suppress warnings diagnostics.
