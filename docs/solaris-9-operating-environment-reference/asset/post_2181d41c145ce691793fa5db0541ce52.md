The exstr command cannot replace strings in all instances. For example, a static initialized character string cannot be replaced by a function call. A second example is that a string could be in the form of an escape sequence that could not be translated. To not break code, you must examine the files created by invoking exstr and delete lines containing strings not replaceable by function calls. In some cases, the code may require modifications so that strings are extracted and replaced by calls to the message retrieval function.

## Options

Extract a list of strings from the named C-language source files, with positional information. This list is produced on standard output in the following format:

```
file:line:position:msgfile:msgnum:string
file The name of a C-language source file.
line Line number in the file.
position Character position in the line.
msgfile Null.
msgnum Null.
string The extracted text string.
```

Normally, you redirect this output into a file. Then, you edit this file to add the values you want to use for msgfile and msgnum.

The file contains the text strings that replace string. A file with this name must be created and installed in the appropriate place by mkmsgs(1) command.

The next step is to use exstr -r to replace strings in file. 

Replace strings in a C-language source file with the message retrieval function gettxt().

Use with the -r option. If the message retrieval fails when gettxt() is invoked at runtime, the extracted string is printed. You use the capability provided by exstr on an application program that needs to run in an international environment and have messages print in more than one language. exstr replaces text strings with function calls that point at strings in a message database. The database depends on the runtime value of the LC_MESSAGES variable (see environ(5)).

# factor — Obtain the Prime Factors of a Number

## Synopsis

```
/usr/bin/factor [integer]
```

## Description

factor writes to standard input all prime factors for any positive integer of fewer than 15 digits. The prime factors are written the proper number of times.

If you type factor without an argument, it waits for you to type an integer and press Return. After you enter the integer, factor factors it, it writes its prime factors the proper number of times, and then waits for another integer. factor exits if you enter a 0 or any nonnumeric character.

If you invoke factor with an argument (integer), it writes the integer, factors it, writes all the prime factors as described above, and then exits. If the argument is 0 or nonnumeric, factor writes a 0 and then exits.

The maximum time to factor an integer is proportional to sqrt(n), where n is the integer that you enter. factor takes this time when n is prime or the square of a prime.

## Operands

- * integer Any positive integer less than 15 digits.

## Examples

The following example enters a number of 15 digits, and factor displays the Ouch! error message. It then factors a number of 14 digits. Type q and press Return to quit factor.

```
castle% factor
123456789012345
Ouch!
12345678901234
2
7
73
12079920647
```

q
castle%
```

- 0 Successful completion.
- 1 An error occurred.
```

# fdformat - Format Diskette or PCIA Memory Card

## Synopsis

```
/usr/bin/fdformat [-d -b -t nec -tM] [devname]
```

## Description

Starting with the 8 release, fdformat has been superseded by rmformat(1), which provides most but not all fdformat functionality.

Use the fdformat command to format the diskette. You must format all blank diskettes or PCIA memory cards before you use them. fdformat formats and verifies the media and indicates whether it encountered bad sectors. If you specify no device name, fdformat uses the diskette as a default.

By default, fdformat uses the configured capacity of the drive. 3.5-inch, high-density drive uses diskettes with a formatted capacity of 1.44 megabytes. 5.25-inch, high-density drive uses diskettes with a formatted capacity of 1.2 megabytes. In either case, you do not need to specify a density when using a diskette with a lower capacity than that of the drive. Use the -H option to format high-density (1.44-megabyte capacity) in an extra-high-density (ED) drive. To format medium-density diskettes (1.2-megabyte capacity), use the -m option with -t nec (this is the same as using the -m option with -t).

Extended density uses double-sided, extended-density (or extra-high) (DS/ED) diskettes. Medium and high densities use the same media: double-sided, high-density (DS/HD) diskettes. Low density uses the media: double-sided, double-density (DS/DD) diskettes.

Note — Substituting one density for diskettes of either higher or lower density does not work. Data integrity is assured whenever a diskette is formatted to a capacity matching its density.

You can use the fdformat command to format a PCMCIA memory card with densities from 512-kilobytes to 64-megabytes.

fdformat writes new identification and data fields for each sector on all tracks you specify the -x option. For diskettes, if you specify the -v option, each sector is verified.

After formatting and verifying, fdformat writes an operating-system label on block 0. Use the -t option (same as the -d option) to put an MS-DOS file system on the diskette or PCIA memory card after the format is. Use the -t nec option with the -M option (same as the -m option) to put an NEC-DOS file system on a diskette. Otherwise, fdformat writes a SunOS label in block 0.
