# grep — Search a File for a Pattern

# Synopsis

```
/usr/bin/grep [-bchilnsw] limited-regular-expression [filename...]
/usr/xpg4/bin/grep [-E -F] [-c | -l | -q] [-bhinsvx] -e pattern-list
[-f pattern-file]... [file...]
/usr/xpg4/bin/grep [-E -F] [-c | -l | -q] [-bhinsvx]
[-e pattern-list -f pattern-file [file...]
/usr/xpg4/bin/grep [-E -F] [-c | -l | -q] [-bhinsvx] pattern
[file...]
```

The grep command searches for a pattern in one or more files and prints all lines that contain that pattern. grep (which stands for global regular expression and print) uses a compact, nondeterministic algorithm.

> Note — Be careful using the characters $, *, [, ^, |, (, ), and \ in the pattern-list because they are also meaningful to the shell. It is safest to enclose the entire line in single quotes '...'.

If you specify no files, grep assumes standard input. Normally, each line found is copied to standard output. The file name is printed after each line if there is more than one input file.

# /usr/bin/grep

The /usr/bin/grep command uses limited regular expressions like those described on the regex(5) manual page.

Lines are limited only by the size of the virtual memory. For a line with embedded null, grep matches only to the first null; if it matches, grep prints the entire line.

# /usr/xpg4/bin/grep

The /usr/xpg4/bin/grep is a POSIX-compliant variant of the /usr/bin/grep command. See standards(5).

The options -E and -F affect the way /usr/xpg4/bin/grep interprets pattern-list. If you specify -E, /usr/xpg4/bin/grep interprets pattern-list as a full regular expression. If you specify -F, grep interprets pattern-list as a fixed string. If you specify neither, grep interprets pattern-list as a basic regular expression, as described in regex(5) manual page.

The results are unspecified if input file contains lines longer than LINE_MAX bytes or contain binary data. LINE_MAX is defined in /usr/include/limits.a.

# Options

The following options are supported for both /usr/bin/grep and /usr/xpg4/bin/grep.

- -b Precede each line by the block number on which it was found. This option can be useful in locating blocks by context (first block is 0).

- -c Print a count of only the lines that contain the pattern.

- -h Prevent the name of the file containing the matching line from being appended to that line. Used when searching multiple files.

- -i Ignore upper-/lowercase distinction during comparisons.

- -l Print the names of files only with matching lines, separated by newline characters. Do not repeat the names of files when the pattern is found more than once.

- -n Precede each line by its line number in the file (first line is 1).

- -s Suppress error messages about nonexistent or unreadable files.

- -v Print all lines except those that contain the pattern.

- -w Search for the expression as a word surrounded by \< and \>.

The following options are supported for /usr/xpg4/bin/grep.

- -e pattern-list Specify one or more patterns to be used during the search for input. Separate patterns in pattern-list by a newline character. You can specify a pattern with two adjacent newline characters in pattern-list. Unless you specify the -E -F option, treat each pattern as a basic regular expression. grep accepts multiple -e and -f options. All of the specified patterns are used when matching lines, but the order of evaluation is not specified.

- -E Match, using full regular expressions. Treat each pattern specified as a full regular expression. If any entire full regular expression pattern matches an input line, the line is matched. A null regular expression matches every line. Interpret each pattern as a full regular expression as described in the regex(5) manual page, except for (\ and \):

- * A full regular expression followed by + matches one or more occurrences of the full regular expression.

- * A full regular expression followed by ? matches 0 or 1 occurrence of the full regular expression.

- * Full regular expressions, separated by | or by a newline, strings that matched by any of the expressions.

- * A full regular expression that can be enclosed in () for grouping. The order of precedence of operators is [], then *, then concatenation, then newline.

- -f pattern-file Read one or more patterns from the file named pattern-file. Terminate patterns in pattern-file with a newline character. You can specify a pattern by an empty line in pattern-file. Unless you also specify the -E or -F option, treat each pattern as a basic expression.

- -F Match, using fixed strings. Treat each pattern specified as a string instead of regular expression. If an input line contains any of the patterns as a contiguous sequence of bytes, match the line. See grep(1) for more information.

- -q Do not write anything to the standard output, regardless of matching lines. Exit with 0 status if input line is selected.

- -x Consider only input lines that use all characters in the line to match an entire fixed string or regular expression.

# Usage

The -e pattern-list option has the effect as pattern-list operand but is useful when pattern-list begins with a hyphen. It is also useful when it is more convenient to provide multiple patterns as arguments. grep accepts multiple -e and -f options uses all of the patterns to match lines. The order of evaluation is not specified. If an implementation finds a null string as pattern, it is allowed to use that pattern first, and effectively ignore any other patterns. The -q option provides a means of determining whether or not pattern (or string) exists in group of files. When searching several files, it provides performance improvement (because grep can quit as soon as it finds the first match) and requires less care by the user in choosing the set of files. 

The following example finds all of the word POSIX in the manual page and displays the line with a line number preceding it. To save space, not all of the lines are shown in this example.

```
castle@/usr/bin/grep -n posix standards.5
7:standards, posix, POSIX, posix.1, POSIX.1, posix.2, POSIX.2, xnet, XNET, xnet4, XNET4, xpg, XPG, xpg3, XPG3, xpg4, XPG4, xpg2, standards
```

# Large File Behavior

See grep(5) for the description of behavior of grep when encountering files greater than or equal to 2GB.

# Examples

You can combine the grep command with other commands to find specific information. In the following example, the output of the env command is piped to grep to search for environment variables that contain the word HOME. As you can see, the search results also include longer words that contain the HOME string.

```
castle% env | grep HOME
OPENWINHOME=/usr/openwin
HOME=/export/home/wins
```

You can use the following commands to find all empty lines in the input.

```
castle% /usr/bin/grep ^
castle% /usr/bin/grep -v
```

Both of the following commands print all lines containing string abc or def or both.

```
castle% /usr/xpg4/bin/grep -E 'abc def'
castle% /usr/xpg4/bin/grep -F 'abc def'
```

Both of the following commands print all lines matching exactly abc or def.

```
castle% /usr/xpg4/bin/grep -E '^abc$ $def$'
castle% /usr/xpg4/bin/grep -x 'abc def'
```

You can use the grep command to search through several files to find a particular string. The following example uses the grep command to search all of the files in a directory for the string kookaburra.

```
castle% grep kookaburra *
kookaburra:Laugh, kookaburra, laugh
kookaburra:Laugh, kookaburra, laugh
kookaburra-1:Laugh, kookaburra, laugh
kookaburra-1:Laugh, kookaburra, laugh
kookaburra-2:Laugh, kookaburra, laugh
kookaburra-2:Laugh, kookaburra, laugh
kookaburra-3:Laugh, kookaburra, laugh
kookaburra-3:Laugh, kookaburra, laugh
kookaburra-3:Laugh, kookaburra, laugh
```
