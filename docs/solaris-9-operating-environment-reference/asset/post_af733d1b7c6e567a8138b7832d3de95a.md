on — Execute a Command on a Remote System, Using the Local Environment

# Synopsis

```
/usr/bin/on [-d] [-n] host command [argument] ...
```

# Description

Use the command to execute commands on another system in an environment similar to that invoking the program. All environment variables are passed through, and the current working directory is preserved. For the working directory to be preserved, the working file system must either be already mounted on the host or exported to it. Relative path names work only if they are within the current file system; absolute path names may cause problems.

The standard input is connected to the standard input of the remote command, and the standard output and the standard error from the remote command are sent to the corresponding files for the on command.

# Bugs

When the working directory is remote mounted over NFS, a Control-Z hangs the window. Root cannot use on.

# Options

- -i Remote echoing and special character processing. This option is needed for programs that expect to be talking to a terminal. All terminal modes and window size changes are propagated.
- -d Print debugging messages as work is being done.
- -n Get-end-of-line when on reads from the standard input instead of passing the standard input from the on program. For example, you need to use the -n option when running commands in the background with job control.

# optisa — Determine Which Variant Instruction Set Is Optimal

# Synopsis

```
/usr/bin/optisa instruction-set...
```

# Description

optisa prints the instruction set out of the ones specified in the command that performs best on this machine. Best is defined by the order in which instruction set names are returned by isalist(1). Possible values for `instruction-set` are given in isalist(5).

> Note — optisa is preferable to uname -p or uname -m in determining which several binary versions of a given program should be used on the machine.

# Examples

The following example displays thealist instruction set and then uses the optisa command to find the command that performs best on a SPARCstation 10.

```
castle% isalist
sparcv8-fsmuld sparcv7 sparc
castle% optisa sparcv8 sparcv8-fsmuld sparcv7 sparc
sparcv8
castle%
```

# pack, pcat, unpack — Compress and Expand Files

# Synopsis

- - /usr/bin/pack [-f] [- file...
- - /usr/bin/pcat file...
- - /usr/bin/unpack file...

# Description

# pack

The pack command stores the specified files in a compressed form. Wherever possible (and useful), each file is replaced by a packed file named z with the same access modes, modified dates, and owner as those of file.

The size of the input determine the amount of compression. Text files are typically reduced to 60–75 percent of their original size. Load modules, which show little compression. The packed versions are usually 90 percent of their size.

pack returns a value that is the number of files it failed to compress. No packing is done under the following conditions.

# pack, pcat, unpack

* The file is already packed.
* The file name has more than 14 bytes.
* The file has links.
* The file is a directory.
* The file cannot be opened.
* The file is empty.
* No disk storage are saved by packing.
* A named file.z already exists.
* The .z file cannot be created.

The file name must contain no more than 14 bytes to allow space to append the .z extension. You cannot compress directories.

# pcat

The pcat command on packed files in the same way that you use the cat(1) command on ordinary files. You cannot use pcat as a filter. Unpacked and written to the standard output.
pcat returns the number of files it was unable to unpack. Unpacking can fail in the following conditions.

* The file cannot be opened.
* The file is not output from the pack command.

# unpack

The unpack command expands files created by pack. For each file specified in the command, a search is made for a called file.z (or just file, if it ends in .z). If this file appears to be a packed file, it is replaced by its expanded version. The new file has the .z suffix stripped from its name and has the same access modes, modification dates, and owner as those of the packed file.
unpack returns a value that is the number of files it was unable to unpack. Unpacking can fail under the following conditions.

* The file cannot be opened.
* The file is not output from the pack command.
* A file with the unpacked name already exists.
* The unpacked file cannot be created.
* The file name (excluding the .z extension) has more than 14 bytes.

# Options

pack uses Huffman (minimum redundancy) codes on a byte-by-byte basis. With the -argument, set an internal flag that prints to standard output the number of times each byte is used, the relative frequency, and the code for the bytes. Additional use of - in place of files resets the internal flag.
