# nischmod — Change Access Rights on an NIS+ Object

# Synopsis

/usr/bin/nischmod [-AfLP] mode name...

# Description

Use the nischmod command to change the access rights (mode) of the NIS+ objects or entries specified by name to mode. Specify entries, using indexed names (see nismatch(1)). Only principals with modify access to an object can change its mode. mode has the following form.

rights [, rights]...

rights has the form:

[who] op permission [op permission]...

- who is a combination of the following identities.
  - n Nobody's permissions.
  - o Owner's permissions.
  - g Group's permissions.
  - w World's permissions.
  - a All or owg.

If you omit who, the default is a.

op is one of the following operators.

- + To grant the permission.
- - To revoke the permission.
- = To set the permissions explicitly.

permission is any combination of the following permissions.

- r Read.
- m Modify.
- c Create.
- d Destroy.

> > **Note** — Unlike the system chmod(1) command, the nischmod command does not accept an octal notation.

# Options

- -A Modify all entries in tables in the concatenation path that match the search criteria specified in name. This option implies the -P option.
- -f Force the operation, and fail silently if it does not succeed.
- -L Follow links, and change the permission of the linked object or entries instead of the permission of the link itself.
- -P Follow the concatenation path within a named table. This option is applicable only when either name is an indexed name or you specify the -L option and the named object is a link pointing to an entry.

# Examples

The following example gives everyone read access to an object (that is, access for owner, group, and all).

```
castle% nischmod a+r object
```

The following example denies create and modify privileges to group and unauthenticated clients (nobody).

```
castle% nischmod gm-cm object
```

The following example sets a complex set of permissions for an object.

```
castle% nischmod o-rmcd,g-rw,n=r object
```

The following example sets the permissions of an entry in the password table so that the group owner can modify them.

```
castle% nischmod g-m 'uid=55,passwd.org_dir'
```

The following example changes the permissions of a linked object.

```
castle% nischmod -L w+mr linkname
```

# nischown — Change the Owner of an NIS+ Object

# Synopsis

/usr/bin/nischown [-AfLP] owner name...

# Description

Use the nischown command to change the owner of the NIS+ objects or entries specified by owner name: Specify entries, using indexed names (see nismatch(1)). If owner is not a fully qualified NIS+ principal (see nisaddcred(1M)), the default domain (nisdefaults(1)) is appended to it.
The only restriction on changing an object's owner is that you must have modify permissions for the object.

> Note — If you are the current owner of an object and you change ownership, you may not be able to regain ownership unless you have modify access to the new object.

The NIS+ server checks the validity of the name before making the modification. The nischown command fails if the master NIS+ server is not running.

# Options

- -A Modify all entries in all tables in the concatenation path that match the search criteria specified in name. This option implies the -P option.
- -f Force the operation, and fail silently if it does not succeed.
- -L Follow, and change the owner of the linked object or entries instead of the owner of the link itself.
- -P Follow the concatenation path within a named table. This option is meaningful only when either name is an indexed name or you also specify the -L option and the named object is a link pointing to entries.

# Examples

The following two examples show how to change the owner of an object to a principal in a different domain and how to change it to a principal in the local domain.

```
castle@ nischown bob.remote.domain. object
castle@ nischown bob.domain object
```

The following example shows how to change the owner of an entry in the password table.

```
castle@ nischown bob.remote.domain. 'uid=55,passwd.org_dir'
```

The following example shows how to change the owner of an object referenced by a link.

```
castle@ nischown -L bob linkname
```

# nischtl — Change the Time-to-Live Value of an NIS+ Object

# Synopsis

nischtl [-AfLP] time name...

# Description

Use the nischtl command to change the time-to-live value (ttl) of the NIS+ objects or entries specified by name to time. Specify entries, using indexed names (see nismatch(1)).

The time-to-live value is used by caches to set the expiration time. When an object is read into the cache, this value is added to the current time, yielding the expiration time. The object can be returned from the cache while the current time is earlier than the expiration time. When the expiration time has been reached, the object is flushed from the cache.

You can specify the time-to-live in seconds or in days, hours, minutes. The latter format uses a suffix of d, h, m or s to identify the units of time. The command fails if the master NIS+ is not running.

> Note — Setting a high ttl value enables objects to persist in caches for a longer period and can improve performance. However, when an object changes, in the worst case, the number of seconds must pass before that change is visible to all clients. Setting a ttl of 0 does not cache the object at all.

A high ttl value is a week, a low is less than a minute. Password entries should have ttl values of about 12 hours (allowing one password change a day), entries in the RPC table can have ttl values of several weeks (this information is ever changing). Only directory and group objects are cached in this implementation.

# Options

- -A Modify all tables in the concatenation path that match the search criteria specified in name. This option implies the -P option.
- -f Force the operation, and fail silently if it does not succeed.
- -L Follow links, and change the time-to-live of the linked object or entries instead of the time-to-live of the link itself.
- -P Follow the concatenation path within a named table. This option makes sense only when either name is an indexed name or you also specify the -L option and the named object is a link pointing to entries.

# Examples

The following example changes the ttl of an object, using the seconds format and the days, hours, minutes, seconds format. The ttl of the second object is set to 1 day and 12 hours.

```
castle@ nischtl 184000 object
castle@ nischtl 1d12h object [uid=99],passwd.org_dir
```
