Next, make reads a default makefile that typically contains predefined macro
definitions, target entries for implicit rules, and additional rules such as the rule for
retrieving SCCS files. If present, make uses the file .rules in the current directory;
otherwise it reads the file /usr/share/lib/make/make.rules, which contains the
standard definitions and rules. Use the following directive in your local make.rules file

```
include /usr/share/lib/make/make.rules
```

Next, make reads variables from the environment (unless you specify the --
option), and treats them as defined macros. Because make uses the most recent
environment it encounters, a macro definition in the makefile normally overrides
environment variable of the same name. When you specify -e, however, environment
variables are read after all makefiles have been read. In that case, the environment
variables take precedence over the makefile.

Next, make reads any makefile you specify with -f one of makefile
described above, and then uses the file in the directory if it exists. If the
makefile contains a KEEP_STATE_FILE, then make reads the state file that
follows the target. For special target, See KEEP_STATE_FILE for details.

Next (after reading the environment if you specify -e), make reads in any macro
definitions supplied as command-arguments. Macro definitions override
macro definitions both in the makefile and the environment, but only for the make
command itself.

make exports environment variables, using the most recently defined value. Macro
definitions supplied on the command line are not normally exported unless the make is
al environment variable.

make does not export macros defined in the makefile. If an environment variable is set
and you define a macro with the same name as the command line, make exports its value
def the command line. Unless you specify -e, macro definitions within the
makefile take precedence over those imported from the environment.

The macros MAKEFLAGS, MAKE, SHELL, HOST_ARCH, HOST_MACH, and TARGET_MACH are
special cases. See "Special-Purpose Macros" on page 795 for details.

# Makefile Target Entries

A target has the following:

```
target... [dependency]... [command]... [command]
```

The first line contains the name of a target or a space-separated list of targets
terminated with a colon or double colon. A list of targets is equivalent to having a
entry of the same form for each target. The colons: can be followed by
d dependency or a dependency list. make checks this before building the target. You
terminate the dependency list with a semicolon;, which can be followed by
a single Bourne shell command. Subsequent lines in the target entry begin with a Tab
and Bourne shell commands. These commands constitute the rule for building
target.

You can continue commands across input lines by expanding the newline with a
backslash (\). The continuing line must also start with a Tab.

To rebuild a target, make expands macros, strips off initial Tab characters, and either
utes the command directly (if it contains no shell metacharacters) or passes each
command line to a Bourne shell for execution.
