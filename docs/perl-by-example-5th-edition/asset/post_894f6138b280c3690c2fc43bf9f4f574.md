## 13.2.6 Using Perl to Create Your Own Module

The following example illustrates how you can create a module in a separate .pm file and use the module in another program. Although this module itself looks like any other package, it additionally includes the Exporter module, @EXPORT, @EXPORT_OK, and %EXPORT_TAGS in order to list and export symbols. When exporting lists, try not to export the names of Perl's built-in functions. In the following example, the function is called nap rather than sleep. If your function is named sleep, the built-in sleep function would be overridden by your function, which could have unwrapped consequences for an unwary user. For guidelines on module creation, see perlmadb.pl. To see a skeleton module to create extensions and modules for CPAN, see Module::Starter or Dist::Zilla. Both are located at perlcode.perl.org or by using the perldoc command.

There are a number of sites that discuss style guides on the naming of modules. See “The Naming of Modules” at https://pause.perl.org/. Also check perldoc.perl.org/perlmodstyle.html. When naming modules, think about who will be using your module and give it context. Just because you know what it does, others won't. Good documentation is also an important part of module creation. We cover documentation in Section 14.5, “Plan Old Documentation—Documenting a Module.” The following example is a function-oriented module that utilizes the *Exporter.pm* module to export variable and subroutine names to the user of the module. Both the module and its user are shown here.

### EXAMPLE 13.10

```perl
# (The MyPet/Cat.pm Module)
package MyPet::Cat;
use strict;
use warnings;
our $VERSION="0.01"; # The version number for the Cat.pm module

use Exporter qw(import); # Simplified import
#require Exporter;
#our @ISA=qw(Exporter);

our @EXPORT=qw(eat); # Default is to eat
our @EXPORT_OK=qw(speak nap play); # Exported on demand
our %EXPORT_TAGS = ('all'=>[ qw(speak nap play eat)]); # Export a collection

sub name{ # Not on the export lists
my $name = shift;
return $name;
}
sub speak{
return "Meowwww\n";
}
sub eat{
return "likes fish\n";
}
sub nap {
return "ZZzzzzzz\n";
}
sub play {
return "catch a mouse!\n";
}
1;
```

### EXAMPLE 13.10 (CONTINUED)

```perl
use MyPet::Cat qw(:all);
use MyPet::Cat;
my $petname = MyPet::Cat::name("Sneaky");
print "$petname ", eat();
print "$petname likes to ", play(), "\n";
print nap(), "\n";
print speak();
```

(Output)
Sneaky likes fish
Sneaky likes to catch a mouse!
ZZzzzzzz
Meowwww

### EXPLANATION

- The file is called MyPet/Cat.pm. It contains a package of the same name without the extension.
- The @EXPORT module allows this module to export functions to a user's namespace using its standard import method.
- This is typically the way @EXPORTER is loaded using the @ISA array and inheritance. (See Section 14.4, “Inheritance,” for more on object-oriented inheritance.)
- The @EXPORT array lists variables and subroutines that will export by default into the user's namespace.
- The @EXPORT_OK array lists variables and subroutines that can export if the user of the module requests them in his use statement. If he doesn't ask, he won't get them.
- The %EXPORT_TAGS hash is a convenient way to bundle up the variables and subroutines in the @EXPORT_OK array and give them one name. The key in the hash in this example, 'all', is the key and will serve as a label for those names listed as values (that is, speak, nap, and play). The name listed in the %EXPORT_TAGS hash must also be listed in either the @EXPORT_OK or the @EXPORT array as well.
- The user must request the speak subroutine since it is listed in the @EXPORT_OK array.
- The eat subroutine is exported to the user's namespace by default.
- A module must return a true value or the use will fail.
- The use directive will import a list of symbols labeled all, created in the %EXPORT_TAGS hash on line 6.
- The use directive will also import the eat function listed in the @EXPORT array on line 4. Symbols listed in the @EXPORT array are imported by default with use.
- The pet's name must be fully qualified as it is not imported (that is, not on any of the export lists).
- The cat and play functions are now available to the user from the Cat.pm module without qualifying their names.

### Creating an import Method Without Exporter

The following module implements its own `import` function that is somewhat limited in what it can do, but demonstrates how importing works. Note the use of a typeglob and a reference to manipulate the symbol table of the caller of this `import` function (that is, the user of `MyPet::Dog.pm`).

### EXAMPLE 13.11

```perl
package MyPet::Dog;
use strict;
use warnings;
sub import{
  no strict 'refs'; # Allow typeglobs
  my $pkg=caller 0; # Get the name of the calling package
  foreach my $sym(qw(speak eat nap)){
    *{"$pkg\::$sym"} = \&$sym; # put a reference to the symbol
    # on the user's symbol table
  }
}
sub name{ # Not exported
  my $name = shift;
  return $name;
}
sub speak{
  return "BowWow";
}
sub eat{
  return "likes steak";
}
sub nap {
  return "ZZZZzzzz\n";
}
1;
```

```perl
# -----(Module user)
use MyPet::Dog; # use will call Module's import function
$dogname = MyPet::Dog::name("Rover");
print "$dogname says ", speak(), "\n";
print "$dogname ", eat(), "\n";
print nap(), "\n";
```

(Output)
Rover says BowWow
Rover likes steak
ZZZZzzzz

### EXPLANATION

- The `Dog.pm` module is in a directory called `MyPet`.
- This is a user-defined **import** function that will be automatically called when the user of this module says `use MyPet::Dog`.
- Turning off `'refs'` for **strict** allows the program to use symbolic references; in this case, symbolic refs to `typeglob`s to **manipulate** the symbol table.
- Perl’s built-in `caller` function, with an argument `0`, returns the name of the package where this `import()` was called.
- Each symbol in the `foreach` list (`speak`, `eat`, and `nap`) will be exported by this import routine to the caller's namespace.
- Here’s where we manipulate the user’s symbol table. A reference to each of the symbols in the list is assigned to the user’s package symbol table via a `typeglob`.

## 13.3 Modules from CPAN

You may want to use a module that has already been created by another programmer and stored somewhere other than in your library files. The best resource to start with is CPAN (the Comprehensive Perl Archive Network) a central repository for a collection of thousands of Perl modules. To find the CPAN mirror closest to you, go to `http://www.perl.com/CPAN`.

Perl modules that depend on each other are bundled together by name, author, and category. You can find these modules under the CPAN `modules` directory or by using the CPAN search engine at `http://metacpan.org`. If you need to install these modules, the CPAN documentation gives you easy-to-follow instructions. The home page for CPAN is shown in Figure 13.5.
