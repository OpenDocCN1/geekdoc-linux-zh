
## 防火墙计算机

防火墙计算机的配置如下：

- **本地主机** — `127.0.0.1`（IP 地址）和 `lo`（接口）。你通常不需要修改这些设置。
- **互联网连接** — `123.45.67.89`（IP 地址）和 `eth0`（接口）。请分别将其替换为你连接到互联网时使用的静态 IP 地址和接口名称。
- **局域网（LAN）连接** — `10.0.0.1`（IP 地址）和 `eth1`（接口）。请分别将 `10.0.0.1` 和 `eth1` 替换为你连接局域网时使用的静态 IP 地址和接口名称。
- **局域网中的计算机** — 示例中，局域网内每台计算机的 IP 地址均在 `10.0.0.2` 到 `10.0.0.254` 之间。请将 `10.0.0.255` 更改为与你局域网地址范围匹配的数字。

以下是一个加载防火墙规则的脚本示例，该脚本可用于图 14-2 所示的配置：

```bash
# (1) 策略（默认）
iptables -P INPUT DROP
iptables -P OUTPUT DROP
iptables -P FORWARD DROP

# (2) 用于 ACCEPT 的 TCP 数据包的自定义链
iptables -N okay
iptables -A okay -p TCP --syn -j ACCEPT
iptables -A okay -p TCP -m state --state ESTABLISHED,RELATED -j ACCEPT
iptables -A okay -p TCP -j DROP

# (3) INPUT 链规则
# 来自局域网的传入数据包规则
iptables -A INPUT -p ALL -i eth1 -s 10.0.0.0/24 -j ACCEPT
iptables -A INPUT -p ALL -i lo -s 127.0.0.1 -j ACCEPT
iptables -A INPUT -p ALL -i lo -s 10.0.0.1 -j ACCEPT
iptables -A INPUT -p ALL -i lo -s 123.45.67.89 -j ACCEPT
iptables -A INPUT -p ALL -i eth1 -d 10.0.0.255 -j ACCEPT

# 来自互联网的传入数据包规则
# 已建立连接的数据包
iptables -A INPUT -p ALL -d 123.45.67.89 -m state --state \
ESTABLISHED,RELATED -j ACCEPT

# TCP 规则
iptables -A INPUT -p TCP -i eth0 --destination-port 21 -j okay
iptables -A INPUT -p TCP -i eth0 --destination-port 22 -j okay
iptables -A INPUT -p TCP -i eth0 --destination-port 80 -j okay
iptables -A INPUT -p TCP -i eth0 --destination-port 113 -j okay

# UDP 规则
iptables -A INPUT -p UDP -i eth0 --destination-port 53 -j ACCEPT
iptables -A INPUT -p UDP -i eth0 --destination-port 2074 -j ACCEPT
iptables -A INPUT -p UDP -i eth0 --destination-port 4000 -j ACCEPT

# ICMP 规则
iptables -A INPUT -p ICMP -i eth0 --icmp-type 8 -j ACCEPT
iptables -A INPUT -p ICMP -i eth0 --icmp-type 11 -j ACCEPT

# (4) FORWARD 链规则
# 接受我们需要转发的数据包
iptables -A FORWARD -i eth1 -j ACCEPT
iptables -A FORWARD -m state --state ESTABLISHED,RELATED -j ACCEPT

# (5) OUTPUT 链规则
# 仅输出具有本地地址的数据包（禁止伪造）
iptables -A OUTPUT -p ALL -s 127.0.0.1 -j ACCEPT
iptables -A OUTPUT -p ALL -s 10.0.0.1 -j ACCEPT
iptables -A OUTPUT -p ALL -s 123.45.67.89 -j ACCEPT

# (6) POSTROUTING 链规则
iptables -t nat -A POSTROUTING -o eth0 -j SNAT --to-source 123.45.67.89
```

我将上述脚本中的命令分成了六个部分。以下文本描述了每个部分。

- **（1）策略** — `iptables -P` 命令设置了 `INPUT`、`OUTPUT` 和 `FORWARD` 链的默认策略。通过将这些策略设为 `DROP`，任何未被匹配的数据包都将被丢弃。换句话说，为了让数据包通过，它必须被脚本中其他规则之一明确匹配并允许（ACCEPT）。

- **（2）自定义链** — 我创建了一个名为 `okay` 的自定义链，用于对请求特定 TCP 服务（即我允许通过的 Web、FTP 和 DNS 服务）的数据包进行更多检查。`N` 选项 `okay` 创建了 `okay` 链。下一行说明请求新连接的 `SYN` 数据包（`--syn`）可以放行。再下一行允许与已建立（`ESTABLISHED`，即已经有流量通过该接口）的连接或相关（`RELATED`，即与已建立的连接相关的新连接）连接关联的数据包通过。这组命令的最后一行告诉 `iptables` 丢弃不满足上述任何检查条件的数据包。

- **（3）INPUT 链规则** — 大部分数据包过滤工作是在 `INPUT` 链中完成的。第一组输入规则指示 `iptables` 何时总是接受来自互联网和来自局域网的数据包。接下来的三组规则确定哪些特定协议（`TCP`、`UDP` 和 `ICMP`）的请求被接受：

    - **来自局域网的数据包** — 由于你希望局域网上的用户和防火墙计算机本身都能使用互联网，这组规则允许由这些计算机发起的数据包通过。第一行告诉 iptables 接受所有协议中源地址位于局域网有效地址范围内的数据包（`-s 10.0.0.0/24`，代表 IP 地址 `10.0.0.1` 到 `10.0.0.254`）。接下来的三行允许来自防火墙计算机本身所有有效 IP 地址的数据包（`-s 127.0.0.1`、`10.0.0.1` 和 `123.45.67.89`）。最后一行接受局域网上的广播数据包（`-d 10.0.0.255`）。

    - **来自互联网的数据包（已连接）** — 这一行被拆分为两行（我只是为了因为页面宽度不足以显示为一行而使用了反斜杠换行）。它`接受`（ACCEPT）那些既与已建立的连接（`-state ESTABLISHED,RELATED`）关联，又直接请求发送到防火墙 IP 地址（`123.45.67.89`）的数据包。

    - **TCP 规则（新连接）** — 在这里，你为希望向互联网用户提供 TCP 服务打开端口。在这些行中，你为 FTP 服务（`-destination-port 21`）、安全 shell 服务（`22`）、Web 服务（`80`）和 `IDENT` 认证（`113`，其中最后一项对于 IRC 等协议可能是必要的）打开端口。不是立即接受这些请求，而是跳转到你定义的 `okay` 链，以进一步检查数据包是否构造正确。

    > **注意：** 在允许数据包被这些端口接受之前，你需要确保这些端口上的服务已正确配置。

    - **UDP 规则（新连接）** — 这些行定义了用于接受来自互联网的 UDP 服务连接数据包的端口。在这个示例中，我选择接受 DNS 服务（`-destination-port 53`）的请求，因为该计算机被配置为 DNS 服务器。示例还说明了接受另外几个可选端口请求的行。端口 2074 是一些多媒体应用程序所需的；你局域网上的用户可能需要使用它，而端口 4000 则被 ICQ 协议（用于在线聊天）使用。

    - **ICMP 规则** — `ICMP` 消息实际上更多地用于报告服务器状态，而非提供实际服务。在我们的示例中，从互联网接受用于 `ICMP` 协议请求的数据包是 `ICMP` 类型 `8` 和 `11`。类型 `8` 服务允许你的计算机接受*回显请求消息*（echo request messages），这使得人们可以 ping 你的计算机以检查其是否可用。类型 `11` 服务与传输过程中*生存时间（TTL）*超过限制的**生存时间**数据包相关，你正在接受返回给你的*超时*（Time Exceeded）消息。（要使用 `traceroute` 命令查找通往你想要到达的主机的故障路由，你需要接受类型 `11` 消息。）

- **（4）FORWARD 链规则** — 由于此防火墙还充当路由器，`FORWARD` 规则用于限制防火墙在两个网络（互联网和本地 `LAN`）之间允许和禁止传输的内容。第一行转发来自本地 `LAN` 的所有内容（`-A FORWARD -i eth1`）。第二行转发来自互联网且与已建立连接（`-state ESTABLISHED,RELATED`）关联的内容。

- **（5）OUTPUT 链规则** — 这些规则基本上用于防止任何人从你的本地计算机伪造 IP 地址（即声称数据包来自它实际未来自的地方）。根据这三条规则，从防火墙输出的每个数据包的源地址必须是防火墙计算机接口地址之一（127.0.0.1、10.0.0.1 或 123.45.67.89）。

- **（6）POSTROUTING 链规则** — POSTROUTING 链定义了对已接受但需要额外处理的数据包的规则。这是实际执行网络地址转换（NAT）的地方。对于 NAT 表（-t nat），在 POSTROUTING 链中，所有发往互联网的数据包都会将其地址转换为防火墙外部接口的地址（-to-source 123.45.67.89）。在这种情况下，我使用了源网络地址转换（SNAT）链，因为我的互联网连接关联了一个静态 IP 地址（123.45.67.89）。如果我使用的是动态 IP 地址（通过 DHCP），我会使用 MASQUERADE 而不是 SNAT。我还需要将所有引用 `-d 123.45.67.89` 的地方更改为 `-i eth0`。（当然，你会使用不同的 IP 地址，可能还有不同的以太网接口。）

## 示例 2：用于共享互联网连接的防火墙（无服务器）

在这种场景中，防火墙保护着一台 Linux 系统（防火墙）以及局域网中几台仅用于连接互联网的计算机。此防火墙后面没有服务器，因此你希望防止互联网上的人请求服务。

你可以使用示例 1 中显示的相同脚本，但不要使用请求 TCP 服务的行。因此，你可以删除第 2 部分中的自定义链，并删除第 3 部分中的 TCP 规则。如果你不希望你的防火墙对 ping 请求（类型 8）可见，并且不关心在数据包超过生存时间值时接收消息（类型 11），例如当数据包遇到故障路由器时，你也可以删除 ICMP 规则。

## 示例 3：具有互联网连接的单一 Linux 系统的防火墙

在这个示例中，有一个网络接口，将你的 Fedora 系统连接到互联网。你没有与其他计算机共享该连接，也没有从你的计算机提供任何服务。

在这种情况下，你可以删除第 2、4 和 6 部分。从第 3 部分中，你可以删除所有与来自局域网的传入请求以及所有 TCP 服务相关的规则。如我在示例 2 中所述，你还可以删除类型 8 的 ICMP 规则，以使你的防火墙对来自互联网的 ping 请求不可见，并删除类型 11 的 ICMP 规则，以避免接受关于生存时间数据包失败的消息。
