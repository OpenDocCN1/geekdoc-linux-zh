
在此模式下，Samba 服务器会将用户名和密码发送到 Windows NT 主域控制器或备份域控制器。这与 Windows NT 服务器执行验证的方式相同。仍然需要配置有效的 Linux 用户账户。

- `ads` — 此安全选项使 Samba 在 ADS 域中作为域成员运行。要使用此选项，必须在 Samba 机器上安装 Kerberos。Samba 还必须加入 ADS 域（参见 `net` 工具）。

- `auth methods` — 设置 Samba 服务（`smbd`）使用的身份验证方法。在大多数情况下保持默认设置即可。您可以选择的身份验证方法包括匿名访问（`guest`）、通过 winbind 中继身份验证（`winbind`）、winbind 之前的 NT 身份验证（`ntdomain`）、基于 NetBIOS 或域名的本地查找（`sam`），或对受信用户的远程 DC 身份验证（`trustdomain`）。

- `encrypt passwords` — 控制是否可以与客户端协商加密密码。默认情况下为开启状态（`yes`）。对于*域*安全，此值必须为 `yes`。较新版本的 Windows NT（4.0 SP3 或更高版本）以及 Windows 98 和 Windows 2000 期望启用加密密码。（有关获取客户端使用加密密码的信息，请参见“设置 Samba 客户端”部分。）

- `client schannel` — 选择是否要求客户端使用 netlogin schannel（`yes`），提供 schannel 但不强制执行（`auto`），或甚至不提供 schannel（`no`）。

- `server schannel` — 选择服务器是否要求客户端使用 netlogin schannel（`yes`），提供 schannel 但不强制执行（`auto`），或甚至不提供 schannel（`no`）。如果将此设置为 `no`，您必须应用 Samba 项目提供的 Windows XP WinXP_SignOrSeal.reg 补丁。

- `passdb backend` — 选择用于存储保存密码的后端数据库的方法。默认情况下，使用基于 TDB 的方法（`tdbsam`），使用名为 `passdb.tdb` 的文件。其他选项包括 `smbpasswd`（Samba 密码存储样式）和 `ldapsam`（基于 LDAP 的存储样式）。

- `guest account` — 指定来宾账户的用户名。当服务被指定为 Guest OK 时，此处输入的用户名将用于访问该服务。该账户通常是 *nobody* 用户名。

> **提示：** 确保来宾账户是有效的用户。（默认的 *nobody* 应该已经设置好以正常工作。）如果来宾账户是无效的用户，列出共享资源的 IPC$ 连接将失败。

- `invalid users` — 可以包含一个用户列表，这些用户不允许登录 Samba 服务。在名称前添加 at 符号（`@`）以将其解释为 NIS 或 UNIX（Linux）组名。

- `valid users` — 添加一个允许登录 Samba 服务的用户名列表。如果此字段或 invalid users 字段中没有任何内容，则允许任何用户登录。

- `admin users` — 可以包含一个具有与 Samba 共享相关的管理员特权的用户列表。

- `read list` — 可以包含一个仅对服务具有只读访问权限的用户列表。

- `write list` — 可以包含一个对服务具有读写访问权限的用户列表。

- `printer admin` — 将您希望允许使用 MS-RPC 服务控制 Samba 打印机的远程管理权限的用户添加到此列表中，通常来自 NT 工作站。

- `hosts allow` — 包含一个允许使用您的计算机的 Samba 服务的一个或多个主机列表。默认情况下，来自任何计算机的用户都可以连接到 Samba 服务器（当然，他们仍然必须提供有效的用户名和密码）。通常，您使用此选项允许来自特定计算机（如 10.0.0.1）或计算机网络（如 10.0.0.\）的连接，这些被 hosts deny 选项排除。

- `hosts deny` — 包含一个不允许用户从这些主机使用您的计算机的 Samba 服务的一个或多个主机列表。您可以使此选项相当严格，然后添加您想要使用 Samba 服务器的特定主机和网络。默认情况下，没有主机被拒绝。

- `preload modules` — 包含一个您希望在任何客户端能够连接到服务之前加载到 smbd 守护进程的模块列表。

### 分配来宾账户

Samba 总是将 Linux 系统上有效用户的权限级别分配给使用服务器的客户端。在共享安全的情况下，用户被分配一个来宾账户（默认是 *nobody* 用户账户）。

如果未设置 guest account 值，Samba 会经过一组相当复杂的规则来确定使用哪个用户账户。结果是在每种情况下很难确定将分配哪些用户权限。这就是为什么如果您希望为 Samba 服务器提供更具体的用户访问权限，建议用户使用 user security。

### 日志选项

以下选项有助于定义 Samba 服务器上的日志记录方式：

- `log file` — 定义 Samba 日志文件的位置。默认情况下，Samba 日志文件包含在 `/var/log/samba` 中（文件名为 `smbd.log` 和 `smbd.1og`，以及 `smb.log`）。在此选项中，`%m` 将被替换为尝试连接到本地 Samba 服务器的每个主机的名称。因此，例如，对于名为 maple 的客户端计算机，smb 日志文件将是 `/var/log/samba/maple.log`。

- `max log size` — 设置日志文件可以消耗的最大空间量，以千字节为单位。默认情况下，该值设置为 0（无限制）。

### 打印选项

cups options 字段用于定义传递给 cups 服务的选项。默认情况下，仅设置了 raw 选项（这将导致打印数据直接传递给 Samba 打印机）。

### 浏览选项

浏览列表是网络上可供 SMB 服务使用的计算机列表。客户端使用此列表来查找不仅位于其自己的 LAN 上，还位于其工作组中可能位于其他可达网络上的计算机。

在 Samba 中，浏览是通过下面描述的选项配置并由 smbd 守护进程实现的。如果您在单个 LAN 内使用 Samba 作为工作组，您可能不需要担心浏览选项。然而，如果您使用 Samba 在几个物理子网之间提供服务，您可能会考虑将 Samba 配置为域主浏览器。以下是一些需要考虑的问题：

- 可以将 Samba 配置为主浏览器。这允许它从本地浏览主收集计算机列表，以形成广域网服务器列表。
- 如果 Samba 充当域主浏览器，Samba 应使用 WINS 服务器来帮助浏览客户端解析此列表中的名称。
- Samba 可以作为 WINS 服务器使用，尽管它也可以依赖其他类型的操作系统提供该服务。
- 每个工作组应只有一个域主浏览器。不要将 Samba 用作与 NT 域名称相同的工作组的域主。

如果您在一个混合了 Samba 和 Windows NT 服务器的环境中工作，您应该使用 NT 服务器作为您的 WINS 服务器。如果 Samba 是您唯一的文件服务器，您应该选择单个 Samba 服务器（smbd 守护进程）来提供 WINS 服务。

> **注意：** WINS 服务器基本上是一个用于 NetBIOS 名称的名称服务器。它提供的服务与 DNS 服务器对 TCP/IP 域名所做的服务相同：它可以将名称转换为地址。WINS 服务器特别有用，因为它允许计算机在信息未在子网边界间广播的多个子网之间通过 SMB 进行通信。
