```
rtt min/avg/max/mdev = 1218.059/1258.384/1290.861/28.000 ms
```

In this example, a ping packet took, on average, 1.3 seconds to make the round trip. From the first example to the second example, latency increased by a factor of 31! A data link that goes from working normally to slowing down by a factor of 31 is a clear sign that link utilization should be investigated.

For a more accurate measure of data throughput, a tool such as tcp can be used. To test your connection with tcp you must have installed the tcp RPM package on machines inside and outside of your network. (The tcp package comes on the DVD included with this book.) If you are not sure whether the package is installed, simply type tcp at a command prompt. You should see something like the following:

```
# tcp
```

The first step is to start up a receiver process on the server machine:

```
# tcp -rs
tcp-r: buflen=8192, nbuf=2048, align=16384/0, port=5001 tcp

```

The -r flag denotes that the server machine will be the receiver. The -s flag, in conjunction with the -r flag, tells tcp that you want to ignore any received data.
