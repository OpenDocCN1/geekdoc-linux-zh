
一次性密码计算器系统，并且你可以编写一个模块来支持它（编写模块的文档包含在系统中），PAM 感知的程序可以使用新模块并与新的一次性密码计算器协同工作，而无需重新编译或以任何方式修改。

## 服务

使用 PAM 的每个程序都定义自己的“服务”名称。login 程序定义服务类型为 login，ftpd 定义服务类型为 ftp，等等。通常，服务类型是用于访问服务的程序的名称，而不是（如果有区别）用于提供服务的程序。

## 配置文件

目录 /etc/pam.d 用于配置所有 PAM 应用程序。（这在早期的 PAM 版本中曾经是 /etc/pam.conf；在找不到 /etc/pam.d 条目时仍会读取 pam.conf 文件，但其使用已被弃用。）每个应用程序（实际上是每个服务）都有自己的文件。一个文件看起来像这样：

```
#
auth required /lib/security/pam_securetty.so
auth required /lib/security/pam_pwdb.so shadow nullok
auth required /lib/security/pam_nologin.so
account required /lib/security/pam_pwdb.so
password required /lib/security/pam_cracklib.so
password required /lib/security/pam_pwdb.so shadow nullok useauthtok
session required /lib/security/pam_pwdb.so
```

第一行是注释。任何以 # 字符开头的行都是注释。第二行到第四行堆叠了三个用于登录授权的模块。第二行确保如果用户尝试以 root 身份登录，他们登录的 tty 是否列在 /etc/securetty 文件中（如果该文件存在）。第三行会导致用户被要求输入密码并检查密码。第四行检查 /etc/nologin 文件是否存在，如果存在，则显示文件内容，并且如果用户不是 root，则不允许他或她登录。请注意，所有三个模块都会被检查，即使第一个模块失败。这是一个安全决策——它旨在不让用户知道其身份验证被拒绝的原因，因为知道被拒绝的原因可能会让他们更容易破坏身份验证。你可以通过将 required 改为 requisite 来改变这种行为；如果任何 requisite 模块返回失败，PAM 会立即失败，而不会调用任何其他模块。第五行会导致执行必要的记账。例如，如果启用了 shadow 密码，pam_pwdb.so 模块将检查账户是否已过期，或者用户是否未更改其密码且更改密码的宽限期已过期。第六行将新更改的密码置于一系列测试之下，以确保它不能例如被基于字典的密码破解程序轻易确定。第七行（我们不得不换行）指定如果登录程序更改用户的密码，应使用 pam_pwdb.so 模块来执行此操作。（它仅在 auth 模块确定密码需要更改时才这样做——即如果 shadow 密码已过期。）第八行也是最后一行指定应使用 pam_pwdb.so 模块来管理会话。目前，该模块什么也不做；它可以被任何必要的模块替换（或通过堆叠补充）。请注意，每个文件内各行的顺序很重要。虽然 required 模块调用的顺序其实并不重要，但还有其他控制标志可用。虽然 optional 很少使用，并且在 Red Hat Linux 系统上默认从不使用，但 sufficient 和 requisite 会使顺序变得重要。让我们来看一下 rlogin 的 auth 配置：

```
auth required /lib/security/pam_securetty.so
auth sufficient /lib/security/pam_rhosts_auth.so
auth required /lib/security/pam_pwdb.so shadow nullok
auth required /lib/security/pam_nologin.so
```

这看起来几乎与 login 条目相同，但多了一行指定额外模块，并且模块指定的顺序不同。首先，pam_securetty.so 防止 root 登录发生在不安全的终端上。这有效地禁止了所有 root rlogin 尝试。如果你希望允许它们（在这种情况下，我们建议你不要连接互联网或位于良好的防火墙后面），你可以简单地删除该行。其次，pam_nologin.so 检查 /etc/nologin，如上所述。第三，如果 pam_rhosts_auth.so 对用户进行了身份验证，PAM 会立即向 rlogin 返回成功，而无需进行任何密码检查。如果 pam_rhosts_auth.so 无法对用户进行身份验证，则该失败的身份验证将被忽略。最后（如果 pam_rhosts_auth.so 未能对用户进行身份验证），pam_pwdb.so 模块执行正常的密码身份验证。请注意，如果你不希望在 securetty 检查失败时提示输入密码，可以将 pam_securetty.so 模块从 required 改为 requisite。

## Shadow 密码

pam_pwdb.so 模块将自动检测你是否使用 shadow 密码并进行所有必要的调整。请参阅 Shadow Utilities 了解更多信息。

## Rexec 和 PAM

出于安全原因，rexec 在 Red Hat Linux 6.0 中未启用。如果你希望启用它，你需要在文件 /etc/pam.d/rexec 中注释掉一行。以下是该文件的示例（请注意，你的文件可能略有不同）：

```
#
auth required /lib/security/pam_pwdb.so shadow nullok
auth required /lib/security/pam_nologin.so
account required /lib/security/pam_pwdb.so
```
