
## 表 8-1

| 代理 | 功能 |
| :--- | :--- |
| 日历代理 | 日历代理为计划好的约会、任务和笔记提供自动状态跟踪信息。<br>当用户安排日历事件时，日历代理会处理所有“接受”和“拒绝”响应，并自动更新组织者日历中该事件的状态信息。<br>只有安排事件的用户才能查看谁接受或拒绝了日历事件。参与者仅看到自己的状态；所有其他参与者均视为待定。<br>如果选择不运行日历代理，用户将在收件箱中收到 I-cal 状态消息。由于状态信息采用 I-cal 格式，事件组织者可能无法判断收件人是接受还是拒绝了约会。<br>I-cal 邮件客户端（如 Microsoft Outlook* XP）也可为计划好的约会提供自动状态跟踪。<br>如果仅使用符合 I-cal 标准的邮件客户端，可以选择由 NetMail 通过日历代理管理状态跟踪，或由邮件客户端管理状态跟踪。<br>如果使用模块化 Web 客户端，必须运行日历代理以提供计划好的约会的自动状态跟踪。 |
| 连接管理器 | 连接管理器代理负责跟踪已认证用户。<br>当用户通过 POP3 或 IMAP4 登录时，POP 或 IMAP 代理会获取客户端的 IP 地址并将其发送给连接管理器代理。<br>连接管理器随后在指定时间段内跟踪该 IP 地址（默认为 15 分钟）。<br>任何代理都可以查询连接管理器以获取已认证的 IP 地址。<br>在 NetMail 中，此服务用于 SMTP 代理的 SMTP-after-POP 功能。这是一项 UBE 保护功能，可防止未授权用户通过您的消息系统进行邮件中继。<br>连接管理器代理监听 UDP 端口 689 上的其他代理，并且应始终受到防火墙保护。 |
| IMAP 代理 | IMAP 代理使 IMAP4 客户端能够从消息系统中下载邮件。<br>除了基本的 NetMail 内存要求外，IMAP 代理每个预期的并发连接到您的 NetMail 系统大约需要 300 KB 内存。<br>为了用户能够访问其邮箱，您的消息系统必须至少包含 1 个 POP、IMAP 或模块化 Web 代理。 |
| 列表服务器代理 | 列表服务器代理使您的 NetMail 系统能够作为列表服务器运行。<br>列表服务器与 NDS 邮件列表和邮件列表对象协同工作。<br>基于 NDS 的邮件列表由容器、组、角色或用户对象构建。普通邮件列表需要每个订阅者的完整电子邮件地址。<br>当向邮件列表发送消息时，如果其中一条消息被拒绝，则不会返回不可投递的状态信息。 |
| 模块化 Web 代理 | 模块化 Web 代理为 NetMail 邮件客户端提供模板界面。提供两个模板：<br>- WebAccess<br>- WebMail<br>使用任一模板，用户都可以通过任何标准 Internet 浏览器发送和接收邮件、管理文件夹并设置邮件偏好。<br>模块化 Web 代理还包含几个模块，支持各种客户端功能：<br>- 邮件模块：提供邮件和通讯录功能。<br>- 日历模块：启用 WebAccess 日历功能，包括约会、任务和笔记。<br>- 偏好模块：允许用户更改密码。<br>- 任务导向管理模块：允许您委派管理功能，如创建、修改或删除用户。<br>除了基本的 NetMail 内存要求外，模块化 Web 代理每个预期的并发连接到您的 NetMail 系统大约需要 300 KB 内存。<br>为了用户能够访问其邮箱，您的消息系统必须至少包含 1 个 POP、IMAP 或模块化 Web 代理。 |
| NMAP 代理 | NMAP 代理负责管理消息处理和投递。<br>它协调从消息进入消息队列开始到投递到用户邮箱或通过 Internet 转发投递为止发生的所有操作。<br>它是唯一能够直接访问消息存储区的代理。因此，每个消息系统至少需要一个 NMAP 代理，且消息系统中的每个用户必须包含在某个 NMAP 代理的上下文中。<br>NMAP 代理的 3 个主要功能如下：<br>- 管理消息存储区：默认情况下，NMAP 代理为其分配上下文中的每个用户对象创建一个邮箱目录。由于 NMAP 是唯一拥有物理访问消息存储区权限的代理，因此消息存储区目录始终在运行 NMAP 代理的服务器上创建。<br>- 管理消息队列：NMAP 代理协调消息队列中的所有消息处理。邮件负载实用程序监控并调节 NMAP 代理的线程使用，以保持最佳效率。<br>- 为其他 NetMail 代理提供对消息存储区和消息队列的 IP 访问。 |
| POP 代理 | POP 代理使 POP3 邮件客户端能够从消息系统中下载邮件。<br>为了用户能够访问其邮箱，您的消息系统必须至少包含 1 个 POP、IMAP 或模块化 Web 代理。 |
| 代理服务器 | 代理服务器允许用户从中央邮箱管理多个电子邮件账户。<br>用户可以来自其他消息系统的多达 3 个 POP3 或 IMAP4 电子邮件账户中检索消息。从这些账户检索的所有消息都存储在用户的 NetMail 邮箱中，仿佛它是原始目的地。<br>根据用户设置，检索的消息副本可以保留在原始邮箱中，或者从主机服务器上删除。所有代理信息都存储在用户对象中。 |
| SMTP 代理 | SMTP 代理是 Internet 与您的消息系统之间的网关。其主要功能是在 Internet 之间传输消息。<br>为了使用户能够从 POP 或 IMAP 客户端发送本地消息或发送消息到 Internet，此代理必须在至少一台消息服务器上运行。<br>它控制哪些域名被消息系统识别。<br>SMTP 代理还提供 NetMail 的大部分 UBE 保护功能，包括：<br>- 反向 DNS 查找<br>- 实时黑洞（RBL）查找<br>- 通过 IP 地址阻止主机<br>- ESMTP 身份验证<br>- SMTP-after-POP<br>- 对通过 IP 地址的远程发送的限制<br>SMTP 代理的其他选项包括：<br>- 入站和出站 Internet 消息的消息大小限制<br>- 对构成安全风险或促进与具有间歇性 Internet 连接的办公室连接的标准化 SMTP 命令的控制<br>- 邮件中继主机定义，允许将所有远程消息通过单个 SMTP 服务器进行漏斗，而不是让每个 SMTP 代理单独访问 Internet |

## 安装目录

在默认安装期间，NetMail 文件会被复制到 `/var/opt/novell/netmail` 和 `/opt/novell/netmail` 目录。

`/var/opt/novell/netmail` 目录包含单一副本、消息存储区和用户目录。`/opt/novell/netmail` 目录包含 NetMail 二进制文件。

## WebAdmin

WebAdmin 是一种基于浏览器、平台独立的系统管理工具。

WebAdmin 在 eDirectory 中不代表 **Agent** 对象。相反，该代理是在服务器上手动启动的。

您可以通过访问 iManager 并选择“启动 NetMail 管理”来通过浏览器访问 WebAdmin。
