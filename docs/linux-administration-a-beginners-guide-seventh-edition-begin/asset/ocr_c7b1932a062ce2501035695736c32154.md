# Secure Copy (scp) Program

Secure Copy (scp) is meant as secure replacement for the older rcp command. Both commands allow you to do remote copies from one host to another. The most significant problem with the older rcp command is that users intend to arrange their remote-access settings to allow far too much access into your system. To mitigate this, instruct users use the scp command instead, and completely disable access to the insecure login programs. The format of scp is identical to rcp, so users shouldn't have problems with this transition.

Suppose user, for example, is logged into her home workstation (client-A) and wants to copy a file named .bashrc in the local home directory to her home directory on server-A. Here's the command:

```
$yangclient-A ~$ .bashrc server-A:/home/yang
```

If she wants to copy the other way—that from the remote system server-A to her local system client-A—the arguments need to be reversed, like so:

```
$yang@client-A ~# server-A:/home/yang/.bashrc .bashrc
```

# Secure FTP (sftp) Program

Secure FTP is a subsystem of the ssh daemon. You access the Secure FTP server by using the sftp command-line tool. To sftp from a system named client-A to an SFTP server running on server-A as the user yangang, type this:

```
root@client-A -# sftp yang@server-A
```

You will be asked for your password, just as when you are using an ssh client. Once you have been authenticated, you will see a prompt like this:

```
sftp>
```

If you have issues sftp commands at the sftp shell. For example, to list all the files and directories under the /tmp folder on the sftp server, you can use the ls command:

```
sftp> ls -l /tmp
```

For a listing of all the commands, just type a question mark (?):

```
sftp> ?
```
