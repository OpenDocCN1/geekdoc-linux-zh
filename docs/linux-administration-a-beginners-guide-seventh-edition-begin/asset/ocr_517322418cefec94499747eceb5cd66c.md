# Domains

NIS servers establish so-called domains that are similar to the domains of a domain controller (DC) in Windows. A significant difference is that the NIS domain does not require the NIS administrator explicitly to join a client. (Bear mind that the NIS model assumes all clients are members of the system administrators.) Furthermore, NIS only centralizes information/data; it does not perform authentication itself. It defers to system routines for this. The process of authenticating users is left to each individual host; NIS merely provides a centralized list of users.

> TIP Because NIS domains must be given names, it's a good practice (though not mandatory) to use names that differ from your DNS domain names. You will have a much easier time discussing your network domains with fellow administrators when everyone knows which is which.

# Configuring the NIS Server

Linux distributions typically have the client-side software for NIS already installed as a part of the operating system installation. This arrangement makes it easy to set up any system as NIS client from the get-go—some distributions will give you the choice of configuring a mechanism to use NIS using the operating system (OS) install.

On the other hand, every system needs to install the NIS server component manually if you need an NIS server. This will usually have to be painfully. The software can be easily downloaded from your distribution's online repository or from the distro install media.

After installing the NIS server, all that is left for you to enable the service (if it isn't enabled already) and configure it. To make sure that the NIS server (pserv) is started automatically by system boots, you can use the system's service management utility/mechanism (such as systemctl, chkconfig, update-rc.d, and so on.
