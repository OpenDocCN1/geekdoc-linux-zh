# Security Implications

Sendmail is a popular open source mail implementation used by many Linux distros and Internet sites. Any other software, its internal structure and design are complex and require a considerable amount of care during development. In recent years, the developers of Sendmail have taken a paranoid approach to their design to alleviate security issues.

The Postfix developers took their mail implementation one step further and wrote the server software from scratch with security in mind. Basically, the package ships in a tight security mode, and it's up to the individual user to loosen it as much as is needed for a specific environment. This means the responsibility falls to us as much as making sure we keep the software properly configured (and thus not vulnerable to attacks).

When deploying any mail server, check the following issues and questions in mind:

+   - When an email is sent to the server, what programs will it trigger? Under what permissions do these programs run?

+   - Are programs securely designed? And can you protect/secure the communication channels between the programs and the end-clients via secure protocols?

+   - If they cannot be made, how can you limit the damage in case of an attack?
