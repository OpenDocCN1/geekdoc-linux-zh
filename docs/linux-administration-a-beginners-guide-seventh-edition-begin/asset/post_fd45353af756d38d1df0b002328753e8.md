## Setting Up NIS Master to Push to Slaves
If you haven't already configured the master server to push to the slave servers, you should do so. This requires two tasks: First, edit the /var/yp/ypvers file so that it includes all the secondary servers to which the master server will push. For example, if you want the master server to push maps to server-B and server-C, you'll edit /var/yp/ypvers so that it looks like this:

```
server-A
server-B
server-C
```

Here, server-A is the hostname of the master server. Second, you'll need to make the Makefile has the line NOPUSH=false.

## Running ypinit
With these steps accomplished, you're ready to run the ypinit command to initialize the secondary server. Type the following command on the secondary NIS server:

```
[root@server-B ~]# /usr/lib64/yp/ypinit -s server-A
```

Here, the -s option tells ypinit to configure the system as a slave server, and server-A is the hostname of the master NIS server. The output of this command will complain about ypfrd not running—you can ignore this. What the secondary server is trying to do is pull the maps from the master server, using the ypfrd daemon. This won't work, however, because you didn't configure the master server to accept pulls down via ypfrd. Rather, you configured the master server to push maps to the secondaries when the master has an update. The server process at this point must be started by hand. It's the same process as the primary server: ypserv. To get it started, run this command:

```
[root@server-B ~]# service ypserv start
```
