
## CHAPTER 6: Booting and Shut Down

Using any text editor you are comfortable with (the vim editor is used in this example), type the following text in the file:

```sh
#!/bin/sh -e
echo "Starting new GRUB2 script creation..."
cat << EOF
menuentry "Change Background Color" {
    set color_normal=white/green
}
EOF
```

- Once the script has been successfully created, make the script executable:
`fedora-server:- # chmod +x 99_custom.sh`

- Run grub2-mkconfig, which will parse the command in the new script you just created and create an appropriate updated /boot/grub2/grub2.cfg configuration file:
`fedora-server:- # grub2-mkconfig -o /boot/grub2/grub.cfg`

- Use the grep command to verify that the new menuentry was added to grub.cfg:
`fedora-server:- # grep -A 4 "99_custom.sh" /etc/grub2/grub2/grub.cfg`
### BEGIN /etc/grub2/99_custom.sh ###
Starting new GRUB2 script creation...
menuentry "Change Background Color" {
    set color_normal=white/green
}
### END /etc/grub2/99_custom.sh ###

- Once you've confirmed the entry is in the grub.cfg file, reboot the system.

When the system reboots, you can test your changes by following the next steps while at the initial GRUB screen:

- After the GRUB menu appears, select the Change Background Color option and press ENTER.

- The color of the menu should change to the color specified in the 99_custom.sh file using the color_normal directive. Note that selection will not actually boot the system. You will have to select a proper menuentry to boot the operating system into Linux.

## Linux Administration: A Beginner's Guide

> TIP: If you don't want a specific menu entry to be automatically created in a system using GRUB 2 as the boot loader, you have to delete or disable the corresponding script in /etc/grub.d/ directory that creates the entry. For example, if you don't want to see entries for other, non-native operating systems as Microsoft Windows in your boot menu, you need to delete /etc/grub.d/30_os-prober or alternatively make it nonexecutable and then run the grub2-mkconfig command to regenerate grub.cfg by using this command:
```bash
# chmod -x /etc/grub.d/30_os-prober
# grub2-mkconfig -o /boot/grub2/grub.cfg
```

## USB GRUB Boot Disk

Let's create a bootable USB GRUB 2 disk. This will allow you to boot the system using the USB device in the chance that you can't boot the system normally, for whatever reason. Some sample situations where a bootable GRUB 2 USB disk can come in handy:

- Your system does not currently have a boot loader.
- The boot loader for the system is damaged or corrupted, possibly by another operating system.
- You want to create a multiboot USB medium for storing and booting operating systems that come in ISO (CD/DVD-ROM) image format.

The general idea behind using a GRUB boot disk is as that you currently have a system with an unbootable, corrupt, or unwanted boot loader—since the system cannot be booted by itself from the hard disk, you need another medium to bootstrap the system. For this, you can use a GRUB 2 USB disk, a GRUB CD, or even a floppy disk (with good luck finding a system with a floppy disk!).

Assuming we are ready to load the entire contents of the target USB device and the current block device for the USB drive is /dev/sdb, we can carry out the following procedures:

1. Plug in a reasonably sized USB drive into the appropriate port on the system and then use either fdisk, lsusb, dmesg, or blkid command to verify the block device file that Linux has associated with your USB drive. We use the blkid here command:

```bash
[root@server]# blkid
/dev/sdb1 UUID="176-ef7-459-a4e6-304" TYPE="ext4"
```

2. Format the drive with the ext4 file system (this will wipe the data on the drive):
```bash
[root@server]# mkfs.ext4 /dev/sdb1
```

3. Use the grub-install utility to install the boot loader:
```bash
[root@server]# grub-install --root-directory=/dev/sdb1
```

4. If you don't want to use GRUB, you can alternatively create the configuration:
```bash
[root@server]# grub2-mkconfig -o /boot/grub2/grub.cfg
```

5. View the files created on the device:
```bash
[root@server]# ls /dev/sdb1
```

6. Once you've finished, you can mount the device:
```bash
[root@server]# mount /dev/sdb1
```
