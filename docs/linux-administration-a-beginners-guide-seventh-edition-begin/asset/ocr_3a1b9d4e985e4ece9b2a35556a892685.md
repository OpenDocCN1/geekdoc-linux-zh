# The Logging Daemon

With so much going on at any time, especially with services that are disconnected from a terminal window, a standard mechanism by which special events and messages can be logged is required. Linux distributions have traditionally used syslog (syslogd) to provide this service. However, more recently, the Linux distros are standardizing on other software besides syslog for the logging function. Most of the popular Linux distros appear to have standardized on the rsyslog package as well as the logging component of systemd referred to as systemd-journal (journal).

Regardless of the software used, the idea remains the same, and the end results between the new approaches in the additional features set offered. In this section, we are concentrating on the logging daemon that ships with Fedora/CentOS/openSUSE/Ubuntu (rsyslog), with references to syslog when appropriate. Managing and configuring rsyslog is similar to the way it is in syslog. Rsyslog daemon maintains backward-compatibility with the traditional daemon but offers a plethora of new features as well.
