# The Registry vs. Text Files

Think of the Windows Registry as the ultimate configuration database—thousands upon thousands of entries, only a few of which are completely documented.

“What? Did you say your Registry got corrupted?” <maniac laughter> “Well, yes, we can restore it from last night’s backups, but then Excel starts funny and the technician (who charges $65 just to answer the phone) said to restore ...."

In other words, the Windows Registry system can be, at best, difficult to manage. Although it's a good idea in theory, most people have dealing with it don't emerge from battling without a scar or two.

Linux does not have a registry, and this is both a blessing and a curse. The configuration files are most kept as a series of text files (think of the .ini files). This setup means you're able to edit configuration files using the text editor of your choice rather than tools like regedit. In many cases, it also means you can liberally comment on configuration files so that months from now you won't forget why you set something in a particular way. Most software programs that are used on Linux platforms store their configuration using the let (pronounced slash) directory or one of its subdirectories. This convention is widely understood and accepted in the FOSS world.

The curse of a no-registry arrangement is that there is no standard of writing configuration files. Each application can have its own format. Many applications are now bundled with GUI-based configuration tools to alleviate some problems. You can do a basic setup easily, and manually edit the configuration file when you need to do more complex adjustments.

In reality, having text files hold information generally turns out to be an efficient method. Once set, they rarely need to be changed; even so, they are straight text files and easy to view when needed. Even more helpful is that it's easy to write scripts to read the same configuration files and modify their behavior accordingly. This is especially helpful when automating server maintenance operations, which crucial in a large site with many servers.
