# Enumerated /proc proc Entries

A listing of the /proc will reveal a large number of directories whose names are just numbers. These numbers are the process identifiers (PIDs) for each running process in the system. Within each of the proc directories are several files describing the state of the process. This information can be useful in finding out the system perceives a process and what sorts of resources the process is consuming. (From a programmer's point of view, the proc files are also an easy way to get information about itself).

For example, here's a long listing of the files under /proc:

```
$root@server ~# ls -l /proc
dr-xr-xr-x 6 root 0 2052-12-27 08:54 1
dr-xr-xr-x 6 root 0 2052-12-27 08:54 1021
dr-xr-xr-x 6 root 0 2052-12-27 08:54 1048
...<OUTPUT TRUNCATED>
```

If you look a closer at the folder 1 in this output, you will notice that this particular folder represents the information about the init process or the process with process identifier of 1 (PID = 1).

Here's a list of files under /proc/1:

```
$root@server ~# ls -1 /proc/1
dr-xr-xr-x. 2 root 0 Dec 26 02:33 attr
--r-- 1 root 0 Dec 28 02:33 auxv
--r--r-- 1 root 0 Dec 26 11:06 cmdline
...<OUTPUT TRUNCATED>
lrwxrwxrwx. 1 root 0 Dec 26 11:06 /proc/1/exe -> /sbin/init
```

As you can see in the output, the /proc/1/exe is a soft link that points to the actual executable for the init program (/sbin/init). On distributions using systemd service manager, the link will instead point to /usr/lib/systemd/system (see Chapter 8). The same logic applies to the other numeric-named directories that are under /proc—that is, their processes.

# Common proc Settings and Reports

As mentioned, the proc file is a virtual file system, and as a result, changes to defaults in /proc do not survive reboots. If you need to change a value under /proc to be automatically set/enabled between reboots, you can edit your boot scripts so that the change is made at boot time or use the sysctl tool. The former approach can, for example, be used to enable IP packet-forwarding functionality in the kernel every time system is booted.
