## Creating the Startup Script

Here you will create the actual script that will be executed during system startup and shutdown. The file you create will be called carpald. The file will be chkconfig-enabled. This means that if you want, you can use the chkconfig utility to control the runs at which the program starts and stops. This is a useful and time-saving functionality.

- 1. Launch any text editor of your choice, and type the following text:
```bash
#!/bin/sh
#Carpald
#
#chkconfig:    35 99 01
# description: Carpald is a program that wakes up every 1 hour and
# tells us that we need to take a break from the keyboard
# or we'll lose all functionality of our wrists and never
# be able to type again as long as we live.
# Source function library.
/etc/init.d/functions
```

```bash
[ -f /usr/local/sbin/carpald.sh ] || exit 0
# See how we were called.
case $1 in
start)
echo "Starting carpald: "
/usr/local/sbin/carpald.sh &
echo "done"
touch /var/lock/subsys/carpald
;;
stop)
echo -n "Stopping carpald services: "
echo "done"
killall -q -9 carpald &
rm -f /var/lock/subsys/carpald
;;
status)
status carpald
;;
restart|reload)
$0 stop
$0 start
;;
*)
echo "Usage: carpal start|status|restart|reload"
exit 1
esac
exit 0
```

A few comments about the preceding startup script:

- Even though the first line of the script begins with #!/bin/sh, note that /bin/sh is a symbolic link to /bin/bash. This is not the case on other UNIX systems.
- The line chkconfig: 35 99 01 is actually quite important to the chkconfig utility that we use. The number 35 means that startup and stop entries for runlevels 3 and 5 by default—that, entries will be created in the /etc/rc.d/rc3.d and /etc/rc.d/rc5.d directories.
- The 99 and 01 mean chkconfig should set the startup priority of our program to be 99 and the stop priority to be 01—that, is start late and end early.

- 2. Save the script into a file called carpald.

- 3. Make the file executable:

```
[root@fedora-server ~]# chmod 755 carpald
```

4. Copy or move the script to the directory where startup scripts are stored—the /etc/init.d/ directory:

```
[root@fedora-server ~]# mv -f carpal /etc/init.d/
```

5. Now you need to tell chkconfig about the existence of this new start/stop script and what you want to do with it:

```
[root@fedora-server ~]# chkconfig --add carpal
```

This will automatically create some of the symbolic links listed here:
lrwxrxrwx. 1 root 17 Dec 15 11:58 S10carpal -> .../init.d/carpal
lrwxrxrwx. 1 root 17 Dec 15 11:58 S99carpal -> .../init.d/carpal
lrwxrxrwx. 1 root 17 Dec 15 11:58 KOcarpal -> .../init.d/carpal
lrwxrxrwx. 1 root 17 Dec 15 11:58 S99carpal -> .../init.d/carpal

(The meaning and significance of the K (kill) and S (start) prefixes in this listing explained earlier).

This might appear rather elaborate, but the good news is that because you've set up this rc script, you've never ever to do it again. More important, the script will automatically run during startup and shutdown and is able to manage itself overhead is well worth the long-term benefits of avoiding carp tunnel syndrome: We have set up the "nuts and bolts" around the infrastructure, but it's not fully useful until we get to run it. We'll use the service command to start daemon and manage it going forward:

- 1. Use the service command to find out the status of carpald.sh:

```
[root@fedora-server ~]# service carpald status
```

- 2. Manually start the carpald program to make that it will indeed start up upon startup:
```
[root@fedora-server ~]# service carpald start
```

TIP As long as the subsystem of the server is running (see Chapter 19), you should see a message from carpald.sh script after an hour. You can use the program from the command line by typing: q at the prompt to quit.

- Now stop the program:
```bash
[root@fedora-server ~]# service carpald stop
```

You can use the systemctl command to stop carpald daemon by running:
```bash
[root@fedora-server ~]# systemctl stop carpald.service
```

We are done.

## Enabling Services

At times you might find that you don't need a particular service to be started at boot time. This is especially important if you are configuring the system as server and only need specific services and nothing more. As described in the preceding sections, you can cause a service not to be started by simply renaming the symbolic link in runlevel; rename it to start with K instead of S. Once you are comfortable with the command line, you'll find that it is easy to enable or disable a service.

## Enabling a Service

The startups of service can also be managed using either the chkconfig utility or the systemctl utility. Here, we will mostly use chkconfig. To view the levels the carpald program is configured to start up, you type:

```bash
[root@fedora-server ~]# chkconfig --list carpald
0:off 1:off 2:off 3:on 4:off 5:off 6:off
```

To make the carpald program start automatically in runlevel 2, you type this:
```bash
[root@fedora-server ~]# chkconfig --level 2 carpald on
```

If you check the list of levels for the carpald program again, you will see that the field for runlevel 2 has changed from 2:off to 2:on. Type the following to:
```bash
[root@fedora-server ~]# chkconfig --list carpald
0:off 1:off 2:on 3:off 4:off 5:off 6:off
```

If you want to use systemd's systemctl to view whether the carpald service is configured to automatically start in the current environment, you type the following:
```bash
[root@fedora-server ~]# systemctl is-enabled carpald
```

If you want to use systemd's systemctl to enable the carpald service at the next system boot, you type:
```bash
[root@fedora-server ~]# systemctl enable carpald
```

## Disabling a Service

To disable a service completely, you must, at a minimum, know the name of the service. You can then use the chkconfig (or systemctl) tool to turn it off permanently, preventing it from starting in all runlevels. For example, to disable our "time-saving" carpald.sh program, you could type this:

```
[root@fedora-server ~]# chkconfig carpald off
```

If you want to use systemd's systemctl utility to disable the carpald service, type this:

```
[root@fedora-server ~]# systemctl disable carpald
```

If you check the runlevels for the carpald.sh program, you will see that it has been turned off for all runlevels:

```
[root@fedora-server ~]# chkconfig --list carpald
0:off 1:off 2:off 3:off 4:off 5:off 6:off
```

To remove the carpald.sh program permanently from the chkconfig utility's control, use chkconfig's delete:

```
[root@fedora-server ~]# chkconfig --del carpald
```

We are done with our sample carpald.sh script, and to prevent it from flooding us with email notifications (in case we accidentally turn it back on), we delete it from the system for:

```
[root@fedora-server ~]# rm -f /usr/local/bin/carpald.sh
```

And that's how services start up and shut down automatically in Linux. Now go out and take a break.

## Graphical Service Managers

GUI tools are available that will help you manage services start at any runlevel. In Fedora and other Red Hat-type systems (including RHEL and CentOS), one tool is the system-config-services utility (see Figure 6-1). Another is the all-encompassing, web-based Cockpit server manager (http://cockpit-project.org/), which also has a function to manage services using system-config-services program, type the following:

```
[root@fedora-server ~]# system-config-services
```

On a system running openSE Linux, the equivalent GUI program (see Figure 6-3) can be launched by typing this:

```
opensuse-server:~ # yast2 services-manager
```
