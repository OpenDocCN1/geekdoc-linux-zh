# Configuring DNS Clients

In this section, we'll delve into the wild and exciting process of configuring DNS clients! Okay, maybe it's not exciting—but there's no denying the clients' significance to the infrastructure of any networked site.

# The Resolver

So far, we've been studying servers and the DNS tree as a whole. The other part of this equation is, of course, the client—host that's contacting the DNS server to resolve a hostname in an IP address.

> NOTE You might have noticed earlier in the section “The DNS Toolbox” that most of the queries we were issuing were made against the DNS server called localhost. Localhost is, of course, the local system shell you are executing the query commands from. In our case, hopefully, this system is serverA.example.org! We specified the DNS server because, by default, the system will query whatever host's default DNS server is. And if it happens that your host's DNS server is some random DNS server that your ISP has assigned, some of the queries will fail, because your ISP's DNS server will not know the zone you manage and control locally. If we configure our local system to use our local DNS server to process all DNS-type queries, we won't have to specify “localhost” manually any longer.

# CHAPTER 16 Domain Name System (DNS)

Under Linux, the resolver handles the client side of DNS. This is actually part of a library of C programming functions that get linked to a program when the program is started. Because all of this happens automatically and transparently, the user doesn't have to know anything about it. It's simply a little bit of magic that helps users, for example, browse the Internet—and remain blissfully unaware of how all the plumbing works!

From the system administrator's perspective, configuring the DNS isn't magic, but it's straightforward. Traditionally, only two files are involved: /etc/resolv.conf and /etc/nsswitch.conf. In addition, Debian-based distros may rely on the resolvconf program, which uses files under the /etc/resolvconf.d/ directory.

# The /etc/resolv.conf File

The /etc/resolv.conf file contains the information necessary to know what its local DNS server is. (Every site will have, at the very least, its own DNS server.) This file has two lines: the first indicates the default search domain, and the second indicates the IP address of the host's name server.

The default search domain applies mostly to sites that have their own local domains. When the default search domain is specified, the client will automatically append this domain name to the requested site and check for it. For instance, if you specify your default domain to "yahoo.com" and then try to connect to the hostname "my," the client software will automatically contacting "my.yahoo.com." Using the same default, if you try to connect the host "www.stat.net," the software will try "www.stat.net" and find that it doesn't exist, and then try "www.stat.net" alone (which does exist).

Of course, you can supply multiple default domains. However, doing so will slow your query process because each domain needs to be checked. For instance, if both example.org and stanford.edu are specified, and you perform a query on www, you'll get three queries: www.stat.net.yahoo.com, www.stat.stanford.edu, and www.stat.net.

The format of the /etc/resolv.conf file is as follows:

```
search domain
nameserver IP-address
```

Here, domainname is the default domain to search, and IP-address is the IP address of your DNS server. For example, here's a sample /etc/resolv.conf file:

```
search example.org
nameserver 127.0.0.1
```

Thus, when a name lookup is needed for serverB.example.org, only the host part is needed—that is, serverB.example.org suffix will be automatically appended to the query. Of course, this is valid only at your local site, where you have control over how clients are configured!

# /etc/nsswitch.conf File

The /etc/nsswitch.conf file tells the system where it should look up certain kinds of configuration information (services). When multiple locations are identified, the /etc/nsswitch.conf file specifies the order in which the information can be best fetched. Typical configuration files that are set up to /etc/nsswitch.conf include the password file, group file, and hosts file. (To see a complete list, open the file in your favorite editor).

The format of the /etc/nsswitch.conf file is simple. The service name comes first. The locations are separated by spaces. The order of the locations is the order in which the system searches them.

For example, if the /etc/nsswitch.conf file contains the line:

```
hosts: files dns
```

the system will first look up the hostname in the hosts file. If it's not found there, it will look in the DNS server. If it's not found there, the system will return an error.

For example, if the /etc/nsswitch.conf file contains the line:

```
hosts: dns files
```

the system will first look up the hostname in the DNS server. If it's not found there, it will look in the hosts file. If it's not found there, the system will return an error.

The `return` option can be used to tell the system to stop searching if the hostname is found in a specific location. If the hostname is not found, the system will return an error and won't look in any subsequent locations.

For example, if the /etc/nsswitch.conf file contains the line

```
hosts: files dns return
```

the system will first look up the hostname in the hosts file. If it's not found there, it will look in the DNS server. If it's not found there, the system will return an error and won't look in any subsequent locations.

The `fail` option can also be used to tell the system to stop searching if the hostname is not found in a specific location. If the hostname is found, the system will return the result and won't look in any subsequent locations.

For example, if the /etc/nsswitch.conf file contains the line

```
hosts: files dns fail
```

the system will first look up the hostname in the hosts file. If it's not found there, it will look in the DNS server. If it's not found there, the system will return an error and won't look in any subsequent locations.

The `neg` option can be used to tell the system to stop searching if the hostname is not found in a specific location. If the hostname is not found, the system will return a "not found" error and won't look in any subsequent locations.

For example, if the /etc/nsswitch.conf file contains the line

```
hosts: files dns neg
```

the system will first look up the hostname in the hosts file. If it's not found there, it will look in the DNS server. If it's not found there, the system will return a "not found" error and won't look in any subsequent locations.

# Configuring the Client

Let's walk through the process of configuring a Linux client to use a DNS server. We'll assume that we are using the DNS server on serverA and we are configuring serverA to be the client. This may sound a bit odd at first, but it is important for you to understand that just because a system runs the server does not mean it cannot be a client. Think of it as running a web server—just because a system runs Apache doesn't mean you can't run Firefox on the machine and access the web sites hosted locally via the loop-back address (127.0.0.1)!

Breaking out the steps to configure the client, we see the following:

- Edit /etc/resolv.conf and set the nameserver entry to point to your DNS server. Per our example:

```
search example.org
nameserver 127.0.0.1
```

- Look through the /etc/nsswitch.conf file to make sure that DNS is consulted for hostnames resolutions:

```
[root@serverA ~]# grep "hosts" /etc/nsswitch.conf
```

If you don't have dns listed, in this output, use any text editor to include dns on the host line.

- Test the configuration with the dig:

```
[root@serverA ~]# dig +short serverA.example.org
192.168.1.1
```

Notice that you didn't have to specify the name server to use with dig (such as dig @localhost +short serverA.example.org) for the preceding query. This is because dig will by default use (query) the DNS server specified in the local /etc/resolv.conf file.
