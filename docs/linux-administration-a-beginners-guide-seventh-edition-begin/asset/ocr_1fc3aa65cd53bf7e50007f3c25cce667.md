You can also access clusterfs by enabling and configuring the appropriate protocol from the server side and sharing/exporting the clusterfs mount point as you would. For example, you can make the contents of the clusterfs mount point on our sample server-B available via the CIFS/SMB protocol to Windows, OS X, and Linux clients by creating a Samba (see Chapter 24) share division similar to the following:

```
[MASSIVE_DATA]
path = /data/B
comment = Samba share on cluster DFS
browseable = yes
writable = yes
```

Similarly, you can make the clusterfs volume available to other Linux or UNIX client systems that are capable of speaking NFS (see Chapter 23). This can be done on our sample clusterfs server-A by creating an entry like the following in the NFS configuration file (/etc/exports):

```
# /etc/exports file for server-A
/data/B 192.168.0.0/24 (ro)
```

In this section, we will access our clusterfs volume using the recommended native clusterfs client.

We will create and mount the remote clusterfs volume at the /mnt/clusterfs/MASSIVE_DATA directory of the client. On the client system, create the mount point:

```
[root@client-C ~]# mkdir -p /mnt/clusterfs/MASSIVE_DATA
```

Mount the exported volume on the clusterfs server-A:/MASSIVE_DATA/

```
[root@client-C ~]# mount -t clusterfs server-A:/MASSIVE_DATA/
/mnt/clusterfs/MASSIVE_DATA/
```

Use the df command to run some basic checks on the remote volume:
df -h /mnt/clusterfs/MASSIVE_DATA/
Filesystem      Size Used Avail Use% Mounted on
server-A:/MASSIVE_DATA
500G   74M    48G   2%    /mnt/clusterfs/MASSIVE_DATA

Access the clusterfs Volume from the Client As soon as you've successfully mounted the remote clusterfs volume on the local client, the client system can begin to read and write data onto the remote storage—provided, of course, that they have the correct file system permissions to do this.
