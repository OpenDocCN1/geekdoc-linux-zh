
## Kernel Configuration

Next, we will step through the process of configuring a Linux 4.*-series kernel. To explore some of the innards of this process, we will enable the support of a specific feature that we pretend must be supported on the system. Once you understand how this works, you can apply the same procedure to add support for any other kernel feature that you want. Specifically, we will enable support for the NTFS file system into our custom kernel.

Most modern Linux distros are a wildcard that ship with the 4.*-series kernel (remember that the asterisk symbol is a wildcard) also have a kernel configuration file for the running kernel available on the local file system as a compressed or regular file. On our sample system that uses Fedora, this fills in the /boot directory and is usually named something like config-*. The configuration file contains a list of the options and features that were enabled for the particular kernel it represents. A config file similar to this one is what we aim to create through the process of configuring the kernel. The only difference between the file we create and the ready-made one is that we will add customization to ours.

> TIP Using a known, preexisting config file as a framework for creating our custom file ensures we don't waste too much duplicating the efforts that other people have already put into finding what works and what doesn't work!

The following steps cover how to configure the kernel. We will be using a text-based kernel configuration utility, which will allow you to follow along in your terminal regardless of whether you are using a GUI desktop environment or not.

- 1. To begin, we'll copy over and rename the preexisting config file from the /boot directory into our kernel environment:

```
[root@server linux-4.*#] cp /boot/config-uname -r) .config
```

We use 'uname -r' here to help obtain the configuration file for the running kernel. The uname -r command prints the kernel's release. Using it ensures that we are getting the exact version we want, just in case other versions are present.

> NOTE Linux kernel configuration editor starts up specifically looking for, and ends up generating, a file named .config (pronounced "dot config") at root of the kernel source tree. This file is hidden.

- 3. We will examine one very important option a little more closely by selecting it in the main body of the application and consulting the menu for it. Use the arrow keys on your keyboard to navigate to (or highlight) the Enable Loadable Module Support item. Once highlighted, use the left/right arrow keys of the TAB key to select <Help> at the bottom of the screen and then press ENTER to execute the Help action on the highlighted entry.

- We'll add support for NTFS in our custom kernel.

While the main configuration screen, use your arrow keys to navigate to and highlight the File Systems item. With File Systems selected, press ENTER to view the sub-menu or child items for File Systems.

> TIP To view the results of some of the changes you made using the menuconfig tool, use the .config file that you saved. Type the following:
```bash
[root@server linux-4.*#] grep .config
CONFIG_FSFS=m
CONFIG_FS_DEBUG=y
CONFIG_FS_RW=y
```

## A Quick Note on Kernel Modules

Loadable module is a Linux feature that allows small pieces of code to be dynamically inserted into the kernel, rather than being permanently built into it. Kernel modules are commonly referred to as drivers. They can be loaded and unloaded from the running kernel without needing to reboot the system. The number of modules that can be loaded depends on the available memory on the system.

## Compiling the Kernel

In the preceding section, we walked through the process of creating a configuration. In this section, we will perform the actual build. The compilation stage of the kernel is by far the easiest, but it also takes the most time, depending on the processing power of your system. Let's dig into the specific steps required to compile your kernel.

- 1. First we will add an extra piece to the identification string for the kernel we are about to build. While still in the root of the kernel tree, open up the Makefile for editing. The variable we want to change is close to the top of the file. Change the line that looks like this:

EXTRAVERSION =

To this:

EXTRAVERSION = -custom

- 2. Save your changes to the, and exit the text editor.

> TIP In the unlikely event that you don't have a simple text editor readily available, you can use the sed utility to quickly search and make the changes to Makefile in the previous step, by running the command:
# sed -i 's/EXTRAVERSION.*/EXTRAVERSION = -custom/' Makefile

- 3. Pass the kernelversion to the make command to view the full of the kernel that you customized:

```
[root@server linux-4.*#] make kernelversion
```

> TIP Most modern systems have more than a single CPU core. Some server-grade hardware might have even more than physical CPU with multiple cores. You can take advantage of all that processing power on the system and speed up the when performing CPU-intensive operations like compiling the kernel. To do this, you can pass a parameter to the make command that specifies the number of jobs to run simultaneously. The syntax for the command is -j N where N is the number of jobs to run. For example, if you have a quad (4) core-capable CPU, you can type:

```
# -j 4
```

- 4. The only command that is needed to compile the kernel is the make command:

```
[root@server linux-4.*#] make
```
