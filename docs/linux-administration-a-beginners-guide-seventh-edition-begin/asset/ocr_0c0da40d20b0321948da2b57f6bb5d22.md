# rc Scripts

In the preceding section, we mentioned that on SysV-based distros, the /etc/initab specifies scripts to run when runlevels change. These scripts are responsible for starting or stopping the services that are particular to the runlevel.

Because of the large number of services that might need to be managed, resource control (rc) scripts are used. On SysV-based distros, the main rc script is responsible for calling the appropriate scripts in the correct order for each runlevel. As you can imagine, a simple script could become extremely uncontrollable! To keep this happening, a slightly more elaborate system is used.

For each runlevel, a subdirectory exists in the naming scheme of rc.d, where X is the runlevel. For example, all the scripts for runlevel 3 are in /etc/rc.d/3.

In the runlevel directories, symbolic links are made to scripts in /etc/rc.d/init.d or /etc/init.d directory. Instead of using the name as it exists in /etc/rc.d/init.d or /etc/init.d directory, the symbolic links are prefixed with an S if the script is to start or with a K if it is to stop (or kill) a service. Note that these letters are case-sensitive. You must use uppercase letters or the startup scripts will not recognize them.
