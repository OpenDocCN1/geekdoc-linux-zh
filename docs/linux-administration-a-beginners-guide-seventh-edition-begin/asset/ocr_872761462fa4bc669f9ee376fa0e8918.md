# Enabling and Disabling Services

At times, you might find that you don't need a particular service to be started at boot time. This is especially important if you are configuring the system as a server and only need specific services and nothing more.
As described in the preceding sections, you can cause a service not to be started by simply renaming the symbolic link in runlevel directory; rename it to start with a K instead of an S. Once are comfortable with the command line, you'll find that it is easy to enable or disable a service.

# Enabling a Service

The startups of service/program can also be managed using either the chkconfig utility or the systemctl utility. Here, we will mostly use chkconfig.
To view the levels in the carpal.sh program is configured to start up, you type:

```
```bash
[root@fedora-server ~]# chkconfig --list carpal
0:off 1:off 2:off 3:on 4:off 5:6:off
```
```

To make the carpal.sh program start automatically in runlevel 2, you type this:
```bash
[root@fedora-server ~]# chkconfig --level 2 carpal on
```

If you check the list of levels for the carpal.sh program again, you will see that the field for runlevel 2 has been changed from 2:off to 2:on. Type the following to:
```bash
[root@fedora-server ~]# chkconfig --list carpal
0:off 1:off 2:on 3:off 4:off 5:off 6:off
```

If you want to use systemd's systemctl to view whether the carpal service is configured to automatically start in the current environment, you type the following:
```bash
[root@fedora-server ~]# systemctl is-enabled carpal
```

If you want to use systemd's systemctl to enable the carpal service at the next system boot, you type:
```bash
[root@fedora-server ~]# systemctl enable carpal
```
