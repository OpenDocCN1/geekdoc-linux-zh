# CHAPTER 24 Samba 635

Let us attempt an actual connection to the share we created earlier (samba-share). To demonstrate the process, the connection will be made from a different hosted named client.

We'll use the smclient utility to connect to the server, connecting as a guest by specifying the -U option. After connecting, we will be dropped down to an smb shell with the prompt: \>

While we're connected, we'll be doing a listing of the files available on the share using the ls command. We'll then try to download one of the files that resides on the share using the FTP-pipe command get.

Finally, we'll end the connection using quit. A sample session on clientB connecting to the host, server, is here:

```
[root@clientB #] smclient -U% //serverA/samba
Domain=[MYGROUP] OS=[Windows *] Server=[Samba 4.*]
smb: \> ls
      D      0      Sun 15 15:27:2020
              D      0      Sun 15 15:27:2020
foool      A      0      Sun 15 15:27:2020
fo2      A      0      Sun 15 15:27:2020
moo3      A      0      Sun 15 15:27:2020
  59501 blocks of size 8192. 55109 blocks available
smb: \> get foo2
getting file [foo2 of size 0 as foo2 (0.0 Kilobytes/sec) (average 0.0 Kilobytes/sec)
smb: \> quit
```

The file (foo2) that was downloaded from serverA will be in the current working directory on the local file system of clientB.

> TIP If you cannot access the shares on your Samba server on Red Hat-like distributions such as Fedora, it is possible that SELinux security system is getting in the way. You can temporarily put SELinux in permissive mode to eliminate it as being the cause of any issues.
# setenforce 0

# Mount Remote Samba Shares

If your kernel is configured to support the SMB file system (as is most kernels that come with modern Linux distributions), you can manually mount a Windows or Samba share onto your local system in the same way you would mount an NFS export or a local volume. This is handy for accessing a large disk on a remote server without having to shuffle individual files across the network.

While logged into clientB, you can use the mount command with the proper options to mount a share that resides on serverA.

+   1. [root@clientB ~]# mkdir -p /mnt/samba
