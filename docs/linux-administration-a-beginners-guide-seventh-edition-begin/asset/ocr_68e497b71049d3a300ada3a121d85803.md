If the remote server that you want to mount is protected with a username/password combination, you can supply the username/password with the mount command like this using the user yyang's account:

```
# mount -t cifs -o username=yyang,password=1gan19 //serverA/samba-share /mnt/b
```

To mount this, use the mount command:

```
[root@clientB]# mount /mnt/smb
```

Debian-based systems such as Ubuntu, you might have to install the cifs-utils package, if it is not already installed, so you can use the mount.cifs command (via mount -t cifs). This can be done by running this command:

```
master@ubuntu-server:~$ sudo apt-get install cifs-utils
```

> TIP On using SELinux in enforcing mode (as Fedora, RHEL, CentOS, and so), you might need to properly label it (with the correct context) new files and directories on the Samba server to allow the remote clients to mount and access the shares remotely.
To permanently label a directory so SELinux allows Samba to write and read it (on behalf of clients), have label it with samba_share_t SELinux context. Use the semanage command to add a new SELinux record to do this, which for our example is /tmp/testshare directory:
# semanage fcontext -a -t samba_share_t "/tmp/testshare(/"
To immediately apply the SELinux label you just created to the /tmp/testshare directory and its content, use the restore command like this:
# restore -v -R /tmp/testshare/
