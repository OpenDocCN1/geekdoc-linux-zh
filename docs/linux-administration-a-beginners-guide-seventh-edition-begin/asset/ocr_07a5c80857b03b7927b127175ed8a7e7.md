back-end (tdbsam) for demonstration purposes, as the other possibilities are beyond
scope of this chapter.

# Creating Samba Users

Let's create a Samba entry for the existing system user, yyang. We will also set the
user's Samba password.

Use the **pdbitedit** command to create a Samba entry for the user yyang. Choose a
good password when prompted to do so. Type the following:

```
[root@server ~]# pdbitedit -a yyang
new password:
retype password:
<OUTPUT TRUNCATED>...
Unix username: yyang
User SID: 1-5-21-3312929510-115705115-270122738-1000
Full Name: Ying Yang
```

The new user will be created in Samba's default user, tdbsam. On Red Hat-like
distros, the database file is at /var/lib/samba/private/passdb.td.

With a Samba user created, you can make the shares available only to authenticated
users, such as the one we created for the user yyang.

If the user wants to access a resource on the Samba server that has been
configured strictly for her (a protected share or non-public share), the user can
issue the smbclient command shown here, for example:

```
[root@clientB ~]# smclient -U yyang -L //serverA
```

It is, of course, possible to access a protected Samba share from a native Microsoft
Windows box. You will need to supply the proper Samba username and corresponding
password when prompted on the Windows system.

# Allowing Null Passwords

If you need to allow users to have no passwords (which is a bad idea, but by way
for which there might be legitimate reasons), you can do so by using the **pdbitedit**nprogram with the -c option to set the "No password required (N)" flag, like so:

```
# pdbitedit -c '[N]' username
```

Here, *username* is the name of the whose password you want to set to empty.
For example, to allow the user yyang to access a share on the Samba server with a
null password, type the following:

```
[root@server ~]# pdbitedit -c '[N]' yyang
```

You can also do this by using the smbpasswd program, like this:

```
[root@server ~]# smbpasswd -n yyang
```
