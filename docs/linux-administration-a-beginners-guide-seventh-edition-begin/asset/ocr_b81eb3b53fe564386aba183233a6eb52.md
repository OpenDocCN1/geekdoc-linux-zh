Like the other services we discussed in this chapter, cron is automatically started by the boot scripts and is most likely already configured for you. A quick check of the process list showing it quite running in the background:

```
[root@server ~#] ps aux grep cron -v grep
root 723 0.0 0.124 3332 ? S Dec26 0:02 /usr/sbin/cron -n
```

The cron service works by waking up every minute and checking each user crontab. This file contains the user's list of events that he or she wants executed at a particular date and time. Any events that match the current date and time are executed.

# The Crontab

The tool that allows you to edit entries is executed by cron crontab. Essentially, all it does is invoke an editor so you can make your changes. Once you're done, crontab places the file in the right location and brings you back to a.

Whether or not you have appropriate permission is determined by cron checking the /etc/cron.allow and /etc/cron.deny files. If either of these exists, your username must be explicitly listed for the actions to be executed. For example, if the /etc/cron.allow file exists, your username must be listed in that file in order to be able to edit your cron entries. On the other hand, if the only file that exists is /etc/cron.deny, unless your username is listed, you are implicitly allowed to edit your cron settings. All values must be listed as integers.

The file listing your jobs (often referred to as the crontab file) is formatted as

Minute Hour Day Month Day_Of_Week Command

If you want have multiple entries for a particular column (for instance, you want to run a program at 4:00 a.m., 12:00 p.m., and 5:00 p.m.), then you need to include each of these times in a comma-separated list. Be not to type any spaces in the list. For the program running at 4:00 a.m., 12:00 p.m., and 5:00 p.m., the Hour value would read 4,12,17. Newer versions of cron allow you to use a shorter notation for supplying fields. For example, if you want to run a process every two minutes, you just need to put 2 as the first entry. That cron uses military time format.

For the Day_Of_Week field, 0 represents Sunday, 1 represents Monday, and so on, the way to 6 representing Saturday.

Any entry that has an asterisk (*) wildcard will match any minute, hour, day, month, or day of week when used in the corresponding column.
