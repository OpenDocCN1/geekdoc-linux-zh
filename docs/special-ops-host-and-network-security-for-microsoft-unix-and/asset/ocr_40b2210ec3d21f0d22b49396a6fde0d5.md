# Rogue DHCP Servers

DHCP servers are widely used in Windows networks because they help in simplification of IP addresses to clients (and even servers sometimes). But imagine that there is a false DHCP server up and running in your network. What damage could it cause? If you are not using DNS services, it could simply lead to assigning clients with wrong addresses, fast exhaustion of pools, and so on. When Dynamic DNS is used, the situation becomes even worse—as an attacker registers addresses on the DNS database, the number of incorrect address resolution replies by the DNS server grows.

Windows 2000 offers some kind of remedy for this—each DHCP server running on a Windows platform must be authorized in Active Directory before it starts distributing IP leases to clients on the network. This action can be performed by Enterprise Admins only and by selecting **Authorize** in the DHCP console. After that, the information about this server is stored in Active Directory (in `CN=NetServices, CN=Services, Configuration,<name of the forest>;branch;<name of the forest>` is a root domain name similar to `DC=what, DC=home`). The DHCP regularly checks Active Directory if it is allowed to function. Unfortunately, this is true only for Windows 2000-based DHCP servers. If somebody joins a Linux-based server, for example, it will function. Worse, if the attacker creates a key with the name `DisableRouteDetection` (type `REG_DWORD`, value=`0x1`) in the branch `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\DHCPServer\Parameters` of system registry, on a Windows 2000 DHCP server, this will turn off any attempt by the server to check for authorization, and it will start functioning.

Now it is possible to create IP address collisions. In some of your servers use dynamic IP addresses (which is understandable, because with DDNS each server can change its IP and still be available on the network by notifying the DNS server), it is possible to make them act in strange ways, substituting their IP addresses for others' or simply making them unavailable by assigning them addresses that are not routable in your network.
