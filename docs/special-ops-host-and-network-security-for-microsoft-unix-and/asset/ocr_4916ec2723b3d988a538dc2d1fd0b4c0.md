# Eliminating Unnecessary Components

One of the biggest challenges that we face when hardening Windows 2000 is making decisions about the elimination of unnecessary components from the systems. Many components are installed by default, and it has become apparent while working with Windows 2000 that it is increasingly necessary that the security professional and administrator be proactive in efforts when securing systems to eliminate unused applications and services. In this section, I touch on some of the areas that can be reduced or eliminated to make your system more secure.

# Network Services

Hardening Windows 2000 network services requires that a good baseline evaluation of the systems is performed. When this is accomplished, it is possible that good decisions can be made, after the evaluation of required services and considering the needs of applications and users.

The first goal in hardening scenarios involving Windows 2000 network services is to eliminate SMB/NetBIOS access and traffic on the network. (Do not do this if you are running Windows clustering on the involved machines. Clustering requires NetBIOS resolution capability.) If you want to eliminate the traffic, don't use the settings on the WINS tab in the network adapter properties section. Instead, open on the top file menu select Advanced | Advanced Settings to reach the window shown in Figure 5.23. Uncheck the box for File and Printer Sharing (enabled by default) and you will shut down not only TCP ports 137, 138, 139 but also TCP port 445, which carries the NetBT traffic for NetBIOS over TCP/IP. You've stopped traffic from originating from your machine. (You must disable this on each adapter that is configured.)

Hardening the network services also requires that you exercise discipline and close down and eliminate services that are unused or unneeded from machines where they exist. In addition to print sharing, this means eliminating Telnet, SNMP, DHCP, FTP, WWW, NNTP, and other services from the system if they are not necessary. Don't be complacent here. It is much easier to install the component if needed than recover from an attack if it is left in place.
