By viewing the source, the user would be able to see the following (addi-
tional HTML formatting tags have been removed removed:

```
<html>
<head><title>HACKME Books</title></head>
<body>

<p align="center"><b>Order Confirmation</b></p>

<form method="POST" action="http://www.acmebooks.com/cgi-bin/buy.cgi">
<input type="text" name="quantity" size="3"> copy(ies) of <input
type="text"

name="book_order" size="20" at $500.00 each
<td>Total : <INPUT TYPE="hidden" NAME="TOTAL_PRICE" VALUE="$500">
<td><input type="submit" value="Submit" name="submit"><input type="reset"
value="reset" name="reset"></td>
</form></html>
```

Once the user clicks on the Submit button, the form is sent to the back-end
processing. The problem arises when the back-end systems accept data from
t own sources. In this case, the user
is now able to control not only the name of the book she wants to buy, (through
text box *book_order* and the number of books she wishes to buy (through the
text box *quantity*) also (and most important) the total value to be deducted
from her account (through the <HIDDEN> field TOTAL_PRICE).

A user could go through the entire procedure, and then stop
of submitting the resultant form. This page could then be saved to disk and
ed using Notepad, vi, or any editor of choice. A few keystrokes would change
the line from:

```
<INPUT TYPE="hidden" NAME="TOTAL_PRICE" VALUE="$500"
to:
<INPUT TYPE="hidden" NAME="TOTAL_PRICE" VALUE="$005">
```

Since no other checks are performed by the target CGI, the few minutes of
eff would effectively have saved the end user about $495.
The solution to this is not to rely on <HIDDEN> fields to keep data private.
