- **802.11b** This standard runs in the 2.4 GHz frequency range at 11 Mbps. It is the most widely deployed standard at this point and the focus of this chapter. ## Components of a Wireless Network

Wireless networks require a different set of hardware than the normal Ethernet hubs and switches. Access points connect the wireless network to the wired one and require wireless NICs to connect to them. In this section, we introduce the basic components of a wireless network.

## Bridging the Air Gap: Access Points and Bridges

In the traditional networking sense, all 802.11 access points are network bridges. They connect the wired and wireless networks at Layer 2 and will forward any packets on that segment like a regular Ethernet bridge. 802.11 devices can be wireless access points or wireless bridges depending on their configuration. Vendors will refer to an 802.11 device that is meant to join two wired network segments as a bridge and a wireless device that access client connections is referred to as an access point (see Figure 15.1). Sometimes a device can be both at once, but usually they are deployed as one or the other role. Since both are Layer 2 bridges to the Ethernet network they are connected to, you should realize that if you plug the access point into an Ethernet hub, each 802.11 client will see all the traffic on the hub. Plugged into a switch, the access point client will see only the packets destined for clients on the wireless network directed towards the AP’s Media Access Control (MAC).

In Ethernet terminology, clients associated with a wireless access point resemble a switch, where the only packets they see are broadcast and those destined for their MAC. This means that to sniff on a network in-band, you would need to use an Address Resolution Protocol (ARP)-spoofing tool such as Ettercap. Although you could watch traffic on the Net using a wireless sniffer, you would be in a receive-only mode and not able to inject traffic directly.

The choice of sniffing methods on the wireless LAN (WLAN) depends mostly on the desired attack. With switch-like behavior, only packets sent to the broadcast address are given to all clients. However, traditional tools that can be used to monitor traffic on an Ethernet switch using ARP manipulation work well on 802.11 networks as. Ettercap (discussed further in Chapter 16) and Arpspoof, two tools used for sniffing nonbroadcast traffic on switches, have been tested and work exactly as they do on a normal switched network. There is no span or monitor port capability to speak of WLANs; that task is covered with 802.11 NIC going into monitor mode and capturing all packets on a given channel. Unfortunately, unlike a switch's monitor port, the admin has no control over who can sniff their traffic in this fashion and has no chance to detect it if the attacker stays passive.

## Using Ettercap

Ettercap (http://ettercap.sourceforge.net) is an open source sniffer that offers built-in password decoding and ARP–related attacks. It supports interpreting data from popular protocols such as the File Transfer Protocol (FTP), Telnet, Virtual Network Computing (VNC), Lightweight Directory Access Protocol (LDAP), Point-to-Point Protocol v3 (POP). Ettercap also includes functionality to perform man-in-the-middle attacks on Secure Socket Layer (SSL) and Secure Shell (SSH1) connections, which means you are still vulnerable even when following best practices as encrypting data over the wireless network. Ettercap comes in UNIX and Windows versions and offers a simple graphical user interface (GUI) in both.

To use Etercap in Windows, click the Ettercap Start menu icon, which brings up a command prompt in the Ettercap directory. Then run Ettercap with the interface you'd like to monitor. An example would be as follows:

```
c:\program files\ettercap\ettercap -i dev
```

Once Ettercap starts, it will perform ARP discovery of the network to identify all the MAC addresses and Internet Protocol (IP) addresses on the local network (see Figure 15.2). After that, it will also attempt to resolve the DNS names of each host. The Etercap interface will show a list of all hosts on the network and allow you to select specific destination and source hosts for monitoring, as well as using any host as the source or destination. You can press H anytime in the Ettercap UI for usage information.

## Picking a NIC

The choice of wireless equipment you purchase for 802.11 security work should mostly be based on what you prefer and what is supported by your primary operating system of choice. There are many tools based on the Prism 2 chipset for UNIX-based operating systems, mainly due to the availability of driver information for this chipset and the easy capability to engage monitor mode on it. The Prism 2 chipset can usually be found nowadays in low-cost cards like the D-Link DWL650 and Symbol Spectrum 24. Most of the WiFi scanners and sniffers can use this chipset as well as the tools used to crack WEP.

plan doing a lot of 802.11 auditing, the Prism 2 is the best choice. Intersil (www.intersil.com) has also released updated version of its chipset, the Prism 2.5 and 3. Cisco is the most prominent user of these chipsets, and their Aeronet 350 series possesses one of the strongest in card amplifiers on the market today at 100+mw. Some of the tools that were written for the Prism 2 work with the 2.5, your mileage may vary depending on what tool uses and what changes were made between the chipset. Commercial 802.11 sniffers such as Wildpackets' AeroPeak and NAI's Sniffer both support the Cisco, so they would be good choices if you plan to do most of your work in a network. The Hermes chipset, manufactured by Agere (www.agere.com) is found in Lucent/Orinoco or other cards, its most popular using NetStumble and AeroPeak.

Although there a couple scanners for Windows platforms based on the Prism 2 chipset, most users for this OS are going to be armed with a Hermes chipset. Newer versions of NetStumble use the Microsoft NDIS 5.1 802.11 application programming interface (API) functions to enable functionality on Cisco and other cards. Be warned that the 802.11 original equipment manufacturers (OEMs) have selected to alter functionality in their chipsets between firmware revs, especially regarding monitor mode, so you may have to upgrade or downgrade your card's software version depending on the tool.

## Selecting an 802.11 Antenna

If you are concerned only with lab testing or internally walking your facility, you could probably get away with the built-in antenna in your wireless NIC. The power output of an average card is about 35–100mw, and assuming you aren't testing the external exposure of the network, it’s more satisfactory. Some, not all, 802.11 client NICs come with an external antenna jack to allow the connection of an external antenna. Cards from Lucent/Orinoco or those directly based on their form factor have a small jack that accepts a proprietary connector.

Most wireless equipment vendors sell pigtails, adapters that convert a card’s small proprietary connector into a conventional RF insight fitting (usually an N-Male). Certain Cisco cards also come without an internal antenna and instead provide sets of these adapters using the Cisco proprietary connector.
