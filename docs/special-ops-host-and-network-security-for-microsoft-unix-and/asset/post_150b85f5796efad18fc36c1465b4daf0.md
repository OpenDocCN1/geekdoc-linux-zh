## Figure 8.3 Authoritative Path for www.cia.gov

![](img/729efc56f204a2ebffb8295c3a2dfdfb_426_0.png)

The initial dot is hidden from everyday use to ease domain usage, this is commonly assumed if not already a part of a query. Performing DNS queries including the unnecessary dot can sometimes be used for information disclosure. Common administrative practice or proof of concept root server troubleshooting are the only common times when the initial dot is in queries.

The domain hierarchy in Figure 8.3 shows how authority is organized. The dot is the symbolic beginning, which is controlled by 13 physical root servers (see Figure 8.4). Contrary to belief, these 13 “servers” are actually clusters of many load-balanced machines.

All root servers (see Table 8.3) are owned and operated by separated entities to minimize single points of failure with the historical exception of root servers A and J. These two servers were located and operated by VeriSign, which also controls the central politics over all 13 root servers and root server IPs. Due to the semisuccessional distributed denial of service (DDoS) attack that occurred on the night of October 21, 2002, root server J was moved 15 days later to a “secret” physical location.

Among the TLDs, delegated authority is in effect. TLDs are not always served by root servers, they are commonly hosted on TLD-controlled systems that receive delegation from the root servers. You can obtain a listing of the specific TLD servers via dig. For example, if you want to know what servers host the .mil TLD you would run the following command:

```
[specialops]# dig mil. NS
```

You can see that the .mil TLD is very well distributed. However, not all TLDs can compete with the dependability required by the Defense Information Agency (DISA). Many newer TLDs have not grown large, as you can see with the .info TLD:
