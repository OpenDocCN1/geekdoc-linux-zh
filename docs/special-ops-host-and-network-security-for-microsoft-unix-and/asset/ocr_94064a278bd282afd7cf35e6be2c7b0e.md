# MAPI Clients and Firewalls

MAPI clients such as Outlook 97, 98, 2000, and 2002 require special considerations when accessing an Exchange server through a firewall. The Outlook client requires access to three ports when it connects to the Exchange server. The first port is the RPC end-point-mapper port (port 135), the second is the directory service, and the third is the information store service. The problem is that “directory service” (picture Dr. Evil saying this) and information store ports are dynamic ports, meaning they change time Exchange 2000 is restarted. MAPI clients use port 135 to “look up” the port numbers for the directory service and the information store.

Since the ports are dynamically assigned, we have to statically map these ports. In general, I think there is a good practice during setup of Exchange servers to statically map the directory service and information-store ports.

Most firewall and infrastructure administrators will become nervous if you tell them you must open up the RPC end-point-mapper (TCP port 135). After all, there have been a couple of well publicized denial-of-service vulnerabilities against this port over the years. Unless you are opening these ports for your data center or backup firewall, you might want to consider letting remote MAPI clients access the network through a VPN rather than opening ports through the firewall. After all, if they are a remote MAPI client, that requires that they have some version of Outlook installed and configured, so the probability of being able to configure a VPN connection from that is good.
