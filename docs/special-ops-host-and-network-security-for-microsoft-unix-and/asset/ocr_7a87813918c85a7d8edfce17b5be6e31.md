# Chapter 10 · Securing IIS Locations

# ### Table 10.2 COM File Locations

| COM Object | Default File Location |
| --- | --- |
| Scripting | %SystemRoot%\System32%scrrun.dll |
| WScript | %SystemRoot%\System32%wshom.exe |
| MSADO | %ProgramFiles%\Common Files\System\msado15.dll |
| CDONTS | %SystemRoot%\System32\cdonts.dll |

In addition to securing these items, you may want to limit NTFS permissions on all COM files located on the system partition. You can produce a list of all COM files with this command:

```
C:\>findstr /S /D:C:\"DllRegisterServer" *.ocxdll *.exe
```

Finally, if you are not using Distributed COM (DCOM) on your server, you should disable it by setting the HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Ole\EnabledDcom key to N.

# # Securing Web Services

Now that you have a hardened Windows 2000 OS, you can focus on securing IIS itself. In its default state, IIS is vulnerable to a number of different attacks. To do this, you must perform the following steps (this process should be completed in this specific order because some of these steps build upon the results of a previous step):

+   1. Run the IIS Lockdown tool.
2. Secure Registry settings.
3. Secure WebDAV.
4. Secure FrontPage.
5. Secure default sites.
6. Secure the master WWW properties.
7. Secure sites, files, and directories.
