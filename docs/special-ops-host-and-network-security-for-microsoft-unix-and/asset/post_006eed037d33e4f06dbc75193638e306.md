This is a domain with only two computers: test1.witt.home and test2.witt.home, both domain controllers. It is possible to see various subdomains created by Active Directory in our zone "witt.home". All of them are SRV records, describing which computer and service is listening. For example, LDAP over TCP can always be found at _ldap._tcp.witt.home:389, which is test1.witt.home with address 10.1.1.11 (also test2.witt.home with 10.1.1.21).

The preceding case is for a single domain, single-site forest, where all services are located on the same hosts. This information also gives names, in our case, Default-First-Site-Name and internal IDs of services 03c6ee0d-3165-46de-88e-bb24a57794ea and 10a27226-4269-4a85-a939-e693e9a58bf8.

## LDAP Probing

To conduct an LDAP probe, we use one of the utilities provided by Microsoft as part of their Windows 2000 Support Tools package—LDP.exe. It is called “Active Directory Tool” there, but it has the same functionality as an LDAP browser (which can be used instead). As we saw before, even a simple anonymous connection gives a lot of information about a domain, starting from its name and the name of the site where it is located. Even more information can be obtained using simple LDAP queries. That information given is not an Active Directory fault—it happens by the nature of LDAP protocol and cannot be easily mitigated. In the following examples, we suppose that you know how to use a LDAP browser and that you also have some basic notion of naming schemes and construction of queries.
