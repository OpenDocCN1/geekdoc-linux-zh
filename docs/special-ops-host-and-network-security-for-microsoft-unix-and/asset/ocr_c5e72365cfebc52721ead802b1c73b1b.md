# Service Accounts

During installation, you will be prompted to provide an account under which the SQL Server and SQL Agent services will run. For many users (system administrators for that matter), it is very tempting to select LocalSystem as the account context does not require an existent account password. However, leaving SQL Server running with such high security context is dangerous should vulnerabilities develop in each SQL Server or an application based on.

Take the time to create a low-privilege account prior to installation. The account can be a local user as long as no file system access to other systems is required, as might exist in a nightly job that copies files to another server or some replication scenarios. The account should have a strong password and be unique to the machine in which they are used. It is acceptable to use the same account for SQL Server and SQL Agent services, but you are welcome to use different accounts if your security requirements demand it.

# Cleanup

SQL Server has had a checked past when it comes to installation procedures due to its tendency to leave credentials lying around (www.microsoft.com/technet/review/default.asp?url=/technet/security/bulletin/MS02-035.asp). Take time to check all temp directories for secrets during SQL Server installations as well as service pack installs. It would be a shame to implement a 25-character, complex 'sa' account password and leave it sitting in a temp directory some-waiting for someone to stumble across it.
