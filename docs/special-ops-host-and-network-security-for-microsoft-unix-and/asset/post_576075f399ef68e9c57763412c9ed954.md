First, you must learn to update your policies to include the latest threats and published vulnerabilities. For instance, if a new worm were to be exploiting users via a Trojan-introduced game, in most cases you wouldn't want this game to be executed within your network. One way to eliminate the risk would be to disallow it to propagate through the e-mail system by file mailboxes; however, that does not completely address the problem since it doesn't prevent users from downloading it via the network. You could create a hash-based rule that would disallow the computer from executing that particular file, similar to the method previously detailed in the "Software Restriction Policies" section.

The second reactive measure you must take is monitoring new programming languages and executables on the Internet. Common file extensions as .zip, .exe, .dll, and .doc are well known descriptors that quickly flag within the software policies. However, if a new programming language as Visual Z Sharp was released with an extension of .vsz, Policy would not flag it as an executable file type. Proper rules should be created to combat these new executable languages. Reference the “Software Restriction Policy” section for information on creating restriction rules.

## Verify Shared Resources and Connections

If you are a traveling professional, it is important that you remember to occasionally check your mapped drives and shared resources. In many cases, when you map a drive to your machine you may use a different set of authentication credentials. These drives are not the same as resources that automatically connect to joining a domain. For instance, when you join a first network and have a mapped drive configured to reconnect at logon, the system sends a broadcast message outwards in search of the Remote system. That broadcast may be in the form of a system name or IP address, the fact remains that you may be broadcasting that sensitive information about other networks.

In the following case, you will see a resource descriptor that has the status Unavailable. The Unavailable status informs the user that your system cannot locate the requested system. To identify your network connections, open a command prompt and type net use. It displays resources that your system currently lists and for the current status of the connection.

```
C:\net use
```

New connections will be remembered.

| Status | Remote | Network |
| --- | --- | --- |
| Disconnected L: | \\system\sharedfiles | Microsoft Windows Network |
| Disconnected M: | \\10.0.300\music | Microsoft Windows Network |
| Unavailable Z: | \\client\workdocs | Microsoft Windows Network |

## Anti-Virus

It is extremely important to maintain a good anti-virus policy within your organization, in addition to the program that you have established for your local systems and workstations. Anti-virus is one of the specialized technology markets where the commercial versions are significantly better than the freeware or shareware. A few AV products exist but are inadequate to protect against the highly fluctuating malicious code to the extent they aren’t worth the installation time. Current commercial AV software can protect against macro-viruses, Trojans, Rootkits, malicious mobile code, backdoors, e-mail-borne threats, and other types of application and language specific vulnerabilities. These are the current commercial industry leaders:

- Trend Micro (www.trendmicro.com)
- McAfee Security (www.mcafee.com)
- Symantec (www.symantec.com)

## Log Storage and Monitoring

System event and performance logs are crucial in identifying numerous types of system bugs, intrusions, application-layer attacks, buffer overflows, denial of service-attacks, and multiple other types of vulnerabilities your system has been exposed to. A log storage and monitoring policy should be implemented to consistently monitor for these types of potential errors. To view your logs in XP Professional, open a MMC session and import the plug-ins via the allowable snap-ins, as shown in Figure 4.22. Follow these steps to monitor your performance logs:

1. Click on the Start button and then click Run.
2. Type MMC and click Enter.
3. Click File and scroll down to Add/Remove Snap-in.
4. Click Add and notice the new active window that has appeared.
5. Select Event Viewer and click Add.
6. Scroll down to select Performance Logs and Alerts and then click Add.

After you have proved the snap-ins into the MMC, you can parse through the logs in order to determine what errors or alerts have been flagged within the specified auditing policy. As you can see in Figure 4.23, the IPSec service has failed to initiate upon the system boot sequence. You can obtain detailed information pertaining to this error if you simply double-click upon the entry. The Properties window specifies the type of failure, a brief description, and user (in this case the system network service was flagged as the user meaning it is spawned by an internal system process), and the time in which the error occurred. The timestamp is probably the most important detail here besides

## Applications and Tools Used in the Chapter

Numerous system assessment and hardening tools were utilized throughout this chapter in addition to general network and packet analysis tools. The following is a concise summary of the tools that were presented and the current locations where you can retrieve them:

- IPSECMD.exe IPSECP.exe is included with Windows support tools (www.microsoft.com).

- HFNetChkLT HFNetChkLT is a free tool available for determining and reporting on systems that lack Windows patches and hotfixes (www.shavlik.com).
