# Publishing Web Content

+   To discern which files on the Web server are required, which were dumped by employees, and which are Trojan scripts placed by hackers, maintain control over the Web server's content with a structured content publishing procedure.

+   Maintain control over the Web server's content in the following ways: Gather all files in a staging area for testing and review; set the time and date stamp on each file; calculate CRC32 and MD5 checks on all Web content; and build an entirely new directory structure when performing major updates to Web content.

+   Q: My server logs are constantly filled with nimda scans. Is there anyways I can prevent these from cluttering my log files?

+   A: You can do this by setting the UsePathReject to 1 in the URLScan.ini file. This will cause URLScan to immediately reject a URL without any further processing or logging by IIS. However, URLScan will record the attempt in its own log file. Note that using this setting bypasses any custom 404 error handling you may have set up for your site.
