The second most popular DNS server is Microsoft DNS. However, this state is slightly misleading: Microsoft DNS is the widely used *internally* along with its semipopular external use. Because of its ease of use and comfortable Windows platform, most average administrators do not get the chance to learn the DNS system from an advanced point of view. Because of this, proper external use of Microsoft DNS is uncommon. Even sites as msn.com and microsoft.com are rumored to be hosted on DNS servers running BIND.

> NOTE
Microsoft DNS is the only common DNS daemon that is not freely available for download.

DJBDNS, written by the respected mathematician and computer science enthusiast DJ. Bernstein (http://cr.yp.to), is the most interesting and recommended of the three daemons. It is the most secure DNS daemon available, but it is also the most technically complex. Currently, only advanced administrators are running this in production, and it is used most by those with high security requirements.

# Hardening the OS

Before installing any daemon, OS hardening should be a requirement. Our examples use a hardened Linux OS with the grsecurity (www.grsecurity.net) kernel patched.

On a Unix platform, daemons should always run within a *chroot* environment. *chroot* environments are simply unable to interact with any part of the file system outside of their jail. Running BIND in this type of environment limits the amount of access a malicious attacker might have if BIND was exploited.

To minimize buffer overflows and exploitation within the BIND binaries themselves, secure compilers combined with the newest stable BIND version should be used. BIND can be found in the Internet Software Consortium (ISC) Web site (www.isc.org/products/BIND).
