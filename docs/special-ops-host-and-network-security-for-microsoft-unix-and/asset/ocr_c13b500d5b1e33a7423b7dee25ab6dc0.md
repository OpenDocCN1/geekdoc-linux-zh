# Attacking and Defending Windows 2000 • Chapter 5

# Summary

Windows 2000 presents some unique challenges to the console security professional when it is used in the enterprise environment. Although very user friendly, it is subject to attack from many directions administrators are not aware of the potential places for breach. During the course of the chapter, there have been opportunities to explore some of the default features of Windows 2000 and view how they operate out of the box as far as availability and security are concerned. The topics explored have revealed that there are some potential problems that exist in out of the box configuration, such as permitting null passwords for authentication when using anonymous accounts for access. Tools are included and available with the operating system to better secure the default configurations according to your needs. These included Windows 2000 Support tools, and use of management consoles customized to perform necessary configuration tasks and apply security templates.

Working with the security templates, I included instruction that provided a framework to create a custom management console to view, analyze, and implement the features of security templates, which are used to create a custom and more secure configuration for Windows 2000 machines. In the basic setup, a strong template and an equally strong password policy puts you on the road to better security in your operation of Windows 2000 clients and servers.

I looked at some of the methods that attackers use to try to gain control of your systems and detailed the processes that an attacker can use to successfully bridge your system. There is a pattern that is used, and the chapter discussed the stages that occurred in this order:

+   * Footprint victim systems.
* Scan for entry points.
* Enumerate possible entry points.
* Get passwords.
* Attack.

At this point, following the path of an attacker, it was discovered that the basic operating system can be vulnerable if administrators leave some default conditions in place and services running that they don't need. Prime these in the Windows environment is the use of NetBIOS functions for network browsing and file sharing, which exposes the network to attack.
