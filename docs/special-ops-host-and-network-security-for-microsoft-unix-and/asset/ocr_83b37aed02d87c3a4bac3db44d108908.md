# Auditing

Auditing is the process of collecting data from different system events such as login, process execution, the changing of file attributes or parameters, and actions related to privileges. When logged, audit data can be used to identify attempted attacks or other misuse of a system. Audit data is typically stored as binary information, and requires a suite of tools to log and review.

# Auditing in Commercial Unix

Solaris performs system auditing through the Basic Security Module (BSM). The level of auditing BSM that is capable of is configurable. BSM is enabled using the `bsmonrun(1M)` command, and disabled using the `bsmonun(1M)` command. The `audit(1)` command is used to control the behavior of the audit daemon, and the `auditconfig(1)` command is to change the audit configuration. BSM is a relatively complex infrastructure with many utilities and configuration files. The level of auditing provided by Solaris is expensive in terms of system resources, so it should be noted that the more auditing is performed, the more expense is incurred. More information about the Solaris Basic Security Module can be attained from the System Administrator Guide: Security Services section of the Solaris 9 12/0 System Administrator Collection at http://docs.sun.com/db/doc/816-4883, and also from Solaris BSM Auditing by Darren J. Moffat at http://online.securityfocus.com/infocus/1362.

HP-UX employs some auditing functions by default. Auditing can be controlled through the SAM interface. Users who prefer the command line interface use `audys(1M)` to start and stop auditing, `audus(1M)` to select the audit to be audited, `audevent(1M)` to change or display event information, `audit(1M)` to change the audit file size and parameters, and `audisp(1M)` to view the audit record. More information about auditing in HP-UX can be gathered from the Auditing section of the HP Technical Documentation at http://docs.hp.com/cgi-bin/onlinedocs.py?conf=false&mpn=B2355-90672&service=hpux-path=../B2355-90672/00/01/124.

AIX also includes auditing capabilities. The auditing daemon is controlled by the `aud(8dex)` command. A list of auditing events is viewed with the `audevent(8dex)` command. `audfilter(8dex)` is used to manipulate the audit files on a host, and `audtrail(8dex)` is used to read the audit trail. IBM has made more information available at the IBM DCE for AIX page located at www-3.ibm.com/software/network/library/publications.
