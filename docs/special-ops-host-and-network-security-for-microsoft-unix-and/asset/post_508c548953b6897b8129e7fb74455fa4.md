## The Internet Explorer JavaScript IE Modeless Pop-Up DoS

The JavaScript IE reboot attack exploits flaws in Internet Explorer to the extent that it automatically requires the system to restart by consuming all of the resources. The implementation of IE allows an indefinite loop to be created that continuously pops up new browsers until you cannot stop the ongoing process. The attack is exponentially aggressive since each new thread of the attack starts a new thread of the continuous loop.

The following is the JavaScript code to exploit the attack. You must place this HTML code into a file called `fploit.html`.

  }

</body>

## The Internet Explorer XMLHTTP Active X Bug

The Internet Explorer XMLHTTP Active X bug allows a remote server to retrieve and read arbitrary files located on the target system. It has not proven capable for modifying, deleting, or writing to any system files or directories. The XMLHTTP control is bundled with the Microsoft core XML services that are used in parsing XML formatted data. It allows for the system to use Hypertext Transfer Protocol (HTTP) functions such as GET, POST, and PUT to aid in using XML files. Microsoft's software flaw was its implementation of the security control over a redirected data stream from a request to a Web site.

In order for the vulnerability to work, the malicious user needs to know the complete path to the target file on the target system. A suitable target file is a file that is located on all systems and is in cleartext. Another obvious prerequisite of the attack is that a user must initiate a connection to a malicious Web site. Because of this, it is hard to target specific systems. Moreover, the malicious site and attacker would target site visitors using a vulnerable browser on a specific operating system. ## The XP Restore Bug

Microsoft Windows XP Professional and Home editions store sensitive restoration in the System32 Volume Information directory. Via a default installation this directory has adequate access controls and permissions; however, unless reconfigured, the subfolders do not inherit these controls. This vulnerability is also one of local access that would allow a malicious user to gain sensitive information and also the potential of placing executable code in shared space. ## The Internet Explorer 6.0 Upgrade and Downgrade Issue

A problem has been identified in the upgrade process from a previous Windows system to XP Professional. It is an atypical problem because it is not the common type of vulnerability that can be exploited remotely or even locally. However, one can utilize a flaw in the upgrade process designed by Microsoft. The situation exists when you are upgrading an old system such as Windows 98 or 2000 to XP Professional and you already have a patched version of Internet Explorer 6 installed. It was published that the IE 6.0 patches and hotfixes do not roll over with the system upgrade, leaving an unpatched browser. The vulnerability increases in risk when users may believe they are running a completely patched version of Internet Explorer 6.0, thus thinking they are invulnerable to multiple browser client-side type attacks such as information disclosure and arbitrary code execution.

One other issue that may pose an obstacle is that Microsoft does not provide the capability to provide the old patches and hotfixes via the automated Windows Update service. This poses serious issues when attempting to lock down your system from a server and client perspective.
