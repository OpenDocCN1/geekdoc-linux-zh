I would recommend that you test each tool against the same range of addresses and analyze the results of each tool. Be sure to select a range that is indicative of the networks you are testing (that is, not test half of a Class C network, if you intend to use the tool to scan a Class B). Some tools don't scale well, so you should try to find this sooner rather than later.

# Test Scanner Performance

If you are responsible for a large network, scanner performance is probably important to you. A lot of factors affect the performance of the tool. Two of the more obvious factors are the scanner engine itself and how the vendor has decided to check for the existence of a vulnerability.Today, most products are multithreaded applications that allow for a bit of user tuning. The bottom line is when comparing scanner performance is that you are scanning multiple machines, you can only do so much to tune performance. Some vendors have addressed this problem by offering distributed scanning solutions that use multiple scan engines scan the network then report back to a central reporting console. In theory, this sounds like an acceptable solution, but it opens the floor to other issues, such as network bandwidth problems, and, of course, the potential security issues if the traffic isn't handled securely.
