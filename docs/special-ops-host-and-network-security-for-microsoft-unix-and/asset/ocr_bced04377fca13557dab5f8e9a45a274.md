# Protecting Against Cache Poisoning

Cache poisoning is easy to protect against. All DNS daemons have the option to turn off caching. If caching is not enabled, forging replies to a server is worthless. Most up-to-date daemons already have patches against poisoning.

Currently, packets received with authoritative records are verified before inputting them into the cache.

# Preventing Buffer Overflows

Buffer overflow mitigation can be very successful. Many tools have developed that aid in preventing unauthorized overly techniques. Anti-buffer overflow compilers such as stackguard (www.immunix.org/products.html#stackguard) should be used in conjunction with the newest DNS daemon within a chosen environment and restricting access limit exposure, truly stopping buffer overflows requires a secure platform from the ground up. A secure OS as OpenBSD and daemons such as DJBNS are the best to reduce the risk of overflow. OS customizations by Theo de Raadt and hardened DJB daemon software may seem extreme, but based on their track records, they are worthy of the administrative time and effort.
