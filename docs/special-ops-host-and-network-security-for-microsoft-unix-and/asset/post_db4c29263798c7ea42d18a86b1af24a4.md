
# Frequently Asked Questions

The following Frequently Asked Questions, answered by the authors of this book, are designed to measure your understanding of the concepts presented in this chapter and to assist you with real-life implementation of these concepts. To have your questions about this chapter answered and click on the www.synergy.com/solutions and the “Ask the Author” form.

- Q: We need to increase our internal network security. Should we buy a vulnerability scanner and scan our entire Class B internal network?
- A: No, you need to classify your assets, create security zones for scanning, then test each range based on the needs of the specified security zone.
- Q: Should we implement continuous assessment for our critical security zones?
- A: If you own a tool such as FoundScan or QualysGuard Int Scanner, why not use it to its potential? I would recommend a nonintrusive continuous scanner that will tell you if a new system comes online in these restricted networks. Then, depending on the size of the network, you should scan with intrusive settings every couple of days.
- Q: What should we do if a new vulnerability and exploit is released publicly in the wild?
- A: Don’t panic, first you need to update your vulnerability scanners to reflect the vulnerability (if your vendor has not updated their tool yet, then you can panic!). Scan your security zones starting with the most critical ones first, and based on the results assign remediation efforts for each zone to responsible parties as soon as they are completed.
- Q: Does the SANS/FBI Top 20 favor Unix or Windows?
- A: The SANS/FBI Top 20 is actually a list of the top 10 Windows vulnerabilities and a list of the top 10 Nessus vulnerabilities.
- Q: If Nessus is free, why should I buy an expensive commercial tool?
- A: If your management supports the use of free tools such as Nessus and you have the skill set to use it, then use other free tools, too; as with any security tool, don’t put all your eggs in one basket.

# Introduction

During his keynote speech at Comdex, Larry Ellison, CEO of Oracle, made the broad statement he went on to his database technology, Oracle 9, was "unbreakable." Mr. Ellison then went to say that users could "keep their Microsoft Outlook and we will make it unbreakable; unbreakable means you can't break it, and you can't break in." Later in his presentation, he went to talk about the significant resources had been spent and focused on research and security defenses within the database code itself in addition to its revamped clustering capability. Soon after, David Litchfield, a database security expert, announced that he had found numerous bugs in Oracle thereby allowing him to add an administrative account remotely in an unauthorized manner. What does this tell you? Nothing is "unbreakable," and not ever challenge the hacker community.

Another example of a gutsy initiative that had an opposite outcome was Bill Gates' XP statement. In cooperation with his marketing executives, Gates stated that "Windows XP is the most secure operating system, ever." After the declaration, vulnerabilities in Windows XP were discovered. According to statistics from the annual CSI/FBI Computer Crime Surveys, when measured by frequency of vulnerabilities and release time, XP doesn't even close to the first initial bugs for Windows 3.1. The point: Bill Gates made a bold statement; only if XP is configured properly his statement stand true that Windows XP is the most secure Windows platform to date.

It is obvious that a great deal of research and architecture redesign thoughts went into the Windows XP release. Besides the appealing appearance and graphical interface, dramatic increases in speed, media enhancements, user-friendly interface add-ons, and other efficiencies within the kernel, Windows XP has incorporated several aspects of client-specific security features. Windows XP, similar to Windows 2000 from a remote vulnerability assessment point of view, is very different considering the built-in in additional features when conducting a local configuration review or local vulnerability assessment.

# Upgrading to XP Professional version XP Home

Note that this chapter is written for Microsoft Windows XP Professional. A few areas in the chapter reference both Windows XP Home and Windows XP by using the broad reference “Windows XP”. Aesthetically, there is no difference between Windows XP Professional and XP Home, but there are a few technological differences between them. The most fundamental difference between the two is that only Windows XP Professional can be joined to a domain. Windows XP Home and Windows XP Professional are capable of joining a workgroup.

In addition to not having domain authentication, XP Home does not have access to the Remote Desktop feature. The Remote Desktop Protocol (RDP) feature is similar to Terminal Services and Remote Desktop allow you to connect to the console.

Another feature related to offline is the Working with Offline Files option. This provides users the ability to create mirrors of networked folders. The key component of this feature is that it can automatically synchronize the folder when the connection is available. The synchronization updates the client and vice versa.

# Attacking and Defending Windows XP Professional

A performance note, XP Home does not support dual processor capabilities. Hence, it would not be the ideal platform of choice for a high-end system that would require processor-intensive utilizations as graphics systems, highly-streaming media servers, or even an enthusiast's gaming station.

Lastly, XP Home does not come with the Encrypting File System (EFS), potentially the most significant security-related feature. Microsoft really hits home with this feature by making it extremely simple to use and all the actual cryptography functions, encryption and decryption, to encrypt “behind the scenes.” In XP Professional, you have to utilize EFS to encrypt a file by right-clicking the file and clicking Properties. Click on the General tab then click Advanced. As shown in Figure 4.1, to encrypt the file you must just check the Encrypt Contents to Secure Data option. There is no need for key management or additional passphrases to remember. In some cases, the EFS feature alone should be reason to upgrade to XP Professional rather than XP Home.

# Windows Features

The Microsoft Windows XP platform provides key features and enhancements over previous products, which is sure to make it the workstation OS of choice going forward. You must realize that even though some of the features and enhancements may not initially appear to be security-related, it is important to know the OS differences if you have to do any type of configuration analysis or forensic discovery; Windows XP integrates the best of the when it comes to features from previous Windows-OS versions. It has implemented almost all of the security features within Windows 2000. In addition to security, it has also implemented many of the user-friendly features from the Windows 95/98/ME era, the Plug and Play component (which I exploit later in the chapter), quick time to boot, and easy user-based localized management.
