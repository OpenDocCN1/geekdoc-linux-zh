
Creating a security baseline is very important when beginning to analyze the security of your operations. It is important to fully evaluate the characteristics and potential vulnerabilities of each portion of the system. This includes recording and knowing the basic settings of your operating system(s), network protocol(s), network devices, and applications related to security. Following that initial evaluation, appropriate adjustments be made to the settings to more fully secure what you have.

## Creating Security Templates

While preparing to provide security in the Windows 2000 environment, administrators can use several Microsoft-provided tools to get a more realistic view of the security levels established (or not established, as the case may be) in the configurations that have been created or after setup. Microsoft provides a couple of tools within the MMC toolkit that are very helpful in comparing various levels of security configuration and creating a security templates and model that is acceptable and useful in a particular setting. In the following sections, I discuss the toolkit and what can be done with it in the analysis arena, and then how to use the tool to configure machines appropriately to your needs.

## Analyzing Security Policy Templates and Machine Security Configuration

One of the first functions that can be utilized within the Security Configuration and Analysis toolkit is the capability to compare security settings among various templates with current machines, and with each other. This allows you to determine if the default configurations of the Microsoft supplied templates are valid for your needs, or whether a needs exists to customize and apply your own templates. ## Customizing and Creating Security Templates

After you have had a chance to analyze the current and possible security settings and configurations available through the stock templates, you may well find that the stock settings do not give you the level of security you want. In many cases, the hisec** templates are more restrictive than your climate will allow, and the basics templates are not just enough to keep you protected. For instance, if you apply the hardening principles I discuss later in the chapter to a machine that has extra configured on it, such as Exchange 2000 or SQL 2000, you may find that there are unintended consequences to those applications and you really need a custom configuration to allow for your particular needs. In that event, you can customize or build your own templates that contain the settings you need. To accomplish this, save any of the existing templates with a filename you choose by highlighting the template name and choosing Save As. Using the Import Template procedure in the preceding section, you import the new template and modify its content to suit your needs. Be sure to check the box Define this policy in the database for changes you saved to the template. This is illustrated in Figure 5.15.
