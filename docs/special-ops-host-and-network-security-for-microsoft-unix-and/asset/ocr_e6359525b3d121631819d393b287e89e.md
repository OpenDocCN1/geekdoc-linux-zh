The information from enum in this case lets the attacker know that there is no restriction on failed attacks on passwords (lockout threshold: none) and that it can be continually worked on when performing that.

The process of enumeration provides a detailing of the currently active Windows systems, and also quick checks for connectivity and security. Again at the command line, the attacker types a command to check for the ability to create a null session connection. If proceeding from the information gathered so far, the attacker would type the command: net use \machinename\ipc$ "" /u (substituting the appropriate machine name in the network being attacked) would attempt a connection to the hidden remote login share on the machine with a null password. If successful, this logon could be used to retrieve information using tools such as the DumpSpec tool mentioned previously. This is a common entry point in Windows 2000, because null session communication is allowed in the default security settings. Of course, the normal TCP/IP nbtstat command can be used as well. This will add to the information base by providing lists of services and names for the machines that have been identified. If the command nbtstat -A 192.168.25.66 (substitute the IP address as appropriate to your environment) was entered in a command it would retrieve a full listing of names and NetBIOS service markers for services in use the particular machine. This defines more information to use in a list of potential spots for entry into unprotected or incorrectly configured system, and is illustrated here:

```
C:\nbtstat -A 192.168.25.66
```
