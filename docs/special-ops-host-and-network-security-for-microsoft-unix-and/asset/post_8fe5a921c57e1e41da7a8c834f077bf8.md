## Summary

How secure do you want to be today? I know the answer already. You want to be as secure as you can possibly be. There is a fairly well known security axiom that states “You should be as paranoid as it is cost-effective to be.” All of the things I have mentioned in this chapter are reasonable steps when it comes to securing your data. The only thing that I consider “extreme” is rolling out S/MIME capabilities for your entire community.

This is the paradox of security. How much administrative effort (and cost) is worth securing your organization? If your organization is Exchange primarily for securing messages about lunch, storing contacts, and appointments, you should take reasonable efforts to secure this data. The more sensitive the data you are sending back and forth, the more “extreme” you should become. No one can make this decision except for you and your superiors. The question that you need to be asking is “How much more money is it worth to be ‘extremely’ versus just secure?”

Throughout this chapter, I covered some of the basic architectural components of Exchange 2000 and outlined Exchange’s dependency on Windows 2000, Internet Information Server, and Active Directory. When you begin the process of securing Exchange 2000, these are the components you have to start with.

I also discussed many of the vulnerabilities with Exchange 2000 (and other messaging systems.) You must take steps to identify these problems in your own environment and decide which of these needs to be fixed and balance the cost and benefit of addressing some of these.

Finally, you need to ensure that you are auditing the important events that occur on your system so that you can adequately respond to problems and intrusions. As long as you follow good operational procedures and best practices, you can keep your Exchange 2000 system running and safe from intruders.

## Solutions Track

### Introducing Exchange 2000

- Exchange 2000 is tightly integrated with Windows 2000 and Internet Information Server.
- Exchange 2000's basic architecture is similar in some respects to Exchange 5.5; the significant difference is that Exchange 2000 does not have its own directory service.
- An additional load will be placed on the Windows 2000 domain controllers and global catalog servers for each Exchange 2000 server.

### Understanding the Basic Security Risks Associated with Exchange 2000

- Administrative mistakes can give users or unauthorized administrators permissions to manage Exchange 2000 servers or even to open users' mailboxes.
- Emessages, when transmitted via SMTP, are inherently insecure.
- Using Windows 2000 login names as part of the SMTP address is a bad security practice.
- Exchange data files and log files on Exchange 2000 servers can give away a lot of information to an intruder.
- The Windows 2000 operating system must be properly secured; this is the biggest vulnerability for Exchange 2000.

### Preventing Exchange Security Problems

- Service packs and security fixes must be up-to-date on all Exchange 2000 servers as well as Windows 2000 domain controllers.
