
## Role-Based Accounts and Commercial Unix

As previously mentioned, some Unix operating systems have modified the existing infrastructure of the operating system to provide expanded capabilities for role-based accounts. Solaris is an example of this, using the `su(1M)` program to allow the changing to a role account. Solaris also uses the `roleadd(1M)`, `rolemod(1M)`, and `rolelet(1M)` programs to manipulate local system roles. The `roleadd` program is used to add roles, the `rolemod` program modifies existing entries. The `rolelet` program is used to remove previously entered roles. The `smrole(1M)` command is used on Solaris with roles that are handled through a name service, such as NIS/NIS+ or LDAP.

More details about role-based access control in Solaris are outlined in the System Administrator Guide: Security sections of the Solaris 9 12/02 System Administrator Security Collection at http://docs.sun.com/db/doc/816-4883. Solaris Operating Environment Security, by Alex Noodergaert and Keith Watson, located at www.sun.com/solutions/blueprints/1202/816-5242.pdf, also provides good documentation of a role-based access control configuration.

Other Unix operating systems such as AIX and HP-UX provide this functionality, though the semantics vary slightly. For example, AIX uses the `mkrole` command to create roles, `chrole` command to change role attributes, `isrole` command to list role information, and `rmrole` command to remove roles. Role-based accounts are handled through the Service Control Manager software package for HP-UX.

## Role-Based Accounts and Linux

Currently, the only Linux that supports role-based access control by default is NSA Security-Enhanced Linux (NSA SELux). NSA SELux is a project that was launched by the U.S. National Security Agency (NSA), which resulted in a suite of patches that may be applied to Linux systems to provide additional security capabilities. One of the primary features of the project is integration of role-based accounts. NSA SELux contains other features such as mandatory access control policies, which limit the amount of privileges granted to any one process, and thus prevent compromise of system integrity in the event of compromise of a service. Other information on NSA SELux is available at www.nsa.gov/selux.

Also available for Linux systems is the Rule Set Based Access Control (RSBAC) package, which provides role-based accounting functionality. This package is a base implementation of role-based accounts, and provides only role-based account functionality. The RSBAC project is located at www.rbac.org.

## Auditing

Auditing is the process of collecting data from different system events such as login, process execution, the changing of file attributes or parameters, and actions related to privileges. When logged, audit data can be used to identify attempted attacks or other misuse of a system. Audit data is typically stored as binary information, and requires a suite of tools to log and review.

## Auditing in Commercial Unix

Solaris performs system auditing through the Basic Security Module (BSM). The level of auditing BSM that is capable of is configurable. BSM is enabled using the `bsmonrun(1M)` command, and disabled using the `bsmonun(1M)` command. The `audit(1)` command is used to control the behavior of the audit daemon, and the `auditconfig(1)` command is to change the audit configuration. BSM is a relatively complex infrastructure with many utilities and configuration files. The level of auditing provided by Solaris is expensive in terms of system resources, so it should be noted that the more auditing is performed, the more expense is incurred. More information about the Solaris Basic Security Module can be attained from the System Administrator Guide: Security Services section of the Solaris 9 12/0 System Administrator Collection at http://docs.sun.com/db/doc/816-4883, and also from Solaris BSM Auditing by Darren J. Moffat at http://online.securityfocus.com/infocus/1362.

HP-UX employs some auditing functions by default. Auditing can be controlled through the SAM interface. Users who prefer the command line interface use `audys(1M)` to start and stop auditing, `audus(1M)` to select the audit to be audited, `audevent(1M)` to change or display event information, `audit(1M)` to change the audit file size and parameters, and `audisp(1M)` to view the audit record. More information about auditing in HP-UX can be gathered from the Auditing section of the HP Technical Documentation at http://docs.hp.com/cgi-bin/onlinedocs.py?conf=false&mpn=B2355-90672&service=hpux-path=../B2355-90672/00/01/124.

AIX also includes auditing capabilities. The auditing daemon is controlled by the `aud(8dex)` command. A list of auditing events is viewed with the `audevent(8dex)` command. `audfilter(8dex)` is used to manipulate the audit files on a host, and `audtrail(8dex)` is used to read the audit trail. IBM has made more information available at the IBM DCE for AIX page located at www-3.ibm.com/software/network/library/publications.

## Auditing in Linux

Linux does not have any built-in low-level auditing facilities in most default implementations. Previously, if this gap existed, it was filled by the daemon auditd, which was maintained by the Hacker Emergency Response Team (www.kert.org). However, maintenance of this tool seems to have fallen by the wayside.

## Non-Executable Stacks and Commercial Unix

Solaris allows the setting of non-executable stack through /etc/system by adding the parameter `noexec_user_stack=1`. It should be noted that adding this to /etc/system will only affect processes created after. Therefore, the system should be rebooted to ensure that processes are insulated with this. More information about this kernel parameter and others can be gained from Solaris Kernel Tuning For Security by Ido Dubrawsky at http://online.securityfocus.com/infocus/1385, and also from Solaris Operating Environment Network Settings for ordergaard and Keith Watson at http://www.sun.com/solutions/blueprints/1299/network.pdf.

HP-UX also provide a non-executable stack with 11i and later. The non-executable stack can be enabled by setting the kernel parameter `executable_stack` to zero. Other parameters may be available that can have an impact on system security. More information about non-executable stacks and kernel parameters in HP-UX is available through Execute Protected Stacks from the HP-11i Release Notes at http://docs.hp.com/cgi-bin/linedocs.py?toc=false&mn=B2355-90672&service=hpux-path=../B2355-90672/00/01/124.

Information about IBM's AIX and tunable kernel parameters is available through Tunable Parameters from the IBM Performance Management Guide at http://pub16.boulder.ibm.com/pseries/en_US/aixman/pftungngl/23654.htm.
