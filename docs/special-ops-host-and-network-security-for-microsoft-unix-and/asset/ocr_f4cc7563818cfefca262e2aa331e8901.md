# Implementing Secure SNMP and IPSec

SNMP is the most utilized network management mechanism in place. Almost all vendors include SNMP management information bases, and MIBS, for their devices. These MIBs collect the data that will be polled by the SNMP agent. Given that SNMP is such a widely used tool, it should come no surprise that most versions of the protocol are completely insecure. In versions one and two, the authentication is the community strings for SNMP and read permissions. These community strings, although they have a catch, are still passphrases that are stored on most network devices in clear text. Furthermore, these community strings, unless encrypted with a different technology, are passed on the wire in clear text, making it easy for someone sniffing your network to pull the passphrases. Recently, SNMP worms have been released for devices with null read and write strings, or for devices that have “public” as their read string, which is generally a device’s default configuration.

Securing the protocol isn’t as tough as you can imagine. Some vendors have begun to implement version 3 of the protocol. Inherently, this new version supports encryption and authentication, huge advantages from the previous implementations. Because not all vendors support the new version, it becomes difficult to use it as a standard within your environment.

Additionally, take a look at the devices that you currently monitor via SNMP. Do all of them need to be monitored? Some rarely need to be polled and have SNMP disabled on. Furthermore, even if a device has to be monitored with SNMP read access, need to ask yourself: do I need to change the record and therefore necessitate a SNMP Write permission?
