# ### Table 7.12 Recommended Audit Policy Events

| Policy | Explanation |
|---|---|
| Audit account logon events | Audits logons using domain accounts
 Audits changes to accounts, such as passwords being reset or group membership changes. The audit event does not always generate the detail I would like, like if an account is enabled or disabled, just that the account is changed. |
| Audit logon events | Audits logons using accounts that are local to the member server |
| Audit policy changes | Audits policy changes such as changing the audit policy |
| Audit system events | Audits events such as system shutdown or restart |

> Windows 2000 event logs can grow to quite a significant size quickly. The default size for these logs is 512KB, and they overwrite data that is only older than seven days. Administrators frequently ignore the warning that an audit log is full and later wonder why they don't complete information in their audit logs. Increase the size of your audit logs to a useful and reasonable size. For a typical Exchange 2000 server hosting 1,000 mailboxes, I don't believe it is unreasonable to have log files of 20,480KB (20MB) or even larger. I highly recommend increasing all of your servers' maximum event log sizes to at least 20MB.

Although I am not a fan of configuring an audit policy that covers every activity that occurs on a server, I also shy away from minimal auditing and auditing that examines only failures. Each additional audit policy you place on the server increases the load on the server by some amount, and it increases the size of the security log files. If you are truly concerned about logging events that may affect the security of your system, you will log not events where someone has tried and failed to accomplish something, this has been my philosophy for some time and it has served me well; though some people think I'm a bit paranoid.
