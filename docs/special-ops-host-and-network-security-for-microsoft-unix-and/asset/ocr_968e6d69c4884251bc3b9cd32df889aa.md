# Reconnaissance

The first phase of every attack on a network is, of course, gathering information about it and probing for the available services. Active Directory is a large store of information and is very interesting from the attacker’s point of view. It can provide attackers with all the data they’ve ever needed to discover the structure and interaction of various parts of our object. Two common ways of probing data are using DNS SRV resource records created by Active Directory, and querying the directory itself—via an LDAP interface.

# DNS Probing

As we already know, Active Directory uses DNS extensively for locating providers of specific services. These include domain clients controlled by users to log in to the domain, Kerberos-related services, Global Catalog servers, and so on.

The first example of information about a domain provided by an Active Directory–integrated DNS will be the simplest one. Assume that the server allows zone transfers. This is the default setting. The idea of making it default makes system administrators’ lives easier, so that they do not have to worry about specifying authorized servers for zone transfers—just install and go. Unfortunately, as always, ease of network interaction conflicts with security needs.
