Here is an example of an SRV RR that will look for a service from one of two different servers:

```
ldap.tcp.wit.home SRV 0 0 389 dns1.root.com
SRV 1 0 389 dns2.branch.root.com
```

DNS servers for the zones that the RRs for an Active Directory must be compatible with Active Directory, or Active Directory will not function. even one DNS server is incompatible for that zone, problems ensue. For example, if a secondary DNS server for AD.DOMAIN.COM is not compatible because it does not support SRV RRs, at any point in time on the network could query incompatible DNS server and not find the SRV RRs needed to locate Active Directory (because they are eliminated automatically from secondary zone due to not being understood). This situation is worse if the incompatible DNS server is primary for the domain, then all zone update the secondary servers with a database that does not include SRV RRs.

The requirement of being able to contact a compatible DNS server by Active Directory DCs is absolute. When a Windows 2000 Server is promoted to a DC, it must have a DNS server available to it. If there is no DNS server discovered, the wizard offers to install the DNS service. However, this does not resolve the need for DNS because it will not create the RRs needed for the Active Directory domain’s zone.
