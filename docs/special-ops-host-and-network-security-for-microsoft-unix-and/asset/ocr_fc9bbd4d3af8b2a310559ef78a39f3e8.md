# Creating Awareness via Pure Enforcement

In a pure enforcement awareness campaign, you count on feedback from automated-defensed systems to provide awareness back to your user base. A prime example is a content filter scheme that responds to forbidden requests with a customized message designed not only to inform the user that their request has been denied, but also to remind them that when using corporate resources, their activity is subject to scrutiny.

This approach can be quite effective, in a fashion similar to that of authenticated proxy usage described in the "Who, What, Where? The Case for Authentication and Logging" section earlier in this chapter. However, there is the potential for this method to backfire. If users regard their IT department in an adversarial fashion, they may be afraid to ask for help at some of the most critical junctures, when erratic system behavior makes them fear they have a virus. If a user opens an e-mail and finds themselves facing a pop-up dialog declaring, "Your system has been infected by the $0p4h-l33t k14n!" then decides to go lunch and hope that another employee takes the fault for introducing the virus, your pure enforcement awareness campaign has just given a new virus reign on system.

There's another technique I've heard discussed for enforcement-based awareness campaigns, which I have never heard of putting into practice. The idea was to distribute a virus-like e-mail to a sampling of corporate users to evaluate how the users handled the message. The subject would be based off the real-world social-engineering successes of viruses such as LoveLetter or Melissa, as "Here's the file you requested." With the message having a from of an imaginary user, the idea was to see how many users opened the message either using built-in notification, logging accesses to an intranet resource requested by the message, or including a copy of the Eicar test virus (not actually a virus, but an industry-accepted test signature distributed by the European Institute for Computer Anti-Virus Research, www.eicar.org) to see how many of the recipients contacted the help desk, or if centralized reporting is enabled. Depending on the results, users would either receive a congratulatory notice on their handling of the message or be contacted by their local IT administrators to ensure that their antivirus software was installed and configured correctly, and explain how they should have handled the message. Again, this approach could be construed as contentious, but if the follow-up direct communication is handled properly this sort of fire drill could build an undercurrent of vigilance in an organization.
