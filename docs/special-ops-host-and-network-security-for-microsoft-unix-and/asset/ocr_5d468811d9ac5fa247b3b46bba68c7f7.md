# Keeping Up With Service Packs and Hotfixes

This is the most important area of your SQL Server maintenance tasks, and it can be the most daunting. At the time of this writing, Windows Update does not support detection of SQL Server packs and hotfixes. You might think the SQLPing tool would be useful for determining patch levels, but the UPD 1434 Resolution Service does not show the version changes (generally only original release version). The most reliable way to detect service packs is to look under the server's Properties in Enterprise Manager or manually request the version by querying the server so:

```
Select @version
go
```

Note that the version changes will reflect only service packs. Hotfixes do not alter the version numbers, so you'll need to keep track of those manually.You can return the version information from various lists like as at http://yaskrip.com/sqljps.htm to be sure you are up to date. Another option is to use Microsoft's HFNetChk tool at www.microsoft.com/security to scan machines for out of date SQL Server installations. A nice feature of HFNetChk is that it scans each instance of SQL Server installed and reports on each instance separately, so it's easy to pinpoint rough changes that are woefully out of date and compromising your security. For more advanced functionality, the ability to push patches, HFNetChkPRO at www.shavlik.com.

As far as applying the service packs and hotfixes, Microsoft has not made this process simple or straightforward for all large enterprises. Besides applying the fixes to all instances (or at least making the default), the process is still largely manual. You can automate this using your own enterprise management tools (such as SMS or Tivoli) or by using one of a myriad of third-party tools, such as HFNetChkPRO (www.shavlik.com), Service Pack Manager 2000 (www.securitybastion.com), or UpdateExpert (www.updateexpert.com).
