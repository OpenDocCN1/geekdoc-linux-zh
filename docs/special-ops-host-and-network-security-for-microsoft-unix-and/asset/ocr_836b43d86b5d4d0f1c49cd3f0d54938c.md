# Figure 3.8 The SPIKE Script Created by httpwizard

```
s_string="POST /exchange/dive/Inbox/asdf HTTP/1.1";
s_string2="Host: 192.168.1.103";
s_string3="Content-Type: application/x-www-form-urlencoded";
s_string4="Content-Length: 285";
s_block_start("post");
s_string.append(s_string);
s_string.append(s_string2);
s_string.append(s_string3);
s_string.append(s_string4);
s_block_end("post");
s_string5="%3Aschemas%3Ahtmail%3AImportance=3%3Asubject=asdf&%3Aschemas%3Ahtmail%3Abody%30%3Adescription=%3D0AasdfFcd=submitpost&CMdReferring=newpost&MsgID=&EmbeddedID=0&ReadFormat=1MsgClass=Imp";
```

Although SPIKE scripts look like C, they are actually interpreted on the fly by SPIKE. Note the function call to `s_blocksize_string(string)` is keyed to the word "post" and later in the script, the "post" block is opened and ended around the actual posted variables. The string "post" is just an identifier; SPIKE neither knows nor cares what the data between the block actually is, it simply calculates the size when it sees `s_block_end()` and fills that in where `s_blocksize_string()` told it to.. # Figure 3.9 SPIKE Running Against Remote Web Server

```
Request:

POST /exchange/dive/Inbox/asdf HTTP/1.1

Host: 192.168.1.103

Content-Type: application/x-www-form-urlencoded

Content-Length: 285
```

```
&%3Aschemas%3Ahtmail%3AImportance=3&%3Aschemas%3Ahtmail%3ASubject=asdf&%3Aschemas%3Ahtmail%3Abody%30%3Adescription=%3D0AasdfFcd=submitpost&CMdReferring=newpost&MsgID=&EmbeddedID=0&ReadFormat=1MsgClass=Imp.*&
```

As you can see, the string `s%3Aschemas%3Ahtmail%3AImportance=1` has changed to a common directory traversal attack. The **Content-Length** field is automatically adjusted by SPIKE to reflect this. This request is then sent to the Web server, and the response is printed to the screen or saved to a file. By scanning the output of SPIKE logs, you can determine if this, or any of the thousands of other attacks SPIKE will iterate through, was successful.
