# Buffer Overflow Vulnerabilities
Found in Resolution Service

At the time of writing, NGSoftware (www.ngssoftware.com) has recently announced that all versions of SQL Server 2000 (MSDE 2000) are vulnerable to several buffer overflows and a denial of service attack by simply specially formed requests to UDP port 1434. Microsoft has issued a patch for the vulnerability at www.microsoft.com/technet/security/bullet/MS02-039.asp.

This vulnerability basically allows any unauthenticated attacker to take control of the SQL Server and run code of his choosing with the security context of the SQL server account. It cannot be stressed enough just how important it is to either apply this patch or block all UDP 1434 inbound to server.

# Osql –L Probing

Osql.exe is a command-line utility provided by Microsoft with SQL Server 2000 (and MSDE 2000) that allows the user to issue queries to the server. Osql.exe includes a discovery switch (-L) that will poll the network looking for other installations of SQL Server. It does this by issuing UDP broadcast on 255.255.255.255 with the discovery payload of x02 (inh). This means it does not provide the precision of SQLPing, nor does it allow for scanning on other subnets. Osql.exe will return only a list of server names and instances but no details about TCP ports, netlibs, or any other information is provided. As a side note, osql.exe also returns any aliases that may be listed in the Registry key:

```
HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\MSSQLServer\Client\ConnectTo
```

# SC.exe Sweeping of Services

It is possible to query servers to see if they are offering SQL Server services using the Server Controller (sc) command. This will require at least user-level access to the server being probed. For example, the following command will inquire an adjacent server about any services that have MSSQL in the name.

```
sc \machine_name query bufsize= 60000|find "MSSQL"
```
