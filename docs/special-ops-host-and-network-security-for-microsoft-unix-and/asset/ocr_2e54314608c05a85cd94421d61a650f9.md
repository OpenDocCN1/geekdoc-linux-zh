Note that you can trace the path where the message originated by looking at the earliest hostname and IP address. In this case, the message originated on a server called HNLEX03 with an IP address of 192.168.23.8. It was then transferred to another internal server called HNLEX01, to a server called SFOEX04, and finally to the organization's SMTP gateway (SMTPGATE).

There is currently no solution in Exchange 2000 that will allow you to rewrite the SMTP headers or clear them up, which could be implemented with an SMTP sink. I do not recommend cleaning up the SMTP headers of messages that are being transferred internally as this can make message transport issues more difficult. However, I recommend finding a way to clear the headers of the message prior to leaving your organization. Two products that currently support this feature include the Cisco firewall (www.cisco.com), Check Point's Firewall-1 (www.checkpoint.com), and Clearswift Mail Sweeper (www.mimeseeper.com). Additional vendors have planned for support in their firewall and SMTP scanners in the future.
