## System Identification Methods

The first step to preparing for attempted access to a network is footprinting, which is simply the process used to identify systems as potential targets to probe or eventually attack. This can involve a number of steps. For instance, in many cases attackers can simply find information about a company's systems through viewing its corporate Web site. Often, this will provide a picture of the overall business structure of the company, and it may follow that the IT department has closely followed structure in developing their network structure. Certainly, it may indicate where certain components are likely to be geographically or physically located. Other publicly available resources may be utilized, such as a telephone directory, search engines, financial information, and so on. I've found information in cases when top-level people in the company have issued press releases detailing information that turned out to be useful in the evaluation of their others. Often, a little social engineering with appropriate name dropping can reveal a lot about the organization that is being analyzed.

Once a decision is made that a particular organization is worth of time and commitment, attackers begin working through the process to look for entry points. Initially, one may choose to scan the systems to begin to get a feel for what is available. A very quick GUI port scanner SuperScan is available free from Foundation, Inc. (www.foundstone.com/knowledge/free_tools.html). Scanline from Foundation and a Win32 version of Nmap at eeye.com are command-line-oriented tools. These tools can be used to quickly check for response of an individual host or a range of addresses that may be in use by the subject network, and test for ports that are responsive. Other tools like GFI's Network Security Scanner (www.gfi.com/lanetscan/index.html) allow not only scanning the network, but also begin to enumerate the hosts and obtain more information about the systems being probed. This allows the refinement of the attack methodology to utilize the exposed interfaces and go known vulnerabilities in these areas.

For instance, using Scanline, one could evaluate a range of addresses and return information about the remote systems, as ports active as the remote systems:

## Remote Enumeration

Remote enumeration can often be accomplished with astonishing ease. Within the Windows environment, attackers can often locate potential targets through the use of simple commands at the command line, and they can establish communication with those targets through null session authentication. For instance, if default settings are in place on Windows 2000 machines allowing null session logons to be established with blank passwords, an attacker can establish that null session and then run tools like Somarsoft's DumpSec (formerly DumpACL) to determine user names and SIDs with ease.

## NetBIOS

Enumerating existing Windows machines on a local wire is extremely easy if NetBIOS services are left running. Generally, this means that if a network is using File and Print Sharing and the normal use of Network Neighborhood or My Network Places, the chances are good that the capability exists to attack and enumerate your network. This is very simple if single vulnerable system is available for connection. How easy is this? Open a command window on any Windows machine with NetBIOS services enabled, and type the command net view. It will immediately deliver the machine names of any machines on the wire that have NetBIOS turned on. The output of that command might look like this:
