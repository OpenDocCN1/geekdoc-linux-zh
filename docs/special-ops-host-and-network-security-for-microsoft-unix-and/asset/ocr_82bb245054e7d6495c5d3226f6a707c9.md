Password attacks can be mounted either via the network or against a database that we have recovered. Many tools use the Internet and commercial sources that allow the recovery of SAM information. It is simple, for instance, to create a bootable Linux floppy and mount an NTFS file system from the resultant operating system. From here, it is a simpler matter to copy the SAM directory from a locally accessible machine to other partitions, media, or the network. It is also relatively easy with the available tools to recover the hashed passwords from the Registry of remote machines. In either case, the information is at hand, password attacks can be mounted using available tools.

There are a number of tools available for both types of attack. Two come to mind that work well are the well known L0ptCrack tools from @stake (www.stake.com) and John the Ripper (www.openwall/john).These tools allow dictionary or brute force attacks against recovered databases and in some versions allow capture of SMB traffic on the network and then work to remove the hashes and decode the passwords for us. Again, once an attacker has access, the system is theirs, not yours.

# Attacks Using Common and Known Vulnerabilities

It is a very wise security professional who subscribes to and reads mailing lists that report software bugs and vulnerabilities and patch deployments and make sure they use all the appropriate fixes to keep their systems secure. As has been reported many times, the Code Red virus could not have continued its unchecked proliferation had system operators and security professionals applied fixes prior to its introduction. This is the case with many of the common attacks that are mounted. Unprotected resources running with unneeded services and unprotected files and file systems will always be subject to attack.
