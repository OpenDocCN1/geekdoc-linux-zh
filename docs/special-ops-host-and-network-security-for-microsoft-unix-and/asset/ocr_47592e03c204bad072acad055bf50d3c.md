# Denial of Service When Redirection Occurs

The Listener service also has problems with denial of service attacks. When the Listener hands off connections to the database instance by redirecting the connection to an alternate port, a denial of service attack attacks can prevent the Listener from accepting new connection attempts and possibly crash the service.

The vulnerability exists because the database creates a new thread each time a request is made by a user. An attacker can simply make 1,500 requests to connect to the database, and the Listener will request the database instance to create 1,500 new threads. The database will happily sit and wait on these new threads until a connection is made. The problem is that after opening 1,500 new threads, the database will fail to open additional threads and more likely you will have consumed all the memory on the operating system.

Once again, since the redirection occurs before an authentication occurs, this attack can be mounted by anyone to send a TCP/IP packet to the Listener.
