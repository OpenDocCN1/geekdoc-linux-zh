# The Plug and Play Denial of Service Attack

The Universal Plug and Play (UPNP) denial of service attack leverages a flaw in the design of Microsoft’s Plug and Play server. A malformed UDP packet is sent to port 1900 with a NOTIFY request that contains a URL redirect to a system with malicious Charger. XP opens the requested URL and initiates a TCP to the specified system. Due to an error in the server data processing of the UPNP service, the server does not conduct any analysis of the URL, thereby any port and system would be specified. Once the TCP request is sent to the Charger server, the Charger sends a packet with code that utilizes all of the XP’s memory memory sending it to an immediate state of unused by consuming all of the CPU cycles.

The modified source code for this attack is presented shortly (note that some lines are wrapped). In order for this attack, you need the ability to compile C source code. It has been tested and verified to work on the RedHat 6.2, Slackware 7.0, and Windows NT/2000/XP platforms. The following steps are required to successfully execute this attack:

+   1. Individually compile both of the programs.
2. Run the Charger.c executable with the port specified in the Notify request of the UPNP service code (the current default is port 1900).
3. Run the Upon executable and be sure to use the same port number that the Charger is listening on.

If the system is running the Plug and Play service and is not patched, the attack should work to ensure that the target system was not rebooted.
