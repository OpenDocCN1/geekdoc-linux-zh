| Option | Description |
| --- | --- |
| multiple-cnames yes/no; | The specification for DNS tables does not allow for CNAME records to point to other CNAME records, so the default for this options is No. Since older versions of BIND did allow this, you can enable this backward compatibility by choosing Yes for this option. (CNAME records are host aliases, discussed later in the chapter.) Default is Yes. Causes a primary DNS server to send a NOTIFY message informing all the primary server’s secondaries that its tables have been updated. The NOTIFY message causes the secondaries to perform zone transfers (to get the latest information from the primary) almost immediately. |
| notify yes/no; | If Yes (the default), the server will attempt to traverse the DNS tree to get information about a requested IP address. This takes the load off the client to perform the same task. (See the fetch-glue option for reasons to turn recursion off.) |
| recursion yes/no; | Specifies a list of IP addresses to be queried if the current server does not have the answer to a request. Forwarders are optional; the addresses generally come from an upstream provider. Example ip-list (with fictitious addresses): Forwarders ( 192.168.8.24; 192.168.3.12; ); |
