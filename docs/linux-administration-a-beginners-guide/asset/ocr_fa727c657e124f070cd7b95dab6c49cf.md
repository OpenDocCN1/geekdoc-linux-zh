The `/etc/syslog.conf` file contains the configuration information that `syslogd` needs to run. This file's format is a little unusual, but the default configuration file you have will probably suffice unless you begin needing to seek out specific information in specific files or sent to remote logging machines.

# Log Message Classifications

Before we can understand the `/etc/syslog.conf` file format itself, we have to understand how log messages get classified. Each message has a `facility` and a `priority`. The facility tells us from which subsystem the message originated, and the priority tells us how important the message is. These two values are separated by a period.

Both values have string equivalents, making them easier to remember. The string equivalents for facility and priority are listed in Tables 9-5 and 9-6, respectively.

| Facility | String Equivalents | Description |
| :--- | :--- | :--- |
| `auth` | `auth` | Authentication messages |
| `authpriv` | `authpriv` | Essentially the same as `auth` |
| `cron` | `cron` | Messages generated by the `cron` subsystem (see later section) |
| `daemon` | `daemon` | Generic classification for service daemons |
| `kern` | `kern` | Kernel messages |
| `lpr` | `lpr` | Printer subsystem messages |
| `mail` | `mail` | Mail subsystem messages (including per mail logs) |
| `mark` | `mark` | Obsolete, but you may find some books that discuss it: `syslogd` simply ignores it |
| `news` | `news` | Messages through the NNTP subsystem |
| `security` | `security` | Same thing as `auth` (should not be used) |
| `syslog` | `syslog` | Internal messages from `syslogd` itself |
| `user` | `user` | Generic messages from user programs |
| `uucp` | `uucp` | Messages from the UUCP (UNIX to UNIX CoPy) subsystem |
| `local0` - `local9` | `local0` - `local9` | Generic facility levels whose importance can be decided based on your needs |

Table 9-5. String Equivalents for the Facility Value in `/etc/syslog.conf`
