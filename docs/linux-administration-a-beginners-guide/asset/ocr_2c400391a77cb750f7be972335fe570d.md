# ## SETUID AND SETGID PROGRAMS

Normally, when a program is run by a user, it inherits all of the rights (or lack thereof) that the user has. If the user can't read the `/var/log/messages` file, neither can the program. Note that this permission can be different from the permissions of the user who owns the program file (usually called the binary). For example, be the program (which is used to generate directory listings) is owned by the root user. Its permissions are set such that all users of the system can read the program. For example, if the user ssh runs `ls`, that instance of `ls` is bound to the permissions granted to the user ssh, not root.

However, there is an exception. Programs can be tagged with what's called a `SetUID` bit which allow a program to be run with permissions from the program's owner, not the user who is running it. Using `ls` as an example again, setting the `SetUID` bit on it and having the file owned by root means that if the user ssh runs `ls`, that instance of `ls` will run with root permissions, not with ssh's permissions. The `SetGID` bit works the same way, except instead of applying the file's owner, it is applied to the file's group setting.

To enable the `SetUID` bit or the `SetGID` bit, you need to use the `chmod` command, which is covered in detail in Chapter 6. To make a program `SetUID`, prefix whatever permission value you are about to assign it with a 4. To make a program `SetGID`, prefix whatever permission value you are about to assign it with a 2. For example, to make the `/bin/ls` a `SetUID` program (which is a bad idea, by the way), you would enter:

```
[root@ford /root]# chmod 4755 /bin/ls
```

# ## WHEN A FILE ISN'T OWNED

The title of this section is a bit misleading. A file is always owned, no matter what. A more accurate title would be: “When a File's Owner's UID Doesn't Map To an Entry in the `/etc/passwd` File” — but my editor was against that.

When a user is created, it gets a new and unique UID. Any files created by that user are owned by that user. To keep things easy, Linux doesn't use the user's name, but the UID, to file ownership.
