
## CIDR

  尽管你可能拥有整个A类或B类地址，但将整个网络配置为一个大型的主机集群并不现实。除了管理上的噩梦之外，你将很难找到任何类型的网络能够容纳如此多的主机集中在一起。例如，以太网每个网段仅允许多达1024台主机。

  为了解决这个问题，这些大型网络通常被划分为更小的子网。这是通过扩展表示网络地址的位数来实现的，这种技术被称为无类域间路由（CIDR），因为它违反了A、B、C类网络的描述。

  典型的场景是在私有IP网络中，其中10网络用于组织内部结构。大多数组织并没有1600万台计算机紧密连接在一起，因此组织的每个部门都成为一个子网。通常，合理的选择是使用24位掩码（255.255.255.0）来实现子网中的254台主机（记住0是网络地址，255是广播地址），这是一个足够合理的主机组规模。

  例如，市场部可能是10.1.1.0网络，销售部可能是10.1.2.0，工程部可能是10.1.3.0，而管理部可能是10.1.4.0。公司网络上的所有主机都使用255.255.255.0的子网掩码。对于销售团队来说，这意味着他们所有主机的IP地址都在10.1.2.1到10.1.2.254的范围内。

## 模块与网络接口

Linux下的网络设备打破了通过文件隐喻访问所有设备的传统。直到网络驱动初始化网卡并注册到内核时，才存在一种机制供任何人访问该网卡。通常，以太网设备注册为ethX，其中X是设备号。第一个设备是eth0，第二个是eth1，等等。

根据你的内核是如何编译的，网络接口卡的设备驱动程序可能已作为模块编译。对于大多数发行版，这是默认的传输机制，因为它使探测硬件变得更容易。

如果驱动程序配置为模块，并且你设置了可自动加载模块，你需要在/etc/conf.modules文件中告知内核设备名称与要加载的模块之间的映射。例如，如果我的eth0设备是3Com 3C905以太网卡，我会在/etc/conf.modules文件中添加如下行：

```
alias eth0 3c59x
```

其中3c59x是设备驱动程序的名称。

> **提示：** 如果你购买了Red Hat 6.0和一块全新的3Com 3C905C网卡，你可能会惊讶地发现驱动程序无法工作。这是因为新网卡在Red Hat 6.0之后推出，而所需的新驱动程序未能包含在发行版CD中。你可以从 http://lcedis.cls.csd.nasa.gov/nilw 下载此驱动程序（以及其他许多驱动）。

你需要为拥有的每个网卡进行此设置。例如，如果我有一块基于DEC Tulip芯片组的网卡和一块SMC-1211（基于RealTek 8139芯片组，这是廉价100baseT卡中常见的芯片组）在同一台机器中，我需要确保/etc/conf.modules包含以下行：

```
alias eth0 tulip
alias eth1 rt8139
```

其中tulip指带有DEC Tulip芯片的网卡，而rt8139指SMC 1211卡。

> **注意：** 这些alias命令不会是/etc/conf.modules文件中唯一的条目。

## IFCONFIG

ifconfig程序负责设置网络接口卡（NICs）。其所有操作均可通过命令行选项执行，在原生格式下，它没有菜单或图形界面。

已经编写了许多工具来包装ifconfig的命令行界面以提供菜单驱动或图形界面，其中许多随Linux发行版一起提供。例如，Caldera用户可以通过COAS配置其网络接口，Red Hat用户可以使用netcfg程序。

在本节中，我们仅关注ifconfig的命令行版本。

### 简单用法

在其最简单的用法中，你只需提供正在配置接口的名称和IP地址即可。ifconfig程序将根据IP地址推导其余信息。因此，我们可以输入：

```
ifconfig dev ip netmask bcast
```

其中dev是正在配置的网络设备，ip是设置的IP地址，netmask是子网掩码，bcast是广播地址。例如：

```
[root@ord /root]# ifconfig eth0 1.1.1.1 netmask 255.255.255.0 broadcast 1.1.1.255
```

这将把eth0设备的IP地址设置为1.1.1.1，子网掩码为255.255.255.0，广播地址为1.1.1.255。

> **提示：** 你可以通过不带参数运行 `ifconfig` 列出所有活动设备。你可以通过运行 `ifconfig -a` 列出所有设备，无论其是否活动。

### 在启动时设置NIC

不幸的是，每个发行版自动化其网卡设置过程的方式略有不同。由于Red Hat Linux的流行性以及随本书附带的Red Hat副本，我们在下一节中涵盖Red Hat Linux。但对于其他发行版，你需要通过以下两种方式之一处理此过程：

- 1. 使用随该发行版提供的管理员工具添加网卡支持。这通常是最简单且最可靠的方法。例如，Caldera Linux使用COAS工具。

- 2. 找到负责配置网卡的启动脚本。（使用grep工具查找运行ifconfig的脚本效果很好。）在脚本末尾添加必要的ifconfig语句。另一个添加ifconfig语句的常见位置是在rc.local脚本中——虽然没那么漂亮，但同样有效。

### 在Red Hat Linux下设置NIC

Red Hat Linux拥有一个使在启动时配置网卡变得容易的系统设置。这是通过在/etc/sysconfig/network-scripts目录中创建在启动时读取的文件来实现的。Linux下的所有图形工具都会为你创建这些文件，但对于那个渴望手动编辑文件的你，以下是你需要知道的：

对于每个网络接口，/etc/sysconfig/network-scripts目录中都有一个ifcfg文件。该文件名以设备名称为后缀，因此ifcfg-eth0对应eth0设备，ifcfg-eth1对应eth1设备，等等。

这些每个文件的格式如下：

```
DEVICE="eth0"
IPADDR="192.168.1.1"
NETMASK="255.255.255.0"
NETWORK=192.168.1.0
BROADCAST=192.168.1.255
ONBOOT="yes"
BOOTPROTO="none"
IPV4SUM_802_2=""
IPXPRIMARY_802_2="no"
IPXACTIVE_802_2="no"
IPXNETNUM_802_3=""
IPXPRIMARY_802_3="no"
IPXACTIVE_802_3="no"
IPXNETNUM_ETHER1=""
IPXPRIMARY_ETHER1="no"
IPXACTIVE_ETHER1="no"
IPXNUMID_SNAP=""
IPXPRIMARY_SNAP="no"
IPXACTIVE_SNAP="no"
```

所有以IPX开头的条目都是用于IPX协议套件的。在本节中，我们只关注文件顶部的IP相关信息。具体来说，我们关注以下字段：

```
DEVICE="eth0"
IPADDR="192.168.1.1"
NETMASK="255.255.255.0"
NETWORK=192.168.1.0
BROADCAST=192.168.1.255
ONBOOT="yes"
```

这些字段决定了eth0设备的IP配置信息。注意每个值如何对应ifconfig中的参数。要更改此设备的配置信息，只需更改ifcfg文件中的信息并运行：

```
[root@ford /root]# cd /etc/sysconfig/network-scripts
[root@ford network-scripts]# ./ifdown ifcfg-eth0
[root@ford network-scripts]# ./ifup ifcfg-eth0
```

如果需要配置第二个网络接口卡，请将ifcfg-eth0文件复制到ifcfg-eth1，并更改ifcfg-eth1中的信息以反映第二块网卡的信息。一旦完成，Red Hat将在下一次启动时自动配置它。如果需要立即激活该卡，请运行：

```
[root@ford /root]# cd /etc/sysconfig/network-scripts
[root@ford network-scripts]# ./ifup ifcfg-eth1
```

ifconfig命令的格式如下：
