# TROUBLESHOOTING SAMBA

There are four typical solutions to connectivity problems with Samba.

+   Restart Samba. This may be necessary because Samba has either entered an unde-\nfined state or (more likely), you've made changes to the configuration but forgot to restart\nSamba so that the changes take effect.

+   Make sure the configuration options are correct. Errors in the smb.conf file are\ntypically in directory names, usernames, network numbers, and hostnames. A common\nmistake is when a new client is added to a group that has special access to the server, but\nSamba isn't told the name of the new client being added.

+   Monitor encrypted passwords. These may be mimatched\u2014the server is config-\nured to use them and the clients aren't; or (more likely) the clients are using encrypted\npasswords and Samba hasn't been configured to use them. If you're under the gun to get\na client working, you may just want to disable client side encryption using the regedit\nscripts that come with Samba's source code (see the docs subdirectory).

+   Monitor cached passwords. Windows often caches passwords in files that end in\npwl. Not only is this a security risk (the pwl files are poorly encrypted), but if your pass-\nword has changed on the server, Windows may continue feeding the cached password\ninstead of prompting you for a new one. Simply remove the pwl files to force Windows to\nprompt you for a password.
