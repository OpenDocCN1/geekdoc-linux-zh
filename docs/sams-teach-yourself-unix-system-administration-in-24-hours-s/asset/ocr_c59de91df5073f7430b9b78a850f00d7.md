3. Most system administrators will tell you that if you encounter errors with fsck you should run the command again and again until it finally reports no errors. It's almost a superstition, but it's also amazing how often a second pass catches new errors introduced by the fixes in the previous run. This situation is no different (I finally unmounted the disk before running these subsequent checks):

```
# fsck -V /disk2
Parallelizing fsck version 1.23 (15-Aug-2001)
[/sbin/fsck.ext2 ... /disk2] fsck.ext2 /dev/hdb
e2fsck 1.23, 15-Aug-2001 for EXT2 FS 0.5b, 95/08/09
/dev/hdb: clean, 3419/64000 files, 36468/255528 blocks
```

A classic frustration with fsck: It assumed that because we'd recently run the command there was no reason to run it again, so it simply reported "clean." But it's not!

The -f flag forces the disk integrity check to be run, and this time I'm going to add the -y flag, which tells fsck to assume I answer yes to all questions that aren't absolutely critical:

```
# fsck -Fy /disk2
```
