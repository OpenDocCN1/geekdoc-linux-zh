3. To kill the vi session, I'll specify SIGTERM and see what happens:

```
# kill -TERM 14575
# kill -TERM 14575
#
```

Ahhh...vi ignores SIGTERM signals, so we'll have to try something a bit stronger:
SIGHUP.

```
# kill -HUP 14575
# kill -HUP 14575
#
```

As you can see, some applications are pretty tough, able to accept and ignore many common signals. The tail command gracefully died when it received its first SIGTERM, but vi is lingering. This means it's time for a SIGKILL (aka -9):

```
# kill -9 14575
# kill -9 14575
bash: kill: (14575) - No such pid
[2]+ Killed nice -5 vi testme
```

That did the trick. Notice that you can specify the signal by name (for example, -KILL) or by its number. Many system administrators have the command kill -9 wired into their fingers after a bit, and don't even think about signal names.

4. If you ever find yourself in a situation where it would be useful to stop a job temporarily, then resume it later, it's worth knowing that you can send the signal equivalent of a ^Z to a process, then a resume signal to have it start up and begin running again:

```
# ps -lU taylor
F S UID PID PPID C PRI NI ADDR SZ WCHAN TTY TIME CMD
100 S 502 14369 14368 0 70 1 . 618 wait4 pts/0 00:00:00 bash
000 S 0 14539 14369 0 70 1 . 589 wait4 pts/0 00:00:00 su
100 S 502 14717 14716 0 71 0 . 618 read_c pts/1 00:00:00 bash
000 R 502 14757 14717 27 78 0 . 445 do_sig pts/1 00:00:00 find
```

You can see that user taylor has a find running that's currently taking up 27% of the CPU. It'd be helpful to stop this find temporarily, run a few sysadmin commands, then start it up again:

```
# kill -STOP 14757
# ps -lU taylor
F S UID PID PPID C PRI NI ADDR SZ WCHAN TTY TIME CMD
100 S 502 14369 14368 0 70 1 . 618 wait4 pts/0 00:00:00 bash
000 S 0 14539 14369 0 70 1 . 589 wait4 pts/0 00:00:00 su
100 S 502 14717 14716 0 71 0 . 618 read_c pts/1 00:00:00 bash
000 T 502 14757 14717 0 78 0 . 445 do_sig pts/1 00:00:00 find
```

now the job is stopped, we can do other stuff for a while

```
# kill -CONT 14757
# ps -lU taylor
```
