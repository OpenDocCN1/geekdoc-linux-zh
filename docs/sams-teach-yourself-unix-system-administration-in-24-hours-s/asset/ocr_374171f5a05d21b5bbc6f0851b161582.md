To see this in action, here's how I could extract a report that lists the account names and password strings:

```
```
$ nireport . /users name passwd
nobody *
root c8bklkt6E1th9
daemon *
unknown *
www *
taylor fse2jv5k6jIA
```
```

You can see that four of these accounts (the ones with the /dev/null login shell, as reported earlier) have login capability disabled, while two have explicit encrypted passwords.

4. To make this more interesting, I created a UID 0 account with no password called badguy, appropriately enough. I can't just append the information to the /etc/passwd file this time, however; I need to use a script called niadduser to add the information to the NetInfo database. (We'll develop this script a bit later in this hour.)

With this new account in place, let's see how nireport can be combined with some regular Unix utilities to create some useful analysis filters:

```
```
$ nireport . /users name uid | awk '$2 == 0 { print $0 }'
root 0
badguy 0
```
```

That reports that there are two accounts that have UID=0.

The test for missing passwords is a bit more subtle:

```
```
$ nireport . /users name passwd | awk 'NF==1 { print $0 }'
badguy
```
```

In this instance, the variable NF is the number of fields, so the awk test is, in essence, "if there's only one field in the output line."
