
现在，当输入URL http://localhost/test.cgi 时，服务器会如预期地返回当前日期和时间：

```
# telnet localhost http
Trying 127.0.0.1...
Connected to localhost.
Escape character is '^]'.
GET /test.cgi
The current date and time is: Wed Apr 10 12:26:36 PDT 2002
Connection closed by foreign host.
```

对于包含超过1,000行信息的配置文件，你可以通过多种方式修改Apache，这不足为奇。你的站点和用户群体的确切需求需要你自己来确定，阅读Apache.org网站上可用的文档将有助于弄清楚可以实现什么以及如何实现。

## 问与答

**问**：为什么大多数Unix变体将Apache服务器称为httpd，而其他变体——特别是Solaris——称其为apache？

**答**：这是一个好问题，但没有确定的答案。按照惯例，大多数守护进程以它们提供的服务命名，因此telnetd提供telnet服务，ftpd提供ftp服务，依此类推。然而，在Solaris平台上，服务守护进程通常以提供服务的应用程序来命名。让人困惑？是的，确实如此。

**问**：你的建议是什么：只允许cgi-bin，还是让用户在任何地方放置CGI脚本？

**答**：我认为，如果你经营一家Web托管公司，并且客户正在访问系统，我的建议是要么只允许一个共享的cgi-bin，只有管理员可以直接访问，要么为每个用户创建一个单独的cgi-bin。这样你就可以集中管理这些脚本，并在必要时逐一检查，以确保它们不会带来任何明显的安全漏洞。

## 第24小时：Apache虚拟主机

在这最后的一小时里，我们将探讨Apache的一项特定功能——虚拟主机——然后以Unix系统安全的一些讨论作结。

如果你有一个网站——而且很可能你有——你会知道托管网站有两种基本方法：每个站点有自己的计算机，或者，以某种方式，多个网站（例如多个域名）解析到一台共享服务器。由于Unix是最早的共享多用户资源，共享Web服务器很容易，甚至功能最弱的Unix机器也能轻松胜任，这不足为奇。

在这最后的一小时里，我们将探讨如何：

- 在Apache中启用虚拟主机
- 保护你的系统

### 在Apache中启用虚拟主机

Apache最有趣的功能是它可以为不同的域名提供不同的网页，即使它们都解析到同一个IP地址。当然，你可以将域名配置为多个IP地址，所有这些地址都在一个系统上提供服务（你可以通过额外的`ifconfig`语句来实现；详情请参见man手册），但这效率非常低，因为没有理由不让这些域名共享一个IP。

当httpd最初作为瑞士欧洲高能物理研究中心（CERN）和伊利诺伊大学厄巴纳-尚佩恩分校国家超级计算应用中心的原始Web服务器出现时，Web服务器就像其他互联网繁荣之前的服务器一样——它们盲目地为他们所运行的机器提供服务请求。

随着互联网变得越来越流行，想要拥有自己域名的人数超过了在线独立服务器的数量，因此很明显，Unix需要添加某种共享或虚拟主机功能。

这正是Apache团队在其Web服务器中实现VirtualHost的灵感来源：这是一种简单的机制，让系统管理员可以在同一系统上设置数十个甚至数百个不同域名的不同网站。

![](img/5ced0c78d748bd190e9027e5549a3622_490_0.png)

> 甚至sendmail也加入了这一行列。请访问www.sendmail.org，阅读关于虚拟用户表（virtusertable）功能的资料。你可以让一个邮件服务器看起来像数十个不同的域名，因此joeb@hisbakerystore和jane@herclotheshop使用同一个系统，在服务器上有相邻的邮箱，但能够以不同的回复地址、时间戳、消息ID等发送邮件。

### 任务24.1：配置虚拟主机

配置虚拟主机解决方案所需的第一步是确保相关域名的DNS名称服务器都被告知，为任何应由中心系统提供服务的域名返回服务器的IP地址。

- 1. 要检查并验证此配置是否已生效，请使用dig确认起始授权记录（SOA记录）中的IP地址（关于域名记录内部的更多细节，请参见第18小时“运行您自己的名称服务器”）。

在本小时的示例中，我们将考虑三个域名。staging.intuitive.com是一个子域，指向用于实验和开发的暂存服务器，而sherlockworld.com和niftylister.com都是向公众开放的网站：

```
# host sherlockworld.com
sherlockworld.com. has address 10.10.2.200
# host niftylister.com
niftylister.com. has address 10.10.2.200
# host staging.intuitive.com
staging.intuitive.com. has address 10.10.2.200
```

许多系统管理员需要对名称到数字的概念进行一些重新思考，才能理解多个域名如何在不冲突的情况下解析到同一个IP地址。简而言之，DNS系统确保名称解析为数字，但你可以让数百个，甚至数千个域名都指向一台机器，而不会违反任何DNS标准和使用规则。

> 如果你阅读了关于虚拟主机的Apache文档（位于http://www.apache.org/docs/vhosts/），就会意识到多个域名共享一个IP地址称为“基于名称的虚拟共享”。如果每个域名有不同的IP地址，那就是“基于IP的虚拟共享”。这有点令人困惑。

- 2. 在标准的Apache配置文件中，虚拟主机指令出现在第三部分，即注释中分隔的“第3部分：虚拟主机”中。

我们为这个服务器——staging.intuitive.com——使用的配置是所有域名共享一个IP地址，因此配置由两个基本元素组成：VirtualHost指令和Directory块，后者指定该特定目录及其所有子目录的权限和配置指令是启用还是禁用。

第一步是在httpd.conf配置文件中启用基于名称的虚拟主机。这通过确保以下行

```
NameVirtualHost *
```

没有被注释掉来完成。

接下来，在文件中，以下是相关的VirtualHost块：

```
<VirtualHost *>
ServerName www.niftylister.com
DocumentRoot /web/niftylister
ErrorLog /web/niftylister/error_log
CustomLog /web/niftylister/access_log
ServerAdmin webmaster@niftylister.com
```
