# Summary

Writing shell scripts is easy—you can start by taking whatever command you'd type on the command line and drop it into a file. Creating truly cool shell scripts, however, is more of an art, and the best system administrators can produce some amazing scripts. Keep your eye out for them, and spend time reading through the many shell scripts on your own system. There's always lots to learn!

# Q&A

Q When do shell scripts get so complex that it makes more sense to switch to a more powerful programming language like Perl?

A This is a question that will garner different answers depending on how comfortable the sysadmin questioned feels about writing shell scripts. There's no standard rule of thumb, that's for sure. I'll switch to a different programming language if I'm doing more data manipulation and relatively little system interaction. Your mileage may vary, of course!

Q What's the most common error in shell script programming?

A The most common error I make is forgetting either that a conditional test of strings should be a = b rather than a == b, or that it should be a = b rather than a -eq b. Unnecessary spaces after a backslash continuation at the end of a line is another common hiccup.
