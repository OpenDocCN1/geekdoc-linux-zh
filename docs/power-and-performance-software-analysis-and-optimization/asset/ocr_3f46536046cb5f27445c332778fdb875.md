There are also an .ascii and an .asciz pseudo-op, which create string data. The difference between .ascii and .asciz is that the second creates a NULL-terminated string, while the first does not.

12.12 demonstrates how to write a function, foo(), in assembly properly follows the x86_64 ABI in to allow invocation from C. The function declaration begins at line 9, whereas line 8 exports the function symbol to the linker. Lines 10 through 13 set up the stack frame, and lines 30 through 32 clean up the stack frame, in reverse order of setup.

As mentioned in "Calling conventions", the section must be 16-byte aligned at the time of a function call, such as the call to the printf(3) function on line 23. Because of this, it is safe to ensure that the current stack on entering this function is 16-byte aligned before the 8-byte return value-two registers are pushed onto the stack on lines 10 and 11. The first PUSH instruction sets the stack pointer to 16-byte alignment, the second PUSH instruction reduces the stack to only 8-byte alignment. In order to remedy this, there are couple of options, subtracting another 8 bytes from the stack pointer. In order to make this point clear, the example rounds the stack pointer down to the next 16-byte multiple, line 13. The original stack offsets before the alignment can be accessed through RBP.

Once the stack frame is initialized, the function loops over the function parameter, invoking printf(3) each iteration. The R12 register is used for the loop counter, since R12 is a preserved register, and therefore the call to printf(3) won't clutter. Notice how the function arguments are loaded into the RDI, RSI, and RDX registers prior to the function call.

Also note the different types of labels and their usages. Lines 16 and 34 are both temporary local labels, referenced using “f” and “b” suffixes, at lines 25 and 28. Line 29 contains a local label, with the “L.” prefix, and is referred at line 18.
