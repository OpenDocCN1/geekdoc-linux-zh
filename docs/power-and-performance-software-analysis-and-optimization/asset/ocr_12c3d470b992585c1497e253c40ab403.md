# 5.4.3 CREATING CUSTOM TESTS

Regardless of whether published or not published, adding custom tests to the deault repertoire is very simple. Essentially, a test profile is a collection of XML files and executables, normally shell scripts, for performing installation and benchmmarking.

First, create a new directory for the test profile in $HOME/.phoronix-test-suite/profiles/local. In this directory, all of the files needed for installing the test, except for any external resources, will be created. This XML file

The heart of a test profile is the test-definition.xml file which describes not only the metadata, such as the name and description, but also the required software, PhoronixTestSuite.TestProfile.External Dependencies for running the actual benchmark, PhoronixSuite.TestInformation.Executable, as well as data about the result metrics. The PhoronixTestSuite.Information.ResultScale property is the label used for the metric, such as “seconds” or “MB/s.” The Phoronix-Suite.TestInformation.Property profile sets whether the metric is reported as “HIB” or “LIB”.

Due to the complexity of the test-definition.xml file, the author recommends simply copying from any existing test profile, and then updating or adding fields as needed. Listing 5.4 demonstrates a simple test definition.

```
<xml version="1.0"
<!--Phoronix Test Suite v4.4.0ml (Forsand)-->
<PhoronixTestSuite>
<TestInformation>
<Title>System X Decompression</Title>
<Description>This measures the time to decompress a Linux kernel tarball using XZ.</Description>
<ResultScale>seconds</ResultScale>
<Proportion>LIB</Proportion>
<TimesToRun>3</TimesToRun>
</TestInformation>
<TestProfile>
<Version>1.0.2</Version>
<SupportedPlatforms>Linux, BSD</SupportedPlatforms>
<SoftwareType>Utility</SoftwareType>
<TestType>Processor</TestType>
<Maintainer>Jim Kukanas</Maintainer>
</TestProfile>
</PhoronixTestSuite>
```
