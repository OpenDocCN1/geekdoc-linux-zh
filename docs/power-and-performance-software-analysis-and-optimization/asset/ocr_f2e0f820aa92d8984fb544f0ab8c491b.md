While it is possible to specify the server configuration at each invocation of git send-email, it's simpler to add these options to the global git configuration. Regardless of the method chosen, Table 4.1 lists the configuration options for configuring Git for SMTP. This command accepts patch files in the mbox format by format-patch. However, it accepts the selected commits via their git ref and invoke git format-patch automatically. The recipients are controlled via the --cc, and --bcc arguments, each of which can appear multiple times for multiple recipients. Conveniently Git supports email aliases, saving the user from full email addresses. This is configured by setting sendmail.aliasesfile, in the Git configuration, to the alias file path, and setting sendmail.aliasfiletype to the format of the file, one of mut, mailrc, pine, or elm. For instance, rather than typing --to linux-kernel@vger.org, Git can be configured to recognize --commit with the following configuration:

```
$ alias1 Linux Kernel <linux-kernel@vger.kernel.org>
$ git config --global sendmail.aliasesfile ~/.mut/contacts
$ git config --global sendmail.aliasfiletype mutt
```
