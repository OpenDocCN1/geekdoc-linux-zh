# 1.4 Intel® 80386 and 80387

The extended general purpose registers are prefixed with a letter E. For instance, the 16-bit AX register extends the 32-bit EAX register. The previous register names operate on a subset of the corresponding extended registers. For instance, the AX register references the least significant word of EAX, and the AH and AL registers the two least significant bytes of EAX.

In Real-Address mode everything continues operating exactly as it had before. All instructions in Real-Address mode default to their 16-bit versions. Within protected mode, a new bit was added to the segment registers, known as the default bit, or D-bit. When this bit is clear, instructions within the code segment default to 16-bit mode. When this bit is set, instructions within the code segment default to 32-bit mode.

While this controls the default for a given segment, the mode of an individual instruction can override the default size with a special instruction prefix. 0x66, known as the Operand-size override prefix. By using this prefix, it is possible to execute 16-bit instructions in 32-bit Protected Virtual-Address mode, and to execute 32-bit instructions in 16-bit Real-Address mode.

Aside from adding this instruction prefix, the 80386 also extends the machine code format. These additions include support for 32-bit immediates, 32- displacements, and a new addressing format. Mentioned in Section 1.1.4, there were previously restrictions on how memory operands could addressed. These restrictions limited addressing to a base, contained within the SI, DI, BX, or BP registers, and an optional displacement. Additionally, if the base was in SI or DI, an optional offset, also known as an index, could be encoded in BX or BP.

In 32-mode the base and offset encodings in the Mod R/M byte are no longer limited to this subset of general purpose registers. Instead, any general purpose register can be used for either the base or index. In order to accommodate some of these encodings, a new option, the scale-index-base (SIB) byte, may need to follow the MOD byte.

The most significant bits within the SIB byte encode the scaling factor. A value of zero encodes a scaling factor of one, a value of one encodes a scaling factor of two, and a value of three encodes a scaling factor of eight. The next 3 bits encode the register containing the index, which is scaled and added to the base. The last 3 bits, the least significant bits, encode the register containing the base and registers are encoded using the same values in the Mod R/M byte for the 8086, as shown in Table 1.5. In other words, 32-bit x86 memory operations are expressed as:

```
EA = base + (index × scale) + displacement
```

The result of this calculation, which can be obtained with the LEA instruction, is referred to as the effective address. In AT&T assembly syntax, this is formatted as displacement(base, index, scale). Because LE can perform two additions and a multiplication, and doesn't modify any flags, it has historically been used as an optimization for general purpose integer arithmetic; however, on modern x86, this is no longer a fruitful optimization.
