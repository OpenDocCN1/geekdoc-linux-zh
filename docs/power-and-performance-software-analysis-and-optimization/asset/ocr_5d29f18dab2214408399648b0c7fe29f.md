Additionally, if pre.sh, interim.sh, or post.sh scripts are present in the test profile directory, these scripts will be executed before, runs, and after the benchmark, respectively.
Finally, the last step is to define a results-definition.xml file. This XML file explains how Phoronic should parse the test output. Results can come either from the output of the benchmarking script, or from the Phoronic sensors. Listing 5.8 demonstrates a result that utilizes the time sensor to monitor the script's duration.

```
<?xml version="1.0"?>
<!--Phoronic Test Suite v4.4.0ml (Forsand)-->
<PhoronicTestSuite>
  <SystemMonitor>
    <Sensor>sys.time</Sensor>
  </SystemMonitor>
</PhoronicTestSuite>
```

Alternatively, the results definition can be sample output, a snippet of sample output, from the benchmarking script, that is, what was written to the $LOG_FILE environmental variable. In the sample output, the numbers to be parsed out of the results are replaced with parser variables. Parser variables begin with a "_# and end with a "#". Thus for the majority of cases, replace the one important result in the sample output with #_RESULT_$.
