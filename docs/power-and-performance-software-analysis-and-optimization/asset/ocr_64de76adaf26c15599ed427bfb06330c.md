Combining the functions defined in Listing 5.2, and the technique for computing the average and standard deviation from Listing 5.1, it would be possible to count the number of cycles for a given workload with the following code snippet:

```
#include <stdio.h>
#include <math.h>
#include <inttypes.h>

static void run_bench(double *const avg, double *const std_dev) {
    size_t i;
    *avg = 0.0;
    *std_dev = 0.0;
    for (i = 0; i < NUM_RUNS; i++) {
        uint64_t start, end;
        double t, measure;

        start = start_cycle();
        /* do benchmarked code */
        end = stop_cycle();

        measure = (double)(end - start);
        *avg += t = measure / (i + 1);
        *std_dev += t * (measure - *std_dev));
    }
    *std_dev = sqrt(*std_dev / (NUM_RUNS - 1));
```

# 5.3.2 CLOCK TIME AND UNIT

As mentioned previously, the processor has no concept of time outside of clock cycles. Therefore, all the interfaces for accessing time in the human units of time, which are provided by the operating system, rather than the instruction set. The Linux kernel has a few different options for a clock timer

Traditionally, the Linux kernel ticked, that is, it would program the hardware timer to generate an interrupt at a given frequency, representing one tick. Each of these interrupts would cause the kernel to pause the current user space program, perform some accounting, and then choose the next process to run. This would occur at an interval selected at time, via the CONFIG_HZ Kconfig option. The possible configuration options for x86 were 1000, 350, 250, and 100 Hz. For instance, a kernel configured with HZ=1000 would receive 1000 tick interrupts every second, limiting the resolution of the timers to 1 ms.
