# 7.2

Available reports.

Details about each of these reports can be found in the VTune documentation or with the built-in help. For instance, in order to get more\information about the callstacks report, and its supported options, execute the
command amplxe-cl -help report callstacks....
The summary report is a good starting point for most analyses. It displays
tmetrics calculated by the analysis type, and a summary of the events counts. For
when run on a general-exploration analysis, the summary report will
print the pages for each Top-Down category. This can be seen in Listing 7.5.

For analysis types that perform sampling, there are useful reports for
identifying functions consumed the most CPU time. The first, hotspots
report type, the time accounted for each function, excluding functions called
from within. This report is sorted so that the functions that consume
tmost time are toward the top of the list. The second, the top-down report type,
displays both the time spent within each function, and the percentage of total
spent within that function, including functions called from within function. This
report is sorted so that the functions responsible for the greatest percentage of CPU
time toward the top of the list. The third, callstacks report type and
the fourth, the gprof-cc report type, provide additional information about the stack
traces with the hotspots.

By default, reports typically group items at a function-level granularity.
group can be changed with the -group-by argument. The available groupings
supported by each report type will be listed in their respective help page. One
of most useful of these is the source-line grouping, which correlates each hotspot
to specific line of code. When interpreting this information, remember to account
for potential UMI skid. Listing 7.3 illustrates the default grouping for
hotspots report run on data collected with a general-exploration analysis type.
