Profs is a memory-backed filesystem that exposes kernel data structures through a hierarchical directory and file interface. Unlike a standard filesystem, the files within proc and sysfs do not physically exist. The VFS file operations, such as opening the file, hook into special functions that generate and the desired content on demand. For profs, the kernel must be compiled with CONFIG_PROC_FS, which is enabled on practically every Linux kernel. The standard convention is that profs is mounted at /proc, although this isn't a technical requirement.

The cpuinfo file is located at the top-level proc directory and contains all of the relevant processor information, such as model, family, frequency, and a list of supported features. The file contains one entry for each logical processor.

The flags field contains a space-delimited list of CPU features for which the kernel has detected support.
Common issue with the flags field is knowing which strings map to which features. For example, the answer is obvious, such as the SSE extensions mapping to the string "sse2". For others, the answer is less obvious, such as the SSE3 extensions mapping to the string "pi", an acronym for Prescott Instructions.

Understanding which string requires a remedial understanding of how the cpuinfo file is generated. All of the x86 processor features are listed in:
${LINUX_SRC}/arch/asm/cpufeature.h.

Each feature is represented by a preprocessor define with X86_FEATURE_, X86_FEATURE_MMX. The value of the mask is used to check for support with CPUID. Finally, each line ends with a C-style comment. Here, within the comment, the name exposed to user space is enclosed within double quotes. If the double quotes are missing from the comment, the name inside is used instead. If the double quotes are empty, the feature is omitted from the cpuinfo file.

Some selects from cpufeature.h are shown in Listing 12.4. The first two selections, X86_FEATURE_TSC and X86_FEATURE_MSR, are represented in the flags field as "tsc" and "msr", respectively, which lack any string descriptor in the comments. The third, fourth, and fifth features would appear as "dts", "sse", and "sse2", respectively. The last one won't appear in the cpu feature list at all.

#define X86_FEATURE_MSR     (0*32+5) /* Model-Specific
                       Registers /
#define X86_FEATURE_DS       (0*32+21) /*dts" Debug Store *
#define X86_FEATURE_XMM      (0*32+25) /*sse" */
#define X86_FEATURE_MM2     (0*32+26) /*sse2" */
#define X86_FEATURE_SYSCALL (3*32+14) /* syscall in ia32
                       userspace */
