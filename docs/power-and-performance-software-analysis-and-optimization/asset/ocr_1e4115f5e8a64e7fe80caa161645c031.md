This is because a mask of all ones, when combined with the value of x with a bitwise operation, will result in the value of x being unchanged, for the addition to occur as expected.

The observation needed for converting the sign bit into the mask is that negative integers are encoded using their two's complement. Therefore, the encoding for negative one, where all bits are set, corresponds to the requirements for the mask when the sign bit is set. By shifting the sign bit, located in the high order bit, right to the lower order bit, also known as the least significant or rightmost bit, the result is a value of one, in the negative case, and zero, in the positive case. Substracting this from one will generate the desired masks. For example, the previous function foo() without the branch:

```
1 int foo(int x, int y)
2 {
3   unsigned hob = (unsigned)x >> (sizeof(int[CHAR_BIT])-1);
4   return y + (x & (hob - 1));
5 }
```

Note on line 3, the variable x is first cast from a signed integer type to an unsigned integer type. This is because the behavior when performing a bitwise shift to the right on a negative integer is implementation-defined by the C Standard. In x86, there are two types of shift instructions, arithmetic and logical, used on signed and unsigned integers respectively. Logical shifts to the right, the SHR instruction, always fills the leftmost bits with zeros. Arithmetic shifts to the right, the SAR instruction, always fills the leftmost bits with the sign bit of the shifted value. For example, a 32-bit negative integer arithmetically shifted would produce a result of 0xFFFFFFFF; this would prevent every other operation. At the same time, a 32-bit positive integer arithmetically shifted right would produce a result of zero. Therefore, using an arithmetic shift would require the proper mask, once the mask's bit had been inverted with a logical operation, instead of subtracting one from the mask value, as is on line 4. The cast to the unsigned type, which by C precedence occurs before the bitwisefiling operator, on line 3 ensures that code only performs an unsigned bitwise shift to the right, with zeros. Additionally, operating on an unsigned integer instead of a signed integer does not affect creation of the mask, since unsigned underflow is well-defined in the C specification and produces the same result.

The sizeof(int[CHAR_BIT])-1 calculation on line 3 is simple a portable way of determining the number of bits in an integer. The syntax of the size calculation de-facto de-exploits the fact that the sizeof operator multiplies an array type by the number of indices, thereby multiplying CHAR_BIT, which the C defines to be the number of bits in a byte, with the number of bytes in an integer. Therefore, the hob variable contains the contents of the high order bit shifted into the lower order bit.
