
## CHAPTER 2 Intel® Pentium® Processors

### Register Renaming

From the instruction perspective, Intel processors have eight general purpose registers in 32-bit mode, and sixteen general purpose registers in 64-bit mode, however, from the internal hardware perspective, Intel processors have many more registers. For example, the Pentium Pro has forty registers, organized in a structure referred to as a Physical Register File.

While this many extra registers might seem like a performance boon, especially if the reader is familiar with the performance gain received from the extra registers in 64-bit mode, these registers serve a different purpose. Rather than providing the process with more registers, these extra registers handle data dependencies in the out-of-order execution engine.

When a value is stored into a register, a new register entry is assigned to contain that value. Another value is stored into that register, a different register entry is assigned to this new value. Internal to the processor core, each data dependency on the first value will reference the first entry, and each data dependency on the second value will reference the second entry. Therefore, the out-of-order engine is able to execute instructions in an order that would otherwise be impossible due to false dependencies.

## 2.3 INTEL® PENTIUM®4

The P6 microarchitecture was used as the basis for the Intel® Pentium® Pro, Intel® Pentium® II, and Intel® Pentium® III processor families. As a result, each of these generations focused on improving the performance of the previous generation while adding new instructions. On the other hand, the Pentium 4, shown in Figure 2.3, was based on the NetBurst architecture. This new architecture adds features including IA-32e mode, which extends the processor from 32-bits to 64-bits, and Intel® Hyper-Threading.

### 2.3.1 IA-32e mode

The IA-32e mode extends Intel Architecture from 32-bit to 64-bit. To enter IA-32e mode, the processor must be in protected mode with PAE enabled. Paging is also a requirement for IA-32e mode, so the 64-bit page tables must be constructed before transitioning to the new mode. In IA-32e mode, a fourth level is added to the paging hierarchy, the page level 4 (PML4) table. This 4-level table contains 512 entries that point to PDPTs. Each PDPT is extended from 4 entries to 512 entries. Unlike 32-bit paging, a PDPTE could only reference a page directory table, a PDPTE can map a 1-GB page. The CR3 register holds the physical base address of the PML4 entry, the LME IA32_EFER MSR is set and then paging is enabled.

Similar to the extension from 16-bit to 32-bit, the extension from 32-bit to 64-bit is handled through the addition of another bit in the code segment descriptor, the L bit. If the L bit is set, then the code within that segment operates in 64-bit mode. If the L bit is not set, then the processor is in IA-32e mode, then the segment operates in compatibility mode. For 16-bit to 32-bit applications to still run while the processor is in 64-bit mode, if the L bit is not set and the D bit is not set, then the code within that segment operates in 16-bit mode. If the L bit is not set and the D bit is set, then the code within that segment operates in 32-bit mode.

In 64-bit mode, the memory address space and the long integer size is increased from 32-bit to 64-bit. While pointers are 64-bit and are therefore theoretically capable of addressing up to 16 exabytes, such a large address space introduces extra complexity for little gain. As a result, at the time of this, 64-bit processors that support a full 64-bit address space are uncommon. These processors support a more manageable subset of the full address space. The size of the physical and linear address space supported by the processor can be accessed through /proc/cpuinfo. For example:

```
$ /proc/cpuinfo | grep "address sizes" | head -n 1
address sizes : 36 physical, 48 bits virtual
```

In this example, the processor supports a physical address space of 64-GB, and a linear address space of 256-TB. At the time of this writing, 36 physical address pins are common for consumer hardware. On the other hand, hardware, often support a significantly larger physical address space, Intel® Xeon processors, for example, 46 physical address pins. In order to prevent a 64-bit memory address from exceeding the supported linear address space, the processor will fault on an address that does not follow canonical. The canonical address form requires that all bits outside of the implemented address range all have the same value as the most significant bit of the supported linear address space. In the example above, the linear address space supports 48 bits, bits 0 through 47, so bits 48 through 63 must have the same value as the 47th bit.

### 2.3.2 MULTI-CORE

In multi-core processors, multiple cores are placed on a single die. Each core has its own L1 cache, but they share the L2 cache and the system bus. This allows for faster communication between cores, but it also introduces some challenges in terms of cache coherence. To manage these challenges, the hardware uses cache coherence protocols to ensure that all cores see a consistent view of memory.

### 2.3.3 INTEL HYPER-THREADING

Hyper-Threading allows a single physical core to act as two logical processors. This is done by duplicating the architectural state of the processor, while sharing the execution resources. This allows the processor to utilize its execution units more effectively, as one thread can wait for data while the other thread performs execution.
