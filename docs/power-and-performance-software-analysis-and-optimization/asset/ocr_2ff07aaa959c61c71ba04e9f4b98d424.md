Consider Listing 12.1, which uses CPUID to check whether the processor supports the Intel® AVX instruction extensions. Line 10 selects the Basic Information Leaf, as described in the Intel SDM, contains, other data, a bit to indicate whether AVX is supported by the processor. Line 11 executes CPUID, and thus loads the relevant information described in the leaf into the EAX, EBX, ECX, and EDX registers. Line 12 masks out of all the bits except the masked value into the appropriate register. EAX when x86 calling conventions. Technically, if we were concerned about returning the exact bit, we would right-shift the bit into the least significant position; however this is unnecessary since C interprets zero as false, and all other values as true, and it is simply enough to return a non-zero value for the truth case.

Another consideration for using CPUID is its associated cost. CPUID is a serializing instruction that flushes the processor's execution pipeline, hence using in conjunction with RDTSC and RDCP to accurately measure clock cycles while accounting for instruction pipelining, as described in Section 5.3.1 of Chapter 5. As such, using CPUID frequently degrades performance, and this should be avoided in performance-sensitive contexts.
In Listing 12.1, we were only interested in checking for Intel AVX support; however, if we were interested in checking for multiple pieces of information, it would be best to perform as few times as necessary, as dictated by the information learned.
