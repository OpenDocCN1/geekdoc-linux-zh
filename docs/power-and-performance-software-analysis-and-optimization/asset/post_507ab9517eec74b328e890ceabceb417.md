In order to promote consistency in computations, the IEEE 754 standard also specifies four user-selectable rounding modes:

- **Round to Nearest**: The default rounding mode. As the name suggests, rounds to the closest representable number in the destination's format.
- **Round to Zero**: Always round toward zero.
- **Round to Negative Infinity**: Always round down toward negative infinity.
- **Round to Positive Infinity**: Always round up toward positive infinity.

In the case of certain conditions, floating point exceptions can be signaled through the setting of a status flag or with the generation of a status that invokes a trap handler. There are five defined exceptions:

- **Invalid Operation**: Raised when the requested computation cannot be performed. If no trap handler is specified, the result is a NaN.
- **Division by Zero**: If no trap handler is specified, the result is infinity.
- **Overflow**: If no trap handler is specified, the result is rounded based on the current rounding mode.
- **Underflow**: Same behavior as overflow.
- **Inexact**: Raised when the rounding of a result is unable to be precisely represented in an overflow.

## 1.2.2 X87 FLOATING POINT

Unlike the 8086, the x87 exposes its registers as a stack instead of flat registers. Each of these eight registers is 80 bits in length, and each value is internally stored and computed in double format. Values from memory, or 8086's registers, are converted from integers, floats, and doubles into this 80-bit format when they are pushed onto the stack. Unlike a traditional stack, each register is also addressable by register relative to the top of the stack. The top of the stack is designated as ST(0). Subsequent registers are designated with an offset, such as ST(1), ST(2), and so on.

Usage of stack makes the FPU operate much like Reverse Polish Notation. For example, in order to add two numbers, both could be pushed onto the stack before executing a `FADD` instruction. This instruction will pop numbers off the stack, perform the addition and push the result onto the stack.

## 1.3 Early Intel® Architecture

A stack was chosen for the registers as it is intuitive for mathematical operations like RPN and accommodates one operand. Using the FXCH instruction, two stack registers can be swapped, and thus the registers could be utilized in a fashion.

Aside from the registers, the 8087 had a 16-bit status register. The status register for FPU is similar to the EFLAGS register for the CPU. The first 6 bits correspond to IEEE 754 exceptions that can be raised during a computation, plus an additional bit to indicate denormalized operand. Additional entries include 3 bits dedicated to the index of the current register at the top of the stack, 4 bits for expressing condition codes, and similar to the flags in EFLAGS that are used for comparisons and branches, and a bit representing interrupt request. The tag register, with 2 bits per register, stores the status of the stack. Each register can be marked as either having a valid entry, an entry of zero, or being empty. The control register allows for masking and unmasking of interrupts, as well as control of the rounding mode and precision mode.

Similar to the parallel architecture of the 8086, the 807 is also divided into two components. The first component, the control unit (CU), is responsible for handling instructions and memory operations, and synchronizes with the main processor, and thus mirrors the BIU of 8086. The second component, the numeric execution unit (NEU), is responsible for performing actual computations, and thus mirrors the EU of 8086. While the floating point unit (FPU), 807 was executing floating point instruction, the CPU was free to execute general purpose instructions, providing parallelism to improve performance.

The 807 and subsequent coprocessors remained separate chips until the 8048 processor, which features MMX technology, SSE, and Vector Extensions (Intel® AVX), which are also capable of floating point operations, the x87 FPU is still heavily utilized in areas where additional precision is needed.

## 1.3 8026 AND 8027

After the 8086 and 80186, the 8026 was introduced in 1982. What makes the 8026 worthy of mention is that it was the first x86 processor designed for multitasking. Much of this multitasking support came through the addition of a memory protection scheme to isolate tasks from one another.

Up until this, no memory protection existed; every byte in the address space was treated equally, regardless of whether it belonged to the operating system or a user application. This meant that there was no mechanism to prevent a user application from tampering with the code and data of another application or of the operating system. Obviously, this was less optimal for security, for application isolation, or for operating system constraints on application behavior. To remedy this, the 8026 included an on-chip Memory Management Unit (MMU), which was responsible for transparently translating between logical segmented addresses consisting of a segment selector and offset, and physical addresses, and for enforcing memory protection. Therefore, each process on the system could be isolated in a separate address space.

## 1.3 Intel® 80286 and 8028

### 1.3.1 PROTECTED AND REAL MODE

Because this represented a paradigm shift in the processor's programming model, two models were split into two processor modes. The legacy mode, which was utilized by the 8086 and 80186, was called Real-Address mode, or simply real mode. The new MMU with memory protections was called Protected Virtual-Address mode, or protected mode. To retain compatibility with legacy applications for the 8086 and 80186, the processor booted into real mode, ensuring that applications would use the 8026 as a faster and better 8086. Applications that would take advantage of the features in the new model would boot into real mode and then switch into protected mode.

Transitioning from real mode to protected mode is a fairly straightforward process. The first step is to create and load all of the protected mode structures, so that the protected environment operates immediately after the switch. The PE in the first control register, CR0, is set, which effectively enters protected mode. Finally, a jump instruction is performed to flush any processor caches. At this point, the processor is now executing in protected mode and any new functionality can be utilized. Once protected mode was entered, there was no method of returning to real mode without resetting the processor.

### 1.3.2 PROTECTED MODE SEGMENTATION

Support for these protected memory regions meant that the current segmentation memory model had to be extended. Originally, segments had been fixed in size; however, that memory protection became more cumbersome, since the fixed sizes were too large for fine-grained tasks. In order to solve this, segments in protected mode were now of variable size.
