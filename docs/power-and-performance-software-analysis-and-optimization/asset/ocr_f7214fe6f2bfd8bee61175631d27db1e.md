Notice that three of the four categories, Bad Speculation, Front End Bound, and Back End Bound, sound fairly deomin. Each of these categories represents stalls within the CPU pipeline, that is, unproductive cycles. Therefore, the percentage attributed to these categories are a less-is-better metric. On the other hand, the fourth category, Retiring, represents forward in the CPU pipeline, which is productive cycles. The percentage attributed to the Retiring is a higher-is-better metric.

The formulas for calculating the percentages attributed to each category are shown in Figure 6.2. The variables at the top of this figure, excluding W, are the PMU events required for the analysis. The IDQ_UOPS_NOT_DELIVERED is nonarchitectural event introduced in the Second Generation Intel® Core™ processor family. As a result, this analysis requires a processor based on the Second Generation Intel microarchitecture or newer.

Since the width represents the number of μops that can be allocated per cycle, the denominator in each of these equations, the pipeline times the total number of cycles, represents the theoretical maximum of μops that could be allocated. Ideally, as shown in Equation 6.2(c), the number of retired μops would equal this theoretical maximum.

Once these metrics have been calculated, the next steps depend on which category dominates the results. Obviously, it is beneficial to first focus on the three categories that represent unproductive cycles. While a high retiring percentage indicates efficient pipeline utilization, it doesn't necessarily mean further performance can be obtained.

```
D = IDQ_UOPS_NOT_DELIVERED.CORE
M = INT_MISC_RECOVERY_CYCLES
N = CPU_CLK_UNHALTED_THREAD
R = UOPS_RETIRED_RETIRE_SLOTS
U = UOPS_ISSUED.ANY
W = pipeline width
```

| P_FE = % Front End Bound | (D/N) * 100 | (6.2a) |
| P_BS = % Bad Speculation | ((U - R + (W * M))/N) * 100 | (6.2b) |
| P_R = % Retiring | (R/N) * 100 | (6.2c) |
| P_BE = % Back End Bound | 100 - (P_BS + P_FE + P_R) | (6.2d) |
