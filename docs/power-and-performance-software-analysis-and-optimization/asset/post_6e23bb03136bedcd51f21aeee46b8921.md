When Git stops to edit a commit, the changes of that commit are already added to the current index, that is, already staged for committing. In order to unstage run git reset HEAD. Now the changes introduced in the commit can be modified, partially staged to create multiple commits.

Splitting changes to a single file can be performed with an interactive add, via hunks added to the index. To stage hunks, select command five, with the label “patch”. Now select the number corresponding to the file with the desired changes. Once all of the files have been selected, press Enter with a number to begin iterating each hunk present in each of the selected files.

For each hunk, the user is prompted whether they want to stage the change, option “y”, skip the change, option “n”, edit the hunk, option “e”, stage this hunk and all later hunks in the file, option “a”, split the hunk into smaller hunks if possible, option “x”, or skip the current change and all other changes, option “q”. Once all of the changes have been staged, commit as normal. Repeat the process until all the desired commits have been created, and then continue the rebasing with git rebase continue.

## Sending patches with git

Traditionally, patches are generated via the diff utility, applied via the patch utility, and communicating attaching the patch file into an email. Git was designed with this workflow in mind, and therefore provides tools to simplify working with patches.

Patches can be created for a series of commits by utilizing git format-patch, which creates a patch file, in the mbox format, for each specified commit. The first line of the commit message is designated as a short summary for the patch, and is used as the subject line for the corresponding email. The From header is populated from the author's name and email address.
