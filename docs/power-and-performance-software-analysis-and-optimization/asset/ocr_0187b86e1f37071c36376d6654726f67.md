The Pixman library provides software implementations for various image and pixel operations, such as composing images. Pixman is used by cairo and the X server as a software fallback when hardware-accelerated implementation of the operation is available. When a Pixman function appears as a hotspot in profiling, the first step is to determine whether hardware-acceleration is being used. Graphics hardware often has limitations on the image formats, image sizes, and operations that can be accelerated. As a result, detecting software fallback and correcting the code to avoid these limitations, and therefore software routines, improve performance.

# 10.2 buGle

The buGle library is an instrument shim, designed for collecting OpenGL traces and statistics. Using the LD_PRELOAD mechanism, the buGle library is loaded before the dynamic linker begins resolving symbols for the application. Because buGle provides all of the symbols that are typically provided by libGL.so or libEGL.so, the OpenGL function calls for a dynamically linked application, are resolved by the dynamic linker to the buGle instruments. These instrumented functions invoke the original libGL.so or libEGL.so functions, but additionally keep track of any desired OpenGL state, such as the function calls made, their durations, and their result.

As a result of this implementation, buGle allows for data collection to be performed on unmodified, dynamically linked, binaries. At the same time, this implementation also has the downside of requiring buGle to remain synchronized with the current OpenGL and ES implementations.

The recording and reporting capabilities of buGle are grouped together into filters. Each filter, such as stats_basic, trace, and showerror, corresponds to what aspects of OpenGL are traced, and therefore subsequently reported. Filters export counters, which can be combined and operated in order to generate custom statistics that can also be displayed.

The definition of one or more enabled filters, along with any custom reporting and statistics, is referred to as a chain. The chain utilized at runtime for tracing is selected the BUGLE_CHAIN environmental variable. Custom chains are defined in the $HOME/filters file, while custom statistics are defined in the $HOME/bugle/statistics file.

Some of the more common filters are:

+   - checks Records warnings, and skips the erroneous function call, on
- showc Records OpenGL errors, that is, glGetError()
- trace Records every GL function executed, with the function parameters
- stats_calltimes Records the duration of each OpenGL function call per frame
