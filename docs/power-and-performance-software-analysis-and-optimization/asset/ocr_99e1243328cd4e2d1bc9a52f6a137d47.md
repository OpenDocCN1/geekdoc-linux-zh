# 11.3.2 IDLE STATS

Maintaining residency in deep idle, that is, C is necessary for reducing power consumption. The Idle Stats window of PowerTOP dissect the system's idle state residency by processor topology, showing the percentage of time spent in each idle state for the processor packages, cores, and hardware. This natural hierarchy allows for an analysis of why certain states were not entered, with each level in the topology requiring the underlying levels enter their idle states. For instance, a processor core can only enter an idle state if its hardware are idle and a processor package can only enter an idle state if all its underlying core and uncore resources are idle.

By monitoring the core and package residencies in the various idle states, it is possible to quantify how-efficient the software is allowing the hardware to be. Additionally, it can identify problems within the system's configuration. The lack of the ability to enter a deeper idle state, that is, a residency of zero, can be indicative of a misbehaving or disbehaved driver. Consider that the integrated graphics hardware is present within the processor package, that is, it is an uncore resource. Since all core and uncore resources within the associated package idle state, which provides the largest power reductions, a misbehaving driver or incorrect configuration that doesn't allow the GPU to enter a RC6 state can drastically affect power and additionally affect the ability of the processor to utilize turbo modes. Unfortunately, this is a very real problem over the last couple of years, as some distributions have disabled RC6 support in the graphics BIOS tables. Make sure RC6 is enabled and working correctly.

It is important to note that just PowerTOP displays idle state does not mean the underlying hardware necessarily supports that. So a zero residency in the deepest sleep state does not necessarily indicate an issue.

11.2 shows an example of the idle state residencies for a Second Generation Intel® Core™ processor laptop. Notice the processor topology, starting from the left: one package, which depends on four cores, which in turn depend on eight hardware threads. Additionally, the GPU residencies can be found at the bottom of the window, which may require scrolling with arrow keys. Notice that the deepest package idle state has a nonzero residency, and each of the cores and the GPU have high residency percentages in the deepest available states. Additionally, take notice of the zero residency in the RC6p and RC6pp states. These residencies are not an error in the configuration, since RC6 support was introduced with the Third Generation Intel® Core™ processors and RC6pp was introduced after that.
