# 5.3 TIMING

In order write benchmarks, it is necessary to understand how to take accurate measurements. One of the most commonly taken measurements is that of time, that is, how long a snippet of code takes to execute a given workload. The process for measuring time seem like it should be fairly straightforward, computer timers are actually a fairly complex subject.

When using timers, or taking any other measurement, it is necessary to always be aware of the measurement resolution, that is, smallest measurable measurable. For instance, if two algorithms are being measured, and the first algorithm runs for 1 ms and the second runs for 100ms, but the timer used for measurement only has a resolution in seconds, then both algorithms will be recorded as taking zero seconds and the significant differences between the two will be lost.

Another important aspect to consider is whether the timer is monotonically increasing. A monotonically increasing timer always returns a result that is greater than or equal to returned results, and thus ensures that the timer moves backwards. A timer without this guarantee could yield misleading results. In the best case, the backwards movement would lead to an arithmetic underflow when comparing the second reading against the first, and thus the results would be obviously wrong. In the worst case, the backwards movement would be enough to not cause an underflow, but would still provide an inaccurate reading, and thus the results would be silently corrupted.
