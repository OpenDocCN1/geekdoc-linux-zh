Equations 6.6(c) and 6.6(f) represent the percentage of cycles where a $\muop$ could not be allocated either because the Reservation Station or Reorder buffer were full. The Reservation Station is the buffer in which $\muops$ are stored until their resources are loaded and one of the appropriate units becomes available. The Reorder buffer is used to store a $\muop until its associated instruction is scheduled to retire. Instruction retirement occurs in the same order as the program requested, and at this point all of the $\muops$ are made visible to the execution pipeline. In other words, the Reorder buffer is used to ensure that out-of-order execution occurs transparently to the developer.

# 6.2.3 BAD SPECULATION

Unlike the case of the Front End and Back End categories, in the Bad Speculation category $\muops$ are successfully allocated from the Front End to the Back End; these $\muops$ never retire. This is because $\muops$ were speculatively executed from a branch that was predicted incorrectly. As a result, all of the $\muops$ with instructions from the incorrect branch need be flushed from the execution pipeline.

It is important to note that this category doesn't quantify the full performance impact of branch prediction. Branch prediction also impacts the Front End Bound category, since the branch predictor is responsible for deciding which instructions to fetch.

Equation 6.7(a) in Figure 6.7 provides an estimate of the percentage of cycles wasted due to removing mispredicted $\muops$ from the execution pipeline. The branch misprediction penalty, variable $P$, is estimate at around 20 cycles (Intel Corporation, 2014).

Obviously, in the case of bad speculation, the culprit is branch mispredicts. The next step is to use sampling to determine which branches are responsible, and how to work on improving their prediction. Chapter 13 gives more detail on improving branch prediction.
