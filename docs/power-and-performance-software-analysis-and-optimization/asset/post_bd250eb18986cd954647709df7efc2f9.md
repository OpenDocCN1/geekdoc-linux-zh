The full list of official tests list-available-tests can be retrieved by executing:

```
$ phoronix-test-suite list-available-tests
```

These test profiles, with test results from the community, are available at http://www.openbenchmarking.org. After the Phoronix Test Suite has finished collecting the desired results, the option is to upload those to the OpenBenchmarking website, which publishes the results publicly. Along with the results, some system information, as distro and software versioning, and hardware information are also published, allowing others to compare results between profiles of interest. Each result is assigned a unique id, that can be used to refer that test and its results. Aside from public results, the OpenBenchmarking website allows users to publish and share custom test profiles.

When passing tests to the phoronix-test-suite script, there are a number of different methods for referencing tests. Commands can usually perform their actions on one of:

- **Test Profile** Command operates on the individual test.
- **Test Suite** Command operates on every test profile contained within the group.
- **OpenBenchmarking.org ID** Command operates on the same test profile or suite associated with the given ID on OpenBenchmarking.org.
- **Test Result** Command operates on the same test profile or suite associated with the given name.

Additionally, test profiles and suites can be referenced by their file system path, relative to the Phoronix directories. This allows for the grouping of related items in subdirectories and for clarification of ambiguous requests.

Test profiles and suites are categorized as either local or official. This categorization serves to identify where the test came from, and to reduce ambiguity in the case of two tests with the same name. The directory structure for available test profiles and suites, folders local, which contains the local tests, and pts, which contains the official Phoronix directories. At the time of this writing, the Phoronix Test Suite only checks two directories for profiles during installation. Within those directories, and within the test results directory, custom directory hierarchies can be created to organize content.

For instance, consider the situation where there are two projects, project 0, and project 1. Each of these projects consists of three tests: test0, test1, and test2. In order to accomplish this, two project folders could be created within the local test profile directory, and then three test profile directories could be created within each of those folders. Because the names of the test profiles, test0, test1, and test2, are ambiguous, the full path, relative to the test profile directory, be used to reference the individual tests, that is, local/project0/test0 and local/project1/test0.

By default, Phorix stores all of the test profiles, test suites, and test results in ${HOME}/.phorix-test-suite/. Tests are also typically installed and execute from this directory. Inside ${HOME}/.phorix-test-suite/, the following directories exist:

- download-cache Contains local copies of downloaded files for testing
- installed-tests Contains the installed benchmark executables and at runtime files required for testing
- modules Contains available modules
- openbenchmarking Contains any resources downloaded from the OpenBenchmarking website
- test-profiles Contains the test profile definitions which are responsible for describing each test and performing the installation
- test-suites Contains the test suite definitions
- xsl Contains the Extensible Stylesheet Language (XSL)

# Configuration

Before installing and running benchmarks, it is necessary to configure the framework. Almost all of the configuration options exposed by the Phorix framework, as opposed to the individual tests, are controlled by the ${HOME}/.phorix-test-suite/user-config.xml file. For reference, Table 5.2 documents all of the options exposed via this XML file. Changes can be made by directly editing the file, or by executing:

```
$ phorix-test-suite user-config set key-value
```

If no user-config.xml exists, the phoronix-test-suite script will create one with t default values. At any time, the configuration can be restored to the default values by deleting the user-config.xml file, and letting the phoronix-test-suite script regenerate, or by executing:

```
$ phorix-test-suite user-config-set
```

The basic formatting, colors, and watermarks for the result graphs can be customized by editing the style fields in ${HOME}/.phorix-test-suite/graph-config.json.

Aside from these configuration files, there are about twenty environmental variables that can modify the behavior of the tests, result output, and so on.

For convenience, there is also an interactive command for configuring

```
$ phoronix-test-suite network-setup
```

## 5.4 Phoronix Test Suite

### Installing tests

Before any benchmarks can be run, they must first be installed. This operation is performed by executing:

```
$ phoronix-test-suite install <test reference>
```

For example, to install the three test profiles that measure boot time with systemd:

```
$ ./phoronix-test-suite install systemd-boot-kernel \
> pts/systemd-boot-userspace \
> systemd-boot-total
```

First, Phoronix creates a lock file in the client's temporary directory, entitled "phoronix-test-suite.archive." This serves to prevent multiple instances of Phorix processes from interfering with each other.

Second, the test profile's support_check.sh script runs to determine whether the benchmark is appropriate for the current system. For instance, in the previous example, the boot time test profiles, this script checks whether the system uses systemd as its init system. If not, there is no point in attempting to install the test, since it has no meaning on this system. The exit status from the script is used to communicate whether the features needed by the test are supported.
