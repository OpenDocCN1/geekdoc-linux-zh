# 1.1.3 INSTRUCTIONS

Continuing the scenario described in the introductory section, and deasserted, the processor initializes the program registers when the #RESET pin is asserted and deasserted, their predefined values. This includes the predefined value of the instruction pointer, providing the BUI the first fetch to decode and for the execution unit.

This location is always the last 16 bytes in the physical address space. For a 16-bit processor with 20-bit physical addresses, this is 0xFFFF0. This provides enough room for a JMP to the BIOS's real initialization code.

To understand the reasoning behind this, consider that the first instructions executed, are responsible for initializing the system and preparing a standard execution environment before booting the operating system, belong to the BIOS. The BIOS is mapped into the physical address space, is stored in a ROM, located on the motherboard, connected with a Low Pin Count (LPC) bus. This ROM is mapped to the very top of the physical address space, such that the last byte of the ROM is the very top. Therefore, differently ROMs have different starting addresses within memory. For example, a 1-KB ROM would start at 0FFFF – 0xFF00 + 1 = 0xFFC00, whereas a 4-KB ROM would start at 0FFFF – 0xF000 + 1 = 0xFF000. These first instructions executed, the last bytes of the BIOS ROM, are the only others guaranteed to contain valid code, and it belongs to the BIOS; it is guaranteed to know where in physical memory the rest of the initialization code resides.

From this point, the processor continues its loop of fetching new instructions, decoding these instructions, and executing those instructions. Each instruction defines an operation that transitions the state machine from one to another. Each individual instruction is comprised of one or more forms, that is, various encodings handling different operand types. An operand is simply a parameter for the instruction, defining what aspect of the state should be acted upon.
