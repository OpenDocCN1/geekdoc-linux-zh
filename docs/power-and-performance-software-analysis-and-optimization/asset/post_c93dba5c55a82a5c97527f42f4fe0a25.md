## 1.1 INTEL® 8086

8086, introduced in 1978 and shown in Figure 1.1, was not the first processor developed by Intel, however it was the first processor to implement what be known as the x86 architecture. In fact, the two digits in the name x86 correspond to the fact that the first x86 processor designations all ended with 86, such as 8086, 80186, 80286, 80386, and so on. This trend was continued until Intel the Pentium® family. Despite being introduced in 1978, the 8086 was continually produced throughout the 1980s and 1990s. Famously, NASA had been the 8086 processor in its shuttles until 2011.

In contrast to the thousands of pages in the Intel® Software Developer Manual (SDM), the 8086 user manual, including a full reference on the system behavior, programming tools, hardware pinout, instructions and opcodes, and so on, fits within about two hundred pages. This simplified nature makes the x86 architecture an excellent introduction to the fundamental concepts of the x86 architecture. The rest of this book will build further on the concepts introduced here.

In the architecture of the 8086, there are three fundamental design principles (Intel Corporation, 1979). The first principle is the usage of specialized components to isolate and distribute functionality. In other words, rather than one monolithic system architecture, building an 8086 system provided flexibility in the peripherals selected. This allowed system builders to customize the system to best accommodate the needs of the given situation. The second principle is the inherent for

To illustrate these principles, consider that with the 8086, there were two Intel processors available, the 8088 and 8089. The 8088 was an identical processor to the 8086, except that the external data bus was 8 bits, instead of 16 bits. The 8088 was chosen by IBM for the heart of the “IBM compatible PC.” The 8089 was a separate coprocessor, with its own instruction set and assembler, designed for offloading data transfers, with Direct Memory Access (DMA) requests. Interestingly, the 8089 was not chosen by IBM for the “IBM compatible PC,” and was never widely adopted.

The EU, however, is unable to access the system's memory, which requires usage of the system bus. The BIU is solely responsible for interfacing with the system bus. This separation allows for the two units to operate in parallel, with the BIU fetching data over the bus while the EU is executing instructions.

To accommodate this asynchronous nature, the two units interface with an instruction queue, therefore allowing the BIU to fetch instructions before they are required. When the BIU detects that there is an available slot in the queue, it begins to fetch an instruction to fill that slot. When the EU detects there is a valid entry in the queue, it removes it and begins executing it. If the EU requires the evaluation of a memory operation, it passes the effective address to the BIU, which suspends prefetching and retrieves the desired system information.

### 1.1.1 SYSTEM STATE

For the general case, there are three members of the 8086 hierarchy: the processor's registers, the system memory, which is RAM, and persistent storage, that is the disk drive. The registers provide volatile storage very close to the processor on the device. Since this memory is very fast, it is also very expensive, and very scarce. On the other hand, the volatile memory is significantly cheaper than the registers, and therefore more prevalent than the registers, but also orders of magnitude slower. Similarly, the persistent storage is significantly cheaper than the external memory, and therefore available in greater quantities, but also orders of magnitude slower than external memory. To quantify the inverse relationship between storage density and speed, consider that the 8086 might be paired with a 10 MB hard drive, which was capable of addressing 1 MB of external RAM, and had 16-bit registers.

### Address space

The 8086 is comprised of two different address spaces, the memory address space, and the I/O address space. The memory address space is capable of 1 MB, and the I/O address space is capable of 64 KB. The I/O address space is mapped into the memory address space using a technique referred to as segmentation. A logical address is comprised of two components, a segment selector and an offset. The segment selector takes the form of a register. The offset is a displacement. To translate a logical address into a physical address, the segment register is shifted left by 4 bits, which is equivalent to multiplying by 16, and then added to the offset.

The EU only handles logical addresses, with address translation from logical to physical being handled by the BIU. The 8086 utilizes four segments: (0) the code segment, described by the CS register, (1) the stack segment, described by the SS register, (2) the data segment, described by the DS register, and (3) the extra data segment, described by the ES register. Some instructions imply the stack and instruction fetches imply the code segment. In other cases, the segment register will need to be explicitly provided.

### 1.1.2 REGISTERS

Aside from the four segment registers introduced in the previous section, the 8086 has seven general purpose registers, and two status registers.

The general purpose registers are divided into two categories. Four registers, AX, BX, CX, and DX, are classified as data registers. These data registers are accessible as either the full 16-bit register, represented with the X suffix, the low byte of the 16-bit register, designated with an L suffix, or the high byte of the 16-bit register, delineated with an H suffix. For instance, AX would access the full 16-bit register, whereas AL and AH would access the register's low and high bytes, respectively.

The second classification of registers is the pointer/index registers. This includes the following registers: SP, BP, SI, and DI. The SP register, the stack pointer, is reserved for usage as a pointer to the top of the stack. The SI and DI registers are typically used implicitly as the source and destination pointers, respectively. Unlike the data registers, the pointer/index registers are only accessible as full 16-bit registers.

As this categorization may indicate, the general purpose registers come with some guidance for their intended usage. This guidance is reflected in the instruction forms with implicit operands. Instructions with implicit operands, operands are assumed to be at a certain register and therefore don't require that operand to be encoded, allow shorter encodings for common uses.
