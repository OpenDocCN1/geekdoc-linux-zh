# # NEON intrinsic reference

The arm_neon.h header file defines 102 data types and 2009 intrinsics that allow the programmer to explicitly include support for ARM NEON instructions in high-level source code. To use an intrinsic, the programmer needs to only call a specific function, but intrinsics are not normal functions. Each intrinsic is defined as an inline function that acts as a wrapper around a built-in command that forces the compiler's back-end to emit a specific instruction (often along supporting instructions).

This appendix provides additional details on ARM NEON intrinsics beyond that provided in Chapter 2. Interested readers should refer to the actual header file, located in /usr/lib/gcc/arm-linux-gnabihf/<version>/include, as well as ARM's documentation for additional details on NEON programming.

# ## B.1 VECTOR DATA TYPES

Tables B.1–B.9 list the types defined in arm_neon.h. NEON intrinsics support 64-bit and 128-bit (quad-word) vectors comprised of signed and unsigned integers and floating-point values.

Intrinsics that use 64-bit (double word) vectors have no suffix, while those use 128-bit (quad-word) vectors require a q-suffix that typically appears after the operation name and before the element type. example:

+   - vmul_s8 performs a pairwise two 64-bit vectors, each comprised of eight-bit signed integers of type int8x8_t
- vmul_qs8 (with the q-suffix) performs a pairwise multiply two 128-bit vectors each comprised of sixteen eight-bit signed integers of type int8x16_t.

NEON also supports special integer vectors called polynomials. Polynomial elements are stored in integer format, but carries are disabled whenever an arithmetic operation uses polynomial input and output operands. As such all additions are replaced with bitwise XOR operations.
