This partitioning is achieved using loop tiling. Loop tiling is a systematic approach that changes the order in which elements are accessed when traversing a multidimensional array. Instead of iterating through each dimension before incrementing the index of the next dimension, the iteration space is decomposed into a series of smaller blocks, where all indices within each block are processed before moving to the next block. To do this, the programmer must add additional levels of outer loops in order to process each “tile” of the image space.

# CHAPTER 4 Memory Optimization and Video Processing

For example, consider the following loop:

```
for (i=0;i<SIZE_Y;i++)
    for (j=0;j<SIZE_X;j++)
        do_something(i,j)
```

This loop can be tiled by adding two levels of nesting:

```
for (i=0;i<ceiling(SIZE_Y/TILESIZE_Y);i++)
    for (j=0;j<ceiling(SIZE_X/TILESIZE_X);j++)
        for (ii=i*TILESIZE_Y;ii<(i+1)*TILESIZE_Y;ii++)
            if (ii<SIZE_Y)
                for (jj=j*TILESIZE_X;jj<(j+1)*TILESIZE_X;jj++)
                    if (jj<SIZE_X)
                        do_something(ii,jj)
```

## 4.6 TILING AND THE STENCIL HALO REGION

As shown in Figure 4.15, a 2D stencil comprising $n$ rows and $m$ columns will access $[n/2]$ rows above and below the tile boundaries, and $[m/2]$ columns to the left and right of the tile boundaries. These pixels form the *halo* region around each tile.

When tiling a stencil loop, the programmer may wish to buffer each tile in a smaller array whose row size matches the tile width. In this case, the programmer must also copy the halo region.

## 4.7 EXAMPLE 2D FILTER IMPLEMENTATION

This section describes how to build a tiled image filter in order to explore the performance impact of tile optimization.

Begin by defining a structure to store a 2D value:

```
struct size {
    int x;
    int y;
};
```

![](img/e6ebc663bbb86c6e7bf9ef22ad136e6f_171_0.png)

**FIGURE 4.16** Boundary tile.

Define a structure to hold the tile size, its location in an image, and the image size:

```
struct tile {
    struct size tile_size, tile_loc, image_size;
};
```

Before filtering each tile the program must determine how to handle tiles where part of the tile extends beyond the image boundary, specifically those of the image boundary, as shown in Figure 4.16.

To do this, determine if the program is processing a boundary tile. If so, determine if the right or bottom edge of the tile is outside the limits of the image. Use a function to precompute the limitations for the X and Y dimension:

```
void find_limit(struct tile *mytile,struct size *limit) {
    limit->x = ((mytile->tile_loc.x+1) * mytile->tile_size.x - 1 >
               mytile->image_size.x) ?
               mytile->image_size.x%mytile->tile_size.x :
               mytile->tile_size.x;
    limit->y = ((mytile->tile_loc.y+1) * mytile->tile_size.y - 1 >
               mytile->image_size.y) ?
               mytile->image_size.y%mytile->tile_size.y :
               mytile->tile_size.y;
}
```

## 4.7 Example 2D Filter Implementation

Next, write functions that apply a 2D and 1D filter to a tile. The function takes as input:
- (1) a tile object, which defines the size of the tile and its location within the image
- (2) a pointer to grayscale-point representation of the input image
- (3) a pointer to the output image
- (4) a pointer to the coefficient array
- (5) the size of each filter dimension
- (6) the usable portion of the tile, to avoid writing beyond the edge of image when processing boundary tiles
- (7) a flag that specifies whether the output image already contains one of direction vector, useful when calculating the Sobel filter.

```
void filter_tile2d(struct tile *mytile,
    float *in,
    float *out,
    float *coeffs_2d,
    int fsize,
    struct size *limit,
    int vec) {
```

The filter must iterate over each value in the tile, requiring two-level nested loop. Each dimension of the loop must be constrained by limit, which can be precomputed using the find_limit() function prior to calling this function.

```
int i,j,k,l,offset,coeff_radius,img_x,img_y;
float sum;
coeff_radius = fsize;
for (i=0;i<limit->y;i++) {
    img_y = mytile->tile_loc.y * mytile->tile_size.y + i;
    for (j=0;j<limit->x;j++) {
        img_x = mytile->tile_loc.x * mytile->tile_size.x + j;
        sum = 0.0;
        // The filter itself is pairwise-accumulate between pixels and their corresponding coefficients.
        // Use if-statements to avoid accessing halo pixels that are outside the boundaries of the image:
        for (k=-coeff_radius;k<coeff_radius+1;k++) {
            if (((img_y+k) >= 0 && ((img_y+k)<mytile->image_size.y)) {
                for (l=-coeff_radius;l<coeff_radius+1;l++) {
                    if (((img_x+l) >= 0 && ((img_x+l)<mytile->image_size.x)) {
                        offset = (i+coeff_radius)*mytile->image_size.x + (j+coeff_radius);
                        // (logic for accumulation using coeffs_2d and vec would go here)
                    }
                }
            }
        }
    }
}
```

This calculates the offset of each input pixel. In this case the pixels are contained within a tile buffer whose dimensions match the size of the tile and its enclosing halo region.

In a separate 1D horizontal filter function use the following loop (note the coefficient array is named "coeff_h" in this version):

```
for (k=-coeff_radius;k<coeff_radius+1;k++) {
    if (((img_x+k) >= 0 && ((img_x+k)<mytile->image_size.x)) {
        offset = (i+coeff_radius)*mytile->image_size.x + (j+coeff_radius)+k;
        sum += in[offset] * coeffs_h[k+coeff_radius];
    }
}
```

In a separate 1D vertical filter function use the following loop (note the coefficient is named "coeff_v" in this version):

```
for (k=-coeff_radius;k<coeff_radius+1;k++) {
    if (((img_y+k) >= 0) && ((img_y+k) < mytile->image_size.y)) {
            offset = (i+coeff_radius+k)*mytile->image_size.x + (j+coeff_radius);
            sum += in[offset] * coeffs_v[k+coeff_radius];
    }
}
```

Lastly, in all three functions, calculate the address of the output pixel and store it. If the vec flag is set, the output is calculated as the norm for the current value and the newly calculated value.

```
offset = (i+coeff_radius) * (mytile->image_size.x + coeff_radius) + j + coeff_radius;

if (vec) {
    out[offset] = sqrt(out[offset]) * out[offset] + sum * sum;
} else {
    out[offset] = sum;
}
```
