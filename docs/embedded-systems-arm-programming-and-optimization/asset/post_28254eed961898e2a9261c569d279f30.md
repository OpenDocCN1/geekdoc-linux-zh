## 2.10 OPTIMIZATION #3: MULTIPLE FLOPS PER SINGLE INSTRUCTION, MULTIPLE DATA

Nearly all modern processors have the ability to perform multiple independent operations using one instruction. These are called Single Instruction, Multiple Data (SIMD) instructions or vector instructions. SIMD instructions decrease the number of instructions per operation, which increases floating point throughput and decreases cache miss rate.

Some processors, such as the ARM Cortex A9 and A15, provide the ability to issue a SIMD instruction in less than an equivalent number of scalar instructions. These processors have multiple SIMD lanes, in which there are a register file that provide simultaneous access to all the necessary input and output registers. In this case, using SIMD instructions allows multiple operations in a single clock cycle compared to using scalar instructions.

Other processors, such as the ARM11, provide SIMD instructions but they require the same number of cycles to issue as scalar instructions. In other words, it requires n cycles to issue an n-way SIMD instruction, while would also take n cycles to issue n regular one-way instructions. While it may seem that, in this case, using SIMD instructions is pointless, these instructions can still provide benefits by providing for less code size and potentially reducing cache misses, but more importantly hiding the latency required by a dependent chain without SIMD instructions. For example, consider the following loop:

```
for (i=0; i<n; i++) {
    fmacs s0, s1, s2 // assume $s1 is loop-invariant
    fmacs s2, s1, s0 // $s0 depends on the result of the previous instruction
...
}
```

## 2.10 Optimization #3: Multiple Flops per Instruction with Single Instruction, Multiple Data

Assume for the sake of this example that the latency of the fmac instruction is four cycles, it will require five cycles to issue the first two instructions. Assuming it is not possible to move enough of the other instructions from the loop body to cover this latency, unroll the loop by a factor of 4 to find more instructions to hide the latency. In this way instructions from other iterations are “borrowed” to cover the latency:

```
for (i=0;i<n;i+=4) {
    facs s0, s1, s2
    facs s2, s1, s0
    ...
    facs s4, s1, s2
    facs s6, s1, s4
    ...
    facs s8, s1, s2
    facs s10, s1, s8
    ...
    facs s12, s1, s2
    facs s14, s1, s12
    ...
}
```

This does not solve our problem, since the instruction stream will have four cycles of uncovered latency between each pair of instructions. Now interleave the four pairs of instructions as:

```
for (i=0;i<n;i+=4) {
    facs s0, s1, $s2
    facs s4, s1, $s2
    facs s8, s1, $s2
    facs s12, s1, $s2
    facs s2, s1, $s0
    facs s6, s1, $s4
    facs s10, s1, $s8
    fmacs s14, s1, $s12
...
)
```

Now are are three intervening instructions between each pair of dependent out-of-order instructions. Note that a processor that is capable of dynamic out-of-order execution may have been able to automatically achieve this same reordering, but depending on its capabilities it may not be able to achieve the same performance when it is done statically.

As a final step, replace the first four and second four instructions with a single SIMD instruction each.

This technique is applicable for the Horner's method kernel. However, there is a major difference in how the ARM11 and ARM Cortex processors implement SIMD instructions. This section examines both separately.

### 2.10.1 ARM11 VFP short vector instructions

The Armv6 VFP instruction set offers SIMD instructions through a feature called short vector instructions, in which the programmer can specify a vector width and stride field through the floating-point status and control register (FPSCR). Setting the FPSCR will cause all the thread's subsequently floating-point instructions to perform the number of operations and access the registers using a stride as defined in the FPSCR. Note that VFP short vector instructions are not supported by Armv7 processors. Attempting to change the vector width or stride on a NEON-equipped processor will trigger an invalid exception.

The 32 floating-point VFP registers are arranged in four banks of eight registers (each registers if using double precision). Each bank can be used as a short vector when performing short vector instructions. The first bank, registers s0-s7 (or d0-d3), will be used as scalars in a short vector instruction when specified as the second input operand. For example, when the vector width is 8, the fads s16,s8,s0 instruction will add each element of the vector held in registers s8-15 with the scalar held in s0 and store results s16-s23.

The fmrx and fmnr instructions allow the programmer to read and write the FPSCR register. The latency of the fmrx instruction is two cycles and the latency of the fbnr instruction is four cycles. The vector width in FPSCR bits 18:16 is encoded such that values 0 through 7 specify lengths 1-8.

Writing to the FPSCR register you must be careful to change only the bits you intend to change and leave the others alone. To do this, you must first read the value using the fmxr instruction, change bits 18:16, and then write the back using the fmxr instruction.

Be sure to change the length back to its default value of 1 after the kernel since the compiler will not do this automatically, and any compiler-generated floating-point code can be affected by the change to the FPSCR.

You can use the function to change the length field in the FPSCR:

```c
void set_fpscr_reg (unsigned char len) {
    unsigned int fspcr;
    asm("fmxr %%[val], [val]\n" : [val]"=r(fspcr));

    len = len - 1;

    spspcr = fspcr & ~(0x7<<16);
    spspcr = fspcr | ((len&0x7)<<16);

    asm("fmxr fspcr, %%val]\n" : : [val]"r(spspcr));
}
```
