# 5.6 PERFORMANCE RESULTS

One surprising result from the example code is that the performance measured using gettimeofday() is substantially less—indicating as little half the performance in Gflops—than the performance measured using OpenCL profiling.

When using gettimeofday(), the program begins measuring immediately after the call to EnqueueKernel(), so there is an assumption that the kernel begins execution soon after calling this function. Latency between when the kernel is queued and when it begins execution on the device will cause this perceived performance difference.

# 5.6.1 Parameter exploration

The values of the WGS, NWG, and VS parameters affect kernel performance. To examine the impact of each parameter separately, hold two parameters constant while varying the other.

# 5.6.2 Number of workgroups

The OpenCL runtime reports both of the Mali T628 GPU devices on the ODROID-X3 board contains four compute units, as reported by clGetDeviceInfo() with the CL_DEVICE_MAX_COMPUTE_UNITS option.

The kernel has little potential for load imbalance, having a uniform loop iteration count and lack of if-statements. Given this, it may be reasonable to conclude that there is no advantage to instantiate more than four workgroups, since four workgroups would utilize all available multicore parallelism.
