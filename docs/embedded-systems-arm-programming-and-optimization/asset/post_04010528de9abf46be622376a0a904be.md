## 5.6 PERFORMANCE RESULTS

One surprising result from the example code is that the performance measured using gettimeofday() is substantially less—indicating as little half the performance in Gflops—than the performance measured using OpenCL profiling.

When using gettimeofday(), the program begins measuring immediately after the call to EnqueueKernel(), so there is an assumption that the kernel begins execution soon after calling this function. Latency between when the kernel is queued and when it begins execution on the device will cause this perceived performance difference.

### 5.6.1 Parameter exploration

The values of the WGS, NWG, and VS parameters affect kernel performance. To examine the impact of each parameter separately, hold two parameters constant while varying the other.

### 5.6.2 Number of workgroups

The OpenCL runtime reports both of the Mali T628 GPU devices on the ODROID-X3 board contains four compute units, as reported by clGetDeviceInfo() with the CL_DEVICE_MAX_COMPUTE_UNITS option.

The kernel has little potential for load imbalance, having a uniform loop iteration count and lack of if-statements. Given this, it may be reasonable to conclude that there is no advantage to instantiate more than four workgroups, since four workgroups would utilize all available multicore parallelism.

Table 5.2 shows the performance results, as reported by the OpenCL profiler, with:

| Table 5.2 Kernel Performance for N=128 MB, NWG=256, VS=4 |

| NWG | Kernel FP Throughput (Gflops) |
| :--- | :--- |
| 4 | 0.6 |
| 2048 | 5.8 |
| 4096 | 6.3 |
| 8192 | 7.1 |
| 16,384 | 14.4 |
| 32,768 | 15.6 |

- * WGS=256, the maximum number in one dimension for the kernel (as reported by clGetKernelWorkGroupInfo() with CL_KERNEL_WORK_GROUP_SIZE),
- * VS=4, the preferred vector size for the device (as reported by CL_DEVICE_PREFERRED_VECTOR_WIDTH_FLOAT),
- * sweeping NWG from 4 to 32,768 (the maximum for N=128 MB).

The results show that performance improves as the workgroups is increased. For this test the maximum performance is 15.6 Gflops, achieved with the 32,768 workgroups, which indicates that the compute units has no effect on the ideal number of workloads.

Recall that Chapter 2, the same kernel executed on four ARM Cortex A15 cores at 2.23 GHz with the most tuned implementation achieved 17.8 Gflops. Note that these results were obtained on the NVIDIA Jetson TK1, which is a larger, more substantial platform than the ODROID-X3.

## 5.7 CHAPTER WRAP-UP

This chapter introduces OpenCL, a framework for developing programs for heterogeneous hardware architectures such as GPU, FPGA, DSP. At the platform level, the programmer must manage the initialization, communication, and synchronization of the devices, allocate device memory, and compile the kernel at runtime. OpenCL provides many opportunities for optimization, such as local memory, use of SIMD intrinsics, and adjusting parallelization. This chapter provides a running example in which the Horner's method program from Chapter 2 is adapted for embedded execution on the Mali T628 GPU.
