Use the “.comm” assembler directive to allocate space for the data array. This creates the array with name "data," size N*4, and whose starting address is aligned on the 4-byte boundary (evenly divisible by 4).

```assembly
2 .comm data,N,4
```

Next, use the “.global” directive to tell the assembler to export the main function (defined later) so it can be statically linked and called by Linux’s runtime environment.

```assembly
3 .global main
```

Finally, use the “.arch” directive to tell the assembler to generate ARMv7-A machine language.

```assembly
4 .arch armv7-a
```

Begin the function with the “main” label, using the first instructions to set r1 to be the iteration limit for both the outer and inner for-loops. Our first instructions will perform the following:

- 1. load the value defined as N into register r1 and
- 2. decrement this r1 by 1

```assembly
5 main: ldr r1,#N @r1=N-1
```

```assembly
6 sub r1,r1,#1 @r1=0
```

Begin the outer-loop by assigning the outer loop counter—the i variable—to register r5 and initialize it to 0:

```assembly
7 mov r5,#0 @i=0
```

Both the outer and inner loops are for-loops. For-loops are pretest loops, so they begin with a test to determine if the loop body should be executed. In this case, compare the value of the outer loop counter to the limit, which is assigned to r5 and r1, respectively. If these values are equal, exit the loop:

```assembly
8 oop:cmp r5,r1 @i==N-1
```

```assembly
9 be exit
```

The outer loop body will consist of the inner loop, which can be set up exactly for the outer loop. Use register 3 for the inner loop:

```assembly
10 mov r3,#0 @j=0
```

## 1.6 Assembly Optimization #1: Sorting

In addition to initializing our loop counter to 0, initialize a base register for the array:

```assembly
11 ldr r2,=data @r2 &data
```

In a literal translation of the C code, the inner loop will load elements j and j+1 into two registers, compare them, and store back in reverse order if necessary. Every iteration of the inner loop needs only to load element j+1, since element j would have been available in the previous iteration.

The inner loop allocates r11 for element j and register r10 for element j+1. The registers are in reverse order so use a store-multiple (stm) instruction to store the registers in order swapping the values in memory (a requirement of the stm instruction).

Before starting the inner loop program pre-load the first element.

```assembly
12 ldr r11,[r2]
```

Add our loop test:

```assembly
13 iloop:cmp r3,r1 @j==N-1
14 beq exit
```

The inner body loads value from the array (corresponding to element j+1), compares it with element j, and stores back to the array in reverse order if necessary.

Use register 2 as the base register for the current position in the array. When loading element j+1, use the pre-increment addressing mode that will load the second value and update register 2 to the address of the second value:

```assembly
15 ldr r10,[r2,#4]
```

Compare these values. The condition of element being greater than the element j+1 value will serve as the predicate for storing the values back in reverse order.

Use the store-multiple instruction when storing the elements.

```assembly
16 cmp r11,r10 @compare values
17 stm r2,(r10,r11) @store in reverse order
```

If the program stored the values back in reverse order, the current value of r11, which originally represented element j, will now have moved up one position in the array to effectively become element j+1. This value will be treated at element j in the next iteration so the program can leave it in register r11 for the next iteration.

If the values were not swapped, copy the value in register r10 to register r11 for the next iteration of the loop. The condition for this is less than or equal (le), the logical complement of greater than.

```assembly
19 move r11,r10
```

After the inner loop body, increment the index register and inner loop counter, then branch back to the beginning of the loop.

```assembly
20 add r2,r2,#4
21 add r3,r3,#1 @++
22 b iloop
```

Upon exiting the inner loop, do the same for the outer loop:

```assembly
23 exit:add r5,r5,#1 @++
24 bloop
```

Upon exiting the outer loop, return from the main function by jumping to the location stored in the link register:

```assembly
25 exit:bx lr
```

Assemble this code using gcc and time its execution:

```bash
gcc bubble_sort_asm.s -o bubble_sort -O3
time ./bubble_sort_asm
```

The time required by this assembly implementation requires 3.6 s, a speed of 11% over the compiler-generated version.

### 1.6.3 Result verification

Assembly code is less readable than C code, making it more prone to programming errors. As such, when testing an optimized implementation you should always validate its results a second, reference implementation and compare the results. Executing both implementations provides the ability to perform performance comparisons, and bugs are revealed by mismatches in the output data.

In order to move forward, convert the reference implementation into a function. This requires deleting the code relating to the array and the value of N, changing the name of the function from main to "bubble_sort", and using arguments to pass in the pointer to the array and its size:

```c
int bubble_sort (int *data,int n) {
    int i,j,temp;
    for (i=0;i<n-1;i++) {
        for (j=0;j<n-1;j++) {
            if (data[j]>data[j+1]) {
                temp = data[j];
                data[j] = data[j+1];
                data[j+1] = temp;
            }
        }
    }
}
```
