There are several methods for reading and writing NEON vector variables outside of the intrinsics. The simplest way is to treat them as any standard C array.

For example:

- Initialize on declaration:
`int8x8_t a=(0,0,2,2,4,4,6,6);`

- Set as an array:
`int8x8_t a;`
`for (i=0;i<8;i++) a[i]=i*2;`

- Read as an array:
`for (i=0;i<8;i++) printf("%d",a[i]);`
`printf("\n");`

As shown below, NEON intrinsics have a suffix that specifies the type and size of their elements. Note the conspicuous lack of 64-bit floating point.

- _s8 signed 8-bit integer
- _u8 unsigned 8-bit integer
- _s16 signed 16-bit integer
- _u16 unsigned 16-bit integer
- _s32 signed 32-bit integer
- _u32 unsigned 32-bit integer
- _p8 8-bit polynomial
- _p16 16-bit polynomial
- _f16 16-bit float
- _f32 32-bit float

Normal, double-word intrinsics assume a 64-bit total width, so the vector size is implied by the element size. For example, the _s8 intrinsic operate on a 64/8=8-element vector. As described above, the "q" specifies a 128-bit vector, so an intrinsic ending with q_s8 would operate on a 128/16=16-element vector.

Some intrinsics are used to instance a vector. For example, the vcreate intrinsics map each 8-bit field from a scalar to the elements of an 8-element vector:

```c
// set vector from least significant byte,
// i.e. a[0]=55, a[7]=55
a = vcreate_s8(0x0D0C0C0A0806040200);
```

The vdup intrinsic sets each element to a specified scalar value:

```c
int8x16_t b;
a = vdup_n_s8(5); // set all 8 elements to 5
b = vdup_n_s8(5); // set all 16 elements to 5
```

You can load and store 64-bit and 128-bit vectors using the vld1 and vld1q intrinsics. For example:

```c
// declare standard local arrays
// demonstrating vld and vst
int8_t data_in[64]
```

NEON supports loading and storing vectors with a stride of two, and four elements with the vld4 and vst4 intrinsics. One way to interpret the behavior of vld4 intrinsic is that it treats the input array as a row-major matrix with n rows and 4 columns, where n is the bit width, while the intrinsic returns the data in transposed order. The code below uses the vld4_s8 intrinsic to load data from the data_in array as declared above. The returned variable, c, is declared as an 8x4 array. The vld4 loads four words (256 bits total), but also applies a stride of four elements to each of the 8 vectors given by c.

```c
int8xx4_t c;
c=vld4_s8(data_in,8);
for (i=0;i<8;i++) {
    for (j=0;j<4;j++) printf("%d ", c[j][i]);
}
printf("\n");
```

## B.3 Vector Manipulation

Several intrinsics are available for manipulating elements within a vector.

Reversing: Vector elements can be reversed using the vrev intrinsic, for example:

```c
// reverse the eight elements in vector a
b=vrev64(a);
```

Combining: A range of elements from two vectors can be extracted and combined using the vext intrinsic. For example if a and b are the following:

```
a = {0, 1, 2, 3, 4, 5, 6, 7}
b = {8, 9, 10, 11, 12, 13, 14, 15}
```

The following intrinsic will extract the last five elements from a and first three from b:

```c
b=vext_s8(a,b,3);
```

Setting the new state of vector b to:

```
b={3, 4, 5, 6, 7, 8, 9, 10}
```

Transposing: The vtrn intrinsic takes two vectors, interprets them as a set of 2×2 matrices, transposes them, and returns the result as a 2D vector having two rows. Assume a and b are initialized as follows:

```
a={0, 1, 2, 3, 4, 5, 6, 7}
b={8, 9, 10, 11, 12, 13, 14, 15}
```

The following intrinsic will interpret these vectors as 2×2 matrices and transpose them. The result is returned as an int8x2_t type:

```c
c=vtrn_s8(a,b);
c={0, 8, 2, 10, 4, 12, 6, 14};
```

Interleaving: The vzip intrinsic takes two input vectors and interleaves them. The result is returned as a two-row vector type. For example, assume a and b are initialized as follows:

```
a = {0, 1, 2, 3, 4, 5, 6, 7}
b = {8, 9, 10, 11, 12, 13, 14, 15}
```

The following intrinsic will return the value of c:

```c
c=vzip1_s8(a, b);
c={0, 8, 1, 9, 2, 10, 3, 11, 4, 12, 5, 13, 6, 14, 7, 15};
```

The vzip intrinsic takes two vectors and returns the even-numbered elements in one vector and the odd-numbered elements in another. Starting with the same input vectors as above:

```
a = {0, 1, 2, 3, 4, 5, 6, 7}
b = {8, 9, 10, 11, 12, 13, 14, 15}
```

The following intrinsic will return the value as an int8x2_t:

```c
c=vuzp_s8(a, b);
c={0, 2, 4, 6, 8, 10, 12, 14, 1, 3, 5, 7, 9, 11, 13, 15};
```

Gather: The vbtbl intrinsic performs a "gather" operation, which takes two vectors and interprets the second vector as a set of indices to load a set of elements from the first vector. If any of the values of the second vector are out of range, vbtbl inserts zeros at their corresponding positions in the return vector. A related intrinsic, vbtlb, performs the same operation but treats out of range values in the second vector differently. For these, vbtbx copies the original values from the first vector. Assume a and b are initialized as follows:

```c
a = {0, 1, 2, 3, 4, 5, 6, 7}
b = {0, 0, 2, 2, 4, 4, 6, 6}
```

Passing $a$ and $b$ to $vtb1$ returns the following value of $c$:

```c
b=vtb11_s8(a,b);
c = {8, 8, 10, 10, 12, 12, 14, 14};
```

Combining: The `vcombine` intrinsic concatenates two vectors, where the result vector is the width of the input vectors. Assume two eight-element vectors $a$ and $b$ with the following values:

```c
a=[0,0,2,2,4,4,6,6];
b=[8,8,10,10,12,12,14,14];
```

The intrinsic call will return the 16-element vector:

```c
c=vcombine_s8(a,b);
c = {0, 0, 2, 2, 4, 4, 6, 6, 8, 8, 10, 10, 12, 12, 14, 14};
```

## B.4 OPTIMIZING FLOATING-POINT CODE WITH NEON INTRINSICS

Inline assembly does not include its own set of data types, but the NEON intrinsics are "type-aware" in that they expect their inputs to be NEON variables passed by value and their outputs are given as return values.

The need for these special vector variables complicates the process by which NEON support is added to existing code that uses C-style arrays, luckily the compiler is to reinterpret standard arrays as NEON vector pointers. However, this requires NEON code include frequent casting, making the code appear more cluttered and less readable.

To demonstrate how existing floating-point code can be enhanced with NEON intrinsics, this appendix examine a simple implementation for matrix inversion using Gaussian elimination.
