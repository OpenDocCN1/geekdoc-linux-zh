## 2.7 INLINE ASSEMBLY LANGUAGE IN GCC

GCC provides an interface that allows the programmer to embed inline assembly language into C/C++ code. Unlike writing an entire function in assembly, inline assembly allows the programmer to write only those components of the code that need to be written in assembly code.

Inline assembly allows the programmer to specify C/C++ variables and positions and operands for instructions that normally take registers or register-based addresses. In this case, the compiler substitutes registers for the variables and automatically adds any additional load immediate or load and store instructions required to temporarily allocate needed registers. The programmer may directly use registers. In this case, the programmer must specify the affected registers in a clobber list the compiler can ensure that the register state is not adversely affected by the inline instructions.

The syntax for inline assembly is shown below:

```
asm[volatile] : output operand : input operand : clobber list);
```

If the volatile modifier is included, the compiler will exclude the statement(s) from being subject to compiler optimization. In other words, the compiler will generate the assembly code as written and not modify it for the purpose of optimization.

When writing short sequences of inline assembly code, the programmer can choose to enclose each instruction in an asm statement or combine multiple instructions within an asm statement. This is not a concern when using floating-point registers, GCC is unlikely to reuse these registers between asm statements.

The output operand is a list of any C/C++ variables used as outputs for the assembly code.

The input operand is a list of a C/C++ variables used as inputs for the assembly code. It uses the same format as the output list.

The format of the input and output lists are

[name]"MC"(expression), ...

- name is the name of symbol in the assembly code. The name is preceded by a percent sign (%) in the code.
- M is an optional constraint modifier, and is usually = for write only operand+ for read-write output.
- C is a constraint, which is usually one of: f (floatingpoint register), i (immediate value), r (general purpose register), or m (memory address). For example, using "f" means that the corresponding operand be placed by the compiler into a register prior to the instruction being fetched, and its value is specified in the inline assembly using C/C++ expression.
- expression is the C/C++ expression, variable, or pointer representing the input or output.

The clobber list is a list of registers that will be modified by the instruction and is used when registers are specified directly.

For example, consider the following inline assembly statement:

```
asm("mov %[outval],%[in], r #2" : [outval]=r(b) : [in]r(a));
```

If a and b are local variables stored on the stack, this line could be translated by the compiler into the following ARM assembly:

```
ldr r3, [sp, #0          (allocate register r3 and load it with the value of a)
mov r3, r3 #2           (perform the mov instruction)

```

## 2.8 OPTIMIZATION #1: REDUCING INSTRUCTIONS PER FLOP

GCC achieved only 8% efficiency (ratio of observed performance) for our C implementation of Horner's method. Since Horner's method performs an equal number of multiply and add instructions, the programmer should use the floating-point accumulate instruction since it performs two floating-point operations in a single instruction.

The ARMv6 Floating Point (VFP) instruction set includes instructions for single and double precision, multiply-accumulate (and variations), divide, and square root. Most floating-point instructions are fully pipelined, meaning that they can be initiated in consecutive cycles, except for divide, square root, and instructions that perform double multiply. The VFP instruction set was replaced with the NEON instruction set in ARM7, but programs containing scalar VFP instructions will still work on ARM7 processors. Vector VFP instructions, covered later, are not supported by NEON. The VFP fmac Fd, Fn instruction is supported in both the ARM11 and Cortex processors.

Horner's method is based on adding each coefficient and multiplying the result with x:

```
temp = (temp + coeff) * x
```

The add-multiply operation is the reverse of fmac instruction. To reconcile this difference, the programmer must use a double buffer where the code alternates register Fd with the next coefficient, Fn with the current partial result, and Rd with x, as shown in the code below:

```
1 temp=coeff[0];
2 for (j=1;j<7;j+=2) {
3 temp2=coeff[j];
4 temp2=temp2+temp1*x;
5 temp1=coeff[j+1];
6 temp1=temp1+temp2*x;
7 }
8 d[i]=coeff[j+1];
9 d[i]=d[i]+temp2*x;
```

Lines 4, 6, and 9 map directly to the fmac instruction. Since the innermost loop has a fixed iteration count, unrolled and translate to inline assembly language as shown below:

