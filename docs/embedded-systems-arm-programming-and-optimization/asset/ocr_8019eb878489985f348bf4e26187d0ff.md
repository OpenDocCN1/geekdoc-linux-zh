-marm” switches), the compiler generates the following assembly code,
where the “in” variable is assigned to register r0:

| Compiler-Generated Assembly Code | Purpose |
|--- |--- |
| 1 mov r3, #0 | i=0 |
| 2 mov r2, r3 | out=0 |
| 3 .L3: | loop body begin |
| 4 rsb r1, r3, #31 | temp = 31 - i |
| 5 mov r1, r0, lsr r1 | temp2 = in << (31-i) |
| 6 or r2, r2, r1.asl r1 | out = out | (temp2 << i) |
| 7 add r3, r3, #1 | i++ |
| 8 cmp r3, #32 | compare i and 32 |
| 9 bne .L3 | if not equal, repeat |

The compiler-generated assembly code looks reasonable, but it is possible to
reduce the number of instructions in the loop body by taking advantage of
instruction features that cannot be described in the C language.

Specifically, recall that using shift operations, either as standalone ins-
tructions or as the flexible second operand, the last shifted out is stored in
t carry flag. Also, the rotate right and extend (RRX) operation allows the carry
flag to be shifted into a register. This allows us to use the carry flag to transfer
between the original and reversed registers while opposing shift
operations. An added benefit is that the program can terminate the loop when all
the bits have been shifted out of the source, eliminating the need for the
instruction that increments the i variable. This approach is shown below.

| Hand-Written Assembly Code | Purpose |
|--- |--- |
| 1 mov r2, #0 | out=0 |
| 2 lsls r0,r0.#1 | in = in <= 1, save bit that
was shifted out to C flag |
| 3 or r0,r0.#1 | set LSB of in to 1 to “mark” bit 32 |
