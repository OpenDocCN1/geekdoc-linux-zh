## 1.2 ARM TECHNOLOGY

ARM processor technology is controlled by ARM Holdings. ARM stands for “Advanced RISC Machine,” and RISC stands for “Reduced Instruction Set Computer.” RISC is a design philosophy in which the native language of the processor, or *instruction set*, is deliberately designed as a repertoire of extremely simple instructions, which requires a large number of simple instructions to execute a program. The advantage of this approach is—even if a program requires the execution of N times more simple instructions as compared to a processor having individual instructions that perform more work—simple instructions can be made to execute more than N times faster on average than complex instructions, which gives better performance overall.

RISC instructions are generally strictly divided into three main types: *arithmetic instructions, memory instructions,* and *control instructions*. Arithmetic instructions are the only types that perform any mathematical computations, while memory and control instructions are necessary overheads required to exchange data with an external memory and implement data dependent behaviors. Memory and control instructions on average substantially more than arithmetic instructions. Memory instructions, in particular, are generally *10–20× slower* than arithmetic instructions, although this depends on the program’s *memory access pattern* and the performance of the processor’s *memory hierarchy.*

## 1.3 BRIEF HISTORY OF ARM

The ARM instruction set architecture was originally developed in the 1980s by the British company Acorn Computers for their ARM1, ARM2, and ARM3 CPUs. These CPUs were intended to use as desktop computer CPUs, but after unsuccessfully competing against the Intel x86 and Motorola 68,000 CPUs of the time, ARM changed their business model from selling CPUs to selling the rights to use its processor or instruction set architecture. Their first major customer was Apple, who used an ARM processor for Newton PDA.

Today, ARM processors are sold as a reusable macrocell, which is a made that is used as a module of a system-on-chip. This ARM macrocell can be inserted into an existing design among other macrocells to form a customized, heterogeneous system-on-chip. Alternatively, one of the ARM instruction set architectures can be licensed and its implementation designed from scratch by the licensee. In either case, the widespread use of a consistent instruction set architecture allows programmers to leverage mature front-end development tools such as compilers, debuggers, and code libraries. There are several versions of both ARM instruction set architecture and the macrocell, but none of them are capable of delivering the rich multimedia features that customers have come to expect, so they are almost always combined with specialized coprocessors to perform most of the multimedia algorithms on behalf of the CPUs.

The ARM instruction set architecture is constantly evolving. After version 6 of the ARM ISA (ARMv6), the ARM ISA forked into three different versions, each optimized for a specific use. Currently, there are three ISAs optimized for microcontrollers (ARMv6-M, ARMv7-M, and ARMv7EM), optimized for real-time applications (ARMv7-R), and two optimized for general-purpose applications (ARMv7-A and ARMv8-A).

This book focuses on the ARMv6 and ARMv7 architectures. The ARMv6 is used in the ARM11 processor in the Raspberry Pi while the ARMv7 is currently used in most embedded devices of the smartphone and tablet variety. ARMv6 and ARMv7 are very similar, with the most significant difference being the addition of the NEON instructions in ARMv7. An overview of NEON instructions appears later in this chapter.

The ARMv8 architecture was introduced in 2013 and includes several fundamental differences to the v6 and v7. These differences include changes to the structure of the register files, the addition and deletion of significant instructions, and the dropping of the conditional execution field.

## 1.4 ARM PROGRAMMING

ARM processors can be programmed using a variety of high-level programming languages. Some ARM processors can even natively execute Java bytecode. Even so, since this textbook is primarily concerned with the ARM architecture, we will focus on assembly language and the way high-level code is compiled into ARM machine code.

In the early days of embedded systems, it was common to write entire programs in assembly language to save memory and processing power. However, modern compilers are highly sophisticated and can often generate code that is as good or better than hand-written assembly. Today, assembly language is still used for performance-critical sections, for interacting directly with hardware, and for writing low-level code like bootloaders and operating system kernels. Understanding assembly language is essential for any embedded developer because it allows them to see exactly what the processor is doing, which can be invaluable in debugging and optimizing code. In the case of ARM, the assembly language is relatively regular and clean compared to other architectures.

## 1.5 ARM ARCHITECTURE

ARM is a load-store architecture. This means that the programmer explicitly load (read) input data from memory into registers before it can be processed. Likewise, the programmer must explicitly store data to memory after it has been processed. Arithmetic instructions use the contents of registers as both their inputs and results. Registers can also be used to store temporary or intermediate results, such as loop counters or sub-expression values. The programmer (or compiler using high-level language) has control of the state of the registers. For example, when adding two values, the programmer must decide which register to temporarily assign each value and the computed sum. Registers can be reused when their contents are no longer needed.

### 1.5.1 ARM general purpose registers

ARM is a three-address architecture, meaning that a single instruction can reference three register addresses. For example, an arithmetic instruction such as “add” can specify two registers from which to read the input values and one register to store the calculated sum. When using assembler, the destination register is listed first.

There are 16 user-accessible integer registers named r0 through r15. Programs that are written entirely in assembly language can freely use any of the registers without interference from the hardware, except for special cases:

- the value of the register r14, the link register (also called lr or LR), is updated by the hardware when executing a branch-and-link instruction
- the value of register r15, the program counter (also called pc or PC), is maintained by the hardware and used to control program flow.

When writing assembly language routine—especially one that is embedded or called from C code—the programmer should be careful when using registers that have special meaning, as defined under the Procedure Call Standard (APCS). Caution is needed because these registers may be arbitrarily changed by code generated by the compiler or code written by other programmers.

These registers are comprised of the following:

- Registers r0 and r1 are used for function return values. Unlike the MIPS instruction set, register r0 is not “wired” to contain a zero value.
- Registers r0 through r3 (also called a1-a4, for argument registers) are used for passing arguments to functions. The programmer can freely use these registers as “scratch registers” but should be aware that their state may not be preserved across function calls.
