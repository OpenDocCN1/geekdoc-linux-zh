## 5.5 OpenCL Implementation of Horner's Method: Device Code

Begin with the kernel parameters, which must match the corresponding parameters in the host code:

``````c
#define N 1024*1024
#define VS 4
#define WGS 256
#define NWG N/(4*VS*WGS)
```

The top-level kernel function must have the "kernel" prefix, its name must match the one specified in clCreateKernel() call, and its arguments must match those specified in clSetKernelArg() calls:

```c
kernel void horner(global float *x, global float *d, global float *coeff) {
```

The kernel requires two local variables to hold intermediate values. By default, local variables are private and allocated in registers. The first, temp, holds each coefficient and partial sums when evaluating the polynomial. The other, xtemp, holds the input value x.

Both these variables must match the vector size of the kernel. Thus, these variables are declared explicitly in five versions of the kernel, corresponding to vector size 1, 2, 4, 8, and 16:

```c
#if VS == 1
float temp,xtemp;
#elif VS == 2
float2 temp,xtemp;
#elif VS == 4
float4 temp,xtemp;
#elif VS == 8
float8 temp,xtemp;
#elif VS == 16
float16 temp,xtemp;
#endif
```

Using preprocessor directives it is possible to avoid having to maintain one version of kernel code for each vector size. Next, the kernel needs to declare integers for both the loop iterator and start and end indices which the loop will use. Note that these variables default to the "private" OpenCL storage class. Since the kernel will operate over vectors of size VS, all vector load and store operations must assume an element size of 4×VS. For example, for VS=4, the kernel will operate over 16-byte values, so all indexing operations must be divided by this value.

Declare and initialize these integers as shown below:

```c
int i,
start = get_global_id(0) * N/(4*NWG*WGS*VS),
end = (get_global_id(0)+1) * N/(4*NWG*WGS*VS);
```

The main loop, which will iterate to N/(4×NWG× WGS× VS) times, begins:

```c
for (i=start;i<end; i++) {
```

The loop body begins by loading the element(s) of x into xtemp. OpenCL requires the use of special load and store intrinsics for vectors, so use pre-processor commands to differentiate the behavior for a given vector size:

```c
#if VS == 1
xtemp = x[i];
#elif VS == 2
xtemp = load2(i,x);
#elif VS == 4
xtemp = load4(i,x);
#elif VS == 8
xtemp = load8(i,x);
#elif VS == 16
xtemp = load16(i,x);
#endif
```

The main computational portion of the loop body can be written in a way that is generalized for any vector size. The code begins by loading VS copies of the first coefficient into temp:

```c
temp = coeff[0];
```

The OpenCL mad(a,b,c) intrinsic is compatible with vector types and performs the operation a×b+c. This intrinsic can multiply the previous sum—initially the coefficient—by x, add the next coefficient to the sum, and store the result back to temp. Unroll this “loop” to avoid the need for an inner loop:

```c
temp = mad(temp,xtemp,coeff[1]);
temp = mad(temp,xtemp,coeff[2]);
temp = mad(temp,xtemp,coeff[3]);
temp = mad(temp,xtemp,coeff[4]);
temp = mad(temp,xtemp,coeff[5]);
temp = mad(temp,xtemp,coeff[7]);
```

The kernel must store the final value of temp back to the d-array. This line depends on the vector size, so as before preprocess to differentiate the code's behavior depending on the value of VS:

```c
#if VS == 1
d[i] = temp;
#elif VS == 2
vstore2(temp,i,d);
#elif VS == 4
vstore4(temp,i,d);
#elif VS == 8
vstore8(temp,i,d);
#elif VS == 16
vstore16(temp,i,d);
#endif

}
```
