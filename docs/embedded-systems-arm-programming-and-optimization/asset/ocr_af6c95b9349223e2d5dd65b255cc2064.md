Table C.1 OpenCL buffer types, from the perspective of the host and kernel

| Global | Constant | Local | Private |
| --- | --- | --- | --- |
| Host | Dynamic allocation, read/write access | Dynamic allocation, read/write access | Dynamic allocation, no access | No allocation, no access |
| Kernel | No allocation, read/write access | Static allocation, read-only access | Static allocation, read/write access | Static allocation, read/write access |

All function local variables default to private memory, and are usually reserved for scalars such as loop iterators and temporaries for index calculations.

Local memory is typically used as a replacement for cache for devices that lacks caches. As such, kernels often contain a loop whose body begins by copying a block of input data into a small array in local memory, process it, and then write it to global memory.

Table C.1 lists the four types of memories in which buffers (arrays) can be allocated in the OpenCL device architecture. Each type of memory has different allocation and access restrictions on the host and device.

# C.2.1 Global memory

Global memory can only be allocated on the host using the `clCreateBuffer()` function. The host sends a pointer to each global buffer to the kernel through the kernel arguments using the `clSetKernelArg()` function.

Global buffers are used to send input data to the kernel (in which the host writes data using `clEnqueueWriteBuffer()` and to retrieve output from the kernel (in which the kernel reads it using `clEnqueueReadBuffer()`).

Since global buffers are normally allocated in off-chip memory, it generally has the highest access time.

# C.2.2 Constant memory

Constant memory is allocated on the host and its pointers are sent to the kernel the same way as with global memory. To define a buffer as being allocated in constant memory, “global const” or “constant” prefix must precede the corresponding kernel arguments.
