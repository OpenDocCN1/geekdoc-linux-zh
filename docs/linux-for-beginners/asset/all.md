## 1.1 What is an Operating System? 

An operating system (OS) is a program that manages all other system programs on the computer after initially installed on a computer with a boot program. App applications use the application to make service requests using a defined application interface (API). Users can also communicate directly with the operating system using a user interface, such as a land-line interface (CLI) or graphical UI (GUI).

### Why use an Operating System?

The operating system brings powerful benefits to computer software and software development. Outside of the application, the entire application will need to enter its UI, as well as the extensive code needed to manage all low-level computer operations, such as disk storage, network connections, and more. Considering the amount of hardware available, this will reduce all applications' size and make software upgrades ineffective.

Instead, most common tasks, such as sending a network package or displaying the text on some standard output devices, such as a monitor, can be sent to system software that acts as a link between apps and hardware. System software provides a consistent and repetitive way for apps to work with hardware without apps needing to know any hardware details.

As long as each application accesses resources and services in the same way, that application software - the app - can work on almost any number of applications. This greatly reduces the time and coding needed to develop and debug the application while ensuring that users can control, configure, and manage system hardware using a standard and understandable interface.

Once you install an operating system, this relies on a large device driver library to make OS services go to a specific hardware location. Therefore, the whole application can make a normal call on the end device, but the Operating System receives that call and uses the corresponding driver to translate the call into actions (commands) required for the basic hardware on that particular computer. Today, the app provides a comprehensive platform that identifies, organizes, and manages a range of computer hardware, including memory devices; processors and memory management; chipsets; storage; communication; port communications, such as High-Definition Multimedia Interface (HDMI), Video Graphics Array (VGA), and Universal Serial Bus (USB); and sub-system areas, such as the Peripheral Component Interconnect Express (PCIe).

### Operating System Functions

The operating system provides three key capabilities: Provides UI with CLI or GUI; presents and manages the application; and identifies and displays hardware resources for those applications - usually, with a default API.

### User Identifier (UI)

Every operating system requires a UI, which enables users and administrators to interact with the OS so that they can set up, configure, and troubleshoot the operating system and its hardware below. There are two main types of UI available: CLI and GUI.

The CLI mode window, or terminal mode, provides a text-based display where users simply rely on the traditional keyboards to enter specific commands, parameters, and issues related to specific functions. The Graphical User Interface, or desktop, provides a visual interface based on icons and symbols where users rely on actions acquired by human interface devices, such as touchpads, touch screens, and mouse devices.

The GUI is widely used by unfamiliar or end-users who have a great desire to create applications and files, such as double-clicking a file icon to open a file in its default application. CLI remains popular among leading users and system administrators who have to handle a series of grammatical and repetitive commands, such as creating and documenting to set up new computers (PCs) for employees.

### Application Management

The app manages the launch and management of the entire app. This often supports multiple behaviors, including processing multiple processes, or threads, so that different tasks can be shared during existing processors; manage software-based interference to get the processor's immediate attention, ensuring that there is sufficient memory to process the system and its corresponding data without interrupting other processes; make error management that can kindly remove system processes; and performing memory management without interfering with other applications or OS.

The operating system can support APIs that allow applications to use OS and hardware functions without the need to know anything about a low-level OS or hardware status. For example, the Windows API may allow an application to receive input from a keyboard or mouse; create GUI objects, such as windows dialog and buttons; read and write files to a storage device; and more. Applications are always designed to use the application where the program intends to run.

In addition, the operating system can perform the following services for applications:

• In a multitasking application, where multiple programs may run simultaneously, the OS determines which programs should run in sequence and how long they should be allowed in each application before giving another program a chance.

• Handles the input and output (I/O) to and from attached hardware devices, such as hard disks, printers, and dial ports.

• Sends messages to each app or to your partner - or to the system operator - about the operating system and any errors that may occur.

• It can delegate responsibility for the management of bulk operations - for example, printing - so that the implementation process is free of this function.

• On computers that can provide the same processing, a working system can manage how a system is divided to run on more than one processor at a time.

All major computer systems (hardware and software) require, and sometimes include, operating systems, and applications must be designed with a variety of features to meet the specific needs of different form elements.

### The Device-Management

The operating system is responsible for identifying, configuring, and giving applications normal access to computer hardware devices. As the OS detects and identifies the hardware, the OS will install compatible drivers of the device that enable the Operating System and applications running on the OS to operate devices without any specific hardware or device knowledge.

The operating system is responsible for identifying the correct printer and installing the appropriate printer drivers so that the system only needs to make calls to the printer without using codes or instructions specific to that printer - that is the function of the application. The situation is the same with other devices, such as USB ports; social networking sites; graphical devices, such as graphics processing units (GPUs); chipsets on motherboard; and storage devices, such as Serial-Attached SCSI (SAS) disk adapters and disks formatted with the appropriate file system.

The OS identifies and prepares effective and understandable service devices and typically records them in a standard format, such as the Windows Registry. Device manufacturers occasionally pair and update drivers, and the OS must update them to ensure maximum security and device performance; when devices are replaced, the OS re-installs and prepares new drivers.

### Operating System Types and Examples

While the app's basic roles are ubiquitous, there are many applications that work for a variety of hardware and user needs.

### • Standard Operating System

A standard-purpose OS represents a large number of applications intended to use a wide range of applications in a wide selection of hardware, enabling the user to use one or more applications or functions simultaneously. A standard-purpose OS can be installed on multiple desktops and laptop models and run applications from accounting systems to databases in web browsers to games. Operating systems typically focus on process (cable) and hardware management to ensure that applications can share reliably with the range of existing computers.

Typical desktop applications include the following:

• Windows is a Microsoft operating system, which is standard for home and business computers. Launched in 1985, the GUI-based OS has been released on several models since then. The easy-to-use Windows 95 was responsible for the rapid development of the personal computer.

• Mac OS is an operating system for Apple Macintosh for PCs and desktops.

• UNIX is  ​​a multi-purpose app designed for flexibility and flexibility. Developed in the early 1970's, UNIX was one of the first applications to be written in the C language.

• Linux is a Clone of Unix operating system designed to give PC users a free or low-cost alternative. Linux has a reputation for being an efficient and fast operating system.

### Mobile OS

The Mobile OS' are designed to accommodate the different needs of mobile computing devices and communication devices, such as smartphones and tablets. Mobile devices typically offer limited computer resources compared to traditional PCs, and the OS must be backed up in size and complexity to reduce its resource usage while ensuring the adequate resources for at least one or more applications running on that device. Mobile operating systems tend to emphasize efficiency, user responsiveness, and greater attention to data management functions, such as the supporting media streaming. Now, Apple iOS and Google Android are examples of mobile apps.

### Embedded OS

Not all computer devices are standard. Dozens of dedicated devices - including home-based digital assistants, automated reporting machines (ATMs), aircraft systems, sales terminals (POS), and Internet of Things (IoT) devices - including computers in need of an application. The big difference is that the compatible computing device does one big thing, so the OS is very fragile and dedicated to both performance and durability. The OS must be fast, uncluttered, and handle all bugs kindly in order to continue working in all conditions. In most cases, the OS is delivered to a chip installed on the basic device. If a medical device is to be used in a patient's life support system, for example, will use an embedded OS that must operate reliably to keep the patient alive. Relating to this example, Embedded Linux is one example of an embedded Operating System.

### Network OS

Network operating system (NOS) is another special OS that aims to facilitate communication between devices running on a local area network (LAN). The NOS provides the communication stack needed to understand network agreements in order to form, exchange, and decompose network packets. Today, the concept of a special NOS no longer works because some types of OS are more sensitive to network connectivity. Windows 10 and Windows Server 2019, for example, incorporate complete communication capabilities. The NOS concept is still used by other communication devices, such as routers, switches, and fire extinguishers, and manufacturers can use related NOSes, including Cisco Internetwork Operating System (IOS), RouterOS, and ZyNOS.

### Real-Time OS

When a computer device must interact with the real world within continuous and recurring time constraints, the device maker may choose to use a real-time application (RTOS). For example, an industrial control system can regulate the operation of a fertile factory or power station. Such a center would produce signals from multiple sensors and send signals to use valves, actuators, motors, and countless other devices. In these cases, the industrial control system must respond quickly and speculatively when it changes real-world conditions; otherwise, disaster could strike. RTOS should work without billing, processing latencies, and other delays, which are perfectly acceptable for some types of applications. Two examples of RTOS include FreeRTOS and VxWorks.

The differences between the app types are incomplete, and some operating systems may share others' features. For example, programs that run for a common purpose often incorporate the network capabilities found in a traditional NOS. Similarly, embedded applications often incorporate RTOS features, while the mobile application can still run multiple applications simultaneously like other standard operating systems.

### UNIX OS

In the late 1960s, a young AT&T Bell Labs engineer Kenneth (Ken) Thompson, worked on a Multics program project. Multics (Multiplexing Information and Computer Services) was the GE-645 mainframe testing system, developed in 1960 by the MIT, Bell Labs, and General Electric. It introduced many new things, but there were many problems, and in the late 1960's, Bell Labs, frustrated with progress and difficulties, withdrew from the project. Taking the help from some of his friends named as Dennis Ritchie, Douglas McIlroy, and Joe Ossanna, so Thompson decided to try some of the Multics' ideas and re-invent them on a much smaller scale. So in 1969 came the idea that Unix was now everywhere.

While Ken Thompson was still able to access the Multics environment, he wrote a new file simulation and a pairing program on it. The group later continued his work on blackboards and took notes. And in 1969, Thompson produced a very interesting game, Space Travel, which was first written on Multics, then translated into Fortran's GECOS, and finally with the much-used PDP-7 at Bell Labs. The same PDP-7 then decided to use it for the first UNIX launch. In this PDP-7 and using its conference language, a team of investigators (initially without financial assistance from the Bell Labs) owned by Thompson and Ritchie, developed a sequence file system, computer and device process concepts, command-line translator, and other small applications.

The name Unics was coined in middle 1970s by team member Brian Kernighan, who played on behalf of Multics. Unics (uncomplicated information and computing system) can end up supporting multiple users simultaneously, and overtime is reduced to Unix.

Structurally, the PDP-7 Unix file system was very similar to the current one; for example, it had:

1.  List of i: a specific list of each node that describes the file. The node contained less than it currently does, but the key details were the same: file protection mode, its type and size, and a list of physical blocks containing the content.
2.  Brochures: a special file type is containing a sequence of words and a related number i.
3.  Special files are describing devices. Device specifications were not explicitly contained in the node but were instead encoded in a code: certain I numbers correspond to certain files or folders.

In the late 1900s Thompson and Ritchie wanted to use Unix on a machine much larger than PDP-7, and they sold out the promise to add Unix text processing power to another financial aid from Bell, encoding the PDP-11/20 machine code. So for the first time in 1970, the active Unix system was officially launched and implemented in PDP-11/20\. Added a text developing program called roff and text editor. All three are written in the PDP-11/20 conference language. Bell Labs used this first "text processing" program, developed by Unix, Roff, and the editor, in patent applications' text processing. Roff soon turned into a troff, the first electronic publishing system with full editing capabilities.

In 1972, Unix was rewritten in the C-programming language, in contrast to the common perception at the time that "nothing is complex as an app, which had to deal with critical periodic events, had to be written only in assembly language" (although Unix was not the first OS, written in the high-level language, has been the Burroughs B5000 since 1961). Language C was developed by Ritchie as an improved version of B language, developed by Thompson as a BCPL translation from Martin Richards. The migration of assembly language to higher C language has resulted in portable software, requiring only a small amount of machine-based code to be replaced when Unix is  ​​installed on other computer platforms.

AT&T has made Unix available to universities and commercial firms, as well as to the United States government, under license. Licenses include all source code, including machine-based parts of the canister, which were written with the PDP-11 assembly code. Copies of the specified Unix kernel sources were widely distributed in the late 1970's in the form of a hard copy, which led to the widespread use of Unix as an educational model. At one point, ARPA (Advanced Research Projects Agency) adopted Unix as the Arpanet (pre-Internet) community's official language.

In the late 1970s and early 1980s, Unix's influence on academic circles led to Unix's widespread acceptance (especially the BSD version, from the University of California, Berkeley) with many commercial initiatives, for example, Solaris, HP-UX, and AIX. Today, in addition to Unix-certified programs like the ones already mentioned, Unix-powered programs such as Linux and BSD generations (FreeBSD, NetBSD, and OpenBSD) are often encountered.

## 5.3 User Change and Activation Instructions like Alternative

The su (short for substitute or switch user) utility allows you to use commands with another user's rights, automatically the root user.

Using the su is an easy way to switch to an administrative account for the current login session. This is especially helpful when the root user is not allowed to enter the system using ssh or using the GUI display manager.

### How to use su Command $su

The standard syntax for the following command is as follows:

$ su [OPTIONS] [USER [CONFLICT ...]]

Copy

$ su

You will be notified that you entered the root password, and once confirmed the user who temporarily uses the command becomes root.

who I am
