
## 通信方法

无连接型通信，正如你可能推测的那样，不需要在开始通信前建立连接。这就像一个拿着扩音器的人对人群中的特定目标大喊大叫。每次新的呼喊，发送者都可以将信息指向另一个人，而无需事先达成任何协议。

类似地，在创建无连接套接字后，你将能够向任何愿意接收消息的套接字发送消息。这里没有连接建立过程，且每条消息都可以发送给不同的接收套接字。

### 理解其优势

与连接型协议相比，无连接型通信具有某些优势。其中一些包括以下几点：

- **更简单**——无需建立连接。
- **灵活**——可以在每次发送消息的操作中向不同的接收者发送消息。
- **高效**——不需要建立或断开连接，而连接建立或断开可能会向网络增加大量开销数据包。
- **快速**——由于没有连接建立或断开过程，因此只发送消息本身。
- **广播能力**——能够将一条消息发送给多个接收者。

无连接型协议许多优势都与效率和速度有关。建立连接需要两个端点之间交换若干数据包后才能进行数据交换。已建立通信信道的断开也需要交换额外的数据包。同样，这会导致额外的开销和时间消耗。

无连接协议的另一个优势是其广播能力。可以将一条消息指向多个接收者。这非常高效地利用了网络带宽。

在本章中，你将学习UDP协议（用户数据报协议），它是一种无连接型协议。该协议享有刚才提到的所有优势。

### 理解无连接通信的劣势

尽管无连接型协议具有诸多优势，你可能会疑惑为什么它们并非总是被使用。与其他大多数事物一样，无连接通信也有其缺点。

UDP协议是一种非常简单的传输层协议，如前所述，它是无连接的。在UDP协议的背景下，存在以下缺点：

- 该协议不可靠。
- 没有多数据报的顺序控制。
- 存在消息大小限制。

对于大多数应用而言，可靠性问题是严重的限制因素。UDP数据报可以由你的应用程序写入网络，但没有保证预期的接收者最终会收到它。消息可能会乱码，以至于同一网络上的接收者无法接收。或者，由于网络路径中的众多路由器之一未能无误地接收到消息，导致消息丢失。当接收到有错误的数据包时，UDP数据包会被静默丢弃并永久丢失。

**注意**

数据报只是通过网络发送和接收的数据单元。它可被比作电报，因为它代表一条完整的消息。

其他问题也可能导致UDP数据包丢失。如果接收主机或路由器无法分配足够的缓冲区空间来容纳UDP数据包，它将被静默丢弃。因此，如果你的UDP数据包必须行进更长的距离，它沿途被丢弃的可能性就更大。

在决定是否为你的应用程序使用UDP之前，必须考虑另一个问题。如果你连续快速发送两个或更多数据报到目的地，有些数据报可能会出现乱序到达的情况。UDP协议使用互联网协议（IP）来传递最终的数据报。IP数据包可能在每次传输中被以不同方式路由，且路由会根据当前网络状况而变化。这常常导致一些数据包在之前的数据包到达之前就先到达了目的地。底线是，UDP数据包可能会乱序到达。

最后，还有数据报大小的问题。UDP数据报的理论最大大小略小于64KB。然而，许多UNIX主机仅支持接近32KB的最大值。其他UNIX内核内置限制进一步限制了大小。有时低至8KB。最后，接收套接字程序会将其限制为接收缓冲区的最大大小。因此，有些程序将自身限制为使用512字节或更小的UDP消息。

如果发送大型UDP数据包，它将被分割成几个较小的IP片段，并在接收端重新组装。重组过程需要分配缓冲区以容纳收到的片段。这仅在指定的超时周期内进行，直到整个数据包可以重新组装。缓冲区的竞争可能导致重组被放弃，结果就是你的UDP数据包被静默丢弃。UDP数据报必须经受许多风险才能成功到达其目的地。

对于一些应用程序，这些注意事项会引导你转向更可靠的连接型协议，如TCP/IP。对于其他应用程序，这些可能不是严重的限制。只有你自己能决定是否适合在你的应用程序中使用UDP。

## 执行数据报的输入/输出

在第1章“介绍套接字”中所示的示例程序清单1.3中，你看到了在从套接字读取和写入时使用read(2)和write(2)函数。当时没有指出的是，所显示的socketpair(2)函数调用使用连接型协议创建了一对套接字。因此，可以使用熟悉的read(2)和write(2)函数在这些套接字上执行I/O。

然而，在发送和接收数据报时，需要另一对不同的函数。这是因为每个被发送的消息潜在地发送给不同的目标地址。用于发送数据报的函数必须允许你指定预期接收者的地址。同样地，当你接收到数据报时，你需要知道它来自谁。这个新函数必须提供一种便捷的方式来确定发送者的地址。

## 介绍sendto(2)函数

sendto(2)函数允许你写入数据报并同时指定接收者的目标地址。该函数的原型如下：

```c
#include <sys/types.h>
#include <sys/socket.h>

int sendto(int s,
           const void *msg,
           int len,
           unsigned flags,
           const struct sockaddr *to,
           int tolen);
```

不要被该函数的参数数量吓倒。描述之后，它们很容易理解：

1. 第一个参数s是套接字号。这个值来自socket(2)函数。
2. 参数msg是指向包含你希望发送的数据报消息的缓冲区的指针。
3. 参数len是以字节为单位的数据报长度，该数据报从msg给定的指针开始。
4. flags参数允许你指定一些选项位。在许多情况下，你只需提供零值。
5. 参数to是指向你已建立的通用套接字地址的指针。这是数据报接收者的地址。
6. 参数tolen是地址参数to的长度。

sendto(2)函数成功返回时，其返回值是发送的字节数（请注意，这并不保证远程端已接收）。当发生错误时，函数返回-1，并可以查阅errno的值以了解原因。

倒数第二个函数参数允许你标识数据报必须发送到的位置。参数to必须指向有效的套接字地址，且参数tolen应包含地址的正确长度。在前几章中，你已成为构建地址的专家，因此在这里你应该觉得得心应手。

表6.1列出了flags参数可以具有的值，不过大多数时候你只需提供零值即可。

### 表 6.1: sendto(2)函数的flags值

| 标志 | 十六进制 | 含义 |
| :--- | :--- | :--- |
| 0 | 0x0000 | 正常——无特殊选项 |
| MSG_OOB | 0x0001 | 处理带外数据 |
| MSG_DONTROUTE | 0x0004 | 绕过路由；使用直接接口 |
| MSG_DONTWAIT | 0x0040 | 不阻塞；等待写入 |
| MSG_NOSIGNAL | 0x4000 | 当另一端断开连接时不引发SIGPIPE |
