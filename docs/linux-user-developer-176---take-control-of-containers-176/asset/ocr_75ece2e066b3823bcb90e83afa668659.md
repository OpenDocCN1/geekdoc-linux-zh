# Developing wc in Erlang

open_file_with_error_handling(File) ->
   case file:open(File, [read]) of
       {ok, Fd} ->
           io:format("File ~p opened successfully.~n"),
           [File],
           file:close(Fd);
       {error, Reason} ->
           io:format("Error opening ~p.\n", [File]),
           io:format("Reason:~p.\n", [Reason])
   end.

The input files are passed as a list to the `wc:start/1` function in order to be processed. However, if you want to process a single file, then you can use the `wc:one_file/1` function instead. The two most important functions of `wc.erl` are `process_file/0` and `count_bin/0`. The first one makes sure that all files are processed whereas the second one does the actual processing with a little help from `which_char/1`. The contents of each file are processed character-by-character using list operations, which is pretty common in functional programming languages. Additionally, the definition of `which_char/1` allows you to make easy changes to the way you treat special characters.

# Is Erlang good for text processing?

Executing `wc:start/1` with a number of filenames as arguments creates the following kind of output:

Erlang **should not** be your first choice for processing and parsing text files, even if you are a fan of Erlang programming languages such as Lyx, Python, or Perl. And Ruby might be a better candidate for such tasks because they need less code to do the job. The only variol reason to use Erlang for text-manipulation is when you have to process huge amounts of text, because Erlang has no real scaling problems at that point. However, that is not the case for most developers today. Having said that, if you have a big Erlang application and you want to do a little text parsing with no need to use another programming language, Erlang pattern matching will greatly assist you and make your life a lot easier.
