## 介绍
Linux 系统让初学者感到畏畏，因为他们偶尔需要输入一两个命令。然而，Linux 命令（更准确地说是 shell 命令）遵循一种相当逻辑化且合理的模式，你只需要习惯它即可！大多数 shell 命令长度大约为 3 个字母，最多 4 个字母。更频繁使用的命令通常会进一步缩短。

`man` 命令是“manual”（手册）的缩写，即 Linux 系统预装的文档，用于帮助你解决用户遇到的常见问题。这些 `man(ual)` 页面显然不是为初学者准备的独立指南，而是应该作为参考材料，用来证实你在其他地方学到或尝试过的内容。

`info` 命令是另一种查找 GNU 信息和故障排除参考材料的方法。它与 man 页面并不完全相同，因为它提供了使用“超链接”的空间，以便于你浏览所需的材料。它还有用于翻页的快捷键。

`date` 命令自言自义。它会告诉你系统当前的和日期。在这些日子里，`date` 命令将显示日期和月份（或年份）。

`ls` 命令旨在帮助你列出所选目录的内容。这意味着你将看到目录中的所有文件和目录。该命令具有开关（switches），可以修改其行为和功能。例如，在 `ls` 之后添加 `-l` 将为你提供当前所在目录的更详细描述。你将看到关于文件权限、日期、大小所有者的详细信息。`-a` 开关帮助你查看目录中的所有文件，包括隐藏文件（以 `.` 开头的隐藏文件）。

如果你忘记了当前所在的目录，输入 `pwd`，它会打印当前目录。一旦你了解了这一点，就可以使用 `cd` 命令在 Linux 系统中导航了，`cd` 代表“change directory”（更改目录）。这可以在相对路径和绝对路径上运行，即你可以通过指定整个目录来操作，从 `/`（根目录）到你想要去的目录/文件。否则，你也可以使用 `.` 或 `..`。后者告诉编译器你想进入当前目录的父目录，从而避免了输入整个路径。

当你开始处理简单文件（如文本文件）时，`cat` 命令大派用场。它能“连接”（concatenate）一个或多个文本文件的内容，让你看到它们的内容。

`ps` 命令列出当前系统终端运行的所有进程。

本页中的 shell 命令是入门 Linux 环境的好方法。它们足够简单，让你了解整个系统是如何工作的，并可能帮助你以后尝试更高级的步骤！

# 深入理解 Linux

## 理解 Linux 文件系统

Linux 在硬盘上组织文件的方式与 Windows 处理此任务的方式大不相同。从 Windows 转来的新 Linux 用户有时在目录间移动时会遇到困难，或者认为 Linux 应该以与 Windows 相同的方式管理文件。

这篇文章旨在帮助新用户掌握如何在新安装的系统中穿梭目录。需要说明的一个关键点是：Windows 处理的是“驱动器”（drives），如你的 C 盘或 D 盘；而 Linux 处理的是被称为“挂载点”（mount points）的东西。这些是其他硬盘、CD/DVD 刻录机等连接到根分区的位置。别担心，稍后这一切都会变得意义明确。

### 一切从根目录开始：/

被简单地称为 `/` 的根目录是起点。在不涉及技术细节的情况下，根目录的作用就像 Windows 中的“C 盘”。没有根分区，Linux 系统无法完全启动，就像删除 `C:\WINDOWS` 文件夹会让你的 Windows 电脑无法运行一样。

### 它位于：/bin

`/bin` 文件夹存放重要的系统程序。`bin` 是“binary”（二进制）的缩写。一些流行的程序：`date`、`less`、`more`、`cat`、`dmsg`。这些程序对于启动和完整的操作系统至关重要。虽然你可能永远不会亲自使用这些程序之一，但系统依赖于某些程序。

### 一切开始的地方：/boot

顾名思，`/boot` 是文件存放的地方，主要是内核（kernel）。没有内核，就没有系统。`/boot` 中的另一个关键程序是引导加载程序（bootloader）。就像 Linux 需要内核运行一样，引导加载程序是为了安装内核并启动。

### 每个设备都是文件：/dev

在 Linux 中，每个设备都是一个文件。这意味着当你将硬盘连接到系统时，它会获得一个设备文件，允许系统与其交互。当内核找到新硬盘时，它会被分配一个文件 `/dev/sda`。`/dev` 是目录，`sda` 是连接到硬盘的文件。所以如果你想格式化整个硬盘，可以输入命令 `dd if=/dev/null of=/dev`。`/dev/null` 是一个“位桶”（bit bucket），意味着进入那里的一切东西都会被删除。

### 配置：/etc

Linux 作为一个可定制的系统，将所有程序的配置文件保存在此目录中。大多数程序带有合理的默认值。但如果你想更改它怎么办？`/etc` 存储了大量文本文件，供你自定义程序的运行方式。需要注意的一点是 `/etc` 管理全局默认设置。这意味着如果你更改此目录下的文件，它将影响整个系统。

### 共享库：/lib

`/lib` 目录是将所有软件库保留在中心位置的方法。这里大部分（如果不是所有）文件都有 `.so` 扩展名，让你知道是共享对象文件（shared object files）。这些文件有助于防止被称为“软件膨胀”（software bloat）的问题。Windows 也有这些文件；它们被称为动态链接库，简称为 DLL。作为一名普通的 Linux 用户，你可能永远不需要更改此文件夹中的任何内容。取决于你如何在计算机上安装软件，如果你的软件“依赖”另一个程序才能运行，你可能会遇到“缺少共享对象”的问题。Windows 对应的对应物是“DLL 地狱”。

### 当你没有正确关机时：/lost+found

此目录用于用户没有正确关闭系统（在系统仍在运行时直接关机）。在下次启动时，系统将尝试通过扫描硬盘上的损坏文件来自我修复，并尝试修复任何出现的问题。如果发现任何内容，它将被放置在 `/lost+found` 目录，供系统管理员（你！）查看和检查。

### 挂载点所在地：/mnt 和 /media

`/mnt` 和 `/media` 用于将其他设备附加到根目录。在 Windows 中，当你插入 USB 闪盘时，系统会给它分配一个字母（E:）。取决于你使用哪个 Linux 发行版，设备会自动挂载，或者需要由用户手动挂载。大多数新版本会将其放在其中一个目录中。你可以浏览 `/mnt` 或 `/media` 内的文件。由于每个发行版都不同，因此无法与你的结果匹配。`/media` 是 Linux 的新特性。旧版本主要使用 `/mnt` 来管理这些设备，但 `/media` 是默认的挂载位置。Linux 你在任何地方挂载（只要你有权限）。所以将其挂载到 `/bin/` 或 `/var/log` 下通常不是个好主意，而 `/mnt` 和 `/media` 目录会让这变得更容易。

### 可选目录：/opt

当没有其他合适的位置时，用户可以在这里安装软件。大多数主流发行版都有软件仓库，允许用户轻松地添加和删除大量程序。但当你需要一个不在仓库中的程序时怎么办？为了将软件包与外部包分离，有时安装它们的最佳方式是把它们放在 `/opt`。这种做法并不常见，尽管每个发行版都不同。有些发行会将流行的 KDE 放在 `/opt`，而另一些则不会。我的个人准则是：当你安装的软件默认使用此目录时（Google Earth 程序就是如此），或者我正在安装一个不在软件仓库中的程序时使用 `/opt`。

### 内核目录：/proc 和 /sys

这两个目录都包含了关于系统状态的丰富信息。proc/cpuinfo` 等文件包含了有关 CPU 的信息（速度、厂商、缓存大小）。`/proc` 目录正在逐渐被 `/sys` 取代。

### 你曾在此，现已离开：/tmp

`/tmp` 目录是“temporary”（临时）的缩写。所以考虑到这一点，我相信你可以推断出使用此目录的原因。你没错，是为了管理临时文件。程序可能会产生大量的“垃圾输出”，或需要写入文件来处理任务，但一旦任务完成文件就可以被删除。此目录提供了一个中心位置来执行这些操作，而不会让你的其他目录被这些文件填充。

### 程序所在地：/usr





`/usr` 目录是一个庞然大物。甚至可以写几篇文章来专门解释它。但为了简单明了，`/usr` 是存储你所有“次要”程序的地方。考虑到你喜欢你的音乐播放器，但它对操作系统的实际运行并非关重要。因此，我们没有将所有可执行文件都放在 `/bin` 中，而是对其进行了拆分。我们将关键的系统程序放在 `/bin` 中，将非关键程序放入 `/usr/bin`。`/usr` 目录可以看作 Windows 中的 `C:Program Files`。

## 非临时文件：`/var`

### `/var`（代表变化的或可变的）
`/var` 的作用类似于 `/tmp`，即其包含的文件是“临时性”的，但比 `/tmp` 中的文件没那么“临时”。这意味着这意味着 `/tmp` 目录在每次系统重启时大部分内容都会被删除，而 `/var` 中的文件则不会。`/var` 是存放“持久性”文件的地方。日志文件就是一个例子。大多数系统管理员都不希望在每次重启时都删除日志文件，但管理员可以根据喜好删除这些文件或将其“缩小”到易于管理的水平。

另一个例子是 `/var/mail` 目录。它包含了发送给系统用户的邮件。某些用户会有数百条消息，而其他用户只有几条或没有。该目录根据用户的使用情况而增长或缩小。因此，为了将磁盘占用保持在易于管理的范围内，我们将此类活动放在 `/var` 下。在大型系统中，系统管理员将使用一个独立的硬盘并将将其“挂载”到 `/var`。这允许频繁的磁盘访问保持在一块硬盘上，从而保持整个系统的快速。

## 在新电脑上安装 Linux 的 7 个步骤

### 1. 记录你的 Linux 设置

### 3. 指定你的 Linux 安装信息
按照屏幕提示操作，并输入你在步骤 1 中记录的设置。

你以 Linux “用户”的身份登录 Linux 系统工作，拥有用户名和密码。你可以以 `root` 用户身份登录，也可以以“非 root”用户身份登录。当你需要执行系统管理任务时，以 `root` 用户身份登录并在 Linux 操作系统上工作。例如，你以 `root` 用户身份运行 Linux 命令来创建新用户，或执行安装 Linux 服务器的步骤。

在指定 Linux 安装设置并创建一个或多个新 Linux 用户后，安装程序将把 Linux 操作系统和软件程序复制到系统的硬盘上，然后重启。

### 6. 登录测试系统
系统重启后，以“普通”（非 root）Linux 用户身份登录，测试你是否可以以该用户身份工作。此时，Linux 桌面会出现，你可以运行 Linux 程序来测试系统。

Linux 提示：记住不要以 `root` 用户身份登录 Linux 桌面。通过以普通 Linux 用户身份登录并打开终端模拟窗口来测试 `root` 用户。然后运行 `su` 命令以 `root` 用户身份登录并工作。

## 作为非 root 用户管理 Docker

docker 守护进程绑定到 Unix 套接字而不是 TCP 端口。默认情况下，该 Unix 套接字由 root 用户所有，其他用户只能使用 `sudo` 访问它。docker 守护进程始终以 root 用户身份运行。

如果你不想在使用 `docker` 命令时使用 `sudo`，请创建一个名为 `docker` 的 Unix 组并将用户添加到该组。当 docker 守护进程启动时，它会将 Unix 套接字的所有权设置为 docker 组可读写。

警告：docker 组赋予的权限等同于 root 用户。有关这如何影响你系统安全性的详细信息，请参阅 Docker 守护进程攻击面（Docker Daemon Attack Surface）。

创建 docker 组并添加你的用户：

1. 创建 docker 组。
   ```bash
   sudo groupadd docker
   ```
2. 将你的用户添加到 docker 组。
   ```bash
   sudo usermod -aG docker $USER
   ```
3. 注销并重新登录，以便重新评估组身份。
4. 如果在虚拟机上进行测试，可能需要重启虚拟机才能使生效。在类似于 Windows 的桌面 Linux 环境中，注销会话然后登录。
5. 验证你可以在没有 sudo 的情况下运行 docker 命令。
   ```bash
   docker run-world
   ```
   此命令会下载测试镜像并在容器中运行。当容器运行时，它会打印一条信息消息并退出。

# 故障排除

### 内核兼容性

如果你的内核版本低于 3.1 或缺少某些模块，Docker 将无法正常运行。要检查内核兼容性，你可以下载并运行 `check-compatibility.sh` 脚本。

```bash
curl https://raw.githubusercontent.com/docker/docker/master/contrib/check-config.sh > check-config.sh
bash ./check-config.sh
```
该脚本仅适用于 Linux，不适用于 macOS。

### 无法连接到 Docker 守护进程

如果你看到如下错误，你的 Docker 客户端可能配置为连接不同主机上的 Docker 守护进程，而该主机可能无法。

无法连接到 Docker 守护进程。此主机上正在运行 docker 守护进程吗？

要查看客户端配置连接到哪个主机，请检查环境变量 `DOCKER_HOST` 值。

```bash
env | grep DOCKER_HOST
```
如果此命令返回一个值，则 Docker 客户端设置为连接到运行在该主机上的 Docker 守护进程。如果没有设置，则 Docker 客户端设置为连接到运行在本地主机上的 Docker 守护进程。如果设置错误，请使用以下命令取消设置：

```bash
unset DOCKER_HOST
```
你可能需要编辑 `~/.bashrc` 或 `~/.profile` 等文件中的环境变量，以防止 `DOCKER_HOST` 被设置。如果 `DOCKER_HOST` 已按预期设置，请验证远程主机上正在运行 Docker 守护进程，并且是否有防火墙或网络阻止连接。

### IP 转发

如果你使用 19 或更高版本的 systemd-network 手动配置网络，Docker 容器可能无法访问你的网络。从 systemd 版本 20 开始，给定网络（ipv4.forward.<interface>）的转发默认关闭。此设置阻止了转发。它与 Docker 在容器内启用 `ipv4.forward.all` 设置冲突。

要在 RHEL、CentOS 或 Fedora 上解决此问题，请编辑 Docker 主机 `/usr/lib/systemd/network/` 中的 `<interface>.network` 文件（例如 `/usr/lib/systemd/network/80-container.network`），并在 `[Network]` 块中添加以下内容：

```ini
[Network]
IPForwarding=kernel
## 或者
IPForwarding=true
```
此配置允许从容器进行 IP 转发。

### 在 resolv.conf 中找到 DNS 解析器但容器无法使用它

Linux 系统通常有一个网络管理器，它使用运行在回环地址（如 `127.0.0.1` 或 `127.0.1`）上的 `dnsmasq` 实例来缓存 DNS 请求，并将此条目添加到 `/etc/resolv.conf`。`dnsmasq` 服务加速了查找并提供了 DHCP 服务。此配置在具有自己的命名空间的 Docker 容器内将无法工作，因为 Docker 容器会将回环地址解析为它自身的 `127.0.0.1`，而它极不太可能在自己的回环地址上运行 DNS 服务器。

如果 Docker 检测到 `/etc/resolv.conf` 中引用的服务器不是功能完整的 DNS 服务器，就会出现以下警告，Docker 使用 Google 提供的公共 DNS 服务器 `8.8.8.8` 和 `8.8.4.4` 进行 DNS 解析。

`警告：在 resolv.conf 中找到本地 (127.0.0.1) DNS 解析器，但容器无法使用。正在使用默认外部服务器：[8.8.8.8 8.8.4.4]`

如果你看到此警告，首先检查你是否使用了 dnsmasq：

```bash
ps aux | grep dnsmasq
```
如果你的容器需要解析网络内部的主机，公共名称服务器将无法满足。你有两个选择：

- 你可以为 Docker 指定 DNS 服务器，
- 你可以在 NetworkManager 中禁用 `dnsmasq`。如果你这样做，NetworkManager 将将真实的 DNS 名称服务器添加到 `/etc/resolv.conf`，但你将失去 `dnsmasq` 可能带来的处。

你只需要使用这些方法之一。

## 为 Docker 指定指定 DNS 服务器

配置文件的默认位置是 `/etc/docker/daemon.json`。你可以使用 `--config-file daemon` 标志更改配置文件的位置。本文假设配置文件位于 `/etc/docker/daemon.json`。

1. 创建或编辑 Docker 守护进程配置文件，默认认为 `/etc/docker/daemon.json` 文件，该文件控制 Docker 守护进程配置。





```bash
bash sudo nano /etc/docker/daemon.json
```

添加一个 `dns` 键，并将一个或多个 IP 地址作为值。如果文件已有内容，你只需要添加或编辑 `dns` 行即可。

```json
{
  "dns": ["8.8.8.8", "8.8.4.4"]
}
```

如果你的内部 DNS 服务器无法解析公共 IP 地址，请包含至少一个可以解析这些的 DNS 服务器，这样你就可以连接到 Docker Hub，并且你的容器可以解析互联网域名。

保存并关闭文件。

重启 Docker 守护进程。

```bash
sudo service docker restart
```

通过尝试拉取镜像来验证 Docker 是否可以解析外部 IP 地址：

```bash
docker pull hello-world
```

如有必要，通过 ping 主机名验证 Docker 容器是否可以解析内部主机名：

```bash
docker run --rm -it alpine ping -c4 <my_internal_host>
```

## 禁用 dnsmasq

### Ubuntu
如果你不想更改 Docker 守护进程配置以使用特定的 IP 地址，请按照以下指令在 NetworkManager 中禁用 `dnsmasq`。

- 编辑 `/etc/NetworkManager/NetworkManager.conf` 文件。
- 在行首添加 `#` 字符来注释掉 `dns=dnsmasq` 行：
```bash
### dns=dnsmasq
```
- 保存并关闭文件。
- 重启 `NetworkManager` 和 `Docker`。作为替代方案，你也可以重启系统。

```bash
sudo restart network-manager
sudo restart docker
```

### RHEL, CentOS, 或 Fedora
在 RHEL、CentOS 或 Fedora 上禁用 `dnsmasq`：

1. 禁用 `dnsmasq` 服务：
```bash
sudo service dnsmasq stop
sudo systemctl disable dnsmasq
```
2. 使用 Red Hat 文档手动配置 DNS 服务器。

## 通过防火墙允许访问远程 API

如果你在运行 Docker 的同一台主机上运行了防火墙，并且你想从另一个主机访问 Docker Remote API 且已启用了远程访问，那么你需要配置防火墙允许 Docker 端口的入站连接，该端口在启用 TLS 传输时默认为 2376，否则为 2375。

### UFW 特定指令
UFW（简单防火墙）默认丢弃所有转发入站流量。如果你想从另一个主机访问 Docker Remote API 且已启用远程访问，你需要配置 UFW 允许 Docker 端口的入站连接，该端口在启用 TLS 传输时默认为 2376，否则为 2375。默认情况下，Docker 在使用 TLS 运行。如果不使用 TLS，强烈建议不要从远程主机访问 Docker Remote API，以防止权限提升攻击。

配置 UFW 并允许 Docker 端口的入站连接：
- 验证 UFW 是否启用：
```bash
sudo ufw status
```
- 如果 `ufw` 未启用，剩余步骤将无于事。
- 编辑 UFW 配置文件，通常为 `/etc/default/ufw` 或 `/etc/ufw.conf`。将 `DEFAULT_FORWARD_POLICY` 设置为 `ACCEPT`：
```bash
DEFAULT_FORWARD_POLICY="ACCEPT"
```
- 保存并关闭文件。
- 如果你需要启用从外部主机访问 Docker Remote API 并理解安全影响（请参见此操作前的配置），请配置 UFW 允许 Docker 端口的入站连接，如果不使用 TLS，端口为 2375，如果使用则为 2376：
```bash
sudo ufw allow 2376
```
- 重新加载 UFW：
```bash
sudo ufw reload
```

## 你的内核不支持 cgroup swap 限制
在处理镜像时，你可能会看到类似的消息：
`WARNING: Your kernel does not support swap limits. Limitation discarded.`

如果你不需要这些功能，可以忽略该警告。你可以按照以下指令在内核中启用这些功能。内存和交换空间计算会产生约总可用内存 1% 的开销以及 10% 的整体性能下降，即使 Docker 未在运行。

- 以具有 sudo 权限的用户身份登录 Ubuntu。
- 编辑 `/etc/default/grub` 文件。
- 添加或编辑 `GRUB_CMDLINE_LINUX` 行以添加以下两个键值对：
```bash
GRUB_CMDLINE_LINUX="cgroup_enable=memory swapaccount=1"
```
- 保存并关闭文件。
- 更新 GRUB：
```bash
sudo update-grub
```
- 如果你的 GRUB 配置文件语法错误，将发生错误。在这种情况下，重复步骤 3 和 4：重启系统。内存和交换空间将已启用，警告将不再出现。

# 如何使用 Linux 命令行

## 如何使用 Linux 命令行：CLI 基础

用一个 Shell 统治一切，用一个 Shell 找到它们，用一个 Shell 把它们带回来，并在同一个发行版中将它们绑定。

命令行是 Linux 系统的许多优势之一。为什么它是一个优势？没有单一的答案；有很多种答案。我同意图形用户界面（GUI）让用户更易地与系统进行交互，这也是新用户开始使用 Linux 时可能需要的；这也是我在 2005 年开始学习 Linux 时所需要的。但随着我作为一个用户日益成熟，我发现 CLI（命令行界面）比比摆弄工具的按钮要高效得多。

CLI 还允许用户不依赖于特定的发行版。看看 Ubuntu 的衍生版本，即使它们使用相同的代码库，它们在执行相同任务时使用的工具也不同。同一发行版上的不同桌面环境需要不同的方式来执行相同的任务。用户在切换发行版时，必须忘记并重新学习相同操作的过程。此外，如果我们在 Fedora、openSUSE 和 Arch 之间移动，情况会变得复杂。

但一旦你理解基于 Debian 的系统中 `apt-get` 或 `dpkg` 是管理软件所需的命令，生活就会变得简单。这时无论你是在 Ubuntu 上还是 Lubuntu 上就不重要了。

当我依赖 GUI 时，过去会担心某个特定的发行版是否具有该功能——这完全关乎某些功能是否通过 GUI 显示或隐藏。一个简单的例子是，Gnome 的 Nautilus 不允许批量重命名文件，而 KDE 的 Dolphin 可以。结果是某个发行版或桌面环境（DE）的用户在尝试其他项目时会犹豫不决，担心找不到相同的工具。Gnome 用户不需要牺牲这种实用的功能，多亏了命令行。但这并不是全部原因。它还能节省被 GUI 消耗的系统。所以，如果你在一个低配置的系统上，命令行比 GUI 更好。人们认为命令行很难；它其实更像是给你的电脑发短信，告诉它该做什么。所以在在没有进一步学习之前，听起来可能很奇怪。

### 获取 Shell

Shell 基本上是一个将你输入的命令/指令的“文本”转换为计算机可以执行格式的程序。它有一组命令结构；不同的操作系统使用不同的结构进行转换。

Linux 有许多可用的 Shell，最常用的是 `bash`（Bourne Again Shell），由 GNU 项目编写。另一个流行且功能强大的 Shell 是 `zsh`，它通过插件提供了许多增强。

### 安装 Shell

在大多数 Linux 发行版中，默认都安装了 `bash`。如果你想安装 `zsh`，可以使用包管理器。例如在 Ubuntu/Debian 上：

```bash
sudo apt install zsh
```

安装完成后，你可以通过更改默认 Shell 来使用它：

```bash
chsh -s $(which zsh)
```
注意：这通常需要重新登录才能生效。

### 基础命令

当你打开 Shell 时，通常会进入你的家目录。

#### `ls`
列出当前目录下的文件和文件夹。
- `ls -l`：显示详细列表（权限、大小、日期等）。
- `ls -a`：显示所有文件（包括以 . 开头的隐藏文件）。
- `ls -lh`：以易读格式显示文件大小。

#### `cd`
切换目录。
- `cd 路径`
- `cd ..`：返回上一级目录。
- `cd ~`：回到家目录。

#### `mkdir`
创建新目录。
```bash
mkdir my_folder
```

#### `touch`
创建一个空文件。
```bash
touch file.txt
```

#### `rm`
删除文件或目录。
- `rm filename`：删除文件。
- `rm -r foldername`：递归删除目录及其内容（谨慎使用）。
- `rm -rf`：强制删除，无需提示。

#### `cp`
复制文件或目录。
- `cp source destination`
- `cp -r source destination`：复制目录。

#### `mv`
移动文件或重命名文件。
- `mv source destination`：移动。
- `mv old_name new_name`：重命名。

#### `cat`
查看文件内容。
```bash
cat filename.txt
```

#### `grep`
在文件中搜索文本。
```bash
grep "search_term" filename.txt
```

#### `head` & `tail`
查看文件的开头或结尾。
- `head filename.txt`：查看前 10 行。
- `tail filename.txt`：查看最后 10 行。




如果你想在一个目录内部创建一个子目录，请在使用 `mkdir` 时使用 `-p` 选项。我将创建一个名为 `distro` 的目录，并在内部创建一个名为 `opensuse` 的子目录。如果我使用 `/distro/opensuse` 作为路径运行 `mkdir` 命令，它会报错说目录 `distro` 不存在。这时 `p` 选项就起作用了，它会创建给定路径中的所有目录：

```
mkdir -p /home/swapnil/Downloads/distros/opensuse
```

此命令将创建新目录 `distros` 以及其内部的子目录 `opensuse`。

### 现在我们来删除它们

如果你想删除任何文件或目录，命令是 `rm`（用于文件）和 `rm -r`（用于目录）。你需要非常小心使用这个命令，因为如果你没有提供文件或目录的正确路径，它将删除当前目录下的所有内容，你可能会丢失珍的数据。命令非常简单：

```
rm /path-of-the-directory-or-file
```

如果我想删除 `opensuse` 目录，命令将是：

```
rm -r /home/swapnil/Downloads/distros/opensuse/
```

然而，如果你想删除目录的所有内容而不删除目录本身，请使用带斜杠的 `*` 通配符。假设我想删除 `opensuse` 目录的所有内容：

```
rm /home/swapnil/Downloads/distros/opensuse/*
```

如果内部有子目录（例如 `opensuse` 目录），那么你需要使用 `-r` 选项来同时也删除这些子目录：

```
rm -r /home/swapnil/Downloads/distros/opensuse/*
```

# Linux 管理与安全基础

## 计算机安全导论

什么是计算机安全？

安全就是风险管理。 - 未知

“如果你可以依赖计算机及其软件表现如你预期的那样，那么这台计算机就是安全的” - 《Practical UNIX and Internet Security》

安全是：可用性、一致性、访问控制、数据机密性、身份验证。 - http://www.sun.com/security/overview.html

“计算机安全的主要目标是保护并确保自动化信息系统及其包含的数据的机密性、完整性和可用性。” - http://cssrc.nist.gov/publications/secpubs/cssclaw.txt

对于“计算机安全”有许多定义，其中大多数都是正确的。从本质上说，计算机安全意味着执行使用策略，必须这样做是因为人类和软件存在导致事故的缺陷，同时也因为有人可能想要窃取你的信息、不恰当地使用你的资源，或简单地拒绝你使用你的资源。

### 安全策略

安全策略是你组织执行的执行。安全目标会有很大差异，例如，银行更关注账户的机密性和完整性，而非其他任何事情；而色情网站可能更关注信用卡处理。市面上有大量的安全技术，从软件到实现方案。如果你对自己的目标没有坚实的想法，就无法妥善实施。连接到办公室的用户需要使用 VPN 吗？如果你的策略规定所有文件和传输必须在“受信任”网络上加密，那么答案是肯定的。对于可以从互联网访问的服务，哪些身份验证方法是可以接受的？你要求强密码、令牌、生物识别认证还是这些者的组合？你从远程站点收集的数据，这些数据被收集重要，还是这些数据保持保密重要？远程遥测数据可能不如信用卡号那么敏感。

某些安全策略需要异常宽泛和通用，例如英国骨干网络 JANET 的策略规定如下：

#### 监控与执行

19. 根据由书面站点协议支持的责任政策，UKERN 必须有某种方法来执行 AUP（可接受使用政策）预见的可能断开，并在必要时向执法机构提供完全访问和协助。

20. 因此，JANET-CERT 已被赋予（与 UKERN 合作）责任：
* 在尽可能尊重隐私的前提下监控网络使用情况，无论是响应有关特定威胁的信息，还是通常情况下由于收到的某种情况；
* 要求主站点通过其指定的联系人纠正其在责任范围内的任何遗漏；
* 当站点无法或不愿配合时，向 UKERN 报告问题并启动紧急断开程序；
* 在必要时获取证据并传递信息，以协助执法机构进行调查；
* 为违反安全的调查提供支持和协调。

另一方面，安全策略也可以非常细致：
所有内部邮件必须使用 `PGP` 或 `GnuPG` 加密，且密钥至少为 1024 位并由授权签署人签名。策略越详细、越偏向技术，就越难遵循和维护。实施策略的实际细节应该被隐藏。将其保密比将其全部整合进策略是更好的主意。

### 可接受使用政策

计算机安全的另一个内容是 AUP（可接受使用政策）。这是一份规定了用户对资源可以或不能做什么的文档。它是合同的一部分，并在购买时签署。许多可接受政策通常禁止非法、可能骚扰他人（从而给提供者带来麻烦）或反感的行为（例如色情内容）。其他标准条款包括“本通知随时更改而不另行”以及“如果您违反本政策，我们可以随时终止您的服务”。通常来说，大多数 AUP 都是合理的，对普通用户不会产生问题。这些是安全策略的良好补充，因为它们明确规定了用户可以或不能做什么，而且由于它们通常是合同的一部分，当用户尝试或已违反策略时，它允许提供者执行其安全策略。

### 隐私政策

隐私政策很有趣，因为它们旨在防止组织（通常是公司）违反用户安全的某些方面（特别是其信息的机密性）。遗憾的是，大多数隐私政策包含类似“本政策随时更改而不另行通知”的条款，或者在公司决定利用用户信息获利时直接被丢弃（例如姓名、地址、信用卡详细信息、购买历史等）。

### 安全是一个过程

你只需要犯一个错误或遗留一个漏洞，攻击者就能进入。这当然意味着大多数网站最终会被入侵。看看 Code Red 和 Nimda 引起的影响，这两者都通过利用 Microsoft IIS 服务器中早已已知且长期解决的漏洞而取得了巨大的成功。定期应用补丁（在测试之后）。定期扫描网络中的开放端口。使用 Nessus 等入侵测试软件扫描服务器。审计文件权限，并确保没有意外的 setuid 或 setgid 二进制文件。

深度防御





所有的技术安全措施最终都会失败或容易受到攻击者的利用。这就是为什么你必须建立多层防护。仅靠防火墙是不够的，你可能会无意中忘记某条规则，或者在初始化规则集时让自己暴露在风险，尽可能使用 `tcp_wrapper` 来限制对服务的访问。限制哪些用户可以访问这些服务，特别是只有少数用户需要访问时。尽可能对流量进行加密，以便攻击者无法轻易嗅探用户名和密码，或劫持会话。由于安全措施可能会失效，你还需要一个强大的审计和日志流程，以便日后查出出了什么问题以及情况有多严重。

## 技术问题

这些只是安全管理员面临的成千上万特定问题的冰一角。

### 网络连接

最大的挑战之一是网络连接性的增加。如果你有一台没有连接到任何机器的机器，攻击者通常需要获得物理访问。这无疑在很大程度上缩小了攻击者的数量。然而，随着万物连接到互联网，有超过 1 亿人可能进入你的机器。

### 不安全的默认设置

这是自从第一天起就引起无数安全问题的问题之一。供应商通常在发行操作系统时带有不安全的默认设置（例如 finger、telnet、ftp 等），这意味着管理员在能够开始主动加固其系统和网络之前，必须花费大量精力来关闭这些安全漏洞。

### 合法访问 vs. 破入

由于你必须授予合法用户访问资源的权限，因此攻击者始终有获得访问可能。攻击者可以猜测身份验证凭据（例如弱密码）、窃取凭据（密码嗅探）、利用服务器本身的漏洞等。

### 最小化访问和权限

尽可能限制访问。如果你不需要运行 finger，请将其关闭并删除。如果 finger 不存在，攻击者就无法利用它。如果可能，不要让用户留在服务器上；如果他们由于某些原因需要 shell 账户，请为此设置一个单独的系统并将其与你的网络其余部分隔离开。尽可能锁定工作站，设置 BIOS 密码，保护启动序列，不要给他们管理员权限。

# 文件系统布局与结构

在 Linux（以及 UNIX）中存在许多常见的攻击/利用手段，通过合理的目录和分区结构，可以降低这些攻击的风险和影响。最常见的拒绝服务攻击之一是用垃圾数据填满磁盘空间，这也可能在软件出现问题时无意中发生。通常的防御方法是为 root 用户分配固定百分比的磁盘空间作为预留空间（通常为 5-10%），因此在 10 GB 的磁盘上，用户无法使用最后的 500 MB，这部分空间将保留给 root。但是，如果某个以 root 身份运行并生成日志文件的程序出现故障，或者受到攻击导致生成海量日志文件，这种方法对你毫无处。下一种利用磁盘设置的大型攻击是 `/tmp` 竞态条件和核心转储（core dumps），即程序在不先检查文件是否存在的情况下不当创建创建链接或文件，特别是以 root 身份运行的程序。攻击者可以将 `/tmp/foo` 链接到 `/etc/passwd` 并可能添加账户、清空密码数据库等。

挂载选项可用于将分区设为只读、禁止执行程序以及其他有用功能。然而，在使用这些选项时可能会遇到困难，例如，如果你将 `/usr` 挂载为只读，那么在升级系统组件时你的工作量将大大增加，特别是对于那些需要保持运行又需要进行关键更新的关键服务器（例如电子商务机器）。更有用的选项是 `nosuid`（不使用 setuid 或 setgid 文件）、`noexec`（不执行可执行文件）和 `nodev`（不允许设备文件）。

- 将用户可以写入的文件系统放在单独的分区上
- 将包含关键系统组件/配置的文件系统放在单独的分区上
