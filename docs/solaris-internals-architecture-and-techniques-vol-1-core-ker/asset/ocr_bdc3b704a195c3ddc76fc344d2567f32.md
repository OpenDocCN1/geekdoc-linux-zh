# Overview

patch tables should be done with extreme caution and should be tested sively before going into production—we’ve seen dispatch table “tweaks” drastically affect the performance of a system, not always for the better.

The interactive class (IA) uses the timeshare dispatch table. This is not necessarily intuitive; you specify the TS or IA table to the dispadmin(1) command, and the command output header will indicate either “Interactive Dispatcher Configuration” or “Time Sharing Dispatcher Configuration,” depending on what was specified on the command. Both classes use the same dispatch table; thus, any changes made for one class affect the other. The IA class was added to make the Solaris window-based desktop environment provide snappier performance. To enhance performance, all processes started under the windowing system (OpenWindows or CDE) are put in the IA class, and the priority of processes attached to the window that has the current input focus (the active window—the one used by the user) is boosted. The procedure uses most of the TS infrastructure with just a few IA-specific routes, which we discuss in the next section.

For the SYS class (kernel mode priorities), an array is built within the TS framework to define the kernel mode priorities available to TS/IA class threads when warrant a priority boost into the SYS class. The config_kmdpris[] is an array of 40 priorities, values 60–99, and is defined in the tdsptbl (timeshare dispatch table) loadable module that be modified, compiled, and loaded into the system. The ts_dptbl(4) for instances is referenced through a ts_kmdpris pointer that points to the first element in the array.

+   * Array of global priorities by ts proc sleeping or
* running in kernel mode after sleep. Must have at least
* 40 values.

```
pri_t config_ts_kmdpris[] = {
    60, 61, 62, 63, 64, 65, 66, 67, 68, 69,
    70, 71, 72, 73, 74, 75, 76, 77, 78, 79,
    80, 81, 82, 83, 84, 85, 86, 87, 88, 89,
    90, 91, 92, 93, 94, 95, 96, 97, 98, 99
};
```

The real-time (RT) dispatch table is quite simple, since RT run at fixed priorities. The kernel does not change the priority of an RT thread unless instructed to do so as a priocntl(1) command or priocntl(2) system call. Each entry in the RT dispatch table is defined by the rtdpent data structure in /usr/include/sys/rt.h.

+   * Real-time dispatcher parameter table entry
/
type struct rtdpent {
    pri_t rt_globpris; /* global (class independent) priority */
    int rt_quantum;    /* default quantum associated with this level *
} rtdpent;
