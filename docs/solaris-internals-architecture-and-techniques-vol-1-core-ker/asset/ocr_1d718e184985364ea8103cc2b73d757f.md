#  5.3.7 Virtual Memory Protection Modes

We break each process into segments so that we can treat each part of the address space differently. For example, the kernel maps the code portion of the executable binary into the process as read-only to prevent the process from modifying its code instructions. The virtual memory subsystem does this by taking advantage of the hardware MMU virtual memory protection capabilities. Solaris relies on the MMU having the following protection modes:

+   - Read — The mapping is allowed to read from.
- Write — The mapping is allowed to written to.
- Executable — The mapping is allowed to have machine codes executed within its address range.

The implementation of protection modes is defined in the segment and HAT layers.
