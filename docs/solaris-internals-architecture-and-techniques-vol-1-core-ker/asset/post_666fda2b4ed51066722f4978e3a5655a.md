The maxpgio parameter is the maximum number of pages the page scanner can push. maxpgio can also limit the number of file system pages that are pushed, thus limiting the write performance of the file system. If your system has memory, we then recommend setting maxpgio to something large, say, 1024. On the E10000 systems, this is the default for maxpgio. For example, on a 4-gigabyte machine, one-fourth of memory is 1 gigabyte, so we would set fastscan to 131072. Our parameters, set in /etc/system, for this machine are shown below.

```text
* Parameters to allow better file system throughput
set fastscan=131072
set handsreadpages=131072
set maxpgio=1024
```

In summary, we have seen the strong relationship between the VM system and file system behavior. The parameters that control the paging system have the most influence on file system performance, since they govern the way pages are made available to the file system. ## 15.5 Bypassing the Page Cache with Direct I/O

In some cases we may want to do completely unbuffered I/O to a file. A direct I/O facility in most file systems allows a direct file read or write to completely bypass the file system cache.

### 15.5.1 UFS Direct I/O

Support for direct I/O was added to UFS starting with Solaris 2.6. Direct I/O allows reads and writes to files in a regular file system to bypass the page cache and access the file at near raw disk performance. Direct I/O can be advantageous when you are accessing a file in a manner where caching is not of benefit. For example, if you are copying a very large file from one disk to another, then it is likely that the file will not fit in memory and you just cause the system to page heavily. By using direct I/O, you can copy the file through the file system without reading through the page cache and eliminate the memory pressure caused by the file system and the additional CPU cost of the layers of cache.

You enable direct I/O by mounting an entire file system with the force-directio option, as shown below.

```bash
# mount -o directio /dev/dsk/c0t00s6 /ul
```

You can also enable direct I/O with the direct system call, on a per-file basis. Note that the change is file based, and every reader and writer of the file will be forced to use directio once it's enabled.

```c
int directio(int ildes, DIRECTIO_ON | DIRECTIO_OFF);
```

Direct I/O can provide extremely fast transfers when moving data with large sizes (>64 kilobytes), but it can suffer for smaller sizes.

Databases are a good candidate for direct/O since they cache their own blocks. The size of the nsize is provided with the kstat. Note that the format of the structure shown below.

```c
struct uds_directio_kstat {
    uint_t logical_reads;      /* Number of */
    uint_t phys_reads;        /* Number of */
    uint_t holes;             /* Number of */
    uint_t nread;             /* Physical bytes */
    uint_t logical_writes;    /* Number of fs */
    uint_t phys_writes;       /* Number of */
    uint_t flushes;           /* Number of times */

A low hit rate does not necessarily mean that the DNLC is undersized; it simply means that we are not always finding the names we want in the name cache. The reason is that a create operation checks to see we are creating a large number of files. it creates the file, causing a large number of cache misses.
