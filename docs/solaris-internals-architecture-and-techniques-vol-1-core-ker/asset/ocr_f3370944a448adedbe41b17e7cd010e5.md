O_CREATE and O_EXCL flags have no meaning beyond the open operation and
not preserved in any of the underlying file support structures.

File modes are established as a result of the (optional) mode bits that can be
passed in the open system call, along with the process file creation mask. The file
creation mask is set with the umask(1) command or programmatically with the
umask(2) system call. It allows users to define default permissions for files they
once set, the value is stored in the user area of the process structure, in
tvariable u_mask. See the umask(1) manual page for specifics. Briefly, the umask
value represents the file-mode bits the user wants when a file is created. It
put another way, the umask value determines which file permission bits will be turned
off by default. The kernel simply uses standard C languagewise operators to
t off whatever bits are defined in the u_mask value for the file's permissions
modes when a file is created. Note that u_mask applies only to newly created
files.

An open(2), of course, can be issued on an existing file, in which case the per-
missions are done to ensure that the calling process has proper permissions.
If the open(2) has a mode value defined as an optional third argument, the per-
mission of an existing file are not changed. Such a change requires use of
chmod(1) or chmod(2).
