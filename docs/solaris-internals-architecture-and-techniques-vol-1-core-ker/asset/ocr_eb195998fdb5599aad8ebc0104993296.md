The utility in crash dumps the uarea of a process. For each open file, crash provides the address of the corresponding file structure. As you see, fd 3 and 4 reference different file structures, even though we opened the same file in the same process. Descriptors 4 and 5 show the same file structure address (60824870), because 5 is a dup of 4. Finally, the f (file) utility dumps file structure information. We first dump the file structure for fd 3 (f 60824c558) and then for fd 4 (f 60824870). You can see that the file structure has a reference count of 2, because two descriptors are referencing it, and you can also see that the sync flag is set in the file structure, as set in the original open(2) system call. The TYPE/ADDR column in the f utility output provides the file and kernel address of the vnode. Note that the vnode is, as any open file in the system will have one and only one vnode, number of open files and file structures.

# 11.3.2 The read and pwrite System Calls

The POSIX standard provides two interfaces, shown below, for performing basic read and I/O. These interfaces are similar to the read() and write() system calls but allow a file offset to be part of the system call.

```
size_t pread(int fild, void *buf, size_t nbyte, off_t offset);
size_t pwrite(int fild, const void *buf, size_t nbyte, off_t offset);
```
