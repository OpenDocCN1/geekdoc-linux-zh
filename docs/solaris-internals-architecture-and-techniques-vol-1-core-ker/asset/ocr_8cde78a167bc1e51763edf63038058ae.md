The object file exec code is implemented as dynamically loadable kernel modules, found in the /kernel/exec directory (aoutec, elfexec, intpecc) and /usr/kernel/exec (javaexec). The elf and intp modules will load through the normal boot process, since these two modules are used minimally by the kernel startup processes and startup scripts. A.out and java modules will load automatically when needed as a result of executing a SunOS 4.X binary or a Java program. When each module loads into RAM (kernel address space in memory), the mod_install() support code loads the execsw structure information in the execsw[] array.

# 8.13 exec Flow

All variants of the exec(2) system call can resolve in the kernel to a common routine, exec_common(), where some initial processing is done. The path name for the executable file is retrieved, exitlwps() is called to force all but the calling LWP to exit, any POSIX4 interval timers in the process are cleared (p_itimer field in the proc structure), and the syssec counter in the cpu sysinfo structure is incremented (exec system calls, readable with sar(1)). If scheduler activations have been set up for the process, the door interface used for such purposes is closed (i.e., scheduler activations are not inherited), and any other doors that exist within the process are closed.
