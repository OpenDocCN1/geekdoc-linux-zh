
If a directory vnode has v_vfsmountedhere set, then it is a mount point. lookup() encounters a mount point while going down the file system tree, then it follows the vnode's v_vfsmountedhere pointer to the mounted file system and calls vfs_root() method to obtain the root vnode for the file system. Path-name traversal continues from this point.

If lookup() encounters a vnode (VROOT flag in v_flag set) when following "", then lookup() follows the vfs_vnodecovered pointer in the vnode's associated vfs to obtain the covered vnode.

If lookup() encounters a symbolic link, then it calls the vn_readlink() vnode method to obtain the symbolic link. If the symbolic link begins with "/", the path name traversal is restarted from the root directory; otherwise, the traversal continues from the last directory. the caller of lookup() specifies whether the last component of the path name is to be followed if it is a symbolic link.

This procedure continues until the path is exhausted or an error occurs. When lookup() completes, it returns a vnode representing the desired file.

## 13.5.2 The vop_lookup() Method

The vop_lookup() searches a directory for a path-name component matching the supplied path name. The vop_lookup() accepts a directory vnode and a string-name component as an argument and returns a vnode representing the file. If the file cannot be located, then ENOENT is returned. Many regular file systems will first check the directory name lookup cache, and if an entry is found, the entry is returned. If the entry is not found in the directory name cache, then a real lookup of the file is performed.

## 13.5.3 The vop_readdr() Method

The vop_readdr() method reads chunks of the directory into a uio structure. Each chunk can contain many entries as will fit within the size supplied by the uio structure. The uio_resid structure member shows the size of the getents request in bytes, which is divided by the size of the directory entry made by the vop_readdr() method to calculate how many directory entries to return.

### 13.5.5.1 DNLC Operation

Most of the DLLC work is done with two functions: dnlc_enter() and dnlc_lookup(). When a file system wants to up the name of a file, it first checks the DLLC with the dnlc_lookup() function, which queries the DLLC for an entry that matches the specified file name and directory vnode. If no entry is found, dnlc_lookup fails and the file system reads the directory from disk. When the file name is found, it is entered into a hashed list (nc_hash[]) by file name and directory vnode pointer. Once the correct nc_hash chain is identified, the chain is searched linearly until the correct entry is found.
