If we had the ideal process that had all of its virtual memory backed by physical memory, then we could run with no physical swap space. Usually, we need something like 0.5 to 1.5 memory size for physical swap space. It varies, of course, depending on the virtual-to-physical memory ratio of the application.

# 5.5.2.2 swaps Implementation

The swaps file system uses a system variable, availrmem, to keep track of the available paging memory in the system and adds it to the total amount of swap space available. When we reserve virtual swap, we decrease the amount of virtual memory available from the pool. As long as enough available memory and physical swap space are available, then the swap allocations succeed. It's not until later that physical swap space is assigned.

When we create a private segment, we reserve swap and allocate anonymous structures. At that stage, that's all that happens until a real memory page is created as a result of a ZFOD or copy-on-write (COW). When a physical page is faulted in, it is identified by vnode/offset, which for anonymous memory is the virtual swap space for the page.

Anonymous pages in Solaris are assigned swaps vnode and offsets when the segment driver calls anon_alloc() to get a new anonymous page. The anon_alloc() function calls into swaps through swaps_getvp() and then calls swaps_getpage() to create a new page with swaps vnode/offset. The anon structure members, an_vp and an_offset, which identify the backing store for this page, are initialized to reference the vnode and offset within the swaps virtual device space.
