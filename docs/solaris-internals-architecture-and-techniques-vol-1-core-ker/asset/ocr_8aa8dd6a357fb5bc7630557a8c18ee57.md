The class function in crash(1M) that class, the class name, the kernel virtual address of the init function for, and the address of the class operations table, also known as the class functions structure or class operations vector table. (Operations vector table is a generic term that describes an array of pointers to functions, which is precisely what the class functions cl_funcs structure is.)

The class functions structure bundles together function pointers for all of the class-specific (scheduling-class-dependent) kernel routines. They essentially fall into one of categories: class management and thread control. The kernel switches in to the appropriate routine for a specific scheduling class, essentially the same method used in the vfs/vnode structure. A set of macros is defined; the macros resolve to the class-specific function by indexing through either the current kernel thread pointer or the system class. Both the system class and kthread structure maintain a pointer to the class functions structure. For example, the class-specific interclass and exitclass functions are indexed through the system class. (The functions must be called to enable a thread to enter or exit the scheduling class because the kernel thread link to the class operations table would not be in place.) The macro for the enter-class function is shown below.

```
#define CL_ENTERCLASS(t, cid, clparsp, credp, bufp) \
(sclass[cid].cl_funcs->thread.cl_enterclass) (t, cid, \
(void *)clparsp, credp, bufp)
```
