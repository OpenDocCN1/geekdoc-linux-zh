With reference to the sigtopproc pseudocode flow on page 332, the posting
of a trap signal occurs at the segment shown below.

```
/* sigtopproc was passed a non-NULL kthread pointer.
 * indicating a directed signal
 */
Set signal bit in aslwp kthread us t_sig sigtoproc()
Call eat_signal()
```

The signal will be added to the t_sig field in the kthread, and the eat_signal ()
function is invoked. The job of eat_signal () is to make sure the kthread is going
to delivery of the signal quickly—a sleeping thread is made runnable, taken
off the sleep queue, and on a dispatch queue, and the t_astflag in the
kthread structure is set. The t_astflag will force the thread to check for a signal
execution resumes. With the signal now posted, sigtoproc() is done, and the
code returns to trap_cleanup(). The cleanup code invokes the
ISSIG_PENDING macro, which will determine from the bit set in the t_sig field
at a signal has been posted. Once the marco establishes the presence of the sig-
al, it invokes the kernel psig () function to handle actual delivery.

The system defines several macros for speeding up the examination of the proc
p_sig and kthread t_sig fields for the presence of a posted signal. The defini-
tions are below from /include/sys/proc.h.

```
#define ISSIG(t, why) ISSIG_FAST(t, ttolwp(t), ttoproc(t), why)
/*
 * Fast version of ISSIG
 *1. uses registers to lwp and instead of reloading them.
 *2. uses bitwise OR of tests, since the usual case is that none of them
 * are true saves orc's and branches.
 * are true; saves orc's and branches.
 *3. loads the signal flags instead of usingempty() macro which does
 * a branch to convert to boolean.
 */
#define ISSIG_FAST(t, lwp, p, why)
ISSIG_PENDING(t, lwp, p) && (why)

#define ISSIG_PENDING(t, lwp, p) \
((lwp)->lwp_cursig |) \
(p)-p_sig_sights[0] | \
(p)-p_sig_sights[1] | \
(t)-t_sig_sights[0] | \
(t)->t_sig_sights[1]) | \
(p)-p_stopsig | \
((t)->t_proc_flag & (TP_PRSTOP|TP_HOLDWLP|TP_CHKT|TP_PAUSE)) | \
((p)--p_t_sig & (EXITLWP)|SKILLED|HOLFORKI|HOLDWATCHING))
```

Header File <sys/proc.h>

As you can see, ISSIG and ISSIG_FAST resolve to ISSIG_PENDING, which per-
forms a logical OR on the p_sig and t_sig fields, logically ANDing that result
with the return value of issig(why).
