# Turnstles and Priority Inheritance

We know from the previous sections on mutex and RW locks that a turnstile is required if a thread needs to block on a synchronization object. Solaris 7 calls turnstile_lookup() to look up the turnstile for the synchronization object in the turnstile_table(). Since we index the array by hashing on the address of the lock, if a turnstile already exists (there are already waiters), then we get the correct turnstile. If no kthreads are currently waiting for the lock, turnstile_lookup() simply returns a null value. If the blocking code must be called (recall from the previous sections that subsequent tests are made on availability before it is determined that the kthread must block), then turnstile_block() is entered to the kernel thread on a sleep queue associated with the turnstile.

Kernel threads lend their attached turnstile to the lock when the kthread becomes the first to block (the lock acquisition attempt fails, and there are no waiters). The turnstile's priority is added to the appropriate turnstile chain, based on the result of a hashing function on the address of the lock. The lock now has a turnstile, so subsequent threads that block on the same lock donate their turnstiles to the free list (on the ts_free link off the active turnstile).

In turnstile_block(), the pointers are set up as the return from turnstile_lookup(). If the turnstile is null, we link up to the turnstile pointed to by the kernel thread's ts pointer. If the pointer returned from the lock is not null, there's at least one kthread waiting on the lock, so the code sets up the pointer pointers appropriately and places the kthread's turnstile on the free list.

The thread is then put into a sleep state through the scheduling-class sleep routine (e.g., ts_sleep()). The ts waiters field in the turnstile is the address of the lock, and t_obj_ops in the thread is set to the address of the lock's operations vector: the owner, asleep, and change_priority functions. The kernel sleep_insert() function places the thread on the sleep queue associated with the turnstile.

The code does the priority inversion check (now called out turnstile_block()), builds the priority inversion links, and applies the necessary priority rules. The priority inheritance rules state that, if the priority of the lock is less (worse) than the priority of the requesting thread, the requesting thread's priority is “willed” to the holder. The holder's t_epri field is set to the new priority, and the inhibitor pointer in the turnstile is linked to the kernel thread. All the threads on the blocking chain are potential inheritors, based on their priority relative to the calling thread.

At this point, the dispatcher is entered through a call to swch(), and another kernel thread is removed from a dispatch queue and context-switched onto a processor.
