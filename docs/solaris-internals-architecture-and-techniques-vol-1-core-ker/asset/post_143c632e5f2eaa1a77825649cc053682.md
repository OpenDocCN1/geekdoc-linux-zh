## 5.8.1 Page Scanner Operation

The page scanner tracks page usage by reading a per-page hardware bit from the MMU for each page. Two bits are kept for each page; they indicate whether the page has been modified or referenced since the bits were last cleared. The page scanner uses the bits as the fundamental data to decide which pages of memory have been used recently and which have not.

The page scanner is a kernel thread, which is awakened when the amount of memory on the free-page list falls below a system threshold, typically 1/64th of total physical memory. The page scanner scans pages in physical page order, looking for pages that haven't been used recently to page out to the swap device and free. The algorithm that determines whether pages have been used resembles a clock face and is known as the two-handed clock algorithm. This algorithm views the entire physical page list as a circular list, where the last physical page wraps around to the first. Two hands sweep through the physical page list, as shown in Figure 5.22.

## 5.8.2 Page-out Algorithm and Parameters

The page-out algorithm is controlled by several parameters, some of which are calculated at system startup by the amount of memory in the system, and some of which are calculated dynamically based on memory allocation and paging activity.

The parameters that control the clock hands do two things: they control the rate at which the scanner scans through pages, and they control the time (or distance) between the front hand and the back hand. The distance between the back hand and the front hand is headspreadpages and is expressed in units of pages. The maximum distance between the front hand and back hand defaults to half of the memory and is capped at 8,192 pages, or 64 Mbytes. Systems with 128 Mbytes or more memory always default this distance to 8,192 pages, or 64 Mbytes.

The distance between the back hand and the front hand is headspreadpages and is expressed in units of pages. The maximum distance between the front hand and back hand defaults to half of the memory and is capped at 8,192 pages, or 64 Mbytes. Systems with 128 Mbytes or more memory always default this distance to 8,192 pages, or 64 Mbytes.

### 5.8.2.1 Scan Rate Parameters (Assuming No Priority Paging)

The scanner starts scanning when free memory is lower than lotsfree number of pages plus a buffer factor, deficit. The scanner starts scanning at a rate of slowscan pages per second and gets faster as the amount of free memory approaches zero. The system parameter lotsfree is calculated at startup as 1/64th memory, and the parameter deficit is either zero or a small number of pages—set by the page allocator at times of large memory allocation to let the scanner free a few more pages above lotsfree in anticipation of more requests.

# Solaris Memory Architecture

For this example, we'll assume that the deficit is zero. When free memory falls to 16 Mbytes, the scanner will wake up and start examining 100 pages per second, according to the system parameter slowscan. The slowscan parameter is 100 by default on Solaris systems, fastscan is set to total physicalmemory/2, capped at 8,192 pages per second. If free memory falls to 12 Mbytes (1,536 pages), the scanner scans at a higher rate, according to the page scanner interpolation shown in the following equation:

```
scanrate = \frac{lotsfree-freemory \times fastscan}{lotsfree} + (slowscan \times \frac{freemory}{lotsfree})
```

If we convert free memory to numbers of pages (free memory of 12 Mbytes is 1,536 pages, and lotsfree is set to 16 Mbytes, or 2,048 pages), then we scan at 2,123 pages per second.

By default, the scanner is run four times per second when there is a memory short-age. The amount of free memory falls below the system parameter minfree, the scanner is awoken by the page allocator for each page-create request. This scheme helps the scanner to keep at least minfree pages on the free list.

## 5.8.2.2 Not Recently Used Time

The time between the front hand and back hand varies according to the number of pages between the front hand and back hand. The time between the front hand and back hand allows a page to be referenced again before the back hand inspects it. If the page is referenced, the referenced bit is set. If the page is modified, the modified bit is set. The page scanner clears these bits when it passes over the page. If the page has not been referenced or modified by the time the back hand reaches it, it is swapped out and freed.

The time between the front hand and back hand varies according to the number of pages between the front hand and back hand is a significant factor that affects the pressure induced by the file system. High scan rates are normal on systems because of the memory pressure from the file system. (We discuss this topic further in “Is All Paging Bad for System?” on page 595).

## 5.8.3 Shared optimization

A subtle optimization added to the scanner prevents it from stealing pages from extensively shared libraries. The page scanner looks at the share count for each page; if the page is shared more than a certain amount, it is skipped during the page scan. An internal parameter, po_share, sets the threshold for the amount of shares a page can have before it is skipped. If the page has more than po_share mappings (i.e., shared by more than po_share), by default, po_share starts at 8; each time around, it is decremented unless the scan clock does not find any page to free, in which case po_share is incremented. The po_share parameter can float between 8 and 134217728.

## 5.8.4 The Priority Paging Algorithm

Solaris 7 shipped with a new optional paging algorithm—a page-stealing algorithm that results in much better system response and throughput for systems using the file systems. The algorithm is also available on older Solaris releases (from 2.5.1 onwards) with the addition of a kernel patch. You enable the new algorithm by setting the priority_paging variable to 1 in /etc/system.

- Enable the Priority Paging Algorithm
- set priority_paging = 1
