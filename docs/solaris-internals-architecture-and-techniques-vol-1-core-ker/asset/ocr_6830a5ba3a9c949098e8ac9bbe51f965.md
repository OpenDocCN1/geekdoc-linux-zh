+   - **p_crlock** — Kernel mutex to synchronize access to the credentials structure.
- **p_swpcnt** — Counter of LWPs linked to the process that have been swapped out. Under severe memory shortfalls, the memory scheduler (PID 0, the sched process) will swap out entire LWPs to free up some memory pages.
- **p_stat** — The process status, or state. The notion of process states is what misleading in the Solaris environment, since the kernel thread, not the entity that has a scheduling class, is prioritized, and is put on a dispatch queue for scheduling. Kernel threads change in the Solaris environment much more frequently than processes. For a nonthreaded process, the process state is essentially whatever the state of the kthread is. For multithreaded processes, several kthreads that belong to the same process can be in different states (e.g., running, sleeping, runnable, zombie, etc.).

In a few areas of the kernel, the process state (p_stat) is used explicitly. In the fork() code, the SIDL state is used, and later in fork(), p_stat is set to SRUN—the process has been created and is runnable. In the exit(), p_stat is set to ZOMB when a process is terminated. These three exceptions aside, all other state changes during the lifetime of a process occur in the kthread and are reflected in the state field of the kthread structure. In fact, the state (S) column from the ps(1) command is derived from the kthread state, not the process p_stat data. If a process has more than one LWP and the -L flag has not been specified in the ps(1) command line, the state field is derived from LWP 1 (the -L flag to ps(1) will print information about each LWP in selected process). A process can be one of the following possible states:

+   - SLEEP — Process is sleeping (waiting for an event)
- RUN — Process is runnable, waiting to be scheduled
- ZOMB — Process is a zombie, that is, it has exited but wait has not yet executed on its itself behalf
- STOP — Process is stopped, typically caused by debugger activity
- SIDL — Process is being created and assigned this interim state
- ONPROC — Process is running on a processor
