Once shmget(2) returns success to an application, the code has a valid shared memory identifier. The program must call shmat(2) to create the mappings (attach) to the shared segment.

```
[application]
shmat(shmid, address, flags)

[kernel]
shmat()
  /* ipc_access() / * check permissions */
  /* ipc_access() / will return EACCES if permission tests fail */
  /* and cause shmat(2) to bail out *
  if (kernel has ISM disabled)
    clear SHM_SHARE_CNT flag
    if (ISM and SHM_SHARE NOT flag)
      calculate number of pages
      find a range of pages in the address space and set address
      if (user-supplied address)
        check alignment and range
      map segment to address
      create shared mapping tables
  if (NOT ISM)
    if (user-supplied)
      find a range of pages in the address space and set address
    else
      check alignment and error
  return pointer to shared segment, or error
```

Much of the work done in shmat() requires calls into the lower-level address space support code and related memory management routines. The details on a process's address space shared mappings are covered in Chapter 10. Remember, attaching to a shared memory segment is essentially another extension to a process's address space mappings.

At this point, applications have a pointer to the shared segment that they use in their code to read or write data. The shmdt(2) interface allows to unmap the shared pages from its address space (detach itself). Unmapping does not cause the system to remove the shared segment, even if all processes detached themselves.. shared segment must be explicitly removed by the shctl(2) call with the IPC_RMID flag set or from the command line with ipcrm(1). Obviously, permissions must allow for the removal of the shared segment.

We should point out that the kernel makes no attempt at coordinating concurrent access to shared segments. The software developer must coordinate the access by using shared memory to prevent multiple processes attached to the same pages from writing to the same locations at the same time. Coordination can be done in several ways, the most common of which is the use of another IPC facility, semaphores or mutex locks.
