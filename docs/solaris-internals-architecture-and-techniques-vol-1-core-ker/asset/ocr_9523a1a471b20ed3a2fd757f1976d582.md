```
rt_enterclass() {
    if (not superuser) 
        return; /* must be root to use RT class */
    if (no user-supplied priority) {
        rtproc->rt_priority = 0;
        rtproc->rt_quantum = rt_dbtbl[0].rt_quantum;
    }
    else {
        rtproc->rt_priority = user-supplied priority;
        if (user-supplied time quantum) /* -t flag in prioritycnt */
        else {
            rtproc->rt_quantum = rt_dbtbl[rt_pri].rt_quantum;
        }
    }
    if (thread is running) {
        kthread = rt_dbtbl[rt_pri].rt_globpri;
        if (thread priority > highest-priority thread on a queue) {
            rtproc->rt_timeleft = rtproc->rt_quantum;
        }
        else {
            surrender the processor
        }
    }
    else /* thread is not running */
        thread_change_pri(new_priority);
}
```

Other housekeeping—initializing the other members of rtproc and setting the pointers in rtproc and the kthread structure—done in rt_enterclass() is not shown above.

A thread will also enter the RT class if it forked from another RT thread, because child threads inherit the parent priority and time quantum in the rt_fork() code. The execution order of parent and child threads in the RT class is different from that of TS/IA class threads. The child executes first, by design, when a TS/IA class thread is forked (this is especially true in the case of vfork(), as discussed in the previous chapter). RT thread ends up on the dispatch while the parent continues to run, unless, of course, the application code is written explicitly to otherwise.

The rt_tick() code, called from the clock handler determines if the thread's time quantum has expired. If the thread is forced to surrender the processor; otherwise, it continues. RT class decrement a counter, rt_timeleft, in the rtproc structure to track processor time clicks. A zero rt_timeleft means the time quantum has been used. It is possible to set an infinite time quantum for RT class threads. An rt_quantum value of -2 in the RT dispatch is interpreted by the kernel as an infinite quantum, in which case an RT thread will continue to run unless it voluntarily surrenders the processor as a result of a sleep (e.g., issuing a blocking system call).

The RT code does not index the dispatch table to fetch the RT_quantum data every time a test is. Once the RT thread is established, the time quantum from the RT table is stored in rt_quantum in the thread's rtproc structure.
