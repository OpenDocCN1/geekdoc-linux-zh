A further callback interface is provided in each cache so that the allocator can let the client know about the memory pressure. This callback is optionally supplied when the cache is created and is a simple function that the client implements to return, by means of kmmem_cache_free(), as many objects to the cache as possible.

A good example is a file system, which uses stores to object the nodes. The slab allocator manages inode objects; the cache management, construction, and destruction of inodes are handed over to the slab allocator. The file system simply asks the slab allocator for a "new inode" each time it requires one. For example, a file system could call the slab allocator to create a slab cache, as shown below.

```
inode_cache = kmmem_cache_create("inode_cache",
               sizeof(struct inode), 0, inode_cache_constructor,
               inode_cache_destructor, inode_cache_reclaim,
               NULL, 0);

struct inode *inode = kmmem_cache_alloc(inode_cache, 0);
```

The example shows that we create a cache named inode_cache, with objects of the size of an inode, no alignment enforcement, a constructor and a destructor function, and a reclaim function. The back-end memory allocator is specified as NULL, which by default allocates physical pages from the slabkm page allocator.
