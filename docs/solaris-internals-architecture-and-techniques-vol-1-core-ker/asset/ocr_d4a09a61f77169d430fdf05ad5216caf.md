# The Solaris Multithreaded Process Architecture

+   * p_parent — Pointer to the parent process.
* p_child — Pointer to the first child process. Subsequent children are linked by means of the sibling pointers in the child processes.
* p_sibling — Pointer to the first sibling (next child created by parent).
* p_psibling — Pointer to previous sibling. Back pointer in support of a doubly linked list of related processes.
* p_sibling_ns — Pointer to a sibling process that has changed state.
* p_child_ns — Pointer to a child process that has changed state.
* p_next — Next process in the active process list. The kernel maintains a doubly linked list of active processes in the system, pointed to by the kernel pointer.
* p_prev — Previous process in the active process list (see above).
* p_nextofkin — Link maintained back to parent process. Used in process exit code to gather accounting information (accumulated time and system time). Also used to set orphan pointers when a process exits. The orphan links of an exiting process are linked to the nextofkin process, which is the parent.
* p_orphan — Orphan pointer. An orphan process lost its parent; that is, an orphan process continues executing after its parent has exited. In the fork code, the p_orphan pointer in the parent is set to the newly created child. Processes without children have a NULL p_orphan pointer. If child processes spawn child processes, p_orphan will link to the grandchild-child.
* p_nextorph — Next orphan pointer. In fork, the newly created child process's p_nextorph is set to the p_orphan pointer in the parent. Essentially, p_nextorph links siblings.
* p_ppglink — Process group link. Forward link to a hash chain of processes in the same process group. Processes are linked in a group when they are controlled by the same controlling terminal. “Sessions and Process Groups” on page 337.
* p_pppglink — Previous process group link. Back link to hash chain of processes in the same process group.

Figure 8.8 illustrates how the process lineage pointers are set up with a test program, written for that purpose. The processes depict process bd, which fork/execs three processes, c1, c2, and c3. The c2 process fork/execs its own child (process c2), as does the c3 process (child name c3). The c3 child process also fork/execs a child, cc3.
