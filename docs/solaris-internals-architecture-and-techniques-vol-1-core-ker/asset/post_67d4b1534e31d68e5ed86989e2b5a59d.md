
## 14.2.4.2 The Superblock

Immediately after the boot block is the superblock. The superblock contains the information about the geometry and layout of the file system and is critical to the file system state. As a safety precaution, the superblock is replicated across the file system with each cylinder group so that the file system is not crippled if the superblock becomes corrupted. The superblock contains a variety of information, including the location of each cylinder group and a summary list of available free blocks. The major information in the superblock that identifies the file system geometry is shown below.

- fs_sblno — Address of superblock in file system; defaults to block number 16
- fs_cblno — Offset of the first cylinder group in the file system
- fs_iblkno — Offset of the first inode blocks in the file system
- fs_dblkno — Offset of the first data blocks after the first cylinder group
- fs_cgoffset — Cylinder group offset in the cylinder
- fs_time — Last time written
- fs_size — Number of blocks in the file system
- fs_dsize — Number of data blocks in the file system
- fs_ncg — Number of cylinder groups
- fs_bsize — Size of basic blocks in the file system
- fs_fsize — Size of fragmented blocks in the file system
- fs_frag — Number of fragments in a block in the file system
- fs_magic — A magic number to validate the superblock; the number is Bill Joy's birthday.

The file system configuration parameters also reside in the super block. The file system parameters include some of the following, which are configured at the time the file system is constructed. You can tune the parameters later with the tunefs command.

- fs_minfree — Minimum percentage of free blocks
- fs_rotdelay — Number of milliseconds of rotational delay between sequential blocks. The rotational delay was used to implement block interleaving when operating the system could not keep up with reading contiguous blocks. Since this is no longer an issue, fs_rotdelay defaults to zero.
- fs_rps — Disk revolutions per second
- fs_maxcontig — Maximum number of contiguous blocks, used to control the number of read-ahead blocks
- fs_maxbgpg — Maximum number of data blocks per cylinder group
- fs_optim — Optimization preference, space, or time

## 14.2.5 Disk Block Location

The disk blocks for a file are represented by disk pointers in the inode for the file. Each inode has space for 12 disk addresses, which, when used on their own, limit the maximum size of a file to 12 * 8K=96K. To allow for larger files, indirect blocks provide more space for disk addresses. With one level of indirection, one disk address points to a system block containing further disk addresses, greatly increasing the number of data blocks per file. A second level of indirection can also be used, allowing even more data blocks. The inode contains a slot for triple pointers, although triple indirection is currently not implemented within UFS. Figure 14.5 illustrates the inode format.

UFS allocates space, known as fragments, in file system blocks. Assuming 8-KB file system blocks:

- The first 12 direct blocks allow 12 blocks, or 98,304 bytes
- The first level of indirection allows a full system block of disk addresses, which means that an 8-KB block can hold 2,048 32-bit disk addresses; (12 + 2048) × 8 = 16,520 bytes
- The second level of indirection (double indirect) allows (12 + 2048 + 2048) × 8 = 34,376,888 bytes

There is, however, a limit to the maximum offset in each disk address, which is expressed as a number of file system segments; using the default size of 1KB, the maximum offset for each block is 2³¹ × 1KB = 2 terabytes.

## 14.2.6 UFS Block Allocation

UFS uses block sizes of 4 and 8 KB, which provides significantly higher performance than the 512-byte blocks used in System V file system. The downside of larger blocks was when partially filled blocks occurred, several kilobytes of disk space were wasted. To overcome this disadvantage, UFS uses the notion of file system segments. Fragments allow a single block to be broken up into 2, 4, or 8 fragments when necessary.

UFS allocation tries to prevent excessive disk seeking by attempting to co-locate nodes within a directory and by attempting to co-locate a file's index and its data blocks. Where possible, all of the nodes in a directory are allocated in the same cylinder group. This scheme helps reduce seeking when directories are traversed; for example, executing a single fragment of a directory will access all the nodes in that directory, and if all the nodes reside in the same cylinder group, most of the data will be cached after the first few files are accessed. A directory will be placed in a cylinder group different from that of its parent.

Blocks are allocated to a file sequentially, starting with the first 96 KB (the first 12 direct blocks), skipping to the next cylinder group and allocating blocks up to the limit by the file system parameter maxblocks, maximum-blocks-per-cylinder. After that, blocks are allocated from the next available cylinder group.

By default, a file system greater than 1 GB, the algorithm allocates 96 MB in the first available cylinder group, 16 MB from the next, and so on. The maximum cylinder group size is 5 MB, and the allocation only one-third of that space is allocated to each section of a single file when it is extended. The maxblocks parameter is to 2,048 8-KB blocks by default at the time the file system is created; it is also tunable but can only be tuned downward, since the maximum cylinder group size is 16 MB allocation per cylinder group.

Selection of a new cylinder group for the next segment of a file is governed by a rotor and free-space algorithm. The rotor points to the cylinder groups; each new disk space is allocated, it starts with the cylinder pointed by the rotor. If the cylinder group has less than average free space, it is skipped and the next cylinder group is tried. This algorithm makes the file system attempt to balance the allocation across the cylinder groups.
