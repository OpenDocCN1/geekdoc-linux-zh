## 9.1.2 Dispatch Tables

Each scheduling class, except the SYS class, loads with a corresponding dispatch table containing default values for priorities and priority readjustment; in the SYS class, the priorities are defined in a simple array and interrupt, which is not really a scheduling class. You can examine and modify the dispatch tables with the disp_admin(1) command, for example, dispadmin -c TS -g will dump the current current timeshare (TS) and interactive (IA) class dispatch table on your Solaris system. Each entry in the TS/IA dispatch table (each row) is defined by the tsdpent (timeshare dispatch entry) structure (from /usr/include/ts.h), as shown below.

```
/* time-sharing dispatcher entry */
struct tsdpent {
    pri_t ts_globpri;      /* global (class independent) priority */
    int   ts_quantum;      /* time quantum given to proc at this level */
    pri_t ts_tqexp;       /* priority assigned when proc sleeps at this level */
    pri_t ts_slpret;      /* when returns to user mode after sleeping */
    short ts_maxwait;      /* if more than elapse before receiving full quantum */
    short ts_lwait;       /* assigned if ts_maxwait exceeds */
} tsdpent;
```

## Header File <ts.h>

The RES and PRI parameters are not defined in tsdpent. Those fields, along with the defined members in the structure, are described below.

- **RES** — (resolution value) interprets the ts_quantum column in the dispatch table. The reciprocal of RES determines the granularity in which the ts_quantum field will be displayed. As the value of RES increases, the ts_quantum column values increase by the same order of magnitude. See ts_quantum for more information.

- **PRI** — The class-dependent priority, systemwide priority. The PRI column is derived as the row number in the dispatch table. The dispatch table is like any generic table—it has rows and columns. Every row corresponds to a unique priority level within the scheduling class, each column contains values that determine the priority adjustments on thread running at that priority. This is not the same as ts_globpri.

- **ts_globpri** — The only parameter (tsdpent member) that is not displayed in the output of dispadmin command and the only value that is tunable. ts_globpri is the class-independent global priority that corresponds to the timeshare priority (closest to the right). A given scheduling class within Solaris has a range of priorities beginning with 0, which represents the lowest priority for that class. The TS and IA classes have 60 priorities, range 0–59. The kernel implements a global priority scheme, every priority level available in every scheduling class can be uniquely identified with an integer value. Refer to Figure 9.2 on page 348 for a list of priorities when all the scheduling classes are loaded. Since TS/IA is the lowest class, the kernel priorities 0–59 correspond to the TS/IA class priorities 0–59. The kernel computes global priorities time and will recompute if necessary if a new class is loaded into a running system. For example, referring again to Figure 9.2, if the RT class is not loaded, global priorities for interrupt threads will be 100–109, just above system (SYS). If the RT class gets loaded, the global priorities for RT become 100–159, and interrupts are bumped up to 160. ts_globpri is the priority for a kernel thread when priorities are set and readjusted.

- **ts_quantum** — The time quantum; an amount of time that this thread is allowed to run before it must relinquish the processor. Be aware that the ts_dptbl(4) manual page, as other references, indicate the value in the ts_quantum field is in ticks. A tick is a unit of time that can vary from platform to platform. On UltraSPARC-based systems, there are 100 ticks per second, so a tick occurs every 10 milliseconds. The value in ts_quantum is in ticks only if RES is 100. If RES is any other value, the default of 1000, then ts_quantum represents some fraction of a second, the fractional value determined by the reciprocal value of RES. With a default of RES = 1000, the reciprocal of 1000 is .001, or milliseconds. Thus, by default, the ts_quantum field represents the time quantum for a given priority in milliseconds.

From Table 9-2 on page 357, we see that priority 0 kthreads get 200 milliseconds (20 ticks), priority 10 kthreads get 160 milliseconds, etc. As a thread's priority gets better (higher global priority integer value), its time quantum is lower. Worse (whose) priorities get larger time quanta, since they are scheduled to run less frequently. Changing the RES value using the -r flag with disp -c TS -q -r 100 causes the values in the ts_quantum column to change. For example, at priority 0, instead of a quantum of 200 with a RES of 1000, we have a quantum of 20 with a RES of 100. The fractional unit is different.20 tenths-of-second, which is the same amount of time, just represented differently [20 × .001 = 200].
