First, when the sigaction() `sigaction() ` call is executed and the handler is installed, if SA NOCLDWAIT is set in p_flags then SNOWAIT is set and the code loops through the child list, looking for child processes in the zombie state. For each child process found, the kernel freeproc() function is called to release the process table entry. (The kernel exit code, described below, will have already executed,-otherwise, it would not be in the zombie state.) In the second occurrence, the kernel calls its internal sigld() function to post a process that has a child terminate. The sigld() code calls freeproc() instead of posting the signal if SNOWAIT is set in the parent's p_flags field.

Having jumped ahead for a second, let's turn our attention back to the actions performed.

```
exit()
All but 1 LWP (exitlwps)
Clean up any doors created by the process
Clean up pending async I/O
Clean up any realtime timers
Flush signal information (set ignore for all signals, clear posted signals)
Set process LWP count to zero (p_lwpcnt = 0)
NULL process termination the kernel thread linked list
Set process termination time (p_mterm)
Close all file descriptors
if (process is session leader)\ Release control terminal
Clean up any semaphore resources being held
Release the process address space
Reassign orphan processes to next-of-kin
Reassign child processes to init
Set process state to zombie
Set process pwdata and pwcode for parent to interrogate
Call kernel sigld() to send SIGLD to parent
if (SNOWAIT flag is set) freeproc() free the proc slot - no zombie *
else post signal to the parent
```

The sequence of events outlined above is pretty straightforward. It's a matter of walking through the process structure, cleaning up resources that reassigning child and orphan processes. Child processes are handed over to init, and orphan processes are linked to the next-of-kin process, which is typically the case.
