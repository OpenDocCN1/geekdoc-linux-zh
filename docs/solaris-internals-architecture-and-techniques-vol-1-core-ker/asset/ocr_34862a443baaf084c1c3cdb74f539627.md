+   In Solaris 7, sleep\_wakeall\_chan() traverses the linked list of kernel threads waiting on that particular condition variable and, for each kthread, calls sleep\_pq\_unlink(). sleep\_pq\_unlink() removes the kthread from the sleep queue linked list, adjusts the pointers (t\_prifow, t\_prback) and returns to sleep\_wakeall\_chan().

+   On the return to sleep\_wakeall\_chan(), the kthread's t\_chan and t\_sobj\_ops fields are cleared, and the scheduling-class-specific wakeup code is called.

For TS/IA threads, the code is ts wakeup(); for RT threads, it is rt\_wakeup(). In Solaris 2.5 and Solaris 2.6, the queue is a singly linked list, with the t\_link pointer in the kthread.

Solaris 2.5 and Solaris 2.6 do not have a sleep\_unlink() function, so sleep\_wakeall\_chan() removes each thread from the list and sets the thread's t\_link, t\_chan, and t\_sobj\_ops fields to NULL.

+   cv\_signal() locates the correct index in the sleep\_head array by hashing on the address of the condition variable, decrements the cv\_waiters field in the condition variable by 1, since only one thread is getting a wakeup, and calls sleep\_wakeone\_chan().

+   ts\_wakeup() puts the kernel thread back on a dispatch queue so it can be executed on a processor.

Threads that have a kernel mode priority (as indicated by the TSPRI flag in the class-specific data structure, which is set in ts\_sleep() if a SYS priority is assigned) are placed on the front of the appropriate dispatch queue. IA class threads will also result in setfrontdq() being called; otherwise, setbackdq() is called to place the kernel thread at the back of the dispatch queue.

+   Threads that are not at a SYS priority are tested to see if they've waited longer for a shot at getting scheduled than the time set in the ts\_maxwait field in the dispatch table for thread's priority level.

If the thread has been waiting an inorder time to run (if wait > dispatch\_table[priority]diswait), then the thread's priority is recalculated, using the ts\_slpret value from the dispatch table. This is essentially the same logic used in ts\_sleep() and gives a priority boost to threads that have spent an amount of time on the sleep queue.

It is in the dispatcher queue insertion code (setfrontdq(), setbackdq()) that the thread is switched from SLEEP to TS\_RUN. It's also in functions that we determine if the thread we just placed on a queue is of higher priority than the currently running thread and if so, a preemption. At this point, the kthread has been woken up and is sitting on a dispatch queue, ready to get text-switched onto a processor when the dispatcher swch() function runs and the newly inserted thread is selected for execution.
