# 6.2.4.7 The Global (Slab) Layer

The global slab layer allocates objects from contiguous areas of physical memory and hands them up to the magazine layer for allocation. The global slab layer is used only when the upper layers need to allocate or deallocate slabs of objects to refill their magazines.

The slab is the primary unit of allocation in the slab layer. When the allocator needs to grow a cache, it acquires an entire slab of objects. When the allocator wants to shrink a cache, it returns unused memory to the back end by deallocating a complete slab. A slab consists of one or more pages of virtual memory carved into equal-sized chunks, with a reference count indicating how many chunks have been allocated.

The contents of each slab are managed by a kmmem_slab data structure that maintains the slab's linking in the cache, its reference count, and its list of buffers. In turn, each buffer in the slab is managed by a kmmem_bufctl structure that holds the freelist linkage, the buffer address, and a back-pointer to the controlling slab.

For objects smaller than 1/8th of a page, the slab allocator builds a slab by allocating a page, placing the slab and dividing the rest into equal-sized buffers. Each buffer serves as its own kmmem_bufctl while the freelist. Only the linkage is actually needed, since everything else is computable. These are essential optimizations for small buffers; otherwise, we would end up allocating as much memory for kmmem_bufctl as the buffers themselves.
