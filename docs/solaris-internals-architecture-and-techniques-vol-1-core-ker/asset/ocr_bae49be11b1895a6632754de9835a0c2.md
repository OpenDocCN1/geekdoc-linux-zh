Processor binding can happen in two ways: using the traditional bind commands or interfaces for processors that have not been configured into a processor set, or by using processor sets and the associated bind methods specific to processor sets.

The original (and still supported) method of binding a process to a CPU was through the pbind(1M) command and processor_bind(2) system call. Bindings created with each method result in the LWPs of the process scheduling only on the CPU that the process is bound to. It is not an exclusive binding; other LWPs in the system may get scheduled on the CPU. It is also possible that other CPUs will do processing on behalf of the bound LWPs. If an LWP issues an I/O, the I/O may be processed on another CPU, interrupting the process when the I/O is complete. Using the command interface, pbind(1M), we can bind bind the process level. The kernel supports LWP-level binding, where different LWPs in the same process could be bound to different CPUs. This binding can be done programmatically with processor_bind(2), by which you can specify an LWP ID.

Solaris 2.6 added processor sets, and with processor sets another method of binding processes to CPUs. Recall that a processor set is a user-level abstraction of a grouping of processors. In the kernel, all processors in the same set are part of the CPU partition. Once a processor set is created (prset_id), the processors in the set are no longer available for running all kernel threads systemwide. Rather, they will only run kernel threads (LWPs) that have been bound to the processor set with prset(1M) or pset_bind(2). Once process is bound, the binding is exclusive—only threads bound to the processor set are scheduled and executed on CPUs. CPUs in the set are not available as targets—you cannot use pbind(1M) or processor_bind(2) to bind processes or LWPs to a CPU that is part of a processor set. If a process has been bound to a CPU with pbind(1M), that process cannot be placed in a processor set until the binding is undone.

Not every processor on a system can be placed in a processor set. The kernel will not allow at least one CPU must remain in the default partition (created at boot time). Support for processor binding, even to a single processor or to a processor set, exists at the kernel level (or LWP, as it is referred to in the reference manual pages; in this context, the kernel thread and LWP can be thought of as the same thing). A few thread structure fields link to CPU structures if the thread is bound, or they reference the processor set in the case of partitioning binding. These fields are discussed in more detail in Chapters 3 and 4.
