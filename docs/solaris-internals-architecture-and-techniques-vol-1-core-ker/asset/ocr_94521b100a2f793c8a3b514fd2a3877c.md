# 11.3.2 File Open Modes and File Descriptor Flags

The Solaris kernel maintains several file flags at different layers in the file code. Within the file structure, flags can be set when the file is opened (`open(2)` system call). Subsequent operations using the `fcntl(2)` (file control) system call allow for setting and clearing file flags after the file has been opened. Some of these flags get pushed down to the file's vnode, so file manipulation at the vnode layer has the information available without referencing the file structure. Finally, some flags maintained in the inode are not exported to the process (application) level.

The system begins looking at file flags in the early stages of opening a file. When the open system call is executed, the system checks to ensure that either the read or write flag is set, and the kernel looks at `O_NDELAY` and `O_NONBLOCK` flags, which the programmer can set (`open(2)`). `O_NDELAY` and `O_NONBLOCK` have the same meaning—they specify nonfiction I/O. Two flags exist because of evolving standards: `O_NDELAY` emerged as a Unix SVR4 standard, and the `O_NONBLOCK` flag comes from POSIX.1 standard. The Solaris environment supports both standards for compatibility. New applications should use the POSIX.1 standard (NONBLOCK), which is what the system chooses if both are set.

To see which flags are set, use the `fcntl(2)` system call with the `F_GETFD` flag, which retrieves the flags from the file descriptor.
