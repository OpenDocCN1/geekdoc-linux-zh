# The Solaris Multithreaded Process Architecture

The psig(1) command lists the signal actions for a process. The example below dumps the signal actions for our ksh process; omitted lines to save space.

```
$ /usr/proc/bin/psig 448
448:     -ksh
HUP      caught RESTART
INT      caught RESTART
QUIT     caught RESTART
ILL      caught RESTART
TRAP     caught RESTART
ABRT     caught RESTART
ENT      caught RESTART
PBRG     default
KILL     default
BUS      caught RESTART
SEGV     caught RESTART
SYS      caught RESTART
PIPE     caught RESTART
ALRM     ignored
TERM     USR1     caught RESTART
USR2     caught RESTART
CLD      default NOCLDSTOP
PWR      default
```

Recall that a signal can originate from several different places, for typically a variety of reasons. SIGHUP, SIGINT, and SIGQUIT are typically generated by a keybroad entry the controlling terminal (SIGINT and SIGQUIT) or if the control terminal is disconnected, which note the use of nohup(1) command makes processes "immune" by sunsetting the disposition of SIGHUP to ignore. Other terminal I/O-related signals include SIGSTOP, SIGTIN, SIGTOU, and SIGTSTP. For those signals that originate from a keyboard command, the actual key sequence that results in the generation of these signals is defined within the parameters of the terminal session, typically, by stty(1). For example, ^ (Control-C) is usually the interrupt key sequence and in a SIGINT being sent to a process, which has a default disposition of forcing the process to exit.

Signals generated as a direct result of an error encountered during instruction execution start with a hardware trap on the system. Different processor architectures defines various traps that result in an immediate vector transfer control to a kernel trap-handling function. The Solaris kernel builds a trap table and inserts trap handling routines in the appropriate locations, based on the architecture of the processors that the Solaris environment supports: SPARC V7 (sun4 architectures), SPARC V8 (UltraSPARC)—sun4m and sun4d architectures), SPARC V9 (UltraSPARC)—sun4u), and Intel x86. (In parlance the routines are called Interrupt Descriptor Tables, or IDTs. On SPARC, they're called trap tables). The kernel-installed trap handler generally generates a signal to the thread that caused the trap. The signals that result from hardware are SIGILL, SIGFPE, SIGSEGV, SIGTRAP, SIGBUS, and SIGENT.
