Also, a t_sleep pointer added in Solaris 7 points back to the array entry in sleepq_head, identifying which sleep queue thread is on and providing a quick method to determine if a thread is on a sleep queue at; if the thread's t_sleep pointer is NULL, then the thread is not on a sleep queue.

Inside the sem_p() function, if we have a semaphore count value of 0, the semaphore is not available and the calling kernel thread needs to be placed on a sleep queue. A sleep queue is located through a hash function into the sleep_head array, which hashes on the address of the object the thread is blocking, in this case, the address of the semaphore. The code also grabs the sleep lock, sq lock (see Figure 3.16) to block any further inserts or removals from the sleep queue until the insertion of the current kernel thread has been completed (that's what locks are for!).

The scheduling-class sleep function is called to set the thread wakeup priority and change the thread state from ONPROC (running on a processor) to SLEEP. The kernel's t_wchan (wait channel) pointer is set to the address of the semaphore it's blocking on, and the thread's t_sobj_ops pointer is set to reference the sem_sobj_ops structure. The thread is now in a sleep state on a sleep queue.

A semaphore is released by the sem_v() function, which has the opposite side effect of sem_p() and behaves very much like the lock release functions we've examined up to this point. The semaphore value is incremented, and if any threads are sleeping on the semaphore, the one that has been sitting on the sleep queue longest will be woken up. Semaphore wakeups always invoke one waiter at a time.
