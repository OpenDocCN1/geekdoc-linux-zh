# 2.6.1 Process Execution Time Statistics

The CPU usage work and tick processing is done on a per-CPU basis; the code loops through the list of online processors and Usage information is maintained in the cpu[] array in each CPU's sysinfo structure. The four-member cpu[] array stores an integer value, for each of USER, SYSTEM, IDLE, and WAIT—the four possible states that the CPU will be. A CPU in the QUIESCED state is charged with idle time. A CPU running an interrupt thread is charged with system time. A CPU running its idle thread is charged with idle time unless the cpu_syswait.iowait value is set; in that case, the CPU is charged with I/O time.

cpu_syswait.iowait is set in the biowait() routine, which is called from the file system support code when buffered I/O is issued (see Part Four, Files and File Systems, for specifics on buffered I/O). biowait() is also called from the drivers in the kernel; thus wait I/O reflects I/O through the file system as well as disk I/O; network I/O is not reflected. The algorithm for calculating wait I/O was reflected in releases prior to Solaris 7, and CPUs that were idle may be charged incorrectly with wait I/O time. Finally, if a thread is not the idle thread or interrupt thread is running on a CPU, the state of the thread is checked to determine if the CPU should be charged with user time or system time.

The last bullet item in the previous section indicates that some of the clock interrupt processing is not done in every interrupt (100 times a second), but rather at one-second intervals. For the services indicated, one-second granularity is sufficient.

Tick processing is done for each kernel thread (if that thread is not an interrupt handler or an operating system kernel thread) running on a CPU. Each kernel thread maintains a t_pctcpu (percent of CPU time) and t_lbolt value, where t_pctcpu is used for per-thread usage information (e.g., accounting) and t_lbolt provides a point of reference for tick processing.
