# File System I/O

We can take a look at the segmap segment on a running system by using adb the segmap segment, as shown below.

```
# adb -k /dev/ksyms /dev/mem
physmem 3b73
segmap/J
segmap:
segmap:             3000022df50
3000022df50<$seg
3000022df50: base      as
3000022df50             2a750000000 7432000
3000022df68: next      prev     104236e0
              10234a0 3000022df88 segmap_ops
3000022df80: data       3000011bd6
```

We can see that this system, the segmap segment has been created at boot as 0x7432000 bytes, or 121,839,616 bytes. This system is a 128-Mbyte Ultra-1, and we can see that free memory was smaller than the 256-Mbyte maximum segment size for the sun4 architecture. Hence, the segment was created at whatever the size of free memory was at that point. Once segmap is created, the segment interfaces are called directly from the file system code during the read and write operations.

The segmap driver divides the segment into block-sized slots that represent blocks in the files it. The segmap block size for the Solaris kernel is 8,192 bytes. A 128-Mbyte segmap segment would, for example, be divided into 128-MB/8-KB slots, or 16,384 slots. The segmap driver maintains a hash list of its page mappings so that it can easily locate existing blocks. One list entry exists for each slot in the segmap segment.
