# 15.5.2 Direct I/O with Veritas VxFS

VxFS also provides a direct I/O implementation, which by default switches on whenever the read or write size is 256 kilobytes or greater. This VxFS feature is known as discovered direct I/O.

# 15.6 Directory Name Cache

The directory name cache caches paths for vnodes, so that when we open a file that has been opened recently, we don't need to rescan the directory to find the file name again. Each time we find the path name for a vnode, we store it in the directory name cache. (See “The Directory Name Lookup Cache (DNLC)” on page 557 for further information on the DNLC operation.) The number of entries in the DNLC is set by the system-tunable parameter, nsize, which is set at boot time by the calculations shown in Table 15-2. The nsize parameter is calculated in proportion to the maxusers parameter, which is equal to the number of megabytes of memory installed in the system, capped by a maximum of 1024. The maxusers parameter can also be overridden in /etc/system to a maximum of 2048.

| Solaris Version | Default nsize Calculation |
| Solaris 2.4, 2.5, 2.1 | nsize = (17 * maxusers) + 90 |
| Solaris 2.6, 2.7 | nsize = (68 * maxusers) + 360 |

The size of the DNLC rarely needs to be adjusted because the size scales with the amount of memory installed in the system. Earlier Solaris versions have a default maximum of 17498 (34906 with maxusers set to 2048), and later Solaris versions have a maximum of 69992 (139624 with maxusers set to 2048).
