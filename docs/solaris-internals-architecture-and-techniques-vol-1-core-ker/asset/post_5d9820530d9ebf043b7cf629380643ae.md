# Figure 5.13 Anon Slot Initialized to Virtual Swap Before Page-out

It's not until the first page-out request occurs—because the page scanner must want to push a page to swap—that real swap is assigned. At this time, the page scanner looks up the vnode for the page and calls its putpage() method. The page's vnode is a vnode, and hence putpage() is called to swap this page to the swap device. The putpage() routine allocates a page-sized block of physical swap and then sets the physical vnode offset fields in the anon slot to point to the swap device. The page is pushed to the swap device. At this point we allocate swap space. Figure 5.14 shows the anon slot *after* the page has been swapped out.

When we exhaust swap space, we simply ignore the putpage() request for a page, resulting in memory problems that are hard to analyze. A failure does not occur when physical swap fills; during reservation, we ensured that we had sufficient virtual swap space, comprising both physical memory and swap space. In this case, putpage() leaves the page in memory and does not push it to physical swap. For this reason, it's often a bad idea to run with 100 percent swap allocation (swap -s shows 0 free) because we might start locking the wrong pages in memory and our working set might not match the pages we wanted in memory.

## 5.5.3 Anonymous Accounting

The amount of anonymous memory in the system is recorded by anon accounting structures. The anon layer keeps track of how anonymous pages are allocated in the anon_info structure, shown below.

```c
struct anon_info {
    int ani_max;          /* total reservable slots on phys swap */
    int ani_free;         /* # of unallocated phys and mem slots */
    int ani_phys_res;     /* # of reserved phys (disk) slots */
    int ani_mem_res;      /* # of reserved mem slots */
    int ani_locked_swap;  /* # of swap slots locked in mem */
};
```

### Header File <sys/anon.h>

The anon_info structure keeps count of the number of slots reserved on physical swap and memory. This information is used to populate the data for the swapctl system call. swapctl() provides the data for the swap command. The swap system call uses a slightly different data structure, the anoninfo structure, shown below.

```c
struct anoninfo {
    int ani_max;
    int ani_free;
    int ani_res;
};
```

### Header File <sys/anon.h>

The anoninfo structure exports the swap allocation information in a platform-independent manner. The swap command output, shown below, summarizes information from the anoninfo structure.

```bash
# swap -s
total: 108504k allocated + 13688k reserved = 122192k used, 114880k available
```

The output of swap -s can be a little misleading because it confuses the terms for swap definition. The output is really telling us that 122,192 Kbytes of virtual swap space have been used, 108,504 Kbytes of swap space are allocated to pages that have been touched, and 114,880 Kbytes are free. This information reflects the stages of swap allocation in Figure 5.15. Remember, we reserve swap as we create virtual memory, and then part of that swap is allocated when real pages are assigned to the address space. The balance of swap space remains unused.
