# Overview

In Solaris, a system class array is initialized at boot time, each entry in the array is a sclass structure, one for each of the loaded scheduling classes. The sclass structure, shown in Figure 9.3 on page 356, contains the following structure members:

+   * cl_name — Pointer to the class name (e.g., TS for timeshare).
* cl_init — Pointer to the class-specific initialization function (e.g., ts_init() for initialization of the timeshare class).
* cl_funcs — Pointer to a class functions; a kernel structure containing pointers to the class-specific functions (e.g., fork, stop, sleep, preempt.).
* cl_lock — A kernel lock for synchronized access to the class structure.
* cl_count — A counter maintaining a count of threads attempting to load the class.
* cl_size — The size in bytes of the class data maintained on a per-thread basis. The size of the structure referenced through the kernel threads t_clidata pointer.

The init routine is called at boot time for all the preloaded scheduling classes. By default, the timeshare and system classes are loaded. The interactive class is dynamically loaded when X Server and Window Manager are started. Only the real-time class is not loaded in a default environment. When a thread is set to the real-time class, with the proccnt(1) command or proccnt(2) system call, the real-time class module is dynamically loaded by the operating system. You can examine which scheduling classes are currently loaded on the running system with the dispadmin(1M) command, as shown below.

```
# dispadmin -l
CONFIGURED CLASSES
=====
SYS (System Class)
TS (Time Sharing)
IA (Interactive)
```

Or, for bit more information, there's a class function in the crash(1M) utility.

```
# /etc/crash
dumpfile = /dev/mem, namelist = /dev/ksym, outfile = stdout
> class
SLOT CLASS INIT FUNCTION CLASS FUNCTION
0 SYS 100fdd10 1042c5a0
1 TS 10137c2c 1045ef90
2 IA 10137d0c 1045f080
```
