+   - ts_quantum — The time quantum; an amount of time that this thread is allowed to run before it must relinquish the processor. Be aware that the ts_dptbl(4) manual page, as other references, indicate the value in the ts_quantum field is in ticks. A tick is a unit of time that can vary from platform to platform. On UltraSPARC-based systems, there are 100 ticks per second, so a tick occurs every 10 milliseconds. The value in ts_quantum is in ticks only if RES is 100. If RES is any other value, the default of 1000, then ts_quantum represents some fraction of a second, the fractional value determined by the reciprocal value of RES. With a default of RES = 1000, the reciprocal of 1000 is.001, or milliseconds. Thus, by default, the ts_quantum field represents the time quantum for a given priority in milliseconds.

From Table 9-2 on page 357, we see that priority 0 kthreads get 200 milliseconds (20 ticks), priority 10 kthreads get 160 milliseconds, etc. As a thread's priority gets better (higher global priority integer value), its time quantum is lower. Worse (whose) priorities get larger time quanta, since they are scheduled to run less frequently. Changing the RES value using the -r flag withdisp -c TS -q -r 100 causes the values in the ts_quantum column to change. For example, at priority 0, instead of a quantum of 200 with a RES of 1000, we have a quantum of 20 with a RES of 100. The fractional unit is different.20 tenths-of-a-second, which is the same amount of time, just represented differently [20 × .001 = 200]. In general, it makes sense to leave the RES value at the default of 1000, which makes it easier to interpret the ts_quantum field as milliseconds.

+   - ts_texp — The new priority thread is set to when it has exceeded its time quantum. From the default values in the TS dispatch table, threads at priorities 0–10 will have their priority set to 0 if they burn through their allotted time quantum of 200 milliseconds (160 milliseconds for priority 10 threads). As another example, threads at priority 50 have a 40-millisecond time quantum and will have their priority to 40 if they use up their time.

+   - ts_slipret — The return priority value. A thread that has sleeping has its priority set to this value when it is woken up. These are set so that the thread will be placed at a higher priority (in some cases, substantially higher) so the thread gets some processor time after having slept (waited for an event, which typically a disk or network I/O).
