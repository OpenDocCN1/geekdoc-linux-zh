Ensure that both swap -s “available” and swap -l “free” are nonzero.

## 7.2 Memory Monitoring Tools

To understand the memory behavior and requirements of a particular system, we need to be able to measure the activity and operation of the virtual memory system. In this section, we look at the current tools bundled with the Solaris kernel, and we discuss some other unbundled tools that allow us to look a little deeper into the virtual memory system.

We have two basic objectives in looking at Solaris memory: to find out all of the memory is allocated and to look at memory (paging) activity. Table 7-1 lists the tools we discuss and the capabilities of each.

Table 7-1 Solaris Monitoring Commands
| Tool | Location of Tool | Capabilities for Memory Utilization Reporting | Paging Activity Reporting |
| :--- | :--- | :--- | :--- |
| vmstat | /usr/bin | Basic | Systemwide only |
| ps | /usr/bin | Process size | — |
| swap | /usr/bin | Swap allocation | — |
| wsm | Engineering/free | Working set size | — |
| ipcs | /usr/bin | SysV shared memory | — |
| MemTool | Engineering/down-load | Process/file system cache | — |
| memstat | Engineering/down-load | Same as vmstat | Breakout of paging for file systems, applications, and libraries |
| pmap | /usr/proc/bin | Process address map | — |
| pmap -x | /usr/proc/bin | Process physical memory utilization, including the amount of memory shared among processes | — |
| crash | /usr/bin/crash | Kernel memory utilization | — |
| dbx | SPARCworks | Memory leaks | — |

## 7.3 The vmstat Command

The Solaris vmstat utility summarizes various functions within the virtual memory system, including systemwide free memory, paging counters, disk activity, system calls, and CPU utilization. The output of vmstat is shown below with explanations of the various fields. Let's take a look at how we can use vmstat to get a quick summary of what is happening on our system. Note that the first line of output from vmstat shows a summary since boot, followed by the output of the last 3 seconds for each additional line.

```
r = run queue length
b = processes blocked waiting for I/O
w = id processes that have been swapped at some time
swap = free and unreserved swap available, in Kbytes
free = free memory measured in pages
re = pages reclaimed from the free list
f = minor faults - the page was in memory but was not mapped
pi = pages paged in from file system or swap device
p = pages paged out to file system or swap device
fr = pages that have been destroyed or freed
de = pages freed after writes
s0-s3 = disk I/Os per second for disk 0-3
in = interrupts/second
s = system calls/second
cs = process context switches/second
us = user cpu time
s = kernel cpu time
id = id+wait cpu time

vmstat 3  memory          page          disk             cpu
```

### 7.3.1 Free Memory

vmstat example shows that we have 2,096 Kbytes of memory free, which seems low for a system with 128 Mbytes. Recall from the introduction that free memory is low because the VM system has used all of it for file system caching, which means that free memory has fallen to approximately the value of lots-free. (See "The Page Scanner" on page 178 for the meaning of lots-free.) Although free memory is almost zero, plenty of memory may still be available for applications. We will look into observe how much of our memory is being used for file system caching later when we discuss MemTool in.

### 7.3.2 Swap Space

The vmstat command reports the amount of virtual space that is free and available for reservation. This is the sum of the total amount of physical swap.

### 7.3.3 Paging Counters

The vmstat command shows the systemwide paging activity. The counters include paging from file system (anonymous memory) to file system. The fields are shown in Table 7-2.

Table 7-2 Statistics from vmstat
| Counter | Description |
| :--- | :--- |
| re | The number of pages reclaimed from the free list since the last sample. |
| mf | Minor faults - the page was in memory but was not mapped. |
| pi | The number of pages paged in from file system or swap device since the last sample. |
| po | The number of pages paged out to file system or swap device since the last sample. |
| fr | The number of pages that have been destroyed or freed since the last sample. |

### 7.3.4 Memory Usage

The pmap command shows the memory usage of a process. To ascertain how much memory is really being used, we need to look more closely at the pmap command. The output of pmap shows the address space of the process.

```
PID SIZE OFFSET SIZE ADDRESS
0000000000000000 0000000000000000 0000000000000000 0000000000000000 0000000000000000
0000000000000000 0000000000000000 0000000000000000 0000000000000000 0000000000000000
0000000000000000 0000000000000000 0000000000000000 0000000000000000 0000000000000000
...
```

The output of pmap shows the address space of the process. The pmap -x option shows the physical memory utilization, including the amount of memory shared among processes.

### 7.3.5 Memory Leaks

The crash utility is used to analyze kernel dumps for memory leaks. The dbx debugger is used to find memory leaks in programs.

The output of crash shows the kernel memory utilization. The output of dbx shows the memory leaks.
