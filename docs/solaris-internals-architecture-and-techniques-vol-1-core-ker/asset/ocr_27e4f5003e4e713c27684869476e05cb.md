As you can see from the variety of control messages provided, the implementation of process/LWP control is tightly integrated with the kernel/LWP subsystem. Various fields (user uarea), LWP, and kernel threads facilitate process management and control with proofs. Establishing process control involves setting flags and mask fields to track events that cause a process or thread to enter or exit the kernel. These events are signals, system calls, and fault conditions. The entry and exit points for these events are well defined and thus provide a natural inflection for control mechanisms.

The system calls, signals, and faults are set for the use of a set data type, where sigset_t, systet_t, and flyset_ operands have values set by the calling (controlling) program to specify the signal, system call, or fault condition of interest. A stop on a system call entry occurs when the kernel is first entered (the process), before the argument for the system call is read from the process. System call exit stops have the process stop after the return value from the system call has been saved. Fault stops also occur when the kernel is first entered; fault conditions generate traps, which force the code into a kernel trap handler. Signal stops are tested for all the points where a signal is detected, on a return from a system call or trap, and upon wakeup (see “Signals” on page 320).

Address space watch directives allow a controlling process to specify a virtual address, range (in bytes), and access type (e.g., read or write access) for a segment of a process's virtual address space. When a watched event occurs, a watchpoint trap is generated, which typically causes the process or LWP to stop, either through a trace of a FLTAWATCH fault or by an unobstructed SIGTRAP signal.
