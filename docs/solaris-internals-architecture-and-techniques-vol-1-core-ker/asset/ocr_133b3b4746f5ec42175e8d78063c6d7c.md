# Kernel Dispatcher

The thread yield (xx_yield) scenario occurs only when a yield is called programmatically in application code through thr_yield(3T). Preemption, as we mentioned earlier, means a thread is involuntarily context-switched off a processor in favor of a higher-priority thread. Once the segments shown in Figure 9.9 have completed the priority work, it's time for queue selection and insertion. Basically, four scenarios drive queue selection:
- An unbound thread whose priority is less than kpreemptpri
- An unbound thread whose priority is greater than or equal to kpreemptpri
- A bound thread whose priority is less than kpreemptpri

kpreemptpri, kernel preemption priority, is a global variable set by the kernel during initialization. The kernel sets the kpreemptpri value as scheduling classes are loaded, either during boot or when a class is loaded at some point while the system is running. By default, kpreemptpri is set to a value of 100, which is the maximum system priority (99) plus one. Any with priority equal or greater than kpreemptpri will cause a kernel preemption.

The basic, logic of queue selection goes like this:

```
if (unbound priority < kpreemptpri)
  insert on dispatcher queue for t_cpu processor
if (unbound priority >= kpreemptpri)
  insert in cp_kq_queue / systemwide kernel queue *
if (bound AND priority >= preemption)
  insert in dispatch queue of CPU thread is bound to
if (bound AND priority > kpreemptpri)
  insert in dispatch queue of CPU thread is bound to
```

When a thread is switched onto a processor for execution, the thread's cpu pointers to TS/IA threads are placed on the dispatch queue of the processor when they run, in the hopes of hitting a warm processor cache and maximizing this performance. Loose affinity maintained by the dispatcher has a time limit in the form of the rechoose interval parameter, which by default is 3 clock ticks. If more rechoose interval ticks have transpired since the thread ran, the likelihood of the thread getting a cache hit has diminished, and the next available processor is selected. rechoose interval can be set to a higher value in /etc/system and for some loads can provide some measurable improvement in performance, especially on loads that have a lot of threads with short execution times and relatively large caches. However, with anything else, you must take care if you alter the default value. Never do such a thing in a production system without having first extensively.
