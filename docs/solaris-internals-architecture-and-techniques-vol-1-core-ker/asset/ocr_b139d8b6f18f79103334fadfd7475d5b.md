The O_RSYNC flag provides for read synchronization and is used in conjunction with the O_SYNC or O_DSYNC flags. With the O_SYNC flag, file integrity (data and inode) is enforced. With the O_DSYNC flag, data integrity is enforced, meaning that any pending writes to the file are completed before the read is done. If O_RSYNC and O_SYNC are both set, pending I/Os are completed and the inode information is updated before the kernel processes the read request. A read issued on a file without any of the O_SYNC flags simply implies that a read from a buffer may be reading data that has not been written to the disks. The open(2) and fcntl(1) manual pages do not explicitly state that O_RSYNC must be used with either O_SYNC or O_DSYNC, though it is somewhat implied.

The various data flags have no corresponding flags at the inode layer. The inode maintains flags to indicate synchronous operations in the kernel file system code (e.g., ufs_read(), ufs_write()), based on the status of the O_SYNC flags in the file structure for the file. They are used by the kernel in the lower-level I/O routines. Solaris provides two library routines—fdasync(3R) and fsync(3C)—that applications can call, for data integrity synchronization, before issuing a read or write. These calls allow for per-file synchronization of data to disk, and return only when the write to nonvolatile storage has been completed.

# 11.3.2 Other File Flags

Other flags are maintained in the per-process file descriptor and the flags that are used at the file descriptor level are mostly for the operating system to use—they are not user settable.

One such flag is FEXEC: the close-on-exec flag. This flag notifies the operating system to close the file descriptor in the new process if a process executes exec(2) call. Normally, all open files are inherited by child processes, which is not always the desired behavior. The kernel implements FEXEC with a simple close_exec() kernel routine called from exec(2). close_exec() walks through the file descriptor array and closes any file with the FEXEC flag set. The fcntl(2) sets, clears, and examines the descriptor's flag field. Currently, FEXEC is the only flag that can be set, or cleared.
