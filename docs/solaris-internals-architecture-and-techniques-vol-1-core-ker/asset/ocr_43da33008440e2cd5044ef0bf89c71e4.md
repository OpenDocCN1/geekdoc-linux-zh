# The Solaris Multithreaded Process Architecture

Other interesting information maintained in the LWP include the following:

+   - lwp_pcb — The hardware context data for the LWP, called a process control block (pcb). It contains various bits of machine state information that are saved when the LWP is switched out and restored when it is switched back in. This is the machine state represented in Figure 8.2.
- lwp_ap — Pointer to the arglist passed in a system call.
- lwp_errno — Error value for current system call.
- lwp_error — Returns value for current system call.
- lwp_eys — End-of-syscall action. Used for post-system-call handling and for special conditions, such as profiling and process tracing.
- lwp_watchtrap — Supports debugger single-step operations.
- lwp_regs — Pointer to registers saved on the stack.
- lwp_fpu — Pointer to floating point unit (fpu) registers.

Most of the LWP structure members exist to support system calls and to maintain hardware context information. Remember, system calls are function calls in the kernel—a process of asking the operating system to do something on its behalf (e.g., open/read/write a file, get my PID, etc). Since LWPs are scheduled on processors (along with their corresponding kernel thread) independently of other LWPs in the same process, they need to execute system calls on behalf of the thread they're bound to. An LWP blocked on a system call does not cause the entire process to block (as long as it's a multithreaded process). See Chapter 2 for details on system call processing.

The following LWP fields handle signals and debugging through the /proc interfaces.

+   - lwp_cursig — Current signal.
- lwp_asleep — LWP sleeping in system call.
- lwp_sigaltstack — Alternate signal stack specified.
- lwp_curinfo — Pointer to a sigqueue, signal information for current signal.
- lwp_siginfo — Signal information for stop-on-fault.
- lwp_siggoldmask — Snapshot of signal mask for sig-suspend.
- lwp_scall_start — Start time of system call.
- lwp_utime — Time LWP spent running in user mode.
- lwp_stime — Time LWP spent running in system (kernel) mode.
- lwp_thread — Pointer to the associated kernel thread. Every LWP has a corresponding kernel thread.
- lwp_procp — Pointer to the proc structure.
