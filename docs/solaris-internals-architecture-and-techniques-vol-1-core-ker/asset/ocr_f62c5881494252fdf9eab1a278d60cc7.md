The kernel breaks up the linear virtual address space into segments, one for each type of memory area in the address space. For example, a simple process has a memory segment for the process binary and for the scratch memory (known as *heap space*). Each segment manages the mapping for the virtual address range mapped by that segment and converts that into MMU pages. The hardware MMU maps those pages into physical memory by using a platform-specific set of translation tables. Each entry in the table has the physical address of the page memory in RAM, so that memory accesses can be converted on-the-fly in hardware. We cover over how the MMU works later in the chapter when we discuss the platform-specific implementations of memory manage-ment.

Recall that we can have more virtual address space than physical address space because the operating system can overflow memory onto a slower medium, like a disk. The slower medium in UNIX is known as *swap space*. Two basic types of memory management manage the allocation and migration of physical pages of memory to from swap space: *swapping* and *demand paging*.
