
## 1.2. C Runtime Handles

The standard I/O environment is part of the C runtime shipped with Solaris. By default, each C program linked to the default C library (libc.so) is started with three file streams, corresponding to the terminal input and output. These file streams can be used to write and read characters from the terminal. Table 11-4 describes the file streams.

## System File/O

### Table 11-4 File Streams

| File Stream | Description |
| --- | --- |
| stdin | Terminal input stream |
| stdout | Terminal output stream |
| stderr | Terminal output stream |

By default, the standard I/O library functions such as printf write to stdout and read from stdin.

## 1.2.3 Standard I/O Buffer Sizes

Standard I/O buffers are configured by default when the file is first opened with fopen(3). The buffer size is chosen according to the characteristics of the underlying file system and the following criteria:

- If the file is a terminal, then a buffer of 128 bytes is chosen.
- If the file is a regular file, then the standard I/O library queries the file system for the suggested I/O size and sets the I/O buffer to that size.
- If the underlying file system does not indicate a preferred I/O size, then 1024-byte size is chosen.

## 11.3 System File/O

System file I/O involves the use of system calls and some library routines for reading and writing files and doing control functions such as locking. These I/O interfaces do not abstract the target of the I/O as a file stream, nor do they provide the extra level of buffering as standard I/O (stdio) interfaces. From a layering perspective, the stdio interfaces sit above the I/O system calls. The fopen(3) library ultimately calls the open(2) system call, read(3), write(2), and so on.

### 11.3.1 File I/O Calls

Once a file descriptor is established, a number of system calls can operate on the open file descriptor. The most basic system calls are the open(), close(), and write() calls. These provide the basic mechanics to perform low-level I/O to a file. For implementation specifics of the file system calls, see “The vnode” on page 533.

### 11.3.1.1 The open() and close() System Calls

The open system call does the work of converting a path name into an open file descriptor. The target file can be opened with a variety of flags, controlling how the underlying file system will perform I/O for that file descriptor. We discuss the flags controlling open modes in "File Open Modes and File Descriptor Flags" on page 485.

### 11.3.1.2 The read() and write() System Calls

The read() and write() system calls allow us to do I/O on a file by reading and writing data from the user's address space, as shown below. See "read() and write() System Calls" on page 549 for details.

```
ssize_t read(int fd, void *buf, size_t nbyte);
ssize_t write(int fd, const void *buf, size_t nbyte);
```
