# Is All That Paging Bad for My System?

To enable priority paging on a live 32-bit system, set the following with adb:

```
# adb -kw /dev/ksym /dev/mem
lotsfree/D
lotsfree: 730 - value of lotsfree is printed
cachefree/W 0t1460 <- insert 2 x value of lotsfree preceded by 0t (decimal)
dyncachefree/W 0t1460 <- insert 2 x value of lotsfree preceded by 0t (decimal)
```

cachefree/D
cachefree: 1460
dyncachefree/D
dyncachefree: 1460

To enable priority paging on a live 64-bit system, set the following with adb:

```
# adb -kw /dev/ksym /dev/mem
lotsfree/E
lotsfree: 730 <- value of lotsfree is printed
cachefree/Z 0t1460 <- insert 2 x value of lotsfree preceded by 0t (decimal)
dyncachefree/Z 0t1460 <- insert 2x value of lotsfree preceded by 0t (decimal)
cachefree/E
cachefree: 1460
dyncachefree/E
dyncachefree: 1460
```

Setting priority_paging=1 in /etc/system causes a new memory tunable, cachefree, to be set to the old paging high watermark, lotsfree, as the system boots scales with minfree, desfree, and lotsfree.

Priority paging distinguishes between executable files and regular files by recording whether they are being mapped into an address space with execute permissions. If regular files have the execute bit set when the memory system calls them into an address space, then those files are treated as executables. Be careful to ensure that data files are being memory mapped do not have the execute bit set.

Under Solaris 7, an extended set of paging counters allows us to see what type of paging is occurring. We can now see the difference between paging caused by an application memory shortage and paging through the file system. The paging counters are visible under Solaris 7 with the memstat command. The output from the memstat command is similar to that of vmstat, but with extra fields to differentiate paging types. In addition to the regular paging counters (sr, po, pi, fr), the memstat command shows the three types of paging: executable, application, and file. The memstat fields are shown in Table 15-1.
