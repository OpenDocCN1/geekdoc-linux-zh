Process groups are a subset of sessions; a session has one or more process groups associated with it. A session abstracts a process and the process's control terminal and extends the abstraction to include process groups. All the processes within a session have a common controlling terminal. Thus, all processes belong to a process group and are associated with a session. Sessions are abstracted by the session data structure, which the process links to its p_sess pointer. With process groups, sessions are inherited through the fork() code.

The control terminal is typically the login terminal user connects to logging in to a Solaris system. The phrase terminal is more than an abstraction (as opposed to an actual, physical terminal) because most sessions are network based and the terminal is a window on the screen of a workstation, implemented by one of many terminal emulation utilities (xterm, dterm, shelltool, cmdtool, etc.). Network logins login(1), telnet(1), etc. are transported through these of pseudotinals, which are software abstractions that provide terminal I/O semantics over a network link or through a window manager running the X Window System (X is the network-transparent windowing system that virtually all UNIX vendors on the planet use for their Graphical User Interface (GUI)-based workstation environments).

A control terminal is associated with a session, and a session can have only one control terminal associated with it. A control terminal can be associated with only one session. We refer to a session leader, which is the foreground process group that has established a connection to the control terminal. The session leader is usually the login shell of the user. It is the session leader that directs input sequences (job control keystrokes and commands) from the control terminal to generate signals to process groups in the session associated with the controlling terminal. Every session has a session ID, which is the PGID of the session leader.

The session abstraction is implemented as a data structure, the session structure, and some support code in the kernel for creating sessions and managing the control terminal. The session structure includes the following:

+   - The device number of the control terminal device special file

+   - A pointer to the vnode for the control terminal device, which links to the snode, since it's a device

+   - UID and GID of the process that initiated the session

+   - A pointer to a credentials structure, which describes the credentials of the process that initiated the session

+   - A reference count
