## 11.5.2. The MADV_WILLNEED Flag

The pages of a file are read, one at a time, the first time we access the location of a file that is not already in memory. This approach may be suboptimal if we know we will be reading or all of a given range, and we can use the MADV_WILLNEED flag to read ahead of a given range, as shown below.

```c
if ((addr = mmap((caddr_t)0, length, PROT_READ,
     MAP_SHARED, fd, offset)) == NULL) {
    perror("mmmap failed");
    exit(1);
}

(void) madvise(addr, length, MADV_WILLNEED);
munmap(addr, length);
```

The range requested by MADV_WILLNEED is read in synchronously, so the madvise call will wait until the entire range is read before returning. A simple test demonstrates how free memory fills as a file is read after a MADV_WILLNEED. The output of the test is shown below.

### 11.5.2.3 The MADV_SEQUENTIAL Flag

By default, the memory system reads in a file as it is allocated and leaves it in memory. The MADV_SEQUENTIAL flag can tell the memory system that a range is being accessed sequentially and can free memory behind that which is read. An example of how MADV_SEQUENTIAL can be used on a range shown below.

```c
if ((addr = mmap((caddr_t)0, length, PROT_READ,
      MAP_SHARED, fd, offset)) == NULL) {
    perror("map failed");
    exit(1);
}

(void) madvise(addr, length, MADV_SEQUENTIAL);
(void) munmap(addr, length);
```

## 11.5.2. The MADV_RANDOM Flag

By default, read-ahead is implemented on file reads (as described for MADV_SEQUENTIAL flag). In some cases, we may know that our access pattern will be random. In such cases, read-ahead offers no benefit and, in fact, additional overhead, since I/Os will be done in 64-kilobyte chunks rather than page-sized chunks (usually 8 kilobytes). We can disable read-ahead by specifying the MADV_RANDOM flag, as shown in the example.

```c
if ((addr = mmap((caddr_t)0, length, PROT_READ,
     MAP_SHARED, fd, offset)) == NULL) {
    perror("mmap failed");
    exit(1);
}

(void) madvise(addr, length, MADV_RANDOM);
(void) munmap(addr, length);
```

## 11.6 64-bit File Systems in Solaris

For many years Sun shipped systems with a maximum file system and file size of 2 gigabytes. This size was a constraint imposed by the number of bits in the offset data types in the kernel. The size limitation occurred in three main places: the disk address type, daddr_t; the file system interface, off_t data type; and the uio structure used for device drivers and some file system interfaces. The pre-Solaris 2.0 types are all 32 bits, as shown below.

```c
typedef long daddr_t;
typedef long off_t;

struct uio {
    struct iovec *uio_iov;
    int uio_iovcnt;
    off_t uio_offset;
    short uio_segfl;
    short uio_mods;
    int uio_resid;
};
```

The daddr_t and uio structures are used by device drivers and by some of the file system interfaces in the kernel, and the off_t data type is used extensively throughout the kernel and user-land programming interfaces.

### 11.6.1 64-bit Device Support in Solaris 2.0

Solaris 2.0 was implemented with partial 64-bit device support, with the aid of the 64-bit data type, long_t. Solaris 2.0 shipped with an additional disk address type (lldaddr_t), an additional offset type (loff_t), and a 64-bit-capable uio structure. The expanded disk addresses and uio structure allow device support beyond 2 GB and file systems to span the 2-Gabyte limit, to a theoretical maximum of 2³. The UFS file system in Solaris 2.x is expandable to 1 terabyte, which is a UFS-specific limitation.

```c
typedef long daddr_t;
typedef long off_t;
typedef long long offset_t;
typedef long long daddr_t;
/* <disk address> type */
/* <offset> type */
/* 
 * Partial support for 64-bit file enclosed herein,
 * specifically used to access devices greater than 2 GB.
 * However, support for devices greater than 2 GB requires compiler
 * support for long device.
 * XXX Then assume big-endian machines XXX
 */
typedef union loff {
    offset_t _f;      /* Full 64-bit offset value */
    struct {
        long long_u;
        off_t _1;
    } /* upper 32 bits of offset value */
      /* lower 32 bits of offset value */
} loff_t;
typedef union lldaddr {
    daddr_t _f;      /* Full 64-bit disk address value */
    struct {
        long long_u;
        daddr_t _1;
    } /* upper 32 bits of disk address value */
        /* lower 32 bits of disk address value */
} lldaddr_t;
```

No user interfaces in Solaris 2.0 accessed large devices, which limited device access and sizes to 2 gigabytes.
