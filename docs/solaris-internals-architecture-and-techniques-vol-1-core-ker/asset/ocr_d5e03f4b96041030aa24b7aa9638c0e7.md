# 9.2.2 Thread Priorities

The operating system uses a global priority scheme to assign priorities to kernel threads; the priorities are derived from a dispatch table according to the scheduling class it belongs to. As we see, each scheduling class has a range of priorities assigned to it. As scheduling classes load into the system, the kernel must ensure that every priority level across loaded scheduling classes has a unique priority number.

The range of priorities for the TS/IA class is 0–59, which corresponds to global priorities 0–59 since the TS/IA class is the lowest class on the system. SYS priorities range from 0–39 and are assigned global priorities 60–99 since SYS class sits directly over the TS/IA class. If the RT class is not loaded, interrupt priorities range from 0–9, occupy global priorities 100–109. Without the RT class loaded, there the interrupt thread priorities are bumped up to global priorities 160–169, and the RT global priority range is 100–159. This protocol is represented in Figure 9.2 on page 348 and Table 9-1 on page 345.

During dispatcher initialization, the kernel calculates the maximum sys priority value and the total number of priority scheduling classes as loaded. These values are recalculated if scheduling classes are loaded following initialization, for example, if the RT class is loaded sometime after the system has booted. The calculated values are stored in the system structure's v_nglobpris and v_maxsyspri field.

```
# /etc/crash
dumpfile = /dev/mem, namelist = /dev/ksyms, outfile = stdout
> v

v_nglobpris: 170
v_maxsyspri: 99
```

Newly created threads inherit their priority and scheduling class from the parent process (parent thread, actually—remember, nonreaded threads have one LWP/kthread pair). Recall from the previous chapter, the forkwp() kernel thread calls lwp_create(), which in turn calls thread_create(). thread_create() is passed as arguments a thread state (TS_STOPPED—the initial state of a thread) and priority, which is established by the calling thread. The other applicable kthread structure members are initialized toward the end of the forkwp() code, including the allocation of the class-specific data structure (e.g., tsproc). completes the setup of the dispatcher data for the new thread, initializing the class data structure for the thread and putting it on the linked list of class structures.
