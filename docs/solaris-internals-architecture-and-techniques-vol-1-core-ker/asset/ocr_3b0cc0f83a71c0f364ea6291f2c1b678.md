# 11.4.2 Kernel Asynchronous I/O

Although the threads implementation of asynchronous I/O worked well for many applications, it didn't necessarily provide optimal performance for applications that needed heavy use of the async I/O facilities. Conventional database systems, for example, use the async I/O interfaces extensively. Overhead associated with the creation, management, and scheduling of user threads motivated the design of an implementation that required less overhead and provided better performance and scalability. A review of the existing async I/O architecture and subsequent engineering effort resulted in an implementation called kernel I/O, or kaio.

Kaio first appeared in Solaris 2.4 (with a handful of revised patches) and has been available, with some restrictions, in every Solaris release since. The restrictions have to do with which devices and software support and which ones not. The good news for applications is that the presence or absence of kaio support for a combination of storage devices, volume managers, and file systems is transparent. If kaio support exists, it will be used. If it doesn't, the original library-based async I/O will be used. Applications do not change in order to take advantage of kaio. The system figures out what is available and enters the appropriate code path.

What kaio, as the names imply, is implement async I/O inside the kernel rather than in user-land with user threads. The basic sequence of events is:

+   - When an application calls aioread(3) or aiocwrite(3), the corresponding library routine is entered.

+   - Once entered, the library routine first tries to process the request with kaio. A kaio initialization is executed and creates a "cleanup" thread, which is intended to ensure that no remaining memory segments have been allocated but not freed during the async I/O process.

+   - Once that is complete

Support for kaio requires specific async I/O read and write routines at the device-driver level. The Solaris kernel provides this support in the SCSI driver for all currently shipping Sun storage products and the Solstice DiskSuite (SDS) device drivers. These products include the fiber-based storage products, which implement the SCSI protocol over the Fibre connect.

Kaio only works when the target of the async I/O is a character device-special file. In other words, kaio only works on raw disk I/O. Additional support has been added with the host-based volume management software for creating RAID volumes on SPARC/Solaris servers: Sun Enterprise Volume Manager, based on Veritas, and Solstice DiskSuite.
