# Header File <sys/ts.h>

The RES and PRI parameters are not defined in tsdpent. Those fields, along with the defined members in the structure table, are described below.

+   * RES — (resolution value) Interprets the ts_quantum column in the dispatch table. The reciprocal of RES determines the level of granularity in which the ts_quantum field will be displayed. As the value of RES increases, the ts_quantum column values also increase by the same order of magnitude. See ts_quantum for more information.
* PRI — The class-dependent priority, the systemwide global priority. The PRI column is derived as the row number in the dispatch table. The dispatch table is like any generic table—it has rows and columns. Every row corresponds to a unique priority level within the scheduling class, each column in the row contains values that determine the priority adjustments on the thread running at that particular priority. This is not the same as ts_globpri.
* ts_globpri — The only parameter (tdpent structure member) that is not displayed in the output of the dispatch(IM) command and the only value that is not tunable. ts_globpri is the class-independent global priority that corresponds to the timeshare priority (closest farthest the right).

A given scheduling class within Solaris has a range of priorities beginning with 0, which represents the lowest priority for that class. The TS and IA classes have 60 priorities, range 0–59. The kernel implements a global priority scheme, that every priority level available in every scheduling class can be uniquely identified with an integer value. Refer to Figure 9.2 on page 348 for a list of priorities when all the bundled scheduling classes are loaded.
