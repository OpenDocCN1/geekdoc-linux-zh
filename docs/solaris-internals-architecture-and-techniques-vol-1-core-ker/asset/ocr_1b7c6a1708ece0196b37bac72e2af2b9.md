# 13.4.1 Memory Mapped I/O

A request to memory-map a file into an address space is handled by the file system vnode method vop_map() and the seg_vn segment driver (see "The seg_map Segment" on page 549). Process requests that a file be mapped into its address space. Once the mapping is established, the address space represented by the file appears as regular memory and the file system can perform I/O by simply accessing that memory.

Memory mapping of files hides the real world of reading and writing the file because the seg_vn memory driver quietly works with the file system to perform the IOs without the need for process-initiated system calls. I/O is performed, in units of pages, upon reference to the pages mapped into the address space; reads are initiated by a memory access; writes are initiated by the VM system finds dirty pages in the mapped address space.

The system call mmap() calls the file system for the requested file with vop_map() vnode method. In turn, the file system calls the address space function for the current address space, and the mapping is created. The flags passed into the mmap() system call are reduced to the subset of all file permissions. If mandatory locking is set for the file, then mmap() returns an error.

Once the mapping is created in the process's address space, file pages are read when a fault occurs in the address space. A fault occurs the first time a mapped segment is accessed because at this point, no physical page of memory is at that location. The memory management unit causes a hardware trap for that memory segment; the memory segment calls its fault function to handle the I/O for that address. The segvn_fault routine handles a fault for a file mapping in a process address space and then calls the file system to read the page for the faulted address, as shown below.
