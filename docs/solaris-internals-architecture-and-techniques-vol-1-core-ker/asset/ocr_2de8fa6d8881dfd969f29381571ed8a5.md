The number of kernel interfaces to the sleep queue facility is minimal. Only a few operations are performed on sleep queue: the insertion of a kernel thread on a sleep queue (putting a thread to sleep), the removal of a thread from a sleep queue (waking a thread up), and traversing the sleep queue in search of a kernel thread. There are interfaces that for waking up one thread or all threads sleeping on the same condition variable.

Insertion of a kthread involves either indexing into the sleepq_head array to find the appropriate sleep queue specified by the condition variable address, traversing the list, checking priorities along the way to determine the proper insertion point. Once the appropriate sublist has been found (at least one kernel thread at the same priority) or it has been determined that no other threads on the sleep queue have the same priority, a new sublist is started, the kernel thread is inserted, and the pointers are set up properly.

The removal of a kthread either involves searching for and removing a specific thread that has been specified by the code calling into sleepq_dequeue()` or sleepq_unsleep()`, or waking up all the threads blocking on a particular condition variable. Waking up all threads or a specified thread is relatively straightforward: hash to the sleepq_head array specified by the address of the condition variable, and walk the list, either waking up or searching for a particular kthread and the targeted thread. In a single, unspecified kthread needs to be removed, the code implements the list as a FIFO (First In, First Out), so the kthread that has been sleeping the longest on a condition variable will be selected for wakeup.
