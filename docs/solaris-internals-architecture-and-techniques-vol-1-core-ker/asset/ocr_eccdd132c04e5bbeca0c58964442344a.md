# Turnstiles and Priority Inheritance

+   - If threads (at least one other) are already waiting for the mutex, the address of the turnstile that has already been allocated for the mutex is retrieved with the tstile pointer() function, which uses the turnstile ID in the waiters field of the lock to locate the turnstile in the tsm_chunk array.

With a turnstile for the lock now ready, we can proceed with changing the thread state to sleep and setting up the sleep queue with the turnstile.

+   - The kernel t_block() function is called and invokes the CL_SLEEP macro.
- Scheduling-specific functions are invoked by macros that resolve to the proper function, based on the scheduling class of the kernel thread. In the case of a timeshare or interactive class thread, the ts_sleep() function is called to set the thread's priority to a SYS priority (a priority boost for when it wakes up—it will run before other timeshare and interactive class threads) and to set the thread state to TS_SLEEP.
- The kernel's t_chan field (wait channel) is set to the address of the lock it is waiting for, and the thread's t_sobj ops pointer is set to the lock's synchronization object vector ("Synchronization Object Vector" on page 70).
- Finally, the thread's t_ts is set to the address of the turnstile, and the thread is inserted into the turnstile's sleep queue.

The generic kernel sleep queue functions are invoked indirectly through macros defined in the turnstile header file; for example, insertion of the sleep queue is done through the TSTILE_INSERT macro, which calls the kernel sleepq_insert() function.

+   - When sleepq_insert(), the kernel resides in the sleep queue associated with the turnstile. A thread can be blocked only by one, and no more than one, synchronization object at any time, so t_ts is either a NULL pointer or a pointer to one turnstile.

All that remains to be done is the priority inheritance check to determine if the thread holding the lock is at a lower (worse priority) priority than the thread requesting the lock (the one that was just placed on a turnstile sleep queue).

+   - The kernel willto() is called to check the priority of the lock owner against the thread waiting.
- If the owner priority is greater than the waiter priority, we do not have a priority inversion condition and the code just bails out.
- If the waiter priority is greater (a better priority) than the owner, we do have a priority inversion condition; then the lock owner is set to the priority of the waiter.
