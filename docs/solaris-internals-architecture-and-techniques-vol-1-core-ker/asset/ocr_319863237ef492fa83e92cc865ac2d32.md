# 11.6.1 64-bit Device Support in Solaris 2.0

Solaris 2.0 was implemented with partial 64-bit device support, with the aid of the 64-bit data type,long_t. Solaris 2.0 shipped with an additional disk address type (lldaddr_t), an additional offset type (loff_t), and a 64-bit-capable uio structure. The expanded disk addresses and uio structure allow device support beyond 2 Gbytes and file systems to span the 2-Gabyte limit, to a theoretical maximum of 2³. The UFS file system in Solaris 2.x is expandable to 1 terabyte, which is a UFS-specific limitation.

```
typedef long daddr_t;
typed long off_t;
typed longlong_t offset_t;
typed longlong_t daddr_t;
/* <disk address> type */
/* <?offset> type */
/
* Partial support for 64-bit file enclosed herein,
* specifically used to access devices greater than 2 GB.
* However, support for devices greater than 2 GB requires compiler
* support for long device.
* XXX Then assume big-endian machines XXX
typed union loff {
    offset_t _f;      /* Full 64-bit offset value */
    struct {
        long_u;
        off_t _1;
    } /* upper 32 bits of offset value */
      /* lower 32 bits of offset value */
} loff_t;
typed union lldaddr {
    daddr_t _f;      /* Full 64-bit disk address value */
    struct {
        long_u;
        daddr_t _1;
    } /* upper 32 bits of disk address value */
        /* lower 32 bits of disk address value */
} lldaddr_t;
```

No user interfaces in Solaris 2.0 accessed large devices, which limited device access and sizes to 2 gigabytes.

# 11.6.2 64-bit File Application Programming Interfaces in Solaris 2.5.1

With databases growing to over 1 terabyte in size and single disk devices growing past 2 gigabytes, application vendors required a mechanism to access data sizes beyond 2 gigabytes. Full, large-file support was destined to appear in Solaris 2.6, but in Solaris 2.5, two interfaces were added to provide large-device support for raw devices. While this may not have seemed like a significant addition, many database vendors use raw devices for storage for database tables. The large-device interfaces enable database vendors to address more than 2 gigabytes of space on raw devices.
