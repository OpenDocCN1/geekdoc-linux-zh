# Solaris threads

Solaris threads provide the thr_sigsetmask(3T) and pthread_sigmask(3T) interfaces for establishing per-user thread signal masks. The disposition and handlers for all signals are shared by all the threads in a process, such that a SIGINT (for example), with the default disposition in place, will cause the entire process to exit. Signals generated as a result of a trap (SIGPE, SIGILL, ...) are sent to the thread that caused the trap. Asynchronous signals, which are all signals not defined as traps, are delivered to the first thread that is not blocking the signal.

The difficulty in implementing semantically correct signals in the Solaris environment arises from the fact that user-level threads are not visible to the kernel; however, the low-level kernel signal code has no way of knowing which threads have signals blocked and, therefore, no way of knowing which signal should be sent to. Some sort of intermediary phase needs to be implemented: something that had visibility both to the user thread signal masks and to the kernel. The solution came in form of a special LWP that the library create creates for programs that are linked to libthread; this LWP is called the aslp (it's actually an LWP/thread pair; remember, they always travel in pairs). The implementation of the aslp extends the traditional signal generation and delivery phases, by adding two additional stages: notification and redirection.

Generation -> Notification -> Delivery

Sending a (generation) to a process causes the aslp to look for a thread that can take delivery of the signal. Once a thread is located, the signal is redirected to that thread and can then be delivered. The exception to this rule is the sending of synchronous or trap signals (listed in Table 8-8). A trap signal, such as SIGSEGV, is not channeled through the aslp, but rather delivered to the LWP/thread that caused the trap, and from there to the user thread.
