#  14.2.6 UFS Block Allocation

UFS uses block sizes of 4 and 8 Kbytes, which provides significantly higher performance than the 512-byte blocks used in the System V file system. The downside of larger blocks was when partially filled blocks occurred, several kilobytes of disk space were wasted. To overcome this disadvantage, UFS uses the notion of file system segments. Fragments allow a single block to be broken up into 2, 4, or 8 fragments when necessary.

UFS allocation tries to prevent excessive disk seeking by attempting to co-locate nodes within a directory and by attempting to co-locate a file's index and its data blocks. Where possible, all of the nodes in a directory are allocated in the same cylinder group. This scheme helps reduce seeking when directories are traversed; for example, executing a single 1s -1 of a directory will access all of the nodes in that directory, and if all the nodes reside in the same cylinder group, most of the data will be cached after the first few files are accessed. A directory will be placed in a cylinder group different from that of its parent.

Blocks are allocated to a file sequentially, starting with the first 96 Kbytes (the first 12 direct blocks), skipping to the next cylinder group and allocating blocks up to the limit by the file system parameter maxblocks, maximum-blocks-per-cylinder. After that, blocks are allocated from the next available cylinder group.

By default, a file system greater than 1 Gbyte, the algorithm allocates 96 Mbytes in the first available cylinder group, 16 Mbytes from the next, and so on. The maximum cylinder group size is 54 Mbytes, and the allocation only one-third of that space to be allocated to each section of a single file when it is extended. The maxblocks parameter is to 2,048 8-Kbyte blocks by default at the time the file system is created; it is also tunable but can only be tuned downward, since the maximum cylinder group size is 16-MB allocation per cylinder group.

Selection of a new cylinder group for the next segment of a file is governed by a rotor and free-space algorithm. points to the cylinder groups; each new disk space is allocated, it starts with the cylinder pointed by the rotor. If the cylinder group has less than average free space, it is skipped and the next cylinder group is tried. This algorithm makes the file system attempt to balance the allocation across the cylinder groups.
