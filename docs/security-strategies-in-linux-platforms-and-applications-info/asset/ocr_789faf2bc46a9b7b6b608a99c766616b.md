# System Authentication Logs

Suspicious logins as regular users should cause concern. One thing that could cause more concern is suspicious use of the root administrative account with related commands such as su and sudo. As described in Chapter 12, authentication logs are associated with the auth and auth facilities configured in the system logging or RSyslog services. The log files in the specified system logging or RSyslog service configuration should contain information on all login attempts, including the following:

+   * Remote access—Remote from any system is logged by IP address, service, and port number.
* Administrative access—Local access with the su or sudo commands is logged with either the root user ID of 0 or the associated user = root environment variable.
* Administrative jobs—Access by services that require administrative privileges, such as a cron job or an e-mail transmission from Postfix, may also be logged.

# Monitor Behavior for Security Issues

One reason average Linux user is more knowledgeable is that Linux users are more likely to experiment with their systems. On a corporate network, it may be appropriate to look for the signs of such behavior in user home directories. If a user has downloaded source code on his or her system, they may have already compiled that code into a binary program of some sort. In that case, there will be files in the tree of the user's home directory with executable privileges.

Of course, such checks are subject to organizational policies. In general, it's best if users know about such checks before they're performed so they are aware of the expectations with respect to behavior. And such checks may not be reasonable if users are in fact Linux developers or testers.
