# PART 3 | Building a Layered Linux Security Strategy

A baseline configuration includes more. It includes the current network state of the system, the interfaces that are used, the firewalls that are configured, the ports that may be open, and on. Of course, one exception is based on key network settings—specifically the IP address and hostnames of each system.

Finally, a baseline configuration includes information on how the system runs. Information is more subjective. But based on a given hardware configuration, a baseline system could be expected to run within certain parameters. The following sections will help you define a baseline system in all of these areas.

# Collect a List of Packages

Perhaps the simplest tool for a baseline system is based on the governing package-management command. For example, the following command includes all packages currently installed on a Red Hat system:

Red Hat systems include a list of packages included in the installation, the /root/install.log file. Ubuntu does not have an equivalent file, although it is relatively easy to create with one command like dpkg -1 install.log.

```
# rpm -qa
```

Look at the output. It includes version numbers for each package. If saved to a file, you could use it in the file to identify changes in the list of installed packages over time.

A similar list of packages is available in Ubuntu systems, using the following command:

```
# dpkg -l
```

While the output of the noted dpkg command includes a bit more information, that output can also serve as a database. If saved to a file, you could also use that database to derive the differences in lists of installed packages at different dates.

Of course, if you've started with a gold baseline and installed a service such as the Samba web server, you'd expect the differences to include related packages. But any additional packages that are not the result of a dependency, an update, or a security issue are should be suspected.

# Compare Files, Permissions, and Ownership

One thing by integrity scanners is to check the status of files compared to a baseline. On any Linux system, some files are expected to change. Change all the time. That is normal. But to key files such as the Linux kernel, modules, configuration files, and service scripts may be a problem. Generally, files in these categories can be divided into stable and unstable directories.

Even so, some changes to files in stable directories can be explained. Administrators may change configuration files. Security updates can change the kernel. The installation of new services can add files to stable directories.
