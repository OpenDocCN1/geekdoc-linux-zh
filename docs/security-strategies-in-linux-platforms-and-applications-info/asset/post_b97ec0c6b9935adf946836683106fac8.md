# Test with the Advanced Intrusion Detection Environment (AIDE)

As with Tripwire, AIDE supports periodic checks of installed and configured files. AIDE was first discussed in Chapter 12. This section goes into a bit more depth on how AIDE works, based on information in the aide.conf configuration file. The configuration for Ubuntu and Red Hat systems can vary somewhat. Of course, the details are subject to change, especially if the developers behind one decide that the approach of the other is better.

In either case, AIDE rules are defined with attributes as described in Table 13-3. Some developers consider AIDE to be superior to Tripwire. In fact, AIDE packages are available from the main Ubuntu repository and Red Hat Enterprise Linux (RHEL) repositories. The installation of AIDE is supported at least in some ways for both distributions.

# Ubuntu AIDE

When installed on Ubuntu systems, AIDE is configured in files in the /etc/aide/ directory. In addition, by the /etc/default/aide file, configuration options for individual services are defined in files in the /etc/aide/aide.conf.d/ directory. While the basic database files are similar, AIDE's version includes directives with combinations of default codes in the /etc/aide/aide.conf file.

For example, the following directive suggests that AIDE can use a variety of checksums for every file. Each of the options is listed in Table 13-3.

```bash
Checksums = md5+sha1+md5160+haval+ gost+crc32
tiger-whirlpool
```

The OwnerMode directive that calculates the permissions, user owner, and group for all files configured:

```bash
OwnerMode = p+u+g
```

The Size directive is applied to files where a constant size can help determine whether there has a change with respect to the size and block count of:

```bash
Size = s+b
```

Additional directives in the aide.conf file describe additional directives that are applied in files in the /etc/aide/aide.conf.d/ directory.

# Table 13-3 AIDE rule codes.

| CODE | DESCRIPTION |
|---|---|
| p | Permissions: read, write, execute |
| i | Inode: labeled location on a volume or partition |
| n | Number of links |
| u | User |
| g | Group |
| s | Size |
| b | Block count |
| m | Modification time; the last time ownership or permissions changed |
| a | Access time; the last time the file was read or otherwise accessed |
| c | Change time; the last time the file was changed |
| S | Label for files expected to change in size, such as log files |

## Red Hat AIDE

In contrast, the Red Hat AIDE configuration is somewhat self-contained in the /etc/aide.conf file. The directives defined are somewhat different and are in some ways cumulative. The R directive here defines a group of codes, as defined in Table 13-3.

```bash
R: p+i+n+u+g+s+m+c+acl+selinux+xattrs+md5
```

This group is inserted in the value of the NORMAL directive here, which incorporates a couple of checksum hash functions.

```bash
NORMAL = R-rmd160+sha256
```

The directive that follows essentially creates a DIR directive equivalent to the R group of codes:

```bash
DIR = p+i+n+u+g+acl+selinux+xattrs
```

Some files could just be checked for access controls, as associated with the PERMS directive defined here. This directive essentially is a check of regular discretionary access permissions, ownership, ACLs, and SELinux contexts:

```bash
PERMS = p+i+n+u+g+acl+selinux
```
