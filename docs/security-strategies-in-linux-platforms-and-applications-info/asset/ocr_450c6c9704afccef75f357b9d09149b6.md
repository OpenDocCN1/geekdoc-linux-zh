# Penetration Testing Tools

The developers behind testing tools such as System Administrators Integrated Network Tool (SAINT) and Nessus, described in Chapter 13, constantly update their databases of security issues. If you subscribe to one of these services and keep up to date with your updates, it'll go a long way keeping your networks up to date with the latest security issues.

Of course, the open source command is nmap, "The History and Future of Nmap" at http://nmap.org/book/history-future.html suggests developments will be centered on related scripts, which are described Chapter 9 of Fyodor's book on the subject at http://nmap.org/book/nse-usage.html. That is built on Nmap version 5.0 which is included in both RHEL 6 and Ubuntu Linux releases.

Scripts associated with nmap command are stored in /usr/share/nmap/scripts/ directory. Because new scripts are written frequently, you may want to download them from the associated Subversion repository, which is different from standard package repositories. One method, as described by one of the nmap developers, David Field, is based on the following commands, which download the latest nmap information in the local nmap/subdirectory. The current list of scripts can be found in the nmap/scripts/subdirectory.

```
$ sv co --username --password
  "" sv://svn.insecure.org/nmap
```

If the sv command is not recognized, you'll need to install the subprocess package. If you prefer to use the latest nmap software installed of that available for your distribution release, you can run the .configure and make commands in the nmap/subdirectory. The noted command built its own version of the nmap command in the nmap/subdirectory. The version available from the nmap Repository may is a beta, so full testing of that may not be complete.

This may be a case where it makes sense to install a later version of a software package, even a beta, before it's made available for a distribution to help discover security flaws as soon as possible. However, the cautions earlier in this chapter about third-party software do apply.

Once installed, you can run one of the 100 scripts listed at http://nmap.org/nsedoc., assuming those scripts are available in the aforementioned /usr/share/nmap/scripts/directory. For example, the following command checks for recursion on the noted Domain Name Service (DNS) server:

```
# nmap --script=dns-recursion 192.168.100.101
```

For information on various nmap scripts, see Chapter 13.

# Single Sign-On

One more important area for development in Linux security is the single sign-on. It's hard enough for regular users to remember username and password. When they're asked to remember multiple usernames and passwords and then change them frequently, users may revolt.
