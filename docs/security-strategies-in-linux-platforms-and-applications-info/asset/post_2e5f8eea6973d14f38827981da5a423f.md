
# CHAPTER 13 Testing and Reporting

There is risk involved. Black-hat hackers could somehow included their code in the packages released for a distribution. They may have penetrated the mirror servers from where many Linux distributions are downloaded and updated. They may take advantage of security issues before you're about to update a default system with fixes.

But there are safeguards. Open source developers test their software in the public eye. The source code is publicly available. If there are security issues, a great majority is revealed in the public testing process. Any issues that this process produces are publicized as soon as they are known by the community.

There are safeguards on the mirror servers that carry Linux distributions. Downloads with commands like yum and apt get GNU Privacy Guard (GPG) keys to ensure the integrity of a downloaded package. If you trust certain groups of developers, one option is to use security tools already included with live boot media.

# Some Tools Already Available on Live CDs

One excellent option for security tools is live boot media, such as CDs, DVDs, and USB keys. Perhaps the model for live media for Linux systems is the Knopix distribution. The operating system can be booted directly from a CD/DVD drive or even a downloaded ISO file is impressive. With the tools on the Knopix distribution, you can back up or recover troubled media. Even Nessus is included on the Knopix DVD as version of 6.2.

One impressive option for live DVD media is Ubuntu Pentest. It includes about 300 tools for penetration testing. Some of the tools for testing DNS servers are shown in Figure 13-10. While it is based on the Ubuntu distribution, the developers behind Ubuntu Pentest are not affiliated with Ubuntu or Canonical. It includes tools for port scanning, virtual private network probing, database testing, and more.

# Best Practices: Testing and Reporting

When testing a Linux system, it's important to test every part of a layered defense. Because some tests may require temporarily disabling defenses, it's appropriate to withdraw a system from production before running tests. Open ports on a system should appear different inside a firewall from outside. Tests of TCP Wrappers depend on the rules configured in the /etc/hosts. A low and /etc/hosts deny files. Tests of some services may be specific to the limitations configured within the configuration for that service. Tools such as the John Ripper help identify passwords that are too simple. Be sure to re-enable any disabled services after tests are complete.

Services aren't accessible over open network ports. It's important to know what network ports are open on local systems to make sure that the only ports that are open are those required for local services. Tools that can help check for network ports include telnet, netstat, lsof, and nmap. The nmap command is especially versatile, as it can scan different ports, protocols, and operating systems on a variety of targets.

Several tools can help you check for unauthorized changes to key files. The rpm -Va and debsums command checks them against installed files. Because even normal changes to configuration files are highlighted, more precise tools are needed. Two options to that are de Tripwire and AIDE.

Some systems have so many security rules, they're too difficult for people to use. That can lead to security problems. For example, when password policies are too strict, users who have trouble remembering their exotic passwords may write them down at their workstations. Password policies can be managed with the change command; access can be regulated with the PAM files.

Several options are available for virtual machine hardware, from VMware to Virtualbox. The emerging standard for an open source virtual machine manager is KVM. While such virtual machines use large files that simulate hard disks, the contents of these files change frequently. So intrusion detection tools are important to monitor the integrity of such systems.

A variety of open source tools are available for security testing. Some of the major open source tools include Wireshark, Snort, and netcat. Snort includes modes for packet sniffing, packet logging, IDS, and inline interaction with the iptables command. The netcat command, can identify a lot of information about open ports and the servers behind them, which highlights configuration issues with different services.

A variety of commercial security testing tools are also available. Two options originally based on open source are NESSUS and SAINT. Both tools include Web-based interfaces, with reports that identify security issues by service, port, and more.
