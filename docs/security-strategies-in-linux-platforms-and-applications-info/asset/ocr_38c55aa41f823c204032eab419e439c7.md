# Additional vsFTP Configuration Files

Two other configuration files are used directly for the vsFTP service: ftpusers and user_list. The list of users in these service is based on the default set of service users. In other words, it includes users with user IDs (UIDs) below 100, 500, or 1000, depending on the distribution. If a black-hacker breaks into one of these accounts, he may be able to obtain administrative privileges (or more) through these accounts. These files can help prevent black-hackers from using these privileges at least on the vsFTP server.

If more services are installed on the local system, you may see additional service users in the shadow password suite. In that case, you should add those users to the appropriate files. Red Hat systems specifically cite /etc/vsftpd/ftusers in the pluggable authentication module (PAM) configuration file, /etc/pam/vsftpd.

> Security Enhanced Linux (SELinux) provides additional protection for vsFTP. Directories shared with FTP servers should be labeled with the public_content_t type. If you use a directory for uploads, you'll need to configure that directory with the public_content_rw_t type. The same options work for directories associated with rsync servers.

# Linux as a More Secure Windows Server

In Chapter 5, you will read how Linux can share specific directories using Samba. This section focuses on the global settings associated with Samba, including how it can be set up as a Primary Domain Controller (PDC), or its cousin, the Backup Domain Controller (BDC). With the right options, the PDC database of usernames and passwords can be maintained on a Linux server.

Samba is the Linux implementation of Microsoft's Server Message Block protocol. As this evolved into the Common Internet File System (CIFS), Samba has kept pace. As case generally does not matter at the Microsoft command line, the value given to most Samba directories can be upper or lower case. For example, security = USER works as security = user.

Not all Samba directives are described in this book. For a more complete list, see the Samba documentation at http://www.samba.org/samba/man/pages/3/conf.html. When Samba 4 is officially released, there will likely be some more added options.

Administrators who believe in Linux are likely to accept that a Windows system, if substituted for a Linux system, is more secure. Some professionals may disagree with that assessment. However, Linux systems maintained as PDCs are more secure, as Samba developers monitor and maintain services while Windows developers no longer do so.

> Because PDCs are on the Microsoft Windows NT 4 Server operating system, Microsoft has not supported PDCs on networks. However, PDC on Linux servers configured with the Samba server are still supported. As long as Windows XP clients are supported, Microsoft should support those systems as PDC clients. However, since this is a book on Linux, no claims are made with Microsoft security support.
