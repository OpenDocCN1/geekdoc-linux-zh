If you wanted to limit user michael to 1 GB of space and 10,000 files, you could set up the following quotas:

Disk quotas for user michael (uid 500):
| Filesystem | blocks | soft | hard | inodes | soft | hard |
| /dev/sda2 | 698172 | 1000000 | 0 | 305 | 10000 | 0 |

In this case the soft limit becomes the implicit hard limit. But that is not you want to do unless the rules are crystal clear. After all, people make mistakes. You may want to set hard limits as well, with a number higher than the soft limit. One example is shown here, where the hard limit is 10 percent over the soft limit:

| Filesystem | blocks | soft | hard | inodes | soft | hard |
| /dev/sda2 | 698172 | 1000000 | 1100000 | 305 | 10000 | 11000 |

A user is allowed to exceed the soft limit for a grace period. Once the changes are saved, you can review the current grace period with the -t command. The result is shown in Figure 5-3 and is almost self-explanatory. The default grace period is seven days. A user is allowed to exceed the soft limit, but not the hard limit, for those seven days. After the grace period has passed, the user has to be back under the soft limit or that user will no longer be able to write to disk. You can change the grace period as shown, in hours, minutes, or seconds.

If you're satisfied with the limits set on the first user, you can copy those quotas to other users. The following command uses the quota configured for user michael as a (-p) prototype for the users in the following list:

```
# edquota -up michael kim mike larry
```

If youve set up quotas for one group and transfer those same quotas to more groups, the command would be similar. The following command uses the quota set for group 1 and copies them for the groups group2 and group3:

```
# edquota -gp group1 group2 group3
```
