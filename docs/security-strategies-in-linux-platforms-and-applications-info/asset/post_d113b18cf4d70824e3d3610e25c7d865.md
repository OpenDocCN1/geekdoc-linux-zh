
## CHAPTER 3 | Basic Security: Facilities Through the Boot Process

## The Costs and Benefits of Obscurity

In some ways, obscurity is the antithesis of open source. Obscurity may be as simple as a label, such as the labeling of an Apache server as a Microsoft Web server. Obscurity can also be more complex—something that requires special options for both client and systems on a network. The belief is that obscurity can help in a "defense in depth" scheme, which can make it more difficult for a black-hat hacker to gather information about your system. In many cases, however, obscurity doesn't provide much of an obstacle. The question is whether the configuration required to put obscurity into practice is worth the trouble. In fact, most security professionals now use the "security through obscurity" as a derogatory phrase for systems or practices that depend upon the obscurity of their mechanism.

Now for more specifics. You'll look at obscurity in four areas. First, there's boot hardware. The hardware doesn't have to be "real"; virtual machines, the boot hardware is virtual. Also, boot hardware varies with the boot process, with messages that are transmitted or hidden from the screen. Obscurity goes further in configuration files, as options in boot files make it difficult for a black-hat hacker to understand the configuration of a system. Administrators can make life difficult for black-hat hackers by using nonstandard ports for services.

## Obscurity in the Boot Menu

Just as security starts with the boot process, so does obscurity. Many modern systems are configured by BIOS/UEFI menus as quickly as possible. Unless you know the magic key, you can't display these menus. Basic options with these menus enhance security include the following:

- Hiding boot screens
- Password protecting BIOS/UEFI menus
- Changing the boot order to avoid automatic booting from floppy, CD/DVD, USB, and other ports own- Disabling external ports

Of course, these options may not be available in BIOS/UEFI menus. Some of these options are relatively simple to bypass. Nevertheless, every obstacle presented to black-hat hackers will slow down time, which may allow security options to alert personnel. Obscurity in the boot process makes things more difficult for administrators who need access to such menus. If appropriate, you can use system like the baseboard management controller (BMC) to access and administer the boot menu from remote locations. While it's certainly convenient to access such systems remotely, it's also a security risk because it is not. Special passwords in the boot menu should be kept secure.

## Obscurity in the Linux Boot Loader

Obscurity in a Linux system goes a bit further. As described earlier in this chapter, the menu associated with GRUB or LILO can be hidden. Furthermore, boot loader configuration files can also hide important details such as the root directory. For example, the following entry from an older GRUB configuration file clearly identifies the root directory:

```
kernel /vmlinuz-2.6.24-generic.x86_64 root=/dev/sda2 ro splash
```

In contrast, the following alternatives from two different GRUB configuration files obscure the location of the root directory:

```
kernel /vmlinuz-2.6.24-generic.x86_64 root=UUID=d7bbf43a-4099-8ffaabb86db ro splash
kernel /vmlinuz-2.6.18-53.4.5 root=LABEL=/root quiet
```

In both cases, the root directory is obscured. The Universal Unique Identifier (UUID) number in the first line was created with the `uuid` command. The LABEL in the second line was created with the `e2label` command. The LABEL is connected to the filesystem information for the volume. You can check the information for a volume as /dev/sda2 with `dum2fs`.

Older Linux distributions display boot messages. Those boot messages include services that are started with the operating system. Every active network service on a system is a potential surface of attack. Standard boot options on Linux distributions hide or obscure those boot messages with the quiet device shown with each of the kernel commands.

Obscurity in the Linux part of the boot process means administrators know more. The process for accessing the boot menu must be well documented. How many people know the shift key to access the GRUB2 menu? Overall, the costs of obscurity in the boot loader are small.

## Obscurity in Other Linux Boot Configuration Files

Other Linux configuration files matter in the boot process. Perhaps the most important of these is /etc/fstab, which specifies how volumes such as partitions, redundant array of disks (RAID) arrays, or logical volumes are to be mounted. Figure 3–4 shows an Ubuntu installation with UUIDs. In the /etc/fstab file shown, UUIDs are used to identify the volumes associated with certain directories.
