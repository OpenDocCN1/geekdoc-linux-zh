
# CHAPTER 5 | Filesystems, Volumes, and Encryption

The right filesystem format can also protect the system in case of a break-in. Journaling filesystems such as ext3, ext4, xfs, and reiserfs can speed recovery in case of problems. However, journaling takes extra space and may therefore be unnecessary for smaller filesystems.

In Linux, you can encrypt individual files, directories, and entire filesystems. Encryption tools can be split into user-space and kernel-space tools. Three of many available Linux encryption tools are gpg, ecryptfs, and cryptsetup. In this chapter, you will see how to use these tools to encrypt files, directories, and filesystems, respectively.

Local file and folder permissions provide one level of discretionary access control. The associated read, write, and execute permissions apply to the file's user owner, group owner, and all other users. You can change ownership with the chown and chgrp commands. You can change permissions with the chmod command.

File and folder permissions differ when shared over a network. In fact, file and folder permissions that you may not work as they may be overridden by the configuration of the network sharing service. NFS sharing has other security issues, unless you use NFSv4 with Kerberos-based authentication. Shared directories include a number of options for configuring how files are shared. Directories shared with the vsFTP daemon service can be protected with a chroot jail.

If a black-hat hacker compromises one of your systems, quota limit damage. Quotas can limit the amount of space or nodes taken by a user or group. You can configure hard and soft limits in each category, buffered by a grace period. You can review what users and groups do with regular quota reports.

With ACLs, you can take discretionary access controls to another level. ACLs can be configured using the same files and commands as quotas. Once configured, you can review current ACLs with the getfacl command. If you configure ACL rules for a specific user, you can further access to key files and directories to other users.

# Basic Bastion Hardening

A bastion server is configured to minimize the risk that a black-hat hacker can compromise any systems. The ideal bastion server is used for a single purpose. Generally, it'll have two open ports—one for the service, one for the remote connection. When properly configured, a bastion server has a number of advantages:

+ - Minimal software—The server has the software required for the service, and nothing else that could present a security risk.
- Closed ports—The only open ports are for the service and a remote tool.

In fact, when you build a bastion, you can start with a minimal installation. It may be an excellent baseline from which you can build single-use bastion servers. All you need on the baseline is the remote service required to administer the bastion, typically a Secure Shell (SSH) server. While serial port connections are also frequently available, the option is more difficult even if you have physical access to the server room.

If Ubuntu Server Edition provides an option for a minimal installation, it may not be what you want. If you want to create a minimal installation of Red Hat Enterprise Linux server, some work is required during the installation process. When installation is complete, some default services are not really necessary. You may want to uninstall some packages that could also compromise the secure nature of the baseline system.

Generally, bastions are designed for a network area known as a demilitarized zone (DMZ). Any area protected from the Internet by one of several firewalls. The main network is further protected from this area with a second router. As shown in Figure 6-1, bastions are typically configured in the DMZ area of a network.

Figure 6-1 depicts three distinct networks: the wide area network (WAN), the DMZ, and the protected internal network. The WAN may be a corporate network or the Internet. The DMZ is an internal network with one IP network address. The protected internal network has a distinct and separate IP network address.
