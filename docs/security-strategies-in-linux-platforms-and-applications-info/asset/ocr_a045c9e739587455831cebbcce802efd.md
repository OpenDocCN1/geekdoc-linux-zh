# CHAPTER 7 | Networks, Firewalls, and More

The first two commands specify that INPUT and FORWARD packets are to be accepted\and read by the next rule, RH-Firewall-1-INPUT.

Next, the following command accepts all input from the loopback adapter, as specified
by the standard loopback device, lo:

```
iptables -A RH-Firewall-1-INPUT -lo -j ACCEPT
```

The command that follows all ICMP messages; the most common ICMP message
from a ping command:

```
iptables -A RH-Firewall-1-INPUT -p icmp --icmp-type any -j ACCEPT
```

The following directives are associated with ports 50 and 51. They allow to the packets
that support Internet Protocol Security (IPSec) communication for authenticating and
encrypting each packet. If you don't set up a virtual private network
(VPN) or a similar encapsulated connection, consider omitting the following directives:

```
iptables -A RH-Firewall-1-INPUT -p 50 -j ACCEPT
```

```
iptables -A RH-Firewall-1-INPUT -p 51 -j ACCEPT
```

The next directive cites port 5353, which is associated with the multicast Domain Name
Service (mDNS) protocol. That protocol provides DNS functionality for systems configured
with zero configuration networking. It is also known as automatic IP addressing
(APIPA) on Microsoft systems and Bonjour on Apple systems. If you don't need mDNS,
considering this directive.

```
iptables -A RH-Firewall-1-INPUT -p udp
--dport 5353 -d 224.0.0.251 -j ACCEPT
```

The following directives are based on a Local UNIX Printing System (CUPS)
server. The standard CUPS server communicates with TCP and UDP packets on port 631.
If you don't need to set up printers or on printing from this system, considering omitting
directives.

```
ipt -A RH-Firewall-1-INPUT -p udp
--m udp --dport 631 -j ACCEPT
```

```
iptables -A RH-Firewall-1-INPUT -p tcp
--m tcp --dport 631 -j ACCEPT
```

The directive that follows continues established connections:

```
iptables -A RH-Firewall-1-INPUT -m state
--state ESTABLISHED,RELATED -j ACCEPT
```

In most firewall configurations, the next set of directives apply only if services on
t noted ports are active. To see the associated ports, review the /etc/services file.
The final directive sends a REJECT message in response to communication attempts
on all other ports.
