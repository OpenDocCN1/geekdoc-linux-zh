# Obscurity in the Linux Boot Loader

Obscurity in a Linux system goes a bit further. As described earlier in this chapter, the menu associated with the GRUB or LILO boot loaders can be hidden. Furthermore, details within boot loader configuration files can also hide important details such as the volume with the top-level root directory. For example, the following entry from an older
> GRUB configuration file clearly identifies the volume with the top-level root directory:

```
kernel /vmlinuz-2.6.24-24-generic.x86_64 root=/dev/sda2
> ro quiet splash
```

In contrast, the following alternatives from two different GRUB configuration files obscure the location of the top-level root directory:

```
kernel /vmlinuz-2.6.24-generic.x86_64 root
>UUID=d7bbf43a-4099-8ffaabb86db ro quiet splash

kernel /vmlinuz-2.6.18-53.1.4.5 root=LABEL=/rhgt quiet
```

In both cases, the volume with the top-level root directory is obscured. The Universal Unique Identifier (UUID) number in the first line was created with the uuid command. The LABEL in the second line was created with the e2label command. The LABEL is connected to the filesystem information for the volume device. You can check the information for a volume device file as /dev/sda2 with the dumpe2fs /dev/sda2

Older Linux distributions displayed boot messages describe the process of an installation. Those boot messages include services that are started with the operating system.

Every active network service on a system is a potential surface of attack. Standard boot options on Linux distributions hide or obscure those boot messages with the quiet device shown with each of the displayed kernel commands.

Obscurity in the Linux part of the boot process means administrators to know more. The process for accessing the boot menu must be well documented. How many people to know the shift key to access the GRUB 2.0 menu? Overall, the costs of obscurity in the boot loader are small.
