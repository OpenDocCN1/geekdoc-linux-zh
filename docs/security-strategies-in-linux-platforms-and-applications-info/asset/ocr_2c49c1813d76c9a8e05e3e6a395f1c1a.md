# 248 PART 2 | Layered Security and Linux

With Samba, a Linux system can take a role as a more secure Windows server.
It can be configured as a PDC, as a stand-alone-server, and as a member of an Active Directory domain. Various Samba options can enhance obscurity, limit access by network interface and IP address, or set WINS name resolution, and more.

Samba can be configured with local databases for domains or can refer to other systems to verify usernames and passwords. Samba can be configured as a master browser for the LAN or even with the Microsoft domain. Samba can be configured to serve Microsoft login scripts and profiles to support a consistent level of access on different remote systems.

The SSH server can be configured in detail in the ssh_config file. Options can regulate how users log in, the use of public keys, authentication with Kerberos tokens, and more. SSH supports secure remote encrypted connections to FTP servers, along with secure copying to from remote SSH servers. SSH passrases can be configured to enhance security further; with a private/public key pair, the passphrase is never seen on the network.

Many users have to communicate with the Internet. Enterprise networks are connected over the Internet. Without encryption, communications would be especially vulnerable. You can reduce the risks with IPSec connections. Such connections can be configured on a host-to-host or network-to-network basis. To support IPSec, the key protocol numbers are 50 and 51; the key port numbers are 50, 500, and 4500. Red Hat and Ubuntu configure IPSec connections in different file locations, in the /etc/sysconfig/scripts/ and /etc/racoon/ respectively.

Telnet is still a popular option for remote connections. Because it is a clear-text protocol, it's easy to find usernames and passwords sent over Telnet with tools such as Wireshark. If you can't convert to SSH, you can at least set Telnet services associated with SSL or Kerberos.

If you need to set up remote connections by telephone modem, the most popular standard is RADIUS. It can be configured to authenticate users via protocols such as PAP, CHAP, and EAP. It includes a number of complex configuration files stored either in the /etc/radius/ or the /etc/radiusd/.

As you pay attention to cleartext protocols like Telnet, you should also remember the clear-text methods used for backups and e-mail. Fortunately, the advantages of SSH can be incorporated directly into rsync commands. In addition, there are secure versions of major e-mail protocols available that can be configured on client systems. Of course, that still requires a matching configuration on e-mail server systems, one of the topics covered in Chapter 9.
