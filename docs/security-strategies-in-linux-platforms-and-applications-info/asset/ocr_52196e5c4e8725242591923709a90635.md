Other RSyslog modules can be defined in the following categories:

+   * Input—Other modules of interest relate to TCP communication,
GSSAPI communications, and more.
* Output—Outputs process messages especially for databases.
* Parser—Parser modules process received messages.
* Message modification—Message modification modules are still in development.
* Library—Library modules can be configured by users.

RSyslog Global Directives
Because RSyslog is relatively new, the global directives are more complete in the versions
released for Ubuntu Hardy Heron and RHEL 6. The following standard $Action directive\uses the traditional format for log message timestamps:

```
$ActionFileTemplate RSyslog,TraditionalFileFormat
```

Be aware, there are 50 different $Action directives available: these can configure
every from log size to timeouts to frequencies. One handy option is to filter
dplicate messages, which can reduce the load when a system makes the same mistake
ever few seconds.
The default setting here sends all log messages to the local system over a TCP
connection using the suggested port of 61514. In these directives, while the double @@
symbol is associated with TCP packets, the single @ is associated with UDP packets.

```
* @@127.0.0.1:61514
```

Of course, if this is a client system logging information to a remote server,
y'd change the 127.0.0.1 IP address to that of the logging server.

# RSyslog Configuration Rules

Some configuration rules set basic parameters for log files. For example, the
directives from the Ubuntu Lucid Linux version of /etc/rsyslog.conf file should be
conceptually familiar from other services, as they set ownership and permissions on related
files. The rules from that version of the configuration file are described in Table 12-4.
The RSyslog developers recommend that administrators use the
$PrivDropUserID and the $PrivDropToGroup directives rather than
$PrivDropToUser andToGroup directives. If the syslog user
does not exist, the $PrivDropToUser syslog and $PrivDropToGroup syslog
directives mean that RSyslog is run with root administrative privileges.

In that situation, if a black-hacker were to break into the syslog log account,
that person would get full root administrative privileges on the local system. Alternatively,
you could just make sure the syslog user and group are properly configured
in the password-authentication database.
