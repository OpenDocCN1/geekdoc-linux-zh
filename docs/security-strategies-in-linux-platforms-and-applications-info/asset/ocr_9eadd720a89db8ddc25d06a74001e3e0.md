# Every Service Is a Potential Risk

AN IDEAL WORLD, every system would be self-contained, with everything a user needs, isolated from the network. But that's not realistic. You can minimize risks, however. To that end, every service is a potential risk.

If you're running a service such as an Apache Web server, you realize that service is subject to risks. You're probably watching for news on Apache, ready to pounce on updates that address security issues.

But what if a print server is already running on the same server? Is it okay if a different file server is installed, but just not running? While there are services with their own control scripts, you also need to remember those services controlled by the internet super server. What happens when a compiler is left on a system after a new kernel has been built? In some cases, you can isolate services with a chroot jail. When you consider the services on a system, X servers and clients are a risk as well. In addition, the productivity tools found on X servers are also subject to attacks.
