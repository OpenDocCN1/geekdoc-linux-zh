# CHAPTER 13 Testing and Reporting

# Verify a Package

The first method for verifying the integrity of the system is relative to its installed state. With the right command, you can compare the current list of installed packages to an associated list of installed files. As you should already know, the basic commands vary depending on whether the distribution is built on packages associated with Red Hat or Debian systems.

Be aware, use of package management commands may not even provide a complete measure of what is installed. Many users and administrators install packages more directly from source code, typically collected in a compressed tarball archive.

# Verifying Ubuntu/Debian Packages

Because Ubuntu is built on Debian Linux, Ubuntu packages are built on the Debian package system. As such, it relies on dpkg and desums. To get a list of currently installed packages on these systems, run the dpkg -l. Prepare to be overwhelmed by a list of hundreds or even thousands of packages whiz. Of course, the value of such a list is as a database, which can be piped to a text file or searched through the grep command.

One variation on dpkg -1 provides a more straightforward list of installed packages is as follows:

```
$ dpkg --selections
```

That's a list of installed packages. When such are installed, they include a list of checksums, classified by package, separated by each installed file, in the /var/lib/dpkg/info/ directory. To take advantage of that list, run the desums command. The output from that command is impressive; it's not uncommon for some desktop systems to include a couple of hundred thousand packages or more.

But not all packages include checksum information. In addition, some files are configured from a combination of packages, as the initial RAM disk file in the /boot/ directory.

For those files associated with checksums, the only indication of a problem is a FAILED message after the filename.

# Verifying Red Hat Packages

The Red Hat Management system is more precise when it checks the integrity of installed packages. It's a straightforward command, given the name of a target package. For example, the following command and output is typical for the Postfix e-mail server:

```
$ rpm -V postfix
```

```
..5....T /etc/postfix/main.cf
```
