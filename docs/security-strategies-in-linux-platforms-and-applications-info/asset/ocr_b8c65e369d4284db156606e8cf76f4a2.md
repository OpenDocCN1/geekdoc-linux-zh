# CHAPTER 15 Best Practices and Emerging Technologies

# Service-Specific Gold Baseline Systems

Some services are more critical than others. For example, the Web sites associated with electronic commerce are more important than the File Transfer Protocol (FTP) server that may need to share electronic copies of user manuals. So you may want to configure your service-specific gold baseline systems. That way, you'll be prepared in case a server goes down.

Some gold baseline systems should go beyond a basic operating system. Some services are mission critical to an organization. In such cases, it may be helpful to create a gold baseline, customized for that service. That would be similar to the bastion systems described in Chapter 6.

If there's a security issue that is unrelated to the subject service, some updates may be required, but any associated configuration file should still perform the intended functions. However, the careful administrator will still test the resulting configuration.

If the service was brought down due to a security issue, however, additional analysis may be required. For example, Ubuntu Security Notice 612-2 highlighted an issue with the way encryption keys were created from passphrases. Because those encryption keys were vulnerable, administrators of SSH servers had to update their SSH servers and arrange to regenerate encryption keys for all users.

# Trust But Verify Corporate Support

The companies behind Linux distributions have found a way to make money. They sell their expertise. Organizations that purchase this type of expertise expect some level of support with updates, hardware certification, and certain core applications. Because these are the people who have put together and tested these distributions, they are qualified to put your software to work. Given the open source nature of this software, others may have similar levels of expertise. In fact, there are other companies that sell similar levels of support.

Some corporate officers are opposed to using software developed by volunteers. Many of their managers recognize that "free software" requires the skills to use such software. If they haven't hired expertise, they can purchase it through corporate support.

Canonical and Red Hat are not the only companies that provide support for their Linux distributions. For example, not Oracle creates its own rehaul of RHEL, but that company also sells its own support for its rebuild. Several vendors such as Dell and HP sell servers with different Linux distributions and provide their own support for such. Of course, any number of consulting companies can also provide varying levels of support for Linux systems.
