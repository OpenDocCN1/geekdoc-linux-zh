# 226 | PART 2 | Layered Security and Linux

Unless otherwise configured, vsFTP is actually run as one of the internet server services described in Chapter 7. It's safer to run vsFTP as its service, with its own control script in the /etc/init.d/ directory. Both Ubuntu and Red Hat versions of vsFTP make this possible with the following directive:

+   - listen = yes

If, however the FTP server is to work on an Internet Protocol version 6 (IPv6) network, you could configure the following alternative directive. Just be aware that vsFTP won't work with both versions of the listen directive:

+   - ipv6 = yes

Frequently, administrators like you are responsible for transmitting corporate or organizational policies regarding the use of services like vsFTP. If the following directive is enabled, vsFTP looks for a hidden .message file in each directory unless overridden by a message_file directive.

+   - dirmarge_enable = yes

Given the popularity of many anonymous FTP services, logging information about uploads and downloads may be useful. It's activated with the xfer_log_enable directive shown next. While the default log file is /var/log/vsftpd.log, it can be changed with the xfer_log_file directive. If you do change the file in the /etc/logrotate.d/ directory; otherwise, the size of this file could easily overwhelm many systems.

+   - xfer_log_enable = yes

One option for uploads is to change the ownership of such files to a specific user, such as nobody or another user with minimal privileges. That can reduce the risk of an uploaded script or binary file that otherwise affects the security of the FTP server. Of course, this assumes user nobody is properly configured in the shadow password suite (or other database) with appropriate minimal privileges.

+   - chown_uploads = yes
- chown_username = nobody

If you want to specifically set a nonprivileged user, the following directive can help:

+   - priv_user = nobody

A couple of additional options can work sort of screensavers; the following options end the connection if no commands or additional file transfers are detected in the given number of seconds. Some administrators may prefer to reduce the value of the idle_session_timeout directive.

+   - idle_session_timeout = 600
- data_connection_timeout = 120

Generally, secure FTP servers do not allow connections based on the American standard code for information interchange (ASCII), as that can lead to denial-of-service (DoS) attacks.
