# Linux Patch Management

Current versions of Linux distributions require Internet access to download updates software. That software is downloaded from a group of packages known as a repository. The repositories for a distribution are frequently mirrored on different servers worldwide.

But such connections depend on the speed of the repository or mirror, along with the geographical proximity of that system. If you find a repository mirror that's fast and relatively close, the packages that need to be downloaded from that system may be huge. For example, updated packages associated with the OpenOffice.org site can easily exceed hundreds of megabytes. If that download multiplied by a few (or more) systems on the local network, the additional load on an Internet connection may be expensive.

A local repository can be a simple mirror of that remote system. A local repository is downloaded only once, minimizing the load on a corporate Internet connection. One additional reason to create a local repository is to limit what users and administrators install on their systems. If you support access to all repositories, users may choose the second and third office suite. Users may choose that fifth Web browser. And then you'll be responsible for making sure all systems are secure.

The methods for configuring repositories and update systems vary widely. Repositories for Red Hat Enterprise Linux and Ubuntu systems provide two diverse models that encompass the range of what's available for different Linux distributions.

Before exploring the differences between repositories and update systems, you need to know more about the commands and configuration files that work with different repositories. The yum command is most closely associated with Red Hat systems; the apt-* commands are most closely associated with Ubuntu systems through their heritage in the Debian distribution. However, these commands are not distribution specific. For example, some repositories associated with the apt-* commands have been configured for Red Hat-style distributions such as Fedora Linux.

The advantage of the yum and apt-* commands is that they can automatically identify dependent packages. For example, if you try to install the system-config-samba configuration tool on a Red Hat system, the yum command automatically determines that packages associated with the Samba file are also required and includes the associated packages in the installation.
