The network addresses shown are just two possible examples. Traffic between the WAN (Internet) and the protected internal network is filtered through two different firewall routers.
Each firewall router has two network devices. In Figure 6-1, the first Ethernet device (eth0) on the external firewall router is connected to the WAN (Internet) and has a public IP address. The second Ethernet device (eth1) on that router is connected to the DMZ network. All traffic directed to and from the DMZ and the protected internal network is filtered through a firewall on this router.
Each bastion server on the DMZ network is used to serve data to users on the Internet. Each bastion server has a single function, such as serving Web pages, sharing files via the File Transfer Protocol (FTP) service, or sharing authoritative name information via a caching Domain Name System (DNS) name server. The external firewall router should stop network traffic that would otherwise harm internal systems, such as denial of service (DoS) packets. In addition, external firewall router should filter requests for each service, and redirect appropriate requests to the right bastion server.
Now look at the internal firewall router. The first Ethernet device (eth2) on that router is connected to the DMZ network. The second Ethernet device (eth3) on that router is connected to the protected internal network. # A Minimal Ubuntu Installation

A minimal installation is a straightforward process for Ubuntu Server Edition. Since release 8.04, Ubuntu has included a minimal installation option from its boot media. The installation is compact; excluding swap space, it requires less than 400 MB of space on a hard drive and a minimum of just 128 MB of RAM. A minimal installation does not include a GUI, any service that you may configure on a bastion, or even the SSH service. Before you set up a minimal Ubuntu baseline, you'll want to install an administrative service like SSH. Of course, you'll also want to set up at basic IPv4 networking. If your Dynamic Host Configuration Protocol (DHCP) server supports hostname assignments, get otherwise. Otherwise, when you copy the partitions from the baseline system. Once configured, you'll be able to copy the partitions or even the virtual disk files to create additional Ubuntu installations.

Once the minimal installation is copied, you can verify the new installation, assign a new hostname, and install the necessary software packages based on the desired function-packages to see what the current list of services and packages can offer. Then you'll want to install the service that fits the function of the specific host. While that function may be any of the services associated with Linux, you shouldn't install more than one service on any single bastion.

# A Minimal Red Hat Installation

A minimal installation is a straightforward process for Red Hat. If you accept the defaults, however, Red Enterprise Linux 5 (RHEL) includes extra software such as a GUI, the OpenOffice.org site, and even games. None of these software packages are required for a Red Hat bastion. As long as you avoid these GUI-based packages, it's possible to use RHEL 5 with a relatively small amount of RAM. While 192 MB is frequently adequate, some trial and error may be required to find an optimal amount of RAM for your bastion system.

When creating a Red Hat prototype for a bastion, you'll need to deselect these options during the installation process. But even when these options are selected, the minimal Red Hat installation includes a number of services that aren't needed on most bastion servers.

# Service Reviews

Once you've configured the distribution, you should check currently active and installed services. Active services can typically be found in one of locations: the scripts in the /etc/init.d/ directory or the files in the /etc/xinetd.d/ directory. Figure 6-2 shows the list of /etc/init.d/ services for a minimal installation of Red Hat Enterprise 5.

The services that are actually active during the boot process are listed in the relative directory associated with the default runlevel for the distribution. Debian-style systems including Ubuntu is runlevel 2. The default runlevel for Red Hat-style distributions generally depends on whether a GUI was included in the installation process. If so, the Red Hat kernel is 5. The default boot runlevel for such systems is 3.

Now take a look at Figure 6-3 for the services that are active in a Hat runlevel 3. The figure displays the contents of the /etc/rc.3/ directory. The services that start with an S are started in the runlevel, followed by those that start with K, which are shut down when entering this runlevel. Even though this is a minimal installation, you should already sense that some work is required to pair this down. You'll see more detail later in the chapter.

> NOTE
Through Red Hat Enterprise 5, the default runlevel and associated parts of the boot process were configured in the /etc/initabb configuration file. While that file is based on the originally designed configuration of UNIX System V, or SysV for short, it is in the process of changing. Starting with the Ubuntu 8.04 release, Ubuntu is moving toward a system as Upstart, where the information is contained in the files of the /etc/event/ directory. The companies behind other major Linux distributions, including Red Hat and Nov, have indicated that they will move future services toward Upstart.

## Package Reviews

Sometimes you just need to take inventory, but even the minimal installations for Red Hat and Ubuntu systems include hundreds of different packages. One way to review the current list of packages on a system is with the applicable package-management tool. On Ubuntu systems, the following command lists all installed packages:

- dpkg -l

On Red Hat, the following command lists all installed packages:

- rpm -qa

Of course, the list of packages from these commands can be redirected to text files for further analysis. But it would help, if these packages are classified in different categories. And if you don't have a GUI on the local system, such tools are fairly rare. Ubuntu includes a useful tool that works with the command line, aptitude, which you can start with the aptitude command. As shown in Figure 6-4, it identifies information on upgradable and installed packages. As shown in the Installed Packages, categories are listed by functionality.

Red Hat doesn't provide a similar command-line base management tool. However, if you've registered the system on the Red Network, it's easy to find a similar list of packages. Different options allow you to see what's installed, what's upgradable (along with associated security alerts), and report. Perhaps most useful is, Red Network allows you to verify the integrity of installed packages, to make sure they've not modified by unauthorized users.

Ubuntu includes similar tools in its Landscape system management and monitoring service.

> NOTE
The aptitude command is also a front-end to the apt-get and apt-cache commands. As such, it can be used to directly install, remove, and search any available package.
