# Keep the System On (At Least for Now)

If you identify a system that has been compromised, be careful. The actions you take determine how much can be learned from the situation, whether other systems may be at risk, and how data from a compromised system may be used with respect to potential legal action.

If you're new to computer forensics, read this section as a guide. Any actions with respect to compromised systems should follow a prearranged plan. That plan should be endorsed by appropriate legal personnel to make any actions preserve evidence in a useful manner. This book is not intended to substitute for a real forensics action plan.

If it is safe, disconnect the system from a public network, but connect the system to an isolated network. That allows you to use a protocol analyzer to read the network traffic going to and from the compromised system. On an Ethernet network, it's possible to use commands like tcpdump and tools like Wireshark to analyze that. Don't forget to run appropriate nmap commands... You might get lucky if the black-hat hacker did not change the IP address of packets sent to the targeted system. In that case, you could block access from that IP address.

At some point, you may want to disconnect the compromised system from the network. Ideally, if it provides a mission-critical service, you'll have a backup in place with appropriate security updates, ready to substitute for the compromised system. If that is not, your users may live without the service for a period of time.

If you power down a compromised system too soon, you may lose critical information. Linux stores dynamic information in RAM. That information is accessible through the /proc/kcore file. If you power down a system, that data may be lost.

To get a picture of data in RAM, you'll need a forensics kit. One popular option that has been commercially is known as Helix Knoppix. Alternatively, the References section in the back of this book lists several items on the Symantic Web site by Marius Burdach on how to create your own forensics kit. Briefly, the kit can be mounted on a compromised system, with direct access to important commands.

For example, if a forensic system is mounted on the /media/cdrom/, you should be able to run commands from that directory. As suggested by Symantic, you should take the following steps while a system is still running:

+   1. Take a digital picture of the active monitor of the compromised system.
2. Mount the forensic CD or DVD on the troubled system with the following command (the -n switch avoids writing the mount to the /etc/mtab file):
(troubled system) # mount -n /dev/cdrom /media/cdrom
Be warned: There is fairly risk associated with using the mount command from a troubled system, especially if that command has been compromised by a black-hat hacker.
3. Use netcat, nc, to open communications from a remote system listening (-l 11111) on a specific port such as 11111:
(diagnostic system) # nc -l 11111 date_on_troubled_host
