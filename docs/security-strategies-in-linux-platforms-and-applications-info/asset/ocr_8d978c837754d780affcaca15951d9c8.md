# CHAPTER 11 | Managing Security Alerts and Updates

While Apache 2.4 may not be officially released for some time, unstable versions of this software are available. Normally, production systems should not include beta versions of critical service applications as Apache. However, Apache 2.4 includes several enhanced security features, including the ability to check an Online Status Protocol (OCSP) server for the current status of a digital certificate. If a black-hat hacker is able to get his or her official certificate through nefarious neighbors, OCSP access can protect users.

For your convenience, Apache makes its software available in binary packages for Red Hat and Ubuntu systems (in formats suitable for deb and pkg commands). However, such packages may not have been tested by the developers behind these distributions.

# Samba File Server

Administrators who run the Samba file server can stay up to date with the Samba Security Web page at http://www.samba.org/samba/history/security.html. Updates are provided in patch format. To incorporate these updates, you'll need the Samba source code. You can then apply the noted patch in a similar manner to applying a patch to the Linux kernel source code as described in Chapter 10.

Alternatively, you can wait until the developers build a distribution process to patch their into your own binary files. Once updated, you can use the applicable package management tool to download and upgrade the new Samba software.

The patch release as described on the Samba Web site is different from the release made by the developers of a distribution. Such developers may have to do additional work to incorporate the newly released patches in a manner compatible with other packages associated with the distribution.

The developers behind Samba maintain several versions of its file software in a manner similar to the developers behind the Linux kernel. As of writing, they will maintain versions 3.3 through 3.5. The developers behind Linux distributions may incorporate the code for those patches in earlier versions of Samba. For example, Ubuntu developers would take the patch associated with Samba version 3.5, and incorporate the associated code in Samba 3.0.28a release. That is also known as a backport.

If you believe you've discovered a significant security issue in a Samba release, the developers encourage e-mail reports to security@samba.org.
