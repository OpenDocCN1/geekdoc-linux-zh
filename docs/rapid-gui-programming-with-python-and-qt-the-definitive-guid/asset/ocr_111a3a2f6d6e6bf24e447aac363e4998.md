# ## Multithreading

Traditionally, applications have a single thread of execution and perform one operation at a time. For GUI programs this can sometimes be a problem—for example, if the user invokes a long-running operation, the user interface might freeze up while the operation is taking place. There are a few solutions that can be tried to eliminate this problem.

One simple solution, particularly useful in long-running loops, is to call QAp-\nlication.processEvents(). This method gives the event loop the opportunity to\nhandle any unprocessed events, such as paint events, as well as mouse and key\npress events. Another solution is to use zero-timeout timers. We have combined\nboth approaches in several examples, usually when loading lots of files—for\nexample, in Chapter 9’s Text Editor’s MainWindow.loadFiles() method.

A third solution is to farm the work out to another program entirely. This can\nbe done using the Python standard library’s subprocess module, or using PyQt’s\nQProcess class. The makepyt.pyw application supplied with the examples uses\nQProcess to execute PyQt’s command-line tools such as pyuic4 and pyrcc4.

In some cases what we really need is a separate thread of execution within the\napplication itself. Applications that have more than one thread of execution\nare said to be multithreaded.\* For example, we might want to create a server that\ncan service as many simultaneous connections as the hardware can cope\nwith, something relatively easily done if we devote a new thread to each\nconnection. And in some cases we might have a GUI application where we\nwant the user to be able to start off a long-running process, and then continue\ninteracting with the application; in such cases it may be best to pass on the\nprocessing to a separate secondary thread and leave the primary (GUI) thread\nfree to respond to the user.

This chapter shows some common techniques used in multithreaded program-\nming. These are enough to get started, but the coverage is not comprehensive.

> \*This chapter assumes a knowledge of the fundamentals of threading. For a thorough, but not\nlight, introduction, see *Foundations of Multithreaded, Parallel, and Distributed Programming*.
