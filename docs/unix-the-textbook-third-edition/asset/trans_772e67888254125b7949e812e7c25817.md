

## 5.4 基于访问权限的保护

第三种文件保护机制可防止用户在未以文件所有者的身份登录时访问彼此的文件。作为文件所有者，您可以为文件附加某些访问权限，以规定谁可以、谁不可以对各种类型的文件操作进行访问。该方案基于 UNIX 下用户类型、访问权限类型以及允许对文件执行的操作类型。在没有此保护方案的情况下，用户可以访问彼此的文件，因为 UNIX 文件系统结构（见图 4.2）有一个单一的根，所有系统中的文件都挂在其下。全书中我们将访问权限、访问特权和访问权利这三个术语同义使用。

UNIX 系统中的每个用户都属于一个用户组，该组由系统管理员在为用户分配系统账户时指定。用户可以属于多个组，但典型的 UNIX 用户只属于一个组。系统中所有组及其成员关系都列在文件 /etc/group 中（见图 4.2）。该文件每组一行，行的最后一个字段包含该组成员的登录名。文件的用户可以是文件的所有者、与所有者属于同一组的用户，或系统上拥有账户的任何其他人。这些分别构成了 UNIX 文件的三种用户类型：user、group 和 others。作为文件所有者，您可以指定谁可以访问它。文件的组名称为文件的组所有者。

一旦用户登录系统，他/她对 UNIX 系统而言就以一个整数编号为人所知，即用户 ID（UID），而不是用户的登录名。每个 UNIX 系统都有一个特殊用户，无论文件上的访问权限如何，都可以访问系统上的所有文件。该用户管理（管理）您的 UNIX 系统，通常称为超级用户或系统管理员。超级用户的登录名为 root，用户 ID 为 0。

您可以通过显示 /etc/group 文件来查看系统上所有用户组的列表，如下所示。

```
$ more /etc/group
root :0:root,davis
other :1:
bin :2:root,bin,daemon
sys :3:root,bin,sys,adm
adm :4:root,daemon,adm
uucp :5:root,uucp
mail :6:root
tty :7:root,tty,adm
lp :8:root,lp,adm
uucp :9:root,nuucp
staff :10:
daemon :12:root,daemon
sysadmin :14:davis
nobody::60001:
noaccess::60002:
nogroup::65534:
utadmin::100:
faculty::101:
ra::102:
courses::103:zartash
student::104:ank
...
$
```

该文件中系统上每个组有一行，每行有四个以冒号分隔的字段。第一个字段指定组名，第二个字段指定有关组的某些信息，第三个字段以数字形式指定组 ID，最后一个字段指定属于该组的用户的以逗号分隔的列表。例如，bin 组具有组 ID 2，其成员为用户 root、bin 和 daemon。如果某行的成员列表缺失（例如 faculty 组），则表示其成员关系在 /etc/passwd 文件中指定。系统管理员在向系统添加用户时将用户设为某个组的一部分。该组称为用户的默认组。用户的默认组成员关系在 /etc/passwd 文件中用户的条目中指定。系统管理员可以通过将用户的用户名放在组的成员以逗号分隔的列表中，使用户成为另一个组（除其默认组外）的一部分。您可以使用 groups 命令显示用户在系统上所属的组。以下会话显示 sarwar 仅属于 faculty 组；zartash 属于 faculty 和 courses 组；davis 是三个组的成员：faculty、root 和 sysadmin；root 属于 11 个组：other、root、bin、sys、adm、uucp、mail、tty、lp、nuucp 和 daemon。

```
$ groups sarwar
faculty
$ groups zartash
faculty courses
$ groups davis
faculty root sysadmin
$ groups root
other root bin sys adm uucp mail tty lp nuucp daemon
$
```
