## 11. 在 PC-BSD 系统上，使用 zfs snapshot、zfs send 和 zfs receive 命令将你的主目录（或主目录中的一个选定子目录）备份到U盘。你的主目录的ZFS数据集应命名为类似于 tank/usr/home/your_username 的名称。

请务必插入并测试你想用于此问题的U盘，以确定它在你的系统上是否可用。如果插入后它没有出现在 /dev 中，那就是不可用的！

测试U盘的可用性后，请确保在“系统设置”中关闭可移动媒体的自动挂载功能。使用磁盘管理器准备U盘，销毁其上的任何分区表，并在其上创建GPT分区表。然后使用 gpart 命令创建一个带有ZFS文件系统的主分区。

## 13. 你将在本问题中实现的过程的一个重要用途是，使你能够为系统磁盘创建ZFS镜像，从而为系统磁盘和数据提供冗余。这个单一的内置硬盘 vdev（其中也可以包含你的所有用户数据文件）可能位于一台只能内置一块硬盘的笔记本电脑内部。你将在本问题中创建的镜像通过USB总线来维护。如果我们在这里指定的外部（但可打开）硬盘盒中的硬盘是SATA驱动器，那么当内部单个SATA硬盘驱动器发生故障时，该驱动器也可以用作其替代品。本问题假设其硬盘盒中的外部USB硬盘和你计算机中的内部硬盘可以轻松移除和重新安装。它们也必须是SATA驱动器，无论是机械硬盘还是SSD。本问题实现的目标与第23章中为 Clonezilla Live 所示的目标相同。

在 PC-BSD 系统上，使用可打开硬盘盒中的外置USB硬盘重复示例24.4中给出的操作。你必须确保该USB外置硬盘的容量足够大，能够容纳镜像的创建。

当你的内部硬盘实际发生故障时，若要重复此过程，请遵循本章前面所示的镜像中 vdev 替换流程。

## 14. Mansoor 正与 Bob 一起做一个项目。他需要能够读取、写入、创建和删除与项目相关的文件，这些文件位于 Bob 主目录的 Project 目录中。Bob 和 Mansoor 是没有管理权限的普通用户。他们希望在完成这个项目时，无需联系系统管理员来请求新建组、更改组成员、sudo 变更等。

项目结束后，Bob 将移除用户 mansoor 对他的主目录和 Project 目录的修改权限。这里的“修改”是指 Mansoor 仍然可以查看 Project 目录的内容，但不能对其中的文件做任何更改。Bob 将自行完成此操作，而不会联系系统管理员。

在你自己的 Solaris 系统上，与另一位用户合作，使用ACL完成以下操作（将你系统上的有效用户名替换 Bob 和 Mansoor）：

- a. 在 Bob 的主目录下创建一个名为 Project 的项目目录。在我们的系统上，这个新目录的路径是 /export/home/bob/Project。
- b. 在 Bob 的主目录上设置ACL，使 Mansoor 对其拥有读、写和执行权限。
- c. 在 Project 目录上设置ACL，使 Mansoor 对其拥有 rwxo 权限。
- d. 让 Bob 在 Project 目录中创建一些文件。
- e. 让 Mansoor 将 Bob 的主目录设为当前目录。
