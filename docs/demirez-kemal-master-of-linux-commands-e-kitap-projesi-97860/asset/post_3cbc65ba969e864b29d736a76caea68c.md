```
root@kemal:~# parted -l
Model: ATA TOSHIBA MK4032GA (scsi)
Disk /dev/sda: 40,0GB
Sector size (logical/physical): 512B/512B
Partition Table: mdos
Disk Flags:

1 1049KB 39,0GB 39,0GB primary ext4 boot
2 39,0GB 40,0GB 1053MB extended

```

## Mkfs-Mount-Umount

Lets continue with the sample above. We listed disc sections in parted tool with print. For the first section, if you want to re-create a new file system, you can use a command such as mkfs1 ext4. But you should be carefull with these kind of commands. Creating new file system means to format that disk space. Which means you can loose your data in this section. Let's be sure about the commands what we are using for.

If you want to reformat the partition of any file system according to any pattern, you can use the following command: mkfs.vfat /dev/sdb, mkfs <disc_section> etc

Biz Let's continue to see what can be done with the partitions listed in the print tool parted again.

- Mkpart to create a new section
- rm to delete a section
- quit to quit

## Kemal Demiriz

There is a tool which scans the disk and repair damaged part. This is fsck. Basic use format is fsck <disc_section>. If it is used with -n parameters with fsck fsck -n <disc_section> it checks file system but does not repair. We want to control our expressed USB disk file systems stated as /dev/sdb, first we must unmount the disk (unmount) from our system. Or we must start our system on 1st user level. Of course, such a method may be preferred, especially when you want to test your file system of disk. During the opening of system without any active action, fsck automatically detects the disk. If we want to do these processes manually, the safest way is to unmount the disk from the system. Now we unmount our usb disk from the system with ummount /dev/sdb command.

```
root@kemal:-# unmount /dev/sdb
root@kemal:-# _
```

After we unmounted the disk, we can test file system with fsck /dev/sdb and start to fixing.

```
root@kemal:-# fsck /dev/sdb
fsck from util-linux 2.25.2
fsck.fat 3.6.27 (2014-11-12)
EXT! Dirty bit is set. fs was not properly unmounted and some data may be corrupted.

1) Remove dirty bit
2) No action
? 1
Leaving filesystem unchanged.
/dev/sdb: 1 files, 1/244127 clusters
root@kemal:-# 
```

After our job is done, we need to re-mount disk to the system. Otherwise you cannot use the disk eventual it is shown in the system. To mount it, if you do not have, create a folder named usb under /media directory with mkdir /media/usb. We will mount the disc to there. Now you can give mount -t vfat /dev/sdb /media/usb command and use it. With -t here states disk's file system type.

```
root@kemal:-# mount -t vfat /dev/sdb /media/usb
root@kemal:-# _
```

On some places, you may see as fsck -t ext3 /dev/sda or fsck -t vfat /dev/sdb instead of fsck /dev/sdb commands. We do not need to use -t to identify he file system because fsck automatically does this.

A little reminder; to see which disc section mount and with which file system, we can use mount -l command. I use mount -l | grep KML command to learn about my usb memory disk information.

```
root@kemal:~# mount -l | grep KML
/dev/sda on /media/usb type vfat (rw,relime)
```
