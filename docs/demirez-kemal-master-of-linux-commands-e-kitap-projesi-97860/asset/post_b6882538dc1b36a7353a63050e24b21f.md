## Suid Bit

Each user can perform actions on the extent of their authority in the system. Sometimes it may be necessary for a normal user with root user rights temporarily. So normally the root user is able to run the program, if suid bit is set up, when other users want to use this program, as long as the program works, it runs with owners authorities. With a clearer expression, a user who wants to use the program but not have the authority, will need suid bit to run the program temporarily.

To set SUID bit, chmod u+s <file_name> command is used. To find the files which have suid bit, we use find / -perm -4000 command.


## Umask

In a linux system, the default access privileges assigned to newly created files and directories are determined by umask. To determine the umask value, we use umask command.

```
root@kemal:~# umask
0022
root@kemal:~#
```

Generally, this value is 022 in all linux distributions. When you create a file or directory, the default permissions will be as follows according to umask:

- for directories rwx-xr-x (755)
- for files rw-r-- (644)

To change umask value, we use umask <new_value> command.

Let us explain what umask means: the umask value as it is 022, then chain each number to three-digit number (binary). Like 022, let's write this with authority codes as "rw-rw-" and "rwx".

## Chattr

Sometimes you can delete a file by mistake. Or you can edit a configuration file, but when the system is restored, you will see that your edits disappear. To avoid situations like these chatter command is available. Lets explain it with an example. For example, we have a file called users.txt, and do not want to make any changes on this file. Even as the root user if we try to make a change by mistake, it will be blocked. For this, we use chattr +i users.txt command.

```
root@kemal:~# chattr +i users.txt
root@kemal:~# rm users.txt
rm: `users.txt` silinemedi: İşleme verilmedi
root@kemal:~#
```

To list the blocked files like this in the system, we use the lsattr command. If you want to check all files under a directory, you must use lsattr -R <directory> command.

```
root@kemal:~# lsattr
-------e-- /deneme
-------e-- /Downloads
----i----e /users.txt
-------e-- /dwhelper

-------e-- /Genel

-------e-- /Şablonlar
-------e-- /Müzik
-------e-- /Videolar
```

When you pay attention to the list, you will see the letter i in line with users.txt file.

To bring the protected file to previous form we use chattr -i users.txt command.

```
root@kemal:~# chattr -i users.txt
root@kemal:~#
```

## User Operations

In a linux system, many user profiles can be created and users can perform various operations on the system within their authority limits. As you know, a root user is the top authorized user in linux system. Root user is authorized to make any changes in the system.

In linux system, informations and passwords about the users are stored in two important files. Now let's examine those files.

## Shadow-Passwd

The files which informations and passwords of the users are stored under /etc directory. Information about the users stored in /etc/passwd file, the encrypted version of the user's password stored in /etc/shadow. When a new user is added to the system, the information of added user are written in these files.

Before written in to the shadow file user passwords are encrypted using encryption algorithms, and kept in the file in encrypted form. This encryption process done by a method known as the crypt. User passwords in the system are generated as follows:

- get the password user wants to set.
- To be used as salt, create a string of eight characters.
- Create an encrypted string with taking the password that you received and work through the crypt function with the salt value.
