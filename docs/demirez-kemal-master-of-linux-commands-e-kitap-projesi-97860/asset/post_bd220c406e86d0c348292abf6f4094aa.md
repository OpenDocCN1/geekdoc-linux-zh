
# Cpio

A simple way to backup and to restore a directory, you can use cpio command. Simple use of the command is as follows:

- `ls | cpio -ov > backup.cpio`: cpio extension of the backup file is created
- `cpio -idv < backup.cpio`: restore the backup created with cpio
- `cpio --list < backup.cpio`: lists the contents of the backup file

For example, if you want to backup /etc directory, in /etc directory when you first use `ls | cpio -ov > /tmp/backup.cpio` command, etc directory backed under /tmp with backup.cpio name.

```bash
root@kemal:/etc# ls | cpio -ov > /tmp/backup.cpio
adduser.conf
adjtime
aliases
alternatives
amap
anacrontab
apache2
apg.conf
apm
apparmor.d
apt
arpwatch.conf
at.deny
at-spi2
navahi
avavrdude.conf
```

Now lets use `--list < backup.cpio` command to list of the backup file content.

```bash
root@kemal:/tmp# -l backup.cpio
-rw-r--r-- 1 root root 956416 Kas 25 01:23 backup.cpio
root@kemal:/tmp# file backup.cpio
backup.cpio: cpio archive
root@kemal:/tmp# cpio --list < backup.cpio
adduser.conf
adjtime
aliases
alternatives
amap
anacrontab
apache2
apg.conf
apm
```

We must use `cpio -idv < /tmp/backup.cpio` to restore backup file.

```bash
root@kemal:/etc# cpio -idv < /tmp/backup.cpio
cpio: adduser.conf oluşturulmadi: daha yeni ya da
adduser.conf
```

## Runlevels

There is a concept in linux systems called runlevels. To explain this concept first we must understand linux system's startings and kernel loads to memory.

When linux systems starts, kernel loads on to memory and searches hardware to install driver updates. Then root file system (/) is mounted and starts init program to execute. While this process is executing runlevel been adjusted. This progress, which chooses to services to start based on the determined process called runlevel. In linux systems there are 7 different working process such as this one. We can simply summarize them as:

- 0: Level of service that none of the services works and begin the shutdown process
- 1: Single-user's level. Network services do not work. The system can be used for maintenance.
- 2: Level multi-user operation without network support.
- 3: Network-assisted multi-level work.
- 4: Not used. But specifically defined by the user.
- 5: Level of operation of the graphical user interface. Almost all Linux distributions today for personal use, this level will start working by default.
- 6: reboot level

To see which level our system is working on, we can use runlevel command.

```bash
root@kemal:~# runlevel
N 5
root@kemal:~# _
```

Each work level has a folder where the scripts located to launch of the service and terminate the services. These directories found in /etc directory and have rcX.d format (X = operating level).

```text
rc0.d
rc1.d
rc2.d
rc3.d
rc4.d
rc5.d
rc6.d
rc.local
rc5.d
```

Files in this directory beginning with K, indicate the services which will stop working when switching to this level. The files starting with S indicates the services which will be executed when switching to operational levels.

