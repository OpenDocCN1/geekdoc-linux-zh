### Cron-Crontab

On the Linux operating system, it is possible to edit some of the work you want to do in specific time range. Means, you can delete some log files on time you scheduled, and you can schedule any process you want. It is possible to schedule every job with cron service.

You can use service cron status command to get information about the status of your cron service.

```
root@kemal:~# service cron status
● cron.service - Regular background program processing daemon
 Loaded: loaded (/usr/lib/system/cron.service; enabled)
 Active: active (running) since Tue 2015-11-22 18:23:24 EET; 2h18min ago
 Docs: mancron(8)
 Main PID: 520 (cron)
 Cgroup: L520 /usr/sbin/cron -f
```

Crontab command is used to edit the scheduled jobs. So crontab files can be edited with the crontab command. Cron application configuration file is /etc/crontab file.

```
root@kemal:~# cat /etc/crontab
# /etc/crontab: system-wide crontab
# Unlike any other crontab you don't have to run the 'crontab'
# command to install the new version when you edit this file
# and files in /etc/cron.d. These files also have username fields,
# and none of the other crontabs do.
SHELL=/bin/sh
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin
# hour mon dom user command
17 + * * * root
25 6 * * * root test -x /usr/sbin/annhourly || ( cd /root; run-parts --report /etc/cron.daily )
47 6 * * * root test -x /usr/sbin/anndaily || ( cd /root; run-parts --report /etc/cron.daily )
52 6 * * * root test -x /usr/sbin/annmonthly || ( cd /root; run-parts --report /etc/cron.monthly )
root@kemal:~#
```

After this brief introduction we will know how to use the crontab command to make arrangements and regulations. Some distributions open cron file using vim. (So, it opens the cron file based on the user who gives the cron command) and after the changes made and quit, the cron service starts with new settings.
```
root@kemal:~# crontab -e

```

```
# Edit this file to introduce tasks to be run by cron.
# Each task has to be defined through a single line
# indicating with different fields when the task will be run
# and what command to run for the task
# To define the time you can provide concrete values for
# minute (m), hour (h), day of month (dom), month (mon),
# day of week (dow) or use '*' in these fields (for 'any').
# Notice that tasks will be started based on the cron's system
# daemon's notion of time and timezones.
# Output of the crontab jobs (including errors) is sent through
# email to the user the crontab file belongs to (unless redirected).
# For example, you can run a backup of all your user accounts
# at 5 am every week with:
# 0 5 * * * 1 tar -zcf /var/backups/home.tgz /home/
```

Scheduled tasks information should be written in open file. It manages the Schedule and works based on our commands. To make arrangements, we first need to learn the characteristics of cron file. There are 6 fields in cron file. The first five are for making the requested work-related days, hours, for information, such as minutes, the last one is for run command.

- 1st field: Determines how many minutes after the hour starts the job will execute. (0-59) (for example, 30 minutes job starts after the 30 minutes of selected hour – like 30 minutes after 1 o'clock)
- 2nd field: Determines the start time of job. (0-23) (number instead of * means that every hour is entered)
- 3rd field: determines which days the job will start. (1-31) (number instead of * means every day is entered. 7,14 would mean also, 7th and 14th day of month)
- 4th field: Determines which month the job will be held. (1-12) (if the number is entered * means every month. 1,6 means in January and June. 1-3 means in January-February-March)
- 5th field: Determines which days of the week the job will performed. (0-7) (number instead of * means every day is entered, 0 and 7 means Sunday. 1,2 expressed on Monday and Tuesday, 1-3 refers to Monday-Tuesday-Wednesday)

We add the lines regarding the work we want to the bottom line of crontab file we open with crontab -e. Our tasks will be performed after we save and quit. Now let's make a simple example. For example, we have a folder named backup we add some work everyday. We want to back this file with backup.tgz under /var/backup directory. To do this we add 22 * * * tar -zcf /var/backup/backup.tgz /root/backup at the end of our crontab file. This command will backup everyday at 22:00 (10 pm) with the name of backup.tgz.

```
# m h dom dow command
0 22 * * * tar -zcf /var/backup/backup.tgz /root/backup
```

Now lets in /var/backup directory.

```
root@kemal:/var/backup# ls
alternatives.tar.0 dpkg.diversions.0 dpkg.extended_states.0 dpkg.status.0
```

Our files have been created as wanted. Let's check our file with backup.tgz.

```
root@kemal:/var/backup# file backup.tgz
backup.tgz: gzip compressed data, last modified: Sun Nov 22 22:00:02 2015, from Unix
```

Finally, we see the last changes done at 22:00:02. We use crontab -l command to list the scheduled tasks.

```
# m h dom dow command
0 22 * * * tar -zcf /var/backup/backup.tgz
```

Crontab -r command is used to delete the scheduled tasks.

```
root@kemal:~# crontab -r
root@kemal:~# crontab -l
no crontab for root
```

This is a simple way to use cron service which is very handy and easy to use. You can use this service on different aims based on your needs.

## Log Files

Log files are the files where records relating to work done kept on the system. These files are located /var/log.

```
root@kemal:~# ls /var/log
alternatives.log dpkg.log lastlog macchanger.log speech-dispatcher
apache2 stunnel4
apt exim4 messages syslog
auth.log fail2 mysql.sql user.log
bootstrap.log config.log wtmp
btmp mysql.log vs.conf
chrootkit gdm3 apps Xorg.log
daemon.log init. postgres
debug installer redis
kern.log
```

Log files are divided into several categories. While some of them found as files, some located as subdirectories and folders. In general, a service of the log file is saved with that service name. For example, when we look at the auth.log file see information about the users of the session.

```
root@kemal:~/var/log cat auth.log
New set seat0
Nov 22 11:07:26 kemal system-log: Watching system buttons on /dev/input events(Power Button)
Nov 22 11:07:26 kemal system-log: Watching system buttons on /dev/input event6(Video Button)
Nov 22 11:07:26 kemal system-log: Watching system buttons on /dev/input event4(Left Switch)
Nov 22 11:07:26 kemal system-log: Watching system buttons on /dev/input event3(Slee Button)
```

Another log file user.log stores process records in.

```
root@kemal:~/var/log cat user.log
Nov 22 11:07:26 kemal mtp-probe: checking bus 1, device 2: "/sys/devices/pci0000:00:14.0/usb1/1-2/id0000"
Nov 22 11:07:26 kemal mtp-probe: device 1 was not on an MTP device
```
