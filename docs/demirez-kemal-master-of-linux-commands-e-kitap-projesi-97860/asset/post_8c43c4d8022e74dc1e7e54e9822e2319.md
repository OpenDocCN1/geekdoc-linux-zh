## Pgrep

To list the processes working in the memory with some criteria **pgrep** command is used. To de changes on working process, we must first find that process. For example, to find process about **apache**, we can use **pgrep apache2** (apache service must be one for use)

```
root@kemal:~# pgrep apache2
2293
2297
2298
2299
2300
2301
2302
```

With this command, we can see the process numbers (pid) about apache service. If we want to see numbers with process names we must use **-l** parameters. Our command might be like **pgrep -l apache2**

```
root@kemal:~# pgrep -l apache2
2293 apache2
2297 apache2
2298 apache2
2299 apache2
2300 apache2
2301 apache2
2302 apache2
```

To find process about any users we can use pgrep -lu <user> command.

```
root@kemal:-# pgrep -lu root

## Kill-Killall

To end process we use kill and killall commands. These commands work as:

- kill <pid> : to terminate the process with pid number
- kill -9 <pid> : fatal hit to the process that we cannot terminate 🙂
- killall <process_name> : To terminate all process abot programming/services
- kill -9 <process_name> : to kill services process that insists not to be terminated
- killall -i <process_name> : To terminate the processes interactively

For example, to terminate all services works with apache, lets use killall apache2 command.

In X session to terminate an application that does not respond, you can use xkill command from the terminal. So mouse pointer gets a skull shape and we can click on the application window that we want to terminate.

## Fg-Bg

Finally, lets talk about executing process in background. When a process is running, the terminal that the process is started, new command cannot be entered until the process completed. But if we sent the working process to the background we can use another command. There are two ways to send a command or working process to background: Use ctrl+Z to cut the process and send it to background with bg command. Or put bring back the command from the background we can use fg command.

```
root@kemal:-# tail -f
tail: uyari: standart girdiyi sonsuza dek takip etmek verimli degildir~
[1]+ Durdu tail -f
root@kemal:-# bg
[1]+ tail &
root@kemal:-# jobs
[1]+ Durdu tail -f
root@kemal:-# fg
tail -f
~
root@kemal:-# _
```

## Fsck

Bad blocks-areas on a disc are tried to be fixed by fsck tool. When our system is first open this tool works at background and automatically checks its disk.

For example to fix errors in our usb memory stick we can use fdisk -p /dev/sdb commands. We will see in the upcoming issue, when using such tools we must first take the disk apart from the system.

```
root@kemal:-# fsck -p /dev/sdb
fsck from util-linux 2.25.2
fsck.fat 3.0.27 (2014-11-12)
/dev/sdb: 506 files, 175330/244127 clusters
