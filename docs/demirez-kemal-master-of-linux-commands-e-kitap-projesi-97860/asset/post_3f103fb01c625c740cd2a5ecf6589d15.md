
## Changing User Password

As you know, root users have the authority to do any changes on the system. Including all applications about users. Root user can change any user in the system at any time. To do this, root user must use, such as for zeynep user, its passwd zeynep command. If root user wants to change his password, he/she can only use passwd command.

```
root@kemal:-# passwd zeynep
Yeni parolayı girin:
Yeni parolayı tekrar girin:
passwd: şifre başarıyla güncellendi
root@kemal:-#
```

## Impersonating Another User's Profile

A user can impersonate other user's identity which means works with other users authorities and execute some process. To do first he/she should know the user's password. If you are a root user, you can work with any user's profile.

Before continue, lets remember w, and whoami command we mentioned earlier. With these commands we can see some informations such as which identity we are working with, identity we connect to the system with. You can see the sample use and differences on the table:

```
root@kemal:-# w
10:50 up 11 min, 2 users,  load average: 0.27, 0.52, 0.46
USR     TTY             FROM             LOGIN   JCPU    PCPU    WHAT
root     0                               10:15  ?xd7   1:12  0.14s gdm-session-wor
pts/0    :0                               10:19  2.00s  0.14s 0.01s w
root@kemal:-# who
root     0                               2015-08-19 10:19 (:0)
pts/0
root@kemal:-# whoami
root     0                               2015-08-19 10:19 (:0)
pts/0
root@kemal:-# who am i
root     0                               2015-08-19 10:19 (:0)
pts/0
```

To learn when the system was turned on who -b, to see the run level information you can use who -r command.

```
root@kemal:-# who -b
system boot 2015-09-18 10:14
root@kemal:-# who -r
acılış-seviyesi 5 2015-09-18 10:15
```

Especially using whoami command, we can easily see which identity we are working at the system at that time. Yoo may ask why we would need it. If you are working only in your system, than there is no need for sure but if you are working as a system admin on a multiple user system you may need it much.

Now lets see how to impersonate others' identity. For root user there is already not limitation so they can do any process with any users identity. However if other users want to root or another user's id to process they must know their password. To impersonate other user's id we basically use su command. How they work this is:

- su <user_name> switches to other user ID.
- su - <user_name> both switches to other user's id and begins to work in his/her shell.

```
root@kemal:-# su zeynep
zeyep@kemal:/root$ whoami
zeyep
zeyep@kemal:/root$ exit
root@kemal:-# _
```

As you can see with su zeynep command, we begin to work zeynep id. When we want to exit, we used exit command. Because we are the root user, it did not ask a password. Lets see su - zeynep command.

```
root@kemal:-# su - zeynep
zeyep@kemal:-$ whoami
zeyep
zeyep@kemal:-$ _
```

We said a reguler er user must know the password if he wants to works as root or another user's id. Lets make a sample.

```
zeynep@kemal:-$ su - root
Parola:
root@kemal:-# _
```

In any user's id, if you want to impersonate the root id, you can use either su or su - commands. Of course you should type root's password. As I menioned before, you can be another user with su command but you would still be working in your directory. With su - command, you can do both, be the user and work in his/her directory.

```
zeyep@kemal:-$ su
Parola:
root@kemal:/home/zeynep# exit
zeynep@kemal:-$ su -
Parola:
root@kemal:-# _
```

## Process

Process is the name given to situation where the file is working. When you run a program, it will be loaded into memory. Except the processes that we start in our system, there are many services and processes are running in the system. Running programs at the same time may consist of multiple processes.

We use ps command to view any currently running processes. To learn parameter of this command we can use ps --help (a) command.

```
root@local~$ ps aux
USER       PID CPU VSZ RSS TTY START COMMAND
root      1 0.1 24184 ? S 23:36 [/bin/init
root      7 0.0 0 ? S 23:36 [thread]
root      3 0.0 0 ? S 23:36 [kthread]
root      5 0.0 0 ? S 23:36 [kworker/events]
root      7 0.0 0 ? S 23:36 [rcu_sched]
root      8 0.0 0 ? S 23:36 [rcu_bh]
root      9 0.0 0 ? S 23:36 [migration]
root     10 0.0 0 ? S 23:36 [watchdog]
root     11 0.0 0 ? S 23:36 [khelper]
```

Of course which works for the best, using parameters would be a better idea. We can use some commands as these:

- ps: Processes relating to the active user.
- ps -e: All processes running in the system.
- ps -e or ps -f: For a detailed list of processes running in the system.
- ps -u <user>: Processes relating to a user.

We can wish to see all of the process to get information about the process. To get information about processes related to SSH service, we can use ps aux | grep 'ssh'.

```
root@kemal:~# ps aux | grep 'ssh'
root      819 0.0 6412 24 7 Ss 23:07 /usr/bin/ssh-agent /usr/dbus-la-exit-with-session gnome-classic
root     1367 0.3 4360 3532 5+ 23:43 ssh
```

If you pay attention to command output in the example, we have to look at process of most recently used in the list. To avoid this, we can try the following command.

```
root@kemal:~# ps aux | grep 'ssh'
root      819 0.0 6412 24 7 Ss 23:07 /usr/bin/ssh-agent /usr/dbus-la-exit-with-session gnome-classic
```

## Ptree

To view the system processes into a hierarchical list, we can use ptree or ps -forest commands.

```
root@kemal:~# ptree
systemd--ModemManager--gdbus
               |--{gmain}
           -NetworkManager--NetworkManager
                               |--{gdbus}
                               |--{gmain}
           -accounts-daemon--gdbus
                               |--{gmain}
               -agetty
               -at-spi-bus-laun--dbus-daemon
                               |--dconf worker
                               |--{gdbus}
                               |--{gmain}
```

If you want to see the processes with the PID numbers we can use pstree -p command.

```
root@kemal:~# pstree -p
systemd(1)-----ModemManager(512)--{gdbus}(572)
                                     |{gmain}(568)
                      |--NetworkManager(520)--{NetworkManager}(604)
                                     |--{gdbus}(619)
                                     |--{gmain}(617)
                      |--accounts-daemon(509)--{gdbus}(573)
                                     |--{gmain}(577)
                      |--agetty(584)
                      |-at-spi-bus-laun(827)--dbus-daemon(831)
                                     |--{dconf worker}(828)
                                     |--{gdbus}(830)
                                     |--{gmain}(832)
```

PID (process id), is the numbers of the processes and provides a kind of communication between the processes in the system. To see the process associated with a user, pstree <user> command is used. To see a process with sub-processes (child processes), we use pstree <PID> command.

```
root@kemal:~# pstree 968
tracker-store--{dconf worker}
               |--{gdbus}
               |--{gmain}
               |--4*[pool]}
```

## Top

To get an information anout the processes, there is another command which is called top. Despite ps tool, this tool watches the process within sudden changes on them. Working applications in system demands sources on their work load, that is why there might be sudden changes. The most basic use of this command is top form. If we use the command top -d 10 than it updates the result every 10 seconds (default value is 3 seconds). To exit, you can press q key.
