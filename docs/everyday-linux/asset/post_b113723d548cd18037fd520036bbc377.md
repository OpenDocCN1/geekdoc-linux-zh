
Setting up a RAID-1 array is relatively easy, but you will need to have a special card for your computer and two hard drives of approximately the same size. Make sure that you total up the cost of the card and the second drive if you think about using a RAID disk array. Usually it comes out to about the same cost as a two gigabyte tape backup system.

### Themes

The prime spot for themes is www.themes.org. You'll be able to find others through searching the web, of course, but themes.org has about 2000 themes on hand, ready for download and installation. You'll find plenty of searching power on themes.org, so you can find exactly what you're looking for.

# Managing Your Files

With most of your setup complete, it’s time to start managing your files. As the owner of this computer, you are effectively the systems administrator for your Linux system. You should be able to quickly and effectively fix problems. To do this, you need a good knowledge of the file system and the File Hierarchy Standard (abbreviated FHS). In this chapter, you should learn how the file system works—that is, how files are referenced and recognized, how to use some of the tools for working with the filesystem that come with Linux, and the locations of special files such as logs or configuration files.

## The Filesystem Structure

For users of MS-DOS, the filesystem (sometimes abbreviated “fs”) will be more familiar than to users of Windows9x. Microsoft patterned DOS after UNIX, so many of the conventions are similar. Those of you with no experience with DOS won’t have to become used to the differences, however.

### Files

Files in Linux serve as many purposes as they do in any other operating system. There are special kinds of files specific to a Linux system that are not present in other operating systems, the same way there are in any other operating system. We'll take a look at some of these files and others as we learn about the files in the filesystem.

### Naming Conventions

Filenames in Linux usually contain no spaces in them. Words are often separated by dashes (-) or underscores (_). Filenames usually consist of a filename and an *identifying extension*. The extension is denoted by a period and then three or four letters.

For instance, if you had taken a picture of your deck and loaded it onto your system via a scanner, the name of the file might be called "deck.jpg" or "deck.jpeg." The format of the file is JPEG—a specific picture format. Old DOS conventions allowed eight characters for a filename and three for an extension, so JPEG was abbreviated as "jpg". UNIX systems didn't employ those restrictions, so JPEG files usually had a .jpeg extension.

Common extensions are .txt or .text (text files), .htm or .html (hypertext markup language files), .jpg or .jpeg (JPEG picture files), .gif (Graphic Image Files), .tif or .tiff (tagged image file format), .mpg or .mpeg (MPEG file format), and others. Many systems administrators create directories with a .d extension to ensure that it is obvious that they are directories, not just files.

Filenames in UNIX can contain any of the 127 standard ASCII characters. This includes spaces and some special escape characters, though it is not recommended that you use spaces or those escape characters when naming files. If you encounter a filename with spaces in it, you usually have to use single quotes to read the file, if you're accessing it from the command line. (More on this when we reach the command-line interface.)

Filenames can be up to 256 characters long. Linux is a case-sensitive operating system, so Filename.txt is different than filename.txt is different than FILE-NAME.TXT is different than FileNaMe.TXT.

## Plaintext vs. Binary Formats

Plaintext files are those that you can read by opening them up in a plaintext editor. Binary files are files that are not plaintext. Binary files include not only programs, but also images, HTML documents, movies, sound files, and some system files, among others.

It is commonly thought that the words *binary file* refer exclusively to executable programs. This is not the case, though your Linux system will store programs in directories called /bin or /usr/local/bin or /sbin and others. Bin is the abbreviation for binary.

## Extensions and Associations

In Windows, even the earlier Windows 3.1x, various extensions were associated with programs. For instance, if you had a program that would open every kind of picture format known to man, you would make associations from the extensions .jpg, .jpeg, .gif, .tiff, .png, .xbm, and others to this program. Every time you double-click on a file with one of those extensions, the program you have associated with it will try to open it.

The same is true for GNOME. (This will **not** work from the command line.) However, in GNOME, associations are referred to as "mime types." You can find a list of these mime types by clicking on the control center icon (the toolbox) on your panel. There is a category labeled “MIME Types” in the control center. If you click on it, a list will appear and you will be able to add, edit, or remove any of your associations.
