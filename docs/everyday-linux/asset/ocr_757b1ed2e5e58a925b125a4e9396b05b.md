# ## Other Directories

Obviously many other directories exist. You might create a few yourself to store scripts or letters in.

However, there are also a number of special directories which you should be aware of. When we discuss the File Hierarchy Standard, we'll talk more about these directories.

# ## The Path

Perhaps one of the harder concepts for users new to the filesystem to grasp is that of the *path*. A path is a collection of directories. It doesn't group the directories into a system the way a directory groups files, however. Instead, the path is stored in an *environment variable*. An environment variable is a setting that is defined every time you log in to the system.

The path tells the computer where to look for commands. It is tedious to type in a directory and the command name every single time you would like to run a command, say `/usr/games/Fortune`. It's far easier just to type “fortune” and have an amusing message pop up. What we want to do is add the directory `/usr/games` to the path.

It is important to note that Linux does not search through the current directory to find commands. This is a small change from the MS-DOS path convention, which will search through your current directory to find commands. When you are in a command line interface, you should use the following syntax to run a command from your current directory: `./commandname`. The “./” tells Linux that you wish to use the current directory.

We will talk about setting the path when we look at special files on your Linux system.

# ## The Directory Tree

You will sometimes hear directories referred to as the *directory tree*. The filesystem is organized as a directory tree. You might find an apt comparison in your family tree, though the directory tree is a little different, since it only requires one *parent directory* to have a *child directory* or a *subdirectory*. A parent directory may have an unlimited number of subdirectories, for all intents and purposes.
