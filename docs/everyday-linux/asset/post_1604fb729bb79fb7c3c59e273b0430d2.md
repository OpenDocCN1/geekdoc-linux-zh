
## Leaving the Linux Configurator

When you’ve finished making modifications in linuxconf, you should click on the “quit” button below the list on the left. When you do this, a new page will appear on the right, telling you that the system is out of sync with the present configuration. Linuxconf will then offer to rectify the situation.

To accept its offer, click on the “activate changes” button. Once the changes are activated, linuxconf will exit. If there are any errors during the synchronization of the system, you’ll be notified and given the chance to review them. Depending on the nature of the errors, you may be asked to take some action to fix them, which usually involves either skipping a command or killing a process.

## Maintaining Your System

As systems grow older and more used, they begin to show signs of their age and use. It is important that you keep your system “well-oiled,” so to speak. You’ll be interested in adding programs and installing new packages, maybe even upgrading your kernel when the present version becomes too outdated.

To maintain your system, you’ll usually want to use the *root* user. This can be inconvenient, however, if you have other tasks to accomplish while logged in as yourself. To solve this little problem, there is a program called *su*. You cannot “*su root*” without being a member of the group *wheel*. In the last chapter we added your user account to the wheel group, so now we cover how to gain access to the root user account using the *su* command.

### Using the Terminal to Access the Super User Account

When you have logged back into your account, now is the time to begin learning to use the super user command. On your panel, there is an icon shaped like a terminal screen. Click on it, and a terminal window appears.

In the terminal screen, type in su. An error message will appear if you didn't properly add yourself to the wheel group. Otherwise, a prompt comes up, and it will look something like this: `password:`. Type in the root password.

You know that you have become root when the ending dollar sign in your prompt changes to a pound sign (#). When you have become root, you can run programs that you could not otherwise. Linuxconf, for instance, is restricted to root only. Type in “linuxconf” in the terminal window, and the linuxconf screen will appear.

You might notice that it looks differently than the rest of your user windows. This is because GNOME and Enlightenment think that you are the root user, and load the preference settings used by root. This includes the desktop theme. If you prefer to use the forest green desktop theme, but root uses the cheese theme, programs run by root will appear using the cheese theme.

You can quit linuxconf now. We don't have a reason to have it open for the moment. This is just an example of how using the su command makes life a little easier. You no longer need to log out of your account, log in to the root account, and fix a problem. Now you can simply use su to fix the problem. This is particularly useful if you administer a larger system with many users.

### Making Upgrades to Your System

As with most systems, you will want to make both software and hardware upgrades to your system. You might find that you need a new hard drive, or that a new version of the GIMP is available. Perhaps your version of StarOffice just became obsolete. Or maybe your graphics card was accidentally fried during a thunderstorm. Myriad reasons to upgrade your system assist.

### Hardware Upgrades

Windows9x pioneered the concept of “plug-and-play” devices. In other words, Windows would detect when a new plug-and-play device was attached to the system, find out what kind of device it was, and install the necessary drivers for it.

Linux has also implemented something similar in recent versions. When you boot into Linux, it will search for new hardware. This is known as a hardware detect process. It's not as refined as the Windows version, but it will pick up new hardware. For instance, when I installed a new Zip drive on my computer, it found the device and made sure it was set up properly. Some devices, unfortunately, will not be detected by this process, so you’ll have to set them up manually. This process usually is not very difficult; we cover three very common upgrades in this chapter.

### Sound Cards

If, for instance, you upgrade your 16-bit sound card to a 32-bit sound card, you will need to run the program `/usr/sbin/sndconfig`. It will probe your computer for a sound card, and upon finding one, will set it up for you. As long as you buy a sound card with Tier 1 compatibility with Linux, you won’t have to make any special effort to get it to work on your system.

### Graphics Cards and Monitors

Graphics cards and monitors are slightly more complicated, but not by much. When you install a new graphics card or buy a new monitor, you should run the program `Xconfigurator`. The installation program runs this program to configure the X-Window System to run on your computer, so it may look familiar. Most graphics cards have no problem running on Linux, and the list that appears with the `Xconfigurator` is extensive. Select your card and then you will have the opportunity to find your monitor. If your monitor is not on the list, you will probably have to set the refresh and synchronization rates—these are available in the manual that came with your monitor or from your monitor manufacturer. You may also be able to find this information from your monitor vendor.

It’s very important that you pay good attention to the refresh rates. These control how often the computer updates the information it sends to your monitor. If they are too low, you will see flickering when your monitor refreshes itself, but if you set them too high, you can burn out the monitor, causing irreparable damage.

### Hard Drives

Users familiar with the inner workings of the computer know that installing hard drives is usually not a very complicated process. Systems now auto-detect the settings of a drive, so you don’t have to edit the BIOS settings manually. This eliminates most of the difficult matters.
