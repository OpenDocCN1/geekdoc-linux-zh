
## Preparing to Dual Boot Using Two Drives

If you're going to dual boot using two drives, you will probably have several partitions already listed. I assume in this installation that you are installing Linux on the second hard drive, which will be hdb. If there are any existing partitions on this drive, they'll be called “hdb1,” “hdb5,” and what have you. The numbers don't necessarily have to go in order, so just pay attention to the “hdb” partitions in the partition summary.

You will need to delete all of the partitions on that drive. To do so, simply click on a partition and then click on the delete button. It's pretty simple. You must be warned, however, that deleting a partition will remove all of the data on the partition, and you won't be able to get it back. To delete all of the hdb partitions, simply click on each of them and click on the delete button for each in turn. Each time you attempt to delete a partition, you will be asked to confirm your choice.

## Preparing to Dual Boot Using One Drive

If you're going to dual boot using one drive, you probably won't need to remove any partitions at all. If you have a few partitions that were created when you installed your other operating system and you don't want them, you can delete them using the procedure described above. These will be named using “hda” and then a number, however.

Please remember that you cannot recover data from a partition that you've deleted, so use the delete button carefully!

## Preparing to Single Boot

You can single boot with as many drives as you'd like. The process that I describe here only removes the partitions on the first drive—if you want to make use of space on other drives, you should remove those partitions as well. Please realize that if you single boot, you're going to destroy your previous system completely and utterly. If this sounds too risky, then you should dual boot.

To single boot, that is, to boot using one operating system, you should remove all of the partitions on the first drive, that is, on the drive called “hda” by Linux. Click on each one of the partitions and then click on the delete key.

## Adding Linux Partitions

Each of the previous preparations detailed how to remove partitions and which ones you should remove. In this section, we add some standard partitions that Linux uses. To do this, we’re going to click on the *add* button.

When you click on the add button, a new window will pop up. In this window, you can specify the *mount point*, the *size*, and the *type* of the partition that you wish to create. There are other characteristics that we’re also concerned about, though.

One of these is the *grow to fill* option. This option allows your partition to take up space beyond the size you specify. I normally don’t use the grow to fill option, but it usually doesn’t matter.

Another, perhaps more significant option, is called *allowable drives*. This list will allow you to select which drives you can use to allocate space for the partition. If you’re dual booting using two drives, you should make sure that you use only the drive which you want the partition to be located on, usually hdb.

### Which Partitions Should I Add?

As explained in the note, there are a number of partitions in a clickable list near the place where you specify the mount point. You’ll want to add at least two of these and a swap partition. We’ll summarize some partitions (some of which are on the list) and then explain how to create a swap partition.

- / *(the root partition)* The root partition contains files that the computer uses to start up the system. You should allocate at least 450 MB for this partition, but more is recommended. You may wish to save this partition for last, so you can allocate space for other partitions and leave plenty left over for the root partition.

- /boot The /boot directory holds all of the data that Linux requires to boot into Linux. You can generally allocate 16 MB for this partition and do just fine. This is a convenient way to protect your boot information.

- /usr This partition will store software that’s accessible to everyone who uses the computer. You should allocate about 500 MB to a gigabyte (1024 MB) of data for these files at a minimum.

- /usr/local The files in this directory are non-commercial programs that you install. We create a partition for this to protect any programs that you install from being overwritten during an upgrade. This should have at least 500 MB of space. You may prefer to allocate more if you’re going to be installing a lot of programs.

- /home This partition will store files specific to the users on the system. (Each user is given a directory called /home/username, where username is the login name that the user chooses.) The size of this partition will vary depending on the number of users who will make use of the system. If it’s very few, you can get away with 250 MB; if it’s a great number, you should have several gigabytes allocated.

- /opt The /opt directory holds commercial programs. You still cannot find many commercial applications for Linux, so you might want to allocate about 500 MB for this partition. If you have space to spare, it wouldn’t hurt to add another 250 MB or so.

- The Swap Partition The swap partition is the portion of the hard drive that Linux will use to complement your RAM. The size of this partition should be the amount of RAM you have in megabytes, or 127 MB, whichever is smaller. So if you have 64-MB of RAM, you should have a 64-MB swap partition. To create this partition, you need to specify the type as “Linux swap.”

You may find it convenient to add other partitions. If, for instance, you want to have a drive readable by both Windows and Linux, you can create a partition with a mount point of /windows or something of type FAT32. You can then easily transfer data back and forth between the drives. This is, of course, only useful if you’re going to be dual booting using Windows.

> **Note**
> Make sure to write down the mount points and the device names of each of your partitions. If you have to reinstall Linux, you won’t have the mount point data.

## Editing Partitions

If you have two hard drives, one of which is another format, you can also specify a mount point for that drive and Linux will automatically mount the drive when you boot up the computer. To specify a mount point, you must highlight the partition in question and then click the edit button.

The only information you will be able to change within this dialogue box is the mount point. You can specify basically any mount point that you wish, but the naming convention is a little different.

In Windows systems, each different directory in the directory tree is separated by a backward slash (\) when called by its *absolute pathname*. The absolute pathname is, for all intents and purposes, the full name of the directory or folder. In Windows, for instance, much attention is paid to the System folder, but its absolute pathname is C:\Windows\System.

In Linux, folders are called directories and they are separated from one another by using a forward slash (/).

When you name a mount point, you are specifying a directory where Linux will store the files in the partition. Each of the mount points will begin with a forward slash and then a combination of directories. Most hard drives are *mounted* in the /mnt directory, so if you have a hard drive with Windows on it, you could use a mount point of /mnt/windows. Alternatively, you could use /what-chama-cali or any other mount point you desire as long as it fits the naming convention specified by Linux.

## Selecting Partitions to Format

In the event that you are using a custom installation, you will be able to specify which partitions you want to format during the installation of packages. Initially, you should select all of them—only Linux-type partitions are listed, so you won't endanger files anywhere else. Make sure that you also check the option, “Check for bad blocks during format.” This will take a little extra time, but it gives you the added benefit of ensuring that the drive is suitable to carry data.

If you’re installing Linux for the second time, or using the upgrade option from the installation to upgrade to a new version of Linux, you should not specify those partitions on which you want to save data, such as the /usr/local partition. Make sure you have your list of partitions handy.
