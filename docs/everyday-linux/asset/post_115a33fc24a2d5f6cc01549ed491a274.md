
## Creating Directories

You can create directories in a variety of ways. We’ll discuss the command line option later. As discussed when we were customizing GNOME to your liking, you can create new directories right on your desktop by right-clicking the desktop, highlighting “new” and clicking on “directory.”

You can also create new directories from the file browser. To do this, make sure that you are in the directory you wish to create a subdirectory under. (Note that you must have write permission to a directory to create a subdirectory in it. Usually you only have write permission to your home directory.) Click on “File” at the top and highlight “new.” Click on directory. Supply the pertinent information, and a new directory will be created for you.

## Removing Directories

You can remove directories the way you remove files—right-click the directory in question, and click on delete. This is an interactive process—you’ll have to tell GNOME that you really do want to delete this directory.

Again, exercise caution when going about deleting directories—you can’t undo this, either.

## Mount Points

One of the more interesting aspects of Linux is that each mount point is recognized as a directory. When you mount a drive or use a partition, you reference it by a system directory. In both Windows and DOS, this was accomplished by the use of “drive letters.” Every drive is associated with a letter and its own equivalent to the root file system on a Linux machine.

In some ways, this Microsoft invention is convenient. File storage is often-times easier to understand and more readable. The advantage of the Linux system, however, is that it is completely transparent to the user. This allows you to include mount points from almost anywhere—even other computers—without users knowing where the files are located. It presents a view of your system that is simple to understand and requires little to no outside knowledge of the hardware on your system. This is a very specific design principle designed so users don’t have to understand much of the system to use it.

## Special Files

Linux makes use of several different kinds of special files. Often you may have to modify these files in order to set certain preferences, such as your path.

### RC Files

The first group of files we should talk about are called “RC files,” named after the extension or suffix they usually have. Examples of these files are “.bashrc,” “.pinerc,” “.cshrc,” and others.

RC files usually control preferences for programs or your shell. Pine, a text-based mailing program, reads a control file called .pinerc to set preferences, such as message width, quoting marks, your real name, your domain name, and a host of others. The file .bashrc controls how the Bourne-Again shell (bash) operates by setting environment variables such as the path, the terminal type (or emulation), user defined aliases and commands, and many other options. (Bash is the default shell for Linux users.)

Let’s examine a sample .bashrc file with a path statement in it and dissect it line by line:

```
PATH=$PATH:$HOME/bin::/bin:/usr/contrib/bin:/usr/bin:$HOME:
$HOME/bin/c:/usr/sbin:/usr/local/bin:/usr/local/lib/interlink/bin:/usr2/home/help/bin:/usr/games
export PATH
```

When using a variable in a statement, you refer to it using a dollar sign ($). When setting a variable, such as PATH, you do not use the dollar sign. So PATH=$PATH says, “Set the path equal to what it is already.” This is useful if you don’t want to lose the preset path.

Every directory listed in a path is separated by a colon (:). You specify each directory in a path by the full system name.

The variable for your home directory is called $HOME. This is a preset variable that you usually cannot change. When using the command line, the shorthand for this variable is the tilde and a forward slash (~/).

So when we write PATH=$PATH:$HOME/bin, we set the path equal to the old path and add on the /bin directory in your home directory. You can break down each of these different directories the same way.

The export command is one that you can run from the command line, but probably won't very often. For our purposes, we'll be using it from the .bashrc file or something similar, though you can use it to set other variables if you need to. What the export command tells the computer to do is to finalize the setting. It will ensure that your path is set.

If you're not sure of what other directories to put into your path, don't follow the following directions. You will likely figure them out as you become more familiar with your system. But you probably don't need to modify your path in any way. When the root user installs more programs, he may have to modify the global path—the one assigned to every user if he doesn't have a path defined in the .bashrc file—so that users can make use of the programs he installs. This file is usually located in /etc/bashrc.

To edit your .bashrc file, you need to open up your home directory. More than likely, the file browser is not set up to display hidden files, so you will need to change the preferences.

To change the preferences, click on “edit.” At the bottom of the edit menu is an option conveniently labeled “preferences.” Click it. The first tab on this screen deals with how you display files; click on “show hidden files” to display hidden files. Then click OK or Accept and your home directory will probably become much more populated. (You can follow this same procedure to stop displaying hidden files if you desire.)

After changing your preferences, a longer file listing will appear. Double-click the file called .bashrc. When the window asking you which application to use to edit the file appears, you should open the folder labeled “Applications” and click on “GEdit.” The GNU Editor will appear with the contents of your .bashrc file in it. You may edit this at your pleasure.

The .bashrc file is used only by the Bourne-Again shell, not by any others. Many different shells exist (such as the C Shell, the Korn Shell, the restricted shell, and so on), and they each use a different RC file to set environment variables and other preferences. Since the default shell is bash, we have supplied the method for editing its RC file. You may see files like .cshrc or .kshrc in your directory—these may be files for other shells.

## Configuration Files

There are other configuration files as well. These usually have extensions of .cfg or .conf. Most of the global configuration files reside in the /etc directory. You would find the configuration for LILO here under the filename lilo.conf. If you use the lynx web browser, you would find its configuration file under lynx.cfg.

It is important that you know the existence of these files, but it is equally important that you not edit them without understanding the contents of the file and what editing them means. If you mess up (the technical term is “corrupt” or “FUBAR”) lilo.conf, your computer may not boot properly. Without a boot disk, it would be impossible to get into the system.

Global configurations are found here as well. If your users do not set their own paths, for instance, you will find RC files in this directory which provide a global path for them. These files are usually not hidden. The global .bashrc file is listed under .bashrc, for instance.

![](img/92fb6d8ad19de3b3470ba95c7b71b82e_135_0.png)

The /etc directory contains most of the files your system requires to run. You can explore this as both a root user and as a regular user, so use your regular user to look at the contents of files (some are not accessible, such as user lists or password files) and to poke around. This will minimize the risk of damaging any files as your Linux system requires to operate. When you need to modify files, use the root user and exercise extreme caution. Make backups of configuration files by copying them and adding an extension of .bak.

## Lock Files

Lock files are special files used by Linux to see whether you are running a program more than once. When you run a program, a lock file is created for that program. If you suspend the program or try to start it again, you will be informed that the program is already running.

These are usually stored in the /tmp directory and are deleted when you exit the program or kill the process. Your first encounter with a lock file will probably come when you use Minicom. If the modem is either in use or hasn't been reset properly, you'll get a message that says, "/dev/modem is locked" when you attempt to start the program.
