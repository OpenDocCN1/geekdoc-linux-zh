
Your hard drive likely comes with instructions about how to install it. Follow these instructions. When you boot into Linux, you will need to use the root account (or the su command, as the case may be) to format the drive for use. Follow this process carefully, otherwise you may format a drive already in use and lose the data on it.

**Step One**—To format a drive, you must use the command line and be logged in as the root user. There is a disk management tool in X-Windows, but it will not allow you to format hard drives. (It is useful for formatting floppy disks, however. It is under the system menu.)

At the command line, type `dmseg | more | grep hd` (if you are using SCSI devices, replace the hd with sd). This will list all of the hard drives on your system (probably more than once). Find the drive you just installed. It will have a device name. If it is the primary slave drive, it will be hdb (this is what I assume for our example).

**Step Two**—The second step is to run the `fdisk` command. To do this, type in `/sbin/fdisk /dev/hdb` at the prompt. (If you are using another drive other than the primary slave, replace it with the appropriate device indicated by our first step.) A screen will appear that lists all of the partitions currently on the drive. If you just bought the hard drive, it may have a single partition listed (if it is preformatted) or nothing on the screen. If it is a used hard drive, you will have to delete all of the partitions.

These are the command keys you should use to navigate through `fdisk`:

-   **h** Pressing the letter *h* will provide you with a help screen—this is one of the best ways to become familiar with fdisk. Use it any time you are unsure of what to do. You can never be too careful when handling data on a hard drive.
-   **d** If you press the *d* key, you will delete a partition. To delete a partition, you must specify which partition by typing in the number at a prompt.
-   **n** To create a new partition, press the letter *n*. You will be asked to supply a drive format. The default is format number 83, which is the Linux ext2 format. Unless you wish to make a partition for another operating system, use this as the default. You will also be asked to specify how large you want to make the partition. The total size of the drive will be available in a table above the prompt. You should create the partitions in numerical order, so the first will be /dev/hdb1, the second /dev/hdb2, and so on.
-   **q** Pressing *q* will cause the program to quit without writing the partition table. This means that no changes will actually be made.
-   **W** You must press a capital *W* if you want to write this data to disk and make it permanent.

Use these commands to create a new partition and remove any extra partitions on the drive that you do not want. Remember to do this to the new drive only, not to an existing drive that has data you want to keep! If you delete a partition, you cannot get the data back!

**Step Three**—You must now create a file system on the new partition. To do this, type `mkfs /dev/hdb1` at the prompt. This is the first partition that you created on the device /dev/hdb (the primary slave hard drive). You must use this command for every single partition on the drive if you created more than one.

The *mkfs* command stands for "make file system." It is analogous to the MS-DOS and Windows command *format*. It creates the Linux file system on a hard drive. If you created a partition that is not a Linux partition, you will have to format it using the operating system for which it is designed. (It is possible to create file systems for MS-DOS, Windows, and other operating systems under Linux, but it is usually better to use its respective operating system instead.)

**Step Four**—You will then need to make sure that the drive is mounted every time you turn on the computer. To do this, run *linuxconf* (either from the main menu, the command line, or by clicking on the system configuration button in the control panel) and find the category "File systems." Click on "Access local volume."

Click the "Add" button at the bottom of the list of devices. You will then need to specify the mount point of the drive and its format. Do so and then click Accept. The drive will then be in the list. If you highlight the drive, you will then be able to mount it. If you want it to be mounted every time the computer boots up, click on the tab labeled "Params" and change that option.

You can then quit and activate the changes.

## Zip and Jazz Drives

If your new drive is an IDE Zip drive or a Jazz drive, it will be on the fourth partition position. For instance, if your Zip drive is a primary slave IDE drive, it will be called *hdb4*; if it's secondary master, it would be *hdc4*. Mine is in the secondary slave position, so its device profile is /dev/hdd4.

## Software Upgrades

Most users will wish to make software upgrades in addition to hardware upgrades. These upgrades can be as simple as installing new software from the Internet or using the GNOME Red Hat Package Manager (GnoRPM) or as complex as upgrading the kernel. We won't cover the complex upgrades in this book, but there are a number of resources we can point you to that will provide you with more information than you really ever wanted to know.

## The Difference Between Regular Software and Packages

Regular software often comes in a compressed file format with the extension .gz or .tgz. The compressor used to make these files smaller is called “gzip,” and it's the GNU version of the popular PKZip software. You must decompress this software, and often untar it (tar stands for tape archive; it is a program that stores files in archives without compressing them) in order to do anything with it. Most of these programs must then be compiled on your computer. This is why we suggest installing the C Development Libraries, since much of the software you may download will make use of these libraries and files.

Packages, on the other hand, are easier to work with and install. These require the program GnoRPM or the command line version, *rpm*. RPM stands for “Red Hat Package Manager” file, a special format of file that only Red Hat can read. Since Red Hat is one of the most popular distributions of the Linux operating system, you will probably be able to find most major software programs in the RPM format. When we look at using GnoRPM, you'll see why it's usually so much easier to use RPM format files than the “tarred” and “gzzipped” versions you'll find on the Internet.

## Tarred Files; Gzipped Files

When you download software from the Internet for your Linux machine, it will likely come in this form: the program name, followed by its version, followed perhaps by the release date or some other serial number, followed by the extension .gz or .tgz. The .gz extension means that the file has been compressed using the GNU version of Zip. The .tgz extension means that the file was first archived using the program “tar” and then gzipped. (Of course, one is not required to use the .tgz extension if he tarred the program first. This naming convention is not entirely universal yet.

In order to install these programs, you will have to read the information that they provide with the package. To get this information, you have to unzip the file, and if it is tarred, untar the file as well. You can do this quite easily from the command line.

You usually download files from the Internet into your home directory. (This is not always the case, but it’s a safe bet.) When you hit the terminal icon on your panel, you immediately enter your home directory. If the files are located in your home directory (typing `ls -l | more` will produce a paginated file listing), you should type `gunzip filename`, where “filename” is the file that you downloaded. It will then display the files it is extracting.

If it extracts a file with a .tar extension, that file has been made by the tar program. You should type `tar xvf` to untar the archive. It will probably make its own directory with the files in it. If you start Midnight Commander (type `mc`), you can more easily navigate the file system. Mind the new directory created when you untarred the file and look for a file in this directory called INSTALL (all caps). It will provide you with installation instructions.

These instructions vary from program to program; the quality varies as well. Usually you can find frequently asked questions (FAQs) on the Internet that will provide you with some extra help if you need it.

## Using GnoRPM

GnoRPM is usually much easier to use than the command line interface. For starters, it includes a number of easy-to-use features. If you want to install a specific package from your installation CD (all of the RPMs that came with your original Linux distribution are on that CD), it’s a simple point-and-click process. If you realize that you never really use a package and don’t want it cluttering up your computer anymore, you can remove it easily, too. And perhaps you know the full name of a command (both the path and the command name) and want to find out what package it belongs to—you can do that too. In addition, each package has a built-in set of information containing a short description of the package, its size in bytes, and a complete listing of all the files included in the package. GnoRPM also comes equipped with what is known as “Web Find,” an option that will search RPM databases on the web to find specific packages that you search for.
