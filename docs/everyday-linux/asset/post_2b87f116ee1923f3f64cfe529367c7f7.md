
# The File Hierarchy Standard

The File Hierarchy Standard, or FHS for short, is a system that standardizes the names of certain directories that contain important information. The computer industry requires more than a little standardization to make up for the differences in education of its members. By standardizing where most of the major files go, all systems administrators regardless of educational background or understanding of Linux or UNIX have a specific map of where files need to go.

This provides newer administrators a guide by which they can plan the layout of a system; older administrators will appreciate the regularity of the standard.

The standard itself is quite lengthy and complicated. We'll include a brief summary of it here, however, and supply further references for your perusal.

- /bin The /bin directory contains program files that are available to all users. These are typically considered “essential.”
- /boot The /boot directory contains static files used by the boot loader. You may want to create a partition for this directory when you install your system—it will add a little extra protection for these files.
- /dev All of your device files are stored in the /dev directory. These range from hard drives, to SCSI devices, the CD-ROM, floppy drive, and many, many others.
- /etc The FHS calls this directory “Host-specific configuration information.” It’s where most of your configuration files that are used for the system are stored. Both conf and rc files are located in this directory. These are usually global configurations.
- /etc/X11 Your X-Window System configuration files are stored in this directory.
- /etc/opt When you install commercial programs, their configuration files are stored in this directory.
- /home User directories are stored in the /home tree. This is labeled “optional” in the FHS, but most users of Linux prefer to have one. If you have a single-user system, you may not wish to include it.
- /lib The /lib directory stores shared files and kernel modules. (A kernel, as one actor put it, is the “brains” of your operating system.) These files are essential. Users usually don’t access these files directly—the programs that they use do. (The GIMP, for example, makes extensive use of GTK+ libraries stored in this directory.)
- /mnt This is the directory for the mount points of temporary file systems.
- /opt You usually store commercial programs here.
- /proc Process and kernel information is stored in this directory. Some users may wish to make a partition for this directory.
- /root This is the home directory for the root user; it is optional. (Most root users don't get a lot of personal attention.)
- /sbin System program files were once stored in the /etc directory. They are now stored in the /sbin directory (which stands for "system binaries").
- /tmp The system will make use of this directory to store temporary files and lock files.
- /usr Most user files are stored here. The /usr directory tree has a hierarchy of its own. (You can read about it at the FHS web page listed at the back of the book.)
- /var The /var directory holds important system information such as logs or cached files. The /var directory also has its own hierarchy which is listed on the FHS web page.

This is just a small summary of the File Hierarchy Standard of organizing your file system. You probably won't have to create any of these directories yourself, but the information is useful when you want to add directories to your path.

When you install Linux, you may also find that some of these files, such as those stored in the /boot directory, are quite vital to your system. Some users create extra partitions for these files. (A partition for the /boot directory would need to be around sixteen megabytes.)

# Using Midnight Commander

Midnight Commander is a text-based file management tool. You probably won't use this too much unless you find yourself using the command line frequently. This is an incredibly powerful tool with myriad options.

For the moment, you probably only need to concern yourself with the navigation principles of Midnight Commander. That alone will allow you to take advantage of many different options. It will also allow you easy access to experimenting with your system.

When you start Midnight Commander, you will be presented with a window on both the left and right sides of your screen. They are identical. To switch between these two windows, press your tab key. You can maintain two different file listings at once this way.

To move up or down in your file listing, use the up- and down-arrow keys. When you want to enter a directory, press the Enter key. The parent directory is noted by the ../ we spoke of earlier in the chapter; the current directory is denoted by ./ .

At the bottom of the screen, the numbers 0–9 are listed. These correspond to “F-keys,” which are the ones labeled F1–F12 at the top of your keyboard. You can use each of these F-keys to perform the associated task. (Next to each number is an operation, such as copy, delete, view, and so on.)

To invoke Midnight Commander from the command line, type mc and press the enter key.

# In Summary

While we haven’t covered every single aspect of the Linux file system, this chapter serves as a brief introduction to it. Most users won’t need much more information—others may be interested in learning more. You can find a lot of the information you seek on the Internet through various pages. Make sure to check the back of the book for more information.

You can always learn more about the file system by experimenting with it. It’s usually pretty hard to damage the system when you’re using your own user, so have fun and explore a little bit. You can’t remove any files but your own, so don’t worry about running around in the file system.

After having made much reference to the command line throughout the course of this book, it is time to step back and take a look at it. Most users will find the command-line interface rather dull, unexciting, and complicated. However, there are some commands that cannot be run from inside the X-Window System and must rather be run from a terminal window. And you may find that the command line is more than just geekspeak or esoteric technobabble. It can be truly useful and interesting. Well, at least useful.

The command-line interface usually seems quite technical and difficult to most users, even some of the more proficient UNIX users. But it is important that you be able to understand it conceptually, since that will allow you a measure of comfort using it. As they say, “Know thine enemy.”

First, let’s introduce the terminal, since that’s how you will interact with the command line.

## What Is a Terminal?

The terminal is sometimes called the “console.” (When we installed Linux, there was a component called “console multimedia.” This component contains programs that will play sound files and movies from the command line.) You will find that both of these terms, that is, terminal and console, are used imprecisely.

Precisely speaking, defining a terminal isn’t the easiest of tasks. Monitors connected to a computer through a network are called terminals. Your library probably makes use of these terminals to hold its card-catalog database.

The word terminal is also often used as shorthand for terminal emulation. Terminal emulation is essentially a keyboard “map” that a remote computer uses to ensure that what you type on the keyboard is what you see on the screen. (It’s called a map because it maps out the keys on the keyboard so that the terminal knows how to react when you press a button like the tab key, for instance.) Examples of such terminal emulations are VT-xxx (52, -100, -202, -220, and so on), ANSI, and others. The most commonly used text-based terminal is VT-100.

We have been using the word “terminal” in the context of a window that allows you access to the command-line interface. This is sometimes called a virtual terminal, since you aren’t actually on a physical terminal on a network, like the terminals on our library network we described above.

You should assume that we use the final definition of terminal, a virtual terminal, when the word is used unless otherwise indicated.

## What Is the Command Line?

Before you use the command line, it is helpful to know conceptually what it is and what it can do for you. It is relatively simple to give you a list of commands and say, “This is what they do, now go have fun.” But you will probably learn little from that kind of an example, and it is usually more comfortable to know a little bit about what you’re getting into before you go about doing so.

So what we’d like to do now is point out a few things about the command line, such as what it actually is and what we do with it. Later we’ll look at why you’d even want it, if it seems so esoteric and scary.
