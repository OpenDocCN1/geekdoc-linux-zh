## Making Drives User-Mountable

Before we actually explain the process, it would be a good idea to introduce the concept of mounting and unmounting drives. When we installed the Linux operating system, we had to specify *mount points* for each one of the partitions we created, and we explained that Linux recognizes each drive (be it a floppy drive, CD-ROM, or hard disk drive) as a part of the directory tree.

### Mounting and Unmounting Drives

When you make a drive accessible, this is known as *mounting* a drive. When you mount a drive, the files on it become available for general access (depending on what permissions you set on the drive when you mount it). Conversely, when you *unmount* a drive, you deny access to the drive—it’s as though it doesn’t actually exist on your computer.

When a drive is *user-mountable*, every user can mount and unmount the drive. Most of the time, only drives that make use of removable media, such as floppy disk drives, CD-ROM drives, or Zip and Jazx drives, are user-mountable. To make a hard drive user-mountable would allow any user to make the main files of the system unusable—it could crash the computer.

### To Make a Drive User-Mountable

This is the process that you’ll take to make a drive user-mountable.

This time, we look for a category on the right called “File Systems.” A subtopic to “File Systems” is called “Access Local Volume.” Click on “Access Local Volume,” and a list will appear on the right, showing all of your drives and partitions; the floppy drive and CD-ROM are also listed, as are Zip drives and others you may have installed.

First we’re going to make the floppy drive user-mountable. This is one of the more commonly used drives, and it also makes use of removable media. This gives us reason to make it user-mountable. What happens if it’s not user-mountable is that your users will have to ask you to mount the drive every time they need to read the contents of a floppy disk.

The device name of your floppy drive is /dev/fd0. This is how the system knows your floppy drive. Click on the line where you see that device name. A new dialogue box appears on the right; this is known as the volume specification page.

We’re interested in the “Options” tab. The first couple of tabs allow you to configure the floppy drive for use; since it’s already configured for use, we don’t want to change any of those settings. Click on the options tab and the options list appears; from this list, you should find “User mountable.” Click it, and then click on the Accept button. If you wish to make other drives available to your users, repeat this process for the other devices in the list (e.g., a CD-ROM, a CD writing device, a Zip drive, and so on). Make sure that you do *not* make hard drives user-mountable.

## Other Functions of the Linux Configurator

So far, we’ve really covered only three different functions of linuxconf. However, this is an incredibly versatile and powerful tool for systems administration. In this section, we go over some other common applications of linuxconf.

Linuxconf is organized into two sections: config and control. The config section allows you to modify the configured status of your system. The control section allows you to perform several actions on components on the system. Most of your configuration will be in the config section, so we cover only subtopics under that section here. The control section is more or less self-explanatory when you go through each of its operations.

Obviously this is not a step-by-step guide of how to use the Linux Configurator. Experimentation with Linux is one of the best ways of learning how to use the system, and the sheer number of tasks you can perform with linuxconf makes writing a simple guide to it nearly impossible.

## Networking

Typically you won't have to make many changes to the networking section. If you switch ISPs or find that your current network data is outdated, some of the settings will need to be changed. These are typically service-dependent, however, so you will need someone from technical support or the network administrator to help you with the changes.

One other item that you may find convenient to change in this category is the hosts file. If you find that you're accessing another system frequently using a telnet prompt or something similar, you can add an entry in the hosts file that will make an "alias" of sorts. Then you could use some shorthand abbreviation for that system. For instance, I have a line in my local hosts file that reads

```
164.107.42.62  stdsun    stdsun.cis.ohio-state.edu
```

Rather than typing in "stdsun.cis.ohio-state.edu" every time I want to access the system, I can type in "stdsun" instead.

## Modifying Boot Loader Properties

It’s usually suggested that you not modify the boot loader properties, since doing so can result in an unbootable system. However, you might become relatively bored of the labels “linux” and “dos” to boot parts of your system, or using a boot disk may simply become troublesome.

If you modify the boot loader, you’ll have a couple chances to back out of making changes if your courage melts like wax once you’ve finished. If you do make changes, however, and they result in an unbootable system, make sure that you have a boot disk on hand. It will also help if you have an installation CD for your other operating system (if you’re dual booting).

In this section, I won’t go into any procedures for installing LILO (if you didn’t install it to begin with). But I will talk about a couple of the terms you’ll run into.
