# ## Special Files

Linux makes use of several different kinds of special files. Often you may have to modify these files in order to set certain preferences, such as your path.

# ### RC Files

The first group of files we should talk about are called “RC files,” named after the extension or suffix they usually have. Examples of these files are “.bashrc,” “.pinerc,” “.cshrc,” and others.

RC files usually control preferences for programs or your shell. Pine, a text-based mailing program, reads a control file called .pinerc to set preferences, such as message width, quoting marks, your real name, your domain name, and a host of others. The file .bashrc controls how the Bourne-Again shell (bash) operates by setting environment variables such as the path, the terminal type (or emulation), user defined aliases and commands, and many other options. (Bash is the default shell for Linux users.)

Let’s examine a sample .bashrc file with a path statement in it and dissect it line by line:

```
PATH=$PATH:$HOME/bin::/bin:/usr/contrib/bin:/usr/bin:$HOME:
$HOME/bin/c:/usr/sbin:/usr/local/bin:/usr/local/lib/interlink/bin:/usr2/home/help/bin:/usr/games
export PATH
```

When using a variable in a statement, you refer to it using a dollar sign ($). When setting a variable, such as PATH, you do not use the dollar sign. So PATH=$PATH says, “Set the path equal to what it is already.” This is useful if you don’t want to lose the preset path.

Every directory listed in a path is separated by a colon (:). You specify each directory in a path by the full system name.

The variable for your home directory is called $HOME. This is a preset variable that you usually cannot change. When using the command line, the shorthand for this variable is the tilde and a forward slash (~/).

So when we write PATH=$PATH:$HOME/bin, we set the path equal to the old path and add on the /bin directory in your home directory. You can break down each of these different directories the same way.
