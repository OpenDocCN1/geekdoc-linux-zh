
## File and Directory Manipulation

If you don't use the Midnight Commander as much as you can (it's usually easier than navigating directories in a regular manner), you'll need to know how to remove files and directories and make directories.

There are several commands we'd like to look at: cd, ls, rmdir, mkdir, mv, and cp. These commands will allow you to navigate the directory tree and manipulate what files and directories are in it.

Make sure that you're in a terminal. The first step is to see what's in your directory. To get a file listing, type `ls`. A series of files and directories will appear, though they'll be in a short form, not the longer form we saw above. If you want to see your files distinguished from one another (executable files will be starred with an asterisk; directories will end in a forward slash), you can type `ls -FC`. This will force the listing to fit into columns (C) and produce a formatted output (F).

This is your file listing. We created a file called “myfile” in the permissions section of this chapter—it should be listed here. It's more or less wasting space, so we'd like to remove it. If you changed the ownership of the file to root, you're going to have to change it back to your own user. (Type in su. Then follow the procedure for changing the owner of the file mentioned above. Type in exit when you're done.)

Once it's your file again, or if you never changed the owner in the first place, we can remove it. To remove a file, you use the rm command. Its syntax is as follows: `rm [options] [filename]`. We have no options here, so we simply want to type in `rm myfile`. You will get no confirmation that the file is actually deleted. All that will happen is you'll see another blank line appear. (If the file didn't exist, you would get an error message to that effect, however.) To find out if the file is there or not, you'll have to look at another file listing.

Now let's do something a little more exciting. Well, maybe a little more exciting. Many users will want to save pictures that they see on the Internet or that others send to them via e-mail. If you receive enough, it's rather stupid to keep them all in the main directory—they'll clog up your file listing and make it difficult to know what you've got stored there. To fix this problem we'll create a pictures directory.

To do so, we'll use the `mkdir` command; its syntax is as follows: `mkdir [directory]`. Simply type in `mkdir pictures` to create the directory.

Like the rm command, you’ll find that you don’t get any confirmation that the directory was actually created. So you’ll need to do another file listing to make sure that it’s there. (It will be, don’t worry.)

To further our example, let’s assume for the moment that your father sends you a lot of pictures he’d like you to store on your system while he’s reformatting his hard drive—it’s information he doesn’t want to lose, but not enough to justify using a tape backup or something similar. You might want to make two pictures directories to hold his pictures and your own, so you would use the mkdir command to do so. However, now your original pictures directory might be inappropriately named—you’d like to rename it to “mypictures.”

This is where the mv command comes in. The syntax for the mv command is `mv [ source ] [ destination ]`. This command not only renames files, it can also move them. The syntax for both is the same. To change the name of your current pictures directory to “mypictures,” you would type in `mv pictures mypictures`. Again, you’ll get no confirmation, but you can do a directory listing to ensure that the directory was appropriately renamed.

So you’ve received these pictures from your dad and created a directory for them called “dads\_pictures.” When you got them, though, you saved them to your home directory, and now you’ve got a slew of images in there that need to be copied to the “dads\_pictures” directory. Enter the cp command. Cp is short for “copy,” and its syntax is as follows: `cp [ source ] [ destination ]`. The difference between the cp and the mv commands is that mv will actually remove the file after copying it to its destination.

To move all of the files with an extension .jpg, we use what is known as a *wild-card character*. A wildcard character is used to substitute for all of the other characters that match the argument you pass to a command. In this case, we’re passing all files with the extension .jpg to the command cp. The wildcard character is the asterisk (*), and we write “all of the files ending with .jpg” in computer lingo as “*.jpg”.

So, let’s copy all of the files with a .jpg extension to the “dads\_pictures” directory we created. To do this, type `cp *.jpg dads_pictures`. There’s no real confirmation that this worked. However, unlike some of the commands we’ve looked at, using a simple ls command will not demonstrate that we’ve done the job.

To look at the files in the “dads\_pictures” directory, you need to type the command `ls dads_pictures` rather than just `ls`. If there are files in the directory, then you know that you’ve done the job right and things are just fine.

But if you do a regular file listing, you'll notice that the files that you copied are still there, clogging up space and annoying you. I had you do this for two reasons. The first is to give you more practice using the rm command. The second is to demonstrate why people like the mv command so much. (To remove these files, type rm \*.jpg.) By using the mv command, you can both copy files and remove them from the source position at the same time.

If you created any directories in the course of this lesson and don't think you're going to need them, you can remove them in two ways. The first, and the one you'll probably want to use more often, since it's safer, is the rmdir command. To use it, the syntax is rmdir \[ directory\]. The other way is to use the rm command using the -r command line option. The syntax for that is rm -r \[ directory\]. This is a more dangerous method because it will search through a directory and remove all the files in it and subsequent subdirectories. The rmdir command will not work if there are files or subdirectories still in a directory, which can be annoying sometimes. This explains the proliferation of the use of the rm version.

## 8 The Command-Line Interface

### Mounting Drives and Partitions

So far, we have only mounted and unmounted drives or partitions from GNOME. While this process is quite simple—just use the drive configuration utility—you can also do it from the command line rather easily. You might find the command line version more useful if you wish to mount a drive from your regular user account. Logging back into root to use the disk configuration utility is annoying at best.

To mount drives from the command line, we're going to use the mount command. The basic syntax of mount is as follows: mount -t \[ type\] \[ device\] \[ mount point\]. There are several different types of drives that Linux supports. Here's an incomplete list with their descriptions:

- **ext2** This is the basic Linux file system. All newer drives formatted under Linux will use this file system.
- **ext** This is the old Linux file system—it's now obsolete, so you'll only use it if you have an older Linux drive to mount.
- **vfat** Drives which make use of the FAT32 allocation table, such as those formatted under Windows98 and 2000, or Windows NT 4.0 and higher.
- **msdos** Drives compatible with MS-DOS and using the FAT16 allocation table should be mounted using the msdos type.
- **hfs** Users who want to mount drives from their Macintosh computers should use the hfs file system.
- **iso9660** This is the type that you'll use for your CD-ROM or CD recording device.

These are the more common types that you'll use, but you can also use types such as minix, bsd, and many others. Even OS/2 formats are supported.

After the type comes the device. The device is simply a device profile stored in the /dev directory. We talked about how IDE and SCSI devices were named in Chapter Two, when we talked about the partition summary categories. If you're not sure what devices are active on your system, you can always run the disk configuration utility or linuxconf to find out.

The mount point is usually an empty directory stored in the /mnt directory. For instance, your mount point for the floppy drive is /mnt/floppy. For the CD-ROM, it's /mnt/cdrom. You should create directories for the various drives you wish to mount; my Windows disk, for instance, is mounted on /mnt/win.

So let's go through the process of mounting a drive. I'm going to use one from my computer as an example. I dual boot, meaning that I'm running both Red Hat Linux and Microsoft Windows 98 on the same computer. When I use Red Hat, I have a few data files from Windows I still like to tool around with, so to take advantage of them I have to make sure that my Windows drive is mounted.

To do this from the command line, I first make sure I'm the super user (by using the su command). I then type in mount -t vfat /dev/hdb1 /mnt/win. This translates to, "Mount a drive of type vfat with a device profile stored in /dev/hda1 at the mount point /mnt/win." A couple seconds later, the mount point has grown a directory tree with all of the information from my Windows drive in it.

This is a simple process, though it might take you a little while to get used to. If you want to see what drives are mounted at the present time, simply type mount without any arguments. A list of the devices and mount points will appear. If you want to unmount a drive, you'll use the umount command. The umount command is considerably easier to use than the mount command, which you'll notice rather quickly. The syntax of umount is as follows: umount [ device ] or [ mount point ].
