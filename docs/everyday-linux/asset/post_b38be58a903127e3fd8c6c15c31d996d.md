
If you simply don't like your computer mouse, or enjoy making procedures harder than they need to be, you can also use the text-based interface navigation instructions that follow.

## Text

If you're running the text install, you will probably have to navigate through the procedure entirely with your keyboard. This may seem rather inconvenient. And it is. That's why we recommend using the graphical installation.

To move forward to another option, press your tab key. If you want to move backward, press the alt (or meta) key in conjunction with the tab key. Use the enter key to select options (such as which hard drive you'll install a partition on) and to press the buttons at the bottom of the screen.

You'll also notice that the last line of the screen has some F-key options, like F1, F5, F12, and so on. You can use them to navigate as well.

## Initial Configuration

The first configuration options you're going to set involve basic settings, like what language you speak, which keyboard you use, and what kind of mouse is attached to your system.

The first two are fairly simple. The defaults will probably work just fine. When you select your keyboard, you can fine-tune some settings, but you don't need to. The help dialogue at the side of the screen will assist you with deciding which keyboard you should use. Most keyboards now do not come equipped with composition keys (so you can create international characters straight from the keyboard).

The mouse, however, is a slightly more complicated matter. Linux is a UNIX derivative, and will make good use of a three-button mouse. If you don't have a three-button mouse, you can choose to emulate a three-button mouse. To take advantage of the “third button,” you must press both the right- and left-hand mouse buttons at the same time.

Another popular mouse feature with spotty support is the wheel. The wheel on most modern mice will allow you to conveniently scroll through pages of text in a document or on the World Wide Web. Lamentably, Linux itself does not come equipped with support for the wheel on your mouse; however, various applications do.

At the time of this writing, Linux also didn't offer overwhelming support for USB devices. So if you're using a USB mouse, you should probably buy a USB-to-PS/2 adapter. They're relatively inexpensive, and a local computer store should carry them. Drivers for most USB devices are presently being written, but almost none of them made it into the Red Hat Linux 6.2 distribution.

## The System Installer

The most complicated bit of installation – and the longest – has arrived. There are a lot of steps to this part, so stay focused. (It's easier if you have something with you to eat, drink, or read when your input isn't needed.)

### The Install Type

The first major decision you'll need to make is what installation type, *or class*, you want to use. There are four choices for you to make. I'll explain them briefly here—you'll notice somewhat similar explanations to the left in the help dialogue box.

#### Workstation with GNOME

If you want to run the GNOME desktop with a minimum of fuss, you can choose this option. I recommend you use GNOME, regardless of what installation class you decide on–first, because it's a phenomenal desktop tool, and second, because a godly portion of this book will be lost on you if you don't.

A *workstation* in this context is a computer that is not serving files to a network. Most home users are not in a capacity to be a server (to serve files), so a workstation class installation is more appropriate.

GNOME is more or less becoming the standard to beat in the desktop environment. KDE, your other option, is close behind, however.

#### Workstation with KDE

If you're more familiar with UNIX or Linux, and you prefer KDE over GNOME, feel free to pick this option.

#### Server

In the event that you're serving files on a network, maybe from your college dorm room or on a home LAN (local area network), you may want to try a server-class installation. This will install various extra programs that will allow other computers access to yours (this can pose security risks, of course).

It's not usually recommended that you use a server-class installation unless you're fairly competent with Linux. “Fairly competent” means that you can do your own systems administration and security troubleshooting.

![](img/92fb6d8ad19de3b3470ba95c7b71b82e_49_0.png)

The attraction of using these pre-defined installation classes is that they will simplify the installation process. They will eliminate your need to create your own partitions, and you won't have to do much in the way of selecting components.

The workstation classes won't cavalierly wipe out any information on any drives that don't already use Linux, but the server installation class will. It will format **all** of your drives and remove **all** of the information on them. This is another reason you should be quite wary of choosing the server installation class.

#### Custom

This leaves us with the fourth and final installation class—the custom installation. The folks at Red Hat kindly suggest that if you're new to Linux that you choose one of the workstation installation classes, and if that seems like a more appropriate route to you after reading about the custom installation class, then by all means choose it.

If you haven't guessed so from the tenor of that paragraph, it is my suggestion that you do use the custom installation class. The custom installation class is the only one that will allow you full autonomy over the installation—which **partitions** you want to create, how large you want them to be, in what format, and what packages you want to install.

The custom installation class is easiest to use when you have a fairly large hard drive—one that's around 4 GB or so. If you have an exceptionally small hard drive—in the neighborhood of a gigabyte or less, you may find simply using the GNOME workbench class easier.

For the purposes of this installation, I assume that you have chosen the custom installation class. If you haven't, some of these steps will not apply, and you can skip over them.

### Creating Partitions

The next order of business is the creation of partitions. In my early days of computing, mentioning partitions was scary stuff, and it still can be today. To combat whatever tremors may be knocking in your knees, we're going to distill partitioning into its conceptual components. We're also going to explain why in the world you'd want to mess around with them.

This will likely take up some space in the book—if you're not interested or already know enough about partitions to satisfy yourself, simply skip ahead.

#### What Is a Partition?

It's often helpful to think of computer terms by their physical equivalents. A partition in a room, for instance, is a barrier between one side and the other. It might separate two classrooms in a pinch or provide us with two smaller rooms instead of one really large one.

In the computer sense, this concept is the same. A hard data partition is a magnetic barrier that separates data on one side of the hard drive from data on the other side. Partitioning is usually done to organize files and manage space. A 40-GB hard drive is like owning a farm—there's a lot of acreage, but it's pretty tough to manage. By partitioning up a hard drive, you reduce it into manageable pieces. The real estate equivalent would be building subdivisions.

That, in a nutshell, is a partition and its use.

#### What Are the Advantages of Using Partitions?

In most modern desktop computers, users have very little interaction with their computer on a relatively simplistic level. Windows users usually have a file manager which organizes everything quite prettily in nice neat rows and columns. The data is already sorted, so there's often not really an organizational need for a partition.

When you use Linux, you'll have opportunities to work with the file system at a more basic level, known as the command line. Having partitions will help you sort out some details pertaining to your files.

The main advantage, however, is data protection. When you install Linux, it's relatively simple to keep your data safe. During the installation process (in the next step, you'll see), you will be able to tell the program which partitions to format. Formatting a partition will wipe out all the data on it. If you upgrade or reinstall Linux, you'll find that you've got some files on the system that you don't want to lose. If they are contained in a specially made partition, you won't have to format the partition and lose the files.

This means that the risk to your files is minimized during a second installation or an upgrade. This is really quite handy.

Another very large advantage is discussed in the next section.

### Characteristics of Partitions

Partitions typically have two main characteristics: size and format. The size of a partition is self-explanatory—it's simply how large or small you want to make the partition. In the analogy of our room, it's where you place the wall.

The format, however, doesn't have as logical an equivalent. Most personal computers run some version of Microsoft Windows. However, other operating systems, such as the Macintosh OS, BeOS, Linux, and others are used. Each of these operating systems uses a different file system, and therefore the files are in a different format. You might liken this to how one side of the room looks compared to the other.

A computer running Windows typically cannot read files formatted under MacOS or Linux. Windows is one of the few operating systems, and the only one in wide use, that is so impaired.

A great advantage of Linux is that it can read disks formatted under different operating systems. Linux supports many different formats, among them the MacOS, Windows, and other UNIX derivatives (such as MINIX, BSD, and so on). Support for these operating systems can be added dynamically using various upgrade tools provided by Red Hat, too, so if you have a hard drive or floppy disk formatted in who knows what, you can probably find support for it in Linux.
