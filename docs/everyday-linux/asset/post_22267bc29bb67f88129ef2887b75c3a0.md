## Installing a New Package or Upgrading an Old One

- The difference between installing a package and upgrading a package is that installation will install a program that you have never had installed on your system. Upgrading will take care to remove the old program and install the new.

If you want to install a new package, simply click the install button. A new window will appear that has a blank list. To add to this list of packages that you wish to install, click the Add button. A new window will appear that will let you browse through the file listings.

If you plan on getting information from your installation CD, make sure that the CD-ROM drive is mounted so that you can read from it. You will then need to navigate to the mount point for your CD-ROM drive. This is usually /mnt/cdrom. The location of the RPMs depends on the vendor of your CD, but the directory is usually very well marked. (Look for something with RPMs in all caps.)

You can select whichever package that you wish to install from here. Most packages are well-named, meaning that you're not going to wonder exactly what a package is when you look at it. If you have questions, though, you can always query the package.

If you get a new package for a program already existing on your computer, you will want to choose the upgrade option instead of install. You'll go through the same selection process. It is nearly identical to a regular install, except that GnoRPM will remove the old program.

If you encounter any errors when installing or upgrading--perhaps a *dependency* isn't fulfilled, for instance--GnoRPM will inform you before you can actually install the package. A *dependency error* is said to occur when you attempt to install a package without installing those packages upon which the one you want to install depends. You can choose to abort installation if you're not sure about the error, or continue if you know that you will rectify it shortly.

### Removing a Package Already Installed on Your Computer

If you have come to realize that you no longer use a specific package on your computer that may be consuming quite a bit of disk space, you will probably want to remove it.

If you suddenly become a UNIX wizard, you will find that you don't need some of the documentation anymore. (It is not recommended that you follow the next procedure--it is only intended to be an example, and the hypothetical situation described is unattainable.) You've been using bind and fetchmail so much that you don't even have to think twice about their options or how to use them.

In that case, you could remove their documentation. To do so, you would open up GnoRPM. There is a section labeled "Documentation." (See it in the screenshot above?) If you click on documentation, you will see a number of different icons shaped like boxes (these are packages). Find the ones with the bind and fetchmail labels. Highlight the first and then click on the Uninstall icon at the top of the GnoRPM screen. GnoRPM will then cheerfully remove the documentation. You can do this for any such package as you please.

If you find that only the bash shell is being used on your system, for instance, you could remove all of the others. (Look under "System Environment.") While this isn't usually suggested, as it's not going to save you scads of room and eliminates the choice of future users, it's entirely possible.

### Querying a Package

If you're interested in the contents, size, or description of an installed package on your system, you should right-click it, and then click on the Query option. You'll find out about the package, what files are contained in it, and how much space it takes up.

Space-conscious users will probably want to periodically review the packages installed on their system and decide whether or not they need them. If you happen to find one that you don't wish to keep, follow the instructions for removing a package listed above.

### Verifying a Package

If you think that some of the files in a package are missing or corrupted, you can choose to verify the package. Right-click the package in question and click on the word "verify." GnoRPM will proceed to check through each and every file contained in the package to ensure that the date and time stamps match and that all of the files listed in the package have been installed.

If you have recently gotten a virus or encountered some hard drive damage, you might want to verify packages that seem to be acting up.

### Finding Packages from Files

When performing routine system maintenance, you might find a program or other file that you believe is no longer in use. However, it's sometimes difficult to know which package contains the file. Make sure to copy down the full name of the file (i.e., the full directory and the filename). You can then click on the find button in GnoRPM.

A new window will appear, asking you for the name of the file. Put in the full name, and it will respond with the package that the file is contained in, if any. For example, try inputting /bin/bash.

### Web Find

One of the more wonderful options of GnoRPM is the "Web Find" option. If you find that you want to install or upgrade a package which you do not have locally, you can search the internet using Web Find.

If, for instance, you hear a widespread rumor that the GIMP has been updated and includes a few new plugins that you might enjoy using, you could type in *gimp* in the search window that appears. A list of all packages containing the word gimp will appear, and you'll probably find exactly what you're looking for.

Once you find what you're looking for, you can query the package, install it, or upgrade it, the same way you would if you were installing from a CD or another disk.

## Stable vs. Unstable Releases

Normally, program updates are released frequently, but as we noted before, there are usually many bugs in the program, especially in the beginning stages. A release is said to be stable (or frozen) if the release has very few bugs or stability problems. If it still contains many major bugs or runs fitfully, it is said to be an unstable release.

It is almost always best to use stable releases of software; this will prevent problems from eventually cropping up in your software. If you’re interested in seeing improvements in software, make sure you’ve got the earlier release backed up. Then install the newer, unstable release and see what the differences are.

## Backups

You will find that your Linux system is incredibly stable and susceptible to few viruses and other calamities that befall many computers running Windows. (A majority of the hundreds of viruses created each month are geared towards systems running Windows9x. Most of the news-making e-mail viruses target computers that use Microsoft Outlook as the default mail program.)

However, it is prudent to make backups of your data periodically. You will probably want to use Zip drives or tape backup systems to protect your data, but another option does exist which I’ll discuss briefly. (You’ll be able to find more information about it on the Internet.)

This is what is known as a RAID disk array. There are six levels of RAID disk protection, each with varying characteristics. Smaller systems may make good use of a RAID-1 disk array, which uses a process known as *mirroring* to protect files.

A RAID-1 disk array requires that you have two times the number of drives that you wish to protect. When you write to one disk, the same data is automatically written to the mirroring disk.

Using a RAID array has both pros and cons. It is a very secure way of ensuring that you lose no data. In the event that one hard drive suffers from a “heat stroke” (it becomes overheated and loses data), the other drive is a ready backup. Unfortunately, it is also relatively slow—writing data twice consumes about twice as much time as writing it once.
