The second item of business will be to create a directory to store the scripts in. Type `mkdir bin` at the prompt. If you type in `ls`, you will notice that your file listing now has the `bin/` directory in it.

Then type `pico` at the prompt.

This is your first time to see a text editor in the command-line interface. This text editor is known as the Pine Composer (pico for short). It is a quite user-friendly text editor, at least in comparison to others such as vi and emacs. If it seems sparse and difficult to use, don't worry. We'll be navigating it together.

Type in `ls -FC` in the blank window. This is the command that we wish to execute.

Hit control-x. (This means that you hold down the CTRL key and press the x key. This is often abbreviated as ^X.) A prompt will appear that asks you what you want to call the file. You should type in `bin/l`. When you press enter, it will save the file and exit the Pico editor.

Now you're confronted with the prompt again. Type in `l`. You'll see the product of your first shell script—you'll see a file listing that is in three columns with files and directories clearly demarcated. It's a handy file to have. When you're done looking at the results, type `exit` to quit using the terminal.

This is your first taste of shell scripting. What we've done is, in reality, very, very simple, and not too useful. It would be far easier to edit your .bashrc file and include the line `alias ls='ls -FC'`, which will create an *alias*. An alias is simply a substitution of sorts; every time you type in "ls," the computer will substitute "ls -FC" in its place.

However, now you can see that you can play with shell scripts. Look in the resources section at the back of this book, and you'll find a few FAQs that will educate you a little more in the field of shell scripting. Shell scripts can become very long and complicated, doing far more than we've just done, so don't pass this off as a little thing.
