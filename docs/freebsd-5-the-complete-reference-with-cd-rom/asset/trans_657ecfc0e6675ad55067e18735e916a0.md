
最稳妥的办法是安装几款邮件客户端并逐一试用。如果你管理的系统中有许多用户，你应该为用户安装一系列邮件阅读器。

邮件阅读器并不总是使用兼容的邮件箱格式。因此，你可能无法轻松地切换邮件阅读器并保持邮件队列（mail spool）的完整性。我建议创建一个测试账号，用于对邮件阅读器进行初步评估。

## 初始设置与配置

安装好邮件应用程序后，它基本就可以直接使用了。不过，有一些细节你可能需要或希望进行配置。这些功能通常是根据每个用户单独设置的，一般存储在以程序命名、位于用户主目录下的配置文件中。有些程序会创建一个完整的子目录来存储这些文件。大多数程序的默认配置文件存储在 /etc 或程序自身的目录树中。这些文件的示例包括：

- **Pine**：此程序将本地默认值存储在 /usr/local/etc/pine.conf 中。用户可以在其主目录中的 `.pinerc` 文件中覆盖这些默认值。
- **Mutt**：/usr/local/etc/Muttrc 文件包含全局默认设置。用户可以通过在其主目录中创建 `.muttrc` 文件来覆盖这些默认值。
- **Spruce**：此程序没有全局配置文件；相反，它在首次运行时提示输入配置值，并将其存储在 ~/.spruce/spruce.conf 中。
- **Sylpheed**：与 Spruce 类似，Sylpheed 在首次运行时提示用户默认值，并将其存储在用户的主目录中——具体来说是 ~/.sylpheed/sylpheedrc 中。

某些程序——特别是基于 X 窗口的工具，以及一些文本模式程序——允许用户从邮件程序内部修改其默认设置。使用此功能通常是个好主意，因为它可以降低因手动编辑错误而破坏配置的风险。图 24-1 展示了一个示例：Spruce 配置选项对话框。该对话框在首次启动程序时出现，并可通过选择“设置 | 首选项”再次打开。大多数其他图形用户界面（GUI）程序提供类似的对话框。你应该确保设置的选项包括：

- **姓名和地址**：许多程序基于 FreeBSD 账户数据库和默认机器信息（如主机名）自动填入你的姓名和电子邮件地址。你可能需要编辑这些信息——例如，如果你的回信仅使用域名，则可以移除主机名中的主机部分。一些程序，包括如图 24-1 所示的 Spruce，为 Reply-To 地址提供了单独的选项。你可以利用此功能将回复发送到另一个地址，前提是收件人的邮件程序支持该字段。

![](img/f34d37e3abe9f4517128e54f80ab2616_609_0.png)

![](img/f34d37e3abe9f4517128e54f80ab2616_610_0.png)

**图 24-1.** 图形界面工具使输入电子邮件账户信息变得简单直观。

- **签名**：电子邮件*签名*是消息末尾的一个简短部分，你可以用它来列出你的电子邮件地址、个人主页、雇主或其他信息。请将签名控制在 4–6 行以内。
- **发件服务器**：许多 FreeBSD 邮件程序（尤其是基于文本的程序）默认使用本地计算机上运行的 `sendmail` 来处理出站邮件。其他程序，包括许多 GUI 程序，要求你显式指定一个发件邮件服务器。如果有一个可以处理该任务的邮件服务器，它可能是 `localhost`，如第 19 章所述；或者也可以是另一台计算机上的邮件服务器。
- **收件服务器**：邮件程序必须知道去哪里查找收件邮件。如果系统直接接收邮件，或者你使用 fetchmail 检索邮件并将其注入本地邮件队列（如第 19 章所述），这可能是一个本地邮件队列。或者，你可以配置大多数邮件阅读器使用 POP 或 IMAP 等协议访问远程服务器上的邮件。你可能能够配置邮件阅读器定期（例如每半小时）检查新邮件；或者你可能需要发出命令或退出并重新启动程序来检查新邮件。
- **编辑器**：一些邮件阅读器，尤其是基于文本的工具，依赖于外部程序来编辑你创建的邮件消息。例如，`.mutrc` 中的 `set_editor` 选项和 `.pinerc` 中的 `editor` 选项分别设置了各自邮件阅读器的编辑器。一些程序，尤其是 GUI 程序，支持将出站邮件格式化为 HTML 或其他高级格式的选项。除非你需要这些选项，否则最好禁用它们。

大多数邮件阅读器会在用户主目录中创建子目录来存储邮件。这些子目录可能与存储配置文件的目录相同，也可能名为 `Mail`、`mail` 或类似名称。通常，邮件阅读器会在邮件目录中创建一个或多个文件来存储消息。你可以使用邮件阅读器功能在邮件目录中创建*文件夹*。这些文件夹通常是可包含多个邮件消息的普通文件，但也可能是以“每文件一条消息”格式存储邮件的子目录。如果你的邮件阅读器读取本地邮件队列，它还会从 `/var/mail/username` 读取收件邮件，其中 `username` 是你的用户名。

一些邮件阅读器会自动将邮件从系统邮件队列传输到名为*收件箱*（inbox）或类似名称的本地邮件文件夹。如果你试用一个将邮件移动到自己邮件文件夹的邮件阅读器，但最终决定不使用该阅读器，这种行为可能会导致一些难以恢复的邮件。

## 阅读和存储电子邮件

大多数电子邮件程序将消息组织到文件夹中。访问这些文件夹的具体方式因程序而异。诸如 `Mutt` 和 `pine` 等基于文本的程序使用你可以输入到主屏幕的命令来“进入”文件夹。然后你可以显示文件夹中的消息，通过输入消息编号或将光标移动到消息上阅读消息，等等。基于 X 窗口的程序通常在主窗口的一个窗口或窗格中显示邮件文件夹列表，或提供一个按钮来打开文件夹列表。例如，图 24-2 显示了 Spruce 的主窗口。窗口左上角的窗格显示了所有可用的邮件文件夹，分为三类：*本地邮件箱*（属于 Spruce 且存储在 `~/.spruce` 目录中的那些），*远程邮件箱*（由你配置 Spruce 使用的 IMAP 服务器维护的那些），以及*本地队列*（可能与其他邮件程序共享的邮件箱，包括主收件队列，如果你以此方式接收邮件的话）。并非所有邮件阅读器都以完全相同的方式组织其邮件箱，但这种组织方式并不少见。在每个邮件文件夹类别中都有单独的邮件文件夹，如图 24-2 中所示的*收件箱、草稿箱和其他文件夹*。在 GUI 邮件阅读器中，你可以通过点击消息列表窗格（位于图 24-2 的右上角附近）中的消息来阅读邮件。文本模式邮件阅读器通常使用你输入的消息编号，或高亮显示特定消息。在这两种情况下，消息都会出现，要么替换消息列表，要么在另一个窗格中显示。在图 24-2 中，消息显示在文件夹和消息列表窗格下方。如果你想保存消息以便将来参考，可以将其存储在一个文件夹中，通常是通过选择菜单选项或拖放操作来实现。大多数邮件阅读器允许你创建新文件夹。例如，图 24-2 中的*文章*文件夹不是 Spruce 邮件文件夹目录的标准部分；我创建了它并将一些消息移入其中。

有时有必要将消息存储到文件中。你可能会出于存档目的或处理消息的需要这样做。大多数程序都包含某种消息*保存*选项。通常，保存的消息版本只包含最小的消息*头*（邮件服务器用于将消息引导至目的地并记录消息经过的系统信息）。报告邮件滥用时需要完整的消息头，因此，能够保存所有消息头的邮件阅读器会是一个极大的助力。

你通常可以通过创建一个新的邮件文件夹并将消息移动到该文件夹来访问完整的消息头。生成的文件通常包含带有所有消息头的消息。

## 发送电子邮件

发送电子邮件涉及选择发送消息的选项。邮件阅读器可能会启动一个外部编辑器，如*jed*、*pico* 或*vi*；或者显示其自带的编辑器。除非你指定使用某个特别复杂的编辑器，否则你看到的编辑器会相当简单。文本模式工具的默认外部编辑器和 GUI 工具自带的编辑器都倾向于非常简洁。在最基本的形式下，电子邮件涉及纯文本消息的交换，因此大多数电子邮件编辑器不包括添加*粗体*或*斜体*等格式功能的选项。然而，近年来，超文本标记语言（HTML）——最广为人知的构建 Web 的文件格式——在电子邮件中变得流行。因此，支持 HTML 的邮件阅读器提供支持 HTML 功能的编辑器，包括文本效果、表格甚至内联图形。

有些人反对接收 HTML 电子邮件。这类消息通常比文本模式消息更大，因此在许多收件人仍在使用慢速拨号连接下载时需要更长时间（如果你包含内联图形，这种影响相当显著）。无法解析 HTML 消息的收件人的邮件阅读器最终会看到“原始”HTML 标记代码，这降低了消息的可读性。除非收件人同意接受此格式，否则我建议你避免使用 HTML 电子邮件。

当你保存消息并退出外部编辑器，或在内置电子邮件编辑器中点击*发送*按钮时，邮件阅读器会尝试发送消息。*一些邮件阅读器*（尤其是基于文本的）默认尝试使用本地 */usr/sbin/sendmail* 程序，这在 FreeBSD 上运行良好，尽管有一些注意事项。具体而言，一些 ISP 阻止直接发送电子邮件，而这是 sendmail 默认尝试做的；如果收件人系统没有立即响应，sendmail 会稍后重试，因此如果你的互联网连接是持续在线的，这种方法效果最好。第 19 章描述了重新配置 sendmail 以使用出站邮件中继，这可以解决这些问题。另一种方法是配置你的邮件阅读器直接使用你 ISP 的邮件服务器，如前文“初始设置与配置”中所述。
