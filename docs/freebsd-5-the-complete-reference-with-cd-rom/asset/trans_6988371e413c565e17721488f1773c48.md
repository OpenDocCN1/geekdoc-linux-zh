

## 注意事项

本示例通过指定完整路径来调用 `/bin/ls`。在大多数情况下，即使脚本不包含其调用程序的完整路径，脚本也能正常工作，但包含完整路径是一个良好的实践，原因有两点。首先，这样做可以最大程度地降低因路径中其他位置添加了重复程序而导致脚本行为发生改变的风险。其次，指定完整路径可以保证即使对于其路径不包含目标目录的用户，脚本也能正常工作。另一方面，包含完整路径可能会降低脚本的可移植性，因为在不同的系统上，同一个程序可能位于不同的位置。

这种方法的一个缺点是，脚本不会传递你给予它的任何参数。例如，如果你输入 `. /lsl a*` 并期望只看到文件名以 a 开头的文件，你会失望的——脚本丢弃了 a* 参数，因此你会看到所有的文件。接下来的章节“使用命令行参数作为变量”将描述如何绕过此限制。

脚本可以调用多个外部程序。将每个程序调用放在单独的一行中，脚本将按顺序调用它们，在下一个程序调用之前等待每个程序调用完成。如果你在程序调用后跟随一个 ampersand (&)，该程序将在后台启动，就像你在 shell 提示符后输入程序名并跟随 ampersand 一样。例如，请参阅清单 31-2。

### 清单 31-2
一个用于启动多个程序的示例脚本

```bash
#!/bin/sh
/usr/X11R6/bin/xtwm&
/usr/X11R6/bin/xclock&
/usr/X11R6/bin/xload&
exit 0
```

该脚本启动了三个程序——一个 xterm 窗口、xclock 程序和 xload 程序。由于这些是基于 X 的程序，你可能希望同时使用它们，因此每个程序名后面都跟有一个 ampersand。当你运行此脚本时，你会看到屏幕上打开三个新窗口，每个被调用的程序一个。

## 管道传输程序和重定向输入输出

第 5 章在 shell 提示符输入命令的背景下介绍了管道和重定向的使用。这些功能在 shell 脚本中以完全相同的方式工作。例如，假设你想创建一个脚本来显示计算机上所有活跃网络接口的名称。清单 31-3 实现了这一目标。

### 清单 31-3
脚本中管道使用的示例

```bash
#!/bin/sh
ifconfig | grep flags | cut -f1 -d“:”
exit 0
```

**注意**

为了可读性，清单 31-3 及后续大多数清单没有提供外部程序的完整路径。如果你愿意可以添加它们；使用 `whereis`，例如 `whereis ifconfig`，来定位这些程序文件。

清单 31-3 在一个管道中调用了三个程序。第一个，`ifconfig`，显示计算机网络接口的信息，如第 14 章所述。但此信息过于冗长。例如，以下是 `ifconfig` 的一些典型输出：

```sh
$ ifconfig
  vr0: flags=8843<UP,BROADCAST,RUNNING,SIMPLEX,MULTICAST>  mtu 1500
        inet 192.168.1.6  netmask 0xffffff00  broadcast 192.168.1.255
        ether 00:80:c8:fa:3b:0a
        media: Ethernet autoselect (100baseTX)
        status: active
  lp0: flags=8810<POINTOPOINT,SIMPLEX,MULTICAST>  mtu 1500
  lo0: flags=8049<UP,LOOPBACK,RUNNING,MULTICAST>  mtu 16384
        inet 127.0.0.1  netmask 0xff000000
  ppp0: flags=8010<POINTOPOINT,MULTICAST>  mtu 1500
```

此示例中的四个接口是 `vr0`、`lp0`、`lo0` 和 `ppp0`，但提取它们并丢弃其他所有内容需要对输出进行修剪。第二个命令 `grep` 搜索包含接口名称的行。这些行都包含单词 `flags`，因此 `grep` 搜索的就是这个单词。第三个命令 `cut` 修剪了输出中除第一个字段外的所有内容。`-f 1` 选项告诉 `cut` 截取除第一个字段外的所有内容，而 `-d " :"` 选项告诉 `cut` 使用冒号作为字段分隔符。运行清单 31-3 会产生如下输出：

```sh
$ ./ifinfo
vr0
lp0
lo0
ppp0
```

虽然清单 31-3 不太可能是一个至关重要的程序，但你可能会使用此类技术为脚本用户生成选项列表。后续示例也基于清单 31-3 执行更有趣任务。你可能还希望将此信息记录到文件中。为此，你可以使用重定向将输出发送到临时或永久文件。例如，你可以将清单 31-3 中的第二行更改为：

```sh
ifconfig | grep flags | cut -f 1 -d " :" > /tmp/if-info.txt
```

然后，你可以在脚本运行后检查输出，将其加载到另一个程序中，甚至可以使用创建该文件的同一个脚本通过输入重定向将其读取到另一个程序中。你可以将这些技术与使用命令行参数（在即将出现的章节“使用命令行参数作为变量”中描述）结合起来，让脚本读取或写入你作为脚本参数指定的文件。

## 使用变量

变量是任何编程语言的重要组成部分，脚本语言也不例外。Shell 脚本变量与环境变量密切相关，后者在第 6 章中介绍。事实上，你可以在 shell 脚本中将环境变量与其他变量同等对待。约定上，环境变量名称全大写，而脚本变量名称小写，偶尔混合大小写。在 shell 脚本中，变量的工作方式与在命令 shell 提示符下相似，但在处理命令行参数时有一些重要的扩展。在脚本中操纵变量的频率通常比在 shell 命令提示符下要高。

### 给变量赋值

第 6 章描述了如何从 shell 提示符给变量赋值，同样的程序在 shell 脚本中也适用。Bourne shell 中最基本的情况如下：

```sh
export color=red
```

此示例将 $color 变量的值设置为 red。值可以是字符串，如 red，也可以是数字，如 12。如果值是包含空格的字符串，你应该用引号（“ ”）括起来。当你给变量赋值时，不包含开头的美元符号 ($)，但随后引用该变量时必须包含此符号。

事实上，完全去掉 export 命令是可能的——通常也是可取的——因为该命令用于将变量导出为环境变量。因此，前面的命令更好地表达为：

```sh
color=red
```

> **注意**
> 不要在等号和变量名或其值之间放置空格。如果这样做，shell 会尝试将变量名解释为命令，或者给变量分配空值，然后尝试将你的预期值解释为命令。

### 使用命令行参数作为变量

脚本中变量的一种常见用途是将命令行参数传递给脚本。例如，你可能想传递文件或目录的名称。再次考虑清单 31-1。此脚本以长目录列表的形式显示当前目录的内容，但如果你在脚本名后输入另一个目录名，脚本会忽略你提供的目录名。幸运的是，有一个直接的方法可以恢复传递给 shell 脚本的参数：你可以将它们作为编号变量引用，从 $0 到 $9。（你可以使用 shift 命令访问第九个参数之后的参数。）$0 是 shell 脚本本身的名称，$1 是传递给脚本的第一个参数，$2 是第二个参数，依此类推。如果你需要知道传递给脚本的参数数量，$\# 变量包含此信息。清单 31-1 改写为将单个参数传递到其命令中，显示在清单 31-4 中。

![](img/f34d37e3abe9f4517128e54f80ab2616_792_0.png)

```sh
#!/bin/sh
ls -l $1
exit 0
```

无需显式定义参数变量；它由 shell 本身隐式定义。如果此脚本名为 `ls1`，则输入 `./ls1` 会产生当前目录的长列表，但添加目录名（如 `./ls1 /tmp`）会产生指定目录的长列表。这种方法的一个限制，至少当目的是将文件或目录名传递给脚本时，在于通配符的处理。FreeBSD shell *扩展* 通配符——即将其转换为可能跨越多个参数的文件列表——在调用用户输入名称的程序之前。因此，如果你输入 `./ls1 *`，清单 31-4 接收当前目录中第一个文件或目录的名称作为 $1 的值。你可以通过将参数括在引号中来解决此问题。例如，输入 `./ls1 "*"` 将星号 (*) 作为 $1 的值传递，然后在脚本内的 `ls` 调用中扩展。

你可以传递文件名以外的信息作为参数。例如，你可以创建一个操作用户信息的脚本，在这种情况下，你可以将用户名作为参数传递。然后，当脚本调用账户操纵程序如 `passwd` 或 `adduser` 时，可以使用像 $1 这样的参数变量代替用户名。
