### Talk to Chrome

I have a problem where my default microphone works perfectly for everything except for Google voice recognition. When trying to use my microphone at google.com (so I can enter a search query without typing), I get this error: "Please check your microphone". I get similar errors at dictation.io (of course, I double-checked that I enabled microphone use). If I remove my ~/.asoundrc, stop JACK and restart Chrome, then online voice recognition works.

But I cannot figure out what I need to change in my ~/.asoundrc (I have many good reasons why I need to use JACK all the time).

I tried to record my voice online at approve.in/online-voice-recorder and it worked as expected (with JACK and my ~/.asoundrc). So, Google Chrome definitely can access my 'default' microphone. This is what puzzles me the most: if something is wrong with my ~/.asoundrc, how come I can use my microphone for everything without issue except for online voice recognition? I use Google Chrome 32.0.1678.0. Do you guys have any tips on what I could try or what could be wrong?

*Well, there are a few things that could help you here. We see you're on Chrome 32, which is fairly old at this point. We're in the mid 40s for Chrome now, so it might be worth looking for a repo to upgrade to the latest Chrome or a binary, or something along those lines. That might fix the problem, although it's not guaranteed.*

*What has a much better chance of fixing it is changing your audio server: instead of ALSA, you should install PulseAudio. There's also a PulseAudio JACK (pulseaudio-module-jack) you can use as well, so you won't lose that functionality. It works a bit better with Chrome and other applications in general. You just give it a microphone to use by default and it will interact with the software that asks for it.*

### Video stuttering

I've been having a bit of a problem playing videos on my Linux laptop. The problem is that when I play a large video file, the playback will be normal for a few seconds, then it will freeze for a split second and continue for another few seconds before doing it all again.

The problem seems to be independent of the player - VLC, MPlayer and Totem all have the same issue. I do have a single-core processor and I wonder if that might be causing the issue?

![](img/e7f197876caa0b235fb5da2d16a578ea_92_0.png)

> Left: If Google is ignoring you, consider switching your audio server  
> Right: You can change the way that specific files are executed thanks to the way file managers handle file types

However, I've managed to work around the problem with MPlayer by increasing the cache via the command line with:

```bash
$ mplayer -cache 10000 -cache-min 80 MyVideo.mp4
```

But this is still a cumbersome workaround and I have to keep remembering to use this exact option every single time.

So I have a couple of questions: is there a more elegant solution to this problem? Are there software packages, such as new codecs, I should install or a config file I should try to alter? Secondly, is there a way I can save the command line arguments in some kind of alias so that when I call MPlayer, it is actually calling MPlayer with these arguments?

**Scott T.**

To answer your first question, your cache solution is basically as good as you're going to get. Unfortunately, with a single-core processor you're going to struggle with the HD videos as it is, especially with modern distros taking up a little more of the resources than they used to. So that leaves you with making sure you don't have to remember the exact cache options to run it. There are two ways to do that:

Firstly, if you're doing it all from the command line anyway, you can use something called alias. This enables you to set a command that will then call a predetermined command, like a macro or keyboard shortcut. For example, you could have update-software set to use apt-get upgrade or something similar. In this case, you could use something like:

```bash
$ alias mp4play="mplayer -cache 10000 -cache-min 80"
```

...and just remember to use `mp4play MyVideo.mp4` to call the video.

Alternatively, you could make a change to the way MP4s are launched from the graphical file system. Right-click, go to Properties and find the Open With dialog for your desktop environment and enter `mplayer -cache 10000 -cache-min 80` as the executable dialogue. Repeat for other file types.

### Bash together a little script

I am taking images from a webcam as a snapshot. It's sending me the files so I know that part is working. Now I need a bash script that will rename the latest file; unfortunately, file names are hard to guess based on sequence numbers. I can only give a partial name like 192.168.0.100*, where the names are IP data and time (and many other things) to be searched for. Let's say I want to change the image to something like mycoolmImage.jpeg. After that's done, I then want to delete the existing old files, in the same manner as `rm -rf 192.168.0.1*`. Consequently, only the latest file will be replaced and previous files will be removed. Now, I must detect the latest file, as if in some cases there are multiple, I then have to use the latest and und any cost.

It also needs to be run in a cronjob (the script) on a per minute (or five-minute) basis.

**Tommy**

Assuming you're receiving the files from that IP address, here's a little bash script:

```bash
#!/usr/bin/bash
cd /path/to/files

# Do not delete files unless two or more exist,
# then limit in order of modtime, select all but
# the latest.
if [ $(ls 192.168.0.100*.jpeg >/dev/null | wc -l) -ge 2 ]
then
    mv $(ls -rt 192.168.0.100*.jpeg | head -n -1) ~/mycoolimage.jpg
fi

# Do not mv file unless one (or more) exists,
# otherwise mv most recent file to target filename.
if [ $(ls 192.168.0.100*.jpeg >/dev/null | wc -l) -ge 1 ]
then
    mv $(ls -rt 192.168.0.100*.jpeg | tail -n -1) mycoolimage.jpg
fi
```

We've got a few fault states in there for you – basically, it checks everything first before doing any moving or deleting. To set it up as a cronjob, first make the file executable using `chmod +x`, then call up `crontab -e` and give it `5 ****/path/to/script` as a line for it to be run every five minutes.
