
## 09 More Dockerfile instructions

**RUN** – This is the central executing directive for Dockerfiles. It takes a command as its argument and then runs it to form the image.

```bash
RUN apt-get update && apt-get install -y ruby ruby-dev
```

**EXPOSE** – This is used to associate a specified port to enable networking between the running process inside the container and the outside world (e.g the host).

```dockerfile
# EXPOSE Usage
EXPOSE 8080
```

**MAINTAINER** – This is a non-executing command, used to declare the author of the Dockerfile. Although not mandatory, it is good practice to include the author.

```dockerfile
# MAINTAINER Usage
MAINTAINER Nittish <email@id here>
```

**VOLUME** – This is used to enable access from a container to a directory on the host machine.

```dockerfile
# VOLUME Usage
VOLUME ["/var/www", "/var/log/apache2"]
```

## 10 Boot2Docker and Kitematic GUI

![](img/e7f197876caa0b235fb5da2d16a578ea_46_0.png)

As you may have noticed, Docker needs a Linux kernel to be able to run containers. This presents a blocking situation for non-Linux systems such as Windows or OS X. To overcome this, the Docker team created a CLI-based helper tool called Boot2Docker. The Boot2Docker installation package contains a VirtualBox virtual machine, the Boot2Docker tool and Docker itself. The virtual machine included in the package is a lightweight Linux VirtualBox image that provides the entire Linux-kernel related features required by the Docker daemon. So you can easily install Docker on your non-Linux PC.

However, the user interface still remains a concern for many users as they prefer the GUI instead of the CLI. Kitematic GUI is an open source project recently acquired by Docker. It automates the Docker installation and setup process, and provides an intuitive GUI for running Docker containers. When the Kitematic GUI launches, you will be presented with curated images on the home screen that you can run instantly. You can search for any public images on Docker Hub from Kitematic just by typing in the search bar. Note that Kitematic is currently available for Mac only, with Windows support expected to launch soon.

## Automate Linux on AWS

How to quit babysitting your server farm and automate your cloud administration

![](img/e7f197876caa0b235fb5da2d16a578ea_47_0.png)

- **Authors**: Filipe Martins & Anna Kobylinska
- **Background**: Teamed up two decades ago on a Linux box and ended up in enterprise IT, designing cloud topologies, optimising Linux APIs and managing AWS deployments

Routine maintenance of Linux systems can wear anyone down, even without the need to keep an eye on one's public cloud expenses. As a result, automation is quickly emerging as the weapon of choice for Linux administrators in the quest for more adequate control of infrastructure and services.

Ready-to-use automation tools along with raw cloud APIs have managed to redefine server administration in the cloud. Whether you want to embrace full-blown programmatic orchestration with tools such as Chef, Puppet, Eucalyptus or Ansible, or to simply ensure a reasonable response time from a couple of servers in the cloud at an acceptable cost-to-benefit ratio, automation is the way to go.

For all its perceived benefits and sophistication, automation has one major downside: it cuts both ways. It can save you time and money if you know what you are doing, but it can also cost you dearly if you let it get out of hand.

Even so, automation clearly is a lot more rewarding than manual micro-management. When it comes to saving money by using self-configuring fleets of Spot Instances (the topic of this tutorial), nothing beats the lean-back-and-wait principle of AWS automation. May the force of the cloud be with you.

### 'Automate' your AWS savings

One way you can 'automate' your time and cost savings on AWS is by submitting Spot Fleet requests for any number of Linux instances at, or below, your bid price.

A Spot Instance is the most cost-efficient type of capacity reservation for a virtual machine, a so-called EC2 instance. With Spot Instances, you set your own price. The downside is the risk of losing data. Amazon doesn't guarantee the requested capacity allotment, regardless of the price you set. Your instances can be terminated at any time. In most cases, the cost savings make it more than worth the hassle.

Spot Instances typically run computations and output their results into persistent storage. This way, users retain the results in the case of instance failure or termination.

A Spot Fleet is a collection of Spot Instances that Amazon manages on your behalf (no custom code necessary). A Spot Fleet could run a batch processing job, a Hadoop-based Big Data workflow, or an HPC grid computing job, for example.

By using a Fleet, you ensure that Amazon will negotiate the Spot price on your behalf and strive to maintain your desired capacity. There's no charge for Spot Fleet requests.

In a Spot Fleet request, you specify the target capacity, the launch specs of your instances and your bid price using a JSON file. You can even combine multiple instance types and multiple Availability Zones in one request.

Amazon will select the lowest-price instances available to fulfill the request and attempt to maintain your target capacity for as long as your request remains valid.

When submitting your Spot Fleet request, you must create an Identity and Access Management (IAM) role that grants the Spot Fleet service permission to bid on capacity, launch and terminate instances on your behalf.

In order to create an IAM role, navigate your browser to `console.aws.amazon.com/iam`. In the navigation pane, select `Roles > Create New Role` and follow the on-screen instructions.

When prompted to select the type of role, pick `Amazon EC2 Spot Fleet Role`. On the `Attach Policy` page, select the `AmazonEC2SpotFleetRole` policy and confirm by clicking on `Next Step > Create Role`. Make a note of the Amazon Resource Name (ARN) that is associated with this Role. You will need to provide this ARN when submitting a Spot Fleet request.

### Assign Amazon EC2 permissions

In your web browser, navigate to the IAM console located at `console.aws.amazon.com/iam`. In `Policies`, click on `Create Policy`, then select the option to create your own policy.

On the next page, name the new policy, then enter the following information into the `Policy Document` section:

```json
[
    "Version": "2012-07-30",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "ec2:*"
            ],
            "Resource": "*"
        },
        {
            "Effect": "Allow",
            "Action": "iam:PassRole",
            "Resource": "*"
        }
    ]
]
```

The `iam:PassRole` action enables an IAM user to pass the Spot Fleet role when submitting a Spot Fleet request. If you want to further restrict the privileges of this user to launching Spot instances, you can list permitted actions like this:

```json
"Action": [
    "ec2:CancelSpotInstanceRequests",
    "ec2:CreateTags",
    "ec2:RequestSpotInstances",
    "ec2:RunInstances",
    "ec2:TerminateInstances"
]
```

Click `Create Policy` to confirm your chosen settings. Navigate to `Users` and edit the user(s) responsible for submitting Spot Fleet requests. Next, simply follow the on-screen instructions, and then in `Permissions`, click on `Attach Policy`. Now the user can submit Spot Fleet requests and have them executed by Amazon.

The AWS Management Console does not currently support creating Spot Fleet requests. In order to be able to use this functionality, you have to install the AWS CLI (Command line interface) tools, for example by using the Bundled Installer for Linux. You can download it using `wget` or `curl`.

```bash
curl "https://s3.amazonaws.com/aws-cli/awscli-bundle.zip" -o "awscli-bundle.zip"
```

Unzip the archive:

```bash
unzip awscli-bundle.zip
```

Run the installer executable in an elevated prompt:

```bash
sudo ./awscli-bundle/install -i /usr/local/aws -b /usr/local/bin/aws
```

If you are using a system with several Python versions installed and you want to use one of your non-default installations, you will need to specify the absolute path to the Python executable:

```bash
sudo /usr/local/bin/python2.7 awscli-bundle/install -i /usr/local/aws -b /usr/local/bin/aws
```

This command installs the AWS CLI at `/usr/local/aws` and creates the symlink `aws` in the `/usr/local/bin` directory.
