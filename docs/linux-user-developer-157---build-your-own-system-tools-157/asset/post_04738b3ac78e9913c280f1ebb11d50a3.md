
## ROUTERS

### FCC threatens to block custom router firmware

New software-defined radio rules could spell trouble for enthusiasts

The ease with which wireless network routers can be modified with a third-party firmware is set to take a hit thanks to new rules from the **US Federal Communications Commission that promise to block firmware modifications.**

Under rules that became effective this year, set to be fully enforced for all devices on the market in June 2016, the FCC is to require all licensed devices – a requirement for sale in the US – to “implement software security to ensure that the devices operate as authorised and cannot be modified,” seemingly to lock out third-party modifications.

Replacing the stock firmware of Linux-based networking hardware with more powerful third-party alternatives, such as OpenWRT, is popular enough that there are router models designed with this specifically in mind. However, under the new FCC Part 15 rules, they could become illegal in the US over fears that they could be used to operate in unlicensed spectrum, or at illegal power levels.

Speaking at the Wireless Battle of the Mesh event in Slovenia, Simon Wunderlich argued that this was likely to have a global impact. “Since the same types of devices are often sold worldwide,” he claimed, “this change does not only affect routers in the US, but also Europe, and this will also affect wireless communities.”

![](img/e7f197876caa0b235fb5da2d16a578ea_8_0.png)

As well as unlocking new features, third-party firmware is often used to breathe new life into devices that manufacturers have ceased to support. This means that under the new rules, consumers could be left running insecure devices on their network due to the new restrictions.

## STORAGE

### Kinetic is now an open Linux project

Seagate’s enterprise-grade storage platform, Kinetic, is now an official **Linux Foundation** Collaborative project, with companies including Western Digital, Toshiba, Dell and Cisco joining the development effort.

Kinetic combines storage devices featuring integrated Ethernet connectivity with a key/value store paradigm claimed to improve the efficiency, scalability and flexibility of enterprise storage.

Using open source software and a standardised set of application programming interfaces (APIs), storage developers can use a Kinetic system to reduce the overheads of storage area network (SAN) implementations, taking advantage of features like direct drive-to-drive data transfer via Ethernet, without needing an intermediate host device.

Although billed as the Kinetic Open Storage platform, the standard remained under Seagate’s control until the formation of the Linux Foundation Collaborative Project. Now truly open, network and storage vendors have joined and pledged their support, but none have offered a release date for Kinetic-compatible, Ethernet-enabled storage devices.

According to documentation, Kinetic enables an increase in rack density, a reduction in power draw and cooling, easy data sharing, and the removal of the company calls “superfluous layers of legacy software and hardware” associated with traditional SAN platforms.

“[The Seagate Kinetic Storage platform…] delivers the new paradigm necessary to enable us collectively, as an industry, not only to meet this mandate, but to do so optimally and in the most cost-efficient manner required,” a company spokesman claimed at the announcement.

## GAMING

### Unity game engine hits Linux

Future support for the platform not guaranteed

The game engine specialist Unity has announced the release of an experimental build of its software for Linux, making good on its roadmap promise to support the operating system in future releases.

A popular engine for both games and general-purpose 3D rendering, Unity has previously been restricted to use on only proprietary platforms. This month’s release changes that, bringing official support for running the software on Ubuntu 12.04 or newer, plus unofficial support for other 64-bit Linux distributions.

The release is a test for the company, however, and Unity has not committed to a full and formal release. “Today’s build is what we call an experimental build; future support is not yet guaranteed,” warned Unity’s NaTosha Bard. “Your adoption and feedback will help us determine if this is something we can sustain alongside our Mac and Windows builds.” Bard did not indicate what usage and feedback levels would constitute enough for the company to adopt Linux as a fully supported platform for all future releases, following in the footsteps of rivals including Epic’s Unreal Engine.

Interest from developers in Linux as a gaming platform is higher than ever, thanks in no small part to game developer and publishing giant Valve basing its gaming-centric operating system SteamOS on the Debian Linux distribution.

## FEDORA

### Support for 32-bit x86 demoted

Fedora makes 64-bit x86 the gold standard

The Fedora project has demoted support for 32-bit x86 architectures from its Linux distribution, following a vote by the Fedora Engineering Steering Committee (FESCo).

In its late August meeting, FESCo raised a vote on removing support for the i686 32-bit x86 instruction set architecture from Fedora 24. “From my POV (point of view), nobody wants to support the i686 image,” Hailuk Guímar told attendees. “I’m completely +1 for (in favour of) dropping all of the i686 images/media in f24 [Fedora 24],” added Kevín Ferzi.

After some discussion, the committee agreed to change the vote away from a total abandonment of i686 support, to making it a non-blocking deliverable. This means that its absence (should work not be complete in time) would not prevent the general launch of Fedora 24, effectively demoting the architecture support.

The 64-bit x86 architecture, backwards-compatible with the traditional 32-bit variant, was launched in 2003 by AMD as AMD64 and picked up by Intel a year later. Today, the majority of both company’s chips are 64-bit.

### Power of two

When it comes to computers, nothing beats binary arithmetic. Here's how to find out if an integer is a power of two.

Identifying whether or not a given positive integer is a power of two is not a challenging job, but it needs a lot of processing, especially if the integer is larger than $2^{20}$. Also, it highlights that: a) you should always think carefully before implementation, and b) it is good to have a sound knowledge of mathematics when you are programming. The more areas of mathematics you know, the better.

Here is a standard, brute force and recursive Python function (power0f2.py) that solves the initial problem:

```python
def powerOf2(num):
    if (num == 1):
        return True
    elif (num == 0) or (num % 2 == 1):
        return False
    else:
        return powerOf2(num / 2)
```

Another version uses binary arithmetic (bitwise.py):

```python
def powerOf2(number):
    return (number & (number-1) == 0) and (number != 0)
```

Put simply, the function checks whether there is more than one "1" bit set in the binary representation of the number variable. As you know, CPUs calculate using binary arithmetic. These calculations are especially fast and happen quicker than any other kind.

To make the algorithm clearer: the binary representation of 64, which is a power of two, is 1000000. 64-1 equals 63, the binary representation of 63 is 0111111. So (1111111 & 1000000) equals 0, which proves that number 64 is a power of two. The drawback is when a solution that uses binary arithmetic is only suitable for problems that have to deal with powers of two.

The following Python script generates 1,000,000 random numbers that will then be used as input for testing the two techniques:

```python
#!/usr/bin/python
import random
MIN = 0
MAX = 100000
TOTAL = 1000000
```

Although the function **random.randrange()** suggests it produces random numbers, their statistical distribution is not so random after all. The following output proves it:

```bash
$ awk '{ if ($0 > 0 && $0 < 10000) print }' numbers | wc -l
99585
$ awk '{ if ($0 > 10000 && $0 < 20000) print }' numbers | wc -l
99811
$ awk '{ if ($0 > 20000 && $0 < 30000) print }' numbers | wc -l
99930
```

The following can find out if there are duplicate numbers:

```bash
$ sort numbers | uniq -c | sort -rn
```

Having duplicates is not a bad thing, it's just good to know. It is now time to perform the actual benchmarking. This time the benchmarking will be done using the **time()** Python function. As you can see in the Python code, each program repeats itself ten times to produce even more accurate results. The results are as follows:

```text
powerOf2.py: 12.287568 seconds
bitwise.py: 8.285457 seconds
```

Although the difference is only four seconds, it took powerOf2.py 50% more time than bitwise.py to perform exactly the same task.

The maximum permitted integer plays a central role in the problem because if it is small, the brute force technique will obviously take less time. The maximum integer that can be found in the sample was set to 1000 for the following results:

```text
powerOf2.py: 11.39706 seconds
bitwise.py: 8.412941 seconds
```
