### Obtain access key ID and set up CLI tools

AWS uses access keys to sign programmatic requests for cloud resources. A key pair consists of an access key ID and a secret access key. You can create these in the Users section.

Select your IAM username, click on User Actions, then on Manage Access Keys and finally on Create Access Key. Download your newly created credentials and remember to store them in a safe place (AWS does not retain a copy).

The fastest way to configure CLI tools with your credentials; begins with the command:

```
$ aws configure
```

You will be prompted to enter the following information (shown here with example user input):

```
AWS Access Key ID [None]: EXAMPLEACCESSKEYID
AWS Secret Access Key [None]: wJrFhXaInFEMI/6EX7MNGDPLYPEXNFXRF1CNEY
Default region name [None]: eu-west-1
Default output format [None]: json
```

To update any of these settings, run the last command again.

### Write SpotFleet configuration file

One popular usage scenario involves launching a specific number of Spot Instances in the most cost-efficient availability zone. In order to create this type of a Spot Fleet configuration, save the following contents in a JSON file:

```
{
"SpotPrice": "0.16",
"TargetCapacity": 7,
"IamFleetRole": "arn:aws:iam::123456789012:role/my-spot-fleet-role",
"LaunchSpecifications": [
{
"ImageId": "ami-la2b3c4d",
"InstanceType": "cc2.8xlarge"
}
]
}
```

This example file does not restrict Amazon to any specific Availability Zone (think of it as a data centre within your region) or any particular subnet. If your account supports EC2-VPC only, as is the case with all newer AWS accounts, Amazon will launch your instances in the lowest-priced Availability Zone that has a default subnet. If your account supports EC2-Classic, Amazon simply selects the lowest-priced Availability Zone.

In order to launch your Spot Instances in the most cost-efficient Availability Zone among those that you approve of, you will need to make some adjustments. The resulting JSON file could look something like this for the Ireland region:

```
{
"SpotPrice": "0.16",
"TargetCapacity": 7,
"IamFleetRole": "arn:aws:iam::123456789012:role/my-spot-fleet-role",
"LaunchSpecifications": [
{
"ImageId": "ami-la2b3c4d",
"InstanceType": "cc2.8xlarge",
"Placement": {
"AvailabilityZone": "eu-west-la"
}
},
{
"ImageId": "ami-la2b3c4d",
"InstanceType": "cc2.8xlarge",
"Placement": {
"AvailabilityZone": "eu-west-lb"
}
}
]
}
```

This configuration prohibits the use of availability zones other than eu-west-la and eu-west-lb.

### Submit your Spot Fleet request

In the AWS command line interface, enter the command to submit your Spot Fleet request:

```
aws ec2 request-spot-fleet --spot-fleet-request-config file://config.json
```

The file config.json is the same JSON document that you created, and it specifies setup details for your Spot Fleet. You can monitor your Spot Fleet requests using:

```
aws ec2 describe-spot-fleet-requests
```

Each of your Spot Fleet requests can assume these states:

- submitted – Amazon is evaluating your request in preparation for launching your instances.
- active – once your request has been validated, this is when Amazon EC2 attempts to maintain the target number of running Spot instances in your fleet.
- cancelled-running – Amazon has received your request to abandon your Spot Fleet; it will not launch any additional Spot instances; currently running instances will continue to perform until they are interrupted or terminated (default).
- cancelled-terminating – Amazon has received your request to abandon your Spot Fleet and is in the process of forcefully terminating instances covered by this request (non-default).
- cancelled – your Spot Fleet has now been successfully cancelled, no instances are running, none will be started and Amazon will delete your request two days after the last instances were terminated.

The following will gracefully end your Spot Fleet request without terminating any of the EC2 instances that are running:

```
aws ec2 cancel-spot-fleet-requests --spot-fleet-request-ids sfr-72fbd1ce-aa42-464c-8877-1cee4MYFLEET --no-terminate-instances
```

If you intend to cancel your request and terminate all instances at the same time, use this command at the prompt:

```
aws ec2 cancel-spot-fleet-requests --spot-fleet-request-ids sfr-72fbd1ce-aa42-464c-8877-1cee4MYFLEET --terminate-instances
```

The response should look something like this (for a request without automatic instance termination):

```
{
  "SuccessfulFleetRequests": [
    {
      "SpotFleetRequestId": "sfr-72fbd1ce-aa42-464c-8877-1cee4MYFLEET",
      "CurrentSpotFleetRequestState": "cancelled_running",
      "PreviousSpotFleetRequestState": "active"
    }
  ],
  "UnsuccessfulFleetRequests": []
}
```

Those who dare to venture into the public cloud quickly learn the value of paranoid security. In the cloud, you are no longer 'merely' facing the risk of a catastrophic data loss or data leak. You are now looking at what amounts to an unlimited financial liability for your pay-as-you-go services that scale on demand. Should an unauthorised party gain control over your AWS account, the financial outcome wouldn't look pretty. Not even close. It is wise to never understate human ingenuity, because the impossible may not be so far-fetched after all.

Over the last year or so, a series of security vulnerabilities, from Heartbleed through Shellshock to VENOM, struck terror into the hearts of active cloud users around the world. Heartbleed and Shellshock famously exposed fatal flaws in tools that were previously deemed to be safe (OpenSSL and Bash, respectively). VENOM forced hurried patching from esteemed vendors of virtualisation software, having lurked in obscurity for over a decade.

When it comes to cloud security, Andy Grove's (former CEO of Intel) remark "only the paranoid survive" seems fitting. On AWS, security is a feature you don't have to pay extra for.

### 01 Create a new IAM user

In order to secure access to your AWS resources, you need to quit using your AWS root credentials. The AWS Management Console, Amazon's web frontend for its infrastructure services, may prompt you to create an IAM user. Even if it doesn't, you should still do so.

Navigate your web browser to the service Identity and Access Management (IAM for short), which is located at: console.aws.amazon.com/iam. In the left-hand navigation pane, switch to the section labeled Users and click on the button Create New Users.

Follow the on-screen instructions in the IAM dashboard to create new users. The wizard will ask you to provide up to five usernames with a maximum of 64 characters each. An access key is optional; if you deactivate the checkbox, you can still add these credentials later.

Once you click on the Create button, up to five IAM users will be added to your AWS root account. So far, these users do not belong to any groups and they have no privileges whatsoever. The real users also do not yet know their login credentials and so do not have access.
