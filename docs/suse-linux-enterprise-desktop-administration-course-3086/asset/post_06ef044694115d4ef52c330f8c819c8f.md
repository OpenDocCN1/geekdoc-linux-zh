## Import File Systems Using Samba

Samba is a suite of applications used to integrate a Linux system into a Windows network. Samba is most commonly used as a file server for Windows hosts, but the package also contains client software to access files.

In the context of this section, we do not look at Samba from the server perspective, but from the perspective of the client accessing files using the SMB (Server Message Block) protocol. You need to

+   - Understand Samba
+   - Use Nautilus to Access and Create Samba Shares
+   - Use Samba Command-Line Tools to Access Shares

### Understand Samba

The Server Message Block (SMB) protocol is a network protocol that provides file and print services in a Windows network. Samba enables Linux to use SMB so that Linux can be integrated in a Windows environment.

SMB services are provided by the NetBIOS protocol. NetBIOS makes its own namespace available, which is completely different from the Domain Name System.

This namespace can be accessed with the Universal Naming Convention (UNC) notation: All services provided by a server are addressed as \\Server\Servicename.

File or print services offered by a server are also called *shares*.

From the desktop perspective, you can use Samba for the following purposes:

+   - *Browse Shared Files and Folders with SMB*—Both Nautilus, the GNOME file manager, and Konqueror, its KDE counterpart, support browsing shared resources through SMB.

A command-line tool that can be used for the same purpose is `smbclient`, which is part of the Samba package. The nmblookup tool can be used for NetBIOS name resolution and testing.

+   - *Share Files and Folders with SMB*—Both Nautilus and Konqueror support sharing folders and files as in Windows. This functionality is provided by the Samba server. The server side of Samba consists of two parts:
+     - *nmbd*—This daemon handles all NetBIOS-related tasks.
+     - *smbd*—This daemon provides file and print services for clients in the network.
+   - *Access and Manipulate User Data on the Windows Server*—Through Nautilus and Konqueror, users are able to access their Windows user data, and can edit, create, and delete files and folders on the Windows server. Users can access their data without having to enter their passwords again and again.

## Use Nautilus to Share Directories Using Samba

For users to be able to share folders with others using the SMB protocol, Samba needs to run on the computer and the Samba configuration has to permit users to share directories. The following lines are needed in the Global section of the /etc/samba/smb.conf file:

```
usershare allow guests = yes
usershare max shares = 50
usershare path = /var/lib/samba/usershare
```

The first line allows access to the shares without a password.
The second line limits the number of shares that can be created.
The third line specifies the directory where Samba stores the information on shared directories. The directory specified in the configuration file has to exist and needs to be writable for the users who are allowed to share directories. The following commands create the directory, change the owning group, and set the proper permissions for the directory:

```
da10:~ # mkdir /var/lib/samba/usershares
da10:~ # chgrp users /var/lib/samba/usershares
da10:~ # chmod 1770 /var/lib/samba/usershares
```

To start Samba, enter rcnmb start; rcsmb start. To have Samba start at system start, enter insserv nmb and insserv smb.
