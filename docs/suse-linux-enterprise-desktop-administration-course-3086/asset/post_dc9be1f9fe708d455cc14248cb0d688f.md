
You can also use the `useradd` command to view or change the defaults. The option **--show-defaults** displays the same information as the `cat /etc/default/useradd` command. The option **--save-defaults** followed by an option with a value changes the default:

```
da10: # useradd --save-defaults -d /export/home
da10: # useradd --show-defaults
GROUP=100
HOME=/export/home
INACTIVE=-1
EXPIRE=
SHELL=/bin/bash
SKEL=/etc/skel
GROUPS=video,dialout
CREATE_MAIL_SPOOL=no
```

You can display a description of additional options by entering `man 8 useradd`. After adding a new user, you need to assign a password.

- **passwd** — You can change a user’s password with the passwd command. If a user enters passwd without a username as an argument, the user can change his or her own password:

```
da10: # useradd -m -c "Geeko Chameleon" geeko
da10: # passwd geeko
New password:
Re-enter new password:
Password changed
```

In addition to being used to change user passwords, the passwd command can also be used to do the following:

- **Lock a user account** — Use the option `-l` (*lock*) to lock a user account; use the option `-u` (*unlock*), to reactivate the account:

```
da10: # grep geeko /etc/shadow
geeko:$2a$05$QurFt5yTH2bhVxMxZ31c9YejHGt7XefIFMQ58QHspu8WDB
FWx7BhPK:13284:0:99999:7:::
da10: # passwd -l geeko
Password changed.
da10: # grep geeko /etc/shadow
geeko:!$2a$05$QurFt5yTH2bhVxMxZ31c9YejHGt7XefIFMQ58QHspu8WDB
BFWx7BhPK:13284:0:99999:7:::
da10: #
```

An account is locked when the password begins with an exclamation mark “!”.

- *Status of a user account* — Use the option `-S` to list the status of a user account:

```
da10:~ # passwd -S geeko
geeko LK 02/02/06 0 99999 7 -1
da10:~ #
```

The status follows directly after the username. In the previous example, LK (locked) means that the user is unable to log in. Other options are NP (no password) or PS (valid password).

These are followed by the date of the last password change, the minimum length of validity, the maximum length of validity, and the warning periods and inactivity periods that specify when a password expires.

- *Change password times* — You can change the various password times by using the options shown in Table 9-1.

| Option | Description |
|---|---|
| `-i number` | Disable an account after the password has been expired for *number* of days. |
| `-n number` | Set the minimum number of days before a password can be changed. |
| `-w number` | Warn the user that in *number* of days his password will expire. |
| `-x number` | Set the maximum number of days a password remains valid. After *number* of days, the password must be changed. |

## Table 9-1

The following is an example:

`passwd -x 30 -w 5 geeko`

In this example, the password of the user geeko remains valid for 30 days. After this time, the password must be changed by geeko. Geeko receives a warning 5 days before password expiration.

When the passwd command is used to establish or change the password of a user account, the /etc/default/passwd file is checked for the encryption method to be used:

```
# This file contains some information for
# the passwd (1) command and other tools
# creating or modifying passwords.

  Define default crypt hash
# CRYPT={des,md5,blowfish}
CRYPT=blowfish
...
# We can override the default for a special service
# by appending the service name (FILES, YP, NISPLUS, LDAP)
# for local files, use a more secure hash. We
# don't need to be portable here:
CRYPT_FILES=blowfish
```

The encryption method is set in the variable CRYPT. By default, it is set to DES. For local files (such as /etc/shadow), the method is changed to Blowfish later in the /etc/default/passwd file using the variable CRYPT_FILES. Another possible encryption method is MD5. YaST also uses the /etc/default/passwd file.

- **userdel** — This command lets you delete an existing user account. If you include the option `-r`, the user’s home directory is deleted as well. Before using `userdel -r`, you should determine the user’s UID (`id user`). The UID enables you to locate files outside the user’s home directory (such as `/var/mail/$USER`) that are assigned to the user. To delete these files, enter the command:

```
find / -uid user_ID -exec rm {} \;
```

- **usermod** — Modify settings (such as UID, standard shell, home directory, and primary group) for an existing user account. The `usermod` options are basically the same as those for the `useradd` command. The following are examples:
  - Change the home directory:
    `usermod --d /data/geeko --m geeko`
  - Change the UID:
    `usermod --u 1001 geeko`

You can use the `id` command in a terminal window to display information about a user’s UID and which groups the user is assigned to. For example, entering `id geeko` provides information about the user geeko:

```
geeko@da10:~> id
uid=1000(geeko) gid=100(users)
groups=16(dialout),33(video),100(users)
geeko@da10:~>
```

This information includes the following:

- *User ID* — uid=1000(geeko)
- *Current default (effective) group* — gid=100(users)
- *All groups of which geeko is a member* — groups=16(dialout), 33(video), 100(users)

## Manage Groups from the Command Line

You can use the following commands to perform the same group management tasks available with YaST (and some tasks not available with YaST):

![](img/9129877170834ca9d5fdac5319bf5f12_294_0.png)

You need to be logged in as root (or switch to root by entering `su -`) to use these commands.

- *groupadd* — Create a new group by entering `groupadd group_name`. In this case, the next free GID is used.
  Using the option `-g` (such as `groupadd -g 200 sports`) lets you specify a GID.
  Using the option `-p` lets you specify an encrypted password. You can use the `mkpasswd` command to create the encrypted password.

- *groupdel* — Delete a group by entering `groupdel group_name`. There are no options for this command.
  You can only delete a group if no user has this group assigned as a primary group.

- *groupmod* — Modify the settings (such as GID, group name, and users) for an existing group.
  The following are examples:
  - Change the GID:
    `groupmod --g 201 sports`
  - Change the group name from sports to water:
    `groupmod --n water sports`
  - Add the user geeko to the group:
    `groupmod --A geeko water`

- *gpasswd* — Change passwords for group accounts. Only the administrator can change the password for any group. The group password can be removed with the option `-r`.

![](img/9129877170834ca9d5fdac5319bf5f12_295_0.png)

You can learn more about these commands by referring to the online manual pages (such as `man groupadd`) or online help page (such as `groupadd --help`).

If you want information on the groups in which you are a member, enter `groups`. You can specify a particular user by entering `group user`.

```
geeko@da10:~> groups geeko
geeko : users dialout video
geeko@da10:~>
```

The newgrp command allows you to change the effective group of the executing user.

```
geeko@da10:~> id
uid=1000(geeko) gid=100(users)
groups=16(dialout),33(video),100(users)
geeko@da10:~> newgrp video
geeko@da10:~> id
uid=1000(geeko) gid=33(video)
groups=16(dialout),33(video),100(users)
geeko@da10:~> exit
geeko@da10:~> id
uid=1000(geeko) gid=100(users)
groups=16(dialout),33(video),100(users)
geeko@da10:~>
```

In this example, you can see that the current shell is replaced with a new shell. A password is requested if the group has a password and the user is not listed in the group file as being a member of that group.

## User and Group Configuration Files

The information you enter when creating or editing users and groups with YaST or command-line tools is saved to the following user administration files:

- `/etc/passwd`
- `/etc/shadow`
- `/etc/group`

![](img/9129877170834ca9d5fdac5319bf5f12_296_0.png)

Whenever possible, you should not modify these files with an editor. Instead, use the Security and Users modules provided in YaST or the command-line tools described in “Manage User.” Modifying these files with an editor can lead to errors (especially in /etc/shadow), such as a user—including the user root—no longer being able to log in.

### /etc/passwd
The /etc/passwd file stores information for each user such as the username, the UID, the home directory, and the login shell.

In the past, /etc/passwd also contained the encrypted password. However, because the file needs to be readable by all (e.g., to show user and group names when using ls -l), the encrypted password is now stored in /etc/shadow, which is only readable by root and members of the group shadow.
