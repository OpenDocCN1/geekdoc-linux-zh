+   - *Status of a user account*—Use the option `-S` to list the status of a user account:

```
da10:~ # passwd -S geeko
geeko LK 02/02/06 0 99999 7 -1
da10:~ #
```

The status follows directly after the username. In the previous example, LK (locked) means that the user is unable to log in. Other options are NP (no password) or PS (valid password).

These are followed by the date of the last password change, the minimum length of validity, the maximum length of validity, and the warning periods and inactivity periods that specify when a password expires.

+   - *Change password times*—You can change the various password times by using the options shown in Table 9-1.

| Option | Description |
|---|---|
| `-i number` | Disable an account after the password has been expired for *number* of days. |
| `-n number` | Set the minimum number of days before a password can be changed. |
| `-w number` | Warn the user that in *number* of days his password will expire. |
| `-x number` | Set the maximum number of days a password remains valid. After *number* of days, the password must be changed. |

# Table 9-1

The following is an example:

`passwd -x 30 -w 5 geeko`

In this example, the password of the user geeko remains valid for 30 days. After this time, the password must be changed by geeko. Geeko receives a warning 5 days before password expiration.

When the passwd command is used to establish or change the password of a user account, the /etc/default/passwd file is checked for the encryption method to be used:

```
# This file contains some information for
# the passwd (1) command and other tools
# creating or modifying passwords.

  Define default crypt hash
# CRYPT={des,md5,blowfish}
CRYPT=blowfish
...
# We can override the default for a special service
# by appending the service name (FILES, YP, NISPLUS, LDAP)
# for local files, use a more secure hash. We
# don't need to be portable here:
CRYPT_FILES=blowfish
```
