
As root partition /dev/hda1 is transmitted to the kernel, various parameters, including the framebuffer, are set, and the system boots to runlevel 1 (single-user mode for administration).

## Manage Runlevels from the Command Line

You can change to another runlevel once the system is running by using the init command. For example, you can change to runlevel 1 from a command line by entering `init 1`.

In the same way, you can change back to the standard runlevel where all programs needed for operation are run and individual users can log in to the system.

For example, you can return to a full GUI desktop and network interface (runlevel 5) by entering `init 5`.

![](img/9129877170834ca9d5fdac5319bf5f12_410_0.png)

If the /usr partition of a system is mounted through NFS, you should not use runlevel 2 because NFS file systems are not available in this runlevel.

Like most modern operating systems, Linux reacts sensitively to being switched off without warning. If this happens, the file systems need to be checked and corrected before the system can be used again.

For this reason, the system should always be shut down properly. With the appropriate hardware, Linux can also switch off the machine as the last stage of shutting down.

You stop the system by entering `init 0`; you restart the system by entering `init 6`. The halt and poweroff commands are equivalent to init 0; the reboot command is equivalent to init 6.

The shutdown command shuts down the system after the specified time (+m: minutes from now; hh:mm: time in hours:minutes, when Linux should shut down; now: system is stopped immediately). The option -h causes a system halt; if you use the option -r instead, the system is rebooted. Without options, it changes to runlevel 1 (single-user mode).

The shutdown command controls the shutdown of the system in a special way, compared with the other stop commands. The command informs all users that the system will be shut down and does not allow other users to log in before it shuts down.

The shutdown command can also be supplied with a warning message, such as the following:

```
shutdown +5 The new hard drive has arrived
```

If a shutdown planned for a later time should not be carried out after all, you can revoke the shutdown by entering `shutdown -c`.

## Exercise 11-2: Manage Runlevels

In this exercise, you practice configuring runlevels. This exercise has four parts.

In the first part, use the runlevel command to find out about the current runlevel and the init command to change to runlevel 3 and then back to 5.

In the second part, reboot your computer and boot into runlevel 3 instead of the default runlevel 5. Log in and switch to runlevel 5.

In the third part, activate the at service atd using the YaST Runlevel Editor. The at service allows commands to be scheduled at a future point in time.

In the fourth part, activate the rsync daemon in runlevel 3 using the YaST Runlevel Editor; rsync can be used to efficiently keep files in sync between machines by only copying the parts of files that have changed.

## Detailed Steps to Complete This Exercise

- Part I: View and Change the Current Runlevel
- Part II: Set a Runlevel at Boot Time
- Part III: Activate the at Service atd
- Part IV: Enable rsyncd with YaST

### Part I: View and Change the Current Runlevel

To view and change the current runlevel, do the following:

- 1. Open a terminal window and switch to the root user using the `su -` command (password `n0v311`).
- 2. Check the previous and current runlevels by entering `runlevel`.
  List the runlevels:

| Previous | Current |
|---|---|
|  |  |

Notice that the previous runlevel is listed as N, which means that there was no previous runlevel set.

- 3. Change to runlevel 3 by entering `init 3`.
  The graphical environment is terminated and you are left at a terminal login prompt.
- 4. Log in as root with a password of `n0v311`.
- 5. Check the previous and current runlevel by entering `runlevel`.
  List the runlevels:

| Previous | Current |
|---|---|
|  |  |

- 6. Switch to runlevel 5 by entering `init 5` in the terminal window.
  The GUI login screen appears.
- 7. Log in as a geeko with a password of `novell`.

### Part II: Set a Runlevel at Boot Time

To set a runlevel at boot time, do the following:

- 1. From the GNOME desktop, select Computer > Shutdown > Restart.
- 2. When the boot menu is displayed, press Spacebar to stop the timer.
- 3. In the Boot Options field, type `3`; then press Enter to boot the Linux system to runlevel 3.
- 4. When the login prompt appears, log in as root with a password of `nov311`.
- 5. Display the current runlevel by entering `runlevel`.
- 6. Switch to runlevel 5 by entering `init 5`.
- 7. Switch back to the virtual terminal by pressing Ctrl+Alt+F1.
- 8. Log out as root by entering `exit`.
- 9. Switch back to the graphical user interface by pressing Ctrl+Alt+F7.
- 10. Log in as geeko with a password of `novell`.

### Part III: Activate the at Service atd

To activate the at service atd, do the following:

- 1. Open a terminal window and change to the `/etc/rc.d/rc3.d` directory by entering `cd /etc/rc.d/rc3.d`.
- 2. List the atd files in the directory by entering `ls -l *atd`.
  Notice that there are none.
- 3. From the graphical desktop, start YaST.
  The YaST Control Center appears.
- 4. Select System > System Services (Runlevel).
  The Runlevel Editor: Services dialog appears.
- 5. Make sure the Simple Mode radio button is selected.
- 6. Select the atd entry in the list of services.
- 7. Select Enable; confirm the message that other services have to be started as well by selecting Continue.
  A message informs you that the service atd started successfully. Confirm this message by selecting OK.
- 8. Close the Runlevel Editor by selecting Finish. Confirm the message that the changes will be saved.
- 9. In the terminal window, again list the atd files in the `/etc/init.d/rc3.d` directory by entering `ls -l *atd`.
  Notice that now there are links pointing to `/etc/init.d/atd`.
- 10. Switch to virtual terminal 1 by pressing Ctrl+Alt+F1. Log in as root (password `nov311`). Verify that the at service is running by entering `rcatd status`.
- 11. Switch to runlevel 1 by entering `init 1`.
- 12. Enter a root password of `n0v3ll`.
- 13. Determine if the at service is running by entering `rcatd status`.
  The service is listed as unused because it is not configured to start at runlevel 1.
- 14. Switch back to your previous runlevel (5) by entering `init 5`.
  The GUI login screen appears.
- 15. Log in as geeko with a password of `novell`.
- 16. Open a terminal window and `su -` to root (password `n0v3ll`).
- 17. Determine if the at service is running by entering `rcatd status`.
  The service is running again.
- 18. Close the terminal window.

### Part IV: Enable rsyncd with YaST

To enable rsyncd with YaST, do the following:

- 1. From the graphical desktop, start YaST.
  The YaST Control Center appears.
- 2. Select System > System Services (Runlevel).
  The Runlevel Editor: Services dialog appears.
- 3. Switch to a more detailed view (with additional options) by selecting Expert Mode.
- 4. Scroll down the Services list and select rsyncd.
- 5. Below the list, in the Service will be started in the following runlevels: section, configure this service to start in runlevel 3 by selecting 3.
- 6. From the Set/Reset drop-down list, select **Enable the Service**.
  Notice that now runlevel 5 is selected as well. When selecting Enable the Service, the runlevel information is read from the Init-info block in the `/etc/init.d/rsyncd` file.
- 7. Deselect 5 in the Service will be started in the following runlevels: section of the dialog by clicking on 5.
- 8. Start the rsyncd service from the Start/Stop/Refresh drop-down list by selecting Start Now.
  A status message appears indicating that the service started successfully.
- 9. Close the status message by selecting OK.
- 10. Stop the rsyncd service from the Start/Stop/Refresh drop-down list by selecting Stop Now.
  A status message appears indicating that the service stopped successfully.
- 11. Close the status message by selecting OK.
- 12. Save the changes by selecting **Finish**; then select **Yes**.
- 13. Close the YaST Control Center and the terminal window.
