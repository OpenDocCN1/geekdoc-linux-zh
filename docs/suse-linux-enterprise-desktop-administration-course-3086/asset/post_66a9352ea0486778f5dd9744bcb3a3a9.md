## Objective 5—Use Encrypted File Systems

With SUSE Linux Enterprise Desktop 10, it is possible to encrypt a file system on a partition, or to create encrypted home directories based on images that contain an encrypted file system. Both can be set up with YaST:

- Use YaST to Encrypt a Partition
- Create an Encrypted Image as Home Directory for a User

### Use YaST to Encrypt a Partition

To encrypt a partition, you only need to select the appropriate option when creating the partition in YaST and enter a password to unlock the partition when it is mounted.

To start YaST, select Computer > More Applications > System > YaST. In the YaST Control Center, select System > Partitioner and confirm the warning dialog. To create a partition, select Create. A dialog similar to the one shown in Figure 9-13 opens up (the dialog has a different caption, depending on whether you create a primary or a logical partition).

In this dialog, enter the information, such as size, mount point, and file system, needed to create the partition, and select the Encrypt file system option.

![](img/9129877170834ca9d5fdac5319bf5f12_319_0.png)

Figure 9-13

> > **NOTE**  
> > YaST does not support the encryption of the root file system.

When you select OK, the dialog shown in Figure 9-14 appears, prompting you to enter a password.

![](img/9129877170834ca9d5fdac5319bf5f12_319_1.png)

Figure 9-14

The minimum password length required is eight characters, but a longer password is advisable.

Eight characters are roughly comparable to a 40-bit symmetric encryption key, which is not considered secure anymore. Twenty random characters would be comparable to a 120-bit key, under the assumption that there are 64 possible choices for each character and they are chosen at random.

Twenty truly random characters, on the other hand, are very hard to remember, so some trade-off has to be made. If you forget the password, the data in that partition is lost.

To unlock the partition when the system boots, a prompt appears during the boot process. Because there is a timeout, the machine boots even if no password is entered, but the partition is not accessible. To access the partition, log in as root and enter `/etc/init.d/boot.crypto start`; then enter the password for the partition.

### Create an Encrypted Image as Home Directory for a User

Another approach is offered in YaST as part of the User Management module. When creating or editing a user with that module, as described in “Manage User and Group Accounts with YaST,” select the Details tab. See Figure 9-15.

![](img/9129877170834ca9d5fdac5319bf5f12_320_0.png)

Figure 9-15

Select **Use Encrypted Home Directory**, and change the Directory Size as needed. This will create a file of that size with an encrypted file system inside. This file system can be mounted as a loop device. The image file is named *username.img* and located in /home. The key used to decrypt the image is *username.key* in /home, and the user’s password is used to unlock it.

The encryption is transparent for the user—the user can access the encrypted files after login without having to enter another password to unlock the files. However, if the user forgets his or her password, the data is lost; when root resets the user’s password, the password for the decryption key remains unchanged. Users should be informed of this fact.

After root has changed a user password, the user has to enter the new password to log in, and the old password to access the files. The password for the files then gets updated automatically, so that on the next login the new user password is again sufficient to log in and to access the files.

![](img/9129877170834ca9d5fdac5319bf5f12_321_0.png)

After the encrypted partition or the encrypted loop file system is mounted, any data on it is protected from being viewed by other users on the system only by the permissions set for the individual files and directories.

## Summary

- Linux is a multiuser, multitasking, and multithreading operating system that restricts access to file and directory resources based on user account.
- Users use normal user accounts to log in to the system, whereas system services use system user accounts when performing tasks on the system. The root user is a special user account that has access to all system resources.
- Each user account is a member of one or more groups that can be viewed using the groups command. System users typically belong to system groups, whereas regular user accounts belong to normal groups. The root user belongs to the root group.
- Linux systems store user information in /etc/passwd and password information in /etc/shadow. Group information is stored in the /etc/group file.
- For system identification, each user account has a UID, and each group account has a GID. The root user always has UID 0 and the root group has a GID of 0.
- The id command displays your UID, GIDs, and primary GID. You can change your session’s primary GID using the newgrp or sg commands.
- The su and gnome-su commands can be used to switch to another user account or run a program as another user account. Alternatively, users can be granted rights to run certain commands as other users using the sudo command via entries in the /etc/sudoers file.
- You can use the useradd, usermod, and userdel commands to add, modify, and remove user accounts on your system, respectively. Similarly, you can use the groupadd, groupmod, and groupdel commands to add, modify, and remove group accounts on your system, respectively.
