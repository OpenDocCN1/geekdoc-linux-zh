# Exercise 15-1: Create an AutoYaST Control File

In this exercise, you create an AutoYaST control file.

## Detailed Steps to Complete This Exercise

To create a AutoYaST control file, do the following:

- 1. In a terminal window, run the su -- command to switch to root (password n0v311) and enter yast2.
- 2. In the YaST Control Center, select Miscellaneous > Autoinstallation.
- 3. Select Tools > Create Reference Profile; select Create.
- 4. Browse through the created profile by selecting sections of the tree on the left side of the dialog and selecting entries in the main window. Change the configuration if you like.
- 5. Save the file by selecting File > Save, enter sled10.xml as the filename, and select Save.
- 6. Have a look at the file /var/lib/autoinstall/repository/sled10.xml in a text editor. Quit the editor when done.
- 7. Close any open windows.

## Objective 4—Installation Server: Setup and Use

An installation server offers the files needed for the installation of SUSE Linux Enterprise Desktop via the network. To provide such a server in your network, you need to understand how to:

- Set Up an Installation Server
- Use the Installation Server

## Set Up an Installation Server

The installation repository requires a certain layout of directories and files on the installation server. The most convenient way to set up such an installation repository is to use SUSE Linux Enterprise Server 10 and its YaST module Installation Server. This module creates the necessary directory structure, prompts you to insert the CDs or DVD to copy their content to the proper directories, and sets up the server (NFS, HTTP, FTP) used to distribute the files. You can also use SUSE Linux Enterprise Desktop 10 as an installation server. However, there is no YaST module for this purpose, so you have to set up the server manually. The following steps are required:

- Fill the Installation Repository
- Configure the NFS Server

## Fill the Installation Repository

First create a directory, such as /export/sled10, where you want to store the installation repository using the mkdir -p /export/sled10 command. Filling the repository is very simple: Just insert the SUSE Linux Enterprise Desktop 10 Installation DVD and copy all files on it to the repository:

```
cp -a /media/SLED100.001/* /export/sled10/
```

![](img/9129877170834ca9d5fdac5319bf5f12_607_0.png)

The same procedure is used for SUSE Linux Enterprise Desktop 10 service packs because they replace the original installation media.

In addition to the packages available for installation on the DVD, you can add external packages. You need to take only a few more steps to make these available. The following describes a directory structure to include software updates, but it can be used for external or custom packages as well.

- 1. To install the autoyast-utils package, log in as root and enter the following in a terminal window:
- 2. Run the create_update_source.sh command with the root of your installation repository as the argument:
- 3. Copy any RPM files you want to make available to the updates/suse/ architecture/ directory.
- 4. Change to that directory and run the updated_package_descr command:

```
yast -i autoyast2-utils
```

```
da10:~ # create_update_source.sh /export/sled10/
Creating /export/sled10//updates..
...
```

This will create the updates and yast directories as well as several subdirectories and files within your installation repository.

```
da10:/export/sled10/updates # cd suse/i386/
da10:/export/sled10/updates/suse/i386 #

using settings:
datadir: .
languages: english

extra_provides: setup/descr/EXTRA_PROV
done

now recoding to UTF-8: packages packages.DU
packages.en
da10:/export/sled10/updates/suse/i386 #
```

5. Change to the updates/setup/descr directory and create SHA1 hash values for the files in that directory. The output of the command is appended to the updates/content file:

```
da10:/export/sled10/updates/suse/setup/descr #
for i in *; do
> echo -n "META SHA1 "
> shasum $i `awk '{ORS=""; print $1}'`
> echo -n "$i"
> basename $i
> done >> /export/sled10/updates/content
da10:/export/sled10/updates/setup/descr # cat content
PRODUCT SUSE SLED Updates
VERSION 10
DISTPRODUCT SuSE-Linux-Updates
...
META SHA1 964d721fd605ce45ceeff7fd9a8b938b5f67daa5
packages.DU
META SHA1 3577376a62f31415fa47c5b3f84daab852334c1d
packages.en
```

6. Create an add_on_products file in the root of your installation repository that lists the directories with add-on products:

```
da10:/export/sled10 # echo
"nfs://10.0.0.10/export/sled10/updates" >
add_on_products
da10:/export/sled10 #
```

7. The content file in the root directory of the installation repository is digitally signed. This signature is checked during installation. You can sign the content file in the updates directory as well and add the public key corresponding to the private key used to create the signature to that directory. Later, during installation, you are asked if you want to accept the key. (To avoid that dialog, include the public key in the initrd.) The commands shown in the following grey box assume that you have already generated a GPG key pair. The last command updates the directory.yast file.

```
da10:/export/sled10/updates # gpg --export --armor
0x50EDE9F2 > content.key
da10:/export/sled10/updates # gpg -b --sign --armor
```
