## Objective 5—Control Mounting of CD-ROM, DVD, and USB Devices

By default, removable media like CD-ROMs, DVDs, and USB storage devices are automatically mounted. The program providing this functionality is the GNOME Volume Manager.

To control the automatic mounting of media, you have to understand how to do the following:

- Use the GNOME Volume Manager
- Disable Automatic Mounting of Media

### Use the GNOME Volume Manager

The GNOME Volume Manager (gnome-volume-manager) is started automatically when the GNOME desktop is launched. It monitors volume-related events and responds with a user-specified policy.

The user or the system administrator can configure what happens when some media, such as a CD-ROM, is inserted and what commands are executed.

The GConf editor lists the available keys under Desktop > GNOME > Volume Manager. See Figure 14-14.

![](img/9129877170834ca9d5fdac5319bf5f12_591_0.png)

Figure 14-14

By checking or unchecking the boxes on the right, you can activate or deactivate various features, like whether or not a window should open when removable media are inserted. Commands to execute when a certain event happens can be changed by double-clicking entries and editing the string in the dialog that opens.

If you, as a system administrator, want to make any settings mandatory, proceed as described in “Use GConf to Set Mandatory Preference Values.”

### Disable Automatic Mounting of Media

Depending on company policy or the use of the workstation, you might have to prevent users from reading from or writing to removable media or mounting removable devices such as USB drives or sticks.

There are various ways to configure this. Which one you choose depends mainly on how difficult you want to make it for any user who tries to circumvent the restrictions you impose.

- GConf and /etc/fstab—Use gconftool-2 to set the automount_drives and automount_media keys in /desktop/gnome/volume_manager in the mandatory GConf repository to false.

While this prevents automatic mounting, the user can still mount the drive by selecting the desktop icon that appears when a CD-ROM is inserted.

You can add an entry in /etc/fstab (like the following) to prevent mounting of CD-ROMs or DVDs by unprivileged users (assuming that /dev/hdc represents the CD-ROM/DVD drive):

```
/dev/hdc   /media/dvd   auto   noauto,defaults   0 0
```

Now an error message will appear when a user selects the CD-ROM icon on the desktop.

- Kernel modules—To read from USB storage devices, the usb_storage kernel module is needed. You can prevent the module from being loaded by entering the following line in /etc/modprobe.conf.local:

```
install usb_storage /usr/bin/true
```

You can use other programs instead of /usr/bin/true as well. The following example (in one line in /etc/modprobe.conf.local) will cause an e-mail notice to be sent when someone inserts such a device:

```
install usb_storage /usr/bin/mail -s "USB-Stick inserted on $HOSTNAME" desktopadmin@digitalairlines.com
```

You could disable USB completely by adding similar lines for usbcore and other USB modules (use lsmod to find which ones). But this might not be practical because that would disable a USB keyboard and mouse as well.

You could rename or remove the USB kernel modules. However, the next kernel update would bring them back and enable USB storage again.

- Configure udev rules—In the past, the /dev/ directory contained a device file for hundreds of devices, even if the hardware was not present. With udev, this has changed; device files are created only for actually present devices. udev is very flexible and can be configured by writing rules to *.rules files in the /etc/udev/rules.d/ directory. A rule to disable devices that require the usb_storage module could look like the following:

```
dal0:/etc/udev/rules.d # cat 10-local.rules
# Disable USB storage
DRIVER=="usb-storage", OPTIONS+="ignore_device last_rule"
dal0:/etc/udev/rules.d #
```

The ignore_device option will ensure that no action is taken and, therefore, no device file is created to access the device. The last_rule option prevents later rules from changing this rule.

Much more fine-grained control than shown above is possible. You could, for instance, write rules allowing a specific USB device based on its serial number, and ignoring other devices.

![](img/9129877170834ca9d5fdac5319bf5f12_593_0.png)

The manual page for udev and the udev HOWTO at http://www.reactivated.net/writing_udev_rules.html provide more information on how to write udev rules.

- Remove the hardware—Physically remove CD-ROM and DVD drives as well as USB ports. This also prevents the computer from being booted from bootable CDs.

## Summary

- Xgl and the Compiz window manager work with the X Window System and your KDE or GNOME desktop environment to provide 3D-enhanced graphical effects using OpenGL.
- To configure your video graphics card and monitor for use with X, you can use YaST or sax2. Following this, you can enable Compiz using the GNOME Control Center or the gnome-Xgl-settings command.
- You can use GConf to customize the GNOME user interface for the system for individual users as well as lock down access to certain desktop areas.
- To configure GConf, you can use gconf-editor, gconftool-2, or the GNOME Preferences panel. Individual GConf user configuration settings are stored in the ~/.gconf directory. Systemwide GConf configuration settings are stored in the /etc/opt/gnome/gconf directory.
- The Desktop Profile Editor can be used in addition to GConf to create custom desktop settings profiles for different user accounts or lock down access to the desktop.
- You can customize graphical applications using YaST, as well as configure program preferences, alter configuration files, and create templates. The /etc/skel directory contains default configuration files that are copied to the home directories of new user accounts.
- To enhance security on a computer that has removable media devices, you should prevent regular users from mounting removable media. This can be done by configuring GConf or by creating udev rules, as well as by editing the appropriate lines in the /etc/fstab or /etc/modprobe.conf.local files.

## Key Terms

**/etc/fstab** A file used to automatically mount file systems at system initialization.
**/etc/modprobe.conf.local** The configuration file that lists kernel modules loaded at system initialization.
**/etc/opt/gnome/desktop-profiles** The directory used to store user profiles and profile configuration information created by the Desktop Profile Editor.
**/etc/opt/gnome/gconf** The directory that stores systemwide GConf configuration.
**/etc/skel** A directory that contains files that are copied to a user's home directory when the user account is created.
**/etc/udev/rules.d** The directory used to contain rules used by the udev system.
**~/.gconf** The directory that stores personalized GConf configuration.
**~/.mozilla/firefox** The directory used to store user-specific configuration information for use with the Firefox Web browser.
**~/.ooo-2.0** The directory used to store user-specific configuration information for use with OpenOffice.org in SUSE Linux.
**Compiz** A composite and window manager that uses Xgl to provide enhanced graphics capabilities to a desktop environment.
**composite manager** A software component that creates composite images within a window manager.
**Desktop Profile Editor** A graphical utility that can be used to create, modify, and apply desktop profiles using GConf.
**Evolution** A common e-mail client application on Linux systems today.
**Firefox** The most common Open Source Web browser used on computer systems today.
