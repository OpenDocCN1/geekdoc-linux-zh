
## gconf-editor

To set or change mandatory settings, you must be logged in as root when you use gconf-editor. The steps you take depend on what you need to do:

- Set Preferences as Mandatory for the First Time
- Change Existing Mandatory Preferences

## Set Preferences as Mandatory for the First Time

As root user, start gconf-editor. The left part of the window lists the available keys. Browse the tree to the key you want to set as mandatory and set it to the desired value. Then select the entry with the right mouse button; in the context menu, select Set as Mandatory.

If you click on the entry to change it again, an error message tells you that this is not possible.

## Change Existing Mandatory Preferences

As root user, start gconf-editor; then select File > New Mandatory Settings. The left part of the window lists those mandatory settings that have already been set in the /etc/opt/gnome/gconf/gconf.xml.mandatory/ repository tree. You can change them as explained in "User-Defined Settings."

To remove a key from the mandatory preferences, right-click on the entry and select Unset Key.

Values that have not been set to a mandatory value previously do not show up in the repository tree on the left of this gconf-editor dialog.

## gconftool-2

You can also use the gconftool-2 command-line tool to set preferences to a mandatory value. (When you use gconftool-2, the gconf-editor can be helpful to browse the configuration repository tree to find the correct key and its path.)

Let's assume that the security policy of the company requires the screens of desktops to be locked after 5 minutes of inactivity. As administrator, it is your task to configure the workstations accordingly and to make sure this policy is followed by all users.

Using gconf-editor as a normal user, you browse the repository tree and find out that the keys for this purpose are /apps/gnome-screensaver/lock_enabled and /apps/gnome-screensaver/idle_delay. To set these to mandatory values, log in as root and use the following commands:

```
da10:~ # killall gconf-2
da10:~ # gconftool-2 --direct --config-source
xml:readwrite:/etc/opt/gnome/gconf/gconf.xml.mandatory --set --type
bool /apps/gnome-screensaver/lock_enabled true
Resolved address "xml:readwrite:/etc/opt/gnome/gconf/gconf.xml.mandatory"
to a writable configuration source at position 0
da10:~ # gconftool-2 --direct --config-source
xml:readwrite:/etc/opt/gnome/gconf/gconf.xml.mandatory --set --type
int /apps/gnome-screensaver/idle_delay 5
Resolved address "xml:readwrite:/etc/opt/gnome/gconf/gconf.xml.mandatory"
to a writable configuration source at position 0
```

The next time a user logs in and tries to change the respective screen saver settings in the GNOME Control Center, the user will not be able to change these values.

![](img/9129877170834ca9d5fdac5319bf5f12_580_0.png)

Not all key-value pairs that can be set seem to have the desired effect. For example, setting the /apps/firefox/general/homepage_url key to a certain value does not seem to have any effect on the default home page of the Firefox browser. Other such key-value pairs might not behave as expected either. Therefore, you should test your settings to make sure they have the desired effect and cannot be changed by the user before you rely on your settings.

## Use the Desktop Profile Editor

The Desktop Profile Editor (sabay on package) allows you as the administrator to set preferences on a per-user basis.

Using the Desktop Profile Editor consists of two steps:

- Define a Profile
- Assign Profiles to Users

## Define a Profile

To start the Desktop Profile Editor, select Computer > More Applications > System > Desktop Profile Editor. You are prompted for the root password. A User Profile Editor window appears, as shown in Figure 14-6.

![](img/9129877170834ca9d5fdac5319bf5f12_580_1.png)

Figure 14-6

Because no profile exists, you must add a profile. Select Add and enter a name for the new profile. This name appears in the User Profile Editor window. Select the name; then select Edit. A GNOME desktop is started in an xnest window.

In this window, you can configure the desktop according to your needs.

![](img/9129877170834ca9d5fdac5319bf5f12_580_2.png)

When the screen saver within the xnest window locks that screen, you can use the host machine's root password to unlock it.

When you are done, in the Editing Profile profilname window, select Edit > Changes. See Figure 14-7.

![](img/9129877170834ca9d5fdac5319bf5f12_581_0.png)

# Figure 14-7

The list displays all configuration changes that were made since the session started or since the last time changes were saved. To make a change mandatory, click on the lock on the respective line. To ignore a change, select the “Ignore” check box. If you do not select either, the value will be used as the default.

To save your profile, select Profile > Save. To close the xnest window, select Profile > Quit. The profile is saved in /etc/opt/gnome/desktop-profiles/ profilname.zip. It contains configuration files such as .gtkrc and GConf preferences containing keys such as .gconf.xml.mandatory/desktop/gnome/background/%gconf.xml.

## Assign Profiles to Users

After creating a profile, you can assign it to specific users or to all users by selecting the profile and then Users in the User Profile Editor.

The dialog shown in Figure 14-8 appears.

![](img/9129877170834ca9d5fdac5319bf5f12_582_0.png)

Figure 14-8

Select the users to whom the profile applies, or select Use This Profile for All Users. This information is stored in /etc/opt/gnome/desktop-profiles/users.xml.

Every time a user logs in to his GNOME desktop, the /etc/X11/xinit/xinitrc.d/sabayon-xinitrc.sh script is executed:

```
#!/bin/bash
#
# Apply the Sabayon profile for the current user (if any)
#
if [ "$XDISABLE_SABAYON_XINITRC" = "x" ] ; then
  if [ -x /opt/gnome/sbin/sabayon-apply ] ; then
    /opt/gnome/sbin/sabayon-apply
  fi
fi
```

This, in turn, executes /opt/gnome/sbin/sabayon-apply. For users with a profile, this command copies the files contained in the .zip file to the user's home directory. Then gconftool-2 reads the various repositories in the sequence given in /etc/opt/gnome/gconf/2/path and sets the preferences accordingly.

As an administrator, you should be aware that a user can at least temporarily circumvent the settings marked as mandatory in the Profile Editor of Sabayon. The user simply needs to

- Kill gconfd-2
- Delete the ~/.gconf.* files and directories

After that, the user can change even those settings that were marked mandatory in the editor. Settings made mandatory in /etc/opt/gnome/gconf/gconf.xml.mandatory cannot be circumvented like that.

The next time the user logs in to GNOME, the deleted GConf files are copied back into the user's home directory.

Therefore, Sabayon should be considered a means to provide a stable configuration that can easily be restored by logging out and in again rather than a way to restrict users.

## Exercise 14-3: Set Mandatory Values for Preferences

In this exercise, you use the Desktop Profile Editor to set mandatory preferences.
Use the Desktop Profile Editor (Sabayon) to lock the screen of all users after five minutes of inactivity.

## Detailed Steps to Complete This Exercise

To set mandatory preferences, do the following:

- 1. On the GNOME desktop, select Computer > More Applications > System > Desktop Profile Editor. Enter the root password (n0v311) in the dialog that appears.
- 2. In the User Profile Editor dialog, select Add. Then, in the Add Profile dialog, enter penguins as the profile name; then select Add.
- 3. Select Edit; an xnest window opens.
- 4. In this window, select Computer > Control Center > Screensaver. Move the Set Session as Idle After slider to 5 minutes.
  Also toggle the settings for Activate screen saver when session is idle and Lock screen when screensaver is active off and on once.
  Close the dialog.
- 5. In the menu of the xnest window, select Edit > Changes.
  Click on the locks in front of the entries that set the idle_delay key to 5 minutes, activate the screen saver when the session is idle, and lock the screen when the screen saver is active.
- 6. In the menu of the xnest window, select Profile > Save. Close the xnest window.
- 7. In the User Profile Editor window, make sure penguins is selected; then select Users.
- 8. In the Users for Profile Penguins dialog, select Use This Profile for All Users.
- 9. Log out from the GNOME desktop. Log in again. Try to change the screen saver settings.

![](img/9129877170834ca9d5fdac5319bf5f12_583_1.png)

If you can still edit the screen saver settings, open a terminal window, killall gconfd-2, delete .gconf* directories and files, and log out and back in again. Then try again to change the screen saver settings.
