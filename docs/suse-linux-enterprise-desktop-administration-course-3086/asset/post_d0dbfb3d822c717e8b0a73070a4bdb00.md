## Boot a System Directly into a Shell

The boot screen of the GRUB boot loader lets you enter parameters that modify the behavior of the Linux kernel.

At the bottom of the GRUB boot screen is the **Boot Options** field. To add a boot option, select an operating system and type the additional boot option in the Boot Options field.

One way to access a system that is not booting anymore is to set a different program for the init process. Normally, the Linux kernel tries to find a program named init and starts this program as the first process. All other processes are then started by init.

With the boot parameter init=new_init_program, you can change the first program loaded by the kernel. For example, by entering the boot parameter init=/bin/bash, the system is started directly into a bash shell.

You are directly logged in as root without being asked for a password.
You can use this shell to access the file system and fix a misconfiguration.

![](img/9129877170834ca9d5fdac5319bf5f12_396_0.png)

Depending on the Linux system, the root file system might be mounted as read-only after booting into a shell. In this case, you need to remount the file system with the following command to be able to change configuration files:

```
mount -o remount,rw,sync -t filesystem_type device_name
mount_point
```

Entering exec /sbin/init at the bash prompt replaces the shell with the init program and continues the boot process until the default runlevel is reached.

If you want to prevent access to the machine as described previously, you can change the boot configuration to require a password before the kernel command line can be edited.

In the /boot/grub/menu.lst file, the following line within the general options makes sure that the choices defined further below in the file (title SLED 10, etc.) can only be selected in unmodified form:

```
Password secret
```

The use of additional kernel parameters requires the password secret. Because the graphical boot menu could be used to circumvent the password feature, it is automatically disabled when the entry password appears in the configuration file.

GRUB can also handle MD5-encrypted passwords that are generated as follows:

```
da10:~ # grub-md5-crypt
Password:
Retype password:
$1$FTeTk1$qaV.tOrzbg3EYAgVfNup40
```

This string can be copied to the /boot/grub/menu.lst file with the following syntax:

```
password --md5 $1$FTeTk1$qaV.tOrzbg3EYAgVfNup40
```

The lock parameter within a title section can be used to force the password query before these title entries can be selected.

```
title Floppy
    lock
    chainloader (fd0)+1
```

Selecting Floppy in the boot menu is now only possible after entering the password. The parameter password can also be used in individual title entries to define a special password for those title entries.

Please note that the password feature only moderately enhances security because it does not prevent booting the computer from another medium, such as the SLED 10 rescue system, and then accessing the files on the hard disk.

If you want to decide for each service (postfix, sshd, etc.) whether or not to start it during booting, use the confirm parameter at the boot prompt.

### The init Program and Linux Runlevels

In order to understand Linux system initialization and management, you need to examine the following:

- The init Program
- The Runlevels
- init Configuration File (`/etc/inittab`)

**The init Program** The system is initialized by `/sbin/init`, which is started by the kernel as the first process of the system.

This process, or one of its child processes, starts all additional processes. In addition, because init is the last process running, it ensures that all other processes are correctly ended. This means that init controls the entire booting up and shutting down of the system.

Because of this position of priority, signal 9 (SIGKILL), with which all processes can normally be ended, has no effect on init.

The configuration file for init is `/etc/inittab`. Various scripts are started by init, depending on entries in this file. All these scripts are located in the `/etc/init.d/` directory.

Part of the configuration in `/etc/inittab` is the runlevel the system uses after booting.
