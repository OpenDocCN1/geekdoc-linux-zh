After he enters that command, whenever anyone enters the write quixoted command, they will immediately get a write: quixoted has messages disabled message.

If later our noble knight wants to make himself available to receive mes-sages and conversations again, then he could type

```
$ msg y<Enter>
```

By default, the system's shell startup process permits messaging. If a user has just entered msg n during a login session and then logs out and logs in again, the system resets the username to msg y. To prevent messages from coming through after exiting and logging in again, the user must reset msg n.

Users can override the default msg y behavior by including msg n in their $HOME/.bash_profile file. In other words, they can set msg n in the script that runs automatically when they log in. We will discuss the $HOME/.bash_profile file and other similar files in Chapter 11, "Shell Vari-ables and the User Environment.""
