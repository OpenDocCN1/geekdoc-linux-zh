
不要试图预知明天。人们所能做的最好的事情，就是构建能够适应未来变化的软件，以满足当今的需求。因此，开发者不应花费数周或数月编写设计规范，而应记录他们计划采取的大致方向的概述，然后着手进行。

尽早构建原型是一个重要步骤。它帮助设计者尽早将应用交到他人手中，从而让向第三系统（Third System）的进展开始得更早而不是更晚。原型加速了你迈向未来的速度。它们鼓励你在事情仍然灵活多变时首先做出改变，而不是等到一切定型。它们向你展示什么将起作用，以及——最重要的是——什么将不起作用。

如果你使用做一件事并将其做好的小程序逐步构建原型，那么构建原型会容易得多。这允许你随着工作进行以最小的努力添加功能。

请记住，软件实际上并不是被“构建”出来的。它是生长出来的。随着软件的成长，它移植到新的硬件平台后无疑会变得更加有价值。当新架构出现时，具有可移植性的软件可以迅速利用它们。因此，在构建原型时，请优先选择可移植性而非效率。可移植的东西能存活下来，而其他一切很快就会过时。

可移植的数据与可移植的应用程序密不可分。只要可能，就将数据存储在扁平文本文件中。同样，我们无法预测未来，所以你无法知道数据最终可能去哪里。不要担心可移植数据效率不高。即将面世的新硬件平台将以比当今最快机器还要快得多的速度移动你的数据。还要记住，使用可移植数据也简化了到达第三系统的过程，因为数据在过程的各个阶段都可以被人类阅读。

可移植软件会来到你编写它时从未梦想过的硬件平台上。从某种意义上说，通过编写可移植软件，你为自计算黎明以来编写的软件财富做出了贡献。请记住，对于你交给世界的任何软件，你也有权接受来自他人的软件。随着你的软件传播，它将增强用户执行任务的能力。

你所做的几乎每件事的影响都会复合放大。同样，还有其他程序员的工作也在复合累积。为了利用这种杠杆效应，请彻底摒弃“非本实验室发明”（NIH）综合征。创建新的应用程序，但不要浪费时间重写别人已经为你写好的东西。今天世界上存在的软件代表着一大笔财富。当你在该领域播种时，务必要收获那些唾手可得的果实——当然，要合法地进行。

为了在双向上更大地增强软件杠杆效应，请尽可能使用脚本和其他高级抽象。它们利用了别人为你所做的工作。脚本有助于将其对世界的影响复合放大，同时让你以更少的努力做更多的事。

如果你有一系列可操作的小程序，构建脚本会容易得多。但是，如果这些程序需要用户直接键入输入，它们就没多大用处。因此，避免使用 CUI（字符用户界面）。相反，将所有程序视为过滤器。程序并不创建数据，它们只修改数据。让你的程序更容易在其他地方被使用。协同效应（Synergy）。这就是关于协同效应。

这就完了吗？嗯，是的。大多数 Unix 和 Linux 程序，单独来看，并不值得吹嘘。你总能找到比 Unix 系统上找到的更好的文字处理程序、更花哨的电子邮件程序或更美观的目录文件夹视图。（不过，一些 Linux GUI 应用程序本身也颇令人印象深刻。）然而，如果你试图对文本做一些单块式文字处理器未设计来处理的事 [2]，你会发现 Unix 非常、非常强大。

其他操作系统的倡导者声称某种操作系统在某些方面比 Unix 做得更好。在某些情况下，这可能是真的。即便如此，Unix（以及随着其成熟度的 Linux）也很可能以编写新应用所需时间的一小部分提供 90% 的解决方案。此外，在几乎所有情况下，即使在那看似无法做到的情况下，Unix 也能提供这种 90% 的解决方案。

## 第 9 章：Unix 与其他操作系统哲学

### 概述

在此节点上，对除 Unix 以外的一些其他操作系统的哲学进行简短的讨论是恰当的。我们不会深入这一领域，因为我们无意撰写关于比较操作系统哲学的论文。但是，对软件世界中其他几种“宗教”的简要考察应该会起到启发作用，至少能说明 Unix 方法为何与其他软件设计方法如此截然不同。

本章我们将探讨三种历史性操作系统的设计哲学。每种都在其各自的利基市场中取得了成功。每种都发展出了一群忠实的拥趸。每种都与 Unix 和 Linux 有一些共同点，每种又具有一些将其区分开来的特征，有时这些特征甚至非常显著。

出于各种各样的原因，其中不乏有限的硬件容量，这些操作系统是为特定的硬件平台编写的。用户需要充分的理由，才愿意花费数千美元乃至数百万美元购买相对不灵活的系統。你无法在折扣零售商和跳蚤市场上获得数千个应用程序。个人电脑并不廉价且充裕。很少有人会在地下室里堆积大量未使用的家庭用品，而在上面放着落满灰尘的旧电脑。

最终，更新、更快的硬件出现了，导致这些 OSS（开放源码系统/或指原文语境下的操作系统）被弃用。没有 Unix 的可移植性，当硬件设计者生产具有更大存储容量、专用外设和先进图形能力的机器时，它们无法跟上步伐。这里的唯一例外是微软的磁盘操作系统（MS-DOS）。然而，MS-DOS 并不是一个可移植的操作系统。它被移植到逐渐更强大的机器上，但它们本质上都是相同的架构。在较新的 Windows 版本中，微软几乎完全淘汰了 MS-DOS，转而支持 Windows API 和 GUI。

虽然这里讨论的操作系统本身大多已湮没无闻，但它们的设计哲学至今仍以某种形式存在。例如，虽然 Atari 家用电脑的生产早在多年前就停止了，但其操作系统中的人机工程概念仍在当今最热门的游戏机中不断被实现和完善。

如果我误解了操作系统设计者的初衷，我表示歉意。正如你可能猜测的那样，关于操作系统哲学的书面资料很难找到。我只能希望以某种方式捕捉到了设计者目标的核心。不过，对我们的目的而言，整体的设计方法论中那种总体脉络比绝对的准确性更为重要。在这方面，以下的讨论应该能为我们服务得很好。
