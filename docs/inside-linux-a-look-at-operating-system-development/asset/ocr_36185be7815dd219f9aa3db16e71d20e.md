This operation was called a code freeze and resulted in version 0.99pl15, which held steady long enough for bug fixes, but no enhancements, to arrive.

Part of the code freeze and the great release was the recognition that Linux had become a suitable foundation for production systems— systems devoted to doing useful work instead of being the direct object of a programmer’s interest. This posed a dilemma: how could Linux continue to evolve and yet be stable? The solution was simple: have two development paths starting from the same point. The even numbered releases (1.0.0, 1.0.1, etc.) followed a slow, careful evolution of a production system and the odd numbered releases (1.1.0, 1.1.1, 1.1.2, etc.) were to be fast-changing, development systems. Version 0.99pl15, with a few fixes, was the basis of these two systems. Some important fixes moved 1.0.0 to 1.0.8 in the early months of 1994, but the production versions saw only a few more changes during the rest of the year. By contrast, the development system underwent over ninety-five changes in a year.

In early 1995 a second major release occurred. Again, the stable and well-tested features of the development versions (up past 1.1.95) have been incorporated in production releases, which are not expected to exceed 1.2.14. Its twin, the development version, is the basis of yet more development work and has undergone over sixty changes in a year.

One thing that also happened with the first great release was that the release itself no longer held a catalog of its changes.
