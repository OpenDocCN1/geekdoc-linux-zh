**Hierarchy—A Non-Flat File System** The systems described so far have only a single directory. The next level of enhancement is to build a hierarchical file system. This means that there are multiple directories, where a directory contains both ordinary files and subordinate directories.

**Access Control—Ownership and Permissions** Somewhere along the way, the idea of ownership of files appears. Some systems strictly limit file access to the owner, but others have added the idea that file access of another user’s files can be controlled by some permission mechanism.

**Structure—File Types** Some systems find utility in having files identified by type. This typing permits the system to manipulate different files in different ways. For instance, although Unix has only one kind of file which can hold data, other file-like entities exist. Besides ordinary files, directories, character devices, block devices, named pipes, and symbolic links exist in most Unix systems.
