It is slightly more subtle than that. A file is created with a link count of two — one count for the directory entry pointing to it and the second count to remember the file is currently open. The counter is incremented each time it is linked to a new directory entry. The counter is also incremented each time the file is opened and decremented each time the file is closed. This ensures a file will not be deleted while it is accessible to a running program. This also means a file can have a legitimate existence without a directory entry pointing to it. Such a file will disappear when the last program closes its access to the file. (Files are automatically closed when a process terminates, even if it doesn't do so explicitly.)

In the past decade, almost all Unix and Unix-like implementations have come to support long file names in their file systems. In the earliest versions of Unix, the directory entries had a fixed size of 16 bytes, such as shown in Figure 5.17, permitting a two byte mode (i#) and file-names of up to 14 characters.
