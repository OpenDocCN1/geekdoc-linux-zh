Other systems with comparable features use much more memory or run slower than Linux.

Linux offers high performance in another sense: it has been ported to some of the fastest microcomputers on the market and it has been ported to symmetrical multiprocessor systems.

# ### 1.2.4 Linux Has Multitasking

Multitasking implies concurrent execution of peer programs. Each process is (potentially) entitled to the full resources of the system. Each process can be greedy in allocating resources—the system will mediate among the processes. Processes are created as children of parent processes. The new process acquires the privileges and has the same ownership as the parent process.

Process scheduling is based on priority, history, resources, etc. Lower priority processes execute less than higher priority processes, and the priority of a process changes over time to meet scheduling goals as discussed in Section 5.2.4. (Internally the most important (greatest priority) process has the lowest value for its priority, but some utilities and system calls try to correct this so that more important processes have higher valued priorities. This is a trap in any discussion of Unix system priorities.)

System calls are implemented as an extension of a user process and the code isn't interrupted within the kernel. Because system calls are generally of short duration, this is usually no hardship. In the cases where the process must block, task switches do occur inside the kernel. This general design is common to almost all Unix kernels.

# ### 1.2.5 Linux Is Multi-user

Linux permits multiple users simultaneous access to the system such that each user is protected from accidents and malicious acts of other users. Each user can have a personalized environment, and resource use can be monitored and limited. Users can share programs and data and their programs can communicate with other user's programs.
