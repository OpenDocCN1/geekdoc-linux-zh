Most of the performance comes from the integration of internal buffering with the actual network file system.

The file naming mechanism is just a generalization of the local file system.  File systems which are exported from a remote system are mounted as if they are local disk partitions.

One common use is for a file server to hold all user home directories and to export them to all client systems where they are mounted as “home”.  In this way the location is transparent to all users and all user home directories have the same name regardless of the system from which they are accessed.

The design of NFS prompted a significant change in most kernels.  Whereas before the file system and the kernel were very tightly coupled, the introduction of NFS prompted the creation of a virtual file system layer which redirected file manipulation system calls to the local file system code or the network file system code.  (This was discussed in Section 5.3.2.)

# 5.3.5  Peripheral Access

Linux permits peripherals to be accessed as devices named in the file system.  For instance, when the open system call is applied to /dev/tty0, /dev/lp, /dev/mouse, and /dev/ttyS0, the user gets direct access to the first virtual console, the printer, the mouse and the first serial line, respectively.  The user can then use read and write for input and output, and the special system call ioctl is used for special operations.

Non-portable (and privileged) code can access some devices by way of reading and writing device registers through the I/O port or memory windows.  While it may provide higher performance, such practices are discouraged.
