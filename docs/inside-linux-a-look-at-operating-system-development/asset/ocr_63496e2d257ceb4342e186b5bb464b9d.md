Implicit in most uses of the term co-routine is the idea these programs would work on some common problem by exchanging data. This combined concept is now well known by the name *producer–consumer*, whereby one program produces data to be placed in a buffer and another program consumes the data from the buffer.

# Preemptive Multitasking

A batch of jobs, where it doesn’t matter if one job or another is delayed for a bit, are perfect candidates for co-operative multitasking. But if the jobs are expected to offer any interactive response, the system will have to switch from one job to the next, even when the jobs don’t request the switch. This *preemptive multitasking* allows each user’s program to run either until it waits for some I/O to complete or until a “time quantum” expires.
