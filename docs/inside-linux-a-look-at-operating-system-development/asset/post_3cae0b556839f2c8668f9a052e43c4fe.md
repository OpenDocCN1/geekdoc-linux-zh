
## 0.2 STYLE AND STRUCTURE

The terms “multiprogramming” and “multitasking” are basically synonymous and refer to concurrent execution of multiple programs. I use “multitasking” throughout. (If you’re interested, “multiprocessing” refers to the use of multiple processors.)

I use “thread” as shorthand for a thread of execution subordinate to a process. It shares much of its state with sibling threads.

Careful use of the term “function” limits its use to a subroutine which returns a value and has no side-effects. Rather than be corrupted by the Unix convention of calling all subroutines functions, I’ve taken the opposite (and more correct) tack of calling all functions subroutines.

The term “operating system” has two meanings—one which refers to the innermost code, i.e., that which directly manipulates the special control of the processor, and the other, much larger product, which includes ancillary programs. I’ve tried to use only kernel or system kernel for the former and have reserved operating system exclusively for the latter. “Linux” is used to refer to both the kernel and the larger product—you’ll have to pay attention to the way in which it is used.

### 0.2.3 Names

Although the proper form is “UNIX”, I’ve followed the convention adopted by Peter H. Salus (and justified by comments by McIlroy) of using the form “Unix”[44]. This should be regarded as a typesetting convention only. It is not meant to identify a different product. Litigious types should apply the necessary conversion, others can enjoy the more pleasant appearance. Some authors have coyly substituted the struct $^\mathrm{UNIX}\times$ to name Unix-like things which don’t necessarily have full recognition by the trademark owners. I use the term “Unix-like” in the few cases it is strictly necessary.

It remains to be decided if Linux is to be regarded as Unix or Unix-like. At least one distributor/developer of Linux, WorkGroup Solutions², has joined X/Open³, the current owner of the Unix trademark. Presumably they will qualify a version of Linux for branding as “Unix”. If that instance of Linux can be referred to as Unix, it’s hard to say the qualification would not extend to other instances of Linux.

### Why you need Linux

Until recently, Linux has been regarded as a hobbyist's system. It started out as a project by a student, Linus Torvalds, to see how the memory management hardware of the Intel 386 really worked. That is, Linus wanted to identify what detailed steps were required to build a practical virtual memory system with that hardware. Since he shared his code on the Internet, there was opportunity for others to make their own contributions to the system. This development process has now been in operation for over five years. Appendix D provides a timeline of the development of Linux.

Although Linux clearly started out as a student project, it is now regarded as an appropriate foundation for many commercial products. Linux has become the operating system of choice for hundreds of thousands of users worldwide¹.

Over the past decade we have seen the establishment of three categories of computer systems: the large scale systems supporting large commercial, engineering or scientific operations; the workstation supporting a single engineer or business worker; and the personal computer used at home. The large scale systems run expensive operating systems requiring a support staff for system management. The workstations run some flavor of Unix and are administered by a small staff or an experienced user. One might suggest the personal computer is run without management—at the whim and abilities of the individual.

The boundary between these categories is changing due to encroachment from below. The mini-computers and micro-computers have always held a price/performance advantage, but now that their absolute performance has grown, they are able to replace many traditionally larger and more expensive systems.

Many large Unix systems are being replaced by high-end siblings of the Unix workstation and workstations are being replaced by high-end personal computers. This change has been characterized as the “attack of the killer micros”.

These changes have fogged the boundary and one should not dismiss Apple and Microsoft systems as toys, nor should one assume Unix is only for workstations. No other operating system covers a wider performance spectrum. A Unix-like interface is available for the most powerful supercomputers and $1500 lap-top computers.

Unlike the proprietary systems such as Apple Macintosh, MS-DOS and Windows 95, there is nobody to count licensed users of Linux because Linux requires no license to operate. It is largely covered by the GNU Public License (GPL), shown in Appendix F, which includes the idea that once you've got a copy, you can pass it on. Therefore, we can only estimate the number of Linux systems in operation. You are encouraged to register$^{2}$ your system(2).

Because Linux is a complete operating system, it is an object worthy of study as a part of learning how operating systems work.
