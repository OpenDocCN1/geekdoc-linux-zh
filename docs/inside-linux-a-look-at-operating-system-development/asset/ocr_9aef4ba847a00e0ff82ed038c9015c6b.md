The ROM has several primitive device drivers and a small control program which will attempt to load a larger bootstrap program from one of a list of peripherals. The configuration information can control the choice and sequence of peripherals.

The bootstrap program in ROM can be quite large. But because it is installed when the system is constructed and because it has to be general purpose in utility, it can do little to directly load the large system kernel.

That step is left to the program in the “boot blocks” of the disk storage.

# BIOS

The Basic Input/Output System (BIOS) of the IBM PC compatible machines provides the bootstrap code outlined above. One interesting aspect of this design is that some of the device drivers are not part of the ROM on the main printed circuit card (motherboard), but rather they are in ROM on various peripheral interface cards. The main code on the motherboard “discovers” this additional code and incorporates it into its basic operations. In this way, unusual programming requirements of new disk drives are hidden from the standard BIOS code.

# 5.7.3 LILo or DOS & LOADLIN

Each system design has a convention for the size and location of the boot blocks. Typically, the bootstrap code in the ROM will load primary bootstrap code from the first few sectors of a disk to some low memory location. Control is transferred to that code, but because the primary bootstrap is small (often 1 Kbyte or less), it usually loads additional (secondary) bootstrap code from disk. The secondary bootstrap is then used to load the kernel.

The code in the Linux loader (LILo) closely follows this model, with the variation that the secondary bootstrap can be used to load one of several kernel images[2].
