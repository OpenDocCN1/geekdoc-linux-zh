Linux is undergoing rapid change. New kernel versions are distributed about once a week. Some of the changes are due to fixes, but most are new features or improvements. ## 1.2 Features

Linux has a multitude of attractive features. A detailed examination of all of them would fill this book, but the following sections give a brief overview. In some cases, the section will also explain *why* some feature is useful. (This explanation is necessary because some of these features may be foreign to the reader's experience.)

### 1.2.1 Linux Is Free

Some software is expensive. Developers have found that they can profit by selling a small number of licenses at a high price. Other developers have discovered that they can profit by selling a very large number of licenses at modest price. Some have gone so far as to cut marketing and distribution cost to nothing and distribute their product free, asking that the users voluntarily send license fees directly to the developer.

The Free Software Foundation$^{3}$ noted that software redistribution was limited by licenses. It also noted that all of the traditional licensing methods have one thing in common: the source is rarely available to the end user. In response, they developed the GNU Public License (GPL) which says in part:

> You may copy and distribute verbatim copies of the Program's source code as you receive it, in any medium, provided that you conspicuously and appropriately publish on each copy an appropriate copyright notice and disclaimer of warranty; keep intact all the notices that refer to this License and to the absence of any warranty; and give any other recipients of the Program a copy of this License along with the Program.

This ensures that access to the source does not become restricted. It also says:

> You may copy and distribute the Program ...in object code or executable form ...provided that you also...Accompany it with the complete corresponding machine-readable source code.... [or offer to make a copy upon demand].

This ensures that the source must be made available with the object or executable.

Linux is bound by this free-to-copy policy and, as a result, Linux distributions are readily available on the Internet at no cost to the user. The same license allows commercial distribution of the system on CD-ROMs. Since the system is freely available, the CD-ROMs are priced to include only modest profits and thus they include more software for less money than any other software in the world.

### 1.2.2 Linux Is Robust

Linux was not developed using formal methods or many of the modern software engineering techniques. It does, however, exploit one well-known method for building better software: code review.

This code review is unlike that usually found in commercial software development environments. The recommended practice is for the author to meet with several reviewers - all of whom have studied the program before the meeting. The review is conducted by someone other than the author in a non-confrontational setting - where the goal is to identify flaws or misunderstandings.

The Linux model cannot support meetings because the members of the development team are spread across many continents. Even if they lived in the same town, they'd be subject to the schedules of their job, family, etc. Therefore, they rely on a well understood process of releasing code at various levels of confidence to an ever-growing user community on the Internet.

This user community subjects the code to study and test according to the user expectations and, on rare occasion, the specifications. Since the entire program, in its source form, is exposed to the world, there is a rush to find and fix flaws that is rare in commercial software development settings.

As a bonus, or perhaps as a side-effect, there is a certain amount of self-selection among the programmers. No one is directed to “design and code” something outside of their experience. Instead, changes are made because the contributor has some expertise to share.

Finally, releases are not subject to external synchronization. Instead, they are made as soon as fixes or enhancements are completed. Thus Linux is *robust* but constantly changing.

Some people are scared by a constantly changing system. They’d rather have a system with well known flaws and well known work-arounds. The danger with this approach is that on flag-day, when a major new release is finally installed, a large number of surprises ambush the users. For this reason, some users stick with years-old system releases. With Linux the changes are modest from one release to another. A cautious user can follow the crowd at a distance, upgrading to new versions at a modest rate, and have the assurance that no problems lie in ambush.

This process of following the leaders is encapsulated in the dual track for releases. Section 9.1 describes this process in greater detail.

### 1.2.3 Linux Offers High Performance

The best performance is achieved when the application is executed with no system kernel overhead. Certainly this holds for what are called “embedded systems”, where the system’s function is limited and rigidly defined.

Unfortunately this doesn’t apply when the system is intended to be general purpose. In that case, there’s always some overhead—the trick is to keep it small.

Linux does a good job at that because there is constant pressure (and continual changes) to reduce the overhead of Linux system calls.

Other systems with comparable features use much more memory or run slower than Linux.

Linux offers high performance in another sense: it has been ported to some of the fastest microcomputers on the market and it has been ported to symmetrical multiprocessor systems.

### 1.2.4 Linux Has Multitasking

Multitasking implies concurrent execution of peer programs. Each process is (potentially) entitled to the full resources of the system. Each process can be greedy in allocating resources—the system will mediate among the processes. Processes are created as children of parent processes. The new process acquires the privileges and has the same ownership as the parent process.

Process scheduling is based on priority, history, resources, etc. Lower priority processes execute less than higher priority processes, and the priority of a process changes over time to meet scheduling goals as discussed in Section 5.2.4. (Internally the most important (greatest priority) process has the lowest value for its priority, but some utilities and system calls try to correct this so that more important processes have higher valued priorities. This is a trap in any discussion of Unix system priorities.)

System calls are implemented as an extension of a user process and the code isn't interrupted within the kernel. Because system calls are generally of short duration, this is usually no hardship. In the cases where the process must block, task switches do occur inside the kernel. This general design is common to almost all Unix kernels.

### 1.2.5 Linux Is Multi-user

Linux permits multiple users simultaneous access to the system such that each user is protected from accidents and malicious acts of other users. Each user can have a personalized environment, and resource use can be monitored and limited. Users can share programs and data and their programs can communicate with other user's programs.

Most other personal computer operating systems do not have this feature. This was claimed to be unnecessary because the computers were “personal”. When we consider a family sharing a computer at home or colleagues sharing a computer at the office, we see this claim was ill-founded.

### 1.2.6 Linux Has Networking

Linux best shows its Unix heritage in its networking ability. All the common utilities such as `telnet`, `ftp`, NFS, `rlogin` (remote login), `rsh` (remote shell), and the X Window System are fully supported by code derived from code released by the University of California—Berkeley and MIT.

In addition to these traditional utilities, other programs such as World Wide Web browsers and multi-user games have been ported to Linux.

A number of physical device drivers have been added so that Linux can communicate via dial-up modem, leased line, Ethernet, parallel port, and ISDN.

### 1.2.7 Linux Uses Virtual Memory

Another great advantage of Linux is that it offers a simple memory model to the user programs—it has a uniform address space of $2^{32}$ bytes which can be addressed by a 32 bit pointer ${}^{4}$. Anyone who has programmed recent x86 hardware knows there are several memory models to choose from. Most commercially produced operating systems use a restrictive model, compatible with the oldest x86 processors, which requires segment registers to be changed in co-ordination with a pointer register. When Linux is used on an Intel based system, it demands a 386 or later processor and, as a consequence, it can offer a simple memory model which doesn’t require two registers to be manipulated when accessing all the memory on the computer.
