An essential element remains: the processors are highly interdependent, but their presence may not be obvious to the user. Leslie Lamport is credited for the observation that “A distributed system is one in which the failure of a computer you didn’t even know existed can render your own computer unusable.”

Linux takes a middle of the road position. It is a single computer system with network support. Each system can run stand-alone, but all systems can co-operate on the network.

### 1.3.3 Linux Is Not Secure

This deliberately scary heading exaggerates the case. This heading refers to systems which are claimed to be secure against malicious attacks because they fully close a lot of paths which are useful when those paths are slightly open. The “Oracle book” describes the steps one must take to qualify a system as secure[13]. Linux is not nearly any worse than other common systems—few systems are secure in a formal sense—and you wouldn’t like using those which are.

For example, some levels of secure systems prevent a user from learning the names of the other users on the system. An even more extreme case involves what are called “covert channels”, tricks which permit programs to pass classified data by non-obvious methods to other programs in violation of security ratings. Since these methods can involve one process watching another process’ memory map or even the rate of spawning child processes, a process’ state is entirely hidden from other processes. These limitations are anathema to much of how Unix and Linux were developed.

In spite of this warning about security, we are seeing constant improvements in Linux security. Unintended and undesirable security gaps are being regularly closed. Just don’t expect the Department of Defense, Ministry of Defense, Department of War (pick your country) to use Linux for keeping secrets.

### 1.3.4 Linux Was Not Formally Designed

This will never happen with Linux. Systems such as FSF’s HURD and CMU’s MACH have spawned a number of publications$^{14}$, $^{15}$, some of which pre-date the concept being implemented.

What we will see is improving documentation for the kernel and for the system. Contrary to popular belief, there are programmers who can write intelligible prose. The Linux Documentation Project (LDP)$^{16}$ is an effort to collect (1) Unix-style man pages, (2) modest tutorials, and (3) books such as the Linux Network Administrator’s Guide[27] and the Kernel Hacker’s Guide[25]. These documents are typically included in CD-ROM distributions of Linux.

While it might have been better to design first and then implement, we can be thankful for this effort to document what has been implemented.

### 1.3.5 Linux Isn’t Built Using a Modern Programming Language

Linux is written almost entirely in C. (There are small fragments written in assembly language.)

C has been characterized as both the world’s lowest high-level language and the world’s highest low-level language. This dual regard places it in a good position as a system implementation language. It also means that C is obliged to set aside some elegant idioms, such as abstract objects and multi-threading, for the sake of utility.

If C wasn’t so popular, it would be regarded as a bad language. It has a number of questionable features, such as a cavalier approach towards functions and types, which have been firmly fixed in tradition.

Several other programming languages were developed about the same time C came into being. Eiffel is one highly regarded example of a modern programming language. The contrast is informative:

- C
    - scoping has three levels: global, local to module, or local to subroutine
    - strong typing, with type casts
    - unions used to change types
    - bits in storage are accessible
    - function return values can be ignored
    - I/O is separately defined as a part of a support library

- Eiffel
    - has classes and multiple inheritance (to support object oriented programming)
    - has packages (to hold related program elements)
    - has a number of predefined classes (comparable to C's run time libraries)
    - has fewer syntactic hiccoughs (such as the dangling "else" problem)

A number of good ideas have leaked into C from other languages. The latest C language specification includes mechanisms to better support separate compilation as well as more complete specification of standard run-time support for the language.

Some of these changes are in the implementation, not the language specification. For instance, type checking is more rigorous and warnings are more readily emitted by the compilers.

System kernels are now seen as a collection of nearly independent modules working in co-operation. Functions in these modules operate on rather complex structures, but the details can be safely hidden from the caller. This has lead to the suggestion that Linux should be rewritten in a language such as C++ which supports concepts such as abstract data types, object oriented programming, separate compilation, etc.

Linux may not offer everything you want or need. The Linux Project Map (LPM)$^{17}$ lists a large number of projects to enhance the Linux kernel or user environment. Some of the more significant ones are listed below. The Linux Software Map (LSM)$^{18}$ is a standardized form for reporting software projects which have been completed (or are at least available for testing). This permits everyone to co-ordinate development and to track the status of desired software.

## 1.4 TEMPORARY SHORTCOMINGS

### 1.4.1 Linux Only Runs On …

On August 25, 1991, Linus Torvalds posted a note to the comp.os.minix newsgroup in which he said:

I'm doing a (free) operating system (just a hobby, won't be big and professional like gnu) for 386(486) AT clones. … It is NOT protable [sic] (uses 386 task switching etc), and it probably never will support anything other than AT-harddisks, as that's all I have …

On July 31, 1992, Linus posted a note to the mailing list Linux-Activists@BLOOM-PICAYUNE.MIT.EDU in which he noted:

… linux has in fact gotten more portable with newer versions: there was a lot more assemby in the early versions. Not that anybody in their right mind would try to port it even now.

That may have been the challenge that started the first effort to port Linux to a different architecture.

Linux has now been ported to a number of other architectures including Motorola 68040$^{19}$ (specifically the Amiga$^{20}$), Atari$^{21}$, and VME$^{22}$), DEC Alpha$^{23}$, MIPS$^{24}$, PowerPC$^{25}$, and SPARC$^{26}$.

Other efforts are in progress, but have not yet provided results.

### 1.4.2 Linux Doesn't Run MS-DOS Programs

Although Linux does not offer a complete virtual machine system, there is a package called **dosemu** which emulates enough of the x86 hardware that MS-DOS can be run inside a Linux process. The package is designed so that neither MS-DOS nor all its applications programs can tell they are not running on the base hardware.

At the time of this writing, **dosemu** has provided a sufficiently complete emulation to boot Microsoft Windows 3.1.

Sections 4.3.2 and 5.2.5 discuss the operation of a virtual machine.

### 1.4.3 Linux Doesn't Do Windows

Microsoft Windows is another operating system for Intel x86 hardware. (Actually, it’s an extension to MS-DOS, but we won’t quibble.) Programs written for this system cannot be directly executed on a Linux system. The WINE$^{27}$ project will overcome this limitation. The Wine FAQ (Frequently Asked Questions and answers) says Wine stands for “**W**indows Emulator, or **W**ine Is Not an Emulator. Both are right. Use whichever one you like best.” Wine provides a program loader and execution environment that includes an emulation library. All the system calls are converted to the appropriate Linux/X Window System calls.

The current condition of this project is “90% done, with the other 10% expected to take another 90% of the time.” Many third party programs run under Wine, but it appears that programs from Microsoft exploit undocumented or ill-documented calls to the system. Once these calls are understood, support for them can be added.

The X Window System is a powerful graphical user interface included in all Linux distributions.
