The SYMBOLS table contains a list of names, each with its type, value, and other information, describing entry points, global variables, etc. Entries referring to specific locations in the TEXT, DATA and BSS areas are called definitions. Other entries, called external references, refer to locations which are not defined within, but must be elsewhere defined. The initial purpose of the symbol table has been extended, through the use of new types, to support debugging information. These references and definitions are indicated by the dashed lines in Figure 7.2.

Addresses in both the TEXT and DATA areas are relative to the base of those areas. Relocation information, which is held in the final two parts of the object file, describes all the addresses in a way which allows a linker to modify the text and data when the areas are shifted to a non-zero base address. This relationship is shown by the dotted lines in Figure 7.2. An executable a.out file can be stripped of all but the HEADER, TEXT, and DATA areas. This makes the file smaller, but it prevents debugging.

The object files have the same format as the executable file, except some of the symbols describe unresolved external references. The linker is used to combine two or more object files into one executable file as shown in Figure 7.3. The text and data areas are concatenated and the relocation information used to adjust addresses. Symbol tables are merged, as are relocation tables, and a consolidated header is formed; external references are resolved as matching definitions are found.
