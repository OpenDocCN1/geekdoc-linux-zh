# 5.2.4 Scheduling

Throughout the operation of a multitasking system, decisions are being made on several levels regarding what processes should be executing. We can easily identify three levels, short term, medium term, and long term, and discuss each separately.

# Short Term

Processes shift between three major states: running, ready, and blocked. Blocked tasks lack access to resources such as memory, disk data, access to a peripheral, etc. They will continue when that resource becomes available. Ready tasks lack only a processor on which to execute. The system will select them to become the running process. Running tasks are actually executing — on most architectures only one per system is allowed. They will wait for some resource, they will relinquish control, or they are preempted by the system.

Processes change state as a result of actions by the running process or an ISR. In a co-operative multitasking system the running process continues until either

+   - it blocks because it must wait for a resource or
+   - it voluntarily relinquishes control of the system.

These actions may be hidden from the application programmer deep within the run-time library; but to the system kernel it's all the same. The important characteristic of co-operative multitasking is that a context switch does not occur except at the direction of the running process.
