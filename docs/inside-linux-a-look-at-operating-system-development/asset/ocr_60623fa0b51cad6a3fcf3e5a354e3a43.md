What we will see is improving documentation for the kernel and for the system. Contrary to popular belief, there are programmers who can write intelligible prose. The Linux Documentation Project (LDP)$^{16}$ is an effort to collect (1) Unix-style man pages, (2) modest tutorials, and (3) books such as the Linux Network Administrator’s Guide[27] and the Kernel Hacker’s Guide[25]. These documents are typically included in CD-ROM distributions of Linux.

While it might have been better to design first and then implement, we can be thankful for this effort to document what has been implemented.

# **1.3.5 Linux Isn’t Built Using a Modern Programming Language**

Linux is written almost entirely in C. (There are small fragments written in assembly language.)

C has been characterized as both the world’s lowest high-level language and the world’s highest low-level language. This dual regard places it in a good position as a system implementation language. It also means that C is obliged to set aside some elegant idioms, such as abstract objects and multi-threading, for the sake of utility.

If C wasn’t so popular, it would be regarded as a bad language. It has a number of questionable features, such as a cavalier approach towards functions and types, which have been firmly fixed in tradition.
