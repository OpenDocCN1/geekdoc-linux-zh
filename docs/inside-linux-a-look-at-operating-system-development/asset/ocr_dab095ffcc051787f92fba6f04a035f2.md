# 5.3.2 File System Implementation

Linux differs from early Unix implementations in that it has fewer hard limits and fixed tables in the kernel. For instance, the maximum number of open files in the system is set at the start, but only as a variable which could be later changed. Likewise, the mount points are held in a linked list of dynamically allocated structures. Along this vein, the number of files which a process can have open is set by a parameter which is part of the file system. (This is the POSIX behavior.)

All this means it's a bit more difficult to point to a declaration in the kernel and say “That is where all the details are stored.” But there are a few fixed points. In the case of I/O, there are two tables in `nux/fs/devices.c`, `chrdevs` and `blkdevs`, which hold details of operations supported by each of the devices in the system.

# Run-Time Library I/O Support

It should be mentioned in passing that the run-time library provides a layer on top of the basic file operations. Some of the most important functions in this library, such as `printf` and `scanf`, provide buffering and formatted I/O. The basic calls, such as the `read` and `write` discussed below, side-step this formatting and buffering.
