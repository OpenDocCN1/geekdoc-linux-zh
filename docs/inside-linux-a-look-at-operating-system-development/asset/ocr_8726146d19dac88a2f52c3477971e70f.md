When the TCP protocol is used within the IP wrapper, the user is offered a reliable end-to-end process-to-process link². The datagram shown in Figure 6.3 contains:

+   • 16-bit source and destination port numbers which identify the ends of the link. Processes at either end **bind** themselves to a port (an agreed-upon numeric identifier) and then either **connect** to a distant process or **listen** for a connect request. These port numbers are defined as part of RFC 1700 and are held locally in `/etc/services`.

> ²This means the processes have guaranteed uncorrupted delivery. IP takes care of the routing and delivery, and TCP takes care of the error detection and correction.
