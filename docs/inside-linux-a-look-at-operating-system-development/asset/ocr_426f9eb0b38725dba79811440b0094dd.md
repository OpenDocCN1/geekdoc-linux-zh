The processor will treat a reference to page **G** in process 2 in Figure 4.19 as a *page fault*. The processor stops that process until that page can be mapped to a frame of memory (by loading it from disk). After the system updates the page table, it will let that process resume execution.

The system uses the modify bit and the reference bits to decide what frames should be written to disk and what frames should stay resident.

Additional bits can be used to control access to a page. For instance, a "read-only" bit could be used to mark code pages which are being shared.

If there is no page image in special storage, the system may abort the user process or it may create a zero filled page. The latter is common when more stack or dynamic data memory is needed.

# ## 4.5 Security

Any multi-user system (and any cautious single user system) has mechanisms to limit what processes can do. These mechanisms must protect against

+   unwanted access of data

+   unwanted destruction of data

+   denial of service

+   system corruption

+   circumvention of accounting,

One should realize that the above problems can occur because of errors as easily as malicious acts. Thus, these issues are properly the domain of all systems, not just networked or multi-user systems.
