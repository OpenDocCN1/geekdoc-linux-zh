# 1.4.8 Linux Is Becoming Bloated

The original Unix kernel was under strong size limitations. The PDP- 11 hardware offered only a 64 Kbyte virtual address space, of which 8 Kbytes referred to device registers. As a consequence, the kernel could not expand without limits to offer new features. When Unix was ported to the DEC VAX and other architectures, this constraint was removed and Unix quickly grew much larger. Fortunately, the fundamentally simple design was not lost.

The Linux kernel has undergone a similar metamorphosis. Because it was the creation of one individual, it was based on a simple, consistent design. It has been rapidly expanding as new features are added. These features have caused the kernel to suffer a 2:1 expansion in the past three years. The kernel modules mentioned in Section 1.3.1 offer a partial solution to this problem in that only those features which are desired are loaded into memory.

In his classic analysis of large software development projects, *The Mythical Man Month*, Fred Brooks noted what he called the *second system effect*. This occurs when the designers pile features into their second system—features which they wisely left out of the first system because of concerns about size or their ability to implement them. Only experience with building a second system teaches the proper balance between what is needed and what is wanted or can be provided

Brooks’ book has been reprinted with additional comments on the past twenty years, in which he names a related phenomenon, *featu- ritis*[7]. He notes that unless the system designers have a firm sense of the user community, new features will be added without limit.

Linux is suffering from *featuritis*, but because of its open and dy- namic nature, truly bad features are purged. Furthermore, users can put experimental features into the system without relying on a “feature czar” deciding what is important. If an experimental feature proves useful, it will migrate to the kernel as a loadable module or as a compile-time selection for the kernel.
