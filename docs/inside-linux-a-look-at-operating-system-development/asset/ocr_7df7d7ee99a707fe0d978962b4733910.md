(The ISR is also called the *interrupt handler*.) The end of the ISR contains a special interrupt return instruction that transfers control back to the interrupted program. If the ISR is written correctly, the interrupted program cannot tell it had been interrupted.

# **Linux's ISR implementation** In brief form, Linux takes the following steps to honor an IRQ:

+   - an interrupt request is posted
+   - when priorities permit, processor honors IRQ
+   - control passes through vector table to the ISR
+   - the ISR performs necessary tasks
+   - the return from the ISR may check for scheduling requests

There are actually two types of interrupt service: fast and normal. When a device is first initialized, the driver calls the **request_irq** kernel subroutine. This subroutine sets the actual interrupt vector, a look-up table used by the hardware, to point to either **do_IRQ** or **do_fast_IRQ**. **request_irq** also modifies the **irq_action** table to point to the device's second level interrupt service routine. When an interrupt occurs, **do_IRQ** or **do_fast_IRQ** will perform some housekeeping and then call the device's ISR.
