There is sufficient redundancy in the file system that common fail-ures can be discovered by examining a file system before it is mount-ed. For instance, the inodes can be examined to build trial copies of the bitmaps and discrepancies with the bitmaps on disk indicate some failure. Similar checks will discover duplicate references to data blocks, cycles in the directory structure, and inodes which have been allocated but are not linked to the directory structure.

The Berkeley Fast File System offered a number of significant im-provements to state-of-the-art in Unix file system implementations. One of the major new features was that it split the partition into several chunks called block groups, each with an almost file system-like struc-ture. Each block group held a copy of the superblock and a share of the data blocks, inode table entries, and the associated bitmaps.

This meant that not only could a file's data blocks be clustered in a neighborhood, but its inode and bitmaps could be in the same part of the disk. This change allows the kernel to further exploit the nature of references to file system data, called locality of reference, whereby references which are close in time tend to be close in location.

The ext2 file system follows the Berkeley Fast File System model for block groups.
