# **Memory implementation** The Sequent Balance and Symmetry

systems provide a bank of semaphore memory which aid processors without atomic read-modify-write instructions. When the processors read from these special locations, a test-and-set operation is performed *in the memory* and the appropriate value is returned. The process which *acquired* the semaphore must later write to that location to release the semaphore.

The Tera MTA provides a semaphore per word of memory called the “*empty*/*full*” bit. The system has the usual *load* and *store* instructions. It also has *load_if_full* and *then mark empty* and *store_if_empty* and *mark full*. These special instructions effectively perform a busy-wait if the memory word’s semaphore is in the wrong state.

# **Software implementations** Not all systems provide such con-

venient support for semaphore implementations. In those cases, the pro-grammer must rely on software implementations of semaphores which require only shared memory.

One example is Dekker’s algorithm, but this algorithm was improved by Peterson and others to operate in an environment with two or more *competing* processes and to operate without busy-waiting[11, 38]. The basic form of most of these are:

+   1. place a claim for the semaphore and then

+   2. check for claims made by other processors.

If no other claims are found, the critical section may be entered. If there *are* other claims, additional steps must be performed to determine when the critical section is free.
