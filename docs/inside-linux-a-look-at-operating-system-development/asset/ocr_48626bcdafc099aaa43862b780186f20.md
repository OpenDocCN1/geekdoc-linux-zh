**Fast interrupt** services are used when the driver interrupt service routine is small enough. The driver initialization declares it wishes to use fast interrupt service. `do_fast_IRQ` saves the minimum necessary context of the interrupt program. It then calls the ISR with the IRQ number as an argument. When the ISR returns, the saved context is restored and the interrupt service completes with an `iret` command.

The line printer driver follows this model. The main part of the driver, `lp_write_interrupt`, attempts to write characters to the printer, but when it is blocked, it will call `interruptible_sleep_on`, which passes control to other processes. It will be awakened when the interrupt service routine signals that the printer is again ready to accept data.

The interrupt service routine is quite simple. Besides some necessary validation, its sole purpose is to wake up `lp_write_interrupt` which is stuck in the kernel trying to write data to the printer.

```c
static void
lp_interrupt(int irq, struct pt_regs *regs)
{
    struct lp_struct *lp = &lp_table[0];
    while (irq != lp->irq) {
        if (++lp >= &lp_table[LP_NO])
            return;
    }
    wake_up(&lp->lp_wait_q);
}

**Normal interrupt** service saves the entire context of the interrupted program. It then calls the ISR with the IRQ number and a pointer to the saved registers as arguments. The ISR responds to the interrupt by tending to some peripheral or processor condition and then returns through a part of the kernel code which first dispatches *bottom half* code and then reschedules processes if appropriate.
