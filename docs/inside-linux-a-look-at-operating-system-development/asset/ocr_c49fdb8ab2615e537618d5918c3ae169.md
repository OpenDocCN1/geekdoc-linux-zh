An experienced user is aware that the shells provide the elements of a full featured programming language.

In the following sections we'll explore the most common features of shell programming languages.

# ## How commands are processed

The shell interprets the input by first breaking it into distinct *tokens*—basically words and punctuation symbols—and then matching the tokens with patterns of the language definition (called its *syntax*).

Simple shells read lines, then expand file names, substitute variables, and note I/O redirection (as described below). The shell then interprets the first token as the command name and the rest of the tokens are passed as arguments to that command$^{2}$. A basic command such as **date** causes the system to search for an executable program with that name. It executes that command and then presents a new prompt.

A slightly more complex command includes arguments which are passed to the program. For instance, the command `echo ‘hello world'`, causes the string argument “hello world” to be passed to the echo program. The command then echos its arguments to the display.

Yet another enhancement permits the shell to redirect a command's output to a file. The command `echo ‘hello world' > tmp.file` will redirect the output to the file instead of the display.

More complex shells allow multiple commands to be joined on one line and one command to cross line boundaries. Tokens such as (“",“;”, “)”, “>”, “|”, and “$”) are used to group, separate, and modify commands. The shell then nibbles at the tokens, using (“" and “)") to group collections of commands and (“;”, “|”),etc. to separate commands.

For instance, the input line

```
(date; echo 'hello world') > tmp.file
```

> ² The exception is for some shells which recognize a command such as “EST=5” to be interpreted as an assignment of “5” to a variable “EST”. The “=” is the key to recognizing this exceptional case.
