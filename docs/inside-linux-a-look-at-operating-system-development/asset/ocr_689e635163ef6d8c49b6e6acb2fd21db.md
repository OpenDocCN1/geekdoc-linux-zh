which still says the output from **command1** is to be used as the input to **command2**, but an internal buffer, rather than a file, is to be used to convey the data. Furthermore, the two commands execute simultaneously.

It is worth noting that the implementation of pipes in MS-DOS doesn't support simultaneous execution. The first MS-DOS program runs to completion, writing to a hidden file; then the second program starts, using that hidden file for input. The only benefit is the more convenient notation.

Unix fully supports the idea that two programs can work in cooperation using a buffered communication path to carry output from one program to become input to another program. This is explored more fully in Section 3.1.1.

# **Binary infix notation**

When Unix was being initially designed, some initial discussions suggested commands themselves should be considered binary operators. For example, the command line

```
`inputfile sort paginate print`
```

would print a paginated sorted image of the input file. Since redirection was already an established Unix feature, this form was transformed to something like

```
`sort inputfile > paginate > print`
```

where the destination of a redirection was executed if it was a command or it was used as a destination if it was a file.

These experimental forms quickly moved to the use of a distinct character, “|”, which joined two programs such that the output of one program is to be the input of the next program.

```
`sort inputfile | paginate | print`
```
