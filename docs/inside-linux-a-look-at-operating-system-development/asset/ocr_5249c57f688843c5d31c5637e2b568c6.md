# ## 4.1.2 Priority Scheduling

A number of scheduling algorithms have been designed, most of which have some sense of process priority. This allows the system or user to designate a process as “really important” or “non-critical”. Section 5.2.4 explores this topic in more detail.

# ## 4.1.3 Real-Time Scheduling

Any formal definition of real-time scheduling will make note of a “strict requirement to meet deadlines”, but that’s really insufficient. Consider a payroll accounting system—everyone agrees it’s not real-time, but you better get those checks out on time! There appears to be an implicit, or at least rarely uttered, element to the definition: “deadlines are often less than a second in the future”.

Real-time scheduling comes in three flavors. *Hard real-time* systems, such as used in airplane flight control software, are designed so that no processes can inappropriately block another. Some of this can be done by strict (and fast) priority based scheduling, but it also often relies on strict bounds on process execution times.

Some systems go so far as to avoid the use of interrupts because unexpected delays of millisecond duration can occur. Instead, the system runs in a polling loop, calling each process as a co-routine (see Section 4.1.1) and each process must return within some fixed time. Some of these processes perform computations and others tend to peripheral I/O.

*Soft real-time* systems can tolerate modest delays. An example of such a system would be a “high-tech home” with window shades which respond to time-of-day, sunlight, and room temperature and a sprinkler system which relies on moisture sensors, clocks, and motion detectors (to avoid ruining the lawn party). If some operation is delayed by a second, perhaps as much as a minute, no harm is done.

Since a soft real-time system can work with context switching overhead, it’s possible to have lower priority processes doing non-real-time work. This means that these systems often have disk storage, network connections, interactive user command loaded processing, and (gasp) even *virtual* memory.
