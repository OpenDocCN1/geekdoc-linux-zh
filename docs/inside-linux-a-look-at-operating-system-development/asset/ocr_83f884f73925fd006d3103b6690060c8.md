The argument to each of these operations is the semaphore (from Greek words for sign (śema) and bearer (phorẽ̈̈us)) associated with the specific data being protected.

The idea is that when the first process enters its critical section, this semaphore value is reduced to zero. If a second process attempts to enter its critical section before the first process restores the semaphore value to 1, the second process will wait until the first process restores the semaphore value to 1.

There are two significant flaws with these definitions. The first is that both the P subroutine and the V subroutine themselves contain references to shared data (the value X). This means that P and V require P and V to operate --a recursive spiral from which the implementation must escape. The second is that the P operation uses a busy wait which doesn't relinquish control to another process.

Nevertheless, this was a remarkable contribution. It provided designers with a simple mechanism to ensure consistent results: implement P and V correctly and wrap critical sections with P and V.

Let us see how the two flaws can be addressed.
