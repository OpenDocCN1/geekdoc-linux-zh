The programmer no longer needs to recall what fields must be ini-
tialized upon allocation, how to locate some specific object, and what
procedures are to be used to deallocate an object. (The alert reader
will recognize that these characteristics are found in C++.)

Since such an abstract object has close control over the allocation
and initialization of data, there is an opportunity to create multiple sem-
aphores, one per shared data object. The next step is to automatically
insert P and V operations at the start and end of those subroutines
which manipulate shared data.

This automatic insertion was done in Modula-2, but has been de-
precated in Modula-3 because the granularity of such a method is too
large. The current design leaves it to the designer of the abstract object
to identify where semaphores should be placed.

# Deadlock

Whenever there are two or more processes, they can enter into a dead-
lock (or deadly embrace). When this happens, those processes are ef-
f ectively stopped, never to resume unless extraordinary action is taken.

# Necessary conditions

Deadlock occurs when four conditions are
met:

+   * *mutual exclusion*— there must be mutually exclusive access to re-
+   sources,
+   * *no preemption*— processes cannot be forced to relinquish resources,
+   * *hold and wait*— processes holding one resource try to acquire another,
+   and
+   * *circular wait*— there is a cycle of processes such that each is waiting for
+   one resource and another process wants the resource it is holding.

(Although *circular wait* presupposes *hold and wait*, they are listed sep-
arately because it eases later analysis.) Figure 5.13 shows the smallest
