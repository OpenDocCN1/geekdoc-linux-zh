# **2.1.5 System Kernel Written In a High Level Language**

This was a mixed blessing. It was widely held that programmer productivity was higher for high-level languages than for assembly languages (since verified by Jones[26] and others). The Multics project would gain tremendously by using PL/I instead of using an assembler.

However, PL/I is a *very* complex language. Since there was no PL/I compiler for the GE 635/645, one had to be written. Because of failures by sub-contractors, a real compiler wasn't ready until 1970, but a back-up plan produced a limited compiler in 1966.

It's worth noting that the early implementations of Unix systems were in assembly language. There was a B interpreter on the PDP-7, but a C compiler as we know it didn't appear until 1972—well after Unix had been implemented on the PDP-11. And it wasn't until 1973, with the addition of data structures, that it was possible to re-write Unix in C.

# **2.2 Unix**

In 1969, Bell Telephone Laboratories withdrew from the Multics project. A number of conjectures have been offered for this action, but it is clear that this large time-share system offered limited value to Bell Labs. The hardware was very expensive and the performance was very low.

Whatever the reason, a number of participants remained interested in creating a versatile operating system. Their informal discussions included the essentials: simple process creation, file system structure, user level command interpreter, and tasking model. These discussions led to small test programs which grew into bigger projects and finally into Unix.
