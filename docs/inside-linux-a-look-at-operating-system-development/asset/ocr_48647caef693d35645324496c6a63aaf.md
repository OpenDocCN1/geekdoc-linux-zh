# Combined methods and secondary methods

These methods can be combined to build more robust systems. There are also systems which use secondary methods of authentication, so called because one of the primary methods of authentication must be used to acquire them.

**Bank cards**  Bank cards combine what you have and what you know. Teller machines require the user to present a card and then provide a personal identification number (PIN). Neither of these alone is sufficient.

**Where you are**  Some systems permit privileged access only from a terminal in a secure area. Since primary methods of authentication are used to secure that area, access from that terminal is a secondary method of authentication.

In the case of many systems, physical possession of the hardware is regarded as authentication for the most privileged (root) account, or at least physical possession permits an intruder to override authentication systems. **Linux users beware! Your system can be compromised by anyone who has physical access to your system.**  At the very least, an intruder could reset the processor. A more sophisticated intruder could reboot the system in single user mode, add entries in the password file, reboot the system and enjoy the newly created accounts. These steps can be made more difficult by using an encrypted file system, such as mentioned on page 82, to deter the single user mode of operation mentioned above. It would also be possible to design bootstrap procedures which required passwords, but this hasn't yet been done.
