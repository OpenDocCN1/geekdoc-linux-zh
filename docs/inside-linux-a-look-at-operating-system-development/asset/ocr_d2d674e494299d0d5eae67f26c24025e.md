# Display manager

All these examples so far presuppose the user is already logged into the system. It's also possible to start the X server when the system is booted. In this case, the system behaves much like an X terminal.

A display manager is used to manage one or more X terminals (stand-alone X servers which offer no additional computing resources) or general X servers. It can be thought of as a super window manager which, instead of controlling windows on one server, ensures servers are running and a login window is present whenever the server is not being used.

# 3.2.6 Resources

X programs are customizable in a zillion (10$^{largenumber}$) different ways, which makes it difficult to remember and enter the options in any reliable manner.

As with most Linux programs, the X programs can use both command line options and the environment variables to modify their operation. Another mechanism, that of a resource list, provides more convenient operation.

While many of the X utilities scan configuration files to locate resource definitions, X has extended the idea of configuration files to a generalized database which may be consulted by all X programs.

Any X utility can use the database to locate the necessary properties by sending a query to the X server via library functions. The reply is a “best match” found in the database. (The xrdp program is used to load initial values to the X server. The editres and appres programs can be used to change or display the resources associated with a program.)
