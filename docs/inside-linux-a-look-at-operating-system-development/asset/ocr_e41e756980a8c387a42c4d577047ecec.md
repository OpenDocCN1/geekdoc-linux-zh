# Bitmaps

There are two distinct bitmaps: one for inodes and one for data blocks. Each bit is used to mark the use of an inode or data block. When the system needs an inode or disk block, it looks in this map instead of scanning a linked list of inodes or data blocks. The slightly more complex code is justified by the higher performance it offers.

Although file data are not necessarily located in adjacent data blocks, performance is significantly improved by placing all of a file's data in nearby data blocks. The data block bitmap is especially important because it allows the system to find such blocks with only modest effort.

# Superblocks

The superblock anchors the files in a disk partition. (Actually it locates the inodes, bitmaps and data blocks, but that's effectively the same thing.) Because of its critical nature, it is replicated several times within the partition.

The superblock holds several categories of data, including both information for installation and information used for the moment-to-moment operation of the file system.

Among the installation data, there is a sixteen bit field which holds a value which identifies a valid superblock. If it is not present, the superblock is rejected as invalid although sometimes a redundant copy of the superblock will be sufficient to recover the file system. Other fields are used to estimate the possibility that the file system could have been corrupted, e.g., if it was not tagged as having been shut down cleanly, or if it was last checked more than some interval ago, or if has been mounted more than some number of times without a check, the user is prompted to check the file system. There is also a revision level to ensure that the current kernel can properly manipulate this partition.
