# 2.2.2  Redirection

Redirection is a useful side-effect of the “Compatible file, device, and inter-process I/O” cited above. Since a program uses the same calls to write to a file, a terminal, or a printer, it is a simple matter to allow that output to be redirected without the knowledge of the program. At the shell (command interpreter) level, this is expressed by the notations **program** > *new destination file* and **program** < *new source file*. The program is unaware its input or output has been redirected.

# 2.2.3  Pipes

Pipes are a software construct used to direct data flow from one program to another.

Long before the invention of pipes, two programs could interact when the output of one was used as the input to the second. Commercial data processing was quite accustomed to this model, even when punch cards were the dominant form of storage. The operator just had to shift the cards from the output hopper to the input hopper.

But this early form of program interaction suffered two handicaps: the specification of this operation on the command line(s) is messy and one has to complete one program before the other can start. Typical data processing leads to the command sequence

```
```
command1 > temp_file
command2 < temp_file
```
```

where the output from **command1** is to be used as the input to **command2**.

A pipe permits the user to effectively combine these two command sequences into the one line

```
```
command1 | command2
