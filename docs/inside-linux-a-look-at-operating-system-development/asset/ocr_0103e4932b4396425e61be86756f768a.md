Preemptive multitasking differs in that an ISR can cause a process not only to shift from blocked to ready, but from ready to running as well! This means that the running process can be interrupted at almost any moment and it will be set aside (as a ready process) for some indeterminative interval. (Implementations may show a transition directly from blocked to running, but a two-stage transition from blocked to ready to running can be regarded as equivalent.)

The kernel keeps track of blocked tasks by placing them on queues, one queue for each different condition for which a process could wait. This is typically done within a device driver, where a call to select_wait, sleep_on, or interruptible_sleep_on causes the current process to be placed on a queue which built into that driver. At some later time, the driver will call wake_up to remove the process from that queue and move it to the ready process queue.

It's hard to catalog all the possible queues in the kernel, because there can be any number of them and there is no central registry of them. The address of each queue for which a process is waiting is shown in the WCHAN field of output of the ps 1 command.
