An essential element remains: the processors are highly interdependent, but their presence may not be obvious to the user. Leslie Lamport is credited for the observation that “A distributed system is one in which the failure of a computer you didn’t even know existed can render your own computer unusable.”

Linux takes a middle of the road position. It is a single computer system with network support. Each system can run stand-alone, but all systems can co-operate on the network.

# ### 1.3.3 Linux Is Not Secure

This deliberately scary heading exaggerates the case. This heading refers to systems which are claimed to be secure against malicious attacks because they fully close a lot of paths which are useful when those paths are slightly open. The “Oracle book” describes the steps one must take to qualify a system as secure[13]. Linux is not nearly any worse than other common systems—few systems are secure in a formal sense—and you wouldn’t like using those which are.

For example, some levels of secure systems prevent a user from learning the names of the other users on the system. An even more extreme case involves what are called “covert channels”, tricks which permit programs to pass classified data by non-obvious methods to other programs in violation of security ratings. Since these methods can involve one process watching another process’ memory map or even the rate of spawning child processes, a process’ state is entirely hidden from other processes. These limitations are anathema to much of how Unix and Linux were developed.

In spite of this warning about security, we are seeing constant improvements in Linux security. Unintended and undesirable security gaps are being regularly closed. Just don’t expect the Department of Defense, Ministry of Defense, Department of War (pick your country) to use Linux for keeping secrets.
