Prevention, Avoidance and Recovery Given this model of deadlock, it’s possible to build a system which cannot deadlock, or will not deadlock, or can recover from deadlock.

Deadlock prevention It is possible to prevent deadlock by ensuring at least one of the necessary conditions does not apply.

If all resources were shareable, mutual exclusion would not be required. Although some resources are fundamentally nonshareable, the system should ensure that as many resources as possible are presented as shareable. Hiding a line printer behind a printer spooler is an example of this approach.

It’s also possible to attack deadlock from the no preemption condition. Each process could be required to be able to safely relinquish its resources at the time it requests more. If a request results in blocking, the rest of the resources are made available to other processes. (It does, unfortunately, not prevent starvation—where a process is constantly denied one resource or another needed to proceed. It should be noted that starvation is a probabilistic effect—the process could at any instant get its needed resources.)

The hold and wait condition can be avoided by forcing all resource allocations to be done at one point in a process’ execution. Although it is wasteful, it does ensure that deadlock cannot occur. (This condition also leads to the possibility of starvation.)
