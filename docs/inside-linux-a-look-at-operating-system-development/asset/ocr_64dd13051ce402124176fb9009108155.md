# CHAPTER 5. THE OPERATING SYSTEM KERNEL

It is important to note that the bootstrap code cannot locate the kernels without help from /sbin/lilo. This is an important step which is sometimes forgotten by neophytes.

The installation part of LILO, /sbin/lilo, reads a configuration file which describes the kernel images, image names, peripheral options, and other bootstrap options.

+   1. It uses this information to locate the secondary bootstrap file boot.b and message when they are not in the default directory /boot.

+   2. It then builds /boot/map which holds pointers to the kernel images.

+   3. Finally it builds the primary bootstrap sector by copying some code from /boot/boot.b and loading pointers to /boot/boot.b, /boot/map, and /boot/message.

(In all the above examples, all occurrences of /boot/ describe the default location. All of these can be overridden by entries in the configuration file. For example, I have a special partition, mounted at /work, where I do all my kernel development. This partition contains an alternate directory /work/boot/ which is cited in the configuration file.)

If one wishes to boot one of two completely distinct Linux systems held in two different partitions, one must first mount the “other” partition on the active partition with a command such as

```
mount -t ext2 /dev/hda2 /mnt
```

prior to running /sbin/lilo. This is because /sbin/lilo locates the kernel images in terms of file names at the time the command is run. The configuration file then needs entries such as:

```
image = /vmlinuz
    root = /dev/hda1
    label = std.linux
image = /mnt/vmlinuz
    root = /dev/hda2
    label = new.linux
```
