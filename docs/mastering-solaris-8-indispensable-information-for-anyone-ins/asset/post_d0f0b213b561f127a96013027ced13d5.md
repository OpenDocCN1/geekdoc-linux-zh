
### pgrep argument
Reports PIDs that match a regular expression. If used with `-d` delimiter, it specifies the delimiter you should place between PIDs; the default is newline. If used with the `-f` option, it matches patterns against arguments rather than names. If used with the `-g` option, it will process only in specified process groups. If used with the `-G` gids option, it will process with real group IDs matching those in gids. If used with `-l` option, it gives verbose output. If used with `-n` option, it will return on the most recent process that matches the pattern. If used with the `-p` pids option, it only processes with the parent process IDs specified in pids. If used with `-s` sids, it shows processes with the specified session IDs. If used with `-t` terminals, it shows only those processes associated with the specified terminal. If used with `-u` euids, it only processes IDs matching those specified. If used with the `-v` option, it inverts the matching pattern and shows only those that do not match. If used with the `-x` option, processes with executable names that match the one on the command line are reported. If used with the `-s` signal option, it specifies a signal to send to each process reported.

### pkill argument
Kills or terminates processes matching a specified pattern. If used with the `-f` option, it matches patterns against the full process argument instead of the name. If used with the `-g` groups option, it processes in the process groups specified by groups. If used with the `-G` gids option, it only processes with real group IDs matching those in gids. If used with `-n` option, it returns only the most recent process matching the pattern. If used with the `-p` pids option, it only processes with the parent process IDs specified by pids. If used with the `-s` sids option, it only processes with the specified session IDs. If used with the `-t` terminals option, it only processes that show specified terminals. If used with the `-u` uids, it shows only processes with effective IDs matching those specified. If used with the `-U` uids option, it only processes with user IDs matching those specified. If used with the `-v` option, it inverts the pattern matching and shows only those not matching. If used with the `-x` option, it only processes with executable names matching the ones specified on the command line. If used with the `-s` signal option, it specifies a signal to send to each process shown. Default signal is SIGKILL.

### pr stat argument
Reports statistics on the current active processes. The default action is to display statistics on all processes. The output can be limited by adding options to the command line. If the `-c` option is not used, then the statistics are updated in place rather than by scrolling. The update period can be specified in seconds on the command line. If used with the `-a` option, it adds user statistics to the default output mode and includes the number of processes and the username, virtual memory size, memory resident set size, percent usage, cumulative execution time, and percent of CPU usage. If used with the `-c` option, it prints new statistics below the current screen. If used with the `-l` list option, it reports only those processes that are bound to the processor designated in 11st and expressed as integers. If used with the `-l` option, it reports lightweight process statistics. If used with the `-m` option, it reports microstate process statistics. If used with the `-n` option, it limits the number of output lines to the number of processes specified. If used with the `-p` pids option, it reports only those process ID numbers specified in pids. If used with the `-p` cpus option, it reports only those processes that have been executed by the processor specified by cpus. If used with the `-s` criterion option, it sorts output by the specified criterion in descending order by one of the following: cpu, time, size, rss, pri. If used with the `-S` option, it sorts in ascending order. If used with the `-t` option, it shows user statistics only, including number of processes, username, total virtual memory size, memory resident set size, percent usage, cumulative execution time, and percent CPU usage. If used with the `-u` uids option, it reports processes with user ID numbers matching those in uids. If used with `-U` uids, it reports processes with real user ID numbers matching those specified in uids. If used with `-v` option, verbose output shows all statistics for processes.

### ps (UCB) argument
Displays process information. If used with the `-a` option, it lists all processes, excluding process group leaders. If used with the `-c` option, it lists processes with more reliable command name information. If used with the `-g` option, it lists all processes including process group leaders. If used with the `-l` option, it formats a long listing. If used with the `-n` option, it replaces USER field with UID. If used with `-r` option, it lists running processes. If used with `-s` option, it displays total CPU time for processes, including child processes. If used with the `-t` term option, it lists processes controlled by the terminal. If used with the `-u` option, it formats running processes as a user listing. If used with the `-U` option, it updates ps database. If used with the `-v` option, it displays virtual memory. If used with the `-w` option, it gives wide output format using 132 characters. If used with the `-x` option, it lists processes that have no controlling terminal. If used with the `-ww` option, it puts no limits on output width.

### ps argument
Displays information about processes currently running. If used with the `-a` option, it lists all processes that are not group leaders. If used with the `-A` option, it lists all processes. If used with the `-c` option, it formats output as described in procnt1. If used with the `-d` option, it lists all processes except session leaders. If used with the `-e` option, it lists all processes that are currently active. If used with the `-f` option, it formats output as a full list. If used with `-g` groupList, it lists process for listed group leaders. If used with `-G` gidList, it lists processes with real group ID listed in gidList. If used with `-j`, it lists processes including session ID and group ID. If used with the `-l` option, it formats output as a long list. If used with `-o` format, it formats output as specified. If used by `-p` procList, it lists processes for all sessions leaders listed in sidList. If used with `-t` term, it lists all processes connected to the terminal specified by term. If used with the `-u` uIDList, it lists all processes with the same UID as those in uIDList. If used with the `-U` uIDList, it lists all processes with the same real UID as those listed in uIDList.

## Input/Output Redirection

When a program types something to your terminal, it is performing *standard output* operations. When you type something into your terminal, usually in response to a prompt, it is called *standard input*. These operations make your terminal “interactive.” They make programming an easier task because the C shell can read your commands from standard input and write responses to standard output. A *standard error* will occur if a running program encounters an inaccurate response, such as a typo or a misspelling. The program can send error messages to standard error, keeping it from getting mixed in with standard output. If you do not redirect one or the other, you may not understand the difference between the output the command sends to standard output and the output it sends to standard error.

Standard input, output, and error messages are usually attached to the terminal. It is possible to reassign their connections to something else quite easily. The input and output of commands can be redirected by using the `< >` tokens in shell scripts. Output from the file datasafe can be redirected as in the following example:

```
cat datasafe  > databank
```

If you want to do a sort on the output, you can give the sort command as shown in the following example:

```
sort datasafe >> databank
```

> **WARNING** If you want to add output to the end of the output file, use `>>` instead of `>`. Otherwise, normal output redirect can overwrite the output file completely and without warning.
