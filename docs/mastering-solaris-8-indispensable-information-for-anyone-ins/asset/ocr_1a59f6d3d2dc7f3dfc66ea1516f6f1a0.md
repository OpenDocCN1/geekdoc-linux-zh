# SUID and SGID Permissions

Executable files can have additional permissions called the Set User ID (SUID) and Set Group ID (SGID) applied to them. When there is no SUID or SGID permission set, the permissions that are applied to a program file are the permissions of the person who calls the file. When you execute an application that has the SUID bit set, the program runs as if it were started by the person who owns it, with their access privileges applied to the executable file instead of yours. In other words, the user inherits the owner's permissions. The use of an SUID flag is best illustrated when you change a password with the `passwd` command. That command is owned by root and the SUID flag is enabled. When you issue the `passwd` command, you assume the root's permissions to it while the `passwd` process runs.
