the shell scans the command line and takes everything from the start of the line to the first
whitespace character as the name of the program to execute: mv. Subsequent whitespace
(the extra spaces) are ignored and the characters up to the next whitespace character
is the first argument to mv: tmp/mazewars. The characters up to the next whitespace character
in this case, the newline character—is the second argument to mv: games. After parsing the
command line, the shell proceeds to execute the mv command, giving it the two specified
arguments tmp/mazewars and games (see Figure 2.9).

As mentioned, multiple occurrences of whitespace characters are ignored by the shell. This
means that when the shell processes this command:

```
echo do we eat?
```

it passes four arguments to the echo program: when, do, we, and eat? (see Figure 2.10).

![](bbox=[0.118, 0.469, 0.528, 0.591])

Because echo takes its arguments and displays them at the terminal, adding an individ-
space between each argument, the output from the following becomes a more legible:

```
$ echo when do we eat?
when do we?
```

It turns out the echo command never sees these blank spaces; they have been “gobbled up”
the shell. When we discuss quotes in Chapter 5, you'll see you can include blank spaces
in arguments to programs, but having extras vanish is exactly the behavior you want.

We mentioned earlier that the shell searches the disk until it finds the program you want
to execute and then its execution. This is true most of the time.
However, there are some commands that are actually built into the shell itself. These built-in
commands include cd, pwd, and echo. Before the shell searches the disk for a command, it first
determines whether it's a built-in command, and if so executes the command directly.
