# Accessing Commands from Your History

You've learned how to edit the command line, but the shell keeps a history of recently entered commands. To access these commands from the history list, use the emacs commands Ctrl+p and Ctrl+n. The Ctrl+n command replaces the current line on your terminal with the previously entered command, putting the cursor at the end of the line. Ctrl+p does the same action, but with the next command in the history list.

Let's assume these commands have just been entered:

```
$ pwd
/users/pat
$ cd /tmp
$ echo this is a test
this is a test
$ 
```

Now use Ctrl+p to access them:

```
$ Ctrl+p          $ echo this is a test_
$ cd /tmp_       $ cd /tmp_
              Ctrl+p
$ pwd_
```

Every Ctrl+p used, the current line is replaced by the previous line from the history.

To execute the command being displayed, just press Enter.

```
$ pwd_           Hit Enter
/tmp
$
```

The Ctrl+r command is used to search through the command history for a command containing the specified string. The Ctrl+r is followed by the search pattern, followed by the Enter key. The shell searches the command history for the most recently executed command that contains that string. If found, the command line is displayed; otherwise, the shell "beeps."

# The emacs Line Mode Edit

When the Ctrl+r is typed, the shell replaces the current line with the prompt ^R:

```
$ Ctrl+r test $ ^Rtest_
```

The search is initiated when Enter is pressed.

```
$ ^Rtest_ Enter $ echo this is a test_
```

To execute the command that is displayed as a result of the search, Enter must be pressed again.

```
$ echo this is a test_ Hit Enter again
this is a test
$_
```

To continue the search through the command history a little differently, by keeping Ctrl+r followed by an Enter.
Bash handles Ctrl+r: When you type Ctrl+r, Bash replaces the current line with (reverse-i-search)':

```
$ Ctrl+r (reverse-i-search)': _
```

As you type, the line is updated inside the ' ' with the text you type, and the rest of the line is updated with the matching command:

```
(reverse-i-search)': c (reverse-i-search)'c: echo this is a test
(reverse-i-search)'c': d (reverse-i-search)'cd: cd /tmp
```

Note how Bash highlights the matching part of the command by placing the cursor on it. As with the Korn, the command is executed by pressing Enter.
When you've found a command in the history (either by Ctrl+p, Ctrl+n, or Ctrl+r), you can also edit the command using the other emacs commands already discovered. As with vi edit mode, you won't actually change the command in the history but are editing a copy of the command, which will be entered in the history list when you press Enter.

|---|---|
| Ctrl+b | Move left one character. |
| Ctrl+f | Move right one character. |

# Other Ways to Access Your History

There are several ways to access your command history that are worth noting if you don't find that either the vi or emacs edit modes work for you.

# The history Command

The easiest way to access your command history is actually to just type in the command history:

```
$ cd shell
507 cd ch15
508 vi int
509 ps
510 echo $HISTSIZE
511 cat $ENV
512 cp int.sv
513 history
514 exit
515 cd shell
516 cd ch16
517 vi all
518 run -n5 all
519 ps
520 lpr all.out
521 history
```

The numbers to the left are relative command numbers (command number 1 would be the first, or oldest, command in your history).

Be aware that the history command differs between the Korn and Bash shells: The Korn shell command writes your last 16 commands to standard output while Bash will list your entire command history, even if it's 500 or 1000 lines long.

# Other Ways to Access Your History

If you're running Bash and don't want to be inundated with commands, you can specify the number of commands to display as an argument:

```
$ history 10
513 cp int int.sv
514 history
515 exit
516 cd shell
517 cd ch16
518 vi all
519 run -n5 all
520 ps
521 lpr all.out
522 history 10
```

# The fc Command

The fc command allows you to start an editor on one or more commands from your history or to write a list of history commands to your terminal. In the latter form, which is indicated by giving the -l option to fc, it is like typing in history, only more flexible (you can specify a range of commands to be listed). For example, the command

```
fc -l 510 515
```

writes commands 510 through 515 to standard output, and the command

```
fc -n -1 -20
```

writes the last 20 commands to standard output, but omits command numbers (-n). Suppose you've just executed a long command and decide that it would be nice to turn that command line into a shell program run. You can use fc to get the command from your history and I/O redirection to rewrite that command to a file:

```
fc -n -1 -1 > runx
```

That's the last 1 followed by the number -1 to get the most recent command (current minus one). fc is described in full detail in Appendix A.

# The r Command

A simple Korn shell allows you to re-execute previous commands using even fewer keystrokes. Type in the r command, and the Korn shell re-executes your last command:

```
$ date
Thu Oct 24 14:24:48 EST 299
$ r
date
Thu Oct 24 14:24:48 EST 299
```

# Functions

Bash and the Korn both have function features not available in the POSIX standard shell.
Let's have a look.

## Local Variables

Bash and Korn shell can have local variables, making recursive functions
possible. These variables are defined with the typeset command, as in

typeset i j

If a variable of the same name already exists, it is saved when the typeset is executed and
ored when the function exits.

After using the shell for a while, you may develop a set of functions that you like to use
your interactive work sessions. A good place to define such functions is inside your ENV file so
they will be defined whenever you start a new shell.

## Automatically Loaded Functions

The Korn allows you to set up a variable called FPATH that is similar to your PATH
if you execute a function that is not yet defined, the Korn searches the
-delimited list of directories in FPATH for a file that matches the function name. If it
finds such a file, it executes it in the current shell with the expectation that somewhere in the
file is the definition for the specified function.

## Integer Arithmetic

Both Bash and the Korn support evaluating arithmetic expressions without arithmetic
expansion. The syntax is similar to $((...)) but without the dollar sign. Because expansion is
not performed, the construct can therefore be used by itself as a command:

```
$ x=10
$ ((x = x * 12))
$ echo $$
120
$ 
```
