# ${parameter:=value}

This version is similar to the previous, but if parameter is null only is value used, but it is also assigned to parameter as well (note the = in the construct). You can assign values to positional parameters this way, however, so that means that parameter cannot be a number.

A typical use of this construct would be in testing to see whether an exported variable has been set and, if not, assigning it a default value:

```
$ PHONEBOOK=$$HOME/phonebook
```

This says that if PHONEBOOK already has an assigned value, leave it alone, otherwise set it to $HOME/phonebook.

Note that the following example could not stand as a command because the substitution is performed the shell would attempt to execute the result:

```
$ PHONEBOOK=
$ ${PHONEBOOK}:=$HOME/phonebook}
sh: /users/steve/phonebook: cannot execute
$
```

To use this construct as a stand-alone command, the null command can be employed. If you write

```
: ${PHONEBOOK}:=$HOME/phonebook}
```

the shell still does the substitution (it evaluates the rest of the command line), yet executes nothing (the null command).

```
$ PHONEBOOK=
$ ${PHONEBOOK}:=$HOME/phonebook
$ echo $PHONEBOOK
/users/steve/phonebook
$ ${PHONEBOOK}:=$foobar
$ echo $PHONEBOOK
/users/steve/phonebook
$
```

# ${parameter?value}

If parameter is not null, the shell substitutes its value; otherwise, the shell writes value to standard error and exits (don't worry—if it's done from your login shell, you won't be logged off). If value is omitted, the shell writes the default error message

```
prog: parameter: parameter null or not set
```
