will not run in the subshell with the who invocation if the ! -f (non-existence) test fails, because test already knows the AND (-a) expression is false. Subtle, but something that can trip up shell programmers if they try to jam too much into conditional expressions with the assumption that everything is run prior to the conditional tests being applied.

# Parentheses

You can use parentheses in a test expression to alter the order of evaluation as needed; just make sure that the parentheses themselves are quoted because they have a special meaning to the shell. So to translate the elater expression into a test command, you would write

```
[ \$count" -ge 0 -a "$count" -lt 10 \ ]
```

As is typical, spaces must surround the parentheses because test expects to see every element in the conditional statement as a separate argument.

# The Logical OR Operator -O

The -o operator is similar to the -a operator, it only forms a logical OR of two expressions. That, evaluation of the expression will be true either the first expression is true or the second expression is true or both expressions are true.

```
- n "mailopt" -o r $HOME/mailfile
```

This command will be true if the variable mailopt is not null or the file $HOME/mailfile is readable by you.

The -o operator has lower precedence than the -a operator, meaning that the expression

```
"$a" -eq 0 -o "$b" -eq 2 -a "$c" -eq 10
```

gets evaluated by test

```
"$a" -eq 0 -o "$b" -eq 2 -a "$c" -eq 10
```

Naturally, you can use parentheses to change this order if necessary:

```
\ ($a" -eq 0 -o "$b" -eq 2 -a "$c" -eq 10
```

Since precedence is critically important in complex conditional statements, you'll find a lot of shell programmers have nested if statements to side-step issues, while others use explicit parentheses to clarify order of interpretation. Just assuming things are interpreted left-to-right is dangerous!
