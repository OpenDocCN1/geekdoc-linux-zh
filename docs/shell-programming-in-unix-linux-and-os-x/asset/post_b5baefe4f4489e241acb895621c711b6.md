
# Functions 269

A function definition can continue over as many lines as necessary. The shell will continue to prompt for commands within the function with the secondary command prompt until you complete the function definition with the ).

You can put definitions for commonly used functions inside your .profile so they'll be available whenever you log in. Alternatively, you can group the definitions in a file, say myfuncs, and execute the function in the current shell by typing

- `. ./myfuncs`

As you know now, this causes any functions defined in myfuncs to become available in the current shell.

The following function, called mycd, takes advantage of the fact that functions are run in the current environment. It mimics the operation of the Korn shell's cd command, which has the capability of substituting portions of the current directory's path (see the discussion of cd in Chapter 14 for more explanation).

```bash
$ myfuncs
# See what's inside
# new cd function:
#   mycd switches dir
#   mycd old new  Substitute for old in current directory's path
#
mycd () {
  if [ $# -le 1 ]; then
    # normal case -- 0 or 1 argument
    cd $1
  elif [ $# -eq 2 ]; then
    # special case -- substitute $2 for $1
    cd $$(echo $PWD | sed "s|$1|$2/")
  else
    # mycd can't have more than two arguments
    echo mycd: bad argument count
    exit 1
  fi
}
```

```bash
$ .myfuncs  Read in definition
$ pwd
/users/steve

$ mycd  Change directory
Did it work?
$ cd /users/pat
$ mycd pat tony  Substitute tony for pat
$pwd
/users/tony
$
```

# Chapter 12 Loose Ends

Functions execute faster than an equivalent shell program because the shell doesn't have to search the disk for the program, open the file, and read its contents into memory; it can just jump right into executing the individual commands directly.

Another advantage of functions is the capability to group related programs in a single file. For example, the add, lu, and rem programs from Chapter 10 can now be defined as individual functions within the rollo program. The template for such an approach is shown:

```bash
$ cat rollo
# rollo program written in function form
add () {
    # Function to add someone to the phone book
    # put commands from add here
}

lu () {
    # Function to look someone up in the phone book
    # put commands from lu here
}

rem () {
    # Function to remove someone from the phone book
    # put commands from rem here
}
```

None of the commands inside the original add, lu, or rollo would have to be changed. The first three are turned into functions by including them inside rollo, sandwiched between the function header and the closing brace. Defining them as functions would make them inaccessible as standalone commands.

# Removing a Function Definition

To remove the definition of a function from the shell, use the unset command with the -f option. Look familiar? Is it the same command you use to remove the definition of a variable from the shell?

```bash
$ unset -f lu
$ lu: not found
```

# The return Command

If you use exit inside a function, its effect is not only to terminate execution of the function but also to exit back to the command line that called it. If you instead want to just exit the function, use the return command, whose format is `return n`. The value n is used as the return status of the function. If omitted, the status is that of the last command executed. This is also what happens if you don't include a return statement in your function. The return status is in all other ways equivalent to the exit status.

# The type Command

When you type the name of a command to execute, it's useful to know whether it is a function, a shell builtin, a standard Unix command or a shell alias. This is where the type command comes handy. The type command takes one or more names as its argument and tells you what it knows about it. Here are some examples:

```bash
$ type () { who | wc -l; }
$ type pwd is a shell builtin
$ type ls is aliased to '/bin/ls'
$ type cat is /bin/cat
$ type lu is a function
```

# Data Formatting Considerations

While the initial name-and-number rollo program shown earlier in the book is handy, there's no question that a more useful program would allow more than just the names and numbers. You'd probably want to save addresses and email addresses too, for example. The new rollo program allows entries in the phone book to consist of multiple lines. A typical entry might be:

Steve's Ice Cream
444 6th Avenue
New York City 10003
212-555-3021

To increase the flexibility of the phone book, an individual entry can now contain as many lines as desired. Another entry in the phone book might read:

YMCA
(201) 555-2344

To logically separate entries in the phone book, each entry is "packed" into a single line by replacing the terminating newline in an entry with a different character. We arbitrarily chose the caret ^ as it appears very rarely in regular user input, addresses, etc. The only repercussion of this decision is that this character cannot be used as part of the phone entry itself.

Using this technique, the first entry shown would be stored in the phone book file as:
Steve's Ice Cream*444 6th Avenue*New York City 10003*212-555-3021*

and the second entry as:
YMCA^(201) 555-2344^

It now becomes quite easy to work with entries when they're stored in this format, a testament to how really thinking through a problem and solution can reap great benefits if it's developed further.

# rollo

```bash
# rollo - rolodex program to look up, add,
# remove and change entries from the phone book
#

# Set PHONEBOOK to point to the phone book file
# and export it other progs know about it
# if it's set on entry, leave it alone
#
: ${PHONEBOOK=$HOME/phonebook}
export PHONEBOOK
if [ ! -e "$PHONEBOOK" ]; then
  echo "$PHONEBOOK does not exist!"
  echo "Should I create it for you (y/n)? "
  read -n answer
  if [ "$answer" = y ]; then
    touch "$PHONEBOOK" || exit 1      # exit if the creation fails
  fi
fi

# If arguments are supplied, then do a lookup
if [ "$#" -ne 0 ]; then
  lu "$1"
fi

# Set trap on interrupt (DELETE key) to continue the loop
trap "continue" SIGINT

# Loop until user selects 'exit'
while true
do
    # Display menu
    echo -e '\nWould you like to:
    1. Look someone up
    2. Add someone to the phone book
    3. Remove someone from the phone book
    4. Change an entry in the phone book
    5. List all names and numbers in the phone book
    6. Exit this program\n\nPlease select one of the above (1-6): '

    # Read and process selection
    read choice
    echo
    case "$choice"
        1) echo -n "Enter name to look up: "
               read name
               if [ -z "$name" ]; then
                   echo "Lookup ignored"
               else
                   lu "$name"
               fi ;;
        2) echo -n "Enter name to add: "
               read name
               echo -n "Enter phone: "
               read phone
               add "$name" "$phone" ;;
        3) echo -n "Enter name to remove: "
               read name
               rem "$name" ;;
        4) echo -n "Enter name to change: "
               read name
               echo -n "Enter new phone: "
               read phone
               change "$name" "$phone" ;;
        5) list ;;
        6) exit 0 ;;
        *) echo "Invalid selection." ;;
    esac
done
```
