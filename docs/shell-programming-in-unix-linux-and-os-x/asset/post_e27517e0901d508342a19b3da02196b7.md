
## Chapter 14 Interactive and Nonstandard Shell Features

It turns out that all the major interactive shells allow you to specify which shell—actually, which program of the thousands included in a Unix or Linux distribution—should be used to run the file. If the first two characters on the first line of a file are #$, the remainder of the line specifies an interpreter for the file. So

```bash
#!/bin/ksh
```

specifies the Korn shell and use

```bash
#!/bin/bash
```

specifies Bash. If you use constructs or notational conventions specific to one shell, you can use this feature to force that shell to run your programs, avoiding compatibility problems.

Since you can specify any program you want, a Perl program beginning

```bash
#!/usr/bin/perl
```

forces the shell to invoke /usr/bin/perl to interpret the lines within the file.

You have to use this feature with caution, because many programs, such as Perl, do not reside in a standard place on every Unix system. Also, this is not specified by the POSIX standard, though it's found in every modern shell and is even implemented at the operating system level on many Unix versions.

Most commonly you'll see system programs use this notation to ensure that Bourne Shell is used regardless of the user's login shell by beginning with

```bash
#!/bin/sh
```

### The ENV File

When you start the shell, the first thing it does is to look in your environment for a variable ENV. If it finds and it's non-null, the ENV will be executed, like the .profile is executed when logging in. The ENV file contains commands to set up the shell's environment. Throughout this chapter, we'll mention many things that you may want to put into this file.

If you decide to have an ENV file, you should set and export the ENV variable inside your

```bash
$ cat .profile

export ENV=$HOME/.alias
... own$
```

Note the shortcut in above: Instead of assigning the variable a value, then calling export, it turns out you can do both on the same line for efficiency.

## Command-Line Editing

For users, the ENV file is read only when Bash is invoked with the name sh, with the --posix command-line option, or after set -o posix is executed (all of force POSIX standard compliance). By default, when a non-interactive Bash shell is started (for example, when you run a shell program), it reads commands from the file specified by the B_ENV environment variable, and when an interactive Bash shell is started (for example, typing bash at the command prompt), it doesn't.

If you're running an older system, you should also export a variable SHELL inside your .profile file.

```bash
$ SHELL .profile
SHELL=/bin/ksh ; export SHELL
$
```

This variable is used by certain applications (such as vi) to determine what shell to start when you execute a shell escape. In such cases, you want to make sure that each time you start a new shell, the shell you want and not another Bourne. Probably, SHELL will already be set by your login shell. You can test it with

```bash
$ echo SHELL
/bin/bash
$
```

Also note that the previous example demonstrates yet another way to set and export a variable, by having two separate commands on the same line, separated by a semicolon. Why the inconsistency? Because Unix is so flexible that you'll find it common for shell programs you read—and users you work with—accompl the same task multiple ways. Might as well get to use variations in notation!

Line edit mode is a feature of the shell that allows you to edit a command line in a manner that mimics features found in two popular editors. The POSIX standard provides the capability to mimic vi and both Bash and the Korn shell also support emacs line edit mode. We list the complete set of commands in Table A.4 in Appendix A.

If you've used either of these text-based editors, you'll find the built-in line editors in the shell are faithful reproductions from a functional perspective. This capability is one of the most useful features in the shell.

To turn on a line use the set command with the -o mode option, where mode is either vi or emacs:

```bash
$ set -o vi
Turn on vi mode
```

Put this in your .profile file to automatically start up the shell with one of the edit modes turned on.

## Command History

Regardless of which shell you use, it keeps a history of all your previously entered commands. Each time you press the Enter key to execute a command, that command gets added to the end of your history.

Depending on your settings, your command history could even be saved to a file and restored between sessions, so you can quickly access commands from previous sessions.

By default, the history is kept in a file in your home directory named .sh_history (Bash). You can change this filename to anything you want by setting the HISTORYFILE variable. This variable can be set and exported in .profile.

There is a limit to the number of commands the shell stores. The minimum value is 128 and most modern shells use 500 or more of your commands on the list. Each time you log in, the shell automatically truncates your history file to this length.

You can control the size of your history file by setting the HISTSIZE variable. If the default isn't adequate for your needs, set the HISTSIZE variable to a larger value, such as 500 or 1000. The value you assign to HISTSIZE can be set and exported in .profile file:

```bash
$ HISTSIZE .profile
HISTSIZE=500
$
```

After the cursor is the character you want to change, you can use the x command to delete the current character ("X" it out). Note that the b moved to the left when the x was deleted and it is now the current character.

To add to the command line, you can use the i before or a commands. The i command inserts before the current character, and the a command adds after the current character. Both of these commands put you back into input mode, remember to press Esc to go back to command mode.

```bash
$ mary had a little lab im $ mary had a little lamb
$ mary had a little lamb m $ mary had a little lambm
$ mary had a little lambb Esc $ mary had a little lammb
$ mary had a little lambb x $ mary had a little lamb
$ mary had a little lamb a $ mary had a little lamb_
$ mary had a little lamb_ da $ mary had a little lambda_
```
