When the loop is exited—signaling the monitored user has logged on—a message displayed at the terminal to that effect and the script is done.

$ waitfor Time passes
sandy has logged on
$

Of course, running the program as shown here is not very practical because it ties your terminal until sandy logs on. A better idea is to run waitfor in the background so that you can use your terminal for other work:

```
$ waitfor & Run it in the background
[1] 4392 Job number and process id
$ nroff newmemo Do work
```

...
sandy has logged on Happens sometime later

Now you can do other with the waitfor program executing in the background sandy logs on, or until you log off the system.

# Note

By default, all your processes are automatically terminated when you logged off. If you want a program to continue after you've logged off, you can run it with the nohup command, or schedule it to run at or from cron. Consult your Unix User's Manual for more details.

Because waitfor only checks once per minute for the user logging, it won't consume many resources while it's running (an important consideration when running programs in the background).

Unfortunately, after the specified user logs on, there's a chance you might miss the one-line notification message. If you're editing a file with a screen editor until vi, the notification message could turn your screen into a mess, and you still might not be able to read it!

A better alternative might be to mail it to yourself. Here, you can let the user choose which they'd prefer by adding an option to the program, if selected, indicates that the message is mailed. If not, the message is displayed at the terminal.

In the version of waitfor that follows, a -m option has been added for this purpose:

```
$ cat waitfor
#
# Wait until a specified user logs on -- version 2
#
```

```
if [ "$1" = -m ]
then
mailopt=TRUE
shift
```
