Tilde Substitution

The shell expands the tilde at the beginning of a word. If the tilde is followed by a name, it is expanded to the home directory of that user. If the tilde is followed by a slash, it is expanded to the home directory of the current user. If the tilde is not followed by anything, it is expanded to the home directory of the current user.

The tilde is only expanded when at the beginning of a word, and it is followed by a name, a slash, or it is at the end of the word.

# Arithmetic Expressions

General Format: $(((( expression ))

The shell evaluates the integer expression. expression can contain constants, variables, and operators. The operators, in order of decreasing precedence, are:

- unary bitwise NOT, logical negation
- multiplication, division, remainder
- addition, subtraction
- left shift, right shift
- comparison
- equal, not equal
- bitwise AND
- bitwise exclusive OR
- bitwise OR
- logical AND
- logical OR-assignment

Parentheses may be used to override precedence. The exit status is zero (true) if the last expression is nonzero and one (false) if it is zero.

Examples

```
y=$((2 * 3))
z=$((y / 1))
```

# Filename Substitution

After parameter substitution and command substitution are performed on the command line, the shell looks for the special characters *, ?, and .. If they are not quoted, the shell searches the current directory, or another /, and substitutes the names of all files that match. If no match is found, the characters remain untouched.

Note that filenames beginning with - must be explicitly matched (in other words, echo * will not display hidden files).

The filename substitutions are summarized in Table A.6.

Table A.6 Filename Substitution Characters

| Character(s) | Meaning |
|---|---|
| ? | Matches any single character. |
| * | Matches zero or more characters. |
| [chars] | Matches any character in chars; the format Ci-Cj can be used to match any character in the range Ci through Cj, inclusive (for example, [A-Z] matches any uppercase letter). |
| ![chars] | Matches any character not in chars; a range of characters may be specified as above. |

# I/O Redirection

When scanning the command line, the shell looks for the special redirection characters < and .. If found, they are processed and removed (with any associated arguments) from the command line. Table A.7 summarizes the different types of I/O redirection that the shell supports.

Table A.7 I/O Redirection

| Construct | Meaning |
|---|---|
| < file | Redirect input to file. |
| > file | Redirect output to file; file is created if it doesn't exist and zeroed if it does. |
| >= file | Redirect output to file; file is created if it doesn't exist and zeroed if it does; the noclobber (-C) option is set. |
| >> file | Like >, appended to file if it already exists.
| << word | Redirect input from file following up a line containing word; parameter substitution occurs on the lines, and back-quoted commands are executed and the backslash character interpreted; if any character in word is passed through unaltered; if word is preceded by a -, leading tabs on the lines are removed. |
| & digit | Standard input is redirected from the file associated with file descriptor digit. |
