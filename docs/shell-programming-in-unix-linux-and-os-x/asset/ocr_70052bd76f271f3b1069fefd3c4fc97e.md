Individual statements can override block redirection, just as any other statements in your shell programs can explicitly redirect from a specified source or send output to a specified destination.

To force input or output to come or go to the terminal, utilize /dev/tty, which always refers to your terminal program, whether you're on a Mac, Linux, or Unix system.

In the following loop, all is redirected to the file `output` except the `echo` command's output, which is explicitly redirected to the terminal:

```
for file
do
  echo "Processing file $file" > /dev/tty

done > output
```

You can also redirect the standard error output from a loop, simply by tacking on a 2> `file` after the done:

```
while [ "$endofdata" -ne TRUE ]
do
  ...

done 2> errors
```

Here output from all commands in the loop writing to standard error will be redirected to the `file errors`.

A variation of the `2> file 1&2` format is commonly used to ensure that error messages go to the terminal even when a script might have its output redirected into a file or pipe:

```
echo "Error: no file $file" 1&2
```

By default, echo sends its output to standard output (file descriptor 1), while file descriptor 2 remains standard error and is not redirected on file redirection or pipe default. The notation above means that the error message from `echo` should have its `file #1` output redirected to `file #2`, which is, standard. You can test this with code like this:

```
for i in "once"
do
  echo "Standard output message"
  echo "Error message" 1>&2
ndone > /dev/null
```

Try it and see what happens.
