# Spaces in Filenames

A discussion of command lines and filenames wouldn't be complete without talking about the bane of old-school Unix people and very much the day-to-day reality of Linux, Windows, and Mac users in filenames.

The problem arises from the fact that the shell uses spaces as delimiters between words. In other words the phrase echo hi is properly parsed as an invocation to the command echo, with two arguments hi and mom.

Now imagine you have a file called my test document. How do you reference it from the command line? How do you view or display it using the cat command?

```
$ cat my test document
cat: No such file or directory
cat: No such file or directory
cat: No such file or directory
```

That definitely doesn't work. Why? Because cat wants a filename to be specified and instead of seeing one, it sees three: my, test, and document.

There are two standard solutions for this: Escape every space by using a backslash, or wrap the entire filename in quotes so the shell understands it's a single word with spaces, rather than multiple words.

```
$ cat "my test document"
This is a test document and is full
of scintillating information to edify
and amaze.
$ cat "my\ test document"
This is a test document and is full
of scintillating information to edify
and amaze.
```

That solves the problem and is critical to how you proceed with file systems that have lots of directories and files that contain spaces as part of their filenames.
