The rem program collects all matching entries into a temporary file, tests the result: If the size of the file is zero, no match was found and an error message is issued. Otherwise, for each matching entry, the program displays the entry and asks the user whether that entry should be removed.

From a user experience perspective, this type of coding practice provides reassurance to the user that they intend to remove the one that the program is going to remove, even in the single case.

After the user has prompted the program with y, a break command exits the loop. Outside the loop, the program then tests the value of answer to determine how the loop was exited. If its value is not equal to y, then the user does not want to remove an entry after all (for whatever reason). Otherwise, the program proceeds with the removal of all lines that don't match the specified pattern. Note that grep matches only entire lines by greping the regular expression to the start and end of line.

Note also in the edge case of removing the last entry in their phonebook, the script now recognizes the situation (by testing to see if the file exists and is non-zero in size) and outputs an informative message. It's not an error, but it ensures that the failure message that would be triggered by the grep -v invocation is not displayed.
