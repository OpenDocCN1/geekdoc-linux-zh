# Ignoring Signals

If the command listed for trap is null, the specified signal is ignored when received. For example, the command

```
trap " SIGINT
```

specifies the interrupt signal is to be ignored. You might want to ignore certain signals when performing some operation that you don't want.

Note that trap lets you specify signal by name, by shortened name (INT) or by the full signal name (SIGINT). We encourage you to use mnemonic names to help produce readable code, but it is, of course, to which you prefer.

In the example, the first argument must be specified as a null value for a signal to be ignored and is not equivalent to writing the following, which has a separate meaning of its own:

```
trap 2
```

If you ignore a signal, all subshells also ignore that signal. If you specify a signal handler action, however, all subshells automatically take the default action on receipt of signal, not the new code sequence.

Suppose you execute the command

```
trap " 2
```

and then start a subshell, which in turn executes other programs as subshells. If an interrupt signal is generated, it will have no effect on the shells or subshells that are executing because they will ignore the signal by default.

If instead of executing the previous trap you execute

```
trap : 2
```

and then execute your subshells, the current shell will do nothing on receipt of an interrupt (it will execute the null command), while subshells will be terminated (the default action).
