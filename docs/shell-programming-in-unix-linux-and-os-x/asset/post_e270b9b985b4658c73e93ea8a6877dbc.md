## The $$ Variable and Temporary Files

If one or more people on your system use the rolo program at the same time, a potential problem may occur. Look at the rem program and see whether you can spot it. The problem occurs with the temporary file /tmp/phonebook that is used to create a new version of the phone book file.

The specific statements in the rem program look like:

```bash
grep -v "$Name" phonebook > /tmp/phonebook
mv /tmp/phonebook phonebook
```

But here's the problem: If more than one person uses rolo at the same time to remove an entry, there's a chance that the phone book file can get messed up because the temporary file will be simultaneously used more than once. To be fair the chance of this happening is rather small, but it's non-zero and means it's a problem.

## The read Command

There are two important concepts that this code raises. Actually, the first is to do with how computers implement multitasking, by swapping individual programs in and out of the processor. The result is that at any point during execution, a program can be swapped out, half-way through a series of commands. Now you can see the problem with the above code: because it's two statements, what happens if the program loses its place in line between the two statements and another instantiation of the program runs to the exact same lines of code? The second program overwrites the result of the first program's grep invocation. Not good for either user!

The second point relates to what's known as a race condition, a situation where more than one simultaneous invocation of a program can cause trouble. Most often that's to temporary files, but it can also occur with sub-processes and lock files, as we'll discuss later in the book.

For now, just keep in mind when writing shell programs that are run by more than one person, make sure each user's temporary files are unique.

One solution is to create temporary files in the user's home directory /tmp/. Another way is to choose a temporary filename that will be unique and different for each invocation of the program. A neat way to do this is to embed the unique process ID (PID) of the specific invocation into the filename. This is easily accomplished by referring to the special $$ shell variable:

```bash
$ echo $$
4668
$ ps
PID TTY TIME COMMAND
4668 co 0:09 sh
6470 co 0:03 ps
$
```

When substituted by the shell, $$ becomes the process ID of the login shell itself. Each process on the system is given a unique process ID, using the value of $$ in the name of file eliminates the possibility of a different process using the same name. To fix the problem highlighted earlier, replace the two lines from rem with this improved sequence:

```bash
grep -v "$name" phonebook > /tmp/phonebook$$
mv /tmp/phonebook$$ phonebook
```

to side-step any potential race conditions. Each person using rolo will run as a different process, so the file used in each instance will be different. Problem solved.

## The Exit Status from read

read returns an exit status of zero unless an end-of-file condition is encountered. If the data is coming from the terminal, this means that the user has pressed Ctrl+d. If the data is coming from a file, it means there's no more data to read. This makes it easy to write a loop that will read lines of data from either a file or the terminal. The next program, called addi, reads lines containing pairs of numbers, which addi adds together; their sums are then written to standard output:

```bash
$ addi
while read n1 n2
do
  echo $((n1 + n2))
done
```

The while loop is executed as long as the read returns an exit status of zero, which occurs as long as there is still data to read. Inside the loop, the two values read from the line (presumably integers—no checking is done here) are added up and the result written to standard output.

```bash
$ addi < data > sums
$ addi < sums
194
233
87
```

## The read Command

The following program, called number, is a simplified version of the standard nl command: it accepts one or more files as arguments and displays their contents with its line number. If no arguments are supplied, it reads standard input.

```bash
cat number
# Number lines from files given as argument or standard input if none
lineno=1

cat $* |
while read line
do
  echo "$lineno: $line"
  lineno=$((lineno + 1))
done
```

The variable line—the line counter—is initially set to 1. Then the arguments typed to number are given to cat to be collectively written to standard output. If no arguments are supplied, $* will be null, and cat will pass no arguments. This will cause read from standard input. The output from cat is piped into the while loop. Each line encountered by read is echoed at the terminal, preceded by the current value of line, whose value is then incremented by one.

number book 973-555-2015

2: Barbara Swingle 201-555-9257
3: Billy Bach 201-555-7618
4: El Coyote 212-555-3232

```bash
who from standard input |
1: root console Jul25 07:55
2: pat tty03 Jul25 09:26
3: steve tty04 Jul25 10:58
4: george tty13 Jul25 08:05
```

Note that number won't work well for lines that contain backslashes or leading whitespace characters. The following example illustrates this.

```bash
$ number
Here are some backslashes: \
1: Here are some backslashes: *
```

Leading whitespace characters are removed from any line that's read. The backslash characters are also interpreted by the shell when it reads the line. You can use the -r option of read to prevent it from interpreting the backslash character. If we change the
while read to
in number to
while read -r line
the output will look like:

```bash
$ number
Here are some backslashes: \*
1: Here are some backslashes: \\*
$
```

In Chapter 11 you'll learn how to preserve the leading whitespace characters and also how to have some control over the parsing of the input data.

## The printf Command

echo is quite adequate for displaying simple messages, sometimes you'll want to print formatted output: for example, lining up columns of data. Unix systems provide the printf command for these tasks. Those of you familiar with the C or C++ programming language will notice many similarities with their function of the name.

The general format of the printf command is

```bash
printf "format" arg1 arg2 ...
```

where format is a string that details how the subsequent values are to be displayed. Since the printf string is an argument and likely to contain special characters, spaces, it's always a good idea to include it in quotes.

Characters preceded by a percent sign are called format specifications and tell printf how the corresponding argument should be displayed. Each percent sign in the format string there should be a corresponding argument, except for the percent specification %%, which causes a single percent to be displayed.

```bash
$ printf "Hello world!\n"
Hello world!
$
```

Let's start with a simple example of printf:

```bash
$ printf "This is a number: %d\n" 10
This is a number: 10
$
```
