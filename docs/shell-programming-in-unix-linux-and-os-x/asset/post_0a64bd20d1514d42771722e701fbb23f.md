The space between Susan and Goldberg, which would normally have delimited two separate arguments, was ignored by the shell. grep interpreted the first argument, Susan Goldberg, as a pattern that included an embedded space and looked for in the file specified by the second argument, phonebook. Note that the shell removes the quotes and does not pass to the program.

No matter how many space characters are enclosed between quotes, they are all preserved by the shell.

```
$ echo one two three four

$ echo 'one'
two three four
$
```

Worth emphasizing is that all special characters are ignored by the shell if they appear within single quotes. That explains how the following works:

```
$ files/users/steve/bin/progl
$ echo $file
/users/steve/bin/progl
$ echo '$file'
not interpreted
$file
$ echo *
addresses into lots of spaces names nu phonebook stat
$ echo '*'
$ echo ' < > | ; ( ) { } >> &'
< > | ; ( ) { } > " &\n$
```

Even the Enter key will be retained as part of the command argument if it's enclosed in single quotes:

```
$ echo 'How are you today,
> John'
How are you today,
John
$
```

After parsing the first line, the shell sees that the > quote isn't matched, so it prompts the user (with ~) to type the closing quote. The > is known as the secondary prompt character and is displayed by the shell whenever it's waiting for you to finish typing a multi-line command.

Quotes are also needed when assigning variables containing whitespace or special characters to shell variables, though there are nuances, demonstrated:

```
$ messages='I must say, this is fun'
$ echo $message
I must say, this is fun
$ text='means all files in the directory'
$ echo $text
```

names nu phonebook stat means all files in the directory
$
```

The quotes are needed in the first statement because the value being stored includes spaces.

The second sequence with the variable text highlights that the shell does filename substitution after variable substitution, the * is replaced by the name of all files in the current directory after the variable is expanded, but before the echo is executed. Annoying!

How do you fix this sort of problems? Through the use of double quotes.

# The Double Quote

Double quotes work similarly to single quotes, except they're less protective of their content:
single quotes tell the shell to ignore all enclosed characters, double quotes say to ignore most.
in particular, the following three characters are not ignored inside double quotes:

- Dollar signs
- Back quotes
- Backslashes

The fact that dollar signs are not ignored means variable name substitution is done by the shell inside double quotes.

```
$ filelist=*
echo $filelist
addresses into lots of spaces nu phonebook stat
echo '$filelist'
$filelist
echo '$filelist*'
*
```

Here you see the major difference between no quotes, single quotes, and double quotes. In the first instance, the shell sees the asterisk and substitutes all filenames from the current directory. In the second case, the shell leaves the characters enclosed within the single quotes completely alone, which results in the display of $filelist. In the final case, the double quotes indicate to the shell that variable name substitution is still to be performed inside double quotes. So the shell substitutes for $filelist. But because filename substitution is not done inside double quotes, * is then passed to echo as the value to be displayed.

> Note
While we're talking about versus double quotes, you should also be aware that the shell has no idea what "smart" quotes are. Those are generated by processors like Microsoft Word and curl "inward" towards the material they surround, making it much more attractive when printed. The problem is, that they'll break your scripts, so be!

If you want to get the value of a variable substituted, but don't want the shell to parse the characters especially, enclose the variable inside double quotes.

Here an another example illustrating the difference between double quotes and no:

```
$ address="39 East 12th Street
> New York, N. Y. 10003"
echo $address
39 12th Street New York, N. Y. 10003
echo "$address"
39 12th Street
New York, N. Y. 10003
$
```

# The Backslash

Functionally, the backslash (used as a prefix) is equivalent to placing single quotes around a single character, though with a few exceptions exceptions. The backslash escapes the character that immediately follows it. The general format is

```
\c
```

where c is the character you want to quote. Any special meaning attached to that character is removed. Here is an example:

```
$ echo >
syntax error: 'newline or ;' unexpected
$ echo \>
>
$
```

In the first usage, the shell sees the $ and thinks that you want to redirect echo's output to a file, so it escapes it to a filename. Because it doesn't, the shell issues the error message.

In the next usage, the backslash escapes the special meaning of >, so it is passed along to echo as a character to be displayed.

```
$ x=* \x
$ echo \$x
$x
$
```

In this case, the shell ignores the $ that follows the backslash, and as a result, variable substitution is not performed.
