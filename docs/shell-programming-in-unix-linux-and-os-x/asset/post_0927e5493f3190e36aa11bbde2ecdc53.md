# More on Loops

## Breaking Out of a Loop

Sometimes program logic dictates an immediate exit from a loop statement. To exit from the loop but not from the program, use the break command:

```bash
break
```

# More on Loops

When the break is executed, control is immediately moved outside of the loop, where execution then continues as normal.

One common way this is with an infinite loop, a block of code that is intended to go around and around executing the same commands until break stops it.

In these situations, the command true can be used to return an exit status of zero. The command false can be used in the opposite situation too, as it returns a nonzero exit status. If you write

```bash
while true
do
  ...
done
```

the while loop will be executed before, because true always returns a zero exit status.

Because false always returns a nonzero exit status, the loop

```bash
until false
do
  ...
done
```

will also execute forever.

The break command is therefore used to exit from these sorts of infinite loops, usually when an error condition or the end of processing is detected:

```bash
while true
do
  cmd=$(getcmd)

  if [ "$cmd" = quit ];
    break
  else
    processcmd "$cmd"
  fi
done
```

the while loop will continue to execute the getcmd and processcmd programs until cmd is equal to quit. At that point, the break command will be executed, causing the loop to be exited.

If the break command is used in the form

```bash
break 
```

The innermost loops are immediately exited, so in

```bash
for file
do
  ...
  while [ "$count" -lt 10 ]
  do
    ...
    if [ -n "$error" ]
    then
      break 2
  fi
  fi
  done
```

both the while and the for loops will be exited if error is nonnull.

# Skipping the Remaining Commands in a Loop

The continue command is similar to break, only it doesn't cause the loop to be exited, just the remaining commands in the current iteration of the loop to be skipped. The program moves immediately to the next iteration of the loop and continues as normal. Like the break, an optional number can follow the continue, so

`continue n`

causes the commands in the innermost n loops to be skipped, after which execution of the program continues as normal.

```bash
for file
do
  if [ ! -e "$file" ]
  then
    echo "$file not found!"
    continue
  fi

  #
  # Process the file
  #
  ...
done
done
```

Each value of file is checked to make sure that the file exists. If it doesn't, a message is printed, and further processing of the file within the for loop is skipped. Execution continues with the next value in the list.

The preceding example is equivalent to writing

```bash
for file
do
  if [ ! -e "$file" ]
  then
    echo "$file not found!"
  else
    #
    # Process the file
    #
    ...
  fi
done
```

# I/O Redirection on a Loop

You can perform I/O redirection on a loop. Input redirected into the loop applies to all commands that read from standard input. Output redirected from the loop applies to commands that write to standard output.

```bash
$ for i in 1 2 3 4
do
> echo $i
> done > loopout
$ cat loopout
1
2
3
4
$
```

Individual statements can override block redirection, just as any other statements in your shell can explicitly redirect from a source or send output to a destination.

To force input or output to come or go to the terminal, utilize /dev/tty, which always refers to your terminal, whether you're on a Mac, Linux, or Unix system.

In the following loop, all is redirected to the file `output` except the `echo` command's output, which is explicitly redirected to the terminal:

```bash
for file
do
  echo "Processing file $file" > /dev/tty
done > output
```

You can also redirect standard error output from a loop, simply by tacking on a 2> `file` after the done:

```bash
while [ "$endofdata" -ne TRUE ]
do
  ...
done 2> errors
```

Here output from all commands in the loop writing to standard error will be redirected to the `file`.

A variation of the `2> file 1&2` format is commonly used to ensure that error messages go to the terminal even when a script might have its output redirected into a file or pipe:

```bash
echo "Error: no file $file" 1&2
```

By default, echo sends its output to standard output (file descriptor 1), while file descriptor 2 remains standard error and is not redirected on file redirection or pipe. The notation above means that the error message from `echo` should have its `file #1` output redirected to `file #2`, which is, standard. You can test this with code like this:

```bash
for i in "once"
do
  echo "Standard output message"
  echo "Error message" 1>&2
done > /dev/null
```

# Piping Data into and out of a Loop

A command's output can be piped into a loop (by having the commands prior to the loop end with a pipe symbol), and the output from a loop can be piped into another command too. Here's an example of the output from a `for` command piped into wc:

```bash
$ for i in 1 2 3 4
do
done | wc
```
