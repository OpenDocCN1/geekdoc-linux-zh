To sort the file instead by the third colon-delimited file (which contains what is known as your user ID), you would want an arithmetic sort, with the third field (-k3), and specifying the colon character as the field delimiter (-t :):

```bash
$ sort -k3 -t : /etc/passwd
root:x:0:The Super User:/usr/bin/ksh
cron::1:1:Cron Daemon for periodic tasks::/
bin::3:3:The system of files::/
uucp::5:5:/usr/spool/uucpublic:/lib/uucp/uucico
as*:6:6:The Owner of Assignable Devices::/
sysinfo*:10:10:Access to System Information::/usr/bin/sh
george*:75:75:/users/george:/usr/bin/sh
steve*:203:300:/users/steve:/usr/bin/ksh
mail*:301::/usr/mail::
```

Here we've bolded the third field of each class so that you can easily verify that the file sorted correctly by user ID.

# Other Options

Other options to sort enable you to skip characters in a field, specify the field to end the sort on, merged input files, and in “dictionary order” (only letters, numbers, and spaces are used for the comparison). For more details on these options, look under sort in your Unix User's Manual.

# uniq

The uniq command is used when you need to find or remove duplicate lines in a file.
The basic format of the command is

```bash
uniq in_file out_file
```

In this format, uniq copies in_file to out_file, removing any duplicate lines in the process. uniq's definition of duplicated lines is consecutive lines that match exactly.

If out_file is not specified, the results will be written to standard output. If in_file is also not specified, uniq acts as a filter and reads its input from standard input.

Here are some examples to see how uniq works. Suppose that you have a file called names with contents as:

```bash
$ cat names
Charlie
Tony
Emanuel
Lucy
Ralph
Fred
Tony
$
```

You can see that the name Tony appears twice in the file. You can use uniq to remove duplicate entries:

```bash
$ uniq names # Print unique lines
Charlie
Tony
Emanuel
Lucy
Ralph
Fred
Tony
$
```

Oops! Tony still appears twice in the preceding output because the multiple occurrences are not consecutive in the file, and uniq's definition of duplicate is not satisfied. To remedy this situation, sort is often used to get the duplicate lines adjacent to each other, as mentioned earlier in the chapter. The result of the sort is then run through uniq:

```bash
$ sort names | uniq
Charlie
Emanuel
Fred
Lucy
Ralph
Tony
$
```

The sort moves the two Tony lines together, and then uniq filters out the duplicate line (but recall that sort with the -u option performs precisely this function).

# # -d Option

Frequently, you'll be interested in finding the duplicate entries in a file. The -d option to uniq can be used for such purposes: it tells uniq only the duplicated lines to out_file (or standard output). Lines are written just once, no matter how many occurrences there are.

```bash
$ sort names | uniq -d # List duplicate lines
Tony
$
```

As a more practical example, let's return to our /etc/passwd file. This file contains information about each user on the system. It's conceivable that over the course of adding and removing users from this file that perhaps the same username has been inadvertently entered more than once. You can easily find such duplicate entries by first sorting /etc/passwd and piping the results into uniq -d as done previously:

```bash
$ sort /etc/passwd | uniq -d      # Find duplicate entries in /etc/passwd
$
```

There are no duplicate line /etc/passwd entries. But you really want to find duplicate entries for the username, so you only want to look at the first field from each line (recall that the leading characters of each line of /etc/passwd up to the colon are the username). This can't be done directly through an option to uniq, but you could now use cut to extract the username from each line of the password file before sending it to uniq.

```bash
$ sort /etc/passwd | cut -f1 -d : | uniq -d      # Find duplicates
cem
```

It turns out that there are multiple entries in /etc/passwd for cem and harry. If you wanted more information on the particular entries, you could now grep them from /etc/passwd:

```bash
$ grep 'cem' /etc/passwd
20:cem*:91:91:/users/cem
166:cem*:91:91:/users/cem
$ grep 'harry' /etc/passwd
29:harry*:103:103:Harry Johnson:/users/harry
79:harry*:90:90:Harry Johnson:/users/harry
$
```

The -n option is used to find out the duplicate entries occur. In the case of cem, there are entries on lines 20 and 166; and harry's case, the two entries are on lines 29 and 79.

# Other Options

The -c option to uniq adds an occurrence count, which can be tremendously useful in scripts:

```bash
$ sort names | uniq -c      # Count line occurrences
1 Charlie
1 Emanuel
1 Fred
1 Lucy
1 Ralph
2 Tony
```

One common use of uniq -c is to figure out the most common words in a data file, easily done with a command like:

```bash
tr '[A-Z]' '[a-z]' datafile | sort | uniq -c | head
```

Two other options that we don't have space to describe more fully let tell uniq to ignore leading characters/fields on a line. For more information, consult the man page for your particular implementation of uniq with the command man uniq.

# Command Files

A shell program can be typed directly, as

```bash
$ who | wc -1
```

or it can be typed into a file. For example, suppose you need to find out logged-in users throughout the day.
You can put any commands inside a file, make the file executable, and execute its contents simply by typing its name to the shell. It's that simple and powerful, and everything you've learned about working on the command line therefore also applies to shell scripts too.
The standard shell mechanisms as I/O redirection and pipes can be used on your own programs as well:

```bash
$ nu > tally
$ cat tally
8
```

Suppose you're working on a proposal called sys.caps and the following command sequence is needed every time you print your proposal:

```bash
tbl sys.caps | nroff -mm -Tlp | lp
```

# Chapter 4 And We Go

Oops! Forgot to mention one thing. Before you execute a script from the command line, you must change the file's permission to make it executable. This is done with the change mode command, chmod. The + indicates that you want to make the file(s) that follow executable. The shell requires that a file be both readable and executable by you before you invoke it.

```bash
$ ls -1 nu
-rw-r--r-- 1 steve steve    12 Jul 10 11:42 nu
$ chmod addx nu
Make it executable
$ ls -1 nu
-rwxrxr-x 1 steve steve    12 Jul 10 11:42 nu
$ 
```

Now you've made it executable, try it again:

```bash
$ nu
8
$
```

> Warning
If you fix the permission issue and still get an error "Command not found," try adding ./ before the command, ./nu to ensure the shell looks in the current directory as well as the usual system locations. To fix it long term, add . to the end of your PATH (typically within your .profile file).
