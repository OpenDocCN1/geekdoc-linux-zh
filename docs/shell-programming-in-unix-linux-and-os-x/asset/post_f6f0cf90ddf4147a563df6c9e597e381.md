
To copy a file from another directory to your current location in the file system and give the file same name, use the handy ".." shortcut for the current directory:

```
$ pwd
/users/steve/misc
$ cp ../programs/collect
$
```

The preceding command copies the file from the directory ../programs into the current directory (/users/steve/misc).

# Moving Files Between Directories

You recall the mv command can be used to rename a file. Indeed, there is no "rename" command in Unix. However, when the two arguments reference different directories, the file is actually moved from the first directory to the second.

To demonstrate, from the home directory to the documents directory:

```
$ cd documents
$
```

Suppose that you now decide that the file contained in the memos directory is really a proposal so you want to move it from the memos directory into the proposals directory. The following would do the trick:

```
$ mv memos/plan proposals/plan
$
```

As with the cp command, if the source file and destination file have the same name, only the name of the destination directory need be supplied, so there's an easier way to move this file:

Also like the cp command, a group of files can be simultaneously moved into a directory by simply listing all files to be moved before the name of the destination directory:

```
$ pwd
/users/steve/programs
$ mv wb collect mon ../misc
$
```

This would move the three files wb, collect, and mon into the directory misc.

You can also use the mv command to change the name of a directory, as it happens. For example, the following renames the programs directory to bin.

```
$ mv programs bin
$
```

# Linking Files: The ln Command

So far everything we've talked about file management has assumed that a given collection of data has one and only one filename, wherever it may be located in the file system. It turns out that Unix is more sophisticated than that and can assign multiple filenames to the same collection of data.

The main command for creating these duplicate names for a given file is the ln command.

The general form of the command is

```
ln from to
```

This links the file from to the file.

Recall the structure of steve's programs directory from Figure 1.8. In that directory, he has stored a program called wb. Suppose that he decides he'd also like to call the program writeback. The most obvious thing to do would be to simply create a copy of wb called writeback.

```
$ cp wb writeback
$
```

The drawback with this approach is that now disk space is consumed. Furthermore, if steve changes wb, he may forget to duplicate the change in writeback, resulting in two of sync copies of what he thinks is the same. Not good!

By linking the file to the new name, these problems are solved:

```
$ ln wb writeback
$
```

Now instead of two copies of the file, only one exists with two names: wb and writeback. The two files have been logically linked by the Unix system. As far as you're concerned, it appears as though you have two files. Executing ls command shows the two separately:

```
$ ls
collect
mon
wb
writeback
$
```

Where it gets interesting is you use ls -l:

```
$ ls -l
total 5
-rwxr-xr-x 1 steve 3725 358 Jun 25 13:31 collect
-rwxr-xr-x 1 steve 3725 219 Jun 25 13:31 mon
-rwxr-xr-x 1 steve 3725 89 Jun 25 13:30 wb
-rwxr-xr-x 1 steve 3725 89 Jun 25 13:30 writeback
$
```

# Working with Directories

Look closely at the second column of the output: The number shown is 1 for collect and mon and 2 for wb and writeback. This is the number of links to a file, normally 1 for directory files. Because wb and writeback are linked, however, this number is 2. You can remove either of the linked files at any time, and the other will not be removed:

```
$ rm writeback
$ ls -l
total 4
-rwxr-xr-x 1 pat 3725 358 Jun 25 13:31 collect
-rwxr-xr-x 1 pat 3725 219 Jun 25 13:31 mon
-rwxr-xr-x 1 pat 3725 89 Jun 25 13:30 wb
$
```

Note that the number of links on wb went 2 to 1 because one of its links was removed. Most often, ln is used to make a file appear in more than one directory. For example, suppose that pat wanted to access steve's wb. Instead of making a copy for himself (subject to the sync problems described previously) or including steve's programs in his PATH, he can simply link the file from his own directory:

```
$ pwd
/users/pat/bin
$ ls -l
total 4
-rwxr-xr-x 1 pat 3822 358 Jan 15 11:01
-rwxr-xr-x 1 pat 3822 504 Apr 21 18:30
$
$ ln -s /users/steve/wb wb
$ ls -l
total 5
-rwxr-xr-x 1 pat 3822 358 Jan 15 11:01
-rwxr-xr-x 1 pat 3725 89 Jun 25 13:30 wb
-rwxr-xr-x 1 pat 3822 504 Apr 21 18:30
$
```

Note that steve is listed as the owner of wb, even when viewing the contents of pat's directory. This makes sense, because there is really one copy of the file and it's owned by steve.

The only stipulation on linking files is for ordinary links the files to be linked together must reside on the same file system. If they don't, you'll get an error when you try to link them. (To delete file systems on your system, execute the df command. The first field on each line of output is the name of a file.) To create links on different file systems (or on different networked systems), you can use the -s option to the ln command. This creates a symbolic link. Symbolic links behave like regular links, except that the symbolic link points to the original file; if the original file is removed, the symbolic link no longer works.

# Chapter 1 A Quick Review of the Basics

Let's see how symbolic links work with the previous example:

```
$ rm wb
$ ls -l
total 4
-rwxr-xr-x 1 pat 3822 358 Jan 15 11:01
-rwxr-xr-x 1 pat 3822 504 Apr 21 18:30
$
$ ls -s /users/steve/wb .symwb
$ ls -1
total 5
-rwxr-xr-x 1 pat 3822 358 Jan 15 11:01
-rwxr-xr-x 1 pat 3822 15 Jul 20 15:22 symwb -> /users/steve/wb
-rwxr-xr-x 1 pat 3822 504 Apr 21 18:30
$
```

Note that pat is listed as the owner of symwb, the file type as the first character in the ls output is 1, which indicates a symbolic link. The size of the symbolic link is 15 (the file actually contains the string /users/steve/wb), but if we attempt to access the contents of the file, we are presented with the contents of file it linked to, /users/steve/wb:

```
$ wc symwb
5 9 89 symwb
$
```

The -l option to the ls command was used with the -1 option to get a detailed list of information on the file symbolic link points to:

```
$ ls -L1
total 5
-rwxr-xr-x 1 pat 3822 358 Jan 15 11:01
-rwxr-xr-x 2 steve 3725 89 Jun 25 13:30
$
```

This type of file is called dangling symbolic link and should be removed unless you have a specific reason to keep it around:

```
$ rm symwb
$ ls -l
total 4
-rwxr-xr-x 1 pat 3822 358 Jan 15 11:01
-rwxr-xr-x 1 pat 3822 504 Apr 21 18:30
$
```

Note that the number of links on wb went 2 to 1 because one of its links was removed.
