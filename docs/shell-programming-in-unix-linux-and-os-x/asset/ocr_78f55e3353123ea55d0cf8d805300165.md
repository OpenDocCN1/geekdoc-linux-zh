If the commands enclosed in the braces are all going to be on the same line, a space must
follow the left brace, a semicolon must appear after the last command. Look closely at the
statement above—{ cd bin; }for an example.

Parentheses work differently. This is the example

```
(cd bin; ls)
```

demonstrates, parentheses are useful for executing commands without affecting the current
environment.

You can also use this for other purposes like pushing a set of commands into the background:

```
$ (sort 2016data -0 2016data; plotdata 2016data) &
[1] 3421
$
```

The parentheses group the sort and plotdata commands together that they can be sent to the
background with their order of execution preserved.

Input and output can also be piped to from these constructs, and I/O can be redirected,
which makes them darn helpful to shell generators.

In the next example, a de-formatted nroff command—ls 2—is effectively prepended the
beginning of the file memo before being sent to nroff for processing.

```
$ echo "ls 2"; cat memo; | nroff -Tlp | lp1
```

In the command sequence

```
$ progl1; prog2; prog3; 2> errors
```

all messages to standard error by the three programs are collected into the errors.

As a final example, return to the waitfor program from Chapter 8. As you'll recall, the\program periodically checks for a user logging into the system. You will recall that it would be
nice if the program could somehow automatically “send itself” to the background. Now you
know how to do it: Simply enclose the until loop and the commands that follow within
parentheses and send the entire grouping into the background:

```
$ cat waitfor
#
# Wait until a specified user logs on -- version 4
#
```
