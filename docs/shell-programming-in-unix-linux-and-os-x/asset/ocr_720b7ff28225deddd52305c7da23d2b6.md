# set with No Arguments

If you don't give any arguments to set, you'll get an alphabetized list of all the variables that exist in the current environment, local or exported:

```
$ set
CDPATH=:/users/steve:/usr/spool
EDITOR=/bin/vi
HOME=/users/steve
IFS=

LOGNAME=steve
MAIL=/usr/spool/steve
MAILCHECK=600
PATH=/bin:/bin:/users/steve/bin:..
PHONEBOOK=/users/steve/phonebook
PS1=$
PS2=$
PWD=/users/steve/misc
SHELL=/bin/sh
TERM=xterm
MWOUT=
T=STEDT
cmd=wc
X=*
$
```

# Using set to Reassign Positional Parameters

You'll recall that there's no way to assign a new value or reassign the value of a positional parameter. Attempts to reassign $1 to 100, for example, might be logically written like this:

```
1=100
```

But it won't work. Positional parameters are set upon the shell program.

However, there's a sneaky trick: you can use set to change the value. If words are given as arguments to set on the command line, the positional parameters $1, $2, ... will be assigned to those words. The previous values stored in the positional parameters will be lost. Within a shell program, the command

```
set a b c
```

will assign a to $1, b to $2, and c to $3. $# also gets set to 3 as appropriate for the new argument count.

Here's a more involved example:

```
$ set one two three four
$ echo $1:$2:$3:$4
```
