
## Command Substitution 117

Moving further into the world of shell scripting, let's see how this works with file redirection. For example, to store the contents of a file into a variable, you can use the handy cat command:

```bash
$ namelist=$(cat names)
$ echo "$namelist"
Charlie
Emanuel
Fred
Lucy
Ralph
Tony
Tony
$
```

If you want to mail the contents of the file memo to all the people listed in the names file, you can do the following:

```bash
$ mail $(cat names) < memo
$
```

Here the replaces the cat command with its output on the command line, so it looks like:

```bash
mail Charlie Emanuel Fred Ralph Tony Tony < memo
```

Then the shell executes mail, redirecting its standard input from the file memo and passing it to the seven recipients specified.

Notice that Tony might receive the same mail twice because he is listed twice in the names file. You can remove any duplicate entries from the file by using sort with the -u option (remove duplicate lines) rather than using cat to ensure each person only receives mail:

```bash
$ mail $(sort -u names) < memo
$
```

Remember that the shell does filename substitution after it substitutes the output from commands. Enclosing the commands in double quotes prevents the shell from doing the substitution on the output.

Command substitution is often used to store the value in a shell variable. For example, if the shell variable name contains someone's name, and you want to convert every character in that variable to uppercase, you could use echo to send the variable to tr's input, perform the translation, and then assign the result back to the variable:

```bash
$ name="Ralph Kramden"
$ name=$(echo $name | tr '[a-z]' '[A-Z]')
$ echo $name
RALPH KRAMDEN
$
```

The technique of using echo in a pipeline to write data to the standard input of the subsequent command is simple but powerful, and is often used in shell programs.

The next example shows how cut can be used to extract the first character from the values stored in a variable filename:

```bash
$ filename=/users/steve/memos
$ firstchar=$(echo $filename | cut -c1)
$ echo $firstchar /
```

sed is also often used to "edit" the value stored in a variable. Here it is used to extract the first character from each line of the file by the variable file:

```bash
$ file=exec.o
$ lastchar=$(echo $file | sed 's/.*\(..)$$/1/')
$ echo $lastchar $
```

The sed command replaces all characters in parentheses on the line with the last (remember that a surrounding pattern can save it in a register in this case register 1, which is then referred as \1). The result of the sed command is stored in the variable lastchar. The quote around the sed command are important because they prevent the shell from trying to interpret the backslashes. (Question: would double quotes also have worked?)

Finally, command substitution can be nested. Suppose you want to change every occurrence of the first first character in a variable to something else. In a previous example, firstchar=$(echo $filename | cut -c1) gets the first character from filename, but how would we use this change to change every occurrence of that character in filename?
A two-step process is one way:

```bash
$ filename=/users/steve/memos
$ firstchar=$(echo $filename | cut -c1)
$ filename=$(echo $filename | tr "$firstchar" "*") translate / to^
$ echo $filename
users/steve/memos $
```

But a single, nested command substitution can perform the same operation:

```bash
$ filename=/users/steve/memos
$ filename=$(echo $filename | tr "$(echo $filename | cut -c1)" "*")
$ echo $filename
users/steve/memos $
```

If you have trouble understanding this example, compare it to the previous one: Note how the firstchar variable in the earlier example is replaced by the nested command substitution; otherwise, the two examples are the same.

## The expr Command

Although the usual shell supports built-in integer arithmetic, older shells don't have this capability. In that situation, the mathematical equation solver expr can be used instead:

```bash
$ expr 1 + 2
3
$
```

It's easy to work with, but expr isn't very good at parsing equations, so each operator and operand given must be separated by spaces to be properly understood. That explains the following:

```bash
$ expr 1+2
1+2
$
```

The usual arithmetic operators are recognized by expr: + for addition, - for subtraction, / for division, * for multiplication, and % for modulus (remainder).

```bash
$ expr 10 + 20 / 2
20
$
```

Multiplication, division, and modulus have higher precedence than addition and subtraction, as with standard mathematics. Thus, in the preceding example the division was performed before addition.

But what about this example?

```bash
$ expr 17 * 6
expr: syntax error
$
```

The shell saw and substituted the names of all the files in your directory, which expr had no idea how to interpret! In the case of multiplication especially, the expression given to expr must be quoted to keep it away from the shell's interference—but not as a single argument, in this example:

```bash
$ expr "17 * 6"
17 * 6
$
```

## Passing Arguments

Shell programs become far more useful after you learn how to process arguments passed to them. In this chapter, you'll learn how to write shell programs that take arguments. Recall the one-line program run that you wrote in Chapter 4 to run the file sys.caps through tbl, nroff, and lp:

```bash
$ cat run
tbl sys.caps | nroff -mm -Tlp | lp
$
```

Suppose that you need to run other files besides sys.caps through this same command sequence. You could make a special version of run for each such file; or, you could modify the run program so that you could specify the name of the file to be on the command line. That is, you could change run so that you could type

```bash
run new.hire
```

for example, to specify that the file new.hire is to be printed through this command sequence, or
run sys.caps

to specify the file sys.caps.
Whenever you execute a shell program, the shell automatically stores the first argument in the special variable 1, the second argument in the variable 2, (For convenience's sake, from now we'll refer to these as $1, $2, and so on, even though the $ is actually part of the variable reference, not the variable name). These special variables—more formally known as positional parameters because they're based on the position of the value in the command line—are assigned after the shell has done its normal command-line processing (that is, I/O redirection, variable substitution, filename substitution, and so on).

To modify the run program to accept the name of the file as an argument, all you do to do the program is change the reference to the file sys.caps so that it instead references the first argument typed on the command line:

```bash
$ cat run
tbl $1 | nroff -mm -Tlp | lp
$
```
