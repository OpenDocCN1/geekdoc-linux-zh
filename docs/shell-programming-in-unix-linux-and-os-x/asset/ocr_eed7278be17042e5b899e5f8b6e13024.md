# The IFS Variable

There is a special variable called IFS, which stands for internal field separator. The shell uses the value of this variable when parsing input the read command, output from command substitution (the back-quoting mechanism), and when performing variable substitution. Succinctly, IFS contains a set of characters that are used as whitespace separators. If it's typed on the command line, the shell treats it like a normal whitespace character (that is, as a word delimiter).

See what it sets to:

```
$ echo "IFS"
$
$ echo "IFS" | od -b
0000000 040 011 012 012
0000004
$
```

Well, wasn't that very illuminating! To determine the actual characters stored in it, pipe the output from echo to the od (octal dump) command with the -b (byte display) option:

The first column of numbers shown is the relative offset from the start of the input. The following numbers are the octal equivalents of the characters read by od. The first such number is 040, which is the ASCII value of the space character. It is followed by 011, the tab character, and then by 012, the newline character. The next character is another newline which was added by echo. This set of characters for IFS should come as no surprise; they're the whitespace characters we talked about throughout the book.

Where this gets interesting is the fact that you can change IFS to any character or set desired. This can be particularly useful when you want to parse a line of data whose fields aren't delimited by the normal whitespace characters.

For example, note the shell normally strips leading whitespace from the beginning of any line that you read with the read command. Change IFS to a newline before the read is executed, however, and it will preserve the leading whitespace (because the shell doesn't consider it as a field delimiter):

```
$ read line
Here's a line Try it the "old" way
$ echo "$line"
Here's a line
```
