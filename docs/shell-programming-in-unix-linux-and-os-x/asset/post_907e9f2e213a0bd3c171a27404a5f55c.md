# Integer Types

Both the Korn and Bash support an integer data type. You can declare variables to be integers by using the typeset command with the -i option

```
typeset -i variables
```

where variables are any valid shell variable names. Initial values can also be assigned to the variables at the time they are declared:

```
typeset -i signal=1
```

# Integer Arithmetic

The main benefit: arithmetic performed on integer variables with the ((...)) construct is faster than on non-integer values.

However an integer variable cannot be assigned anything but an integer value or integer expression. If you attempt to assign a non-integer to it, the message `bad number` is printed by the shell:

```
$ typeset -i i
$ i=hello
ksh: bad number
```

Bash simply ignores any strings that don't contain numeric values and generates an error for anything that contains numbers and other characters:

```
$ typeset -i i
$ i=hello
$ echo $i
0
$ i=1hello
bash: ihello: value too great for base (error token is "hello")
$ i=10+15
$ echo $i
25
$
```

The preceding example also shows that integer-valued expressions can be assigned to an integer variable, without even using the ((...)) construct. This holds true for shells.

# Numbers in Different Bases

Both Korn and Bash allow you to perform arithmetic in different numeric bases. To write a number in a different base with these shells, you use the notation

```
base#number
```

For example, to express the value 100 in base 8 (octal) you can write

```
8#100
```

You can write constants in different bases anywhere an integer value is permitted. To assign octal100 to the integer variable i, you can write

```
typeset -i i=8#100
```

Note that with the Korn shell the base of the first value assigned to an integer variable sets the default base of all subsequent uses of that variable. In other words, if the first value assign to the integer i is an octal, each time you reference the value of i on the command line, the Korn displays it as an octal number using the notation 8#value.

```
$ typeset -i i=8#100
$ echo $i
8#100
$ i=50
```

```
$ echo $$
8#62
$ (( i = 16#a5 + 16#120 ))
$ echo $$
8#705
```

Because the first value assigned to i is an octal number (8#100), all further references to i will also be in octal. When the base 10 value of 50 is next assigned to i and then i is subsequently displayed, we get the value 8#62, which is the octal equivalent in base 10.

There's a subtlety in the example above: while the display of i is set to octal, the default numeric value for bases assigned to the variable remains decimal unless specified. In other words, i=5 was not equal to i#50 even though the shell knew i was referred to as base 8.

In the preceding example, (( )) is used to add the two hexadecimal values a5 and 120. The result is then displayed, again in octal. We admit, that fairly obscure and not likely something you'll encounter in day-to-day shell programming or interactive use!

Bash uses both the base#number syntax for arbitrary bases and the C language syntax for—octal numbers are preceded by 0 (zero), and hexadecimal numbers are preceded by 0x:

```
$ typeset -i i=0100
$ echo $$
64
$ i=0x80
$ echo $$
128
$ i=2#1101001
$ echo $$
105
$ (( i = 16#a5 + 16#120 ))
$ echo $$
45
```

Unlike the Korn shell, Bash doesn't keep track of the variable's numeric base; integer are displayed as decimal values. You can always use printf to print integers in octal or hexadecimal format.

As you see, with Bash and the Korn it is easy to work with different bases which makes it possible to write functions that perform base conversion.

# The alias Command

An alias is a shorthand notation provided by the shell to allow customization. The shell keeps a list of aliases that is searched when a command is entered before any substitution occurs. If the first word of a command line is an alias, it is replaced by the text of the alias. An alias is defined using the alias command. The format is

```
alias name=string
```

where name is the name of alias, and string is any string of characters. For example, alias='ls -l' assigns ls -l to the alias. Even better, you can type arguments after the alias the command line, as in

```
ls *.c
```

which transforms into this alias substitution has performed:

```
ls -l *.c
```

The shell performs its normal command processing when the alias is set and used, so quoting can be tricky. No matter the current directory, the alias prints your working directory inside a variable called PWD:

```
$ cd /users/steve/letters
$ echo $PWD
/users/steve/letters
$
```

You can create an alias that gives you the name of your current directory by using the PWD variable and one of the parameter substitution constructs:

```
alias dir="echo ${PWD*/}"
```

This seems reasonable, but let's see how this works in practice:

| | |
| :--- | :--- |
| $ alias dir="echo ${PWD*/}" | Define alias |
| $ pwd | Where are we? |
| /users/steve | Execute alias |
| $ dir | |
| steve | |
| $ cd letters | Change directory |
| $ dir | Execute the alias |
| steve | |
| $ cd /users/spool | One more try |
| $ dir | |
| steve | |

The alias alias prints steve. That's because we weren't careful about quotes when we defined the alias. Recalling that the shell performs parameter substitution inside double quotes, the problem is that the shell evaluated ${PWD*/} at the time the alias was defined. This means that the alias was essentially defined as if we'd typed in following:

```
$ alias dir="echo steve"
```

No wonder it didn't work! The solution is use single rather than double quotes when defining the alias to defer substitution until the alias is executed:

```
$ alias dir='echo ${PWD*/}'
$ pwd
/users/steve
$ dir
letters
$ cd /users/spool
$ dir
spool
$
```

If an alias ends with a space, the word after the alias is also checked for alias substitution. For For example:

```
alias nohup="/bin/nohup "
```

causes the shell to perform alias checking on the string after replacing nohup with /bin/nohup.

Quoting a command or prefacing it with a backslash prevents alias substitution. For example:

```
$ 'ls'
ksh: ls: command not found
$
```

The format

```
alias name
```

causes the value of the alias name to be listed, and the alias command without arguments causes all aliases to be listed.

# Arrays

The following aliases are automatically defined when the Korn shell starts up:

```
autoload='typeset -fu'
functions='typeset -f'
history='fc -l'
integer=typeset -i
local=typeset
nohup='nohup'
suspend=kill -STOP $$
```

Note from the preceding example that r is actually an alias for the fc command with the -e option, and history is an alias for fc -l. By comparison, Bash doesn't automatically define any aliases by default.

# Removing Aliases

The alias command is used to remove aliases from the alias list. The format is unalias name which removes the alias name and unalias -a removes all aliases.

If you develop a set of alias definitions that you like to use during your login sessions, you might want to define them inside your ENV file so that they will always be available for you to use, as they don't otherwise migrate to subshells.

# Arrays

Both Korn and Bash provide a limited array capability. Bash arrays may contain an unlimited number of elements (subject to memory limits); Korn shells are limited to 4096 elements. Array indexing in both shells starts at zero. An array element is accessed with a subscript, which is an integer-valued expression enclosed within square brackets. You don't declare the maximum size of a shell array either, you simply assign values to elements as needed. The values that you can assign are the same as for ordinary variables:

```
$ arr[0]=hello
$ arr[1]=some text
$ arr[2]=users/steve/memos
$
```
