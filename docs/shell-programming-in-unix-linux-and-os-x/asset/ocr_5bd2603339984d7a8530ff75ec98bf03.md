This is not atypical for the Unix system; there is almost always more than one approach to solving a particular problem. In the case we just saw, either approach is satisfactory (that is, tr or sed), but tr is probably a better choice because it is a much smaller program and likely to execute faster.

Table 3.4 summarizes how to use tr for translating and deleting characters. Bear in mind that tr works only on single characters. So if you need translate anything longer than a single character (say all occurrences of unix to UNIX), you have to use a different program, like so, instead.

# Table 3.4 tr Examples

| Command | Description |
| --- | --- |
| tr 'X' | Translate all capital X's to small x's. |
| tr '()' '{}' | Translate all open parentheses to open braces, all parentheses to closed braces |
| tr '[a-z]' '[A-Z]' | Translate lowercase letters to uppercase |
| tr '[A-Z]' '[N-M]' | Translate uppercase letters A-M to N, and N-Z to A-M, respectively |
| tr ' ' | Translate all tabs (character in first pair of quotes) to spaces |
| tr -s ' ' | Translate multiple spaces to spaces |
| tr -d '\14' | Delete all feedform (octal 14) characters |
| tr -d '[0-9]' | Delete all digits |

# grep

grep allows you to search one or more files for a pattern you specify. The general format of the command is

```
grep pattern files
```

Every line of file that contains pattern is displayed at the terminal. If more than one file is specified to grep, each line is also preceded by the name of the file, enabling you to identify the particular file that the pattern was found in.

Let's say that you want to find every occurrence of the word shell in the file ed.cmd.

```
$ grep shell ed.cmd
files, and is independent of the shell.
to the shell, just type in a q.
$
```

This output indicates that two lines in the file ed.cmd contain the word shell.
