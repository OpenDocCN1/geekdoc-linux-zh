value substituted, of course), =, and julio. test then evaluates whether the first argument is identical to the third argument and returns a zero status if it is and a nonzero exit status if it is not.

The exit status returned by test is tested by the if statement. If it's zero, the commands between then and fi are executed; in this case, the echo command is executed. If the exit status is nonzero, the echo command is skipped.

As demonstrated above, it's good programming to enclose shell variables that are arguments to test inside a pair of double quotes (to allow variable substitution). This ensures that test sees the argument even if its value is null. For example, consider the following

```
$ name=
$ test $name = julio
sh: test: argument expected
$ 
```

Because name was null, only two arguments were passed to test: = and julio—because the shell substituted the value of name before parsing the command line into arguments. In fact, after $name was substituted by the shell, it was as if you typed the following:

```
test = julio
```

When test executed, it saw only two arguments (see Figure 7.1) and therefore issued the error message.
