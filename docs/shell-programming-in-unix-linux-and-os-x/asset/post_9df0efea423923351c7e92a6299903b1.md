# Saving Matched Characters: \(..\)

It is possible to reference the characters matched against a regular expression by enclosing them inside backslashed parentheses. These captured characters are stored in pre-defined variables in the regular expression parser called *registers*, which are numbered 1 through 9.

This gets a bit confusing, so take this slowly!
As a first example, the regular expression

\(.\)
matches the first character on the line, whatever it is, and stores it into register 1.

To retrieve the characters stored in a particular register, the construct \*n* is used, where *n* is a digit from 1 to 9. So the regular expression

\(.\.\1
initially matches the first character on the line and stores it in register 1, then matches-ever is stored in register 1, as specified by the \1. The net effect of this regular expression is to match the first characters on a line if *they are both the same character*. Tricky, eh?

The regular expression
\(.).*\1$
matches all lines in which the first character on the line (.) is the same as the last character on the line (\1$). The . * matches all characters in-between.

# Chapter 3 Tools of the Trade

Let's break this one down. Remember ^ is the beginning of line and $ the end of line. The simplified pattern is then ..* which is the first character of the line (the first .) followed by .* for the rest of the line. Add the \( \ notation to push that first character into register 1 and \ to refer to that character, and it should make sense to you.

Successive occurrences of the (...) construct assigned to successive registers. When the following regular expression is used to match some text

```bash
\(...\)/\(...\)
```

the first three characters on the line will be stored into register 1, and the next three characters into register 2. If you appended \2\1 to the pattern, you will match a 12-character string in which characters 1-3 matched characters 10-12, and which 4-6 matched characters 7-9.

When using the substitute command in ed, a register can also be referenced as part of the replacement string, which is where this can be really powerful:

```bash
$ phonebook
```

The names and the phone numbers are separated from each other in the phonebook file by a single tab character. The regular expression

```bash
\(.*\) \*.*
```

says to match all the characters up to the first tab (that the character sequence .* between the \( and \) and assign them to register 1, and to match all the characters that follow the tab character and assign them to register 2. The replacement string

```bash
2 \1
```

specifies the contents of register 2, followed by a space, followed by the contents of register 1. When ed applies substitute command to the line of file:

\(.\) matches everything to the tab (Alice Cheabba) and stores it into register 1, and everything after the tab (Alice Cheabba) stores it into register 2. The tab itself is lost because it's not surrounded by parentheses in the regex. Then ed substitutes the characters that were matched (the entire line) with the contents of register 2, followed by a space, followed by the contents of register 1.

As you can see, regular expressions are powerful tools that enable you to match and manipulate complex patterns, albeit with a slight tendency to look like your keyboard at times! # cut

This teaches you about a useful command as cut. This command comes in handy when you need to extract (that, "cut out") various fields from a data file or the output of a command. The general format of the cut command is

```bash
cut -chars file
```

where chars specifies characters (by position) you want to extract from each line of file. This can consist of a single number, in -5 to extract the fifth character from each line of input; a comma-separated list of numbers, in -c1,13,50 to extract characters 1, 13, and 50; or a dash-separated range of numbers, in -c20-50 to extract characters 20 through 50, inclusive. To extract characters to the end of the line, you can omit the number of range

```bash
cut -c5- data
```

extracts characters 5 through the end of the line from each line of data and writes the result to standard output.

If file is not specified, cut reads its input from standard input, meaning that you can use cut as a filter in the pipeline. Let's take another look at the output from the who command:

```bash
$ who
root console Feb 24 08:54
steve tty02 Feb 24 12:55
george tty08 Feb 24 09:15
dawn tty10 Feb 24 15:55
$
```

# cut 65

As shown, four people are logged in. Suppose that you just want to know the names of the logged-in users and don't care about what terminals they are on or when they logged in. You can use the cut command to cut out just the usernames from the who command's output:

```bash
$ who | cut -c1-8
root
steve
george
dawn
$
```

Extract the first 8 characters

The -c1-8 option to cut specifies characters 1 through 8 are to be extracted from line of input and written to standard output.

The following shows how you can track a sort to the end of the preceding pipeline to get a sorted list of the logged-in users:

```bash
$ who | cut -c1-8 | sort
dawn
george
root
steve
$
```

Note, this is our first-command pipe. Once you get the concept of output connected to subsequent input, pipes of three, four or more commands are logical and easy to assemble.

If you wanted to see which terminals were currently used or pseudo virtual terminals were in, you could cut out just the tty field from the who output:

```bash
$ who | cut -c10-16
console
tty02
tty08
tty10
$
```

How did you know that who displays the terminal identification in character positions 10 through 16? Simple! You executed the who command at your terminal and counted out the appropriate positions.

You can use cut to extract as many different characters from a line as you want. Here, cut is used to display the username and login of all logged-in users:

```bash
$ who | cut -c1-8,18-
root
Feb 24 08:54
steve
Feb 24 12:55
george
Feb 24 09:15
dawn
Feb 24 15:55
$
```
