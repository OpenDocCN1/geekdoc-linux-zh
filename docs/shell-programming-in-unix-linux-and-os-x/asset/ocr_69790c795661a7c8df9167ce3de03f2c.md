When login begins execution, it displays the string Password: at the terminal and waits for you to type your password. After you have typed it and pressed Enter (you won't see any output as type, for security reasons), login then proceeds to verify your login name and password against the corresponding entry in the file /etc/passwd. This file contains an entry for each user account that specifies, other things, the login name, home directory, and program to start up when user logs in. The last bit of information (the login shell) is stored as the last colon of each line. If nothing follows the colon, the standard shell /bin/sh is assumed by default.

If you log through a terminal, the data handshake might involve a program like ssh on the server, and if you're opening a window on your Unix computer, it will just let you in without having to type in your password!

But back to the password file. The following three lines show typical lines from /etc/passwd for three users of the system: sue, pat, and bob:

```
sue*:15:47:/users/sue
pat*:99:7:/users/pat:/bin/khsh
bob*:13:100:/users/data/data/bin_data_entry
```

After login validates an encrypted version of the password you typed in the encrypted password for the specified account stored in /etc/shadow, it checks for the name of the login program to execute. In many cases, this will be /bin/sh, /bin/ksh, or /bin/bash. In other cases, it may be a special custom-designed program or /bin/nologin for accounts that don't include interactive access (common for file ownership management). The idea underlying all of them is that you can set a login account to automatically run any program whatsoever whenever someone logs to the system. The shell is the program most often selected because of its general utility, but it's not the only game in town.
