# Chapter 14 Interactive and Nonstandard Shell Features

It turns out that all the major interactive shells allow you to specify which shell—actually, which program of the thousands included in a Unix or Linux distribution—should be used to run the file. If the first two characters on the first line of a file are #$, the remainder of the line specifies an interpreter for the file. So

```
#!/bin/ksh
```

specifies the Korn shell and use

```
#!/bin/bash
```

specifies Bash. If you use constructs or notational conventions specific to one shell, you can use this feature to force that shell to run your programs, avoiding compatibility problems.

Since you can specify any program you want, a Perl program beginning

```
#!/usr/bin/perl
```

forces the shell to invoke /usr/bin/perl to interpret the lines within the file.

You have to use this feature with caution, because many programs, such as Perl, do not reside in a standard place on every Unix system. Also, this is not specified by the POSIX standard, though it's found in every modern shell and is even implemented at the operating system level on many Unix versions.

Most commonly you'll see system programs use this notation to ensure that Bourne Shell is used regardless of the user's login shell by beginning with

```
#!/bin/sh
```

# The ENV File

When you start the shell, the first thing it does is to look in your environment for a variable ENV. If it finds and it's non-null, the ENV will be executed, like the .profile is executed when logging in. The ENV file contains commands to set up the shell's environment. Throughout this chapter, we'll mention many things that you may want to put into this file.

If you decide to have an ENV file, you should set and export the ENV variable inside your

```
$ cat .profile

export ENV=$HOME/.alias
...
$
```

Note the shortcut in above: Instead of assigning the variable a value, then calling export, it turns out you can do both on the same line for efficiency.
