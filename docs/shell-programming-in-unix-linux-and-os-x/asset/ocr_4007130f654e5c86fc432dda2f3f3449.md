Uh oh, that's not good. What happened?

Whenever you type the name of a program, a shell searches a list of directories until it
inds the requested program. When the program is started up. This list of directories
to search for user commands is stored in a shell variable PATH and it is automatically set
when you log on. To see what it is set to any point, use echo:

```
$ echo PATH
/usr/bin/
$
```

Chances that your PATH has a somewhat different value, but don't worry about that—
it's just variations in system configuration. The important thing to notice is that directories
are separated by a colon (:) and the shell searches them in order, left to right, to find
requested commands or programs.

In the preceding example, directories are listed: /bin, /usr/bin, and , (which, you)
recall, for the current directory). Whenever you type the name of a program, the
shell searches the directories listed in PATH until it finds a matching executable file. Type in
rolo and the shell first looks for /bin/rolo, then /usr/bin/rolo, finally, /rolo in the
Current directory. As soon as it finds a match it executes, but if the shell doesn't find
rolo any of the directories specified in PATH, it issues a "not found" error.

To have the current directory searched anything else, put at the start of PATH:
.:bin:/usr/bin
