# The gettops Command 181

Don't get too anxious if this seems really confusing. The fact is, it is all very complicated, so let's look at an example you can see how gettops works. Suppose for a script you're writing you want to use gettops to recognize the options -a, -i, and -r. Your gettops call look like this:

```
getopts "a" option
```

Here the first argument--air—specifies the three acceptable command flags (-a, -i, and -r) and option is the name of the variable that gettops will use to store each matching value encountered.

The gettops command allows options to be clustered or grouped together the command line. This is done by following a single minus sign with more than one consecutive option. For example, our foo command can be executed like this:

```
foo -a -r
```

or like this:

```
foo -ari
```

using this simple grouping feature.

But wait, gettops is far more powerful than what we've explained so far! For example, it can also handle the case where an option requires an additional argument. For example, the new -t option to be the waitfor command requires an argument too.

To properly parse arguments subsequent to a user-specified option, gettops requires that the command be invoked with least one space separating the option from the argument. In this instance, options cannot be grouped together.

To indicate gettops that an option has a required argument, add a colon character after the option letter on the gettops command line. so the waitfor program, which allows both -m and -t options, the latter of which has a required additional argument, should call gettops

```
getopts mt: option
```

If gettops doesn't find an argument after an option that requires one, it stores a question mark inside the variable and outputs an error message to standard error. Otherwise, it stores the character in the variable and the user specified argument inside a special variable called OPTARG.
