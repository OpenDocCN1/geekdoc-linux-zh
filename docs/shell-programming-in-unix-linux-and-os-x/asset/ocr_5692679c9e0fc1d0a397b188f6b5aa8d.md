# The read Command

Note that if the file already exists, the echo command prompts for the yes/no response is executed. The read command that follows causes the shell to wait for the user to type a response. What shows is that the shell doesn't prompt the user when it's waiting for data; it's up to the programmer to add a useful prompt to the program.

The data that is stored in the variable answer and is then tested against the characters yes to determine whether the copy process should proceed. The quotes around the reference to the variable answer in the test

```
"$answer" != yes
```

are necessary in the case just uses the Enter key without typing any data. In that case, the shell should store a null value in answer and, without the quotes, test would issue an error message.

Also note the use of the semicolon to make the then statements onto the same line as if the This is a common shell programmer trick, as mentioned in the previous chapter.

# Special echo Escape Command

A slight annoyance with mycp that after the echo command is run, the response typed by the user appears on the next line. This happens because the echo command automatically adds a terminating character after the last argument.

Furthermore, this can be suppressed if the last two characters to echo are the escape characters \c. This tells echo to omit the newline after displaying the last argument. If you changed the echo command in mycp to read like this:

```
echo "$0 already exists; overwrite (yes/no)? \c"
```

The user's input will be typed right after the message on the same line. Bear in mind that the \c is interpreted by echo and not by the shell, meaning it must be quoted so that the backlash makes it echo.

Note

Some Linux and Mac OS systems have shells that don't interpret these echo escape characters, so the object should be shown as newfile.txt already exists; overwrite (yes/no)? \c

If testing reveals that your shell works like that, change those specific invocations of echo to the separate segment /bin/echo and they'll work fine. All your other echo statements can remain as regular echo commands, of course.
