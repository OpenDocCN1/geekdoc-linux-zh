When a command is sent to the background, the Unix system automatically displays two numbers. The first is called the command's job number and the second process ID, PID. In the preceding example, 1 is the job number and 1258 the process ID. The job number is used as a shortcut for referring to a specific background job by shell commands. (You'll learn more about this in Chapter 14.) The process uniquely identifies the command that you sent to the background and can be used to obtain status information about the command. This is done with the processor status—ps—command.

# # ps Command

The ps command gives you information about the processes running on the system. Without any options, it prints the status of processes. If you type in ps at your terminal, you'll get a few lines describing the processes you have:

```
$ ps
PID TTY         TIME CMD
13463 pts/16    00:00:09 bash
19880 pts/16    00:00:00 ps
$
```

The ps command (typically; your system might vary) prints out four columns of information: PID, the ID; TTY, the name of the process that was run; TIME, the amount of time in minutes and seconds that process used; and CMD, the name of the process. (The bash process in the preceding example is the shell that was started when we logged in, and it's used 9 seconds of compute time.) Until the command is finished, it shows up in the output of the ps command as a running process, so process 19880 in the preceding example is the ps command itself.

When used with the -f option, ps prints out more information about your processes, including the parent process ID (PPID), the time the process started (STIME), and the command arguments:

```
$ ps -f
UID     PID     PPID    STIME TTY         CMD
steve   13463   13355   00:12 pts/16    00:00:09 bash
steve   19884   13463   00:13 pts/16    00:00:00 ps -f
$
```
