
# Stopped Jobs and the fg and bg Commands

If you are running a job in the foreground (without an &) and you want to suspend it, you can press Ctrl+z. The job stops executing, and the shell prints the message

```
$ n + Stopped (SIGTSTP) sequence
```

The stopped job becomes the current job. To have continue executing, using the fg or bg command: the fg command causes the current job to resume execution in the foreground, and bg causes the current job to resume execution in the background.

You can also specify a job number, the first few characters of the pipeline, a +, -, or % preceded by a % to specify any job to the fg and bg commands. These commands also print out the command sequence to remind you what is being brought to the foreground or sent to the background.

```
$ fg memo photo
Ctrl+z
[1] + Stopped (SIGTSTP) traff memo | photo
$ bg
[1] traff | photo &
$
``````

The preceding sequence is one of the most used with job control: stopping a running foreground job and sending it to the background.

If a job running in the background tries to read from the terminal, it is stopped, and the message

```
$ - Stopped (SIGTTIN) sequence
```

is printed. Then it can be brought to the foreground with the fg command to enter the data required. After entering the input, the job can be stopped again (with Ctrl+z) and moved to the background to continue running.

Output from a background job normally goes directly to the terminal, which can be confusing if you're doing something else at the time. There's a fix, though: the command

```
stty tostop
```

causes any background job that attempts to write to the terminal to be stopped and the message

```
$ - Stopped (SIGTTOU) sequence
```

to be printed. (Bash generates slightly different messages than the ones shown here, but the functionality is identical)

The following shows how job control might be used:

```
$ stty tostop
$ rundb Start up data base program
??? find green red Find green and red objects This may take a while
Ctrl+z
```

# Other Features of the cd Command

The cd command seems straightforward, but it has a few tricks up its proverbial sleeve. For example, the argument means "the previous directory" as a convenient shortcut:

```
$ pwd
/usr/src/cmd
$ cd /usr/local/uucp
$ pwd
/usr/local/uucp
$ cd - cd to previous directory
/usr/src/cmd
$ cd - cd prints name of new directory
$ cd -
/usr/local/uucp
$
```

As you can see, cd - cd can be used to toggle between two directories with no effort at all.

The Korn shell’s cd command has the capability to substitute portions of the current directory’s path. (Neither Bash nor the POSIX standard shell support this feature)

The format is

```
cd old new
```

cd attempts to replace the first occurrence of the string old in the current directory's path
with the string new.

# Tilde Substitution

If a word on the command line begins with the tilde ~ character, the shell performs the follow-instutions: If the tilde is the only character in the word or if the character following ttilde is a slash /, the value of the HOME variable is substituted:

```
$ echo
/users/pat
$ grep Korn ~/shell/chapter9/ksh
```

# Order of Search

It's worthwhile understanding the search order the shell uses:

1. The shell first checks the alias list.
2. If it's not a reserved word, the shell proceeds to:
3. The shell checks the function list.
4. If it's not a built-in, the shell continues.
5. Finally, the shell searches the PATH.
6. If the command still isn't found, a “command not found” error is issued.

# Commands

The general format of a command typed to the shell is
command arguments

where command is the name of the program to be executed, and arguments are its arguments. The command name and arguments are delimited by whitespace characters, normally the space, tab, and newline characters (changing the variable IFS affects this).
Multiple commands can be typed on the same line if they're separated by semicolons;.

Every command that gets executed returns a number known as the exit status; zero is used to indicate success, and non-zero indicates a failure.

The pipe symbol | can be used to connect the standard output from one command to the standard input of another, as in

```
who | wc -1
```
