
## The printf Command

printf doesn't automatically add a newline character to the end of its output like echo but does understand the same escape sequences (refer to Table 9.1 earlier in this chapter), so adding \n to the end of the format string causes the newline character sequence to be printed and the command to appear on the next line as expected.

Although the preceding is a simple example that could also be handled by echo, it is used to illustrate how the conversion specification (%d) is interpreted by printf: the format string is scanned and outputs each character in the string until its the percent sign. Then it reads the d and replaces the %d with the next argument given to printf, which must be an integer. If that argument (10) is set to standard output, printf continues scanning the format string, sees the \n, and outputs a newline.

Table 9.2 summarizes different format specification characters. 

| Character | Use for Printing |
|---|---|
| %d | Integers |
| %u | Unsigned integers |
| %o | Octal integers |
| %x | Hexadecimal integers, using a-f |
| %X | Hexadecimal integers, using A-F |
| %c | Single characters |
| %s | Literal strings |
| %b | Strings containing backslash escape characters |
| %% | Percent signs |

### Table 9.2 printf Format Specification Characters

The first conversion specification characters are all used for displaying integers. %d displays signed integers, and %u displays unsigned integers; %u can also be used to display the positive representation of a negative number. By default, integers displayed as octal or hexadecimal do not have a leading 0 or 0x, but you can fix that if needed, as we will show later in this section.

Strings are printed using %s or %b. %b is used to print strings literally, without any processing of backslash escape characters; %b is used to force interpretation of the backslash escape characters in the string argument.

Here are a few printf examples to clarify:

```
$ printf "The octal value for %d is %o\n" 20 20
The octal value for 20 is 24
$ printf "The hexadecimal value for %d is %x\n" 30 30
The hexadecimal value for 30 is 1e
```

The general format of a conversion specification is

```
%[flags][.precision]type
```

The type is the conversion specification from Table 9.2. As you can see, only the percent sign and type are required; the other parameters are called modifiers and are optional. Valid flags are -, +, #, and the space character

- - left-just the value being printed, which will make more sense when we discuss the width modifier.
- + causes printf to precede integers with a or - sign (by default, negative integers are printed with a sign)
- # causes printf to precede octal and hexadecimal integers with 0x or 0X, specified as %#x or %#X.
- The space character printf to precede positive integers with a space and negative integers with a - for alignment purposes.

## The printf Command

As you can see, using + or space as the flag causes a column of positive and negative numbers to align nicely.

The width modifier is a positive number that specifies the minimum field width for printing the argument. The argument is right-justified within this field unless the flag is used:

```
$ printf "%02d\n" string1 string2
string1 string2
$ printf "-%2d-%02d\n" string1 string2
string1 string2
$ printf "%5d%%5d\n" 1 10 100
$ printf "-%5d%%5d\n" -1 -10 -100
$ printf "%-5d%%5d\n" 1 10 100
10 100
$
```

The width can be useful for lining up columns of text or numbers (Tip: for numbers and leading 0, %x and %X characters are counted as part of the width). The width specifies a minimum size for the field, but if the width of an argument exceeds width, it can overflow or not output at all. An easy way to test:

```
printf "-%15.15s\n" "this is more than 15 chars"
```

The .precision is a positive number that specifies the minimum number of digits to display for %d, %u, %o, and %X. This results in zero-padding on the left of the value:

```
$ printf "%5d.%4X\n" 10 27
00010
```

For strings, the .precision modifier specifies the maximum number of characters to print. If the string is longer than precision, it is truncated on the right. It's important to realize as you line up multiple lines, if any individual value is wider than the field:

```
$ printf "%6s\n" "Ann Smith"
Ann Sm
```

Width can be combined with .precision to specify both a width and zero padding (for numbers) or truncation (for strings):

```
$ printf "%10.5x%%5.4d\n" 1 10 100
00001
$ printf "%9.5s\n" abcdef
abcde
$ printf ":%9-9.5s\n" abcdef
:abcde
$
```

Finally, in all cases where this is not enough, if * is used in place of a number for width or precision, the two arguments preceding the value to be printed must be numbers and used as the width or precision, respectively. If * is used in place of both, two integer arguments must precede the value and are used for the width and precision:

```
$ printf("%.*s\n" 12 10 "test two"
test one
$ printf("%12s10s\n" "test one" "test two"
test one
```

As you can see, the two prints in this example produce the same result. In the first printf, 12 is the width for the first string, 10 as the width for the second string, and 2 as the precision for the second string. In the second printf, these numbers are specified as part of the format specification. While the format specification for printf is unquestionably complex, its power and capabilities to output exactly what you want from your own shell programs are helpful command worth studying more closely so you know how to use it as you develop more sophisticated programs.

## Your Environment

When you log on to your system, whether it's a shiny new Mac OS X Terminal app, a clean Linux install, or a Unix server in the back office, you're effectively given your own copy of the shell program. This login shell maintains what's known as your environment—a configuration that is distinct from other users on the system. This environment is maintained from the moment you log on until the moment you log off. In this chapter you'll learn about the shell environment and how it relates to writing and running programs.

## Local Variables

Type the following program called vartest into your computer:

```
$ cat vartest
echo $x:
$
```

vartest consists of a single echo command that displays the value of the variable x surrounded by colons.

Assign any value you want to the variable x from your terminal:

```
$ x=100
```

Question: What do you think will be displayed when vartest is now executed? Answer:

```
$ vartest
::
$
```

vartest doesn't know about the value of x. Therefore, its value is the default: null. the variable x that was assigned the value 100 in the login shell is known as a local variable. The reason why it has this name will become clear shortly.
