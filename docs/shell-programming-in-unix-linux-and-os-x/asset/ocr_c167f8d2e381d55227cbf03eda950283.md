else

```
echo "Couldn't find $name"
```

fi

You can use a complex sequence of commands on either or both the left- or right-hand side of these constructs. If the exit status is tested is that of the last command in the pipeline; thus

```
who | grep "$name" > /dev/null | echo "$name's not logged on"
```

causes execution of the echo if the grep fails

The && || can also be used on the same command line:

```
who | grep "$name" > /dev/null && echo "$name's not logged on" \
|| echo "$name is logged on"
```

(Recall that when echo is used at the end of the line it line continuation to the shell.
The first echo gets executed if the grep succeeds, the second fails if)

These constructs are also often used in commands, as demonstrated in this snippet for a system program (don't worry if you don't understand every command invoked):

```
if validates "$sys" $timeok
then
sendmail "$user@$sys" < $message
```

```
fi
```

If validates returns an exit status of zero, timeok is executed and its exit status is tested for it. If the status is zero, then sendmail is executed. If validates returns a nonzero status, however, timeok is not executed, and the failed exit status is tested by the if, and sendmail ends up not being executed.

The use of the && operator in the preceding case is a logical AND; both programs must return an exit status of zero for the sendmail program to be executed. In fact, you could have the above if some conditional

```
validates "$sys" $timeok sendmail "$user@$sys" < $message
```

By comparison, the || is used in an if, the exit status is a logical OR:

```
if endmonth || specialrequest
then
sendreports
```

```
fi
```

If endmonth returns an exit status, sendreports is executed; otherwise specialrequest is executed and if its exit status is zero, sendreports is executed. The net effect is that sendreports is executed if either endmonth or specialrequest returns an exit status of zero.
