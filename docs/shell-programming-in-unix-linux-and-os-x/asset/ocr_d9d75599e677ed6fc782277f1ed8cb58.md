# The test Command

Be warned that both of the preceding operators expect an argument to follow, so get into the
habit of enclosing the argument within double quotes.

```
$ nullvar=
$ nonnullvar=abc
$ test -n "$nullvar"
$ echo $?
```

Does nullvar have nonzero length?

```
1
$ test -n "$nonnullvar"
$ echo $?
```

No
And what about nonnull?

```
0
$ test -z "$nonnullvar"
$ echo $?
```

Yes
Does nullvar have zero length?

```
1
$ test -z "$nonnullvar"
$ echo $?
```

Yes
And nonnull?
No

Note that test can also be picky about its arguments. For example, if the shell variable symbol
contains an equals sign, look at what happens if you try to test it for test length:
$ echo $symbol

```
$ test -z "$symbol"
sh: test: argument expected
$
```

The operator has higher precedence than the -z operator, so test attempts to process the
command as an equality test, and expects an argument to follow the =. To avoid this sort of
problem, many shell programmers write their test commands as

test X"symbol" = X

which will be true if symbol is null, and if it's not. The X in front of symbol prevents test
from interpreting the characters stored in symbol as an operator.

# An Alternate Format for test

The test command is used so often by shell programmers that an alternative format of the
command is available and can make your programs a lot ne: [. This improves the
readability of if statements and other conditional tests throughout your shell scripts.

You'll recall the general format of the test command is

```
test expression
```

This can also be expressed in the alternative format as

```
[ expression ]
```
