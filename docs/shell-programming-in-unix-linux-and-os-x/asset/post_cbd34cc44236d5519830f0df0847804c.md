
In Chapter 7, you'll learn how to test the action prior to taking it so the program can determine whether more than one matching entry is found. The program might want to alert the user that more than one match has been found, for example, rather than just blindly delete multiple entries. (This can be very helpful, because most implementations of grep will match everything if an empty string is passed as the parameter, which would effectively delete the phonebook entry. Not good.)

Incidentally, note that `sed` could also have been used to delete the matching entry. In such a case, the grep could be replaced with

```bash
sed "$1/d" phonebook > /tmp/phonebook
```

to achieve the result. The double quotes are needed around the sed command's argument to ensure that the value of $1 is substituted, while at the same time ensuring that the shell doesn't see a command line

```
sed /Stromboli Pizza/d phonebook > /tmp/phonebook
```

and pass three arguments to sed rather than two.

## ${n}

If you supply more than nine arguments to a program, you cannot access the tenth and greater arguments with $10, $11, and so on. If you try to access the tenth argument by writing

```
$10
```

the shell actually substitutes the value of $1 followed by a 0. Instead, the format ${n} must be used. To directly access argument 10, you must write

```bash
${10}
```

in your program, and so on for arguments 11, 12, and so on.

## The shift Command

The shift command allows you to effectively left-shift your positional parameters. If you execute the command

```bash
shift
```

whatever was previously stored inside $2 will be assigned to $1, whatever was previously stored in $3 will be assigned to $2, and so on. The old value of $1 will be irretrievably lost.

When this command is executed, $# (the number of arguments variable) is automatically decremented by one:

```bash
cat tshift
echo $#
shift
echo $#
# Program to test the shift
```

```bash
shift
echo $*
shift
echo $*
shift
echo $*
shift
echo $*
$ shift a b c d e
5 a b c d e
4 b c d e
3 c d e
2 d e
e
0
$
```

If you try to shift when there are no variables to shift (that is, when ## already equals zero), you'll get an error message from the shell (the error will vary from one shell to the next):

`prog: shift: bad number`

where prog is the name of the program that executed.

You can shift more than one "place" at once by writing a count immediately after shift, as in

```bash
shift 3
```

This command has the same effect as performing separate shifts. The shift command is useful when processing a variable number of arguments. You'll see it to use when you learn about loops in Chapter 8. For now, just remember that positional parameters can be moved along the chain using shift.

## Decisions

This chapter introduces the conditional statement, a construct present in almost every programming language: `if`. It enables you to test a condition and then change the flow of program execution based on the result of the test. The general format of the `if` command is

```bash
if condition
then
    command
    ...
fi
```

where `command` is executed and its exit status is tested. If the exit status is zero, the commands that follow `then` and `fi` are executed; otherwise, they are skipped.

## Exit Status

To understand how conditional tests work, it's important to know what Unix calls the exit status. Whenever any program completes, it returns an exit status to the shell. This status is a numeric value that indicates whether the program ran successfully or failed. By convention, an exit status of zero indicates that program succeeded, and non-zero indicates it failed, with different values indicating kinds of failures.

Failures can be caused by invalid arguments passed to the program or by an error detected by the program. For example, the `cp` command returns a non-zero (fail) exit status if copy fails (for example, if it can't find the source file or create the destination file), or if arguments aren't correctly specified (for example, the wrong number of arguments or more than two arguments and the last one isn't a directory).

What do we mean by non-zero? Simply, any integer value that isn't 0. Most command man pages list possible exit status values, so possible error conditions for `cp` command could be:

- 1 for file not found
- 2 for file readable
- 3 for destination not found
- 4 for destination not writable
- 5 for general error copying the file
- 0 for success

In the case of grep, an exit status of zero (success) is returned if it finds the specified pattern in at least one of the files specified; a non-zero value is returned if it can't find the pattern or if a different error occurs, like failure to open a specified file. In a pipeline, the exit status reflects the last command in the pipe. grep exit status is used by the shell as the exit status for the whole pipeline. In this case, an exit status of zero (success) means that fred was found in who's output (that is, fred was logged on the time that this command was executed).

## The $ Variable

The shell variable $ is automatically set to the exit status of the last command executed. Naturally, you can use `echo` to display its value at the terminal.

```bash
$ cp phonebook phone2
$ echo $?
0 "succeeded"
$ cp nosuch
cp: cannot access nosuch
$ echo $?
2 "failed"
$ who
# See who's logged on
root console Jul 8 10:06
wilma tty02 Jul 8 12:36
barney tty04 Jul 8 14:57
betty tty15 Jul 8 15:03
$ who | grep barney
barney tty04 Jul 8 14:57
$ echo $?
0 Print exit status of last command (grep)
"succeeded"
$ who | grep fred
$ echo $?
1 "failed"
$ echo $?
0
$
```

Note that the numeric result of a "failure" for some commands can vary from one version of Unix to the next, but success is always signified by a zero exit status.

Let's write a shell program called `on` that tells us whether a specified user is logged on to the system. The name of the user to check will be passed to the program `on` on the command line. If the user is logged on, we'll print a message to that effect; otherwise we'll say nothing. Here is the program:

```bash
$ cat
#
# determine if someone is logged on
#
user="$1"

if who | grep "$user"
then
    echo "$user is logged on"
fi
```

This first argument typed on the command line is stored in the shell variable `user`. Then the `if` command executes the pipeline

```bash
who | grep "$user"
```

and tests the exit status returned by grep. If the exit status is zero (success), grep found who's output. In that case, the `echo` command that follows is executed. If the exit status is non-zero (failure), the specified user is not logged on, and the `echo` command is skipped.

The `echo` command is indented from the left margin for aesthetic reasons only. In this case, just a single command is enclosed between the `then` and `fi`. When more commands are included, and when the nesting gets deeper, indentation can have a significant impact on the program's readability. Later examples help illustrate this point.

Here are some sample uses of `on`:

| User | Terminal | Date | Time |

| barney | tty03 | Jul 8 | 12:38 |
| fred | tty04 | Jul 8 | 13:40 |
| joanne | tty07 | Jul 8 | 09:35 |
| tony | tty19 | Jul 8 | 08:30 |
| lulu | tty23 | Jul 8 | 09:55 |

```bash
$ on tony tty19 Jul 8 08:30
tony is logged on
```
