
## ${parameter:=value}

This version is similar to the previous, but if parameter is null only is value used, but it is also assigned to parameter as well (note the = in the construct). You can assign values to positional parameters this way, however, so that means that parameter cannot be a number.

A typical use of this construct would be in testing to see whether an exported variable has been set and, if not, assigning it a default value:

```bash
$ PHONEBOOK=$HOME/phonebook
```

This says that if PHONEBOOK already has an assigned value, leave it alone, otherwise set it to $HOME/phonebook.

Note that the following example could not stand as a command because the substitution is performed the shell would attempt to execute the result:

```bash
$ PHONEBOOK=
$ ${PHONEBOOK:=$HOME/phonebook}
sh: /users/steve/phonebook: cannot execute
$
```

To use this construct as a stand-alone command, the null command can be employed. If you write

```bash
: ${PHONEBOOK:=$HOME/phonebook}
```

the shell still does the substitution (it evaluates the rest of the command line), yet executes nothing (the null command).

```bash
$ PHONEBOOK=
$ ${PHONEBOOK:=$HOME/phonebook
$ echo $PHONEBOOK
/users/steve/phonebook
$ ${PHONEBOOK:=$foobar
$ echo $PHONEBOOK
/users/steve/phonebook
$
```

## ${parameter?value}

If parameter is not null, the shell substitutes its value; otherwise, the shell writes value to standard error and exits (don't worry—it's done from your login). If value is omitted, the shell writes the default message

```
parameter: null or not set
```

The term pattern is used here because the shell allows you to use the same matching characters that it uses in filename substitution and case:

- * to match zero or more characters
- [...] to match any single character
- [...] to match any single character from the specified set
- [!] to match any single character not in the specified set

## Parameter Substitution

When you write the construct

${variable%pattern}

the shell looks inside *variable* to see whether it ends with the specified *pattern*. If it does, the contents of *variable* are used, with the shortest matching pattern removed from the right. If you use the construct

${variable%%pattern}

the shell once again inside *variable* to see whether it ends with *pattern*. This time, however, it removes the longest matching pattern from the right. % and %% behave the same way.

Finally, the construct

${variable#pattern} works like #, except longest occurrence of *pattern* is removed from the left. Remember that in all cases, no changes are made to the pattern itself. You are affecting only what gets on the command line. Also, remember that the pattern matches are anchored. In the case of % and %% constructs, the variable must *end* with the pattern; in the case of # and ## constructs, the variable must *begin* with it. Here are some simple examples to show how these constructs work:

```bash
$ var=test
$ echo $var
$ echo ${var%*}      Remove smallest match from right
$ echo $var
test
$ echo ${var%%*}    Remove longest match from right
$ echo $var
test
$ echo ${var#?}      Remove smallest match from left
$ echo $var
test
$ echo ${var#*}      Remove smallest match from left
$ echo $var
test
$ echo ${var##}     Remove longest match from left
```

```bash
$ echo ${var#test}    Remove test from left
test
$ echo ${var#teas}      No match
test
```

There are many practical uses for these constructs. For example, the following tests see whether the filename stored inside the variable ends in the two characters .o:

```bash
if [ "${file.*o}" = "$file" ]; then
  # file ends in .o
  ...
```

Another example, here's a shell program that works just like the Unix system's basename command:

```bash
$ cat lookup
echo ${1##*/}
```

The program displays its argument with all the characters up to the last / removed:

```bash
$ basename /usr/spool/uucpublic
uucpublic
$ basename $HOME
steve
$ basename memos
memos
```

But wait, there are more constructs:

## ${#variable}

Need to figure out how many characters are stored in a variable? That's just what this construct offers:

```bash
$ text='The shell'
$ echo ${#text}
9
```

## The $0 Variable

Whenever you execute a shell program, the shell automatically stores the name of the program inside the special variable $0. This can be helpful in a number of situations, including when you have a program accessible through different command names through hard links in the file system. It lets programmatically figure out which one was executed.

It's more commonly used for displaying error messages because it is based on the actual program file name, not whatever hardcoded in the program itself. If the name of the program is referenced by $0, renaming the program will update the message without requiring the program to be:

```bash
$ cat lookup
#
# Look someone up in the phone book
#

if [ "$0" -ne 1 ]; then
  echo "Incorrect number of arguments"
  echo "Usage: $0 name"
  exit 1
fi

name=$1
grep "$name" PHONEBOOK

if [ $? -ne 0 ]; then
  echo "I couldn't find $name in the phone book"
fi
```

```bash
$ PHONEBOOK=$HOME/phonebook
$ export PHONEBOOK
$ lookup Teri
Teri Zak          201-393-6000
$ lookup Teri Zak
Incorrect number of arguments
Usage: lookup name
$ mv lookup Teri      Rename it
$ lookup Teri Zak  See what happens now
Incorrect number of arguments
Usage: lookup name
$
```

Some Unix systems will automatically make $0 a full pathname including directories, which can lead to some clunky error and usage messages. In that instance, use $(basename $0) or utilize the trick from earlier to chop out the path name:

```bash
echo ${0##*/}
```

## The set Command

The set command also serves two purposes: it turns on trace mode and reassigns positional parameters.

## The -x Option

Earlier, in Chapter 7 we briefly looked at using -x to debug problems in a shell. The set command lets you turn on and off trace mode for specific portions of the program. Within a program,

```bash
set -x
```

enables trace mode, which means all executed commands will be printed to standard error. The traced commands are preceded by plus signs.

```bash
set -x
+ ls
+ wc
```

You can turn off trace mode at any time by executing:

```bash
set +x
```

## set with No Arguments

If you don't give any arguments to set, you'll get an alphabetized list of all the variables that exist in the current environment, local or exported:

```
$ set

LOGNAME=steve
```

## Using set to Reassign Positional Parameters

You'll recall that there's no way to assign a new value or reassign the value of a positional parameter. Attempts to reassign $1 to 100, for example, might be logically written like this:

```
1=100
```

But it won't work. Positional parameters are set upon the shell program.

However, there's a sneaky trick: you can use set to change the value. If words are given as arguments to set on the command line, the positional parameters $1, $2, ... will be assigned to those words. The previous values stored in the positional parameters will be lost. Within a shell program, the command

```bash
set a b c
```

will assign a to $1, b to $2, and c to $3. $# also gets set to 3 as appropriate for the new argument count.

Here's a more involved example:

```bash
$ set one two three four
$ echo $1:$2:$3:$4
```
