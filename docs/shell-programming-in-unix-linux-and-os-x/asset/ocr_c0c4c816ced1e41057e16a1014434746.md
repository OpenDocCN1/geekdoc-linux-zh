```
$ IFS=""
> "
$ read line
  Here's a line
  Set it to just a newline
  Try it again
$ echo "$line"
  Here's a line
  Leading spaces preserved
$
```

To change IFS to a newline, an open quote was typed, followed by pressing the Enter key, by the closing quote on the next line. No additional characters can be typed inside those quotes because they'll be stored IFS and then used by the shell.

Now let's change IFS to something more visible, the color:

```
$ IFS:
$ read x y z
123:345:678
$ echo $x
123
$ echo $z
678
$ list="one:two:three"
$ for x in $list; do echo $x; done
one
two
three
$ var=a:b:c
$ echo "$var"
a:b:c
$
```

Because IFS was changed to a colon, when the line was read, she divided it into three words: 123, 345, and 678, which were then stored into the three variables x, y, and z. In the next-to-last example, the shell used IFS when substituting the value of list in the for loop. The last example demonstrates that the shell doesn't use IFS when performing variable assignment.

Changing IFS is often done in conjunction with the set command:

```
$ line="Micro Logic Corp.::Hackensack, NJ 174:07602"
$ IFS=
$ set $line
$ echo $#
  How many parameters were set?
3
$ for field; do echo $field; done
Micro Logic Corp.
Box 174
Hackensack, NJ 07602
$
```
