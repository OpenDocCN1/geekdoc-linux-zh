
## The trap Command

General Format: trap commands signals

This command tells the shell to execute commands whenever it receives one of the signals listed in signals. The listed signals can be specified by name or number.

trap with no arguments presents a list of the current trap assignments.

If the first argument is the null string, as in

```
trap signals
```

the signals in signals are ignored when received by the shell.

If the format

```
trap signals
```

is used, processing of each signal in signals is reset to the default action.

### Examples

```
trap "echo hangup >> $ERRFILE; exit" HUP    Log message and exit on hangup
trap "rm $TMPFILE; exit" 1 2 15             remove $TMPFILE on signals 1, 2, or 15
trap "" 2                             Ignore interrupts
trap 2                               Reset default processing of interrupts
```

Table A.12 lists values that can be specified in the signal list.

| Signal # | Signal Name | Generated for |
|---|---|---|
| 0 | EXIT | Exit from the shell |
| 1 | HUP | Hangup |
| 2 | INT | Interrupt (for example, Delete key, Ctrl+c) |
| 3 | QUIT | Quit |
| 6 | ABRT | Abort |
| 9 | KILL | Kill |
| 14 | ALRM | Alarm timeout |
| 15 | TERM | Software termination signal (sent by kill by default) |

The shell scans when the trap command is encountered and again when one of the listed signals is received. This means, for example, when the shell encounters the command

```
trap "echo $count lines processed >> $LOGFILE; exit" HUP INT TERM
```

it substitutes the value of count at that point, and not when one of the signals is received. You can get the value of count substituted when one of the signals is received if you instead enclose the commands in single quotes:

```
trap 'echo $count lines processed >> $LOGFILE; exit' HUP INT TERM
```

## The true Command

General Format: true

This command returns a zero exit status.

## The type Command

General Format: type commands

This command prints information about the indicated commands.

### Examples

```
$ type troff echo
troff is /usr/bin/troff
echo is a shell builtin
$
```

## The umask Command

General Format: umask mask

umask sets the default file creation mask to mask. Files that are subsequently created and with this mask to determine the mode of the file.

umask with no arguments presents the current mask. The -s option says to produce symbolic output.

### Examples

```
$ umask          Print current mask
0002            No write to others
$ umask 022     No write to group either
$
```

## The unalias Command

General Format: unalias names

The aliases names are removed from the alias list. The -a option says to remove all aliases.

## The unset Command

General Format: *unset names*

This causes the shell to erase definitions of the variables or functions listed in names. Read-only variables cannot be unset. The -v option to unset specifies that a variable name follows, whereas the -f option specifies a function name. If neither option is used, it is assumed that variable name(s) follow.

### Example

```
unset dblist files    Remove definitions of variables dblist files
```

## The until Command

General Format:

```
until command;
do
    command
    command
..
done
```

command, is executed and its exit status tested. If it is nonzero, it is executed enclosed between the do and done are executed. Then command, is executed again and its status tested. If it is nonzero, the commands between the do and done are once executed. Execution of command, and subsequent execution of the commands between the do and done continues until command, returns a zero exit status, at which point the loop is terminated. Execution then continues with the command that follows the done.

Because command, gets evaluated immediately on entry into the loop, the commands between the do and done may never be executed if the test returns a zero exit the first time.

### Example

```
# sleep for 60 seconds until jack logs on
until while | grep jack > /dev/null
do
    sleep 60
done
echo jack has logged in
```

The preceding loop continues until the grep returns a zero exit status (that is, finds jack in who's output). At that point, the loop is terminated, and the echo command that follows is executed.

## The wait Command

General Format: wait job

This command causes the shell to suspend its execution until the process identified as job finishes executing. Job can be a process ID or a job_id. If job is not supplied, the shell waits for all processes to finish executing. If more than one process id is listed, wait wait for all to complete.

wait is useful for waiting for processes to have been sent to the background for execution.

### Example

```
sort large_file > sorted_file & sort in the background
wait Continue processing
Now wait for sort to finish
plotdata sorted_file
```

The variable $! can be used to obtain the process ID of the last process sent to the background.

## The while Command

General Format:

```
while command_c
do
command
command
..
```

command, is executed and its status tested. If it is zero, the commands enclosed between the do and done are executed. Then command, is executed again and its status tested. If it is nonzero, the commands between the do and done are once executed. Execution of command, and subsequent execution of the commands between the do and done continues until command, returns a zero exit status, at which point the loop is terminated. Execution then continues with the command that follows the done.

Because command, gets evaluated immediately on entry into the loop, the commands between the do and done may never be executed if the test returns a zero exit the first time.

### Example

```
# sleep for 60 seconds until jack logs on
until while | grep jack > /dev/null
do
    sleep 60
done
echo jack has logged in
```
