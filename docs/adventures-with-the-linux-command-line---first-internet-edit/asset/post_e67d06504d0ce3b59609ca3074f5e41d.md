
# Indentation Settings For Scripts

For our purposes, we will use method 2 and add the following lines to our sh.vim file to set tabs to indent 2 spaces. This is a popular setting specified in some shell script coding standards.

```vim
setlocal tabstop=2
setlocal shiftwidth=2
setlocal expandtab
setlocal softtabstop=2
setlocal autindent
setlocal smartindent
```

In addition to the tabs, we also included the autindent and smartindent settings, which we write blocks of code.

After adding the indentation settings to our sh.vim file, we'll add more lines to our shell script (type this in to see how it behaves):

```bash
# /bin/bash

# This is a shell script to demonstrate features in vim.
# It doesn't really do anything, it just shows what we can do.

# Constants
A=1
B=2

if [ "$A" == "$B" ]; then
  echo "This shows how smartindent works.\n  echo "This shows how autindent works.\n  echo "A and B match."
else
  echo "A and B do not match."
fi

afunction() {
  cmd1
  cmd2
}

if [ -e file ]]; then
  cmd1
  cmd2
fi
```

As we type these additional lines into our script, we notice that vim can now automatically provide indentation as needed. The autindent option causes vim to repeat the previous line's indent when the smartindent option provides indentation for certain program structures like the function and if statements. This saves a lot of time while coding and ensures our code stays nice and neat.

If we find others editing an existing script with an indentation scheme differing from our current settings, vim can convert the file. This is done by typing:

```vim
:retab
```

The file will have its tabs adjusted to match our current indentation style.

# Power Moves

As we learned in TLCL, vim has lots of movement commands we can use to quickly navigate around our documents. These commands can be employed in many useful ways.

Here is a list of the common movement commands. Some of this review, some is new.

- h Move left (also left-arrow)
- l Move right (also right-arrow)
- j Move down (also down-arrow)
- k Move up (also up-arrow)
- 0 First character of the line (also the Home key)
- First non-whitespace character on the line
- $ Last character on the line (also the End key)
- f(char) Move right to the next occurrence of char on the current
- t(char) Move right till (i.e., just) the next occurrence of char on the line
- r Repeat last f or t command
- g Go to last line. If a count is specified, go to that line.
- w Move forward (word) to beginning of next word
- b Move backward (word) to beginning of previous word
- e Move forward to end of word
- ) Move forward to beginning of next sentence
- ( Move forward to beginning of next paragraph
- { Move backward to beginning of previous paragraph

Remember, each of these commands can be preceded by a count of how many times the command is to performed.

# Operators

Movement commands are often used in conjunction with operators. The movement command determines how much of the text operator affects. Here is a list of the most commonly used operators:

- c Change (i.e., delete then insert)
- d Delete/cut
- y Yank (i.e., copy)
- t Toggle case
- g Make lowercase
- g Make uppercase
- q Format text (a topic we'll get to shortly)
- ? ROT13 encoding (for obfuscating text)
- > Shift (i.e., indent) right
- < Shift left

We can use visual mode to easily demonstrate the movement commands. Move the cursor to the beginning of line 3 of our script and type:

# Text Object Selection

In addition to the traditional vi movement commands, vim adds a related feature called *text object selection*. These commands only work in conjunction with operators. commands are:

- Select entire (all) text object.
- Select interior (in) of text object.

The text objects are:

- Word
- Sentence
- Paragraph
- Tag block (such as `<a>...</a>` used in HTML)
- { enclosed block
  { enclosed block (b can also be used)
  { enclosed block (B can also be used)
- "quoted string"
- 'quoted string'

The way this works is very interesting. If we place our cursor on a word for example, and type:

caw

(short for "change all word\ vim the entire word, deletes it, and switches to insert mode. Text objects work with visual mode too. Try this: move to line 11 and place the cursor inside the quoted string and:

vi"

The interior of the quoted string will be-selected. If we instead type:

va"

the entire string including the quotes is selected.

# Text Formatting

Let's say we wanted to add a license header to the beginning of our script. This would consist of a comment block near the top of the file that includes the text of the copyright notice.

We'll move to line 3 of our script and add the text, but before we start, let's tell vim how long the lines of text to be. First we'll ask vim what the current setting is:

```vim
:set tw=75
```

Vim will respond:

```text
textwidth=0
```

"tw" is short for text, the length of lines setting. A value of zero means that vim is not enforcing a limit on line length. Let's set textwidth to another value:

```vim
:set tw=75
```

Vim will now wrap lines (at word boundaries) when the length of a line exceeds the value.

# Formatting Paragraphs

Normally, we wouldn't want to set a text width while writing code (though keeping line length below 80 characters is a good practice), but for that it will be useful.

So let's add our text. Type this in:

```bash
# This program is free software: you can redistribute it and/or modify it
# under the terms of the GNU General Public License as published by the
# Free Software Foundation, either version 3 of the License, or (at your
# option) any later version.
```

```bash
# This program is distributed in the hope that it will be useful,
# WITHOUT ANY WARRANTY; without even the implied warranty of
# MERCHANTABILITY OR FITNESS FOR A PARTICULAR PURPOSE. See the Vim General
# Public License at <http://www.vim.org/licenses/> for more details.
```

Notice the magic of vim as we type. Each time the length of the line reaches the text width, vim starts a new line including the comment symbol. The firstly is set for shell scripting, understands certain things about shell syntax and tries to help. Very handy.

Now let's say we were not happy with the length of of these lines, or that we have edited the text in that some of the lines are either too long or too short to maintain our well-formatted text. Wouldn't be great if we could reformat our comment block? Well, we can. Very easily, in fact.

To demonstrate, let's change the text width to 65 characters:

```vim
:set tw=65
```

Now place the cursor inside the comment block and type:

ggip

(meaning "format in paragraph") and watch what happens. Presto, the block is reformatted to the new text! A little later, we will show how to reduce this four key sequence down to a single key.
