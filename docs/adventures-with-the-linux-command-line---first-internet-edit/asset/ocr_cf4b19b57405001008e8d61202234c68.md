What's more, this list of directories might be useful to other programs, too. For example, we could have a file restoration script called restore_me that restores files from the backup server to the backup client system. If this were the case, we would then have twice as many scripts to maintain. A much better way handle this issue would be to create a configuration file to define the BACKUP_DIR constant and store it into our scripts at run time.

Here's how we could do it.

First, we would create a configuration file named back_me.cfg and place it somewhere sensible. Since the back_me_up and restore_me scripts are used on a system-wide basis (as most backup programs), we will treat them as locally installed resources. Then, we would put them in the /usr/local/sbin directory and

```
# Configuration file for the back_me_up program
BACKUP_DIR=/etc /usr/local /home/
```

While our configuration file must contain valid shell syntax, since its contents are executed by the shell, it differs from a real script in two regards. First, it does not require a shebang to which execute it, and second, the file does not need executable permissions. It only needs to be readable by the shell.

Next, we would add the following code to the back_me_up and restore_me scripts to our configuration file:

```
CONFIG_FILE=/usr/local/etc/back_me_up.cfg

if [[ -f "$CONFIG_FILE" ]]; then
    source "$CONFIG_FILE"
elelse
    echo "Cannot read configuration file!" >&2
    exit 1
fi
```
