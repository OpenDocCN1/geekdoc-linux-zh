
```
me@linux share $ cd bin
me@linux bin $ pwd
/usr/local/bin
```

Pathnames can be abbreviated as long as they are unambiguous. If we type:

```
me@linux ~ $ ls /usr/share<tab>
```

zsh will expand it into:

```
me@linux ~ $ ls /usr/local/share/
```

That can save a lot of typing! Arguments are provided for many commands. To invoke this feature, we type the command and the leading dash for an option, then hit the key:

```
me@linux ~ $ rm <-tab>
--force ignore nonexistent files, never prompt
--help display help message and exit
-i prompt before removal
-i prompt when removing many files
-i-interactive prompt under condition (defaulting to always)
--preserve-root do not treat / specially
--one-file-system stay within file systems of given as arguments
--preserve-root do not remove / (default)
--recursive -R r remove directories and their contents recursively
--verbose explain what is being done
--v output version information and exit
```

This displays a list of options for the command, and like the cd command, repeatedly pressing tab zsh to cycle through the options.

## Pathname Expansion

The shell provides several powerful additions to pathname expansion that can save steps when specifying file arguments. We can use "**" to cause recursive expansion. For example, if we wanted to list every file ending with .txt in our home directory and subdirectories, we would have to do this in bash:

```
me@linux $ find -name "*.txt" | sort
```

In zsh, we could do this:

```
me@linux ~ $ ls **/*.txt
```

and get the same result. And if that were not cool enough we can also add qualifiers to the wildcard to perform many of the tests with find command. For example:

```
me@linux ~ $ **/*.txt
```

will only display the files whose names end in .txt and symbolic links. There are many supported qualifiers and they may be combined to perform fine grained selection. Here are some examples:

| Qualifier | Description |
| :--- | :--- |
| - | Regular files | ls * (.) |
| / | Directories | ls * (/) |
| @ | Symbolic links | ls * (@) |
| * | Executable files | ls * (*) |
| F | Non-empty directories | ls * (^F) |
| ^ | Empty directories | ls * (m) |
| m | Modified n ago | ls * (m-5) |
| m-n | Modified than n days | ls * (m+5) |
| m+n | More than n days | ls * (L) |
| L | Empty (zero length) | ls * (LM+5) |
| LK-n | File smaller than n kilobytes | ls * (LK0) |

## Global Aliases

Shell provides powerful aliases. With zsh we can define an alias in the usual way, such as:

```
me@linuxbox ~ alias vi=/usr/bin/vim
```

and it will behave just as in bash. But we can also define a global alias that can be used at any position on the command line, not just at the beginning. For example we define a commonly used name as an alias:

```
me@linuxbox ~ alias -g ls='/var/log/syslog'
```

and then use it anywhere on command line:

```
me@linuxbox ~ $ ls
```

The use of an alias name is not a requirement it's just a custom to make it easier to see. We can also use global aliases to define common redirections:

```
me@linuxbox ~ $ alias -g L='| less'
```

or

```
me@linuxbox ~ $ alias -g W='| wc -l'
```

Then we can do things like this:

```
me@linuxbox ~ $ cat /var/log/syslog
```

to display the number of lines in.

## Suffix Aliases

What's more, we can define aliases to act like “open with...” by defining a suffix alias. For example we can define an alias that says all files end with “.txt” should be viewed with:

```
me@linuxbox ~ alias -s txt='less'
```

Then we just type the name of a text file and it will be opened by the application specified by the aliases:

```
me@linuxbox ~ dir-list.txt
```

How cool is that?

## Improved History Search

zsh adds a neat trick to history searching. bash (and zsh too) we can perform a reverse incremental history search by typing Ctrl-r, and each subsequent keystroke will refine the search. zsh gets one better by simply typing a few letters of the desired search string on the command line and press up-arrow. It moves back through the history to find the first match, and each time we press the up-arrow the next match is displayed.

## Environment Variable Editing

zsh provides a builtin called varied for editing shell variables. For example if we wanted to make a quick change to our PATH variable we can do this:

```
me@linuxbox ~ $ varied PATH
```

and the contents of the PATH variable appear in the command editor, so we can make a change and press Enter and the change takes effect.

## Frameworks

We have only touched a few of the features available in zsh. It has a lot. But with a large set of complexity configuring zsh to take advantage of its full potential can be daunting. Here the man page is only a table of contents to the other 10+ pages that cover various topics. Fortunately communities have sprung up to provide frameworks that supply ready-to-use configurations and add-ons for zsh. By far, the most popular of these is Oh-My-Zsh, a project led by Robby Russell.

Oh-My-Zsh is a large collection of configuration files, aliases, and themes. It offers support for tailoring zsh for many types of common tasks, particularly software development and system administration.

## Changing to Another Shell

Now that we have learned a little about the different shells available for Linux, how can we experiment with them? First we can simply enter the name of the shell from our bash prompt. This will launch the second shell as a child process of bash:

```
me@linuxbox ~ $ tsh%
```

Here we have launched tsch from the bash prompt and are presented with the default tsch prompt, a percent sign. Since we have not created any setup files for the new shell we get a few bare-bones environment. Each shell has its own configuration file(s) for interactive use as bash has .bashrc file to configure its interactive sessions.

Here is a table of configuration files:

| Shell | Configuration File |
| :--- | :--- |
| dash | ~/.profile |
| bash | ~/.bashrc |
| ksh | ~/.kshrc |
| tsch | ~/.tcrc |
| zsh | ~/.zshrc |

We need to consult the respective /usr/share/doc directory. To exit our shell we simply enter the exit command:

```
me@linuxbox ~ $ exit
```

Once we are done with experimentation, we can change the default shell from bash to zsh using chsh. For example, to change from bash to zsh we use:

```
me@linuxbox ~ $ chsh /bin/zsh own```

The name must appear in /etc/shells. That would be bad.

## Summing Up

Because of the growing popularity of Linux among Unix-like operating systems, bash has become the world’s predominant shell. It has many of the best features of earlier shells and a few tricks of its. However, if light weight and script execution is needed (for example, in embedded systems), dash is a good choice. Likewise, if working with other systems is required, ksh will provide the necessary compatibility. For the adventurous among us, the advanced interactive features of zsh can enhance our day-to-day shell experience.
