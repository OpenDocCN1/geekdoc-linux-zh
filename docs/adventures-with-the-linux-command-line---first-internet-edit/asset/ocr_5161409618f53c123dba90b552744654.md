# Pathname Expansion and Wildcards

Since pathnames in Unix-like systems can contain any character except / and NULL,
need to take special precautions during expansion.

+   # To prevent filenames beginning with `` from being interpreted
# command options, always do this:
command1./*.txt

+   # Not this:
command1!*.txt

Here is a snippet of that will prepend ./ to a pathname when needed.

```
# This will sanitize `$pathname`
[[ "$pathname" =~ [^./$S]* ]] || pathname="$pathname"
```

Unless a script must in a POSIX-compatible environment, use [[ ... ]] rather than
[ ... ] when performing conditional tests. Unlike the [ and test builtins, [[
]] is part of shell syntax, not a command. This means it can handle its internal elements
(test conditions) in a more robust fashion, as pathname expansion and word splitting do
not occur. Also, [[ ... ]] adds some additional capabilities such as ~ to perform
regular expressions tests.

# Use (( )) for Integer Arithmetic

Use (( )) in place of let or exper when performing integer arithmetic. The bash
let builtin works in a similar way as (( )) but its arguments often require careful
quoting, where exper is an external command and many times slower than the shell.

```
# Use (( )) rather than [[ ... ]] when evaluating integers
if (( i > 1 )); then
...
fi
```

```
# Perform arithmetic assignment
(( y = x * 2 ))
```
