not count the newline character at the end of each line, so we have to add them to make
the character count out the same as the real wc.

Even if we don't include a filenames on the command line for AWK to input, we can tell
AWK to read data from a file specified from within a program. Normally we don't
to do this, but there are some cases where this might be hard. For example, if we wanted
to insert one file inside another, we could use the getline function in AWK. Here's an
example that adds a header and footer to an existing body file:

```
awk '
BEGIN {
    while (getline <"header.txt" > 0) {
        print $0
    }
}
(print)
END {
    while (getline <"footer.txt" > 0) {
        print $0
    }
}' body.txt > finished_file
```

getline is quite flexible and can be used in a variety of:

# getline

In its most basic form, getline reads the next record from the current input stream. $0,
NF, NR, and FNR are set.

# getline var

Reads the next record from the current input stream and assigns its contents to the
variable var. var, NR, and FNR are set.

# getline <file

Reading a record from file. $0 and NF are set. It's important to check for errors when
reading from files. In the earlier example above, we specified a loop as follows:
while (getline <"header.txt" > 0)

As we can see, getline is reading from the file header.txt, but what does the “> 0"
mean? The answer is that, like most functions, getline returns a value. A positive value
means success, zero means means EOF (end of file), and a negative value means some other
file-related problem, such as file not found has occurred. If we did not check the return
value, we might end up with an infinite loop.
