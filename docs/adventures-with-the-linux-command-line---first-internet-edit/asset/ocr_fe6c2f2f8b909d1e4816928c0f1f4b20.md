The query takes some time to run (it has lot to do) and from the results we see that it produces 4 packages: package name, description, number of files in the package, and total size of the package. Let's take this query apart and see how it works. At the uppermost level we see the normal pattern of a SELECT statement.

```
SELECT list_of_items FROM Package_Descriptions
ORDER BY total_files DESC
LIMIT 20;
```

The basic structure is simple. What's interesting is the subquery in a WHERE clause: this list_of_items part. We know the list of items is a comma-separated list of items to output, or if we follow the commas we can see:

+   1. package_name
2. description
3. (SELECT COUNT(file) FROM Package_Files WHERE Package_Descriptions.package_name = Package_Files.package_name) AS files
4. (SELECT SUM(size_bytes) FROM Package_Files WHERE Package_Descriptions.package_name = Package_Files.package_name) AS size

It's also possible to use a subquery in a WHERE clause. Consider this query when we use name subquery_demo2.sql:

```
-- subquery_demo2.sql

-- Query to list all packages containing more than 1000 files

.mode column
.header on
.width 20 60
SELECT package_name, description
FROM Package_Descriptions
WHERE 1000 < (SELECT count(file))
FROM Package_Files
```
