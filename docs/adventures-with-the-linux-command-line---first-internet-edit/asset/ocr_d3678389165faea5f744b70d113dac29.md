As we recall from TLCL, shell functions are miniature shell scripts that we can add to our .bashrc file to perform anything that we may otherwise do with a shell script. Here is an example function that displays a quick snapshot of a system's health:

```
status() {
  echo -e "uptime:"
  utime
  echo -e "ndisk space:"
  df -h 2>/dev/null
  echo -e "ninodes:"
  df -i 2>/dev/null
  echo -e "\nblock devices:"
  blkid
  echo -e "\nmemory"
  free -m
  if [[ -f /var/log/syslog ]]; then
    echo -e "insyslog"
    tail /var/log/syslog
  fi
  if [[ -f /var/log/messages ]]; then
    echo -e "inmessages"
    tail /var/log/messages
  fi
} | less
```

Unlike aliases, shell functions can accept positional parameters:

```
params() {
  local argrc=0
  while [[ -n $1 ]]; do
    argc=$((++argc))
    echo "Argument $argc $1"
    shift
  done
}
```

# Command Line Editing

Aliases and shell functions are all well and good, provided we know in advance of the operations we wish to perform, but on-the-fly, what about the rest of the time? Most command line operations we perform are on-the-fly, so other techniques are needed.

As we saw in Chapter 8 of TLCL, the shell includes a library called readline to handle keyboard input during interactive shell sessions. This includes text typed at the shell prompt and keyboard input using the read builtin with the -e option is specified. The readline library supports a large number of commands that can be used to edit what we type at the command line. Since readline is from the GNU project, many of the commands are taken from the emacs text editor.
