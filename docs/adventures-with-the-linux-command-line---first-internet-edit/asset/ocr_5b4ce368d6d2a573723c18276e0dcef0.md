possible to redirect script's output at runtime using the command line. For example,
if we had the following script:

```
#!/bin/bash

# exec-test - Test external redirection and exec
exec 1 > ~/fool.txt
echo "Boo."

# End of script
```

and we tried to invoke it with redirection:
me@linuxbox ~ ./exec-test > /foo2.txt
The attempted redirection would have the effect. The "Boo" would still be written to the file fool.txt, not foo2.txt as specified in the command line. This is because the redirection performed inside the script via exec is performed after the redirection on the command line, and thus takes precedence.

Another way we can use exec to open and close additional file descriptors. While most often use descriptors 0, 1, and 2, it is possible to use others. Here are examples of opening and closing file descriptor 3:

```
# Open fd 3
exec 3 > some_file.txt

# Close fd 3
exec 3>&-
```

It's easy to open and use file descriptors 3-9 in the shell, and it's even possible to use file descriptors 10 and above, though the bash may page counts against it.

So why would we want to use additional file descriptors? That's a little hard to answer. In most cases we don't need to. We could open several descriptors in a script and use them to redirect output to different files, but it's just as easy (using shell variables, if desired) the names of the files that we want to redirect since most commands are going to send their data to standard output anyway.

We can't use standard output to do it, because standard output is being used to output the filtered data.
