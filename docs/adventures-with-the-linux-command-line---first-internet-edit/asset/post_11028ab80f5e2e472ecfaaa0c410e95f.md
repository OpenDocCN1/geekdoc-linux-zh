## Case Conversion

Sometimes, we need to change text from upper to lower case and vice versa, vim has the following case conversion commands:

| Command | Description |
| :--- | :--- |
| gU | Convert text to upper case |
| gu | Convert text to lower case |

Both the gU and gu commands can be applied to selected text in visual mode or used in conjunction with motion commands or text selections. For example:

```
guis   Convert the current sentence to upper case
guf:   Convert text from the cursor position to the next ':'
       character on the current line
```

## File Format Conversion

Once in a while, we are afflicted with a text file that was created or used in a DOS/Windows system. These files will contain an extra carriage return at the end of each line. Vim will indicate this after loading the file by displaying a "DOS" message at the bottom of the editing window. To correct this annoying condition, do the following:

```
:set fileformat=unix
```

The file will be rewritten in the correct format.

Help topics: 'textwidth' gq 'fileformat' ~ gu gU

## Macros

Text editing sometimes means we get stuck with a tedious repetitive editing task where we do the same set of operations over and again again. This is the bane of every computer user. Fortunately, vim provides us a way to record a sequence of operations we can later playback as. These recordings are called macros.

To create a macro, we begin recording typing q followed by a single letter. The character typed after q becomes the name of the macro. After start recording, everything we gets gets in the macro. To conclude, we type q again.

| :--- | :--- |

| ^ | Move to the first non-whitespace character in the current line |
| xx | Delete the first two characters under the cursor |
| j | Move down one line |

Or we could precede the macro invocation with a count as with other commands. For example, if we type:

One thing about macros is that vim remembers them. Each time we exit vim, the current macro definitions are stored and ready for reuse the next time we start another editing session.

## Registers

We are no doubt familiar with the idea of copying and pasting in text editors. With vim, we know y performs a yank (copy) of the selected text, while p and P each paste text at the current cursor location. The way vim does this involves the use of **registers**.

Registers are named areas of memory where vim stores text. We can think of them as a string of variables. Vim uses one particular set to store that we delete, but there are others that we can use to store and restore it as we desire. It's like having a multi-element clipboard.

To refer to a register, we type " followed by a lowercase letter or a digit (though have a special use), for example:

"a

refers to the register named "a". To place something in the register, we follow the register with an operation "yank to end of the line:

"ay$

To recall the contents of a register, we follow the name of the register with a paste operation like so:

"ap

Vim, with Vigor 173

Using registers enables us to place many chunks of text into our clipboard at the same time. But even without consciously trying to use registers, vim is using them while we perform deletes and yanks.

As we mentioned earlier, the registers named 0-9 have a special use. When we perform ordinary yanks and deletes, vim places our latest yank in register 0 and our last nine deletes in 1-9. As we continue to make deletions, vim moves the previous deletion to the next number, so register 1 will contain our most recent deletion and register 9 the oldest.

Knowing this allows us to overcome the problem of performing a yank and then a delete losing the text we yanked (a common hazard using vim). We can always recall the latest yank by referencing register 0.

To see the current contents of the registers we can use the command:

```
:reg
```

Help topics: " :registers

A small menu will appear at the bottom of the display with a list of keys we can type to perform different completions. This will perform filename completion. If we start the name of an existing path/file, we can type Ctrl-x-f and vim will attempt to complete the name.

### Dictionary Lookup

If we define a dictionary, by adding this line to our configuration file:

```
setlocal dictionary=/usr/share/dict/words
```

which is the default dictionary on most Linux systems, we can begin typing a word, type Ctrl-x-k, and vim attempt to complete the word using the dictionary. We will be presented with a list of words from which we can choose the desired entry.

## Mapping

Like many interactive command line programs, vim allows users to remap keys to customize vim behavior. It has a specific command for this, map, allows a key to be assigned the function of any other key or a sequence of keys. Further, vim allows us to say that a key is to be remapped in a certain mode, for example in normal mode but not in insert mode.

Before we go on, we should point out that the use of the map command is discouraged. It can create nasty side effects in some situations. Vim provides another set of mapping commands that are safe to use.

Earlier, we looked at the paragraph reformatting sequence gqip, To demonstrate a useful remapping, we will map the Q key to generate this sequence. We can do this by entering:

```
:nnoremap Q gqip
```
