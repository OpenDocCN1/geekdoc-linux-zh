# Changing to Another Shell

Now that we have learned a little about the different shells available for Linux, how can we experiment with them? First, we can simply enter the name of the shell from our bash prompt. This will launch the second shell as a child process of bash:

```
me@linuxbox ~ $ tschn%
```

Here we have launched tsch from the bash prompt and are presented with the default tsch prompt, a percent sign. Since we have not created any setup files for the new shell, we get a few bare-bones environment. Each shell has its own configuration file(s) for interactive use as bash has .bashrc file to configure its interactive sessions.

Here is a table that lists the configuration files for the shells when used as an interactive (i.e., not a login):

| Shell | Configuration File(s) |
| --- | --- |
| dash | User-defined by setting the ENV variable in ~/.profile |
| bash | ~/.bashrc |
| ksh | ~/.kshrc |
| tsch | ~/.tchrc |
| zsh | ~/.zshrc |

# Interactive shell configuration files

We need to consult the respective shell's man page (always a fun!) to see the complete list of features. Most shells also include additional documentation and example configuration files in the /usr/share/doc directory.

To exit our temporary shell, we simply enter the exit command:

```
% exit
me@linuxbox ~ $
```

Once we are done with our experimentation and configuration, we can change the default shell from bash to our new shell by using the chsh command. For example, to change from bash to zsh, we could do:

```
me@linuxbox ~ $ tsch
password:
Changing the login shell for me
Enter the new value, or press ENTER for the default
  Login Shell [/bin/bash]: /usr/bin/zsh
$
```

We are prompted for our password and then prompted for the name of the new shell whose name must appear in the /etc/shells file. This is a safety precaution to prevent an invalid name from being specified and thus preventing us from logging in again. That would be bad.
