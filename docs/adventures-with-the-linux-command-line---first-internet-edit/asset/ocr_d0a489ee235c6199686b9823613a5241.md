This will work as long as the “clue” given to readline is not ambiguous. If we had two files in our imaginary directory named “foo.txt” and “foo1.txt”, a successful completion would not take place since “less” could refer to either file. What happens instead readline makes the next best guess by completing as “less” since both possible answers contain those characters. To make a full completion, we need to type either less for foo.txt or less for foo1.txt.

If we have typed ambiguous clue, we can view a list of all possible completions for guidance as to what type. In the case of our imaginary directory, pressing Tab a second time will display all of the files beginning with “foo” so that we can see what more needs to be typed to remove the ambiguity.

Besides name completion, readline can complete command names, environment variable names, user home directory, and network host names:

# Completion
Command names

# Description

Completion on the first word of a line will complete the name of an available command. For example, typing “lsu” followed by Tab will complete lls.

# Variables

If completion is attempted on a word with “$”, environment variables will be used. For example, typing “echo $STEM” will complete to echo STEM.

# User names

To complete the name of a user’s home directory, precede the user’s name with “~” and press ‘Tab’. For example: ~ro followed by Tab will complete to ~root/. It is also possible to force completion of a user name without the leading - by typing Alt-- For example “who ro” followed by Alt-- will complete to who root.

# Host names

Completion on a word starting with “@” causes host name completion, however this rarely works on modern systems unless they tend to use /etc/hosts file.

# File names

In all cases, completion is attempted on file and path names.
