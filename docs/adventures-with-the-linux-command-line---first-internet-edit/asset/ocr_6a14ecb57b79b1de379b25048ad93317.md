When working with files, it's important to note that "closing" a window (with either q :close) does not remove the buffer containing the window's content; we can recall it at any time. However, when we close the final window, vim terminates.

To exit, make sure the cursor is in the help window and enter the quit command.

```
:q
```

But enough about windows, let's get back to help. If we scroll around the initial help file, we see it a hypertext document full of links to various topics and it begins with the commands we need to navigate the help system. This is all well and good, but it's not the most interesting way to use.

The best way is to type :h followed by the topic we are interested in. The fact we don't have to type out "help" reveals that most commands can be abbreviated. This saves a lot of work. Frequently used commands, like help, can be shortened to their smallest non-ambiguous form. are often shortened to a single character but the system of abbreviations is unpredictable, so we have to use help to find them. For the remainder of this adventure, we will try to use the shortest available form.

There is an important table near the beginning of the initial help file:

| WHAT | PREPEND | EXAMPLE |
| Normal mode command | (nothing) | :help x |
| Visual mode command | v | :help v_u |
| Insert mode command | i | :help i <Esc> |
| Command-line command | : | :help :quit |
| Command-line editing | c | :help c <Del> |
| Vim command argument | | :help r |
| Option | | :help filepath |

Search for help: Type ":help word", then hit CTRL-D to see matching help entries for "word".

This table describes how we ask for help in particular contexts. With the normal mode 'i' which invokes insert mode. We're familiar with the case of such a command, we simply type:

```
:h i
```

to display its help page. For command commands, we precede the command with ':', for example:

```
:h :q
```

gets help with the :quit command.

There are other contexts for modes we have yet to cover. We'll get to those in a little bit.
