# 10 Vim, with Vigor

TLCL Chapter 12 taught us the basic skills necessary to use the vim editor. However, we barely scratched the surface of its capabilities. Vim is a very powerful program. In fact, it's safe to say that vim can do anything. It's just a question of figuring out how. In this adventure, we will acquire an intermediate level of skill in this popular tool. In particular, we will look at ways to improve our productivity writing shell programs, configuration files, and documentation. Even better, after we get the hang of some of these additional features, using vim is actually fun.

In this adventure, we will look at some of the features that make vim popular among developers and administrators. The community supporting vim is large and vigorous. Because vim is extremely rich in features and scriptable, there are many plugins and addons available. However, we are going to restrict ourselves to stock vim and that normally ship with it.

A note about nomenclature: In TLCL we used the terms "command", "insert", and "ex" to identify the three primary modes of vim. We did this to match the traditional modes of vim's ancestor. Since this is an all-vim adventure, we will switch to the names used in the documentation which are *normal*, *insert*, and *command*.

## Let's Get Started

First, we need to be sure we are running the full version of vim. Many distributions only ship with an abbreviated version. To get the full version, install the "vim" package if it's not already installed. This is also a good time to add an alias to the .bashrc file to make "vi" run vim (some distributions linking 'vi' to 'vim', so this might not be needed).

Next, let's create a minimal .vimrc, its configuration file.

```bash
alias vi='vim'
[me@linuxbox ~]$ vi ~/.vimrc
```

Edit the file so it contains two lines:

```
set compatible
filetype plugin on
```

This will ensure that vim is not restricted to the vi feature set, and load a standard plugin that lets vim recognize different file types. After inserting the two lines of text, return to normal mode and (just for fun) type 'm' followed by uppercase 'V'.

```vim
mV
```

Nothing will appear to happen, and that's OK. We'll come back to that later. Save the file and exit vim.

```vim
:wq
```

## Getting Help

Vim has an extensive built-in help system. If we want vim:

```bash
[me@linuxbox ~]$ vi
```

and enter the command:

```vim
:help
```

It will appear at the top of the display.

![](img/9aafc495f4afbc0a97de2b31a0d13f46_165_0.png)

Vim help window

Though is extensive and very useful, it immediately presents a problem because it creates a split in the display. This is a rather advanced feature that needs some explanation.

Vim can divide the display into multiple panes, which in vim parlance are called windows. These are very useful when working with multiple files and other vim features as help. When help is displayed this way, we can toggle the windows by typing Ctrl-w twice. We can manipulate vim windows with the following commands:

```vim
:split      Create a new window
Ctrl-w Ctrl-w Toggle between windows
Ctrl-w       Enlarge the active window
Ctrl-w =    Make the windows the same size
:close      Close active window
:only       Close all other windows
```

When working with files, it's important to note that "closing" a window (with either q :close) does not remove the buffer containing the window's content; we can recall it at any time. However, when we close the final window, vim terminates.

To exit, make sure the cursor is in the help window and enter the quit command.

```vim
:q
```

But enough about windows, let's get back to help. If we scroll around the initial help file, we see it a hypertext document full of links to various topics and it begins with the commands we need to navigate the help system. This is all well and good, but it's not the most interesting way to use.

The best way is to type :h followed by the topic we are interested in. The fact we don't have to type out "help" reveals that most commands can be abbreviated. This saves a lot of work. Frequently used commands, like help, can be shortened to their smallest non-ambiguous form. are often shortened to a single character but the system of abbreviations is unpredictable, so we have to use help to find them. For the remainder of this adventure, we will try to use the shortest available form.

There is an important table near the beginning of the initial help file:

| WHAT | PREPEND | EXAMPLE |
| :--- | :--- | :--- |
| Normal mode command | (nothing) | :help x |
| Visual mode command | v | :help v_u |
| Insert mode command | i | :help i <Esc> |
| Command-line command | : | :help :quit |
| Command-line editing | c | :help c <Del> |
| Vim command argument | | :help r |
| Option | | :help filepath |

Search for help: Type ":help word", then hit CTRL-D to see matching help entries for "word".

This table describes how we ask for help in particular contexts. With the normal mode 'i' which invokes insert mode. We're familiar with the case of such a command, we simply type:

```vim
:h i
```

to display its help page. For command commands, we precede the command with ':', for example:

```vim
:h :q
```

gets help with the :quit command.

There are other contexts for modes we have yet to cover. We'll get to those in a little bit.

As we go along, free to use help to learn more about the commands we discuss. As this adventure goes on, the text will include help topics to explore.

Oh, and while we're on the subject of command mode, now is a good time to point out that command mode has command line history similar to the shell. After typing ':' we can use the up and down arrows to scroll through past commands.

**Help topics:** :split :only

## Starting a Script

In order to demonstrate features in vim, we're going to write a script. What it does is not important, in fact, it won't do anything except show how we can. To begin, let's start vim with the name of an-existent script:

```bash
[me@linuxbox ~]$ vi
```

and we will get our familiar "new file" window:

New file

## Setting the Filetype

At this point vim has no idea what kind of file we are creating. If we had named the filescript.sh the filetype plugin would have determined we were editing a shell script. We can verify this by asking vim what the filetype is:

```vim
:set?
```

When we use the set command this way, it displays the current value of an option—in this case the ft (short for filetype) option. It should respond with the following indicating that the ft option is unset:

filetype=

For the curious, we can ask for help like this to get more information:

```vim
:h :set
:h 'ft'
```

To see all the current option settings, we can do this and the entire list will appear:

```vim
:set
```

Since we want our new file to be treated as a shell script, we can set the filetype manually:

```vim
:set ft=sh
```

Next, let's enter insert mode and type the first couple lines in our script:

```
#!/bin/bash
```

Exit insert mode by pressing the Esc key and save the file:

```vim
:w
```

Now that our file contains the shebang on the first line, the filetype plugin will recognize the file as a shell script when it is loaded.

## Using the Shell

One thing we can do with filetypes create a configuration file for each of the supported types. Normally, these are placed in the ~/.vim/ft directory. To do this, we need to create the directory.

We don't have leave vim to do this; we can launch a shell from within vim. This is easily done by entering the command:

```vim
:sh
```

After doing this, a prompt will appear and we can enter our shell command:

```bash
[me@linuxbox ~]$ mkdir -p ~/.vim/ftplugin
```

When we're done with the shell, we return to vim by exiting the shell:

```bash
[me@linuxbox ~]$ exit
```

Now that we have a place for our configuration file to live, let's create it. We'll open a new file:

```vim
:e ~/.vim/ftplugin/sh.vim
```

The filename sh.vim is required.
