# Subqueries

The SELECT statement can be used to produce many kinds of output. For example, it can be used to simply print literal strings.

```sqlite
sqlite .mode column
sqlite .header off
sqlite SELECT 'String 1', 'String 2';
string 1 string 2
```

As we saw before, SELECT can produce calculated values.

```sqlite
sqlite>.header on
sqlite SELECT 2 + 2;
2 + 2
$
SELECT COUNT(file), AVG(size_bytes) FROM Package_Files;
count(file) avg(size_bytes)
-------------------------------------------
153506 33370.3488658424
```

To make complicated expressions more readable, we can assign their results by aliases using the AS clause.

```sqlite
SELECT COUNT(file) AS Files,
...> AVG(size_bytes) AS 'Average Size'
... FROM Package_Files;
... Average Size
-------------------------------------------
153506 33370.3488658424
```

An important feature of SELECT is ability to produce results by combining data from multiple tables. This process is done by performing joins and subqueries. joins a little later, but now let's count on subqueries. SELECT allows us to include another SELECT statement as an output. To demonstrate this, we produce a table that includes columns for package name, number of files in the package, and the total size of the package. The SELECT statement to do this is rather formidable. We will open our text editor and create a file named subquery_demol.sql with the following:

```sql
-- subquery_demol.sql

-- Query to list 20 packages with the greatest number of files

.mode column
.header on
.width 20 40 10 10
SELECT package_name, description,
(SELECT COUNT(file)
    FROM Package_Files
    WHERE Package_Descriptions.package_name = Package_Files.package_name),
    (SELECT SUM(size_bytes)
    FROM Package_Files
    WHERE Package_Descriptions.package_name = Package_Files.package_name)
AS size
FROM Package_Descriptions ORDER BY files DESC LIMIT 20;
```

We'll run this query and view the results.

```bash

---------------------------
```

Let's take this query apart and see how it works. At the uppermost level we see the normal pattern of a SELECT statement.

```sql
SELECT list_of_items FROM Package_Descriptions
ORDER BY total_files DESC
LIMIT 20;
```

The basic structure is simple. What's interesting is the subquery in a WHERE clause: this list_of_items part. We know the list of items is a comma-separated list of output, or if we follow the commas we can see:

1. package_name
2. description
3. (SELECT COUNT(file) FROM Package_Files WHERE Package_Descriptions.package_name = Package_Files.package_name) AS files
4. (SELECT SUM(size_bytes) FROM Package_Files WHERE Package_Descriptions.package_name = Package_Files.package_name) AS size

It's also possible to use a subquery in a WHERE clause. Consider this query when we use subquery_demo2.sql:

```sql
-- subquery_demo2.sql

-- Query to list all packages containing more than 1000 files

.mode column
.header on
.width 20 60
SELECT package_name, description
FROM Package_Descriptions
WHERE 1000 < (SELECT COUNT(file) FROM Package_Files)
```

# Updating Tables

The UPDATE statement is used to change values in one or more rows. We will demonstrate this by adding 100 to the size of each file in the sqlite3 package. First, let's look at the files in the package:

```sqlite
sqlite> mode column
sqlite> headers on
sqlite> width 50 10
sqlite> SELECT file, size_bytes FROM Package_Files
file> ... WHERE package_name = 'sqlite3';
```

| file | size_bytes |
|---|---|
| /usr/bin/sqldiff | 1103280 |
| /usr/bin/sqlite3 | 1260976 |
| /usr/share/doc/sqlite3.1.gz | 1261 |
| /usr/share/man/man1/sqlite3.1 | 356 |
| /usr/share/doc/sqlite3/changelog.Debian.gz | 35 |
```

Next, we update the table, adding 100 to the size of each file:

```sqlite
sqlite> UPDATE Package_Files set size_bytes = size_bytes + 100
...> WHERE package_name = 'sqlite3';
```

When we examine the results, we see the change:

```sqlite
sqlite> SELECT file, size_bytes FROM Package_Files
...> WHERE package_name = 'sqlite3'
```
