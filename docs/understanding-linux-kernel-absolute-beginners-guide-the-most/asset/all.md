Kernel space vs. Userspace?Kernel space is the place where the kernel code stored, it executes here and provides its services. On the contrary,  user space is that set of memory locations where user processes run. Userspace processes can access kernel space routines through system calls.MicroKernel vs. Monolithic KernelThe two most popular types of kernels are microkernel and monolithic kernel. Here we will discuss differences between them. First of all, services. Services are kept in separate address space in microkernel where in monolithic kernel services are kept in the same address space.  If services are crashed, it does not affect micro kernel core as it runs in separate address space but monolithic core crashes. In microkernel, execute quite slower compared to monolithic kernel.  Microkernels are smaller in size compared to monolithic ones. Another point, microkernels are easy to extend.Chapter 2: Introduction to Linux KernelLinux KernelLinux inherits the “Monolithic” type of kernel.  This kernel was first released by Linus Torvalds in 1991.  The Linux kernel is a relatively small part of the full Linux System and it is the core that is responsible for how well the system will work.  Since 2005, Linux kernel uses the Git source code management system.Linux Kernel Developer CommunityIf you want to write code for Linux Kernel, you are welcome; as Linux kernel is an open-source project. This layer provides authentication to userspace processes to execute kernel space routines.  In simple words, a system call is just a userspace request for a function or service of kernel space.![Macintosh HD:Users:mahbub:Desktop:system-call-interface.png](image_rsrc2JG.jpg)Syscalls  / System CallsSyscalls / System Calls are accessed via a function call. Usually this function calls are defined in the C library. Syscalls accept variety to arguments (zero to many) as input returns a value and performs one or more tasks. Ideally a system call should have exactly one purpose.System Call NumbersEach system call is assigned a 32-bit system number, which is unique; and it is used to refer C specific system call. Linux kernel maintains a table called sys-call-table to store all registered system calls.Parameters in System CallWhile calling system calls, it may require to pass parameters to them.  Here, parameters are stored in registers. On x86-32 bit system, the registers are ebx, ecx, edx, esi and edi. But the scenario may happen when more than 5 parameters need to be passed. Then a single register is used to hold a pointer to user-space where all the parameters are stored. And the return value is sent to the user-space also via register.Advantages of System callThe system call interface approach has couple of advantages. For example,

*   Secured : If userspace processes/programs could directly read and write to the kernels address space, system security will be nullified.  Userspace functions have limited access to the resources/hardware of the system due to implementation of system call.

*   Faster performance : System call interface provides a faster performance to the system.

*   Portability : System call interface makes user space application more portable. Due to any change in the kernel side, userspace programs don’t need to change.

*   Easier Implementation : System call interface makes user space application development easier; here they do not need to think about low-level functionality of the system.

Disadvantages of system callTo develop or implement a new system call, it needs to have a unique system call number officially assigned to you. More pain points, all architecture needs to separately register the system call. At first, need to add source file in the kernel source tree. Then compile the kernel. If there is no compile error, then build the kernel. If no build error happens, then reboot the machine to get effected result.This approach is quite complex and time-consuming. If any system problem occurs, then it becomes hard to debug; because it is really hard to notify in which of the base kernel caused the trouble. Thus kernel development process becomes quite hard to maintain.To solve this issue Loadable Kernel Module (LKM) feature appeared. LKM was first introduced in kernel version 1.2 in 1995.What is Loadable Kernel Module?Loadable Kernel Module is a small piece of software that can be added or removed into the kernel without the need of rebooting system. Loadable Kernel Modules are used to add or modify functionality to the system without performance penalty, time consumption, and system crash penalties.Loadable Kernel Module works on the current process like statically linked kernel functions.Advantages of Loadable Kernel ModulesLoadable Kernel Modules are not time wasters. They save a lot of time. Because to add/modify, recompile and build Loadable Kernel Module, we don’t need to rebuild the kernel.Due to the Loadable Kernel Module approach Linux kernel is still small and easier to maintain.Another advantage of the Loadable Kernel Module is better memory optimization. When the system booted, all parts of the base kernel stay loaded all the time while Loadable Kernel Modules are loaded when they are needed.Disadvantages of Loadable Kernel ModulesAs Loadable Kernel Modules have higher access permissions to the system, they will become a higher security threat if programs used in the wrong way. Although this security threat can be solvable by allowing only signed modules.Security concern of Loadable Kernel ModuleSeveral LKM security issue arises. For example, Sangram Gayal explains the Linux kernel privileged process Hijacking Vulnerability.Rainer Winchmann provides analysis on Linux Kernel Rootkit.How to minimize these security risks:-          Buffer overrun is one of the most common sources of security risks in LKM. Proper use of buffer overrun will minimize this risk.-            Proper input filtering-            Proper checking of memory initialization and de-initialization-          Enforcing signed modules : LKMs have full access to a low level and critical kernel space resources, sticking with the signed module option will make the utmost safety.Chapter 6:Before starting to write the Loadable Kernel ModuleThings to learnWhat you have learned to write user-space C programming on *nix platforms? Chapter 10:Introduction to Device DriversIntroduction to device driverMost of the Linux kernel’s source code are in its device drivers. The drivers directory contains all of Linux’s device drivers source codes. This directory has the following parts

1.  /block
    *   The block device drivers resides here.
    *   Block devices include both IDE and SCSI based devices.

    *   The char device drivers resides here. Example, tty.

    *   In this directory all of the CDROM code for Linux resides.

    *   PCI pseudo-drivers resides in this directory.
5.  /scsi
    *   All of the drivers for the scsi devices supported by Linux resides here.
6.  /net
    *   Network device drivers resides here.
7.  /sound
    *   All sound card drivers resides here.

What is device driver?A device driver is ultimately designed and developed to control or operate a specific type of hardware that is attached with the system. In other words, device driver consists of a bunch of source code which tells the system how to communicate, operate or control hardware. The kernel uses device driver to control or communicate hardware without knowing any details of the hardware, for example, how hardware operates. A device driver uses bus system of the computer to communicate with the device or through other communication system to which the hardware being connected.When a kernel calls device driver?

*   To check whether the device available or not.
*   To handle device specific input/output calls.
*   To perform user space requests to the sysconfig utility.
*   To check whether data is ready or not through handling interrupts.
*   To set/reset and initialize/reinitialize the device.
*   To perform Input / Output operations from user space standard library Input / Output calls.

Device driver working procedure with User Space, Kernel Space and Hardware Space:

*   In user space, any source program or library are unable to communicate with hardware directly, so they make calls to the kernel space source programs.
*   Although kernel has the supreme power mode in the system, kernel doesn’t try to access hardware directly, rather kernel follow a convention. Kernel uses device driver to communicate with hardware.
*   A device driver in kernel space, responsible to communicate with the hardware or device, for example, opening the device, reading and writing to the device through a bus to peripheral device registers and then closes the device.
*   In hardware space, a bus works as a transmission path or communication path along with access protocols between the processor and device controller. When a device driver reads data from or writes data to the hardware registers of a controller, the data travels across the bus. 
*   In hardware space, a controller works as a physical interface for controlling one or more devices.
