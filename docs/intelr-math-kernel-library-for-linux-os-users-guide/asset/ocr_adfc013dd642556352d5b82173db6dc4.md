# LINPACK and MP LINPACK Benchmarks

-DASYOUGO2: Gives detailed single-node DGEM performance information. It captures all DGEM calls (if you use Fortran BLAS) and records their data. Because of this, the routine has a marginal intrusive overhead. Unlike -DASYOUGO2, which is quite non-intrusive, -DASYOUGO2 is interrupting every DGEM call to monitor its performance. You should be aware of this, although for big problems, it is for sure, less than 1/10th of a percent.

However, the problem size and the block size are so big by comparison that as it prints the value for 0.045, it was already through 0.08 fraction of the columns. On a few larger problems, the fraction number will be more accurate. It never prints more than the 112 numbers above. So, smaller problems will have fewer than 112 updates, and the biggest problems will have precisely 112 updates.

The Mflops is an estimate based on 128 columns of LU with lookahead steps, that work is not actually completed when the output is made. Nevertheless, this is a good estimate for identifying runs.

The 3 numbers in parenthesis are ASYOUGO adds. The DT is the total time processor 0 has spent in DGEM. The DF is the number of billion operations that have been performed in DGEM by one process. Hence, the fraction of processor 0 (i columns in DGEM) is always DF/DT. Using the number of DGEM flops as a basis based on the number of LU flops, you can get a lower bound on performance of our run by using DGEM to compare with. It uses the global LU time, but the DGEM flops are computed under the assumption that the problem is distributed among the nodes, as only HPL's node (0,00) returns any output.

Note that using above performance monitoring tools to compare difference performance drop off HPL.dat input data sets is sensitive to some input data. For instance, when you try very small problems, the performance drop off from initial values to equal values is very rapid.
