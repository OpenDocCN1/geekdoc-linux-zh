上述输出表明，我们对参数的更改处于待处理状态。

我们可以通过使用带有 `-u` 选项的 `kmtune` 来应用对动态参数 *maxuprc* 的更改，将其从 77 更新为 80：

```shell
# kmtune -u
The kernel's value of maxuprc has been set to 80 (0x50) .
```

此输出表明，我们希望对内核所做的更改已经完成。我们可以通过再次运行 `kmtune` 并搜索 *maxuprc* 来确认这一点：

```shell
# kmtune | grep maxuprc
maxuprc             80 Y 80
```

*Current* 和 *Planned* 值都已更新为 80。这种动态更新可以使用 **kmsystem** 向内核添加动态驱动程序来完成。

还有许多其他过程，你需要执行额外的步骤才能将这些修改包含在内核中并重新构建它。对于这些非动态更改，你需要创建一个新的内核，该内核将生成为 **/stand/build/vmunix_test**，使用以下所示的命令：

```shell
# mk_kernel -s system
Compiling conf.c...
Loading the kernel...
Generating kernel symbol table...
```

此时，新内核位于 /stand/build 目录中。现有内核将使用 **kmupdate** 与新生成的内核一起更新。**kmupdate** 将新的内核文件移动到 /stand 目录。我建议首先将现有的 /stand/system 内核文件移动到一个备份文件，然后更新新内核，如下所示：

```shell
# mv /stand/system /stand/system.prev (可能想要移动图 4-3 中显示的其他文件)
# kmupdate /stand/build/vmunix_test
Kernel update request is scheduled.

Default kernel /stand/vmunix will be updated by newly built kernel /stand/build/vmunix_test at next system shutdown or startup time.
```

**kmupdate** 会自动为你创建 /stand/vmunix 和 /stand/dlkm 的备份副本。这些将分别创建为 **/stand/vmunix.prev** 和 /stand/dlkm.vmunix.prev。

现在你可以关闭系统，如果更新未能动态完成且需要重启，系统将自动从新内核启动。

| Step | Comments |
|---|---|
| 1) run `sysdef` and `ioscan -f` | Analyzes and reports tunable parameters of currently running kernel. |
| 2) perform long listing of /stand directory | The file `vmunix` is the existing kernel, and `system` is used to build a new kernel. |
| 3) `cd /stand/build` | This is the directory where the new kernel will be built. |
| 4) `/usr/bin/sysadm` `system_prep -s system` | This examines the currently running kernel. |
| 5) use `kmsystem` and `kmtune` to make changes | Does changes in the `/stand/build` directory. Dynamic update complete here. |
| 6) `mk_kernel -s system` | Makes a new kernel in the `/stand/build` directory, called `vmunix_test`. DLKM files are produced in `dlkm_vmunix_test`. |
| 7) `mv /stand/system /stand/system.prev`<br>`mv /stand/vmunix /stand/vmunix.prev`<br>`mv /stand/dlkm /stand/dlkmvmunix.prev` | Saves the existing files as `.prev`. |
| 8) `mv /stand/build/system /stand/system`<br>`kmupdate /stand/build/vmunix_test` | Renames the kernel and the newly generated kernel. Automatically saves the old versions in `/stand` as follows:<br>`vmunix as /stand/vmunix.prev`<br>`dlkm as dlkmvmunix.prev` |
| 9) `cd /`<br>`shutdown -r 0` | Changes directory to `/` and shuts down the system so that it comes up with the new kernel. This may not be required if your change could be implemented dynamically. |

实际上存在两种不同的生成内核的过程——一种是针对动态元素，例如前面示例中所示的参数 *maxuprc*；另一种是针对静态元素。静态过程由几个额外的步骤和一次重启组成。在 HP-UX 11i 中，越来越多的内核对象将动态更新，从而减少修改内核时的重启次数。

### 内核参数

**aio_listio_max** 指定可以在“listio()”调用中指定的 POSIX 异步 I/O 操作的最大数量。

可接受的值：
- 最小值 2
- 最大值 0x10000
- 默认值 256

此参数对系统资源设置了限制，以防大量 POSIX 异步 I/O 操作在单个“listio()”调用中被请求时消耗系统资源。该值应设置得足够大，以满足系统编程需求，同时保护系统免受故障进程发起的过度异步 I/O 操作的影响。

指定的值不得超过 `aio_max_ops` 的值。

**aio_max_ops** 指定在任一给定时间可以同时排队的 POSIX 异步 I/O 操作的全系统最大数量。

可接受的值：
- 最小值 1
- 最大值 0x100000
- 默认值 2048

指定整数值。
