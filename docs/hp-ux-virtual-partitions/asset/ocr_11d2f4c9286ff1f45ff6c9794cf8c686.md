# # Virtual Partitions and Processors

When assigning processors in Chapter 2, we had a choice of making them *unbound* or *bound*. Bound CPUs are dedicated to a vPar and can't be dynamically removed or added to vPars. Bound CPUs handle I/O interrupts and should therefore be used with I/O-intensive applications. Unbound CPUs can be dynamically added and removed from vPars. Unbound CPUs do not handle I/O interrupts and should be used for CPU intensive applications. Working with processors is a little tricky because you have many options, some of which you can only execute when creating a vPar, others of which require the vPar to be down before executing, so let's take a look at one of the tables from the **vpstatus** man page (Table 5-2):
