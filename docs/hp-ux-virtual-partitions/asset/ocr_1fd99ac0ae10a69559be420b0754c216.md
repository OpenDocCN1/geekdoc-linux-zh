may be that there are some background processes consuming a lot of CPU time that can be changed to run "nice."

Second, compare the number of transfers taking place. These are usually indicated by something like blocks per second (b/s), transfers per second (t/s), or seeks per second (s/s). These numbers give an indication of the amount of activity taking place on a disk. If one volume is consistently much higher than other volumes, then it may be performing an inordinate amount of the workload. Notice on HP-UX that the milliseconds per average seek (ms/s) for all disks is always equal to one.

# ## Virtual Memory Statistics with vmstat
