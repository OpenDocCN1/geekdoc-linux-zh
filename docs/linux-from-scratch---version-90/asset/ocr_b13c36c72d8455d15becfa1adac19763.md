# 7.3.2. Module Loading

Device drivers as modules may have aliases built into them. Aliases are usually related to the output of the bus-specific identifiers of devices supported by a module. For example, the snd-pcm801 driver supports PCI devices with vendor ID 0x1319 and device ID 0x0801, and has an alias of :pci:v0001319d00000801*=snd-pcm*. For most devices, the bus driver exports the aliases of the driver which would handle the device sysfs. E.g., /sys/bus/pci/devices/0000:00:1d.0/modalias file might contain the string "pci:v0001319d00000801s00001319d000001bc4c000*. The default rules provided by Udev will call udev to /sbin/modprobe with the contents of the MODALIAS environment variable for loading all modules whose aliases match this string after wildcard expansion.

In this example, that in addition to snd-pcm801, the obsolete (and unwanted) fororte driver will be loaded if it is available. See below for ways in which the unloading of unwanted drivers can be prevented.

The kernel is also able to load network protocols, filesystems and NLS support on demand.

# 7.3.4. Handling Hotpluggable/Dynamic Devices

When you plug in a device, such as a Universal Bus (USB) MP3 player, the kernel recognizes the device is now connected and generates a uevent. This is then handled by udev as described.

# 7.3.3. Problems with Loading Modules and Creating Devices

There are a few possible problems when it comes to automatically creating device nodes.

# 7.3.3.1. A kernel module is not automatically loaded

Udev will only load a module if it has a bus-specific alias and the bus driver exports the necessary aliases to sysfs. In other cases, no other module loading by will occur. With Linux-5.2.8, Udev is known to load well-written drivers for INPUT, PCI, USB, SCSI, SERIO, and FireWire.

To determine if the device you requires the necessary support for Udev, run modinfo with the module name as you row and check whether there is a modalias file.

If no modalias exists in sysfs, the driver supports the device and can talk to it directly, but doesn't have the alias, it is a bug. Load the driver without help from Udev and expect the issue to be fixed.

If there is no modalias file in the relevant directory under /sys/bus/, this means that the kernel developers have not added modalias to this bus type. With Linux-5.2.8, this is the case with ISA busses. Expect this issue to be fixed in later kernel versions.

Udev is not intended to load “wrapper” drivers such as snd-pcm-oss and non-hardware drivers as loop at all.
