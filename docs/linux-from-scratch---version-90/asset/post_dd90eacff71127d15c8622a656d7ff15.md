
## 6.21. GCC-9.2.0

The GCC package contains the GNU compiler collection, which includes the C and C++ compilers.

Approximate build time: 95 SBU (with tests)
Required disk space: 4.2 GB

### 6.21.1. Installation of GCC

If building on x86_64, change the default directory name for 64-bit libraries to "lib":

```bash
case $(uname -m) in
  x86_64)
    sed -e '/m64/s/lib64/lib/' '\'
      -i.orig gcc/config/i386/t-linux
    ;;
esac
```

The GCC documentation recommends building GCC in a dedicated build directory:

```bash
mkdir -v build
cd build
```

Prepare GCC for compilation:

```bash
SED=sed
./configure --prefix=/usr
  --enable-languages=c,c++
  --disable-multilib
  --disable-bootstrap
  --with-system-zlib
```

Note that for other languages, there are some prerequisites that are not yet available. See the BLFS Book for instructions on how to build all of GCC’s supported languages.

**The meaning of the new configure parameters:**

```bash
SED=sed
Setting this environment variable prevents a hard-coded path to /tools/bin/sed.
--with-system-zlib
This switch tells GCC to link to the system installed copy of the Zlib library, rather than its own internal copy.
```

Compile the package:

```bash
make
```

> **Important**
> In this section, the test suite for GCC is considered critical. Do not skip it under any circumstance.

One set of tests in the GCC suite is known to exhaust the stack, so increase the stack size prior to running the tests:

```bash
ulimit -s 32768
```

Test the results as a non-privileged user, but do not stop at errors:

```bash
chown -Rv nobody .
su nobody -s /bin/bash -c "PATH=$PATH make -k check"
```

To receive a summary of the test results, run:

```bash
../contrib/test_summary
```

For only summaries, pipe the output through grep -A7 Summ.
Results can be compared with those located at http://www.linuxfromscratch.org/lfs/build-logs/9.0/ and https://gcc.gnu/org/ml/gcc-testresults.
Six lists related to get-time are known to fail. These are apparently related to the en_HK locale.
Two named lookup.cc and reverse.cc in experimental/ are not known to fail in LFS ch environment because they require /etc/hosts and iana-etc.
Two named pr57193.c and pr90178.c are known to fail.
A few unexpected failures cannot always be avoided. The GCC developers are usually aware of these issues, but have not resolved them yet. Unless the results are vastly different from those above the URL, it is safe to continue.

Install the package and remove an unnecessary directory:

```bash
make install
rm -rf /usr/lib/gcc/$(gcc -dumpmachine)/9.2.0/include-fixed/bits/
```

The GCC binary is owned by nobody now and the ownership of the installed header directory (and its content) will be incorrect. Change the ownership to root user and group:

```bash
chown -v -R root:root \
/usr/lib/gcc/*linux-gnu/9.2.0/include{,-fixed}
```

Create a symlink you the FHS for "historical" reasons.

```bash
ln -sv ..usr/bin/cpp /lib
```

Many packages use the name gcc to call the C compiler. To satisfy those packages, create a symlink:

```bash
ln -sv gcc /usr/bin/cc
```

Add a compatibility symbol to enable building programs with Link Time Optimization (LTO):

```bash
install -v -dm755 /usr/lib/bfd-plugins
ln -sfv ../../libec/gcc/$(gcc -dumpmachine)/9.2.0/liblto_plugin.so \
/usr/lib/bfd-plugins/
```

Now that our final toolchain is in place, it is important to ensure that compiling and linking will work as expected.
We do this by performing the same sanity checks as we did earlier in the chapter:

```bash
echo 'int main()' > dummy.c
cc dummy.c -v -Wl,--verbose & dummy.log
readelf -l a.out | grep ': /lib'
```

There be no errors, and the output of the last command will be (allowing for platform-specific differences in dynamic linker):

[Requesting program interpreter: /lib64/ld-linux-x86-64.so.2]

Now make sure that we're set up to use the correct starts:

```bash
grep -o '/usr/lib.*crt[1]. *succeeded' dummy.log
```

The output of the last command should be:

```
/usr/lib/gcc/x86_64-pc-linux-gnu/9.2.0/.../lib/crt1 succeeded
/usr/lib/gcc/x86_64-pc-linux-gnu/9.2.0/.../lib/crti succeeded
/usr/lib/gcc/x86_64-pc-linux-gnu/9.2.0/.../lib/crt0 succeeded
```

Depending on your architecture, the may may differ slightly, the difference usually being the name of the directory after /usr/lib/gcc. The important thing to look for is that gcc has all three crt*.o files under /usr/lib directory.

Verify that the compiler is searching for the correct header files:

```bash
grep -B4 '^/usr/include' dummy.log
```

This command should return the following output:

```cpp
#include <...> search starts here:
/usr/lib/gcc/x86_64-pc-linux-gnu/9.2.0/include
/usr/local/include
/usr/lib/gcc/x86_64-pc-linux-gnu/9.2.0/include-fixed
/usr/include
```

Again, note the directory named after your target triplet may be different than the above, depending on your architecture.

Next, verify if the linker is being used with the correct search paths:

```bash
grep 'SEARCH.*</usr/lib' dummy.log | sed 's| |\n|'
```
