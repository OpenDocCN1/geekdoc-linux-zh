
## 7.9. Creating the /etc/shells File

The shells file contains a list of login shells on the system. Applications use this file to determine whether a shell is valid. For each single line should be present, consisting of the shell's path, relative to the root of the directory structure ( / ).

For example, this file is consulted by chsh to determine whether an unprivileged user may change the login shell for her own account. If the command name is not listed, the user will be denied of change.

It is a requirement for applications such as GDM which does not populate the face browser if it can't find /etc/shells, or FTP daemons which traditionally disallow access to users with shells not included in this file.

```
cat > /etc/shells << "EOF"
# Begin /etc/shells

/bin/sh
/bin/bash

# End /etc/shells
EOF
```

## 8.2. Creating the /etc/fstab

The /etc/fstab file is used by some programs to determine which file systems are to be mounted by default, in which order, and must be checked (for integrity) prior to mounting. Creating a new file systems table like this:

```
cat > /etc/fstab << "EOF"
# Begin /etc/fstab
# file system mount-point type options dump fsck order
/dev/<xxx> / <fff> defaults 1 0
/dev/<yyy> swap swap pri=1 0 0
proc /proc proc nosuid,noexec,nodev 0 0
sysfs /sys sysfs nosuid,noexec,nodev 0 0
devpts /dev/pts devpts gid=5,mode=620 0 0
tmpfs /run tmpfs defaults 0 0
devtmpfs /dev devtmpfs mode=0755,nosuid 0 0
# End /etc/fstab
EOF
```

Replace <xxx>, <yyy>, and <fff> with the values appropriate for your system, for example, sda2, sda5 and ext4. For details on this file, see **man fstab**.

Filesystems with MS-DOS or Windows origin (i.e. vfat, ntffs, smbfs, iso9660, udf) need a special option, utf8 for non-ASCII characters in file names to be interpreted. For non-UTF8 locales, the value of ioarchet should be set to the same as the character set of the locale, adjusted in a way that the kernel understands it. This works if the relevant character set is defined (under File systems -> Language Support when configuring the kernel) is compiled into the kernel or as a module. However, if the character set of the locale is UTF-8, the option ioarchet=utf8 would make the file system sensitive to this. To use the special option utf8 instead of ioarchet=utf8, for UTF-8 locales. The "codepage" option is also needed for vfat and smbfs filesystems. For example, in order to mount USB flash drives, a _RU_UTF8-R user would need the following in the options portion of its line in /etc/fstab:

```
noauto,user,quiet,showexec, codepage=866, ioarchet=koi8
```

The corresponding options fragment for _RU_UTF8-R users is:

```
noauto,user,quiet,showexec, codpage=866, utf8
```

Note that using charset is the default for the iso8859-1 (which keeps the file system case insensitive), and the utf8 option tells the kernel to convert the file names using UTF-8 so they can be interpreted in the UTF-8 locale.

It is also possible to specify default codepage and charset values for some filesystems during kernel configuration. The relevant parameters are named "Default NLS Option" (CONFIG_NLS_DEFAULT), "Default Remote NLS Option" (CONFIG_SMB_NLS_DEFAULT), "Default codepage for FAT" (CONFIG_FAT_DEFAULT_CODEPAGE), and "Default charset for FAT" (CONFIG_FAT_DEFAULT_CHARSET). There is no way to specify these settings for the nfs filesystem at kernel compilation time.

It is possible to make the ext3 filesystem reliable across power failures for some hard disk types. To do this, add the barrier=1 mount option to the appropriate entry in /etc/fstab. To check if the disk drive supports this option, run hdparm on the applicable disk drive. For example,:

```
hdparm -I /dev/sda  | grep NCQ
```

returns non-empty output, the option is supported.

Note: Logical Volume Management (LVM) based partitions cannot use the barrier option.

## 8.3. Linux-5.2.8

### 8.3.1. Installation of the kernel

Building the kernel involves a few steps—configuration, compilation, and installation. Read the README for more information.

Prepare the kernel by running the following:

```
makeproper
```

Configure the kernel via a menu-driven interface. For general information on the kernel, see the documentation in the linux-5.2.8/Documentation directory. Also, modprobe.d(5) may be of interest.

Compile the kernel image and modules:

```
make
```

Install the modules, if the kernel configuration uses them:

```
make modules_install
```

After kernel compilation is complete, additional steps are required to complete the installation. Some files need to be copied to the /boot directory.
