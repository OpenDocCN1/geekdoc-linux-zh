
## Chapter 9. The End

### 9.1. The End

Well done! The new LFS system is installed! We wish you much success with your shiny new custom-built Linux system.

It may be a good idea to create an /etc/lfs-release file. By having this file, it is very easy for you (and for us if you need to ask for help at some point) to find out which LFS version is installed on the system. Create this file by running:

```bash
echo 9.0 > /etc/lfs-release
```

It is also a good idea to create a file to show the status of your new system with respect to the Linux Base (LSB). To create this file, run:

```bash
cat > /etc/lsb-release << "EOF"
DISTRIB_ID="Linux From Scratch"
DISTRIB_RELEASE="9.0"
DISTRIB_CODEN="name here"
DISTRIB_DESCRIPTION="Linux From Scratch"
EOF
```

Be sure to put some customization for the field 'DISTRIB_CODEN' to make the system uniquely yours.

### 9.2. Get Started

Now that you have finished the book, do you want to reboot as an LFS user? Head over to http://www.linuxfromscratch.org/cgi-bin/counter.php and register as an LFS user by entering your name and the LFS version you have used. Let's reboot into LFS.

### 9.3. Rebooting the System

Now that all of the software has been installed, it is time to reboot your computer. However, you should be aware of a few things. The system you have created in this book is quite minimal, and most likely will not have the functionality you need to be able to continue. By installing a few extra packages from BLFS while still in your current environment you can leave yourself in much better position. Here are some suggestions:

- A text mode using Lynx will allow you to easily view BLFS in one terminal, while another-GUI browser will allow you to perform copy/paste actions in virtual terminals.
- If you are in a situation where static IP configuration does not meet your requirements, installing a package such as dhcp-client may be useful.
- Installing sudo may be useful for building packages as a non-root user.
- If you want to access your new system from a remote system within a comfortable environment, install openssh.
- To make fetching files over the internet, install wget.
- If one or more of your disk drives have a partition table (GPT), either gdisk or parted will be useful.

Finally, a review of the following configuration files is also appropriate at this point:

- /etc/bashrc
- /etc/dircolors
- /etc/fstab
- /etc/hosts
- /etc/inputrc
- /etc/profile
- /etc/resolv.conf
- /etc/vimrc
- /root/.bash_profile
- /root/.bashrc
- /etc/sysconfig/network-eth0

Now that we have said that, let's move on to booting your shiny LFS installation for the first time! First exit from the chroot environment:

```bash
logout
```

Then unmount the virtual file systems:

```bash
umount -v $LFS/pts
umount -v $LFS/dev
umount -v $LFS/run
umount -v $LFS/proc
umount -v $LFS/sys
```

Unmount the LFS file system itself:

```bash
umount -v $LFS/usr
umount -v $LFS/home
umount -v $LFS
```

If multiple partitions were created, unmount the other partitions before unmounting the main one, like this:

Now, reboot the system with:

```bash
shutdown -r now
```

Assuming the GRUB boot loader was set up as outlined earlier, the menu is set to boot LFS 9.0 automatically. When the reboot is complete, the LFS system is ready for use and more software may be added to your needs.

### 9.4. What Now?

Thank you for reading this LFS book. We hope that you have found this book helpful and have learned more about the system creation process.

Now that the LFS system is installed, you may be wondering “What next?” To answer that question, we have compiled a list of resources for you.

- Maintenance: Bugs and security notices are reported regularly for all software. If an LFS system is compiled from source, it is up to you to keep abreast of such reports. There are several online resources that track such reports, some which are shown below:
    - CERT (Computer Emergency Response Team): CERT has a mailing list that publishes security alerts concerning various operating systems and applications. Subscription information is available at http://www.us-cert.gov/cas/signup.html.
    - Bugtrap: Bugtrap is a full-disclosure computer security mailing list. It publishes newly discovered security issues, and potentially fixes for them. Subscription information is available at http://www.securityfocus.com/
    - Beyond Linux From Scratch: The Linux From Scratch book covers installation procedures for a wide range of software beyond the scope of the LFS Book. The BLFS project is located at http://www.linuxfromscratch.org/blfs/
    - LFS Hints: The LFS Hints are a collection of educational documents submitted by volunteers in the LFS community. The hints are available at http://www.linuxfromscratch.org/hints/list.html.
    - Mailing lists: There are several LFS mailing lists you may subscribe to if you are in need of help, want to stay current with the latest developments, want to contribute to the project, and more. See Chapter 1 - Mailing Lists for more information.
    - The Linux Documentation Project: The goal of the Linux Documentation Project (TLDP) is to collaborate on all of the issues of the Linux documentation. It is located at http://www.ldp.org
