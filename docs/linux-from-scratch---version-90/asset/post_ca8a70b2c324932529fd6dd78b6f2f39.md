
## 6.10. Adjusting the Toolchain

Now that the final C libraries have been installed, it is time to adjust the toolchain so that it will link any newly compiled program against these.

First, backup the /tools linker, and replace it with the adjusted linker we made in chapter 5. We'll also create a link to its counterpart in /tools/$(uname -m)-pc-linux-gnu/bin:

```
mv -v /tools/bin/(ld,ld-old)
mv -v /tools/$(uname -m)-pc-linux-gnu/bin/(ld,ld-old)
mv -v /tools/bin/(ld-new,ld)
ln -sv /tools/bin/ld /tools/$(uname -m)-pc-linux-gnu/bin
```

Next, adjust the GCC specs file so it points to our new dynamic linker. Simply deleting all instances of "tools" leaves us with the correct path to the dynamic linker. Also adjust the spec file so that GCC knows where to find the correct headers and Glibc start. A sed command accomplishes this:

```
gcc -dumpspecs | sed -e 's@/tools@@g' \
-e '\*startfile_prefix_spec;/(n;s@*/usr/lib/@@' \
-e '\*cpp:n@ -system /usr/include/@@' \
-e '\*diname $(gcc --print-libgcc-file-name)\' /specs
```

It is a good idea to inspect the spec file to verify the intended change was actually made.
It is imperative to ensure that the basic functions (compiling and linking) of the adjusted toolchain are working as expected. To do this, perform the following sanity checks:

```
echo 'int main()' > dummy.c
cc dummy.c -v -Wl,--verbose &> dummy.log
readelf -l a.out | grep ':lib'
```

There should be no errors

Note that on 64-bit systems /lib is the location of our dynamic linker, but is accessed via a symbolic link in /lib64.

> Note
On 32-bit systems the interpreter should be /lib/ld-linux.so.2.

Now make sure you're set up the start scripts:
The output of the last command should be:

```
/usr/lib/../../crt1.o succeeded
/usr/lib/../../crt.o succeeded
/usr/lib/../../crtn.o succeeded
```

Verify that the compiler is searching for the correct header files:

```
grep -B1 '^' '/usr/include' dummy.log
```

This command should return the following output:

```
#include <...> search starts here:
/usr/include
```

Next, verify that the linker is being used with the correct search paths:

```
grep 'SEARCH_..*/usr/lib' dummy.log|sed 's;\n|g'
```

References to paths that have components with '-linux-gnu' should be ignored, but otherwise the output of the last command should be:

```
SEARCH_DIR("/usr/lib")
SEARCH_DIR("/lib")
```

Make sure that we're using the correct libc:

```
grep "/lib.*/libc.so.6" dummy.log
```

The output of the last command should be:

```
attempt to open /lib/libc.so.6 succeeded
```

Lastly, make sure GCC is using the correct dynamic linker:

```
grep found dummy.log
```

The output of the last command should be (allowing for platform-specific differences in dynamic linker name):

```
found ld-linux-x86-64.so.2 at /lib/ld-linux-x86-64.so.2
```

If the output does not appear as above or is not correct at all, then something is seriously wrong. Investigate and retrace the steps to find out where the problem is and correct it. The most likely reason is that something went wrong with the steps adjustment. Any issues will need to be resolved before continuing the process.
Once everything is working correctly, clean up the test files:

```
rm -v dummy.c a.out dummy.log
```

## 6.13. Readline-8.0

The Readline package is a set of libraries that offers command-line editing and history capabilities.

**Approximate build time:** 0.1 SBU
**Required disk space:** 1 MB

### 6.13.1. Installation of Readline

Reinstalling Readline will cause the old libraries to be moved to .old. While normally not a problem, in some cases a linking bug in ldconfig can be avoided by issuing the following two commands:

```
sed -i '/.old/d' Makefile.in
sed -i '/.old/c' support/shlib-install
```

Prepare Readline for compilation:

```
./configure --prefix=/usr \
    --disable-static \
    --docdir=/usr/share/doc/readline
```

Compile the package:

```
make SHLIB_LIBS="-L/tools/lib -lcurses"
```

The meaning of the de- the make option:

```
SHLIB_LIBS="-L/tools/lib -lcursesw"
```

This option forces Readline to link against the libcurses library.

This package does not come with a test suite.

Install the package:

```
make SHLIB_LIBS="-L/tools/lib -lcursesw" install
```

Move the dynamic libraries to a more appropriate location and fix up permissions and symbolic links:

```
mv -v /usr/lib/{readline,history}.so.* /lib
chmod -v /usr/lib/{readline,history}.so.*
ln -sf ../lib $(readlink /usr/lib/libreadline.so) /usr/lib/libreadline.so
ln -sf ../lib $(readlink /usr/lib/libhistory.so) /usr/lib/libhistory.so
```

If desired, install the documentation:

```
install -v -m664 doc/*.{ps,pdf,html,dvi} /usr/share/doc/readline-8.0
```

### 6.13.2. Contents of Readline

**Installed libraries:** readline.so and libreadline.so
**Installed directories:** /usr/include/readline and /usr/share/doc/readline-8.0

**Short Descriptions**
- history Provides a consistent user interface for recalling lines of history
- libreadline Provides a set of commands for manipulating text entered in an interactive session of a program

CC=gcc CFLAGS="-std=c99"

-O3
