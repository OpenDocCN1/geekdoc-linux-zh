# 8.4. Using GRUB-v Set Up the Boot Process

# 8.4.1. Introduction

> Warning
Configuring GRUB incorrectly can render your system inoperable without an alternate boot device such as a CD-ROM. This section is not required to boot off your LFS system. You may just want to modify your current boot loader, e.g. Grub-Legacy, GRUB2, or LILO.

Ensure an emergency boot disk is ready to "rescue" if the computer becomes unusable (un-bootable). If you do not have a boot device, you can create one. In order for the procedure to work below, you need to jump ahead to BLFS and install xorriso from the libosurn package.

```
cd /tmp
gub-mkresrescue --output=grub-img.iso
xorriso -as cdrecord -v dev=/dev/cdrom blank=as_needed grub-img.iso
```

> To LFS on systems that have UEFI enabled, the kernel needs to have been built with the CONFIG_EFI_STUB capability described in the previous section. However, LFS can be booted using GRUB without it turned off. With this addition, the UEFI Mode and Secure Boot capabilities in the system's BIOS need to be found. For details, see the lfs-uefi.txt hint at http://www.linuxfromscratch.org/hints/downloads/lfs-uefi.txt.

# 8.4.2. GRUB Naming Conventions

GRUB uses its own naming structure for devices and partitions in the form of (hdn,m) where n is the hard drive number and m is the partition number. The hard drive starts from zero, but the partition number starts from one for normal partitions and five for extended partitions. This is different from earlier versions where numbers started from zero. For example, partition sda1 is (hd0,1) and sdb2 is (hd1,2). In contrast, GRUB does not consider CD-ROM drives to be hard drives. For example, if using a CD on hdb and a second hard drive on hdc, that second hard drive would be (hd1).

# 8.4.3. Setting Up the Configuration

GRUB works by writing to the first track of the hard disk. This area is not part of any file system. The programs access GRUB modules in the boot partition. The default location is /boot/grub/.

The location of the boot partition is a choice that affects the configuration. One recommendation is to use a separate small (suggested size is 100 MB) partition for boot information. By that way each, LFS or some commercial distro, can access the same boot files and be made from any booted system. If you choose to do this, you will need to mount the separate partition, move all files in the current /boot directory (e.g the linux kernel you have built in the previous section) to the new partition. You will then need to unmount the partition and remount it as /boot.

Using the lfs partition will also work, but configuration for multiple systems is more difficult.

Using the above information, determine the appropriate designator for the root partition (or boot partition, if a separate one is used). For the example, it is assumed that the root (or separate boot) partition is sda2.
