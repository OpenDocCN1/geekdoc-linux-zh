
## 6.51. Python-3.7.4

The Python 3 package contains the Python development environment. It is useful for object-oriented programming, writing scripts, prototyping large programs or developing entire applications.

Approximate build time: 1.3 SBU
Required disk space: 399 MB

### 6.51.1. Installation of Python 3

Prepare Python for compilation:

```bash
./configure --prefix=/usr \
--enable-shared \
--with-system-expat \
--with-system-ffi \
--with-ensurepip=yes
```

The meaning of the configure options:

--with-system-expat
This switch enables linking against system version of Expat.
--with-system-ffi
This switch enables linking against system version of libffi.
--with-ensurepip=yes
This switch enables building pip and setuptools packaging programs.

Compile the package:

```bash
make
```

The test suite requires TK and X Windows session and cannot be run until Python 3 is reinstalled in BLFS.

Install the package:

```bash
make install
chmod -v 755 /usr/lib/libpython3.7m.so
chmod -v 755 /usr/lib/libpython3.so
ln -sf pip3.7 /usr/bin/pip3
```

The meaning of the install commands:

```bash
chmod -v 755 /usr/lib/libpython3{7..}so
```
Fix permissions for libraries to be consistent with all other libraries.

If desired, install the pref documentation:

```bash
install -v dm755 /usr/share/doc/python-3.7.4/html
tar --strip-components=1 \
--no-same-owner \
--no-same-permissions \
-C /usr/share/doc/python-3.7.4/html \
xvf ../python-3.7.4-docs-html.tar.bz2
```

The meaning of the documentation install commands:

```bash
--no-same-owner and --no-same-permissions
```

Ensure the installed files have the correct ownership and permissions. Without these options, using tar will install the package files with the upstream creator's values.

### 6.51.2. Contents of Python 3

Installed Programs: 2to3, idle3, pip3, pydoc3, python3, python3-config, and pyvenv

Installed Library: libpython3.7so and libpython3.so

Installed Directories: /usr/include/python3.7m, /usr/lib/python3 and /usr/share/doc/python-3.7.4

# Short Descriptions

- 2to3 is a Python program that reads Python 2.x source code and applies a series of fixes to transform it into valid Python 3.x code.
- idle3 is a wrapper script that opens a Python GUI editor. For this script to run, you must have installed Tk before Python so that the Tkinter Python module is built.
- pip3 The Package installer for Python. You can use pip to install packages from Python Package Index and other indexes.
- pydoc3 is the Python documentation tool.
- python3 is an interpreted, interactive, object-oriented programming language.
- pyvenv creates virtual Python environments in one or more target directories.

## 52. Ninja-1.9.0

Ninja is a small build system with a focus on speed.

Approximate build time: 0.2 SBU
Required disk space: 69 MB

### 52.1. Installation of Ninja

When run, Ninja normally runs a maximum number of processes in parallel. By default this is the number of cores on the system plus two. In some cases this can overheat a CPU or run a system out of memory. If run from the command line, passing a -j parameter will limit the number of parallel processes, but some packages enable the execution of ninja and do not pass a -j parameter.

Using the optional procedure allows a user to limit the number of parallel processes via an environment variable, NINJAJOBS. For example, setting:

```bash
export NINJAJOBS=4
```

will limit ninja to four parallel processes.

If desired, add the capability to use the environment variable NINJAJOBS by running:

```bash
sed -i '/int Guess a/ \
int j = 0;\
char* jobs = getenv("NINJAJOBS");\
if (jobs != NULL) j = atoi(j);\
if (j > 0) return j;\
'src/ninja.cc
```

Build Ninja with:

```bash
python3 configure.py --bootstrap
```

The meaning of the build option:

```bash
--bootstrap
This parameter forces ninja to rebuild itself for the current system.
```

To test the results, issue:

```bash
.ninja ninja_test
./ninja_test --git-filter=SubprocessTest.SetWithLots
```

Install the package:

```bash
install -vm7555 ninja /usr/bin/
install -vdm644 misc/bash-completion /usr/share/bash-completion/completions/ninja
install -vdm644 misc/zsh-completion /usr/share/zsh/site-functions/_ninja
```

## 6.53. Meson-0.51.1

Meson is an open source build system meant to be both extremely fast, and even importantly, as user friendly as possible.

Approximate build time: less than 0.1 SBU
Required disk space: 28 MB

### 6.53.1. Installation of Meson

Compile Meson with the following command:

```bash
python3 setup.py build
```

This package does not come with a test suite.

Install the package:

```bash
python3 setup.py install --root=dest
cp -rv dest/*/
```

The meaning of the install parameters:
--root=dest
By default python3 setup.py installs various files (such as man pages) into Eggs. With a specified root location, setup.py installs these into a standard hierarchy. Then we can just copy the hierarchy so the files will be in the standard location.

### 6.53.2. Contents of Meson

- **Installed programs:** meson
- **Installed directory:** /usr/lib/python3.7/site-packages/meson-info and /usr/lib/python3.7/site-packages/build

# Short Descriptions

- **meson** A high productivity build system

## 54. Coreutils-8.31

The Coreutils package contains utilities for showing and setting basic system characteristics.
Approximate build time: 2.5 SBU
Required disk space: 20 MB

### 54.1. Installation of Coreutils

POSIX requires that programs from Coreutils recognize character boundaries correctly in multibyte locales. The following patch fixes this non-compliance and internationalization-related bugs.

> Note
In the past, many bugs were found in this patch. When reporting new bugs to Coreutils maintainers, check first if they are reproducible without this patch.

Supress a test on machines which can loop forever:

```bash
sed -i '/test.lock/s/^*/#' gnulib-tests/gnulib.mk
```

Now prepare Coreutils for compilation:

```bash
autoreconf -f
FORCE_UNSAFE_CONFIGURE=1 \
.configure \
    --prefix=/usr \
    --enable-install-program=kill,uptime
```

The meaning of the configure options:

- autoreconf
This command updates configuration files with the latest version of automake.
- FORCE_UNSAFE_CONFIGURE=1
This environment variable allows the package to be built as the root user.
- --enable-install-program=kill,uptime
The purpose of this switch is to prevent Coreutils from installing binaries that will be installed by other packages later.

Compile the package:

```bash
make
```

Skip down to "Install the package" if not running the test suite. Now the test suite is ready to be. First, run the tests that are meant to be run as user root:

```bash
make NON_ROOT_USERNAME=nobody check-root
```

We're going to run the remainder of the tests as the nobody user. Certain tests, however, require the user be member of more than one group. So that tests are not skipped we'll add a temporary group and make the user part of it:

```bash
echo "dummy:x:1000:nobody" >> /etc/group
```

# Linux From Scratch - Version 9.0

Fix some of the permissions so that the non-root user can compile and run the tests:

```bash
chown -Rv nobody
```

Now run the tests. Make sure the PATH in the su environment includes /tools/bin.

```bash
su nobody -s /bin/bash \
-c "PATH=$$PATH make RUN_EXPENSIVE_TESTS=yes check"
```

The test program-getinfo is known to fail in a partially built system like the chroot environment here, but passes if run at the end of this chapter. The test tty.sh is also known to fail.

Remove the temporary directory:

```bash
sed -i '/dummy/d' /etc/group
```

Install the package:

```bash
make install
```

Move programs to the locations specified by the FHS:

```bash
mv -v /usr/bin/{cat,chgrp,chmod,chown,cp,date,dd,df,echo} /bin
mv -v /usr/bin/{false,ln,ls,mkdir,nod,mv,pwd} /bin
mv -v /usr/bin/{md5,stty,sync,true,uname} /bin
mv -v /usr/bin/chroot /usr
mv -v /usr/share/man/man1/chroot.1 /usr/share/man/man8/chroot.8
sed -i "/1\/8/"
```

Some of the scripts in the LFS-Bootscripts package depend on head, nice, sleep, and touch. As /usr may not be available during the early and late stages of booting, these binaries need to be on the root partition to maintain FHS compliance:

```bash
mv -v /usr/bin/{head,nice,sleep,touch} /bin
```
