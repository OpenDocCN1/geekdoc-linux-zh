For the "en_GB.iso88591" locale, the above command will print:

```
ISO-8859-1
```

This results in a local setting of "en_GB.ISO-8859-1". It is important that the locale found using the heuristic is tested prior to adding to the Bash setup files:

```
LC_ALL=<locale name> locale language
LC_ALL=<locale name> locale charset
LC_ALL=<locale name> locale int_curr_symbol
LC_ALL=<locale name> locale int_prefix
```

The above commands should print the locale name, the character encoding used by the locale, the local currency, and the prefix to de the phone number in order to get into the country. If any of the commands fail with a message similar to the one below, this means that your locale was not installed in Chapter 6 or is not supported by the default installation of glibc.

```
locale: cannot set LC_* to default locale: No such file or directory
```

If this happens, you should install the desired locale using the localectlef command, or choosing a different locale. Further instructions assume that there are no error messages from Glibc.

Some packages may also lack support for your chosen locale. One example is the X library (part of the X Window System), which outputs the following error if the locale does not exactly match one of the character maps in its internal files:

```
Warning: locale not supported by Xlib, locale set to C
```

In several cases Xlib expects that the character map will be listed in uppercase notation with canonical dashes. For instance, "ISO-8859-1" rather than "iso88591". It is also possible to find an appropriate specification by modifying the charset map of the locale. This can be checked by running the locale charset in both locales. For example, one would have to change "de_DE.ISO-8859-15@euro" to "de_DE@euro" to get this locale recognized by Xlib.

Other packages may also function correctly (but not necessarily display any error messages) if the locale name does not meet the expectations. In those cases, investigating how other Linux distributions support your locale might provide some useful information.

Once the proper locale settings have been determined, create the /etc/profile file:

```
cat > /etc/profile << "EOF"
# /etc/profile

export LANG=<locale>.<charset>@<modifiers>

# End /etc/profile
EOF
```

The "C" (default) and "en_US" (the recommended for one United States English users) locales are different. "C" uses the US-ASCII 7-bit character set, and treats bytes with the high bit set as invalid characters. That's why, e.g., the ls commands then show such characters with question marks in the locale. Also, an attempt to send mail with such characters from Mutt or Pine results in non-RFC-conforming messages (the charset in the outgoing mail is indicated as "unknown 8-bit”). So you can use the "C" locale only if you are sure that you will never need 8-bit characters.
