
## 1.5.3 Compilation Problems

Both the screen output and the contents of various files are useful in determining the cause of compilation problems. The screen output from the `configure` script and the `make` run can be helpful. It is not necessary to include the entire output, but do include enough of the relevant information. Below is an example of the type of information to include from the screen output from `make`:

```
gcc -DALIASPATH="/mnt/lfs/usr/share/locale:."
-DLOCALEDIR="/mnt/lfs/usr/share/locale"
-LDLIBDIR="/mnt/lfs/usr/lib*"
-DINCLUDEDIR="/mnt/lfs/usr/include*" -DHAVE_CONFIG_H -I. -I. -g -o2 -c getopt.c
gcc -o2 -static -o ar.o ascan.o dir.o expand.o file.o function.o implicit.o main.o misc.co read.make rule.o signature.o variable.o vpath.o default.o remote-sub.version opt.o util.o: load_too_high
/lfs/tmp/make-3.79.1/job.c:1565: undefined reference to `getaway'
collect: ld returned 1 exit status
make[2]: *** Error 1
make[2]: Leaving directory `/lfs/tmp/make-3.79.1'
make[1]: *** Error 1
make[1]: Leaving directory `/lfs/tmp/make-3.79.1'
make: ***all-recursive Error 2
```

In this case, many people would just include the bottom section which is not enough to properly diagnose the problem because it only notes something went wrong, not what went wrong. The entire section, as in the example above, should be saved because it includes the command that was executed and the associated error message. An excellent article asking for help is available at http://linux.org/faqs/questions.html. Read and follow the hints in this document to increase the likelihood of getting the help you need.

# Chapter 2. Preparing the Host

### 2.1 Introduction

In this chapter, the host tools needed for building LFS are checked and, if necessary, installed. Then a partition which will host LFS system is prepared. We will create a file system on it and mount it.

### 2.2 Host Requirements

Your host system should have the following software with minimum versions indicated. This should not be an issue for most Linux distributions. Also many distributions will place headers into separate packages, in the form of `<package-name>-devel` or `<package-name>-dev`. Be sure to install them if your distribution provides them. Earlier versions of the listed software may work, but have not been tested.

- Bash-3.2 (/bin/sh should be a symbolic or hard link to bash)
- Binutils-2.25 (Versions greater than 32 are not recommended)
- Bison-2.7 (/usr/bin/yacc should be a link to script that executes bison)
- Bzip2-1.0.4
- Coreutils-6.9
- Diffutils-2.8.1
- Findutils-4.2.3
- Gawk-4.0.1 (/usr/bin/awk should be a link to awk)
- GCC-6.2 (including the C++ compiler, Versions greater than 9.0 are not recommended)
- Glibc-2.11 (Versions greater than 30 are not recommended)
- Grep-2.5.1
- Gzip-1.3.12
- Linux Kernel-3.2

The reason for the kernel requirement is that we specify when building glibc in Chapter 6 it is also required by udev. If the host kernel is earlier than 3.2, you need to replace the kernel with a more up-to-date version. There are two ways to go about this: First see if your Linux vendor provides a 3.2 or later kernel package; if so you may wish to install it. If your vendor doesn't offer an acceptable kernel package or you prefer not to install it, you may compile a kernel yourself. Instructions for compiling the kernel and configuring the boot loader (assuming the host uses GRUB) are located in Chapter 8.

- M4-1.4.10
- Make-4.0
- Patch-2.5.4
- Perl-5.8.8
- Python-3.4
- Sed-4.1.5
- Tar-1.22
- Texinfo-4.7
- Xz-5.0.0

### Important

Note that the symlinks mentioned above are required to build an LFS system using the instructions contained within this book. Symlinks that point to other software (such as dash, awk, etc.) may work, but are not tested or supported by the LFS development team and may require deviation from the instructions or additional patches to some packages.

To see whether your host system has all the appropriate versions and the ability to compile programs, run the following:

```bash
cat > version-check.sh << "EOF"
#!/bin/bash
# Simple script to list version numbers of critical development tools
LC_ALL=C
bash --version | head -n1 | cut -d " " -f2-4
MS=$(readlink -f /bin/sh)
echo "/bin/sh -> $MS"
echo $MS | grep -q bash || echo ERROR: /bin/sh does not point to bash

echo -n Binutils: "; ld --version | head -n1 | cut -d " " -f3-
bison --version | head -n1

if [ -h /usr/bin/yacc ]; then
echo "/usr/bin/yacc -> $(readlink -f /usr/bin/yacc)"
elif [ -x /usr/bin/yacc ]; then
echo "yacc is $(/usr/bin/yacc --version | head -n1)"
else
echo "yacc not found"
fi

bzip --version 2>&1 < /dev/null | head -n1 | cut -d " " -f1,6-
echo -n Coreutils: "; chown --version | head -n1 | cut -d " " -f2
diff --version | head -n1
find --version | head -n1
gawk --version | head -n1

if [ -h /usr/bin/awk ]; then
echo "/usr/bin/awk -> $(readlink -f /usr/bin/awk)"
elif [ -x /usr/bin/awk ]; then
echo "awk is $(/usr/bin/awk --version | head -n1)"
fi
EOF
```
