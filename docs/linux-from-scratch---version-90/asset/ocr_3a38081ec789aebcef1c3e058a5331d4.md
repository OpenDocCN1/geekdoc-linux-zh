# # Appendix C. Dependencies

Every package built in LFS relies on one or more packages to build and install properly. Some packages even participate in circular dependencies, where the first package depends on the second which turn depends on the first. Because of these dependencies, the order in which packages are built in LFS is very important. The purpose of this page is to document the dependencies of each package built in LFS.

For each package we build, we have listed three, and sometimes four, types of dependencies. The first list lists what packages need to be available in order to compile and install the package in question. The second list lists what packages, in addition to the first list, require this package to be built and installed in its final location before they are built and installed. In most cases, this is because these packages will have hard code to binaries within their scripts. If not in a certain order, this could result in paths of /tools/bin/[binary] being inside installed into the final system. This is obviously not desirable.

The last list of dependencies are optional packages that are not addressed in LFS, but could be useful to the user. These packages may have additional mandatory or optional dependencies of their own. For these dependencies, the recommended practice is to install them after completion of the LFS book and then go back and rebuild the LFS package. In several cases, re-installation is advised in BLFS.

# Acl

+   - Installation depends on: Attr, Bash, Binutils, Coreutils, GCC, Gettext, Grep, M4, Make, Perl, Sed, and Texinfo
- Test suite depends on: Automake, Diffutils, Findutils, and Libtool
- Must be installed before: Coreutils, Sed, Tar, and Vim
- Optional dependencies: None
