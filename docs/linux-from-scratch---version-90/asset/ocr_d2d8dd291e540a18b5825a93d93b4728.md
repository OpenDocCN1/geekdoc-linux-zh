# Linux From Scratch - Version 9.0

First place the debugging symbols for selected libraries in separate files. This debugging information is needed if running regression tests that use valgrind or gdb later in BLFS.

```
save_lib=ld-2.30.so libc-2.30.so libthread-2.30.so libthread_db-1.0.so

cd /lib

for LIB in $save_lib; do
  objcopy --only-keep-debug $LIB.dbg
  strip --strip-unneeded $LIB
  objcopy --add-gnu-debuglink=$LIB.dbg $LIB
done
save_usrl="libquadmath.so.0.0.0 libstdc++.so.6.0.267
libitim.so.1.0.0 libatomic.so.1.2.0"

cd /usr/lib

for LIB in $save_usrl; do
  objcopy --only-keep-debug $LIB.dbg
  strip --strip-unneeded $LIB
  objcopy --add-gnu-debuglink=$LIB.dbg $LIB
done

unset LIB save_lib save_usrl
```

Before performing the stripping, take care to ensure that none of the binaries that are about to be stripped are running:

```
exec /tools/bin/bash
```

Now the binaries and libraries can be safely stripped:

```
/tools/bin/find /usr/lib -type f -name \*.a \
  -exec /tools/bin/strip --strip-debug {} \'

/tools/bin/find /usr/lib -type f \ -name \*.so* -a ! -name \*dbg \ \
  -exec /tools/bin/strip --strip-unneeded {} \'

/tools/bin/find /bin,sbin /usr/bin,sbin,libexec -type f \
  -exec /tools/bin/strip --strip-all {} \;'
```

A large number of files will be reported as having their file format not recognized. These warnings safely ignored. These warnings indicate that those files are scripts instead of binaries.
