# 1.5.3 Compilation Problems

Both the screen output and the contents of various files are useful in determining the cause of compilation problems. The screen output from the `configure` script and the `make` run can be helpful. It is not necessary to include the entire output, but do include enough of the relevant information. Below is an example of the type of information to include from the screen output from `make`:

```
gcc -DALIASPATH="/mnt/lfs/usr/share/locale:."
-DLOCALEDIR="/mnt/lfs/usr/share/locale"
-LDLIBDIR="/mnt/lfs/usr/lib*"
-DINCLUDEDIR="/mnt/lfs/usr/include*" -DHAVE_CONFIG_H -I. -I.
-g -o2 -c getopt.c
gcc -o2 -static -o make ar. ascan commands.o dir.o
expand.o file.o function.o getopt.o implicit.o job.o main.o
misc.co read.make rule.o signature.o variable.o vpath.o
default.o remote-sub.version.o optl.o
-lutil job.o: `load_too_high`
/lfs/tmp/make-3.79.1/job.c:1565: undefined reference
to `getlodaway'
collect2: ld returned 1 exit status
make[2]: *** [make] Error 1
make[2]: Leaving directory `/lfs/tmp/make-3.79.1'
make[1]: *** [all-recursive] Error 1
make[1]: Leaving directory `/lfs/tmp/make-3.79.1'
make: *** [all-recursive-am] Error 2
```

In this case, many people would just include the bottom section:

```
make [2]: *** [make] Error 1
```

This is not enough to properly diagnose the problem because it only notes something went wrong, not what went wrong. The entire section, as in the example above, is should be saved because it includes the command that was executed and the associated error message(s).

An excellent article asking for help on the Internet is available at http://catb.esr/faqs/smart-questions.html. Read and follow the hints in this document to increase the likelihood of getting the help you need.
