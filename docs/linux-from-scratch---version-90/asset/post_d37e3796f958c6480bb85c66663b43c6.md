
## 7.6.2. Configuring Sysvinit

During the kernel initialization, the first program that is run is either specified on the command line or, by default **init**. This program reads the initialization file /etc/initab. Create this file with:

```bash
cat > /etc/initab << "EOF"
# Begin /etc/initab

id:3:initdefault

si::sysinit:/etc/rc.d/init.d/rc S

10:0:wait:/etc/rc.d/init.d/rc 0
11:S:wait:/etc/rc.d/init.d/rc 1
12:2:wait:/etc/rc.d/init.d/rc 2
13:3:wait:/etc/rc.d/init.d/rc 3
14:4:wait:/etc/rc.d/init.d/rc 4
15:5:wait:/etc/rc.d/init.d/rc 5
16:6:wait:/etc/rc.d/init.d/rc 6

ca:12345:ctrlaltdel:/sbin/shutdown -t1 -a -r now

su:S016:once:/sbin/login

1:2345:respawn:/sbin/agetty --nuclear tty1 9600
2:2345:respawn:/sbin/agetty tty2 9600
3:2345:respawn:/sbin/agetty tty3 9600
4:2345:respawn:/sbin/agetty tty4 9600
5:2345:respawn:/sbin/agetty tty5 9600
6:2345:respawn:/sbin/agetty tty6 9600

# End /etc/initab
EOF
```

An explanation of this initialization file is in the page for **initab**. For LFS, the key command to run is **rc**. The initialization file above will **rc** to run all scripts starting with S in the /etc/rc.d/ directory followed by all the scripts starting with S in /etc/rc.d/rc where the question mark is specified by the default value.

As a convenience, the **rc** script reads a library of functions in /lib/init-functions. This library also reads a configuration file, /etc/sysconfig/rc. Any of the system configuration parameters described in subsequent sections can alternatively be placed in this file.

As debugging convenience, the function also logs all output to /run/var.log. The /run directory is tmpfs, this file is not persistent across boots, however it is appended to the permanent file /var/boot.log at the end of the boot process.

## 7.6.2. Changing Run Levels

Changing run-levels is done with init <runlevel>, where <runlevel> is the target run-level. For example, to reboot the computer, user could use the init 6 command, which is alias for the reboot command. Likewise, init 0 is alias for the halt command.

There are directories under /etc/rc/ that look like rc? (where ? is the number of the run-level) and rc.d, all containing a number of symbolic links. Some begin with K, the others begin with S and all of them have two numbers. The numbers determine the order in which scripts run, from 0 to 99—the lower the earlier it gets. When init switches to another run-level, the appropriate services are either started or stopped depending on the runlevel chosen.

The real scripts are in /etc/rc.d/init.d. They do the actual work, and links point to them. K and S links point to the same script in /etc/rc.d/init.d. because the scripts can be called with different parameters like start, stop, reload, and status. When a K is linked, the appropriate script is run with the start argument. When an S is encountered, the appropriate script is run with the start argument.

There is one exception to this explanation. Links that start with S in the rc6 directories will not cause anything. They will be called with the stop parameter. The logic behind this is when a user is going to reboot or halt the system, the system only needs to be stopped.

These are descriptions of what arguments the scripts make:

- start: The service is started.
- stop: The service is stopped.
- restart: The service is stopped and then started again.
- reload: The configuration of the service is updated. This is used after the configuration file of a service was modified, when the service does not need to be restarted.
- status: tells if the service is running and with which PIDs.

Feel free to modify the way your boot process works (after all, it is your own LFS). The files given here are examples of how it can be done.

## 7.6.3. Udev Bootscripts

The /etc/rc.d/init.d/udev initscript triggers any "coldplug" devices that have already been created by the kernel and waits for rules to complete. The script also notices the uevent handler from the default /sbin/hotplug. This is because the kernel no longer needs to call out to an external binary. udev will listen on a socket for events that the kernel raises.

The /etc/rc.d/init.d/udev_retry initscript triggers cases of re-triggering events for subsystems whose rules rely on filesystems that are not mounted (the script is run, in particular, /usr and /var may cause this). This script runs all those rules (if re-triggered) should succeed the second time. It is configured from the /etc/sysconfig/udev_retry file; any rules in this file that are not comments are considered subsystem names to trigger retry time. To find the system of a device, udevadm info --attribute-walk <device> where <device> is an absolute path in /dev or sys as /dev/sr0 or /sys/class/rtc.

For information on kernel module loading and udev, see Section 7.3.2.3, “Module Loading”.

## 7.4. Configuring the System Clock

The setclock script reads the time from the hardware clock, also known as the BIOS or the Complementary Oxide Semiconductor (CMOS). If the hardware clock is set to UTC, this script will convert the hardware clock's time to the local time using the /etc/local file (which tells the hwclock program timezone the user is in). There is no way to detect whether or not the hardware clock is set to UTC, so this needs to be configured.

The setclock is run via udev when the kernel detects the hardware capability upon boot. It can also be run manually with the parameter to store the system time to the CMOS clock.

If you cannot remember whether or not the hardware clock is set to UTC, find out by running the hwclock --show command. This will display what the current time is according to the hardware clock. If this time matches whatever watch shows, then the hardware clock is set to local time. If the output from hwclock is not local, it is set to UTC. Verify this by adding or subtracting the proper amount of hours to the timezone to hwclock. For example, if you are currently in the MST timezone, create the following:

```bash
cat > /etc/local << "EOF"
# Begin /etc/local

TZ=MST
# End /etc/local
EOF
```

## 7.6.5. Configuring the Console

This section discusses how to configure the console. The console bootscript reads /etc/sysconfig/console to determine the keymap and font. The following variables are recognized:

- LOGLEVEL: This variable specifies the log level for kernel messages sent to the console. Valid values are from "1" (no messages) to "8". The default is "7".
- KEYMAP: This variable specifies the arguments for loadkeys program, typically, the name of keymap to load, e.g., "it". If this variable is not set, the default keymap will be used. Note that a few keymaps have multiple versions with the same name (cz and its variants in qwerty and qwerty?). In these cases the parent directory should also be specified (e.g., qwerty/) to ensure the proper keymap is loaded.
- KEYMAP_CORRECTIONS: This (rarely used) specifies the arguments for the second call to loadkeys program. This is useful if the stock keymap is not satisfactory and a small adjustment has to be made. E.g., to include the Euro sign into a keymap that normally doesn't have it, set this variable to "euro2".
- FONT: This variable specifies the arguments for the setfont program. Typically, "-m", and the name of the application character map to load. E.g., to load the "lat1-16" together with "8859-1" application character map (as it is appropriate in the USA), set this variable to "lat1-16 -m 8859-1" mode, the kernel uses the application character map for conversion of 8-bit codes in the keymap to UTF-8, and thus the argument of the "-m" parameter should be set to the encoding of the composed key codes in the keymap.
- UNICODE: Set this variable to "1", "yes" or "true" in order to put the console into UTF-8 mode. This is useful in UTF-8 locales and harmful otherwise.
- LEGACY_CHARSET: For many keyboard layouts, there is no stock Unicode keymap in the Kbd package. The console bootscript will convert an available keymap to UTF-8 on the fly if this variable is set to the encoding of the available non-UTF-8 keymap.

Some examples:

```bash
cat > /etc/sysconfig/console << "EOF"
# Begin /etc/sysconfig/console

LOGLEVEL=7
KEYMAP=us
FONT=lat1-16
FONTMAP=8859-1
UNICODE=1
# End /etc/sysconfig/console
EOF
```
