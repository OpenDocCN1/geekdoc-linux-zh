One set of tests in the GCC suite is known to exhaust the stack, so increase the stack size prior to running the tests:

```
ulimit -s 32768
```

Test the results as a non-privileged user, but do not stop at errors:

```
chown -Rv nobody .
su nobody -s /bin/bash -c "PATH=$PATH make -k check"
```

To receive a summary of the test results, run:

```
../contrib/test_summary
```

For only summaries, pipe the output through grep -A7 Summ.
Results can be compared with those located at http://www.linuxfromscratch.org/lfs/build-logs/9.0/ and https://gcc.gnu/org/ml/gcc-testresults.
Six lists related to get-time are known to fail. These are apparently related to the en_HK locale.
Two named lookup.cc and reverse.cc in experimental/ are not known to fail in LFS ch environment because they require /etc/hosts and iana-etc.
Two named pr57193.c and pr90178.c are known to fail.
A few unexpected failures cannot always be avoided. The GCC developers are usually aware of these issues, but have not resolved them yet. Unless the results are vastly different from those above the URL, it is safe to continue.

Install the package and remove an unnecessary directory:

```
make install
rm -rf /usr/lib/gcc/$(gcc -dumpmachine)/9.2.0/include-fixed/bits/
```

The GCC binary is owned by nobody now and the ownership of the installed header directory (and its content) will be incorrect. Change the ownership to root user and group:

```
chown -v -R root:root \
/usr/lib/gcc/*linux-gnu/9.2.0/include{,-fixed}
```

Create a symlink you the FHS for "historical" reasons.

```
ln -sv ..usr/bin/cpp /lib
```

Many packages use the name gcc to call the C compiler. To satisfy those packages, create a symlink:

```
ln -sv gcc /usr/bin/cc
```

Add a compatibility symbol to enable building programs with Link Time Optimization (LTO):

```
install -v -dm755 /usr/lib/bfd-plugins
ln -sfv ../../libec/gcc/$(gcc -dumpmachine)/9.2.0/liblto_plugin.so \
/usr/lib/bfd-plugins/
```
