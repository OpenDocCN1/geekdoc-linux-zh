
Normally, all files in the /tmp directory are deleted at boot. Depending on the number of files or directories present, this can cause a noticeable delay in the boot process. To skip removing these files set the variable SKIPMTCLEAN=y.

During shutdown, the init process sends a TERM signal to each program it has started (e.g. aget), waits for a set time (3 seconds), and sends each a KILL signal as all. This process is repeated in the signalscript for any processes that are not shut down by their own. The delay for init can be set by passing a parameter. For example to remove the delay in init, set the -t0 when shutting down or rebooting (e.g., /bin/shutdown -t0 -r now). The delay for the signalignal script can be skipped by setting the parameter KILLDELAY=0.

## 7.7. The Bash Startup Files

The program /bin/bash (hereafter referred to as “shell”) uses a collection of startup files to create an environment to run in. Each file has a specific use and may affect and influence environment differently. The files in the /etc directory provide global settings. If an equivalent file exists in the home directory, it may override the global settings.

An interactive login is started after a successful login, using /bin/login, by reading the /etc/passwd file. An interactive non-login shell is started at the command-line (e.g. [prompt]#bin/bash). A non-interactive shell is usually present when a shell script is running. It is non-interactive because it is processing a script and not waiting for user input under commands.

For more information, see info under the Bash Startup Files and Interactive Sections section.

The files /etc/profile and ~/.bash_profile are read when the shell is invoked as an interactive login shell. The base /etc/profile below sets some environment variables necessary for native language support. Setting them results in:

- The output of programs translated into the native language
- Correct classification of characters into letters, digits and other classes. This is necessary for bash to accept non-ASCII characters in command line in non-English locales
- The correct alphabetical sorting for the country
- Appropriate default paper size
- Correct formatting of monetary, time, and date values

Replace <ll> with the two-letter code for the desired language (e.g., "en") and with the two-letter code for the appropriate country (e.g., "GB"). <charm> should be replaced with the canonical charset for your chosen locale. Optional modifiers such as "@euro" may also be present.

The list of all locales supported by Glibc can be obtained by running the following command:

```
locale -a
```

Charmaps can have various number of aliases, e.g., "ISO-8859-1" is also referred to as "iso8859-1" and "iso88591". Some applications cannot handle the various synonyms correctly (e.g., require that "UTF-8" is written as "UTF-8", not "utf8"), so it is safest in most cases to choose the canonical name for a particular locale. To determine the canonical name, run the following command, where <locale name> is the output given by locale -a for your preferred locale ("en_GB.iso88591" in our example).

```
LC_ALL=<locale name> locale charmap
```

For the "en_GB.iso88591" locale, the above command will print:

```
ISO-8859-1
```

This results in a local setting of "en_GB.ISO-8859-1". It is important that the locale found using the heuristic is tested prior to adding to the Bash setup files:

```
LC_ALL=<locale name> locale language
LC_ALL=<locale name> locale charset
LC_ALL=<locale name> locale int_curr_symbol
LC_ALL=<locale name> locale int_prefix
```

The above commands should print the locale name, the character encoding used by the locale, the local currency, and the prefix to de the phone number in order to get into the country. ## 7.8. Creating the /etc/inputrc File

The inputrc file is the configuration file for the Readline library, which provides editing capabilities while the user is entering a line. It works by translating keyboard inputs into specific actions. Readline is used by Bash and many other applications.

Most people do not use user-specific functionality so the command below creates a global /etc/inputrc used by everyone who logs in. If you later decide you need to override the defaults on a per-user basis, you can create a .inputrc file in the user's home directory with the modified.

For more information on how to edit the inputrc file, see **info bash** under the *Readline Init File* section. **info readline** is also a good source of information.

Below is a generic global inputrc along comments to explain what the various options do. Note that comments cannot be on the same line as commands. Create the file using the following command:

```
cat > /etc/inputrc << "EOF"
# Begin /etc/inputrc
# Modified by Chris Lynn <rory@rory.dynup.net>

# Allow the command prompt to wrap to the next line
set horizontal-scroll-mode Off

# Enable 8bit input
set meta-flag On
set input-meta On

# Turns off 8 bit stripping
set convert-meta Off

# Keep the 8th bit for display
set output-meta On

# none, visible or audible
set bell-style none

# All of the following map the escape sequence of the value
contained in the 1st argument to the readline specific functions
"\eod": backward-word
"\eoc": forward-word

# for linux console
"\e[1~": beginning-of-line
"\e[4~": end-of-line
"\e[5~": beginning-of-history
"\e[6~": end-of-history
"\e[3~": delete-char
"\e[2~": quoted-insert

# for xterm
"\eoH": beginning-of-line
"\eoF": end-of-line

# for Konsole
"\e[H]\
```
