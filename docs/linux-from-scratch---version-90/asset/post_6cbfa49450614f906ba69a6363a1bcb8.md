
# Syslog

This package contains programs for logging system messages, such as those given by the kernel or daemon processes when unusual events occur.

- Sysvinit

This package provides the init program, which is the parent of all other processes on the Linux system.

- Tar

This package provides archiving and extraction capabilities of virtually all packages used in LFS.

- Tcl

This package contains the Tool Command Language used in many test suites in LFS packages. It is only installed in the temporary toolchain.

- Texinfo

This package contains programs for reading, writing, and converting info pages. It is used in the installation procedures of many LFS packages.

- Util-linux

This package contains miscellaneous utility programs. Among them are utilities for handling file systems, consoles, partitions, and messages.

- Vim

This package contains an editor. It was chosen because of its compatibility with the classic editor and its huge number of powerful capabilities. An editor is a very personal choice for many users and any other editor could be substituted if desired.

- XML::Parser

This package is a Perl module that interfaces with Expat.

- XZ Utils

This package contains programs for compressing and decompressing files. It provides the highest compression generally available and is useful for decompressing packages in XZ or LZMA format.

- Zlib

This package contains compression and decompression routines used by some programs.

# Prerequisites

Building an LFS system is not a simple task. It requires a certain level of existing knowledge of Unix system administration in order to resolve problems and correctly execute the commands listed. In particular, as an absolute minimum, you should already have the ability to use the command line (shell) to copy or move files and directories, directory file contents, and change the current directory. It is expected that you have a reasonable knowledge of using and installing Linux software.

Because the LFS book assumes at least this basic level of skill, the aware LFS forums are unlikely to be able to provide you with much assistance in these areas. You will find that your questions regarding such basic knowledge will likely go unanswered or simply be referred to the LFS essential pre-reading list.

Before building an LFS system, we recommend reading the following:

- Software-Building-HOWTO http://www.tldp.org/HOWTO/Software-Building-HOWTO.html

This is a comprehensive guide to building and installing "generic" Unix packages under Linux. Although it was written some time ago, it still provides a good summary of the basic techniques needed to build and install software.

- Beginner's Guide to Installing Source http://mol.vonos.net/linux/beginners-installing-from-source/
This guide provides a good summary of basic skills and techniques needed to build software from source code.

# Typography

To make things easy to follow, there are a few typographical conventions used throughout this book. This section contains some examples of the typographical format found throughout Linux From Scratch.

```
/configure --prefix=/usr
```

This form is designed to be typed exactly as seen unless otherwise noted in the surrounding text. It is also used in the explanation sections to identify which of the commands is being referenced.
In some cases, a line extended to two or more lines with a backslash at the end of the line.

```
gcc -B/usr/bin/" ... /binutils-2.18/configure \
--prefix=/tools --disable-nls --disable-werror
```

Note that the backslash must be followed by an immediate return. Other whitespace characters like spaces or tab will create incorrect results.

```
install-info: unknown '--dir-file=/mnt/lfs/usr/info/dir'
```

This form (fixed-width) shows screen output, as the result of commands issued. This format is also used to show filenames, such as /etc/ld.so.conf.

Emphasis

This form is used for several purposes in the book. Its main purpose is to emphasize important points or items.
http://www.linuxfromscratch.org/
This format is used for hyperlinks both within the PFS community and external pages. It includes HOWTOs, download locations, and websites.

```
cat > $LFS/etc/group << "EOF"
root:x:0:
bin:x:1:
...\EOF
```

This format is used when creating configuration files. The first command tells the system to create the file $LFS/group from whatever is typed on the following lines until the sequence End Of File (EOF) is encountered. Therefore, this entire section is generally typed as seen.

```
<REPLACED TEXT>
```

This format is used to encapsulate text that is not to be typed as seen or for copy-paste operations.

[OPTIONAL TEXT]

Linux From Scratch - Version 9.0

This format is used to encapsulate text that is optional.

password(5)

This format is used to refer to a specific manual (man) page. The number inside parentheses indicates a specific section inside the manuals. For example, `password` has two man pages. For LFS installation instructions, those two man pages will be located at `/usr/share/man/man1/password.1` and `/usr/share/man/man5/password.5`. When the book uses `password(5)` it is specifically referring to `/usr/share/man/man5/password.5`. **man password** will print the first man page it finds matches "password", which will be `/usr/share/man/man1/password.1`. For this example, you will need to run **man 5 password** in order to refer the specific page referred to. It should be noted that most man pages do not have duplicate page names in different sections. Therefore, **man <program name>** is generally sufficient.

## 1.1. How to Build a LFS System

The TFS system will be built by using an already installed Linux distribution (such as Debian, OpenMandriva, Fedora, or openSUSE). This Linux system (the host) will be used as a starting point to provide necessary programs, including a compiler, linker, and shell, to build the new system. Select the “development” option during the installation to be able to access these tools.

As an alternative to installing a separate distribution onto your machine, you may wish to use a LiveCD from a commercial distribution.

Chapter 2 of this book describes how to create a new Linux partition and system. This is the place where the new TFS system will be compiled and installed. Chapter 3 explains how packages and patches need to be downloaded to build TFS system. Chapter 4 discusses the setup of appropriate working environment. Please read Chapter 4 carefully as it explains important issues you must be aware of before beginning your way through Chapter 5.

Chapter 5 explains the installation of a number of packages that will form the basic development (or toolchain). Chapter 5 also shows you to build a first part of the toolchain, including Binutils and GCC (first pass these two packages will be reinstalled). The next step is to build Glibc, the C library. Glibc will be compiled by the toolchain built first. Then, a second pass of the toolchain will be built. This time, the toolchain will be dynamically linked in pass with the newly built Glibc. The remaining Chapter 5 packages are built using this second pass.

In Chapter 6, the full system is built. The chroot (change root) program is used to create a virtual environment and start a shell whose root directory will be the TFS partition. This is very similar to rebooting and restarting the kernel to mount the TFS partition as the root partition. The system does not reboot, but instead uses chroot because creating a bootstrap system requires additional work which is not necessary just. The major advantage is that “chrooting” allows you to continue using the host system while TFS is being built.

To finish the installation, the basic system configuration is set up in Chapter 7, and the kernel and boot loader are set up in Chapter 8. Chapter 9 contains information on continuing the experience beyond this book.

This is the process in a nutshell. Detailed information on each step is discussed in the following chapters and package items. Items that may seem complicated will be clarified, and will fall into place as you embark on the TFS adventure.
