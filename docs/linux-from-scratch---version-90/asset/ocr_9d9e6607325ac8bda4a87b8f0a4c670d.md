# ## 5.10.1. Installation of GCC

Our first build of GCC has installed a couple of internal system headers. Normally one of them, *limits.h*, will turn in including the corresponding system limits.h header, in this case */tools/include/limits.h*. However, at the first build of gcc */tools/include/limits.h* did not exist, the internal header that GCC installed is a partial, self-contained file and does not include the features of the system header. This was adequate for building the temporary library, but this build of GCC now requires the full internal header. Create a full version of the internal header using the GCC build system in normal circumstances:

```
cat gcc limitx.h gcc gclimits.h gcc limit.h \ \
`dirname $(LFS_TGT-GCC-file-name)`/included-fixed/limits`
```

Once again, the configuration of GCC's default linker is to use the one installed in */tools/*.

```
for file in gcc/config/{linux,i386,64}; do
cp -uv ${file}.orig
sed -e 's@/lib/(64)/\(32)\)?/ld/tools&@g' \ \
-e 's@/usr/tools@g' ${file}.orig > ${file}
echo
#undef STANDARD_STARTFILE_PREFIX_1
#undef STANDARD_STARTFILE_PREFIX_2
#define STANDARD_STARTFILE_PREFIX_1 "/tools/lib/"
#define STANDARD_STARTFILE_PREFIX_2 "" >> ${file}
touch ${file}.orig
done
```

If building on x86_64, change the directory name for 64-bit libraries to "lib":

```
case $(uname -m) in
x86_64)
sed -e 's@lib=/lib/64/lib/@' \ \
-i.orig gcc/config/i386-t-linux

nesac
```

As the first build of GCC it requires the GMP, MPFR and MPC packages. Unpack the tarballs and move them into the required directory:

```
tar -xf ../mpfr-4.0.2.tar.xz
mv -v mpfr-4.0.2 mpfr
tar -xf ../gmp-6.1.2.tar.xz
mv -v gmp-6.1.2 gmp
tar -xf ../mpc-1.1.0.tar.gz
mv -v mpc-1.1.0 mpc
```
