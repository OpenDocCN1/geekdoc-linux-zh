# The meaning of the options and new configure parameters:

CC="gcc -ffile-prefix-map=/tools=/usr"
Make GCC record any references to files in /tools during the compilation as if the files in /usr. This avoids introduction of invalid paths in debugging symbols.

--disable-error
This option disables the Werror option passed to GCC. This is necessary for running the test suite.

--enable-stack-protector=strong
This option increases security by adding extra code to check for buffer overflows, such as stack smashing attacks.

--with-headers=/usr/include
This option tells the build system to find the kernel API headers. By default, those headers are sought in /tools/include.

libc_cv_libdir=/lib
This variable sets the correct library for all systems. We do not want lib64 to be.

Compile the package:

```
make
```

> **Important**nIn this section, the test suite for Glibc is considered critical. Do not skip it under any circumstance.

Generally a few tests do not pass. The failures listed below are generally safe to ignore.

```
case $ (uname -m) in
i686) ln -sfnv $PWD/elf/l1d-linux.so.2 /lib ;
x86_64) ln -sfnv $PWD/elf/l1d-linux-x86-64.so.2 /lib ;
esac
```

> **Note**
The symbolic link above is needed to run the tests at this stage of building the chroot envirment. It will be overwritten in the install phase below.

```
make check
```

You may see some failures. The Glibc test suite is somewhat dependent on the host system. This is a list of the most common issues seen for some versions of LFS:

+   - misc/test-tty is known to fail in the LFS chroot environment.
- inet/test-idna_classif is known to fail in the LFS chroot environment.
- posix/getaddrinfo4 and posix/getaddrinfo5 may fail on some architectures.
- The nss/test-nss-files-hosts-multi may fail for reasons that have not been determined.
