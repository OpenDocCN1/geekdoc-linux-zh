+   3. Create the */etc/mail/client-b.ftr* file for the second client. This file is likely to be similar to the previous example; but, suppose the **client-b.com** owner wants all c-mail addresses to be automatically mapped to her existing accounts in your hometown ISP mail server. In such a case, this map file looks as follows:

```
$client-b.com  $1@home-town-isp.com
```

+   4. Now that you have two virtual user map files, create the final */etc/mail/virtualtable* file by using the following commands:

```
touch /etc/mail/virtualtable
cat *.ftr >> /etc/mail/virtualtable
```

The first command creates the */etc/mail/virtualtable* file (if it doesn't already exist). The second command concatenates all the FTR files to */etc/mail/virtualtable*. This effectively creates the final */etc/mail/virtualtable* file.

+   5. Run the **makemap** program to create the database version of the file, as follows:

```
makemap hash /etc/mail/virtualtable <
/etc/mail/virtualtable
```

As this example demonstrates, creating multiple virtual user map files can help you keep track of individual domains quite easily. Any time you want to change a domain-specific map, just modify the domain's FTR file and create the final */etc/mail/virtualtable* file using the technique just discussed.
