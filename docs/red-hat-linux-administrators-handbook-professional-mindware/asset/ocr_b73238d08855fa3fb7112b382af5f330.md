After you are successfully authenticated, an xterm (or whatever application you put in the Command field while editing this entry in X-Utl32) appears on your MS Windows system. If you do not see the application in a few seconds, however, go back to the X-Win32 icon on your taskbar, click the Show Messages option, and try to run your application again. Watch for any permission errors in the message window. If you do get permission errors, you have forgotten to enable the rexec or rsh service, you have forgotten to restart the xinetd server after modifying the `/etc/xinetd.d/rsh` or `/etc/xinetd.d/rexec` files, or you have not yet set up the `.rhosts` file for rsh-only sessions. Make sure your `.rhosts` file is writable only by the owner; everyone else should have only read-only access to this file.

At this point, you should have an X Window application running under the Micro X-Win32 server. If you prefer to start an X Window manager, such as `fvwm2` or `openstep`, and run all X Window applications as usual (that is, as if you were on the Red Hat Linux system), do the following:

+   1. Using XUtl32, create or edit a session. Enter the host name, the login username, and the connection method (rsh, rexec), as you did before. Select the Switch to single window option and enter the following line as the command:
+      `fvwm2 -display $DISPLAY`
+   2. Don't forget to replace fvwm2 with your favorite X Window manager. Save the new (or edited) session.

Close any X Window client sessions that you have already started; then, start the new session. You should see a large single window where your favorite X Window manager is loaded. Now you can use X Window as if you were running it from the console of the Red Hat Linux system. In case of a problem, read the online troubleshooting information for details.
