## About Plug-ins

In Hour 12, “Using Filters to Improve Images,” you learned a little about plug-ins (in the form of graphics filters), and how to use them to alter your images directly. Now you will spend some time learning how GIMP interacts with plug-ins, what exactly they are, and how you can use them to augment your GIMP experience.

## So, What Exactly Are Plug-ins?

GIMP relies on plug-ins for its internal operations. In fact, almost everything you do in GIMP is the result of a plug-in at work. This is why GIMP was designed. Because it's an Open Source application, development on GIMP is taking place at a fast pace. New features and elements are added all the time. Therefore, in order to satisfy the end user's appetite for new functions and to make things easier for the developer, GIMP was designed from the ground up to be a modular application. This means that many things, such as graphics filters, file types, small internal applications, can be added to GIMP. They can be written as plug-ins and can enhance the GIMP directly without the need to reinstall or recompile the entire application, at least most of the time. As new things are added to GIMP, continually recompiling would be a pain.

This modularity has many benefits. For one, a developer with knowledge about a certain kind of application can extend GIMP relatively easily. For the end user, it is fantastic because it means he or she can immediately enjoy new benefits without the need to recompile the application or wait for another release (in the traditional commercial arena, being able to use a new feature or function means waiting for another release or purchasing an upgrade). Therefore, a new feature such as support for a new file format, a new type of filter, or even a sophisticated internal application, can be enjoyed with little trouble. And official development focuses on improving the internals of the application itself, providing a faster and more secure environment for these plug-ins to run in. This also means it is relatively easy for a large number of people to contribute to the GIMP project. And the more people contribute, the more robust the application will become (it's only at version 1.0 now; imagine how robust GIMP will be in a couple of major revisions!).

## A WORD ABOUT GIMP DEVELOPMENT

If you are a little developer and want to try your hand at contributing to GIMP development, there are a few things you can do:

- From the user standpoint, if you run into a bug or find something that doesn't work like it's supposed to, you can always submit it to the GIMP report mailing address. Fill out Zach Deane's bug report format at http://zach.dnet.org/gimp/news/bugreport.html.
- Writing plug-ins is the easiest way to contribute to GIMP development because it adds features and functionality without touching the core source tree. It also doesn't require official approval from the GIMP community at large. You simply need to write your plug-in and then submit it to the plug-in registry at http://registry.gimp.org. The end user is your quality assurance team—if your plug-in doesn't live up to expectations, it can be deleted without affecting the rest of the GIMP installation. However, if your plug-in is good enough, there is a chance that it will become a staple of any good GIMP distribution in the future.
- If you want to dig a little deeper, you can always download the latest developer's source tree and muck around it for a while. The latest, unstable development releases are available from the GIMP CVS (Concurrent Version System), which is a method of version control for software products. Please read here: http://www.gimp.org/devel_ver.html for more details. You should also check out the GIMP developer FAQ at http://www.gimp.org/help/faq-dev.html.

- Of course, if you are starting your own patches for the core GIMP development tree, you will want to start communicating with other GIMP developers and get your fantastic patches accepted into the official distribution. This is handled through the GIMP mailing list. You can subscribe and unsubscribe from the GIMP mailing list at http://www.gimp.org/mailing_list.html. The GIMP development community is composed of many different people from all areas of life, with their own ideas about how things should work. The GIMP, inheriting the strongest and most practical ideas from this pool of knowledge, grows and evolves like a true Darwinian organism—thrives on evolution and rivalry. It is really exciting stuff, even if you only sit back and watch it all happen.

This is somewhat different from the concept of plug-ins in Photoshop. In that application, plug-ins are mainly filters and other similar apps that alter and create images. In GIMP, a plug-in is anything that can be added to the GIMP without affecting the core source tree. This makes the GIMP infinitely scalable, but perhaps a bit more obfuscated at times.

Yes, there are many things that are native to the GIMP itself that are not plug-ins. These include the color models, the basic tools, the GTK interface, the Plugin API, the Script-Fu interface, and the core functions as layers, undos, masks, antialasing, core dialog boxes, and so on. Everything else is handled by a plug-in of some sort. This includes all the filters, extraneous tools, file formats, interfacing applications (for scanners, printers, email, and so forth).

## How to Obtain and Install New Plug-ins

In order to install a new plug-in, you will need to find and compile it. (No binary distributions here!) Note that a few of the plug-ins are version-dependent and as such they will only work in versions 1.0 or 1.1 of GIMP. This is because the plug-ins must communicate with the GIMP directly, and the internals can get drastically altered between releases.
