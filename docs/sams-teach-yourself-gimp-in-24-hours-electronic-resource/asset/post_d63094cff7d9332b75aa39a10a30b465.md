# Installing GIMP

The following sections contain instructions for installing GIMP on your system. The first thing to do in approaching GIMP installation is to determine which installation method you want to use. Depending on your situation, there are a few different ways to go about installing GIMP.

# Binary Installation

If you want to get the GIMP up and running as quickly and painlessly as possible, binary installation is by far the best way to go. (Binary is another term for executable program.) This means that you will install the program into its proper place, and then run it.

> NEW TERM

Note that the binaries on the CD-ROM are for Linux 2.0+, Solaris, and IRIX only. If you are running another platform, you will need to get the binaries elsewhere, or compile the source code on your machine.

![](img/0183f053b347a6407a2381be231d0345_29_1.png)

There are generally two main ways to go about a binary installation: the standard way by using a package manager.

# The Standard Way

The standard way to go about a binary installation is to grab the program in the form of compressed archive (usually a tar.gz file), decompress the archive (tar -xzvf *.tar.gz), and put the files where they need to go according to the documentation. The GIMP for Solaris on the CD-ROM is packaged in this manner.

# Using RPM

Another popular way to do this is using RPM—the Red Hat Package Manager. This program, which is available by default on the Red Hat, Caldera, and S.u.S.E distributions available for any UNIX platform, takes care of installation issues for you. It takes any file compacted into RPM format, installs it, and puts everything where it needs to go. Installation and upgrading are greatly simplified, because all the details to where things are taken care of you. (This is particularly hard for uninstalling software.) It can also retain your configuration files, so that customizations are not lost during upgrades. One little command and you're finished.

There are other good package managers out there as well, the Debian distribution's DEB format and Stampede's SLP format. These should work much the same way as RPM.

# Binary Installation for RPM Enabled Systems

You can find GIMP binaries on the CD-ROM in the RPM format under the /gimp/RPM/ directory. As root, simply change into the directory reflecting your form of choice (that is, /mnt/gimp/RPM/) and type the following at:

```
-Uhvh gimp-1.0.2.i386.rpm
-Uhvh gimp-devel-1.0.2.i386.rpm
-Uhvh gimp-data-extras.1.0.2.i386.rpm
-Uhvh gimp-plugins-uninstall.-1.0.2.i386.rpm
```

This will be followed by a success of hashes (#) indicating the installation is in progress. Pending no error messages, you should be ready to run the GIMP. Nice and simple, won't you see?

# RPM Troubleshooting Quick Reference

- I need a dependency not found error.

A This means that the installing package was looking for a required file or library that was not there. You will need to install/upgrade any packages containing the files you need. This might require a little investigation on your part. if the error says libjpeg.so.1 - dependency not found, you can deduce from this there is a problem with the libjpeg package. It's probably misplaced, not installed, or is an outdated version. You should go to any one of Linux FTP sites to download/install the latest libjpeg package to reconcile the problem.

Although most of the time these dependency issues are pretty easy to resolve, sometimes it is not quite so to deduce what package contains the missing file at merely firstly glance. But, not to worry; most of the time you can find out where the file belongs by way of a little research. After checking the newsgroups or mailing lists, someone will have run into the same thing and can tell you what are missing. These resources are always timely, accurate, and quick to respond. (You'll be surprised.)

![](img/0183f053b347a6407a2381be231d0345_30_0.png)

- Q That didn't work. After installing the latest necessary packages, I will still get the same error.

A Assuming the problem is associated with library dependencies (lib*,so), you might need to add the directory containing the said lib to the library path. You do this by editing /etc/ld.so.conf and adding the string /usr/local/lib (or wherever the library resides). Then run ldconfig and you should be set.

Otherwise, you might need to add the directory to your LD_LIBRARY_PATH variable in your .bashrc (or equivalent) if you do not have administrative privileges.

Every once in a while, older versions of lib might be installed in a different directory, such as /usr/lib, thereby causing confusion. You might need to completely uninstall all the older library packages before installing the new ones.

- Q I get undefined symbol: register frame info errors when trying to run the GIMP.

A This is caused by running a gcc-compiled GIMP with egcs-compiled graphics libraries (as can be the case when upgrading the GIMP in Red Hat 5.1). You will need to recompile GIMP with egcs, or update all the RPM packages, including graphics libraries and gtk, for consistency (The binaries in /gimp/RPMS/ on the CD-ROM are compiled uniformly).
