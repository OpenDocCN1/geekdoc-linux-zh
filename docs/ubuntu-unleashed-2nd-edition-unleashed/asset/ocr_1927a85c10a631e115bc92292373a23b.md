Building many software packages for Linux that are distributed in source form requires the use of GNU’s autoconf utility. This program builds an executable shell script named configure that, when executed, automatically examines and tailors a client’s build from source according to software resources, or dependencies (such as programming tools, libraries, and associated utilities), that are installed on the target host (your Linux system).

Many Linux commands and graphical clients for X downloaded in source code form include configure scripts. To configure the source package, build the software, and then install the new program, the root user might use the script like this (after uncompressing the source and navigating into the resulting build directory):

```
$ ./configure ; make ; sudo make install
```

The autoconf program uses a file named configure.in that contains a basic ruleset, or set of macros. The configure.in file is created with the autoscam command. Building a properly executing configure script also requires a template for the makefile, named Makefile.in. Although creating the dependency-checking configure script can be done manually, you can easily overcome any complex dependencies by using a graphical project development tool such as KDE’s KDevelop or GNOME’s Glade. (See the section “Graphical Development Tools,” later in this chapter, for more information.)

# Managing Software Projects with CVS and Subversion

Although you can use make to manage a software project, larger software projects require document management, source code controls, security, and revision tracking as the source code goes through a series of changes during its development. CVS and Subversion provide source code version control utilities for this kind of large software project management. You can find this utility in APT packages on your Ubuntu DVD.

Both CVS and Subversion are used to track changes to multiple versions of files, and can be used to backtrack or branch off versions of documents inside the scope of a project. They can also be used to prevent or resolve conflicting entries or changes made to source code files by multiple developers. Subversion is newer than CVS, and many projects are making the move from CVS to Subversion. Although Subversion introduces many welcome features, such as the capability to work offline, it uses very similar command-line syntax to CVS so that CVS users feel at home.

Source code control with CVS and Subversion requires the use of at least the following six command options on the cvs or svn command line:

+   - checkout—Checks out revisions
+   - update—Updates your sources with changes made by other developers
+   - add—Adds new files in cvs records
+   - import—Adds new sources to the repository
+   - remove—Eliminates files from the repository (Note: Subversion uses delete for this)
+   - commit—Publishes changes to other repository developers
