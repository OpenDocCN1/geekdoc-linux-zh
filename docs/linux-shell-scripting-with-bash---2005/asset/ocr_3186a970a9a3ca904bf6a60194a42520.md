# ## Stopping a Script

The \texttt{logout} command, which ends an interactive login session, cannot be used to stop a script. (After all, a script is not a login session.) Instead, Bash provides two built-in commands for terminating a script.

As seen previously, the \texttt{exit} command unconditionally stops a script. \texttt{exit} can include a status code to return to the caller of the script. A status code of \texttt{0} indicates no error. If the status code is omitted, the status of the last command executed by the script is returned. As a result, it's always best to supply an exit status.

```
```
exit 0 # all is well
```
```

A script automatically stops when it reaches its end as if there was an implicit \texttt{exit} typed there, but the \texttt{exit} status is the status of the last command executed.

The \texttt{suspend} command likewise unconditionally stops a script. However, unlike \texttt{exit}, execution is suspended until the script is signaled to wake up and resume the next statement after the \texttt{suspend} command.

```
```
suspend # wait until notified otherwise
```
```

This command is discussed in more detail later in Chapter 10, “Job Control and Signals.”

There is also a Linux utility called \texttt{sleep}. Sleep suspends the script for a specific number of seconds after which it wakes up and resumes the next statement after the \texttt{sleep} command.

```
```
sleep 5 # wait for 5 seconds
```
```

Sleep is useful for placing pauses in the script, enabling the user to read what's been displayed so far. Sleep isn't suitable for synchronizing events, however, because how long a particular program runs on the computer often depends on the system load, number of users, hardware upgrades, and other factors outside of the script's control.

# ## Reading Keyboard Input

The built-in \texttt{read} command stops the script and waits for the user to type something from the keyboard. The text typed is assigned to the variable that accompanies the \texttt{read} command.

```
```
print "Archive files for how many days? "
read ARCHIVE_DAYS
