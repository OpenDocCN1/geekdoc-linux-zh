
The input chain must be configured to use the user-defined chains as follows:

```bash
# ipchains -A input -d 192.115.144.17 -j ext-if
# ipchains -A input -d 192.115.144.14 -j dmz-if
# ipchains -A input -d 10.0.0.1 -j priv-if
```

## DEFINE THE ext-if CHAIN

The ext-if chain is set up as follows:

```bash
# ipchains -A ext-if -i ! eth0 -j DENY
# ipchains -A ext-if -p TCP --dport 61000:65096 -j ACCEPT
# ipchains -A ext-if -p UDP --dport 61000:65096 -j ACCEPT
# ipchains -A ext-if -p ICMP --icmp-type pong -j ACCEPT
# ipchains -A ext-if -j icmp-err
# ipchains -A ext-if -j DENY
```

These rules allow DNS, traceroute, and ping connections from any external network to the firewall machine. Linux IP masquerading code uses destination ports 61000 and above. By default 4096 ports are reserved for this purpose, thus we get the range 61000-65096. Therefore we have the rules to accept all UDP and TCP packets marked with these destination ports.

## DEFINE THE dmz-if CHAIN

The dmz-if chain is set up as follows:

```bash
# ipchains -A dmz-if -i ! eth2 -j DENY
# ipchains -A dmz-if -p TCP -s 192.115.144.1 domain -j ACCEPT
# ipchains -A dmz-if -p UDP -s 192.115.144.1 domain -j ACCEPT
# ipchains -A dmz-if -p ICMP --icmp-type pong -j ACCEPT
# ipchains -A dmz-if -j icmp-err
# ipchains -A dmz-if -j DENY
```

These rules allow DNS replies, ping replies, and ICMP errors to the firewall from the DMZ.

## DEFINE THE priv-if CHAIN

The priv-if chain is set up as follows:

```bash
# ipchains -A priv-if -i ! eth1 -j DENY
# ipchains -A priv-if -p ICMP --icmp-type ping -j ACCEPT
# ipchains -A priv-if -p ICMP --icmp-type pong -j ACCEPT
# ipchains -A priv-if -j icmp-err
# ipchains -A priv-if -j DENY
```

These rules allow the internal interface of the firewall to receive ping replies and traceroute packets.

## UNBLOCK THE input, output, AND forward CHAINS

After all the rules are defined, the blocking rules from the input, forward, and output chains can be removed as follows:

```bash
# ipchains -D input 1
# ipchains -D forward 1
# ipchains -D output 1
```

## CREATE A FIREWALL SCRIPT

After all these rules have been defined, a startup script, `/etc/rc.d/init.d/firewall`, must be created so that the chains and rules are re-created each time you boot your firewall system. You must add a link to this script in rc3.d directory as follows:

```sh
# cd /etc/rc.d/rc3.d
# ln -s /etc/rc.d/init.d/firewall S90firewall
```

> **Note**
> The name S90firewall is an example. Refer to Chapter 4, “Booting Up and Shutting Down,” which explains how to add startup scripts.

The complete script should look like the following, based on the examples used in this chapter:

```sh
#!/bin/bash
PATH=$PATH:/bin:/usr/sbin:/bin:/usr/bin
export PATH
# Set up anti-spoofing
for f in /proc/sys/net/ipv4/conf/*/rp_filter; do echo 1 > $f; done
# Block input, output, and forward chains while firewall \
rules are being installed
iptables -A input -i ! lo -j DENY
iptables -A output -i ! lo -j DENY
iptables -A forward -j DENY
# Load protocol specific special masquerade modules
/sbin/modprobe -a
/sbin/modprobe ip_masq_ftp
/sbin/modprobe ip_masq_raudio
/sbin/modprobe ip_masq_irc
/sbin/modprobe ip_masq_quake ports=26000,27000,27910,27960
/sbin/modprobe ip_masq_cuseeme
/sbin/modprobe ip_masq_vdolive
# Make sure IP source forwarding is turned on
echo "1" > /proc/sys/net/ipv4/ip_forward
# Create user-defined chains
iptables -N prv-dmz
iptables -N dmz-priv
iptables -N ext-dmz
iptables -N priv-ext
iptables -N ext-priv
# Set up the user-defined chains to be called from the forward chain
iptables -A forward -s 10.0.0.0/255.0.0.0 -i eth2 -j priv-dmz
iptables -A forward -s 10.0.0.0/255.0.0.0 -i eth0 -j eth0
iptables -A forward -s 192.115.144.0/255.255.255.240 -i eth1 -j dmz-priv
iptables -A forward -s 192.115.144.0/255.255.255.240 -i eth0 -j ext-dmz
iptables -A forward -i eth2 -j ext-dmz
iptables -A forward -i eth1 -j ext-priv
# Log anything that doesn't match any of these
# This should never happen
iptables -A forward -j DENY -l
```

## IP PORT FORWARDING

IP port forwarding is needed if you must provide access to an internal masqueraded host from the Internet. As a general rule, it is preferable to locate the servers that need access from the Internet in your DMZ network. However, this might not always be possible and you might have to devise a way to access one of your internal masqueraded servers from the external network.

This is best done on Linux kernel 2.2.x, using a tool called ipmasqadm. You must also select the IPPORTFW option when compiling the Linux kernel for the IP port-forwarding feature to be available. You can download the package ipmasqadm-0.4.2.tar.gz from http://juanjox.kernelnotes.org.
