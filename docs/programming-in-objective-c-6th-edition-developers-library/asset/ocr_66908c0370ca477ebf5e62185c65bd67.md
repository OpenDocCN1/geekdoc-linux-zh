You should note some interesting points with respect to the m routine that tests out the a function. In the first call to the function, the value of the variable f , initially set to −1 , is passed. Inside the function itself, this value is assigned to the variable x. Because the result of the i test is TRUE, the statement that negates the value of x is executed, thereby setting the value of x to 1 . In the next statement, the value of x is returned to the m routine where it is assigned to the variable r and is then displayed.

When the value of x is changed inside the a function, this in no way affects the value of the variable f . When f was passed to the a function, its value was automatically copied into the formal parameter x by the system. Therefore, any changes made to the value of x inside the function affect only the value of x and not the value of f . This is verified by the second p call, which displays the unchanged value of f . Make certain you understand that it's not possible for a function to directly change the value of any of its arguments—it can only change copies of them.

The next two calls to the a function illustrate how the result returned by a function can be used in an arithmetic expression. The absolute value of f is added to the absolute value of f and the sum is assigned to the variable r .

The fourth call to the a function introduces the notion that the type of argument that is passed to a function should agree with the type of argument as declared inside the function. Because the function a expects a floating value as its argument, the integer variable i is first cast to type f before the call is made. If you omit the cast operation, the compiler does it for you anyway because it knows the a function is expecting a floating argument. (This is verified by the fifth call to the a function.) However, it's clearer what's going on if you do the casting yourself rather than relying on the system to do the conversion for you.

The final call to the a function shows that the rules for evaluation of arithmetic expressions also pertain to values returned by functions. Because the value returned by the a function is declared to be of type f , the compiler treats the division operation as the division of a floating-point number by an integer. As you recall, if one operand of a term is of type f , the operation is performed using floating arithmetic. In accordance with this rule, the division of the absolute value of −6.0 by 4 produces a result of 1.5.
