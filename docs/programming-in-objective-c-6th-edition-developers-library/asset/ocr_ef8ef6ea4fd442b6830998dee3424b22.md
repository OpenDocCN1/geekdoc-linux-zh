Obviously, you should modify the program to correctly account for this situation. You could put the burden on the calling routine and mandate that it never pass a negative argument to the sqrt function. Although this approach might seem reasonable, it does have its drawbacks. Eventually, you would develop a program that used the sqrt function but which forgot to check the argument before calling the function. If a negative number were then passed to the function, the program would go into an infinite loop as described and would have to be aborted. A much wiser and safer solution to the problem is to place the onus of checking the value of the argument on the sqrt function itself. In that way, the function is “protected” from any program that uses it. A reasonable approach to take is to check the value of the argument x inside the function and then (optionally) display a message if the argument is negative. The function can then immediately return without performing its calculations. As an indication to the calling routine that the sqrt function did not work as expected, a value not normally returned by the function could be returned.

> The square root routine in the standard C library is called sqrt() and it returns a domain error if a negative argument is supplied. The actual value that is returned is implementation-defined. On some systems, if you try to display such a value, it displays as nan, which means not a number.
