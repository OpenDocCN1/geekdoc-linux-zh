You can expand on the notion of the D    macro a little further to allow for both compile-time and execution-time debugging control: Declare a global variable D    that defines a debugging level. All D    statements less than or equal to this level produce output. D    now takes at least two arguments; the first is the level:

```
<u>Click here to view code image</u>
```
   D
   ```
```

If the debugging level is set to 1 or 2, only the first D    statement produces output; if the debugging level is set to 3 or more, both D    statements produce output. The debugging level can be set via a command-line option at execution time as follows:

```
<u>Click here to view code image</u>
```bash
a.out -d1    Set debugging level to 1
a.out -d3    Set debugging level to 3
```
```

Again, if D    is defined to be nothing, the D    calls become null statements.

The following definition provides all the mentioned features, as well as the ability to control the definition of D    at compile time.

```

```

   #
   #
   #
```
```

When compiling a program containing the previous definition (which you can conveniently place inside a header file and include in your program), you either define D    or not. If you compile p    as follows:

```
```bash
$ gcc prog.c
```
```

it compiles in the null definition for D    based on the #    clause shown in the previous preprocessor statements. On the other hand, if you compile your program like this:

```
```bash
$ gcc -D DEBON prog.c
