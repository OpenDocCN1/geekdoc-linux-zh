If many functions in the file need to access the value of i, it is easier to make the declaration just once at the front of the file. However, if only one function or a small number of functions need to access this variable, there is something to be said for making separate declarations in each such function: It makes the program more organized and isolates the use of the particular variable to those functions that actually use it.
When declaring an external array, it is not necessary to give its size. Thus, the declaration
e
enables you to reference a character array t that is defined elsewhere. As with formal parameter arrays, if the external array is multidimensional, all but the first dimension must be specified. Thus, the declaration
e
suffices to declare a two-dimensional external array m that contains 50 columns.

# ### **Static Versus Extern Variables and Functions**

You now know that any variable defined outside of a function is not only a global variable, but is also an external variable. Many situations arise in which you want to define a variable to be global but not external. In other words, you want to define a global variable to be local to a particular module (file). It makes sense to want to define a variable this way if no functions other than those contained inside a particular file need access to the particular variable. This can be accomplished in C by defining the variable to be $ .

The statement
$
if made outside of any function, makes the value of m accessible from any subsequent point in the file in which the definition appears, but not from functions contained in other files. If you need to define a global variable whose value does not have to be accessed from another file, declare the variable to be $. This is a cleaner approach to programming: The $ declaration more accurately reflects the variable’s usage and no conflicts can be created by two modules that unknowingly both use different external global variables of the same name.
