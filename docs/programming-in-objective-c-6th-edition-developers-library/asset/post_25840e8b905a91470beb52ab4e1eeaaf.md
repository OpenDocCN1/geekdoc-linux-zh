## Working with Pointers and Structures

You have seen how a pointer can be defined to point to a basic data type, such as an int or a char. But pointers can also be defined to point to structures. In Chapter 8, "Working with Structures," you defined your date structure as follows:

```c
struct date {
    int month;
    int day;
    int year;
};
```

Just as you defined variables to be of type struct date, as in

```c
struct date t;
```

so can you define a variable to be a pointer to a struct date variable:

```c
struct date *p;
```

The variable p, as just defined, then can be used in the expected fashion. For example, you can set it to point to t with the assignment statement

```c
p = &t;
```

After such an assignment has been made, you then can indirectly access any of the members of the date structure pointed to by p in the following way:

```c
(*p).day = 21;
```

This statement has the effect of setting the day of the date structure pointed to p to 21. The parentheses are required because the structure member operator . has higher precedence than the indirection operator *.

To test the value of month stored in the date structure pointed to p, a statement such as

```c
i = (*p).month;
```

can be used.

Pointers to structures are so often used in C that a special operator exists in the language. The structure pointer operator ->, which is the dash followed by the greater than sign, permits expressions that would otherwise be written as

```c
(*p).month
```

to be more clearly expressed as

```c
p->month
```

So, the previous statement can be conveniently written as

```c
i = p->month;
```

## Structures Containing Pointers

Naturally, a pointer also can be a member of a structure. In the structure definition

```c
struct intPtr {
    int *p1;
    int *p2;
};
```

a structure called intPtr is defined to contain two integer pointers, the first one called p1 and the second one p2. You can define a variable of type struct intPtr in the usual way:

```c
struct intPtr myPtr;
```

The variable myPtr can now be used in the normal fashion, remembering that myPtr itself is not a pointer, but a structure variable that has two pointers as its members.

Program 10.5 shows how the intPtr structure can be handled in a C program.

}

## Linked Lists

The concepts of pointers to structures and structures containing pointers are very powerful ones in C, for they enable you to create sophisticated data structures, such as *linked lists*, *doubly linked lists*, and *trees*.

Suppose you define a structure as follows:

```c
struct linkedList {
    int value;
    struct linkedList *next;
};
```

This defines a structure called linkedList, which contains two members. The first member of the structure is a simple integer called value. The second member of the structure is a member called next, which is a *pointer to a* linkedList *structure*. Think about this for a moment. Contained inside a linkedList structure is a pointer to another linkedList structure. This is a perfectly valid concept in the C language. Now suppose you define two variables to be of type linkedList as follows:

```c
struct linkedList *n1, *n2;
```

You set the next pointer of structure n1 to point to structure n2 by executing the following statement:

```c
n1->next = n2;
```

This statement effectively makes a link between n1 and n2, as depicted in **Figure 10.4**.

![](img/e50cb5e8cc6587186db5746e2ac19394_222_0.png)

Figure 10.4 Linked structures.

Assuming a variable n3 were also defined to be of type struct linkedList, you could add another link with the following statement:

```c
n2->next = n3;
```

This resulting chain of linked entries, known more formally as a linked list, is illustrated in Figure 10.5. Program 10.6 illustrates this linked list.

![](img/e50cb5e8cc6587186db5746e2ac19394_222_1.png)

Figure 10.5 A linked list.

## Program 10.6 Using Linked Lists

Click here to view code image

```c
#include <stdio.h>

struct linkedList {
    int value;
    struct linkedList *next;
};

int main() {
    struct linkedList n1, n2, n3;
    struct linkedList *p;

    n1.value = 1;
    n2.value = 2;
    n3.value = 3;

    n1.next = &n2;
    n2.next = &n3;
    n3.next = NULL;

    p = &n2;
    printf("%d\n", p->value);

    return 0;
}
```

## Program 10.6 Output

2

The structures n1, n2, and n3 are defined to be of type struct linkedList, which consists of an integer member called value and a pointer to a linkedList structure called next. The program then assigns the values 1, 2, and 3 to the value members of n1, n2, and n3, respectively. The next two statements in the program

```c
n1.next = &n2;
n2.next = &n3;
```

set up the linked list, with the next member of n1 pointing to n2 and the next member of n2 pointing to n3. Execution of the statement

```c
printf("%d\n", p->value);
```

proceeds as follows: The value member of the structure pointed to by p is accessed and assigned to the integer variable for printing. Because you set p to point to n2, the value member of n2 is accessed by this statement. Therefore, this statement has the net result of assigning 2 to the output, as verified by the printf call that follows in the program. You might want to verify that the expression `p->value` is the correct one to use and not `p.value`, because the next field contains a pointer to a structure, and not the structure itself. This distinction is important and can quickly lead to programming errors if it is not fully understood. The structure member operator . and the structure pointer operator -> have the same precedence in the C language. In expressions such as the preceding one, where both operators are used, the operators are evaluated from left to right. Therefore, the expression is evaluated as

```c
(p->value)
```

which is what was intended.

The second printf call in Program 10.6 displays the value member that is pointed to by p. Because you set p to point to n2, the contents of n2 are displayed by the program.

As mentioned, the concept of a linked list is a very powerful one in programming. Linked lists greatly simplify operations such as the insertion and removal of elements from large lists of sorted items. For example, if n1, n2, and n3 are defined previously, you can easily remove n2 from the list simply by setting the next field of n1 to point to whatever n2 is pointing to:

```c
n1.next = n2.next;
```

This statement has the effect of copying the pointer contained in n2 into n1, and, because n2 was set to point to n3, n1 is now pointing to n3. Furthermore, because n1 no longer points to n2, you have effectively removed it from your list. Figure 10.6 depicts this situation after the preceding statement is executed. Of course, you could have set n1 pointing to n3 directly with the statement

```c
n1.next = &n3;
```

![](img/e50cb5e8cc6587186db5746e2ac19394_224_0.png)

but this latter statement is not as general because you must know in advance that n2 is pointing to n3. Inserting an element into a list is just as straightforward. If you want to insert a node called n4 after n1 in the list, you can simply set n4 to point to whatever n1 was pointing to, and then set n1 to point to n4. So, the sequence of statements

```c
n4.next = n1.next;
n1.next = &n4;
```
