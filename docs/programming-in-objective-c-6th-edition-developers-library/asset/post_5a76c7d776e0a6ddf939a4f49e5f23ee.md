To set t to point to the first character inside the t array, either the statement `t = &t[0]` or `t = t` can be used. Whichever statement you choose to use is strictly a matter of taste.

The real power of using pointers to arrays comes into play when you want to sequence through the elements of an array. If v is as previously defined and is set pointing to the first element of v, the expression `*v` can be used to access the first integer of the v array, that is, `v[0]`. To reference v through the v variable, you can add 3 to v and then apply the indirection operator: `*(v + 3)`.

In general, the expression `*(v + i)` can be used to access the value contained in `v[i]`. So, to set `v[3]` to 27, you could obviously write the expression `v[3] = 27` or, using v, you could write `*(v + 3) = 27`.

To set v to point to the second element of the v array, you can apply the address operator to v and assign the result to v: `v = &v[1]`.

If v points to `v[0]`, you can set it to point to `v[1]` by simply adding 1 to the value of v: `v = v + 1`.

This is a perfectly valid expression in C and can be used for pointers to any data type.

So, in general, if a is an array of elements of type x, p is of type “pointer to x,” and i and n are integer constants or variables, the statement `p = &a[i]` sets p to point to the first element of a, and the expression `*(p + i)` subsequently references the value contained in `a[i]`. Furthermore, the statement `p = p + n` sets p to point n elements farther in the array, no matter what type of element is contained in the array.

The increment and decrement operators `++` and `--` are particularly handy when dealing with pointers. Applying the increment operator to a pointer has the same effect as adding one to the pointer, while applying the decrement operator has the same effect as subtracting one from the pointer. So, if t is defined as a char pointer and is set pointing to the beginning of an array of chars called t, the statement `t++` sets t pointing to the next character in t, which is `t[1]`. In a similar fashion, the statement `t--` sets t pointing to the previous character in t, assuming, of course, that t was not pointing to the beginning of t prior to the execution of this statement.

It is perfectly valid to compare two pointer variables in C. This is particularly useful when comparing two pointers in the same array. For example, you can test the pointer v to see if it points past the end of an array containing 100 elements by comparing it to a pointer to the last element in the array. So, the expression `v > &v[99]` is TRUE (nonzero) if v is pointing past the last element in the v array, and is FALSE (zero) otherwise. Recall from previous discussions that you can replace the preceding expression with its equivalent `v > v + 99` because v used without a subscript is a pointer to the beginning of the v array. (Remember, it's the same as writing `&v[0]`.)

## A Slight Digression About Program Optimization

It is pointed out that the local variable `a` was not actually needed by the function because you could have explicitly compared the value of `p` to the end of the array inside the `for` loop:

![](img/e50cb5e8cc6587186db5746e2ac19394_237_0.png)

The sole motivation for using `a` was one of optimization. Each time through the `for` loop, the looping conditions are evaluated. Because the expression `a` is never changed from within the loop, its value is constant throughout the execution of the `for` loop. By evaluating it once *before* the loop is entered, you save the time that would otherwise be spent reevaluating this expression each time through the loop. Although there is virtually no savings in time for a 10-element array, especially if the `a` function is called only once by the program, there could be a more substantial savings if this function were heavily used by a program for summing large-sized arrays, for example.

The other issue to be discussed about program optimization concerns the very use of pointers themselves in a program. In the `a` function discussed earlier, the expression `*` is used inside the `for` loop to access the elements in the array. Formerly, you would have written your `a` function with a `for` loop that used an index variable, such as i, and then would have added the value of `a` into `s` inside the loop. In general, the process of indexing an array takes more time to execute than does the process of accessing the contents of a pointer. In fact, this is one of the main reasons why pointers are used to access the elements of an array—the code that is generated is generally more efficient. Of course, if access to the array is not generally sequential, pointers accomplish nothing, as far as this issue is concerned, because the expression `*` takes just as long to execute as does the expression `a`.

## Is It an Array or Is It a Pointer?

Recall that to pass an array to a function, you simply specify the name of the array, as you did previously with the call to the `a` function. You should also remember that to produce a pointer to an array, you need only specify the name of the array. This implies that in the call to the `a` function, what was passed to the function was actually a pointer to the array `v`. This is precisely the case and explains why you are able to change the elements of an array from within a function.

But if it is indeed the case that a pointer to the array is passed to the function, then you might wonder why the formal parameter inside the function isn't declared to be a pointer. In other words, in the declaration of `a` in the `a` function, why isn't the declaration `i` used? Shouldn't all references to an array from within a function be made using pointer variables?

To answer these questions, recall the previous discussion about pointers and arrays. As mentioned, if `v` points to the same type of element as contained in an array called `v`, the expression `*` is in all ways equivalent to the expression `v`, assuming that `v` has been set to point to the beginning of `v`. What follows from this is that you also can use the expression `*` to reference the i-th element of the array `v`, and, in general, if x is an array of any type, the expression `x` can always be equivalently expressed in C as `*`.

As you can see, pointers and arrays are intimately related in C, and this is why you can declare `a` to be of type “array of i’s” inside the `a` function *or* to be of type “pointer to i.” Either declaration works just fine in the preceding program—try it and see.

If you are going to be using index numbers to reference the elements of an array that is passed to a function, declare the corresponding formal parameter to be an array. This more correctly reflects the use of the array by the function. Similarly, if you are using the argument as a pointer to the array, declare it to be of type pointer.
