# D. 常见的编程错误

以下列表总结了 C 语言中一些更常见的编程错误。它们没有按特定顺序排列。了解这些错误有望帮助你在自己的程序中避免它们。

## 1. 分号位置错误。

```c
while (i < 10)
    j = 0;
```

在上面的语句中，由于右括号后的分号位置错误，j 的值始终会被设置为 0。请记住，这个分号在语法上是有效的（它代表空语句），因此编译器不会产生错误。这种类型的错误在 while 和 for 循环中经常发生。

## 2. 混淆运算符 `=` 和运算符 `==`。

这个错误通常出现在 if、while 或 do 语句内部。

```c
if (a = 2)
    printf("always called");
```

前面的语句是完全有效的，其效果是将 2 赋值给 a，然后执行 printf 调用。printf 函数*始终*会被调用，因为 if 语句中包含的表达式的值始终是非零的。（它的值将是 2。）

## 3. 省略原型声明。

```c
int r(int);
```

如果一个函数在程序的后部定义，或在另一个文件中定义，且未明确以其他方式声明，编译器将假设该函数返回 int。此外，编译器将 float 参数转换为 double，将 int、char 和 short 参数转换为 int。不会进行其他参数的转换。请记住，为*所有*你调用的函数（无论是你自己显式调用还是通过在你的程序中包含正确的头文件隐式调用）包含原型声明始终是最安全的做法，即使它们定义在前面。

## 4. 混淆不同运算符的优先级。

*示例*

```c
c = getchar() == EOF;
if (c)
    a = 10;
else
    a = -10;

y = (0 == x) & 1;
```

在第一个示例中，`getchar` 返回的值首先与 `EOF` 的值进行比较。这是因为不等式测试的优先级高于赋值运算符。因此，分配给 `c` 的值是测试的 TRUE/FALSE 结果：如果 `getchar` 返回的值不等于 `EOF`，则为 1，否则为 0。在第二个示例中，整型常量 0 首先与 `x` 进行比较，因为相等测试的优先级高于任何按位运算符。此测试的结果（0 或 1）然后与 `x` 的值进行 AND 运算。

## 5. 混淆字符常量和字符字符串。

在语句

```c
t = 'a';
```

中，单个字符被分配给 `t`。在语句

```c
t = "a";
```

中，指向字符字符串 "a" 的指针被分配给 `t`。在第一种情况下，`t` 通常被声明为 `char` 变量，而在第二种情况下，它应被声明为 `char *` 类型。

## 6. 使用错误的数组边界。

*示例*

```c
for (i = 1; i <= 100; i++)
    a[i] = i;
```

数组的有效下标范围从 0 到元素数减一。因此，前面的循环是不正确的，因为 `a` 的最后有效下标是 99 而不是 100。该语句的作者可能也打算从数组的第一个元素开始；因此，`i` 应初始设置为 0。

## 7. 忘记为字符串的终止空字符在数组中保留额外的位置。

请记住声明字符数组时，使其足够大以容纳终止空字符。例如，如果你想在末尾存储一个空字符，则字符字符串 "abcde" 需要在字符数组中占用六个位置。

## 8. 引用结构成员时混淆运算符 `->` 和运算符 `.`。

请记住，运算符 `.` 用于结构变量，而运算符 `->` 用于结构指针变量。因此，如果 `x` 是结构变量，则使用 `x.m` 来表示 `x` 的成员 `m`。另一方面，如果 `x` 是指向结构的指针，则使用 `x->m` 来表示由 `x` 指向的结构的成员 `m`。

## 9. 在 `scanf` 调用中非指针变量前省略 &。

*示例*

```c
scanf("%d %d", i, j);
```

请记住，`scanf` 调用中格式字符串之后的所有参数都必须是指针。
