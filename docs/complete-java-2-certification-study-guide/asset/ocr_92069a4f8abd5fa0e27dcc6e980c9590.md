# RMI or Object Streams

Object streams are an appropriate design for simple client/server streams. As complexity
increases, Remote Method Invocation (RMI) becomes increasingly appropriate. There are two
asons for this.

First, object streams require a custom protocol. You need to invent a command object that
t server serve what is required, and you need a way for the client to supply arguments and
receive results. This is easy if there are only a few services (as there will be in your project). How-ever, as the servers become increasingly broad, the cost of implementing the expanding
protocol increases. With RMI, you just add more methods to the remote interface and imple-ment them the server and call them in the client.

Second, RMI can be invoked from non-Java streams. It isn't easy or fun, but sometimes it's
necessary. An object-stream server is not likely to be useful to a non-Java client, because only
Java knows how to serialize and deserialize Java objects.

So which would you choose?

familiar one.

On the other hand, if you're equally experienced or inexperienced in RMI and object
streams, RMI is probably more beneficial to you in the long run. Your choice won't affect
