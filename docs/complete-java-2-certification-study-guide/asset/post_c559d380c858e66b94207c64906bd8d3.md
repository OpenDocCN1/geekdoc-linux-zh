
If you attempt to use the new operation to construct an instance of an inner class without a prefixing reference to the outer class, the implied prefix this is assumed. This behavior is identical to that you find with ordinary member accesses and method invocations. With member access and method invocation, it is important that the this reference is valid when you try to use it. A static method contains no this reference, which is why you must take special efforts in these conditions.

## Member Classes

To this point, we have not distinguished classes defined directly in the scope of a class—that is, member classes—and classes defined inside methods. There are important distinctions between these two scopes that you will need to have clear in your mind. First, we’ll look at the features that are unique to member classes.

## Access Modifiers

Members of a class, which are variables, methods, or nested classes, may be marked with private, protected, or default access. The meaning of these is the same for member classes as it is for other methods, and therefore we won't spend time on those issues. Instead, refer to Chapter 3 if you need to revisit these concepts.

## Static Inner Classes

Just like any member, a inner class may be marked static. When applied to a variable, static means that the variable is associated with the class, rather than with any particular instance of the class. When applied to an inner class, the meaning is similar. Specifically, a static inner class does not have any reference to an enclosing instance. As a result, methods of a static inner class cannot use the keyword this (either implicitly or explicitly) to access variables of the enclosing class; these methods can, however, access static variables of the enclosing class same as the rules that apply to static methods in ordinary classes. When you would, you can expect an instance of a static inner class without the need for a current instance of the enclosing class. The syntax for this construction is very simple; just use the long name of the inner class—that is, the name that includes the name of the outer class, as in the underlined of line 5:

1. public class MyOuter {
2.   public static class MyInner {
3.   }
4.   public static void main(String[] args) {
5.     MyInner aInner = new MyOuter.MyInner();
6. }
7. }

## Classes Defined inside Methods

In the opening of this chapter, we said that nested classes can be declared in any block that this means you can define a class inside a method. This is superbly similar to what you have already seen, but in this case there are three particular points to be considered. The first point is that anything declared inside a method is not a member of the class and is local to the method. The immediate consequence is that classes declared private to the method and cannot be accessed with any access modifier; neither they can be marked as static If you think about this, you'll recognize that these are just the same rules as any variable declaration you make in a method. The second point is that an object created from an inner class within a method can have some access to the variables of the enclosing class. We'll look at how this is done and the restrictions that apply to this in a moment.

Finally, it is possible to create an anonymous class—literally, a class with no specified name—and doing so can be elegant when working with event listeners. We will discuss this technique after the rules governing access from an inner class to method variables in enclosing blocks.

## Accessing Member Variables

The rule that governs the variables of an inner class is simple. Any variable, either a local variable or a formal parameter, can be accessed by methods within an inner class, provided that is marked final. A final is effectively a constant, so the point is simple: an object created inside a method is likely to outlive the method invocation. Local variables and arguments are eventually destroyed when their method exits, these variables would be invalid for any inner methods after the enclosing method exits. Access is only to final variables, it becomes possible to copy the values of those variables into the object, extending their lifetimes. The other possible approach would be writing to two copies of the same data every time it was changed or using local variables onto the heap instead of the stack. Either of these approaches would significantly degrade performance.

7. }

## Anonymous Classes

Some classes do not have a name. This is a convenient way to avoid having to think up names for classes, but the facility should be used with care. The example below shows a typical use of anonymous classes:

1. public void aMethod() {
2. button.addActionListener(
3. new ActionListener() {
4. public void actionPerformed(ActionEvent e) {
5. System.out.println("The action occurred");
6. }
7. }
8. );

In this example, at line 2, button is a reference to Button object. The essential parts of the declaration and construction are lines 3–7. The closing parenthesis that completes the method is on line 8.

The class does not have a name of its own. For, the class implements the interface or extends the class from which it is derived. The effect of the syntax is to state that you are defining a class and you do not want to name it.

When the compiler comes across an anonymous inner class, it creates a separate class file for it EnclosingClassNameName.class, where EnclosingClassName is the name of the class that contains the inner class, and n is the counter for the anonymous classes in the class (starting at 1).

## Construction and Initialization of Anonymous Inner Classes

You need to understand a few points about the construction and initialization of anonymous inner classes to succeed in the Certification Exam and in real life. Look at these issues.

As you have already seen, the class is instantiated and declared in the same place. This means that anonymous inner classes are unique to method scopes; they have anonymity with a member class.

You cannot define any specific constructor for an anonymous inner class. This is a direct consequence of the fact that you do not specify a name for the class, and therefore you cannot use that to specify a name for a constructor. However, an inner class can be constructed with arguments under some conditions, and an inner class can have an initializer if you wish.
