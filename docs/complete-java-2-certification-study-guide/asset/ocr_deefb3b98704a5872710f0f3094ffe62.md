# FIGURE 9.6 A Vector and its references

![](bbox=[0.257, 0.149, 0.603, 0.316])

The Vector contains three references and can be drawn as shown in Figure 9.6. When an output stream writes the Vector of Figure 9.6, the three Bytes are serialized. If instead of Bytes the Vector contains objects that have references to still objects, those other objects would also be serialized. In the terminology of serialization, when an object is serialized, then entire graph is serialized. An object's graph is the object itself, plus all the objects it iters, plus all the objects these object references, and so on. When an input stream deserializes an object, the entire graph is deserialized.

Not all objects may be serialized, though this is not obvious from a casual glance at an API page for ObjectOutputStream. The method summary for writeObject() says

```
public void writeObject(Object obj)
```

However, if you read the detail section for writeObject(), you'll see that it throws NotSerializableException if "some object to serialize does not implement the java.io.Serializable interface.\ Even though the method declares that its argument is an object, it contains code for the precondition that the argument must be an instanceof Serializable, and it throws the exception if the precondition is not met. If the object is being passed into the method implements Serializable, the exception might still be thrown. Since the object's graph is serialized, all objects referenced by the object must implement Serializable, and all objects referenced by those must do the same, and so on.

> Recall from Chapter 5, "Flow Control, Assertions, and Exception Handling," in the discussion on assertions that assertions should not be used to check conditions in public methods. Fortunately, writeObject() respects this rule.

You probably recognize the Serializable interface from your reading of the API pages. Most of the core Java classes implement it. All the wrapper classes do so, and so do the collection classes. In fact, the only core Java classes that do not implement Serializable are ones that should not be serialized.
