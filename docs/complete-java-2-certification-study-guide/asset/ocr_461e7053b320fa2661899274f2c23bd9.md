+   1. public void allDragonsSeekTreasure(Vector<Dragon> vec) {

To appreciate the benefits of generic vectors and Iterators, compare the version above to the code that would be required without generics:

+   1. public void allDragonsSeekTreasure(Vector vec) {
2. Iterator driter = vec.iterator();
3. while (driter.hasNext())
4. ((Dragon)driter.next()).seekTreasure();
5. )

Now line 4 requires the more complicated casting syntax, and you have to get the parents right. Moreover, if vec contains an object that is not dragon-compatible, you will get a ClassCastException at line 4. Then you will track down the code with the incompatible object added to the vector. With generics, you never get a ClassCastException, because incompatible objects can get added to the Vector.

The Vector of our examples is one of the classes that implement the L1 interface. All the principles governing declaration, construction, and iteration of a Vector can also be applied to any other class that implements List. Sets can be generic. To declare and construct a generic Set, just use the angle-bracket syntax.

The following code creates a String Set:

```
Set<String> stringSet;
stringSet = new HashSet<String>();
```

Notice that the second line assigns a tree set of strings to a reference which is a type of strings. Generics obey the conversion rules that you learned in Chapter 4. The types declared in the angle brackets (String in class) must be identical, but the types of the generic collections (Set and TreeSet) may be different.
You can use a generic Iterator to retrieve the members of a generic set. The following method uses a generic Iterator to compute the average length of the strings in a generic Set:

```
public float meanStringLength(Set<String> stringSet) {
float totalLengths = 0;
Iterator<String> iter = stringSet.iterator();
while (iter.hasNext())
totalLengths += iter.next().length();
return totalLengths / stringSet.size();
}
```
