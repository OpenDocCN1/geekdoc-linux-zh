# Answers to Review Questions

+   1. C. The assignment is evaluated as if it were

x = a + b; a = a + 1; b = b + 1;

So the assignment to x is made using the sum of 6 + 7, 13. After the addition, the values of a and b are incremented; the new values, 7 and 8, are stored in the variables.

+   2. B. C. In option A, the use of ! is illegal because x is int type, not boolean. In option B, the comparison operation is valid, because the expression (x > 3) is a boolean type the operator can be properly applied to it. In option C, the bitwise inversion operator is legally applied to an integral type.

+   3. A. Option A uses the unsigned right shift, so os are shifted into the most significant positions; any two's-complement number with a 0 in the most significant position is positive. Option B shifts by 32 % 32 = 0, so there is no effect. Option C doesn't compile, "x >>> 5" is an int, which can't be assigned to a variable. Option D applies the signed right shift, so the result is negative.

+   4. A. Options A and C are equivalent. They both add a String to int; the result is assigned to x, whose type is String, the code is legal. Option B doesn't compile because an int and String may not be compared. C is illegal because the last statement tries to assign a String to an int.

+   5. B. When doing arithmetic with a negative left-hand operand, the result is the negative of what it would be if both operands were positive. So - 7 % 5 is the negative of 8 % 5.

+   6. When doing modulo arithmetic with a negative right-hand operand, the result is the same as it would be if the right-hand operand were positive. So 7 % -4 is the same as 7 % 4.

+   7. The XOR operator performs a 1 in bit position where the operands are different. 00001010 ^ 00000101, which is 5.

+   8. In this case, the optional return values for the conditional operator, 99.9 (double) and 9 (int), are of different types. The result of a conditional operator must be fully compiled at time, and in this case they chosen, using the rules of promotion for binary operands, double. Because the result is a double, the output value is in a printing-point format.

If the two argument types are entirely incompatible--for example, (x > 4) ? "Hello" :9--the compiler would have issued an error at that line.

+   10. The Thing class is free to equals() to anything it likes. The method can even return true when comparing the current instance to an instance of Integer.
