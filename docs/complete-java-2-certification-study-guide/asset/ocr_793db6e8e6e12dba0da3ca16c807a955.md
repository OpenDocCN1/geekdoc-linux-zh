# Sets

You've seen that Lists are based on an ordering of their members. Sets have no concept of order. A Set is just a collection of references to objects.

Sets may not contain duplicate elements. If you try to add an element to a Set that already contains it the add() call will return false and the Set will not be changed. A true return might be expected. Sets use the equals() method, not the == operator, to check for duplicates of elements. You might be surprised by the following code:

```
1. void addTwice(Set set) {
2.   set.clear();
3.   Point p1 = new Point(10, 20);
4.   Point p2 = new Point(10, 20);
5.   set.add(p1);
6.   set.add(p2);
7.   System.out.println(set.size());
8. )
```

The Point class in java.awt package is a simple class that contains x and y values. The class' equals() method returns true if the two points have identical x and y values. The Point instances created in lines 2 and 3 are distinct but equal. Sets use equals() to check for membership duplication, line 6 will not affect the Set, and line 7 will print out 1, not 2.

The java.util Set interface extends java.util.Collection but does not add any methods. The most commonly used implementations are java.util.HashSet and java.util.TreeSet. Their names are, unfortunately, they refer to the classes' underlying technologies hash tables and red-black trees and aren't very descriptive of their purpose. It is important to understand the difference between the two, and that you need to understand what it means to iterate over a Set.

When you use a List, the Iterator returns elements in their order of appearance in the List. A List has an inherent sense of order, and it would make sense to present the elements in any other order. But a Set has no order, so how should we return an Iterator performance? We can imagine three possibilities:

+   1. An Iterator could present elements in the order in which they were added to the Set.
2. An Iterator could present elements in an unpredictable order.
3. An Iterator could present elements in some sort of order.

+   Option 1 is not very useful, since Lists already present elements in the order in which they were added. Option 2 is implemented by the HashSet class, and option 3 is implemented by the TreeSet class.
