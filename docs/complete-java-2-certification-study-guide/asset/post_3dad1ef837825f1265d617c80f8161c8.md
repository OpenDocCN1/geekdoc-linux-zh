Threads are Java's way of making a single Java Virtual Machine (JVM) look like many machines, all running at the same time. This effect, usually, is an illusion: there is only one JVM and usually only one CPU, the CPU switches among the JVM's various threads to give the impression that there are multiple CPUs. JVM threads work behind the scenes on your behalf, listening for user input, garbage collection, and performing a variety of other tasks.

As a Java programmer, you can choose between a single-threaded and a multithreaded paradigm. A single-threaded Java program has one entry point (the main() method) and one exit point. Instructions are run serially, from start to finish. A multithreaded program has a first entry point (the main() method), followed by multiple entry and exit points for other methods that may be scheduled to run concurrently with the main() method.

Java provides you with tools for creating and managing threads. Threads are valuable for allowing unrelated, loosely related, or tightly related work to be programmed separately and concurrently.

The Certification Exam requires that you be familiar with Java's thread support, including the mechanisms for creating, controlling, and communicating between threads. This chapter begins with some fundamentals of thread programming. After that you'll learn about basic thread control techniques, and then move on to the real heart of the matter: monitor programming.

# Thread Fundamentals

Java's thread support resides in three places:

- The java.lang.Thread class
- The java.lang.Object class
- The Java language and JVM

In this section you'll learn some of the underlying concepts of thread programming, including what really happens when a thread executes, what happens after execution ends, basic thread states, priorities, and daemon threads.

# What a Thread Executes

To make a thread execute, you call its start() method. Doing so registers the thread with a piece of system code called the thread scheduler. The scheduler might be part of the JVM or of the host operating system.

![](img/09f8389b7ae2705d1ab14be2d5e857e3_248_0.png)

The scheduler determines which thread is running on each available CPU at any given time. Note that calling your thread's start() method doesn't immediately cause the thread to run; it just makes the thread eligible to run. The thread must still contend for CPU time with all the others. If all is well, then some point in the future the scheduler will permit your thread to execute.

During its lifetime, a thread spends some time executing and some time in states. In this section we will look at what the thread actually executes, which is the run() method. The question at hand is: when the thread executes, what does it do? You have two choices:

- The thread executes its own run() method.
- The thread executes the run() method of some other object.

If you want the thread to execute its own run(), you must subclass Thread. For example:

```java
public class CounterThread extends Thread {
    public void run() {
        for (int i = 1; i <= 10; i++) {
            System.out.println("Counting: " + i);
        }
    }
}
```

To start the thread, you call the start() method.

Wait, what if you call the run() method instead of start()? If you do that, the run() method is called like any other method, and is executed by the current thread, not by a new thread. This is a common mistake.

Another choice is to implement Runnable. For example, counts from 10 to 1:

```java
public class DownCounter implements Runnable {
    public void run() {
        for (int i = 10; i >= 1; i--) {
            System.out.println("Counting Down: " + i);
        }
    }
}
```

To start this thread, you must pass the instance of Runnable to the Thread constructor and then call start():

```java
DownCounter dc = new DownCounter();
Thread t = new Thread(dc);
t.start();
```

The Runnable interface is often preferred because it allows the class to extend another class. The Runnable interface itself describes a single method:

```java
public interface Runnable {
    void run();
}
```
