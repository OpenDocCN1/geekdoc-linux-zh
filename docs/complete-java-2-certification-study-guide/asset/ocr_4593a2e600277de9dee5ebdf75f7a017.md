Backslashes are tricky. Suppose you want to use "\s" as a delimiter-specifying regular expression. The following code won't work:

```
scanner.useDelimiter("\s");
```

In fact, this line won't compile! The regular expression processor isn't the only on the block that uses backslashes in literal strings. The Java compiler also, and it doesn't recognize "\s" as a escape sequence. The line produces an "illegal escape character"

```
scanner.useDelimiter("\s");
```

The first backslash tells that the second backslash to be accepted and not as an instruction to treat "\s" in a special way. The compiler strips off the first backslash and internally stores "\s". Now suppose you need to scan an input string the tokens might be separated by groups of one or more "\x" character. The input might be "132xxxx555". The scanner as it stands: the output will have several blank lines between "132" and "555". This happens because the scanner sees those consecutive "x"s as delimiters between entries, each of which is printed on its own line.

We need a delimiter-regular expression that represents one or more "\x". The string that we want is one or more, "+" means one or more "\x". The "+" sign is called a quantifier. A quantifier is a symbol in a regular expression that represents a sequence of input characters. The quantifiers you should know for the exam are:

+   * Matches zero or more occurrences of the preceding pattern
+ Matches one or more occurrences of the preceding pattern
? Matches zero or one occurrences of the preceding pattern

If you look at the regular expression (on the API page for java.util.regex, Pattern), you'll see that each of these quantifiers can be made "greedy", "reluctant", or "possessive". The distinction is simple, and the exam requires you to know only about the default behavior, which is "greedy". A greedy quantifier matches the largest character sequence.

You can use parentheses to group characters and then apply a quantifier to the group. As so, for example "(ab)*" matches one or more occurrences of "ab", as "abab" or "abababab.
