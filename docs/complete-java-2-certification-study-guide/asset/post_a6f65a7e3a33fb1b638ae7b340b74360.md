## The Object Class

The Object class is the ultimate ancestor of all Java classes. If a class does not contain the extends keyword in its declaration, the compiler builds a class that extends directly from Object.
All the methods of Object are inherited by every class. Three of these (wait(), notify(), and notifyAll()) support thread control, and they are discussed in detail in Chapter 7, "Threads". Two other methods, equals() and toString(), provide little functionality on their own. The intention is that programmers develop reusable classes can override equals() and toString() in order to provide class-specific functionality.
The signature of equals() is

```
public boolean equals(Object object)
```

The method is supposed to provide "deep" comparison, in contrast to the "shallow" comparison provided by the == operator. To see the difference between the types of comparisons, consider the java.util.Date class, which represents a moment in time. Suppose you have two references of Date: d1 and d2. One way to compare them is with the following line of code:

```java
if (d1 == d2) {
}
```

The comparison will be true if the reference in d1 is equal to the reference in d2. Of course, this is the only case when variables refer to the same object.
Sometimes you want a different kind of comparison. You know they are different objects. What we care about is the two objects, which encapsulate date and time information, represent the same moment in time. In this case, you don't want the shallow reference-level comparison of ==; you need to deeply look into the objects. The way to do that is with

```
d1.equals(d2)
```

The version of equals() provided by the Object class is not very useful because it just does an == comparison. All classes should override equals() so that it performs a useful comparison. just is what most of the standard classes do; they represent the relevant information objects.

The purpose of the toString() method is to provide a string representation of an object's state. This method is useful for debugging.
The toString() method is similar to equals() in that version provided by the Object class is not especially useful—it prints the object's class name, followed by a hash code. Many classes override toString() to provide more information. Java's string-concatenation facility makes use of this method, as you will see later in this chapter, in the "String Concatenation The Easy Way" section.

The Object class provides a clone method, which returns a copy of the current object. In other words, the clone has the same class as the original, and all its values are identical. Thus all references in the clone point to the same objects as those pointed to in the original. Object's version of clone() is protected, so a class clone() may not be called by any code anywhere. If you want a class clone() to be public, you need to insert something like the following:

```
```java
public Object clone()
    throws CloneNotSupportedException {
    return super.clone();
}
```
```

Notice the CloneNotSupportedException. It is a runtime exception, so it must be dealt with classes that override clone() generally declare that they implement java.lang.Cloneable, which defines the single clone() method.
The Cloneable interface is a marker interface.
