# Common-Sense GUI Design 471

Our last principle of GUI design can be called "disabling the impossible." A GUI should make it impossible for a user to configure a request that the GUI cannot fulfill. As a simple example, think about typing a credit card number into a web page. What would you type the first digits? A space? A hyphen? The next digits? Have you guessed wrong and had to wait for an error-message page that tells you that without entering the required format? Then you have to remember what format you typed into the original page, which is now gone forever. It would be better if the error-message page told you how your format was wrong. It would be better if the original form page made it impossible to type a bad format, either by accepting all formats, or by best of all, by prompting you as in Figure 14.6.

In the figure, it's obvious that the groups of digits are separated by hyphens, and it's equally obvious that the user shouldn't type any hyphens-because they're already there. The ultimate in user-friendliness would be if the field accepted only digits as input.

Another example, consider a form for ordering ice cream. Suppose online ice cream stands only chocolate, vanilla, and strawberry. Figure 14.7 would be the wrong way to prompt for input.

What happens if the user uses an unavailable flavor or misspells an available flavor, as in the figure? This kind of GUI usually flashes a dialog box that says something irritating like, "Flavor unavailable, please try again." This is a waste of the user's time. The GUI should make it impossible to specify an unavailable flavor or to miss an available one. Since the program already has access to the list of available flavors, it should present users with all legal options and allow them to choose from those options. This can be done with a combo box if there are a group of radio buttons as shown in Figure 14.8.
