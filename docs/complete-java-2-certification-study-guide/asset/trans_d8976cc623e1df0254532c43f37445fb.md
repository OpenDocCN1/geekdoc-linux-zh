

# JTable 379

在第 4 级修改表格的值和控制器。Swing 使用“渲染器”（renderer）一词指代实现功能的代码，使用“编辑器”（editor）一词指代实现控制器功能的代码。如果你查看 javax.swing table 包的 API 页面，你会发现名为 `TableCellEditor` 和 `TableCellRenderer` 的接口。第 4 级是本书的范围，此外你在考试作业中也会它们。

让我们回到第 2 级，即子类 `AbstractTableModel`。该类包含三个抽象方法，要创建你自己的模型类，只需要实现这三个方法：

- public int getRowCount()
- public int getCellCount()
- public Object getValueAt(int rowNum, int colNum)

前两个方法返回表格的行数和列数。`getValueAt()` 方法负责提供数据的实际工作。简单的模型类使用字符串二维数组来存储值。但请注意，方法的返回类型是 `Object`，而不是 `String`。通常情况下，返回的值将字符串，如果它们不是，表格的视图将调用它们的 `toString()` 方法或其他某些类的方法；如果将数据存储为 `Integer` 或 `StringBuffer` 的实例更方便，你就不需要担心转换为字符串。

`AbstractTableModel` 实现了一些你可以轻松重写的方法。这些方法是：

- public String getColumnName(int colNum)
- public boolean isCellEditable(int rowNum, int colNum)
- public void setValueAt(Object value, int rowNum, int colNum)

如果你重写了 `getColumnName()`，你就可以为表格的列提供自定义名称。它们将显示为列标题。（稍后我们将看到如何当表格垂直滚动时制作一个滚动表格。）

默认情况下，表格单元格是不可编辑的。如果用户点击并开始打字，什么都不会发生。表格通过调用模型的 `isCellEditable()` 方法来确定哪些单元格可能是可编辑的。`AbstractTableModel` 中的版本返回 `false`。如果你提供了自己的实现，可以让任何你喜欢的单元格变为可编辑。通常，整列要么完全可编辑，要么完全不可编辑。

如果你想通过程序（而不是通过输入）更改表格数据，可以重写 `setValue()`。此操作稍微有点危险。显然，你对该方法的实现应该修改类 'data'。目前还不清楚该方法是否需要做额外工作。当数据更改时，模型的义务是通知组件的其他部分（视图需要知道，可能控制器也需要）。由 `AbstractTableModel` 处理的 JTable 复杂性（在第 2 级操作并远离第 3 级的另一个理由！）在你 `setValue()` 代码存储了新值后，你只需要调用 `TableCellUpdated()`，并传递单元格的行号和列号。如果你查看 JTable 的 API 页面，你会看到有七个方法名以。通过 Swing 支持组件内部通信。通常你应该远离它们。

# 第 11 章 · Swing 组件

如果单元格是可编辑的，当用户按下回车键时（键盘聚焦在可编辑单元格上），模型的 `setValue()` 方法会被调用。
这就是创建你自己的模型类的全部内容了。要创建一个使用自定义模型的表格，请创建模型类的实例并将其传递给 `JTable` 构造函数。让我们来看一个例子。

接下来的模型类有一个构造函数参数，是一个字符串数组。相应的表格有两列。第一列包含按字母顺序排序的字符串。第二列包含字符串的长度。
