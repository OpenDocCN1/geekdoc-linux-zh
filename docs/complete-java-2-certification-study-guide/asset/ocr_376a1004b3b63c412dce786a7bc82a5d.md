Let's get back to level 2, where subclass AbstractTableModel. This class contains three abstract methods, to create your own model class you need only implement three methods:

+   - public int getRowCount()
- public int getCellCount()
- public Object getValueAt(int rowNum, int colNum)

The first two methods return the number of rows and columns in the table. The getValueAt() method does the real work of supplying data. Simple model classes use two-dimensional arrays of strings to values. However, note that the method's return type is Object, not String. In general, returned values will be strings, if they aren't the table's view code will call their toString() method or some other class, if it's more convenient to store data as instances of Integer or StringBuffer you don't need to worry about converting to a string.

There are a few methods that the AbstractTableModel implements that you can easily override. These are:

+   - public String getColumnName(int colNum)
- public boolean isCellEditable(int rowNum, int colNum)
- public void setValueAt(Object value, int rowNum, int colNum)

If you override getColumnName(), you can provide custom names for your table's columns. These appear as column headers. (We'll see how to make a scrolling table in place when the table scrolls vertically. A little later on.)

By default, a table's cells are not editable. If a user uses a click and starts typing, nothing happens. The table determines which cells may be editable by calling the model's isCellEditable(). The version in AbstractTableModel returns false. If you provide your own implementation, you can make editable all cells you like. Usually, an entire column is monolithically editable or not entirely.

If you want to change the table's data programmatically (versus typing), you can override setValue(). This doi is slightly fraught with danger. It is clear that your implementation of this method should modify the class 'data'. It's not obvious that the method needs to do extra. When the data changes, the model's obligation is to notify other parts of the component (the view needs to know, and possibly the controller as well).
