At line 11, the overriding method in the DecoratedRectangle class uses the parental toString method to perform the greater part of its work. Because the variables x, w, and h in the Rectangle class are marked as private, it would have been impossible for the overriding method in DecoratedRectangle to achieve its work directly.

A call of the super.xxx() always invokes the behavior that would have been used if the current method had not defined. It does not matter whether the method is defined in the immediate subclass or in some ancestor class after the hierarchy: super invokes the version of this method that is "next up the tree." To summarize, these are the key points over overriding methods:

+   - A method that has an identical name and identical number, and order of arguments as in a parent class is an overriding method.
- Each parent method may be overridden once in any subclass. (That is, you cannot have two identical methods in the same class.)
- An overriding method must not return exactly the same type as the method it overrides.
- An overriding method must not be less accessible than the method it overrides.
- An overriding method must not throw any checked exceptions (or subclasses of exceptions) that are not declared for the overridden method.
- An overriding method is completely replaced by the overriding method unless the overridden method is directly invoked from the subclass.

# Variable-Length Argument Lists

Prior to Release 5.0, a method declaration specified an exact number of arguments. Release 5.0 allows a method to declare that its argument list includes a variable number of args of a particular type. This is done by appending three dots (...) after the type. For example, here's a method declaration that accepts a variable number of Strings:

```
void xyz(String ... strings)
```

Callers may invoke this method with any number of String arguments (even none at all). Within the method, string appears as an array of Strings.
Many of the core Java classes accept variable argument lists, so keep your eye out for the three dots in method descriptions in the API pages.
