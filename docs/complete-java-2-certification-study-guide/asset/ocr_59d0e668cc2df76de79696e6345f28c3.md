# Answers to Review Questions

+   1. A, C, E. In each of these, the argument list differs from the original, the method is an overload. Overloaded methods are effectively independent, and there are no constraints on the accessibility, return type, or exceptions that may be. B would be a legal overriding method, except that it cannot be defined in the same class as the original method; rather, it must be declared in a subclass. D is also an override, because the types of its arguments are the same: changing the parameter names is not sufficient to count as overloading.

+   2. B, D. A is illegal because it is less accessible than the original method; the fact that it throws exceptions is perfectly acceptable. B is legal because it overrides the method of the parent class, and as such it is not constrained by any rules governing its return value, accessibility or argument. The exception thrown by C is sufficient to make method illegal. D is legal because the accessibility and return type are identical, and the method is an override because the types of the arguments are identical—remember that the names of the arguments are irrelevant. The absence of an exception list in D is not a problem: overriding method may legitimately throw fewer exceptions than its original, but it may throw more.

+   3. E, F. The Cat class is a subclass of Pet, and as such should extend Pet, rather than contain an instance of Pet. B and C should be members of the Pet class and as such inherited into the Cat class; therefore, they should not be declared in the Cat class. D would declare a reference to an instance of the Cat class, which is not generally appropriate inside the Cat (unless, you were asked to give the Cat a member that refers to its mother). Finally, the needed flag and markings descriptions, E and F, are the items called for by the specification; these are correct items.

+   4. The class should be public, because it is to be used freely throughout the application. The statement "A cat is a pet" tells you that the Cat class should subclass Pet. The other words offered are required for the body of the definitions of either Cat or Pet—or use as member variables—are not part of the declaration.

+   5. The first message is produced by the Base class when b1.method(5) is called and therefore Value is 5. Despite the fact that varB is declared as being of the Base class, the behavior that results when method() is invoked it is the behavior associated with the class of the actual object, not with the type of the variable. The object is class Sub; not class Base, the second message is generated by line 3 of class Sub: This value is 6.

+   6. B, C. Because the class has explicit constructors, the default constructor is suppressed, so A is not possible. B and C have argument lists that match the constructors defined at lines 2 and 4 respectively, and so they are correct constructions. D has three integer arguments, but there are no constructors that take three arguments of any kind in the Test class, so D is incorrect. Finally, E is a syntax for construction of inner classes and is therefore wrong.
