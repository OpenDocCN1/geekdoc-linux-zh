# Step 4: Choose Layout Managers

Layout managers are objects that manage the size and location of components. In Java you don't directly program geometry; you choose a layout manager and let take care of the details.

Layout managers are discussed in detail in Chapter 12, for now let's just say that the work of designing a GUI includes deciding how to use layout managers.

# Common Swing Methods

Some properties are common to nearly all component types. These include size, location, foreground and background color, font, and enabled state. The methods that support these properties are described in the following sections. AWT programmers will recognize these methods from the java.awt.Component class, which the Swing components inherit from java.awt.Component.

# getSize() and setSize()

The getSize() method returns the size of a component. The return type is Dimension has public data height and width, whose units are pixels.

The setSize() method takes two arguments: width and height; an overloaded form takes a single Dimension object. If you have tried this method, knowing that doing so is usually futile. A layout manager generally overrides the size and position for you. In fact, the setSize() method exists for the use of managers. The exceptions to this rule are the JFrame and JDialog classes, which are not under the thumb of a layout manager and are perfectly well to have your size or bounds.

# getLocation() and setLocation()

These methods access and set the location of a component in pixel relative to the top-left corner of the component. The return type of getLocation() is Point. The setLocation()'s argument requires width and height ints or a single Point object.

Calling setLocation() is like calling setSize(); usually a layout manager overrides the location you set, but you can always set the location of a JFrame or JDialog.

# setForeground() and setBackground()

This method sets a component's foreground and background color. The argument is an instance of java.awt.Color. The foreground color is used for rendering the component's decorations and text label if the component uses any text). The background color is used for rendering the component's background.

# setFont()

The setFont() method dictates which font component will use for rendering any text it might display. The setFont() method takes one argument of type Font whose constructor takes three arguments: a font family, and a size. The family is a string. Different platforms offer different fonts, but you can count on “Serif”, “SansSerif”, and “Monospaced” a fixed-width font such as Courier. The style may be Font.PLAIN, Font.BOLD, Font.ITALIC, or the bit-width combination Font.BOLD.ITALIC. The size argument defines the point size of the font.

# setEnabled()

The setEnabled method determines whether a component can respond to input. The method takes a single boolean argument. A disabled component changes its appearance to a slightly greyed-out. A component should be disabled if the input is in a state that cannot accept input from the component.

Disabling is preferable to the two commonly seen alternatives:

- Leave the component enabled. When the user uses the component, display some sort of “unavailable” message.
- Remove unusable areas from the screen until they become usable, creating a visually unstable area.

Judicious use of setEnabled() helps create a GUI that clearly reflects the application’s state to the user.

# Container Components

Container components are components that can contain other components (including other containers). Containers use layout managers to determine the size and position of their children. The code examples in this chapter use the very basic FlowLayout manager. If you are unfamiliar with this class, just be aware that it arranges contained components in an evenly spaced row.

The container components that we will cover are

- JFrame
- JPanel

# JFrame

JFrame is an independent window that can be moved around on the screen independently of any other GUI windows. Any application that requires a GUI must have one or more frames to contain the desired components. The following code displays an empty JFrame:

```
1. import java.swing.*;
2.
3. public class FrameDemo {
4.     public static void main(String[] args) {
5.         JFrame f = new JFrame("Frame Demo");
6.         f.setSize(350, 250);
7.         f.setVisible(true);
8.     }
9. }
```

Line 5 demonstrates a constructor whose argument is a string that newly JFrame has zero width and height and must be given a size before it is shown. You can set size explicitly, in line 6, or call pack() which respects preferred sizes and layouts of its components. Line 7 is necessary because a newly created JFrame is not visible on the screen. If, at some point, you want to remove a visible frame from the screen, you can call setVisible(false).

An empty frame is not very useful. Frames are intended to be populated with child components. Readers familiar with Java AWT know that the Frame implementation allows for child components to be directly added. The JFrame class is different in that it is not a container. You access the content portion of the frame by calling the JFrame's getContentPane() method. The following application displays a frame whose content pane contains three buttons. In order to demonstrate application content, we have to get a bit ahead of ourselves by using a layout manager and the JButton class. We will explain these soon.
