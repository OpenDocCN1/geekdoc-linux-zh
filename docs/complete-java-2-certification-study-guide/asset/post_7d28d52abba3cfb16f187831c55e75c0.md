## The StringBuilder and StringBuffer Classes

Java's StringBuilder and StringBuffer classes represent strings that can be dynamically modified.

The most commonly used StringBuilder constructor takes a String as input. You can also construct an empty string buffer (probably with the intention of adding characters to it later). An empty string buffer can have its initial capacity specified at construction time. The three constructors are:

- StringBuilder() Constructs an empty string buffer.
- StringBuilder(int capacity) Constructs an empty string buffer with the specified initial capacity.
- StringBuilder(String initialString) Constructs a string buffer that initially contains the specified string.

A string buffer has a capacity, which is the longest string it can represent without needing to allocate more memory. A string buffer can grow beyond this capacity as necessary, usually you do not have to worry about it. However, it is more efficient to declare a large initial capacity instantiating a string buffer to satisfy all calls required to allocate more memory.

The following list presents some of the methods that modify the contents of a string buffer. All of them return the original string buffer:

**StringBuilder append(String str)** Appends str to the current buffer. Alternative forms supporting primitives and char arrays, which are converted to strings before appending.

**StringBuilder append(Object obj)** Calls to toString() on obj and appends the result to the current buffer.

**StringBuilder insert(int offset, String str)** Inserts str into the current buffer at position offset. There are numerous alternative forms.

**StringBuilder reverse()** Reverses the characters of the current buffer.

**StringBuilder setCharAt(int offset, char newChar)** Replaces the character at offset with newChar.

**StringBuilder setLength(int newLength)** Sets the length of the buffer to newLength. If newLength is less than the current length, the string is truncated. If newLength is greater than the current length, the string is padded with null characters.

The following code shows the effect of using several of these methods in combination:

- 1. StringBuilder sbuf = new StringBuilder("12345");
2. sbuf.reverse(); // "54321"
3. sbuf.insert(3, "aaa"); // "543aaa21"
4. sbuf.append("zzz"); // "543aaa21zzzz"

The StringBuffer class does not override the version of equals() which it inherits from Object. This method returns true only when comparing references to the same object. If two distinct instances encapsulate identical strings, equals() will return false.

One string buffer method that bears mentioning is toString(). You saw earlier in this chapter that StringBuilder has one of these methods. Surprisingly, the string buffer's version just returns the encapsulated string as an instance of String. You will see in the next section that this method plays a crucial role in synchronization of the class.

StringBuffer are threadsafe. If multiple threads make concurrent calls on a single string buffer, this will not become corrupt no matter what combination of calls is made. This is achieved through synchronization of the class.

The StringBuilder class was introduced in 5.0. It is nearly not threadsafe. If you multiple threads have concurrent access to a mutable string, use a StringBuilder. If mutable string will be accessed only by a single thread, there is an advantage to using a string builder, which will generally execute faster than a string buffer.

Both StringBuffer and StringBuilder implement the java.lang.Appendable interface, which specifies several overloaded forms of append(). Later in this chapter, the Formatting Text section shows you how you can use it.

## String Concatenation the Easy Way

The concat() method of the String class and the append() method of StringBuilder give you two strings. Another way to concatenate strings is to use Java's + operator. Similarly, another way to append strings is to use Java's += operator. However, don't forget that you, the programmer, cannot define overloads. String concatenation is useful in many situations—for example, in debugging statements. To print the value of radius, all you have to do is:

```
System.out.println("radius = " + radius);
```

To print the value of dimension, you need to:

```
System.out.println("dimension = " + dimension);
```

It is important to understand how the technique works. At compile time, if either operand of + is a String object, the compiler recognizes that it is in string context. In string context, the + is interpreted as concatenation rather than arithmetic addition. For example, if variable a is a String, the following line of code is string context:

```
a + b + c
```

## Strings

The Java compiler treats the previous code as if it were the following:

```
new StringBuilder().append(a).append(b).append(c).toString();
```

If any of the variables (a, b, or c) is a primitive, the append() method computes an appropriate string. For an object, the append() method uses the string returned from toString() on it. The conversion begins with an empty buffer, then appends each element in turn to the buffer, and finally calls toString() to convert the buffer to a string.

The following code implements a class with its own toString() method:

- 1. class Ab {
2. private int a;
3. private int b;
4. private int c;
5.
6. Ab(int a, int b, int c) {
7. this.a = a;
8. this.b = b;
9. this.c = c;
10. }
11.
12. public String toString() {
13. return "a = " + a + ", b = " + b + ", c = " + c + ";";
14. }
15. }

Now the toString() method (lines 12–14) can be used by any code that wants to take advantage of string concatenation. For example:

```
Abc theAb = new Ab("Here it is: ", 11, 13, 48);
System.out.println(theAb);
```

The output is

Here it is: a = 11, b = 13, c = 48

To summarize the sequence of events for a string context:

- 1. An empty buffer is constructed.
2. Each argument in turn is concatenated to the string buffer, using the append() method.
3. The string buffer is converted to a string by a call to toString().
