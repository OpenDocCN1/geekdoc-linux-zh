## Other Modifiers

In this section, we will discuss Java’s other modifiers, namely:

- final
- abstract
- static
- native
- transient
- volatile
- synchronized

The transient and volatile modifiers are not mentioned in the Certification Exam objectives, so they are just touched on briefly in this chapter. In addition, the synchronized modifier is discussed in more detail in Chapter 7, "Threads".

Unlike the access modifiers, the modifiers listed above are unrelated to one another. Each relates to a distinct programming concept. A feature may have more than one of these modifiers; in this situation the order of appearance of the keywords does not matter.

Not every modifier can be applied to every kind of feature. Table 3.2, at the end of this chapter, summarizes which modifiers apply to which features.

## final

The final applies to classes, variables, and methods. The meaning of final varies from context to context, but the essential idea is the same: final features may not be changed.

A final class cannot be subclassed. For example, the code below will not compile, because the java.lang.Math class is final:

```java
class SubMath extends java.lang.Math { }
```

The compiler error says, "Can't subclass final classes."

A final variable cannot be modified once it has been assigned a value. In Java, final variables play like constants in C++ and #define constants in C. For example, the java.lang.Math class has a final variable, of type double, called PI. Obviously, pi is not the sort of value that should be changed during the execution of a program.

If a final is a reference to an object, it is the reference that must stay the same, not the object. This is shown in the following code:

```java
1. class Walrus {
2.    int weight;
3.    Walrus(int w) { weight = w; }
4. }
5. 
6. class Tester {
7.    final Walrus w1 = new Walrus(1500);
8.    void test() {
9.        w1 = new Walrus(1400); // Illegal
10.       w1.weight = 1800; // Legal
11. }
12. }
```

Here the final variable is w1, declared on line 7. Because it is final, w1 cannot receive a new value; line 9 is illegal. However, the data inside w1 is not final, and line 10 is perfectly legal. In other words,

- You may not change a final object reference variable.
- You may change data owned by an object that is referred to by a final object reference variable.

A final method may not be overridden. For example, the following code will not compile:

```java
1. class Mammal {
2.    final void getAround() { }
3. }
4.
5.
6. class Dolphin extends Mammal {
7.    void getAround() {
```

Dolphins get around in a different way than mammals, so the compiler error at line 7 says "Final methods cannot be overridden."

## abstract

The abstract modifier can be applied to classes and methods. An abstract class cannot be instantiated, but it can be subclassed. An abstract method has no implementation and must be overridden by the first concrete subclass.

Consider the following example of an abstract class:

```java
1. abstract class Shape {
2.    abstract void draw();
3. }
4.
5. class Circle extends Shape {
6.    void draw() {
7.        System.out.println("Drawing a circle");
8.    }
9. }
```

The abstract modifier is used to define a template for subclasses to follow, ensuring consistency across the hierarchy.

The static modifier can be applied to variables and methods. You can think of static features as belonging to a class, rather than being associated with an individual instance. Static methods are not allowed to use the nonstatic features of their class.

The following example shows a simple class with a static variable:

```java
1. class Ecstatic {
2.    static int x = 0;
3.    Ecstatic() { x++; }
4. }
```

Variable x is static; this means there is only one x, no matter how many instances exist. The 4 bytes occupied by x are allocated when Ecstatic is loaded. The initialization to 0 (line 2) also happens at class-load time. The static variable is incremented every time the constructor is called, so it is possible to know how many instances have been created.

You can reference a static variable two ways:
- Via a reference to any instance of the class
- Via the class name

The first method works, but it can result in confusing code and is considered bad form. The following example shows why:

```java
1. Ecstatic e1 = new Ecstatic();
2. Ecstatic e2 = new Ecstatic();
3. e1.x = 100;
4. e2.x = 200;
5. reallyImportantVariable = e1.x;
```

If you don't know x is static, you might think that reallyImportantVariable gets to 100 in line 5. In fact, it gets set to 200, because e1.x and e2.x refer to the same (static) variable. A better way to refer to a static variable is via the class name. The following code is identical to the previous code:

```java
1. Ecstatic e1 = new Ecstatic();
2. Ecstatic e2 = new Ecstatic();
3. Ecstatic.x = 100; // Why did I do this?
4. Ecstatic.x = 200;
5. reallyImportantVariable = Ecstatic.x;
```

Now it is clear that line 3 is useless, and the value of reallyImportantVariable gets to 200 in line 5. Referring to static features via the class name rather than an instance result in source code that more clearly describes what happen at runtime.
