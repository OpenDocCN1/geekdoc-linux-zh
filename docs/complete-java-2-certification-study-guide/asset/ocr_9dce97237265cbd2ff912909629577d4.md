For example, the following code generates a compiler error:

+   1. short s = 259;
2. byte b = s; // Compiler error
3. System.out.println("s = " + s + ", b = " + b");

The compiler error message for the second line will say (among other things), "Explicit cast needs to convert short to byte." Adding an explicit cast is easy:

+   1. short s = 259;
2. byte b = (byte)s; // Explicit cast
3. System.out.println("b = " + b + ");

When this code is executed, the number 259 (binary 100000011) is squeezed into a single byte. This is accomplished by preserving the lower-order byte of the value and discarding the rest. The code prints out the (perhaps surprising) message:

b = 3

The 1 bit in position 8 is discarded, leaving only 3, as shown in Figure 4.5. Narrowing conversions can result in radical value changes; this is why the compiler requires you to cast explicitly. The cast tells the compiler, "Yes, I really want to do it."

Casting a value to a wider value (as shown in Figure 4.3) is always permitted but never required; if you omit the cast, an implicit conversion will be performed on your behalf. However, explicitly casting can make your code a bit more readable. For example

+   1. int i = 2;
2. double radians;
   // Hundreds of
   // lines of
   // code

600. radians = (double)i;

The last line is not required, but it serves as a good reminder to all readers (including yourself) who might have forgotten the type of radians.
Two simple rules govern casting of primitives:

+   * You can cast any non-boolean type to any other non-boolean type.
* You cannot cast a boolean to any other type; you cannot cast any other type to a boolean.

Note that although casting is ordinarily used when narrowing, it is perfectly legal to cast when widening. The cast is unnecessary, but it provides a bit of clarity.
