Overloading is relatively new. Every language that has a type system has used in a way, although most have not allowed the programmer free to use it. Consider the arithmetic operators +, -, *, and /. In most languages, they can be used with integer or floating-point operands. The implementation of, say, multiplication for integer and floating-point operands involves completely different code, yet the compiler performs the same symbol to be used. Because the operand types are different, the compiler can decide version of the operation should be used. This process is known as operator overloading and it is the same principle as method overloading.

It is quite useful to think about using names for related methods and for improving readability, to be able to use one method name for several related implementations. However, you should restrict your use of overloaded method names to situations where the methods you are performing the same basic function with different data sets. Methods that perform different jobs should have different names.

One last point to consider is the return type of an overloaded method. The language treats methods with overloaded names as totally different methods, and as such they can have different return types (you will see shortly that overriding methods do not have this freedom).

# Invoking Overloaded Methods
