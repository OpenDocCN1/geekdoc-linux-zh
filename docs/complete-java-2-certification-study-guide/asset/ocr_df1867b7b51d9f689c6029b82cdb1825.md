# Inner Class Details

Here is a simple public interface:

```
public interface Reporter {
    public void report();
}
```

Write an application that answers the following two questions:

+   1. Suppose an enclosing class contains a non-anonymous inner class, which implements Reporter. Suppose the enclosing class has a method getReporter() with return type Reporter that returns an instance of the inner class. How useful is the returned object? Can it be used outside of the class where it is defined? The external class doesn't know the definition of the inner class and doesn't even know the return type is an instance of the inner class; it only knows it's going to get something that Reporter. The situation seems reasonable. Verify for yourself whether it works. To go further, experiment with different access modes for the inner class.
2. What if the inner class in part 1 is anonymous?

Although for the purpose of naming, being able to define a class inside another class provides some organizational benefit, but this is not the end of the story. Objects that are instances of the inner class generally retain the ability to access the members of the outer class. This behavior is discussed in the next section.
