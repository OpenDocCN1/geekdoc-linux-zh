If no exception is thrown, the try block runs to completion, and then execution continues at the first line after the last catch block. If an exception is thrown, the appropriate catch block executes, and then execution continues at the first line after the last catch block.
There is more to say about catch blocks, but first let's look at a way to handle exceptions without using catch blocks at all.

# # Declaring Exceptions

There is a way to call exception-throwing methods without enclosing the calls in try blocks. A method declaration may end with the `throws keyword`, followed by an exception type, or by multiple types `followed by commas`. A throws declaration may be combined without restriction with any modifiers. Here are some examples:

```
public void throwsOne() throws IOException {

private static synchronized int throwsTwo()
trows IOException, AWTException {
}
```

When a method declares that it throws, any method that throws exception `types listed in the method declaration does not need to appear in a try block`. In the examples above, throwsOne() may contain calls to methods that throw IOException, without enclosing those calls in try blocks. Similarly, within throwsTwo(), any calls to throw IOException or AWTException need not appear in try blocks.
Of course, catch throwsOne() or throwsTwo() must either enclose those calls in try blocks or declare that they, too, throw the exception types.

# # How the JVM Dispatches Exceptions
