# Contracts and Naming Conventions

In programming, as in life, a contract is an agreement about behavior; each party agrees to act in predictable ways and gains the right to expect predictable behavior from the other party. More precisely, a java contract is an agreement that prescribes the behavior of some of a class's methods. Any class honors the contract can expect to interact predictably with other classes.

Java's two most common contracts are the equals contract and the hash code. They describe the expected behavior of any equals() or hashCode() method. If a class's equals() and hashCode() honors the contract, the many useful Java classes can take advantage of which is the Collections framework is described in Chapter 8, “The java.lang and java.util Packages."

The equals contract is described in detail on the API page for java.Object, in which the equals() method. It has several parts, of which most important are

+   * Any object should be equal to itself.
* If x equals y, then y equals x.
* If x equals y and y equals z, then x equals z.

The version of equals() inherited from Object uses the == operator to test for equality. If you override this behavior, the compiler will have no way to know whether your new version honors the contract. Your choices are to make sure it does or to forgo the benefits of, for example, the Collections framework.
