In the remainder of this chapter, you'll look at the Monitor States represented by the cloud at the left of the figure. A monitor is an object that can block and revive threads. The concept is simple, but it takes a bit to understand what monitors are for and how to use them effectively.

The reason for having monitors is that sometimes a thread cannot perform its job until an object reaches a certain state. For example, consider a class that handles requests to write to standard output:

+   1. class Mailbox {
2. public boolean request;
3. public String message;
4. )

The intention of this class is that a client can send message to some value and then set request to true:

+   1. myMailbox.message = "Hello everybody.";
2. myMailbox.request = true;
