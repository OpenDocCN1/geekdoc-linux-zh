In Java, you never explicitly free memory that you have allocated; instead, Java provides automatic garbage collection. The runtime system keeps track of the memory that is allocated and is able to determine whether memory is still usable. This work is usually done in the background by a low-priority thread that is referred to as the garbage collector. When the garbage collector finds memory that is no longer accessible from any live thread (the object is out of scope), it steps to release back into the heap for re-use. Specifically, the garbage collector calls the destructor method finalize(c) (if it is defined) and then frees the memory.

Garbage collection can be done in a number of different ways; each has its advantages and disadvantages, depending on the type of program that is running. A real-time control system, for example, needs to know that nothing will prevent it from recovering quickly to interrupts; this application requires a garbage collector that can work in small chunks or can be interrupted early. On the other hand, a memory-intensive program might work better with a garbage collector that stops the program from time to time recovers memory more urgently as result. Present, garbage collection is hardwired into the Java runtime system; most garbage collection algorithms use an approach that gives a reasonable compromise between speed of memory recovery and responsiveness. In the future, you will be able to plug in different garbage-collection algorithms or different JVMs with appropriate collection algorithms, to your particular needs.

This discussion leaves one crucial question unanswered: When is storage recovered? The answer is that storage is not recovered no longer in use until it's that. Even though you are not using an object longer, you cannot say if it will be collected in 1 millisecond, or 100 milliseconds, or if it will be collected at all. The System.gc() and Runtime.gc() look as if you are the garbage collector, but even these cannot be relied upon in general, because some other thread might prevent the garbage-collection thread from running.
