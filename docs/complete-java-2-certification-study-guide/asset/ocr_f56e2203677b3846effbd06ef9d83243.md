When you iterate over a TreeSet, elements will always be presented in sorted order (Whatever that mean! See below). You might expect that there is a performance cost to be paid for maintaining order. In fact, as you can see in the TreeSet API page, the amount of time required to perform a basic operation on a Tree Set is proportional to the logarithm of the number of elements in the set.

> Don't worry if you've forgotten your high school math. You don't need to remember what a logarithm is. All you have to know is that as a TreeSet's population grows, the time to perform basic operations increases, but not drastically.

The TreeSet class implements the java.util.SortedSet, which extends java.util.Set. The SortedSet interface provides several useful methods that support dealing with sorted data. These include:

**Object first()** Returns this set's first element.

**Object last()** Returns this set's last element.

**SortedSet headSet(Object thru)** Returns a sorted set containing this set's elements through the specified element.

**SortedSet tailSet(Object from)** Returns a sorted set containing this set's elements from the specified element through the end.

**SortedSet subSet(Object from, Object to)** Returns a sorted set containing this set's elements from through to to.

So do you choose which set to use? If you care about iteration order, use a TreeSet and pay the time penalty. If iteration order doesn't matter, use the higher-performance HashSet.

But what does iteration order mean? If a Set contains only instances of Integer or String, you would have elements be presented in numerical or alphabetical order, and indeed that's what would happen. There is nothing magic about this. Sets rely on all their elements implementing the java.lang.Comparable interface, which defines a single method:

```
public int compareTo(Object x)
```

The method returns a positive number if the current object is "greater than" x, by whatever definition of "greater than" the class itself uses to. The method returns a negative number if the current object is "less than" x, and 0 if the current object is "equal to" x. When you add an object to a TreeSet, the TreeSet maintains order by calling compareTo() on its elements and on the object added.
