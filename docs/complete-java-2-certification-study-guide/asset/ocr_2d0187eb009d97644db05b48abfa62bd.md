Two questions remain. First, what is the significance of the value "1.0" that was set as the weight—what is the effect of other values? Second, how can you make more than one row or column stretch? It turns out that these questions are related. If you apply weights to more than one row or column, then the available space is divided among rows or columns. Exactly how it is determined by the weight values.

The values you specify represent a proportion of the whole space; the width (in the case of columns) is the ratio of a column's width to the total of all column weights. If you have three columns weights of 9, 9, and 18, the first two will get one-fourth of the total gain: 9 / (9 + 9 + 18). The third then will get one-half of the extra space for it. Similarly, if you specify the same weight for (7, 7, and 7, for instance), then each column will gain one-third of the total space gained. The calculations hold true for vertical stretches.

Weights can be any number. They do not have to add to 1.0 or 0, but it is generally reasonable to use weights that add to 100 (or thereabouts) so that you can consider the values to be percentages. Just in mind that doing so is not required.

Although it is useful to set weights for rows and columns using a GridBagConstraints object when a component is added, this is not the only nor the best way to do so. Instead, you can use the public variables rowWeights and columnWeights. These variables are both doubles and will act as mechanism for each row or column. It makes little sense from a point of view to see weights for a row or column by means of data when adding a component to a cell.

Using the rowWeights and columnWeights arrays has two advantages. First, it makes much more sense to set the weights this way, and more importantly, it lets you set a weight on a row or column that might not have any component unique in that row or column. Using these arrays in conjunction with the rowHeights and columnWidths allows you to simplify the code of many layouts and to avoid the use of dummy components (a technique you sometimes used in complex GridBag layouts).
