When you create a class that might be serialized, the class should implement Serializable. This is because, the interface doesn't define any methods at all. All you need to do is implement java.io.Serializable in your class declaration, and you're finished. Empty interfaces such as Serializable are known as tagging interfaces. They identify implementing classes having certain properties, without requiring those classes to actually implement any methods. Arrays of primitives or serializable objects are themselves serializable.

Deserializing involves a lot of tricky behind the scenes. The object stream creates a blank instance of the object being deserialized and then sets its field values. In order for that, a bizarre constructor must apply. Think about the class hierarchy of the object. The object itself implements Serializable; the object's parent class might or not implement Serializable. As you work with the inheritance hierarchy, you eventually get to the first superclass that is not serializable. That superclass must have a no-args constructor. Often the first non-serializable class is Object, which has the right kind of constructor. If the condition isn't met, readObject() throws InvalidClassException. The exception message says, "valid constructor."

```
private void writeObject(ObjectOutputStream oos)
throws IOException
private void readObject(ObjectInputStream ois)
throws IOException, ClassNotFoundException
```

Notice the access access. When an object stream executes its writeObject() method, it checks to see if the object has a writeObject method matching the signature. If it is the case, the stream bypasses its default behavior (which is to serialize the object's non-transient fields) and just calls the class's writeObject() method. Similarly, when an input stream executes its readObject() method, it checks to see if the object has a readObject() matching the signature, and if so the ordinary deserialization is bypassed in favor of a call to the readObject() method.

If a class wants its readObject() method to take special action in addition to, rather than instead of, the default serialization behavior, it can call the output stream's defaultwriteObject() method, which serializes the object's non-transient fields. As you might expect, the ObjectInputStream class has a defaultReadObject() method, which deserializes the current object from the object input stream.
