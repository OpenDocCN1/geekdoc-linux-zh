## GridBag's Shorthand

You have undoubtedly seen two features used in GridBag layout examples: RELATIVE and REMAIN. These settings provide a shorthand mechanism designed to reduce typing when you're coding a GridBag layout. They can also simplify maintenance of some types of layout.

If you think back to the earlier examples, you will recall seeing many lines setting values for gridx and gridy. Very often, the value being set is greater by one than the current value; this is often the case in real layouts, too. If you add your components in an orderly fashion, then you will probably set up the component in row zero, column zero first; then do column one, column two; and so on. You could do so using code like:

```
c.gridx++;
```

instead of the explicit name used earlier.

In many cases, if you are filling a layout completely, from top-left to bottom-right, one row at a time, then the shorthand mechanism of RELATIVE and REMAINDER will help. Let's look at a simple example:

```java
import java.awt.*;
import javax.swing.*;

public class Shorthand extends JPanel {
    setLayout(new GridBagLayout());
    GridBagConstraints c = new GridBagConstraints();
    c.fill = GridBagConstraints.BOTH;
    c.weightx = 1;

    add(new JButton('1'), c);
    add(new JButton('2'), c);
    add(new JButton('3'), c);
    add(new JButton('4'), c);
    c.gridwidth = GridBagConstraints.REMAINDER;
    add(new JButton('5'), c);
    c.gridwidth = 1;
    c.weightx = 0;

    add(new JButton('A'), c);
    add(new JButton('B'), c);
```

```java
add(new JButton('C'), c);
c.gridwidth = GridBagConstraints.REMAINDER;
add(new JButton('D'), c);
c.gridwidth = 1;
```

```java
add(new JButton('a'), c);
c.gridwidth = GridBagConstraints.RELATIVE;
add(new JButton('b'), c);
c.gridwidth = GridBagConstraints.REMAINDER;
add(new JButton('c'), c);
c.gridwidth = 1;
```

```java
public static void main(String args[]) {
    JFrame f = new JFrame("GridBag Example 5");
    Shorthand sh = new Shorthand();
    f.getContentPane().add(sh, BorderLayout.CENTER);
    f.setVisible(true);
}
```

The output of this program is shown in Figure 12.34.
Notice that when the GridBagConstraints object is constructed, its values are mostly left constant—not by any value for gridx or gridy; in fact, these values remain at default—RELATIVE throughout the program. It's important to realize that the X and Y control in this example is done entirely with the gridwidth value.
We use REMAINDER in the gridwidth field to indicate the last component on each line. After each line we set gridwidth back to 1, failing to do so would cause every component to be on a line of ones for the rest of the layout.
The component labeled b is interesting, too. You will see that we set a value for gridwidth of RELATIVE for this button. As a result, it fills the space from its starting point to the start of the column. The documentation describes the component as being "last but one." This effect can be useful when you are creating a workspace area and want to have a row of buttons either under or on the right side, as you might for a toolbar.

## Other Layout Options

The five layout managers of the AWT will support most layout schemes you might want to implement. However, it is useful to know a little about the other options. If you are in a situation where Flow, Grid, Border, Card, and GridBag will not create the layout you need, your choices are:

- To find a layout manager from another source
- To create your own layout manager
- To use no layout manager

Finding a third-party layout manager might be simple or hard, depending on the particular behavior you want. Several have been described in books, and are more available as freeware, shareware, or in commercial graphics libraries for Java.
It is beyond the scope of this book to show you how to create your own layout manager over setting a container's layout manager to null is that you no longer have to write code to detect resizing of the container; you just write code implementing the layout policy, and the system will make the right calls at the right time. Writing your own layout manager class implementing the LayoutManager interface (possibly the LayoutManager2 interface).

You always have the option of using no layout manager at all. To do this, call myContainer.setLayout(null);

If a container has no layout manager, it inherits each component's x, y, width and height values. Then, you can setBounds() on a component, add() to a container that has no layout manager, and the component end up where you expect it to be. This approach is tempting, but the first part of this chapter has convinced you that layout managers are simple and efficient to work with. Moreover, if your container resides in a larger container (frame, for example) that gets resized, your layout may need to be redone to prevent components from being overlaid or clipped away. People who set a container's layout manager to null find that they have to write code to detect when the container resizes, and more code to do the right thing when resizing occurs. Doing so ends up being more complicated than creating your own layout manager.

## Summary

Layout managers provide a layer of geometrical support that relieves you of having to specify the size and position of each component. The trade-off is that you must be aware of the layout policy implemented by each of the various layout managers. This chapter has discussed the five AWT layout managers: Flow, Grid, Border, Card, and GridBag. Alternatives to using the layout managers presented here include using a different manager, creating your own, and setting the layout manager to null.
