The declaration and construction start on line 3. Notice that the name of the interface is used immediately after the new keyword. This pattern is used for both interfaces and classes. The class has no visible name of its own in the source but is referred to simply using the class or interface name from which the anonymous class is derived. The effect of this syntax is to state that you are defining a class and you do not want to think up a name for it. For, the class implements the specified interface or extends the specified class without using either implements or extends keyword.

An anonymous class you you convenient way to avoid having to think up trivial names for classes, but the facility should be used with care. Clearly, you cannot instantiate objects of this class except in the code shown. Further, anonymous classes should be small. If the class defines methods other than those of a simple, well-known interface such as an AWT listener, it should probably not be anonymous. Similarly, if the class contains methods more than one or two lines of straightforward code or if the entire class has more than 10 lines, it should probably not be anonymous. These are not absolute rules; however, the point is that if you do not give the class name, you have the "self-documenting" nature of the code to explain what it is for. If, in fact, the code is not simple enough to be genuinely self-documenting, you should probably give it a descriptive name.

When the compiler comes across an anonymous inner class, it creates a separate class file for it EnclosingClassNameName.class, where EnclosingClassName is the name of the class that contains the inner class, and n is the counter for the anonymous classes in the class (starting at 1).

# Construction and Initialization of Anonymous Inner Classes

You need to understand a few points about the construction and initialization of anonymous inner classes to succeed in the Certification Exam and in real life. Look at these issues.

As you have already seen, the class is instantiated and declared in the same place. This means that anonymous inner classes are unique to method scopes; they have anonymity with a member class.

You cannot define any specific constructor for an anonymous inner class. This is a direct consequence of the fact that you do not specify a name for the class, and therefore you cannot use that to specify a name for a constructor. However, an inner class can be constructed with arguments under some conditions, and an inner class can have an initializer if you wish.
