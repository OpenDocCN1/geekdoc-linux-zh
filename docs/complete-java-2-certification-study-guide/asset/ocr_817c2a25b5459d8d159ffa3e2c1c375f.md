A naming convention is a contract that specifies how a method's name relates to its behavior. Java's most important naming convention is the JavaBeans convention (it has nothing to do with Enterprise Java).

The JavaBeans naming convention concerns properties of objects. A property is a quality that is represented by one or more of an object's variables. The convention specifies a discipline for choosing names for properties and the methods that are not used. Examples: bear, inner,

+   A property name has a lowercase letter. All subsequent letters are lowercase except the first letter of a new word. Underscores are not used. Example: normalizedRotationalInertia

+   A method that returns the value of a property is named getX(), where xxx is the property name. Example: getInner()

+   A method that modifies the value of a property is named setX(), where xxx is the property name. Example: setNormalizedRotationalInertia()

If you develop the habit of using the JavaBeans naming convention, the habit will serve you if you decide to pursue the various technologies of J2EE.

# Enums

5.0 introduces the enum, which is a class with certain added functionality and also certain restrictions. Enums are subclasses of java.lang.Enum. They address a problem that is best explained by example. Suppose you are programming a Java-based automatic car. One of the car's tasks will be to respond to an oncoming traffic light. So you decide to create a TrafficLight class to encapsulate a light's red/yellow/green status. Here is one approach:

```
public class TrafficLight {
    private int state; // 1 means read
                   // 2 means yellow
                   // 3 means green

public int getState(){
    return state;
}

```

Assume that the class also contains timing code to change the state at appropriate intervals. That code isn't relevant here.
