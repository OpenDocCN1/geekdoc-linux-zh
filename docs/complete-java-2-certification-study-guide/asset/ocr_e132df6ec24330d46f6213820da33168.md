# TABLE 14.1 Secondary jar Options

| Option | Requires Filename | Function |
| --- | --- | --- |
| -v | no | Verbose |
| -0 (zero) | no | Don't compress |
| -M | no | Don't create a manifest |
| -f | yes | Specifies jar file to create, extract, etc. |
| -m | | Specifies manifest file |

The last jar or manifest filename required by a secondary option, the command line ends with a list of content filenames (*). java in our example). These are the files to be inserted into or extracted from the archive. You don't need to specify them if you're doing a listing or an extraction; if no filenames appear, then jar will list or extract everything in the archive. If you're doing a create, the listed files will be copied into the new archive. If you're doing an update, the listed files will be copied into an existing archive. If a directory's contents are processed recursively.

A jar file may appear in a classpath, in place of a directory name. Thus if you create several packages containing numerous class files, you can ship them to your customers in a single jar archive. Your customers can use them without extracting the archive, which is a messy alternative to keeping everything inside the jar. Leaving classes in a jar is slightly less efficient than extracting them, because the JVM must extract and decompress them before they can be loaded. However, this inefficiency is slight and incurred only once per file; after a class is loaded, its description is inside the JVM and the file never be touched again.

If a jar contains an application's name, you can make the jar executable. This is a nice convenience for your users, because with an executable jar they don't have to remember the name of the main class. To run an executable jar file, you just use the -jar option and name the file on the java command line, like this:

```
java -jar the_executable_archive.jar
```

To make an executable jar, first create a manifest that tells which class file is the main class. To do this, create a text file that contains a line like the following:

Main-Class: x.y.MyMainClass
