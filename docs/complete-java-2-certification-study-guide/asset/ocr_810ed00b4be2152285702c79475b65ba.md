It is important to recognize that objects are always allocated on the heap. Even if they are created in a method using code like

```
public void aMethod() {
    MyClass mc = new MyClass();
}
```



The local variable mc is a reference, allocated on the stack, whereas the object to which that variable refers, an instance of MyClass, is allocated on the heap.
In discussion we are concerned with worry when storage allocation on the heap can be released. Languages require that you, the programmer, explicitly release the storage when you have finished with it. This approach has proven error-prone, because you might release the storage too soon (causing corrupted data if any reference to the data is still in use) or forget to release it altogether (causing a memory storage). Java's garbage collection solves the first of these problems and simplifies the second.
