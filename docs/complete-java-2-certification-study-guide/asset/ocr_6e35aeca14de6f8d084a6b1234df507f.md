# JTree

Like JTable, a JTree is complex enough to warrant its library of support classes. It is becoming more widely used in GUI designs, a drill-down or focus-oriented control, or as an indexing tool for things like e-mail messages, and of course, files.

But JTree is not well-defined as JTable, because it implements the ScrollPane and Accessible interfaces. The primary use for a JTree is outlining a data structure that lends itself to hierarchical order. It could be used to diagram, say, the operations of a recursive descent parser, but it is more readily useful as an indexing tool.

Tree consists of a series of nodes in a single root node, from which other nodes are children nodes. A node that has no children is a leaf node; otherwise it is called a branch node. A node is primarily identified by two ways: by path, the route it links to the root; and by its row, the area it uses for display (similar to a List element).

Aside from defining tree actions for adding and removing nodes, the most common event associated with a tree selection. In the trouble-ticket system, for example, you might want to associate a different display or action with each kind of node. If a user clicks a child of a Reporter node, you might want to display contact information for that person, or perhaps limit the tree to display the items reported by that person.
