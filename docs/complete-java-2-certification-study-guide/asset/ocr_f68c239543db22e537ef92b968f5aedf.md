# Deadlock

The term deadlock describes another class of situations that might prevent a thread from executing. In general terms, if a thread blocks because it is waiting for a condition, and some-else in the program makes it impossible for condition to arise, then the thread is said to be deadlocked.

Deadlock conditions occur for many reasons, but there is one classic example of the situation that is easy to understand. Because it is used as the standard example, this situation has a special name of its own: "deadly embrace".

Imagine a thread trying to obtain exclusive use of two locks that are encapsulated in objects a and b. The first thread gets the lock on object a, and then it proceeds to try to get the lock on object b. This process sounds itself enough, but now imagine that thread already holds the lock on object b. Clearly, the first thread cannot proceed without the second thread releases the lock on object b.lock on object a.

For the nasty part: imagine that the other thread, while holding the lock on object b, is trying to get the lock on object a. This situation is hopeless. The first thread holds the lock on object a and cannot proceed without the lock on object b. Further, the first thread cannot release the lock on object until it has obtained the lock on object b. At the same time, the second-thread holds the lock on object b and cannot release it until it obtains the lock on object a.
