
The new notation says the argument to add() is no longer any Object but must be compatible with the type of the Set.
The notation for addAll() is even stranger. It used to be

```
boolean addAll(Collection c);
```

Now it's

```
boolean addAll(Collection<? extends E> c);
```

So the argument of addAll() is no longer any collection at all. The ?-extends E notation refers to the type of the argument collection. It is defined by the extends key; it doesn't mean the argument Collection's type must extend E, as determined by the instanceof operator. If E is a class, the argument Collection's type might be E or any subclass of E. If E is an interface, the argument Collection's type might be E, or any subclass of E, or any class that implements E. The big idea is that it might be legal, according to the rules of generics, to add every element of the argument Collection to the current Collection.

> One last notation you will encounter on Set's API page

```
Iterator<E>();
```

Here the brackets appear in the return type. This tells you that the method returns a generic Iterator whose type is E.
The angle-bracket notation takes some getting used to, but once you are familiar with it you will be able to fully understand the API pages. If you look at source code for a generic collection class, you'll see that the notation is actually part of the language. If you want to create your own generic class, you can do so by using the angle-bracket notation.

# Generics and Enhanced For Loops

In Chapter 5, “Flow Control, Assertions, and Exception Handling,” you saw how Java's enhanced for loops can iterate over arrays. You also just seen that generics can improve code that iterates over collections. Here you will learn how enhanced for loops make collection processing even easier.

Almost all collection iteration is structured like this:

```
Iterator<SomeClass> iter = myCollection.iterator();
while (iter.hasNext()){
  iter.next().doSomething();
}
```

> Enhanced for loops let you abbreviate this structure by completely hiding the Iterator. As an example, suppose you have a set containing Dragons:

```
HashSet<Dragon> dragons;
```

# Chapter 8 · The java.lang and java.Util Packages

If you want to call sitOnGold() on each dragon in the set, you can now do it like this:

```
for (Dragon d:dragons)
  d.sitOnGold();
```

The code above is ideal compared to the following pre-Java 1.5 code:

```
Iterator iter = dragons.iterator();
while (iter.hasNext()) {
  Dragon d = dragons.next();
  d.sitOnGold();
}
```

The Java 5.0 version is perfectly understandable (once you get used to the colon), it is shorter by 60 percent and eliminates the Iterator and cast. The new syntax is

```
for (type variable_name : collection)
```

The type and variable name form a declaration through the loop, the variable takes on different values. Each pass contains the values of the collection, presented in the order that they appear (This is expected, since an Iterator is created and used as the underlying mechanism, even though it can't be seen). The collection after the colon can be anything that implements the Collection interface: a List, a Set, or a Map. The enhanced for loop, like generic collections, provides a way to write code that is cleaner, less vulnerable to errors, and easier to read.

# Scanning and Formatting

Java contains extensive facilities for dealing with text. The relevant classes reside in the java.lang and java.util packages. Text can present special problems for programmers. Text contains meaning, which is expressed in language, and both meaning and language are deep concepts implicitly involved in what makes us. No wonder computers have trouble with text! The problems fall into two areas: how to extract meaning from existing text and how to create text that contains meaning. One way to address these problems is to get into computational linguistics and dedicate your life to figuring it out. But if your goal is just to pass the exam, all you need to do is learn about Java's facilities for scanning and formatting text.

# Scanning Text

Text scanning is the art of extracting information from text. This can be daunting because text is designed to have its information extracted by humans. Java 5.0 helps by providing a class called Scanner. The API page for this class calls "A scanner which can parse primitives and strings using regular expressions." In this context, parse means to extract strings from natural language. The term scanner is subject to debate. It's easy enough to figure out how to use this class, except for one detail: regular expressions.

Regular expressions are an extensive topic in their own right, dating back to the early days of Unix. You can use a regular expression as a string that encodes a general pattern. For example, the regular expression \s+ matches one or more blank spaces. Encoding a representation for a more sophisticated pattern, such as digits followed by a period, takes considerable effort. If you look at the description of regular expressions in the API (the page for java.util.regex.Pattern), you'll see it is possible to know by heart. So you can treat this as an overview and just use the basic idea. As long as you recognize a simple regular expression you will do fine.

> The description of regular expressions in the API is the Pattern class in the java.util.regex package. This package also contains a class named Matcher. A matcher is an engine that scans input using a pattern to guide its behavior. You rarely ever use these classes directly. Instead, you use classes like Scanner, which in turn use Pattern and Matcher.

![](img/09f839b7ae2705dab14be2d5e857e3_325_0.png)

A scanner breaks up an input into tokens and delimiters. Tokens are parts of a string that have meaning. Delimiters are used to set tokens. For example, if you're trying to extract the numeric values from the comma-separated string "12, 3.1415, 49", then the tokens are 12, 3.1415, and 49, because those are the parts of the string that convey meaning to you. The commas are delimiters.

The Scanner class has a large number of constructors. The simplest one is

```
public Scanner(String source)
```

The source is be scanned for tokens. Other constructor versions specify different text sources, such as files or input streams. After a scanner is constructed, it must know what delimiter or delimiters to use. This is done by calling the scanner's useDelimiter() method, passing in a regular expression that represents the delimiter. For example, suppose your input string consists of integer numbers, separated by x characters. You can set up your scanner as follows:

```
String scanMe = "123x2x3x";
String delim = "x";
```

A regular expression can specify a class or group of characters. This is done by enclosing a specification inside brackets. The expression [aeiou] matches any of the letters a, i, o, or u. Here's a piece of code that uses this expression:

```
String scanMe = "abcdefghijkl";
String delim = "[aeiou]";
Scanner scanner = new Scanner(scanMe);
scanner.useDelimiter(delim);
while (scanner.hasNext())
  System.out.println(scanner.next());
```

The output is:

bcd
fgh
jkl

You can specify a range of characters to be matched by using a hyphen. For example, [a-e] matches any of a, b, c, d, or e. There are several predefined classes. You must be aware of for the exam are:

- \. Matches any character
- \d Matches any digit ("0" – "9")
- \s Matches whitespace character, such as space, tab, or newline
- \w Matches any letter ("a" - "z" or "A" - "Z") or digit

Note the backslashes, which tell the regular expression-processing code that the next character has special rather than literal meaning. There's a difference between "d", which recognizes the fourth letter of the alphabet, and "\d", which recognizes any digit.
