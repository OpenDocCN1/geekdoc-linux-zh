
Neither is sufficient to test for arrays of Object element type like this
if (x instanceof Object[])
because the array may be of a primitive base type, in which case the test will fail.

Although it is not required by the Certification Exam, you might find it useful to know whether an object is in an array without regard to the base type. You can do this using the isArray() method of the Class class. For example, this test returns true if the variable myObject refers to an array: myObject.getClass().isArray().

If the left argument of instanceof is a null value, the instanceof operator simply returns false; it does not cause an exception.

# The Equality Comparison Operators: == and !=

The operators == and != test for equality and inequality, returning a boolean value. For primitive types, the concept of equality is straightforward and subject to motion rules such that, for example, a Float value of 10.0 is considered equal to a byte value of 10. For objects of object type, the "value" is taken as the reference to the object—typically, the memory address. You should not use these operators to compare the contents of objects, such as strings, because they will return true if two references refer to the same object, rather than if the objects have equivalent value. Object comparisons compare the data of two objects, whereas reference comparisons compare the memory locations of two objects.

To achieve a content or semantic comparison, for example, so that two Double objects containing the value 1234 are considered equal, you must use the equals() method rather than the == or !=.

To properly, the equals() method must have been defined for the class of the object you are comparing. To determine whether it has, check the documentation supplied with the JDK, or for third-party classes, produced by Javadoc. The documentation should report that an equals() method is defined for the class and overrides equals() in some subclass. If this is not indicated, then you should assume that the equals() method will not provide a useful content comparison. You also need to know that equals() is defined as accepting an Object argument, but the actual argument must be of the same as the object upon which the method is invoked—that is, for x, equals(y), the y instanceof the-type-of-x must be true. If this is not the case, equals() must return false.

# The Bitwise Operators

The bitwise operators—&, ^, and |—provide bitwise AND, exclusive-OR (XOR), and OR operations, respectively. They are applicable to integral types. Collections of bits are sometimes used to save space or to represent the states of binary inputs.

# Defining an equals() Method

This information is not required for the Certification Exam but is generally of value when writing programs. If you define equals() method in your own classes, you should be careful to observe three rules, or your classes might behave incorrectly in some circumstances. First, the argument to equals() method is an Object; you must avoid the temptation to make the argument specific to the class you are defining. If you do this, you will have overloaded the equals() method, and functionality in other parts of Java APIs that depends on equals() method will fail. Perhaps most significant, lookup methods in containers such as HashMap, will fail. The second rule is that equals() method is commutative: the result of x.equals(y) should always be the same as y.equals(x). The final rule is that if you define equals() method, you should also define hashCode() method. This method should return the same value for objects that compare equal. Minimal acceptable behavior for hashCode() method is simply to return 1. Doing so removes any efficiency gains that hashing would give, forcing HashMap to behave like linked list but at least the behavior is correct. The bitwise operations calculate each bit of their results by comparing the corresponding bits of the two operands on whole numbers, rather than just single digits as to cause confusion.

However, in this calculation, both operand bits are 0, which is the condition that produces a 0 result bit for the OR operation. Programmers usually apply these operators to the bits in integer variables, it is also permitted to apply them to Boolean operands.

# Boolean Operations

The comparison operators behave in fundamentally the same way when applied to arguments of boolean, rather than integral, types. However, instead of calculating the result on a bit-by-bit basis, the boolean values are treated as single bits, with true corresponding to a 1 bit and false to a 0 bit. The general rules discussed in the previous section may be modified like this when applied to boolean values:

- For AND operations, true AND produces true. Any other combination produces false.
- For XOR operations, true XOR produces true, false XOR produces true. Other combinations produce false.
- For OR operations, false OR produces false. Any other combination produces true.
