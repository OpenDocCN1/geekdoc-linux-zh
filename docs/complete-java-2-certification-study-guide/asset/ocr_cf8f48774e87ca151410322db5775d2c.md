Neither is sufficient to test for arrays of Object element type like this
if (x instanceof Object [])
because the array may be of a primitive base type, in which case the test will fail.

Although it is not required by the Certification Exam, you might find it useful to know whether an object is in an array without regard to the base type. You can do this using the isArray() method of the Class class. For example, this test returns true if the variable myObject refers to an array: myObject.getClass().isArray().

# The Equality Comparison Operators: == and =

The operators == and != test for equality and inequality, returning a boolean value. For primitive types, the concept of equality is straightforward and subject to motion rules such that, for example, a Float value of 10.0 is considered equal to a byte value of 10. For objects of object type, the "value" is taken as the reference to the object—typically, the memory address. You should not use these operators to compare the contents of objects, such as strings, because they will return true if two references refer to the same object, rather than if the objects have equivalent value. Object comparisons compare the data of two objects, whereas reference comparisons compare the memory locations of two objects.

To achieve a content or semantic comparison, for example, so that two Double objects containing the value 1234 are considered equal, you must use the equals() method rather than the == or !=.

To properly, the equals() method must have been defined for the class of the object you are comparing. To determine whether it has, check the documentation supplied with the JDK, or for third-party classes, produced byJavadoc. The documentation should report that an equals() method is defined for the class and overrides equals() in some subclass. If this is not indicated, then you should assume that the equals() method will not provide a useful content comparison. You also need to know that equals() is defined as accepting an Object argument, but the actual argument must be of the same as the object upon which the method is invoked—that is, for x, equals(y), the y instanceof the-type-of-x must be true. If this is not the case, equals() must return false.

# The Bitwise Operators

The bitwise operators—, ^, and |—provide bitwise AND, exclusive-OR (XOR), and OR operations, respectively. They are applicable to integral types. Collections of bits are sometimes used to save storage space where several boolean values are needed or to represent the states of a collection of binary inputs from physical devices.
