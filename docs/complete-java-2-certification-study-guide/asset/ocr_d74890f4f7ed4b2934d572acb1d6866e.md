# Thread Priorities

Every thread has a *priority*, which is an integer from 1 to 10; threads with higher priority should get preference over threads with lower priority. The scheduler considers the priority when it decides which thread should execute. The scheduler chooses the highest-priority waiting thread. If more than one thread is waiting, the scheduler chooses one of them. There is no guarantee that the thread chosen will be the one that runs longest.

The default priority is 5, but all newly created threads have their priority set to that of the creating thread. By using `thread.setPriority()`, you can set the new priority. The `getPriority()` method returns the current priority of the thread. The following code example avoids hard-coding the value 10, and instead uses `MAX_PRIORITY`. The Thread class defines `MIN_PRIORITY` (which is 1) and `NORM_PRIORITY` (which is 5).

+   1. int oldPriority = thread.getPriority();
2. int newPriority = Math.min(oldPriority, MAX_PRIORITY);
3. thread.setPriority(newPriority);

The specifics of how thread priorities affect scheduling are platform dependent. The Java specification states that threads must have priorities, but it does not dictate precisely what the scheduler should do about them. This vagueness is a problem: algorithms that rely on manipulating thread priorities might not run consistently on all platforms.

# Daemon Threads

Some threads are daemon threads (Pronounced like "demon", the name comes from the folklore of the early days of Unix). Daemon threads are infrastructure threads, created automatically by the JVM. The garbage collector is a daemon thread, and so is the GUI event-processing thread.

When an application begins, there is only one non-daemon thread, the main thread, which runs `main()` method. Any threads created by daemon threads are initially daemon threads. Threads created by non-daemon threads are initially non-daemon threads. Before a thread begins execution, you can change its daemon status by calling `setDaemon()`. The JVM runs until the only live threads are daemons. In other words, the JVM considers its work to be done when the only remaining threads are its own infrastructure threads.
