The following sections describe code (including class locks and deadlocking), synchronized code, and wait(), notify(), and notifyAll() methods and show how these can be used to make thread code robust.

# The Object Lock and Synchronization

Every object has a lock. At any moment, that lock is controlled by, at most, one single thread. The lock controls access to the object's synchronized code. A thread that wants to execute an object's synchronized code must first attempt to acquire that object's lock. If the lock is available—that is, if it is not already controlled by another thread—then well. If the lock is under another thread's control, then the attempting thread goes into the Seeking Lock state and becomes ready only when the lock becomes available. When a thread owns a lock checking and state-changing is done behind the scenes; the only explicit programming you need to do is to declare code to be synchronized.
