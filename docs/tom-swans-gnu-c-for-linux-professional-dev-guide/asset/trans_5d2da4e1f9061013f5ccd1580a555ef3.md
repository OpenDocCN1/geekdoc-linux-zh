图21.1中的数据对象（如Data1、Data2和Data3）提供了一个返回自身副本的函数。然而，该函数并不会构造一个全新的对象，而只是递增其对象的所有权计数器并返回同一对象。例如，在图21.1中，如果使用Data3构造一个新对象G，该对象的函数会递增Data3的所有权计数器，以表明三个对象拥有该数据。这样，内存中只存在该唯一数据的一个副本。

删除对象也需要特殊处理。再次使用图21.1，如果程序删除对象B，它一定不能同时删除Data2，因为另外两个对象C和D仍然拥有该数据。为了处理B的删除，Data2的析构函数只需递减其所有权计数，将3改为2。类似地，如果删除对象D，Data2的所有权计数器再次从2递减到1，表明只有一个对象拥有它。如果随后删除C，Data2也会被销毁，因为其所有权计数器现在等于1，表示这是该数据的唯一副本，因此可以安全删除。

## 写时复制方法

仅仅依靠引用计数，只是实现安全、高效的对象复制的一半工作。谜题的另一部分涉及对重复对象进行修改时会发生什么。例如，在图21.1中，如果程序将新数据赋给对象D，程序必须采取三个操作：

- 1. 复制一份Data2并将其赋值给D。
- 2. 递减Data2的所有权计数。
- 3. 更改原始数据。

这些就是写时复制方法的基本步骤——对象仅在其数据发生更改时才会被复制。图21.2显示了对象之间的最终组织结构。原始Data2的所有权计数器表明它现在由两个对象B和C拥有。修改后的Data2值（标记为Data2.1）由对象D唯一引用。

TData 类为那些仅在其数据更改时才被复制的对象提供了基础。TData 对象的重复副本由对象自身计数。这个类在这里完全内联实现，它在两个方面与本书中的大多数类有显著不同：

- TData 将另一个类声明为友元。
- TData 的所有成员对该类而言都是私有的。
