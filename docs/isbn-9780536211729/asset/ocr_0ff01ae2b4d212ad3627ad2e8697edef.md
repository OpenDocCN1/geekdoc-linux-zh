ADVANCED_PORTS_UDP variables. List the ports to ignore, either because you will have a real service on them or because you want to ignore the chatter on them, using the ADVANCED_EXCLUDE_TCP and ADVANCED_EXCLUDE_UDP variables. While the documentation gives dire warnings about listening on ports above 1023, I have not found this to be a problem. Of more importance is the fact that a number of vulnerable and commonly attacked services are above this number.

I prefer the advanced stealth mode to the others and find that the following works on a firewall:

```
#Watch 1080 for socks, 2049 for NFS, and 6000 for X
ADVANCED_PORTS_TCP="6010"
ADVANCED_PORTS_UDP="1024"
# Default TCP Ident and NetBIOS service
ADVANCED_EXCLUDE_TCP="113, 139, 37"
# Default UDP route (RIP), NetBIOS, DHCP, NTP, bootp broadcasts.
ADVANCED_EXCLUDE_UDP="520,138,137,67,123,127"
```

The IGNORE_FILE variable's name lists hosts packets you want to ignore completely. If you will be blocking attackers, these will be systems you trust a lot (both the honesty of your Sysadmins and their ability to resist being breached) that need access through your firewall. These might include the SysAdmins' work and home systems if they are well secured. Unlike the Tracer Trap, PortSentinel will not even warn you if these systems attack you. The RESOLVE_HOST variable normally is set to "1" (quotes included) to attempt to resolve the name of the attacking system. This will tell you about the circumstances of the attack. If the host name has random characters in it, it is probably someone's compromised DNS server. If its name is ns2 or dns3 then it is probably someone's If its name is www, you are probably dealing with a compromised web server. If you have a slow DNS server, set it to "0".

The BLOCK_TCP and BLOCK_UDP variables determine whether PortSentinel will operate as an Adaptive Firewall and use. "1" to have PortSentinel do the blocking, "2" to have invoke only the command specified in KILL_RUN_CMD (invoke the Tracer Trap or your own custom IPT/IP chains, or an interface to another firewall for blocking), and "0" to not block. All modes except the Basic TCP mode are subject to forced source IP-address mode DoS attacks. In reality, these are so rare for all the best-known sites that Sysadmins would not worry about the risk.
