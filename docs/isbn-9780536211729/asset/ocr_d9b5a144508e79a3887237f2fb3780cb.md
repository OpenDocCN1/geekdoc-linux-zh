You may configure Tripwire to store the checksum data (and itself) on a floppy. You
then set the floppy to Read/Only to prevent tampering, and of course, arrange for
cron to check the results periodically and e-mail them to you. You might want this e-mail
to be sent to a different system resisting tampering in case this system is cracked. What if
t cracker is really good and he alters your shell or kernel when you instruct
system to run Tripwire, it instead runs a fake Tripwire? Because it is Linux, if you have
already created a set of rescue disks, now is a fine time and the Linux Administrators
Guide explains this.

Rescue disks are a set of floppies with the first one being a self-contained boot-
ernel and the second one being a root file system that gets copied into
RAMDISK, typically containing tools for repairing a corrupt root file system. Its
principal intent is to repair a hard disk root file system that is so badly damaged
that it will not boot.

Many SysAdmins do not take advantage of the ease of creating their own custom
rescue disk. They are quite easy to create. Many systems will boot from CD-
ROM, allowing their use in this way too.
