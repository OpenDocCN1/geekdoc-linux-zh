IP address-MAC address pairs and backs this up to disk (/var/log/eth/) every 15 minutes. If your upstream router is connected to this system via Ethernet, its MAC address should be specified with the -u flag for smart bogon detection.

Normally, Arpatch will fork itself into the background. When a noteworthy event occurs, it uses Syslog to generate a log entry and send an e-mail. A common "gotcha" is to forget to create the database file as a zero-length file. If it does not exist when Arpatch starts up, it generates a log entry with Syslog and exits silently. To the casual observer, this behavior is indistinguishable from correct startup.

When initially configuring Arpatch, do ps -axlw arpatch to see it stayed running. Also, keep in mind that it writes every to the database file (which is viewable with more only every 15 minutes or when sent an interrupt, or HUP signal). If invoked with debugging (-d), it will run in foreground and write messages to standard error instead of generating log messages and e-mail. If you are starting it for the first time on a large network, you may want to debug it until it has built up its database of running systems.

When a new IP address is seen, it will generate an e-mail saying this is a new station. The e-mail includes the IP address, the host name if DNS is successful, the MAC address, the Ethernet card value, and a time stamp. Machines bogons begins either is misconfigured or are hackers on your network. All of these messages warrant investigation, many DHCP configurations will cause positives.

When a packet comes from the Internet through a router, the packet's source IP address will be that of the system on the Internet but will have the router's MAC address. The only way to distinguish it from a router is that Arpatch will that bogons warnings are suppressed if the MAC address matches that of the router, as specified with the -u flag. The -u flag may be used more than once if one's network is not connected via Ethernet (for example, if the firewall is doing its own routing with an internal T1 card), -u should not be used. Arpatch also recognizes that the system it is running on may be a router and assumes that any packet with a MAC address that matches that of one of its interfaces is being routed.

When a hacker takes over a system and is planning on using it for a while to change his IP address to not already in use to make it harder for you to track him down. Do not bother to change the Ethernet address, for if you keep track of system has which MAC address, these problem systems are easy to track down. Even if a hacker changes the MAC address of the NIC, Arpatch will notify you that a new machine has been brought on the network (or that an existing machine has changed its MAC address). You then investigate the cause.
