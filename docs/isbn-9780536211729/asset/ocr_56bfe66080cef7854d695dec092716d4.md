If the system has been running for a long time with no trimming of the log files it could take 10–60 seconds to run the first time. Logcheck tracks how large each log file is when it is being processed, remembers the next time, and does the equivalent of a tail command using its logtail program. The implementation is very efficient: if 10 lines of new text have been added to a 10MB log file then it does a seek to the start of those 10 new lines rather than reading the 10MB. Invoke Logcheck a second to convince you of this. Check your e-mail and pager and ensure that it works. If it complained in each e-mail about the same missing log file that does not exist in your distribution of Linux, simply create the zero-length file with the touch command and chmod to 600.

If you have running IP Tables or IP Chains without Logcheck or other monitoring, you will probably be surprised by the large number of dropped packets. If Windows and DHCP on your network then there will be a lot of chatter that will not be of interest. This could be dealt with by editing your firewall and logging off of the rules that drop these packets. It could take some time to tune the rules to avoid all of this, but this will save you over the long run. In configuring clients around the world, I have noticed about half of the ISP's unintentionally waste clients' bandwidth and the time of those involved in configuring firewalls with things as undesired routing protocol (RIP) packets (on UDP port 520) and indent (on TCP port 113) in response to DNS or SMTP requests. These can and should be dropped or rejected.

The UDP requests certainly should not be trusted, as UDP packets are spoofable and most ISPs do not use the simple antispoofing techniques discussed in this book. The request most likely are due to someone at the ISP not thinking about bandwidth issues during configuration.
