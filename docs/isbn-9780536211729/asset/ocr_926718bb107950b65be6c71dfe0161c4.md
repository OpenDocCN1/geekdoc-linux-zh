# Using PortSentry to Lock Out Hackers

To install the downloaded 1.1 version, do the following:

```
tar -xovf portsentry-1.1.tar.gz
cd portsentry-1.1
```

Have a look at the LICENSE and README* files. Improvements in the 1.1 version include support and bug fixing for the 2.4 kernel and IP Tables and netmask support. The README, COMPAT file lists the compatible platforms, which include Linux and popular versions of UNIX, and OSX for the Mac.

Follow these steps to configure and invoke PortSentry:

+   1. portsentry_config.h. If any of these are not to your liking, now is the best time to change them. The /etc/hosts.deny file is only used if you have selected TCP Wrappers for the Adaptive Firewall option instead of more effective methods, such as IP Tables. If you want to get fancy, you could change the SYSLOG_FACILITY to DAEMON to, per-haps, LOG_LOCAL0, edit /etc/syslog.conf to place these messages in a separate file and monitor them carefully. While "An Example for Automatic Paging" on page 358 explains how to do this, a better solution would be to KILL_RUN_CMD to generate e-mail to your pager.

+   2. portsentry.conf. It is not a shell script but will rule many lines beginning with the # character and blank lines are a = is used to assign a quoted value to a variable. You will want to specify what TCP and UDP ports to trigger and what action to take. While this file is reasonably well-commented, it is important to note that PortSentry only use the variables that apply to the mode of protection selected by command-line flags. It has suggested values that form a good starting point for customizing it for your site. You may need to adjust, depending on what services you offer on your system. If it will be running on the firewall, you probably offer only SSH and Ident.

+   If you are using basic port-bound or the stealth mode then you will need to set the TCP_PORTS variable to the TCP ports to listen for attacks, and you will need to set the UDP_PORTS variable for UDP ports. This is a comma-separated list; spaces and tabs are not allowed. Only the basic mode will actually bind to these ports. The stealth mode will open a raw socket, analyze all incoming traffic containing this system's destination address (and broadcast packets), and react to those in the port list. If you select the basic mode, there is a limit on the number of open ports. On Linux 2.2 and 4 kernels, this limit is normally 1024 open ports. On many UNIX systems, it is 64 per process, including regular files and I/O devices to open.
