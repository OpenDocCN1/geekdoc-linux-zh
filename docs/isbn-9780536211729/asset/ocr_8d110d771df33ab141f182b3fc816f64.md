# 3.8 Doing the Samba

If you want a home directory for the user, change the -d parameter to /home/bob, and make sure that the home directory permissions are 700.

In this configuration, you would want your nswitch.conf file to be

```
passwd: files
shadow: files
group: files
```

This way, the only place that user accounts can be stored on the local machine.

If you have a single Samba server, then this is the most secure way of setting up user accounts. If you have multiple Samba servers, or if you need to synchronize user accounts with another machine, you can use this method, but as the system administrator, you will be responsible for keeping the files in sync manually. Here use rsync and similar tools to keep multiple Samba servers' accounts synchronized, but they can be problematic and there is always a lag before updates propagate, as well as race conditions. The methods described below will help alleviate that problem and make it easier to share a common set of user accounts across multiple machines.

3.8.13.2 NIS and NIS+. NIS and NIS+ are the UNIX standsbys for synchronizing accounts across multiple machines. NIS uses a machine designated as the master server and other hosts on the network pull their user account data from it. It is remarkably effective, but has security problems due to the use of insecure protocol (because RPC runs on UDP). There is a Web site that shows how to run NIS+ securely, as well as NIS can be made to run. It can be found at www.linux-nis.org.

When using NIS, you will still need to find an smpasswd file. As the system administrator, this can be a big job if there are lot of users in the NIS map files. If you are both the NIS administrator and the Samba administrator, be sure that when adding and deleting users from the NIS map files you also make corresponding changes to the smpasswd file. If you have multiple machines you have a lot of work to do with such smpasswd. You may wish to use a perl script for finding the differences between the NIS database and the smpasswd file and deal with them automatically.

Because of security weaknesses in NIS, you will want to have IP Chains or IP Tables for defining which computers on your network have access to the local portmap daemon. However, this will only give you partial security because portmap (RPC) uses UDP, and it is spoofable. Check and double-check that the port daemon is blocked by the firewall to prevent possible exploitation of this historically vulnerable service. Portmap runs on TCP and UDP ports 111.

3.8.13.1 winbind. The winbind daemon is a recent addition in the 2.2 series and went into the standard distribution at version 2.2.3. It allows a Windows domain controller to function as the /etc/passwd and /etc/group file.

There are a few directives that need to be placed in the smb.conf file to enable this behavior. Plus, you will need to start the winbind daemon before you start Samba.
