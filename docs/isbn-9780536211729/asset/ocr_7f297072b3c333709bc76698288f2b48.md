4.7 A TCP server connection request acknowledgment.

Two fields not visible to the packet-filtering level are included in the SYN-ACK header. Along with the ACK flag, the server includes the client's sequence number incremented by the number of contiguous data bytes received. The purpose of the acknowledgment is to acknowledge the data referred referred by its sequence number. The server acknowledges this by incrementing the client's sequence number, effectively saying it received the data, and sequence number plus one is the next data the server expects to receive. The client is free to throw its copy of the original SYN message away now that the server acknowledges receipt of it.

The server also sets the SYN flag in its first message. As with the client's first message, the SYN flag is accompanied by a synchronization sequence number. The server is passing along its own sequence number for its half of the connection.

This first message is the only message the server will send with the SYN flag set. With this and all subsequent messages have the ACK flag set. The presence of the ACK flag in all servers, compared to the lack of ACK flag in the client's first message, will be a critical difference when we get to the information available for constructing a firewall.

Your machine receives this message and replies with its own acknowledgment, after which the connection is established. Figure 4.8 shows a graphical representation of this. From here on, both the client and the server set the ACK flag. The SYN flag will not be set by either program.

With each acknowledgment, the client and server programs increment their partner process's sequence number by the number of contiguous data bytes, plus one, indicating receipt of that, and indicating the next data byte in the stream they expect.
