For example, when debugging a firewall script, I'll create a cron entry to disable the firewall every 2 minutes. I can then safely run the firewall script and find out whether I've locked myself out my SSH session. If indeed I have locked myself out. I merely wait a few minutes for the firewall script to run and shut the firewall down, giving me the opportunity to fix the script and try again.

Furthermore, remember that firewall filters are applied in the order which you define them on the INPUT or OUTPUT chain. The rules are appended to the end of their chain in the order which you define them. The first matching rule wins. Because of this, firewall rules must be defined in a hierarchical order from most specific to more general.

Firewall initialization is used to cover a lot of ground, including defining constants used in the shell script, enabling kernel support services (when necessary), clearing out any existing rules in the firewall chains, defining default policies for the INPUT and OUTPUT chains, reclaiming the loopback interface for normal system operation, denying access from any hosts or networks you have decided to block, and defining some basic rules to protect against bad addresses and to protect certain services running on unprivileged ports.
