
文件描述符（打开的文件号）0、1 和 2 分别是标准输入、标准输出和标准错误。它们都重定向到了 `/dev/null`。标准输入和标准输出指向 `/dev/null` 的存在表明该程序正在作为守护进程运行；也就是说，它是一个长时间运行的进程，不与任何用户终端（tty）相关联。文件描述符 3 是一个套接字，例如网络连接。执行 `netstat -avp` 命令。`netstat` 命令提供网络状态信息。`-a` 标志列出所有打开的网络端口，包括那些当前未连接到远程系统的端口。`-v` 标志增加详细程度。`-p` 标志将使 netstat 列出每个拥有打开网络端口的进程（程序）的 PID 和名称。`-p` 标志是新增的且非常有用，但许多人并不知道它可用。使用 `-p` 标志需要 root 访问权限。执行 `netstat -avp` 时将显示以下内容：

```
Proto Recv-Q Send-Q Local Address Foreign Address State
PID/Program name
...
tcp           0       0 *:1243            *:*         LISTEN
16887//bin/is
...
```

这表明特洛伊木马正在监听 TCP 端口 1243。

> **Foreign Address**（外部地址）字段标识了程序正在与之通信的远程主机和端口，如果存在已建立的 TCP 连接。如果针对入侵者进程显示此信息，那将是其*发起*攻击的系统，或其*通过*你的系统发起攻击的系统。

在此示例中，Foreign Address 字段中仅显示 *:*，表示不存在此类连接。由于协议显示为 *tcp*，这意味着该程序正在作为服务器运行，等待客户端连接。对于使用 1023 以上端口且*未*连接到远程系统知名端口的程序，要保持*极度*警惕。因此，此程序是可疑的。在 1023 以上的端口上，只有少数合法且广泛使用的服务。（1080 用于 SOCKS，6000 用于 X，6010 用于 SSH 封装的 X，2049 用于 NFS 是常见的。）通过执行以下命令双重检查此端口：

```bash
grep 1243 /etc/services
```

`grep` 没有找到任何结果。运行*第 80 页“关闭不需要的服务”中讨论的 `ports` 程序，并观察输出。

```
TCP
Lcl port     Rmt port  Status   Rmt IP   Rmt host
...
*  1243=subseven   0=zero  0A=LISTEN  0.0.0.0  local
*** cracker server
...
```

`ports` 程序根据其默认端口号立即识别出该特洛伊木马。如果你的入侵者选择了更改其版本监听的端口，这可能更具挑战性，尽管 `ports` 会标记处于监听状态下的高端口 TCP 连接。大多数脚本小子甚至不会费心从可执行文件中剥离符号表。在这种情况下，你可以使用通常的调用方式通过 `nm` 程序查看符号。

```
nm suspicious_file | less
```

即使符号表已被剥离，几乎每个程序都包含 ASCII 字符串，这些字符串会提供有关其功能及来源的线索。`strings` 程序搜索可打印字符序列并打印出来。`-a` 标志将打印所有字符串，而不仅仅是文本和数据段中的字符串。典型用法如下

```
strings -a suspicious_file | less
```

它对运行程序也很有用。要分析运行中的进程号 86，请使用以下命令：

```
strings -a /proc/86/exe | less
```

许多更高级的入侵者工具都有帮助消息，暗示其功能。

你可以更大胆地实际单步执行特洛伊木马。在此之前，备份系统是个好主意，因为此时你正在处理一个活动的“炸弹”，它可能会引爆。一旦你使用 `gdb`（或我最喜欢的调试器 `ddd`）附加到它，它就被停止（“冻结”），直到你允许它继续。`ddd` 调试器可从

```
http://www.gnu.org/software/ddd/
```

获取。当 `.genie` 停止时，它无法自行重启，因此在当前时刻创建当前系统的备份或继续其他事情是相对安全的。任何地方都可能有特洛伊木马，因此你应该信任这些都被分析之前不要信任该系统，正如*第 491 页“查找被入侵者修改的文件”中讨论的那样。

如果你确实想要单步执行，你可以 `telnet` 到它。在此示例中，你可以通过不同窗口中的以下命令执行此操作：

```
telnet www.pentacorp.com 1243
```

然后，在 `gdb`（或 `ddd` 窗口）中单步执行代码。在执行前检查每条指令，以确保它不会做有害的事情，例如

```
execl ("rm", "/bin/rm", "-rf", "/", 0);
```

如果有疑问，终止调试会话。最安全的方法是首先执行以下命令。（在我们的示例中，特洛伊木马的 PID 是 16887。）

```
kill -9 16887
```

可以对 *wizbang* 进程进行类似的分析。

### 12.2.1 常见的特洛伊木马

此处讨论了一些最常见特洛伊木马。如果你怀疑自己拥有一个或多个特洛伊木马，它们为搜索特洛伊木马提供了起点，它们还让你对预期的特洛伊木马类型有了“感觉”。关注安全邮件列表、新闻组和网站（均在附录 A 中介绍）至关重要，因为每周都会发现新的漏洞利用。

检测特洛伊木马的一种方式是使用 Tripwire，这在*第 386 页“Tripwire”中有讨论。定期使用 tar -d 或 rpm 也很有效。这两种方法在*第 491 页“查找被入侵者修改的文件”中有讨论。此外，扫描系统中打开的端口，并仔细与*netstat* 或 *ports* 的过往结果进行对比，应能显示任何过去未打开的可疑端口。

- 1. *fingerd* 程序通常被替换为包含特洛伊木马的版本。Tripwire 通常应能检测到这一点，因为 *fingerd* 的完整路径名应在 */etc/inetd.conf* 中指定，或通过其使用 *tcpd* 暗示，且假设 Tripwire 配置为监视所有系统目录。

- 2. *xinetd* 或 *inetd* 进程是互联网“超级服务器”守护进程，基于远程系统的请求启动大多数网络服务。一旦入侵者拥有 root 访问权限，使用 *inetd* 创建特洛伊木马非常容易且快速。以 root 身份运行的入侵者只需做的是

```
echo ingreslock stream tcp wait root /bin/sh -i > /tmp/tim
/usr/sbin/inetd /tmp/tim
/bin/rm /tmp/tim
```

创建 *xinetd* 特洛伊木马几乎同样容易。*ingreslock* 服务似乎很流行；也许某些防火墙允许它。然而，任何未使用的 TCP 服务都可以使用。当然，因为入侵者需要 root 权限才能创建此后门，他可以添加新的服务名称到 */etc/services* 或更改现有服务的端口号。

检测此妥协的最佳方式是知道你的系统上*应该*运行哪些服务，并每天或每周使用 *ports* 或 *netstat -atupv*，可能与存储在文件中的过往结果进行比较。

当然，你可以像入侵者那样通过以下方式测试漏洞利用

```
telnet yoursys.com ingreslock
```

看看是否能获得 root shell，但这可能很危险。虽然上述特洛伊木马很简单（虽然绝非无害），但后续版本可能需要密码，如果未提供正确密码则可能损坏系统。这就是使用不受信任软件的风险所在。

Tripwire *不会*检测到这种妥协，因为 `inetd` 和 `/etc/inetd.conf` 未被修改。你可以通过以下命令计算正在运行的 `inetd` 进程数量

```
ps -axlww | grep inetd | grep -v grep | wc -l
```

但在 `inetd` 在启动请求的服务前执行 `fork` 以进行 `exec` 时，请预期会出现周期性的误报。

注意，使用第二个运行中的 `inetd` 进程使用恶意的 `inetd.conf` 文件，使得入侵者可以以极少的精力或思考投入来实现许多其他漏洞利用。例如，他可以如本节前面所述在系统上安装被修改的 `fingerd`。

然而，为了避免被 Tripwire 和其他文件系统比较方法检测到，他删除了 `/tmp/tim`。

- 3. 一些入侵者会创建一个在 `inetd` 本身中内置了特洛伊木马的 `/usr/sbin/inetd` 可执行文件。通常，此版本将监听额外的 TCP 端口，如 `ingreslock`，并为使用 `telnet` 连接魔法端口的任何人提供 root shell。此特洛伊木马将被 Tripwire 检测到。

然而，入侵者甚至可以从 Tripwire 或 `tar -d` 中隐藏此特洛伊木马。这是通过调用特洛伊木马版本为 `/usr/sbin/inetd`，然后将其从磁盘上删除并将“真实的”版本放回原处来实现的。因此，

```
ls -1 /proc/PID/exe
```

将指回 `/usr/sbin/inetd`，而 Tripwire 将显示 `/usr/sbin/inetd` 与 Tripwire 存储的*校验和*完全相同；同样，如果入侵者将创建时间调回过去，`tar -d` 将显示 `/usr/sbin/inetd` 与备份副本匹配，尽管有些入侵者不会费心这样做。检测此细微问题的一种方式是执行以下命令

```
cmp /proc/PID/exe /usr/sbin/inetd
```

如果入侵者确实从磁盘上删除了可执行文件，`getdel` 脚本将自动检测并提醒你。该脚本在*第 392 页“检测已删除的可执行文件”中有讨论。

- 4. 一些入侵者会安装 `/bin/ls` 和 `/bin/ps` 的版本，其中包含特洛伊木马，不会列出入侵者的任何文件，也不显示入侵者的进程。这种技术被入侵者相当频繁地使用。甚至脚本小子也使用它。当然，Tripwire 会检测到这些特洛伊木马。
