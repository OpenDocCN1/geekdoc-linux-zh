Chapter 5, "Packet-Filtering Concepts," covers the background ideas and concepts behind a packet-filtering firewall. Each built-in chain has its own default policy. Each rule can apply not only to an individual chain, but also to a specific network interface, message protocol type (such as TCP, UDP, or ICMP), and service port or ICMP message type. Individual acceptance, and rejection rules are defined for the INPUT chain and the OUTPUT chain, as well as for the FORWARD chain. The next chapter pulls those ideas together to demonstrate how to build a simple, single-system, custom-designed firewall for your site.

This chapter covers the iptables administration program used to build a Netfilter firewall. For those of you who are familiar with or accustomed to the older ipwad and iptchains programs used with the IPTFW technology, iptables will look very similar to those programs. However, it is much more feature-rich and flexible, and it is very different on subtle levels.

There is indeed difference between iptables and Netfilter, though you'll often hear the terms used interchangeably. Netfilter is the Linux kernel-space program code to implement a firewall within the Linux kernel, either compiled directly into the kernel or included as a set of modules. On the other hand, iptables is the user program used for administration of both Netfilter and iptables. Throughout this text, I will refer to iptables as being inclusive of both Netfilter and iptables, unless otherwise noted.



Because iptables is so different from the previous ipchains, this book won't attempt to cover the older implementation.
