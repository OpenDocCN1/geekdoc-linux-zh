# 2.4.1 Shadowed MD5 Passwords for Good Security

| DANGER LEVEL | 💀 💀 💀 💀 💀 |

As mentioned elsewhere, if a cracker manages to see your encrypted passwords, cracking them becomes much easier. Because of this, modern Linux (and UNIX) systems offer shadowed passwords. Instead of storing the passwords in /etc/passwd, which is readable by everyone, they are stored only in /etc/shadow. This file is readonly by root. Slack has been using shadow passwords by default at least since version 3.4. All major distributions used shadowed passwords automatically now.

Commonly, the transformed password is the result of the DES or MD5 algorithm is referred to as encrypted because someone looking at it will not know what the original password was. To be precise, encrypted means that a nonforce method can be used to determine from what it the original phrase was.

The DES or MD5 algorithm is used to transform a user's entered password what is stored on disk properly is called a hash. Similar to the hash used in compilers and databases, it is a one-way algorithm. This prevents someone from determining the original password easily but if someone subsequently enters the "plain text" password, the system can run the algorithm on this and see it results in the same hash. If it does, the person entered the correct password.

An additional feature on Linux and UNIX is the availability of MD5 password "encryption" (hashes). MD5 passwords solve the weaknesses of DES passwords. DES passwords are limited to 8 significant characters and it uses only 56-bit encryption, which is easy to crack with recent computers. DES also uses 4096 different salt possibilities; MD5 uses 2***18.

Salt causes the hashed passwords of two different users (or the same user on two different systems) to be different, if they enter the same password. It prevents a cracker from hashing a list of common passwords and simply checking against each user's hashed password. Salt is also discussed in "Avoiding Weak and Default Passwords" on page 36.
