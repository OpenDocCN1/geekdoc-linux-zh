# ALLOWING PEER NEWS NEEDS FOR A LOCAL USENET SERVER

A small, home-based site is unlikely to have a peer-to-peer news-feed relationship with an ISP. Although news servers used to be fairly accessible to the general Internet, few open servers are available nowadays of SPAM and server load issues.

If your site is large enough or rich enough to host a general Usenet server, you have to get your news feed from somewhere. The next rules allow your local news server to receive its news feed from a remote server. The local server connects the remote server as a client using the name or address of the host: The only difference between the peer-to-peer news-feed rules and the regular client

```
if [ "$CONNECTION_TRACKING" = "1" ]; then
$IPT -A OUTPUT -o INTERNET -p tcp \\
-s $IPADDR --sport $UNPRIVPORTS \\
-d my.news.feed --dport 119 -m state NEW -j ACCEPT
```

fi

```
$IPT -A OUTPUT -o INTERNET -p tcp \\
-s $IPADDR --sport $UNPRIVPORTS \\
-d my.news.feed --dport 119 -j ACCEPT
```

```
$IPT -A INPUT -i INTERNET -p tcp ! \\
-s <my.news.feed --sport 119 \\
-d IPADDR --dport $UNPRIVPORTS -j ACCEPT
```

# 7.5.3 Telnet (TCP Port 23)

Telnet had been the de facto standard means of remote login over the Internet for many years. As the nature of the Internet community has changed, telnet has come to be viewed more as an insecure service because it communicates in ASCII clear text. If you have the option, you should always use an encrypted service, such as SSH, rather than telnet. However, Microsoft Windows does not offer an SSH service and only offers telnet—so much for security commitment!
