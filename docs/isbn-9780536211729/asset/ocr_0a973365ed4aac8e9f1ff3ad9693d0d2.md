Before going further, I need to introduce the term "bogon" (bo'gon-gon). A packet with an IP address that is incorrect for the subnet it comes from is called a bogon.

To install the enhanced version of Arpacket on your system, mount the CD-ROM and build from the tarball:

```
cp /mnt/cdrom/book/arpacket.bob.tar.gz
zcat arpacket.bob.tar.gz | tar -xovf-
cd arpacket-bob
./configure
make
make install
make install-man
man arpacket
man arp
```

Next, add commands similar to the following to the /etc/rc.d/local file so that it will start automatically on reboot:

```
# "-O"          Enhancement to suppress Apple 0.0.0.0 nonsense
# "-m foo"      Enhancement to mail to foo instead of root
# "-w from"      Enhancement to specify from address (include which office)
# "-u MAC"      Enhancement to specify MAC of our upstream router
               to avoid false positives on bog detection
echo "Starting arpacket on each Ethernet interface"
ARPACKET=/usr/local/sbin/arpacket
ARPARGS="-0 m sysadmin@pentacorp.com"
# Specify MAC address of upstream router, if any
ARPUPS="-u 00:07:4C:92:76:68"
killall arpacket
$PARGS -f /var/log/eth0 -i eth0 -w "arpacket" (NYC:eth0) " \
  $PARGS $ARPUPS
$PARGS -f /var/log/eth1 -i eth1 -w "arpacket" (NYC:eth1) " \
  $PARGS
$PARGS -f /var/log/eth2 -i eth2 -w "arpacket" (NYC:eth2) " \
  $PARGS
```

Finally, initialize its human-readable databases and start it for the first time:

```
cd /var/log
touch eth0 eth1 eth2
chmod 600 eth0 eth1 eth2
/etc/rc.d/local
```

This firewall has both an internal network on eth1 and a DMZ on eth2. The argument to the -w flag will show as the "From" address. as "arpacket" and indicate which of our firewalls is generating the message and which NIC card the packet originated from.
