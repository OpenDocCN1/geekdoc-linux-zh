When root attempts to log in, the login program first consult the configuration file
/etc/security to see whether the tty device that root is trying to log in is listed.
(The leading /dev/ should not be specified in /etc/security.)

If the device is not found in /etc/security, login considers the tty insecure,
charmfully prompts for a password anyway, and then Login incorrect. If there is
no /etc/security file, root might log in from any tty if so is missing there is a

The reason for saying Login incorrect is to prevent someone from trying to guess
root password from an unsecured terminal where he will not be observed and then spend
minimal time on the secure terminal actually logging in and planting a Trojan.

Some sites mistakenly include the following pseudo tty devices in /etc/se-
curety.

```
tty[p-za-e]*
```

This is a dreadful mistake that will allow crackers to guess passwords via telnet
(if telnet is enabled). Many crackers have automatic programs that will grind
away at this until success is reached.

The /etc/security file should be mode 600 or 400 to prevent interlopers from
seeing what their choice of root-capable terminals is. Some distributions incor-
rectly distribute it mode 644, such as Mandrake and Slackware, a quick chmod
fix that problem.
