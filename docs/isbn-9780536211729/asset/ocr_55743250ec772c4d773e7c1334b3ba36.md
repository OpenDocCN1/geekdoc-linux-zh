The shell script sets number of variables. Among these is the location of the iptables command itself. It's important to set this in a variable so that it is explicitly located. There is no excuse for ambiguity with a firewall script. The variable used to repre-sent iptables command in this chapter is $IPT. If you see $IPT, it is a substitute for the iptables command. You could just easily execute the commands from the shell by typing iptables instead of $IPT. However, for use in a script (which is the intention of this chapter), setting this variable is a good idea.

There is great debate over whether it is advisable to compile a custom kernel or stick with the "stock" kernel that comes with a Linux distribution. The debate also includes whether it is inherently better to compile a monolithic kernel (in which everything is com-pled into the kernel) or use a modular kernel. With any debate, there are pros and cons to each method. On the one hand there are those who are (almost always) build their own kernel, sometimes called "rolling their own.". On the other hand, there are those who rarely or never roll their own kernel. There are those who always build monolithic kernels and others who use modular kernels.

Building a custom kernel has a few advantages. First is the capability to compile in only the exact drivers and options necessary for the computer to run. It is great for a server such as a firewall that the hardware rarely, if ever ever changes. Another advantage to com-pling a custom kernel, if you choose a monolithic kernel, the capability to completely prevent some types of attacks against monolithic kernels are possible, they are less common than attacks against modular kernels. Furthermore, when you roll your own kernel you are not confined to the kernel version by the dist-tribution. This enables you to use the latest and greatest kernel, which may include bug fixes for your hardware. Finally, with a custom kernel you can apply additional security enhance-ments to the kernel itself.

Building a custom kernel is not without its own pitfalls. After you roll your kernel, you can no longer use the distribution's kernels and use the updates, but it's likely that the distribution uses an ear-lier version of the kernel that may reintroduce bugs fixed in your custom system. Using a stock kernel also makes it easier to support from the vendor for kernel issues.
