
## addrtype filter TABLE MATCH EXTENSION

The addrtype match extension is used to match packets based on the type of address used, as unicast, broadcast, and multicast. The types of addresses include those listed in Table 6.20.

### Table 6.20 Address Types Used with the addrtype Match

| Name | Description |
| --- | --- |
| ANYCAST | An anycast packet |
| BLACKHOLE | A blackhole address |
| BROADCAST | A broadcast address |
| LOCAL | A local address |
| MULTICAST | A multicast address |
| PROHIBIT | A prohibited address |
| UNICAST | A unicast address |
| UNREACHABLE | An unreachable address |
| UNSPEC | An unspecified address |

Two commands are used with the addrtype match, as listed in Table 6.21.

### Table 6.21 addrtype Match Commands

| Option | Description |
| --- | --- |
| --src-type <type> | Matches for addresses with a source of type <type> |
| --dst-type <type> | Matches for addresses with a destination of type <type> |

## iprange filter TABLE MATCH

Sometimes defining a range of IP addresses using CIDR notation is insufficient for your needs. For example, if you need to limit a certain range of IPs that do not fall on a subnet boundary or only a couple addresses, the iprange match type will do the job.

Using the iprange match, you specify an arbitrary range of IP addresses for the match to take effect. The iprange match can also be negated. Table 6.22 lists the commands for the iprange match.

### Table 6.22 iprange Match Commands

| Command | Description |
| --- | --- |
| [!] --src-range <ip address-ip address> | Specifies (or negates) the range of IP addresses to match. The range is given with a single hyphen and no spaces. |
| [!] --dst-range <ip address-ip address> | Specifies (or negates) the range of IP addresses to match. The range is given with a single hyphen and no spaces. |

## length filter TABLE MATCH

The length filter table match examines the length of the packet. If the packet's length matches the value or optionally falls within the range given, the rule is invoked. Table 6.23 lists the one and only command related to the length match.

### Table 6.23 length Match Command

| Command | Description |
| --- | --- |
| --length<length>[:<length>] | Matches a packet of <length> or within the range <length:length> |

### 6.4.4 NAT Table Target Extensions

As mentioned earlier, iptables supports four general kinds of NAT: source NAT (SNAT); destination NAT (DNAT); masquerading (MASQUERADE), which is a specialized case of the SNAT implementation; and local port direction (REDIRECT) to the local host. As part of the NAT table, each of these targets is available when a rule specifies the nat table by using -t nat specifier.

### SNAT NAT TABLE TARGET EXTENSION

Source Address and Port Translation (NAPT) is the kind of NAT people are most commonly familiar with. As shown in Figure 6.5, Source Address Translation is done after the routing decision is made. SNAT is a legal target only in the POSTROUTING chain. Because SNAT is applied immediately before the packet is sent out, only an outgoing interface can be specified.

Some documents refer to this form of NAT (the most common form) as NAPT, to acknowledge the port modification. The other form of traditional, unidirectional NAT is basic NAT, which doesn't touch the source port. That form is used when you are translating the private LAN and a pool of public addresses.

NAPT is used when you have a single public address. The source port is changed to a free port on the firewall/NAT machine because it's translating for any number of computers, and the port that the internal machine is using might already be in use by the NAT machine. When the responses come back, the port is all that the NAT machine has to determine that the packet is really meant for an internal computer rather than itself and to determine which internal computer the packet is meant for.

Figure 6.5 NAT packet traversal.

The general syntax for SNAT is as follows:

```
iptables -t nat -A POSTROUTING --out-interface <interface> ... \n  -j SNAT --to-source <address>[[:<address>]::<port>]]
```

The source address can be mapped to a range of possible IP addresses, if more than one is available.

The source port can be mapped to a specific range of source ports on the router.

### MASQUERADE TABLE TARGET EXTENSION

Source Address Translation has been implemented in two different ways in iptables, SNAT and as MASQUERADE. The difference is that the MASQUERADE target extension is intended for use with connections on dynamically assigned IP addresses, particularly in the case where the connection is temporary and the IP address assignment is likely to be different at each new connection. As discussed previously, in the “NAT Table Features,” MASQUERADE can be useful for dial-up connections in particular.

Because MASQUERADE is a specialized case of SNAT, it is likewise a legal target only in the POSTROUTING chain, and the rule can refer to the outgoing interface. Unlike the more generalized SNAT, MASQUERADE does not take an argument specifying the source address to apply to the packet. The IP address of the outgoing interface is used automatically.

The general syntax for MASQUERADE is as follows:

```
iptables -t nat -A POSTROUTING --out-interface <interface> ... \n  -j MASQUERADE --to-ports <port>[-<port>]
```

The source port can be mapped to a specific range of source ports on the router.

### DNAT NAT TABLE TARGET EXTENSION

Destination Address and Port Translation is a highly specialized form of NAT. A resident or small business site is most likely to find this useful if its public IP address is dynamically assigned or if the site has a single IP address, and the site administrator wants to forward incoming connections to internal servers that are not publicly visible. In other words, the DNAT features can be used to replace the previously required third-party forwarding software, such as ipmasquerading.

Referring back to Figure 6.5, Destination Address and Port Translation is done before the routing decision. On the PRERUTING chain, DNAT can be a target when the incoming interface is specified. On the OUTPUT chain, DNAT can be a target when the outgoing interface is specified.

The general syntax for DNAT is as follows:

```
iptables -t nat -A PRERUTING --in-interface <interface> \
  -j DNAT --to-destination <address>[-<address>]:[:port-<port>]
iptables -t nat -A OUTPUT --out-interface <interface> \
  -j DNAT --to-destination <address>[-<address>]:[:port-<port>]
```

The destination address can be mapped to a range of possible IP addresses, if more than one is available.

The destination port can be mapped to a specific range of alternate ports on the destination host.

### REDIRECT NAT TABLE TARGET EXTENSION

Port redirection is a specialized case of DNAT. The packet is redirected to a port on the local host. Incoming packets that would otherwise be forwarded to the incoming interface are redirected to the interface's INPUT chain. Outgoing packets generated by the local host are redirected to a port on the local host's loopback interface.

REDIRECT is simply an alias, a convenience, for the specialized case of redirecting a packet to this host. It offers no additional functional value. DNAT could just as easily be used to cause the same effect.

REDIRECT is a legal target only in the PRERUTING and OUTPUT chains. On the PRERUTING chain, REDIRECT can be a target when the incoming interface is specified. On the OUTPUT chain, REDIRECT can be a target when the outgoing interface is specified.

The general syntax for REDIRECT is as follows:

```
iptables -t nat -A PRERUTING --in-interface <interface> \
  -j REDIRECT [--to-ports <port>[-<port>]]
iptables -t nat -A OUTPUT --out-interface <interface> \
  -j REDIRECT [--to-ports <port>[-<port>]]
```

The destination port can be mapped to a different port or to a specific range of alternate ports on the local host.
