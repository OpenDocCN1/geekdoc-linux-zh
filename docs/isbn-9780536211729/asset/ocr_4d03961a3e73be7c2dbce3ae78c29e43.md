There are a number of solutions including some combination of the following:

+   1. Wrap the FTP daemon with SSH or use sftpd, that is part of SSH2. See “TCP Wrap-pers” on page 109.

+   2. Allow the use of FTP only by trusted clients via TCP Wrappers or firewalling with IP Chains.

+   3. Make use of the WU-FTPD feature to chroot anonymous users and even nonanonymous users if desired. Using man 5 ftppass will generate useful documentation on many of WU-FTPD's capabilities to limit which systems and users may access it, how to use its chroot capability, and to specify of which commands will be allowed, and so on.

+   4. Consolidate “anonymous FTP” needs onto a single system that has no confidential data and is outside your corporate network, and typically in the DMZ. Thus, if it is cracked then there is nothing to “get,” though there will be a cracker causing the distribution of undesirable files.

+   5. On your Web server (http), supply the MD5 checksums for the files that you distribute on your FTP server so that those downloaded files can verify that they are correct and that the files on the FTP server have not been altered. For extra security, CGI operation should place a on a third machine and all of these machines should be in a DMZ that allows appropriate services to each of these.

+   6. If one person want to give data to a second person and they cannot transfer it easily via other methods as e-mail (possibly wrapped in PGP or SSL), the first person could FTP up to the FTP server and then the second person could pull down. The advantage of this two-step procedure over one ftpping into the other user's machine is that neither user's system has to suffer the security risks of being a FTP server.

As part of the “Rings of Security,” you do not want to allow anyone to FTP into your root account because knowing only the root password would crack your system. Likewise, you will want to block FTP from accessing your other system accounts and create additional accounts too. These account names may be listed in the /etc/ftpusers file, one line to prevent anyone from logging in via FTP to them. Blank lines and comment lines starting with the “# character are allowed to.

The most elegant and easiest way to add a user to the /etc/ftpusers to forbid any remote user from logging into FTP as this is the use of the echo command and the shell >> operator to append a command's output to the named file. Thus, to prevent using the root and ftp (anonymous) accounts via FTP, follow the following commands.(Thanks to the Neuss team for this technique).

```
echo root >> /etc/ftpusers
echo ftp >> /etc/ftpusers
```
