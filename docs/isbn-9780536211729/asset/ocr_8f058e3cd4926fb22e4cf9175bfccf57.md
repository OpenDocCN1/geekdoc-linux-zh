# Stop Squid from Inking Out Their Trail

Note that Squid operates as a daemon rather than being invoked by inetd, so you can not use TCP Wrappers to control which systems it may be accessed from.

Because the downloading of each URL and each image within a URL is via a separate TCP connection, Squid to be called via inetd instead of it being a daemon, it would have to be forked dozens or hundreds of times per second. This would be an impractical waste of resources. Additionally, operating as a daemon is able to buffer the most popular pages in memory for even performance improvement and reduction of required resources (disk).

Because Squid is open source, I expect that it would be easy to add support for libwrap. A gold star goes to the person who does this and submits it to the Squid team for integration.

Additionally, you can control what ports Squid will connect to. By default it uses the rules.

```
acl Safe_ports port 80 21 443 563 70 210 1025-65535
http_access deny !Safe_ports
```

Note that this excludes 25 (SMTP), which is what sendmail uses. This is to prevent someone from using Squid as a mail relay for spam. This allows the services shown in Table 3.3.

What is wrong with this? The philosophy was to disallow “dangerous” services, such as mail (for relaying spam) and echo (for launching DoS attacks), from the reserved ports of 0 to 1023 and allow 1024-65535. Besides the obvious off-by-one error, there are plenty of dangerous ports over 1023.

# Table 3.3 Services Squid Allows by Default

| Port | Service |
|---|---|
| 80 | http |
| 21 | ftp |
| 443 | https |
| 563 | news (NNTP over SSL) |
| 70 | Gopher |
| 210 | WAIS |
| 1025-65535 | "Dynamic and Private" |

+   5 TCP Wrappers normally operates as a program, tcpd, that is invoked by inetd. This is done by specifying the full pathname for tcpd as the program to supply the service in /etc/inetd.conf. Because this does not work for daemons (daemons are not started from inetd) the libwrap library was created.
Support for TCP Wrappers may be added to any daemon (or other program) by applying simple modifications to its source to call libwrap to decide whether the request should be granted.
