# 3.9 Stop Squid from Inking Out Their Trail

# DANGER LEVEL

Squid is a popular free source Web Proxy Cache. It allows a system to cache HTTP, FTP, Gopher, and the related DNS entries, and supports the use of proxies with HTTPS. Squid can reduce your network's Internet bandwidth requirements dramatically, which also improves performance by caching frequently accessed Web pages. It does this by caching (temporarily storing) Web pages frequently accessed by your users.

By default, Squid will let anyone in the world point their browser at and make requests. Some distributions are now including it with no access limit to prevent this; Red Hat is one such distribution. The request to the Web server will show as coming from Squid, the actual user. This causes you two problems: if "squatter" is set to no, logs from the Web server will point to your system. This might cause your ISP to shut your Internet connection down first and ask questions.

It might even you a visit from the folks with guns (law enforcement) and earn some publicity that you do not want. It will also use your bandwidth twice for each request. Although Squid can pass on information about who seemed to have made the request, a cracker can spoof his source address or use a compromised system and Squid's "I am doing it for this other guy" does not show up in low-level packet traces that just report IP addresses. The solution is to make use of some rules in Squid's

```
/etc/squid/squid.conf
```

configuration line to limit which systems will accept client requests from. In some installations, this file is in /usr/local/squid/etc instead.

You may also implement rules to limit what Web servers it allow connections to and it will do some content filtering of URLs too. The Squid FAQ (Frequently Asked Questions) has links for some filtering rules that will block many sites that are of an adult nature by matching words of adult nature. Many of these adult sites, in turn, are getting around that by using the HTTP feature of "%% hexadecimal encoding where a percent sign is followed by two hexadecimal numbers representing the ASCII value of each character in the URL. One solution would be to use the content filtering to block URLs with "" characters in them. A better solution is to enhance Squid to "unhex" these sequences before doing pattern matching for illegal URLs.

A rule in your firewall will allow only Squid to access ports 80 (http) and 443 (https) out of your organization will prevent users sidestepping your Squid rules.
