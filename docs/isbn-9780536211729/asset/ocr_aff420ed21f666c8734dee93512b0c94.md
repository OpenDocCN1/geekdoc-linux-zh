# TIP

You might want to invoke the find command using an account other than root. Then, if a particular directory is mode 700, find will not descend into it. Thus, you will not be bothered by any files underneath a directory that may be world-writable but not in danger because the 700 on that directory will keep anyone else from getting to the files underneath.

You might want to redirect standard error to /dev/null so you will not be bothered by warnings of permission denied on directories that you are denied access to, because they clearly are protected.

Note that this trick will detect the subtle and rare problem of a directory with mode 711 that allows someone to access files (and subdirectories) if she knows the names then neither (nor find) can obtain a list of the files in their directory. If someone is using this technique, she probably knows what she is doing. You can find such directories for closer inspection, if you want, by invoking each of these commands in turn.

```
find / -fstype proc -perm -001 -perm -004 -type d -ls
find / -fstype proc -perm -010 -1 -type d -ls
```

Deciding which files must remain world-readable is harder than the world-writable problem because many files should be world-readable, as shell scripts in the binary directories, man pages, libraries, /etc/passwd and /etc/group, /etc/hosts, and /etc/resolv.conf. Certainly, on a secure system, users' files generally should not be world-readable and perhaps not even group-readable. This is where your file system is useful.

The following command will find all world-readable files under /home and under /usr/oracle, where there be database-related files. This command does not check /usr/oracle/bin where Oracle-related programs are kept. It makes use of the -path option to match /usr/oracle/bin and the -prune option to skip it. It similarly ignores /home/ftp. It does not pipe standard error, if you can you desire.

```
home /usr/oracle -path /usr/oracle/bin -o \
-path /home/ftp \ -prune -perm 4 -ls \
Mail -s 'world readable' your_address
```
