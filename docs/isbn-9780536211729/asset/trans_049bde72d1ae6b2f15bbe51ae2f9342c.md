## 3.10 syslog 服务

![](img/7d04225c75a86d3cf4bd6077596f35b2_199_0.png)

syslog机制被许多守护进程和内核用于记录错误消息和建议消息。它具有通过UDP端口514接受来自远程系统消息的功能。这是一种从多个系统整合消息，然后只需扫描和审查一个日志文件的便捷方法。最近版本的syslog需要-r标志来启用监听UDP端口514，以记录来自远程系统的消息。这是一项受欢迎的增强安全性的改进，使得不使用此功能的大多数系统能够抵御入侵者向此端口发送攻击。

远程日志记录功能可以通过远程记录系统活动来提高安全性。因此，如果一个系统被攻陷且所有日志文件被销毁，你仍然在远程系统上拥有这些数据，假设远程系统没有被同时攻陷。通过让一个支持最少服务的特殊“高安全性”系统（以减少被攻陷的可能性）来处理日志记录，可以将所有日志被销毁的可能性降至最低。这将在第343页的“监控系统”中讨论。

然而，UDP数据包欺骗确实存在。幸运的是，现代版本的syslog（v1.3，早在Hat 6.0中就被注意到）除非配置，否则不会监控UDP端口。有些漏洞利用可以通过反复向syslog发送数据包来导致拒绝服务（DoS），从而拒绝合法客户端访问，或由于记录消息量大而占满空间。偶尔，入侵者会向互联网上可访问此端口的各种系统写入伪造的日志消息。

可能存在获取root权限的方法，虽然希望在你读到这篇文章时这些方法已被修复，假设你拥有最新的syslog。当然，一些入侵者会欺骗他们的UDP源IP，这很简单，然后发送消息。这些消息将被记录，肯定会让你困惑。它们可能会包含他们放置的任何文本，从而错误地指示入侵事件。

明确的解决方案是让你的防火墙阻止来自受信任网络之外站点对此端口的访问。

除非你真的需要，否则不要使用syslogd -r，并确保防火墙阻止对UDP端口514的访问。nsyslog程序是syslog的替代品，提供SSL封装的TCP连接以提高安全性。可从以下地址下载：

```
http://coombs.anu.edu.au/~avalon/nyslog.html
```

## 3.11 打印服务 (lpd)

![](img/7d04225c75a86d3cf4bd6077596f35b2_200_0.png)

标准Linux的lpd程序监听TCP端口515，以接收远程打印作业请求。其安全模式是基于rsh及其相关程序中存在的有缺陷的R*安全模型，这在第146页的“rsh, rcp, rexec 和 login 服务”中有所讨论。lpd将接受/etc/hosts.equiv和/etc/hosts.allow中指定的系统和用户的作业。强烈建议防火墙阻止所有不受信任的系统访问此端口。一种较弱的替代方法是编辑/etc/services，或调用lpd时使用替代端口号，这样入侵者更不太可能检测到并攻击该端口。

当lpd启动时，端口号在命令行上以简单数字形式指定（无破折号）。如果可能的话（本地或远程），建议以-f标志启动lpd，以便通过syslogd记录请求。由于2001年初大量因Red Hat bug导致的攻陷事件，以及入侵者继续频繁攻击此端口，危险等级在第二版中有所提高。

## 3.12 ident 服务

![](img/7d04225c75a86d3cf4bd6077596f35b2_200_1.png)

ident服务通过ident程序运行，该程序可以作为守护进程运行，或由inetd启动。当某人使用客户端程序（如Netscape、telnet或FTP）从你的系统连接到远程系统上的服务器时，该远程系统只知道你系统的IP地址以及哪个端口号发起了连接。ident系统无法知道你的系统中哪个用户已连接，甚至无法知道他们是否欺骗了你的IP地址。如果你的某个用户制造了麻烦，该远程系统无法确定是哪个用户造成的，也无法向你报告该用户。ident服务通过告知远程系统哪个用户拥有此端口号来回答这些问题。identd服务器也可以配置为记录这些查询，以便后续分析。

ident服务向任何询问的进程提供关于你系统的信息。如果允许提供用户名，攻击者可能会利用这些信息猜测密码或电子邮件地址。请记住，任何信息要从登录尝试中辨别出来，都需要提供有效的用户名和该用户的密码。建议调用identd时提供-n标志，以便提供数字UID而不是用户名，因为UID对此目的没有用处。此外，建议使用-user和-group标志来更改ident，使其自身转变为无害的用户和组，例如ident。这样，如果入侵者发现了其中的漏洞，他们也无法获得访问权限。

> 你可能想要修改identd，使其在每次被查询时提供相同的响应（伪造的用户名）。这将阻止入侵者发现谁已登录，并阻止入侵者和垃圾邮件发送者出于恶意目的获取用户名。你可以从 www.ajk.tele.fi/~too/sw/ 下载这样的伪造版本。

此外，由于这是攻击者可以耗尽的资源，拒绝服务（DoS）攻击是可能的。建议如果运行此服务，应仅在具有具有shell账户的“真实用户”的系统上运行。（其他系统没有用处。）默认关闭的-o选项将导致identd声明操作系统是OTHER而不是UNIX。虽然有些人提倡“通过保密性获得安全”，但我认为这种技术并没有特别的价值，尽管我不认为泄露用户数字是明智的；那信息会准确揭示漏洞。

-l选项将导致identd通过syslog记录请求。默认是开启的。
熟练的入侵者可以通过观察系统在处理数据包时如何对某些条件做出不同响应来确定你系统的操作系统。nmap程序特别擅长于此。如果你通过telnet服务或提供Linux和UNIX特有的其他服务提供了这些信息，那就不必要这样做了。如有疑问，就不要提供identd。

## 3.13 INND 和 News

| 危险等级 |
| :--- |
| 💀💀💀 |

这些服务器提供Usenet（网络）新闻，也称为“新闻组”或News。在许多最近的发行版中，INND默认是启用的。启用时它使用相当多的资源，即使在默认配置下，它也占用周期。当然，除非你将使用它，否则应该关闭它，就像应该关闭任何不需要的服务一样。

除了在处理大量组时资源密集之外，这些服务似乎相对安全。它们应该以news用户和组运行。应该预期存在伪造的帖子，因此发件人信息不可信。INND和News使用nntp端口（网络新闻传输协议端口），即TCP端口119。要禁用，你应该发出以下命令：

```
/etc/rc.d/init.innd stop
chkconfig innd off
```

## 3.14 保护你的DNS注册

危险等级

这是大多数系统管理员从未想到要担心的安全领域。简而言之，他们与Network Solutions的有用人士注册，从不担心他们数百万美元的公司依赖于大约80字节将域名映射到名称服务器IP地址的数据。参见第558页的“AOL的DNS变更混乱”，了解AOL面临的“非常大”的问题。有时，你可能想要更改这些信息，特别是在更换ISP或更换充当名称服务器的系统时。当然，记住密码是个麻烦事，你有丢失它们的风险。

Network Solutions提供了三种电子方式更改此信息。默认方式是发送邮件，账号被列为注册者或技术联系人。众所周知，欺骗这些邮件很容易。这就是发生在AOL身上的情况，也可能发生在采用这种方法的大多数域名所有者身上。解决方案是通过更改你连接Network Solutions的身份验证方法来改变你域名的认证方式。

另外两种方法是通过使用密码或使用PGP密钥。在密码方法中，你提供，嗯，啊，密码。Network Solutions将此称为CRYPT-PW方法。使用此方法，Network Solutions加密你提供的密码并以类似Linux存储用户密码加密版本的方式存储它。要更改信息，你需要提供原始密码。即使入侵者攻陷了Network Solutions（虽然我没有听说发生过这种情况），入侵者也无法获得你的密码。

此方案中的一个次要弱点是，加密算法似乎对未加密密码的前两个字符不做更改。因此，建议前两个字符不要使用容易猜到的单词。这是一个小问题，因为加密后的密码不是公开信息。使用良好的密码，如第36页“避免弱密码和默认密码”中讨论的。
