For a cracker, use of rwho could allow him to watch for times on your system when nobody is logged in to begin his attacks. It also allows him to find out user names of accounts on your system as possible attack points.

Likely, most Linux distributions recognize this vulnerability and although they include rwhod, most do not enable it by default. To verify that it is not running on your system, type the following command:

```
ps axlwm | grep rwho
```

If a process other than the grep itself shows up, you should disable it. Note that this is a daemon started out of /etc/rc.d. The reason for this is that each running rwhod broadcasts a list of users logged in to the system to anyone else who might be listening on the network.

When a user invokes rwho it queries the local rwho which disgorges the cached data from other systems. Because the communications method used is UDP broadcast packets, this data does not go over the Internet. (This is because UDP broadcast packets are not routed by a network, but typically restricted to a subnet, unless a router is misconfigured.)

Because rwho is not over the Internet it might be considered safer than finger so as there are no compromised systems on the LAN (and the LAN cannot be sniffed by crackers).

Still, enabling rwho would violate the policy of “Rings of Security” because if one system gets compromised rwho could be used to get account names on other systems, allowing the next step in breaking into those systems. (If telnet and ftp are disabled and replaced with ssh and sftp, and mail is encrypted, even a network sniffer will not see account names on the wire.)

On Red Hat and similar distributions, the command to remove rwhod from your system is as follows.

```
rpm -e rwho
```
