# 3.8.11.2. IP Tables. Protecting Samba with IP Tables is very similar to doing with IP Chains. Repeat the following using udp.

```
iptables -A INPUT -p tcp -s 192.168.1.0/24 -dport 137:139 -j ACCEPT
iptables -A INPUT -p tcp -dport 137:139 -j LOG
iptables -A INPUT -p tcp -dport 137:139 -j DROP
```

```
iptables -A OUTPUT -p tcp -d 192.168.1.0/24 -sport 137:139 -j ACCEPT
iptables -A OUTPUT -p tcp -sport 137:139 -j LOG
iptables -A OUTPUT -p tcp -sport 137:139 -j DROP
```

# 3.8.11.3 Machine Accounts. Samba 2.24 has the capability of being a Primary Domain Controller (PDC) and a Backup Domain Controller (BDC), making it an better replacement for Windows NT. Earlier versions could operate as a PDC, but not a BDC. For your system as a ADC, you will need at least 2.2.3.

There are countless facts, using the Samba book that is distributed with the source code, where you can find how to set up a PDC with Samba, I am not going to do it. I however wish to discuss machine accounts which are required to properly emulate the domain environment. "into the Domain field", cryptographically speaking. These accounts will all end with the "$ sign. Their names match the NetBIOS names given to computers on a Windows network. Network them as the NetBIOS hostnames.

A couple of things that you as a system administrator need to remember is to ensure that these machine accounts do not have a login shell and that their passwords are disabled, not just to guess, but by disabling a "! in the password field. These accounts would normally fall into the state account category, they are not actively being used. Keep an eye on them so if they suddenly get a password and have their UID and GID change to 0, you know you have some digital shenanigans going on. You might find it advantageous when setting up a domain to set a range of UIDs for the machine accounts. This would help automate checking, should you choose to go that route. for example:

> If the username ends with a "$ and the UID is less than 10,000 or greater than 10,500, the SysAdmin there might be a problem.

The add machine script directive in the smb.conf file, if enabled, will allow machine accounts to be created automatically for new machines entering your network. If you set aside a range, be sure to enforce your ranges there, too. It may take some tricky programming to do.
