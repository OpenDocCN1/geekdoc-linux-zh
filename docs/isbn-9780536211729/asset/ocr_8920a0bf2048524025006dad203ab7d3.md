# 7.2 Initializing the Firewall

A firewall is implemented as a set of packet-filtering rules defined by options on the iptables command line. iptables is executed once for each individual rule. (Different firewalls can range from a dozen to hundreds.)

The iptables invocations should be made from an executable shell script, not directly from the command line. You should invoke specific iptables rules from the command line because this could cause your firewall to accept or drop packets inappropriately. When the chains are initialized and the default policy enabled, all network services are blocked until acceptance filters are defined to allow the individual service.

Ideally, you should execute the shell script from the console. But the brave execute the shell script from either a remote machine or a Windows xterm session. Not only is remote network traffic blocked, but also the local interface used by Windows is blocked until access to the interface is explicitly granted. Ideally, Windows should not be running or even installed on a firewall. It is a typical example of software that is not necessary and has been used as a means to exploit servers in the past.

As someone manages Linux computers that are geographically to thousands of miles away, I can activate a firewall script only from a remote location. In these instances, it is advisable to do two things: First, change the default policy to ACCEPT for the first or first few executions of the firewall. Do this to debug the syntax of the script itself not. After the script is syntactically correct, change that policy back to DROP.
