How are your users doing? Choke, cough, gag, hack. Every account is a possible entry point. Have your users followed your advice, company policy, or threats to devise a password? Are they being as careful as you are? Probably not. Now it is your turn to don the black hat and think like your enemy.

Using programs like crack (which cracks passwords), you can break into your users' accounts? You definitely will need to get written management approval to conduct the level of security audit. There are notable cases of unauthorized audits landing people in jail or at least on the enrollment rolls. Rand Schwartz is one.

You might install a module in the password program that automatically tries to break a user's proposed new password. Though the standard password program makes very simple tests, there are more sophisticated routines that include much of crack's capability. One way to do this is to use of the cracklib capability in the Pluggable Authentication Modules (PAM) enhancements to the password program. The cracklib analyzes passwords to determine whether they are easily crackable. PAM offers additional security for Linux systems and other operating systems too. Edit the /etc/pam.d/password file to:

```
password password requisite /usr/lib/security/pam_cracklib.so retry=3
password password required /usr/lib/security/pam_pwdb.so use authtok
```

This will cause the PAM-enabled password program to load these dynamically loadable libraries. PAM now is standard with Red Hat. On some systems these are in /lib instead of /usr/lib.

There is more documentation on configuring PAM-enabled utilities at:

www.kernel.org/pub/linux/libs/pam/

Another good source for PAM information is:

www.sun.com/software/solaris/pam/

On Slack, this capability will be enabled if the following line is present in /etc/login.defs (and the dictionary is installed):

```
CRACKLIB_DICTPATH      /var/cache/cracklib/cracklib_dict
```
