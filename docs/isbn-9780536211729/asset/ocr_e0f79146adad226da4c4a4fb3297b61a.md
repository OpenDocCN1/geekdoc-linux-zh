With REJECT, another special-purpose target is QUEUE. Its purpose is to hand off the packet via the netlink device to a user-space program for handling. If there is no waiting-program, the packet is dropped.

RETURN is another special-purpose target. Its purpose is to return from a user-defined chain before rule matching that has completed.

Locally generated outgoing packets can be filtered based on the user, group, process, or group ID of the program generating the packet. Access to remote services can be authorized by the packet-filtering level on a per-user basis. This is a specialized option for multiuser, multipurpose hosts because firewall routers shouldn't have normal user accounts.

Matching can be performed on various pieces of IPSec header, including the SPIs (security header) and ESP (encapsulating security payload).

The type of packet, be it broadcast, unicast, or multicast, is another form of match.

A range of ports well as a range of addresses are also valid match with iptables. The type of address is another valid match with we. Related to type matching is the ICMP packet type. Recall that there are a number of valid types of ICMP packet types. iptables can match against these types.

The length of the packet is a valid match, as is the time of packet arrive. This time matching is interesting. Using the time matches, you can configure the firewall to reject certain traffic after business hours or allow it only during certain times of day.

A good match for auditing, a random packet match is also available with iptables. In this match, you can capture every nth packet and log it. This would be a method for auditing the firewall rules without logging too much information.

# 6.3.1 NAT Table Features

There are three general forms of NAT:

+   Traditional, unidirectional outbound NAT—Used for networks using private addresses.

+   NAT—Address Translation only. Usually to map local private addresses to one of a block of public addresses.

+   NAPT (Network Address Port Translation)—Usually to map local private addresses to a single public address (for example, Linux masquerading).

+   Bidirectional NAT—Two-way address translation allows both outbound and inbound connections. A use of this is bidirectional address mapping between IPv4 and IPv6 address spaces.
