
## 3.4.1 Configuring Anonymous FTP

Many Linux distributions offer anonymous FTP configurations either standard or as options. Frequently, the configurations supplied are not as secure as they could be, so you will want to examine them carefully and correct them so they conform to the guidelines discussed here.

### 3.4.1.1 Limiting Who Can Log In Anonymously

If the -a flag was given to enable the use of the /etc/ftppass configuration file, the guestserver command may be used to specify which hosts someone may initiate an anonymous login. If an argument is supplied, only this host may be used for anonymous login. Multiple guestserver commands may be used to specify multiple hosts. If guestserver is specified without a host, anonymous login is disabled. Disabling all anonymous logins this way is equivalent to specifying ftp in the /etc/ftpusers file.

### 3.4.2 Specifying ftp's Home Directory

The choice of where to specify FTP's home directory, ~ftp, in the real /etc/passwd file depends on whether you will offer downloading only (Read/Only access) or downloading and uploading (Read/Write access). Only allowing uploading is possible and should be treated similarly to Read/Write except that there will be no files for download. If there will be uploading, steps must be taken to prevent malware or unintentional excessive use from causing an important system to run out of space. The preferred solution is to use a separate file system, though quotas may also be used. Using "grow," system log files grow, or if you have real users...

Although /var is intended for system-related files, system logs are rarely kept there and you really do not want to allow an anonymous FTP user to be able to fill up the file system used for logging and stop logging. This could happen unintentionally, which makes it easy for a cracker to block logging as the first step in an attack. Certainly, you can compute how long it would take someone to fill up a disk. A baud is a bit per second and it takes roughly 10 bits per character. This, over a 33 Kbaud (kilobaud) PPP line, means 3.3 KB can be transferred in an 11.6 MB per hour or 27 MB per day. It would take days to use 1 GB. A T1, which is rated at 1544 kbaud, is 48 times as fast and would fill a 1 GB partition in two hours.

### 3.4.3 Adding the ftp user and Group

Create an ftp user in /etc/passwd and an ftp group in /etc/group. The UID and GID should be different than that of any other user or group. The ftp user, group, UID, and GID should be used only as discussed here. A directory tree of common system directories needs to be created under ~ftp. Most modern distributions offer this chroot anonymous FTP configuration by default; Red Hat and Slackware do.

### 3.4.4 File Ownership

Except where needed, all files and directories in ~ftp absolutely must have an owner and group with a UID and GID that is different from that of the ftp user and group (except where noted). Failure to adhere to this advice is a common mistake and will cause security problems. Create a separate account and group called ftpadmin with a separate UID and GID than ftp. Have the files in ~ftp owned by ftpadmin with a group of ftpadmin. Thus, to maintain the anonymous FTP files, only the password for ftpadmin, not root, is required.

You need to populate this directory tree with a few small pieces of the Linux root file system. The directories needed include bin, etc, and pub. If you are using a chrooted environment, which is an excellent idea, create a lib directory to hold any dynamically linked libraries. By default, anonymous FTP logins in an environment chrooted to ~ftp, and this should not be altered. All of these directories should have an owner of ftpadmin, a group of ftpadmin, and be mode 755. Next, you will need to create some files. First on the file parade are passwd and group; they should go in ~ftp/etc.

### 3.4.1.5 passwd and group Files

You positively must not use the real /etc/passwd or /etc/group files. That would be giving away security information to crackers that will enable them to break into your system, specifically account names and, if passwords are not used, encrypted passwords for them to break on their own systems or yours. Linux distributions that provide anonymous FTP violate this rule, so you will need to alter the existing configuration. Instead, create passwd and group files that have different names, UIDs and GIDs, and different encrypted passwords. In fact, you will want to ensure that none of the names in ~ftp/etc/passwd or ~ftp/etc/group are real, except to provide a mapping from the UID and GID of the files under ~ftp back to some names. These typically would be a user and group of ftp and ftp.

Even these names (for UID 0 and GID 0, as GID 0 is used) should not be real; mapping them back to a user of root or root or wheel is not giving away any secrets. Having the FTP versions of these files be different from the real /etc/passwd and /etc/group is absolutely necessary for security. The fake passwd and group files are used by the dir command to show the ownership of files under the FTP hierarchy where the FTP ls1 command is given. You can allow the real and FTP versions of the passwd and group files to have the same UID and GID for ftp because there is no reason not to and because it is less confusing. It is suggested that a high value be used for the UID and GID to reduce the likelihood of the same value being used for other purposes accidentally. (Note that some popular distributions violate this rule; you should correct your configuration.)

The following may be used as the ~ftp/etc/passwd file.

```text
root*:0:0:::
bin*:1:1:::
ftp*:9910:9910:::
```

The following may be used as the ~ftp/etc/group file.

```text
root:0:
bin::1:
ftp::9910:
```

### 3.4.1.6 The ftppd Arguments

The FTP daemon typically is started by inetd using the mapping provided by an entry in /etc/inetd.conf. This is where you decide whether to use TCP Wrappers. Even if you offer a public anonymous FTP service, you probably want to use TCP Wrappers. This will allow you to shut off daemons by disabling anyone from your hosts a connection. Some sites will want to use IP addresses. If you use the Adaptive TCP Wrappers, you will want to enable TCP Wrappers so that if the system detects someone attempting to crack it, that system will be locked out of FTP too.

The Washington University FTP daemon that you will probably be using accepts a number of arguments, some of which you will want to use.

- **+** - causes each FTP connection to be logged. This is highly recommended.
- **-** - causes each FTP command to be logged. This includes connections as well as each command. This is useful for analyzing your users' behavior as well as for spotting abuses. Note the minor issue: if a user accidentally enters her password instead of her user name to the USER command, her password will be logged. If your log files are publicly readable, which is a bad idea, her password will be on public display. This flag is overridden if ftpaccess is used. This is a polite way of saying that it is silently ignored if the ftpaccess file is specified with a -a flag. In this case, the following line to /etc/ftpaccess is used to get this effect.
- **+** - causes logging of each put request, which uploads a file to the server. It is logged to the xfer file, normally under /usr/adm, unless the -X flag also is given, in which case logging is by the syslog facility. This combination allows you to use the syslog facility to consolidate the logs of more than one system on a single system for convenience and security. Considering the past security problems that have been encountered with FTP, this is an excellent idea. It allows the logging of FTP to a more secure system so that a successful cracker will not be able to destroy the logs that might give clues to what he did and how. The -i flag is overridden if ftpaccess is used.
- **-o** - causes logging of the output. See -i for the effect of -X and ftpaccess.
- **-X** - modifies -i and -o to cause logging to be done via syslog instead of being logged by FTPD directly to the xferlog file. See also the discussion on -i.
- **-u** - specifies the default umask.
- **-w** - suppresses the logging of each user logged in under ftp in the wtmp file. If you use this, it is discouraged.
- **-r** - causes FTPD immediately to do a chroot to the specified directory for all users, not just the anonymous or ftp user. This provides substantial additional security that is useful for many sites.
