# 2.8.3 Stopping Uncontrolled Access to Data

| DANGER LEVEL |

"Finding Permission Problems" on page 53, you saw how to use the find command to search the entire file system for files with modes that are too lax and correct them. Presumably, if the files were owned by users, they corrected them or discussed the problem with them. The issue here is that many users and programmers are too busy to worry about permission. If it is a choice of missing a deadline or skimming on security, well, you will know the answer to this one.

As a consequence there might be some files that need to be world-readable or even world-writable due to the programmer's implementation. In some cases this problem is due to not wanting a "set-UID in root" program or set-UID shell scripts are in connection to CGIs and database work. The answer is to get the programmers to alter the implementation to not require this access. Instead of a small-UID C program that executes the script (without forking). In other words, the small-UID C program should start with execcl() or execv() and should not fork().

Another possible problem is that the Linux permissions might be strict and proper, the application's internal configuration will leave anyone at the data. A perfect example here is CGI code is used to access a database but the database itself has no rules restricting access. Thus anyone who knows SQL can alter the data, either an inappropriate user or a cracker who might be in your system as an privileged user. Most programs offers different grades of information that different sets of people are allowed to access. This should be used to prevent this problem.

# 2.8.4 Limiting Server Interfaces

| DANGER LEVEL |

Although it is desirable to have different systems perform different functions to increase security, in small networks one system may serve as the firewall, Samba server, AppleTalk server, Web server, NFS server, etc. If you are not careful, this will cause access to these servers to be granted to everyone on the Internet even when this is not desired. Although you may "limit" access to a system with particular IP addresses, these can be spoofed easily. Although IP Chains rules will block this when used and properly configured, the "Rings of Security" concept suggests an additional ring of security that should be used too.
