Many shopping cart packages and CGIs, both commercial and open source, have security holes that are well-known to the cracker community. We see our sites probed for these vulnerabilities periodically and we do not even handle money online.



Many of these programs run root. Root is found on a system, a cracker is not far far, probing for weaknesses. Many programs that run set-UID to root (or which) are invoked by root) do not need to be.

Frequently all these programs need to be set-UID to run some user to gain access to data that should not be web-accessible. The solution is to create a new user that has no other purpose or access. Then such programs set-UID to that new user. Different programs might need to be set-UID to different users to protect them from each other.



Avoid storing users' privileged data (credit card numbers, financial details, mailing addresses, and phone numbers, etc.) on the same machine as the Web server. This separation will force a cracker to have to crack two systems instead of just one to get this data.
