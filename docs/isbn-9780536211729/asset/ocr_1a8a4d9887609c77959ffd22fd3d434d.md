Unfortunately, all of the distributions still are using only FTP rather than SFTP for updates. Hopefully, this will change.

SuSE is moving to patch packages rather than full packages for updates. This makes life easier for those on low-bandwidth connections.

Red Hat 7.3 has a slick GUI interface to its update updating program. It also has an icon on the tool menu at the bottom of the screen for up2date. When doing workstation install, it asks if you want the system configured to check for updates automatically (which I strongly recommend). By default, it checks every two hours. This check determines if there are any new updates available; it does not download them. Perhaps it just exchanges a timestamp.

Up2date will not automatically install packages, but the icon will change from a green tickmark to a red exclamation point when security patches are available. Click on the ! icon to pop up the update window. At this point, you will click on the up2date button, which causes it to download details on any new patches that are available. It loads a summary of the patches, not patches themselves, but so is it.

Red Hat has taken some care in the design to make the process as painless as possible so that people will better to do the updates. It is in everyone's interest. Update lists the updates by package name. Click on a package and it explains what the package does. There are too many packages for anyone to know what they all do. An application that is not set-UID and is not invoked by root or another privileged user is much not of a threat unless it interprets data from the Internet.

Click on the Advisory to find out what the problem is. You can select any combination of packages to be downloaded and installed or you can click on the Select packages button. Clicking Next starts the download and installation process. At this process is automatic, so you can do other things while the packages download and install. Progress bars are displayed while it is running.

The software is not perfect, though. Several times downloading, the software stalled. This required me to use ps to go which process to kill (the Python process) in to recover. The icon vanished, and I was asked if I wanted to relaunch it. I clicked on Yes and was able to restart the process.

Mandra and SuSE have similar updating facilities, though perhaps not as slick as from Red Hat. Regardless of whether you opt for an automatic update, a semiautom update (which I prefer in order to have control over changes to my systems), or being on a mailing list and manually updating, it is critical to stay up-to-date. No software is free. I cannot stress enough how important it is to minimize a cracker's window of opportunity by quickly applying the security patch that gives given vulnerability.

There are alternatives to up2date and the vendor-provided update tools. Autopdate (http://fresh.net/projects/autoupdate/) and automorp (http://fresh.net/projects/autorp/) work for any distribution based on rpm, and can be configured six ways from Sunday. They will check, compare versions, resolve dependencies, download, and install the updated RPMs for your system.
