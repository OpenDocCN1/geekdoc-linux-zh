
When you're finished, type the command `quit` to exit smbclient:

```

```

**W**hen you use your computer for work, creating text files, spreadsheets, graphics, or other important documents, you invest a lot of time and effort. When you work with multiple computers on the same or similar projects, you can end up with multiple directories containing multiple versions of important documents. Keeping track of these documents and ensuring that all important copies are stored in a single or multiple locations can be difficult and time-consuming, especially if you're used to copying files using drag and drop, multiple selections, or wildcards.

This short chapter outlines several approaches you can use to keep information synchronized between your notebook, other notebooks, or other desktop computers.

## General Strategies

There are several approaches you can take to keep track of data and multiple documents. Obviously, the simplest approach is to keep a central repository or directory of files and projects on a computer that has ample hard drive space. As work progresses, you dump your files into a central directory.

Another approach is to selectively back up specific directories. However, before you begin backing up, you should devise at least a simple strategy. See Chapter 13, “Crash Prevention and Recovery,” for details about backup strategies and approaches to maintaining recovery data or archives of your system.

## Useful Clients

Linux comes with a variety of programs you can use to build backup files or archives. Two programs, cvs (Concurrent Versions System) and RCS (Revision Control System), are generally included with most Linux distributions. Although cvs is nominally used to keep track of programming source code changes, RCS was developed from the start to maintain different versions of text documents.

These programs were developed well before the concept of multiple authoring, revision marks, and group editing, but they support these concepts. By using these document-tracking systems, you can keep tabs on changes to important files through the revision control facilities provided by the clients included with each system.

### Using RCS

The RCS system consists of seven different programs, but you can get started with document tracking with just two commands: `ci` (check in) and `co` (check out). First, create a directory for your document(s) with the `mkdir` command, like this:

```bash
# mkdir work
```

Next, create a directory named RCS in the directory you just created:

```bash
# mkdir work/RCS
```

Navigate to your project directory, and then create a text file, perhaps named book1.txt. At the top of the file, create a header that looks like this:

```text
/* $Header$
 $Author$
 $Date$
 $Revision$
 */
```

Continue editing the file. When you're finished, save the file and exit your text editor. When you next want to work on the file, navigate to the work directory, and use the `ci` command, followed by the name of the file to work on:

```bash
# ci book1.txt
RCS/book1.txt,v  <--  book1.txt
enter description, terminated with single '.' or end of file:
NOTE: This is NOT the log message!
>>  Second revision
>>  .
initial revision: 1.1
done
```

When prompted, enter a short description, press Enter, type a period (.), and press Enter again. When you're ready to open and work on the file again, use the `co` command with its `-l` (lock) option, like this:

```bash
# co -l book1.txt
RCS/book1.txt,v  -->  book1.txt
revision 1.1 (locked)
done
```

You can then open the file in your text editor. However, you’ll see that the header information has changed to look like this:

```text
/* $Header: /home/iball/work/RCS/book1.txt,v 1.1 2000/03/02 19:53:46 iball Exp $
 $Author: iball $
 $Date: 2000/03/02 19:53:46 $
 $Revision: 1.1 $
 */
```

Each subsequent editing session will update the header. RCS also keeps track of all your changes to the file or files in your project folder. You can then use other RCS programs to view all the changes to a file, merge changes from different versions, or remove a version from the change log.

### Reporting with tar

The *tar* (tape archive) command is used to create archives of specified files or directories. But you can also use *tar* to compare a backup archive with the current state of a directory. For example, you can create a tape archive of your work directory like this:

```bash
# tar cvf work.tar work
work/
work/RCS/
work/RCS/book1.txt,v
```

When you use *tar* with the *v* (verbose) option, it outputs a list of directories and files being added to the archive. One way to keep track of the archive’s contents is to use the date and time stamping provided by the Linux kernel. Every file has a creation and modification date. You can see this by using the *ls* command:

```bash
# ls -l work.tar
-rw-r-r-- 1 iball iball 10240 Mar 2 15:29 work.tar
```

You can also find out a directory’s creation date by using the *ls* command’s *d* (directory) option:

```bash
# ls -ld work
drwxr-xr-x 3 iball iball 1024 Mar 2 15:17 work/
```

Manually comparing the date and times between archives and directories could be considered a bit tedious. You can, however, use the *tar* command to compare the differences between the contents of an archive and the current state and contents of a directory. For example, you could create additional files under the work directory and then compare the directory with your previous archive by using the `tar` command's `d` option:

```bash
$ tar fd work.tar work/*
tar: work:/file2: Not found in archive
tar: Error exit delayed from previous errors
```

In this example, the `tar` command reports that it found a file named file2 in the directory that is not present in the archive. The new file can be easily added to the existing archive by using the `tar` command's `r` (append) command:

```bash
$ tar fr work.tar work/*
```

This will add the new file to the end of your archive.

## Using NFS

Creating archives of existing directories works very well for backing up information, but the `tar` command is usually used to send files to a remote device, such as a tape drive. You can, however, perform direct-copy operations to remote hard drives from your notebook’s drive if you connect your laptop to a LAN.

Using the Network File System (NFS), you can directly mount remote drives or your notebook's drive on remote computers using software included in your system. A few simple configuration files and commands are all that's needed to be able to back up entire directories or hard drives.

### Configuring NFS

The first step in configuring NFS access is to create a file named /etc/exports on the remote computer hosting the drives you'd like to mount. The format of this file is simple. Each entry consists of a single line, beginning with an accessible path and followed by a space, the name of the remote host (in this case, your notebook), and read and write permissions in parentheses. For example, if your remote computer has an extra hard drive, such as /d3, that contains a directory named backup, and your notebook's hostname is zippo, the entry would look like this:

```
/d3/backup zippo(rw)
```
