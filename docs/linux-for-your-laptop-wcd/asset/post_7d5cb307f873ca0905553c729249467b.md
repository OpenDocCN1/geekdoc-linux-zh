## Potential Networking and Communications Problems

Mobile Linux users need to be aware that some devices, especially PC cards, might not work very well if the notebook is put into suspend or hibernation and then resumed. Just as you should never eject a floppy disk until write operations have finished (when the drive light, if there is one, goes out), you should always wait until read or write operations have finished when using a flash memory card (which simulates an IDE drive) or a SCSI PC card interface for an external drive. Modem cards might also be susceptible to problems if they are ejected prematurely.

A much safer approach is to wait for current operations to finish and then eject the card and shut down Card Services before putting your notebook to sleep. You can do this in a variety of ways, including using a shell script.

### Using a Shell Script

Shell scripts are a handy way to quickly craft utilities for Linux. The following script, which you can name *dosleep*, should work with Red Hat and Mandrake Linux notebook systems. The script first uses the `cardctl` command to shut down and disable power for two PCMCIA sockets. (If you have only one, don’t use the second command.) The script then shuts down Card Services and networking (the script assumes you have a network card in one of your PC card slots). Finally, the `apm` command is used to put the notebook to sleep.

```sh
#!/bin/sh

# stop Card Services (note: may not be safe for all cards!)

# stop networking, then put a notebook to sleep
/sbin/cardctl suspend 0
/sbin/cardctl suspend 1
/etc/rc.d/init.d/pcmcia stop
/etc/rc.d/init.d/network stop
/usr/bin/apm -s
```

When resuming from a suspend or hibernate, you could use the following script, perhaps named *wakeup*:

```bash
#!/bin/sh

# start Card Services (note: a pause is needed to initialize cards!)
# then networking
/etc/rc.d/init.d/pcmcia start

/bin/sleep 5

/etc/rc.d/init.d/network start
```

### Using init Scripts

You can also use the `apmd` system script, with proper entries, to handle PC cards and APM events gracefully. Although they are normally used to start, stop, or restart APM services for your system, the following two entries in this script may be used to control your PC cards before and after sleep:

```bash
sleep)
        /sbin/cardctl eject 0
        /sbin/cardctl eject 1
        /etc/rc.d/init.d/pcmcia stop
        /etc/rc.d/init.d/network stop
        /usr/bin/apm -S
        ;;
```

```bash
wake)
        /etc/rc.d/init.d/pcmcia start
        /bin/sleep 5
        /etc/rc.d/init.d/network start
        ;;
```

You could then use the script with the keyword `sleep` like this:

```bash
# /etc/rc.d/init.d/apmd sleep
```

Alternatively, after resuming from sleep or hibernation, to restore your PC cards, you would use `apmd` like this:

```bash
# /etc/rc.d/init.d/apmd wake
```

### Avoiding Save-to-Disk Problems

Notebooks with a compatible BIOS for APM usually come with an existing partition or disk file on a Windows partition used to support save-to-disk hibernation functions. This means that if you install Linux on a notebook, and you find a partition that looks like this to the Linux `fdisk` command:

```
282 838 13680a0 IMK ThinkPad hibernation /dev/hda4
```

you should leave it alone! This example is a save-to-disk partition used to support a notebook that has 128MB of RAM, and it’s designed to hold the contents of the memory during hibernation. Other save-to-disk schemes might have the contents of memory saved to a specific file on a Windows partition. One common DOS utility used in conjunction with the creation and management of these files and partitions is the Phoenix `PHD disk.EXE` command.

If hibernation operations do not work on your notebook, despite having an APM-compatible BIOS and using an APM-enabled Linux kernel, suspect the absence of this hibernation file or partition. You can generally re-create this partition or file by booting your notebook with a DOS diskette and then running the PHD disk utility.

Another source of problems, according to Tuxtops, a Linux laptop distributor, can be the XFree86 X11 server, which can lock up systems using a Mach64 chipset. This problem exists on notebooks such as various Dell Inspiron models. One workaround, according to Tuxtops, is to use the `chvt` command before issuing a suspend. Another fix is to install a modified X11 server by Steve Hsieh, found at http://www.eecs.umich.edu/inspiron.

## Tracking Time Between Suspends and Hibernation

Time can be very important, and for mobile Linux users, having the correct time set on your notebook can be critical. There are two types of time on a notebook: the hardware time, maintained by your notebook’s power and internal batteries; and the system time, maintained by the Linux kernel.

The Linux APM driver updates the Linux system time from your notebook’s hardware clock when recovering from a suspend or hibernation. However, there might be instances in which, depending on how you configure APM, the driver might not be able to properly update the system. If you need to obtain the correct or hardware time for your system, and you’re not on a network, you can use the `hwclock` command. For example, to see the hardware time, use `hwclock` and its `--show` option:

```
Wed Mar 1 21:30:01 2000 -0.349767 seconds # hwclock --show
```

You'll see the day, month, date, time, and year, along with a number indicating a time drift factor (which can be used in subsequent calls to help adjust your notebook's clock). If you want to see the Linux system time, use the `date` command, like this:

```bash
# date
Wed Mar 1 21:32:24 EST 2000
```

The `hwclock` command and its `--hctosys` option set the Linux system time to match your notebook's hardware clock:

```bash
# hwclock --hctosys
```

If you want to set the hardware clock from the Linux system time, use the `--systohc` option:

```bash
# hwclock --systohc
```

### Can't Keep Track of the Time?

If you have a hard time keeping your notebook's hardware clock and Linux kernel time synchronized, read the `hwclock` man page. You'll learn that all hardware clocks are subject to drift, and you'll also see how you can adjust the time for better accuracy. Another alternative is to use the `rdate` command when you have an active Internet connection. This is a great way to have the most accurate time available. Use the `rdate` command along with its `-s` (set) option, followed by an accurate source of time, such as `time.nist.gov`:

```bash
rdate -s time.nist.gov
```

## KDE APM Utilities

If you use X11 and the K Desktop Environment, you'll really enjoy the convenience of the `kmlaptop` utilities. This set of programs, launched from the desktop panel's Settings and Laptop menus (as shown in Figure 7.4), consists of a battery monitor, power control menu, and PCMCIA slot controls that can dock into the panel.

If you select the Power Control menu item, you'll see a dialog box, as shown in Figure 7.5, that you can use to set the intervals, or time-outs, for putting your laptop into suspend or standby when on battery or AC power.

Note that these settings take place only during your KDE sessions. You might have to use other utilities with other window managers in order to control your notebook.
