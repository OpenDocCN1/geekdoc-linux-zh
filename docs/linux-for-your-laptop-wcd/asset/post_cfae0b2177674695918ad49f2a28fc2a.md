## Behind the Scenes

Red Hat Linux stores most networking information under the /etc directory. Control of networking services during startup and shutdown is through various scripts under the /etc/rc.d/init.d directory. Information about your notebook's adapter(s) is contained in different files under the /etc/sysconfig/network-scripts directory. For example, information about an eth0 device would be contained in the file ifcfg-eth0. These files are automatically created, edited, and deleted by *netcfg* and *linuxconf* and are, in turn, used by other scripts to start and stop networking services.

## Configuring with linuxconf

The *linuxconf* command, which works with or without X11, can be used to configure a newly installed network adapter for your notebook. Start *linuxconf* from your console's command line, from the command line of an X11 terminal window, or through a Red Hat-specific root menu of your X11 window manager.

Under the Config menu, click on the Network task list, click on the Client task list, and click on the Basic host information item. In the dialog box that appears, click on the Adaptor tab, and then fill out as much information as possible about your notebook's adapter, as shown in Figure 11.6.

## Wireless Connections

Wireless networking, although available for several years now, has always been an expensive proposition and networking alternative—until now. In the last year, a number of inexpensive wireless networking cards with cost and capabilities close to typical 10Base-T performance have hit the market. These cards use 2.4GHz radio technology and offer 2MBps networking using IEEE 802.11 specifications known as frequency-hopping spread-spectrum networking. An installed and configured card appears as an Ethernet device (such as eth0) and provides a high-speed wireless link between a similar card installed in another PC or notebook. Range is typically 500 feet or less through walls and perhaps up to 1,000 feet with line-of-sight access.

The great news is that at least one or two models from different manufacturers work with Linux. Even better news is that one of the most inexpensive models, the Aviator 2.4, manufactured by Webgear, Inc., not only works well for nearly all Intel-based mobile Linux users, but also has drivers (developed by Corey Thomas) included with Card Services as a kernel module. Using these cards, you can quickly build a network of up to at least 61 different computers, or nodes.

Networking two laptops wirelessly is quite easy. Insert the wireless card, and then wait for Card Services to recognize, initialize, and configure the device. Use the dmesg command to look for output similar to this:

```
eth0: RayLink, irq 4, hw_addr 00:00:84:88:DB
ray_cs interrupt network "LINUX" started
```

Then, as the root operator, configure the eth0 device using netcfg. Repeat these steps on the other laptop, but look for something like this (again using dmesg):

```
eth0: RayLink, irq 10, hw_addr 00:8F:48:E8:45

ray-os interrupt network "LINUX" joined
```

If each laptop's IP address or host information is listed in each one's /etc/hosts, you can use any standard network utility to transfer or share information. However, if you want to allow a remote laptop user access to a LAN through the second wireless interface, you have to use one of two alternative methods: bridging or routing a subnet. More expensive wireless card series offer wireless "access points," or wireless network interfaces that quickly plug into a LAN and allow remote users to roam through different networks.

To allow access to a LAN through an Aviator card, the card is installed in either a laptop with two PC card slots to support a network (RJ-45) PC card and an Aviator card, or a desktop PC with an ISA PC card slot adapter and an installed network (RJ-45) interface adapter. For example, the desktop's first interface, eth0, might have an IP address of 192.168.2.38, while the Aviator card, installed as eth1, would have an IP address of 192.168.1.1. The route command is then used to route traffic through eth0:

```
# route add 192.168.1.1 gw 192.168.2.38
```

This ensures that the remote user, with a wireless adapter configured with an IP such as 192.168.1.2, can reach other computers on the LAN in the range of 192.168.2.XXX. You can also enable IP packet forwarding for the 192.168.1.XXX subnet like this:

```
iptables -A forward -s 192.168.2.0/24 -j MASQ
iptables -A forward -s 192.168.1.0/24 -j MASQ
```

This gives the remote user the ability to send and receive e-mail or browse the Web if the access point has an active connection to the Internet (perhaps using PPP). Continuing our example, in order to access the rest of the LAN and take advantage of IP forwarding, the wireless user must use the route command like this:

```
# route add default gw 192.168.1.1
```

This example specifies, and then creates, a default gateway, or a gate for packet information to flow to and from the remote laptop. (Note that the IP address in this example is not for the remote computer, but for the eth1 that is already reachable on the desktop PC on the LAN.)
