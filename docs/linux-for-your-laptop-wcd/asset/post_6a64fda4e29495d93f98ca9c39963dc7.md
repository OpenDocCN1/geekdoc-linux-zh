## Hard Drive Maintenance On-the-fly

Linux comes with numerous utilities to check, verify, report on, and fix filesystems. Some of these files are listed in Table 13.1.

| Utility | Description |
| :--- | :--- |
| badblocks | Searches for bad blocks on the specified device |
| bonnie | Filesystem performance benchmark utility |
| cksum | Creates a checksum and counts bytes in the specified file |
| defrag | Defragmentation utility |
| dosfsck | Checks and repairs DOS filesystems |
| dump | Backs up filesystems |
| e2fsck | Linux ext2 filesystem check and repair command |
| mbadblocks | Searches and marks bad blocks on DOS floppies |
| mcat | Dumps a raw disk image of a DOS floppy |
| pathck | Checks file name length and size |
| sum | Creates a checksum and counts bytes in the specified file |
| tune2fs | Adjusts filesystem parameters |

The most important utility, and the first program you will encounter if Linux detects a problem with your notebook's hard drive, is the `e2fsck` command. This command is run from the system's `rc.sysinit` file under the `/etc/rc.d` directory, especially when you reboot Linux after not performing a proper shutdown. If serious errors are detected, Linux drops into a manual root shell. You should then run the `e2fsck` command and specify the problematic Linux partition. For example, if a problem is detected with /dev/hda9, you might have to run e2fsck like this:

```
# e2fsck /dev/hda9
```

Follow the prompts as the command offers *repair* options. Portions of files or data collected during the repair option will be placed in your system's *lost+found* directory. After the repair is complete, you'll use the `exit` command, and Linux will reboot.

Here's the best way to avoid any hard drive problems with Linux: Always perform a proper shutdown or reboot! The `shutdown` command may be used with the `-h` (halt) option or the `-r` (reboot) option, followed by the word *now* or the number `r` to immediately shut down or reboot the notebook. You can also specify a time delay in seconds and include a message to send to all logged-on users. For example:

```
# /sbin/shutdown -r -t 300 "System is going down in 5 minutes."
```

This will reboot your notebook in 5 minutes and send the message to everyone who is logged on. You can cancel a shutdown by using the `-c` (cancel) option:

```
# /sbin/shutdown -c
```

Never just turn off your computer! Mobile Linux users need to be sure that APM is properly working and configured in order to suspend or hibernate the laptop before power runs out. This will save you untold headaches!

## Restoring Your Hard Drive

If you use Mandrake or Red Hat Linux and you did not create an emergency boot disk when you installed Linux, follow these steps right now:

1. Insert a blank floppy in your notebook's floppy drive.
2. Use the `uname` command and its `-r` (revision) option to get the revision number of the current Linux kernel:
   ```
   # uname -r
   2.2.14-15mdk
   ```
3. Use the `mkbootdisk` command along with the information returned by the `uname` command:
   ```
   # mkbootdisk --device /dev/fd0 2.2.14-15mdk
   Insert a disk in /dev/fd0. Any information on the disk will be lost.
   Press “Enter” to continue or “C” to abort:
   ```
4. After you press Enter, your boot disk will be created. Keep this disk in a safe place.

This diskette can be used to boot Linux on your notebook if LILO or another boot loader has become corrupted and won't initialize to load the Linux kernel. This happens if you install a Microsoft operating system after you install Linux. With typical disregard, Microsoft's installers will overwrite your primary hard drive's Master Boot Record. You can try to prevent this by installing LILO into the root partition of your Linux primary partition, but you will need some way to jump to the boot loader.

## LILO's Quick Read

Need to bone up on LILO fast? Here's a command line you can use if you use X11:

```
# gv /usr/doc/lilo*/User*.ps
```

This launches the *gv* PostScript viewer and displays LILO's user guide. You'll find loads of information on troubleshooting and error codes.

Emergency boot disks can be handy, especially if you cannot mount your Linux filesystem during the normal boot process. This shouldn't cause for alarm, because you have a good backup, right?

Always check and verify full backups by extracting one or two test files. This will inspire confidence in the integrity of the backup.

The general approach to recovering from a problem is to boot with the emergency boot disk and then attempt to mount the problem partition. For example, the *mount* command is used, along with the filesystem type, the partition device, and possibly read-write permissions, like this:

```
# mount -t ext2 -o rw /dev/hda9 /mnt
```

You should always make a copy of your notebook's Linux filesystem table */etc/fstab*. This text file lists known partitions and partition numbers. This file becomes even more important if you have a number of computers, or if you have created numerous partitions for your filesystem (such as having */*, */boot*, */usr*, */tmp*, and */home* on different partitions). For example, it might be hard to remember the following:

```
/dev/hda1    /     ext2  defaults     1 1
/dev/hdd1    /a2   ext2  noauto,defaults 1 2
/dev/hdd3    /d3   ext2  noauto,defaults | 1 2 |
/dev/hdd6    /d4   ext2  noauto,user | 1 2 |
/dev/hdd7    /d5   ext2  noauto,defaults | 1 2 |
/dev/hdd8    /home ext2  defaults | 1 2 |
/dev/hdd9    /music ext2 noauto,user | 1 2 |
/dev/hdd5    /opt  ext2  noauto,defaults | 1 2 |
/dev/hda9    /tmp  ext2  defaults | 1 2 |
/dev/hda6    /usr  ext2  defaults | 1 2 |
/dev/hda7    /var  ext2  defaults | 1 2 |
/dev/hda10   swap  swap  defaults | 0 0 |
```

At the very least, you should attempt to recover and back up the /home directory, followed by the /etc directory. Much of the remaining filesystem can be restored without losing any important data. This is another good reason to use different partitions for your filesystem!

## Undeleting Linux Files

Sorry. It can't be done. After you delete a file under Linux, it's gone. Actually, the file's inodes are deleted and reallocated. The file, for all intents and purposes, is gone. However, you did back up your files, right? If you didn't, and you delete an important text file, you might be able to recover a portion of the file by searching the entire contents of the partition on which the file resided, saving the search results, and then searching for known strings in the output file. This will not work for binary files, such as images or compiled programs.

This tip, by Michael Hamilton in the Linux Tips-HOWTO, relies on several factors:

- You can remember the approximate number of lines in the text file, and you know the Linux partition on which the file was created and then deleted.
- You can recall a text string close to the beginning of the file.
- You can recall a text string close to the end of the file.
- You have enough room on an available hard drive to save the search results.

For example, if you delete a file with the known string Introduction, followed by the text string Conclusion, and you know roughly how many lines (say 200) were in the file (which resided on /dev/hda5), you can use the egrep command to construct a recovery command line like this:

```
$ egrep -200 'Introduction.*Conclusion' /dev/hda5 >/tmp/hope
```
