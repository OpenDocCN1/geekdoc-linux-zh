# CardBus Support

CardBus slots, present in nearly all notebooks made in the last several years, are backward compatible with older PC cards and support greater throughput and networking speeds of 100MBps. Although several SCSI and networking cards are now supported, almost no Linux CardBus drivers can handle APM suspend and resume events.

If you’re careful, you can work around this limitation; however, most Linux users generally opt for a fully supported card.

# Boot-Time Recognition

The first step in configuring an Ethernet notebook interface is to make sure the adapter is recognized when Linux boots. Although PC card users can insert or remove (*hot-swap*) cards, you should first insert the card, connect to the LAN, and then turn on your notebook and boot Linux. After you get to the command line, use the `dmesg` command to see if the adapter was recognized (and, in the case of a PC card, recognized and initialized).

Apple iBook users booting Linux for the PowerPC will see the internal Ethernet adapter recognized as this:

```
eth0: GMAC at 00:0a:27:ad:0b:bc
```

Notebook users with a PC card adapter might see this:

```
eth0: NE2000 Compatible: io 0x300, irq 3, hw_addr 00:80:98:06:84:C5
```

These examples show that the adapter, its type, and its unique hardware address have been recognized. This does not mean that your Ethernet interface has been configured or is active! To accomplish this, you need to use one or more of the commands discussed next.

# Traditional Command-Line Configuration

Normal networking devices may be configured, assigned an IP address, and enabled through the `ifconfig` command. In this use, the command generally takes this form:

```
ifconfig device IP address action
```

For example, here’s one way you could assign an IP address and enable the first Ethernet interface in a notebook:

```
# ifconfig eth0 192.168.2.34 up
```
