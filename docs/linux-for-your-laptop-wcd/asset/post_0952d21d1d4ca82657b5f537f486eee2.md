
# Configuring for pilot-xfer

Before you can begin using *pilot-xfer* with Linux and your PDA, you need to know what serial port to hook up the Palm's HotSync cable to on your notebook. You also need to know the name of the serial port, such as /dev/ttyS0. You can see a list of serial ports recognized by Linux when you boot by using the *dmesg* command:

```
# dmesg | fgrep tty
ttyS0 at 0x03f8 (irq = 4) is a 16550A
ttyS1 at 0x02f8 (irq = 3) is a 16550A
ttyS2 at 0x03f8 (irq = 9) is a 16550A
```

Next, use your shell (such as *bash*) to create a *pointer* or *environment variable* that defines PILOTPORT to point to the serial port. For example, if your HotSync cable is attached to COM1, you would use this:

```
# export PILOTPORT=/dev/ttyS0
```

Because most notebooks today come with modern serial ports capable of high-speed data transfer, you can automatically set *pilot-xfer* to use the fastest speed possible when transferring files. Create an environment variable named PILOTRATE, and assign it a serial port speed like this:

```
# export PILOTRATE=115200
```

You're now ready to try *pilot-xfer*!

# IrDA, PDAs, and Linux

You can also use your notebook's IrDA port and an IrDA-capable Palm PDA, such as a III, IIIe, V, and so on, to back up or install software without resorting to a HotSync cable. Browse to http://home.instafl.de/wehe/IR-HOWTO.html to learn how to configure your notebook's IrDA port and Linux to work with your Palm PDA.

# Backing Up Your Palm

One of the most important things you should do occasionally when using your Palm is create a backup of the entire contents of the PDA. To do this using the *pilot-xfer* command, use the `-b` option, followed by the pathname or name of the directory you'd like to hold the backup software. Next, connect your HotSync cable and insert your PDA into its cradle. For example, to back up your PDA to a directory named *pii*, use *pilot-xfer* like this:

```
$ pilot-xfer -b pii
Waiting for connection on /dev/ttyS0 (press the HotSync button now)....
Rate 115200 too high, dropping to 57600
Connected
Back up 'pii/Net Prefs.prc'... OK
Backing up 'pii/TideDB3Locs.pdb'... OK
Backing up 'pii/TideDB2Locs.pdb'... OK
Backing up 'pii/HardBall.prc'... OK
...
```

Not all the output is shown here. Note that you do not have to turn on your Palm. Simply press the HotSync button on the cradle, and the backup will begin. Note also that if the serial port speed is too high, *pilot-xfer* drops the speed to a more negotiable value. After the transfer is complete, you can restore the contents of your PDA at any time by again using *pilot-xfer*, but this time with its *-r* option:

```
# pilot-xfer -r pii
```

# Synchronizing Your Palm

Another great feature of the *pilot-xfer* command is its ability to synchronize your PDA with your backup directory. This means that you can synchronize the contents of the directory with your Palm using a single command line. Use the *pilot-xfer* command, along with its *-s* (synchronize) option:

```
# pilot-xfer -s pii
```

Files that have not been modified will not be backed up. To install a new file into your Palm, use *pilot-xfer*’s *-i* option:

```
# pilot-xfer -i palmOMC.prc
Waiting for connection on /dev/ttyS0 (press the HotSync button now)....
Rate 115200 too high, dropping to 57600
Connected
Installing palmOMC.prc... OK
Install done
```

# Alternative Synchronization Devices

If you don't have much information to synchronize or save as a backup, there are other devices you can use with your notebook. These devices do not have to be expensive. With a little ingenuity, you can devise creative strategies to back up important information.

# Using Flash Memory

One of the least-expensive ways to quickly and (more important) safely save important data is to use a flash memory card with Linux. Flash memory cards, also known as ATA Flash drive cards, flash, or compact flash, are memory cards in PCMCIA form factors, usually of Type II. This means that if you have two PC card slots available in your notebook, you can use an additional two “mini” hard drives with Linux on your notebook.

Flash memory cards are well supported under Linux, thanks to David Hinds' Card Services. First, ensure that Card Services is running on your notebook. Red Hat and Mandrake Linux users should ensure that the proper entries exist in the file *pcmcia* under the /etc/sysconfig directory. Next, make sure that the Card Services daemon is running by using the following:

```
# /etc/rc.d.init.d/pcmcia start
```

If you have a compact flash card (such as those used by many digital cameras), insert the small card into its Type II PCMCIA carrier, and then insert the card into a slot on your notebook. You should hear two high beeps, signifying that the card was recognized and initialized. You can check this status by using the *dmesg* command:

```
# dmesg
...
hde: Sundisk SDCFB-8, ATA DISC drive
ide2  at 0x000-0x0f7,0x10e on irq 9
hde: Sundisk SDCFB-8, 7MB w/1KB Cache, CHS=245/23/32
hde: hdel

ide_cs: hde: Vcc = 3.3, Vpp = 0.0
VFS: Disk change detected on device ide2(33,0)
hde: hdel
...
```

Not all the output is shown here. But the pertinent information you can see is that Card Services has recognized the card and has assigned a device (/dev/hdel in this example) to the card. From here, it is a simple matter to mount the card under an appropriate directory (such as /mnt/flash). Use the *mount* command, like this:

```
# mount -t vfat /dev/hdel /mnt/flash
```

You can then copy files to and from the card without having to worry about disk corruption in case of power loss. This is a handy way to work while on the road! When you're finished saving your files, you can unmount and eject the card using the *umount* and *cardctl* commands (with the eject keyword and proper slot number):

```
# umount /mnt/flash
# cardctl eject 0
```

## Using Iomega Zip Drives

Another inexpensive device you can use to store information is the Iomega Zip drive. This drive comes in a variety of form factors, such as parallel port, internal and external SCSI and IDE (ATAPI), and USB. Newer drives (supported by the Linux *immr.o* kernel module) support 250MB disks. This section describes how to use the legacy 100MB Zip disks that have a parallel-port Zip drive with newer Linux (2.2.X) kernels, such as those included with Red Hat 6.0 and Mandrake 6.1 or greater.

The first step is to hook up your Zip drive to your notebook using the proper cable, and then apply power to the drive. Insert a Zip disk into the drive. Next, as root, load the *ppa* kernel module like this:

```
# insmod ppa
```
