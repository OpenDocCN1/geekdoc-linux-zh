This diskette can be used to boot Linux on your notebook if LILO or another boot loader has become corrupted and won't initialize to load the Linux kernel. This happens if you install a Microsoft operating system after you install Linux. With typical disregard, Microsoft's installers will overwrite your primary hard drive's Master Boot Record. You can try to prevent this by installing LILO into the root partition of your Linux primary partition, but you will need some way to jump to the boot loader.

# LILO's Quick Read

Need to bone up on LILO fast? Here's a command line you can use if you use X11:

```
```
# gv /usr/doc/lilo*/User*.ps
```

This launches the *gv* PostScript viewer and displays LILO's user guide. You'll find loads of information on troubleshooting and error codes.
```

Emergency boot disks can be handy, especially if you cannot mount your Linux filesystem during the normal boot process. This shouldn't cause for alarm, because you have a good backup, right?

Always check and verify full backups by extracting one or two test files. This will inspire confidence in the integrity of the backup.

The general approach to recovering from a problem is to boot with the emergency boot disk and then attempt to mount the problem partition. For example, the *mount* command is used, along with the filesystem type, the partition device, and possibly read-write permissions, like this:

```
```
# mount -t ext2 -o rw /dev/hda9 /mnt
```
```

You should always make a copy of your notebook's Linux filesystem table */etc/fstab*. This text file lists known partitions and partition numbers. This file becomes even more important if you have a number of computers, or if you have created numerous partitions for your filesystem (such as having */*, */boot*, */usr*, */tmp*, and */home* on different partitions). For example, it might be hard to remember the following:

```
```
/dev/hda1    /     ext2  defaults     1 1
/dev/hdd1    /a2   ext2  noauto,defaults 1 2
