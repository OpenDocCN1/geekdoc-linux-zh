One of many great things about using the Linux operating system is the wealth of networking tools, utilities, and commands included with every distribution. Although most networking experts give the Berkeley Software Distribution (BSD) UNIX the nod as having the fastest TCP/IP stack, there is a greater wealth of software for Linux, and you'll find many more X11 clients—such as Ethernet, Point-to-Point Protocol (PPP), monitoring tools, and related software included on a typical Linux CD-ROM.

For mobile Linux users, networking is a part of daily life. Many corporate LANs offer workers docking stations, and users on the go routinely take work home, along with an entire computer. This chapter discusses several of the more traditional ways to configure your notebook to support various networking schemes, such as switching from life on the road to plugging into the corporate network, and then connecting to a home-based LAN. You'll learn how to configure an Ethernet network adapter from the command line, or by using the Red Hat Linux netcfg and linuxconf tools. You'll also learn how to use inexpensive hardware and cables to network computers.

## Basic Interfaces

Unlike other operating systems and, indeed, other commercial UNIX operating systems, networking interfaces under Linux are created on-the-fly by various command-line tools and exist in memory space. For example, the first hardware Ethernet device recognized and configured by Linux is named eth0. However, you won't find this device listed under the /dev directory like, say, a serial port, which can be represented by any number of /dev/ttyXX devices.

Although most Intel-based notebooks do not come with an internal Ethernet adapter, a growing number do. Apple PowerBook users know that Apple's notebook line has a long tradition of providing this networking capability, including inside the latest iBook. For nearly all other users, the Ethernet adapter of choice will probably be a 16-bit PC card supporting 10Base-T. The best performance you can hope for with this type of 16-bit PC Ethernet card is about 2 to 3 Mbps, with FTP file transfers in the 800 Kbps range.

Networking using the USB port is growing in popularity but is unsupported under Linux at this time. Newer versions of the Linux kernel will offer improved USB support, so you might find many new and inexpensive networking devices becoming available for Linux in the next several years.

## CardBus Support

CardBus slots, present in nearly all notebooks made in the last several years, are backward compatible with older PC cards and support greater throughput and networking speeds of 100 MBps. Although several SCSI and networking cards are now supported, almost no Linux CardBus drivers can handle APM suspend and resume events.

If you’re careful, you can work around this limitation; however, most Linux users generally opt for a fully supported card.

## Boot-Time Recognition

The first step in configuring an Ethernet notebook interface is to make sure the adapter is recognized when Linux boots. Although PC card users can insert or remove (hot-swap) cards, you should first insert the card, connect to the LAN, and then turn on your notebook and boot Linux. After you get to the command line, use the `dmesg` command to see if the adapter was recognized (and, in the case of a PC card, recognized and initialized).

Apple iBook users booting Linux for the PowerPC will see the internal Ethernet adapter recognized as this:

```
eth0: GMAC at 00:0a:27:ad:0b:bc
```

Notebook users with a PC card adapter might see this:

```
eth0: NE2000 Compatible: io 0x300, irq 3, hw_addr 00:80:98:06:84:C5
```

These examples show that the adapter, its type, and its unique hardware address have been recognized. This does not mean that your Ethernet interface has been configured or is active! To accomplish this, you need to use one or more of the commands discussed next.

## Traditional Command-Line Configuration

Normal networking devices may be configured, assigned an IP address, and enabled through the `ifconfig` command. In this use, the command generally takes this form:

```
ifconfig device IP address action
```

For example, here’s one way you could assign an IP address and enable the first Ethernet interface in a notebook:

```
# ifconfig eth0 192.168.2.34 up
```

Another way to assign an IP address and enable the first Ethernet interface would be to use this:

```
# ifconfig eth0 valo up
```

In the first example, the `ifconfig` command is used to assign a specific IP address to eth0 and then activate the interface, or bring it “up.” The second example shows that you can also use information listed in your system’s /etc/hosts file, such as a hostname (such as valo) and its associated IP address to configure the interface. A small /etc/hosts file might look like this:

```
127.0.0.1             localhost             localhost.localdomain
192.168.1.2           wireless.home.org     wireless
192.168.2.30          valo.home.org         valo
192.168.2.31          aptiva.home.org       aptiva
192.168.2.32          ascentia.home.org     ast
192.168.2.33          stinkpad.home.org     stinky
```

To check on the status of an individual device, use `ifconfig`, followed by the device name, like this:

```
# ifconfig eth0
```

Apple iBook users might see something like this:

```
eth0          Link encap:Ethernet  HWaddr 00:04:27:AD:9C:DB
              inet addr:192.168.2.39  Bcast:192.168.2.255  Mask:255.255.255.0
              UP BROADCAST RUNNING MULTICAST  MTU:1500  Metric:1
              RX packets:30 errors:0 dropped:0 overruns:0 frame:0
              TX packets:33 errors:0 dropped:0 overruns:0 carrier:0
              collisions:0
```

Intel-based notebook Linux users might see something like this:

```
eth0          Link encap:Ethernet  HWaddr 00:E0:98:06:84:C5
              inet addr:192.168.2.38  Bcast:192.168.2.255  Mask:255.255.255.0
              UP BROADCAST RUNNING MULTICAST  MTU:1500  Metric:1
              RX packets:46778 errors:0 dropped:0 overruns:0 frame:0
              TX packets:48398 errors:0 dropped:0 overruns:0 carrier:0
              collisions:4872 txqueuelen:100
              Interrupt:3  Base address:0x300
```

Note that the output of the `ifconfig` command is roughly the same in these two examples, with the exception of IRQ and I/O address information for the Intel notebook (the iBook uses different hardware and a different type of adapter).

## Using Graphical Interface Administration Tools

Although it is possible to set up, configure, and enable networking manually under Linux, you might want to opt for a much easier approach by using one or more graphical interface networking tools. Red Hat and Mandrake Linux users will find two tools especially helpful: the older and more mature netcfg (network configuration) client, or the newer and quite capable `linuxconf` tool.

SuSE Linux users can use the YaST tool, and Caldera OpenLinux users can use `lisa` or COAS. Some of these programs, such as YaST, `lisa`, and `linuxconf`, do not require a running X11 session. On the other hand, Red Hat's `netcfg` must be run from the command line of an X11 terminal window or through Red Hat's `control-panel` client for X11.

### The iBook's Ethernet Adapter

When this chapter was written, support for the Apple iBook's internal network adapter was so new that iBook users had enjoyed the benefits of TCP/IP networking for only two weeks! During development and testing, it appeared that PowerPC Linux support for the iBook's networking adapter was not as robust as it could be (meaning that the `ifconfig`, `netcfg`, and other software did not work as well as the general PowerPC kernel support software for the internal adapter).

Although this software picture will certainly improve with time, bear in mind that the software configuration tools described here will work very reliably on Intel-based notebooks. Linux on the iBook was only four months old at the time this chapter was written!
