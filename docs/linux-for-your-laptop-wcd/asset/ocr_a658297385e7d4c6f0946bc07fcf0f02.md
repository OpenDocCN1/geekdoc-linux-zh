Fortunately, all modern Linux kernels contain code to handle these problems, so you should not have to worry about the stability of your system. You can look for some of this output when Linux boots by *piping* (with the bar operator) the output of the `dmesg` command through the `fgrep` command:

```
```
# dmesg | fgrep bug
Intel Pentium with F0 0F bug - workaround enabled
```
```

This shows (from a boot on a Pentium 300MHz MMX laptop) that Linux determined a CPU bug type and enabled a fix.

# ### How Does Linux Handle CPU Bugs?

One of the benefits of using Linux is that you get the source code to the kernel of the operating system. One of the places to see specifically how Linux attempts to detect and protect your system against CPU instruction set errors is the file `traps.c` under the `/usr/src/linux/arch/i386/kernel` directory. Note that this applies only to Intel-based computers!

Linux also runs quite handily on older 486-based notebooks. However, with prices of used 75 to 150MHz Pentium laptops in the $200 to $400 range, you’ll get much better performance with a faster CPU.

You can also use Linux to determine the exact type of CPU in your notebook. Again, use the `dmesg` command, but pipe the output through the `less` text reader (known as a *pager*):

```
```
# dmesg | less

Detected 501145385 Hz processor.

CPU: Intel Pentium III (Coppermine) stepping 01
```
```

This shows the output when booting Linux on a Pentium III 500MHz notebook. If you use the K Desktop Environment (KDE) for your X11 sessions, use the KDE Control Center client Information menu’s Processor item, as shown in Figure 2.1, to display details about your notebook’s CPU.
