Keyboards generally do not pose a problem when you're installing, configuring, or using Linux. Most problems occur when the keyboard is not placed ergonomically, is too cramped (a real possibility with smaller notebooks), does not offer frequently needed keys (such as for internationalization), or puts frequently used keys in difficult-to-reach positions. Other problems can arise if, for example, a notebook with a U.S. keyboard is booted with a Linux distribution customized for another language.

Fortunately, under Linux, your notebook's keyboard may be completely remapped, either for the console or for use during X11 sessions. This means that you can change the return values generated by individual keys to support typing in different languages using different fonts, or swap key locations for added convenience.

The correct keyboard type is usually selected during the initial Linux installation, but it may be changed later. Under Intel-based Linux, the keyboard is a PS/2 device. When you install and configure Linux for an Apple iBook, the keyboard is recognized and configured as an Apple Desktop Bus (ADB) device.

Linux includes a host of utilities to modify the keyboard. Some of these commands are listed in Table 2.4. You'll find many others available over the Internet.

Keyboard settings for X11 sessions are set in the system's XF86Config file. Although console keymaps are generally stored under the /usr/lib/kbd/keymaps directory, definitions of more than two dozen keyboards are defined in the file free86 under the /usr/X11R6/lib/X11/xkb/keymap directory (for use by the setXkbmap client).

Changing the keyboard style for the console is easily accomplished with the loadkeys command. For example, to set the keyboard to support German, you can use

```
# loadkeys de-latin1
```

To return to the default keyboard, you can use

```
# loadkeys -d
```

The default keyboard used during X11 sessions is set, as previously mentioned, in the Keyboard section of the XF86Config file. For example:

```
XkbRules	"xfree86"
XkbModel	"pc101"
XkbLayout	"us"
```

These entries correspond to those listed under the XFree86's keymap directory and define the type of keyboard. To configure X11 to load a keyboard mapping to support German, you might use this:

```
XkbModel "pc102"
XkbLayout "de"
XkbVariant "nodeadkeys"
```

Note that changes would not take effect until the X server had been restarted.

One interesting X11 client, xkbsprint, may be used to generate a PostScript graphic of your currently configured keyboard. Use this client from the command line of an X11 terminal window, specify the current X session or display, and designate an output file like this:

```
# xkbsprint :0 mykeys.ps
```

You can then use the gv client to display the graphic:

```
# gv mykeys.ps
```

For example, many notebooks place the Caps Lock key on the far left of the keyboard, while the Ctrl key (used quite often by a number of Linux text editors and other programs) resides in an awkward position, sometimes near the special Fn key.

Swapping the Caps Lock and Ctrl keys is easily accomplished for X11 sessions by entering the swap into your XF86Config file:

```
XIOptions "ctrl:swapcaps"
```

You can also do this on-the-fly during your X11 session with the xmodmap client. For example:

```
# xmodmap -e 'add lock = Control_L'
# xmodmap -e 'remove lock = Caps_Lock'
# xmodmap -e 'add control = Caps_Lock'
# xmodmap -e 'remove control = Control_L'
```

If the Caps_Lock entry really bothers you, disable the key by configuring it to return no value:

```
# xmodmap -e 'keycode 66 = NoSymbol'
```

These settings may also be placed in a file named .Xmodmap in your home directory. Another use for xmodmap is to turn the useless “Windows” key on many notebook keyboards into something more useful. If you use a window manager such as Fvwm, you can edit its resource, or configuration file, .fvwmrc, in your home directory to bind the key to different menu operations.
