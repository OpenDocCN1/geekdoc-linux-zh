
This shows that the pcmcia_core, i82365, and related support modules have been loaded. These modules will reside under the /lib/modules/2.2.X/pcmcia directory, where *X* is the version of your Linux kernel.

## Beep Patterns

Card Services also provides audio feedback when cards are installed or removed. If you insert an Ethernet PC card and then hear one high beep and then one low beep, but you don’t see any errors and the card seems to be recognized, make sure that you have set up the card under Linux for networking by assigning an Internet Protocol (IP) address. If you hear only one beep, the card was identified but not configured. Two high beeps generally indicates that a card was recognized and configured.

Card Services comes with a PC card control command named `cardctl`. This command, with its nine command-line options, may be used to perform software insertion and removal of a card from a specific slot in your notebook. You might also find the X11 client `cardinfo`, shown in Figure 2.7, a graphical interface to PC card management for your notebook.

This is very important if you don’t want to waste time and trouble! The PCMCIA-HOWTO contains loads of information on diagnosing, troubleshooting, and configuring, as well as information on using Card Services with different Linux distributions. ## Serial Ports

Your notebook should have at least one male nine-pin serial port available for external serial devices. Larger notebooks have the port available through the rear of the case, and ultralights or subnotebooks might use a port "extender" or replicator.

Existing serial ports are recognized by Linux when booting. You can check to see what ports were recognized by using the dmesg command like this:

```
# dmesg | fgrep ttyp
ttyS0 at 0x03f8 (irq = 4) is a 16550A
```

In this example, a single serial port, ttyS0, was found at the specified address, using an initial Interrupt Request (IRQ). This is a value that designates an assigned location for the device—in this case, a 16550A Universal Asynchronous Receiver-Transmitter (UART).

Serial ports under Linux generally have the name ttyS0, ttyS1, ttyS2, and so on. They correspond to device pointers under the /dev directory and usually match those ports similar to COM1, COM2, COM3, and so on under DOS.

Linux supports serial-port transfer speeds up to 115200 bits per second (bps). The main command to control characteristics of your notebook's serial port is the setserial command. This command can be used to configure the port, IRQ, UART, speed, and other characteristics of your serial ports. If you're new to Linux, be sure to read its man page if you have trouble getting your modem to work. Another good document to read is David S. Lawyer's Serial-HOWTO, found under the Red Hat or Mandrake Linux /usr/doc/HOWTO directory.

The good news is that you shouldn't have to troubleshoot serial-port problems very often. The only time you can run into difficulty is when different devices, such as your sound card or IrDA and serial ports, have an IRQ conflict. By using the setserial command to change an IRQ, you should be able to resolve any problems quickly. For example, to change /dev/ttyS1 from an initial IRQ of 3 to a new IRQ of 4, use setserial like this:

```
# setserial /dev/ttyS1 irq 4
```

You can then confirm the change by using `setserial`'s -a option:

```
# setserial -a /dev/ttyS1

/dev/ttyS1, Line 1, UART: 16550A, Port: 0x02f8, IRQ: 4
    Baud_base: 115200, close_delay: 50, divisor: 0
    closing_wait: 3000, closing_wait2: infinite

    Flags: spd_normal skip_test
```

The `setserial` command will print as much information as it can determine about the specified serial port.

If you need additional serial ports for your notebook, consider getting a serial-port PCMCIA card.

## Internal Modems

Most notebooks, including the Apple iBook, come with an internal modulator/demodulator, known as a *modem*. Having a working internal modem in your notebook when using Linux is a wonderful thing. You don't have to carry an extra PCMCIA card or use a large, bulky external modem with its associated cables and power supply.

That said, here's the bad news: In an effort to cut manufacturing costs, save money, and reduce chip count, most Intel-based notebooks on the market today use proprietary "software-driven" modems that depend on closed-source drivers and that work only with operating systems from the PC software monopoly.

These modems are, in my opinion, simply bad engineering even though today's CPUs have more than enough horsepower to handle the work with software. As much as I'd like to say that you should not buy a laptop with an internal "controllerless" modem, the truth is that many so-equipped notebooks work well with Linux—with the exception of these useless modems. Even worse, no manufacturer (with the possible exception of one at the time this chapter was written) will release the specifications so that an Open Source solution may be developed.

This puts you, the consumer, at the mercy of proprietary software and a slow-to-respond industry. The modem controller chip manufacturers do not live in Internet time, but mobile Linux users do. The industry's sloth-like response to consumer needs, bug fixes, and other problems is only exacerbated by the notebook manufacturing industry's acquiescence in continuing to build notebooks with these devices. This situation won't change until the Linux notebook user base grows and consumer demand forces reevaluation of the hardware or software design strategy.

### iBook Trade-Off

You can use the iBook's internal modem if you use the Yaboot Boot utility and boot Yellow Dog Linux using Apple's Open Firmware prompt. However, your X11 sessions will be limited to 256 colors. If you boot Yellow Dog Linux using the BootX control panel, the internal modem will not work, but you'll be able to use X with thousands of colors!

The good news is that at least one project is attempting to develop an Open Source driver for some of these devices. Browse to
http://www.linmodems.org

You can read an alternative view about how to use these chips with Linux, such as for an answering machine, call recording, and so on. You'll find the source code for this ongoing project, along with a (predictable) binary-only driver from Lucent in the form of a 500Kb+ kernel module. The driver, named lucent.o, has been reported to work with a number of Lucent chipsets in different notebooks. While this book was written, I tested an IBM ThinkPad 390X, Mandrake 7.0, and the lucent.o module, and found that reliable connections were possible at speeds up to 38400 Kbps.

The other good news is that not all notebook manufacturers use these devices. Some notebooks on the market include "real" internal modems! Although the manufacturer rarely touts this as a marketing point, such laptops (like the Sony 505TX and TR) are highly prized items with mobile Linux users.

Notebooks may also be ordered without an internal modem. If so, buy a supported PCMCIA 56K V.90 modem or a combination Ethernet/modem card. Some of the best modem cards are those that do not rely on proprietary cables (or dongles) but instead have a pop-out tab sporting an RJ-11 telephone jack. If you are looking for an excellent combination card that does not use proprietary dongles or take up two Type II slots, the Linksys EtherFast 10/100 + 56K V.90 PCMCIA card is an excellent choice. This card features built-in RJ-11 and RJ-45 ports for telecommunications and network. You'll also be able to use another Type II card if you have two PCMCIA slots in your notebook.

When you've determined what serial port is used by your internal modem (hint: use dmesg to look for /dev/ttyS1 output), you should use the ln command to create a symbolic link named /dev/modem for use by communications programs or when connecting to the Internet:

```
$ ln -s /dev/ttyS1 /dev/modem
```
