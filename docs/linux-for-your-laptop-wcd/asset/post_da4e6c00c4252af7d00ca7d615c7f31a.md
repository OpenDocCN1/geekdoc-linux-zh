## Network Installation

If your notebook does not have an internal CD-ROM, but you have access to a LAN, you can install Linux over the network in a variety of ways. You'll need to use the PCMCIA boot disk unless your notebook has an internal Ethernet port, in which case you can try to use the BOOTNET.IMG floppy to boot to your installation. Create your boot disk, make sure your notebook is attached to a LAN, and reboot. Page through the initial Red Hat dialog boxes until you come to the Installation Method dialog box, shown in Figure 4.5.

Scroll through the list of types of installation, and then use the spacebar to choose an install to match your NFS-exported, FTP-mounted, or HTTP-available Linux install distribution. When finished, press Enter to start the install process.

### Installation via FTP

Installing Linux via FTP is very easy. If you're working on a local LAN and you have another Linux computer set up as an FTP server, you can have your Red Hat Linux CD-ROM mounted directly in the /home/ftp/pub directory. Use the mount command like this:

```
# mount -t iso9660 /dev/cdrom /home/ftp/pub
```

In this example, the CD-ROM device is /dev/cdrom (it could be /dev/hdc, or another device, depending on the remote computer). The Linux CD-ROM is then mounted at the /home/ftp/pub directory and made available for public use. Note that other distributions, such as SuSE Linux, might use the /usr/local/ftp directory for anonymous logins and that the remote computer must be running the FTP daemon!

After you choose the FTP installation and press Enter, the installation will recognize your network card and display the dialog box shown in Figure 4.6.

If you're on a network that provides the Dynamic Host Control Protocol (DHCP) service, choose that service and press Enter to have an Internet Protocol (IP) address automatically assigned to your adapter. To manually configure your card, select the Static IP address item and press Enter. You'll then see the dialog box shown in Figure 4.7.

### Installation via NFS

Yet another way to install Linux is through the use of the Network File System (NFS). To set up an NFS installation on a LAN, the remote computer must be running the nfsd daemon and have your computer’s IP address or hostname in its /etc/exports file. For example, if you assign an IP address of 192.168.2.70, the remote computer should have an entry that looks similar to this:

```
/d2/pub                 192.168.2.70    (ro)
```

This entry shows that the computer with the IP address of 192.168.2.70 has read-only access to the /d2/pub directory. The Red Hat software would then be available under this directory. To install Linux via NFS, attach your notebook to the LAN, choose the NFS installation method, and be sure to assign the IP address 192.168.2.70 for the installation. Proceed through the dialog boxes until you come to the NFS Setup dialog box, shown in Figure 4.11.

Enter the remote server’s hostname (or IP address), along with the directory containing the Red Hat software. Select OK and press Enter to begin the installation.

## PLIP Installation

If you have a spare computer and a correctly wired 12-conductor parallel port, you can install Linux onto your notebook. Your first task should be to read the PLIP-Install HOWTO document, found under the /usr/doc/HOWTO directory or through http://www.linuxdoc.org. Although this HOWTO describes using an alternative Linux distribution, Debian Linux, you may also use Red Hat Linux.

The basic procedure is to connect the two computers, set up networking and an NFS export or FTP service on the remote computer, and boot your notebook to a network installation. When the installation fails to find a network card, you'll be asked to select a driver, as shown in Figure 4.12.

You might then be asked if you want the installation to autoprobe your notebook's parallel port settings, or to specify settings. In most cases, the autoprobe will work, and you can then proceed through the installation. If you have difficulty, you might want to try setting up networking between two computers using the same parallel cable to make sure it works. You should also make sure that the remote computer is not running the line printer spooler daemon, lpd, and that it does not have the Linux kernel's lp.o printer module loaded. For details about setting up PLIP networking, see the PLIP-HOWTO.
