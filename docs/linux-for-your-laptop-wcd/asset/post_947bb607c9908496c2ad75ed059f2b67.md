As you can see, there is quite a bit of information on an audio CD besides music! The `cdcd2wav` command uses your audio CD's directory and track information when reading and saving music. You can use the command's `track` option to specify a range or series of tracks to record. Be warned that the resulting .wav files will have more than 10MB per minute of song length, so you can quickly fill up a smaller partition when grabbing all the tracks from an audio CD.

The resulting .wav file can then be converted to .mp3 format by using an MPEG encoder, such as the `bladenc` command. Use this command, along with the name of the .wav file, like this:

```
$ bladenc audio.wav
```

After you press Enter, you'll see the following:

Note that even on a 300MHz Pentium computer, this process can take as long as 10 or more minutes for a 5-minute song! However, you'll end up with a file that provides about 1 minute of digital for each minute of audio—a 10:1 compression ratio over using the .wav format! Using a little simple math, this means that you can store about 10 one-hour audio CDs in a little less than 600MB of hard drive storage.

## XMMS Rules!

Without a doubt, one of the best .mp3 players for Linux and X11 is the *xmms* client. This program uses playlists of files to play, offers equalizer controls for fine-tuning sound, and collapses to a nifty, ultra-small control panel that is sure to please any mobile Linux user looking to maximize screen real estate.

Although you can use the command line to create .mp3 files, a much easier way to rip audio CDs into .mp3 format is to use a graphical interface client that will build the necessary command lines automatically and save your files with several mouse clicks.

## Using the Krabber Client

One of the easiest-to-use graphical clients for converting audio CDs to .mp3 files is the *krabber* KDE client. This program uses various installed rippers and encoders to offer choices in settings, such as quality and the name of each track. Another great feature is that if you have an active Internet connection, *krabber* automatically saves and uses your audio CD’s title, artist, and track information after retrieval from a remote server!

To get started, insert an audio CD in your notebook’s CD-ROM drive. Then start the *krabber* client from the command of an X11 terminal window like this:

```
$ krabber &
```

Note that if you want your files named automatically, you should also have an active Internet connection. When *krabber* starts for the first time on your computer, it checks for required files, such as ripping and encoder utilities. After the program starts, you’ll see the window shown in Figure 18.13.

Select Settings, CDDB settings. In the Krabber Configuration dialog box, select the CDDB tab. Click on the Enable Remote CDDB item, select a CDDB remote server, click on Update, and click on OK. (Note that this dialog box is very similar to the one shown in Figure 18.10.)

Next, click on button 1 to choose your music. You’ll see a list of tracks. To rip the entire CD, click on the Take All button. The *krabber* client then displays your tracks, queries a remote CD database server, and then displays the name of the CD, along with the name of each track on the CD, as shown in Figure 18.14.

## Writing CD-ROMs

Until the advent of newer notebook models from Dell Computer, few (if any) laptops provided an internal CDRW drive. The most common way for mobile Linux users to copy, create, or collect audio tracks and data on CD-ROM is to use an external CDRW drive with a PCMCIA interface. Unfortunately, the current marketplace offers a wide and potentially confusing array of choices when it comes to picking an external CDR or CDRW drive. These external drives vary widely in quality, performance, price, and size. You’ll find slimmed-down, PCMCIA port-powered versions from well-known manufacturers (which might or might not work with Linux) to bulky, shoddily built, no-name pieces of junk that only serve to create write-once coasters.

Fortunately, you can check the CD-Writing HOWTO for an up-to-date list of drives that work with Linux. Browse to

```
http://www.gugug.de:8080/cgi-bin/yi-nn1/lsc-orig.pl
```

You can browse through a list of hundreds of drives from nearly 50 manufacturers, and read reports from users on how well a model performs.

Less-expensive (although perhaps equally capable if supported) combinations generally use a PC Card IDE interface with an ATAPI CDR or CDRW drive. However, using an ATAPI CDR or CDRW drive with Linux can create additional steps and might or might not require you to rebuild your Linux kernel. This is necessary to add SCSI host adapter emulation, which makes your IDE CDR or CDRW drive appear as a SCSI device. Before trying this, however, try booting Linux with the kernel argument append keyword, followed by the device name of your ATAPI CDR or CDRW drive:

```
append="hdd=ide-scsi"
```

In this example, /dev/hdd is the designated drive. You can then try using the insmod command to load the ide-scsi.o module:

```
# insmod ide-scsi
```

For the least amount of hassle, you can choose to use a SCSI PC card adapter and an external SCSI CDRW drive. Although these drives are bulky, require an external power supply, and cost more, you're almost guaranteed ease of use, speed, and compatibility when using this type of drive with Linux to create CDR or CDRW disks. One combination that I can heartily recommend is an Adaptec 1260 PCMCIA adapter and an HP or Yamaha external drive (such as Yamaha's CRW8424SX). You can check David Hinds' SUPPORTED.CARDS document for a list of supported SCSI adapter PC cards.

To use an external SCSI CD-Writer, insert the PCMCIA SCSI adapter, and then turn on the external drive. Next, power up your notebook. During the boot process, you should hear two high beeps. When you examine the kernel boot messages (using the dmesg command), you should see something like this:
