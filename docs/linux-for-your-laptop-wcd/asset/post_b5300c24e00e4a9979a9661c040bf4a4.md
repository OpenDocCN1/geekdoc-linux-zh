
Note that you should never suspend or eject a card that is in use, especially an IDE flash memory card! You could corrupt the card's filesystem. The cardinfo client is a handy tool to get troubleshooting information about a card. (Hint: You can also use the dmesg command to look for logging messages when a card is inserted.)

Problems generally occur when you try to use an unsupported PC card, if incorrect configuration settings are used in the /etc/pcmcia/config.opts file, or if an IRQ conflict occurs. Card Services provides diagnostic beeps when cards are inserted or removed. Two high beeps generally signify successful recognition and configuration. If you install a network adapter and then hear one high beep followed by a low beep, the card might have been recognized, but you might not have enabled networking or set up the card's IP addressing.

If you're having trouble using a card with Linux on your notebook, first read David Hinds' PCMCIA-HOWTO. You can find a copy at http://pcmcia.sourceforge.org/ or in your system's /usr/doc/HOWTO directory. Another place to get help is to ask your question on Usenet's comp.os.linux.portable newsgroup.

## Configuring Sound

Configuring Linux to work with your notebook's sound system can be either very easy or very difficult, depending on your notebook's model and whether it is the "latest and greatest" from the manufacturer. Although most notebooks provide diminutive speakers producing tinny sound, nearly all of them have a line-out jack so that you can play sounds or music through external amplifiers or speakers.

To configure sound for Red Hat or Mandrake Linux, use the sndconfig command. You might also need technical information regarding your notebook's sound chipset and settings before you begin. If you do not have this information available in your notebook's manual, reboot your notebook and check the BIOS audio section for clues about I/O address, IRQ, and DMA settings you can try. Then type sndconfig at the console and press Enter. You'll see the dialog box shown in Figure 6.3.

Scroll through the list of cards and look for your notebook's sound system. If you don't find an exact match, check your notebook's technical documentation or manual to see if your notebook's sound system emulates a common card, such as a SoundBlaster. Many notebooks' sound chipsets provide such emulation, making the job of configuring Linux for sound a bit easier (this is true on the Sony 505 series of laptops). When finished, press Enter. You'll then be asked some technical information about the sound card, as shown in Figure 6.5.

When finished, press Enter. The sndconfig command will then attempt to play a sound (Linus Torvalds pronouncing "Linux") and then a MIDI scale of notes. When finished, the sndconfig command will save the settings. They will be used the next time you boot Linux.

Sound support for Linux is provided by loadable kernel modules found under the /lib/modules/2.X.XX/misc directory (where X.XX is the version of your Linux kernel, found with the uname -r command). You'll see some documentation in the /usr/src/linux/Documentation/sound directory if you install the Linux kernel sources. For example:


These files may also be found under the /usr/doc/kernel-doc-2.X.XX directory. If you run into trouble and you know the sound chipset used in your notebook, you can try searching the pertinent file for clues on configuration. But if nothing seems to work, don't give up hope! There are alternative sources of help.

Browse to http://www.alsa-project.org and follow the links to download the Advanced Linux Sound Architecture sound drivers for Linux. This set of free, alternative sound drivers supports more than 75 different types of sound cards—and support for new cards is being added all the time. After downloading and decompressing the required drivers, libraries, and utilities, you'll need to navigate to each directory and do the following:

```bash
# ./configure
# make
# make install
```

This will build and install the drivers (which are loadable kernel modules). You can then use recommended settings (as documented in the ALSA packages) in your /etc/modprobe.conf or similar systems/etc/conf.modules file, along with the `modprobe` command, to load and run the ALSA modules.

The drivers, if compatible, will correctly configure elements of your notebook's sound system, but they must be "unmuted" before use. For example, to set the volume at 100 percent for the master volume one, you need to use ALSA's `amixer` command like this:

```bash
# amixer set Master 100 unmute
```

After unmuting other recognized devices (such as Bass, Treble, Synth, PCM, Line-In, MIC, and CD), you can play music or sound. If you need help installing and configuring the ALSA drivers, browse to http://www.alsa-project.org/~valentin/Alsa-sound-mini-HOWTO.html

If the ALSA sound system doesn't work for you, your next option is to browse to http://www.opensound.com. You can download a demonstration version of the commercial Open Sound System sound drivers from 4Front Technology. At last count, more than 330 different sound systems were supported. Chances are quite good that this software will work with your notebook's sound system if the free versions of OSS (included with every Linux distribution) don't work for you.

Download the OSS software package after choosing the correct version from the Web page. Create a temporary directory, copy the package into the directory, and navigate into the temporary directory. Next, decompress the software using the `tar` command:

```bash
# tar xvfz oss*.tgz
INSTALL
LICENSE
oss-install
oss.pkg
```

To install the software, use the `oss-install` script like this:

```bash
# ./oss-install
```

The screen will clear, and you'll be presented with a number of dialog boxes to help you install sound support.

## Solving Problems with X

Although Linux works quite well in console (text-only) mode, a working X11 configuration can be extremely important and especially satisfying. Unless you're using your notebook as a server, you'll probably want to benefit from the graphics features of your laptop's display. The good news is that X11 works on just about every laptop ever made. How well X11 works depends on how well X is supported by your notebook's graphics chipset.

Getting the most out of your notebook's display with the XFree86 software is a combination of several factors. First, your notebook's graphics chipset should be supported by the XFree86 software. Next, you need to craft a correct XF86Config file, which is usually located under the /etc/X11 directory (or /usr/X11R6/lib/X11 or /root if you're testing X as the root operator).

The XF86Config file settings are critical to having a properly configured graphical interface. This file contains various sections dealing with the following:

- Locations of installed fonts and other files
- Settings and options for the X server
- Keyboard configuration and mappings of various keys
- Pointer settings, such as type, speed, or number of buttons
- Correct horizontal and vertical frequency settings of your notebook's LCD display
- Specifications, such as the amount of video RAM and options for your notebook's graphics chipset
- Lists of available resolutions and color depths for your notebook
- Options specifying what color depth and resolution to use by default

The format and content of the XF86Config file are documented in its man page, which you can read with the man command like this:

```bash
$ man XF86Config
```

Scroll through the document and press the Q key when finished. You should also read the file QuickStart.doc under the /usr/X11R6/lib/X11/doc directory when trying to manually configure X11.

If you cannot get your display configured during your Linux installation, don't worry! Every Linux distribution, including Red Hat, Mandrake, and Yellow Dog Linux, comes with two or more utilities you can use to configure your display. Each utility is designed to build a working XF86Config file for your notebook and X11.
