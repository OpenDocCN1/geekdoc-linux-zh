You can also use the `t` option with the `tar` command's `z` option to decompress the file and combine two steps into one. For example, to see a list of the contents of a compressed tape archive, such as `xpat2.tar.gz`, you would use this:

```bash
# tar tzf xpat2.tar.gz
```

Viewing the contents of a compressed archive is the safest thing to do before blindly decompressing its contents. You can also view the contents of an .rpm archive by using the `-qpl` option:

```bash
# rpm -qpl xpat2-1.04-2.i386.rpm
```

This will query the package and list, or print the contents and file destinations of files within the archive. To extract and install the contents of an .rpm file, use the `-ivh` option, followed by the name of the .rpm file:

```bash
# rpm -ivh xpat2*.rpm
```

To extract the contents of a compressed tape archive, use `tar`'s `x` (extract) option:

```bash
# tar xzf xpat2.tar.gz
```

### Creating Archives

Creating compressed archives is an easy way to quickly back up important data. For example, you can easily back up the contents of all your users' directories like this:

```bash
# tar cvzf home.tgz /home
```

By creatively combining your compression utilities and Linux scheduling, you can quickly build an automated backup system. If your backup needs are modest, you can save multidisk archives to floppy disks quite easily if you use the `tar` command's `w` option:

```bash
# tar cvwM /dev/fd0 /home
```

When the disk fills up, the `tar` command returns this prompt:

```text
Prepare volume #2 for /dev/fd0 and hit return:
```

Eject and label your floppy disk, and then continue until the `tar` command finishes. To restore your files, insert your first floppy disk from the archive, and then use `tar` like this:

```bash
# tar xvfl /dev/fd0
```

## Getting the Most out of Your Notebook's RAM

One of the most expensive components of any computer system is memory. If memory were inexpensive compared to hard drive storage, most notebook computers wouldn't have any moving parts. They would simply use battery backed-up RAM and flash RAM to boot the operating system. Fortunately, because of the bloated software requirements of "other" commercial operating systems, consumers and the notebook industry are inured to ever-increasing requirements for greater CPU speeds, larger-capacity hard drives, and, of course, more money in which to run applications.

This is all good news for Linux users, because even the very latest Linux kernels and software for most users run quite comfortably in 32 or 64MB of memory. You can even get by with a 16MB notebook computer (but few of these are found on the market today). At the time this chapter was written, base memory on most models ran at about 64MB.

Linux comes with many different software utilities to display and manage processes running in memory. Like most modern operating systems, Linux incorporates memory management in the kernel. Requests for often-used blocks of memory are cached for quick retrieval. Large blocks of memory flowing outside user space that are not needed may be paged or sent to the swap partition. This partition, usually *twice the size of available physical memory* (but which might be many times the size of your notebook's RAM), is usually created when you install Linux. When you install Linux, make this partition large enough to incorporate any planned needs, such as graphics work, or if you plan to expand your notebook's memory.

**Swap Is Not Hibernate Memory!**

Nearly all notebooks support Advanced Power Management. One of the modes of this power management is the ability of the notebook's BIOS to save a “snapshot” of currently running memory to a special disk file or partition on your notebook’s hard drive. If you install Linux and see a small partition about the size of this partition alone. You’ll need to create a swap partition and at least one native Linux partition during your installation.

### Showing Memory

To get a quick look at your memory, use the `free` command:

```text
$ free

             total       used       free     shared    buffers     cached
Mem:         128016     124720      3296      56612      14292      69888
-/+ buffers/cache:      40540      87476
Swap:          264560       3520     261040
```

This example shows a notebook with 128MB of RAM, of which 124MB is in use. The swap file size is about 258MB, but only 3.5MB has been used. You can also use the `-b`, `-k`, or `-m` option to display the values in bytes, kilobytes (the default), or megabytes. In addition, you can use the `free` command's `-s` option, followed by a number in seconds, to indicate how often the display should be updated.

Other utilities that can show memory usage include `vmstat`, as well as graphical programs, such as `xosview` for X11, shown in Figure 8.3.

### Managing Processes

One of the best features of Linux is that you have total control over the software you start and run. If a program goes awry, you can kill its process and go back to work with confidence, without having to worry about your system's stability. Experienced Linux users routinely use the `ps` command to display a list of running processes.

Other commands found with nearly every Linux distribution include `uptime` (which displays how long your system has been running), `w` (which shows who is logged in), and *top*. The **top** command works with or without X11. It offers keyboard commands to display built-in help and sort processes by use or by user. It can also be used to kill any task (as long as it is owned by you).

## General Advice

The following list is a small set of rules that may help you economize system resources when faced with building a Linux system on a notebook with limited RAM, hard drive space, and CPU speed. Many interactive programs are event-driven, and spend most of the time waiting for your input when running. This means that you can build and run a capable Linux system on older hardware through cautious choice of software, and adopting simple cost-saving strategies.

- Don't install software you don't need. Why have games installed if you don't need them?
- Remove software that duplicates other software. How many text editors do you need, anyway?
- Text-based programs generally require less memory than GUI-based clients. You can browse the Web with the text-based Lynx browser instead of Netscape Communicator.
