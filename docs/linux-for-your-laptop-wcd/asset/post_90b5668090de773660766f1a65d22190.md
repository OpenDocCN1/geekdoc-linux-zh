
Save and close the file; then reboot your iBook. During the reboot, hold down the Cmd+Option+o+f keys, and you'll see Apple's Open Firmware prompt. To boot Linux, use the boot keyword, along with a pointer to the Yaboot loader like this:

```
`boot hd:8,/yaboot.tzh1`
```

You'll then boot to Linux. Note that, at least with Yellow Dog Linux 1.2, your X11 sessions will be limited to 256 colors! You can find out more about Yaboot by perusing [http://www.yellowdoglinux.com/support/faq/bootloader.shtml](http://www.yellowdoglinux.com/support/faq/bootloader.shtml)

An easier way to boot Linux is to use BootX. This program allows you to choose different Linux kernels, boot to an installation with the Yellow Dog Linux 1.2 CD-ROM, and set various options, such as delays or for video. If you use BootX on your iBook, current or new Linux kernels may be kept in a folder named Linux Kernels inside your Mac's System folder. This is an easy way to test new Linux PPC kernels.

To properly boot Yellow Dog Linux on the Apple iBook, you should use the following BootX settings:

- The proper Linux kernel should be selected in the Kernel: field.
- The root device (if Yellow Dog Linux is installed on the same hard drive) should be set to /dev/hda10.
- The “No video driver” option should be selected.
- In the Options dialog box, the “Force video settings” option should be selected.
- The “More kernel arguments” field should have an entry of `adb_buttons=103,111` to map F11 and F12 to the middle and right mouse buttons for use during X11 sessions after booting Linux.

After booting, if you do not boot directly to X11, you can use Ctrl+Command+2 through Ctrl+Command+6 to jump between text-only Linux consoles. Unfortunately, you cannot jump from an X session to a text-only console and back using the Intel-based X11 Ctrl+Alt+F2 though Ctrl+Alt+F6 and Alt+F7 keyboard commands.

## PCMCIA and Card Services

David Hinds' Card Services is the most important software package for mobile Linux users besides the Linux kernel and a base installation. Nearly all Intel-based notebooks are equipped with one or two PCMCIA card slots. (Note that the Apple iBook does not support PCMCIA.)

Support for PCMCIA cards, now better known as PC cards, is provided by the cardmgr daemon. This daemon is started through the /etc/rc.d/init.d/pcmcia script.

![](img/70d85e6f4d1ff2750ca2a98ba3d9855c_173_0.png)

Figure 6.1 The ntsysv command is used to set specific services to be started when Linux boots on your notebook.

If you have configured Linux to use cardmgrd when booting. One way to ensure that Card Services is available is to use Red Hat’s ntsysv command. Type ntsysv on the console or command line of an X11 terminal window and press Enter. You’ll see the dialog box shown in Figure 6.1.

Scroll through the list of services using the up and down arrow keys to select pcmcia, and then press the spacebar to ensure that an asterisk (*) appears. Press the Tab key to highlight the OK button, and then press Enter. This will ensure that PCMCIA support is present when Linux reboots. You can also use the pcmcia script to start the service right away, like this:

```
$ /etc/rc.d/init.d/pcmcia start
```

If you’re contemplating purchasing a PC card for Linux, do yourself a favor and be sure to read the latest list of supported cards in the SUPPORTED.CARDS file. You’ll find a copy under the /usr/src/linux/pcmcia* directory if you install the Linux kernel source on your notebook. You can also read the very latest copy by browsing to

```
http://pcmcia.sourceforge.org/
```

### Building and Installing Card Services

If you have a card that does not work with Linux, take heart; support for new cards is often added to each new release of the Card Services software. If the version of Card Services included with your Linux distribution does not work with your PC card, you can try to download the latest drivers. To install the new drivers, decompress the sources in the /usr/src/linux directory. Note that you’ll need to have the Linux kernel sources installed.

Navigate to the new pcmcia directory, and then use the Configure script to set up and create a makefile, like this:

```
# ./Configure
```

After you press Enter, you might see this:

------ Linux PCMCIA Configuration Script ------

The default responses for each question are correct for most users.
Consult the PCMCIA-HOWTO for additional info about each option.

Linux source directory [/home2/rpn/BUILD/linux]: /usr/src/linux

Type /usr/src/linux to specify the Linux kernel source directory (this works with Red Hat and Mandrake Linux), and then press Enter. You will see the following:

The kernel source tree is version 2.2.14-15mdk.
The current kernel build date is Tue Jan 4 22:24:20 2000.

Alternate target install directory [/var/tmp/kernel-2.2.14-15mdk-root]:

The Configure script will recognize the current Linux kernel and then offer an alternative installation directory. If you're not worried about overwriting your original modules, you can use the default setting and press Enter. You'll then be asked the following:

Module install directory [/lib/modules/2.2.14-15mdk]:

This step is critical if you want the new Card Services PCMCIA kernel modules to work with your system. If you accept the default settings, the new modules will overwrite your existing ones. If you just want to see if the modules will build, specify an alternative directory and press Enter.

Build 'trusting' versions of card utilities (y/n) [y]:

This option is used to create modules that may be used by anyone on your notebook---not just the root operator. Type y or n, and then press Enter.

Include 32-bit (CardBus) card support (y/n) [n]:

If you use newer CardBus PC cards, press Enter. Note that fewer CardBus cards are supported than older 16-bit PC cards.

Include PnP BIOS resource checking (y/n) [n]:

Unless you need your notebook's BIOS to help configure your card, use the default option, n, and press Enter.
