
## Bridging

You can also try using an experimental feature of the Linux kernel to build a wireless bridge for your LAN. Using a spare desktop or laptop recompile the Linux kernel to enable bridging. Install the wireless card and network card, but do not assign an IP address to the wireless card.

Next, browse to

```
ftp://shadow.cab1.net/pub/linux/
```

Download, build, and install Alan Cox's bridge configuration utility from the file BRFCFG.tgz. Enable both network cards, but use the ifconfig command like this:

```
# ifconfig eth0 promisc up
# ifconfig eth1 promisc up
```

You can then enable bridging with this command:

```
# brcfg -ena
```

After you start your wireless remote connection, you should be able to access any computer on your LAN.

## Telco Connections

If you're fortunate enough to have one of those rare Intel-based laptops with a real built-in modem, congratulations! All lesser beings have to purchase a PC card modem or hook up an external modem through the notebook's serial port. Before the advent of the Internet, modems were the portals to the outside world and the glue that held wide-area networks together. And despite the increasing movement toward Digital Subscriber Lines (DSLs) and cable modems, modems still enjoy popular use, although transfer speeds have stagnated to a now more-or-less standard 56Kbps, with various compression technologies and techniques boosting throughput slightly.

### The iBook Modem and Lucent Module

The Apple iBook modem is only supported under Linux when you boot using Apple's OpenFirmware prompt and the Yaboot utility. If you have an Intel-based notebook with a Lucent controllerless modem, you can try the lucent.o modem enabler available at http://www.linmodems.org.

## Setting Up to Support Dial-In

You can set up your notebook to accept dial-in calls via the telephone and your notebook’s internal or attached modem. By making a few simple changes to some files on your system, you can dial in to and—if your notebook is connected to a network—access the network.

Several utilities are available with every Linux distribution that allow you to set up Linux for dial-in:

- **ugetty**. Part of Kris Gleason’s getty_ps package for Linux, this program may be used with a number of speeds and configurations (contained in the file /etc/gettydefs), but you must first correctly set up your modem for dial-in support and create a special configuration file for each line monitored.
- **agetty**. An extremely simple and easy-to-use line-monitoring utility by Wietse Venema that supports embedded modem setup strings in the initialization line (you’ll see an example in a moment).
- **mgetty**. Part of Gert Doering’s mgetty+sendfax package, this utility may be used to control your modem to answer the phone, send and receive faxes, and even (with the right hardware) become a voice answering machine.

The easiest command to set up is agetty. Red Hat and Mandrake Linux users should log in as the root operator and then open the system’s initialization table, /etc/inittab. Look for the entry for runlevel 3, used for multiple users and networking (note that this runlevel is 2 for SuSE Linux users):

```
3:2345:respawn:/sbin/mingetty tty3
```

Although the mingetty command is fine to monitor local logins, you’ll want to change this entry. To have agetty monitor the serial port used with your modem and have the modem answer the call on the first ring, change the entry to the following:

```
3:2345:respawn:/sbin/agetty -w -I “ATE0&1D2&Dz&IS0=11\015” 115200 ttyS0 vt100
```

This example assumes that you’d like to support high-speed answering, and that your notebook’s modem is attached to /dev/ttyS0 (corresponding to DOS COM1). Note that you shouldn’t make this change if you don’t have agetty installed. You can find a copy at ftp://ftp.porcupine.org/pub/security/index.html

The ugetty command may also be used like agetty. Again, edit the runlevel 3 entry to look like this:

```
3:2345:respawn:/sbin/ugetty ttyS1 115200 vt100
```

Save this file and exit. You will also need to create a file named **ugetty.ttyS1** under the `/etc/default` directory containing this:

```
ALTLOCK=ttyS1
TIMEOUT=60
INIT="" \d+++\dAT\r OK\r\n ATH0\r OK\r\n AT+E\r\nS00\r\nS4\r\nS8=1\r OK\r\n
DELAY=1
```

The entries in this file specify a lockfile so that `ugetty` will restart and reinitialize your modem, tell `ugetty` how long to wait (in seconds) before disconnecting if the connection is idle, contain a modem initialization string, and finally, specify how long to delay (in seconds) before printing your system's log-in banner.

After making these changes and creating your file, you can force the changes by using this command:

```
# telinit q
```

This causes your system to reinitialize. You can then test your setup by calling in from a remote computer.

## Setting Up a Dial-In PPP Server

You can also set up your system to offer a PPP connection when someone dials in. One way to do this is to edit a user's `/etc/passwd` entry, but instead of offering a login shell, launch a shell script that starts the PPP daemon on your system. For example, suppose Fred Smith wants to dial in and get PPP service. You would create his account and then edit his `/etc/passwd` entry to look like this:

```
fsmith:x:501:101::/home/fsmith:/usr/local/bin/startppp
```

The `startppp` script would contain this line:

```
exec /usr/sbin/pppd -detach
```

However, you also need to set various PPP options in the options file under the `/etc/ppp` directory:

```
asyncmap 0
netmask 255.255.255.0
proxyarp
lock
crctests
modem
```

A static IP address may be assigned by specifying the server address and the assigned address in a file named /etc/ppp/options.ttyX (where X is the number of your modem’s serial port):

```
192.168.2.31:192.168.2.2
```

In this example, the first IP is the server address, and the second is the assigned address. Other methods to use would be to assign an IP based on the serial port used, such as if you have a multiple-line system (although most notebooks would probably be able to handle only three lines).

## Direct Connections

This section introduces several ways to directly connect two computers in order to share, transfer, or back up information.

### Setting Up a Null-Modem PPP Connection

One of the quickest, easiest, and cheapest ways to set up and transfer small amounts of information between a notebook computer and desktop computer is to use an inexpensive null-modem serial cable. This cable, which will have its TX (transmit) and RX (receive) pin lines crossed, can be found in nearly any computer store (usually in 6-foot lengths) and is a great tool to keep on hand.

First, make sure both computers have an assigned IP address. Next, make sure these addresses are in both computers’ /etc/hosts file. For example:

```
# sample /etc/hosts file listing
# IP Addr		Hostname				Alias
192.168.2.31	stinky.home.org		stinky
192.168.2.34	aptiva.home.org		aptiva
```

Next, create a single-line script (perhaps named hook) for each computer, specifying the hostnames and the serial port used by the null-modem cable. An example for the computer named stinky (where the cable is attached to /dev/ttyS0) would look like this:

```
/usr/sbin/pppd -detach xonxoff stinky:aptiva /dev/ttyS0 38400 &
```

For the computer aptiva, on the other hand, the script might look like this:

```
/usr/sbin/pppd -detach xonxoff aptiva:stinky /dev/ttyS1 38400 &
```

This script shows that the cable on aptiva is attached to `/dev/ttyS1`. Next, both scripts should be made executable and copied to the `/usr/local/bin` directory:

```
# chmod +x hook
# cp hook /usr/local/bin
```

Ensure that networking services are enabled on both machines, and connect the serial cable to the appropriate ports on each computer. Then, on each computer, execute this command:

```
# hook
```

You can then verify the connection by using the `ping` or `ifconfig` commands. Although this setup doesn't offer blistering networking speeds, it is a very cost-effective solution that works in a pinch.

## Networking with the Parallel Line Interface Protocol

The Parallel Line Interface Protocol (PLIP) is another inexpensive way to network two computers, but with better performance than using serial ports. You'll need a free parallel port on each computer (set to ECP, EPP, or bidirectional mode), along with a parallel null cable. Many shorter cables (6 feet or less) may be found at larger computer discount stores.

Your kernel must support loadable modules, networking, IP forwarding, network devices, the parallel port, and associated devices. This shouldn't be a problem for stock kernels from recent Red Hat or Mandrake Linux distributions.

Your notebook must also have at least a bidirectional parallel port. Although PLIP works well with many desktop computers, not all notebooks can support this protocol, because the parallel port does not work well bidirectionally (despite manufacturer and BIOS claims to the contrary).

Here is the general procedure to set up a PLIP link between two Linux computers, such as laptop to laptop or desktop to laptop:

Connect the cable to each computer. Next, boot each computer and check each one's parallel-port BIOS information. On each computer, make sure `/etc/hosts` contains the IP address of the two computers, and then issue this command:

```
# insmod parport
```

This loads generic support code. Next, load the parport_pc module with this:

```
# insmod parport_pc io=0x378 irq=7
```
