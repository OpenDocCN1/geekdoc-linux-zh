## USB on the Horizon

The advent of the newer Linux 2.4 series of kernels for Intel-based Linux will enable new hardware compatibility for a variety of USB hardware, such as mice, keyboards, speakers, scanners, printers, webcams, cameras, and joysticks. If you currently use a Linux kernel of at least version 2.2.14, you can get some USB functionality by installing kernel patches and recompiling your kernel. Browse to http://www.suse.cz/development/usb-backport/ to download the kernel patch. Browse to http://home.snafu.de/wehe/usb\_linux.html to see a list of laptops on which users have reported success with various USB devices.

### Configuring Pads

If you have a Synaptics TouchPad, browse to http://www.pdos.lcs.mit.edu/~cannan/Synaptics/ to download a driver to configure tapping and other features. Mobile Linux users with notebooks that use a TrackPoint pointer should browse to http://www-hft.ec.TU-Berlin.DE/~strauum/tp4utils and download the `tp4utils` package. Browse to http://parzelle.de/Linux/Lifebook/ to download special drivers for the Fujitsu Lifebook B112/B142 series of notebook (using touch panels).

Other notebooks, such as the Sony Vaio 505 series, which use a VersaPad (and include a small plastic drawing stylus), also work well when configured as a PS/2 pointing device.

### Using a Joystick

Linux includes support for joysticks through loadable kernel modules or as built-in support in the XFree86 X server. However, few, if any, notebooks are equipped with a traditional joystick port. Support for many new types of joysticks will arrive with improved USB support in the Linux kernel.

A number of joystick utilities are available for Linux, but few are included with normal Linux distributions. Support for joysticks is mainly provided by a particular program or client, but you might find the following utilities helpful:

- **kcmljoystick**. A KDE joystick calibration client. Get it at `http://www.geocities.com/SiliconValley/Vista/2964/index.html`.
- **joystick**. The Linux joystick driver. Look under `/usr/src/linux/drivers/char/joystick` for a variety of support modules.
- **joy2key**. A driver that converts joystick movement to keyboard commands. This allows the use of a joystick with many programs that would otherwise not support a joystick. Browse to `http://www-unix.oit.umass.edu/~trrtron/joy2key/`.
- **joyd**. A joystick daemon that can be used to run commands through the movement of your joystick. Browse to `http://www.h.shuttle.de/mitch/joyd.en.html`.
- **gxtest.c**. A program you can use to test your joystick at the console. Browse to `http://www.trylinux.com/projects/joystick/gxtest.c`.

### Keyboard and Internationalization

You'll most likely choose the proper keyboard to use for Linux during installation. However, as you can see from Table 10.1, and as pointed out in Chapter 2, "Taking Inventory," Linux comes with many different commands and utilities you can use to reconfigure or remap your keyboard. Your only potential problem will be understanding when and how to apply changes for the console or the X Window System. Manually creating or redefining an entire keyboard mapping is beyond the scope of this chapter, but you'll see how to use at least one X11 client, named `xkeycaps`, which can quickly generate the required files to remap your keyboard for your X11 sessions.

#### Remapping and the Console Keyboard

Fortunately, Linux comes with many different default keyboard styles, layouts, and languages for the console. These files, known as keymaps, may be used by the `loadkeys` command to remap your keyboard. They are stored under the `/usr/lib/kbd/keymaps` directory. You'll find a list of many different keyboards, including those for the Amiga, Atari, Intel-based, Apple Macintosh, and Sun computers. And for each of these computers, there are keymaps for many different languages.

The default keymap for your (Red Hat-compatible) system is located under the keymap directory for the keyboard you chose when you installed Linux. The type of keyboard is listed in the file `/etc/sysconfig/keyboard`, which looks like this:

```
KEYTABLE=us
BACKSPACE=Delete
```

This file is created by Red Hat’s `kbdconfig` command, as shown in Figure 10.4.

The Yellow Dog Linux `kbdconfig` command looks quite different. You're initially asked if you have a PC or ADB keyboard, and then (on the iBook) you're given a choice of only four different keyboards to use.

#### Booting Different Console Fonts

If you don't use X11 on your Intel-based notebook, but prefer the text-only console or command-line interface, you might be able to use different fonts when booting Linux. This gives you the ability to have a greater number of lines or characters per line, other than the default 80 characters by 25 lines. You'll need to test your notebook's built-in VGA fonts by using the `vga=` kernel message. You can pass at the LILO boot prompt, or which may be placed in LILO's configuration file, `/etc/lilo.conf`.

According to LILO's documentation, `User_Guide.ps`, found under the `/usr/doc/lilo` directory, the `vga=` kernel message has several options:

![](img/70d85e6f4d1ff2750ca2a98ba3d9855c_265_0.png)

- **normal**. Uses normal VGA text mode.
- **extended**. Attempts to use 80×50 text mode.
- **ask**. Just before booting, prompts for a number, corresponding to a displayed text mode.

Results between different notebooks will vary. For example, at the LILO boot: prompt, you can try this:

`boot: vga=ask`

Press Enter. You might see an error message like this:

```
No such image. [Tab] shows a list.
```

Press Backspace, and then press Enter again. You'll see this:

```
Loading Linux……
Press <RETURN> to see video modes available. <SPACE> to continue or wait 30 secs
```

Press Enter to display the video modes. You'll then see this (depending on your notebook):

```
Video adapter: VESA VGA
Mode:    COLUMNS×ROWS:
0  0F00  80×25
1  0F01  80×50
2  0F02  80×43
3  0F03  80×28
4  0F05  80×30
5  0F06  80×34
6  0F07  80×60

Enter mode number or 'scan':
```

You can then enter a number, such as 2, and press Enter. Linux will boot and attempt to use the console font you selected. If you enter the keyword scan and press Enter, the screen will blank for 5 or more seconds, and you'll again see a list of text modes. These modes represent the capabilities of your notebook, and are a better list of modes to try.

### Remapping the X11 Keyboard

Manually remapping your X11 keyboard using various X11 clients and the xmodmap client could be a tedious task. However, thanks to Jamie Zawinski's xkeycaps client, you can scroll through a list of hundreds of keyboards and quickly reconfigure your X11 keyboard to match your hardware. This is especially useful for notebook users, because notebook keyboards rarely match desktop PC keyboards in type or location of keys.

Start the xkeycaps client from the command line of an X11 terminal window like this:

```
# xkeycaps &
```

After you press Enter, you'll see two dialog boxes, as shown in Figure 10.5.

![](img/70d85e6f4d1ff2750ca2a98ba3d9855c_267_0.png)

*Figure 10.5 The X11 xkeycaps client provides a number of keyboard definitions for popular notebooks, such as the IBM ThinkPad 770.*

Scroll through the list of keyboards. If the Select Keyboard dialog box doesn't initially appear, click on the Select Keyboard button. If you click on the Write Output button, xkeycaps will create a file named .xmodmap-hostname, where hostname is the name of your computer. You can then use your new keyboard settings by using the xmodmap client like this:

```
# xmodmap < .xmodmap-`uname -n`
```

This is the fastest way to reconfigure your notebook's keyboard. You'll find keyboards for various notebooks, such as those from Compaq, Hewlett-Packard, IBM, Midwest Micro, Texas Instruments, and Toshiba.
