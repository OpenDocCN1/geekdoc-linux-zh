This chapter introduces general concepts, strategies, software, and hardware you can use to extend your mobile Linux sessions while using your notebook's batteries. You'll learn about accepted practices for battery treatment and Linux software you can use to monitor usage and extend battery life with an aim to conserve energy. This chapter builds on the advanced power management information you learned in Chapter 7, "Advanced Power Management."

## General Strategies

There are many strategies you can use to extend your mobile sessions. Some of these are obvious, and others require you to read your notebook's manual to determine specific features or keyboard controls for your notebook.

### Change the Screen Display

The first strategy is to reduce your screen's brightness, either through manual or keyboard controls, to an acceptable level for your environment. Active-matrix screens consume more power than passive-matrix (DSTN) displays. Some laptops allow you to turn off the LCD's backlight, but this can render most active-matrix screens unreadable except in the dark. Other laptops, such as Sonys, also provide BIOS settings for initial screen brightness. An alternative is to turn off your notebook's display and use an external monitor, although this is not always convenient and might be impossible when you're on the road.

### Don't Play Audio

Don't play audio through your notebook's speakers. Use the headphone jack instead, or don't listen to audio and turn off sound by unloading the sound modules with the `rmmod` command. For example (on a Dell Inspiron 7500), first use the `lsmod` command to list the modules in use:

```
$ lsmod
Module          Size  Used by
maestro         26176   0  (unused)
soundcore        3524   2  [maestro]
```

To turn off sound, exit any running sound clients, such as **kmix** or **xmixer**, and then unload the sound modules with the **rmmod** command:

```
# rmmod maestro
# rmmod soundcore
```

Multimedia applications and tasks that tax your notebook's CPU and devices, such as taking ".mp3s off audio CDs, can suck the juice from your battery faster than any other application.

## Ports and PCMCIA

Keep your online time to a minimum to reduce the use of a built-in modem or serial port.

To save additional power, use your computer's BIOS to disable the IrDA port, or, if possible, turn it off using an **Fn-key** keyboard command. If you have a network or modem PC card, first make sure the network or modem is not in use with the **cardctl** command:

```
# cardctl status
Socket 0:
3.3V 16-bit PC Card
function 0: [ready], [hat dead], [bat low]
Socket 1:
5V 16-bit PC Card
function 0: [busy]
```

After stopping a card's use, you can software-eject the card like this:

```
# cardctl eject 0
```

You can then turn off PCMCIA's Card Services by using its script like this:

```
# /etc/rc.d/init.d/pcmcia stop
```

## The cron Daemon

Check your /etc/crontab scripts to reduce frequently running scripts. Better yet, stop the cron daemon service like this:

```
# /etc/rc.d/init.d/crond stop
```

## Kernel and System Logging

You can also temporarily turn off kernel and system logging during your mobile sessions by using the syslog script under the /etc/rc.d/init.d directory like this:

```
# /etc/rc.d/init.d/syslog stop
```

This is only a good idea for temporary use. You should normally run syslog services for security reasons. You can also stop the httpd daemon using a similar script to disable Web server logging.

## External Devices

Avoid printing or other tasks that send data through your parallel port. Don't use a serial mouse or external keyboard. Also avoid using devices such as Webcams that use your notebook's PS2 port for power. External CD-ROM drives use the PCMCIA slots for power unless the drive features an external power source that takes over.

## Filesystem Update

One software tweak you can perform is to change the default value for filesystem buffer flushing performed by the `updated` daemon. If you examine your Red Hat Linux system initialization table, `/etc/inittab`, you'll see an entry that looks like this:

```
# Things to run in every runlevel.
ud:once:/sbin/update
```

The `updated` (bdflush) daemon is started for each runlevel when Linux is booted. Note that if you try to read the `updated` man page, the `bdflush` man page will be displayed. This is because the `updated` command is used to start `bdflush`. These daemons are used to write changed (aged) data to disk at specific intervals. The default is 30 seconds for data buffers and 5 seconds for non-data, such as directories.

You can view the current defaults by using the `updated` command with its `-d` option:

```
# /sbin/update -d
0:	40 Max fraction of IPU list to examine for dirty blocks
1:	500 Max number of dirty blocks to write each time bdflush activated
2:	64 Num of clean buffers to be loaded onto free list by refill_freelist
3:	256 Dirty block threshold for activating bdflush in refill_freelist
4:	500 Percentage of cache to scan for free clusters
5:	3000 Time for data buffers to age before flushing
6:	500 Time for non-data (dir, bitmap, etc) buffers to age before flushing
7:	1884 Time buffer cache load average constant
8:	1 LAW ratio (used to determine threshold for buffer fratricide).
```

In this example, the important values are for 5 and 6, which show the amount of time, in hundredths of a second, between flushing of data and syncing of the data to disk (with the `sync` command).
