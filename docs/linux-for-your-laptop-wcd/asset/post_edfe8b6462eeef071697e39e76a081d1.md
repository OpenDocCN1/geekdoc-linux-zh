
## Shell Command Line Editing Commands

| Command | Description |
| :--- | :--- |
| Alt+d | Deletes the current word |
| Alt+l | Converts the current word to lowercase |
| Alt+r | Undoes line changes |
| Alt+t | Transposes words |
| Alt+u | Converts the current word to uppercase |
| Ctrl+a | Goes to the beginning of the line |
| Ctrl+b | Cursor goes backward one character on the line |
| Ctrl+c | Aborts the command line |
| Ctrl+d | Deletes the current character |
| Ctrl+e | Goes to the end of the line |
| Ctrl+f | Cursor goes forward one character on the line |
| Ctrl+k | Deletes a line |
| Ctrl+t | Transposes letters |
| Ctrl+u | Deletes a line (but keeps a copy in the buffer) |
| Ctrl+w | Deletes a word backward |
| Ctrl+y | Pastes the buffer to the line |
| Down arrow | Goes to the next (history) command line |
| Left arrow | Cursor goes backward on the command line |
| Right arrow | Cursor goes forward on the command line |
| Tab | Expands the command line (help) |
| Up arrow | Displays the previous (history) command line |

Shell aliases are also useful if you want to create abbreviated commands, shortcuts, or custom versions of commands for use from the command line after you log in to Linux. Red Hat (and other Red Hat-based distributions such as Mandrake and Yellow Dog) Linux users can define these aliases in the file `.bashrc` in the home directory. Here are some of the most useful (and safer) aliases to define:

```shell
alias rm='rm -i'
alias mv='mv -i'
alias cp='cp -i'
```

These examples create much safer versions of the `rm`, `mv`, and `cp` commands. The `-i` (interactive) option forces you to type a `y` or `n` when deleting, renaming, or potentially copying over existing files. Open your `.bashrc` file with a favorite text editor, and then type in these aliases. Another one you might want to create is for custom directory listings with the `ls` command:

```shell
alias ll='ls -l'
```

Save the `.bashrc` file, and then use the bash shell’s `source` command to read in the new aliases, like this:

```shell
# source .bashrc
```

After you become familiar with other Linux commands, you’ll be able to craft your own favorite aliases!

## Setting the Shell Prompt

You can view your current shell's prompt by examining your shell's environment variables. For example, search for and display the value of the `PS1` variable like this:

```shell
$ env | fgrep PS1
```

You might see the following value returned:

```shell
PS1=\u@\h \W\$
```

This indicates that the shell prompt should display a bracket ([), the current user's name, and the at symbol (@), followed by the computer's hostname, a space, the current working directory, and a closing bracket. It might look like this:

```shell
[bash@green bash]$
```

You can redefine your shell prompt, which is usually defined in the file `/etc/profile`, on-the-fly by using the bash shell's `export` command. For example, if you prefer to have the date and time instead, you can use this:

```shell
$ export PS1='\d \t -> '
```

After you press Enter, you'll see the following:

```text
Thu Mar  9 16:01:19 ->
```

The bash shell recognizes 23 different backslash (\) special characters, such as `\d` and `\t` (just shown), along with underlining, boldface, blinking, and other attributes. Read the bash man page's PROMPTING section for details.

## Setting Console Colors

The Linux console recognizes myriad control codes and escape sequences you can use to customize your text-only sessions. By default, the console appears with white characters on a black background. However, if you prefer to use green characters; for example, use the `echo` command to send the proper escape sequence and codes:

```shell
$ echo -e '\033[32m'
```

After you press Enter, the characters will be green. To reset your console to the default, use this:

```shell
$ echo -e '\033[0m'
```

For other control codes, see the `console_codes` man page.

## Using Virtual Consoles

When you boot Linux to the command line, you see a login prompt. After you type your username and password, you're at the shell prompt. Yet another amazing feature of Linux is that you can then jump to another login prompt and log in again or log in as another user! In fact, most Linux distributions support at least six logins, or *virtual consoles*. (They support even more if you consider that you can run at least two additional X sessions at once. See the later section “Using Multiple X Sessions.”)

If you start at the Linux console, jumping to another console is quite easy. If you're using Intel-based Red Hat Linux, press Alt+F2. You'll then see another login prompt. If you're using Yellow Dog Linux on the iBook, press Ctrl+Cmnd+2, and you'll jump to another login prompt. On the iBook, press Ctrl+Cmnd+1 to jump back to the original login.

If you boot Linux directly to X11, you can jump to a console login screen by pressing Ctrl+Alt+F2. To jump back to your X11 session, press Alt+F7.

## Must Kill X11 on the iBook?

At the time this chapter was written, it appeared that if you use Yellow Dog Linux on the Apple iBook, there is no way to jump to a text-based console without pressing Ctrl+Opt+Cmnd+Del to kill the current X server. However, you can then jump between text logins at consoles 2-6 with ease by using Ctrl+Cmnd+1 (or 2-6 as appropriate).

Using multiple logins is a handy way to run different text-based applications at once in full-screen mode on your notebook. However, if you have only one screen available, such as if you have logged in remotely via a modem, you can use features available in some shells to temporarily suspend, and then retrieve, a running application.

This is accomplished by using the bash shell's job control feature, which allows you to suspend a running program to the background (in memory) while you start and run another program. For example, you can start the pine e-mail program and use its `-z` (enable-suspend) option like this:

```shell
# pine -z
```

The pine program will start normally. If you need the console for another program right away, but you don't want to quit pine, press Ctrl+z to suspend the pine e-mailer to the background. You'll then see this:

```text
pine suspended. Give the 'fg' command to come back.
[3]+ Stopped        pine -z
#
```

pine's menus will disappear, and your shell's prompt will reappear. You can then run other programs. When you want pine to reappear, use the foreground command:

```shell
# fg
```

The pine e-mailer will reappear, and you can continue working.

## Using X11

The X Window System, also known as X11 or, more simply, X, was developed by a consortium of companies and educational institutions and was first released in 1986. X is a networking graphics system based on a server and client model. This means that X, as distributed, provides a graphics server that runs on local and remote computers (such as your notebook or other computers connected to a LAN or the Internet). The server handles communication between computers and between X11 applications known as clients. This model has (pun intended) served quite well over the last 14 years and has proved to be remarkably adept at incorporating advances in communication, networking, and graphics.

The free distribution of X11 for Linux was derived from early efforts by four programmers in 1992. It has grown into a loose association of 200 developers and testers worldwide called The XFree86 Project, Inc. This free distribution, which includes source code, forms the base of the graphical interface for Linux (and a number of other operating systems, such as BSD).

Linux is quite usable without a graphical interface. You can save hundreds of megabytes of hard drive space if you don't install X and its associated clients. Indeed, many people using Linux as a server don't install X and prefer to have as little system software and service programs installed as possible.
