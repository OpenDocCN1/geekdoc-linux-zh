This is only a good idea for temporary use. You should normally run syslog services for security reasons. You can also stop the httpd daemon using a similar script to disable Web server logging.

# External Devices

Avoid printing or other tasks that send data through your parallel port. Don't use a serial mouse or external keyboard. Also avoid using devices such as Webcams that use your notebook's PS2 port for power. External CD-ROM drives use the PCMCIA slots for power unless the drive features an external power source that takes over.

# Filesystem Update

One software tweak you can perform is to change the default value for filesystem buffer flushing performed by the `update` (updated) daemon. If you examine your Red Hat Linux system initialization table, `/etc/inittab`, you'll see an entry that looks like this:

```
# Things to run in every runlevel.
	ud:once:/sbin/update
```

The `updated` (bdfush) daemon is started for each runlevel when Linux is booted. Note that if you try to read the `updated` man page, the `bdfush` man page will be displayed. This is because the `updated` command is used to start `bdfush`. These daemons are used to write changed (aged) data to disk at specific intervals. The default is 30 seconds for data buffers and 5 seconds for nondata, such as directories.

You can view the current defaults by using the `updated` command with its `-d` option:

```
# /sbin/update -d

	0:	40 Max fraction of IPU list to examine for dirty blocks
	1:	500 Max number of dirty blocks to write each time bidlush activated
	2:	64 Num of clean buffers to be loaded onto free list by refill_freenist
	3:	256 Dirty block threshold for activating bldlush in refill_freenist
	4:	500 Percentage of cache to scan for free clusters
	5:	3000 Time for data buffers to age before flushing
	6:	500 Time for non-data (dir, bitmap, etc) buffers to age before flushing
	7:	1884 Time buffer cache load average constant
	8:	2 LAW ratio (used to determine threshold for buffer fratricide).
```

In this example, the important values are for 5 and 6, which show the amount of time, in hundredths of a second, between flushing of data and syncing of the data to disk (with the `sync` command). Knowing this, intrepid mobile Linux users will change the default intervals to allow for a longer hard drive standby or *spindown*
