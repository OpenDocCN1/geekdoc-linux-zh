
- Pick applications that are conservative with memory and disk space. If you need to perform spreadsheet operations, try using the sc or teapop editor instead of Applix, StarOffice, or other GUI-based X11 clients.
- Delete unwanted documentation. If you install all the documentation from most distributions, you'll end up with documents in French, German, Italian, Polish, Greek, Chinese, and many other languages. Most full installations of the /usr/doc directory require at least 200MB of storage!
- Compress desired documentation. If you decide that you really do need to have all the HOWTOs available, use the gzip or bzip2 commands to compress all the files. You can then use decompression or pagers such as zless to read the files.
- Delete unwanted documentation formats. Most Linux distributions include HOWTO and other files in HTML and SGML. You can delete these directories, usually found under the /usr/doc/HOWTO/otherformats directory, to save at least 25MB of drive space.
- Delete example files. If you're familiar with the software installed, you can delete nearly every program's auxiliary documentation and example files under the /usr/doc directory.
- Clean up temporary or backup files. Regularly use scripts to clean up your filesystem.
- Maintain good backups. Always back up important directories such as /home and /etc.
- If you need more storage, consider using an auxiliary peripheral, such as a Zip drive. If that's too bulky, use a Type II flash memory card. IBM now markets the MicroDrive, a 170 to 340MB drive that is the size of a compact flash card, which can be used with Linux.
- Don't start services you don't need. For security, edit the /etc/inetd.conf file to turn off unwanted services. Red Hat and Mandrake users should use the ntsysv command to select services to be started during the boot process. SuSE Linux users should use the yast command, and Caldera OpenLinux users can use the liisa command or the graphical COAS utility to control system services. This will save system memory and keep the number of running processes to a minimum.

For users migrating from other operating systems and who aren't familiar with DOS, the command line might at first seem intimidating—but don't worry! You can quickly master the command line by understanding a few simple concepts and learning a small number of commands.

### Using the Console

The main interface to the Linux kernel, which is the core operating system, is the shell. Linux comes with nearly a dozen different shells, but most users will opt for the default shell, named bash (the Bourne-Again Shell) just one of thousands of programs provided by the Free Software Foundation, and it's critical to working with Linux. The shell interprets your commands and sends information to the Linux kernel, which in turn launches your commands or provides other services, such as opening, reading, writing, and closing files.

The bash shell has a number of different features, such as providing in-memory variables, known as environment variables; a customizable prompt, or shell prompt; built-in help; and the ability to send input or output to the display, other programs, or other files, which is known as input/output redirection. Table 9.1 lists some common environment variables you'll use in your bash shell.

Input and output redirection is used to specify where keystrokes, text, or programs get input and where the results should be sent, such as to a file or device. For example, you can build an instant catalog of all files under the /usr/doc directory like this:

```
$ ls -lR /usr/doc >helpfiles.txt
```

In this example, the output of the `ls` command is redirected to a file. You can also use input and output redirection at the same time to create a simple text editor with the `cat` command:

```
$ cat >myfile.txt <<.
> This is the most easy to use editor
> available for Linux, and will quickly
> create a short text file.
> .
```

In this example, the `cat` command is instructed to send its output to the file myfile.txt, and the redirection here (`<<.`) operator is used to specify an end-of-file marker. After pressing Enter, you can type and press Enter to create a text file.

The file will be closed only until the here operator detects a single period (.) on a line by itself. This also shows that the shell works on a line-by-line basis.

You can also append information to an existing file. For example, if you have a log that shows how long Linux has been running, you can send the output of the uptime command to the log like this:

```
$ uptime >>myuptime.log.txt
```

In this example, the append `>>` operator is used to attach the output of the uptime command to the end of the file named myuptime.log.txt. If you had simply used the output `>` redirection operator, the output of the uptime command would have wiped out any existing text in the log file. This shows that you should use output redirection carefully. You can quickly and unforgivingly overwrite files.

### Using the Shell

The bash shell also features rudimentary command-line editing, the ability to recognize and use command synonyms, known as aliases, and the ability to recall previous command lines, known as history editing. Table 9.2 lists several common editing commands you can use with the bash shell's command line.

You also can craft simple or amazingly complex patterns or expressions using a feature known as extended expressions, or globbing. These expressions can range from simple, such as `*` to match all characters, to more complicated, such as `{a-z}{0-9}*` to match embedded letters and numbers.

Experienced mobile Linux users are familiar with a variety of shells for Linux, and they use the shell to get work done quickly and efficiently. The bash shell, which can mimic other shells, may also be used to create simple to complex programs, known as shell scripts. Shell programming is a fine art and a craft worth learning, but you can build your own simple shell scripts using just a few commands.

### Bash Is Big

If you're strapped for space on your notebook's hard drive, and you really want to use a stripped-down system, consider using an alternative shell for your Linux console sessions. You'll find at least two other shells, ash and csh, that can work quite well for most online needs. Other shells, such as ksh, are also much smaller than the bash shell (which weighs in at nearly 0.5MB, compared to the ash shell's paltry 61,000 characters). The csh shell is used when rebooting Linux for emergency repair, because it is stand-alone, and it does not require shared software libraries like other shells.
