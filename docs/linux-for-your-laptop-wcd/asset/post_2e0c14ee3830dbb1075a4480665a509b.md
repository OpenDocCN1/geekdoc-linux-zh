### Formatting Floppy Disks

You can quickly format a DOS diskette from the Linux command line with the
mformat command:

```bash
# mformat a:
```

If you use X11 and the K Desktop Environment, you can also use KDE's kfloppy
client. Start this client from the command line of an X11 terminal window, or
choose the kfloppy menu item from KDE's Application Starter Utilities menu.
You'll see the dialog box shown in Figure 8.1.

![](img/70d85e6f4d1ff2750ca2a98ba3d9855c_219_0.png)

*Figure 8.1 KDE's kfloppy client is used to
quickly format a floppy for DOS or Linux.*

Most Intel-based notebooks today use a 1.44MB floppy. If you have an older notebook with a 720KB floppy, however, you can use the setfdprm command, along with the /dev/fd0 device and a setting to properly format a floppy:

```bash
# setfdprm -p /dev/fd0 720/720
```

You would then use fdformat to perform a low-level format. If you want to skip using setfdprm, you can also specify the proper device directly:

```bash
# fdformat /dev/fd0720
```

To create a Linux filesystem on the floppy, use the mk2fs command and the device name like this:

```bash
# mk2fs -C -v -L "Linux" /dev/fd0
```

### Making Extra Room

After mounting the floppy, you can use the df (disk free) command to show how much room is available for files:

```bash
# df /mnt/floppy
Filesystem               Size  Used Avail Use% Mounted on
/dev/fd0                 1.4M   13K  1.3M   1% /mnt/floppy
```

Note that this example shows that the floppy has only 1.3MB available! What happened to the extra 5 percent? Linux automatically reserves extra room on every volume for the root operator. This means that there is potentially 300MB of extra storage available on a 6GB hard drive! To make as much room as possible available on a volume, such as a floppy or hard drive, use the `mkexts` command's `-m` option with a value of 0 to specify no reserve room:

```bash
$ mkexts -m 0 /dev/fd0
```

After formatting and mounting, the `df` command reports:

```bash
$ df /mnt/floppy
Filesystem     Size  Used Avail Use% Mounted on
/dev/fd0       1.4M   13k  1.4M   1% /mnt/floppy
```

As you can see, the entire floppy is now available. This can make a big difference, especially if you're trying to squeeze out as much room as possible on the floppy, and it makes a very big difference if you're installing a new hard drive for Linux! (Note that you can also *increase* the amount of room to reserve for the root operator, but this wouldn't make much sense.)

### Macintosh HFS Support

File utilities for other operating systems, such as the Macintosh, are also found with most Linux distributions. One package, `hfsutls`, includes a number of programs that you can use much like those included in the `mtools` package. For example, to create a 1.44MB Macintosh HFS diskette, use the `hformat` command like this:

```bash
$ hformat /dev/fd0
Volume name is "Untitled"
Volume was created on Mon Feb 28 16:05:57 2000
Volume was last modified on Mon Feb 28 16:05:57 2000
Volume has 1448960 bytes free
```

You can then mount the new Macintosh floppy like this:

```bash
$ mount -t hfs /dev/fd0 /mnt/floppy
```

Alternatively, you can use the `hmount` command like this:

```bash
$ hmount /dev/fd0
```

You would then use the various `hfsutls`—such as `hcopy`, `hdel`, or `hls`—to copy, delete, or list files on the floppy. Although the Apple iBook does not come with an internal (or external) floppy, after you boot Linux, the Macintosh HFS partition may be mounted like this:

```bash
# mount -t hfs /dev/hda8 /mnt/macdesktop
```

Obviously, you have to create the /mnt/macdesktop folder first, and then ensure that /dev/hda8 contains your MacOS partition (which it should if you install Linux on top of the Mac OS on the iBook). But you can then copy files to and from the Macintosh desktop folder.

### Automated Disk Cleanup

Linux is similar to UNIX. As such, it has inherited many features and traits of SysV and BSD UNIX. This means that many configuration files, system logs, and temporary files can be created, can multiply, and can grow over the course of each successive Linux session. Some of the first steps are understanding your system's requirements, determining where the most software is installed, and deciding where on your file system cleanup might be a good strategy to use. For example, the du command may be used to print the relative size of each directory, starting at the root, or /, directory:

```bash
# du -h --max-depth=2 /
4.9M    /bin
1.7M    /home/ftp
6.7M    /home/htpd
1.0k    /home/samba
21M     /home/bball
29M     /home
43M     /lib/modules
269k    /lib/security
47M     /lib
1.8M    /root
5.6M    /sbin
96M     /usr/X11R6
150M    /usr/bin
404k    /usr/dict
192M    /usr/doc
1.1M    /usr/games
12M     /usr/include
5.1M        /usr/info
292K        /usr/lib
578M        /usr/local
26M         /usr/man
13M         /usr/sbin
367M        /usr/share
470K        /opt
```

This output shows that the du command reported to a depth of two directory levels, displaying the use, mostly in megabytes, of various directories on the sample system. According to the output, at least one good candidate for cleanup might be the /usr/doc directory. You might also want to take a look at the /var directory (which can grow quite large due to log files), like this:

```bash
# du -h --max-depth=2 /var
```

If you use X11 and KDE, you can get a quick picture of your hard drive’s usage with the kfsstatx client, as shown in Figure 8.2.

Fortunately, Linux and the Linux console, or shell, comes with a number of utilities and built-in commands you can use to limit the size of files or ferret out and delete unwanted files.
