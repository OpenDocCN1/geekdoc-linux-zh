However, the computing experience without X11 for Linux would not be as rich and rewarding on a notebook, especially since today's laptops are as powerful as desktops and feature displays rivaling desktop monitors.

By default, most Linux distributions attempt to properly configure X11 for your notebook and set up Linux to boot directly to an X11 login during installation, as shown in Figure 9.2.

Configuring Linux to boot directly to X involves proper settings in your system's initialization table, /etc/inittab. For example, if you examine a Red Hat (or Mandrake or Yellow Dog) Linux /etc/inittab, you'll see the following:

```
###
# Default runlevel. The runlevels used by RH are:
# 0 - halt (Do NOT set initdefault to this)
# 1 - Single user mode
# 2 - Multiuser, without NFS (The same as 3, if you do not have networking)
# 3 - Full multiuser mode
# 4 - unused
# 5 - X11
# 6 - reboot (Do NOT set initdefault to this)

#
#id:5:initdefault:
...
```

This example shows that the default runlevel has been set to 5, or multiuser X11 mode.

## Not All Distributions Are Alike!

Note that other Linux distributions, especially SUSE Linux, do not use the same runlevel configuration as Red Hat-based distributions. This means that the values in the `/etc/inittab` file might be different, depending on the type of Linux distribution installed on your notebook. SUSE Linux, for example, uses runlevel 3 as multiuser mode with X11.

Here is the pertinent line in `/etc/inittab` that launches your X11 login screen:

```
# Run xdm in runlevel 5
# xdm is now a separate service
x:5:respawn:/etc/X11/prefdm -nodademon
```

This example shows Red Hat’s default entry. If you prefer to use the K Desktop Environment’s K display manager (kdm), you can use an entry that looks like this:

```
# Run xdm in runlevel 5
# xdm is now a separate service
# x:5:respawn:/etc/X11/prefdm -nodademon
x:5:respawn:/usr/bin/kdm -nodademon
```

This example forces Linux to launch the kdm client for your X11 session login.

## Using Different Resolutions

Ideally, you should have a screen resolution of 1024×768 pixels when using X11. This is because some X11 clients, such as `xfix`, `xboing`, `xmahjongg`, and others, require that screen size. However, until recently, the majority of notebooks sold featured maximum resolutions of 800×600. Some mini-notebooks, such as the Sony C-1X series, provide 1024×480, or a half-size XGA screen, but most mid- and even lower-priced notebooks today support larger displays. Higher-end notebooks provide surprisingly good LCD displays up to 1280×1024. The largest display (SXGA+) currently available from Dell and IBM top out at a whopping 1400×1050!

You can get by with using 800×600 and even smaller resolutions, but you'll need to use every trick in the book to get the most out of this size of screen real estate. One technique familiar to experienced mobile Linux X11 users is to use a virtual screen setting in the system's XF86Config file. If your notebook has enough extra video RAM and if you use a low-enough color depth setting, you might be able to craft a virtual screen that extends beyond your notebook LCD's physical limitations.

Virtual screen modes are defined in your XF86Config Screen Section's Display subsection. For example:

```
# Screen sections
# ***************

# The Colour SVGA server
Section "Screen"
Driver "svga"
Device "My Video Card"
Monitor "LCD Panel 1024x768"
Subsection "Display"
Depth 16
Modes "1024x768" "800x600" "640x480"
Virtual 1152 900
ViewPort 0 0
EndSubsection
EndSection
```

In this example, a virtual screen size of 1152×900 has been created. However, you need to read the man page for your notebook's X11 server (XF86_SVGA in this example) to determine the virtual screen sizes supported by the server. When you restart X11, your notebook's server will choose a setting that matches this virtual size as closely as possible.

When you use a virtual screen entry, the ViewPort setting is used to set the initial view (upper-left corner) when the X session is started. You can change this setting to have the initial view of the lower-left corner. Using the preceding example, the ViewPort entry would look like this:

```
ViewPort 0 132
```

After you restart X11, the lower-left corner of the virtual display will reside in the lower-left corner of your notebook's screen. (This is handy when you're using KDE or GNOME, because the default menu button resides in the lower-left corner of the display. The value 132 is the difference between the virtual and physical screen size (900 minus 768).

As root, open your system's XF86Config file (found under the Red Hat or Mandrake Linux /etc/X11 directory), create your settings, and save the file. If you're running xdm, kdm, or gdm, you can kill the current X session, and X will restart with the new settings. If all goes well, you'll end up with a larger resolution, and your display will “pan,” or move, when the cursor hits a boundary that has more real estate. This is a great way to get a larger display if you need it!

The other display resolutions in the sample listing allow you to toggle between screen sizes on-the-fly. If you want to use this feature, your notebook's display must support each resolution, a companion modeline entry must exist in your XF86Config file, and you must have enabled toggling by commenting out the DontZoom entry in XF86Config's ServerFlags section:

```
# DontZoom
```

## The Fine Art of Tweaking Modelines

Modelines in your XF86Config are lines of text that define possible resolutions, along with associated graphics chip clock settings and resolutions for your LCD. XF86Re6 comes with a default XF86Config file named XF86Config.efg (found under the /usr/X11R6/lib/X11 directory) that provides many different default settings. Although most notebook users will find acceptable defaults that work well, you might need to create your own settings. Be careful! Using memory, monitor, resolution, clock, or frequency settings out of range could damage your display! Always be prepared to kill a test X session with Ctrl+Alt+Backspace when testing. The best approach is to browse the Linux laptop pages for the exact model of your laptop and to use any recommended settings. If you're still determined, first read Eric S. Raymond's Video Timings HOWTO (see the “Resource Information” section at the end of this chapter).

Toggling resolutions on a desktop PC with a normal keyboard is quite easy; press Ctrl+Alt+KeyPad++ (plus) or Ctrl+Alt+KeyPad− (minus). Performing this stunt on a notebook can be a little trickier, because few, if any, notebooks come with a separate keypad (although you can buy one that plugs into your PS2 port). Toggling resolutions on a notebook usually involves pressing Ctrl+Alt along with a special Fn key and then the + or − keypad keys (which are enabled when you use the NumLock key on your notebook's keyboard).

Although most mobile Linux users will always want to use the highest resolution available, there might be instances when you want to use a lower resolution. You’ll have to experiment with different settings in your XF86Config file. You should also read about your notebook’s graphics chipset in a readme file under the /usr/X11R6/lib/X11/doc directory.

## Using Multiple X Sessions

If you don’t configure Linux to boot directly to X11, you most likely use the *startx* command to jump to your X session. This command has a number of interesting features and command-line options you can use to start multiple X11 sessions on your notebook (if you have enough RAM). Why would you want to do this? Because you can then run different X11 window managers, use X11 at different screen resolutions, or run a session using a different *color depth*, or number of colors.

To start multiple X sessions, configure your Red Hat (or Mandrake) /etc/inittab to boot Linux to multiuser mode, or runlevel 3. Next, log in and use the *startx* command to start your X session:

```
# startx -- :0 vt7
```

After you press Enter, X will start and use the default display (:0) and default virtual console (7). To start another X11 session, press Ctrl+Alt+F2. You’ll see another text-only login prompt. Log in, and again use *startx* to start another X11 session:

```
# startx -- :1 vt8
```

You’ll end up in another X11 session running on a different display (:1) and using a different virtual console (vt8). To jump to the other X11 session, press Ctrl+Alt+F7. After working in that X desktop, you can jump back by pressing Ctrl+Alt+F8. To jump to a new text-only session, press Ctrl+Alt+F3. After working at the command line, you can jump back to either X session by pressing Alt+F7 or Alt+F8.

This is a great way to show off the features of your Linux notebook and a quick way to jump between different window managers. You should know, however, that running multiple X11 sessions can quickly exhaust your system’s memory and tax system resources! Properly log out of each running X session to return memory to the Linux kernel.
