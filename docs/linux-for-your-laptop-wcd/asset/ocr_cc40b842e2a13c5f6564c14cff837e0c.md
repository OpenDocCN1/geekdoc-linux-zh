This is accomplished by using the bash shell's job control feature, which allows you to suspend a running program to the background (in memory) while you start and run another program. For example, you can start the pine e-mail program and use its -z (enable-suspend) option like this:

```
# pine -z
```

The pine program will start normally. If you need the console for another program right away, but you don't want to quit pine, press Ctrl+z to suspend the pine e-mailer to the background. You'll then see this:

```
pine suspended. Give the 'fg' command to come back.
[3]+ Stopped        pine -z
#
```

pine's menus will disappear, and your shell's prompt will reappear. You can then run other programs. When you want pine to reappear, use the foreground command:

```
# fg
```

The pine e-mailer will reappear, and you can continue working.

# Using X11

The X Window System, also known as X11 or, more simply, X, was developed by a consortium of companies and educational institutions and was first released in 1986. X is a networking graphics system based on a server and client model. This means that X, as distributed, provides a graphics server that runs on local and remote computers (such as your notebook or other computers connected to a LAN or the Internet). The server handles communication between computers and between X11 applications known as clients. This model has (pun intended) served quite well over the last 14 years and has proved to be remarkably adept at incorporating advances in communication, networking, and graphics.

The free distribution of X11 for Linux was derived from early efforts by four programmers in 1992. It has grown into a loose association of 200 developers and testers worldwide called The XFree86 Project, Inc. This free distribution, which includes source code, forms the base of the graphical interface for Linux (and a number of other operating systems, such as BSD).

Linux is quite usable without a graphical interface. You can save hundreds of megabytes of hard drive space if you don't install X and its associated clients. Indeed, many people using Linux as a server don't install X and prefer to have as little system software and service programs installed as possible.
