
## Showing and Setting Time

Getting and showing the date and time from Linux is relatively easy. A short C program can quickly retrieve and print the date and time. For example:

```c
#include <stdio.h>
#include <time.h>

int main()
{
	time_t now;

	time(&now);
	fputs(ctime(&now), stdout);
	return 0;
}
```

If you type this into a file named qd.c, you can then build the program, and perhaps give it the name qd:

```bash
# gcc -o qd qd.c
```

You can then run qd like this:

```bash
# ./qd
Wed Mar 22 10:18:16 2000
```

Note that after you press Enter, you see the current date and time. However, to check that your system time matches the time or is properly offset from the time in your notebook’s hardware clock, use the hwclock command with its --show option:

```bash
# /sbin/hwclock --show
Wed Mar 22 10:19:17 2000  -0.497501 seconds
```

In this example, the Linux system time is set to match the notebook’s hardware clock. You can use the hwclock command to manually set the hardware clock by using its --set and --date options like this:

```bash
# /sbin/hwclock --set --date "12/25/00 21:03:00"
```

After you press Enter, the hardware clock will be set to 9:03 p.m., December 25, 2000. The hwclock command can transfer date and time values from the Linux system time to your notebook’s hardware clock or back again using the --systohc or --hctosys options.

Red Hat, Mandrake, and Yellow Dog Linux include Red Hat's `timetool` client. This command requires that you run X11. It may be started from the command line of an X11 terminal window like this:

```bash
# timetool &
```

After you press Enter, you see the dialog box shown in Figure 16.1. You can use it to set the date and time.

Another command you can use from the console to set the system date and time is the `date` command. In its simplest form, use the `date` command followed by the month, day, hour, and minute, like this:

```bash
# date 03221200
```

Wed Mar 22 12:00:00 EST 2000

After you press Enter, the `date` command displays your new system time.

## Keeping Track of Where You Are

Red Hat and Yellow Dog Linux use a symbolic link, `/etc/localtime`, to designate your current time zone. This link points to the desired time zone database file under the `/usr/share/zoneinfo` directory. Under Mandrake Linux, `/etc/localtime` may be a copy of an actual time zone database file. You can use the `ls` command to see if the file is a link like this:

```bash
# ls -l /etc/localtime

lrwxrwxrwx 1 root root 32 Feb 17 1999 /etc/localtime -> ../usr/share/zoneinfo/US/Eastern
```

In this example (from a Red Hat system), the time zone is set to EST, known as Eastern Standard Time.

When you boot Linux, the `/etc/rc.d/rc.sysinit` system initialization script uses the `hwclock` command to set the system time. Options for the `hwclock` command are kept in the `/etc/sysconfig/clock` file, and they use settings such as this:

```ini
ZONE="US/Eastern"
UTC=false
```

You can change this file manually, create your own symbolic link, or use the Red Hat `timeconfig` command to set the time zone. This command may be run (as root) from the console or a command line of an X11 terminal window:

```bash
# timeconfig
```

After you press Enter, you see the dialog box shown in Figure 16.2.

Use the Tab key to move to different buttons and the up and down cursor keys to select a time zone. Use the spacebar to toggle the selection of the Hardware clock setting to UTC. Navigate to the OK button and press Enter after making your choices.

If you use KDE, use the `kmclock` client to set a different time and zone. This client requires that you run X11. Click the desktop's Application Starter button on the panel, and then select Settings, Date and Time. You can also (as root) start the client from the command line of an X11 terminal window by typing `kmclock` and pressing Enter. You see the dialog box shown in Figure 16.3.

This client has the advantage of being able to set the date, time, and time zone from one dialog box (although you have to click the Time Zone tab to set the time zone). Unlike Red Hat's `timeconfig` command, `kmclock`'s time zones are not listed as location names, but only as offsets from GMT, or 0.

## The TZ Environment Variable

Linux also recognizes the `TZ` environment variable, a setting retained in memory by your shell. You can use this variable to tell other applications launched from the shell what time zone is currently in use. For example, you can use the `bash` shell's `export` command to set this variable on-the-fly:

```bash
# export TZ=EST+5
```

This sets the time zone to EST without daylight saving time. To specify DST, use additional fields for the `TZ` variable, like this:

```bash
# export TZ=EST+5EDT,M4.1./M1.0.,5.0
```

## Getting Accurate Time

You probably set your watch and clocks according to other clocks. If you're at home, take a quick look at your different clocks, watches, radios, stereos, or VCRs to see if they all have the same time. Chances are they don't! If this is the case, how can you get accurate time settings into your notebook's hardware and the Linux system?

If you're connected to the Internet, one way to get the correct time is to browse to one of the many different Web sites that post the current time (local and for other time zones), such as http://www.time.gov/, sponsored by the U.S. Department of Commerce and the National Institute of Standards and Technology.

However, the best way to get and set the time for Linux is to use the `rdate` command (as root). You'll need to have an active Internet connection, use the `rdate` command's `-s` (set) option, and specify the hostname of a remote time server. For example:

```bash
# rdate -s time.nist.gov
```

This command sets your Linux system time by retrieving time information from the remote server. If you want just the time displayed, use the `rdate` command like this:

```bash
# rdate time.nist.gov
[time.nist.gov] Wed Mar 22 13:56:23 2000
```

The `rdate -s` command may be placed in your system's `/etc/crontab` file to have the time regularly updated if your notebook is connected to the Internet. Once accurate time is maintained on a local server, the `timed` daemon may be used to provide time service to the rest of the network. The `timed` daemon works as a server and as a client. If you start the daemon using the `-x` flag, it becomes a master and provides services to any other hosts designated by the `-r` option. For example, on a server, you might use this:

```bash
# timed -M -F stinky vaio green
```

The remote computers (perhaps a notebook or two), stinky, vaio, and green, should then run the `timed` daemon without any options, like this:

```bash
# timed
```

An interesting feature of this software is that if the master time server quits or is unresponsive, the other hosts elect a new master!

Another daemon used to synchronize time across a network is the `xntpd` daemon, which provides time via the Network Time Protocol (NTP). However, you'll need to have a radio, satellite receiver, or modem in order to set up and provide service.

To get started with learning about NTP and xntpd, look under the /usr/doc/xntpd directory and use the text-only lynx Web browser like this:

```bash
$ lynx /usr/doc/xntpd*/index.html
```

Don't have access to a network? You can use a telephone to hear the latest time by calling the U.S. Naval Observatory's Master Clock Voice Announcer at (202) 762-1401 or (202) 762-1069. You can also call long-distance (and not have to worry about satellite delays) by dialing 900-410-TIME; however, there is a charge of $.50 (U.S.) for the first minute and $.45 (U.S.) for each additional minute.

## Useful Clients

Mobile Linux users are enamored with clients that provide lots of information in small packages; they save screen real estate and reduce desktop clutter. KDE users know that the date and time are displayed by default in the lower-right corner of the desktop's panel. If you cannot see the date and time, your screen resolution is too small, and you should reconfigure the panel to its “tiny” setting (use the Configure menu item on the panel).

Linux also comes with many different clock and calendar clients. You can quickly craft your own pop-up current monthly calendar by combining the output of the text-based `cal` command with the `xmessage` X11 client like this:

```bash
$ cal | xmessage -geometry +1-0 -file - -title "Calendar"&
$ cal | xmessage -geometry +1+0 -file - -title "Calendar"&
$ cal | xmessage -geometry -1+0 -file - -title "Calendar"&
$ cal | xmessage -geometry -1-0 -file - -title "Calendar"&
```

These command lines produce a small monthly calendar in the lower-left, upper-left, upper-right, or lower-right corner of your desktop no matter what the screen resolution, as shown in Figure 16.4.

If you're traveling and you need to make sure you don't wake up someone halfway across the world, try KDE's `kworldwatch` client. This client may be launched from KDE's Utilities menu or from the command line of an X11 terminal like this:

```bash
$ kworldwatch &
```

After you press Enter, you'll see the window shown in Figure 16.5. It displays the local time, UTC time, time zone times, and a Mercator projection of the earth, showing the demarcation of sunrise and sunset.
