
# GNU/Linux脚本编程初学者指南：轻松学习Bash与Unix核心工具

## 前言

> —— 起笔。《公主新娘》（1987）

### 本书面向人群

本书面向所有希望在Linux、Mac OS等Unix环境中提升工作效率的读者。作为一本入门教材，本书假定读者此前没有相关领域的基础知识，读者可以预期学到日常使用Unix环境时最核心的命令与概念。

近年来，在DevOps理念的框架下，开发人员与系统管理员之间的差距已通过各种方式得到可喜缩小，因此本书对于需要开始接触裸金属（底层硬件）的开发人员同样实用。

这部分开发人员可以从本书中接触到循序渐进的学习路径，以及Unix环境常用命令的快速查询指南。

另一方面，也有部分人群（比如本书作者）对应用开发的底层环节感兴趣，希望以系统管理员或架构师为职业发展方向。对这部分读者而言，本书是合适的入门起点，可以帮助他们了解日常工作中会用到的基础工具与核心概念。

他们很快可能会感觉到需要更全面、更深入的学习材料，市面上也有大量书籍和资源可以满足他们的求知欲，但我希望他们能享受和我一起迈出的这第一步。

### 本书编写目的

我撰写本书的契机，是当时正在为我的初级同事筹备一系列短期培训课程。我多年没有和初级员工共事过，虽然我清楚知道有些人成长过程中没有接触过命令行，但实际上我还是默认他们了解我所掌握的知识——这恐怕是许多资深程序员都会犯的错误。

因此，我决定开展一些培训课程，从最简单的命令开始，逐步带领大家了解Bash Shell，再到一些实用的脚本编写技巧。当他们终于掌握了正确的管道命令组合、或是发现正则表达式的妙用时，露出的满意笑容就是对（我）最好的回报，这种回报至今仍在延续。

从这些培训课程，以及我为筹备课程撰写的笔记中，我萌生了创作一本书的想法，这本书可以读起来会很容易，甚至可以利用碎片时间进行，毕竟如今人们很难找出时间来啃厚厚的巨著。我用英语写作或演讲时通常会避免刻意搞笑——它不是我的母语，所以我既缺乏相关的词汇储备，也摸不准喜剧的节奏。但多年前我学到的一点是，笑声能帮助人们记住所说的内容，所以这次我决定尝试轻松一点的风格。希望这能减轻阅读负担，让你进入Unix世界的旅程更轻松。如果效果不好的话，我提前道歉。你也可以去找一些像《Unix圣经》那样的黑魔法古籍。我很确定，当你成功召唤出某种多触手的洛夫克拉夫特式恐怖存在时，这个画面会在你记忆里留存很多年，但我不确定这会对你的职业生涯有什么实质性影响——除非我们考虑它大概率会直接终结你的职业生涯这个因素。

## 你为什么应该读这本书

如果你是程序员，现如今你可能已经接触过开源软件、Git这类版本控制系统、AWS这类云服务，还有Python或Ruby这类动态编程语言。这些东西的共同点是什么？可能有很多，但其中一个是肯定的：它们都植根于Unix世界。[^1] Unix的世界非常丰富，这本书甚至连它的皮毛都碰不到。但Unix系统最强大的功能之一就是命令行。没错，在2019年，面对无时无刻不在处理我们线上搜索和操作内容的人工智能、拥有完美界面的手机，以及即将到来的成熟虚拟现实技术，那套老派的绿字黑底终端依然有其不可替代的价值。不，远不止有价值！在我看来，命令行是一种永远不会过时、永远有用的工具。看到某个程序的图形界面简洁又好用时我会很开心，但能带来比命令行更高效能的东西根本不存在。所以长话短说，你绝对有必要至少学懂命令行的基础知识！

## 这本书不适合谁读

简单来说，这是一本入门读物，所以如果你已经是资深Unix用户，可以在这里停读了。这本书不是为你准备的。但如果你还是决定往下看，请明白这本书是写给完全没听说过Unix的人做入门介绍的。我知道，在如今这个时代，居然有人用电脑都不用终端，还能日复一日地以为管道是输水的、插座是装在墙上的，这听起来很不可思议，但正是如此，我才觉得这样一本书是有用的。平心而论，2019年要给新手介绍Unix，你不得不面对50年的历史，还有无数在成长过程中浸淫其中的人觉得理所当然的选择遗产。目前至少有两大主流实现：Linux和Mac OS X，前者有几十种不同的发行版，后者的行为方式更是各种意想不到。所以我不得不做一些妥协。尤其是亲爱的专家挑刺党，你会注意到我把“Unix”“Unix shell”“bash”“terminal”这几个术语当成了同义词使用。相信我，每次这么做我都觉得浑身别扭。但说实话，这本书是写给对这门小众学科一无所知的人做入门的。而我的经验告诉我，打击一个人信心最好的方式，就是让他觉得自己很蠢——往对话或课程里塞一堆他从来没听过、也听不懂的术语，以此凸显自己的博学。没错，这样你确实能闪闪发光，但意义何在？所以抱歉了。我知道书里的术语命名远不够准确，也希望新手们几年后再回看这本书时，能笑着原谅我如此轻慢地亵渎了Unix这片神圣领地的行为。

## 提示符

命令行在等待输入时，总会固定地在每一行前面打印一段字符串，这段字符串被恰如其分地称为*提示符*。提示符的可定制性非常高，因为它能随时提供非常有价值的信息。比如我的提示符通常会包含我当前所在目录的完整路径，这样我随时都能清楚自己的位置。很多人还会加上当前时间，或者自己当前所在的Git分支。因为不同系统、不同用户的提示符都不一样，所以大家习惯用美元符号`$`来代表它。所以下面这段代码：

```
$ command --option value --another-option another-value
```

意味着你需要输入`command`后面的字符串，因为`$`对应的提示符在你的终端里本来就已经存在了。我经常会按照终端里的实际显示，把命令输出放在提示符正下方展示，就像这样：

```
$ command --option value --another-option another-value
output line 1
output line 2
output line 3
output line 4
output line 5
```

只有和解释相关、且长度不会太长的命令输出我才会收录。这本书的核心理念是让读者在自己的终端上测试命令，所以我觉得往书里塞满没人会看的输出纯粹是浪费篇幅。当我需要截断输出时，会加上方括号包裹的省略号，示例如下：

```
$ command --option value --another-option another-value
output line 1
output line 2
output line 3
[...]
```

如果你对历史感兴趣的话，用来做提示符的美元符号最早出现在1979年贝尔实验室发布的Unix第7版中，因为这是首个搭载Bourne shell的版本。所谓的长久选择，不过如此！

## 水果标签产品的歧视

在程序员群体中，Mac OS是桌面用户基数最大的类Unix操作系统，因为很多人的主力设备都是苹果笔记本。我并不是其中一员，而且我当初发现Mac OS自带的shell和Linux发行版提供的传统bash shell仅部分兼容时，也非常惊讶。尤其是Mac OS的核心工具链不是GNU系的，所以很多命令行选项要么不存在，要么和Linux上的不一样。因为我打算在退休前把这本书出版，所以我就选了最简单的方案：很抱歉，我不会为Mac OS的终端提供示例或讲解。如果你正在用Mac，不管是自己选的还是有什么外部限制，你都只能去网上找专门的解决方案。目前我会提供在Docker容器里运行Linux机器的教程，这样所有人都能跟着学习、享受这本书的内容。说不定未来我会补充标准工具链非GNU版本的讲解，但现在的任务对我来说太复杂了。尽管我上面语气调侃，但我真的很抱歉没法覆盖所有情况！好消息是，虽然单个命令的选项可能不同，但整体概念是一致的，所以哪怕你是Mac OS用户，读这本书学习怎么用命令、怎么查命令帮助、怎么把命令组合成脚本，也会大有裨益。

### Linux用户

如果你使用的是Linux系统，那么基本已经完成了环境配置。你只需要下载测试文件，并确保在克隆出的目录中运行示例和练习即可。将压缩包解压到你选择的目录中，然后通过终端进入该目录。如果你使用的是Gnome或KDE这类图形化桌面环境，通常在文件浏览器中可以找到“在此处打开终端”的选项。否则你也可以直接打开终端（KDE对应Konsole，GNOME对应GNOME终端，或任意其他终端模拟器），然后通过以下命令切换到目标目录：

```
$ cd path/of/the/directory
```

其中`path/of/the/directory`是你上一节中克隆的仓库的完整路径。恭喜，你已经准备就绪！

### Mac OS用户/Windows用户

本书至少初期版本只会讲解Linux系统。Linux是绝大多数云解决方案所使用的操作系统，也是服务器上事实上的最普及的Unix系统，这就是我选择讲解它的合理原因。我个人电脑也在使用Linux，但大多数程序员使用的是Mac或Windows设备。

不讲解Mac OS的主要原因是其默认终端与Linux的对应终端并非100%兼容（因为Mac没有使用GNU工具集）。我没有Mac设备，而且即便我可以涵盖所有不同版本的工具集，我认为这对初学者来说也会非常难以承受。

不讲解Windows的主要原因是它甚至不是Unix系统。我知道新版本包含了某种Linux层，但我同样没有时间精力去研究这些系统。因此如果你使用的是Mac OS X或Windows，你就需要在Docker容器中运行Linux。我会在这里提供两种不同的方案，第一种更简单，但会缺失系统的部分组件；第二种稍微复杂一些，但功能完整。

请注意，无论选择哪种方案，你都需要在系统中安装Docker，具体安装步骤可参考Docker官方文档⁹。如果你最初选择了简单方案，之后想尝试更完善的版本，也可以随时回来运行更复杂的方案。

### 简单方案

你可以在Docker中运行默认的Ubuntu镜像。该镜像经过精简以减小体积，因此你会缺失Linux系统自带的一部分文档，也就是我们常说的“man手册（手册页）”。我们将在第一课中使用这些手册，我也建议读者通过它们学习命令的使用方法，因此如果你选择这个方案，每次需要查询命令帮助时都需要参考在线man手册。我会在书的相关章节中提及这些在线资源，所以现在不用担心。

要运行Ubuntu镜像，首先克隆包含示例文件的仓库，进入该目录后运行Docker，命令如下：

```
$ git clone https://github.com/bgutbook/bgutbook_files.git
$ cd bgutbook_files
$ docker run -t -i -v $(pwd):/opt/bgutbook_files ubuntu /bin/bash
root@1d888c92ee76:/# cd /opt/bgutbook_files/
root@1d888c92ee76:/opt/bgutbook_files#
```

至此你已经可以开始阅读本书并运行示例了。想要退出时只需要输入`exit`并按下回车键即可。如果想要继续使用，只需要重复上述流程，跳过`git clone`步骤即可，具体命令如下：

```
$ cd bgutbook_files
$ docker run -t -i -v $(pwd):/opt/bgutbook_files ubuntu /bin/bash
root@1d888c92ee76:/# cd /opt/bgutbook_files/
root@1d888c92ee76:/opt/bgutbook_files#
```

### 进阶方案

如果你需要一个自带man手册的Ubuntu容器，你需要创建一个新的Docker镜像。我在`bgutbook_ubuntu`仓库中提供了这类镜像的Dockerfile配置文件。

首先克隆该仓库：

```
$ git clone https://github.com/bgutbook/bgutbook_ubuntu.git
```

然后进入目录并构建Docker镜像：

```
$ cd bgutbook_ubuntu
$ docker build -t bgutbook_ubuntu .
```

现在Docker会创建一个名为`bgutbook_ubuntu`的镜像并存储在你的系统中。至此你已经可以随时运行该镜像来跟随本书的示例了。退出存放Dockerfile的目录，克隆包含示例文件的仓库，进入该目录后运行Docker，命令如下：

```
$ cd ..
$ git clone https://github.com/bgutbook/bgutbook_files.git
$ cd bgutbook_files
$ docker run -t -i -v $(pwd):/opt/bgutbook_files bgutbook_ubuntu /bin/bash
root@1d888c92ee76:/#
```

如你所见，命令行提示符发生了变化，这说明你已经进入了Linux容器。请注意，提示符中`@`符号后面的数字是运行中的Docker容器的ID，因此你的提示符中的数字会和示例不同。此时切换到容器内存放示例文件的目录：

```
root@1d888c92ee76:/# cd /opt/bgutbook_files/
root@1d888c92ee76:/opt/bgutbook_files#
```

至此你已经可以开始阅读本书并运行示例了。想要退出时只需要输入`exit`并按下回车键即可。如果想要继续使用，只需要重复上述流程，跳过`git clone`步骤即可，具体命令如下：



```bash
$ cd bgutbook_files
$ docker run -t -i -v $(pwd):/opt/bgutbook_files bgutbook_ubuntu /bin/bash
root@1d888c92ee76:/# cd /opt/bgutbook_files/
root@1d888c92ee76:/opt/bgutbook_files#
```

软件最重要的部分就是文档。遗憾的是，我们开发的软件往往没有完善的文档，因为“乐趣都在代码里”。我们大多喜欢开发能实现特定功能的程序，而不是撰写枯燥的文字。

好在Unix系统以及在这个环境下工作的人有着非常出色的文档文化，因此你要学的第一件事就是如何查找和阅读你将要学习的命令的帮助信息。欢迎来到Unix手册页，简称*man手册页*。

每当你需要查询某个命令的帮助时，你可以运行：

```bash
$ man <command>
```

然后进入一个纯文本（但功能非常强大，请注意）的帮助系统。为了学习如何在这个系统中导航，我们来查询一个很快就会学到的简单命令`echo`的帮助。

```bash
$ man echo
```

> ⚠️ 如果你在Docker容器中运行Linux，并且选择了简单方案，那么你的系统不会安装man手册页，因此你需要到https://manpages.ubuntu.com/阅读相关手册。页面的右上角有搜索框。

首先，我来教你一些man手册页操作的基础知识。你可以用上下方向键在文档中移动，也可以用翻页键快速滚动整个页面。请注意，由于手册页是只读的，所以没有光标，只有当前行，也就是最顶部的那一行。屏幕底部的帮助文本会提示你当前的状态：

```
Manual page echo(1) line 1/68 51% (press h for help or q to quit)
```

退出程序有时会异常复杂（随便问个`vi`新手就知道了），但退出man手册只需要按下代表退出的`q`键即可。试试看，然后再次进入`echo`的手册页。呼！至少我们不会永远被困在这里了。

不过，帮助系统并不总是那么直观易懂。里面也有不少命令需要学习。

那么，我们该怎么获取……关于帮助本身的帮助呢？

你看底部提示就行，`q`代表退出，`h`代表帮助。目前来看还算顺利，毕竟早晚会出现代表“动物园”的`a`命令，但基础命令显然还是遵循字母排序的。如果你按下`h`，屏幕就会切换，显示元帮助，也就是关于帮助系统本身的说明。我就不逐条讲解了，你之后可以自己看。

你只要先记住一点：如果忘了某个命令或快捷键，不用急着翻遍整个Stack Overflow找答案，可以直接问系统本身。

现在有个非常重要的操作值得学习，那就是字符串搜索。手册页通常特别长，还经常很无聊，没完没了地讲一些显然无关的细节，可你当下急需用到*那个*参数（多数时候是因为你的系统快崩了，用户气得打电话来催，你还得把运行中的进程按CPU占用率排序，毕竟这样看起来整齐嘛）。

所以，要在手册页里搜索字符串，你只需按下`/`（注意底部会弹出输入提示），然后输入你要找的内容就行。试试按`escape`键，输入完关键词记得敲`ENTER`。

你会看到搜索的关键词被高亮显示了，这视觉效果非常直观。之后按`n`（next，下一个）就可以跳转到下一个匹配结果，按`N`（不是下一个，是上一个）就能往回跳。

> – *来吧，让我们开始吧。*

人们往往不会读长消息，比如你发邮件的时候就要注意这点。如果内容太长，大家通常只会看开头，然后跳过中间部分直接看结尾。也就是说，如果你消息的核心内容是你耗时20年研究时间旅行得出的最终成果，教你如何用洗碗机制作时光机，那这部分内容就丢了、彻底没了。抱歉，你本可以写得再简洁一点的。虽然这是人的坏习惯，但读取数据流的开头和结尾部分往往非常实用。

比如，我们可能需要按大小列出文件并提取前5个，也可能需要输出系统最后10条日志，以便随时了解系统运行状态。好在Unix提供了两个好用的命令来完成这些操作，分别是`head`和`tail`。仅从名字你就能分清它们的功能，这点是这些命令的作者为我们做的非常贴心的设计。

运行如下命令时：

```bash
$ head <file>
```

系统会默认输出文件的前10行。你可以在示例仓库提供的`slices.txt`文件上尝试这个命令以及后面的示例。该文件只是从1到20的连续编号行，方便你快速验证操作是否正确。因此执行`head slices.txt`应该会输出第1-10行。

反过来，如果执行`tail slices.txt`，你会得到第11-20行，也就是文件的最后10行。如果需要快速浏览文件、大致了解内容结构，10行通常是合适的量级，但你也可以指定输出更少或更多的行。

这两个命令都可以通过`-n`参数后接指定的行数来实现这个功能。比如`head -n3 slices.txt`会输出文件的前3行。请注意Unix命令行的一个重要规则：参数和它的值之间可以加空格也可以不加，因此执行`head -n3 slices.txt`和`head -n 3 slices.txt`会得到完全相同的结果。你甚至可以在参数和值之间加多个空格，如果你觉得开心的话，但等我们开始按列分割文本时，你大概就不会喜欢多空格了，所以最好还是别这么做。友情提示哦。

### 第五天 - 分号、逻辑与、管道

> – 好了，我们逻辑上理清这件事吧。
> 《回到未来3》（1990）

到目前为止，bash和Unix似乎没有使用其他编程语言或系统中那些烦人的奇怪符号，这不是很好吗？是的，但遗憾的是这并不属实。这节课我们会接触到Unix用来表达复杂操作的一些花里胡哨的“象形文字”，如果你还在遗憾大学时错过了古巴比伦语言课，那现在开心了吧，你很快就能补上了。

首先我们来了解分号。尝试在两个命令之间加上分号，比如：

```bash
$ echo "First string"; echo "Second string"
```

如你所见，bash会按顺序执行这两个命令，因此`;`显然代表两个命令之间的某种“与”关系。

但如果其中一条命令执行失败会怎么样呢？这一点也很有趣。我们尝试把第一个命令设为读取一个不存在的文件的内容：

```bash
$ cat nofile.txt; echo "Second string"
```

这条组合命令的输出先是`cat`的错误提示（它毫不留情地让我们罚站），然后才是`echo`命令的输出。

因此，分号会无视命令的执行结果，始终执行所有命令。但很多时候我们需要另一种命令串联方式：只要有一条命令执行失败，就中断后续操作。比如你可能需要查找所有指定名称的文件，并生成一份统计日志，但如果找不到符合要求的文件，你肯定不想执行最后一步。

现在我们来看看`&&`运算符对上面两条命令的作用：

```bash
$ cat nofile.txt && echo "Second string"
```

看起来这正是我们需要的效果：我们仍然会收到`cat`的错误提示（又要罚站了，抱歉），但不会输出`echo`的内容。因为有一条命令执行失败，bash中断了后续操作。

把这个知识点记牢，迟早会用得上。还有第三个“古文字”熬过了古埃及王国的衰亡，最终登陆了Unix系统，它是你必须掌握的最重要的运算符之一。所以，去泡杯浓咖啡吧，你得保持清醒。

### 注意事项

你可能会注意到，本书后面我始终使用`cat <file> | <command>`的模式，尽管很多命令的手册页显示你也可以省略`cat`和管道符，直接执行`<command> <file>`。虽然我日常工作中两种用法都会用，但本书更推荐第一种，因为它能更清楚地说明`<command>`的作用，同时帮助你熟悉管道的用法。

到目前为止，我们运行命令时，输出都会（神奇地？）打印在终端上，这没问题，因为大多数时候我们都需要查看命令的执行结果。而命令的输入则几乎全部来自你硬盘上已有的文件。

如果你运行如下命令：

```bash
$ head -n 10 slices.txt | tail -n 5
```

只要你的系统没出毛病，你应该会看到`slices.txt`文件的第6-10行。

但等等……我们让`head`输出10行，这结果怎么有点奇怪？`|`运算符叫做*管道*，作用是把第一个命令的输出结果“导走”，让它不再显示在终端上，而是直接传给`tail -n 5`命令处理。所以我们得到的是`slices.txt`前10行中的最后5行，也就是第6-10行。我之前就说这节课讲的是管道工程吧？

许多处理文件的Unix命令都支持从管道接收输入，现在你应该明白管道为什么这么重要了吧？通过管道你可以连接多个命令，用简单的命令组合出复杂的操作。现在，欢迎来到Unix教授的操作系统哲学课！

我这话可没全在开玩笑，所谓的*Unix哲学*要求你开发小巧的程序，只做非常具体的事，但要把这些事做到极致。之后你可以用管道和其他运算符把这些小程序组合起来，实现更复杂的功能。

今天就到这儿吧！你今晚可能会梦到漏水的管道、哲学家和法老们。我只能推荐你读本好书、喝杯热茶。就是别看任何和古文化相关的内容就行！建议今晚观看的电影：《星际之门》（1997）—— 一些Unix程序员在一家工厂里协同工作，这座工厂似乎证明了古埃及人早就熟悉命令行操作。

### 第6天 - 打印指定行

## 第12天 - 正则表达式 - 单字符

正则表达式（regex）是你在搜索（和替换）文本时能学到的最强大的工具。它们是具有特定语法的字符串，用于搜索其他字符串。它们不幸有着极其复杂的名声，但我希望能成功打破这个迷思。你当然可以写出复杂的正则表达式，有时候要花很久才能想明白如何表达某个特定模式，但你会发现它们绝对是容易上手的。

我有没有成功给你带来希望？有？很好，因为这一章会超级难。哈哈，开玩笑的！

为了练习正则表达式，我们会用到`examples.txt`文件和我们的老朋友`grep`。让我们看看加上启用正则表达式的`-E`选项的`grep`的实际效果：

```
$ grep -E "dog" examples.txt
dog
dog
corn dog
```

如你所见，`-E`选项似乎没有改变工具的行为，太令人失望了。这是因为字符串`dog`本身已经是有效的正则表达式了，它匹配的是字符`d`，后跟字符`o`，再后跟字符`g`。你大概觉得我在绕弯子吧？

好了，是时候写第一个“正规”的正则表达式了，或者说至少用一下正则表达式提供的特殊语法。毕竟我们来这儿不是为了看猫和狗的。

让我们运行以下命令（记住这次不用`-o`选项）：

```
$ grep -E "d." examples.txt
dog
beholder
dryad
dog
aardvark
corn dog
direwolf
phase spider
undead red dragon
Spider-Man [*]
wild hog
Big Bad Wolf
```

如你所见，`grep`会高亮两个字母的组合，且这些组合都以`d`开头。**狗**里的"do"、`spider`里的"de"、**龙**里的"dr"，这些行都有一个共同点：它们都包含一个`d`，后面跟着另一个符号（字母或空格，比如"wild hog"里就是这样）。这就是正则表达式中符号`.`的作用。它并不像常规标点用法里那样表示句号，而是代表“任意字符”。只要正则表达式中包含`.`，就代表此处可以是任意单个字符。注意：单个`.`仅匹配单个字符。

如此一来你会发现，正则表达式本质上是简单的字符串，但其中既可以包含普通字符（大多数字母表的字母，包括大小写，以及数字），也可以包含特殊字符。到目前为止，我们只学过其中一种特殊字符，也就是`.`，在这个场景下通常被称为“点号（dot）”。那如果要匹配字符串里真正的句号该怎么办呢？由于正则表达式会给部分字符赋予特殊含义，如果你想用这些字符原本的含义，就需要用`\`（反斜杠）来转义。

所以，对比下面两条命令：

```
$ grep -E "1.1" examples.txt
Police
101
HTTP/1.1
```

```
$ grep -E "1\.1" examples.txt
HTTP/1.1
```

前者会匹配两个被任意单个字符隔开的"1"，而后者只会匹配被实际句号隔开的项。注意：这个点可以是标点符号、小数点，或者任何其他含义。正则表达式完全不会理睬你正在解析的文本内容，只会将其视为纯字符处理。

```
$ head examples.txt | sed -r s,".g","--",g
d--
cat
elephant
ostrich
D--
the
D--
beholder
dryad
d--
Police
101
aardvark
```

上面的命令会查找任意字符后跟着小写`g`的情况（即`.g`），并将其替换为双短横线。显然在命令的替换部分放正则表达式是没有意义的，因为正则表达式的用途是搜索。在`sed`中，正则表达式通常被用来删除行内不需要的部分。举个例子，我想打印`simple.log`文件的前5行，同时删掉每行中`GET`之后的所有内容：

```
$ head -n 5 simple.log | sed -r s,"GET.*","GET",
83.149.9.216 [17/May/2015:10:05:03] GET
83.149.9.216 [17/May/2015:10:05:43] GET
83.149.9.216 [17/May/2015:10:05:47] GET
83.149.9.216 [17/May/2015:10:05:12] GET
83.149.9.216 [17/May/2015:10:05:07] GET
```

我用了可以匹配所有内容的`.*`模式来删掉输出中不需要的行内部分。如你所见，我需要重复写入`GET`才能保留它。我们将在后续章节中学习避免这种重复的技巧。

### 第14天 - 正则表达式 - 字符类

> – 我曾在沃尔什夫人的英语课上坐在你旁边！《土拨鼠之日》（1993）

你被正则表达式的强大功能惊到了，所以决定回来继续学习！你说是不是？我懂了，是你老板逼你学正则表达式的，但你真正的梦想是成为动作片明星。你应该考虑上点表演课。

说回正题，本节课的主题是正则表达式里的「字符类」，这不是夜校课程，而是字符的集合。上一章我们学了如何在正则表达式里匹配单个特定字符，以及如何匹配任意单个字符。这两个选项非常实用，但很多时候我们需要匹配一组字符，比如数字1、2、3，或者"a"到"f"之间的字母。我们之前讲的两种语法都无法实现这类匹配，所以我们需要新的语法。在正则表达式中，`[<字符列表>]`这个语法代表“字符列表中的任意单个字符”，正好能满足我们的需求。举个例子：

```
$ cat examples.txt | grep -E "[abc]"
```

这条命令会匹配单个的"a"、单个的"b"或者单个的"c"。注意：`grep`会高亮每行中所有匹配到的元素，并打印整行内容；如果你想只打印匹配到的部分，可以使用`-o`参数。比如"dog"这一行会被排除在输出之外，因为它不包含字符类里的任意一个字母。

字符类尤其实用的地方在于它支持使用范围。比如：

```
$ cat examples.txt | grep -E "[a-z]"
```

这条命令会匹配所有英语字母的小写形式。这会高亮"gorilla"和"aardvark"这样的整个单词，因为它们完全由小写字母组成。而"Johnny 5"不会被完整高亮，因为大写的"J"和数字5无法被这个正则表达式匹配。如果你在编辑器里用正则表达式搜索字符串（你自己探索一下常用编辑器怎么实现这个功能吧），`[a-z]`会匹配文本中的第一个小写字母，重复搜索就会找到第二个，以此类推。

```
$ cat examples.txt | grep -E "[a-zA-Z]"
```

这条命令会匹配任意字母，但不会匹配数字。注意：像`A-z`（大写A到小写z）这样的范围是能生效的，但它还会匹配到编码上位于大写和小写字母之间的其他字符，也就是`[`、`\`、`]`、`^`、`_`和`"`这些符号。如果你需要包含这些字符，最好把它们显式添加到字符类里，因为`A-z`的语法很容易被忽略。给后来要调试你代码的人留点活路吧，Unix终端已经比古代魔法书还难懂了，别再让它更糟了。注意：字符类，也就是方括号（包括方括号本身）里的整个块，只是正则表达式的一个元素，它的前面或后面都可以跟其他元素。练习2和3会帮助你实际理解这一点。

### 第15天 - 正则表达式 - 锚点

> ——好了，就这儿。停。抛锚。《龙威小子》（1984）

今天是你正则表达式学习之旅的第3天，准备好迎接更多奇妙内容了吗？今天我们来学习如何使用锚点。

少瞎想，我们不是去烧船锚，你能理解吗？我们要学习的是如何告诉正则表达式文本的位置，以及如何管理重复匹配。

我们先从锚点说起。

你可能想知道，常用于添加超链接的HTML标签`<a>`来源于anchor（锚点），因为它的作用就是把元素固定在标记的特定位置。

时过境迁，如今的情况已经大不相同了。

不过这件事和正则表达式没什么关系，只是恰好说明我们通常都有指定文本查找位置的需求。

不过在深入探讨定位之前，我们先来聊聊跨多行的文本。一般来说，文本按行分隔只是一种约定。我们约定`\n`字符代表换行，这一约定源自C语言，目的是确保代码的最大可移植性，因为ASCII十六进制值`0x0a`可能无法被部分系统识别。

新起一行的文本通常被认为是和上一行相互独立的，至少要被视为列表中的不同条目。比如我们列一个群体的人员名单时，通常会把两个人放在两行，避免名字、中间名和姓氏之间产生混淆。

因此，Unix工具通常是逐行工作的，我们之前用`grep`的时候已经注意到了这一点。使用正则表达式时也不例外，因为处理正则的工具都是逐行读取、处理文本的。

当然也有办法对多行文本应用正则表达式，不过这部分我们留到之后的课程再讲。

我们回到锚点上来。

当我们要在长文本中查找某个字符串时，最常见的两种情况是：字符串位于行首，或者字符串位于行尾。

正则表达式语法提供了两个特殊字符来标记这两种位置，恰如其分地被命名为*锚点*，分别是`^`（*脱字符*，也叫*插入符*）和`$`（*美元符*）。

请注意：部分Shell用作提示符的`$`（本书示例中也用了这个符号）和锚点`$`没有任何关系。

比如，在`examples.txt`文件中运行以下命令：

```
$ grep -E "dog" examples.txt
dog
dog
corn dog
```

会返回所有包含"dog"字符串的行。

如果你运行：

```
$ cat examples.txt | grep -E "^dog"
dog
dog
```

你会发现最后一行没有出现，因为`^`会把"dog"字符串锚定到行首。

反过来，如果你运行：

```
$ cat examples.txt | grep -E "dog$"
dog
dog
corn dog
```

你会得到和第一次运行相同的结果，因为这些"dog"字符串都位于行尾。

如果你需要同时把内容锚定在行首和行尾，也可以把两个锚点组合在同一个正则表达式中：

```
$ cat examples.txt | grep -E "^co.*og$"
corn dog
```

### 第16天 - 正则表达式 - 多重复匹配
> ——约会会给你胸花，可不会让你多处骨折。《恐怖小店》（1986）

太棒了！我们学完3节被归为进阶内容的课程后还活得好好的，恭喜！我希望你不仅坚持下来了，还真正享受这段学习之旅。我觉得你已经开始意识到：正则表达式其实并不难，只是比较复杂，充满了特殊符号和规则。

到目前为止，我们已经学了如何使用`.`匹配任意字符，用`[`和`]`定义字符类、用`-`表示范围，最后还学了两个锚点`^`和`$`。
今天我们来学习多重复匹配。

一般来说，多重复匹配是指对前一个正则表达式的重复匹配，典型的使用场景是你需要匹配指定数量的数字或字母，不过多重复匹配也可以更宽泛，比如匹配数量不固定的小写字母。

我们先从精确匹配开始，这种匹配使用`{N}`语法，其中`N`代表匹配次数。
正如我之前所说，所有多重复匹配操作都作用于前一个正则表达式，因此如果你运行

```shell
$ grep -E "a{2}" examples.txt
```

输出：

```shell
aardvark
```

就是让`grep`匹配所有由2个相邻`a`字符组成的组合，比如`aardvark`里的`aa`。
括号里的数字可以是任意正整数，不过填1没有意义，因为单个字符本身就已经是匹配1次重复的正则表达式了。

所以虽然你可以运行

```shell
$ grep -E "a{1}" examples.txt
```

得到正确结果，但这和运行

```shell
$ grep -E "a" examples.txt
```

完全等价，我个人觉得引入花括号让正则表达式更复杂难读没什么必要。
如果你喜欢自找麻烦，不妨试试用`PHP`写一个社交网络。等等，你说什么？他们真这么干了？

花括号会重复前一个正则表达式组件，因此`a{2}`的语法等价于字面量`aa`。
不过这种语法不仅可以重复字母，还可以作用于正则表达式的任意前一个组件。

比如运行以下命令：

```shell
$ grep -E "[a-z]{3}" examples.txt
```

输出：

```shell
dog
cat
ele
pha
ost
ric
the
beh
old
[...]
```

会匹配恰好3个相邻的小写字母。
需要注意的是，匹配的模式不会重叠：比如在`elephant`中，正则表达式只会匹配到`ele`和`pha`，而不会匹配`ele`、`lep`、`eph`之类的组合。

一旦某个模式被匹配后，就会被跳过以继续分析整行内容。如果你用我们之前学过的`grep`的`-o`选项，这一点会非常明显，该选项只会输出字符串中匹配的部分：

```shell
$ grep -Eo "[a-z]{3}" examples.txt
```

输出：

```shell
dog
cat
ele
pha
ost
ric
the
beh
old
[...]
```

花括号还可以用来指定范围：`{n,m}`表示重复`n`到`m`次，`{n,}`表示重复`n`次及以上，`{,m}`表示重复0到`m`次。
比如：

```shell
$ grep -E "[a-z]{8,12}" examples.txt
```

输出：

```shell
elephant
beholder
aardvark
direwolf
manticore
basilisk
```

会匹配所有包含至少一个由8到12个小写字母组成的单词的行。

有两个特定的范围非常常用，分别是`{1,}`和`{0,}`。前者匹配组件的一次及以上重复，适用于你知道至少会出现一次、但不确定上限的场景；后者则用于匹配组件的任意次出现（包括0次）。
由于这两个范围非常重要，因此有对应的简化语法：`{1,}`可以写成`+`，`{0,}`可以写成`*`。

因此，以下命令：

```shell
$ grep -Eo "D[a-z]+" examples.txt
```

输出：

```shell
Dug
Dog
```

会匹配字母`D`后跟着至少一个小写字母的内容，因此输出会包含`Dug`和`Dog`（注意这里用了`-o`选项，可以清晰展示匹配结果）。

而命令

```shell
$ grep -Eo "D[a-z]*" examples.txt
```

输出：

```shell
Dug
Dog
D
```

还会匹配来自`R2-D2`一行的单独`D`，因为这个`D`后面跟着0个或多个小写字母。

请注意最后两个例子：你会发现`+`和`*`是作用于正则表达式的最后一个*组件*，和花括号的规则一致，而不是作用于最后一个*字符*。`a+`的语法之所以成立，是因为单个字母或数字本身也是一个独立的正则表达式组件。

### 第17天 - 正则表达式 - 捕获组
> _它们三人一组。_
> *《逃出纽约》（1981）*

哦，捕获组。我有多喜欢捕获组呢？这么说吧，肯定比喜欢披萨少，不过毕竟披萨是轻松就能赢过的好选择。好了，美食比较暂且不论，我认为捕获组是正则表达式最棒的特性之一，这既得益于它们的强大表达能力，也得益于它们引入了一种通常只有编程语言才会提供的工具：变量。接下来我们来看看为什么捕获组很重要。

总的来说，捕获组允许你隔离正则表达式的特定部分，并在后续复用它们，但你可以复用它们的方式取决于你使用的工具。捕获组在 `sed` 中尤其有用，因为它们能大幅优化搜索替换的语法。以下代码使用 `sed` 解析正则表达式（通过 `-r` 选项启用），用括号隔离一个捕获组，并在替换字符串中使用匹配到的模式。

```shell
$ echo "10:30" | sed -r s,"([0-9]{2}).*","H:\1", H:10
```

该正则表达式尝试匹配2个相邻的数字（`[0-9]{2}`），但将它们用括号放入捕获组后，`sed` 会将该值存储在变量中。在本例中，存储的值是 `10`，其余内容被可匹配任意内容的 `.*` 忽略。如你所见，`sed` 访问搜索过程中存储的捕获组值的方式是反斜杠加数字。第一个（本例中也是唯一一个）捕获组命名为 `\1`，第二个为 `\2`，以此类推。因此，替换模式是一个以 `H:` 开头，后接搜索过程中匹配并存储的值（即 `10`）的字符串。

接下来我们尝试一个稍微复杂点的、包含两个捕获组的示例。

```shell
$ echo "10:30" | sed -r s,"([0-9]{2}):([0-9]{2})","H:\1 - M:\2", H:10 - M:30
```

```shell
$ echo "alpha10" | sed -r s,"([a-z]+([0-9]+))","Full code:\1 - Number:\2", Full code:alpha10 - Number:10
```

你会发现内部捕获组 `([0-9]+)` 匹配到了数字 `10`，但外部捕获组同时匹配了字母和数字两部分，本质上相当于没有内部组的 `([a-z]+[0-9]+)`。

在替换字符串中使用捕获组时，你不必按顺序保留它们，例如：

```shell
$ echo "First,Second" | sed -r s/"(.*),(.*)/"/\2,\1"/ Second,First
```

这是交换逗号分隔字符串中两个字段的非常简便的方法。嗯，也许你觉得这没那么简单，那我们一起来复盘一下。首先，我使用 `/` 来分隔搜索字符串和替换字符串，因为搜索字符串中包含逗号。第一个捕获组匹配第一个逗号之前的所有内容，之后第二个捕获组捕获剩余部分。在替换字符串中，我先输出第二个捕获组的内容，再加一个逗号，最后输出第一个捕获组的内容。

我们也可以在 `grep` 中使用捕获组，尽管匹配值的复用显然受限于 `grep` 不会替换文本这一特性。`grep` 中捕获组的最佳用途是所谓的环视表达式，这类表达式由 Perl 兼容正则表达式语法（PCRE）提供，通过 `-P` 开关启用，而我们之前一直使用的 `-E` 开关则是启用扩展语法（ERE）。这两种语法的差异超出了本书的讨论范围，你可以自由地在网上查阅相关资料。

环视表达式可以提供匹配模式周边环境的信息，但不会将周边环境本身纳入匹配结果。我们来看一个例子：最简单的环视形式是正向先行断言，其中捕获组指定了字符串匹配部分之后应该出现的内容：

```shell
$ cat examples.txt | grep -P "[A-Za-z ]+(?=[0-9]+)" Police 101 H2O R2-D2 Johnny 5 Cyborg 009
```

```shell
$ cat examples.txt | grep -oP "[A-Za-z ]+(?=[0-9]+)" Police H R D Johnny Cyborg
```

正向先行断言的进阶用法是负向先行断言，由 `?!` 表示。你已经开始发现其中的规律了（提到正则表达式，这个词用得还挺贴切）。环视捕获组以 `?` 开头，后接判断条件，可以是相等（`=`）或不相等（`!`）。你还可以使用后行断言，它以 `?<` 开头，而非以单纯的 `?` 开头。这类表达式匹配后行断言捕获组之后出现的模式，例如：

```shell
$ cat examples.txt | grep -oP "(?<=[A-Z])[a-z]+" ug og olice ohnny pider an yborg ig ad olf ony ictures
```

它会匹配所有大写字母后的小写字母，但不会将大写字母本身纳入匹配结果。这里的后行断言是 `(?<=[A-Z])`。

提醒一下：环视表达式通常很难掌握，它的行为可能会出人意料，因为这很大程度上取决于正则引擎的实现。你刚学会使用捕获组，暂时不会遇到这么复杂的场景，但以后可能会碰到。目前请记住，正则表达式引擎还有很多重要的知识点需要学习，比如它是否是贪婪匹配。本书只是一本入门指南，因此我会假装这些问题不存在，但请记住，还有很多知识等着你去学习！

`grep` 实际上也支持后向引用，但它的行为可能出人意料。这段代码匹配一个大写字母后接一个数字（放入捕获组）、一个横杠、另一个大写字母，以及搜索中捕获组匹配到的相同数字。像 `R2-D3` 这样的字符串就不会匹配这个正则表达式，因为数字 `3` 和之前匹配的数字不一致。或者它不匹配可能是因为处理引擎内置了《星球大战》设定核查器！

捕获组最后一个有趣的特性是，它允许在局部使用逻辑或运算符。我们先来看一下没有捕获组的标准正则表达式中的这个运算符。读到这里，你肯定能看懂以下正则表达式：

```shell
$ cat examples.txt | grep -E "^o" ostrich ogre
```

```shell
$ cat examples.txt | grep -E "a$" gorilla
```

第一个匹配以字母 `o` 开头的行，第二个匹配以 `a` 结尾的行。你可以用管道 `|` 表示的逻辑或同时匹配这两种情况：

```shell
$ cat examples.txt | grep -E "^o|a$" ostrich gorilla ogre
```

不要被管道符号的用法搞混了。在正则表达式中，这个字符没有命令行中的含义（即连接命令），它仅代表逻辑或。这是一个强大的工具，因为它允许你同时运行多个不相关的正则表达式，而无需将它们拆分成多次执行 `grep` 或其他工具。不过目前，这个运算符只能分隔两个完整的表达式。

捕获组允许你在局部使用逻辑或，如以下示例所示：

```shell
$ cat examples.txt | grep -E "[A-Z]([a-z]|[0-9]-)" Dug the Dog Police 101 R2-D2 Johnny 5 Spider-Man Cyborg 009 Big Bad Wolf TM Sony Pictures
```

该正则表达式匹配一个大写字母，后跟一个小写字母（`Du`、`Cy`）或者一个数字加横杠（`R2-`）。由于我希望横杠仅在出现数字时跟随其后，这个条件在没有或运算符、也没有捕获组支持的情况下，用单次运行是无法表达的，否则我就必须把表达式的一部分重复两遍。永远记住，重复的代码是恶习，哪怕是在正则表达式中。

```
-n do not output the trailing newline
```
因此，如果你运行以下命令：
```
$ echo -n "Just a string"

Just a string$
```
你会看到字符串后面立刻跟着命令提示符，如上所示。这个功能在你想要给运行中的进程（比如 for 循环）输出用户反馈，并且想要打印单个字符（比如一个点）时非常有用。在循环中，你需要打印这些字符时不带换行，让它们显示在同一行输出中。

#### 练习 2.03
运行以下命令：
```
$ echo "First line\nSecond line"
```
会发生什么？你能找到把`\n`转换为换行的方法吗？

##### 解答
运行上述命令时，输出会是字面字符串`First line\nSecond line`。`\n`序列在 Unix 系统中用来表示换行，但显然`echo`默认无法识别它。这是因为默认情况下，`echo`会忽略`\n`这类*反斜杠转义符*。在编程领域，*转义*是一种避免系统对某些字符做默认解释、向编程语言表明我们赋予其特殊含义的方式。在本例中，如果`echo`遇到字符`n`，只会直接输出字符`n`，但我们想让它有特殊作用。长话短说，如果你在`echo`的手册页中搜索 backslash，会发现它支持`-e`参数来启用反斜杠转义符的解释功能，因此你可以运行`echo -e "First line\nSecond line"`来让两行内容分两行打印。

#### 练习17.03 `simple.log`文件中有3行请求的HTTP状态码为500，示例如下：

```shell
66.249.73.135 [18/May/2015:15:05:42 GET /misc/Title.php.txt HTTP/1.1 500 - -
```

请找出这些行，并将每个客户端的IP地址输出为单个逗号分隔的行（即`<IP地址1>,<IP地址2>,<IP地址3>`）。

##### 解答

这道题可以使用`grep`、`sed`和`xargs`命令求解。

```shell
$ grep -E "HTTP/1.1 500" simple.log | sed -r s,"([0-9.]+) .*","\1", | xargs echo | sed s/" "/,/g

66.249.73.135,66.249.73.135,64.131.102.243
```

首先使用`grep`匹配习题文本中提到的`HTTP/1.1 500`来筛选出相关行，随后用`sed`提取IP地址，再通过`xargs`把多行IP合并为单行，最后将用作分隔符的空格替换为逗号。除了`sed`之外，也可以用`grep`实现：

```shell
$ grep -E "HTTP/1.1 500" simple.log | grep -Eo "^[0-9.]+" | xargs echo | sed s/" "/,/g

66.249.73.135,66.249.73.135,64.131.102.243
```

利用IP地址后方的空格不会被字符类匹配的特性。`xargs | sed`组合的常用替代方案是`paste`命令（本书未介绍过该命令）：

```shell
$ grep -E "HTTP/1.1 500" simple.log | grep -Eo "^[0-9.]+" | paste -s -d,

66.249.73.135,66.249.73.135,64.131.102.243
```

建议你阅读一下`paste`命令的手册页，这个命令非常简单实用，值得收入你的工具集。
