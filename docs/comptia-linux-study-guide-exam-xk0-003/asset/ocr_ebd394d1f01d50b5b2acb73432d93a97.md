Although Linux includes a ki11 program, many shells, including Bash and csh, include built-in ki11 equivalents that work in much the same way as the external program. If you want to be sure you're using the external program, type its complete path, as in /bin/ki11.

The -s signa1 parameter sends the specified signal to the process. You can specify the signal using either a number (such as 9) or a name (such as SIGKILL). The signals you're most likely to use are 1 (SIGlUP, which causes many server programs to reread their configuration files), 9 (SIGKILL, which causes the process to exit without performing routine shutdown tasks), and 15 (SIGTERM, which causes the process to exit but allows it to close open files and so on). If you don't specify a signal, the default is 15 (SIGTERM). You can also use the shortened form -signa1. If you do this and use a signal name, you should omit the SIG portion of the name---for instance, use KILL rather than SIGKILL. The pid option is, of course, the PID for the process you want to kill. You can obtain this number from ps or top.

![](bbox=[0.12, 0.38, 0.22, 0.44])

The ki11 program will kill only those processes owned by the user who runs ki11. The exception is if that user is root; the superuser may kill any user's processes.

A variant on ki11 is ki11a11, which has the following form:

```
ki11a11 [options] [-] name [...]
```

This command kills a process based on its name rather than its PID number. For instance, ki11a11 vi kills all the running processes called vi. You may specify a signal in the shortened form (-signa1) or by preceding the signal number with -s or --sig na1. As with ki11, the default is 15 (SIGTERM). One potentially important option to ki11a11 is -i, which causes it to ask for confirmation before sending the signal to each process. You might use it like this:

```
$ ki11a11 -i vi
Ki11 vi(13211) ? (y/n) y
Ki11 vi(13217) ? (y/n) n
```

In this example, two instances of the Vi editor were running, but only one should have been killed. As a general rule, if you run ki11a11 as root, you should use the -i parameter; if you don't, it's all too likely that you'll kill processes that you should not, particularly if the computer is being used by many people at once.

Some versions of Unix provide a ki11a11 command that works very differently from Linux's ki11a11. This alternate ki11a11 kills all the processes started by the user who runs the command. This is a potentially much more destructive command, so if you ever find yourself on a non-Linux system, do not use ki11a11 until you've discovered what that system's ki11a11 does, say by reading the ki11a11 man page.
