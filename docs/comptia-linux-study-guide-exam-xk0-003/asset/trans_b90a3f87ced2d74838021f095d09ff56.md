
C. `xinetd` 的 `bind` 选项允许您将服务器绑定到单一网络接口，而不是将它们全部链接在一起。这与在一个端口上运行多个服务器、通过主机名指定计算机或解决服务器之间的冲突没有任何关系。

D. `/etc/inittab` 文件控制默认的运行级别。虽然可以使用 `telinit` 临时更改运行级别，但这种更改不是永久性的。命令 `telinit` Q 告诉系统重新读取 `/etc/inittab`，因此可以在您编辑该文件后用于实施新的默认设置，但在编辑该文件之前不会有任何效果。`/etc/modules.conf` 文件与运行级别无关，并且没有标准的 `runlevel` 模块。

C. `telinit` 命令用于更改运行级别。选项 A，`telnet`，是 Linux 用于发起远程登录的 Telnet 客户端。选项 B，`runlevel`，显示当前和上一次的运行级别，但不更改运行级别。没有 `switch-runlevel` 命令（选项 D）。

D. 当以 hh:mm 格式指定重启时间时，它被表示为 24 小时制时间，因此 01:00 对应于上午 1:00。`-r` 参数指定重启，而不是停机。（`-h` 指定停机。）

A. 选项 A 正确描述了这两个运行级别的含义。与选项 B 相反，SysV init 脚本在 Red Hat（以及大多数其他 Linux 系统）的所有运行级别中都被使用。选项 C 描述的是运行级别 1 和 2–5 之间的区别，而不是 3 和 5 之间的区别。

B. Ubuntu 默认在所有其多用户运行级别中运行 X，因此进入运行级别 3 对 X 没有影响；您必须使用 SysV 启动脚本在 Ubuntu 上关闭 X。选项 A 是错误的，因为 Ubuntu 的标准配置并不是错误配置，尽管它不同于 Red Hat 的系统；而且控制其在哪个运行级别运行的是您的 SysV init 和运行级别配置，而不是 X 服务器。选项 C 是错误的，因为没有 `stomp` 命令，尽管有一个 `startx` 命令可以从文本模式登录启动 X。与选项 B 相反，在标准 Ubuntu 配置中，X 不会在运行级别 4 下关闭。

A. `emerg` 优先级代码是可用代码中的最高级，因此高于所有其他选项。（`panic` 代码与 emerg 等效，但不是选项之一。）从最高到最低的优先级，给出的选项代码为 `emerg`、`crit`、`warning` 和 `debug`。

C. 入侵者通常会试图篡改系统日志以隐藏其存在。将日志放在另一台计算机上会降低他们实现这一目标的可能性，因此您更有可能检测到入侵。将日志记录到单独的计算机实际上会增加远程使用量。`Tripwire` 并不执行日志分析；那是 `Logcheck` 的工作，而 `Logcheck` 可以在任何存储日志的计算机上运行。系统日志记录器可以本地记录任何可以远程记录的信息。

B. Logcheck 使用模式匹配规则来提取包含与可疑活动相关的关键词的日志文件条目。虽然其他选项可能有用，但 Logcheck 和其他常见的日志文件分析工具无法执行这些任务。

A. `logrotate` 程序会查阅一个名为 `/etc/logrotate.conf` 的配置文件，该文件包含几个默认设置，并通常引用 `/etc/logrotate.d` 中的文件来处理特定的日志文件。

C. **logrotate** 程序可以通过在 cron 中添加一个条目来自动——且无人值守——定期启动。**at** 实用程序将在您希望程序只运行一次时使用，而 **logrotate.d** 定义了该程序如何处理特定的日志文件。**init**tab 表用于服务和启动，而不是用于单个程序。

B. **sed** 实用程序可用于“流式”处理文本并将一个值更改为另一个值。在这种情况下，s 选项用于将 **dog** 替换为 **mutt**。选项 A 中的语法是错误的，而选项 B 和 D 也是错误的，因为 **grep** 不包含执行更改所需的功能。

C. **xinetd** 包含安全功能，使您可以控制哪些远程系统可以连接到特定的 **xinetd** 管理的服务器。如果您使用 **inetd**，则必须添加独立的 TCP Wrappers 包才能获得类似的功能。因此，选项 B 是正确的。选项 A 是错误的，因为 **inetd** 和 **xinetd** 都不用于控制 SysV 启动脚本（尽管这两个程序通常都是从 SysV 脚本启动的）。选项 C 是错误的，因为 **inetd** 使用每行一个服务器的配置文件格式；**xinetd** 使用更详细的多行格式。哪个更好取决于个人偏好。选项 D 是错误的，因为 **inetd** 和 **xinetd** 都不启动 X。（不过，两者都可以启动某些与 X 相关的工具，例如 XDMCP 登录服务器。）

传统的 PC 操作系统，如 DOS 和早期版本的 Windows，基本上是单用户操作系统。虽然两个人或更多人使用运行这些操作系统的计算机显然是可行的，但这些操作系统本身不提供任何机制来帮助防止用户读取甚至损坏彼此的文件。另一方面，Linux 基于 Unix 建模，而 Unix 被设计为多用户操作系统。在 Linux 和 Unix 中，操作系统提供了旨在帮助防止用户损害彼此文件的工具。相同的机制用于提供安全并防止用户损坏整个操作系统。出于这些原因，Linux 系统管理员必须了解操作系统如何处理用户，以及有哪些可用工具可以帮助您管理自己系统上的用户。

本章涵盖几个特定的用户管理主题，首先是对基本多用户概念的概述。接下来是关于配置用户和用户组的信息，以及您在管理用户和组时可以采用的常见策略。由于 Linux 的账户系统是其安全系统的支柱，本章描述了您可以用于账户管理以提高安全的策略，重点是良好的密码实践。本章最后讨论了访问控制——使用账户、加密和服务器特定选项来限制特定用户或计算机对计算机的访问。

## 理解多用户概念

在处理 Linux 系统上管理用户帐户的琐碎细节之前，您应该了解潜在的概念，包括一些实现细节。了解这些信息将有助于您规划有效的账户结构或扩展现有结构以满足新需求。当您从一台计算机迁移帐户到另一台计算机，添加新硬盘或执行其他类型的系统维护时，这些信息可能也至关重要。

### 用户账户：多用户系统的核心

Linux 用户账户基本上与其他类 Unix 操作系统中的用户账户相同。它们允许多人在不同时间或同一时间使用同一系统，而不会互相干扰。单个用户甚至可以拥有多个同时激活的登录，这有时很方便。重要的是要理解用户账户允许您对系统执行哪些操作，以及用户是如何被识别的。

### 多用户系统中的账户

技术上讲，用户是一个人，而账户是与该用户相关联的一组数据结构和权限。然而，术语“用户”经常被使用，仿佛它与“账户”是同义词，例如“你必须删除这个用户”。不要字面地理解这种语言——删除的是账户，而不是用户。

Linux 账户有几个重要的功能，包括：

- **用户名**：用户名是账户对人类已知的名称，例如 ellen。Linux 用户名的特征稍后将在“Linux 用户名”中更详细地描述。
- **登录权限**：账户允许个人登录到 Linux 计算机。根据系统配置，这可能是控制台登录（即直接连接到计算机的键盘和显示器）或远程登录（通过串行线、调制解调器或网络）。当个人登录时，该人可以使用计算机上可用的一些或所有程序和Resources。一些其他资源，如由 Web 服务器提供的文件，不需要登录。
- **密码保护**：Linux 账户由密码保护。尝试登录的人必须提供用户名和密码。用户名通常是公开的，但密码是秘密的。某些形式的登录绕过密码保护，通常是通过委托给另一台计算机执行的认证。
- **权限**：每个账户都有权限运行某些程序并访问某些文件。这些权限基于文件逐一控制，如第 2 章“使用文本模式命令”中所述。
- **主目录**：每个账户都有一个与之关联的主目录。这是用户可以存储数据文件的目录。通常，每个用户都有自己的主目录，尽管可以配置系统使两个或更多用户共享一个主目录。还可以指定一个用户无法写入的主目录，但这很少有用。（如果用户应该能够运行不生成自身数据但不应在计算机上存储文件的程序，您可能会使用这种配置。）
- **用户和组 ID**：计算机处理的是数字，而不是单词——我们在计算机屏幕上看到的单词在内部编码为数字。Linux 为每个账户关联两个数字。第一个是用户 ID（UID），映射到特定的用户名。第二个是组 ID（GID），映射到特定的用户组。这两个过程将在“将 UID 和 GID 映射到用户和组”一节中进一步描述。
- **默认 Shell**：当在基于文本的登录时使用 Linux 计算机（例如，在没有运行 X 窗口系统的控制台上，或通过基于文本的网络协议如 Telnet），Linux 向用户呈现一个称为 shell 的程序，如第 2 章中所述。Linux 有几个可用的 shell，可以按账户设置。
