## 使用 VNC

VNC 最大的优势在于其跨平台特性。Linux、其他 Unix 变体、Mac OS、Windows 以及更多较不常见的操作系统均有 VNC 客户端和服务器可用。这使得 VNC 成为跨平台环境中远程图形用户界面访问的良好选择。

### 配置 VNC 服务器

Linux 上的标准 VNC 服务器配置相当独特：它以普通用户身份运行 VNC 服务器。访问该服务器将产生以运行服务器的用户身份登录到计算机的操作。因此，如果 Fred 和 Mary 都在 Linux 系统上运行 VNC 服务器，他们各自可以分别登录；但如果 George 和 Sally 在系统上也有账户却没有运行 VNC，他们将无法远程登录。在幕后，Linux 的 VNC 服务器程序包含一个 VNC 服务器和一个 X 服务器；两者相互链接，VNC 服务器部分作为 X 服务器部分的虚拟键盘、鼠标和显示器。

![](img/9903a4d3f7abd8dcbef1035fa04a3406_536_0.png)

可以将 VNC 链接到一个 X 显示管理器控制协议（XDMCP）服务器。这样做时，访问 VNC 服务器系统的用户将看到标准的 Linux XDMCP 登录界面。此配置需要使用此处未描述的 VNC 高级选项。

运行 VNC 的第一步是安装它。存在几种不同的 VNC 服务器，大多数发行版都附带其中至少一个。通常，可用的客户端和服务器软件包是独立的，通常称为 vnc 和 vnc-server，或这些名称的变体（例如 tightvnc 和 tightvncserver）。如果你不确定系统中是否安装了 VNC，请使用高级包管理器（如 yum 或 apt-get）搜索相关软件包。如果没有安装 VNC，请安装适用于你的发行版的相应软件包，或访问 RealVNC 网站（http://www.realvnc.com/）或 Tight VNC 网站（http://www.tightvnc.com）。安装 VNC 后，在 VNC 服务器系统上以普通用户身份执行以下步骤：

- 1. 在主目录中创建一个名为 ~/.vnc 的目录。此目录将存放你的 VNC 配置文件。
- 2. 输入 vncpasswd。该程序会提示你输入一个密码以及用于验证此密码的内容。默认情况下，VNC 不使用标准的 Linux 密码数据库。你需要此密码才能进入系统。
- 3. 输入 vncserver。该命令实际上是一个脚本，它执行各种检查，然后以你的名义启动一个 VNC 服务器（使用 Xvnc 程序文件）。该程序会显示一些摘要信息，包括 VNC 会话号：

```
New `tranquility.luna.edu:1` (`neil`) `desktop is` `tranquility.luna.edu:1`
```

现在，你应该能够访问此 VNC 服务器系统，如即将描述的“使用 VNC 客户端”一节所述。不过，尝试时可能会遇到问题。一个常见问题是服务器无法启动，或者启动后崩溃。请检查 `~/.vnc` 中的日志文件。这些文件可能包含问题的线索。一个常见问题与字体路径有关；VNC 服务器对其字体路径非常敏感，如果你指定了不存在的或配置错误的字体目录，它将崩溃。你可以在命令行中添加 -fp 选项和一个逗号分隔的字体目录列表来解决此问题。或者，你可以调整你的配置文件。

第二个问题——或者说是一系列问题——是各种默认选项可能设置得不太正常。大多数配置使用两种类型的配置文件：

**VNC 启动脚本** `vncserver` 脚本中包含各种选项，例如默认桌面大小、默认字体路径等。在很大程度上，这些默认值等同于你在本地 X 服务器的 xorg.conf 文件中设置的 X 服务器默认值。你可以编辑此脚本以更改这些默认值。

**用户配置文件** 大多数 VNC 服务器使用 `~/.vnc/xstartup` 作为用户的本地启动脚本。此脚本可能会调用 `/etc/X11/xinit/xinitrc` 或其他本地默认启动脚本，或者启动一个极简的窗口管理器，例如 twm。无论如何，你可以像编辑任何其他 X 启动脚本一样编辑此脚本。

## 使用 VNC 客户端

Linux VNC 客户端程序通常称为 `vncviewer`。该工具接受多个选项，但在大多数情况下，你通过输入程序名称、VNC 服务器名称、冒号以及 VNC 会话号来使用它。例如，你可能会输入以下命令：

```
$ vncviewer blueox.luna.edu:1
```

密码：

如果你输入正确的密码，`vncviewer` 将在终端中显示更多文本并打开一个窗口，显示远程计算机的桌面。许多其他操作系统也有可用的 VNC 客户端；关于这些客户端，请查看原始 VNC 或 Tight VNC 网站。这些非 Linux VNC 客户端的工作方式与 Linux VNC 客户端非常相似，但更强调使用对话框输入服务器的主机名和密码。

VNC 的一个重要缺点是，用户通常需要在运行 VNC 客户端程序之前，先通过服务器计算机启动 VNC 服务器。在某些情况下，这个要求并不是主要问题。例如，如果你坐在工作站前，并且知道近期希望从其他位置使用它，你可以在离开工作站之前启动服务器。但在其他情况下，你可能需要使用文本模式登录工具登录 VNC 服务器计算机以启动 VNC 服务器。此过程需要两次登录，这很麻烦。更重要的是，这意味着你必须在服务器计算机上运行两种登录协议，从而增加了其安全暴露面。

## 部署 MySQL

如扩展名称所示，结构化查询语言 (SQL) 是一种用于从数据库中检索数据的语言。实际上，SQL 在几种不同的数据库产品中实现。因此，你应该了解一些可用于 Linux 的 SQL 产品。安装了 SQL 包后，你就可以开始学习 SQL 使用原则并运行 SQL 产品。

### 选择 SQL 包

SQL 是一种访问数据的语言，而特定的 SQL 包实现了该语言。这种区别类似于网络协议（如 SMTP）与实现该协议的服务器（如 sendmail 和 Postfix）之间的区别。原则上，你可以使用任何 SQL 包来满足你的 SQL 数据库需求。实际上，使用 SQL 存储数据的具体产品可能更适合（甚至需要）特定的包。Linux 中一些更常见的选择包括以下：

**MySQL** Sun 拥有此 SQL 实现，并已在 GPL 下发布。大多数主要 Linux 发行版的软件包数据库中都包含 MySQL。对于完整安装，你可能需要安装多个软件包，例如客户端、服务器以及可能的开发工具。你可以在 [http://www.sun.com/software/products/mysql/](http://www.sun.com/software/products/mysql/) 了解更多。

**PostgreSQL** 此 SQL 实现源自早期的 Ingres 软件（*PostgreSQL* 这个名字是 *post-Ingres SQL* 的压缩形式）。它可用在 BSD 许可证下，并且在大多数 Linux 发行版中作为多个软件包提供。与 MySQL 一样，你很可能必须安装客户端、服务器，也许还有额外的支持软件包。PostgreSQL 总部位于 http://www.postgresql.org。

**SQLite** 此软件包基于 http://www.sqlite.org，是一个实现 SQL 的库。因此，它不是一个独立数据库；相反，它旨在提供一种方式，让程序能够访问程序内的 SQL 数据库功能。如果你安装了一个使用 SQLite 的程序，你发行版的包管理器应该为你安装相关的库。如果你想编写一个需要数据库访问的程序，又不想安装完整的客户端-服务器 SQL 包（如 MySQL 或 PostgreSQL），SQLite 可能正是你需要的。

还有几十个其他的 Linux SQL 数据库产品。为了学习 SQL，MySQL 或 PostgreSQL 应该就可以了，或者如果你愿意，可以使用另一种完整的实现。不过，如果你使用 SQL 有特定目的，你应该更深入地研究 SQL 包。你可能需要特定的产品以与其他软件兼容，或者可能需要提供特定功能的 SQL 包。Linux+ 目标仅按名称提及了 MySQL。

正如刚提到的，一些 SQL 软件包，包括 MySQL 和 PostgreSQL，采用客户端-服务器模型：一个程序（服务器）管理数据库，而另一个（客户端）为用户提供对数据库的访问。此类实现可以工作在网络上，使得多个客户端系统的用户能够访问集中的数据库服务器。

### 使用 MySQL

为了学习 SQL，你应该能够访问一个 SQL 数据库。为了演示目的，我使用 MySQL 作为参考。其他 SQL 实现与我这里描述的相似，但有些细节不同。从管理角度来看，你需要知道如何设置 MySQL 配置选项，如何启动和停止服务器，以及如何测试其是否正常工作。实际上，使用 MySQL 执行数据库查询是一个复杂的话题，超出了本书或 Linux+ 考试的范围。

#### 配置、启动和停止 MySQL

MySQL 的主配置文件名为 *my.cnf*，通常存储在 /etc/ 或 /etc/mysql/ 中。你应该浏览此文件以熟悉一些关键的 MySQL 选项。不过，除非你知道需要更改默认设置，否则你最初应该谨慎更改此文件的内容。
