

## 入侵检测

包嗅探器也是黑客中流行的工具。包嗅探器可以帮助入侵者发现用户密码和其他敏感数据。事实上，在许多组织中，使用包嗅探器可以成为纪律处分的理由。因此，尽管Snort是一个非常好且正当的工具，当正确使用它时，除非你有授权，否则你不应该安装和使用Snort。

除了作为通用的包嗅探器功能外，Snort还可以作为**入侵检测系统（IDS）**发挥更复杂的作用。IDS是一个监控网络流量以检测可疑活动并向管理员发出警报的程序。换句话说，IDS是一个能够识别表明攻击正在进行的活动的包嗅探器。

安装Snort的第一步是决定将其放在哪里。图12.3展示了几个可能的位置。在这个图中，Snort系统#1可以监控来自或发往整个互联网的流量，而Snort系统#2可以监控本地流量。两者都有机会捕捉到针对特定本地计算机的外部攻击，但系统#1会对被防火墙阻止的攻击敏感，而系统#2则会对纯粹的本地攻击敏感。此外，系统#2需要本地使用集线器而非交换机，或者使用编程为将所有流量回传给Snort系统#2的交换机；没有这种配置的交换机将向Snort系统隐藏本地计算机之间的大多数流量，使其无用。

大多数现代Linux发行版都附带Snort，因此你应该能够以通常的方式安装它。一旦安装，Snort通过/etc/snort.conf文件进行配置。（有些发行版不提供此名称的文件，但提供名为snort.conf.distrib或其他变体的文件。你可以复制或重命名此文件，并用作可修改的模板。）默认的snort.conf文件可能工作得不错，但你可能想要自定义几个变量，例如$HOME_NET、$SMTP_SERVERS和$HTTP_SERVERS。其中第一个指定要监控的IP地址。其他变量定义特定类型服务器的IP地址。默认值告诉Snort监控所有IP地址，这可能没问题，因为你可能希望Snort监控其本地网络上的所有流量，这是它通常能够看到的全部。

一些发行版将一系列辅助的Snort配置文件放在/etc/snort目录中，这些文件以.rules结尾。这些规则文件定义了Snort应视为可疑的包类型。大多数协议都有一个.rules文件，例如用于SMTP包的smtp.rules。这些.rules文件通过主snort.conf文件中的include指令引用，因此请确保你的主snort.conf文件加载了适合你网络的适当规则。如果你没有看到你想监控的协议的.rules文件，请检查[http://www.snort.org/snort-rules/](http://www.snort.org/snort-rules/)。该网站托管了许多针对不太流行协议的Snort .rules文件。

要启动Snort，输入其命令名：snort。程序运行并将其输出记录在位于/var/log/snort的文件中。这些日志文件记录可疑包的信息。你应该确保定期监控这些日志文件。为了永久启动Snort，你可以从启动脚本运行它。事实上，许多发行版提供SysV启动脚本来启动Snort。

> Snort不需要IP地址来监控网络流量。因此，你可以配置一个专用的Snort系统，带有网络驱动但没有IP地址，用它来监控网络流量。这种配置使Snort监控器对来自外部的攻击具有极强的抵抗力，因为攻击者无法直接寻址该系统。缺点是，你必须使用Snort系统自己的控制台或RS-232串行链接来监控其活动。

## 使用 PortSentry

另一个IDS是[PortSentry](http://sourceforge.net/projects/sentrytools/)。PortSentry的基本思想与Snort类似，因为两者都旨在提醒你注意可疑的网络活动。一个关键区别是PortSentry运行在个人计算机上以监控对其自身端口的访问尝试，而Snort可以监控整个网络。另一个区别是PortSentry可以主动阻止网络扫描。事实上，从某种意义上说，PortSentry更像是一个防火墙而不是IDS。

安装PortSentry（通常来自名为`portsentry`的包）后，你可以通过其`portsentry.conf`文件进行配置，该文件通常位于`/etc`或`/etc/portsentry`中。你使用`TCP_PORTS`和`UDP_PORTS`选项指定你想要PortSentry监控的端口，这两个选项都指定逗号分隔的端口列表。PortSentry绑定到这些端口，记录访问它们的尝试，并可以基于PortSentry配置文件中的其他选项采取各种可选操作。这些操作可以包括忽略访问尝试、运行外部程序、从路由表中丢弃路由等等。

## 使用 Wireshark

Wireshark (<http://www.wireshark.org>)，以前称为Ethereal，是另一个包嗅探器。虽然Snort和PortSentry是流行的IDS，但Wireshark更常被用作网络诊断工具。它具有对网络包的深入分析功能，这意味着程序可以帮助你挖掘网络包，发现它们携带的含义，从而让你能够追踪网络问题——例如，由于协议版本不匹配导致的认证失败、拼写错误的密码、丢失的包或其他问题。

> **警告**
> 就像Snort一样，Wireshark也可能被滥用。在使用它之前，请从上级那里获得书面许可，以免违反禁止未授权使用包嗅探器的政策。

使用Wireshark最基本的方法是通过`tshark`命令，默认显示程序截获的原始包数据：

```
# tshark
  Running as user 'root' and group 'root'. This could be dangerous.
  Capturing on eth1
       0.000000 08:10:74:24:1b:d4 -> Broadcast ARP Who has 192.168.1.1? Tell 192.168.1.254
     0.308644 192.168.1.8 -> 192.168.1.2 SSH Encrypted response packet len=128
     0.308721 192.168.1.8 -> 192.168.1.2 SSH Encrypted response packet len=48
```

这个例子（被截断；实际输出将无限期继续）显示了一个地址解析协议（ARP）广播，后跟两个SSH包。如果你想限制Wireshark的输出，你可以使用非常广泛的`tshark`选项做到这一点。查阅其man页面以获取详细信息。

你可能会发现通过GUI界面使用Wireshark更容易，它通常作为与主Wireshark包分离的包安装。例如，在Fedora上，你必须安装`wireshark-gnome`。然后你可以输入`wireshark`来启动主要的Wireshark GUI程序。点击Capture > Start开始捕获所有流量。（你可以通过使用Capture > Capture Filters选项来限制捕获的内容。）点击Capture > Stop终止捕获操作。结果类似于图12.4。此窗口有三个窗格。顶部窗格提供每个网络包的摘要，中间窗格提供在顶部窗格中选择的包的特定于协议的分析，底部窗格显示原始包数据。

## 使用 Tripwire

监控网络流量是检测不良活动的有用策略，但并不能保证检测到入侵者。例如，黑客可能正在使用来自授权位置的授权协议，因此入侵尝试不会触发Snort或PortSentry中的任何触发器。如果有人设法闯入你的计算机，[Tripwire](http://www.tripwire.org) 可能是你检测这一事实的最佳选择。这个实用程序记录关于计算机上所有重要文件的一组信息，包括各种类型的校验和（checksums）和哈希值——简短的数字“签名”，使你能够快速确定文件是否已被更改。（这些也可以用于其他方式；例如，Linux使用哈希值来存储密码。）将此数据库存储在安全位置后，你可以定期检查系统是否被修改。如果入侵者修改了你的任何文件，Tripwire将提醒你这一事实。如果愿意，你可以定期运行Tripwire验证——例如，每周通过cron作业运行一次。
