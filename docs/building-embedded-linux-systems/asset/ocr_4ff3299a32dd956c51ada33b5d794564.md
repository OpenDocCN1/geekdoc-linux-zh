*strace* is available at <http://www.sourceforge.net/projects/strace> under a BSD license. For our target application, we used *strace* version 4.5. Download the package and extract it in your $/PRJROOT/</span><span class="=">debug</span> directory. Move to the package’s directory, and then configure and build *strace*:

```
$ cd $(PRJROOT)/debug/strace-4.5
$ architecture-linux-gcc ./configure --host=iTarget
$ make
```

If you wish to statically link against uClibc, add LDLGFLAGS="-static" to the <span class="=">make</span> command line. Because <span class="=">strace</span> uses NSS, you need to use a special command line if you wish to link it statically to glibc, as we did previously for other packages:

```
$ make \
  > LDLIBS="-static -lI -lstart-group -Ic -Iins_files -Ins_dns \
  > -Iresolv -lI -lend-group"
```

When linked against glibc and stripped, <span class="=">strace</span> is 145 KB in size if linked dynamically and 605 KB if linked statically. When linked against uClibc and stripped, <span class="=">strace</span> is 140 KB in size if linked dynamically and 170 KB if linked statically.

After compiling the binary, copy it to your target’s root filesystem:

```
$ cp strace $(PRJROOT)/rootfs/uzr/sbin
```

No additional steps are required to configure <span class="=">strace</span> for use on the target.

# ## System Tracing

One of the main system tracing utilities available for Linux is the next generation Linux Trace Toolkit (<span class="=">LTTng</span>) created and maintained by Mathieu Desnoyers (also author of the kernel markers infrastructure), inspired by Karim Yagmour’s original <span class="=">LTT</span> tool. <span class="=">LTTng</span> is available under the GPL, along with various other tools and utilities such as the <span class="=">LTTV</span> viewer. You can download <span class="=">LTTng</span> and sign up to the user or developer mailing lists for these tools at the <span class="=">LTTng</span> website: <http://ltt.polymtl.ca>.

In contrast to other tracing utilities, such as <span class="=">strace</span>, <span class="=">LTTng</span> does not use the <span class="=">ptrace()</span> mechanism to intercept applications’ behaviors. Instead, it includes a kernel patch that instruments key kernel subsystems. The data generated by this instrumentation is then collected by the trace subsystem and forwarded to a trace daemon to be written to disk. The entire process has very little impact on the system’s behavior and performance. Extensive tests have shown that the tracing infrastructure has marginal impact when not in use, and an impact lower than 2.5 percent under some of the most stressful conditions.
