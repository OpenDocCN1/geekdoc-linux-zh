
# Appendix A m4 Macro Command Reference

**FEATURE** (always_add_domain) This feature adds the hostname of the system to all local mail. With this feature enabled on a server named ibis.foobirds.org, mail from the local user craig to the local user kathy was delivered as mail craig@ibis.foobirds.org to kathy@ibis.foobirds.org.

**FEATURE** (bestmx_is_local) With this feature, mail addressed to any host that lists the Sendmail server as its MX server is accepted by the Sendmail server as local mail.

The Dns macros are:

- CANONIFY_DOMAIN(domain) This macro defines a domain name that will be passed to DNS for its canonical form if the canonify feature is in use. Computers can be known by aliases. The official domain of a host stored in DNS is called its canonical name. This macro is generally used to enable canonification of the local domain when canonify is in use.
- CANONIFY_DOMAIN_FILE(filename) This macro identifies a file containing a list of domain names that should be converted to canonical form if canonify has selected.

- LOCAL_DOMAIN(alias-hostname) This macro defines an alias for the local host. Mail addressed to the alias will be accepted as if it were addressed directly to the local host.

The macros and features described in this section are not limited to the DOMAIN source file. They can appear in any m4 source file, and, in fact, are often found in the macro control file. I listed them because they are most naturally associated with the DOMAIN file. I took my cue in this from the documentation in the cf/cf/README file.

# MAILER

MAILER macro points to an m4 source file that contains the configuration commands that define a Sendmail server. A least one MAILER command must appear in the configuration file. Generally, more than one MAILER command is used.

It is possible that you will need to customize a file in an OSTYPE file or that will need to define domain-specific information in a DOMAIN file, but unless you develop your own mail delivery program you will not need to create a MAILER source file. Instead, you will need to invoke one or more existing files in your macro configuration file.

Table A.5 lists each MAILER value and its function. These are invoked using the MAILER(value) command in the macro configuration (.mc).

# Table A.5 MAILER Values

| Name | Function |
|---|---|
| local | The local and prog mailers. |
| smtp | All SMTP mailers: smtp, smtp, smtp8, and relay. |
| uucp | All UUCP mailers: uucp-old (uucp) and uucp-new (uuccp). |
| usenet | Usenet support. |
| fax | Fax support using HylaFAX software. |
| pop | Post Office Protocol (POP) support. |
| procmail | An interface for procmail. |
| mail11 | The DECnet mail11 mailer. |
| phquery | The phquery program for CCSO phone book. |
| qpage | The QuickPage mailer used to send e-mail to a pager. |
| cyrus | The Cyrus and cyrusbb mailers. |

Your macro configuration file should have a MAILER(local) and a MAILER(smtp) entry. Selecting local and smtp provides everything you need for a standard TCP/IP installation. The others are:

**uucp** This provides UUCP mail support for systems directly connected to UUCP networks. The uucp-old mailer supports standard UUCP mail and the uucp-new mailer is used for sites that can handle multiple recipients in transfer. Specify MAILER(uucp) after the MAILER(smtp) entry if your system has both TCP/IP and connections.

**usenet** This mail sends local mail that contains group.usenet in the recipient name to the program news. Most current user mail agents support Usenet directly and most users already have a favorite news post. Posting news through Sendmail with the group, **usenet** syntax is not common.

**fax** This is an experimental mailer that supports the HylaFAX software. The fact that this software has been described as experimental for a number of years makes me think that it is not widely used.

**pop** This mailer supports the Post Office Protocol. On Linux systems, POP support is provided by a specialized POP mail daemon, the MAILER(pop) command is not needed or used.

**procmail** This mailer provides a procmail interface for the mailertable. Even though procmail is used as the Linux local mailer, the MAILER(procmail) command is not required. See the discussion of procmail in Chapter 11.

**mail11** This is an obsolete mailer that was used only on DCNet mail networks that used the mail111 mailer.

**phquery** This mailer provides CCSO phone book (ph) directory service using the phquery program. User directory services are usually configured in the user mail agent, not in Sendmail.

**cyrus** This mailer provides a local mail delivery program that uses a mailbox architecture. It permits the user+detail address syntax where detail is interpreted as a mailbox name. Despite some advanced features, cyrus and cyrusbb mailers are not widely used.

**qpage** This mailer provides an interface from e-mail to payers using the QuickPage program.

Not everything about mailers is defined in the source files loaded by the MAILER commands. We have already seen that some define commands relating to mailers are specified in the OSTYPE source file. Additionally, you can define your own mailers.

# Local Code

There are several macros that allow you to put sendmail.cf. These macros are:

- LOCAL_RULE LOCAL_RULE_n heads a section of ruleset, where n is 0, 1, 2, or 3.
- LOCAL_CONFIG LOCAL_CONFIG heads a section of code to be added to sendmail.cf.
- LOCAL_RULESETS LOCAL_RULESETS heads a section of code to be added to sendmail.cf. Generally, these are named as opposed to numbered rulesets.
- LOCAL_NET_CONFIG This macro defines how the local network is handled.
- MAILER_DEFINITIONS MAILER_DEFINITIONS This macro is placed before the sendmail.cf.

# DAEMON_OPTIONS

The DAEMON_OPTIONS macro defines parameters for the Sendmail daemon when it is acting as MTA and when it is acting as MSA. (See Chapter 2, “Understanding E-Mail Architecture,” for information about the purpose of an MTA and an MSA.) DAEMON_OPTIONS commands need to be set the parameters for both the MTA and the MSA. The Sendmail configuration defaults to the following values:

```
DAEMON_OPTIONS(`Port=25, Name=MTA`)
```

```
DAEMON_OPTIONS(`Port=587, Name=MSA, M=E`)
```

These two lines assign the standard ports to the MTA and the MSA, and a modifier to the MSA. Use the no_default feature to clear the MSA defaults before you set new MSA values with the DAEMON_OPTIONS.

DAEMON_OPTIONS parameters are assigned using keyword=value pairs. The possible keys and values are listed below:

- Port Port identifies a network port number to the daemon. The standard port for an MTA is 25 and the standard port for an MSA is 587. Changing these standard ports means that clients will have difficulty locating the service. The port numbers are therefore rarely changed.
- Name The Name identifies the Sendmail daemon for which the parameters are set. There are four documented values:
- MTA This identifies the Mail Transport Agent interface of Sendmail that is used to deliver mail.
- MSA This identifies the Mail Submission interface of Sendmail that can be used by external MTAs to submit mail. In practice, this is functional to the MTA function, except for port number, because both aspects of Sendmail ensure that all mail, no matter how it arrives, is processed through all necessary rulesets, filters, and databases.
- MTA-v4 MTA-v4 is the same as the MTA interface and is designed to handle e-mail delivery to hosts with standard 32-bit IPv4 addresses.
- MTA-v6 MTA-v6 is an interface designed to handle delivery to hosts that use the 128-bit IPv6 addresses.
