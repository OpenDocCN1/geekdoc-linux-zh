Once the DNS zone has been created and a Sendmail configuration has been built using
the correct dns1 feature, the new configuration can be tested by running the sendmail
command with the -bt option. Listing 11.3 shows a test of the dns1.foobirds.
domain.

# 11.3 Testing the dns1 Feature

```
$ sendmail -bt -Ctest-dns1.cf
ADDRESS TEST MODE (ruleset 3 NOT AUTOMATICALLY invoked)
Enter <ruleset><address>
> .D(client_addr)172.16.12.1
> Basic_check_relay <>
rewrite: ruleset 19 input: < >
rewrite: ruleset 19 returns: OK
> .D(client_addr)192.168.72.37
> Basic_check_relay <>
rewrite: ruleset 19 input: < >
rewrite: ruleset 19 returns: <>
  $: $# error $# 5 . 7 . 1
  ': "550 Mail from '192 . 168 . 72 . 37
    rejected by blackhole site dns1.foobirds.org."
```

> <O

The client_addr variable normally contains the IP address of the remote system that in-
tiated the connection. Because there is a bt test, there is no mail connection involved,
so we use the .D command to place a value in the client_addr variable. Next, the
rules Basic_check_relay is run without any input address, which is why the address
focus characters <and> are used but do not enclose any value. The Basic_check_
relay rules does not process the address; it processes the address found in
client_addr. The first test returns OK, Next, the address 192.168.72.37 is stored in client
addr and rules Basic_check_relay is run again. This time the address is found in the
dns1.foobirds.org domain, and the Basic_check_relay returns the mes-
sage "550 Mail from 192.168.72.37 refused by blackhole site dns1.foobirds.org."
