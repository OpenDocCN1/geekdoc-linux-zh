Blank lines are ignored. Lines that begin with # are comments. Comments are invaluable aids to understanding the arcane sendmail.cf file. Lines that begin with the uppercase character are configuration commands. Listing 7.1 contains the commands D, C, F, and K.

The local information is defined by D commands that define macro variables, C commands that define class variables, F commands that load class values from files, and K commands that define databases of information. The sendmail.cf syntax is very terse. The commands are only one character long and many variables have one-character names. Add to this the fact that the value assigned to the variable is crammed right next to the variable and you have configuration commands that are terse and hard to read. Let’s take a closer look at the D, C, F, and K commands so that we decide what is happening in the Local Info section.

# The Define Macro Command

The define macro (D) defines a variable and assigns a value to it. Once the variable is defined, the store is used by other sendmail.cf commands and Sendmail itself provides the flexibility to permit the same sendmail.cf configurations to run on many different systems, simply by modifying a few specific macro variables.

Traditional variables are a single ASCII character, with user-created macro variables using uppercase letters as names and Sendmail macros using lowercase letters and special characters as names. These rules have changed. Now Sendmail defines the meaning of several variables with uppercase names, and Sendmail version 8 variables are not restricted to a single character. Long variables are enclosed in curly braces—e.g., {VrtHost} is a valid variable name. However, a quick check of the sendmail.cf delivered with the Red Hat RPM shows that not a single long variable name was used with a define macro command.
