One of the most useful things that the -bv option does is the input address through the aliases database. The test of MAILER-DAEMON shows. On this system MAILER-DAEMON is aliased to postmaster, which in turn is aliased to root. root is then aliased to craig. The address echoed back for the MAILER-DAEMON test is craig—the address after all aliasing has been performed.

The last two tests are interesting because they show how -bv can be used to test a new configuration. In this example, the client-one.cf file created in Chapter 9 using the nullclient feature is tested. The nullclient sends local mail to the MAIL_HUB server. The second test of craig and joe clearly shows this. In the first test, with the default configuration, these addresses are delivered on the local host by the local mailer. In the last two tests, these addresses are sent via the relay mail to foobirds.org, which in this example is the MAIL_HUB server. The -bv test is a simple and useful tool for testing a relay configuration.

The -C option is used in the last -bv tests to test a new configuration. If -C is not used, Sendmail uses the default sendmail.cf file. In Linux systems, the default sendmail.cf is found in either /etc or /etc/mail, depending on your configuration. Use -C to test a new configuration before you make your default sendmail.cf configuration.

Another command-line option that, like -bv, was used earlier in this book is -v. The -v option runs the sendmail in verbose mode.

# Running in Verbose Mode

Verbose mode is used in Chapter 1, "Internet Mail Protocols," to display the SMTP protocol interactions between two systems exchanging e-mail. In Chapter 1, we run the sendmail with the -v option for verbose output and the -t option so that we could type in the mail message from the terminal. It is not necessary to send a real message when all you want to observe the protocol interactions. For works as well as a real message.
