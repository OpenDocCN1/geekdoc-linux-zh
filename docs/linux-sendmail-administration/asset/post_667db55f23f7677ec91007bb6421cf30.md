
# The aliases Database 153

Aliases can be in a variety of formats to handle the various ways that e-mail is addressed to a user. The next three lines, which forward mail to norm@awk.foobirds.org, all illustrate that Mail is mapped to the alias norm, and the alias norm forwards mail to norm@awk.foobirds.org. This server will accept mail addressed in any of three different formats and make sure it gets to the correct recipient on the remote hawk.foobirds.org.

The last five lines have the same alias format: first name, last name. This format is a popular for e-mail addressing. When combined with an MX record in DNS that says this server is the mail changer for the entire domain, it creates the simplified mail-addressing schemes used at many organizations. Assume the MX record for the domain foobirds.org points to this server. Mail addressed to Rebecca.Hunt@foobirds.org would actually be delivered to beky@parrot.foobirds.org. Notice that e-mail aliases are not sensitive.

The aliases database is used on every system to specify how mail is forwarded. The aliases database handles mail forwarding for the entire system. It is also possible for individual users to define forwarding for their own mail in the .forward file. While the .forward file is not strictly a database, its close relationship to systemwide makes this a good time to take a quick look at the .forward file.

# Defining Personal Mail Aliases

As of the lines in the aliases file in Listing 6.5 illustrate, one of the main functions of the aliases file is to forward mail to other accounts or other computers. The aliases file, because it impacts the entire system, must be maintained by the system administrator. If, a user wants to set up forwarding for their account through the aliases file, they need to ask the system administrator for help. The .forward file, which can be created in any user's home directory, defines mail forwarding for an individual user and is completely under the control of the user. Often, the .forward file is the most convenient place to set up forwarding.

It is possible to use the .forward file to do something that can be done in the aliases file. For example, if Norman Edwards had an account on a system but didn't really want to read his mail on that system, he could create the following .forward file:

```
norm@awk.foobirds.org
```

The function of this entry is very similar to the norm alias line in Listing 6.5. It forwards all mail received in this user's account on the local system to the norm account at hawk.foobirds.org.

# Chapter 6 Using Sendmail Databases

However, simple forwarding is not the primary use for the .forward file. A much more common use for this file is to invoke mail processing before mail is delivered to your personal mail account. Chapter 11, "Stopping Spam," illustrates when procmail and mail filtering are discussed.

The aliases database and the .forward file are the default files used to process addresses. Sendmail will use both of these files if it finds them. There is no need to define them inside the Sendmail configuration; they are used by default. There is also an optional database that can be used to process users' addresses. It is the user database, and it is our next topic.

# The User Database

The user database is available to Sendmail only if Sendmail is compiled with the USERDB compiler flag and the user database is defined inside the Sendmail configuration using the USERDB_SPEC option. Listing 6.1 shows that the Sendmail delivered with the Red HAT RPM has the USERDB flag set, and in Chapter 5 we saw that the redhat.mc file contains the following define command:

```
define('USERDB_SPEC', '/etc/mail/userdb.db')
```

From these things, we know that we can use the user database on our sample Red Hat system. If your system doesn't meet both of these conditions, you can't use this database until you update the configuration.

Sendmail applies the user database to inbound mail after the aliases database and before the .forward file. Unlike the aliases and .forward files, the user database can also be applied to outbound mail to transform the sender address and, in effect, create a reverse alias. Listing 6.6 shows a realistic user database based on the last four lines of the aliases database in Listing 6.5.

# Listing 6.6 A Sample User Database File

```
[root] cd /etc/mail
[root]# cat userdb
andy.wright:maildrop andy
andy:mailname andy.wright@foobirds.org
sara.hhenson:maildrop sara
sara:mailname sara.hhenson@foobirds.org
kathy.McCafferty:maildrop kathy
kathleen.McCafferty:maildrop kathy
kathy:mailname kathleen.mccafferty@foobirds.org
[root]# makemap btree userdb.db < userdb
```

In Listing 6.6, we change to the /etc/mail directory and display the contents of the user database file we have created. Arbitrarily named this file userdb. Like the aliases file, the user database file must be converted to a true database before it can be used by Sendmail. The makemap command to build the database. The makemap program reads the standard input and writes out the specified database of type. The makemap command is fully described later in this chapter.
