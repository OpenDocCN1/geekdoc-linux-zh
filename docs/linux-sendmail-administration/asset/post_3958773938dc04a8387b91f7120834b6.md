In Listing 10.14, the address sara@foobirds.org is run through ruleset final, producing the output sara@foobirds.org. That is exactly what we expected, but address test mode shows the value that went into the ruleset and the value that comes out; it does not show any of the intervening data. From the =s command in Listing 10.13, we know that the final ruleset contains individual rules. With the default settings, we can't see the individual rules in action. Therefore, we use the -d21 command to set the debug level to 1. A second test is where the address@foobirds.org is run through ruleset. The time of each rewrite rule is displayed. Sendmail displays the string trying rule: followed by the pattern field of the rule. If the address does not match the pattern, Sendmail displays the string rule fails and moves to the next rule. If the address matches, Sendmail prints the string rule matches: followed by the template from the rule, and then prints the rewrite. It keeps on this manner until the ruleset has been run or a rule has been encountered that causes Sendmail to exit the ruleset. This level of detail is probably needed only when you're debugging a ruleset that you have written that does not perform as you expect.
