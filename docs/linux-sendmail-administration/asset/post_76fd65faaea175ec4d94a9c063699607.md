- NEWDB This option adds the database support used on Linux systems. It provides hash and btree databases. This option provides all you need to build and access most local Sendmail databases.

- MAP_REGEX This option adds a new feature to Sendmail that permits databases to be searched with regular expressions. Anyone who has used regular expressions with grep knows they are much more powerful than simple wildcard characters. This added power is useful when you need to create complex rules to block spammers.

- USERDB This option supports for the user database, which can be used to process e-mail on inbound and outbound e-mail. A related option is UDB_DEFAULT_SPEC, which defines the default path to the user database. The path can also be set with the CONFUSERDB_SPEC in the Sendmail configuration, as we saw in the redhat.file in Chapter 5, "Understanding a Vendor's Configuration." I prefer setting the path value in the configuration instead of compiling it into Sendmail because it is easily changed when it is in the configuration. However, some path value must be explicitly defined before Sendmail can use the user database.

- NIS This option provides access to Network Information System (NIS) databases. These are administrative databases, such as /etc/mail/aliases and /etc/hosts, stored on the NIS server. The related database options NISPLUS and YCOMPAT are rarely used in Linux systems. NIS+, which is an upgraded version of NIS, is not used in Linux environments; YCOMPAT creates compatibility with a version of NIS that has not been produced in several years. YCOMPAT permits use of "plus syntax," in which a+ is placed at the end of a local administrative database to tell the system to first search the local database and then search the database on the NIS server. With, YCOMPAT and a + at the end of the /etc/mail/aliases database, Sendmail first checks the local aliases database and then checks the NIS server, it without the outdated syntax (Details of setting up an NIS server on a Linux system are covered in the Linux DNS Server Administration book of this series.).

To force Sendmail to use these database options, you could either edit the devtools/OS/linux.m4 file or create a file in the devtools/Site directory that contains the following line:

```
define(`confDEFMAP`, `-NEWDB -NIS -DMAP_REGEX -DUSERDB`)
```

# Configuration Options

The configuration used to add support for Sendmail databases is the next topic. As noted at the beginning of this section, the aliases database is the only database that is available to Sendmail by default. All of the other databases described in this chapter must be added to the Sendmail configuration before they can be used. The following defines and features are used as important:

- define(`CONFUSERDB_SPEC`, `path`) The CONFUSERDB_SPEC option tells Sendmail to apply the user database to local addresses after the aliases database is applied and before the forward file is applied. The path argument given with this option is the full pathname of the database. There is no default for the path unless Sendmail is compiled with USER_DEFAULT_SPEC. Setting the path with CONFUSERDB_SPEC is much simpler and more flexible than using USER_DEFAULT_SPEC, which can be found in /etc/mail/userdb.db.

```
define(`CONFUSERDB_SPEC`, `/etc/mail/userdb.db`)
```

- define(`CONFFILE`, `path`) The CONFFILE option tells Sendmail to add the list of hosts to permit relay from the specified file to the variable. The full pathname of the file can be provided as an argument. If the pathname is not provided, it defaults to /etc/mail/relay-domains.

- FEATURE(`use_ct_file`, `path`) The use_ct_file feature tells Sendmail to add trusted users from the file to the variable t. The full pathname of the file is an optional argument. If the pathname is not provided, it defaults to /etc/mail/trusted-users.

- FEATURE(`use_cw_file`, `path`) The use_cw_file feature tells Sendmail to add hostname aliases from the file to the variable w. The full pathname of the file is an optional argument. If the pathname is not provided, it uses /etc/mail/local-hostnames.

# Adding Database Support

- FEATURE(`access_db`, `specification`) The access_db feature tells Sendmail to use the access database to control mail relaying and mail delivery from the source of the mail. An optional database specification can be provided to define the database type and the full pathname of the database. By default, the database type is hash and the database path is /etc/mail/access.

- FEATURE(`mailertable`, `specification`) The mailertable feature tells Sendmail to use the mail table to map the domain name in a delivery address to a specific mailer and host for delivery. An optional database specification can be provided to define the database type and the full pathname of the database. By default, the database type is hash and the database path is /etc/mail/mailertable.

- FEATURE(`virtertable`, `specification`) The virtertable feature tells Sendmail to use the virtertable database to map the recipient address in incoming e-mail to a different recipient address. This function is similar to the one performed by the aliases database, except that the virtertable aliases names, not just usernames. An optional database specification can be provided to define the database type and the full pathname of the database. By default, the database type is hash and the database path is /etc/mail/virtertable.

- FEATURE(`genericable`, `specification`) The genericable feature tells Sendmail to use the genericable database to map the sender address outbound to a different sender address. An optional database specification can be provided to define the database type and the full pathname of the database. By default, the database type is hash and the database path is /etc/mail/genericable.

- FEATURE(`domaintable`, `specification`) The domaintable feature tells Sendmail to use the domain table to map one domain name to another. An optional database specification can be provided to define the database type and the full pathname of the database. By default, the database type is hash and the database path is /etc/mail/domaintable.

- FEATURE(`uucpcdomain`, `specification`) The uucpcdomain feature tells Sendmail to use the uucpcdomain database to map UUCP sites to Internet domain names. An optional database specification can be provided to define the database type and the full pathname of the database. By default, the database type is hash and the database path is /etc/mail/uucpcdomain.

By default, the database type is hash and the database path is /etc/mail/bitdomain.
