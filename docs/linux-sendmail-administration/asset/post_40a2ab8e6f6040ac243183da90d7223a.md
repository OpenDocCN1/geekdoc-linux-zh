## The mailq Command

The -bp option, which is also known as the mailq command, displays the contents of the mail queue. If no mail is queued, it simply prints the pathname of the queue directory and declares it empty, as shown below:

```
[root]# mailq
/var/spool/queue is empty
```

An empty queue is a good thing. Everything is running smoothly and all of the mail by your users has been delivered. But things do not always run smoothly. As we saw in Listing 10.4, a remote host might be down or unreachable and the mail must be queued for later delivery. Listing 10.5 shows a mailq run that reports a piece of mail in the queue.

### Listing 10.5 A sample mailq Report

```
[root]# mailq
/var/spool/queue (1 request)
--Q-ID-----Size------Q-Time-------------Sender/Recipient-----
eA1Cej50074 1190 Wed Nov 1 07:04 craig
(Deferred: goat.mammals.org.: Network is unreachable)
sara@goat.mammals.org
```

The first line of output from the mailq command prints the pathname of the queue and the number of items found in the queue. In this case, one item is found in the queue, therefore mailq displays the "1 request." This is followed by a header line that defines the four fields found in a standard mailq report:

- Q-ID: The first field is the unique queue identifier assigned to this piece of mail. The identifier is composed of a character string followed by the process ID (PID) of the process that originally attempted to deliver this mail. In Listing 10.5, the string eA1Cej5 is combined with the PID 00742 to create a unique identifier.

### Simple Command-Line Options 277

Option, a single character indicates a special status for this piece of mail can follow the queue identifier. There are three possible single character values:

- +: indicates that the queue file containing the mail is locked by a valid file-locking mechanism.
- *: indicates that the MinQueueAge option has been set in the Sendmail configuration, and that piece of mail has not been queued long enough to meet the MinQueueAge requirement. The MinQueueAge sets the minimum amount of time a message must remain in the queue. It tells Sendmail not to deliver messages that fall below this minimum when Sendmail processes the queue. By default, this option is commented out of the sendmail.cf file and Sendmail delivers all of the messages from the queue that it.
- X: indicates that the load of the server is currently too high to deliver this piece of mail.

- Size: The second field contains the size of the mail message in bytes. In Listing 10.5, the message is 1190 bytes.

- Q-Time: The third field contains the date and the time that the message first entered the queue, displayed in a simple, straightforward manner.

- Sender/Recipient: At a minimum, the fourth field contains the address of the sender and the address of the recipient of this piece of mail. Usually, this field has more information than just the addresses. The field begins with the sender address. In Listing 10.5, the sender address is creat. This is followed by the MIME message body, if the message contains special MIME data. In Listing 10.5, no message body is listed, so it is a traditional text message in an RFC 822 format. After the message body is listed, mailq displays the error message associated with the last delivery attempt in parentheses, if the queue file has a copy of the error message. In Listing 10.5 it is Deferred: goat.mammals.org : Network is unreachable. The fourth field ends with the recipient address, which in Listing 10.5 is sara@goat.mammals.org.

The amount of information displayed by mailq is increased slightly if the -v option is added to the command line. When mailq is run in verbose mode, it adds a Priority field between the Size and Q-Time fields. The Priority field lists the queue priority of the message calculated by Sendmail. The numeric priority value may be ended with an optional +. The + indicates that a warning message about the delivery failure has been sent to the originator of the message.
