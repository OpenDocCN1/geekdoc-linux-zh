Readers who use include commands in other languages generally think the include command can be done to separate a complex configuration into several files and then bring those files together for processing. While that is true for m4 in general, it is not true for Sendmail configuration. All macro configuration files are short files that do not benefit from being segmented. The only time you'll use include in the files provided with the Sendmail distribution is when cf.m4 itself includes the large and complex chead.m4 file. And the only time you will include is when you want to include the cf.m4 file into your macro configuration file to simplify the m4 command line.

The LOCAL_CONFIG, LOCAL_RULESET, and LOCAL_RULE_n commands allow you to put raw sendmail.cf configuration directly in the m4 source file. These commands, and other related commands, mean that everything that can be done in the sendmail.cf can be done in the m4 macro source files (sendmail.cf configuration commands are discussed in Chapter 7). We use the LOCAL_CONFIG, LOCAL_RULESET, and LOCAL_RULE_n commands several times in this text to define sendmail.cf.

The MODIFIER_MAILER_FLAGS flag is used to override the flags for a mailer. Mailer flags are described in Chapter 7, "Sendmail.cf File," and for listing of all of the mailer flags is found in Appendix C, "Sendmail Variables, Options, and Flags." The MODIFIER_MAILER_FLAGS command has two arguments: the name of the mailer and the flag to be modified. The flag is preceded by a + if it is to be added to the existing set of flags or by a - if an existing flag is to be removed.

The MASQUERADE_AS and EXPOSED_USER commands both deal with masquerading. Frequently, an organization wants all of its outbound mail to appear as if it came from one source and to hide the names of internal systems that are not directly receiving. Masquerading is the name for this type of mail rewriting. MASQUERADE_AS defines the hostname that is used as the hostname par. If MASQUERADE_AS=('foobirds.org') is set in the configuration, mail from craig@wen.foobirds.org goes out as mail from craig@foobirds.org.

EXPOSED_USER addresses a problem created by masquerading. Assume that mail from root@wen.foobirds.org and root@ibis.foobirds.org is passed through the server with the MASQUERADE_AS=('foobirds.org') setting. If both addresses are rewritten to root@foobirds.org, you have a problem. There is no way for the recipient to know exactly where the message originally originated, and the remote user could not reply to the correct address.
