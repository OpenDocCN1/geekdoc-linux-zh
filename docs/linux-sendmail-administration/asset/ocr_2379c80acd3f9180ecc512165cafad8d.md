# Chapter 6 Using Sendmail Databases

The genericstable database has one small feature not found in the user database. It can accept +detail syntax in the original address and the detail part of the address as %1 to the output address, in the following manner:

```
sales+@insects.org    %1sales.insects.org
```

Of the course, +detail syntax is only important if you actually use it, and it is rarely used. If a domain name is included in the first part of a genericstable entry, then domain name must be defined in class G. Values are stored in class G using the GENERIC_DOMAIN macro or they can be loaded into class G from the file identified by the GENERIC_DOMAIN_FILE. For example, the following command stores the domain name insects.org in class G:

```
GENERIC_DOMAIN(`insects.org`)
```

While the next command loads G from a file named /etc/mail/generics-domains:

```
GENERIC_DOMAIN_FILE(`/etc/mail/generics-domains`)
```

The domain names in G normally ensure each match. Using the GENERIC_DOMAIN() macro shown above, user@insects.org would match the requirements by class G but user@fly.org would not match, even though fly.insects.org is part of the insects.org domain. To Sendmail to match all hosts and subdomains within a domain defined in class G, use FEATURE(`generics_entire_domain`).

The similarities between the user database and the genericstable database mean that you can use either one of these databases to rewrite sender addresses. The syntax of genericstable entries is a little simpler because genericstable does not use keywords like mailname. But the genericstable only handles sender addresses. Recipient addresses must be handled in a separate database, /etc/aliases or the user database. Administrators like the similarity of the genericstable database; prefer the user database so they can have everything in one file. It is primarily a matter of taste. Both files work in the same way.

I generally prefer use aliases for recipient addresses and the genericstable for sender addresses because that's what I use. I have several configurations already set up this way. However the redhat.mc file does not have genericstable support in the configuration. To use genericstable with that configuration, I must add FEATURE(`genericstable`) command to the macro configuration and rerun m4 to build a new sendmail.cf file. In the case of the redhat.mc configuration, it is probably just to use your user database.
