
The sendmail.cf file is created from a macro configuration (.mc) that usually contains fewer than 20 lines of m4 commands. The m4 commands that you will use to build a basic sendmail configuration are listed in Table 4.1.

## Table 4.1 Common m4 Commands

| Command | Usage |
| --- | --- |
| define | Defines a value for a configuration variable. |
| divert | Directs the output of the m4 process. |
| dn | Deletes all characters up to, and including, next newline character. |
| DOMAIN | Selects a file containing attributes for your specific domain. |
| FEATURE | Identifies an optional Sendmail feature to be included in the configuration. |
| MAILER | Identifies a set of mailers to be included in the sendmail.cf file. |
| OTYPE | Selects a file containing operating system-specific attributes. |
| undefined | Clears the value set for a configuration variable. |
| VERSIONID | Defines version control information for the configuration. |

The commands shown in Table 4.1 are the most commonly used m4 macro commands. All of the commands shown in uppercase are macro commands defined in cfhead.m4 file. The commands shown in lowercase are built-in m4 commands. The subset of commands shown in Table 4.1 is all you need to build a basic configuration. As such, they deserve a more thorough explanation.

## Controlling m4 Output

The m4 program is a stream-oriented processor. It views the data it handles as a stream of text characters. It collects input data from various files, expands macros embedded in those files, and directs the output stream of characters to another file. Two of the commands in Table 4.1 are used to control the stream of output characters: *divert* and *dn*.

The divert command directs the output stream to different targets. As of Sendmail 8.11, there are 11 different targets for the data stream. The 11 possible divert values are listed in Table 4.2.

## Table 4.2 Possible Values for the divert Command

| Value | Meaning |
| --- | --- |
| -1 | Discard this output. |
| 0 | Send this data through normal processing. |
| 1 | Use this data for hostname resolution. |
| 2 | Add this data to rules 3. |
| 3 | Add this data to UUCP-specific sections of rules 0. |
| 4 | Use this data to define domain names this server will relay. |
| 5 | Add this data to the Local Info section of the sendmail.cf file. |
| 6 | Save this data as a mailer definition. |
| 7 | Use this data to define a spammer blacklist. |
| 8 | Add this data to rules 1 or 2. |

Most of the values that can be specified with divert are used only by the Sendmail developers. They are used, in essence, as buffers to hold data for specific parts of the sendmail.cf file. The data is collected in these buffers and then moved to the sendmail.cf file in the final stage of processing. It is possible to use any of these values in a configuration, and unlike unnecessary commands exist to send data to the correct buffers without resorting to divert commands. For any reasonable configuration, the divert command is used with only two settings:

- divert is set to -1 to discard the output. divert(-1) is found at the start of a block of text that is not to be written to the sendmail.cf file. While the block of text could be anything that's not intended for the output file, it is usually the copyright statement that is found at the beginning of many of the configuration files. The divert(-1) command at the start of the copyright means that the copyright is treated as a large comment.

- divert is set to 0 to direct the stream to the output file—e.g., sendmail.cf. If the divert(-1) command is used at the start of a large comment, divert(0) is used at the end of the command to redirect the stream to the output file.

The dn command is also used to control the output stream. The dn command accepts no arguments. Its two basic functions are determined by its position on the command line:

- If the dn command occurs at the end of a line, after another m4 command, it is used to clean up unwanted blank lines from the output file. For example, on the line OSTYPE(linux)dn ensures that any extraneous output generated after the linux OSTYPE macro expands not get written to the sendmail.cf.

- If the dn command occurs at the beginning of the line, it is treated as a comment. For example, the line dn define the domain is a comment. If the sample line did not begin with dn, m4 would interpret “define” and “domain” as m4 commands. Messy! Always start each comment with dn, unless it is a large comment bracketed by divert commands.

The divert and dn commands direct m4 output but they do not define or generate the output data. The other m4 commands are used to generate the actual configuration file.

## The Basic Commands

In terms, there are two types of files used to build an m4 configuration. One of these is the macro configuration file, which is traditionally identified by the .m4 extension. The macro configuration file is the input file for the m4 command, and its name appears on the m4 command line. The other files are m4 source files that are referenced by the macro configuration file. Traditionally, m4 source files are given the .m4 extension. Almost all the commands from Table 4.1 can appear in either type, although three of them are generally found only in macro configuration:

OSTYPE The OSTYPE macro is required, and is always found in macro configuration. The only argument passed to OSTYPE is the name of the file. The Sendmail distribution provides more than 40 system-specific files, and you can create your own for Linux. Here is the command that processes linux:

```
OSTYPE(linux)
```

## The m4 Macro Language

DOMAIN The DOMAIN macro loads a file that contains information specific to your domain. The file is a perfect place for commands that affect hostnames and domain names, and define values such as relay names that are specific to your network. Because the information is specific to your domain, you must create your own file. The Sendmail code distribution provides a sample generic.m4 that you can use as a starting point. Assume you created a file you called foobirds.m4. The following command, placed in configuration file, uses foobirds to help in building:

```
DOMAIN(foobirds)
```

THE MAILER command is optional. When it is used, it normally appears only in macro configuration.

MAILER The macro identifies the various sets of mailers that should be included in the sendmail.cf file. A usable configuration must have at least one MAILER; almost every configuration has at least two:

MAILER(local1) The MAILER(local1) command adds the local1 mailer and the prog mail to the configuration. The local1 and prog mailers are essential, so any usable configuration will have at least this MAILER command.

MAILER(smtp) The MAILER (smtp) macro adds mailers for SMTP, Extended SMTP, eight-bit SMTP, directed delivery SMTP, and relayed mail. Every system that sends SMTP mail, whether directly or through a mail server, has this MAILER command.

In addition to two important sets of mailers, there are nine other sets of mailers available with the MAILER command. Most of them are of little interest to the average system administrator; they are all covered in Appendix A.

OSTYPE, DOMAIN, and MAILER are generally found only in macro configuration. The other four commands like it are found in both macro configuration and macro source files:

VERSIONID The VERSIONID macro defines version control information. This macro is optional, but is found in most m4 files. The command has no required format for the argument. Use any version control information you desire. The basic format of the VERSIONID macro is:

```
VERSIONID(`version-control-data`)
```
