
Another level of aliasing occurs after the recipient is processed through the aliases database. The aliases database defines mail forwarding for the entire system. The .forward file, which can be created in any user's home directory, defines mail forwarding for an individual user. Sendmail identifies the user to whom the mail will be delivered, or looks for a .forward file in the user's home directory. If the .forward file is found, the mail is forwarded to the e-mail address contained in that file. If the file is not found or empty, the mail is delivered directly to the user's account.

> NOTE The aliases database, the local-host-names file, and the .forward file are all described in Chapter 6, “Using Sendmail Databases.”

The Sendmail terms “forwarding” and “relaying” are often used interchangeably, but there is a slight difference. Referring refers to the act of transferring to another host mail that was originally addressed to the local host. For example, if mail addressed to norm the local host is sent to normane@hawk.foobirds.org as a result of aliasing, you would say the mail has been forwarded to hawk.foobirds.org. Relaying, which is next topic, is subtly different.

## Mail Relaying

Relaying occurs when mail is transferred toward its destination and neither the source or the destination address of the mail is the address of the local system. For example: If a server named wen.foobirds.org receives mail from ibis.foobirds.org that is addressed to craig@wrotebook.com and re-sends that mail to the host wrotebook.com, is acting as a mail relay.

At one time mail relaying was the default configuration for Sendmail systems, but no more. Spammers use unsuspecting mail servers to relay their spam in order to hide the true origin of the nuisance mail. Now the default configuration is to relay no mail at all. In Figure 2.1, the system uses this default configuration. Each system sends its own mail. None of the systems accepts mail for relaying from any other system. It is not to loosen those restrictions if you need to provide mail relaying for some of your clients (Proper relay configuration is described in Chapter 11.). In Figure 2.2, the server is configured as a relay for the systems on the local network.

By default, Sendmail does not relay mail. A server accepts mail addressed to the server itself or any of its local hostname aliases. It rejects all other mail. To enable relaying, specific names of the hosts or domains that are allowed to relay mail must be provided to Sendmail. The hostnames of relay clients can be provided in the relay-domains file or through the access database. Both of these files are covered in Chapter 6.

## A Client

One possible role for a Linux system running Sendmail is frequently overlooked is the role of a client. By default, every Linux system is a Sendmail server. It is a limited server, because it is set up to handle only mail from users who are directly logged in to the system, but it is a server nonetheless. Turning a Linux system into a true client takes configuration effort, and it is rarely worth the effort. While the client configuration is touched upon in Chapter 9, the true focus of this book is to properly configure the Sendmail server functions for every Linux system from laptop to an enterprise server.

## In Sum

The SMTP protocol runs on top of the TCP protocol. TCP is a reliable, connection-oriented protocol. It ensures that mail is always delivered, and it means that SMTP directly delivers mail to the remote system without dependence on intervening systems. This is a great mail-delivery model because it provides immediate feedback from the remote server over or not the mail was successfully delivered. However, the system demands a remote system that is fully capable of accepting SMTP mail. Unfortunately, that is not always the case. Sendmail queries DNS and the MX records to route mail to a fully capable SMTP server for those that cannot handle their out mail.

The fact that direct delivery to end systems and delivering to intervening mail servers are available to Sendmail creates the possibility of a variety of e-mail architectures. Servers are clients and servers, and the servers can be described in different ways. Servers that handle inbound mail are described as hubs or mailbox servers. Servers that handle outbound mail are called relays or simply servers. To clarify the vagueness of this language, Internet standards document the functions of message user agents (MUAs), message submission agents (MSAs), and message transfer agents (MTAs).

Even with the narrowly defined MUA, MSA, and MTA, there can be confusion because most functions do not match any definition. Various functions overlap across systems and things are not easily tied up in neat packages. The easiest way to avoid making the language of e-mail architecture complex is to use a little judgment. Don’t be too rigid in interpreting the meaning of a term. Always look at things in context. Sendmail frequently uses the same word to describe two different things. The text is clue to understanding.

Sendmail is the software that turns a Linux system into an e-mail server. It acts as an MSA and an MTA and can even be used as an MUA. Chapter 3, “Running Sendmail,” looks at how Sendmail is installed on a Linux system and how it runs once it is installed.

# Running Sendmail

Chapter 2, "Understanding E-Mail Architecture," illustrates the importance of Sendmail for a Linux system. Sendmail implements the SMTP protocol for Linux systems. It sends and receives SMTP mail for the system, and it acts as an interface between the user's mail program and the Internet. These vital tasks make Sendmail an essential part of Linux systems. Sendmail is such an essential part of Linux system that it is usually installed by default. You need to know how to install Sendmail on your system. This chapter covers both topics. It also examines how and why to control Sendmail at start-up.

## Running Sendmail at Start-Up

Sendmail runs in two distinct modes: real-time mode for outbound mail and daemon mode for collecting inbound mail. When mail user agent (MUA) has mail to send, it creates an instantiation of Sendmail. Sendmail daemon, on the other hand, runs the entire time, constantly listening for inbound mail and periodically processing the queue. Like other daemons, is started at boot time. The ps command reveals whether or not Sendmail is running on your system:

```
ps -C sendmail
PID TTY      TIME CMD
542 ?       00:00:36 sendmail
```

The process ID (PID) shows that this process was started during the boot. Running this ps command on Linux systems will show that Sendmail is running because, generally, many systems are running the Sendmail daemon unnecessarily. It is not necessary to run Sendmail as a daemon in order to send mail. A Linux mail client can collect inbound mail from the mailbox server using POP or IMAP and relay outbound mail through the mail relay server without running the Sendmail daemon. Deciding which systems should run the Sendmail daemon is part of planning your e-mail architecture. Unneeded daemon consumes system resources and provides holes through which network intruders can slash. Take care when selecting systems really need any daemon, including Sendmail.

It is possible to enable or disable Sendmail after the system is installed, and there are several tools to do this. These tools vary depending on the type of start-up procedures used. Some Linux systems use BSD-style start-up procedures, while others use V-style procedures.

On distributions that use V-style boot procedures, the script that starts Sendmail is usually found in the /etc/rc.d directory, where it is stored under a name such as sendmail, mail, or mta. On distributions that use BSD-style boot procedures, the commands that start Sendmail are found in one of the rc.m script located in the /etc/rc.d directory. Regardless of the name of the script used for this purpose, some start-up script is used to start Sendmail at boot time.

> TIP Locate the daemon start-up script on your Linux system, go to the directory that holds start-up scripts and run the command grep sendmail * to search every file for references to Sendmail. Not sure where the start-up scripts are stored? Go to /etc and look for files or directories that begin with the string rc. Those are start-up files and directories.
