The /parse command starts printing out two informational messages. The first one says that the input address is stored in a variable g for the duration of the process. The comment calls the input address the "cracked address." All means is that any standard RFC 822 command format that accompanied the address was removed before the address was stored in variable g. The second message tells you that the address is processed as an envelope recipient address.

The first /parse command processes the address as a delivery address, passing through ruleset 3 (canify) and ruleset 0 (parse). Once the smtp mailer is selected for the address, the canonical address is passed through ruleset 2, the envelope defined by the R parameter of the smtper (EnvToSMTP), and finally through ruleset 4 (final). This extensive processing is exactly the hereof that was shown in Figure 8.1 in Chapter 8. The /parse command makes it possible for you to send an address through this complete process without remembering the order in which rulesets execute.

The last line displayed by the /parse command is the mail delivery triple that will be used for this address. If /parse believes there will be an error delivering the mail to the selected address, it will also display an error message, as shown below:

```
final       returns: al @ bird . org
al@bird.org... Transient parse error - message queued
for future delivery
```

# Processing a Specific Address Type

By default, the /parse command, and the /try command, process addresses as envelope recipient addresses. You'll recall from Figure 8.1, different types of addresses are processed by different rules. Use the /tryflags command to select a different type of address processing. The /tryflags command accepts four possible values:

+   H This flag requests header address processing.
E This flag requests envelope address processing.
S This flag requests sender address processing.
R This flag requests recipient address processing.
