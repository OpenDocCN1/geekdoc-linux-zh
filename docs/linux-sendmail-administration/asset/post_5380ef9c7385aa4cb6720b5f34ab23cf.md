The generic.m4 file contains six m4 commands after the copyright notice. The first is a VERSIONED macro that can be ignored. The first significant command is a define command.

## Defining .forward Path

The first define command assigns a value to the CONFORWARD_PATH variable. This holds a colon-separated list of paths that Sendmail searches when looking for a .forward file. (Chapter 2, “Understanding E-Mail Architecture,” explains the purpose of the .forward file.)

The default value of CONFORWARD_PATH is $/.Sendmail:$sw:$z/.forward, where $z is the recipient's directory and $sw is a valid name for that host. (See Appendix C for a full list of Sendmail variables, including $z and $sw) If the recipient's directory is /home/jill and the hostname is gull, the path is interpreted as /home/jill/.forward.gull:/home/jill/.forward.

The first define in Listing 5 increases the complexity of the .forward path. It retains the two paths from the search list and inserts in front of them the value $z/.forward.sw+$z/.forward-$h. The $z and $sw variables serve the same purpose as .forward. The $h variable contains the detail that user+detail addressing syntax is used and procmail is used as the local mailer. Now procmail is being used as the local mailer because we use the local_procmail feature in the linux.m4 OSTYPE file. Given this configuration, local mail on a host named egress addressed to craig+sysex would prefer the following .forward search path to the standard path: /home/craig/.forward+sysex:/home/craig/.forward+sysex.

## The +detail Syntax

The +detail syntax is an adaptation of the mailbox syntax in the Cyrus mailers. The Cyrus mailers allow mail to be addressed to a specific mailbox. In a Cyrus address, the detail is a mailbox name. Thus mail addressed to rebecca+in is placed in a mailbox inbox owned by the user rebecca.

The problem with this is neither Sendmail nor Linux uses a mailbox architecture. Sendmail writes to a single spool file for each user, and Linux user mail agents read from a single spool file for each user. Thus, bound for user rebecca is written to and read from the file /var/spool/mail/rebecca. Mailboxes exist on Linux systems, but they exist because the user mail agent reads the mail from the single spool file and routes it to different mailboxes based on some filtering defined inside the user mail agent.

## Chapter 5 Understanding a Vendor's Configuration

The +detail syntax is rarely used in the addresses entered by users. It requires an odd form of addressing that most users don't like, and it solves a problem that user mail agents already solved to the satisfaction of most users. If used at all, the +detail syntax is used internally by sendmail or procmail in the same way the pseuddomains are used to help the mail programs route the mail. (Not sure what a pseudo-domain is? Don't worry—you'll see one in a second.)

Defining the CONFORWARD_PATH variable seems more like a command that would happen in the OSTYPE source file, in the DOMAIN source file. It defines a path file, which is something that commonly happens in the OSTYPE file, and this specific path is directly related to using procmail as the local manager, which is also defined in the OSTYPE file. This just goes to show that you really cannot tell something will be defined in a Sendmail configuration. The only way to know the complete configuration is to look at all of the files.

The definition of .forward search path is the most complex define in generic. The second define is easier to understand. It sets the maximum number of bytes allowed for all headers. By default no limit is set. In the generic.m4 file shown in Listing 5.3, the maximum length is set to 32,768 bytes (32KB). That is more enough for any reasonable form of mail abuse. Headers longer than that might indicate a mail problem or some form of mail abuse. So perhaps this limit is set to detect mail problems or abuse. But most likely this value is being set in the generic.m4 file to provide another example of define command syntax.

The define commands that open the generic.m4 DOMAIN file are followed by two FEATURE commands that add optional capabilities to the Sendmail configuration.

## Adding Support for the .REDIRECT Pseudo-Domain

The FEATURE(redirect) macro adds support for the .REDIRECT pseudo-domain. A pseudo-domain is a domain-style extension added to an e-mail address by Sendmail to define special handling for the address. The .REDIRECT pseudo-domain works together with the aliases database to handle mail for people who no longer read mail at your site but still get mail sent to old address.

After enabling this feature, add aliases for each obsolete mailing address in the form:

```
old-address new-address.REDIRECT
```

## The Generic Linux Configuration

For example, assume that Jay Henson is no longer a valid e-mail user in your domain. His old username, jay, should no longer accept mail. His new mailing address is HensonJ@industry.com. Enter the following alias in /etc/aliases file:

```
jay HensonJ@industry.com REDIRECT
```

Now when mail is added to the jay account, the following error is returned to the sender telling them to provide a new address for the recipient:

```
551 User not local; please try <Henson@industry.com>
```

This is a useful feature for any site that is small enough, or organized enough, to keep track of the e-address of employees who have moved to new jobs. It is a courtesy to the ex-employee, and yet it cuts down on the number of requests the postmaster receives from the ex-employee's new e-mail address.

The second FEATURE command also specifies a useful feature.

## Adding Support for Local Host Aliases

The FEATURE(use_cw_file) command loads the class variable from a file. The name of the file is defined with the confCW_FILE variable. Unless modified with the confCW_FILE variable, the default file used to load class w is /etc/mail/local-host-names.

Class holds a list of hostnames for which the local computer will accept mail. If a running Sendmail receives mail addressed to another host and forwards the mail to that host if the local host is configured as a relay, or discards the mail if it is not configured as a relay. If your system should accept mail that is addressed to another host, the name of the other host should be added to the class.
