We have covered most of the K command name, database type, and the switches. The last field in the K command is the path. This is simply the name of the database (The K command adds the correct extension—for example, .db—to the pathname based on the database type.). The path value is only required if the database is external to Sendmail, as the list of database types declared by K commands are internal to Sendmail. When an internal database is used, no path is needed. Some sample K commands from the sendmail.cf file will make the structure of the command clear.

## Realistic Commands

The sample configuration contains five K commands, all of which are shown in Listing 7.6.

### Listing 7.6 The K Commands Found in sendmail.cf

```
[kraig] $ grep '^K' /etc/sendmail.cf
Karith ar
Kquote devote
Kmailtable hash -o /etc/mail/mailertail
Kvirtuser hash -o /etc/mail/virtertuser
Kaccess hash /etc/mail/access
```

Let's work our through Listing 7.6 from the bottom up. The last K command declares a database name access. The database is the standard hash type. The file that contains /etc/mail/access. All of this information—the internal name, the database type, and the file that holds the database—defined by the K command is the direct result of the FEATURE(`access_db`) command from our sample configuration file. The access database, which is used to control mail relaying and delivery, is covered in Chapter 6.

The previous K commands define the virtuerstable and mailterable databases that result from the following commands found in the sample configuration file:

```
FEATURE(`mailterable`, `hash -o /etc/mail/mailterable`)
FEATURE(`virtuerstable`, `hash -o /etc/mail/virtuerstable`)
```

Both hash type databases use the -o-switch, which means Sendmail will run even if these files are not found. The K command for the access database did not use the -o-switch. If the file /etc/mail/access is not found, Sendmail will fail if a command attempts to use the access database. Even if you do not have entries for the access database, create an empty /etc/mail/access.db file in order to make Sendmail robust, as in this example:

```
+ [root] touch /etc/mail/access
[root] makedmap /etc/mail/access < /etc/mail/access
```

The mailterable, the virtuerstable, and the access database are all covered in Chapter 6. The other databases, however, were not covered in that chapter. Both the ar and deque databases are pseudo-databases. That means they are not real databases. Instead they are internal Sendmail routines that are accessed by rewrite rules if they were databases. The deque map, which has already been discussed, is used to remove quotation marks from addresses. The ar map is used to do arithmetic functions for STARTTLS settings. STARTTLS is covered in Chapter 12.

The four commands, D, C, F, and K illustrate everything that is in the Local Info section of the sendmail.cf file. The Local Info section is the most important section of the file from the standpoint of a system administrator trying to directly configure sendmail.cf, because information varies from system to system. We have covered every command in the Local Info section of our sample system, but before moving to the Options section, we should cover the only configuration command that occurs before the Local Info section—

## The Version Level Command

The version level command (V) defines the version of the sendmail.cf file. This should not be confused with the Z variable that identifies the Sendmail source release number or the m4 VERSIONID macro defines revision control information for the macro source files.

## Chapter 7 The sendmail.cf File

The V command tells Sendmail the level of syntax and commands required to support the configuration. If the Sendmail program cannot support the requested commands and syntax, it complains about the commands it does not understand and displays the following version level error message:

```
[root]# sendmail -v -t
/etc/sendmail.cf: version 9 exceeds 8.11.0
/etc/sendmail.cf: version 8.11.0 exceeds 9
```
