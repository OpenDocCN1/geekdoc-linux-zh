# Rewrite Rules 235

Listing 8.5, we create a ruleset named RemoveAngles that contains only one rule. The pattern in the rule matches any number of tokens ($*) before the literal <and any number of tokens ($*) between the literals <and>. The template in the rule replaces the indefinite tokens without the angle brackets.

The sendmail -bt in Listing 8.5 shows that the rule works; it removes all the angle brackets from the address craig<<wren>>. Don't assume, however, that it removes all of the angle brackets in one pass. The first time the address matches the pattern it is rewritten as craig@wren. The rewritten address is again compared to the pattern and it again matches. This time it is rewritten as craig@wren, which doesn't have the angle brackets required to match the pattern.

Once the pattern no longer matches, no further processing is done by this rule and the address is passed to the next rule in line. The RemoveAngles list from Listing 8.5 contains no other rules processing steps, but most rulesets have more than one rule. Rules in a ruleset are processed sequentially, although a few symbols can be used to modify this flow.

The recursion built into rewrite rules creates the possibility for infinite loops. The $ and the $: templates are used to control processing and prevent loops. The template begins with the $ symbol, the entity is terminated and the remainder of the template is returned by the ruleset. Use $ to exit a ruleset at a specific rule.

In 8.3, the $ symbol was used to control the flow inside the ClassTest rule. The template in each rule in list starts with the $ symbol, so if a pattern match is found, the template is applied and the rule exits. Suppose the $ was not used on the first rule in list. In that case, the test of the address christ@robin would have produced the response "Wrong format" instead of the response "Found" that it's expected. Here's why. The address christ@robin matches the pattern of the first rule, which is $0=$w. Therefore, the address is rewritten to Found $it. If the $ is not used, the address is then processed by the next rules in line. It doesn't match the pattern of the second rule, which is $0=$*w in the rule. The address Found it is there-entially passed on to the third rule in line. This time it doesn't catch the pattern $*, which essentially matches anything that hasn't been caught by the first two rules. The third rule rewrites the address Found it into the address Wrong Format—not, of course, what we want. To get the result we want, every rule in ruleset ClassTest requires a flow control symbol, even the third rule.
