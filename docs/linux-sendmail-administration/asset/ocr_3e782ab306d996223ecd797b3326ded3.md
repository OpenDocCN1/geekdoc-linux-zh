# Don't ifdef

I have a philosophical objection to having ifdef inside the OSTYPE file. I understand why it had to be done: it was done to create an OSTYPE file that would work for all versions of Linux. However, that is my objective. If different Linux distributions require different OSTYPE settings, the developers of such distributions should create an OSTYPE file for their distribution that contains the correct setting. After all, that is what the OSTYPE file is. There is no reason why there shouldn't be an ostype/redhat.m4 file, and an ostype/suse.m4 file, and an ostype/slackware.m4 file, and a file for any other distribution you can imagine. You'd find that distribution developers would want to put their names in the ostype directory, but the fact is that not a single Linux developer has added an OSTYPE file to the directory of the Sendmail code distribution.

As Listing 5.2 shows, the last line in linux.m4 is a FEATURE macro. The feature that this macro adds to the configuration is local_procmacail, which will specify that procmail will be used as the local mailer. You will see in Chapter 11, “Stopping Spam,” procmail is a very powerful mailer. The fact that Linux uses procmail as the local mailer is a plus. The local_procmacail feature accepts up to three options:

+   * The path to the mailer. The default is the path value assigned to PROCMAIL_MAILER_PATH, which in Listing 5.2 is /usr/bin/procmacail. The same effect could have been obtained with the following FEATURE command:
  FEATURE(`local_procmacail`, `/usr/bin/procmacail`)
* The command line for executing the mailer. The default is procmail -Y -a sh -h $u, where sh is replaced by the detail if the user+address syntax is used, and $u is replaced by the username from the recipient address. $ and $ are the Sendmail variables that hold the remote hostname and the remote user's address in a standard delivery. In this case, however, procmail is being used as local mailer, so there is no hostname and the $ is used to hold the detail value. (See Appendix C, “Sendmail Variables, Options, and Flags,” for a full listing of Sendmail flags.)
* The flags for this mailer. The default is SPFhn9. (See Appendix C, “Sendmail Variables, Options, and Flags,” for a full listing of mailer flags.)
