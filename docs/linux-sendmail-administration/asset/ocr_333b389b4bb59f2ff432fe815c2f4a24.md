The 15 lines in Listing 6.5 define aliases for special names. All of these, except the webmaster alias that I added, come pre-configured in the Red Hat aliases. The first two, MAILER-DAEMON and postfix, are aliases that people expect to find on any system running Sendmail. Most of the others are assigned to the daemon usernames as found in the /etc/passwd file. One can actually log using the daemon usernames, so any mail that might be directed to these pseudo accounts is forwarded to a real user account. In the example, this mail is forwarded to the root user account.

Of course you don't want people logging into the root account to read mail, so the aliases file has an alias for root. In the example, I wrote the root entry to forward all mail addressed to staff, which is another alias. Notice how often aliases point to others. Doing so is very useful if you want to update aliases instead of when the real user account the mail is delivered to.

The staff alias is a mailing list. A mailing list is simply an alias with multiple recipients. In the example, five people are responsible for maintaining this mail server. Messages addressed to root are delivered to all of these people through the staff mailing list.

Two special aliases are associated with the mailing list. The owner-staff alias is a special alias used by Sendmail for error messages to the mailing list. The format for this alias is owner-list, where list is the name of the mailing list. The other special alias, staff-request, is not required by Sendmail but it is expected by remote users. By convention, manual mailing list maintenance requests, such as being added or deleted from a list, are sent to the list-request, where list is the name of the mailing list.

The last nine lines are user aliases I added to the file. These lines direct mail received at the mail server to users who read their mail. The first alias directs this mail server receives for Jill. Remember that when we classed class w, it pointed out that adding a hostname to class does not mean that the server will be able to handle the mail for a specific user on remote host. The user needs either an account on the server or an alias in the aliases database. This means that it is not necessary to create a user account for Jill on the mail server her mail is forwarded to egret. fobirds.org. It is egret's job to see that Jill gets her mail.
