Like the Sendmail variables assigned by the D command, class variables traditionally had single names, with user-created classes using uppercase letters for names and Sendmail internal classes using lowercase letters for names. Now, classes can use long by enclosing the name inside curly braces—e.g., {Accept}. Listing 7.3 uses a grep command to show all of the C commands contained in the sendmail.cf file delivered with the Red Hat RPM:

# Listing 7.3 The Class Commands Found in sendmail.cf

```
[craig]$ grep '^C' /etc/sendmail.cf
Cwlocalhost
CP.
CO @ %!
C.
[[
(Accept)OK RELAY
C(tls)VERIFY ENCR
CPDIRECT
C(src)E F H U
```

The first command in Listing 7.3 adds the value localhost to class w. From the discussion of the local1-host-names file in the previous chapter, you know that class holds all of the computer's hostname aliases. In that chapter we used sendmail -bt to view the contents of class w, so you also know that class contains more than just the word localhost. Unlike a D command, which overwrites the contents of a variable to set the variable to a specific value, C commands are additive. This C command doesn't replace everything in class with the word localhost; it adds the word localhost to whatever else is there.

The variable P is a good example of the additive nature of C commands. The second command in Listing 7.3 stores the value . (dot) in variable P. Later, in the second-to-line of Listing 7.3, another C command shows the value REDIRECT in the same variable P. After the latter command, P contains a . (dot) and the word REDIRECT, as this sendmail -bt test shows:

```
[root]# sendmail -bt
ADDRESS TEXT MODE (rules NOT automatically invoked)
Enter <ruleset><address>
>=$P
```
