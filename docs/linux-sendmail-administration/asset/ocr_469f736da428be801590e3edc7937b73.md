# On a BSD-Style System

Linux systems as Slackware use BSD-style boot procedures start Sendmail by executing the sendmail command directly from one of the main start-up files. The code that runs the Sendmail daemon in the Slackware Linux /etc/rc.d/rc start-up script is very straightforward, as shown in Linux 3.1.

+   3.1 Starting Sendmail from a Slackware Boot Script

```
# Start sendmail daemon:
if [ -x /usr/sbin/sendmail ]; then
  echo "Starting sendmail daemon"
  /usr/sbin/sendmail -bd -q 15m
fi
```

Listing 3.1 shows a kernel system ready to run Sendmail. The first line is a comment, as indicated by the fact that it starts with a pound sign (#). The next lines are if statement checks whether or not the sendmail command is available. If the command fails, a message is displayed on the console indicating that Sendmail is starting and then the sendmail command is run.

The code in 3.1 runs the sendmail command with the -bd and the -q options. In addition to listening for inbound mail, the Sendmail daemon periodically checks to see whether there is mail waiting to be delivered. It's possible that a Sendmail process that was started to send a message was not able to successfully deliver the mail. In that case, the process writes the message to the mail queue and counts on the daemon to deliver it at a later time. The -q option tells the Sendmail how often to check the undivered mail queue. In the Slackware example, the queue is processed every 15 minutes (-15m).

To prevent Slackware from starting Sendmail at boot time, comment the lines shown in Listing 3.1 out of the rc.M script by placing a pound sign at the beginning of each line. To restore Sendmail to the boot process, remove the pound signs. These techniques are easy and work, but they are far from elegant.

Directly editing a start-up script is easy, but dangerous. Most system administrators worry that an editing error will have a major negative impact on the next boot. I have never had a major boot problem cause by an editing error, but I understand the fear. Distributions that use V-style start-up procedures alleviate this fear by making it unnecessary to directly edit the start-up file.
