The address in the address field can define an individual, a host, a domain, or a network:

+   - An individual is defined using either a full e-mail address in the form user@host.domain or a username in the form username@.
- A host is identified by its hostname or its IP address.
- A domain is identified by a domain name.
- A network is identified by the network portion of an IP address.

Listing 6.7 illustrates the various possible address fields. The listing is a contrived example that includes each tag type and each address type.

# **6.7** Address Formats for the access Database

| spamer@bigisp.com | REJECT |
|---|---|
| makoneyfast@ | REJECT |
| wespamu.com | REJECT |
| 172.18 | REJECT |
| [172.20.12.6] | REJECT |
| From:weselljunk.com | REJECT |
| Connect:wepushorn.com | REJECT |

The two lines in this access database define two individual users. These lines tell Sendmail to reject any from the e-mail address spamer@bigisp.com and any mail from a user named makoneyfast. The third line defines an entire domain. It rejects mail from any host in the domain wespamu.com. The fourth line defines an entire network. It rejects mail from any computer whose IP address begins with network number 172.20.12.6. The fifth line defines a specific computer with the address 172.20.12.6, the square brackets surrounding the individual address mean that this IP address is literally in the e-mail address because it doesn't resolve to a hostname or is flagged by Sendmail as "might be forged."

> NOTE Addresses that do not map to hostnames are rejected by default, normally there would be no need to have an entry that rejects [172.20.12.6] in the access database. But as noted above, Listing 6.7 is a contrived example meant to show different address formats.
