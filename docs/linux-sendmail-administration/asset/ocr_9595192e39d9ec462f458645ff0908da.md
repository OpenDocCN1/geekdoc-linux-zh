The database is /etc/mail/access. All of this information—the internal name, the database type, and the file that holds the database—defined by the K command is the direct result of the FEATURE(`access_db`) command from our sample configuration file. The access database, which is used to control mail relaying and delivery, is covered in Chapter 6.

The previous K commands define the virtuer and mailterable databases that result from the following commands found in the sample configuration file:

```
FEATURE(`mailterable`, `hash -o /etc/mail/mailterable`)
FEATURE(`virtuerstable`, `hash -o /etc/mail/virtuerstable`)
```

Both hash type databases, and use the o-switch, which means Sendmail will run even if these files are not found. The K command for the access database did not use the o-switch. The file /etc/mail/access is not found, Sendmail will fail if a command attempts to use the access database. Even if you do not have entries for the access database, create an empty /etc/mail/access.db file in order to make Sendmail robust, as in this example:

+   [root] touch /etc/mail/access
[root] makedmap /etc/mail/access < /etc/mail/access

The mailterable, the virtuerstable, and the access database are all covered in Chapter 6. The other databases, however, were not covered in that chapter. Both the ar and deque databases are pseudo-databases. That means they are not real databases. Instead they are internal Sendmail routines that are accessed by rewrite rules if they were databases. The deque map, which has already been discussed, is used to remove quotation marks from addresses. The ar map is used to do arithmetic functions for STARTTLS settings. STARTTLS is covered in Chapter 12.
