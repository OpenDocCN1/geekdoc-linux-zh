There are more databases available for Sendmail than you will ever use. A couple are of little or no value to Linux sites—the bitdomain database converts addresses for a network that works no Linux sites and the uucdomain database converts UUCP “bang” addresses, the old hostuser e-mail addresses, that almost no one uses. Other databases have overlapping functions that you might not need to use both of them at your site. The default delivered by the RPM contains fewer than half of the defines and features listed above, and that configuration probably has more database capabilities than you will really need. To help you evaluate databases you do need, we will examine all of them in detail.

# # The Cr, Cw, and Ct Files

The first three databases we cover are not, in the strict sense of the word, databases. They are disk files used to load sendmail.cf classes. The “cr” and “cw” perform important roles in configuring Sendmail, but changes in the security atmosphere of the network mean that the “ct” file has no useful role.

The file that loads the ct variable is often called the “ct” file because the traditional name of this file was /etc/sendmail.ct. In Sendmail 8.11 the default name of this file is /etc/mail/trusted-users, but the function of the file remains the same. It is used to add usernames to the list of users that are trusted to send mail under another user's name. By default, ct contains the usernames daemon, root, and ucp.

You will never use the /etc/mail/trusted-users file, and there are some good reasons why you won't. First, it is a bad idea to let people send mail under other people's names. In general, if you don't want to expand the list of trusted users, if you decide absolutely must add usernames to the trusted user list, you won't add enough to justify putting them in a separate file. For example, you could add the username “mail” to the trusted user list. You could edit the macro configuration file to add the FEATURE(use_ct_file) command, rebuild the sendmail.cf file, and create a trusted-users file containing the single word mail. But why? You could easily edit the macro configuration file to add the define(`TRUSTED_USERS`, `mail`) command, rebuild the sendmail.cf file, and be done with it. It is not only this second approach slightly easier, but it is safer because there is fewer file created and thus fewer file where the permissions could be set.

> **WARNING** Despite this example, neither TRUSTED_USERS nor use_ct_file is recommended because you shouldn't add any users to the trusted user list. Trusting users is a bad idea in this age of spammers and security crackers.
