

# 通用 Linux 配置

`generic-linux.mc` 文件调用的第一个源文件不出所料，是 `linux.m4` OSTYPE 文件。必须分析 `linux.m4` 文件的内容才能完全理解通用的 Linux Sendmail 配置。

## Linux OSTYPE 文件

`OSTYPE` 文件包含了特定于操作系统的配置值。运行 Sendmail 的不同操作系统之间，最大的配置差异在于文件的位置。定义路径名的变量通常存储在 `OSTYPE` 文件中。由于该文件是针对 Linux 操作系统的，而本书是关于在 Linux 上运行 Sendmail 的，让我们来看来看这个 `OSTYPE` 文件。

命令 `OSTYPE(linux)` 从 `ostype` 目录加载 `linux.m4` 文件。列表 5.2 显示了该 OSTYPE 文件的内容：

### 5.2 的 linux.m4 OSTYPE 文件

```
[craig]$ cat ../ostype/linux.m4
divert(-1)
#
# Copyright (c) 1998, 1999 Sendmail, Inc. and its suppliers.
# All rights reserved.
# Copyright (c) 1983 Eric P. Allman. All rights reserved.
# Copyright (c) 1988, 1993
# The Regents of the University of California. All rights reserved.
#
# By using this file, you agree to the terms and conditions set
# forth in the LICENSE file which can be found at the top level of
# sendmail distribution.
#
#
divert(0)
VERSIONID(`$Id: linux.m4,v8.11.16.1 2000/05/09 18:48:58 gshapiro
Exp ($)
define(`/confEBINDIR`, `/usr/sbin`)
define(`/PROCM_MAILER_PATH`, `
define(`/PROCM_MAILER_PATH`, `/usr/bin/procmail`))
FEATURE(local_procmail)
```

文件开头是一个版权声明。版权声明被 `divert(-1)` 语句和 `divert(0)` 语句包围，因此被视为注释并可以安全地忽略。`VERSIONID` 宏也可以忽略。

> **注意** 在本章的其余部分中，为了减少列表长度，文件开头的版权声明不再打印，但你应该意识到它们是存在的。

文件中的第一个实际配置命令是一个 `define` 语句，它为 `confEBINDIR` 参数分配了一个值。该参数存储了存放某些可执行二进制文件的目录路径。Sendmail 8.11 对 `confEBindir` 的默认值为 `/usr/libexec`。此 `define` 将设置更改为 `/usr/sbin`。这两个目录在 Linux 系统上都存在，但 `/usr/sbin` 目录是更用于存放系统文件的目录，在这种情况下它是正确的。`confEBINDIR` 路径用于定位 `smrh` 邮件送器，它在 Linux 系统上经常被用作程序邮件送器（prog mailer）。`smrh` 默认使用无限制的 shell。（（第 12 章“Sendmail 安全”描述了使用 `smrh` 邮件送器的优势。）在我们示例 Linux 系统上快速执行几次 `ls` 命令可以看出，`confbinder` 的正确值是 `/usr/sbin`：

```
[craig]$ ls /usr/libexec/smrh
ls: /usr/libexec/smrh: No such file or directory
[craig]$ ls /usr/sbin/smrh
/usr/sbin/smrh
```

第二个配置命令也是一个 `define`。这稍微复杂一点。这个 `define` 包含在一个 `ifdef` 中。`ifdef` 与配置 Sendmail 无关。它是一个内置的 `mdef` 条件命令，用于检查变量是否已经设置了值。`ifdef` 命令有三个字段：

- 正在测试的变量名
- 如果变量已赋值，要执行的操作
- 如果变量未赋值，要执行的操作

在列表 5.2 中，`ifdef` 测试变量 `PROC_MAILER_PATH`。如果变量已经定义，则什么都不做。我们知道这一点是因为 `ifdef` 的第二个字段是空的（注意连续的两个逗号 `,,`）。如果变量未设置，则执行 `ifdef` 第三个字段中的 `define`。在我们示例系统上正是发生了这种情况，因为我们没有在文件中为 `PROC_MAILER_PATH` 分配任何值。`define` 将 `PROC_MAILER_PATH` 变量赋值为 `/usr/bin/procmail`。这覆盖了 Sendmail 对 `PROC_MAILER_PATH` 的默认值 `/usr/local/bin/procmail`。快速通过 `ls` 显示新值是正确的：

```
[craig]$ ls -l /usr/bin/procmail
-rwxr-xr-x 2 root root 68276 Aug 10 1999
```

我对在 `OSTYPE` 文件中使用 `ifdef` 有哲学上的意见。我理解为什么要这样做：是为了创建一个适用于所有 Linux 版本的 `OSTYPE` 文件。然而，我的目的是：如果不同的 Linux 发行版需要不同的 `OSTYPE` 设置，这些发行版的开发者应该为自己的发行创建一个包含正确设置的 `OSTYPE` 文件。毕竟，这就是 `OSTYPE` 文件的作用。`ostype/redhat.m4`、`ostype/use.m4`、`ostype/slackware.m4` 以及其他发行版的开发者可能想把文件名放在 `ostype` 目录，但事实是没有任何 Linux 开发者为 Sendmail 发行版添加 `OSTYPE` 文件。

如列表 5.2 所示，`linux.m4` 的最后一行是 `FEATURE` 宏。该宏为配置添加的功能是 `local_procmail`，它将指定 `procmail` 作为邮件送器。你将在第 11 章“停止垃圾邮件”中看到 `procmail` 是一个强大的邮件送器。使用 `procmail` 作为本地邮件送器是一个优点。`local_procmail` 功能接受三个选项：

- 邮件送器路径。默认分配给 `PROC_MAILER_PATH` 的路径，在列表 5.2 中是 `/usr/bin/procmail`。通过以下 `FEATURE` 命令也可以获得相同的效果：`FEATURE(local_procmail, /usr/bin/procmail)`
- 执行邮件送器的命令行。默认是 `procmail -a -h $u`，如果使用了 `user+address` 语法，则 `h` 被替换，`u` 被替换为收件人地址中的用户名。在$`$` 是存储远程主机和远程用户地址的 Sendmail 变量。在这种情况下，`procmail` 被用作本地邮件送器，因此没有主机，`$` 用于存储详细值。（附录 C，“Sendmail 变量、选项和标志”，获取 Sendmail 标志的完整列表。）
- 该邮件送器的标志。默认是 `SPFhn`。（附录 C，“Sendmail 变量、选项和标志”，获取邮件送器标志的完整列表。）

> **注意** 通过 `local_procmail` 功能，`procmail` 被用作本地邮件送器。受影响的命令行标志和邮件送器标志是由 `LOCAL_MAILER_FLAGS` 和 `LOCAL_MAILER_ARGS` 设置的，而不是 `PROC_MAILER_FLAGS` 和 `PROC_MAILER_ARGS`，后者供 `MAILER (procmail)` 命令使用——尽管 `local_procmail` 使用的是 `PROC_MAILER_PATH` 路径而非 `LOCAL_MAILER_PATH`。没人说这容易理解。

`linux.m4` OSTYPE 类型定义了 `smrh` 程序的目录、`procmail` 的路径以及使用 `procmail` 作为本地邮件送器的功能。显然，`OSTYPE` 类型是查找文件名和邮件送器选项的好地方。`linux.m4` 中的设置名称与我们在示例系统上尝试使用 `generic.cf` 文件时看到的问题有关；linux.m4` 文件中的所有内容都值得理解，因为这些设置都会影响 Linux 系统的配置。

如列表 5.1 所示，`generic-linux.mc` 加载的第二个 m4 源文件是领域目录下的 `generic.m4` 文件。让我们详细该文件。

## 通用 DOMAIN 文件

`DOMAIN` 命令是可选的。它加载你创建的 m4 源文件来配置特定于你的域或网络的值。你不需要创建 `DOMAIN` 源文件，但如果你有任何特定领域的处理，强烈建议创建一个。

主机和用户名处理、域名伪装、邮件中继和反垃圾邮件功能是 `DOMAIN` 源文件中通常包含的信息类型。列表 5.3 显示了 `generic-linux.mc` 宏配置文件使用的 `generic.m4` DOMAIN 文件。

### 列表 5.3 domain/generic.m4 中的配置命令

```
[craig]$ tail -6 generic.m4
VERSIONID($id: generic.m4,v 8.15 1999/04/04 00:51:09 ca Exp '$)
define(CONFORWARD_PATH, '$forward.w+h$z$/forward.w+h$z$/)
forward.w$)\dn1
define(CONMAX_HEADERS_LENGTH, '32768')dn1
FEATURE(redirect)dn1
FEATURE(use_cw_file)dn1
EXPOSED_USER(root'))
```
