# Using the DOMAIN File

At the conclusion of Chapter 5, “Understanding a Vendor's Configuration,” the redcat.m4 file was written to take advantage of the structure inherent in the Sendmail m4 configuration directory. In Listing 5.6, the large redcat was divided into three files: a macro control file named redhat81.m4, an OSYPE file named redhat7.m4, and a DOMAIN file named foobirds.m4. Traditionally, the macro control file selects configuration components, the OSYPE file configures operating system-specific values, and the DOMAIN file holds all configuration options that are specific to your network or domain. In the first few sections of this chapter, we stick to the traditional use of these files by making our changes to the foobirds.m4 file, which is shown in Listing 9.1.

# **9.1** A Sample DOMAIN File

```
```
# cat ../fobirds.m4
VERSIONID(`Settings for the foobirds.org domain)`'dnl
DEFINE(`forward.W$h:$sz/forward+h$sz/forward.W$sz/
  forward)`'dnl
DEFINE(`conUSERDB_SPEC, /etc/mail/userdb.db)`'dnl
FEATURE(`always_add_domain)`'dnl
FEATURE(`blacklist_recipients)`'dnl
FEATURE(`redirect)`'dnl
FEATURE(`cw_file)`'dnl
EXPOSED_USER(`root)`'dnl
# cat ../m4/redhat81.mc > plain.cf
# cp ../domain/fobirds.m4 ../domain/old-fobirds.m4
```
```

All of the commands shown here are explained in Chapter 5, and for the most part existing commands do not have anything to do with the topics covered in this chapter. We process redhat81.mc, which is the macro control file that uses this DOMAIN file, through m4 to create plain.cf. That will be the baseline sendmail.cf file against which we can compare our changes. At the end of Listing 9.1, the original DOMAIN file is copied to foobirds.m4. That provides a backup file in case we don't like the changes we make in the next few sections, and against an original which we can compare the changes. These originals will be an important part of the test that helps us determine the impact of each additional configuration command.
