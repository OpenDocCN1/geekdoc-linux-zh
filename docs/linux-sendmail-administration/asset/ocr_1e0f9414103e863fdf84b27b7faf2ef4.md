# The m4 Macro Language

DOMAIN THE DOMAIN macro loads a file that contains information specific to your domain or network. THE DOMAIN source file is a perfect place for commands that affect hostnames and domain names, and define values, such as mail relay names, that are specific to your network. Because the information is specific to your domain, you must create your own DOMAIN source file. The Sendmail code distribution provides a sample generic.m4 that you can use as a starting point for creating your own configuration. Assume you created a DOMAIN source file that you called foobirds.m4. The following command, placed in the macro control file, uses foobirds.m4 to help in building the sendmail.cf file:

DOMAIN(foobirds)

THE MAILER command is optional. When it is used, it normally appears only in the macro configuration file.

MAILER The macro identifies the various sets of mail definitions that should be included in the sendmail.cf file. A usable configuration must have at least one MAILER; almost every Linux configuration has at least two:

MAILER(local1) The MAILER(local1) command adds the local1 mailer and the prog mail to the configuration. The local1 and prog mailers are essential, so any usable configuration will have at least this MAILER command.

MAILER(smtp) The MAILER (smtp) macro adds mailers for SMTP, Extended SMTP, eight-bit SMTP, directed delivery SMTP, and relayed mail. Every Linux system that sends SMTP mail, whether directly or through a mail server, has this MAILER command.

VERSIONID The VERSIONID macro defines version control information. This macro is optional, but is found in most m4 files. The command has no required format for the argument. Use any version control information you desire. The basic format of the VERSIONID macro is:

```
VERSIONID(`version-control-data`)
```
