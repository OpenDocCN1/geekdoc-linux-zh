
# Creating an Anti-Spam Database

The format of the entries in the access database is the easy part. Deciding exactly what to put in the database is harder. There are organizations on the Internet that collect information about spammers that might help you build an anti-spam database. A few sites to start with are maps.vix.com, spam.abuse.net/, and www.mids.org/nospam. These sites are a starting point for locating information about known spammers.

Of course, in addition to extracting data from online lists of spammers, you can enter your own entries directly into the access database using your favorite editor. I find this the simplest method, and the most flexible for responding to the problems of my individual users.

If you have Windows tools, you can use linuxconf to build the access database. Figure 11.1 shows an anti-spam filter being created with linuxconf.

# Using Anti-Spam Rewrite Rules

Most administrators think of Sendmail rewrite rules as a way to modify addresses on outbound e-mail that originates on the local system. The anti-spam rulesets allow you to process the addresses and headers from incoming mail. Sendmail provides two anti-spam rulesets for your personal rules. These are:

- Local_check_relay: This is a ruleset where you can define rules for handling mail that is being relayed.
- Local_check_rcpt: This is a ruleset where you can define rules to process mail based on the recipient address.
- Local_check_mail: This is a ruleset where you can define rules to process mail based on the sender address.

Assume that you have been receiving mail that is trying to masquerade as local by using a From: address that contains only a username. Further, assume that you have configured your mail server so the From: address of mail always includes the hostname. You use Local_check_mail: to check the sender address as shown in Listing 11.4.

# Managing Mail with procmail

As mentioned in Chapter 5,"Understanding a Vendor's Configuration," procmail is the default local mail delivery program for Linux systems. procmail provides the most powerful and e-mail filtering system available for Linux. procmail filters are defined by the user in the .procmailrc file. Additionally, the system administrator can define system filters in the /etc/procmailrc file. The format of both files is the same. The system administrator uses the /etc/procmailrc file for general anti-spam filtering. The end user can then use .procmailrc to add filtering for personal preferences.

> NOTE The examples in this section show both anti-spam filtering and personal filters for the sake of completeness.

The procmail file contains two types of entries: environment variable assignments and mail filtering rules, which procmail calls "recipes." Environment variable assignments are straightforward and look like these assignments would be in a initialization script like .bashrc. For example, HOME=/home/craig is a valid environment variable assignment. Assignment statements are rarely needed because the variables usually have the correct values for your see. See the procmail manual for the full listing of the more than 30 environment variables.

The real substance of a procmail file are the recipes. The syntax of each recipe is:

```
:0 [flags] [[:lockfile]
```
