# Limit Login Access

For security reasons, you want to limit remote login access to the server. Deleting telnetd and from the inetd.conf file as described in the previous section eliminates the basic remote login services. Eliminating all remote logins would provide an ideal level of security, but it is usually impractical. Many users want to read e-mail directly on the server, which requires a login account. Other users want POP or IMAP access, which also requires a user account and password on the server. As the system administrator, you need to provide secure login and controlled access.

If you use only POP or IMAP access, create the user's account without a valid login shell. The username and password from the account will provide IMAP or POP access, yet the user will not be granted login access without a valid shell. /bin/false is commonly used as the shell for this type of account. This works for users that require only POP or IMAP, but it does not work if the user also requires login access. In cases, you may need to provide secure login software.

The secure shell (ssh2) program is probably the most secure remote login software available. It supports login access and even X Windows access. Linux systems include openssh, a version of ssh that does not use any patented cryptographic techniques. If secure shell is not provided with your Linux distribution, it is available on the network. Go to www.ssh.org for more information about secure shell and to download the latest source code.

POP and IMAP services can be run inside a secure connection using tunnel. tunnel1 is a program that uses Secure Sockets Layer (SSL) to encrypt traffic for daemons that do not encrypt their own traffic. When run over tunnel1, POP is called pops and assigned TCP port 995, and IMAP is called imaps and assigned TCP port 993. For example, the following command added to the start-up of a Calder system would run POP inside an SSL tunnel:

```
tunnel -d 995 -1 /usr/bin/ipop3 ipop3d
```

That system could run pops inside tunnel1 from inetd using the following entry in the inetd.conf file:

```
pops tcp nowait root /usr/sbin/tunnel -1 /usr/sbin/ipop3d -- ipop3d
```
