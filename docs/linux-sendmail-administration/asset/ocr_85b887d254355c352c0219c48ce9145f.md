# Sendmail Security Protocols

tls_client The tls_client ruleset is called after Sendmail, acting as a server, receives a STARTTLS command from a remote client. The value in {verify} is checked to see if the TLS handshake completed. The ruleset also looks up {client_name} in the access database using tag tls_Ct: If {client_name} is not found, {client_addr} is looked up using tag tls_Ct: If no entries for the client are found in the access database, {verify} variable determines whether or not the SMTP connection is allowed. If entries are found, the access database determines whether or not the connection is made.

Chapter 6, "Using Databases," describes the syntax of the access database including the use of tag. In Chapter 6, only three tag fields are described—To;, From;, and Connect: TLS adds four tag fields to the access database syntax—CERTSUSER; CERTSUBJECT; TLS_Ct; and TLS_Srv: Only access database entries that start with these tags are used for TLS processing. In addition to new tag TLS adds two new values to the access database. These are:

[PERM+|TEMP+|VERIFY:{bits}] The VERIFY key requires verification completed successfully—i.e., {verify} must be equal to OK. Optionally, a colon and a number may be added to the key. If bits is defined, the encryption key used for this connection must be at least the specified number of bits long. By default, the verification failure returns a temporary error code, meaning the remote system can retry the connection. Putting the PERM in front of the keyword VERIFY causes Sendmail to send a temporary error code. The TEMP+ string causes Sendmail to send a temporary error code, which is the unless TLS_PERM_ERR is in the m4 configuration file.

[PERM+|TEMP+|ENCR] The ENCR key requires the encryption key used for this connection must be at least bits number of bits long. Putting the PER+ in front of the keyword ENCR cause Sendmail to send a permanent error code. The TEMP+ string causes Sendmail to send a temporary error code, which is the unless TLS_PERM_ERR is in the m4 configuration file.

A sample access database lines will clarify how these values are used.

TLS_Ctt:ibis.foobirds.org PERM+VERIFY:128
TLS_Srv:wolf.mammals.org ENCR:128
