Make sure that one can modify the aliases database. The aliases file and the directory that contains the aliases file should only be writeable by the owner, which is the TrustedUser (usually root). If you put an alias in the database that sends mail to a program, you must be absolutely sure that the program you send the mail handles the data properly. Buffer overflows and other data-handling problems are a security hole commonly exploited by intruders. Personally, I never alias mail to a program.

You might not be able to create the .forward file for every user, but you can control the programs that are available to the user through the l program syntax. Controlling those programs is the primary function of smrsch.

# Using the smrsch Feature

The smrsch feature was introduced during the discussion of the Red Hat configuration in Chapter 5, "Understanding a Vendor's Configuration." smrsch is the Sendmail Restricted Shell. It replaces /bin/sh as the program used for the prog mail. The mail delivery agent used when Sendmail processes an address that uses the l program syntax. On Linux systems /bin/sh is the Bourne Again Shell (bash), which means that any command that can be processed by bash can be processed by the prog mail. is a flexible configuration but a potentially dangerous one. Anyone who can get a command to the prog mail has the same access to the system as a user logged on to a terminal. smrsch limits the flexibility and reduces the damage.

smrsch is a restricted shell. Some built commands—exec, exit, and echo—work, but most not. smrsch does not allow standard I/O redirection. Of special the special characters used by the shell—carriage return, newline, <, >, &, $, ( and are not allowed; only ll and && are accepted. Most importantly, only those commands that can be run by exec or those that you choose to make available to smrsch through a special execution directory are available to the user.

smrsch forwards only to programs in the /usr/adm/sm.bin directory. The Sendmail administrator creates the directory and populates it with the programs that are trusted to be accessible through the prog mail. smrsch strips the initial pathname of the program to which mail is being forwarded. Thus, if the user enters /usr/local/vacation as the program name, smrsch strips the program name down to vacation and looks for a file of that name in the /usr/adm/sm.bin directory.

/usr/adm/sm.bin is the default execution directory used by smrsch. Compile smrsch with either -PATH or -DCMDBIN to specify a different execution path.
