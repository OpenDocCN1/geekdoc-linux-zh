# Known Problems

The Sendmail documentation lists some problems that are known to affect compilation on Linux systems. The problems fall into several categories ranging from compiler problems to kernel problems.

Two problems relate to GNU tools that are commonly used on Linux systems. One is an incompatibility detected between GDBM 8.8. Later versions of Sendmail improved the heuristic to detect GDBM so that the Sendmail can adapt to GDBM. The Sendmail release notes suggest Berkeley DB instead of GDBM.

The other GNU problem is with the gcc compiler. Old versions of gcc, version 2.4 and 2.5, cannot be used to compile Sendmail with the compiler optimization (-0) option. This was fixed when version 2.6 was released. The Caldera system used to generate the example in Listing 3.10 uses the Experimental GNU Compiler Suite 2.9I, which is a fail-on-gcc

Several problems are existed with very old kernels (pre-version 1.0), very old versions of libc (pre-version 4.7), and a very old version of the BIND domain name software (version 4.9.3). No should should be running any of this software.

The Sendmail documentation also reports problems to having previously compiled BIND on your system. The symptoms of this problem are unresolved references during the phase of the Sendmail compile. If you have compiled BIND from source code on your system and BIND wrote header files in /usr/local/lib/1 and /usr/local/include, these files may cause problems when Sendmail is compiled. The documentation suggests adding -1resolv1 to LIBS in the Sendmail Makefile to avoid this problem.

Finally, the documentation mentions problems with Linux kernel 2.2.0. The most worrisome of the problems reported because the documentation does not provide a workaround for this problem. I have never personally seen this problem, but if I did, I would upgrade the Linux kernel to the highest patch.

Franklin, none of the problems described in the Sendmail installation notes has struck any Linux system that I have worked with. A far common occurrence
