Some features are important in the fight against spam because they help you control how your mail server will deliver or forward on. These are accept_unqualified_senders, accept_unresolvable_domains, access_db, blacklist_recipients, and dnsbl. All of these are covered in Chapter 11, "Stopping Spam," and in the "DOMAIN" section of this appendix.

The always_add_domain macro makes Sendmail add the local hostname to locally delivered mail, even to pieces of mail that would normally have a username as an address. The bestmx_is_local feature allows mail addressed to a host that lists the local host as its preferred MX server if the mail was local. If this feature is not used, mail bound for a remote host is sent directly to the remote host if its MX record lists the local host as its preferred MX server. The bestmx_is_local feature should not be used if you use a wildcard MX record for your domain.

The use_cw_file and the use_ct_file features illustrate how define affect features. Both of these features use a file. The file can be set by a define command. If a define is used to modify a value by a FEATURE, the define should be included in the macro configuration file before the FEATURE.

The redirect feature handles mail for users who no longer read mail at your store. When properly configured, it returns an error to the sender providing with the user's e-mail address. Configuring the redirect feature is covered in Chapter 9.

There are three features that select optional programs for the local and the proc mail. local_procmail selects procmail as the local mailer. The path to procmail as the argument in the FEATURE command. The local_ntp feature selects local, a mailer provided with the Sendmail distribution, as the local mailer. The smrf feature selects the Sendmail Restricted Shell (smrf) as the proc mail. smrf provides improved security over /bin/sh, which is normally used as the proc provider. Provide the path to smrf as the argument in the FEATURE command.

## OSTYPE

The OSTYPE command points to the m4 source file that contains the operating system-specific information for this configuration. This required file is examined in detail in Chapter 5, “Understanding a Vendor’s Configuration.”

The essential characteristic of the items in Table A.3 is that all have something to do with the location of files on the system. Some of these, as HELP_FILE, STATUS_FILE, ALIAS_FILE, and QUEUE_FILE, are obviously file locations. The others, all of which relate to mailers, might not be so obviously linked to file locations unless you realize that most of the mailers require a pathname. If some mailer options are going to be placed in the OSTYPE source file, it only makes sense to put all of them here. Because files vary from system to system, it is traditional to put file locations and mailer options in the OSTYPE source file.

The MODFY_MAILER_FLAGS macro can be used to change the flags of a mailer. This is slightly different than the mailer flags definitions covered in Table A.3. All of those definitions can add flags, but none of them can remove a flag that is already defined. For example:

```
define(`LOCAL_MAILER_FLAGS`, `9`)
```
