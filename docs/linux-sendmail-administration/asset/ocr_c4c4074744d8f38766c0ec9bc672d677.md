The changes we make to the Sendmail configuration using .D and .C commands only as long as the sendmail -bt run. When we terminate the run, these temporary changes vanish. Setting values in test mode allows you to observe the effect of potential configuration changes before you make the changes.

In Listing 10.12, we don't actually change configuration values. In this example, we ask Sendmail to display the values it obtains from external information sources.

# Listing 10.12 Requesting Outside Information from Sendmail

```
> /mx foobirds.org
getxr(foobirds.org) returns 2 value(s):
wren.foobirds.org.
parrot.foobirds.org.
> /canon redbreast
getanname(redbreast) returns robin.foobirds.org
> /map generics kathy
map_lookup: generics (kathy) returns kathy.mcafferty (0)
```

Listing 10.12 is an excerpt from the middle of a sendmail -bt session. The first two commands in Listing 10.12 request information from the Domain Name System. The /mx command asks for the MX records at the hostname foobirds.org. In this case, DNS returns two records: wren.foobirds.org and parrot.foobirds.org. The records are listed in priority sequence. Thus, wren.foobirds.org is the primary MX server for foobirds.org, and parrot.foobirds.org is the backup MX server. If the hostname provided to the /mx command does not have a true MX record in the DNS system, the value returned by the /mx command will be the hostname itself. For example, ibis does not have an MX record.

```
> /mx ibis.foobirds.org
getxr(ibis.foobirds.org) returns 1 value(s):
isbis.foobirds.org.
```
