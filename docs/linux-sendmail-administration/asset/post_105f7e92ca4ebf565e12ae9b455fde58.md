
# Analyzing a Sample M

Examining one of the mailer entries from Listing 7.12 explains the structure of all of the mailer definitions. The entry for the smtp mailer from Listing 7.12 is:

```
Msmtp,
  P=[IPC], F=dMFux, S=EnvFromSMTP/HdrFromSMTP,
  R=EnvToSMTP, E=\n, L=990,
  T=DNS/RFC822/SMTP,
  A=TCP 5h
```

Let's examine each field in this:

- Beginning a line with M indicates that the command is a mailer definition. smt immediately following the M is the name of the mailer, which this is smtp.

- [IPC] The P argument defines the path to the program used for this mail. In this case it is [IPC], which means this mail is delivered by such mail. Other mailer definitions, such as local1, have the full path of external program in this field.

- F=dMFux The F argument defines the Sendmail flags for this mail. Other than knowing that these are mailer flags, the meaning of each individual mailer flag is of little interest, the flags are correctly set by the m4 macro that builds the mailer entry. In this case, m says that this can can send to multiple recipients at once; DFM says that Date, From, and Message-ID headers are used; u says that message lines beginning with X do not have extra prep.

- S=EnvFromSMTP/HdrFromSMTP The S argument defines the rulesets that process sender addresses. The ruleset can be different for every mailer, allowing different mailers to process e-mail addresses differently. In this case, the mail "envelope" is processed through ruleset EnvFromSMTP, and the sender address in the message is processed through ruleset HdrFromSMTP. These rulesets are also addressable as 11 and 31. So it is possible that you'll see S for the smtp mailer defined as S=11/31 on some systems.

- EnvToSMTP The R argument defines the ruleset to process recipient addresses for this mail. Every mailer has a different R value to allow each mailer to handle recipient addresses differently. Like the S field described above, the R field can have two rulesets, one for the envelope header and one for the mail header, separated by a slash. In this case, one ruleset (EnvToSMTP) is applied to all recipient addresses for the smtp mailer. EnvToSMTP is also known as ruleset 21, so this could have been written as R=21.

- E=\ The argument defines how individual lines in a message are terminated. In this case, lines are terminated with a carriage return and a line feed.

- L=990 The argument defines the maximum line length for this mailer. In this case, the mailer can handle messages that contain individual lines up to 990 bytes long.

- T=DNS/RFC822/SMTP The argument defines the MIME type for messages handled by this mailer. In this case, the mailer uses DNS for hostnames, RFC822 for e-mail addresses, and SMTP for error codes.

- A=TCP The argument defines the command used to execute the mailer. In this case, the argument refers to an internal Sendmail process. In other cases—the local mailer is a good example—the argument is clearly a command line.

> NOTE One of confusing idiosyncrasies of Sendmail is that the path to Sendmail's internal mail delivery can be either TCP or IPC. For this version of Sendmail, TCP was used in the argument. On your version it might be.

It is good to know how mailer definitions are structured, but the basic definitions built from the m4 contains all the mailers you need to run Sendmail on a TCP/IP network environment. You shouldn't need to modify any mailer definitions for an average configuration. In fact, nothing in the sendmail.cf files needs direct modifications for an average configuration. This section of the book doesn't limit itself to average configurations, so in the next section we directly edit the sendmail.cf file and use tools to observe the impact of the change.

## Editing the sendmail.cf File

It's important to realize how rarely the sendmail.cf file needs to be modified on a typical Linux system. The configuration file that comes with your Linux system works. Generally, you modify the Sendmail configuration not because you need to, but because you want to. You modify the configuration to improve the ways operate, not to get them to operate, and when you do it, change the m4 configuration—sendmail.cf. Despite this, in this section we edit the sendmail.cf file to change the way that Sendmail works.

> TIP Before you make any change to sendmail.cf—even a minor one—copy sendmail.cf to a work file such as test.cf and edit the work file. Never edit sendmail.cf without having a backup.

Assume your Linux system is named parrot.org. Using the default configuration, the address on e-mail is user@parrot.org. This is a valid address, but it's not exactly what you want. You want to hide the hostname in outbound e-mail by using user@parrot.org. Chapter 9, “Special m4 Configurations,” provides much more coverage on masquerading, but for now all we need to know is that we want to masquerade as domain.

To create the new configuration, you need to understand the purpose of the macro variable, found in Local section of sendmail.cf. The comment for Listing 7.1, you find that no value is assigned to M, which means masquerading is not used. To replace the name of the host in outbound mail, set M to the domain name, as shown below.

- # masquerade as (null for no masquerading)
- parrot.org

## Testing Your Configuration

To test the new configuration, run the sendmail command with the -bt option. Sendmail displays a welcome message and waits for you to enter an address. The details of the -bt syntax are covered in Chapter 10, “Testing Sendmail.” For now all you need to know is that we want to see if the header address is properly rewritten to masquerade the hostname as the domain when we send outbound mail. First, test the existing configuration to see how the address is processed by the default configuration:

```
root]# sendmail -bt
ADDRESS TEST MODE (ruleset 3 NOT invoked)
Enter <ruleset> <address>
> /tryflags HS
> /try smtp craig
Trying header address craig for mailer smtp
```

### Testing Your Configuration

```
canonify input: craig
Canonify2 input: craig
Canonify2 returns: craig
canonify returns: craig
1 input: craig
1 returns: craig
HdrFromSMTP input: craig
PseudoToReal input: craig
PseudoToReal returns: craig
MasqSMTP returns: craig < @LOCAL*
MasqHdr input: craig < @LOCAL*
MasqHdr returns: craig < @parrot.org >
HdrFromSMTP returns: craig < @parrot.org >
final input: < @parrot.org >
final returns: craig < @parrot.org
Rcode = 0, addr = craig@parrot.org
```

> NOTE These tests run with Sendmail 8.11. The output from older versions of Sendmail, which used ruleset numbers instead of names, will look slightly different. 

The address returned by ruleset final, which is always the last ruleset to process an address, shows the address that will be used on outbound mail after all of the rulesets have processed the address. With the default configuration, the input address is craig@parrot.org.

> NOTE Ruleset final is also known as ruleset 4.

Next, run the sendmail command with the -C option to use the newly created test.cf command file. The -C option permits you to specify the Sendmail configuration file on the command line.

MasqSMTP input: craig

This tells you that the address in the Macro is used to rewrite the sender address in the header field. You know this because the only change made to the sendmail.cf file was set to a value for M, and now the address from ruleset final is craig@parrot.org. This is what you wanted.
