All of the things described above—removing login and telnetd, limiting logins to secure shell, creating POP and IMAP users without login shells, protecting POP and IMAP passwords through encryption or strong authentication—are all to prevent unauthorized login access. Course, login access may not be the only network service you want to protect on your Sendmail server. To control access to all services started by inet, use the wrapper.

# Controlling Network Access with Wrapper

The wrapper daemon, named tcpd, is executed by inetd. It is an integral part of most Linux distributions. Using the wrapper on a Linux system is easier than it is on any other systems because the entries in the inetd.conf file already protect to the tcpd program. Listing 12.3 is a few lines from the inetd.conf file on Caldera system.

# Listing 12.3 Linux Is Pre-configured for Wrapper

```
ftp stream tcp nowait root /usr/sbin/tcpd -1 -a
telnet stream tcp nowait root /usr/sbin/tcpd in.telnet
shell stream tcp nowait root /usr/sbin/tcpd in.rsh
login stream tcp nowait root /usr/sbin/tcpd in.rlogin
imap stream tcp nowait root /usr/sbin/tcpd imapd
```

In Listing 12.3, bold text is to highlight the reference to tcpd in each line of the inetd.conf file. The path to tcpd is used in the path of each network service daemon. Therefore, when inetd receives a request for a service, it starts tcpd. tcpd then logs the service request, checks the access control information, and, if permitted, starts the real daemon to handle the request.

The wrapper performs two basic functions: it logs requests for Internet services and provides an access control mechanism for those services. If the tcpd access control files are not found, tcpd allows every host to have access and simply logs the access request. The wrapper uses the authpriv facility of syslog to log its messages. Look in the /etc/syslog.conf file to find where your logs authpriv messages. (On a Caldera system, these messages are logged to /var/log/secure.) Logging requests for specific network services is a useful monitoring function, especially if you are looking for possible intruders. If logging were all it did, wrapper would be a useful package. But the real power of wrapper is its ability to control access to network services.
