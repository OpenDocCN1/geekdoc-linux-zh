The relay_based_on_mx feature is another feature that grants relating to a group of hosts. This feature will relay mail for any host where the local host is an MX server. This is a useful feature if the server that inbound mail for your clients is also the system that handles their outbound mail. The MX record that routes mail through the server to its clients can also be the signal to relay outbound mail from those clients. The weakness of this approach is that the Sendmail administrator cannot control all of the MX records in the same domain name. A remote site could relay mail through your server by simply adding an MX record to their domain. Despite this weakness, this feature is still an effective defense against spammers. Because they can hide the source of spam mail, spammers don't send mail that can be tracked back to their domain names, and thus they cannot write MX records for the domain names they use.

The last feature that relaxes restrictions is probably the most dangerous. Is the FEATURE ('promiscuous_relay') Current versions of Sendmail block by default. The promiscuous_relay feature returns to the past by telling Sendmail to relay all mail from any source. This is exactly the configuration spammers hope to find and the configuration they love to exploit. This feature can be used if your server is completely cut off from the Internet, either because you have no connection or your connection is through a firewall that does not allow any external mail delivery to your server. Regardless of your network connection, I recommend against using this feature it exposes your system to exploitation.

All of the features listed in this section weaken the barrier to mail relaying, although some are worse than others. promiscuous_relay should not be used to return to the past and make your system a potential spam relay. Avoid the relay_local_from feature because it is easy for spammers to write whatever they want in the Mail From: header, including your local domain name. Be careful when using any of the features described in this section that you don't weaken the Sendmail configuration so much you become a spam source.
