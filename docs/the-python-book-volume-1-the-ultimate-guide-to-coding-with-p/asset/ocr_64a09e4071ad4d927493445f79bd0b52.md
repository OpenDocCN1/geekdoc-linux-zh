For a game like this you usually want to run some update function many times per second, updating the widget positions and carrying out game logic - in this case collisions with the ball (Fig. 06). The Clock can schedule any function at any time, either once or repeatedly. A function scheduled at interval automatically receives the time since its last call (dt here), which we've passed through to the ball and player via the references we created in kv language. It's good practice to scale the update (eg ball distance moved) by this dt, so things remain stable even if something interrupts the clock and updates don't meet the regular 1/60s you want.
