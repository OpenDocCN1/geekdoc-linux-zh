# What is a shell script?—Well, if you now know what a shell is, and what a script is, then it should make sense to you that a shell script is nothing more than a script that you create using commands from your current shell (bash, csh, and so on) that the shell can interpret. For instance, a shell script may not operate properly in a different shell as a different syntax may be used. In any case, you can check your local system’s man pages for help if needed.

# What is a shell script primarily used for?—Quite simple, (most) scripts are used for automation of tasks. Who wants to type hundreds of lines of text into the shell prompt? Didn’t think you wanted to do that, but what if you put all that script (one file) and had that run? Quite possibly with at or cron? The whole picture would be clearing up.

# What is an example of a script in action?—A simple shell script in action is nothing more than picking the shell you are currently working with (I am going to use bash for this example), and knowing what commands you can enter into it. To create a script, you need to know what commands you will enter into it, and what it is going to do beforehand. This way, you don’t waste your time writing in your editor or at the shell prompt. If you have a clear picture defined beforehand, then this will save time and frustration.

Again, a shell script is little more than a list of commands that run in sequence. Study the man pages to these commands and get all the syntax laid out ahead before doing it on the Unix system, especially if it is not a test system and one you use for work or at.
