# **Tip**

If you're using our reference deployment in Appendix A, instructions for setting up the network and operating system are provided there. You are welcome to read through the following to increase your understanding of how configuration is done manually, but you can safely skip down to the “System Configuration” section of this chapter.

If you're using a virtualization technology other than our reference deployment in Appendix A to run through these deployment scenarios, you will need to do a bit of configuration on the host system where your OpenStack virtual machines are running.

Both VMs, controller and compute, will need to be configured to use a bridge with NAT. This is likely an option in the configuration of your virtualization technology. A basic NAT, in which all of the VMs’ outbound traffic is automatically translated, will not work for this environment.

The following is an example of how you would set up your bridges on the virtual machine host if it’s not being done automatically by your virtualization technology. You will need the bridge-utils and iptables packages installed.

```
$ sudo brctl addbr virbr0
$ sudo ip addr add 192.168.122.1/24 dev virbr0
$ sudo ip link set up dev virbr0
$ sudo iptables -t nat -A POSTROUTING -s 192.168.222.0/24 \
\! -d 192.168.122.0/24 -j MASQUERADE
$ sudo brctl addbr virbr1
$ sudo ip addr add 203.0.113.1/24 dev virbr1
$ sudo ip link set up dev virbr1
```

When you launch your controller node, one NIC should be associated with virbr0 and the second NIC with virbr1. The NIC connected to the virbr0 network will be how you access the system to configure and interact with OpenStack. The second bridge (virbr1) will be used for the example external network, which will be used to give your instances access beyond their default tenant networks.

# **Note**

If you’re using virsh and KVM for your environment you will likely already have a virbr0 configured and only need to add virbr1. A DHCP service will also be run by virsh to automatically assign a 192.168.122.1/24 address to your VM.

If a DHCP server is not automatically assigning addresses, you will need to manually configure an address on each of the nodes for their eth0 interface. You may use the following parameters during the installation of Ubuntu 14.04 LTS Server on these nodes:

+   - IP Addresses—192.168.122.2 (for controller) or 192.168.122.5 (for compute)
+   - Netmask—255.255.255.0
+   - Gateway—192.168.122.1
+   - Name server addresses—8.8.8.8, 8.8.4.4

Your single NIC compute node needs to be associated with virbr0.
