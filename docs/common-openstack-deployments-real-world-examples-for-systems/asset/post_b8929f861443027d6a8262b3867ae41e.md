
We’ll now move away from Neutron configuration files and back over to Nova. We need to add a `[neutron]` section in our `/etc/nova/nova.conf` that contains the following (remember, the `metadata_proxy_shared_secret` from the `metadata_agent.ini` earlier):

```ini
[neutron]
auth_url = http://controller:5000/v3
username = nova
password = NOVA_PASSWORD
project_domain_name = default
project_name = service
user_domain_name = default
region_name = RegionOne
timeout = 10
extension_sync_interval = 600
service_metadata_proxy = True
metadata_proxy_shared_secret = something_secret
```

Restart your nova services to be sure all your configuration changes have been picked up:

$ sudo service nova-consoleauth restart
$ sudo service nova-scheduler restart
$ sudo service nova-conductor restart
$ sudo service nova-novncproxy restart

$ sudo ovs-vsctl add-port br-ex eth1

## Compute Node

The compute node is much simpler than the controller node, requiring just a handful of services to be installed. This configuration is used exclusively for the management of instances and takes instructions via the services running on the controller.

### Nova

First we’ll install the nova-compute package and sysfsutils, which though not necessarily being used for the original purpose, does enable us to easily pull in the required virtualization tooling that we’ll need to run compute instances.

```bash
$ sudo apt-get install nova-compute sysfsutils
```

Once the installation completes, we’re going to once again edit `/etc/nova/nova.conf`, making the following changes. Remember to update the password to the Nova user password you were prompted for earlier, set **my_ip** to this compute node IP (using 192.168.122.5 as an example again) and the **rabbit_password** to the one you set when first setting up the openstack rabbit user. For the **enabled_apis** line in the following, remove **ec2** from the list.

```ini
[DEFAULT]
my_ip = 192.168.122.5
enabled_apis = osapi_compute,metadata
rpc_backend = rabbit
auth_strategy = keystone
use_neutron = True
firewall_driver = nova.virt.firewall.IptablesFirewallDriver

[oslo_messaging_rabbit]
rabbit_host = controller
rabbit_userid = openstack
rabbit_password = RABBIT_PASSWORD

[keystone_authtoken]
auth_url = http://controller:5000/v3
auth_uri = http://controller:35357
auth_type = password
project_domain_name = default
user_domain_name = default
project_name = service
username = nova
password = NOVA_PASSWORD

[vnc]
enabled = True
vncserver_listen = 0.0.0.0
vncserver_proxyclient_address = $my_ip

[glance]
glance_api_servers = http://controller:9292

[oslo_concurrency]
lock_path = /var/lib/nova/.lock

[libvirt]
virt_type = qemu
```

With these changes in place, restart nova-compute:

```bash
$ sudo service nova-compute restart
```

Back on the control node, you should be able to run the service list command again and see that there is now a compute service available on your compute host (output truncated):

```bash
$ openstack compute service list
```

### Neutron

The compute node does not have a Neutron database. It only has a couple of plug-ins that interact with the networking services on the controller. So first we'll install these plug-ins:

```bash
$ sudo apt-get install neutron-openvswitch-agent
```

In the `/etc/neutron/neutron.conf` file, make the following edit in the `[DEFAULT]` section:

```ini
service_plugins = router
```
