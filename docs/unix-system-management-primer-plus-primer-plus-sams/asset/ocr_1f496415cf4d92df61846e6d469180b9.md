In most cases, you use a top-down approach to system design. Rarely will management show you a pile of hardware work half a million dollars and ask, “What can we do with this stuff?” Instead, management will present you with a problem or a need and ask you to find a resolution. Because you know what management wants the system to provide, it makes sense to start with that idea and work your way down to the bits and pieces of hardware you'll need to make the idea a reality.

Using the top-down approach, you work through the business and technical goals and arrive at your first architecture decision—choosing the software for your system. Software comes in many forms, such as web servers, databases, and operating systems, and you must take into account aspects of each type of software when comparing products. When you've chosen software, you're ready to select the hardware upon which the software will run. The following sections discuss the issues involved in making these important decisions for your organization.

# Choosing Application Software

Application software provides the functionality of your product. Web servers, databases, text editors, and compilers are all applications that contribute to your technical and business goals. Using a top-down design approach, the ideas behind your project should translate directly into the functionality of the application software. Web sites need web server software. Accounting departments need financial packages that can manage the books. Online stores need shopping cart software. Public login servers need hundreds of public domain applications.
