# Using Shell Special Characters

Unix processes often rely on the shell to execute commands on their behalf, executing commands with the shell can create some serious security issues if not handled properly. Problems occur when an external user is able to feed arbitrary data to a program that uses the data in a shell command.

For example, imagine a network service running as root accepts a username and returns the processes owned by that user. If this program was written in Perl, you could use the system function to run ps from a shell:

```
system("ps -fu username");
```

This code works, but what happens when you insert a special character, such as a semicolon; into the username? Because the ps command is being fed to the shell, the semicolon is interpreted as a command separator, and you can make the shell run any command that follows. If you input mike;rm -rf / to this program, it would pass that string to the shell as follows:

```
ps -fu mike;rm -rf /
```

This would return the list of processes owned by mike, and then proceed to remove the entire contents of the server's file system!

There are two ways around this problem. You can check for semicolons and other special characters in a string before passing them to the shell, but you still run the risk of missing a character or two. Instead, you can verify that the string does not contain anything other than a set of valid characters. The following code uses regular expressions to ensure that the system contains non-alphanumeric characters:

```
if ($username =~ /[^\w]/) {
    print "Username contains illegal characters.\n";
} else {
    system("ps -fu $username");
}
```

# Reserve root for Necessary Processes

Never run processes as root unless they absolutely require root privileges to perform their intended tasks. This minimizes the potential damage from an exploited program.
