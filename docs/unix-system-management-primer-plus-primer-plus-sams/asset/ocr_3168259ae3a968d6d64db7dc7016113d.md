Geometric relationships can be more difficult to extrapolate. In this kind of relationship, consecutive results vary by a constant ratio. So, instead of having a constant increase in response time for each additional connection, the response time would increase in larger and larger amounts as connections are added, reaching the breaking point much sooner. This would produce a graph curving upward to the right rather than a predictable straight line. Making accurate predictions with such a graph is difficult unless you plot enough data to reveal an obvious pattern.

Not all relationships between load increase and system stress are purely linear or geometric. Some load-test results are linear up to point, and then the nature of the stress on the system causes the test relationship to become geometric. Some relationships are neither linear nor geometric, making it impossible to extrapolate anything from the test data. Only by testing can you find out what these relationships are and what you can do with them.

# Real-World Example: Load Testing to Please Management

A small market research company was expecting its Web usage to double in less than two months. The company's system administrator quickly assessed the situation and determined that the two CPU servers could not handle the load reliably. Knowing the server software was expandable to four processors each. Before deployment, the administrator performed a load test on the new servers. Many samples were taken, and a linear relationship was observed between the number of connections and the server response time. The test was performed on the old site, and a linear relationship was also found. After plotting, the administrator discovered that although the old site could handle only 100 concurrent connections and still respond within 7 seconds, the new site could handle 450 concurrent connections and keep response time within 7 seconds. Doubling the resources more than quadrupling the capacity of the site Not only that, but because additional CPU modules could be installed, the new servers could grow with the company.

# Regression Testing

Regression testing is one of the primary tools of any quality assurance (QA) team. Begin regression testing is by establishing a baseline of the functionality and behavior of an existing system. Then compare the baselines against the functionality and behavior of a new system.

Regression testing is not intended to measure performance; you're not trying to beat the numbers from the last test. Instead, a regression test makes sure that everything still functions as it did before, so you know that nothing will break when the new system is deployed.

# Conducting Regression Tests

Regression testing is an art, especially for larger projects. In preparing for the test, the system administrator must account for all features of a project, and then add the information to the baseline results. Preparing an accurate baseline is the most critical part of the test, as the baseline is the data to which all other results are compared.
