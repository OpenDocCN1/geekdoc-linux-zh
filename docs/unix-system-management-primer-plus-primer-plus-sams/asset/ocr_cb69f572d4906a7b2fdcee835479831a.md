# Chapter 13 • IMPLEMENTING SYSTEM SECURITY

The ALL keyword is used a wildcard for both services and clients. As an example, you can use ALL to deny all services unless explicitly permitted by placing the line in hosts.deny:

ALL: ALL

Unless a service/client pair is explicitly specified in hosts.allow, TCP Wrappers falls to this catch-all entry in hosts.deny and denies the connection.

You can supplement ALL with the EXCEPT keyword, which allows you to make exclusions from the wildcard. Using this method, you can logically say something like "allow all services except Telnet from 192.168.1.2 and 192.168.1.3," which is much easier than listing every permitted service. The configuration for this example appears as follows in hosts.allow:

ALL EXCEPT telnet: 192.168.1.2, 192.168.1.3

TCP Wrappers drop all denied connections to syslog by default. The logs look like this:
Apr 10 14:45 app inetd[7536]: refused connect from 127.0.0.1

You can specifically specify the syslog and log level to use with the severity option. The following configuration from hosts.allow sends logs for denied telnet connections to the daemon.info facility:

telnet: ALL: severity daemon.info

You can then use an application like logferrer (see Chapter 6, "Monitoring Services") to watch for these kinds of logs and notify you of failed attempts to connect to private systems.

# Spawning External Programs from Within TCP Wrappers

The ability to spawn external programs for matching connections is a useful feature of TCP Wrappers. System administrators use this feature to set booby traps or trigger notifications of connections made from a specific location. This feature is especially useful for tracking potential attackers.

The spawn option runs an external command of your choice in a subshell, so you can specify arguments, redirect output, pipe to other commands. If you suspect a user that always Telnets from 192.168.0.2 has been trying to hack into your system, you could set up the following configuration to send an email when a user connects from that address:
telnet: 192.168.0.2: spawn (echo "They're back!" | mail root) &

Now you will know exactly when a connection is made from that address and you can monitor the user's activities as appropriate.

# Removing Unnecessary Services for inetd

inetd is the Unix "super server," listening for requests for various network services and launching the appropriate programs in response. Unfortunately, Unix distributions activate every service in inetd by default. Most of these services are unnecessary and are even vulnerable to various remote exploits.
