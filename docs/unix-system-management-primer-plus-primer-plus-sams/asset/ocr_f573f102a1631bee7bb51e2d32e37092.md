# Avoiding Problems with Overwritten Configuration Files

As with patches, operating system upgrades can overwrite your valuable configuration files if you're not careful. Well-known files like /etc/passwd, /etc/group, and /etc/shadow are usually all allowed by Unix system upgrades, as they contain important information. But other files may not be so safe, depending on the upgrade process. For example, in the upgrade you mentioned, you must be sure to make a backup of /etc/resol.conf, because that file contains name service configuration. You don't want that if the file is overwritten with a default file during the upgrade. (The earlier advice on making a full backup of any system before upgrading.)

Some operating systems have failsafe measures in place to deal with the problem of overwriting files. Red Hat's upgrade process, for example, uses RPM to upgrade its packages. RPM packages can identify files as configuration files to make sure they're not overwritten during an upgrade. This protection is not required behavior, however, it is never safe to assume that these files will be preserved during an upgrade. To ensure the preservation of your configuration files, back them up to tape or copy them to another directory for safekeeping. You can obtain a list of the files designated as configuration files by an RPM package with the following:

```
rpm -acp package-file argument is the name of the RPM file, which should end in .rpm
```

# Guaranteeing Adequate Disk Space for the Upgrade

Considering that your previous partitioning scheme was poorly optimized for the new version of the operating system, the new version may require more space than currently available.
