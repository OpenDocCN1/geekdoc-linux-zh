# Back-Tracking Through Multiple Addresses

The address that a user has connected from may be the first in a longer chain of addresses. For example, a user can Telnet from his desktop computer to server1, from server1 to server2, and from server2 to your system. You will need the cooperation of the administrators of each server to trace the connections back to the original user's machine. You should also take into account IP spoofing, which will make tracing this chain of addresses extremely difficult, if not impossible. You can read more about IP spoofing in the section titled "Exploits and Attacks" in Chapter 13.

# Using to Locate Remote Users

The who command displays a list of users who are currently logged in to your system, along with a number of statistics such as the user's remote address. Just filter out the user you are looking for with grep; the remote address is the last field. In this example, the user joeuser has logged in from server4.example.com:

```
bash$ who joeuser
joeuser pts/2      Apr 9 08:29 (server4.example.com)
```

# Using to Locate Remote Users

The last command shows all login activity for a system, including current logins. last is the first command you should use to look for historical login data. Here's how you use last:
last [-num] [username]
Without arguments, last displays all of the logins recorded on a system's wtmp log file (wmp on Red Hat Linux). If you supply a username, last displays only logins for particular user; you can also specify the number of logins displayed on the command line. The following example shows the response to a last command asking for the display of the last five logins for joeuser:

```
bash$ last -5 joeuser
joeuser pts/2      server4.example.com - Tue 9 08:29 still logged in
joeuser pts/2      pool-141-158-35 - Mon 8 17:59 - 20:18 (02:18)
joeuser pts/2      pool-141-158-35 - Mon 8 13:37 - 17:46 (04:09)
joeuser pts/2      pool-141-158-35 - Mon 8 13:37 - 13:37 (00:00)
joeuser pts/2      pool-141-158-35 - Mon 8 11:03 - 13:11 (02:08)
```

The remote server is in the third field, but there is a problem with it—the name is limited to 16 characters! This is the major pitfall with last; even today few operating systems support longer hostnames in last, the most notable of which is OpenBSD. You may need to rely on other logs to determine the hostname; TCP Wrappers can do this for you if you wrap remote login services like Telnet and SSH.

# Linux Failed Login Attempts

Red Hat Linux has a central database of failed login attempts in /var/log/btmp, which can be viewed with the last command. This can show who is trying to access accounts on your system even when they are not successful.
