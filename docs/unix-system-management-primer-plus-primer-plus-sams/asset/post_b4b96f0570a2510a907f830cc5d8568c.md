rsync can natively copy files to and from the same system, but it requires a separate network transport to copy files between machines. The default program is rsh, but you should change the default to something like ssh for its stronger authentication and encryption; you can do this with the -e flag. The syntax for rsync is similar to that of rcp, with a few fewer options.

- -a Archive mode; causes rsync to behave like tar and recursively copy directories, preserving ownerships and symbolic links
- -e Deletes files on the server that do not exist on the client file system
- -z Specifies an "rsh-like" command (such as ssh) to use in place of rsh as a network transport
- -z Compresses network communications

To synchronize /home/jeff/src on server1 and server2 using ssh as the transport, you could run the following command on server1:

```bash
bash$ ls -l src
total 16256
-rwxr-xr-x 1 jhorwitz staff 4075520 Mar 31 24:18 mrtg-2.9.17.tar
-rwxr-xr-x 1 jhorwitz staff 3763828 Mar 31 24:18 openssh-3.1p1.tar
-rw-r--r-- 1 jhorwitz staff 222608 Mar 31 24:15 syslog-ng-1.4.11.tar.gz
-rw-r--r-- 1 jhorwitz staff 234762 Mar 31 24:18 top-3.5beta9.tar.gz
bash$ rsync -avc -e ssh /home/jeff/src server2:/home/jeff/src
building file list ... done
/openssh-3.1p1.tar
wrote 002829 reads 36 bytes 94454.1 bytes/sec
total size is 8301410 speedup is 10.34
```

Note how the only file transferred was openssh-3.1p1.tar. The other files already existed on server2 and matched the files on the client, they were not transferred, speeding up the theoretical transfer by over 10 times.

# The Trailing Slash is important

The additional slash after the source path tells rsync to synchronize the contents of the directory, not the directory itself. This is important if you need the permissions on the destination directory to be that on the source directory.

You can also increase the speed for individual file transfers by making a small change to one of the files in src and resynchronizing that file. For example, the file sshd.c in the tar file openssh-3.1p1.tar was copied to another file in the same directory and the tar file was recreated with a small 43KB size. The file was transferred using rsync, rsync -z, ftp, cpf, and scp -C. Every command except for rsync transferred the entire contents of the file. Table 1.3 holds the summarized results; rsync using SSH with compression was the clear winner taking over 80% less time to transfer the file than the clearest ftp transfer.

# Using rdist to Distribute Files

All of the tools mentioned so far are concerned with copying or synchronizing files and directories; they have no provisions for relocating or renaming individual files in a large directory, or for copying more than one destination. rdist is a program for distributing files from a central repository to multiple remote hosts based on rules contained in a configuration file.

Almost all Unix distributions include a version of rdist, though it is usually an older version based on the original BSD 4.2 rdist. Newer versions with more functionality exist; the most popular of them is Magnicomp's rdist, which can be downloaded at http://www.magnicomp.com/rdist.

The rdist configuration file is called the distfile; it contains all of the definitions and rules rdist needs to properly distribute files. You can specify the distfile to use with the -f flag; otherwise rdist looks for a named distfile in the current directory.

The two major components of distfile are variables and rules. Variables are useful for creating a single name that refers to multiple files or hostnames, which in a larger distfile could become quite confusing. Rules dictate which distfile are used to distribute remote hosts. The following sections describe how to use these distfile components.

# Using Variables in a distfile

The parentheses are required when assigning list of values to a variable. A typical distfile for an Apache Web server configuration may have variable assignments like these:

```
WEBSERVERS = ( dopey grumpy sneaky doc )
DEVSERVERS = ( sleepy happy bashful )
FILES = ( /usr/local/apache/conf )
```

The value of a variable is referenced with the ${ construct; the value of the FILES variable in the previous example is ${FILES}.

# Creating Distfile Rules

distfile rules have the following format:

```
label: source_list -> destination_list command_list
source_list contains the files to be distributed, destination_list contains the list of hosts where the files should be distributed, and command_list is a list of optional commands to run on the remote host before or after copying files. If one of the sources is a directory, it is recursively copied to the destinations. label is an optional label that can be used on the command line to selectively run just parts of the distfile. Wildcards such as * and ? can be used in the list of source files.
```

Using the previously listed variable declarations to distribute the directory specified in the FILES to the hosts in WEBSVERS, you can write the following distfile:

```
WEBSVERS = (dopy grumpy sneaky doc )
FILES = ( /usr/local/apache/conf )
```

web: ${FILES} -> ${WEBSVERS}
Rules can also contain primitives, which are actions that rdist should take when updating remote files. Primitives are listed just below each rule, one ending with a semicolon. Some of the more useful primitives are as follows:

| except filename... | Omits files from distribution |
|---|---|
| except_pat... | Omits files that match the patterns |
| install [options] destination-name | Installs a file with a different name than its source |
| notify address... | Sends email to each address that lists the updated files |
| special [filename]...command-line | Runs a shell command after each file is updated |
| cmdspecial command-line | Runs a shell command after all of the files are updated |

You can use these primitives to automatically restart an Apache server after all of its configuration files are updated:

```
WEBSVERS = ( dope grumpy sneaky doc )
FILES = ( /usr/local/apache/conf )
```

```
web: ${FILES} -> ${WEBSVERS}
cmdspecial "/usr/local/apache/bin/apachectl" ;
```

# Running the rdist Command

Now that you have created the distfile, it is time to run the rdist command to actually distribute our files.
Like rsync, rdist requires a separate command to provide the network transport. By default, this command is ssh and cannot be changed in the original BSD 4.2 version of rdist. However, Magiccomps provides a flag for specifying alternate rsh-like commands. This and a few other command-line options are listed here:

| -f distfile | Specifies an alternate distfile |
| -m host | Only runs rules for the destination host |
| -P rsh-command | Specifies path to an alternate rsh-like command |

Assuming your distfile is named Distfile and is located in the current directory, you can run rdist as, using ssh as the transport command:

```
# rdist -P /usr/local/bin/ssh
sneeze: updating sneeze
sneeze: /usr/local/apache/conf/httpd.conf: updating
sneeze: /usr/local/apache/conf/mime.types: updating
sneeze: cmdspecial "/usr/local/apache/bin/apachectl restart"
sneeze: http restarted
sneeze: updating of sneeze finished
```

Note how Apache was restarted after all of the files were updated; if you had used special instead of cmdspecial, Apache would have been restarted after each file was updated.
