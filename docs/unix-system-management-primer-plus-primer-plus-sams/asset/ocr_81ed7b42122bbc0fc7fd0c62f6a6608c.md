# UNIX SYSTEM MANAGEMENT PRIMER PLUS

Solaris is a bit more complicated (as usual): You must disable all of the other possible modes and enable only the speed and duplex combinations that you want. You can accomplish this in /etc/system, as follows; the disabling takes effect upon reboot (you can use ndd to perform these operations without rebooting, but the settings will not persist across reboots):

```
# Full Duplex 100 Mb
set hme_adv_autoneg_cap=0
set hme_adv_100fdx_cap=1
```

```
# Half Duplex 100 Mb
set hme_adv_autoneg_cap=0
set hme_adv_100fdx_cap=0
set hme_adv_100hdx_cap=1
```

```
# Full Duplex 10 Mb
set hme_adv_autoneg_cap=0
set hme_adv_100fdx_cap=0
set hme_adv_100hdx_cap=0
set hme_adv_10fdx_cap=1
set hme_adv_10hdx_cap=0
```

```
# Half Duplex 10 Mb
set hme_adv_autoneg_cap=0
set hme_adv_100fdx_cap=0
set hme_adv_100hdx_cap=0
set hme_adv_10fdx_cap=1
set hme_adv_10hdx_cap=1
```

You can configure a NIC in OpenBSD to full duplex with ifconfig, as follows, but only if your card supports it.

```
# ifconfig x10 media 100baseTX mediaopht full-duplex
```

In order to persist across reboots, you must configure this in /etc/hostname.INT, where INT is the name of your network interface. For example, in /etc/hostname.x10.
inet 10.1.1.1 0xffffff 10.1.1.255 media '100baseTX' mediaopt 'full-duplex'

The settings for Linux NICs are vendor-dependent, and there is no generic method to hard-code the duplex. See your NIC vendor's documentation for more details.

# Prioritizing Important Traffic

A WAN connection like a T1 or T3 is usually not limited to carrying just one protocol. A typical T1 to the Internet might carry well over ten Internet protocols at any time during peak usage, including HTTP, SMTP, and DNS. A T3 between two data centers carry more application-specific traffic, such as Oracle SQL*Net or NFS. In either case types of traffic are probably more important than others, and you should prioritize them to ensure their timely transport.
