Though RAID-4 offers excellent redundancy, its use does have some drawbacks; the biggest of these is its poor performance. Since each RAID-4 partition has one parity disk, all writes to that partition result in a write to that single parity disk, making it a significant bottleneck.

# How Parity Works

Parity is a fast and simple way to check for correct errors in a sequence of bits. in parity identifies whether there are an even or odd number of ones. This information enables you to figure out the value of a missing bit anywhere in the string by counting the number of ones and comparing it to the parity bit. A parity value of one indicates an odd number of ones, and a parity value of zero indicates an even number. For example, assuming a parity value of 1, the missing bit in the following bit string is 1, as there are an even number of ones in the string. a parity value of 1 indicates that there should be an odd number of ones.

Interestingly enough, the result of the common logic operator XOR (exclusive or) is 1 for an odd number of "1" operands, and 0 for an even number:

```
0 1 XOR 0 = 1
1 XOR 0 XOR 0 = 0
1 XOR 0 XOR 1 = 0
1 XOR 1 XOR 1 = 1
```

What makes it all work is the transitive nature of XOR. You can rearrange all the bits in an XOR equation, even switching sides of the equation, and it still be correct. That means you can calculate the value of a missing bit by XORing the bits for which you know the values, including the parity bit.

This makes parity calculations extremely fast since the XOR operation is native to all processors. The same operations are used in actual RAID-4 and RAID-5 configurations, only on a much larger scale.

# RAID-5

RAID-5 was designed to solve the RAID-4 problem of the overworked parity disk. It does this by striping the parity across all of the disks in the partition, just as it stripes the data (see Figure 10.10). This arrangement enables as many disks as possible to contribute to parity storage. Parity calculations in RAID-5 remain the same as with RAID-4.

# Real-World Example: Optimizing RAID-4

Network Appliance uses RAID-4 in its filters successfully despite its inherently poor write performance. It does this by tightly integrating RAID-4 with its file system, WAFL (Write Anywhere File Layout). When possible, WAFL schedules writes to the same disk stripe at the same time. WAFL limits the distance the heads must travel on the parity drive between writes and thus dramatically improves write performance.
