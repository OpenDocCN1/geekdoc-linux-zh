Another method to avoid shell character exploits is to pass the arguments directly to the command you are running and not shell at all. C and Perl make this very easy to do.

Use one of the exec functions to pass arguments to a command in C, as follows:

```
args[0] = "fu";
args[1] = username;
args[2] = NULL;
execve("/bin/ps", args);
```

In Perl, just separate arguments into a list instead of passing them to system as a single string, as follows:

```
system("ps", "-fu",username);
```

# Shell Escapes

Some commands allow you to spawn shell commands from within their own processes. vi is such a program; typing ls from "ex" runs the ls command in a subshell and returns to vi. If you are using sudo to edit user files as root, you are actually allowing them to run any command as root! The three most common interactive Unix commands that allow commands to be in a subshell include:

+   - vi
- more
- less (can be disabled)

Check your sudo configurations, special user shells in /etc/passwd, as well as any setuid programs to make sure these commands are never run as root or any other privileged user.

# Buffer Overflows

Buffer overflows were the most popular exploit in the late 1990s. These exploits take advantage of the fact that C does not prevent you from writing past the end of a buffer, a fixed amount of memory aside for storage of program data. For example, the following code is perfectly valid in C, though it may produce a runtime error:

```
char string[10] = "Hi there!";
string[20] = 'a';
```

The variable string is ten characters long (string[10]), but string[20] = 123 sets the 21st character of string to 'a' (string[0] is the first character), which is beyond the end of the buffer allocated for string. This was done on purpose, but many functions in the standard C library do not check for these overflows, such that many programmers unintentionally expose their programs to buffer overflows. strcpy strcpy copies one string to another as follows:

```
strcpy(destination, source);
```
