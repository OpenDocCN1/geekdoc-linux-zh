# Changing Nice Values

Any user can increase the nice value of his or her own processes, but only root can decrease the nice value of a process. This means that when a user increases the nice value of a process, he she can cannot decrease it back to its original value.

You can set a process's nice value on the command line before the process is run, in order to tune down the CPU usage of processes you know will cause a problem. For example, the following command clears old files from temporary directories:

```
# -n 10 find 10 /var/tmp -mtime +14 -type f rm -f {} \&
```

top can verify the nice setting (Solaris), as shown here:

| PID USER THRI NICE SIZE RES STATE TIME COMMAND |

| 16107 root 1 48 312K 312K sleep | 0:00 0.07% sh |
| 16165 root 1 28 912K 664K sleep | 0:00 0.08% sleep |
| 16098 root 1 58 2280K 2184K sleep | 0:00 0.03% ssh |
| 21928 root 1 58 1650K 888K sleep | 0:24 0.0% prngd |

| 22000 root 1 58 2632K 1736K sleep | 0:04 0.00% ssh |
| 223 root 7 53 7920K 7260K sleep | 0:02 0.00% nscd |

You can prioritize processes using the renice command. The following command increases the nice value of the sleep process by 5:

```
# renice -n 10 16165
```

This command changes the process's nice value by 10:

```
# renice -n -10 16165
```

# Other Scheduling Implementations

This chapter discusses the renice command because it is universal to all Unix systems. However, many operating systems have their own priority scheduling mechanisms; Solaris is one of the many powerful scheduling implementations, but it is beyond the scope of this discussion. See the Solaris manual pages for prioritycntl and dispadin for more information on that implementation.

# Using Multiple Processors
