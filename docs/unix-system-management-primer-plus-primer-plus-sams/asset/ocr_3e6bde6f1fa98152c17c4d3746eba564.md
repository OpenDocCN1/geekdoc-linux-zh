# Establishing Policies for Physical Security

The physical security of an organization protects its various sites and physical property from unauthorized access or damage. Some items you might see documented in a physical security policy include:

+   - Entry/exit access mechanisms (such as keys and card readers)
- Logging requirements for office visitors and vendors
- Logging requirements for hardware brought into a data center
- Visual monitoring requirements (such as cameras)
- Methods of disposal for sensitive documents (such as shredding)
- Removable media restrictions (for example, employees cannot copy confidential files onto a floppy disk and remove it from the office)
- Storage requirements for sensitive paper documents (for example, put them in a fire safe)

Many system administrators are so preoccupied with the system and network side of security that they neglect the physical aspects of security. A server that has been hardened at the operating system level and sits behind a well-configured firewall may be relatively safe from remote hackers. But if that server is not properly locked in your data center, anyone with a serial cable or a CD-ROM could potentially access that system from within your own borders. Make sure your security policies include ample guidelines for ensuring the physical security of your system.

# Require Passwords for Single-User Mode

With access to the physical console of a Unix system can reboot it into single-user mode. Although most Unix operating systems require the root password to enter single-user mode by default, Red Linux does not. You can require the password by adding the following line to /etc/inittab:

```
ss:S:once:/bin/sologin
```

However, entering single-user mode is not the only way to gain root access without a password. You can tell LILO (LILO Loader, the default boot loader for Red Hat and other Linux vendors) to boot directly into LILO altogether. Type linux init=/bin/bash at the LILO prompt to see this in action.

Fortunately, you can configure LILO to require a password before booting using the restricted and password parameters in each boot image section. The restricted parameter tells LILO that access to the image is restricted, and the password parameter sets the password in clear text. Add the following lines to /etc/lilo.conf, changing "mypass" to another password and run the lilo command to activate your changes:

```
restricted
password=mypass
```

You should also use chmod to only allow root to read /etc/lilo.conf, as the password is stored in clear text.
