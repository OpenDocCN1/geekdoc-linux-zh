# Failover Clustering

A failover cluster consists of a single active server and one or more standby servers; if the active server fails, a standby server can take over. Using failover clustering requires extra software and support in the kernel to be able to transition the exact state of one machine to another. A server failure typically causes a short pause in operations before the standby server automatically takes over services. Adding redundancy to the cluster is as easy as buying another server.

# Use Identical Hardware in Failover Clusters

Try to use identical hardware for each server in your cluster. This ensures that performance for your applications will be the same on the standby server as it is on the active server. Some clustering software may require identical hardware.

Unix vendors that offer failover clustering solutions include:

+   - Sun Microsystems: Sun Cluster (Solaris)

+   - Veritas: Veritas Cluster Server (HP-UX and Solaris)

+   - Hewlett Packard: MC/ServiceGuard (HP-UX and Linux)

# Parallel Clustering

Parallel clustering pools the resources of many machines to create one large parallel server. Parallel clustering provides dramatic server performance enhancements, when properly optimized, complex calculations that would take days on a single-CPU server might take minutes when executed in a large cluster with multiple CPUs and massive amounts of memory. If one server in a parallel cluster fails, the system loses processing power only; other processing continues and the clustering software relocates the job scheduled on the failed server to another available server.

Unix vendors that offer parallel clustering solutions include:

+   - The Beowulf Project (Linux)

+   - IBM: Eserver Cluster Edition (AIX and Linux)

+   - SGI: Advanced Clustering Environment (IRIX and Linux)
