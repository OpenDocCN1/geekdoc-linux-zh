# Planning for Storage Needs

Planning for future storage capacity should be a priority for any system administrator. Historically, no other computing resource exhausts itself as quickly as disk space. To keep your system functioning smoothly, you need to be prepared for increases in storage needs as well as the long-term storage needs of your organization. This involves proper allocation of disk resources, monitoring usage trends over time, and taking advantage of operating system features such as quotas and logical volume managers to dynamically control the space available for user data and file systems in general.

# Monitor Disk Usage Trends

Disk space utilization typically increases either through short spikes in demand or as a result of long-term growth. Bursts of disk usage occur when a user downloads a large file or a DBA adds another file to a database. Planning for these events is difficult; however, maintaining at least 20% free space available on each file system avoids usage problems resulting from these spikes.

Long-term growth, on the other hand, usually follows predictable trends. Monitoring usage over time is easy with SNMP-based tools like MRTG or RRTool; these tools query your systems periodically. Of course, you can write your own monitoring tools using Unix commands like df and du. In a minimal environment, a daily disk-space check is a reliable monitoring practice, and it familiarizes you with your system's usage trends.

No matter which you choose to monitor disk space, it is absolutely critical to correlate the usage trends with business goals. If an email service with 10,000 consumes consumes an 1% of your total storage every week, it's a good bet that 20,000 users will consume 2% every week. You can use this data to predict future costs and plan for the thinning of new disk purchases.

# Allocate Enough Space for Each Partition

File systems traditionally reside on fixed-size partitions; after you create a partition, you can't easily increase or decrease the size of the file system. To avoid the need for changes, you must know the storage requirements of the resident file systems while the disk is being partitioned. Allocating space to file systems without prior planning almost guarantees that one file system won't have enough space, while others will be highly underutilized.

# Expand Striped RAID Devices

Typically, you can expand RAID devices by adding additional disks to the RAID configuration. This solution is especially useful when you need more space on a file system that resides on a RAID device. The procedures for adding disks to the RAID configuration are implementation-dependent—check your RAID hardware and software documentation for details (note that the file systems on these disks must support this growth as well).
