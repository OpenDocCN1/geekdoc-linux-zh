# Implementing TCP Wrappers

You can implement TCP Wrappers in two ways. Programs can support it natively or you can run it as a process through inetd, after which the software spawns the program it is wrapping. SSH and wu-ftpd are two of the few mainstream applications that support TCP Wrappers natively—you do not have to run them out of inetd to enjoy the benefits of TCP Wrappers. For most other applications, such as telnetd and ftppd, you need to run them out of inetd.

Configuring TCP Wrappers in inetd is easy. Each service in inetd's configuration file inetd.conf is represented on one line. If you are interested in the sixth field of each line, which contains the path to the server program. TCP Wrappers replaces this program with its own program called tcpd. tcpd is responsible for reading the TCP Wrappers configuration files, deciding whether the incoming connection to a particular service is allowed, and taking appropriate action.

If you want to wrap the Telnet service, you must change its inetd.conf entry from telnet stream tcp nowait /usr/sbin/in.inetd telnet

telnet stream tcp nowait /usr/sbin/tcpd in.telnetd

assuming the path to the tcpd program is /usr/sbin/tcpd. Use the last field to tell tcpd which server program to run if the connection is permitted. For existing services, you can usually leave the current value intact.

After editing inetd.conf, restart inetd by sending a HUP signal to the inetd process (kill -HUP PID), and your configuration will be activated.

Red Hat Linux and some other Linux distributions have moved to xinetd, a radically different version of inetd. Instead of using a single configuration file, xinetd has the ability to break up the configuration into multiple files; Red Hat Linux uses one file for each service. Red Hat's installation of xinetd supports TCP Wrappers by default; all you need to do is discover the names of the services to use in the TCP Wrappers configuration by looking in each xinetd configuration file. The service name is specified after the service keyword. For example, the service configuration looks like this:

service telnet {

```
    disable = no      = REUSE
    flags == stream
    socket_type = no
    wait == root
    user == root
    server == /usr/sbin/in.telnetd
    log_on_failure += USERID
```
