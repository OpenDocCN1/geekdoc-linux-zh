# Alternative Authentication Methods

Authentication represents the most glaring security hole in most organizations. Many sites simply require a username and password for user authentication, and that is sufficient for most sites. However, when you think about how easy it is for someone to guess a password, sniff a network connection, or even just look over your shoulder while you are typing a password, quickly understand that usernames and passwords are not the most secure authentication mechanism by any means.

Unix, like most operating systems, is capable of supporting alternative authentication methods. This section documents some of the more common methods in practice.

# Pluggable Authentication Modules

Red Hat Linux, HP-UX, and Solaris support pluggable authentication modules, or PAM. PAM separates authentication mechanisms from the application code so you can change how your users without changing a line of code. Authentication code comes in the form of shared objects that are dynamically loaded by the application. A configuration file called pam.conf controls which authentication mechanisms are associated with which applications. Many of the functions documented in this section of the chapter are available as PAM modules. You can read more about PAM at http://www.sun.com/software/solaris/pam.

# One-Time Passwords

When you are traveling and have no access to encryption software such as SSH or a VPN, your last resort for remote access is Telnet. However, typing a password over a clear channel can be very dangerous, because anyone might be listening. One-time passwords, or OTP, solves this problem.

One-time passwords are used once and only once for the same account, and prevent anyone from sniffing a valid password off of the network. Typically, a user prints out a list of passwords generated by the OTP system and uses those passwords one by one in order. You also can use the OTPs in conjunction with regular passwords to provide two-factor authentication.
