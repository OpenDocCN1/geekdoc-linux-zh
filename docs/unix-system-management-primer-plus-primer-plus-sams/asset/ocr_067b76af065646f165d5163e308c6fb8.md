If you pass "messages" to this script, it returns the contents of /var/log/messages. You might assume that this command displays only the files in /var/log, but that is certainly not the case. You could easily insert "...", the parent directories, and move up the tree to display any file the Web server has permission to read, such as /etc/passwd. The string ../etc/passwd causes the script to move up two directories to read the passwd quite easily.

Unfortunately, the fix to this problem is easy; you must write some code to verify that the input string does not contain any slashes, as follows:

```
if (Slogname =~ /\/) {
    print "Illegal character in log name!\"
}
```

# IP Spoofing

Network traffic is not immune to exploits; in fact, the entire IP protocol, when not encrypted through IPSec or other mechanisms, is quite vulnerable. IP spoofing is one of the easiest ways to exploit a network; it works by fabricating IP packets on a system with forged source addresses. Hackers typically use this exploit to accomplish one of the following goals:

+   - Gain access to a system that uses address-based access mechanisms
- Conceal the actual source of an attack
- Launch a distributed denial-of-service attack against the spoofed source address

An address-based access system like rhosts mechanism is not of much use if the source IP address can be forged. Adding to this concern is the unnerving fact that attacks using spoofed source addresses are nearly impossible to trace back to their true source.

Luckily, routers provide a mechanism to avoid both of these situations. By installing a router or firewall in your system, you can deny all inbound packets with a source address of one of your internal networks. After all, if your internal network is 192.168.1.0, you never should receive a packet from the outside with the same address. In fact, you should configure your routers to deny all packets from public networks that have source addresses in the Internet Assigned Numbers Authority private network ranges or your own public addresses. These are summarized in Table 13.1.

# TABLE 13.1 IANA Private Networks

| Network | Address Range |
| --- | --- |
| 10.0.0.0/8 | 10.0.0.0 – 10.255.255.255 |
| 172.16.0.0/12 | 172.16.0.0 – 172.31.255.255 |
| 192.168.0.0/16 | 192.168.0.0 – 192.168.255.255 |
