# Automating Root Logins

Most administration tasks require root privileges at some point. Tasks are easy to run as root on a single machine, but the situation becomes more complex in multisystem environments where one machine may need to run a remote process or copy a file as root to another machine. In interactive situations, the administrator can simply log in to remote machines and su to using root's password; this option, however, doesn't work for automated processes. You don't need to put a root password in a script file, no matter how well that is protected.

# Using the Berkeley r-commands Without a Password

One of the oldest methods for executing commands on a remote system is using the Berkeley r-commands, named for their remote access capabilities. Three of the r-commands can perform tasks on remote systems:

+   - rcp—copy a file to or from a remote system
- rlogin—log in to a remote system
- rsh—run a command on a remote system

The r-commands allow you to log in or run processes on a remote machine without a password, even as root. Two configuration files on the remote server control your access: /etc/hosts.equiv and .rhosts. Both files contain lines of trusted hosts and users in the following-format:

hostname [username]

hostname is the name of the host from which password-less logins are allowed; username is the optional name of a user allowed to log in from that host. More than one username can be specified for the same host; if none are specified, all users are allowed to log in without a password. The only requirement for using r-commands is that the UIDs of the users are identical on both machines. A + can be substituted for either the hostname or username to match any in front of that host or user to deny access for that host or user.

/etc/hosts.equiv applies the access rules to all users on the machine; .rhosts lives in a user's home directory and only controls access to that particular account. For added security, /etc/hosts.equiv file must be owned by root and .rhosts must be owned by the user attempting access. This entire authentication mechanism is often referred to as an “hosts” authentication mechanism.

A few configuration examples might help.

To allow Jeremy from server1 to access his own account remotely, add the following to Jeremy's .rhosts file:

```
server1
```
