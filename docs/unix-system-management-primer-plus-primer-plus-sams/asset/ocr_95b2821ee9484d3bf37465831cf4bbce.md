+   - Single-threaded programs: Single-threaded programs, such as ls, cat, and most everyday Unix commands and shells have a single thread of execution within their scope of operation that can perform one task at a time. Multiple processors are of no benefit to these individual programs, as there is only one thread of execution to process. However, if many of these single threaded programs are running at the same time, as can occur on multiuser systems, multiple processors can ease some of the load by running processes

+   - Multiprocess Programs: Multiprocess programs spawn—which is known as forking in the Unix world—child processes to handle concurrent requests. Apache is a perfect example of an application that uses this strategy. When Apache is started, multiple http processes are forked, and the original parent process handles each incoming connection to one of the children. Each child process is single-threaded and can handle only one HTTP request at a time, but the concurrent processing of all the httpd processes makes the Web server much scalable, even on a single-processor system. If another processor is added, you can achieve true concurrency, where one http process is executing on one processor while another is executing on the other process

# The Price of Process-Based Multithreading

The price of process-based multithreading comes in the forms of memory and latency (delays in processing). Each separate process occupies portion of memory, and you must consider this when calculating the optimum number of processes to spawn. Latency occurs because forking a child process uses overhead, much of it involved in copying memory and allocating kernel structures. This overhead isn't much of a problem for individual processes, but it can add quickly as more and more processes are created in a short period of time. This is one reason Apache preforks several children ahead of time (Apache 2.0 will have an option to use threads instead of processes).

+   - True Multithreaded Programs: A multithreaded program can have multiple threads of execution within a single process. Unlike a process, creating a thread requires very little overhead, although threads execute independently of each other, each thread still has access to global data structures within the process. Most importantly, multiple threads within the same process can run concurrently on different processors, bringing the benefit of multiprocessing to single processes.

# Upgrading Processors

Processor speed is an important factor in overall system performance, but upgrading a CPU to a faster model doesn't always provide the performance boost you would expect. A process has to be using the CPU to benefit from a faster one. For example, you could significantly speed up a weather simulation program that performs millions of complex calculations by upgrading from a 400MHz processor to a 1GHz processor.
