# Chapter 4 • TESTING YOUR SYSTEMS 101

# Pad Your Schedule for Unforeseen Events

Always add in a few days to your deployment schedule to account for resolving problems such as compatibility issues.

# Determining What to Test

If you change a component of a system that interacts with any other component of that system or systems, you should verify that those components are still compatible with each other. Too often, a system administrator will install an application, make a configuration change, or apply a patch without testing to see how it affects other applications and systems.

Determining what interactions to test can be difficult because many aspects of a Unix system relate to each other and to other systems on a network. The most effective way to test interactions is to create a dependency tree for the component you are changing; list the things that depend on the changed component (dependent), as well as the things on which component relies (dependencies).

Hardware and software documentation should list many of the dependencies, such as required operating system versions, patch levels, and any required third-party software. However, determining the dependent components lies mostly on your shoulders because only you know how components of your system are being used. For example, if you have upgraded to a newer version of the Perl interpreter over your server, what other software have you installed that depends on uses Perl?

In general, the following common occurrences should warrant compatibility tests:

+   * Operating system upgrades and patches.
* Application upgrades and patches.
* Shared library changes.
* Replacing old or broken hardware with hardware of a different make or model. This includes cables.
* Configuration changes for major subsystems. For example, changing /etc/nsswitch.conf to use DNS for hostname lookups instead of local host files.

# Conducting Compatibility Tests

Procedures for a compatibility test are highly dependent on the components you are testing. For example, if you replace an Ethernet card in a server with one from a different vendor, you could verify that the server (a dependent component) detects the network interface using ifconfig -a; you then could attempt to ping another server on its network ( functionality of the ping command is dependent). You could also use netstat to check for network errors, which might indicate compatibility issues.
