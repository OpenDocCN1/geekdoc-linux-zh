# # Duplicate End User Conditions

Your environment should mirror the conditions that a typical user would experience. For example, if most of your customers are dial-up Internet users, test your site using a dial-up connection to the Internet. This gives you more insight into the overall "end user experience."

The logging subsystem is critical to Nearest Integer's operations; you can test it by having various coworkers around the log in to the site and go through several mock transactions, carefully noting their actions each time. You can then compare the system logs against the users' notes of transactions, to ensure that the system accurately recorded the transactions. If system logs and user notes do not match or any of the logs are failing, the logging subsystem has failed the unit test.

The system must also rotate and activate the logs every day at 3:00 a.m. You don't have to wait until hour to test this function; you can run the rotation and archiving procedures manually. If the procedures pass the unit test during the manual run, you can then set them to run automatically at 3:00 a.m. and check the results the following morning.

You know how the procedures work individually, but you must test to ensure that the tests work together as they do. A successful log rotation might result in the log directory structure, with logs renamed every night at 3:00 a.m.

```
bash ls -l
total 1292
-rw-r--r-- 1 root 272475 Feb 20 16:32 access_log
-rw-r--r-- 1 root 438923 Feb 20 02:57 access_log.1
-rw-r--r-- 1 root 534829 Feb 19 02:55 access_log.2
-rw-r--r-- 1 root 13122 Feb 20 16:32 error_log
-rw-r--r-- 1 root 16030 Feb 20 03:00 error_log.1
-rw-r--r-- 1 root 9482 Feb 19 02:59 error_log.2
```

In this case, log files are rotated by renaming them, appending numbers relative to the age of the files—access_log is the current log file, access_log.1 is the last rotated log, and access_log.2 is from two rotations ago. Assuming today is February 20, you can see that access_log.1 and error_log.1 were both last modified before 3:00 a.m. this morning, indicating that the rotation occurred at the appropriate time.

# Be Wary of File Modification Times

When files are moved into a Unix file system, only their name and potentially their parent directory structures are changed. The date and time in ls output reflect content changes, those fields may not correspond to the time they were moved.
