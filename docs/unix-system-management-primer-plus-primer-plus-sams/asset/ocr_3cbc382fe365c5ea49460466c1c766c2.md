# Tuning Memory and Swap Performance

The virtual memory subsystem on Unix operating systems relies heavily on both physical memory and disk; ironically, the swap performance often relies on the optimization of the swap partitions on disks. Much of the performance of memory and swap lie deep within highly optimized kernel code, but there are a few things administrators can optimize memory and swap performance. These tuning measures include tweaking various operating system-specific settings, optimizing the placement of swap partitions, and taking advantage of programming techniques that maximize the use of memory.

# Using Solaris Priority Paging

File system caching can severely degrade the performance of virtual memory on Solaris 7 and earlier, Sun introduced a new paging algorithm called priority paging. Priority paging limits the size of the file system cache. When the free list shrinks to a certain limit (called cachefree), the operating system begins to reclaim file system cache pages by processes, keeping the free list well above the dangerous lotsfree low-water mark at which the daemon begins scanning.

You can enable priority paging in Solaris 7 and earlier by adding the following line to /etc/sys-config and rebooting:

```
set priority_paging=1
```

# Don't Set Priority Paging in Solaris 8

> Never set this variable on a Solaris 8 system—Solaris 8 includes a more elegant solution called cyclic caching that eliminates the need for priority paging.
