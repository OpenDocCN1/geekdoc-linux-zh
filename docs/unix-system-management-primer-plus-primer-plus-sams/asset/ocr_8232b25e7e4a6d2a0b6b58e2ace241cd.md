# Use a umask to Ensure Default File Permissions

A umask is a number that specifies file permissions are not allowed to be set for newly created files; you can use a umask to prevent other users from having access to your files by default. Ensure that the umask of a user who wants to share files within a group is 002 or 007, so directories are group-writable. You can learn more by reading the umask man page.

# Real-World Example: Replacing World-Writable Permissions

A small group of developers needed access to each other's source files, so they simply made each file world-writable (writable by everyone), not understanding the associated security risk. The system administrator came across these files a few days later and realized that the developers needed group-writable files, so he created a new group for the developers. Because the developers were creating new files and directories on a daily basis, the administrator decided to use the setgid method to manage the group permissions. The administrator changed the group assignment on all of the developers' files and directories to this new group, removed the "other" write bit from the files, and set the setgid bit on each of the directories. The developers now had a much more secure repository, and no work was required on their part to maintain it.

# Exploits and Attacks

The Internet today is riddled with programs designed to disable, destroy, or break into other systems. It is a system administrator's job to ward off these attacks and keep services available and data secure. The two most common types of attacks on a Unix system are exploits for privileged accounts, which use bugs in programs and poor configurations to gain unauthorized access to accounts, and denial-of-service attacks, which render services unusable.

In the sections that follow, you learn how some of the most damaging Unix system attacks occur, and some effective techniques for preventing them from invading your systems.

# Script Kiddies

Many exploits are packaged into a convenient script that can be run by anyone with the least bit of computing knowledge. You can find these scripts on hacker Web sites, security Web sites and mailing lists, and IRC (Internet Relay Chat). People who use these scripts are commonly known as "script kiddies," as most of them are teenagers to break into systems to run IRC bots or their own Web servers.
