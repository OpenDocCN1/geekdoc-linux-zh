# Real-World Example: Last-Minute Testing Checklist

A company that was about to deploy a Web site for its users failed to plan for full-site testing, and system administrators caught this oversight just two weeks before the site was to launch. The CTO of the company held an emergency meeting, and the developers, system administrators, and DBAs all came up with a master checklist of items to test, from the user log in page to performance requirements for the site. The testing process took the entire two weeks to complete, but it allowed everyone to find bugs and performance problems that would otherwise have caused the deployment to fail.

# Unit Testing

The simplest test to execute and understand is a unit test, unit tests determine whether each functional unit within the system is working properly. Unit tests examine a wide variety of system components and functions, including authentication, system logging, a Web server, or reboot recovery. The system passes the test when each functional unit works according to its original specifications.

# Programmers Use Unit Tests, Too

Professional programmers use unit tests to test each functional unit of a program (rather than a system) before testing the program as a whole. Individual unit testing significantly reduces the number of places administrators must look for errors when they discover bugs.

# Determining What to Test

In most cases, you won't need to perform unit tests on each and every functional unit of a system. These tests could take months and are unnecessarily redundant, as all operating system and software vendors typically run unit tests on their products before they reach their data center.

The most important aspects of a system to test are those that affect the intended use of that system. For example, if you are deploying a new Web server, you would want to test the following functional units of that Web server:

+   * Startup and shutdown scripts
* Access and error logging
* Serving static HTML files and images
* Serving dynamic Web pages like CGI scripts or Java servlets
* Accessibility from the Internet
* Access controls on protected content
