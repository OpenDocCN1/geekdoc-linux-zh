# Testing Release Candidates

Release candidate testing goes one step beyond beta testing. Release candidate products contain code that the company believes is ready for release, but that might still contain some minor, yet undetected, bugs. In a beta test, the release candidate system is made available to end users for comment, and any last-minute bugs that they find are fixed. Also as beta tests, companies might issue multiple release candidates for a product before it reaches a point when it becomes suitable for public consumption.

One reason to issue a release candidate is so developers who use your systems have a chance to update their software on new systems. This is especially important for users who run a lot of their own scripts and programs on your system—they may need time to rewrite their code to work with your new system. Using an example from the operating system business, Sun will release early access versions of Solaris to developers so there are products available when it is eventually released to the public.

# Summary

Testing is an essential part of any system administrator's or developer's normal routine. The deployment process is complex and the final product must please a wide variety of people, including the system's users and the company's upper management. To make the deployment a success, everything must work as documented.

Unit testing is a good start, making sure every functional piece of a system works as it should. To guarantee that no compatibility issues remain in the system, conduct compatibility testing. Load testing stresses the system as a whole; load tests pinpoint the system's breaking points and help ensure that the system performs to specifications. User testing is the final phase of the process. Alpha tests, beta tests, and release candidate tests offer your users early access to products and systems while helping you gather valuable input on bugs and function issues in your system. No matter what your business is, testing is crucial to the success of your products. Remember: there is no such thing as too much testing.
