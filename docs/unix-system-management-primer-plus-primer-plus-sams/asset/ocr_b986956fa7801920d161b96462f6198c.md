sudo requires a user to enter his or her password for authentication before running the command. This password protection prevents someone from wandering over your computer while you are away running commands as root. To minimize the hassle of entering a password for every command, sudo maintains a timestamp file for each user that allows users to run commands for a default of five minutes without re-entering a password.

You can see a good example of how sudo works by running the id command, which displays the UID of the user command.

```
$bash id
uid=1000(jeff) gid=1000(jeff) groups=jeff, 0(wheel)
bash-2.05$ sudo id
```

We trust you have received the usual lecture from the local System Administrator. It usually boils down to these two things:
#1) Respect the privacy of others.
#2) Think before you type.

```
Password:
uid=0(root) gid=0(wheel) groups=1000(jeff), 0(wheel)
bash$ sudo id
uid=0(root) gid=0(wheel) groups=1000(jeff), 0(wheel)
```

Note how the second instance of sudo does not require a password. If five minutes had passed between the two commands, sudo would have asked for a password.

If a user is not permitted to run a command, the following error is displayed:

```
$bash$ sudo id
jeff is not in the sudoers file. This incident will be reported.
```

# Specify Your Identity

By default, sudo assumes you want to execute commands as root. If you want to run a command as another user, specify that user by adding the -u flag to the sudo command.

The sudo configuration file is /etc/sudoers, and should only be edited with the visudo command. As crontab does for user crontab files, visudo checks the syntax of the sudoers files and reports any errors with the configuration. sudo has the following three main parts:

+   - Aliases
- Defaults
- User specification
