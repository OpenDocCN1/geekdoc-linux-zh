# Chapter 14 · INTERNAL COMMUNICATION

The last item in this list—the back-out plan—protects both you and the other users and administrators of your system. A back-out plan is a list of detailed instructions for "undoing" any change made to the system. The back-out plan gives you a concrete procedure to follow if a system change fails, and explains how to revert your changes in case you are not available to do the work yourself. The back-out plan should be comprehensive—anyone with the appropriate access and a reasonable knowledge of your systems should be able to bring the system back to the exact state it was in before the change was made.

Following is an example of a poorly written plan for backing out of a Web server deployment:

+   1. Shut down the new server.
2. Change the IP address on the old server back to what it should be.
3. Start Apache and make sure it works.

As the Web server's administrator might understand these instructions, but they're too vague and ineffective to help most users. A more appropriate back-out plan procedure might look like this:

+   1. As root, shut down the new server using the shutdown command.
2. Log in to the old server and su to root.
3. Change the IP address back to the original Web server address (192.168.1.80) by typing `ifconfig hme0 inet 192.168.1.80` up.
4. Restart Apache by typing `apachectl restart`.
5. Tail the error log in `/usr/local/apache/logs/error_log` to verify that the server started properly.
6. Test the Web server by connecting to `http://www.example.com` with your browser and verify that the site page is displayed.

The deployment of a new Web server should be accompanied by a change log like this:

Time of change: Mon Apr 5 12:01:00 EST 2002
Time takes effect: Mon Apr 5 12:01:00 EST 2002
Responsible people: Jeff, Scott
Where the change was made: the web servers apple and orange
Which services are affected: corporate web site
Reason for change: deploy more scalable hardware
Back-out plan:
1. Shut down orange using shutdown command.
2. Login to apple and su to root.
3. Change IP back to 192.168.1.80 by typing ifconfig hme0 inet 192.168.1.80 up.
4. Restart Apache by typing `apachectl restart`.
5. Tail `/usr/local/apache/logs/error_log` to verify that the server started properly.
6. Test the site by connecting to `http://www.example.com` and verify that the home page is displayed.
