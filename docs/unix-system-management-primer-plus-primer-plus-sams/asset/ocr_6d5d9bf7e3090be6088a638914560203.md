```
# chgrp web httpd.conf
# chmod g+w web
# ls -l httpd.conf
-rw-rw-r-- 1 root      web 33998 Jul 17 2001 httpd.conf
```

Users need special privileges over membership in the web group to edit this file. This arrangement is much more secure than giving your Webmaster privileges just to edit a file.

The setgid bit plays an important role in group write permissions. Normally to run programs with specific group permissions, the setgid causes all new file system objects created within a directory to inherit the group ownership of that directory. This type of permission is important for shared directories where many people with potentially different group memberships are making changes to the same files. Instead of giving these people access or forcing them to chgrp files as they are created, you can use the setgid method to ensure that files are owned by the appropriate group.

# Group Ownership on BSD

Directory inheritance of group ownership is the standard behavior on BSD variants of Unix. The setgid method forces this behavior on System V like Solaris and the Red Hat Linux.

Consider the following as an example:

```
drwxwsxr-x 2 jeff      shared 4096 Apr 19 10:22 shared1
drwxrwsxr-x 2 jeff      shared 4096 Apr 19 10:22 shared2
```

Both directories are owned by the user jeff and the group shared, and writable by the group shared. The shared2 directory has its setgid bit set by running chmod g+s shared2. Assume these directories are being used to share source code among developers in the shared group. What happens when the user scott, who belongs to the shared group but primary group is staff, creates a file in each of these directories?

```
bash groups
staff shared
bash touch shared1/file1
bash touch shared2/file2
bash ls -l shared*
shared1:
total 0
-rw-rw-r-- 1 jeff      staff       0 Apr 19 10:32 file1
shared2:
total 0
-rw-rw-r-- 1 jeff      shared     0 Apr 19 10:33 file2
```

The file created in shared1 has a group of staff, scott's primary group. That behavior is normal on System V, where the primary group of the user who creates a file object becomes the default group of the newly created object. But you don't want that arrangement here, because members of the shared group must be able to edit this file.
