# UNIX SYSTEM MANAGEMENT PRIMER PLUS

Root account management also poses a security risk for your users and any sensitive data stored on a system, as root is free to view or modify any local files and sniff network traffic flowing and out of the machine. As a system administrator, you need to become familiar with the techniques for properly managing your root account, as discussed in the sections that follow.

# Limiting Access to Root Passwords

Guard your system's root account password carefully. Reveal the root password only to the people responsible for administering a system. The password is necessary for installing software, changing system configuration files, and similar administration tasks. Technicians can perform most privileged tasks using group permissions or by installing programs to run commands on behalf of a regular user (you learn more about these techniques in "Delegating Authority" later in this chapter).

# Choosing Secure Root Passwords

One of the most important things you can do to protect your root accounts is to secure passwords for them. A secure password is one that casual users can't easily guess and isn't susceptible to "dictionary attacks" using variations on random words. The root password should contain a combination of letters, numbers, and punctuation, and should be at least six characters long—though eight or more is better.

If you are responsible for more than one system, as many system administrators, you may want to consider creating a root password scheme. This scheme combines a fixed string of characters with the names of your systems to create root passwords for each individual system. The alternative is to use a completely different password for each server, but remembering all of the passwords can be difficult. Using a root password scheme, each machine has a different root password, but those are easy to remember because they are based on one fixed string of characters.

For example, you could choose the string uif4e! (Unix is for everyone); and form passwords by surrounding it with the first and second letters of a system's hostname. The root password on a system named apple, for example, would be uif4eip!, while the password on orange would be uif4eir. If someone managed to guess the password on apple, it would be useless on orange, minimizing the damage caused by a cracked root password.

# Disguise Your Password Scheme

Someone who happens to guess or otherwise discover a root password based on a system may be able to infer the secret just from that discovery. You can make your schemes less obvious by using characters other than the first letter of the hostname and embedding those characters within the scheme's string instead of surrounding it.
