# # High-Availability Options for Internet Services

The infrastructure that makes the Internet work in the first place contains its own high-availability features. You can use this same infrastructure to achieve high availability for your services. Some of the most common high-availability services on the Internet include DNS and SMTP. Previous chapters of this book have mentioned these services, but the following sections discuss them specifically in connection with their contributions to high availability.

# # Using Redundant Name Servers

Without DNS, the Internet would cease to function—users would be lost in a world of dots and numbers. On a smaller scale, a failed DNS infrastructure can render a company's online presence useless, as the company's domain name no longer resolves to any meaningful address. For this reason, every domain name on the Internet is actually required to have at least two separate authoritative name servers to serve its zone (RFC 2182).

While it is tempting to just buy more servers and plug them into your existing networks, think about what happens in case of a network failure. If all of your servers are on the same network, a network failure makes them all unavailable to the rest of the Internet and brings down your Internet presence. A more reliable implementation would place one or more servers on at least two physically and logically separate networks, optimally from different providers or backbone. This arrangement minimizes the impact of small local network failures and major backbone outages. A good example of the use of redundancy is yahoo.com, which has name servers on five different networks, as a simple who will tell you:

# # Changing Important Addresses

Your names probably includes several addresses that you consider critical to your business. Addresses of Web servers, name servers and MX records, for example, are addresses you cant live without. Eventually these addresses will need to be changed (due to an upgrade or a relocation, for example), and you can't afford to make a mistake when handling these changes.

DNS relies on caching name servers to the Internet to cache records received from authoritative name servers. These records are cached for, at most, the time to live (TTL) for the zone in question; during time the authoritative server is not contacted for cached records. This lack of contact means that a caching name server could potentially ignore all changes for a zone until the TTL expires, which could have disastrous consequences if you make a mistake in a zone with a TTL.
