# UNIX SYSTEM MANAGEMENT PRIMER PLUS

Every IT organization develops its own specifications for system documentation, but most system administrators document the following three types of information:

+   - Network maps draw the network architecture and are used by administrators to locate, identify, and trace paths between devices within the network.

+   - Host functionality data documents the services running on a network and the systems that host and use those services; this documentation is useful for planning system maintenance or tracking the score of failures.

+   - Procedural documentation records the "how to" of processes used to maintain and run each system and service, so both system administrators and users have clear step-by-step instructions for performing critical tasks.

The sections that follow describe these types of documentation in more detail.

# Targeting Documentation to Audience Expertise and Needs

As you saw in the preceding section, writing useful system documentation involves more than simply jotting down your instructions for using the system. System documentation contains different types of information, and it's also used by people with varying levels of expertise. These people use system documentation for different reasons, as well, so system documentation must be written to address the technical proficiency and needs of its target audience. In general, system administrators must craft documentation to be useful to the three types of users:

+   - Other system administrators or technical staff, who use system documentation for maintaining the devices and services for which they are responsible. Communicating with technical staff is easy for system administrators, because this audience understands technical jargon and is familiar with most processes.

+   - Nontechnical staff often use system documentation as a reference for the technical side of their organization. They also turn to documentation for step-by-step procedures for technical tasks necessary in the course of their jobs. Writing for nontechnical staff can be more difficult, because you cannot assume that they understand jargon and processes. This documentation must clearly explain processes in easy-to-follow steps and simple terms. These readers understand terms and acronyms specific to your organization, however including code names for products and server names, enabling them to use these terms freely in this type of documentation.

+   - Clients and customers need system documentation if they have access to their technology (for example, if they use mail servers to store and read their email), and they use it primarily for step-by-step procedures and contact information. You must be carefully to write clear, jargon-free documentation for these readers. Assume that any or all of these readers have no technical background and are unfamiliar with any of your company's internal practices and terminology. This documentation must be wellwritten, easy to use, and complete in its instructions and information.
