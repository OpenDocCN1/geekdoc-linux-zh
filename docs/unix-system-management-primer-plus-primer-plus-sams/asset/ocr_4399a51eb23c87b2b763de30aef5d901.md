The important statistics to check here are the response time, transaction rate, and concurrency. In this run, the average request took 0.30 second to return a response—a relatively speedy response time. There were 2.27 transactions per second with an average of 0.68 transaction running concurrently. Turn to the Seige documentation to interpret the numbers.

Siege documentation recommends that the number of concurrent transactions should never exceed half of the total number of transactions processed; otherwise, severe performance degradation will be seen. This makes sense; if there is more than one transaction queued up while another is being served, the system won't be able to process transactions enough to keep the queue from growing. Your test results show that the system is well under that threshold in this particular run. You've produced a good baseline; it shows how our servers perform under a very nominal load.
