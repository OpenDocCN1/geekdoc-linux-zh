# Delegating Authority

This chapter has spent a lot of time stressing the importance of protecting root privileges at
costs. There are times, however, when delegating this authority to normal users is appropriate
and even necessary. You can use any of several tools and methods to delegate this authority
safely, including aliases and defaults, controlling access over Solaris 8, and using Unix Group
Permissions. The sections that follow offer detailed information about using each of these tech-
niques to delegate access authority and other privileges.

# Unix System Privileged Accounts

root may not be the privileged account on a Unix system. For example, all Web servers recom-
end they be run as a user other than root, as do the MySQL database server and various
other applications. The users under which these applications run can be considered privileged with
respect to those particular applications.

# Using sudo to Run Commands as Another User

sudo, which is short for "superuser do," is a command that allows a user to run commands as
y other user, though system administrators usually use it to delegate root privileges for per-
cific tasks. It is the most popular third-party tool among administrators for delegating root
pileges. sudo supports the following features:

+   - Central configuration file

+   - The ability to restrict which commands can be run on a per-user, per-group, and per-
host basis

+   - Password authentication

+   - Verbose logging for command auditing

You would want to use sudo to delegate authority in the following situations:

+   - Backup operators need root access to run dump and restore commands.

+   - A DBA needs to reboot database servers but does not have the root password.
