# Choosing a RAID Level

RAID levels 0, 1, 4, and 5 are the most common forms of RAID in the field today. Deciding which level is right for your applications can be confusing at first. Table 10.2 summarizes the pros and cons of each RAID level and can help you make the right decision.

| RAID Level | Pros | Cons |
|---|---|---|
| 0 | Fast I/O | No redundancy |
| 1 | Easy to increase redundancy, can round robin reads among disks | Highest cost-to-capacity ratio |
| 4 | Low cost-to-capacity, high read performance | Very poor write performance |
| 5 | Low cost-to-capacity, high read performance | Poor write performance, slow rebuild times |

# Hardware Versus Software RAID

RAID can be implemented in both hardware and software. Hardware RAID devices are disk arrays with RAID functionality built in; nothing more is required to implement other than configuring the array itself. Software RAID is typically implemented via operating system device drivers and can be used on regular drives without any inherent RAID functionality.

Hardware RAID is an optimal configuration, as all calculations and disk operations are mediated in dedicated hardware, making them very fast. You can easily transfer the RAID functionality to a new host by moving the array. RAID arrays can be very expensive, but they can be worth the cost for larger implementations where CPU could become a bottleneck. This is especially important with RAID-5, as the overhead of parity calculations can place a significant load on a server's CPU. Some servers even come packaged with internal hardware controllers, though you mainly see this in Intel packages from vendors like Dell and Compaq.

Software RAID is naturally slower than hardware RAID, as the host CPU must perform all calculations. Software RAID is extremely flexible, however; it can use internal hard drives, external disks arrays, and any other RAID devices to form its own RAID partitions. Software RAID is an extremely cost-effective solution as well, because it does not require the purchase or installation of extra drives. Most Unix operating systems come with some form of software RAID functionality, making it a convenient alternative as well. # A Representative RAID Solution: Solstice DiskSuite

Solstice DiskSuite is a software package for Solaris that offers most of the RAID functionality you've learned about this chapter. It provides both command-line and graphical interfaces, the GUI is as functional as the command line, so you can use whichever interface you are more comfortable with.

DiskSuite uses metadrives, which are virtual disks that can be used just like physical disks. DiskSuite uses these metadrives to abstract the actual physical storage configuration: The metadrives can represent entire physical disks, individual slices (Sun's name for partitions), and RAID devices built from these disks and slices. Many software implementations use virtual disks.

DiskSuite is unique in that it can work with a slice or partition, instead of an extra disk. This means you can mirror one file system on a disk but not the others. For example, you can use two slices on two physical disks to create one mirrored device by creating two metadrives, one for each slice, as follows:

```
# maintain d11 1 1 c0t00s0
d11: Concat/Stripe is setup
# maintain d12 1 1 c0tid0s0
d12: Concat/Stripe is setup
```

This code produces two submirror metadrives, d11 and d12, that can be used to create a mirror d10. First the mirror is created using d11, and then d12 is attached, prompting the initial synchronization of the mirror:

```
# maintainit d10 -m d11
d10: Mirror is setup
# metattach d10 d12
```
