# Using ps to Monitor Process Usage

Although not overly verbose, ps can provide some very simple size usage statistics for a process. On a System V platform (Solaris) -1 can show the size of a process in pages in the SZ field, as follows:

```
bash$ -lp 382
FS UID PID PPID C PRI NI SZ WCHAN TTY TIME CMD
8 S 0 382 1 40 20 423 ?? 0:05 http
```

The pagesize command is used to determine the size on Solaris, in which this case is 8KB. The total size of the http process's address is 423 × 8KB = 3,384KB.
The BSD version of ps provides some more useful information akin to the output of top: ps will display the resident size as well as the total size of process, just like top. On Solaris, the BSD version of ps is located at /usr/uc/ps; on Red Linux, ps will behave with BSD semantics if you use BSD-style arguments like awk. Note how the size SZ in the following calculation:

```
jhorwitz@nause[build|$] /usr/uc/ps ps 382
USER PID %CPU %MEM SZ RSS TT S START TIME COMMAND
root 382.0 0 4.3784 172 S Aug 08 0:04 /usr/local/apache/
```

# Using pmap to Monitor Memory Usage

Solaris 2.6 introduced the pmap command, which provides a map specifying what parts of each process are using which parts of memory. This includes executable, shared libraries, the heap, and the stack. A pmap prints total usage at the bottom of the output:
