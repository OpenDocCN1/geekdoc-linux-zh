# Using tcpcdump and snoop to Locate Remote Users

Users do not have to log in to your system to cause problems; a simple denial-service attack or an exploit for a network service vulnerable to buffer overflows are just as damaging to your system as anything a local user could. Locating these is much more difficult because they are not actually logged into systems that you can control. However, as long as they continue to send network traffic to your machine, you can sniff that traffic and identify the remote addresses using tools like tcpcdump and snoop (both are discussed in Chapter 13).

For example, if someone is repeatedly using Telnet to connect to your server, to log in as a certain user and failing, you can figure out where those connections are coming from by port 23, Telnet's port (output truncated), as follows:

```
# tcpcdump -n port 23
kernel filter, protocol ALL, data packet packet
tcpcdump: listening on all devices
20:55:03.008065 eth0 < 192.168.1.21:52136 > 192.168.1.66:telnet: S 3617855084:36 176855084(0) win 24820 <nop,nop,sack>ms 140> (DF)
20:55:03.008017 eth0 > 192.168.1.66:telnet < 192.168.1.21:512336: S 715025216:711 025810(0) ack 3617855085 win 31220 ms 146>nop,nop,sack> (OK)
20:55:03.001118 eth0 < 192.168.1.21:512336 > 192.168.1.66:telnet: . 1:(0) ack 25 win 24820 (DF)
20:55:03.002902 eth0 > 192.168.1.21:512336 > 192.168.1.66:telnet: P 1:(24) ack 25
20:55:03.002963 eth0 > 192.168.1.66:telnet < 192.168.1.21:512336: . 1:(0) ack 25 win 31220
20:55:03.015742 eth0 > 192.168.1.66:telnet > 192.168.1.21:512336: P 1:(13(2) ack 25 win 31220 (DF)
```

Assuming your server is located at 192.168.1.66, you can see where the connection is coming from and can work with the remote administrators to figure out who the culprit is.

# Connections to Popular Services Can Be Difficult to Trace

Tracking down connections for a popular service like Telnet can be a daunting task on a busy server. You may not be able to distinguish one from a swarm of other connections to the same port. In particular you must rely on tools like last and last to identify the addresses from which various users have connected to your system.

# Identifying a Remote User using the IDENT Protocol

The IDENT protocol, specified by RFC 931 and RFC 1413, supports the identification of a remote user to sites that the user connects to. The only requirement for the remote server must be a running server that supports the IDENT protocol, such as ident. A free implementation of identd is available at http://www.lysator.liu.se/~pen/pident—this is the same identd package that is installed on Red Hat Linux.
