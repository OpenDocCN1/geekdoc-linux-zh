Remember the Order of Cylinders
The lowest numbered cylinder is always the outermost cylinder. Don't forget when positioning your file systems, as a mistake could greatly affect the performance during heavy activity.

You can optimize system performance by improving seek time. While the outer cylinders have the highest transfer rates, they are also the furthest from the inner cylinders. To find files in these locations, the heads might have to seek the entire radius of the disk to access data; extended searches for data add to the process's latency before any data is actually transferred.

You can solve this problem by placing file systems that are usually accessed concurrently close to each other on the disk. If you have one file system whose access is not correlated to the access of any other data on disk, you can locate it in the middle cylinders—the disk heads will have to travel at most half the radius of the disk, reducing latency before and after the access.

# Position Active File Systems Together

If you cannot spread two active file systems across multiple disks, place them in adjacent partitions on the same disk. This minimizes the distance the heads have to travel between file systems.

# Striping Data Across Multiple Disks (RAID-0)

RAID-0 striping was briefly discussed in Chapter 10, but an in-depth discussion of its performance benefits is appropriate here. Striping increases throughput by spreading the data across multiple drives, allowing each disk to access data in parallel for a single I/O operation. Striping divides each drive into chunks and distributes sequential chunks of data on different disks. The size of these data chunks is referred to as the disk's *interface*. Figure 11.2 shows a very simple RAID-0 array.

Theoretically, you can tune a RAID-0 array to deliver bandwidth comparable to that of all of the drives combined, so taking the time to tune your RAID-0 array is worth the effort. Three significant factors contribute to the performance of a RAID-0. The first is drive homogeneity—each drive should be identical so that no single disk performs worse than the others

The second factor that affects performance is the interface size. Calculating the correct size is a complicated task, involving disk geometry, I/O request sizes, and access patterns. For sequential access patterns, performance is best when the size of an I/O request is the same as the interface size. Successive requests hit different disks, but most operating systems buffer related I/O requests and issue them at the same time, allowing the striped disks to operate in parallel.

Random access patterns call for large interface sizes. These patterns typically signal small I/O requests, and large sizes eliminate the risk of crossing a chunky boundary. Crossing this boundary sends the request to the next disk in the array, adding to latency and reducing the overall performance of the array.

The last factor to consider is the disk-controller relationship. With multiple disks acting as a single device and serving requests at the same time, it is ideal for a single controller hosting all of those disks to be overloaded with I/O requests and data transfers. Ideally, your system should have a one-to-one disk-to-controller relationship, but this can be quite an expensive option. An alternative strategy is to alternate disks across two or more controllers, so that consecutive requests go to different controllers.

## RAID 0+1: Mirrored Stripes
RAID-0 by itself offers an incredible increase in performance, but does not provide redundancy. If one disk fails in a RAID-0 array, the entire array fails. You can, however, mirror the drives in a RAID-0 configuration, creating what is called RAID 0+1. In this configuration, any single disk can fail without affecting the performance or integrity of the array. RAID 0+1 is seen as the "Holy Grail" of performance and redundancy, but comes at a price—twice the number of disks is required to provide the mirroring component.

# Don't Out Of Inodes

Disk space utilization typically increases either through spikes in demand or as a result of long-term growth. Bursts of disk usage occur when a user downloads a large file or a DBA adds another file to database. Planning for these events is difficult; however, maintaining at least 20% free space on each system avoids usage problems resulting from these spikes.

Long-term growth, on the other hand, usually follows predictable trends. Monitoring usage over time is easy with SNMP-based tools like MRTG; these tools query your systems periodically. Of course, you can write your own monitoring tools using Unix commands like df and du. In a minimal environment, a daily disk-space check is a reliable monitoring practice, and it familiarizes you with your system's usage trends.

No matter which you choose to monitor disk space, it is absolutely critical to correlate the usage trends with business goals. If an email service with 10,000 users consumes an 1% of your total storage every week, it's a good bet that 20,000 users will consume 2% every week. You can use this data to predict future costs and plan for the thinning of new disk purchases.

# Planning for Storage Needs

Planning for future capacity should be a priority for any system administrator. Historically, no other computing resource exhausts itself as quickly as disk space. To keep your system functioning smoothly, you need to take advantage of operating system features such as quotas and logical volume managers.

# Allocate Enough Space for Each Partition

File systems traditionally reside on fixed-size partitions; after you create a partition, you can't easily increase or decrease the size of the file system. To avoid the need for changes, you must know the storage requirements of the resident file systems while the disk is being partitioned. Allocating space to file systems without prior planning almost guarantees that one file system won't have enough space, while others will be highly underutilized.

# Expand Striped RAID Devices

Typically, you can expand RAID devices by adding additional disks to the RAID configuration. This solution is especially useful when you need more space on a file system that resides on a RAID device. The procedures for adding disks to the RAID configuration are implementation-dependent—check your RAID hardware and software documentation for details (note that the file systems on these disks must support this growth as well).
