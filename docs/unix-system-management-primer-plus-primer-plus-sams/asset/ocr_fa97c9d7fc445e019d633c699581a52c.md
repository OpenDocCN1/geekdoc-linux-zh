# Signing Data

Data can also be encrypted with the private key—this is known as “signing” the data. Recipients of a signed message can use the freely available public key to decrypt it. If it successfully decrypts, the recipient knows the message from the true owner of the private key, because it is mathematically impossible for any other key to encrypt data that can be decrypted by that public key.

# Real-World Example: Encryption on the Web

The web uses an encryption mechanism called SSL (Secure Sockets Layer) that is actually a hybrid of symmetric key and public key encryption. Public key encryption is used to verify the authenticity of the server using digitally signed certificates and is then used to securely transmit a session key to be used with a symmetric key cipher for all further communications. This method uses the advantages of each type of encryption; public key encryption is used for signature verification and securely transmitting a key, at which point symmetric key encryption takes over for speed.

# One-Way Hashes

One-way hashes are not a form of encryption, but rather a way of mathematically obfuscating data into a “hash” so that it is computationally infeasible to decode the original data from the hash in a reasonable amount of time. Hashes are like an unsolved jigsaw puzzle—without the picture on the box, it is extremely difficult to put the pieces together to reveal the original image.

No two messages result in the same hash. Mathematically, it is possible for two messages to produce the same hash, but it is highly unlikely to occur in practice. One-way hashes have two main functions in Unix: checksums and password verification.

# One-Way Hashes for Checksums

When you download a file from a remote Web site, how do you know it has not been tampered with? Many sites nowadays, especially those containing software and source code, provide checksums for each file available on their site. After downloading a file, you can compute its checksum and compare it to the checksum on the Web site. If the checksums do not match, the file (or checksum) has been tampered with, and you should discard that file.

One of the most common-way hash mechanisms is called MD5. You can see MD5 in practice on Apache’s Web site, http://www.apache.org. Suppose you wanted to download and compile Apache 1.3.24, which you wanted to be certain that the file was authentic. After downloading the file apache_1.3.24.tar.gz, you could view another file on the site called apache_1.3.24.tar.gz.md5, which contains an MD5 checksum of ebe6588c3954731fcc318029bc82409
