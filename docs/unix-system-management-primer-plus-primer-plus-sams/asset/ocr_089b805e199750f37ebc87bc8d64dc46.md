Content distribution spreads bandwidth demands over multiple channels by distributing content in multiple physical locations. Optimally, content distribution uses different providers over different Internet backbones, allowing more users to access the content than would be possible over a single network link. This approach also prevents a disaster at one site from denying all access to your content.

With multiple sites, you can use DNS round robin, intelligent DNS, HTTP redirection, and distributed content services to optimize network traffic. The following sections discuss these techniques in more detail.

# DNS Round Robin

In an earlier section of this chapter, you learned about DNS round robin techniques, and content distribution is a wonderful application of these techniques. To put DNS round robin to work in this manner, create a pool of A records using the name you want clients to see, such as when. Then, assign each server in each location A record in the pool. DNS takes care of the rest by globally distributing your services automatically.

# Intelligent DNS

Intelligent DNS is a broad term used to describe name services that are aware of the availability of services behind the IP addresses. Much as a traditional load balancer detects and removes a downed server from a load-balanced pool, intelligent DNS can remove records from a server when a particular server becomes unavailable. Even more advanced servers can return different records, depending on the clients' IP address. You could send requests from the east coast of the United States to Web servers in Philadelphia, for example, and requests from the west coast to servers in San Francisco.

There isn't much hardware or software that supports this kind of service yet, but F5 Labs has already made some advances in this arena. In addition to the BigIP, F5 Labs also offers the 3-DNS controller. The 3-DNS controller is a dedicated DNS server that can detect failures and alter DNS zones appropriately to ensure only available servers are contacted. It also offers other balancing schemes in addition to round robin, like the BigIP.

# Time-to-Live Management

Load balancing using DNS can be a tricky business because of client caching. Each zone has a time to live (TTL) that specifies how long clients should cache records from that before requesting new records from the server. If changes are made on the server side, a large TTL can prevent those changes from being seen for quite some time. If availability is critical, try lowering TTL times for specific zones or records (5 or 10 minutes is reasonable) to reduce the amount of time it takes for your changes to propagate.
