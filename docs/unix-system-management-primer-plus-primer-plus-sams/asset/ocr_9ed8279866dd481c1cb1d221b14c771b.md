# UNIX SYSTEM MANAGEMENT PRIMER PLUS

rsync can natively copy files to and from the same system, but it requires a separate network transport to copy files between machines. The default program is rsh, but you should change the default to something like ssh for its stronger authentication and encryption; you can do this with the -e flag. The syntax for rsync is similar to that of rcp, with a few fewer options.

+   -a Archive mode; causes rsync to behave like tar and recursively copy directories, preserving ownerships and symbolic links

+   -e Deletes files on the server that do not exist on the client file system

+   -z Specifies an "rsh-like" command (such as ssh) to use in place of rsh as a net-work transport

+   -z Compresses network communications

To synchronize /home/jeff/src on server1 and server2 using ssh as the transport, you could run the following command on server1:

```
bash$ ls -l src
total 16256
-rwxr-xr-x 1 jhorwitz staff 4075520 Mar 31 24:18 mrtg-2.9.17.tar
-rwxr-xr-x 1 jhorwitz staff 3763828 Mar 31 24:18 openssh-3.1p1.tar
-rw-r--r-- 1 jhorwitz staff 222608 Mar 31 24:15 syslog-ng-1.4.11.tar.gz
-rw-r--r-- 1 jhorwitz staff 234762 Mar 31 24:18 top-3.5beta9.tar.gz
bash$ rsync -avc -e ssh /home/jeff/src server2:/home/jeff/src
uilding file list ... done
/
openssh-3.1p1.tar
/
wrote 002829 reads 36 bytes 94454.1 bytes/sec
total size is 8301410 speedup is 10.34
```

Note how the only file transferred was openssh-3.1p1.tar. The other files already existed on server2 and matched the files on the client, they were not transferred, speeding up the the-oretical transfer by over 10 times.

# The Trailing Slash is important

The additional slash after the source path tells rsync to synchronize the contents of the direc-, not the directory itself. This is important if you need the permissions on the destination direc-ory to be that on the source directory.

You can also increase the speed for individual file transfers by making a small change to one of the files in src and resynchronizing that file. For example, the file sshd.c in the tar file openssh-3.1p1.tar was copied to another file in the same directory and the tar file was recreated with a small 43KB size. The file was transferred using rsync, rsync -z, ftp, cpf, and scp -C. Every command except for rsync transferred the entire contents of the file. Table 1.3 holds the summarized results; rsync using SSH with compression was the clear winner taking over 80% less time to transfer the file than the clearest ftp transfer.
