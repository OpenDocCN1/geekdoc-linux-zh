
# UNIX SYSTEM MANAGEMENT PRIMER PLUS

The simplest way to support IDENT queries is to use Wrappers with the rfc931 option. For example, to add IDENT support to your SSH server, you could use the following TCP Wrappers configuration:

```
- sshd: 127.0.0.1 : rfc931 : DENY
```

You would then start to see logs containing remote user identification like this:
Apr 8 22:45:40 server1 sshd[22624]: refused connect from baduser@127.0.0.1

We can see that baduser is trying to connect to our server, but there is a major problem: You are now trusting information from a remote site, which may itself be compromised.

Another problem lies in the implementation of IDENT. Administrators should protect the identity of users on their machines for privacy and security reasons. Modern IDENT implementations include support for the encryption of usernames; only a string of seemingly random characters is sent as the identifier. However, when you send this string back to the remote administrator, he or she is able to decrypt the string into the real username.

In general though, IDENT is not widely deployed, and many administrators choose to disable it on systems such as Red Hat Linux, due to user privacy concerns. In addition, IDENT is primarily restricted to Unix, so you cannot take advantage of it for any Windows clients, which are the majority of clients on the Internet.

# Contacting the Remote Site Administrators

After you know the address of a remote connection, you can use information to determine the contacts for that particular network and notify them of any problems. The number one way to do this is by using who, which will look up official contact information from the various authoritative sources.

# Using who to Find Contact Information for Domains

If you know a site's domain name, you can use who to query InterNIC, the official Internet name registry, for its contact information. The who command has a very simple syntax, as follows:

```
who [-h whois-server] domain
```

By default, whois queries InterNIC at whois.internic.net, but that only tells you which of the many Internet name registrars contains authoritative information for that domain.

```
$ whois Version example.com
```

Domain names in the .com, .net, and .org domains can now be registered with many different competing registrars. Go to http://www.internic.net for detailed information.

# Using whois to Find Contact Information for Networks

Registration is required for all Internet networks as well as domain names. In the Americas, parts of Africa, and the Caribbean, this information is managed by ARIN, the American Registry for Internet Numbers. You can query the ARIN whois server just like any other whois server, except that you must use networks rather than domain names. ARIN's whois server is whois.arin.net: if you wanted to query 192.168.1.0 (a private reserved network), you could type the following:

```bash
$ whois -h whois.arin.net 192.168.0.0
```

# When All Else Fails, Email root

If you are unable to get in touch with or get a response from any of the contacts for that domain, your last resort is to send mail to root. This might seem like the logical first step, but there are two problems with emailing root.

First of all, not all administrators forward root to a real user's mailbox where it will be read. If that's the case, any email you send to root might not have been seen for months, if ever. The other problem with emailing root is that if a system has been compromised, mail to root may end up being seen by the hackers or they may have disabled root altogether. And if the remote system is owned by the first place, sending mail to root is pointless. In these cases you will have to contact their network provider, which you can identify using whois. Summary

Effective communication is the key to this process; this chapter introduces several methods of communicating with users, such as the write command, newsgroups, and the message of the day, and the appropriate situations in which to use each of them. Such situations include incidents in which a user misbehaves and is in violation of your usage policies or even the law. Remote users can also present a problem, especially when they exhibit malicious behavior toward your system—knowing how to discover and contact remote administrators solve many of these problems before they get out of hand. The who, whose, last, and top commands are very useful for tracking down the location of these remote users. However, always remember that users are your customers and clients; without them, your systems (and your job) would not exist in the first place. Rule your systems with a firm hand, but always listen to users' concerns and treat them with respect. Review Questions

- 4. How would you locate the owner of the network address 172.16.0.1?
