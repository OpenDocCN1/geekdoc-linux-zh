# HTTP Redirection

One of the simplest and easiest content distribution mechanisms is HTTP redirection. When a user requests the content from one site, an HTTP redirect is sent back to the client with the URL of a convenient location from which the user can retrieve the content. The user's browser then requests the content from the new location.

All modern Web servers contain redirect functionality; you can even redirect based on client IP using Apache's mod_rewrite. For example, to redirect requests for /docs on one server to the remote URL http://www.example.com/mysite, you could add the following lines to your Apache http.conf file:

```
<Directory /docs>
<RewriteEngine on
RewriteCond %{ADDR} ^10.1.*
RewriteRule * http://www.example.com/mysite [R]
</Directory>
```

HTTP redirection isn't a perfect solution because it still relies on a central server that the client must initially contact before redirected to a closer server. But this is usually not an issue as long as the high-bandwidth content is served from other locations.

# Distributed Content Services

Some companies have cached on the extreme bandwidth requirements of multimedia and provide storage and caching for your data on their servers around the world. If you use one of the previously described methods to force your users to retrieve the content from those distributed sites. Distributed content services take the load off your network and your servers.

One example of such a company is Akamai Technologies. If you've visited www.msnbc.com or www.yahoo.com recently, you've used Akamai's services. If you view the HTML source for www.msnbc.com, you can see that all of the images come from servers in the akamai.net domain, leaving the low-bandwidth text out to MSNBC, and the high-bandwidth graphics, sound, and video to Akamai's distributed network.

# Real-World Example: September 11, 2001

The need for distributed content services was exemplified on September 11, 2001, during the World Trade Center attacks. For several hours after the attacks, most major sites on the Web were unable to handle the volume of requests for information, and failed to serve any pages at all. CNN was one of the major sites that was forced to quickly redesign its home page in a text-only-format, leaving visitors with articles, but no pictures or videos of the event. While it is not possible to plan for an event of this magnitude, a more globally distributed content network would have eased the load on CNN's main servers, allowing people to view the original image-rich home page.
