For example, you could put the following banner in /etc/banners/in.telnet:

Now when users use Telnet to server1, they see the following banner message:

Banners displayed with TCP Wrappers can also include variables that are filled dynamically for each incoming connection. Table 15.1 lists these variables.

### Limit the Amount of Information in Your Banners

The previously displayed banner contained some information (Unix(r) System V Release 4.0) that indicated the specific operating system of the server. This information is valuable to hackers who can use it to determine what kind of attacks would be successful against a server, so you should limit the amount of server-specific information in banners like /etc/issue or TCP Wrappers.

If you don't have access to TCP Wrappers, you can use /etc/issue to display banners in Unix. Most operating systems display the contents of the file /etc/issue above the line prompt. This feature is the responsibility of the getty process (mington on and Red Hat Linux), so check the man page for getty to see if it supports /etc/issue and /etc/issue.net for Red Hat Linux.

### Posting Messages in the Message of the Day

System administrators can also use the Message of the Day feature in Unix to issue non-generous announcements about new software, upcoming maintenance schedules, or just to print a nice welcome message. Unix stores the message of the day in /etc/motd and displays the message on each user's terminal after the user logs in, as such:

```bash
bash$ telnet orange
Trying 192.168.1.21...
Connected to character is orange.
Escape character is ']'.
```

Unix 5.8

```
login: joesuser
Password:
Last login: Thu Jun 6 16:45:56 from apple
```

Welcome to the Example.COM UNIX server. All questions, comments and suggestions regarding this server should be sent to helpdesk@example.com.

IMPORTANT!!! This server will be shut down tomorrow morning for maintenance. It will be available again no later than 6 AM. Thank you.

```bash
bash$
```

In a default configuration, users can suppress the motd feature by creating a file called .hashlogin in their home directories, so do not expect 100% of your user base to see these messages. You can always force the motd to display by editing the login scripts in /etc/profile (Bourne shell) and /etc/.login (csh).

> **Keep the Message of the Day Short**
Make sure that your messages of the day are kept short and to the point. Users tend to skip over messages of the day that take more than 5 or 10 seconds to read—they want to get started on their work as soon as they login.

### Posting Messages to Newsgroups

Usenet newsgroups are threaded forums in which users can post messages to groups with a common interest. Although most newsgroups are publicly accessible and anyone on the Internet can post them, individual news servers can have newsgroups private to an organization. Users can check these private newsgroups for announcements about your services and even post questions and comments. Newsgroups are convenient for communicating with users when your systems are unavailable, because a user does not need to be logged into their systems to view them.

If you use newsgroups, be sure to post consistently. Much like a bulletin board, users must actively choose to look at or subscribe to a particular newsgroup; if users know that messages are posted often, they will be more likely to check for new messages.

### Sending Messages via Email

Many organizations create their own intranets for posting internal information such as outage status. Whenever possible, do not limit your communications to a single forum, such as a Web site. You will reach a much wider audience in a shorter period of time if you distribute your message across multiple-forums, since everyone will prefer to use a different forum.

> **Send Urgent Email Well Ahead**
Many organizations create their own intranets for posting internal information such as outage status. Some users may not have access to certain forums at various times (that is, a person on a business trip may only have access to email on his her pager). As an example, you might announce a Web site outage on the Web site itself, as well as on newsgroup and via email to your clients.

The problem with using email to communicate with users is that sending a single message to thousands of users can use tremendous resources. If your user base is more than a hundred people, you would be wise to invest in mailing list software that can create these mailings for you.

Some powerful commercial software can send mass mails from your own server, and some companies also provide this functionality on the Web. Some of the well-known mailing list software and Web sites include:
