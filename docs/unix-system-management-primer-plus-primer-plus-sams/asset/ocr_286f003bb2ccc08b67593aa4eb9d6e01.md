To forward a local port to a remote server, choose an unused port on your client to use as the local port. Using a high port number (over 30000) is usually safe. To forward traffic to a remote server, use the -L flag to SSH, as follows:

```
ssh -L local-port:remote-server:remote-port
```

The server you SSH to does not have to be the same server as which you are forwarding the port traffic. This method works well if that server cannot be connected to via SSH, as is the case with Windows. The server you SSH to, however, must have access to the server and port to which you are forwarding. To SSH to the server apple, while forwarding port 30001 to 80 on orange, you would type:

```
ssh -L 30001:orange:80 apple
```

You see a completely normal-looking SSH session, but this time port forwarding is enabled. If you point your Web browser to http://127.0.0.1:30001, SSH forwards the port to orange and you see the Web server on orange.

# Using Virtual Private Networks

Virtual private networks, or VPNs, are one of the hottest technologies in information technology today. They create simulated networks of secure links over public VPN networks with the goal of making physically and logically separate hosts to be on the same network. Organizations use VPNs to provide their employees secure remote access to an internal network. VPNs can also be configured between two routers or firewalls to create enterprise-wide encrypted tunnels between two organizations.

VPNs can be implemented in hardware and software; corporate end users usually install small VPN clients on their home computers or laptops that send all traffic destined for internal networks over the VPN. Dedicated VPN hardware sits between a broadband router (cable or DSL) and transparently encrypts traffic over a VPN without installing any software on a computer. Dedicated VPN hardware is useful for homes with multiple computers using a single Internet connection.

One of the biggest problems with corporate VPNs is that they expose an internal corporate network to the outside world. For example, a virus on your home computer could easily spread to your company's internal network over a VPN connection. Furthermore, someone hacks into your home computer could potentially gain access to your company's network, as well. For this reason, you should require antivirus and firewall software be installed on any computer that participates in the VPN.

One company was paranoid about the vulnerability of their corporate network to attack over a VPN that it allowed VPN connections only from company-issued laptops running Windows 2000. These laptops had antivirus and firewall software preinstalled by IT staff and users were locked out of local administrative accounts so that no malicious software could be installed outside the company walls.
