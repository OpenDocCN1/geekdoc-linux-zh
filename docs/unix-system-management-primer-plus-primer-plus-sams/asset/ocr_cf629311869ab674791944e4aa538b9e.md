mkfs -m /dev/rdsk/c0tid03 changes the number of bytes per inode (the nbi setting is 6179 bytes), as follows:

```
# mkfs -m /dev/rdsk/c0tid03
mkfs -F ufs -o next=24,ntrack=19,size=8192,fragsize=1024,cgsize=22,free=3,
rps=167,nbi=6179,opt=t,ac=0,gap=0,npos=8,maxconfig=128 /dev/rdsk/c0tid03
4198392
```

A 6KB block size is ideal for many standards by today. However you can create another file system using the -i flag, which specifies average bytes per inode, the predicted size of an average file on that file system. If you assume an average file size of 6KB (6536 bytes), you can run the following command to create the file system:

```
mkfs -i 6536 new file system /dev/rdsk/c0tid04: (y/n) y
/dev/rdsk/c0tid04: 4198392 sectors in 891 cylinders of 248 sectors
```

After mounting the first file system (6KB per inode) on /fs1 and the second (64KB per inode) on /fs2, use df -k to see the file savings in /fs2, as follows:

```
# -k /fs1 /fs2
Filesystem bytes avail capacity Mounted on
/dev/rdsk/c0tid03 2056211 1%
/dev/rdsk/c0tid04 2094315 1%
```

According to the available space column, you saved approximately 37MB by reducing the number of inodes in the file system. This was only a 2GB file system; the savings increase as you grow into the hundreds of gigabytes and terabytes.
