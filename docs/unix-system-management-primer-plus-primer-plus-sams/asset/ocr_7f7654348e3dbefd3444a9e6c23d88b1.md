# Chapter 13 • IMPLEMENTING SYSTEM SECURITY

The SYN flood attack utilizes a client that sends thousands of SYN packets to a server with a spoofed IP address. As part of the three-way handshake, the server responds to the source address with an ACK packet, but because the source address is spoofed, the server never gets a SYN/ACK back to complete the connection. leaves leaves resources allocated for the connection in a state of limbo; the server is expecting to eventually complete the connection, so it can't release the resources. Until the attempted connections time out, the client can continue flooding the server with thousands of SYNs, eventually consuming all of the network resources on the system, making new network connections impossible.

# Spoofed Publicly Routable Addresses

If the spoofed IP address is a publicly routable address, the server being attacked floods that address with ACK packets. These packets should be ignored by the remote system (or thrown out by its firewall), but the process still wastes significant bandwidth on both.

Recent versions of software in firewalls and operating systems contain code to minimize the effect of SYN flooding. Systems limit resource allocation while any three-way handshake is pending, some reduce the rate at which SYN packets are processed as more resources are allocated, and some use other, more complex methods.

# Smurf Attack

A Smurf attack is a form of distributed denial-of-service attack (named after originally to launch the attack). A distributed denial-of-service attack is an attack in which multiple systems are used to attack a single system. Smurf attacks can be especially crippling because they are amplified by the multiple systems launching the attack. These attacks are also difficult to prevent, because traffic is coming in from many different networks.

The Smurf attack sends ICMP echo requests (`ping`) to directed broadcast addresses on different networks, broadcasting the ICMP packet to all of the hosts on those networks. Normally, this widely broadcast request would result in a flood of responses back to the initiating host, which would be counterproductive for someone trying to attack another system. Smurf attacks use spoof IP packets, placing the victim's IP address in the source address field. This spoofed address results in all responses to the ICMP echo request being sent to the victim, consuming all of the bandwidth and network resources on that.

The Smurf attack was prevalent in the middle and late 1990s, but the industry eventually caught on and implemented some barriers to this attack. Most firewalls and routers allow you to disable ICMPdirected broadcasts, which denies all ICMP packets to broadcast addresses. This action alone reduces the effectiveness of Smurf by several orders of magnitude, but many administrators additionally refusing incoming ICMP echo packets on their firewalls, eliminating the problem altogether.
