# Using logrotate as a Generic Log
Rotation Tool

Red Hat Linux runs the logrotate as a daily cron job to maintain its own log files, but few people take advantage of logrotate to manage their own application logs.
Information pertaining to each log and its rotation policies are stored in a configuration file:
/etc/logrotate.conf by default. To maintain state between runs, logrotate stores the time of last rotation of each log in a "state file," /var/lib/logrotate.status on Red HatnLinux. The state file ensures that logrotate does not rotate logs more than once per day, unless an administrator accidentally runs it more than once.

logrotate has a very simple syntax, as follows:
logrotate [-dv] [-f|--force] [-s|--state-file] config-file

The logrotate -d option enables debugging mode and performs a dry run of the configuration.\Verbose mode is enabled with -v and will produce output explaining each task it

The logrotate command has a few options—the real magic lies in the configuration file.
Default configuration is stored in /etc/logrotate.conf and looks like this:

```
# see "man logrotate" for details
# rotate log files weekly
weekly

# keep 4 weeks worth of backlogs
rotate 4

# send errors to root
errors root

# create new (empty) log files after rotating old ones
create

# uncomment this if you want your log files compressed
#compress

# RPM packages drop log rotation information into this directory
include /etc/logrotate.d

# no packages own lastlog or wtmp .. we'll rotate them here
/var/log/wtmp {
monthly
create 0664 root wtmp
rotate 1
}
```
