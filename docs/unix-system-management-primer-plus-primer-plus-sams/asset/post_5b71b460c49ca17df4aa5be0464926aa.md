
# Communicating with Users

System administrators communicate with users on their systems for a variety of reasons, including the following:

- Announcing system maintenance
- Announcing new or removed features of a system
- Warning a user about his or her activities
- Discussing a problem in real time
- Posting disclaimers and policies
- Posting contact information

Unix provides a variety of ways to communicate with users. You can use active communication methods that enable you to exchange written messages, broadcast messages to a group, or open a real-time dialog with instant messaging. Unix also facilitates passive communication methods, such as issuing messages of the day and posting to newsgroups, Web pages, and email.

Each communication technique described in this section is effective for given situations and purposes. Some are more suitable for announcements and updates. By understanding all of the Unix communication tools available to you, you'll be able to choose and use the techniques that are best suited to delivering your communications to the right people, at the right time, and in the right way.

# Be Consistent When Communicating

You should be consistent in your use of communication methods; users will come to expect certain types of messages in certain places and might overlook them if they are placed anywhere else. Also, remember that your communications aren't effective if users do not receive them; whenever possible, get the message to your user, rather than expecting your users to come looking for messages. This is especially important for urgent messages like system maintenance notifications.

# Active Communication Methods

Active communication methods are those in which you send messages to users in real time and see the messages as they arrive. Active communication methods are essential for sending urgent messages, such as those announcing system shutdowns and asking users to log out immediately. Communicating these messages actively guarantees that the messages appear immediately on each user's terminal.

# Communicating with Individual Users Using write

The simplest communication tool on Unix is write, which displays a short message on another user's terminal. Write issues one-way communications, like a walkie-talkie, and it's most useful for sending a short message to a single user. Using write is simple, as follows:

If a user is logged into more than one terminal, write uses the first writable terminal in the Unix tmp file, which is where current terminal records are stored. If you know the terminal to which you want to send a message, you can specify that on the command line. To send a message to the user chip on pts/1, you could type the following:

```bash
bash$ write chip pts/1
Please stop pinging my mail.
```

End the message with CTRL-D, and chip sends the following message on his terminal:

```bash
bash$
Message from jhorwitz (pts/2) [ Apr 7 13:32:28 ] ...
<EOT>
Please stop pinging our mail server.
```

Users can block interruptions from write using the mesg command. If a user uses the message command, only root and the user's own account are allowed to write to that user. The message command reverses this state. If a user doesn't respond to your message, resending it as root to ensure that he or she actually sees the message.

# Broadcasting Communications with wall

If you want to announce to all users logged into a system, you want to use wall. wall, which is short for "write all," will broadcast a message to each user's terminal, interrupting whatever they happen to be doing at the time. To announce an imminent system shutdown in 5 minutes, you could type the following:

```bash
# wall
This system will be shut down in 5 minutes. Please save your work and log immediately.
Thank you.
```

A user at the shell prompt would immediately see this message displayed:

```bash
bash$ Broadcast Message from root (pts/1) on tremors Apr 7 13:17:09...
This system will be shut down in 5 minutes. Please save your work and log immediately.
Thank you.
```

As with write, users can disable the display of these messages using mesg n, which only root can circumvent.

It is important not to overuse wall or any broadcast communication mechanism. Users do not like being interrupted, and users' workflow can suffer from frequent disruptions. But if you use wall appropriately to announce emergency information, users are more likely to respect the importance of the announcement and comply with less grumbling and hostility.

# Instant Messaging with talk

Most people think of AOL Messenger, ICQ, or Yahoo! Messenger when they think about instant messaging, but each of these applications owes its functionality to the Unix talk is a two-way messaging tool that has been available for over three decades on Unix. talk presents a character-based two-paned display on user terminals, with your messages at the top and messages from the other party on the bottom. Use this command to launch talk:

```bash
talk user[@hostname]
```

# talk Communicates with Other Systems

talk is the only Unix messaging tool that can communicate with users on other systems; just specify @hostname after the username you are talking to.

When you talk to another user, you are actually issuing a request to that user, he or she sees on the terminal as follows:

```
Message from Talk_Daemon@server1 at 14:19 ...
ntalk: connection requested by root@server1.example.com.
talk: respond with: talk jhorwitz@server1.example.com
```

When the user responds with the corresponding talk command, talk presents you with the double-paned display, and you can begin typing messages to the other user.

```
[Connection established]
What are you doing?
Okay, just checking.
Trying to hack into your server.
No problem. I'll let you know when I get root.
```

System administrators rarely use talk to communicate with users directly, because it's a two-way communication technique that isn't appropriate for announcements or warnings. Some administrators find that talk is useful, however, for communicating with users they know personally or from prior interactions, especially in corporate environments where the administrators are familiar with most users. They can use talk to help a user diagnose a problem in real time, without going through the normal support lines that would otherwise take hours or days.

# Limit Your Use of the talk Command

Use the talk command sparingly when you communicate with users. Otherwise you may find that users will start conversations with you when they have a problem instead of using appropriate lines like your help desk.

# Passive Communication Methods

Passive communications are like postings on bulletin board or a newspaper—you write a message and hope that users see it within a reasonable amount of time. This communication is less intrusive than the active communication methods you've just read about, and therefore, less disruptive to users. However, passive communication delivers messages only if users know where to find them—and actually take the time to access that location.

# Tell Users How to Reach You

Always provide the means for users to communicate back to you any problems or concerns they have with announcements. A simple way to provide this information is to add an email address or a help desk number to your announcements. Use an IT department email address rather than your own, though; you may want others to manage these emails in your absence.

# Posting Messages in a Banner

Unix displays banners when users first connect to a system; typically, the banners provide information about the system connected to, including any warnings or usage guidelines. For example, when you Telnet to one of the login servers at the University of Michigan, the system displays the following banner before you can log in:

- This is the University of Michigan information environment.
- You must be authorized to use these resources. As an authorized user, by your use of these resources, you have implicitly agreed to abide by the highest standards of responsibility to your colleagues -- faculty, staff, and external users who share this environment. You are required to comply with all University policies, state, and federal laws concerning appropriate use of information technology. Non-compliance is considered a serious breach of community standards and may result in disciplinary or legal action.

You can use TCP Wrappers or /etc/issue to display a banner on a Unix system. Under Red Hat Linux, use /etc/issue.net to display a banner for Telnet sessions.
