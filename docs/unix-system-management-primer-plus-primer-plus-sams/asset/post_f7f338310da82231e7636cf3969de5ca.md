
# Pay Attention to Larger Units

The difference between the bytes-on-disk and bytes-in-memory measurements becomes significant for larger units: A terabyte in memory is almost 10% larger than a terabyte on disk. Keep this in mind when planning for capacity.

# Disk Architecture

A disk platter is made up of circular tracks divided up into smaller sectors, typically 512 bytes long. These, when extended to include all of the disk platters, form what is known as a cylinder (see Figure 11.1). Because disk platters are circular, tracks on the outside of the disk have more surface area than tracks on the inside. If each track had an equal number of sectors, there would be massive amounts of wasted space in the outer tracks.

To alleviate this problem, most disks today are formatted using a technique called zone bit rate (ZBR) recording, which divides the disk into zones of increasing sector density, moving from the spindle to the outside track. This technique results in the outer tracks having more sectors than the inner tracks, keeping any wasted space to a minimum.

# Bandwidth Versus Latency

The time it takes for read from a disk and sent to a process is affected by two main specifications: bandwidth and latency. *Bandwidth* refers to the amount of data that can be read from and written to a disk in a specified amount of time. Like a network interface, channels to a disk have maximum bandwidth specifications; for example, an Ultra-SCSI bus can push 40MB per second back and between the disk and the CPU. *Latency* is the delay between the time a read or write request is issued and the time that request is fulfilled by the disk.

A disk is a physical piece of hardware with moving parts, however, it takes time to find data on a disk. The delay incurred while the system locates data is referred to as *latency*. Four factors contribute to a disk's latency:

- Rotational speed of the disk's platters
- The speed of the disk's head assembly
- The distance from the inside of the platters to the outside of the platters
- The disk's I/O queuing strategy

Latency can vary widely, as data can be located at any point on a disk and the heads could be in any position at any given time. For this reason, latency is usually specified as average latency.

# Sequential Access Versus Random Access

There are two major disk access patterns that affect performance: sequential and random. Sequential access patterns read or write blocks that are clustered together, often in sequence. Random access patterns read or write blocks in no particular order. Sequential accesses can take advantage of the full transfer rates of a disk because the heads don't have to constantly seek new positions, with random accesses; therefore, it is beneficial to cluster high-use file systems on a disk.

# Block I/O Versus Character I/O

Due to the mechanical nature of disks, it makes sense for the system to store, read, and write in discrete blocks of data, rather than a byte at a time. This use pattern, called block I/O, is how most disk I/O is performed on Unix systems. The opposite strategy, operating on one byte at a time, is called character I/O or raw I/O. Character I/O is used to format new file systems and backup devices, while block I/O is used for everything else. The block storage of data on a disk is critical to proper performance tuning, as you learn later in this chapter.

# Inodes

Inodes are "index nodes" that all Unix file systems use to store file and directory metadata like ownership, permission, time of modification, and size. A file's inode is maintained independently of its contents, and in most file systems are preallocated when a file system is created. Preallocation places a ceiling on the number of files in that file system. The section titled, "Optimizing the File System Inodes," later in this chapter, demonstrates how to tune the number of inodes on new file systems.

# Inode Shortage Versus Storage Shortage

New file creation on a file system that is out of inodes will report the same error (ENOSPC) as a file system that is out of storage space. This can be confusing when -k output shows plenty of space left in the file system.

# Tools for Measuring Disk Performance and Capacity

One of the easiest tools to monitor disk capacity is df. This tool tells you the total capacity of each mounted file system, as well as its current usage and available space. Its use is very straightforward, as long as you know which operating system you are using.

# Understanding the Effects of Reserved Space

There is one caveat to the output of df -k, regarding file system space, also called minimum free space. Many file systems support (and recommend) reserving a small percentage of a file system's space for root access only; this reserve is 10%. Reserved space prevents users or unprivileged processes from filling up file systems like /var. Although the capacity may read 100%, there may still be reserved space left for root use. For this, the percentage capacity might not match the result of (used space)/(total space).

With root access, it is easy to determine the amount of reserved space on a file system. On the UFS file system device will report the percentage of reserved space on the devices file system in the free field. In the following example, the file system has 10% of its space reserved for root.

```bash
# mkfs -m /dev/dsk/c0t0d04
mkfs -U fs -o nsect=248,ntrack=19,bsize=8192,fragsize=1024,cgsize=16,free=10,
rps=167,nbipi=2053,opt=t,ac=0,gap=0,npos=18,maxcontig=16 /dev/dsk/c0t0d04
```

# Locating Files and Directories

When it comes to trim down a file system's disk usage, the first step is to figure out where the majority of the space is being used. The find and du commands will help you do this.The -size option to find can help find large files by printing the paths to files with sizes over a certain limit. The limit is specified in 512-byte blocks by default, though different versions of find support other units like bytes and kilobytes. Finding all files 1MB in /usr/local is as easy as:
