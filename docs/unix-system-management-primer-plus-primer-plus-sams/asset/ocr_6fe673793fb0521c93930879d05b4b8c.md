# # Shared Scheduling

In shared scheduling, servers combine their resources to balance the work load among themselves, without a master. In this shared scheduling mechanism, servers communicate their resource availabilities to each other, and servers that receive new requests can dispatch these requests to other servers if necessary.

Shared scheduling avoids the single-point-of-failure problem of the master-slave configuration, but it can suffer from bandwidth congestion. As the number of servers in the pool increases, so does the number of status messages sent over the network, as each server communicates with every other server (or worse, via broadcast). The system loses network bandwidth as processing resources increase. With the advent of multicast, however, the traffic becomes exponentially less; each server need only send one status message to the shared multicast address, letting routers and switches deal with getting the message to the right hosts.
