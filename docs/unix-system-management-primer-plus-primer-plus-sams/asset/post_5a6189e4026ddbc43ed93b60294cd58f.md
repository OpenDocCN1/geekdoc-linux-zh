## Load-Balancing Hardware

Dedicated load-balancing hardware is easier to maintain than complicated software configurations. The hardware's only job is to sit in front of your servers and direct traffic to them; it doesn't depend on or even care about the underlying application.

Several types of load-balancing hardware are available. You can use your own hardware and purchase traffic management software to run on them, or you can buy integrated hardware solutions that plug into your network and configure. Most administrators choose the latter option, because it's an all-in-one solution with a single support source for both hardware and software. Here are some popular load-balancing options:

- F5 Labs BigIP Controller
- Cisco LocalDirector
- Alteon Web Switches (recently purchased by Nortel Networks)

The BigIP refers to both a command line and perhaps the most intuitive Web interface of all the available hardware; it's also one of the most popular load-balancing hardware options. BigIP refers to load balanced services as "virtual servers." You can assign individual nodes (server/port combinations) to each virtual server or pools of nodes that can be addressed as a single unit. The BigIP can then load balance across the nodes belonging to a virtual server, using methods such as robin or least connections. ## Data Redundancy Using RAID

RAID is a type of storage that utilizes multiple disks to provide data redundancy and high availability of that data. Few things are more important to a company than its data. It's job as a system administrator to protect that data, and RAID is one of the most powerful tools you can use for achieving that goal. RAID offers several levels of protection. Each RAID level is designated by a number that indicates the amount of redundancy that level provides. The most common and practical levels are 0, 1, 4, and 5.

RAID-0 doesn't provide any redundancy (thus the zero designation). Instead it spreads, stripes, data across multiple disks to increase capacity and enhance performance. Chapter 11, "Performance Tuning and Capacity Planning," discusses striping in more detail. Each of the other commonly used RAID levels provides redundancy in a different way, and each offers unique advantages and disadvantages.

## RAID-1

The most redundant form of RAID is RAID-1, or mirroring. RAID-1 mirrors the data on individual disks to one or more disks in raid. Every time data is written to a RAID-1 partition, the data is written to all disks in the configuration. The beauty of mirroring is that if one disk fails, copies of that disks data exist on other physical disks. Mirroring, therefore, keeps data intact even when disks are lost. In fact, if you have four disks in a mirrored partition, it would take four concurrent disk failures to lose any data!

When you replace a failed disk in a mirror, the RAID hardware or software resynchronizes the disk with the other disks and then the disk is added back into the mirror. RAID-1 can perform either full or incremental resynchronizations. A full resynchronization copies all of the data from the mirror to the new disk, in addition to keeping up with new writes during the speed of the process. Full resynchronizations can take several minutes or hours depending on the speed of your disks and controllers. They are usually necessary when inserting a completely new disk into the mirror.

Incremental resynchronizations copy only data changes that have occurred since the disk was removed from the mirror, and are much faster than full resynchronizations. RAID-1 stores the locations of changed information in a log called the dirty region log; this speeds up the resynchronization process even further, as it's much faster for the RAID hardware or software to analyze a log of changes than it is to scan and compare all of the data on multiple disks.

Incremental resynchronizations are used when a disk is removed and subsequently reinserted into the mirror. This can happen by accident (i.e. an administrator trips over a SCSI cable) or as a result of an I/O error. Bad cables, failing expansion cards, and failing disk controllers can all cause these I/O errors, in which the disk itself is not to blame.

## Resynchronizations Happen Automatically

Most RAID-1 implementations will resynchronize replaced disks automatically, without any user intervention. The resynchronization is usually incremental to save time. If for some reason you require a full resynchronization, you would have to invoke that manually whatever RAID hardware or software is controlling the mirror.

RAID-1 does involve additional costs: For every disk that contains data, you need at least one additional disk for the mirror. This makes RAID-1 the most expensive RAID option. So plan to spend twice as much on disks as you would without mirroring. Figure 10.8 shows how data is mirrored across two disks in a RAID-1 mirror.

## RAID-4

Though RAID-4 offers excellent redundancy, its use does have some drawbacks; the biggest of these is its poor performance. Since each RAID-4 partition has one parity disk, all writes to that disk, making it a bottleneck.

## How Parity Works

Parity is a fast and simple way to check for errors in a sequence of bits. This parity identifies whether there are even or odd number of ones. This information enables you to figure out the value of a missing bit by counting the number of ones and comparing it to the parity bit. A parity value of one indicates an odd number of ones, and a parity value of zero indicates an even number. For example, assuming a parity value of 1, the missing bit in the following bit string is 1, as there are an even number of ones. parity value of 1 indicates that there should be an odd number of ones. Interestingly enough, the result of the common logic operator XOR (exclusive or) is 1 for an odd number of "1" operands, and 0 for an even number:

```
0 1 XOR 0 = 1
1 XOR 0 XOR 0 = 0
1 XOR 0 XOR 1 = 0
1 XOR 1 XOR 1 = 1
```

What makes it all work is the transitive nature of XOR. You can rearrange all the bits in an XOR equation, even switching sides of the equation, and it still be correct. That means you can calculate the value of a missing bit by XORing the bits for which you know the values, including the parity bit. This makes parity calculations extremely fast since the XOR operation is native to all processors. The same operations are used in actual RAID-4 and RAID-5 configurations, only on a much larger scale.

## RAID-5

RAID-5 was designed to solve the RAID-4 problem of the overworked parity disk. It does this by striping the parity across all of the disks in the partition, just as it stripes the data (see Figure 10.10). This arrangement enables as many disks as possible to contribute to parity storage. Parity calculations in RAID-5 remain the same as with RAID-4.

## Real-World Example: Optimizing RAID-4

Network Appliance uses RAID-4 in its filters successfully despite its inherently poor write performance. It does this by tightly integrating RAID-4 with its file system, WAFL (Write Anywhere File Layout). When possible, WAFL schedules writes to the same disk stripe at the same time. WAFL limits the distance the heads must travel on the parity drive between writes and thus dramatically improves write performance.
