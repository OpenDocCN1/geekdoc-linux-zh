You have just been assigned the task of designing and deploying your company's next-generation IT architecture. Projects like this don't come along often, and you are understandably excited. As the euphoria wears off, you begin to realize the magnitude of the daunting task that lies before you: Construct a working, reliable technology infrastructure on which your company will depend for years to come...from scratch. Excitement quickly turns to panic as reality sets in. Where do you begin?

Every completed project owes its success to good planning. During this planning phase you lay out each step of the project that lies ahead. Constructing a good system architecture plan is just as important in a Unix environment as in a Microsoft shop, an academic VAX cluster, or any other environment. In fact, most of the issues covered in this chapter (and this section of the book) are universal to administrators of all operating systems, and the information you learn here can be helpful to you throughout your career.

## Defining the Project Scope

The logical first step in the planning process is to understand the scope of your project. The project's scope includes several aspects:
* **Required system resources** This includes all of the hardware, software, and network infrastructure involved in your project.
* **Required human resources** Human resources are the people involved in your project, including consultants.
* **Required operating resources** These resources include hardware and software support and any other requirements for your daily operations, such as offsite tape storage. Recurring costs, such as monthly charges for a T1 line, are here as well.
* **Time allocated for each task** The time spent on each task directly affects the cost of the human resources for a project, especially when expensive outside consultants are involved. It also affects each person's availability for other projects.
* **User impact** Users are affected in many ways by a project: They could be the recipients of new workstations, or they could lose Internet connectivity for a few hours during the project. Knowing who will be affected ahead of time helps prepare them for the potential benefits and pitfalls of project.

To understand the process of defining project scope, consider some examples. First, imagine that you are deploying a cluster of workstations on your corporate LAN. This project involves six workstations, a file server, a 100Mb Ethernet switch, and assorted cabling. You need to install operating systems and application software, and you should configure an additional-subnet on your router.

A single administrator could easily complete all of these tasks in a few days. The setup and installation doesn't impact any user until the end of the project, when six happy people get to use their new workstations. You can summarize the scope of this project by listing the details of its requirements and final impact, as follows:

* **Required system resources**
- SunBlade 1000 workstations (1GB RAM, 136GB disk)
- 1 file server
- 100Mb Ethernet switch
- 8 lift category 5e cables Solaris 8 media and licenses
* **Required human resources**
- 1 FTE (full time employee) system administrator for 3 days
* **Required operating resources**
- Gold support for 6 SunBlade 1000 workstations
- Gold support for 6 Solaris 8 licenses
- Support for 100Mb Ethernet switch
* **Time allocated for each task**
- Hardware installation: 2 hours
- Operating system load (6 machines): 8 hours
- Software installation and configuration: 12 hours
- End user training: 2 hours
* **User impact**
- 6 internal software engineers get new workstations

## A Later Look at Hardware Resources

This section of the chapter doesn't include a discussion of hardware requirements. You learn how to specify hardware resources in “Analyzing Hardware Requirements,” later in this chapter.

Now consider a second project in which you are rolling out a customer’s new e-commerce site with a redundant database back end that utilizes a storage area network. A rough estimate of the resources required for the e-commerce site includes the server hardware, operating system software, database software. Web server software, disks for the storage area network, a fiber channel switch, optical cabling, host bus adapters, a tape library, tapes for the library, backup software, load balancing switches, a data center, a T1 for Internet connectivity, and multiple administrators to install and manage the system.

This project will impact many of your customers and jumpstart your company’s online sales business. Clearly, the scope of this project is much greater than that of the previous project, and the project requires more planning. As before, you can summarize the requirements and impact of this project in a detailed list.

* **Required system resources**
- 4 Sun Enterprise 280R servers (2 CPU, 2GB RAM)
- 2 fiber channel disk controllers
- 2 fiber channel switches
- 1TB of disk for fiber channel controllers
- 1 20-slot Ultra-3 SCSI LTO tape library with 2 drives
- 20 100/200GB LTO tapes
- 2 PCI Ultra-3 SCSI adapters for Sun
- 2 PCI fiber channel host bus adapters for Sun
- Solaris 8 media and Parallel server media and licenses
- Oracle 8i Veritas NetBackup software and licenses
- Apache 1.3.24 source code
* **Required human resources**
- 2 FTE system administrators
- 1 FTE database administrator
- 1 outside consultant for Veritas backup install
* **Required operating resources**
- Sun Gold support for 4 Enterprise 280R servers
- Sun Gold support for 4 Solaris 8 licenses
- Support for fiber channel switches, disks, and controllers
- Support for 100Mb Ethernet switch
- Support for tape library hardware
- Support for Veritas software
* **Time allocated for each task**
- Hardware installation: 8 hours
- Operating system load: 8 hours
- Software installation and configuration: 24 hours
- Backup configuration: 8 hours
* **User Impact**
- Customers will experience an outage during the switchover to the new Web servers.
- Customers will have to learn a new user interface
- Support staff will need to learn a new customer service interface.

As these examples demonstrate, projects can differ vastly in scope, based on their individual goals and requirements. Defining the scope of your project early in the process helps you plan for the resources you will need and reduce the chance of being overwhelmed down the road.

## Classifying Your Systems

Computers are not all alike. The machine that services 10 million Web hits per day has a very different configuration than the one you'd put on an employee's desktop. Different classes of computers require different hardware. Most Web servers, for example, have more memory and disk space than desktop workstations do, and they use SCSI disk controllers rather than IDE controllers for performance. Web servers also require redundant power supplies and mirrored disks to provide some high availability features—none of which are necessary in desktop workstations.

Hardware differences among computer types result in cost differences, as well. When you're planning an entire system of computers, these cost differences can multiply dramatically. To accurately plan a plan for the cost of any new system deployment, the early stages of your design process must include a classification of each system you plan to deploy.

Your experience will dictate how you classify your systems, but in general, the following types of systems are typical within IT infrastructures:

- Desktop Workstations
- Interactive Login Servers
- Application Servers
- Database Servers
- Compute Servers
- File Servers
- Administrative Servers
