# UNIX SYSTEM MANAGEMENT PRIMER PLUS

Failover configurations are not perfect high availability solutions. Because the standby units definition do not do anything until they are called into action, system administrators find them very easy to ignore for long periods of time. Components with mechanical parts (for example, disk drives) are prone to failure, whether or not they are in active use. To solve this problem, you must monitor standby components just as you monitor active components. A spare disk drive isn't of much use a failover if it doesn't work. Most hardware and software capable of failover provide diagnostics that report problems with failover components, but you could always monitor services yourself using the techniques discussed in Chapter 6, "Monitoring Services."

# Load Balancing

Insufficient capacity is a major player in system failures. A web server designed to handle 10,000 page hits per day that instead handling 1 million hits per day is bound to fail due to inadequate resources like CPU and memory. If a server is incapable of providing services due to its limited capacity, redundancy and failover techniques won't resolve the problem. Load balancing is a technique used to help minimize problems resulting from inadequate capacity.

# A Single Machine Is a Single Point of Failure

Though increasing the server's capacity might seem the logical solution in this situation, a behemoth server with 16 CPUs and 64GB of RAM is a single point of failure. A failed machine means downtime for your service no matter how powerful the machine.

Instead of increasing the capacity, load balancing splits the work over several servers. Hardware or software balances incoming requests for services among the individual servers. You can also use load balancing techniques on routers, switches, and other hardware, but this section focuses on load balancing Unix servers (the concepts remain the same in any application, however).

What does the distribution of "labor" buy the system administrator who uses load-balancing techniques in his or her infrastructure? First, load balancing can increase overall capacity by distributing work over several components. Second, load balancing can increase uptime by providing multiple components for a single function, ensuring that no single component breakdown can stop the service delivery. That distribution eliminates many of resource contention issues that can exist on a single system, such as processor sharing, excessive memory usage, and paging.

# Load-Balancing Systems Detect Server Failures

Most load-balancing hardware and software are able to detect server failures and all subsequent requests to servers that are still operational. End users never know that a server went down.
