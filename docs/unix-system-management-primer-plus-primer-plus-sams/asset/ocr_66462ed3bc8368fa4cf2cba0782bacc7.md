# INTERNAL COMMUNICATION

**You will learn about the following in this chapter:**

+   * How to write system documentation
* Techniques for crafting documentation for targeted audiences

* File revision control

Communication within an information technology organization is just as important as the organization's communication to the outside world. Previous chapters of this book discuss external communication tools and management techniques, including outage notifications, first level support, and messages of the day. As a system administrator, you depend upon sound internal communication tools and management techniques to coordinate the efforts of your IT staff. In this chapter, you learn about some of these tools and techniques, including system documentation, change management, and system activity scheduling. You also learn some of the most practical approaches to internal communication management, to help keep your Unix network system running smoothly and efficiently.

# Writing System Documentation

Few (if any) system administrators would rather spend time documenting their systems than actually designing, deploying, and maintaining those systems. Nevertheless, documentation is a necessity. System administrators are human, and they easily forget details of procedures they last implemented months ago. System administrators aren't the only people using their system; other administrators, users, or even auditing firms may, at some point, need to view a system's architecture and procedures.
