# Checking Out Files

Check out files in RCS using the co command. The -1 flag locks the file from subsequent check-outs until you check back into the repository with your changes. When you check out a file from an RCS repository in your current directory, an editable version of the file appears in your current directory, as follows:

```
bash$ co - httpd.conf
RCS/httpd.conf,v -> httpd.conf
revision 1.2 (locked)
done
```

What happens if someone else tries to check out the file for editing while you have checked it out? Since you used the -1 flag, RCS doesn't allow that person to check out the file using co- -1:

```
bash$ co -1 httpd.conf
RCS/httpd.conf,v -> httpd.conf
co: RCS/httpd.conf,v: Revision 1.2 is already locked by jeff.
```

# Check In Files Immediately After You Make Changes

Get into the habit of checking in files after you have made your changes. Checking in a file unlocks it, giving others a chance to make their own changes.

However, other users can still check out the file without locking it. Users can view the official version of the file while you are editing the new version, as follows:

```
bash$ co httpd.conf
RCS/httpd.conf,v -> httpd.conf
revision 1.2
done
```
