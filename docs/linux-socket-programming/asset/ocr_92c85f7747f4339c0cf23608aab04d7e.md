# Binding Ports to the Socket

The connection-based socket begins, as always, with a call to `socket()`. The server typically uses the reliable TCP protocol layer, so you can use the `SOCK_STREAM` flag. But, you must take it one step further—the clients need to know to which port to connect.

The `bind()` system call asks the system if your program can own a particular port number. Just like a sales company requests and publishes a central phone number for its clients, `bind()` selects a port number. If your server doesn't specify a port number, the operating system assigns the next available one from its pool of numbers. This port can be different each time you run the program if the OS assigns one for you.

You can also tell if the server is already executing if you request—but don't get—a specific port number. The operating system assigns the port to only one process.

The `bind()` system call looks like the following:

```
```
#include <sys/socket.h>
#include <resolv.h>
int bind(int sd, struct sockaddr *addr, int addrsze);
```
```

The `sd` variable is the socket descriptor you first created. First defined in [Chapter 1](#chapter_1), the variable `addr` points to a socket name (the port number) from the family of `sockaddr` records (defined in [Chapter 2, "TCP/IP Network Language Fluency"]) (#[chapter_2]). The last parameter you provide, `addrsze`, is the length of the `sockaddr` record.

The program needs to provide the size of the record to the operating system because of the whole concept of the Sockets API: one interface but many architectures. The operating system supports many protocols, each using its own naming structure, and each structure having a different size.

To use `bind()`, you need to create and fill `addr` (see [Listing 6.1](#listing_6_1)).

Example 6.1. Using bind() in a TCP Server
