3. 然后，我使用 vi 或任何文本编辑器打开 Makefile。你可以将 EXTRAVERSION 值更改为你喜欢的任何内容。例如，在我的系统上，最初的 Linux 内核是 2.4.18-3。此后我构建了许多其他内核，如 2.4.18-3ghosh、2.4.18-3smp、2.4.18-3_dummy、2.4.18-3bsd 等等。因此，EXTRAVERSION 代码有助于区分系统上大量可用的 Linux 内核。

4. 完成后，我保存并退出 Makefile。然后执行：make mrproper。它会清理编译文件夹中在同一系统上之前编译 Linux 内核时创建的任何垃圾。读者必须注意，所有执行的命令（包括此命令）都应从 /usr/src/linux-2.4 目录内执行。

5. 然后我执行：make menuconfig。读者如果有 X11 或 X Window 系统的访问权限，也可以使用 xconfig。

6. 进入 menuconfig 后，调整可用的选项。确保进入“File systems”部分，然后选择“UFS file system support (read-only)”和“UFS file system write support (DANGEROUS)”选项。因此，你应该得到类似这样的内容：<*> UFS file system support (read-only) 和 [*] UFS file system write support (DANGEROUS)。配置的内核级选项为：CONFIG_UFS_FS 和 CONFIG_UFS_FS_WRITE，分别对应只读和写入支持。此外，进入“Partition types”部分并选择 [*] BSD disklabel (FreeBSD partition tables) 选项，即 CONFIG_BSD_DISKLABEL 选项。这使你能够访问并读取 FreeBSD 切片中的 FreeBSD 磁盘标签。

7. 启用这三个选项后，我保存配置文件并退出。现在执行：make dep && clean。

8. 然后执行：make bzImage && modules 以创建压缩的 Linux 内核映像文件和相应的模块。

9. 然后执行：make modules_install 以将新创建的模块安装到各自对应的目录中。

10. 之后，我将 bzImage 文件复制到 /boot 目录。如果需要，你也可以使用 mkinitrd 命令创建初始 RAM 磁盘映像文件。

11. 完成后，我使用 vi 编辑器打开 /boot/grub/grub.conf 文件并在其中添加相应的条目。保存并退出。重新启动以检查新内核是否正常工作。我相信它会！

一旦新构建的自定义 Linux 内核安装完成，你就可以开始使用它来挂载 UFS 文件系统。使用此命令：mount -t ufs /dev/hda2 /mnt/bsd；前提是 /dev/hda2 是 FreeBSD 切片且 /mnt/bsd 存在。使用命令简单卸载：umount /mnt/bsd。

要在 Linux 上挂载 Windows 95/98/ME FAT32 文件系统，请使用命令：mount -t vfat /dev/hda1 /mnt/windows。/mnt/windows 目录必须存在于系统上。通过执行命令简单卸载：umount /mnt/windows。对于使用 NTFS 文件系统的读者，有坏消息！他们必须在配置文件中包含 NTFS 文件系统支持并构建自定义 Linux 内核。读者必须注意：NTFS 写入支持是危险的且有限的。

## 4. 故障排除

尽管 FreeBSD、OpenBSD 和 GNU/Linux 操作系统都是非常出色的软件，但在将它们全部或组合双启动或多启动 PC 时，人们经常会遇到问题。问题范围从易于检测和排除的到非常奇怪的问题。故障排除，正如所有 UNIX 老手所知（并欣赏），并不是一门精确的艺术。在本章中，我列出了我在双启动和多启动系统时遇到的一些问题，这些系统使用不同的操作系统和硬件。

读者必须注意，根据使用的特定硬件和发行版/版本，他们可能会遇到下面列出问题的略有不同版本。如果你遇到一个全新的问题，或者可以通过提供下面列出问题的更好解决方案为本指南做出贡献，请务必给我发邮件至：subhasish_ghosh@linuxwaves.com。

我个人在多启动系统方面的经验看到了一些奇怪的故障类型，并且经常出现不稳定的行为，但大多来自 Linux 的 fdisk 和安装程序。我经常为以后诊断和排除故障而做笔记。正如我所能得出的结论，在 Linux 发行版（包括 Red Hat、Slackware、SuSE 和 Mandrake）、OpenBSD 和 FreeBSD 版本中，FreeBSD 的 fdisk、disklabel 和整体安装程序（/stand/sysinstall）是其中最好的，绝对没有错误和突然崩溃。最初，我总是认为必须有一种精确的方式来安装所有这些操作系统，或者必须遵循一个确切的顺序，但随着时间的推移，我学到了真相：只要硬件支持良好，安装 CD-ROM 没问题，安装程序的不稳定行为是由于之前安装的未擦除数据造成的。因此，在致力于创建多启动系统之前，请确保在全新格式化的硬盘上开始安装。继续阅读以了解该程序的详细信息！一些常见的读者问题包括：

### Q1. 我创建了一个扩展分区，其中包含逻辑磁盘驱动器或其内的子分区。但当我安装 FreeBSD 时，它完全忽略了该分区内的内部分区。这是正常的吗？

Ans1: 是的，这绝对正常。FreeBSD 操作系统软件只能检测并表示它称为“slices”的主硬盘分区。扩展分区虽然会在 FreeBSD fdisk 中表示，但不会表示容器的组成部分。

### Q2. 我已成功在我的 PC 上安装了 FreeBSD 和 OpenBSD 操作系统。当我尝试安装 Red Hat Linux 时，Linux 的 fdisk 显示了“too many partitions”错误消息。这是什么意思？我现在可以做什么？
