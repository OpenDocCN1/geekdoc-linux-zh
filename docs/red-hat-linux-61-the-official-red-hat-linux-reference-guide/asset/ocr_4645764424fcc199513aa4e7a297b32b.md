After the client is granted access by TCP wrappers, the NFS server refers to its configuration file, /etc/exports, to determine whether the client can mount any of the exported file systems. After granting access, every file and directory operations are sent to the server using remote procedure calls.

> Warning
NFS mount privileges are granted specifically to a client, not a user. Exported file systems can be accessed by any users on the remote machine.

When configuring the /etc/exports file, be very careful when granting read-write permissions (rw) for an exported file system.

# 9.1.1. NFS and portmap

NFS relies upon remote procedure calls (RPC) to function. The portmap service is required to map RPC requests to the correct service. RPC services notify portmap when starting, revealing the port number they are monitoring and the RPC numbers they expect to serve. The client system connects to portmap with a particular RPC number. portmap redirects the client to the proper port number to communicate with its intended service.

Because RPC services rely on portmap to make all connections with incoming clients, portmap must be available before any of them start. For instance, the portmap service unexpectedly quits, restart portmap and any services running when it was started.

The portmap service uses with TCP wrappers' hosts files (/etc/hosts.allow and /etc/hosts.deny) to control remote systems are permitted to specify each of RPC-based services on the server. See Chapter 15 TCP Wrappers and xinetd for more information. Access control for portmap will affect all RPC-based services. Alternatively, it is possible to specify each of the NFS RPC daemons to be affected by a particular access control. The pages for rpc.mount and rpc.stat contain information regarding the precise syntax for these rules.

# 9.1.1.1. Troubleshooting NFS with portmap

As portmap provides the coordination between RPC services and the port numbers used to communicate with it, it is able to view the status of current RPC services using portmap when troubleshooting. The rpcinfo command shows each RPC-based service with its port number, RPC program number, version, and IP protocol type (TCP or UDP).

To make sure proper RPC-based services are enabled for portmap, use the rpcinfo -p command:

```
program vers proto port
100000 2 tcp 111 portmap
100000 2 udp 111 portmap
100024 1 udp 1024 status
100024 1 tcp 1024 status
100011 1 udp 819 rquotad
100011 2 udp 819 rquotad
100005 1 udp 1027 mountd
100005 1 tcp 1106 mountd
100005 2 udp 1027 mountd
100005 2 tcp 1106 mountd
100005 3 udp 1027 mountd
100005 3 tcp 1106 mountd
```
