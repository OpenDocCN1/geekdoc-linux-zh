# 16.3.5. Match Options

Different network protocols provide specialized matching options which may be set in specific ways to match a particular packet using that protocol. Of course, the protocol must first be specified in the iptables command, by using -p tcp <protocol-name> (where <protocol-name> is the target protocol), to make the options for that protocol available.

# 16.3.5.1. TCP Protocol

These match options are available for the TCP protocol (-p tcp):

+   - dport Sets the destination port for the packet. Use either a network service name (such as www or smtp), port number, or range of ports to configure this option. To browse the names and aliases of network services and the port numbers they use, view the /etc/services file. The --destination-port match option is synonymous with --dport.
- To specify a range of port numbers, separate the two numbers with a colon (;), such as -p tcp --3000:3200. The largest valid range is 0:65535.
- Use an exclamation point character (!) after the --dport option to tell iptables to match all packets which do not use network service or port.
- --sport Sets the source port of the packet using the same options as --dport. The --source match option is synonymous with --sport.
- --syn Applies to TCP packets designed to initiate communication, commonly called SYN packets. Any packets that carry a data payload are not touched. Placing an exclamation point character (!) as a flag after the --syn option calls all-SYN packets to be matched.
- --tcp-flags Allows TCP packets with specific bits, or flags, to be matched with a rule. The --tcp-flags match option accepts two parameters. The first parameter is the mask, which sets the flags to be examined in the packet. The second parameter refers to the flag that must be set in order to match.

+   - ACK
- FIN
- PSH
- RST
- SYN
- URG
- ALL
- NONE

For example, an iptables rule which contains -p tcp --tcp-flags ACK, FIN, SYN will only match TCP packets that have the SYN flag set and the ACK and FIN flags unset.

Using the exclamation point character (!) after --tcp-flags reverses the effect of the match option.

+   - --tcp-option Attempts to match with TCP-specific options that can be set within a particular packet. This match option can also be reversed with the exclamation point character (!).
