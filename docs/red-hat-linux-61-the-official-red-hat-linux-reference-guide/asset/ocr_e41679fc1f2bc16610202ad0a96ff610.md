# 202 Chapter 1. Pluggable Authentication Modules (PAM)

The pam_hosts_auth.so module authenticates the user using .hosts in the user's home directory. If this succeeds, PAM immediately considers the authentication to have succeeded. If pam_hosts_auth.so fails to authenticate the user, the authentication is ignored.

```
auth required /lib/security/pam_stack.so service=system-auth
```

If the pam_hosts_auth.so module fails to successfully authenticate the user, the pam_stack.so module performs normal password authentication.

The argument service=system-auth indicates that the user must pass through the PAM configuration for system authentication as found in /etc/pam.d/system-auth.

> Tip To prevent PAM from prompting for a password when the security result fails, change the pam_security.so module to require.

# 14.5. Creating PAM Modules

New PAM modules can be added at any time for PAM-aware applications to use. For example, if a developer introduces a one-time-password creation method and writes a PAM module to support it, PAMaware programs can immediately use this new module and password without being recompiled or modified. This allows developers and system administrators to mix-and-match, as well as test, authentication methods for different programs without recompiling them.

Documentation on writing modules is included with the system at /usr/share/doc/pam-<version-number>/ directory (where <version-number> is the version number for PAM).

# 14.6. PAM and Device Ownership

Red Hat Linux allows the first user to log in on the physical console of the machine the ability to manipulate devices and perform some tasks normally reserved for the root user. This is controlled by a PAM module called pam_console.so.

# 14.6.1. Device Ownership

When a user logs in to a machine under Red Linux, the pam_console.so module is called by login or the graphical logins, gdm and kdm. If it is the first user to log in the physical console—called the console user—the module grants the user ownership of a variety of devices normally owned by root. The console uses these devices until the last session for that user ends. Once the user has logged out, ownership of the devices reverts to the root user. The devices affected include, but are not limited to, sound cards, disk drives, and CD-ROM drives.

This allows a local user to manipulate these devices without attaining root, simplifying common tasks for the console user.

By modifying the file /etc/security/console.perms, the administrator can edit the list of devices controlled by pam_console.so.
