# Chapter 2. Berkeley Internet Name Domain (BIND)

Consider the following A record examples for the example.com zone:

```
IN A 10.0.1.3
server1 IN A 10.0.1.5
```

Requests for example.com are pointed to 10.0.1.3, while requests for server1.example.com are pointed to 10.0.1.5.

+   - CNAME — Canonical name record, maps one name to another. This type of record is also known as an alias record.

The next example tells that any requests sent to the <alias-name> will point to the host, <real-name>. CNAME records are most commonly used to point to services that use a common naming scheme, such as www for Web servers.

```
<alias-name> IN CNAME <real-name>
```

In the following example, an A record binds to an IP address, while a CNAME record commonly used hostname to it.

```
server1 IN A 10.0.1.5
www IN CNAME server1
```

+   - MX — Exchange record, which where numerical ranking is sent to a mail server controlled by this zone go.

```
IN MX <preference-value> <email-server-name>
```

In this example, the <preference-value> allows numerical ranking of the mail servers for a namespace, giving preference to some email systems over others. The MX record with the lowest <preference-value> is preferred over the others. However, multiple servers can share the same value to distribute mail traffic among them.

The <email-server-name> may be a hostname or FQDN.

```
IN MX 10 mail.example.com.
IN MX 20 mail2.example.com.
```

In this first example, mail.example.com email server is preferred to mail2.example.com when receiving email for the example.com domain.

+   - NS — NameServer record, which announces the authoritative nameserver for a particular zone.

This is an example of an NS record:

```
IN NS <nameserver-name>
```

The <nameserver-name> should be a FQDN.

Next, two nameservers are listed as authoritative for the domain. It is not important whether the nameservers are slaves or if one is a master; both are still considered authoritative.

```
IN NS dns1.example.com.
IN NS dns2.example.com.
```

+   - PTR — PointTeR record, designed to point to another part of the name.

PTR records are used reverse for name resolution, as they point IP addresses to a particular name. See Section 12.3.4 Reverse Name Resolution Zone Files for more examples of PTR records in use.

+   - SOA — Start Of Authority record, proclaims authoritative information about a namespace to the nameserver.

Located after the directives, an SOA resource record is the first record in a zone file.

The following example shows the basic structure of an SOA record:

```
@ IN SOA <primary-nameserver> <hostmaster-email>
<serial-number>
<time-to-refresh>
<time-to-retry>
<time-to-expire>
<minimum-TTL>
```
