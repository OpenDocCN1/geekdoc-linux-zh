# 11.2. Email Program Classifications

In general, all email applications fall into at least one of three classifications. Each classification plays a specific role in the process of moving and managing emails. Most users are aware of the specific email program they use to receive and send messages, each one is important for ensuring that mail arrives at the correct destination.

# 11.2.1. Mail Transfer Agent

A Mail Transfer Agent (MTA) transfers emails between hosts using SMTP. A message may involve several MTAs as it moves to its intended destination.

While the delivery between machines may seem rather straightforward, the process of deciding which particular MTA can or accept a message for delivery is quite complicated. In addition, due to problems from spam, the use of a particular MTA is usually restricted by the MTA's configuration or by the lack of access to the MTA's network.

Many modern email clients can act as an MTA when sending mail. However, this action should not be confused with the role of a true MTA. The reason email client programs are capable of sending out email (like an MTA) is the host running the application does not have its own MTA. This is particularly true for email programs on non-Unix/based operating systems. However, these client programs only send outbound messages to MTAs they are authorized to use and do not directly deliver the message to the recipient's email server.

Since Red Hat Linux includes two MTAs, Sendmail and Postfix, email client programs are often required to act as an MTA. Red Hat Linux also includes a special purpose called Fetchmail. For information on Sendmail and Fetchmail, refer to Section 11.3 Mail Transport Agents.

# 11.2.2. Mail Delivery Agent

A Mail Delivery Agent (MDA) is invoked by the MTA to file incoming email in the user's mailbox. In many cases, the MDA is actually a Local Delivery Agent (LDA), such as mail or Procmail.

Any program that actually handles a message for delivery to the point where it can be read by an email client can be considered an MDA. For this reason, some MTAs (such as Sendmail and Postfix) can fill the role of an MDA when they append new email messages to a local user's mail spool file. In general, MDAs do not transport messages between systems nor do they provide a user access; MDAs distribute and sort messages on the local machine for an email client application to access.
