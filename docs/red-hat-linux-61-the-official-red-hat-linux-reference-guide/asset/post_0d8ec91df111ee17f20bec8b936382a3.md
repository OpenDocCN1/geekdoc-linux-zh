
## Chapter 16. iptables

When looking at the structure of an iptables command, it is important to remember that, unlike other commands, the length and complexity of a iptables command can change based on its purpose. A simple command to remove a rule can be very short, while a command designed to filter packets from a particular subset using a variety of specific parameters and options can be lengthy. When creating iptables commands it is helpful to recognize that some parameters and options may need the need for other parameters and options to further specify the previous option's request. In order to construct a valid rule, this must continue until every parameter and option that requires another set of options is satisfied.

Type `iptables -h` to see a comprehensive list of iptables command structures.

### 16.3.3. Commands

Commands iptables to perform a specific action. Only one command is allowed per iptables command string. With the exception of the help command, all commands are written in upper-case characters.

The iptables commands are as follows:

- -A Appends the iptables rule to the end of the specified chain. This is the command used to simply add a rule when order in the chain does not matter.
- -C Checks a particular rule before adding it to the user-specified chain. This command can help you verify complicated iptables by prompting you for additional parameters and options.
- -D Deletes a rule in a particular chain by number (such as 5 for the fifth rule in a chain). You can also delete the entire rule, and iptables will delete the chain that matches.
- -E Renames a user-defined chain. This does not affect the structure of the table.
- -F Flushes the specified chain, which effectively deletes every rule in the chain. If no chain is specified, this command flushes every rule from chain.
- -h Provides a list of command structures, as well as a quick summary of command parameters and options.
- -I Inserts a rule in a chain at a point specified by a user-defined integer value. If no number is specified, iptables will place the command at the top of the chain.

# Caution

Be aware of which option (-A or -I) is used when adding a rule. The order of the rules within a chain are important for determining which rules apply to what packets.

- -L Lists all the rules in the chain specified after the command. To list all rules in all chains the default filter, do not specify a chain or table. Otherwise, the syntax should be used to list the rules in a specific chain in a particular:
`iptables -L <chain-name> -t <table-name>`
- -N Creates a new chain with a user-specified name.
- -P Sets the default policy for a particular chain, so that when packets traverse an entire chain without matching a rule, they will be sent to a particular target, such as ACCEPT or DROP.
- -R Replaces a rule in a particular chain. The rule's number must be specified after the chain's name. The first rule in a chain corresponds to rule number one.
- -X Deletes a user-specified chain. Deleting a built-in chain for any table is not allowed.

Powerful options for the -L command that provide rules and allow more verbose rule descriptions, others, are described in Section 16.3.7 Listing Options.

- -Z — Zeros the byte and packet counters in all chains for a particular chain.

### 16.3.4. Parameters

Once iptables commands are specified, including those used to add, append, delete, insert, or replace rules within a particular chain, parameters are required to construct a packet filtering rule.

- -c — Resets the counter for a particular rule. This parameter accepts the PKTS and BYTES options to specify which counter to reset.

- -d — Sets the destination hostname, IP address, or network of a packet that will match the rule. When matching a network, the following IP address/network formats are supported:

- N.N.N/M.M.M.M — Where N.N.N is the IP address range and M.M.M.M is the netmask.
- N.N.N/M — Where N.N.N is the IP address and M is the netmask.
- -f — Applies this rule only to fragmented packets.
By using ! after this parameter, only unfragmented packets will be matched.

- -i — Sets the incoming interface, such as eth0 or pp0. With iptables, this optional parameter may only be used with the INPUT and FORWARD chains when used with the filter PREROUTING chain with the nat and mangle tables.
This parameter also supports the following special options:

- ! — Tells parameter not to match, meaning that any specified interfaces are specifically excluded from this rule.
- + — A wildcard used to match all interfaces, then every interface is affected by the rule. For example, -eth* would apply this rule to any Ethernet interface except other interfaces, such as pp0.

If the -i is used but no interface is specified, then the standard options, ACCEPT, DROP, QUEUE, and RETURN, as well as extended options that are available through modules loaded by default by the Red Linux RPM package, such as LOG, MATCH, and REJECT, among others. See the iptables page for more information on these other targets.

You may also make a direct matching to a user-defined chain outside of the current chain so that other rules can be applied to the packet.

If no target is specified, the packet moves past the rule with no nat action. However, the counter for this is still increased by one, as the packet matched the specified rule.

- -o — Sets the outgoing interface for a rule and may only be used with OUTPUT and FORWARD chains in the filter table, and the POSTROUTING chain in the nat and mangle tables. This parameter's options are the same as those of the incoming network interface parameter (-i).

- -p — Sets the IP protocol for the rule, which can be icmp, tcp, udp, or all, to match every supported protocol. In addition, any protocols listed in /etc/protocols may also be used. If this option is omitted when creating a rule, a all is the default option.

- -s — Sets the source for a particular packet using the same syntax as the destination (-d) parameter.

### 16.3.5. Match Options

Different network protocols provide specialized matching options which may be set in specific ways to match a particular packet using that protocol. Of course, the protocol must first be specified in the iptables command, by using -p <protocol-name> (where <protocol-name> is the target protocol), to make the options for that protocol available.

#### 16.3.5.1. TCP Protocol

These match options are available for the TCP protocol (-p tcp):

- dport Sets the destination port for the packet. Use either a network service name (such as www or smtp), port number, or range of ports to configure this option. To browse the names and aliases of network services and the port numbers they use, view the /etc/services file. The --destination-port match option is synonymous with --dport.
- To specify a range of port numbers, separate the two numbers with a colon (:), such as -p tcp --3000:3200. The largest valid range is 0:65535.
- Use an exclamation point character (!) after the --dport option to tell iptables to match all packets which do not use network service or port.
- --sport Sets the source port of the packet using same options as --dport. The --source match option is synonymous with --sport.
- --syn Applies to TCP packets designed to initiate communication, commonly called SYN packets. Any packets that carry a data payload are not touched. Placing an exclamation point character (!) as a flag after the --syn option calls all-SYN packets to be matched.
- --tcp-flags Allows TCP packets with specific bits, or flags, to be matched with a rule. The --tcp-flags match option accepts two parameters. The first parameter is the mask, which sets the flags to be examined in the packet. The second parameter refers to the flag that must be set in order to match.

- ACK
- FIN
- PSH
- RST
- SYN
- URG
- ALL
- NONE

For example, an iptables rule which contains -p tcp --tcp-flags ACK, FIN, SYN will only match TCP packets that have the SYN flag set and the ACK and FIN flags unset.

Using the exclamation point character (!) after --tcp-flags reverses the effect of the match option.

- --tcp-option Attempts to match with TCP-specific options that can be set within a particular packet. This match option can also be reversed with the exclamation point character (!).
