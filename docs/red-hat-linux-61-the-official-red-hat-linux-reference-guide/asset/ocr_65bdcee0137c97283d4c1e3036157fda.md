# 10.2.4. Modules and Apache HTTP Server 2.0

In Apache HTTP 2.0, the system module has changed to allow modules to be chained
together or combined in new and interesting ways. Common Gateway Interface (CGI) scripts, for-
, can generate server-parsed HTML documents that can be processed by mod_include.
This opens up a tremendous range of possibilities with regards to how modules can be combined to
aieve a specific goal.

The way by which each request is served by exactly one module followed by zero or
more filters.

Under Apache HTTP 1.3, for example, a PHP script would be handled in the entirety by the
PHP module. Under Apache HTTP 2.0, the request is initially handled by the core module
which serves static files and is filtered by the PHP module.

Exactly how to use this, and all the other features of Apache HTTP 2.0 for that matter,
in the scope of this document; however, the change ramifications if the PATH_INFO directive
is used for a document handled by a module that is now implemented as a filter, as each-
contains trailing path information after the true file name. which initially handles the
request, is not by default understand PATH_INFO and will return 404 Not Found errors for-
quests contain such information. As an alternative, use the AcceptPathInfo directive to coerce
the module into accepting requests with PATH_INFO.

The following is an example of this technique:

```
AcceptPathInfo on
```

For on this topic, refer to the following documentation on the Apache Software Foundation’s
website:

+   - httpd.apache.org/docs-2.0/mod/core.html#acceptpathinfo
