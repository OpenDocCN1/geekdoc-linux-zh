
## 5.3.10. /proc/sysvipc/

This directory contains information about System IPC resources. The files in this directory relate to System IPC calls for messages (msg), semaphores (sem), and shared memory (shm).

## 5.3.11. /proc/tty/

This directory contains information about the available and currently used tty devices on the system. Originally called teletype devices, any character-based terminals are called tty devices.

In Linux, there are three different kinds of tty devices. Serial devices are used with serial connections, such as a modem or over a serial connection. Virtual terminals are used by the common console connection, as the virtual consoles are available when pressing [Alt]-[F-Key] at the system level. Pseudo terminals are a virtual two-way communication that is used by some higher level applications, such as XFree86. The drivers file is a list of currently used tty devices:

```
serial           /dev/cu        5 64-127 serial:callout
serial           /dev/ttyS      4 64-127 serial
pty_slave        /dev/pts      136 0-255 pty:slave
pty_master       /dev/ptm      128 0-255 pty:master
pty_slave        /dev/ttyp      3 0-255 slave
pty_master       /dev/pty       2 0-255 pty:master
/dev/vc0         /dev/vc0       5 0 system:vtmaster
/dev/ptmx        /dev/ptmx      5 2 system
/dev/console     /dev/console  1 system:console
/dev/tty          /dev/tty       5 system:dev/tty
unknown          /dev/kd        4 1-6 console
```

The /proc/tty/driver file lists the usage statistics and status of each serial tty lines.

In order that tty devices can be used in a similar as network devices, the Linux kernel will enforce line discipline on the device. This allows the driver to place a specific type of header with every block of data transmitted over the device, making it possible for the remote of the connection to see a block of data as just one stream of data blocks. SLIP and PPP are common line disciplines, and each are commonly connected to systems to one another via serial link.

Registered line disciplines are stored in the ldiscs file, with detailed information available in the ldiscisc directory.

## 5.4. Using the sysctl command

The /sbin/sysctl command is used to view, set, and automate kernel settings in the /proc/sys/ directory.

To get a quick overview of all configurable in the /proc/sys/ directory, type the /sbin/sysctl -a as root. This will create a large, comprehensive, small portion of which looks like this:

```
net.ipv4.route.min_delay = 2
kernel.sysrk = 0
kernel.sem = 250 32000 32 128
```

This is the same information if each of the files were viewed individually. The only difference is the file location. The /proc/sys/net/ipv4/route/min_delay is signed by net.ipv4.route.min_delay, with the directory slashes replaced by dots and the proc.sys assumed.

# Chapter 5. The proc File System

The sysctl command can be use in place of echo to assign values to writable files in /proc/sys/ directory. For instance instead of using this command:

```
echo 1 > /proc/sys/kernel/sysrq
```

You can use the sysctl command:

```
sysctl -w sysrq="1"
kernel.sysrq = 1
```

While quickly setting values like that in /proc/sys/ is helpful during testing, it does not work as well on a production system. All /proc/sys/ special settings are lost when the machine is rebooted. To preserve the settings that you would like to make permanent to the kernel, add them to the /etc/sysctl.conf file.

Every time the system boots, the init program runs the /etc/rc.d/rcinit script. This script contains a command to execute sysctl /etc/sysctl.conf to dictate the values passed to the kernel. Any values added to /etc/sysctl.conf will affect each time the system boots.

# Chapter 6. Users and Groups

Control of users and groups is a core element of Linux system administration. Users can be either people, meaning accounts tied to physical users, or accounts which exist for specific applications. Groups are logical expressions of organization, tying users together for a common purpose. Each user and group have a unique identification called a userid (UID) and groupid (GID) respectively. When a file is created, it is assigned to a user and group. It is also assigned separate read, write, and execute permissions for the owner, the group, and everyone else. The group to which a file belongs be changed by the root user, or by the creator of the file. Proper management of users and effective management of permissions are among the most important tasks a system administrator undertakes. Managing users and groups can be a tedious task, but the easiest way to manage them is through the graphical application redhat-config-users. The following command tools can also be used:

- useradd, usermod, and userdel — Industry-standard methods of adding and modifying user accounts.
- groupadd, groupmod, and groupdel — Industry-standard methods of adding and modifying user groups.
- gpasswd — Industry-standard method of administering the password.
- pwck, pwunconv — Tools for verifying and converting back to standard words.

For an overview of users and group management, see the chapter titled User and Group Configuration Guide.
