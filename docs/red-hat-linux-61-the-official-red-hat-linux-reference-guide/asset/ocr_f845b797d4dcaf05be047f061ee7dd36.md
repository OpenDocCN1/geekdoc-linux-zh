Berkeley Internet Name Domain (BIND)

On most modern networks, including the Internet, users locate other computers by name. This frees users from the daunting task of remembering the numerical network address of network resources. The most effective way to configure a network to allow such name-based connections is to set up a Domain Name Service (DNS) or nameservers, which resolves hostnames on the network to addresses and vice versa.

This chapter reviews the nameserver included in Red Hat Linux, Berkeley Internet Name Domain (BIND) DNS server, with an emphasis on the structure of its configuration and how it may be administered both locally or remotely.

For instructions on configuring BIND using the graphical Bind Configuration Tool (redhat-config-bind), refer to the chapter BIND Configuration in the Red Hat Linux Customization Guide.

# 12.1. Introduction to DNS

When hosts on a network connect to one another via a hostname, also called a fully qualified domain name (FQDN), DNS is used to associate the names of machines to the IP address for the host.

Use of DNS and FQDNs has advantages for system administrators, allowing the flexibility to change the IP address of a host without affecting name-based queries to the machine. Conversely, administrators can shuffle which machines handle a name-based query.

DNS is normally implemented using centralized servers that are authoritative for some domains and other DNS servers for other domains.

When a client requests information from a nameserver, it usually connects to port 53. The nameserver then attempts to resolve the FQDN based on its resolver library, which may contain information about the requested or cached data from an earlier query. If the nameserver does not have the answer in its local resolver, it queries other nameservers, including root nameservers, to determine which authoritative nameservers are authoritative for the FQDN in question. With information, the authoritative nameservers determine the IP address of the requested host. If performing a recursive lookup, the same procedure is used, except the query is made with an unknown IP address rather than a name.
