# 17.6. Configuring a Kerberos 5 Client

Setting up Kerberos 5 client is less involved than setting up a server. At a minimum, install the client packages and provide each client with a kerb5.conf configuration file. Kerberized versions of rsh and rlogin will require some configuration changes.

+   1. Be sure that you have synchronization between the Kerberos client and the KDC. See 17.5 Configuring a Kerberos 5 Server for more information. Additionally, verify that DNS is working properly on the Kerberos client before configuring the Kerberos client programs.

+   2. Install the kerb5-libs and kerb5-workstation packages on all the client machines. You must supply a version of /etc/kerb5.conf for each client; this can be the same as kerb5.conf file used by the KDC.

+   3. Be a workstation in the realm that allows users to connect using Kerberos rsh and rlogin, that workstation will need to have the xinetd package installed and its own principal in the Kerberos database. The kshd and klogind server programs will also need access to the keys for their service's principal.
Using kadmin, add a principal for the workstation on the KDC. The instance in this case will use the -randkey option to kadmin's addprinc command to generate a random key:
addprinc -randkey host/blah.example.com
Now you have created the principal, you can extract the keys for the workstation by running kadmin on the workstation itself, and using the ktadd command within kadmin:
tadd -k /etc/kerb5.keytab host/blah.example.com
