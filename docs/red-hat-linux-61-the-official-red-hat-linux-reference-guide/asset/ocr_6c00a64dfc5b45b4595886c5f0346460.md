# 9.2. autofofs

One drawback to using /etc/fstab is, regardless of how infrequently a user may access the NFS mounted file system, the system must dedicate resources to keep that in place. This is not a problem with one or two mounts, but when the system is maintaining mounts to dozens systems at one time, overall system performance can suffer. An alternative to /etc/fstab is to use the kernel-based mount utility, which will manage NFS file systems automatically, saving resources.

The autofofs script, located in the /etc/rc/init.d/, is designed to control automount while mount can be specified in the command line, it is more convenient to specify the mount, hostname, exported directory, and options in files rather than typing them all by hand. By running autofofs as a service that starts and stops in designated runlevels, the mount configurations in the various files can be automatically implemented.

The autofofs configuration files are arranged in a parent-child relationship. A configuration file (/etc/auto.master) refers mount points on your system that are linked to a particular map type, which takes the form of other configuration files. For NFS exports it is to use a file as the map type for the particular mount point. The auto.master file contains lines referring to each of the mount points, organized like this:

```
<mount-point>                                 <map-type>
```

The <mount-point> element of this line indicates the location of the mount on the file system. The <map-type> relates to the way in which the mount point will be mounted. The most common method for automount NFS exports is to use a file as the map type for the particular mount point. The map file, usually named auto.<mount-point>, where <mount-point> is the mount point designated in auto.master, contains lines that like this:

```
<directory>  <mount-options> <host>:<exported-file-system>
```

The <directory> refers to the directory within the mount point where the exported file system should be mounted. Like a standard mount command, the hosting export file system, as well as the file system exported, are required in the <host>:<exported-file-system>. To specify particular options to use when mounting the exported file system, place in the <mount-options> section, separated by commas. For NFS mounts that use autofofs, place -fstype=nfs in the <mount-options> section.

While autofofs configuration files can be used for a variety of mounts to many types of devices and files, they are particularly useful in creating NFS mounts. For example, some organizations store a user's directory on a central server via NFS. Then, they configure the auto.master file on each of an auto.home file containing the specifics for how to mount the /home/directory via NFS. This allows the user to access personal data and configuration files in their /home/directory by logging in anywhere on the internal network. The auto.master file in this situation would look similar to:

```
/home                               /etc/auto.home
```
