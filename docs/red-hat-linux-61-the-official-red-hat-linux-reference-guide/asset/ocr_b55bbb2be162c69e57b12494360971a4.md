# 1.2.4. The /sbin/init Program

The /sbin/init program (also called *init*) coordinates the rest of the boot process and configures the environment for the user.

When the init starts, the parent or grandparent of all the processes that start up automatically on a Red Linux system, for example runs `/etc/rc/rc.init` script, which sets the environment path, starts swap, checks the file systems, and takes care of everything the system needs to handle at initialization. For example, some systems use a lock file, as `rc.sysinit` reads the `/etc/sysconfig/config` file to initialize the hardware clock.

Another example is if there is special port script which must be initialized, `rc.sysinit` will execute the `/etc/init.file` script.

The init command runs `/etc/inittab` script which shows how the system should be set up in each SysV init runlevel. Among others, the `/etc/inittab` sets the default runlevel and dictates that `/sbin/init` should be run whenever it starts at a runlevel 4.

The next, init command starts the source function, or `/etc/init.d/functions`, for the system. This tells us how to start or kill a program and how to determine the PID of a program.

The init program starts all the background processes by looking in the appropriate `rc` directory for the runlevel as default in `/etc/inittab`. For instance, `/etc/rc/rc5/` is the directory for runlevel 5.

When booting to runlevel 5, the init program looks in the `/etc/rc/rc5/` directory to determine which processes to stop and start.
