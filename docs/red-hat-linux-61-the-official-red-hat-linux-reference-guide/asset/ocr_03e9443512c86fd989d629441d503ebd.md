# Chapter 12. Berkeley Internet Name Domain (BIND)

```
$ORIGIN example.com
$TTL 86400
@ IN SOA dns1.example.com. hostmaster.example.com. (
    2001062501 ; serial ; refresh after 6 hours
    21600 ; retry after 1 hour
    3600
    604800 ; expire after 1 week
    86400 ) ; minimum TTL of 1 day

IN NS dns1.example.com.
IN NS dns2.example.com.

IN MX 10 mail.example.com.
IN MX 20 mail2.example.com.

IN A 10.0.1.5
server1 IN A 10.0.1.5
server2 IN A 10.0.1.7
dns1 IN A 10.0.1.2
dns2 IN A 10.0.1.3

ftp IN CNAME server1
mail IN CNAME server1
mail2 IN CNAME server2
www IN CNAME server2
```

In this example, standard directives and SOA values are used for dns1.example.com and dns2.example.com, which have records that point to 10.0.1.2 and 10.0.1.3.

The email servers configured with the MX records point to server1 and server2 via CNAME records. Since the server1 and server2 names do not end in a trailing period (.), the $ORIGIN domain is placed after them, forming server1.example.com and server2.example.com. Through the related A resource records, their IP addresses can be determined.

FTP and Web services, at the standard ftp.example.com and www.example.com names, are pointed to the appropriate servers using CNAME names.

# 12.3.4 Reverse Name Resolution Zone Files

A reverse name zone file is used to translate an IP address in a particular namespace into a FQDN. It works similarly to a standard zone file, except that PTR records are used to link the IP addresses to a fully qualified name.

A PTR record looks like this:

```
<last-IP-digit> IN PTR <FQDN-of-system>
```

The <last-IP-digit> relates to the name in an IP address that should point to a particular system's FQDN.

In this example, IP addresses 10.0.1.20 through 10.0.1.25 are pointed to corresponding FQDNs.

```
$ORIGIN 10.0.1.in-addr.arpa
$TTL 86400
@ IN SOA dns1.example.com. hostmaster.example.com. (
    2001062501 ; serial ; refresh after 6 hours
    21600
    3600 ; retry after 1 hour
```
