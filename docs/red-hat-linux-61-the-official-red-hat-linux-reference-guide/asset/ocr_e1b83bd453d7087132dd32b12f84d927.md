Except for the hostname, each section is called a zone, which defines a specific namespace. A namespace controls the mapping of the sub-domains to its left. While this example contains two sub-domains, a FQDN must contain at least one sub-domain but may include many, depending upon how the namespace is organized.

Zones are defined as authoritative nameservers through zone files, which describe the namespace of that zone, the mail servers are for a particular domain or sub-domain, and more. Zones are stored on primary nameservers (also called master nameservers), which are truly authoritative and where changes are made to the files, and secondary nameservers (also called slave nameservers), which receive their zone files from the primary nameservers. Any nameserver can be a primary and secondary nameserver for different zones at the same time, and they may also be considered authoritative for multiple zones. It depends on how the nameserver is configured.

#  12.1.2. Nameserver Types

There are primary nameserver configuration types:

+   master - Stores authoritative zone records for a certain namespace, answering questions from other nameservers searching for answers concerning that namespace.

+   slave - Queries answers from other nameservers concerning namespaces for which it is not authoritative. However, slave nameservers get their names information from master nameservers.

+   caching-only — Offers name to IP resolution services but is not authoritative for any zones. Answers for all resolutions are cached in memory for a fixed period of time, which is specified by the retrieved zone.

+   forwarding — Forwards requests to a specific list of nameservers for name resolution. If none of the specified nameservers can perform the resolution, the resolution fails.

A nameserver may be one or more of these types. For example, a nameserver can be a master for some zones, a slave for others, and only offering resolutions for others.

#  12.1.3. BIND as a Nameserver

BIND performs name resolution services through the /usr/sbin/named daemon. BIND also includes an administration utility called /usr/sbin/rndc. More information about rndc can be found in Section 12.4 Using rndc.

BIND stores configuration files in the following places:

+   /etc/named.conf — The configuration file for the named daemon.

+   /var/named/ directory — The named working directory which stores zone, statistic, and cache files.
