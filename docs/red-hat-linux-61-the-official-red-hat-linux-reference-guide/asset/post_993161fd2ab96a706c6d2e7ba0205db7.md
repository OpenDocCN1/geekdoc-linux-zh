## Appendix A.

### General Parameters and Modules

This appendix is provided to illustrate some of the possible parameters available for common hardware drivers¹, which under Red Hat Linux are called kernel modules. In most cases, the default parameters will work. However, there may be times when extra module parameters are necessary for a device to function or if it is necessary to override module's parameters for the device.

During installation, Red Hat Linux uses a limited subset of drivers to create a stable installation environment. Although the installation program supports installation on many different types of hardware, some (including drivers for SCSI, network adapters, and many CD-ROM devices) are not included in the installation kernel. Rather, they must be loaded as modules by the user at boot time. For information on how one can find extra kernel modules during the installation process, refer to the section concerning alternative boot methods in the chapter titled Steps to Get Started in the Red Hat Linux Installation Guide.

Once installation is completed, support exists for a large number of devices through kernel modules.

### A.1. Specifying Module Parameters

In situations, it may be necessary to supply parameters to a module as it is loaded in order for it to function properly. This can be done in one of two ways:

- Specify a full set of parameters in one statement. For example, the parameter cdu31=0x340,0 could be used with a Sony CDU 31 or 33 at port 340 with no IRQ.
- Specify the parameters individually. This method is used when one or more parameters in the first set are not needed. For example, cdu31_port=0x340 cdu31_irq=0 can be used as the parameter for the same CD-ROM, SCSI, and Ethernet tables in this appendix to show where the first parameter method stops and the second method begins.

> Note
Only use one method, and not both, when loading a module with specific parameters.

> Caution
When a parameter has commas, be sure not to put a space after a comma.

1. A driver is software that enables Linux to use a particular hardware device. Without a driver, the kernel cannot communicate with attached devices.
