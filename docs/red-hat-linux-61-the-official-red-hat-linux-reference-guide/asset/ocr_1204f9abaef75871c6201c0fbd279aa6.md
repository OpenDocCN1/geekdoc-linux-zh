Chapter 2. Boot Loaders

The boot process used by other operating systems may differ. For example, Microsoft's DOS and Windows operating systems, as well as any other proprietary operating systems, are loaded using a chain loading boot method. Under this method, the MBR points to the first sector of the partition holding the operating system. It finds the files necessary to actually boot that operating system.

GRUB supports both direct and chain-loading boot methods, allowing it to boot almost any operating system.

Warning

During installation, the Microsoft's DOS and Windows installation program completely overwrites the MBR, destroying any existing boot loader. If creating a dual-boot system, it is best to install the Microsoft operating system first. For instructions on how to do this, see the appendix titled Installing Red Hat Linux in a Dual-Boot Environment in the Red Hat Linux Installation Guide.

# 2.2.2. Features of GRUB

GRUB contains a number of features that make it preferable to other boot loaders available for the x86 architecture. Below is a partial list of all the most important features:

+   * GRUB provides a true command-based, pre-OS environment on x86 machines. This affords the user maximum flexibility in loading operating systems with certain options or gathering information about the system. For years, many x86 architectures have developed pre-OS environments that allow booting from a command line. While some command features are available with LILO and other x86 boot loaders, GRUB is more feature.
* GRUB supports Logical Block Addressing (LBA) mode. LBA addresses the address conversion to boot files in the hard drive's firmware, and is used by any IDE and all SCSI devices. Before LBA, boot loaders could not encounter the 1024-cylinder BIOS limitation, where the BIOS could not find a file that cylinder held the disk. LBA support allows GRUB to boot operating systems from partitions beyond the 1024-cylinder limit, so long as the system BIOS supports LBA. Most modern BIOS revisions support LBA.
* GRUB can read partitions. This functionality allows GRUB to access its configuration file, /boot/grub/grub.conf, every time the system boots, eliminating the need for the user to write a new version of the first boot loader to MBR when configuration changes are made. The only time a user would need to reinstall GRUB on the MBR is if the physical location of the /boot partition is moved on the disk. For details on installing GRUB to the MBR, see Section 2.3 Installing GRUB.

# 2.3. Installing GRUB

If GRUB was not installed during the Red Hat Linux installation process it can be installed afterward. Once installed, it becomes the default boot loader.

Before installing GRUB, make sure to use the latest GRUB package available or use the GRUB package from the Red Hat Linux installation CD-ROMs. For instructions on installing packages, see the chapter titled Package Management with RPM in the Red Hat Linux Customization Guide.

Once the GRUB package is installed, open a root shell and prompt the command /sbin/grub-install <location>, where <location> is where Stage 1 boot loader should be installed.
