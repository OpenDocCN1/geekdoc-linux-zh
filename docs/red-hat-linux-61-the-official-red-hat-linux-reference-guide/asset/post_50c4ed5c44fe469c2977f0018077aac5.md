# 9.2. NFS Server Configuration Files

Configuring a server to share files and directories using NFS is a simple process. Every file system is exported to remote users via NFS, with the access rights relating to those files, located in the /etc/exports file. This file is read by the exportfs command to give rpc.mountd rpc.nfs information necessary to allow the remote mounting of a file system by an authorized host.
The exportfs command allows the root user to selectively export or export directories without restarting the service. When exportfs is passed the options, the file systems are exported written to /var/lib/nfs/stab. Since rpc.mount refers to the xtab when deciding access privileges to a file system, changes to the list of exported files take effect immediately.
Various options are available when using exportfs:

- -r — Causes all directories listed in /etc/exports to be exported by constructing a new export list in /etc/lib/nfs/stab. This option effectively refreshes the export list with any changes that have been made to /etc/exports.
- a — Causes all directories to be exported or unexported, depending on the other options passed to exportfs.
- o — Allows the user to specify directories to be exported that are not listed in /etc/exports. This additional file system must be written in the same way they are specified in /etc/exports. This option is used to test an exported file system before adding it permanently to the list of files to be exported.
- i — Ignore /etc/exports; only options given from the command line are used to define exported file systems.
- u — Unexports directories being mounted by remote users. The command exportfs -ua effectively suspends NFS sharing while keeping the various NFS daemons up. To allow NFS sharing to continue, type exportfs -r.
- v — Verbose output, where the file systems exported or unexported are displayed in greater detail when the exportfs command is executed.

If no options are passed to the exportfs command, it displays a list of currently exported file systems.
Changes to /etc/exports can also be made by reloading the NFS service with the service nfs reload command. This keeps the NFS daemons running while re-exporting the /etc/exports file.

# 9.2.1. /etc/exports

The /etc/exports files control which files are exported to remote hosts and specifies options. Blank lines are ignored, can be made by starting a line with the hash mark (#), and long lines can be wrapped with a backslash (\). Each exported file system should be on its own individual line. Lists of authorized hosts placed after an exported file system must be separated by space characters. Options for each of the hosts must be placed in parentheses after the host identifier, without any spaces separating the first and the last parenthesis.

In its simplest form, /etc/exports only needs to know the directory to be exported and the hosts permitted to use it:

```
/some/directory bob.example.com
another/exported/directory 192.168.0.3
```

After re-exporting /etc/exports with the /bin/service nfs reload command, the bob.example.com host will be able to mount /some/directory and 192.168.0.3 can mount another/exported/directory. Because no options are specified in this example, several default NFS preferences take:

- Read — Hosts mounting this file system will not be able to change it. To allow hosts to make changes to the file system, the rw (read-write) option must be specified.
- async — Allows the server to write to disk when it sees fit. While this is important if the host is accessing as read-only, or if host makes changes to a read-write file system and the server crashes, data could be lost. By specifying the sync option, all writes are committed to the disk requested by the client. This may improve performance.
- wdelay — Causes the NFS to delay writing to the disk if it suspects another other write is imminent. This can improve performance by reducing the number of times the disk must be accessed by separate write commands, reducing overhead. The no_wdelay option turns off this feature, but is only available when using the sync option.
- root_squash — Strips roots connected remotely from having root privileges by assigning them nobody user. This effectively "squashes" the power of the root user to the local user, preventing remote users from acting as they were the root on the local system. The no_root_squash option turns off root squashing. To squash every remote user, using root, the all_squash option specifies the user and group IDs respectively. In this case, a special user can be created for remote NFS users to share and specify (if uid=<uid-value> ngid=<gid-value>, where <uid-value> is the user number and <gid-value> is the group ID in value).

In order to override these, you must specify an option that allows that. For example, if you do not specify rw, that export will only be read-only. For every exported file system must be included. This allows in the ability to disable sub-tree checking, allow access from insecure ports, and insure file locks (necessary for early NFS client implementations). The exports man page for details on these used options.

When specifying hosts, use the following methods:

- single host — Where particular host is specified with fully qualified domain name, hostname, or IP address.
- wildcards — Where a * or ? character is used to take into account a grouping of fully qualified domain names that match a pattern string of characters. Wildcards are not to be used with IP addresses; however, they may accidentally work if reverse DNS lookups fail.

> > Warning The format of the /etc/exports file is very precise, particularly in regards to use of the space character. Remember to always save exported file systems from another with a space character. However, there should be no space characters in the file except on comment lines.
> For example, the two lines do not mean the same thing:

```
/home bob.example.com (rw)
home bob.example.com (rw)
```

The first line allows only users from bob.example.com read-write access to the /home directory. However, this requires that the second line allows users from bob.example.com to mount the directory read-only (the default), but the rest of the world can mount it read-write.

# 9.3. NFS Client Configuration Files

Any NFS share available by a server can be mounted using various methods. The share can be manually mounted, using the mount command. However, this requires the root user type the mount command every time the system restarts. Two methods of configuring NFS shares to be mounted automatically by modifying /etc/fstab or using the autofofs service.

# 9.3.1. /etc/fstab

Placing a properly formatted line in the /etc/fstab file has the same effect as mounting the exported file system. The /etc/fstab file is read by the /etc/rc.init.d/netfs script at system startup and any NFS shares listed will be mounted.

A sample /etc/fstab for an NFS export looks like the following:

```
<server>:/path/to/dir <local/mount/point> nfs <options> 0 0
```

The <server-host> corresponds to hostname, IP address, or fully qualified domain name of the exporting file system.

The <path/to/directory> specifies where the local file system to mount the exported directory. This mount point must exist before /etc/fstab is read or the mount will fail.

The nfs option specifies the type of file system being mounted.
