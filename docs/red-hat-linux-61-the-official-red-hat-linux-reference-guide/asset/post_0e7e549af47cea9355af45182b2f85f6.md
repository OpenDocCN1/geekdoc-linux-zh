### 4.1.1. /etc/sysconfig/amd

The /etc/sysconfig/amd file contains various parameters used by amd, which allow for the automatic mounting and unmounting of file systems.

### 4.1.2. /etc/sysconfig/apmd

The /etc/sysconfig/apmd file is used by apmd as a configuration for what on off power settings to start/stop on suspend or resume. It is configured to turn on apmd at boot time, depending on whether the hardware supports Advanced Power Management (APM) or whether the user has configured the system to use it. The apmd daemon is a monitoring program that works with power management code within the Linux kernel, capable of alerting users to low battery power on laptops and other power-related settings.

### 4.1.3. /etc/sysconfig/arpwatch

The /etc/sysconfig/arpwatch file is used to pass arguments to the arpwatch daemon at boot time. The arpwatch daemon maintains a table of Ethernet MAC addresses and their IP address pairings. For more information about what parameters are available for this file, see the arpwatch man page. By default, this file sets the owner of the arpwatch process to the user pcap.

### 4.1.4. /etc/sysconfig/authconfig

The /etc/sysconfig/authconfig file sets the kind of authorization to be used on the host. It contains one or more of the following lines:

- USEMD5=<value>, where <value> is one of the following:
  - yes — MD5 is not used for authentication.
  - no — MD5 is not used for authentication.

- USERKERBOS=<value>, where <value> is one of the following:
  - yes — Kerberos is used for authentication.
  - no — Kerberos is not used for authentication.

- USELDAPUTH=<value>, where <value> is one of the following:
  - yes — LDAP is used for authentication.
  - no — LDAP is not used for authentication.

### 4.1.5. /etc/sysconfig/clock

The /etc/sysconfig/clock file controls the interpretation of values read from the system hardware clock.

The correct values are:

- UTC=<value>, where <value> is one of the following boolean values:
  - true or yes — The hardware clock is set to Universal Time.
  - false or no — The hardware clock is set to local time.

- ARC=<value>, where <value> is the following:
  - true or yes — The ARC console's 42-year time offset is in effect. This setting is only for ARC- or AlphaBIOS-based systems. Any other value indicates that the normal UNIX epoch is in use.

- SRM=<value>, where <value> is the following:
  - true or yes — The SRM console's 1900 epoch is in effect. This setting is only for SRM-based systems. Any other value indicates the normal UNIX epoch is in use.

- ZONE=<filename> — The timezone file under /usr/share/zoneinfo that /etc/localtime is a copy of it. This file contains information such as:
  ZONE="America/New York"

Earlier releases of Red Linux use the following values (which are deprecated):

- CLOCKMODE=<value>, where <value> is one of the following:
  - GMT — The clock is set to Universal Time (Greenwich Mean Time).
  - ARC — The ARC console's 42-year time offset is in effect (for Alpha-based systems only).

### 4.1.6. /etc/sysconfig/desktop

The /etc/sysconfig/desktop file specifies the desktop manager to be run, such as:

DESKTOP="GNOME"

The /etc/sysconfig/dhcpd file is used to pass arguments to the dhcpd daemon at boot time. The dhcpd daemon implements the Dynamic Host Configuration Protocol (DHCP) and the Internet Bootstrap Protocol (BOOT). DHCP and BOOT assign hostnames to machines on the network. For more information about parameters available in this file, see the dhcpd man page.

With Red Hat Linux 8.0, the first time the system boots, the /sbin/init program calls the /etc/rc.d/init.d/firstboot script, which launches Setup Agent. This application allows the user to install the latest updates as well as additional applications and documentation. The /etc/sysconfig/firstboot file tells the Setup Agent not to run on subsequent boots. To run only when the system boots, remove /etc/sysconfig/firstboot and execute chconfig --level=5 firstboot on.

The /etc/sysconfig/gpm file is used to pass arguments to the gpm daemon at boot time. The gpm daemon is the mouse server which allows mouse acceleration and middle-click pasting. For more information about what parameters are available for this file, see the gpm man page. By default, it sets the mouse device to /dev/mouse.

The /etc/sysconfig/harddisks tunes the hard drive(s). The administrator can also use /etc/sysconfig/harddisks to configure parameters for specific drives. Do not make changes to this file without careful consideration. By changing the default values, it is possible to corrupt all the data on the hard drive(s). The /etc/sysconfig/harddisks file may contain the following:

- USE_DMA=1, setting this value to 1 enables DMA. However, with some chipsets and hard drive combinations, DMA can cause corruption.
- Multiple_IO=16, where a setting of 16 allows for multiple sectors per I/O. When enabled, this feature reduces system overhead by 50%.
- EIDE_32BIT=3 enables (EIDE) 32-bit support.
- LOOKHEAD=1 enables lookahead.
- EXTRA_PARAMS=specifies extra parameters can be added.

### 4.1.11. /etc/sysconfig/hwconf

The /etc/sysconfig/hwconf file lists all hardware detected on the system, as well as drivers used, vendor ID, and device information. The program detects and configures new or changed hardware on the system. The /etc/sysconfig/hwconf file is not meant to be manually edited. If edited, devices could show up as added or removed.

### 4.1.12. /etc/sysconfig/i18n

The /etc/sysconfig/i18n file sets the default language, supported languages, and the default font. For example:

```
LANG=en_US.UTF-8
SUPPORTED=en_US.UTF-8
FONT="latin1"
```

### 4.1.13. /etc/sysconfig/identd

The /etc/sysconfig/identd file is used to pass arguments to the identd daemon at boot time. The identd daemon returns the username of processes over TCP/IP connections. Some services on the network, as FTP and IRC servers, will complain and slow responses if identd is not running. In general, identd is not a required service, so if security is concern, do not run it. For more information about parameters available for this file, see the identd man page. By default, the file contains no parameters.

### 4.1.14. /etc/sysconfig/init

The /etc/sysconfig/init file controls how the system will appear and function during the boot process. The following values may be used:

- BOOTP=<value>, where <value> is one of the following:
  - BOOTP=color means the standard color boot display, where success or failure of services starting up in different colors.
  - BOOTP=verbose means an old style display, which provides more information than a purely message of success or failure.
  - Anything else marks a new display, but without ANSI formatting.

- RES_COL=<value>, where <value> is the number of the column of the screen to start status labels. Defaults to 60.
- MOVE_TO_COL=<value>, where <value> moves the cursor to the value in the RES_COL line via the echo command.
- SETCOLOR_SUCCESS=<value>, where <value> sets the color to a color indicating success via the echo command. The default color is set to green.
- SETCOLOR_FAILURE=<value>, where <value> sets the color to a color indicating failure via the echo command. The default color is set to red.
- SETCOLOR_WARNING=<value>, where <value> sets the warning color via the echo command. The default color is set to yellow.
- SETCOLOR_NORMAL=<value>, where <value> resets the color to "normal" via the echo command.
- LOGLEVEL=<value>, where <value> sets the initial console level for the kernel. The default is 3; 8 everything (including debugging); 1 means nothing except kernel panics. The syslog daemon overrides this setting once set.
- PROMPT=<value>, where <value> is one of the following boolean values:
  - yes - Enables the key for interactive mode.
  - no - Disables the key for interactive mode.

### 4.1.15. /etc/sysconfig/ipchains

The /etc/sysconfig/ipchains file contains information used the ipchains initialization script when using the ipchains service. This file is modified by typing the command /sbin/service ipchains save when valid ipchains rules are in place. Do not manually edit this file. Instead, use the /sbin/ipchains command to configure the necessary packet filtering rules and then save the rules to this file using /sbin/service ipchains save.

Use of ipchains to set up firewall rules is not recommended as it is deprecated and may disappear from future releases of Red Hat Linux. If a firewall is needed, use iptables instead.

### 4.1.16. /etc/sysconfig/iptables

Like /etc/sysconfig/ipchains, /etc/sysconfig/iptables file stores information used by the kernel to set up packet filtering rules at boot time or when the service is started. Do not modify this file by hand unfamiliar with how to construct iptables rules. The easiest way to add rules is to use the Security Level Configuration Tool (redhat-config-securitylevel), or the GNOME Lokit command, the /usr/sbin/lokkit command to create a firewall. These applications edit this file at the end.

Rules can be created manually by using /sbin/iptables: then /sbin/service iptables save to add the rules to the /etc/sysconfig/iptables file. Once this file exists, any firewall rules saved it persists through a system reboot or service restart. For more information on iptables see Chapter 16.
