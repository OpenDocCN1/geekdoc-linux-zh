
# Chapter 4. The sysconfig Directory

## 4.1.31. /etc/sysconfig/samba

The /etc/sysconfig/samba file is used to pass arguments to the smbd and the nmbd daemons at boot time. The smbd daemon offers file sharing connectivity for Windows clients on the network. The nmbd daemon offers NetBIOS over IP naming services. For more information about what parameters are available for this file, see the smbd man page. By default, this file sets smbd and nmbd to run in daemon mode.

## 4.1.32. /etc/sysconfig/sendmail

The /etc/sysconfig/sendmail file allows messages to be sent to one or more recipients, routing the message over whatever networks are necessary. The file sets the default values for Sendmail application to run. Its default values are to run as a background daemon and to check its queue an hour in case something has backed up.

The following values may be used:

- DAEMON=<value>, where <value> is one of the following boolean values:
  - yes: Sendmail should be configured to listen to port 25 for incoming mail. yes implies the use of Sendmail -bd options.
  - no: Sendmail should not be configured to listen to port 25 for incoming mail.

- QUEUE=lh which is given to Sendmail if -qQUEUE option is not given and /etc/sysconfig/sendmail exists and QUEUE is empty or undefined.

## 4.1.33. /etc/sysconfig/soundcard

The /etc/sysconfig/soundcard file is generated by sndconfig and should not be modified. The sole use of this file is to determine what card entry in the menu to pop up by default next time sndconfig runs. Sound card configuration information is located in the /etc/modules.conf file.

It may contain the following:

- CARDTYPE=<value>, where <value> is set to, for example, SB16 for a Soundblaster sound card.

## 4.1.34. /etc/sysconfig/spamassassin

The /etc/sysconfig/spamassassin file is used to pass arguments to the spamd (a daemon-ized version of Spamassassin) at boot time. Spamassassin is an email filter application. For a list of available options, see the spamd man page. By default, it configures spamd to run in daemon mode, create user preferences, and auto-create whitelists. For more information about Spamassassin, see Section 1.4.2 Spam Filters.

## 4.1.35. /etc/sysconfig/squid

The /etc/sysconfig/squid file is used to pass arguments to the squid daemon at boot time. The squid daemon is a proxy caching server for Web applications. For more information on configuring a squid proxy server, use a Web browser to open /usr/share/doc/squid-<version>/ (replace <version> with the version number installed on the system). By default, this file sets squid to start in daemon mode and sets the amount of time before it shuts down.

## 4.1.36. /etc/sysconfig/tux

The /etc/sysconfig/tux file is the configuration file for the Red Hat Accelerator (formerly known as TUX), the kernel-based Web server. For more information on configuring the Red Hat Accelerator, use a Web browser to open /usr/share/doc/tux-<version>/index.html (replace <version> with the version number installed on the system). The parameters available for this file are listed in /usr/share/doc/tux-<version>/parameters.html.

## 4.1.37. /etc/sysconfig/ups

The /etc/sysconfig/ups file is used to specify information about any Uninterruptible Power Supplies (UPS) connected to the system. A UPS can be very valuable for Red Hat Linux system because the following values give it time to correctly shut down the system in case of power interruption:

- SERVER=<value>, where <value> is one of the following:
  - yes: A UPS device is connected to the system.
  - no: A UPS device is not connected to the system.

- MODEL=<value>, where <value> must be one of the following or set to NONE if UPS is connected to the system:
  - apcsmart: An APC SmartUPS or similar device.
  - tentonups: A Fenton UPS.
  - optiups: An OPTI-UPS device.
  - bestups: A Best Power™ UPS.
  - generics: A generic brand UPS.
  - ups-trust: A TrustUPS™.

- DEVICE=<value>, where <value> specifies where the UPS is connected, such as /dev/tty0.
- OPTIONS=<value>, where <value> is a special command that needs to be passed to the UPS.

## 4.1.38. /etc/sysconfig/vncservers

The /etc/sysconfig/vncservers file config the way the Virtual Network Computing (VNC) server starts up. VNC is a remote display system that allows users to view the desktop environment not only on the machine where it is running but across different networks on a variety of architectures. It may contain the following:

- VNCSERVERS=<value>, where <value> is set like "local", to indicate that VNC server should be set for user display. User must have set a VNC password using vncpasswd before attempting to connect to the VNC server.
- When using a VNC server, communication with it is unencrypted, and so it should not be used on an untrusted network. For specific instructions concerning the use of SSH to secure the VNC communication, please read the information found at http://www.redhat.com/howto/vnc. To find out more about SSH, see Chapter 18 SSH Protocol or Red Hat Customization Guide.

## 4.1.39. /etc/sysconfig/xinetd

The /etc/sysconfig/xinetd file is used to pass arguments to the xinetd daemon at boot. The xinetd daemon starts providing Internet services when a request is received to the port for that service. For more information about the parameters available for this file, see the xinetd man page. For more information see Section 15.3 xinetd.

## 4.2. Directories in the /etc/sysconfig/

The directories are normally found in /etc/sysconfig/.

- apm-scripts/ — This directory contains the Red APM suspend/resume script. Do not edit the files directly. If customization is necessary, create a file called /etc/sysconfig/apm-scripts/apmcontinue and it will be called at the end of the script. It is also possible to control the script by editing /etc/sysconfig/apmdd.
- cbq/ — This directory contains the configuration files needed to do Class Queuing for bandwidth management on network interfaces.
- networking/ — This directory is used by the Network Administration Tool (redhat-config-network), and its contents should not be edited manually. For more information about configuring network interfaces using the Network Administration Tool, see the chapter Network Configuration in the Red Hat Customization Guide.
- network-scripts/ — This directory contains the following network-related configuration files:
  - Network configuration files for each configured network interface, such as ifcfg-eth0 for the eth0 Ethernet interface.
  - Scripts used to bring up and down network interfaces, such as ifup and ifdown.
  - Scripts used to bring up and down ISDN interfaces, such as ifup-isdn and ifdown-isdn.
  - Various shared network functions which should not be edited directly.
For more information on the network-scripts directory, see Chapter 8 Network Interfaces. own- rhn/ — This directory contains information about the hardware configuration. For more information, visit http://www.redhat.com/support.
