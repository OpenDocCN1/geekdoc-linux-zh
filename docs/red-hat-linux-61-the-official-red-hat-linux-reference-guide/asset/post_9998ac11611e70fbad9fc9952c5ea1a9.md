## 2.4. GRUB Terminology

One of the most important things to understand before using GRUB is how the program refers to devices, such as drives and partitions. This information is particularly important when configuring GRUB to boot multiple operating systems.

### 2.4.1. Device Names

Suppose a system has more than one hard drive. The first hard drive of the system is called (hd0) GRUB. The first partition on that drive is called (hd0,0), and the fifth partition on the second drive is called (hd1,4). In general, the naming convention for files when using GRUB breaks down in this way:

```
<type-of-device><bios-device-number>,<partition-number>
```

The parentheses and comma are very important to the device naming conventions. The `<type-of-device>` refers to whether a hard (hd) or floppy disk (fd) is being specified.

The `<bios-device-number>` is the number of the device according to the system's BIOS, starting with 0. The secondary IDE hard drive is numbered 1. The ordering is roughly equivalent to that the Linux kernel arranges drives by letters, where the a in hda relates to 0, the b in hdb relates to 1, and so on.

![](img/31025704b51d5760c0228ff0f3db98bf_28_0.png)

> Note
> GRUB's numbering system for devices starts with 0, not 1. Failing to make this distinction is one of the most common mistakes made by new GRUB users.

The `<partition-number>` relates to one of specific partition on a disk device. While most partitions are specified by numbers, if a system uses BSD partitions, they are specified by letters, such as a or c.

GRUB uses the following naming conventions for devices:

- It does not matter if hard drives are IDE or SCSI. All hard drives start with hd.
- To specify an entire device with respect to partitions, leave off the comma and the partition number. This is important when telling GRUB to configure the MBR for a particular disk. For example, (hd0) specifies the MBR on the first device and (hd3) specifies the MBR on the fourth device.
- If a system has multiple drive devices, it is very important to know the drive boot order set in the BIOS. This is rather simple to do if a system has only IDE or SCSI drives, but if there is a mix of devices, it can become confusing.

### 2.4.2. File Names and Bootlists

When typing commands to GRUB involving a file, such as a menu list to use when allowing the booting of multiple operating systems, it is necessary to include the file immediately after specifying the device and partition.

A sample specification for an absolute file name is organized as follows:

```
<type-of-device><bios-device-number>, <partition-number>/path/to/file
```

Most of the time, a user will specify files to GRUB by the directory path on that partition, plus the file name.

It is also possible to specify files to GRUB that do not actually appear in the file system, such as a chain loader that appears in the first few blocks of a partition. To specify these, you must provide a blocklist, which tells GRUB, block by block, where the file is located in the partition, since a file can be comprised of several different sets of blocks, there is a specific way to write blocklists. Each file's section is described by an offset number of blocks and a number of blocks from that offset point, and the sections are put together in a comma-delimited order.

The following is a sample blocklist:

```
05,100+25,200+1
```

This blocklist tells GRUB to use a file that starts at the first block on the partition and uses blocks 0 through 49, 99 through 124, and 199.

Knowing how to write blocklists is useful when using GRUB to load operating systems that use chain loading, such as Microsoft Windows. It is possible to leave off the offset number of blocks if starting block 0. As an example, the chain loading file in the first partition of the first hard drive would have the following:

```
(hd0,0)+1
```

The following shows the chainloader command with a similar blocklist designation at the GRUB command line after setting the correct device and partition as root:

```
chainloader +1
```

### 2.4.3. GRUB’s Root File System

Some users confuse the term "root file system" with GRUB. It is important to remember that GRUB’s root file system is the root partition and has nothing to do with the Linux root file system.

The GRUB root file system is the root partition for a particular device. GRUB uses this information to mount the device and load files from it.

With Red Linux, once GRUB has loaded its partition (which equates to the /boot partition and contains the Linux kernel), the kernel command can be executed with the location of the kernel file as an option. Once the Linux kernel boots, it sets the root file system Linux users are familiar with. The original GRUB root file system and its mounts are forgotten; they only existed to boot the kernel.

Refer to the root and kernel commands in Section 2.6.

## 2.5. GRUB Interfaces

GRUB features three interfaces, which provide different levels of functionality. Each of these interfaces allows to boot the kernel. The interfaces are as follows:

### Menu Interface

If GRUB was automatically configured by the Red Hat installation program, this is the interface shown by default. A menu of operating systems are displayed by name. Use the arrow keys to select an option and press [Enter] to boot it. Alternatively, a timeout period is set, so GRUB will start the default option.

Press the [e] to enter the entry interface or [c] to load the command interface.

See Section 2.7 GRUB Menu Configuration for more information.

### Menu Entry Interface

To access the entry editor, press [e] from the boot loader menu. The GRUB commands are displayed here, and you may alter these before booting the operating system by adding a command (l inserts a new line after the current line and O inserts a new line before it), editing it, or deleting it.

After all changes, b executes the commands and boots the operating system. The Esc discards any changes and reloads the standard interface. The [c] key loads the command interface.

> Tip For changing runlevels with GRUB using the menu entry editor, refer to Section 2.10 Changing Runlevels at Boot Time.

### Command Line Interface

The command line is the most basic of the GRUB interfaces, but it is also the one that grants the most control. The command line makes it possible to type any relevant GRUB commands followed by [Enter] to execute them. This interface features some advanced shell-like features, including Tab key combination based on context, and Ctrl key when typing commands, as Ctrl-a to move to the beginning of a line, and Ctrl-e to move to the end of a line. Addition the arrow, [Home], [End], and [Delete] keys work as you do in the *bash* shell.

See Section 2.6 GRUB Commands for a list of common commands.

### 2.5.1. Order of the Interfaces

GRUB loads its secondary boot loader, it first searches for its configuration file. Once found, it builds a menu list and displays the menu interface.

If the configuration file cannot be found, or if the configuration is unreadable, GRUB loads the command line interface, allowing the user to type commands to complete the boot process.

If the configuration file is not valid, GRUB prints out the error and asks for input. Pressing any key reloads the menu option and correct the problem based on the error reported by GRUB. If the correction fails, GRUB reports an error and reloads the menu interface.
