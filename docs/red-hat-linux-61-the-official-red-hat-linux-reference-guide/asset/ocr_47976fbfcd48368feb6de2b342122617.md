Chapter 12. Berkeley Internet Name Domain (BIND)

# 12.3. Zone Files

Zone files contain information about a particular namespace and are stored in the named working directory, `/var/named/` by default. Each zone file is named according to the file option in the zone statement, usually in a way that relates to the domain and identifies the file as containing data, such as example.com.zone.

Each zone file may contain directives and resource records. Directives tell the nameserver to perform tasks or apply special settings to the zone. Resource records define the parameters of the zone and assignments to individual hosts. Optional, but resource records are required to provide nameservice to a zone.

All directives and resource records should go on their own individual lines.
Comments can be placed after semicolon characters (;) in zone files.

# 12.3.1. Zone File Directives

Directives begin with the dollar sign ($) followed by the name of the directive. They usually appear at the top of the zone file.
The following are commonly used directives:

+   * $INCLUDE Configures named to include another zone in this zone file at the place where the directive appears. This allows additional zone settings to be stored apart from the main zone file.
* $ORIGIN Appends the name to resource records, such as with the hostname and nothing more.

For example, a zone file may contain the following line:
$ORIGIN example.com
Any names in resource records that do not end in a trailing period (.) will have example. appended to them.

Note
The use of the $ORIGIN directive is unnecessary if the zone is specified in /etc/named.conf because the zone name is used as the value for the $ORIGIN directive by default.

+   * $TTL Sets the Time to Live (TTL) value for the zone. This is the length of time, in seconds, a resource record is valid. Each resource record can contain its own TTL value, which overrides this directive.

Increasing this value allows nameservers to cache the zone information for a longer period of time, reducing the number of queries for the zone and lengthening the amount of time to proliferate resource record changes.

# 12.3.2. Zone Resource Records

The primary component of a zone file is its resource records.
There are many types of zone resource records. The following are used most frequently:

+   * A Address record, which specifies an IP address to assign to a name, as in this example:
<host> IN A <IP-address>
If the <host> is omitted, then an A record points to a default IP address for the top of the namespace. This system is the target for all non-FQDN requests.
