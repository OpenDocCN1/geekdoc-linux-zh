# Chapter 15. TCP Wrappers xinetd

# 15.4.1. The /etc/xinetd.conf File

/etc/xinetd.conf contains general configuration settings which effect every service under xinetd's control. It is read once when the xinetd service is started, so in order for changes to take effect, the administrator must restart the xinetd service. Below is a /etc/xinetd.conf file:

```
defaults
{
    instances = 60
    log_type = SYLOG authpriv
    log_on_success = HOST PID
    log_on_failure = HOST
    cps = 25 30
}
```

These lines control various aspects of xinetd:

+   - Sets the maximum number of requests xinetd facility can handle at once.
- log_type - Configures xinetd to use the authpriv log facility, which writes log entries to the /var/log/secure file. Adding a directive creates a custom log file xinetd in the /var/log/xinetd/ directory.
- log_on_success - Configures xinetd to log if the connection is successful. By default, the remote host's IP address and the process ID of serving the request are recorded.
- log_on_failure - Configures xinetd to log if there is a connection failure or if the connection is not allowed.
- cps - Configures xinetd to allow no more than 25 connections per given service. If this limit is reached, the service is retired for 30 seconds.
- includedir /etc/xinetd.d/ - Includes options declared in the service-specific configuration files located in the /etc/xinetd.d/ directory. Refer to Section 15.4.2 The /etc/xinetd.d/Directory for more information about this.

Often, both the log_on_success and log_on_failure settings in /etc/xinetd.conf are further modified by the service-specific log files. For this reason, more information may appear in a given service's log than this file may indicate. See Section 15.4.3.1 Logging Options for more logging options.

# 15.4.2. The /etc/xinetd.d/ Directory

The files in the /etc/xinetd.d/ directory contains the configuration files for each service managed by xinetd and the names of files correspond to the service. As xinetd.conf, this file is read only when the xinetd service is started. In order for any changes to take effect, the administrator must restart the xinetd service.

The format of files in the /etc/xinetd.d/ directory use the same conventions as /etc/xinetd.conf. The primary configuration for each service is stored in separate file to make customization easier and less likely to affect other services.
