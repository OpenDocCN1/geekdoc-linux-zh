### 10.2.1.2. Server-pool Size Regulation

In Apache HTTP Server 2.0, the responsibility for accepting requests and dispatching child-processes to handle them has shifted to a group of modules Multi-Processing Modules (MPMs). Unlike other modules, only one module from the MPM group can be loaded by the Apache HTTP Server. There are three MPM modules that ship with version 2.0: prefork, worker, and perchild.

The Apache HTTP Server 1.3 behavior has been moved into the prefork MPM. Currently only the prefork MPM is available on Red Hat Linux, although other MPMs may be made available at a later date.

The prefork MPM accepts the same directives as Apache HTTP Server 1.3, so the following directives may be migrated directly:

- StartServers
- MinSpareServers
- MaxSpareServers
- MaxClients
- MaxRequestsPerChild

For more on this topic, refer to the following documentation on the Apache Software Foundation's website:

- http://httpd.apache.org/docs-2.0/mpm.html (DSO)

### 10.2.1.3. Dynamic Shared Object (DSO) Support

There are many changes required, and it is highly recommended that anyone trying to modify an Apache HTTP Server 1.3 configuration to suit version 2.0 (as opposed to migrating the changes into the version 2.0 configuration) copy this section from the stock Red Hat Linux HTTP Server 2.0 configuration file.

Those who do not want to copy the section from the stock Apache HTTP Server 2.0 configuration should note the following:

- The AddModule and ClearItemList directives no longer exist. These directives used to ensure that modules could be enabled in the correct order. The Apache HTTP Server 2.0 API allows modules to specify their ordering, eliminating the need for these two directives.
- The order of the LoadModule lines is no longer relevant.
- Many modules have been added, removed, renamed, split up, or incorporated with each other.
- LoadModule lines for modules packaged in their own RPMs (mod_php, php, mod_ssl, and the like) are no longer necessary as they can be found in the relevant file in /etc/http/conf.d/
- The various HAVE_XXX definitions are no longer defined.

### 10.2.1.4. Global Environment Changes

The following directives have been removed from Apache HTTP Server 2.0's configuration:

- ServerType — The Apache HTTP Server can only be run as ServerType standalone making this directive irrelevant.
- AccessConfig and ResourceConfig — These directives have been removed since they mirror the functionality of the Include directive. If the AccessConfig and ResourceConfig directives are set then replace them with Include directives.

To ensure that the files are read in order by the older directives the Include directive should be placed at the end of httpd.conf, with the one corresponding to ResourceConfig preceding the corresponding to AccessConfig. If using default values, then explicitly include them as conf/srm.conf and conf/access.conf files.

## 10.2.2. Main Server Configuration

The main server section of the configuration file sets up the main server, which responds to any requests that are not handled by a <VirtualHost> definition. Values here provide defaults for any <VirtualHost> containers defined.

The directives used in this have changed little between Apache HTTP Server 1.3 and 2.0. If the main server configuration is heavily customized it may be easier to modify the configuration file to suit Apache HTTP Server 2.0. With users with only lightly customized main server sections should change their changes into the default 2.0 configuration.

### 10.2.2.1. UserDir Mapping

The UserDir directive is used to enable URLs such as http://example.com/~bob to map a subdirectory within the home directory of the user bob, such as /home/bob/public_html. A side-effect of this feature allows a potential attacker to determine whether a username is present on the system. For this reason, the default configuration for Apache HTTP Server 2.0 disables this directive.

To enable UserDir mapping, change the directive in httpd.conf from:

```
UserDir disable
```

to the following:

```
UserDir public_html
```

For more on this topic, refer to the documentation on the Apache Software Foundation’s website, http://httpd.apache.org/docs-2.0/mod_userdir.html#userdir.

### 10.2.2.2. Logging

The following logging directives have been removed:

- AgentLog
- ReferrerLog
- ReferrerIgnore

However, agent and refer logs are still available using the CustomLog and LogFormat directives. For on this topic, refer to the following documentation on the Apache Software Foundation’s website:

- http://httpd.apache.org/docs-2.0/mod/mod_log_config.html#customlog
- http://httpd.apache.org/docs-2.0/mod/mod_log_config.html#logformat

### 10.2.2.3. Directory Indexing

The deprecated FancyIndexing directive has been removed. Same functionality is available through the FancyIndexing option within the IndexOptions directive.

The new VersionSort option to the IndexOptions directive causes files containing version numbers to be sorted in a more natural way. For example, httpd-2.0.6.tar appears after httpd-2.0.36.tar in a directory page.

The defaults for the ReadName and HeaderName directives have changed from HEADER to README.html and HEADER.html.

For on this topic, refer to the following documentation on the Apache Software Foundation’s website:

- http://httpd.apache.org/docs-2.0/mod/mod_autoindex.html#indexoptions
- http://httpd.apache.org/docs-2.0/mod/mod_autoindex.html#readmename
- http://httpd.apache.org/docs-2.0/mod/mod_autoindex.html#headername

### 10.2.2.4. Content Negotiation

The CacheNegotiDocs directive now takes the argument on or off. Existing instances of CacheNegotiDocs should be replaced with cachenotiogated on. For on this topic, refer to the following documentation on the Apache Software Foundation’s website:

- http://httpd.apache.org/docs-2.0/mod_negotiation.html#cachenotiated

### 10.2.2.5. Error Documents

To use a hard-coded message with the ErrorDocument directive, the message should be enclosed in a pair of quotation marks rather than just preceded by a quotation mark as required in Apache HTTP 1.3. To migrate an ErrorDocument setting to Apache HTTP Server 2.0, use the following:

```
ErrorDocument 404 "The document was not found"
```

### 10.2.4. Modules and Apache HTTP Server

In Apache HTTP 2.0, the system module has changed to allow modules to be chained together or combined in new and interesting ways. Common Gateway Interface (CGI) scripts, for, generate server-parsed HTML documents that can be processed by mod_include. This opens up a tremendous range of possibilities with regards to how modules can be combined to achieve a specific goal.

The way by which each request is served by exactly one module followed by zero or more filters. Under Apache HTTP 1.3, for example, a PHP script would be handled in the entirety by the PHP module. Under Apache HTTP 2.0, the request is initially handled by the core module which serves static files and is filtered by the PHP module.

Exactly how to use this, and all the other features of Apache HTTP 2.0 for that matter, in the scope of this document; however, the change ramifications if the PATH_INFO directive is used for a document handled by a module that is now implemented as a filter, as each contains trailing path information after the true file name. which initially handles the request, is not by default understand PATH_INFO and will return 404 Not Found errors for requests contain such information. As an alternative, use the AcceptPathInfo directive to coerce the module into accepting requests with PATH_INFO.

The following is an example of this technique:

```
AcceptPathInfo on
```

For on this topic, refer to the following documentation on the Apache Software Foundation’s website:

- httpd.apache.org/docs-2.0/mod/core.html#acceptpathinfo
