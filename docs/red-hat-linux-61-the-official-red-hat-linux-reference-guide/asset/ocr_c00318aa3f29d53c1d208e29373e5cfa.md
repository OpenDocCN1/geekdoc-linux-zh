+   - key "<key-name>" — Defines a key name. Keys are used to authenticate various accounts, such as secure updates or the use of the rndmc command. Two options are used with key:

+   - algorithm <algorithm-name> — The type of algorithm used, such as dsa or hmac-md5.

+   - secret "<key-value>" — The encrypted key.

See 12.4.2 Configuring /etc/rndc.conf for instruction on how to write a key statement. Logging — occurs for the use of multiple types of logs, called channels. By using the channel option within the logging statement, with its own name (file), size limit (size), version (version), and level of importance (severity), can be customized. Once a customized channel has been defined, a category option is used to configure the channel and begin when named is restarted.

By default, named logs standard for the syslog daemon, which places them in /var/log/messages. This occurs because several channels are built into BIND with various severity levels, such as one that handles informational logging (default_syslog). A default category, default uses the built-in channels to do normal logging without any specification.

Customizing the logging process is a very detailed process and is beyond the scope of this chapter. For information on custom BIND logs, see the BIND 9 Administrator Reference Manual in Section 12.7.1 Installation Details.

+   - server — Defines options particular how named acts to route remote namesvers, especially regarding notifications and zone transfers.

The transfer-format option controls how one resource record is sent with each message (one-answer) or multiple resource records are sent with each message (many-answers). While many-answers is more efficient, only fewer BIND namesvers understand it.

+   - trusted-keys — Contains assorted public keys used for secure DNS (DNSSEC). See Section 12.5.3 for more information connecting BIND security.

+   - view "<view-name>" — Creates special views depending upon the hosting host to the nameserver. This allows hosts to receive one answer regarding a particular zone while other hosts receive totally different information. Alternatively, certain zones may only be available to particular trusted hosts while non-trusted hosts can only make queries for others.

Multiple views may be used, so long as their names are unique. The match-clients option specifies the IP addresses that apply to a particular view. Any options statement may also be used within a view, overriding the global options configured for named. Most views contain multiple zone statements that apply to the match-clients list. The order in which view statements are listed is important, as the first view that matches a particular client's IP is used.

See 12.5.2 Multiple Views for more information about the view statement.

+   - * / - When text is enclosed in this, the block of text is ignored by named.
