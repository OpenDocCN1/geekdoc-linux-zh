> > Warning The format of the /etc/exports file is very precise, particularly in regards to use of the space character. Remember to always save exported file systems from hosts and one another with a space character. However, there should be no space characters in the file except on comment lines.
> For example, the two lines do not mean the same thing:

```
/home bob.example.com (rw)
home bob.example.com (rw)
```

The first line allows only users from bob.example.com read-write access to the /home directory. However, this requires that the root user type second line allows users from bob.example.com to mount the directory read-only (the default), but the rest of the world can mount it read-write.

# 9.3. NFS Client Configuration Files

Any NFS share available by a server can be mounted using various methods. The share can be manually mounted, using the mount command. However, this requires the root user type the mount command every time the system restarts. Two methods of configuring NFS shares to be mounted automatically by modifying the /etc/fstab or using the autofofs service.

# 9.3.1. /etc/fstab

Placing a properly formatted line in the /etc/fstab file has the same effect as mounting the exported file system. The /etc/fstab file is read by the /etc/rc.init.d/netfs script at system startup and any NFS shares listed will be mounted.

A sample /etc/fstab for an NFS export looks like the following:

```
<server>:/path/to/dir <local/mount/point> nfs <options> 0 0
```

The <server-host> corresponds to hostname, IP address, or fully qualified domain name of the exporting file system.

The <path/to/directory> specifies where the local file system to mount the exported directory. This mount point must exist before /etc/fstab is read or the mount will fail.

The nfs option specifies the type of file system being mounted.
