# 17.2. Kerberos Terminology

Kerberos has its own terminology to define various aspects of the service. Before learning how kerberos works, it is important to learn the following terms.

ciphertext

Encrypted data.

client

An entity on the network (a user, a host, or an application) that can get a ticket from Kerberos.

crypt hash

One way has to authenticate users. While more secure than plain text, it is fairly easy to decrypt for an experienced challenger.

GSS-API

The Generic Security Service Application Program Interface [RFC-2743] is a set of functions that provide security services which clients can authenticate to servers and which servers can authenticate to clients without specific knowledge of the underlying mechanism. If a network service (such as IMAP) uses GSS-API, it can authenticate using Kerberos.

key

Data used when encrypting or decrypting other data. Encrypted data cannot be decrypted without the proper key or extremely good guessing.

Key Distribution Center (KDC)

A service that issues Kerberos tickets, usually on the same host as the Ticket Granting Server

key table or keytab

A file that includes an unencrypted list of principals and their keys. Service retrieves the keys they need from keytab instead of using kinit. The default keytab file is /etc/krb5.keytab. The KDC administration server, /usr/kerberos/bin/kadmin, is the only service that uses any other file (it uses /var/kerberos/krb5kdc/kadm5.keytab).

kinit

The kinit command allows a principal who has already logged in to obtain and cache the initial Ticket Granting Ticket (TGT). For more on using the kinit command, see its man page.
