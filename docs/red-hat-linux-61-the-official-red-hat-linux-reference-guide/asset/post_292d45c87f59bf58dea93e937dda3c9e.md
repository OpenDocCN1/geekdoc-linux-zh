
## 10.52. ReadmeName

ReadmeName names the file, if it exists in the directory, is appended to the end of generated directory listings. The Web server first tries to include the file as an HTML document and then try to include it as plain text. By default, ReadmeName is set to README.html.

## 10.53. HeaderName

HeaderName names the file, if it exists in the directory, is prepended to the start of server directory listings. Like ReadmeName, the server tries to include it as an HTML document if possible or in plain text not.

## 10.54. IndexIgnore

IndexIgnore lists file extensions, partial file names, wildcard expressions or full filenames. The Web server will not include any files which match any of those parameters in server generated directory listings.

## 10.55. AddEncoding

AddEncoding names filename extensions which should specify a particular encoding type. AddEncoding can also be used to instruct browsers to uncompress certain files as they are downloaded.

## 10.56. AddLanguage

AddLanguage associates file name extensions with specific languages. This directive is useful for Apache HTTP Servers which serve content in multiple languages based the client Web browser's language settings.

## 10.57. LanguagePriority

Language-Priority sets precedence for different languages in the client Web browser's language preference set.

## 10.58. AddType

Use the AddType directive to map MIME type and file extension pairs. For example, using PHP, use the AddType directive to make the Web server recognize with PHP extensions (.php4, .php3, .php) as PHP MIME types. The following directives allow the Apache HTTP Server to recognize AddType text/html.

```
AddType text/html .html
AddHandler server-parsed .shtml
```

## 10.59. AddHandler

AddHandler maps file extensions to specific handlers. For example, the cgi-script handler can be matched with the extension .cgi to automatically treat a file ending with .cgi as a CGI script. The following is a sample AddHandler directive for the .cgi extension.

```
ErrorHandler cgi-script .cgi
```

This directive enables CGIs outside of the cgi-bin to function in any directory on the server which has the ExecCGI option within the directories container. Refer to Section 10.5.24 Directory for more information about setting the ExecCGI option for a directory.

In addition to cgi scripts, the AddHandler directive is used to process server-parsed HTML and image-map files.

## 10.5.60. Action

Action specifies a MIME type and CGI script pair, whenever a file of media type is requested, a particular CGI script is executed.

## 10.5.61. ErrorDocument

The ErrorDocument associates an HTTP response code with a message or a URL to be sent back to the client. By default, the Web server outputs a simple and usually cryptic message when an error occurs. The ErrorDocument directs the Web server to output a customized message or redirects the client to a local or external URL.

> **Important**

In order to be valid, the message must be enclosed in a pair of double quotes "".

## 10.5.62. BrowserMatch

The BrowserMatch allows the server to define environment variables and take appropriate actions based on the User-Agent HTTP header field — which identifies the client's browser type. By default, the Web server uses BrowserMatch to deny connections to specific browsers with known problems and also to disable keepalives and HTTP headers for browsers that are known to have problems with those actions.

## 10.5.63. Location

The <Location> and </Location> tags create a container in which access control based on URL can be specified.

For instance, to allow people connecting from the server's domain to see status reports, use the following directives:

```
<Location /server-status>
SetHandler server-status
Order deny,allow Deny from all
Allow from <.example.com>
</Location>
```

Replace <.example.com> with the second-level domain name for the Web server.

To provide server configuration reports (including installed modules and configuration directives) to requests from inside the domain, use the following directives:

```
<Location /server-info>
SetHandler server-info
Order deny,allow
Deny from all
Allow from <.example.com>
</Location>
```

Again, replace <example.com> with the second-level domain name for the Web server.

## 10.5.64. ProxyRequests

To configure the Apache HTTP Server to function as a proxy server, remove the hash marks from the beginning of the <IfModule mod_proxy.c> line to the mod_proxy module and set the ProxyRequests directive to On.

## 10.5.65. ProxyVia

<Proxy > </Proxy> tags create a container that encloses a group of configuration directives to apply only to the proxy server. Many directives are applicable to a directory and may be used within <Proxy> tags.

## 10.5.66. ProxyVia

The ProxyVia command controls whether or not an HTTP header is sent along with requests or replies which go through the proxy server. The Via: header sends the hostname if ProxyVia is set to On, shows the hostname and the Apache HTTP Server version for Full, passes any Via: lines unchanged for Off, and lines are removed for Block.

## 10.5.67. Cache Directives

A number of cache directives are supplied by the default Apache HTTP Server configuration. In most cases, uncommenting these lines by the hash mark [#] from the beginning of the line is sufficient. However, here is some of the most important cache-related directives.

- CacheRoot Specifies the name of the directory containing cached files. The default CacheRoot is the /var/httpd/proxy/ directory.
- CacheSize Specifies how much space the cache can use in kilobytes. The default CacheSize is 5 KB.
- CacheInterval Specifies the number of hours which must pass before files in the cache are deleted. The default CacheInterval is 4 hours.
- CacheMaxExpires Specifies how long documents are retained (without a reload from the originating Web server). The default is 24 hours.
- CacheLastModifiedFactor Specifies the creation of an expiry (expiration) date for a document which did not come from its originating server with its own expiry date. The default CacheLastModifiedFactor is 0.1.
- CacheDefaultExpires Specifies the expiry time for a document received using a protocol that does not support expiry. The default is 1 hour.
- NoCache Specifies a list of hosts whose content is not cached.

## 10.5.68. NameVirtualHost

The NameVirtualHost directive associates an IP address and port number. if necessary, for any name-based hosts. Name-based hosting allows one Apache HTTP Server to serve different domains without using multiple IP addresses.

Name-based virtual hosts only work with non-secure HTTP connections. If using virtual hosts, use IP address-based virtual hosts instead.

To enable name-based virtual hosting, uncomment the NameVirtualHost directive and add the IP address. Add more VirtualHost containers for each virtual host.

## 10.5.69. VirtualHost

<VirtualHost> and </VirtualHost> tags create a container outlining the characteristics of a virtual host. The <VirtualHost container accepts accepts configuration directives.

A set of commented VirtualHost container is provided in httpd.conf, which illustrates the minimum set of configuration directives necessary for each virtual host. Refer to Section 10.8 Virtual Hosts for more information about virtual hosts.

## 10.5.70. SSL Configuration Directives

The SSL directives in /etc/httpd/conf.d/ssl.conf file can be configured to secure Web communications using SSL and TLS.

## 10.5.71. SetEnvIf

SetEnvIf sets environment variables on the headers of incoming secure connections. In the supplied /etc/httpd/conf.d/ssl.conf file, it is used to disable HTTP keepalive and allow SSL to close the connection without a close alert from the client browser. This setting is necessary for certain browsers that do not shut down the SSL connection.
