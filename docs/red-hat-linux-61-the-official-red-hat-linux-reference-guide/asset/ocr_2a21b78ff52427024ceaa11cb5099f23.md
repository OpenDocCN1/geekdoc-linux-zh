# Chapter 9. Network File System (NFS)

# 9.2.1./etc/exports

The /etc/exports files control which files are exported to remote hosts and specifies options. Blank lines are ignored, can be made by starting a line with the hash mark (#), and long lines can be wrapped with a backslash (\ Each exported file system should be on its own individual line. Lists of authorized hosts placed after an exported file system must be separated by space characters. Options for each of the hosts must be placed in parentheses after the host identifier, without any spaces separating the first and the last parenthesis.

In its simplest form, /etc/exports only needs to know the directory to be exported and the hosts permitted to use it:

```
/some/directory bob.example.com
another/exported/directory 192.168.0.3
```

After re-exporting /etc/exports with the /bin/service nfs reload command, the bob.example.com host will be able to mount /some/directory and 192.168.0.3 can mount another/exported/directory. Because no options are specified in this example, several default NFS preferences take:

+   - Read — Hosts mounting this file system will not be able to change it. To allow hosts to make changes to the file system, the rw (read-write) option must be specified.
- async — Allows the server to write to disk when it sees fit. While this is important if the host is accessing as read-only, or if host makes changes to a read-write file system and the server crashes, data could be lost. By specifying the sync option, all writes are committed to the disk requested by the client. This may improve performance.
- wdelay — Causes the NFS to delay writing to the disk if it suspects another other write is imminent. This can improve performance by reducing the number of times the disk must be accessed by separate write commands, reducing over head. The no_wdelay option turns off this feature, but is only available when using the sync option.
- root_squash — Strips roots connected remotely from having root privileges by assigning them nobody user. This effectively "squashes" the power of the root user to the local user, preventing remote users from acting as they were the root on the local system. The no_root_squash option turns off root squashing. To squash every remote user, using root, the all_squash option specifies the user and group IDs respectively. In this case, a special user can be created for remote NFS users to share and specify (if anuid=<uid-value> anongid=<gid-value>, where <uid-value> is the user number and <gid-value> is the group ID in value).

In order to override these, you must specify an option that allows that. For example, if you do not specify rw, that export will only be read-only. For every exported file system must be included. This allows in the ability to disable sub-tree checking, allow access from insecure ports, and insure file locks (necessary for early NFS client implementations). The exports man page for details on these used options.

When specifying hosts, use the following methods:

+   - single host — Where particular host is specified with fully qualified domain name, hostname, or IP address.
- wildcards — Where a * or ? character is used to take into account a grouping of fully qualified domain names that match a pattern string of characters. Wildcards are not to be used with IP addresses; however, they may accidentally work if reverse DNS lookups fail.
