More importantly, you can apply rules differently depending on where the traffic comes from. You can set up rules for three areas or profiles:

+   - **Domain**: For those computers authenticated on your domain.

+   - **Public**: For computers from outside your network. You would treat outside traffic more carefully than traffic coming from another machine in your domain.

+   - **Private**: Private refers to traffic from your own computer, thus the term private.

Administrators should always follow these rules with all packet filtering:

+   - If you do not explicitly need a port, block it. For example, if you are running a web server on that machine, block all inbound port 80 traffic. With home machines you can usually block all ports. With individual workstations on a network, you need to keep some ports open in order to allow for various network utility to access the machine.

+   - Unless you have a compelling reason not, always block ICMP traffic because many utilities such as ping, tracer, and many port scanners use ICMP packets. If you block ICMP traffic, you will prevent many port scanners scanning your system for vulnerabilities.

+   - Occasional, I would suggest continuing to write out acronyms such as ICMP just to make sure this is reinforced.

The Windows Firewall also has a logging feature, which is disabled by default. Turn this feature on (when you configure the firewall you will see a place to turn on logging). Check this log periodically. You can find more details on the Windows 10 Firewall at https://docs.microsoft.com/en-us/windows/access-protection/windows-firewall/windows-firewall-with-advanced-security.

# FYI: Log Files

If you are using the Windows Firewall on a workstation in a network that already has a perimeter firewall and the Windows Firewall on all workstations, you might not want to turn on the logging for reviewing your perimeter firewall and all the workstations' firewall logs is impractical. The sheer number of reviewing all those logs makes it likely that they will never be reviewed.

Typically, you will review logs on your perimeter firewall and all server firewalls, but not on workstation firewalls. Of course, if your security needs dictate that you log all system firewalls and you have the resources to routinely review those logs, it is certainly a good idea to do so.
