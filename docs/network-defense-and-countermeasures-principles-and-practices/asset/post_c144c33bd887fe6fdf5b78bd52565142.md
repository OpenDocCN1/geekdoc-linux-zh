
# Understanding Denial of Service Attacks

The first type of attack to examine is the denial of service (DoS). Recall from Chapter 1 that a denial of service attack is any attack that aims to deprive legitimate users of the use of the target system. This class of attack does not actually attempt to infiltrate a system or to obtain sensitive information; it simply aims to prevent legitimate users from accessing a given system. This type of attack is one of the most common categories of attack. Many experts feel it is so common that most forms of service attacks are fairly easy to execute. The ease with which these can be executed means even attackers with minimal technical skills can successfully perform a denial of service.

The concept underlying the denial of service attack is based on the fact that every device has operational limits. This fact applies to all devices, not just computers. For example, bridges are designed to hold up to a certain limit, aircraft planes on how far they can travel without refueling, and automobiles can only accelerate to a certain point. All of these various devices share a common trait: they have limitations to their capacity to perform work. Computers are not different from these, or any other machine; they, too, have limits. Any computer system, web server, or network can only handle a finite load.

How a workload (and its limits) differs from one machine to another. A workload for a computer system might be defined in a number of different ways, including by the number of simultaneous users, the size of files, the speed of data transmission, and the amount of data stored. Any of these limits will stop the system from responding. For example, if you flood a web server with more requests than it can process, it will be overloaded and no longer be able to respond to further requests. This reality underpins the DoS attack. Simply overload the system with requests, and it will no longer be able to respond to legitimate users attempting to access the web server.

# DoS in Action

The concept of a denial of services attack is simple; however, most principles are easier to grasp if one can see a concrete example. In this case you need a safe way to simulate a DoS attack within a classroom or laboratory setting. One simple way to illustrate a DoS attack, especially in a classroom setting, involves the use of the ping command with certain parameters. (Recall that in chapter 1 `ping /h` or `ping /` will show you all the options for the `ping` command). The first step is to set up a web server running on a computer that will be used as the target for this attack. You can use any operating system and any web server (such as Microsoft Internet Information Services or Apache HTTP Server). Apache is a free download from www.apache.org. Microsoft Windows 10 comes with Internet Information Services, so you should have no trouble purposefully use a low-capacity machine. An older machine, perhaps an older laptop, would be ideal. You would want to pick a machine that is easy to overload. In essence you are looking for the exact opposite of what you look for when setting up a web server.

Setting up a web server is actually quite simple. Because Apache is available as a free download for both Linux and Windows (www.apache.org), let's examine it. Follow these steps to install and configure Apache on your system.

# Installing for Windows

- 1. Download Apache for Windows from www.apache.org.
- 2. Look in C:\Program Files\Apache Group\Apache2\conf for the httpd.conf file and open it.
- 3. Set the ServerName = localhost.
- 4. Save the file.
- 5. From the command prompt type httpd start.

You should now be able to open a browser and see the default Apache website.

# Installing for Linux

- 1. Download Apache for Linux (or in many Linux distributions you can simply add the Apache web server package) from www.apache.org.
- 2. Look in /etc/httpd/conf for the httpd.conf file. When you find it, right-click it and open it with a text editor.
- 3. Set the ServerName = localhost.
- 4. Save the file.
- 5. From a shell, /etc/init.d/httpd start. The server should start and you will get an OK message.
- 6. Open your browser and go to http://localhost/

You should see the Apache default website.

When you are ready to make your server live (reachable from other PCs), in the /etc/httpd/httpd.conf file change the following settings:

> FYI: Changing the Configuration File
> Any time you change the configuration file you must stop the Apache server and restart it. To stop Apache, use /etc/init.d/httpd stop.
> - Change servername to your registered URL or to your IP:port such as 10.10.10.117:80.
> - Change listen to reflect the IP and what you want (there is an example in the config file).
> - Check the document directory to make certain that is where you want your web pages to be served up from. The default should be /var/www/html.
> - From a shell /etc/init.d/httpd start.

The next step is to verify that the web server is actually running and that you can reach its default web page. One person in the class can open his or her browser and type the target server's IP address in the address bar. He should then be viewing the default website for that server. You now can do a primitive DoS attack on it.

Make the actual attack using the ping command. If you don't recall how to use the ping command, you should note that typing ping /h at the command prompt displays all the options for the ping command. The options to use in this exercise are -w and -t. The -w determines how many milliseconds the ping utility will wait for a response from the target. In this case, set that option to -0, so it does not wait at all. The -l option allows users to change the size of the packet you can send. Keep in mind that a TCP packet can be of a finite size, so you are going to set these packets to be as large as you can send.

At the command prompt in Windows 10 (the shell in Unix/Linux), ping <address of target machine goes here>=l 65000 -w 0 -t. The machine should be similar to that is shown in Figure 2-1. Note that in the figure I am ping the looping address for your machine. You will want to substitute the address of the machine on which you are running the web server.
