
Windows servers have similar logs. However, with Windows systems you have an additional possible concern. The possibility exists that the attacker cleared the logs before leaving the system. Tools are available that will allow one to wipe out a log, such as auditpol.exe. Using auditpol\disable turns off logging. When the criminal exits he can use auditpol\enable to turn it back on. Tools such as WinZapper also allow one to selectively remove items from event logs in Windows. Simply turning off logging before an attack and turning it back afterward is also possible.

## Linux Logs

Obviously, Linux also has logs you can check. Depending on your Linux distribution and what services you have running on (such as MySQL), some of these logs might not be present on a particular machine.

- var/log/faillog: This log file contains failed user logins. This can be very important when tracking attempts to crack the system.
- var/log/kern.log: This log file is used for messages from the operating system’s kernel. This is not likely to be pertinent to computer crime investigations.
- var/log/prlog.*: This is the printer log and can give you a record of any items that have been printed from this machine. That can be useful in corporate espionage cases.
- var/log/mail.*: This is the mail server log and can be very useful in any computer crime investigation. E-mails can be a component in any computer crime, and even in some non-computer crimes as fraud.
- var/log/mysql.*: This log records activities related to the MySQL database server and will usually be of less interest to a computer crime investigation.
- var/log/apache2/*: If this machine is running the Apache web server, then this log will show activity. This can be very useful in tracking attempts to hack into the web server.
- var/log/httptd/*: If this machine is running the Lightpd web server, then this log will show activity. This can be very useful in tracking attempts to hack into the web server.
- var/log/apport.log: This records application crashes. Sometimes these can reveal attempts to compromise the system or the presence of a virus or spyware.
- var/log/user.log: These contain user activity logs and can be very important to a criminal investigation.

### The Windows Registry

The Windows Registry is an incredible repository of valuable information. It is the heart of the system. You can find a number of interesting pieces here.

### USB Information

There are other keys related to USBSTOR that provide information. For example, MountedDevices allows you to match the serial number to a given drive letter.

### Wi-Fi

When an individual connects to a wireless network, the service set identifier (SSID) is logged. This information can be found in the Registry.

### Uninstalled Software

This is a very important key for forensic examination. It lets you see all the software that has been uninstalled from this machine.

## Gathering Evidence from a Cell Phone

In our modern times, cell phones are ubiquitous. As common as they are, it should be no surprise that cell phones play a role in some computer cases. As discussed in previous chapters, there are some crimes that are primarily executed via cell phones. Sending pornographic images via cell phone is one crime. Securing data from a suspect's cell phone in criminal investigation is often a good idea. Some of the kinds of data that might be retrieved and examined during a cell phone forensic investigation include

- Photos
- Videos
- Text messages or SMS messages
- Call times, dialed and received calls, and all calls
- Contact names and phone numbers
