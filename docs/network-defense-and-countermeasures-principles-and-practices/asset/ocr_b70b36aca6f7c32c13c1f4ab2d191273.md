# CHAP

CHAP is actually a three-part handshaking (a term used to denote authentication processes) procedure. After the link is established, the server sends a challenge message to the client originating the link. The originator responds by sending back a value calculated using a one-way hash function. The server checks the response against its calculation of the expected hash value. If the values match, the authentication is acknowledged; otherwise, the connection is usually terminated. This means that the authorization of a client connection has three stages. Figure 7-3 illustrates them.

What makes CHAP particularly interesting is that it periodically repeats the process. This means that even after a client connection is authenticated, CHAP repeatedly seeks to re-authenticate that client, providing a robust level of security.

> FYI: What Is a Hash Function?

The term hash function comes up a bit in discussions of encryption and authentication. Having a solid understanding of what it is therefore important. As Discussed in Chapter 6, "Encryption Fundamentals," a hash function (h) is a transformation. This transformation takes a variable-sized input (n) and returns a fixed-length string. The fixed-length string that is returned is the hash value h(n). Expressed as a mathematical equation, this is h(n). More details about hash functions are available at the following websites:

# L2TP

Layer 2 Tunneling Protocol is an extension or enhancement of the Point-to-Point Tunneling Protocol that is used to operate virtual private networks over the Internet. It is a new and improved version of PPTP. As its name suggests, it operates at the data link layer of the OSI model (like PPTP). Both PPTP and L2TP are considered by many experts to be less secure than IPSec. However, seeing IPSec used together with L2TP to create a secure VPN connection is not uncommon.
