
# The Basics of a Network

Subnetting also allows you to use certain, limited subsets. Another approach is CIDR, or classless interdomain routing. Rather than define a subnet mask, you have the IP address followed by a slash and a number. That can be any number between 0 and 32, which results in IP addresses like these:

- 192.168.1.10/24 (basically a Class C IP address)
- 192.168.1.10/31 (like a Class C IP address with a subnet mask)

When you use this, rather than having classes with subsets, you have variable-length subnet masking (VLSM) that provides classless IP addresses. This is the most common way to define IP addresses today.

You should not be concerned that new IP addresses are likely to run out. The IPv6 standard is already available, and methods are in place to extend the use of IPv4 addresses. The IP addresses come in two groups: public and private. The public IP addresses are for computers connected to the Internet. No two IP addresses can be the same. However, a private IP address, such as one on a private company network, has to be unique in that network. It does not matter if computers in the world have the same IP address, because this computer is never connected to other worldwide computers. Network administrators often use private IP addresses that begin with a 10, such as 10.0.102.230. The other private IP addresses are 172.16.0.0-172.31.255.255 and 192.168.0.0-192.168.255.255.

Also note that an ISP will pull a pool of IP addresses and assign them to when you log on. So, an ISP might have its own pool of IP addresses and have 10,000 customers. Because all 10,000 customers will not be at the same time, the ISP simply assigns an IP address to a customer when she or he logs on, and the ISP unassigns the IP address when the customer logs off.

IPv6 utilizes a 128-bit address (instead of 32) and utilizes a hex numbering method in order to avoid long addresses such as 132.64.34.64.156.143.57.1.3.7.44.122.111.201.5. The hex address appears in the form of FFFE:800::example. This gives you 2¹⁸ possible addresses (many trillions of addresses), so no chance of running out of IP addresses in the foreseeable future.

There is no subnet in IPv6. Instead, it uses CIDR. The network portion is indicated by a slash followed by the number of bits in the address that are assigned to the network portion, as such:

```
/48
```
```
/64
```

There is a loopback address for IPv6, and it is written as ::1. Other differences between IPv4 and IPv6 are described here:

- Link/machine-local: The IPv6 version of IPv4's APIPA or Automatic Private IP Addressing. So if the machine is configured for dynamically assigned addresses and cannot communicate with a DHCP server, it assigns itself a generic IP address. DHCP, or Dynamic Host Configuration Protocol, is used to dynamically assign IP addresses within a network. IPv6 link/machine-local IP addresses all start with fe80::. So if your computer has this address, that means it could not get to a DHCP server and therefore made up its own generic IP address.

- Site/network-local: The IPv6 version of IPv4 private address. In other words, these are real IP addresses, but they only work on this local network. They are not routable on the Internet. All site/network-local IP address begins with FE and have C to F for the third hexadecimal digit: FEC, FED, FEE, or FEF.

DHCPv6 uses the Managed Address Configuration Flag (M flag):
- When set to 1, the device should use DHCPv6 to obtain a stateful IPv6 address.

Other stateful configuration flag (O flag):
- When set to 1, the device should use DHCPv6 to obtain another TCP/IP configuration settings. In other words, it should use the DHCP server to set things like the IP address of the gateway and DNS servers.

# Uniform Resource Locators

For most people, the main purpose of getting the Internet is web pages (but there are other things as e-mail and file downloading). If you had to remember IP addresses and type those in, surfing the Net would be cumbersome at best. Frankly, you don't have to. You type in domain names that make sense to humans and get translated into IP addresses. For example, you might type in www.chuckeast.com to go. Your computer, or ISP, must translate the name you typed (a Uniform Resource Locator, or URL) into an IP address. The DNS (Domain Name Service) protocol, which is introduced along with other protocols in Table 1-2, handles this translation process. So you are typing in names that make sense to humans, but your computer is using a corresponding IP address. If that address is found, your browser sends a packet to such requests (using the HTTP protocol) TCP port 80. If that target computer has software that listens and responds (like web server such as Apache or Microsoft Information Services), then the computer will respond to your browser's request and communication will be established. This is how web pages are viewed. If you have ever encountered an Error 404: Not Found, you're seeing that your browser back a packet (from the web server) with error code-404, denoting that the web page you requested could not be found. The web server can send back a series of error messages to your browser, indicating different situations.

E-mail works just as visiting websites. Your e-mail client will seek the address of your e-mail server. Your e-mail client will use POP3 to retrieve your e-mail, or SMTP to send your outgoing e-mail. Your ISP (probably or your company) will then try to resolve the address you are sending to. If you send something to chuckeast@yahoo.com, your e-mail server will translate that e-mail address into an IP address for the e-mail server at yahoo.com, and then your server will send your e-mail there. Note that newer e-mail protocols are out there; however, POP3 is still the most commonly used.

IMAP is now widely used as well. Internet Message Access Protocol operates on port 143. The main advantage of IMAP over POP3 is it allows the client to download only the headers to the machine, and then the user can choose which messages to fully download. This is particularly useful for smart phones.

# MAC Addresses

MAC addresses are an interesting topic. (You might notice that MAC is a sublayer of the data link layer of the OSI model.) A MAC address is a unique address for a NIC. NIC in the world is a unique address that is represented by a six-byte hexadecimal number. The Address Resolution Protocol (ARP) is used to convert IP addresses to MAC addresses. So, when you use in a web address, the DNS protocol is used to translate that into an IP address. The ARP protocol translates that IP address into a specific MAC address of an individual NIC.

# Protocols

Different types of communications exist for different purposes. The different types of network communications are called protocols. A protocol is, essentially, an agreed-upon method of communications. In fact, this is exactly how the word protocol is used in standard, non-computer usage. Each protocol has a specific purpose and normally operates on a certain port (or ports in a bit). Table 1-2 lists some of the most important protocols.

Table 1-2: Protocols and Ports

| Protocol | Purpose | Port |
| :--- | :--- | :--- |
| FTP (File Transfer Protocol) | For transferring files | 20, 21 |
| SSH (Secure Shell) | Secure login on system | 22 |
| Telnet | Used to remotely log on system | 23 |
| SMTP (Simple Mail Transfer Protocol) | Sends e-mail | 25 |
| DNS (Domain Name Service) | Translates URLs to addresses | 53 |
| tFTP (Trivial FTP) | Quicker but less reliable FTP | 69 |
| HTTP (Hypertext Transfer Protocol) | Displays web pages | 80 |
| POP3 (Post Office Protocol v3) | Retrieves e-mail | 110 |
| NNTP (Network News Transfer Protocol) | Used for newsgroups | 119 |
| NetBIOS | Naming services on local network | 137, 138, 139 |
| IRC (Internet Relay Chat) | Chat rooms | 194 |
| HTTPS (Hypertext Transfer Protocol Security) | HTTP encrypted with SSL/TLS | 443 |
| SMB (Server Message Block) | Used by Active Directory | 445 |
| ICMP (Internet Control Message Protocol) | Error and control messages | No specific port |
