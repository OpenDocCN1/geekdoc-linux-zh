
# FYI: Don't Know—Don't Touch

You should be cautious when shutting down services so that you do not inadvertently shut down a service that you need. Always check with your operating system documentation. The rule of thumb is that if you are not sure, do not touch it.

# Shutting Down a Service in Windows

Shutting down a service in Windows is relatively easy. In our example we will shut down the FTP service on a machine that does not require FTP.

Go to Start, select Settings, and choose Control Panel. Double-click Administrative Tools, and then double-click Services. You should see the Services dialog box, which looks like the one shown in Figure 8-8.

![](img/b9022ea8d49ef539d37d0ec09f73f71c_238_0.png)

Figure 8-8 Services

The Services dialog shows all services installed on your machine, whether they are running or not. That the dialog box displays information about whether a service is running, whether it starts up automatically, and so forth. In Windows 7 and beyond, more information can be seen by selecting an individual service. When you double-click on an individual service, you see a dialog box similar to Figure 8-8, which gives you detailed information about the service and enables you to change the service's settings. In Figure 8-9, we are examining the FTP service on a machine that does not require it.

![](img/b9022ea8d49ef539d37d0ec09f73f71c_239_0.png)

Figure 8-9: FTP services

> FYI: Dependencies
> Are going to turn off the FTP service; but before you turn off any service, click on the Dependencies tab to see whether other services depend on the one you are about to shut off. If other services depend on that service, you will then be causing them to malfunction by shutting down.

In this particular case there are no other dependencies, so you can go to the General tab and do two things: Change the Startup type option to Disabled, and then click the Stop button. When you're done, the screen will show the status as disabled. The service is now shut down.

Shutting down unnecessary services is an essential and very basic part of hardening an operating system. Every running service is a possible avenue for a hacker or a virus to get to your machine, so the rule for services is: If you don't need it, shut it down. Chapter 12 discusses utilities that scan for vulnerabilities. Many of these utilities will point out running services and open ports.

Starting and stopping services from the command prompt is also possible. Many administrators prefer command prompt because it is often faster than going through several layers of the Windows graphical user interface. The syntax is quite simple:

```
net start servicename
```

or

```
net stop servicename
net start servicename
```

For example:

```
net stop messenger
net start messenger
```

This is inaccurate, but has somehow become somewhat of an urban legend among Windows users. The following documentation from Microsoft's own website confirms that you can indeed start and stop a service from the command prompt:
https://answers.microsoft.com/en-us/windows/forum/windows_10_other_settings/learning-the-net-start-command/02dfe674-d1e9-4a6d-9d75-f7896a54626f

# Encrypting File System

Beginning with Windows 2000, the Windows operating system has offered the Encrypting File System (EFS), which is based on public key encryption and takes advantage of the CryptoAPI architecture in Windows 2000. This still exists in Windows 7, 8, and 10; however, with the later versions of Windows, EFS is only available in the upper-end editions of Windows such as Windows Professional. With this system, each file is encrypted using a randomly generated file encryption key, which is independent of a user's public/private key pair; this method makes the encryption resistant to many forms of cryptoanalysis-based attacks. For our purposes the exact details of how EFS encryption works are not as important as the practical aspects of using it.

# User Interaction

The default configuration of EFS enables users to start encrypting files with no administrator effort. EFS automatically generates a public key pair and file encryption certificate for file encryption the first time a user uses it.

File encryption and decryption is supported per file or for an entire folder. Folder encryption is transparently. Each file has a unique file encryption key, making it safe to rename. If you move from an encrypted folder to an unencrypted folder on the same volume, the file remains encrypted. However, if you copy an unencrypted file into an encrypted folder, the state will change. The file becomes encrypted. Command-line tools and administrative interfaces are provided for advanced users and recovery agents.

> Users might encrypt a file and then be unavailable to decrypt it. They might become unavailable due to leaving the company, illness, or other reasons. Fortunately, EFS does give administrators a method by which they can recover it. The best thing about EFS is that it is virtually transparent to the user. EFS is built into Windows, costs nothing extra, and is so easy to use. If you want more details, the following websites would be helpful to you:
- ServerWatch review of EFS: www.serverwatch.com/tutorials/article/210683
- A utility for retrieving EFS keys: www.lostpassword.com/efs
