# Policy and Personnel Documentation

All policies must be on file. Any revisions should be filed along with the originals. Assuming you have employees an agreement stating they are aware of the policies (and you absolutely should), then copies of that should be on file.

Along with policy documentation, you should keep a list of personnel along with what items they have access to. This includes physical access as well as any machines (servers, workstations, or routers) that have login rights (to). You should also note what level of access they have (standard user, power user, administrator, and so on).

# Probe Documents

Any time you conduct any security audit, a report of that audit should be filed. Even audits by outside consultants should be kept on file. The audit report should include any flaws found, and have a follow-up report of what steps were taken to correct them.

Should you have a security incident (such as a virus infection or intruder), there should be at least a brief memo summarizing what occurred. That document should state what the security incident was, when it occurred, what machines were affected, and how it was corrected.

# Network Protection Documents

The most obvious item to document is exactly what network protections you have in place. This documentation should detail the following:

+   - What firewall are you using and how is it configured?
- What IDS are you using and how is it configured?
- What antivirus and/or anti-spyware are you using?
- Have you configured any honeypots?
- What individual machine security measures (such as workstation firewalls) do you have taken?

One of caution: These documents should be kept under lock and key, with only limited access. If an intruder were to get access to these documents, they would have a detailed analysis of your network's weaknesses.
