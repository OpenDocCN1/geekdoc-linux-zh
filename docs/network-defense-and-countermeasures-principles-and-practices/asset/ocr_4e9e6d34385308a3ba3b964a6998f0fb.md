# Learning About Modern Encryption Methods

Once the round key has been generated for the current round, the next step is to address the half of the original block that is going to be input into the round function. Recall that the two halves are each 32 bits. The round key is 48 bits. That means the round key does not match the size of the half block it is going to be applied to. You cannot XOR a 48-bit round key with a 32 bit half block, unless you simply ignore 16 bits of the round key. If you did, you would basically be making the round key effectively shorter and less secure, so this is not a good option.

The 32-bit half needs to be expanded to 48 bits before it is XORed with the round key. This is accomplished by replicating some bits so that the 32-bit half becomes 48 bits.
This expansion is actually quite simple. The 32 bits that is to be expanded is broken into 4-bit sections. The bits on each end are duplicated. If you divide 32 by 4 the answer is 8. So there are eight of these 4-bit groupings. If you duplicate the bits of each grouping, that will add 16 bits to the original 32, providing a total of 48 bits.

It is also important to keep in mind that it was the bits on each end that were duplicated; this will be a key item in the round function. Perhaps this example will help you understand what is occurring at this point. Let us assume 1110011010101111111000101010001 as shown here:

```
1110011010101111111000101010001
```

Now divide into eight sections each of 4 bits, as shown here:

```
1111 0011 0101 1111 1111 0001 0101 1001
```

Now each of these has its ends duplicated, as you see here:

```
1111 becomes 111111
0011 becomes 000111
0101 becomes 010111
1111 becomes 111111
1111 becomes 111111
0001 becomes 000011
0101 becomes 010111
1001 becomes 110011
```

The resultant 48-bit string is now XORed with the 48-bit round key. That is the extent of the round key used in each round. It is now dispensed with, and on the next round another 48-bit round key will be derived from the two 28-bit halves of the 56-bit cipher key.

Now we have the 48-bit output of the XOR operation. That now split into eight sections of 6 bits each. For the rest of this explanation we will focus on just one of those 6-bit sections, but keep in mind that the same process is done to all eight sections.
