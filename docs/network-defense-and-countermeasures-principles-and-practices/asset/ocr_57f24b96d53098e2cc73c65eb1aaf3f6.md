# In Practice

# Packet Filtering Rules

Unfortunately in real world networks there are so many applications different types of packets setting up proper rules for packet filtering can be more difficult than you might think. A simple network with a few servers running a small number of devices (perhaps a web server, an FTP server, and an e-mail server), configuring packet filtering rules can, indeed, be rather simpler. In other situations it can become quite complicated.

Consider the wide-area network connecting multiple sites in geographically diverse regions. When you set up a packet filtering firewall in this scenario, you need to be aware of any application or service that use network communications of any type, on any machine, in any of the sites your WAN connects to. Failure to take these complexities into account can result in your firewall blocking legitimate network service.

# Stateful Packet Inspection

The stateful inspection (SPI) firewall is an improvement over basic packet filtering. This type of firewall will examine each packet, denying or permitting access based not only on the examination of the current packet, but also on data derived from previous packets in the conversation. This means that the firewall is aware of the context in which a specific packet was sent. This makes these firewalls less susceptible to ping floods and SYN floods, as well as being less susceptible to spoofing. SPI firewalls are less susceptible to these attacks for the following reasons:

+   - They can tell whether the packet is part of an abnormally large of packets from a particular IP address, indicating a possible DoS attack in progress.

+   - They can tell whether the packet has a source IP address that appears to come from inside the firewall, thus indicating SPI is in progress.

+   - They can also look at the actual contents of the packet, allowing for some advanced filtering capabilities.

SPI firewalls are an improved version of the packet filtering firewall. Most quality firewalls today use the stateful packet inspection method; when possible, this is the recommended type of firewall for most systems. In fact most routers have the option of using stateful inspection. The name stateful packet inspection derives from the fact that in addition to examining the packet, the firewall is examining the packet's state in relation to the entire IP connection. This means the firewall can refer to the preceding packets as well as those packets' contents, source, and destination. As you might suspect, SPI firewalls are becoming quite common.
