
# Atbash Cipher

Hebrew scribes copying the book of Jeremiah used the Atbash cipher. Using it is simple; you just reverse the alphabet. This is, by modern standards, a primitive and easy-to-break cipher. However, it will help you get a feel for how cryptography works.

The Atbash cipher is a Hebrew code that substitutes the first letter of the alphabet for the last, the second letter for the second to last, etc. It simply reverses the alphabet; for example, A becomes Z, B becomes Y, C becomes X,

This, like the Caesar cipher and ROT 13 ciphers, is also a single-substitution cipher.

# Multi-Alphabet Substitution

Eventually, a slight improvement over the Caesar cipher was developed, called multi-alphabet substitution (also called polyalphabetic substitution). In this scheme, you select multiple numbers by which to shift letters (that is, multiple-substitution alphabets). For example, if you select three alphabets (12, 22, 13), then

- A CAT
- becomes
- C ADV

Notice that the fourth letter starts with another 12, and you can see that the first A was transformed to C and the second A was transformed to D. This makes deciphering the underlying text much difficult. Although this is harder to decrypt than a Caesar cipher, it is not overly difficult to decode. It can be done with simple pen and paper and a bit of effort. If it can be cracked quickly with a computer, no one would use such a method today to send any secure message, for this type of encryption is considered very weak.

One of the most widely known multi-alphabet ciphers is the Vigenere. This topic is discussed in detail later in this chapter. This cipher was invented in 1553 by Giovanni Bellaso. It is a method of encrypting alphabetic text using a series of different mono-alphabetic ciphers selected based on the letters of a key. This algorithm was widely misattributed to Blaise de Vigenere, and so it is known as the "Vigenere cipher," even though Vigenere did not invent it.

Multi-alphabet ciphers are more secure than single-substitution ciphers. However, they are still not acceptable for modern cryptographic usage. Computer-based cryptanalysis systems can crack historical cryptographic methods (both single substitution and multi-alphabet) easily. The single-substitution alphabet alphabets are discussed just to show the history of cryptography, and to help you get an understanding of how cryptography works.

# Rail Fence

All the preceding ciphers we examined are substitution ciphers. Another approach to classic cryptography is the transposition cipher. The rail fence cipher may be the most widely known transposition cipher. You simply take the message you wish to encrypt and alter each letter on a different row. So "attack at dawn" is written as:

```
A t c a d w
takt a n
```

Next, you write down the text reading from left to right as one normally would, producing atcadwtaktan.

In order to decrypt the message, the recipient must write it out in rows:

```
A t c a d w
takt a n
```

Then the recipient reconstructs the original message. Most texts use two rows as examples; however, it can be done with any number of rows you wish.

# Vigenère

As we previously discussed, polyalphabetic cipher uses multiple substitutions to disrupt letter and word frequency. Let us consider a simple example. Remember a Caesar cipher has a shift of +2, -1, +3. When you get to the fifth letter, you simply start over again. So, consider Attack being encrypted:

| Letter | Shift | Result |
| :--- | :--- | :--- |
| A | +2 | C |
| T | -1 | S |
| T | +1 | U |
| A | +3 | D |
| C | +2 | E |
| K | -1 | J |

So, the ciphertext is CSUDEJ. Perhaps the most widely known polyalphabetic cipher is the Vigenère cipher. This cipher was actually invented in 1553 by Giovanni Bellaso, though it is named after Blaise de Vigenere. It is a method of encrypting alphabetic text using a series of different mono-alphabetic ciphers selected based on the letters of a keyword. Bellaso added the concept of using any keyword making the choice of alphabets difficult to calculate.

# Enigma

It is really impossible to have a discussion about cryptography and not about Enigma. It is not a single machine but rather a family of machines. The first version was invented by German engineer Scherbius near the end of World War I. It was used by several militaries, not just Germans. Some military texts using Enigma were broken by Polish cryptanalysts Marian Rejewski, Jerzy Rócki, and Henryk Zygalski who used that information to develop tools for breaking Enigma, including the cryptic bomb. The core of Enigma machine was the rotors that were arranged in a circle with 26 letters on them. Essentially, each rotor represented a different substitution. One can think of Enigma as a sort of mechanical polyalphabetic cipher. The operator would be given a message in plaintext and then type that message into Enigma. The recipient would type in the ciphertext, getting out the plaintext, provided Enigma machines had the same rotor settings. There were actually several variations of the Enigma machine. The Naval Enigma machine was eventually cracked by British cryptographers working at the famous Bletchley Park. Alan Turing and a team of analysts were able to eventually break the Naval Enigma machine, shortening World War II by as much as two years. This story is the basis for the movie The Imitation Game.

# Binary Operations

Part of modern symmetric cryptography involves using binary operations. Various operations on binary numbers (numbers made of zeros and ones) are well known to programmers and programming students. But for those readers not familiar with them, a brief explanation follows. When working with binary numbers, three operations are not found in normal math: AND, OR, and XOR. Each is illustrated next.

# AND

To perform the AND operation, you take two binary numbers and compare them one at a time. If both numbers have a one in both places, the resultant number is one. If not, the resultant number is a zero, as you see here:

```
1 0 1
1 0 0
-----
1 0 0
```

# OR

The OR operation checks to see whether there is a one in either or both numbers in a given place. If so, the resultant number is one. If not, the resultant number is zero, as you see here:

```
1 0 1
1 0 1
------
1 0 1
```

# XOR

The XOR operation impacts your study of encryption the most. It checks to see whether there is a one in a number in a given place, but not in both numbers at that place. If it is in one number but the other, the resultant number is one. If not, the resultant number is zero, as you see here:

```
1 1 0
1 0 1
------
0 1 1
```

XORing has an interesting property in that it is reversible. If you XOR the resultant number with the second number, you get back the first number. And, if you XOR the resultant number with the first number, you get the second number.

```
0 1 1
1 0 0
------
1 1 0
```

Binary encryption using the XOR operation opens the door for some rather simple encryption. Take any message and convert it to binary numbers and then XOR that with some key. Converting a message to a binary number is a simple two-step process. First, convert a message to ASCII code, and convert those codes to binary numbers. You can use a random string of binary numbers of any length as the key. Simply XOR your message with the key to get the encrypted text, and then XOR it with the key again to retrieve the original message.

This method is easy to use and great for computer science students; however, it does not work well for truly secure communications because the underlying letter and word frequency remains. This exposes valuable clues that an amateur cryptographer can decrypt the message. It does provide a valuable introduction to the concept of single-key encryption, which is discussed in more detail in the next section. Although simply XORing the text is not the method typically employed, single-key encryption methods are widely used today. For example, you could include a multi-alphabet substitution that was then XORed with some random bit stream—variations of which exist in a few actual encryption methods used.
