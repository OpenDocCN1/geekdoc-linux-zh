`~/.rhosts` files consisted of the cluster alias and not the individual cluster member names. This works fine as long as the `out_alias` attribute is applied to the login service in the `/etc/clua_services` file.

From the client system:

```
```text
# rlogin babylon5
Password:
Last login: Tue Sep  3 00:46:19 EDT 2002 from babylon5.dec.com
```
```

```
```text
# hostname
molari.dec.com
```
```

In order to achieve the convenient trust that was enabled prior to removing the `out_alias` attribute from the `/etc/clua_services` file, we will have to enter a line for each individual cluster member in the `~/.rhosts` file.

```
```text
[ molari]
# cat /.rhosts
babylon5.dec.com
sheridan-ics0
molari-ics0
climach4
climach3
```
```

```
```text
[ molari]
# cat >> /.rhosts
molari
sheridan
```
```

```
```text
[ molari]
# cat /.rhosts
babylon5.dec.com
sheridan-ics0
molari-ics0
climach4
climach3
molari
sheridan
```
```

Now the login works without a password required.

From the client system:

```
```text
# rlogin babylon5
Last login: Tue Sep  3 00:48:42 EDT 2002 from sheridan.dec.com
```
