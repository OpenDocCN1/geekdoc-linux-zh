

## 注意：

SPL有时被称为中断优先级（IPL）。

实际上，CPU总是在8个SPL（0-7）之一中运行，较高的SPL比较低的SPL更重要。

系统还将处于两种可能的处理模式之一：用户模式或内核模式。机器中的大多数标准处理将在SPL 0和用户模式下进行。如果更重要的事件需要优先于当前处理，则会发出中断，并以内核模式执行中断服务例程（ISR）。

可能存在中断和其他内核模式处理，可能需要访问系统支持结构，如设备驱动程序和内核例程。

ISR必须以确保不会被相同级别或更低级别的后续中断中断的方式运行。这是通过设置CPU寄存器（处理器状态（PS）寄存器）中的位来指示处理器当前运行在哪个SPL上来实现的。PS寄存器中还有另一位指示内核模式或用户模式。请注意，SPL是每个CPU独有的现象，因为每个CPU都有一个PS寄存器。

为了讨论的目的，中断由硬件设备生成，以指示已发生事件（例如I/O完成）。因此，可以为各种设备分配一个SPL，以运行其ISR。在较高SPL中断的设备优先于在较低SPL中断的设备的ISR。当所有ISR处理完毕后，系统会将SPL降低到中断发生前所处的级别。

如果你想知道这与集群环境有何关系，请记住，集群环境包括多个系统，具有许多I/O设备，每个系统有一个或多个CPU，每个CPU都有自己的PS寄存器。因此，集群中计算机的每个CPU在任何时刻都可能与集群其他成员的CPU处于不同的SPL。重点是，必须为进程和系统本身提供其他同步机制，以在集群中保持一定的合理性和同步性。随着系统复杂性接近完全集群状态，接下来的几节将介绍许多处理同步和通信的系统机制。

## 2.3 多CPU系统

向计算机添加第二个CPU会增加同步系统活动的复杂性。每个CPU都有自己的一组寄存器，包括包含SPL和模式信息的PS寄存器。因此，任何试图通过软件将SPL设置为非零值以与ISR同步的尝试都是错误的。它只提供与恰好在该特定CPU上运行的ISR的同步。在另一个CPU上运行的ISR和其他内核模式代码不会感知到此CPU上的SPL设置。

### 2.3.1 异步多处理（ASMP）

同步问题的一种解决方案是强制所有在内核模式下运行的代码（包括ISR）在特定CPU上运行。这是一种“隧道化”形式，强制活动在特定CPU（通常是主CPU）上运行。在多处理器系统（机箱内多个CPU）中，强制所有内核模式活动在单个CPU上运行是一种称为异步多处理（ASMP）的解决方案。ASMP相对容易实现，并且即使涉及多个CPU，也允许内核模式活动的SPL同步继续工作。然而，它会导致高调度开销，因为每个需要进入内核模式的进程（例如，对于系统调用）必须重新调度到主CPU上运行。

ASMP起作用了，但效果不够好，而且扩展性差。随着添加更多的CPU，实际可用的CPU周期越来越少。必须有另一种在多CPU之间同步的方法。请记住，我们仍然在谈论单台计算机。我们还没有达到添加更多计算机或集群计算机的地步，但我们会达到。
