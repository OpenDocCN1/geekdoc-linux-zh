# Blocking Processes

What do you do when somebody asks you for something that you can't right away? If you're a human being and you're bothered by a human being, the only thing you can say is: 'Not right now, I'm busy. Go away!' But if you're a kernel module and you're bothered by a process, you have another possibility. You can put the process to sleep until you can service it. After all, processes are being put to sleep by the kernel and woken up all the time (that's how multiple processes appear to run on the same time on a single CPU).

This kernel module is an example of this. The file (called `/proc/sleep`) can only be opened by a single process. If the file is already open, the kernel module calls module_interruptible_sleep on. This function changes the status of the task in the kernel data structure which holds information about a process and the system to TASK_INTERRUPTIBLE, which means the task will not run until it is woken up and adds it to queue of tasks waiting to access the file. Then, the scheduler calls context switch to a different process, which has use for the CPU.

When a process reads a file, it closes it, and module_close is called. That wakes up all of the processes in the queue (there's no mechanism to wake up one of them). Then it returns and the process which just closed the file can continue to run. Then, the scheduler decides that the process has had enough and gains control of the CPU to another process. Eventually, one of the processes which was in the queue will be control of the CPU by the scheduler. It starts at the point right after the call to module_interruptible_sleep on. It can then proceed to set a global variable
