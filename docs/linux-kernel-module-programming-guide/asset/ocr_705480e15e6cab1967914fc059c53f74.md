cutting B out of the loop. Then, when B is removed, it will restore the system call to what it thinks is the original, Aopen, which is no longer in memory. At first glance, it appears we could solve this particular problem by checking if the system call is equal to our open function and if not changing it at all (so that B won't change the system call when it's removed), but that will cause an even worse problem. When A is removed, it sees that the system call was changed to Bopen so that it is no longer pointing to Aopen, so it won't restore it to sysopen before it is removed from memory. Unfortunately, Bopen will still try to call Aopen which is no longer, so that even without removing B the system would crash.

I can think of two ways to prevent this problem. The first is to restore the call to the original value, sysopen is not part of the kernel system table in /proc/ksym, so we can't access it. The other solution is to use the reference count to prevent root from rmmod the module once it is loaded. This is good for production modules, bad for an educational sample — which is why I don't do it here.
