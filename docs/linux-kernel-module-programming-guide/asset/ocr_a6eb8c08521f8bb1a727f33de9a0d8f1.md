# ## 2.1 Kernel Versions Source Files

The system calls, which are the major interface the kernel shows to the processes, generally stay the same across versions. A new system call may be added, but usually the old ones will behave exactly like they used to be. This is necessary for backward compatibility a new kernel version is not supposed to break regular processes. In most cases, the device files will also remain the same. On the other hand, the internal interfaces within the kernel and do change between versions.
The Linux kernel versions are divided between stable versions (n.<number>) and the development versions (n.<number>.m). The development versions include all the new ideas, including those which will be considered a mistake, or reimplemented, in the next version. As a result, you can't trust the interface to remain the same in those versions (which is why I don't bother to support them in this book, it's too much work and it would become too quickly). In the stable versions, on the other hand, we can expect the interface to remain the same regardless of the bug fix version (the number).
