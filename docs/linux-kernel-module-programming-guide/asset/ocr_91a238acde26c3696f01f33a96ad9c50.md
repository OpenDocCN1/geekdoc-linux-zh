By the way, the reason why the Makefile recommends against using insmod from X
is because the kernel has a message to print with printk, it sends it to the console.
When you don't use X, it goes to the virtual terminal you're using (the one you chose
al Alt-F3) and you see it. When you do use X, on the other hand, there are two
possibilities. Either you have a console open with xterm -C, in which case the output
will be sent there, or you don't, in which case the output will go to virtual terminal 7 — the
covered by X.

If your kernel becomes unstable you're unlikely to get the debug messages without X.
Outside of X, printk goes directly to the console. In X, on the other hand,
print's go to the X server (xterm -C). When process receives CPU time,
it is supposed to send it to the X server process. Then, when X server receives the CPU,
it is supposed to display it — but an unstable kernel usually means the system is about
to crash or reboot, so you don't want to delete the error messages, which might explain to
you what went wrong, longer than you have to.

# 1.2 Multiple Kernel Modules

Sometimes it makes sense to divide a kernel module between several files. In
this case, you need to do the following:

+   1. In all the source files, add the line #define _NO_VERSION_ This is im-
because module.h normally includes the definition of kernel_version,
global variable with the kernel version the module is compiled for. If you need
version.h, you need to include yourself, because module.h won't do it for
you with _NO_VERSION_

+   2. Compile all the source files as usual.

+   3. Combine all the object
files into a single one. Under x86, do it with ld -m elf_i386 -r -o <name
