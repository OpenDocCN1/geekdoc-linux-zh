
This code binds to IRQ 1, which is the IRQ of the keyboard controlled under Intel architectures. Then, when it receives a keyboard interrupt, it reads the keyboard's status (that's the purpose of the *inb (0x64)* and the scan code, which is the value returned by the keyboard). Then, as soon as the kernel thinks it's feasible, it runs got_char which gives the code of the key used (the first seven bits of the scan code) and whether it has been pressed (if the 8th bit is zero) or released (if it's one).

## Symmetrical Multi–Processing

One of the easiest (read, cheapest) ways to improve hardware performance is to put more than one different CPU on the board. This can be done either making the different CPUs take on different jobs (asymmetrical multi-processing) or by making them all run in parallel, doing the same job (symmetrical multi-processing, a.k.a. SMP). Doing asymmetrical multi-processing is much easier than symmetrical multi-processing, but it is also less efficient. Doing symmetrical multi-processing is much harder because it requires the kernel to be re-entrant.

In asymmetrical multi-processing, one CPU is designated as the master and the others as slaves. The master handles all the interrupts, and the slaves perform the tasks. In symmetrical multi-processing, all CPUs can handle interrupts and perform tasks. This is much more efficient, but it is much more complex to implement.

In this chapter, we will discuss how to implement symmetrical multi-processing in Linux. We will start with a simple asymmetrical multi-processing model and then gradually add more features.
