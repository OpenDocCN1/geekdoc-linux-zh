# Using /proc For Input

So far we have two ways to generate output from kernel modules: we can register a device driver and mknod a device file, or we can create a /proc file. This allows the kernel module to tell us anything it likes. The only problem is that there is no way for us to talk back. The first way we'll send input to kernel modules will be by writing back to the /proc file.

Because the proc filesystem was written mainly to allow the kernel to report its situations, the proc_dir_entry struct doesn't include a pointer to an input function, which it includes a pointer to an output function. Instead, to write into a /proc file, we need to use the standard filesystem mechanism.

In Linux there is a standard mechanism for file registration. Since every file system has its own functions to handle file and file operations¹, there is a special structure to hold pointers to all functions, struct inode_operations, which includes a pointer to struct file_operations. In /proc, whenever we register a new file, we're allowed to specify which struct inode_operations will be used for access to it. This is the mechanism we use, a struct inode_operations which includes a pointer to struct file_operations which includes pointers to our module_input and module_output functions.

It's important to note that the standards of read and write are reversed in the kernel. Read functions are used for output, whereas write functions are used for input.

> ¹The difference between the two is that file operations deal with the file itself, and inode operations deal with ways of referencing the file, such as creating links to it.
