When the first caveman programmer chiseled the first program on the walls of the first computer, it was a program began to paint the string 'Hello, world' in Antelope pictures. Roman programming textbooks began with the 'Salut, Mundi' program. I don't know what happens to people who break with this tradition, and I think it's safer not to find out.

A kernel module has to have at least two functions: init_module which is called when the module is inserted into the kernel, and cleanup_module which is called just before it is removed. Typically, init_module either registers a handler for something with the kernel, or replaces one of the kernel function with its own code (usually code to do something). The cleanup_module function is supposed to undo whatever init_module did, so the module can be unloaded safely.

    return 0;

{

## 1.1 Makefiles for Kernel Modules

A kernel module is not an independant executable, but an object file which will be linked into the kernel in runtime. As a result, they should be compiled with the -c flag. Also, all kernel modules have to be compiled with certain symbols defined.

- - _KERNEL_ — This tells the header files that this code will be run in kernel mode, not as part of a user process.

- - MODULE — This tells the header files to give the appropriate definitions for a kernel module.

- - LINUX — Technically speaking, this is not necessary. However, if you ever want to write a serious kernel module which will compile on more than one operating system, this will allow you to do conditional compilation on the parts which are OS dependant.

There are other symbols which have to be included, or not, depending on the flags the kernel was compiled with. If you're not sure how the kernel was compiled, look it up in /usr/include/linux/config.h

- - _SMP_ — Symmetrical MultiProcessing. This has to be defined if the kernel was compiled to support symmetrical multiprocessing (even if it's running on one CPU). If you use Symmetrical MultiProcessing, there are other things you need to do (see chapter 12).

- - CONFIG_MODVERSIONS — If CONFIG_MODVERSIONS was enabled, you need to have it defined when compiling the kernel module and to include /usr/include/linux/modversions.h. This can also be done by the code itself.

## Makefile for a basic kernel module

```makefile
CC=gcc
MODCFLAGS :=-Wall -DMODULE -D__KERNEL__ -DLUX

hello.o: hello.c /usr/include/linux/version.h
	$(CC) $(MODCFLAGS) -c hello.c
	echo insmod hello.o to turn it on
	echo rmmod hello to turn it off
	echo
	echo X and kernel programming do not mix.
```

echo Do the insmod and rmmod from outside X.

So, now the only thing left is to root (you didn't compile this as, did you?
Living on the edge...), and then insmod hello and rmmod hello to your heart's
content. While you do it, notify your new kernel module in /proc/modules.

By the way, the reason why the Makefile recommends against using insmod from X
is because the kernel has a message to print with printk, it sends it to the console.
When you don't use X, it goes to the virtual terminal you're using (the one you chose
al Alt-F3) and you see it. When you do use X, on the other hand, there are two
possibilities. Either you have a console open with xterm -C, in which case the output
will be sent there, or you don't, in which case the output will go to virtual terminal 7 — the
covered by X.

If your kernel becomes unstable you're unlikely to get the debug messages without X.
Outside of X, printk goes directly to the console. In X, on the other hand,
print's go to the X server (xterm -C). When process receives CPU time,
it is supposed to send it to the X server process. Then, when X server receives the CPU,
it is supposed to display it — but an unstable kernel usually means the system is about
to crash or reboot, so you don't want to delete the error messages, which might explain to
you what went wrong, longer than you have to.

## 1.2 Multiple Kernel Modules

Sometimes it makes sense to divide a kernel module between several files. In
this case, you need to do the following:

- 1. In all the source files, add the line #define _NO_VERSION_ This is im-
because module.h normally includes the definition of kernel_version,
global variable with the kernel version the module is compiled for. If you need
version.h, you need to include yourself, because module.h won't do it for
you with _NO_VERSION_

- 2. Compile all the source files as usual.

- 3. Combine all the object
files into a single one. Under x86, do it with ld -m elf_i386 -r -o <name
