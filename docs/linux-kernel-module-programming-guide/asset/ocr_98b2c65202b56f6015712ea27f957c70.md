# Scheduling Tasks

Very often, we have 'housekeeping' tasks which have to be done at a certain time, or so often. If the task is to be done by a process, we do it by putting it in the crontab file. If the task is to be done by a kernel module, we have two possibilities. The first is to put a process in the crontab file which will wake up the module by a system call when necessary, for example by opening a file. This is terribly inefficient, however — we run a new process off of crontab, read a new executable to memory, and all this just to wake up a kernel module which is in memory anyway.

Instead of doing that, we can create a function that will be called once for every timer interrupt. The way we do this is we create a task, held in a struct tg_struct, which will hold a pointer to the function. Then, we use queue_task to put that task on a task called tqtimer, which is the list of tasks to be executed on the next timer interrupt. Because we want the function to be kept running, we need to put it back on tqtimer whenever it is called, for the next interrupt.

There's one more point we need to remember. When a module is removed by rmmod, first its reference count is checked. If it is zero, module_cleanup is called. Then, the module is removed from memory with all its functions. Nobody checks to see if the timer's task list has a pointer to one of those functions, which will no longer be available. Ages later (from the computer's perspective, from a human perspective) the kernel has a hundredth of a second and tries to call the function on the task list. Unfortunately, the function is no longer there. In most cases, the memory page where it sat is unset, and you get an ugly error message. But if some other code is now sitting at the same memory location, things could get very ugly.
