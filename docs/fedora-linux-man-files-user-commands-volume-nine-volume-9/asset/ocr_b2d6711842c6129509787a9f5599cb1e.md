Only the formats qcow and qcow2 support compression. The compression is read-only. It ans that if a compressed sector is rewritten, then it is rewritten as uncompressed data.

Image conversion is also useful to get smaller image when using a growable format such as qcow: the empty sectors are detected and suppressed from the destination image.

sparse_size indicates the consecutive nuer of bytes (defaults to 4k) that st contain only zeros for qe-img to create a sparse image during conversion. If *sparse_size* is 0, the source will not be scanned for unallocated or zero sectors, and the destination image will always be fully allocated.

You can use the *backing_file* option to force the output image to be created as a copy on write image of the specified base image; the *backing_file* should have the sa content as the input's base image, however, the path, image format, etc may differ.

If the -n option is specified, the target volu creation will be skipped. This is useful for formats such as rbd if the target volu has already been created with site specific options that cannot be supplied through qe-img.

**info [-f fmt] [--output=ofmt] [-backing-chain] filena** Give information about the disk image *filena*. Use it in particular to know the size reserved on disk which can be different from the displayed size. If VM snapshots are stored in the disk image, they are displayed too. The command can output in the format *ofmt* which is either *human* or *json*.

If a disk image has a backing file chain, information about each disk image in the chain can be recursively enurated by using the option –backing-chain.

For instance, if you have an image chain like:

```
base.qcow2 <- snap1.qcow2 <- snap2.qcow2
```

To enurate information about each disk image in the above chain, starting from top to base, do:

```
qe-img info --backing-chain snap2.qcow2
```

**map [-f fmt] [--output=ofmt] filena** Dump the tatadata of image *filena* and its backing file chain. In particular, this commands dumps the allocation state of every sector of *filena*, together with the topmost file that allocates it in the backing file chain.

Two option formats are possible. The default format (human) only dumps known-nonzero areas of the file. Known-zero parts of the file are omitted altogether, and likewise for parts that are not allocated throughout the chain. **qe-img** output will identify a file from where the data can be read, and the offset in the file. Each line will include four fields, the first three of which are hexadecimal nuers. For example the first line of:

```
Offset Length Mapped to File 0 0x20000 0x50000 /tmp/overlay.qcow2 0x100000 0x10000 0x95380000 /tmp/backing.qcow2
```
