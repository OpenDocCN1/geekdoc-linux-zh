# > OPTIONS

servicena

servicena is the na of the service you want to use on the server. A service na takes the form //server/service where *server* is the NetBIOS na of the SMB/CIFS server offering the desired service and *service* is the na of the service offered. Thus to connect to the service “printer” on the SMB/CIFS server “sserver”, you would use the servicena //sserver/printer

Note that the server na required is NOT necessarily the IP (DNS) host na of the server ! The na required is a NetBIOS server na, which may or may not be the sa as the IP hostna of the machine running the server.

The server na is looked up according to either the *-R* parater to sclient or using the na resolve order parater in the (5) file, allowing an administrator to change the order and thods by which server nas are looked up.

password

The password required to access the specified service on the specified server. If this parater is supplied, the *-N* option (suppress password prompt) is asud.

There is no default password. If no password is supplied on the command line (either by using this parater or adding a password to the *-U* option (see below)) and the *-N* option is not specified, the client will prompt for a password, even if the desired service does not require one. (If no password is required, simply press ENTER to provide a null password.)

Note: So servers (including OS/2 and Windows for Workgroups) insist on an uppercase password. Lowercase or mixed case passwords may be rejected by these servers.

Be cautious about including passwords in scripts.

*-R*||—na-resolve `<na resolve order>`

This option is used by the programs in the Saa suite to determine what naming services and in what order to resolve host nas to IP addresses. The option takes a space-separated string of different na resolution options.
