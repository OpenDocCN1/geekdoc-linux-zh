All control characters (but never tabs) are always escaped, regardless of this option’s setting. The escape idiom that started in 2.6.7 is to output a literal backslash (\) and a hash (#), followed by exactly 3 octal digits. For example, a newline would output as “\#012”. There are 3 possible levels: (1) output nu ers with a separator between each set of 3 digits (either a comma or a period, depending on if the decimal point is represented by a period or a comma); (2) output nu ers in units of 1000 (with a character suffix for larger units — see below); (3) output nu ers in units of 1024. The default is human-readable level 1. Each -h option increases the level by one. You can take the level down to 0 (to output nu ers as pure digits) by specifying the **--no-human-readable** (**--no-h**) option. The unit letters that are appended in levels 2 and 3 are: K (kilo), M (ga), G (giga), or T (tera). For example, a 1234567-byte file would output as 1.23M in level-2 (assuming that a period is your local decimal point). Thus, specifying one or two -h options will behave in a comparable manner in old and new versions as long as you didn’t specify a **--no-h** option prior to one or more -h options.
