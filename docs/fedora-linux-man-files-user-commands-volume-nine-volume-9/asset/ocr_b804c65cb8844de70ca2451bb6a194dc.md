# DESCRIPTION

is a script that uses (1) to log into a remote machine (presumably using a login password, so password authentication should be enabled, unless you’ve done so clever use of multiple identities). It assess a list of one or more fingerprints (as described below) and tries to log in with each key, to see if any of them are already installed (of course, if you are not using ssh-agent1 this may result in you being repeatedly prompted for pass-phrases). It then assess a list of those that failed to log in, and using ssh, enables logins with those keys on the remote server. By default it adds the keys by appending them to the remote user’s ~/.ssh/authorized_keys (creating the file, and directory, if necessary). It is also capable of detecting if the remote system is a NetScreen, and using its ‘set’ ssh pka key ... command instead.

The options are as follows:

+   *   `-i identity_file`
+       *   Use only the key(s) contained in *identity_file* (rather than looking for identities via ssh-add1 or in the **default_ID_file** ) If the filena does not end in .pub this is added. If the filena is omitted, the **default_ID_file** is used.
+       *   Note that this can be used to ensure that the keys copied have the comnt one prefers and/or extra options applied, by ensuring that the key file has these set as preferred before the copy is attempted.
+   *   `-n`
+       *   do a dry-run. Instead of installing keys on the remote system simply prints the key(s) that would have been installed.
+   *   `-h , -`
+       *   Print Usage summary
+   *   `-P port , -o ssh_option`
+       *   These two options are simply passed through untouched, along with their argument, to allow one to set the port or other (1) options, respectively.
+       *   Rather than specifying these as command line options, it is often better to use (per-host) settings in (1)Ns’s configuration file: ssh_config5.

Default behaviour without -i is to check if ‘ssh-add’ -L provides any output, and if so those keys are used. Note that this results in the comnt on the key being the filena that was given to ssh-add1 when the key was loaded into your ssh-agent1 rather than the comnt contained in that file, which is a bit of a sha. Otherwise, if ssh-add1 provides no keys contents of the **default_ID_file** will be used.

The **default_ID_file** is the most recent file that matches: ~/.ssh/id*.pub (excluding those that match ~/.ssh/*-cert.pub so if you create a key that is not the one you want to use, just use (1) on your preferred key’s .pub file to reinstate it as the most recent.
