+   - End of command line options. All remaining paraters are interpreted as file nas, even if they start with a dash.

+   - If the file na parameter is a single dash, setfacl reads a list of files from standard input.

# ACL ENTRIES

The setfacl utility recognizes the following ACL entry formats (blanks inserted for clarity):

```
[d[efault]:] [u[ser]:]uid [:perms]
Permissions of a nad user. Permissions of the file owner if uid is empty.
[d[efault]:] g[roup]:gid [:perms]
Permissions of a nad group. Permissions of the owning group if gid is empty.
[d[efault]:] m[ask][: [:perms]
Effective rights mask
[d[efault]:] o[ther][: [:perms]
Permissions of others.
```

Whitespace between delimiter characters and non-delimiter characters is ignored.

Proper ACL entries including permissions are used in modify and set operations. (options -m, -M, --set and --set-file). Entries without the *perms* field are used for *deletion* of entries (options -x and -X).

For *uid* and *gid* you can specify either a na or a nuer.

The *perms* field is a coination of characters that indicate the permissions: read (*r*), write (*w*), execute (*x*), execute only if the file is a directory or already has execute permission for so user (*X*). Alternatively, the *perms* field can be an octal digit (0-7).

# AUTOMATICALLY CREATED ENTRIES

Initially, files and directories contain only the three base ACL entries for the owner, the group, and others. There are so rules that need to be satisfied in order for an ACL to be valid:

+   * The three base entries cannot be removed. There st be exactly one entry of each of these base entry types.

+   * Whenever an ACL contains nad user entries or nad group objects, it st also contain an effective rights mask.

+   * Whenever an ACL contains any Default ACL entries, the three Default ACL base entries (default owner, default group, and default others) st also exist.
