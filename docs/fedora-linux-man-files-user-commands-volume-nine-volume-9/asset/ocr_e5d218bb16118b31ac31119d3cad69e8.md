This option is most often used when the receiving disk partition does. not have enough free space to hold a copy of the largest file in the transfer. In this case (i.e. when the scratch directory is on a different disk partition), rsync will not be able to rena each received temporary file over the top of the associated destination file, but instead st copy it into place. Rsync does this by copying the file over the top of the destination file, which ans that the destination file will contain truncated data during this copy. If this were not done this way (even if the destination file were first removed, the data locally copied to a temporary file in the destination directory, and then renaed into place) it would be possible for the old file to continue taking up disk space (if soone had it open), and thus there might not be enough room to fit the new version of the file on the sa ti.
