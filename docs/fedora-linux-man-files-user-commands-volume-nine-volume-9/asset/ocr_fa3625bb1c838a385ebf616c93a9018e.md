**-rand file(s)**
a file or files containing random data used to seed the random nuer generator, or an EGD socket (see (3)). multiple files can be specified seperated by a OS-dependent character. The separator is ; for MS-Windows, , for OpenVMS, and : for all others.

**-newkey arg**
this option creates a new certificate request and a new private key. The argument takes one of several forms. **rsa:nbits**, where **nbits** is the nuer of bits, generates an RSA key **nbits** in size. If **nbits** is omitted, i.e. **-newkey rsa** specified, the default key size, specified in the configuration file is used.
All other algorithms support the **-newkey alg:file** form, where **file** may be an algorithm parater file, created by the **genpkey -genparam** command or and X.509 certificate for a key with appropriate algorithm.
**param:file** generates a key using the parater file or certificate **file**, the algorithm is determined by the paraters. **alga:file** use algorithm **alga** and parater file **file**: the two algorithms st match or an error occurs. **alga** just uses algorithm **alga**, and paraters, if necesssary should be specified via **-pkeyopt** parater.
**dsa:filena** generates a DSA key using the paraters in the file **filena**. **ec:filena** generates EC key (usable both with ECDSA or ECDH algorithms). **gost2001:filena** generates GOST R 34.10-2001 key (requires **ccgost** engine configured in the configuration file). If just **gost2001** is specified a parater set should be specified by **-pkeyopt paramset:X**

**-pkeyopt opt:value**
set the public key algorithm option **opt** to **value**. The precise set of options supported depends on the public key algorithm used and its implementation. See KEY GENERATION OPTIONS in the **genpkey** manual page for more details.

**-key filena**
This specifies the file to read the private key from. It also accepts PKCS#8 format private keys for PEM format files.

**-keyform PEM|DER**
the format of the private key file specified in the **-key** argument. **PEM** is the default.

**-keyout filena**
this gives the **filena** to write the newly created private key to. If this option is not specified then the **filena** present in the configuration file is used.

**-nodes**
if this option is specified then if a private key is created it will not be encrypted.

**-\[digest\]**
this specifies the ssage digest to sign the request with (such as **-md5**, **-sha1**). This overrides the digest algorithm specified in the configuration file. For full list of possible digests see openssl dgst -h output.
So public key algorithms may override this choice. For instance, DSA signatures always use SHA1, GOST R 34.10 signatures always use GOST R 34.11-94 (-**md_gost94**).
