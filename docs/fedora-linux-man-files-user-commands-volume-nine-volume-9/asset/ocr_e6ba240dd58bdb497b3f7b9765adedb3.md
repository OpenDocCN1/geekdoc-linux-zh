# REAL-TIME AND HIGH-PRIORITY SCHEDULING

To minimize the risk of drop-outs during playback it is recomnded to run PulseAudio with real-ti scheduling if the underlying platform supports it. This decouples the scheduling latency of the PulseAudio daemon from the system load and is thus the best way to make sure that PulseAudio always gets CPU ti when it needs it to refill the hardware playback buffers. Unfortunately this is a security risk on most systems, since PulseAudio runs as user process, and giving realti scheduling privileges to a user process always cos with the risk that the user misuses it to lock up the system — which is possible since making a process real-ti effectively disables preemption.

To minimize the risk PulseAudio by default does not enable real-ti scheduling. It is however recomnded to enable it on trusted systems. To do that start PulseAudio with —**real** (see above) or enabl*ed* the appropriate option in daemon.conf. Since acquring realti scheduling is a privileged operation on most systems, so special changes to the system configration need to be made to allow them to the calling user. Two options are available:

On newer Linux systems the system resource limit RLIMIT_RTPRIO (see **(2)** for more information) can be used to allow specific users to acquire real-ti scheduling. This can be configured in */etc/security/limits.conf*, a resource limit of 9 is recomnded.

Alternatively, the SUID root bit can be set for the PulseAudio binary. Then, the daemon will drop root privileges imdiately on startup, however retain the CAP_NICE capability (on systems that support it), but only if the calling user is a er of the pulse-rt group (see above). For all other users all capabilities are dropped imdiately. The advantage of this solution is that the real-ti privileges are only granted to the PulseAudio daemon — not to all the user's processes.

Alternatively, if the risk of locking up the machine is considered too big to enable real-ti scheduling, high-priority scheduling can be enabled instead (i.e. negative nice level). This can be enabled by passing —**high-priority** (see above) when starting PulseAudio and may also be enabled with the appropriate option in daemon.conf. Negative nice levels can only be enabled when the appropriate resource limit RLLIMIT_NICE is set (see **(2)** for more information), possibly configured in */etc/security/limits.conf*. A resource limit of 31 (corresponding with nice level -11) is recomnded.
