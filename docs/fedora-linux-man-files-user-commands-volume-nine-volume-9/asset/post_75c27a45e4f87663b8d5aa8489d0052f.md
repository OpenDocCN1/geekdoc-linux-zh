## NOTES

This **ps** works by reading the virtual files in /proc. This **ps** does not need to be setuid km or have any privileges to run. Do not give this **ps** any special permissions.

This **ps** needs access to nalist data for proper WCHAN display. For kernels prior to 2.6, the System.map file st be installed.

CPU usage is currently expressed as the percentage of ti spent running during the entire lifeti of a process. This is not ideal, and it does not conform to the standards that **ps** otherwise conforms to. CPU usage is unlikely to add up to exactly 100%.

The SIZE and RSS fields don’t count so parts of a process including the page tables, kernel stack, struct thread_info, and struct task_struct. This is usually at least 20 KiB of mory that is always resident. *SIZE* is the virtual size of the process (code+:data+:stack).

Processes marked <defunct> are dead processes (so-called “zoies”) that remain because their parent has not destroyed them properly. These processes will be destroyed by (8) if the parent process exits.

If the length of the userna is greater than the length of the display column, the nuric user ID is displayed instead.

Commands options such as **ps -aux** are not recommanded as it is a confusion of two different standards. According to the POSIX and UNIX standards, the above command asks to display all processes with a TTY (generally the commands users are running) plus all processes owned by a user nad “x”. If that user doesn’t exist, then **ps** will assu you really ant “*ps aux*“.

- 4 used super-user privileges

## PROCESS STATE CODES

Here are the different values that the s,statandstate output specifiers (header “STAT” or “S”) will display to describe the state of a process:

- D uninterruptible sleep (usually IO)
- R running or runnable (on run queue)
- S interruptible sleep (waiting for an event to complete)
- T stopped by job control signal
- t stopped by debugger during the tracing
- W paging (not valid since the 2.6.xx kernel)
- X dead (should never be seen)
- Z defunct (“zoie”) process, terminated but not reaped by its parent

For BSD formats and when the stat keyword is used, additional characters may be displayed:

- < high-priority (not nice to other users)
- N low-priority (nice to other users)
- L has pages locked into mory (for real-ti and custom IO)
- s is a session leader
- 1 is lti-threaded (using CLONE_THREAD, like NPTL pthreads do)
- + is in the foreground process group
