# FILE CREATION OPTIONS

**-export**
This option specifies that a PKCS#12 file will be created rather than parsed.

**-out filena**
This specifies filena to write the PKCS#12 file to. Standard output is used by default.

**-in filena**
The filena to read certificates and private keys from, standard input by default. They st all be in PEM format. The order doesn't matter but one private key and its corresponding certificate should be present. If additional certificates are present they will also be included in the PKCS#12 file.

**-inkey filena**
file to read private key from. If not present then a private key st be present in the input file.

**-na friendlyna**
This specifies the “friendly na” for the certificate and private key. This na is typically displayed in list boxes by software importing the file.

**-certfile filena**
A filena to read additional certificates from.

**-cana friendlyna**
This specifies the “friendly na” for other certificates. This option may be used multiple tis to specify nas for all certificates in the order they appear. Netscape ignores friendly nas on other certificates whereas MSIE displays them.

**-pass arg, -passout arg**
the PKCS#12 file (i.e. output file) password source. For more information about the format of **arg** see the **PASS PHRASE ARGUMENTS** section in **(1)**.

**-passin password**
pass phrase source to decrypt any input private keys with. For more information about the format of **arg** see the **PASS PHRASE ARGUMENTS** section in **(1)**.

**-chain**
if this option is present then an attempt is made to include the entire certificate chain of the user certificate. The standard CA store is used for this search. If the search fails it is considered a fatal error.

**-descert**
encrypt the certificate using triple DES, this may render the PKCS#12 file unreadable by so “export grade” software. By default the private key is encrypted using triple DES and the certificate using 40 bit RC2.

**-keypbe alg, -certpbe alg**
these options allow the algorithm used to encrypt the private key and certificates to be selected. Any PKCS#5 v1.5 or PKCS#12 PBE algorithm na can be used (see **NOTES** section for more information). If a a cipher na (as output by the **list-cipher-algorithms** command is specified then it is used with PKCS#5 v2.0. For interoperability reasons it is advisable to only use PKCS#12 algorithms.
