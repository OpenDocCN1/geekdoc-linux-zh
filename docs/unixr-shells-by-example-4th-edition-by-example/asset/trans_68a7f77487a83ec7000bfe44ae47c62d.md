## 1.6.6 Redirection and Pipes

### File Descriptors.

所有 I/O，包括文件、管道和套接字，均由内核通过一种称为文件描述符的机制来处理。文件描述符是一个小的无符号整数，是内核维护的文件描述符表中的一个索引，内核使用它来引用打开的文件和 I/O 流。每个进程从其父进程继承自己的文件描述符表。前三个文件描述符 0、1 和 2 分配给你的终端。文件描述符 0 是标准输入（stdin），1 是标准输出（stdout），2 是标准错误（stderr）。当你打开一个文件时，下一个可用的描述符是 3，它将被分配给新文件。如果所有可用的文件描述符都在使用中，⁸ 则无法打开新文件。

### Redirection.

当文件描述符被分配给终端以外的对象时，就称为 I/O 重定向。shell 通过关闭标准输出文件描述符 1（终端），然后将该描述符分配给文件来进行输出重定向到文件（见图 1.5）。重定向标准输入时，shell 关闭文件描述符 0（终端）并将该描述符分配给文件（见图 1.6）。Bourne、Bash 和 Korn shell 通过将文件分配给文件描述符 2 来处理错误（见图 1.7）。而 C 和 TC shell 则通过更复杂的过程来实现同样的功能（见图 1.8）。

### EXAMPLE 1.12

```text
1  $ who > file1
2  $ cat file1 file2 >> file3
3  $ mail tom < file
4  $ find / -name file -print 2> errors
5  % ( find / -name file -print > /dev/tty ) >& errors
```

### EXPLANATION

- 1 who 命令的输出从终端重定向到 file1。（所有 shell 都是这样重定向输出的。）
- 2 cat 命令的输出（连接 file1 和 file2）追加到 file3。（所有 shell 都是这样重定向并追加输出的。）
- 3 file 的输入被重定向到 mail 程序；也就是说，用户 tom 将收到 file 的内容。（所有 shell 都是这样重定向输入的。）
- 4 find 命令的任何错误都被重定向到 errors。输出发送到终端。（Bourne、Bash 和 Korn shell 是这样重定向错误的。）
- 5 find 命令的任何错误都被重定向到 errors。输出发送到终端。（C 和 TC shell 是这样重定向错误的。% 是 C shell 提示符。）
