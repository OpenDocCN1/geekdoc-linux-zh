Chapter One

What is Linux?

Linux is an operating system that can work on computers, smartphones, and even some household appliances.

The Linux operating system has been around since the 90’s, and it has evolved into an operating system that spans across multiple continents, is used by many industries, and is user based. There are not many places that you are going to be able to look without finding some sort of trace of Linux.

Most of the supercomputers that are being used to make some of the most historical scientific breakthroughs run as well as keeping the internet running so that we are able to enjoy it. However, even before the Linux operating system became the primary operating system, it was the most reliable operating system that allowed its users to use it without having any worries about the security issues that many other operating systems have.

Linux is exactly like Windows 7 and Windows 8 operating systems. We will examine what an operating system is in the next chapter. If you do not have an operating system on your computer, then your computer’s software is not going to function the way that it is supposed to if it operates at all.

You may be wondering why you should choose Linux over one of the other operating systems. Installing Linux means that you have to learn an entirely new user interface when you most likely already know how to use an operating system such as Windows. But, take a step back and look at the operating system that you are currently using. Do you have to repair your operating system continuously or does it frequently crash?

With Linux, you are not going to have to deal with what you are currently dealing with when using your current operating system. Linux evolves with the current computer technology thus making it one of the most stable ecosystems on the planet.

Another added bonus to using Linux is that it is completely free. You are not going to have to pay anything for any licenses that you may have to pay for when you are using a different operating system.

Linux came from the Unix operating system which was first started in 1969 by Ken Thompson, Joe Ossanna, Douglas McIlroy, and Dennis Ritchie. But, in 1971 Unix was released to the public a programming language that was comply assembled. As time went on, Unix was rewritten in the C programming language thus giving it a higher level of language implementations.

Chapter Two

Operating Systems – What are They?

Operating systems are the systems that are going to communicate with the hardware inside of the computer so that it can talk to the software and allow the computer to run the way that it is supposed to. Every program that you are going to use on your computer is going to run off of the operating system. The only exception is going to be firmware that you may be running on your computer.

Operating systems that use a timeshare are going to schedule a variety of tasks to be done so that you can use the system more efficiently based on the resources that are frequently used.

Every operating system is going to have these pieces that are going to come together to work and make the operating system whole. Without one of these pieces, your operating system may still work, but it may not necessary work the way that you want it to.

•Daemons: the daemons are services that run in the background and are going to start up after your computer is booted up or after you have logged into the desktop.

•Bootloader: this is the software that will manage whenever your computer boots up. For many users, it is a splash screen that is going to boot up the operating system so the computer can run.

•Kernel: the kernel is part of the whole Linux system. The kernel is the core of the operating system that is going to manage everything from the peripheral devices to the CPU. On the scale of how important the kernel is to the operating system, the kernel will be the lowest on the scale.

•Graphical server: the graphical server controls the graphics that you see on the websites that you visit.

•The shell: the shell is the command process that is going to enable you to give the computer commands through a text interface. When using Linux, you do not need to touch the command line.

•Desktop environment: the desktop is what you are going to use as the user of the computer. Every desktop environment that you encounter is going to have various applications that are built into it that are going to be specific to that desktop.

•Applications: these are the software titles that you can install on your computer.

The first computers were first built to do single tasks in a series just like a calculator does. These operating systems were first developed in the 50’s so that different programs could be run in succession so that the processing could be sped up. It was not until the sixties that the modern and sophisticated operating systems were developed.

Some of the hardware that was added were things such as parallel processing and runtime libraries. Whenever personal computers started becoming more popular in the 80’s, the operating systems evolved so that they could be used on these computers just as they were the larger computers that they were designed for.

The earliest record of an electronic system that had no operating system came around in the 40’s. these electronic systems were programmed to switches that had to be switched on and off. Or they were hooked up to jumper wires that were then connected to plug boards. It was these systems that were made to generate ballistics tables that were used by the military or for payroll checks to be printed and controlled from the data that could be found on a paper card that had been punched by the worker for when they were at work and when they were not at work.

Chapter Four

Navigation of Linux

Since you are new to using Linux, you are going to need how to navigate through the new operating system. Some of the core competencies that you require are to move around the file system so that you can get a good idea of the new interface.

Figuring out where you are through the use of the pwd command

After you have logged into your desktop, you are going to be placed in the home directory. This home directory is going to be where all your files are located, and you are going to be able to create directories as you need them.

In order to locate your home directory in relation to where all the other file systems are, you can use the pwd command. The pwd command will show you which register you are currently using.

After using the pwd command, you should get a result of /home/user account.

Each home directory is going to be named for the user account that you are working with. Since the home directory is going to be the very top of the directory, it will be the root directory.

Searching the contents of your directory

Being that you are now able to get into the directory, you need to know what materials the directory houses. Being that your root directory is not going to have many things in it, you will want to try and find another directory.

First, you are going to enter cd/ usr/ share into the command prompt before entering the pwd command again.

At this point, you should be inside of a new directory. So that you can see the files in this directory, you will use the ls command. By using this command, you will have a list of all of the contents of the directory no matter how many items there are in it. You will now have the option to add some flags to the command so that you can look for files that follow specific behaviors.

In case you are wanting to find the hidden files in the directory, you need to add in -a to your command prompt. Keep in mind that there are no files that are actually hidden inside of the user directory. Most of the “hidden” files are going to be those that hold special indicators such as configuration files.

The dot entries that you see are not going to necessarily be directories but methods that have been built into the operating system in reference to other directories. Single dots are going to be for the directory that you are currently using while the double dot is going to be for the parent directory.

Navigating your file system

You have already made your way into the directory to your home directory, and then you moved on to a different directory, but, let’s look at some other things you can do in moving through the file system on your new Linux system.

Go back to your home directory by using the cd /usr/share command.

The command that you have just used will give you the most direct path to the directory in question. All files and directories in Linux are going to be located in the root directory but will be referenced by the slash that starts out the command.

Absolute paths are going to show you the location of the directory where the file is located in the root file. The absolute path is going to be there so that we can reference the directories in the most direct way so that you are not getting the directory mixed up with another directory.

Keep in mind that you are going to have to start all of your absolute paths with a slash.

On the other hand, you can use a relative path which will show the directory as it is related to the current directory. Whenever the directory that you are trying to get to is close to the directory in the hierarchy, then you are going to want to use this method because it is going to be the easiest and shortest way for you to get to the file that you want. Whenever your directory is inside of the directory that you are currently located in, you are going to be able to reference this directories name without using a slash.

Chapter Six

The Linux Interface

There are several different interfaces that you are going to be allowed to use depending on what your purpose is for using Linux. The two interfaces that are on the API (application programming interface) are the kernel user space and the kernel internal.

The API on Linux is in the kernel user space API. This means that the programs on the system are going to have access to the resources and services that are on the kernel. The Linux system is made out of the system call interface and the kernel that allows for subroutes to the GNU C Library.

The developers of the API for Linux made it to where the API can provide unsable features as to the specifications that have been defined by POSIX so that it is compatible with other features that are going to be useful but have not necessarily been defined by POSIX.

The API for Linux is completely stable and has been stable for many decades. This occurs thanks to the stability that is granted by the source code. However, while the system is stable and never going to break down, those who work on the development of the system are conservative when it comes to introducing new calls into the system.

All of the open source software for Linux is free and written specifically for the POSIX API. Since everything has to go through the Linux kernel, the API for the kernel has been bigger because of all of the additional features that have been put into the API.

Because of these added features, there is a technological advantage to the the API on Linux that makes it superior to the POSIX API. Some of the best-known examples are Weston and systemd. Many people who use Linux have no hesitated to state that they prefer the Linux API over the POSIX API because of the advantages that the Linux API has to offer.

System call interface

The system call interface is the basis for everything that is implemented and even made available for the system calls that are inside of the Linux kernel. Several subsystems are going to be empowered to define their own calls.

C standard library

The C library is going to be what surrounds the system calls done by the Linux kernel. There is a combination composed of the system call interface and the C library that is going to make up the entire Linux API.

Linux ABI

The ABI is going to be the kernel user space for the ABI. ABI stands for application binary interface, and when speaking of the ABI, you are going to be referring to the application binary interface which is all of the binaries that are found inside of the machine’s code.

Any code that is part of the machine’s binary is going to be tied to the instruction set. When you are trying to define an ABI that is useful, the developers for the Linux kernel and the C library developers are not going to be held responsible. Instead, the Linux distributions and the independent software vendors are going to be the ones that are held responsible for ensuring that the ABI is stable for the user to use.

Chapter Eight

Installing a Firewall with Linux

By default, Linux Ubuntu is not going to have a firewall installed. Many people already have a firewall on their computer, but sometimes they do not, and you are going to need a firewall to help with the security on your computer. With Ubuntu, you are going to have at least two packages that you are going to be able to choose from for a firewall.

Lokkit

Lokkit is going to be a basic firewall, and it is not going to be hard to configure the firewall. The first thing that you need to do is run Lokkit with superuser privileges by opening the run command and entering gksudo gnome-lokkit. Once it comes up you going to be requested to enter your password before going any further. Once the password has been inserted, a dialog box will appear asking if you want to configure a firewall.

The wizard that walks you through installing Lokkit is going to be explained on the screen. It is recommended that you use the high-security option on your firewall. The only time you are not going to want to choose this option is if you are doing DCC file transfers to IRC. Another reason you will not choose high security is if you are using the DHCP in order to get an IP address from cable or DSL modems.

Whenever the setup wizard asks about turning DHCP on, you are going to want to click yes. For those using DSL or cable modems, you are going to need to have your IP address pulled up through the use of DHCP.

As long as your computer is the only computer that is on the network, then you do not necessarily have to enable the services that the firewall is going to provide. It does not matter if you click no or not; the SSH is going to be left open to any machines that are on the network you are using. You just need to make sure you click yes whenever Lokkit asks about trusted hosts that may be on your network’s interface.

Lokkit is going to ask some more questions about the security that it should offer for your computer before the firewall is going to be enabled. Make sure you are saving the changes that you make before you start the firewall.

Should you ever believe that you are having problems with your firewall, you are going to need to rerun Lokkit so that you get rid of all of the rules that the firewall has set into place.

Guarddog

You are going to need to open the run dialog box and enter gksudo guarddog so that guarddog is opened. You do not have to be a superuser to run this firewall, but there are going to be special rules that you will have to apply to the firewall if you are wanting to use it as a super user.

This firewall is going to be more complex than the one that we just discussed. You are going to see this whenever you start guarddog. The first thing that you are going to notice is that there are tabs and in these tabs are going to have the settings that are going to allow you to define the various rules that the firewall is going to have to abide by.

Guarddog is going to come with two zones that are already configured. They are the internet zone and the one that is set up for all the IP addresses that appear but do not match any of the other zones.

The guarddog firewall is going to take some time for you to set up correctly because there are all kinds of settings that you are going to have to go through, but it is going to give you a complete sense of protection on your new operating system.

Chapter Nine

File Management

The files that you keep on your operating system are going to be important to you as they are things that you are going to need access to at various points in time. Since Linux runs off a command prompt, you will need to enter the command that you want the operating system to execute.

The files that are located on Linux are going to be placed together based on the purpose of what the purpose of the file is. Ultimately, all of the files are going to be under the root directory.

The root directory is going to be the home directory where you are going to start out when you are looking for a particular file or directory.

Home is going to be where all of your main directories are. These are going to be directories for things such as samba and HTTP.

Bin is the commands that you are going to need to enter when your computer is booting up. This is typical commands that an average user will be using.

Sbin: the commands that are going to be used by normal users but are going to be run by Linux specifically.

Proc: the proc file system will not be located on a disk. Instead, it is a file system that will be located in the imagination of the kernels on the Linux memory system.

Usr: this directory is going to have everything that you are going to use for normal operations on your computer. This directory will also include the bin and sbin file systems along with include which is going to be the files for the C programming language. Lib, the files that are not going to change the data for any programs or subsystems. Local, where all of your local software is going to be stored. Man, the manual pages for your computer. Info, the information documents.

Boot: any files that are used that are related to the bootstrap loaded as well as any kernel images that are on the computer will be located in this file.

Lib: libraries that are shared by programs.

Dev: the files that are on the device.

Etc: any files that have to be configured specifically to the machine that is being used.

Var: files that are for printers, man pages, and temp files will be under this library.

Mnt: when temporary mounts need to be placed on the system, they are going to be located in this library.

Chapter Ten

System Administration and Security

Once you have installed Linux, you are going to need to configure your systems, backup your files, monitor the system, and deal with user management and updates on the system.

As the system administrator, you are going to have to know how to do things such as deal with the storage media, managing the memory on the operating system, booting and shutting down the system, and how to handle users that are on the system.

Disks and storage media

After you have connected the operating system, you are going to have to create all of the filesystems on your disk so that you have a place saved to store files for your system.

Some of the things that you are going to do with your disks are to format them, move file systems around so that you can form a structured tree of files. Partition a hard disk so that you can do different activities that are not going to work against each other, but separately. You will also be able to make a file system on each disk and partition that you have set up.

There are two different devices that Linux is going to recognize, the access block devices and character devices. A few of the devices are going to be continued access while others are going to be random access. Every device that you have supported on your file system is going to be represented by a device file. That way, when you create a device file, the data will be inputted from the device that it belongs to or be sent to the device it is representing.

This makes it to where you do not have to have anything special in order to access the devices that you are using on the Linux system.

Managing memory

Linux has a virtual memory which is when a disk is being used as an extension of the RAM that is being used by the memory so that you have enough room to do what it is that you need to do. Any contents that are placed on the hard disk for memory are going to be able to be called upon later. As a user, you are not going to be able to see where all the contents of programs are going to be saved because it is not for the user to know, it is for the program to know, but not all programs are going to realize that some part of their memory is hiding on the hard disk.

While managing the memory, you are going to have the option to create a memory swap which is going to swap the file that you have selected will be swapped from where it is currently residing in the reserve memory space.

Booting and shutting down

Whenever you start your operating system, you are going to be participating in the act of booting it up. This is going to be when the image from the computer comes up during bootstraps.

When the computer is going through its bootstrap process, it is going to pull up some code that is known as the bootstrap loader which will start the operating system so that it can be used. Every computer that you use is going to go through the bootstrap process differently.

You need to follow the appropriate steps to make sure that you shut the Linux system down. If you do not do your shutdown properly, then you are going to end up causing your files to become scrambled, and your operating system is going to end up being messed up.

It is important to remember that the Linux system uses a disk cache that is not going to write everything onto the disk in one setting but is going to do it in intervals so that the performance of the operating system is superior to other operating systems. That is why it is essential to follow the proper shutdown procedures so that you are not wiping out any data that is being moved to the disk at that point in time.

Security

A great many people decide to use Linux because of the security that the server offers. Linux has not had any major problems when it comes to the security provided to its users. But, this does not mean that you do not need to keep an eye on the security of the system.

The Linux system is not going to be immune to everything

It is true that downloading a Linux distribution is going to be more secure than if you were to download Windows out of a box that you just bought, however, due to the fact that Linux is free, there are going to be vulnerabilities that Linux is going to have. But, you are not going to find as many exploits as you will with another operating system. This does not mean that there are not any found, it just means there are less.

If you are using Linux on a desktop, you are going to still be open to exploits that are browser based such as a rootkit. The system is not going to necessarily have to be rooted in order for it to be disrupted in its operating.

Therefore, you are going to still need to have security in mind as the system administrator so that you can protect yourself, your files, and your users.

There is no obligation to have an antivirus

Working with Windows, you are used to having an antivirus, however, when you move over to Linux, you are not going to need one. There are not many antiviruses out there that are going to work on a Linux operating system due to the fact that Linux does not display the same problems that Windows does when it comes to viruses and malware.

If it makes you feel comfortable, you are going to be able to install an antivirus if you want. But, you are most likely not going to get any results back when you scan your system because there will not be any threats on your system.

Most attacks that Linux users are going to be open to are worms and cross-site scripting. Other attacks such as phishing attempts are going to be based on what the user decides to enter into the attack because you are going to be asked for personal information while you are on the internet and it is possible not to realize that you are being fooled by someone trying to hack into your computer.

It is better to prevent than it is to cure

If you have ever been the victim of a virus or malware, then you know that it is a lot easier just to maintain it so that it is running properly rather than to spend hours upon hours of trying to get all of your information back after you have had a security breach.

The first thing that you are going to want to do is to get on the email list for the vendor’s security list that way that you are instantly alerted when there are problems with the distribution that you are using and how it can be fixed.

If you are using a third party distributor, then you are going to probably see updates in security slower than if you were to use an upstream vendor.

Also, make sure you keep your operating system up to date. At least once a week you are going to want to run updates so that you can update everything in case there are patches that you are going to need to make sure that you are secured. If you do not do this, then you are opening yourself up to attacks.

User permissions and encryption

You can also do your part in making sure that you keep your system locked down to just those that need to be on the system. Depending on which distribution you are using is going to change which tools are offered for system security. You need to go through and learn where these tools are and how to use them so that you can lock down your system or turn the tools off if they are not needed.

It is important that you know the way that Linux allows for permissions to be set up so that others have access to your files but not so much access that they can end up getting in and messing up your system. This is vital when it comes to a system that is being used by multiple users or if you are running off a host service that is being shared.

It is not a bad idea to encrypt the partition that you have set up either. Whenever an individual has physical access to the machine that you are running Linux on, they are not going to need to know any of your passwords to get in and get the data that is located on that machine if it is not encrypted.

Audit and intrusion detection

Lastly, you should take into consideration setting aside some time to place intrusion detection on the servers that you are a system administrator to and running checks to verify that your system has not already been compromised.

Many hackers are experienced enough to be able to get into an operating system and compromise it without leaving any signs until it is too late.

Backups

No matter how reliable your system is, you are going to want to have backups of anything that is on your system so that you do not lose everything. While it is highly unlikely that you are going to suffer from a security breach when using Linux, it is better to be safe than sorry.

As you know, Linux is going to run off of commands, and there are millions of commands to do everything it is that you are wanting to do. You are going to want to make the computer do the work for you and use shell so that you have the option to automate things. This is going to be why scripts are written.

If you do not already know, scripts are going to be lines of code that tell the computer what to do. Your shell is going to have the ability to read the file that contains all of your scripts and execute them as if you were to type them out right then and there.

Scripts are good for a great number of things such as:

•Getting automatic updates to your Linux system from your vendor.

•Back up your files to another server so that you do not risk losing them.

•Managing a website and the files located on it (if you manage a website.)

Your first script

Obviously, you want your shell script to be successful, and for that to happen, you have to make sure you are following these three steps.

1.Placing the script somewhere that your shell has access to it.

2.Writing out script correctly so that it can be read by the shell.

3.Giving the shell the proper permissions that are needed for the script to be executed on your operating system.

The scripting for the shell is going to be in ASCII text; therefore you need to have a text editor opened to create the proper shell script. The text editor that you use is going to be based on your personal preferences, but some of the ones that you can choose from are the notepad or word processor. Just ensure that the editor you decide to use is going to be able to read as well as write out the ASCII texts.

After your text editor has been opened, you are going to enter in some text that looks like this:

#!/ bin/ bash

#the first shell script for Linux

Echo: “I did it!”

The next thing that you are going to need to do is to save the file with a name that you are going to know what it is and where you can find it.

When looking at the opening line of your script, you are going to notice that it is going to tell the shell which program you are wanting to be used when it comes to interpreting your script. You can use other programs such as Perl or python if you prefer.

Your second line is going to be your comment which is set apart from the rest of the code with the hashtag. Anything that is following the hashtag is going to be ignored by the interpreter because it is not an actual part of the script.

The longer your script is, the more comments that you are going to have in your script so that you are able to go back and figure out what it is that you are doing with your code or so that others can use your code and know what it is that you are doing.

That last line in your script will be the command that is echoed. Basically, this is the command that you are going to want to be printed on your display.

Setting permissions

You have to allow the shell to know that it is okay to run the code that you have put into the command prompt. You are going to need to use the chmod command along with the number 755. The number 755 allows for anyone to execute, read, and write the code. But, if you want your code to be private instead, you will use the number 700.

Placing it into your path

When your script is executed, you should see the “I did it!” message that you put into your code back when you first wrote it. On the off chance that you do not see your code on the screen, relocate your file in its directory and move the shell there rather than the directory that it is currently using.

Whenever the name of a command is entered into the system, the system is not going to go through the entire computer to locate that file. Instead, it is just going to search through where you tell it to search specifically. Scanning your entire computer would take way too long, and you may not always have that time.

Your shell is going to keep a list of all the directories in which programs that are executable will be located and the only directories that are searched (if you do not tell shell where to look) and it will find the file. If the file cannot be found, then you are going to get an error message that tells you that your command could not be found.

The list of directories that the shell is going to search will be the path, and you are going to be able to look at all the paths by placing $PATH into your command prompt. The result is going to be the entire list of directories that are going to be searched when looking for your command.

You also have the option to add directories so that the shell looks in that directory rather than going into a different directory.

Editing

Your home directory already has some scripts that are being run by the shell that you did not put on your computer but were put there so that it can configure the behavior of your sessions while you are on the computer. These scripts can be edited by you if you want to edit them.

Some commands are automatically built into your shell that you are not going to be able to change. Your shell is going to understand a handful of commands on its own and others are going to have to be taught to it. Some commands that your shell is going to know automatically are cd and pwd.

Another group of commands are the programs that are executable. A great number of commands in this group are going to be found in the files that are located in your directory.

The last group of commands will be the commands that include runtime environments. When using these commands, the system is going to be holding an unknown number of facts in the memory bank. The information that is in the memory bank is known as the environment, and these environments are going to be things like the names of your files, your user names, so on and so forth. You can use the set command to be able to see all of the environments that are in this group.

With the alias command, you have the ability to create custom commands that are going to be unique to you.

You should know that function is a command that is built into the shell as well just like alias is so if you want to make the command last just for your current session, enter your command into the command prompt rather than into your text editor.

Throughout the pages of this book you have learned what Linux is and the various things that you are going to be able to do with it. 1. Look at the processes that are not being run by you.

If you are doing something on your machine and find that while you are in the middle of that intense online game, your computer freezes. Your first inquiry is going to be what has happened to your computer to make it do this. The answer is that another user could be taking some of the CPU that your computer needs to run the game that you are playing.

To look at the processes that are being run, but not by you, you will need to enter this code into your command prompt:

Ps aux | grep -v ‘whoami.’

Using this code is going to pull up all of the processes that are taking up CPU on your computer. But, this is going to all of the processes that are running in the background as well. So, why not sort out the processes so that you can see the top ten processes that are taking up the most CPU. You will enter this syntax into your prompt.

Ps aux - - sort = % cpu | grep – m 11 – v ‘whoami’

You are probably going to want to run this command out of your root directory so that you are getting the background process filtered out. And now that you have these CPU killing processes, you are going to be able to shut them down and get back to your game!

2. Replacing the same text across several files

In order to change the text from windows to Linux in the directory and its subdirectories will be this code:

Find. – name’ * .txt’ – print | xargs perl – pi -e’s/windows/Linux/ig’ * .txt

Find – type f – name ‘ * .txt’ -print0 | xargs - - null perl – pi – e ‘s/windows/Linux/’
