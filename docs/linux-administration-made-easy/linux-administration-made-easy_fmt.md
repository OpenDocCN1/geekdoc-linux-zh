### 2.2. 选择 Linux 发行版

有多种 Linux 发行版可供选择。每个发行版提供相同的 Linux 内核和系统工具，但在安装方法和捆绑应用程序上有所不同。每个发行版都有自己的优缺点，因此在决定之前，花点时间研究特定发行版提供哪些功能是明智的。

以下是一些你可以访问的网站列表，它们将描述特定的 Linux 发行版，并提供有关如何下载或购买它的信息：

- http://www.redhat.com/

Red Hat 发行版由商业供应商 Red Hat Software 开发，是最流行的发行版之一。由于可以选择图形界面（GUI）和文本界面安装程序，`Red Hat 6.1` 可能是最容易安装的 Linux 发行版。它通过 `RPM` 工具提供了方便的升级和包管理，并包含了 GNU 网络对象模型环境（`GNOME`）和 `K 桌面环境`（`KDE`），两者都是 `X Window` 系统流行的 GUI 窗口管理器。该发行版适用于 Intel、Alpha 和 Sparc 平台。

- http://www.debian.org/

Debian 发行版由名为 `Debian 项目` 的非营利组织开发，是开源社区的宠儿。它同样通过 `dpkg` 工具提供了方便的升级和包管理。该发行版适用于 Intel、Alpha、Sparc 和 Motorola（Macintosh, Amiga, Atari）平台。

- http://www.suse.com/

S.u.S.E 发行版由商业供应商 S.u.S.E. 开发，是另一个流行的发行版，也是欧洲领先的发行版。它包含了 `K 桌面环境`（`KDE`），并通过 `YAST` 工具提供了方便的升级和包管理。该发行版适用于 Intel 和 Alpha 平台。

- http://www.caldera.com/

OpenLinux 发行版由商业供应商 Caldera 开发，面向企业用户。随着新的 2.2 版本发布，Caldera 以其似乎最易安装的特性提高了门槛。此外，它还配备了 `K 桌面环境`（`KDE`）。该发行版适用于 Intel 平台。

- http://www.mandrake.com/

Mandrake 发行版由商业供应商 MandrakeSoft 开发，将 Red Hat（你的选择）与额外的软件集成。

- http://www.slackware.com/

Slackware 发行版由 Walnut Creek Software 的 Patrick Volkerding 开发，是现代发行版的祖祖。提供相当简单的安装，但升级和包管理较差。该发行版适用于 Intel 平台。

## 第3章 Linux 概述

欢迎来到 Linux！

### 3.1. 什么是 Linux？

Linux 是一种真正的 32 位操作系统，运行在多种不同的平台上，包括 Intel、Sparc、Alpha 和 Power-PC（在其中某些平台上，如 Alpha，它实际上是 64 位的）。虽然也有其他端口可用，但我没有那方面的经验。

Linux 最早于 20 世纪 90 年代初由一位芬兰的小学生林纳斯·托瓦尔斯（Linus Torvalds）开发。当时 Linux 有一个“尖端”的 386 minix，决定编写一个基于 286 的 Minix 系统（一种主要用于操作系统课程的小型类 Unix 实现）的替代品，以利用当时新芯片上提供的额外指令集，并开始编写一个简单的裸机内核。

最终，他在 USENET 组 `comp.os.minix` 中宣布了他的小项目，邀请感兴趣的人士查看并为该项目做出贡献。结果是惊人的！

Linux 有趣的一点在于，它是完全免费的！Linux 决定采用自由软件基金会（Free Software Foundation）的 `GNU GPL` 许可证，这意味着代码受版权保护——但这种保护意味着它必须始终对他人可用。

免费意味着——你可以免费获取它，免费使用它，你甚至可以自由出售它以获利（这听起来并不奇怪；包括红帽（Red Hat）在内的几家机构将标准 Linux 内核、一组 GNU 工具打包，并附上他们自己“口味”的包含应用程序，将其作为发行版出售。一些常见且流行的发行版有 Slackware、Red Hat、SuSE 和 Debian！很棒的一点是你可以访问源代码，这意味着你可以根据自己的需求对操作系统进行定制，而不是迎合大多数商业厂商“目标市场”的需求。

Linux 可以且应该被视为 Unix 的完整实现。然而，它不能被称为“Unix”；这并不是因为不兼容或功能性匮乏，而是因为“Unix”一词是 AT&T 的注册商标，该词的使用仅在许可协议下才允许。

Linux 与任何其他操作系统解决方案一样，拥有同样的支持、可靠性和可行性（嗯，在我看来，它甚至比它们要好得多！）。然而，由于其起源、背后的哲学以及缺乏数百万美元的营销活动，关于它流传着很多神话。人们对这个精彩的操作系统还有很多需要学习！

### 3.2. 打破神话

我已经使用 Linux 几年了，我认为我对这个操作系统以及它能做和不能做什么有一定的了解。作为一名热衷的 USENET 读者，我关注最新的进展，当然还有各种必然出现的“口战”（那些该死的交叉发帖倡导者！:-) ））。我见过的神话比很多人认为的要多（这些神话通常被称为 FUD——“恐惧、不确定性、怀疑”，这似乎是商业技术供应商用来恐吓其市场远离竞争技术的一种常用策略）。所以，让我来试着列举几个最常见的神话，并尝试打破它们 :-)

- Linux 是免费软件（freeware），因此它是一个玩具。

某些人似乎有这样观念：由于某件软件是由没有营利动机的志愿者编写的，其结果显然必然逊于商业级产品。

这在过去可能是事实（我的意思是，在 DOS 和早期 Windows 世界中，有很多免费软件完全是垃圾），但在最近这绝对不是事实。

互联网的力量让全球最聪明的人聚集在一起成为可能，让他们对他们感兴趣的项目进行协作。参与开发 Linux 或成千上万 GNU 工具和应用程序包的人来自不同的背景，他们所有人对于想要贡献都有不同的个人理由。

有些人是硬核黑客，出于对编码的热爱而开发；另一些人有某些需求（例如，工作局域网的网络流量监控器）并决定自己编写；还有一些人是学者和计算机科学家，他们使用 Linux 进行研究。

与开发并销售包但排除源代码的商业产品不同，Linux 中使用的用户代码会受到任何有兴趣和能力的人审查、调试和改进。这种同行评审的行为是 Linux 能够提供如此高可靠性和高性能的原因之一。



不要忘记：互联网本身几乎完全构建并运行在开源项目之上。你每天与世界各地的人交换的电子邮件有 80% 的概率由 `Sendmail` 处理其中一个或两个；你在“冲浪”网网时浏览的网页，全球 50% 以上的网站是由 `Apache` 为你提供的。这对你来说足够可靠吗？

`Linux` 没有支持。

听到这个神话让我感到有些反感。而且据称“其他”厂商确实提供支持？我个人用过一个非常流行的商业操作系统，该厂商所谓的“支持”完全没用处。

首先，`Linux` 是有支持的。是的，商业支持。有些公司可以根据你愿意支付的费用提供大量支持，提供电话和电子邮件支持，许多公司甚至愿意直接上门为你解决问题！

然而，在你遇到 `Linux` 的 99% 情况下，只要你能从社区获得帮助，就能完成你的愿望。`Linux` 社区庞大且活跃，并且乐于提供帮助。有无数的论坛、邮件列表和网站，你可以在那里找到你问题的答案。

## 4.1. 创建安装磁盘

将 `Red Hat Linux` 分发版安装到系统中的第一步，是找到一种启动安装程序的方法。通常的方法是创建一个安装光盘，尽管如果你是从 CD-ROM 安装，且你的系统 BIOS 支持，你应该能够直接从 CD 启动进入安装程序。

否则，要创建一个安装软磁盘，你需要将 `boot.img`（这仅仅是一个 `ext2` 格式的 `Linux` 启动磁盘的镜像，其中包含一个额外的安装程序）拷贝到软磁盘上。`boot.img` 文件可以从 `Red Hat` CD-ROM 的 `/images` 目录获取，或者通过 FTP 从 `ftp://ftp.redhat.com` 的 `/pub/redhat/redhat-6.1/i386/images` 目录下载（假设你正在 `Intel` 机器上安装 `Linux`）。

你可以从 DOS 或 Windows 系统创建启动软磁盘，也可以从现有的 `Linux` 或 `Unix` 系统创建。对于目标磁盘，你可以使用未格式化或预先格式化（针对 DOS）的软磁盘——这没有区别。

在 DOS 环境下：假设你的 CD-ROM 可识别为 `D:` 盘，你可以输入：

```
d:
cd \images
..\dosutils\rewrite
```

对于源文件，输入 `boot.img`。对于目标文件，输入 `a-:`（假设你创建的软磁盘已插入 `A:` 盘）。随后 `rewrite` 程序将把 `boot.img` 文件拷贝到软磁盘上。

在 `Linux`/`Unix` 环境下：假设 `boot.img` 文件位于当前目录（你可能需要将 CD-ROM 挂载到 `/mnt/cdrom` 并在 `/mnt/cdrom/cdrom` 中找到文件），你可以输入：

```
dd if=boot.img of=/dev/fd0
```

`dd` 实用程序将其输入文件（`if`，即 `boot.img` 文件）拷贝到输出文件（`of`）`=/dev/fd0`（假设你的软磁盘可以通过 `/dev/fd0` 访问）。

除非 `Linux` 或 `Unix` 允许对软磁盘设备写入权限，否则你可能需要以超级用户身份执行此命令。（如果你知道 `root` 密码，输入 `su` 成为超级用户，执行 `dd` 命令，然后输入 `exit` 回到普通用户状态）。

通过上述任一方案，你现在应该拥有了一个可引导的 `Red Hat 6.1` 安装软磁盘，你可以用它来安装新的 `Red Hat Linux` 系统了！

## 4.3. 分区硬盘（硬盘）

那么，到底要不要分区呢？嗯，虽然你可以在单分区系统上运行一个功能完的 `Linux` 系统，而且这样配置起来其实要简单一些，但将你的一个或多个存储设备划分为多个分区会有许多益处。

虽然 `Linux` 在只定义了一个大分区的磁盘上运行良好良好这是事实，但将你的磁盘至少划分为四个主要文件系统（`root`、`usr`、`home` 和 `swap`）的分区有几个优点。这些优点包括：

首先，可以缩短执行文件系统检查所需的时间（无论启动时还是手动执行 `fsck` 时），因为这些检查可以并行进行。（顺便说一下，永远不要在挂载的文件系统上运行 `fsck`！！！你几乎肯定会对发生的事情感到后悔。唯一的例外是该文件系统是以只读方式挂载的，在这种情况下是安全的）。此外，在具有多个分区的系统上进行文件系统检查要容易得多。例如，如果我知道我的 `/home` 分区出了问题，我只需要卸载它，执行文件系统检查，然后重新挂载该配对的文件系统（而不是使用救援盘以单用户模式启动系统并进行修复）。

其次，有了多个分区，你可以根据意愿将你的分区中的一个或多个分区挂载为只读。例如，如果你决定 `/usr` 中的所有内容都不会被 `root` 动，你就可以将 `/usr` 分区挂载为只读。

最后，分区提供的最重要的益处是保护你的文件系统。如果某个文件系统发生了什么故障（无论是由于用户错误还是系统故障），在分了区的系统中，你可能只会丢失单个文件系统上的文件。在未分区的系统中，你可能会丢失所有文件系统的文件。

这个小事实可以是一个巨大的优势。例如，如果你的 `root` 分区损坏导致无法启动，你基本上可以从救援盘启动，设置你的 `root` 分区，并将你能复制的内容（或从备份恢复；详见第 8 章关于如何备份和恢复文件的细节）到另一个分区（如 `home`），然后再次使用紧急启动盘重启，输入 `mount root=/dev/hda3`（假设包含你 `root` 文件系统的分区在 `hda` 的第三个分区上）并启动功能正常的 `Linux` 系统。然后你就可以对未卸载的损坏的 `root` 分区运行 `fsck` 了。

我曾有过文件系统灾难的个人经历，我非常感激由于使用了多个分区将损害限制在了局部范围内。

最后，由于 `Linux` 允许你安装其他操作系统（如 `Windows 95/98/NT`、`BeOS` 等）并对你的系统进行双系统（或三系统、……）启动，你可能希望设置额外的分区来利用这一点。通常，你可能为每个操作系统操作系统设置一个分区。`Linux` 包含一个不错的启动加载程序（在基于 `Intel` 的系统上称为 `SILO`，尽管 `Alpha` 上有类似的产物称为 `MILO`，在 `Sparc` 上也称为 `SILO`），它允许你在开机时指定想要启动的操作系统，并默认在超时后启动你最喜欢的操作系统（可能是 `Linux`，对吧？）。

你应该根据自己的需求对磁盘（或磁盘）进行分区。我在 `Intel`、`Alpha` 和 `Sparc` 平台上的经验是，对于一个功能相当丰富的系统，执行相当多的任务（作为家中的桌面系统或工作中的 Internet 服务器），我发现以下空间近似值对于确定分区大小非常有效。

给定：

一个为 `X Mb/Gb` 的磁盘（例如 `2 Gb`）

（或总计 `X Mb/Gb` 的多个磁盘）

计算：

| 分区 | 建议大小 |
| :--- | :--- |
| `(swap)` | 约内存 大小（例如 `64 Mb`） |
| `/root` | 约可用空间的 10%（例如 `200 Mb`） |
| `/home` | 约可用空间的 20%（例如 `400 Mb`） |



| `/usr` | 剩余空间（例如 72 Mb） |
| `/var` | （可选 - 下文） |

# 第 5 章 配置 X Window 系统

X Window 系统，又称 `X`（许多人经常且错误地称为 `X-Windows`）是一个运行在 Linux 之上的 GUI。与 Microsoft Windows 不同，X Window 系统可以有许多不同的外观和运行方式。它可以是原始的也可以是非常先进的，外观可以美观也可以丑陋，运行可以流畅快速也可以缓慢（这些都是主观属性，引发的用户间争论就像 `Linux 对阵 Microsoft NT` 辩论一样）。

让 X 正常工作的难度从简单到令人抓狂的复杂不等！这是 Linux 新手用户的常见抱怨，我自己也与配置设置斗争过无数次，我对此完全感同。幸运的是，在较新的 Linux 发行版中，这种配置变得越来越简单和自动化了。事实上，如果你使用的是 Red Hat 6.1，你可能不需要担心这个问题。

虽然在大多数情况下 X 可以自动配置，但仍有例外；我在这里指出这些例外。

## 5.1. 让 X 工作

让 X 工作有两种主要方法，第一种是使用配置文件，第二种是使用命令行。第一种更灵活，因为它允许为不同的会话指定不同的配置。第二种方法简单但灵活性较低。

如果你想使用第一种，你需要编辑 `/etc/X11/xinitrc` 文件。该文件包含 X 服务器的设置，如分辨率、色彩深度以及要使用的窗口管理器。

## 5.2. 使用 X 桌面管理器

如果你愿意，可以使用 X 桌面管理器 (`xdm`) 在启动时自动启动 X Window 系统。这让你的 Linux 系统始终运行在 X 下（尽管你可以通过 `<Ctrl><Alt>-<F1>` 切换到常规控制台，需要时通过 `<Alt><F7>` 回到 GUI）。

要启用 `xdm`，只需编辑 `/etc/initabb` 文件并修改包含如下内容的行：

```
id:5:
initdefault:
```

上述更改将使 Linux 在系统启动时切换到级别 5；此运行默认将启动 `xdm`。

```
x:respawn:/usr/bin/X11/xdm -nodemon
```

如果你启用了 `xdm` 并且希望使用比默认值 8 更高的 `bpp` 值（且你的显卡和显示器支持它），你需要按照如下方式修改 `etc/X11/xdm/Xservers` 文件：

```
:0 local /usr/X1R6/bin/X -bpp 24
```

上述更改将以每像素 24 位（24 bits）启动 `xdm`。

你可能还想编辑 `etc/X11/xdm/Xsetup_0` 文件，并用 `#` 字符注释掉以 `xbanner` 开头的行，如下所示：

```
#/usr/X1R6/bin/xbanner
```

这将防止默认的 `xdm` 横幅屏在 KDE 会话之间进行分屏显示时出现。我知道，这只是为了美观，但是……

> 提示：有时你可能会发现需要切换回控制台（例如，某些游戏在控制台运行，但在 X 下不运行）。有两种方法可以实现。要临时从 X 切换到控制台，按下 `<Alt><F1>`；要切换回 X，按下 `<Alt><F7>`。或者，如果你想完全终止 X（从而释放你的可用内存），你可以以 `root` 身份输入 `"/sbin/telinit 3"` 来切换系统运行级别；这告诉 XDM 终止。要切换回，输入 `"/sbin/telinit 5"`

## 5.3. 改进 X 下的字体外观

坦率地说，X 从来不是以具有特别吸引力的字体而闻名的。事实上，许多人接受了这样观点：拥有丑陋、难看的字体是 X 系统中一种不幸的命运。

幸运的是，在 X 下可以显著改善字体的外观并增加你可以使用的字体数量。事实上，如果你有一份 Windows 系统，你甚至可以从该平台复制 TrueType 字体并在 X 下使用它们！这种字体支持是通过使用如 `xfsft` 或 `xfs` 这样的字体服务器来实现的。



红帽 6.1 现在内置了对 `xfs` 的支持，并开箱即提供了吸引人的字体支持。因此，如果你正在使用这个版本的 Linux，你可以对现状感到满意。不过，你仍然可以采取一些措施来进一步改进，如果你有 TrueType 字体，也可以使用它们。

要启用 TrueType 字体支持，创建一个目录（例如 `"/usr/local/share/ttfonts"`），并从你的 Windows 系统（可以在 `"c:\windows\fonts"` 目录中找到）复制任何或所有字体文件到新目录。

> 提示：如果你没有可用的 TrueType 字体，可以直接从微软官网下载：http://www.microsoft.com/typography/fontpack/default.htm。

要使用这些字体，在新的 `ttfonts` 目录中，输入以下命令（作为 root）：

```
ttmkfdir -o fonts.scale
mkfontdir
```

接下来，编辑 `"/etc/X11/fs/config"` 文件，将你的新字体目录添加到现有目录列表中。此外，将默认点大小（`point-size`）从 120 改为 140，这将为你提供更大、更易读的字体。

最后，退出 X（如果你还没有退出），并按照如下方式重启你的 `xfs` 服务：

`/etc/rc/init.d/xfs restart`

最后，重启 X 并享受你光丽的新字体！

关于改进 X 下字体支持的更多详细信息，有一个非常优秀的资源名为 "XFree86 Font Deugification Mini HOW-TO"，地址为：http://www.frii.com/~meldroc/Font-Deugification.html。

## 5.4. 为 X 选择窗口管理器

现在，你应该决定一个窗口管理器。X 窗口系统只是允许在你的系统硬件上显示图形的环境；窗口管理器负责 X 的外观以及它如何与你和你的应用程序交互。

红帽 Linux 发行版包含了几个窗口管理器，包括 `fwwm`, `olvm`, `twm`, `AfterStep` 等。当你第一次启动 X 时，可能会看到的默认窗口管理器是 `fwm95`，这是一个类似于 Win95 的环境。

个人而言，我觉得通常提供的选项与我自己的任务不符，我推荐 `GNOME` 或 `KDE`（或者两者都用！），它们的安装方法将在接下来两个章节中介绍。

## 6.1 Root 账户



“root”账户是 Unix 系统上权限最高的账户。该账户让你能够执行系统管理的所有方面工作，包括添加账户、更改用户密码、检查日志文件、安装软件等。

在使用此账户时，尽可能保持谨慎至关重要。“root”账户没有施加任何安全限制。这意味着你可以毫不费力地执行管理职责。然而，系统假设你清楚自己在做什么，并且会完全按照你的要求执行操作——不带任何提问。因此，很容易因为输错命令而删掉关键文件。

当你以“root”身份登录时，shell 提示符的最后一个字符会显示为‘#’（如果你正在使用 `bash`）。这是为了向你警告该账户的绝对权力。

经验法则是，除非绝对必要，否则永远不要以“root”身份登录。在输入“root”类型的命令时要小心，并在按下回车键之前双重检查。一旦完成了你登录的任务，立即注销“root”账户。

## 6.6. Linux 密码与 Shadow 文件格式

传统的 Unix 系统将用户账户信息（包括单向加密密码）存储在名为 `/etc/passwd` 的文本文件中。许多工具（如 `ls`）需要使用该文件来显示文件所有权，通过匹配用户 ID（UID）与用户名，因此该文件必须是全用户可读的。因此，这在某种程度上存在安全风险。

另一种存储账户信息的方法是我一直使用的，即影子密码格式（shadow password format）。与传统方法相比，这种方法以兼容格式将账户信息存储在 `/etc/passwd` 文件中。然而，密码是以单个“x”字符的形式存储的（即不存储在此文件中）。第二个名为 `/etc/shadow` 的文件包含了加密后的密码以及账户或密码过期值等其他信息。`/etc/shadow` 文件仅允许 `root` 账户读取，因此安全风险较低。

虽然某些其他 Linux 发行版强制你安装 Shadow Password Suite 才能使用影子格式，但 Red Hat 使其变得简单。要在两种格式之间切换，请输入（作为 root 用户）：

```
/usr/sbin/pwconv 转换为 shadow 格式
/usr/sbin/pwunconv 转换回传统格式
```

使用影子密码后，`/etc/passwd` 文件包含账户信息，如下所示：

```
smithj:x:561:561:Joe Smith:/home/smithj:/bin/bash
```

`passwd` 条目中的每个字段由冒号（`:`）分隔，内容如下：

- 用户名，最多 8 个字符。区分大小写，通常全小写。

- 密码字段中的“x”。密码存储在 `/etc/shadow` 文件中。

- 数字用户 ID (`UID`)。由 `adduser` 脚本分配。Unix 使用此文件以及下的组 ID (`GID`) 来识别哪些文件属于该用户。

- 数字组 ID (`GID`)。Red Hat 以一种相当独特的方式使用组 ID 来增强文件安全。通常组 ID 将与用户 ID 匹配。

- 用户全名。我不确定此字段的最大长度是多少，但请尽量保持合理范围（30 个字符以内）。

- 用户家目录。通常为 `/home/username`（例如 `/home/smithj`）。所有用户的个人文件、网页、邮件转发等将存储在此处。

- 用户的“shell 账户”。通常设置为 `/bin/bash` 以提供对 `bash` shell（我个人最喜欢的 shell）的访问。

也许你并不想为你的用户提供 shell 账户。例如，你可以创建一个名为 `/bin/sorry` 的脚本文件，它可以显示某种错误信息并注销用户，然后将此脚本设置为他们的默认 shell。

> 注意：如果账户需要提供“FTP”传输以更新网页等操作，则 shell 账户需要设置为 `"/bin/bash"` —— 并且需要在用户的家目录中设置特殊权限以防止通过 shell 登录。有关此的详情请参见第 7.1 节。

`/etc/shadow` 文件包含用户的密码和账户过期信息，如下所示：

```
smithj:Ep6mckrOLCH::10063:0:99999:7:::
```

与 `passwd` 文件一样，`shadow` 文件中的每个字段也由冒号（`:`）分隔，内容如下：

- 用户名，最多 8 个字符。区分大小写，通常全小写。与 `/etc/passwd` 文件中的用户名直接匹配。

- 13 位加密密码。空项（例如 `::`）表示登录不需要密码（通常是个坏主意），`*` 条目（例如 `**`）表示账户已禁用。

- 自上次更改密码以来的天数（自 1970 年 1 月 1 日起）。

- 密码可以更改的天数（0 表示可以随时更改）。

- 密码可以更改的天数（0 表示可以随时更改）。

- 密码必须更改的天数（99999 表示永不过期）。

- 密码过期前的天数（7 表示提前一周警告）。

- 账户锁定前的闲闲天数（自 1970 年 1 月 1 日起）。

- 自上次更改密码以来的天数（自 1970 年 1 月 1 日起）。

- 预留字段。

要关闭系统，输入 `shutdown -h now`。这将停止系统并关机。如果你希望改为重启，请使用 `shutdown -r now`。你也可以调度未来的关机，例如 `shutdown -h +10` 将在 10 分后关闭系统。要取消已调度的关机，请使用 `shutdown -c`。

## 7.2. 域名服务器 (DNS) 配置与管理

在我们的工作单位，我们使用 Linux 作为 DNS 服务器。它的性能异常出色本节将介绍如何使用 Red Hat 发行版自带的 BIND 8.x 软件包为这些服务配置 DNS 表。

注意：Red Hat 5.1 及更早版本使用的是 BIND 4.x 软件包，其配置文件格式略有不同。BIND 8.x 提供的功能比 BIND 4.x 更多，由于 4.x 不再进行开发，你应该考虑将 BIND 包升级到最新版本。只需安装 BIND RPM 包（详细信息请参阅第 10.1 节使用 RPM 工具的说明），然后将你的配置文件转换为新格式即可。

幸运的是，将现有的 BIND 4.x 配置转换为符合 BIND 8.x 标准的文件非常简单！在 BIND 提供的文档中（例如，针对 BIND 8.1.2 的 `/usr/doc/bind-8.1.2/`），存在名为 `named-bootconf.pl` 的文件，这是一个可执行的 Perl 程序。假设你的系统中安装了 Perl，你可以使用该程序转换配置文件。操作时，请执行以下命令（以 root 身份）：

```bash
cd /usr/doc/bind-8.1.2/
./named-bootconf.pl < /etc/named.boot > /etc/named.conf
mv /etc/named.boot /etc/named.boot-obsolete
```

现在你应该有一个 `etc/named.conf` 文件，它看起来应该是 BIND 8.x 的“开箱即用”状态。现有的 DNS 表可以在新版本的 BIND 中直接工作，因为表的格式保持不变。

在 Linux 下配置 DNS 服务涉及以下步骤：

- 1. 要启用 DNS 服务，`etc/host.conf` 文件应如下所示：

```conf
# 首先通过 /etc/hosts 查找名称，然后按照 DNS 查询顺序查找
hosts, bind
# 我们没有具有多个地址的机器。检查是否存在 IP 地址欺骗
nospoof on
# 如果有人尝试欺骗则发出警告
alert on
```

额外的欺骗检测会给 DNS 查找带来轻微的性能影响（尽管忽略不计），所以如果你不太担心这一点，你可能希望禁用 `nospoof` 和 `alert` 条目。

- 2. 根据需要配置 `/etc/hosts` 文件。通常这里不需要包含任何内容，但为了提高性能，你可以添加任何你访问的主机（例如本地服务器），以避免对它们进行 DNS 查询。

- 3. `/etc/named.conf` 文件应根据下面的示例进行配置，以指向你的 DNS 表。

> （注意：所示的 IP 地址仅为示例，必须替换为你自己的类类地址！）

```conf
options {
// DNS 表位于 /var/named 目录下 "/var/named"

// 将任何未解析的请求转发到我们 ISP 的名称服务器
// （这只是示例 IP 地址 - 请勿使用！）
forwarders {
123.12.40.17;
}
/*
* 如果你与想要通信的名称服务器之间存在防火墙，
* 你可能需要取消注释下面的 query-source
* 指令。之前的 BIND 版本始终使用端口 53
* 进行提问，但 BIND 8.1 默认使用非特权
* 端口。
*/
// query-source address * port 53;
};

// 启用缓存并加载根服务器区域 "named.root" {
type hint;
file "";
};

// 所有 DNS 信息存储在 /var/named/mydomain_name.db 中
// （例如，如果 mydomain.name = foobar.com 则使用 foobar.db）
zone "mydomain.name" {
type master;
file "mydomain_name.db";
allow-transfer { 123.12.41.0 };
};

//  123.12.41.*, .42.*, .43.*, .44.* C 类的反向查找
// （这些是示例 C 类 - 请勿使用！）
zone "41.12.123.in-addr.arpa" {
type master;
file "123_12.rev";
allow-transfer { 123.12.41.0 };
};

// 126.27.18.*, .19.*, .20.* C 类的反向查找
// （这些是示例 C 类 - 请勿使用！）
zone "18.27.126.in-addr.arpa" {
type master;
file "126_27.rev";
allow-transfer { 123.12.41.0 };
};
```

提示：请注意上面的 `allow-transfer` 选项，它将区域传输限制给指定的 IP 地址。在我们的示例中，我们允许位于 123.12.41.0 的主机（可能是我们域中的一个从用 DNS 服务器）请求传输。如果你省略了此项，互联网上的任何人都将请求此类传输。由于这些信息经常被垃圾邮件发送者和欺骗者利用，我强烈建议你将区域传输限制在从用 DNS 服务器上，或者使用环回地址 `127.0.0.1`。

- 4. 你现在可以像 `/etc/named.conf` 文件所示，在 `/var/named/` 目录中设置你的 DNS 表。首次配置数据库文件是一项巨大的工程，并且超出了本文的范围。有几份指南应当参考。然而，下面提供了几个示例。

## 7.6. 网络文件系统 (NFS) 服务

Linux 可以作为网络文件系统协议提供文件系统的客户端和服务器，该协议是 Unix 系统之间提供文件系统挂载的标准。

为了使用 NFS，通过修改 `/etc/exports` 文件来配置共享。以下是一些示例条目：

```
/archive spock.mydomain.name(ro)
/archive2 spock.mydomain.name(ro)
/mnt/cdrom other.domain(ro)
/archive2 10.23.14.8(ro, insecure)
```

前两行允许主机 `spock.mydomain.name` 访问 `/archive` 以及 `/archive2` 目录。这些共享以只读 `(ro)` 选项可用。出于安全考虑，建议对所有的 NFS 共享都这样做。

第三行允许 `domain.name` 域名空间中的任何主机访问 CD-ROM 驱动器。当然，必须先将 CD-ROM 设备挂载到 `/mnt/cdrom`。

> 注意：使用 `(ro)` 选项标记此设备只读似乎有些多余，但这样做可以防止在 CD-ROM 设备未挂载时恶意分子向真实文件系统写入。

在修改 `/etc/exports` 文件后，你需要重启 NFS 守护进程。执行此操作输入：

```
/etc/rc.d/init.d/nfs restart
```

你还可以使用 `Linuxconf` 工具中包含的“网络配置”工具配置你的 NFS 挂载点。有关 `Linuxconf` 的更多信息，参见第 7.7 节。

关于 NFS 的更多信息可以在 http://metalab.unc.edu/LDP/HOWTO/NFS-HOWTO.html 的“NFS-HOWTO”指南中找到，也可以在 `nfsd` 和 `exports` 的手页中找到。

## 第 8 章 备份与恢复流程

定期执行备份被认为是负责任的系统管理员的首要任务之一。尽管 Linux 是一个极其可靠的操作系统，但故障仍然发生，而且可能将会发生。它们可能是由硬件故障、停电或其他不可见的问题引起的。

更有可能是由人为错误引起的问题，导致对关键文件发生非预期的更改，甚至是删除。如果你在你的系统上托管服务，你肯定会被要求恢复一两个由于不小心删除的文件。

如果你执行定期备份，最好是每天一次（至少对于经常更新的用户文件），你可能希望这样可以减少这种情况发生的可能性，并增加你从此类文件丢失中恢复的能力。

进行备份最安全的方法是将它们记录在单独的介质上，例如磁带、移动式驱动器、可写 CD 等，然后将你的备份集存储在与 Linux 系统不同的位置。有时这可能并不切实际——也许你没有一个可以存放备份带的防火金库！或者你根本就无法访问此类外部备份系统。尽管如此，仍然可以进行备份，尽管规模是有限的。

在我的工作单位，我对几台 Linux 服务器进行备份。根据情况，其中一些备份集被写入磁带，另一些则通过网络写入单独的服务器，例如在 `archive/` 文件系统中，通过自动的 `cron` 任务执行（可能服务器位于远程位置，每天去一次进行磁带备份是不切实际或不可能的）。

在家里，我没有外部备份系统，也没有大量的可用磁盘空间来写入备份镜像。因此，我仅备份 `/home/` 下的用户文件以及 `/etc/` 中的一些自定义配置文件，并将备份集写入单独的磁盘分区。

## 8.1. 服务器备份流程

使用 Linux 执行备份有多种方法。这些方法包括每个 Linux 发行版都附带的命令行工具，如 `dd`、`dump`、`cpio` 以及 `tar`。还有可用的基于文本的实用程序，如 `Amanda` 和 `Taper`，后者旨在为备份和恢复流程添加更用户友好的界面。此外也有基于 GUI 的工具，例如 `BRU` 和 `PerfectBackup+`。最后，还有商业备份工具可用。任何这些备份解决方案都能为你的贵贵数据提供保护。

一些可用工具的简要列表（包括在哪里获取）可以在“Linux 应用与工具页面”找到：http://www.xnet.com/~blatura/linapp2.html#back。在决定备份解决方案时，你需要考虑以下因素：

- 可移植性 - 备份的可移植性（即在一个 Linux 发行版上备份并在另一个上恢复，例如从 Solaris 到 Red Hat Linux）对你重要吗？如果是，你可能需要选择命令行工具（例如 `dd`、`dump`、`cpio` 或 `tar`），因为你可以确信这些工具在任何 *nix 系统上都是用的。
- 无值守或自动备份 - 自动化备份以便定期执行而无需人工干预对你重要吗？如果是，你需要选择支持这种备份方案的工具和备份介质。
- 用户友好性 - 用户友好的界面对你重要吗？如果是，你可能希望选择一个提供文本或 GUI 界面的工具。商业工具可能还提供更简单的界面以及额外的的技术支持。
- 远程备份 - 从远程机器启动备份和恢复对你重要吗？如果是，你可能希望选择命令行工具或基于文本的实用程序，而不是 GUI 工具（除非你有足够快的网络连接和运行 X 会话的能力）。
- 网络备份 - 在网络主机之间执行备份和恢复对你重要吗？如果是，你可能希望选择某些支持网络访问备份设备的命令行工具（如 `tar`），或专门的工具（如 `Amanda`）或某些商业工具。

### 8.1.1. 使用 tar 备份

如果你决定使用 `tar` 作为你的备份解决方案，你可能应该花时间了解各种选项；输入 `man tar`。

以下命令将对你的整个系统进行备份，但除了 `/proc/` 文件系统、`/mnt/` 下挂载的文件以及大型缓存文件（这些没有必要备份）：

```
tar -zcpvf /archive/full-backup `date '+%d-%B-%Y'`.tar.gz -directory / -exclude=mnt -exclude=proc -exclude=var/spool
```

助记表示法通过前缀一个 `-` 字符来识别，而全称则以两个此类字符为前缀。再次强调，`man` 页面仅供使用 `tar` 时提供信息参考。

另一个示例，这次仅将指定的文件系统（与示例中演示的写入所有文件系统相反）写入 SCSI 驱动器：

```bash
tar -cvpf /dev/nst0 -label=Backup set created on '$(date '+%d-%B-%Y')' \
-directory / \
exclude=var/spool/
etc home usr/local var/spool
```

一旦一切设置完毕，你可以通过输入以下命令手动启动 Netatalk 服务：

```
/etc/rc.d/init.d/stalk start own
```

（服务应该在启动时自动启动）。

有关更多信息可以从 Samba 主页获取：http://samba.anu.edu.au/samba/

此外，非常有用的配置信息可以在 Netatalk HOWTO 中找到，地址为 http://thehamptons.anders/.



在上述命令中，注意没有使用“`z`”（压缩）选项。我强烈建议不要将压缩数据写入磁带，因为如果磁带某部分的数据损坏，你将丢失整个备份集！然而，如果磁带归档的某些部分损坏，存储为未压缩格式的归文件对于未受影响的文件具有很高的恢复率。

由于磁带驱动器是字符设备，无法指定实际的文件名。因此，作为 `tar` 参数的文件名仅是设备名称 `"/dev/nst0"`，它是 SCSI 总线上的第一个磁带设备。

> 注意：`"/dev/nst0"` 设备在备份集写入后不会重新倒带；因此，可以在一个磁带上写入多个备份集。（你也可以将设备称为 `"/dev/st0"`，在这种情况下，磁带在备份集写入后会自动倒带。）

当我们无法为备份集指定文件名时，可以使用 `"-label"` 选项将有关备份集的信息写入归档文件本身。

最后，只有包含在 `"/etc/"`、`"/home/"`、`"/usr/local/"`、和 `"/var/spool/"` 中的文件（Squid 的缓存数据文件除外）会被写入磁带。

在操作磁带时，你可以使用以下命令倒带并弹出磁带：

```bash
mt -f /dev/nst0 rewind
mt -f /dev/nst0 offline
```

> 提示：你会发现 `tar` 在创建归档文件时会剥离开头的 `"/"`（斜杠）字符。这是 `tar` 的默认操作模式，旨在防止你在尝试恢复时错误地恢复了错误的文件，用这些文件的旧版本覆盖关键文件。如果你不喜欢这种行为（记住，这是一个功能！），可以为 `tar` 指定 `"absolute-paths"` 选项，这将保留开头的斜杠。但是，我不建议这样做，因为这是危险的！

### 8.2.1. 使用“tar”恢复

以下命令将从 `full-backup-09-October-1999.tar.gz` 归档恢复所有文件：

```bash
tar -zxvpf /archive/full-backup-09-October-1999.tar.gz
```

上述命令提取压缩归档中的所有文件，并保留原始所有权权限。`x` 选项代表提取。其他选项在第 8.1 节中描述。这取决于备份是如何创建的。因此，我强烈建议先用 `t`（类型）选项测试你的 `tar` 命令，当你完全确定命令会按照你的预期执行时，再将 `t` 替换为 `x`（提取）。

如果你不需要恢复归档中的所有文件，可以指定想要恢复的一个或多个文件，如下例所示：

```bash
tar -zxvpf /archive/full-backup-09-October-1999.tar.gz \
    etc/profile usr/local/bin/tolower
```

上述命令从示例归档中恢复 `etc/profile` 和 `usr/local/bin/tolower` 文件。

在上面的示例中，归包中包含的所有文件都按文件名列出。输出结果通过管道交给 `grep` 命令（使用 `grep` 的 `i` 选项来忽略大小写），显示目录名或路径名中包含 `profile` 的任何文件。一旦你确定了想要恢复的精确文件名，就可以在常规 `tar` 命令表达式中指定该文件进行解压。

如第 8.1 节所述，在创建归包文件时，`tar` 将删除文件名开头的 `"/"`（斜杠）字符。这意味着文件可能不再存在于备份时的相同位置。因此，请切换到 `"/"` 根目录，或使用 `-directory` 选项。

> 注意：更安全的解决方案是在不同的目录（例如，你的家目录）下恢复所需的文件，然后以后比较、移动或更新这些文件到它们的原始位置。

### 8.2.2. 使用“KDat”进行恢复

要从由 KDat 创建的备份集中恢复一个或多个文件，请将备份磁带插入驱动器，从“文件”菜单选项选择“挂载磁带”（Mount Tape）（或左键点击像磁带的图标）。

KDat 将尝试从磁带上读取头信息，如果成功，它将尝试找到与磁带头找到的标识匹配的磁带索引。该磁带索引存储在你的硬盘上，是为每个由 KDat 格式化的备份磁带创建的唯一文件，并在你每次执行备份时都会更新。

## 8.3. Cisco 路由器配置备份

在工作场所，我们有一个连接远程位置的 WAN。这些远程位置通过 ISDN 或某些情况下的 Centrax 数据中心连接 Cisco 路由器，以提供 Internet 和 WAN 连接。Cisco 路由器产品允许在网络服务器通过 TFTP（简单文件传输协议）读取和写入配置文件。每当路由器配置发生更改时，在 Linux 服务器上保存配置文件都是关重要的，这样就可以维持备份。

请注意，Red Hat 默认禁用了 TFTP 服务，因为如果配置不当，可能会成为一个真正的安全漏洞。TFTP 守护允许任何人在不进行身份验证的情况下读取和写入文件。我个人的设置方法是创建一个由 root 拥有的 `"/tftpboot/"` 目录，然后修改 `"/etc/inetd.conf"` 文件中现有的配置行以修复位置：

```
tftpd dgram wait root /usr/sbin/tcp in.tftpd /tftp-boot
```

> 注意：在上述行末尾添加 `/tftpboot` 路径专门指示了 TFTP 守护允许访问文件的位置。虽然实际上可以省略此部分并允许 TFTP 访问系统上的任何地方，但由于 TFTP 被认为具有安全风险，这可能是一个非常糟糕的主意。

一旦你启用了 TFTP 服务，别忘记输入：

```
killall -HUP inetd
```

上述命令重启 INETD 守护进程以识别你对 `inetd.conf` 文件所做的任何更改。



创建路由器配置文件的备份涉及 3 个步骤：对现有文件设置权限（或创建一个新文件）以允许写入、写入备份文件，然后重置权限以限制对文件的访问。以下是路由器备份会话的示例：

```
root@host:# chmod 644 config.file
root@host:# cp config.file config.bak
root@host:# chmod 600 config.bak
```

## 第 10 章 升级 Linux 及其他应用程序

### 10.1. 使用 Red Hat 包管理器 (RPM)

Red Hat 发行版 Linux（包括内核、库和应用程序）是以 RPM 文件的形式提供的。RPM 文件也称为“包”，是软件分发的一种方式，可以方便地安装、升级、查询和删除。RPM 文件包含包的名称、版本、其他文件依赖信息（如果适用）、平台（如 Intel 或 Alpha 等）以及默认安装位置等信息。

RPM 工具最初由 Red Hat 开发，并作为开源产品提供，这在 Linux 社区中很常见。其他开发者接手了它并添加了额外功能。RPM 文件打包方法已变得流行，不仅用于 Red Hat 的发行版，也用于其他某些发行版。

流行的 Linux 应用程序几乎总是以 RPM 文件的形式发布，而且通常速度很快。然而，在 Unix 中，软件包分发的事实上标准仍然是所谓的“tar 包（tarballs）”。tar 包仅仅是可以用“`tar`” 工具读取的文件。从 tar 安装比使用 RPM 要费琐得多。那么，为什么人们会这样做呢？遗憾的是，有时开发者需要几周时间将软件包的最新版本转换为 RPM（许多开发者首先以 tar 包的形式发布）。

如果你开始使用 tar 安装或升级你的系统，你的 RPM 数据库将变得过时且不一致。这并不是什么大问题（当我使用 Slackware 时，我完全使用 tar —— 因为没有其他选择 —— 并没有感到太不适），但只要可能，我都会尝试耐心等待直到 RPM 可用，或者可能向该包的开发者提交建议。（你也可以构建自己的 RPM 文件并分发给他人，这对于没有能力或时间制作此类文件的开发者有时是有帮助的。）

检查某个软件是否有 RPM 格式的一个好地方是位于 `http://refus.w3.org/linux/RPM/` 上的 RPM 仓库。该仓库提供了索引分类，这对于定位特定的 RPM 文件很有帮助，并包含了指向数千个文件的指针。

若要查询软件包，请使用 `rpm -q pkg-name`（例如 `rpm -q pkg-name -q pine`）。RPM 将告诉你是已经安装了哪个版本的包，或者该包尚未安装。

假设包已经安装，并且版本比你下载的包要旧（这应该是肯定的），那么你就可以通过 `rpm -Uvh pkg-name` 应用更新。如果一切顺利，该包将自动安装并立即可以可以使用。如果不顺利，RPM 将给你一个非常充分的理由（例如，可能需要先升级某个支持包）。这可能需要一点思考，但这类问题很容易解决。

另一方面，如果包尚未安装，而你决定安装它，请输入 `rpm -ivh pkg-name`。如果有任何所需的支持包，RPM 会告诉你。

有时，你可能想安装一个仅以源码格式提供的包。事实上，除非你使用 tar 安装或升级系统，否则你的 RPM 数据库将变得过时且不一致。这并不是什么大问题（当我使用 Slackware 时，我完全使用 tar —— 因为没有其他选择 —— 并没有感到太不适），但只要可能，我都会尝试耐心等待直到 RPM 可用，或者可能向该包的开发者提交建议。

更糟糕的是，无意中覆盖了现有文件。

一旦 tar 包（tarball）安装到相应的目录，你几乎肯定会在新安装的文件中找到一个“README”或“INSTALL”文件，其中包含有关如何准备软件软件包以供使用的进一步说明。你可能需要输入类似于下面示例的命令：

```
./configure
make
make install
```

上述命令将配置软件，以确保你的系统具有必要的功能和库来成功编译该软件包，将所有源文件编译为可执行的二进制文件，然后将二进制文件和任何支持文件安装到适当的位置。当然，你需要遵循的实际步骤可能会随不同的软件包而异，因此你应该仔细阅读每份文档。

再次，除非绝对必要，否则我真的建议避免使用 tar 包，如果可以的话坚持使用 RPM。

## 10.5. 升级 Red Hat 标准内核

升级内核最简单的方法是使用 Red Hat 提供的标准包。这种方法非常简单且几乎没有风险。只需以 root 身份执行以下命令序列：

## 10.7 迁移到 2.2.x 内核

Linux 内核 2.2.0 于 1999 年 1 月 25 日发布，它带来了许多新功能、性能增强和硬件支持。任何 Linux 系统都可以以与 10.4 节描述相似的方式升级到这些新内核。

本节将描述如何将您的 RedHat 系统升级到新内核。由于 Red Hat Linux 6.0 及更高版本已默认配备新内核和支持包，因此本节仅对那些仍在使用旧版本（如 5.2）的用户有用。一旦我认为大多数用户已迁移到 6.0 及以后，我可能会从未来的文档中删除本节。

> 警告！如果您决定升级旧系统以支持新内核，请注意由于涉及大量的软件包升级，可能会发生严重的错误。一如既常，请准备好最新的备份以防万一。如果您没有使用 RPM 升级文件以及编译内核的经验，也许您想尝试：

```bash
mount root=/dev/h
```

上述命令假设您的“/”（根）分区位于 `/dev/hda`。Linux 应该能够正常启动（尽管由于您使用的是启动磁盘上的内核，某些服务或设备在此期间内可能无法正常工作），然后您可以恢复旧内核并重启。随后您可以尝试用不同的选项重新编译内核并再次尝试。

```
rpm -Uvh kernel-source*.rpm kernel-headers*.rpm
```

```
/sbin/chkconfig kernel off
/etc/rc.d/modulus stop
rpm -Uvh modulus*.rpm
```

现在你应该能够配置并安装你的（详情请参见第 10.6 节）。重启后，你可以再次启用内核模块：

```
/sbin/chkconfig kernel on
/etc/rc.d/modulus start
```

接下来，如果你的邮件服务器的主机名与其运行的实际物理主机不同，你可以在 `"/etc/sendmail.cw"` 文件中添加一个或多个别名。例如，如果你有一个名为“kirk.mydomain.name”的系统，它被设置为 `mydomain.name` 的邮件交换器，但你希望将格式为“user@mydomain.name”的邮件投递到“kirk”上的用户，那么只需按照如下方式添加此别名即可：

`mydomain.name`

最后，如果你需要限制某个域名（或子域）连接到你的 `sendmail` 服务，你可以编辑 `"/etc/mail/access"` 并添加域名信息以及限制类型。对于：

```
some.domain               REJECT
hax0r.another.domain    550 Contact site administrator (555) 555-1234.
```

上述示例将拒绝所有来自“some.domain”站点的电子邮件连接，并带有描述性消息地拒绝特定的机器名“hax0r.another.domain”。

在对此文件进行更改后，你需要更新 `"access.db"` 文件，然后按照如下方式重启 `sendmail`：

```
/usr/sbin/makemap hash /etc/mail/access.db < /etc/mail/access
/etc/rc.d/init.d/sendmail restart
```

> 提示：如果你担心邮件滥用问题，可以从“邮件滥用预防系统”（MAPS）项目获取有关处理此类滥用的非常有用的的信息；请参阅网页 http://www.mail-abuse.org/

如果你正在使用 Sendmail 8.9 或更高版本，该版本已经内置了 RBL 支持，但默认未启用。要启用此支持，请在你的 `sendmail.mc` 文件中添加以下内容：

```mc
# FEATURE (rbl)
```

然后，重新配置并重启 Sendmail 守护进程。

欲需更多详细信息，包括其他邮件传输代理的配置说明，请访问 http://www.mail-abuse.org/rbl/usage.html。

有时，某个域名可能会进入 RBL 列表，但你仍希望与其保持通信。也许与黑名单域名中的某些用户通信对你至关重要。在这种情况下，Sendmail 允许你覆盖这些域名以允许接收它们的邮件。只需按照上述方法编辑 `"/etc/mail/access"` 文件并提供相应的域名信息。例如：

```
blacklisted.domain    OK
```

不要忘记重建 `access.db` 文件（如上所述）！

如果你决定订阅 RBL，如果适用，通知你的邮件用户可能是一个明智的主意，这样如果他们不同意你的决定，就可以做出其他服务安排。

关于 Sendmail 的更多信息，请查看位于 http://www.sendmail.org/faq/ 的 FAQ 文档。

## 第 11 章：使用 Linux 进行企业计算

由于 Linux 以稳定和可靠赢得了良好誉，它被应用于企业和科学领域更多的任务关键型。

本章将讨论与企业级 Linux 用户最相关的问题，例如调优服务器以便在高负载下获得更好的性能，使用 RAID 技术保护数据安全，以及讨论跨服务器迁移的通用步骤。

### 11.1. 性能调优

（建设中。:- ）

随着存储需求的增加，有时有必要上线容量更大的驱动器。然而讽刺的是，根据概率法则，随着存储设备数量的增加，设备故障的可能性也随之增加。因此，一个带有单个硬盘的系统发生故障的可能性只有带有四个硬盘系统的 25%。[ 嗯，理论上来说，反正如此 - ]

幸运的是，此类故障可以通过优雅的方式处理，更重要的是可以在无需停机的情况下处理，这使用了“冗余磁盘阵列”（RAID）技术。

本节将描述安装、配置和设置 Mylex RAID 阵列，我不但对其性能和可靠性印象深刻，也对其提供的技术支持印象深刻。

在 Linux 下获取用 RAID 阵列的第一步是编译支持该驱动的自定义内核。对于960 的驱动程序可以从 Dandelion 页面下载：http://www.dandelion.com/。

在 Linux 下使你的 RAID 阵列可用的最后一步是使用 `fdisk` 工具创建分区。这与你在 IDE 或常规 SCSI 磁盘上的操作完全相同。

> 注意：DAC960 驱动程序最多支持 7 个分区。如果你需要更多，可以使用 RAID 配置（按 Alt 进入）。

一旦你能看到 RAID 阵列，就应该初始化任何所需的交换区。以下是在第三个分区上初始化交换区的示例：

```
/sbin/mkswap -c /dev/rd03
/sbin/swapon /dev/rd03
```

> 注意：上述 `mkswap` 命令中的 `-c` 选项会在创建文件系统时启用坏块检查。这会显著增加完成过程的时间，但执行此类检查可能是非常明智的主意。

对于你定义的任何交换区，你应该在 `etc/fstab` 文件中创建一个条目，以确保后续启动时使用该交换区。如下：

```
/dev/rd03 swap defaults 0 0
```

最后，一旦文件系统完成，你就可以创建挂点并将文件系统移动到阵列上。在生产环境中使用之前，对阵列进行几天测试可能是个主意。

欲需更多关于 Mylex AcceleID 控制器的信息，请访问 Mylex 网站。关于 RAID 的更多信息（包括软件和硬件的解决方案），请查看 Linux 高可用性网站 http://linas.org/raid.html。

### 11.3. 服务器迁移与可扩展性

凭借对多样化硬件的支持，以及良好的速度和可靠性，Linux 能够应对随需求增加而进行的扩展挑战。这可能包括为了更大的处理需求而迁移到 SMP（对称多处理）配置、RAID 0 到 5 层等。

偶尔，你可能会觉得你的 Linux 服务器已经超过了它所运行的硬件，或者需要进行主要的 Linux 版本升级，甚至移动到不同的 Linux 发行版。当然，这样做有两种方法。你要将服务器留在现有或升级的硬件上（在这种情况下，你只需关闭设备、备份数据、执行所需的修改，然后在需要时恢复数据），或者在更激进的情况下将服务器迁移到新硬件。

本节将重点关注后者的情况，即你实际上将各种服务从旧服务器迁移到新服务器。当然，有多种迁移策略，但本节将尝试提供一些大致的策略

您可以遵循以下指南，以确保您的迁移工作成功，并对用户产生最最小的干扰。

- 根据需要准备你的新服务器；安装并配置 Linux，以确保你的新硬件设备得到支持，并启用任何所需的守护进程和内核功能（如防火墙）。详情请参阅第 4 章以及第 10.6 节。



## 设置现有服务并准备迁移

- 设置你现有的服务（如 Apache 服务器、Samba 或 Netatalk 文件与打印服务），并使用测试数据运行至少几天，以确保一切运行正常。详情请参阅第 7.4 节和第 7.5 节。不要忘记确保你在 `/etc/` 目录下所做的任何更改或自定义脚本（包括 `/etc/rc.d/` 中的任何内容）也已根据需要在新服务器上完成。特别重要的一点是记得复制 `/etc/passwd`、`/etc/group` 以及（如果你使用 shadow 密码的话）`/etc/shadow` 中的用户账户信息！

- 关闭旧服务器上的服务，这样你的文件系统将看到最少的文件更新活动。显然，你不希望在向新服务器恢复数据时，用户还在旧服务器上上传网页和接收电子邮件！作为 root 用户，你可以使用以下命令关闭大部分服务：

```
killall httpd atalkd smbd nmbd sendmail ftpd
```

上述命令将关闭 Web 服务器、文件与打印服务以及电子邮件服务器。（你运行的服务可能比我上面列出的少或多。请检查你的进程列表并终止任何你认为适当的服务；详情请参阅第 9.2 节。）

你可能还想编辑旧服务器上的 `/etc/inet.conf` 文件，并使用 `#` 字符注释掉任何可能导致文件系统更新的服务（如 FTP、IMAP 和 POP3 服务）。然后，再次以 root 身份：

```
killall HUP inetd
```

上述命令将重新加载针对 Internet 服务的 TCP 封装器（安全封装），使得未来对你在 `/etc/inet.conf` 文件中禁用的任何服务的连接将不会被加载。

# 第 11 章 使用 Linux 进行企业级计算

现在你应该能够将数据从一个系统移动到另一个系统了。你可能已经为新服务器准备好了运行所需的所有内容，包括你想要安装但未随 Red Hat 发行版附带的任何额外软件。因此，你可能需要备份存储在 `/home/`、`/var/spool/` 以及可选文件系统（如可能的 `/archive/`）中的任何数据。这是一个使用 `tar` 工具制作数据压缩文件的示例命令：

```
cd /
tar zcvcp /tmp/backup_data.tar.gz -exclude=var/spool/ squid \
    home archive var/spool
```

上述命令将把你的 `/archive/`、`/home/` 和 `/var/spool/` 文件系统（或子目录，取决于你如何设置系统）备份以压缩格式写入名为 `/tmp/backup_data.tar.gz` 的文件中。确保你有足够的空间创建备份，或者将其写入其他地方！

> 提示：你可以使用 `du` 工具来帮助确定所需的空间。例如，要确定 `/archive/` 和 `/home/` 目录树的需求，

```
du -h -s /archive /home
```

请记住，上述命令将报告数据的实际大小，但如果你使用 `tar` 的 `z` 选项（如上所示）来压缩镜像文件，你的空间需求可能会少得多。请考虑 `du` 命令输出结果作为所需空间的最坏情况估计。

现在，你可以从 tar 文件将备份数据恢复到新服务器上。你可以直接通过 NFS 恢复（配置 NFS 的详情请参阅第 7.6 节），或简单地使用 FTP 传输并在本地解压。以下是一个恢复已备份文件的示例：

```
cd /
tar zxvpf /tmp/backup_data.tar.gz
```

- 接下来，如果有必要，交换你的 IP 地址，以便新服务器可以通过旧地址被访问。

- 最后，你可能希望关闭并重启服务器，以确保没有出现意外的错误信息。详情请参阅第 6.7 节。

完成后，请确保一切运行符合预期！如果不是，你始终可以重新启用在旧服务器上禁用的任何服务并重启它们，以便用户在你解决新服务器上的问题之前继续使用它（但请记住，如果你选择这样做，将需要重复上述步骤）。

## 保持服务器安全的核心措施

虽然对安全问题的详细讨论超出了本文的范围，但以下清单提供了一些你应该做的最重要的事情：

- 升级系统工具、应用程序和内核：入侵最常见的原因之一是没有保持系统更新。定期升级系统内核、工具和用程序可以确保你的系统不会充满存在已知漏洞的旧项目。关于保持系统更新的详情，请参阅第 4.9 节以及第 10.3 节。

- Shadow 密码：你应该使用 Shadow 密码；切换到这种格式非常简单！详情请参阅第 6.6 节。

- 明智密码管理：确保密码（特别是提供 shell 权限的用户密码）足够强大且经常更换。此外，如果你有多台服务器，不要对所有服务器使用相同的密码（否则，如果黑客通过发现的密码破解了一台服务器，他们就能破解所有服务器）。

- 使用安全 shell `ssh`：用 `ssh` 代替 `telnet`。`Telnet` 是安全的，原因有两个：第一，会话未加密，这意味着包括用户名和密码在内的一切都以明文传输。第二，开放的 `telnet` 端口是黑客尝试连接的首选位置之一。

> 注意：上述列出的 SSH RPM 文件是国际版本。如果您在美国在美国或加拿大，可以选择下载美国版本的软件包（其可能具有更强的加密算法）；这些软件包在版本号后面所使用的后缀是 `us` 而不是 `i`。根据美国法律，向美国或加拿大以外地区出口强加密产品是非法的。希望有一天，美国司法部的那些蠢货们最终能开开眼来，取消这一愚蠢的限制（红帽发行版 Red Hat 正因为这个原因没有在他们的发行版中包含 SSH，而我们都深陷其苦）。

您的 Windows 用户可能会因为无法再次连接到您的系统而义愤填膺，他们会很高兴地发现有几个免费的 Windows 版 SSH 客户端可用：

- `TeraTerm Pro` 客户端软件

http://hp.vector.co.jp/authors/VA002416/teraterm.html

- `TTSSH` 客户端软件

http://www.zip.com.au/~roca/download.html

- `Cryptlib` 客户端软件

http://www.doc.ic.ac.uk/~ci2/ssh

- `Putty` 客户端软件

http://www.chiark.greenend.org.uk/~sgatham/putty.html

> 注意：如果您决定切换到使用 `ssh`，请确保在所有的服务器上都安装并使用它。拥有五个安全的服务器和一个不安全的服务器是浪费时间，尤其是如果您愚蠢地对多个服务器使用同一个密码，情况更是如此。

- 限制对外部服务的访问：接下来，您应该编辑 `/etc/hosts.allow` 以及 `/etc/hosts.deny` 文件，以限制外部主机对服务的访问。这里是限制 `telnet` 和 `ftp` 访问的示例。首先是 `/etc/hosts.allow` 文件：

```
# hosts.allow

telnetd: 123.12.41, 126.27.18, .mydomain.name, .another.name
in.ftpd: 123.12.41, 126.27.18, .mydomain.name, .another.name
```

上述配置允许 IP C 类中所有 `123.12.41*` 和 `126.27.18*` 的主机，以及任何 `mydomain.name` 和 `another.name` 域内的主机建立 `telnet` 和 `ftp` 连接。

接下来，是 `/etc/hosts.deny` 文件：

```
# hosts.deny
telnetd: ALL
in.ftpd: ALL
```

- 关闭并卸载未使用的服务：编辑您的 `/etc/inetd.conf` 文件，并禁用（即使用 `#` 字符注释掉）任何不需要的服务（如果您按照上述建议使用 `ssh`，那么您可能希望禁用 `telnet` 服务）。完成后，以 root 身份输入 `/etc/rc.d/init.d/inet restart` 以带上更改重启 `inetd` 守护进程。

- 安装安全检测系统：考虑安装此类安全程序，例如 `Tripwire`（参见 http://www.tripwiresecurity.com/），它可以检测入侵行为；以及 `Abacus Sentry`（参见 http://www.psionic.com/abacus/），它可以帮助防止入侵。



尽职调查：保持您系统中的操作系统处于最新状态，进行随机的安全审计（这可以简单地检查密码文件中的可疑条目、检查进程列表，并检查日志文件中的可疑条目），对于保持系统安全大有裨益。此外，向相应部门报告任何入侵尝试——这可能是一件麻烦，特别是当您的系统在某周内遭受了多次此类攻击时，但此类报告可以确保通过惩罚威慑震慑黑客，同时也确保其他人的系统安全。

## 13.4. 附加文档指南

关于 Linux 及其应用的文档多得惊人。大部分内容可以在网上和你的本地书店找到，但你可能会发现，大量的有用文档已经可供使用，它们是作为红帽 Linux 安装过程的一部分被加载的。

当你试图弄清楚命令如何工作时，帮助手册（man pages）是必读的。例如，如果你正在尝试弄如何使用“tar”实用程序，可以输入 `man tar`，它将提供关于 tar 的详细描述，包括其所有的命令行选项。

你可以在 `/usr/doc/` 目录中找到更通用的信息。在这里，你会找到子目录，其中包含实用程序和命令的文档、常见问题 (FAQ) 文档，以及为各种主题提供良好说明的 HOWTO 文档，例如如何设置网络，或安装对日语的支持。

你还应该查看 `/usr/info/` 目录，其中包含实用程序、库以及如 emacs 等应用程序的教程。

最后，你应该访问红帽用户常见问题 (FAQ) 文档 http://www.pobox.com/-aturner/RedHat-FAQ/，其中包含了许多针对红帽发行版 Linux 的有帮助信息。
