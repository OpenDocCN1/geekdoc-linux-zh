# Installation Features

You may install Debian from floppies, CD-ROM, a hard drive partition containing the installation files, or by NFS. A minimal Debian 2.2 installation requires at least 12MB of memory and 65MB of hard disk, although in order to install X and the most commonly used packages, you would require just 1GB and would benefit greatly a memory increase to (If you have an unusually slim system, the Debian 2.1 can install in 4MB of RAM and 35MB of disk space). The Debian installation procedure does not try to anticipate your choices or even the most basic decisions. will not select which disks you wish to use which partitions on those disks will be used as the root partition or which will be used as swap. Debian installs a “base” system from its installation medium. When it reboots into this base system, which has just enough functionality to install any other packages you choose. The base system only has to support floppy and hard drives. From that point, you can choose which kernel modules to load during this initial phase of the installation.

Debian installs a highly modularized kernel, which means that most modules are available with the default kernel. This kernel includes SMP support, as of Debian 2.2, but it still works on single-CPU systems.

# Corel

Corel Linux (http://linux.corel.com) is the distribution from the company that sells WorldPerfect. Currently at version 1.2, which also goes by the moniker “Corel Second Edition,” this distribution is based on Debian but includes a more user-friendly installation routine and default desktop configuration. Corel aims its distribution to people with little or no Linux or Unix experience who want to use Linux as a desktop OS. It comes with fewer packages than most distributions, but they’re the packages that Corel believes are most important for desktop use.

In building on the Debian base, Corel has added user-friendly GUI configuration tools similar to the Linuxconf by Red Hat, Mandrake, and a few others. Unfortunately, the 1.2 release includes code that enfodes its way of doing in startup scripts. The result is that if you have a nonstandard system that requires customizations not easily handled through the GUI, you must dig into startup scripts to disable parts of the system that don’t need disabling with most other distributions. One of us did a test installation of Corel Linux 1.2 on a computer that used the System Commander loader, for instance, only to discover that Corel Linux disabled System Commander after every boot.
