# 406 Chapter 12 Serial Communications, Terminals, and Modems

To expand the default configuration to support terminals run over a serial port, it's necessary to add some further entries to /etc/initabb. To do so, follow these steps:

+   1. Install the mgetty package. On a Red Hat 7.0 system, the package name is mgetty-1.1.22-1i386.rpm, and is on the second CD-ROM.

> NOTE Different distributions use different getty programs by default. Red Hat's mingetty can't handle serial port traffic, but some default getty programs can handle the serial port, this step may not be necessary with all getty programs. If you use something other than getty, however, some of the following details differ; consider your getty program's documentation for details.

+   2. To add support terminal attached to /dev/tty50, follow the following line to /etc/initabb just after the existing mingetty lines:
S0:2345:respawn:/sbin/mgetty -s 57600 -r /dev/tty50

+   3. Type telinit Q to let Linux reexamine the /etc/initabb file and make appropriate changes—namely, to run mgetty.

You may need adjustments to step 2 for your particular needs. Specifically, step 2 specifies that the terminal runs at 57,600 bps (the -s 57600 parameter) and that it uses /dev/tty50. The -r parameter indicates that the connection is direct—that is, not via a modem. Modem logins, as described shortly, require a few changes to this configuration.

Once logged in a terminal, the user can run Linux text-mode programs, including administrative tools like Linuxconf (assuming the user has sufficient privileges, of course). Some programs, however, rely on text-positioning protocols. These protocols were originally used with particular models of dumb terminals, and are frequently named after those terminals. Examples include VT-100 and VT-220. In many cases, mgetty can determine the type of terminal that's connected. In other cases, you may need to do this by setting the TERM environment variable. For instance, if you're using a VT-100 terminal, you could use the following after logging:

```
$ export TERM=vt100
```

If you find your display strange things, type env | grep TERM to see what the system thinks the terminal type is, and adjust it as appropriate. Some dumb terminals emulate others, and most terminals emulate one or more popular dumb terminals.
