# Chapter 13 Printers and the Spooling Subsystem

This printcap file example contains the configuration for a directly connected Lexmark Optra 40, a remote HP LaserJet 4000, and a remote SMB/Windows Stylus Color 800. The first line assigns the local printer's name, in this case 1lp1p0|1lexmark. This is actually a specification for three names, each separated from the others by vertical bars (\). In this case, users can refer to the printer as 1lp, 1p0, or 1lexmark, with identical results. 1lp is the default for the first printer on systems. The next uncommon line sets the spooling directory for the printer to /var/spool/1pd/1lexmark. The line beginning with :mx sets the maximum file size in kilobytes; the 0 in our example sets it to unlimited. The next line sets up the printer to suppress the page header, when present information on who ran the print job, to making print jobs easier in a busy printing environment. The next line sets the printer device name to /dev/lp0. This device name is the printer's hardware device—the file to which NPR sends its output. The name may or not bear any resemblance to the print pool name defined earlier. The line beginning with :if provides the path to the file that contains the filter information for any print types defined for that printer. These options and more are documented in the printcap page.

The sample printcap file contains stanzas (sections) for two more printers. The 1lp|hp4000 entry is for a printer located on a hostname of tennesse, located on the same network as the local machine. The difference in this stanza is instead of 1lp, it contains an rm line, which specifies the machine to which the printer is connected; and an rp line specifying the queue name on that machine. This also has its own spool directory.

The 1lp|2lp entry is for an SMB/Windows 95/NT printer. The standard Red Hat format does not place information on SMB servers in the printcap file, instead, that information is located in the .config file in the spool directory. For an SMB printer, you must include a username and password for the host machine. For security reasons, the username should be the same as that user's account on the Linux machine. We'll discuss printing to a networked Windows printer later in the chapter.

After reading through the printcap file and printing anything left in the queue, the line printer daemon goes into a passive mode, waiting for requests to print files, reorder print jobs in the queue, or display the waiting print jobs. It uses the system calls listen and accept to determine whether any requests are made.

As mentioned above, the line printer daemon package includes other programs necessary for the printing functionality. These binaries perform specific functions, which we will look at next.
