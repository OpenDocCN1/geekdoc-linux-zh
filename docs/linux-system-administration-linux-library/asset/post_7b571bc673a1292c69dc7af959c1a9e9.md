## Conditional Expressions

Bash and other shells include functionality that allows evaluating a variable and using the results to determine how to proceed. For instance, you might want to check the $USER variable, which holds the current user's login name, to see if it is equal to vick1 before starting the script vickt_script. If the values are the same, the script starts; otherwise, it echoes an error message to the screen.

These tests are accomplished with statements containing conditional expressions. These conditional expressions may be used in conditional statements or loops.
Quite often a script will check whether a given file or variable exists before attempting to make use of it. This checking is done with one of the conditional expressions listed in Table 14.1.

Conditional expressions are typically used in the formation of an if, for, or while loop. For example, consider the -a option, which simply tests whether a file exists. If you want to determine whether the user who is logged in has a .bash_profile and execute that profile if it exists, you can use the following if statement:

```
if [ -a /home/$USER/.bash_profile ]
  then
    /home/$USER/.bash_profile
fi
```

Perhaps you want to execute a program once for each of a certain number of files. For instance, you need a simple script that will play all the .wav files existing in a given directory. The script would use a for loop as in Listing 14.2.

## Loops

### Listing 14.2 A Simple Script to Play Audio Files

```bash
#!/bin/bash
for d in `ls *.wav`; do play $d; done
```

![](img/4fb617eb648f87def380ef5d92052d01_492_0.png)

**WARNING** The characters preceding ls and following *.wav in the preceding example are back-quotes, also called back-ticks, which are usually located on the key Tab on the keyboard, along with the tilde (~) symbol. If you use single-quote characters (located next to the Enter key), the above script will not correctly.

The preceding example uses several features to accomplish its goal:

- *The ls *.wav command works just as it would when typed at a command prompt—it lists all the files that end in .wav. These are effectively expanded as input for the script.* 
- *The for in part of the script uses the expansion of the ls *.wav to initiate a loop that executes once per file. This loop structure is extremely important to many file-manipulation tasks. The variable $d receives the name of each file in turn, then the rest of the loop executes with variable set. On the next go, the second filename is assigned to d, and so on until all the files are exhausted.*

**WARNING** This loop syntax uses spaces to delineate files, so if a filename includes a space, the script will not be able to parse the files. For instance, if you have a file called Londo.wav, the script in 14.2 will try to play Londo Cats.wav, but chances are neither exist so the file won't be played.

- *The semicolons (;) separate individual commands on one line.*
- *The play command passes the name of any file (stored in the $d variable) to the play utility. This results in the desired effect, one file at a time.*
- *The command signals the end of the for loop.*

**NOTE** The play command is a front-end to the Linux Sound (sox) package and plays any sound to the default device.

On the business end, let's say that anyone who works on the Help desk is required to write a document each time, detailing the conversation and any work that was done in support of that call. This policy has been in place for a year now and the directory containing these files is fairly large. A lot of text is contained in these documents, you reason they will probably compress quite well. You want to add the extension .2001 to show the year in which the files were created. You might create something like Listing 14.3 to perform these tasks.

### Listing 14.3 A Script to Rename and Compress All the Files in a Directory

```bash
#!/bin/bash
for d in /usr/local/caldocs/*; do
 mv $d $d.2001
gzip $d.2001
done
```
