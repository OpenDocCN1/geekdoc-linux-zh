When users change their passwords, the variable-length password that they enter and a two-character salt that the system generates are run through a modified DES or MD5 algorithm to generate a hash. Although the hash is often referred to as an encrypted password, it is actually encoded instead. As described in Chapter 6, the salt is a sort of monkey wrench that changes the hash in any one of 4096 ways. Under Linux, the DES result is a 13-character one-way hash, a string of characters that is almost impossible to regenerate into its clear text form. The first two characters represent the salt, and the remaining 11 represent the hashed password. For MD5, the password is 32 characters long and begins with $1.

Linux systems do not “decrypt” the stored passwords at all during authentication. Instead, the password that a user supplies to a DES system at login and the two-character salt taken from the /etc/passwd file are run through the same DES algorithm, generating a one-way hash. In the case of MD5 passwords, the first two characters will be $ and the rest is the hashed password. As with DES passwords, the salt is removed and passed with the login password into the appropriate algorithm. The result is compared to the hash stored in /etc/passwd. If they are the same, it is assumed the proper password was supplied.
