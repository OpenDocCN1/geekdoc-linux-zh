| --- | --- |

# Automating Removable-Media Access

Microsoft's OSs treat removable disks differently than Linux. In a Microsoft OS, each removable disk has a drive letter, as A: for the first floppy disk. There's no need to explicitly mount a removable disk; you can simply specify a file on a removable disk by inserting the drive letter in front of the disk's name, as in A:\\SOMEFILE.TXT. This approach is convenient for users but has the drawback of making it unsafe to cache disk writes, or performance suffers. Some hardware notifies the OS when the user presses the E button, allowing the OS to finish any cached disk accesses before ejecting the disk. When using such a device, cache disk writes are possible.

This discussion is relevant to Linux because many Linux users are accustomed to the Windows method of handling disks. These users expect to be able to read and write files on the disk without explicitly mounting the disk, much less relying on the superuser to do the job. Linux provides several workarounds for these users. Specifically:

+   - The user and owner mount options, which are normally used in /etc/fstab, allow users to mount and unmount removable disks. Although these options don't provide truly authentic access, they can be adequate for users with some Linux know-how. They're also a critical step to some other possibilities.
- Window managers and file managers can often be customized to run specific commands when a user clicks on an icon or picks an item from a pop-up menu. Such a configuration can allow users who are uncomfortable with a text-based shell to issue mount andmount commands. Configuration details vary substantially from one program to another, so consult the appropriate package documentation for details.
- The default configurations for the KDE and GNOME desktop environments include automated access to CD-ROM and floppy disks similar to the access in Windows.
