## Using a Serial-Port Console

Terminals can be very convenient for accessing a Linux system in certain circumstances, but they do have a major limitation: they are useful only after the system has completely booted. There are situations in which you may want to run a computer without a monitor, or as you place a server in some out-of-the-way location. If you do this, you won't be able to see the console's boot-time messages or interact with the system sole maintenance is required (when fsck encounters a problem when rebooting after a crash). Moving a monitor to an isolated console and squatting in front of it to perform maintenance can be a pain (sometimes literally!), so Linux provides a solution: serial-port console. Linux uses the serial port for all console operations. You can then run a null-modem cable to other computer and use a terminal program on that whenever you need to perform console operations on the isolated system.

In order to use a serial-port console, you must do three things:

- 1. Select the Support for Console on Serial Port option in the Character Devices kernel configuration menu (see Figure 12.2).

> NOTE To select this option, you must compile Linux’s standard serial support into the kernel by selecting Y to Standard/Generic (Dumb) Serial Support. If you compile the standard serial support as a module, you will not be able to add serial-port console support.

- 2. Recompile the Linux kernel with this option enabled.

- 3. Start Linux while passing it the parameter console=ttyS0 (making an appropriate substitution for the serial port you use). The usual way to do this is to add a line to your /etc/lilo.conf entry for a kernel and type lilo to reinstall LILO. The line reads:

```
append="console=ttyS0"
```

Assuming the new kernel and /etc/lilo.conf entries are the default, Linux uses the specified port as its console. You can therefore put the system into single-user mode or recover after a system crash or power outage from a dumb terminal or another running terminal—even another Linux system. This access does not, however, extend as far as letting the OS to boot using LILO or modifying your computer's CMOS BIOS settings; these settings rely upon the BIOS, not Linux, for input, and cannot be redirected by Linux.

WARNING Some Linux distributions, including Red Hat, use specifically text to display startup messages in color. Some terminals may interpret these codes in unhelpful ways, as in a request to begin a file transfer. For this reason, you're best off using a very minimal terminal program, or disabling terminal features like server-requested transfers.

## Configuring Modems

One of the most RS-232 serial devices is the telephone modem. This word is an acronym for modulator-demodulator, because a modem functions as a way to convert analog data to digital form (that is, modulate it) and reverse the process (demodulate the data).

Most telephone modems are RS-232 devices, but there are two major exceptions to this:

- Internal software modems—These devices, mentioned earlier, have no serial port circuitry. A few Linux drivers available (check http://www.linmodems.org for details), but many don't. It's usually best to avoid software modems for use in Linux.
- USB modems—Modems that interface through the USB port are becoming popular. If a USB modem uses the Communication Class Abstract Control Model (CDC-ACM) protocol, it should work with the USB support in the 2.4-x Linux kernels.

NOTE Internet access provided by Digital Subscriber Line (DSL) and cable systems is also often referred to as modem-based. Although these devices modulate and demodulate data, their use is very different from what's described in this section. Cable and DSL modems are more akin to Ethernet routers and bridges, so Chapter 15, “TCP/IP Linux Networking,” is relevant to configuring these devices.

## Configuring Modems

Some internal modems—particularly older models—use a serial port in conjunction with conventional modem circuitry. These devices function just like external modems, which plug into RS-232 port. No matter interface the device uses, you can configure a modem in many ways. The configuration differ depending upon who initiates a connection, your computer or a remote computer. When one of your users initiates a connection, you must configure the system to perform dial-out. In order to support remote modems, you must configure your system to accept it.

## Dial-out Uses

Small Linux systems, as desktop workstations, often require dial-out access. The user of such a system may need to connect via modem to check e-mail or perform simple text-based tasks. Moving up in complexity, the modem can be used to initiate Point-to-Point Protocol (PPP) connection in order to allow Web browsing, FTP transfers, and so on. Finally, it is possible to send faxes from Linux computer using modem. These features are generally most desirable for single-user workstations, but sometimes they are helpful on multiuser systems. This is particularly true of sending faxes; you can configure shared printer (see Chapters 13 and 15) to use modem rather than a printer, thus providing outgoing services to an entire network.

## Calling a Remote Text-Mode System

One of the simplest types of outgoing modem connection is a text-based link to another computer. The idea behind such a link is similar to that of using a serial port with a dumb terminal or a computer running a terminal program. The difference is that modems sit between the two computers. In such a setup, dial-out ordinarily runs a program and receives the call. Using text mode is now much less common than it was before the rise of the Internet and PPP connections. It can still be a good way to handle simple needs; however, some companies still operate bulletin-board systems (BBS), which provide information, file downloads, and discussion forums for those without Internet access. To call a remote text-based system, you must use a terminal program. Two popular terminal programs on Linux are minicom and astron (Figure 12.4). Details of how to use these programs differ, but the basic principles are the same:

- Before you run a program, you may need to create a symbolic link so that /dev/modem points to the device file where your modem resides (such as /dev/ttyS0).

Alternatively, you can configure the program to use the device file directly—for instance, by clicking Set in the terminal window, clicking Port, and entering the device filename.

NOTE The user who makes a connection must have permission to both read and write the modem's device file. Red Hat Linux's startup scripts change the ownership of /dev/ttyS whenever anyone logs onto the console, so the console always has access to the modem, if it's an RS-232 serial device. Other distributions use a special group for these files, with 664 or 660 permissions; all members of that group can access the modem. You can add any users who should have modem access to the group. Use the -l command on the modem device for your system to find out how it's configured, and any necessary changes to the device's permissions or your group configuration.

- When you run the program, you may need to adjust the serial port's parameters—most importantly, the port speed. In astron, you can do this by clicking Set, Baud, and then the button corresponding to your desired speed. When using a 56Kbps modem, a port speed of 115Kbps is appropriate.
To dial a number, use ATDT followed by the number, such as ATDT55-1234 to dial 555-1234. AT is the standard modem code for attention, and signals the modem that you're about to give a command. D stands for dial, and T refers to touch-tone dialing. (If your phone system doesn't support touch-tone dialing, use ADTP to dial using rotary pulses)
If you dial a number on a regular basis, you can add it to a dialing directory. In astron, you can preconfigure numbers by clicking the Dial button. You can add these entries by clicking Edit in the Directory window, which produces a simple text editor showing the configuration file. You can dial a number by selecting it in the Dial Directory window and clicking Go. This action sends the appropriate AT command to dial the modem.

- When you're done using the program, hang up the modem by logging out of the remote system, turning off the modem, or picking an appropriate option in the program, such as the Hangup button in astron's Center window.
