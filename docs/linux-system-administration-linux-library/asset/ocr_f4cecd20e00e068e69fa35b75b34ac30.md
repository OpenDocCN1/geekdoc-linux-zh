+   Check the ppp-on-dialer script. This script includes a “chat” sequence—a series of strings the program expects to see from the modem or remote system in one column, and a series of responses in another column. You may need to log on using Seyon or mini and capture the prompts your ISP uses to ask for your username and password, and modify the last two lines of the script in order to make it work. Alternatively, you may need to comment out the last two lines by preceding them with pound signs (#) and remove the backslash (\ from the CONNECT line if your ISP uses PAP or CHAP.

> NOTE The chat program expects a single line; its input is only formatted as columns in ppp-on-dialer for the convenience of humans. The backslashes ending most lines line continuations, so that chat interprets multiple lines as a single line. Only the final line should lack a backslash.

When you're making these changes, type ppp-on (preceding it with a complete path, if necessary) as root to test the connection. If all goes well, your system will give the modem, link up, and give you Internet access. If this fails, check the few lines of /var/log/messages with a command such as tail -n 20 /var/log/messages. There should be some sort of error messages, which may help you to diagnose the problem.

WARNING Debugging text-mode PPP connections sometimes bears an uncanny resemblance to voodoo. The problem is that there are many minor implementations of PPP, both on the ISP side and on the Linux side. Some combinations are incompatible or require unusual ppp parameters in the ppp-on script if you read the ppp pages and may also be able to find help on your ISP's Web site, if you have some alternate means of accessing it.

Many ISPs send name system (DNS) information to clients during PPP authentication. If you doesn't, you'll need to enter this information into your /etc/resol.conf file. This file should contain one to three lines listing DNS server addresses, as provided by your ISP. For instance:

```
nameserver 192.168.1.1
```

If your PPP configuration doesn't set this information automatically and you don't set manually, you'll be able to access sites on the Internet by numeric IP address (such as 216.224.70.176), but not by names (see as www.syex.com). You only need to configure DNS information once, not once per connection.
