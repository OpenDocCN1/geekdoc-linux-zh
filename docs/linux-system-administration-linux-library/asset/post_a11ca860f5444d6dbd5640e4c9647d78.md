Finally, the /etc/rc.local file is run. This is the file where you make your local changes to the startup process. This file runs after all of the other initialization files and can be used to override any settings made during the earlier initialization steps. You don't typically add to this file since it's task is critically important. By default, this file creates the login banners /etc/issue. These files are used to set the display that will precede the login prompt when a user logs in locally (/etc/issue) or remotely (/etc/issue). By default, the file contains this:

Red Hat Linux release 7.0 (Guinness) Kernel 2.2.16-22

Many system administrators think this is too much information to give to someone. It might be better to change the /etc/issue banner to something more generic like "Welcome to local" or to give your users information they need before entering your system. If you change the /etc/issue file directly, it will be overwritten when the /etc/rc.local file is run again. Since this file is one big clause, any commands that you wish to add should be added before the last. The Debian Model

Debian's initab file is slightly different from Red Hat's. Listing 5.4 shows the Debian initab.

## Listing 5.4 Debian's initab

# /etc/initab: init(8) v1998/05/10 37:50

# The default runlevel.
id:2:

# Boot-time system configuration. This is run first except in emergency (-b) mode.
sysinit:/etc/rcS

# What to do in single-user mode.
/etc/rc.d/ S and K scripts upon change of runlevel.
# Runlevel 0 is halt. Runlevel 1 is single-user. Runlevels 2-5 are multi-user. Runlevel 6 is reboot.

10:0:wait:/etc/rc.d/rc 0
11:1:wait:/etc/rc.d/rc 1
12:2:wait:/etc/rc.d/rc 2
13:3:wait:/etc/rc.d/rc 3
14:4:wait:/etc/rc.d/rc 4
15:5:wait:/etc/rc.d/rc 5
16:6:wait:/etc/rc.d/rc 6

# Normally reached, but fallthrough in case of emergency.
z:6:respawn:/sbin/getlogin

# What to do when CTRL-ALT-DEL is pressed.
ca:12345:ctrltdel:/sbin/shutdown -r now

# Action on special keypress (ALT-Up-Arrow). Let this work.
kb:kbrequest:/bin/echo "Keyboard Request - edit /etc/initab"

# What to do when the power fails/returns.
pf::powerwait:/etc/rc.d/powerfail start
pn::powerfailnow:/etc/rc.d/powerfail stop
po::powerokwait:/etc/rc.d/powerfail stop

# /sbin/getty invocations for the runlevels.
# The "id" field MUST be the same as the last characters of the device (after "tty").
# Format:
# <id>:<runlevels>:<action>:<process>

1:2345:respawn:/sbin/getty 38400 tty1
2:2345:respawn:/sbin/getty 38400 tty2
3:2345:respawn:/sbin/getty 38400 tty3
4:2345:respawn:/sbin/getty 38400 tty4
5:2345:respawn:/sbin/getty 38400 tty5
6:2345:respawn:/sbin/getty 38400 tty6

## Example how to put a getty on a serial line (for a terminal)

# Initialization and Startup Scripts

T0:23:respawn:-/bin/getty -L ttyS0 9600 vt10
T1:23:respawn:-/bin/getty -L ttyS1 9600 vt10

## Example how to put a getty on a modem line.

T3:23:respawn:-/bin/mgetty -x0 -s 57600 ttyS3

Under Debian, the first uncommented line in initab sets the default level to 2. You'll remember that this level is a multi-user mode that doesn't include networking.

The next line in initab instructs the init process to run the /etc/rcS file, which we'll look at next. Like its Red Hat counterpart, it executes the S and K scripts for the specified level, and adds an Alt+Up-Arrow shortcut to define a keyboard request function differently than the Red Hat model. The rcS script sets up UPS power functions similar to Red Hat's, adding a function for immediate shutdown. The getty programs are set up; Debian only has the first tty respawning a getty when the system is at level 5. The last part of Debian's initab gives examples of how to run getty programs on a serial line and a modem line.

Listing 5.5 shows the Debian rcS file mentioned earlier.

### 5.5 The Debian rcS File

```bash
#!/bin/sh
#
# rcS
    Call all S??* scripts in /etc/rcS.d in
    numerical/alphabetical order.
#

# Version: @(@)

# PATH=/sbin:/usr/sbin:/bin:/usr/bin
# BOOT=0
# umask=022

# Call all S??* scripts in /etc/rcS.d in
# numerical/alphabetical order.
for i in /etc/rcS.d/S??; do
    if [ -x "$i" ]; then
        . "$i"
    fi
done
```
