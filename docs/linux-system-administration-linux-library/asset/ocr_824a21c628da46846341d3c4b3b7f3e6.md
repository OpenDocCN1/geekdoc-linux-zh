# Tuning the System 291

Now that you've checked the disk itself for bad blocks, you should give the filesystem a chance to repair them. You do this using /sbin/fscck.ext2 (or /sbin/e2fsck, which is the same program). When passed the flag -1 followed by the badblocks output file, e2fsck will attempt to move any data contained in the questionable block to a healthy block. When run, e2fsck reports its five passes through the filesystem, including any problems it encounters, then:

```
# e2fsck -f - badblocks.rpt /dev/hda7
e2fsck 1.19, 13-Jul-2000 for EXT2 FS 0.5b, 95/08/08
```

+   Pass 1: Checking inodes, blocks, and sizes
Pass 2: Checking directory structure
Setting filetype for 'pump.sock' in /var/run (30156) to 6.
Setting filetype for entry 'fs100' in /tmp/.font-unix (37489) to 6.
Pass 3: Checking directory connectivity
Pass 4: Checking reference counts
Pass 5: Checking group summary information

> / ***** FILE SYSTEM WAS MODIFIED *****
/: 96133/165792 files (0.6% non-contiguous)/331332 blocks

In the above example, e2fsck found minor problems with files, /var/run and /tmp/.font-unix. The utility corrected both problems automatically. On rare occasion, e2fsck may require your help in fixing problems. If this happens, your best bet is to accept the default option for each problem, unless you understand the ext2 filesystem intimately.

# Eliminating Unnecessary Processes

Chapter 7 noted that unnecessary processes left running on a system pose a significant security risk. That reason is enough to merit altering the system so that these processes are not automatically started. If you need another reason, here it is: Any processes running on your machine use memory and CPU cycles. In other words, they waste resources that could be used by required processes.
