## Accepting PPP Connections

It's desirable to configure a Linux system to accept PPP logins. So configured, an Internet-enabled Linux computer can function as a gateway between a remote computer running any of several operating systems and the Internet. This setup can be convenient if you have a system at work with always-on Internet access and a modem, and you want to provide yourself or your employees with Internet access at home or when they are on the road. Many ISPs use Linux systems running PPP servers to handle dozens, hundreds, or more users.

> NOTE 56Kbps modems operate with a speed asymmetry—upload speeds are lower than download speeds. This state of affairs exists because the high upload speeds require that one (the ISP's) computer in a normal configuration) have a special connection to the telephone network. Unless you acquire such a connection, your dial-in PPP system will be limited to 33.6Kbps speeds, even if you have a 56Kbps modem.

There are many ways to accept PPP connections. The method described here is comparatively simple to set up, but it requires that the calling system use a connection script or manually enter authentication information. No matter how you do it, there are several configuration features you must set. In essence, a PPP link requires that the Linux computer function as a router between the dial-in systems and the rest of the network. Therefore, these systems require router support in the Linux kernel (which is standard in most Linux distributions, including Red Hat 7.0). You must also be able to assign an IP address to the dial-in systems. Normally, this is done on a static basis according to the serial port, as you'll shortly see.

To configure a Linux system as a PPP server, follow these steps:

- 1. Configure the computer to accept a remote login via a getty program, as described in the previous section.

- 2. Modify the /etc/ppp/options file so that it contains the following entries (you may need to modify the netmask to conform to your network; this value should be the same as the netmask of the PPP server:

```
asyncmap 0
netmask 255.255.255.0
proxyarp
lock
crtscts
odem
login
```

- 3. Create a file /etc/ppp/options.port, where port is the port file, such as ty50 for the first serial port. This file contains the IP address or hostname of the PPP server followed by a colon (:) and the IP address or hostname of the PPP client. be sure that the PPP client hostname is available for use on the network. For

```
192.168.1.3:192.168.1.200
```

- 4. Create an /etc/ppp/pap-secrets file entry for any users who should be able to use the PPP link. This entry is similar to the one for dial-out PPP access, but it lists a local username and password. For instance, the following allows the user abell to connect to a PPP server using the password watson:

```
abell *
watson
```

- 5. Check the permissions on the pppd file. You should set it uid root by typing chmod u+s /usr/sbin/pppd, if necessary. When you've done this, typing ls -1 /usr/sbin/pppd should reveal the following permissions:

```
-rw-xr-x 1 root root 140656 Mar 7 10:25 /usr/sbin/pppd
```

- 6. To run pppd, users dialing in must normally type a slightly cumbersome command-it's not very complex by Linux system administration standards, but it's a bit of an nuisance. You can reduce the annoyance factor by setting up a global alias to run this command. Once set up, a user need type ppp to launch pppd on Linux. You can set this up by entering the following line in /etc/bashrc (assuming your user's account is configured to use Bash as the default):

```
alias ppp=exec /usr/bin/ppp -detach
```

With these steps followed, a user should be able to use PPP to connect to the computer and any network to which it is attached. The PPP server requires manual login via a standard prompt: after which the client must send the ppp command pppd on the Linux system or by manual procedure from some dialers, such as the one that comes with Microsoft Windows.

## Receiving Faxes

If you've configured your system to accept dialup text-mode logins using mgetty, your system is automatically configured to receive faxes. When a call comes in on the line which the modem is attached, the modem determines whether the call is a data call or a fax. If it's a data call, mgetty passes control of the serial line to appropriate programs to handle transmission. If the modem detects an incoming fax, mgetty initiates fax reception and places incoming faxes in the /var/spool/incoming/ directory. Incoming faxes use the standard fax format. You can view these files with several programs, such as KDE's KFax (shown in Figure 12.8). Such programs are typically simple enough; they allow you to view or print the file, but not much else. mgetty includes options to set configuration to the modem so that it functions as only a data modem or as only fax modem. These options are -D and -F, respectively. They can be added to the appropriate lines in /etc/inittab.

## Configuring Serial Printers

Most printers connected to Linux use the parallel interface, as discussed in Chapter 13. The parallel interface offers one great advantage over the traditional RS-232 interface: speed. Modern parallel ports are theoretically capable of transferring 2MB/s, compared to 14KB/s of an RS-232 serial port. This speed difference is important for printers—especially modern color printers, which often take massive bitmaps as input.

Despite the advantages of parallel ports, some printers use RS-232 serial ports. This interface is problematic when the printer understands PostScript, because most Linux programs that can print create PostScript output, which is more complex than the bitmap output that Ghostscript creates. (See Chapter 13 for a discussion of Ghostscript and how to use it in a Linux printer queue.)

Since 1999, USB printers have started to become popular. The USB interface is capable of 1.5MB/s—roughly comparable to a parallel port. If you want to use a USB printer in Linux, you'll need a 2.4.x kernel, or at least a backport of the USB drivers to a 2.2.x kernel.

## Special Considerations for Serial Printers

For an RS-232 printer, the configuration details that differ from a parallel-port configuration in the /etc/printcap file are:

- You must specify an appropriate serial port, such as /dev/ttyS1, on the lp=
- You must set the speed of the port using the # line (The pound symbol is used in place of an equal sign with this option.) For best results, you should set the speed as high as your serial port and printer allow—ideally 115,200 bps (#115200).

To use a USB printer, you must specify the appropriate USB printer device file on the lp= line /dev/usb1p or something similar, as described in Table 12.1. You do not set the speed for USB printers as you do for RS-232 serial printers.

In the case of RS-232 and USB printers, you must have appropriate support in the Linux kernel for the port. All major Linux distributions include RS-232 support, but you may need to add this support for USB printers, as described.

## When to use a Serial Printer

If you have a choice, use a parallel printer in Linux, or one that uses an Ethernet interface if you have a network. These interfaces provide the best speed, particularly when printing graphics—Ghostscript converts text into graphics when printing to non-PostScript printers. Unless the printer supports PostScript, most Linux printing is graphics printing.

The USB interface is as fast as the parallel interface and so can be a good choice in this respect. The fact that USB support is still so new in Linux, however, makes this interface a second choice, particularly if you're using a distribution, such as Red Hat 6.2, that includes no USB support by default. (Red Hat 7.0 and some other distributions add USB support to their kernels.) Because you should check http://www.linux-usb.org for compatibility information on specific models.
