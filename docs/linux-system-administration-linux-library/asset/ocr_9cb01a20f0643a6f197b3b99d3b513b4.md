# Remote Printing

On a network, a workstation may be configured to print to a printer attached to a divergent host machine on the network or to a standalone printer with an internal network interface card (NIC). In the first case, the host machine may be a Linux or Unix box or a machine running some version of Microsoft Windows. In the second case, the printer runs its own server software thats functionally identical to a Linux/Unix or Windows server.

# Linux to Linux

In the case of Linux-to-Linux printing, you'll need to configure printing on both the server (the machine to which the printer is attached) and the client (the machine that submits a print job). There are two steps to this overall configuration, beyond basic network setup:

+   1. Configure the server to print to the printer it controls. You should test local printing functions as described earlier in this chapter. You can perform this configuration manually or via a GUI utility such as Tshirt.
2. Configure the client to print to the network printer hosted by the server, as described earlier in this chapter. You can perform this configuration manually or via a GUI utility such as Tshirt.

Both of these steps have been covered in the preceding discussion. Once you configure the print server to print locally, it's automatically configured to accept remote jobs, if you're using LPRng with Red Hat 7.0. This makes printer setup very easy, but it's also a potentially big risk, because it means that anyone who wants to send huge print jobs to your printer. The older 1pd printing system is a bit less promiscuous by default. To accept remote jobs with the old 1pd, you must enter the names or IP addresses of the computers from which 1pd will accept the jobs in the /etc/hosts. 1pd file (or in /etc/hosts.equiv, but this file grants permission to use a range of additional services, so it's best not to use it in most cases).
