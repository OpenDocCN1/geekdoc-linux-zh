Your Linux system can get by without these accounts, but if you install certain programs, they may not work correctly, because they'll assume that these accounts are present. Other accounts, such as nobody, fall in between these two cases; they may be used by several different packages but aren't strictly required for basic functionality.

Some programs add users to /etc/passwd during installation. The qmail mail server adds several entries for its use. If you install such a program but remove it, the program may fail to operate correctly, or at all. You should, however, remove any such accounts if you remove the software that required them.

> TIP: It's a good idea to back up the /etc/passwd file (as well as the /etc/shadow file, which stores passwords, and /etc/group, which stores group information) after system installation, as well as after adding or deleting users. This can make it easier to recover the system if you ever need to reinstall. It can help you track down system breakdowns; crackers often create their own accounts. These often have a UID of 0, giving them root privileges even if they use another username on the account. Crackers sometimes add passwords revealed in /etc/shadow on most systems and login shells to normal system accounts as ftp.

## Shadowed Passwords

When a user picks or is assigned a password, it is encoded with a randomly generated value referred to as the salt. Using the salt, any password can be stored in /etc/shadow. The salt is used to prevent attackers from using precomputed tables to crack passwords. Because each user has a unique salt, an attacker would have to crack each password individually, which is much more time-consuming.

The shadow file contains several fields for each user, separated by colons. The fields are:

- Username: The name of the user.
- Password: The encrypted password.
- Last Change: The number of days since the epoch the password was last changed.
- Minimum: The minimum number of days the user must wait between password changes.
- Maximum: The maximum number of days the password is valid before it expires.
- Warning: The number of days before the password expires that the user is warned.
- In: The number of days after the password expires that the user is still allowed to log in.
- Comment: A comment about the user.
- Home Directory: The path to the user's home directory.
- Shell: The path to the user's login shell.

## Chapter 6: Creating and Maintaining Accounts

Shadowing solves the problem of storing passwords in the /etc/passwd file, which is readable by all users on the system. By storing encrypted passwords in the /etc/shadow file, which is only readable by root, shadowing prevents unauthorized users from attempting to crack passwords.

To add a new user, use the `useradd` command. This command has several options that allow you to configure the user's account:

- -m: Create the user's home directory.
- -d: Specify the path to the home directory.
- -s: Specify the user's login shell.
- -g: Specify the user's primary group.
- -G: Specify the user's supplementary groups.
- -c: Add a comment for the user.
- -p: Set the encrypted password (deprecated).

After adding a user, you must set their password using the `passwd` command. This will prompt you to enter the password twice, and then encrypt it and store it in /etc/shadow.

To modify a user's account, use the `usermod` command. This command has several options that allow you to change various aspects of the user's account:

- -l: Change the user's username.
- -d: Change the user's home directory.
- -s: Change the user's login shell.
- -g: Change the user's primary group.
- -G: Add the user to new supplementary groups.
- -c: Change the comment for the user.
- -L: Lock the user account.

To remove a user, use the `userdel` command. This command has several options:

- -r: Remove the user's home directory and mail spool.

To manage groups, use the `groupadd`, `groupdel`, and `groupmod` commands. These commands allow you to create, delete, and modify groups on the system, respectively.
