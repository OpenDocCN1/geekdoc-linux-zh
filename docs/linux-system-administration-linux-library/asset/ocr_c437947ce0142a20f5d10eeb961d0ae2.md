Xia The Filesystem, called xafs at mount time, was an extension to the Min filesystem filesystem competed with extfs and ext2fs. Released at the same time as ext2fs, Xafs was more stable, and ext2fs offered larger partition and file sizes. Since then, ext2fs has become very stable, surpassing Xafs in all important measures. In the meantime, ext2fs became the standard Linux filesystem. The Xafs option was removed from the 2.2.x kernel.

ISO-9660 This filesystem is unusual in its use it is restricted to CD-ROM discs. In some sense, it's not really a native filesystem; as CD-ROMs intended for Linux invariably use the ISO-9660 filesystem, it's included in this list. "Raw" ISO-9660 is very limited in filename length, and it Linux's ownership and permissions. The Rock Ridge to ISO-9660 correct this shortcoming, allowing CD-ROMs to contain these important features. Another filesystem, Joliet, is used in conjunction with at least a minimal ISO-9660 filesystem and provides long filenames for Windows systems. Linux can also read Joliet CD-ROMs, if appropriate support is compiled into the kernel. All three variants use iso9660 filesystem type code.

In 2000 and early 2001, the most important traditional Linux filesystem is clearly ext2fs. You'll only find extfs on museum pieces, and although the Linux system continues to live in 2.2.x and 2.4.x kernels, its practical use is restricted to floppy disks. ISO-9660 and its extensions are important, but only for CD-ROMs.

Although ext2fs is a good filesystem by traditional filesystem standards, it has its limits. Most important at the moment is the disk check duration problem; however, ext2fs is also limited to a maximum filesystem size of 16 terabytes (16,34GB) and a maximum file size of 4GB. Although 16TB disks are still not available for desktop computers at this writing, filesystems take sufficient development time that filesystem developers need to start planning for these disks well before their introduction. The 4GB file-size limit is an issue for some installations today, and it's likely to become more important to more people with the growth of applications such as video editing.

> NOTE Linux relies upon a Virtual Filesystem (VFS) layer to implement features used by all filesystems. In the 2.2.x kernels, the VFS imposes a partition-size limit of 4TB and a file-size limit of 2.2GB. The kernel developers have rewritten most of the code responsible for these limits in the 2.3.x kernel series, and any remaining stragglers will no doubt be dealt with by the time 4TB disks become available.
