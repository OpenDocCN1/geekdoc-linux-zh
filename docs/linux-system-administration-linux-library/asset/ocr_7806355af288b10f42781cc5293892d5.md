# Compiling for Packages

Source RPM files are identified by the presence of .src in the filename, rather than .i386 or some other architecture identifier. For example, samba-2.0.7-21ss1.src.rpm is the source RPM for the Samba 2.0.7 package that comes with Red Hat 7.0; samba-2.0.7-21ss1.i386.rpm is the matching compiled binary for x86 customers. If you wanted to compile the source RPM on LinuxPPC (Linux for Macintosh and other PPC-systems), the result would be a file called samba-2.0.7-21ss1.ppc.rpm.

> NOTE Non-source RPM files are architecture-independent. These can contain documentation, fonts, architecture-independent scripts, and so on. They're identified by a .noarch filename component. These RPMs can be installed without modification on systems using any CPU.

To compile a source RPM package, you use the --rebuild operation to the rpm command, thus:

```
# rpm --rebuild samba-2.0.7-21ss1.src.rpm
```

If all goes well, you'll see a series of compilation commands as a result. These may take anywhere from a few seconds to several hours to run, depending on the package and your computer's speed. On a typical 500MHz Intel-architecture computer, many packages compile in a few minutes.

Building a package requires that you have necessary libraries installed—not just the libraries required by the final binary package, but also the matching development libraries. These libraries aren't always included in source RPM dependency, so it's not unusual to see a compilation failure because of a missing library. Your best when this happens is to examine the error message and check the list of requirements on the program's home page. With luck, the failure message will bear some resemblance to a requirement listed on the package's home page. You can then locate an appropriate development RPM (which usually contains devel in its name), install it, and try again.

> TIP You often use the command -qpi packagefile to locate the RPM's home page. The package maintainer often has a home page, as well.
