At this point, you may let it run on in the background until it terminates when the backup
has completed, or you may use the fg command to bring the process to the foreground
again.

If you want to start a process in the background, simply append ampersand to the
command. the tar command would then look like this:

```
$ tar zcf /dev/st0 / &
```

You will then be given a process ID, which looks like this:

```
[2] 4036
```

You can then bring the process to the foreground using the fg command as we did before
or let it run its course in the background.
nTechnically, interactive processes in X work the same as they do in text mode; however,
GUI environments include default methods of launching programs that are eff-
tively the same as appending ampersand on a command line. Running an X program
in the background doesn't make the X program inaccessible, though; it opens a X win-
dow and displays its output. Your experience is therefore one in which programs appear
to run side-by-side, and you use mouse clicks, or perhaps merely mouse movements,
bring one process or another to the foreground. All the visible programs are active and
unning, even if you are not doing much when you're not interacting with them.
If you launch an X program from an xterm or other terminal window, however, the
 becomes unresponsive unless you include the ampersand in the command. If
you use Ctrl+Z to regain control of the xterm, the X program you launched from the
term becomes unresponsive unless you type bg to allow both processes to run. It's
easy to be confused and think that an X program has crashed, when in fact it's just
been stopped after having been launched from an xterm.
