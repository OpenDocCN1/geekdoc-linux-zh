# Configuring POP and IMAP

Fortunately, setting up the POP and IMAP protocols is not very difficult. Compared to sendmail, the POP and IMAP servers require very little in the way of configuration. If you're building a departmental mail server, though you may need to configure user accounts, and this may require some thought. It's also possible to use a Linux system as a POP or IMAP client. In many cases, you do via MUAs; however, there's a special program that lets you grab POP or IMAP mail and serve it through a regular Linux mail queue.

# Running POP and IMAP Daemons

The first step to running POP and IMAP is to install the appropriate server package. In Red Hat 7.0, it's called imap-4.7c2-12, and it includes servers for both POP and IMAP. Other distributions ship with similar packages.

> NOTE Just sendmail isn't the only SMTP server, the POP and IMAP servers included in the imap-4.7c2-12 package aren't the only POP and IMAP servers. You'll likely need to look for an alternative if you use qmail as your MTA, because qmail stores e-mail in different locations than do most other MTAs, which confuses POP and IMAP servers. The gmail Web site links to alternative POP and IMAP servers that work with qmail. Exim and Postfix are compatible with the standard imap package, however.

The POP and IMAP daemons are normally run from a super server, as described in Chapter 15. Red Hat 7.0 and Mandrake 7.2 use the inetd server, but most other distributions in 2001, as well as earlier versions of Red Hat and Mandrake, use inetd. The configuration of these programs differs.

If your distribution uses inetd, the /etc/inetd.conf file probably contains the following lines relating to POP and IMAP servers:

```
pop-2 stream tcp nowait root /usr/sbin/tcp ipop2d
pop-3 stream tcp nowait root /usr/sbin/tcp ipop3d
imap stream tcp nowait root /usr/sbin/tcp ipapd
```
