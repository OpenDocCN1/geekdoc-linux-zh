On a server with 128MB of memory and a fairly low load use, settings of "256 512 768" tend to work well. If the system will be restricted to light server duty and fairly significant desktop usage, these settings are probably adequate. If the server load becomes heavier and the system seems to stall, you can experiment with increasing the settings using the guidelines noted above.

To adjust these settings, simply echo the desired values and redirect the output to /proc/sys/vm/freepages as follows:

```
# echo "256 512 768" > /proc/sys/vm/freepages
```

Another tool is /proc/sys/vm/overcommit-memory file, which you can use to allow overcomm of resources. It contains only a flag setting (0 off, 1 on) to turn this feature off or on. Overcommitting allows you to do with fewer resources than you would otherwise need. We don't recommend this, because if programs try to use the resources they've been told available, the programs or system may crash. If you need more memory, add more physical memory.

The /proc/sys/vm/bdflush file determines the behavior of the bflush kernel daemon. This daemon determines when existing “dirty” buffers should be written to disk. A “dirty” buffer is one that is awaiting a disk write. When memory is short, you can set the maximum number of dirty buffers that can exist in a buffer cache to a high value/or the maximum number of dirty buffers bflush can write to the disk at once. This causes Linux to perform less frequent but longer-lasting disk writes. A low value allows dirty writes more often in their frequency and duration. Other settings control the allocation of free buffers, and can be adjusted to meet the system's needs as well. Read more about bflush at /usr/src/1linux/Documentation/vm.txt.

The /proc/sys/vm/swapp file contains settings that control kernel swapping. You can control how many pages swap at once and the number of pages swap in one turn (a swap cluster). You'll want to set the swap cluster reasonably large so that swap does the I/O in large chunks and the disk won't see very often, but if you set it too high, the system will be bogged down with very lengthy swaps. The setting used by default for Red Hat will work for a server that is not heavily used, but you can experiment.
