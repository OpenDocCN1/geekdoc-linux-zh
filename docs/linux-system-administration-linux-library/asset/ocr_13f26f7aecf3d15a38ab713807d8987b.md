For instance, you might compile a kernel and discover that the process requires 15:03 to
complete. After setting several optimizations, you might find that the same process
requires only 11:34—a substantial improvement. In performing such a comparison,
th, you must ensure that nothing about the compilation itself has changed. You
should compile the same source code from the same source tree. Also, be sure to make
clean before each test compile. This command removes the intermediate object code
created from the source code files. If you do not make a clean, the subsequent make
bzImage (see Chapter 8) or similar command will simply relink the kernel against the pre-
viously compiled object files, resulting in a huge speed difference that does not reflect the
results of your performance tuning.

To measure X performance, use the xbench tool. As described on its Web site (http://
charon.astro.nju.edu/xbench), this tool uses a measurement called xStones, which is
a weighted average of several tests indexed over an old Sun station with a single-bit depth.
xbench uses 13 low-level tests:

| line | Draws vertical and diagonal lines of different lengths |
| dline | Draws dashed lines |
| wline | Draws wide lines |
| rects | Draws rectangles |
| fillrects | Draws solid filled rectangles |
| tiledrects | Draws tiled rectangles |
| stippledrects | Draws stippled rectangles |
| invects | Inverts rectangles on the screen |
| arc | Draws arcs of varying angles between 5 and 360 degrees |
| filledarc | Draws arcs of varying angles between 5 and 360 degrees |
| filledpoly | Draws a filled polygon with five points |
| bilblt | Test varies; see Web site for details |
| imagestring | Draws a string |

The simple tests listed above really test the graphics engine. Additionally, xbench
uses one complex test to the X server's overall performance. This test creates a win-
down, clears an area, draws some text, scrolls the window, and destroys the window. This
is a very old tool. If there was a newer tool that measured the same type of activity, we'd
use it. As it is, though, xbench is the usual benchmark for X performance.
