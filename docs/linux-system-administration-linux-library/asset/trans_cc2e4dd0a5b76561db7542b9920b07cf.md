## 从 Windows 打印到 Linux 打印机假设你已经配置了一台 Linux 计算机打印到本地打印机，你只需要设置一个 Samba 共享，允许局域网上的 Windows 电脑进行打印。你将在安装 Samba 时创建的 smb.conf 文件中进行此操作。（此文件在 Red Hat 7.0 中位于 `/etc/samba.d/`，但在其他发行版中可能位于 `/etc`、`/etc/samba.d` 或其他地方。）如列表 13.2 所示，向你的 smb.conf 添加打印配置：

**列表 13.2** 一个允许网络 Windows 电脑打印到 Linux 打印机的示例 smb.conf 文件

```
[global]
workgroup = ARBORETUM
printing = bsd
encrypt passwords = Yes

load printers = Yes
log file = /var/log/samba-log.%m
lock directory = /var/lock/samba
```

```
[printers]
comment = All Printers
security = Server
path = /var/spool/samba
browse = No
printable = Yes
public = Yes
create mode = 0700
```

Samba 配置涉及设置适用于所有共享的全局选项（在 smb.conf 文件的 `[global]` 部分）以及针对特定共享或共享类型的选项。列表 13.2 仅显示了一个共享——`[printers]` 共享。此共享是特殊的，因为它会为 `/etc/printcap` 中定义的每个“打印机”创建一个独立的打印机共享。此选项依赖于 `[global]` 部分中的 `load printers = Yes`。（或者，你也可以通过为每个打印机单独创建共享定义来共享某些打印机。）

同样极其重要的是 `workgroup = ARBORETUM` 全局参数。它设置了 Samba 服务器的 NetBIOS 工作组名称，类似于域名。如果此选项设置不当，你将无法在 Windows 电脑的“网络”浏览器中看到 Samba 服务器。在列表 13.2 的情况下，该服务器是 ARBORETUM 网络的一个成员。

另一个 Samba 配置问题涉及验证。与 Linux 到 Linux 的打印不同，SMB/CIFS 打印会在机器之间发送密码以授权打印。默认情况下，Samba 接受明文（未加密）密码并将其与普通的 Linux 登录密码进行比对。从 Windows 95 OSR2 和 Windows NT 服务包 3 开始，微软已经程序让 Windows 电脑默认发送加密密码。由于 SMB/CIFS 使用的编码方法与 Linux 不同，在使用加密密码时，Samba 无法在普通的 Linux 密码数据库上运行。因此，你必须使用 Samba 的 `smbswd` 工具创建一个新的密码数据库，它允许你像使用 Linux `passwd` 工具设置登录密码一样设置 Samba 的加密密码。要使用此工具添加用户，请向其传递 `-a` 参数和你希望的用户名（此用户名必须与现有的 Linux 用户对应）

```
# smbpasswd -a someuser
New SMB password:
Retype new SMB password:
```

在输入密码时，屏幕不会显示。如果你以前没有使用过该工具，它会报错无法打开 `smbswd` 文件，但尽管有此错误，它仍创建一个新文件。要使用加密密码，你必须如列表 13.2 所示，在 smb.conf 中添加 `encrypted passwords = [global]` 部分。

Windows 9x 和 Me 系统本地存储你发送到服务器的密码。这可能是一个大大的安全问题，特别是当用户的 Samba 和 Linux 登录密码相同时。有很多方法可以降低 Windows 本地存储密码带来的风险。其中最简单的方法是确保 Samba 加密密码与普通的 Linux 登录密码不一致。
