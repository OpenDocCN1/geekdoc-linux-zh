# Kernel Panics

Another possible problem is a kernel panic. These events are really frequent if you aren't doing bleeding-edge kernel testing and not a lot of typos in files like /etc/lilo.conf and /etc/fstab. Many Linux system administrators have never experienced one kernel panic. A kernel panic is often quite frustrating for new system administrators, since it can be the result of several problems—including both hardware and software. One key to remember is that kernel panics may be caused by arguments passed to LILO, but if the LILO phase was successful and the problem is not hardware, the culprit is probably something that was run from /etc/rc.d/rc.sysinit. Look through this file and see if you can determine what it was. Another possible cause is an error in the /etc/fstab file that prevents the root filesystem from being mounted.

Now that the system initialized, let's look at what happens when a user logs in. You will need to know this process well so that you can troubleshoot user login.

# User Initialization Files

A different type of initialization happens when a user logs in. This is not a system-wide initialization like the boot process. It is another sequence for user-specific initialization. But just as with the system initialization files on each desktop, the system administrator is responsible for the user initialization files.

When a user logs in, the system user configuration files are run first. These files are scripts and are sourced instead of being executed. A file is sourced via the "dot" command. To source the .login file, for example, use the following command:

- /home/some/.login
