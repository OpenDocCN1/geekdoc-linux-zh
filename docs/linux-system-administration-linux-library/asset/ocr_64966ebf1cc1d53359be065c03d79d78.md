Your distribution maintainer is usually the best source of updates for critical system components such as lib, XFree86, and major servers. By using an update provided by your distribution maintainer, you can reasonably ensure that the update will not conflict or cause problems for other packages that come with the distribution. In such cases as the following, you may want or to look elsewhere for updates.

**Unavailable updates** If your distribution's maintainer is slow in updating, you may have little choice but to look elsewhere when you learn of a problem with an important package.

**Prior self-updates** If you've previously updated a package using another source, you may want to stick with that source rather than return to the distribution maintainer's package. Presumably you've already worked through any compatibility issues, and it may be a nuisance to have do this again if you revert to the original supplier.

**Package substitutions** You might decide to replace a standard package with another different program that provides similar functionality. For instance, if you use Postfix to replace sendmail on a Red Hat 7.0 system, you won't find Postfix updates on Red's Web site.

**Package additions** Just as with substituted packages, you won't find updates for programs that don't ship with the original distribution. For example, you'll have to turn to Appix (http://www.appix.com) for AppixWare updates.

**Kernel updates** As described earlier in “Obtaining a Kernel,” the Linux kernel can be updated via prepackaged files, but it's often beneficial to compile the kernel yourself from original source code.
