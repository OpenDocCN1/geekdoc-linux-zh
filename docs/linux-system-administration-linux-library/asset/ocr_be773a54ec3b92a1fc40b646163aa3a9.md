The configuration files contained in /etc/skel are intended to be set up for the typical user in that system. The files in this directory include .defaults, .bash_logout, .bash_profile, .bashrc, .kerc, .kde/ and Desktop/. You may add files that will be contained in your user’s home directories.

Default values for certain user characteristics may be set in the /etc/login.defs file. The mail directory, which is typically set to /var/spool/mail/username, is set via the MAIL_DIR variable in that file. Password aging information is also stored in the login.defs file. The minimum and maximum UID and GID values are stored for automatic selection by the useradd command.

# Migrating Users from Other Unix Systems

Since most users use the same format for /etc/passwd files, it is possible to migrate users directly from a Unix platform to Linux. If the Unix user is using passwords, you must first run the command to “unshadow”—punwconv. The punwconv utility requires no privileges. Copy the appropriate user lines from the passwd file of the other machine into the /etc/passwd file on Linux and run /sbin/punwconv to reapply shadowing.

# Modifying User Accounts

Most system administrators make changes to user accounts by editing the appropriate files. It is easier to use a text editor to edit the passwd file to change a simple configuration detail like the user’s shell than bring up a GUI utility or use armored at the command line. We’ll show you all three, and you can decide which you prefer.

# Manually Modifying User Accounts

The most direct way to modify a user’s account information is to edit the corresponding entry in /etc/passwd. For example, suppose you want to change your hypothetical user Donald’s shell to the C shell. Use your favorite editor to open the /etc/passwd file.

```
donald:x:503:0:Unka Donald:/home/donald:/bin/bash
```
