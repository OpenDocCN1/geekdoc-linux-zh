Even when a filesystem has been cleanly unmounted, Linux systems often issue an fsck on the filesystem at boot time. This is because ext2fs has a maximum mount count—maximum number of times Linux will mount the partition before it requires a check, in order to ensure that errors haven't onto the system. There's also a maximum time between checks, for you can determine these values for any ext2fs partition by using the dump2fs program. (This program produces a lot of output, so you should pipe it through less, as in dump2fs /dev/hda9 | less\.) For lines labeled Maximum mount count and Check interval. Typical values are 20 and 6 months, respectively.

You can alter these values (and others) using the tune2fs program. Include the -c parameter to adjust the maximum mount count, and the -i parameter to adjust the check interval. For instance, tune tune2fs /dev/hda9 -c 5 -i 1m to reduce the limits to 5 mounts or 1 month (You can also use d and w for units to the -i parameter, to indicate days and weeks, respectively.)

Naturally, filesystems other than ext2fs use different criteria for determining when to force a filesystem check. Most include flags that let spot a filesystem that was not cleanly unmounted, but any given filesystem may not include equivalents to the forced checks by time or number of mounts included in ext2fs. Equivalents to the dump2fs and tune2fs programs may exist for specific filesystems, but not usually.
