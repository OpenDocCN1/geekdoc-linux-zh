# Replacing a Disk

Fundamentally, you can treat a disk transplant much as you do a disk addition; it's moving everything from one disk to another. There are some special caveats to keep in mind:

+   If you're replacing a disk because you can't add more disks to your system, you'll need to temporarily disconnect a device, such as a Zip or CD-ROM drive, in order to perform the replacement. Alternatively, you can use a tape backup device as an intermediary storage device, but this is likely to be a slower process.

> NOTE You can use a network storage device, such as a server system, as an intermediary storage device. If you do so, it's best to back up the files to the network server. Copy the files directly may result in the loss of important filesystem characteristics.

+   Step 4 of the second procedure in "Adding a Disk" uses the -1 parameter to tar. This parameter keeps the transfer restricted to one filesystem, which helps avoid problems with /proc or endless loops that result copying the root file-system. When moving an entire instance, it's best to do so one filesystem at a time.

+   When you've finished copying all the files, edit /etc/fstab on the destination system to reflect the partition assignments as they will exist after you removed the original disk. For instance, if the original disk is /dev/sda and the new one is /dev/sda, removal of /dev/sda changes all the /dev/sda partitions to equivalently numbered /dev/sda partitions. The new disk's /etc/fstab file should include references to itself as /dev/sda.
