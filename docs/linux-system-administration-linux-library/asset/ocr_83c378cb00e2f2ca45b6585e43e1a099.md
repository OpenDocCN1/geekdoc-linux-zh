# Deleting an Account with userdel

The userdel utility will remove a user's entry in the /etc/passwd file and optionally remove that user's home directory and all the files and subdirectories it contains. Any files owned by that user outside the home directory will remain on the system and appear as owned by the user's ID when displayed via ls -l command. The userdel command to delete our hypothetical Donald's passwd entry and home directory looks like this:

```
# userdel -r donald
```

You may also choose to delete Donald's /etc/passwd entry but leave all the files in his home directory by omitting the -r.

You may choose to use the find command shown earlier to locate all files owned by Donald or in his group.

# Groups

You saw earlier in the chapter that each user has a default group identity, called a login group, which is assumed upon logging in to the system. Once activated by /bin/login, the user assumes the group identity specified in the /etc/passwd file. In Red Hat Linux, the user's default group ID is the same as the user ID; in other Linux distributions, all users are by default in a single group, typically called users. Linux administrators create new groups, associating users for specific purposes such as projects that require certain users to have access to the same set of files. The next sections show how to add and remove groups, and how users can become members of different groups.

# The Function of Groups

Groups are an integral part of Linux security. As described in Chapter 3, every file has associated permissions This string specifies the presence or absence of read, write, and execute permission to each of three classes of users: the file's owner, the file's group, and all users (often called world permissions). By controlling the group setting for files and assigning users to particular groups, you can enhance the internal security of your Linux system. For instance, if your system is being used by two different sets of employees, each of which is working on one project, you can create two groups, and by denying access to users' files, you can prevent employees in one group from reading files created by members of the other group. If a few users belong to both groups, you can make those users members of both groups, so they can read both groups' files.
