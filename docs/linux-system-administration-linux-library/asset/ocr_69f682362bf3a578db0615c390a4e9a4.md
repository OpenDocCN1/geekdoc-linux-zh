# Locating Unusual Filesystems

A few filesystems don't ship with the regular Linux kernel. Most of these are development filesystems—they're new enough that they have yet to be added to the kernel. The most interesting of these filesystems are the new journaling filesystems, which are described shortly, in "Journaling Filesystems." (That section includes pointers to these filesystems' homes on the Internet). Journaling filesystems can greatly speed boot times after a crash. If your Linux system operates in an environment with speedy recovery from power outages or system crashes is important, or if you have hard disks larger than 20GB, you may want to investigate these filesystems.

If you're looking for a specific filesystem and can't find it in the kernel, try a search on Deja News (http://www.deja.com/usenet/), or with a Web search engine as Yahoo! (http://www.yahoo.com) or Google (http://www.google.com). There's a good chance you'll find a lead.

Most substandard filesystems require that you patch your Linux kernel—that is, add files to the kernel source. These patches usually come with instructions for accomplishing this task, you should follow these instructions. You can then select the kernel driver as just described in "Preparing to Use a Standard Filesystem," and compile a kernel or kernel modules with the necessary support.

# Linux Native Filesystems

A native filesystem is one that can be used as the primary filesystem for an OS. Linux can run using nothing but a single native filesystem that is, it doesn't need a mix of two or more filesystems. An OS's native filesystems are often designed for a specific OS, although in some cases an OS "inherits" or "adopts" a native filesystem from a predecessor or later OS. Throughout its history, Linux has inherited and adopted filesystems and has Linux-specific filesystems designed for it. (Chapter 3 details this history for Linux.) This is in contrast to foreign filesystems, which are designed for another OS. As a general rule, foreign filesystems don't mesh well with Linux as native filesystems. In some cases, these definitions become blurred, as you'll discover.

This discussion separates native filesystems into two camps: traditional and journaling. Other categorizations could also be made, but for purposes this one is quite useful.
