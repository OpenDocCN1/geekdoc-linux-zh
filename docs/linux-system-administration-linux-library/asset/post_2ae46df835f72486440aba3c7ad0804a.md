In Red Hat, every new user is added, a group with the same user ID and numeric ID as that user is created. A user group called david would be created, and the user group david would be added to that user private group. The mask (see Chapter 4) is set to 002, which means that any file created by david would have read-write permission for him (the owner) and for the group read-only for world. This works well since we know that his user has membership in the group by default. Since Donald is the only member of his private group, only he and the super-user can access files with the group set to donald. Anyone can be added to the donald group and then have group access to any files that Donald creates with this mask.

Other distributions don't always work this way. Create a single group (generally called users), and place all users in this group. Thus, both donald and bety accounts by default belong to the users group. Typically, the mask is 022, so users can read each other's files, but cannot write to them. This is a shared-group approach.

On small workstations, these approaches do to work well, because workstations have to just one or two users, and the implications of group membership have small consequences. At worst, you may need to add one or two users to each other's groups in the user private group approach, or create a couple of new groups and change default group membership in the shared group approach. On larger systems, you're likely to need to create more complex configuration. In an academic environment, you may need to create groups for different courses; and in a work environment, you may need to create groups for different working groups. The tools to do this are parallel tools used to create user accounts in many respects.

## The /etc/group File

Information about each group is contained in the /etc/group file. Just with /etc/passwd, it is critical that any system administrator clearly understand this important file. Its structure is fairly simple. Listing 6.2 shows an excerpt from a typical /etc/group file.

Listing 6.2 Portion of the /etc/group File

```
root:x:0:root
bin:x:1:root,bin,daemon
daemon:x:2:root,bin,daemon
```

<... other entries ...>
slocate:x:21:
project2038:x:1000:annie:x:betty
marty:x:500:
ernie:x:501:
betty:x:502:
donal:x:503:

Each entry declares a group name, password, and numeric group ID, called the GID.

## Adding New Groups

Just as users can be added manually, with a command-line utility, or using Linuxconf, groups can also be created in any of these ways. The different methods are explained below so that you can choose the method you prefer. (Once you've created a new group, you presumably want to add users to that group. This process is described shortly, in “Changing Group Membership.")

## Manually Adding a Group

Because the structure of the /etc/group file is fairly simple, administrators typically add groups by directly editing the file. To create a group with an initial set of group members, simply add the usernames of the users to the comma-delimited list at the end of the entry. For instance:

```
cs101::101:donald,betty
```

To check your work, the id command reports all groups a user has. The output for david looks like:

```
uid=1000(david) gid=1000(david) groups=1000(david)
```

**NOTE** It's not necessary to add to groups. Ordinarily, the groupadd command is used instead.

## Adding a Group with groupadd

To add a new group, use groupadd command. The syntax for groupadd is:

```
groupadd [-g GID] [-r [-f]] group
```

The meanings of groupadd parameters are:

- g GID The numeric value of the group.
- f If a group already exists, groupadd would complain about it.
- r The system group will be assigned to.
- group The name of the new group being created.

## Creating and Maintaining User Accounts

You can also use Linuxconf to add new groups. To do so, follow these steps:
1. Select Config > User Accounts > Group Definitions from the Linuxconf main menu.
2. Click the Add button to add a new group.
3. Specify the group's name and any members.
4. Click Accept.
5. Activate the changes.

## Group Membership

All actions performed by a user are performed under a specific user ID and group ID. Therefore, although a user may belong to more than one group (by adding multiple /etc/group entries, as described earlier), a user may only act as a member of one group at a time. Ordinarily, this is not terribly important, but it can be in some cases. For instance, a user might need to create files that carry a certain group membership, so that other members of the appropriate group can read those files. Every user has a primary group affiliation, specified in the user's /etcpasswd entry. Upon logging in, the user acts as a member of that group. The newgrp command provides a means for users to temporarily change the group associated with their actions (The command sg is frequently a synonym for newgrp). To use newgrp, type the command, with a hyphen (which causes the shell to reinitialize the user's environmental variables), and the new group name. For instance, to become a member of the project1 group, type:

$ newgrp - project1

If the user don has used newgrp to join the group project1, when he creates a new file, it will show up in a long listing (ls -1) with group ownership by the new group:

```
-rw-r--r-- 1 donald project1 10332 Aug 20 16:07 proj_doc
```
