

## 输入/输出

除了磁盘访问外，许多其他 I/O 过程也非常重要，但并非在所有情况下都如此。视频硬件对于某些视频密集型任务至关重要，例如在 X 系统中显示和移动窗口，以及游戏运行。网卡 I/O 对于服务器和其他网络密集型任务至关重要。即使是低速的串口和并行端口，对于打印等任务也可能至关重要。

在大多数情况下，I/O 速度直接取决于相关硬件的质量。有时，硬件质量与为硬件编写的驱动程序质量相互影响——例如，在历史上，最快的视频硬件最初在 Linux 中通过驱动程序支持，但这些程序并未充分利用显卡的特性。因此，最新的显卡在 Linux 中的性能通常很差，至少在 XFree86 开发者推出改进的驱动之前——这一过程可能需要几个月。

有时，特殊的驱动参数可以提高 I/O 设备的性能。Linux 通常在启动时设置最佳参数，但在某些情况下，你可能想或需要调整这些设置。第 12 章涵盖了串口速度的调整，本章则提供了其他一些 I/O 设备的技巧。

## 软件性能

衡量软件性能的工具通常昂贵，而且并不经常使用。通常，软件性能通过速度和准确性来衡量。软件速度直接取决于编写软件的程序员的水平，但由于你无法控制这一点，当软件性能出现下降时，你只能转向硬件操作系统。通常，用户频繁运行的某个特定程序就是系统运行不佳的线索。

## 测量性能

衡量性能的方法非常多，以至于很难使其具有意义。Linux 系统最好的基准测试之一是在不运行 X 的情况下，从命令行编译特定内核所需的时间；这在比较两台完全相同的计算机，或者在比较单台计算机在重新配置前后的差异时非常有用。因为在 Linux 下编译内核执行了除了浮点数性能之外的普通基准测试中涉及的大部分功能，这种比较产生了非常有价值的数据，并且具有易于比较的格式这一额外益处。为了使比较更完美，你可以关闭任何外部访问，防止用户污染数据。当然，你需要使用相同的内核源码树和相同的 .config 文件，以确保你进行的是同类比较（apples to apples）。如果你的意图是测试系统的“核心”，这就足够了。

例如，你可能编译一个内核并发现该过程需要 15:03 完成。在设置了若干优化选项后，你可能会发现相同的过程仅需 11:34——这是一个重大的改进。在执行此类比较时，你必须确保编译本身没有发生任何变化。你应该从相同的源码树编译相同的源代码。此外，务必在每次测试编译之前执行 `clean`。此命令会删除从源文件创建的中间对象代码。如果不执行 `clean`，随后的 `make bzImage`（见第 8 章）或类似命令将简单地将内核与之前编译的对象文件重新链接，导致巨大的速度差异，这种差异并反映你性能调优的结果。
