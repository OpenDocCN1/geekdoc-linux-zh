# Linux Filesystem Support

Linux filesystem support is excellent, but not perfect. Some filesystems do not work on
a default installation of Red Hat Linux (or of other distributions, for that matter).
These filesystems require that you use the appropriate drivers, and in all probabil-
ity, recompile your kernel. Other filesystems work, but their features are limited.
Most importantly, many filesystem drivers are available in read-only formats—they can
be used to read files from the foreign filesystem, but not to write to them. Still
others work in full read/write mode, but their feature sets do not mesh perfectly with
Linux's assumptions and requirements. For all these reasons, you must understand
the specific filesystems you are using in order to be aware of the limitations and work
around them where possible.

# Locating Filesystems

Most Linux filesystems come with the Linux kernel, and Red Hat Linux includes most of
these filesystems in its default configuration. Many of these filesystems are available as
kernel modules. You can find which filesystem modules are available by typing the
command:

```
$ ls /lib/modules/x.y.z/fs
```

In this command, x.y.z is the kernel version number, as of 2.2.16. In response, you'll
see a set of filesystem driver modules, as hpf s.. These modules are usually named
after the filesystems they implement. Some of these drivers are true of modules, how-
ever, and not independent filesystems. (This is particularly true of nls_cp*. mod-
els, which implement language support by FAT and Juliet filesystems.) Also, be
aware that not all filesystems appear in this directory—some are built into the kernel file
itself. Most importantly, the filesystem from which Linux boots (ext2fs in most cases)
must be built into the kernel.
