When a parent process dies before all of its child processes have died, the remaining child pro-\cess are said to be orphan processes. These processes are required to have a parent process,
so the init process adopts the orphan processes until they, too, are completed or killed.

You can see in Listing 3.5 a login process with a PID of 4270 was started for the user
; logins are owned by root. Since it has a pts number, it is a remote login.
This login process forked a child process with a PID of 4271. This child process is
bash shell that initiated by the login process when the user logged in.

Since user logged remotely, a pts was assigned instead of a tty number. In older versions
of Red Hat, remote tys are referred to as tty0, tty1, etc. In Red Hat 6.0 and later,
remote tys are referred to as pts/0, pts/1. The init process runs as long as the system
is active. Nothing else can run without the init process. We will discuss the init
process in Chapter 5 when we discuss startup and shutdown. During a
system shutdown, init performs the reverse of its bootup procedure. It kills all other run-
ing processes, unmounts all filesystems, and stops the process, along with anything
el has been configured to do.
