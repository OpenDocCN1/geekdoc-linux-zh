# X Concepts 543

As an example, consider the following: You're sitting at the computer
dino.pangeea.edu, and you want to run a program that's located at
larch.threeroomco.com. Assuming both computers are Linux or Unix boxes, you would
follow these steps:

+   1. Log in to dino.pangaea.edu.
2. If dino isn't already running X, start it by typing startx.
3. Issue the command xhost +larch.threeroomco.com.
4. Use Telnet or Secure Shell (SSH) to log in to larch.threeroomco.com from
dino.pangaea.edu.
5. Type export DISPLAY=dino.pangaea.edu:0 on your larch login.
6. Run whatever programs you want to run using your larch login.
7. When you're done, type xhost -larch.threeroomco.com on to remove larch
from dino's hosted host.

If your computer (dino) sits behind a firewall, especially one that uses IP masquerading,
you may not be able to follow these steps, because the outside client won't be able to
reach the firewall to connect to your X server. There are two common workarounds to
this problem:

Use VNC, mentioned earlier, reverses the client/server configuration, so the
server falls outside the firewall. Assuming the firewall doesn't block out VNC
connections, you can use a local VNC client and run the VNC server on the remote
system. Use the VNC documentation for details of its use.

Use SSH can be configured to tunnel X connections through its own con-nection. When this happens, the SSH server looks for X connection attempts
from local programs and passes back to the system on which the SSH client
(and X server) runs. When properly configured, this works automatically, so you
skip steps 3, 5, and 7 from the above procedure. If this doesn't work initially,
check the file /etc/ssh/ssh_config on the client; its ForwardX11 line should read
yes. The server /etc/ssh/sshd_config file should include a line that reads
X11 Forwards ways.
