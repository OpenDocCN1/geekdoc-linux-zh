

# 324 第 10 章 文件系统与磁盘管理

> **注意** 正如前面提到的，标准的 x86 PC 硬件无法读取 Apple 为其 400KB 和 800KB 软盘使用的底层数据记录方法。HFS Utilities 软件包并没有提供能够规避这一限制的魔法方法。

## 访问大容量移动磁盘

随着典型文件大小的增加，大容量移动磁盘（如 Iomega Zip Disk、Imation LS-120 磁盘和 Carlsbad Orb 驱动）变得越来越流行。通常情况下，Linux 处理这些设备没有问题，但有一些需要注意的地方。

其中最重要的是确保设备的接口（ATAPI、SCSI、并行端口、USB 或其他接口）与 Linux 兼容。大多数情况下，EIDE/ATAPI 和 SCSI 设备没有问题。大多数并行端口驱动器都可以正常工作，但为某些稀有设备寻找底层的 Linux 驱动程序可能是一个挑战。2.2.x 内核不支持 USB 驱动器。请查阅 http://www.linux-usb.org 获取 USB 设备支持的详细信息。

处理大容量移动设备有两种方式：将其视为大软盘或视为移动磁盘。在第一种，使用主设备文件来访问驱动器，例如，对于配置为主 EIDE 链上从机的 EIDE 或 ATAPI 驱动器，使用 `/dev/hdb`；对于获取所有 SCSI 磁盘中最低 SCSI ID 的 SCSI 驱动器，使用 `/dev/sda`。这种方式处理移动磁盘对于某些介质（如磁光盘）很常见。它的优点是你不需要担心磁盘的分区问题。

更常见的做法是像处理硬盘一样处理移动磁盘。在这种安排下，使用 `fdisk`（稍后在“磁盘分区”部分中讨论）或类似的磁盘分区工具对磁盘进行分区。然后，你在创建和挂载文件系统时访问该分区。例如，你可能访问 `/dev/hdb1` 或 `/dev/sda1`。一种方法是分区号可能在不同磁盘之间变化。Iomega Zip 磁盘使用第四个分区，但某些其他磁盘类型和工具使用第一个分区。因此，你可能需要创建多个 `/etc/fstab` 条目来处理所有可能性，特别是当你与几个人交换磁盘时。

> **注意** Macintosh Zip 磁盘使用 Mac 分区表进行分区，这与 x86 PC 上使用的分区表系统不同。然而，Linux 的 HFS 驱动包含了对 Macintosh 分区的有限支持，因此你可以像对待软盘一样挂载 Macintosh 磁盘（使用 `/dev/hdb`、`/dev/sda` 或“无编号”设备文件）。或者，你可以将 Macintosh 分区表支持编译到 Linux 内核中，并挂载移动磁盘上的第四分区。

## 访问文件系统

你可以在大容量移动磁盘上使用任何可以在硬盘上使用的文件系统。特别是，`ext2fs` 在移动磁盘上运行良好。FAT 和 HFS 也是流行的选择，特别是当你想要分别与 Windows 或 Macintosh 用户交换数据时。日志文件系统使用的日志文件可能会消耗移动磁盘容量的很大比例。例如，ReiserFS 会创建一个物理大小为 32MB 的日志文件——大约是 100MB Zip 磁盘容量的三分之一左右。

## 读取 CD-ROM 光盘

CD-ROM 光盘在挂载和访问方式上并不特别奇特。有两点需要注意：

- *只读访问*。CD-ROM 光盘默认是只读的。因此，`rw` 选项无效，你无法向 CD-ROM 光盘写入数据。
- 文件系统选择。虽然 Linux 可以挂载使用几乎任何文件系统创建的 CD-ROM，但 ISO-9660 占据了 CD-ROM 文件系统领域。许多为 Macintosh 市场创建的光盘使用 HFS 代替或增加 ISO-9660。考虑到 Linux 或 Unix 创建的光盘通常使用 ISO-9660。
