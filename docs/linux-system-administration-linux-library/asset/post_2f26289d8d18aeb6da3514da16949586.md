## Basic lpd Functionality

A master line printer daemon runs constantly to keep track of any print spooling needs on the system. The master lpd is started at boot time in the same way as other daemons we discussed when we talked about system initialization. Red Hat Linux has an lpd script in /etc/rc.init.d, which runs at boot time. You can start or stop LPRng at other times by issuing a command consisting of the full path to the lpd script, a space, and one of the following: start, stop, status, or restart. When the line printer daemon is started, it reads the /etc/printcap file, discussed earlier. Listing 13.1 shows an example of a printcap file.

+ Listing 13.1 An Example printcap File

```
1p|1p0|lexmark:\n:sd=/var/spool/lpd/lexmark:\n:mx#0:\n:sh:\
:lp=/dev/1lp0:\n:if=/var/spool/lpd/lexmark/filter:\nlp1|hp4000:\n:sd=/var/spool/lpd/hp4000:\n:mx#0:\n:sh:\
:rm=-tennessee:\n:rp=hp4000:\n:if=/var/spool/lpd/hp4000/filter:\nlp2|epson:\n:sd=/var/spool/lpd/epson:\n:mx#0:\n:sh:\
:if=/var/spool/lpd/epson/filter:\n:af=/var/spool/lpd/epson/acct:\n:lp=/dev/null:
```

## Chapter 13 Printers and the Spooling Subsystem

This printcap file example contains the configuration for a directly connected Lexmark Optra 40, a remote HP LaserJet 4000, and a remote SMB/Windows Stylus Color 800. The first line assigns the local printer's name, in this case 1lp1p0|1lexmark. This is actually a specification for three names, each separated from the others by vertical bars (|). In this case, users can refer to the printer as 1lp, 1p0, or 1lexmark, with identical results. 1lp is the default for the first printer on systems. The next uncommon line sets the spooling directory for the printer to /var/spool/lpd/1lexmark. The line beginning with :mx sets the maximum file size in kilobytes; the 0 in our example sets it to unlimited. The next line sets up the printer to suppress the page header, when present information on who ran the print job, to making print jobs easier in a busy printing environment. The next line sets the printer device name to /dev/lp0. This device name is the printer's hardware device—the file to which NPR sends its output. The name may or not bear any resemblance to the print pool name defined earlier. The line beginning with :if provides the path to the file that contains the filter information for any print types defined for that printer. These options and more are documented in the printcap page.

The sample printcap file contains stanzas (sections) for two more printers. The 1lp|hp4000 entry is for a printer located on a hostname of tennesse, located on the same network as the local machine. The difference in this stanza is instead of 1lp, it contains an rm line, which specifies the machine to which the printer is connected; and an rp line specifying the queue name on that machine. This also has its own spool directory.

The 1lp|2lp entry is for an SMB/Windows 95/NT printer. The standard Red Hat format does not place information on SMB servers in the printcap file, instead, that information is located in the .config file in the spool directory. For an SMB printer, you must include a username and password for the host machine. For security reasons, the username should be the same as that user's account on the Linux machine. We'll discuss printing to a networked Windows printer later in the chapter.

After reading through the printcap file and printing anything left in the queue, the line printer daemon goes into a passive mode, waiting for requests to print files, reorder print jobs in the queue, or display the waiting print jobs. It uses the system calls listen and accept to determine whether any requests are made.

As mentioned above, the line printer daemon package includes other programs necessary for the printing functionality. These binaries perform specific functions, which we will look at next.

## lpr

The lpr program is the spooling command that makes requests of lpd. Lpr makes contact with the line printer daemon when it needs to put a new print job into the spool. The format is basic:

```
lpr path-to-file [arguments]
```

When you print from an application under Linux, the program runs lpr, specifying a stream from which to read. This data may take any of several forms, including PostScript, raw text, JPEG, and so on. lpr passes the data to lpd, which checks the printcap file for specifies about the printer. If the printcap entry includes a filter line, lpd sends the data (document) through that filter as discussed earlier. Once the document is filtered, lpd sends it to the queue entry for that printer.

Commonly used arguments to lpr include:
- Pqueename Forces output to a particular printer instead of the default.
-h Suppresses the header.
-num Prints copies of the file.
-T Title to print.

## lpq

The lpq command examines the queue and lists the jobs currently waiting. It returns the user's name, the job ID, and the total size in bytes. To check the queue for a specific printer, use the -P option. In action, lpq looks like this:

```
$ lpq
Printer: 1lp is active
Queue: 12180
Printer: 1p0 is active
Spooler: 12181 
```

## lpc

The LPR System Control program, or lpc, provides the capability to disable or enable a print queue, to reorder the print jobs in a queue, and to obtain status about a printer, a queue, or a job. These commands are applicable to any printer. If issued without an argument, the lpc session will be interactive and a lpc prompt will be returned. You can also include the lpc command in a script, using the following format:

```
lpc [subcommand]
```

The available subcommands are as follows:

- **abort**: Terminates any printing in progress and disables further printing to the specified printer(s). The queue is left intact so that the waiting jobs will be printed when the start command is next issued. Sometimes, if a printer has stopped printing for no apparent reason, issuing the abort command followed by the command will get going again.
- **disable**: Turns the queue off that it won't accept any more jobs, although the superuser can still print jobs. Printing is not halted, so anything in the queue already or added by the superuser will print. When a printer is to be deactivated, you should issue the disable command followed by the stop command.
- **down**: Turns the specified printer queue off, disables printing to the printer, and logs a message to the printer status file. Subsequent attempts to run the lpc command will indicate that it is down and output the status message.
- **enable**: Enables spooling on the specified printer's queue so that it will accept new jobs.
- **exit**: Terminates the interactive lpc session.
