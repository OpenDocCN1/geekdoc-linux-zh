# 故障排除

明显的网络问题应该分阶段处理。首先确认本地机器是否可以 ping 远程主机，以及远程机器是否能 ping 回本地。如果本地 ping 成功但远程机器 ping 失败，请检查远程机器的配置问题。如果你找不到问题所在，请找一台可以 ping 通本地的远程机器，并比较两台机器的配置。大多数以太网卡都有指示灯，显示网卡是否能够发送数据包。排查网络最好的方法就是去实践。

以下是几个与 Linux 或软件配置相关的网络问题。我们无法解决网络硬件所带来的更广泛的问题范围，因为可能的组合和配置太多，无法涵盖。

# 未知主机消息

如果你在尝试 Telnet 或使用其他各种网络工具时遇到此错误，说明主机无法解析为 IP 地址。这可能是因为服务器问题、网络问题或拼写错误。尝试 ping IP 地址而不是主机名。如果你能通过数字 IP ping 通主机，说明问题出在名称设置上。否则，请验证输入的名称是否正确。如果正确，尝试 ping 与产生问题的主处于同一网络上的另一台机器。如果可以，问题几乎确定出在问题主机的设置或连接到该网络的电缆上。

另一种可能性（特别是在不使用内部 DNS 的本地网络上）是 `/etc/hosts` 文件的问题。该文件可以作为本地网络上 DNS 的替代；它包含了主机到 IP 地址的映射。示例所示：

![](img/4fb617eb648f87def380ef5d92052d01_642_0.png)

127.0.0.1 localhost

192.168.1.1 speaker.rodsbooks.com speaker

192.168.1.2 teela.rodsbooks.com teela luckyyone

每行以单个 IP 地址开头，后面跟着一个或多个主机名。（通常首先是完整主机名，然后是一个或多个缺失域名的主机名或同义词。）如果你的网络使用了 `/etc/hosts`，请确保该文件存在且内容合理。

你可能还想检查 `/etc/host.conf` 文件。该文件告诉 Linux 尝试各种主机名解析方法的顺序。它通常包含如下所示的一行：

```
order hosts,bind
```

此行指定 Linux 将先使用 `/etc/hosts`，然后是 DNS（有时被称为 BIND，即伯克利互联网名称守护进程）。此行可能包含额外的条目，或者另一种顺序的条目。如果缺少此处显示的任一项，本地网络或整个互联网的名称解析可能会受到影响。

# make menuconfig 产生关于 ncurses.h 的错误

你可能输入 `make menuconfig` 并得到以下错误：

```
make[1]: *** [lxdialog.o] Error 1
```

```
make[1]: Leaving directory /usr/src/linux-2.2.16/scripts/lxdialog/
```

```
make: *** [menuconfig] Error 2
```

问题在于你没有安装包含 `ncurses.h` 的包。这可能让人有些困惑，因为你可能已经安装了 ncurses RPM 但仍然收到此错误。在运行 Red Hat 包管理器 (RPM) 的系统上，你需要安装 `ncurses-devel` RPM 才能使用 `make menuconfig`。

# 信号 11 错误

有时用户或系统管理员编译新内核时，gcc 会返回以下错误：

```
gcc: internal compiler error 11
```

信号 11 是段错误（segmentation violation），通常意味着程序试图写入它不拥有的内存。问题通常是由计算机内存损坏引起的。如果你立即尝试运行 `make` 命令并且它运行了一段时间，那么问题几乎确定是硬件问题。有一个网站详细介绍了信号 11 错误，地址为 http://www.bitwizard.nl/s111。

# 我每次升级都需要重新配置内核吗？

你可以将旧内核的配置设置拷贝到新内核中。命令如下：

- cp /boot/config-$(uname -r) .config
- make menuconfig

`menuconfig` 命令提供了一个用于配置内核的交互式界面。一旦完成配置，`.config` 文件将会被更新。然后可以使用以下命令编译内核：

```
make
```

编译完成后，你可以使用以下命令安装新内核：

```
make install
```

最后，你需要更新引导加载程序：

```bash
grub-mkconfig
```

完成后，你就可以重启系统并进入新内核了。
