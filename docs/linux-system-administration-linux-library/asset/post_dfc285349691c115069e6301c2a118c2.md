## make menuconfig

Like make config, this option presents a text-based configuration tool, with each make menuconfig tool uses text-mode menus, so you can skip from one to another. This is a good way to configure the kernel if you're using a text-based console login.

## make xconfig

This command also uses menus for configuration, but the menus are X-based, so you can configure the kernel using mouse clicks in X.

The kernel configuration options are arranged in groups. If you use make menuconfig or make xconfig, you can select one group to see a list of items in that group, as shown in Figure 8.2. Particularly in the 2.4.x kernels, groups often have subgroups, so you may need to examine a few menus before you find a particular driver or option.

## Kernel Version Numbers

Each Linux kernel has a version number of the form x.y.z.

- The x number is the major version number, and in 2001 this number is 2.
- The y number denotes an important change to the kernel and has a special meaning. Even-numbered y values are considered stable—they're unlikely to contain major bugs, and they don't change from one release to another. An odd y denotes a development kernel, which contains features that are experimental. Development kernels may be unstable and may change substantially over time. Unless you desperate to use a feature introduced in a development kernel, you shouldn't use one of these.
- The z number represents a minor change within a given stable or development kernel. In stable kernels, these represent minor bug fixes and occasionally the addition of important new (but-well-tested) drivers. Within development kernels, incrementing z numbers represent major bug fixes, added features, changes, and (being realistic) bug introductions.

When Linus Torvalds believes a development kernel is becoming stable and contains the features he wants in that kernel, he calls a code freeze, after which point features aren't added, just bug fixes. When the kernel stabilizes enough, a test release in the next stable version is announced. This kernel has a number as 2.4.0-test1. Once Linus is satisfied with the stability of the kernel, the test moniker is removed. At this writing, the current stable kernel version is 2.2.17, and the 2.4.0-test8 kernel is also available. Once 2.4.0 is released, a 2.5.x development series will begin, leading eventually to the release of a 2.6.0 or 3.0.0 kernel.

## Table 8.5 Linux 2.4.x Kernel Configuration Options

| Kernel Configuration Item | Subsumed Options |
|---|---|
| Code Maturity Level | This menu provides options allowing you to select experimental drivers and features. |
| Loadable Module Support | Modern kernels typically include loadable modules (separate driver files). This menu lets you enable support for these modules and a couple of options related to it. |
| Processor Type and Features | You can configure the system to optimize the kernel for your particular CPU, as well as enable CPU-related options such as floating-point emulation (which is not required for modern CPUs). |
| General Setup | This menu contains an assortment of miscellaneous options that didn't fit anywhere else, such as types of binary program files supported by the kernel and power management features. |
| Memory Technology Devices (MTD) | This menu allows you to enable support for certain types of specialized memory storage devices, such as flash ROMs. Chances are you don't need this support on a workstation or server. |
| Parallel Port Support | Here you can add support for parallel-port hardware (typically used for printers and occasionally for scanners, removable disk drives, and other devices). Support for specific devices must be added in various other menus. |
| Plug and Play Configuration | The 2.4.x kernel includes support for ISA plug-and-play (PnP) cards. Prior kernels relied upon an external utility, isapnp, to configure these cards. You can use the kernel support or the old isapnp utility, whichever you prefer. |
