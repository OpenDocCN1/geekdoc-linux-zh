
在DHCP服务器中，您需要在服务器的dhcpd.conf文件中放置相应的TSIG密钥声明和allow-update条目，如下例所示。key声明的语法与DNS服务器中的相同。然后使用DHCP zone语句来指定域名的IP地址和要使用的TSIG密钥。DNS和DHCP服务器的配置文件中的域名和IP地址需要完全匹配。与named.conf文件不同，dhcpd.conf文件中的域名或IP地址周围没有引号。在dhcpd.conf文件中，zone语句中使用的域名和IP地址也需要以句点结尾，就像在DNS区域文件中一样。key语句列出要使用的密钥。尽管DHCP会尝试确定要更新的DNS服务器，但建议您使用zone条目中的primary语句来显式标识它们。

```
key mydhcpserver {
    algorithm HMAC-MD5;
    secret "ONQAfBbLnvWU9H8hRqq/WA==";
};
```

```
zone mytrek.com. {
    primary 192.168.0.1;    #DNS domain zone to update
    #address of DNS server
    key mydhcpserver;       #TSIG signature key
};
```

```
zone 1.168.192.IN-ADDR.ARPA. {
    primary 192.168.0.1;    #domain PTR zone to update
    #address of DNS server
    key mydhcpserver;       # TSIG signature key
};
```

为了生成在DNS更新中使用的完全限定主机名，DHCP服务器通常会使用自己的域名和DHCP客户端提供的主机名（有关例外情况，请参阅dhcpd.conf手册页）。如果希望为某个主机分配特定的主机名，可以使用ddns-hostname语句在主机硬件部分中指定它。域名在domain-name选项中指定：

```
option domain-name "mytrek.com"
```

可以使用ddns-update-style语句为所有域打开或关闭DNS更新功能。该功能默认是打开的。要为特定域关闭DNS更新，可以使用ddns-updates语句。这一功能默认也是开启的。下面展示了dhcpd.conf文件中一个简单的DHCP服务器DNS更新配置。

```
/etc/dhcpd.conf
option routers 192.168.0.1;
option subnet-mask 255.255.255.0;
option domain-name "mytrek.com";
option domain-name-servers 192.168.0.1;
key mydhcpserver {
    algorithm HMAC-MD5;
    secret "ONQAfBbLnvWU9H8hRqq/WA==";
};
```

```
subnet 192.168.1.0 netmask 255.255.255.0 {
  range 192.168.0.5 192.168.0.128;
  default-lease-time 21600;
  max-lease-time 43200;
  zone mytrek.com. {
    primary 192.168.0.1;
    key mydhcpserver;
  }
  zone 1.168.192.IN-ADDR.ARPA. {
    primary 192.168.0.1;
    key mydhcpserver;
  }
}
```

## 子网

如果你正在将网络空间划分为多个子网，可以使用单个DHCP服务器来管理它们。在这种情况下，你需要为每个子网定义一个subnet声明。如果你正在建立自己的小型网络，可以使用以192.168开头的网络地址。range将指定该网络内可能的IP地址。因此，对于地址为192.168.0.0的网络，你需要创建一个子网掩码为255.255.255.0的subnet声明。在这个声明中，你需要放置一个range声明，以及你想提供给客户端主机的任何其他信息。在下面的示例中，可以将从192.168.0.1到192.168.0.75的IP地址范围分配给该网络上的主机：

```
subnet 192.168.0.0 netmask 255.255.255.0 {
  range 192.168.0.5 192.168.0.75;
}
```

你可能希望为每个子网指定不同的策略，例如不同的租约时间。subnet声明中的任何条目都会覆盖全局设置。因此，如果你已经设置了全局租约时间，subnet声明中的租约设置将覆盖该子网的全局设置。下一个示例为不同的子网设置了不同的租约时间，以及不同的地址分配。第一个子网的租约时间取自全局租约时间设置，而第二个子网定义了自己的租约时间：

```
default-lease-time 21600;
max-lease-time 43200;
```

```
subnet 192.168.1.0 netmask 255.255.255.0 {
  range 192.168.0.5 192.168.0.75;
}
```

```
subnet 192.168.1.128 netmask 255.255.255.252 {
  range 192.168.0.129 192.168.0.215;
  default-lease-time 56000;
  max-lease-time 62000;
}
```

如果你的子网是同一个物理网络的一部分，那么你需要将它们声明为共享网络来通知服务器。你可以通过放置subnet来实现。
