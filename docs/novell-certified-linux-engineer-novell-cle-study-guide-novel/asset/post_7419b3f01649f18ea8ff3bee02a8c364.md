
## Lab Exercise 10.1: Implementing NetMail

In this lab, you're going to configure NetMail on your server. Then you will send email messages back and forth between two users in your eDirectory tree.

In order to complete this lab exercise, you must ensure that the DNS server (provided by the named daemon) you configured in Chapter 5 is running on your server and configured to service the CLE.com zone. If you haven't configured it, go back to Chapter 5 and complete those steps before starting this exercise.
Also, if you decide to use a separate workstation to test your NetMail system, you will need to configure its TCP/IP stack to use your Linux server as its DNS server.

Complete the following steps:

1. Verify that your DNS server is resolving properly by completing the following:
   a. On your Linux server, open a terminal session.
   b. Log in as a user in your eDirectory tree (such as CGrayson) with a password of **novell**.
   c. Change to your root user account by entering `su` — with a password of **novell**.
   d. At the shell prompt, enter `nslookup`.
   e. At the prompt, enter `cle1.cle.com`.
   f. Your named service should resolve this name to your server's IP address.

If it doesn't resolve correctly, verify that the service is running by entering `chkconfig -list named`. The service should be configured to start at run-levels 3, 4, and 5. Also check your `/etc/named.conf` file and make sure an entry exists for the `cle.com` zone that points to the `/var/named/named.hosts` file. Check your `/var/named/named.hosts` file and make sure a record exists for your CLE1 server.

   g. Enter `exit`.

2. Using the `chkconfig` command, make sure postfix and sendmail are set to **off** at run-levels 3, 4, and 5.

3. Configure the contexts in your eDirectory tree serviced by the NetMail server by completing the following:
   a. Open a browser window and navigate to http://your_server_IP_address:8018.
   b. In the **User Name** field, enter **admin.if.cle**.
   c. In the **password** field, enter **novell**.
   d. Expand your **Internet Services** container.
   e. Expand your **CLE1 Messaging Server** object.
   f. Select your **NMAP Agent** object.
   g. Select the **Context** tab. When you do, the screen in Figure 10.28 is displayed.

   h. The Managed Contexts field should be automatically populated with the context where the CLE1 server object resides in the tree (in this case, **IF.CLE**).
   i. Click the **Browse** icon.
   j. Browse to and select the **SLC.CLE** container.
   k. Click **Save**.

4. Limit the size of outgoing messages to 2MB by completing the following:
   a. In the left frame, select your **SMTP Agent** object.
   b. Scroll down to the **Message Size Limit** drop-down list.
   c. In the Message Size Limit drop-down list, select 2.
   d. Click Save.

5. Select your POP Agent and verify that its Agent Status is set to Enabled.

6. Select your IMAP Agent and verify that its Agent Status is set to Enabled.

7. Configure your AntiSpam Agent to block messages coming from the SpamsIsUs.com domain by completing the following:
   a. In the left frame, select your AntiSpam Agent object.
   b. Configure the AntiSpam Agent to return spam messages back to the sender by marking Yes under Send Back.
   c. Configure the AntiSpam Agent to send a copy of the spam message back to the sender's postmaster by marking Yes under CC Postmaster.
   d. In the Blocked Sites field, enter SpamsIsUs.com.
   e. Click Save.

8. Configure your NetMail server's Modular Web Agent by completing the following:
   a. In the left frame, select your Modular Web Agent object.
   b. In the Default Language drop-down list, select your language.
   c. In the Default Time Zone drop-down list, select your time zone.
   d. Scroll down to the Default Template field. Verify that it is set to use the WebAccess template.
   e. Click Save.
   f. Expand your Modular Web Agent object.
   g. Select the IMS Mail Module.
   h. In the Message Size Limit drop-down list, select 2.
   i. In the Personal section under Address Book, select Enabled.
   j. Under System-Wide, select Enabled.
   k. In the field under System-Wide, enter your server IP address.
   l. Under Default LDAP Server, select Enabled.
   m. In the field under Default LDAP server, enter your server IP address.
   n. Click Save.

You now have a functional NetMail system that is fully integrated with your eDirectory tree. No more will you need to maintain separate user accounts for your email system. If you add a user to a context supported by your NMAP Agent, he or she automatically has an email account. In all but the smallest of organizations, this can amount to a huge time (and cost) savings.

## Summary

In this chapter, you learned about the features and benefits of NetMail. You learned that NetMail is fully integrated with eDirectory, is easy to deploy, is modular, and is highly scalable. You also learned that NetMail's modularity is created using modular agents, including the following:

- Address Book Agent
- Alias Agent
- AntiSpam Agent
- AntiVirus Agent
- AutoReply Agent
- Calendar Agent
- Connection Manager Agent
- IMAP Agent
- List Server Agent
- Modular Web Agent
- NMAP Agent
- POP Agent
- Proxy Agent
- SMTP Agent

You also learned that installing NetMail extends the schema of your eDirectory tree, adding several new object classes as well as new attributes to your organization, organizational unit, server, and user objects.

You then learned about the directories in your Linux server's file system that are used for the Message Store and the Message Queue. You also learned that the NetMail system is configured using the WebAdmin utility, which is separate from the iManager utility you've used to configure other NLM products.

You learned that NetMail creates two files when it receives an email message: a control file and a data file. You then learned about the nine stages that these files progress through as they are processed in the NetMail system.
