### Checking or Repairing a File System

The native Linux filesystem (*ext2*) does not need to be defragmented. However, occasionally, you may need to check a partition's file allocation and make repairs.

Type: `fsck OPTIONS FILESYSTEM` or `fsck OPTIONS MOUNTPOINT`.

Note that:

- By default, repairs are done without prompting.
- Two ways of specifying a filesystem exist. You do not need to specify a filesystem if you use the `-t` or `-A` options.
- This check is also run when the system starts if it was not shut down gracefully or after a predefined number of reboots.

> Linux partitions do not need defragmenting. `FAT16` and `FAT32` filesystems can be defragmented under another operating system.

### The `fsck` Command (Checks Filesystems)

| Option | Action | Comment |
| :--- | :--- | :--- |
| `-A` | Checks all filesystems listed in `/etc/fstab`. | |
| `-r` | Prompts before each repair is done. | |
| `-R` | Checks all filesystems listed in `/etc/fstab` except the root partition. | Use with `-A`. |
| `-t TYPE` | To only check filesystems of a certain type | Common types are:<br>- `ext2`: The native Linux format.<br>- `swap`: Linux swap file. Use only for the swap file.<br>- `vfat`: The format for Windows 98, ME, and the second release of Windows 95.<br>- `iso9660`: CD drive |

## 13 Configuring the System

Progeny Debian automatically configures your system during installation. However, you may need to use other configuration methods if:

- Your system works, but some settings can be improved.
- Your system works, but you want to lower the settings to save system resources or improve speed.
- You want to make adjustments based on personal preferences.
- A device is not detected.

This chapter explains how to set up basic hardware, as well as many parts of your everyday working environment, including:

- Hardware.
- Partitions.
- Networks and internet connections.
- Graphical Displays.
- Other Settings.

### Understanding Configuration Methods

Linux includes dozens of configuration tools, from command line utilities that ask you questions to graphical interfaces. However, the most common methods for configuration in Progeny Debian are:

- `dpkg-reconfigure` TOOLS: Configures using simple question and answer dialogs. Two useful tools are `ethernet` and `pppconf`.
- GNOME Control Center > System: The same tools that you used during the install are available there.
- Manually editing the necessary configuration files: This method requires exact knowledge, but allows complex configuration and is always available so long as you have a text editor.

> **Note**
>
> Hardware connected with the graphical display including the monitor, video card, and pointer can be configured by editing the profiles in the `/etc/X11/Xf86Config-4` file. In each section of the file, the first profile is used by default.

- Recompile the kernel: This method requires exact knowledge, and can be intimidating to new users. However, it may be necessary, especially if hardware is undetected.

### Understanding the System Settings

Progeny Debian includes the tools used to configure during the install as part of the GNOME Control Center.

1. Do one of the following:
    - From the panel, select the Control Center icon from the panel.
    - From the menu, select Settings > System.
    - From the menu, select Programs > Settings > System.

2. Select the configuration tool to use. Choices are:
    - Date and Time.
    - Electronic Mail.
    - Network.
    - Printer.
    - X Configuration (Display).

### Understanding Manual Configuration

Most configuration files are found in the `/etc/` directory. Configuration files can be changed in a text editor.

Dozens of text editors are available, but you should learn either a variant of `vi` or `emacs`. At least one of these editors should be available on any Linux system. By default, Progeny Debian uses `vim` ("vi improved") editor.

Manual configuration is especially useful if you are using single-user mode, or do not have the X Window System running.

For more information on your preferred text editor, see its on-line help.

1. Prepare an emergency disk if you do not already have one.
2. Log in as root.
3. Make an extra copy of the file you are editing.
4. Edit and save the file in a text editor.

> **Note**
> As an extra precaution, write down the changes you have made.

5. In some cases, you may have to restart the X Window System or your computer for the changes to take effect.

### Recovering from Errors While Manually Reconfiguring

If changing settings may make your system unusable, you can recover by following these steps:

1. Start your machine with a boot disk or select single-user mode from the boot manager.
2. Type: `cp -f BACKUP FILE`. The backup of the configuration file overwrites the damaged file.
3. Restart your system. The damage to your system is now repaired.

### Using the vim Text Editor

The *vim* editor is an enhanced version of *vi*, one of the standard text editors.
Like *vi*, *vim* has two modes:

- Command mode: For entering keyboard commands about the program or the file being edited.
- Insert mode: For editing a file.

Type *vim* to start. To open *vim* with a file, type `vim FILE`.

### Recompiling a Kernel

The Linux kernel contains the drivers for hardware, filesystems, and other features of the operating system.

Since most types of hardware or feature has its own modules, you can make your operating system quicker and more efficient by only loading support for what is actually on your system.

You may need to reconfigure the kernel when you add or remove hardware or other features. You can temporarily enable a module, with the `modprobe` command. However, if you reboot the system, you will need to use the command again.

Making permanent changes to the kernel consists of three steps:

1. Editing the kernel.
2. Building or compiling the kernel.
