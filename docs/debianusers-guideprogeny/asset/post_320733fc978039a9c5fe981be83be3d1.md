## Setting the Priority for a Process From the Command Line

Linux assigns priorities for processes. However, you can set your own priorities.

**Type:** `nice -n ADJUSTMENT COMMAND`.

In this structure:

- The adjustment is a number with a range from -20 (highest priority) to 19 (lowest priority). Only the root user can use a negative priority (-1 to -20).
- The command includes any options or arguments.

> **Warning**
>
> Changing a process’s priority may cause problems on your system, especially on systems with limited hardware resources or a large number of users.

## Backing Up and Compressing Files

Regular backups are a basic precaution against loss of data due to security leaks, power loss, or user carelessness.

> **Note**
>
> Use backup commands with crontab to have automatic, regularly scheduled backups. See “Backing Up and Compressing Files,” page 319.

Linux supports most backup devices that use IDE or SCSI standards, or use a parallel port. These devices include tape, zip and iomega drives, as well as removable hard drives. However, for some of these devices, you may need to install a package that is not installed by default. Be prepared to do some research before backing up to such devices.

### Planning a Backup

Before doing a backup, plan it carefully. Consider:

- Which files are irreplaceable without a backup. Irreplaceable files probably include those in users' home directories (including /root/), and configuration files, such as those in the /etc/ directory.
- Which files are on removable drives, such as CDs or floppies. Since you probably do not need to back up removable drives, you might unmount them before doing a backup.
- Which files can be easily replaced by installing a package or doing a selective install or upgrade of the operating system. You can save time and storage space by not including these files in a backup.
- Which files are unnecessary or dangerous to backup. For example, files in /tmp are probably unnecessary, while restoring some files that are in the /proc directory could crash the system.
- Whether to compress files using zip or bzip2. Compressing saves space, but adds another step to the backup. Also, while compression is generally reliable, it creates another stage at which the process can fail.
- Whether users are responsible for backing up their own files. Since only the root user has full permissions for all files on the system, usually backups are best done by the root user.

### Choosing a Backup Tool

Linux has several tools for backing up and restoring files:

- **dump / restore**: Old tools that work with filesystems, rather than files, and can back up unmounted devices. Although you can easily control what is backed up with dump by editing a single column in the /etc/fstab file, for some reason these utilities have fallen into disuse. Today, many distributions of Linux, including Progeny Debian do not even include them by default.
- **tar**: A standard backup tool, and by far the easiest to use. It is especially useful for backing up over multiple removable devices using the -M option. See “The level of compression..”, page 336.
- **cpio**: A very flexible command, but one that is hard to use because of the unusual way in which the command must be entered.

Many commercial or free software backup tools are also available.

### Backing Up and Restoring Using the cpio Command

The cpio command is one of the most commonly used Linux backup tools. The cpio command has two unusual features:

- Unlike tar, in which the files to work with are typed in as part of the command, cpio reads the files to work with from the standard input (in other words, the screen).
    This feature means that cpio must be used as part of a multiple command or with a redirection pipe. Examples of this usage are shown in the tables below.
- cpio must always be used with one of three flags. Flags are options that set the mode in which the command runs.
    Only one flag can be used at a time, and it must come before any other options. In addition, the choice of flags limits the options that can be used.
    Each flag also has a GNU option that can be used in its place. The GNU option gives a convenient name for each flag: extract, create, and pass-through.

#### The cpio Command (Backup and Restore)

| Flag | GNU Option | What it does |
|---|---|---|
| -i OPTIONS STRING | --extract | Restores files from an archive that match the string. Metacharacters can be used in the string. See “Using Metacharacters or Wild Cards,” page 118. Strings should be surrounded by double quotation marks. |
| -o OPTIONS | --create | Backs up files to an archive file. |
| -p OPTIONS DIRECTORY | --pass-through | Copies files to another directory on the same system. This option is useful for repeating a backup that is later burned to a CD. |

#### Backing Up using the cpio Command

To do a backup, use cpio with a search command, such as find. See “Searching for Files: Using the find Command,” page 182.

The basic structure is: `find -name STRING -print | cpio -o OPTIONS > DIRECTORY`.

In this structure:

- The -name option for find lets you search for a string enclosed in double quotation marks. Metacharacters can be used. See “Using Metacharacters or Wild Cards,” page 118.
- The bar character (|) redirects the output of find to cpio.
- The -o flag sets cpio to create an archive file for backing up.
- The target is a directory.
- The > redirection operator redirects files to the location for the backup. Typically, this location is on a removable device.

##### The -o Flag in the cpio Command (Backup)

| Option | Action | Comments |
| :--- | :--- | :--- |
| -A --append | Adds files to an existing archive. | |
| -v --verbose | Displays progress on screen. | |

#### Restoring Files Using the cpio Command

To restore files from an archive file, use cpio with a redirection pipe. Type: `cpio -i OPTIONS STRING < TARGET`.

In this example:

- The -i flag sets cpio to restore files.
- The string describes the files to restore. Metacharacters can be used. See “Using Metacharacters or Wild Cards,” page 86.
- The < pipe redirects the files described by the string to the target.
- The target is the directory to which to restore files.

##### The -i Flag for the cpio Command (Restore)

| Option | Action | Comments |
| :--- | :--- | :--- |
| -f --non-matching | Copies all files except those that match the string | |
| -m | Keeps previous modification time on restored files. | |
| -d --make-directories | Makes directories as needed. | |
| -u --unconditional | Overwrites old files. | |
| -R USER GROUP --owner USER GROUP | Reassigns file ownership. | This option can only be used by the root user. If no user is specified, the root user becomes the owner. |
| -r | Renames files. | Provide new file names when prompted. |
| -t -list | Displays files in the archive. | Use with the -v option to display file attributes |
| -v -verbose | Displays progress on-screen. | |

### Copying Files for Later Backup

At times, you may not want to copy files directly to the backup device. You might want to prepare the backup first in order to see its size, or to compress the files before backup.

Similarly, if you are creating a CD, copying the files directly to the CD is unreliable or difficult with some CD burning software. The -p option for cpio is designed for all such circumstances.

To do a copy for later backup, use cpio with a search command, such as find. See “Searching for Files: Using the find Command,” page 182.

The basic pattern is:

`find -name STRING -print | cpio -p OPTIONS > TARGET`.

In this example:

- The -name option for find lets you search for a string enclosed in double quotation marks. Metacharacters can be used. See “Using Metacharacters or Wild Cards,” page 86.
- The bar character (|) redirects the output of find to cpio.
