If you start using LVM, you lose control on which (physical) device data is stored. As long as everything goes well, this doesn't really matter. # More useful additions

The usage of LVM will make the administration of large servers easier, but private users may also benefit. If a file system becomes full without LVM, you needed to backup up your data and repartion your hard disk. With luck, you could use a free partition, but it is easy to make mistakes here lose your data.

With LVM, full file systems will never happen. The system administrator can extend the file system at the right time. Especially if you use ext2online you will have a longer uptime for your users.

If you run a server containing file systems, you know that a file system check after a crash may run for a long time. Crashes are bad, and are made worse if the reboot takes a long time so your users can' access the server. There are several projects that implement or port a journaled file system. Every change is logged in a log or journal and in a crash, only the log to be checked, replayed and cleaned. Current projects are ext3, an extension of the ext2 file system, reiserfs, a completely new file system, a port of IBM's JFS from OS/2 and a port of XFS from IRIX.

# 4.6 Printing under LINUX

Before we start printing under LINUX, the kernel must first recognize and initialize the corresponding printer port, for which either a parallel or serial connection can be used. Here and in the following chapters, we assume that the printer is connected to the parallel port. The driver for this port can either be compiled into the kernel during kernel configuration or be loaded later as a module (see also Section 4.1.1). If the driver was compiled into the kernel, a message similar to the one shown in Listing 4.26 should be displayed after a restart of the computer.

```
lp1 at 0x0378, using polling driver
```
