# Automatic rotating of log files

The log rotate can work with arbitrary files, old logs can be deleted or compressed, an arbitrary count of old versions can be kept, and you can execute any command you wish before or after the rotating of the logs. Logs can be rotated daily, weekly, or monthly, or depending on the size of the log file. logrotate is not integrated in syslog, but apart from that almost everything you can wish for is implemented.

logrotate's option create creates an empty file with the corresponding owner, group, and permissions. Listing 4.31 is an example of a simple configuration. More information is available in the main page logrotate(8).

```
# Log file get rotated weekly
weekly
# keep four versions
rotate 4
# please send error message to 'root'
errors root
# create new log files as default
create
# More configuration in that directory.
include /etc/logrotate.d
```

**Listing 4.31** A simple configuration for logrotate.

The configuration in listing logrotate.conf is for all files that logrotate rotates. You can override the configuration for each file as needed. The directory /etc/logrotate.d is a storage pool for other packages that logrotate configures. That each package that writes log files can easily drop in a configuration file for logrotate. Examples for such packages include UUCP, apache, or samba.
