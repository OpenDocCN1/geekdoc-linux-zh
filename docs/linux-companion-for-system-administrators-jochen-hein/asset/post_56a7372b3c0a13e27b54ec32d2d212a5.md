# The standard editor vi

Hated by many and loved by some, vi has become the standard editor for UNIX systems. Prior to vi, there were only line editors (such as ex or ed), now (meaning from around 1978) you can edit 'visually,' that is, you can view a large section of the text and all modifications you make are shown immediately. This was when the environment variable VISUAL came into being which, together with EDITOR, is used to select the standard editor.

Both editors are largely compatible with their archetype, but have some extended functions. vi, for example, can mark text columnwise and has a macro recorder. In the context of freely available systems (*BSD and GNU), nvi is employed as a vi clone. Here, the aim is to develop a truly compatible clone which has the bugs of the original.

It is highly recommended that you make yourself familiar with the basic functions of vi. vi is usually the only editor to be found on boot or emergency disks because of its reduced size (about 100 Kbytes for small clones). Furthermore, this editor, in contrast to Emacs and other free editors, stands for 'visual' because changes to the text are immediately displayed on screen. If the program is called with the name ex, only the line mode is used. If you only want to view a file, you can load it read-only into the editor by means of view.

The simplest case is vi filename. The vi editor works in different modes (command mode, insertion mode, and command line mode) in which the keyboard is differently mapped. This differentiation originated from the requirement to be able to use vi in a reasonable way even with slow terminals and network connections. Today, this kind of handling looks antiquated, but as soon as the keyboard come straight from your fingers rather than from your memory, working with vi is easy.

After loading the text, you will normally be in command mode. In mode, commands are triggered by simple keystrokes. Thus, the key does not cause the letter x to be displayed on screen, but the character under the cursor to be deleted. In command mode, nearly every key calls a specific command. Commands are expressed as upper case, in which case the character key must be pressed together with the Ctrl key. Other commands require simultaneous pressing of the Ctrl key.

Other more complex commands can be input in command mode which you enter by pressing the colon. Therefore, this mode is also known as colon mode. An overview of the most important commands is shown at the end of this appendix in Table A.1.

From command mode, you can switch to other modes by pressing specific keys. The most important modes are the insertion mode, which is activated by pressing the i key, and the command line mode, which is reached by pressing the colon. To return from insertion mode back into command mode, you must press the Esc key. If you do not know which (or where) you are, you should simply press the Esc key. The worst that can happen is that you will have a beep.

If existing text is to be overwritten, this is best done in overwrite mode. This mode is accessed by pressing Shift-r. If you only want to replace a single character, you can do in command mode by pressing r followed by the new character. Text can be deleted by pressing the x key. If a whole line is to be deleted, you need to press the d key.

If you want to move around your text file, you can usually do this using the cursor keys, but only in command mode (this may, however, depending on version and terminal mode). If the terminal adaptation does not match, you can still move around the document in command mode, by pressing h to move left, l to move right, j to move down and k to move up. Pageweight through a document is possible by pressing Ctrl-f to move forward and Ctrl-b to move backward. A disadvantage of the cursor keys is (depending on the compatibility of the vi clone) that they trigger a command. Afterwards, you can neither undo your last command with u nor repeat it with . (in the original vi: most clones work better).

To save the file, you need to enter :w in saves the file under its current name. If the file is to be saved under a different name, this name can be specified, for example, :w filename. If the file is protected, you can overwrite it in spite of this by :w!.

You can quit vi by entering q. If the document was changed, you are advised of this by the message 'Use q!' to abort changes, or wq to save changes. You have the possibility of saving the document and terminating vi wq or discarding the changes to the document and simply terminating vi q!

Many commands can be executed by means of a numeric prefix. The key combination 5x in command mode, for example, deletes the next five characters. There are also shortcuts for many functions, such as for example w or d for 'change word' or 'delete word' respectively. You can search a string with / and find the next occurrence of a word with n. You can search through a document with /.

Obviously, vi can also search and replace. The notation used for recalls of sed (Section 10.6). First of all, search and replace is a colon command, that, it must be entered in command mode. Then you must specify the range in which replacement should take place; this can be done by means of line numbers (here, the :set nu command is very helpful) or search expressions.

The command for search and replace is s, followed by the search term and the replacement. If the replacement is to be executed repeatedly, a g must be appended. If this sounds complicated, here is a brief example.

```
$1 s/sought/replaced/g
```

In the whole text (from line l to end), the character string is replaced. This syntax, which initially appears quite complicated, makes vi very flexible. This certainly does not exhaust the power of vi. For example, vi is able to cooperate with auxiliary programs, such as ctags, and is therefore employed by many programmers and system administrators.

Users can define their own macros or adapt vi to their own requirements. The configuration file for vi is ~/.vimrc. Here you can define (your own) function keys and carry out other settings.
