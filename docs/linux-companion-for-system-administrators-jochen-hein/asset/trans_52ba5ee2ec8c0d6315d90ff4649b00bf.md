## 2.3.4 /etc - 本地系统配置

如今，只有配置文件存储在 /etc 目录中。在旧的 UNIX 或 LINUX 系统中，存储在此处的所有程序现在可以在 /sbin 或 /usr/sbin 下找到。因此，即使是 root 用户，其程序搜索路径中不再包含 /etc 目录，而是 /sbin 和 /usr/sbin 目录。

为了进一步结构化，标准针对一系列程序建议了以下子目录：

- /etc/rc.d 包含系统启动期间创建的脚本。这既适用于 Slack 发发安装的 System-V 类 init，也适用于“真正的”System V Init。系统启动的功能和不同的配置将在第 3 章中更详细地讨论。

- /etc/skel 包含了 adduser 程序复制到新用户主目录的文件。这允许在用户首次登录之前为新用户设置特殊环境。合理的文件选择可能是 .profile、.login、.bashrc、.emacs 和 .inputrc，这样就可以设置路径并让用户找到一个无需修改即可开始使用的环境。这可能是一个系统级或网络级的标准配置，有助于新用户首次接触系统并简化用户支持。

- /etc/X11 用于特定机器的 X 配置，其中也包括 XF86Config。然而，XFree 86 将无法在此位置找到该文件，因此必须建立相应的符号链接（例如从 /etc/X86Config）。此外，还可以为各个窗口管理器和 X 显示器 xdm 创建子目录。此时，/etc/X11/xdm 目录存储了以前可以在 /usr/lib/ 下找到的配置文件。

## 2.3.5 /home - 用户主目录

除了用户自己的主目录外，用户在文件系统中只有极少数点具有写访问权限。如果可能的话，主目录应该存储在单独的分区上，这样这些数据就不会受到系统重装的影响。这种解决方案在系统数据和用户数据备份之间提供了良好的隔离。

另一个优势是“硬件配额”，它确保用户只能向其 /home 分区填充数据。这维持了系统的整体性能。如果根分区、tmp 或 /var 分区满了，系统性能可能会受到影响。因此，Extended-2 文件系统创建了一个预留空间，该空间只有系统管理员可以使用。可以使用 tune2fs 程序来指定预留块的百分比以及允许使用这些块的用户。请参阅挂载分区上的 tune2fs 手册。

从内核 2.0 开始，长期以求的配额支持已被纳入标准内核。这使得为单个用户或用户组分配指定的硬盘空间部分成为可能。它区分了可以临时覆盖的软限制（soft limit）和防止进一步写入尝试的硬限制（hard limit）。在许多（拥有合理用户）且磁盘空间有限的计算机上，使用配额是一种明智的预防措施。

/home 目录的使用是 Linux 的特性，但它被广泛应用，其目的显而易见。其他 UNIX 系统使用 /usr/users 或类似的目录。这些目录通常会进一步细分为不同的用户组，例如学生、员工或系统管理员。然而，最终的划分是系统管理员根据本地需求应该做的决策。

程序（以及用户）不应直接通过名称引用主目录，而应使用 shell 变量 HOME，或者根据 shell 的不同使用带有波浪字符 (~) 的短形式。

## 2.3.6 /lib - 共享库

这是启动所需的所有共享库的存储地。Linux 内核为其他进程提供内部信息。因此，例如 ps 程序读取 /proc 文件系统以获取当前运行进程的信息。

显示网络统计的程序通常使用 /proc 文件系统。因此，此文件系统在所有 Linux 计算机上应该是可用的，并应该挂载在此位置。为了实现这一点，你必须对“proc 文件系统支持”问题回答“y”，并且 /etc/fstab 文件应包含相应的条目。目前的发行版都是如此。

## 2.3.7 /mnt - 临时挂载

经常，系统管理员必须快速挂载另一个文件系统。可能是硬盘、软磁盘或网络设备。为了这个目的，可以使用 /mnt。

## 2.3.8 /opt 中的附加软件包

/opt 目录用于存储系统之外安装的大型程序包。对于每个软件包，应该创建一个独立的 /opt 目录。可执行程序存储在 /opt/bin 下，手册页存储在 man 目录下。

## 2.3.9 /proc - 进程信息

/proc 文件系统并不真实存在，因此不占用硬盘上的任何空间。在这里，Linux 内核为其他进程提供内部信息。因此，例如 ps 程序读取 /proc 文件系统以获取当前运行进程的信息。
