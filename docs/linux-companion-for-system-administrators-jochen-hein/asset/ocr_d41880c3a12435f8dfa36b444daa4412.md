These are the default splitting. You are requested to use only a small number of IP addresses with a special netmask (the number of bits used for the network addresses). This is called subnetting; see Section 13.5.1 for details.

You can not only specify the IP address as a group of four bytes, but also as an integer number, for example, telnet 2137064433 instead of 127.0.0.1. On the basis of an IP address a.b.c.d this number is calculated via the formula a*256²+b*256²+c*256+d. Input of an IP address by means of this formula can confuse even-boiled system administrators.

If your internal network is not to (continuously) connected to the Internet, it is often impossible to obtain an official IP address for all computers, because the available address space is limited and may be nearly exhausted through the rapid growth of the Internet. This situation will change with the introduction of IPv6, which significantly increases the available space.

For such cases, there are numbers reserved by the Internet (see Table 13.3). [rfc1918] which are not routed in private networks, even if these are later to be connected to the Internet. For this case too, [rfc1918] gives some hints on how to prevent all computers from being given a new IP address later. [rfc1627], in contrast, points out the problems you can run into using internal addresses.
