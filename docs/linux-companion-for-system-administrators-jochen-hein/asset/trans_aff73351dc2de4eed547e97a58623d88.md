

## /proc 文件系统

/proc 文件系统的另一个有趣应用是可以在调试器中观察运行中的 LINUX 内核。虽然你不能设置断点，但你仍然可以查看内部数据结构：

```gdb
(Linux):~$ gdb /usr/src/linux/vmlinux /proc/kcore
```

为了与其他系统兼容，你可以建立一个名为 `/dev/core` 的符号链接，指向（虚拟）文件 `/proc/kcore`。该文件包含调试器所使用的 'core' 格式的内核内存映像。

## 2.3.10 /root - 系统管理员的家目录

传统上，用户 root 的家目录是 `/`。这导致了一个实际上无法避免的后果：在 `/` 下创建了许多文件，这使得根目录变得太大，而无法清晰地概览系统。为了保持该目录条目的数量较少，如今通常使用 `/root` 目录作为系统管理员的家目录。

然而，此目录应该位于根分区上，以便在挂载了其他分区时系统管理员仍能登录。某些登录程序在 `/etc/passwd` 文件中指定的目录不可用时会自动使用 `/` 作为家目录，但也有程序会拒绝登录。在这种情况下，用户 root 将被锁定在系统之外。

给 root 用户的电子邮件应重定向到普通用户；这可以通过创建一个 `~/.forward` 文件来实现，该文件包含接收邮件的用户用户名，也可以创建一个 sendmail 别名。同样，不应使用 root 用户来读取或写入新闻，或每天在系统上进行日常工作。

## 2.3.11 /sbin - 系统启动所需的系统程序

`/sbin` 目录包含了在 `/usr` 文件系统挂载之前启动所需所需程序，以及只有系统管理员需要的程序。非特权用户也需要的程序应该存储在 `/bin` 或 `/usr/bin` 中，以防止这些用户在搜索路径中拥有 `sbin` 目录。安装在 `/sbin` 目录中的重要程序包括：

- `init` 程序，负责系统启动。系统管理员可以使用它更改运行级别——即 LINUX 系统的运行模式——例如将系统切换到网络服务器模式。

- 用于文件系统维护和修复的程序，例如 `mkfs`、`fsck` 和 `fdisk`。该组还包括 `mkswap` 和 `swapon` 程序。特别是对于主内存较小的计算机，在创建或检查文件系统之前，通常需要创建额外的虚拟内存。

- 网络程序，如 `ifconfig` 或 `route`，用于在系统启动时初始化网络，并确保可以通过 NFS 挂载 `/usr` 分区。

用户在日常操作中使用的程序（如 `ping`、`shells` 或 `tar`），如果系统启动或恢复操作需要，应该安装在 `/bin` 目录中。出于系统安全考虑，`/bin` 和 `/sbin` 目录并没有分开。因此，这些目录可以（也应该）对所有用户可读，其中包含的程序应该是可执行的。对于 `setuid` 或 `setgid` 程序，显然是有合理的例外的（见第 4 章）。

## 2.3.12 /tmp - 临时文件

该目录是程序创建临时文件的地方。然而，并没有规定这些文件应该保留多久。在内存容量大的计算机上，`/tmp` 目录可以位于 RAM 磁盘上。FHS 建议每次重启时都删除 `/tmp` 目录。

在其他 UNIX 系统中，标准做法是在每次系统启动时或按给定的时间间隔删除 `/tmp` 目录。对于后者，你可能需要根据特定需求调整列表 2.1 所示的脚本。该 shell 脚本会删除过去三天内未读取过的文件以及旧的空目录。

```bash
if [ -d /tmp ]; then
  cd /tmp; find -type f -atime +3 -exec rm -f {} \;
  find . ! -name -type d -atime +1 \; -exec rmdir {} > /dev/null 2>&1;
fi
```

列表 2.1 删除 /tmp 目录。

请注意，此脚本设计时没有考虑安全性，可能会导致系统的非特权用户删除任意文件。Red Hat 发行版包含为此目的开发的 `tmp` 程序，该程序考虑了安全性。对于你的家用电脑，简单的脚本显然足够了，但在更复杂的环境中，它绝对不够安全。

`/tmp` 目录必须对所有用户可写，因为许多程序使用它来创建临时文件。例如当调用外部编辑器时的 `cronab` 或邮件阅读器。如果 `/tmp` 目录不可写，绝许多程序将直接退出，导致崩溃原因不明确。出于安全考虑，该目录应设置 `t` 位，以便用户只能删除自己的文件。

同样，如果 `/tmp` 目录满了也很令人恼。如果你的计算机运行异常，请查看 `/tmp` 目录的内容、访问权限以及可用的磁盘空间。

## 2.4 /usr 层级结构

在许多 LINUX 系统上，`/usr` 文件系统占据磁盘空间的大部分。发行版提供的大多数程序都安装在这里。此处描述的相同结构可以（也应该）在 `/usr/local` 重建。系统管理员除了安装发行版提供的程序外，在此安装计算机本地所需的所有程序。

`/usr` 文件系统包含可以被不同计算机使用但不需要写权限的数据。这允许 `/usr` 文件系统通过 NFS 挂载为只读保护，或者通过 CD 挂载“活动”文件系统。这是购买新硬盘的替代方案，特别是当硬盘空间很小时时。

对于如 TeX 或 emacs 等大型程序包，不应直接在 `/usr` 下创建目录，而应该在 `/usr/lib` 下使用新目录。此旨在防止 `/usr` 目录变得太大且太复杂。表 2.3 显示了 `/usr` 下通常找到的目录概览。

| /usr | /usr 目录 |
| :--- | :--- |
| - X11R6 | X Window 系统 |
| - bin | 所有的程序 |
| - games | 游戏 |
| - include | C 程序的头文件 |
| - lib | 库和程序包 |
| - local | 本地安装（初始为空） |
| - sbin | 系统管理员使用的程序 |
| - share | 与架构无关的数据 |
| - src | 各种程序的源代码 |

表 2.3 /usr 层级结构概览。

| :--- | :--- |
| /usr/adm | /var/adm |
| /usr/preserve | /var/preserve |
| /usr/spool | /var/spool |
| /usr/tmp | /var/tmp |
