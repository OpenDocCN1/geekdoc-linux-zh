If you don't add any special options to vgcreate the size of the volume group is restricted to 256 GB. The option -s allows you to enter another value than 4 MB for the size of a physical extent (this is the size LVM uses internally). Note that the number of physical volumes and logical volumes is restricted to 256. In any case, this number should only be reached on very large servers.

The opposite command to vgextend, which adds a physical volume to a volume group, is vgreduce. You can only remove an unmounted physical volume from the volume group. pvdisplay shows which volumes are used; the option -v (for verbose) creates more output. Here you will find which logical volumes are stored on that physical volume. The command pvmove allows you to move data without interrupting the service.

Other commands for volume groups are vgchange (to change a volume group), vgdisplay (to display data of a volume group), vgrename (to rename an inactive volume group) and vgscan (to scan for volume groups).

If you need the data of a volume group on another system, you must first remove the volume group from your system. The file systems must be unmounted and the volume deactivated by vgchange. The command vgexport exports the volume group from your system. You can now move the hard disks to another system and import the volume group with vgimport. You can now use the data as if it had been created on that system.

The logical volume manager manages a lot of important data. You should back up the data in the file systems as well as the meta information about the volume groups and logical volumes. The LVM stores that data in the file /etc/lvm.conf. The commands vgbackup and vgrestore save the meta information. Every volume group has a directory under /dev with its name. In that directory you will find the devices for the volume group and each logical volume.

# More useful additions

The usage of LVM will make the administration of large servers easier, but private users may also benefit. If a file system becomes full without LVM, you needed to backup up your data and repartion your hard disk. With luck, you could use a free partition, but it is easy to make mistakes here lose your data.

With LVM, full file systems will never happen. The system administrator can extend the file system at the right time. Especially if you use ext2online you will have a longer uptime for your users.

If you run a server containing file systems, you know that a file system check after a crash may run for a long time. Crashes are bad, and are made worse if the reboot takes a long time.

## 4.6 Printing under LINUX

Before we start printing under LINUX, we check as to whether the printer can be accessed. As root, you can simply perform this check by means of the command cat /etc/passwd > /dev/lpi. Immediately after this command, the driver should begin to print. Depending on the printer type, different problems may occur.

One phenomenon occurring with many printers is what is known as the staircase effect. This means that a new line is not started in the first column of the next line, but after the last character of the previous line. This is because under LINUX (and UNIX) the individual lines of a text are separated by means of the character LF (line feed). In texts under DOS, this separation is carried out by means of the character combination CR and LF (carriage return and line feed). Many printers are configured in such a way that the CR and LF characters are mandatory to begin a new line. This problem can be solved in two ways:

- Before printing, the text can be converted, for example by means of the recode program (see also Section 8.8) or a short sed script (see Section 10.6).
- The printer can be configured in such a way that the LF character is interpreted as CR+LF, either by means of a control sequence or with a changed setting of the printer's DIP switches. Even when used under DOS, this setting has no negative consequences the second CR is ignored. Consult your printer manual.

A further problem is that LINUX uses the ISO-Latin-1 character set, whereas DOS generally uses code pages 437 or 850. Thus, umlauts and other special characters are coded differently, so you can reconfigure the printer by means of an appropriate control sequence or the DIP switches, or you can convert the text accordingly, once using the recode program.
