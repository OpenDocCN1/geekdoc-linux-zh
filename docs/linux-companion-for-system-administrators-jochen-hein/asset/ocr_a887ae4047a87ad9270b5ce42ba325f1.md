The fifth column contains the user name under whose ID service is carried out. If you also want to change the group, you can specify this by separating it with a dot. Many daemons must be started with root privileges. For some of the services (for example finger) it may be sensible for security reasons to start the service as nobody or under another ID.

The next entry is the name of the program to be started, together with possible parameters to be passed. The parameters begin with arg[]; that is, the program name itself. Older UNIX systems limit the parameters to five entries, so you may be required to start a script that calls the server with the appropriate parameters.

The inetd server provides some simple services (echo, discard, charg, daytime, time). For these, internal is entered as the program.

After modification of the file inetd.conf, the daemon must re-read this file, or it can either be terminated and not started, or can be sent a SIGHUP signal, for example with the command kill -HUP 'cat var/run/syslog.pid' or the command killall -HUP inetd.

Generally, the inetd server will allow any connection; authorization is the responsibility of the individual applications. Many applications do not have such procedures; thus, a computer that provides Internet services is relatively vulnerable. Therefore, a local network is usually separated from the Internet by means of a firewall, which can also be installed under LINUX. The maintenance of a firewall requires much time and knowledge, and is usually too expensive for a private user.

# 14.3 The TCP wrapper (tcpd)

A measure of protection is implemented by the TCP wrapper (tcpd). This program is started instead of the true daemon. It checks whether the connection is legal on the basis of the files /etc/hosts.allow and /etc/hosts.deny and makes it possible to release or block specific protocols for specific computers or networks. This relies on the assumption that a computer actually has an IP address under which it wants to establish a connection. Feigning of another IP address is also known as IP spoofing. By means of targeted research, the TCP wrapper tries to exclude possible spoofing attacks. Additional information on these subjects can be found in the man page tcpd(8).
