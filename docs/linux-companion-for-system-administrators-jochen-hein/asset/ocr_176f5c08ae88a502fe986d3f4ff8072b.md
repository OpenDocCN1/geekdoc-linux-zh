# 10.1.6 Excessive length parameter lines

The xargs command generates a command line from the standard input which is passed to the specified command. If the command line exceeds the maximum length, the specified command is called several times in a row or simultaneously. With the use of xargs, the error message ‘Command line too long’ will never appear again.

If you want to search files for specific text using the find command in combination with the grep command, grep supplies the lines in which the sought text is found, but not the file name. There are several possibilities for solving this problem:

+   - You can pass grep the file /dev/null as an additional parameter.
- If the output of the file name is sufficient, you can pass grep the option -1.
- Several files at a time can be searched with xargs. An example can be found in Listing 10.14.

Because the grep command is not called separately for each file, as find would do with the -exec option, the file names are now output as well. Furthermore, this variation ‘friendlier’ to other users since it employs further system resources in processes, memory, and processor time.

```
(Linux):# find /etc -type f -print | xargs grep LUEN02
/etc/hosts:192.168.10.1 LUEN02.goe LUEN02
/etc/HOSTNAME:LUEN02.goe\LUEN02.goe
/etc/dr/rc.net1:/sbin/ifconfig dummy LUEN02
/etc/dr/rc.net1:/sbin/route add LUEN02
/etc/hosts,v:127.0.0.1         LUEN02.goe LUEN02
/etc/hosts,v:127.0.0.1         LUEN02.goe LUEN02
```

Frequently, a series of files has been renamed. Unfortunately, the command can rename only one file at a time (mv *.c *.bak does not work because of the expansion of the asterisks by the shell). Instead, you can use either a small for loop, or the mv command, or the xargs command with the option -n -i.
