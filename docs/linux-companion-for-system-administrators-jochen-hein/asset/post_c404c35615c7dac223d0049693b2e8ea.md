
## 10.7.4 Displaying the beginning of files

It is often sufficient to display the beginning of a file to find out about the contents or the topicality of the file. The use of programs as more or less is completely unnecessary. The tiny program head fulfils exactly this purpose and by default displays only the first ten lines of a file. With the option -n lines or, shortly, -lines, an arbitrary number of lines can be displayed. With the option -c bytes, a certain number of bytes can be displayed.

## 10.7.5 Displaying the end of a file

The counterpart of head is tail, which displays the end of a file. BSD versions of tail are capable of outputting relatively small files in reverse order. GNU project uses the tac program for this purpose.
Analogy to head, the option -n lines displays the last lines. If the option +n lines is specified, display begins starting with this. Thus, tail can also be used to split a file into several parts. Usually, however, you would employ the split program for this task.

Frequently, one needs to look at a log file which continues to grow. Programs such as more read the entire file, so that newly added messages are not immediately displayed. With the option -f, tail instead shows the up-to-date end of the file.

## 10.7.6 Displaying character strings in binary files

The strings program allows you to filter character strings out of binary files. This can be useful, for example, to establish which files the program is going to access, or to detect 'hidden' functions. The GNU strings (from binutils), by default, does not read all parts of a program, so the switch -a should be set.

## 10.7.7 Analysing binary programs

The LINUX tool strace is used to 'debug' compiled programs. All system calls are listed too. Thus, for example, you can find out which files are accessed by the program. By means of the command line parameter -o filename, the output of strace can be written to the specified file. Furthermore, it is possible to restrict the system calls to be listed by setting the option -e=syscall.

Another useful program is ltrace which traces calls rather than System calls. If a library call fails, strace will not display the call but ltrace.

## 10.7.8 Displaying files in different formats

Sometimes it is necessary to analyse a file in more detail. In many cases, programs such as strings achieve good results, but sometimes you need an accurate value of the individual characters contained in the file. In such cases, you can employ the od program. By default, od displays the data in octal representation, but you may choose a different one. Listing 10.52 shows some simple examples of formatting output with od.

```
(Linux):> echo Hello World ' | od
0000000 044145 066c 06740 035537 071154 062012
0000013
(Linux):> echo Hello World ' | od -x
0000000 4865 6120 5761 726c 640a
0000013
(Linux):> echo Hello World ' | od -a
0000000 H e l l o s p W o r l d nl
0000013
```

## 10.8 The shell as a connecting link between various programs

Shells are not only a user interface, but are also relatively powerful programming languages. Every UNIX user has a login shell which is automatically started at login. In principle, this is a normal program; often, for example, a business or another commercial package is automatically started at this point. For interactive use of a UNIX system, usually one of the most widely used shells is started, such as the Bourne or the Korn shell, or the C shell, or any of their descendants.

The shell takes over the interaction with the user and starts the required programs. Furthermore, all shells can also be used as programming languages—in the first place, to write initialization files, but also for further shell scripts. Control structures; such as branches and loops, are implemented inside the shell itself. For nearly all other functions, the common UNIX programs are used. For reasons of performance, however, many functions, such as echo and past, are also implemented internally. Since these functions are described by the POSIX standard, internal and external commands are a rule compatible with each other.

The following section introduces some functions for programming with the which are, however, also very useful for interactive control. Please note that other UNIX systems only have an original sh, and therefore some extensions of the bash cannot be used on all systems.

Practically all modern UNIX systems support the # mechanism for starting shell scripts. After this sequence, the complete path to the interpreter must be specified. This restricts the choice of interpreter for scripts that are to run unchanged on different systems. Often the only remaining shells are the /bin/sh or the /bin/csh, where the csh should be avoided as a script language. The reasons for this position can be found in the text "Why csh is considered harmful" by Tom Christiansen (tchrist@mox.perl.com). This is periodically posted, for example, in the comp.unix.shell newsgroup, and can be found in the FAQ archive at rtfm.mit.edu.

On practically all modern UNIX systems, the standard output and standard error are represented by file descriptors 1 and 2, respectively. The standard input is represented by 0. These descriptors can be redirected using various operators. Redirection allows you to send the output of a command to a file instead of the screen, or to provide input to a command from a file instead of the keyboard.

The most common redirection operator is the > operator, which redirects the standard output of a command to a file. If the file exists, it is overwritten. The >> operator appends the output to the end of the file. The < operator redirects the standard input of a command from a file. The 2> operator is used to redirect the standard error to a file. For example, command 2> error.log will send only error messages to that file. This is useful when you want to capture errors without the normal output. The 2>& operator is used to redirect both standard output and standard error to the same file. For example, command > file 2>&1 will send both types of output to the file.

The pipe operator | is used to connect the output of one command to the input of another. For example, command1 | command2 will take the output of command1 and use it as input to command2. This is a powerful tool for building complex programs from simple commands.

## 10.8.1 Input and output

Redirection is the process of changing the source of input or the destination of output. In Unix, the standard input is the keyboard, the standard output is the screen, and the standard error is also the screen. These can be redirected using the operators mentioned.

The > operator is used to redirect the standard output of a command to a file. If the file exists, it is overwritten. The >> operator appends the output to the end of the file. The < operator is used to redirect the standard input of a command from a file. The 2> operator is used to redirect the standard error to a file. For example, command 2> error.log will send only error messages to that file. The 2>& operator is used to redirect both standard output and standard error to the same file. For example, command > file 2>&1 will send both types of output to the file.

The pipe operator | is used to connect the output of one command to the input of another. For example, command1 | command2 will take the output of command1 and use it as input to command2. This is a powerful tool for building complex programs from simple commands.

Another form of redirection is the here document, which allows you to specify a block of text directly within the script. This is started with the << operator followed by a word. The block ends with the same word on a new line. For example:

```
cat << EOF
This is a test.
This is another line.
EOF
```

This is useful for creating files or providing input to programs. Another useful feature is command substitution, which allows you to use the output of one command as an argument to another. This is done using backticks ` ` or the $(... ) syntax. For example, echo "The date is $(date)" will output the current date.

Finally, variables can be used to store and use data in scripts. Variables are created using the = operator and accessed using the $ symbol. For example, NAME="World" and echo $NAME will output World. Variables can also be used for arithmetic operations using the expr command.
