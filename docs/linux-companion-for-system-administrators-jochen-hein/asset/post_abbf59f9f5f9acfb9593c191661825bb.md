Another function of ssh is the option of redirecting TCP connections and encrypting them at the same time. ## 16.5 Sending warnings to remote computers with rwall

On the local computer, warnings or messages can be sent to all users using the wall command. This happens, for example, in the case of shutdown. When a server is shut down, it might be a good idea to inform the users of the other computers as well. This can be done by using the command rwall computer. However, the rwalld daemon must be running on the target computer. Under LINUX, this is the program /usr/sbin/rpc.rwalld. Whether and on which computers service is running can be determined by the command rpcinfo -b 100008 1.

## 16.6 File transfer with rdist

The rdist program can be used to synchronize directory trees in the network. Thus, it is possible to install a master server with programs which are then forwarded to other computers (local file servers). Only new or modified files are transferred, and superfluous files may be deleted. The login on the remote computer is carried out via rsh. It is, however, possible to use the ssh in this case, you must either replace the rsh with a copy of the ssh or compile rdist accordingly.

The rdist program can be controlled both via parameters and options by means of files. Especially with more complex tasks and therefore more voluminous parameters, it is a good idea to use rdist scripts. For this purpose, you will need to create an input file and enter the rdist program as the interpreter in the first line. Here, you can also specify additional parameters. A rdist file consists of entries that conform to one of the following following formats:

- variable = list
  A variable which is used in the further course of the script is assigned a value.

- source_files -> destination commands
  The specified source_files are to be transferred to the computers whose names are specified in destination. The specified command is used for the transfer. Legal commands are presented in more detail in this chapter. However, only those files are transferred that are older or not present on the remote computer.

- source_files :: timestamp_file commands
  In this format, the files to be transferred are determined by the timestamp_file.

Inside rdist scripts, a series of commands can be called to transfer files or trigger other actions.

- install copies the files to be transferred to the target computer(s). Additional options can be specified, which are documented in the man page.

- notify causes rdist to send a list of the transferred files and possible error messages to the specified user. If the username does not contain an '@' sign, the corresponding user on target computer is used.

- except copies all files that are not specified. This is an easy way of transferring a directory with the exception of a few files.

- except_pat is similar to except, with the difference that patterns for file names are specified. Patterns are expanded in the same way as in shell.

- special can be used to call external commands for each transferred file.

- special, in contrast, is executed once only after all affected files have been transferred.

The example in Listing 16.13 contains the most important configuration files of a user. This is a relatively simple solution to configure unique environment without a shared directory. This is a simple example. All options and features of rdist are described in the man page, where you can also find a more detailed example.

```
HOSTS = users.example.org
FILES = ~/.emacs/.gnus/.vm/.project/.plan/.fwm/.netrc/.rhosts/.tin/.emacs/.init/.work
install;
```

## 16.7 Conversation between users with talk

Two logged-in users can talk to each other, even via a network, by means of the talk program. For this purpose, the corresponding talk daemon must be installed on the communicating systems. Unfortunately, there are two different and incompatible protocols (talk and ntalk), so communication is not possible.

After the establishment of a connection, shown in Listing 16.14, the screen is split. The upper field displays one's input. Below this, one or more fields are shown which display the texts of talk partners. With four or more partners, the screen becomes garbled.

In the standard talk, communication is limited to two users. A more powerful and flexible program is ytalk which can handle both protocols and, in addition, allows communication with several partners. Users with ytalk can view the texts of all other users in the corresponding screen areas, but not the texts of users using the standard talk.

A talk connection is opened with ytalk user@host. The corresponding user receives a message with an invitation for talk. If the user issues the command specified in the message (see Listing 16.14), the connection is established. All further input is transmitted to the interlocutor, whose input is in turn displayed in the dedicated screen area. The connection is terminated with Ctrl

```

talk: connection requested by user@users.example.org
talk: respond with: talk user@users.example.org
```

In comparison with the UNIX talk, the ytalk program offers a series of additional features. These functions are called via a menu, which appears when you press the Esc key. With a German keyboard mapping, for example, the Alt key sends an 'Escape' before the second key, so that these functions can be directly called with Alt-key. This keyboard setting can be configured by means of the setmetamode command.

- add key is used to add a new interlocutor.
- delete key terminates the connection with a partner.
- additional options can be changed by the a key. These options can also be permanently configured in the file ~/.ytalc.
- a useful feature is the shell by means of the s key, so you can enter commands whose output is transmitted to the interlocutor.
- an overview of all active users can be obtained by means of the u key (user).
- you can protocol the text of an interlocutor in a file by means of the w key (write), so this is available for future use.
- the key terminates ytalk.

In local networks, communication with talk is quick and easy. If the interlocutor is further away, long waiting times accumulate because each keystroke is transmitted individually.

## 16.8 Internet Relay Chat (irc)

When communicating with several partners via ytalk, screen space runs out quickly. Furthermore, each partner must have the ytalk program, which is not, however, available as a standard under many UNIX variations. Another protocol for communicating with several partners is Internet Relay Chat (IRC). In IRC, you will find a large number of channels on which online discussions place on the most varied subjects.

The backbone of the system is a series of IRC servers which exchange the messages entered by the users. These computers are usually connected via fast lines to keep waiting times to a minimum. The servers forward the messages to the logged-in clients, which in turn handle the user interaction.

If you are unwilling or unable to operate IRC on your system, you still have the option of accessing IRC via a telnet gate. Detailed information on IRC can be found in the documentation of the IRC client IRCII*. Alternatively, more user-friendly clients are irchat for Emacs and Zinc for X.

It is also possible to set up chat rooms on one’s Web server. The advantage is that only a Web browser is required and no other client. On the other hand, the user circle is very limited because no use is made of the worldwide infrastructure of the IRC. For many companies, however, this is a striking argument, because only in this way can they have exclusive control over the chat room and, for example, fill it with advertising.

## 16.9 File transfer with sendfile

In a network with several users it is often necessary to exchange files between users and computers. If only a text file is to be sent, this can often be done using the standard mail program:

```
(Linux)-> mail user < file
```

If the file contains 8-bit coded text (foreign language special characters) or if it is a binary file, it must be converted into a format that survives transport as mail before it is actually transmitted. This can be done by means of programs like uuencode, or you can use MIME encoding.

However, this method is laborious, particularly if the mail system limits the length of messages to be sent. with sendfile one or more files can be sent to a user. The transmitted files can then be received by means of receive.

```
(Linux)-> sendfile file User@host
```
