When updating a distribution, you must be aware that program files in /usr/or/ may be overwritten. By definition, the /usr/local directory is therefore not the complete responsibility of the local system administrator and is not modified. For safety, you can also simply unmount this directory (and remove it from the file /etc/fstab) when upgrading.

# 2.4.6 /usr/sbin - further system programs

Here, the system administrator will find a series of programs for system management. These programs, however, are not needed in emergencies, but only during normal operation. This is usually where you will find network daemons, programs for system administration, and servers started in the so-called multi-user mode. Locally installed programs for the system administrator should be stored in the /usr/local/sbin directory.

# 2.4.7 /usr/share - architecture-independent data

In the initial stage of Linux, only Intel-based PCs were supported. Therefore, there was no distinction between processor-dependent data and processor-independent data. Today, for practically all hardware platforms are available or under development, so this has changed. In the /usr/share/man, or /usr/doc, you will find that data are static and can be shared by different computers with different processor architectures.

Many of the data stored here could previously be found under /usr/lib, /usr/man, or /usr/doc. For reasons of downward compatibility, individual directories may still be installed under /usr/lib; this depends on the distributor.
