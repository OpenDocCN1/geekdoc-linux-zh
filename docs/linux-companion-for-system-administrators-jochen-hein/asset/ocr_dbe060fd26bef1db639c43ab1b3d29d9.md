# # 3.3 Starting the kernel

After one of the boot loaders has loaded the kernel image, for example \mlinuz, from the active partition into RAM, the kernel must first be decompressed, since version 0.99pl12, all kernels are created in a compressed form. The additional load of the CPU does not count because that time is ‘twiddling its thumbs,’ waiting for data to arrive from the disk I/O ‘bottleneck.’ The net loading time of compressed data is even lower. If, in contrast, the CPU represent the bottleneck, using uncompressed data would be more advantageous; however, this is not to be expected in the near future. Another advantage of compression is the saving of disk space, but in this case this is not important.

The use of compressed kernels has become necessary, because in an uncompressed form they became bigger than 704 Kbytes (640 Kbytes of ‘conventional DOS memory’ plus 64 Kbytes of unused data area of the graphic boards under DOS), and the processor at that point is still in real mode, in which only memory addresses below 1 Mbyte are available. Obviously this is only a restriction on Intel hardware.

The introduction of compressed kernels has only obfuscated the real problem. because of the large number of drivers that can be linked into the kernel, one again reaches the limits of the real mode, which requires the kernel to be loaded initially into the memory below 1 Mbyte. Sooner or later, the boot loader will run in protected mode, so the size of the kernel will only be limited by the real amount of RAM.
