# 152 THE EMACS EDITOR

The Emacs editor is very powerful; it is a Lisp interpreter which how to handle texts. The Lisp dialect of Emacs is a (fully-fledged) Lisp: the Emacs Lisp (in short, elisp). Thus, during execution of macros, the novice user will be surprised by strange messages such as: Garbage collecting...

This message tells you that an internal function of the Lisp interpreter is running which releases memory that is no longer used. Since Lisp does not have explicit allocation and release of memory, this function is called periodically (or when more memory is needed).

There is a large number of adaptations, extensions, and macros for Emacs written in english: these macros are stored in files with the extension *.el, *.el files are the corresponding (byte-)compiled versions which the Lisp interpreter can execute much faster. These Lisp programs, together with the extensive and well-written documentation, are the reason for the huge space requirements of Emacs.

# 5.1 Which version of Emacs should I choose?

The Emacs family consists of a huge number of variations and more or less compatible clones. This multitude makes choosing a version relatively difficult, but there are always good reasons for choosing one version or other.

The most widespread version is probably the GNU Emacs which is directly developed by the FSF under the direction of Richard Stallman. This version includes a good selection of additional Lisp packages and runs both over X and on a terminal. Under X, different fonts and colours can be used. If required, texts can be stored in RTF (Rich Text Format) including the attributes.

The biggest competitor is the XEmacs. This version was originally developed to improve the X interface, but it can also be used on a terminal. Here, special functions are the use of colours on colour terminals and under X, together with the possibility of addressing one Emacs process from both a terminal and under X. A further advantage is that more Lisp packages are supplied than with Emacs. These packages are also stored in a better structured way.

One disadvantage of the XEmacs is that the Lisp interpreter and some functions are not compatible with the GNU Emacs – Emacs is not the 'standard Emacs'. Therefore, many Lisp extensions run only with the GNU Emacs or an older version of the XEmacs. Emacs needs significantly more memory and CPU power than the GNU Emacs. The increase in power comes at a price.

When we talk about Emacs in the following sections, we mean both GNU Emacs and XEmacs. In most cases, these two have very similar or even identical behaviour, so that differentiating between them makes little or no sense.
