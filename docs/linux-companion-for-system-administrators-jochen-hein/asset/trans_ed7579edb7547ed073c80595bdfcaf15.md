

# LINUX 发行版对比 3

- LINUX 可以在无需巨大代价的情况下，将 PC 转换为工作站、终端或灵活且强大的服务器。
- LINUX 支持同样由发行版和开发者提供，甚至可以由其他用户提供。事实上，任何感兴趣的实体都可以提供商业支持，因此用户可以在许多提供者之间自由选择选择。
- LINUX 很好地适应常见的 PC 硬件，有很多驱动程序，且系统运行较快。
- 在程序开发、办公套件、互联网服务器和客户端领域已经有了许多应用程序，以及如 Windows 或 IBC2 等系统的模拟器。此外，商业应用市场也在不断增长。
- 该系统通过电子手册（位于 `/usr/doc` 或 `/usr/share/doc` 中）或帮助页（man pages）提供了完善的文档，并且有很多关于该主题的书籍。如果文档未能回答问题，在最坏的情况下，你始终可以在源代码本身中寻找解决方案。
- 得于 LINUX 的免费属性以及发行版之间的激烈竞争，LINUX 的价格低廉。这通常是一个主要的卖点，但我个人认为选择操作系统的自由要价值得多。
- 这个列表显然并不完整，并且可以扩展，不同的用户会强调不同的方面。目前还没有哪个系统能满足每一个可能的用户。

## 1.2 LINUX 发行版的对比

如上所述，存在大量的 LINUX 发行版。为个人使用选择一个“好”的发行版并不是容易的。在接下来的章节中，我将简要介绍我自己尝试过的某些发行版，并展示它们各自优缺点。这个列表是不完整的，因为我没有尝试过每一个发行版，而且合理的测试需要大量的时间。此外，许多测试结果随着相应发行版版本的更新而过时。

每个发行版都应该提供相应的安装说明。这些说明可能以 `README` 文件、随 CD 附的小册或打印手册的形式出现。通常，此类说明会详细地描述系统的安装过程，因此在本文介绍中我们将省略这类描述。我们将重点突出不同发行版之间的主要区别。显而易见，不同的发行版对应不同的需求，发行版的适用性将取决于用户的需求。现在你甚至可以获得预装了 LINUX 的系统，这样就没有安装的烦恼。得益于通用公共许可证（GPL），许多在 LINUX 下使用的程序和内核都受该协议约束，每个发行版都有义务提供相应程序的源代码，或者根据要求提供。因此，许多发行版在 CD 上也包含了源码。如果出现问题，你就可以修改并重新编译单个程序，或者找出安装了哪些选项。

这是一个我们可以在发行版之间找到显著差异的领域。某些 CD 不提供支持，而另一些则允许用户获得安装支持（通过电子邮件、传真或电话）。某些公司提供定期的支持或咨询服务。供应商通常维护一个邮件列表，其中对他们的发行版提供特殊支持。为了防止发行版之间的过度差异，开发了文件系统层次结构标准（详见第 2 章），该标准定义了 LINUX 目录结构。这里介绍的大多数发行版都遵循这一标准，但在个别情况下也会偏离该标准。这些偏差通常记录在发行版手册中。目前人们正努力创建一个“LINUX Base”，以定义一个完整的基础，以便二进制程序可以在任何 LINUX 系统上无问题地安装和使用。

关于这里介绍的发行版以及其他发行版（例如发行者的地址）的更多信息可以在文档中找到。对于 LINUX 下几乎可以想象的每一个主题，都有一个文件介绍该主题并部分承担了 FAQ（常见问题列表）的功能。然而，除了文档之外，还有一个 FAQ 列表。此外，一个志愿者小组致力于 Linux 文档项目，该项目制作帮助页和手册。这些书籍质量良好，其中一些还在书店出售。已出版书籍的概述可以在附 C 中找到。

在介绍发行版之前，我想更详细地说明一个发行版应该满足的要求。重要的问题是安装程序和系统本身，但我们还将讨论技术背景。

- 安装程序应该能够不需要软盘。帮助程序使得在安装期间显示额外信息并为用户提供支持。
- 如果发生输入错误，可以重新进行单独设置而无需重新开始。这应该适用于尽可能多的设置。
- 软件包的选择应该在安装之前而不是在安装期间进行。在那个点还应该检查可用空间。这将使得在没有用户交互的情况下运行安装中最耗时的部分成为可能。
- 发行版应该提供在不同的“标准安装”之间进行选择（例如带有或不带 X，或 TEX）。这些选择对于初学者非常有帮助，因为程序的数量和种类可能会令人望而畏。
- 之后可以删除或添加单个软件包。在这里必须考虑软件包之间的依赖关系，因为许多软件包是构建在其他软件包之上的，或者它们之间互斥。
- 强大的系统管理工具可以方便安装。并不是每个用户都对收集配置文件并使用文本编辑器对其进行感兴趣。Windows 是一个很好的例子，展示了在图形工具帮助下系统配置是多么简单。

# 未来的 LINUX 操作系统？

- 发行版应该包含许多用于数学、图形、文本处理等的应用程序包。在这里，将程序划分为不同的应用组或系列是有用的。
- 发行版应该在安装时提供软件包的良好文档（描述），这些描述对于新手来说应该是易懂的。安装后，软件包的完整文档（`README` 文件、手册和示例文件）应该在硬盘的 `/usr/doc` 或 `/usr/share/doc` 下可用。
- 程序的所有源代码应该是可用的并且只需按一下即可安装。
- 应该可以使用一个命令重新编译程序，其方式与为发行版编译的方式完全一致。
- 程序的原始源码（例如供其他系统使用）和针对发行版的适配应该分开。
- 发行版应该对应文件系统层次结构标准（FHS）。如果那里没有指定具体问题，所遵循的原则对用户来说应该是清晰且简单的。偏离 FHS 的情况应当被记录。
- 系统应该基于模块化的内核，以便最初提供的内核可以直接使用。
- 发行者应该参与 LINUX 社区，为项目提供支持和合作，并与程序员合作消除错误等等。
- 应该能够在不中断服务的情况下更新系统。

这个列表是不完整的，但它展示了发行版应该满足的广泛需求。创建和维护一个发行版的成本相当高，因此市场在这方面可能会停止增长。
