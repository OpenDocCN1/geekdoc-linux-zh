## 1.2 A comparison of LINUX distributions

As already mentioned above, there is a large number of LINUX distributions. It is not easy to choose a 'good' distribution for individual use. In the following section, I will briefly present some distributions that I have tried myself and show their respective advantages and disadvantages. This list cannot be complete, because I have not tried every distribution, and a reasonable test requires a lot of time. Furthermore, many test results become obsolete with new versions of the corresponding distributions.

Each distribution should be supplied with corresponding installation instructions. These may come in the form of a README file, a booklet accompanying the CD, or a printed manual. Usually, such instructions describe the installation of the system in great detail, so in this presentation we will omit this kind of description. We will concentrate on highlighting the main differences between the distributions. It will be obvious that different distributions match different requirements and that the suitability of a distribution will depend on the user's requirements. Now you can even get a system with LINUX pre-installed, so you have no hassle installing it. Thanks to the General Public License (GPL), to which many of the programs used under LINUX and the kernel are subject, every distributor is bound to supply the source code of the corresponding program together with the program or provide it on demand. Therefore, many distributions also include the sources on the CD. In case of problems, you can then change and recompile individual programs or find out which options were installed.

This is an area where we can find significant differences between the distributions. Some CDs are offered without support, others entitle the user to installation support (via email, fax, or telephone). Some companies offer regular support or consulting services. Often, vendors maintain a mailing list in which special support is given for their distribution. To prevent excessive differences between the distributions, the File System Hierarchy Standard (see Chapter 2) was developed, which defines the LINUX directory structure. Most of the distributions presented here adhere to this standard, but some deviate from it in individual cases. These deviations are usually documented in the distribution manual. There is an ongoing effort to create 'LINUX Base' that defines a complete base, so that binary programs may be installed and used on any LINUX system without any problems.

Further information on the distributions presented here and on other distributions, such as for example, the addresses of the distributors, can be found in documentation. For practically every imaginable subject under LINUX, there is a file which introduces the subject and partly assumes the function of a FAQ (Frequently Asked Questions) list. Besides documents, however, there is also a list of FAQs. In addition, a group of volunteers works on the Linux Documentation Project, which produces man pages and manuals. These books are of good quality and some of them are also sold in bookstores. An overview of published titles can be found in Appendix C.

Before we come to the presentation of distributions, I would like to explain in more detail the requirements that a distribution should fulfill. Important issues are the installation routines and the system itself, but we will also discuss the technical background.

- The installation routine should be able to do without a floppy disk. The help program makes it possible to display additional information during the installation and to provide the user with support.
- In case of input errors, it should be possible to carry out individual settings again without having to start over. This should apply to as many settings as possible.
- The selection of packages should take place before, not during, the installation. Available space should also have been checked at that point. This will make it possible to run the most time-consuming part of the installation without user interaction.
- The distribution should offer a choice between different 'standard installations' (for example with or without X, or TEX). These selections can be very helpful for a beginner, since the number and variety of programs can be daunting.
- It should be possible to delete or add individual packages at a later time. Here, dependencies between the packages must be considered, because many packages build on others or mutually exclude each other.
- A powerful system administration tool can facilitate the installation. Not every user is interested in collecting the configuration files and adapting them with a text editor. Windows is a good example for showing how easy a system configuration can be with the aid of graphical tools.

- The distribution should include many application packages for mathematics, graphics, text processing, and so on. Here, a sensible subdivision into different application groups or series is useful.
- The distribution should include good documentation (description) of the packages at installation which should also be comprehensible to newcomers. After installation, complete documentation (README files, manuals and sample files) of the package should be available on the hard disk under /usr/doc or /usr/share/doc.
- The entire source code of the programs should be available and installable at the touch of a button.
- It should be possible to recompile the programs with one command in exactly the way as they were compiled for the distribution.
- The original sources of the programs (for example, for use under other systems) and the adaptations for the distribution should be separated.
- The distribution should correspond to the file system hierarchy standard (FHS). If individual issues are not specified there, the principles to be followed should be clear and simple for the user. Deviations from the FHS should be documented.
- The system should be based on a modularized kernel, so that initially the supplied kernel can be used.
- The distributor should become involved in the LINUX community, offering support and cooperation in projects, and with programmers to eliminate errors, and much more.
- It should be possible to update the system without disruptions.

This list is not complete, but it shows the wide spectrum of requirements that should be met by distributions. The effort of creating and maintaining a distribution is fairly high, so the market may soon stop growing in this respect.
