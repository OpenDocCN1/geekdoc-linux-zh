There are administrators who mount the /usr partition with the option for read-only. # Locally installed programs

In cases, if a particularly large number of programs have been installed locally in the /usr/local partition and essential changes to the programs have been made, it may be sensible to backup this partition too, at least periodically. If only a few programs are present, it might be easier to reinstall them. Obviously, at this point, the program sources/or the installation media should be kept. If you keep a log of the software you install and the changes you make, populating a new/usr/local will be much easier.

# Directories not worth backing up

The directories /tmp, /var/tmp, and other directories for the storage of temporary files (for example /usr/local/tmp), plus the pseudo file system /proc not need be saved. Therefore, these directories should always be excluded from the backup. At the system administrator's discretion, file systems as /var/cache may also be excluded.

# 7.4.3 Sequencing of incremental and full backups

Execution of an incremental backup is sensible if relatively few files are modified between the individual backups. Initially, you must begin with a complete backup, so that every file has been saved on at least one medium. Subsequently, only the modified files need to be backed up again.

Complete restoring of a backup is laborious if the last complete backup was carried out some time ago and in the meantime incremental backups have been carried out. In case of data loss, the complete backup must be restored first, followed by all incremental backups in the correct order. Therefore, you should periodically carry out complete backups to limit the number of incremental backups. In practice, for example, one complete backup per week with daily incremental backups has proved to be an acceptable solution.
