## 10.1.1 Searching for files with the find command

The find command can be used to search the file system for files that satisfy specific criteria. The output is a list of found files which can then be processed by other programs, such as awk (Section 10.5). Alternatively, a UNIX command can be specified which is executed on every file by the find command.

The find command can be passed the starting directory as the first parameter. All subdirectories of this directory are searched. The nesting depth can be restricted by means of the -maxdepth option; the whole search can be limited to a single file system with the option -xdev.

Various search criteria that the files must satisfy can be specified. Possible criteria are, for example, the file name (or a search pattern), the file type, or the last access, modification, or creation date. To search for a file name, the criterion would be input as -name file name.

Another parameter must tell the find command what to do if a matching file is found. Possible options are, simply to output the file name (option -print) or to start other UNIX programs with the found name as a parameter (option -exec). The GNU program find -print as the default action if nothing different was specified; other UNIX systems may or not do the same. If you want to remain portable, you should always specify -print. 10.1 searches for all files in the directory /etc whose names match the pattern *net.

```
(Linux):$ find /etc -name *net* -print
/etc/cd/rc.inet1
/etc/cd/rc.inet2
/etc/inet
/etc/inetd.conf
/etc/networks
```

- Listing 10.1 Searching for files with find

For /etc specifies the directory to be searched. The parameter -name '*net*' tells find to search for files whose names match the search pattern *net*. The file name should be enclosed in single quotes so that the shell calls does not interpret the special characters. The -print parameter instructs find to output the complete file name.

When the -print option is specified, the output can be modified by means of a format specification, for example, to include modification date, file owner, or file size in the output. The -ls option is a very convenient way to get an output similar to the ls program. The man page for find contains a complete overview of possible formats. Several additional output formats can be set, for

example, -print0 inserts a null byte as a separator between the individual names instead of a line feed.
Instead of listing the found file names, a UNIX command can be started with the file name as a parameter. This is obtainedby using -exec which generates a new process for each found file. If the search result contains many files, it is recommended that one of the commands shown in Listing 10.2 be used, which generates only one or a few additional processes. They employ either a mechanism of the shell or the xargs program (see Section 10.1.6).

```
(Linux):$ find -name "*.bak" -exec rm -f {};
(Linux):$ rm -f $(find -name "*.bak")
(Linux):$ find -name "*.bak" | xargs rm -f
```

**Listing 10.2** Execution of commands with find.

All examples in Listing 10.2 delete all files bearing the extension .bak. The -exec parameter executes the command rm -f for each found file. The brackets are placeholders for the file name. The semicolon tells the find command where the -exec parameter ends. As the shell would also evaluate the semicolon, it must be masked with a backslash (\).
If you are not sure the specified command should be executed for all files, you can use the option -ok instead of -exec. Here, for each file, find files in which a particular piece of text occurs. The example in Listing 10.3 lists all files that contain the host name. Depending on the extent of the file system, the example can take a while to run, because all directories are searched.

Another interesting purpose of the -exec option can be seen in its combination with the grep command. This makes it quite easy, for example, to find files in which a particular piece of text occurs.

```
(Linux):# find -type f -exec grep -L \ 'hostname{}';
/etc/profile
/etc/hostname
/etc/hosts
/etc/nntpasswd
/etc/ftpaccess
```

**Listing 10.3** find in combination with grep.

In combination with the cpio or commands (Section 7.5), it is also possible to use find for a backup. Rudimentary example can be found in Listing 10.4. As a rule, it is possible to adapt the system. Often, however, it is sufficient to know which files have modified to learn more about the system.

## 10.1.2 Searching with locate

One disadvantage of the find command is searching in large file systems
or worse, on network drives takes a long time. Furthermore, there is a risk
in the case of symbolic links, find ends up in an infinite loop. There is, however, a second method of finding files, namely the GNU program
locate.

Instead of the file systems, the locate command searches a database for
the requested file name. This UNIX database must have been previously createdby means the updatedb command; only then can the locate command be
employed. The search is now much faster than the find command, but
there is a chance that the database is not completely up to date, so not all files
are found, or files shown that have been deleted. locate warns the user
when the database is older than eight days.

The updatedb command searches all directories specified in the
environment variables SEARCHPATHS and NFSPATHS. The search pattern in
the variable PRUNEREREGEX can be used to exclude file names or whole paths
from being included in the database. By default, these are the directories tmp,
/usr/tmp and /var/tmp. It is recommended that the /proc directory is
included in this expression as well. The /proc file system only contains data
represent the internal status of the system, and such data change quickly.

To begin with, you should exclude the users' home directories from the
search, because otherwise even unreadable directories would be searched by the
system administrator. If you wish to provide your users with a database of all
home directories, you should at least start this search as user nobody.
Otherwise, each user can create an additional database for his/her own directories
and have it searched by locate by default. Listing 10.7 shows an example for
creation and search of a user's locate database.

Besides the options discussed above in more detail, find can also search
other criteria, such as file owner, access rights, or size. Furthermore, find
can search for several criteria at a time, with the possibility of specifying
actions as well. The complete documentation of find can be found in the man
page or in the Texinfo documentation.
