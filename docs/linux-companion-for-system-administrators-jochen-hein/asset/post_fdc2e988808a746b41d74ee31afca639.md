
# 242 NATIONAL LANGUAGE SUPPORT

- Under DOS usually the IBM code page 437 is used, under UNIX the ISO-Latin-1 character set. Letters that are also defined by the US-ASCII character set do not need conversion.

- Under DOS the line end of a text file is represented by the character sequence CR+LF (Carriage Return and Line Feed), under UNIX only by LF.

If you do not want to memorize the names of the associated character set tables, you can for example define the following aliases, which are sufficient for this purpose:

For the GNU bash:

```
(Linux) ~# alias fromdos='/usr/local/bin/recode ibmp:lat1'
(Linux) ~# alias todos='/usr/local/bin/recode lat1:ibmp'
```

For the tcsh:

```
(Linux) ~# alias fromdos '/usr/local/bin/recode ibmp:lat1'
(Linux) ~# alias todos '/usr/local/bin/recode lat1:ibmp'
```

You can find extensive documentation on implementation and functioning of recode in the Info documentation which you can, for example, read with the Emacs editor. The POSIX.2 standard requires the implementation of the icon program. However, no free implementation of this program is so far available.

# Localization

This chapter describes the remapping of the keyboard and the configuration of individual programs for use with foreign language special characters and the international A4 standard paper size. More generally, this chapter describes ways of obtaining a system-wide consistent keyboard mapping for special characters (such as BS, DEL, HOME and END), together with an 8-bit clean character representation on the console, in shells, and in application programs (including mail and news). The description is limited to general setup instructions; detailed information on individual configurations can usually be found in the documentation supplied with the programs. Detailed information on how to set up individual character sets for foreign languages can be found in the corresponding HowTos.

Two sections, namely the ones on console keyboard mapping and XFree86, describe LINUX-specific configurations. The remaining sections can also be applied to other UNIX systems.

## 9.1 Console keyboard mapping

A detailed description of keyboard mapping is given in Section 5.4. If you simply load one of the keyboard mappings presented there, you will not need any further information.

For most users, the national keyboard maps (whose names usually consist of the two-letter language code and the extension .map) plus the file xx-latin nodekeys are sufficient. Nevertheless, you may want to redefine or newly assign a couple of keys. Fortunately, you do not have to create an entirely new keyboard map, it is sufficient to create a new file (for example /etc/keytables/local.map which contains only the changes. In the rc scripts, this file is loaded with loadkeys and the keyboard is set up accordingly.)

If for some particular reason, you want to use a special pair of symbols as opening and closing quotes you can compose these characters by means of a Compose key. Listing 9.1 shows an example of a possible Compose key configuration, in this case the right-hand Ctrl key yields 97 (as shown by the showkey program). The construction of the French opening quote is achieved by pressing and holding the right-hand Ctrl key and pressing the French closing quote is obtained by pressing and holding the right-hand Ctrl key and pressing the key twice,

```
keycode 97 = Compose
compose         = to'
compose         = to`
```

## 9.2 Using the ISO-Latin-1 character set

After system start-up, LINUX uses a modified IBM character set. This character set includes both of the ISO-8859-1 characters from the range 127–255 and a series of graphical symbols which are used, for example, by the mc program for representation of frames. Thus, this character set cannot be used to represent all of the characters of the ISO-Latin-1 character set.

This can instead be achieved by the appropriate character set together with the corresponding conversion table, and subsequently activating the newly loaded character set.

```
(Linux)-> setfont iso01.f14
(Linux)-> mapscrn trivial
(Linux)-> echo -e '\033(K'
```

Loading the character set and the conversion table applies to all virtual consoles, whereas switching character sets by means of the ESC sequence applies only to the current console. Unfortunately, the output of the mc program afterwards is not readable because the frames are not built out of the correct characters. Programs and character sets used can be found in the package kbd0.89.tar.gz.

## 9.3 Keyboard assignment under X11

Since version XFree86 2.1.1, XFree86 reads the keyboard table of the LINUX kernel, and as far as possible, sets its own assignments to the same values. The only exceptions are special combinations and characters, such as the 'dead-keys' (the ˜ or the accent keys ` and '). To assign these keys, you must use the xmodmap program. When starting the X Window environment with startx, the following files are used, if present.

- The system-wide configuration is located in /etc/X11/xmodmap.
- The user-specific configuration is located in ~/.Xmodmap.

To create a mapping, you can use the `xmodmap -p` command to output the current mapping to a file, which you can then edit. For example, to change the Caps Lock key to Control, you would add:

```
keycode 66 = Control
```

To apply the changes, you run `xmodmap ~/.Xmodmap`.

You can also define dead-keys, which allow you to type accented characters by pressing a key combination. For example, to define the acute accent dead key, you would use:

```
keycode 94 = dead_keys
key 94 = acute accent
```

## 9.4 Use of foreign characters at the shell

After logging in to LINUX, a shell is started which accepts user input. As a rule, no special characters such as umlauts should be used in file names in many (older) systems, this can lead to problems. The `setxmap` command allows you to switch between different layouts. For example, to switch to a German keyboard layout:

```bash
setxmap de
```

In some environments, the `Alt` and `AltGr` keys are also used to act as modifier keys for symbols. This can be configured in the `Xkb` configuration files located in `/usr/share/X11/xkb/symbols/`.

## 9.5 Keyboard mapping in X11

The X11 system provides a more flexible way of keyboard mapping than the old kernel-level mapping. The `Xkb` extension allows for complex layouts, including multiple languages. The configuration files are located in `/usr/share/X11/xkb/`. To use a specific layout, you can use the `setxkb` command:

```bash
setxkb layout us
```
