## 5.3.4 Emacs as server – one for all

Various programs, for example em, and cron, can call an arbitrary
editor for editing or texts. Usually, these programs use the environment
EDITOR or VISUAL which contain the name of the editor. If these
variables simply contain emacs, a new Emacs process is started at each call.
This is impractical because it costs time and memory; furthermore, Emacs
processes cannot access each other's buffers. Therefore, true Emacs users
start everything inside Emacs, which terminate until logging out.

It is possible to use a running Emacs as an editor for a new buffer, for
example from em, by configuring Emacs as a server. For this purpose,
the function server-start must be called from within Emacs. This can be
automated by means of an appropriate entry in the file ~/.emacs. The
has the consequence that, whenever an application calls emacsclient, a message is sent to the Emacs server in which this is asked to load a specific file into a new buffer. If with virtual consoles, you must switch to the console Emacs; When you have finished editing the text in the server, you leave the buffer
with C-x and the previously edited buffer is again displayed in the
window. Then a message is sent to emacsclient, asking it to terminate.
Thus, these programs do no difference from a direct call to an editor. The whole process also works on text consoles. Here, it is more practical to start Emacs on one console and another, because it is faster to change console than to load Emacs completely. takes a long time to configuration, so this procedure is worthwhile.

## 5.3.5 Emacs as server – even more features

The functions provided by GNU Emacs as server are not always sufficient. Thus it is not possible to have the running process evaluate individual Lisp expressions. To avoid clashes between GNU Emacs and XEmacs, XEmacs uses different Lisp functions, and you should write your Lisp files in such a way that you can use them with both editors. This is useful if Emacs is not installed or if you frequently have switch between the two environments.

In Emacs, the server is started by means of the function server-start. Listing 5.8 shows an example of how to differentiate between GNU Emacs and XEmacs inside Lisp functions.

```
; Which one is running, XEmacs or GNU Emacs?
(defvar running-emacs
  (string-match "XEmacs\|GNU Emacs" version))
(cond
  (not running-emacs)
    (setq GNU Emacs-specific-code
      (server-start))
  (t; Emacs-specific-code
    (server-start))))
```

Subsequently, you can work with the emacsclient program in exactly the same way as with emacs. The only difference is that processing the buffer can also be carried out from a different computer. For this purpose, host-based authentication or a password check must be carried out. If Emacs has been installed correctly, the xauth program can be used; the display number is used.

Particularly interesting extensions of GNU Emacs are the programs scratch and remote. With scratch, an already running Emacs can be persuaded to accept additional input on the current terminal. This is useful if one is logged in via a modem or sitting at a colleague's workstation, and one cannot or not want to start a new Emacs. It may, however, that the keyboard mappings and the colours do not match the current terminal, since these are often carried out only once at the start of Emacs.

The program remote is used to have Lisp expressions evaluated by Emacs. Examples for the call can be found, for example, in the man page for remote. With this method you can control a running Emacs from outside – the security implications are the same as scratch.

## 5.4 Keyboard mapping

Besides the call of functions via menus (under X), keyboard shortcuts, and the call by means of M-x command, practically all keys can be associated to functions. Emacs differentiates between a global mapping that applies to all modes and a local mapping, possibly adapted to individual modes.

Please note that many modes redefine individual keys in a local table, so the mapping can change between buffers and a global adaptation possibly not working in one particular mode.
