
The KDE project follows a similar approach with the Kdm program. The use of a separate login form has the advantage that the correct look and feel is already used at stage, and, furthermore, additional settings can be made. The same thing applies for GNOME, which uses gdm. You may change the language or the session type when logging in, and it looks better than plain xdm.

## 6.3.3 Keyboard mapping under X

The keyboard mapping too can be extensively modified by X. This is done by means of the xmodmap program. Usually, you will not have to make many changes to the keyboard map, because XFree86 takes over the keyboard assignments of the console. In spite of this if you plan substantial changes, I recommend the use of xcaps, which you can find in the Contrib directory on ftp.x.org. Another useful tool is the kev program which displays the full text for all events it receives (key strokes, mouse movements, and so on).

Especially in X applications that employ the Motif libraries, frequent use of special keyboard assignments which are not present in statically linked applications. These applications should contain a file XKeysymDB in which the missing linking between keys and functions is established. This file is stored either as /usr/lib/X11/XKeysymDB or as /usr/openwin/lib/XKeysymDB, another file can be used or in case of missing entries, you may be faced with error messages such as 'unknown keysyms'.

With the xmodmap program, you can also reconfigure your mouse as left handed. ## 6.3.4 X resources

Only can X itself be widely adapted to the requirements of the users in its look and feel, but the individual X clients can also usually be configured in a very flexible way. This is done by means of resources. Resources store values which are either system-wide or which can be overwritten by the user. System-wide valid resources are stored in the directory /usr/X11R6/lib/X11/app-defaults. There you can find a resource file for practically every X client.

The resources which are read by an application program and can be used for it configuration are documented in the corresponding map page in RESOURCES section. Some of these settings can be passed to the client command line options at the start. Each user, however, specify his/her settings by creating the file ~/.Resources. This file is loaded at the start of X (or after the login).

Modifications to this file do not become automatically active in an ongoing session, but must be read into the X11 system by means of a command, for example xrdb -merge .Resources. This data is stored in the X server which supplies the applications with the appropriate values.

Resources can be specified in a series of different formats, where many specialized ones are preferred to less specialized ones. The specification of:

```
rxvt.background:           lightblue
```

causes the program rxvt to use the colour lightblue as the background colour. With the entry:

```
*background: white
```

the background colour is set to the colour white for all clients. If both entries are present in the resources, rxvt uses the colour specified for it, whereas all other clients use white as their background colour.

If you cannot install programs in the system directories, you can specify the direct to be searched in the environment variable XAPPRESDIR. All in all, this configuration method has a do-it-yourself aspect, and does not compare favorably with the easy-to-use modern systems. On the other hand, the system is very flexible and is available on every X server.

## 6.3.5 Other configuration options

Another program to adapt X to users' requirements is xset. You can switch the keyboard click on and off and change its volume. If you want to change the tracking speed of the mouse, you also need to use xset. In addition, you can use this program to dynamically modify search paths for fonts.

## 6.4 Window managers

The appearance (the 'furniture') and the behaviour of the windows resembles the look and feel of a Window system. Under X, this part is implemented by means of the so-called window manager. The window manager under X is not part of the X Window system itself, but a client (application program), like any other.

This has the advantage that X itself does not (and cannot) make any prescriptions about look and handling, and even with 'busy' X client the system still reacts correctly.

Window managers determine the layout of the window's title bar, window frame, type of icons and, if needed, number of several virtual desktops. In addition, the window manager is responsible for the keyboard input. Depending on personal preferences, one can require a click in the window or to transfer the keyboard focus. Personally, I prefer the option in which the focus always belongs to the window where the mouse pointer is located.

There is a whole series of window managers with different properties, with the more recent ones following the 'Inter-client Communications Manual' (ICCM). The ICCCM is one of the official documents of the X Consortium which define the X Window system or the X environment. This documentation can be found on the Internet at ftp://ftp.x.org/xc/doc/specs/ICCCM. The ICCCM specifies the conventions with which applications operate.

### 6.4.1 The window manager fvwm

LINUX systems very often use fvwm, the new version fvwm2, or the special variation fvwm95. This window manager is derived from the standard twm, but needs significantly less memory. Nevertheless, this window manager is very powerful; it is able, for example, to represent a virtual desktop, and is flexible in its configuration, which implements almost every option you can think of.

This is initially the only option for a unique system environment although its look and handling are no longer state of the art. For commercial systems, the Motif window manager is currently the standard. Under LINUX you can use fvwm in Motif compatibility mode, or the Motif clone lestif, or you can employ a commercial mwm. On the other hand, it might be sensible to install fvwm on the other systems; often, however, this is not possible.

In this section, we introduce the configuration of fvwm version 2. Since the order of the entries is significant, the various options will be presented in the order specified in the default system.fvwmrc. We will discuss this later, but it should be briefly mentioned that besides fvwm itself there is a series of add-on programs, the so-called modules, whose configuration is also carried out in .fvwmrc. The default file is extensively commented, therefore, together with the man page for fvwm, the configuration is relatively easy to master.
