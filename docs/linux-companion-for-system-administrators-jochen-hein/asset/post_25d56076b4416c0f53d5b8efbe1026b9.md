## 10.2.5 Creating and inserting patches

Many programs employed under LINUX are distributed in the form of source code. When an author releases a new version, the number of changes is often relatively small in comparison with the entire source code. In such cases it is sensible to publish only the changes, or to download the changes from an ftp server in order to keep network load and transmission costs to a minimum. A file contains only the changes between two versions is called 'diff' or 'patch.' Such changes can be implemented automatically by means of the patch command.

Patch files are generated with the diff program. Even normal diffs, context diffs (-C), or unified diffs (-u) can be created. Normal diffs are smaller than context or unified diffs, but can be inserted only into otherwise identical files since the context of the changes is missing. Context and unified diffs contain (in slightly different formats) some lines of context around the changes, the changes can also be implemented manually if needed. Generally, however, changes are implemented using the `patch` program.

Since the changes between individual versions of the LINUX kernel are published as patches, we are going to use these patches as an example. First of all, we look at the beginning of a file patch (Listing 10.23) by means of the head program (see also Section 10.7.4). The patch contains the names of the modified files in the `linux` path.

If the patch is carried out inside the directory `/usr/src/`, the complete path must be preserved using the option `-p0`. Normally, this option could be omitted, but if new files are created, they will be created in the wrong directory.

If the patch is carried out inside the directory `/usr/src/linux`, the first directory name can be removed using the option `-p1`. Setting the option `-s` screens messages to be displayed only in the event of an error.

```
(Linux):/usr/src# zcat 1.2-patches/patch-1.2.13.gz | head
diff -u -r -N v1.12/linux/Makefile linux/Makefile
--- v1.12/linux/Makefile      Tue Jul 25 12:39:54 1995
++ linux/Makefile             Wed Jul 26 09:43:44 1995
```

## 10.4 Starting commands automatically

It is often required that CPU-intensive programs or programs that need exclusive access to the computer should be executed at a later point in time, for example, at night. This can be achieved by means of the @ command. If specific programs are regularly to be started at a given time, we can use the crontab command, which manages the control tables for cron.
