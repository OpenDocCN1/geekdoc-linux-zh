## 4.5.2 The mount program

Another possibility for accessing a data medium is to mount it into the LINUX directory tree. Most partitions are automatically mounted at system start-up and can be used by all users. For this purpose, the start scripts can call the mount program, which evaluates the file /etc/fstab.

However, the mount command is a privileged command which can only be executed by the system administrator. Thus, a non-privileged user cannot use mount to mount additional file systems. The program mount from the util-linux package is setuid is installed and carries out a series of additional checks. However, users can only mount file systems that are registered in the file /etc/fstab with the user option, and it is not possible to specify any further options.

It must be ensured that these file systems are provided with a series of additional options to prevent security problems. The options nouid and nodev are particularly important. If the corresponding file systems are not to be mounted at system start-up, the option noauto must be specified.

If a file system is registered in the file /etc/fstab, most options are superfluous when mounting it into the LINUX directory hierarchy. The commands shown in Listing 4.20 are equivalent to the /etc/fstab file specified in Listing 4.19.

In /etc/fstab, a series of additional options can be specified; for example, the uid and gid under which DOS file systems are mounted (DOS does not have user IDs). The fifth field specifies the frequency with which the file system is saved by means of dump. The sixth field indicates the order in which the file systems are to be saved. Often the root file system is marked with a l and all other file systems with a 2.

The mount program understands a series of options that are indispensable for system security. Other options are important for the convenience and security of non-privileged users. Some of the more important options are discussed below. They can either be entered in the file /etc/fstab or be specified after the option -o in a call of the mount program.

- - nodev prevents a device file from being used on a data medium that has enough access permissions to endanger system security. All hard disk devices (/dev/hd* and /dev/sd*) should only be readable (and writable) for the system administrator (and, if necessary, a corresponding group). Otherwise, a user could read (or even manipulate) all data on this hard disk. Therefore, this option should be set for all removable media (including CD-ROMs). The opposite of this option is dev.

- - Execution of programs from this device can be forbidden by means of the noexec option. The exec option, on the other hand, allows the execution of programs.

- - Generally, execution of programs can be allowed, but the particular use of suid programs can be forbidden by means of the nosuid option. The suid option, instead, allows the execution of suid programs.

- - Some partitions are automatically mounted at system start-up, others are not. This is achieved by means of the keywords auto and noauto, which only make sense in the /etc/fstab file.

- - File systems can be mounted either with read/write access (rw) or with read-only access (ro).

- - The root partition cannot be unmounted; thus at start-up, it is initially mounted readonly, and only after the file system check is carried out is the access mode changed to write access by means of the remount option. At system shutdown, the remount option is used again to change the mode back to readonly operation.

- - Partitions can be mounted with the sync option, which prevents modifications from being temporarily stored in the buffer cache. The default is async, which allows buffering. For diskettes, it may be sensible to write all data unbuffered before the user removes the floppy disk from the drive.

- - Nonprivileged users too should be allowed to mount disks or CD-ROMs. This is achieved by entering the user option in the /etc/fstab file. The system uses the options noexec, nosuid, and nodev as the default. The system administrator can overwrite these options in the /etc/fstab file.

- - The defaults option implies the options rw, suid, dev, exec, auto, nouser, and async, as discussed above.

Individual file systems may have additional options. Thus, the FAT file system nor HPFS has user IDs. Therefore, a user and group ID can be globally assigned to the whole file system when it is being mounted. This is done by means of the uid= and gid= options, each followed by the numeric identification. Assignment of permissions too can only be carried out for the entire file system, by specifying the corresponding umask= during mounting. Further options are extensively described in the man for mount (8).

## 4.5.3 The automounter amd or autofofs

The easiest solution for the user is the automounter (amd or autofofs) which, every time a user changes directory, temporarily mounts the corresponding file system. If the file system is not used for a certain time, it is automatically unmounted. It is, however, also possible to trigger the unmounting in such a way that a user can remove a data medium from the drive immediately after usage, without having to wait for the timeout. The full power of the automounter, however, is only unleashed in network operation; more detailed information on this subject is given in Section 18.3. The latest kernel version integrates autofofs which is soon supposed to replace the automounter.

## 4.5.4 The logical volume manager

One of the most important features of the kernel release 2.4 is the Logical Volume Managers. Up to now a filesystem was restricted to a single partition or RAID device. The logical volume manager has a completely different concept, working with physical volumes and logical volumes.

You need a current kernel release or a patch for one of the older releases and the programs to manipulate logical and physical volumes. The Web site where you can download these programs is mentioned at the end of this section; current distributions we deliver with a patched kernel and all utilities. An example.

### Physical volumes

A physical volume, or PV for short, is an ordinary partition on a hard disk, which is to be used by the logical volume manager. The partition type 0x8e is reserved for that use. The command pvcreate defines that partition as a physical volume. An example is shown in Listing 4.21.

```
# fdisk -l /dev/sda
```

More programs for the management of physical volumes are pvchange (to change the attributes of a PV), pvdata (as a debugging aid), pdisplay (to display information about a physical volume), pvmove (to move data between PVs) and pvscan (to scan for PVs). For detailed information and more options please see the pages.

### Volume groups

The logical volume manager manages a number of physical volumes in a volume group (VG). The command vgcreate creates a new volume group, and the command vgxtend adds more physical volumes.
