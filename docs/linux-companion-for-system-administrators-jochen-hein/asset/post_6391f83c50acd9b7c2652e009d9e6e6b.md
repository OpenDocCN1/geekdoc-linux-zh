# Image-specific options

The globally effective options can also be used inside the image-specific configuration blocks. Besides the global options, LILO provides the following additional options, which can *only* be used inside image-specific blocks.

```
append=string
```

Appends the string to the kernel command line.

```
literal=string
```

Sets the kernel command line to string.

```
ramdisk=size
```

Creates a RAM disk of corresponding size (in Kbytes).

```
read-only
```

Causes the kernel to mount the *root* file system read-only. Thus, an fsck can be carried out on this file system too. This is standard with all distributions. After the file system has been checked, it is remounted with write access. The parameters for number and intervals of the checks can be configured by means of the `tune2fs` program.

```
read-write
```

The *root* file system is mounted in read/write mode.

```
root=root_device
```

The specified device is used as *root* file system.

```
vga=mode
```

Allows the screen resolution of the console to be changed. At runtime, you can also use the SVGATextmode program for this purpose.

```
initrd=image
```

The file image is loaded as RAM disk. If this is not desired, you can specify *noinitrd* in the *LILO* prompt.

It is possible to have several configurations for the same image file, because LILO does not store the configurations in the image, but in what are known as image descriptions. An additional name can be assigned to an entry by means of

```
alias=alias
```

The use of LILO together with a UMSDOS file system is possible, but problematic. If a defragmenter is called under DOS, a kernel image can be moved to a different location on the hard disk. Subsequently, LILO may no longer find the kernel image to be booted, and the start of the system fails. In this situation, you can start the system with loadlin and reinstall LILO.

# The GRUB boot loader

A recent development is GRUB (Grand Unified Bootloader). Like LILO, it essentially consists of a boot sector, and there is no easy-to-handle configuration program (yet). The substantial advantage of GRUB is that it is capable of booting many systems directly and it has information on the corresponding file systems.

With LILO, it is only possible to start previously specified kernel images. GRUB can browse through the file system at the boot prompt and dynamically load different kernels. For daily use, you can set up a menu, but it is always possible to select other kernels or options dynamically.

# Configuration of GRUB

When booting, grub tries to read its configuration file. If such a file exists you can choose the system you want to boot from a menu. If no such file exists, grub opens a command line, which you can also call from the menu.

For regular use you save your configuration into a file. The name of that file is a name of your choice, but you must provide the name to grub when installing your boot sector. Listing 3.2 shows a simple configuration. A complete documentation of all options is provided in the source code of grub.

```
# timeout until the start of the default image
timeout = 30

# Boot a Linux kernel from /dev/hda2
title= Linux Boot
root=(hd0,1)
kernel=(hd0,1)/boot/mlinuz-2.0.0

# Boot Windows NT OR DOS
title= Windows NT 3.5/DOS boot menu
root=(hd0,1)
makeactive=
chainloader=+1
```

3.2 A simple grub configuration.

The configuration file for grub is a regular text file, in either UNIX or DOS format (they differ in the encoding of line end: UNIX uses a line feed, DOS uses carriage return and line feed). Comments start with a number sign (#) in the first column.

grub has, like LILO, global and local options. Global options are for grub itself or all images. The global options are:

timeout=number
time that grub waits before it starts the default image.

default=number
Number of the default image. The count starts with zero, so that the default zero starts the first image in the grub configuration.

fallback=number
If GRUB can't start the chosen image it tries to start the fallback image. This will only work when the error occurs in grub and not in the already started system.

password=password_new_configuration
Without this entry every user can change images or create new entries. It is also possible to select a kernel without any restriction and start it with any parameters. This entry disables these functions until the correct password is entered. After that grub uses the new configuration file where you may have entered images for the single-user mode.

Every image starts with a title line and ends implicitly with the option boot. The image options are:

root=partition [hdbias]
Use the partition partition as the root-partition. This partition is by grub, which passes some informations to the next loader. If the root partition is not readable by means of the BIOS, for example if it is beyond 1GB limit, you can use the option rootnoverify=disable the reading of the partition. The optional parameter hdbias is only used for BSD systems.

kernel=kernel-image...
grub loads the given kernel image. The image may be in a.out, ELF, LINUX or BSD format. The command itself ignores the remainder of the line, which is passed to the kernel as the command line.

initrd-file...
Loads the given file as an initial RAM disk for a LINUX kernel and passes the following parameters to the kernel as a command line.

makeactive
Marks the partition given as a parameter to root= as active. This may be required for some operating systems. You can only mark primary partitions as active.

chainloader=
Loads the given file or boot sector as a chain loader. grub passes control to some other boot loader, such as one from OS/2 or Windows.

pause=text
The given text is printed on the monitor and grub stops. A ^G is a beep.

uppermem=kilobytes
grub is able to detect more than 64MB RAM and gives that information to the operating system. This option is only likely to be for older systems.

boot
Boots the given image.

```
module=file ...
```

Loads a multiboot module. Modules may be stored compressed and will be decompressed automatically.

```
modounzip=file ...
```

Like the option module=, but grub will never attempt decompression.

grub has no mounted file systems, but can access files on different file systems because it knows the internal structures of these systems. This is the reason that you must enter the name of the partition as well as the filename. The syntax:

```
disk,partition,BSD-slice
```

You can use fd0/fdl for floppy drive, but in that case you't add a partition. If you use hd0/hd1 you can access the MBR if you don't enter a partition. The partition numbering starting with zero, so the first partition of the first hard disk is (hd0,0). The naming scheme is derived from BSD systems and is therefore different from the LINUX naming.

Beside the normal partitions used by DOS, Windows or LINUX, grub can also access slices of BSD systems. You can append a character to the partition number to identify the slice.

If grub expects a file name, you can append the absolute path to the partition name. For some functions it is possible to enter an offset or a sector number(with sector number).

You will appreciate grub's command line editor when you use it. The usage is similar to the bash shell and has completion well. The tab key shows a list of possible commands or other input. Since the size of grub is very restricted, not all functions of the bash interface are implemented.

The most useful commands for interactive usage are kernel= to select the kernel to boot and boot to finally start the operating system.

# Installing grub

Installing grub is not as easy as LILO. For LILO you create a configuration file /etc/lilo.conf and run LILO. Most distributions contain a configuration interface, so most users don't need to worry when installing LINUX.
