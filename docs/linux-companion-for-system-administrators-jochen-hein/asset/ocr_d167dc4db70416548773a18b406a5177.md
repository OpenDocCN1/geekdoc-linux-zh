# 446 NETWORK FILE SYSTEM (NFS)

+   - The network must be configured (ping from server to client and versa).

+   - The port mapper rpc.portmap must be started.

+   - The daemons rpc.mountd and rpc.nfsd must be started.

+   - When PC/NFS is used, the daemon rpc.pcnfsd must be started. This daemon is required for authentication and provision of printer services in connections involving DOS and Windows PCs.

+   - The NFS protocol assumes that the uid and gid numbers are the same on both computers. This can be obtained through identical /etc/passwd files or by means of NIS (see Chapter 21). If neither is possible (or sensible), the rpc.uuid can be used.

Which directory trees are available to other computers is specified in the file /etc/exports. There, the access to individual computers or networks can be restricted or read-only access allowed. This is achieved by means of several options, the most important of which are:

+   - Volumes are exported write-protected (ro, default) or writable (rw).

+   - The option root_squash redirects the user ID 0 to the user nobody (uid-2). The default value is no_root_squash.

+   - The users ID of server and client are equal to map_identity (default) or are assigned via rpc.ugidd (map.daemon).

A complete list of the possible options can be found in the man pages for exports(5) and nfs(5). Listing 17.2 contains an example for the file /etc/exports. The volume /home is exported to all computers in the domain veggies.example.org. The volume /opt is exported only to nfsclient. Accesses by user root are restricted to the user nobody whose names begin with proj. The volume /pub can be mounted worldwide.

```
/nfsclient(ro,root_squash)
/home *.example.org (rw,root_squash)
/project proj*.example.org (rw)
/pub (ro,insecure,root_squash)
```
