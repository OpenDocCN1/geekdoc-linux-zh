```sudoers
# Host alias specification
Host_Alias SERVER=server
Host_Alias CLIENTS=client1,client2

# User alias specification
User_Alias Operator=michael

# Cmd alias specification
Cmd_Alias LPR=/usr/bin/lpr,usr/sbin/lpc

# Privileges for users
#Who system=(dest_user) command
OPERATOR SERVER=LPR
wheel ALL=(ALL)
clientadm CLIENTS=(ALL)
jochen ALL=(root,uucp) NASSWD: ALL
```

## 4.17 Sudoers.

The first part of the sudoers file you may define aliases for systems, networks, users, and commands. These may be used to give a group of privileges and to simplify the rest of the configuration. The last part of the file in Listing 4.17 defines the granted privileges. The users defined in the alias OPERATOR may use all the commands defined in the command alias LPR on the server. In the example it only the user michael may use the commands lpc and lpr on the host server. More than one command, username, or hostname may be given separated by commas.

The next entry defines that the members of the UNIX group wheel (often a synonym for the system administrators) may use all commands on all systems. The keyword ALL is an internal alias defined by sudo. The third entry clientadm refers to the netgroup clientadm. In this example it may be used for grouping the system administrators of the client machines. The last line in Listing 4.17 allows the user to execute all commands as the root or uucp, without having to enter a password. If the system administrators have discipline, running sudo bash may be of real value. Even if you need a shell, there is no need for su: just type sudo bash. If you run sudo without further options, the command will be executed as root. The option -u switches to the given user instead.

The first time you run sudo you have to enter your password, not the root password. The calling user should be able to run certain commands as root, but should not know the password. In the standard configuration of the validity of the password will be stored in a timestamp file, so you will have to enter the password only once every so often. The command -k removes the timestamp file, so that you will have to enter the password again. Calling the command when logging out or when you leave your office for a day is a good idea.

The command -l lists all commands that are allowed for you. sudo lists all commands and parameters with syslog to edit the file and recompile sudo. For complete documentation see the pages sudo(8) and sudoers(5).

## 4.4.4 Capabilities under LINUX

Other systems, such as Windows NT or VMS, have a series of individual permissions that can be individually assigned and revoked. Under VMS, a user can even have the right to procure specific permissions, but these are not active at a normal login. This provides far better control over the system.

In the framework of POSIX standardization, a special standard for UNIX security is under development. This standard is known as POSIX.1(formerly POSIX.6) and, after many years, has not yet been passed. Even work, or it has stopped.

The standard defines a series of security interfaces, as for example auditing, access control lists and subdivision of the root privileges. Under LINUX, a project (LINUX Privs) exists which implements these features in the kernel and the corresponding user programs. These functions are still under development, and I hope that they will find their way into the distributions as quickly as possible.

## 4.5 File systems and data media

UNIX does not utilize drive letters. All data is integrated into one directory tree, and can be accessed in this tree. For the user, it makes no difference at all on physical hard disk or on file server the data is stored. When the access paths to the files are the same on all computers in the network, the user will notice no difference between being logged on to the file server or an arbitrary client.

Mounting the file systems and building up the directory hierarchy is normally a task for the system administrator. Nevertheless, it is common for non-privileged users to access their own data media, such as floppy disks, magnetic tapes, or CD-ROMs. Depending on data media and file system, various options are possible.

## 4.5.1 The mtools package for DOS file systems

DOS diskettes or hard disk partitions can be accessed by means of the mtools package. For this purpose, the existing drives or partitions that are to be made available are entered in the file /etc/mtools.conf. Alternatively, it is possible to use the file ~/.mtoolsrc or the file whose name is stored in the environment variable MTOOLSRC.

## CONFIGURATION ADMINISTRATION

To use the mtools, the user must have access rights to the corresponding devices. These can be obtained, for example, by assignment to a special group in the file /etc/group, which then has read and write permissions on the corresponding device files. All users who are using floppy drives are additionally registered in the floppy group. This is the default for modern systems.

The commands for accessing DOS data media are all known from DOS, with an 'm' put in front of the command name to differentiate it from other commands (mcopy, mformat, mtype, mcd, and so on). In all programs of the mtools, except for mformat, the corresponding device can be used with automatic recognition of the media size. Since the formatting program cannot determine the size by itself, the matching device must be used. An example for the file /etc/mtools.conf is shown in Listing 4.18. The corresponding device systems must not be mounted at the same time; otherwise the file systems might be damaged.

On most of the supported platforms, the mtools can be used without further configuration. In the example in Listing 4.18, the DOS partition and the virtual floppy disk and hard disk for the Doseemu are made available as well. Further information on configuration of the mtools can be found in extensive documentation.

The current version of the mtools supports the VFAT file system. This allows storage of long file names on diskettes as well, making it possible to transport such files too without any problems. As opposed to diskettes created with tar or cpio, these diskettes are also readable on a DOS or Windows PC.

Listing 4.18 Excerpt from the file /etc/mtools.conf.

```mtools
drive a: file="/dev/fd0" exclusive
drive b: file="/dev/fd1" exclusive

# First SCSI hard disk partition
drive c: file="/dev/sda1"

#dosemu floppy image
drive m: file="/var/lib/dosemu/diskimage"

#dosemu hdidimage
drive n: file="/var/lib/dosemu/diskimage" offset=3840
```
