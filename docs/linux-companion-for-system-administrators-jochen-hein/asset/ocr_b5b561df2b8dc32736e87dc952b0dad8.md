# THE LINUX BOOT LOADER 59

(fd0)

Writes the boot sector back to the floppy disk, after the block numbers of the stage2 file have been merged. When installing on a hard disk, (hd0) for the MBR of the first hard disk or (hd0, Partition) for partition. Remember that the partition count starts at zero.

(hd0,2)/boot/grub/stage2

Uses the file /boot/grub/stage2 of the given partition as a stage2 loader. The sector numbers of this file will be merged into stage1 loader. This code eventually reads the config file, loads the selected kernel and so on.

0x8000

Loads the stage2 loader at the address 0x8000. You won't change that address when using LINUX, for FreeBSD and the stage1_5 loader you use 0x2000.

p

Stores the name of the config file in the stage2 loader.

(hd0,2)/boot/grub/menu.lst

Uses the /boot/grub/menu.lst on the partition /dev/hda3 as a configuration file.

The biggest problem when installing grub is that there is no configuration tool. You have to enter a complex install= at least once. Later you can enter that command into the configuration file and then forget it. Newer versions of grub contain a LINUX shell, so there is no reboot required to install the boot loader.

# Where's the beef?

I like grub. It is very flexible and powerful, in particular for LINUX and *BSD systems. The biggest gains are the runtime configuration and the ability to select a kernel at boot time. But there are some drawbacks: the complex and unfamiliar configuration as well as the non-existent support like configuration tools in distributions. If you are in doubt as to whether you like it or not: just try it out by installing it on a floppy disk
