# 490 CONFIGURATION AND OPERATION OF A NAME SERVER

The PTR records are required by the function ghostbyaddr(3), which is responsible for the conversion of IP addresses into names. Each name in the PTR record is terminated with a dot to prevent BIND binding from the domain IN-ADDR.ARPA. You should include all network users that have an IP address in the name server to avoid having to wait for a name server timeout because no entry is available for reverse lookup.

```
name        (ttl)   addr-class  PTR      real name
155.31      IN          PTR      pea.example.org.
151.31      IN          PTR      corn.example.org.
```

Please note that all names must be terminated with a dot. Otherwise, the zone name (...in-addr.arpa) would be appended.

# 20.7.8 Mail Exchange (MX)

If a computer cannot be reached at the moment of sending mail (or the computer is not connected to the Internet, but via UUCP), another available computer can be entered for receiving the mail. If the original computer becomes reachable again, the mail is forwarded. Lower preference values correspond to 'costs'.

This function is often employed to enable only one or two computers in the network to accept mail. This concentrates configuration efforts and availability problems to a few computers only. You should check with the administrator of the computer before you have an MX record point to another computer. Otherwise, this computer will be bombarded with unexpected mail which may get lost.

Most mail servers are configured to accept only local mail and relay mail only to from local users. This is considered good practice, it stops members from abusing the system. However, you cannot simply use that machine as your MX, because relaxing is denied, and mail will be bounced back to the sender.

```
name                (ttl) addr-class preference mail exchange
pea.example.org. IN          MX 0      bean
```
