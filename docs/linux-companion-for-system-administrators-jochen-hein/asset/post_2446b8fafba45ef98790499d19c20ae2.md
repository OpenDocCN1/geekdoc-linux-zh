## 24.2.2 Network performance

A frequent complaint of network users is that data output over the network is too slow. Usually, users store all their data centrally on one (or more) servers. This has the advantage that data can be easily backed up and exchanged between colleagues. Transmission via the network is slower than storage on a local hard disk, but the advantages outweigh this.

Network throughput becomes even more important when, in addition, operating systems and programs are loaded from the network servers. The advantage is again easier and centralized management; the disadvantage is the high network load. Further network killers are X programs and swapping via NFS (for diskless devices). There may be several causes for the fall in data throughput rates.

## Collisions in the network

First of all, the network load may simply be too high. The Ethernet protocol CSMA/CD, Carrier Sense Multiple Access/Collision Detect is defined in a way that each computer can access the network at any time. In case of a collision (when several computers simultaneously send data over the network), data transmission is repeated.

After each collision, the computer waits a short time and retry transmission. If another collision is detected, the waiting time is increased. These delays are set at random to avoid the two colliding computers causing a new collision at the next attempt.

One disadvantage of the Ethernet protocol is that from a certain network load onward, the net transfer rate fails because of the number of collisions. This problem is not shared by the Token Ring protocol. Here, a special character (token) circulates around the ring. Each station which has this token can then work with the network. After transmission, the token is handed over to the next station. If the ring consists of a large number of stations, this can also lead to a fall in throughput. If the token disappears, for example, because the computer that had it has just crashed, then a new token is generated by one computer.
