## 4.12.2 The editor joe

the joe is an easy-to-handle WordStar clone programmed by Joseph H. Allen (jhallen@world.std.com). For many people used to DOS, this editor will initially be the easiest to handle one. The editor is configured by the system administrator by means of the file /usr/lib/joerc. Users can copy this file as ~/.joerc and modify it as they wish.

The author has created additional configurations for a better emulation of the WordStar or Turbo C editor (jstar) and a still fairly primitive emulation of Emacs (jmac). All sample configurations are well-documented text files which can be processed with any editor.

## 4.13 Keyboard mapping

Under Linux, keyboard mapping can be adapted to personal requirements in a very flexible way. This applies both for working at the console and working under X. This section only deals with console keyboard mapping; information on remapping keys under X can be found in Section 6.3.3.

Keyboard mapping for the Linux console is carried out by means of the loadkeys program. If a file name is specified as a parameter (for example, loadkeys de-latin1.map), the file is read and the keyboard mapping is modified accordingly. However, the loadkeys program can also read its input from the standard input. This is useful if the keyboard mapping is stored in compressed form (for example, on a boot or emergency floppy disk). Then, it could look like:

```
zcat /etc/keytables/de-latin1.map.gz | loadkeys
```

The kbd-0.95.tar.gz package, can be obtained anywhere an up-to-date Linux kernel is available, includes a series of keyboard tables. These keyboard tables are installed in the directory /usr/lib/kbd/keytables.

- de-latin1-nodeadekeys.map: In contrast to the keyboard mapping de-latin1.map, here the accent keys are not defined as dead-keys. Thus, these keys do not act as modifiers, as under de-latin1.map, but output the corresponding character directly.

The keyboard mapping is initially loaded at start-up by means of the loadkeys program. Users can, however, use the loadkeys programs to remap the keyboard according to their requirements. This can also have the effect of putting the keyboard into an unusable state. The file de-latin1.map can serve as an example of how to modify the keyboard mapping.

## The Emacs editor

Emacs Makes All Computing Simple
One solution to the acronym Emacs

In its documentation, Emacs is called an extensible, customizable, user-friendly, self-documenting editor. These are big words which, however, are not exaggerated when comparing Emacs with other editors. This chapter presents some of the functions of Emacs that make it so special.

The Emacs editor was originally written by Richard M. Stallman, founder of the Free Software Foundation (FSF) and initiator of the GNU project. The origin of this editor goes as far as pre-UNIX times: the first Emacs (Editor MACROs) was a macro package for TECO (Text Editor and COrrect) and ran on DEC's legendary PDP-11.

This editor has given rise to a whole family of Emacs-like editors which are distributed both commercially and free of charge. The central focus in this family is the GNU Emacs which is still maintained by its author. Richard M. Stallman. Other family members are, for example, XEmacs, developed on the basis of a prerelease of the GNU Emacs 19, jed, MicroEmacs, and jove.

Emacs is fairly large and on several computers (particular in little memory and CPU power) is relatively slow. On such computers, running an Emacs clone makes sense. However, the clone differs in many details from the original, and therefore a continuous switch between two editors is quite tiresome. Furthermore, many Lisp packages simply cannot be employed unless XEmacs is used.

Many operating system and computer vendors supply Emacs as an additional software package with their products. Otherwise, Emacs can be compiled on practically every UNIX system around because, as with all GNU programs, it is automatically configured by means of ./configure. Emacs demands a lot from the operating system, both during compilation and execution – but it is portable.

The Emacs editor is very powerful; it is a Lisp interpreter which how to handle texts. The Lisp dialect of Emacs is a (fully-fledged) Lisp: the Emacs Lisp (in short, elisp). Thus, during execution of macros, the novice user will be surprised by strange messages such as: Garbage collecting...

This message tells you that an internal function of the Lisp interpreter is running which releases memory that is no longer used. Since Lisp does not have explicit allocation and release of memory, this function is called periodically (or when more memory is needed).

There is a large number of adaptations, extensions, and macros for Emacs written in english: these macros are stored in files with the extension *.el, *.el files are the corresponding (byte-)compiled versions which the Lisp interpreter can execute much faster. These Lisp programs, together with the extensive and well-written documentation, are the reason for the huge space requirements of Emacs.

## 5.1 Which version of Emacs should I choose?

The Emacs family consists of a huge number of variations and more or less compatible clones. This multitude makes choosing a version relatively difficult, but there are always good reasons for choosing one version or other.

The most widespread version is probably the GNU Emacs which is directly developed by the FSF under the direction of Richard Stallman. This version includes a good selection of additional Lisp packages and runs both over X and on a terminal. Under X, different fonts and colours can be used. If required, texts can be stored in RTF (Rich Text Format) including the attributes.

The biggest competitor is the XEmacs. This version was originally developed to improve the X interface, but it can also be used on a terminal. Here, special functions are the use of colours on colour terminals and under X, together with the possibility of addressing one Emacs process from both a terminal and under X. A further advantage is that more Lisp packages are supplied than with Emacs. These packages are also stored in a better structured way.

One disadvantage of the XEmacs is that the Lisp interpreter and some functions are not compatible with the GNU Emacs – Emacs is not the 'standard Emacs'. Therefore, many Lisp extensions run only with the GNU Emacs or an older version of the XEmacs. Emacs needs significantly more memory and CPU power than the GNU Emacs. The increase in power comes at a price.

When we talk about Emacs in the following sections, we mean both GNU Emacs and XEmacs. In most cases, these two have very similar or even identical behaviour, so that differentiating between them makes little or no sense.
