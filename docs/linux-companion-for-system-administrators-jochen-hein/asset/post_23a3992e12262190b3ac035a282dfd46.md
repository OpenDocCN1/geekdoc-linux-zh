grub is different. Most distributions don't use grub and there are no configuration tools. But there are some tricks to make your life easier.

The first method is to drop the grub boot sector on a floppy. Under LINUX you can use the commands shown in Listing 3.3. Boot from that floppy and you are dropped in the command line. Here you can select a kernel image and boot it or you can install grub.

```
(Linux):> dd if=bin/stage1 of=/dev/fd0 bs=512 count=1
(Linux):> dd if=bin/stage2 of=/dev/fd0 bs=512 seek=1
```

Listing 3.3 Creating a generic grub disk.

The command install completes the rest of the installation. If you started with the generic boot disk you must enter the complete command. If you have a preconfigured grub installation you can enter the command in the config file. You can also use the grub shell and run it with a hand-made config file. The complete syntax of the install command is:

```
install=stage1 [d] destination stage2 [address] [p]
[config-file]
```

grub will read and check the file stage1. The block list from the stage2 will be entered into stage1 and the result installed in destination. The address, if given, is the destination for loading stage2. If the option p is used, the name of the configuration file will be stored in the stage2 file.

This seems to be very complicated, but it really isn't. Just take pencil and paper and note the comment. I used the commands shown in Listing 3.4 to install grub on a floppy disk.

```
install=(fd0)+1 (fd0) (hd0,2)/boot/grub/stage2 0x8000 p \
    (hd0,2)/boot/grub/menu.lst
```

Listing 3.4 Installing grub on a floppy.

The parameters are in:

- (fd0)+1: Reads the first sector of the floppy disk and uses it as the boot sector.
- (fd0): Writes the boot sector back to the floppy disk, after the block numbers of the stage2 file have been merged. When installing on a hard disk, (hd0) for the MBR of the first hard disk or (hd0, Partition) for partition. Remember that the partition count starts at zero.
- (hd0,2)/boot/grub/stage2: Uses the file /boot/grub/stage2 of the given partition as a stage2 loader. The sector numbers of this file will be merged into stage1 loader. This code eventually reads the config file, loads the selected kernel and so on.
- 0x8000: Loads the stage2 loader at the address 0x8000. You won't change that address when using LINUX, for FreeBSD and the stage1_5 loader you use 0x2000.
- p: Stores the name of the config file in the stage2 loader.
- (hd0,2)/boot/grub/menu.lst: Uses the /boot/grub/menu.lst on the partition /dev/hda3 as a configuration file.

The biggest problem when installing grub is that there is no configuration tool. You have to enter a complex install= at least once. Later you can enter that command into the configuration file and then forget it. Newer versions of grub contain a LINUX shell, so there is no reboot required to install the boot loader.

# Where's the beef?

I like grub. It is very flexible and powerful, in particular for LINUX and *BSD systems. The biggest gains are the runtime configuration and the ability to select a kernel at boot time. But there are some drawbacks: the complex and unfamiliar configuration as well as the non-existent support like configuration tools in distributions. If you are in doubt as to whether you like it or not: just try it out by installing it on a floppy disk.

# Another boot loader: Choose-OS

Yet another boot loader is cho (Choose-OS) by Tuomo Valkenen, chos is as static as LILO, but the syntax of the configuration is simpler, see Listing 3.5.

```
# Title of the menu
banner=Please choose your system

# Where to install the boot loader
install=/dev/hda2

Linux "Linux" {
  image=/boot/vmlinuz
}

bootsect "DOS" {
  image=/dev/hda1
}

/etc/chos.conf.
```

**Listing 3.5** A very simple /etc/chos.conf.

The configuration consists of a global and an image-related part, as for LILO. A nice addition is that you may not use a text file as a message to display but can use a screen dump that can contain attributes, like colours. The nice optical appearance and the possibility to use different colours for text, the menu and selected entry is useful for many users.

When comparing it with grub, chos is still static. But it contains the tool vchos to configure the boot loader under X. The colours are nice, but support for a serial console is missing. If you like, you can try chos on a floppy disk.
