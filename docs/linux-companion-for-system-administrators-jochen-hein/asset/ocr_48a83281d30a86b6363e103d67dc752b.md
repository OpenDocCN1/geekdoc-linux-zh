The necessary IP addresses can be entered into the corresponding rc script or into a configuration file. In the Red Hat distribution, the IP addresses are stored in the file /etc/sysconfig/network; The S.U.S.E. distribution stores this information in the file /etc/rc.config.

The IP address can also be dynamically assigned during booting of a BOOTP request [rfc0952]. For this purpose, a BOOTP server or a corresponding gateway may be configured in the local network which determines the IP address that corresponds to the hardware address and passes it to the client. RFCs working on this subject are [rfc1497] and [rfc1542]. An extension of the BOOTP protocols is defined in [rfc2132] with the DHCP (Dynamic Host Configuration Protocol). More about setup and operation of a BOOTP server can be found in Chapter 23.

Since the address space available on the Internet (with IPv4) is slowly becoming exhausted, the implementation of IPng (Internet Protocol, version 6) has begun, which greatly increases the address space. Through this change, the IP addresses are becoming significantly longer, so many more computers can be individually addressed.

# 13.3.1 Netmask and broadcast address

The Internet Protocol differentiates between local computers installed in the same subnet and remote computers. A computer is in the same subnet if its address matches all bits of the broadcast address specified by the netmask.

In this case, membership in the same network can still be directly seen by the user. If you use subnetting (see also [rfc0940] and [rfc0501]) you must look at the bit masks. Subnetting is used to subdivide an assigned network internally and to separate the subnets by means of a router. Such a separation is recommended for reasons of reliability of operation of networks that exceed a certain size. Another reason for subnetting could be that your provider has assigned you only 32 or 64 official IP addresses.

In subnetting, the boundary between network address and host address does not necessarily lie on a byte boundary. Thus, the network administrator is free to choose any arbitrary subdivision. This has the unfortunate effect that already scarce IP addresses are given away (one network address and one broadcast address for each subnet), so employing private addresses in the sense of [rfc1918] should be considered instead.

The counterpart to the above is supernetting (see [rfc1518] and [rfc1519]).
