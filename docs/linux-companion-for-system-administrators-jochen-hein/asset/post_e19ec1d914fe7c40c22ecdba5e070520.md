## Connecting to the Internet 23

Larger business networks are usually connected to the Internet (via a provider) by means of a router or firewall. If you need to connect only one or a few computers temporarily to the Internet, you will usually employ a modem or ISDN connection. Under LINUX, several alternatives are available. Which of these you can use is a matter of discussion with your Internet Service Provider (ISP), who will also be able to supply you with sample configuration files or scripts. Even if your ISP cannot provide direct support for LINUX, you should still check the usually available scripts for Windows – this may help you.

Note that during an online connection your computer is a nearly fullyfledged Internet computer. This means that alien users can gain access to your computer and the services provided by it. Many problems can be easily solved, others require effort. Some hints are listed in the following overview:

- You should employ the TCP wrapper to prevent access by alien computers via its protection mechanisms. More details about the TCP wrapper can be found in Section 14.3.
- You should provide as few network services as possible. Check the file /etc/inetd.conf for unnecessary services and deactivate them.
- You should use well-chosen passwords and mark unused user IDs with an asterisk (*) in the password field.
- You should watch the log files of your system. Here you can find traces of failed ‘attacks’; sometimes, however, the cause for log entries can also lie in one's own carelessness.


**23.1** The file /etc/ppp/options.

With the keyword auth you can specify that authentication is required for each PPP connection. Thus, a connection can be established only to computers who are known locally. There are two protocols, named Password Authentication Protocol (PAP) and Cryptographic Handshake Authentication Protocol (CHAP) with which can be used by PPP. If you can, you should use CHAP because it is more secure than PAP, but in no case should you do this without an authentication.

CHAP requires the peer to have a special password file (secrets). PPP with the ppp-option login checks the password against the system password file (/etc/passwd).

This kind of authentication can be requested from the server and from the client. Thus, both sides are relatively sure that the partner is what it claims to be. This problem is not solved by SLIP.

Various options of this file can be overwritten by other settings, for example in the file ~/.ppprc. However, options that are particularly relevant for security can no longer be changed, therefore you should create a global option file.
