`ping` 也可以存储在 `/usr/bin` 下，但另一方面，它对于错误检测非常有用。

**文件系统修复** 在系统崩溃的情况下，文件系统会在下次系统启动时自动进行检查。这是通过从一个仅可读的根文件系统启动完成的。因此，修复文件系统所需的所有程序都必须存储在根分区中。关于系统启动的更多详细信息可以参阅第 3 章。

作为替代方案，你可以从第二个根分区启动系统，或者使用启动软盘或安装光盘。但通常情况下，你应该可以在不需要这些辅助工具的情况下完成。

**恢复数据备份** 将数据备份所需的程序和配置文件存储在根分区中通常是明智之举举，因为这允许你在紧急情况下通过一个极简的系统来恢复丢失的数据。第 7 章关于数据备份的内容将更详细地讨论这一主题。

LINUX 的初学者现在可能可能会不使用 `/usr` 分区，或者为整个 LINUX 系统只划分一个分区。在这种情况下，所有需要的程序都是可用的，但有很多理由让根分区尽可能小，并将数据分布在多个分区上。对于你的需求和系统，什么是明智的取决于你决定。

**错误敏感性** 根分区中的错误比其他文件系统中的错误更严重，因为它们可能会损坏文件检查所需的程序或其他重要程序，导致必须使用启动软盘或应急软盘。

由于 `/` 分区始终处于可写状态，在系统崩溃期间发生的不一致情况比平均水平要多。当 `tmp` 或 `/var` 目录没有存储在单独的分区且程序仅创建了临时文件时，情况尤其如此。

为了让你放心，应该说，即使在系统崩溃后，数据丢失也非常罕见。检查文件系统的程序（特别是 Extended-2 文件系统）非常强大且可靠。

**非共享数据的分离** 根分区不能被不同的计算机共享，因为要考虑许多特定于系统的项，例如内核中的驱动程序、主机名或网络地址。

# 18 LINUX 标准

多个根分区 带有较小的根分区，如果出于数据安全考虑创建了第二个根分区，在硬盘上只会占用少量额外空间。这可以作为应急或备份系统使用。

**用户数据的简单备份** 出于数据安全考虑，可以通过将数据分布在不同的文件系统上来来实现数据分离。此外，`/home` 和 `/usr/local` 分区在系统更新期间保持卸载状态，因此这些文件系统在系统更新或重装后不会损坏。关于数据安全的更多信息可以参阅第 7 章。

**性能方面** 交换文件（swap file）明显比交换分区（swap partition）慢，因为在内存区域之间进行交换时必须执行文件系统的管理功能。根分区中的交换文件会导致磁盘和文件系统的持续活动。这增加了系统崩溃时发生文件系统错误的概率。通常，`/tmp` 目录也存储在单独的分区中，或者在内存很大的计算机上存储在内存磁盘（RAM disk）中。

访问负载可以分布在不同的硬盘和分区上。特别是在配备了多个 SCSI 硬盘的系统中，这种分布可以显著提高速度。

当前的 LINUX 版本提供了 RAID 0、1 和 5 级。这允许将数据分布在多个物理硬盘上（RAID-0）、进行镜像处理（RAID-1）或通过校验分分区（RAID-5）来确保安全。RAID-0 可以提高性能；RAID-1 和 RAID-5 提供更高的数据安全性，因为一块硬盘故障而不会丢失任何数据。关于此主题的更多信息可以在内核源码中的 `README.md` 文件中找到。
