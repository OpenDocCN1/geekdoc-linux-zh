# 16.3 The r tools

One disadvantage of the telnet and ftp protocols is that at each login
password is transferred unencrypted via the network, thus, via potentially
insecure connections.² This can be prevented by the r tools, although then you
are depending on the reliability of the system administrators. Furthermore, these
tools, which originate from the BSD world, exist only on UNIX systems. Some
NT servers have installed these services too, but they do not belong to standard
distributions.

As a further restriction, the corresponding daemons must be running on the
remote computer. On many systems, this is not the case for reasons of security.
Security can be jeopardized, for example, by users including a plus sign (+) in the
/.hosts, thus opening their user ID to the whole world. There are
daemons which simply ignore this kind of entry. The protocol itself is to IP
 DNS spoofing and this is only really sensible in environments that are
single administration.

The r tools were developed at the University of California at Berkeley,
when the TCP/IP system was implemented at BSD. Beside the already
standardized protocols such as telnet and ftp, additional protocols were
developed and some local UNIX commands adapted to be used in networks and
on remote computers. The r is an abbreviation of remote.

# 16.3.1 Execution of programs on remote computers

The program rsh (remote shell), not to be confused with the restricted shell
which is sometimes also called rsh can be used to start programs on remote
computers. On some systems, the program is also called rsh to avoid the
name clash with the 'restricted shell'. For this purpose, the file /.hosts (see
Listing 16.5) must be created on the remote computer. Each line of this
contains a computer name. Thus, the user can directly log in from the alien
computer using the r tools without having to specify a password.
