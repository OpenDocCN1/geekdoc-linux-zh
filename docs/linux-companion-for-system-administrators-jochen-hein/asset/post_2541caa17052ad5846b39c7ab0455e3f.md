## 2.4.2 /usr/bin - programs

The /usr/bin directory is the primary directory for programs in a LINUX or UNIX system. An exception is deuted by programs that are exclusively destined to be used by the system administrator (these programs are stored in the corresponding /sbin directory), programs that have been installed by the administrator in /usr/local for the system in question, and the programs required for system start-up, which must be located in /bin.

When creating scripts that are started via the ! mechanism, you must specify the complete path to the interpreter. The character sequence ! tells the kernel that the program cannot be started directly, but has to be processed by an interpreter. Thus, the interpreter is loaded and passed the script.

The absolute path is no problem for sh or c scripts since these programs can be found in the /bin directory in every UNIX system. More problems are caused by interpreters, such as perl, tcl, or python, which are often installed in different locations. Scripts that use these interpreters can often not be ported unchanged from one system to the other, because the path in the first line of the script must be modified. Here, the file system hierarchy recommends that these interpreters be installed in the /usr/bin directory, or that symbolic links to the programs should be established. Then scripts can reference the interpreter in /usr/bin, independently of the directory in which the programs are actually installed.

## 2.4.3 /usr/include - include files

This directory contains the header or include files for the C library libc. It contains a series of subdirectories in which the header files for different subsystems are stored. The header files belonging to libc are not complete; the kernel-specific header files are missing. Here, the symbolic links to the kernel sources (generated by means of make symlinks in the kernel directory) of the utmost importance, otherwise many system-related programs cannot be compiled.

## 2.4.4 /usr/lib - libraries and program packages

This directory stores the libraries and object files required for programming, but also internal programs of the GNU C compiler gcc. In addition, there is a range of static data. Each program that needs static, processor-type-independent data should install this data in a subdirectory under /usr/lib.

Old sendmail versions used to be installed as /usr/lib/sendmail. Therefore, this path is hard-coded in many programs. The sendmail program is now installed in the /usr/sbin directory. For reasons of compatibility, you should create a corresponding symbolic link. The /usr/sbin directory should be readable for all users, and the sendmail program should be executable for all users. The smail program is also installed in /usr/sbin, but you must also create a symbolic link with the name sendmail.

## 2.4.5 /usr/local - locally installed software

Here, you should create essentially the same hierarchy as under /usr. The system administrator can install local programs which are not part of a distribution (see Table 2.6). After the installation of a distribution, this hierarchy should be empty except for the names of directories, so that programs belonging to the distribution and subsequently installed programs can be identified. This separation facilitates system maintenance both when installing or updating other programs.

| /usr/local | /usr/local hierarchy |
|---|---|
| bin | Locally installed programs |
| games | Games |
| include | Header files for C programs |
| lib | Libraries and program packages |
| local | Local installations (initially empty) |
| sbin | Programs for the system administrator |
| share | Architecture-independent data |
| src | Source code of various programs |

Table 2.6 Overview of the /usr/local hierarchy.

When updating a distribution, you must be aware that program files in /usr/ may be overwritten. By definition, the /usr/local directory is therefore not the complete responsibility of the local system.

## 2.4.6 /usr/sbin - programs

The /usr/sbin directory contains programs intended for the system administrator. Here, you will find programs that are used for system maintenance and administration. These programs are not intended to be used by regular users.

## 2.4.7 /usr/share - architecture-independent data

This directory contains data that is architecture-independent. This includes documentation, icons, and other resources used by various programs. The data here is not specific to any particular processor or operating system.

## /usr/share/man - online documentation

The /usr/share/man directory is the primary manual directory. Here, you will find all man pages for the programs contained in / and /usr. The documentation is subdivided into the following sections:

- 1. Commands: documentation of the commands that users can call at the shell.
- 2. System calls: operating system calls.
- 3. Functions of the C library: documentation of many functions.
- 4. Device files: description of special files (devices).
- 5. File formats and conventions: description of configuration files, for example, /passwd and /syslog.conf.
- 6. Games: description of the installed games.
- 7. Macro descriptions and standards: hints on macro packages (for example groff) or standards (for example character sets).
- 8. Commands for the system administrator: description of commands which are used only by the system administrator.

In directories other than /usr/share/man, individual sections can be omitted if no manual pages are needed for these sections. This applies, for example, to category 4, device files, which exists under /usr/share/man, but not under /usr/local/man.

Man pages are distributed in English. It is, however, desirable that programs should in future be supplied with translated man pages. A group of committed users working with Martin Schulze doing just for German translations, and there are other translations as well.

For an ordered, language-dependent access, you need to create a subdirectory for each new language in the above-mentioned structure. For manual pages in English, you can still use the path /usr/share/man/; German manual pages would be found under /usr/share/man/de/man/. The names of the directories are derived from the POSIX.1 standard; a precise explanation can be found in Section 8.3.

If a distribution installs preformatted man pages, this can be done in the catman directory. Installing only preformatted man pages is generally considered poor style. Users can view this documentation on screen, and cannot output it as a PostScript or DVI file. This makes a visually appealing printout impossible.

## /usr/share/misc - miscellaneous

Many programs have only one or a few files that can be stored under /usr/share. Since it is not worth creating a separate subdirectory for each program, it has been decided to propose this directory. The FHS contains a list of files that are likely to be found here.
