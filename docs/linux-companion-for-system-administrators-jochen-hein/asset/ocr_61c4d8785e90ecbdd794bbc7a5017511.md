Furthermore, you can specify the domain name in resolv.conf. Otherwise, the part after the first dot (.) is used in the host name. The domain used in Listing 15.3 is store.tuttifrutti.example.org.

The search list (keyword search) specifies how to construct an existing computer name out of an incompletely specified host name (without domain). By default, the only domain name is appended rather than all parts of the domain separated by dots, as in older versions. An incongruent entry in the search list can lead to a number of unwanted DNS requests to alien computers, which is not well received. The following example is intended to clarify the process.

In the sample file /etc/resolv.conf (Listing 15.3), the search list is entered as store.tuttifrutti.example.orgtuttifrutti.example.org. Now, a user tries to establish a connection with the computer name into an IP address (with a aid of name server, the file /etc/host.conf), a search is made for the computer name itself. If it is not found in the name server, the string store.tuttifrutti.example.org is appended with a dot (.) to the computer name, and the next entry of the search list is asked again. If this request is unsuccessful (tuttifrutti.example.org in the above example) is tried.

If the top-level domain (for example .uk, .edu or .com) were also part of the search list, a further request is added to the above-mentioned requests which would, for example, for the computer somehost.somewhere.org domain org.uk. This kind of domain name is no longer assigned, and neither are two-letter subdomain names.

For individual processes, you can overwrite the configuration of search and option with the environment variables LOCALDOMAIN or RES_OPTIONS. More detailed information on the keywords sortlist and options can be found in the man page for resolver (5).

Several programs are available to test the connection to a name server or its configuration. Some of the most widely used tools are presented in the following sections.
