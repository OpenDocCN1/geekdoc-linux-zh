# Password Authentication Protocol

If authentication with CHAP is not possible, you should at least use the Password Authentication Protocol (PAP). In this file, too, both the personal and the remote passwords are stored.

The entry in Listing 23.6 is used for logging in the computer corn. If the computer corn identifies itself by means of PAP, the second line is used for verification. Please note that some systems only have one password or secret for each communication partner. In this case, the password is the same for both directions.

With PAP, the password is transferred via the link. At the remote system it may be checked against the pap-secrets file or the system password file (/etc/passwd) by the means of the crypt (3) function. Since CHAP uses a different encryption algorithm this PAP is not possible with CHAP.

# 23.2 Automatic connection with dial

The procedures described up to now require the connection to be manually established and terminated by the user. This is not very efficient and it may lead to 'forgetting' an open connection which goes on accruing telephone charges. It is much more useful if the connection is dynamically established when needed, without the user having to intervene. If the connection is not used for a certain time, it can also be automatically terminated. Since establishing and terminating connections are initiated from a root process, the pppd program in this case does not need to be made setuid.
