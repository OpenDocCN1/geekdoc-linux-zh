QIC-40/80 magnetic tapes must be formatted. Under LINUX, this is not possible, so you must either buy preformatted tapes or format them over DOS. Under LINUX, the device files for the floppy streamer are /dev/rft0 to /dev/rft3 or /dev/nrft0 to /dev/nrft3 for no-rewind devices. ## 7.3.2 QIC-02 streamers

Another interface standard is QIC-02. Here, the tape drives are connected to an additional controller card. Thus, the timing problems of the floppy tape drive no longer apply, but in return you need a free interrupt, a DMA channel, and a free I/O address. The capacity of the tapes is higher than the above-mentioned 120 Mbytes.

## 7.3.3 SCSI streamers

For SCSI streamers there is a range of standards (QIC-150/520/625). They differ in capacity, recording method, and sizes of cassettes. For LINUX, it makes practically no difference which drive type is used; only the SCSI controller must be supported.

Today's most fashionable devices are (SCSI-) DAT drives, which have a very high capacity (up to 4 Gbytes). Thus, even larger partitions can be backed without changing tapes. Unfortunately, after using the cassettes several times, data security suffers due to the very high abrasion experienced during operation. You should therefore regularly clean the drive and replace a tape after a certain number of write operations. DLT drives do not have this problem, or are significantly more expensive.

## 7.3.4 Backup via network

Under LINUX, as under any other UNIX, the backup can be carried out on a tape drive that is connected to another computer which can be reached via the network. For a large number of computers in a network, it may be sensible to create a backup server. This system is then connected to powerful tape machines, and all computers of the network could be backed up by this system.

This makes it possible to carry out central backup, so tape management need only take place at one location. Here, special measures such as the safe storage of cassettes can be organized relatively easily. Furthermore, it is no longer the individual user or the local system administrator who has to be responsible for backup, but backup can be established as a service of the computer center.

The disadvantages are the effort of coordinating and configuring the system plus in network load. Furthermore, a backup may take more time over the network than on a fast tape drive. However, if you need to backup many (networked) computers, you should in any case choose a network-wide solution.

## 7.3.5 CD-ROM or CD-RW

Today CD writers are available at a low cost for connection to an IDE or SCSI controller. Even cheap drives write at least double speed and have a capacity of 650 MBytes. In a lot of cases this is sufficient to backup your own data. The cost of the empty disks has fallen in the last years, so it is not too expensive to use CDs for regular backups.

CD-ROMs are stable for years, whereas some magnetic tapes should be copied at least once a year to another tape. Furthermore nobody can change data once it has been written to a CD-ROM, which is very useful for archives or revisions. Private users may prefer CD-RW for backup, because the disk can be overwritten when needed.

## 7.3.6 Special data media

In rare cases, removable disks, floptical disks or WORMS (Write Once Read Many times) are used for backup purposes. Because of their high cost, these data media are rarely employed.

## 7.4 Backup strategies

Backup strategies are determined by many local factors. The system administrator must decide which data needs backing up at which intervals, and the number of backup media needed for this purpose. Furthermore, the sequence of complete and incremental backups needs to be specified. In complete backups, with a few exceptions, all files are backed up. In an incremental backup, the backup affects all files that have been modified since the last backup.

### 7.4.1 Extent and time of backup

First, the question should be answered what data needs backing up and at what intervals. For many LINUX systems, the following gradients are the most likely.

As a rule, you should try to backup your data at low traffic. If you want to obtain a truly consistent backup, you should carry out the backup in single-user mode. In practice, this will not always be possible. Except when backing up databases, however, you should copy these files into a new directory first (for example /etc.old), so that they can be directly accessed after the update. This allows many settings applied to a LINUX or UNIX system to be easily applied again to the updated version.

### 7.4.2 Classes of files

Not all files need to be backed up on a daily basis. For many files which are only amended, a weekly backup may be sufficient. For other files, even a daily backup is not enough.

# Backup of user data

User data under LINUX are usually stored in the /home directory are continually modified and should be frequently backed. In commercial environments, we recommend a daily (incremental) backup of modified data. In addition, a complete backup should be carried out at least once a week. Loss of work done by several programmers or employees over a couple of days could cause substantial costs.

On privately used systems, a weekly or monthly backup can be sensible, according to the user's or system administrator's estate. Depending on the amount of data, it might be possible to plan only complete backups which would greatly facilitate the handling. Longer intervals between backups are seldom sensible if you work with your system on a regular basis.

# Configuration files

The configuration files stored in /etc and /var are also subject to frequent changes. These files are often the result of extremely hard work and specialist knowledge, so this data should be backed up regularly. This applies particularly to network and mail configurations.

These files should in any case be backed up before a system update. It is often sensible to copy these files into a new directory first (for example /etc.old), so that they can be directly accessed after the update. This allows many settings applied to a LINUX or UNIX system to be easily applied again to the updated version.

These settings are the ones that adapt the system to the requirements of the user and facilitate day-to-day work. These adaptations have not been checked at least by the system administrator, the new installation is not yet a full replacement for the old one.

# The /usr partition

The data and programs stored in the /usr partition are relatively static and to a large extent be copied fresh from the installation medium. Nevertheless, it may be sensible to make backups at longer intervals, but certainly always an update of important software packages.
