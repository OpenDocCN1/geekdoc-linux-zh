The parameters of the connection can be further restricted by the use of a configuration file. In the file /etc/ppp/options, global options for the system can be specified. Listing 23.1 shows a simple example. You may create an options file for every port (/etc/ppp/options.Port) or for every peer (/etc/ppp/peers/peername).

```
# Global PPP options
auth # Authentication required for each connection
Lock # Create UUOCP-like lock files
```

**23.1** The file /etc/ppp/options.

With the keyword auth you can specify that authentication is required for each PPP connection. Thus, a connection can be established only to computers who are known locally. There are two protocols, named Password Authentication Protocol (PAP) and Cryptographic Handshake Authentication Protocol (CHAP) with which can be used by PPP. If you can, you should use CHAP because it is more secure than PAP, but in no case should you do this without an authentication.

CHAP requires the peer to have a special password file (secrets). PPP with the ppp-option login checks the password against the system password file (/etc/passwd).

This kind of authentication can be requested from the server and from the client. Thus, both sides are relatively sure that the partner is what it claims to be. This problem is not solved by SLIP.

Various options of this file can be overwritten by other settings, for example in the file ~/.ppprc. However, options that are particularly relevant for security can no longer be changed, therefore you should create a global option file.
