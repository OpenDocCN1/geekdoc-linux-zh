every ten minutes, the crontab could contain one of the entries shown in
Listing 10.33.

```
# The following command is started every ten minutes.
# This entry is standard on System V computers
#0,10,20,30,40,50 *** touch /tmp/cron_is_running
# Start every ten minutes; Vixie Cron extension
0/59-10 *** touch /tmp/cron_running.2
# And still somewhat simpler
#10/* *** touch /tmp/cron_running.3
```

Listing 10.33 Executing commands every ten minutes.

Some cron versions require an empty line at the end of the file, but do not
support commands. If in doubt, you will find further information /var/
log/cron or the system log category daemon.

The use of the cron command can be controlled bymeans of the files
/etc/cron.allow and /etc/cron.deny. If a file /etc/cron.allow
exists, only the users who are listed in this file may use this tool. If the
/etc/cron.deny exists, those users listed in the file are excluded from using
cron command. If neither of the files exists, either every user or root
 use this tool, depending on the implementation of the cron daemon.

# Further examples

In Listing 10.34, a program is to be started at 6:00 in the morning and at 22:00
ine the evening, but only on working days (Monday to Friday). The same program
 obviously be used again in further entries. Thus, you can easily define
different patterns for working days and weekends.

As in Listing 10.35, a program is to be started on the first day of
every month at 02:00; obviously no restriction on special days of the week or
public holidays is possible. If you specify a day of the week, for example Sunday,
the program is executed additionally on each Sunday. There is no intuitive way of
having jobs executed on the last day of every month.

```
0 6,22 * * 1-5 /usr/lib/uucp/uucico -r1 -spertron
```

Listing 10.34 Execution twice a day from Monday to Friday.

```
0 2 * * clean_logs
```
