Another function often missed under UNIX is sending a short message to a logged-in user. If this user works on the same computer, you can use the write command. However, if the user is logged in on another computer, you cannot write. If sendfile is installed, you can send a brief message with sendmsg which is immediately displayed to the user.

## Network File System (NFS)

With the Network File System (NFS), files can be accessed and used by different computers. Thus, for example, users can have their home or mail directories, data and configuration files on all computers, which greatly facilitates their daily work. Another sensible server installation of programs in /usr/local or /usr, in particular of voluminous packages such as X11 or TeX. This also reduces the administrative effort of updates.

The computer on which these directories are locally available is called the NFS server; the computer that uses data from a remote computer is called an NFS client. For the user, it does not matter at all whether files are stored locally or on a remote directory tree is integrated into the local directory tree. Directory trees exported by the NFS server are also known as NFS volumes.

The Network File System is implemented on the basis of Remote Procedure Calls (RPCs, see also Section 14.6). This protocol was developed by Sun and is published in [rfc1094]. NFS is the standard protocol for sharing directories between different UNIX systems. In the PC world, you will also find NetWare (IPX), Server Message Block (SMB), LAN manager, Windows for Workgroups, Windows NT; see Section 19.2.

As already mentioned in Chapter 14, the Sun RPC system is mandatory for the operation of an NFS client or server.

### 17.1 LINUX as NFS client

Frequently, NFS servers already exist in local networks for the home directories of the users or, for example, for sharing CD-ROM drives. Since many system vendors no longer supply printed documentation with their systems, Usually, in these cases, LINUX will initially be configured as an NFS client. The following conditions must be satisfied:

- The network must be configured; that is, a ping to the NFS server must be possible.
- The NFS file system must be compiled into the kernel or loaded as a module. You can check this by looking at the output of the command cat /proc/filesystems in which nfs must appear. Otherwise, you must either load the module nfs.o or reconfigure or recompile the kernel.
- The RPC system must have been started. You can view the services registered with the port mapper by means of the command rpcinfo -p
- Another computer in the network must export data to this computer. Which directories are exported can be determined by means of the command mount -t nfs -e nfs-server.

The command mount -t nfs nfs-server:nfs-volume /mnt can be used to mount the volume exported by the server nfs-server. The type (-t nfs) need not be specified because the mount program recognizes the colon (:) that it is dealing with an NFS volume. The command mount -e nfs-server displays a list of directories exported by this server.

When mounting these directories, several options can be specified which are sensible to keep the network secure or allow work to be continued in case of failure of the NFS server. As with local file systems, these options can also be specified in the file /etc/stab (Listing 17.1). The following list contains only the most important options. A complete description of all options can be found in the man page nfs(5).

| nfs-server:/home /home nfs rw,auto 0 0 |
| nfs-server:/cd0 /mount/cd0 nfs ro,noautouser,user 0 0 |

- The option size specifies the block size for read access. The current default is 1024 bytes; other systems support block sizes of 2048, 4096 and 8192 bytes. In case of performance problems, it may be necessary (and sensible) to change these sizes; often a block size of 8192 bytes is used.
- The option wsize specifies the block size for write access, in analogy to what has been said about the option rsize.
- The option timeo is used to set the time, in tenths of a second, to a timeout. The default value is 7 (7 seconds).
- The option retrans (default 3) specifies the number of retransmissions before a major timeout.
- The hard option repeats the request indefinitely. This is the default.
- The soft option allows interruption of the request by Ctrl-C.
- The intr option signals an I/O error.
- The root_squash option redirects the user ID 0 to the user nobody (uid-2). The default is no_root_squash.
- The ro option exports volumes write-protected.
- The rw option exports volumes writable.
- The map_identity option (default) assumes users ID of server and client are equal.
- The rpc.ugidd (map.daemon) option assigns IDs.
- The insecure option allows mounting from worldwide.
- The restricted option limits access to known networks.

### 17.2 LINUX as NFS server

NFS server provides other computers with disk space that can be used. For the application of LINUX as NFS server, some conditions must be satisfied:

- The network must be configured (ping from server to client).
- The port mapper rpc.portmap must be started.
- The daemons rpc.mountd and rpc.nfsd must be started.
- When PC/NFS is used, the daemon rpc.cnfsd must be started. This daemon is required for authentication and provision of printer services in connections involving DOS and Windows PCs.
- The NFS protocol assumes that the uid and gid numbers are the same on both computers. This can be obtained through identical /etc/passwd or by means of NIS (see Chapter 21). If neither is possible (or sensible), the rpc.uuid can be used.

Which directory trees are available to other computers is specified in the file /etc/exports. There, the access to individual computers or networks can be restricted or read-only access allowed. This is achieved by means of several options. A complete list of the possible options can be found in the man pages for exports(5) and nfs(5). Listing 17.2 contains an example for the file /etc/exports.

```
/nfsclient(ro,root_squash)
/home *.example.org (rw,root_squash)
/project proj*.example.org (rw)
/pub (ro,insecure,root_squash)
```
