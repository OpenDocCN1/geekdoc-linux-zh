This way, we'll be able to sift through each folder and check the validity of paths without having to worry about the relative position of our directories – everything will be absolute. We're still a couple of functions short of a backup solution. You may have noticed in our `createClient` function we make a call to `load_list_of_watched_files_and_folders()`. Its function is just a descriptive way to start reading our JSON file. (**Fig. 07**).

The `now_my_watch_begins` function is slightly more interesting, depending on whether or not we determined a folder or file will be stored in our JSON file. `now_my_watch_begins` will delegate each item to an appropriate function to allow for its checking and upload. After each file and folder has been checked and uploaded/updated appropriately, it will rewrite all of the items processed back to our JSON file, reset any variables that will have been changed in the script's execution and then wait for a set amount of time (five minutes by default, but it can be as frequent as you like) before reloading and re-checking our JSON file and all of the files/folders contained within. (**Fig. 08**).

### 08 Creating folder paths and uploading files

When we added folders to our JSON for uploading, we did so that each one could be independent of any other folder being existent or non-existent. That decision helps us now that we're ready to upload to Dropbox. But before we even think about uploading a file to Dropbox, we need to check whether or not there is already a directory we can upload to. By splitting the path with our folder on our system, we can work through each sub-folder and create the directories as we go along. This gives us an identical folder hierarchy on our Dropbox account to the one on our system — this way, every file we upload will be in the same relative place to every file that was on our system. By calling `client.metadata()` we can check whether a directory already exists. If the directory doesn't already exist, the Dropbox SDK will throw an error. RestResponse that we can catch and then use the `client.file_create_folder(path)` endpoint to create the required directory. Simple. (Fig. 09).

Now we have the folder in place, we can start uploading the files in those directories. (Fig. 10). We're treating files a little differently from folders here. Whereas with the folders we're merely checking that they do in fact exist, since files can be larger and thus more taxing if we continuously upload them willy-nilly; here—if we find that there is already a file with the same name in the same folder— we simply check whether it is any different from the file we have on our system. If it is different, we'll upload it, but if not then we'll skip over it. If we don't find a file with the same name, then we will just upload it; there's no point in checking for something that wasn't already there.

Handling the upload of a single file is a little simpler. We apply the same criteria for checking whether or not the file has changed, but rather than uploading the file to the equivalent folder on Dropbox, we upload it to the Files folder in our apps root folder.
