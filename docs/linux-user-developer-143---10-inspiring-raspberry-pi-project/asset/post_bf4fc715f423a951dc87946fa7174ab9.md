### Spot the difference

Still not sure if you want to upgrade? Here’s a close-up look at the specific differences between the Model B and the Model B+.

![](img/daaca9116bc2b1db669c224de81abc7c_83_0.png)

**Video out** In case you don’t have a TV with HDMI input, the original Model B also came with a classic analogue video out port for standard definition display. This has been removed from the Model B+.

**GPIO pins** An array of GPIO pins make up the GPIO port, used for connecting the Raspberry Pi to a multitude of other physical devices from simple electronic circuits to touch screens and robots.

**MicroUSB power** The B takes its power via a microUSB port. While it technically can be run off a PC’s USB port, it won’t adequately power the device for everything. Use a 1.5 A adapter for the best performance.

**Headphone jack** Analogue audio-out in case you can’t use the HDMI port for digital sound. It fits all headphones or speakers that use the industry standard 3.5 mm jack. It doesn’t include a microphone in function though.

**HDMI port** The main video and audio-out port for the Raspberry Pi, outputting up to 1080p video along with digital audio. Even though the Pi is small, it can easily decode and run high-definition video.

**Dual-USB port** Having two USB 2.0 ports was a luxury compared to the Model A with its singular port. It can’t power much, though, so expanding it required a USB hub with an external power source.

**Ethernet port** Exclusive to the B, the ethernet port gives the option of wired networking, which is useful for updating and maintaining your Pi if drivers don’t work for a Wi-Fi dongle or you run out of USB ports.

## Raspberry Pi Model B+

Is it worth the upgrade?

**REVIEW**

![](img/daaca9116bc2b1db669c224de81abc7c_84_0.png)

**GPIO pins** The B+ has had its ports upgraded to a respectable 40. There’s nothing new that the ports can do – though they all have duplicated functions from other ports – but what it does mean is that you have more choice.

**USB 2.0 ports** Doubling the USB ports up to a total of four gives you so many more possibilities – even if it’s as simple as being able to have mouse, keyboard, wireless and storage all connected at once.

**Ethernet port** Largely remaining the same, the ethernet port is still the only network interface connected by default to the Model B+.

**MicroUSB power** The placement of the power socket has changed, and we believe it makes the Pi tidier. Benchmark tests have shown that the B+ uses significantly less power than the B, but a 1.5 A supply is still recommended.

**3.5mm headphone jack** Moved so it lives next to the HDMI port, the 3.5mm jack is not only sleeker and more streamlined, it’s also received some audio improvements and is able to output a higher quality feed.

**HDMI port** With the 3.5mm jack on the same side of the board as the HDMI port, all the AV connectors are grouped together. The HDMI is no different from the B and still delivers high-def digital video and audio.

### X and mouse

I have a bluetooth mouse, and when I use it, I disable the touchpad on my laptop. If my mouse does not connect for some reason (it's happened before), I have no easy way to turn the touchpad back on.

I can enable the touchpad using a terminal in X with `synclient TouchpadOff=0`, but I can't get to a terminal in X with no mouse! If I switch to another terminal (Ctrl+Alt+F1), synclient fails with the error message "Failed to connect to X Server". I have tried `DISPLAY=":0"` with no effect. How can I get this to work? Is there a way to run a command on a terminal other than the one that I am logged into?

Robin Allan

**Your synclient needs to use environment variables set by X, which you can grab using the following while logged in as a normal user:**

```bash
$ export -p > envars
```

**Log in as root in another terminal and copy the envars file into the home folder. Open it up in nano and remove all the variables but XAUTHORITY and DISPLAY, followed by sourcing the file from root. You could try writing a little script to do it automatically for you that looks something like this:**

```bash
#!/bin/bash
declare -x DISPLAY="[variable]"
declare -x XAUTHORITY="[variable]"

if [ $1 is "on" ]
then
    synclient TouchpadOff=0
fi

if [ $1 is "off" ]
then
    synclient TouchpadOff=1
fi
```

Julian

**What may well be happening is that the module is not loading properly.** This can happen with any kind of driver or module but to fix this specific case use

`$ modprobe ndiswrapper`

...followed up by adding ndiswrapper to the end of /etc/modules file. It will autoload ndiswrapper at boot time and get your wireless working as soon as you log in.
