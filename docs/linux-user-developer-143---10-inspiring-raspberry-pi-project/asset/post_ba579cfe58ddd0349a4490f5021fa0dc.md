
# Design advanced user interfaces for Android

## Create complex GUIs with minimal effort and learn your way around the system

The previous instalment of our Android tutorial concluded with a small RSS reader, which displayed the results of the downloading process in a text view. This is not particularly elegant: using a list and a dedicated form would lead to a much nicer app.

Both Palm OS and Windows Mobile provided developers with an easy-to-use list box. Developers provided the widget with a batch of strings, which were then displayed. Android’s list architecture is more academic, forcing applications to be designed around a relatively complex set of classes which act as a broker between the stored data and the widgets used for its display.

Tablets provide a new source of grief. Their larger screens can not be utilised efficiently by “normal” programs, instead demanding a complete redesign of your interface. Fragments can be used to simplify this process by dividing the user interface into smaller components. These can then be arranged in order to form different layouts that are ideally suited to the screen at hand.


## Processing data

Our display infrastructure is ready. Sadly, the data generated by the HTTPTask currently can not be displayed anywhere – the list framework has no way to figure out what it should do with the vector passed in.

As mentioned before, adapter classes act as a “broker” between the list and its data. The getCount() function is used in order to inform the operating system about the number of items which need to be displayed.

**Left:** We can tailor our app so that it will work differently depending on if it’s in portrait or landscape

```java
public class MyArrayAdapter extends ArrayAdapter<String> {
    public Context myContext;
    public Vector<String> myTitles;
    int myResource;

    public MyArrayAdapter(Context context, int resource, Vector<String> _myTitles) {
        super(context, resource);
        myContext = context;
        myTitles = _myTitles;
        myResource = resource;
    }

    @Override
    public int getCount() {
        return myTitles.size();
    }
}
```

Android uses widgets in order to display the individual rows of the list. GetView is responsible for the generation of said widget, which gets created from the layout presented above (Fig. 04).

With that, our application is ready. The “titles” of the feed in question will be displayed in a visually pleasing list. Sadly, story content is not shown by the current version of our application.

## Going landscape

Programs such as Microsoft Outlook and Mozilla Thunderbird have accustomed users to a Master-Slave view. Clicking the title of an email opens its contents in a different pane. Initially, this paradigm could not be implemented on mobile phones as the screen resolution was too low.

As technology evolved, companies like WeblB tried to implement “split views” in their products. In order to make things a little bit more interesting, our application shall use this advanced paradigm only when running in landscape mode. Clicking a feed in portrait mode shall, instead, open a new window showing the feed in its entirety.

The first step involves the creation of a new layout which will be used only in landscape mode. Right-click the folder /res/layout, and select the option New»Android XML Layout. The file name must be “activity_main.xml” – Eclipse’s warning about the existing file can be ignored.

Proceed by clicking Next in order to open the configuration dialog. Android’s resource system can select the correct resource file via a batch of parameters. In our case, select the qualifier “Layout Direction”, which can then be parametrised to select portrait, landscape or squares. By picking landscape mode, the file will be dumped in the folder layout-land. Change its structure as in **Fig 05**.
