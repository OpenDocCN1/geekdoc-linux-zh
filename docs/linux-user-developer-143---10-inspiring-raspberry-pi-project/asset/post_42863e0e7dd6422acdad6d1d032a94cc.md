
## What is the Raspberry Pi B+?

A new version of the Raspberry Pi is out, but what exactly is it and what does it mean by B+?

There's a new version of the Raspberry Pi out, then? That's absolutely correct – the Raspberry Pi Model B+, the latest version of the Raspberry Pi.

I have some questions about this in relation to the name. This is the first one, model B? Was there a model A? Absolutely, and there still is a model A as well. It's the cheaper version of the Raspberry Pi and it's got a lot less features than what the normal model B has/had.

So what features is the model A missing, then? The model A does not include an ethernet port; it only has one USB port and it has a bit less RAM than the model B does – half as much, in fact, at 256 MB of memory.

If it's the 'inferior' version then why is it still being sold? It was actually released after the original model B and it's a bit cheaper than the model B as well. It's mainly for people that only really need the Pi for its computing capabilities in projects and other maker builds. It will also remain available now the model B+ is out.

I see. Back to the B+ then: so it's the second version of the model B? No, technically it's the third version of the model B. Shortly after its initial release the model B got a minor upgrade to double its RAM to 512 MB, as it initially had the same amount as the model A. In fact, before release, the model A was originally going to be released with 128 MB of RAM but that was changed at the last minute. Either way, the model B version 2 has been around longer than the original model B and probably the one most people have.

So why not release the B+ as the B version 3? Or why not call it the Raspberry Pi model C? Or Raspberry Pi 2?

Fundamentally, the chips and such that power the model B+ are the same that power the B and even the A as well. It's just a new configuration and doesn't really add much major functionality; for example, the A lacks networking but the B has an ethernet port.

**What kind of functionality would allow it to become a model C?**

Well, that's up to the Raspberry Pi Foundation, but perhaps wireless or another kind of major input or output.

**So what exactly is the difference between the last model B and the model B+?**

The model B+ has been re-arranged to have a slimmer profile and to fit within the confines of the circuit board. To do this it has switched to a microSD port on the underside that clicks in and out, while the Video out jack has also been removed. Another dual USB port has been added as well, meaning you won't need to use your powered USB hub as often. There are also a few more GPIO pins lining the side of the Pi.

**That's a fair amount of change. But it's not enough to call it a model C?**

Again that's up to the Raspberry Pi Foundation, but there's been no real added functionality.

**Apart from the extended GPIO pins? Would they count? Also, does that ruin a lot of projects that rely on the GPIO pins to be setup?**

Well, yes, there's a bit more you can do with extended GPIO pins but nothing major. And yes, everything you would have been able to do before still works with the B+ – the extra pins are just added onto the end of the original arrangement. If you've seen the PiFTS screen we've used before, that still works perfectly fine on the board. Also, just to clarify, the pins start at the edge, so the pins have been extended into the board rather than shifting them up the board.

**Well, that all sounds interesting. Should I upgrade to it?**

If all the information here still has you on the fence, you can check out our review later on in the issue. It's also the same price as the original model B and is completely replacing it as well, so if you need to buy any more in the future then they will most certainly be B+.

### Focus on change

**What are the changes that have been made to the Raspberry Pi?**

- **USB**
  The most noticeable one is the inclusion of more USB ports – something the Pi was always in need of. There are now four ports all lining one side of the Raspberry Pi.
- **GPIO port**
  There are now 40 GPIO pins lining the side of the Raspberry Pi, adding 14 onto the original 26 without ruining their original configuration.
- **MicroSD**
  This one is the biggest change as it will involve you getting more hardware (a microSD card), however it really helps reduce the Raspberry Pi's profile.

## Science on a Raspberry Pi

### This month learn how to do some scientific number-crunching on your Raspberry Pi

A few issues ago, we looked at using **MPI with Python on your Raspberry Pi**. This is useful when you are dealing with large problems that you want to spread across multiple machines. But what kind of work can you do on each of these machines? If you want to create a cluster of Raspberry Pis to do scientific work, you will want to look into using *scipy* to handle the actual computation tasks. *Scipy* is built on top of *numpy*, a Python module that provides enhanced number handling capabilities.

*Numpy* uses optimised shared libraries, like LAPACK or BLAS, to handle linear algebra type operations at the same speed as code written in C or FORTRAN. With these modules, we will take a quick look at what kind of science you can do with these powerful little machines.

Almost every Linux distribution, including the standard ones for the Raspberry Pi, include packages for *scipy* and *numpy*. To install *scipy*, you would execute:

```python
sudo apt-get install python-scipy
```

Since *numpy* is part of the *scipy* environment, it will get automatically installed when you install *scipy*. In order to use them you will need to import them, usually with an alias...

```python
import numpy as np
import scipy as sp
```

This import of the main *scipy* module only provides some core functionality that is available. All of the rest of the functions are subdivided into a number of sub-modules, such as *cluster* (providing clustering algorithms), *integrate* (providing integration and ordinary differential equation solvers), *signal* (for signal processing) and *weave* (for C/C++ integration). Each of these sub-modules needs to be imported individually.

In this way, you can just import the sections you need to solve the problem at hand without cluttering up the name-space with unneeded objects.

Before we dive into *scipy*, it is worth taking a look at *numpy* and why it is worth considering Python for scientific computing. The default extended object in Python is a list. The problem with this is that a list could contain any type of object. *Numpy* provides an *array* object that can only contain elements of a single type. With this concession, you can start to take some shortcuts because you have some meta-knowledge about the data.

In regular Python, when you scale a vector you might use a for loop like:

```python
a = [1, 2, 3, 4]
b = []
scale = 2
for curr_a in a:
    b.append(curr_a * scale)
```

In this small example, there is a lot of overhead involved. On each iteration around the for loop, Python needs to check the type of scale and the type of the current element from the list to see what it needs to do to apply the multiplication operation. When you use *numpy* arrays, all of this goes away. The equivalent code would look like:

```python
a = np.array([1, 2, 3, 4])
scale = 2
b = scale * a
```

In this case, Python only needs to check the type of scale and a once, it then hands the two objects out to the shared linear algebra library to handle the actual multiplication step. Then the answer object comes back and is stored in b. So you get some speed-ups, one from removing all of the type checking that Python does and another from using optimised routines in the shared library.

Getting back to *scipy*, we should look at what we can do. A common task in scientific problem solving is integrating a function over some range. The usual *scipy* function to do this is `integrate.quad()`. You can either hand in a predefined Python function, or create a lambda expression on the fly. As an example, say you want to integrate the sine function from 0 to 1. You could do so with:

```python
import scipy.integrate as spi
import math as m
result = spi.quad(lambda x: m.sin(x), 0.0, 1.0)
```

Hopefully, you should get the result **(0.45969769413186023, 5.103669643922839e-15)**. The first value is the integral, and the second value is an estimate of the absolute error in the result.

Another common task is to try and fit a function to some experimental data. The usual method is to do a least-square fitting to minimise the difference between the function and the experimental data. The function 'leastsq' is in the '*scipy.optimize*' sub-module. To do this type of calculation, you need to provide a function to compute the residuals, and a starting point for each of the adjustable parameters in this function. As an example, say you had some measurements that seemed to be in a sinusoidal shape. You could try fitting a general sinusoidal function...

```python
y = A * sin(2*pi*k*x + theta)
```
