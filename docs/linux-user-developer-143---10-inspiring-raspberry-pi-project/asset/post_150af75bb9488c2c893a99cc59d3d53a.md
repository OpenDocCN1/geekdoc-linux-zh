## Piping Netflix

I have been using the Netflix Desktop solution to watch Netflix on my computer for a while now, however as I'm using Firefox as my browser anyway and I've just done a big operating system update on it, I'd rather it just work straight from there. I am having trouble getting Pipelight to work, though. The test pages worked fine, Truetype installed and all, but when I get to Netflix, the video just does not play. I tried:

```
firefox &> pipelight.log
```

...and it came up with an error telling me that my 32-bit OpenGL drivers for my Nvidia card haven't been installed properly. It works fine for everything else but frustratingly just not Pipelight. I'm using an Nvidia 660 GTX Ti on Fedora 20 64-bit, is there anything I can do?

Hans

Nvidia cards are always a bit dodgy when it comes to drivers and this kind of support. What you'll need to do is install 32-bit MESA from the repos and look into recompiling your standard drivers with 32-bit support or looking for restricted drivers and have a go installing them.

It's a bit of a shame that Netflix still blocks Linux from the site. We've heard from developers in the past it's because they're worried that the more tech-savvy Linux users would be able to "steal their bytes". Hopefully they learn to properly trust us soon because these solutions don't seem to be giving them any cause for concern.

## CCTV Conversions

I am trying to convert an H264 video (from CCTV controller) into mov, mp4, or any other more accessible format. However, I am experiencing dropped frames and mplayer while playing back the converted output issues a huge list of errors.

I am using this command for the conversion:

```
$ avconv -i /media/usb8/RecordFile/video_264 -vcodec copy video.mov
```

Anything you can see that's instantly wrong? Am I missing anything?

Ed Rounds

Our first thought is that maybe you need to update all of your software and have a minimal load on the CPU while encoding the file. Otherwise, you might also consider dropping the -vcodec option or even trying out ffmpeg.

It may also be a driver issue with your graphics card if for some reason your PC has decided to use it to help with the encode, so if there are some alternate drivers you can use, then have a go with them.

## Subversion subdirectories

There is one old project in my local svn repository and the other day I added a new project using 'svn import'. While the book recommends adding the subdirectories trunk/, branches/, and tags/ to a project's root directory, I could not find how to do this.

I have two questions. Can I use admin tools to retroactively add the subdirectories to the old project? If so, what is the correct syntax to add them and put existing files in the trunk/ subdirectory?

Also, how do I initially set up the project directory structure while adding a new project to the repository? Hope you can give me a hand with this.

Rich Shepard

Ah, unfortunately you can't really add the subdirectories. What you should have done is create the whole project using the svnadmin tools, creating _path/to/my/repository/_ for the repository itself. Also, create project root directories using 'svn mkdir project-name / path/to/my/repository/'.

Also for each project root directory you should create branches/, tags/, and trunk/ as above. Now the repository and its directory structure are in place, use 'svn import /path/to/my/repository/project' from the source directory. Now just add a log comment with the -m option.

Finally, remove, or back up with a different name, your original source directory. Then use 'svn checkout /path/to/my/repository/project/trunk/' to produce the working copy in your preferred location.

This should get you started again.
