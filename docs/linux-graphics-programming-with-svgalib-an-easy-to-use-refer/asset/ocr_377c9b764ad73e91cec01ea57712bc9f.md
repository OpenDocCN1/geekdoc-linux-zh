# ## Screen Shots

One useful application to be made with graphic files is a screen shot program. This sort of thing is common in the Windows world but relatively unknown with Linux. Perhaps you’ll break new ground?

In this example, I’ll be moving away from libung and using a package called gifsave instead. Gifsave isn’t actually a library, per se, but rather a collection of routines written in C. Like virtually everything else in this book, gifsave can be found in the massive Linux repository at Metalab:

```
metahal.unc.edu/pub/Linux/libs/graphics/gifsave-1.0.2.tar.gz
```

Before we get into that, however, you’ll need to learn one more thing about SVGALib: raw keyboard mode. Raw keyboard mode enables you to use every key on the keyboard, even those that don’t correspond with the ASCII codes. This includes the twelve function keys (F1 to F12), the four directional arrows (Insert, Home, Delete, End, Page Up and Down), and, most importantly, Print Screen. If you’re a Windows user (you’re among friends here—you can admit the truth), you probably know that by pressing the Print Screen key, you copy contents of the screen to the Windows Clipboard. You can then print the saved screen by “pasting” the contents of the Clipboard into an application such as Windows Paint. The screen capture feature isn’t integral to the PC, but rather to Windows, so it generally doesn’t work in other PC operating systems, such as Linux. You can use raw keyboard mode to change that.

The keyboard functions are contained within vgat, but you’ll need to include the `<vgaKeyboard.h>` header file to make them work. To begin, go ahead and enter a graphics mode as usual. Once you’ve done that, the actual function to begin raw keyboard mode is keyboard_init(void). This function returns 0 if successful and -1 otherwise. Therefore, a good error-checking construction might be the following:

```
```
if (keyboard_init())
{
    vga_setmode(TEXT);
    printf("Could not initialize keyboard.\n");
    exit(1);
}
```
```

Finally, when your program is finished, you should return to normal, “cooked” keyboard mode by entering the keyboard_close(void) command. This final step is just as important as vga_setmode(TEXT), because omitting it can potentially mess things up for the next program.
