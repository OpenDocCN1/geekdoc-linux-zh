# Development Objectives

Given the inherent space constraint (one chapter), I feel it’s important to concentrate on the essential features that a small paint program should provide. These most notably include ease of use and functionality. Other features of lesser importance (and perhaps limited interest) can always be added later.

The following list details my priorities. You may feel that some of the items are obvious and/or excessively elementary, but it’s important that all bases be covered. Remember, not everyone has the same level of experience. Here’s the list:

+   ◆ *Intuitive interface*—Despite Bruce Ediger’s assertion that “the only intuitive interface is the nipple,” there are certain things that we have come to expect when using an application. This program must meet or surpass those expectations.
+   ◆ *Functionality*—If a program isn’t useful, why bother having it! A successful paint program will have a variety of drawing tools and the ability to save images in a variety of formats.
+   ◆ *Code clarity*—You don’t get extra points for obfuscation. Remember, other people might need to add to your code, too.
+   ◆ *Overall simplicity*—The user shouldn’t have to expend a lot of effort learning your program. The sooner the user is comfortable and productive, the better.

# Interface

As mentioned earlier, people have come to expect a certain look and feel in “professional” applications. Figure 18.1 shows a standard layout, which is what I’ll be following. (Of course, you’re allowed to deviate from the “norm” if you have solid ideas regarding interface design, but it’s best to stick with what’s tried and true if you don’t.)

Some programs adapt to take advantage of the highest available screen mode, but I’m not going to worry about that here. For simplicity, I’ve decided to keep the screen fixed at a resolution of 640x480. This is large enough to be useful, and it’s also likely to be supported by most modern video cards. Eliminating the variable screen size also frees up some programmer brain cells for other tasks.

Another option (regarding screen modes) is to see whether *vga_getdefaultmode(void)* returns anything. This function corresponds to the *SVGALIB_DEFAULT_MODE* environment variable, and it returns either a screen mode, or −1 (if no mode has been defined). It’s likely that if a mode has been defined, the user would like you to accommodate it. It’s up to you as to whether you’ll honor that request.
