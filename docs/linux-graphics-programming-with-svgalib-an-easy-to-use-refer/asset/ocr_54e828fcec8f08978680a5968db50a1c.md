> **Note**
> *Users of glibc should note that after you unpack the source code, you'll need to install the binary distribution to the compatibility libraries directory, which is (on most glibc2 systems) /usr/1486-linux/lib.*

If you have an older distribution (such as 1.3.1), I’d suggest erasing that directory now. Cautious users may feel the need to keep their old SVGAlib files on hand as an emergency backup, but this is generally unnecessary, because the current version is stable. Keeping these older source files won’t affect your new distribution, but they will take up space.

With regard to your old shared libraries (located in /lib), it’s not necessary to erase these, because the new binaries will overwrite the old ones by default. If you feel the overwhelming urge to keep your old “.so” files, you’ll need to edit Makefile.cfg. Be aware, though, that the rewrite is the last step in the installation process. If your compile bombs, the old shared libraries won’t be touched. Alternatively, you can hide them by renaming them.

# A Word About Slackware

Unlike a lot of people, I personally like Slackware. I feel it’s helped me learn a great deal about Linux—knowledge that I might not have otherwise obtained. Whereas other distributions hold your hand every step of the way, Slackware usage dictates that you get your hands dirty. But, alas, there’s one drawback: Slackware, by default, will scatter your SVGAlib files all over the place. If you want to erase your old distribution, you’ll need to look in /usr/lib/svgalib, /usr/lib/threeDKit, and /usr/doc/svgalib-version number. Why they did this, I’ll never know.

# Building SVGAlib

You have a number of decisions to make when compiling your own version of SVGAlib, and we’ll attempt to help you out with those here. The choices you make will affect your library’s performance, but all is not lost if you make a mistake. Simply reread the pertinent configuration files, recompile if necessary, and you’ll be able to start afresh.
