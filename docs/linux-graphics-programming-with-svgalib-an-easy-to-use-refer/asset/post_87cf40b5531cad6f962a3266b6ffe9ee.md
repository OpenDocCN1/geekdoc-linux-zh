## Gradient Screen

Let’s go ahead and make a more attractive program. This will be one to impress your friends with. Using screen mode 5 (G320×200×16) and your ability to alter palettes, you can make a blue gradient screen, much like the ones found in certain installation programs. Listing 5.4 has all the details.

> **Listing 5.4 The code for creating a blue gradient screen.**

```
#include <std.lib.h>
#include <vga.h>

int main(void)
{
int c,
a,
y = 0;

vga_init();
vga_setmode(G320x200x256);

for (c = 63; c > 0; c--)
{
    vga_setpalette(c, 0, 0, c);
    vga_setcolor(c);
    for (a = 0; a < 3; a++)
    {
        vga_drawline(0, y, 319, y);
        y++;
    }
}
vga_getch();
vga_setmode(TEXT);
return 0;
}
```

The code is rather anticlimactic, isn't it? However, it produces a nice effect, as shown in Figure 5.2. All you're doing is covering the 63 shades of blue (skipping 0), starting with full intensity blue at the top and working down to nothing (blackness) at the bottom. Because screen mode 5 has 200 vertical lines, each shade of blue needs to be drawn three times. The remaining unpa inted lines don't matter, because you're fading to black anyway. ## 256 Shades

We've explored 64-shade RGB colors, but it's made clear by the previous example that sometimes 64 (or 63, really) might not be quite enough. You cheated by drawing each shade three times, but what would you do in a 640×480 mode? Furthermore, most references to RGB color involve a 256-color scale. Wouldn't it be nice if you could have this with SVGA Iib? Well, as a matter of fact, you can.

Returning to vgalib, you get a number of functions designed to be used with the full range of 256 shades. Conceiveably, this gives you 16,777,216 colors (256×256×256) to choose from.

![](img/2e475714ef8969ed272622c46473d334_114_0.png)

**Figure 5.2**
A blue gradient screen.

However, if you're in a screen mode that uses fewer than 16 million colors (mode 5, for example), you'll only be able to use as many colors as your mode allows any particular moment (This would be 256 simultaneous colors, in the case of mode 5). This doesn't mean you can't alternate amongst the 16 million possibilities; you just can't use more than 256 at one time. Also, be advised that vgaGL makes you jump through an extra hoop if you're in a 256-color mode—to use RGB functions, you must first declare gl_setrgbpalette(void). If you forget to do this, you'll just end up with a hodgepodge of ugly colors. Once you move on to 32K color modes, though, gl_setrgbpalette() is no longer necessary.

> **Warning**
>
> When using vgaGL's RGB functions in a 256-color screen mode, you must first declare gl_setrgbpalette().

One more thing: You can't write directly to the screen using vgaGL functions while in a 16-color mode. This shouldn't be a problem for most people; the 16-color palette is practically worthless. But, do keep this in mind. To use 16 colors with vgaGL, you'll need to write to a framebuffer, which can then be copied to the screen, as described in Chapter 4.

### VgaGL Functions

We'll start with gl_setpixelrgb(int x, int y, int r, int g, int b). This one should be pretty obvious. It draws a single RGB pixel at coordinates x and y. The values for r, g, and b refer, of course, to the individual color components (their range extend from 0 to 255). If this function is too intense for you, you can try one that's more akin to what we were doing before—gl_rgcolor(int r, int g, int b) or gl_setpixel(int x, int y, int c). ## Color Consistency Across Platforms

If you need to design applications for multiple platforms, you might consider using special color values to achieve consistency. At the beginning of this chapter, I explained why SVGAlib's colors don't always match those in other operating systems. It's not a defect of SVGAlib, nor is it a problem with the other OS. The problem is simply that *256*-color palettes vary across platforms.

The solution might be to use a specific set of *216* colors (it's *216*, not *256*—Windows and Macintosh both reserve *40* colors for their own use). These *216* colors are composed using a combination of six values: *0, 51, 102, 153, 204*, and *255*. By sticking with these numbers when you declare your RGB values, you should have something that will match a similar application on another OS.

For example, `gl_rgbcolor(102, 153, 51)` should create the same color as the equivalent command in a Windows-based application. Conversely, `gl_rgbcolor(116, 218, 244)` most likely would not.

Just for fun, Listing 5.6 and Figure 5.3 show what these colors are going to look like.

**Listing 5.6 The code to display the *216* platform-independent colors.**

```
#include <stdlib.h>
#include <vga.h>
#include <vgagl.h>

int main(void)
{
    int x,
        y,
        r,
        g,
        b,
        c[216],
        i = 0;

    vga_init();
    vga_setmode(G320x200x256);
    gl_setcontextvga(G320x200x256);

    gl_setrgbpalette();

    for (r = 0; r < 256; r+= 51)
    {
        for (g = 0; g < 256; g += 51)
        {
            for (b = 0; b < 256; b += 51)
            {
                c[i] = gl_rgbcolor(r, g, b);
                i++;
            }
        }
    }

    i = 0;

    for (y = 2; y < 183; y += 12)
    {
        for (x = 2; x < 183; x += 12)
        {
            if (i < 216)
            {
                gl_fillbox(x, y, 10, 10, c[i++]);
            }
        }
    }

    vga_getch();
    vga_setmode(TEXT);

    return 0;
}
```
