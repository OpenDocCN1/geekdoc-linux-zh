## int vga_oktowrite(void)

Indicates whether the program currently running is visible on the screen. That is to say, whether it's okay to write to video memory (assuming background running has been allowed). Note that this is not entirely safe, because a console switch interrupt may occur during a video operation. Therefore, it's best to avoid this function. Usually your program will be suspended when it has no access to the screen, but see vga_runinbackground() for an alternative.

## Manage Color Lookup Tables

These functions manage the color lookup tables:

### void vga_setpalette(int index, int r, int g, int b)

Sets the current color with index `index` to RGB values `r`, `g`, and `b`, each in the range 0 to 63. This function is only sensible in 16- or 256-color modes. It selects which color all `vga_setcolor(index)`-drawn pixels will actually refer to.

Note that setting color 0 will modify the background color and that setting any color in the range 0 to 15 will affect the operation of `vga_setagacolor()`. If the VGA_CLUT8 feature is set for the current mode with `vga_ext_set()`, the red, green, and blue values will be in the 0 to 255 range. The vgaTest demo shows the basic use of this function.

### void vga_getpalette(int index, int *r, int *g, int *b)

Gets the color with index `index` and stores its RGB values at `*r`, `*g`, and `*b`, each in the range 0 to 63. This function is only sensible in 16- or 256-color modes. It returns the color that all `vga_setcolor(index)`-drawn pixels actually refer to. If the VGA_CLUT8 feature has been set for the current mode with `vga_ext_set()`, the red, green, and blue values will be in the range 0 to 255.

### int vga_setpalvec(int start, int num, int *pal)

Sets `num` colors starting with index `start` to the RGB values given in `*pal`. `*pal` contains 3 `num` integers that are the color values to be set. These come in the order red, green, and then blue (it takes three consecutive entries in `*pal` to build a palette entry).

Each color entry is in the range 0 to 63. This function is only sensible in 16- or 256-color modes. It selects which color all `vga_setcolor(start)`-drawn pixels (and `num` - 1 following colors) will actually refer to.

Note that setting color 0 will modify the background color and that setting any color in the range 0 to 15 will affect the operation of `vga_setagacolor()`. If the VGA_CLUT8 feature has been set for the current mode with **vga_ext_set**(), the red, green, and blue values will be in the 0 to 255 range. This function returns the value of **num**.

### int vga_getpalvec(int start, int num, int *pal)

Gets the **num** colors starting with index **start** from the color lookup table and stores the RGB values in `*pal`. `*pal` contains **num** 3-integers, which are the color values from first to last palette entry in the order red, green, blue (three consecutive entries in `*pal` always build a palette entry).

Each color entry is in the range 0 to 63. This function is only sensible in 16- or 256-color modes. It shows which color all **vga_setcolor**(start)-drawn pixels (and **num** - 1 following colors) will actually refer to. If the VGA_CLUT8 feature has been set for the current mode with **vga_ext_set**(), the red, green, and blue values will be in the range 0 to 255. The function returns the value of **num**.

## Mouse Handling

The functions in this section cover mouse handling:

- These functions must include **<vgamouse.h>**.

### void vga_setmousesupport(int stat)

Sets mouse support; 0 disables (default), and 1 enables. If enabled, the mouse is set up for the same screen resolution as the current graphics mode. You can then use the various mouse functions. You can also use **mouse_init**() for more flexibility. However, this isn't the standard procedure for applications—the mouse is configured in **/etc/vga/libvga.config**, and your application will want to use that. The **mousetest**(), **eventtest**(), and **spin**() demos make use of the mouse functions.

### int mouse_init(char *dev, int type, int samplerate)

See **mouse_init_return_fid**().

### int mouse_init_return_fid(char *dev, int type, int samplerate)

**return_fd** version returns the file descriptor of the mouse device to allow you to do further tricks with the mouse (but the *filehandle* may change during a VC switch). The other version just returns 0 if successful. Note that both versions return -1 on error.

```cpp
void mouse_close(void)
```

Closes the mouse device file. This should be called at the end of the program (if a mouse is used), because it tries to restore the original mouse state, if the state has been changed.

```cpp
int mouse_update(void)
```

This reads in mouse events from the mouse buffer and updates the internal SVGAlib variables that store the current mouse position and button states. If there are no events to be read, this routine returns immediately. The function returns 0 if there was no event and a nonzero value otherwise.

```cpp
void mouse_waitforupdate(void)
```

This reads in mouse events from the mouse buffer and updates the internal SVGAlib variables that store the current mouse position and button states. If there are no events, the function does not return until one occurs.

```cpp
void mouse_setscale(int s)
```

This routine sets the scale factor between the motion reported by the mouse and the size of one pixel. The larger the *scale*, the slower the mouse cursor appears to move. The *scale* may be set to any nonzero integer. Negative *scales* result in flipped axes. Currently, there is no support for scale factors between 0 and 1, which would make the mouse appear faster than usual. If this routine is never called, *scale* defaults to 1.

```cpp
void mouse_setwrap(int state)
```

This routine determines what to do if the mouse position reaches a boundary. *state* should be either *MOUSE_WRAP*, *MOUSE_NOWRAP* or a bitwise OR of *MOUSE_WRAPX*, *MOUSE_WRAPY*, *MOUSE_WRAPXZ*. These define if all or the respective coordinates wrap or are clipped at the ends. This variable has been overloaded for the case of multidimensional mice that support rotations and can be used to select the coordinate system used to return the current position of the mouse.

If the value of *state* is also ordered with *MOUSE_ROT_RX*, *RY*, *RZ*, rotational information will be returned as the angular position, as expressed by the total angle wound around the *x*, *y*, and *z* axes. This is the simplest coordinate system to use, but it's also the least useful, because angular rotations about perpendicular axes don't commute. There are situations where this system might be useful for controlling truly independent quantities, such as color, with each axis being used to dial a level of red, green, or blue, but for modeling the actual orientation of a physical object, it's utterly hopeless.

If state is instead ORed with `MOUSE_ROT_INFITESIMAL`, the angles returned are expressed as differences from the previously reported position. If the differences are sufficiently small, the angular displacements will commute with each other and can be used to track the motion of a physical object. Other coordinate systems, such as yaw, pitch, and roll, could be defined but haven't been done due to lack of time. If you feel you need this feature, send email to Eric Sharkey (`sharkey@superk.physics.sunysb.edu`) and he just might consider coding it up. `MOUSE_WRAP` and `MOUSE_ROT_COORDS` can be used to mask out the bits used for wrap and coordinate states, respectively.

```cpp
void mouse_setxrange(int x1, int x2)
```

See mouse_setyrange().

```cpp
void mouse_setyrange(int y1, int y2)
```

These two define the boundaries for mouse cursor. Arguments x1, x2, y1, and y2 are the coordinates of the left, right, bottom, and top edges of the screen, respectively. The return values of mouse_getx() and mouse_gety() will always stay in these boundaries. For 3D pointer devices, there's actually another interface. See mouse_getposition_6d().

```cpp
int mouse_getx(void)
```

See mouse_getbutton().

```cpp
int mouse_gety(void)
```

See mouse_getbutton().

```cpp
int mouse_getbutton(void)
```

These three routines do the obvious, namely returning the current mouse pointer position and button state:

Mouse_getbutton() returns an integer that can be bitwise ANDed with `MOUSE_LEFTBUTTON`, `MOUSE_MIDDLEBUTTON`, `MOUSE_RIGHTBUTTON`, `MOUSE_FOURTHBUTTON`, `MOUSE_FIFTHBUTTON`, `MOUSE_SIXTHBUTTON`, or `MOUSE_RESETBUTTON`.

A 1 on any of these bits means the button has been pressed, whereas 0 means it hasn't. Note that you need to call mouse_update() or mouse_waitforupdate() for the mouse state to actually change. For 3D pointer devices, there's actually another interface. See mouse_getposition_6d().

```cpp
void mouse_setposition(int x, int y)
```

Sets the current mouse position to (x, y).

For 3D pointer devices, there is actually another interface. See mouse_getposition_6d().
