
## Antialiasing

Computers are well known for their "choppy," or jagged, diagonal lines. This is one drawback of the bitmap-style screen matrix; vertical and horizontal lines run evenly along the grid, but diagonal lines must be comprised of several disjointed pixels, especially in low-resolution modes. Antialiasing is the process of smoothing these lines, and it works by shading the outside edges of a line with gray or colored pixels. This shading works to blend the line with the background color, and reduces the "jaggies," or undesirably sharp edges that are known.

## Coding Fonts

To use SVGAlib fonts, we must return to our old friend vga1. The process is really quite simple. First you prepare the font by loading it into memory, and then you render it on the screen, much like you would with a standard shape function. Listing 7.1 will get you started.

**Listing 7.1** *Preparing a font for use.*

```c
#define FONT_HEIGHT 8
#define FONT_WIDTH 8
#define COLOR 15

void *font = malloc(256 * FONT_WIDTH * FONT_HEIGHT * BYTESPERPIXEL);

gl_expandfont(FONT_WIDTH, FONT_HEIGHT, COLOR, gl_font8x8, font);
gl_setfont(FONT_WIDTH, FONT_HEIGHT, font);
```

**Note**

Remember that `WIDTH` and `HEIGHT` are defined internally by `vga.gl`, meaning that you should use other constants (e.g., `FONT_WIDTH`) to define fonts in your code.

This little bit of code introduces three new vga.gl functions:

- `gl_expandfont(int fw, int fh, int c, void *sfp, void *dfp)`
- `gl_font8x8`
- `gl_setfont(int fw, int fh, void *fp)`

Starting from the inside, `gl_font8x8` is a packed-pixel bitmapped font that comes with vga.gl. It's the only font included in the SVGAlib package; you'll have to find others elsewhere or create your own. This font looks quite a bit like Courier, which you might be familiar with. The 8x8 refers to the fact that it's 8 pixels high by 8 pixels across. This is the standard size of SVGAlib fonts, and, because it's a bitmapped font, you can't change these dimensions. A little thought will reveal that a low-resolution screen mode (such as 320x200) will yield a large font, whereas a high-resolution mode will make bitmapped type appear much smaller. This is because the font is always 8 pixels by 8 pixels—such is life. You may be able to compensate for this by having textual screens (such as high score pages or instructions) display in low-res mode, while having the rest of the application in a higher resolution mode. To have a larger font while in screen mode 800x600, for example, you'll need to switch to something larger, such as 16x16. Don't worry; there'll be more on this later.

First, use `gl_expandfont()` to uncompress the font data. With it, you'll need to declare the dimensions of the font, the desired color, the location of the font file itself, and a pointer to a memory location to hold the resultant bitmaps. I've called the pointer `font`, but you can name it whatever you like.

With that done, you'll then need to call `gl_setfont()`, again stating the dimensions and the memory location (pointer). This lets SVGAlib know that you'll be using the font you just expanded, much in the same way you might set a color with `vga_setcolor()`. Now you're actually ready to render type on the screen. Listing 7.2 shows you how to do this.

**Listing 7.2** *Aren't you glad this doesn't say “Hello World”?*

```c
char words[] = "SVGAlib is fun!";

gl_write(100, 100, words);
```

This plots your phrase/word/statement (or whatever) with point 100,100 as the upper left of the first character. The actual command is `gl_write(int x, int y, char *s)`. That's all you have to do. Figure 7.4 shows a close-up of how this might look.

Listing 7.3 has the entire code snippet. When you feel comfortable with that, you might experiment with `gl_writen(int x, int y, int n, char *s)`, which only displays the first n characters of your string.

![](img/2e475714ef8969ed272622c46473d334_150_0.png)

**Listing 7.3** *The complete font code.*

```c
#define FONT_HEIGHT   8
#define FONT_WIDTH    8
#define COLOR         15

char words[] = "SVGAlib is fun!";
void *font = malloc(256 * FONT_WIDTH * FONT_HEIGHT * BYTESPERPIXEL);

gl_expandfont(FONT_WIDTH, FONT_HEIGHT, COLOR, gl_font8x8, font);
gl_setfont(FONT_WIDTH, FONT_HEIGHT, font);
gl_write(100, 100, words);
```

Some caution must be exercised with `gl_write()` and `gl_writen()`, however, as the following construction will not work:

```c
gl_write(FONT_WIDTH, FONT_HEIGHT, "SVGAlib is fun!");
```

The reason is that the above string literal needs to end with `"\0"`, the standard "null character" (ASCII code 0) that tails all char arrays. Without it, you won't see anything on the screen. Let's try it again, this time with the proper string termination:

```c
gl_write(FONT_WIDTH, FONT_HEIGHT, "SVGAlib is fun!\0");
```

## Different Fonts

Presumably you'll want to use fonts other than `gl_font8x8`. This, too, is easy to do once you understand the process. The font itself is located in a rather cryptic-looking char declaration, such as the one shown in Listing 7.4.

**Listing 7.4** *Sample font data.*

```cpp

    227,241,248,124,62,31,143,199,124,128,186,2,238,8,171,32

```

The declaration consists of 2,048 numbers (with most of them omitted here for brevity). These numbers range from 0 to 255. Now, let's go over what they mean. Each character in an 8x8 font (which is standard for SVGAlib) is actually made up of eight horizontal strips of eight pixels each. See Figure 7.5 for a graphical representation of this.

Each strip has some, all, or none of its pixels filled. If you think about it, there are 256 possibilities (0 to 255). Every possible combination of filled and unfilled pixels is covered. So, to draw a capital S, you need these eight codes: 126, 128, 128, 124, 2, 2, 252, and 0. See Figure 7.6 to see what you'd end up with.

If your font consisted of only the letter S, your declaration would look like this:

```cpp
unsigned char s_font[8] =
{
    126, 128, 128, 124, 2, 2, 252, 0
};
```

In reality, fonts consist of 256 characters. Each character needs eight numbers (to represent its eight strips), and 256x8 is 2,048. Therefore, each font declaration needs 2,048 codes. You don't need to worry about all of them to begin with, however. You can use zeros (0) for everything but the letters you're interested in.
