When you're all finished, you may need to close the mouse. Use mouse_close(void) if you initialized the mouse with mouse_init(). If you used vga_setmousesupport(), instead, you won't have to do anything—the mouse closes itself.

Now, what mouse events can occur between initialization and closing? The possibilities include mouse movement, button clicks, and the mouse being forcibly ripped from the computer by an angry user. That last option is hard to check for, but you can use these three functions to cover everything else:

- `int mouse_getx(void);`
- `int mouse_gety(void);`
- `int mouse_getbutton(void);`

The first two functions return the mouse's current position, and mouse_getbutton() obviously checks the state of its buttons. Table 15.2 shows the seven possible return values for mouse_getbutton(), and Listing 15.2 shows exactly how you'd go about using them.

### Listing 15.2 The mechanics of mouse_getbutton().

```c
int button;
button = mouse_getbutton();

if (button & MOUSE_LEFTBUTTON)
{
    /* The left button has been pressed */
}

if (button & MOUSE_RIGHTBUTTON)
{
    /* The right button has been pressed */
}
/* repeat for all applicable button codes */
```

As you can see, the integer returned from mouse_getbutton() can be bitwise "and"ed (&) with MOUSE_LEFTBUTTON, MOUSE_RIGHTBUTTON, and so on to produce a meaningful value. A 1 on any of these bits means the button has been pressed, whereas a 0 means it hasn't.

## Mouse Cursors

Now that you've got a basic grasp on the standard mouse functions, I'm sure you'll want to run off and code some programs. However, you may be in for a surprise when you realize that SVGAlib doesn't provide you with a mouse cursor. That's right—although the position of the mouse is carefully tracked, there's nothing shown on the screen.

This may seem like a major setback, but in actuality it's a blessing. You've been given the freedom to come up with a cursor of your own design. I suppose it might not be too unreasonable to hope for a default cursor, but conversely, you're not saddled with someone else's deficient pixel work, either. Regardless of your outlook, you'll still have to come up with *something*.

Your cursor can be as simple as a set of crosshairs or even a dot. However, I think most people are looking for something more akin to a Microsoft pointer. Therefore, Listing 15.3 shows my code for just that. The methodology I use is fairly straightforward:

1. Take a “snapshot” of the section of the screen where the mouse pointer will be painted. This will be used to restore the screen if and when the pointer moves. Don’t worry—it’s only a few pixels, so it won’t take up too much memory.
2. Draw the pointer/cursor icon in the area where you took the snapshot.
3. When movement occurs, you restore the screen area where the mouse pointer was with your snapshot. Then you find the new coordinate and start over with Step 1.

The variables `x` and `y` refer to the mouse’s current position. As you may have guessed, `ox` and `oy` (old `x` and old `y`) are then used to remember its previous position. To use this code, call `draw_cursor()` initially. Then, you should detect movement and update the mouse’s position with `move_cursor()`. I’m sure there are plenty of other ways to do this, but this method has worked well for me.
