# ## Restoring Text Mode

If the driver fails to restore text mode properly, starting X Windows will often help. It won't restore text mode, but it might allow you to see the output of the program (using either `dev/vcs` or else `/dev/vcsa`).

Next, the `mode3` utility (in `SVGA lib's` `lrm1-0.6m` subdirectory) is a lifesaver. It might very well be able to restore your card to normal text mode, in case your screen becomes corrupted by a bad driver. I can testify that `mode3` has helped me on any number of occasions.

The `mode3` code can also be used for debugging. If a particular screen mode (say, `G800x600x256`) isn't working properly, but `mode3` is, you might try experimenting with the following:

+   1. Run `vgest` (in `SVGA lib's` `demos` directory).
+   2. Select **`mode11`** (for `G800x600x256`). While the wrong mode is displayed, press **d** to receive a register dump.
+   3. Then, run **`mode3 259`** (that is, run `mode3` with a command-line argument of `259`). Follow this with `dumpreg` (in `SVGA lib's` `utils` subdirectory)
+   4. Run `mode3` again (thereby restoring the screen back to text mode) and compare the register dump of `VESA` mode `259` (`G800x600x256`) with the output from your driver.

Your objective is to find incongruous bits and to determine what the differences mean. In other words, simply compare the two files, and when you find a difference, go from there. In this manner, you can slowly work out your bugs.
