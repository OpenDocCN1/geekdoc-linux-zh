
## Driver Report

If you’ve compiled and run any of these programs already, you’ve probably noticed the *driver report*, which is printed after the program finishes. (Actually, the report is printed as soon as you call `vga_init()`, but it isn’t visible until after your program has finished.) If this annoys you, or if your init makes your applications look unprofessional, you can eliminate the message with `vga_disabledriverreport()`. (Isn’t that a mouthful?) Insert this *before* you call `vga_init()`. Otherwise, it won’t have any effect.

## More Fun With Pixels

Now that you know how to compose a basic program using SVGAlib, we can play around with things a bit. Did you think that the single pixel was a little hard to see? Imagine if we were in mode 12 (1,024×768). By placing a few pixels near each other, we can create the illusion of one large pixel. You probably don’t need to see a full example; however, Listing 3.4 does show a snippet.

### **Listing 3.4** Grouping pixels together for visibility.

```c
vga_drawpixel(159, 99);
vga_drawpixel(160, 99);
vga_drawpixel(159, 100);
vga_drawpixel(160, 100);
```

This creates a larger dot in the center of the screen. Let’s go ahead now and draw 10 pixels along a line. Note that we only need to use the one `vga_setcolor()` statement—once we’ve set the color, it remains in effect until we say differently. Listing 3.5 shows one way to scatter 10 yellow pixels along a horizontal line.

### **Listing 3.5 The yellow pixels of Texas.**

```c
vga_setcolor(14);
vga_drawpixel(5, 100);
vga_drawpixel(10, 100);
vga_drawpixel(15, 100);
vga_drawpixel(20, 100);
vga_drawpixel(25, 100);
vga_drawpixel(30, 100);
vga_drawpixel(35, 100);
vga_drawpixel(40, 100);
vga_drawpixel(45, 100);
vga_drawpixel(50, 100);
```

This draws 10 yellow pixels evenly spaced along the x-axis. Pretty simple stuff. To add some pizzazz, you can change the color of each pixel by prefacing each `vga_drawpixel()` statement with `vga_setcolor()`. Also, you can save some time by using a loop. Listing 3.6 shows the efficient way to draw those pixels.

### **Listing 3.6 More yellow pixels.**

```c
vga_setcolor(14);
for (x = 5; x < 55; x += 5)
{
    vga_drawpixel(x, 100);
}
```

By now you're probably sick of pixels. But before you dismiss them entirely, though, Figure 3.1 shows a good example of what you can do with nothing more than two colors (black and white) and a whole bunch of `vga_drawpixel()` statements. Not too shabby, eh?

## Other Commands

A screen in mode 320x200 has 64,000 pixels and would therefore require 64,000 `vga_drawpixel()` statements to be painted completely white. Fortunately, we have some more comprehensive functions to work with; otherwise, our hands would fall off. Of course, you could create a loop, such as the one in Listing 3.7. But that's for pedestrians. Real programmers use `vga_drawline(int x1, int y1, int x2, int y2)`.

### **Listing 3.7 Paint it white.**

```c
#include <stdlib.h>
/* Tedious program to change the screen's color using    */
/* vga_drawpixel()                                       */

#include <vga.h>

int main(void)
{
   int x, y;

   vga_init();
   vga_setmode(G320x200x256);
   vga_setcolor(15);

   for (y = 0; y < 200; y++)
   {
      for (x = 0; x < 320; x++)
      {
         vga_drawpixel(x, y);
      }
   }

   vga_getch();
   vga_setmode(TEXT);
   return 0;
}
```

Now let's try that again, this time using `vga_drawline()`. We'll need to include four arguments, those being the x and y coordinates of the pixel that starts the line and the x and y coordinates of the pixel that ends it. Check it out in Listing 3.8.

### **Listing 3.8 Whitewashing with vga_drawline().**

```c
#include <stdlib.h>
#include <vga.h>

int main(void)
{
   int y;

   vga_init();
   vga_setmode(G320x200x256);
   vga_setcolor(15);

   for (y = 0; y < 200; y++)
   {
      vga_drawline(0, y, 319, y);
   }

   vga_getch();
   vga_setmode(TEXT);
   return 0;
}
```

Now that's better. And, a lot faster, too. As you've just seen (and as you'll see in the upcoming chapters), it's possible to save a lot of time in coding (and in execution) by using one advanced command in place of several basic ones.

You're not limited to just using horizontal lines with `vga_drawline()`. You can draw lines in any direction, starting anywhere. For instance, `vga_drawline(319, 199, 0, 0)` draws a line from the lower-right corner to the upper-left corner (assuming you're in a 320x200 mode, such as mode 5).

Sometimes a line is too thin, as is the case with the individual pixels. You can remedy that by drawing two or more lines in parallel, one pixel removed from each other.

## Simple Shapes

Naturally, you can use lines to draw squares and rectangles. It doesn't take much imagination to deduce that the code in Listing 3.9 creates a square.

### **Listing 3.9 A square.**

```c
vga_drawline(10, 10, 100, 10);
vga_drawline(100, 10, 100, 100);
vga_drawline(100, 100, 10, 100);
vga_drawline(10, 100, 10, 10);
```

![Figure 3.2](img/2e475714ef8969ed272622c46473d334_73_0.png)

**Figure 3.2** A close-up of a square.

We've now got a square ranging from points (10, 10) in the upper left, (100, 10) in the upper right, (100, 100) in the lower right, and (10, 100) in the lower left. See Figure 3.2 for an illustration of this.

The problem is, this square is hollow. Let’s go ahead and draw three filled-in squares, and we’ll color them red, green, and blue. You can see how to do this in Listing 3.10.

### **Listing 3.10 Three squares.**

```c
#include <stdlib.h>
#include <vga.h>

int main(void)
{
    int y;

    vga_init();
    vga_setmode(G320x200x256);

    vga_setcolor(4);
    for (y = 75; y < 120; y++)
    {
        vga_drawline(30, y, 80, y);
    }

    vga_setcolor(2);
    for (y = 75; y < 120; y++)
    {
        vga_drawline(130, y, 180, y);
    }

    vga_setcolor(1);
    for (y = 75; y < 120; y++)
    {
        vga_drawline(230, y, 280, y);
    }

    vga_getch();
    vga_setmode(TEXT);
    return 0;
}
```

Now, you may have noticed that I cheated; these squares aren’t perfectly square. However, if these squares are exactly 50 pixels wide by 50 pixels tall, they appear elongated, due to the distorting layout of screen mode 5. We can compensate for this by knocking five pixels off of the height of the squares (making them rectangles, in reality), and this makes them appear to be plumb. ## Erasing

There’s no way to erase output on the screen. Nor is there any way to **undo** an action. To remove an object, you simply paint over it. If you don’t want anything in its place, set the color to the background color and then paint. As far as *undoing* goes, just take the unwanted part out of the program.

Using the three squares program from Listing 3.10, I’ll demonstrate how you can erase objects. The code for this is shown in Listing 3.11. As the user presses keys, the squares are deleted. When the third square is gone, the program pauses for a second and then exits.

### **Listing 3.11 Bye-bye squares.**

```c
#include <stdlib.h>
#include <vga.h>
#include <unistd.h>

int main(void)
{
   int y;

   vga_init();
   vga_setmode(G320x200x256);

   vga_setcolor(4);
   for (y = 75; y < 120; y++)
   {
       vga_drawline(30, y, 80, y);
   }

   vga_setcolor(2);
   for (y = 75; y < 120; y++)
   {
       vga_drawline(130, y, 180, y);
   }
}
```
