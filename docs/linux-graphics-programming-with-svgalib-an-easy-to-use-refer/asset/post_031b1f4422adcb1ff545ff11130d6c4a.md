
To build a new external function from scratch, the best way to begin is to examine the code from an existing file. The logical choice for dissection would be `vga_drawpixel()`, but it’s a little convoluted. Instead, I suggest tearing apart `vga_drawline()`. Listing 4.11 comes straight from the SVGAlib source (vgaline.c, in the src subdirectory), and it shows that there isn’t all that much to `vga_drawline()`. As a matter of fact, it’s mainly comprised of `vga_drawpixel()` statements. (See, cheating exists at all levels—and you thought it was just the government.)

## **Listing 4.11** An intimate look at `vga_drawline()`’s source file.

```c
/* I’m skipping the credits -- see vgaline.c if you’re
   offended by this, or simply curious */

#include <stdio.h>
#include "vga.h"
#include "libvga.h"

#ifdef BACKGROUND
#include "vgabg.h"
#endif

#define ABS(a) (((a)>0) ? -(a) : (a))

int vga_drawline(int x1, int y1, int x2, int y2)
{
   int dx = x2 - x1;
   int dy = y2 - y1;
   int ax = ABS(dx) << 1;
   int ay = ABS(dy) << 1;
   int sx = (dx >= 0) ? 1 : -1;
   int sy = (dy >= 0) ? 1 : -1;

   int x = x1;
   int y = y1;

   #ifdef BACKGROUND
      __svgalib_dont_switch_vt_vet();
   #endif

      if (ax > ay) {
         int d = ay - (ax >> 1);
         while (x != x2) {
            #ifdef BACKGROUND
               vga_drawpixel(x, y);
            #endif
            #ifdef BACKGROUND
               __svgalib_fast_drawpixel(x, y);
            #endif
         if (d > 0 || (d == 0 && sx == 1)) {
             y += sy;
             d -= ax;
         }
         x += sx;
         d += ay;

      } else {
          int d = ax - (ay >> 1);
          while (y != y2) {
          #ifndef BACKGROUND
              vga_drawpixel(x, y);
          #endif
          #ifndef BACKGROUND
              _svgalib_fast_drawpixel(x, y);
          #endif
              if (d > 0 || (d == 0 && sx == 1)) {
                  x += sx;
                  d -= ay;
              }
              y += sy;
              d += ax;
          }
      }

#ifndef BACKGROUND
    vga_drawpixel(x, y);
#endif
#ifndef BACKGROUND
    _svgalib_fast_drawpixel(x, y);
    _svgalib_is_vt_switching_needed();
#endif

    return 0;
}
```

(The actual source file, vgaline.c, is only 79 lines long, whereas vgapix.c is a whopping 492 lines long. Which would you rather work with? I thought so.) Now, let's use this code as a guide for creating your own functions.

First of all, you probably noticed the preponderance of statements using the BACKGROUND variable—#ifdef BACKGROUND and #ifndef BACKGROUND, for example. This refers to a line in Makefile.cfg (remember that from Chapter 1?) in which you specified BACKGROUND = y (or else you left the line commented out with a hash mark) before compiling SVGAlib. More specifically, this variable serves to let SVGAlib know whether it can run in background mode. Of course, if you're using a kernel that's earlier than 2.0.36 or 2.1.123, it’s a moot point; it won’t work anyhow. For these examples, I’m going to make things simple and assume that background mode is a no-go. After all, other than the BACKGROUND statements, this code is virtually identical to what you’d find in your own programs.

> **Warning**
>
> SVGAlib programs will not run in background mode if your Linux kernel is earlier than 2.0.36 or 2.1.123! Attempting to run a program in background mode with an older kernel may cause your system to crash.

### Sample External Function

Let’s get started by creating a hypothetical function to be stored in an external file. This can then be compiled along with the main program file, compiled into SVGAlib, or made into a separate library. Just for laughs, I’ll call the new function `book_splotchy_circle()`.

This function serves the highly important purpose of displaying an imperfectly filled circle. But, it’s a very fast imperfectly rendered solid circle, and the pattern created where the function leaves off is somewhat appealing. I plan on using this function quite a lot (hypothetically), so I’ve decided to store it externally.

#### Option One: Separate Source Files

The easiest method for me is to keep `book_splotchy_circle()` in a separate source file in the same directory as the rest of the program. I’ve got the function in its own file, called `splotchy_circle.c`, and the code looks identical to functions I’ve created within programs. I also need to have a header file, which I’ll simply call `headers.h`. It could be called anything, however, as long as it ends in “.h”. The header file is used to declare functions contained in or used by multiple source files. Listing 4.11 shows what the `headers.h` might look like.

**Listing 4.11 Headers.h**

```c
void book_splotchy_circle(int xc, int yc, int radius);

void book_another_function(int a, int b, int c);
```

No code goes in this header file—just declarations. Your C compiler knows it’s dealing with a declaration when it sees the semicolon at the end of the function. Now, I just need to put some #include statements into every source (code) file that uses the functions declared in `headers.h`. The statements look like this:

```c
#include <headers.h>
```

Note that `<headers.h>` is not used because the brackets indicate that the header file is in a /usr/include or /usr/local/include directory. Quotes mean that the header file is in a local directory. So, in summary, if my source file **main.c** contains the declaration **#include "headers.h"**, I’m free to use any function declared in that file, including **book_splotchy_circle()**. When I compile this program, I simply include all the source files at once, like this:

```bash
gcc -03 -Wall -o myprogram main.c splotchy_circle.c -lvga
```

This gives me the same end result as if I had compiled and linked the source files separately, like so:

```bash
gcc -03 -Wall -c main.c

gcc -03 -Wall -c splotchy_circle.c

gcc -o myprogram main.o splotchy_circle.o -lvga
```

#### Option Two: External Static Libraries

Now, despite the drawbacks, let’s say I wanted to compile `splotchy_circle.c` into its own shared library. I could group it together with other homebrewed functions in the library, or I could have it stand alone. Either way, here’s what I need to do:

1. Compile the source files into an object file. Here’s an example:
   ```bash
   gcc -03 -Wall -c splotchy_circle.c
   ```
2. Using the resultant file, `splotchy_circle.o`, I can now create my static library:
   ```bash
   ar -r libbook.a splotchy_circle.o
   ```
3. I now create an index for this new library, so that *ld* can find the functions within it. This is accomplished by running **ranlib**:
   ```bash
   ranlib libbook.a
   ```
4. Finally, I run **ldconfig**, which updates *ld*’s cache of libraries. This may not be necessary, but it’s better to be safe than sorry.

When this is all said and done, I will most likely put my new library (`libbook.a`) into the /usr/lib directory, which is the standard repository for static libraries. Then, I can link to it with the *-lbook* command line flag, just like I link to SVGAlib with *-lvga*.

#### Option Three: Compilation In SVGAlib

I don’t necessarily recommend this option; *you* have nothing to gain that can’t be achieved by the first two. Furthermore, you run the risk of building programs that only work on your machine. However, if you want to save yourself the trouble of having to add extra flags to the command line, you can compile your more useful functions directly into SVGAlib. All you'll need to do is move your source file into SVGAlib's `src` subdirectory and then add it to the list of modules in the Makefile (also in the `src` subdirectory—not the main Makefile). The section you need should look like this:

```makefile
MODULES = vga.o \
        vgsadraw.o vgaclear.o vgaline.o vgapis.o \
        vgapal.o vgacon.o vgamodesel.o vgamisc.o \
        vgadump.o vgamonvplanner.o vgacell.o \
        timing.o vgregs.o interface.o accel.o \
        vgabpage.o vgapit.o vgapci.o
```

You can insert your file in behind `vgapci.o`. Then, include all your function declarations in `/usr/include/vga.h` (or create your own file). Just remember to reference any header files that you create.

Finally, compile SVGAlib as usual.

#### Conclusion

SVGAlib and vgagl have a wide assortment of commands for you to use. Nevertheless, you'll find times when no “canned” function is available to fit your needs—meaning you'll have to concoct your own. This may sound like a daunting task at times, but if a dullard like me can do it, surely you can too. There's no reason to let a lack of prewritten functions slow you down.

This chapter has provided you with a number of examples on how to forge your own shape-drawing routines. From circles to arcs to ellipses, there's a huge number of variations to be drawn on these basic themes. Furthermore, just about any book on graphics and/or geometry can help you learn the theory behind shapes, which you can then apply to SVGAlib. Mostly, all you need is confidence and imagination to be able to craft the tools you need.

If you happen to come up with something really good, feel free to submit it to the current maintainer of SVGAlib (**maintainer@svgalib.org**) for possible inclusion in the next distributed version. That's how the library develops and grows, after all. We're all self-appointed, and everyone is welcome to participate. That's the spirit of Linux.
