## Timing

Often overlooked, the concept of timing is vitally important to any game. In addition to evaluating the movement of sprites and other elements of the screen, your program will need to display the same number of frames per second. Otherwise, game speed will be inconsistent on computers with different processor speeds. One option is to utilize `gettimeofday()`, which generally provides sub-second timing. Performance with this function varies across architectures, but fortunately the i386 does exceedingly well.

Another option is to use `usleep()`, which is accurate to the millisecond and is described in Chapter 6.

Russell Marks, author of `zgv` and `zblast`, also suggests using `settimer()` to set a flag at a given interval. Listing 14.3 shows how this might be done.

### Listing 14.3 Using settimer().

```c
volatile int timer_flag=0;

void sighandler(int foo)
{
    timer_flag=1;
}

void start_timer(void)
{
    struct sigaction sa;
    struct itimerval itv;
    int tmp=1000000/20;      /* 20 ints/sec */

    sigemptyset(&sa.sa_mask);
    sa.sa_handler=sighandler;
    sa.sa_flags=SA_RESTART;
    sigaction(SIGALRM,&sa,NULL);

    itv.it_value.tv_sec=itv.it_interval.tv_sec=tmp/1000000;
    itv.it_value.tv_usec=itv.it_interval.tv_usec=tmp%1000000;
    setitimer(ITIMER_REAL,&itv,NULL);
}

void wait_for_timer(void)
{
    sigset_t mask,oldmask;

    sigemptyset(&mask);
    sigaddset(&mask,SIGALRM);

    /* The procmask stuff is to avoid a race condition (not actually
     * a big deal, would just rarely lose an interrupt, but FWHW...).
     */
    sigprocmask(SIG_BLOCK, &mask, &oldmask);
    if (!timer_flag)
        while (!timer_flag)
            sigsuspend(&oldmask);

    sigprocmask(SIG_UNBLOCK, &mask, NULL);
    timer_flag = 0;
}
```

## A Note from Russel Marks

The advantage of not calling `do_a_frame()` directly from `signal handler()` is twofold—there’s very little you can do safely in a signal handler, and the “polling” approach means you degrade gracefully on machines too slow to handle the game (that is, the game runs slow rather than completely screwing up). Also, a polling model is less of a hassle than dealing with interrupts. One final thing: you *could* explicitly stop the timer, but because it’s only setting a flag there’s usually no need, you can just leave it running.

```c
/*
 * 'tsleep' for the current turn time (using select).
 * Eat any input that might be available.

void tsleep()

    char c;

    tv.tv_usec = fallRate;
    while (TV_POS(&tv))
        if (rnwait(&tv) && read(0, &c, 1) != -1)
            break;
}
```
