# Step Three

When your customizations are finally complete, you'll need to go back and change all the sk\_ function prefixes to chipset\_ (where chipset is the name of the chipset in question). This change includes all the sk\_ functions—even those you haven't touched.

Once you have that done, you'll be ready to integrate your driver into SVGA\_lib. To do so, you'll need to edit the following files:

+   - Makefile.cfg
+   
+   - src/Makefile
+   
+   - src/driver.h
+   
+   - src/vga.c
+   
+   - src/vga.h

You can easily see what changes are needed in those files by following the example of SVGA\_lib's existing drivers.

# Step Four

This is where the fun begins, and I know it's the step you've all been eagerly anticipating—debugging. Actually, this is the part where you'll stay up until 4:00 in the morning, cursing under your breath.

Generally speaking, a new driver will never work as intended when you first plug it in. You'll certainly want to iron out the kinks before you go “live” and offer your driver for global distribution (at least, I hope so). With that in mind, Matan Ziv-Av has passed along a few pointers, which I've summarized in the following paragraphs.

The process of setting screen modes can be broken down into two distinct elements: setting the timings and setting the memory organization. Knowing this, you can usually pinpoint a driver problem by watching the screen. If the wrong screen is displayed or if some or even all of the pixels are miscolored, you'll know you have a problem with your memory organization. However, if the display looks “stormy,” you've got a timing problem.

If the problem involves memory organization, you might see whether the card will work in linear mode. To test this, try running the testlinear and linear2 demo programs, both of which can be found in SVGA\_lib's demos subdirectory.

On the other hand, if the problem involves timing, having a digital monitor that displays both horizontal and vertical timings can be of great value. If the horizontal frequency is right but the vertical is wrong, the problem is with the vertical timing. However, if both the horizontal and the vertical frequencies are off, the problem lies with either the clock frequency or the horizontal frequency.
