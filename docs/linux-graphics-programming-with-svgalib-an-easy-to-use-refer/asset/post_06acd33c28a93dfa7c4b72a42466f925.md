If you have an older distribution (such as 1.3.1), I’d suggest erasing that directory now. Cautious users may feel the need to keep their old SVGAlib files on hand as an emergency backup, but this is generally unnecessary, because the current version is stable. Keeping these older source files won’t affect your new distribution, but they will take up space.

With regard to your old shared libraries (located in /lib), it’s not necessary to erase these, because the new binaries will overwrite the old ones by default. If you feel the overwhelming urge to keep your old “.so” files, you’ll need to edit Makefile.cfg. Be aware, though, that the rewrite is the last step in the installation process. If your compile bombs, the old shared libraries won’t be touched. Alternatively, you can hide them by renaming them.

## glibc2 Or libc.so.5?

You probably know that libc is the library that includes all the standard C commands (such as *printf*, *read*, *open*, and so on), as well as system calls. Up until 1997, the only library available was the GNU libc v1, which since the move to ELF binary format was given major number 5 (*`/lib/libc.so.5`*). In 1997, the Free Software Foundation developed GNU libc v2, with the intention of being cleaner, more portable, and more standard (POSIX compliant). Under Linux, this version got major number 6, hence it's called libc6. These two libraries are incompatible—if a program is compiled with one libc's headers and stubs, it can't be used with the other. Some of the distributions (Redhat since version 5, Debian since 2, SuSE since 6, and Slackware since 4) have moved to libc6 (meaning that most binaries are compiled with libc6, and the development environment contains libc6 headers and produces programs that work only with libc6). The distributions still contain libc5, as well as other libraries that are linked with libc5, in order to run libc5 binaries, which will usually be programs where the source is not available (such as Quake). The problem is that if a user of the system wants to use a new version of one of these libraries, she can't compile them, because only libc6 programs or libraries can be produced.

—Contributed by Matan Ziv-Av

## Makefile.cfg

*Makefile.cfg* is a text file that defines the events that will take place during compilation and installation. It's a good idea to look at it, even if you don't anticipate making any changes.

> **Note**
>
> *It's Makefile.cfg that you want to edit, not the actual makefile.*

Unfortunately, some users will have to make at least one modification: If you're using a glibc2-based system (such as RedHat 5.x, Debian 2.x, or SuSE 6.x), you must uncomment `USEGLIBC=yes`.

Let's take a look at Makefile.cfg, shown below, and go over some of the more important points. Basically, the default install puts the shared libraries in */lib*, the static library in */usr/lib*, and the header files in */usr/include*. Text mode utilities are installed in */usr/bin*.

> **Note**
>
> *In case you haven't worked with this type of configuration file before, commented lines begin with a pound sign (#) and are ignored by the compiler. To make these lines active again, simply remove the leading #. Conversely, adding a leading # will make a line invisible to the compiler, if you need to do that.*

```
# -------------------------------
# SVGA-lib Compile-time configuration file
# -------------------------------
# If you change ANYTHING in here you MUST 'make clean' and
# remake what you need.
```

Actually, you only need to run **make clean** if you've already compiled SVGA-lib once using this same source package. (See Step 2 in the preceding list of steps for building SVGA-lib.)

```
# -------------------------------
#Configuration Section#
# -------------------------------#
```

```
# Source directory.
#$srdir = /usr/local/src/svga-lib-$(VERSION)
srdir = $(shell sh -c pwd)
```

If you don't change this part, **srdir** will be the current directory. Pretty simple; no need to change anything here.

```
# Common prefix for installation directories.
# NOTE: This directory must exist when you start the install.
TOPDIR=
**prefix = $(TOPDIR)/usr**
exec_prefix = $(prefix)
```

Because **TOPDIR** is blank, the default prefix is *usr*.

```
libdir = $(exec_prefix)/lib
```

This is the directory where the shared stubs and static library will be installed. If you've left **TOPDIR** blank, your *static* library will be installed to */usr/lib*. This is standard for most static libraries. I suggest you leave this part alone.

```
sharedlibdir = $(TOPDIR)/lib
```

Here's the directory where the shared library will be installed. This is */lib* by default, and again, I suggest you leave it alone. If you *do* decide to change it, you'll potentially have a situation where `ld` *(the dynamic linker)* won't be able to find your shared libraries. You can solve this by making an entry in the `/etc/ld.so.conf` file, which contains a listing of non-standard directories for `ld` to search through. The dynamic linker will always look in */lib* and */usr/lib*, so you won't need to add those.

```
bindir = $(exec_prefix)/bin
```

Here's the directory where the font and text mode utilities will be installed.

```
datadir - $(TOPDIR)/etc/vga
```

Here's the directory where the runtime configuration files will be installed.

```
includedir - $(prefix)/include
```

Here's the directory where the header files will be installed.

```
mandir - $(prefix)/man
```

Here's the directory where the man files will be installed.

```
# TARGET_FORMAT - a.out
TARGET_FORMAT - elf
```

The only other major decision will be regarding the target format. Leave this option untouched unless you know, beyond a shadow of a doubt, that you're running an a.out system. By default, SVGA1ib will be compiled as an ELF (executable and linking format) binary. ELF has been the standard on Linux systems for several years, and chances are pretty good that you can leave this option untouched.

```
# Uncomment the next line if your are compiling with a version of
# (GNU) glibc:

# USEGLIBC - yes
```

For the last time, if you're using RedHat since version 5, Debian since version 2, SuSE since version 6, or Slackware since version 4, you must uncomment this line. Other users (those compiling with libc.so.5) should leave it commented out.

```
ROOT_VC_SHORTCUT - y
```

Leave this line uncommented if you always want root processes to be able to get a new virtual console (VC). Alas, some games misuse *sudo* root privileges and become root; SVGA1ib cannot detect this and will allow any user to open a new VC. If this annoys you, be sure to comment out this line.
