### liblug

Despite its silly-sounding name, liblug makes life much easier for you, the programmer. Developed by Raul Rivero and the Universidad de Oviedo in Oviedo, Spain, liblug is very similar to SVGAlib. It's a static library (ends with “a”), and it must be linked to your code at compilation time.

> *Note*
> *The name itself is an acronym for “Libreria de Utilidades Graficas”, or Graphics Utilities Library. It's certainly not “Linux Users Group”, as it might first appear.*

To find liblug, you need travel no further than the University of North Carolina's Web site:
`metatalab.unc.edu/pub/Linux/libs/graphics/liblug-1.0.6.tar.gz`

Once there, you'll find that you have a choice between getting the pre-compiled binary version, and the much larger source package. Trust me here—you'll want the source (liblug-1.0.6.tar.gz). The binary version may download more quickly, but I experienced a number of errors trying to work with it. The source, however, compiled like a charm.

You’ll also want to download the documentation: `liblug-Manual.tar.gz`. Unfortunately, the manual is contained in a PostScript (PS) file. Not everyone has the ability to read these, I know, so I’ve “distilled” the file into an Acrobat PDF file that you can find on the accompanying CD-ROM.

liblug itself utilizes some external libraries. Most notably, these include `libjpeg.a` and `libtiff.a`. If you want this functionality, you can find these at Metalab as well, in same directory that you found liblug. Look for `libjpeg-6a.tar.gz` and `libtiff-3.0-ELF.tar.gz`.

To compile liblug, I copied the `Makefile.linux` to create a `Makefile`, and then I did some editing. For the compiler options, I added `-O3` and `-Wall`. Then, I specified which image libraries I wanted to include, as I mentioned above. (Just comment out the definitions that you don’t want.) I proceeded to define the viewer as `SVGAlib` (`VIEWDEF = -DLINUX`), and I removed `show/xl.1.o` from the Library Objects section (`OBJS`).

After that, I just ran `make`.

> **Note**
> Although you won’t see the name “`SVGAlib`” anywhere in `liblug`, that’s what “`Linux`” means. If you look at the source, it does indeed use `libvga.a` and `libvgagl`.

The final product is installed in `/usr/local/lib`, unless you specified differently. This shouldn’t be a problem; `ld` should be able to find it there. If you’re concerned, however, double-check to make sure this path exists in your `/etc/ld.so.conf` file.

Once the library’s installed, you can jump right in. If you’ll have a look at some of the GIF functions contained within `liblug`, you’ll see how they’ll make your life:

- `read_gif_file(char *file_name, bitmap_hdr *bitmap)`
- `write_gif_file(char *file_name, bitmap_hdr *bitmap)`

After you’ve read a GIF file with `read_gif_file()`, you can easily print the image to the screen with `gl_putbox(int x, int y, int w, int h, void **dp)`, where `*bitmap` and `*dp` are pointers to the same image. Conversely, `gl_getbox(int x, int y, int w, int h, void **dp)` will help you copy part of the screen into memory, which you can then print to a file with `write_gif_file()`. Eureka! Have a look at Listing 9.1 to see what I mean.

#### Listing 9.1 An introduction to `liblug`.

```c
#include <stdlib.h>
#include <vgalib.h>
#include <vgalvl.h>
#include <lug.h>
#include <lugfonts.h>

int main(void)
{
    byte        *ptr;
    
    bitmap_hdr in;
    
    vga_init();
    vga_setmode(GI1024x768x256);
    gl_setcontextvga(GI1024x768x256);
    gl_setrgbpalette();
    
    read_gif_file("sample.gif", &in);
    gl_putbox(0, 0, in.xsize, in.ysize, in.r);
    
    vga_getch();
    vga_setmode(TEXT);
    
    return 0;
}
```

Now, I suppose some explanations are in order. First, note that I've included `<lug.h>` and `<lugfonts.h>`. (I went ahead and copied all the liblug header files to `/usr/include`). I've also declared `in` to be a `bitmap_hdr` structure, which is defined in `lug.h`. This is a nice structure, as it not only includes the image itself, but it also includes the dimensions. GIF images can only hold 256 colors, so I chose a 256-color mode. Finally, note that I've set `gl_setrgbpalette()`.

Even with `gl_setrgbpalette()`, however, the colors still don't look right. Don't fret; liblug provides an example of how to correct this, as seen below in Listing 9.2.

#### Listing 9.2 Color corrections for liblug.

```c
for (i = 0, ptr = in.cmap; i < in.colors; i++)
{
    r = (double)*ptr++;
    g = (double)*ptr++;
    b = (double)*ptr++;
    gl_setpalettecolor(i, r>>2, g>>2, b>>2);
}
```

Therefore, the entire code would be like I've shown in Listing 9.3. You can get fancy and set the screen mode based upon the dimensions given by `in.xsize` and `in.ysize`, but I'll let you figure that one out on your own.

#### Listing 9.3 Complete program using liblug.

```c
#include <stdio.h>
#include <vga.h>
#include <vgagl.h>
#include <lug.h>
#include <lugfnts.h>

int main(void)
{
  int        i,
             r,
             g,
             b;
  byte       *ptr;

  bitmap_hdr in;

  vga_init();
  vga_setmode(G1024x768x256);
  gl_setcontextvga(G1024x768x256);
  gl_setrgbpalette();

  read_gif_file("sample.gif", &in);

  for (i = 0, ptr = in.cmap; i < in.colors; i++)
  {
    r = (double)*ptr++;
    g = (double)*ptr++;
    b = (double)*ptr++;
    gl_setpalettecolor(i, r>>2, g>>2, b>>2);
  }

  gl_putbox(0, 0, in.xsize, in.ysize, in.r);

  vga_getch();
  vga_setmode(TEXT);

  return 0;
}
```

Now, wasn’t that simple? Certainly, liblug is a great benefit to SVGAlib programmers everywhere. Thanks, Raul!

> Note. Because liblug is a static library, you don’t need to worry if people on other systems will be able to use your compiled code. Any liblug routines you include will be hard-compiled into your executable. Just use `-llug` in exactly the same manner as you’d use `-lvga`.

## Screen Shots

One useful application to be made with graphic files is a screen shot program. This sort of thing is common in the Windows world but relatively unknown with Linux. Perhaps you’ll break new ground?

In this example, I’ll be moving away from liblug and using a package called gifsave instead. Gifsave isn’t actually a library, per se, but rather a collection of routines written in C. Like virtually everything else in this book, gifsave can be found in the massive Linux repository at Metalab:

`metatalab.unc.edu/pub/Linux/libs/graphics/gifsave-1.0.2.tar.gz`

Before we get into that, however, you’ll need to learn one more thing about SVGAlib: raw keyboard mode. Raw keyboard mode enables you to use every key on the keyboard, even those that don’t correspond with the ASCII codes. This includes the twelve function keys (F1 to F12), the four directional arrows (Insert, Home, Delete, End, Page Up and Down), and, most importantly, Print Screen. If you’re a Windows user (you’re among friends here—you can admit the truth), you probably know that by pressing the Print Screen key, you copy contents of the screen to the Windows Clipboard. You can then print the saved screen by “pasting” the contents of the Clipboard into an application such as Windows Paint. The screen capture feature isn’t integral to the PC, but rather to Windows, so it generally doesn’t work in other PC operating systems, such as Linux. You can use raw keyboard mode to change that.

The keyboard functions are contained within `vga`, but you’ll need to include the `<vgaKeyboard.h>` header file to make them work. To begin, go ahead and enter a graphics mode as usual. Once you’ve done that, the actual function to begin raw keyboard mode is `keyboard_init(void)`. This function returns 0 if successful and -1 otherwise. Therefore, a good error-checking construction might be the following:

```c
if (keyboard_init())
{
    vga_setmode(TEXT);
    printf("Could not initialize keyboard.\n");
    exit(1);
}
```

Finally, when your program is finished, you should return to normal, “cooked” keyboard mode by entering the `keyboard_close(void)` command. This final step is just as important as `vga_setmode(TEXT)`, because omitting it can potentially mess things up for the next program.
