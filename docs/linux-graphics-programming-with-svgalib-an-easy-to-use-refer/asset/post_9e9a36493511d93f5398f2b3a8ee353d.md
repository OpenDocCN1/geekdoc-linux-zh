y1,
x2,

for (i = 0; i < n; i++)
{
    x1 = xarray[i];

See how I’ve got the polygon drawing contained within `book_polygon1()` in the second example? All you need to know is the number of vertices and their x and y coordinates, respectively, and `book_polygon1()` takes it from there. Do be certain that your vertex value matches the actual points; otherwise, you may have an odd-looking polygon.

Now let’s proceed by drawing a filled polygon. The filled, nonrectangular polygon is what’ll differentiate these functions from those demonstrated in earlier chapters. Listing 11.3 is based on the same code as shown in the previous listings, but it’s obviously more involved. For starters, I’ve included a basic version of `vga_drawline()` within the code itself. Here’s why: We’ll need to know every point along the outside border of the polygon in order to fill it completely. I could have drawn an outline as before and then used `vga_getcansgment()` to find where the polygon's borders were, but that adds a needless second step. Instead, I'll record each point as it's being drawn. Hence the need for the customized drawing function, which I've called `book_drawline()`.

Once the borders have been drawn and all the outside points defined, it's only a matter of drawing horizontal lines from the top of the polygon to the bottom. Figure 11.4 might help to clarify what I'm doing.

Now you should be ready to examine the code in Listing 11.3. This won't set any speed records, but it's fast enough, and it's a lot easier than similar functions described in other books. Note that I've stepped up to six vertices to make the final product more interesting.

### Listing 11.3 Filled-in polygon.

```c
#include <vga.h>
#include <stdlib.h>

#define VERTICES 6
#define YMAX 200
#define ABS(a) (((a)<0) ? -(a) : (a))

void book_polygon2(int n, int *xpoint, int *ypoint);
int book_drawline(int x1, int y1, int x2, int y2);

void extremes(int x, int y);

static int topy,
         boty,
         leftmost[YMAX],
         rightmost[YMAX];

int main(void)
{
    int xarray[VERTICES] = {50,20,100,200,195,110},
        yarray[VERTICES] = {50,100,150,130,45,30};

    vga_init();
    vga_setmode(6320x200x256);
    vga_setcolor(vga_white());

    book_polygon2(VERTICES, &xarray, &yarray);

    vga_getch();

    vga_setmode(TEXT);
    return 0;
}

void book_polygon2(int n, int *xarray, int *yarray)
{
    int x1,
        y1,
        x2,
        y2,
        i;

    topy = yarray[0];
    boty = yarray[0];

    for (i = 0; i < n; i++)
    {
        x1 = xarray[i];
        y1 = yarray[i];
        if (i != (n - 1))
        {
            x2 = xarray[i + 1];
            y2 = yarray[i + 1];
        } else {
            x2 = xarray[0];
            y2 = yarray[0];
        }
        book_drawline(x1, y1, x2, y2);

        if (yarray[i] < topy)
        {
            topy = yarray[i];
        }
        if (yarray[i] > boty)
        {
            boty = yarray[i];
        }
    }

    for (i = topy; i <= boty; i++)
    {
        book_drawline(leftmost[i], i, rightmost[i], i);
    }

    return; /* function returns void */
}

int book_drawline(int x1, int y1, int x2, int y2)
{
    int dx = x2 - x1;
    int dy = y2 - y1;
    int ax = ABS(dx) << 1;
    int ay = ABS(dy) << 1;
    int sx = (dx >= 0) ? 1 : -1;
    int sy = (dy >= 0) ? 1 : -1;

    int x = x1;
    int y = y1;

    if (ax > ay) {
        int d = ay - (ax >> 1);
        while (x != x2) {
            vga_drawpixel(x, y);
            extremes(x, y);

            if (d > 0 || (d == 0 && sx == 1)) {
                y += sy;
                d -= ax;
            }
            x += sx;
            d += ay;
        }
    } else {
        int d = ax - (ay >> 1);
        while (y != y2) {
            vga_drawpixel(x, y);
            extremes(x, y);

            if (d > 0 || (d == 0 && sy == 1)) {
                x += sx;
                d -= ay;
            }
            y += sy;
            d += ax;
        }
        vga_drawpixel(x, y);
        extremes(x, y);
    }
    return 0;
}

void extremes(int x, int y)
{
    if ((leftmost[y] == 0) && (rightmost[y] == 0))
    {
        leftmost[y] = x;
    }
    else
    {
        if (x < leftmost[y])
        {
            if (rightmost[y] > leftmost[y])
            {
                leftmost[y] = x;
            }
            else
            {
                rightmost[y] = leftmost[y];
                leftmost[y] = x;
            }
        }
        if (x > rightmost[y])
        {
            rightmost[y] = x;
        }
    }
}
```

Let's stop for a moment to examine what has happened differently in this example. As you can see, the code's foundation is the same as it was in the previous two listings. However, as the perimeter lines are drawn, the topmost and bottommost points are recorded in **topy** and **boty**, accordingly. Then, the left and right edges of the polygon are recorded for each *y* line. Once you have that information, it's a simple matter of drawing a series of horizontal lines from left extreme to right extreme, starting at the top and continuing to the bottom, as I did here:

```c
for (i = topy; i <= boty; i++)
{
    book_drawline(leftmost[i], i, rightmost[i], i);
}
```

This procedure fills your polygon from top to bottom, and the results will look something like what's shown in Figure 11.5. Time to call your agent—you're headed for the big leagues. Hello, Pixar?

## Working With threeDKit

Note that I took the easy way out and described the drawing of a *convex* polygon in the previous examples. What happens, then, if one needs a nonconvex or complex polygon? Do we wait for the gl designers to come up with a new function?

The good news is that it's already been done. The threeDKit is used to draw fast, filled triangles. These triangles can be combined to form any sort of polygon.

The bad news (well, it's not that bad) is that the threeDKit isn't as integrated with SVGLib as one might hope. It's kind of like Cousin Olivier from the television show *The Brady Bunch*: It's a hastily added piece that doesn't quite fit. Unlike vgaagl, there's no shared library to go along with threeDKit. This means you'll have to copy the appropriate object and header files from `/usr/src/svglib-1.4.0/threeDKit` to the directory where your source code is, and then you'll have to include those object files in your compilation command. What's more, because most of the threeDKit files depend on one another, you'll end up including most of them. (Another option would be to create your own shared library, but then you'd run into that same old problem of your code not running on other machines).

![](img/2e475714ef8969ed272622c46473d334_255_0.png)

A polygon with six vertices.

### Note
*Although threeDkit functions begin with the gl_* prefix, they are not a part of vgaagl.*

Ignoring these shortcomings, let's jump right in. The first function to explore is `gl_strangle(int x0, int y0, int x1, int y1, int x2, int y2, int color, int bf)`. The s in strangle stands for solid (as this will be a filled triangle). It should be fairly self-explanatory; you pass the x and y values of three screen points to the function, followed by the fill color. Then you get to that weird bf value. This is used in three-dimensional drawing, so you won't need to be concerned with it here. Its purpose is to state when, if ever, the triangle shouldn't be drawn (say, if it were on the back side of a hill, and drawing it would only slow things down because it would be overwritten by the front side of the hill anyway). For now, use a value of -1 for bf, which should ensure that the triangle will always be drawn.

If you're using a screen mode of 640x480, and you use points (100,300), (150,290), and (230,260), your output will resemble what's shown in Figure 11.6.

Note that you can create an octagon with eight calls to `gl_strangle()`; the triangles point inward like eight pieces of a pie. See Listing 11.4 and Figure 11.7 for an example of how one might do this.
