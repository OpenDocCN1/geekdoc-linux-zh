# Table 3.1 SVGAlib's 16 basic colors.

| Color Number | Name | | 0 | Black | | 1 | Blue | | 2 | Green | | 3 | Cyan (grayish blue) | | 4 | Red | | 5 | Magenta (purple) | | 6 | Brown | | 7 | Light gray (silver) | | 8 | Dark gray | | 9 | Light blue | | 10 | Light green | | 11 | Light cyan | | 12 | Light red | | 13 | Light magenta (lavender) | | 14 | Yellow | | 15 | White |

Based on this information, you can see that `vga_setcolor(15)` makes the active color white. Everything we draw will now be done in white, unless we use another `vga_setcolor()` statement. Note that `vga_setcolor()` will only affect the drawing commands that come after it; pixels painted previously will not change. Also note that some drawing commands include an argument for the color and therefore don't need a separate color declaration such as this. We don't need to worry about that now, though.

The fourth command, `vga_drawpixel(int x, int y)`, is what actually puts something on the screen. In this case, it's a single pixel in the upper-left corner. Naturally, `vga_drawpixel(1,0)` is one pixel to the right of that. Pixel (319, 199) is in the extreme lower right, and I'm sure you can figure out the rest.

# Note

> If you try to draw a pixel that doesn't exist, such as (320, 200) while in mode 5, the program wraps the pixel around and places it, in this case, at (0,0). (400,250) would become (80, 50), and so on, and so forth.

We'll now revisit `vga_setmode()` to return to text mode. I've got `vga_setmode(TEXT)` in the example, but you can just as easily use `vga_setmode(0)` instead. It's entirely a matter of aesthetics. Regardless of which you choose, do not forget this part. Your users will hate you if you do.
