For implementors: In conjunction with raster operations (ROP_XOR, ROP_INV), it’s important that endpoints of inner line section are only drawn once. If you cannot achieve that, you must signal that this function cannot be used in conjunction with raster operations. In this case, it’s valid to always draw all points of the line segments, including the endpoints, regardless of the existence of an ACCEL_END parameter.

# vga_accel(ACCEL_POLYLINE, int flag, int y, int n, unsigned short *xcoords)

This function combines the features of ACCEL_POLYLINE and ACCEL_DRAWHINELIST. Starting in row y, horizontal lines are drawn from top to bottom. For each horizontal scanline, the *coords array will contain a number n, followed by n x coordinates in left to right order. Horizontal lines are drawn between the first and the second, the third and the fourth x coordinates, and so on. If the m coordinates are exhausted, if increased, a new number m is read from the *coords array, and operation continues. This procedure is done for n scan lines.

In addition, there’s a flag parameter that works similar to ACCEL_POLYLINE. Your first call to ACCEL_DRAWHINELIST must have the ACCEL_START bit set for proper initialization. The y parameter is ignored when ACCEL_START is not given.

Contrary to ACCEL_POLYLINE, it’s required that the last call have the ACCEL_END bit set. The function is intended for drawing complex filled polygons using horizontal scanlines. By issuing small and fast calls for only a few scanlines, it’s possible to intermix drawing and calculations.

The operation of ACCEL_POLYLINE is undefined if the x coordinates are not sorted from left to right, or if there are zero-length segments in any scan line, or if n or one of the m counters are zero, or one of the m’s is not even.

# vga_accel(ACCEL_POLYFILLMODE, onoff)

Switches polygon fill mode to (on is nonzero) or off. When in polygon fill mode, ACCEL_DRAWLINE and ACCEL_POLYLINE will only draw a single point on each scanline of each line segment. ACCEL_SCREENCOPYM0NO will horizontally scan its source area and start drawing in the foreground color when it encounters a set pixel. When the next pixel is encountered, it will start using the background color, and so on. This function can be used for hardware filled polygons:

+   1.  Enable polygon fill mode.
+   2.  Fill an offscreen rectangular area with a color with all bits zero (usually black).
+   3.  Draw a polygon outline (usually closed) in this offscreen area in the color with all bits set (usually white). To get the proper bits set for the polygon outline, it is recommended to use ROP_XOR so that outlines intersecting in a single point are handled correctly.
