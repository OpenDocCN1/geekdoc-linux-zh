
(But how does an application know?) The Mach32 support for this is smarter. It enables this feature only when it's safe to be used.

To avoid all these problems, you can use the following:

- *nonlinear*—Inhibits use of a linear mmap’d frame buffer.
- *linear*—Allows (not enforces) use of a linear mmap’d frame buffer.

**Note**

Add a line in the /etc/vga/libvga.config file to disable the linear frame buffer if it cannot be used.

This function returns the size of the mapped framebuffer if successful (it can be less than total video memory) and -1 if not. The *testlinear* demo shows the use of this feature (should it work for you).

```
void vga_setmodeX(void)
```

Tries to enable Mode X-like memory organization for the 256-color modes that use up to 256K of memory, such as G320x200x256 and G640x400x256. Modes such as G320x240x256 are Mode X-like by default. *vga_modeinfo*() lists which modes have Mode X memory layouts. A Mode X-like memory layout means that memory is organized in four pages—one vga_setpage()—and that the top-most pixel (0,1,2,3) is the first pixel in pages 0, 1, 2, and 3. Pixels 4, 5, 6, 7 are then the second pixels in pages 0, 1, 2, and 3.

On the other hand, packed pixel screen modes will have pixel 0,1,2,3 as pixel 0,1,2,3 in page 0, and so on. It will only use the next pages if the size of the first 64K page is exceeded. This is the way that most SVGA 256-color modes work. This function isn’t guaranteed to work. A better method would be to define a new mode for planar 320x200x256.

## Extended Features

This enormous section deals with SVGAlib’s extended features:

```
int vga_ext_set(unsigned what, ...)
```

This function comprises several extended features of SVGAlib. Before trying to call vga_ext_set(), you should check whether it’s available in *vga_getmodeinfo()* for compatibility with older versions of SVGAlib. In addition, the availability of certain features will depend on the current graphics mode. However, VGA_EXT_PAGE_OFFSET and VGA_EXT_FONT_SIZE are features of the base module of SVGAlib and are always available if your version of SVGAlib supports them.

Actually, the result of *vga_getmodeinfo()* shows the availability of enhancements of vga_ext_set() in the given SVGA graphics mode. Hence, these base features may be supported even if SVGAlib doesn’t admit it. Since version 1.2.13, you’ve been able to check *vga_getmodeinfo*(TEXT) to see if basic *vga_ext_set()* functionality is available. The VGA_EXT_PAGE_OFFSET and VGA_EXT_FONT_SIZE calls are then available in any mode even if *vga_getmodeinfo()* states that you shouldn’t call *vga_ext_set()* at all.

As of now, the following calls are defined.

Query availability of features includes the following:

- `vga_ext_set`(VGA_EXT_AVAILABLE, VGA_AVAIL_SET)—Returns an `int` with the `i`th bit set if `i` is a valid `what` parameter for `vga_ext_set`().
- `vga_ext_set`(VGA_EXT_AVAILABLE, VGA_AVAIL_ACCEL)—Returns an integer with the `i`th bit set if `i` is a valid parameter for `vga_accel`(). For nicer code, the following integers are predefined to have a bit set in the right position: ACCELFLAG_FILLBOX, ACCELFLAG_SCREENCOPY, ACCELFLAG_PUTIMAGE, ACCELFLAG_DRAWLINE, ACCELFLAG_SETGCOLOR, ACCELFLAG_SETBGCOLOR, ACCELFLAG_SETRANSARENCY, ACCELFLAG_SETRASTEROP, ACCELFLAG_PUTBITMAP, ACCELFLAG_SCREENCOPYBITMAP, ACCELFLAG_DRAWLINEHIST, ACCELFLAG_SETMODE, and ACCELFLAG_SYNC.
- `vga_ext_set`(VGA_EXT_AVAILABLE, VGA_AVAIL_ROP)—Returns an integer as `VGA_AVAIL_ACCEL` does, but this time listing the `vga_accel`() operations that obey a `vga_accel`(ACCEL_SETRASTEROP, ...) setting.
- `vga_ext_set`(VGA_EXT_AVAILABLE, VGA_AVAIL_TRANSPARENCY)—Returns an integer as `VGA_AVAIL_ACCEL` does, but this time listing `vga_accel`(3) operations that obey a `vga_accel`(ACCEL_SETTRANSPARENCY, ...) setting.
- `vga_ext_set`(VGA_EXT_AVAILABLE, VGA_AVAIL_ROPMODES)—Returns an integer with the `i`th bit set if `i` is a valid mode parameter for a `vga_accel`(ACCEL_SETRASTEROP, mode) call. Here’s an example:

```
if (vga_ext_set(VGA_EXT_AVAILABLE, VGA_AVAIL_ROPMODES) &
    (1 << ROP_XOR))
{
    vga_accel(ACCEL_SETRASTEROP, ROP_XOR);
} else {
    /* do something else */
}
```

- `vga_ext_set`(VGA_EXT_AVAILABLE, VGA_AVAIL_TRANSMODES)—Returns an integer with the `i`th bit set if `i` is a valid mode parameter for a `vga_accel`(ACCEL_SETTRANSPARENCY, mode, ...) call. The function lists only the supported enable functions (currently ENABLE_TRANSPARENCY_COLOR and ENABLE_BITMAP_TRANSPARENCY). It’s assumed the corresponding disable functions will then exist as well.
- `vga_ext_set`(VGA_EXT_AVAILABLE, VGA_AVAIL_FLAGS)—Returns an `int` with 1-bit on/off flags. Bits that are set refer to special features that can be enabled in the current mode.

Operations with 1-bit flags include the following:

> **Note**
>
> *A certain mode might have a special feature that can be turned on or off by applications. These functions allow `vga_ext_set()` to handle such features.*
>
> *You can always set flags, and their settings are remembered if they're not supported in the current mode. This is to avoid problems when switching VCs.*

- `vga_ext_set(VGA_EXT_SET, int bitflags)`—Sets all flags that are set in **bitflags**. Don't touch any other flags. Returns previous settings of all flags.
- `vga_ext_set(VGA_EXT_CLEAR, int bitflags)`—Clears all flags that are set in **bitflags**. Don't touch any other flags. Returns previous settings of all flags.
- `vga_ext_set(VGA_EXT_RESET, int bitflags)`—Sets all flags to the corresponding bits of **bitflags**. Returns previous settings of all flags.

The next group uses one-bit flags for special features. As of now, `vga_ext_set()` only supports the following:

- `VGA_CLUT8`—This is set by calling `vga_ext_set(VGA_EXT_SET, VGA_CLUT8)`. This makes the color lookup table for 16- and 256-color lookup table modes work with 8 bits per red, green, and blue parts instead of the ordinary 6 bits. (As of now, this feature is only available for Mac32 cards with type 2 DACs.) This means, however, that all calls to `vga_setpalette()` and `vga_setpalette()` (need to be adjusted accordingly. Also, the interpretation of the return values of `vga_getpalette()` and `vga_getpalette()` changes. The **testaccell()** demos makes use of this to show a smooth 256 blue shades scale.

Miscellaneous features include the following:

- `vga_ext_set(VGA_EXT_PAGE_OFFSET, int offset)`—For all following `vga_set*page(n)` calls (even those explicitly done by SVGAlib drawing functions), use `vga_set*page(n + offset)` instead. This is very nice for drawing in an offscreen area. However, it requires the mode being able to use more than one page at all as well as not having called `vga_setlineaddressing()`. A better approach would be to simply use higher y values for all draw operations to have them end up in offscreen regions that may be displayed later (see `vga_setdisplaystart()`). The previously set value for `VGA_EXT_PAGE_OFFSET` (which defaults to 0 at startup) is returned.

- `vga_ext_set(VGA_EXT_FONT_SIZE, int size)`—Sets the size of the buffer that the application passes to `vga_gettextfont()` and `vga_puttextfont()`. Old versions of SVGAlib used a fixed size of 8,192, which is still the default. Newer versions of SVGAlib use a larger size internally to properly support the extended font capabilities of newer kernels. Calling `vga_ext_set(VGA_EXT_FONT_SIZE, 0)` returns the size of the internal buffers of SVGAlib. It's recommended that you use this (or a larger size) for any font-storing/restoring application. If this differs from the size of the application's buffers, set vga_gettextfont() and vga_puttextfont() to truncate and zero-pad all buffers accordingly. Otherwise, the previously set buffer size is returned.

### int vga_screeneoff(void)

See vga_screeneon().

### int vga_screeneon(void)

These functions turn the generation of the video signal on or off. On some video boards, SVGA memory access is faster when no video signal is generated. On the other hand, not all boards allow you to disable it (at least, not in all modes). These functions should always return 0, but it might be a good idea not to rely on this.

### int vga_guesstiming(int x, int y, int clue, int arg)

Calculates a timing line for an x*y resolution, according to the value of clue. If clue is 0, the aspect ratio for the requested mode (x/y) must be 4:3. A mode with the same aspect ratio as the given mode (while still having a higher resolution) is found and then scaled down to the requested mode. If clue is 1, the next lower resolution with the same aspect ratio will be found.

> **Warning**
>
> No guarantee is given that a *modeline* will be *created* or that the *created modeline* will be *useful*.

## Get Video Mode Information

These functions return data pertaining to the current video mode:

### int vga_getxdim(void)

This function returns the horizontal width (in pixels) of the current screen mode.

### int vga_getydim(void)

This function returns the vertical height (in pixels) of the current screen mode.

### int vga_getcolors(void)

This function returns the current screen resolution's number of displayable colors.

### int vga_white(void)

vga_white() returns the color white in the current screen resolution as it would be set with vga_setcolor() or written directly into the screen.

In high color modes, it's always clear how white is set with vga_setrgbcolor(3). In the other modes, you need vga_white(). However, this function only knows about the default palette. If you change the palette, this function will not know.
