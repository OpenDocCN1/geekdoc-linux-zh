
It's important to know that `bf = 2` defines the back to be drawn when the points are arranged clockwise, `bf = 3` defines the back to be drawn when the points are arranged counterclockwise, and `bf = -1` will probably always draw the front.

```c
void gl_wtriangle(int x0, int y0, int xd0, int yd0, int z0, int x1, int y1, int xd1, int yd1, int z1, int x2, int y2, int xd2, int yd2, int z2, TD_tridata *tri)
```

The following code:

```c
typedef struct {
    unsigned char *bitmap1;
    unsigned char *bitmap2;
    int bf;
} TD_tridata;
```

draws a triangle at points 0, 1, 2 by mapping the pixmaps defined in the `TD_tridata` structure into the triangle.

The x and y values represent the triangle on the bitmap, and the x and y values represent the triangle on the screen. The z values represent an additional value that will be added to the color that's looked up from the pixmap data. Once again, if the current context is more than eight bits, the result is interpreted as an index to the same lookup table. See `gl_triangle()` for more details on shadowing.

`gl_wtriangle` is used to draw wrapped surfaces with shadowing interpolation. The function `gl_swtriangle()` does it without shadowing.

`bitmap1` defines the back side of the triangle, and `bitmap2` the front.

The `bf` value is used to tell the routine to draw the backside if it's facing the other way. Also, `bf` tells which way the triangle should be facing to show the front—you'll more than likely require both combinations.

It's important to know that `bf = 2` defines the back to be drawn when the points are arranged clockwise, `bf = 3` defines the back to be drawn when the points are arranged counterclockwise, and `bf = -1` will probably always draw the front.

```c
void gl_trisetcolorlookup(int i, long color)
```

See `gl_trigetcolorlookup()`.

```c
long gl_trigetcolorlookup(int i)
```

`gl_trisetcolorlookup` sets the color of index `i` in the interpolation table used in greater-than-256-color modes. Note that it's your responsibility to set all the intermediate color values. You can use this function to create the index table, but remember not to let it go over 4,096.

`gl_trigetcolorlookup` retrieves a previously set value from the table.

```c
void gl_trisdrawpoint(void (setpixelfunc) (int x, int y, int color))
```

If this function is called with `setpixelfunc` set to a nonzero value, the function `setpixelfunc` is used thereafter to draw each pixel (instead of the usual direct screen buffer writes). This function need never be used, except if you want to use your own pixel-drawing function for extra effects. If you use this feature, you can be assured that none of the triangle routines will access the hardware, thus enabling portability to other environments.

## ASCII Character Codes

Use the charts displayed in Figures C.1 and C.2 to view all 256 ASCII character codes. To access the characters that aren't available on the keyboard, simply use a construction like the following:

```text
int num;

char c[] = {num, '\0'};
```

Here, `num` is the ASCII value in question. For example, if the value of `num` were 156, character `c` would be the symbol for pounds sterling (£).

An alternate method exists for PC users who have extended (101 or 104-key) keyboards. Simply press and hold down either Alt key and use the numeric keypad on the right side to input the ASCII value in question. For instance, typing Alt+1+5+6 (without the plusses) would yield the same symbol (£) as before. Just don't let up on the Alt key between numbers. This feature isn't specific to Linux, but rather to the extended keyboard, so you're able to use this trick on any other operating system that utilizes PC hardware.

## Chipsets Supported By SVGAlib

The following chipsets, current as of January 1, 2000, are known to work with SVGAlib.

Be aware that many video card manufacturers, including big name brands, routinely use chipsets built by other companies. Therefore, it’s entirely possible that your graphics card is supported, even if you don’t see it listed in this appendix. At the very least, it might be able to use the VESA driver. Conversely, even though two companies might share a chipset, it doesn’t mean that the same driver will work with both cards. The two cards may differ enough that two separate drivers are required.

Finally, as stated previously, the new VESA driver will work with many cards that don’t have a driver of their own.

# Appendix F

## A Brief History Of SVGA

Now that you’ve learned how to use SVGA lib, you might be interested in learning a bit about its background and how it came to be.

The simple story is that SVGA lib was created by Harm Hanevaeger, who lived in the Netherlands at the time, and is likely still there today. His original Linux SVGA library was based on VGALib 1.2, which was written by Tommy Frandsen of Denmark.

> Just for fun, you can find VGALib 1.2 on the companion CD-ROM. Thanks to Russell Marks for that one!

Expanding on VGALib, Hanevaeger added support for multiple drivers, with an emphasis on Cirrus chips (his specialty). He then integrated something called nvga lib (also based on Frandsen’s work), which contained added support for Trident cards. Now, with the scattered fragments of the old VGALib reunited, and a healthy dose of new code added for good measure, Harm’s SuperVGA library was born. SVGA lib version 1 was released in January 1994.
