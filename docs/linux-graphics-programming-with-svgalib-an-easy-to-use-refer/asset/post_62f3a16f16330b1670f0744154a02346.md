## More Fun With Gradients

In Chapter 4, you learned how to draw a filled circle, a function SVGAlib doesn't (yet) provide. In Chapter 5, I showed you how to draw a simple gradient screen. By combining the two, you can create the illusion of a 3D image with purely 2D techniques.

You may feel, as I do, that plainly colored circles are somewhat boring. They're flat, dull, and they just don't excite me. In fact, SVGAlib circles bring to mind an old George Harrison tune: "In their life there's something lacking/What they need's a damn good whacking."

To rectify the situation, you can apply a liberal dose of shading to make your circles more vibrant and appealing. If you do it correctly, the end result looks rather sharp. As such, Listing 6.4 demonstrates one way to make a gradient circle, which is similar in concept to the gradient screen in Chapter 5. Instead of moving from top to bottom, however, the circle's hue gradually brightens as it progresses from the outside to the center. I accomplished this effect with a series of `gl_setpalettecolor()` and `book_fillcircle()` statements.

More specifically, I drew one circle atop another, making each circle in the progression smaller and lighter than its predecessor. This may sound primitive, but the illusion works—it actually looks quite seamless. You could conceivably pass additional arguments to this function to allow any one color to become another, but I've sufficed with white and red. Note that I've also included the `book_fillcircle()` function from Chapter 4.

### Listing 6.4 Red-to-white gradient circle.

```c
void red_gradient_circle(int xc, int yc, int radius)
{
    int a,
        b,
        i,
        j = 0,
        color = 1;

    if (radius < 64)
    {
        a = 64 / radius;

        for (i = 0; i <= 63; i += a)
        {
            gl_setpalettecolor(color, 63, i, i);
            book_fillcircle(xc, yc, (radius - i), color);
            color = (color + 1 < 64) ? color + 1 : color;
        }
    } else if (radius > 64) {
        a = radius / 55;
        b = radius % 55;

        if (((b > 5) && (b < 11)) || (b > 50))
        {
            a++;
        }

        for (i = 0; i < radius; i += a)
        {
            gl_setpalettecolor(color, 63, j, j);
            book_fillcircle(xc, yc, (radius - i), color);
            color = (color + 1 < 64) ? color + 1 : color;
            j = (j + 1 < 64) ? j + 1 : j;
        }
    } else {
        for (i = 0; i <= 63; i++)
        {
            j = (i < 63) ? 1 : 63;
            gl_setpalettecolor(color, 63, j, j);
            book_fillcircle(xc, yc, (radius - i), color);
            color = (color + 1 < 64) ? color + 1 : color;
        }
    }
}

void book_fillcircle(int sx, int sy, int r, int c)
/* from Listing 4.6 */
{
    int x = 0,
        y = r,
        d = 1 - r;

    if (r < 1) {
        gl_setpixel(sx, sy, c);
        return;
    }

    gl_hline(sx - x, sy + y, sx + x, c);
    gl_hline(sx - x, sy - y, sx + x, c);
    gl_hline(sx - y, sy + x, sx + y, c);
    gl_hline(sx - y, sy - x, sx + y, c);
    while (x < y)
    {
        if (d < 0)
        {
            d = x * 2 + 3;
        } else {
            d = x * 2 - y * 2 + 5;
            y--;
        }
        x++;
        gl_hline(sx - x, sy + y, sx + x, c);
        gl_hline(sx - x, sy - y, sx + x, c);
        gl_hline(sx - y, sy + x, sx + y, c);
        gl_hline(sx - y, sy - x, sx + y, c);
    }
}
```

## Antialiasing

Despite the long name, *antialiasing* is quite simple. Briefly, it refers to the process of "smoothing" rough edges on diagonal lines.

![](img/2e475714ef8969ed272622c46473d334_129_0.png)

**Figure 6.1** Pseudo-sphere.

By this point, I'm sure you're painfully aware that although vertical and horizontal lines look good in SVGAlib, diagonal lines leave something to be desired. This is an unfortunate fact of life with the screen matrix system, and it's especially painful in lower-resolution modes. The problem is that there are simply not enough pixels available to represent a diagonal line accurately in most matrices. Therefore, you're left with a rough approximation, complete with jagged edges (or the *jaggies*). This defect, also found in many other systems (that is, it's not intrinsic to Linux or SVGAlib but in fact occurs everywhere you have a screen matrix) is often referred to as *stair-stepping* as well. See Figure 6.2 for an example.

But what's with the name *antialiasing*? A line or shape with rough edges is said to be *aliased*. Therefore, a line or shape that compensates for this flaw has been rendered *antialiased*.

The technique we'll use is to paint some of the jagged object's surrounding pixels to a shade that's in between the object's color and the background color. This provides a sort of make-shift blending effect, and it's quite effective in higher resolutions (that is, in a 640×480 screen mode or higher). Even in low res, it's often better than nothing, although the resultant image may look blurry. Have a look at Figure 6.3 for a better “description”.

For example, suppose you wanted to use color *a* for your line, and the background is color *c*.
