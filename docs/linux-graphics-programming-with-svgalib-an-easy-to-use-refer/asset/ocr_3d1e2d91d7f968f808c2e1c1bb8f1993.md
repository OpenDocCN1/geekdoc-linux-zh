You're already familiar with text mode (whether or not you use that term); Linux gives you 80 characters horizontally and 25 characters vertically. To get beyond ASCII characters, you must enter into a graphics mode.

For a theoretical example, we can create a screen mode called 4×3. What this means is that your screen will be divided into a matrix consisting of three horizontal rows intersecting four vertical columns, thereby creating a total of twelve individual pixels. Refer to Figure 2.3 if you're having trouble visioning this.

However, a matrix of these dimensions is virtually useless. Knowing that pixels can only contain one color, we're limited to chunky blocks that each take up a twelfth of the screen. It would take some imagination to draw anything recognizable in *this* graphics mode, as evidenced by Figure 2.4. (Heck, even the Atari 2600 had better resolution!) Therefore, we need to create a larger grid.

In reality, SVGAlib's smallest matrix is 320 pixels wide by 200 pixels high. Look at Figure 2.5 for an example of mode 320×200.

Clearly this gives us more to work with. We actually have a recognizable house (albeit blocky, as it just uses black and white), and it's clear that one could make several primitive drawings in this manner. Furthermore, logic indicates that as the size of the matrix increases (say, to 1,024×768), the number of available pixels increases, and the problem with blocks and jagged edges goes away. Only one more element is needed to spice up this picture: color.
