You can think of an SVGAlib application as having three stages. Here’s what you need to do:

+   1. Put the display adapter into graphics mode.
+   2. Do your stuff.
+   3. Return the card to text mode.

Not too horrendous of a proposition, now, is it? Let’s have an up-close and personal look at these concepts in action. Listing 3.1 begins your quest.

# Listing 3.1    My first SVGAlib program.

```
#include <stdlib.h>
#include <vga.h>

int main(void)
{
  vga_init();
  vga_setmode(G320x200x16);
  /*  Some prefer vga_setmode(1), which is identical  */
  vga_setcolor(15);  /*  white  */
  vga_drawpixel(0, 0);
  vga_setmode(TEXT);
  /*  This is the same as vga_setmode(0)  */
  return 0;
}
```

Of course, if you compiled the **mode_tester.c** program in Chapter 2, this is actually your second SVGAlib program, but let’s not be *too* anal-retentive here. This program is comprised of only five commands, plus the *return* statement, all of which should be within easy grasp of anyone who has ever worked with C. It starts by initializing the display adapter and then sets the screen to mode 1 (G320x200x16 to be specific, which is a matrix of 320 pixels horizontally, 200 pixels vertically that includes 16 possible colors). It then continues on to select white as the active color, paints a single pixel in the extreme upper-left corner, returns the adapter to text mode (mode 0), and finishes in a flurry with a return code of 0 (no errors). How’s that for excitement? Hope you ate your Wheaties.

# Note

> I’ll take a break for a moment to say that *gcc* now wants you to begin your **main** loop (function) with **int main(void)** (of course, replacing **void** with any input arguments needed by the function). At this time, your programs will still compile using the older methods (for example, **void main(void)**, instead of **int**), but you’ll get *annoying compilation warnings*. My advice would be to avoid this syntax altogether, as *someday gcc will stop accepting it*.
