To accomplish animation across a patterned or otherwise nonsolid background, you could take the following steps:

+   1. Paint the desired background on a virtual screen.
+   2. Copy the background to the physical screen. This means that two identical backgrounds are now in memory, but only one is visible. The “pure” frame buffered background will always stay intact, whereas the visible background will be painted on.
+   3. Paint the relevant object (or sprite) onto the physical screen with `gl_putbox()`, as demonstrated in Listing 10.4.

Naturally, `gl_putbox()` requires that your image be rectangular in shape. It may be that your sprite isn’t, in which case you’ll have to redraw it by hand. Matters would be simplified considerably if it were possible to “paste” an irregularly shaped sprite into a scene. In fact, this is possible—with the help of transparency. See Chapter 14 for a discussion on transparent backgrounds.

+   4. When it comes time to move the object (or sprite), restore the relevant part of the background with `gl_copyboxfromcontext(GraphicsContext *gc, int x1, int y1, int w, int h, int x2, int y2).`

`gl_copyboxfromcontext()` is fantastic in that it allows you to copy only part of a screen. In other words, if you had some activity elsewhere on the screen, `gl_copyboxfromcontext()` would allow you to leave that part undisturbed. Furthermore, it saves you three steps. In other words, it’s not necessary to change your context, invoke `gl_getbox()`, return to your previous context, and then use `gl_putbox()`. Instead, you can accomplish all this in one fell swoop. It’s generally advised that you stay away from `gl_copyboxcontext(int x1, int y1, int w, int h, GraphicsContext *gc, int x2, int y2)`, however, because it’s much less efficient.
