
**void vga_setchipinstfeatures(int chipset, int par1, int par2)**

This forces the chipset and sets optional parameters such as the exact chipset type and the amount of video memory installed. This function is similar to `vga_setchipset()`, and it allows the same values for the chipset. Furthermore, you can pass additional parameters to the setup routine whose meaning depends heavily on the driver. You should only use this function for debugging and if you know what you're doing, which is why further explanation is omitted.

## Hardware Configuration Inquiries

The following functions are concerned with hardware configuration:

### int vga_getmousetype(void)

This returns the mouse type configured in `etc/vga/glibvga.config`. The return value logically added with **MOUSE_TYPE_MASK** is one of the following values (defined in `<vgamouse.h>`):

- **MOUSE_NONE**—There is no mouse installed. It's good style to check whether there's a mouse available first and then enable mouse support to avoid an SVGA/lib error message from trying to initialize a nonexistent mouse.
- **MOUSE_MICROSOFT**—A Microsoft-compatible mouse (2 buttons; default).
- **MOUSE_MOUSESYSTEMS**—A MouseSystems-compatible mouse (3 buttons).
- **MOUSE_MMSERIES**—A MMSeries-compatible mouse.
- **MOUSE_LOGITECH**—An ordinary LogiTech-compatible mouse.
- **MOUSE_BUSMOUSE**—A busmouse.
- **MOUSE_PS2**—A PS/2 busmouse.
- **MOUSE_LOGIMAN**—An ordinary LogiTech LogiMan-compatible mouse.
- **MOUSE_GPM**—The GPM daemon is used.
- **MOUSE_SPACEBALL**—A 3D SpaceTec Spaceball pointer device.
- **MOUSE_INTELLIMOUSE**—A Microsoft IntelliMouse or MouseMan+ on the serial port.
- **MOUSE_IMPS2**—A Microsoft IntelliMouse or Logitech MouseMan+ on the PS/2 port.

The return value may be compared with one or more of the following flags:

- **MOUSE_CHG_DTR**—Changes the setting of DTR to force the mouse to a given mode
- **MOUSE_DTR_HIGH**—Sets DTR to high instead of setting it to low (default)
- **MOUSE_CHG_RTS**—Changes the setting of RTS to force the mouse to a given mode
- **MOUSE_RTS_HIGH**—Sets RTS to high instead of setting it to low (default)

Your application may use this information to perform specifications (for example, to go into a 3D pointer device mode).

### int vga_getcurrentchipset(void)

Returns the current SVGA chipset that was autodetected or forced. See vga_setchipset() for a partial list of predefined values that may be returned.

### int vga_getmonitortype(void)

This returns the monitor type configured in /etc/lga/libvga.config. This function is really obsolete, because the returned data isn’t of much use to the application. vga_getmodeinfo() and vga_hasmode() already check the monitor type, and there are more flexible ways to specify it, too.

The return value is one of the following:

- **MON640_60**—31.5kHz (standard VGA). Does 640x480 in 60Hz vsync.
- **MON800_56**—35.1kHz (old SVGA). Does 800x600 in 56Hz vsync.
- **MON1024_43**—35.5kHz (low-end SVGA, 8514). Does 1,024x768 in 43Hz vsync interlaced.
- **MON800_60**—37.9kHz (SVGA). Does 800x600 in 60Hz vsync.
- **MON1024_60**—48.3kHz (SVGA noninterlaced). Does 1,024x768 in 60Hz vsync, noninterlaced.
- **MON1024_70**—56.0kHz (SVGA high frequency). Does 1,024x768 in 70Hz vsync.
- **MON1024_72**—Does 1,024x768 in 72Hz vsync or even better.

## Setting Video Modes

The following functions pertain to video modes and their settings:

### int vga_setmode(int mode)

vga_setmode() selects the video mode given and clears the screen (if the given mode is a graphics mode). Basically, this should be the first action of your application after calling vga_init() and finding out which mode to use. Prior to exiting your application, you should call vga_setmode(TEXT). Vga_setmode() returns 0 on success and -1 if the desired mode is not available. Argument mode should be one of the predefined values in <vga.h>, or else a value in the range 1 <= mode <= vga_lastmodenumber().

Here are some predefined values for mode:

- **TEXT**—Restores text mode and falls back to ordinary text console handling. All other calls switch to a graphics mode. You should set this mode prior to exiting an SVGA lib application.
- **VGA compatible graphics modes**—In general, for all modes following, the first number is the amount of x pixels, the second is the amount of y pixels, and the third is the number of colors (with shortcuts 32K, 64K, 16M, and 16M4 in lieu of 32,768, 65,536, and 1,677,721). Those with two colors or more than 256 colors use fixed-color mappings (either black and white or some RGB true/high color); the others make use of a color lookup table. Memory layout for the VGA modes is weird—too weird to be explained here. However, you can check the usual VGA literature. *vga_setmode*(X()) has a short explanation that’s valid for all 256 color modes. Here, VGA are the VGA modes: (1) G320x200x16, (2) G640x200x16, (3) G640x350x16, (4) G640x480x16, (5) G320x200x256, (6) G320x240x256, (7) G320x400x256, (8) G360x256, and (9) G640x480x2.
- **Basic SVGA modes**—These use linear 256-color memory layouts similar to G320x200x256. These modes are (10) G640x480x256, (11) G800x600x256, (12) G1,024x768x256, and (13) G1,280x1,024x256.
- **High color SVGA modes**—These also use linear memory layouts, but for 32K and 64K, each pixel occupies two bytes, and three for 16M. For 32K, each 16-bit word is divided into 555-bit portions referring to 5-bit red, green, blue parts. The most significant bit is ignored by the card. For 64K, the division is 565, allowing you to specify green in a little more detail. (Human eyes are more sensitive to green. People joke that this is because our ancestors lived in trees where light was filtered through green leaves.) For the 16M modes, from low to high addresses, the three bytes are named BGR and specify the blue, green, and red parts of the pixel value. These modes are (14) G320x200x32K, (15) G320x200x64K, (16) G320x200x16M, (17) G640x480x32K, (18) G640x480x64K, (19) G640x480x16M, (20) G800x600x32K, (21) G800x600x64K, (22) G800x600x16M, (23) G1,024x768x32K, (24) G1,024x768x64K, (25) G1,024x768x16M, (26) G1,280x1,024x32K, (27) G1,280x1,024x64K, and (28) G1,280x1,024x16M.
- **High resolutions with less color numbers**—Memory layout is probably one nibble per pixel and two pixels per byte in a linear fashion where the most significant nibble is the leftmost pixel. These modes are (29) G800x600x16, (30) G1,024x768x16, and (31) G1,280x1,024x16.
- **Hercules emulation mode**—Again, check out the ordinary VGA literature for the memory layout. This mode is (32) G720x348x2.
- **32-bit per pixel modes**—These are similar to 16M, but each pixel uses four bytes. The first three are similar to 16M but the fourth is left empty and ignored by the VGA card (you can store your own status there). This eases pixel address calculations on the screen and drawing operations. However, one-higher more data has to be moved to the screen. Experiments show, usually, that the higher memory bandwidth used outweighs the effects of the simplified algorithms by far. These modes are (33) G320x200x16M32, (34) G640x480x16M32, (35) G800x600x16M32, (36) G1,024x768x16M32, and (37) G1,280x1,024x16M32.

Many more resolution/screen modes are available in <vga.h>. The **vgatest** demo produces a list of supported modes for your hardware, prints some information on the modes, and allows you to try each of them.

```c
int vga_addmode(int width, int height, int num_cols, int offset, int bytesperpixel)
```

Adds a mode to the list of modes, with the given parameters. The function returns the mode number. If such a mode already exists on the list, its number is returned, and no mode is added.

Adding a mode to the list is not enough to use it. There must also be a timing line that fits that mode. This can be added either as a *modeline* in the config file or with either one of these functions: **vga_adtiming()** or **vga_guesstiming()**.

```c
void vga_setdisplaystart(int a)
```

Sets the display start address to **a**, where the address is the number of pixels offset from the start of video memory (except for hicolor/truecolor modes, which use a unit of one byte). This can be used for page-flipping and virtual desktop scrolling, but it might not work properly for 16-color modes.

You should ensure that the memory displayed is actually available on your SVGA card by querying the memory size with **vga_modeinfo()** and ensuring that it’s saved by SVGAlib during console switches with **vga_claimvideomemory()**. You may only set the bits of the display start address returned by **vga_modeinfo()**.

```c
void vga_setlogicalwidth(int l)
```

Sets the logical scanline width to **l** bytes, which must be in multiples of eight. This function only changes the VGA register; drawing functions don’t take it into account. The logical scanline width is the offset between points above each other in consecutive lines. Note that for some cards and graphics modes, a multiple of eight will not suffice to ensure a proper video timing. Therefore, you should only set **l** to multiples of the value returned by **vga_modeinfo()** for the graphics mode in question.

```c
int vga_setlinearaddressing(void)
```

Switches to linear addressing mode. This maps all (or most) of the SVGA memory to the position returned by **vga_getgraphmem()** (which will probably change by the time you call **vga_setlinearaddressing()**). The **vga_setpage()** calls are no longer required. This ensures optimal performance; however, the drawing functions of SVGAlib do not support this memory layout and neither does every video card. Use **vga_modeinfo()** to check for availability of the function in a given mode.

Some cards (such as Cirrus) just enable this buffer at a fixed hardware address. For Cirrus, it’s mapped at **14MB**, so you should never use it if you have more than **14MB** of memory.
