
> Oddly enough, at the time of this writing, many elements of the Linux kernel, arguably the ultimate in C programming, still use void as the return type, which continues to generate warnings every time it's compiled. Let's get it together, Mr. Torvalds!

Now, let's break this program down and take a look at what happens every step of the way. We start with **vga_init()**.

Despite the brackets, **vga_init()** takes no arguments. Its sole purpose is to initialize the VGA card—that is, it establishes a direct connection with the card and says, in essence, “Hey, buddy! You'll be taking directions from me now and will continue to do my bidding until I exit.” However, that doesn't mean your program has exclusive rights; your other virtual terminals should still work independently, unless you have a bum graphics card. But you do have that direct connection, which is essential for graphics. You also have an important speed advantage over X Windows, which requires an extra step. Finally, **vga_init()** relinquishes root status, which greatly reduces the possibility of security breaches. (I'll have more to say about security problems later.) It's important to make this the first line of your code.

If you noticed that the sample program in Chapter 2, called **mode_tester.c**, didn't use **vga_init()**, good for you. The reason is that **mode_tester.c** outputs text and graphics, thus making **vga_init()** unnecessary.

Note that X windows programs don't establish a direct connection with the graphics adapter because they go through the X server. The X server, however, does need to interact directly with the card. Having the X server as a middleman allows networked graphics but also reduces performance.

Next, we set the screen mode with **vga_setmode(int mode)**. SVGAlib provides 140 screen modes for your enjoyment, all of which can be found in Table 2.4 (located near the end of Chapter 2). You can either enter a mode number (for example, 1), or you can enter the full mode description (G320x200x16). Either works just as well as the other. Do be aware whether your selected mode is available with the graphics card you're using; otherwise, you may have problems. (Again, see Chapter 2 for help.)

> **Note**
> It's necessary to establish a screen mode before you begin drawing so that your video card can allot its memory correctly. If you attempt to draw before you set the mode, your program will crash.

Moving right along, we establish the active color with **vga_setcolor(int color)**. Because the chosen screen mode for this example has 16 colors, you can choose any color from 0 to 15. (Note that **vga_setcolor()** is also compatible with 256 color modes, but nothing higher.) Table 3.1 contains a listing of the 16 basic SVGAlib colors, also known as the EGA colors, which correspond closely to the 16 basic colors in MS-DOS/Windows and other operating systems.

### Table 3.1 SVGAlib's 16 basic colors.

| Color Number | Name |
| :--- | :--- |
| 0 | Black |
| 1 | Blue |
| 2 | Green |
| 3 | Cyan (grayish blue) |
| 4 | Red |
| 5 | Magenta (purple) |
| 6 | Brown |
| 7 | Light gray (silver) |
| 8 | Dark gray |
| 9 | Light blue |
| 10 | Light green |
| 11 | Light cyan |
| 12 | Light red |
| 13 | Light magenta (lavender) |
| 14 | Yellow |
| 15 | White |

Based on this information, you can see that `vga_setcolor(15)` makes the active color white. Everything we draw will now be done in white, unless we use another `vga_setcolor()` statement. Note that `vga_setcolor()` will only affect the drawing commands that come after it; pixels painted previously will not change. Also note that some drawing commands include an argument for the color and therefore don't need a separate color declaration such as this. We don't need to worry about that now, though.

The fourth command, `vga_drawpixel(int x, int y)`, is what actually puts something on the screen. In this case, it's a single pixel in the upper-left corner. Naturally, `vga_drawpixel(1,0)` is one pixel to the right of that. Pixel (319, 199) is in the extreme lower right, and I'm sure you can figure out the rest.

> **Note**
> If you try to draw a pixel that doesn't exist, such as (320, 200) while in mode 5, the program wraps the pixel around and places it, in this case, at (0,0). (400,250) would become (80, 50), and so on, and so forth.

We'll now revisit `vga_setmode()` to return to text mode. I've got `vga_setmode(TEXT)` in the example, but you can just as easily use `vga_setmode(0)` instead. It's entirely a matter of aesthetics. Regardless of which you choose, do not forget this part. Your users will hate you if you do.

**Note**

Resetting the terminal to text mode is always a nice thing to do for your users. It’s a pain when some inconsiderate programmer forgets to do this; you get garbage all over your screen (as well as on every other virtual terminal), and you usually have to reboot to clear it. Of course, you can’t see what you’re typing, so then you take the risk of messing things up. And if you just shut the machine off, you might damage your file system. You can avoid this whole scenario by using `vga_setmode(0)` before you turn out the lights and say goodnight. It’s that easy. If you’re especially paranoid, you can be logged into another terminal with `shutdown -r now` pretyped on the command line. If the console gets hung, just switch to the disaster relief terminal and press Enter.

Finally, we use `return 0,` meaning the program has executed flawlessly. Also, `exit(0)` works fine, too, and can be found in the SVGAlib demo programs. As with the screen modes, it’s six of one, half dozen of the other. You might note that in the interest of portability, some people prefer to use `return EXIT_SUCCESS` instead of `return 0.`

### Compilation

I’m not going to have a compilation section after every installment, but we can go over the process here one more time, just to make sure you’re on the right track. If the preceding code were called `myfirst.c,` you would compile it by typing this:

```
gcc -Wall -O3 -o myfirst myfirst.c -lvg a
```

### Setuid Requirement

There’s one more step to take after compilation, and it’s something you’ll need to remember. As you know, a process must have root status to interact directly with a piece of hardware. While this direct communication is one of SVGAlib’s assets, it also requires that you plan ahead. If your SVGAlib app has graphical output (and most do, obviously), you must change its run-time permissions with `chmod` to allow nonroot users to run it.

To make an application `setuid` root (that is, accessible by ordinary users), you will need to execute one of the following commands. (We’ll assume that the compiled program is still called `myfirst.`)

```
chmod u+s myfirst
```

Or, an equally acceptable solution is to type:

```
chmod 4755 myfirst
```

Remember that the `vga_init()` command relinquishes root status, so there's not much to worry about here.

> **Warning**
> An SVGAlib application must be *setuid* root for ordinary users to have access.

And with that, your first real SVGAlib program is complete. Congratulations! Consider yourself baptized into the world of Linux graphics. See, it wasn't as hard as you thought. Nor should it be.

Feel free to play around with the code. Experimentation is the best way to learn. Using the color table presented in Table 3.1 as a guide, how would you make the pixel red instead of white?

Note that this first program only included `<vga.h>` and `<stdlib.h>`, and *not* any of the other standard header files, such as `<stdio.h>` and `<stdlib.h>`. That's because every function need for this program is contained within `<vga.h>`. If you're in the habit of blindly including `<stdio.h>` or others, it won't hurt anything. It's just unnecessary.

### Viewing Time

If you've run that program, you may have noticed one slight problem. It runs so quickly that you don't have time to see it. By using the `sleep()` function (and including the `<unistd.h>` header file), we can add a delay to make the output viewable. Listing 3.2 shows this code.

**Listing 3.2 My first SVGAlib program, with a pause.**

```c
#include <stdlib.h>
#include <vga.h>
#include <unistd.h>

int main(void)
{
    vga_init();
    vga_setmode(G320x200x16);
    vga_setcolor(15);
    vga_drawpixel(0, 0);
    sleep(3);
    vga_setmode(TEXT);
    return 0;
}
```

The program now waits for three seconds so that you can relish that white pixel in all its glory. Of course, `sleep(15)` would create a 15 second pause, and so on.
