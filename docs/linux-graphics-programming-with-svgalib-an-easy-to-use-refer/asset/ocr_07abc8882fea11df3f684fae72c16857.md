A well-designed user interface, graphical or not, should be considered a vital element of any application. In fact, it’s such an essential and ubiquitous feature that it’s often taken for granted. But, make no mistake here. All it takes is one look at a sloppily designed and implemented screen to see the mastery involved in making the good ones unique. The illusion of a transparent interface takes many hours to achieve.

Sometimes programming a menu or selection screen may seem boring and uneventful. After all, I doubt many people aspire to write GUIs. (At least, they didn’t in the days prior to GNOME and KDE.) Perhaps you view this task as a lot of work, without a lot of credit. Or maybe it’s just plain dull. In any event, it’s certainly not glamorous like other applications.

Nevertheless, it’s critical that you get this part right. After all, an interface isn’t optional. Just as a fish needs water and a tree requires sunlight, your user must have some way to communicate with the computer. The interface is what makes this happen, and the more efficient and “intuitive” your interface is, the more likely it is that your program will be a success.

The basic concept is simple enough: Interfaces accept user input and display processed output. This explanation may seem overly pedestrian, but that’s it in a nutshell. The interface serves as a bridge between user and machine. It may be used to launch other programs, or it can help make interactions with a single application appear seamless. Certainly, an interface can go a long way in making things easier for computer novices, and that’s an important consideration, too.
