Are you looking for some pointers? You’ve come to the right place. This chapter is all about SVGA lib pointing devices (the mouse and joystick) and how to use them effectively.

So far, I’ve only demonstrated working with the keyboard as an input device. This omission hasn’t been a blundering oversight but rather a calculated move designed to keep things simple. I wanted you, the reader, to be able to concentrate on the code at hand, without having to worry about extraneous variables (such as the mouse). This philosophy is why I’ve been using the old “101” (PC extended keyboard) exclusively. Of course, it doesn’t hurt that the keyboard-only philosophy also fits in nicely with the Linux/hacker ethos.

However, there comes a time to accept that the 1980s did happen. The mouse has been an accepted part of our lives since the earliest Macintoshes appeared on the scene, and it isn’t likely to go away anytime soon. Furthermore, joysticks have many applications outside of games, ranging from industrial equipment to aviation (and not just fighter planes, either—the Airbus A-340 uses a “sidestick” as opposed to the traditional yoke [steering wheel]). With that in mind, let’s look at how to use these new-fangled things.

## The Mouse

As new as it may seem (relatively speaking), the mouse has a long history. Although it might be fun to imagine its inventor listening to Devo and having “Weird Science” hair, the first model was actually developed in the early 1960s by someone named Doug Engelbart. Furthermore, it's fairly well known now that Apple (the “Linus of the “80s”) didn't help to develop the mouse (as it appeared at the time). Instead, Apple stole it from Xerox, along with the GUI. I'm not a complete Apple basher, though Apple certainly helped to popularize both mice and GUIs, and Apple/OS Basic will always have a special place in my heart—even if it was written by Microsoft (cough, cough).

## Customizing libvga.config

Moving right along, the mouse is defined in `/etc/vga/libvga.config`. It's possible to pass all mouse parameters to the program at execution time (thus eliminating the need for the mouse section of libvga.config), but you must be aware that most programs don't do this. Therefore, you'll need to work with this onerous file once again.

Fortunately, what you're interested in appears right on top:

```text
# Mouse type:
# mouse Microsoft # Microsoft
# mouse MouseSystems # Mouse Systems
# mouse MMSeries # Logitech NM Series
# mouse Logitech # Logitech protocol
# mouse Bsmouse # Bus mouse
# mouse PS2 # PS/2 mouse
# mouse MouseMan # Logitech MouseMan
# mouse Spaceball # Spacejet SpaceBall
# mouse IntelliMouse # Microsoft IntelliMouse
# or Logitech MouseMan+ on
# serial port.
# mouse IMPS2 # Microsoft IntelliMouse
# or Logitech MouseMan+ on
# PS/2 port.
# mouse none # None
mouse none
```

The mouse section first contains sample definitions (commented out with hash marks) and then the actual configuration. Note that I have mine set as “mouse none”. To install a Microsoft mouse, you would change this to the following:

```text
mouse Microsoft
```

I'm sure you can figure out what to do if, for example, you have a Logitech mouse.

> **Note**
> Did you know that the “proper” term for the hash or pound sign (#) is octothorpe?

If you’re confused by the terms *bus mouse* and PS/2, have no fear. They simply refer to the different connectors that mice sometimes use. Refer to Figure 15.1 for a reference.

The bus mouse is a now-obsolete connector that was briefly in vogue in the 1980s. Although it resembles the PS/2 plug, the pin layout is different. If you have something other than a serial mouse, chances are good that it’s a PS/2.

## Next, The mouse_accel “Defines”

The next group of definitions you’ll encounter in libvga.config occur in the `mouse_accel` section. Not all mice are affected by these definitions in the same manner, so I’d suggest leaving this section alone for the time being. If you encounter problems with a precompiled program as you progress, this is the place to do your tweaking. Chances are, though, you’ll have to use some good of’ trial and error to find the right values.

Case in point: I recently bought a new mouse, and it was *much* too fast. However, I was able to get the speed to a more manageable level by changing `mouse_accel_mult` from 60 to 20 and lowering `mouse_accel_offset` from 30 to 10. (Your mileage may vary.)

## Using /dev/mouse

As you may know, the files in the `/dev` directory refer to your computer’s hardware. For instance, `/dev/hda` refers to an IDE hard drive—specifically, the primary master (the C: drive in DOS/Windows)—and `/dev/ttyS0` refers to your first serial port (COM1 in DOS/Windows).

> **Note**
> Yes, *standard* Linux *tty* devices range from 0 to 3, whereas DOS COM ports range from 1 to 4. Same ports, different scales. How’s that for confusing?

Generally, `/dev/mouse` is a symbolic link to your actual input device for the mouse. For example, my mouse uses `/dev/ttyS0`, so my `/dev/mouse` file points there. It's important to have this link because SVGAlib programs often assume a `/dev/mouse` file is present.

Such linking can be a point of contention, however, because some “gurus” are strongly against the use of symbolic links for devices. Therefore, your Linux distribution may not have provided you with a `/dev/mouse`. To rectify this, use the following simple command:

```text
ln -s /dev/ttyS1 /dev/mouse
```

For example, if your mouse is on `/dev/ttyS1`, you would type this:

```text
ln -s /dev/ttyS1 /dev/mouse
```

If you happen to be one of the people who are dead set against `/dev/mouse`, your other option is to uncomment the following line in libvga.config:

```text
# mdev /dev/ttyS0 # mouse is at /dev/ttyS0
```

If you choose to go this route, make sure you’ve altered the preceding line to reflect your actual serial port. However, I suggest not using this option—you may still find yourself faced with precompiled applications containing `/dev/mouse` hard-coded inside.

> **Note**
> *Old time Linux users may know that cua and ttyS are synonymous. However, the cua device is being phased out, and its use is now discouraged.*

## Mouse Initialization

Coding for the mouse is surprisingly simple. In fact, you may find it similar to raw keyboard mode. You merely have to initialize the mouse and then wait for events, such as movement and/or button clicks. When finished, you simply “close” the mouse. Note that you’ll need to include the vgamouse.h header file for your code, but you won’t need any additional command-line flags for compilation (such as `-lvga` ).

There are two methods for initializing the mouse: the one-step easy method and the longer manual method. This being SVGAlib, it’s recommended that you use the easy method. (Don’t you love it?) Calling `vga_setmouseupp(int stat)` before you set the screen mode will prepare the mouse in one fell swoop. Simply pass an argument of 1 to enable the mouse or 0 (the default) to disable it. Once the mouse is enabled, you’ll be ready to scan for events.

On the other hand, the manual method is demonstrated in Listing 15.1. To use this method, you’ll need the following four commands:

- `mouse_init(char *dev, int type, int samplerate);`
- `mouse_setrange(int x1, int x2);`
- `mouse_setrange(int y1, int y2);`
- `mouse_setwrap(int state);`

### Listing 15.1 Manual initialization of the mouse.

```text
mouse_init("/dev/mouse", MOUSE_MICROSOFT, MOUSE_DEFAULTSAMPLERATE);
mouse_setrange(0, WIDTH - 1);
mouse_setrange(0, HEIGHT - 1);
mouse_setwrap(MOUSE_NOWRAP);
```

The first command, `mouse_init()`, requires three arguments: the device in question (`/dev/mouse` is the default), the type of mouse, and the sample rate (explained in the following paragraph). Next, the "territory" for the mouse is set with `mouse_setxrange()` and `mouse_setyrange()`. This will usually be the entire screen, but that decision is left up to you. Remember that `WIDTH` and `HEIGHT` are defined in `vga.h`, so these constants won't be automatically available if you're using plain-ol' libvga (standard VGA/lib). Finally, `mouse_setwrap` details what happens if the mouse is pushed past the edge of its range.

Of course, you don't have to use the same arguments demonstrated in Listing 15.1. `MOUSE_DEFAULTSAMPLERATE` is defined as 150 (Hz), but you may use any other value. Table 15.1 details all the possible values for `mouse_init()`'s mouse type.

If you don't want to hard-code a mouse type (and you probably shouldn't), `vga_getmousetype(void)` will return the int value that's defined in `libvga.config`.
