
For example, if you had your source code in a file called **source.c** and wanted the compiled program to be called **george**, you'd type the following:

```
gcc -o george source.c
```

Now, to include the functionality of SVGAlib, you'll need to add **-lvgal** to the end of your command line, like so:

```
gcc -o george source.c -lvgal
```

This tells **gcc** that it needs to link your compiled program with **libvgal.so.1** (refer to Chapter 1). If you also need functions in SVGAlib's extended library, **libvgagl.so.1** (this extension to SVGAlib is described in detail later; don't worry if it means nothing to you now), you'll need to add another flag to the command line. But, be careful. When linking to multiple libraries, the most important libraries must come last. Because **libvgal.so.1** is more important than **libvgagl.so.1**, your command line would look like this:

```
gcc -o george source.c -lvgagl -lvgal
```

> **Note**
> When performing a compilation using **vgagl** (libvgagl.so.1), you must reference it before **libvgal.so.1**, like this: **-lvgagl -lvgal**

Worried about errors in your code? Adding the **-Wall** (warnings, all) flag will display every possible problem that **gcc** finds with your code.

Finally, you can optimize the compilation to make the resultant executable faster. You do this by adding the **-O** flag. You can get an even better optimization (as well as a larger program and a longer compile) by using **-O2**. In fact, you can go all the way up to **-O3**.

Here's what we have now, using all of the flags:

```
gcc -Wall -O3 -o george source.c -lvgagl -lvgal
```

Using this, you can compile every example in this book.

## VESA

A lot of people are excited about the VESA driver. VESA, which stands for the *Video Electronics Standards Association*, was founded in 1989 to set interface standards for the PC and other computing environments. It's hoped that all video cards will someday conform to VESA guidelines, and that SVGAlib will then be able to use a single driver for all VESA cards, extending its reach considerably. At this point in time, SVGAlib's VESA driver is known to work on Banshee, TNT, Matrox, Neomagic, i740, and a few other cards. Check the Web site if you're in doubt.

## Prototypical App

The biggest problem people seem to have with graphics is getting started. They simply don't know where to begin; they feel overwhelmed. This is due to a combination of two things: A lack of learning material and the spaghetti-like quagmire of poorly written and badly documented programs they’ve been using as examples. It doesn’t have to be that way. A well-written graphics app can be as simple as a poem or a song, succinct and to the point.

You can think of an SVGAlib application as having three stages. Here’s what you need to do:

1. Put the display adapter into graphics mode.
2. Do your stuff.
3. Return the card to text mode.

Not too horrendous of a proposition, now, is it? Let’s have an up-close and personal look at these concepts in action. Listing 3.1 begins your quest.

### Listing 3.1 My first SVGAlib program.

```c
#include <stdlib.h>
#include <vga.h>

int main(void)
{
  vga_init();
  vga_setmode(G320x200x16);
  /*  Some prefer vga_setmode(1), which is identical  */
  vga_setcolor(15);  /*  white  */
  vga_drawpixel(0, 0);
  vga_setmode(TEXT);
  /*  This is the same as vga_setmode(0)  */
  return 0;
}
```

Of course, if you compiled the **mode_tester.c** program in Chapter 2, this is actually your second SVGAlib program, but let’s not be *too* anal-retentive here. This program is comprised of only five commands, plus the *return* statement, all of which should be within easy grasp of anyone who has ever worked with C. It starts by initializing the display adapter and then sets the screen to mode 1 (G320x200x16 to be specific, which is a matrix of 320 pixels horizontally, 200 pixels vertically that includes 16 possible colors). It then continues on to select white as the active color, paints a single pixel in the extreme upper-left corner, returns the adapter to text mode (mode 0), and finishes in a flurry with a return code of 0 (no errors). How’s that for excitement? Hope you ate your Wheaties.

### Note

> I’ll take a break for a moment to say that *gcc* now wants you to begin your **main** loop (function) with **int main(void)** (of course, replacing **void** with any input arguments needed by the function). At this time, your programs will still compile using the older methods (for example, **void main(void)**, instead of **int**), but you’ll get *annoying compilation warnings*. My advice would be to avoid this syntax altogether, as *someday gcc will stop accepting it*.
