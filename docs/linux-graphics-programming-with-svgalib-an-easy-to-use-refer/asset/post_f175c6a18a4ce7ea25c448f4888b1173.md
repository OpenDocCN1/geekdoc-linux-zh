
## Text Drawing

`void gl_write(int x, int y, char *s)`

See `gl_written()`.

`void gl_written(int x, int y, int n, char *s)`

`gl_write` writes the zero-terminated string `s` to position (x, y) using the currently selected font.

`gl_written` works similarly but writes exactly `n` characters, thus allowing the use of character 0. The type of text-draw operation employed is set with `gl_setwritemode()`.

> **Warning**
>
> - Beware! Prior to the use of `gl_write()` and `gl_written()`, you must set a font.

Here's a good default initialization sequence:

```c
gl_setfont(8, 8, gl_font8x8);
gl_setwritemode(FONT_COMPRESSED + WRITEMODE_OVERWRITE);
gl_setfontcolors(0, vga_white());
```

`int gl_printf(int x, int y, const char *fmt, ...)`

Like `printf()`, `gl_printf()` writes a formatted string to position (x, y) using the currently selected font. If one or both of x and y is negative, the text printing continues at the last position. The special characters `\b`, `\r`, `\n`, `\a`, `\t`, and `\v` have the usual effects. Printing wraps at the screen borders. Nevertheless, behavior is undefined if not a single character fits on the screen or if the initial position is outside the screen. This kind of text-draw operation is set with `gl_setwritemode()`.

> **Warning**
>
> - Beware! Before using `gl_printf()`, you must set a font.

Here's a good default initialization sequence:

```c
gl_setfont(8, 8, gl_font8x8);
gl_setwritemode(FONT_COMPRESSED + WRITEMODE_OVERWRITE);
gl_setfontcolors(0, vga_white());
```

The return value is the number of characters printed.

For compatibility reasons, this function is not contained in **a.out** libraries.

> **Note**
>
> - This function (and its original description) was written by Trek, who can be reached at `trek00@freenet.hut.fi` and/or `trek@mediaservice.net`.

### Fonts

`extern unsigned char *gl_font8x8`

`gl_font8x8` contains a packed pixel font with 8x8 pixels per character. Before using it, you might want to expand it with `gl_expandfont()`. Although it's slower, you can use nonexpanded fonts when the `gl_setwritemode()` flag `FONT_COMPRESSED` is set.

## Pixmap And Bitmap Drawing

The following functions are used for copying and pasting sections of the screen.

`void gl_getbox(int x, int y, int w, int h, void *dp)`

Copies a rectangular bitmap at position (x, y) with size (w, h) from the screen to the buffer dp. Pixmaps are in row-major order. The destination pixmap has the size w * h * BYTESPERPIXEL.

`void gl_copybox(int x1, int y1, int w, int h, int x2, int y2)`

Copies the rectangular area at (x1, y1) of size (w, h) to (x2, y2).

`void gl_copyboxfromcontext(GraphicsContext *gc, int x1, int y1, int w, int h, int x2, int y2)`

Copies the rectangular area at (x1, y1) in the context gc of size (w, h) to position (x2, y2) in the current context. This is more efficient than copyboxtocontext().

`void gl_copyboxtocontext(int x1, int y1, int w, int h, GraphicsContext *gc, int x2, int y2)`

Copies the rectangular area at (x1, y1) of size (w, h) to position (x2, y2) in the context gc. If possible, use copyboxfromcontext() instead.

`void gl_putbox(int x, int y, int w, int h, void *dp)`

Copies the contents of memory buffer dp to a rectangular bitmap at position (x, y) with size (w, h). Pixmaps are in row-major order. The source pixmap memory is sized w * h * BYTESPERPIXEL.

`void gl_putboxpart(int x, int y, int w, int h, int bw, int bh, void *dp, int xo, int yo)`

Copies the contents of memory buffer dp to a rectangular bitmap at position (x, y) with size (w, h). However, only part of the bitmap is copied. The copied size is (bw, bh), starting at offset (xo, yo). Pixmaps are in row-major order. The source pixmap memory is sized w * h * BYTESPERPIXEL.

`void gl_putboxmask(int x, int y, int w, int h, void *dp)`

Copies the contents of memory buffer dp to a rectangular bitmap at position (x, y) with size (w, h). This function works like gl_putbox but does not write pixmap pixels of color zero. If the same pixmap is used often, you should consider using the faster `gl_putboxmaskcompiled()`.

Pixmaps are in row-major order. The source pixmap memory is sized `w * h * BYTESPERPIXEL`.

`void gl_putboxmaskcompiled(int x, int y, int w, int h, void *dp)`

Copies the contents of memory buffer `dp` to a rectangular bitmap at position `(x, y)` with size `(w, h)`. This function works like `gl_putbox()` but doesn't write pixmap pixels of color zero. Also, for faster operation, the pixmap should be compiled with `gl_compileboxmask()` first.

`void gl_compileboxmask(int w, int h, void *mdp, void *dmp)`

Converts the rectangular masked bitmap of size `(w, h)` at `mdp` to a compressed format that allows faster drawing, which is stored at `dmp`. Allocating `w * h` bytes for the compiled version is usually enough; an upper limit should be `(w + 2) * h`. Compiled bitmaps are supported only in linear 256-color modes.

`int gl_compiledboxmasksize(int w, int h, void *mdp)`

Returns the size of the compiled version of the masked bitmap of size `(w, h)` at `mdp` that would be generated by `compileboxmask()`. Compiled bitmaps are supported only in linear 256-color modes.

`void gl_scalebox(int w1, int h1, void *mdp, int w2, int h2, void *dmp)`

Scales the bitmap sized `(w1, h1)` at `mdp` to size `(w2, h2)` and stores it at `dmp`, which must be a big enough buffer. The pixel size of the current graphics context is used.

## Palette Handling

These functions are in regard to palette management.

`void gl_getpalettedir(int c, int *r, int *g, int *b)`

See `gl_getpalette()`.

`void gl_getpalettedirs(int s, int n, void *dp)`

See `gl_getpalette()`.

`void gl_getpalette(void *dp)`

`gl_getpalettedir` gets the red, green, and blue values (in the range 0 to 63) of color `c` from the color-lookup table and stores them as integers in the memory locations pointed to by `r`, `g`, and `b`.

`gl_getpalettedirs` gets the RGB values of `n` colors starting at `s`, which are stored as a table of groups of three bytes, each at `dp`.

`gl_getpalette` is equivalent to `gl_getpalettedirs(0, 256, dp)`.

`vga_ext_set()` might change the range of the colors returned to 0 to 255.

`void gl_setpalettecolor(int c, int r, int g, int b)`

See `gl_setpalette()`.

`void gl_setpalettecolors(int s, int n, void *sp)`

See `gl_setpalette()`.

`void gl_setpalette(void *sp)`

`gl_setpalettecolor` sets the red, green, and blue values (in the range 0 to 63) of color c from the color-lookup table to r, g, and b.

`gl_setpalettecolors` sets the RGB values of n colors starting at s, which are stored as a table of groups of three bytes, each at sp.

`gl_setpalette` is equivalent to `gl_setpalettecolors(0, 256, sp)`.

`vga_ext_set()` might change the range of the colors to be set to 0 to 255.

`void gl_setrgbpalette(void)`

Sets the 256-color RGB palette (bits 0 to 2 are blue, 3 to 5 are green, and 6 to 7 are red). Call this prior to using `gl_getpixelrgb()`, `gl_rgbcolor()`, or `gl_setpixelrgb()` in 256-color modes.

> **Warning**
>
> Beware! These functions aren’t directly a part of libvga or libvga. However, their source code is distributed along with SVGA lib version 1.4.0, and it can be found in the threeDKit subdirectory of your SVGA lib distribution.

Usage is similar to vga. You’ll need to include `<triangle.h>` in your headers. The actual routines are defined in the `trio.o` and `triangl.o` files (or their respective sources), as well as in the threeDKit subdirectory, which must then be linked to your program at compilation time.

`void gl_triangle(int x0, int y0, int x1, int y1, int x2, int y2, int color, int bf)`

Draws a noninterpolated (solid) triangle between the three points 0, 1, and 2 using the color given in color. The bf value is used to tell the routine not to draw the triangle if it's facing the other way. Also, bf tells which way the triangle needs to be facing to be drawn, because you'll more than likely require both combinations.

It's important to know that bf = 0 disables drawing when the points are arranged clockwise, bf = 1 disables drawing when the points are arranged counterclockwise, and bf = -1 will probably always draw the triangle.

`void gl_swtriage(int x0, int y0, int xd0, int yd0, int x1, int y1, int xd1, int yd1, int x2, int y2, int xd2, int yd2, int c, TD_tridata *tri)`

The following code

```c
typedef struct {unsigned char *bitmap1; unsigned char *bitmap2; int bf; } TD_tridata;
```

draws a triangle at points 0, 1, and 2 by mapping the pixmaps defined in the TD_triangle structure into the triangle.

The xd and yd values represent the triangle on the bitmap, and the x and y values represent the triangle on the screen.

bitmap1 defines the back side of the triangle, and bitmap2 the front.

The bf value is used to tell the routine to draw the backside if it is facing the other way. Also, bf tells which way the triangle should be facing to show the front, because you will more than likely require both combinations.

It's important to know that bf = 2 defines the back to be drawn when the points are arranged clockwise, bf = 3 defines the back to be drawn when the points are arranged counterclockwise, and bf = -1 will probably always draw the front.

`void gl_triangle(int x0, int y0, int z0, int x1, int y1, int z1, int x2, int y2, int z2, int bf)`

Draws a triangle between the three points 0, 1, and 2. The colors at these points are z0, z1 and z2. Therefore, if you set the palette to grayscale, the triangle will have an interpolated gray shade.

If you're using more than 8-bit color, the z values will be interpreted as an index to a lookup table that's, at most, 4,096 entries long. Each entry is of type long. You can set the entries with the function gl_tricolorlookup().

The bf value is used to tell the routine to draw the backside if it's facing the other way. Also, bf tells which way the triangle should be facing to show the front—you'll more than likely require both combinations.
