**Note**

Resetting the terminal to text mode is always a nice thing to do for your users. It’s a pain when some inconsiderate programmer forgets to do this; you get garbage all over your screen (as well as on every other virtual terminal), and you usually have to reboot to clear it. Of course, you can’t see what you’re typing, so then you take the risk of messing things up. And if you just shle the machine off, you might damage your file system. You can avoid this whole scenario by using `vga_setmode(0)` before you turn out the lights and say goodnight. It’s that easy. If you’re especially paranoid, you can be logged into another terminal with `shutdown -r now` pretyped on the command line. If the console gets hung, just switch to the disaster relief terminal and press Enter.

Finally, we use `return 0,` meaning the program has executed flawlessly. Also, `exit(0)` works fine, too, and can be found in the SVGAlib demo programs. As with the screen modes, it’s six of one, half dozen of the other. You might note that in the interest of portability, some people prefer to use `returnEXIT_SUCCESS` instead of `return 0.`

# Compilation

I’m not going to have a compilation section after every installment, but we can go over the process here one more time, just to make sure you’re on the right track. If the preceding code were called `myfirst.c,` you would compile it by typing this:

```
gcc -Wall -O3 -o myfirst myfirst.c -lvg a
```

# Setuid Requirement

There’s one more step to take after compilation, and it’s something you’ll need to remember. As you know, a process must have root status to interact directly with a piece of hardware. While this direct communication is one of SVGAlib’s assets, it also requires that you plan ahead. If your SVGAlib app has graphical output (and most do, obviously), you must change its run-time permissions with `chmod` to allow nonroot users to run it.

To make an application `setuid` root (that is, accessible by ordinary users), you will need to execute one of the following commands. (We’ll assume that the compiled program is still called `myfirst.`)

```
chmod u+s myfirst
```

Or, an equally acceptable solution is to type:

```
chmod 4755 myfirst
```
