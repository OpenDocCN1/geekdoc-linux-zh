
## Conventions Used In This Book

It's well known that there are several ways to format a program written in C. Some people will argue that their way is the best, while others will be staunchly in favor of utilizing their own method. Regardless, the only issues that really matter are your ease of coding, and your code's readability by others.

Keeping in line with my second criterion, I have strived to make the code in this book as readable as possible.

### Function Names

All function names will appear in lowercase letters. When a name is comprised of two or more words, an underscore character will be used to join them, as follows:

```
function_name()
```

### Braces (a.k.a. Curly Braces, or Brackets)

Although this deviates from the original Kernighan & Ritchie method (as demonstrated in their landmark volume, “The C Programming Language”), I have made an effort to place all braces in line with one another. I find this to be the easiest method of distinguishing between functions, especially for beginners. It does use some extra space, but I find the end result to be well worth it.

For example:

```
function()
{
   /* Code goes here */
}
```

### Comments

For those of you who are new to C, everything that appears within a pair of forward slash and asterisk characters is a comment. For example:

```
/* This is a comment */
```

Comments may be used liberally, as they are stripped from your source code by the C compiler at compilation time, and don't add to a compiled program's size.

### SVGAlib Versions

This book is relevant to all versions of SVGAlib, although I've focused on the most recent release: 1.4.0. Many Linux distributions contain earlier versions of the library, which you're welcome to use for coding purposes. However, you may find that you're missing some useful features and functions, so I'd recommend installing the most current rendition. I've attempted to make this as painless as possible by including version 1.4.0 on the enclosed CD, but you may want to download something even newer. You'll find instructions on compilation and installation in Chapter 1.

#### How To Get And Install SVGAlib

Many Linux distributions come with a precompiled version of SVGAlib. If yours did and you’re satisfied with it, you can skip this section. However, if you’d like to upgrade to the newest version, read on. Even if you already have SVGAlib installed on your machine, upgrading will be a great opportunity to get your feet wet and to ensure that everything's properly configured. By all means, don't be frightened by the prospect of compiling your own copy of SVGAlib. It's a very straightforward process and shouldn't take you more than 15 minutes from start to finish.

To begin with, you'll need to obtain the SVGAlib source package. While there are several methods available, I'd suggest doing one of the following:

- Copy it from the enclosed CD-ROM.
- Download it from the Internet.

The CD-ROM that accompanies this book contains version 1.4.0, the most up-to-date version of SVGAlib at the time of this writing. However, this being a progressive library, improvements are bound to be made. For example, several new video card drivers have been added in the past few months, so I'd suggest that you visit the official Web site every now and then to see if a newer version's been released.

The SVGAlib Web site is located at www.svgalib.org. This site is a great resource for developers; it contains up-to-date tips and hints, as well as a bulletin board you can post to if you need extra help. The distribution isn't actually housed at svgalib.org; it links to the gigantic metavalab.unc.edu (formerly Sunsite) Linux repository. If you'd like to go there directly, the full address is metavalab.unc.edu/pub/Linux/libs/graphics. Access isn't restricted to the Web, however; Metalab allows the use of a regular FTP client as well.

The source “earball” is called svgalib-1.4.0.tar.gz. If your system is based on glibc2 (GNU’s C library, which supersedes the libc.so.5 series), you'll also want to download the precompiled binary version. Despite how it seems, the precompiled SVGAlib isn't there to save you time. Rather, its purpose is to allow compatibility with precompiled applications that were built with libc.so.5. If this is all Greek (“geek”? ) to you, don't worry. I'll go into more detail later in the chapter.

> **Note**
> Users with a glibc2-based system (such as RedHat 5.x, Debian 2.x, or SuSE 6.x) will need to download the binary distribution as well as the source, because glibc2 isn't compatible with previous Linux libcs, and you'll need the binary distribution to run older, precompiled libc.so.5 programs, such as Quake. We’ll give more information on this in a bit.
>
> Don't worry if you get the following error: “Warning: return type of ‘main' is not ‘int’”. This is merely a case of outdated syntax, and won't have any adverse effect upon your compilation.

### C Compiler

In addition to the SVGAlib source files, you'll also need the GNU C compiler, gcc. This comes with just about every Linux distribution; in case you don't already have it, it can also be found at `metalab.unc.edu` in the `/pub/Linux/GCC` directory. If you're interested, the original gcc site is at `www.gnu.org`. In either case, look for `gcc-2.95.1.tar.gz`, or any later version.

**Note**

The author has successfully compiled SVGAlib on Intel- and Cyrix-based systems. However, AMD processors can sometimes cause problems when used with Linux. They may look like a good buy now ("I can buy the computer and a VCR!"), but you might be sorry later ("Why isn't this compiling?"). My advice is to accept that AMD is a Windows platform and leave it at that.

### SVGAlib On The Compaq Alpha

Although SVGAlib is used mainly on Intel (and variant) systems, David Mosberger-Tang has contributed patches to make SVGAlib run on Alphas. Read the O-INSTALL file if you have an interest in this.

### Unpacking The Distribution

It's suggested that you store the source files in either the `/usr/src` or `/usr/local/src` directory, but it makes no difference. After downloading or otherwise obtaining the distribution, you'll need to uncompress it by running `gunzip` and `tar`. Simply type `gunzip svgalib-1.4.0.tar.gz` and then `tar -xzf svgalib-1.4.0.tar`. You can save a step and do this all at once by using `tar -xzf`. Typing `tar -xzf svgalib-1.4.0.tar.gz` will create a directory called `svgalib-1.4.0`, which will be filled with the subdirectories and files listed in Table 1.1.

Table 1.1 Package contents.

| Directory | Files |
|---|---|
| *demos/* | Demo and test programs. |
| *doc/* | README files and man pages. (See the O-README file in this directory for information on how to read these man pages without installing SVGAlib and how to produce nice printouts.) |
| *et4000/* | Notes, utilities, and sample registers for ET4000. |
| *gl/* | External framebuffer graphics library sources. |
| *include/* | Links to the various header files needed for compilation. |
| *jmp/* | Configuration files for building a DLL shared library. |
| *lrm-0.6m/* | Linux real-mode library (used for VESA drivers). Including a utility for restoring text mode. |
| *mach/* | Notes and a utility for the ATI Mach32 driver. |
| *sharedlib/* | Shared library image and stubs. |
| *src/* | Main library source. |
| *support/* | DOS-based utility for dumping VGA registers. |
| *svpmi/* | Basic initial untested SVPMI skeleton driver. |
| *threeDKit/* | Routines for drawing 3D triangles and 3D demos. |
| *utils/* | Text mode/font utilities. |
