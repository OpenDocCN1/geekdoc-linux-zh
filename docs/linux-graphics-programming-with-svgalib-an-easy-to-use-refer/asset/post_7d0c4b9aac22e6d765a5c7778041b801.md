
# Key State

If the key with that scancode has been pressed, `buffer[SCANCODE]` will be 1. Actually, `KEY_PRESSED` is 1 and `KEY_NOT_PRESSED` is 0, which allows you to use constructs such as this:

```c
if (buffer[SCANCODE_ENTER]) {
    /* do something */
}
```

This is more efficient than calling `keyboard_keypressed()`, in case you want to check for many different keys. Note that keyboard events will only be processed when you occasionally call `keyboard_update()` or `keyboard_waitforupdate()`.

### void keyboard_clearstate(void)

When in raw keyboard mode, SVGLib receives press and release events from the kernel and keeps track of which keys are currently pressed. Calling `keyboard_clearstate()` sets this information to all keys released. You can use this for cleanup at certain places in your program. In addition, SVGLib resets the states of all keys when a VC switch occurs because it doesn’t know the current state of keys when it regains control of the console.

```c
typedef void (*_keyboard_handler) (int scancode, int press);
void keyboard_seteventhandler(_keyboard_handler handler)
```

See `keyboard_setdefaulteventhandler()`.

### void keyboard_setdefaulteventhandler(void)

These functions allow you to define a keyboard event handler that is called by `keyboard_update()` and `keyboard_waitforupdate()` when a keyboard event occurs. The argument `press` is `KEY_EVENTRELEASE` or `KEY_EVENTPRESS` if the key scancode was released or pressed. Actually, the first value is 0, and the second is 1 (which are intuitive so that you may use them in your programs). Even if you specify your own handler, SVGLib will check for Alt+F7 or Ctrl+C for console switches or generation of SIGINT, if allowed by `keyboard_translatekeys()`.

Calling `keyboard_setdefaulteventhandler()` reinstates the default handler, which maintains the tables used by `keyboard_getstate()` and `keyboard_keypressed()`. It’s probably a good idea to call `keyboard_clearstate()` after re-enabling the default handler. See `keyboard_keypressed()` for the list of scancodes.

## Joystick Handling

The functions in this section cover joystick handling:

> **Note**
> *These functions must include `<vgajoystick.h>`. The joystick module is basically independent from the rest of SVGLib. You can easily use it in text mode only, but there’s no benefit to doing that. If used in a graphics mode, however, it will release* the joystick devices upon a VC switch so that several applications can share joysticks. Unfortunately, this doesn't work during joystick calibration. Therefore, you should lock the VC with **vgalockvc()** while calibrating in graphics mode. Also, when using joysticks in text mode only, SVGAlib won't detect VC switches and joysticks cannot be shared among applications.

The simple test **demo joytest()** and the more complex graphical **mjoytest()** demo show the use of the joystick package in more and more detail.

These functions are only available in **ELF** versions of SVGAlib (which the vast majority of users have, anyway). Due to backwards compatibility issues, it cannot be used with shared .a out libs. Certain game ports seem to be unable to detect missing joysticks properly. (This might also be a Linux device driver issue.) Anyway, in using the joystick interface, allow a user of your application to specify the number of joysticks to be used as well as to bail out of the joystick calibration (when he is not able to press a button on a missing joystick). Usually **Ctrl+C** works, but you shouldn't rely too heavily on it, because it can be disabled. As a general guideline, try to open and calibrate joysticks while still in text mode. **Ctrl+C** will usually still work then. If this succeeds, you may assume a joystick is there for any following recalibrations in graphics mode.

```c
typedef void (*_joystick_output)(const char *msg);
int joystick_init(int joydev, _joystick_output jo)
```

This function opens a joystick device. A negative value is returned on failure--otherwise the joystick was initialized. SVGAlib supports several joysticks. The corresponding device code names can be configured in `/etc/vga/libvga.config`.

The **joydev** parameter indicates which joystick is to be initialized. As of this writing, SVGAlib supports up to four joysticks: **joydev = 0** to **joydev = 3**. Be advised, however, that existing hardware and kernel drivers can probably only handle joysticks 0 and 1.

It's strongly encouraged that your programs allow the user to calibrate the joystick. This is controlled by the **jo** parameter. If it's **NULL**, no calibration is performed. Otherwise, calibration is performed and instructions are printed to the user by calling the user-supplied **jo** function. It's the responsibility of this function to print the **NUL** and NL-terminated message (pointed to by **msg**) to the user. The message might contain embedded NL characters and will not extend 256 characters, including the terminating **NUL**.

Usually an **fputs(msg, stdout);** followed by **fflush(stdout);** will do, but for your convenience, you can perform the same by passing **JOY_CALIB_STDOUT** for **jo**. **gl_printf()** is well-suited for this job as well. However, it needs some font setup first, so a special preprocessor constant is not provided.

It's valid to initialize an already initialized joystick. This allows you to recalibrate the joystick at any time. The module supports older version **0.x** as well as newer version **1.x** joystick device protocols.

```c
void joystick_close(int joydev)
```

This closes the joystick **joydev** that was opened with `joystick_init()`. Giving argument **joydev = -1** closes all currently open joystick devices. Note that any calibration data is lost if you close a joystick.

```c
int joystick_update(void)
```

This queries all currently opened joysticks for position changes and calls the appropriate event handlers. A nonzero value is returned if and only if any joystick reported a position change. In more detail, the logical and of the return value and `(1 << joydev)` is nonzero if the joystick status changed.

```c
typedef void (*__joystick_handler)(int event, int number, char value, int joydev);
void joystick_sethandler(int joydev, __joystick_handler jh);
```

See `joystick_setdefaulthandler()`.

```c
void joystick_setdefaulthandler(int joydev)
```

By default, each call to `joystick_init()` enables the default handler for the opened joystick. This handler maintains a state table that can be read by the `joystick_getaxis()`, `joystick_getbutton()`, `joystick_button1` through `joystick_button4()`, `joystick_getb1` through `joystick_getb4()`, `joystick_xylyzl()`, and `joystick_getx1y1z1()` functions. If you define an own handler, several parameters are passed.

Argument **event** is one of the following values:

- `JOY_EVENTBUTTONDOWN` — A button was pressed.
- `JOY_EVENTBUTTONUP` — A button was released.
- `JOY_EVENTAXIS` — The joystick position was changed.

All other event values are reserved for future use.

Argument **number** identifies the button or axis to which this event belongs. Argument **value** is for axis events—the new position in the range -128 to 127. See `joystick_getaxis()` for further comments on the range.

Argument **joydev** identifies the joystick affected (this allows you to use one handler for many joysticks). Entering **joydev = -1** modifies the event handler of all currently open joystick devices.

```c
char joystick_getnumaxes(int joydev)
```

See `joystick_getnumbuttons()`.

```c
char joystick_getnumbuttons(int joydev)
```

This queries the number of axes (the number of continuous ranges that the joystick allows you to choose from) and buttons. The old version 0.x joystick protocol reports two axes (x and y) and four buttons, although the actual joystick will usually have fewer (often two buttons). SVGAlib supports up to 127 axes and buttons, provided the underlying device driver does, too.

```c
char joystick_getaxis(int joydev, int a)
```

See `joystick_getbutton()`.

```c
char joystick_getbutton(int joydev, int b)
```

These functions query the current state of joystick **joydev**. Actually, this is the state found during the last call to `joystick_update()` with the default joystick event handler active. The function `joystick_getaxis(joydev, a)` returns the current state of the given axis (usually x - 0, y - 1, z - 1,..) in the range -128 to 127. Some effort is made to ensure that the center position is close to 0.

Note that the protocol joystick calibration for version 0.x is very bad. You won't usually see the extreme values on the extreme position. Also, the center position will be close to zero, but not exactly zero, and return values will also vary slightly from call to call—even when the user didn't move the joystick.

The function `joystick_getbutton(joydev, b)` returns the state of a button. It returns 1 for a pressed button and 0 otherwise. Note that no hardware check exists for button clicks. The button press is only detected during a call to `joystick_update()`, at least in the 0.x protocol.

> **Note**
> *The functions simply return the data passed to the default joystick event handler.*

For your convenience, the following shortcuts have been established by use of the preprocessor:

- `joystick_button1(i)` for `joystick_getbutton(i, 0)`
- `joystick_button2(i)` for `joystick_getbutton(i, 1)`
- `joystick_button3(i)` for `joystick_getbutton(i, 2)`
- `joystick_button4(i)` for `joystick_getbutton(i, 3)`
- `joystick_x(i)` for `joystick_getaxis(i, 0)`
- `joystick_y(i)` for `joystick_getaxis(i, 1)`
- `joystick_z(i)` for `joystick_getaxis(i, 2)`
- `joystick_getb1()` for `joystick_getbutton(0, 0)`
- `joystick_getb2()` for `joystick_getbutton(0, 1)`
- `joystick_getb3()` for `joystick_getbutton(0, 2)`
