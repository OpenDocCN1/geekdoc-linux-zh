## Conclusion

Obviously, one chapter can't begin to do justice to such an expansive field as landscape generation. Hopefully, though, you'll be able to base some of your work on the code presented here.

You can use artificial landscapes for many purposes. Many choose to utilize them in games that need unpredictable, yet realistic, terrain. Others, like myself, prefer to enjoy these pseudo-worlds as they are, for no other purpose than to marvel at their beauty and complexity.

One excellent reference regarding artificial landscapes is Dr. F. Kenton Musgrave. Dr. Musgrave (or Ken for short) actually worked with Benoit Mandelbrot many years ago and now has his own company called *FractalWorlds.com* (I'll let you figure out the Web address). His credits include some artificial moon shots from the movie *Apollo 13*, as well as the clouds that morph into the likeness of Mickey Mouse in a certain cruise line's commercials. His book, *Texturing and Modeling*, contains a wealth of information, albeit a little on the academic side. In short, Ken is a really nice guy, and his work is a benefit to programmers everywhere. If you have a chance to talk with him, tell “Mo” I said hello.

### A Brief Look At Porting

Perhaps you have a favorite application that you'd like to see on Linux? You might be the one to make it happen. If you have the source, then your work is cut out for you.

Of course, SVGAlib programs are generally written in C/C++, and oftentimes DOS code is, too. If your original program was compiled with Borland C (a popular package) or even Fastgraph (for DOS or Windows), you can consult Table 17.4 for a list of common graphic functions and their equivalents in SVGAlib and vga1.

#### Porting From Pascal

If your program was instead written in Pascal—and many have been—don't despair. Many Linux distributions come with a neat little program called p2c. Simply put, p2c translates most reasonable Pascal programs into C, at which point your conversion to SVGAlib should be fairly straightforward. According to the p2c man page, the following variants are supported: HP Pascal, Turbo/UCSD Pascal, DEC VAX Pascal, Oregon Software Pascal/2, Macintosh Programmer's Workshop Pascal, Sun/Berkeley Pascal, and Modula-2.

Table 17.4 Porting functions.

| Borland C | Fastgraph | libvga | libvga1 |
| :--- | :--- | :--- | :--- |
| initgraph() | fg_setdc (HDC hdc) | vga_init() | N/A |
| putpixel(int x, int y, int c) | fg_putpixel(int ix, int iy) | vga_drawpixel (int x, int y) | gl_setpixel(int x, int y, int c) |
| cleardevice() | gl_fillpage() | vga_clear() | gl_clearscreen (int c) |

### Includes

Many of the header files used by a DOS C program will no longer be applicable in Linux. Universal headers such as `<stdio.h>` and `<stdlib.h>` can be kept, but you'll need to get rid of `<conio.h>`, `<graphics.h>`, and `<dos.h>`. Then, insert `<vga.h>` and `<vga1.h>` (if needed).

Note also that you may need to add vga_setmode(), because the old Borland initgraph() was equivalent to both vga_init() and vga_setmode().
