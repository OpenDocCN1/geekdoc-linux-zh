## Listing 8.3 Fern leaf.

```c
/*  Pre-SVGA1ib code by Paul Bourke:
www.mhri.edu.au/~pdb/fractals/fern */

/*  Usage: <program name> <nsteps>
(Try 50,000 nsteps -- it won't take long). */

#include <stdio.h>
#include <stdlib.h>
#include <math.h>
#include <cvg.a.h>

#define NX 1024
#define NY 768
#define MIN(x,y) (x < y ? x : y)

double a[4] = {0.0,0.2,-0.15,0.75};
double b[4] = {0.0,-0.26,0.20,0.04};
double c[4] = {0.0,0.23,0.26,-0.04};
double d[4] = {0.16,0.22,0.24,0.85};
double e[4] = {0.0,0.0,0.0,0.0};
double f[4] = {0.0,1.6,0.44,1.6};

int main(int argc, char *argv[])
{
int i,j,k;
int n;
int ix,iy;
double r,x,y,xlast=1,ylast=1;
double xmin=-1e32,xmax=-1e32,ymin=1e32,ymax=-1e32,scale,xmid,ymid;

if (argc < 2) {
fprintf(stderr,"Usage: %s nsteps\n",argv[0]);
exit(0);
}
n = atoi(argv[1]);

vga_init();
vga_setmode(G1024x768x256);
vga_setcolor(15);

for (j=0;j<2;j++) {
for (i=0;i<n;i++) {
r = rand() % 100;
if (r < 10)
k = 0;
else if (r < 18)
k = 1;
else if (r < 26)
k = 2;
else
k = 3;
x = a[k] * xlast + b[k] * ylast + e[k];
y = c[k] * xlast + d[k] * ylast + f[k];
xlast = x;
ylast = y;
if (x < xmin) xmin = x;
if (y < ymin) ymin = y;
if (x > xmax) xmax = x;
if (y > ymax) ymax = y;
if (j == 1) {

scale = MIN(NX / (xmax - xmin),NY / (ymax - ymin));
xmid = (xmin + xmax) / 2;
ymid = (ymin + ymax) / 2;
ix = NX / 2 + (x - xmid) * scale;
iy = NY / 2 + (y - ymid) * scale;
vga_drawpixel(ix, iy);
}
}
}

vga_getch();
vga_setmode(TEXT);
return 0;
}
```

Thus far, I've shown you how to draw a number of images on the screen. That's okay for your own personal usage. Sometimes, though, it'd be nice to capture these images to show others, especially if they don't use Linux or SVGA1ib. It'd also be nice to be able to view images that others have given you.

To accomplish this, we have the graphic file. Graphic files are binary files that contain image data. The standard formats are cross-platform, and they're often compressed to save space. Some common formats are GIF, JPG (or JPEG), and BMP.

Like fonts, graphic files come in two formats: bitmapped and vectored. A bitmapped image is made up of a grid, much like a screen matrix, whereas a vector format utilizes mathematical equations to record image data. The vector format corresponds with a vector font and often allows for a smaller file than a bitmap of the same image would.

Graphic files consist of header information, meaning the file format, as well as size and color information, which is then followed by the actual image data. The image data can be as small as one pixel or as large as your computer's memory will allow.

You may have worked with text files in C before; examples include /etc/passwd and even /etc/vga/libvga.config. Here's how you might print libvga.config to the screen:

```c
char line[256];
FILE *myfile;

myfile = fopen("/etc/vga/libvga.config", "r");
while (fgets(line, 255, myfile) != NULL)
{
    printf("%s\n", line);
}
fclose(myfile);
```

Binary files (such as graphic files) are opened in a similar manner, except that they use the +b string. Here’s an example:

```c
myfile = fopen("binary_file", "r+b");
```

## GIF

CompuServe’s Graphics Interchange Format. This format—extremely popular on the Web—allows for a total of 256 colors. It is compressed horizontally, so an image with many horizontal lines will be smaller than one of the same size with many vertical lines. It’s officially pronounced *giff*, but many people say *gif*. The GIF compression algorithm copyright is now owned by UNISYS.

## JPG (JPEG)

This format, pronounced *jay-peg*, was developed by the Joint Photographic Experts Group (hence the name). Compression is achieved by dividing the picture into tiny pixel blocks, which are halved over and over until the desired ratio is achieved. Compression as high as 100:1 can be achieved, but 10:1 and 20:1 are more common ratios.

## BMP

A Windows bitmap file, BMP file, can allow for 2, 16, 256 or 16 million colors (1-bit, 4-bit, 8-bit, and 24-bit color). The BMP file is generally uncompressed.

## Bitmap File Header

The **BITMAPFILEHEADER** data structure contains information about the type, size, and layout of a *device-independent bitmap* (DIB) file:

```c
typedef struct tagBITMAPFILEHEADER {
    WORD    bfType;
    DWORD   bfSize;
    WORD    bfReserved1;
    WORD    bfReserved2;
    DWORD   bfOffBits;
} BITMAPFILEHEADER;
```

The **BITMAPFILEHEADER** data structure contains the fields shown in Table 9.1.

A **BITMAPINFO** data structure immediately follows the **BITMAPFILEHEADER** structure in the DIB file.

## Bitmap Info

The **BITMAPINFO** structure fully defines the dimensions and color information for a Windows 3.0 device-independent bitmap:

```c
typedef struct tagBITMAPINFO {
    BITMAPINFOHEADER    bmiHeader;
    RGBQUAD             bmiColors[];
} BITMAPINFO;
```

> **Note**
> *3.0 refers to the bitmap format, and not to a particular version of Windows.*

The **BITMAPINFO** structure contains the fields shown in Table 9.2.

A Windows 3.0 device-independent bitmap consists of two distinct parts: a **BITMAPINFO** data structure that describes the dimensions and colors of the bitmap, and an array of bytes that define the pixels of the bitmap. The bits in the array are packed together, but each scanline must be zero-padded to end on a LONG boundary. Segment boundaries can appear anywhere in the bitmap, however. The origin of the bitmap is the lower-left corner.

The **biBitCount** field of the BITMAPINFOHEADER structure determines the number of bits that define each pixel, as well as the maximum number of colors in the bitmap. This field may be set to any of the values shown in Table 9.3.

The **biClrUsed** field of the BITMAPINFOHEADER structure specifies the number of color indexes in the color table actually used by the bitmap. If the **biClrUsed** field is set to 0, the bitmap uses the maximum number of colors corresponding to the value of the **biBitCount** field.

The colors in the **bmiColors** table should appear in order of importance. Alternatively, for functions that use device-independent bitmaps, the **bmiColors** field can be an array of 16-bit unsigned integers that specify an index into the currently realized logical palette instead of explicit RGB values. In this case, an application using the bitmap must call device-independent bitmap functions with the *wUsage* parameter set to *DIB_PAL_COLORS*.

### Table 9.1 BITMAPFILEHEADER.

| Field | Description |
| :--- | :--- |
| bfType | Specifies the type of file. It must be BM. |
| bfSize | Specifies the size, in **DWORDs**, of the file. |
| bfReserved1 | This is reserved and must be set to zero. |
| bfReserved2 | This is reserved and must be set to zero. |
| bfOffBits | Specifies, in bytes, the offset from the bitmap file header of the actual bitmap in the file. |

### Table 9.2 BITMAPINFO.

| Field | Description |
| :--- | :--- |
| **bmiHeader** | Specifies a BITMAPINFOHEADER data structure that contains information about the dimensions and color. |
| **bmiColors** | Specifies an array of RGBQUAD data structures that define the colors in the bitmap. |

### Table 9.3 BITMAPINFOHEADER.

| Value | Meaning |
| :--- | :--- |
| 1 | The bitmap is monochrome, and the **bmiColors** field must contain two entries. Each bit in the bitmap array represents a pixel. If the bit is clear, the pixel is displayed with the color of the first entry in the **bmiColors** table; if the bit is set, the pixel has the color of the second entry in the table. |
| 4 | The bitmap has a maximum of 16 colors, and the **bmiColors** field contains up to 16 entries. Each pixel in the bitmap is represented by a 4-bit index into the color table. For example, if the first byte in the bitmap is 0x1f, the byte represents two pixels. The first pixel contains the color in the second table entry, and the second pixel contains the color in the 16th table entry. |
| 8 | The bitmap has a maximum of 256 colors, and the **bmiColors** field contains up to 256 entries. In this case, each byte in the array represents a single pixel. |
| 24 | The bitmap has a maximum of $2^{24}$ colors. The **bmiColors** field is **NULL**, and each three bytes in the bitmap array represents the relative intensities of red, green, and blue, respectively, of a pixel. |
