# Listing 10.3 A first stab at animation.

```c

#include <vga.h>

int main(void)
{

    y = 100,
    c,
    white;

  vga_init();
  vga_setmode(V320x200x256);

  white = vga_white();

  for (x = 300; x > 0; x--)
  {
    c = white;
    book_example(x, y, c);
    c = 0;
    vga_waitretrace();
    book_example(x, y, c);

  book_example(x, y, c);
```

By experimenting with different values, you can find the speed that's right for your application.

A word of caution, though—the simplicity of this method is offset by the fact that it produces programs that only look good on your computer, or others with the same processor and clock speed.

### Animation With Vgagl

As always, *vgagl* can do it better, faster, and with less typing on your part. Recall **gl_getbox()** and **gl_putbox()** from the last chapter; they'll make things a lot easier for you. Here's how you might animate using vgagl:

- 1. Take a “snapshot” of the background with **gl_getbox()**. That space is now saved in memory and is pointed to by *\*dp*. Remember? It's **gl_getbox(int x, int y, int w, int h, void \*dp)**.
- 2. Draw your image in the same location.
- 3. Now take a snapshot of the image you just drew, using a different pointer.
- 4. Finally, use **gl_putbox()** to alternate placing the two images on the screen. Erase with the first image (the blank background), move your point of reference, and then redraw with the second image.

**Frame buffer**

Memory in the graphics adapter used to hold a frame (i.e., one screen's worth of data). All VGA cards have at least one frame buffer; this is where the bitmapped screen image is stored as it's written to the screen. More advanced (and expensive) cards have enough memory to hold multiple frames. VgaI allows the use of two frame buffers: the physical screen and one "virtual" screen.

# Animation Over Photographic Backgrounds

Up until now, we've assumed that the background color is solid black. How, then, can one manipulate an object over a multicolored or even photographic background without leaving an amateurish "trail of destruction" in its wake? Elementary, my good reader—we'll use VgaI's frame buffer.

As you've probably noticed by now, VgaI is initialized like this:

```c
gl_setcontextvga(mode);
```

What this is really saying is, "Draw to the screen, boo." Perhaps you think this is obvious; where else would VgaI write? Well, it can also write to a virtual screen. This virtual screen, or frame buffer, exists only in the memory of your VGA card. However, you can transfer the contents of the virtual screen to the physical screen, and vice versa. When drawing to the virtual screen, you must first use the following:

```c
gl_setcontext(virtualscreen);
```

This creates an occurrence where **virtualscreen** is memory space allocated by *_gl_allocatecontext(void)*. You can return to the physical (visible) screen with the following:

```c
gl_setcontext(physicalscreen);
```

This is assuming you’ve similarly defined *physicalscreen*.

In Listing 10.5, I’m going to create a virtual screen with VgaI and then I’m going to draw a box on it. I’ll finish by copying the entire virtual screen to the physical (visible) screen.

# Listing 10.5 Frame buffer demonstration.

```c
#include <stdio.h>
#include <vga.h>
#include <vga1.h>

#define WIDTH 10
#define HEIGHT 10
#define COLOR 3

int main(void)
{
  int x = 10,
      y = 10;

  GraphicsContext *physicalscreen;
  GraphicsContext *virtualscreen;

  vga_init();
  vga_setmode(V320x200x256);

  gl_setcontextvga(V320x200x256);
  physicalscreen = gl_allocatecontext();
  gl_getcontext(physicalscreen);

  gl_setcontextvgavirtual(V320x200x256);
  virtualscreen = gl_allocatecontext();
  gl_getcontext(virtualscreen);

  /* Now I'm drawing to the frame buffer */
  gl_setcontext(virtualscreen);

  gl_fillbox(x, y, WIDTH, HEIGHT, COLOR);
```

```c
/* The contents of the current screen (the frame buffer)
are now copied to the physical screen.
*/
gl_copyscreen(physicalscreen);

vga_getch();
vga_setmode(TEXT);

return 0;
}
```

To accomplish animation across a patterned or otherwise nonsolid background, you could take the following steps:

- 1. Paint the desired background on a virtual screen.
- 2. Copy the background to the physical screen. This means that two identical backgrounds are now in memory, but only one is visible. The “pure” frame buffered background will always stay intact, whereas the visible background will be painted on.
- 3. Paint the relevant object (or sprite) onto the physical screen with `gl_putbox()`, as demonstrated in Listing 10.4.

Naturally, `gl_putbox()` requires that your image be rectangular in shape. It may be that your sprite isn’t, in which case you’ll have to redraw it by hand. Matters would be simplified considerably if it were possible to “paste” an irregularly shaped sprite into a scene. In fact, this is possible—with the help of transparency. See Chapter 14 for a discussion on transparent backgrounds.

- 4. When it comes time to move the object (or sprite), restore the relevant part of the background with `gl_copyboxfromcontext(GraphicsContext *gc, int x1, int y1, int w, int h, int x2, int y2).`

`gl_copyboxfromcontext()` is fantastic in that it allows you to copy only part of a screen. In other words, if you had some activity elsewhere on the screen, `gl_copyboxfromcontext()` would allow you to leave that part undisturbed. Furthermore, it saves you three steps. In other words, it’s not necessary to change your context, invoke `gl_getbox()`, return to your previous context, and then use `gl_putbox()`. Instead, you can accomplish all this in one fell swoop. It’s generally advised that you stay away from `gl_copyboxtocontext(int x1, int y1, int w, int h, GraphicsContext *gc, int x2, int y2)`, however, because it’s much less efficient.

**Sprite**

An independent graphical object. The hollow box animation used in Listing 10.3 is an example of a sprite. Sprites can move without affecting other parts of the screen and are routinely used in games. For instance, the characters in Mario Bros. are sprites.
