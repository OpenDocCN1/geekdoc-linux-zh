Splitting white light with a prism.

Pure light is white, and you get colors by splitting it. Then, as if by magic, reuniting the split colors forms white again. Figure 5.1 shows how a prism separates white light into multiple hues, forming the basis for this color theory (and a Pink Floyd album cover).

Your monitor is the opposite of a prism; it takes three distinct colors and combines them.

# Color In SVGAIib

I'm sure you're eager to move on to some real-world examples, so let's begin. You've seen SVGAlib's 16- and 256-color modes demonstrated in the previous two chapters—we simply used vga_setcolor() and entered a numeric value from 0 to 15 or 0 to 255. The results should have been familiar; most computers use the same basic 16 colors. (This is presumably because they're the standard EGA colors.) However, starting with the 256-color modes, shades numbering over 16 vary from one platform to another. For example, color 192 is going to be different on a Macintosh than it is on a PC. This variance gives rise to the complaint that SVGAlib's colors are too dark. This is easily explained—some ported programs haven't had their colors adjusted to match the SVGAIib palette. So, any unintentionally dark colors can be attributed to programmer laziness, ignorance, or indifference, and not to any fault on the part of SVGAIib.

There's no excuse for dark colors when we can fix the situation. The next new function, vga_getpalette(int index, int *r, int *g, int *b), gives the current RGB values for every standard color in SVGAIib. Simply insert the color number you're interested in, followed by pointers to the values for red, green, and blue. Have a look at Listing 5.1 for an example of vga_getpalette() in action.
