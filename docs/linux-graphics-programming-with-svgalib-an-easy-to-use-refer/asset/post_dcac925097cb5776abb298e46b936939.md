# Graphical Interfaces On Unix/Linux

Of course, GUIs aren’t limited to desktops. Another early graphical interface was Motif, designed for Unix and the X Windowing System. Because X isn’t restricted to Linux, Motif could be found across multiple platforms, including Sun and AT&T systems. This made it enormously successful and widely utilized, and it’s still in use today.

More recently, a new breed of graphical interfaces has been developed, specifically for Linux. You may be familiar with them; they include GNOME (the GNU Network Object Model Environment) and KDE (the K Desktop Environment). These have received a lot of press lately, mainly because Linux lags so far behind Windows and Macintosh in the “mom and dad” usability department. In other words, if Linux is ever to enter the desktop market, it needs a friendly face, and these applications are designed to help. ## Design Considerations

Interface experts have compiled a number of helpful points to be considered when crafting a GUI. These are proven, real-life criteria, and should be taken into account when developing an application. They are as follows:

- **Use Metaphors**—Play on a user’s existing knowledge to help ease the learning curve. For example, applications can and should employ symbolism. Everyone knows what a file folder is; they likely use them every day in the office. Thus, it should be obvious that a file folder icon represents a collection of files on the computer.
- **Direct Manipulation**—The user should feel that he or she is directly affecting anything that’s being worked on. So, rather than that shows that your program is processing the request.
- **Forgiveness**—Any action which might have serious consequences (deleting a file, for example) must be preceded by a second chance—that is, an opportunity for the user to back out or say no. If possible, make actions reversible by providing an “undo” command or function.
- **Aesthetic Integrity**—Here’s another important one. In addition to having a visually pleasing environment, design elements must remain consistent across your application(s). For example, don’t change the look of your icons and/or pop-up windows as you go. Strive to achieve consistency in colors and styles. This will go a long way in assuaging any fears that a user might have. Remember, familiarity is comforting.

# Finally, Some Code!

As you may have guessed, the objective of this chapter is to create a simple GUI for SVGAlib. I’m going to start by creating the menu bar for Splash, the paint program featured in Chapter 18. I’ll then continue by suggesting some ideas for icons and pop-up windows.

If you do it right, you can share many elements of your GUI with both your control screen and with the applications that run from it. In other words, the menu bar from the basic interface can also be employed by your graphical applications (for example, Splash). Given the right spin, this can be considered a “feature,” or perhaps a common element introduced for consistency.

Listing 19.1 shows the basic outline for the menu bar. Note that I’ve created a new SVGAlib font called “Cupertino” in homage to one of the earliest available GUIs. I prepare two versions of it in prep_fonts()—one white and one black.

The fonts here pose a new challenge, because SVGAlib (vagal) fonts are normally printed on a black background (specifically, the default background, or color 0). This clashes with the blue menu bar, and it would be absurd to attempt to redraw the blue around the letters. Therefore, you can employ gl_setwritemode(int m) to make the font's background transparent. Argument m can be one of four values, and the one for transparency is WRITEMODE_MASKED. The complete list of defines and their corresponding values can be found in Table 19.1. Note that two values will be in effect at all times—one for WRITEMODE and one for FONT. For example, if you change WRITEMODE, the FONT state will remain the same as before.

| Define | Value | Default Value |
| :--- | :--- | :--- |
| WRITEMODE_OVERWRITE | 0 | default |
| WRITEMODE_MASKED | 1 | |
| FONT_EXPANDED | 0 | default |
| FONT_COMPRESSED | 2 | |

The two fonts pose one more problem, however. The “transparency” made possible by gl_setwritemode() isn't anything magical. It simply decides whether the background color should be printed. This works fine, except when your font is the same color as the background (that is, black). Then you'll get nothing—your font will be transparent, just like the background. And, of course, if gl_setwritemode(WRITEMODE_OVERWRITE) is set, your result will be nothing more than a black box—a black font on a black background. To circumvent this aggravating and unfortunate combination of “features", you can set the font’s color to be most, but not entirely, black. I've used gl_rgcolor(10, 10, 10), which, being on the 256-color scale, appears to be a solid shade of pure, all-American charcoal black. Be careful not to set your RGB values too low, though, because gl_rgcolor() may round you down to 0, thereby defeating your efforts.

```c
void file_menu();
void edit_menu();

/*
    mouse & menu boxes:
    width * box height * 15 bits per pixel
*/
char mouse_box[11 * 19 * 15],
     menu_box[100 * 80 * 15],
     edit_box[125 * 20 * 15];

int a, i, j;
int color[20];
int x, y, ox, oy;
int button;

void *fontw,
     *fontb;

int main(void)
{
    int key;

    vga_disabledriverreport();
    vga_init();

    if ((a = vga_hasmode(6640x480x32K)) == 0)
    {
        printf("Your video card is incapable of handling mode 6640x480x32K\n");
        exit(1);
    }

    vga_setmousesupport(1);
    gl_setwritemode(WRITEMODE_MASKED);
    vga_setmode(6640x480x32K);
    gl_setcontextvga(6640x480x32K);
    prep_fonts();
    prep_screen();

    x = ox = 50;
    y = oy = 50;

    mouse_setposition(x, y);

    gl_getbox(x, y, 11, 19, mouse_box);
    draw_cursor(x, y);

while ((key = vga_getkey()) != 27) {
    mouse_update();
    x = mouse_getx();
    y = mouse_gety();
    button = mouse_getbutton();

    if ((x != ox) || (y != oy)) {
        move_cursor(x, y, ox, oy);
        ox = x;
        oy = y;
    }

    if (button & MOUSE_LEFTBUTTON) {
        if (y <= 19)
        /* we're in the menu bar */
        {
            if ((x >= 45) && (x < 79))
            {
                file_menu();
            } else if ((x >= 105) && (x <= 139)) {
                edit_menu();
            }
        }
    }
}
```
