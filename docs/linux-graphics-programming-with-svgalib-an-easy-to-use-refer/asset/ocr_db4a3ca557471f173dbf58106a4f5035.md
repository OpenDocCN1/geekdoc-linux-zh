For example, if you had your source code in a file called **source.c** and wanted the compiled program to be called **george**, you'd type the following:

```
gcc -o george source.c
```

Now, to include the functionality of SVGAlib, you'll need to add **-lvgal** to the end of your command line, like so:

```
gcc -o george source.c -lvgal
```

This tells **gcc** that it needs to link your compiled program with **libvgal.so.1** (refer to Chapter 1). If you also need functions in SVGAlib's extended library, **libvgagl.so.1** (this extension to SVGAlib is described in detail later; don't worry if it means nothing to you now), you'll need to add another flag to the command line. But, be careful. When linking to multiple libraries, the most important libraries must come last. Because **libvgal.so.1** is more important than **libvgagl.so.1**, your command line would look like this:

```
gcc -o george source.c -lvgagl -lvgal
```

> **Note**
> When performing a compilation using **vgagl** (libvgagl.so.1), you must reference it before **libvgal.so.1**, like this: **-lvgagl -lvgal**

Worried about errors in your code? Adding the **-Wall** (warnings, all) flag will display every possible problem that **gcc** finds with your code.

Finally, you can optimize the compilation to make the resultant executable faster. You do this by adding the **-O** flag. You can get an even better optimization (as well as a larger program and a longer compile) by using **-O2**. In fact, you can go all the way up to **-O3**.

Here's what we have now, using all of the flags:

```
gcc -Wall -O3 -o george source.c -lvgagl -lvgal
```

Using this, you can compile every example in this book.
