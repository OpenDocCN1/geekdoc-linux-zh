# Simple Paint Program

Key Topics:

One application that’s clearly missing from the SVGAlib milieu is any sort of drawing/painting/imaging program. This gaping absence may come as a surprise, considering how useful such programs can be. Virtually every operating system allows you some method of doodling on the screen, no matter how primitive, and yet SVGAlib conspicuously offers nothing. One can hardly make it through the day without seeing some media reference to Adobe’s Photoshop, Jasc’s Paint Shop Pro, or even the GIMP, a popular imaging program for X Windows. When compared to these application giants, SVGAlib comes up flat. Of course, we as programmers have our own drawing primitives, but there’s nothing available for the end user.

With that in mind, the objective of this chapter is to create a comprehensive paint program using SVGAlib. Most importantly, it must be one that’s accessible to nonprogrammers. If you decide to code as you read along, you should have a working example by the end—one that you can distribute among your friends. Otherwise, if you’d rather just read, you’re welcome to take the code presented here and expand on it. The finished product might be somewhat limited in its capabilities (when compared to Photoshop, for example), but I’m sure you’ll enjoy it nonetheless.

Last but not least, this project will touch on the issue of interface design and will serve as a comprehensive summary of the commands that you’ve learned thus far. In a sense, then, it will be your final examination. Fear not, though—it’s an open book test, and you get to grade yourself.

## Development Objectives

Given the inherent space constraint (one chapter), I feel it’s important to concentrate on the essential features that a small paint program should provide. These most notably include ease of use and functionality. Other features of lesser importance (and perhaps limited interest) can always be added later.

The following list details my priorities. You may feel that some of the items are obvious and/or excessively elementary, but it’s important that all bases be covered. Remember, not everyone has the same level of experience. Here’s the list:

- **Intuitive interface**—Despite Bruce Ediger’s assertion that “the only intuitive interface is the nipple,” there are certain things that we have come to expect when using an application. This program must meet or surpass those expectations.
- **Functionality**—If a program isn’t useful, why bother having it! A successful paint program will have a variety of drawing tools and the ability to save images in a variety of formats.
- **Code clarity**—You don’t get extra points for obfuscation. Remember, other people might need to add to your code, too.
- **Overall simplicity**—The user shouldn’t have to expend a lot of effort learning your program. The sooner the user is comfortable and productive, the better.

## Interface

As mentioned earlier, people have come to expect a certain look and feel in “professional” applications. Figure 18.1 shows a standard layout, which is what I’ll be following. (Of course, you’re allowed to deviate from the “norm” if you have solid ideas regarding interface design, but it’s best to stick with what’s tried and true if you don’t.)

Some programs adapt to take advantage of the highest available screen mode, but I’m not going to worry about that here. For simplicity, I’ve decided to keep the screen fixed at a resolution of 640x480. This is large enough to be useful, and it’s also likely to be supported by most modern video cards. Eliminating the variable screen size also frees up some programmer brain cells for other tasks.

Another option (regarding screen modes) is to see whether *vga_getdefaultmode(void)* returns anything. This function corresponds to the *SVGALIB_DEFAULT_MODE* environment variable, and it returns either a screen mode, or −1 (if no mode has been defined). It’s likely that if a mode has been defined, the user would like you to accommodate it. It’s up to you as to whether you’ll honor that request.

## Screen Layout

Following the example of most GUI programs, I’ve placed a menu bar at the top of the screen. This will accommodate pull-down menus such as those used to open and save files.

On the left side, I’ve allocated space for a drawing menu and a color palette. A more advanced program might allow these sections to “float” around the screen as portable tool bars, but this, too, detracts from my goal of simplicity.

The rest of the screen is devoted to the drawing area. The larger this area is, the better. Nevertheless, scrollbars will be provided for images that don’t fit within the confines of one screen.

## Basic Code

To start with, I’m going to check and verify that the video card can handle a screen mode with a 640x480 matrix and 32K colors. If you’re curious as to why I’ve chosen 32K, it’s because it’s the next step up from 256. Although 256 overall colors might be adequate, it’s possible that the user will attempt to load a GIF image with 256 colors of its own. If those don’t match the colors used by the interface, some will be corrupted or lost. Therefore, 32K is necessary, and if the video card in question can’t handle this, then the program should exit with an error message.

Listing 18.1 shows the basic shell of my program. As you can see, it isn’t much different (yet) than many of the other programs in this book.

### Listing 18.1 Basic code outline.

```c
#include <stdio.h>
#include <stdlib.h>
#include <luc.h>
#include <lucfnits.h>
#include <vga.h>
#include <vga91.h>
#include <vgamouse.h>

int main(void)
{
   int a;

   vga_disableintverport();
   vga_init();

   if ((a = vga_hasmode(G640x480x32K)) == 0)
   {
      printf("Your video card is incapable of handling mode G640x480x32K\n");
      exit(1);
   }

   vga_setmousesupport(1);
   vga_setmode(G640x480x32K);
   gl_setcontextvga(G640x480x32K);

   /* program goes here */

   vga_setmode(TEXT);

   return 0;
}
```

### Building The Interface

The next step is to build the bare essentials of the user interface, as shown in Listings 18.2 and 18.3. This will make the program workable, albeit rather Spartan. Starting with Listing 18.2, I’m going to draw the menu bar (without any options), the color palette, and the drawing area. In my continuing effort to keep things simple, I will only allow users to access the 16 basic EGA (Enhanced Graphics Adapter) colors.

Note that I introduce some new variables (*i* and *color[]*), which will be assumed to be at the beginning of the **main()** loop. When the complete code is given at the end of this chapter, the variables will be placed properly.

### Listing 18.2 Basic interface.

```c
/* Define some colors that'll be used throughout */

int i;
int color[18];

for (i = 0; i <= 15; i++)
{
    color[i] = vga_setegacolor(i);
}
color[16] = gl_rgbcolor(235, 235, 235);    /* background */
color[17] = gl_rgbcolor(51, 51, 255);     /* menu bar */
color[18] = gl_rgbcolor(130, 130, 130);    /* dark gray */
color[19] = color[0];                     /* current color */

/* draw the background */
gl_clearscreen(color[16]);

/* draw the menu bar */
gl_fillbox(0, 0, 640, 20, color[17]);

/* draw the color palette */
for (i = 0; i <= 7; i++)
{
    y = (250 + (i * 21));
    gl_hline(9, (y + 20), 49, color[15]);

    gl_fillbox(9, y, 20, 20, color[(i * 2)]);
    gl_hline(9, y, 28, color[18]);
    gl_hline(10, (y + 1), 27, color[0]);
    gl_hline(10, (y + 19), 28, color[7]);
    gl_vline(9, (y + 1), 9, (y + 19), color[18]);
    gl_vline(9, (y + 2), 10, (y + 18), color[0]);
    gl_vline(28, (y + 1), 28, (y + 18), color[7]);

    gl_fillbox(30, y, 20, 20, color[((i * 2) + 1)]);
    gl_hline(30, y, 49, color[18]);
    gl_hline(31, (y + 1), 48, color[0]);
    gl_hline(31, (y + 19), 49, color[18]);
    gl_vline(30, (y + 1), 30, (y + 19), color[18]);
    gl_vline(31, (y + 2), 31, (y + 18), color[0]);
    gl_vline(49, (y + 1), 49, (y + 18), color[7]);
}
gl_vline(29, 250, 29, 397, color[15]);
gl_vline(60, 250, 50, 397, color[15]);

/* draw the current color */
y = 424;
gl_fillbox(16, 426, 28, 28, color[19]);
gl_hline(14, y, 44, color[18]);
gl_hline(15, (y + 1), 43, color[0]);
```
