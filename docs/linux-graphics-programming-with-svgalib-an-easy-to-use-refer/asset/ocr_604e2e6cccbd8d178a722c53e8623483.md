Remember that the `vga_init()` command relinquishes root status, so there's not much to worry about here.

> Warning
> An SVGAlib application must be *setuid* root for ordinary users to have access.

And with that, your first real SVGAlib program is complete. Congratulations! Consider yourself baptized into the world of Linux graphics. See, it wasn't as hard as you thought. Nor should it be.

Feel free to play around with the code. Experimentation is the best way to learn. Using the color table presented in Table 3.1 as a guide, how would you make the pixel red instead of white?

Note that this first program only included `<vga.h>` and `<stdlib.h>`, and *not* any of the other standard header files, such as `<stdio.h>` and `<stdlib.h>`. That's because every function need for this program is contained within `<vga.h>`. If you're in the habit of blindly including `<stdio.h>` or others, it won't hurt anything. It's just unnecessary.

# ## Viewing Time

If you've run that program, you may have noticed one slight problem. It runs so quickly that you don't have time to see it. By using the `sleep()` function (and including the `<unistd.h>` header file), we can add a delay to make the output viewable. Listing 3.2 shows this code.

Listing 3.2  My first SVGAlib program, with a pause.

```c
#include <stdlib.h>
#include <vga.h>
#include <unistd.h>

int main(void)
{
    vga_init();
    vga_setmode(G320x200x16);
    vga_setcolor(15);
    vga_drawpixel(0, 0);
    sleep(3);
    vga_setmode(TEXT);
    return 0;
}
