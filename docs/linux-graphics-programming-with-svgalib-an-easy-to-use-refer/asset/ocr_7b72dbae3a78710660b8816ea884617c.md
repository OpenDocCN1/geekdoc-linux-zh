the perimeter lines are drawn, the topmost and bottommost points are recorded in **topy** and **boty**, accordingly. Then, the left and right edges of the polygon are recorded for each *y* line. Once you have that information, it's a simple matter of drawing a series of horizontal lines from left extreme to right extreme, starting at the top and continuing to the bottom, as I did here:

```
for (i = topy; i <= boty; i++)
{
    book_drawline(leftmost[i], i, rightmost[i], i);
}
```

This procedure fills your polygon from top to bottom, and the results will look something like what's shown in Figure 11.5. Time to call your agent—you're headed for the big leagues. Hello, Pixar?

# Working With threeDKit

Note that I took the easy way out and described the drawing of a *convex* polygon in the previous examples. What happens, then, if one needs a nonconvex or complex polygon? Do we wait for the gl designers to come up with a new function?

The good news is that it's already been done. The threeDKit is used to draw fast, filled triangles. These triangles can be combined to form any sort of polygon.

The bad news (well, it's not that bad) is that the threeDKit isn't as integrated with SVGLib as one might hope. It's kind of like Cousin Olivier from the television show *The Brady Bunch*: It's a hastily added piece that doesn't quite fit. Unlike vqagl, there's no shared library to go along with threeDKit. This means you'll have to copy the appropriate object and header files from /usr/src/svglib-1.4.0/threeDKit to the directory where your source code is, and then you'll have to include those object files in your compilation command. What's more, because most of the threeDKit files depend on one another, you'll end up including most of them. (Another option would be to create your own shared library, but then you'd run into that same old problem of your code not running on other machines).
