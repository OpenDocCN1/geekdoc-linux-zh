## Moving Beyond gl_circle()

At this point, though, no progress has been made over the original **gl_circle()** function. Let's begin customizing the code by making the circle thicker—something **gl_circle()** can't do. Basically, all you'll be doing is drawing a succession of hollow circles, one inside another. Because they touch at the edges, they'll conglomerate to become one large (thick) circle. (Yes, I know you can execute several **gl_circle()** statements, but this will be all within one function.) Take a look at Listing 4.3 to see how I did it.

### Listing 4.3 A thick circle.

```c
void book_circle(int xc, int yc, int radius, int thickness)
{
    double theta,
        costheta,
        sintheta;
    int degrees,
        i;
    
    for (degrees = 0; degrees < 360; degrees++)
    {
        /* Define PI as 3.14, if your compiler doesn't accept the following line. */
        theta = (PI / 180) * degrees;
        costheta = cos(theta);
        sintheta = sin(theta);
        
        for (i = radius; i > radius - thickness; i--)
        {
            vga_drawpixel(xc + i * costheta,
                yc + i * sintheta);
        }
    }
}
```

Now you've got yourself a big ol' circle, just like the one shown in Figure 4.3. See, we're making progress.

### Filled Circles

You already know that vgaal offers gl_fillbox(), but at this point there’s no equivalent function for circles. Wouldn’t it be nice to fill this emptiness?

Being the clever person that you are, you probably think you can fill in your circles by using the previous formula and making the thickness equal to the radius. That is to say, if your radius is 100 pixels, you should, by accord, be able to color the entire circle by setting the thickness to 100 pixels. Right? ### Listing 4.4 Finally! A filled-in circle.

```c
void book_solid_circle(int xc, int yc, int radius)
{
    double theta,
        costheta,
        sintheta;

    int degrees,
        y,
        old_y = 0;

    for (degrees = 0; degrees < 360; degrees++)
    {
        theta = (PI / 180) * degrees;
        costheta = cos(theta);
        sintheta = sin(theta);
        y = yc + radius * costheta;
        if (degrees > 0)
        {
            while ((old_y - y) > 1)
            {
                old_y--;
                vga_drawline(xc - radius * sintheta, old_y,
                             xc + radius * sintheta, old_y);
            }
        }
        vga_drawline(xc - radius * sintheta, y,
                     xc + radius * sintheta, y);
        old_y = y;
    }
}
```

And there you have it. Note that the **old_y** sections exist solely to account for gaps in the circle (that is, rounding errors). Without that, you could make the code much more compact.

## Faster Circles

In case you’re interested, you can optimize your circle-drawing code to some degree. Listing 4.5 shows how this is done. Truth be known, the method in Listing 4.5 is very similar to the procedure enacted by gl_circle() itself. The philosophy is that you only draw an eighth of your circle and then use equated values to fill in the rest. This may sound convoluted, but your processor likes this procedure better. Let’s have a look.

### Listing 4.5 Faster circle, kill, kill.

```c
void book_faster_circle(int xc, int yc, int radius)
{
    int x,
        y,
        d;

    y = radius;
    d = 1 - radius;

    for (x = 0; x < y; x++)
    {
        if (d < 0)
        {
            d += x * 2 + 3;
        }
        else
        {
            d += x * 2 - y * 2 + 5;
            y--;
        }

        vga_drawpixel(xc + x, yc + y);
        vga_drawpixel(xc - x, yc + y);
        vga_drawpixel(xc + x, yc - y);
        vga_drawpixel(xc - x, yc - y);
        vga_drawpixel(xc + y, yc + x);
        vga_drawpixel(xc - y, yc + x);
        vga_drawpixel(xc + y, yc - x);
        vga_drawpixel(xc - y, yc - x);
    }
}
```

In addition to being faster, this method benefits from not needing to work with sine and cosine values (that is, it doesn’t need <math.h>). I didn’t use Listing 4.5 first because the other examples are probably easier to understand, conceptually speaking—they don’t involve eight simultaneous plots. Furthermore, the format of the original examples tie in with many of the following examples, so it was good to get them into the mix right away.

Regarding the formula itself, remember that **xc** and **yc** refer to the center point of the circle, and x and y are assigned values by the function. For speed, replacing **vga_drawpixel()** with **gl_setpixel()** will make this function faster yet. For further study, I suggest you get a copy of Michael Abrash’s *Zen of Graphics Programming*, also published by The Coriolis Group, in which he describes this technique in detail.
