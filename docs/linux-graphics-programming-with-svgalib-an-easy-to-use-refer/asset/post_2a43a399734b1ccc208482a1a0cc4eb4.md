
# Appendix G
## FAQs And Troubleshooting

Contrary to popular belief (primarily amongst newbies), SVGAlib doesn't provide any debugging tools at this time. Perhaps you've become accustomed to more advanced programming environments that instantly detect syntactical errors as they're being typed, much in the same way that several modern word-processing programs systematically check for mistakes in spelling and grammar. However, you'll find no such luxuries here. If your application doesn't execute or is running improperly, it's up to you to determine the root cause of the problem. Because SVGAlib programs are written like every other C program on Linux (that being with a simple, unintelligent text editor such as pico or vi), you'll likely need to do some debugging at one time or another.

Don't despair, however, because this deficiency isn't nearly the insurmountable challenge that it might first appear to be. You've got several resources at your disposal, and many of them are listed here. For starters, it's highly probable that the error you've experienced has crept up sometime in the past. Therefore, this next section will cover several common problems that beginners have experienced and routinely post to USENET, mailing lists, and message boards.

### FAQs

Q: When I try to run my application, I receive this error:

```
svgalib: Cannot get I/O permissions
```

**A: SVGAlib applications must be run as root, or setuid root.** So, although one of the major advantages of SVGAlib is its ability to write directly to the VGA card, this advantage is offset by the fact that direct hardware access under Linux requires root privileges.

To make a program setuid root, you must perform the following steps:

1. Log in as root.
2. Ensure that the program in question is *owned* by root. If it’s not, it will become setuid user, where user is the non-root owner of the program. This is an important step, and it’s where a lot of people make mistakes.
3. Type the following to make the program setuid root:

```
chmod u+s <program>
```

If all goes well, an `ls -al` listing should reveal something like the following:

```
-rwxr-xr-x  1 root    root    29710 Nov 17 06:04 program*
```

Notice that the first `x` has been replaced with an `s`. However, this next program is only setuid tim, because it’s not owned by root:

```
-rwsr-xr-x  1 tim     users     29710 Nov 17 06:04 program*
```

Q: When I try to run my application, I receive this error:

```
Not running in a graphics capable console, and unable to find one
```

A: In addition to the setuid requirement, SVGAlib normally mandates that all programs be run from a physical Linux console. If, however, you attempt to run a program via a Telnet session or from within an xterm, SVGAlib may try to open a virtual console for you (provided this option was selected at compilation time). Because virtual consoles can only be opened by root and/or the owner of the console device (typically root as well), nonroot users operating in this manner will receive this error message.

> **Note**
> If you’re running an SVGAlib application from an xterm, you may need to recompile SVGAlib with `ROOT_VG_SHORTCUT` defined. See Chapter 1 for help on changing options when compiling SVGAlib.

Q: When I run my program, all I get is the following message:

`[svgalib: allocated virtual console #7]`

Why don't I see any graphics?

A: As stated previously, SVGAlib won't display output over a Telnet session. If you're not at an actual console, you'll receive this message.

Q: I'm having trouble compiling my program. I keep getting the message `undefined reference to 'vga_init'` and several others like it.

A: You have forgotten to link your program to SVGAlib (libvga and libvgal). Your compilation command should resemble (at a minimum) the following:

`gcc -o program program.c -lvgal -lvga`

See Chapter 2 for a more in-depth examination of compiling programs with SVGAlib.

Q: My video card is listed as being supported, yet SVGAlib doesn't seem to work.

A: Make sure you're using the latest release of SVGAlib—many Linux distributions come with outdated versions. Also, you might want to have a look at the latest *developmental* release, because it may contain some changes to your chipset's driver as well.

Finally, be sure that the problem is indeed with SVGAlib, and not with the program that you're trying to run. You can determine this by running `vgatest`, one of the SVGAlib demo programs.

Q: My card is supported, but some modes do not work.

A: Using `vgatest`, check to see whether the problem is with SVGAlib or the program you've attempted to run. Then, report your results to the appropriate person.

Q: My card works with the VESA driver, but text mode is not properly restored.

A: This can often be solved by adding the line

`VesaText`

to the config file (usually `/etc/vga/libvga.config`).

Q: When will a driver for my card be written?

A: When someone who owns the same type of card writes one. See Chapter 20 for some advice on writing graphics drivers.

Q: Why does my program terminate immediately with the following message?

```
svgalib: mmap error in paged background memory
```

A: SVGAlib's implementation of background execution relied on a kernel feature (mmapping `/proc/self/mem`) that was removed in version 2.3.27 of the Linux kernel. If you're using that kernel (or later), you'll need to recompile SVGAlib without background execution support.

To do this, edit `Makefile.cfg` and comment out the line

```
BACKGROUND = Y
```

so that it reads like this:

```
#BACKGROUND = Y
```

Q: My program contains a `gl_hline()` command that produces no output. Why is this?

A: Check to see whether your horizontal line runs from left to right. If not, change it. SVGAlib won't allow a right-to-left `gl_hline()`; older versions will segfault, and newer versions simply do nothing.

> **Note**
> *A segfault is a segmentation fault.*

Q: My program using vgaqsl aborts immediately with a segmentation fault. Why is this?

A: Check to see if you've remembered to call `gl_setcontextvga()` after `vga_setmode()`.

Q: The colors in a particular application seem especially dark.

A: If you're the author of the application in question or if you have access to the source code, you can adjust the palette to make the colors brighter. Otherwise, you can try increasing the brightness on your monitor. If you're running a precompiled (binary only) commercial application, you may be out of luck, unless you alter SVGAlib itself.

The following code example will double the intensity of your colors, provided your application is set to run in at least a 15-bit (32K) screen mode.

```c
for ( i = 0; i < 256; i++ )
{
    vga_setpalette( i, 255 - ((255 - i) / 2),
                    255 - ((255 - i) / 2),
                    255 - ((255 - i) / 2) );
}
```

See Chapter 5 for a complete discussion regarding color palettes.

Q: How is "SVGAlib" pronounced?

A: The first part of the name is enunciated letter by letter, just as it looks: S-V-G-A. The next part, "lib", is short for "library", and thus rhymes with "tribe". Many people choose to pronounce "lib" in the same manner as "ad-lib", however, and that has become acceptable as well.

### Additional Help

If the preceding section didn't answer your question, feel free to utilize the following resources:

- For questions regarding hardware, setup, and drivers, visit the message board at www.svgalib.org.
- For questions involving programming, write to the mailing list at linux-svalib@vger.rutgers.edu.
- As a last resort, you can contact the maintainer directly at maintainer@svgalib.org.
