Color is of such monumental importance to our lives that it’s hard to imagine a world without it. From clothing to traffic signals to advertisements to food, color dictates who we are and what we do. We use color to differentiate objects, to appraise goods, to warn, to communicate, to mark, and to judge. The list goes on and on.

It goes without saying that color is a vital element of perception, even with computers. Studies have shown that the human eye detects movement first, followed closely by silhouette and then color. Certainly, life without color would be difficult. Even the blind must compensate for their disability if they are to function within the confines of our society. Color is everywhere.

In this chapter, I’ll go over what color is and how it can be used effectively in your applications. You’ll learn how to alter the basic colors that SVGAlib gives you as well as create individualized palettes that can help set your programs a notch above the rest. Remember that color, and graphics by extension, are very valued in today’s society: After all, the introduction of the Apple Macintosh effectively spelled the demise of MS-DOS (not to mention what TV did to radio). Although it’s true that many users prefer the text-only environment that standard Linux provides, even that basic interface uses many different colors to highlight special files. Color makes things interesting, and its power can’t be ignored.

### What Is Color?

So what is color? We can define color as being a component of light. As light enters the visible spectrum, it’s generally split into multiple hues. Note here that color is a perceived quality, not an absolute. Something that appears to be one color under certain conditions can actually be another, and two people might have differing ideas on what exact hue best describes an object. Confusion is compounded when viewers are situated in different locations. The physical aspect of light is measured in a spectral power distribution, or SPD, but color itself exists only in our eyes and minds.

In the human-visible portion of the light spectrum, we notice that three colors are stronger than the rest: red, green, and blue. Our perception of these three colors as dominant may stem from the fact that our retinas contain three different types of photoreceptor cone cells. It could be that we’re alone with this vision; other animals might perceive colors differently. Regardless, it’s possible to describe any color we can see by giving it three values—one each for red, green, and blue.

> **Note**
> The system of using three values to describe a color was first introduced by the Commission Internationale de l’Eclaire in 1931.

### Why Red, Green, And Blue?

This three-value system provides the basis for modern video displays. We know that black is the absence of color, white is all three colors at full intensity, and every other shade is some combination in between. But how, exactly, does this color system work?

When I began using computers, I was puzzled at the choice of having green as one of the three primary colors for displays. “Something seems amiss,” I thought. Everyone knows that the three primary colors are red, blue, and yellow. If you want green, you just mix yellow with blue, right? I couldn’t understand how any combination of RGB could produce yellow, or any other lighter shade. And how can they all combine to form white?

The answer is simpler: I was using the wrong system! Red, blue, and yellow are the three primary colors of *paint*, whereas red, green, and blue are the three primary colors of *light*. And light is what we’re dealing with.

> **EGA**
> Enhanced Graphics Adapter. This was IBM’s 16-color predecessor to the VGA card. EGA required a monitor capable of doing its own digital-to-analog conversion. Compare this to VGA, which has onboard DAC conversion.

Splitting white light with a prism.

Pure light is white, and you get colors by splitting it. Then, as if by magic, reuniting the split colors forms white again. Figure 5.1 shows how a prism separates white light into multiple hues, forming the basis for this color theory (and a Pink Floyd album cover).

Your monitor is the opposite of a prism; it takes three distinct colors and combines them.

### Color In SVGAlib

I'm sure you're eager to move on to some real-world examples, so let's begin. You've seen SVGAlib's 16- and 256-color modes demonstrated in the previous two chapters—we simply used `vga_setcolor()` and entered a numeric value from 0 to 15 or 0 to 255. The results should have been familiar; most computers use the same basic 16 colors. (This is presumably because they're the standard EGA colors.) However, starting with the 256-color modes, shades numbering over 16 vary from one platform to another. For example, color 192 is going to be different on a Macintosh than it is on a PC. This variance gives rise to the complaint that SVGAlib's colors are too dark. This is easily explained—some ported programs haven't had their colors adjusted to match the SVGAlib palette. So, any unintentionally dark colors can be attributed to programmer laziness, ignorance, or indifference, and not to any fault on the part of SVGAlib.

There's no excuse for dark colors when we can fix the situation. The next new function, `vga_getpalette(int index, int *r, int *g, int *b)`, gives the current RGB values for every standard color in SVGAlib. Simply insert the color number you're interested in, followed by pointers to the values for red, green, and blue. Have a look at Listing 5.1 for an example of `vga_getpalette()` in action.

#### Listing 5.1 Getting the RGB values of color 3 (cyan).

```c
#include <stdio.h>
#include <stdlib.h>
#include <vga.h>

int main(void)
{
    int r,
        g,
        b,
        *pr,
        *pg,
        *pb;

    pr = &r;
    pg = &g;
    pb = &b;

    vga_init();
    vga_setmode(64x480x16);    /* one of the many 16 color modes */

    vga_getpalette(3, pr, pg, pb);

    printf("Red - %d, green - %d, blue - %d\n", r, g, b);

    return 0;
}
```

If you compile and run the code in Listing 5.1, you'll get the following output:

```text
Red - 0, green - 42, blue - 42.
```

> **Note**
> Note that nothing is actually drawn in this example, so the use of `vga_init()` isn't absolutely necessary. Nor is it necessary to return to text mode. However, including `vga_init()` doesn't hurt anything, and using it is a good habit to get into.

Now, what can you do with this information? First of all, note that these RGB numbers are in a 64-shade scale (0 to 63). Therefore, you can infer that cyan uses no red, but instead contains equal portions of green and blue at approximately two-thirds of their full intensity. Cyan is a light blue color, but let's say you want it to be lighter. You can use `vga_setpalette(int index, int r, int g, int b)` to change the RGB values of color 3. Suppose you want to advance the green and blue values to 50? Let's do this in Listing 5.2.

#### Listing 5.2 Partial code for changing the value of EGA color 3.

```c
vga_setmode(64x480x16);
}

vga_setpalette(3, 0, 50, 50);
```

Now cyan no longer exists; color 3 has been redefined, and it will stay that way until the program exits or until the values are reset.

> **Note**
> Note that these palette commands are only applicable in 16- and 256-color modes. That's because they work in conjunction with `vga_setcolor()`.

You can now go ahead and change every color value, if you want. However, be aware that all functions that use a color index will now use your new colors, including `vga_setgacolor()`. You may want to save the old values for each color in case your program ever needs to go back to the defaults.

> **Warning**
> Not only is color 0 black, it's also the background color. Therefore, changing it will also change the background.

Color 0 is a special color. Not only is it black, it's the color of the background. By altering it, you also change the color of the background. Although this might be disastrous if done unintentionally, it does serve as a great way to quickly alternate background colors. If you find the need to use black again (while using a custom colored background), you might be able to change another value to be black. This is an especially useful solution in 256-color modes, where it's unlikely that you'll need all 256 colors simultaneously.

Let's take a look at Listing 5.3, which demonstrates how you can change the background color by setting color 0 to red.

#### Listing 5.3 I see a black screen and I want it painted red.

```c
#include <stdlib.h>
#include <vga.h>

int main(void)
{
    int a;

    vga_init();
    vga_setmode(G640x480x16);
    vga_setcolor(15); /* Drawing color is white */

    vga_setpalette(0, 63, 0, 0); /* Color 0 is now red, and
                                   so is the background */

    for (a = 50; a < 150; a++)
    {
        vga_drawline(10, a, 630, a); /* white rectangle */
    }
}
```
