you'll need to do is move your source file into SVGAlib's `src` subdirectory and then add it to the list of modules in the Makefile (also in the `src` subdirectory—not the main Makefile). The section you need should look like this:

```
MODULES = vga.o \
        vgsadraw.o vgaclear.o vgaline.o vgapis.o \
        vgapal.o vgacon.o vgamodesel.o vgamisc.o \
        vgadump.o vgamonvplanner.o vgacell.o \
        timing.o vgregs.o interface.o accel.o \
        vgabpague.o vgapit.o vgapci.o
```

You can insert your file in behind `vgapci.o`. Then, include all your function declarations in `/usr/include/vga.h` (or create your own file). Just remember to reference any header files that you create.

Finally, compile SVGAlib as usual.

# ## Conclusion

SVGAlib and vgagl have a wide assortment of commands for you to use. Nevertheless, you'll find times when no “canned” function is available to fit your needs—meaning you'll have to concoct your own. This may sound like a daunting task at times, but if a dullard like me can do it, surely you can too. There's no reason to let a lack of prewritten functions slow you down.

This chapter has provided you with a number of examples on how to forge your own shape-drawing routines. From circles to arcs to ellipses, there's a huge number of variations to be drawn on these basic themes. Furthermore, just about any book on graphics and/or geometry can help you learn the theory behind shapes, which you can then apply to SVGAlib. Mostly, all you need is confidence and imagination to be able to craft the tools you need.

If you happen to come up with something really good, feel free to submit it to the current maintainer of SVGAlib (**maintainer@svgalib.org**) for possible inclusion in the next distributed version. That's how the library develops and grows, after all. We're all self-appointed, and everyone is welcome to participate. That's the spirit of Linux.
