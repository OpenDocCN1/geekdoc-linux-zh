
## Words From The Man Page

The joystick module is basically independent from the rest of SVGAlib. You can easily use it in text mode only, but there's no benefit to doing that. If used in a graphics mode, however, it will release the joystick devices upon a VC switch so that several applications can share joysticks. Unfortunately, this doesn't work during joystick calibration. Therefore, you should lock the VC with `vga_lockvc()` while calibrating in graphics mode.

Also, when using joysticks in text mode only, SVGAlib won't detect VC switches and joysticks cannot be shared among applications.

Similar to working with the mouse, you can open, update, and close the joystick with the following three commands:

- `joystick_init(int joydev, __joystick_output jp)`
- `joystick_update(void)`
- `joystick_close(int joydev)`

Listing 15.6 shows these functions in the context of a real program. Notice the similarities to the mouse functions already shown. However, because the joystick is largely independent of SVGAlib, you can initialize it before you call `vga_init()`.

The first argument to `joystick_init()`——`joydev`——should be a number from 0 to 3. The implication is that you can have multiple joysticks operating simultaneously, but Linux can only handle two at the present. (Whoops.) It's also recommended that you use `JOY_CALIB_STDOUT` (defined in `vgajoystick.h`) for the second argument.

### Listing 15.6 Joystick basics.

```C
#include <stdlib.h>
#include <vga.h>
#include <vgajoystick.h>

int main(void)
{
    int joydev = 0;

    if (joystick_init(joydev, JOY_CALIB_STDOUT) < 0)
    {
        exit(1);
    }

    vga_init();
    vga_setmode(G640x480x256);

    while ((key = vga_getkey()) != 27)
    {
        /* Press 'ESC' to exit. */
        joystick_update();

        /* Put the 'meat' of the program here */

    }

    vga_setmode(TEXT);
    joystick_close(joydev);

    return 0;
}
```

To begin checking for events, use `joystick_getaxis(int joydev, int a)` and `joystick_getbutton(int joydev, int b)`. Remember that the values returned from these functions are only as recent as the last time `joystick_update()` was called. Therefore, you should call `joystick_update()` fairly often.

For the x-axis in `joystick_getaxis()`, argument a should be 0. For the y-axis, use 1. Your return value will be in the range of -128 to 127. Remember, this doesn’t give you an absolute position like `mouse_getx()` or `mouse_gety()` does, but rather it returns the state of the joystick itself (that is, how far it’s bent). It’s up to you to actually place the “cursor.”

Next, `joystick_getbutton()` returns a 1 for a pressed button and a 0 otherwise. To use this function, you’ll need to pass the button’s assignment number as an argument, along with the value of `joydev`. The buttons themselves are numbered 0 through 3 because, like everything else in Linux, numeric sequences start with 0.

For example, you can use the following code to determine whether or not the first button has been pressed:

```
if (joystick_getbutton(joydev, 0) == 1)
{
    /* Button has been pressed */
}
```

## Background

In order for you to gain an understanding of how this all works, it becomes necessary to return to the befuddling and mystically seductive world of fractals. As you'll recall from Chapter 8, fractals are images produced from equations. Specifically, they're not produced from just any old equation but rather formulas involving the square root of -1. As Mandelbrot himself so eloquently phrased it, “A fractal is a set whose Hausdorff-Besicovitch dimension is strictly greater than its topological dimension.” (Is it any wonder why I was rejected from all the really good schools?)

If you haven't guessed already, computer-generated topographies bear much in the way of resemblance to the two-dimensional fractals discussed in Chapter 8.

## Random Fractal Forgery

Coined by Richard F. Voss of IBM's Thomas J. Watson Research Center, this term refers to the seemingly realistic depictions of natural objects that can be generated with simple algorithms. These algorithms are distinguished by their use of randomness and fractal self-similarity.

## A Brief History Of Artificial Landscapes

As with many great inventions, the discovery of the landscape techniques presented here was by and large an accident. At some point, it was noticed that a combination of subdivision and random perturbation of a line creates an image that somewhat resembles a distant mountain ridge. The principle isn't altogether different from Koch's Snowflake (see Chapter 8), and if you look at Figures 16.2 through 16.4, you'll see a good example of the process in action.

A line is broken into two sections, and the midpoint is raised or lowered according to a random value. Then, each of the resultant two lines is broken and displaced in the same manner. You can repeat this cycle over and over until you've run out of space (of course, you can't subdivide a single pixel!), but all it usually takes is three repetitions to achieve the desired effect.

This exercise is good for demonstrating the principle, but it's not very inspiring. What you need is some depth.
