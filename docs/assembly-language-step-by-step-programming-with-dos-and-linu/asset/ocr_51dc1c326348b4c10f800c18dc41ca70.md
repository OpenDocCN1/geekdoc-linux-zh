# Closing the Outer Loop

But does that mean JCXZ closes the outer loop? No. JCXZ tells us when both loops are finished. The outer loop does a little different from closing the inner loop. Take another look at the two nested loops:

```
DoLine: mov BL, LineLen ; Each line will consist of 64 characters
DoChar: stos ; Note that there's no REP prefix;
    jcxz AllDone ; When the full set is printed, quit
    inc AL ; Bump the character value in AL up by 1
    dec BL ; Decrement the line counter by one
loopnz DoChar ; Go & do another char until BL goes to 0
    add DI, (ScnWidth - LineLen)*2 ; Move DI to start of next line
    jmp DoLine ; Start display of the next line
```

The inner loop is considered complete when we've displayed one full line of the ASCII table to the screen. BL governs the length of a line, and when BL goes to zero (which the LOOPNZ instruction detects), a line is finished. LOOPNZ then falls through to the instruction that modifies DI.

We modify DI to jump from the end of a completed line to the start of the next line at the left margin. This means we have to “wrap” by some number of characters from the end of the ASCII table to the end of the visible screen. The number of bytes this requires is given by the assembly-time expression (ScnWidth-LineLen)*2. This is basically the difference between the length of one ASCII table and width of the visible screen. Multiplying by 2 is done because each character position is actually represented by a character and an attribute byte in the video refresh buffer. The result of the expression is the number of bytes we move into the video refresh buffer to come to the start of the next line at the left screen margin.
