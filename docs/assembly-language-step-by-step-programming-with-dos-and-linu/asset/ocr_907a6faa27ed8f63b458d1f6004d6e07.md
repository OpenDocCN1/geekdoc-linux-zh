# Register Halves

The same is true for the other four general-purpose registers EAX, EBX,
ECX, and EDX, but there's an additional twist: the low 16 bits are them-
selves divided into two 8-bit halves. So, what we have are register
names on two but three levels. The 16-bit registers AX, BX, CX, and
DX are present as the lower 16-bit portions of EAX, EBX, ECX, and EDX.
But AX, BX, CX, and DX are themselves divided into 8-bit halves, and
assemblers recognize special names for the two halves. The A, B, C, and
D are retained, but instead of the X, a half is specified with an H (for
high half) or an L (for low half). Each register half is 1 byte (8 bits) in
size. Thus, making up 16-bit register AX, you have byte-sized register
halves AH and AL; within BX there are BH and BL, and so on.

Again, this can best be shown in a diagram. See Figure 6.7. As I men-
ed earlier, one quirk of this otherwise useful system is that
there is no name for the high 16-bit portion of the 32-bit registers.
in other words, you can read the low 16 bits of EAX by specifying AX in
assembly language instruction, but there's no way to specify the high 16
bits by themselves. This keeps the naming conventions for the registers
a little simpler (would you like to remember EAXH, EBXH,
ECXH, and EDXH on top of everything?), and the lack is not as felt
of you might think.

One thing about the 8-bit register halves is that you can read and
change one half of a 16-bit number without disturbing the other half.
Means that if you place the word-sized hexadecimal value 76E9H
into register AX, you can read the byte-sized value 76H from register
AH, and 0E9H from register AL. Better still, if you then store the value
0AH into register AL and then read back register AX, you'll find that the
original value of 76E9H has been changed to 760AH.
