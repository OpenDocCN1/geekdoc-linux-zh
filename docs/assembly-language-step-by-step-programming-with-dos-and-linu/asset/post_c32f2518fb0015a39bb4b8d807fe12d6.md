## Moving Around the Edit Window

When you're in NASM-IDE and an assembly language source code file is displayed in an edit window, any characters you type on the keyboard will be inserted into the file and displayed on your screen. You can move the cursor around within the current file using any of a number of cursor movement keys.

The easiest to remember are the PC's cursor keypad keys. The four arrow keys will move the cursor one character position in the arrow points. The PgUp key will move the cursor up one page (that is, the size of your text screen; typically 25, 43, or 50 lines depending on how you set it up—more or shortly) whereas PgDn will move the cursor one page down. The Home key will move the cursor immediately to the left margin, and the End key will move the cursor immediately to the end of the current line. (The end of the line is defined as the character after the rightmost nonblank character in the line.)

There are numerous cursor movement keys that you can use within JED. I describe them all in detail later in this chapter. You can also zoom on a particular location in the file by clicking on a character with the mouse. The cursor will move immediately to the point at which you clicked. You can use the mouse to slide up and down within the file by clicking on the “thumb” of the scroll bar on the right-hand edge of the edit window, and dragging the thumb up or down. (The thumb is a small rectangle set into the scroll bar.)

Take a few moments scooting around inside EAT2.ASM until you feel comfortable with it.

## Making Changes to the File

The simplest way to change the file is simply to type something at the keyboard. All such characters will appear at the cursor, and the cursor will move one position to the right for each character.

You can insert a new line beneath the current line by pressing Enter.

Getting rid of unwanted text is as important as adding new text. Deleting one character at a time can be done by moving the cursor to the immediate right of the offending character, and simply using the backspace key to back the cursor over it. The character will disappear. You can also place the cursor to the left of the text you want to delete, and then press the Del key for each character to be deleted. To the right of the cursor will be pulled in toward the left as characters disappear.

You can delete an entire line by placing the cursor on the line and pressing Ctrl-Y. This can be done too easily by accident, and lose a line that you may or may not have in your head or written down on paper. Be careful!

NASM-IDE contains several other ways to delete text, all of which will be described later in this chapter. For the sake of the current guide through NASM-IDE, move the cursor to the blank line beneath EAT2.ASM's comment header (line 9 in the file) and type the phrase "MOV ax,bx." That done, press Enter and add a new line beneath it.

## Saving Changes to a File

As they say in Chicago, that grand old (cold) town where I grew up, "Vote early and often. The same philosophy applies to saving the changes you make to your current file within NASM-IDE. Every so often, when you kick back in your chair to think for a bit, save your work. It's easy: one keystroke, the function key F2. There's no visible indicator that anything's happening, but pressing F2 will save your file in its entirety back to the place you loaded it, wherever that might be on your system.

Get in the habit of pressing F2 once in a while. Keep in mind that if you save your work every five minutes, you will never lose more than five minutes of work!

NASM-IDE keeps an eye on things and does its best level to keep you from losing any of your work. If you try to exit NASM-IDE without saving your file to disk, it will remind you with the dialog box shown in Figure 5.3.

Before it exit back to DOS, NASM-IDE will require some response from you. If you click on the green button reading "Yes," NASM-IDE save your work to disk, just as though you had pressed F2. Clicking on the button reading “No” will allow you to exit NASM-IDE without saving your work—and any changes you made that you have not saved will be lost. Finally, if you click on the button reading “Cancel,” the command will be cancelled, and nothing will happen. Your work will not be saved, nor NASM-IDE will exit back to DOS.

If you don't have a mouse, you can press Enter to select “Yes,” which is the default option for this dialog box. (NASM-IDE gives you every opportunity to lose your changes!) If you want to move to one of the other buttons but don't have a mouse, you must use the Tab key to bounce from one button to another. The buttons will change when they are selected: The text after the initial character of the button labels will be in white after yellow. The three buttons cycle, so if you tab right the button you want, press it a few more times and you will get back to your chosen button. Then when you press Enter, that button will be clicked and the appropriate action taken.

## Assembling the Current File

If you're satisfied that you understood all the various NASM-IDE features I've described so far on this tour, it's time to assemble EAT2.ASM and make an actual runnable program out of it. Press function key F9. NASM-IDE will invoke the assembler behind the scenes. You won't see anything to indicate it on your screen; NASM-IDE will remain there as always.

However, assuming you did what I told you earlier and typed some text at line 9 of EAT2.ASM, the screen will split horizontally and a new window will be displayed beneath the text window containing EAT2.ASM. This window has the title "Error Information" and will look a lot like Figure 5.4.

If you recall, you made a change to EAT2.ASM a little earlier by typing the phrase "MOV ax,bx" mnemonic—on line 9. This phrase is something like assembly language—only something, and in the form I gave it to the assembler NASM will have no idea what to do with it. So, NASM dutifully complained in the form of an error message. You can see this error message in Figure 5.4. When NASM tells you "Parser: Instruction Expected" that means what it got in the line it paused at was not an instruction. You inserted an error into EAT2.ASM here because no instruction in the 86-family instruction set is named MVO. This may not prevent your fevered fingers from transforming MOV (which is a legal instruction) to MVO in the furious passion of creation—or under the influence of the caffeine shocks.

The error information window will remain on the screen until you close it, which you can do by clicking on the close control at the upper-left corner of the window. And until you fix the error you inserted into EAT2.ASM, that's as far as we can go here.

Fixing it, however, is easy. NASM-IDE is reasonably smart and has placed the cursor right where it thinks the error is in the edit window.
