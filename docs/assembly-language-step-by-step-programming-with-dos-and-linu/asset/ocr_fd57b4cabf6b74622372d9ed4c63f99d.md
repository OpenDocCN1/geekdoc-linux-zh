This is a pretty obnoxious collection of bits to remember or manipulate, so let's split it into groups of four from the right:

```
1111 0000 0000 1111 1010 0110
```

Each of these groups of four binary digits can be represented by a single hexadecimal digit. Do the conversion now. What you should get is the following:

```
1111 0000 0000 1111 1010 0110
F 0 0 0 F A E
```

In other words, the hex equivalent of that handful is

```
F000FA6E
```

In use, of course, you would append the $H$ on the end, and also put a 0 at the beginning, in any kind of assembly language work the number would actually be written 0F00FA6EH.

This is still a good-sized number, but unless you're doing things counting hard high-value things, 32-bit numbers are the largest quantities you would typically encounter in journeyman-level assembly language programming.

Suddenly, this starts starts a little more graspable.

Hexadecimal is the programmer's shorthand for the binary numbers.

This is why I said earlier that computers use base 2 (binary) and base 16 (hexadecimal) both at the same time in a rather schizoid fashion. I didn't say that the computer isn't really the schizoid; you are. At their very hearts (as I explain in Chapter 3) computers use only binary. Hex is a means by which you and I make dealing with the computer easier. Fortunately, every four binary digits may be represented by a hex digit, so the correspondence is clean and comprehensible.
