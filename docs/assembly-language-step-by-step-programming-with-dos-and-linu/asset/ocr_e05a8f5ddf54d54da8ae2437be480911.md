# Protected Mode Flat Model

Intel’s CPUs have implemented a very good protected mode architecture since the 386 appeared in 1986. However, application programs cannot use of protected mode by themselves. The operating system must set up and manage a protected mode before application programs can use it. MS-DOS couldn’t do this, and Microsoft Windows couldn’t do it either until NT first appeared in 1994.

Other protected operating systems have since appeared. The best known is probably Linux, the implementation of Unix written from scratch by a young Finnish college student during the first half of the 1990s. NT and Linux are vying for the same general market, while NT will probably remain the market leader for years to come, Linux is showing strength for something that no one organization actually owns in the strictest sense of the word.

Protected mode assembly language programs may be written for Windows NT and Linux. The easiest way to do it under NT is create console applications, which are text-mode programs that run in a text-mode window called a console. The console is controlled by a command line almost identical to the one in MS-DOS. Console applications use protected mode flat model and are fairly straightforward compared to writing Windows applications. The default mode for Linux is a text console, so it’s easier to create assembly programs for Linux, and a more people appear to be doing it. The memory is very much the same.

I’ve drawn the protected flat model in Figure 6.10. Your program sees a single block of memory addresses running from zero to a little over 4 gigabytes. Each address is a 32-bit quantity. All of the generalpurpose registers are 32 bits in size, and so one GP register can point to any location in the full 4-GB address space. The instruction pointer is 32 bits in size as well, EIP can indicate any machine instruction-where in the 4 GB of memory.
