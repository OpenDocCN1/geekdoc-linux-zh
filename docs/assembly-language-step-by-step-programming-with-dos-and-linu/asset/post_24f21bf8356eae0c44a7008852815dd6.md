## Yet Another Lookup Table

The lookup table named Digits (used by Byte2Str and Word2Str in the previous section) is so obvious that it didn't need much in the line of comments or explanations. Digits simply converted the table's index into the ASCII character equivalent to the value of the index. Digits is only 16 bytes long, and its contents pretty much indicate what it's for:

```
Digits DB '0123456789ABCDEF'
```

Most of time, your lookup tables will be a little less obvious. A lookup table does not have to be one DB variable definition. You can define it pretty much as you need to, either with all table elements defined on a single line (with Digits) or with each table element on its own line.

Consider the following lookup table:

```
OriginTbl DW 0B00H ; Code 0: No adapter identified
DW 0B00H ; Code 1: MDA
DW 0800H ; Code 2: CGA
DW 0B00H ; Undefined
```

Here's a tale in which each element has its own DW definition statement on its own line. This table treats a problem connected with the numerous different kinds of display adapters installed in a PC. There are two different addresses where the video refresh buffer begins. On boards connected to color/gray monitors, the address is B800:0000, whereas on monochrome monitors, the address is B000000. (Refer back to Figure 6.11 and the accompanying text if you've forgotten what the video refresh buffer is.)

If you intend to access video memory directly (and doing so is much faster than working through DOS as we have been), then you have to know which at the video refresh buffer lies. Knowing which display adapter is installed is the hardest part—and the DisPID procedure in the previous section answers that question. Each of the nine codes returned by DisPID has a refresh buffer address associated with it. But which goes with which? You could use a long and interwoven series of CMP and JE tests, but that's the hard road and is grossly wasteful of memory and machine cycles. A lookup table is simpler, faster in execution, and much easier to read and understand.

The following routine uses the OriginTbl lookup table shown previously to return the segment portion of the video refresh buffer address in AX. OriginTbl must be present in the data segment, and the display adapter code must be passed to VidOrg in AL:

## Using Shift Instructions to Multiply by Two

To use shift instructions, expressing a number (that is, in binary), shifting the binary pattern one bit to the left, and then to decimal or hex. Like so:

```
00101001 Binary equivalent of 35H, 53
01101010 Binary equivalent of 6AH, 106
```

Sharp readers may have guessed that shifting to the right divides by powers of two—and that's also correct. Shifting right by one divides by 2; shifting right by two bits divides by 4, and so on.

The advantage of multiplying with shift instructions is that it's fast. Even on the oldest and slowest CPUs, shifting a byte-sized value in a register to the left by one bit *only two cycles*—as opposed to 7 (on those older machines) with MUL. And MUL can do not better than 13 cycles on the newest Pentium-class processors.

As we say, no contest.
