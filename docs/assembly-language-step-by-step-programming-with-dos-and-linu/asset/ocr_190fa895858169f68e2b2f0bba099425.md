What doesn’t change from DOS version to DOS version is the number of the interrupt that holds a particular address. In other words, since the PC first began, interrupt 21H has pointed the way into darkest DOS’s services dispatcher, a sort of multiple-way switch with spurs heading out to the many (over 50) individual DOS service routines. The address of the dispatcher has changed with every DOS version, regardless of version, programs can find the address of the dispatcher in slot 21H of the interrupt vector table.

Furthermore, programs don’t have to go snooping the table for the address themselves. the x86 CPUs include a machine instruction that makes use of the interrupt vector table. The INT (Interrupt) instruction is used by EAT.ASM to request the services of DOS in displaying two strings on the screen. At two places, EAT.ASM has an INT 21H instruction. When an INT 21H instruction is executed, the CPU goes down to the interrupt vector table, fetches the address from slot 21H, and jumps execution to the address stored in slot 21H. The DOS dispatcher lies at the address in slot 21H, the dispatcher gets control of the machine and does what it knows how to do.

The process is shown in Figure 8.4. When DOS loads at boot time, one of the many things it does to prepare the machine for use is put correct addresses in several of the vectors in the interrupt vector table. One of these addresses is the address of the dispatcher, which goes into slot 21H.

Later on, when you type the name of your program MYPROG on the DOS command line, DOS loads MYPROG.EXE into memory and gives control of the machine. MYPROG.EXE does not know the address of the DOS dispatcher. MYPROG.EXE knows that the dispatcher’s address will always be in slot 21H of the vector table, so it executes an INT 21 instruction. The correct address lies in vector 21H, and MYPROG is to remain ignorant and simply let the INT 21 instruction and vector 21H take it where it needs to go.
