

# 前言

时光流逝。就在恰好10年前的这个夏天，也就是1989年7月，我交出了一本名为《从零开始的汇编语言》（Assembly Language from Square One）的手稿。那本书很受欢迎，但它的出版商在面世几个月后就倒闭了。这可能是一种幸运，因为那本书太短了，错误也比该有的多，而且印在糟糕的廉价纸上，稍微一用力就会撕裂，现在已经变黄了。

于是，我抓住机会重写这本书，并由一家真正的出版社出版——即最受尊敬的约翰·威利父公司（John Wiley & Sons，正如他们的T恤上写的，自1902年以来一直非常棒）。新书经过了彻底的改写，成为一本新标题的新书，并于1992年9月上架。时光流逝，但在计算机书籍的寿命可能只有八个月或更短的世界里，威利让《汇编语言步步阶》（Assembly Language Step-by-Step）从1992年到2000年持续出版了八年。

在那段时间里，它的销量可能超过了任何其他汇编语言书籍，我收到了数百封关于建议、纠正、反馈以及简单的“这是送给你的！”的赞美信。感谢大家抽出时间写信，这对我来说意义重大。我不清楚这第二版如何保持印刷热度，但只要人们继续购买（并告诉我这对他们很有用），我怀疑这个版本或后续版本将一直持续供应。

时光流逝。在进入正文之前，我有些话想和大家聊聊。1999年7月8日，我的姐姐Gretchen Dutemann Roper发现凯特琳·杜特蒂曼（Kathleen Dutemann）在芝加哥平静地睡梦去世了，距离我完成《从零开始的汇编语言》恰好10年，那本书也是献给她的。她把两本书都放在咖啡几上，并展示给每一位访客看，尽管她从未用过电脑，可能也永远不懂什么是汇编语言。她是我的姨妈兼教母，是我父亲唯一的兄弟，她曾教我唱ABC字母表，并在我六岁时要求我进入阿德勒天文馆，尽管当时的规定是孩子必须满七岁才能看星象。“给那个好大叔指一下行星的名字，”她对我说，我照办了，当我指完所有行星后，我开始指星座。我被录取了，因为她相信我。她见证了我生命中的每一个重要时刻：初领圣体、坚信、父亲的病与去世、多年来的圣诞、感恩节和生日，她一直伴在我身边，带着爱尔兰式的幽默和慷慨的心灵——我无法，也永远不会忘记她。

我之所以说这些，是因为你们中很多人比我年轻得多，可能会在生活的狂热中遗忘：时光流逝，那些相信我们的人也是如此，我们在撞击墙壁时推着我们前进，这样我们到达中年时才有所收获。父母、祖父母、姨妈和叔舅对我们生活的影响是无法估量的，而且当我们忙于应碌时，经常忘记珍惜他们，因为在他们离开之后再去珍惜真是一件孤独的事情。

与此同时，在又谈论了十年的汇编语言后，我决定学习如何编写它。只要有电脑，汇编语言就会存在。请期待，2009年就会到来。

# “你为什么要这么做？”

1985年，我正在纽约市乘坐公交车去参加一群浮躁的自大狂的聚会。我刚刚开始我的职业生涯（担任《PC杂志》的技术编辑），并偶然遇到了一位资深作家/专家，他给我留下了深刻印象。我当时正与他谈论某件事。我不会透露他的名字，他为这个领域做了很多贡献，在他离开之前还会做更多。由于我不小心透露我是一个Pascal迷迷，而我真正想做的是学习编写使用全新Windows界面的Pascal程序。我的第一本书仍然在未来。他皱了皱鼻子，苦涩地笑了，说出了那个著名的问题：“你为什么要这么做？”

我以前从未听过这个问题（尽管之后我听了很多次），这让我大吃一惊。为什么？因为，嗯，我想知道它是如何运作的。“**嘿，那是为了……。”

进一步的讨论没有带给我任何方向。但某些探索让我明白，在……中编写Windows应用是不可能的。或者吧，我从未学过真相。但我确实学习了那个著名问题的含义。

请注意：当有人问你“你为什么要这么做？”时，它的真实意思是：“你问我如何用比这更容易的工具来完成某事，但我不想通过承认这一点而丢脸。”所以，在这些年里，我反复听到这句话：

- Q：我如何设置一个字符串以便不需要扫描就能读取它的长度？
- A：你为什么要这么做？
- Q：我如何从Pascal调用汇编语言子程序？
- A：你为什么要这么做？
- Q：我如何用汇编语言编写Windows应用？
- A：你为什么要这么做？

你明白这个意思了。那个著名问题的答案总是相同的，如果他们真的问你，请尽快回答：*因为我想知道它是如何运作的。*

这是一个完全充分的答案。这是我每次使用的答案，除了很多年前一次，我提出想写一本教人们将汇编语言作为他们的*第一次*编程经历的书。

- Q：天哪，你为什么要这么做？
- A：因为这是理解整个编程世界如何运作的最佳途径。

成为程序员高于一切的一点是：理解事物是如何运作的。此外，学习成为一名程序员几乎完全是一个学习事物如何运作的过程。这可以在不同的层次完成，取决于你使用的工具。如果你在用Visual Basic编程，你必须理解某些事情如何运作，但那些事情很大程度上局限于Visual Basic本身。

大量的机制被Visual Basic在程序员和计算机之间的层所隐藏了。（Delphi、Java、Perl以及许多其他高级编程环境也是如此。）如果你使用C编译器，你离机器近得多，看到很多机制——并且必须理解它是如何运作的才能使用。然而，即使对于老练的C程序员来说，仍有很多是隐藏的。（许多C程序员觉得自己知道的比实际多——并且有这种自大的恶运。）

另一方面，如果你在用汇编语言工作，你离机器尽可能近。汇编语言不隐藏任何东西，也不保留任何力量。当然，反面是是你和机器之间没有任何魔法层会吸收你的无知并照顾你。如果你不懂某事是如何运作的，你就完完了——除非你有足够的知识来自己解决它。

这是一个关键点：我编写这本书的目标并不完全是教你汇编语言*本身*。如果说这本书有一个首要指令，那就是传递一种对机器的纪律性的好奇心，以及一些基础背景，让你能够从最底层开始探索机器。以及尽力一的信心。这些是困难的内容，但只要给予一些专注、耐心和所需的时间，并不是你无法掌握的——警告一下，这时间可能是相当巨大的。

事实上，我真正教你的是如何学习。

# 总体计划

你需要一台基于Intel的计算机。对于我将解释的大部分内容，字面上任何基于Intel的机器都可以——一直可以追溯到1981年原始的基于808的IBM PC。然而，为了能尝试所有的示例，你需要一台386。书中大部分内容与16位DOS有关，它随Windows 95和98一起提供，并（稍微受限的形式）被Windows NT模拟。在书的末尾，我解释了如何在Linux下使用汇编语言，这绝对你需要一台386或更先进的Intel机器。
