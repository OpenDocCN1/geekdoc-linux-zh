# Stringing Up

```
DoChar:  stos ; Note that there's no REP prefix!
      add    AL, '1' ; Bump the character value in AL up by 1
      aaa             ; Adjust AX to make this a BCD addition
      add    AL, '0' ; Basically, put binary 3 in AL's high nybble
mov    AH, 07 ; Make sure our attribute is still 7
```

```
loop DoChar ; Go back & do another until CX goes to 0
```

The LOOP instruction first decrements CX by 1. It then checks the Zero flag to see if the decrement operation forced CX to zero. If so, it falls through to the next instruction. If not (that is, ZF remains 0, indicating that CX was still greater than 0), LOOP branches to the label specified as its operand.

So, the loop keeps looping the LOOP counts down to 0. At that point, the loop is finished, and execution falls through and continues with the next instruction following the loop.

# Displaying a Ruler on the Screen

As a useful demonstration of when it makes sense to use STOSW-without REP (but with LOOP) let me offer you another item for your video toolkit.

The Ruler macro which follows displays a repeating sequence of ascending digits from 1 at some selectable location on your screen. In other words, you can display a sequence of digits like this at the top of a window:

```
123456789012345678901234567890123456789012345678901234567890
```

This might allow you to determine where the window line begins or some character falls. The macro allows you to specify how long the ruler is, in digits, and where on the screen it be displayed.

A call to Ruler would look like this:

```
Ruler VidOrigin,20,80,15,5
```

This invocation (assuming you had defined VidOrigin to be the address of the start of the video refresh buffer in your machine) places a 20-character long ruler at position 15,5. The “80 argument indicates to Ruler that your screen is 80 characters wide. If you have a wider or narrower screen, you would have to change the “80” to reflect the true width of your screen in text mode.
