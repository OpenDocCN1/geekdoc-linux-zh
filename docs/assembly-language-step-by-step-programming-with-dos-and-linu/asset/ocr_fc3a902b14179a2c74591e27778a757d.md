# Hexadecimal as Shorthand for Binary

The number 218 is expressed in binary 11011010. Expressed in hex,
hover, the same value is quite compact: DAH. The two hex digits
comprising DAH merit a closer look. AH (or 0AH as your assembler
will require it for reasons I explain later) represents 10 decimal. Counter
verting any number to binary simply involves detecting the powers of
two within it. The largest power of 2 within 10 is 8. Dot down a
1 digit and subtract 8 from 10. What's left is 2. Now, 4 is a power of 2,
but there is no 4 hiding within 2, so we put a 0 to the right of the 1. The
next smallest power of 2 is 2, and there is a 2 in 2. Dot down another 1 to
the right of 2. Two from 2 is 0, so there are no 1s left in the number.
Down a final 0 to the right of the rest to represent the 1s column.
What you have is:

```
1 0 1 0
```

Look back at the binary equivalent of 218: 11011010. The last four digits
is1010—the binary equivalent of 0AH.

The same will work for the upper half of DAH. If you work out the
binary equivalence for 0DH as we just did (and it would be good men-
alercise), it is 1101. Look at the binary equivalent of this way:

| 218 | decimal |
| 1101 1010 | binary |
| D A | hex |

It should be daunting on you that you can convert long strings of binary
is and 0s into more compact format by converting every four binary
dig (starting from the right, not from the left!) into a single hex digit.

As an example, here is a 32-bit binary number that is not the least bit
remarkable:

```
11110000000000001111011001101110
```
