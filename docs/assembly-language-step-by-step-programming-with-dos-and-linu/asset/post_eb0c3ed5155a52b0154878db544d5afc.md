## Flags

Immediately beneath the mnemonic is a minichart of machine flags in the Flags register. I haven't spoken in detail of flags yet, but the Flags register is a collection of 1-bit values that retain essential information about the state of the machine for short periods of time. Many (but by no means all) x86 instructions change the values of one or more flags. The flags may be individually tested by one of the JMP instructions, which then change the course of the program depending on the state of the flags.

We'll get into this business of tests and jumps in Chapter 10. For now, simply understand that each of the flags has a name, and for each flag is a symbol in the flags minichart. You'll come to know the flags by their two-character symbols in time, but until then, the full names of the flags are shown to the right of the minichart. The majority of the flags are not used frequently in beginning assembly language work. Most of you'll be paying attention to, flags-wise, is the Carry flag (CF). It's used, as you might imagine, for keeping track of binary arithmetic operation carries out of a single byte or word.

There will be an asterisk (*) beneath the symbol of any flag affected by the instruction. How the flag affects depends on what the instruction does. You'll have to divide that from the Notes section. When an instruction affects no flags at all, the word <none> will appear in the minichart.

In the example page, the minichart indicates that the NEG instruction affects the Overflow flag, the Sign flag, the Zero flag, the Auxiliary carry flag, the Parity flag, and the Carry flag. The ways that the flags are affected depend on the results of the negation operation on the operand specified. These ways are summarized in the second paragraph of the Notes section.

## NEG Negate (Two's Complement); That Is, Multiply by -1

Flags affected:

O D I T S Z A P C OF: Overflow flag TF: Trap flag AF: Aux carry
F F F F F F F F DF: Direction flag SF: Sign flag PF: Parity flag
* * * * * * IP: Interrupt flag ZF: Zero flag CF: Carry flag

Legal forms:

| r8 | 286 | 386 | 486 | Pentium |
| :--- | :--- | :--- | :--- | :--- | :--- |
| NEG r8 | X | X | X | X | X |
| NEG m8 | X | X | X | X | X |
| NEG r16 | X | X | X | X | X |
| NEG m16 | | X | X | X | X |
| NEG r32 | | | X | X | X |
| NEG m32 | | | | X | X | |

Examples:

- NEG AL
- ECX
- NEG BYTE [BX] ; Negates byte quantity at DS:BX
- NEG WORD [DI] ; Negates word quantity at DS:BX

Notes:

This is the assembly language equivalent of multiplying a value by -1. Keep in mind that negation is not the same as inverting each bit in the operand. (Another instruction, NOT, does that.) The process is also known as generating the two's complement of a value. The two's complement of a value added to that value yields -1 =FF; -2 =FE; -3 =FD; and so forth.

If the operand is 0, CF is cleared and ZF is set; otherwise, CF is set and ZF is cleared. The operand contains the maximum negative value (-128 for 8-bit or -32768 for 16-bit), the operand does not change, and OF and CF are set. SF is set if the result is negative, else SF is cleared. PF is set if the low-order 8 bits of the result contain an even number of (1) bits; otherwise, PF is cleared.

NOTE: You must use a type specifier (BYTE or WORD) with memory data.

```
sr = CS DS SS ES
m8 = 8-bit memory data        m16 = 16-bit memory data
i8 = 8-bit immediate data      m16 = 16-bit immediate data
d8 = 8-bit signed displacement  d16 = 16-bit signed displacement
```

## Legal Forms

A given mnemonic represents a single x86 instruction, but each instruction may include more than one legal form. The form of instruction varies by the type and order of operands passed to it. What the individual forms actually represent different binary opcodes. For example, beneath the surface, the POP instruction is the number 58H, whereas the SI instruction is the number 5EH.

Sometimes there will be special cases of instruction and operands that are shorter than the general cases. For example, the XCHG instruction, which exchanges the contents of two operands, has a special case when one of the operands is register. The general forms of XCHG (for example, XCHG r16,r16) are always 2 bytes. This implies that there are actually two different opcodes that will do the job for a given combination of operands; for example, XCHG AX,DX—and some programmers are smart enough to choose the shortest form in any situation. If you are hand-assembling a sequence of raw bytes, say for use in a higher-level language, you will need to be aware of the special cases, and all special cases will be marked as such in the Legal forms.

When you want to use an instruction with a certain set of operands, make sure to check the Legal forms of the reference guide for that instruction. The MOV instruction, for example, cannot move one segment register directly into another, nor immediate data directly into a segment register. Neither combination of operands is a legal form of the MOV instruction, though they make sense and would be nice to have. If you want to negate the value in a segment register, you'll first have to use MOV to move the value from the segment register into one of the general-purpose registers before using NEG, and finally moving the negated value back into the segment register. Note well that using NEG on a segment register is an almighty thing to do, and for that reason, that form of NEG was not given any budget for the real mode portion of the CPUs.

## Operand Symbols

The symbols used to indicate the nature of the operands in the Legal forms section are summarized at the bottom of every page in the reference. They're close to self-explanatory, but I'll take a moment to expand upon them here:

- r8—An 8-bit register, one of AH, AL, BH, BL, CL, DH, or DL.
- r16—A 16-bit general-purpose register, one of AX, BX, CX, DX, BP, SP, SI, or DI.
- sr—One of the four segment registers, CS, DS, SS, or ES.
- m8—An 8-bit byte of memory data.
- m16—A 16-bit word of memory data.
- m32—A 32-bit word of memory data.
- i8—An 8-bit byte of immediate data.
- i16—A 16-bit word of immediate data.
- i32—A 32-bit word of immediate data.
- d8—An 8-bit signed displacement. We haven't covered these yet, but a displacement is a distance between the current location in the code to which we want to jump. It's signed (that is, either negative or positive) because a positive displacement jumps you higher (forward) in memory, whereas a negative-displacement jumps you lower (back) in memory. We examine this notion in detail in Chapter 10.
- d16—A 16-bit signed displacement. Again, for use with jump and call instructions. See Chapter 10.
- d32—A 32-bit signed displacement.

## What's Not Here…

Appendix A differs from most detailed assembly language references in it does not have the binary opcode encoding information, nor indications of how many machine cycles are used by each form of the instruction.

The binary encoding of an instruction is the actual sequence of binary bytes that the CPU digests and recognizes as the machine instruction. What we call POP AX, the machine sees as the binary number 58H. What we call ADD SL,07733H, the machine sees as the 4-byte sequence 81H 0C6H 33H 77H. Machine instructions are encoded anywhere from one to four (rarely more) binary bytes depending on what instruction they are and what their operands are.
