+   - You can continue program execution at full speed, so that your program will run without pause until the point of execution encounters another breakpoint, or until it ends normally—or abnormally.

+   - You can continue execution one step at a time, using gdb's single-stepping commands.

Both are useful techniques. The continue command takes your program out of pause mode, and simply lets it run as though it were running outside the debugger. (Actually runs a little bit more slowly, because gdb is still there, watching for breakpoints as your program goes.) Once you pick up execution again with continue, the program will run until it encounters another breakpoint, at which time it will pause again.

You can also pick up execution with the until command, which allows you to specify a particular breakpoint at which to pause. You must follow the word until with the identification number of the breakpoint at which you want to pause:

```
(gdb) until 2
```

Note well that if execution for some reason never passes breakpoint 2 (if your code branches around that breakpoint, your program could well execute to completion (or to some problem that halts without pausing again).

The continue and until commands are useful ways to move from breakpoint to breakpoint within a program. The really cool way to move around your code is one instruction at a time, watching things happening as you go. This is what single-stepping is all about, and with gdb it's remarkably easy.

Single-stepping is simple in principle: You type a gdb command that executes a single machine instruction. You type the command again, and you execute the instruction after that. In between executions, you can look at registers, memory locations, and other things that might provide tellt to your program’s operation.
