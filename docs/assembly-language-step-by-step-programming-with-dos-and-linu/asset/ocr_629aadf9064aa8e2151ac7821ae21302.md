But unlike standard output, which is predefined for you by the C library
always available, you have to create or open a disk-based text file in
ord to use it. The fopen function does the job.

There are three general ways to open a file: for reading, for writing, andor appending. When you open a file for reading, you can read text from
it via such functions as fgets, but you can't write to the file. When you
open a file for writing, whatever may have been in the file before is
thrown away, and new material is written at the beginning of the file.
When you open a file for appending, you may write to the file, but new
material is written after any existing material, and whatever was orig-
nally in the file is retained.

Ordinarily, when you open a file for writing you can't read from it, but
there are special modes that allow both reading from and writing to a
file. For text files especially (which are what we're speaking of here)
that introduces some complications, so for the most part, text files are
opened for either reading or for writing, but not at once.

In the Unix file system, if you open a file for either writing or append-
ing the file does not already exist, the file is created. If you don't
 if a file exists and you need to find out, attempt to open it for read-
ing and for writing, or you'll get the file whether it exists or not!

To use fopen, you must push the following parameters onto the stack
before the call:

+   1. First onto the stack is a pointer to a code indicating which mode the file
 be opened for. The various available modes are listed in Table
13.4. The ones you'll typically use for text files are "r","w" and "a".
These should be defined as short character strings, followed by a null:

```
writecode db 'w',0
opencode db 'r',0
```

+   2. Next onto the stack is the address of the character string containing the
name of the file to be opened.

With those two items on the stack, you make the call to fopen. If the file
was successfully opened, fopen returns a file handle in EAX. If the file
un unsuccessful, EAX will contain 0. Here's how opening a file for
reading looks in code:

```
push dword opencode ; Push pointer to open-for-read code "r"
push ebx ; Pointer to name of help file is passed in ebx
```
