# ASSEMBLY LANGUAGE STEP-BY-STEP

The Write procedure displays a string to your screen, and then returns the cursor to the left margin of the following screen line. This action is actually two distinct activities, and Write very economically uses a mechanism that already exists: the Write procedure. The first thing that Write does is call Write to display the string itself to the screen. Remember that the caller loaded the address of the string to be displayed into DX before calling Write. Nothing has disturbed DX, so Write can immediately call Write which will fetch the address from DX and display the string to the screen.

Returning the cursor is done by displaying the newline sequence, which is stored in a string named CRLF. (If you recall, the carriage return and line feed character pair was built right into our message string in the EAS.ASM program we dissected in Chapter 8.) Write uses again Write to display CRLF. Once it is done, the work is finished, and Write executes a RET instruction to return execution to the caller.

Calling procedures from within procedures requires you to pay attention to one: stack space. Remember that each procedure call pushes another address onto the stack. This return address is not removed from the stack until the RET instruction for that procedure executes. If you execute another CALL instruction before returning from a procedure, the second CALL pushes another address onto the stack. If you keep calling procedures from within procedures, one return address will pile up on the stack for each CALL until you start returning from all those nested procedures.

If you run out of stack space, your program will crash and return to DOS, possibly taking DOS with it. This is why you should take care not to use more stack space than you have. Ironically, in small programs written in real mode flat model, this usually isn't a problem. Stack space isn't allocated in real mode flat model; instead the stack pointer points to the high end of the program's single segment, and the stack uses as much of the segment as it needs. For small programs with only a little data (such as the toy programs we're building and dissecting in this book), 95 percent of the space in the segment has nothing to do and can be used by the stack if it needs it. (Which it doesn'—not in this kind of programming!)
