Display or change the contents of all CPU registers allow you to work very quickly, and you should use them as much as you can. This means that you need to see what's going on in registers while you use them, and with one command, DEBUG can display the contents of all machine registers and flags at one time. If you want to change the contents of a register while stepping through a program's machine instructions, you can do that as well.

Fill a region of memory with a single value. If you have an area of memory that you blanked out, DEBUG will allow you to fill that area of memory with any character or binary value.

Search memory for sequences of binary values. You can search any area of memory for a specific sequence of characters or binary values. This could include names stored in memory or sequences of machine instructions. This allows you to examine or change something that you know exists somewhere in memory but not where.

Assemble new machine instructions into memory. DEBUG contains a simple assembler that does most of what NASM can do—one machine instruction at a time. If you want to replace a machine instruction somewhere within your program, you can type MOV,BX rather than to look up and type the raw binary code values 8BH 0C3H.

Unassemble binary machine instructions into their mnemonics and operands. The flip side of the last feature is also possible: DEBUG can take the two hexadecimal values 8BH and 0C3H and tell you that they represent the assembly language MOV AX,BX. This feature is utterly essential when you need to trace a program in operation and understand what is happening when the next two bytes are read into the CPU and executed. If you don't know what instruction those two bytes represent, you'll be totally lost.

Single-step a program under test. Finally, DEBUG's single most valuable skill is to run a program one machine instruction at a time, pausing after each instruction for as long as you like. During this pause you can look at or change memory, look at or change registers, search for things in memory, patch the program by replacing existing machine instructions with new ones, and so on. This is what you'll do most of the time with DEBUG.
