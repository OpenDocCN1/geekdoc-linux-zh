# Assembly-Time Calculations

But in assembling the preceding line, the assembler has to pull another trick out of its hat. It has to be deal with the expression 80*4*2. We've not seen this before in our discussions, but the assembler happily parses the expression and performs the math exactly as you would imagine: It cooks 80*4*2 down to the single integer value 640. It then performs another substitution on the line in question, which finally cooks down to this:

```
DI, 640      ; Start table display down a ways
```

At last, the line becomes an utterly ordinary line of assembly language code, which is turned to object code in a thrice.

So, the assembler can in fact do a little math on its own, quite apart from the arithmetic instructions supported by the CPU. This is called assembly-time math, and it has some very important limitations:

+   - Assembly-time calculations may only be done on values that are fixed and unambiguous at assembly time. This pointedly excludes the contents of variables are fine. Equates are DBs, DWs, and DDs are not. Variables are empty containers at assembly time; just buckets into which values will be thrown later at runtime. You can't perform a calculation with the contents of an empty bucket!

+   - Assembly-time calculations are performed once, at assembly time, and cannot be recalculated at runtime for a different set of values. This should be obvious, it's easy enough to misconstr the nature of assembly-time math while you're a beginner.
