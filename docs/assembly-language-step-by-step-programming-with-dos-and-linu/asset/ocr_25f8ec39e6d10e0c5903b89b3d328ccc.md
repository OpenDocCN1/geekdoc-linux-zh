# ASSEMBLY LANGUAGE STEP-BY-STEP

Don't just read the code inside Ruler! Load it into a copy of EAT5.ASM, and display some rulers on the screen. You don't learn half much as just reading assembly code as you do by loading and using it!

```
; RULER -- Displays a "1234567890"-style ruler on-screen
; Last update 9/16/99
;
; Caller must pass:
; InAddress: The address of the start of the video buffer
; InLength: The length of the ruler to be displayed
; InScreenW: The width of the current screen (usually 80)
; InScreenY: The line of the screen where the ruler is
; be displayed (0-24)
; InScreenX: The row of the screen where the ruler should
; start (0-79)
; Action: Displays an ASCII ruler at ScreenY.
%macro Ruler 5,VidAddress,Length,ScreenW,ScreenX,ScreenY
, DI,[1] ; Load video address to ES:DI
mov AL,%5 ; Move Y position to AL
mov AH,%3 ; Move screen width to AH
imul ; Do bit-8 multiply*AH to AX
add DI,AX ; Add Y offset into vidbuff to DI
add DI,%4 ; Add X offset into vidbuff to DI
shl DI,1 ; Multiply by two for final address
mov CX,%2 ; CX monitors the ruler length
mov AH,07 ; Attribute 7 is "normal" text
mov AL,'1' ; Start with digit "1"
%DoChar: stosw
add AL,'1' ; Bump the character value in AL up by 1
aaa
add AL,'0' ; Adjust AX to make this a BCD division by binary 3 in AL's high nyble
mov AH,07 ; Make sure our attribute is still 7
loop %DoChar ; Go back & do another until BL goes to 0
%endmacro
```

Over and over the LOOP instruction, there's a fair amount of new assembly technology at work here could stand explain. Let's detour from the string instructions for a bit and take a closer look.

# Simple Primitives with IMPUL

Ruler can put its ruler anywhere on the screen, to a position passed as ScreenX and ScreenY. It's not using GotoXY, either. It's actually calculating a position in the video refresh buffer where the ruler characters must be placed—and then using STOS to place them there.
