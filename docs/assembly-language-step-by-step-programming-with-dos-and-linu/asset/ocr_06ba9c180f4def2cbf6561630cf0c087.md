# Memory Data or Immediate Data?

You may be wondering the variable identifier LRXY is for and where it is defined. What's for simple to hold the current X,Y coordinates for the lower-right corner of the screen. Where it is defined in the program's data segment, in the usual way variables are defined, and you'll see if you look ahead to the full listing of EAT3.ASM which follows.

The more interesting question is why. Most of the time I've been you values loaded into registers from immediate data, and this is often useful. The coordinates of the upper-left corner of the full screen, for example, are always going to be 0,0, and nothing will ever change that. The lower-right corner, however, is not necessarily 79,24.

The original 1981 vintage IBM MDA and CGA graphics adapters are capable of 80 by 25 text screens and no more. However, with EGA, it is possible to have an 80 by either 25 or 43 text screen, and the VGA introduced in 1987 with the PS/2 line can display either 25 or 50 lines, all 80 characters wide. The newer VGA video boards are capable of even different text modes, some of them with more than 80 characters in a visible line. If your program can determine what size screen is in force when it is invoked, it can modify its displays accordingly.

Avoid dropping immediate values into code (we call this hard coding) whenever you can. A better strategy, which I follow from now on, uses variables in the data segment initialized with currently correct values when the program begins running.
