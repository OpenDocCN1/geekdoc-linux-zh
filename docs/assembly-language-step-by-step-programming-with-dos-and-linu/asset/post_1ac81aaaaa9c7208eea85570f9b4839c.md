# Notes:

AND performs the AND operation on its two operands. Once the operation is complete, the result replaces the destination operand. AND is performed on a bit-by-bit basis, such that bit 0 of the source is ANDed with bit 0 of the destination, bit 1 of the source is ANDed with bit 1 of the destination, and so on. The AND operation yields a 1 if both of the operands are 1; and a 0 only if either operand is 0. Note that the operation makes the Auxiliary carry undefined. CF and OF are cleared to 0, and the other affected flags are set according to the operation.

# BT Test (386+)

# Flags affected:

# Examples:

- BT AX,CX
- BT [BX-DI],DX

- BT EAX,ECX

# Notes:

BT copies a single bit from the left operand to the Carry flag, where it can be tested using the shift/rotate instructions. Which bit is copied is fed back into the right operand. Neither operand is altered by BT. When the right operand is an 8-bit immediate value, the value specifies the number of bits to copy. If the immediate value exceeds the size of the left operand, the value is expressed modulo the size of the left operand. (Here, if the right operand is not an immediate value, the right operand only specifies an offset from the memory reference in the left operand. This is complicated. See a detailed discussion in a full assembly language reference.)

```

# CALL Call Procedure

# Flags affected:

O D I T S Z A P C OF: Overflow flag TF: Trap flag AF: Aux carry
F F F F F F DF: Direction flag SF: Sign flag PF: Parity flag
<none> IF: Interrupt flag ZF: Zero flag CF: Carry flag

# Legal forms:

```
CALL <near label>
CALL <far label>
CALL r16
CALL m16
CALL r32 386+
CALL m32 386+
```

# Examples:

```
CALL InsideMySegment   ;InsideMySegment is a Near label
CALL OutsideMySegment ;OutsideMySegment is a Far label
CALL BX
CALL EDX
CALL WORD [BX+DI+1]   Calls Near address at [BX+DI+1]
CALL DWORD [BX+DI+1]  ;Calls full 32-bit address at [BX+DI+1]
```

# Notes:

CALL transfers control to a procedure address. Before transferring control, CALL pushes the address of the instruction immediately after itself onto the stack. This allows a RET instruction (also see) to pop the return address into either CS:IP or IP only (depending on whether it is a Near or Far call) and thus return control to the instruction immediately after the CALL instruction.

In addition to the obvious CALL to a defined label, CALL can transfer control to a Near address within a 16-bit general-purpose register, and to an address located in memory. These are shown in the Legal Forms column as m16 and m32. m32 is simply a 32-bit address that may be addressed through any legal x86-addressing mode. CALL m16 and CALL m32 are useful for creating jump tables of procedure addresses.

There are many variants of the CALL instruction with provisions for working with the protection mechanisms of operating systems. These are not covered here, and for more information see an advanced or full assembly language reference.

```
r8 = AL AH BH CH CL DH          r16 = AX BX CX DX BP SI
sr = CS DS SS ES FS GS            r32 = EAX EBX ECX EBP ESI EDI
m8 = 8-bit memory data               m16 = 16-bit memory data
m32 = 32-bit memory data             i8 = 8-bit immediate data
i16 = 16-bit immediate data        i32 = 32-bit immediate data
d8 = 8-bit signed displacement      d16 = 16-bit signed displacement
d32 = 32-bit unsigned displacement
```
