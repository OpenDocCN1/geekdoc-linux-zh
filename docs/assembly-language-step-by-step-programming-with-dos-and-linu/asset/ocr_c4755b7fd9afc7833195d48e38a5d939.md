This is the logical way to work it, it doesn't have to be done that way. STOSW can just easily begin at a high address and move downward in memory. On each store into memory, DI can be decremented by 2 instead.

Which way STOSW fires—uphill successively higher addresses, or downhill successively lower addresses—is governed by one of the flags in the Flags register. This is the Direction flag DF. DF's sole job in life is to control the direction of certain instructions, like STOSW, can move in one of two directions in memory. Most of these (like STOSW) are string instructions.

The sense of DF is: When DF is set (that is, when DF has the value 1), STOSW and its fellow string instructions work downhill, from higher to lower addresses. When DF is cleared (that is, when it has the value 0), STOSW and its siblings work uphill from lower to higher addresses. This turn is simply the direction in which the DI is adjusted: When DF is set, DI is decremented. When DF is cleared, DI is incremented.

The Direction flag defaults to 0 (uphill) when the CPU is reset. It is generally changed in one of two ways: with the CLD instruction, or with the STD instruction. CLD clears DF, and STD sets DF. (You should keep in mind when debugging the POPF instruction can also change DF, by popping an new set of flags from the stack into the Flags register.) It's always a good idea to place the appropriate one of CLD or right before a string instruction to make sure that your machine fires in the right direction!

People sometimes get confused and think that DF also governs whether CX is incremented or decremented by the string instructions. So not! Nothing in a string instruction ever increments CX! You place a count in CX and it counts down, period. DF has nothing to say about it.
