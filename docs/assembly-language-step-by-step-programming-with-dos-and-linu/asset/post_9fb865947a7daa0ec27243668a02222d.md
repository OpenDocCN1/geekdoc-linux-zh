## Pretty Chips All in a Row

One of the most perplexing things for beginners to understand is that a standard 64-megabit RAM chip does not contain 1 byte . . . just 64 million bits. Remember that the RAM chips we use today have only one data pin. To store a byte you would have to store eight bits in sequence at eight consecutive addresses, and to retrieve that byte you would have to retrieve eight bits in sequence. Since it takes 70 nanoseconds at the very least to store a bit in one of those chips, storing a byte would take least 560 nanoseconds, and in practical terms, close to a microsecond, (believe it!) is, far too slow to be useful.

What is actually done is to distribute a single stored byte across separate RAM chips, with one bit from the stored byte in each chip, at the same address across all chips. This way, when a single address is applied to the address pins of all eight chips, all eight bits appear simultaneously on the output pins, and we can retrieve a full byte in 70 nanoseconds instead of 560 nanoseconds. See Figure 3.3.

We call this row of eight chips a bank of memory, and how much memory is contained in a bank depends on the type of chips incorporated in the bank. A row of 1-megabit chips like that shown in Figure 3.3 contains one megabyte. (That megabyte taken as a whole contains 8 x 1 or 8 million bits, however. Remember, computers deal with information a minimum of 8 bits at a time.) A row of 256K bit chips contains 256K bits. The memory SIMMs in current use typically contain a row of eight chips, each of which contains 32 or 64 megabits. Some high-end SIMMs are formed of 128-megabit chips and contain 128 megabytes.

Actual computers combine various combinations of memory banks in various ways to produce different amounts of memory. I'll take up the subject again when we begin talking about the PC in Chapter 6.

## The Shop Foreman and the Assembly Line

The gist of the previous section was only this: Electrically, your computer’s memory consists of one or more rows of memory, each chip containing a large number of cells consisting of transistors and other components. Most of the time, it’s just useful to forget about the transistors and even rows of chips to avoid confusion. (My high school science teacher was not entirely wrong ... but he was right for the wrong reasons.)

Over the years, memory have been accessed in different ways:
- Eight-bit computers (now ancient and extinct) accessed memory eight bits (one byte) at a time.
- Sixteen-bit computers access memory 16 bits (one word) at a time.
- And today's 32-bit computers (everything in the PC realm since 386) access memory 32 bits (one double word) at a time.

It can be confusing, so it's better in most cases to envision a very long row of byte-sized containers, each with its own address. Don't assume that in computers which process a word at a time only words have addresses; it is a convention with the PC architecture that every byte has its own address regardless of how many bytes are pulled from memory at one time.

If this seems counterintuitive another metaphor will help: When you go to the library to take out the volumes of Tolkien's massive fantasy The Lord of the Rings, you will find that each of the volumes has its own catalog number (essentially volume's address in the library) but you take all at once and process them as a single entity. If you really want to, you can take only one of the books out at a time, but to do so will require another trip to the library to get the next volume, which is wasteful of your time and effort.

## The Honcho Chip

All of this talk about reading things from memory and writing things to memory has thus skirted the question of who is doing the reading and writing. The answer is always a single chip, and a remarkable chip it is, too: the central processing unit, or CPU. If you are the president and CEO of your personal computer, the CPU is your shop foreman, who sees that your orders are carried out in the chips where the work gets done.

Some would say that the CPU is what actually does the work, but that's an oversimplification. Plenty of real work is done in the memory system, and especially in what are called peripherals such as video display boards, serial and parallel ports, and modes. So, while the CPU does a good deal of the work, it parcels out a bit to other components within the computer. I think its role of foreman outweighs its assemble-line grunt.

Most of the CPU chips used in the machines lump together as a group and all PCs come from a company called Intel, which pretty much invented the single-chip CPU back in the early 1970s. Intel's first big up success was the 8080, which helped trigger the personal computer revolution by being chosen for the seminal MIT Altair 8800 computer in Popular Electronics in 1974. The 8080 was an eight-bit CPU because it accessed memory 8 bits (one byte) at a time. 8080 is long extinct, but gave birth to a pair of next-generation CPU chips the 8086 and the 8088. These two chips are nearly identical except that the 8088 is an 8-bit CPU while the 8086 is a 16-bit CPU and accesses a word (2 bytes) at a time. IBM chose 8088 for its original 1981 IBM PC and later the PC XT, but the 8086 made it into a true IBM computer until the forgettable (and largely forgotten) PS/2 models 25 and 30 appeared in 1987.

We thought for a long time that 32 bits is an ideal "fetch size" for a CPU memory access, and increasing memory access beyond 32 bits at a time would begin to slow things down. Well, we were wrong.

## Lifting the Hood

Some time in the next few months as I write, Intel will begin sampling its first 64-bit CPU, code-named Merced. Merced fetches 8 bytes (a quad word) at a time and will run at speeds of 1 GHz (gigahertz: a billion clock cycles per second) or has plenty of internal machinery to make sure that expanding its jaws to swallow 64 bits at a time will not slow anything down. Is 64 bits an optimal size? No bets taken here. I've been in this business long enough to see the foolishness of making sweeping statements like that.

## Talking to Memory

The assorted Intel CPUs operate at varying speeds with various features, but at the bottom of things they are conceptually identical, and this discussion will apply to all of them.

The CPU chip's most important job is to communicate with the computer's memory system. Like a memory chip, a CPU chip is a small square of silicon onto which a many transistors have been placed. The fragile silicon chip is encased in a plastic or ceramic housing with a large number of pins protruding from it. Like the memory chips, the CPU chip has a number of pins devoted to memory addresses, and these pins are connected directly to the computer's bands of memory chips. When the CPU desires to read a byte (or a word, or double word) from memory, it places the memory address of the byte to be read on its address pins, encoded as a binary number. Seventy nanoseconds or later, the byte appears (also as a binary number) on the data pins of the memory chips. The CPU chip also has data pins, and it slurps up the byte presented by the memory chips through its own data pins. See Figure 3.4.

The process, of course, also works in reverse: To write a byte into memory, the CPU first places the memory address where it wants to write onto its address pins. Some number of nanoseconds later (which varies from system to system how memory is arranged) the CPU places the byte it wishes to write into memory on its data pins. The memory chips obediently store the byte inside themselves at the requested address.
