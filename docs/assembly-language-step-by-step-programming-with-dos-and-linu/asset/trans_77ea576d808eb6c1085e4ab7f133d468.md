# 汇编源代码文件

文本编辑器首先创建一个文本文件，随后在你扩展、修改和完善汇编语言程序时，更改同一个文本文件。按照惯例，大多数汇编语言源文件都被赋予 .ASM 扩展名。换句话说，对于程序 FOO，汇编语言源代码文件将命名为 FOO.ASM。

可以使用 .ASM 以外的扩展名，但我认为使用 .ASM 扩展名可以消除困惑，让你一眼就能看出一个文件的用途——只需看它的名字。总而言之，汇编语言开发过程中可能涉及大约九种不同的文件——在 Windows 开发中更多（我们只提到四五种）。每种类型的文件都有其标准的扩展名。任何有助于将所有复杂性保持在（诚然）标准命名范围内的做法。从图 4.5 的流程中你可以看到，编辑器产生源代码文件，显示为 .ASM 扩展名。该文件随后传递给汇编器以转换为可重定位的对象文件，扩展名为 .OBJ。当你调用汇编器时，DOS 会从磁盘加载汇编器。汇编器会打开你命名的源文件并开始处理。紧接着，它会创建一个与源文件相同但扩展名为 .OBJ 的文件。当汇编器从源文件中读取行时，它会检查它们，构建二进制机器指令，然后将这些机器指令写入对象文件。当汇编器到达源文件的末尾时，它将同时关闭源文件和对象文件并将控制权返回给 DOS。

# 汇编的权利

当汇编器从源文件中读取它不理解的内容时，我们将之为错误，汇编器会显示错误消息。例如，下面这行汇编语言会混淆汇编器并发出错误消息：

```
MOV AX, VX
```

原因很简单：没有 "VX" 这种东西。所谓的 "VX" 实际上本应该是 "BX"，这是一个寄存器的名字。V 键紧挨着 B 键，手指可能不经意间按错了。

这样的拼写错误是最容易发现的错误类型。其他需要一些研究才能发现的错误涉及违反汇编器的许多规则。例如：

```
MOV ES,0FF0H
```

这看起来应该是正确的，因为 ES 是一个真实的寄存器，而 FF0H 是一个可以放入 ES 的 16 位数值。然而，在许多规则中，86 系列汇编器不能直接将立即值（任何如 FF0H 的数值）移动到 ES、DS、SS 或 CS 等段器中。这并不是 CPU 机制可以完成的。你必须首先将值移动到通用寄存器，然后将其移动到段寄存器。这并不是 CPU 机制可以完成。你必须首先将值移动到通用寄存器，然后将其移动到段寄存器。
