You can convert the value of a number in any base to decimal (10) by determining the value of each column in the alien base, by multiplying the value of each column by the digit contained in the column (to create the decimal equivalent of each digit), and finally taking the sum of the decimal equivalent of each column. This is in Figure 2.2, and the octal number and its decimal equivalent are shown side by side. Choosing not to notice in Figure 2.2 is the small subscript on the right-hand side of the columnar sums. These subscripts are used in many technical publications to indicate a number base. The subscript in the value $76225_8$, for example, indicates that the value $76225$ is denoting a quantity in octal, not Martian and decimal, there's really nothing about an octal number itself that sets it off as octal. (We encounter this same problem later on when we confront hexadecimal.) The value $31893_{10}$, by contrast, is shown by its subscript to be a base 10, or decimal. This is mostly done in scientific and research writing. In most computer publications (including this one) other indicators are used, or with more later.

Now that we've looked at columnar notation from both Martian and an octal perspective, make sure you understand how columnar notation works in any arbitrary base before we go on.

# Alien Fossils

Octal as a number base is very nearly extinct. The DEC PDP-8 machines that were octal's home turf are now dishwasher-sized museum pieces with about the same computing power as a Furby toy. There is, however, one small domain where octal numbers still (literally) roam the Earth. People who used the CompuServe online system for some time may be known by their numeric IDs. (Newer CompuServe accounts use alphabetic IDs, just as all Internet systems use.) Back when I had a CompuServe account, it was 76711,470. Note that nowhere in numeric ID is any digit larger than 7. In fact, nowhere in any old-style CompuServe ID you will find the digit 8 or the digit 9.
