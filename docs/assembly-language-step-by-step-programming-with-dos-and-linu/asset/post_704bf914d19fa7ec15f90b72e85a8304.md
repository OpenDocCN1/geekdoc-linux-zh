# STOS Store String

Flags affected:

O D I T S Z A P C OF: Overflow flag TF: Trap flag AF: Aux carry
F F F F F F F DF: Direction flag SF: Sign flag PF: Parity flag
<none> IF: Interrupt flag ZF: Zero flag CF: Carry flag

# Legal forms:

- STOS ES:m8
- STOS ES:m16
- STOSB
- STOSW
- STOSD 38+

# Examples:

- STOS ES:WordVar ; Stores AX to [ES:DI]
- STOS ES:ByteVar ; Stores AL to [ES:DI]
- STOSB ; Stores AL to [ES:DI]
- STOSW ; Stores AX to [ES:DI]
- STOSD ; Stores EAX to [EDI]
- REP STOS ; Stores AX to [ES:DI] and up, for CX repeats

# Notes:

Stores AL (for 8-bit operations), AX (for 16-bit operations), EAX (for 32-bit operations) at the location at [ES:DI] or for [EDI]. ES must be the destination and cannot be overridden. (For bit-protected mode flat model, all segments are congruent and ES does not need to be specified explicitly). Similarly, DI or EDI must always be the destination offset.

By placing a repeat count (not a byte, word, or d!) in CX/ECX and preceding the mnemonic with the REP prefix, STOS can do an automatic "machine-gun" store of AL/AX/EAX into successive memory locations beginning at [ES:DI] or [EDI]. After each store, DI/EDI is adjusted (see next paragraph) by 1 (for 8-bit store operations), 2 (for 16-bit store operations), or 4 (for 32-bit store operations), and CX is decremented by 1. Don't forget that CX/ECX operations (the number of data is stored to memory) and not bytes!

Adjusting means incrementing if the Direction flag is cleared (by CLD) or decrementing if the Direction flag has set.

```
r8 = AL AH BH CL CH DL DH r16 = AX CX DX BP SP SI DI
sr = CD DS SS ES FS GS EAX EBX ECX EDX EBP ESI EDI
m8 = 8-bit memory data m16 = 16-bit memory data
m32 = 32-bit memory data i8 = 8-bit immediate data
i16 = 16-bit immediate data i32 = 32-bit immediate data
d8 = 8-bit signed displacement d16 = 16-bit signed displacement
d32 = 32-bit unsigned displacement
```

# SUB Arithmetic Subtraction

Flags affected:

O D I T Z A P C OF: Overflow flag TF: Trap flag AF: Aux carry
F F F F F F F DF: Direction flag SF: Sign flag PF: Parity flag
* * * * * * * IF: Interrupt flag ZF: Zero flag CF: Carry flag

# Legal forms:

```
SUB r8,r8
SUB m8,r8
SUB r8,m8
SUB r16,r16
SUB m16,r16
SUB r16,m16
SUB r32,r32 38+
SUB m32,r32 38+
SUB r32,m32 38+
SUB r8,i8
SUB m8,i8
SUB r16,i16
SUB m16,i16
SUB r32,i32 38+
SUB m32,i32 38+
SUB AL,i8
SUB AX,i16
SUB EAX,i32 38+
```

# Examples:

- SUB BX,DI ;Uses single-byte opcode
- SUB AX,0FFFF ;Uses single-byte opcode (Note: likely 0FFFFH or similar)
- SUB AL,42H ;Uses single-byte opcode
- SUB EBX, DWORD [EDI]
- SUB WORD [ES:BX],0B0H
- SUB WORD [BX+SI],DX

# Notes:

SUB performs a subtraction without borrow, the source is subtracted from the destination, and the result replaces the destination. If the result is negative, the Carry flag is set. Multiple-precision subtraction can be performed by following SUB with SBB (Subtract with Borrow) which takes the Carry flag into account.

```
r8 = AL AH BH CL CH DL DH r16 = AX CX DX BP SP SI DI
sr = CD DS SS ES FS GS EAX EBX ECX EDX EBP ESI EDI
m8 = 8-bit memory data m16 = 16-bit memory data
m32 = 32-bit memory data i8 = 8-bit immediate data
i16 = 16-bit immediate data i32 = 32-bit immediate data
d8 = 8-bit signed displacement d16 = 16-bit signed displacement
d32 = 32-bit unsigned displacement
```

# XOR Exclusive Or

Flags affected:

O D I T S Z A P C OF: Overflow flag TF: Trap flag AF: Aux carry
F F F F F F F DF: Direction flag SF: Sign flag PF: Parity flag
* * * * * * * IF: Interrupt flag ZF: Zero flag CF: Carry flag

# Legal forms:

```
XOR r8,r8
XOR m8,r8
XOR r8,m8
XOR r16,r16
XOR m16,r16
XOR r16,m16
XOR r32,r32 38+
XOR m32,r32 38+
XOR r32,m32 38+
XOR r8,i8
XOR m8,i8
XOR r16,i16
XOR m16,i16
XOR r32,i32 38+
XOR m32,i32 38+
XOR AL,i8
XOR AX,i16
XOR EAX,i32 38+
```

# Examples:

- XOR BX,DI ;Uses single-byte opcode
- XOR AX,0FFFF ;Uses single-byte opcode
- XOR AL,42H
- XOR EBX, DWORD [EDI]
- XOR WORD [ES:BX],0B0H
- XOR WORD [BX+SI],DX

# Notes:

XOR performs the exclusive OR operation between its two operands. Once the operation is complete, the result replaces the destination operand. XOR is performed on a bit-by-bit basis, such that 0 of the source is XORed with 0 of the destination, and 1 with 1. XOR yields a 1 if the operands are different, and so on. Note that the operation sets the Auxiliary carry flag undefined. CF and OF are cleared to 0, and other affected flags are set according to the operation’s results.

```
r8 = AL AH BH CL CH DL DH r16 = AX CX DX BP SP SI DI
sr = CD DS SS ES FS GS EAX EBX ECX EDX EBP ESI EDI
m8 = 8-bit memory data m16 = 16-bit memory data
m32 = 32-bit memory data i8 = 8-bit immediate data
i16 = 16-bit immediate data i32 = 32-bit immediate data
d8 = 8-bit signed displacement d16 = 16-bit signed displacement
d32 = 32-bit unsigned displacement
```

# Segment Register Assumptions for Real Mode

Once the modes are so awful that there is a whole layer of assumptions to be remembered about which segments are used in which ways. In 32-bit mode (as in Linux), all segments point to the same space, and thus you don’t need to “mess with” segments. Where allowed, segment may be overridden with segment prefixes. These are DS; SS; CS; and ES. Under NASM, they must be placed inside the brackets (MASM and TASM place them outside.)

```
mov [ES:BX], AX
```

The assumptions are:

- 1. When the offset is specified in BX, SI, or DI, the assumed segment is DS.
- 2. When the offset is specified in SP, the assumed segment is SS. This may not be overridden!
- 3. When the offset is specified in BP, the assumed segment is SS.
- 4. For string instruction LODS, the assumed segment is DS and the assumed offset is SI. This may not be overridden!
- 5. For string instructions STOS and SCAS, the assumed segment is ES and the assumed offset is DI. This may not be overridden!
- 6. For string instruction MOVS, the source must be pointed to DS:SI and the destination must be pointed to ES:DI. This may not be overridden!
