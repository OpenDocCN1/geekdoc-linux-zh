Look at the third line of the register display, which've been ignoring up until now. To the right of the address display FFFF:0000 is this series of five bytes: EA5BE000F0.

These five bytes make up the machine instruction we. Notice that the first line of the memory dump begins with the same address, and, sure enough, shows us the same five bytes.

Trying to remember what machine instruction EA5BE000F0 would try anyone's intellect, DEBUG is a good sport and translates the bytes into a more readable representation of the machine instruction. This translation is placed to the right of the binary machine code EA5BE000F0. We call this process of translating binary machine codes back into human-readable assembly language unassembly or, more commonly, disassembly:

```
JMP F000:E05B.
```

What this instruction does, quite simply, is to tell the CPU to jump to the address F0000:E05B and begin executing the machine instructions located there. If we execute the machine instruction at CS:IP, that's what will happen: The CPU will jump to the address 0F000:0E5B and begin executing whatever machine instruction it finds.

All IBM-computer PCs have a JMP instruction at address 0FFFF:0. The address to that JMP instruction jumps will be different for different and models of PC. This is why on your machine you're not necessarily the exact five bytes EA5BE000F0, but whatever bytes you find at 0FFFF:0, they will always begin with 0AH. The 0AH byte specifies that this instruction will be a JMP instruction. The remainder of the machine instruction is the address to which the CPU must jump.
