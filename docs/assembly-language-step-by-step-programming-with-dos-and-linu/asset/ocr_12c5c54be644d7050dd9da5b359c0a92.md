# Coding for Linux

remember that you already used the label loop on line 187 of a 1,432-line program?

You won't. And sooner or later, you'll try and use the label loop again. NASM will call you on it with an error.

This is a common enough problem (especially with obviously useful labels such as loop) NASM's authors created a feature to deal with it: local labels. Local labels are founded on the fact that nearly all labels in assembly work (outside of subroutines and major sections) are “local” in nature, by which I mean that they are only referenced by JMP instructions that—perhaps one or two instructions away. Labels are usually parts of tight loops and are not referenced from far away in the code.

Here's an example:

```
; Clear a buffer to nulls
Bufclr: mov ecx, BUFSIZE+5    ; Fill whole buffer plus 5 for safety
.loop:  dec ecx                   ; BUFSIZE is 1-based decrement first!
mov     [randchar+ecx],0        ; Mov null into the buffer
cmp     ecx,0                   ; Are we done yet?
nz     .loop                    ; If not, go back and pull another null
```

```
; Create a string of alphanumeric characters
Pulchr: mov ebx, BUFSIZE      ; BUFSIZE tells us how many chars to pull
.loop:  dec ebx                   ; BUFSIZE is 1-based, so decrement first!
mov     edi, dword pull6         ; For random in the range 0-63
call pull                    ; Get a random number from
mov     cl, [chartbl+eax]        ; Use name # as offset into table
                                 ; copy character from table into cl
```

```
mov [randchar+ecx],cl      ; Copy char from cl to character buffer
cmp     ecx,0                   ; Are we having fun yet?
nz     .loop                    ; If not, go back and pull another
```

You'll see that this code snippet the label loop has a period in front of it. This period marks it as a local label—and there are two labels here, each separate and distinguishable. Local labels are local to the first nonlocal (that is, the first label not prefixed by a period; we call this global) that precedes them in the code. In the preceding snippet, the first label .loop is local to the global label Bufclr. is not visible further up the source code past Bufclr, and once you get above Bufclr, there may be another local label called .loop, without any conflict with the two .loop labels.

Going down the source code from the global label Bufclr, the local label .loop is reference until the next global label, Pulchr, is encountered.
