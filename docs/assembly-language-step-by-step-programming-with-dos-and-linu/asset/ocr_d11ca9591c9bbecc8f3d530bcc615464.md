# Bits, Flags, Branches, and Tables

```
VidOrg:
xor AH,AH ; Zero AH
mov DI,AX ; Copy AX (with code in AL) into DI
shl DI,1 ; Multiply code by 2 to act as word index
mov BX,OriginTbl ; Load address of origin table into BX
mov AX,[BX+DI] ; Index into table using code as index
ret ; go home!
```

This works a lot like the Digits lookup table mechanism in Byte2Str. There's an important difference, however: each entry in the OriginTbl lookup table is two bytes in, whereas each entry in Digits was one byte size.

# Using Shift Instructions to Multiply by Powers of Two

To use the Digits lookup table, we simply used the value to be converted into the table. Because each element in the table was one byte in size, this worked. When table elements are more than one byte long, you have to multiply the index by the number of bytes in each table element, or the lookup won't find the correct element.

OriginTbl is a good working example. Suppose you get a code 2 back from DispID, indicating that you have a CGA in the system. Adding the 2 to the starting address of the table (as we did with Digits) takes us to the start of the second element in the table. Read across to the comment of that second element and see which code it applies to: code 1, the MDA! Not cool.

If you scan down find the element associated with the CGA, you'll find it starts at an offset of four from the start of the table. Index into the table correctly, you have to add 4, not 2, to the offset address of the start of the table. This is where multiplication comes in.

There is a general-purpose multiply instruction in x86 CPU, but MUL is outrageously slow as machine instructions go. There's a better way—in some cases. When you need to multiply a value by some power of 2 (that is, 2, 4, 8, 16, 32, and so on), you can do it by using the shift instruction, SHL. Shifting a value to the left by one multiplies the overall value by 2. Shifting a value to the left by two bits multiplies the value by 4. Shifting a value to the left by three bits multiplies the value by 8, and so on.
