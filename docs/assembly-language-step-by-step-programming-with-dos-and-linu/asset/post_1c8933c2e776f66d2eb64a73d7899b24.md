The x command can dump memory for a specified number of bytes beginning at a specified address. The two additional tricks are the repeat count and the unit size. # Changing Register and Program Variable Values

Changing values within machine registers and simple variables (that is, variables that are not strings or arrays) can be done with the print command. Just as print can show what's in a register or a variable, it can place new values in them as well. The notation looks a lot like an assignment statement in C:

```
(gdb) print edx=42
$9 = 42
```

Here, the EDX register will be given the new value 42. Print will echo the new value and assign it a number in the value history. This can be done with simple program variables as well. For example, given a 32-bit integer named seconds, you can store a new value into seconds this way:

```
(gdb) print seconds=57
$9 = 57
```

There's another way to do the same thing. The set var command will change the value of a variable without echoing the value back to you, and without adding another record to the value history:

Patching memory at arbitrary addresses is something you may need to do from time to time. Another variation of the set command will get you there. You need to provide the name of a valid simple data type that gdb knows what size and range to allow for the intended data. # Single-Stepping Your Programs

The continue and until commands are useful ways to move from breakpoint to breakpoint. The really cool way to move around your code is one instruction at a time, watching things happening as you go. This is what single-stepping is all about, and with gdb it's remarkably easy.

Single-stepping is simple in principle: You type a gdb command that executes a single machine instruction. You type the command again, and you execute the instruction after that. In between executions, you can look at registers, memory locations, and other things that might provide tell to your program’s operation.
