Each column in the hexadecimal system has a value 16 times that of the column to its right. (The rightmost column, as in any number base, is the units column and has a value of 1.) As you might imagine, the values of the individual columns go up frightening fast as you move from right to left. Table 2.6 shows the values of the first seven columns in hexadecimal. ## ASSEMBLY LANGUAGE STEP-BY-STEP

Let’s try an easy one. The hex number is 7A2. Start at the right. This is the units column in any number system. You have 2 units, so enter 2 into your calculator. (Or press the SUM button, if you have.) For many units. Keep in mind what you’re really doing is keeping a tally of the columns in the hex number. Move to the next column to the left. Remember that each column represents a value 16 times the value of its right. So, the second column from the right is the 16s column (Refer to Table 2.6 if you lose track of the column). The 16s column has an A in it. A in decimal 10. The total value of that column, therefore, is 16 x 10, or 160. Perform that multiplication on your calculator, and add the product to that stored in memory (Again, the SUM button is a handy way to do this if your calculator.) Remember what you’re doing: evaluating each column in decimal and keeping a running total. Now, move to the third column from the right. This one contains a 7. The value of the third column is 16 x 16, or 256. Multiply 256 x 7 on your calculator, and add the product to your running total. You’re done. Retrieve the running total from your memory. The total should be 1954, which is the decimal equivalent of 7A2. Okay—let’s try it again, quickly, with a little less and a much larger number: C60DBH.

- 1. Evaluate the units column. B x 1 = 11 x 1 = 11. Start your running total with 11.
- 2. Evaluate the 16s column. D x 16 = 13 x 16 = 208. Add 208 to your running total.
- 3. Evaluate the 256s column. 0 x 256 = 0. Move on.
- 4. Evaluate the 4096s column. F x 4096 = 15 x 4096 = 61440. Add it to your running total.
- 5. Evaluate the 65536s column. C x 65536 = 393216. Add it to your running total.
- 6. Evaluate the 1,048576s column. C x 1048576 = 12 x 1048576 = 12582912. Add it to your running total.

The running total should be 13,037,787. Finally, do it yourself without any help for the following: 1A55BEH.

## From Decimal to Hex

The lights should be coming about now. This is good because going in the other direction, from our familiar base 10 to hex, is much harder and involves more math. What we have to do is find the hex values within a decimal number—and that involves careful use of long division. But let's get to it, again, starting with a fairly easy number: 449. The calculator will be handy with a vengeance. Tap in the 449 and store it in the calculator’s memory.

What we need to do first is find the largest hex column value that is contained in 449 at least once. Remember “gaz?” (how many times?) Division is often introduced to students as a way of finding how many times some number is present in—another.” It’s something like that. Looking back at Table 2.6, we can see that 256 is the largest power of 16, and hence the largest column value, that is present in 449 at least once. The next largest power of 16—512—is obviously too large to be in 449.

So, we start with 256, and determine how many 256 “goes into” 449: 449 / 256 = 1.7539. At least once, but not quite twice. 449 contains only one. Write down a 1 on paper. Don’t enter it into your calculator. We’re not keeping a total here; if anything, we could say we’re keeping a running remainder. The “1” is the leftmost digit of the hex value that is equivalent to decimal 449.

We know that there is only one 256 contained in 449. What we must do now is remove it from the original number, now that we’ve “counted” it by writing a 1 down on paper. Subtract 256 from 449. Store the difference, 193, into memory.

The 256 column has been removed from the number we’re converting. Now we move to the next column, the 16s. How many 16s are contained in 193? 193 / 16 = 12.0625.
