The only authentication mechanism currently supported by `named` is the use of a secret key, encrypted with the HMAC-MDS algorithm, and shared between `rndc` and `named`. The easiest way to generate a key is to use the `dnsssec-keygen` utility. In the following example, you are asking the utility to generate a 128-bit HMAC-MDS user key named `rndc`:

```
$ dnsssec-keygen -a hmac-md5 -b 128 -n user rndc
Krndc.+157+14529
$ cat Krndc.+157+14529.private
Private-key-format: v1.2
Algorithm: 157 (HMAC_MD5)
Key: mKKd2FiHMMFe1JqXl/z4cfw==
```

The utility creates two files with .key and .private extensions, respectively. The Key: line in the .private file tells us the secret that `rndc` and `named` need to share (mKKd2FiHMMFe1JqXl/z4cfw==). When we have this, we can set up the `rndc.key` configuration file which is shared by both `rndc.conf` and `named.conf`.

```
key "rndc" { algorithm hmac-md5; secret "mKKd2FiHMMFe1JqXl/z4cfw=="; };
```

# rndc.conf

`rndc` uses a TCP connection (on port 953) to communicate with `named`. The configuration file, /etc/rndc.conf by default, must specify a server to talk to, as well as include the corresponding key (which must be recognized by `named`) to use while talking to it:

```
# Use the key named "rndc" when talking to the nameserver "localhost."
server localhost {
    key        "rndc";
};

# Defaults.
options {
    default-server       localhost;
    default-key          "rndc";
};

# Include the key to use
include "/etc/rndc.key";
```

The file needs to have three sections:

+   - **Server section**—Defines a nameserver (localhost) and specifies a key (rndc) to be used while communicating with it.
