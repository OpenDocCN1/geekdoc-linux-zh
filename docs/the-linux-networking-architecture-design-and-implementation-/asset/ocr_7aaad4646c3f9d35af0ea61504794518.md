The IP_MULTOP Loop Socket Option There is a special network device: called the loopback device, to enable applications in the local computer to communicate. This device works at minimal cost and behaves like a physical network device. The reason it is often used to test network applications locally or to design them that there will be no difference between situations where the communication partner is reachable or remotely over the network. One example is the X-Windows system. The loopback device in Linux is denoted To and has the reserved IP address 127.0.0.1.

The socket option IP_MULTICAST_LOOP can now be used to determine whether multicast packets to be sent be replicated over the loopback device to local sockets. For example, this could be useful for the video part in a videoconference so that the users can receive their own images for control purposes. In contrast, this is not desirable for audio data, because it would cause interferences.

When setting the IP_MULTICAST_LOOP, we have to make sure that opt val is a pointer to the Boolean value for enabled (1) or disabled (0).For example, the compiler would not accept the following call:

```
setsockopt(socket, IPPROTO_IP, IP_MULTICAST_LOOP, 0, 1)
```

The correct call looks like this:

```
int loop = 1;
sockoptopt(socket, IPPROTO_IP, IP_MULTICAST_LOOP, &loop, sizeof(loop));
```

The IP_ADD MEMBERSHIP Socket Option The socket option (IP_ADD MEMBERSHIP) is available on application level to join an IP multicast group. In the kernel, the results in the function ip_mc_join(). The kernel is instructed to use IGMP, unless it is already used, to join the desired group, and to forward the data to the application. Notice that more than one application in one single computer can be members of a group.

For example, the code sequence to join 233.25.10.72 looks like this:

