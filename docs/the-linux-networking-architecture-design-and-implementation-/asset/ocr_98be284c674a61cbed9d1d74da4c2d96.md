# 14.2 Implementing the Internet Protocol

IP datagram arrives and is held in the fragment cache until the wait time for all fragments (IP_FRAG_TIME) expires or all fragments of IP datagram have arrived.

```
ip_find()
```

ip_find(iph) searches for the fragment cache for the ipq entry for an IP datagram with the iph packet header. To this end, ipqhashfn() is used to compute the hash value of this entry from the sender address, destination address, protocol ID, and fragment IP from the packet header fields. Based on these parameters, different datagrams can be distinguished, and incoming fragments can be allocated to each datagram. Collisions of several ipq structures with identical hash values are resolved linearly in a doubly linked list.(See Figure 14–7). If ip_find() cannot find a matching entry for the ip frag, then a new ipq entry is created in the fragment cache (ip_frag_create()).

```
ip_frag_queue()
```

ip_frag_queue(qp, skb) orders a new fragment, as it arrives, in the queue of fragments (represented by the ipq structure). The function checks for whether the datagram is complete, which would mean that a new fragment is a duplicate. If this is not the case, the position (offset and len) of the fragment in the original IP datagram is computed from the Fragment Offset parameter in the IP packet header. Subsequently, the MF flag is used to check on whether this is the last fragment of a datagram (LAST_IN set).

Subsequently, the list of received fragments (qp->fragments) is searched for the correct position, and the socket buffer is placed at this position. The meat parameter in the ipq structure of the datagram is increased by the length corresponding to the fragment added. As mentioned earlier, the length parameter specifies the number of bytes received for a fragmented IP datagram.

```
ip_frag_reasm()
```

This function is invoked by ip_defrag(); it reassembles all fragments of a packet (qp->len == qp->meat) and reassembles them as a single IP datagram. First, a new socket buffer with a headroom of qp->len is created, and the IP datagram header is initialized. The IP payload of each fragment is copied to the header of the new socket buffer.

ip_defrag()
