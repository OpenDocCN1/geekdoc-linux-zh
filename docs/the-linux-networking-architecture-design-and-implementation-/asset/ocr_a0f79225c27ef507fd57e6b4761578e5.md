The “traditional” Unix command to manage routing tables is route. However, it does not support the relatively new rule-based routing, and all it allows you to do is modify the main table and read from the routing cache. It uses the ioctl() system call to interface with the kernel.

Alexey Kuznetsov, one of the major contributors to the development of routing implementation in the Linux kernel, also proposed a tool that uses the most recent RT netlink interface to the kernel. It can be used to manipulate not only routing tables but also a number of parameters of the network configuration. The command is ip, and it expects that the first parameter will always be an area to be configured. Table 16–1 shows an overview of all possible areas.

The syntax of the command is relatively uniform for different areas: The area identifier normally followed by an action identifier (e.g., show, add, delete.), followed by area-specific parameters, which are denoted by a leading keyword. The action identifier help always supplies a syntax description. For example, ip route shows the syntax of commands used to manipulate and query routing tables.

The following subsections describe only those two variants of the ip command that are used to manipulate routing tables. More information about the other variants is included in the ip tool documentation [Kuzn99].

# The ip rule Command

The ip rule variant of the ip command serves to output, add, or delete routing rules in the kernel database using ip rule show, ip rule add, and ip rule delete, ip rule shows all rules; the other two commands require additional parameters to describe a rule. These parameters are denoted by a leading keyword, as shown in Table 16–2: see also Section 16.1.6 for a description of the meaning of these parameters.

If mandatory parameters are not stated, then default values are used.
