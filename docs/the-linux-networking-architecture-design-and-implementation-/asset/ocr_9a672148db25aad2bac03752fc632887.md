# 16.3 Implementation

```
struct fn_zone
net/ipv4/fib_hash.c
```

An fn_zone structure manages all entries with the same prefix length by a hash table. The fixed prefix length is noted in the fz_order element, and fz_mask includes an appropriate network mask. The hash table contains entries of an array of fib_node structures, which are referenced by the fz_hash pointer. The array size is specified by fz_divisor, fz_hashmask holds a bit mask to use the hash value to the range permitted for indexing in the array in its last computation step.

An fn_zone structure for a specific prefix length exists only provided that entries with this prefix length actually exist. All fn_zone structures are linked in a linear list in the order of descending prefix length (using the fz_next element), which is hooked into the fz_zone_list element of the fn_hash structure at the bottom of the fib_table structure. This forms the base of a search with the longest network prefix matching a specific destination address.

```
struct fib_node
net/ipv4/fib_hash.c
```

Each entry in a routing table is represented by a fib_node structure. In its fib_key element, this structure contains the destination prefix (with identical length for all entries of one zone), and its fib_tos_elems includes a TOS value, which is also part of the key used to search a routing table. The type and scope of entry are encoded in fn_type and fn_scope, and the fn_state element stores two flags to manage the structure.

All additional information in a routing-table, which is not required for searching an entry, but represents merely part of the search results, is located in the fib_info structure, which can be reached over fn_info.

```
struct fib_info
include/net/ip_fib.h
```

The fib_info structure represents information about the result of a FIB query, including the output interface to be used and the next hop along the route to the destination system, if necessary. This information is included in a fib_nh structure in the fib_nh of the fib_info structure. The fib_nh element is an array to represent the situation where several equivalent routes lead to the same destination in the FIB. This array is declared with size null, and sufficient space is reserved for new entries that all stated routes can be stored. The number of these is then stored in the fib_nh element of the fib_info structure.

The fib_nh is declared in ip_fib.h and contains the output interface to be used in the form of (nh_oif) as a pointer to the net_dev structure (nh_dev), it also includes the IP address of the next router (nh_gw).

> Though quality information (metric) plays a role in searching, it is not explicitly used. The reason is that it already finds an entry's position in the fib_node list when the entry is inserted, so that entries with lower metric values are automatically found earlier.
