# 19.3.3 Comparing iptables and ipchains

The most important differences between netfilter and the old ipchains architecture are doubtless that the facts mentioned in Section 19.2.2 were removed: New packet filter functions can easily be integrated into the Linux kernel by use of the programming interface introduced in 19.3.2. In addition more complex functions, such as the support of transparent proxies or address-translation modules (NAT), are now implemented as independent modules with clearly defined interfaces. The changes to the existing network code to integrate a new hook for packet-filter functions are limited to single call of the NF_HOOK macro in the netfilter architecture. (See Section 19.3.1).

Moreover, the netfilter architecture changed the path packet streams across the kernel. In contrast to ipchains, iptables now handle each packet based on exactly one of the three rules listed: INPUT, FORWARD, or OUTPUT. The routing decision is made early, before the transit through the INPUT or FORWARD hook, so that forwarded packets do not have to traverse all three hooks (See Figure 19.3). In ipchains (Figure 19.2), all packets had to traverse the input list before a routing decision was made; given this decision, packets were then redirected to a local process or to the forward list. This modification simplifies the rules-listing handling, no undesired dependencies between them occur, and reduces the processing cost in the kernel, so that packets are handled faster.

And finally, there was a slight change to the syntax of the iptables command-line tool used to manage rules lists, compared to the older ipchains. Table 19.1 gives an overview of the most important changes. Most options and parameters are identical. However, iptables rules use uppercase letters; also, DENY was renamed to DROP, and MASQ replaces the former MASQUERADE.
