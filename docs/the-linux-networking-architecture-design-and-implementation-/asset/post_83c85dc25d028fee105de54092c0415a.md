## 16.1 INTRODUCTION

One of the most important functions used by the IP layer (the network layer of the TCP/IP protocol architecture) is to forward packets between communicating end systems across a number of intermediate systems. (See Figure 16-1.) The determination of the route that packets will take across the Internet and the forwarding of packets towards their destination is called routing.

As was mentioned in Chapter 14, the Internet represents a network of networks. Special nodes, which are integrated in all subnetworks that are connected in one place, are used to link these subnetworks; these nodes are called routers. ### 16.1.2 Forwarding and Routing

Routers forward IP packets from one network to another, where the second network is normally “closer” to the destination (not necessarily in the sense of geographic distance, but rather from the first network). To decide in which direction each packet has to be forwarded, the router requires a certain amount of information about the topology, which it stores locally. In the core area of the Internet, the situation is not simple. Rather than a small LAN, there is a large area of the entire Internet that needs forwarding. In addition, it has to be adapted continuously: when new paths are added, when old ones fail, and for these reasons, the size of the global Internet requires automatic methods to update topology information and determine suitable routes. These methods to determine forwarding information in each router are commonly called 'routing.' This means that we can identify two different functions that, together, have to be clearly distinguished: Forwarding of IP packets in routers, which is based on given forwarding information. A router has to look up database and make a decision for each packet that passes through it on its way to the Internet. Routing: determining the best routes over which to transport each packet between networks, and deriving forwarding information about topologies and states regularly between routers within the entire network. Forwarding is implemented in the kernel because its a task of the IP layer. In contrast, routing is handled on higher layers: the routing protocols used to distribute information about topologies and states normally build on top of transport-layer protocols, and the pertinent programs (routing daemons) are user processes running in systems. The interface between the two parts is built by a database in which routing daemon stores its forwarding information, and which IP uses as basis for its decisions when packets have to be forwarded. As mentioned earlier, forwarding information in small networks at the 'outskirts' of the Internet is rather static and can be managed manually—not necessarily with a routing daemon. In this case, the system administrator can use tools like those discussed in Section 16.2 to add forwarding information manually to the database. This method is called static routing, in contrast to dynamic routing, which is based on routing. Routing is not done in the kernel, so it is not discussed in detail in this book. Instead, we refer interested readers to general books about internetworking (e.g., ...). This chapter focuses on forwarding in the IP layer and the information database which is also implemented in the kernel.

## 16.3 IP Addresses

To be able to send packets to arbitrary ends in the Internet, we need a means of unique identification of ends. We know from a previous section that this is accomplished by using IP addresses, which are 32 bits in length and normally represented by four single-byte values in dotted decimal notation for IP Version 4.

Network Addresses and End-System Identifiers In addition to identifying network nodes, IP addresses have another important function involved in the finding of nodes. In fact, if IP addresses were randomly distributed (but unique) values, they could still serve as identifiers, but would be hard to forward packets to a specific destination, because each router would have to know the forwarding direction for each possible destination IP address in the Internet. Considering the enormous number of ends connected to the Internet, this would obviously be very expensive with memory requirement and search time.

To allow for the forwarding direction to be determined efficiently, IP addresses are structured hierarchically, and consist of two different parts: a network address and end-system identifier. The network address is identical for all end systems in a subnetwork; the end-system identifier distinguishes end systems in a specific subnet. During forwarding of packets, the end-system identifier can be totally ignored until the packet arrives in the correct subnetwork. This means that routers do not need to know end-system identifiers; in this way, the division of IP addresses into two parts dramatically reduces the amount of information routers have to store. Because it always forms the beginning of an IP address, the network-address part of an IP address is also called network prefix.

## Address Classes and Classless Addressing

The question we have to answer is about the sizes of the network part and the end-system identifier in an IP address. Three different variants were defined when addressing in the Internet: The address classes A, B, and C, having 7, 16, and 24 bits for the network part and 8 bits for end-system identifier, determined by the first (leftmost) bits of the address. Figure 16–3 illustrates this scheme. This addressing was originally designed by assuming that each physical network would actually have a size from three classes mentioned above. However, it was soon seen that this approach would quickly exhaust all network prefixes. In addition, the existing classes proved to be inappropriate: class-A network could contain almost 16777216 systems, a number that even the largest organizations would hardly need, from the fact that no physical network can handle that number of end systems. In contrast, class-C networks are much more numerous, but cannot hold more than 254 systems, which is not enough in many cases. These limitations motivated the development of technologies to better utilize the existing address space. The basic idea was to have the boundary between the network prefix and end-system identifier at an arbitrary position, instead of only at the three positions dictated by the A, B, and C classes.
