The spanning-tree algorithm runs in three steps:

+   1. **Select the root bridge**: The root bridge is the root of the tree topology we want to build. The problem is now to select one of the bridges as the root bridge. To this / end, we use a similar principle to the one used in token-ring networks: The bridge with the smallest identifier (bridge ID) is selected as the root bridge.

At the beginning, the bridges in the LAN internet select configuration BPDUs periodically with their own identifiers ID to all other bridges. When a bridge receives a BPDU, it is immediately compared with its own bridge ID. If the received root ID is smaller, the BPDU is forwarded. In contrast, the own bridge ID is smaller, it is registered as the root ID and distributed to the other bridges. Eventually, the bridge with the smallest identifier becomes the root bridge.

One major benefit of this principle is its decentralized property. This means that no central management unit is required. However, the path cost in a LAN internetwork does not play any role in determining the root bridge. This means that you won't necessarily select the best topology, as in the Minimal Spanning Tree method.

+   2. **Determine the root port of each bridge**: Each bridge selects the network adapter with the smallest path cost on the path to the root bridge as its root port (root-path cost, RPC). If several paths have the same cost, then the port with the highest priority or (if no priorities are set) the port with the smallest port ID is selected as the root port.

+   3. **Select the designated bridge for a LAN**: When one subnet internetwork is connected to several bridges, so that at least one route over each of these bridges leads to the root bridge, then one of these bridges has to be selected for traffic forwarding to the root bridge. This is the only way to create a tree topology. In a local area network, the bridge with the smallest path cost to the root bridge (the-called root-path cost) is normally selected. The network adapter used to connect to the local area network is called the **designated port**. Consequently, there is only one designated port for each LAN. All adapters of the root bridge are designated ports.

All output adapters that were not selected as root ports or designated ports are locked (i.e., they take the blocking state). Though payload packets will be transported over these ports, they can continue receiving BPDUs. This means that a deactivated adapter can detect a component failure and reactivate itself when needed.

**Behavior When a Component Fails** When an active adapter (i.e., a root bridge or a designated port) fails, then this can be discovered by a message-mechanism. To this end, each bridge manages a max value. If the message value of a BPDU exceeds this value, then the spanning-tree algorithm is restarted to check for which bridges should be active in the new topology. More specifically, bridges where network adapters change state sends the topology-change notification BPDUs described above over the path to the root bridge. This means that all other bridges are informed about a change in topology, so that they can respond accordingly.
