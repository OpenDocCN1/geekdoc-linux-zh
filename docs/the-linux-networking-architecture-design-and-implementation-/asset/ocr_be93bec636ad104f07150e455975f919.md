# 17.5.2 Accessing MBone over the routed daemon

The routed daemon is a tool you can use to connect to MBone. It enables you to build tunnels to other MBone nodes and ensure connectivity. In addition, this daemon enables routing for multicast packets within or at the boundaries of a multicast network. The standard implementation of multicast in UNIX uses the Distant Multicast Routing Protocol (DVMP); see Section 17.5.3).

Like daemons, routed operates in the user-address space and can be started and stopped at runtime. It communicates with the kernel over specific interfaces, which will be included in the course of this chapter. The routed daemon can be changed at runtime, so we can implement different routing algorithms. The routed daemon is not the only multicast routing daemon for Linux, but it is the most popular and the most frequently used.

How Routed Operates Multicast packet forwarding is separate from selecting of forwarding routes; the kernel is responsible for forwarding, and the routing daemon determines the routes. Again, this shows a known principle, the separating of the data path from the control path. To determine routes, the routed daemon obtains information about all incoming multicast packets, including their destination and origin. Using this information, it computes the multicast routing tables and passes them to the kernel over a specific interface. This means that the daemon tells the kernel how it should forward packets from a specific sender to a specific group. The paths or routes for multicast packets are stated in the form of virtual network devices, which were introduced in Section 17.4.2.

Interface Between the Multicast Daemon and the Kernel The routed daemon communicates with the Linux kernel over a special socket. The kernel obtains routing information for multicast packets by setsockopt() calls over a raw socket. routed daemon uses the IPPROTO_ICMP protocol to open the socket a head of time.
