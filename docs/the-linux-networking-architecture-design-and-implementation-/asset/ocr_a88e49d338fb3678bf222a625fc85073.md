The following algorithm shows the source code of the Nagel algorithm.
These few lines are sufficient to achieve the behavior discussed above.

```
tcp_nagle_check() include/net/tcp.h
```

```
static __inline_ int tcp_nagle_check(struct tcp_opt *tp,
               struct sk_buff *skb, unsigned mss_now)
```

```
{
    return (skb->len > mss_now &&
            !(tp->TCPCB_FLAG_URG|TCPCB_FLAG_FIN)
            && (tp->nonagle == 2 ||
            (!tp->nonagle &&
                tp->packets_out &&
                tcp_minshall_check(tp))));
}
```

The Nagel (i.e., the tcp_nagle_check() method) is asked in tcp_snd_test() whether the next segment may be sent. If it wants to prevent the segment from being sent at this time, tcp_nagle_check() returns the true value. If there are reasons for immediate transmission of this data, then it returns false.

The first check is for whether there is a sufficient amount of data to fill a complete segment. If this is the case, there is no reason to delay its transmission further. Consequently, the segment length (skb->len) collaborates with mss_now to determine the amount of data that can be sent at once.

The next check is for whether there are particularly important control packets (e.g., FIN or URG packets). These packets have to be sent immediately, and Nagel’s algorithm must not delay them.

The next line for whether the socket option TCP_CORK was activated (tp->nonagle == 2). It forces only complete packets to be sent.

If all checks done so far have resulted in false, the next checks for whether the Nagel algorithm has been disabled by the socket option TCP_NODELAY. If so, tp->nonagle would have the value and tcp_nagle_check() would return false, which means that the segment can be sent.

However, if the Nagel algorithm is still active, then tcp_minshall_check() (described later) checks for whether incomplete packets are on their way (i.e., packets that have not yet been acknowledged). If there are no small and unacknowledged packets in the connection, this data packet may be sent; otherwise, it is to be delayed.

The previous line checks for whether acknowledgments for packets are still missing. This query is much faster than the method call in the next line (tcp_minshall_check(tp)). Lazy evaluation saves time, because the slower method is invoked only if the fast query has not yet returned a result.
