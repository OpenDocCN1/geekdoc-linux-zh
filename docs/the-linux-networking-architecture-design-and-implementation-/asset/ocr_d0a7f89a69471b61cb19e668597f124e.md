If the driver was translated as a kernel module, the driver itself has to create a net_device structure for each existing network adapter. This can be done by the module itself, or for Ethernet drivers, by use of function init_etherdev().

The list of network devices is used to store entries for those network adapters actually existing. For this reason, before an entry is added to this list, we check for whether a network adapter can be found for a driver. To check this, each of these has an init() or probe() function. It is very specific to each adapter and will be described in more detail in Section 5.3. Among the exception, are logical network devices, such as loopback (lo) and PPP (ppp), which don't have to rely on underlying hardware.

The following discussion assumes that we want to register a network device based on an Ethernet adapter. During booting of the system or loading of the driver module, the appropriate adapter was found. However, for the network device can be added to the list of known network devices (dev_base), the net_device structure should have been initialized so that the network device can be actually activated and used. The kernel has certain functions (mainly for Ethernet adapters) that facilitate the driver programmer's work.

```
init_netdev()                               drivers/net_init.c
```

init_netdev(dev, sizeof_priv, mask, setup) initializes the important elements from the general range of the net_device structure. (Section 5.1.1). First, we have to check whether there is a net_device structure at all. If the value null was entered for dev in the call, init_alloc_dev() is used to create a new net_device structure, which is also added to the list of network devices by register_net_device() at the end of the initializing process. If the net_device structure existed already before the call, then the caller has to register.

Subsequently, the name of the network device is verified. If the dev->name consists of an empty string or with a blank, then the kernel use the method dev_alloc_name() to allocate a name. In this case, there is an option to use the mask parameter to specify a prefix which is then added to a valid name for a network device by the known scheme. For example, the prefix%d produces the name test1, and so on, depending on the network devices already existing with this prefix. If the prefix does not contain a formatting character (%d), then the name should be unique; otherwise consecutive numbering is not possible, and the function will return an error. Consequently, the network device cannot be initialized.

Once a network device has a unique name, we verify that parameters for its hardware configuration have been stated when the system boots. For this, the list dev_boot_setup in the method netdev_boot_check() is searched for an entry with the name of the new device. If there is such an entry, the parameters irq, name_start, mem_end, and base_addr are taken and added to the net_device structure of the network device.
