# SENDING AND RECEIVING UDP DATAGRAMS

The sending of UDP packets, starting from the system call at the socket interface and running all the way until the completed packet is added to the output queue of the network interface, is handled in just one pass, the receiving of UDP packets requires two separate steps: Once a packet has been received, udp_recv() first allocates to a socket in bottom-half context and places it into that socket's receive queue. From there, the packet is fetched via system call of a user process, which is mapped to udp_recvmsg().

The function udp_sendmsg() is invoked over the socket interface whenever a UDP packet has been sent: The different kinds of systems calls all lead to this function's being being called. Its parameters are a socket structure with the state of the sending PF_INET socket, a pointer to a msg structure that specifies the receiver and payload, and the length in octets.

First, a locally created fakeheader structure takes the destination address and the destination port from the msg_name_element of the msg structure. The destination doesn't have to be specified explicitly only if a default address has previously been assigned to this socket via udp_connect(). In this case, the information from the socket structure is used. The source address and the source port derive from the sock structure. Additionally, they are stored in an ipcm_cookie structure. This structure, which we will not describe here in detail, serves later on to the addresses, the device identifier, and the IP options (if applicable) to the Internet Protocol.

Any control messages in the msg_control element of the msghdr structure are processed by calling the function ipc_msg_send(), and the results are registered in the ipc_cookie structure. Control messages can be used to modify the address or to pass IP options, which will then also be registered in the ipc_cookie address. If no IP options are specified, the IP options stored in the socket structure, will be used.

A routing cache has to be procured, so it is also necessary to handle the source routing IP options before; the address of the first intermediate station might need to be instead of the destination address.

If the socket had previously obtained a routing cache by udp_connect(), and if the corresponding destination address has not been changed in the process of udp_sendmsg(), then this routing cache is now checked. If this produces a negative result, or if the destination address was changed, then ip_route_output() is used to produce a new routing cache entry (which is stored in the socket structure).
