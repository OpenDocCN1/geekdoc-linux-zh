## 24.2 Sending TCP Segments

This section describes how payload is sent over a TCP instance (i.e. how TCP segments containing payload are transmitted). The transmission of acknowledgments (ACKs) is initiated by incoming TCP segments or by the Delayed ACK timer. (See Sections 24.2.1 and 24.5.)

# 468 Chapter 24 Transmission Control Protocol (TCP)

A TCP instance uses the send() system call to send payload. The send() system call calls the tcp_sendmsg() function to be invoked. This function is present as a handling routine for this system call in the tcp_prout structure (net/ipv4/tcp_ipv4.c). Figure 24–4 shows the invocation hierarchy during the process of sending payload over the TCP instance.

# tcp_sendmsg() net/ipv4/tcp.c

tcp_sendmsg(sock, msg, size) copies payload from the user-address space into the kernel and starts sending this data in the form of TCP segments. Before it starts sending, however, it checks on whether the connection has already established or whether it is in the TCP ESTABLISHED state. If no connection has been established yet, the system call waits for wait_tcp_connect() for a connection.

The next step computes the maximum segment size (tcp_current_mss) and starts copying the data from the user-address space. First, it checks for a “half empty” segment is present at the end of the socket's transmit queue (tp->write_queue), which could be used to pack data. Subsequently, if no small segment was available, tcp_alloc_skb() creates new socket buffers. The data to be sent is copied from the user-address space into socket buffers, and tcp_send_skb() is invoked to order data within the transmit queue.

tcp_send_test(sk, skb, cur_mss, nagle()) is an inline method that checks whether the TCP segment, skb may be sent at the time of invocation. It verifies the criteria specified in RFC 1122 to ensure standard-compliant behavior, and mainly, that there is sufficient space in the transmit and congestion-control windows and what the Nagle algorithm says with regard to sending this packet. The behavior of participating algorithms is described in Section 24.4.

/* This checks if the data bearing SKB (usually tp->send_head) should be put on the wire now. */
```c
static __inline int tcp_send_test(struct tcp *opt, struct sk_buff *skb, unsigned cur_mss, int nagle) {
    * RFC 1122 - Section 24.3:
    * We must queue if
    * a) The right edge of this frame exceeds the window
    * b) There are packets in flight and we have a small segment
    * [SWS avoidance and Nagle algorithm]
    * part of SWS is done on packetization
    * segments in flight. (tcp_nagle_check)
    * c) We have too many packets 'in flight' 
    * Don't use the Nagle rule for urgent data (or for FIN).
    */
    return ((nagle==1) || tp->write_queue) &&
        !tcp_nagle_check(tp, skb, cur_mss, nagle)) &&
        (tp->packets_inflight < tp->snd_cwnd) ||
        (SKB_CB(skb)->flags & TCP_CB_FIN) &&
        !after(SKB_CB(skb)->end_seq, tp->snd_una + tp->snd_win));
}
```

# tcp_transmit_skb() include/tcp_output.c

tcp_transmit_skb(sk, skb) is responsible for completing the TCP segment in the socket buffer, and for subsequently sending it over the Internet Protocol. To this end, it fills the TCP packet header with the appropriate values from the opt structure—for example, much like an explicit credit specified by tcp_select_window(). tcp_syn_build_options() registers the TCP options for SYN packets, and tcp_build_and_update_options() registers the options for all other packets.

Subsequently, all actions required to send a payload-carrying segment or a segment with ACK flag are executed:

If the ACK flag is set, the number of permitted Quick ACK packets decrement in the tcp_event_ack_sent() method provides that the connection is in the Quick ACK mode. Subsequently, the timer for delayed ACKs is stopped, because the next step needs an acknowledgement.

If the segment to be sent carries payload, we first have to check for whether an interval corresponding to the retransmission timeout (stored in tp->reime) has elapsed since the last data segment (stored in tp). If this is the case, the congestion window is set to the minimum value (tcp_cwnd_restart), as specified in RFC 2861.

Subsequently, the function pointer tp->af_specific->queue(), which references the transmitting function—depending on the Internet Protocol version (e.g., ip_queue_xmit() for IPv4)—passes the socket buffer to the IP layer for transmission.

Finally, the tcp_enter_cwd() method adapts the threshold value for the slow-start algorithm. This completes the transmit process for the TCP segment within the TCP instance, unless no acknowledgement arrives for this packet during the retransmission timeout, so that it would have to be retransmitted; see details in Section 24.5.
