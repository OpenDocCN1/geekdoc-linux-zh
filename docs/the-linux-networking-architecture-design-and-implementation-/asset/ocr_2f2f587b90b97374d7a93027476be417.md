# 15.1 USING THE ADDRESS RESOLUTION PROTOCOL

As mentioned above, the Address Resolution Protocol (ARP) is a decentralized protocol to resolve address mappings between layer-3 and layer-2 addresses in local area networks. Figure 15-1 shows how ARP works. When computer A wants to send a packet to router R in the same LAN, it needs the layer-2 address, in addition to the IP address, to be able to tell the data link which computer is supposed to get this packet. For this purpose, computer A sends an ARP Request to all computers connected to the LAN. This request is generally sent in a broadcast message using the MAC broadcast address (FF:FF:FF:FF:FF:FF). The intended computer can see the destination ARP PDU for this request so computer returns a reply to the requesting computer A, including its MAC address. Computer A now learns the MAC address of R and can instruct its data link layer to deliver the packet.

To avoid having to request the MAC address again for subsequent packets, A stores the MAC address of R in a local table—the ARP cache (See Section 15.3.). Computer R can also extract the MAC address of A from its request and store that in its own ARP cache. It can be seen from A's request that A and R will communicate soon, which means the MAC address of A will be needed. In this case, we avoid one ARP request, because the mapping will have been previously stored.
