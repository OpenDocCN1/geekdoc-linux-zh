Again, the Ext Len field specifies the length of the packet-header extension in 8-bytes, excluding the first 8 bytes. Routing Type specifies the variant of the Routing packet-header extension RFC 2460 standardizes only Loose Routing (known from IPv4) to Routing Type = 0x00. The Segments Left parameter handles the number of nodes still has to visit. The last field type-specific information: the addresses of nodes left along the path (in addition to four reserved bytes, in the case of Loose Routing).

How an IPv6 packet includes the Routing packet-header extension is forwarded can be explained by a simple practical example. Assume that an IPv6 packet should be transported from the sender, over nodes R1 and R2 to the receiver. These nodes are addressed directly in the IPv6 packet header, and the Routing packet-header extension specifies the previous and subsequent destinations, the end system. Each addressed node replaces the IPv6 receiver address by an entry for the next hop, and then replaces this by its IPv6 address. In this example, the IPv6 packet would be composed of in the following statistics:

+   - Node S: Source = S, Destination = R1, Segments Left = 2, Address[1] = R.
- Node R1: Source = S, Destination = R2, Segments Left = 1, Address[1] = R1, Address[2] = R.
- Node R2: Source = S, Destination = R, Segments Left = 0, Address[1] = R1, Address[2] = R2.
- Node R: Source = S, Destination = R, Segments Left = 0, Address[1] = R1, Address[2] = R2.

The Fragment packet-header extension is required for sending an IPv6 packet to a receiver when its size is larger than the maximum packet size (Maximum Unit–MTU) of a connection on the route. In contrast to IPv4, an IPv6 packet is fragmented by the sender only, never in the routers traverses along the way. The Fragment packet-header extension is specified by the Next value 0x2C and looks like this:

| 8 | 16 | 29 | 32 |
| Next Header | Reserved | Fragment Offset | Res | M |
| Identification | |

Each of the two reserved fields has to be initialized to null. The 13-bit Offset specifies the offset (8-byte units) of the data following this packet-header extension in relation to the fragmentable part of the original packet. The M field specifies whether more fragments are to follow (M = 1) or this is the last of IPv6 packet (M = 0). This corresponds to the segmenting and reassembling in IPv4. The Identification field identifies packets belonging together by a unique number. This number must be assigned only once for each sender/receiver relationship during a packet's lifetime, to avoid confusion with other fragmented IPv6 packets. The details are left to the implementation.
