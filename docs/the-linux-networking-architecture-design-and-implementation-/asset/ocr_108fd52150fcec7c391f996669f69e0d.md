# 12.4.5 Implementing the Spanning-Tree Protocol

This section describes how the spanning-tree protocol according to IEEE 802.1ld and the relevant functions are implemented. The spanning-tree protocol is used to prevent cycles in a redundant LAN network. The algorithm operates in a decentralized way: Each station has to work out the current state in the LAN network from the information contained in control packets (BPDUs). For example, each bridge initially assumes that it is the root bridge, and probably has to learn that this is not so from incoming BPDU.

For this reason, the implementation of the spanning tree protocol is based on the fact that the "best" configuration is stored in each port. This means that each new incoming message is verified to see whether the information it contains is better than the information currently stored, so that the currently best configuration is accepted. By comparing the configuration message most recently received with the information available on the bridge itself, it is easy to figure out the root bridge, the root port, and the designated ports.

This also means that all steps are executed consecutively for each configuration message with better information. This means that the root bridge is not defined in all bridges to then take the cost for all bridges, and subsequently the knowledge of the immediate neighbors is added, and so on, until the configuration messages have visited the entire LAN network so that the bridges can make their optimal choice for the LAN internet. This shows clearly that a real-world implementation does not necessarily have to correspond to the theorical model to be efficient.

One major benefit of this implementation is that relatively few configuration messages must be exchanged. How fast a tree structure can build depends on the bridges that send their configuration messages first. It is normally beneficial when bridges with smaller identifiers or higher priorities send configuration messages earlier. However, bridges do not immediately change from the blocking into the forwarding state; they take various intermediate states where no data packets may be forwarded, so the probability of temporary cycles is low.
