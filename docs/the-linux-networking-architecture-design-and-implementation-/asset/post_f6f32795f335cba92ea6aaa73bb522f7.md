The most important structure within the BSD socket support is struct socket.
It is defined in include/linux/net.h:

```c
struct socket {
  struct_state       state;
  unsigned long      flags;
  struct proto_ops    *ops;
  struct inode        *inode;
  struct fasync_struct *fasync_list; /* Asynchronous wakeup list*/
  struct file         *file; /* File back pointer for gc */
  struct sock         *sk;
  wait_queue_head_t wait;

  short               type;
  unsigned char      passcred;
};
```

This structure is slightly reduced, compared to that in earlier kernel versions.
The socket state stored in state can take the following values (include/linux/net.h): SS_FREE (not busy), SS_UNCONNECTED (not connected), SS_CONNECTING (currently being connected), SS_CONNECTED (connected), SS_DISCONNECTING (currently being disconnected). The flags are required to synchronize accesses. The ops pointer references the protocol operation of the connected protocol (e.g., TCP or UDP) after the initialization. Just as there is an inode for each file in Linux, an inode is assigned to each socket. A pointer to the file structure is stored in file; this is connected to the socket and can also be used to address it. If any process is waiting for events at this file, then that process can be reached via fasync_list.

A matching sock structure can be used via the sk pointer. This structure is initialized by protocol-specific sockets underneath the BSD sockets (e.g., PF_INET sockets) to this pointer. The wait entry serves to implement synchronous (blocking) request. The type field serves to store the second parameter by the same name of the socket in the file. The administrative parameters are defined in include/asm/socket.h: SOCK_STREAM, SOCK_DGRAM, SOCK_RAW, SOCK_RDMA, SOCK_PACKET, and SOCK_PACKET. (The last should not be used.)

Now let's see how of this works in the Linux kernel when socket() is invoked by an application. As was mentioned, this call is passed within the function sys_socketcall() in net/socket.c by invoking the function sys_socket().

## 26.2 BSD Sockets

```c
sys_socket()
net/socket.c
```

This function initializes the socket structure and allocates an inode and a file descriptor by calling the functions sock_create() and sock_map_fd().

```c
sock_create()
net/socket.c
```

In this function, the first step checks whether the protocol family is available. An attempt may be made to load the family module. Subsequently, the type field of the socket structure is described, and two additional functions are invoked: sock_alloc(), to provide a socket, and net_families[family]->create(). The function sock_alloc() is described later on. net_families[family]->create() executes the create() function of the lower-layer socket. For this purpose, respective registers register with the vector struct_proto_family *net_families[NPROTO] when the system starts or when the appropriate module is loaded by the sock_register() function(net/socket.c). They also pass the name of the protocol family and a pointer to the create() function. In this case, example is done by the sock_register(&inet_family_ops) (net/ipv4/af_inet.c), call, which exports the inet_create() function. The control flow allows the BSD socket area and is passed to the implementation of the lower-layer socket.

```c
sock_alloc()
net/socket.c
```

This function is initially invoked by sock_create(); it reserves a new inode and allocates a socket structure. The fields of the socket structure are initialized to null, or state is initialized to SS_UNCONNECTED.

```c
sock_map_fd()
net/socket.c
```

This function uses a number of helper functions to allocate a file descriptor for the socket, which is used to address this socket. It is also called socket descriptor, but there is no difference from other descriptors. This is the reason why you can use read() and write() calls to read or write over a socket. The file entry for the socket structure is also set in the sock_map_fd() function.

The create() function of the lower-layer socket, is invoked by net_families[family]->create()—as described before—now it has to fill the fields of the socket structure with entries—in particular, the ops pointer, which refers to the proto_ops (include/linux/net.h) structure. This structure serves to supply the BSD socket with the functions of a lower-layer socket.

```c
struct proto_ops {
    int    family;
    int (*release)  (...);
    int (*bind)     (...);
    int (*connect)   (...);
    int (*socketpair) ();
    int (*accept)();
    int (*getname)();
    unsigned int (*poll)();
    int (*ioctl)();
    int (*listen)();
    int (*shutdown)();
    int (*setsockopt)();
    int (*getsockopt)();
    int (*sendmsg)();
    int (*recvmsg)();
    ssize_t (*sendpage)();
};
```

Notice that not all of these functions have to be implemented: in such case, however, an error should be returned. This also makes the sending of data over BSD socket understandable: For example, when an application sends data over the sendto() call, the function sys_socketcall() executes sys_sendto() in net/socket.c. There message consisting of transmit data, the address, and control fields is composed. Finally, the function sendmsg() uses socket->ops->sendmsg() to invoke the transmit of the respective lower-layer protocol.

BSD sockets support many different protocols, so a general structure, sockaddr (include/linux/socket.h), was defined. It consists of a protocol-family identifier and the corresponding address:

```c
struct sockaddr {
    sa_family_t sa_family;
    char            sa_data[14]; /* address */
};
```

## 26.3 PROTOCOL-SPECIFIC SOCKETS

The central structure of all protocol-specific sockets underneath the BSD sockets is struct sock. This structure was oriented to TCP/UDP and IP in earlier kernel versions. Along with the addition of other protocols (e.g., ATM), the sock structure was extended, and other entries were partially removed from the structure. Initially created construction having a number of entries needed for a few protocols. With the introduction of the three structures (net_pinfo, tp_pinfo, and prot_info), each of which contains a reference to protocol options of the matching layer, this situation would gradually improve, and the structure is still rather extensive, but we will introduce only the entries of interest in the following sections.

### 26.3.1 PF_INET SOCKETS

This section describes the initialization on level of PF_INET sockets when an application uses socket().

```c
inet_create() net/ipv4/inet.c
```

As has mentioned, this function is invoked by the function socket_create() to initialize the socket structure. Initially, the state of the BSD socket is set to SS_UNCONNECTED, and then the function sk_alloc(), which is described in Chapter 4, allocates a socket structure. The protocol family can only be PF_INET at this point, but we still have to distinguish between type and protocol. This is now done by comparing against the information in a list, struct inet_protosw inetsw_array, which is created by inet_register_protosw() (net/ipv4/inet.c) when the kernel starts.

Next, the ops of the BSD socket structure are filled. The sk pointer connects the BSD socket to the new socket structure, and the latter is connected to the BSD socket by the ops pointer. (See sock_init_data() in net/core/sock.c.) Similarly to the proto_ops structure, the proto structure supplies the functions of the lower-layer protocols:

```c
struct proto {
    void (*close) (...);
    int (*connect) (...);
    int (*disconnect) (...);
    struct sock* (*accept) (...);
    int (*ioctl) (...);
    int (*init) (...);
    int (*destroy) (...);
    void (*shutdown) (...);
    int (*setsockopt) (...);
    int (*getsockopt) (...);
    int (*sendmsg) (...);
    int (*recvmsg) (...);
    int (*bind) (...);
    int (*backlog_rcv) (...);
    void (*hash) (...);
    void (*unhash) (...);
    int (*get_port) (...);
    char name[32];
    struct {
        int use;
        unsigned char _pad[SMP_CACHE_BYTES - sizeof(int)];
    } stats[NR_CPUS];
};
```

Consequently, the proto structure represents the interface from the socket layer to the transport protocols. The hash() and unhash() functions serve to position or find a socket structure in a hash table.

Finally, inet_create() invokes the inet() function for the identified protocol from the proto structure, if it exists. For example, this would be the function tcp_v4_init_sock() (net/ipv4/tcp_ipv4.c) in TCP. A similar function exists in net/ipv4.c for direct access to IP (SOCK_RAW). The other protocol functions are now available over the socket structure in these init() functions.
