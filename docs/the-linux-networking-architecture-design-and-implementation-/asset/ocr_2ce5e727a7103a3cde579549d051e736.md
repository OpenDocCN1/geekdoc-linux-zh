fn_hash_select_default() selects one out of several default routes, considering whether the intermediate system specified as the next router is currently reachable. fn_hash_insert(), fn_hash_dump() serve to insert, delete, and display entries over the RT netlink interface.

fn_hash_flush() removes all fib_info structures of a zone that are premarked as invalid.

fn_hash_get_info() serves to display routing tables over the proc file system.

# Interfaces to the User-Address Space From within the user-space, you can manage routing tables both over the traditional ioctl(1) interface and over RT netlink.

For the RT netlink interface, the functions inet_rtm_newroute(), inet_rtm_delete(), and inet_dump_fib() from net/ipv4/fib_frontend.c are registered in the table inet_rtlink_table[] in net/ipv4/devinet.c so they can be invoked to add, delete, or output a routing table and handle corresponding messages.

ioctl() system calls are handled by ip_rt_ioctl(net/ipv4/fib_frontend.c), which is invoked by the general routine that handles ioctl() calls at PF_INET sockets. (See Chapter 26.) The parameters for the call are converted into an RT netlink message by fib_convert_entry() and passed to inet_rtm_newroute() or inet_rtm_delete() for further handling.

# Proc File System The contents of the pseudo file /proc/net/route, which can be used to view the main routing table, are created by the function (net/ipv4/fib_frontend.c) fib_get_procinfo(), using proc_create()... The function creates a header line and uses the function pointer tb_get_info() from the main table, which normally points to fn_hash_get_info(ipv4/net/fib_hash.c), to output the data. All, fib_node structures in fib_zone_list are visited, and the appropriate data is eventually output by fib_node_get_info() (net/ipv4/fib_semantics.c).
