    int i;
    int base_addr = dev->base_addr;

    SET_MODULE_OWNER(dev);

    if (base_addr > 0x1ff) /* Check a single specified location. */
        return netcard_probe(dev, base_addr);
    else if (base_addr != 0) /* Don't probe at all. */
        return -ENXIO;

    for (i = 0; i < netcard_portlist[i]; i++) {
        int ioaddr = netcard_portlist[i];
        if (check_region(ioaddr, IO_NUM))
            continue;

        if (netcard_probe(dev, ioaddr) == 0)
            return 0;
    }
    return -ENDEV;
}
```

Once we have selected a basic address for the network adapter in the above method, the method netcard_probe(dev, ioaddr) tests whether the adapter we searched for is really at this address. For this purpose, the method has to check specific properties of the card, where access should be limited to read access on the I/O ports to ensure that no other adapters will be involved. At this point, it is still unknown whether the adapter we are searching for is really present in the base address.

A simple method to identify the address compares the manufacturer identification with the MAC address. Each network adapter has a unique MAC address, where

the first three bytes identify the manufacturer. This identification must correspond with the manufacturer code of the searched card. In any event, additional checks should be done, but they are not adapter-specific and not described in detail here.

Once we are sure that the network adapter is searched for in the basic address ioaddr, this address is stored in the net_dev structure (dev->base_addr), and the network device is initialized. The I/O ports, starting from the base address, are reserved by request_region(ioaddr, IO_NUM, cardname) and at the end of the initialization function to ensure that no other initialization method can get access to it.

The initialization process can be divided into the following phases:

- If the network adapter does not support dynamic interrupt allocation, then the interrupt set by jumpers on the network adapter should be determined and reserved at this point. The kernel searches for the interrupt number. Calling the method autoirq_setup() makes the kernel remember interrupt lines currently registered in a variable. Subsequently, the network adapter should be caused to trigger an interrupt. We can then use the method autoirq_report() to discover, from the previously stated and the actual interrupt vectors, which interrupt was active. Next, the interrupt found is reserved for the network adapter by the method request_irq(). In addition, the DMA channel is determined and reserved by request_dma().

- For modern adapters that do not require specific interrupt or DMA lines, the two system resources are not allocated at this point, but rather when the device is opened. This is necessary to avoid conflicts with other devices.

- Once system resources have been allocated (for older adapters only), memory is reserved for the private data structure of the network device dev->priv and initialized. This data structure stores the private data of the network driver and statistic information collected during the operation of the network device (net_dev_stats structure).

- Finally, the references to driver-specific methods are set in the net_dev structure, so they can be used by the higher layers and protocols. The adapter-specific methods (see also Section 5.1.1) have to be explicitly set. Methods specific to the MAC protocol used (e.g., Ethernet) can be set by special methods (e.g., ether_setup()).

If the network adapter was found and all data structures were initialized correctly, then dev->init() returns 0.

## 5.3.2 Opening and Closing a Network Adapter

We know from 5.2 that network devices are activated and deactivated by the command ifconfig. More specifically, ioctl() invokes the methods ifopen() or close(). Where the general steps to activate and deactivate a device are executed. The adapter-specific actions are handled in the driver methods_open() and stop(), respectively, of the present network adapter. We use the skeleton driver sample to explain these steps.

```c
net_open
drivers/net/isa_skeleton.c
```

The open() method is responsible for initializing and activating the network adapter. At the beginning, the system resources required (interrupt, DMA channel) are registered. To make available these system resources, the kernel offers various methods you can use as helpers. These methods were introduced briefly in the previous section. System resources are reserved in the open() method for modern adapters, which do not have fixed values for IRQ and DMA lines. For older cards, they are searched for and reserved in the init() method. See init().

Once a network adapter has been initialized successfully, the counter of the module should be incremented for modularized drivers. From the kernel, we can use the macro MOD_INC_USE_COUNT for this purpose.

The network adapter is initialized when all system resources have been allocated successfully. Each adapter is initialized in an individual manner. Normally, a specific value is written to a hardware register (I/O port) of the adapter, which causes the adapter to initialize itself.

The transmission of packets over the network device is started by net_start_queue(dev). Finally, the value 0 is returned if the transmission was successful; otherwise, a negative error code is returned.
