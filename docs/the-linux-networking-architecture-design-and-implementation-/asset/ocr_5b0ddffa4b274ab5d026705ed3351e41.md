ip6_rcv_finish() function invokes ip6_forward() when an IPv6 packet has been forwarded. The latter checks to see whether forwarding is enabled; otherwise the packet could simply be dropped. Subsequently, the packet's lifetime is checked, and if the Hop Limit field is smaller than or equal to one, the packet is actually dropped, and an ICMP6 message is sent to the corresponding node. If the IPv6 packet is not explicitly sent over this computer or to the destination (which means the address of the local node is in the Routing packet-header extension), and if the packet would leave the computer over the same interface on which it arrived in the local node, then an ICMP message of the type Redirect is returned to the sender. IPv6 packets with a Link-Local, Multicast or Loopback source address will also be dropped. The final check is to see whether the length of the new MTU is exceeded and, if so, to send an ICMP6_PKT_TO_BIG message to the sender. Finally, the NETFILTER call NF_IP6_FORWARD passes the IPv6 packet to the ip6_forward_finish() function, which in turn, invokes ip6_output().

Packets that have to be delivered locally are taken by the ip6_rcv_finish() function and passed either to ip6_mc_input() or directly to ip6_input(). However, ip6_mc_input() merely checks to find out whether the multicast address is addressed to this computer, and if so, passes it to ip6_input(). ip6_input() invokes ip6_input_finish() function over a NF_IP6_LOCAL_IN netfilter and assumes further processing.
