
## 21.3 Implementing the NAT Module

```c
struct ip_nat_multi_range  linux/netfilter/ipv4/ip_nat.h
```

The ip_nat_multi_range structure is used mainly to specify the set of addresses for address translation. It contains one or several structures of the type ip_nat_range, each specifying a continuous IP address range, and a rangesize field that takes the number of contained ip_nat_multi_range structures:

```c
struct ip_nat_multi_range
{
  unsigned int rangesize;
  /* hangs off end. */
  struct ip_nat_range range[1];
}
```

```c
struct ip_nat_range  linux/netfilter/ipv4/ip_nat.h
```

The ip_nat_range structure serves to represent a continuous IP address range; the range boundaries are specified in the min_ip and max_ip fields:

```c
struct ip_nat_range
{
  /* Single range specification. */
  /* Set to OR of flags above. */
  unsigned int flags;
  /* Inclusive: network order. */
  u_int32_t min_ip, max_ip;
  /* Inclusive: network order */
  union ip_conntrack_manip_proto min, max;
};
```

If the flags bit value contains the IP_NAT_RANGE_PROTO_SPECIFIED, then the min and max fields additionally specify a protocol-specific address range: a port number for TCP and UDP, a value range from the ICMP ID for ICMP.

NAT fully relies on the means offered by the netfilter architecture to manage the selection needs to pack packets requiring an address translation. For this purpose, two branch destinations, SNAT and DNAT, are defined with the functions ipt_snat_target() and ip_dnat_target(), which do the actual address-translation work. A multipurpose parameter, targetinfo, is used to pass the address range available for translation to these functions in the form of an ip_nat_multi_range.

```c
struct ip_nat_info  linux/netfilter/ipv4/ip_nat.h
```

As explained in Chapter 20, the connection-tracking module creates a data structure of the type ip_contract for each session flow, to store all relevant information. If the NAT functionality was activated in the Linux kernel (CONFIG_IP_NAT_NEEDED), then this structure additionally contains a nat substructure, and the info field of that structure contains a structure of the type ip_nat_info:

```c
struct ip_conntrack
{
    ...
#ifdef CONFIG_IP_NF_NAT_NEEDED
    struct {
        struct ip_nat_info info;
    ...
    } nat;
#endif /* CONFIG_IP_NF_NAT_NEEDED */
};
```

struct ip_nat_info structure stores the address bindings of a session flow:

```c
struct ip_nat_info
{
  /* Set to zero when conntrack created: bitmask of maniptypes */
  int initialized;

  unsigned int num_maps;
  /* Manipulations to be done on this conntrack. */
  struct ip_nat_info_manip manips[IP_NAT_MAX_MANIPS];
  /* The mapping type which created us (NULL for null mapping). */
  const struct ip_nat_mapping_type *mtype;
  struct ip_nat_hash byysource, byipspro;
  /* Helper (NULL if none). */
  struct ip_nat_helper *helper;
};
```

The initialized bit vector specifies whether the address binding for the source-address (bit 0) or the destination address (bit 1), or both, was initialized.

The num_maps field specifies the number of executable manipulations stored in the manips vector. Manipulations are counted separately at different hooks and for different directions. Each of these manipulations is represented by a structure of the type ip_nat_info_manip.

The bysource and byiproto fields include hash values used to sort the structure in the two hash tables described below, and helper is a pointer to an optional helper module. (See Section 21.4.2.)

```c
struct ip_nat_info_manip             linux/netfilter_ipv4/ip_nat.h
struct ip_nat_info_manip
{
    /* The direction. */
    u_int8_t direction;
    /* Which hook the manipulation happens on. */
    u_int8_t hooknum;
    /* The manipulation type. */
    u_int8_t maniptype;
    /* Manipulations to occur at each conntrack in this dir. */
    struct ip_conntrack_manip manip;
};
```

The ip_nat_info_manip structure represents a manipulation or address binding. It contains the direction (IP_CT_DIR_ORIGINAL for the forward direction, IP_CT_DIR_REPLY for the reverse direction), the netfilter hook number, and the address translation type (IP_NAT_MANIP_SRC for source NAT, IP_NAT_MANIP_DST for destination NAT), and its ip_conntrack_manip structure includes the IP address and port number to which the former address should be mapped.

To manage addresses, the NAT module uses two tables, bsource and biiproto, where collisions are resolved by linear lists. The biiproto table is used to account for mappings, to ensure that no mappings map to the same IP address.
