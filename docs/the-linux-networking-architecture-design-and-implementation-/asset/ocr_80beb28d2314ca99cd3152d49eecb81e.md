Linux distinguishes between synchronous and asynchronous PPP, depending on whether the underlying TTY device supports packet-oriented data transmission (synchronous—for example, ISDN with HDLC the layer-2 protocol) or works with a continuous byte stream (e.g., in a modem connection).

We will discuss the asynchronous transmission over a serial interface in more detail later, because it requires more functionality than synchronous PPP. The ISDN subsystem of Linux has its own, independent PPP implementation, which is not discussed here.

# 8.1.1 Subprotocols

Figure 8–2 shows the structure of a (synchronous) PPP packet. Synchronous PPP processes entire frames of the lower-layer protocol, which is the reason why it is not necessary to specify the length. Asynchronous PPP additionally requires frame detection, similar to SLIP (See Section 7.1.1.) Section 8.3.5 describes how this frame detection is implemented in PPP.

The first 16 bits of a PPP packet specify the content encapsulated in the payload field. Table 8–1 gives an overview of the protocol numbers used. The numbers are built by the address-extension scheme of the HDLC protocol [ISO93], so that the protocols most frequently used can be encoded in one byte. All protocols where the first bit of the higher-order byte is deleted and the first bit of the lower-order byte is set (i.e., all have odd numbers). However, truncating the protocol field to 8 bits means that both communicating peers have to support this mode. Linux doesn’t know this version, and which configuration attempts of the peer are blocked off.
