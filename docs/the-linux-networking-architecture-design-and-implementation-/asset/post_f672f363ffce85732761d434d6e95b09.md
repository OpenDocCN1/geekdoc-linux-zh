
# Chapter 2 The Kernel Structure

A maximum of 32 software interrupts can be defined in the Linux kernel. Note that only four were defined in the Versions 2.4.x. This includes the IRQs NET_RX_SOFTIRQ NET_TX_SOFTIRQ, which have ensured efficient protocol handling since the kernel Version 2.4, and the soft IRQ TASKLET SOFTIRQ, which is used to implement the concept of tasklets, further described later in this chapter.

Software interrupts differ clearly from the tasklet and bottom halves of activity, as we have seen in Tables 2-2 and 2-3. The most important properties of software interrupts are the following:

- A software interrupt can run concurrently in several processes. This means that the handling routine has to be implemented reentrant (e.g., with net_rx_action). If critical sections exist in a software interrupt (e.g., any global variable accesses), then they must be protected by locks.
- A software interrupt cannot interrupt itself while running on a processor.
- A software interrupt can be interrupted during its handling on a processor only by a hardware interrupt.

Calling `in_softirq(include/asm/softirq.h)` causes a function to check immediately whether it is currently in a software interrupt; see details in [Russ0b].

## 2.2.4 Tasklets

Tasklets are a combination of parallel executable (but lock-intensive) software interrupts and the bottom halves, where we can talk neither parallelism nor of performance. Tasklets were introduced to replace the bottom halves.

Tasklets have the following properties:

- The function `tasklet_schedule(&tasklet_struct)` can be used to schedule a tasklet for execution. A tasklet is run only once, even if it was scheduled for execution several times.
- A tasklet can run on one processor at any given time.
- The macro `DECLARE_TASKLET(name, func, data)` can be used to define a new tasklet, where name denotes a name for the `tasklet_struct` data structure and func denotes the tasklet's handling routine. When the tasklet is to run, then the pointer data, pointing to private data, if applicable, are passed to the function `func(c)`.
- `tasklet_schedule()` is used to schedule a tasklet for execution; `tasklet_disable()` can be used to stop a tasklet from running, even when it is scheduled for execution. It remains scheduled for execution or can be rescheduled. `tasklet_enable()` is used to react a deactivated tasklet. However, if that tasklet was not scheduled for execution, it will not run when you activate it.

> In this connection, we have to differentiate between the general concept of a bottom half that can be implemented by a tasklet (a soft IRQ) and a bottom half in the Linux kernel. In contrast, the form of activity of a bottom half is Linux-specific and denoted by sans-serif font in this text.

## 2.2.5 Bottom Halves

Bottom halves (BHs) were the main form of activity in the kernel in early kernels. For example, NET_BH was responsible for handling of network protocols and sending of packets. There can be a maximum of 32 BHs, which are scheduled for execution by the `mark_bh()` function.

BHs are the form of sections with the smallest parallelism in the kernel, as mentioned in previous sections. The following property shows the major drawback of BHs:

- Only one bottom half can run concurrently on all processors of a system at one time.
- Because BHs are inflexible and they are to be replaced by tasklets or soft-interrupts in future Linux kernel versions, we will not discuss them further here. Information on BHs is found in the literature (e.g., [RuCo01], [BBDK01] or [BoCe00]).

## 2.3 Locking—Atomic Operations

Different forms of activity can operate and interrupt each other in the Linux kernel. (See Section 2.2.) In multiprocessor systems, different activities operate in parallel. This is the reason why it is very important for the stability of the system that these operations run in parallel without undesired side effects.

As long as the activities in the Linux kernel operate independently, there will not be any problem. But as soon as several activities access the same data structures, there will be undesired effects, even in single-processor systems.

After some processing of B, A continues its operations. Figure 2–3 shows the result of this procedure. Structure skb_b was added to the list correctly.

Undesired results can also occur in multiprocessor systems when the two activities A and B run quasi-in-parallel on different processors, as in the example shown in Figure 2-4.

To avoid these problems when several activities operate on a common data structure (the so-critical section), then operations have to be atomic. Atomic means that an operation composed of several steps is executed as an indivisible operation.

The following example shows how easy it is to define and activate a new tasklet:
```c
#include <linux/interrupt.h>
/* Handling routine of new tasklet */
void test_func(unsigned long);
/* Data of new tasklet */
char tasklet_data[] = "Hello, I am a struct tasklet";
/* Definition of tasklet_structure of tasklet */
DECLARE_TASKLET(tasklet, test_func, (unsigned long) &test_data);
void test_func(unsigned long data)
{
    /* Do what you think you have to do, e.g.:*/
    printk(KERN_DEBUG "%s\n", (char *) data);
}
/* Use an activity to activate the tasklet */
tasklet_schedule(&test_tasklet);
```

To avoid these problems when several activities operate on a common data structure (the so-critical section), then operations have to be atomic. Atomic means that an operation composed of several steps is executed as an indivisible operation. No other activity can access [it].

The next sections introduce atomic operations.

### 2.3.1 Bit Operations

Atomic bit form the basis for locking spinlocks and semaphores, introduced in the following subsections. These differ mainly in the way they wait for entry into critical section. All of these operations are implemented by one single machine command. However, critical sections cannot be reduced to one single command, but consist of several operations. Using the atomic bit or integer operations introduced in this section, you can implement locks to protect larger ranges for exclusive access.

```c
test_and_set_bit(nr, void *addr) sets the bit with number nr in the unsigned long variables of addr.The previous value of the bit is returned as value.
test_clear_bit(nr, void *addr) deletes the specified bit and also returns that bit's previous value.
test_change_bit(nr, void *addr) inverts bit nr and resets it to its original value.
set_bit(nr, void *addr) sets the bit with number nr at address addr.
clear_bit(nr, void *addr) deletes the specified bit.
change_bit(nr, void *addr) inverts bit nr.
test_bit(nr, void *addr) returns the current values of the bits.
```

### Integer Operations

Operations can also be run atomically on integers. To do this, however you have to use the atomic_t data type, which corresponds to the int data type in all supported architectures.

- `atomic_set(atomic_t *var, int i)` sets the value to i.
- `atomic_read(atomic_t *var)` reads the variables.
- `atomic_add_sub(int i, atomic_t *var)` adds or subtracts.
- `atomic_inc/atomic_dec(atomic_t *var)` adds or subtracts in increments of 1.
- `atomic_..._test(...)`:see Bit Operations.
