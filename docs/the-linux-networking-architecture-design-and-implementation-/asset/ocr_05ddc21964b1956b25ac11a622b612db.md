The packet options are separated and stored in the opt data structure. Normally, Boolean values (e.g., opt->is_strictroute) are set at this point. Consequently, the opt->srr pointer has to be fetched. If this pointer is set to one, then the packet option Loose Routing or Strict Source Routing is specified, which means that the function ip_options_rcv_srr() has to be invoked.

The return value of ip_rcv_finish() function is a pointer that points to either ip_local_deliver() or ip_forward(), depending on whether the packet has to be delivered locally or forwarded.

Local Packet Delivery The function ip_local_deliver() is invoked if an IP packet has to be delivered to the local computer. This packet could be a fragment of a larger IP datagram, which means many things have to be checked—for example all fragments have arrived, which is checked by the function ip_defrag(). Once all fragments have arrived, all options have to be removed from the first fragment to reassemble the fragments into the original datagram. The first fragment always includes all options that were copied when the datagram was fragmented. Next, the packet traverses the netfilters once more. The function ip_local_deliver_finish() completes a local packet delivery in the IP layer.
