# 11.2 L2CAP

The Logical Link Control and Adaptation Protocol (L2CAP) handles tasks on
data-link layer in the Bluetooth protocol stack. It establishes ACL connections for
the next lower layer, but does not transport pure audio data, which primarily is trans-\ported over SCO connections. In particular, the L2CAP protocol is responsible for
multlexing data streams from higher layers to an ACL connection, because there
always be at most one ACL connection at a time between two Bluetooth de-\VICES. Other important tasks include the segmenting and reassembling of data pack-
ets to be able to send and receive the much larger packets of the higher-layer
protocols despite the small packet sizes of the baseband layer. L2CAP supports
packet sizes up to 64 Kbytes.

To multiplex several data streams, L2CAP uses the abstraction of the channel.
Each channel is allocated to one specific protocol. There are connection-oriented
channels for point-to-point communication and connectionless channels used for
group communication. A simple signaling method is used to establish a L2CAP con-
ection. The L2CAP protocol can also be accessed directly from the user space over
socket. This is normally a socket from the PF_BLUETOOTH family with protocol\identifier

hci2_recv_frame(). If the channel identifier in the packet header is 0x0001, then

otherwise, the function 12cap_data_channel() is invoked.

The type of signaling packet is recognized within this function and, depending on
type, an appropriate handling function is invoked.
