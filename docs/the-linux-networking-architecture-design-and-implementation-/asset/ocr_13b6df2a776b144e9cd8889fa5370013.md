The problem is now that it can receive a new window size (i.e., a transmit credit) only together with a new packet. There is no acknowledgement, because it cannot send more data, which means the sender now depends on whatever other end sends. If the receiver does not have data to send, or if it was also granted a window having size null, then the communicating partners would wait eternally to be able to continue sending.

To solve this problem, the Transmission Control Protocol includes a mechanism known as zero-window probing. This mechanism is based on an additional timer, the probe timer. When this timer expires, a TCP packet is sent the advertising window has size null. This packet consists of only a packet header: it does not carry payload, because data must not be transmitted in this situation.

The communication peer acknowledges this packet, and if the other end was able to remove its congestion, to some extent, in the meantime, a larger window is granted with this acknowledgement, so that the transmission of data can be resumed. If the window size occurs again, then the communication peers wait until the probe expires expires sending another probe.

tcp_probe_timer(sk) is the handling routine for the zero-window probe timer, if it leads to a timeout. The initially checks on whether the receiver has offered a meaningful transmit window over a lengthy period. If several (more max_probes) window probes were sent unsuccessfully, then an error message is output to announce that there are serious problems in the TCP connection (tcp_write_err()) and to close this connection by tcp_done().

If the maximum number of window probes has not yet been reached, tcp_send_probe0() sends a TCP segment without payload, and the acknowledgment segment will then, it is hoped, grant a credit (advertised window) larger than null.
