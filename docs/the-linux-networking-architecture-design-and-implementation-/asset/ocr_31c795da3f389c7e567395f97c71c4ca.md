# CHAPTER 20

# Connection Tracking

# 20.1 INTRODUCTION

This chapter discusses the connection-tracking module, which forms the basis for extended packet-filter functions, particularly for network address translation (NAT—Chapter 21) in Linux 2.4.

The connection-tracking module manages individual connections (particularly TCP connections, but also UDP associations) and serves to allocate incoming, outgoing, and forwarded IP packets to existing connections. A new connection entry is generated as soon as the connection-tracking module registers a connection-establishment packet. From then on, each packet belonging to this connection is uniquely assigned to this connection. For example, this enables the NAT implementation to figure out whether an incoming packet needs a free IP address or one of the addresses and port numbers previously assigned can be. The connection is deleted after a certain period of time has elapsed without traffic (timeout), which depends on the transport protocol used (i.e., TCP, UDP, or ICMP). Subsequently, the NAT can resolve the address and port that have become available.

The connection-tracking module is not limited to transport protocols; it can also support complex application protocols. For example, a stateful filter and address-translation mechanism for active FTP (Section 19.1.2) can be implemented. For this purpose, the connection-tracking module has to be able to associate newly established data connections with an existing control control.

# 20.1.1 Using the Connection-Tracking Module

Two functions can be invoked to access connection entries: ip_conntrack_get() and ip_conntrack_put(). The ip_conntrack_get() returns a connection entry for an IP packet passed as an sk_buff structure and automatically increments the reference counter for this connection. The ip_conntrack_put() informs the connection-tracking module that the previously requested connection is no longer needed and decrements the reference counter.
