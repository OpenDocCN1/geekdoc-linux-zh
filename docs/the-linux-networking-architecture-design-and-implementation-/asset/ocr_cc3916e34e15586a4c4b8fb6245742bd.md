During forwarding of packets, the end-system identifier can be totally ignored until the packet arrives in the correct subnetwork. This means that routers do not need to know end-system identifiers; in this way, the division of IP addresses into two parts dramatically reduces the amount of information routers have to store.

Because it always forms the beginning of an IP address, the network-address part of an IP address is also called network prefix.

# Address Classes and Classless Addressing

The question we have to answer is about the sizes of the network part and the end-system identifier in an IP address. Three different variants were defined when addressing in the Internet was specified [Post81]: The address classes A, B, and C, having 7, 14, and 21 bits for the network part and 24, 16, and 8 bits for the end-system identifier. The class address belongs is determined by the first (leftmost) bits of the address. Figure 16–3, which was also used in Chapter 14, illustrates this scheme. We will not go into detail about the two addition-classes, D and E, which are reserved for special purposes; or other reserved network prefixes and end-system identifiers again at this point: see Section 14.1 for this.

This addressing was originally designed by assuming that each physical network would actually have a network identifier from one of three classes mentioned above (depending on the size of the physical network). However, it was soon seen that this approach would quickly exhaust all available network prefixes. In addition, the existing classes proved to be inappropriate: class-A network could contain al-most 224 or 16777216 systems, a number that even the largest organizations would hardly need, from the fact that no physical network technology can handle that number of end systems. In contrast, class-C networks are much more numerous, but cannot hold more than 254 systems, which is not enough in many cases.

These limitations motivated the development of technologies to better utilize the existing address space. The basic idea was to have the boundary between the network prefix and the end-system identifier at an arbitrary position, instead of only at the three positions dictated by the A, B, and C address classes.
