# 8.3.3 Initialization

When the PPP module ppp_generic_o is loaded, then ppp_init first registers a character-oriented device with the major number 108, which is normally embedded /dev/ppp into the system. In the next step, the module uses ppp_async_init() to register a new TTY line discipline (see Section 7.2.1) by the name 'ppp' for the asynchronous PPP driver (ppp_async.). This TTY line discipline is an intermediate layer between the device and the underlying device and the ppp async_c module, which facilitates access to all incoming data packets. Once the /dev/tty device and the PPP TTY line discipline have been registered, the first initialization phase is completed.

The second phase is initiated by the calling of ppp. After a brief test of its version number matches the kernel driver version, it opens the device /dev/ppp. It then opens a file descriptor, which is required to communicate with the generic PPP driver: at first, however, the reference pointer USAGE_COUNT of the PPP device increments.

Next, a user needs to establish a physical connection (e.g., the chat program could dial the number of a dialup server). If this action was successful, then ppp uses the system ioctl(tty_fd, TIOCSREED, N_PPP) to change the TTY line discipline to N_PPP. It then uses ioctl(ppp_fd, PPPOCNEWUNIT) to request the generic PPP driver to create a new network device and then uses ioctl(fd,, PPPOCGCATATCH) to bind the new network device to the underlying TTY device.

These steps complete the establishment of the actual PPP connection: now the PPP protocols, as LCP, can start authenticating the user and configure higher layers (see Section 8.4).

# 8.3.4 Transmitting IP Packets

The generic PPP driver accepts packets for transmission over two routes: the network layer sends payload packets over the matching network device (pppX), and the PPP daemon controls packets over the character-oriented device /dev/ppp.

Each data packet to be sent to the function ppp_start_xmit() by the network layer in an sk_buff buffer. (See Section 4.1) This function adds a 2-byte PPP header (see Figure 8-2) to the beginning of the packet and stores the packet in the transmit queue ppp_xq. The very same thing happens in ppp write(). the function that accepts packets from ppp.

Finally, the function ppp_xmit() is invoked in each case. It takes packets from the transmit queue and forwards them to the function ppp_send_frame() for further processing. Depending on the setting, the packet headers might be compressed by the Van-Jacobson method and the deflate and BSD-Compress method might be used for payload compression. After a forwarding to the function ppp_send_async()_ of the asynchronous PPP driver (or to the corresponding function of the synchronous PPP driver), the generic PPP driver has completed its processing.
