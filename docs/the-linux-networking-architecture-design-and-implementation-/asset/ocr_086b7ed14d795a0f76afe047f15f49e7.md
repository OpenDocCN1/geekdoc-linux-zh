All segments arriving over an established connection are subject to the following checks by the PAWS algorithm [JaBB92]:

The RST flag should not be set.

The TCP partner instance should have received a valid Timestamp option (i.e., the tp->ts_recent variable contains a valid value).

If an incoming segment contains the Timestamp option, and if its timestamp, tp->rc_tsval, is smaller than the timestamp stored last. tp->ts_recent, this segment should be dropped. This check is done in the tcp_paws_discard() function below, which is invoked in Slow Path in the tcp_rc_established() function. (See Section 24.2.1).

```
extern __inline_ int tcp_paws_discard(struct tcp_opt *tp, struct sk_buff *skb)
 return ((u32)(tp->ts_recent - tp->rc_tsval) > TCP_PAWS_WINDOW &&
        xtime.time_sec < tp->ts_recent_timestamp + TCP_PAWS_24DAYS &&
        !tcp_disordered_ack(tp, skb));

```

The second condition checks the validity of the tp->ts_recent timestamp. There is a very small probability that an extremely long time has passed the time when the timestamp was taken from a received segment, which is stored in the tp->ts_recent timestamp variable. This means that, if more than 24 days have passed this time, the ts_recent timestamp is considered invalid. [Stevc94b] includes an example for such a situation.

If the TCP connection is not in the ESTABLISHED state, then the PAWS check on incoming packets is done in the tcp_paws_check() method (net/ipv4/tcp_input.c).

The PAWS mechanism requires the use of the timestamp option as monotonically increasing values. In addition, it requires that the timestamp increase at least once per period and the time in which it repeatedly takes the same value is greater than the maximum segment lifecycle.

The Timestamp option is a prerequisite for the PAWS algorithm and additionally is used to determine the packet round-trip time and the retransmission timeout; we need to introduce it.

# The Timestamp Option This option offers TCP a way to continually probe and adapt the packet round-trip time (RTT) in each segment. The connection option allows you to set a timestamp in each segment. The receiver returns this timestamp in the acknowledgement segment, allowing the sender to compute the round-trip time for each acknowledgement received. A timestamp is a monotonically increasing value taken from a timer. Figure 24–14 shows the format of the timestamp option in the TCP packet header [JaBB92].
