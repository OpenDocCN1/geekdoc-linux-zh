- **hardware_address**: This array stores the physical address of the neighboring computer.

It is not necessary to fill these every time; it is more efficient to have them computed and readily stored, so they need only be copied.

The output() functions of the neigh_ops structure are particularly important. Each neighbour structure includes an output() pointer to a function used to send data to a neighboring station. For ARP cache entries in the NUD_REACHABLE, NUD_PERMANENT, or NUD_NOARP state, the output() pointer references the function connected_output() of the neigh_ops structure; it is the fastest of all. Reachability was confirmed recently or no confirmation is required (point-to-point).

For neighbour stations in other states, the output() pointer references the output() function which is slower and more careful. Reachability is doubted, so an initial attempt is made to obtain a confirmation of the neighboring computer's reachability (probe).

# Address Resolution Protocol (ARP)

### Possible States for neighbour Entries

It is theoretically possible to leave entries for all states learned in the ARP cache. However, there are several reasons why these entries are valid for a limited period of time. First, it would mean memory wasted to maintain entries, especially if there is little or no data exchange with them. Second, there is a situation when the network adapter in a computer is replaced and this computer will have a different layer-2 address. Therefore, the mapping stored for a computer is valid if that computer has not sent anything for some time.

In practice, the size of the ARP cache is limited (normally to 512 entries), and rarely used entries are removed by garbage collection. On the other hand, it could be that a computer does not communicate over a lengthy time, which means that its table is empty. This was not possible up to kernel 2.4, because garbage collection was done when the table included fewer than gc_thresh values, which normally mean 128 entries. This limit no longer exists in kernel 2.4 and higher. You can use the arp command (see Section 15.2) to view the contents of the ARP cache.

Each neighbour entry in the ARP cache has a state, which is stored in the nud structure. Figure 15-6 shows all possible states and the most important state transitions. There are other transitions, but they img/5a25b942ec3329b879f2b5f0de564f6305_0.png (FIGURE 15-6 State transition diagram for neighbour entries in neighbour caches) are left out for the sake of keeping the figure easy to understand. The states and state transitions are described below.

- **NUD_NONE**: This entry is invalid. A neighbor is normally in this state only temporarily. New entries for the ARP cache are created by the neigh_alloc() function, but this state is changed immediately.
- **NUD_NOARP, NUD_PERMANENT**: No address resolution is done for entries in these two states. NUD_NOARP are neighbors that do not require address resolution (e.g., PPP). Entries with the NUD_PERMANENT state are permanently set by the administrator and are not deleted by the garbage collection.
- **NUD_INCOMPLETE**: This state means there is no address mapping for this neighbor yet, but it is being processed. This means an ARP request has been sent, and the protocol is waiting for a reply.
- **NUD_REACHABLE**: neighbour structures in this state are reachable with the fastest output() function (neigh_ops->connected_output()). An ARP reply from this neighbor was received, and its maximum age is neigh->parms->reachable_time units. This interval is restarted when a normal data packet is received.
- **NUD_STALE**: This state occurs when an entry has been reachable, but reachable_time has expired. For this reason, it is no longer certain that the neighboring computer can be reached with the address mapping currently stored. For this reason, rather than using connected_output() to send packets to this neighbour, the slower neigh_ops->output() is used.
- **NUD_DELAY**: If a packet needs to be sent to a station in the NUD_STALE state, then the NUD_DELAY state is set. It is between the NUD_STALE and NUD_PROBE states only temporarily. Of course, if the address mapping is confirmed once again, the entry changes to the NUD_REACHABLE state.
- **NUD_PROBE**: The entry in the ARP cache is in the probing phase: Consecutive ARP request packets are sent in an attempt to obtain the layer-2 address of this computer.
- **NUD_FAILED**: The address mapping cannot be resolved for entries in this state. ARP tries to solve the problem by sending neigh_max_probes request packets. If it still doesn't get replies to these packets, the state of the neighbour entry is set to NUD_FAILED. Subsequently, the garbage collection deletes all entries in this state from the ARP cache.
