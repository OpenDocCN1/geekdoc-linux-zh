# 26.3 PF_NETLINK Sockets

PF_NETLINK sockets are used to exchange data between parts of the kernel and the user space. The protocol family to be stated is PF_NETLINK, and the type is SOCK_RAW or SOCK_DGRAM. The protocol can be selected from among number of options (see include/linux/netlink.h): NETLINK_ROUTE (interface to the routing and the network), NETLINK_USERSOCK (reserved for protocols that run in the user space), NETLINK_FIREWALL (interface to the firewall functionality), NETLINK_ARPD (management of the ARP table), NETLINK_ROUTE6 (IPv6 routing), NETLINK_IP6 (IPv6 fire-wall), and others.

A header containing information about the length and content of the message is appended to data to be sent from the user to the kernel. The format of this header is defined as struct nlmsghdr (include/linux/netlink.h).

The field nlms_type can take any of three values: NLMS_NOOP, NLMS_ERROR, and NLMS_DONE. Other valid values for nlms_flags are also available in include/linux/netlink.h.

This general Netlink interface is used for communication between the user space and different parts of the kernel. For further adaptation to the respective application purpose, additional values for nlms_type were defined (e.g., for NETLINK_ROUTE6 in include/linux/ipv6_route.h and for NETLINK_ROUTE in include/linux/rtlink.h).

In addition to the PF_NETLINK sockets, there is another Netlink interface over a character device (see net/netlink/netlink_dev.c), but it is still used for reasons backward compatibility. We will only discuss the so-called RT Netlink interface
