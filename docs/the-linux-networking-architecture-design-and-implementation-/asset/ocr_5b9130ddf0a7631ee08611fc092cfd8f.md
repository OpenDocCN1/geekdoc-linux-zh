The ip_nat_info_manip structure represents a manipulation or address binding. It contains the direction (IP_CT_DIR_ORIGINAL for the forward direction, IP_CT_DIR_REPLY for the reverse direction), the netfilter hook number, and the address translation type (IP_NAT_MANIP_SRC for source NAT, IP_NAT_MANIP_DST for destination NAT), and its ip_conntrack_manip structure includes the IP address and port number to which the former address should be mapped.

To manage addresses, the NAT module uses two tables, bource and biiproto, where collisions are resolved by linear lists. The biiproto table is used to account for mappings, to ensure that no mappings map to the same IP address. The keys are the transport protocol number and the IP source and destination addresses of the session flow after the address translation.

The keys for the bource table are the transport protocol, the IP source address, and the source port before the address translation. This table is used by the find_appropriate_src() function to detect existing session flows. (See Section 21.3.4).

# 21.3.2 Initializing and Uninitializing the NAT Module

The two functions init() and fini() are used to initialize and uninitialize the NAT module. In turn, these two functions invoke the init_or_cleanup() function with parameter 1 (initialize) or 0 (uninitialize).

```
init_or_cleanup()
netip/ipv4/netfilter/ip_nat_standalone
```

The init_or_cleanup() function serves to initialize or uninitialize the NAT module, depending on the value of the init parameter.
To initialize the NAT module, the ip_nat_rule_init() function from /net/ipv4/netfilter/ip_nat.c) is invoked first. This function uses ipt_register_table() to create the new netfilter table. Subsequently, it uses ipt_register_target() to register the new branch destinations. SNAT and NAT, with the handling handlers ipt_snat_target() and ipt_dnat_target(). Next, the ip_nat_init() function from /net/ipv4/netfilter/ip_core.c) initializes the standard protocols—TCP, UDP, and ICMP and the two tables—bource and biiproto. Finally, the functions ip_nat_fn(), ip_nat_local_fn(), and ip_out() are registered with the appropriate hooks, and the usage counter of the connection-tracking module is incremented.

To uninitialize the NAT module, the cleanup work is done in reverse order: First, the usage counter of the connection tracking module is decremented; then the NAT functions are removed from the hooks; next, ip_nat_cleanup() deletes the tables and the transport protocol modules; and, finally, ip_nat_rule_cleanup() releases the branch destinations and the NAT table.
