# Appendix B Debugging in the Linux Kernel

Though this rather simple but useful fault-tracing variant often helps, there can be cases where an error in the operating-system kernel causes the entire computer to crash, leaving no way to store or read log information. These cases often occur when function pointers are wrongly initialized or by accesses to beyond array boundaries. Some of these errors can be caught with the well-known ‘kernel oops(),’ but some lead inevitably to a crash.

The following sections introduce several helpful methods to create outputs from the kernel and make them visible to the programmer or user.

# B.1.1 Using printk() to Create Log Outputs

The printf() function is normally used in conventional writing of C programs—and the Linux kernel is actually not different—to output messages at a text console; printf() is a function of the standard input/output library <stdio.h>, which is not available in the Linux kernel. For this reason, the Linux developers simply implemented print() and integrated it into the kernel as the printk() function. Other functions borrowed from the standard libraries help the handling of character strings (lib/string.h).

```
printk() kernel/printk.c
```

printk() offers almost the same functionality as printf() and has a similar syntax. A special property of printk() is the classification of messages to be output by different debugging levels. The syslog and klogd daemons can be used to store and output kernel messages or send them to specific addresses.

Alternatively, there are eight debugging levels, from KERN_DEBUG to KERN_EMERG—the highest level (system unless). These debugging levels are defined in <linux/kernel.h>. Depending on the DEFAULT_CONSOLE_LOGLEVEL variable, messages are output on the current console. The administrator can use the command syslog -c to modify the value appropriate.

printk() itself uses the printf() function to generate the output string. The reason is why the syntax of the two functions and parametrizing of the variables to be output is identical. sprintf() will be introduced in Section B.2.

# B.1.2 The syslog Daemon

While the operating system is running, there are often situations where programs have to log error messages or specific information. In text mode these messages are simply at the console (stdout or stderr). A popup window is normally created for window-based applications (X11). The operating kernel and processes working directly for it, such as daemons or child processes of the init process, have no allocation to a console.
