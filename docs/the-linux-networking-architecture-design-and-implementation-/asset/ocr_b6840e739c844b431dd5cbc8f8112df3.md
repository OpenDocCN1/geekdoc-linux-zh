fib_info structure does not contain any backward references to its position within the routing-table data structures. Instead, the fib next and fib prev pointers serve to arrange all existing fib_info structures to form a doubly linked list, which is hooked into a global variable, fib_info_list. When creating a new entry, the fib_create_info(), which is invoked by tb_insert(), first checks for whether an identity exists in the list. Rather than duplicating an entry, it would merely increment the reference counter fib_clintref. This means that fib_node structures can reference one fib_info structure. When a fib_node is freed, the reference counter has reached null.

In contrast to fn_zone and fib_node, the fib_info structure becomes visible to the outside again: It is declared in include/net/ip_fib.h and its contents are read directly in some places (e.g., in net/ipv4/route.). All operations to manage fib_info structures that go beyond the plain reading of a data element are implemented in the file net/ipv4/fib_semantics.c, however.

# Managing and Initializing Memory The FIB implementation is initialized in ip_fib_init()(net/ipv4-frontend). If route-based routing is not used, the function fib_hash_init() is invoked directly for the two tables table_local and table_main held in global variables. This function occupies memory for a fib_table and sets the enclosed pointers to the fn_hash functions. The structure of the type fn_hash, which contains the hash table, is initialized to null.

In contrast, if route-based routing is used, routing tables are not previously initialized. The global array that references the tables is created as a memory area initialized to when the kernel loaded. When a routing table is accessed via an element of the array, it is checked whether the table already exists, and if this is not the case, it is created by fib_hash_init().

The function fib_hash_init() also ensures that a slab cache (see Section 2.6.2) called "ip_fib_hash" exists. This slab caches memory for fib_node structures, which are allocated in the function fib_hash_insert() to create new entries when needed.

# Managing Hash Structures The functions that access fn_zone and fib_node structures, are used internally to manage routing-tables using hash tables, which are collected in the file net/ipv4/fib_hash.c. They are invoked by all other FIB functions to access fn_zone and fib_node structures.

Encapsulation of these internal structures allows them to be reimplemented, if necessary, using other data structures offering a more efficient search process, without the need to effect changes in other places.

The most important functions in net/ipv4/fib_hash.c are as follows:

+   fn_rehash_zone() enlarges the hash tables, if necessary.
f_new_zone() creates a new fn_zone structure and sorts it into the zone list based on its prefix length.
f_hash_lookup() handles the main task in a FIB query: The fn_zone structures in a routing table are walked through the sequence of descending prefix length, and the hash table is searched for an entry matching the key passed as an argument.
