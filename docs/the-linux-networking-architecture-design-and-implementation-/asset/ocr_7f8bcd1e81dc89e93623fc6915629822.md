# INFORMATION IN THE /PROC DIRECTORY

As was mentioned earlier, the files in the /proc directory serve to make current information-
about system components available to the user. They are regenerated
upon each read access.

The /proc directory and its subdirectories include a large number of files that reflect-
t the current system state. The meaning of each of these files should be known.
Some information about the meaning of file contents and their—partially cryptic-
syntax in the Documentation directory in the kernel source text.

# Entries in the /proc Directory

Initially, a separate subdirectory is created in the /proc directory for each process, named
by the ID. Each such subdirectory includes process-specific information. However,they are of minor interest for the Linux network architecture, so we will not discuss
them any further here. Within the scope of this book, we are mainly interested in the
/proc/net and /proc/sys/net directories, which contain information about and parameters-
of protocol instances and network devices, some of which can even be configured.

The /proc directory itself holds the following files of general interest:

+   meminfo shows information about free and occupied memory in the system.
mskg: During reading of this file, the buffer with the last kernel messages are out-
out and emptied. These messages are normally read by the klogd daemon and
processed by the syslog daemon. (See Section B.1.2.)

+   kcore returns a copy of the kernel. The file size corresponds to the size of the kernel-
in main memory, including the page size. This allows you to debug the kernel at
time:

```
root@tux # gdb /usr/src/linux/vmlinux /proc/kcore
```

Section 4 includes more detailed information.

+   modules shows information about the modules loaded and their-
dependencies. The contents correspond to the output of lsmod.
devices holds information about registered device drivers and their major-
bumbers. The file distinguishes between character-oriented and block-oriented drivers.
As described in Chapter 5, network devices represent a separate class of
drivers; therefore, they are not listed in /proc/devices.
interrupts lists all instances (character-oriented, block-oriented, and network
devices) that occupy interrupts. Specifically,the interrupt number,the total-
 of interrupts (per processor), and the device name are listed. A look in this file
el helps when controlling to whether a device's driver works. You can see
by the presence of a device and an increasing number of interrupts. Linux
supports more than one device's using the same interrupt. In this case, only the-
actual number of the corresponding interrupts is shown; they are not itemized by
device.
