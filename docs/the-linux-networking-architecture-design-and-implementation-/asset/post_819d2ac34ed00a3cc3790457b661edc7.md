## ipmr_ioctl1()

ipmr_ioctl1(sk, cmd, arg) can be used to poll various status information. If cmd has the value SIOCGETVIFCNT, a pointer to a sioc_vif_req structure (see below) in arg is expected. It includes the index of the virtual device for which information is to be queried (e.g., how many packets and what data values have been received and sent over this device). The result is added to the passed sioc_vif_req structure.

If cmd is equal to SIOCGETSCNT, a pointer to a sioc_sg_req structure in arg is expected. The corresponding information about the matching entry in the multicast forwarding cache is deleted.

ipmr_ioctl1() is entered in inet_create() (in net/ipv4/af_inet.c) as ioctl1() handling routing in the proto structure for raw sockets.

## ip_mr_init()

ip_mr_init(void) initializes the multicast functions in the kernel: it is invoked when inet_proto_init() (in net/ipv4/af_inet.c) starts.

## ipmr_get_route()

ipmr_get_route(skm, rtm, nowait) determines the route for a packet from a specific source for a specific group. This function is used for informative purposes only. The result is packed into a packet to send it to other routers (e.g. so that these routers exchange routing information). The route for the actual routing of multicast packets is specified in ip_mr_forward().

## ipmr_cache_find()

ipmr_cache_find(origin, mcastgrp) searches the multicast forwarding cache (see Section 17.4.2) for a specific entry. The packet's source address and multicast group address serve as search keys. An MFC entry is found, it includes all virtual network devices (VIFs) that can be used to forward the packet. The result is returned in the form of a pointer to an mfc_cache structure.

## ipmr_new_tunnel()

ipmr_new_tunnel(v) is responsible for creating a new tunnel. All information required this end is passed, together with the victfl structure (v). The function gets the tunnel network device, tun10, and tries to create a tunnel to the destination specified in v. If it is successful, then this virtual network device is returned; otherwise an error message (null) is returned.

## ipmr_cache_unresolved()

ipmr_cache_unresolved(cache, vifi, skb) is invoked by ip_mr_input() and ipmr_get_route(). if a specific entry was polled from the multicast forwarding cache and if this entry either does not exist or has not been filled yet, though it was requested by mrouted, ipmr_cache_unresolved creates a new entry in the multicast forwarding cache and sets its status to MFC QUEUED, which means the route specified in this entry has not yet been entered by mrouted.

Subsequently, the timer is activated, and ipmr_cache_report is invoked to ask mrouted for the required route. The timer causes the entry to be deleted from the cache at a certain time, if mrouted cannot determine the route before this time.

```
ipmr_cache_report()
net/ipv4/ipmr.c
```

ipmr_cache_report(pkt,vifi,assert) asks mrouted to create an entry in the multicast forwarding cache (MFC) for a specific packet—its origin and multicast group—to determine the route. For this purpose, a packet is created, and socket_rcv_skb() is used to send it to mrouted.

```
ipmr_cache_timer()
net/ipv4/ipmr.c
```

ipmr_cache_timer(data) deletes an entry from the MFC, if the mrouted daemon was requested to determine the route, and if it was unable to do this within a specific time. ipmr_cache_timer() is the timer-handling routine for mfc_timer defined in the mfc_cache structure.

```
ipmr_cache_alloc()
net/ipv4/ipmr.c
```

ipmr_cache_alloc(priority) creates a new mfc_cache structure and adds a few initial values, including the data and handling routine and information statistics that the route does not exist yet. ipmr_cache_alloc() does not write the created structure to the multicast forwarding cache; ipmr_cache_insert() has been invoked separately for that purpose.

```
ipmr_mfc_modify()
net/ipv4/ipmr.c
```

ipmr_mfc_modify(action,mfc) is invoked when the mrouted daemon uses MRT_ADD or MRT_DEL_MFC to manipulate an MFC entry over setsockopt(). In addition to this action, the function checks whether this is a new entry or the entry already exists and has to be filled. If the latter is a case, and if the MFC entry is set to MFC_QUEUED status, then ipmr_cache_resolve() is invoked to send waiting packets.

```
ipmr_cache_resolve()
net/ipv4/ipmr.c
```

ipmr_cache_resolve(cache) is invoked by ipmr_mfc_modify() when the route is in an MFC entry and packets are waiting to be sent. The timer (see above) is deleted, and ip_mr_forward() sends the waiting packets.

## Data Exchange Between the mrouted Daemon and the Kernel

This section explains the most important structures exchanged between the Linux kernel and the mrouted daemon. The daemon passes data to the kernel as shown below. We use the example of a query of the virtual network device and an MFC entry to explain the procedure:

Initially, the mrouted daemon allocates memory space for a sioc_vif_struct and writes the index of the desired virtual network device to the wifi field. Calling of the ioctl() SIOCGETVIFCNT command makes the appropriate part executed by the depr_ioctl. The argument for the ioctl() command is the address by which the vif index points to valid virtual network device. If this is the case, the referenced structure is filled with the appropriate values and copied back to the user address space by copy_to_user(). Structure used to pass the data of a virtual network device is as follows:

``` evenstruct sioc_vif_req
include/linux/mroute.h
sioc_vif_req {
    vif_t           vifi;      /* Which iface? */
    unsigned long  icount;    /* In packets */
    unsigned long  ibytes;    /* In bytes */
    unsigned long  obytes;    /* Out bytes */
};
```

vifi: This is the index of the virtual network device.
icount: This is the number of packets received.
ibytes: This is the number of bytes received.
obytes: This is the number of bytes sent.

The procedure for querying an entry in the multicast forwarding cache is identical, except that the sioc_sg_req structure and SIOCGETCNT are used:

```struct sioc_sg_req
include/linux/mroute.h
sioc_sg_req {
    struct in_addr src;
    struct in_addr grp;
    unsigned long pktcnt;
    unsigned long bytecnt;
    unsigned long wrong_if;
};
```

src: This is the sender address.
grp: This is the multicast group.
pktcnt: This is the number of packets.
bytecnt: This is the number of bytes.
wrong_if: This is the index of the virtual network device.

## 17 Multicast for Group Communication

Because multicast packets can be received and sent over physical adapters and tunnels, we use vifct1 structures. The routing table of the kernel is influenced by MFC—entries. These structures are used by the kernel to learn how to forward multicast packets.

```
struct vifct1 include/linux/mroute.h
struct vifct1 {
    vif_t vifi;               /* Index of VIF */
    unsigned char flags;      /* VIF_flags */
    unsigned char threshold;  /* ttl limit */
    unsigned int rate_limit;  /* Rate limiter */
    struct in_addr l1_addr; /* Our address */
    struct in_addr rmt_addr; /* IP tunnel addr */
};
```

```
struct mfccct1 include/linux/mroute.h
struct mfccct1 {
    struct in_addr mfcc_origin;    /* Origin of mcast */
    struct in_addr mfcc_mcastgrp;  /* Group in question */
    vif_t mfcc_parent;            /* Where it arrived */
    unsigned char mfcc_ttl[MAXVIFS]; /* Where it is going */
    unsigned int mfcc_pkt_cnt;     /* / pkt count for src-grp */
    unsigned int mfcc_byte_cnt;
    unsigned int mfcc_wrong_if;
    int mfcc_expire;
};
```
