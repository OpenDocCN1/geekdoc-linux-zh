Receiving a Data Packet In contrast to sending a data packet, receiving a data packet from the network is an unforeseen event for the operating system. The network adapter receives a packet in parallel to processor operations and wants to forward this packet to the kernel. In general, there are two methods to inform the kernel that a packet has arrived.

First, the system could periodically ask the network adapter whether data has been received; this is the so-called polling principle. One major problem with this method is the size of the time interval in which the network adapter should be asked. This interval is too short, then unnecessary computing time is wasted; but if it is too long, the data exchange is unnecessarily delayed and the network adapter might be unable to buffer all incoming packets.

The second method uses an interrupt and an appropriate interrupt-handling routine to inform the operating system about an incoming packet. A process of the system is briefly interrupted in its current work, accepts the packet received and stores it in a queue. Next, the packet is handled as soon as the processor has time. This interrupt principle clearly performs better than the polling principle, and adapts itself better to the system load. For this reason, each modern network adapter works by this principle (i.e., the receive function of the network driver is called by its interrupt-handling routine).

The driver method used to handle incoming packets is responsible for requesting a socket buffer and for filling the packet data with the packet received. The method dev_alloc_skb() can be used to request a new socket buffer. This method attempts to get a used buffer from the buffer-cache to avoid slow memory management. Occasionally, more than one packet arrives. In the case discussed in this we use up to ten packets that are accepted by the network adapter and introduced as socket buffers to the Linux network architecture. The status of the received packet can be verified from specific hardware registers (whether the packet was received correctly and, if which error occurred). If errors occur, then these are generally collected in a net_device_stats_structure, which is not part of the dev_device_structure; it has to be managed in the private data space (dev--) of the network device.
