# 5.3.6 Adapter-Specific ioctl() Commands

ioctl() are extremely useful tools to start certain actions from within the user address space. Normally, executing the system call ioctl() in a socket causes an ioctl() command of a network protocol to be invoked. The corresponding symbols are defined in the file include/linux/sockios.h and normally to a specific protocol instance. However, when an ioctl() command of higher protocol instances cannot be processed, the kernel forwards it to the network devices, which can define their own commands in the driver method do_ioctl().

```
net_do_ioctl()
drivers/isa_skeleton.c
```

The ioctl() implementation for sockets connects 16 additional ioctl() commands, which can be used by drivers. More specifically, these are the commands SIOCDEPRIVATE to SIOCDEPRIVATE + 15. When one of these commands is used, then the method dev->do_ioctl() of the relevant network device is invoked.
When calling, ioctl(dev, ifr, cmd) gets a pointer to a structure of the type ifreq. This pointer (ifr) points to an address in the kernel address space. which contains a copy of the ifreq structure passed by the user. After the loopback from the dev_ioctl method, this structure is copied back to the user address space. This means a network driver can use its ioctl() both to return and to output data. Examples for driver-specific ioctl() commands include reading or writing special registers, such as the MII register of some modern network adapters (eepro100, epic100, etc.).
