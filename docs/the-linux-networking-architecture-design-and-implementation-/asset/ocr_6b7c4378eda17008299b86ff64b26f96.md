Section 7.1.1 briefly explains why framing is necessary: an asynchronous TTY device (eg., a modem connection) can process only unstructured byte streams and full packets, so it is necessary to mark the beginning and end of a packet. PPP, this is done by use of the special character PPP_FLAG with the binary representation 01111110.

Of course, the remaining data stream should not inadvertently contain such special characters. To prevent special characters from occurring, we use character stuffing. This means that all payload bytes by a control character, such as PPP_FLAG, are prefixed by the character PPP_ESCAPE, or 01111101. There are more control characters; we see include/linux/ppp.defs for a complete list.

Framing and character stuffing are properly implemented in the function ppp_async_encode(). A bit vector in the field xaccm in the struct async_struct is used to detect the characters that should have a PPP_ESCAPE prefix. Each of the 32 × 8 bits in this vector corresponds to one of the 256 available-bit characters. The following program dump from drivers/net/ppp_async.c shows how we can convert payload into a data stream:

```
#define PUT_BYTE(ap, buf, c, iscl) do {
    if ((iscl && c < 0x20) || (ap->xaccm[c] & (1 << (c & 0xf))))))
        *buf = PPP_ESCAPE;
    *buf = c ^ 0x20;
} while (c);
```

In this code, iscl is a flag set for special LPC commands, which have to work even when the bit vector->xaccm not yet been initialized or has been wrongly initialized.

To protect against transmission errors, a 2-byte checksum (Frame Check Sequence–FCS) is appended to the PPP packet before the closing end character (PPP_FLAG). If the packet was fully converted into a data stream, then the driver of the underlying TTY device, is called by tty->driver.write(), assumes the remaining work.

# 8.3.6 Receiving PPP Packets

Receiving PPP packets over the asynchronous PPP driver works much like sending packets, just in opposite direction: Incoming data is first sent to the function ppp_asyncctty_receive() of the asynchronous PPP driver by the driver of the TTY device. Then the function ppp_async_input() searches for boundaries and undoes character stuffing. The function checksum (FCS: see Section 8.3.5) is correct. Finally, the restored packet is passed to the function ppp_input() of the generic PPP driver.
