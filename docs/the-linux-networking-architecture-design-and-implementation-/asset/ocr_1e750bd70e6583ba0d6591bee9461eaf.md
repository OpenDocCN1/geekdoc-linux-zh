# 112 Chapter 5 Network Devices

get_stats(dev) returns a pointer to the statistical data of a network device
(dev). A sample implementation might look like this:

```
/*
 * Get the current statistics.
 * This may be called with the card open or closed.
 */
static struct net_device_stats *net_get_stats(struct net_device *dev) {
    struct net_local *ilp = (struct net_local *)dev->priv;
    short ioaddr =dev->base_addr;

    /* Update the statistics from the device registers. */
    ilp->rx_missed_errors = inw(ioaddr+1);
    return ilp->stats;
}
```

# 5.3.8 Multicast Support on Adapter Level

```
net_set_multicast_list()
```

A network adapter uses the MAC address of a packet to decide whether it will accept or ignore it. This process runs on the network adapter, so it doesn't interfere with the central processor's work. The central processor will be interrupted in its work only if the network adapter triggers an interrupt because it wants to forward the packet to higher protocol instances. In general, a network adapter accepts only packets intended for it, to ensure that the processor is not necessarily interrupted. One exception to this rule is the promiscuous mode, where all packets are accepted for analytical purposes.

For multicast, it is relatively easy to see whether the computer is interested in a packet. The network adapter merely has to detect its own MAC address as the destination address in the layer-2 packet header. Broadcast packets are also accepted without exception. The situation is different when detecting correct multicast packets. How can the card know the computer is interested in the data of that group? In case of doubt, the card accepts the packet and passes it on to higher protocols, which should be able to know the groups subscribed. This method is very expensive, because the central processor has to check each multicast packet, it is the only way for some (other) network adapters to receive the correct multicast packets.

A better support for multicast on the MAC level is offered by modern network adapters. Such adapters manage a list of MAC addresses from which they want to receive packets. If only the packets of a specific multicast group should be received, then the corresponding MAC group address is passed to the network adapter, which will then receive the multicast packets. Section 17.4.1 describes the connection between group addresses on the MAC and IP levels.

A network device stores the list of active MAC group addresses in a list (dev->mc_list). Whenever a new address is added or the state of the network device changes, the driver method dev->set_multicast_list transfers this list to the adapter.
