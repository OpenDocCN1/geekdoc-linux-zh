In the next step, the application can specify QoS parameters for the socket previously. To end this, an application calls setsockopt() and uses the options SOL_ATM and SO_ATMQS.

### atm_do_setsockopt() net/atm/common.c

In the function atm, the values specified by the application are entered in the structure struct atm_qos (from include/linux/atm.h) contained in the structure atm_vcc. The structure atm_qos includes two structures:

```
struct atm_qos {
    struct atm_trafp txtp; // parameters in TX
    struct atm_trafp rxtp; // parameters in RX
    unsigned char aal;
};
```

The structure atm_trafp (also from include/atm.h) is used to specify traffic parameters for the connection. This structure includes the following:

```
struct atm_trafp {
    unsigned char class; // traffic class
    int max_pcr; // cells per second
    int min_pcr; // cells per second
    int max_cdr; // in microseconds
    int max_sdu; // in bytes
};
```

The parameter traffic_class can take the following values: ATM_NONE (no traffic specified), ATM_UBR (Unspecified Bit Rate), ATM_CBR (Constant Bit Rate), ATM_VBR (Variable Bit Rate), ATM_ABR (Available Bit Rate), and ATM_any (any traffic class).

The function atm_setsockopt() is used to check the socket status. If these checks run, the function check_qos() is invoked. For a PVC, the function change_qos() is used to change parameters. For an SVC, the function svc_change_qos() defined in net/svc.c is called to change.

### pvc_bind() net/atm/common.c

Next, the function pvc_bind() is invoked when the application wants to open the socket to send or receive data. The implementation does not distinguish between bind() and connect(). The function pvc_bind() is used to initialize the address sockaddr_atmvc, which is used for PVC. The other functions are located in net/atm/common.c, because they are used both for PVC and SVC.

```
atm_connect(), atm_connect_vcc(), net/atm/common.c
atm_do_connect(), atm_do_connect_dev() 
```

These functions are used in the order shown here. First, atm_connect() checks the status. Next, atm_do_connect() or the function atm_do_connect_dev() is invoked, depending on whether a network interface was specified. If no network interface was specified, then atm_do_connect() is invoked, and the function atm_find_dev() available in net/atm/resources.h is used to search the list of ATM network cards for an interface with the matching identifier. If this search is successful, then the open() function supplied by the driver (over dev->ops->open()) is invoked, much as for the function atm_do_connect_dev().

### atm_sendmsg() net/atm/common.c

The transmission of data is identical over PVC and SVC, so this functionality is maintained in the file net/atm/common.c. First, the function atm_sendmsg() waits for a transmission possibility; next, the data are sent by the driver-specific transmission routine, which is addressed over dev->ops->send().

### atm_recvmsg() net/atm/common.c

Like the function atm_sendmsg(), the function atm_recvmsg() is used for both PVC and SVC connections. The function waits in a loop for incoming data, which is copied from the socket buffer into the user space by the function copy_to_user().

### atm_release(), atm_release_vcc_sk() net/atm/common.c

We mention the function for orderly release of an ATM socket for the sake of completeness. This is done by the two functions, atm_release() and atm_release_vcc_sk(), which eventually use the close() function supplied by the driver to release all pertinent resources in the driver.
