Forwarding Packets The function ip_forward() is invoked that an IP packet has to be forwarded. (See the center part of Figure 14-10). The packet is checked again, including a test for the Strict Routing option. If this option exists, and the local address is not in the option field, then an ICMP message is returned to the sender accordingly. In this case, neither Strict Routing nor Loose Source Routing may be specified in the option field to ensure that an ICMP Redirect message can be returned to the sender.

A backup copy of the IP packet (including all packet options) has been created, because the packet could be changed in the future course. The value of the TTL variable is decremented by one. If the packet is too big and the Don't-Fragment bit is set in the IP packet header, then the packet is discarded. The netfilter is called again, but this time with the ip_forward_finish() parameter.

The function ip_forward_finish() checks the length of each IP packet. If the length is not null, then the function ip_forward_options() handles the Record Route Source Routing options, and ip_send() is invoked either case. If the packet is too big and has been fragmented, then ip_send() invokes the ip_fragment() function. Depending on whether the Copy flag is set, only some of the packet options or only the first have been copied to all fragments. This function is extremely space and time-saving. It also means that ip_options_fragment() is invoked provided that the content of the socket buffer is the first or only fragment.

The next function is ip_finish_output(), which completes the packet-forward process.

At the end, the packet is passed to the lower layers or ARP (Address Resolution Protocol—Chapter 15).
