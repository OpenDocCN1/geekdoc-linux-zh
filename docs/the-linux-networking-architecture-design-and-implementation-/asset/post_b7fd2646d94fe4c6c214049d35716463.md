
## Forwarding Packets
The function ip_forward() is invoked when an IP packet has to be forwarded. (See the center part of Figure 14-10). The packet is checked again, including a test for the Strict Routing option. If this option exists, and the local address is not in the option field, then an ICMP message is returned to the sender accordingly. In this case, neither Strict Routing nor Loose Source Routing may be specified in the option field to ensure that an ICMP Redirect message can be returned to the sender.

A backup copy of the IP packet (including all packet options) has been created, because the packet could be changed in the future course. The value of the TTL variable is decremented by one. If the packet is too big and the Don't-Fragment bit is set in the IP packet header, then the packet is discarded. The netfilter is called again, but this time with the ip_forward_finish() parameter.

The function ip_forward_finish() checks the length of each IP packet. If the length is not null, then the function ip_forward_options() handles the Record Route Source Routing options, and ip_send() is invoked in either case. If the packet is too big and has been fragmented, then ip_send() invokes the ip_fragment() function. Depending on whether the Copy flag is set, only some of the packet options or only the first have been copied to all fragments. This function is extremely space and time-saving. It also means that ip_options_fragment() is invoked provided that the content of the socket buffer is the first or only fragment.

The next function is ip_finish_output(), which completes the packet-forward process.

## Handling Packets Created Locally
A packet created locally can take either of two paths across the IP layer:

The function ip_build_and_send_pkt() is invoked. Though the passed socket contains a datagram, it doesn't have a protocol header yet. In this case, packet options are passed as parameters, separately from the payload, and all pointers in the header structure are set. Depending on whether there are options, the header length, which was previously set to "5" bytes, is corrected, and the function ip_build() is invoked with the socket buffer, the packet options, the destination address, and the routing table. Next, ip_send_check() and maybe_reroute() invoke the netfilters. The IP options have no further rule on the remaining path as the packet travels through the IP layer. At the end, the packet is passed to the lower layers or ARP (Address Resolution Protocol—Chapter 15).

The higher layers pass the IP as parameter of the function ip_queue_xmt() to the IP layer. Notice that the packet options are not directly passed as parameters to them; ip_queue_xmt() can use a pointer referring to the socket to access. The first step is to decide where the packet has to be sent. If the Source Routing option is set, then the destination address of the packet is determined by the address specified next. This requires a check for whether the option is_stricroute exists and for whether the destination address is equal to the router registered in the local routing table. In this case, the IP packet cannot be transmitted. If the route can be determined without problem, the next step clears the remaining protocol header, as in the first way.

### 1.4 INTERNET CONTROL PROTOCOL (ICMP)
The Internet Control Message Protocol (ICMP) is used for error reporting and diagnostic information. Although IP is responsible for delivering packets, it does not have a mechanism for reporting errors. ICMP provides this mechanism. ICMP messages are encapsulated within IP packets.

The following are the types of ICMP messages defined in various standards:
- RFC 792: Informs the sender that a packet cannot be delivered.
- RFC 792: Informs the sender that a packet was discarded because its TTL had expired.
- RFC 792: Reports an error in the IP header options.
- RFC 792: Informs the sender that packets were dropped due to congestion.
- RFC 792: Directs the sender to use a better path for routing.
- RFC 792: Used for connectivity testing (Echo/Reply).
- RFC 792: Used to synchronize clocks (Timestamp/Reply).
- RFC 79: Used to determine the network address of a host.

The most popular application of ICMP is the ping command, which checks the reachability of a host. Another tool is traceroute, which uses ICMP to map the path to a destination.

### 1.4.1 Functional Principle of ICMP
ICMP sends and receives special messages. Error messages occur whenever IP packets do not reach their destinations. ICMP provides information about the network state.
