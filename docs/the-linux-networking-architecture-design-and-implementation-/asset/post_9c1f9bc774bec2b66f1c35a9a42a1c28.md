## 15.1.2 Receiving an ARP Packet and Replying

As mentioned earlier, ARP Request and ARP Reply PDUs have the same packet format; they differ only in their Operation fields. An ARP request also differs from a subsequent reply by the missing layer-2 address of the destination, so that it is easy to create a reply to a request. When receiving a request packet in which the desired station fills its layer-3 address, the following steps are completed:

- The layer-2 address of the network adapter is inserted in the Layer-2 Destination Address.
- The two address fields for sender and destination are swapped.
- The Operation field takes value 2 to mark the PDU as ARP Reply.
- Finally, the reply packet is sent.

An ARP request includes a valid mapping between the layer-3 address and the layer-2 address of the request; only one entry for the initiator is created in the ARP cache.

## 15.2 THE ARP COMMAND

The arp command can be used to output the ARP table (ARP cache) of a computer. It can also be used to manipulate the ARP table (e.g., to create permanent or delete entries). The following options are available for the arp command:

Display the ARP table: you can use option -a when running the arp command to view the ARP table of a computer:

```
root@linux # arp -a
IP address             type             address
192.168.1.1           ethernet        00:0c:29:4f:8b:11
192.168.1.2           ethernet        00:0c:29:4f:8b:22
```

The first column shows the IP address of the destination; the second column shows the category (e.g., Ethernet); the last column shows the layer-2 address of the network adapter.

## 15.3 Implementing the ARP Instance in the Linux Kernel

If the word incomplete appears in the last column this means that the network device specified by the entry failed or is defective.

**Address format:** In addition to Ethernet, ARP is also used in broadcast-enabled LAN technologies (e.g., ATM networks and token ring) for address resolution. These network technologies may use different formats. Notice that arp shows only entries for Ethernet; to view a list of all addresses, you have to use option -t with the command: `arp -a -t`.

**Deleting ARP entries:** You can use option -d to remove the entry of that computer. This forces a new ARP request upon the next request for the layer-2 address of the computer. Deleting an ARP mapping can be useful when a computer's configuration is wrong or when the layer-2 address has changed—for example, when a network adapter has been replaced.

To avoid this case, ARP entries are automatically declared invalid after a certain period. This period is in the range of a few minutes, so that the replacement of a network adapter should not cause any problem.

**Setting ARP entries:** It can sometimes be useful to add an entry manually to the ARP table. The option -s computer-address is available for such cases. It can also be used when ARP requests to a specific computer are not answered because of faulty or missing ARP instances. The option -s can also be used when a computer in the same LAN identifies itself erroneously with the same IP address and replies to the ARP request. The following command adds an entry to the ARP table: `arp -s address`.

In contrast to entries determined automatically in the ARP cache, entries created with the option -s are not removed after a certain period; they remain in the ARP cache until the computer restarts (static entry).

## IMPLEMENTING THE ARP INSTANCE IN THE LINUX KERNEL

In theory, ARP would have to run address resolution for every outgoing IP packet before transmitting it. However, this would significantly increase the bandwidth. For this reason, address mappings are stored in a table—the so-called ARP cache—as the protocol learns them. We have mentioned the ARP cache several times before. This section describes how the ARP cache and the ARP instance are implemented in the Linux kernel.

Though the Address Resolution Protocol was designed for generic use, it is not used by all layer-3 protocols. For example, the new Internet Protocol (IPv6) uses Neighbor Discovery (ND) address resolution to map IPv6 addresses to layer-2 addresses. Though the operation of the two protocols (ARP and ND) is similar, they are actually two separate protocol instances. The Linux kernel designers wanted to utilize the similarity between the two protocols implemented a generic support for address resolution protocols in LANs, the so-called neighbour management.

A neighbour represents a computer that is reachable over layer-2 services (i.e., directly over the LAN). Using the neighbour interface and the available functions, you can implement special properties of either of the two protocols (ARP and Neighbour Discovery). The following sections introduce the neighbour interface and describe the ARP functions. Chapter 23 describes how Neighbour Discovery is implemented.

## 15.3 Implementing the ARP Instance in the Kernel

The set of reachable computers is managed in the ARP cache, which is organized in a hash table. The hash function arp_hash() can be used to map structures to the hash table. Linear collision occurs if several structures fall on the same hash row. The basic functions of the ARP table are handled by the neighbour management. The structures are introduced below:

```c
struct neighbour include/neighbour.h
```

The neighbour is the representation of a computer that can be reached over the data-link layer. The ARP instance creates a neighbour as soon as a layer-3 protocol (normally the Internet Protocol) asks for the layer-2 address of a computer in the LAN. This means that the ARP cache contains all reachable stations, and additionally, the addresses of stations that are currently being determined. To prevent the cache from growing endlessly, entries with layer-2 addresses that have not been requested are deleted. The neighbour structure has the following parameters:

- next: Because neighbor stations are organized in hash tables, and collisions are resolved by the chaining strategy (linear linking), the next field references the next neighbour structure in a hash row.
- tbl: This pointer points to the neightable structure that belongs to this neighbour and manages the current entry.
- parms: The neigh_parms structure includes several parameters about a neighbour (e.g. a reference to the associated timer and the maximum number of probes. See neigh_timer_handler() function, below.)
- dev: This is a pointer to the corresponding network device.
- timer: This is a pointer to a timer used to initiate the handling routine neigh_timer_handler().
