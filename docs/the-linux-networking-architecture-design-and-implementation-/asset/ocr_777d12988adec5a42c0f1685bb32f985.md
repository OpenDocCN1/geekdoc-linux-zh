# Chapter 24 Transmission Control Protocol (TCP)

tcp_transmit_skb() include/linux/tcp_output.c

tcp_transmit_skb(sk, skb) is responsible for completing the TCP segment in the socket buffer, skb, and for subsequently sending it over the Internet Protocol. To this end, it fills the TCP packet header with the appropriate values from the opt structure—for example, much like an explicit transmit credit specified by tcp_select_window(). tcp_syn_build_options() registers the TCP options for SYN packets, and tcp_build_and_update_options() registers the options for all other packets.

Subsequently, all actions required to send a payload-carrying segment or a segment with ACK flag are executed:

If the ACK flag is set, the number of permitted Quick ACK packets decrement in the tcp_event_ack_sent() method provides that the connection is in the Quick ACK mode. Subsequently, the timer for delayed ACKs is stopped, because the next step needs an acknowledgement.

If the segment is to be sent carries payload, we first have to check for whether an interval corresponding to the retransmission timeout (stored in tp->lsntime) has elapsed since the last data segment (stored in tp). If this is the case, the congestion window is set to the minimum value (tcp_cwnd_restart), as specified in RFC 2861.

Subsequently, the function pointer tp->af_specific->queue_(), which references the transmitting function—depending on the Internet Protocol version (e.g., ip_queue_xmit() for IPv4)—passes the socket buffer to the IP layer for transmission.

Finally, the tcp_enter_cwd() method adapts the threshold value for the slow-start algorithm. This completes the transmit process for the TCP segment within the TCP TCP instance, unless no acknowledgement arrives for this packet during the retransmission timeout, so that it would have to be retransmitted; see details in Section 24.5.
