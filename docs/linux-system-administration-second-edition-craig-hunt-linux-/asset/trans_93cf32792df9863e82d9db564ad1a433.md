
当然，你应该将*desired-address.com*更改为你想要用作发件人地址的地址。第一行会使From:头更改。大多数邮件客户端（MUA）使用此头来确定发件人以及回复应发送到的地址。FEATURE(*masquerade_envelope*)行使sendmail进行额外的头部替换，如果某个MUA使用非标准头部来确定发件人地址，这可能非常有用。这些选项不会更改Received:头，而Received:头对于追溯邮件的真实来源具有最大的诊断价值。

**注意** 某些MUA可以更改From:头。因此，更改你的sendmail配置可能是多余的。如果你使用MUA设置了一个From:地址，该设置将覆盖使用sendmail的伪装功能设置的任何内容。

## 配置中继

如前文“推送和拉取协议”中所述，电子邮件在其源和目标之间通常会经过多次中继。你很有可能会以某种方式应对这种情况。在某些情况下，你可能希望或需要使用*出站中继*，即你的计算机将邮件传递给另一个系统，由该系统将邮件递送到其目的地。在其他情况下，你可能需要配置计算机使其*充当*出站中继；其他计算机（例如你所在域上的邮件客户端）连接到你的Linux机器以发送邮件。每种配置都需要其自身的选项。

## 使用出站中继

在其他条件相同的情况下，sendmail能够向sendmail程序可以连接的任何其他MTA递送邮件。在大多数情况下，这意味着sendmail可以向互联网上运行自己SMTP服务器的任何系统递送邮件。配置Linux计算机直接递送邮件通常是可取的，因为这有效利用了网络资源并绕过了可能不可靠的邮件中继。Linux计算机本身*可能*就是官方邮件服务器。然而，直接发送邮件存在可能出现的问题和限制。这些包括：

-   无法到达的目的地
    如果由于崩溃或网络问题导致目标邮件服务器不可用，sendmail必须在本地保留邮件，直到问题解决。它还必须定期重新尝试递送。这些操作会消耗CPU时间、磁盘空间和网络资源，尽管可能每样都很少。更重要的是，如果发送邮件的系统具有间歇性互联网连接（例如PPP链接），由于该连接可能处于断开状态，后续的发送尝试可能会失败，从而导致邮件完全无法递送，而不仅仅是短暂延迟。

-   拨号反垃圾邮件配置
    *拨号用户列表（DUL）*是与拨号（通常是PPP）连接相关的IP地址列表。（有关DUL的更多信息，请参见 http://www.mail-abuse.org/dul/ ）。许多邮件服务器使用DUL或他人维护的类似列表来阻止来自这些连接的邮件，因为垃圾邮件发送者有时会滥用拨号线路发送垃圾邮件。如果你的ISP已将你的拨号号码列入DUL，某些收件人将基于此理由拒绝你的直接邮件。通过ISP的官方服务器中继你的邮件可以规避此问题；DUL仅*影响*直接从列入名单的地址发送的电子邮件。

-   ISP对端口25的封锁
    同样为了打击垃圾邮件，一些ISP在将出站连接指向远程系统的端口25（SMTP端口）时，会封锁其拨号地址的出站连接。如果你的ISP这样做，你就完全无法直接发送邮件；你*必须*通过ISP的邮件服务器中继邮件。

-   远程反垃圾邮件措施
    一些邮件服务器采取了相当极端的反垃圾邮件措施，其中一些可能会阻止你的访问尝试，即使你未受到DUL条目的影响，或未受到封锁端口25访问尝试的ISP的影响。例如，如果你声称的主机名与你的IP地址关联的主机名不匹配，远程站点可能会阻止你的电子邮件，使用PPP账户时这种情况很可能发生。

鉴于以上所有原因，通常建议将拨号Linux计算机配置为通过ISP的邮件服务器中继邮件。另一方面，一些ISP的邮件服务器本身也以不可靠而闻名，因此你可能更愿意冒直接发送邮件的风险。相比之下，如果你的计算机以更具持久性的方式连接到互联网，中继邮件提供的优势较少——但如果你所在的ISP或组织为此目的提供了邮件服务器，通常也几乎没有*劣势*。你可能需要咨询你的ISP或网络管理员，以了解你特定网络上的优势和劣势。当然，你也可以加入自己的个人经验——如果你知道你所在组织的邮件服务器不可靠，那么直接发送邮件可能非常可取。

Red Hat的默认配置（以及其他发行版的默认配置）直接发送邮件。要更改此配置细节，你必须在sendmail.mc或等效的m4配置文件中添加以下行：

```
FEATURE(`nolixclient', `mail.example.net')
```

**注意** 通过sendmail.mc中的FEATURE命令传递的选项通常用单引号括起来。但与其他大多数配置工具不同，m4需要不同的开始和结束引号。开始引号是反引号字符，通常位于键盘上数字1键左侧的键上。结束引号是通常的单引号字符，在大多数键盘上位于分号（;）键右侧的键上。当然，你应该将mail.example.net更改为你所在组织或ISP的邮件中继系统。当你重建sendmail.cf并重启sendmail后，结果应该是通过你本地sendmail副本发送的所有邮件都通过你指定的邮件中继系统中继。

**提示** 使用ISP的邮件中继的一个常见反对意见来自使用多个ISP的用户。由于大多数ISP会拒绝来自其域之外的邮件中继尝试，这种配置仅在一个ISP上有效。规避此问题的一种方法是创建*两个*sendmail.cf文件，每个ISP一个。将每个文件命名为适当的名称，例如sendmail.cf.isp1和sendmail.cf.isp2。然后你可以修改你的PPP拨号脚本（在第11章中描述），将自定义文件复制覆盖常规sendmail.cf并重启sendmail。结果是sendmail将通过适当的ISP邮件服务器中继。

## 配置Sendmail为域中继

配置sendmail使用另一个邮件服务器作为中继，在作为工作站的中小型Linux系统上很方便。然而，Linux通常被用作替他人中继的邮件服务器。此配置在Linux服务器拥有始终在线的专用互联网连接时效果最佳。默认情况下，所有现代Linux发行版都配置为不从其他系统中继邮件。这是一项反垃圾邮件措施，但它阻碍了将Linux服务器用作你自己计算机的中继。诀窍是*放宽*但*不移除*反中继限制。

**注意** 要使sendmail作为中继运行，它也必须配置为接收邮件。你可能需要调整你的配置以允许此行为，如“接收邮件”部分所述。

要允许sendmail从特定类别的计算机中继邮件，你必须向sendmail.mc或等效文件添加FEATURE行。此FEATURE行包含以下选项之一：

-   *promiscuous_relay*
    这个极度危险的选项告诉sendmail中继所有到达的邮件。不要使用此选项，因为它几乎可以保证垃圾邮件发送者迟早会滥用你的系统。

-   *relay_based_on_MX*
    此选项配置sendmail接受来自其他计算机的中继，只要这些计算机的域配置显示你的系统为MX。由于这基本上让其他人（控制远程系统DNS服务器的人）决定你的系统是否作为中继运行，因此此选项在安全性上相当宽松。

-   *relay_entire_domain*
    如果你设置此选项，sendmail接受来自其所属域内任何主机的邮件。这是快速将Linux系统配置为有限邮件中继的便捷方式。

-   *relay_local_from*
    如果发件人使用服务器地址作为自己的地址，此选项告诉sendmail接受中继。在某些情况下这很方便，但也很容易被滥用。

-   *relay_hosts_only*
    此选项使用访问数据库（稍后描述）允许你列出可接受或不可接受中继的单个主机。

-   *access_db*
    此功能允许你使用访问数据库（稍后描述）列出sendmail将中继邮件的域。

例如，Red Hat的默认sendmail.mc文件包含以下行：

```
FEATURE(`access_db',`hash -o /etc/mail/access.db')dnl
```

如果你的网络适合，你可以修改此行以使用其他中继选项。或者，你可以调整访问数据库文件。在Red Hat 7.3中，此文件称为/etc/mail/access，但在某些发行版中可能位于其他地方。该文件由多行组成，每行包含单个域名、机器名称或IP地址，后跟一个标签，指示sendmail如何处理从发件人收到的消息。（以井号[#]开头的行是注释，会被忽略。）Red Hat 7.3的默认配置如下所示：

```
# 默认情况下，我们允许从localhost中继...
localhost.localdomain	RELAY
localhost	RELAY
127.0.0.1	RELAY
```

有效标签如下：

-   **OK** 强制sendmail接受邮件，即使其他规则会拒绝它。
-   **RELAY** 接受来自或发往指定域的中继邮件。
