
企业工作负载涉及将负载分布到多个处理器和磁盘上，从而能够处理大量数据和高事务速率。在许多环境中，数据量正以惊人的速度增长，因此数据库管理系统需要能够通过添加更多磁盘和CPU轻松扩展到更高的负载。

DB2的并行技术将处理过程分解为可在多个处理器上并发运行的独立执行组件，从而在大型数据库上实现高度可扩展的性能。通过并行处理单个查询，可以显著缩短查询的耗时。DB2支持可扩展的增长路径，通过“纵向扩展”（SMP）或“横向扩展”（MPP）或两者兼施，轻松为现有系统添加更多处理能力。

### 1.4.1 SMP环境

过去，复杂的企业工作负载通常运行在高端的SMP（对称多处理器）机器上。在同一机器内运行并通过高带宽总线连接的大量处理器可以提供出色的性能。由于Linux版DB2与运行在高端UNIX系统上的DB2共享99%以上的代码，因此它继承了利用SMP架构的能力。DB2在SMP系统上运行的能力仅受当今Linux SMP可扩展性的限制。最近在8路Linux系统上进行的SAP基准测试⁴取得了前所未有的结果，这证明了DB2 for Linux在SMP环境中的有效性。IBM Linux技术中心的众多开发人员正与Linux社区合作，以扩展Linux在16路及更高路SMP机器上的能力。

### 1.4.2 数据库集群

使用Linux集群的驱动力在于，通过将负载分布到多个运行开源操作系统的低成本服务器上，可以更快、更可靠、更经济地完成更大的任务。如果负载增加，可以扩展集群以管理额外的需求，而不会影响性能。DB2是Linux上第一个提供内置集群功能的商业数据库。也就是说，DB2可以直接部署在Linux集群上，无需额外的集群软件。Linux上的DB2集群非常适合运行要求苛刻的事务性应用程序以及涉及大量数据的仓库，同时提供以下好处：

- 更快的处理时间
- 支持超大型数据库
- 出色的可扩展性
- 更高的可用性
- 更低的成本

将集群方法与DB2对64位Linux环境的支持相结合，可提供额外的性能和可扩展性优势。

## 数据库集群架构

主要有两种数据库集群架构：共享磁盘（shared-disk）和无共享（shared-nothing）。Oracle RAC使用共享磁盘架构。Linux版DB2采用无共享架构。

### 共享磁盘

在共享磁盘环境中，每个数据库节点都有自己的处理器，但与其他节点共享磁盘。因此，所有处理器都可以访问集群中的所有磁盘。这带来了协调节点间资源和锁的额外开销。例如，如果节点1想要访问某个磁盘上的数据，而该磁盘已被集群中的另一个节点锁定以进行更新，则节点1必须等待其他节点完成操作。虽然这在集群中节点较少时（例如大型机环境）效果很好，但分布式锁管理和缓存一致性问题的开销会严重限制可扩展性，并在四个或更多节点时导致性能下降，从而无法在Linux上利用大型集群的经济性。此外，这种方法需要专门的硬件和软件来进行共享磁盘和缓存管理，使其比无共享架构昂贵得多。
