Kali Linux 的安装程序确实可靠，但遇到错误或外部问题（如镜像源、网络问题等）是非常常见的。因此，在这些情况下，您只需要对安装过程进行故障排除以便继续进行。

每当 Kali Linux 安装程序失败时，都会出现显示“安装步骤失败（Installation Step Failed）”的屏幕。此时，您需要知道 Kali Linux 安装程序在多个虚拟控制台上运行：您可以在第五个控制台上看到主界面（对于图形界面安装程序使用 `CTRL+Alt+F5`），也可以在第一个控制台上看到主界面（对于文本安装程序使用 `Shift+F4`）。

在这两种情况下，通过 `CTRL+Shift+F4` 的第四个控制台将帮助显示安装程序内部确切正在发生的所有相关日志。您可以通过更详细的错误信息轻松地评估安装程序问题的原因，例如“安装程序日志屏幕（the log screen of installer）”，这表明目标机器空间不足，安装程序无法继续该步骤。

第三个和第二个控制台（分别为 `CTRL+Shift+F3` 和 `CTRL+Shift+F2`）托管了 `shell`，可以使用它们对当前状况进行更详细的调查。大多数命令行工具都由 `BusyBox` 提供，因此功能set较有限。但它们足够解决您在安装 Kali Linux 过程中可能遇到的大多数问题。

当您点击“安装失败（Installation Failure）”主界面上的“`Continue`”时，安装程序将带您回到一个在正常情况下不会看到的屏幕——Kali Linux 安装程序的主菜单（Main Menu）。此屏幕将让您能够逐个启动安装步骤。如果您能够借助安装程序 `shell` 访问解决问题，就可以轻松地从失败的步骤重新开始。

通过安装程序 `shell`，您可以使用命令 `debconf-get` 和 `debconf-set` 轻松地检查并修改 `debconf` 数据库。这些命令用于测试先前的值。可以使用 `more` 或 `cat` 检查任何文件，如位于 `/var/log/syslog` 的完整安装日志。您还可以使用 `nano` 编辑系统上安装的任何文件。

如果您仍然无法解决安装问题，可以提交 bug 报告。bug 报告需要包含安装程序的日志，可以通过主菜单中的“`Save Debug Logs`”轻松检索。

通过这种方式，您可以用多种方式导出日志，例如挂载的文件系统、软磁盘或 Web 上。保存调试日志最方便的方法是让 Kali Linux 安装程序启动一个用于托管日志文件的 Web 服务器。您可以从位于同一网络中的任何其他计算机上启动 Web 浏览器，然后下载所有可用日志文件。

还有其他各种简单的方法可以排除 Kali Linux 安装的故障。让我们来看看这些：

- 下载官方格式的 Kali Linux 镜像：确保您已从官方网站下载了 Kali Linux 的 ISO 文件。镜像文件有多种格式，如 ISO 文件、ARM 镜像和 VMware 镜像。ISO 文件有两种格式：32 位和 64 位。VMware 镜像预装了 VMware 虚拟机。VMware 镜像格式为 32 位 PAE。在 ARM 镜像的情况下，并非所有格式的镜像都能适用于所有 ARM 设备。在 Kali Linux 网站上，您可以找到各种设备的 ARM 镜像，如 rk3306 mk/ss808、`ODROID-U2/X2`、`Samsung Chromebook`、树莓派等。
- 验证下载镜像的 SHA1 校验：在下载 Kali Linux 镜像时，请确保检查了下载镜像旁提供的 `SHA1SUMS.gpg` 和 `SHA1SUMS` 文件。在验证镜像之前校验和，请确保 `SHA1SUMS` 文件是唯一一个由 Kali 生成的文件。

您需要遵循的下一步是设置驱动器、对其进行加密和分区。将弹出一个对话框，要求您选择安装所需的分区类型。选择“引导式使用整个磁盘”（`Guided-Use Entire Disk`）以获得最佳性能。与仅对 `/home` 目录加密相比，这也有助于对整个 USB 盘进行完全加密。请始终记住，在渗透测试时，Kali Linux 的工具会将所有数据存储在主目录（`home directory`）之外的各种其他地方。

- 现在系统将开始分区过程，分区完成后安装系统将启动。

将 USB 盘插入机器并启动。在启动过程中，打开启动菜单并选择要使用的 USB 盘。现在将要求输入口令，输入成功后系统将启动。

# 管理文件系统的 Linux 命令

- **`ls`**: 此命令有助于列出当前目录下的所有内容。当向它提供路径时，它将仅列出特定路径的内容。您需要了解的一些有用选项有 `-l` 和 `-a`，它以长列表格式显示信息，包含更详细的信息，并显示点点隐藏文件。
- **`cd`**: 此命令有助于从当前目录跳转到指定的目录。当您不带任何参数使用此命令时，它将返回主目录。当您使用带有两个点的命令 `cd..` 时，它将带您返回上一级目录；使用带有连字符的命令 `cd –` 则将返回到之前的目录，无论其相对于当前目录的位置如何。
- **`pwd`**: 此命令有助于打印当前目录。当您的提示符不包含此特定信息时，此命令非常有用。它对于获取执行代码时的目录引用的 BASH 编程非常有用。
- **`file`**: 该命令有助于指明文件类型。由于 Linux 系统中的文件并不强制要求具有与系统相关的扩展名即可运行，用户有时难以获取文件的确切类型。此命令有助于解决与 Linux 相关的这类类型问题。
- **`cp`**: 该命令用于复制所有目录和文件。由于此命令默认不递归复制目录，请务必记住在使用命令时配合 `-a` 或 `-r`。`-a` 命令可以在复制的同时帮助保留文件的所有权、模式和时间戳。
- **`mv`**: 它用于重命名或移动目录和文件。重命名和移动可以被视为单一操作，重命名仅仅是将一个单个文件以不同的名称移动到相同的位置。
- **`rm`**: `rm` 命令用于删除目录和文件。这是一个非常基础的命令，你需要它，因为没有它你无法移除任何杂物。然而，在使用此命令时必须格外小心，因为它会永久删除文件和目录。与其他命令不同，此命令甚至不会将删除的文件和目录存储在其他地方以便日后找回。一旦删除，就永远消失了。因此，在这种情况下，配合命令使用 `-r` 开关是非常重要的。
- **`ln`**: 此命令用于在文件之间创建符号链接或硬链接。软链接（符号链接）类似于 Windows 的快捷方式，提供了一种访问任何特定文件夹或文件的非常方便的方法。
- **`chmod`**: 它有助于更改用户的权限。权限包括对文件的写入、查看和执行。任何用户都可以更改其拥有文件的用户权限。
- **`chown`**: 该命令用于更改文件的所有权。只有 `root` 用户（`root`）才能使用此命令并更改文件所有权。为了递归更改目录内所有文件的所有权，你可以使用带有 `-R` 参数的命令。
- **`find`**: 此命令用于在整个文件系统中搜索特定的目录或文件。此命令本质上非常强大，不仅是因为它具有搜索能力，还因为它允许用户在匹配或不匹配的文件上执行任何任意形式的命令。
- **`locate`**: 与 `find` 相反，`locate` 命令通过数据库搜索文件名的模式。这种数据库形式由整个文件系统的快照组成。
- **`du`**: `du` 命令用于显示目录或文件的大小。在各种可用选项中，`--s` 提供摘要而非完整列表，`-h` 将报告的大小转换为更符合人类阅读习惯的格式，`--d` 则有助于控制目录的递归深度。
- **`df`**: 此命令用于显示磁盘的使用情况。该命令的默认输出列出了每一个文件系统，报告它们的大小以及已用空间和可用空间。你可以在此命令上添加 `-h` 以获取更符合人类阅读习惯的格式报告。
- **`dd`**: 该命令有助于根据手册转换和复制特定文件。你需要为此命令提供源和目的地，它将分别复制文件。
- **`mount/unmount`**: 这对命令执行文件系统的挂载和卸载功能。这一系列操作范围可以从 USB 闪盘到 ISO 镜像。
- **`more/less`**: 这两个命令的功能非常相似，允许用户按屏幕显示量分块查看文本。假设某些命令（如用于文件的 `cat`）产生了非常庞大的输出，而模拟器需要一些时间来滚动整个文本。当你使用这些命令中的任一个时，现在可以轻松地滚动文本了。与 `more` 相比，`less` 更为现代，因此现在不再使用 `more`。
- **`head/tail`**: 这也是一对命令，但它们都有各自的用途。`head` 命令有助于输出文件从第一行开始的内容，`tail` 命令通过提供任何文件最后一行的内容来提供帮助。默认输出行数
- **`grep`**: 此命令通过在文本中搜索模式来提供帮助。它可以是正则表达式也可以是普通字符串。它还可以打印匹配或不匹配的行。
- **`sort`**: 此命令用于根据标准对行进行排序。此命令可以使用的有用开关有 `-n`（数字）和 `-r`（降序）。

## 常用系统命令

- `wc`：`wc` 命令用于统计字、行、字节和字符数。
- `diff`：此命令有助于逐行显示两个文件之间的差异。
- `kill`/`xkill`/`pkill`/`killall`：所有这些命令用于杀死和终止任何进程。它们之间的区别在于它们接受的参数。`kill` 命令接受 ID，`xkill` 命令允许用户点击窗口进行关闭，而 `killall` 和 `pkill` 则接受进程名称。
- `ps`/`pgrep`：`ps` 有助于打印有关活动进程的信息。`pgrep` 通过要求进程名称来工作并返回进程 ID。
- `top`/`htop`：这两个命令的功能相似，都有助于显示进程。它们也可以被视为控制台系统的监控器。
- `time`：此命令作为一个进程运行。你可以将其认为是执行程序的计时秒表。
- `su`/`sudo`：这两个命令都是实现相同目标的不同方式——以其他用户的身份运行命令。这两个命令的区别在于，`su` 切换到另一个用户，而 `sudo` 仅以其他用户的权限运行命令。
- `date`：与 `time` 命令不同，此命令有助于结合标准输出格式打印时间。输出也可以根据用户规范进行格式化，并包含了月份、日期和年份。
- `alias`：此命令有助于创建和更改某些命令的别名。这意味着你可以轻松为新命令提供新名称，或重命名已有的命令。它对于缩写可能引起产生问题的长命令字符串非常有用。
- `uptime`：此命令将告诉你系统运行持续的时间。它不是非常重要，但有助于了解系统处理的总时间。
- `sleep`：此命令有助于在指定的时间段后关闭系统。
- `useradd`, `usermod`, `userdel`：所有这些命令都将帮助你添加、修改和删除用户账户。如果你是系统的唯一用户，可能并不太需要这些命令。但如果系统同时被多个用户使用，那么这些命令将非常有用。
- `passwd`：此命令允许你更改用户账户的密码。作为 root 用户，你可以重置所有普通用户的密码，但你无法查看这些密码。

定期更改密码至关重要。

## 手册与命令行基础

- `man` / `whatis`：`man` 命令通过显示某个特定命令的帮助手册来提供帮助。大多数命令行命令都可以被视为 Linux 系统的优势之一。CLI 或命令行界面允许用户完全摆脱对发行版的限制。它还让与系统交互的任务变得简单得多。Ubuntu 的派生版本使用相同的代码基础，但它们都带有一套完全不同的工具来执行相同的工作。相似发行版上不同形式的桌面环境需要不同的方式来完成相同形式的任务。作为用户，你需要忘记已经知道的过程，然后重新学习执行相同任务的过程，因为它们在不同发行版之间切换。Linux 命令行节省了 GUI 消耗的系统资源。因此，如果你在较慢的系统上工作，使用命令行比使用 GUI 好。

很多人认为命令行非常困难；然而事实如此。它就像给朋友发消息一样，你只需要告诉系统做什么。

Shell 无非一个将输入的文本转换为计算机系统执行的指令或命令的程序。你可以使用各种形式的命令来执行相同的任务。Linux 中可以找到各种 shell，但最流行的 shell 是由 GNU 项目编写的 `BASH`。另一种现代 shell 形式是 `zsh`，你可以轻松为你的发行版安装它。

如果你在桌面环境中工作，你需要一个终端模拟器在特定界面内模拟终端。不同形式的发行版自带自己的模拟器：KDE 附带 `Konsole`，Gnome 也附带 `Gnome terminal`。

当你打开终端模拟器时，默认情况下将处于登录用户的家目录中。你可以轻松地找到登录用户的用户名以及主机名。`$` 表示你以普通用户身份登录，而 `#` 表示你已以 root 身份登录。除非你在执行任何形式的管理任务或在 root 目录之外运行，否则永远不要以 root 身份运行。

这将更改你已工作过的所有目录及其文件的权限，并将你变为所有目录的 root 用户。你可以使用 `ls` 命令轻松列出所有可用目录及其内部的文件。

如果你需要更改任何目录，请使用 `cd` 命令。你还可以使用 `tab` 键，它有助于自动补全完整路径。你可以使用正斜杠来进入目录。如果你想进入当前目录的子目录，不需要提供整个路径。要查看目录的内容，不需要切换目录。只需使用 `ls` 命令查看特定目录的内容即可。

大多数使用 Linux 命令行工作的开发者都熟悉命令的基本形式，如 `cd`、`ls`、`tail`、`head`、`cat`、`grep`、`find`、`sort` 等。高级用户需要知道如何操作像 `awk` 和 `sed` 这样的工具，甚至是 perl 单行命令。通过 `BASH` 脚本知识，你会发现想象力是唯一的限制。让我们来看一些高级形式的命令行。

## 高级命令行工具

- `watch`：此命令运行像一个非常精美的程序，定期执行一个程序并在全屏上输出其内容。如果你将命令放在引号内，你也可以一次运行一个命令，例如

- `iconv`：此命令有助于将一种方式编码的文件转换为另一种格式。
- `nc`：此命令能够完成一切，也可以用于检查服务请求并确保发送了正确的标头。

大多数人使用图形化文件管理器来查找 Linux 中的文件，如 Gnome 中的 `Nautilus`、`Xfe` 中的 `Thunar` 以及 KDE 中的 `Dolphin`。然而，你也可以使用命令行查找 Linux 中的各种内容，这甚至不取决于你使用的桌面管理器。

`find` 命令允许你搜索已经知道可能文件名的文件。该命令的最简单形式搜索当前目录下的所有文件，然后根据你的搜索标准搜索其子目录。你可以通过名称、组、所有者、类型、日期、权限等各种其他标准来搜索文件。在命令后输入点（`.`）如 `find.`，将列出当前目录下找到的所有文件。为了查找匹配特定模式的文件，你可以使用参数 `--name`。你可以提供文件名的元字符如 `*`，但你需要在它们前面加上反斜杠 `\` 或将其封装在引号内。如果 `find` 命令无法找到任何符合你标准的文件，它将不会产生输出。

## 使用 `locate` 命令

此命令返回一个包含特定字符组的所有路径名称的大列表。该命令最简单的形式是查找从根目录开始的文件系统中的所有文件。如果你想找到符合你提供的特定标准且仅符合该标准的目录或文件，可以在使用命令时配合使用 `--b` 参数，如 `locate --b \yourdata`。反斜杠在命令行中被用作通配符（globbing character），它提供了一种将非特定性质文件名中的通配符字符扩展为一组特定性质文件名的方法。

通配符无非一种符号，在评估整个表达式时，它可以被轻松替换为一个或多个字符。最广泛使用的通配符符号形式是 `?`，它表示单个字符；以及 `*`，它表示一长串字符。`mlocate` 命令是 `locate` 命令的新形式。它有助于索引整个文件系统。然而，搜索结果仅包含当前用户有权访问的文件。每当你更新 `mlocate` 数据库时，它会保留数据库中的时间戳信息。

此命令返回在发布任何命令时调用的可执行文件的确切路径。

`which` 命令对于查找任何可执行文件的位置非常有用，其目的是在用户桌面、任何面板或桌面管理器中的其他地方为该程序创建快捷方式。`which` 命令默认只会显示第一个匹配的可执行文件。为了显示所有匹配的可执行文件，你需要在使用命令时配合使用选项 `--a`。

为了创建空文件，你可以使用 `touch` 命令。在假设文件内容已更改但没有任何变化的情况下，该命令有助于更新文件的 `mtime`（修改时间）和 `atime`（访问时间）属性。当你 `touch` 任何实际不存在的文件时，系统将创建该文件而不向其中放入任何数据。你可以使用如下命令：`touch myfile.txt`。只有当文件不存在时，此命令才会创建一个名为 `myfile.txt` 的新空文件。

有时你可能需要将命令的输出结果保存到特定文件中。为了轻松实现这一目标，你需要使用符号 `>` 将结果输出重定向到某些特定文件。例如，`echo` 命令被用于将文本作为输出。因此，命令将是：`echo "example text"`。此命令会将文本打印在屏幕上，然后返回命令行提示符。要将此相同输出重定向到文件，你可以使用 `>`。例如，`echo “example text">myfile.txt`。这将把“example text”文本放入名为 `myfile.txt` 的文件中。如果 `myfile.txt` 不存在，系统将创建它。如果它已经存在，该文件的所有内容将被覆盖；它将破坏该文件的原有内容并替换为新文本。

重定向操作符 `>>` 与 `>` 相似。然而，该命令不是覆盖文件内容，而是将新数据附加到该文件的末尾位置。例如，`ls -l>>directory.txt`。此命令将获取 `ls -l` 的输出并将其添加到 `directory.txt` 文件中。如果文件不存在，系统将创建它。如果它已经在系统中存在，`ls -l` 的输出将附加到文件末尾，位于现有文件内容最后一行之后。

# Linux 环境变量与常用工具

## Shell 基础

shell 是一种特殊的用户程序，有助于为与操作系统相关的服务提供良好的接口。shell 接收用户人类可读的命令，然后将其转换为内核可以理解的内容。它可以被视为命令语言的解释器，有助于执行从键盘等输入设备或从系统文件中读取的命令。shell 在用户登录系统或启动终端时启动。

shell 可以被轻松分为两类：

- 图形化 shell
- 命令行 shell



# 图形化 shell

图形化 shell 提供了各种方法用于操作基于 GUI 或图形用户界面的程序。这是通过允许关闭、打开、调整大小和移动窗口等操作，以及在窗口之间切换焦点来实现。Ubuntu 操作系统和 Windows 操作系统可以认为是很好的示例，它们为用户提供了 GUI，以便与各种程序进行交互。

# 命令行界面

用户可以使用 CLI 或命令行界面访问 shell。Linux 中提供了一种名为终端（terminal）的特殊类型程序，用于输入诸如 `ls`、`cat` 等其他人类命令，并对其进一步执行。最终结果将直接显示在终端上，供用户查看。假设你执行了 `ls` 命令并带有 `-l` 选项。这将以长列表的形式列出当前工作目录下的所有可用文件。

# Linux 中的 Shell 类型

在 Linux 系统中，有多种类型的 shell 可供用户：

- `BASH`: 也称为 Bourne Again Shell，广泛用于基于 Linux 的系统。它被作为 Linux 系统登录的默认 shell。如果你需要，也可以在 Windows 操作系统中安装它。
- `CSH`: 也称为 C shell，它使用 C shell 的语法，其用法与 C 编程语言大同。
- `KSH`: 也称为 Korn shell，它是 POSIX Shell 标准的基础。

每种 shell 的功能方式相同，但它们都能够理解各种命令并提供各种内置函数。

# Shell 脚本

通常情况下，shell 本质上是交互性的，这意味着它们可以接受用户的命令作为输入并执行它们。然而，可能会出现你需要或想要以例行方式执行大量命令的情况，这样你每次都需要在终端内输入所有命令。由于 shell 也可以以文件的形式接受命令，你可以将命令写在一个文件中，然后在 shell 中执行它们，以避免重复任务。所有这些文件被称为 Shell 程序（Shell Programs）或 Shell 脚本（Shell Scripts）。Shell 脚本的结构与 MS-DOS 中的批文件相似。每个 shell 脚本都以 `.sh` 文件扩展名保存，例如 `yourscript.sh`。

shell 脚本也像所有其他语言一样具有语法。如果你已经熟悉 C、C++ 或 Python 等任何编程语言，那么开始编写 shell 脚本对你来说更容易。shell 脚本包含：

- Shell 关键字：包括 `else`、`if`、`break` 等
- Shell 命令：包括 `ls`、`cd`、`echo`、`touch`、`pwd` 等
- 控制流：包括 `if..then..else`、`shell` 和 `case` 循环等

你可以使用 shell 脚本来避免重复性工作，从而选择自动化。它有助于监控系统，并允许为 shell 添加各种新功能。

## 网络类型

计算机网络可以分为两大类：有线和无线。在谈到有线网络时，它需要一种物理形式的网络，用于在两个节点之间传输信息。对于商业场所家庭的数字通信，由于其整体的成本效益和耐用性，使用了以太网线。今天，光纤也被用于跨距离的数据传输。

光纤提供的速度比以太网线更快。然而，与光纤相比，以太网线便宜得多。

在无线网络形式中，利用电波通过空气传输数据。在这种情况下，设备之间不需要任何形式的电缆连接。无线局域网（WLAN）被广泛用于网络目的。今天可以找到各种替代方案，如蓝牙、卫星、蜂窝网络和微波等。

通过各种实践经验发现，与无线网络模式相比，有线网络具有更好的速度、安全可靠性。但与有线网络相比，无线网络具有更大的扩展性、灵活性。两种类型的网络都根据网络的物理层进行分类。它还可以根据网络的构建和设计结构、网络叠加以及用于 SDN 的方法进行区分。网络还可以根据广域网（WAN）、局域网（LAN）、存储区域网（SAN）、环境等方面进行分类。

## 网络系统及其类型

## 网络组件

网络系统需要适当物理形式的网络基础设施。它由多个网络组件组成，如交换机、路由器、访问点以及一些基础形式的固件，这些固件最终有助于连接组件的运行。其他组件包括用于网络安全、监控和管理的软件。

每个网络主机的物理形式形式的地址被称为 MAC 地址。它与网络接口卡（NIC）保持连接。你可以找到 48 位或 12 个半字节（nibble）的 MAC 地址。MAC 地址是在设备制造时分配给设备的。

## ProxyChains 的功能

ProxyChains 的主要功能是：

- 它支持 SOCKS4、SOCKS5 以及基于 HTTP CONNECT 的代理服务器。
- ProxyChains 可以与列表中的任何其他类型的代理混合。
- ProxyChains 支持多种链式方法，例如：随机模式（random），即在配置文件的列表中随机选择任何一个代理；或者按类似的列表顺序链式代理，通过文件中的换行符将不同形式的代理彼此分开。它还带有一个动态选项（dynamic），ProxyChains 只通过那些本身处于活动状态的代理。它排除了任何形式的无法访问或失效的代理。这种代理形式也被称为智能选项（smart option）。
- 你可以将 ProxyChains 与 sendmail、squid 等许多服务器一起使用。
- ProxyChains 还具有通过代理解析 DNS 的。
- 它可以处理任何形式的 TCP 客户端应用程序，如 telnet、nmap 等。

## ProxyChains 的语法

与其仅仅运行简单的渗透测试或直接使用你的 IP 地址创建各种目标请求，你可以使用 ProxyChains 来涵盖并处理这些工作。你只需要为每项任务添加命令 `proxychains` 即可。这将启用 ProxyChains 服务。

```

## 渗透测试的细节

这是一个测试系统的过程，用于发现第三方是否可以渗透系统。道德黑客经常与渗透测试混淆，因为两者的目的在某种程度上是相似的，且功能或多也相同。在渗透测试中，渗透测试人员扫描系统以寻找任何形式的系统漏洞、缺陷、风险和恶意内容。你可以在在线形式的环境、服务器甚至计算机系统中执行渗透测试。渗透测试具有最终形式的目标：增强系统安全性，并防御组织结构免受潜在攻击和威胁。

渗透测试是完全合法的，并与其他官方工作一起进行。当以正确和适当的方法使用时，渗透测试具有作为道德黑客的潜在部分进行测试的能力。你需要定期进行渗透测试，因为它可以提高系统能力。它也有助于提高网络安全。为了找到程序、系统或应用程序中的所有弱点，渗透测试人员会创建各种形式的恶意内容。为了进行有效的测试，有害内容会传播到整个网络中进行漏洞测试。

渗透测试使用的技术可能无法处理所有的安全问题，但它可以帮助减少系统受到攻击的可能性。渗透测试确保组织或公司绝对免受所有威胁，并有助于提供来自攻击的保护。它还指示了组织需要更改的安全措施。所有关于渗透测试的报告都会交给系统管理员。

## SQL 注入与 Wi-Fi 破解

提到网络攻击时，最广泛的形式之一是 SQL 注入攻击。在这种攻击中，攻击者执行威胁或无效格式的 SQL 语句，用于控制 Web 应用程序的数据库服务器。它还用于在用户完全不知情的情况下修改、删除或添加数据库中的记录。这最终会损害数据的完整性。避免或防止 SQL 注入所可以采取的最重要步骤是输入验证。

## SQL 注入及其类型

今天你可以找到多种类型的 SQL 注入。让我们来看看它们：

- 经典或带内 SQL 注入：
  1. 基于错误（Error based）：攻击者利用数据库生成的错误来攻击数据库服务器。
  2. 基于并集（Union based）：在这种情况下，使用 UNION SQL 运算符来组合返回到 HTTP 响应的响应。
- 推断或盲注 SQL 注入：
  1. 基于布尔（Based on Boolean）：基于返回真或假。
  2. 基于时间（Time based）：发送 SQL 注入强制数据库在响应之前等待。
- 带外 SQL 注入（Out of band）：当攻击者无法使用类似的通道进行攻击和收集结果时，就会发生这种情况。

## 用于 SQL 注入的工具

有多种工具用于执行 SQL 注入。

- `SQLMap`：该工具用于自动形式的 SQL 注入，并能帮助接管数据库。
- `jSQL Injection`：这是一个基于 Java 的工具，用于 SQL 注入。
- `Blind-SQL-BitShifting`：通过位移（BitShifting）进行盲注 SQL 注入。
- `BBQSQL`：一种盲注形式的 SQL 注入利用工具。
- `explo`：一种机器和人类可读的漏洞测试格式。
- `Whitewidow`：用于检查 SQL 数据库漏洞的扫描工具。
- `Leviathan`：它充当一个音频工具包。
- `Blisqy`：用于在 HTTP 头部中利用基于时间的 SQL 注入。

## Wi-Fi 破解

Wi-Fi（或无线网络）是当今世界用于网络连接的首选媒介。然而，由于其流行性，无线网络也面临各种攻击以及若干安全问题。如果攻击者获得了网络连接的完全访问权限，攻击者可以从任何附近的位置嗅探数据包。攻击者利用嗅探工具寻找 SSID，然后破解 Wi-Fi 或无线网络。在成功破解后，攻击者可以监控所有设备。

## 破解 Wi-Fi 的工具

为了破解 WEP，攻击者使用诸如 Acrack、Aircrack、Kismet、WEPDecrypt 等多种工具。为了破解 WPA，会使用 Cain 和 Cowty 等工具。还有其他常用工具，如 `wireshark`、`Airsnort`、`Wifiphisher`、`Netstumbler` 等。Android 可以被认为是最常见的手机平台，但它也非常受到某些特定类型漏洞的影响，这最终使得攻击者更容易利用设备安全并从中窃取数据。对移动设备最危险的威胁是第三方应用程序、电子邮件木马和短信。

## 如何进行 Wi-Fi 攻击？

大多数网络攻击都是通过设置流造访问点（Rogue Access Points）实现的。

- 恶意孪胎攻击（Evil Twin attack）：在这种情况下，黑客设置一个与公司场所附近的企业 AP 命名相同的虚假访问点。当公司的任何员工连接到该访问点时，该员工在不知情的情况下提供了实际访问点的所有身份验证详细信息。因此，黑客可以轻松地破坏整个连接。
- 信号干扰（Signal jamming）：黑客可以通过干扰网络信号来轻松中断网络连接。这是通过各种用于产生噪声的工具实现的。
- 配置错误攻击（Misconfiguration attack）：当网络路由器使用默认配置形式、弱加密形式、弱凭据和算法进行设置时，攻击者可以轻松破解网络。
- 热点攻击（Hotspot attack）：攻击者设置与任何公共 Wi-Fi 访问点 SSID 名称相同的虚假热点或访问点。当任何用户无意中连接到该访问点时，黑客可以轻松进入实际网络。

## 如何执行有效的攻击

“黑客”一词并不意味着它总是是负面的。只有当你对背后的过程有清晰的感知时，你才会对黑客的整个过程有一个正确的理解。你不仅能够学习黑客的过程，还能让你的系统受到来自外部攻击的保护。大多数时候，当攻击者尝试获取组织或公司的服务器访问权限时，通常是使用 5 个正确的步骤完成的。让我们来看看这些步骤。

- **侦察 (Reconnaissance)**：这可以被视为黑客过程的第一步。在此阶段，攻击者利用所有可用手段，收集有关主要目标系统的所有形式的相关信息。相关信息可能包括对目标的正确识别、服务器的 DNS 记录、目标范围内的 IP 地址范围、网络以及其他各个方面。简单来说，攻击者试图收集各种信息以及网站或服务器的联系方式。攻击者可以通过使用 `maltego` 等多种形式的搜索引擎、通过对目标系统进行研究，或者使用如 `HTTPTrack` 等各种工具下载完整网站以供后续阶段进行枚举来实现。

通过执行所有这些步骤，攻击者能够非常容易地确定组织内所有人员的名称，找到指定的职位以及员工的电子邮件地址。

- **扫描 (Scanning)**：在收集了目标的所有相关信息后，攻击者现在开始扫描过程。在此阶段，攻击者采用拨号器、端口扫描器、漏洞扫描器、扫描器和网络映射器等各种工具对目标网站或服务器数据进行扫描。在这一步中，攻击者试图寻找所有实际上有助于执行成功攻击的信息，例如系统的 IP 地址、该服务器内的用户帐户和计算机名称。黑客完成基础信息的扫描后，他们开始测试目标网络以寻找可能的攻击途径。他们还可能采用像 Kali Linux 这样的多种方法进行网络映射。黑客还会寻找任何自动电子邮件系统，通过该系统向目标公司的员工发送某些虚假查询，例如向公司人力资源部门发送职位查询。

- **获取访问 (Access gaining)**：这是所有步骤中最重要的一的一步。在此阶段，攻击者根据第一步和第二步收集的所有相关信息，设计目标网络的蓝图。在黑客完成数据枚举和系统扫描后，他们现在将转向获取系统的访问权限，这将基于所收集的信息。

- 例如，攻击者可能决定使用钓鱼攻击。攻击者总是试图采取稳妥的方法，可能会使用非常简单的攻击来获取系统的整体访问权限。攻击者还可能从 IT 部门的终端渗透系统。黑客利用公司真实的电子邮件地址使用钓鱼邮件。通过使用此钓鱼邮件 ID，攻击者将向技术人员发送邮件，邮件中将包含形式的特殊程序以及用于收集登录密码和 ID 的钓鱼网站。为此，攻击者可以使用手机应用、网站信箱或其他方法，然后要求员工使用他们的凭据登录新网站。当黑客使用这种方法时，他们已经在后台运行了一个特殊类型的程序，该程序被称为社会工程工具包（Social Engineering Toolkit），用于使用用户的地址发送邮件。

- **维持服务器的访问 (Maintaining access to the server)**：在攻击者获得目标服务器的访问后，他们将尝试一切可能的方法确保其服务器访问的安全，以便未来的攻击和利用。由于攻击者现在拥有服务器的整体访问权限，他还可能将服务器作为其启动其他形式攻击的基地。当攻击者获取整个系统的访问权限并拥有该系统时，这种系统被称为僵尸系统（zombie system）。黑客可能还会尝试通过创建一个新的管理员账户来隐藏自己，以便无人不知的情况下与系统融合。为了确保访问系统的安全，黑客会追踪所有长时间未使用的帐户，然后将所有帐户的权限提升给自己。

当黑客确保没有人察觉他在系统中的存在时，他开始复制该服务器上的所有数据，以及联系人、消息、机密文件等以备以后使用。

- **清除踪迹 (Clear of tracks)**：在开始攻击之前，黑客们会规划他们的整个轨迹，以确保无人能够追踪到他们。攻击者从更改系统 MAC 地址开始，然后通过 VPN 运行整个系统，这样就无人能追踪他们的真实身份。

## 术语

## 入口测试，渗透测试（Pentesting）

渗透测试是分析人员在明确规则内采用的方法、程序和方法论，旨在尝试绕过数据框架的安全，包括消除该框架的协调安全防护。此类测试与评估框架的技术、法规和操作设置及控制有关。

常规渗透测试仅评估处于构建状态的数据框架的安全性。目标系统的管理员和人员可能会意识到渗透测试正在进行。

## 红队，红队演习（Red Teaming）

红队在程序和方法上模拟潜在的敌人。

这些小组通常比渗透测试小组更大，拥有更丰富的经验。渗透测试本身通常是红队演习的一个组成部分，然而这些活动测试了组织安全设备的不同元素。红队经常通过技术、社交和物理方法攻击组织。他们经常利用与黑客（Black Hat Hackers）类似的程序来测试组织或数据框架对抗这些敌角色的能力。除了渗透测试，红队还将执行社会工程攻击，包括网络钓鱼和针对性网络钓鱼，以及包括翻找垃圾桶和开锁在内的物理攻击，以获取数据和访问权限。总的来说，目标组织的员工通常不会意识到正在进行红队演习。

## 道德黑客（Moral Hacking）

道德黑客是专家渗透分析师，为了框架所有者或拥有数据框架的组织的利益而攻击框架。就本书的而言，道德黑客与渗透测试是同词。

白帽（White Hat）是道德黑客或计算机安全专业人员的俚语，他们信奉能够提高数据框架安全性的哲学。

## 黑帽（Dark Hat）

黑帽是一个术语，用于区分利用专业方法在未经许可的情况下绕过框架安全实施不道德行为的个人。渗透测试人员和红队人员经常利用黑帽所使用的策略，在执行批准的活动或测试时模仿这些人。黑帽在未经授权和非法的情况下引导他们的活动。

黑帽指的是一种跨越白帽和黑帽界线的专业大师。这些人经常尝试在未经许可的情况下绕过数据框架的安全防护，不是为了利益而是为了让框架管理员意识到发现的缺陷。黑帽通常没有测试框架的授权，但通常不是财务上的额外负担。

## 无能力评估，脆弱性分析（Powerlessness Assessment, Vulnerability Analysis）

无能力评估用于评估数据框架的安全设置。此类评估包括对已应用于框架或缺失的安全补丁进行评估。漏洞评估团队（VAT）可以位于框架之外，也可以是框架支持人员的一部分。

## 安全控制评估（Security Controls Assessment）

安全控制评估评估数据框架与明确法律或行政要求的一致性。这些要求的示例包括但不限于《联邦信息安全管理法》（FISMA）、支付卡行业标准（PCI）和《健康保险可移植性与责任法》（HIPAA）。安全控制评估被用作组织用于证据链（BOE）的一部分，以批准数据框架在生成环境中的运行。一些框架要求渗透测试作为安全控制评估的主要方面。

## 恶意用户测试（Noxious User Testing, Malicious User Testing）

在恶意用户测试中，评估人员接受扮演具有恶意的内部人员、怀有敌意的客户或滥用者的工作。在这些测试中，评估人员被赋予授权或管理客户的凭证，通常作为一个测试账户。评估人员将利用这些权限尝试绕过安全限制，同时查看文件和设置以寻找记录未获得许可之处，更改不应更改的设置，并将自己的权限提升至超过记录应拥有的水平。恶意客户测试模拟了特权内部人员的行为。

## 社会工程学（Social Engineering）

社会工程学攻击通常对数据框架或客户是有害的。社会工程工程师利用人们帮助他人的自然需求来换取进入数据框架。常见的社会工程学策略包括试图让工作区域检查员重置客户账户密码，或让最终客户暴露他们的密码，从而使社会工程师能够登录他们未获得授权的账户。其他社会工程学策略包括网络钓鱼和针对性网络钓鱼。

## 网络钓鱼（Phishing）

在网络钓鱼（发音类似 angling）中，社会工程师试图让目标人物泄露个人数据，如客户姓名、账号密码和密码。这通常通过使用来自合作伙伴、银行和客户服务人员的看似真实但虚假的信息来实现。不同类型的网络钓鱼试图让客户点击虚假链接，这将能够在其不知情的情况下在目标计算机上引入恶意代码。这种恶意软件将用于从计算机中提取信息或利用计算机攻击他人。网络钓鱼通常不针对特定客户，但可能是邮件列表上的任何人或具有特定电子邮件后缀的任何人，例如每个带有 "@foo.com”后缀的客户。

## 针对性网络钓鱼（Spear Phishing）

针对性网络钓鱼是一种钓鱼，其中目标客户被明确识别。例如，攻击者可能会发现组织首席执行官（CEO）或其他官员的电子邮件地址，并仅针对这些人进行钓鱼。

## 翻找垃圾桶（Dumpster Diving）

在翻找垃圾桶中，评估人员筛选框架客户丢弃的垃圾，寻找可以进一步了解目标的数据。这些数据可能是框架设置和配置、网络拓扑图、程序版本和设备部件，甚至是用户名和密码。该术语指的是进入巨大的垃圾容器，或者“潜入”小型办公室垃圾桶，因为那里也能产生有价值的信息。

## 现场光盘、现场磁盘或现场操作系统（Live CD, Live Disk, or LiveOS）

现场光盘或现场系统指的是一个包含整个工作系统的光学光盘。这些光盘对许多评估人员非常有帮助，并可以调整以包含特定的程序段、设置和工具。虽然现场系统通常出现在 Linux 发行版中，但微软也发布了一些 Windows 版本。根据框架的设置，现场光盘可能是评估人员或分析师应该带来的主要硬件，因为目标框架可以启动到现场系统。这把数据框架的一个资源转而对抗框架本身。

Kali Linux 是由 Offensive Security 发布的最新即时系统安全发行版。此版本包含了 300 多个安全和渗透测试工具，并根据渗透分析人员和其他数据框架评估人员经常使用的支持小组进行了分类。与 Offensive Security 发布的任何发行版本不同，Kali Linux 以 Debian 7.0 发行版的基础。Kali Linux 继承了其前身 Backtrack 的血统，并由类似的团队进行维护。正如 Offensive Security 所述，名称的更改代表了组织对 Backtrack 发行版的全面重构。相比于之前的 Backtrack 版本，巨大的改进使得更名变得合理，表明这不仅仅是 Backtrack 的另一个版本。Backtrack 本身是基于 White Hat 和 SLAX 这两个安全工具的改进版。在该系列中，Kali Linux 是安全检查和渗透工具的最新表现。

## 硬盘选择

不要使用这句话，但“大小确实会有影响”。一个通用原则是：硬盘越大越好。本书建议使用至少 120 GB 空间的硬盘。由于密码破解、取证或渗透测试任务需要大量的空间，这很快就会满。由于一般的业务和安全评估，操作系统会被清理、删除或完全移除以保持初始状态。这种培训通过安全网络广泛认可，因为需要正确处理用户分类信息并防止损害组织数据的泄露。

## 硬盘分区

分区是通过设置不同的大小和划分将硬盘划分为特定部分的演示。分区可以防止操作系统被假设控制框架的文件破坏，并在特定情况下提供更高的安全性。操作系统基本上被拆分为两个不同的部分。

主部分是交换区，用于内存分页和容量。另一个部分分配给其他所有内容，并使用文件系统设计，例如扩展文件系统 3 (`ext3`) 或扩展文件系统 4 (`ext4`)。在电脑上，特别是那些经常加载操作系统的设备上，进一步分区并不重要。对于具有更稳定操作系统的特殊设备，仍需要划分出临时（tmp）文件。

硬盘的强制分区以及本书范围之外的双启动电脑是不安全的。主要的例外是附录 A，其中提供了名为 Kali Chicken 的第三方应用程序重新发行。

## U 盘安装

USB 内存设备（通常称为 U 盘）是一种通过 USB 接口连接到 PC 的简单存储设备。本书建议使用具有至少 8GB 空间的 USB 设备，理想情况下更多。新 PC 可以从 USB 设备启动。如果选择此此选项，请确保所使用的 PC 支持从 USB 设备启动。

关于将 U 盘作为启动设备使用，有两个关键术语：持久性（persistence）和非持久性（non-persistence）。持久性是指您的设备在关关闭后保留任何已写入或修改记录的能力。非持久性是指设备在机器重启或关闭时丢失所有设置、自定义和记录。对于本书而言，从 Windows 阶段创建的 Kali Linux U 盘安装是非持久性的，而从 Linux 阶段创建的是持久性的。

### Windows（非持久性）

所需应用程序——`Win32 Disk Imager`: `http://sourceforge.net/ventures/win32diskimager/`

在下载 Kali Linux ISO 之前，将 U 盘插入 PC 并等待 Windows 识别它，观察分配的驱动器号。接下来打开 `Win32 Disk Imager`。点击信封图标浏览并选择 Kali ISO 文件，然后点击“alight”按钮。从设备下拉菜单中选择正确的驱动器号。最后点击“State”（状态）按钮。

## Linux（持久性）

在构建持久性 U 盘时，再次强调，大小确实很重要！U 盘容量越大越好。此外，取决于您构建此 USB 设备的 Linux 版本，请确保已引入 `GParted` 应用程序。如果您在引入 `GParted` 时遇到问题，请检查您的工作系统的文档。如果未引入 `GParted`，以下技术之一可能对您的 Linux 安装至关重要：

- `apt-get install gparted`
- `apt install gparted`
- `yum install gparted`

通过从文件菜单栏点击 Partition（分区）菜单后显示的菜单中选择 New（新建），向 USB 增加另一个分区。不同设备制造商的输出可能会略有差异。通常情况下，方法如下：

- 点击灰色的“unallocated”（未分配）空间。
- 从 Partition 下拉菜单中点击“New”（新建）。
- 使用滑块或物理确定驱动器大小。
- 将文件系统设置为 ext4。
- 点击 Add（添加）。
- 在主窗口中，从 Edit（编辑）下拉菜单选择 Apply All Operations（应用所有操作）。
- 在出现提示时点击 Okay（确定）。这可能需要一些时间。

要包含持久性功能，使用以下命令：`mkdir /mnt/usb` `mount /dev/sdb2 /mnt/usb` `echo "persistence" > /mnt/usb/persistence.conf` `umount /mnt/usb`

LiveUSB 的创建已完成。重启 PC 并从 U 盘启动。

# 第 3 章：合适的软件包处理工具

APT 软件包处理工具，被称为 "`apt-get`"，是一种用于引入和删除软件包的轻量级且极其强大的命令行设备。它构建在 Debian 包管理器 (`dpkg`) 之上。`apt get` 监控所有引入的内容以及所需的条件，即其他程序正常运行所需的额外软件包。例如，`Metasploit`（渗透测试者的亲伴）依赖于名为 Ruby 的特定编程语言。如果没有引入 Ruby，`Metasploit` 将无法运行；因此，Ruby 是 `Metasploit` 的依赖。

`apt get` 并不监控已引入程序的条件。当更新可用时，它将监控形成和封存条件。

损坏的 `apt-get` 将在下次刷新时提醒客户端，并提示移除旧的软件包。

`apt-get` 可以是一个极其基础的、也可以是一个异常复杂的工具。软件包的组织对于确保 Kali Linux 正常运行以及确保产品包处于最新状态至关重要。虽然 Kali Linux 普通用户不需要了解 `apt-get` 的内部操作，但每个用户都应该了解一些基础知识。

## 引入应用程序或软件包

引入额外的程序是操作系统最基本的能力，而且操作非常简单。下面的语法结构将提供 `introduce` 子命令的基本用法示例：

`apt-get introduce {package_name}`

尝试引入 "gimp;" 一个图像处理程序软件包：`apt-get introduce gimp`

## 更新

偶尔，应该检查源（或存储库）以获取在 Kali Linux 上引入的各种应用程序和软件包的更新。在引入任何新软件包之前应该检查更新，并且在对操作系统、程序应用程序或软件包进行升级之前也是需要这些。执行刷新的命令是：`apt-get update`

## 升级

没有任何操作系统是完美的。每个主要的操作系统都处于持续进展、改进和修复错误的状态，以提供新功能或修复 Bug。更新功能将下载并引入所有新引入的程序软件包的新版本。所有基于 Linux 的操作系统的伟大之处在于它们是开源的，这意味着地球上的任何人都可以向操作系统的发行者提交新代码，以帮助提高框架检测 Bug 或开发需求的实用性。这使得补丁可以比微软等公司更快地刷新。如前，在运行升级之前必须安装更新。使用以下命令更新：

`apt-get update`

## 发行版升级

应用程序更新的工作原理与升级工作类似。此功能同样搜索特殊软件包及其状态的热点，以及发行者分配的包含最新版本的各种软件包。例如，在执行发行版升级工作时，整个 Kali 将从版本 1.0 升级到版本 1n 或 2n 等。使用以下命令更新 Kali：`apt-get dist-upgrade`

## 移除

`apt-get` 可用于在移除特定程序时减少操作系统的印象。建议卸载所有未使用的、不满足需求或对你的操作系统冗余的软件包。例如，如果框架上不需要 Leafpad 应用程序，请将其移除。如果以后需要引入该应用程序，它通常是需要的，尽管忽略无用的东西是理想的。可以使用以下命令移除应用程序或软件包：`apt-get remove {package_name}`

尝试移除 "leafpad" 然后重新安装该应用程序：



`apt-get remove leafpad`

`apt-get introduce leafpad`

## 自动移除

一段时间后，操作系统的应用程序软件包会被更优的版本取代。自动移除不再需要的旧软件包，以实现框架的最佳效用。建议在升级或发行版升级之前执行自动移除工作。使用以下命令运行自动移除：

```
apt-get autoremove
```

## 清理

`remove`（移除）和 `cleanse`（清理）之间的区别是什么？`remove` 命令不会删除任何设计文件，如果以后需要这些文件，它们将保留在你的硬盘上。这对于应用程序特别有用，例如 MySQL、Samba Server 或 Apache。设置记录对于应用程序的操作性至关重要。有时，需要从系统中移除整个应用程序文件，甚至是该应用程序的设计记录，以便重新引入应用程序并从干净开始，或者清除所有潜在敏感数据的痕迹。从系统中清理应用程序将一次性彻底根除软件包及所有相关的配置文件。使用 `cleanse` 工作时不要太粗心；当不当或在不恰的应用程序上使用时它是危险的，因为所有相关记录将从系统中移除。可以使用以下语法清理：`apt-get purge {package_name}`

## 清洁

软件包从源下载到系统中，解包，然后引入。这些软件包将留在系统中，直到另有通知。

在应用程序建立之后，这些软件包不再是必要的。一段时间后，这些软件包会占用磁盘空间并应该被清理掉。可以使用以下语法启动完美功能：`apt-get clean`

## 自动清理

`autoclean` 同样以类似完美的功能清理系统。它应该用于系统的升级和交付更新，因为 `autoclean` 功能将移除被新版本取代的旧软件包。例如，假设应用程序 Y 版本 1 被引入系统，在系统升级后，应用程序 Y v1 被应用程序 Y v2 取代。`autoclean` 将仅清理版本 1，而 `clean` 功能将移除两个版本的软件包。以下语法将启动自动清理工作：`apt-get autoclean`

## 汇总一切

软件包的组织与更高效的工作密切相关。以下是用户可以使用的命令，以确保所有可能的修复、软件包和更新都是前瞻性的且准备就绪的：

- 1. `apt-get update && apt-get upgrade && apt-get dist-upgrade`
- 2. `apt-get autoremove && apt-get autoclean`

命令行行上的 `"&&"` 符号允许连续运行多个方向。

# 第 4 章：Tarballs

Tar 起始于早期的 Unix 框架，其命名是因为它的功能，最初用于将许多文档组合成磁带存档（Tape Archives, TAR）。

并不是所有人都需要将各种记录移动到磁带的能力。然而，他们可能需要 tar 应用的特性功能，即生成一个包含不同文档的容器文档。这使得文档的传输更加简单。此外，这些文档可以使用 `gunzip` (`gzip`) 进行压缩，以减小它们的总体尺寸。tarball 设计中有几种包，并通过 `.tar` 记录扩展名或用于压缩 tar 包的 `.tar.gz` 进行有效地区分。

在渗透测试期间，会产生大量的过滤存档、屏幕截取、审计和用户文档。使用 Tarball 框架考虑了更简单的分类、归档和支付。此外，非常建议将所有渗透测试记录保留在受保护区域内 5 年，或根据执行工作所在地法律时规定的日期。客户可能还有其他的维护需求，这些应在渗透测试的约定规则（ROE）中进行说明。ROE 将将在公告部分进行探讨。如果一个组织或承包商对渗透测试非常活跃，文档数量可能会迅速积累并很快失控。Tarball，特别是经过压缩的，提供了一种控制方案，可以保持记录分离，并考虑了更简单的强化和管理。

## 创建 Tarball

创建一个 tarball 记录可以是简单的也可以复杂的。请记住，`tar` 命令的首要功能旨在将记录发送到 TAR。tarball 框架的现代用法请参阅 tarball 的手册页（`man tar`）。对于本书，仅将包含 tarball 记录的基本格式；尽管如此，这些数据是有用的，并且可以适用于几乎任何基于 Linux 的平台。以下提供了用户可以遵循创建一个示例 tarball 所需的步骤概述。

1. 为你的文档创建一个索引。在这种情况下，使用 `mkdir` 命令创建 `tar-demo` 目录：`mkdir tar-demo`
2. 接下来在索引中创建各种可用于定义 tar 方向的记录。在这种情况下，将使用正确的星号（`.`）来创建一个内容为“Hi world.”的记录。该文件将被命名为 `record1`，可以通过修改这些记录以类似的方式创建许多记录，这将把你的文档移动到指定的注册表中，在此处为 `tar-demo`：`echo "Hi World" > tar-demo/file1`, `echo "Hi World" > tar-demo/record2`
3. 进入你想要放置 tarball 的目录，在此处为 `tar-demo`：`cd tar-demo`
4. 创建一个包含内部记录的 tarball。

这种情况下将使用星号（`*`）来控制，以保持文件分离创建新的 tarball：

```
tar -cf tarball.tar *
```

使用 `tar - tf` 命令将显示 tarball 的内容：
`tar -tf tarball.tar`

## 从 Tarball 提取文件

从 tarball 提取文件可以是简单的也可以复杂的。记住，从 tarball 提取记录的步骤是第一、第二、三；尽管如此，数据所在的注册表是关键。从 tarball 提取记录时，非常建议使用 `-C` 选项来指定记录要提取的目录。

1. 创建一个用于提取记录的索引。在这种情况下，创建的名为 `tar-demo2`：

```
mkdir tar-demo2
```
2. 将记录提取到该目录：
`tar xf tarball.tar -C tar-demo2`
3. 确保所有记录都已提取：
`ls -R tar-demo2`

## 打包 Tarball

Tarball 在创建时可以使用许多不同的算法进行打包。其中一种标准是 `gunzip`，也称为 `gzip`。这是通过随后的指令完成的。

1. 为你的文档创建一个索引。在这种情况下创建了 `tar-demo3`：
`mkdir tar-demo3`
2. 接下来将记录移动到索引中。如上所述，使用 `echo` 命令创建记录：`echo "Hi World" > tar-demo3/file1`
3. 进入你想要放置 tarball 的目录。再次，在此模型中为 `tar-demo3`：`cd tar-demo3`
4. 创建一个包含内部记录的 tarball。

这是使用 `-czf` 指令通过 `tar` 完成的。`tar` 命令的开关确保了 tarball 的正确创建。`c` 开关创建一个新的，`z` 开关确保记录被打包（或压缩），`f` 开关意味着跟随开关的名称（`tarball-demo.tar.gz`）将被用作新文件的名称：

```
tar -czf tarball-demo.tar.gz *
```



使用 `tar - tf` 指令显示 tarball 的内容：
`tar - tf tarball-demo.tar.gz`

## 网络基础

系统管理可以被认为是电脑之间电子街道序列。这些街道可以是物理的，最常见的是 5 类或 6 类铜缆（CAT 5 或 CAT 6）链路或光纤链路。远程系统管理利用独特的无线发射器和接收器来引导物理系统之间相同的底层任务。

无论介质如何，物理或远程系统管理都有相似的基础部分。首先，至少有两个设备将通信，例如，Adam 的电脑将与 Bill 的电脑通信。为了实现这一点，他们需要在正确的介质上使用正确的交换设备。在这个模型中，Adam 将与 Bill 连接的相同的物理 CAT5 系统接口。如果设置正确，只要双方的约定和设置正确，Bill 就可以使用远程网卡而 Adam 就可以使用有线网卡。为了让此正常工作，Adam 和 Bill 都应该通过类似远程交换机的设备接入相同的系统部分，将有线和远程不同的物理介质类型关联。

有许多部分构成了一个现代网络，而完全解释系统管理远超本书的范围。将介绍的小型系统部分足以描述如何配置网卡。这个小系统只是 Adam 和 Bill 使用的两台电脑、一个连接调制解调器的有线交换机以及连接一切的链路（本模型中全是 CAT5）。交换机的内部互联网协议 (IP) 地址为 192.168.1.1，这对于小型家庭办公室 (SOHO) 和家庭系统的默认设置非常常见。这个小交换机通过其外部连接接入互联网，使用互联网提供商分配的 IP 地址，这将使 Adam 和 Bill 在有效配置其网卡后能够上网。在这个模型中，交换机还提供了动态主机配置协议 (DHCP)、基本的防火墙功能和域名系统 (DNS)，这些每项都将在以后详细讨论。该系统如图 4.3 所示，并将作为后续章节使用的基础系统。

## 私有地址

交换机的内部接口（或网卡）的 IP 地址为 192.168.1.1；这就是所谓的私有位置，因为它不能在互联网上使用。内部系统接口与图中的黑盒的地址类似于 DHCP 分配的地址（分配给 Adam 和 Bill 电脑的 IP 地址）。一个表格记录了可以用于内部或私有系统的正常私有 IP，但无法在互联网上使用。

为了访问互联网，交换机执行一种称为网络地址转换 (NAT) 的魔法，它将 Adam 和 Bill 使用的 IP 转换为可以在互联网上使用的地址。这通常是数字互联网供应商提供给交换机的地址，并将分配到外部接口（另一个网卡）。如果客户端在互联网上使用这些地址而没有 NAT 交换机，通信将失败，因为互联网路由器和其他设备会拒绝这些私有 IP 地址。

## 默认网关

交换机的内部接口 IP 地址是退出 Adam 和 Bill 的系统。此位置被称为默认网关，稍后在为客户的两个 PC 设计系统网卡时将派用到。描述默认网关的一种形象方法是将其看作离开社区的唯一一条街道。任何需要离开城镇的人都需要知道这条街道在哪里。在系统 PC 上（通过系统网卡），PC 需要知道离开局域的出口在哪里；这就是默认入口。

## 域名服务器 (Name Server)

PC 之间通过数字进行对话，而个人之间在通过单词和表达进行交流方面则有了极大的提高。为了让通信能够有效进行，PC 定期使用域名服务器或区域域名管理（DNS）。本书将在稍后的部分以更详尽的细节介绍 DNS，因此本节仅将对 DNS 进行简单概述。从根本上说，域名服务器将人类可读的名称（如 www.synergy.com）解释为 IP 地址，PC 和具有名称管理分段的设备更擅长处理这种地址。DNS 与域名服务器同义，在人类友好的名称与 PC 良好的位置之间进行解释。例如，当一台 PC 需要与另一台 PC（例如一个 Web 服务器）通信时，它最初应该将易懂的位置解释为可以发送消息的 PC 邻居地址。个人将在其首选程序中输入 www.synergy.com，PC 将将此位置发送到 DNS 机器。DNS 将通过提供该网站页面的 IP 地址（163.172.x.x）进行回答。客户的 PC 然后将使用此 IP 地址与 Sygress Web 服务器通信，客户即可与 Syngress 网站进行协作。如果没有这种管理，人们将被记住每个网站的特殊 IP 地址。这意味着个人需要记住 69.163.177.2，而不是 syngress.com。手动设计系统网卡需要 DNS 或域名服务器的区分标识证明。

## DHCP

对于纯粹的系统魔法，没有什么能比得上 DHCP 了。对于一台设置了 DHCP 自动配置的 PC，客户端只需连接到正在运行的系统链接并开始工作即可。这是在 PC 启动并在系统中建立通信时，通过发送一个搜索 DHCP 服务器的通信请求来实现。服务器响应客户端并为所提到的 PC 分配组织配置。这包括 PC 的 IP 地址（仅限系统网卡，但在本解释中略显复杂）、默认网关、域名服务器——或域名服务器以及默认子网掩码。

通常，这是配置你系统网卡的极佳方法。如果你正在进行渗透测试，使用 DHCP 配置你的系统网卡会向所有人报告你正在进入系统，这通常不是值得感谢的。

## 基础子网划分 (Essential Subnetting)

子网划分是一个可能会困扰许多人的主题，因此在书中，子网划分被描述为以理想方式设计组织以节省 IP 地址的最佳方法。这是通过应用一个掩码来过滤 PC IP 地址的一部分，从而允许不同的系统被隔离。回到 Syngress 模型，IP 地址是 69.163.177.2，如果我们处于一个少于 255 个客户端的小型系统中，我们可以使用 C 类子网掩码 255.255.255.0。在应用掩码时，位置的部分被抵消，而其他部分保留，使得系统上的 PC 知道自己所在的哪个系统。再次，子网掩码的一个基本示例仅使用 255 和 0 这两个数字字节位；因此，为了区分系统，协调位置的任何部分都不会发生变化，所以 IP 地址的前三个字节（69, 163, 177）将与 255 协调，允许前面的数字通过。由于 0 被完全抵消，位置的最后一个字节（即 2）将被偏移，导致变为 0。因此，通过将子网掩码 255.255.255.0 应用于位置 69.163.177.2，我们发现系统地址是 69.163.177.0。在大多数小型系统中，255.255.255.0 的子网掩码将运行良好，而较大的系统将需要另一个不同的子网掩码，该掩码可能被确定为向特定数量的主机提供服务。

### 使用图形用户界面配置网络接口

了解如何从命令行配置或重新配置网络接口至关重要。这在不使用 Linux 图形界面或通过终端窗口远程连接到系统时非常有用。在渗透测试的许多情况下，命令行是更改设置的主要选择。

检查 PC 网卡的状态以及每个网卡的状态通过以下命令完成：

```

这将显示 PC 上所有系统网卡的当前布局。在图 4.7 中，显示了两个系统地址：`eth0`（主以太网卡）和 `lo`（回环接口或内部接口）。此连接器的设置是通过图形化界面设置的，而使用命令行更改这些设置非常基础。

#### 启动和停止接口

可以使用 `ifconfig` 命令的 `up` 选项启动接口，或使用 `down` 选项停止接口，同时需要指定要停止或启动的接口。随附的命令将停止主以太网连接器。

以下顺序将启动主以太网连接器：
```
ifconfig eth0 up
```

利用以下命令可以将此连接器的 IP 地址从其当前布局 192.168.1.66 更改为 192.168.1.22。
```
ifconfig eth0 192.168.1.22
```

也可以通过随附命令利用命令行更改系统配置。这将把 IP 地址设置为 192.168.1.22 并将子网掩码设置为 255.255.255.0。
```
ifconfig eth0 192.168.1.22 netmask 255.255.255.0
```

在命令行完整配置系统网卡比使用图形化 UI 需要更多工作，因为设置选项并没有全部存储在同一个区域。通过随附命令包含或更改默认网关，在此情况下设置为 192.168.1.2。
```
route add default 192.168.1.2
```

通过修改 `/etc/` 索引下的 `resolv.conf` 记录来更改名称服务器（或 DNS）设置。可以使用您喜好的文本编辑器修改该记录，或者基本上在命令行使用随附的命令。
```
nameserver 4.4.4.4 > /etc/resolv.conf
```

上述命令将清空当前的名称服务器并替换为 4.4.4.4。若要包含额外的名称服务器，随附命令会将新的名称服务器地址附加到 `resolv.conf` 中已记录的地址之后。

当 PC 执行名称查询时，它将按照记录的顺序检查前三个名称服务器。
```
nameserver 8.8.8.8 >> /etc/resolv.conf
```

## 密码和密钥

如果在掉落时选择了 WEP 或 WPA 个人模式作为安全技术，请在密文/密钥字段中输入安全密钥。勾选“显示密码/密钥”复选框以确认所使用的密钥已正确输入。在不需要显示密码的情况下，请保持未勾选复选框。某些框架使用密码或密钥转换策略。如果是，请通过选择正确的列表为每个列表输入密码或密钥，然后为该文件输入正确的密钥或安全密钥。

系统可能具有开放系统框架或共享密钥验证。在共享密钥验证中，路由器会向尝试连接的 PC 发送测试即时消息。连接的 PC 随后使用 WEP 密钥对内容进行加密，并将编码内容返回给路由器。

如果连接 PC 使用的加密密钥提供了正确的加密字符串，路由器随后将允许连接。开放框架验证同样允许 PC 在没有此测试和响应安排的情况下进行连接，这取决于 PC 使用了正确的 SSID。在这两种情况下，当使用 WEP 密钥验证通道时，通信通道即完成。虽然共享密钥验证看起来更安全，但实际上更不安全，因为测试消息和编码内容响应是以明文发送的，允许任何监控远程通道的人截获测试和响应。由于 WEP 密钥被用于加密测试，截获测试和响应可以导致 WEP 密钥被破解。

## 零成本构建实验室

在虚拟化时代之前，信息技术（IT）专家、安全专业人员和学生都拥有装满 PC 设备的车库、地下室和其他房间。有时，这些 PC 和系统管理硬件从地板堆到天花板，电费单高得惊人。拥有大量的设备是一种折磨；如果你需要搬家，想象一下带走它们有多难。感激现在不是这样了。

无论你的 PC 运行的是 Windows、Mac 还是 Linux 操作系统，处理家庭虚拟化都有两种基本方法。这两个项目都不需要费用，并且适用于大多数运行 32 位或 64 位架构的各种操作系统。

### VMWare Player

优点
- 虚拟机（VMs）创建在专用于 NAT 的虚拟交换机上。许多虚拟机将能够选项相互通信，并可能从主机进行访问。
- 自然引入了 DHCP，因此所有虚拟机都可以相应获取 IP 地址。
- 对 Xen、XenServer、vSphere 等其他主流虚拟机程序提供高级虚拟化支持。

缺点
- 不支持 Mac、Solaris 或 FreeBSD 操作系统。
- 不考虑现有虚拟机的快或克隆。
- 与某些 Wi-Fi 组织连接器存在困难。

### VirtualBox

优点
- 适用于 Windows、Linux、Mac、Solaris 和 FreeBSD。
- 具有克隆虚拟机的功能（节省时间）。
- 支持日益增多的虚拟硬盘记录类型。这在运行下载和预制的虚拟机时特别有帮助。

缺点
- 除非在主机上启用了端口转发，否则虚拟机之间是相互隔离的。
- 不支持 Xen、XenServer、vSphere 或其他类型虚拟机程序所需的硬件虚拟化。
- 如果虚拟机崩溃，整个虚拟机损坏的概率更高。

本指南专门针对在 Microsoft Windows 7 专业版上引入的 Oracle VirtualBox 版本 4.2.16。选择使用 VirtualBox 而不是 VMware Player 是因为互联网上有更多资源可以在出现问题时提供帮助；尽管它需要一些额外的配置。

请记住，在选择虚拟化框架时，最好的测试就是你的研究。关于哪种最好有很多讨论，最终选择一个虚拟化框架而不是另一个是个人喜好。同样，与防病毒软件不同，两者都可以引入以满足不同的需求，因此可以在同一台 PC 上安装 VirtualBox 和 VMware Player。本指南使用的所有链接和引用在编写时是有效的。请注意功能、下载区域和数据可能会随时更改。

## 扩展你的实验室

通过 Metasploitable2 项目，学习者不仅仅是获得了一台可以攻击的机器，而是获得了一个进入不同准备区域的门户。虚拟机本身通常对远程和本地攻击没有防御能力；随附的 Web 管理也随 Metasploitable 提供。

- 1. phpMyAdmin——通过 Web 界面管理 SQL 通常并不简单，但 phpMyAdmin 是用 PHP 编写的免费 Web 应用程序，改进了与 Web 服务器关联的 MySQL 数据库的管理。通过 phpMyAdmin 可以直接访问 MySQL 数据库，这是渗透测试人员和程序员极喜欢的目标。
更多信息：`http://www.phpmyadmin.net/`。

- 2. Mutillidae（名为 most-till-I-day）是 OWASP 的一个开源项目，致力于帮助安全专家和学生创建 Web 应用程序攻击技能。Mutillidae 是一个非常有用的准备工具，具有很高的网络支持并且不断更新。它包含在 Metasploitable2、SamuraiWTF 和 OWASP Broken Web Apps (BWA) 中。

Jeremy Drunin（在安全网络中称为 webpasswd）在 YouTube 上上传了许多关于 Mutillidae 的教程视频。随 Metasploitable 自然带的版本已经过时，且缺乏更现代的挑战。从 Sourceforge 项目页面下载最新版本的 Mutillidae 并将其传输到 Metasploitable2 的 `/var/www` 目录中以获取最新更新。
更多信息：
`http://sourceforge.net/projects/mutillidae/`
`http://www.youtube.com/client/webpwnized.`

- 3. WebDAV——网站管理员和经理可能需要更改网站内容。WebDAV 是 HTTP 协议的扩展，允许远程更改网站。WebDAV 使用用户名和密码组合来管理帐户访问。如果 WebDAV 设置未经过验证，攻击者可能会破坏网站、传输恶意文件并将 Web 服务器用于不同的邪恶目标。
更多信息：`http://www.webdav.org/`

- 4. DVWA——Damn Vulnerable Web App 是另一个供安全专家、教师、学生发现 Web 安全性的准备阶段，正如其名，它是没有防御的。
更多信息：`http://www.dvwa.co.uk`
`http://sourceforge.net/projects/dvwa/`

- 5. TWiki——一个强大的开源 Web 2.0 应用程序 wiki，已在 Metasploitable引入以测试 Web 2.0 应用程序。当前版本的 TWiki 已被企业巨头使用，例如 Yahoo!、Nokia 和 Disney。
更多信息：`http://twiki.org`。

上述所有应用程序都托管在 Apache Web 服务器上。任何放入 `/var/www` 的组织或站点都可以通过虚拟机上的 Web 界面访问。有许多像 Mutillidae 和 DVWA 这样的准备工具将帮助提高渗透测试的技能范围。

## 神奇的代码注入彩虹

Dan Crowley 是 Trustwave 的一名数据安全爱好者和自由科学家，他设计并生成了五个著名的准备套件。他最新的作品是将他的 Web 攻防工具结合成一个名为“神奇代码注入彩虹”（MCIR）的高级演练场。MCIR 包含以下模块：

- SQLol——一个 SQL 注入准备环境，它考虑了空白字符和序列的自定义，专注于基于测试的阶段，以准备测试和攻击 SQL 安全措施的关键技能。

- Shelol——一个用于命令注入的可配置框架 shell 准备环境。
- XSSmh——跨站脚本准备设备。
- CryptOMG——与 Andrew Jordan 合作，CryptOMG 是一个旨在利用加密基础漏洞的可配置横幅风格 Web。更多信息：`https://github.com/SpiderLabs/MCIR`。

## 生命周期序言

绝大多数人认为，渗透分析师（或程序员）需要做的只是坐在电脑前，开始编写一串黑色的代码，然后——哒哒！地球上的任何电脑都瞬间被攻破了。这种存在于好莱坞传说中的概括与现实相径远。该领域的专家在发现和利用计算机框架漏洞时，所使用的方法极其严谨。经过一段时间的开发，已经形成了一套被熟练的道德黑客使用的结构。该结构的四个阶段引导渗透分析师通过实验性滥用数据框架的过程，从而获得一份详尽的报告，在必要时可以使用其来重现测试任务的部分。这一程序为分析师提供了一个框架，同时也为渗透测试活动制定了高水平的设计。每个阶段都扩展了之前的进展，并为随后的进展提供了细节。虽然程序是连续的，但许多分析师会返回之前的阶段以解释发现并确认结果。

过程中的前四个阶段由 Patrick Engebretson 在其书籍《黑客与渗透测试基础》（The Basics of Hacking and Penetration Testing）中描述。这些阶段分别是：侦察、扫描、渗透和维持访问。

本书使用了这些阶段，并在 Patrick 的工作基础上增加了一个额外阶段：报告。此外，与 EC-Council 在其著名的认证道德黑客（CJEH）课程中描述的五阶段过程相比，许多人可能会发现该程序的最后一个阶段“隐藏踪迹”（Covering Tracks）缺失了。这是刻意为之，旨在关注之前的阶段并留出一个用于报告的部分，这是许多关于该主题的书籍所忽略的主题。

本书还通过消除生命周期的循环表示来区别于之前的书籍，取变为一种更直接的感知描述，这符合道德黑客在普通任务中通常的体验。这始于对目标数据框架的监控，结束于渗透分析师或测试小组长向数据框架管理员报告所发现的内容。

每个阶段的核心视角将在本部分介绍，并在专门针对每个阶段的章节中进行更广泛的描述。尽管如此，后续章节将介绍每个阶段常用的工具。

## 渗透测试生命周期

第 6 节：渗透测试生命周期简介展示了生命周期的各个阶段。此外，它还概述了安全领域的工程师们首选使用的工具。这些章节将不会详尽，但将开始揭示什么工具或策略可以帮助引导此类测试。大量的工具或系统都有专门的书籍——有时是多本书介绍它们的正确用法和应用。

## 第一阶段：侦察 (RECONNAISSANCE)

在一个灯光昏暗的小房间里，专家和官员正在检查和审查威胁区域的地图。房间里的其他人盯着显示全球地图的电视屏幕，疯狂地做着笔记。这个房间里的最后一次会议正在对被检查的目标的一切情况进行细致的评估。虽然这种情况展示了在对潜在目标进行军事观察时可能发生的情况，但这与渗透分析师在渗透生命周期侦察期间所做的事情相似。

这一阶段的核心在于掌握有关目标系统和关联的一切信息。这是通过浏览互联网和对目标进行潜在扫描完成的。在这个阶段，分析师尚未真正进入系统，而是识别并报告目标可能产生的任何会话数据。

## 第二阶段：扫描 (SCANNING)

在敌军后方，一名孤独士兵躲在灌木丛和树丛中。传回的报告告知其他人关于营地的区域以及每栋建筑正在进行的工作类型。报告还记录了穿过整个营地的路线以及可见的各种类型。

模型中的士兵通过侦察阶段的调查已经获得了一个战略目标。这适用于渗透测试生命周期的第二个阶段。分析师将利用第 1 阶段收集的数据来真正开始过滤目标系统和数据框架。

## 第三阶段：渗透 (EXPLOITATION)

四名军官穿过一片开阔的地野；月亮像一条弯月并被雾气遮挡，战士们在幽灵的光芒中看到一切。他们冲入建筑，溜过栅栏上的一个洞，然后通过一个开放的间接入口。在目标处只待了几分钟，他们就带着关于未来几个月部队部署和计划的基本数据撤离离开了。

同样，这符合道德黑客在渗透阶段将做的事情。该阶段的计划是进入目标框架并利用框架漏洞和已证明的系统秘密带走数据。

## 第四阶段：维持访问 (MAINTAINING ACCESS)

根据攻击小组提供的图纸，一群才华横溢的建筑师在某处发现了之前获取的关键数据的房间。这一阶段的目的是为对手利用提供易于访问的空间。对于分析师来说，这就是当框架被用于间接访问，且在框架上留了 rootkits 以允许日后访问的情况。

## 第 5 阶段：报告

打击小组负责人在指挥官和高级海军军官面前进行汇报，澄清攻击的细微之处。每一个进展都将以极其详尽的进行阐明，详细说明导致滥用发生的每一个细节。渗透分析师也应该创建详尽的报告，以澄清黑客攻击过程中的每个步骤、被滥用的漏洞以及真正被破坏的框架。此外，按照规定，可能需要小组中的某个人（有时是多个人）向目标数据框架的高级倡议人员和专业人员提供逐项准备说明。

## 演示

正如军事组织者在制定战斗方案之前会仔细分析可用数据一样，成功的渗透分析师也应该在引导有效的渗透测试之前，仔细分析可以获取的全部数据。通常，这些数据可以通过使用 Google 等其他工具浏览互联网来获取，包括那些专注于数据共享和在线生活的工具。数据也可以在互联网的名称服务器上找到，这些服务器为客户端程序提供引导。电子邮件可以通过关联进行跟踪，甚至回执邮件也能帮助渗透分析师。

创建并分析目标网站的离线副本可以提供大量的重要数据源，并在以后可用作社交工程任务的工具，前提是测试规则（ROE）允许。

此阶段始于测试小组对目标的进行最少思考。给予小组的详细程度可以从仅知道关联名称和可能的网站地址，到详细且明确的框架数据，包括在 ROE 中描述的用于限制或缩小测试范围的 IP 地址空间和创新技术。ROE 可能还会限制测试小组开展活动的能力，记住禁止进行社交工程和破坏性活动，例如拒绝服务（DoS）和分布式拒绝服务（DDoS）攻击。

目标是尽可能多地获取有关关联的数据。

关于该关联应当解决的几件事包括：

- 层级结构，包括逐项的高级、部门和小组授权大纲；
- 层级基础，包括 IP 空间和系统拓扑；
- 使用的进展，包括设备阶段和软件软件包；
- 代表性的电子邮件地址；
- 授权人员；
- 授权办公室的物理区域；
- 电话号码。

# 第 8 章：从目标自己的网站开始

目标的官方网站为构建攻入档案提供了海量数据。例如，许多地方乐意展示授权大纲和关键人物的简介。这些应该被作为建立目标档案和关联中关键人物数据的依据。它们可以用于通过网络化社交媒体场所进行进一步的数据获取，并用于社交工程，前提是所表 ROE 允许。

许多授权网站还包含招聘职位页面。这对于决定关联中使用的技术具有基础性。例如，招聘了解 Active Directory 和 Windows Server 2012 的框架负责人的公告将是一个强有力的指标，表明关联至少在使用 Windows Server 2012。类似的招聘熟悉 Windows Server 2003 或 2000 管理的负责人或大师的公告应该让任何渗透分析师警觉，因为这些阶段与更新的操作系统相比是无能的。

每个网页都应该检查是否有连接网络邮箱的链接，一旦发现就应该对其进行评估。如果点击链接显示 Outlook Web Access 页面，那么可以推断正在使用 Microsoft Exchange 服务器处理电子邮件。如果显示 Office 365 页面，这是一个良好的指示，表明电子邮件服务正在被重用，且邮件服务器可能过度依赖大多数 ROE。这对于 Google 网页邮箱也有效；无论如何，这应该在承诺开始前界定的限制范围内进行。如果存在关于跨越限制可行性的查询，应该使用被认为承诺的操作员来确定该查询。

## 网站镜像

有时，复制关联的整个网站以进行离线评估更有力。这可能是为了使用自动化工具扫描术语，或者仅仅是为了在对当前网站上的敏感数据进行更改时有一个副本。仅仅拥有网站的副本以进行离线监控也是有价值的。像 `wget` 命令行这样的工具可以复制网站的所有 html 文档并将其存储在本地硬盘上。`wget` 工具包含在 Kali Linux 中，是一个简单易用的工具。通过在终端窗口运行以下命令将下载整个网站的 html 文档。必须注意的是，wget 不会复制页面的服务器端程序，例如那些使用 PHP 内容制作的页面。

`wget -m -E -v http://foo.com`

在这个模型中，`wget` 命令后跟着各种开关或选项。与 Kali Linux 上的设备一样，可以参考用户手册来决定工具对承诺任务的使用。要查看 `wget` 手页，请使用相应命令。`man wget`

进入手册页后，使用上下方向键进行翻阅内容。按 h 键获取帮助，按 q 键退出手册页。对 `wget` 手页中此设置的审核显示了以下：

- -m reflect，开启适用于镜像的选项；
- -p page or essentials，此选项确保下载所需的文档，包括图片和 css 记录；
- -E alter extension，这将使所有页面在本地保存为 html 文档；
- -k convert interfaces，这允许文档转换为本地查看；
- -K keep original files，将原始文件以 .orig 后缀备份。

从关联的 Web 服务器移动的文档将存放在以被复制网站命名的封包中。在复制网站时，下载制作或包含 PHP 的页面可能会出现错误。这是因为制作页面的许多代码是由网站页面背后的服务器内容生成的，这是一个大多数克隆应用程序无法访问的区域。

## 包含所有这些词

此字段用于发现包含交换框中输入词汇的页面，而不忽略这些词汇在网页上的具体位置。这些词汇不需要在请求中组合或相邻，只需出现在页面的某个地方即可。要进行此查询，在对话框中输入各种术语并点击“高级搜索”按钮。通过这样做，在开发搜索页面中输入的词汇将转换为查询字符串，然后发送到 Google，就像直接在 Google 主页搜索框中输入它们的一样。

## 确切的词或短语

在此选项左侧的字段中输入查询术语，将使 Google 网页搜索工具发现精确请求中组合的词汇或表达式。与“包含所有这些词”搜索不同，只有在准确请求中包含且相邻出现该表达式或词汇的网页才会被包含在结果集中。此查询通过在语句内部设置搜索术语来工作。

## 包含这些词中的任意一个

使用此字段时，Google 搜索将发现包含其中任何一个词的页面。与“包含所有这些词”字段完全不同，返回的页面并不包含所输入的全部词汇。这种搜索通过在查询框中的术语之间放置 OR 连接符来工作。

## 不包含这些词

在此内容框中输入的词汇将用于排除随后的 Google 搜索中的页面。任何包含输入词汇的页面都将从结果集中删除。此搜索通过在结果集中你不需要的词汇或术语前加上一个短横号来工作。

## 数字范围

通过利用此处的两个内容字段，搜索将发现具有输入范围范围内数字的页面。这种搜索可以通过包含计量单位进行分类，例如，磅 (lb)、英里或毫米 (mm) 或像 $ 这样的货币。通过在数字之间设置两个句点，可以在主搜索框中直接进行此查询。

## 语言

通过下拉选择器选择语言，后续页面大部分将使用所选语言。此查询限制器可以用于将结果限制在以目标所在地通用语言编写的页面上。例如，通过关注德国网站，一个对德国公司进行渗透测试的小组可以更有可能寻找与该特定任务相关的数据。

## 地位置/地区

通过下拉选择器选择位置，后续页面将来自位于所选区域的站点页面。如果使用方言下拉菜单没有产生选择，则选择区域后的搜索结果将包含分布在该位置的页面，而不考虑所使用的基本语言。通过同时选择语言和地区，可以引导更深层次的搜索。

## 最后更新时间

通过在下拉菜单中选择时间限制，只有在所选时间范围内更新的页面才会被记录。这将确保较旧的页面被排除在结果之外，并可用于确保后续页面是在关键事件之后。例如，作为渗透测试重点的协会最近与另一家公司完成了合并或收到了另一项创新，搜索可以限制在自事件发生以来的时间，以确保查询结果具有更高的相关性。

## 站点或域名

在缩小目标项目列表时，此内容框可能是最有帮助的工具之一。例如，寻找管理机构可能通过将结果限制在 .gov 空间内而获益，而寻找 Foo 公司则可能通过将结果限制在 foo.com 区域而获益。这种限制也可以通过在基础 Google 搜索内容框中使用 site 搜索限制器来引导，后跟应应在结果集中返回的区域或空间。例如，使用 site: foo.com 将结果限制为仅来自 foo.com 区域的页面。

## 制造分身 (Make a Doppelganger)

故事中的分身是人的复制品。在开始网络生活之前，建立一个人格（persona）是通常的做法。使用安全专家或准入分析师的简介对目标进行直接研究通常不是一个好主意。更好的主意是分析师可以通过社交网络与该协会的人建立社交联系。如果分析师拥有一个声称曾在目标协会工作过或与分析师试图接触的机构上过相似学校的人格，将更具吸引力。显然，分析师必须小心不要完全接管真实个人的身份，这种行为可能会导致某些人认为发生了欺诈。个人可能拥有相似的名字。例如，建立一个名为 John Smith、就读于威斯康星大学的完全虚构的人格并不等同于获取就读于那里的真实 John Smith 的身份。无论如何，确保你的人格不会渗透到欺诈或虚假中。这意味着除了其他事情外，不要填写有你身份名称的申请表，或使用该身份参加合法活动。使用分身的界限应该从承诺开始就标明，如果允许社交工程，则应该建立一个当社交构建成为重要因素时可行的分身。在填写网络生活注册表时，分析师应关注使用方法，以确保使用分身时没有违反策略、规则或法律。

## 理解网络流量

系统流量对某些人来说可能是困惑的；然而，需要对此主题有基本的理解才能从检查阶段获得最大的收益。系统流量是发生在关联各种策略 PC 框架之间的电子通信。今天最广泛认可的系统管理策略是有线和无线以太网。理解以太网通信的关键标准至关重要。本节将探索端口和防火墙、IP 协议，包括传输控制协议 `TCP`、用户数据报协议 `UDP` 和互联网控制消息协议 `ICMP`。

### 获取 获取端口和防火墙

保护系统最核心的策略之一是在内部（通常是公司网络）与世界其他部分（如互联网）之间实现防火墙。防火墙只是一个带有至少两个网卡的充当系统守护者的注册设备。访问控制记录仔细监控出站流量（离开）和入站流量（进入）。只有符合入站控制标准的流量才允许通过，而其余的防火墙丢弃。它通过打开或关闭端口来允许或拒绝流量来实现。

端口用于 PC 到 PC 通信的独特通信通道。有 `65,535` 个 `TCP` 端口和其他 `65,535` 个 `UDP` 端口可用于通信。这些端口中的少数分配给了特定用途，但不限于此用途。例如，`TCP` 端口 `80` 通常用于使用超文本传输协议 `HTTP` 的典型互联网流量，但其他流量也可以通过端口 `80`，互联网流量也可以通过不同的端口。

### 理解 IP 协议

协议是规则，即使在 PC 系统上也是如此。立法者和高级权威经常有处理协议问题的人员。协议场所的人员确保每个客人或权威消息以指示的方式执行，确保消息或客人被正确获取并带有正确的标题和尊重。

在 PC 世界中，这些协议按照预定义的规则确保框架之间的通信发生。虽然对于所有 PC 框架可用的协议数量惊人，本节将介绍 Kali Linux 上主流过滤应用程序中最常使用的三种协议，它们分别用于检测、无防御扫描和入口测试：`TCP`、`UDP` 和 `ICMP`。

## TCP

`TCP` 是用于组织数据交换的主要协议之一。

`TCP` 是一种基于关联的通信传输协议，这意味着交换通道两端的计算机都识别到会话已建立，并且双方都在接收该关联中的消息。此前，许多人将其类比为电话通话。
