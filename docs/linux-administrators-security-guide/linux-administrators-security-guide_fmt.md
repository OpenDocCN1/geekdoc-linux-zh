## 本指南是什么，以及它不是什么

本指南并不是一份通用的安全文档。本指南专门关于如何保护 Linux 操作系统免受通用和特定威胁的攻击。如果你需要对安全的概概述，请去 www.ora.com 购买《Practical Unix and Internet Security》（《实用 Unix 与网络安全》）。

O'Reilly 及其关联公司是我最喜欢的计算机书籍出版社之一（他们还制作很漂亮的 T 恤），附录列出了我推荐的其他各种计算机书籍。

## 如何确定需要保护的内容以及如何保护

你是否正在保护数据（专有的、机密的或其他）？你是否正尝试保持某些服务（你的邮件服务器、Web 服务器等）？你是否只想保护物理硬件免受损坏？你正在防止什么？恶意破坏（如 8 Sun Enterprise 10000 的损坏）、删除（调查数据、你妈的食谱集）、篡改（带有医疗记录的物理介质、银行）、泄露（涉及诉讼的机密内部通信、应对未婚母亲的计划）。“坏”事件发生的概率有多大？网络探测（我每天都会遇到）、物理入侵（尚未发生在我身上）、社会工程学（“你好，我是 IT 部门的 Bob，我需要你的密码以便我们重置……”）。

你需要列出所有包含数据、提供服务、构成你公司基础设施等的资源（服务器、数据和其他组件）。以下是一个简短列表：

- 物理服务器设备
- 邮件服务器及服务
- DNS 服务器及服务
- WWW 服务器及服务
- 文件服务器及服务
- 公司内部数据，如会计记录和人力资源数据
- 你的网络基础设施（线缆、集线器、交换机、路由器等）
- 你的电话系统（PBX、语音信箱等）

你需要确定你想要防止什么情况的发生：

- 物理损坏（烟雾、水、食物等）
- 数据的删除/修改（会计记录、你 WWW 网站的篡改等）
- 数据泄露（会计数据等）
- 服务连续性（保持邮件/网页/文件服务器正常运行）
- 防止他人非法/不当使用你的服务（邮件垃圾邮件等）

最后，事件发生的概率有多大？

- 网络扫描——每天一次是稳妥的预期
- 社会工程学——各异，通常最脆弱的人往往是目标人物
- 物理入侵——视情况而定，通常罕见，但一个拿着电线钳的敌对员工在电信机房可以造成巨大破坏
- 员工将你的数据卖给竞争对手——这种情况会发生
- 竞争对手雇佣技术人员渗透你的网络——如果这种情况发生，没人会谈论它

一旦你明确了内容，就可以采取相应的保护措施。

心情不好时电话响起来让人心烦。除非有强迫需求，否则请将使用交互式 shell（`bash`, `pine`, `lynx` 等）的用户数量保持在极少数。将服务进行分段（设置邮件服务器、Web 服务器等），以最大限度地减少单点故障。通常情况下，一个配置得当的服务器会运行而不需要维护（我在客户那里有一台邮件服务器已经运行了 2 年，总共维护时间仅约 10 小时）。任何升级都应该经过仔细计划并在测试环境中执行。关于服务器需要记住的几个点点：

- 1. 限制对服务器的物理访问。
- 2. 遵循最小权限原则，他们破坏的范围会更小。
- 3. **务必备份！**
- 4. 定期检查服务器的更改（端口、软件等），自动化工具对此非常有帮助。
- 5. 软件更改应该经过仔细计划/测试，因为它们可能会产生不利影响（例如内核 2.2.x 不再使用 `ipfwadm`，如果你忘记安装 `ipchains`，那将不是很尴尬吗）。

权限最小化意味着赋予用户（以及管理员）完成工作所需的最少访问权限。赋予用户工作站“root”权限，如果所有用户都精通 Linux 且值得信赖，这样做是合理的，但他们通常并非如此（在这方面都不如此）。即使他们确实如此，这也是个坏主意，因为他们很可能会安装某些损坏/不安全的软件等。如果用户访问的需求仅是关闭/重启工作站，那么这就是他们应该被授予的访问权限量。你绝不会将财务文件留在具有“世界可读”权限的服务器上供会计人员查看，这一概念一直延伸到整个网络。限制访问还可能在账户被渗透时限制损害（你读过人们贴在显示器上的贴签上写的内容吗？）。

### 物理启动安全

#### 物理访问

这部分在《实战 Unix 与 网络安全》一书中有深入介绍，但我将简要概述一下基础知识。关闭你的主会计服务器，重新开启，从特制的软盘启动，并将 `payroll.db` 传输到异地的 `ftp` 站点。除非你的会计服务器被锁定，以防止恶意用户（或大楼保洁人员、快递员等）这样做！我听听过保洁人员为了插上清洁设备而拔掉服务器插头的恐怖故事。我曾见过有人点击电源插线的小开关并重启他们的服务器（尽管我从未这样做过）。将你的服务器锁在安全房间内（甚至是封闭的柜子内）是有意义的。将服务器放在架高的表面上也是一个非常好的主意，以防止洪水导致的损坏（无论是屋顶漏水还是洒了一桶冰沙）。

### 计算机 BIOS

#### LILO

```
delay=x
控制 LILO 在启动到默认选择之前等待用户输入的时间（以 1/10 秒为单位）。C2 安全要求之一是将此间隔时间设置为 0（显然，双系统启动意味着大部分出了问题）。除非系统要双启动其他内容，否则将其设置为 0 是个好主意。
```

强制用户输入内容。`LILO` 不会自动启动系统。这在服务器上可能有用，可以作为一种在没有人工值守的情况下禁用重启的方法，但通常如果黑客有重启系统的能力，他们可以使用新的启动选项重写 MBR。如果你添加了超时选项，系统将在超时后继续启动。

`restricted` 意味着如果向引导程序传递了启动选项（如 "`linux single`"），则需要使用密码。确保在每个镜像上都使用这一个（否则服务器启动时需要密码，如果你从未计划重启它，这没问题）。

`password=XXXXX` 需要输入密码，与 `restricted` 配合使用，同时确保 `lilo.conf` 不再可读，否则任何用户都能读取密码。

这里是我其中一台服务器的 `lilo-conf` 示例（密码当然已经更改）。

```
boot=/dev/hda
map=/boot/map
install=/boot/boot.b
prompt
timeout=100
default=linux
image=/boot/vmlinuz-2.2.5
label=linux
root=/dev/hda1
read-only
restricted
password=some_password
```

这使用 `/boot/vmlinuz-2.2.5` 内核启动系统，该内核存储在系统第一个 IDE 硬盘的 MBR 上。`prompt` 关键字通常会停止重启，但由于在系统中已设置，它可以无问题地启动 "`linux`" ，但如果你想进入 "`linux single`" ，你有 10 秒时间输入它，此时系统会提示你输入密码（"`some_password`"）。结合 BIOS 设置为仅启动保护模式，你就有了一个相当安全的系统。

## 访问

### Telnet

`Telnet` 是目前最古老且广为人知的远程访问工具，几乎每个 Unix 系统都带有它，甚至连 NT 系统也支持它。只有当你能从命令提示符管理系统时（NT 系统并不擅长），`Telnet` 才会真正有用，这使其非常适用于 Unix。`Telnet` 极不安全，密码、用户名以及会话数据均以明文形式传输，是嗅探器的首选目标。所有 Linux 发行版都带有 `Telnet`。你永远不应该使用 `telnet` 来远程管理系统。

### SSL Telnet

`SSL Telnet` 在 `Telnet` 的基础上增加了 `SSL` 加密，这使其变得更加安全、更可靠。通过使用 `X.509` 证书（也称为个人证书），你可以轻松地管理远程系统。与 `SSH` 系统不同，`SSL Telnet` 是完全的 GNU 程序且供所有人免费使用。你可以从这里获取 `SSLnet` 服务器和客户端：`http://ftp.replay.com/`

## SSH

`SSH` 最初是免费的，但现在采用了商业许可，不过它具有许多功能，使其值得使用。它支持多种形式的身份验证（密码、rho、RSA 密钥），允许你重定向端口，并轻松配置允许登录哪些用户。`SSH` 可从这里获取：`http://ftp.replay.com/`。如果你打算将其用于商业，或者想获得最新版本，应该前往：`http://www.ssh.fi/`

### LSH

`LSH` 是 `SSH` 协议的免费实现，`LSH` 采用 GNU 许可，并且开始看起来 `SSH`（从商业角度来看，`SSH` 已不再如此）的替代品。你可以从这里下载：`http://www.net.lu.ac.uk/psst/`，请注意它仍在开发中。

### REXEC

`REXEC` 是较老的远程 Unix 工具之一，它允许你在远程系统上执行命令，它有一个严重的缺陷，即没有真正的安全模型。安全性是通过使用“`hosts`”文件来实现的，该文件指定了哪些主机/等可以运行命令，但这容易受到伪欺骗和其他形式的攻击。你永远不应该使用 `REXEC` 来远程管理系统。

### Slush

`Slush` 基于 `OpenSSL`，目前支持 `X.509` 证书，这对于大型组织来说，这比在各种服务器上记住几十个密码要好得多（也更明智）。`Slush` 是 GPL 协议的，但尚未完成（它实现了大部分实用功能，但有局限性）。另一个完全基于开源软件，使得后门/等远程访问成为可能。最终，它可以使用更优的工具替代 `SSH`。你可以从这里获取：`http://violet.ibs.com.au/slush/`

### NSH

`NSH` 是一款功能完备的商业产品（我的意思是全全）。它在构建时就支持加密，因此使用起来相对安全（我无法真正验证这一点，因为它不是开源）。易用性很高，你只需 `cd //computername` 就能登录计算机，然后你可以轻松地复制/修改/等文件，运行程序并获取进程列表进行命令操作等。`NSH` 还有一个可用的 Perl 模块，使得命令脚本编写变得简单，非常适合管理许多系统（如工作站）。此外，`NSH` 可用于多个平台（Linux、BSD、Irix 等）。`NSH` 可从这里获取：`http://www.networkshell.com/`，并可以轻松下载 30 天的试用版。

### Fsh

`Fsh` 代表“远程命令执行”，概念上与 `rsh/rep` 类似。它通过使用 `ssh` 建立加密隧道或在隧道上运行所有命令，避免了不断创建加密会话的消耗。你可以从这里获取：`http://www.lysator.liu.se/fsh/`

### secsh

`secsh`（Secure Shell）提供了另一层登录安全，当你通过 `ssh` 或 `SSL telnet` 登录后，系统会提示另一个密码，如果你获取了 `secsh`，它会终止登录尝试。你可以在这里获取 `secsh`：`http://www.leenux.com/`

## 本地

### YaST



YaST（另一个设置工具）是一个功能完备的商业产品。它在构建时支持加密，因此使用起来相对安全（我无法真正验证这一点，因为它不是开源）。易用性很高，你只需 `cd //computername` 就能登录计算机，然后你可以轻松地复制/修改/等文件，运行程序并获取进程列表进行命令操作等。NSH 还有一个可用的 Perl 模块，使得命令脚本编写变得简单，非常适合管理许多系统（如工作站）。此外，NSH 可用于多个平台（Linux、BSD、Irix 等）。NSH 可从这里获取：http://www.networkshell.com/，并可以轻松下载 30 天的试用版。

## 访问

### Telnet

Telnet 是目前最古老且广为人知的远程访问工具，几乎每个 Unix 系统都带有它，甚至连 NT 系统也支持它。只有当你能从命令提示符管理系统时（NT 系统并不擅长这一点），Telnet 才会真正有用，这使其非常适用于 Unix。Telnet 极不安全，密码、用户名以及会话数据均以明文形式传输，是嗅探器的首选目标。所有 Linux 发行版都带有 Telnet。你永远不应该使用 telnet 来远程管理系统。

### SSL Telnet

SSL Telnet 在 Telnet 的基础上增加了 SSL 加密，这使其变得更加安全、更可靠。通过使用 X.509 证书（也称为个人证书），你可以轻松地管理远程系统。与 SSH 系统不同，SSL Telnet 是完全的 GNU 程序且供所有人免费使用。你可以从这里获取 SSLnet 服务器和客户端：http://ftp.replay.com/

## SSH

SSH 最初是免费的，但现在采用了商业许可，不过它具有许多功能，使其值得使用。它支持多种形式的身份验证（密码、rho、RSA 密钥），允许你重定向端口，并轻松配置允许登录哪些用户。SSH 可从这里获取：http://ftp.replay.com/。如果你打算将其用于商业，或者想获得最新版本，应该前往：http://www.ssh.fi/

### LSH

LSH 是 SSH 协议的免费实现，LSH 采用 GNU 许可，并且开始看起来是 SSH（从商业角度来看，SSH 已不再如此）的替代品。你可以从这里下载：http://www.net.lu.ac.uk/psst/，请注意它仍在开发中。

### REXEC

REXEC 是较老的远程 Unix 工具之一，它允许你在远程系统上执行命令，它有一个严重的缺陷，即没有真正的安全模型。安全性是通过使用 `hosts` 文件来实现的，该文件指定了哪些主机/等可以运行命令，但这容易受到欺骗和其他形式的攻击。你永远不应该使用 REXEC 来远程管理系统。

### Slush

Slush 基于 OpenSSL，目前支持 X.509 证书，这对于大型组织来说，这比在各种服务器上记住几十个密码要好得多（也更明智）。Slush 是 GPL 协议的，但尚未完成（它实现了大部分实用功能，但有局限性）。另一个是完全基于开源软件，使得后门/等远程访问成为可能。最终，它可以使用更优的工具替代 SSH。你可以从这里获取：http://violet.ibs.com.au/slush/

NSH 是一款功能完备的商业产品（我的意思是全全）。它在构建时就支持加密，因此使用起来相对安全（我无法真正验证这一点，因为它不是开源）。易用性很高，你只需 `cd //computername` 就能登录计算机，然后你可以轻松地复制/修改/等文件，运行程序并获取进程列表进行命令操作等。NSH 还有一个可用的 Perl 模块，使得命令脚本编写变得简单，非常适合管理许多系统（如工作站）。此外，NSH 可用于多个平台（Linux、BSD、Irix 等）。NSH 可从这里获取：http://www.networkshell.com/，并可以轻松下载 30 天的试用版。

COAS 项目（Caldera Open Administration System）是一个非常有野心的项目，旨在为系统管理提供一个开放框架，范围涵盖了从命令行（带有半图形化界面）、X 环境内（使用 qt 组件集）到 Web 端。它通过提供一个中间层来抽象实际的配置数据，使其适用于不同的 Linux 平台。版本 1.0 刚刚发布，看起来 Caldera 终于在推进该项目。COAS 网站地址为：http://www.coas.org/。

### /etc/passwd

密码文件无疑是 Linux（以及大多数 Unix 系统）中最关键的系统文件。它包含了用户名、用户 ID（UID）以及用户所属的主组 ID（GID）的映射。它可能包含实际密码，但更可能（也安全得多）是使用影子密码将密码存储在 `/etc/shadow` 中。该文件`必须`对世界可读，否则即使是像 `edit` 简单的命令也无法正常工作。GECOS 字段可以包含真实姓名、电话号码等数据；家目录是用户交互式登录时放置的默认目录；登录 shell（login shell）必须是一个交互式 shell（如 bash 或菜单程序），并列在 `/etc/shells` 中，用户才能登录。其格式为：

```
username:password:UID:GECOS_field:home_directory:login_shell
```

### /etc/shadow

影子文件存储用户名和密码对，以及过期日期等账户信息和其他任何特殊字段。此文件必须不惜一切受到保护。

### /etc/groups

组文件包含所有的组成员信息，以及可选项目如组密码（在当前系统中通常存储在 `gshadow` 中），此文件必须对世界可读，系统才能正常运行。其格式为：

```
groupname:password:GID:member,member,member
```

一个组可以不包含成员（即未未使用）、单个成员或多个成员，密码是可选的。

### /etc/gshadow

与密码影子文件类似，此文件包含组、密码和成员。

### /etc/logins.def

该文件（`/etc/logins.def`）允许你为各种程序（如 `usadd` 和密码过期）定义一些有默认值。它在不同的发行版甚至版本之间略有不同，但通常有良好的注释并倾向于包含合理的默认值。

### /etc/shells

shells 文件包含有效 shell 列表，如果用户的默认 shell 未列在此处，他们可能无法进行交互式登录。更多信息请参见 Telnet 章节。

```
/etc/securetty
```

此文件包含 root 用户可以登录的 tty 列表。控制台 tty 通常是 `/dev/tty1` 到 `/dev/tty6`。串口（如果你想通过调制解调器以 root 登录）通常是 `/dev/tty0` 及以上。如果你允许 root 通过网络登录（这是一个非常糟糕的主意，请使用 `sudo`），则添加 `/dev/ttyp1` 及以上（如果有 30 个用户登录且 root 尝试登录，root 将来自 `/dev/ttyp31`）。通常你只应该允许 root 从 `/dev/tty1` 登录，并且建议完全禁用 root 账户。



任何 UNIX 系统的不可或缺的一部分是 Linux 中大部分日志由两个主要程序提供的：`syslog` 和 `klogd`。前者为程序和应用程序提供日志服务，后者为 Linux 内核提供日志能力。内核实际上会将消息发送到 `syslog` 设施，但偶尔会在控制台上弹出消息（例如内核恐慌 `kernel panic`）。`syslog` 负责处理消息并将其发送到适当的文件或设备，这在 `/etc/syslog.conf` 中配置。默认情况下，记录到文件的位于 `/var/log/`，通常处理自己日志的程序（如 `apache`）会将日志记录到 `/var/log/proname/`；这使得日志集中化，并更容易将它们放置在单独的分区上（某些攻击可以很快填满你的日志，而分区分满可没意思了）。此外，有些程序有自己的内部日志，其中最有趣的是之一 `bash` 命令行 `shell`。默认情况下，`bash` 在 `~username/.bash_history` 中保留执行过的命令历史，这个文件可能非常有阅读价值，因为很多管理员会无意中在命令行输入密码。

### 密码文件与影子密码

在 UNIX 类操作系统中有有几个常量，其中之一就是 `/etc/passwd` 文件及其工作原理。为了让用户验证正常工作，你需要（至少）某种（文件）用于用户名映射、GID 到组名的映射、用户密码以及其他杂项信息。这样做的问题在于，每个人都需要访问密码文件，每当你访问它时，你如何安全地存储所有密码并保持它们可读？多年来，解决方案一直简单且有效：对密码进行哈希并存储哈希值，当用户需要验证密码时，他们输入密码，进行哈希，如果匹配则说明密码相同。这个问题的麻烦在于计算能力已经巨大增长，我可以获取你的密码文件的副本并在合理的时间内对其暴力破解。解决这个问题有几种方案：

- 使用“更好”的哈希算法 `MD5`。问题：如果其他其他内容，可能会破坏很多东西。
- 将密码存储在其他地方。问题：系统/用户仍然需要访问它们，如果没有做好准备可能会导致某些程序失败。

许多操作系统采用第一种方案，Linux 已经实现了第二种方案，被称为影子密码。在密码文件中，你的密码被替换为 `'x'`，告诉系统根据影子文件检查你的密码。任何人仍然可以读取密码文件，但只有 `root` 有访问影子文件的权限（组文件也是如此）。这似乎足够了，直到最近实现影子密码一直是一件麻烦事。你必须重新编译所有检查密码的程序（`login`、`ftpd` 等），这只需要花费一点精力。这就是为什么 `RedHat` 在依赖 `PAM` 方面表现出色。要实现影子密码，你必须做两件事。第一件相对简单，更改密码文件，但第二件可能很麻烦。你必须确保你的程序支持密码，这在某些情况下非常痛苦（这是发行版应该带 `PAM` 的 的有力理由）。由于 `RedHat` 依赖 `PAM` 进行认证，一个新的认证方案只需要添加一个 `PAM` 模块来理解它，并编辑相应程序的配置文件（例如 `login`），允许它使用该模块进行认证。不需要重新编译，不需要很多麻烦，对吧？在 `RedHat 6.0` 中，你在安装期间会被提供选择影子密码的。

### 软件管理

`RPM` 是最初由 `RedHat` 创建的软件管理工具，后来经过 GNU 化并向公众发布（http://www.rpm.org/）。它是系统管理的核心，任何管理员的首要任务之一就是安装并保持软件更新。据各种估计，大多数安全侵入事件都应归咎于弱密码和带有漏洞的旧版软件。这并不完全令人意外，但考虑到一台平均服务器恰好包含 200-400 个软件包，人们就会开始理解为什么保持软件更新是一项重大任务了。

## 现代 Linux 发行版与源码安装

现代 Linux 发行版使用包管理系统来安装、跟踪和删除软件。有很多例外，Slack 并没有使用真正的包管理系统，而是使用预编译的 tarballs（包含文件的压缩 tar 包），你只需将其从根目录解压即可安装，这些软件包也可以移除，具有查询、安装文件（尝试篡改等）等功能。或者你想获取 X 的最新版本，但还没有人制作出良好的 `.rpm` 或 `.deb` 文件，所以你获取源码。

我将单独讨论这一部分，即检查从远程站点获取的软件的完整性。通常人们并不担心，但最近 `ftp.win.nl` 被攻破了，`tcp_wrappers` 软件包（以及其他包）是木马。在发生 59 次下载后，该站点删除了这些软件包并启动了修复程序。你应该始终检查从远程站点下载的文件的完整性，总有一天某个大型站点会出问题，许多人将面临痛苦。

RPM 软件包可以（且通常）由作者进行 PGP 签名。可以检查此签名以确保软件包未被篡改或不是木马。这在《Maximum RPM》第 7 章（可在 `http://www.rpm.org/` 在线查看）中有详细描述，包括将开发者密钥添加到你的 PGP 密钥环中，然后使用 `-K` 选项，它将从密钥环获取相应的密钥并验证签名。要这样伪造软件包需要窃取开发者的私钥 PGP 密钥以及解锁它的密码，这几乎是不可能的。

TCP-IP 创建于一个安全并不是被非常关注的时代和背景。最初，“互联网”（当时被称为 Arpanet）仅由极少数主机组成，全都是学术机构、公司或政府性质。每个人彼此认识，接入互联网是一件很了不起。TCP-IP 协议族异常健壮（它从未失败），但遗憾的是，它没有真正的安全机制，即身份验证、校验、加密等。在当今的互联网中，伪造数据包、拦截数据包、读取数据负载等都非常容易。最常见的攻击是拒绝服务攻击，这种攻击最容易执行也最难击败，其次是数据包嗅探、端口扫描和其他相关活动。

主机名并不总是指向 IP 地址，而 IP 地址也不总是反向查询到正确的主机名。如果可能，请不要使用主机名认证，DNS 缓存中毒相对容易；依赖 IP 地址进行身份验证会将问题简化为伪造问题，但其本身也存在缺陷。在广泛传播的网络中，没有机制可以验证谁发送了数据以及谁在接收数据（不过 IP/IPv6 和 VPN 技术正在开始获得动力）。

你可以从禁止声称源自你网络（们）的数据开始，因为这些数据显然是伪造的；为了防止你的用户进行伪造攻击，你应该阻止所有不是来自你 IP 地址的传出数据。这相对简单且易于管理，绝大多数网络都没有这样做（在他们开始之前我骚扰了我的 ISP 大约一年）。如果互联网上的每个人都有出站过滤器（即限制出站流量为特定的流量），那么伪造攻击将是不可能的，追溯攻击者到源头也会变得更容易。你还应该阻止预留网络（127.*, 10.* 等），我注意到有很多来自互联网的攻击标记为这些 IP 的数据包，如果你使用网络地址转换（如 IPMASQ）且没有正确配置防火墙，你可能会很容易受到攻击，或被用来将攻击转发给第三方。

如果你必须使用 VPN 技术与人们进行安全通信，“最好”的可能是 IPSec，它是一个由所有主要供应商支持的开放标准，且大多数主要供应商都有实际的实现。更多细节请参阅附录 B 或加密服务与数据章节。

### IPSec

IPSec 是数据包级别的加密，它不仅提供数据加密，如果你使用签名证书（类似于签名的 PGP 密钥），还可以提供参与方的身份验证。几个证书供应商（例如 Verisigen、Thwaite 等）计划提供 IPSec 证书签名，这样你就能确定你正在与谁交道，并让你实现公司级证书架构的能力。IPSec 在本文后文会有详细介绍。

## PPP 安全

PPP 在串口（可以连接到调制解调器）上提供 TCP-IP（以及 IPX/SPX 和 NetBEUI）连接。它是大多数人连接互联网的主要方法（几乎所有的拨号账户都是 PPP）。PPP 连接本质上由两个计算设备（计算机、Palm Pilot、终端服务器等）通过串口链路（通常通过调制解调器）连接组成，两端都调用 PPP，身份验证由处理（多种方法之一），并建立链路。PPP 对加密没有真正的支持，所以如果你需要安全链路，你必须投资一些 VPN 软件。大多数系统以相当笨拙的方式调用 PPP，即“登录”设备（终端服务器等），然后当你的登录 shell 被调用时，当然，你的用户名和密码会以明文形式发送到线路上，并且你必须在该设备设备上有一个账户，在这种情况下，PPP 完全没有处理身份验证。处理此问题的一种稍显安全的方法是使用 `PAP`（密码认证协议），由 PPP 处理身份验证，因此你不需要在服务器上拥有真实账户。

## 网络服务

### Telnetd

Telnet 是现今互联网上最早的服务之一，它允许你交互式地登录到远程机器，发布命令并查看结果。它仍然是大多数环境中远程管理的主要默认工具，并拥有几乎通用的支持（即使 NT 也有 telnet 守护进程和客户端）。它也是最不安全的协议之一，容易受到嗅探、劫持等攻击。如果你使用 telnet 连接服务器，你应该尽可能为你的账户加密，并使用 `tcp_wrappers` 限制 telnet 仅允许特定的主机使用。加固 telnet 的最佳解决方案是禁用它并使用 SSL 加密后的 telnet 或 ssh。

telnet 的问题：

- 明文身份验证，用户名和密码。
- 所有命令均为明文传输。
- 密码破解攻击（极少，会记录在日志文件中）。

最佳解决方案是关闭 telnet 并使用 ssh。然而，在所有情况下这并不可行。如果你必须使用 telnet，我强烈建议使用防火墙进行防护，设置规则允许主机/网络访问 23 端口，然后设置一个拒绝访问该端口的通用规则（这样效率更高，因为系统只检查 TCP 连接而不是每个数据包（防火墙规则）。使用 `tcp_wrappers` 允许人们发现你正在运行 telnet，它允许他们连接，评估连接，如果他们不在允许列表中则关闭连接）。防火墙规则的示例如下：

```bash
ipfwadm -I -a accept -p tcp -s 10.0.0.0/8 -D 0.0.0.0/0 23
ipfwadm -I -a accept -P tcp -S some.trusted.host -D 0.0.0.0/0 23
ipfwadm -I -a deny -p tcp -s 10.0.0.0/0 -D 0.0.0.0/0 23
```

或者在 ipchains 中：

```bash
ipchains -A input -p all -j ACCEPT -s 10.0.0.0/8 -d 0.0.0.0/0 23
ipchains -A input -p all -j ACCEPT -s some.trusted.host -d 0.0.0.0/0 23
ipchains -A input -p all -j DENY -s 0.0.0.0/0 -d 0.0.0.0 23
```

使用 `tcp_wrappers` 的示例：

在 `/etc/hosts.allow` 中

```
in.telnetd: 10.0.0.0/255.0.0.0, some.trusted.host
```

在 `/etc/hosts.deny` 中

```
in.telnetd: ALL
```

### RSH, REXEC, RCP

R 服务如 `rsh`, `rcp`, `rexec` 等非常不安全。没有其他方式可以描述这一点。它们的安全性基础基于连接机器的主机名/IP 地址，这可以轻易被伪造，或者通过 DNS 投毒等技术被破坏。默认情况下，它们并没有被全部禁用，请立即禁用它们。编辑 `/etc/inetd.conf` 查找 `rexec` `rsh` 等并将其它们注释掉，然后执行 `killall -1 inetd` 重启 `inetd`。

如果你需要易用且类似于 `rsh/etc` 的远程管理工具，我推荐 `nsh` (Network Shell) 或 SSH，它们都支持加密，安全性高得多。或者，使用 VPN 软件可以减少风险，因为它可以拒绝伪造者攻击你系统的机会（IPSec 是发送者的身份验证，这在某些情况下比加密数据更重要）。

### FTP

`FTPD` 曾经是互联网上最常用的协议，直到几年前它被 HTTP 取代（是的，互联网曾是那样的）。

### SQUID

`SQUID` 是一个强大且快速的对象缓存（Object Cache）。它能代理 `FTP` 和 `WWW` 会话，基本上让它具备了 `FTP` 和 `WWW` 服务器的许多属性，但它只在其缓存目录内进行文件的读写操作（我们希望是这样），这使得它相对安全。除了以 `root` 用户（通常为 '`nobody`'）运行外，`Squid` 很难攻破它所运行的系统，因此通常不需要太担心。你对 `squid` 最主要的担心应该是配置不当，例如，如果 `squid` 连接到了你的内部网络（这通常是如此的）和互联网（再次，非常常见），它实际上可能被用来访问内部主机（即使它们使用的是非路由 `IP` 地址）。妥妥地配置 `squid` 非常重要。

确保这种情况不会发生的最简单方法是使用 `squid` 的内部配置，并仅绑定到内部接口，不让外部世界尝试将其作为访问你内部局域网（`LAN`）的代理，此外，对其进行防火墙隔离也是个好主意。`Squid` 还可以用作 `HTTP` 加速器，也许你在内部网络上有一个想要与世界共享的 `WWW` 服务器，在这种情况下配置会变得复杂一些，但是可以安全地实现的。幸运的是，`squid` 拥有良好的 `ACL`（访问控制列表），允许你通过名称、`IP`、时间、实际日期来锁定访问（也许允许真正去办公室的人在周末进行无限制浏览）。请记住，`ACL` 越复杂，响应请求的速度就越慢。

`ACL` 的工作原理是定义规则，然后应用这些规则，例如：

```
acl internet 10.0.0.0/255.255.0.0
http_access allow internet
http_access deny all
```

这把 "`internet`" 定义为源地址为 `10.0.0.0/255.255.255.0` 的任何内容，允许其访问 `http` 缓存端口，并拒绝其他所有。记住规则是按照给定的顺序读取的，就像 `ipfwadm` 一样，这允许你获得非常复杂的配置（如果你不小心就会出错）。始终从特定的规则开始，然后是更通用的规则，并记得在特定的允许（`allow`）之后放置拒绝（`deny`），否则它可能会放行。意外拒绝一切也比让它通过要好，因为你会发现拒绝后的（来自恼怒用户的反馈）比通过后的反馈更快（当恼怒的用户注意到来自内部 `www` 服务器的统计文件出现在互联网上时）。`squid` 配置文件 (`squid.conf`) 注释详尽（到了过头的程度），并且也有相当不错的帮助页（`man-page`）。

另一个实用的例子是拦截广告，为了拦截广告，你可以在 `squid.conf` 中添加以下内容：

```
acl ads dstdomain ads.blah.com
http_access deny ads
```

`acl` 声明仅仅是一个模式，无论是目标域名、源域名、正则表达式等，`http_access` 声明激活了对它执行什么操作（拒绝、允许等）。如果设置得当，这是一个限制访问 `WWW` 的极其强大的工具，遗憾的是，它确实有一个喀琉斯之踵：它不支持基于用户的身份验证和控制（尽管可能没有哪个产品都能做到）。请记住，像任何规则一样，它们是从上到下读取的，所以先放特定的拒绝和允许，然后是更通用的规则。`squid.conf` 文件应该有详尽的注释且自明易懂，`squid` `FAQ` 位于：`http://squid.nlar.net/Squid/FAQ/FAQ.html`。



许多人忽视的一个重要安全问题是它保留的日志文件。默认情况下，`squid`可能会记录或不记录它处理的每一个请求（取决于配置文件），从`http://www.nsa.gov/`到`"members.porn.com/bin/access&johndoe&password=booboo"`。你绝对想要禁用访问日志，以便密切关注人们在互联网上的浏览内容（这在法律上是有争议的，请咨询你的律师），指令是`cache_access_log`，将其设置为`"/dev/null"`，这会记录所有访问和 ICP 查询（缓存间的通信）。下一个是`cache_store_log`，它实际上对于生成关于你的 www 缓存有效性的统计非常有用，它不记录谁发起了请求，只记录缓存中对象的状态，所以如果你看到游乐场的图片被反复提供，请将其设置为`"none"`。`cache_log`应该保持开启，它包含了基本的调试信息，例如服务器何时启动以及何时停止，将其设置为`"/dev/null"`。另一个未被很好记录的日志文件是`cache_swap_log`，它记录了缓存发生的情况，还会显示人们在为谁服务（但不是具体的谁/等），将其设置为`"/dev/null"`是不起的（在`squid`输出中），且将其设置为`"none"`也不行。停止它的唯一方法是将文件链接到`"/dev/null"`（通过你缓存的默认根目录），并链接到`log-cache-last`尽管在快速测试中它似乎没有存储任何内容），在`squid`中：

```
cache_access_log /dev/null
cache_store_log none
cache_log /dev/null
cache_swap_log /dev/null
```

## DHCPD

DHCPD 是所有网络管理员都应该使用的工具。它允许你向请求网络设置/等信息的客户端提供服务，这意味着网络连接所需的客户端设置只需保持默认值并开启机器即可。它还允许你轻松地重新配置客户端（例如从 10.0.1.0 移动到 10.0.2.0，或使用一组新的 DNS 服务器）。从长期来看（以及短期内也是如此），DHCP 将为你节省大量工作、金钱和精力。我在家里运行它，只有 8 个客户端，发现生活变得简单多得多。DHCPD 由 ISC 维护，地址为：`http://www.isc.org/dhcp.html`。

我强烈建议你运行 DHCPD 2.x（3x 处于 alpha 阶段），它有很多新功能，而且易于设置和使用。不过，该程序的绝对版本往往有点神经质，请注意它是 beta 软件。务必不要将 DHCPD 暴露在互联网上。DHCP 流量应该只在本地网段上运行，可能会被转发到另一个网段的 DHCP 服务器，但你在互联网上看到的唯一 DHCP 流量将是攻击/DoS（它们可能会恢复你所有的 IP，让你的客户端孤立无援）。如果你要在互联网上转发 DHCP 流量，**千万不要**。出于多种原因，这是一个一个坏主意（主要是性能/可靠性，也包括安全性）。

我建议 DHCP 服务器仅作为一个 DHCP 服务器，锁定在某个地方（如果你依赖 DHCP 运行网络，而 DHCP 服务器故障，你的网络将面临严重问题），允许它快速运行，如果你需要跨越子网（如果你有多个服务器，其中只有一个服务器物理连接了 DHCP 服务器），请使用 DHCP 中继（NT 没有内置功能，Linux 的 DHCP 软件具有此能力，等）。NT 和 DHCP 之间也存在已知问题，NT RAS 有一个糟糕的习惯，会疯狂地吸取 IP 地址（我见过一个 NT 服务器抢占了 64 个地址并无限期保留），因为它正尝试为将拨入/拨出的客户端预留 RAS IP。要么关闭 NT 的 RAS，要么将其放在它单独的子网中，它发送给 DHCP 服务器的 MAC 地址非常奇怪（并且在前几个字节中拼写出 RAS），并且很容易进行映射。

DHCPD 包含 2 个可执行文件：

- `dhcpd` - DHCP 服务器

- `dhrelay` - 一个 DHCP 中继程序（用于将请求中继到中央 DHCP 服务器，因为 DHCP 是基于广播的，而广播通常不会（也不应该）跨越路由器/以太卡。）

DHCPD 需要 2 个库文件：

- `/lib/dhcp-linux.so.2`

- `/lib/libc.so.6`

一个配置文件：

- `/etc/dhcpd.conf` - 配置信息、启动文件位置等。

以及其他一些杂项文件：

- `/etc/dhcpd.leases` - 活动租约列表

- 一个启动文件，你可以仅对随附的那个进行修改

`tftp`（简单文件传输协议）用于需要从网络服务器获取信息的设备，通常在启动时使用。它是 `ftp` 的一种极其简单的形式，剥离了大部分安全功能和高级命令，它基本上允许设备以一种非常简单的方式从服务器检索（上传）文件。`tftp` 几乎专门用于工作站、路由器配置以及任何启动时需要信息的设备，因为它呈现了一个巨大的安全漏洞，如果有人连接到你的 `tftp` 服务器并抓取了你 Cisco 路由器的文件，就了。此外，`tftp` 默认授予对文件系统（包括 `/etc/passwd` 文件）的访问。现代版本的 `tftp` 限制了访问，并使用 `TCP_WRAPPERS` 来限制对主机的访问。默认情况下，`tftp`（至少对于 RedHat）只提供对 `/tboot` 目录的访问。将 `tftp` 目录尽可能与系统分开是一个好主意。这通过在 `ftp` 命令启动 `inetd.conf` 后指定 `tftp` 有权访问的目录来实现。此示例正常启动 `tftp` 并授予对 `/tboot` 目录和 `/kickstart` 目录的访问。

```
tftp dgram root /usr/bin/tcp in.tftp /tboot
/kickstart
```

还要记住 `tftp` 使用 '`ps aux`' 不一定会显示谁登录了或他们正在做什么（与 `ftp` 不同，除非他们正在下载文件，否则不会显示，因为你不太可能抓到他们）。监控 `tftp` 的最佳地方是 `syslog`，但即使是 `tftp` 也不记录地址或任何有用信息。以下是活动 `tftp` 会话的 `ps` 输出和 `syslog` 输出。

```
nobody 744 0.0 6 780 R 14:31 0:tftp
Apr 24 14:31 hostname tftpd[744]: trying to get file
Apr 24 14:31 hostname tftpd[744]: serving file from /tboot
```

TFTP 可以使用 `TCP_WRAPPERS` 和防火墙轻松地限制，`tftp` 运行在端口 `69`，只需限制到你的工作站所需的访问即可。此外，在网络边界阻止所有流量也是一个好主意，因为没有必要机器跨互联网使用 `tftp` 进行远程启动。此外，`tftp` 以 `nobody` 身份运行，但由于没有进行身份验证且所有访问 `tftp` 服务器的设备都是这样做的，因此文件级安全相当没用。`tftp` 仅运行在端口 `69`。

SNMP（简单网络管理协议）的设计是为了让异构系统和设备相互通信、报告数据并允许在 TCP/IP 网络上对其设置进行修改。例如，启用 SNMP 的设备（如 路由器）可以从 SNMP 客户端进行监控/配置，你可以轻松编写脚本在拒绝的数据包/秒数超过 20 时提醒你。遗憾的是，SNMP 没有内置安全功能。`SNMPv1` 最初在 `RFC 1157`（1990年5月）中提出，其第 8 节（安全考虑）读起来确实是：“本备录中没有讨论安全性。”我认为这已经说明了问题。1992/1993 年发布了 `SNMPv2`，并包含了安全考虑，但这些安全考虑在随后被证明完全破解后后被丢弃了。我们最终留下了 `SNMPv2` 而没有安全性。保护你的 SNMP 设备的唯一方法是将社区名称设置为难以破解的内容（但很容易通过嗅探线缆并找到该名称）。

## Finger

`Finger` 是大多数管理员都会禁用并忽略的服务之一。它在某些情况下是有用的工具，但如果你想让其他管理员找出你的哪些用户当前正尝试破解他们的机器，应该使用 `ident`。`Finger` 泄露的信息过多，是目标进行初始探测和数据收集的常用工具。目前还出现过几次极其恶劣的 DOS 攻击，基本上是通过发送数百个 `finger` 请求，并在某些配置下利用服务器漏洞。请不要运行 `finger`。许多发行版默认开启了它，但引用 RedHat 的 `inetd` 描述：

```
### Finger, systat and netstat 给出的信息可能对
### 潜在的“系统破解者”有用。许多站点选择禁用
### 部分或全部这些服务以提高安全性。
```

如果你仍然非常想运行它，请使用 `-u` 来拒绝 `finger @host` 请求，这些请求从未被用于为未来的攻击收集信息。真的请禁用 `finger` 吧。`Finger` 还导致了最近几次非常严重的拒绝服务攻击，特别是当你运行带有大型映射的 NIS 时，不要，重复一遍，**不要**运行 `finger`。`Cfingerd`（可配置的 `finger`）是原生 `finger` 的绝佳替代方案，它在设计时考虑了安全性，以非 root 用户运行，并可以轻松配置使其无法被 `finger` 查询。可以从此处获取 `cfingerd`：http://ftp.bitgate.com/cfingerd/。`Finger` 运行在端口 79，而 `cfingerd` 运行在端口 2003，两者都使用 tcp。

```

ipfwadm -I -a accept -P tcp -S some.trusted.host -D 0.0.0.0/0 79
ipfwadm -I -a deny -P tcp -S 0.0.0.0/0 -D 0.0.0.0/0 79
```

或者

```
ipchains -A input -p tcp -j ACCEPT -s 10.0.0.0/8 -d 0.0.0.0/0 79
ipchains -A input -p tcp -j ACCEPT -s some.trusted.host -d 0.0.0.0/0 79
ipchains -A input -p tcp -j DENY -s 0.0.0.0/0 -d 0.0.0.0/0 79
```

## Identd

`Identd` 服务用于将用户/进程映射到输入端口。例如，源服务器尝试通过进行 `ident` 查找来找出是谁连接到了它们的，这基本上是询问 `ident` 关于某个端口号的信息，信息范围从无所获（如果没有人使用该特定端口）到用户名、组名、进程 ID（PID）以及其他感兴趣的信息。许多发行版的默认设置是 `identd` 开启（可以运行它，且较新版本会发送较小的 `ident` 响应），并且仅提供用户名。`ident` 的主要用途是通过追踪连接到其服务器的用户来允许远程系统访问，包括 `telnet`、邮件或，或者用于身份验证目的（这不是个好主意，因为非常容易伪造）。埃德蒙顿的当地大学如果你想 `telnet` 进入任何一个主服务器，就需要运行 `identd`，主要是为了让他们能够快速追踪到被破解的账户。`Identd` 是一个实用的工具，但通常在机器上它是一把双刃剑，虽然它提供了追踪攻击者（无疑是你想要从服务器上踢出去的人）的信息，但它也被用于获取有关你系统的信息，导致他们的账户被破解。我建议在带有账户`/etc` 的服务器上运行 `identd`。

`Identd` 支持一些功能，并可以轻松设置为以非 root 用户运行。根据你的安全策略，你可能不想提供太多信息，或者你可能提供尽可能多的信息。只需在 `inet.conf` 中 `identd` 之后添加选项即可（默认是 `-l -e`）。

```
-p port
- address
```

可以用于指定它绑定的端口和地址（对于具有 IP 别名或多个接口的机器），这通常只在你希望机器进行连接时才有用，因为外部机器可能无法查出你更改了哪个端口。

```
-u uid
-g gid
```

用于设置 `identd` 在连接到端口后将降权的用户和组 ID，这将使其更不容易受到破坏系统安全的威胁。至于处理它提供的信息量：

```
-o
```

指定 `identd` 不返回操作系统类型，而是简单地显示 "UNKNOWN"，这是一个非常好的选项。

```
-n
```

让 `identd` 返回用户数字（即 UID）而不是用户名，这仍然提供了足够的信息让你识别并允许你轻松追踪该用户，而不会给潜在的攻击者提供价值价值线索。

```
-N
```

允许你创建一个 `/.nident` 文件，这将强制 `identd` 返回 "HIDDEN-USER" 而不是信息。

```
-F format
```

允许你指定比标准多得的信息，从用户名和数字到实际的 PID、命令名、以及提供的命令名称和参数！我建议在内部使用，因为这些对于攻击者来说可能是非常有用的大量信息。

总来说，我建议禁用 `identd`，主要是由于它容易受到许多拒绝服务攻击。只有当你想要方便其他管理员的生活（即追踪你的哪些用户是坏人）时，才应该运行它。不过，还有其他带有安全增强 `identd` 版本（我尚未测试过这些）：

http://insecurity.net/ - Paul 写的 secure identd

http://www.ojnk.nu/~ident/ - ojn identd

http://www.tildes/null.html - null identd

http://www.ajk.tele/~too/ - fake identd

http://pur.het.net/ - midident

`Identd` 运行在端口 113，使用 tcp，通常在你需要 IRC（许多网络需要 ident 响应）或运行守护进程（如 tcp_wrapped `telnet` 或 `sendmail`）时才需要它。

```

ipfwadm -I -a accept -P tcp -S some.trusted.host -D 0.0.0.0/0 113
ipfwadm -I -a deny -P tcp -S 0.0.0.0/0 -D 0.0.0.0/0 113
```

或者

```

ipchains -A input -p tcp -j ACCEPT -s some.trusted.host -d 0.0.0.0/0 113
ipchains -A input -p tcp -j DENY -s 0.0.0.0/0 -d 0.0.0.0/0 113
```

## ntpd

`NTP`（网络时间协议）的任务相当简单，就是为了保持时钟同步。如果不同服务器的时间相差几分钟，尝试比较它们。`NTP` 工作原理是客户端连接到时间服务器，获取时间并设置时钟（在局域网内可能只有 1-2ms，跨越互联网可能是几毫秒），此外，服务器可以“聚类”以保持同步，三个或更多服务器丢失时间的概率（也称为 "drift"）相对较低。时间信号通常由原子钟或 GPS 信号产生，这些是 "stratum 1" 服务器，它们的下方是公开访问的 stratum 2 服务器，公司如果有足够的调整，可能会拥有自己的 stratum 3 服务器，以此类推。数据非常敏感，如果攻击者能够篡改各种数据，可能会导致不可用，账户可能会提前过期。因此，一个主意是运行你的时间服务器（它们只会产生几秒的偏移，不应该太大）。如果你有大量的客户端，考虑购买一个各种形状和尺寸的 GPS 时间单元，直接插入服务器的 PCI 卡。为你的时间服务器设置防火墙是一个主意，因为拒绝服务攻击会对你的网络产生危害。此外，如果可能，使用 DES 加密通常足以阻止大多数攻击者。关于 `ntpd` 或 `xntpd`（有详细文档）的帮助可以在 `/usr/doc/` 找到，或访问：http://www.udel.edu/~ntpd/spool/index.htm。`NTP` 运行在端口 123，使用 udp，对其进行防火相对简单：



```
ipchains -I input -p udp -j ACCEPT -s 10.0.0.0/8 -D 0.0.0.0/0 123
ipfwadm -I -a accept -p udp -s some.trusted.host -D 0.0.0.0/0 123
ipfwadm -I -a deny -p udp -j DENY -s 0.0.0.0/0 -D 0.0.0.0/0 123
ipfwadm -I -a accept -p tcp -s 10.0.0.0/8 -D 0.0.0.0/0 123
ipfwadm -I -a accept -p tcp -s some.trusted.host -D 0.0.0.0/0 123
ipfwadm -I -a deny -p tcp -j DENY -s 0.0.0.0/0 -d 0.0.0.0/0 123
```

或者

```
ipchains -A input -p udp -j ACCEPT -s 10.0.0.0/8 -d 0.0.0.0/0 123
ipchains -A input -p udp -j ACCEPT -s some.trusted.host -d 0.0.0.0/0 123
ipchains -A input -p udp -j DENY -s 0.0.0.0/0 -d 0.0.0.0/0 123
ipchains -A input -p tcp -j ACCEPT -s 10.0.0.0/8 -d 0.0.0.0/0 123
ipchains -A input -p tcp -j ACCEPT -s some.trusted.host -d 0.0.0.0/0 123
ipchains -A input -p tcp -j DENY -s 0.0.0.0/0 -d 0.0.0.0/0 123
```

`rsync` 是一种极其高效的文件镜像方法，无论是是 CVS 树的源代码文件、网站，甚至是本文，`rsync` 都能保留文件权限、链接、文件时间，此外，它还支持匿名模式（顺便提一下我用它来镜像本文），这让所有相关人的生活变得非常容易。`rsync` 程序本身可以作为客户端（通过命令行或脚本）也可以作为服务器（通常运行在 `inetd` 中）。该程序相当安全，作为客户端或服务器都不需要 `root` 权限（除非你真的想要，并且可以选择任何被镜像内容的根目录，但这需要 `root` 权限并且可能比其价值更危险）。你也可以映射访问访问系统的用户 ID 和组 ID（对于预编译的 rsync 包，默认是 `nobody`，这可能是最好的选择）。在非匿名模式下，`rsync` 支持用户名和密码，这些密码使用 128 位 MD4 进行加密。“rsync.conf” 页面清楚地将 `rsync` 设置为服务器并使其运行较快。默认配置文件是 `/etc/rsync.conf`，包含一个全局部分和模块部分（每个共享输出目录都是一个模块）。

rsync 示例：

```
motd file = /etc/rsync.modt # 指定要显示的文件，法律
免责声明，等
max connections = 5      # 最大连接数，防止你被流量淹没
[pub-ftp]
    comment = public ftp area # 简单注释
    path = /home/ftp/pub     # 目录路径
    read only = yes          # 设置为只读，非常适合导出
    chroot = yes             # chroot 到 /home/ftp/pub
    uid = nobody             # 显式设置 UID
    gid = nobody             # 显式设置 GID
[secret]
    comment = my stuff # 我的东西的路径
    path = /home/user/secret
    list = no               # 在请求时隐藏此模块
    secrets file = /etc/rsync.users # 密码文件
    auth = bob   # 查看我内容的的用户列表
    hosts = 1.1.1.1, 2.2.2  # 允许的主机列表
```

如你所见，`rsync` 是可配置的且通常是，异常是实际传输没有以任何方式加密。如果你需要免费方案，建议使用 `SSH` 建立隧道连接，或者某些 VPN 解决方案如 WAN。还要确保你运行的是 `rsync 2.3.x`，或者在 2.2.x 中发现了潜在漏洞。`Rsync` 可以在此处获取：http://rsync.org/。`Rsync` 运行在端口 873`tcp`。

`lpd` 是 UNIX 的打印设施（打印守护进程）。它允许你提交打印作业、通过过滤器运行、管理打印队列等。`lpd` 可以在本地或通过网络接受打印作业，并访问系统的各个部分（守护进程等），这使其成为一个潜在的安全漏洞。`lpd` 曾是许多问题的根源，但现在大多已修复，由于其功能仍然存在潜在的拒绝服务攻击（例如提交打印作业和出纸）。随着网络打印机的出现，`lpd` 正在被逐渐淘汰，但 `lpd` 访问仍通过 `/hosts` 控制。你应该从外部对墙 `lpd`，如果你需要跨网络发送打印作业，请记住任何人都可以读取，因此 VPN 解决方案是一个好主意。`Lpd` 运行在端口 515 `tcp`。`hosts` 文件应该包含一个主机列表（workstation1,yourdomain.com 等），每行一个允许使用服务器上 Lpd 服务的主机，你同样可以使用 `ipfwadm/ipchains`：

## X Window System

X Window System 提供了一种共享数据的网络透明方法，具体说是将程序的导出到远程（本地）主机。使用它可以运行 3D 渲染。这是一个强大的工具，但也非常危险。X Window System 是许多漏洞的根源，但现在大多已修复，由于其功能仍然存在许多潜在的拒绝服务攻击。你应该从外部对 X 使用防火墙，如果你需要跨网络发送数据，请记住任何人都可以读取，因此 VPN 解决方案是一个好主意。X 运行在端口 6000 `tcp`。`hosts.access` 文件应该包含一个主机列表（workstation1,yourdomain.com 等），每行一个允许使用服务器上 X 服务的主机，你同样可以使用 `ipfwadm/ipchains`：

## CVS

CVS 允许多个开发者协作进行源代码项目，并以一种相当合理的方式维护大型代码库。CVS 的内部安全机制本身相当简单（有些人甚至认为很薄弱），我对此赞同这一观点。CVS 的身份验证通常通过 `pserver` 在网络上实现，用户名以明文发送，而密码经过了简单的哈希处理（没有任何安全性可言）。为了绕过这个问题，你有几个很好的选择。在 Unix 环境中，可能最简单的方法是使用 `SSH` 在客户端和服务器之间建立隧道连接，“Time Wemaster” (Tim Hemel) 编写了一篇涵盖该内容的优秀文章，我没打算重新整理它，你可以在此处找到：http://cubic.xa4.nl/~cvs/。另一种稍微复杂一点（但从长远来看对于大型安装更好）是将 CVS 服务器和客户端 Kerberos 化，大型网络（特别是大学环境）已经建立了 Kerberos 基础设施。关于对 CVS 进行 Kerberos 化，可以在此处找到信息：http://www.cyclic.com/cyclic-pages/security.html。除外，我强烈建议对 CVS 使用防火墙，除非你将其用于某些公共目的（例如跨越互联网的开源项目）。

`rsync` 是一种极其高效的文件镜像方法，无论是是 CVS 树的源代码文件、网站，甚至是本文，`rsync` 都能保留文件权限、链接、文件时间，此外，它还支持匿名模式（顺便提一下我用它来镜像本文），这让所有相关人的生活变得非常容易。`rsync` 程序本身可以作为客户端（通过命令行或脚本）也可以作为服务器（通常运行在 `inetd` 中）。该程序相当安全，作为客户端或服务器都不需要 `root` 权限（除非你真的想要，并且可以选择任何被镜像内容的根目录，但这需要 `root` 权限并且可能比其价值更危险）。你也可以映射访问系统的用户 ID 和组 ID（对于预编译的 rsync 包，默认是 `nobody`，这可能是最好的选择）。在非匿名模式下，`rsync` 支持用户名和密码，这些密码使用 128 位 MD4 进行加密。“rsync.conf” 页面清楚地将 `rsync` 设置为服务器并使其运行较快。默认配置文件是 `/etc/rsync.conf`，包含一个全局部分和模块部分（每个共享输出目录都是一个模块）。

# Samba

`SAMBA`是自大发明以来最好的工具之一，如果你想在`Windows`和`*NIX*`之间共享文件和打印机。它在某种程度上被误解，并且受到与各种（有时是损坏的）`Windows`客户端交互的影响很大。`SAMBA`有一些很棒的临时方案（kludges）试图让它变得正常，但可能会导致看起来像故障的行为。`SAMBA`仅通过`SMB`（服务器消息块）访问文件系统，这是用于共享文件和打印机的协议。它会验证用户名和密码（如果需要），然后根据设置的文件权限等访问文件。我将只介绍`Samba 2.x`，`Samba 1.x`已经非常老且过时。

`Samba 2.x`通过`smb.conf`控制，通常位于`/etc`（`man smb.conf`）。在`/etc/smb.conf`中你有四个配置区域：`[globals]`、`[printers]`、`[homes]`以及每个`[sharename]`自己的配置（无论是打印机还是驱动器）。有很多开关，`samba conf`页面对此详尽说明。重要的（安全）选项包括：

- `security = xxxx`其中`xxxx`是服务器或域，`security`按共享单独设置，带有每个人都可以获取的密码，或者意味着`samba`服务器本身通过`/etc/password`或`smpasswd`身份验证用户。如果你将其设置为`domain`，`samba`将通过`NT`控制器验证用户，完美地融入到你现有的`NT`网络中（如果你有的话）。

- `guest account = xxxx`其中`xxxx`是你希望客用户映射的账户用户名。如果定义了共享，则对该共享的所有请求将作为此用户处理。

- `hosts allow = xxxx`其中`xxxx`是用空格分隔的允许连接到服务器的主机/`IP`块列表。

- `hosts deny = xxxx`其中`xxxx`是用空格分隔的不允许允许连接到服务器的主机/`IP`块列表。

- `interfaces = xxxx`其中`xxxx`是用空格分隔的`samba`将绑定的`IP`块列表。

我强烈建议安装并使用`SWAT`（`samba Web`管理工具），因为它可以减少你可能犯的错误等。`Samba`和`SWAT`可在此获取：http://www.samba.org/，并随几乎每个发行版一起发布。

## 基于网络的身份验证

### NIS / NIS+

`NIS`和`NIS+`（正式称为“黄页”）代表网络信息服务。本质上，`NIS`和`NIS+`提供了一种在许多机器上分发密码文件、组文件和其他配置文件的方法，提供了账户和密码同步（以及其他服务）。`NIS+`本质上是带有若干增强（主要与安全相关）的`NIS`，它们非常相似。使用`NIS`，你需要设置一个`NIS`服务器，它将包含记录并允许更改它们（添加用户等），此服务器可以将记录分发到从属`NIS`机器，这些机器包含记录的只读副本（如果发生糟糕的情况，它们可以被提升为主节点并进行读写）。`NIS`网络的客户端本质上请求部分信息并将其直接复制到配置文件中（如`/etc/passwd`），使其在本地可访问。使用`NIS`可以为数千条路由和服务器提供相同的用户名、信息、密码等，显著减少了管理噩梦。然而，问题在于，共享这些信息会使攻击者能够访问，这是`NIS+`试图解决的问题，但`NIS+`的设置是另一个噩梦。另一种替代策略是使用某些`VPN`支持（`FreeSWAN`，这难道不解决一些问题吗？）并在数据进入网络之前对其进行加密。有一个`NIS/ NIS+`教程：http://metalab.com/LDP/HOWTO/NIS-HOWTO.html，`O'Reilly`有一本关于该主题的好书。`NIS+`运行在`RPC`之上，使用端口`111`，`tcp`和`udp`。这目前应该定义在你的网络边界，但将不会完全阻止`NIS / NIS+`

```
ipfwadm -I -a accept -P udp -s 10.0.0.0/24 -d 0.0.0/0
ipfwadm -I -a accept -P udp -s some.trusted.host -d 0.0.0/0
ipfwadm -I -a deny -P udp -s 0.0.0/0
```

或

```
ipchains -A INPUT -p udp -j ACCEPT -s 10.0.0.0/24 -d 0.0.0/0
ipchains -A INPUT -p udp -j ACCEPT -s some.trusted.host -d 0.0.0/0
ipchains -A INPUT -p udp -j DENY -s 0.0.0/0 -d 0
```



由于 `NIS` 和 `NIS+` 是 `RPC` 服务，它们以某种随机的方式使用高位端口（即 1024 以上），使得对其进行防火墙拦截非常痛苦。最好的解决方案是将你的 `NIS` 服务器放置在内部禁止与互联网完全入出站通信的机器上。

### SRP

`SRP` 是一个相对新的成员，但它比一些旧程序有许多优势。`SRP` 商业用途免费，且不使用加密来保护数据，将其出口到美国以外并不是太大的问题。`SRP` 使用单向哈希对双方进行身份验证。缺点是 `SRP` 只加密登录（用户名和密码），因此任何传输的数据（如 `telnet` 会话或 `ftp` 站点）都是脆弱的。你可以从 `SRP` 获取 `SRP`：`http://srv.stanford.edu/srp/`。`SRP` 目前支持 `Telnet` 和 `FTP`（我们也是），启用其他协议相对简单。

`Kerberos` 是一种现代网络身份验证系统，其基于一旦用户向 `Kerberos` 服务器身份验证后向其发放票据（类似于 `NT` 对令牌的使用）。`Kerberos` 可在此获取：`http://web.mit.edu/kerberos/www/`。`Kerberos` `FAQ` 可位于：`http://www.nrl.navy.mil/CCS/people/kenh/kerberos-faq.html`。`Kerberos` 适用于大型安装，因为它的扩展更好且比 `NIS` / `NIS+` 更安全。通过一些努力可以实现 `telnet`、`imap` 和 `pop` 等程序的 `Kerberos` 化，然而，支持 `Kerberos` 的 `Windows` 客户端则较难找到。

## 加密网络服务

几乎所有的网络流量都是未加密的，很容易被攻击者读取。如果有人破解了你网络上的某台机器并安装了密码嗅探器（基本上就是带有过滤器的你的常用数据包嗅探器），你的整个网络可能会在几小时内被攻破。某不具名的互联网服务提供商（`ISP`）将托管客户放在同一个局域网（`LAN`）中，使用普通的以太网集线器，这意味着所有机器都能看到彼此的流量（用户通过 `pop` 获取的电子邮件、`telnet` 会话等）。这就是为什么加密流量是一个好主意的众多原因之一。

目前存在或正在开发各种加密机制，用于在网络堆栈的各个层级上加密网络流量。某些方案仅加密发送的数据（如 `PGP` 加密邮件），某些加密会话（`SSL`），有些加密数据包的载荷（`IPSec` 和 `VPN`）。根结底，最佳解决方案将是 `IPSec`（我的个人观点），因为它不需要对应用程序进行任何修改，并为计算机之间提供了极高的安全性。微软不支持[它]，这对于任何大规模解决方案都是一个严重障碍（坦率地说，微软确实没有 `IPSec` 支持，但它还没有准备好）。目前最好的可用方案是 `SSL`。安全套接层（`Secure Sockets Layer`）最初由 `Netscape` 提出，在服务器级别加密数据，如果你的应用程序支持 `SSL` 且服务器支持 `SSL`，你就成功。大多数浏览器、邮件/新闻阅读器以及免费的 `ftp` 和 `telnet` 客户端目前都支持 `SSL`，对于 `Linux`，大多数服务都可以进行 `SSL` 化。然而，`SSL` 需要具备 `SSL` 能力的客户端，这是你无法让大多数人支持的，这意味着 `SSL` 化的服务通常被限制在组织内部。`SSL` 库可以在 `http://www.openssl.org` 获取。

`SSLnet` 和 `MZtel` 是 `telnet` 的无缝替代品，比旧的 `telnet` 提供了更高的安全性，尽管 `SSLnet` 和 `MZtel` 没有 `SSH` 那么灵活，但它们实际上是免费的（即 `GNU` 许可），而 `SSL` 则不是。服务器和客户端包以 `tarball` 形式提供：`ftp://ftp.uni-mainz.de/pub/internet/security/ssl/`，并以 `ftp://ftp.replay.ru/pub/relay/linux/redhat/` 的 `RPM` 包形式提供。

### FTP - SSL

同样是你喜爱的 `ftp`（可能是 `WuFTPD`）的无缝替代品，也可以作为 `WuFTPD` 的补丁集提供。这非常合适，因为大多数服务器都有许多需要 `ftp` 访问的用户。`tarball` 可以在 `ftp://ftp.uni-mainz.de/internet/security/ssl/` 获取，`RPM` 包可以在 `ftp://ftp.replay.com/pub/linux/redhat` 获取。

## 虚拟私有网络解决方案

### IPSec

`IPSec` 是一种被提议的（目前已在某些操作系统中实现）的 `IP` 级加密标准。`IPSec` 的支持程度不一，某些发行版自带了它，但大多数并没有（我们美国的出口法就是原因之一）。`IPSec` 使用公钥加密工作，密钥是经过交换的，并且提供了密钥服务器（`pluto`, `phyto` 等）。`IPSec` 的一个主要问题是该协议尚未通过完全批准，因此实现方式可能存在差异。`Linux` 的 `IPSec` 效应（`Free/WAN`）托管在：`http://www.xs4all.net/~freeswan`，它由加拿人（我的家乡和母国）领导，可以完全出口到世界上任何允许使用强加密的地方（法国、中国、利比亚等除外）。他们刚刚发布了 `1.0`，并支持 `2.x` 系列内核。

### PPTP（点对点隧道协议）

由于大多数服务器都有许多需要 `ftp` 访问的用户，这非常合适。`PPTP` 可以在 `http://www.more..com/vpn/`，可以在 `ftp://ftp.replay.com` 获取。

### CIPE（加密封装）

`CIPE` 是一种被提议的（目前已在某些操作系统中实现）的 `IP` 级加密标准。`IPSec` 加密，流量是不加密的，很容易被攻击者读取。

### ECLipt（加密）

`ECLipt` 是一种被提议的（目前已在某些操作系统中实现）的 `IP` 级加密标准。`IPSec` 加密，流量是不加密的，很容易被攻击者读取。

## 防火墙

防火墙技术是过滤 `TCP-IP` 流量实践，通常发生在你的网络连接到另一个网络（例如互联网、客户的局域网或其他网络）的节点上。这些网络可能是不可信的（如互联网），也可能是可信的（你大楼的另一楼层）。就像大楼里的防火墙一样，网络防火墙可以防止甚至阻止攻击的扩散。

`Linux` 长期以来一直具有以 `ipfwadm` 形式提供的防火墙功能，这是一种非常简单的数据包级过滤器，但非常有效，对大多数人来说足够了。随着内核 `2.1+` 版本的出现，它被 `ipchains` 取代了，后者要复杂得多。然而，两者仍然都是基础的数据包过滤器，不支持高级功能，如状态检测（`stateful inspection`）或某些代理连接。尽管如此，`Linux` 支持 `IPMAS`，这是一种高级的 `NAT`（网络地址转换）形式。`IPMAS` 允许你将计算机网络连接到互联网，但在数据包级上对其连接进行代理，因此所有流量看起来都像是进出某台机器（`Linux IPMAS` 节点），这为内部网络提供了高程度的保护。作为一个额外的好处是，内部网络上的连接不需要代理配置，只要 `Linux IPMAS` 服务器配置正确，就能良好工作。

`ipchains` 和 `ipfwadm` 都提供了以下基本能力：

- 根据 `IP`/`端口`/`接口` 源/目的阻断/允许数据通过
- 根据 `IP`/`端口`/`接口` 源/目的进行连接的伪装（`masquerading`）

此外，`ipchains` 还支持：

- 端口转发
- 创建链，以便于更复杂的规则和条件，便于维护
- 服务质量 (`QoS`) 路由，用于慢速连接或其他拥堵的连接
- 指定 `IP`/`端口`/`接口` 以及反向指定（使用 `!`）

`Firewall-HOWTO` 和 `man <command>`（`ipchains` 或 `ipfwadm`）页面非常详细地涵盖了设置规则的机制，但并没有真正涵盖防火墙安全的策略。你的首要选择是采用“默认允许”还是“拒绝所有”策略，然后是你希望允许和阻止的哪些和服务和主机。

当你做决定时，你会选择一个默认拒绝所有内容（除非显式允许）的策略（也就是说，如果发生故障，希望可以通过默认策略将其降至最低），或者一个允许和阻止某些服务/主机的策略。我通常使用默认拒绝的策略，因为它可以容错错误，并且比允许数据通过的策略更安全。例如，如果你有一个通过防火墙保护的服务器，目前运行着 `apache`，你在凌晨 3 点为其内部使用安装了 `WU-FTPD`（这样人们就可以上传文件），但你忘记了更改防火墙规则。如果你选择了默认允许的策略，那么互联网上的任何人都可以访问该 `ftp` 服务器，而你又蠢地安装了一个旧版本，导致某人攻破了这台机器。另一方面，如果你采用默认拒绝的策略，他们将无法访问 `ftp` 服务器，也不会通知你的用户，但你很快就会发现问题。

我决定在这一节中不涵盖具体的防火墙规则，对于每个网络服务，我将提供示例，因为要正确地对协议进行防火墙处理，你需要了解它的行为。例如，对 `web` 和 `ftp` 的入站和出站访问进行防火墙处理有巨大的差异。一些通用概念/规则：

## IPFWADM

`ipfwwadam` 是 `Linux` 下一个稳健的数据包过滤器，尽管它缺乏 `Ipchains` 中提供的许多功能。它只支持数据包的 `Target`：接受（`accept`）、拒绝（`deny`）或拒绝（`reject`），而 `ipchains` 规则可以针对 6 个内置单元或用户定义的目标。`ipfwwadam` 实际上仅适用于 `IP` 级防火墙、`IP` 伪装以及如果你计划使用 `FreeSW`（目前不支持内核 `2.2.x`）。基本选项是：指定方向（入站或出站，带上接口标志）、输入规则、输出规则、规则（你可能有多个接口，也涵盖了伪装规则）以及控制超时的伪装规则。你可以插入、追加和删除规则，设置默认策略并列出所有规则，与 `ipchains` 不同，你只有 3 个目标（`ACCEPT`, `DENY`, `REJECT`）。除此外它与 `ipchains` 非常相似，只有细微差异。以下是一个适用于桥接两个网络（`eth0` 上的 `10.0.0.x`，`eth1` 上的 `10.0.0.1` 和 `192.168.0.1`）且运行有邮件服务器的脚本。

```bash
```



#!/bin/bash

### 首先刷新所有规则集

`ipfwadam -I`

`ipfwadam -f -O`

`ipfwadam -F`

### 允许两个网络之间的转发，出于安全考虑其他拒绝

```bash
ipfwadam -F -a accept -P all -S 10.0.0.0/24 -i eth0 -D 192.168.0/24
ipfwadam -F -a accept -P all -S 192.168.0/24 -i eth1 -D 10.0.0.0/24
ipfwadam -F -P deny
```

### 当然，我们必须允许这些数据包进入

```bash
ipfwadam -I -a accept -P tcp -S 10.0.0.0/24 -i eth0 -D 192.168.0/24
ipfwadam -I -a accept -P tcp -S 192.168.0/24 -i eth1 -D 10.0.0.0/24
ipfwadam -I -P deny
```

### 让他们访问服务器上的邮件服务器，但什么都不能访问

```bash
ipfwadam -I -a accept -P tcp -S 10.0.0.0/24 -i eth0 -D 192.168.0/24
ipfwadam -I -a accept -P tcp -S 192.168.0/24 -i eth1 -D 10.0.0.0/24
```

## IPchains

`ipchains` 有一些新功能，你可以创建规则链（因此得名）并将它们链接起来，使得防火墙的管理更加简单。`ipchains` 支持比 `iptables` 更多的目标，你可以规则指向 `ACCEPT`、`DENY`、`REJECT` 或 `RETURN`。这种方式非常强大，你可以重定向 80 端口的数据包，并结合服务质量（QoS）路由，`ipchains` 给出的示例中流量优先级高于 ftp，这减少了由拥塞链路引起的延迟问题。以下脚本适用于具有 2 个接口的网关，我使用 `DENY` 而不是 `REJECT` 的原因是数据包会被直接丢弃且不予响应，这会减慢扫描。`ipchains` 适用于具有 2 个接口的服务器，如果你计划使用它，需要设置防火墙规则。我们假设所有机器都与网关通信。

## 扫描 / 入侵测试工具

在过去的几年里，Windows 和 UNIX 安全工具的数量大幅增加，更令人惊讶的是，其中大多数在互联网上都是免费提供的。我将只介绍免费工具，因为大多数商业工具价格极其昂贵，不是开源的，在许多情况下被证明包含重大的安全漏洞（例如在安装后以明文存储密码）。如果任何严重的破解者/黑客都有这些工具可用，为什么你不能用呢？

工具分为几个大类：那些从主机内部进行扫描的工具、一种扫描其他主机并报告它们运行什么操作系统的工具（使用一种名为 TCP-IP 指纹识别的技术）、可用的服务等；在食物链顶端的是入侵工具，它们实际上会尝试执行漏洞利用，并报告执行是否成功；最后我包含了漏洞利用（exploits）类别，虽然它们严格来说本身不是入侵工具，但它们确实存在，你应该关注它们。

`NFR`（网络飞行记录器）远不止是一个数据包嗅探器，它实际上会记录数据并实时检测攻击、扫描等。这是一个非常强大的工具，需要投入大量的时间、精力和机器性能来运行，但它是检测领域中的顶端工具。`NFR` 位于：http://www.nfr.com。

## 主机监控工具

监控你的服务器和主机对于各种原因都非常重要，从追踪入侵到法律要求比应皆有。记住，防患胜于治疗。在“日志（Logging）”部分有多种监控工具可用，从 `syslog` 到 `audit`（允许你审计用户文件、运行的程序等）。我强烈建议你使用它们。因为还有许多特定的程序可以监控系统状态并防止用户做他们不该做的事。

### bgcheck

`bgcheck` 在后台运行并检查进程表以查找应该运行的项目（例如 irc 机器人、密码破解器等）。你可以从这里下载：http://blue.dhs.org/bgcheck/。

### Sxid

`Sxid` 检查 setuid 和 setgid 的变化，生成文件的 MD5 签名，并通常允许你跟踪所做的任何更改。你可以在这里获取：ftp://marcus.seva.net/pub/sxid/

### Viperdb

`Viperdb` 检查 setuid/setgid 程序和文件夹，并在发生任何更改时通知你，同时限制对它们的访问，它可以从这里处下载：http://www.resent.org/projects/viperdb/。

### Pikt

`Pikt` 在上一节中介绍过，可以用于监控用户活动。我向大型安装推荐它，因为它非常灵活且强大。`Pikt` 位于：http://pikt.uchicago.edu/pikt/

### DTK

欺骗工具包（Deception ToolKit）是一组程序，模拟已知服务以便向攻击者提供一组虚假的读数。其希望通过引导他们得出错误的结论来迷惑并减缓攻击者，你可以从这里下载 `DTK`：http://all.net/dtk/

## 数据包嗅探器

数据包嗅探是捕获并非指向你机器的网络数据的行为，通常用于查看机密/敏感流量，例如 telnet 会话或人们阅读电子邮件。遗憾的是，没有真正的方法可以检测数据包嗅探器，因为它是一种被动活动；但通过利用网络交换机和光纤骨干（这些很难被接管），你可以最大限度地减少威胁。

### tcpdump

Linux 数据包嗅探器的鼻祖，这个工具自我记忆中以来就一直存在了，主要用于调试网络问题。它并不易于配置，缺乏较新数据包嗅探器的高级功能，但它可以很有用。大多数分发版都自带了 `tcpdump`。

### sniffit

我最喜欢的数据包嗅探器，`sniffit` 非常健壮，具有良好的过滤功能，可以将数据有效负载转换为 ASCII 文本以供阅读（如 telnet 会话），甚至有一个图形模式（非常适合监控整体活动/连接）。`Sniffit` 位于：http://sniffit.rug.ac.be/sniffit/sniffit.html。

### Ethereal

一个外观良好的网络协议分析器（又称为增强版嗅探器），它的界面与 NT 的网络监视器非常相似，并且始终便于查看。`Ethereal` 位于：http://www.wireshark.org/（注：现在改名为 Wireshark）。

## 病毒/蠕虫/木马的消毒

备份你的数据，格式化并从已知的介质重新安装系统。一旦攻击者获取了 Linux 系统的 root 权限，他们字面上可以做任何事情，从破坏 `gcc/egcs` 到在启动时加载增加的内核模块。不要以 root 身份运行不可信软件。检查你下载文件的 PGP 签名等。稍防未缪就可以很大程度上阻止 Linux 下病毒、蠕虫和木马的传播。

处理病毒及病毒的最简单方法是使用系统完整性工具，如 `tripwire`、`L5` 和 `Gog&Magog`，你可以轻松地找到哪些文件被破坏，并对其进行恢复/替换/更新。

## 病毒扫描器

如上述，病毒在 Linux 世界并不是真正的关注，但运行在 Linux 上的病毒扫描器是有用的。在网络网关处过滤电子邮件或其他形式的内容可以提供额外的强力防御，因为提供防御威胁的平台不会被该威胁本身破解。

## AMaViS

## 密码存储

这是许多人没有考虑过的问题。如何安全地存储密码？最明显的方法是记住它们，但这样做有缺点，如果你管理 30 个不同的网站，你通常想要 30 个不同的密码，而一个好的密码长度在 8 个字符以上，通常不是最容易记忆的。这导致许多人在多个系统中使用相同的密码（来吧，承认吧）。最简单的方法之一是将密码写下来，这是**大忌忌**，当人们发现到处乱丢时，以及他们在寻找时发现了什么，你会感到惊讶。更好的选项是以加密格式存储密码，通常以电子形式存储在你的计算机或掌电脑上，这样你只需要记住一个密码来解锁其他密码。可以使用像 `PGP` 或 `GnuPG` 这样简单的工具来实现这一点。

# Gpasman

`Gpasman` 是一个需要 `gtk`（在非 Gnome 系统上相对容易安装，只需加载 `gtk` 库）的应用程序，并使用 `rc2` 算法加密你的密码。程序启动时输入主密码，假设它是正确的，你将看到一个漂亮的用户账户、网站、密码和注释字段列表。`Gpasman` 的地址为：http://www.student.wau.nl/~olivier/gpasman/

# 执行基准/系统完整性

许多人在保护机器安全时的一个重大疏忽是忘记创建系统基准，基准是系统在正常运行时的配置、资源使用情况等。例如，简单的 `netstat -n > netstat-output` 就可以为你提供一个参考，以便稍后检查是否有不该开启的端口。内存使用和磁盘使用也是需要关注的事项，内存使用的的突然激增可能导致系统资源匮乏，磁盘使用也是如此，这可能是错误、恶意用户或已经入侵你的系统并正在扫描其他人的蠕虫程序。存在多种工具来测量内存和磁盘使用：`vmstat`、`free`、`df`、`du`，它们都由各自的涵盖。

至少要进行全系统备份，并定期备份配置文件和日志，当你准确定位发生了入侵时（例如用户账户 "rewrt" 在第 4 次备份后被添加，而该账户不在 3 月 20 日的备份中），这也能对你有帮助。一旦系统被破解，就会安装“根内核包”（rootkit），这些被木马化的二进制文件几乎不可能安全地删除，你最好格式化磁盘并从头开始。这条规则当然没有例外，如果你勤快并使用了如 `L5` 这样的文件/目录完整性工具，你就能轻松定位受影响的文件并处理它们。

### Tripwire

`Tripwire` 不再是源码工具，我完全不反对商业软件，但当我依靠一个程序来提供安全时，如果我（或任何人）无法轻松查看源码（它根据某些特殊协议提供，可能是 NDA），我必须拒绝。`Tripwire` 在 Linux 上大约花费 70 美元，并且仅以 RPM 包的形式提供（其他操作系统上为 500 美元），对于一个可以被 `L5` 等替代方案替换的软件来说，这个价格偏高。`Tripwire` 地址：http://www.tripwiresecurity.com。

`Gog&Magog` 创建系统文件属性、所有者、权限、文件的 MD5 签名等。你可以让它自动对比，并确保任何更改的文件都能引起你的注意。这从入侵中恢复也变得简单，因为你会知道哪些文件被破坏了。你可以从此处下载 `Gog&Magog`：http://www.multimania.com/cparisel/gog/

## 互联网连接检查清单

以下是为连接互联网的人员（PPP、DSL、电缆调制解调器等）准备的清单。虽然内容详尽，但应该有所帮助。

关闭所有不必要的守护进程和网络软件——除非你计划使用，否则禁用 telnet, ftp, rsh, auth, pop, imap 等。如果已关闭，风险会小得多。

尽可能使用 `ipfwadm/ipchains` 为服务设置防火墙，如果你默认开启了防火墙，这将极大地减少人们在你的机器上执行的扫描。通常情况下，NFS / Samba、imap 和 pop 等服务仅需要内部用户访问，阻止外部访问将极大地简化问题。

使用 `TCP_WRAPPERS` 来保护你留下的服务，在可能的情况下将 imap、pop 和 ftp 等服务的访问限制在内部或特定的互联网客户端。请记住，大多数发行版随带的 nfs 均配置了 `TCP_WRAPPERS`，且 SSH 也可以使用 `TCP_WRAPPERS`。这允许你轻松地集中对服务的访问控制。

将所有软件（特别是网络软件）更新到最新版本，检查适用于你发行版的错误列表 - 安全页面。

使用如 `AIDE` 或 `Gog&Magog` 等系统完整性工具来建立你当前（已知良好的）文件的列表和签名。如果你以后被黑客入侵了，这将让你的工作变得更轻松。

从外部站点运行渗透测试，即针对你的机器运行 `nmap / strobe, nessus` 类似的工具，以确保它被妥善锁住。记住，坏人拥有这些工具，所以你也应该使用它们。

保持软件 / 访问列表更新。定期使用 `logcheck` 等工具审计日志文件。如果可能，使用 `AIDE` 等工具监控并防止系统问题（例如，大量的邮件）。启用内核审计。确保你有足够的磁盘空间。
