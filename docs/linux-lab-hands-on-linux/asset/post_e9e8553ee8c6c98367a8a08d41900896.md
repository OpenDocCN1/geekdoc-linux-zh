**CONCEPTS**
The Linux kernel is the core of the Linux operating system. The Linux kernel is used by serial of Unix-like operating systems. It is the first part of the operating system which is loaded into memory during booting (system startup), and it remains there until the session is expired, because its services are required to work with the Linux. GRUB is the default GNU boot loader, which comes with Linux. This boot loader resides on your system hard disk and starts Linux when you start your PC. It is the first thing that appears after the booting of your computer.

## Understanding Kernel Concepts

- Kernel types: Monolithic versus modular
- Reasons to build a new kernel
- Reasons not to build a new kernel

A monolithic kernel is one in which support for all hardware, network protocols, and file systems is built within a single file.

A modular kernel is the standard for most distributions, because they allow a kernel to run on wide variety of hardware.

Systems with monolithic kernels may boot faster than the systems with modular kernels. It uses constant amount of memory (RAM).

In modular kernels, modules are loaded on demand, so they are memory efficient.

Following are the reasons to build a new kernel:

- To optimize as a router, not a host
- To reconfigure the page size to change the allocation of memory addresses between kernel and user space

To change the kernel operating parameters that are not configurable at boot time.

### Modular Kernel Components

Many components of the kernel can be compiled as dynamically modules. This increases kernel functionality without increasing the size of the kernel loaded at boot time. Good candidates for modularization are any supplementary capabilities that are not needed at boot time, including peripheral device drivers and supplementary file systems.

### The /lib/modules directory

Kernel modules reside in **/lib/modules/(kernel-version)**, which in turn contains various subdirectories according to the module type, such as *block*, *cdrom*, *net*, and *scsi*. The directory name must match the kernel version. Type the following commands in the command line to display the release number:

```
uname -r or uname -a
```

### Controlling Modules

Modules are generally loaded on demand by the kernel. *lsmod* lists the modules currently resident in the kernel. The kernel can be prompted to load a particular module with *insmod*, and various module parameters can be specified as command line arguments. *rmmod* module is used to unload a module if it is idle.

To list the modules, run the following command

```
[root@netmon opt] # lsmod
```

To load a particular module

```
[root@netmon opt] # insmod e100-k0
```

To unload module

```
[root@netmon opt] # rmmod e100
```

To get module information:

```
[root@netmon opt] # modinfo e100
```

## Controlling Modules Intelligently

Many modules depend on other modules to be present. A database of module dependencies can be generated with depmod command. This command seldom needs to be run manually, because the default rc.sysinit script is configured to run the command at system boot. The modprobe command can be used to load kernel modules, with three improvement over insmod listed as follows:

- modprobe loads any underlying modules required by a given module
- modprobe consults /etc/conf.modules for default module parameters
- modprobe can try list of modules, and when it loads a module successfully, it will cease trying other list

## Kernel Version Naming Conventions

Kernels are generally referred to by major version number, minor version number, and patch level.

Type the following command in the command line to display the Linux Kernel release number:

```
uname -r or uname -a
```

As you type the preceding command in the command line and press the ENTER key, the kernel release number is displayed as follows:
2.6.26-10
2.6.26.x even-numbered minor-versions imply that the kernel is a part of the stable development branch.
2.3.x odd-numbered minor versions imply that the kernel is development.

## Kernel RPMs

- kernel-version.i386.rpm: Represents the precompiled kernel and modules
- kernel-source-version.i386.rpm: Represents the kernel source (less headers and SMP-related code) needed to build Red Hat’s standard kernel for x86 platform, installed into /usr/src/linux
- kernel-version.src.rpm: Represents the kernel sources

## Required RPMs for Compilation

## Quick Kernel Compilation Steps

Following are the steps for kernel compilation:
1. Make sure that you have the packages that are needed to build the kernel.
Type the following commands to check the packages:

```
rpm -qa | grep binutils\*
rpm -qa | grep gcc-2\*"
```

```
rpm -qa | grep kernel-headers*
rpm -qa | grep kernel-source*
rpm -qa | grep dev86*
rpm -qa | grep make-*
rpm -qa | grep glibc-devel*
rpm -qa | grep gcc*
rpm -qa | grep cpp*
rpm -qa | grep ncurses-devel*
```

In case some of the packages are not installed, mount Red Hat Linux distribution CDs and from RPMS directory install required packages.
Use the following command to install required package that are not installed by using the preceding commands:

- 1. rpm -Uh /mnt/cdrom/RedHat/RPMS/kernel-headers*
- 2. Use cat command to familiarize yourself with system’s hardware by examining /proc/cpuinfo, /proc/pci, /etc/modules.conf, /proc/scsi/*.
- 3. Edit the top-level Makefile ( under /usr/src/linux-2.*) Change
  EXTRAVERSION=-22
  to
  EXTRAVERSION=-22r1
  Your kernel now installs the modules in a separate directory than the kernel that came with Red Hat Linux. Using Red Hat’s EXTRAVERSION as the beginning of your help, make it clear, which source you use to build the custom kernel.
- 4. Determine the appropriate processor generation

```
cd /usr/src/linux
cp -p config/kernel-2.6.26.x.i386.config arch/i386/defconfig
make mrproper
make oldconfig
```

- 5. See what each of the following kernel compilation approaches look like by giving the following command:

```
# cd /usr/src/linux
# make xconfig (obviously, you must be in an x session for this work)
or # make menuconfig (text, graphical mode)
or # make config (text mode)
```

When choosing kernel options, take into consideration the specific hardware on your system and need for protocols and services. The following are some general guidelines that help you to choose kernel options:

- Under “Code Maturity Level options”, check “Prompt for development and/or incomplete code/drivers”. If you fail to check these options, certain essential services (most probably nfsd) may fail to work correctly.
- Optimize for your processor family, and turn the math emulation support off.
- Modularize all the possible hardware support.
- Turn off the ISDN and IrDA support for old CD-ROM drivers.
