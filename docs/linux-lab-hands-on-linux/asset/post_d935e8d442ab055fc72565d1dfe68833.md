## Configuring nfs on the Server

Both the NFS server and client have to have parts of the NFS package installed and running. The server needs portmap, nfs, and nfslock, as well as a correctly configured /etc/exports file.

### The /etc/exports File

The /etc/exports file is the main NFS configuration file that consists of two columns. The first column lists the directories you want to make available to the network, whereas the second column has two parts. The first part lists the networks or DNS domains that can get access to the directory, and the second part lists NFS options in brackets.

/etc/exports
/data/files *(ro, sync)
/home 172.16.1.0/24(rw, sync)
/distro/rhel5 172.16.1.200/32(rw, sync)

After configuring your /etc/exports file, you need to activate the settings, but first make sure that NFS is running correctly.

The following points help you to configure an NFS server:

- Use the chkconfig command to configure the required nfs and RPC portmap daemons to start at boot. Following is the syntax to use chkconfig command:

[root@netmon tmp]# chkconfig --level 35 nfs on
[root@netmon tmp]# chkconfig --level 35 nfslock on
[root@netmon tmp]# chkconfig --level 35 portmap on

- Use the init scripts in the /etc/init.d directory to start the nfs and RPC portmap daemons. The following examples use the start option, but when needed, you can also stop and restart the processes with the stop and restart options.

[root@netmon tmp]# service portmap start
[root@netmon tmp]# service nfs start
[root@netmon tmp]# service nfslock start

- Test whether NFS is running correctly with the rpcinfo command. You should get a listing of running RPC programs that must include mountd, portmapper, nfs, and nlockmgr.

The syntax for testing NFS by using the rpcinfo command:

[root@netmon tmp]# rpcinfo -p localhost
[root@netmon tmp]#

## Configuring NFS on the client

To configure NFS on the client first you need to start the NFS application, then create a directory to mount the directories of the NFS server that you exported via the /etc/exports file, and finally mount the directory of the NFS server on your local directory, or mount point.

### Starting NFS on the Client

The following steps help you to configure NFS on the client:

- Use the chkconfig command to configure the required NFS and RPC portmap daemons to start at boot. Activate nfslock to lock the files and reduce the risk of corrupted data. The syntax to use the chkconfig command is as follows:

[root@netex tmp]# chkconfig --level 35 netfs on
[root@netex tmp]# chkconfig --level 35 nfslock on
[root@netex tmp]# chkconfig --level 35 portmap on

- Use the init scripts in the /etc/init.d directory to start the NFS and RPC portmap daemons. As on the server, the examples use the start option, but you can also stop and restart the processes with the stop and restart options. The syntax to start NFS and RPC portmap daemons is as follows:

[root@netex tmp]# service portmap start
[root@netex tmp]# service netfs start
[root@netex tmp]# service nfslock start

- Test whether NFS is running correctly with the rpcinfo command. The listing of running RPC programs must include status, portmapper, and nlockmgr commands.

[root@netex root]# rpcinfo -p
[root@netex root]#

### Manually Mounting NFS File Systems

It is a manual process. In this case, you're mounting the /distro/rhel5 directory as an NFS-type file system on the /mnt/nfs mount point. The NFS server is Netmon whose IP address is 172.16.1.100.

The syntax to mount NFS file systems manually is as follows:

[root@netex tmp]# mkdir /mnt/nfs
[root@netex tmp]# ls /mnt/nfs
[root@netex tmp]# mount -t nfs 172.16.1.100:/distro/rhel5 /mnt/nfs

[root@netx tmp]# ls /mnt/nfs
[root@netx tmp]#

### Making NFS Mounting Permanent

If you want NFS directories to be permanently mounted, make an entry in the /etc/fstab file in addition to the creation of the mount point directory.

- **The /etc/fstab File**

The /etc/fstab file lists all the partitions that need to be auto-mounted when the system boots. Therefore, you need to edit the /etc/fstab file if you need the NFS directory to be made permanently available to users on the NFS. For the example, mount the /data/files directory on server Netmon (IP address 172.16.1.100) as an NFS-type filesystem using the local /mnt/nfs mount.

| #/etc/fstab | Directory Mount Point | Type | Options | Dump | fsck |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 172.16.1.100:/distro/rhel5 | /mnt/nfs | nfs | soft,nfsvers=2 | 0 | 0 |

- **Permanently Mounting the NFS Directory**

You first learn to create a mount point directory, /mnt/nfs, to mount the remote NFS directory and then learn to use the mount -a command to activate the mount.

The syntax to create a mount point directory, to mount the remote NFS directory, to activate the mount is as follows:

[root@netx tmp]# mkdir /mnt/nfs
[root@netx tmp]# ls /mnt/nfs
[root@netx tmp]# mount -a
[root@netx tmp]# ls /mnt/nfs
[root@netx tmp]#

Each time your system boots, it reads the /etc/fstab file and executes the mount -a command, thereby making this a permanent NFS mount.

### Testing NFS

Use the following commands to test NFS:

**The showmount Command**

When run on the server, the showmount -a command lists all the currently exported directories. It also shows a list of NFS clients accessing the server.

The syntax to list all the directories is as follows:

[root@netmon tmp]# showmount -a
[root@netmon tmp]#

**The df Command**

The df command lists the disk usage of a mounted file system. Run it on the NFS client to verify that NFS mounting has occurred. In many cases, the root_squash mount option prevents the root user from doing this. Therefore, it is best to try it as an unprivileged user.

The syntax to use df command is as follows:

[root@netx tmp]$ df -F nfs
[root@netx tmp]$

**The nfsstat Command**

The nfsstat command provides useful error statistics. The -s option provides NFS server stats, while the -c option provides them for clients.
