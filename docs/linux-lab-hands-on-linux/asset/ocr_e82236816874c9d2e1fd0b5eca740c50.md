```
$ echo $(( 1 && 1 ))
1
```

Yes. Just as you would expect. So do be on guard against this shell "gotcha", which only affects the outcome of tests and command result values. It probably will not surprise you to learn that no one mentions this strange anomaly in the offical Bash documentation.

# ■ **A Couple of Rules about Logical Operators Used as Branches**

+   □ If you write "test && command", the command will only be executed if the test succeeds.
+   □ If you write "test || command", the command will only be executed if the test fails.
+   Run these tests:

```
$ true && echo "Yes."
Yes.
$ false || echo "Yes."
Yes.
```

The output for the above test is entirely based on logical comparison.
The following is another scheme commonly seen in shell script programming and interactive sessions:

```
$ command1 && command2 && command3 && command4
```

This line of code will not run the next command in the sequence unless the prior command has returned "true", meaning no errors. It is a way to avoid running a command if a required prior outcome is not present.

# ## Loops and Repetition

+   □ Here are some examples of loop operators:

```
for fn in *; do
echo "$fn"
done
```

In this example, the "*" is expanded by the shell to a list of all the files in the current directory, then each filename is applied to the loop control area.

```
for fn in tom dick harry; do
echo "$fn"
done
```

```
$ ./myscript.sh
tom
dick
harry
```
