
## Configuration Files of FTP Server (vsftpd daemon)

The examples of configuration files are as follows:

- Package: vsftpd
- Daemon: /usr/sbin/vsftpd
- Script: /etc/init.d/vsftpd
- Configuration: /etc/vsftpd/vsftpd.conf, /etc/vsftpd.ftpusers, /etc/pam.d/vsftpd
- Log: /var/log/xferlog

## Steps to Install and Configure the FTP Server

Perform the following steps to install and configure the FTP server (vsftpd daemon):

### Installing the VSFTPD Daemon

Search for the file with the .rpm extension (Check with Linux distribution CD or DVD).

Type the following command to install the FTP server:

```
[root@netmon tmp]# rpm -ivh vsftpd-1.5.6-i386.rpm
```

### Starting the VSFTPD Daemon

Use the following commands to start, stop, and restart VSFTPD after booting:

```
[root@netmon tmp]# service vsftpd start
[root@netmon tmp]# service vsftpd stop
[root@netmon tmp]# service vsftpd restart
```

Use the following chkconfig command to start VSFTPD at boot time.

```
[root@netmon tmp]# chkconfig --level 345 vsftpd on
```

### Testing the Status of VSFTPD

You can always test whether the VSFTPD process is running by using the netstat command, which lists all the TCP and UDP ports on which the server is listening for traffic. The succeeding example shows the following output:

```
[root@netmon root]# netstat -a | grep ftp | grep tcp:21
```

### Edit the vsftpd.conf file

The vsftpd.conf file uses a number of default settings that you need to know.

The configuration file is fairly straightforward as you can see in the code snippet:

```
# Allow anonymous FTP?
anonymous_enable=YES
# Uncomment this to allow local users to log in.
local_enable=YES
# Uncomment this to enable any form of FTP write command.
# (Needed even if you want local users to be able to upload files)
write_enable=YES
# Uncomment this to allow the anonymous FTP user to upload files. This only
# has an effect if global write enable is activated. Also, you will
# obviously need to create a directory writable by the FTP user.
anon_upload_enable=YES
# Uncomment this if you want the anonymous FTP user to be able to create
# new directories.
anon_mkdir_write_enable=YES
# Activate logging of uploads/downloads.
xferlog_enable=YES
# You may override where the log file goes if you like.
# The default is shown below.
xferlog_file=/var/log/vsftpd.log
# The directory which vsftpd will try to change
# into after an anonymous login. (Default = /var/ftp)
anon_root=/data/directory
```

To activate or deactivate a feature, remove or add the # at the beginning of the appropriate line. Descriptions on this and more can be found in the vsftpd.conf man (manual) pages.

The following points explain the configuration of VSFTPD:

- **VSFTPD runs as an anonymous FTP server:** By default Anonymous FTP Services is always on. You can set the configuration file's anonymous_enable directive to no to disable this feature. You'll also need to simultaneously enable local users to be able to log in by removing the comment symbol (#) before the local_enable instruction.

- **VSFTPD allows only anonymous FTP downloads to remote users, not uploads from them:** You can change this by modifying the anon_upload_enable directive shown above.

- **VSFTPD doesn't allow anonymous users to create directories on your FTP server:** You can change this by modifying the anon_mkdir_write_enable directive.

- **VSFTPD logs FTP access to the /var/log/vsftpd.log log file:** You can change this by modifying the xferlog_file directive.

### Change FTP Greeting Banner

Change the default greeting banner in the vsftpd.conf file to make it harder for malicious users to determine the type of system you have. The directive in this file is:

```
ftpd_banner=Welcome to S.P.I.T. FTP site
```

### Using Anonymous Access

The following steps are performed to use anonymous access of FTP server:

1. Check for the presence of a test file on the FTP client.

   Type the following command to check the presence of test file on the FTP client:

   ```
   [root@netx tmp]# ll
   total 1

   [root@netx tmp]#
   ```

### Troubleshooting FTP

1. Initial setup failures could be caused by firewalls along the path between the client and server blocking some or all types of FTP traffic. To disable default setting of firewall run the following command:

   ```
   [root@netmon tmp]# iptables -F
   ```

   > *Iptables* is Linux firewall module, we can use it to specify firewall rules. *iptables -F* flushes all the firewall rules. Refer Appendix for more information on iptables.

2. There is a possibility that you may not get access to ftp server due to SELinux policy.

   To disable SELinux ftp policy, run the following command:

   ```
   [root@netmon tmp]# setsebool -P ftpd_disable_trans 1
   ```

   **Security** Enhanced Linux (SELinux) enhancements developed by the US Federal National Security Agency (NSA) are included with Fedora Core beginning with version 3 and Red Hat Enterprise Linux version 4. The fine-grained access control architecture is supported in the Linux kernel. Both *type* enforcement and **Role Based Access Control (RBAC)** are supported. System processes and files (including socket descriptors, IPCs, devices, ...) are each assigned a collection of security attributes known as a *security context*. Refer appendix for more information on Selinux.

### Adding FTP Users with Read-Only Access to a Shared Directory

This example is for when anonymous FTP is not desired and ftp access needs to be provided to the group of trusted users with read-only access to shared directory.

Perform the following steps to add FTP users with read-only access to a shared directory:

- Disable anonymous FTP

  ```
  # Allow anonymous FTP?
  # anonymous_enable=YES
  ```

- Enable individual logins

  ```
  # uncomment this to allow local users to log in.
  local_enable=YES
  ```

  After modifying `/etc/vsftpd.conf` as above mentioned steps, start VSFTPD.

  ```
  [root@netmon tmp]# service vsftpd start
  ```

- Create a user group and shared directory. In this case, use `/home/share-docs` and a user group name of share-resource for the remote users.

  ```
  [root@netmon tmp]# groupadd share-resource
  [root@netmon tmp]# mkdir /home/share-docs
  ```

- Make the directory accessible to the share-resource group.

  ```
  [root@netmon tmp]# chmod 750 /home/share-docs
  [root@netmon tmp]# chown root:share-resource /home/share-docs
  ```

- Add users, and make their default directory `/home/share-docs`.

  ```
  [root@netmon tmp]# useradd -g share-resource -d /home/share-docs aday
  ```

- Copy files to be downloaded by your users into the `/home/share-docs` directory.

- Change the permissions of the files in the `/home/share-docs` directory to read-only access by the group.

  ```
  [root@netmon tmp]# chown root:share-resource /home/share-docs/*
  [root@netmon tmp]# chmod 740 /home/share-docs/*
  ```

Users should now be able to log on via FTP to the server using their new usernames and passwords. If you absolutely do not want any FTP users to be able to write to any directory, then you should set the write_enable line in your vsftpd.conf file to no:

```
write_enable = NO
```

It is important to note that you must restart VSFTPD to ensure that changes made in configuration file have taken place.

```
[root@netmon tmp]# service vsftpd restart
```
