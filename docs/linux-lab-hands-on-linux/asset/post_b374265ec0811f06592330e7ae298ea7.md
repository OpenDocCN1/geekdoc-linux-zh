In Fedora Linux you are required to manually install the Telnet server.

Remember that the TELNET server RPM’s filename usually starts with telnet-server followed by a version number. For example:


### Setting Up a TELNET Server

Telnet is xinetd managed service. Xinetd is called Internet super server daemon. It is launched at boot time, and listens for connection on network sockets. When xinetd starts up, it checks the xinetd.conf file to see what services should be running. It then reads the /etc/services file to see what ports those services should be running on. After xinetd starts, if there is a connection made on a service port listed (in our case TELNET) in xinetd.conf, xinetd then launches the appropriate network service. So telnet is not standalone service but handle by xinetd daemon.

### Xinetd-Managed Server Services

Xinetd-managed services store their configuration files in the /etc/xinetd.d directory. Each configuration file has a disable statement (as shown in following code) that you can set to yes or no. This governs whether xinetd is allowed to start them or not.

Edit following file (/etc/xinetd.d/telnet) and make disable=no

```
# xinetd-managed service
# default: on
# description: The telnet server serves telnet sessions; it uses \n# unencrypted username/password pairs for authentication
service telnet
{
    flags = REUSE
    socket_type = stream
    wait = no
    user = root
    server = /usr/sbin/in.telnetd
    log_on_failure + = USERID
    disable = yes
}
```

To activate the telnet service we have to actually start xinetd services as telnet is not standalone but managed by xinetd daemon.

```
[root@netmon tmp]# service xinetd restart
```

You can test whether or not the TELNET process is running by using the netstat command.

The netstat command checks the TCP/UDP on which your server is listening. If the TELNET process is not running then the server will not respond. The syntax to use the netstat command is as follows:

```
[root@netmon tmp]# netstat -a | grep telnet
tcp 0 0 *:telnet *:* LISTEN
[root@netmon tmp]#
```

You can also use the chkconfig --list command to start TELNET on the next reboot. The syntax to use the chkconfig --list command is as follows:

```
[root@netmon tmp]# chkconfig --list | grep telnet
telnet: on
[root@netmon tmp]#
```

### Stopping a TELNET Server at Boot Time

You can deactivate TELNET even after the next reboot by using the chkconfig command. The syntax to use the chkconfig command is as follows:

```
[root@netmon tmp]# chkconfig --level 35 telnet off
```

### Let TELNET Allow Connections from Trusted Addresses

1. Add a list of trusted servers to the /etc/xinetd.d/telnet file separated by spaces:
   ```
   # default: on
   # description: The telnet server serves telnet sessions
   # unencrypted username/password pairs for authentication.
   service telnet
   {
       flags = REUSE
       socket_type = stream
       wait = no
       user = root
       server = /usr/sbin/in.telnetd
       log_on_failure += USERID
       disable = no
       only_from = 172.16.1.100 127.0.0.1
   }
   ```

This is the entire process to allow connections from trusted addresses. Let’s perform the following commands to restart TELNET.

2. Restart TELNET by using the following command:
   ```
   [root@netmon tmp]# chkconfig --level 35 telnet off
   [root@netmon tmp]# chkconfig --level 35 telnet on
   ```

3. Test the TELNET session. Clients that are not on the trusted list get the message “Connection closed by foreign host.”

```
[root@netx tmp]# telnet 172.16.1.100
Trying 172.16.1.100...
Connected to 172.16.1.100.
Escape character is '^]'.
Connection closed by foreign host.
[root@netx tmp]#
```

## Securing Remote Logins with OpenSSH

You can access a shell remotely on most of the Linux/Unix systems by using various ways. One of the ways is to use the telnet program that is available on most network capable operating systems. OpenSSH is an application, developed for OpenBSD, that uses the SSH protocol to provide secure remote logins and an interactive command interface. A secure remote login application, OpenSSH, was ported to the XTS-400 in order to provide remote login capabilities. SSH is designed and created to provide the best security when you access another computer remotely. It not only encrypts the session but also provides better authentication facilities and features, such as X session forwarding, port forwarding as well as it also increase the security of other protocols. It can use different forms of encryption ranging anywhere from 512 bit to as high as 32768 bits and includes ciphers, such as Advanced Encryption Scheme ( AES ), Triple DES, Blowfish, CAST128, or Arctour. The higher the bits, the longer it takes to generate and use keys as well as to pass data over the connection. ## Configuring the SSH Server

OpenSSH uses a server-client relationship. The system to which you connect is known as a *server* and the system *requesting* the connection is known as a *client*. A system can be both an SSH server and a client.

### Starting Openssh

OpenSSH is installed by default during Linux installations. You can run the following commands to check whether the SSH programs are installed

```
[root@netmon tmp]# rpm -qa |grep ssh
Or
[root@netmon tmp]# rpm -qa |grep openssh
```

You can start SSH at boot time by using the chkconfig command. The syntax to use the chkconfig command is as follows:

```
[root@netmon tmp]# chkconfig -level 35 sshd on
```

You can also start, stop, and restart SSH after booting by running the sshd initialization script. The syntax to start, stop, and restart SSH after booting is as follows:

```
[root@netmon tmp]# service sshd start
[root@netmon tmp]# service sshd stop
[root@netmon tmp]# service sshd restart
```

It is important to note that you should restart the SSH process every time you make a change to the configuration files to make the changes effective on the running process.
