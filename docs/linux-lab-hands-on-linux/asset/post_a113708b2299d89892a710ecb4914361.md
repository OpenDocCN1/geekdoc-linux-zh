
## Set NIC’s Speed Configuration with ethtool

Unlike mii-tool, ethtool settings can be permanently set as a part of the interface configuration script with the ETHTOOL_OPTS variable. In our next example, the settings will be set to 100Mbps, full duplex with no chance for autonegotiation on the next reboot:

```
#
# File: /etc/sysconfig/network-scripts/ifcfg-eth0
#
DEVICE=eth0
IPADDR=192.168.1.100
NETMASK=255.255.0.0
BOOTPROTO=static
ONBOOT=yes
ETHTOOL_OPTS="speed 100 duplex full autoneg off"
```

The ethtool settings can also be changed from the command line by using the -s switch followed by the interface name and its desired configuration parameters, as shown below:

```
[root@netmon tmp]# ethtool -s eth1 speed 100 duplex full autoneg off
```

## Hostname Configuration

### Configuring the /etc/hosts File

The /etc/hosts file is just a list of IP addresses and their corresponding server names. Your server will typically check this file before referencing DNS. If the name is found with a corresponding IP address, DNS will not be queried at all. Add a quick /etc/hosts file entry:

```
172.16.1.100 netx
```

You can check the network connectivity by using ping command:

```
[root@netmon tmp]# ping netx
PING zero (172.16.1.100) 56(84) bytes of data.
64 bytes from netx (172.16.1.100): icmp_seq=0 ttl=64 time=0.185 ms
64 bytes from netx (172.16.1.100): icmp_seq=1 ttl=64 time=0.064 ms
-----
```

### The loopback Interface’s localhost Entry

Usually, the first entry in /etc/hosts defines the IP address of the server’s virtual loopback interface. This is usually mapped to the name localhost.localdomain (the universal name used when a server refers to itself) and localhost (the shortened alias name). By default, Fedora inserts the hostname of the server between the 127.0.0.1 and the localhost entries like this:

```
127.0.0.1 netmon localhost.localdomain localhost
```

When the server is connected to the Internet, this first entry after the 127.0.0.1 needs to be the fully qualified domain name (FQDN) of the server—for example, netmon.mysite.com:

```
127.0.0.1 netmon.spit.ac.in localhost.localdomain localhost
```

Some programs, such as Sendmail, are very sensitive to this and if they detect what they feel is an incorrect FQDN they will default to using the name localhost.localdomain when communicating with another server on the network.

> You must always have a localhost and localhost.localdomain entry in /etc/hosts mapping to 127.0.0.1 for Linux to work properly and securely.

## Enable IP Forwarding

Forwarding allows the network packets on one network interface (i.e. eth0) to be forwarded to another network interface (i.e. eth1). This allows the Linux computer to connect (ethernet bridge) or route network traffic.

IP forwarding can be turned on to allow Linux computer to act as a gateway or router. In simple words, packet forwarding enables packets to flow through the Linux box from one network to another.

The Linux kernel configuration parameter to activate this is named net.ipv4.ip_forward and can be found in the file /etc/sysctl.conf. Remove the # from the line related to packet forwarding.

Before:

```
# Disables packet forwarding
net.ipv4.ip_forward=0
```

After:

```
# Enables packet forwarding
net.ipv4.ip_forward=1
```

The above syntax enables packet forwarding only when you reboot, at which time Linux will create a file in one of the subdirectories of the special RAM memory-based /proc file system. To activate the feature immediately, you have to force Linux to read the /etc/sysctl.conf file with the sysctl command using the -p switch. The syntax to use the sysctl command is as follows:

```
[root@netmon tmp] sysctl -p
sysctl -p
net.ipv4.ip_forward = 1
net.ipv4.conf.default.rp_filter = 1

kernel.sysrq = 0
kernel.core_uses_pid = 1
[root@netmon tmp]#
```

## Useful Network Commands and Utilities

Few network commands and utilities along with their purposes are listed as follows:

- ifconfig: Displays IP address information.
- netstat: Displays routing information and network status.
- ip: Displays IP address information.
- ping: Sends answer request to other hosts.
- route: Shows routing information.
- arpl: Shows arp table entry.
- tcpdump: Captures IP packets on a network interface (usually Ethernet NIC).
- nslookup: Performs DNS lookups and returns the results.
- host: Gets information about networked host.
- dig: Performs more complex DNS lookups than host.
- ftp: Transfers files to another host (insecure).
- ssh: Makes an encrypted connection to another host.
- ssh-keygen: Generates authentication keys for SSH.
- telnet: Makes an insecure connection to another host.
- traceroute: Prints the packet and time taken for hops to a host.
- whois: Gets information about a domain name.
- xhost: Represents X window access control tool.
