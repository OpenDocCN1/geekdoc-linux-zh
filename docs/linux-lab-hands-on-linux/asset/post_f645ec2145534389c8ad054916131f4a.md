## Step 2: Setting up Environment Variables

At this point, you should update the environment variables. You should also add ns-allinone-2.34/bin to your path. This has links to all the executables created by NS-2. The executables such as, NAM or xgraph can be called automatically by Tcl scripts however it is good to specify them in the path.

Carefully follow all the instructions given in the notices. The above-mentioned variables can be updated either by editing /etc/profile or changing environment variables directly. In case you update /etc/profile, you need to source your new environment to reflect the changes (i.e. source /etc/profile).

### For example:

```bash
# .bash_profile

# Get the aliases and functions
if [ -f ~/.bashrc ]; then
.  ~/.bashrc
fi

# User specific environment and startup programs

PATH=$PATH:$HOME/bin
PATH=$PATH:$HOME/bin:/usr/src/ns-allinone-2.34/bin:/usr/src/ns-allinone-2.34/tcl8.4.14/unix:/usr/src/ns-allinone-2.34/tk8.4.14/unix
BASH_ENV=$HOME/.bashrc

USERNAME="root"
export  USERNAME BASH_ENV PATH
export   LD_LIBRARY_PATH=/usr/src/ns-allinone-2.34/otcl-1.13:/usr/src/ns-allinone-2.34/tcl8.4.14/unix
export    LD_LIBRARY_PATH=/usr/src/ns-allinone-2.34/bin:/usr/src/ns-allinone-2.34/tcl8.4.14/unix:/usr/src/ns-allinone-2.34/tk8.4.14/unix
export TCL_LIBRARY=/usr/src/ns-allinone-2.34/tcl8.4.14/library
```

## Running TCL Scripts in NS 2

NS 2 is a discrete event simulator written in C++, with an OTCL interpreter shell as the user interface that allows the input model files (TCL scripts) to be executed. Most network elements in NS 2 simulator are developed as classes, in object-oriented fashion. The simulator supports a class hierarchy in C++, and a very similar class hierarchy in OTCL. NS 2 provides substantial support for simulation of TCP, routing algorithms, queuing algorithms, and multicast protocols over wired and wireless (local and satellite) networks. It is freely distributed, and its source code is also available for free. Following command is used to run the "tcl" script in NS-2:

- Use command "ns file.tcl"

## Functions of NS 2

- Read the Tcl file
- Run the simulation program
- Create trace files
- NAM (network animator) input files

You can see the result by using the following command:
"nam file.nam"

## Starting Network Animator (NAM)

Nam is a Tcl/TK based animation tool for viewing network simulation traces and real world packet traces. It supports topology layout, packet level animation, and various data inspection tools. ## Summary

We use NS 2 because of its support to graphical representations and multiple protocols. NS 2 is a tool that helps you to understand certain mechanisms in protocol definitions, such as congestion control, that are difficult to see in live testing.
