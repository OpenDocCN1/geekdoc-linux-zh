By not specifying the runlevels with the `--level` switch, `chkconfig` makes the changes for runlevels 3 and 5 automatically:

```
`[root@netmon tmp]# chkconfig sendmail off`
```

Because the intention is to shut down sendmail permanently, we might also have to stop it from running now:

```
`[root@netmon tmp]# service sendmail stop
Shutting down sendmail: [  OK  ]
Shutting down sm-client: [  OK  ]
[root@netmon tmp]#`
```

# Double-check that sendmail Will Not Start Up

We can then use `chkconfig` to double-check our work:

```
`[root@netmon tmp]# chkconfig --list | grep mail
sendmail 0:off 1:off 2:off 3:off 4:off 5:off 6:off
[root@netmon tmp]#`
```

# Turn On sendmail Again

To reactivate sendmail, we can use `chkconfig` once more, but with the `on` argument. Start sendmail again to get it running immediately, not just after the next reboot.

```
`[root@netmon tmp]# chkconfig sendmail on
[root@netmon tmp]# chkconfig --list | grep mail
sendmail 0:off 1:off 2:off 3:on 4:off 5:on 6:off
[root@netmon tmp]# service sendmail start
Starting sendmail: [  OK  ]
Starting sm-client: [  OK  ]
[root@netmon tmp]#`
```

# System Shutdown

The system should not be shut down or power off immediately after finishing the work. This can corrupt the files as well as the filesystem directory structure. Linux has a number of ways to gracefully shut down and reboot your system, which is outlined in the following sections.

Commands to shut down the system are listed as follows:

+   - shutdown –h now
+   - halt
+   - poweroff
+   - init 0
