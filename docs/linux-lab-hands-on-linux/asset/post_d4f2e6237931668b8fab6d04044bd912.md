**CONCEPT**

DNS is a facility provided by the TCP/IP that allows you to remember only the name of a site instead of the large and lengthy IP address. It is a client/server based architecture that functions at the Application Layer. Nowadays, the use of Internet services is widespread. The name of a site you type in the address bar is converted into an IP address. Suppose, the DNS utility was not available and you wanted to search for information on any topic from Google. In that case, you had to type 216.239.51.10 instead of typing www.google.com.

Domain name space is designed based on the Hierarchical name space. An inverted tree structure with the root at its top is shown in Fig Linux-5.6. Starting from 0 (root level) to 127 (highest level), a tree can have a maximum of 128 levels. The names in the DNS are not case-sensitive; for example, express is treated the same as Express or EXPRESS.

FC6 and RHEL-5 provide the named daemon, which is Berkeley Internet Name Domain (BIND).

### Authoritative DNS Server

Authoritative servers provide the definitive information for your DNS domain, such as the names of servers and Web sites in it. There are 13 root authoritative DNS servers (super dupe r authorities) as shown in figure 1.

![](img/f3b9cff79e19317416c12eaf5ded7245_151_0.png)

▲ Figure 1

These root servers know all the authoritative DNS servers for all the main domains—.com, .net, and the rest. This layer of servers keep track of all the DNS servers that Web site systems administrators have assigned for their sub domains.

For example, when you register your domain apple.com, you are actually inserting a record on the .com DNS server that points to the authoritative DNS server, which you have assigned for your domain.

### Caching Name Server

Caching nameserver provides name lookup for client programs such as web browsers by contacting other name servers. This information is cached in local storage in case it is requested in near future.

If you want to host your own website with full control of all the web domains and your ISP provides you with a fixed IP address then authoritative DNS server is the answer.

### DNS Testing of DNS Interrogation at DNS client

DNS Server (named) resolves or maps fully qualified domain name such as www.spit.ac.in to an ip address. This is also called forward lookup. Also it resolves or map ip address to Fully qualify domain name. This is called as reverse lookup.

There are a number of commands you can use to do these lookups. Linux uses the host and nslookup command as DNS client side program, but Windows uses nslookup as DNS client side program.

## The host Command

The host command accepts arguments that are either fully qualified domain names or the IP addresses of the servers while providing results. Following is the syntax to perform a forward lookup:

Syntax:

```text
[root@netmon tmp]# host www.spit.ac.in
www.spit.ac.in has address 202.22.21.20
[root@netmon tmp]#
```

Following is the syntax to perform a reverse lookup:

Syntax:

```text
[root@netmon tmp]# host 202.22.21.20
20.21.22.202.in-addr.arpa domain name www.spit.ac.in.
[root@netmon tmp]#
```

## The nslookup Command

The nslookup command provides the same result on Windows PCs. To perform forward lookup:

```text
C:\> nslookup www.spit.ac.in
Server:  nsi.spit.ac.in
Address:  202.22.21.20

Non-authoritative answer:
Name:  www.spit.ac.in
Address:  202.22.21.20

C:\>
```

To perform a reverse lookup:

```text
C:\> nslookup 202.22.21.20
Server:  nsi.spit.ac.in
Address:  192.168.1.200

Name:  20.21.22.202.www.spit.ac.in
Address:  202.21.22.20
C:\>
```

## Configuration files

Following are the list of important configuration files on client and server side.

Client side:

- `/etc/nsswitch.conf` To determine the order in which to query name services
- `/etc/resolve.conf` To mention whois your DNS server

Server Side:

| Config Path | Description |
| :--- | :--- |
| /var/named/chroot/etc/named.conf | Main DNS configuration file that list location and name of the zone files to be used for your desired website domains. |
| /var/named/chroot/var/named/... (name of the forward zone file) | maps domain name to ip addresses |
| /var/named/chroot/var/named/... (name of the reverse zone file ) | ipaddresses to domain name. |
| /var/named/chroot/var/named/named.ca | List of 13 root authoritative servers. |
| /var/named/chroot/etc/rndc.key | File used in named authentication |

- Client side program: nslookup, dig and host
- Server Side program: named, named-checkzone

## Steps to Install and configure DNS Server/Client

### Client Side

1. Edit /etc/resolv.conf
    - nameserver {ip address of DNS server}

For example, nameserver 172.16.20.1

Table 1 is displaying keywords of /etc/resolv.conf

| Keywords in /etc/resolv.conf | Value |
| :--- | :--- |
| nameserver | IP address of your DNS name server. There should be only one entry per nameserver keyword. If there is more than one name server, use multiple nameserver lines |
| Domain | The local domain name to be used by default. If the server is netmon.split.ac.in, then the entry would just be split.ac.in. |
| Search | If you refer to another server just by its name without the domain added on, DNS on your client appends the server name to each domain in this list and does a DNS lookup on each to get the remote server's IP address. This is a time-saving feature, enabling you to refer to servers in the same domain by only their server name without having to specify the domain. The domains in this list must be separated by spaces. |

### Server Side

1. Configuring resolv.conf
    - You will have to make your DNS server refers to itself for all DNS queries by configuring the /etc/resolv.conf file to reference localhost only

```text
nameserver 127.0.0.1
```

2. Use the `chkconfig` command to enable the startup of named services during system boot.
    - Following is the syntax for `chkconfig` command:
    - Syntax:

```text
[root@netmon tmp]# chkconfig --level 345 named on
```

Following is the syntax to start *named* after booting:
Syntax:

```text
[root@netmon tmp]# service named start
```

Following is the syntax to stop *named* after booting:
Syntax:

```text
[root@netmon tmp]# service named stop
```

Following is the syntax to restart *named* after booting:
Syntax:

```text
[root@netmon tmp]# service named restart
```

Remember to restart the *named* process every time you make a change to the configuration file for the changes to reflect on the Executing process.

> Fedora Core/RHEL installs BIND (named) chroot package by default. Hence bind works in chroot environment.

### Configuring named.conf

Modify the following example of `named.conf` file according to your organization’s domain name:

```text
// sample file
options {
directory "/var/named";
/*
* If there is a firewall between you and nameservers you want
* to talk to, you might need to uncomment the query-source
* directive below. Previous versions of BIND always asked
* questions using port 53, but BIND 8.1 uses an unprivileged
* port by default.
*/
query-source address * port 53;
};
/// a caching only nameserver config
controls {
inet 127.0.0.1 allow { localhost; } keys { rndckey; };
};
zone "." IN {
type hint;
file "named.ca";
};

zone "localhost" IN {
type master;
file "localhost.zone";
allow-update { none; };
};

zone "0.0.127.in-addr.arpa" IN {
type master;
file "named.local";
allow-update { none; };
};

zone "spit.ac.in" IN {
type master;
file "spit.ac.in.forward";
allow-update { none; };
};

zone "1.168.192.in-addr.arpa" IN {
type master;
file "spit.ac.in.reverse";
allow-update { none; };
};

include "/etc/rndc.key";
```

The named.conf file contains the main DNS configuration and tells BIND (named) where to find the configuration files for each domain you own. This file usually has the following two zone areas:

- **Forward zone**: Refers to the file definitions that lists files to map domains to IP addresses
- **Reverse zone**: Refers to the file definitions that lists files to map IP addresses to domains

In the following example, you set up the forward zone for www.spit.ac.in by placing entries at the bottom of the named.conf file. The zone file is named as spit.ac.in.forward, and, although not explicitly stated, the file spit.ac.in.forward should be located in the default directory of /var/named/chroot/var/named in a chroot or in /var/named in a regular one. Use the code:

```text
zone "spit.ac.in" {
type master;
otify no;
allow-query { any; };
file "spit.ac.in.forward";
};
```

In addition, you can insert additional entries in the named.conf file to reference other Web domains you host. Here is an example for another-site.com using a zone file named another-site.zone:

```text
zone "another-site.com" {
type master;
otify no;
```
