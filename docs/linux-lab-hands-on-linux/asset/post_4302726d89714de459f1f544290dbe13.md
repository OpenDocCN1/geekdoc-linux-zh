# Appendix: Linux Firewalls

- Aim: To convert a Linux server into:
  - A firewall while simultaneously being your home website's mail, web and DNS server.
  - A router that will use NAT and port forwarding to both protect your home network and have another web server on your home network while sharing the public IP address of your firewall.

Tools: Netfilter is a very important part of the linux kernel. It provides security, packet mangleing and manipulation. The iptables is a frontend of the netfilter, which "tells" the kernel what the user wants to do with the IP packets arriving into, passing through, or leaving the linux box.

Netfilter has a few tables, each containing a default set of rules, which are called chains. The default table loaded in the kernel is the filter tables, which contains three chains: INPUT, FORWARD and OUTPUT.

Another type of tables provided by netfilters are NAT and Mangle tables. Which are used for Naterwork address translation and changing the parameter in IP header of the packet.

## Installation of Iptables Package

Before you begin, you need to make sure that the iptables software RPM is installed. When searching for the RPMs, remember that the filename usually starts with the software package name by a version number, as in iptables-1.2.9-1.0.i386.rpm.

```
[root@netmon tmp]#rpm -qa|grep iptables
[root@netmon tmp]#rpm -qI iptables
```

You can start, stop, and restart iptables after booting by using the commands:

```
[root@netmon tmp]# service iptables start
[root@netmon tmp]# service iptables stop
[root@netmon tmp]# service iptables restart
```

To get iptables configured to start at boot, use the chkconfig command:

```
[root@netmon tmp]# chkconfig iptables on
Iptables - Commands
```

List the rules of chain -iptables -L CHAIN e.g iptables -L INPUT

- Create new chain - N chainname
- Flush a chain i.e delete all the rules - iptables -F
- append rules to chain - iptables -A
- delete a rule from a chain -iptables -D

## Filtering Specifications layer 2 and layer 3 Match Criteria

| iptables command Switch | Description |
| :--- | :--- |
| -t <table> | If you don't specify a table, then the filter table is assumed. As discussed before, the possible built-in tables include: filter, nat, mangle |
| -j <target> | Jump to the specified target chain when the packet matches the current rule. |
| -A | Append rule to end of a chain |
| -F | Flush. Deletes all the rules in the selected table |
| -p <protocol-type> | Match protocol. Types include, icmp, tcp, udp, and all |
| -s <ip-address> | Match source IP address (Filtering Specification Layer3) |
| -d <ip-address> | Match destination IP address (Filtering Specification Layer3) |
| -i <interface-name> | Match "input" interface on which the packet enters. (Filtering Specification Layer 2) |
| -o <interface-name> | Match "output" interface on which the packet exits (Filtering Specification Layer 2) |

1. In this command switches example

   iptables -A INPUT -s 0/0 -i eth0 -d 172.16.1.1 -p TCP -j ACCEPT

iptables is being configured to allow the firewall to accept TCP packets coming in on interface eth0 from any IP address destined for the firewall's IP address of 172.16.1.1. The 0/0 representation of an IP address means any.

## Filtering Specifications Layer 4 Match Criteria

| Switch | Description |
| :--- | :--- |
| -p tcp --sport <port> | TCP source port. Can be a single value or a range in the format: start-port-number:end-port-number |
| -p tcp --dport <port> | TCP destination port. Can be a single value or a range in the format: start-port-number:end-port-number |
| -p tcp --syn | Used to identify a new TCP connection request. ! --syn means, not a new connection request |
| -p udp --sport <port> | UDP source port. Can be a single value or a range in the format: start-port-number:end-port-number |
| -p udp --dport <port> | UDP destination port. Can be a single value or a range in the format: start-port-number:end-port-number |

2. In this example:

   iptables -A FORWARD -s 0/0 -i eth0 -d 192.168.1.58 -o eth1 -p TCP \
   --sport 1024:65535 --dport 80 -j ACCEPT

iptables is being configured to allow the firewall to accept TCP packets for routing when they enter on interface eth0 from any IP address and are destined for an IP address of 192.168.1.58 that is reachable via interface eth1. The source port is in the range 1024 to 65535 and the destination port is port 80 (www/http).

3. iptables -A OUTPUT -p icmp --icmp-type echo-request -j ACCEPT

```
iptables -A INPUT -p icmp --icmp-type echo-reply -j ACCEPT
```

iptables is being configured to allow the firewall to send ICMP echo-requests (pings) and in turn, accept the expected ICMP echo-replies.

4. Consider another example

```
iptables -A INPUT -p icmp --icmp-type echo-request \\
-m limit --limit 1/s -i eth0 -j ACCEPT
```

The limit feature in iptables specifies the maximum average number of matches to allow per second. You can specify time intervals in the format /second, /minute, /hour, or /day, or you can use abbreviations so that 3/second is the same as 3/s.

In this example, ICMP echo requests are restricted to no more than one per second. When tuned correctly, this feature allows you to filter unusually high volumes of traffic that characterize denial of service (DOS) attacks and Internet worms.

```
iptables -A INPUT -p tcp --syn -m limit --limit 5/s -i eth0 -j ACCEPT
```

You can expand on the limit feature of iptables to reduce your vulnerability to certain types of denial of service attack. Here a defense for SYN flood attacks was created by limiting the acceptance of TCP segments with the SYN bit set to no more than five per second.

## Common Extended Match Criteria

| Switch | Description |
| :--- | :--- |
| -m multiport --sports <port, port> | A variety of TCP/UDP source ports separated by commas. Unlike when -m isn't used, they do not have to be within a range. |
| -m multiport --dports <port, port> | A variety of TCP/UDP destination ports separated by commas. Unlike when -m isn't used, they do not have to be within a range. |
| -m multiport --ports <port, port> | A variety of TCP/UDP ports separated by commas. Source and destination ports are assumed to be the same and they do not have to be within a range. |
| -m --state <state> | The most frequently tested states are:<br>ESTABLISHED: The packet is part of a connection that has seen packets in both directions<br>NEW: The packet is the start of a new connection<br>RELATED: The packet is starting a new secondary connection. This is a common feature of such protocols such as an FTP data transfer, or an ICMP error.<br>INVALID: The packet couldn't be identified. Could be due to insufficient system resources, or ICMP errors that don't match an existing data flow. |

6. This is an expansion on the previous example:

```
iptables -A FORWARD -s 0/0 -i eth0 -d 172.16.1.58 -o eth1 -p TCP \
-sport 1024:65535 -m multiport --dports 80,443 -j ACCEPT

iptables -A FORWARD -d 0/0 -o eth0 -s 172.16.1.58 -i eth1 -p TCP \
-m state --state ESTABLISHED -j ACCEPT
```

Here iptables is being configured to allow the firewall to accept TCP packets to be routed when they enter on interface eth0 from any IP address destined for IP address of 172.16.1.58 that is reachable via interface eth1. The source port is in the range 1024 to 65535 and the destination ports are port 80 (www/http) and 443 (https). The return packets from 172.16.1.58 are allowed to be accepted too. Instead of stating the source and destination ports, you can simply allow packets related to established connections using the -m state and --state ESTABLISHED options.

## Allowing DNS Access To Your Firewall

```
iptables -A OUTPUT -p udp -o eth0 --dport 53 -sport 1024:65535 \
-j ACCEPT

iptables -A INPUT -p udp -i eth0 --sport 53 --dport 1024:65535 \
-j ACCEPT
```

## Allowing WWW And SSH Access To Your Firewall

```
iptables -A OUTPUT -o eth0 -m state --state ESTABLISHED,RELATED \
-j ACCEPT

iptables -A INPUT -p tcp -i eth0 --dport 22 --sport 1024:65535 \
-m state --state NEW -j ACCEPT

iptables -A INPUT -p tcp -i eth0 --dport 80 --sport 1024:65535 \
-m state --state NEW -j ACCEPT
```

## Allowing Your Firewall To Access The Internet

```
iptables -A OUTPUT -j ACCEPT -m state \
--state NEW,ESTABLISHED,RELATED -o eth0 -p tcp \
-m multiport --dports 80,443 --sport 1024:65535

iptables -A INPUT -j ACCEPT -m state --state ESTABLISHED,RELATED \
-i eth0 -p tcp
```

## Allow Your Home Network To Access The Firewall

In this example, eth1 is directly connected to a home network using IP addresses from the 172.16.1.0 network. All traffic between this network and the firewall is simplistically assumed to be trusted and allowed.

Further rules will be needed for the interface connected to the Internet to allow only specific ports, types of connections and possibly even remote servers to have access to your firewall and home network.

```
iptables -A INPUT -j ACCEPT -p all -s 172.16.1.0/24 -i eth1
iptables -A OUTPUT -j ACCEPT -p all -d 172.16.1.0/24 -o eth1
```
