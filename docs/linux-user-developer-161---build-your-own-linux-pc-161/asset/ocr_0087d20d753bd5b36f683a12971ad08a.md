# ## Processes and Programs

It is important to understand exactly what a process is and how it differs from a program. A process has its own execution environment which contains instructions, user and system data and other kinds of resources that are obtained during execution.

On the other hand, a program is a file that contains executable code and static data, which represents the instruction and data parts of a process.

The only way to execute a process on Linux is through the fork() system call. When fork() is called, a new process is created. The only way to create a new process is a copy of the existing process.

When you execute a system by system call, you create a new process that is a copy of the calling process's data and system data parts and the parent process both execute the same instructions from the same point.

Although used individually neither fork nor exec is sufficient to run a program; it is vital to make sure you completely understand the differences and similarities of processes and programs.

There exist functions in the family: execi, execp, execve, and execv. The i signifies that the arguments are given as a list whereas the v signifies that the arguments are given as a vector. The e at the end of the name indicates that you are executing a process with an environment which should be used when searching for a program. As you can see in next, you cannot use both p and e in the same system call!

When you use one of the exec system calls to execute a program, the new program replaces the process and starts execution in its main function.

execv is used for executing a program with an argument list. This list contains the path of the program to be executed. The new program is executed in its (main) function. Both user and stack data are replaced by the parts of the new process. Therefore, a successful call to exec does not return any value. If it fails, it returns -1 which happens when the path does not exist.

execve is used for executing a program with an argument list and an environment. The first character in the path argument must be absolute or relative.

With execvp(), the first argument is the path to the executable. The rest of the process remains the same except for the heap, stack, user data and file descriptors. The process does not keep any open file descriptors.

# ## How a process is terminated

There are many ways to terminate a running process; some are normal and some are handled by the process itself while others are abnormal and violently terminate a process. An example of abnormal termination is when a process receives a signal SIGKILL, which is signal used to terminate a process by cutting it off with the power of a switch; used if you need it.

A normal termination happens when you normally exit via a menu or an option - this allows the process to perform any necessary cleanup. System terminates a process normally: exit(1), exit(2) and exit($2). You can also terminate the process with the return() function; however the following two calls are equivalent when called:

```
exit(0);
return();
```

All three functions take a single integer argument that specifies the exit status, which is if needed. The C standard defines two constants, EXIT_SUCCESS and EXIT_FAILURE, that may be passed to exit indicate successful or unsuccessful termination, respectively. If you want to write perfectly portable, you can use either exit or EXIT_SUCCESS to indicate a successful termination.
