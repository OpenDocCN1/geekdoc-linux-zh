```
$ snort -dev /1 -log
```

You can see from the command that there is no need to specify the verbose mode or -e switches. In binary mode, the packet is logged and not just parts of it. If you need to enable network intrusion detection, you can use the following command: 

```
$ snort -dev /1 -home $HOME_NET -etc/snort/
snort.conf
```

Please note that Snort is the name of your file and HOME_NET is a variable value defined in the configuration file. The rule section in the snort.conf file will be applied to each packet, and a decision will be made for each if an action needs to be taken or not. The default action is alert. Other rules file is to read through the entries of snort.conf before calling it the command is

application behaviour to process Pass rules first, then Alert, as shown in this command:

```
$ snort -h 192.168.1.0/24 -1 /log -etc/snort/
snort.conf
```

Another important thing is that we need to understand the Snort configuration. Snort provides a variety of options to display the output and the detected information. In many network security administrators need to monitor and investigate the information generated by Snort. To do this, Snort must output the data in a format that enables multiple-output plugins and a variety of tools to be employed by security administrators. We have a quick look at some of the snort configurations:

+   - Alert syslog: UNIX-based systems use the syslog facility to consolidate the detected messages. Snort-generated information can be presented in syslog in different ways. If you use syslog in the snort configuration, the format looks like this

It is important to note that if you are using an IDS, you should not use the -u switch in the command line for the sake of speed. When used as a network intrusion detection system, Snort provides real-time detection capabilities.

In some cases, we are interested in the performance of Snort. In such scenario, you can use the -A and -fast options. The output will be logged in tcpdump format and that provides very minimal alerts. The following command you can use for this purpose:

+   - tcpdump: This logs packets to the tcpdump file. There are a variety of applications that can read this format.
- MySQL: Logging requires the database support to be present on the system running Snort, in the form of the MySQL software and libraries.

Also note that Snort applies its rules to packets in a specific order. The default order is Alert will be applied first, then the rules and finally the Log. Snort provides the -o switch to change the default rule
