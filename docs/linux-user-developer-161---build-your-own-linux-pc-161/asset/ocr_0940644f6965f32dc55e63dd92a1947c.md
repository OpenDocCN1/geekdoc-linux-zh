# Get a move

Now that our models are visible on the screen, it is time to add some inertia. The laws of physics dictate that bodies with mass cannot change their position without an external force. Acceleration is applied, gradually moving objects to their intended position.

Simulating this behaviour on a computer is quite easy: the model class is represented with three fields called dx, dy and dz. By using a variable with the letter d that contains a value in minus, this delta letter signifies the acceleration. The next step is the actual movement. In each Update(), each position is updated with the value in its delta field.

# Stay apart

Collision detection is one of the most significant parts of game design: major mistakes here can lead to broken blocks. Sadly, errors can be even worse, as they signify high CPU usage during program execution we use the above method as a first step.

When dealing collision in 'open-box' cases, a two-pronged approach is better. Elements are not contained within the boundaries of the screen by a bounding box, however boundaries are enforced during each step of the collision update.
