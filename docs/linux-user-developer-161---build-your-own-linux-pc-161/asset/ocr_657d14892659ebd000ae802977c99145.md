In other words, if the fork() call succeeds, it returns despite the fact that it is called once! It is also important to remember that both the parent and the child continue execution with the code that follows the call to fork()
You usually use fork() to create processes that wants to duplicate itself so that the parent and the child can execute each different section of code at the same time.

As you will see in a forking server multiple processes such as Apache use fork() to start processes and allow to serve multiple client requests. The parent process gets one client request for each TCP/IP port, and is responsible for sending request to its child to be served. Second, when a process wants to run a different program it is very common for Linux shells. The child executes the exec system call immediately after it returns from fork() such as an example:

```
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int main(int argc, char **argv) {

    pid_t pid;
    pid = fork();

    if (pid == 0)
        exec("/bin/ls", "ls", "la", (char*)0);
    else if (pid < 0)
        printf("Error executing fork!\n");
```

+   Printing the environment

When you execute a Linux program, it automatically gets all the environment variables from the process - other processes that invoked it. The first argument of the main function is the command name of the program. The second is the environment. The program also has access to a global environment which is an array of strings called environ.

The following code (c) prints all the environment variables of program

```
#include <stdio.h>
#include <stdlib.h>

extern char **environ;

int main(int argc, char **argv) {

    for (char **env = environ; *env != NULL; ++env)
        printf("%s\n", *env);
    return 0;
```

The program is executed as usual, until it reaches fork(). At this point, another process is created and the parent continues its execution. So you now have two processes running. The child process is the child of the parent by calling the return value of fork() - this is happening inside the child process. Similarly, the parent process understands that it is the parent of the child. The myfork.c is the printing of two messages on screen, one from the parent and another from the child. The difficulty is that after the message, you get the command prompt and then the child prints the message, which happens because the parent does not control the message
