# Resolve errors

From time to time you may encounter errors with your
PiBeacon, specifically in persuading the status to switch
"DOWN" to "UPRUNNING".

Restarting the device is no good here. Instead, you need to reset
the hci device. First, enter hicnfig to configure the hci device
name. Usually, this is how.

Next, enter sudo hci reset. This essentially clears
every out and lets you start again. To check, input
hicnfig again, where you should see the status now reads
"UPRUNNING".

```
sudo hicnfig hci reset
```

# Test with an iOS device

Before proceeding to use your PiBeacon for a particular
project, you'll need to make sure it is broadcasting correctly.
To do this, you'll need an iPhone or an iPad Touch to
detect the Scan Data Response—including the
UUID from the PiBeacon to your smartphone when it\comes into proximity.

In addition, you'll need an app. Something like Toolkit,
mentioned above, should be sufficient. We are really just looking
at this stage to test the strength and range of your PiBeacon.
Of these qualities rely on the BLE device connected to your
Raspberry Pi's USB port.

# Using the app Toolkit

With the app Toolkit open and tap Listen. The iOS device will display
as you move your phone or tablet around, the position
of the PiBeacon and you can use this information to get
signal of signal strength, and you can expect the PiBeacon
to be picked up by the interrupted device.

But right now, why use this? Because PiBeacon technology
is really like a sort of NFC, but without the proximity of
contact. This has some security concerns, so be careful,
how you use it...
