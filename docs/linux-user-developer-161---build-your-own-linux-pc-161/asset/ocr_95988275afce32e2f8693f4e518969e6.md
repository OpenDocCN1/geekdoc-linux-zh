# Read-only memory

The kernel uses memory in many different ways. There are runtime allocations for user applications, which are usertasks filesystems, internal kernels, and numerous others besides. There is also statically "allocated" memory that is defined in the course of the kernel and remains at boottime.

Some memory is not allocated by the kernel, it is reserved for use by the kernel from the moment it begins to execute. This memory often contains regions that are written and read again, no matter how long the kernel remains running. Some of this memory contains sensitive data, that if modified by bad or rogue code, security features aims to reduce the risk of such by making memory regions read only.

One of the most notable features is the addition of a driver for the Broadcom VideoCore IV (VCA4) GPU System-on-Chip processors, known as BCM2836 SoC (System-on-Chip) processors, known more generally used in the Raspberry Pi 2. The new KMS (Mode Setting Kernel) driver allows the kernel to control the display balance and cursor, but it marks the first time that the kernel has direct access to graphics on the Raspberry Pi.

Modern operating systems divide physical memory into millions of small (sometimes not so small) chunks known as "pages". Pages are typical. To put into context, each page is 4KB, so the plaintext of this column on a machine contains about 2MB of physical memory (400 pages). It would take 100 pages to contain all the memory-mapped file data used to store features and metadata.
