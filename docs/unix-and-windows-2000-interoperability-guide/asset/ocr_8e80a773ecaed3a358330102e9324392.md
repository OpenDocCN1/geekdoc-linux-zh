# Table 11–1 Default Primary NFS Mount Options

| Option | Signifies |
|---|---|
| rw | Mount the directory read/write. |
| suid | Allow mounted programs have setuid permission to run with the permissions of their owners, regardless of who starts them. This includes setuid programs owned by root. |
| hard | Causes the client to keep trying to access the server if it goes down. |
| intr | Often used with hard mounts, specifies that a user can interrupt a retry of an unavailable NFS resource using CTRL-C or the kill command. |
| fg | Mounts are tried in the continuously until they succeed. |
| devs | Allows the mounting of device files. |
| timeout=7 | The timeout, in tenths of a second, for NFS request. |
| retrans=4 | The number of times an NFS request is retransmitted after it times out. |
| rsize=8192 | The number of bytes the NFS client requests from the NFS server in a single read request. |
| size=8192 | The number of bytes the NFS client sends to the NFS server in a single write request. |

There are also additional cache options you can consider. See Hewlett-Packard’s Configuring and Administering NFS for more information.

Once you mount a file system in this manner, you can see the results by executing the mount command. For example:

```
# mount
/ /dev/dsk/c0t6d defaults on Wed Dec 13 14:58:15 2000
/pcmnt on w2kserv.book.local:/music defaults, NFSv3 on Wed Dec 13 14:59:48 2000
```

Note that the word defaults appears in the output to indicate the default options listed above. Also, note that the mount succeeded using NFS protocol version 3, the default protocol on both HP-UX NFS and Server for NFS.
