# The Internet Layer

We now proceed to the next level of the four-layer TCP/IP model, the internet layer, sometimes called the network layer. (If the word internet is not capitalized, it refers to the inter-networking of networks in a generic sense. The word Internet (with a capital I) refers to the now worldwide public internetwork.) The Internet layer enables pieces of data, usually called datagrams, to find their correct destination, even if the destination is several networks away. Within the TCP/IP protocol suite, IP, the Internet Protocol, is responsible for the routing of these datagrams. Because of the recent Internet phenomenon, TCP/IP is omnipresent these days, making it a key to system interoperability. TCP/IP runs on a wide variety of platforms: mainframes, Macs, VAXs, and of course UNIX and Windows 2000 systems. Therefore, your desktop computer may run Windows 2000, you can connect to a Web server running HP-UX 11 or Linux, since the Web relies on Hypertext Transfer Protocol (HTTP), a TCP/IP application. So let's look at TCP/IP concentrating in this chapter on IP, the network layer.

TCP/IP began as a part of the Defense Department's Advanced Research Projects Agency in 1969. It was incorporated into BSD UNIX in the early 1980s and is part of every current implementation of UNIX. Microsoft released a completely rewritten TCP/IP suite with the release of Windows NT 3.5 in 1994. Whatever the source, any vendor claiming to prove TCP/IP must ensure that it adheres to the Internet Standards set forth in the Request for Comments (RFC) document series. According to RFC 2026, The Internet Standards Process – Revision 3, p. 3, “The Internet standards process is an activity of the Internet community by the Internet Architecture Board (IAB) and the Internet Engineering Steering Group (IESG)” are the official means of these bodies to regulate Internet standards. You can find the RFCs in a number of locations on the Internet, one of which is the Internet Engineering Task Force's Web site at www.ietf.org.
