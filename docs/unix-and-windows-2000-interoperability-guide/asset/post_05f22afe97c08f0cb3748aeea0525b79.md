## Basic TCP/IP Utilities

Bundled with Windows 2000 are a number of TCP/IP utilities that experienced UNIX users have known about for quite some time. With the advent of the Internet, more Windows-oriented users have come to know about at least two of them: Telnet and FTP. We will look at those other utilities, how they differ between the two platforms, and how to use them between platforms.

## 9.1 General Observations

In this chapter, we will examine the following utilities:

- Finger
- FTP
- Tftp
- Rsh
- Rcp
- Rexec
- Telnet

On Windows 2000, these utilities are clients only. In other words, they enable access to remote systems running server versions of these utilities, but they do not enable remote systems to access Windows 2000. Even the server versions of Windows 2000 run these utilities only as clients, with the exception of FTP, the server version of which can be installed with Internet Information Services. Otherwise, you must install additional software, such as Microsoft's Services for UNIX or Hummingbird's Exceed, to run these utilities as services on Windows 2000.

## Chapter 9 • Basic TCP/IP Utilities

On UNIX systems, all of these utilities come in both the client and the server varieties. The names of the server versions all end in the letter d to indicate that they are daemons. In the UNIX world, daemons run as background processes, ready to serve requests. Some daemons run continually; others, including the below, run only when needed. On HP-UX 11, the server versions of the utilities mentioned above are:

- /usr/bin/fingerd
- /usr/bin/ftpd
- /usr/bin/remshd
- /usr/bin/rexcd
- /usr/bin/telnetd
- /usr/bin/tftpd

The clients are:

- /usr/bin/finger
- /usr/bin/ftp
- /usr/bin/rcp
- /usr/bin/rexec
- /usr/bin/remsh
- /usr/bin/telnet
- /usr/bin/tftip

If you are new to UNIX, it is probably confusing to think that both server and client components of key utilities can be found on a single system, including one that can be considered a "client" system. But such is the case that a system administrator logged on to a UNIX server (because it is so big and probably runs something, like a database) can use the Telnet client on that server to connect to the Telnet server running on a client system in order to run commands on it. It happens all the time, even in the Windows world. If you are logged in as an administrator of a Windows 2000 Advanced Server system, you can use your FTP client to connect to the FTP server on a remote UNIX client. You can issue commands via your FTP client (on Windows 2000 Advanced Server) to the FTP server (on the UNIX workstation). So, in both the UNIX and Windows 2000 arenas, utilities can exist in either client or server form despite the "official" role of the system.

Now, back to the server versions of the basic TCP/IP utilities. Because the number of daemons on a given system can grow large, and because some daemons, though necessary, are used infrequently, UNIX systems employ an intermediate daemon to manage network requests. This daemon is inetd, short for Internet daemon. The daemons discussed in this chapter do not run continually in the background. Instead, /usr/sbin/inetd runs continually, ready to awaken other daemons to fulfill client requests. Once the daemon's work is done, it dies, to be resurrected when needed.

## 9.2 Finger

The finger utility provides information about users on a remote system. Among other things, this utility provides the login name, full name, login time, user's home directory, and login shell. Exactly what you depends on the implementation of fingerd on the remote system. The Windows 2000 version of finger has the following syntax:

```
finger [-l] @user@hostname
```

The @hostname parameter is the target system's host name or IP address and is required. If you do not specify a user, you will get information only logged in users. If you use the optional user parameter, you can get information about that user, regardless of whether she or is logged in. The -l option provides with complete information about a user. Otherwise, you will get something like the following:

```
C:\finger @hpux1
```

This is most information derived from the gecos in the /etc/passwd file. The output above shows the user dylan logging in at 1:36 pm. Monday, after not logged in for 37 days.

```
#finger stream tcp nowait /usr/sbin/fingerd fingerd
```

In the /etc/inetd.conf file, as any UNIX configuration files, any line beginning with the pound sign (#), is ignored by the system. In UNIX verbatim, having a # at the beginning of a configuration file means that line is "commented out."

## 9.3 FTP

Because of the omnisence of the Internet days, FTP is widely known and spelled. In all caps, FTP refers to File Transfer Protocol. The user interface to this protocol is spelled FTP (in Windows) or ftp (in UNIX). Using FTP, users copy (not really transfer) files from a server. On UNIX systems, FTP is available in both client and server, while on Windows 2000, you must do one of the following to run ftpd: (1) install Internet Services, (2) install Services for UNIX, or (3) install a third-party version. For both Windows 2000 and HP-UX, the FTP client supports a number of subcommands, that is, commands available at the <FTP> prompt. These subcommands are quite similar, yet running the FTP client differs.

## 9.3.1 Windows 2000

The syntax of the FTP command in Windows 2000 is

```
ftp [-v] [-n] [-i] [-d] [-g] [-s:filename] [-a] [-A] [-w:windowsize] hostname
```

- -v suppresses the display of remote server responses. On HP-UX, this enables verbose output.
- -n suppresses autologon upon initial connection. This is the same on HP-UX.
- -i disables interactive prompting by multiple-file commands. This is the same on HP-UX.
- -d enables debugging. This option is not available on HP-UX.
- -g disables file name globbing (using wildcard characters). This is the same on HP-UX.
- -s:<filename> specifies a text file contain FTP commands, run automatically after FTP starts. This option is not available on HP-UX.
- -a specifies that any local interface can be used when binding the FTP data connection. Not available on HP-UX.
- -A logs in to the FTP server as anonymous. Not available in HP-UX
- -w:windowsize specifies the size of the transfer buffer. The default is 4096 bytes.

The hostname parameter is optional. If you specify a host, then FTP starts and immediately opens a connection to the target host. If you do not specify a host, you just get the <FTP> prompt. This prompt waits for you to issue subcommands.
