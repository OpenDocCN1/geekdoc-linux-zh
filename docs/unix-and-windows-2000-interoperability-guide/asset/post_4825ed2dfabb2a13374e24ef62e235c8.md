## 6.4.4 DHCP

DHCP was developed to ease the TCP/IP configuration process and to accommodate mobile computing and sites that frequently move their clients. As DHCP was deployed, it became apparent that there was a new problem to solve: how to keep DNS updated when clients kept their IP addresses.

Actually, this problem wasn't so bad for a lot of organizations. Typically, the pattern that all the UNIX systems used TCP/IP and had their configurations manually. The PC-based systems, at least initially, ran NetBEUI or IPX/SPX. As they converted to TCP/IP, their configuration was usually done through a DHCP server because it was so simple to do. Most sites saw no need for DNS to keep track of PC-based client systems and their IP addresses, since these systems usually did not provide shares or other services. (That's the job of servers).

However, as UNIX systems started becoming DHCP clients, the need to update DNS really became apparent, because things such as file transfers between clients was (and still is, in some places) commonplace in that community.

Windows 2000 DHCP clients can either register their IP information directly with DNS or do it on their behalf. You can configure Windows 2000 DHCP servers to do this for non-Windows 2000 systems by selecting the Enable updates for DNS clients that do not support dynamic updates on the DNS tab of the DHCP console. Whether your UNIX DHCP server can do this depends on the vendor. The HP-UX 11 server does not support registering with DNS. The Internet Software Consortium (ISC) DHCP distribution 3.0, in beta, will support DNS.

## 6.5 Conclusion

In this chapter, we looked how name resolution takes place within Windows 2000 and HP-UX. Windows 2000 computer names are based on DNS domain names. You can set both primary and connection-oriented suffixes in Windows 2000. For compatibility with other Windows systems, Windows 2000 systems still have NetBIOS computer names. In an all-Windows 2000 network, name resolution is done with DNS. In a mixed network with Windows 2000 and non-Windows 2000 systems, DNS is tried first, then NetBIOS. NetBIOS name resolution is the same as on Windows 2000 as it is on pre-Windows 2000 systems. Windows 2000 continues to support Windows for mixed environments.

HP-UX host names are using the hostname command or the set_params script. They do not use NetBIOS computer names unless you install something like AdvancedServer. The /etc/hosts file, NIS, DNS, or some combination of the three to resolve names. To configure which of these methods to use, and in what order, you configure the name service. The BIND resolver has a lookup process similar to the one on Windows 2000, involving a number of system variables and the /etc/resolv.conf file.

There are also differences in tools such as nslookup, and DHCP. Windows 2000 DNS is a dynamic DNS, whereas you must have BIND version 8.1.2 or later on UNIX systems to support dynamic updates. The Microsoft DHCP server can update a Microsoft DNS server on behalf of its clients.

## 6.4.4 DHCP

DHCP was developed to ease the TCP/IP configuration process and to accommodate mobile computing and sites that frequently move their clients. As DHCP was deployed, it became apparent that there was a new problem to solve: how to keep DNS updated when clients kept their IP addresses.

Actually, this problem wasn't so bad for a lot of organizations. Typically, the pattern that all the UNIX systems used TCP/IP and had their configurations manually. The PC-based systems, at least initially, ran NetBEUI or IPX/SPX. As they converted to TCP/IP, their configuration was usually done through a DHCP server because it was so simple to do. Most sites saw no need for DNS to keep track of PC-based client systems and their IP addresses, since these systems usually did not provide shares or other services. (That's the job of servers).

However, as UNIX systems started becoming DHCP clients, the need to update DNS really became apparent, because things such as file transfers between clients was (and still is, in some places) commonplace in that community.

Windows 2000 DHCP clients can either register their IP information directly with DNS or do it on their behalf. You can configure Windows 2000 DHCP servers to do this for non-Windows 2000 systems by selecting the Enable updates for DNS clients that do not support dynamic updates on the DNS tab of the DHCP console. Whether your UNIX DHCP server can do this depends on the vendor. The HP-UX 11 server does not support registering with DNS. The Internet Software Consortium (ISC) DHCP distribution 3.0, in beta, will support DNS.
