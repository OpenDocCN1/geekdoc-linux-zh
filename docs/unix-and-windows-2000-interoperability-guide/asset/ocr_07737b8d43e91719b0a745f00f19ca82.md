exec stream tcp nowait root /usr/bin/rexec rexcd

If there is a pound sign (#) at the beginning of this line, remove it and run the inetd -c command.

On Windows 2000, the syntax for Rexec command is the same as that for Rsh:
rexec [-l user_name] [-n] command

If you do not specify a user name when issuing this command, the HP-UX system will assume that your user name be the same as your Windows 2000 user name. If it is, then you can simply press Enter and then type your password. In the case of Rsh and Rcp, it is important to verify that you do not specify a user name with the -l option, your logged-in Windows-2000 user name must match your HP-UX user name, letter-by-letter, case-by-case.

The -n option, as it does with Rsh, redirects the input of Rexec to NUL. See the syntax of Rsh for more information.

# 9.61 Examples

If you are logged on Windows 2000 as dylan and your HP-UX system account is called dylan, then you can execute a Rexec command without the -l user_name parameter:

```
C:>rexec hpx1 dylan
Name (hpx1.book.local:dylan):
Password (hpx1.book.local:dylan):
Wed Oct 25 20:44:01 PDT 2000
```

If you are logged on Windows 2000 with an account that does not exist on HP-UX (such as Administrator), you must supply a different user name (such as root). For example:

```
C:>rexec hpx1 dylan
Name (hpx1.book.local:Administrator): root
Password (hpx1.book.local:Administrator):
Wed Oct 25 20:53:05 PDT 2000
```

If you supply a user name, then you are not prompted for a user name:

```
C:>rexec hpx1 -l dylan date
Password (hpx1.book.local:)
Wed Oct 25 20:55:09 PDT 2000
```

As with Rsh, if you use any command redirection using the > >> symbols, you must quote them if you want redirection to take place on the remote system.

```
C:>rexec hpx1 -l root cat /profile ">" /tmp/root_profile
Password (hpx1.book.local:)
```

This command, issued on a Windows 2000 system, instructs the HP-UX system to concatenate (using the HP-UX cat command) the contents of /profile to a file called /root_profile on the HP-UX system. In the UNIX world, the cat command is equivalent to the Windows type command). If you don't see any error messages, you can assume your redirection command worked.
