
You can set the MTU of a network adapter manually by changing the value of the following Registry parameter:

```
HKLM\System\CurrentControlSet\Services\Tcpip\Parameters\Interfaces\n<interface-name>=MTU
```

Setting a value for this parameter will override anything discovered dynamically (provided, of course, that you have not disabled Path MTU discovery). But, according to the Windows 2000 Server Resource Kit, if you enter a value greater than the dynamically determined MTU, the system uses the value of the dynamically determined MTU instead. You can use this entry to reduce, not to increase, the size of the MTU.

## 4.2.9.2 HP-UX

By default, when a new routing entry is created for the local subnet, the Don't Fragment bit is never turned on. If the route is for a remote destination, the Don't Fragment bit is not initially set. Instead.

1. An ICMP Echo Request of full MTU size is generated and sent out with the Don't Fragment bit on.
2. The datagram that created the routing table entry is sent immediately without the Don't Fragment bit set.
3. If no response to the Echo Request is received, the Don't Fragment bit is never turned on for that route. If an ICMP Fragmentation Needed message is received from the Echo Request, the PMTU is reduced accordingly, and a new Echo Request with the new PMTU is sent. This process repeats as necessary. If a response to this Echo Request is received, the Don't Fragment bit is set for all future packets.

If you want the Don't Fragment bit set on all outgoing datagrams, issue the following command:

```
# ndd -set /dev/ip ip_pmtu_strategy 1
```

If you want to disable PMTU discovery, use 0 instead of 1 for the above command. Using the route -p pmtu command to set the PMTU for a static route in HP-UX: The -p pmtu option is only useful if you know the network topology well enough to choose an appropriate PMTU for a host or network route. If fragment a datagram to the MTU specified for the route on the local host before sending the datagram to the remote. If the PMTU specified in the route command is correct, it will avoid fragmentation by routers along the path. Using the -p pmtu option can simplify the maintenance of route when the same PMTU can be applied to all hosts on a network. However, this feature can result in poor network performance or connectivity problems if a network consists of multiple media with different PMTUs. Therefore, using the -p pmtu for a network route should be used with some caution. (For more information, see the Release Notes for HP-UX 11.0, Section 7.18.1.)

## Conclusion

In the first command, we specified 1472 as the data length because if we add the ICMP Echo Request (8 bytes) and the IP header (20 bytes), we get 1500, the MTU of Ethernet. By adding another byte in the second command (1473), we exceeded the Ethernet MTU and received ICMP error messages to that effect. You can specify the packet size in HP-UX with the -s parameter.

- In Windows 2000, the -t option means ping will continue without interruption. In HP-UX, it sets the time-to-live.
- In Windows 2000, the -a option resolves addresses to computer names. There is no -a option in HP-UX.
- Windows 2000 has a -i option to set the time-to-live. HP-UX uses the -t option.
- The -v option of Windows 2000 sets the type-of-service field to the value specified by tos; in HP-UX, it specifies verbose output, where ICMP packets other than Echo Responses are shown.
- The -r count option in Windows 2000 records the route of the outgoing packet and the returning packet in the field. In HP-UX, -r specifies to bypass the normal routing tables and send to a host on an attached network.
- Windows 2000 has a -s option, specifying the timestamp for the number of hops. HP-UX does not have a -s option.
- In Windows 2000, -j computer-list routes in loose-source mode by the list of computers, and -k computer-list routes in strict-source mode. The closest HP-UX equivalent is -o, which inserts IP Route in outgoing packets when the command terminates.
- Windows 2000 has a -w option, specifying the timeout interval in milliseconds. HP-UX does not have this option.
- Finally, if you ping from an HP-UX system and do not specify the number of pings with the -n count option, ping keeps sending until interrupted (Ctrl-C). Windows 2000 ping will continue only.

# CHAPTER 5: The Transport Layer

At the transport layer we have the connection-oriented Transmission Control Protocol (TCP) and the connectionless User Datagram Protocol (UDP). While both HP-UX and Windows 2000 implementations of TCP/IP interoperate, they differ significantly in the tunable parameters. This chapter briefly describes those parameters.

## 5.1 TCP

The TCP connection establishment process between HP-UX and Windows 2000 works per the standard:

1. The client sends a synchronize (SYN) segment to the server, specifying a port port and initial sequence number (ISN).
2. The server responds with a SYN segment containing its ISN and an acknowledgment (ACK) containing the client's ISN plus one.
3. The client acknowledges the server's SYN segment by acknowledging the server's ISN plus one.

TCP ports are well-defined and standardized. The common TCP ports are listed in Table 5–1. Windows 2000 networking services are often NetBIOS-based, making TCP port 139 an important one.

### Table 5–1 Commonly Used TCP Ports

| Service Name | Port |
| :--- | :--- |
| FTP (Data Channel) | 20 |
| FTP (Control Channel) | 21 |
| Telnet | 23 |
| HTTP | 80 |
| NetBIOS session service | 139 |

### 5.1.1 Tunable Parameters

#### 5.1.1.1 Maximum Segment Size (MSS) and Path MTU Discovery

In Chapter 4, “The Internet Layer,” we talked about Path maximum transmission unit (MTU) discovery, in which the Don't Fragment bit in the IP header is sent to see if any router along the path returns an Internet Control Message Protocol (ICMP) error. TCP handles Path MTU discovery during connection setup, when each side can announce its maximum segment size (MSS). If the receiving end does not announce its MSS, TCP on the sending station will use one of 536 bytes. By that point, TCP will send IP datagrams with the Don't Fragment bit set. If a router returns ICMP Destination Unreachable-Fragmentation Needed, TCP will start adjusting its MSS until no more messages are received.

By default, Windows 2000 sends TCP segments with the Don't Fragment flag set in the IP header. Therefore, Windows 2000-initiated TCP sessions automatically participate in MTU discovery. Windows 2000 will adjust the TCP MSS to the MTU of the router indicated in the ICMP Destination Unreachable-Fragmentation Needed message.

HP-UX TCP on HP-UX will also adjust its MSS from ICMP Destination Unreachable-Fragmentation Needed messages. This is the default. To disable this behavior, use the following command:

```
# ndd -set /dev/tcp tcp_ignore_path_mtu 1
```

If you run the above command, TCP will default to an MTU of 576 bytes (536-byte MSS plus 40 bytes for the IP and TCP headers).
