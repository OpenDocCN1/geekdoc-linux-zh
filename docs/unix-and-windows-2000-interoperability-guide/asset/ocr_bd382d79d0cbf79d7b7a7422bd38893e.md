system password and store it in the /var/opt/samba/private directory as a file with a
name in the following format: domain_name.server_name.mac. In my example, the
name is BOOK.LOCAL.HPUX1.mac. (The Mac extension means that this is a machine
account.)

Edit your smb.conf file and specify the following variables:

+   * security = domain
* netbios name = server_netbios_name
* workgroup = domain_name
* password server = domain_controller_name(s)
* encrypt passwords = yes

For example, my smb.conf contains the following entries for these variables, as well as
for a couple of others:

```
[global]
workgroup = BOOK.LOCAL
netbios name = HPUX1
security = DOMAIN
encrypt passwords = Yes
password server = w2kserv
username map = /var/opt/samba/usermap
guest account = smbnull
read only = No
case sensitive = yes
```

As you can see, I specify the file /var/opt/samba/usermap to contain mappings of user
accounts whose names differ between the two operating systems. In my test environ-
ment, all my user account names match, with the exception of root and administrator.
So, in this file, I have only one entry:

```
root = administrator
```

I also specify smbnull for the guest account and case sensitivity.

+   Start the Samba daemons smbd and nmbd. With CIFS/9000, you do so by executing the
following command:

```
# /opt/samba/bin/startsmb
```
