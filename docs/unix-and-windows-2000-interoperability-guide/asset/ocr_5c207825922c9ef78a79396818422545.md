# A Word About Terminals and Emulation

Telnet originated in the UNIX world. The first terminals in the UNIX world were teletypes, essentially typewriters/printers, which connected to computers via serial ports. In time, CRTs replaced these teletypes, too were serial devices that first emulated teletypes and then had their own features. Many versions of these terminals exist, each with its own set of capabilities.

For each terminal you configure on a UNIX system, you must have a get process running on each terminal port. This process sets up the port's initial characteristics and prompts for a login session. On HP-UX systems, the get process sets up the terminal when logging into file /etc/getdefs to set up speed and minimal settings. The command tset sets up the terminal when logging into an HP-UX system. It does terminal-dependent processing, such as setting erase and kill characters, or resetting delays, and any sequences needed to properly initialize the terminal. It first determines the type of terminal involved, and then does the necessary initializations and modes. The type of terminal attached to each HP-UX port is specified in the /etc/tty database. Type names for terminals can be found in the files using the /usr/share/libterminfo directory. Programs such as vi and the text version of SAM know what terminal you are working on in order to behave properly. They consult the value of the TERM variable, set by the tset program upon login, to determine your terminal.

All processing is necessary for logging in and using physically attached terminals. Telnet is a method whereby you can log into and work on a remote system as if you were working on a physically attached system. It achieves this through a process called terminal emulation, where software produces a screen that pretends to be a terminal. You type commands in screen sent to the remote system, and the output of those commands are sent back to your screen. Widely emulated terminal types include VT52, VT100, and ANSI. With Telnet, you open a terminal emulator and use it to connect to a remote system over the network.
