## 12.4.1.2 How It Works

We have our CIFS/9000 member of a Windows 2000 domain. By configuring smb.conf the way we have, we specify that client requests to the CIFS/9000 server will first be authenticated by the Windows 2000 domain controller. On top of all that, we have our Windows 2000 domain controller running for NIS.

In my environment, this setup works well. If I log into a Windows 2000 client as an everyday user, say dylan, the domain controller authenticates me, as you would expect. Then, when I browse the network, I click on the book.local domain icon. One of the servers I see is hpux. My CIFS/9000 server. Double-clicking on that icon shows me a list of shares available. In my initial configuration, the only share I see is one called dylan. Where did it come from?

By default, CIFS provides a shared definition called home in smb.conf. If a user's home directory exists on the server, it will create a temporary share configured with the parameters from the home definitions so that the user can access that home directory. How does it determine the home directory? Either by scanning /etc/passwd or consulting an NIS map. In my case, the user dylan is defined in an NIS map maintained by Server for NIS. I created this user using Active Directory for Users and Computers, being the UNIX Attributes so that dylan was defined in NIS as well. See Figure 12-2.

Therefore, upon logging in as dylan, CIFS/9000 sees that dylan's home directory actually exists on the CIFS/9000 server, a share with the name dylan is created. Here is an important point. All Windows 2000 users whose home-directories are to be served by CIFS/9000 must actually have those directories created for them by the root user. For example, when creating a new user account lucky, I used Active Directory Users and Computers to do so. However, I also had to issue the following commands as root on hpux, my CIFS/9000 server:

```
# cd home
# mkdir lucy
# chown lucy:tech lucy
# ls -l
total 6
drwxrxr-x 3 dylan tech 1024 Dec 22 05:30 dylan
drwxrxr-x 4 hilary tech 1024 Dec 21 22:19 hilary
drwxrxr-x 2 lucky tech 1024 Dec 22 05:54 lucky
```

With what I have described so far, we have two home directories for users: one defined in the user’s UNIX Attributes and residing on an HP-UX system, and another as yet undefined but defaulting to the root directory of the Windows 2000 system they are logging onto. If you want to unify your home directories, specify the appropriate CIFS/9000 share in the Profile page of Active Directory Users and Computers, as shown in Figure 12–3. When the dylan user logs on, there will be a Z: drive pointing to to his home directory on the CIFS/9000 server. Also, when he opens a command prompt, it will open to this share.

The scenario just described works quite well but should be viewed as a proof-of-concept only. There are probably a number of gotchas here. But the point is that by combining CIFS/9000 with Server for NIS, you can achieve a great deal of interoperability. For one thing, you have only one authenticating authority. For another, you can have both your Windows users and their NIS counterparts specified in a single location. You can also have single home directory whether the user logs from a Windows system or an HP-UX system. In our example, the user *dylan* logged on from Windows 2000. However, if that user logs on to *hpux1* (an NIS client), then his user information, including account name, home directory, and login shell, are obtained from NIS, and he gains access to his system normally. This combination is certainly worth further study!

## 12.5 CIFS/9000 Client in a Windows 2000 Domain

Now we can go in the other direction. By using the CIFS/9000 client, we can access files located on a Windows 2000 system. While smclient is installed with the CIFS/9000 package, the client portion is not Samba-based. As we previously discussed with the CIFS/9000 server, we will create a scenario of using the client and learn the complete description of the product to HP's official documentation, Installing and Administering the CIFS/9000 Client.

In this scenario, we have some engineers who still need to use HP-UX workstations to run their CAD application. While they use HP-UX workstations periodically, they do most of their work on Windows 2000. To access files on the Windows 2000 server, they will use the CIFS/9000 client. Occasionally, while working on HP-UX workstations, they want to access the 2000 server. To make this possible, we will use the CIFS/9000 client.

So, from whatever Windows 2000 client dylan logs on, his home directory will be found in the Z: drive, which actually resides on wkserv. The next step, then, is to share the home directory. We could share each individual's home directory, but that could create an excessive number of shares, depending on how many users you have. Also, CIFS/9000 does not support automounting, so if you had multiple users, you would have to make static mounts for each workstation.

In order to share one directory, namely home, in a way that everyone has access to the home directory, you have to give Full Control permissions to Everyone when you create the share. See Figure 12–5.

![](img/1c1e7552b53cca888836b6c6895bdb48_214_0.png)

Figure 12–5 Granting Full Control to Everyone for the home share.

At first, there appears to be a problem here. If we give Everyone the Full Control share permission, do we not compromise the security of home's subdirectories? However, in order to secure each user's home directories, we must ensure that those directories reside on NTFS volumes and then assign the appropriate NTFS permissions. Done properly, all CIFS/9000 clients will be able to access the home share, but each subdirectory within that share will be protected by NTFS permissions.

In our example, we secure the Dylan subfolder of the home directory by right-clicking on its icon, choosing Properties, and then clicking the Security tab (see Figure 12–6).

Note that only Dylan has permissions to control this folder. This will keep others from messing with this folder despite the fact that Everyone has Full Control permission on the home share.
