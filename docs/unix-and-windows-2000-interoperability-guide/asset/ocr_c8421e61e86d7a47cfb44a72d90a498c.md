NFS clients make requests to the file server's NFS server in the same manner as they always do: via Remote Procedure Calls (RPCs) containing the UID and GID of the user making the request. The file server's NFS server validates each request, using either files or NIS. The CIFS server authenticates CIFS client requests with NTLM 0.12 authentication, not Kerberos, and must operate with Windows 2000 servers authenticating in mixed mode, that is, both NTLM and Kerberos. The Cerra file server does not do any CIFS authenticating but instead forwards authentication requests to domain controllers. Thus the file server runs as a member server only.

# 13.1.2 Benefits of NAS

NAS makes it possible for both UNIX and Windows clients to access the same data without the use of general-purpose servers. This performance is quite high. NAS can provide a great deal more reliability and availability as well, particularly if the file servers connect storage arrays such as Symmetrix. NAS helps to eliminate data duplication by consolidating data on a single platform, making management and backup much easier. As long as the amounts of data used by users throughout the world continue to grow, and as long as there are heterogeneous clients needing to access this data, NAS is a very attractive form of UNIX and Windows 2000 interoperability.

# 13.2 The X Window System

One important way for UNIX and Windows 2000 systems to operate is to employ the X Window System. Originally developed for UNIX systems by MIT, the X Window System (X, for short) is a graphical window system that separates an application from the display server. In other words, applications, known as X clients, can run in one place but have their displays elsewhere on the network. These displays run X server software that accepts instructions from the clients, creating little traffic in so doing. Figure 13–3 illustrates the system. In this diagram we see what is known as X terminals, diskless systems dedicated to running X servers. By placing X server software on your workstation, you are effect installing X terminal emulator.

With X, you can have true application servers in your environment. In other words, you can have more powerful server applications for you; they simply display the application at your desktop. Running an application via NFS or CIFS is not the same thing, because your local CPU is doing the work while you run the program. By using X, the remote system does the processing while the local system does the display. A rough parallel to this way of doing things can be found in the World Wide Web, where a browser sends instructions to applications on remote servers that process the input and display the results back to the browser.

The main benefit of X in a mixed UNIX and Windows environment is that you don't have to worry about porting key applications from one platform to another.
