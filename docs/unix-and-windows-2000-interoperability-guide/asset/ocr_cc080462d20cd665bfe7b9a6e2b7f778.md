The next screen, the Location of UNIX NIS Map Source Files screen, simply asks for the location of the source files to migrate. In my case, I copied them via FTP to a directory called DWIS. The Destination Domain for migration follows (see Figure 10–9). By default, the Migration Wizard will migrate maps to an NIS domain that is the same name as the Windows 2000 domain. Microsoft also recommends that you use the default Active Directory container for migration. Otherwise, some objects will not appear in the Active Directory Users and Computers MMC.

The Migration Wizard then asks how you will handle conflicts during the migration. Active Directory may already contain objects that exist in the NIS maps being. If, for example, you have a user with accounts in both the Windows 2000 and the UNIX NIS networks, and that account name is the same, then you will have a conflict. Your choices will be to keep the existing entry, replace the existing entry with the new entry, and/report the conflict. The Migration Wizard will run in “dummy mode” first so that you can view the log files for conflicts you may want to resolve before actually performing the migration.
