# 4.1 ARP

IP uses a 32-bit addressing scheme to send datagrams. However, these addresses are logical; in other words, they are not tied to a particular system. In fact, in Dynamic Host Configuration Protocol (DHCP) environments IP addresses for particular machines change all the time. (We will talk about DHCP later.) IP must respond on a protocol that sits between and the network interface layer to find the physical hardware address of a machine. That protocol is the Address Resolution Protocol, or ARP.

Let's assume your network is Ethernet. Ethernet sends frames to other systems using the 48-bit hardware address burned into the NIC (MAC address). When IP sends a datagram to Ethernet for delivery, that datagram contains the destination IP address. Since Ethernet does not understand IP addresses, it uses ARP to determine the appropriate hardware address of the machine owning the destination IP address, and once does so, delivers the frame. ARP then goes through the broadcast mechanism again. Cache entries for frequently destinations do not have to go through the broadcast last up to 10 minutes in Windows 2000, five minutes on HP-UX. Static entries do not expire.

ARP sends an ARP request in the form of a broadcast to find the hardware address of the destination system. All systems on the network hear this request, but only the owner of the destination IP address will respond with an ARP request containing its hardware address. If the IP address belongs to a system on a remote network, then the first-hop router will reply to the ARP request, though the ultimate destination may be several routers away. This service is known as proxy ARP.

# 4.1.1 Viewing the ARP Cache

### 4.1.1.1 Windows 2000

To view the ARP cache in Windows 2000, use the arp -a command. For example:

```
C:\>arp
```

| Interface: 10.0.0.3 on Interface 0x2 | | |
| :--- | :--- | :--- |
| Internet Address | Physical Address | Type |
| 10.0.0.4 | 08-00-09-83-31-b1 | dynamic |
| 10.0.0.5 | 08-00-5a-d8-1e-a9 | dynamic |
| 10.10.1.1 | 00-60-b0-6a-8e-9c | dynamic |

ARP Here you see that all four cache entries are labeled *dynamic*: that is, they are acquired automatically, without user intervention. Dynamic entries last for a maximum of 10 minutes. You can see the expiration time of unreferenced entries by changing the value of the following Registry entries in

```
HKLM\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters\ArpCacheLife\ArpCacheMinReferencedLife
```

Notice that the hardware addresses are given as six hexadecimal bytes separated by dashes. HP-UX requires the use of colons:

### 4.1.1.2 HP-UX

HP-UX also has the *arp -a* command, but the output is different.

```
# arp -a
houyhhnmm.book.local (10.0.0.3) at 0:8:0:a36:f7 ether
aix1.book.local (10.0.0.5) at 8:5a:d8:e1-a9 ether
```

Notice that HP-UX provides the host name as well as the IP address for each entry. Also, note that the hardware addresses are given as six hexadecimal bytes separated by colons. By default, dynamic ARP cache entries stay in the cache for five minutes. To change this parameter, use the *ndd -set /dev/arp arp_cleanup_interval* command, specifying the interval in milliseconds. For example, the first command will set the ARP cleanup interval to six minutes; the second will display the new value:

```
# ndd -set /dev/arp arp_cleanup_interval 360000
# ndd -get /dev/arp arp_cleanup_interval
```

# 4.1.2 Deleting ARP Cache Entries

### 4.1.2.1 Windows 2000

In Windows 2000, do *arp -a* to find the entry you want to delete and then supply only the IP address to the *arp -d* command. For example:

```
C:\arp -a
```

| Interface: 10.0.0.3 on Interface 0x2 | | |
| :--- | :--- | :--- |
| Internet Address | Physical Address | Type |
| 10.0.0.5 | 08-00-5a-d8-e1-a9 | dynamic |
| 10.0.0.4 | 08-00-09-83-31-b | dynamic |
| 10.0.10.1 | 00-60-b0-6a-8e-9c | dynamic |

```
C:\arp -d 10.0.0.4
C:\>arp -a
```

| Interface: 10.0.0.3 on Interface 0x2 | | |
| :--- | :--- | :--- |
| Internet Address | Physical Address | Type |
| 10.0.0.5 | 08-00-5a-d8-1e-a9 | dynamic |
| 10.10.1.1 | 00-60-b0-6a-8e-9c | dynamic |

### 4.1.2.2 HP-UX

HP-UX requires that you provide the host name of the entry to be deleted, not the IP address, as in Windows 2000.

```
# arp -d w2kserv.book.local
w2kserv.book.local (10.10.1.1) deleted
```

### 4.1.3.1 Windows 2000

In Windows 2000, use the arp -s command. You must supply both the IP address and the hard-ware address.

```

```

```

### 4.1.3.2 HP-UX

HP-UX also has the arp -s command.

```
# arp -s w2kserv.book.local 00:60:b0:6a:8e:9c
# arp -a
w2kserv.book.local (10.10.1.1) 00:60:b0:6a:8e:9c
houyhhnmm.book.local (10.0.0.3) at 0:8:0:a36:f7 ether
aix1.book.local (10.0.0.5) at 8:5a:d8:e1-a9 ether

Note that static entries in HP-UX are permanent.

# 4.1.4 Gratuitous ARP

### 4.1.4.1 Windows 2000

Windows 2000 supports gratuitous ARP, sending ARP requests upon startup check to see if the IP address being configured exists on the local network. The number of requests is sent in the following Registry entry:

```
HKLM\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters\ArpRetryCount
```

If a duplicate exists, Windows 2000 disables the interface of the booting machine.

### 4.1.4.2 HP-UX

HP-UX also supports gratuitous ARP. However, unlike Windows 2000, HP-UX does not disable the interface of the machine.

# 4.2 IP

At the internet layer, IP is the key protocol. It sends and receives packets, known as datagrams, using a 32-bit addressing scheme. As a system administrator, you should already know something about IP addressing and subnet masking, so we won't go into any details here. However, if you'd like more information about addressing, two excellent references are W. Rich-Stevens', TCP/IP Illustrated, Volume I (Addison-Wesley Publishing Company, 1994) and Microsoft Corporation’s, Microsoft Windows 2000 Server TCP/IP Core Networking Guide (Microsoft Press, 2000).

# 4.2.1 Configuring IP

### 4.2.1.1 Windows 2000

Windows 2000 Professional defaults to using DHCP when you install the system. DHCP typically provides each client with an IP address, subnet mask, and a default gateway, as well as other parameters. However, if you are not using DHCP—for example, when installing a domain controller—then you must enter the IP information in the Internet Protocol (TCP/IP) Properties box. (see Figure 4–1).

### 4.2.1.2 HP-UX

You can do the following to configure IP on HP-UX:

- Use the command line. Command-line changes are not permanent.
- Edit system startup files. Changes you make to these files do not take effect until you reboot the system.
- Use SAM. This will make changes to the system and ensure the proper entries are placed in the startup file.
- Use the *set_parms* script.
