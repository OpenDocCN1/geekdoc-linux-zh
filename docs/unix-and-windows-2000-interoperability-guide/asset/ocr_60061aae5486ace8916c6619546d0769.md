# 10.1 Telnet Client

The SFU Telnet Client's command has options the bundled client does not have. The syntax of the former is

```
telnet [-a] [-e escapeChar] [-f logfile] [-l user] [-t term] [host [port]]
```

The -a and -l options attempt an automatic login, which works only when the Telnet server supports the ENVIRON option. In my attempts to connect to either HP-UX 11 or Solaris 8 using those options, I found that the Telnet servers on both systems did not recognize the ENVIRON option. You can set the escape character (the keyboard sequence that takes you to the Microsoft Telnet> prompt while connected) to something other than the default CTRL+ with the -e option. You can set up a connection log file with the -f option. The log file you specify records the input and output of your Telnet session. For this Telnet client is VT100. If you want to specify a different one, use the -l option with VT52, ANSI, and VTNT as the terminal type. You can specify a host name or an IP address to connect to the remote system, as well as a port number if you do not use the default port of 23.

Telnet subcommands are also a bit different from the standard Telnet client. Listed in Table 10–1 are the subcommands documented by Microsoft. I've also indicated the command abbreviations in parentheses.

| Table 10–1 SFU Telnet Client Subcommands |
|---|---|
| open (o) | Establishes a Telnet connection to a host. |
| close (c) | Closes an existing Telnet connection. |
| display (d) | Produces a list of current settings for the Telnet client. |
| quit (q) | Exits from Telnet. |
| set | Sets the terminal type for the connection, turns on local echo, sets authentication to NTLM, sets the escape character, and sets up logging. |
| unset (u) | Turns off local echo or NTLM authentication. |
| status | Determines whether the Telnet client is connected. |

The display subcommand of the SFU Telnet Client provides the following output:

```
Microsoft Telnet> d
Escape Character is 'CTRL+'
Will auth (ntlm Authentication)
```
