# 8.1.2 Remote Logon

Remote logon is also known as network authentication. In other words, you have already gained access to your workstation: you now want to access resources on the network. With share-level security, you have to enter a password to a dialog box to access the server, even though you have already logged on. With user-level security, you perform interactive logon only once. Thereafter, a behind-the-scenes mechanism takes place to authenticate the service, acting on your behalf. After all, that is what takes place with network services. A network client runs on your behalf and somehow has to prove it to the network server. Exactly how this takes place depends on the protocol.

# 8.1.2.1 NTLM

NTLM uses a challenge-response protocol at connection time, for example, when a user attempts to map a network drive. When a server receives a connection request, the server authenticates the user by issuing a challenge (bytes chosen at random) to the client. The client encrypts this challenge with a hash of the user's password and returns the whole thing to the server. The server takes this information and contacts the domain controller to verify the user's identity. If verification is successful, the domain controller sends the user's SIDs, and the LSA on the server turns builds a security access token based on those SIDs. The server can then use the access token to determine whether to grant the user's request to access one of its shares.

The key point to remember in this process is that user authentication in a remote logon is the responsibility of the server, not the client. The server must contact the domain controller to verify the identity of the user.
