#  5.1.1 Tunable Parameters

5.1.1.1 Maximum Segment Size (MSS) and Path MTU Discovery
In Chapter 4, “The Internet Layer,” we talked about Path maximum transmission unit (MTU) discovery, in which the Don't Fragment bit in the IP header is sent to see if any router along the path returns an Internet Control Message Protocol (ICMP) error. TCP handles Path MTU discovery during connection setup, when each side can announce its maximum segment size (MSS). If the receiving end does not announce its MSS, TCP on the sending station will use one of 536 bytes. By that point, TCP will send IP datagrams with the Don't Fragment bit set. If a router returns ICMP Destination Unreachable-Fragmentation Needed, TCP will start adjusting its MSS until no more messages are received.

By default, Windows 2000 sends TCP segments with the Don't Fragment flag set in the IP header. Therefore, Windows 2000-initiated TCP sessions automatically participate in MTU discovery. Windows 2000 will adjust the TCP MSS to the MTU of the router indicated in the ICMP Destination Unreachable-Fragmentation Needed message.

HP-UX TCP on HP-UX will also adjust its MSS from ICMP Destination Unreachable-Fragmentation Needed messages. This is the default. To disable this behavior, use the following command:

```
# nd -set /dev/tcp tcp_ignore_path_mtu 1
```

If you run the above command, TCP will default to an MTU of 576 bytes (536-byte MSS plus 40 bytes for the IP and TCP headers).
