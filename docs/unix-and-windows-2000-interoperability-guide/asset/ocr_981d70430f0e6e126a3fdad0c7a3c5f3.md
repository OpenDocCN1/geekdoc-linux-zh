As you can see, the dation and dlogin applications specify libpam_ntlm. This permits me to log into CDE (See Figure 8–2.) Once I have logged in, I can run the passwd command: If I do so, passwd will change my password on the Windows 2000 domain controller. If I want to access a share on a Windows 2000 server, I do not have to run the cflogin utility first because I will have already been authenticated via NTLM. In other words, my interactive login takes place at the CDE login screen; my network login (remote login) takes place behind the scenes, as described in the Windows 2000 section of this chapter.

Using NTLM in this manner provides a single sign-on capability in that a single Windows 2000 domain controller maintains login and password management. However, it would be incorrect to think that you have a unified user account management system. In order for you to do anything on your HP-UX system (commands, utilities, applications), you have to have a user account on that system. To log in you have to have another account on your Windows 2000 domain controller. In other words, if you have a new user to your network, you will have to create an HP-UX account and a Windows 2000 domain account. To make this form of interoperability easier, you should keep the user names the same on both systems. Otherwise, you have to maintain a user map file. This maps HP-UX user names to Windows 2000 domain user names so that when you log in to HPUX, PAM NTLM knows what Windows 2000 user name to use when authenticating. You will probably need to have this file regardless of whether user names match in at least one case—the administrative account—you will have two different names: root for HP-UX and administrator for Windows 2000.

For more detailed information on PAM NTLM, consult Installing and Administering the CIFS/9000 Client, available at docs.hp.com.
