# 6.4.3 The DNS Server

UNIX systems typically employ some version of BIND as their DNS server. Windows 2000 DNS is a different piece of software. While both BIND and Windows 2000 DNS are RFC-compliant, there are some important differences between the two:

+   * Dynamic updates support
* WINS and DNS integration
* Active Directory support

6.4.3.1 Dynamic Updates
Windows 2000 DNS supports dynamic updates, which is the ability to register new systems and their IP addresses automatically in the DNS database. BIND version 8.1.2 or later also supports dynamic updates; however, many UNIX systems still run BIND 4.9.7, which does not. If your current implementation of DNS does not support dynamic updates, you should disable client-side registration by clearing the Register this connection's addresses in DNS box in the Advanced TCP/IP Settings. (See Figure 6–5.) This will keep your DNS servers from being bombarded with registration requests from your clients.

6.4.3.2 WINS
Windows 2000 DNS can be configured to query a WINS server should it fail to find a client's request. The DNS server then passes on the response to the client on behalf of the WINS server. The resource records that support this functionality—WINS and WINS-R—are found only in Windows 2000 DNS servers.

6.4.3.3 Active Directory
If your DNS service not run on a Windows 2000 server, then you must make sure that the service supports the SRV (service location) resource record in order to support Active Directory. BIND 4.9.6 and later support SRV resource records. According to Microsoft, if you use a third-party server, however, you cannot use the DNS console or Dnscmd.exe.
