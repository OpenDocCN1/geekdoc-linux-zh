# Table 2–3 NTFS File Permissions⁴

| NTFS File Permission | Allows the User To |
|---|---|
| Read | Read the file and view file attributes, ownership, and permissions. |
| Write | Overwrite the file, change file attributes, and view file ownership permissions. |
| Read & Execute | Run applications *plus* perform the actions permitted by the Read permission. |
| Modify | Modify and delete the file *plus* perform the actions permitted by the Write permission and the Read & Execute permission. |
|Full Control | Change permissions and take ownership *plus* perform the actions permitted by all other NTFS file permissions. |

# 2.3.8 Networking

In the beginning, there was LAN Manager. This product product provided part of the foundation of Windows NT 3.1 Advanced Server. (Taken from *Introducing Microsoft Windows 2000 Server*, p. iii³) Microsoft announced LAN Manager in 1987. This networking product ran natively over the NetBIOS Frames Protocol (NBF), which is actually a set of protocols also known as NetBEUI. The term NetBIOS refers to a networking API developed by Sytec, Inc., for IBM. LAN Manager provided a number of network services for the PC that used the NetBIOS API and ran over NetBEUI.

RFC 1001, “Protocol Standard for a NetBIOS Service on a TCP/UDP Transport,” was published in 1987. When Microsoft released Windows NT 3.1 in 1993, its networking services were based on LAN Manager. In other words, there were NetBIOS services. These services ran over only NetBEUI, but IPX/SPX and TCP/IP as well. Because NetBEUI was designed for a LAN—it was not routable—and because of the growing interest in inter-LAN communication and the Internet, the default transport mechanism for Windows NT 4.0 networking services was TCP/IP.
