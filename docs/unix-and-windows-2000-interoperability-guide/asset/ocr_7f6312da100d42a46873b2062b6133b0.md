# Chapter 6 • Name Resolution

• FQDNs. These are names terminated with a period (for example, mysystem.emc.com).
These names are immediately submitted to DNS.

• Multiple-label, unqualified domain names. These either look like FQDNs without a terminating period (for example, mysystem.emc) or incomplete FQDNs (for example, mysystem.emc). In the former, the resolver appends a period to create an FQDN and then submits the name to DNS. In the latter, it appends DNS suffixes (specifiable by the user) and submits each to DNS until resolution succeeds. The user can specify what suffixes to add on the DNS tab in the Advanced TCP/IP Settings dialog box (see Figure 6–3). If there are no entries in this table, the resolver uses the primary DNS suffixes specified on the Network Identification tab of the System Properties dialog box. (Click on the System icon in the Control Panel).

• Single-label, unqualified domain names. These are simply host names (for example, mysystem). In this case, the resolver appends DNS suffixes in the manner described in the previous bullet until resolution succeeds.

For both types of unqualified domain names, the DHCP server can set the primary DNS suffix and the connection-specific DNS suffix. The DNS name resolution process can be quite complex. For more information, including some excellent flow charts illustrating the process, see the Microsoft Windows 2000 Server TCP/IP Core Networking Guide, pp. 344–354.

The Windows 2000 resolver caches information received from a DNS query, be it positive (host found) or negative (host name not found). After undergoing name transformation as previously described, if needed, all queries first go through this cache. The DNS cache also contains the entries in the HOSTS file, loaded automatically upon system startup. The following options to the ipconfig command affect the DNS cache:

+   /flushdns Removes all entries from the DNS cache.
/displaydns Displays the contents of the DNS cache.

You can set the length of time that positive and negative responses are cached by editing the Registry entries:

```
HKLM\SYSTEM\CurrentControlSet\Services\DNSCache\ParametersMaxCache
EntryTtl1Limit
```

```
HKLM\SYSTEM\CurrentControlSet\DNSCache\ParametersNegativeCacheTime
```

The default for positive responses is 86,400 seconds (24 hours) for negative, 300 seconds.
