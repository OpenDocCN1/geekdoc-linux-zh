```
# PAM Configuration
#
# Account Management
dction account required /usr/lib/security/libpam_unix.1
dlogin account required /usr/lib/security/libpam_unix.1
ftp account required /usr/lib/security/libpam_unix.1
login account required /usr/lib/security/libpam_unix.1
su account required /usr/lib/security/libpam_unix.1
OTHER account required /usr/lib/security/libpam_unix.1
# Authentication Management
dction auth required /usr/lib/security/libpam_krb5.1
dlogin auth required /usr/lib/security/libpam_krb5.1
ftp auth required /usr/lib/security/libpam_unix.1
login auth required /usr/lib/security/libpam_unix.1
su auth required /usr/lib/security/libpam_unix.1
OTHER auth required /usr/lib/security/libpam_unix.1
# Password Management
dction password required /usr/lib/security/libpam_unix.1
dlogin password required /usr/lib/security/libpam_unix.1
login password required /usr/lib/security/libpam_unix.1
asswd password required /usr/lib/security/libpam_unix.1
OTHER password required /usr/lib/security/libpam_unix.1
# Session Management
dction session required /usr/lib/security/libpam_unix.1
dlogin session required /usr/lib/security/libpam_unix.1
login session required /usr/lib/security/libpam_unix.1
OTHER session required /usr/lib/security/libpam_unix.1
```

Since up Kerberos authentication is more involved, you might consider using PAM NTLM instead, since Windows 2000 domain controllers can indeed authenticate with NTLM for mixed environments.

Also, since account management and session management are not defined under Kerberos, you don't have to configure the Account Management and Session Management functions. They are provided only for compatibility with the PAM specification. One thing to watch out for PAM Kerberos is that there is no user-mapping file. Therefore, you need a user called root on the Windows KDC if you want that account to be authenticated by that name. Other
