# 10.2.5 Connecting to Telnet Server with UNIX Telnet Clients

Though I have used an HP-UX system to provide most of the UNIX examples in this book, I found the behavior of other UNIX Telnet clients to be worth mentioning. To illustrate each process, I've used the toggle options subcommand with the UNIX Telnet clients.

10.2.5.1 AIX

With both NTLM and plain text authentication enabled, I got the following output. Notice that the AIX received from the Windows 2000 Telnet server a message of do 37. (I've marked this in bold text.) This means that the Windows 2000 server wants the AIX to do authentication negotiation (in order to do NTLM authentication). The AIX responds (also marked in bold) that it won't do authentication negotiation (because it doesn't recognize or support it).

```
Trying.
Conected to w2kserv.book.local.
Escape character is '^'.
SEND DO ECHO
SEND DO SUPRESS GO AHEAD
SEND WILL TERMINAL TYPE (don't reply)
SEND DO SUPORT SAK
SEND WILL NEGOTIATE WINDOW SIZE (don't reply)
RCVD do 37 (reply)
SEND wout 37 (don't reply)
RCVD will ECHO (reply)
RCVD do ECHO (don't reply)
RCVD will SUPRES GO AHEAD (reply)
SEND DO SUPRES GO AHEAD (don't reply)
RCVD do 39 (reply)
SEND wout 39 (don't reply)
RCVD do NEGOTIATE WINDOW SIZE (don't reply)
SEND suboption TELOPT-NAWS Width 91, Height 28
RCVD do BINARY (reply)
SEND WILL BINARY (don't reply)
RCVD will BINARY (reply)
SEND do BINARY (don't reply)
RCVD do TERMINAL TYPE (don't reply)
RCVD wout SUPORT SAK (don't reply)
Microsoft (R) Windows 20 (TM) Version 5.0 (Build 2195)
Welcome to Microsoft Telnet Service
Telnet Server Build 5.20.0412.1
login:
```

The result of this exchange is that the AIX client eventually gets a login prompt. With NTLM authentication disabled, the following exchange takes place:

```
Trying.
Conected to w2kserv.book.local.
Escape character is '^'.
SEND DO ECHO
```
