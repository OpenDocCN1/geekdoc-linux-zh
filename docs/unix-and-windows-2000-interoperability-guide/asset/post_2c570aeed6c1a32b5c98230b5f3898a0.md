### 2.3.6 Directory Tree

Though Windows 2000 is an entirely different operating system than DOS, it has inherited many of its characteristics, including a directory structure that has a letter at the root level. Unlike UNIX, there is no single root directory; there are, in fact, many root directories, 24 altogether (represented by the letters C–Z). This drive scheme also goes back to the days when PCs did not have hard drives, only floppies. Typically, a system had two floppy drives, one labeled A: and one labeled B:. You usually loaded your application, such as WordStar, from a floppy in drive A and kept your data files on the floppy in drive B. When hard disks begin to show up on these systems, they did not replace the A and B floppy drives. Therefore, the hard disk became the C: drive. The A and B letters are still reserved for floppies. Commonly found directories include

- **Documents and Settings.** This directory contains data and settings on the local computer. However, because of Microsoft's Intelli technology, both of these items can exist elsewhere on the network.

- **Program Files.** This contains applications installed on the local system. However, you can put applications on any drive and in any directory.

- **The value of the %SystemRoot% variable.** This is the directory that contains the Windows 2000 system files. You specify this location when you install the operating system; otherwise, the directory will be \WINNT.

### 2.3.7 File System Format

Windows 2000 supports the NTFS and two file allocation table (FAT) file systems: FAT16 and FAT32. The latter are available to allow dual booting of systems. However, the real workhorse of Windows 2000 file systems is NTFS. This file system offers a number of features and benefits and it is the only one you should consider if you are not dual booting and managing a network of more than just a few machines. Features of NTFS include the following:

- **File and folder-level security.** You can apply permissions on both files and directories, much like you do in UNIX.

- **Disk compression.** You can set an NTFS volume to be compressed to save disk space. Not all NTFS volumes have to be in a compressed state, however.

- **Disk quotas.** UNIX file systems have long supported quotas to keep a few users from eating most of a group's disk space. Windows 2000 NTFS allows you to do the same. You can set quotas for all users or for individuals.

- **Encryption.** Encryption is available for physical volumes and helps protect you if disk drives are stolen from any of your systems. It provides an additional security mechanism to access access control lists (ACLs).

### 2.3.7.1 NTFS Security and Permissions

When a user logs into a Windows 2000 system, the user is either authenticated locally or by a domain controller, depending on the account the user has. If the user is properly authenticated, the operating system creates an access token containing the user's security identifier (SID) and security settings. NTFS stores an ACL for each file and directory, much like a node in a UNIX file system. Each ACL contains an access control entry (ACE) for the user or group to which the user belongs and the associated permissions. For a user to access an object in the file system, the ACL for that object must contain an ACE for that user or his her group. That ACE in turn specifies what kind of access is to be granted.

As in UNIX file systems, NTFS permissions vary, depending on whether you apply them to folders or to files. Tables 2–2 and 2–3 summarize NTFS permissions. (Taken from the Microsoft Windows 2000 Beta Training Kit, pp. 384–5.)

#### Table 2–2 NTFS Folder Permissions³

| NTFS Folder Permission | Allows the User To |
|---|---|
| Read | See files and subfolders in the folder and view the folder ownership, permissions, and attributes. |
| Write | Create new files and subfolders within the folder, change folder attributes, and view folder ownership and permissions. |
| List Folder Contents | See the names of files and subfolders in the folder. |
| Read & Execute | Move through folders to reach other files and folders, even if the users do not have permission for those folders, and perform actions permitted by the Read permission and the List Folder Contents permission. |
| Modify | Delete the folder plus perform actions permitted by the Write permission and the Read & Execute permission. |
| Full Control | Change permissions, take ownership, and delete subfolders and files plus perform actions permitted by all other NTFS folder permissions. |

#### Table 2–3 NTFS File Permissions⁴

| NTFS File Permission | Allows the User To |
|---|---|
| Read | Read the file and view file attributes, ownership, and permissions. |
| Write | Overwrite the file, change file attributes, and view file ownership permissions. |
| Read & Execute | Run applications *plus* perform the actions permitted by the Read permission. |
| Modify | Modify and delete the file *plus* perform the actions permitted by the Write permission and the Read & Execute permission. |
| Full Control | Change permissions and take ownership *plus* perform the actions permitted by all other NTFS file permissions. |

### 2.3.8 Networking

In the beginning, there was LAN Manager. This product provided part of the foundation of Windows NT 3.1 Advanced Server. (Taken from *Introducing Microsoft Windows 2000 Server*, p. iii³) Microsoft announced LAN Manager in 1987. This networking product ran natively over the NetBIOS Frames Protocol (NBF), which is actually a set of protocols also known as NetBEUI. The term NetBIOS refers to a networking API developed by Sytec, Inc., for IBM. LAN Manager provided a number of network services for the PC that used the NetBIOS API and ran over NetBEUI.

RFC 1001, “Protocol Standard for a NetBIOS Service on a TCP/UDP Transport,” was published in 1987. When Microsoft released Windows NT 3.1 in 1993, its networking services were based on LAN Manager. However, NetBEUI was not routable—and because of the growing interest in inter-LAN, the default transport mechanism was TCP/IP. Windows 2000 offers something new with TCP/IP. According to the Microsoft Windows 2000 Server TCP/IP Core Guide, NetBIOS is not used for name resolution. DNS is used for name resolution and Windows 2000 directory and server components support direct communicating with other clients, such as Windows 95. By default, both NetBIOS and direct tried in parallel when a new connection is established.
