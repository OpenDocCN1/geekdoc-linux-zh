# Nslookup Differences

+   If the input host name does not end with a dot, BIND looks it up with domain names appended to it. The domain names BIND appends to it can be configured in four places: the LOCALDOMAIN environment variable, the hostname command, the search option in the `/etc/resolv.conf` file, and the domain option in the `/etc/resolv.conf` file. If a user has used the LOCALDOMAIN variable, as in the following example,

```
export LOCALDOMAIN=nmt.div.inc.com
```

the LOCALDOMAIN variable overrides the host name and any search or domain option in `/etc/resolv.conf` for BIND requests made within the context of the user's shell environment. The target host name is looked up in each of the domains in the variable, in the order they are listed.

If the local host name is set to an FDN, and the search and domain options are not specified in `/etc/resolv.conf`, the host name is looked up in the domain configured in the fully qualified host name.

The search option specifies a list of domains to search. You can set the search option to list any of domains, but the first domain in the list must be the domain of the local host. BIND looks up host names in each domain, in the order they are listed. BIND uses the search option only if the LOCALDOMAIN variable is not set.

The domain option specifies the local domain. If you use the domain option, BIND will only search the specified domain to resolve host names. BIND uses the domain option for host name lookups only if the LOCALDOMAIN is not set and the search is not specified. (Do not use the domain and search options together in the same `/etc/resolv.conf` file. If you do, the one that appears last in the file will be used, and any previous ones will be ignored.)

# 6.3 Nlookup Differences

The nslookup command works much the same way in both Windows 2000 and HP-UX. You can run it in interactive or non-interactive mode to query Internet domain servers. A key difference, however, is that in Windows 2000 nslookup queries DNS servers only, whereas in HP-UX it can also query /etc/hosts and NIS. Since NIS is not a Windows 2000 name service, you might expect it to consult the HOSTS file. This is not the case, however.

HP-UX, on the other hand, will follow the service switch, and nslookup will follow the directives of /etc/nsswitch.conf file. Therefore, if you follow the following entry:

```
hosts: files [NOTFOUND-continue] dns [NOTFOUND-return. UNAVAIL-return]
```

then nslookup will consult /etc/hosts first and DNS. For example,

```
# nslookup hp.com
Using /etc/hosts on: hpx11
```
