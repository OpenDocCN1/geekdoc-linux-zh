
1. The first connection request to a remote host advertises a receive window size of 16 kilobytes (KB) or 16,384 bytes.

2. Upon establishing the connection, the receive window size is rounded up to an integral multiple of the TCP MSS that was negotiated during connection setup.

3. If the rounded-up value is not at least four times the MSS, then it is adjusted to 4 × MSS, with a maximum size of 64 KB, unless a window-scaling option (RFC 1323) is in effect.

To override this process and set the window size manually, edit the following Registry-entry:

```
HKLM\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters\nInterface\<interface>\TcpWindowSize
```

HP-UX: The default maximum size for the receive window of time is 32,768 bytes. To specify another value, use the following command, where window_size is in:

```
# ndd -set /dev/tcp tcp_rec_hiwater_window_size
```

You can also set the maximum size for the receive window of "long, fat pipes" (Lfp), as Fibre Channel, using the ndd -set /dev/tcp tcp_rec_hiwater_lfp command. The default for this value is 65,536 bytes. For receive windows of "long, narrow pipes" (Inp), as PPP, use the ndd-set /dev/tcp tcp_rec_hiwater_inp command. The default here is 8,192 bytes.

### 5.1.1.3 TCP Keep-Alive Messages

You can set it at Windows 2000 TCP sends keep-alive messages on an inactive connection with the following Registry parameter:

```
HKLM\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters\KeepAliveTime
```

The default interval is 7,200,000 milliseconds (two hours). Often, applications like Telnet, rather than users, set up keep-alive messages.

In HP-UX, the following kernel parameters affect TCP behavior for keepalive packets:

- tcp_keepalive_interval
- tcp_ip_abort_interval
- tcp_ip_abort_cinterval
- tcp_keepalive_detached_interval

The parameter tcp_keepalive_interval determines the amount of time that TCP waits for an idle connection with no unacknowledged data before sending keep-alive packets. The default is two hours. You can use the ndd command to reset the default. The argument to this command is in milliseconds. For example, to set the keep-alive interval to three hours, you would type:

```
# ndd -set /dev/tcp tcp_keepalive_interval 10800000
```

If the remote system does not acknowledge the keep-alive packet, TCP will use one of the following retransmission timers and terminate the connection when it elapses:

| State | Timer | Default |
| --- | --- | --- |
| Established connection | tcp_ip_abort_interval | 60000 ms (10 minutes) |
| Connection establishment | tcp_ip_abort_cinterval | 240000 ms (4 minutes) |
| Connection termination | tcp_keepalive_detached_interval | 240000 ms (4 minutes) |

### 5.1.1.4 TCP-Time Wait Delay

By default, Windows 2000 maintains a socket pair for 240 seconds (four minutes) after the connection closes. To change this value, you edit the following Registry entry:
HKLM\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters\TcpWaitDelay

The value of this parameter can be anywhere from 30 to 300 seconds.
HP-UX, by default, maintains a time interval of 60 seconds for TCP endpoints to persist in a Time-Wait Delay. This value can be changed using the ndd -set /dev/tcp tcp_time_wait_interval command. This command's argument is specified in milliseconds, ranging from 100 milliseconds to 600,000 milliseconds.

### 5.1.2 Windows 2000-Only Tunable Parameters

Windows 2000 allows tuning of TCP using the Registry for which there are no HP-UX equivalents. Following is a list of some of these Registry entries. See the Registry Reference for more information.

- **TcpDelAcks.** Changes the ACK timer. The default is 200 milliseconds.
- **SacOpts.** Enables/disables selective acknowledgments (SACKs). The default is enabled.
- **TcpMaxDataRetransmissions.** Determines how many times TCP retransmits an unacknow data segment on an existing connection. TCP retransmits data segments until they are acknowledged, or until this value expires. The default is five.
- **TcpMaxConnectRetransmissions.** Determines how many times TCP retransmits an unanswered request for a new connection. TCP retransmits new connection requests until they are answered, or until this value expires. The default is two.
- **TcpMaxDupAcks.** Specifies how many duplicate ACKs (ACKs for the same sequence numbers) constitute a signal to retransmit a segment. The default is two.
