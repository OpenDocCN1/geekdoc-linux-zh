# 8.2.1 Basic Authentication

The file `\`/etc{/}passwd\` is a list of users known to the system. Each line of this file contains, among other things, a user's login name, encrypted password, user identifier (UID), and default group identifier (GID). Each UID is a simple integer and is unique so that the operating system can distinguish between users. If your system is part of a network (and most are these days), you must ensure that all UIDs are unique across the network. The `\**/etc{/}passwd\` file does not contain passwords; instead, it contains encrypted passwords created as password keys using a one-way hashing function `crypt()`. Crypt uses an algorithm based on the Data Encryption-Standard (DES) of the National Institute of Standards and Technology. More common these days is for a UNIX system to store the encrypted passwords in a separate file, usually called `\**/etc{/}shadow\` (as in “shadow password file”). Only the root user can read this file. Otherwise, ordinary users can obtain a list of the encrypted passwords, and using special programs, possibly determine the actual passwords themselves.

If you are logging into a text-based terminal, you interact with the get process. This process prompts you for a user name. If you provide this name, `get` calls the login process, which prompts you for a password, takes the password you type, encrypts it using the same process described previously, and then compares the result with your encrypted password in `\**/etc{/}passwd\`. If there is indeed a match, you are authenticated and have access to your local system.

If you are logging into a workstation running the Common Desktop Environment (CDE), the default for HP-UX), the `login` and `digreet` processes handle logins. The essential process is the same: the password you type while logging is encrypted, the result of which is compared to the entry for your user name in `\**/etc{/}passwd\`.

# 8.2.2 Network Authentication

In the UNIX world, network authentication is simply the act of making the `\**/etc{/}passwd\` file information on one machine available to others on the network. The technology that makes this possible is NIS. With this technology, the system consults its local `\etc{/}passwd\` file to verify a user. If the user is not found, the system calls the “networked version” of `\**/etc{/}passwd\`, usually called a map.

The exact process of how this works varies to vendor and is documented in countless numbers of books and manuals. However, the key point is that even though a networked version of `\**/etc{/}passwd\` exists, authentication still takes place on the local system, not on a server. So, though the master copy of `\**/etc{/}passwd\` exists on the NIS master server, the local system `login` or `digreet` process does the actual authentication. Therefore, once a local system authenticates a user, using either the local `\**/etc{/}passwd\` file or the networked map, the user has access to the system. If a user wants to access, a networked file system, the client simply says, “I am this user because my local system says so.” The file server simply accepts this assertion and does not try to find out on its own if the information is correct.
