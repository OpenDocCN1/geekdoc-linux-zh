# Chapter 10 • Windows Services for UNIX

**User Name Mapping.** This component maps Windows-based network user names to UNIX-based network user names. Server for NFS, Client for NFS, and Gateway for NFS use User Name Mapping for NFS authentication and access.

There is a lot of stuff in SFU, so let's look at some of what it has to offer, beginning with Telnet and Server for NFS. Since NFS concerns file sharing issues, we will defer discussion to the next chapter.

SFU comes on a compact disc; inserting into your CD-ROM drive starts the Windows Installer program. If your system is installed with Windows 2000 Professional, the following standard products are installed: Telnet Client, Telnet Server, Client for NFS, Korn Shell, and Utilities. Standard installation on Windows 2000 Servers also allows Server for NFS. The Custom Install of SFU allows you to install other components. You cannot install Client for NFS and Gateway for NFS if you want to synchronize the passwords of your domain accounts, you must install Password Synchronization on a domain controller. Also, you must install Server for NFS on a domain controller. By default, the installer will place SFU in the *SFU* directory and create an environment variable SFUDIR. If you choose a different directory, be sure that directory does not contain a space (like Program Files). The space can cause problems with shortcuts and the function of NFS.

SFU is administered through a Microsoft Management Console (MMC). Once you install your components, run Start→Programs→Windows Services for UNIX→Services Administration to get the MMC shown in Figure 10–1.
