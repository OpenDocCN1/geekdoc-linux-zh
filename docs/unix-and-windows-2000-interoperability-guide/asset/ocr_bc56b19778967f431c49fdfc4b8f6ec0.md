# 2.3.3.2 Windows 2000 GUI

One of the great appeals of Windows 95 and Windows 2000 is that they run GUIs similar to those found on Windows 95 and Windows 98. Most user and administrative activities do not require a command-line interface. However, while both UNIX and Windows 2000 systems provide easy-to-use GUIs, the graphical subsystems are vastly different. As you might recall, UNIX GUIs are based on the X Window system, a network-based display system, while Windows 2000 employs its own Windows Manager as a component of the Executive. With Windows, "a client program executing natively on computer A can run separately from its windowing GUI B across a network." (Taken from Architecting Enterprise Solutions with UNIX-Networking by John Blommers.) In Windows 2000 this is not the case; both the client and server functionality of Windows Manager run on the same computer. Therefore, you cannot run an application on one system and another, unless you deploy Windows 2000 Terminal Services.

Terminal Services provides similar functionality to Windows: It runs on a server (any of the Windows 2000 server family) and provides a client system with an application that runs on the server but displays on the client. However, only Windows-based clients can connect to Terminal Services without a separate software package. You simply load the Microsoft Remote Desktop Protocol (RDP) client available on the server. Other clients, such as Macintosh and UNIX systems, require the purchase of a client from Citrix Services.

# 2.3.4 The MMC

The MMC provides a way to centralize Windows 2000 administrative tools, including third-party tools. The MMC itself does not do any administrative tasks; it is simply an interface. Figure 2–4 shows a predefined MMC called Computer Management. Predefined consoles are created when you install Windows 2000. Each of the applications displayed in a console is known as a snap-in. You can create custom consoles containing only the tools you want to use or those that certain users can. Also, you can use MMC to administer remote systems.

# 2.3.5 Getting Help

To get help on basic Windows 2000 operation, do a Start→Help. You will get a graphical help system that includes topics like the ones you see in Figure 2–5. The equivalent of UNIX pages is the help command you type at the command prompt. The syntax is help [command]. For example:

```
C:\>help diskcopy
Copies the contents of one floppy disk to another.

DISKCOPY [drivel: [drive2:]] [/V]
```

/V Verifies that the information is copied correctly.

The two floppy disks must be the same type.
You may specify the same drive for drivel and drive2.
