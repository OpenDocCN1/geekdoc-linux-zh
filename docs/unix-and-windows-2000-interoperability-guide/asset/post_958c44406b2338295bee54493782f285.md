
## CIFS/9000 Client in a Windows 2000 Domain

### 12.5.2 Using the CIFS/9000 Client

Installing and Administering the CIFS/9000 Client provides instructions for installing the client. Once you do so, Hewlett-Packard recommends you use the value of only the domain variable in the configuration file, /etc/opt/cifsclient/cifsclient.cfg, unless you need to do any localization. In my test environment, I of course set the value accordingly:

```
domain = book.local
```

After that, you simply start the CIFS/9000 client daemon by issuing the following command as the root user:

```
# /opt/cifsclient/bin/cifsclient start
```

Once the daemon starts, you can mount shares. However, if you want the mount to take place every time the system restarts, then using the mount command. You should configure the /etc/fstab file like this:

```
/dev/dsk/ct6d0 /hfs defaults 0 1
w2kserv/home/pchome defaults 0 0
```

This shows that I have a file system (or share) on w2kserv called home that needs to be mounted on my local /home directory at system startup. After making this entry, I can issue the following command to mount all the shares specified in /etc/fstab

```
# mount -A cifs
```

Finally, I need to set the RUN_CIFSCLIENT variable in the /etc/rc.config.dcifsclient file:

```
RUN_CIFSCLIENT=1
```

So far, we have created the share home on w2kserv containing Full Control permissions for Everyone. We have also secured the dylan subdirectory (or subfolder) under NTFS permissions. We configured and started the CIFS/9000 client on hpux1. Then, as we mounted the share home to the local /pchome directory. In order to access the /pchome directory, each user must first be authenticated by w2kserv. Unless you use PAM NTLM to do your authentication (which we will discuss a little later), you must use the cifslogin command. Note the following series of commands:

```
$ id
uid=1004 (dylan) gid=1000 (tech)
$ cd /pchome
sh:/pchome: Permission denied.
$ cifslogin w2kserv
Remote user dylan's password:
$ cd /pchome
$ 11
total 0
drwwxrwxwx 2 dylan tech 131072 Dec 28 2000 dylan
drwwxrwxwx 2 dylan tech 131072 Dec 22 12:16 Hilary
$ cifslist -A
```

This is because the home share has Full Control permissions for Everyone. But the NTFS permissions override the share permissions, so that dylan cannot write to the dairy directory if the NTFS permissions prohibit him.

### 12.5.3 PAM and the CIFS/9000 Client

We described PAM NTLM in Chapter 8, “User Authentication,” and stated that by employing it you can avoid having to use cifslogin. Let’s review how to do that.

- 1. Edit the PAM NTLM configuration file /etc/opt/cisclient/pam/smb.conf. You set the workgroup parameter, which is actually your Windows 2000 domain, and then you set the password server parameter, which is your domain controller name. In our example we have:

```
==================== Global Settings ==================
[global]
# workgroup = NT-Domain-Name or Workgroup-Name, eg: REDHAT4
workgroup = BOOK
```

# Use password server option only with security = server or
password server = w2kserv
Domain user map = /etc/opt/cisclient/pam/domain_user.map

As I have done with my configuration file, you might want to specify a user map file with the domain user map parameter. My map file contains only one mapping: that of root to Administrator.

- 2. Edit the global HP-UX PAM configuration file /etc/pam.conf. If you want NTLM authentication only when a user logs into the console running the Common Desktop Environment (CDE), change the libpam_unix.1 entries to libpam_ntlm/under the appropriate sections. For password authentication and change without password expiration support, change only the Authentication management (dtlogin and dtaction) and Password management (dtlogin and dtaction) sections. If you do want password expiration support, change the Account management (passwd, dtlogin, dtaction) section as well. Below is a example:

```
# PAM configuration
#
# Authentication management
# auth required libpam_unix.1
login auth required libpam_unix.1
dtlogin auth required libpam_ntlm
dtaction auth required libpam_ntlm
ftp auth required libpam_unix.1
#
# Account management
# auth account required libpam_unix.1
login account required libpam_unix.1
dtlogin account required libpam_ntlm
dtaction account required libpam_ntlm
su account required libpam_unix.1
#
# Session management
# auth session required libpam_unix.1
login session required libpam_unix.1
dtlogin session required libpam_ntlm
dtaction session required libpam_ntlm
su session required libpam_unix.1
#
# Password management
# auth password required libpam_unix.1
login password required libpam_unix.1
dtlogin password required libpam_ntlm
dtaction password required libpam_ntlm
passwd password required libpam_unix.1
```

Exactly how you configure PAM NTLM is, but you need to be careful or you might not be able to log in. In Chapter 8, we also described Kerberos. Consult that chapter for more information. As you might recall, PAM Kerberos is a little trickier. You need to have a user set up on the Windows Key Distribution Center (KDC), create a keytab file on the KDC, transfer that file to the HP-UX system, synchronize clocks between the HP-UX system and the KDC, configure /etc/krb5.conf, and then configure /etc/pam.conf for CDE only, change the dtaction and dtlogin under the Authentication section. Since up Kerberos authentication is more involved, you might consider using PAM NTLM instead, since Windows 2000 domain controllers can indeed authenticate with NTLM for mixed environments. Also, since account management and session management are not defined under Kerberos, you don't have to configure the Account Management and Session Management functions. One thing to watch out for PAM Kerberos is that there is no user-mapping file. Therefore, you need a user called root on the Windows KDC if you want that account to be authenticated by that name.
