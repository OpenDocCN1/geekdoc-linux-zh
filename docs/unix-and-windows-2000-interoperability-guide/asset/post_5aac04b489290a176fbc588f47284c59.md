
# Networking

1.4.5 TCP/IP are blood brothers. In the mid 1970s, the Defense Department's Advanced Research Projects Agency (DARPA) funded Bolt, Beranek, and Newman (BBN) to develop TCP/IP for UNIX, and the University of California-Berkeley later integrated this software into BSD UNIX. Since then, UNIX networking has met TCP/IP, and, until recently, TCP/IP was driven by the speed of UNIX and the Internet.

Modern UNIX systems support a variety of network interface layer devices and protocols: Ethernet, Token Ring, ATM, ISDN, and others. They also support either SLIP or PPP. Networking applications include NFS for file sharing, and NIS for the sharing of key information, such as passwords.

One extremely important application is the X Window System. Though it is often thought of as a graphical system, it really is a networking protocol that separates the client application from the display server. The client runs natively on a system and connects to its display via the network, even if the display is on a separate system. All forms of UNIX support X Window, and it is the basis for all GUIs in use today, including the Common Desktop Environment found on HP-UX, AIX, Solaris, and the GNOME and KDE found on Linux.

# System Management Tools

Even though I praise the virtues of command-line system administration, there is much to be said about the graphical system administration tools provided by most versions of UNIX. HP-UX has SAM, the System Administration Manager. AIX has SMIT, System Management Interface Tool. Many Linux distributions include a similar tool Linuxconf. These tools help you do tasks for which you know what needs to be done (for example, mount a file system) but you are not sure how it should be done. Since I will be using HP-UX for most of my UNIX examples, I will refer to the SAM tool frequently.

# What Is Windows 2000?

If you are a long-time UNIX system administrator, Windows 2000 may seem like a fortified version of Windows 98. Or, you may think that Windows 2000, installed mostly on Intel processor-based systems, is directly descended from the old DOS world. Windows 2000, built on NT technology, however, is a completely different beast from both DOS and Windows 98. So how did it come to be? Again, let's look at a little history.

# 2.1 A New Operating System

For a long time (in computer-industry time), when someone thought of a PC, he or she usually thought of an Intel processor based running some form of DOS. Even Windows 95 and Windows 98 were based on DOS. However, to say that Windows 2000 is a PC operating system is somewhat misleading. For one thing, it is not based on DOS. For another, Windows 2000 can run on more than just an Intel processor. In 1988, Microsoft began working on a new operating system that would have a number of highly desirable features:

- The ability to run on different processors
- Be multiuser and multitasking
- Meet C2-level security
- Be scalable for the enterprise
- The ability to support legacy DOS and Windows applications

It was designed to be an operating system for high-end workstations and servers where UNIX had dominated. (Today, Windows 2000 runs on "everyday" PCs and laptops.) To lead this effort, Microsoft recruited David Cutler from Digital Equipment Corporation (DEC). Cutler was an experienced system designer who knew a lot about things multitasking, but it took him and his team five years to release the first version of what was to become Windows NT.

Microsoft released two flavors of its operating system, Windows NT 3.1 and NT Advanced Server 3.1, in the summer of 1993. The version number 3.1 was chosen to coincide with that of the 16-bit Windows operating system prevalent throughout the world at the time. It also implied that this new operating system was not an unstable 1.0 release. It was slow, using a lot of memory and requiring much in the way of computer hardware, but it was a significant achievement, nonetheless, it was the 32-bit Windows operating system, and it could run on non-Intel-based processors: MIPS, Alpha, and Power. Though not a big commercial success, it was a propitious start in the effort to create an alternative to UNIX.

From 1993 to 1996, Microsoft released three major versions of NT: 3.5, 3.51, and 4.0. Version 4.0 has been by far the most successful version of NT. It offered more device support, default TCP/IP networking. Internet services, and a Windows 95 interface. These and other features have made Windows NT 4.0 the operating system of choice for business desktops, cutting severely into the UNIX desktop business since its release in 1996.

The next generation of NT technology is Windows 2000, known unofficially as Windows NT 5 until a few months before its official release in February 2000. There are several versions of Windows 2000:

- Windows 2000 Professional. Designed for business desktops and laptops.
- Windows 2000 Server. Designed for workgroup and small business network services.
- Windows 2000 Advanced Server. Designed for e-business and line-of-business applications.
- Windows 2000 Datacenter Server. Designed for large systems running critical applications such as OLTP.

# 2.2 Windows 2000 Architecture

Figure 2-1 depicts the major components of Windows 2000. At the lowest level is the hardware itself, most often Intel processor-based system. Above that is the Hardware Abstraction Layer (HAL), a layer of software designed to hide hardware differences from the rest of the operating system. At the next level, we have both device drivers and the kernel. Herein an important difference between most versions of UNIX, including HP-UX, and Windows 2000. The Windows 2000 kernel is a microkernel; it does not include device drivers. Therefore, the kernel remains small, taking care of the most basic of operating system functions. As pointed out in Chapter 1,“What is UNIX?” most UNIX kernels require that a device’s driver be compiled into the kernel. Moreover, whereas UNIX kernels handle I/O and memory management, in Windows 2000, these functions are separated into subsystems.
