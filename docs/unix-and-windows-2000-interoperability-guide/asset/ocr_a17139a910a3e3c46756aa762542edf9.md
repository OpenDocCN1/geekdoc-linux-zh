To access certain pieces of the hardware, such as a tape drive, the driver for that device must be built into the kernel and must have at least one device file serving as a kernel pointer to the driver somewhere on disk.

Traditionally, UNIX systems have drivers for all the devices you use to be built directly into the kernel, creating a single, monolithic kernel. Adding new devices to this kind of kernel requires you to compile a new one that includes the new drivers, moving it into the appropriate location on disk, and then rebooting. Recently, however, UNIX systems have seen the emergence of dynamically loadable kernel modules, modules that can be added to the running kernel to support devices that may be used only sparingly. Having dynamically loadable kernel modules keeps the size of the kernel proper small, using fewer computing resources. HP-UX 11 supports modules.

#  1.4.2 The Shell

A shell is an interface between you, the user, and the kernel. It enables you to “do things” with the system. Traditionally, UNIX users have thought of the shell as a command-line interpreter. In other words, the shell would provide a command prompt, waiting for you to issue some kind of command. The command may be a built-in shell command (thus residing in memory when the shell is loaded) or it may be found on disk. If you are a long-time DOS user, then you know that your shell is COMMAND.COM.) More recently, however, the shell can take the form of some kind of graphical user interface (GUI), enabling you to carry out functions without having to issue something on a command line. However, even these functions require a traditional shell to execute.

There are many shells to UNIX users. Each flavor of UNIX usually has what is known as the default shell, the shell used by system management scripts. The default shell is available Available shells include the Bourne shell, the C Korn shell, the POSIX shell, and BASH (the Bourne-again shell, similar to the Bourne shell). Each shell has its own built-in commands, scripting language, command prompts, and special features. Which one you use is up to you, to keep you from having to learn all the shells and then choosing, the following:

+   - The Bourne shell is nearly universal on all versions of UNIX but is being obsolete on HP-UX because it lacks many features contained in the POSIX and Korn shells.
- The Korn shell is a superset of the Bourne shell, with some nifty features like history recall and editing.
- The POSIX shell is the default shell on HP-UX, and is similar to the Korn shell.
- BASH is the default shell for Linux and combines the best features of the Bourne and C shells. It is not available on HP-UX.
- The C shell incorporates a command history buffer, C language-like syntax, and control facilities. It is offered on all UNIX systems.
