# 7.2.3 Active Directory and DNS

Windows 2000 can store a primary DNS zone in Active Directory, making the data therein Active Directory objects. Therefore, in addition to normal DNS zone transfers, you can have information replicated through the Active Directory replication process. The advantage of integrating DNS with Active Directory is that you can have multimaster replication, with multiple domain controllers updating the zone. (See Microsoft Windows 2000 Server TCP/IP Networking Guide, p. 376) With traditional DNS, only a primary server can update the database.

According to the Microsoft Windows 2000 Server TCP/IP Networking Guide, p. 429, for the domain controller to work properly, the primary DNS server is authoritative for the names that are to be registered by the Netlog on the domain controller, must support the service location resource record (SRV RR). Furthermore, as we have already seen, BIND 8.1.2 on HP-UX does not support SRV records. Because you would have to manually update the primary zone when you configure Active Directory if you use an older version of BIND, Microsoft recommends that your DNS support dynamic updates. Bind 8.1.2 does so.

The ISC has published on its Web site, www.microsoft.com/resources/bind-faq.html, the following statement regarding BIND and Active Directory.

# Microsoft Windows 2000 and BIND

BIND, by default, checks all records to ensure that only host names are used where host names are expected to prevent accidental interoperability problems.
Windows 2000 uses a subzone "mscdcs" to hold the Active Directory data. While this subzone cannot clash with any legal host name, it also makes it impossible to put hosts within this subzone without an illegal name. The use of such names will be rejected; by default, by BIND.
The Active Directory wants to have its "global catalog" server in members (e.g., _mscdcs.example.com), which will be rejected by default. To work around this we recommend that the Active Directory be a separate zone (e.g., _mscdcs.example.com) configured to not check for illegal host names. This should be reasonable as the Windows 2000 servers create this data and should not have interoperability problems with other Windows 2000 machines wanting to access this data. For example,

```
zone "mscdcs.example.com" {
    type master;
    file "mscdcs.example.db";n    check-names ignore;
    allow-update {localnets};
};
```
