All Windows 2000 domain controllers are peers; therefore more than one KDC can exist in a domain. According to the Microsoft Windows 2000 Server Distributed Systems Guide, p. 659, "Windows 2000 does not, however, implement the Kerberos protocol. Instead, it replicates the information store for Active Directory by using a multicast replication protocol over a secure channel between replication masters."2

The Authentication Service Exchange The Authentication Service (AS) Exchange is where the KDC provides the client logon key and a Ticket-Granting Ticket (TGT) for use with other services. When a user logs onto a Windows 2000 domain from a Windows 2000 workstation (defaulting to Kerberos authentication), the workstation's LSA converts the user's password to an encryption key and saves the result in the credentials cache, a protected area of volatile memory. The LSA (via the Kerberos client) then sends an authentication request (KRB_AS_REQ) to the KDC containing the user's name and pre-authentication data encrypted with the long-term key.

The KDC looks up the user in the principal database, fetches the long-term key associated with that user, decrypts it, creates a logon session key and encrypts a copy with the user's long-term key. It also embeds another copy of the logon session key along with authorization data for user in a TGT. Authorization data include the user's SID and SIDs for the user's groups. The TGT is also encrypted, this time with the KDC's own long-term key, and is sent to the client in an authentication service reply (KRB_AS_REP). The client uses the locally cached encryption key to decrypt the logon session key and stores it in the credentials cache. It then extracts the TGT and stores it in the credentials cache.

At this point, the client has a TGT that it can present when it needs session tickets for services in the domain. The next step is for the client to obtain a session ticket for the current logon session. Once done, the user has access to his or her workstation.

The Ticket-Granting Service Exchange This process provides the client with a session ticket that provides the user access to the local workstation. The client requests credentials for the ticket-granting service (TGS) from the KDC. This request (KRB_TGS_REQ) containing the user's name, an authenticator encrypted with the logon session key, the TGT, and the name of the user's computer. The KDC decrypts the TGT, extracts authentication. If all is valid, the KDC extracts the user's authorization data from the TGT and creates a session key to enable the user to use the workstation.

Once the client receives this session key, the LSA decrypts it with the locally cached encryption key and extracts her authorization data. The LSA also checks the local SAM to see if the user belongs to any local groups. If so, it adds SIDs to the list of SIDs contained in the authorization data. The LISA then builds an access token for the user and passes it to Winlog, which completes the logon process.
