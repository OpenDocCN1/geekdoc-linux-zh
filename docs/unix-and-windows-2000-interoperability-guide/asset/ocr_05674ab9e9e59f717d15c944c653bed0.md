# Telnet Server 145

There are four areas you can configure: Authentication, Logging, Server Settings, and Sessions, each of which has its own configuration page. When you make changes to these pages, you must stop and then restart the Telnet service by either right-clicking on the Telnet Server icon on the snap-in or by entering the following commands at a command-line prompt:

```
tnadmin stop
tadmin start
```

You can administer remote systems with this snap-in by right-clicking on the Services For Unix folder and selecting Connect to Another Computer. To configure the remote system, you should be logged on to the local system as a user with administrative rights and that user must be recognized by the remote system. Otherwise, you must start Windows for Unix Administration using the runas command. For example,

```
runas /profile /user:RemoteComputer\AdminUser "mm %SFUDIR%\fumgt.msc"
```

For more information on runas, see the Help utility. You can also administer a remote system by using the Telnet client and running tnadmin. The tnadmin command provides a command-line interface to all the functions available via the MMC. More information on this command can be found in Help for Services for UNIX. (Run Start→Windows Services for UNIX→Help for Services for UNIX)

# 10.2.1 Authentication

The Telnet Server supports both NTLM and plain text authentication. NTLM authentication works quite well with Windows Telnet clients; it avoids having to enter a user name and password and thereby keeps encrypted passwords over the network. With HP-UX Telnet server will prompt for a user name and password, even if you use PAM NTLM to authenticate you with HP-UX. The reason for this is that the Telnet client and server negotiate which options they will employ at session startup. Windows 2000 Telnet clients and servers support option 37, the Authentication Option, to enable NTLM authentication. HP-UX clients and servers do not. Therefore, even if PAM NTLM authenticated you when you logged on to your HP-UX workstation, the Windows 2000 Telnet server will still ask for a user name and password because the HP-UX Telnet client does not support option 37.

Once authenticated, Windows 2000 runs the %SYSTEMROOT%\system32\login.cmd script, which by default looks like the following:

```
@echo off
rem
rem Default global login script for the Telnet Server
rem In the default setup, this command script is executed when the
rem initial command shell is invoked. It, in turn, will try to
rem invoke the individual user's login script.
rem
```
