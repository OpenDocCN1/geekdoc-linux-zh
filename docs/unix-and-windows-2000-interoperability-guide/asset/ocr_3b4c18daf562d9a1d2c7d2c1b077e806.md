5. On the HP-UX system, edit /etc/krb5.conf to refer to the Windows 2000 domain controller
as the KDC. You can use the sample /etc/krb5.conf file shown previously, but you won
need the [logging] stanza. Since your KDC is a Windows system. If your HP-UX
s’s DNS name is the same as the realm name, then you won't need the
[domain_realm] stanza. Otherwise, use that stanza to map your DNS name to
your Kerberos realm name. For example:

[libdefaults]

```
default_realm = BOOK.LOCAL
default_tgt_encypes = DES-CBC-CRC
default_tgs_encypes = DES-CBC-CRC
ccache_type = 2
```

```
[realms]
{
kdc = w2kserver.book.local:88
adm_server = w2kserver.book.local
}
```

6. Synchronize your system clock to read within two minutes of the KDC’s clock to prevent
authentication errors due to clock skews.

7. Create corresponding user accounts on both the Windows 2000 domain controller and
HP-UX system. The HP-UX user account does not need a password, since authentication
to the Windows 2000 KDC. However, include the UID, shell, and home directory
information so the user actually has access to the workstation once authenticated.

The examples came from my small lab used in writing this book. The system called
W2KSERV, a Windows 2000 domain controller, was my KDC, and BOOK.LOCAL was my
realm name. I created a user account for my HP-UX system, hpux1, on the KDC and then used
