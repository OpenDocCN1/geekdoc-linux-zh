The differences, of course, lie in the drivers for these adapters. If a particular network adapter is to work on both Windows 2000 and UNIX systems, it must have an appropriate driver for the operating system. Many network interface card (NIC) vendors, though, will design cards for Intel processor-based systems, which confines their functionality to only those operating systems that run on such architectures, such as Linux, OS UNIX, or some version of Windows. Yet, whether the NIC is designed for a Reduced Instruction Set Computing (RISC)-based UNIX system or an Intel-based Windows system, as long as you standardize on a particular technology, such as 100Base-T Ethernet, and as long as your systems support it, you will have basic network interconnectivity out of the box.

If your system, be it UNIX-based or Windows-based, comes with the operating system preinstalled, the appropriate driver for the network is already present. If you install the operating system, the install process will detect your NIC (if it is a popular one) and ensure that you have the right driver in place. RISC-based UNIX systems ship only with NICs supported by the appropriate operating system. Windows 2000 systems come with a wider variety of NICs. However, you may wind up installing some systems with cards not found on Microsoft's Hardware Compatibility List (HCL). Microsoft supplies as many of the NIC vendors in existence as on the installation CDs, but sometimes you will have to go to the driver's Web site to get an updated driver for Windows 2000.

HP-UX systems can automatically detect newly installed hardware and create device files for them, but usually the device drivers still need to be present in the kernel. (With HP-UX 11 and Linux, you can employ dynamically loadable kernel modules that are precompiled kernel modules that can be loaded into memory as needed. However, such modules are reserved for less frequently used devices, NICs.) Because the Windows 2000 kernel is a microkernel, device drivers are not built into it, making it possible for you to add devices dynamically without building kernel modules. Windows 2000 supports Plug and Play (PnP), which provides for automatic hardware detection and configuration.

An important element in networking interoperability is the ability of an operating system to run multiple protocol stacks on a single network card. UNIX systems have been able to handle multiple stacks easily because of their protected memory model. (John Blomers, Architecting Enterprise Solutions with UNIX Networking, p. 168.) Windows 2000 accomplishes this task, something using an NDIS wrapper. NDIS is for the Network Device Interface Specification, which provides for an interface that, among other things, allows multiple protocols to bind to a single NIC driver. What this means is that both UNIX and Windows 2000 systems can concurrently run protocols such as TCP/IP, IP/SPX (or NWLink for Windows 2000), or AppleTalk.
