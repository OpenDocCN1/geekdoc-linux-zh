For my test case, I listed the following in the /etc/named.conf file:

```
zone "book.local" {
    type master;
    file "db.book";
    allow-update { any };
}
```

```
zone "0.0.10.IN-ADDR.ARPA" {
    type master;
    file "db.10.0.0"
    allow-update { any };
}
```

I had two statements: one for the book.local domain and one for the 0.0.10.IN-ADDR.ARPA reverse domain. Both statements contain the allow-update { any }; substatement, which essentially opened my BIND server to update requests from any host on the network. (This is not a secure thing to do, but I used it as a proof-of-concept tool.) As a result, Windows 2000 client successfully updated its RR and PTR records for the server, as shown by the following Network monitor capture:
