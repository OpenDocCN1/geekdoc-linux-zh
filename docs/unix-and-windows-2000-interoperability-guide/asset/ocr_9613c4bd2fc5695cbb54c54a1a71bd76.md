# Chapter 9 • Basic TCP/IP Utilities

On UNIX systems, all of these utilities come in both the client and the server varieties. The names of the server versions all end in the letter d to indicate that they are daemons. In the UNIX world, daemons run as background processes, ready to serve requests. Some daemons run continually; others, including those below, run only when needed. On HP-UX 11, the server versions of the utilities mentioned above are:

+   - /usr/bin/fingerd
- /usr/bin/ftpd
- /usr/bin/remshd
- /usr/bin/rexcd
- /usr/bin/telnetd
- /usr/bin/tftpd

The clients are:

+   - /usr/bin/finger
- /usr/bin/ftp
- /usr/bin/rcp
- /usr/bin/rexec
- /usr/bin/remsh
- /usr/bin/telnet
- /usr/bin/tftip

If you are new to UNIX, it is probably confusing to think that both server and client components of key utilities can be found on a single system, including one that can be considered a "client" system. But such is the case that a system administrator logged on to a UNIX server (because it is so big and probably runs something, like a database) can use the Telnet client on that server to connect to the Telnet server running on a client system in order to run commands on it. It happens all the time, even in the Windows world. If you are logged in as an administrator of a Windows 2000 Advanced Server system, you can use your FTP client to connect to the FTP server on a remote UNIX client. You can issue commands via your FTP client (on Windows 2000 Advanced Server) to the FTP server (on the UNIX workstation). So, in both the UNIX and Windows 2000 arenas, utilities can exist in either client or server form despite the "official" role of the system.

Now, back to the server versions of the basic TCP/IP utilities. Because the number of daemons on a given system can grow large, and because some daemons, though necessary, are used infrequently, UNIX systems employ an intermediate daemon to manage network requests. This daemon is inetd, short for Internet daemon. The daemons discussed in this chapter do not run continually in the background. Instead,/usr/sbin/inetd runs continually, ready to awaken other daemons to fulfill client requests. Once the daemon's work is done, it dies, to be resurrected when needed.
