To turn the system into an NIS client of the new master server (the Windows 2000 system), choose Actions→Disable Client and then Actions→Set Domain Name. ## 10.3.4 Issues with Migration

10.3.4.1 UIDs Since my test bed was so small, there was not much for me to be worried about, so I ran the migration without much concern. The only problem I ran into was that the Active Directory account dylan did not seem to retain the UNIX UID for that user (which was 102). In Figure 10–11, I show the UNIX Attributes tab of the dylan account. Because I chose not to overwrite any data of Windows objects, the UID was set to a different number. The result was although I could log in as user dylan on the HP-UX system (after converting the master server into a client). I had file permission problems. Changing dylan's UID in Active Directory to 102, the original value, fixed everything.

Also, in HP-UX the default GID for the users group is 20. But Server for NIS reserves GIDs below 100. So, you either have to change the GID to a number over 100 in Server for NIS leave alone and ensure the name service switch consults files at some point. If you want to be sure your name service switch works properly, use the nsquery utility. For example:

```bash
# /usr/contrib/bin/nsquery group users
```

Using "files" nis" for the group policy.

```
Searching /etc/group for users
Group name: users
Group Id: 20
Group membership: root
Switch configuration: Terminates Search
```

Note that nsquery found the users group with GID 20, because the name service switch consults /etc/group first.

## 10.3.4.2 Passwords

Because the dylan account already existed in Active Directory, the UNIX password for that account was set to be the same as that on the HP-UX system. However, the Windows 2000 password for dylan did not change. To synchronize the password, I logged on as dylan on my Windows-2000 server and changed the password: (In the default Domain Controller Policy object, I had to grant the users group the right to log on locally to do this). The result was that both passwords were changed, and the NIS password was pushed to the HP-UX client.

However, when I logged into hpux/ as dylan, I used ypasswd to change my NIS password:

```bash
$ ypasswd
Changing password for dylan on NIS server
Old NIS password:
New password:
Re-enter new password:
NIS (YP) passwd/attributes changed on w2kserv, the master NIS server.
```

Indeed, the NIS password changed. The Windows 2000 password, however, did not. Two-way synchronization is possible only by installing and configuring the separate Password Synchronization tool in SFU.

## 10.3.4.3 Creating a New User

During migration, the Migration Wizard created a new Windows user because there was no equivalent user in place at the time of migration, the user's UNIX password in Active Directory will be the same as the existing UNIX password. However, the user will be required to change his or her password upon the next login to Windows.

Since the Windows 2000 domain controller is now the NIS master server, you can create new users for both Windows and UNIX clients using the Active Directory Users and Computers tool. If you do, so, only the Windows password will be set; there will be no NIS password. In other words, logging on to Windows will require a password; logging on to a UNIX client will not. As we have seen, logging on to UNIX and using passwd will set the NIS password on the domain controller, the only way to synchronize the password (unless you are using the Password Synchronization tool) is to have the user log on to a Windows client system and change passwords there.

## 10.3.4.4 Home Directories

If you create a new user on the domain controller running Server for NIS, that user will have a UNIX home directory that defaults to the home of the migrated passwd map. For example, if your UNIX Home directory are in /home. Active Directory will specify /home/username in its UNIX Home Directory attribute. So, where are these home directories to be found? Well, unless you centralize their location using NFS or Common Internet File System (CIFS), you must.
