# 6.1.2 Lookup DNS

Windows 2000 departs from the NT tradition of going through the NetBIOS name resolution process before trying DNS. Instead, it works the other way around: It goes the DNS route first and then NetBIOS. This assumes, of course, that you have a Windows 2000-only network. In order for Windows 2000 systems to communicate with systems that are not Active-Directory enabled, you still must use Windows Internet Naming Service (WINS).

When a user uses a Winsock-based application like Ping or FTP and specifies a host name as the target, the systems calls the gethostbyname() function, which

+   1. Checks to see if the destination host name matches the source destination name.
2. Checks the local HOSTS file (\SystemRoot\System32\Drivers\Etc) for a matching entry.
3. Queries DNS.
4. If all else fails, and if the destination host name is 15 bytes or fewer, follows the NetBIOS name resolution method.

If a Winsock application tries to get a host name using an IP address, it calls the ghostbyaddr() function, in which case the system

+   1. Consults the local HOSTS file for a matching entry.
2. Queries DNS.
3. Sends a NetBIOS Adapter Status Request to the target IP address, the reply to which contains the host name.

Remember, if you have an all-Windows 2000 network, the workstation and server services can use DNS exclusively for communications, eliminating the need for NetBIOS. By default, NetBIOS over TCP/IP is enabled. It is a good idea to keep this setting until all your systems are either Windows 2000 or fully compatible systems.
