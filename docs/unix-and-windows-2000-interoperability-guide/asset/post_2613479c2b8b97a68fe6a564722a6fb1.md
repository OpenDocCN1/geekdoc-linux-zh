It consists of the HAL, the microkernel, device drivers, and several kernel-mode components, such as the I/O Manager, Memory Manager, and the Process Manager.

Running in user mode is the POSIX, Win 32, and OS/2 subsystems. The POSIX subsystem provides APIs to enable POSIX-based applications to run. The OS/2 subsystem provides a set of APIs for 16-bit, character-based applications. Win 32 is a subsystem that provides an environment for running Win 16 and MS-DOS applications, as well as Win32-based applications. Also running in user mode are several integral subsystems. These subsystems perform essential operating system functions such as security services and the server and workstation services.

## 2.3 Elements of Windows 2000

Please note that in this book, the term directory is used interchangeably with the term folder. (I will also use the term login and logon interchangeably.)

### 2.3.1 The Registry

Windows 2000, like NT, keeps hardware and software settings in a hierarchical database called the Registry. Other versions of Windows keep this information in text files, often ending in .ini. UNIX systems, with the exception of AIX, still rely heavily on configuration files. However, you cannot change the contents of the Registry using a text editor. Instead, you use the Registry Editor, regedt2.exe.

In Windows 2000, the Registry contains information about virtually everything installed on a particular system, things such as hardware (for example, CPU and bus type), device drivers, applications, and network settings. The following describe the components that use the Registry. (Taken from the Microsoft Windows 2000 Beta Training Kit, pp. 117–118).

### Windows NT Kernel

During system startup, the kernel, ntoskrnl.exe, reads information from the Registry, including the device drivers to load and the order in which they should be loaded. The kernel writes information about itself to the Registry, such as the version number.

### Device Drivers

Device drivers receive configuration parameters from the Registry and also write information to it. A device driver informs the Registry which system resources it is using, such as hardware interrupts or DMA channels. Device drivers also report configuration data.

### Elements of Windows 2000

#### Setup Programs
A setup program can add new configuration data to the Registry when it installs hardware or software. It can also query the Registry to determine whether required components have been installed.

Ntdet.com
On Intel-based computers, ntdet.com scans the system for the hardware. It adds configuration information to the Registry for components it discovers. RISC-based computers extract such data from the computer firmware.

#### Hardware Profiles
Computers with two or more hardware configurations use hardware profiles. When Windows 2000 starts, the user selects a hardware profile. Windows 2000, with the Registry, then configures the system accordingly.

#### User Profiles
Windows 2000 creates and maintains user environmental settings in a user profile. When a user logs on, the system caches the profile in the Registry. Windows 2000 first writes user configuration changes to the Registry and then to the user profile.

### 2.3.2 Active Directory

Active Directory is Windows 2000's directory services. Directory services enables users and applications to locate network resources, including user data, servers, and printers. Active Directory uses the Domain Name System (DNS) to locate network names and Lightweight Directory Access Protocol (LDAP) or HyperText Protocol (HTTP) for obtaining resource information. Because of its reliance on DNS, Active Directory domain names coincide with DNS names, though an Active Directory domain is not exactly the same thing as a DNS domain.

### 2.3.3 User Interfaces

In Chapter 1, we saw that UNIX traditionally provided a default shell with which to run commands and applications. In recent years, HP-UX, AIX, and Solaris have provided a graphical user interface (GUI) called the Common Default Environment (CDE), which makes a number of day-to-day tasks easier. Additionally, all major forms of UNIX provide some of system management tool, such as SAM in HP-UX and SMIT in AIX, to help simplify system administration. Windows 2000 provides similar tools: a command interpreter, a GUI, and a system administration tool known as the Microsoft Management Console (MMC).

#### 2.3.3.1 Command Interpreter

The Windows 2000 application C:\Windows\System32\cmd.exe starts a window running what looks like an MS-DOS prompt (See Figure 2–2). Actually, it is a 32-bit program that, according to the Help, “retains and enhances almost all the functionality of MS-DOS.” However, a number of MS-DOS commands are not available on the Windows 2000 command line. Though not fully scriptable, the Windows 2000 command interpreter supports batch commands, if and for more information, see the Windows 2000 Command Reference.

Windows 2000 is not case sensitive when you enter commands. If you type DIR at a command prompt, you will get a directory listing. You will get the same thing if you type dir. However, Windows 2000 is retaining. In other words, if you were to type mkdir at the prompt and then do a directory listing, you would see a directory named .. If you were to change your directory by typing cd .., your command prompt would show C:\. Therefore, Windows 2000 retains the case of a file or directory name for display purposes only. As in UNIX, you must be aware of what your PATH variable is set to. If, for example, the following command is not in your path, you will see something like:

```
C:\>cmd.exe
'cmd.exe' is not recognized as an internal or external command, operable program or batch file.
```

You can set the PATH variable by right clicking on My Computer, selecting Properties, clicking on the Advanced tab, and selecting Environment Variables. The PATH variable is found in the Environment box. See Figure 2–3.

#### 2.3.3.2 Windows 2000 GUI

One of the great appeals of Windows 95 and Windows 2000 is that they run GUIs similar to those found on Windows 95 and Windows 98. Most user and administrative activities do not require a command-line interface. However, while both UNIX and Windows 2000 systems provide easy-to-use GUIs, the graphical subsystems are vastly different. As you might recall, UNIX GUIs are based on the X Window system, a network-based display system, while Windows 2000 employs its own Windows Manager as a component of the Executive. With Windows, "a client program executing natively on computer A can run separately from its windowing GUI across a network." (Taken from Architecting Enterprise Solutions with UNIX-Networking by John Blummers.) In Windows 2000 this is not the case; both the client and server functionality of Windows Manager run on the same computer. Therefore, you cannot run an application on one system and another, unless you deploy Windows 2000 Terminal Services.

Terminal Services provides similar functionality to Windows: It runs on a server (any of the Windows 2000 server family) and provides a client system with an application that runs on the server but displays on the client. However, only Windows-based clients can connect to Terminal Services without a separate software package. You simply load the Microsoft Remote Desktop Protocol (RDP) client available on the server. Other clients, such as Macintosh and UNIX systems, require the purchase of a client from Citrix.

### 2.3.4 The MMC

The MMC provides a way to centralize Windows 2000 administrative tools, including third-party tools. The MMC itself does not do any administrative tasks; it is simply an interface. Figure 2–4 shows a predefined MMC called Computer Management. Predefined consoles are created when you install Windows 2000. Each of the applications displayed in a console is known as a snap-in. You can create custom consoles containing only the tools you want to use or those that certain users can. Also, you can use MMC to administer remote systems.

### 2.3.5 Getting Help

To get help on basic Windows 2000 operation, do a Start→Help. You will get a graphical help system that includes topics like the ones you see in Figure 2–5. The equivalent of UNIX pages is the help command you type at the command prompt. The syntax is help [command]. For example:

```
C:\>help diskcopy
Copies the contents of one floppy disk to another.

DISKCOPY [drivel: [drive2:]] [/V]
```

/V Verifies that the information is copied correctly.

The two floppy disks must be the same type.
You may specify the same drive for drivel and drive2.
