### 1.4.3.2 File System Formats

The term file system can also refer to a formatted area on some media for the purpose of storing files. This media can be CD-ROMs, floppy disks, hard disks, or partitions of hard disks. There are many different system formats, but to a user, these formats are transparent, as long as the operating system knows how to access them. HP-UX recognizes the following file systems:

- HFS, the High-Performance File System. The HFS physically resides on a mass storage device, usually on a hard disk. Earlier versions were known as the UNIX File System (UFS).
- NFS, the Network File System, NFS is a remote file system accessed over a network. The local system treats NFS as local.
- CD-ROM, also known as the ISO 9660 file system, makes the files and directories in compact disk available to the local system.
- JFS, the Journaled File System. JFS is an extent-based journaling file system that offers performance and file system recovery.

Linux recognizes NFS and ISO 9660 file systems, as well as many others. The default file system on Linux is the Second Extended file system, also known by the abbreviation ext2. Linux can also access MS-DOS, Windows 98, Windows NT, OS/2, and Apple Macintosh file systems.

Hard disk systems are formatted areas that can encompass one or more entire disks, a single partition on a single disk, a single partition spanning more than one disk, or a collection of small units that collectively form a logical partition. These file systems are the physical containers files. To access these, the entire file system must be attached, or mounted, to a directory in the root partition. If there is a single file system for a single hard disk in a system, then the contents of the file system are mounted to the /directory. If there are multiple file systems on one or more hard disks, then each of these file systems, once mounted, form physical types of the virtual file system tree. In this way, UNIX avoids the use of drive letters in its file tree, because each file system is mounted on a directory in the root partition, regardless of its location, be a logical volume, partition, or remote file system.

If this seems confusing, consider this simple example. Let's say you have a UNIX system with a hard disk sliced into three partitions. One file system contains the root partition, one contains all the files and directories to the /usr directory, and one contains something called a swap partition. When this boots, the first partition to be mounted is then the root partition. For some reason the partition containing the /usr directory does not mount, you have access to nothing in /usr. Assuming that all the commands you need to access the system can be found in the root directory, then a listing of the files in /root would show things like /bin, /etc, /tmp, /opt, /sbin—and even /usr! But whereas these directories would contain files, /usr would not work. Why? Because the physical location of these files, the file system, is mounted. ### 1.4.4 Permissions

One of the hallmarks of UNIX is its permissions: owner, group, and other. To determine a file's permissions, you use the ls -l command. For example, if you type the following command:

```
$ ls -l myfile
```

you will get output something like:

```
-rw-r--r-- 1 leslie 154 Nov 4 10:18 myfile
```

The first dash on the left indicates that myfile is a file. Were it a directory, you would see a d in place of the dash. Each of the other items is explained in Table 1–2.

## Table 1–2 Standard Permissions

| Permission | Means This for a Directory | Means This for File |
|---|---|---|
| read (r) | Users can view names of files and directories. | Users can view the contents. |
| write (w) | Users can create, rename, or remove files or directories. | Users can change the contents. |
| execute (x) | Users can enter the directory. | Users can run the file |

## Table 1–3 Explanation of ls -l

| Output | Meaning | Explanation |
|---|---|---|
| rw-r--r-- | Permissions | Permissions are displayed in groups of three. Owner leslie has read and write permission. Group users and others have read-only permission. If a permission is not allowed, a dash appears in place of the letter. |
| | Number of links | Each entry has at least one link. |
| leslie | The owner of the file | leslie is owner. |
| users | Group | These are the permissions of the users group. |
| 154 | Size of the file in bytes | A very small file. |
| Nov 4 10:18 | Modification date | If the time of last modification was more than months ago, the year is substituted for the hour and minute. |
| myfile | The file name | myfile is the item being listed. |
