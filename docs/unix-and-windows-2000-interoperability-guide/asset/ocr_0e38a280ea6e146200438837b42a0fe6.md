# DHCP and DNS

Until recently, Dynamic Host Configuration Protocol (DHCP) and Domain Name System (DNS) have not coexisted very well. The latest incarnations of these services from both Microsoft and other sources move them closer together, even to the point of integration. While we mentioned both services in Chapter 6, “Name Resolution,” they bear a closer examination here. Because both Hewlett-Packard and Microsoft provide extensive documentation on both of these services, we will examine only the interaction between DHCP and DNS, not explore them in depth.

# 7.1 DHCP Clients

# 7.1.1 Windows 2000

By default, a Windows 2000 DHCP client will update its forward name (A resource record) with the Dynamic DNS (DDNS) server after receiving its IP address from the DHCP server. The DHCP server in turn updates the DNS with the reverse name (PTR resource record) of the client.

The Windows 2000 client uses an option in its messages to convey all or part of its domain name to a DHCP server. This option is called option 81, Client FDQN (fully qualified domain name), and its minimum length is four bytes. The format of this option is

| Code | Len | Flags | Rcode1 | Rcode2 | Domain Name |
