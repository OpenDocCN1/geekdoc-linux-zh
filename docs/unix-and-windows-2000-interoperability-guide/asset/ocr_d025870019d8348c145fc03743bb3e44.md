Finally, the client will send end-of-line sequences as ASCII carriage return and line feed.

By large, these settings work fine for HP-UX, with one notable exception: SAM. When you connect to an HP-UX system from a Windows 2000 Telnet client, HP-UX will recognize the ANSI terminal and set the HP-UX TERM variable accordingly. Applications as vi and SAM use the value stored in this variable to determine how to behave. While HP-UX recognizes the ANSI terminal, SAM does not work properly with the Windows 2000 Telnet client. SAM does not redraw the screen correctly after leaving some menus, making the application unbearable. Setting the TERM type option to VT100 does not help either. The only solution to the problem I've found is to use either a Windows server for a Telnet client that emulates an HP, HPTERM, or VT220 terminal. Other applications, such as vi and man, seem to work fine with the Microsoft Telnet client.

# 9.8 Authentication Issues

The Windows 2000 Finger. Rsh. and Rcp utilities do not require authentication; they require system configuration. Rexec requires user authentication but does not support Kerberos authentication. Therefore, when you type a password when executing Rexec, password is sent over the wire unencrypted. Traditionally, FTP and Telnet do the same. However, in Chapter 8, “User Authentication,” we saw that we can configure HP-UX FTP and Telnet servers to use Kerberos authentication. Avoiding this use of plain-text passwords and makes the use of these utilities more secure.

# 9.9 Conclusion

The basic TCP/IP utilities we looked at in this chapter are found on both Windows 2000 and HP-UX systems, though their syntax and behavior differ. Of these, the most widely used are undoubtedly FTP and Telnet. An FTP server and client are included in HP-UX, while on Windows 2000, we have the client only—unless you install the server with Internet Services. Both a Telnet server and client are bundled with HP-UX; only the client is bundled with Windows 2000. We look at the Windows 2000 server, available in a separate product, in the next chapter.
