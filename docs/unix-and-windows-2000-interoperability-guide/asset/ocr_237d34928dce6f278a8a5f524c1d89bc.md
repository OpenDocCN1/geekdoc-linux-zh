# 2.3.7.1 NTFS Security and Permissions

When a user logs into a Windows 2000 system, the user is either authenticated locally or by a domain controller, depending on the account the user has. If the user is properly authenticated, the operating system creates an access token containing the user's security identifier (SID) and security settings. NTFS stores an ACL for each file and directory, much like a node in a UNIX file system. Each ACL contains an access control entry (ACE) for the user or group to which the user belongs and the associated permissions. For a user to access an object in the file system, the ACL for that object must contain an ACE for that user or his her group. That ACE in turn specifies what kind of access is to be granted.

As in UNIX file systems, NTFS permissions vary, depending on whether you apply them to folders or to files. Tables 2–2 and 2–3 summarize NTFS permissions. (Taken from the Microsoft Windows 2000 Beta Training Kit, pp. 384–5.)

# Table 2–2 NTFS Folder Permissions³

| NTFS Folder Permission | Allows the User To |
|---|---|n| Read | See files and subfolders in the folder and view the folder ownership, permissions, and attributes. |
| Write | Create new files and subfolders within the folder, change folder attributes, and view folder ownership and permissions. |
| List Folder Contents | See the names of files and subfolders in the folder. |
| Read & Execute | Move through folders to reach other files and folders, even if the users do not have permission for those folders, and perform actions permitted by the Read permission and the List Folder Contents permission. |
| Modify | Delete the folder plus perform actions permitted by the Write permission and the Read & Execute permission. |
| Full Control | Change permissions, take ownership, and delete subfolders and files plus perform actions permitted by all other NTFS folder permissions. |
