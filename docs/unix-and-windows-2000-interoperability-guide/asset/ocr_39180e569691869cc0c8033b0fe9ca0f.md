# Terminal Emulators

1.4.2.1

So, how do you access a shell? When you create a UNIX account, one of the things you must specify is the path name of the shell that will run when the newly created user logs in. On older UNIX systems, you logged into some kind of text-based terminal, after which the login prompt disappeared and a blank screen with either a $ or a % command prompt took its place. This is frequently still the case on large server systems, however fancy graphics displays are usually unnecessary. If you use a current UNIX workstation, however, you are likely to login to some kind of graphical user interface based on the X Window System. Here, once you login, you get a number of windows, including something usually called a terminal emulator. A terminal emulator mimics one of the other terminals, most often the DEC v100 terminal.

Figure 1–1 displays an example of an *xterm*, a v100 emulator. This example comes from a Linux system; therefore the default shell is BASH. The default prompt for BASH is $bash$, but here it has been set to reflect the current user name and base name of the current working directory. Of course, *xterm* can run any of the other shells, and there are other terminal emulators out there, depending on the flavor of UNIX you run.

# Entering Commands

If you want to administer a UNIX system efficiently, with lots of power and flexibility at your fingertips, then it is a good idea to master one of the shells. Although some folks might scoff at a command-line method of system administration, you can do much more, and do so quickly, you get a good start at it. This is one of the golden rules of UNIX system administration.
