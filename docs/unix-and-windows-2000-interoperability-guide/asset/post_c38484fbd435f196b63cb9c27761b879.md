
## The Network Interface Layer

Now that we have a basic understanding of both UNIX and Windows 2000, let's move to the foundation of interoperability: networking. In recent years, the computing market place has moved to a number of standards that make networking between disparate operating systems much easier than in the early days of LANs. With the explosive growth of the Internet, one of these standards is the TCP/IP protocol suite. TCP/IP is often described using a four-layer model, depicted in Figure 3–1. Using that as our guide, we will begin our discussion with the lowest layer, the layer upon which all the other layers depend to function: the network interface layer.

## 3.1 Network Interface Cards and Drivers

From the viewpoint of the system administrator, the network interface layer deals primarily with network interface cards, cabling, and the operating system drivers that make these physical components work. It concerns the physical and electrical properties of a network medium, such things as voltages, currents, impedances, cable shielding, and distance limitations. It is also concerned with sending data to and receiving data from a network medium, usually in the form of frames (data encapsulated between headers and trailers). Each network interface technology in use today defines these and related characteristics. These technologies, found on both UNIX and Windows 2000 systems, include:

- Ethernet
- Token Ring
- FDDI
- ATM
- ISDN
- PPP over RS-232
- Fibre Channel

Details on how each of these technologies works can be found in a multitude of computer networking and data communications books, so there is no need to describe them in detail here. However, I would like to discuss two a little more: Ethernet, because of its importance today, and Fibre Channel, because of its increasing importance.

## Network Interface Cards and Drivers

### 3.1.1 Ethernet

It seems that today the network interface layer of choice for LANs is some form of Ethernet. Though adequate for most business desktop use, the 10-Mbs shared technology has been replaced by various forms of 100-Mbs networking, commonly as Base-TX (running on 4-pair UTP, Category 3, 4, or 5 at half-duplex), 100Base-TX (2-pair Category 5 UTP or Type 1 STP cable at full-duplex), and 100Base-FX (2 strands 62.5/125 micron multimode fiber at full duplex). Gigabit Ethernet (100Base-SX) is also making a showing these days, commonly for use in servers. Most desktops, however come with a 10/100-Mbs auto-sensing Ethernet card so that you can upgrade from 10-Mbs to 100-Mbs networking without buying a new adapter.

Digital Equipment Corp., Intel, and Xerox (DIX, for short) published the Ethernet II (sometimes called DIX) standard in 1982, based on Xerox's original technology. A few years earlier, the IEEE published another Ethernet standard, commonly known as IEEE 802.3, which, combined with the 802.2 Logical Link Control standard, defined a different frame format for Ethernet. Both types of frames can exist on the same network, but if your systems' network adapters cannot read both, then you will have to standardize on a frame format or separate your systems with an IP router.

### 3.1.2 Fibre Channel

Fibre Channel is a data communications technology that can interconnect storage devices with servers as well as provide high-speed networking. A Fibre Channel adapter can serve either as a disk I/O adapter or a network adapter because both SCSI and IP can run on top of it. Currently its most prevalent use is for connectivity to storage. Transfer rates are currently 133 Mbps, 266 Mbps, 530 Mbps, and 1 Gbps, with rates up to 4 Gbps coming soon. This technology is becoming increasingly important as the growth in Storage Area Networks (SANs) and Network-Attached Storage (NAS) continues.

A SAN is a network of shared storage, connecting servers of different types to high-capacity disk arrays, either through the use of Arbitrated Loop technology (up to 126 nodes) or Switched Fabric technology (theoretically, more than 16 million nodes). A conceptual view of a SAN is shown in Figure 3–2. Client systems can in turn access the information stored in these arrays over an existing IP network using a file server running some kind of file-sharing protocol such as Network File System (NFS) or Common Internet File System (CIFS), or both.

An important element in networking interoperability is the ability of an operating system to run multiple protocol stacks on a single network card. UNIX systems have been able to handle multiple stacks easily because of their protected memory model. (John Blomers, Architecting Enterprise Solutions with UNIX Networking, p. 168.) Windows 2000 accomplishes this task, something using an NDIS wrapper. NDIS is for the Network Device Interface Specification, which provides for an interface that, among other things, allows multiple protocols to bind to a single NIC driver. What this means is that both UNIX and Windows 2000 systems can concurrently run protocols such as TCP/IP, IP/SPX (or NWLink for Windows 2000), or AppleTalk. For a look at how Windows 2000 network architecture accomplishes this, see Figure 3–4. This capability is something we will come back later in this book.
