# User Authentication

Before we look at the interoperability of applications, we need to look at the issue of user authentication. We do so because most, if not all, of these applications require some kind of verification that the users are who they say they are. For example, if you use the Telnet application on a Windows, 2000 computer to connect to a UNIX system, you are asked to provide a user name and password. You are already authenticated by Windows 2000, but you need authentication from the UNIX system. If you install a Telnet-server on a Windows 2000 system and wish to connect to it via Telnet, you will go through an authentication process there as well. So it is a good idea to examine how authentication takes place in both Windows 2000 and UNIX (again using HP-UX as our example), so that we have some idea of what's going on when you issue a user name and password.

This chapter examines authentication only, not authorization. Authentication is the process of verifying the identity of a user to the system. From the system's standpoint, authentication answers the question, “Do I know you?” If it does, you have access to the system. If not, you do not have access. Authorization is the process of determining what an authenticated user can do. The system knows who you are and grant you access, exactly what you can perform on the system is a matter of authorization.
