# Chapter 10 • Windows Services for UNIX

**User Name Mapping.** This component maps Windows-based network user names to UNIX-based network user names. Server for NFS, Client for NFS, and Gateway for NFS use User Name Mapping for NFS authentication and access.

There is a lot of stuff in SFU, so let's look at some of what it has to offer, beginning with Telnet and Server for NFS. Since NFS concerns file sharing issues, we will defer discussion to the next chapter.

SFU comes on a compact disc; inserting into your CD-ROM drive starts the Windows Installer program. If your system is installed with Windows 2000 Professional, the following standard products are installed: Telnet Client, Telnet Server, Client for NFS, Korn Shell, and Utilities. Standard installation on Windows 2000 Servers also allows Server for NFS. The Custom Install of SFU allows you to install other components. You cannot install Client for NFS and Gateway for NFS if you want to synchronize the passwords of your domain accounts, you must install Password Synchronization on a domain controller. Also, you must install Server for NFS on a domain controller. By default, the installer will place SFU in the *SFU* directory and create an environment variable SFUDIR. If you choose a different directory, be sure that directory does not contain a space (like Program Files). The space can cause problems with shortcuts and the function of NFS.

SFU is administered through a Microsoft Management Console (MMC). Once you install your components, run Start→Programs→Windows Services for UNIX→Services Administration to get the MMC shown in Figure 10–1.

## 10.1 Telnet Client

The SFU Telnet Client's command has options the bundled client does not have. The syntax of the former is

```
telnet [-a] [-e escapeChar] [-f logfile] [-l user] [-t term] [host [port]]
```

The -a and -l options attempt an automatic login, which works only when the Telnet server supports the ENVIRON option. In my attempts to connect to either HP-UX 11 or Solaris 8 using those options, I found that the Telnet servers on both systems did not recognize the ENVIRON option. You can set the escape character (the keyboard sequence that takes you to the Microsoft Telnet> prompt while connected) to something other than the default CTRL+ with the -e option. You can set up a connection log file with the -f option. The log file you specify records the input and output of your Telnet session. For this Telnet client is VT100. If you want to specify a different one, use the -l option with VT52, ANSI, and VTNT as the terminal type. You can specify a host name or an IP address to connect to the remote system, as well as a port number if you do not use the default port of 23.

Telnet subcommands are also a bit different from the standard Telnet client. Listed in Table 10–1 are the subcommands documented by Microsoft. I've also indicated the command abbreviations in parentheses.

| Table 10–1 SFU Telnet Client Subcommands |
|---|---|
| open (o) | Establishes a Telnet connection to a host. |
| close (c) | Closes an existing Telnet connection. |
| display (d) | Produces a list of current settings for the Telnet client. |
| quit (q) | Exits from Telnet. |
| set | Sets the terminal type for the connection, turns on local echo, sets authentication to NTLM, sets the escape character, and sets up logging. |
| unset (u) | Turns off local echo or NTLM authentication. |
| status | Determines whether the Telnet client is connected. |

The display subcommand of the SFU Telnet Client provides the following output:

```
Microsoft Telnet> d
Escape Character is 'CTRL+'
Will auth (ntlm Authentication)
```

Local echo off

Line feed mode - Causes return key to send 0x0D

Current mode: Console

Will term type

Preferred term type is VT100

These parameters are similar to those of the standard Telnet client. If you type SET NTLM at the Telnet prompt, you will be authenticated by NTLM. If you are connecting to a Windows 2000 Telnet Server, you will not be prompted for a password. Even if you are using PAM NTLM on HP-UX, however, you will be prompted for a user name and password because the HP-UX Telnet Server does not recognize the NTLM option. Your default terminal type with this client is VT100, usually just fine for connecting to UNIX systems. If you will be connecting to Windows 2000 Telnet Servers and plan to use applications as EDIT, then you will set your terminal type to VTNT. In my tests using this Telnet client with HP-UX or Solaris Telnet servers, there will be no need to change the line feed mode.

### 10.2.1 Authentication

The Telnet Server supports both NTLM and plain text authentication. NTLM authentication works quite well with Windows Telnet clients; it avoids having to enter a user name and password and thereby keeps encrypted passwords over the network. With HP-UX server will prompt for a user name and password, even if you use PAM NTLM to authenticate you. The reason for this is that the Telnet client and server negotiate which options they will employ at session startup. Windows 2000 Telnet clients and servers support option 37, the Authentication Option, to enable NTLM. HP-UX clients and servers do not. Therefore, even if PAM NTLM authenticated you when you logged on to your workstation, the Telnet server will still ask for a user name and password.

Once authenticated, Windows 2000 runs the %SYSTEMROOT%\system32\login.cmd script, which by default looks like the following:

```
@echo off
rem
rem global login script for the Telnet Server
rem In the default setup, this command script is executed when the
rem initial command shell is invoked. It, in turn, will try to
rem the individual user's login script.
rem
```

```
echo ====================================================
Welcome to Microsoft Telnet Server.
echo ====================================================
```

```
cd /d %HOMEDRIVE%\HOMEPATH%
```
