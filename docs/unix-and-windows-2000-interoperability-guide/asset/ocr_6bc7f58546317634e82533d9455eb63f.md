# NFS File Sharing

In late 1984, Sun Microsystems introduced the Network File System (NFS), a means of sharing files among computers connected to a network. Though it was designed to be operating system-independent. NFS originated in SunOS, a Berkeley-based UNIX operating system, and dominates file sharing in the UNIX world. However, NFS does not exist on other systems, including mainframes, minicomputers, and PCs. Windows Services for UNIX version 2 provides both an NFS server and client for Windows 2000 systems.

# 11.1 Basic Concepts

NFS is designed as a client-server technology. A system running an NFS server can export file systems to client systems. The NFS clients running on the client systems mount (gain access to) the server's exported file systems. The mount process essentially “attaches” a remote file system to a local directory, making it appear to the local system and the user that the remote file system is actually local. Thus, with the appropriate permissions, a user can change directories to the mounted file system and list, create, and delete files there, with no indication (barring a ridiculously slow network) that he or she is actually working on remote files.

While there are certainly many differences between NFS and CIFS (Common File System, the Windows file sharing system), those familiar with the latter can draw some parallels. Instead of exporting file systems, Windows systems makes directories available over the network in the form of shares. Clients connect to these shares either by mapping a network drive or by referring to a Universal Naming Convention, or UNC. The mapping process is somewhat analogous to mounting a file system. Windows users click on the icons representing network drives, and—depending on the permissions—add, delete, delete, edit, list, or print files.
