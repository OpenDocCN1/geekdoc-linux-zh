## 8.3.1.3 /etc/krb5.conf

This file specifies the defaults for the realm and for Kerberos applications, mappings of names onto Kerberos realms, and the location of KDCs for Kerberos realms. A sample /etc/krb5.conf is as follows:

```
[defaults]
  default_realm = REALM.HP.COM
  default_tkt_encypes = DES-CBC-CRC
  default_tgs_encypes = DES-CBC-CRC
  ccache_type = 2

[realms]
  REALM.HP.COM = {
    kdc = hostname.hp.com:88
    admin_server = hostname.hp.com
  }

[domain_realm]
  cup.hp.com = REALM.HP.COM

[logging]
  kdc = FILE:/var/adm/krb5kdc.log
  admin_server = FILE:/var/adm/kadmin.log
  ccache = FILE:/var/adm/krb5lib.log
```

In the environment, of course, you would specify your own realm instead of REALM.HP.COM. In the [defaults] section, you must include "ccache_type = 2" for PAM Kerberos configuration. In the [realms] section, you specify the KDC and administrative server for each realm. You specify the location of log files issued by the KDC and administrative server in the [logging].

## 8.3.2 Employing a Windows 2000 KDC with HP-UX Application Servers and Clients

The following is derived from a Microsoft white paper Step-by-Step Guide to Kerberos 5 (krb5 1.0) Interoperability, be sure that MIT Kerberos distribution is installed on the HP-UX system and the Support Tools are installed on the Windows 2000 KDC. The Support Tools, which are stored on the Advanced Server Installation CD, include the ktpass utility.

- 1. Using the Active Directory Users and Computers management tool on the KDC, create a user account for the HP-UX host. (That's right, a user account for a computer).
- 2. On the KDC, use ktpass to create the keyfile and set up the account for the HP-UX host. The syntax is

```
C:> ktpass -princ host/hostname=REALM-NAME -mapuser account -out -pass password keytable.out
```

where hostname is the FDN, REALM-NAME is the uppercase name of the Windows 2000 domain, account is the user account for the computer, password is a complex password for the account, and keytable.out is the name of the output file. Microsoft's documentation using unixmachine.keytab, but you can use a different name. For

```
C:> ktpass -princ host/hux1.book.local@BOOK.LOCAL -mapuser hux1 -pass password -out unixmachine.keytab
```

- 4. On the HP-UX system, manage the imported keytab file with the default keytab file /etc/krb5.keytab using the ktutil utility. My installation put this utility in /opt/krb5-1.2/src/sbin/ktutil. For example:

```
# cd /opt/krb5-1.2/src/sbin/ktutil
# ./ktutil
ktutil: rkt unixmachine.keytab
ktutil: list host/hpux1.book.local@BOOK.LOCAL
ktutil: wkt /etc/krb5.keytab
```

In this example, the user runs ktutil to read (rkt) the imported keytab file (unixmachine.keytab), list its contents, and then to write (wkt) the contents to /etc/krb5.keytab.

- 5. On the HP-UX system, edit /etc/krb5.conf to refer to the Windows 2000 domain controller as the KDC. You can use the sample /etc/krb5.conf file shown previously, but you need the [logging] stanza. Since your KDC is a Windows system, if your HP-UX DNS name is the same as the realm name, then you won't need the [domain_realm] stanza. Otherwise, use that stanza to map your DNS name to your Kerberos realm. For example:

```
[defaults]
  default_realm = BOOK.LOCAL
  default_tkt_encypes = DES-CBC-CRC
  default_tgs_encypes = DES-CBC-CRC
  ccache_type = 2

[realms]
  kdc = w2kserver.book.local:88
  adm_server = w2kserver.book.local
}
```

- 6. Synchronize your system clock to within two minutes of the KDC’s clock to prevent authentication errors due to skews.

- 7. Create corresponding user accounts on both the Windows 2000 domain and HP-UX system. The HP-UX user account does not need a password, since authentication to the Windows 2000 KDC include the UID, shell, and home directory information so the user actually has access to the workstation once authenticated.

 examples came from my small lab used in writing this book. The system called W2KSERV, a Windows 2000 domain controller, was my KDC, and BOOK.LOCAL was my realm name. I created a user account for my HP-UX system, hpux1, on the KDC and then used ktpass to create a keytab file. I copied this keytab file to hpux1 and then ran ktutil to merge it with /etc/krb5.keytab, I edited /etc/krb5.conf as in the example in step 6, synchronized the clocks, and then created two users on the KDC: root and dylan.

After some experimentation, I came up with a basic /etc/pam.conf file to suit my needs. The contents of this file were

```
# PAM Configuration
#
# Account Management
#
account required /usr/lib/security/libpam_krb5.1
dtlogin account required /usr/lib/security/libpam_krb5.1
ftp account required /usr/lib/security/libpam_krb5.1
login account required /usr/lib/security/libpam_krb5.1
su account required /usr/lib/security/libpam_unix.1
other account required /usr/lib/security/libpam_krb5.1
#
# Authentication Management
auth auth required /usr/lib/security/libpam_krb5.1
dtlogin auth required /usr/lib/security/libpam_krb5.1
ftp account required /usr/lib/security/libpam_krb5.1
login auth required /usr/lib/security/libpam_krb5.1
su auth required /usr/lib/security/libpam_unix.1
other auth required /usr/lib/security/libpam_krb5.1
#
# Password Management
password required /usr/lib/security/libpam_krb5.1
dtlogin password required /usr/lib/security/libpam_krb5.1
login password required /usr/lib/security/libpam_krb5.1
passwd password required /usr/lib/security/libpam_unix.1
other password required /usr/lib/security/libpam_krb5.1
#
# Session Management
#
session required /usr/lib/security/libpam_krb5.1
dtlogin session required /usr/lib/security/libpam_krb5.1
login account required /usr/lib/security/libpam_krb5.1
other session required /usr/lib/security/libpam_krb5.1
```
