
## 数据使用策略
本节应涵盖服务器上的用户和数据文件类型，以及应如何处理这些文件。它应包含初始权限、访问控制和组创建标准。

## 审计、监控与执行
如果安全策略未被实际执行，那么它毫无用处。在本节中，您应明确定义将用于监控服务器和网络资源以确保策略得到遵守的工具和方法。务必明确列出将对违规者施加的惩罚性和/或纠正性措施类型。

> **注意** 您必须落实策略文档中的审计部分，否则制定该策略毫无意义。这听起来可能显而易见，但如果您不监控网络的安全状态，就无法拥有一个安全的网络。

## 正式认可
这是您明确说明谁直接负责策略的编写及持续执行的章节。它应包含 IT 官员、法律顾问以及策略本身的开发者的签名。务必注明签名的日期。

即使是最清晰、简洁且完整的安全策略，如果员工无法访问，也将无效。务必将该策略的纸质副本包含在新员工入职培训资料中，并定期提醒员工其在线位置，以便他们可以在策略演变时查阅它。此外，定期进行关于其使用和合规性的培训课程，并建立一种机制，使用户和 IT 人员都能提交改进建议。

# 安全机制实施

一旦达成了一致认可的安全策略，就需要实施必要的机制来执行它。这通常是系统配置更改、工具安装、用户流程开发和监控的组合。为了实施上一节中策略大纲所述的机制，您需要执行以下任务：

- **物理安全**：在数据中心安装 UPS 设备、组合锁和物理环境报警器，如果尚未提供这些设施的话。配置 Linux 服务器，使得 root 访问仅允许在控制台上进行。
- **内网和外网服务**：安装并配置周边防御设备（防火墙、带有访问列表的路由器等），以执行对外网和内网服务的限制。（第 9 章“网络层防火墙”详细探讨了 Linux 防火墙的话题。）
- **远程访问**：安装并配置虚拟专用网端点（参见第 12 章“虚拟专用网”）和/或支持强远程认证和授权的网络设备（参见第 13 章“强用户认证”）。
- **用户账户策略**：配置 `/etc/login.defs` 配置文件，强制用户定期更改密码。我建议将 `PASS_MAX_DAYS` 设置为最多 90 天，这将强制用户在每三个月内更改密码。这段时间能保持用户的警觉，并提醒他们密码是网络安全非常重要的一部分，尽管每 90 天更改一次密码可能被视为一种麻烦。编写一个脚本，定期执行 `last` 和 `finger` 命令，以确定用户处于非活动状态的时间长度，并视情况在 `/etc/passwd` 条目中插入星号 (*)。此外，您应训练用户选择良好的、不可预测的密码，该密码包含字母数字字符，且与用户的环境无关，例如其配偶的名字、居住的街道或驾驶的汽车。
- **数据使用策略**：在初始文件创建时使用正确的全局 `umask` 权限，并定期执行脚本，以确保没有未经授权的 setuid/setgid 可执行文件。（参见第 2 章“系统安装与设置”，其中全面讨论了系统安全配置和监控。）
- **审计、监控与执行**：安装审计和监控工具，如 Satan、COPS 或 PortSentinel，并定期使用它们，以确保您的网络防御仍符合您的安全策略。（参见第 5 章“网络监控与审计”，其中综合讨论了网络审计和监控工具。）

# 策略定期编辑和安全审计

就像互联网一样，您的网络可能一直在变化。确保审查您的安全策略，以确保它仍然反映您的网络需求。您最近是否添加了任何新服务器？由于贵公司最新的并购，您的用户群是否大幅增长？是否最近有一轮裁员，导致许多不满的员工离开？即使您的网络没有发生重大变化，您需要扮演入侵者的角色，尝试从外部进入您的服务器。确保您领先于那些不断试图做同样事情的真实坏蛋一步。

您安全策略中值得特别关注的领域是远程访问。随着 VPN 技术的近期出现，使用安装在笔记本电脑上的简单点对点隧道协议 (PPTP) 或互联网协议安全 (IPSec) 客户端为差旅用户提供的通用访问比以往任何时候都更容易。认识到允许这种类型访问的含义很重要。过去您可以物理上看到网络的边界，而远程访问将内网的周边扩展到您可能不希望完全信任的地方。您可能希望重新装备您的安全策略，以包括对以下方面等的限制：

- 要使用的 IPsec/PPTP 客户端版本。
- 客户端的超时设置。通常，闲置了 15 分钟的用户并不介意重新建立远程连接。
- 使用的认证类型。用户名/密码已不足以进行安全的远程访问。
- 屏幕保护类型和闲置长度。要求使用在达到闲置超时后锁定密码的屏幕保护程序。

此外，本书介绍了一些软件实用程序，可用于自动化确保策略合规性所必需的部分审计和监控。第 3 章“系统监控与审计”讨论了系统级别的审计，而第 5 章将讨论扩展到网络层。

# 信息安全的目标

您可以将 Linux 服务器的所有安全需求映射到四个基本目标之一：

- 数据保密性
- 数据完整性
- 用户认证和访问控制
- 数据和服务可用性

您的安全策略、工具及策略实施以及配置管理的最终目的是解决这些每一个目标。以下部分将详细研究每个目标。

# 数据保密性

在这个日益公开的世界中，维护 Linux 服务器中数据的保密性本身是一项全职工作。随着用户依靠网络服务器处理日常工作的更多方面，他们也将更多机密和私密信息托付给这些服务。密码学的出现为 Linux 系统管理员提供了一项宝贵的工具，通过允许用户加密存储在服务器上的敏感数据来确保保密性。Linux 支持私钥和公钥加密，这是两种主要的密码加密类型。

# 私钥加密

也称为*对称密钥*加密，私钥加密允许用户选择一个秘密密钥，然后用于初始化一个算法，将敏感数据（明文）转换为混乱或加密的数据（密文）。此过程是可逆的，因此，只要他能或她生成原始的加密密钥，同一用户可以解密密文以恢复原始明文。密钥越长，攻击者从密文推导出明文就越困难。

私钥加密的*事实*标准是数据加密标准 (DES)，由 IBM 于 1977 年开发供美国政府使用。虽然当时认为其 56 位密钥是足够的，但 DES 算法已被破解多次。这促使美国国家标准与技术研究院 (NIST) 协调开发下一代 DES，称为 AES（高级加密标准），它使用更长的密钥长度，且实质上是更加健壮的。

有几个 Linux 安全应用程序使用了私钥加密，包括 Kerberos 认证工具套件。第 13 章更详细地涵盖了这一主题。

# 公钥加密

虽然私钥加密是保护敏感数据的有效方式，但它缺乏保护两个方之间数据交换所需的多功能性，特别是当这两个方彼此之间没有先前知识时。这促使 Martin Hellman 和 Whitfield Diffie 在 1976 年的里程碑式论文《密码学的新方向》（发表于 *IEEE Transactions on Information Theory*）中开发了公钥加密的概念。这个想法出奇地简单：发送方使用接收方广为人知的公钥加密消息。接收方（且仅接收方）随后可以解密消息以恢复原始明文。这确保了消息的保密性，而无需发送方和接收方共享一个共同的私钥。不出所料，公钥加密是一种常用的技术，用于保护电子邮件内容在通过互联网传输时的安全。

Linux 支持的 Pretty Good Privacy (PGP) 包及其开源对应物 GNU Privacy Guard (GPG) 提供了两个由公钥驱动的安全应用程序的示例。第 6 章“电子邮件”描述了 PGP 和 GPG。
