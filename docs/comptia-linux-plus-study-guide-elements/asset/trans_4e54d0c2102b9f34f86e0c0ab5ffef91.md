

你应时不时地通过查看 `/etc/passwd` 和 `/etc/shadow` 文件来研究你的本地账户。第5章对这些文件及其内容有更详细的描述。请特别关注以下安全问题：

**未知账户** 大多数Linux系统都有许多系统账户，你可能无法记住所有账户，因此不要妄下结论，但如果你发现一个不认识的账户，你应该对其进行调查。检查该账户的特征是否存在任何可疑之处，将你当前的文件与系统安装后制作的备份进行对比，并检查涉及该账户活动的日志文件。

**UID为0的账户** Linux使用UID 0来表示*root*，因此任何除了*root*以外的UID为0的账户都*高度*可疑。攻击者有时会创建这样的账户，或者将现有账户的UID更改为0，以便在系统上获得*root*权限。

**带有密码的系统账户** 系统账户，例如*daemon*和*cron*，通常被Linux用于在没有*root*权限的情况下运行服务器或其他工具。通常，这些账户不需要密码，因此如果你在`/etc/shadow`中看到此类账户的密码，这极有可能表明存在入侵。如果你使用shadow密码，那么所有账户在`/etc/passwd`文件的密码字段中都有一个*x*，因此你必须检查`/etc/shadow`文件。没有密码的账户在该文件密码字段（即第二个字段）中由感叹号或星号表示。

**登录Shell** 登录Shell是`/etc/passwd`文件中的最后一个字段。大多数系统账户使用`/bin/false`或`/dev/null`作为登录Shell，尽管有一些例外。最值得注意的是，*shutdown*账户使用`/sbin/shutdown`，*halt*账户使用`/sbin/halt*，而*root*使用普通Shell（通常是`/bin/bash`）。一些服务器软件包也会创建具有普通Shell作为登录程序的账户，但大多数不会。这种做法因服务器程序和发行版而异。不过，作为一般规则，你应对除`/bin/false`或`/dev/null`以外具有登录Shell的系统账户保持警惕。

审查账户的最佳方法之一是在写保护的可移动介质（例如写保护的软盘）上保存`/etc/passwd`和`/etc/shadow`的备份。然后，你可以挂载该磁盘并使用*diff*将备份与磁盘上的文件进行对比：

```
# diff /etc/passwd /mnt/floppy/passwd
# diff /etc/shadow /mnt/floppy/shadow
```

如果你没有添加、删除或修改账户，这些命令应不返回任何输出行。如果账户已更改，`diff`将总结这些更改。请注意，对`/etc/shadow`的更改包括密码更改，因此在多用户系统上，这种比较很可能会发现许多更改，特别是如果用户勤于定期更改密码的话。

> 存储在软盘上的密码文件本身构成安全风险。它们应上锁保存——理想情况下放在保险箱中，只有通常可以读取原始文件的系统管理员才能访问。

## 验证已安装的文件和软件包

最终的安全审计方法是验证已安装的文件和软件包。实现这一点的一种方法是使用RPM等软件包工具，这在后文“使用软件包管理校验和”中有所描述。此过程有助于查找被粗糙替换的程序文件。但它无法帮助你发现未通过软件包管理器安装的程序文件中发生的更改。此外，它对配置文件的更改过于敏感，而这些配置文件在安装软件包后你经常会自行修改。Tripwire（后文“使用Tripwire”中有描述）是另一种可以以此方式使用的工具。它在发现关键配置文件的更改方面更有用，但使用起来更麻烦。

你可以采取的另一种方法是保持已知良好配置文件的备份在只读介质上。然后，你可以时不时地将当前配置文件与备份进行对比。使用后文“审查账户”中描述的diff，可以是执行此操作的有效方法。

## 入侵检测

即使配置得最好的计算机也存在漏洞。幸运的是，这些漏洞可能不会被利用，但你不应做此假设。相反，你应该主动搜索系统中入侵的证据。这样，你至少会在入侵发生时收到警报，并能够在入侵发生后尽快采取适当措施。“适当措施”通常是彻底重新安装或从干净备份恢复，随后加强疑似入口点的安全措施。一旦系统被获取root权限，你就无法完全信任该系统上的任何事物，从已知干净的来源恢复所有文件通常比检查每个文件是否有篡改迹象更容易。

存在多种检测入侵者的方法。这些方法从警惕可疑活动到使用各种可以监控网络活动或检查关键文件变化的程序不等。

## 入侵的症状

检测入侵的一种方法是注意系统运行的异常。这种方法不可靠，但也是最通用的方法，因此即使入侵者有方法击败你可能使用的更具体的监控工具，这种方法也可能成功。基本方法听起来很简单：了解你的系统通常如何运行，并警惕这种运行行为的改变。入侵的症状可能包括以下内容：

- **系统变慢** 入侵者可能会在你的计算机上运行导致其比通常更缓慢地响应正常工作负载的程序。
- **网络活动增加** 就像入侵者可以消耗CPU时间一样，他们也可以消耗网络资源。事实上，黑客入侵计算机的一个原因是利用你的网络连接。他们可能正在使用你的系统向他人发起DDoS攻击，在非法FTP服务器上分发布文件，或用于其他消耗大量网络带宽的目的。
- **程序行为改变** 黑客经常用自己的定制版本替换标准系统工具。这些工具的行为可能与原始工具略有不同，因此常见工具行为的变化（例如输出文本不同，或抱怨昨天可用的选项不再可用）可能是系统被妥协的线索。
- **系统或软件崩溃** 如果计算机或个别程序开始无明显原因的崩溃，可能是因为它们已被入侵者修改。在某种意义上，这只是程序行为改变这一症状的推论，但更为严重。
- **神秘更改的数据文件** 如果你没有修改普通数据文件而它们却发生了改变，一种可能的解释是入侵。事实上，根据更改的性质，这可能是一个明显的信号。例如，入侵者有时仅以破坏网站为目的进行入侵，因此此类更改几乎可以肯定表明系统已被妥协。
- **缺失或损坏的日志文件** 入侵者经常试图通过修改或删除日志文件来掩盖他们的踪迹。（第4章更详细地涵盖了日志文件。）因此，此类更改应引起警惕。
- **外部投诉** 如果其他网站的管理员联系你，抱怨来自你网站或其他可疑行为的攻击，可能你的计算机已被妥协，并正被用于攻击其他系统。
- **本地用户投诉** 本地用户可以警惕某些类型的问题，例如系统迟缓或程序行为变化。倾听他们的投诉，并迅速进行调查。

使用这些症状中任何一个的问题在于，它们都可能由入侵以外的原因造成。本地程序可能会失控运行，消耗CPU时间或网络带宽；由于合法的程序升级、新出现的硬件缺陷或更改的环境设置，程序的行为可能会不同或崩溃；由于其他用户的合法活动或磁盘错误，数据文件和日志文件可能会发生改变；外部投诉可能是错误产生的，或者可能追溯到没有获得不当本地访问权限的流氓本地用户；本地用户投诉可能反映这些或许多其他非安全问题。尽管如此，警惕这些线索可以引导你调查并解决问题，无论最终是否是安全问题。

### 使用Snort

Snort（http://www.snort.org）是一个强大的*数据包嗅探器*程序——一个监控定向到其主机计算机（或其本地网络段上的其他计算机）数据包的程序。数据包嗅探器是非常强大的网络诊断工具，因为它们允许你深入网络交易的“内部”。你从此类调查中获得的帮助可以诊断各种各样的问题，但这需要对底层协议有广泛的知识。
