### 管理进程

在很大程度上，文件相当静态；一旦创建，文件可能会在几分钟、几小时、几天或更长时间保持不变。正在运行的程序或进程是一个更具动态性的实体；它存储在内存中，并指示计算机的CPU执行某些任务。由于这一事实，进程提出了与文件不同的管理挑战。

### 理解进程

进程以多种方式启动。这包括从shell启动，如第2章所述，以及从系统启动脚本启动，如第4章“管理系统服务”中更详细地描述。无论进程如何启动，都可以以各种方式控制。您可以获取运行中进程的列表，限制其CPU使用，甚至可以终止您不希望其运行的进程。

在继续之前，了解一些术语非常重要。在Linux中，进程几乎与正在运行的程序同义。由于Linux是一个多用户、多任务操作系统，因此一个程序可以同时作为多个进程运行。例如，假设tbaker和smccoy都使用Vi编辑文本文件。计算机将同时运行两个Vi进程。事实上，单个用户可以这样做。单个程序创建（或fork）子进程也是可能的。例如，Vi可以启动一个拼写检查程序。实际上，当你从shell启动程序时就是这样——shell会fork你正在启动的程序。当一个进程fork另一个进程时，原始进程被称为父进程，被fork的进程被称为子进程。这种父子关系产生了一种树状层次结构，最终可以追溯到init，这是内核启动时运行的第一个进程。图3.1展示了一个简化的示例。在图3.1中，init fork了login进程，login进程又fork了bash进程，bash进程fork了其他进程。（实际上这比这稍微复杂一些；init不是直接fork login，而是通过另一个进程，如getty来做。）这可以继续任意层，尽管许多程序不能fork其他程序。

### 使用ps查看进程列表

进程管理中最重要工具之一是ps。该程序显示进程的状态（这就是它被称为ps的原因）。它具有许多有用的选项，对于监控系统上发生什么非常有帮助。当计算机没有按预期工作时，这可能特别关键——例如，如果它异常缓慢。ps程序支持数量不寻常的选项，但只需其中几个就能让你走得很远。同样，解读ps输出可能很棘手，因为如此多的选项改变了可用的内容。一些类似的ps程序，最著名的是top，也值得关注。

### 查看ps选项

ps的正式语法相当简单：

```
ps [options]
```

这种形式的简单性掩盖了相当大的复杂性，因为ps支持三种不同类型的选项，以及每种类型中的许多选项。这三种类型的选项如下：

- **Unix98选项** 这些单字符选项可以分组在一起，并以单个连字符(-)开头。
- **BSD选项** 这些单字符选项可以分组在一起，但*不能*以连字符开头。
- **GNU长选项** 这些多字符选项不分组在一起。它们以两个连字符(--)开头。

可以分组的选项可以聚集在一起，中间没有空格。例如，而不是输入ps -a -f，你可以输入ps -af。如此复杂的原因在于，ps工具在历史上从一个Unix操作系统到另一个变化很大。主要Linux发行版中附带的ps版本试图实现所有这些不同ps版本的大多数功能，因此它支持许多不同的个性。事实上，你将PS_PERSONALITY环境变量设置为posix, old, linux, bsd, sun, 或digit1，或其他各种值，可以更改其一些默认行为。（第2章描述了如何设置环境变量。）本节其余部分描述了大多数Linux系统上默认的ps行为。表3.1总结了一些更常用的ps功能。
