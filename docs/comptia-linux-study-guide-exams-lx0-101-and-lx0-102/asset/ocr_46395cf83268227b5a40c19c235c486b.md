# Using GPG 507

$ gpg --export name > gpg.pub

This command saves the public key associated with name in the file gpg.pub. You can use your email address as name. (If you create additional public keys or add others' public keys to your keyring, you can specify their names to export those.) You can then make your public key available to others so that they may encrypt email messages sent to you or verify your signed messages. Adding the --armor option produces ASCII output, which may be preferable if you intend to send the key. You can make the file accessible on your Web site, transfer it as an email attachment, or distribute it in various ways.

One important method of distributing your public key is using a keyserver. This is a network server that functions like a keyring. To send your public key to a keyserver, you can use the --keyserver hostname and --send-keys keyname options to gpg, as follows:

```
$ gpg --keyserver ppg.mit.edu --send-keys jennie@luna.edu
```

This example sends the public key for jennie@luna.edu from your public keyring to the server at ppg.mit.edu. Anybody, who wants to retrieve the key from that server. (ppg.mit.edu is a popular site for hosting GPG public keys.)

# Importing Keys

To encrypt email send to others, you must obtain their public keys. Ask your correspondents to obtain them. Once you do so, you can add their keys to your keyring (that is, the set of keys GPG maintains):

```
$ gpg --import filename
```

This command adds filename to your set of public keys belonging to other people.

![](bbox=[0.14, 0.603, 0.223, 0.653])

Although public keys are, by definition, public, there are security concerns relating to them. Specifically, you should use a legitimate public key. Hypothetically, a miscreant could distribute a fake public key in order to obtain sensitive communications or fake a signed email. For instance, George might distribute a fake GPG public key that claimed to be from Harold. George could either sign messages or intercept email sent to Harold that was encrypted using the fake key. Thus, you should use as secure a communication method as possible to distribute your public key and receive public keys from others.

Once you've created your own key, and perhaps, imported keys from others, you can see what keys are available using the --list-keys option to gpg:

```
$ gpg --list-keys
/home/jones/.gnupg/pubring.gpg
```
