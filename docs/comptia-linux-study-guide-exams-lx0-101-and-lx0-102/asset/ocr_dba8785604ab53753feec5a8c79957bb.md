The word formatting is somewhat ambiguous. It can refer to low-level formatting, which creates a structure of sectors and tracks on the disk media, or high-level formatting, which creates a filesystem. Hard disks are low-level formatted at the factory and should never need to be low-level formatted again. Floppy disks, though, can be both low- and high-level formatted. The tools described here can high-format a floppy disk as well as a hard disk. To low-format a floppy disk, you must use the fdcommand, as in fdformat /dev/fd0. This command cannot be used on a hard disk.

# # Common Filesystem Types

Linux supports quite a few different filesystems, both Linux-native and intended for other OSs. Some of the latter work under Linux, and even when they do not support all the features that Linux expects in its native filesystems. When preparing a Linux system, you will use one or many of native filesystems for most or all partitions:

**Ext2 The Second Extended File System (ext2fs or ext2)** is the traditional Linux-native filesystem. It was created for Linux and was the dominant filesystem throughout the late 1990s. Ext2fs has a reputation as a reliable filesystem. It has since been eclipsed by other filesystems, but it still has its uses. In particular, ext2fs can be a good choice for a small /boot partition, if you choose to use one, and for small (sub-gigabyte) removable disks. On small partitions, the size of the journal used by more advanced filesystems can be a real problem, the non-journaling ext2fs is a better choice. (Journaling is described more detail shortly.) The ext2 filesystem type is ext2.

> On an EFI-based computer, using ext2, ext3fs, or ReiserFS /boot partition enables the firmware to read this partition with the help of suitable drivers. This can expand your options for boot loader configuration.

**Ext3fs The Third Extended File System (ext3fs or ext3)** is basically a filesystem that is as reliable as ext2fs but that recovers from power outages and system crashes more quickly. The ext3 filesystem type is ext3.

**Ext4fs The Fourth Extended File System (ext4fs or ext4)** is the next-generation version of this filesystem. It adds the ability to work with very large disks (over 16TiB, the limit for ext2fs and ext3fs) and very large files (over 2TiB), as well as extensions to improve performance. Its filesystem type is ext4.

**ReiserFS** This filesystem was designed from scratch as a journaling filesystem for Linux. It is particularly good at handling large numbers of small files (say, smaller than 32KB) Because ReFS uses various tricks to squeeze the ends of files into each other's unused space. These small savings can add up to a large percentage of file sizes when files are small. You can use reiserfs as the code type for this filesystem.
