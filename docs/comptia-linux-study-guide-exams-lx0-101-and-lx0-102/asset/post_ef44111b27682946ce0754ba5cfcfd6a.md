
# Designing a Hard Disk Layout

### Filesystem Choice
By partitioning your disk, you can use different filesystems—data structures designed to hold all the files on a partition—each partition. Perhaps one filesystem is faster than another and is so important for time-critical or frequently accessed files, but another may provide accounting or backup features to use for users' data files.

### Disk Space Management
By partitioning your disk, you can lock sets of files into a fixed space. For instance, if you restrict users to storing files on one or two partitions, they can fill those partitions without causing problems on other partitions, such as system partitions. This feature can help keep your system from crashing if space runs out. On the other hand, if you get partition sizes roughly, you can run out of space on just one partition much sooner than if you'd used fewer partitions.

### Disk Error Protection
Disks sometimes develop problems. These problems can be the result of bad hardware or errors that creep into the filesystems. In either case, splitting a disk into partitions provides some protection against such problems. If data structures on one partition become corrupted, these errors affect only the files on that partition. This separation can protect data on other partitions and simplify recovery.

### Security
You can use security-related mount options on different partitions. For instance, you might mount a partition that holds critical system files read-only, preventing users from writing to that partition. Linux's file security options should provide similar protection, but taking advantage of Linux filesystem options provides redundancy that can be helpful in case of an error in setting up file or directory permissions.

### Backup
Backup tools work best on partitions. By keeping partitions small, you may be able to back up more easily than you could if your partitions were large.

In practice, most Linux computers use several partitions, although precisely how the system is partitioned varies from one computer to another (The upcoming section "Common Partitions and Filesystem Layouts" describes some possibilities.)

# Understanding Partitioning Systems

Partitions are defined by data structures that are written to specified parts of the disk. Several competing systems for defining these partitions exist. On x86 and x86-64 hardware, the most common method up until 2010 was the Master Boot Record (MBR) partitioning system, because it stores its data in the first sector of the disk, which is also known as MBR. The MBR system is limited to partitions and partition placement of 2 terabytes (TiB; 1TiB is 2⁴ bytes), at least when using the nearly universal sector size of 512 bytes. The successor to MBR is the GUID Partition Table (GPT) partitioning system, which has much higher limits and certain other advantages. The tools and methods for manipulating MBR and GPT disks differ from each other, although there's substantial overlap.

Still more partitioning systems exist, and you may run into them from time to time. For instance, Macintoshes that use PowerPC CPUs generally employ the Apple Partition Map (APM), and many Unix variants employ Berkeley Standard Distribution (BSD) disk labels. You're most likely to encounter MBR and GPT disks, so those are the partitioning systems covered in this. Details for other systems differ, but the basic principles are the same.

# MBR Partitions

The x86 partitioning scheme allowed for only four partitions. Hard disks increased in size and the more for partitions became apparent, the original scheme was extended in a way that retained backward compatibility. The new scheme uses three partition types:

- Primary partitions, which are the same as the original partition types
- Extended partitions, which are a special type of primary partition that serves as a placeholder for the next type
- Logical partitions, which reside within an extended partition

Figure 3.4 illustrates how these partition types relate. Because logical partitions reside within a single extended partition, all logical partitions must be contiguous.

**FIGURE 3.4** The MBR partitioning system uses up to four partitions, one of which can be a placeholder extended that contains logical partitions.

| First partition | Second primary partition/extended partition | First logical partition | Second logical partition | Third partition |
|---|---|---|---|---|

For any one disk, you're limited to four partitions, or three partitions and one extended partition. Many OSs, such as DOS, Windows, and FreeBSD, *must boot* from primary partitions, and because hard disks include at least one primary partition. Linux, however, is not limited, so you could build Linux from a disk that contains no primary partitions, although in practice few people do this.

The primary partitions have numbers in the range of 1–4, whereas logical partitions are numbered 5 and up. Gaps can appear in the numbering of MBR partitions; however, such gaps cannot exist in the numbering of logical partitions. That is, you can have a disk with partitions 1, 3, 5, 6, but not 1, 3, and 7—if a partition 7 exists, there must be a 5 and a 6.

In addition to the partition table, the MBR data structure holds the primary BIOS boot loader—the first disk-loaded code that the CPU executes when a BIOS-based computer boots. The MBR is extremely important and sensitive. Because the MBR exists only in the first sector of the disk, it's vulnerable to damage; accidental erasure will make your disk unusable unless you have a backup.

You can back up your MBR partitions by typing `fdisk -d /dev/sda > sda-backup.txt` (or similar commands to specify any other device or backup file). You can then copy the backup file (sda-backup.txt in this example) to a removable disk or another computer for safekeeping. You can restore the MBR partitions by typing `fdisk -f /dev/sda < sda-backup.txt`. Be sure you are using the correct backup file, though a mistake can generate incorrect partition definitions!

MBR partitions have type codes, which are 1-byte (2-digit hexadecimal) numbers, to identify their purpose. Common type codes you may run into:
- 0x0c (FAT)
- 0x05 (an old type of extended partition)
- 0x07 (NTFS)
- 0x0f (a new type of extended partition)
- 0x82 (Linux swap)
- 0x83 (Linux filesystem)

Although the MBR data structure survived for three decades, its days are numbered because it's not extensible beyond 2TiB. A new system is needed.

# GPT Partitions

GPT is part of Intel's EFI specification, but GPT can be used on computers that don't use EFI, and it is the preferred partitioning system for disks larger than 2TiB. Most EFI computers use GPT on smaller disks than 2TiB.

GPT employs a protective GPT, which is a MBR definition that makes GPTunaware units think the disk spans the entire disk. Additional data structures define the true GPT partitions. These data structures are duplicated, with one at the start of the disk and another at its end. This provides redundancy which can help in data recovery should an accident damage one of the two sets of data structures.

GPT goes away by default (and that limit may be raised, if necessary) MBR distinction. You can define up to 128 partitions, but gaps occur in partition numbering, so you can have a disk with partitions numbered 3, 7, and 104, to name just possibility. In practice, GPT partitions are usually numbered consecutively with 1.

GPT's main drawback is that support for it is relatively immature. The fdisk utility (described shortly in “Partitioning a Disk”) doesn't work with GPT disks, although alternatives to fdisk are available. Some versions of the GRUB boot loader also don't support it. The situation is worse in OSparticularly older ones. Nonetheless, you should be at least familiar with GPT because of MBR's inability to handle disks larger than 2TiB.
