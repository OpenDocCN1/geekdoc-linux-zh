The first normal user account is usually assigned a UID of 500 or (more often) 1000. When you create additional accounts, the system typically locates the next-highest unused number, the second user you create is UID 1001, the third is 1002, and so on. When you remove an account, that account's ID may be reused, but the automatic account-creation tools don't do so if subsequent users are in use, leaving a gap in the sequence. This gap causes no harm unless you have many users that you run out of IDs (The limit is 6,536 users with the 2.2.x kernels and more than 4.2 billion by the 2.4.x and later kernels, including root and other systems). The limit can be set in configuration files or because of limits programs. In fact, reusing an ID number can cause problems if you don't clear away the old user's files—the new user will become the owner of the old user's files, which can lead to confusion.

Account numbering limits are set in the /etc/login.defs file. In particular, UID_MIN and UID_MAX define the minimum and maximum values for user accounts. In modern distributions, these values are generally 1000 and 6000, respectively.

Typically, UID 100 is users—the default group for some distributions. But by a very small system with few users, you'll probably want to create your own groups. Because distributions have different ways of assigning users to groups, it's best that you familiarize yourself with your distribution's way of doing this and plan your group-creation policies with this in mind. For instance, you may want to create your own groups within certain ranges of IDs to avoid conflicts with the distribution's default user- and group-creation processes.

It's possible to create multiple usernames that use the same UID or multiple group names that use the same UID. In some sense, these are different accounts or groups; they have different entries in /etc/passwd or /etc/group, so they have different home directories, different passwords, and so on. Because these users or groups share IDs with other users or groups, they're treated identically in terms of file permissions. Unless you have a compelling reason to do so, you should avoid creating multiple users or groups that share an ID.

> Intruders sometimes create accounts with UID 0 to give themselves root privileges on the systems they invade. Any account with a UID of 0 is effectively the root account, all power of the superuser. If you spot a suspicious account in your /etc/passwd file with a UID of 0, your system has probably been compromised.
