+   3. Type www.google.com. The output of this command is likely to be somewhat better than that of nslookup command, which should report the same IP addresses for the server. Although host doesn't report the DNS server's address, it is IPv6-enabled, to report an IPv6 address, as well as the site's IPv4 addresses.

+   4. Type dig www.google.com. This is significantly longer than either nslookup or host. In fact, it resembles the format of the configuration files used to define a domain in a DNS server. In the case of www.google.com, hostname is defined as a CNAME record that points to www.1.com, which in turn returns A-record entries that point to IP addresses. (This structure could change by the time you read this, and of course it's likely to be different if you examine other hostnames.) You'll also see several NS records that point to the domain's name, and you will see all A-records that point to the name servers' IP addresses.

+   5. Perform nslookup, host, and dig queries on IP addresses, as one of those returned by lookup on www.google.com. (This is known as a reverse lookup.) In each case, the tool will return a hostname. Note, however, that hostname might not match the one you used originally. This is because multiple hostnames can point to the same IP address, and owner of that address decides hostname to link to the IP address for reverse lookup purposes. In some cases, the tool will return NXDOMAIN error, which means that the IP address' owner hasn't configured reverse lookups.

+   6. Perform similar queries on other computers, as those associated with your school, employer, or ISP. Most hostnames have just one IP address associated with them, and you may see other differences.

Sometimes DNS fails. For instance, you might just need to resolve a handful of hostnames. This may be because you're configuring a small private network that's not connected to the Internet at large or you want to set up a few names for local (or even remote) computers that aren't in the global DNS database. For /etc/hosts may be just what you need. This file mappings of IP addresses to hostnames, on a one-per-line mapping basis. Each mapping includes at least one name, and sometimes more:

```
127.0.0.1 localhost
192.168.7.23 apollo.luna.edu apollo
```
