
# 506 Chapter 10 Securing Your System

You should consider whether you really need a remote text-mode login server. Such a server can be a great convenience—often enough to justify the modest risk involved. For extremely high-security systems, though, using the computer exclusively from the console may be an appropriate approach to security.

One unusual security use with SSH is its keys. As noted, the private-key files are extremely sensitive and should be protected from prying eyes. Remember to protect the backups of these files, as well—don't leave a system tape lying around where it can be easily stolen.

# Using GPG

SSH is designed to encrypt interactive login sessions and file transfers. Sometimes, though, another type of encryption is desirable: You may want to encrypt messages or files sent to another person via other means. Email was never designed as a secure data transfer tool, and most email messages pass through several email servers and network routers. A compromise at any one of these enables a cracker to sniff traffic and extract sensitive data, such as credit card or Social Security numbers. Encrypting your email keeps details private.

The usual tool for encrypting is the Gnu Privacy Guard (GPG or GnuPG, http://www.gnupg.org/) package. This package is an open source re-implementation of the proprietary Pretty Good Privacy (PGP). In addition to encrypting messages, GPG enables you to digitally “sign” messages. Used in this way, messages can be read by recipients who lack the GPG software or appropriate keys; but those who have these tools can verify that the contents haven't been tampered with.

# Generating Keys

To begin GPG, you should first install the software. Chances are, your distribution includes it as a standard package, so you can install it that way. Once this is done, you must generate keys. GPG keys are conceptually similar to SSH keys: You need a private key (a secret key) and a public key. As the names imply, the private key is kept private, the public key is publicly available. You can sign your messages with your private key, and readers can verify it with your public key; or you can encrypt a message with another user's public key, and it can be decrypted by that user's private key.

To generate keys, you use the gpg program with its --gen-key option:

```bash
$ gpg --gen-key
```

The program will ask you a series of questions. In most cases, the defaults should work well, although you may have to type in your full name and email address. The keys are stored in a keyring (a file that holds keys) in the ~/.gnupg directory. Once you've generated your keys, you can export your public key:

# Using GPG 507

```bash
$ gpg --export name > gpg.pub
```

This command saves the public key associated with name in the file gpg.pub. You can use your email address as name. (If you create additional public keys or add others' public keys to your keyring, you can specify their names to export those.) You can then make your public key available to others so that they may encrypt email messages sent to you or verify your signed messages. Adding the --armor option produces ASCII output, which may be preferable if you intend to send the key. You can make the file accessible on your Web site, transfer it as an email attachment, or distribute it in various ways.

One important method of distributing your public key is using a keyserver. This is a network server that functions like a keyring. To send your public key to a keyserver, you can use the --keyserver hostname and --send-keys keyname options to gpg, as follows:

```bash
$ gpg --keyserver ppg.mit.edu --send-keys jennie@luna.edu
```

This example sends the public key for jennie@luna.edu from your public keyring to the server at ppg.mit.edu. Anybody, who wants to retrieve the key from that server. (ppg.mit.edu is a popular site for hosting GPG public keys.)

# Importing Keys

To encrypt email send to others, you must obtain their public keys. Ask your correspondents to obtain them. Once you do so, you can add their keys to your keyring (that is, the set of keys GPG maintains):

```bash
$ gpg --import filename
```

This command adds filename to your set of public keys belonging to other people.

![](img/35f616c7eba4e79e12bfd762129c5d27_561_0.png)

Although public keys are, by definition, public, there are security concerns relating to them. Specifically, you should use a legitimate public key. Hypothetically, a miscreant could distribute a fake public key in order to obtain sensitive communications or fake a signed email. For instance, George might distribute a fake GPG public key that claimed to be from Harold. George could either sign messages or intercept email sent to Harold that was encrypted using the fake key. Thus, you should use as secure a communication method as possible to distribute your public key and receive public keys from others.

Once you've created your own key, and perhaps, imported keys from others, you can see what keys are available using the --list-keys option to gpg:
