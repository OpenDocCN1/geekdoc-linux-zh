# Chapter 8 • Configuring Basic Networking

# EXERCISE 8.2 (continued)

To study and modify your system's network configuration, follow these steps:

+   1. Log into the Linux system as a normal user.

+   2. Launch an xterm from the desktop environment's menu system, if you used a GUI login method.

+   3. Acquire root privileges. You can do this by typing su in an xterm or using sudo (if it's configured) to run commands in the following steps.

+   4. Type ifconfig displays information about your local network settings for all your network interfaces. Most systems have both a loopback interface (lo) and an Ethernet interface (eth0). Look for a line in the Ethernet section that contains the string addr=: The following 4-byte number is your IP address. Write it down, as well as your netmask (Mask): Study the other information in that output, too, as the number of received (RX) TX packets, the number of errors, the number of collisions, and the Ethernet adapter's hardware address.

+   5. Type -n. The output is your system's routing table information. This normally includes information about the loopback network address (127.0.0.1/24), the local network address, and a default route (as the route for 0.0.0.0). Some systems may display either or additional lines, depending on local configuration. The default route includes an IP address under the Gateway column. Write down that data.

+   6. Use ping to test connectivity to local and remote computers. (This command is described in more detail in "Testing Basic Connectivity.") You need the name or IP address of at least one local computer and at least one distant computer (by your local router). Type ping address, where address is the name or IP address of each test machine. Perform this for localhost or 127.0.0.1, your own machine (the IP address you noted in step 4), your local router (the IP address you noted in step 5), and a distant computer (if you connected to the Internet, you can use an Internet-accessible site, such as www.org). All of these pings should be successful. However, that some computers are configured to ignore packets by ping. Some of these tests may fail if you are not using Linux. You can learn the configuration of local computers from your administrators, or for Internet sites, you may simply try another site if the first one you tests fails.

+   7. Bring down the local Ethernet connection by typing ifconfig eth0 down.

+   8. Repeat steps 4-6. Note that the eth0 interface is no longer shown when you type ifconfig, all routes associated with it have been removed from the routing table, and pinging systems from the interface no longer works (Linux retains some information about its Ethernet Link, so you may still be able to ping the computer itself via its eth addr.).

+   9. Bring the local connection back up by typing ifconfig eth0 up address mask, where address is the original IP address and mask is the original netmask, as identified in step 4.
