The set keyword precedes the root keyword, and an equal sign (=) separates root from the partition specification.

The rootroverify keyword has been eliminated; you use root insert.

Partitions are numbered starting from 1 rather than 0. A similar change in disk numbering is not implemented. GRUB 2 makes further changes, in that it employs a set of scripts and other tools that help automatically maintain the /boot/grub.cfg file. The intent is that system administrators never need to edit this file. Instead, you would edit files in /etc/default/grub, to change your GRUB 2 configuration. After making such changes, you must rebuild the grub.cfg file, as described shortly.

Files in /etc/grub.d control GRUB OS probers. These scripts scan the system for particular OSs and add GRUB entries to /boot/grub.cfg to support those OSs. You can add custom kernel entries, such as shown in Listing 5.2, to the 40_custom file to support your own locally compiled kernels or unusual OS that GRUB doesn't automatically detect.

The /etc/default/grub file controls the defaults created by the GRUB 2 configuration. For instance, if you want to adjust the timeout, you might change the following line:

```
GRUB_TIMEOUT=10
```

A distribution that's designed to use GRUB 2, such as Ubuntu, will automatically run the configuration scripts after certain actions, such as installing a new kernel with the distribution's package manager. If you need to make changes, you can type update-grub or grub-mkconfig > /boot/grub/grub.cfg after editing /etc/default/grub or files in /etc/grub.d. This command re-reads these configuration files and writes a fresh file to /boot/grub/grub.cfg (Some installations use use 2 in command names, as in grub-2-mkconfig).

Unlike GRUB Legacy, GRUB 2 is designed to work with both BIOS and EFI-based computers, as well as with a few more-exotic firmware types. When you first install Linux, the installer should set up GRUB correctly, using grub-install in the way described for GRUB Legacy. On EFI-based computers, GRUB 2's grub-install should install the EFI binary file where it belongs; but if you have problems, you may need to use efibootmgr, as discussed earlier with reference to GRUB Legacy.
