# Configuring Logins Without Passwords

If you use SSH in automated tools, you won't become annoyed by the need to type a password with every connection. There is a way around this: you can set up the SSH client with keys and give the client's public key to the server. With this configuration, the SSH client can identify itself, possibly obviating the need for you to type a password. To operate without the use of passwords is convenient, but it increases security risks. If someone gets access to your account on the SSH client, that person will be able to log into your system without your password. Thus, you should create a password-less login only from a client that's well-protected.

To configure SSH not to require a password, follow these steps:

- Log into the SSH client as the user using a version 2 key:
- Type the following command to generate a version 2 key: `ssh-keygen -q rsa -f ~/.ssh/id_rsa -C -N ""`
- Generate two files: id_rsa and id_rsa.pub. Transfer each of these files to the SSH server in any way that's convenient—via a USB drive, using scp, or by any other means. Copy the file under a temporary name, temp.rsa.
- Log into the SSH server. If you use SSH, you'll need to type your password.
- Add the contents of the file you've just transferred to the end of ~/.ssh/authorized_keys. (This file is sometimes called authorized_keys, so you should check which is present. If neither is present, you may need to experiment) Typing `cat temp.rsa >> ~/.ssh/authorized_keys` should do this job if you stored the original file as temp.rsa.
- On some systems, you may need to modify permissions on the ~/.ssh/authorized_keys file and on the directories leading to it. The authorized_keys file may require 060 permissions, and you may need to remove write permissions for any but the account's owner on your home directory and ~/.ssh directory.

If you now log out of the SSH server and try to log in again, SSH authentic automatically. If this doesn't work, chances are the ~/.ssh/authorized_keys file needs another name, as described earlier. You may also want to check that the file includes a line matching the contents of the original public key on the client. Some older clients may require you to specify that you use version 2 of the SSH protocol by using the -2 option:

```bash
$ ssh -2 server
```

# Using ssh-agent

Another SSH authentication option is to use the ssh-agent program. This program requires a password to initiate connections, so it's more secure than configuring logins without passwords; however, ssh-agent remembers your password, so you need to type it once per local session. To use ssh-agent, follow these steps:

1. Follow the procedure for enabling no-password logins described in "Configuring Logins Without Passwords," but with one change: omit the -N option from the ssh-keygen command in step 2. You will be asked for a passphrase at this step. The passphrase will be your key for all SSH logins managed by ssh-agent.
2. On the client system, type `ssh-agent /bin/bash`. This launches ssh-agent, which in turn launches bash. You will use this bash for subsequent SSH logins.
3. In your system, type `ssh-add ~/.ssh/id_rsa`. This adds your RSA key to the agent managed by ssh-agent. You will be asked to type your SSH passphrase at this time.

From this point, whenever you use SSH to connect to a remote system to which you have given your public key, you won't need to type a password. You will, however, repeat steps 2 and 3 when you log out, and the benefits will accrue only to the shell running step 2 or any shells you launch from that.

If you have used this facility, you can insert ssh-agent into your normal login procedure. For instance, you can edit /etc/passwd so that `ssh-agent /bin/bash` is your login shell. For a GUI login, you can rename your normal GUI login script (for instance, change ~/.session to ~/.session-nossh) and create a new GUI login script that calls ssh-agent with the renamed script as its parameter. Either action inserts ssh-agent at the root of your user process tree so that any call to SSH uses ssh-agent.
