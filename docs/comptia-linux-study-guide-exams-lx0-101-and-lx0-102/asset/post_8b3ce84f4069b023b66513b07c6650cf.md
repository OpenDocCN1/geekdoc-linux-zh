
The word formatting is somewhat ambiguous. It can refer to low-level formatting, which creates a structure of sectors and tracks on the disk media, or high-level formatting, which creates a filesystem. Hard disks are low-level formatted at the factory and should never need to be low-level formatted again. Floppy disks, though, can be both low- and high-level formatted. The tools described here can high-format a floppy disk as well as a hard disk. To low-format a floppy disk, you must use the fdcommand, as in `fdformat /dev/fd0`. This command cannot be used on a hard disk.

## Common Filesystem Types

Linux supports quite a few different filesystems, both Linux-native and intended for other OSs. Some of the latter work under Linux, and even when they do not support all the features that Linux expects in its native filesystems. When preparing a Linux system, you will use one or many of native filesystems for most or all partitions:

**Ext2 The Second Extended File System (ext2fs or ext2)** is the traditional Linux-native filesystem. It was created for Linux and was the dominant filesystem throughout the late 1990s. Ext2fs has a reputation as a reliable filesystem. It has since been eclipsed by other filesystems, but it still has its uses. In particular, ext2 can be a good choice for the /boot partition, if you choose to use one, and for small (sub-gigabyte) removable disks. On small partitions, the size of ext2 can be a real problem. The non-journaling ext2 is described in more detail shortly. The ext2 filesystem type is ext2.

**Ext3 The Third Extended File System (ext3fs or ext3)** is basically a filesystem that is as reliable as ext2 but recovers from power outages and system crashes more quickly. The ext3 filesystem type is ext3.

**Ext4 The Fourth Extended File System (ext4fs or ext4)** is the next-generation version of this filesystem. It adds the ability to work with very large disks (over 1TB) and very large files (over GB), as well as extensions to improve performance. Its filesystem type is ext4.

**ReiserFS** This filesystem was designed from scratch as a journaling filesystem for Linux. It is particularly good at handling large numbers of small files (say, smaller than 32KB). Because ReiserFS uses various tricks to squeeze the ends of files into unused space, these savings can add up to a large percentage of file sizes when files are small. You can use reiserfs as the type for this filesystem.

## Creating Partitions and Filesystems

As of Linux kernel 3.6, ReiserFS is current. A from-scratch rewrite known as Reiser4 is under development, although development has slowed to the point that it is uncertain if Reiser4 will ever be included in the mainline kernel.

JFS IBM developed the Journaled File System JFS for its AIX OS and OS/2 version was subsequently donated to Linux. JFS is a technically sophisticated journaling filesystem that may be of interest if you're familiar with AIX or want an advanced filesystem to use on a dual-boot system. As you might expect, this filesystem's type is jfs.

XFS Silicon Graphics (SGI) created its Extents File System XFS for its IRIX OS and, like IBM, later donated to Linux. Like JFS, XFS is a very technically sophisticated filesystem. XFS has gained a reputation for robustness, speed, and flexibility on IRIX, but some of the features that make it possible on IRIX aren't supported under Linux. Use xfs as the type for this filesystem.

Btrfs This filesystem (pronounced "butter fs" or "bee tree fs") is an advanced filesystem with features inspired by Sun's ZFS (Z File System). Like ext4, Btrfs is a fast performer and is able to handle very large disks and files. As of the 3.6.0 kernel, Btrfs is considered experimental; however, its advanced features make it a likely successor to the popular filesystems.

In practice, most administrators create ext3, ext4, or ReiserFS as their primary filesystems; JFS and XFS work well, and some administrators prefer them, particularly on large disks. Ext4 also handles large files. Hard data on the merits and problems with each filesystem are difficult to come by, and even when they exist, they suspect filesystem performance interacts with many other factors. For instance, as noted, ReiserFS can cram more small files into a small space than other filesystems, but this advantage isn't very important if you're storing mostly larger files.

If you're using an x86 or non-x86-64 platform, be sure to check filesystem development on that platform. A filesystem may be speedy and reliable on one CPU but sluggish and unreliable on another.

In addition to these Linux-native filesystems, you may need to deal with others from time to time, including the following:

FAT The File Allocation Table (FAT) filesystem is old and primitive—but ubiquitous. It's the only hard disk format supported by DOS and Windows 9x/Me. For this reason, every major OS understands FAT, making it an excellent filesystem for exchanging data on removable disks. Two orthogonal variants of FAT exist: it varies in size (12-, 16-, or 32-bit pointers), and has variants that support long filenames. Linux automatically detects the FAT size, so you shouldn't need to worry about this. To use the original FAT filenames limited to eight characters with an optional three-character extension (the so-called 8.3 filenames), use the Linux filesystem type of mddos. To use Windows-style long filenames, use the filesystem type of vfat. A Linux-only long filename system, known as umdos, provides additional Linux features—enough that you can install Linux on a FAT partition, although this practice isn't recommended except for types of emergencies or to try Linux on a Windows system.

NTFS The New Technology File System (NTFS) is the preferred filesystem for Windows NT/2000/XP/Vista/7. Unfortunately, Linux's support is rather rudimentary. As of the 2.6.x kernel series, Linux can reliably read NTFS and can overwrite existing files, but the Linux kernel can't write files to an NTFS partition.

HFS and HFS+ Apple has long used the Hierarchical File System (HFS) with its Mac OS, and Linux provides read/write support. This isn't as reliable as FAT support, so you may want to use FAT when exchanging files with Mac users. Apple has extended HFS to support large disks with its HFS+.

ISO-9660 The standard filesystem for CD-ROMs has long been ISO-9660. This filesystem comes in several levels. Level 1 is similar to the original FAT in that it supports only 8.3 filenames. Level 2 and 3 add support for longer-character filenames. Linux uses ISO-9660 with its iso9660 filesystem type. Linux's ISO-9660 also works with the Rock Ridge extensions, which are a series of extensions to ISO-9660 to enable it to support Unix-style long filenames, permissions, symbolic links, and so on. Similarly, Joliet provides support for long filenames as implemented in Windows. If a disk includes Rock Ridge or Joliet, Linux will automatically detect and use them.

UDF The Universal Disk Format (UDF) is the next-generation filesystem for optical discs. It's commonly used on DVD-ROMs and recordable optical discs. Linux supports it, but read/write UDF support is still in its early stages.
