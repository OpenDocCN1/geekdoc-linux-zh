```
echo "/tmp/tempstuff found; aborting!"
exit
```

This causes the script to exit if the file /tmp/tempstuff is present and larger than 0 Bytes. The then keyword marks the beginning of a series of lines that execute only if the conditional is true, and fi (if backward) marks the end of the if block. This code may be useful if the script creates and then deletes this file, because its presence indicates that a previous run of the script did not succeed or is still underway.

An alternative for a conditional expression uses the test keyword rather than square brackets around the conditional:

```
if test -s /tmp/tempstuff
```

You can also test a command's return value by using the command as the condition:

```
if [ command ]
then
    additional-commands
fi
```

In this example, the additional-commands will be run only if command completes successfully. If command returns an error code, the additional-commands won't be run. Conditional expressions may be expanded by use of the else clause:

```
if [ conditional-expression ]
then
    commands
else
    other-commands
```

Code of this form causes either commands or other-commands to execute, depending on the evaluation of conditional-expression. This is useful if something should happen in a part of the program but precisely what happens depends on some condition. For instance, you may launch one of two different file archiving programs depending on a user's input.

What do you do if two outcomes are possible—for instance, if a user may provide any of four possible inputs? You can nest if/then/else clauses, but this gets away very quickly. A cleaner approach is to use case:

```
case word in
    pattern1) command(s) ;;
    pattern2) command(s) ;;
...
esac
```
