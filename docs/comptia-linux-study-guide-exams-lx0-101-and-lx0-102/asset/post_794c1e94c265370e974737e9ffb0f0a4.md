Sometimes you want to process a file in some way prior to sending it to the printer. Chapter 1 covers some commands that can do this, as fmt. Another program is mpage, which reads plain-text or PostScript files and reformats them so that each printed sheet contains reduced pages from the original document. This can be a good way to save paper if you don't mind a reduction in the document's image size. In the simplest case, you can use mpage much as you use lpr:

```
$ mpage -Plexmark report.ps
```

This command prints report.ps reduced to fit four pages per sheet. You can change the number of pages to fit on each page with -1, -2, -4, and -8, which specify one, two, four, eight pages per output, respectively. Additional mpage options exist to control features such as the page size, the font used for plain-text input files, and the range of input pages to be printed. Consult the man page for mpage for more details.

### Displaying Print Queue with lpq

The lpq utility displays information about the print queue—how many files it contains, how large they are, who their owners are, and so on. By entering the user's name as an argument, you can use this command to check on prints owned by a particular user. To use lpq to examine a queue, you can issue a command like the following:

```
$ lpq -Ph4000
hp4000 is ready and printing
```

| Rank | Owner(s) | Total Size |
| --- | --- | --- |
| active |midt | 90112 bytes |

Of particular interest is the job number—1630 in this example. You can use this number to delete a job from the queue or redirect so that it prints before others. Any user may use the lpq command.

### Removing Print Jobs with rm

The rm command removes one or more jobs from the print queue. You can use this a couple of ways:

- If rm is used with a number, the number is understood to be the job ID (as shown in lpq's output) of the job to be deleted.
- If a user runs the BSD or CUPS rm, it passes a dash -- to the program, it removes all jobs belonging to the user.

This program may be run by root or by an ordinary user; just noted, ordinary users may only remove their own jobs from the queue, but root may remove anybody's jobs.

### Controlling the Print Queue

In the original LPD system, the lpc utility starts, stops, and reorders jobs within print queues. Although CUPS provides an lpc command, it differs. Instead, the CUPS web interface provides point-and-click print queue management:

- You can disable a queue by clicking the Stop Printer link for the printer on the CUPS Web interface. When you do so, this link changes to Start Printer, which reverses the effect when clicked. The Job links also provide a way to cancel and otherwise manage specific jobs.
- You can use a series of commands, such as cupsenable, cupsdisable, and cupsmove, to control the queue. These commands enable to disable queue, delete a queue, or move a job from one queue to another. Moving a job can be handy if you must shut down a queue for maintenance and want to redirect the queue's existing jobs to another printer.

## Summary

X is Linux's GUI system. Because of Linux's modular nature, X isn't a single program. Fortunately, most Linux distributions use X.org-X11 and its main competitor, Free86, are configured in the same way, using xorg.conf (for X.org-X11) or Free86conf. Whatever its name, this file consists of sections, each of which controls subsystem, such as the mouse, the keyboard, or the video card. This file also controls X's fonts, but most programs are now emphasizing a new font system, Xft, instead of X fonts. For this reason, Linux configuration can be complex.

X's GUI login system uses XDMCP, which starts and manages the X system. Default X servers are common in Linux, the most important being KDM, XDM, and GDM. They all perform the same tasks, but configuration differs. X is also less sophisticated than KDM and GDM. X is a network-enabled GUI, which means you can use an X server to access programs running on another. Doing so requires a few steps for each log session. You can also tunnel X through SSH, which greatly improves the security of the connection.
