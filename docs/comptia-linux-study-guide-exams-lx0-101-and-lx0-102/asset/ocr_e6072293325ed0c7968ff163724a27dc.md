As with any filesystems you want to mount, you must provide mount points—that is, create empty directories—for user-mountable media. Removable media are usually mounted in subdirectories of /mnt or /media.

Many distributions include auto-mount facilities that automatically remove media when they are inserted. These tools typically create mount points in /media and create icons on users' desktops to enable easy access to the media. This configuration produces effects that are familiar to users of Windows and Mac OS.

The credentials option for the /win mount point in Listing 3.1 deserves greater elaboration. Ordinarily, most SMB/CIFS shares require a username and password as a measure of access control. Although you can use the username and password-pass options these options are undesirable, particularly in /etc/fstab because they leave the password vulnerable to discovery—anyone who can read /etc/fstab can read the password. The credentials=file option provides an alternative—you can use it to point Linux to a file that holds your username password. This file has labeled lines:

```
username=schmidt
password=yiT9Td
```

Of course, the file you specify (/etc/creds in Listing 3.1) must be well protected—it be readable only to root and perhaps to the user whose share it describes.

# Summary

Most Linux tools and procedures provide a layer around the hardware, insulating you from a need to know many details. Nonetheless, you have to dig in and configure hardware directly. Firmware switches can control onboard devices such as hard disk and USB ports. Wide and SCSI devices have their own quirks, and USB in particular is quickly evolving.

Hard disks are one class of hardware that are likely to require more attention than most. Specifically, you must know how to create partitions and prepare filesystems on those partitions. These tasks are necessary when you install Linux (although most distributions provide GUI tools to help guide you through this task installation), when you add a hard disk, or when you reconfigure an existing system. You should also know something about boot managers. These programs help Linux up and running when you turn on a computer’s power, so they’re unusually critical to Linux operation.
