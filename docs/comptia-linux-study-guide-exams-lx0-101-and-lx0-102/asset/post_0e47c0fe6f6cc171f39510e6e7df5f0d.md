
# Managing the Shell Environment

## LD_LIBRARY_PATH

A few programs use this environment variable to indicate directories in library files may be found. It works much like PATH.

## PS1

This is the default prompt in bash. It generally includes variables of its own, such as \u (for the username), \h (for the hostname), and \W (for the working directory). This value is frequently set in /etc/profile, but it's often overridden by users.

## TERM

This variable is the name of the current terminal. To move the text-mode cursor and display text for programs like text-mode editors, Linux needs to know what commands the terminal supports. The TERM environment variable specifies the terminal in use. This information is combined with data from additional files to provide terminal-specific code information. TERM is normally set automatically, but in some cases you may need to change it.

## DISPLAY

This variable identifies the display used by X. It's :0, which means the first (numbered from 0) display on the computer. You may use X in a networked environment, though this value may be preceded by the name of the computer at which you're sitting, as in machine1.luna.edu:0. This value is set automatically when you log in, but you may change it if necessary. You can run multiple sessions on one computer, in which case each one gets a DISPLAY number—for instance, :0 for the first session and :1 for the second.

## EDITOR

Some programs point to this environment variable when they need to call a text editor for you to use. Thus, changing your variable to your favorite editor can help you work in Linux. It's best to set this to a text-mode editor, though; GUI editors may cause problems if they're called from a program that was launched from a text-mode login.

> The PATH variable sometimes includes the current directory indicator (.) so that you can easily run programs in the current directory. This practice poses a security risk, though a miscreant can create a program with the same name as another program (such as ls) and trick another user into running it in a directory the victim frequents. Even the root user may be victimized by this. For this reason, it's best to omit the current directory from the PATH variable, especially for the superuser. If it's really needed for ordinary users, put it at the end of the path.

Any given system is likely to have other environment variables, which are fairly esoteric or relate to specific programs. If a program's documentation says that it needs certain environment variables, you can set them system-wide in /etc/profile or some other suitable file, or you can set them in user configuration files, as you deem appropriate.

Although you can see the entire environment by typing env, this output can be long enough to be intimidating. If you just want to know the value of one variable, you can use the echo command, which echoes to the screen what you type. If you pass a variable name preceded by a dollar sign ($), echo returns the value of the variable. Here's an example:

```bash
$ PS1
\u@\h \W\$
```

This command reveals the PS1 environment variable is set to '\u@\h \W$', which in turn produces a prompt like [david@penguin homes]. Exercise 9.1 illustrates how you can change your prompt.

## EXERCISE 9.1

### Changing your bash Prompt

This exercise describes how to change your bash prompt to show the current time and number of jobs managed by the shell. To accomplish this task, follow these steps:

- 1. Log into the Linux system as a normal user.
- 2. Launch an xterm from the desktop environment's menu, if you use a GUI login method.
- 3. Type `export PS1="\T; \j jobs"`. The backslash (\ is an escape character that denotes special data to be inserted into the prompt when used in the PS1 variable. \T is expanded into the current time in 12-hour format, and \j is expanded into the number of jobs the shell manages. The man page for bash has a complete list of expansions the PS1 variable accepts. The result of typing this command should be an immediate change in your prompt to resemble something 04:42; 0 jobs;
- 4. Wait for a minute, and run a program in the background by typing its name and appending an ampersand (&). For instance, you can type `keys &` to run the keys from xterm. You will see the number of jobs increase, and the time will change.
- 5. To make this change permanent, edit the .bashrc file in your home directory. Load this file into your favorite editor, and add a line to it that `exports PS1="\T: \j jobs"`. Save the file, and exit the editor. Shell configuration files are described in more detail shortly, in "Modifying Shell Configuration Files."
- 6. To test your change to .bashrc, log out and log back in again. Instead of your default prompt, you should see the new one.
- 7. If you don't like the prompt, edit .bashrc again and delete the line you added in step 5.

## Using Aliases

Most Linux shells, including bash, support command aliases, which are new names you can give to regular commands. Typically, you'll use aliases to assign easier-to-remember names to obscure commands, to implement desirable commands as default for commands, or to create a shortened version of a command to minimize the amount of typing you do. You can define aliases in a one-off fashion at bash prompt, but they're typically included in your bash startup scripts, as described shortly in “Modifying Shell Configuration Files."

To implement an alias, you use the following syntax:

```bash
alias alias_name='commands'
```

The alias_name is what you want to type at the command prompt, and the shell substitutes commands for whatever you type. For example, the ls command, which lists the contents of a directory. A popular option for this command is --color, which color-codes the output, etc. If you want to use this option as the default, you can use alias:

```bash
$ alias ls='ls--color'
```

In this example, ls becomes an alias for an extended version of itself. This doesn't result in recursion—that the ls to the right of the equal sign is not expanded. After you type this alias command, typing ls will work as if you'd typed ls --color. In fact, particular aliases are popular enough that they're included as a standard part of many distributions' bash scripts.

You can use an alias name that's unrelated to the original command name. For instance, suppose you want to logout. You can do so with alias:

```bash
alias bye='logout'
```

## Modifying Shell Configuration Files

Configuring shells requires editing configuration files. These files can be classified in a couple of ways. First, files may be global that affect all users or local that affect just one user. Second, files may be login files that are launched by login (such as console) or non-login files that are launched by other processes (such as xterm). Precisely which of these files are used differs from one distribution to another.

### TABLE 9.2 Common configuration files

| Type of file | Login file location | Non-login file location |
| :--- | :--- | :--- |
| Global | /etc/profile and files in /etc/profile.d | /etc/bashrc |
| User | ~/.bash_login, ~/.profile, or ~/.bash_profile | ~/.bashrc |

Global configuration affects all users of a system; however, their settings may be overridden by individual users, either in configuration files or commands the user. Thus, you shouldn't rely on global configuration to set options that shouldn't be changed by users. For that, you should look to global security features, such as permissions on executable files.

The /etc/skel directory holds files that are copied to individual users' home directories when their accounts are created. These files are sometimes skeleton files. Typically, this set of files includes local configuration files. You can examine these files and, if necessary, alter them to suit your local needs. These changes affect new users, not existing accounts. If you want to make a change that affects existing and new users, you should edit a global configuration instead.

Just as shells have startup scripts, they may also have logout scripts—scripts that run when the user logs out. For bash, this script is ~/.bash_logout. Most distributions create this script as part of users' home directories, but individuals can do so. The logout script may execute programs to clean up temporary directories, remove security keys from memory, clear the screen or perform tasks that are appropriate when a user logs out.

One problem with logout scripts is that they may not work well when users log in multiple times. If you regularly have multiple sessions open, such as logins in multiple terminals, be careful about what you do in a logout script lest you wipe out temporary files when you log out of just one session.

