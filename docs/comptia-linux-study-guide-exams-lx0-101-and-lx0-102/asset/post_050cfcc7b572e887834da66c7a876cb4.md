
# Appendix A - Answers to Review Questions

11. B. Yum uses files in the /etc/yum.reposd directory to locate its repositories, so you can add to the repository list by adding to this subdirectory, option B specifies, typically by installing an RPM or by adding a file manually. Option A describes a method of adding a repository to a computer that uses APT. Option C's add-repository subcommand is fictitious. Although the /etc/yum.conf file described in options D and E is, it doesn't store repository data.

12. B. The /etc/ld.so.conf file holds the global path, so editing it is the preferred approach. You must then run ldconfig to have the system update its library path. Option B is correct. Although you can add a directory to the library path by altering the LD_LIBRARY_PATH environment variable, as in option A, this approach isn't the preferred one, so option B is correct. Option C won't work. Option D won't work, although linking individual library files would. This method isn't the preferred one for a whole directory. The ldd displays information on libraries by executable files, so option E won't have the desired effect.

13. D. Libraries are selected by programmers, not by users or system administrators. If you don't like the widgets provided by one library, you have few options, and option D is correct (Many widgets provide a great deal of configurability, so you may be able to work around the problem in other ways). Options A, B, and E describe fictitious options to ldconfig, rpm, dpkg, and the kernel. Option C won't work; Qt-using programs would crash when they found GTK libraries in place of the Qt libraries they were expecting.

14. D. The kill -9 command accepts values in numeric or named form 9 (in this example) along with process ID number (1128 in this example). Signal 9 corresponds to SIGKILL, which is an extreme way to kill processes that cannot run. Thus, option D describes the effect of this command. Although you might use kill -11 to kill network processes, you cannot do it so option A is incorrect. The program won't display information about the number of processes that have been killed, making option B correct. To do as C suggests, you'd need to tell kill -11 to SIGHUP (signal 1), so the command would be kill -11 -1 1128, and option C is incorrect. The kill -11 command can't change the property of a process, so option E is correct.

15. C. The top utility displays a dynamic list of processes ordered according to their CPU use along with additional system information, including load averages, so option C is correct. If you want only the average at a specific moment, uptime (option D) may be better because it presents extraneous information—it shows the current time, the time since the system was booted, the number of active users, and load averages. Option A's ld has nothing to do with displaying load averages (it's a programming tool that links process modules into an executable program). There are no standard Linux programs called load (option B) or Ia (option A).

16. A. The --forest option to ps shows parent-child relationships creating visual links between process names in the ps output, making option A correct (Listing 2.4 shows this effect.) Options B and C are both valid, but neither created the specified effect. Option D describes a fictitious ps option. Since options B, C, and D are incorrect, option E is also necessarily incorrect.

17. CPU-intensive programs routinely consume 90 percent or more of available CPU time, but not all systems run such programs. Furthermore, some types of program bugs can create CPU loads. Thus, option A is correct, and you must investigate the matter. What is dump? Is it designed as a CPU-intensive program? Is it consuming this CPU time consistently, or was this a brief burst of activity? Options B, C, D and E all jump to conclusions or present fictitious reasons for the behavior being normal or abnormal.

18. The jobs command summarizes processes that were launched from your current shell. When no processes are running, jobs returns nothing, so option E is correct. The jobs command doesn't check or summarize CPU load, so option A is incorrect. The jobs command also doesn't check for processes from shells other than the current one, so option B is incorrect (processes running under username could have been launched from another shell or from a GUI environment). There is no standard jobs in Linux, so option C is incorrect. Because the jobs output is limited to your processes in the shell you're running, a blank output does not indicate a crashed system, so option D is incorrect.

19. The nice command launches a program (in this example) with decreased priority. The default priority when nice is specified is 10, and nice also sets the priority to 10, options C and E are equal. Option A is not a valid nice because nice has no --value option. Option B is a valid nice because, it sets the priority to -10 rather than 10. Despite the similarity in form of options C and D, option D is not valid and is incorrect. To pass a numeric nice, you must use a preceding dash, or -n.

20. Linux limits users' actions from one another, and this rule applies to root; root may modify the priority of other users, so option D is correct. Similarly, root may only increase the priority of a process, in order to prevent users from setting priorities to maximum priority, stealing CPU time from others, so option E is correct. Option A correctly decreases priority, but not nice; the whole point of nice is to be able to change the priorities of others.
