
# Managing Disk Quotas

Just one user of a multi-user system can cause serious problems for others by consuming too much disk space. If a single user creates huge files (say, multimedia recordings), those files can use enough disk space to prevent others from creating their own files. To manage this situation, Linux supports disk quotas—limits, enforced by the OS, on how many files or how much disk space a single user may consume. The Linux quota system supports quotas for individual users and for Linux groups.

# Enabling Quota Support

Quotas require support in both the kernel for the filesystem being used and various user utilities. The ext2fs, ext3, ReiserFS, JFS, and XFS filesystems support quotas, but this support is missing for some filesystems in early 2.6.x kernels. Try using the latest kernel if you have preferred filesystem. You must explicitly enable support via the Quota Support option in the filesystem area when recompiling your kernel. Most distributions have this support enabled, recompiling your kernel may not be necessary, but you should be aware of this option if you recompile your kernel.

Two general quota support systems are available for Linux. The first was used through the 2.4 kernel and referred to as the quota v1 support. The second was added with the 2.6 kernel and is referred to the quota v2 system. This description applies to the latter system, but the former works in a similar way.

Outside of the kernel, you need support tools to use quotas. For the quota v2 system, this package is usually called quota, and it installs a number of utilities, configuration files, system startup scripts, and so on.

You can install the support software from source code, if you like; however, this job is handled most easily using a package for your distribution. This description assumes that you install the software in this way. If you don't, you may need to create startup scripts to initialize the quota when you boot your computer. The Quota Mini-HOWTO, at http://en.ldp.org/HOWTO/Quota.html, provides details of how to do this.

You may modify your /etc/fstab entries for any partitions on which you want to use quota support. In particular, you must add the usquota filesystem mount option to employ user quotas and the grquota option to employ group quotas. Entries that are so configured resemble following:

```
/dev/sdc5 /home ext3 usquota,grpquota 1 1
```

This line activates both user and group quota support for the /dev/sdc5 partition, which is mounted at /home. Of course, you can add other options if you like.

Depending on your distribution, you may need to configure the quota package's system startup scripts to run when the system boots. Chapter 5 describes script management detail. Typically, you'll type a command as chconfig quota on, but you should check on the SysV scripts installed by your distribution's quota package. Some distributions require the use of other commands as chconfig to do this, as described in Chapter 5. Whatever it does, this startup script runs the quota command, which activates quota.

After installing software and making configuration file changes, you must activate the systems. The simplest way to do this is to reboot the computer, and this step is necessary if you had to recompile your kernel to add quota support directly into the kernel. If you didn't do, you should be able to get by with less disruptive measures: using modprobe to install the kernel, or necessary; running the startup script for the quota tools; and remounting the filesystems on which you intend to use quotas by mounting -o remount /mount-point, where mount-point is your point in question.

# Setting Quotas for Users

At this point, quota support should be fully active on your computer, but the quotas themselves aren't set. You can set the quotas using edquota, which starts the Vi editor (described in Chapter I, "Exploring Linux Command-Line Tools") on a temporary configuration file (/etc/quotat) that controls the quota for you specify. When you use it, edquota uses the temporary configuration file to write the quota information to low-level data structures that control the kernel's quota mechanisms. For instance, you might type edquota salty to edit salty's quotas. The contents of the editor show your current quota information:

Disk quotas for user salty (uid 21810):
| Filesystem | blocks | soft | hard | inodes | soft | hard |
| /dev/sd4 | 97104 | 104856 | 104856 | 1242 | 0 | 0 |

The temporary configuration file provides information about both the disk blocks in use and the use of inodes. (Each file or multiple consumes an inode, so the inodes are effectively limits on the number of files a user may use). Disk blocks vary depending on the filesystem and filesystem options, but typically ranging from 512 bytes to 8KB. Changing the information (under the blocks and inodes) has no effect; these columns report how many blocks or inodes the user is actually consuming. You can alter the soft and hard limits for both blocks and inodes. The hard limit is the maximum number of inodes that the user may consume; the kernel won't permit a user to surpass these limits. Soft limits are somewhat less stringent; they issue warnings. Soft limits also interact with a grace period; if the soft quota limit is exceeded for longer than the grace period, the kernel begins treating it like a hard limit and refuses to allow the user to.

When using edquota, you can adjust independently for every filesystem for which quotas are enabled. To edit quotas for a group, use the -g option. A few more quota-related commands are available. The first is quotacheck, which verifies and updates quota information on quota-enabled disks. This command is normally run as part of the quota package startup script, but you may want to run it periodically (say, once a week) as a cron job (Chapter 7). Although theoretically not everything is necessary, quotacheck ensures quota accounting doesn't become inaccurate. The second auxiliary quota command is reportquota, which summarizes the quota information about the filesystem you specify or on all filesystems you pass in the -a option. This tool can be very helpful in keeping track of disk usage. The quota command has a similar effect. It takes a number of options to modify their outputs. For instance, -g displays group quotas, -1 limits NFS mounts, and -q outputs to filesystems on which usage is over the limit. Consult quota's man page for more obscure options.

# Locating Files

Maintaining your filesystems in perfect health, setting permissions, and so on is pointless if you can't find them. For this reason, Linux provides several tools to locate the files you need to use. The first of these tools is a standard for where files are located; with the right knowledge, you may be able to find files without any specialized programs. The second class of tools includes just specialized programs, which search a directory tree or a database for whatever meets your criteria.

Linux's placement of files is derived from more than 40 years of Unix history. Given that fact, the structure is remarkably stable and coherent, it's easy for a new administrator to become confused. Some directories exist, on the surface, to fulfill similar or identical roles, but in fact there are subtle but important differences.
