# Using GUI Configuration Tools

Most distributions include their GUI configuration tools for network interfaces. For instance, Fedora and Red Hat ship with a custom GUI tool called Network Configuration (system-config-network), and SUSE has a text-mode and GUI tool called YaST. The details of operating these programs differ, but the GUI configuration tool provides a means to enter the information much earlier.

Although the exam doesn't cover GUI network configuration tools, they are generally easier to use and learn the configuration files in which settings are set. Thus, you may want to look for your distribution's tool and learn to use it. Once you understand the principles of network configuration (IP addresses, DHCP, and so on), you shouldn't have trouble entering the information in the GUI fields.

The precise details of how configuring a Linux system using GUI tools differ from one distribution to another. For instance, SUSE's YaST doesn't lay out its options in precisely the same way as Fedora's Configuration tool. The basic principles are the same; you must choose whether to use static IP address assignment or an automatic system such as DHCP and enter a number of key options, depending on what configuration method you choose.

# Using the ifup and ifdown Commands

Most Linux distributions today use two commands, ifup and ifdown, that combine the functions of other network commands, most notably ifconfig and route. In their simplest forms, they bring interfaces up or shut down based on information in whatever files your distribution uses to store network configuration data:

+   # ifup eth0

Determining IP information for eth0... done.

After you issue this command, eth0 will be fully configured, including you've properly configured it using your distribution's network configuration tools or by manually editing configuration files as /etc/network/interfaces and /etc/sysconfig/network/ifcfg-name. You can bring the interface down equal by typing eth0.

The ifup and ifdown commands are useful for verifying that the network settings are configured for the next time the computer boots. They're also useful if you want to quickly down the network or bring it back again, because you can type fewer commands and you don't need to remember all the details of IP addresses, routes, and so on. If you need to experiment or debug a problem, though, using ifconfig and route individually is preferable, because they give finer control over the process.
