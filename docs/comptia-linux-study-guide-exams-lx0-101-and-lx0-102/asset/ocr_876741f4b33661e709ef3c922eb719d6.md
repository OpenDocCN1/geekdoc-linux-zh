You can restrict the output of lsof by including an address after the -i option. The address takes the following format:

+   - [46] [protocol]:[@hostname|hostaddr]:[:service|port]

The digit 4 or 6 represents an IPv4 or IPv6 connection, the protocol is the protocol type (TCP or UDP), the hostname or hostaddr is the connection hostname or IP address associated with the remote system, the service is a service name (from /etc/services), and the port is the port number. For instance, you may want to verify that no FTP server is running on a computer. You can search for connections associated with the FTP port:

```
# lsof -i :ftp
```

Alternatively, you can replace ftp with 21, because 21 is the port number associated with the FTP port. (Table 8.2 in Chapter 8 summarizes the common network port numbers). In this case, this command returns a list of all processes associated with FTP connections, both incoming and outgoing. If it returns no output; the system produces a new prompt. Be sure to note which output lines are linked as opposed to client processes. Even if you're not running an FTP server, the preceding command may produce dozens of lines of output if users on the computer are making FTP connections.

To perform a general audit of your system's connections, you should type lsof -i by itself, restricting the output. You'll probably want to pipe the output through less or use a terminal's scroll buffer to view the output. Piping the output through grep to search for the STRING LISTEN is a shortcut to find active servers:

```
# lsof -i | grep LISTEN
```

Paging through the output (without using grep to search for LISTEN) will provide you with a better idea of your system's overall network usage. You could conceivably spot something suspicious, such as an outgoing connection to a sensitive computer that the client isn't contacting. This network activity may activate active tracking by users of the client, an intrusion by another, or the work of an automated Trojan or horse program.

If you identify programs that are not running, such as unnecessary servers, you can use the command name, PID, and other information to help shut them down. The preceding section "Disabling Unused Servers" describes how to do this in more detail.

Another use of lsof is identifying who is accessing files. This might be handy if you need to mount a filesystem (including a network filesystem) but can't because of in-use files or if you suspect inappropriate activities involving file access.

# Using Network Scanners

Network scanners, as Nmap (http://www.insecure.org/nmap/) or Nessus (http://www.nessus.org), can scan for open ports on the local computer or other computers. The more sophisticated scanners, including Nessus, check for known vulnerabilities, so they can tell you whether a server is compromised should you decide to leave it running.
