# Correcting Problems

Library path problems usually manifest as a program's inability to locate a library. If you launch the program from a shell, you'll see an error message like this:

```
$ g
p: error while loading shared libraries: libXinerama.so.1: cannot
open shared object file: No such file or directory
```

This message indicates that the system couldn't find the libXinerama.so.1 library file. The usual cause of problems is that the library isn't installed, so you should look for it using commands as find (described in Chapter 4, “Managing Files”). If the file isn't installed, try to download the package to which it belongs (a Web search can work wonders in this task) and install.

If, on the other hand, the library file is available, you may need to add its directory globally or to LD_LIBRARY_PATH. Sometimes the library's path is hard-coded in the program's file. (You can discover this using ld, as described shortly in "Library Management Commands.") When this happens, you may need to create a symbolic link from the location of the library on your system to the program expects. A similar problem can occur when the program expects a library to have one name but the library has another name than your system. For instance, the program may link to libglib.so.5, but your system has libglib.so.2 installed. Minor version-number changes like these are usually inconvenient, so creating a symbolic link will correct the problem:

```
# ln -s libglib.so.2 libglib.so.5
```

You must type this command as root in the directory in which the library resides. You must then run ldconfig, as described in the next section.

# Library Management Commands

Linux provides a pair of commands that you're likely to use for library management. The ldd command displays a program's shared library dependencies—that is, shared libraries that a program uses. The ldconfig program updates caches and links used by the system for locating libraries—that is, it reads /etc/ld.so.conf and implements any changes in that file or in the directories to which it refers. Both of these tools are invaluable in managing libraries.
