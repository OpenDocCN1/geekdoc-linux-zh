Yum is configured via the /etc/yum.conf file, with additional configuration files in the /etc/yum.repos.d/. The yum.conf file holds basic options, such as the directory which Yum downloads RPMs and where Yum logs its activities. Chances are that you won't need to modify this file. The /etc/yum.repos.d/, on the other hand, potentially holds several files, each of describes a Yum repository—that is, a site that hosts RPMs that may be installed via Yum. You probably shouldn't directly edit these files; instead, if you want to add a repository, you should manually download the RPM that includes the repository configuration and install it using yum. The next time you use Yum, it will access your new repository along the old. Several Yum repositories exist, for Red Hat, CentOS, and Fedora, as the the following:

Livna This repository (http://yum.livna.org/) hosts multimedia tools, such as additional codecs and video drivers.

KDE Red Red Hat, CentOS, and Fedora the GNU Network Object Environment (GNOME) desktop environment, however they ship with the K Desktop Environment (KDE), too. The repository at http:///kde-redhat.sourceforge.net provides improved RPMs for those who favor KDE.

Fresh RPMs This repository (http://freshrps.net) provides additional RPMs, mostly focusing on multimedia applications and drivers.

Many additional repositories exist. Try a Web on terms such as yum repository, or check the Web of any site that hosts unusual software you want to run to see whether it is a Yum repository. If so, it should provide an RPM or other instructions on adding its site to your Yum repository list.

# RPM Compared to Other Package Formats

RPM is a very flexible package management system. In most respects, it's comparable to Debian's package manager, and it offers many more features than tarballs do. When compared to Debian packages, the greatest strength of RPMs is probably their ubiquity. Many software packages are available in RPM form from their developers and/or distribution maintainers.

> Distribution packages frequently modify the original programs in order to make them integrate more smoothly into the distribution as a whole. For instance, distribution-specific setup scripts may be made, program binaries may be relocated from default /usr/local subdirectories, and program source code may be patched to fix bugs or add features. Although these changes can be useful, you may not want them, particularly if you're using a program on a distribution other than the one for which the package was intended.
