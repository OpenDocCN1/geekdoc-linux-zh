# Configuring Linux for a Local Network

# Configuring Hostnames

The hostnames described earlier (in “Resolving Hostnames”) are configured in a couple of ways:

**On DNS** Your network administrator should be able to add an entry for your system to your network's DNS server. This entry should make your computer addressable by name from other computers on your local network, and perhaps from the Internet at large. Alternatively, remove systems’ /etc/hosts files can be modified to include your system.

**On Your Local Computer** Various local programs should know your computer's name. For instance, you may want to set your hostname displayed as a command prompt or automatically in email messages. For this task, you must set your hostname locally. This is entirely independent of your DNS. In theory, you can set the two to very different values, but this practice is likely to lead to confusion and perhaps even failure of some programs to operate properly.

The most basic tool for setting your hostname locally is called, appropriately enough hostname. Use the command to see what your hostname is, or type it with a new name to set the system's hostname to that name:

```
# hostname dnsname.example.com
```

Similar commands, domainname and dnsdomain, display or set the computer's domain name (as example.com). The domainname command sets the domain name as used by Network Information System (NIS), whereas dnsdomain sets the domain name as used by DNS. These commands do not affect remote servers—just the name given to programs that use calls designed for these servers.

Many Linux distributions use the /etc/hostname or /etc/HOSTNAME file for the hostname to set at boot. If you want to set your hostname permanently, you should look for these files and, if one exists, you should edit it. Fedora uses /etc/sysconfig/network for this purpose, others. If you cannot find any of these, consult your distribution's documentation; it is conceivable that your distribution stores its hostname in some unusual location.

# Configuring a Network Connection

In this exercise, the assumption is that the computer is correctly configured to use an IPv4 Ethernet network, including both local access and access to a larger network (probably the Internet) via a router.

Some of the procedures in this exercise can easily break your network connectivity if something goes wrong. If this happens, typing ifdown followed by ifup is one way to recover. If this fails, rebooting the computer is almost certain to work, although it's a radical solution.
