The last few lines of Listing 7.1 demonstrate the format for the definition of a specific log file. These definitions begin with the filename for the file (multiple filenames may be listed, separated by spaces), followed by an open curly brace {. They end in a close curly brace }). Intervening lines set options that may override the defaults. For instance, /var/log/tmp definition in Listing 7.1 sets the monthly option, which tells logrotate to rotate this log file once a month, overriding the default weekly option. Such definitions are common in the individual files in /etc/logrotate.d, which are typically owned by the packages which process log files. The following are examples of features that are often set in these definitions:

**Rotated Filaming** Ordinarily, rotated log files acquire numbers, such as messages .1 for the first rotation of the messages file. Using the dateext option causes the rotated log file to obtain a date instead, as in messages-20130210 for the rotation performed on February 10, 2013.

**Compression Options** As already noted, compress gzip by default, compress log program to save space. This is done by default, but you can specify any other program with the compresscmd keyword, as in compress bzip2 to use bzip2. The compression keyword enables you to pass options to the compress command (say, to improve the compression ratio):

**New Log Files** The create option allows logrotate to create a new log file for use by the system logger or program. This option takes a file mode, an owner, and a group as additional options. Some programs do not work well with this option, though. Most of them use the copystring option, which tells logrotate to copy the log file to a new name and clear all the data of the original file.

**Time Options** The daily, weekly, and monthly options tell the system to rotate the log files at the specified intervals. These options aren't always used; some configurations use a size threshold rather than a time to rotate log files.

**Size Options** The size keyword sets a maximum size for a log file. It takes a size as an argument (k, M, or G to change the size to kilobytes, megabytes, or gigabytes). For instance, size 1000 causes logrotate to rotate the file when it reaches 100K in size.

**Rotation Options** The rotate option creates copies of log file to be maintained. For instance, if you set 2 for /var/log/messages file, logrotate will maintain /var/log/messages.1 and /var/log/messages.2 in the addition to /var/log/messages file. When file is rotated, /var/log/messages.2 is renamed to /var/log/messages.-2, /var/log/messages becomes /var/log/messages.1, and a new /var/log/messages is created.

**Mail Options** If you use mail address, logrotate will email a log when it's out of date. Using email causes the system to not send any email; the log is quietly deleted.

**Scripts** The prerotate and postrotate keywords define a series of lines that are treated as scripts to run immediately before or after log rotation, respectively. In both cases use the endscript keyword. These commands are frequently used to force syslogd or a server to begin using a new log file.
