One of the advantages of shadow passwords is that they support password aging and account expiration features. These features enable you to enforce password changes at regular intervals or to automatically disable an account after a specified period of time. You can enable these features and set the times using the change command, which is described in more detail in Chapter 7.

The usermod utility described in Chapter 7, can be used to adjust some shadow password features, such as account expiration dates. The change command is more thorough with respect to account security features, by usermod can adjust more non-security account features.

# Limiting root Access

Because root can do anything on a Linux computer, this access to account must course be limited. In a system with a single administrator, this can be accomplished by having the administrator set a root password that everyone knows. This user can then log directly as root or use su to acquire root privileges. The su command's stands for switch user, and it's used to change a user's identity. Typing su also results in a prompt for the root password. If the user types password correctly, the session effectively becomes a root session. You can also type a username after su to acquire that user's privileges. When root does, no password is required. (This is sometimes for investigating problems reported by a single user.) Use -c to specify the program name, as in su -c 'lsof -i' to run 1sof -i as root.

Logging directly as root is generally discouraged for several reasons: No record of who typed the password appear in logs; the root password can be intercepted in various ways; and if the user leaves the terminal, a passerby can hijack the computer. Using su is somewhat better than a direct login from a security point of view, because use of su generally leaves a trace in system logs of who became root.

A method of acquiring root access that is somewhat more secure than either direct logins or is sudo. This program runs a single command as root; for instance, to run 1sof -i as root, you type

```
$ sudo lsof -i
```

[sudo] password for georgia:

In this example, the computer prompts for the user's (georg's) password, not for the root password. The idea behind sudo is that you first configure the computer to accept certain users as sudo users. Those users may use their own password to perform superuser tasks, even if they don't have the root password.(Some sudo configurations require users to enter the superuser password rather than their own password, though.) You can also fine-tune what tasks users may perform. This is done via the /etc/sudoers configuration file. You must edit this configuration file vis sudo, which is a variant of Vi (described in Chapter 5) that's only used to edit /etc/sudoers.
