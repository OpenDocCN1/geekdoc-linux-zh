SHELL=/bin/bash

Be sure to type these lines exactly; a typo will cause problems. One exception: Substitute your email address on the Linux system or elsewhere for username; cron uses the MAILTO environment variable to determine how to email the output of cron jobs.

+   4. Type crontab cronjob to install the crontab file as a cron job. Note that this method replaces any existing user crontabs that might exist. If you've already defined user crontabs for your account, you should edit your existing crontab file to add the line ifconfig rather than create a new file, or type crontab -e to edit its copy from the crontab storage directory.

+   5. Wait for noon (12 in the cron time format). When this time rolls around, you should have a new email waiting for you with the contents of the ifconfig output.

Instead of waiting for noon, you can substitute a time that's a couple of minutes in the future. Remember that cron specifies minutes first, followed by the hour in a 24-hour format. For instance, if you create the file at 3:52 p.m., you might enter 54 as the first two numbers on the final line of the file; this will cause the cron job to execute at 15:54 on a 24-hour clock, or 3:54 p.m.

# Using anachron

Cron is a great tool for performing tasks, such as rotating log files, on systems that are most or all of the time, it's a much less useful tool on systems that are frequently shut down, such as notebook computers or even desktop systems. Frequently, late-night cron jobs are not executed on such systems, which can lead to bloated log files, cluttered /tmp directories, and other problems.

One solution to these problems is anachron cron to ensure that regular maintenance jobs are executed at regular intervals. It works by keeping a record of programs it should execute and how frequently it should, in days. When anachron runs, it checks to see when it executed each of the programs is configured to manage. If a period greater than the program's execution interval has passed, anachron runs the program. Typically, anachron runs itself from a cron job. You can then configure your regular system cron as anachron jobs and be sure they'll execute on systems that are regularly shut for long stretches of time.

Like cron, anachron is controlled through a configuration file named itself: /etc/anachrontab. This file consists of three types of lines: comment lines (denoted by a leading hash mark, #), environment variable assignments (as in SHELL=/bin/bash), and job definition lines. This type of line contains four fields:

period delay identifier command
