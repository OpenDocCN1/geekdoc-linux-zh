You can back up your MBR partitions by typing fdisk -d /dev/sda > sda-backup.txt (or similar commands to specify any other device or backup file). You can then copy the backup file (sda-backup.txt in this example) to a removable disk or another computer for safekeeping. You can restore the MBR partitions by typing fdisk -f /dev/sda < sda-backup. Be sure you are using the correct backup file, though; a mistake can generate incorrect or even partition definitions!

MBR partitions have type codes, which are 1-byte (2-digit hexadecimal) numbers, to identify their purpose. Common type codes you may run into 0x0c (FAT), 0x05 (an old type of extended partition), 0x07 (NTFS), 0x0f (a new type of extended partition), 0x82 (Linux swap), and 0x83 (Linux filesystem).

Although the MBR data structure survived for three decades, its days are numbered because it's not easily extensible beyond 2TiB disks. A new system is needed.

# GPT Partitions

GPT is part of Intel's EFI specification, but GPT can be used on computers that don't use EFI, and it is the preferred partitioning system for disks larger than 2TiB. Most EFIbased computers use GPT on smaller disks than 2TiB.

GPT employs a protective GPT, which is a legal MBR definition that makes GPTunaware units think the disk holds spans the entire disk. Additional data structures define the true GPT partitions. These data structures are duplicated, with one at the start of the disk and another at its end. This provides redundancy which can help in data recovery should an accident damage one of the two sets of data structures.

GPT goes away by default (and that limit may be raised, if necessary) MBR distinction. You can define up to 128 partitions, but gaps occur in partition numbering, so you can have a disk with partitions numbered 3, 7, and 104, to name just possibility. In practice, GPT partitions are usually numbered consecutively with 1.

GPT's main drawback is that support for it is relatively immature. The fdisk utility (described shortly in “Partitioning a Disk”) doesn't work with GPT disks, although alternatives to fdisk are available. Some versions of the GRUB boot loader also don't support it. The situation is worse in OSparticularly older ones. Nonetheless, you should be at least familiar with GPT because of MBR's inability to handle disks larger than 2TiB.

Like MBR, GPT supports partition type codes; however, GPT type codes are 16-byte GUID values. Disk partitioning typically translate these codes into short descriptions, such as “Linux swap.” Confusingly, most installations use the same type code for their filesystems that Windows uses for its filesystems, although a Linux-only code is available and is likely to begin heavier use beginning in 2013.
