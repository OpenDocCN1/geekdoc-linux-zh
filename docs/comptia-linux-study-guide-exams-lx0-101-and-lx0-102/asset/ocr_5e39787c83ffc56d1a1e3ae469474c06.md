# Understanding syslogd

Most Linux systems employ a special daemon to handle log maintenance in a unified way. The traditional Linux system logger is syslog, which is often installed from a package called syslog-log. The syslog daemon handles messages from servers and other user-mode programs. It's usually paired with a daemon klogd, which is generally installed from the same syslog package as syslog. The klogd daemon handles logging of kernel messages.

Other choices for system loggers exist. For instance, syslog-ng is a replacement that supports advanced filtering, and metalog is another option. Recent versions of Fedora and Ubuntu use rsyslog. This chapter describes the traditional syslog logger. Others are similar in principle, and in some specific features, but differ in many details.

The basic idea behind a system logger is to provide a unified means of handling log files. The daemon runs in a background and accepts data from servers and other programs that are configured to use the log daemon. The daemon can then use information provided by the server to classify the message and direct it to an appropriate log file. This configuration enables you to consolidate messages from various servers in a handful of standard log files, which can be easier to manage and maintain potentially dozens of log files from the various servers running on the system.

In order to work, of course the log daemon must be configured. In the case of syslogd, this is done through the /etc/syslog.conf file. (The rsyslog configuration file is /etc/rsyslog.conf and is similar to syslog.conf.) The next section describes the syslog.conf file's format in detail.

# Setting Logging Options

The format of the /etc/syslog.conf file is conceptually simple but provides a great deal of power. Comment lines, as in many Linux configuration files, are denoted by a hash mark (#). Non-priority action take the following:

facility.priority action

In this line, the facility is a code for the program or tool that generated the message to be logged; the priority is a code for the importance of this message; and the action is a remote computer, or other location to accept the message. The facility and priority are often referred to collectively as the selector.

Valid codes for the facility are auth, authpriv, cron, daemon, lpr, mail, news, security, syslog, user, uucp, and local0 through local7. Many of these names refer to specific servers or program classes. For instance, mail servers and other mail-processing tools typically log using the mail facility.
