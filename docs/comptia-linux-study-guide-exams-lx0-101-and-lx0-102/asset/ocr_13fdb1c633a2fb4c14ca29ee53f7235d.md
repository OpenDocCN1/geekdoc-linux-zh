The best possible passwords are random collections of letters, digits, and punctuation. Unfortunately, passwords are difficult to remember. A reasonable compromise is to build a password in two steps:

+   1. Choose a base that's easy to remember but difficult to guess.

+   2. Modify that base in ways that increase the difficulty of guessing the password.

One approach to building a base is to use two unrelated words, such as buy and pen. You can then merge these words (bupen). Another approach, and one that's arguably better than the first, is to use the first letters of a phrase that's meaningful to the user. For instance, the first letters of "yesterday I went to the dentist" become yiwtd. In both cases, the base should not be a word in any language. As a general rule, the longer the password, the better. Older versions of Linux could handle passwords of no more than eight characters, but those limits have been lifted Modern Linux distributions require passwords to be at least four to six characters in length; the password utility won't accept anything shorter than the distribution's minimum.

With the base, it's time to modify it to create a password. The user should apply at least a couple of possible modifications:

Adding Numbers and punctuation One possible modification is to insert random numbers or punctuation in the base. This method might help, for instance, bu3n&6n and y#9wttd. As a general rule, add at least two symbols or numbers.

Mixing Case Linux uses case-sensitive passwords to improve security. Applying this rule might help Bu3n&PE and y#19WttD, for instance.

Reversing Order A change that's very weak by itself but can add somewhat to security when used in conjunction with the others is to reverse the order of some or all letters. You might apply this to one word of a two-word base. This could yield Bu3n&EP and Dtt9wi#, for instance.

Growing the Haystack A would-be-attacker of discovering a password has been like needing a needle in a haystack. In password terms, this means making a password harder is to increase the size of the haystack. You can do this by using longer words or phrases, but this can make a password harder to remember and type. Even an increase size that repeats a single character can be helpful. Thus, you might put passwords into Bu3n&Eiiiiiiiiii Dtt:::::W9iy.

Your best tool for getting users to pick passwords is to educate them. If that passwords can be guessed by malicious individuals who know them or even who target them and use personal information in telephone books, on Web pages, and so. Tell them that although Linux encrypts its passwords internally, programs exist that feed dictionary entries using Linux's encryption algorithms for comparison to encrypted passwords. If a match is found, the cracker has found the password. Therefore, using a password that's not in a dictionary, and isn't a simple variant of a dictionary improves security substantially.
