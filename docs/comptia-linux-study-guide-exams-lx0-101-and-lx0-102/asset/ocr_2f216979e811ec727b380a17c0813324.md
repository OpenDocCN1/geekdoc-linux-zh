# Setting Up inetd

You control servers that launch via inetd through the /etc/inetd.conf file in /etc/inetd.d. The /etc/inetd.conf file consists of a series of lines, one for each server. A typical line resembles the following:

```
ftp stream tcp nowait /usr/sbin/tcp /usr/sbin/in.ftpd -l
```

This and several subsequent examples refer to in.ftpd, an FTP server that was once quite popular but that's been replaced on many systems by other FTP servers. Some of these servers cannot be run from a super server.

Instead of using a monolithic /etc/inetd.conf file, versions of inetd enable you to split the configuration into several files in the /etc/inetd.d directory. Doing so enables you to easily add or delete servers by adding or deleting configuration files. For, the following paragraphs refer only to /etc/inetd.conf, and the description applies to files in /etc/inetd.d, as well.

Each line in /etc/inetd.conf consists of several fields separated by one or more spaces.
The meanings of these fields are as follows:

+   **Service Name** The first field (ftp in the preceding example) is the name of the service as it appears in the /etc/inetd.services file.

+   **Socket Type** The socket entry defines the type of connection to expect—a reliable two-way connection (stream), a less reliable connection with less overhead (dgram), a low-level connection to the network (raw), or others. The different types are highly technical; your main concern in editing this entry should be to correctly type the value specified by the server's documentation.

+   **Protocol** This is the TCP/IP transport-layer protocol used, usually tcp or udp.

+   **Wait/No Wait** For dgram socket type, this entry specifies whether the server connects to its client and waits (nowait) or processes all its packets and times out (wait). Servers that use other socket types should nowait in inetd.

+   **User** This is the username to run the server. The root and nobody are common choices, but others are possible as well. As a general rule, you should run servers with a low-privilege user whenever possible as a security precaution. Consult the server's documentation for details.

+   **Server Name** This is the filename of the server. In the preceding example, the server is specified as /usr/sbin/tcpd, which is the TCP Wrappers binary. As described shortly in “Controlling Access via TCP Wrappers,” this program is an security tool and should be included in the list of launching programs via inetd.

+   **Parameters** Everything after the server name consists of parameters that are passed to the server. If you use TCP Wrappers, you pass the name of the true target server (such as /usr/sbin/in.ftpd) in this field, along its parameters.
