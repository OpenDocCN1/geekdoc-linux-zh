
# Administering Network Security

On computers using the SysV startup system, /etc/initt deserves examination. This file, described in Chapter 5, controls some of the earliest stages of the startup process. Of greatest interest from a specific point of view is that later /etc/initt installations started the processes used to accept text-mode logins, as well as similar processes used to accept logins via dial modems and RS-232 serial ports. These processes are called getty or some variant of this, such as mingetty. Ordinarily, a machine must have at least one such process running, and it's controlled by an /etc/initt entry such as the following:

```
1:2345:respawn:/sbin/mingetty --nuclear tty1
```

The first character of this line (1) specifies the virtual terminal (VT) it controls. Most Linux distributions include lines for the first six VTs, and there's usually no need to adjust these lines. Lines that begin with #, which is a number, control login via RS-232 serial ports and:

```
5:2345:respawn:/usr/sbin/mingetty -f -s 5700 /dev/tty50
```

If you want to use the computer without a button then ensure that /etc/initt does not have such lines. Modern systems that lack /etc/initt or have very basic /etc/initt files typically move these functions into other files, such as SysV startup scripts or files in /etc/init. You won't ordinarily need to modify such configurations, but you may want to check if your system is listening for dial modem connections unnecessarily. Files /etc/init/tty# (where # is a number) control local login access, whereas /etc/init/tty# files control RS-232 serial or modem access.

# Uninstalling or Reconfiguring Servers

Once you've identified an unnecessary server, your task becomes one of shutting down. Broadly speaking, two options are:

- You can disable the server by changing its startup script configuration or by disabling it in your system's server. Consult Chapter 5 and the preceding sections in inetd and details how to perform these tasks. Disabling the server in this way has the advantage that you can easily reactivate the server in the future if you decide to do it. It has the disadvantage that the server's file will continue to consume disk space, and the server might be accidentally reactivated in the future.

- You can completely uninstall the server using your distribution's package management tools or by deleting its files. Chapter 2, "Managing Software," describes this task. Completely uninstalling software has the advantage of reducing the risk of accidental reactivation, but it has the drawback that it will take more effort to reactivate the server you choose to do so in the future.

Overall, completely removing the server is generally preferable unless you merely want to temporarily disable a server. If you decide to reactivate the server in the future, you can always re-install it.

# Administering Local Security

Security isn't limited to networking—local security issues can be as much of a threat as remote intruders. Thus, you should attend to some local security matters: securing passwords, limiting root access to the computer, setting user limits, and tracking SUID/SGID files.

# Securing Passwords

A default Linux configuration relies heavily on passwords. Users' passwords are their keys into the system, and careless handling of passwords is like careless handling of physical keys—security breaches occur. Understanding these risks is critical to maintaining system security, but this is one task for which you must enlist the help of users; after all, they are the ones in possession of their passwords! You should also be aware of the tools Linux provides to keep passwords secure. (Most of the details concerning password-related commands are described in Chapter 7, "Administering the System.")

# Password Risks

Passwords can end up in crackers' hands in various ways, and you must take steps to minimize these risks. Steps you can take to improve your system's security include the following:

**Strong Passwords**: Users should employ good passwords, as described shortly in “Choosing a Good Password.” This practice won’t eliminate all risk, though,

**Change Pass Frequently**: You can minimize the chance of damage due to a compromised password by changing passwords frequently. Some Linux tools can help to ensure such changes, as described in “Tools for Managing Passwords” and in more detail in Chapter 7.

**Use Shadow Passwords**: If a cracker’s broken into your system through an ordinary user account can read the password file, or one of your regular users is a cracker who has access to the password file, that individual can run any of several password-cracking programs on the file. For this reason, you should use shadow passwords stored in /etc/shadow whenever possible. Major Linux distributions use shadow passwords by default. If yours doesn’t, consult the upcoming section “Tools for Managing Passwords” for information about enabling this feature.

**Keep Passwords Secret**: You should remind your users not to reveal their passwords to others. Sometimes even a well-intention password recipient may slip up and let the password fall into the wrong hands. This can happen by writing the password down, storing it in electronic form, or sending it by email or electronic means. Users shouldn't email their own passwords to themselves, because email can be intercepted.

**Use Remote Login Protocols**: Certain remote login protocols are inherently insecure; all data traverse the network in an unencrypted form. Intervening computers can be configured to snatch passwords from such sessions. Because of this, it's best to disable Telnet, FTP, and other protocols that use cleartext passwords in favor of protocols that encrypt passwords, such as SSH.

**Be Alert to Shoulder Surfing**: If users log in using public terminals, as is common on college campuses, in Internet cafes, and the like, it will be others able to watch them type their passwords—a practice sometimes called shoulder surfing. Users should be alert to this and minimize such logins.

**Use Each Password on Just One System**: If one computer's password database is compromised and if users reuse passwords on other systems, then other systems can be compromised. For this, it's best to use each password just once. Unfortunately, the proliferation of Web sites that require passwords makes this rule impossible to enforce, without violating the rule of not writing them down (Modern browsers can remember passwords for you, but this is by storing them in a file). A reasonable compromise might be to use one password for the least-sensitive Web sites (such as online newspapers) and unique passwords for sensitive Web sites (such as banking sites) and login accounts.

**Be Alert to Social Engineering**: Crackers often use social engineering to obtain passwords. This practice involves tricking individuals into giving up their passwords by pretending to be a system administrator or misleading them. A related practice is phishing, in which an attacker puts up a fake Web site or sends an email pretending to be someone else. The victim is lured into revealing sensitive data (such as credit card numbers).

Some of these steps are things you can do, such as replacing insecure login protocols with encrypted ones. Others are things your users must do. This illustrates the importance of user education, particularly on systems with many users.

# Choosing a Good Password

As a rule, people tend to be lazy when it comes to security. In computer terms, this means users tend to pick passwords that are easy to guess, and they change those passwords infrequently. Both conditions make a cracker's life easier, particularly if the cracker knows it. Fortunately, Linux includes tools to help your users select good passwords and change them regularly.

Poor but common passwords include those based on the following:

- Names of family members, friends, and pets
- Favorite books, movies, television shows, or the characters in any of them
- Telephone numbers, street addresses, or Social Security numbers
- Any other meaningful personal information
- Any single word that's found in a dictionary (in any language)
- Any simple keyboard or alphanumeric combination, such as qwerty or 123456
