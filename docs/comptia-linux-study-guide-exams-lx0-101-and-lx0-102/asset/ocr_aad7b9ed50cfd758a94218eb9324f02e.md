# Creating Partitions and Filesystems

As of Linux kernel 3.6.0, ReiserFS version 3.x is current. A from-scratch rewrite by ReiserFS, known as Reiser4, is under development, although development has slowed to the point that it is uncertain if Reiser4 will ever be included in the mainline kernel.

JFS IBM developed the Journaled File System JFS for its AIX OS and later reimplemented on OS/2. The OS/2 version was subsequently donated to Linux. JFS is a technically sophisticated journaling filesystem that may be of interest if you're familiar with AIX OS or want an advanced filesystem to use on a dual-boot system with one of these OSs. As you might expect, this filesystem's type code is jfs.

XFS Silicon Graphics (SGI) created its Extents File System (XFS) for its IRRIX OS and, like IBM, later donated to Linux. Like JFS, XFS is a very technically sophisticated filesystem. XFS has gained a reputation for robustness, speed, and flexibility on IRIX, but some of the features that make it possible on IRRIX aren't supported under Linux. Use xfs as the type code for this filesystem.

Btrfs This filesystem (pronounced "butter eff" or "bee tree eff") is an advanced filesystem with features inspired by Sun's Zabbay File System (ZFS). Like ext4, JFS, and Btrfs is a fast performer and is able to handle very large disks and files. As of the 3.6.0 kernel, Btrfs is considered experimental; however, its advanced features make it a likely successor to the current popular filesystems.

In practice, most administrators create ext3, ext4, or ReiserFS as their primary filesystems; JFS and XFS work well, and some administrators prefer them, particularly on large disks. (Ext4 also handles large files.) Hard data on the merits and problems with each filesystem are difficult to come by, and even when they exist, they suspect because filesystem performance interacts with many other factors. For instance, as noted, ReiserFS can cram more small files into a small space than other filesystems, but this advantage isn't very important if you're storing mostly larger files.

> If you're using an x-86 or non-x86-64 platform, be sure to check filesystem development on that platform. A filesystem may be speedy and reliable on one CPU but sluggish and unreliable on another.

In addition to these Linux-native filesystems, you may need to deal with others from time to time, including the following:

FAT The File Allocation Table (FAT) filesystem is old and primitive—but ubiquitous. It's the only hard disk format supported by DOS and Windows 9x/Me. For this reason, every major OS understands FAT, making it an excellent filesystem for exchanging data on removable disks. Two orthogonal variants of FAT exist: it varies in the size (12-, 16-, or 32-bit pointers), and has variants that support long filenames.
