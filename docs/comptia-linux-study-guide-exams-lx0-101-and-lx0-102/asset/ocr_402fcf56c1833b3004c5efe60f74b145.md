# Chapter 7 • Administering the System

When you run at and give it a time specification, the program responds with its own prompt, at>, which you can treat much like your normal bash or other command prompt. When you're typing commands, press Ctrl+D to terminate input. Alternatively, you can pass a file with commands using the -f parameter to at, as at -f commands sh noon to use the contents of commands.sh as the commands you want to run at noon.

The at command has support tools. The most important of these is atd, the at daemon. The program must be running for at to do its work. If it's not, check for its using ps. If it's not running, look for a startup script and ensure it's enabled, as described in Chapter 3.

Other programs include atq, which lists pending at jobs; atm, which removes from at the queue; and batch, which works like at but executes when system load level drops below 0.8. These utilities are all fairly simple. To use atq, simply type its name (The program supports a couple of options, but chances are you won't need them; consult atq's man page for details). To use atm, type the program name and the number of at, as returned at. For instance, you might type at 12 to remove job at noon.

The facility supports access restrictions like those of cron. Specifically, the /etc/at.allow and /etc/at.deny files run analogously to the /etc/cron.allow and /etc/cron.deny files. There are a few wrinkles with at, though. If neither at.allow nor deny exists, only root may use at. If at.allow exists, the users listed are granted access to at. # Summary

Routine system administration involves a variety of tasks, many of which center around user management. Adding, deleting, and modifying user accounts and groups are critical tasks that all system administrators must master. Also related to users, you should know where to go to modify the default user environment.

System log files are critical troubleshooting tools that are maintained by the system. You should be able to configure what data is logged and know how to use these log files.

Time management is important in Linux. Setting the Linux clocks (both hardware and software) and configuring NTP to keep the system clock accurate are important tasks. Tools that rely on the time include cron, anacron, and at, which enable the system to run programs in the future. These tools are used for many common system tasks, including rotating log files.
