# Appendix A - Answers to Review Questions

15. A. A default use of df reports the percentage of disk space used (option D) and the mount point for each filesystem (option E). The number of inodes (option B) and filesystems (option C) can both be obtained by passing parameters to df. This utility does not report how long a filesystem has been mounted (option A), so option is correct.

16. D. The journal of a journaling filesystem records operations, resulting in quicker disk checks after an uncontrolled shutdown, option D is correct. Contrary to option A, journaling filesystems are, as a class, never than non-journaling filesystems; in fact, the journaling ext3 is built upon the non-journaling ext2fs. Also disk checks are quicker with non-journaling filesystems than with fsck, they still need to be run from time to time, so option B is correct. All Linux-native filesystems support Linux ownership and permissions; this isn't an advantage of journaling filesystems, contrary to option C. The journal of a journaling filesystem doesn't provide an "undo" feature, so option E is correct.

17. When without a filesystem type specification, mount attempts to auto-detect the filesystem type. If the media contains any of the specified filesystems, it should be detected and the disk mounted, option E is correct.

18. B. The /etc/fstab consists of lines that contain the device identifier, the mount point, the filesystem type code, the dump flag, and the filesystem frequency in order. Order B provides this information in the correct order and so will work. Order A reverses the second and third fields which is correct. Options C, D, and E all reverse the first three fields and also specify the noauto mount option, which causes the filesystem to not mount automatically at boot.

19. A, B, C. The user, and owners in /etc/fstab enable all ordinary users to mount a filesystem, but with very different implications: users enables to mount a filesystem, but only that user may mount; it enables to mount a filesystem, and only may unmount it; owners enables only the owner of the mount point to mount or unmount a filesystem. Thus, options A, B, and C are all correct. The owners parameter of option D does not exist. The uid1000 parameter of option E tells Linux to set the ownership of UID on filesystems that lock permissions features. Although this might be desirable for some disks, it doesn't enable the user with UID 1000 to mount the disk, so option E is correct.

20. A A correctly describes the safe procedure for removing a removable medium that allows a locking mechanism from a computer (Instead of using mount /dev/sdb; in this context, the two commands are equivalent.) Option B reverses the order of operations; the mount must be before you physically remove the drive. Option C also has the sync; the sync command can prevent damage when removing the drive. There is no standard usbdrive-remove command in Linux, and if you were to write a script that calls unmount usbdrive-remove-remove, pulling the flash drive quickly, as option D describes, would be exactly the wrong thing to do. The fsck command of option E checks a filesystem for errors. It's not necessary to do this before removing a disk, and it won't unmount the disk, so option E is correct.
