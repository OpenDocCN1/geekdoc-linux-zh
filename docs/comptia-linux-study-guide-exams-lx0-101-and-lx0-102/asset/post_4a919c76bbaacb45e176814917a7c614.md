3. C. The vertical refresh rate range includes a maximum value, but that value may be reduced when the resolution and vertical refresh rate would demand a higher horizontal refresh rate than the monitor can handle. Option C is correct. Since the resolution affects the maximum refresh rate, option A is incorrect. The color depth is irrelevant to resolution and refresh rate calculations, option B is incorrect. 4. E. Option E describes the correct location for this. The ServerLayout section (referenced in option A) combines all the other options but doesn't set the resolution. The Modeline option in the Monitor section (as described in option B) defines one possible resolution, but there may be several Modeline entries defining many resolutions, and there is no guarantee that any of them will be used. The Modeline option does not exist in the Device section (as suggested by option C), nor is it that there is no DefaultResolution section (as referenced in option D).

Converting a bitmapped display into ASCII text of optical character recognition (OCR) software, not a font server, so option D is incorrect. 6. E. XDMCP servers are launched either from a system script or by init (as specified in /etc/initab, as described in options C and E. The XDMCP server starts X. The Stored folder mentioned in option A is a Windows structure, not a Linux structure. The /.xinitrc script mentioned in option B is an X login script starting X from the command line via start; it's not to automatically start X when the system boots. A boot manager, as described in option D, launches the kernel; it doesn't directly start X, so option D is incorrect.

7. The XDM greeting is a resource in the /etc/X11/xdm/Resources file, so option E is correct. XDM does not offer many options on its main screen and certainly not one to change its settings, as described in option A. The kernel does directly handle the login process, nor does it pass options directly to XDM, so option B is incorrect. Although the xorg.conf file mentioned in option C is real, this provides no XDM configuration options because XDM is a separate program from the X server. There is no xdmconfig program, as mentioned in option D.

8. C. KDM and GDM have many features, one of which is a menu that enables users to select their desktop environment or manager when they log in rather than specifying it in a configuration file, as option C states. Option A describes the advantages of the Secure Shell (SSH) as a remote-access protocol. Option B describes a feature common to all three servers. Option D describes how both KDM and XDM function: GDM is the one that presents username and password fields in rather than simultaneously. Although a failure of X to start usually results in a fallback to a text-mode login, this feature is not provided by the XDMCP server, so option E is correct.

9. The xhost command controls various aspects of the X server, including the remote-host computers from which it will accept connections, making option A correct. Option B sets the DISPLAY environment, which doesn't directly affect the X server (it does tell X clients which server to use). Option C initiates a text-mode remote login session with penguin@example.com via ssh may also initiate a tunnel, this isn't guaranteed, and option D's access is a fictitious program. Although logging into penguin@example.com allows the local X to accept connections from the remote computer, option E is correct.

10. As stated in option A, GNOME, KDE, and other users often override the keyboard repeat settings in the X configuration file. Option B has it backward; most Linux distributions have adopted XFree86, and therefore X86Config, in favor of X.org11 and xorg.conf. Option C is pure function; xorg settings apply to all varieties of keyboards, and there is no uskbrate program. Although keyboards have hardware switches, which don't affect X's ability to control the keyboard repeat rate, contrary to option D. Although you can set a keyboard's nationality in xorg.conf, this option is independent of the keyboard repeat rate settings, so option E is incorrect.

11. C. The Orca and Em programs provide text-to-speech conversion facilities, so option C and E are both correct. Braille is a form of writing that uses bumps or holes on a surface that can be read by touch. Linux supports Braille output devices, the question specifies computer-generated speech, but Braille is, so option B is incorrect. SoX is an audio format converter, which can't convert text to speech. The talk program (option D) is an early Unix text-mode "chat" program, but it has no built-in speech capabilities.

12. E. Time zones are determined by the timezone file, in /usr/share/zoneinfo, making option correct. The smart filter makes a printer “smart” that it can accept different formats (plain text, PostScript, graphics, and so on) and print them all correctly, as in option E. Soft smoothing is useful on low-resolution computer monitors, but not on most printers, and adding font is not a function of a smart filter, so option A is incorrect. A smart filter does not detect confidential information (option B) or prank jobs (option D). The lpr command can be given a parameter to email a user when the job finishes (option C), but the smart filter does not do this.

13. D. Coordinated Universal Time (UTC) is the standard for time, so option D is correct. Local time (option B) is also an option, but UTC is the global reference. Pacific time (option A) is an offset from UTC, not the standard itself. The TZ variable (option E) is a way to set time, but it is not the time standard.

14. C. The LC_ALL environment variable, when set, adjusts all locale, so option C is correct. BSD has no locale data, so option A is incorrect. There is no /etc.conf file, so option B is incorrect. There is no standard locale_set utility, so option D is incorrect.

15. A. The Unicode Transformation Format 8 (UTF-8) standard can encode characters for any language on Earth, while looking like ordinary ASCII. ASCII-8 (option B) is an old standard that is adequate for English but lacks characters needed by most languages. ISO-8859 (options C and D) is a standard that extends ASCII, but it requires separate encodings for different languages. ATASCII (option E) is a variant of ASCII used in the 1980s by Atari; it is obsolete and inadequate.

18. The lpr command (option C) deletes a job from the print queue. It can take the -Pqueue option to specify the queue and a print job number or other parameters to specify which jobs to delete. BSD LPD, LPRng, and CUPS all implement the lpr command, so you can use it with any of these systems, making option A incorrect.
