# Mounting and Unmounting Filesystems

Filesystem Type The filesystem type code is the same as the type code to mount a filesystem with the mount command. You can use any filesystem type code you can use directly with the mount command. A filesystem type code of auto lets the kernel auto-detect the filesystem type, which can be a convenient option for removable media. Autodetection does not work with all filesystems, then.

Mount Options Most filesystems support several mount options, which modify how the kernel treats the filesystem. You may specify multiple mount options, separated by commas. For instance, uid=500,umask=0 for windows in Listing 3.1 User ID (owner) of all files and 500 sets the mask to 0. (User ID and umasks are covered in more detail in Chapter 4). Backup Order The next-to-last field contains 1 if the dump utility should back up a partition or 0 if it shouldn't. If you never use the dump program, this option is essentially meaningless. (The dump program was once a common backup tool, but it is less popular today).

Filesystem Check Order At boot time, Linux uses the fsck program to check filesystem integrity. The final column specifies the order in which this check occurs. 0 means that fsck should not check a filesystem. Higher numbers represent the check order. The root partition should have a value of 1, and all others that should be checked should have a value of 2. Some filesystems, as ReiserFS, should not be automatically checked and have values of 0.

If you add a new hard disk or repartition the one you have, you'll probably need to modify /etc/fstab. You may also need to edit some of its options. For instance, setting the user ID or umask on Windows partitions mounted in Linux may be necessary to ordinary users to write to the partition.

# Managing User-Mountable Media

You may want to give ordinary users the ability to mount certain partitions or removable media, such as floppies, CD-ROMs, and USB flash drives. To do so, create an ordinary /etc/fstab entry but to add the user, or owner option to the options column. Table 3.5 describes the differences between these three options. Listing 3.1 shows some examples of user-mountable media: /media/a/cdrom, /media/a/usb, /other/home, and /other/win. The first two of these are designed for removable media and include the noauto option, which prevents Linux from wasting time to mount them when the OS first boots. The second pair of mount points are network file shares that are mounted automatically at boot time; the users option on these lines enables ordinary users to unmount and then remount the filesystem, which might be handy if, say, ordinary users have the ability to shut down the server.
