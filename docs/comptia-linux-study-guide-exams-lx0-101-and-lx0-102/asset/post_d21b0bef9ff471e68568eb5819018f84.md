# Configuring Routing

As explained, routers pass traffic from one network to another. You configure your Linux system to direct contacts on the local network. You also give the computer a router's address, which your system uses as a gateway to the Internet. Any traffic that's not destined for the local network is directed at this router, which passes on to its destination. In practice, there are likely a dozen or more routers between you and most Internet sites. Each router has at least two network interfaces and keeps a table of rules where to send data based on the IP address. Your own Linux computer has such a table, but it's probably very simple compared to those on major Internet routers.

```bash
route [add | del] [-net | -host] target [netmask nm] [gw gw] = [reject] [[dev interface]]
```

You specify add or del along with a target (a computer or network address) and optionally other parameters. The -net and -host options route to interpret the target as a network or computer address, respectively. The netmask option lets you to set a netmask as you desire, and gw lets you specify a router through which packets go. The reject keyword installs a blocking route, which refuses all traffic destined the specified network. This is not a failure, though. Finally, although route can usually figure out the interface device (for instance, eth0) on its own, you can force the interface with the dev option.

As an example, consider a network in which packets destined for the 172.20.0.0/16 subnet should be passed through the 172.21.1.1 router, which isn't the default gateway system. You can set up this route with the following command:

```bash
# add -net 172.20.0.0 netmask 255.255.255.0 gw 172.21.1.1
```

Incorrect routing tables can cause some problems because all computers won't respond. You can examine your routing table by typing route alone and compare the results to what your routing table should contain. (Consult a network administrator if you're not sure what your routing table should contain.) You can then delete incorrect routes and add new ones to replace them, if necessary. Ultimately, of changing your configuration files is the best solution, but typing a couple of route commands will do the trick in the short term.

One thing you may need to do if you're setting up a route is enabling routing. Ordinarily, a Linux system won't forward packets it receives from one system that is directed at another. If Linux is to act as a router, then it must accept all packets and send them to the destination network (or to an appropriate gateway). To enable this, you must modify a key file in the /proc/sys filesystem:

```bash
# echo "1" > /proc/sys/net/ipv4/ip_forward
```

This command enables IP forwarding. Permanently setting this option requires modifying a configuration file. Some distributions set it in /etc/sysctl.conf:

```bash
net.ipv4.ip_forward = 1
```

Other distributions use other configuration files and options, such as /etc/sysconfig/sysctl1 and its IP_FORWARD line. If you can't find it, try grepping to search for ip_forward or IP_FORWARD, or modify a local startup script to add the command to perform the change.

# Using GUI Configuration Tools

Most distributions include their GUI configuration tools for network interfaces. For instance, Fedora and Red Hat ship with a custom GUI tool called Network Configuration (system-config-network), and SUSE has a text-mode and GUI tool called YaST. The details of operating these programs differ, but the GUI configuration tool provides a means to enter the information much earlier.

Although the exam doesn't cover GUI network configuration tools, they are generally easier to use and learn the configuration files in which settings are set. Thus, you may want to look for your distribution's tool and learn to use it. Once you understand the principles of network configuration (IP addresses, DHCP, and so on), you shouldn't have trouble entering the information in the GUI fields.

The precise details of how configuring a Linux system using GUI tools differ from one distribution to another. For instance, SUSE's YaST doesn't lay out its options in precisely the same way as Fedora's Configuration tool. The basic principles are the same; you must choose whether to use static IP address assignment or an automatic system such as DHCP and enter a number of key options, depending on what configuration method you choose.

# Using the ifup and ifdown Commands

Most Linux distributions today use two commands, ifup and ifdown, that combine the functions of other network commands, most notably ifconfig and route. In their simplest forms, they bring interfaces up or shut down based on information in whatever files your distribution uses to store network configuration data:

```bash
# ifup eth0
Determining IP information for eth0... done.
```

After you issue this command, eth0 will be fully configured, including you've properly configured it using your distribution's network configuration tools or by manually editing configuration files as /etc/network/interfaces and /etc/sysconfig/network/ifcfg-name. You can bring the interface down equal by typing ifdown eth0.

The ifup and ifdown commands are useful if you need to bring the network back. They are implemented as scripts that consult the configuration files and run behind the scenes.

# Configuring Hostnames

The hostnames described earlier (in “Resolving Hostnames”) are configured in a couple of ways:

**On DNS** Your network administrator should be able to add an entry for your system to your network's DNS server. This entry should make your computer addressable by name from other computers on your local network, and perhaps from the Internet. Alternatively, systems’ /etc/hosts files can be modified to include your system.

**On Your Local Computer** Various local programs should know your computer's name. For instance, you may want to set your hostname displayed as a prompt or automatically in email messages. For this task, you must set your hostname locally. This is entirely independent of your DNS. In theory, you can set the two to different values, but this practice is likely to lead to confusion and perhaps failure of some programs to operate.

The most basic tool for setting your hostname locally is called, enough hostname. Use the command to see what your hostname is, or type it with a new name to set the system's hostname to that name:

```bash
# hostname dnsname.example.com
```

Similar commands, domainname and dnsdomain, display or set the computer's domain name (as example.com). The domainname command sets the domain name as used by Network Information System (NIS), whereas dnsdomain sets the domain name as used by DNS. These commands do not affect remote servers—just the name given to programs that use calls designed for these servers.

Many Linux distributions use the /etc/hostname or /etc/HOSTNAME file for the hostname to set at boot. If you want to set your hostname permanently, you should look for these files and, if one exists, you should edit it. Fedora uses /etc/sysconfig/network for this purpose, others. If you cannot find any of these consult your distribution's documentation; it is conceivable that your distribution stores its hostname in some unusual location.
