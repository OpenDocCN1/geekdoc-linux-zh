
# Understanding Network Addressing

- IPv6 includes a new feature, known as stateless address auto-configuration (SAC), which simplifies initial network setup. This feature is similar in some ways to the Dynamic Host Configuration Protocol (DHCP) which is commonly used in IPv4, (DHCP can also be used on IPv6; which works best on the local network's configuration.)
- IPv6 introduced the Internet Protocol Security (IPsec) tools, which can improve the security of Internet connections. IPsec has been back-ported to IPv4.
- IPv6 streamlined some data structures, enabling quicker processing by routers.

More obscure differences also exist. Check http://en.wikipedia.org/wiki/IPv6 or http://www.ipv6forum.com for detailed information about IPv6.

IPv6 is starting to emerge as a new networking force in many parts of the world. The United States is lagging behind IPv6 deployment. The Linux kernel includes IPv6 support, and many distributions now attempt to automatically configure IPv6 networking in addition to IPv4. Chances are by the time the average office will need IPv6, it will be standard. Configuring a system for IPv6 is somewhat different from configuring it for IPv4, which is what this emphasizes.

In order for one to communicate with another over a network, the computers need to have some way to refer to each other. The basic mechanism for doing this is provided by a network address, which can take several different forms, depending on the type of hardware, protocol stack, and so on. Large and routed networks pose additional challenges to network addressing, and TCP/IP provides answers to these challenges. Finally, to address a specific program on a remote computer, TCP/IP uses a port number, which identifies a specific running program, something like a telephone extension number which identifies an individual in a large company. The following sections describe all these methods of addressing.

# Using Network Addresses

Consider an Ethernet network. When an Ethernet frame leaves one computer, it's normally addressed to another Ethernet card. This addressing is done using low-level Ethernet features, independent of the protocol stack in question. Recall, however, that the Internet is composed of many networks that use many different low-level hardware components. A user may have a dial-up telephone connection (through a serial port) but connect to one server that uses Ethernet and another that uses Token Ring. Each of the devices uses a different type of low-level network address. TCP/IP requires something to integrate different types of network hardware. In total, three types of addresses are important when you're trying to understand network addressing: network hardware addresses, numeric IP addresses, and text-based hostnames.

# Addressing Hardware

One of the characteristics of dedicated network hardware such as Ethernet or Token Ring cards is that they have unique hardware addresses, also known as Media Access Control (MAC) addresses, programmed into them. In the case of Ethernet, these addresses are 6 bytes in length, and they're generally expressed as hexadecimal (base 16) numbers separated by colons. You can discover the hardware address for an Ethernet card using the ifconfig command. When ifconfig ethn, where n is the number of the interface (0 for the first card, the second, and so on), you'll see several lines of output, like this one:

```
eth0 Link encap:Ethernet hwaddr 00:A0:CC:24:BA:02
```

This line tells you that the device is an Ethernet card and that its address is 00:A0:CC:24:BA:02. What is this used for? Certain low-level network utilities and hardware use the hardware address. For instance, network switches use it to direct packets. The switch detects that a particular address is connected to a particular wire, and so it sends data directed at that only over the associated wire. The Dynamic Host Configuration Protocol (DHCP), which is described in the upcoming section “Configuring with DHCP,” is a means of automating the configuration of specific computers. It has an option that uses the hardware address to consistently assign the IP address to a given computer. In addition, advanced network diagnostic tools are available that let you examine packets that come from or to specific hardware addresses.

For the most part, you don't need to be aware of a computer's hardware address. You don't enter it in most utilities or programs. It's important for what it does in general.

# Managing IP Addresses

The network mask (also known as the subnet mask or netmask) is a number that identifies the portion of the IP address that is a network address and the part that's a computer address. It's helpful to think of this in binary (base 2) because it uses binary 1 values to represent the network portion of an address and binary 0 values to represent the computer address. The network portion leads the computer portion. Expressed in base 10, these addresses usually consist of 255 or 0 values, being a network byte and 0 being a computer value.
