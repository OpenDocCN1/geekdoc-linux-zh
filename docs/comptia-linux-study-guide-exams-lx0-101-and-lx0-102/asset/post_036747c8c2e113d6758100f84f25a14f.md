Linux borrows heavily from Unix, and Unix began as a text-based operating system (OS). Unix and Linux retain much of this heritage, which means that to understand how to use and, especially, administer Linux, you must understand at least the basics of the command-line tools. Thus, this book begins with an introduction to Linux shells (the programs that accept and interpret text-mode commands) and many of the basic commands and procedures you can use from a shell.

This chapter begins with shell information, including shell options and procedures for using them. From there, this chapter covers streams, pipes, and redirection, which you can use to shunt input and output between programs or files and programs. These techniques are frequently combined with text processing using filters—commands you can use to manipulate text without the help of a conventional text editor. Sometimes you must manipulate text in an abstract way, using codes to represent several different types of text. This chapter covers this topic.

## Understanding Command-Line Basics

Before you do anything else Linux, you should understand how to use a Linux shell. Several shells are available, but most provide similar capabilities. Understanding a few basics will take a long way in your use of Linux, I describe some of these techniques and commands. You should also understand shell environment variables, which are placeholders for data that may be useful to many programs. Finally, on the topic of command line basics, you should know how to get help with commands you're trying to use.

## Exploring Your Shell Options

With many key software components, Linux provides a range of options for shells. A complete list will be quite long, but the more common choices include the following:

- **bash**: The GNU Bourne Again Shell (bash) is based on the earlier Bourne shell for Unix but extends it in several ways. In Linux, bash is the most common default shell for user accounts, and it's the one emphasized in this book and on the exam.
- **bsh**: The Bourne shell upon which bash is based also goes by the name bsh. It's not often used in Linux, although the bsh command is sometimes a symbolic link to bash.

![](img/35f616c7eba4e79e12bfd762129c5d27_58_0.png)

- **tcsh**: This shell is based on the C shell (csh). It's a fairly popular shell in some circles, but no major Linux distributions make it the default shell. Although in many respects, some operational details differ. For instance, you don't assign environment variables in the same way in tcsh as in bash.
- **csh**: The Original C shell isn't used on Linux, but if a user is familiar with csh, tcsh makes a good substitute.
- **ksh**: The Korn Shell (ksh) was designed to take the best features of the Bourne shell and the C shell and extend them. It has a small but dedicated following among users.
- The file `/bin/sh` is a symbolic link to the system's default shell—normally /bin/bash for Linux. This enables you to point to a shell, at the start of a simple shell script, as described in Chapter 9, "Writing Scripts, Configuring E-mail, and Using Databases" and ensure that a shell will be called, even if the system's available shells change. This feature is particularly important when developing shell scripts that might be run on other computers, as described in Chapter 9.

## Using a Shell

Linux shell is fairly straightforward for anybody who used a text-mode OS before: You type a command, with possible options to it, and the computer executes the command. For the most part, Linux commands are external—that is, they are separate programs from the shell. A few commands are internal to the shell, though, and knowing the distinction is important. You should also know some of the tricks that can make using the command shell easier—how to have the computer complete a long command or line, retrieve a command you've recently run, or edit a command you've recently used (or have yet finished).

> One class of commands—those for handling basic file management—is very important but isn't described here in great detail. For more information on these commands, consult Chapter 4, "Managing Files."

## Starting a Shell

If you log into Linux using a text-mode login screen, chances are you'll be dropped directly into your default shell—the shell is what presents the prompt and accepts subsequent commands.

If you log into Linux using a graphical user interface (GUI) login screen, though, you'll have to start a shell manually. Some GUIs provide a menu option to start a program called terminal, xterm, Konsole, or something similar. These programs enable you to run text programs within Linux, and by default they come up running your shell. If you can't find such a menu, look for one that enables you to run an arbitrary command. Select it, and type xterm or console as the command name; this will launch an xterm-type program that will run a shell.

## Using Internal and External Commands

Internal commands, as you might expect, built into the shell. Most shells offer a similar set of internal commands, but shell-to-shell differences exist; consider your shell's page (as discussed later, in "Getting Help") for details, particularly if you're using an exotic shell. Internal commands you're likely to enable you to perform some common tasks:

- **Changing the Working Directory**: Whenever you're running a shell, you're working in a specific directory. When you refer to a file without providing a complete path to the file, the shell works in the current directory. The cd command changes the current working directory. Similarly, for instance, typing cd /home/sally changes to /home/sally directory. The tilde (~) character is a useful shortcut; stands for your home directory, typing cd ~ will have the same effect as cd /home/sally if your home directory is /home/sally.
- **Display the Working Directory**: The pwd command displays "prints" to the screen to the current working directory.
- **Display a Line of Text**: The echo command displays what you type; for instance, typing echo causes the system to display the string Hello. This may seem pointless, but it's useful in scripts (described in Chapter 9), and it can also be a good way to review the contents of environment variables (described later in this chapter, in "Using Environment Variables")
- **Execute a Program**: The exec command runs an external program that you specify, as in exec run myprog. In most cases, this is best accomplished by typing the name of the program you want to run. The exec command has one special feature: that Rather create a new process that runs alongside the shell, the new process replaces the shell. When the new process terminates, it's if you terminated the shell.
- **Time an Operation**: The time command counts how long subsequent commands to execute. For instance, typing time tells you how long the system took to execute the pwd command. The time is displayed after the full command completes. Three times are displayed: total execution time (real time), user CPU time, and system CPU time. The final two values tell about CPU time consumed, which is likely to be much less than the total execution time.
- **Set Options**: In its most basic form, set displays a wide variety of options relating to bash operation. These options are formatted like environment variables, but they aren't the same things. You can pass various options to set to have effect a wide range of shell operations.
