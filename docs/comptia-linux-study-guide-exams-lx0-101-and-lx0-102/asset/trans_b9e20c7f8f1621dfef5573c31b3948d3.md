

## 分区的替代方案：LVM

对于某些功能，分区的另一种替代方案是逻辑卷管理（LVM）。要使用 LVM，你只需预留一个或多个分区，并为它们分配 MBR 分区类型代码 0x8e（或 GPT 磁盘上的等值）。你使用一系列工具，如 `pvcreate`、`vgcreate`、`lvcreate` 和 `lvscan`来管理分区（在此方案中称为物理卷），将它们合并为卷组，并管理卷组内的逻辑卷。最终，你通过在 /dev/mapper 目录中为其分配的名称来访问逻辑卷，例如 `/dev/mapper/myvol-1`。LVM 最大的优势是它允许你轻松地调整卷的大小，而无需担心周围分区的位置或大小。在某种意义上，逻辑卷就像文件系统中的文件；文件系统（在 LVM 的情况下为卷组）在你调整文件（或逻辑卷）大时管理空间的分配。如果你不确定分区的最佳起始大小，这将巨大的巨大的。你可以轻松地以新磁盘的形式添加磁盘空间，以扩展现有卷组的大小。

缺点是，LVM 增加了复杂性，并不是所有的 Linux 发行版都支持箱即用。如果 LVM 配置跨越多个磁盘，一个磁盘的故障将使你所有的卷组面临风险。更安全的方法是配置系统至少包含一个文件系统（用于 /boot），根文件系统（/）位于独立分区，并将 LVM 留给 /home、/usr 和其他文件系统。

尽管有这些缺点，在某些情况下你可能也会考虑进一步研究 LVM。如果你想创建一个具有许多专用文件系统的安装，并希望在未来保留调整这些文件系统的选项，那么它可能会很有用。另一种情况是，当你需要创建单个物理磁盘无法处理的巨大文件系统时，LVM 非常方便。

## 挂载点

一旦磁盘被分区，操作系统就必须有某种方式访问分区上的数据。在 DOS 和 Windows 中，这是通过为每个分区分配驱动器号（例如 C: 或 D:）来实现。（DOS 和 Windows 使用分区类型代码来决定哪些分区获得驱动器号，哪些被忽略。）然而，Linux 使用统一的目录结构。每个分区都挂载在该结构中的一个挂载点。挂载点是一个用于访问分区上文件系统的目录，而挂载文件系统是将文件系统链接到挂载点的过程。

例如，假设一个 Linux 系统有三个分区：根（/）分区、/home 和 /usr。根分区存放基本系统文件，所有其他分区都通过目录访问。如果 /home 包含用户 sally 和 sam，那么这些目录可以通过 `/home/sally` 和 `/home/sam` 访问；该分区挂载在 /home。如果此分区被卸载并重新挂载到 /users，相同的目录将可以通过 `/users/sally` 和 `/users/sam` 访问。

## 设计硬盘布局

分区可以挂载在 Linux 目录树的任何位置，包括根分区上的目录以及已挂载分区上的目录。例如，如果 /home 是独立分区，你可以拥有一个 `/home/morehomes` 目录，作为另一个分区的挂载点。

真实世界场景

何时创建分区

拆分许多分区的一个问题（特别是对于新管理员）是很难确定合适的大小。如表 3.4 所示，各种分区的合适大小在不同系统之间差异巨大。例如，工作站可能需要较小的 /var（例如 100MiB），但邮件服务器或新闻服务器可能需要 GB 级的 /var。猜错并不是致命的，但很令人讨厌。你需要调整分区（这很麻烦）或在分区之间建立符号链接，以便子目录位于其他。LVM 可以简化这种后续更改，但如前所述，LVM 增加了自身的复杂性。

出于这个原因，我建议新管理员使用简单的分区布局。根（/）分区是必须的，swap 是一个很好的主意。除此之外，/boot 可以留在大于 8GB 的硬盘上，BIOS 自 2000 年以来很少需要。作为数据（在 home 或其他地方），2012 年大多数 Linux 安装需要 5–25GB，因此 /home 的合适大小对于新管理员来说相对容易，或者你可以在创建根 (/) 和 swap 后将所有磁盘空间分配给 /home。除了这些点，我建议新管理员谨慎谨慎。

随着对 Linux 经验的增加，你可能在随后的安装或升级磁盘硬件时将其他目录拆分到自己的分区中。你使用 `du` 命令来学习给定目录内文件占用的多少空间。
