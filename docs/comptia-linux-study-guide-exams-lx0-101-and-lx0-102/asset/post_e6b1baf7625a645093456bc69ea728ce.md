
# Configuring X Base Features

XFree86 The dominant server in Linux 2004 was XFree86 (http://www.xfree86.org). This open source software supports a wide array of video cards and input devices, and Linux software was originally designed with XFree86. As I wrote, the most recent version is 4.8.0. Significant changes occurred between 3.3.6 and the 4.x series, and some older users work only with the 3.3.6 and earlier versions of XFree86. Although a thin number of elderly systems must run XFree86 3.3.6 or earlier for driver support reasons, most systems today run XFree86 4.x or X.org-X11; the latter is more common on distributions released since 2004.

X.org-X11 In 2004, most distributions shifted from XFree86 to X.org-X11 because of licensing changes to XFree86. X.org-X11 6.7 was based on XFree86 4.39, but it independently developed up to the current version, 7.7. Because X.org-X11 is based on XFree86, the two are virtually identical in most important respects. One significant difference is the name of the configuration file; another is the default location for fonts. Subsequent sections of this chapter point out these differences. You can learn more at http://www.x.org/wiki/

Accelerated-X The commercial Accelerated-X server from Graphics (http://www.xig.com) is an alternative to the open source XFree86 and X.org-X11. In practice, running Accelerated-X is seldom necessary, but if you have problems getting your video card working, you may want to look into Accelerated-X; its driver is independent of the more popular open source choices, it's possible you'll have better luck with it. The Accelerated-X tools and files are completely different from those described in "Methods of Configuring X" and "X Configuration Options," so you'll need to consult its documentation for help.

In practice, it is easiest to stick with whatever server your distribution provides. For modern distributions, this is most often X.org-X11. For a handful of elderly video cards, you may need to run the equally elderly XFree86 3.3.6 rather than a more recent version.

# Real World Scenario

## Using Manufacturer-Provided Video Drivers

One of X's functions is to provide drivers that control the video card. XFree86, X.org-X11, and Accelerated-X all ship with a wide variety of drivers that support most video cards. Some cards, though, have weak support in the stock packages. Other cards are supported by the standard drivers, which don't support all of the video device's features. XFree86 4.x and X.org-X11 both support a modular driver architecture, which means you can drop in a modular driver for your card and use with minimal changes to your configuration. Both AMD (formerly ATI) and NVIDIA provide video card drivers designed to work with XFree86 and X.org-X11. (Both servers can use the same drivers.) Thus, if you have problems with the standard X drivers, you may want to check with your video card manufacturer and the video card chipset manufacturers for Linux drivers.

Installing and using the manufacturer-provided video drivers is usually a matter of extracting files from a tarball and running an installation script. Consult the documentation that comes with the driver for details. Many of these drivers are particularly helpful for enabling 3D acceleration features of modern cards. These features were first used by games but are increasingly being used by desktop environments and other non-game software.

One problem with manufacturer-supplied drivers is that they're often proprietary. You might not have source code, which the drivers might not work on more exotic CPUs, and the drivers could cease working with a future upgrade to your X server. The AMD and Nvidia drivers also include Linux kernel drivers as a necessary component, so you'll need to reinstall the drivers if you upgrade your kernel.

# Methods of Configuring X

Configuring X has traditionally been a difficult process because the X configuration file includes many arcane options. The task is made simpler if you can use a configuration utility, and many Linux distributions now run such a utility as part of the installation process. If the configuration utility does not do everything you want it to, though, you may need to delve into the X configuration file to set options manually, knowing something about its format will help you. You must also know how to go about restarting X in order to test your changes.

# X Configuration Utilities

Several configuration tools for XFree86 4.x and Xorg-X11 are available:

**The Server Itself** - The X server itself includes the capacity to query the hardware and produce a configuration file. To do this, type `XFree86 --configure` (for XFree86) and `Xorg --configure` (for Xorg-X11) as root when no X server is running. The result should be a file called `/root/XF86Config.new` (for XFree86) or `/root/xorg.conf.new` (for X-11). This file may not produce optimal results, but it's at least a starting point for manual modifications.

**Distribution-Specific Tools** - Many modern distributions ship with their own X configuration tools. These include Red Hat's (and Fedora's) Display Settings tool (accessible from the default desktop menu or by typing system-config-display in an xterm) and SUSE's YaST and YaST2. These tools frequently reassemble the distribution's install-time-X configuration tools, which can vary substantially.

**xf86cfg or xorgcfg** - This utility is named differently from XFree86 X.org-X11. It's deprecated, meaning it's no longer supported; but if it's present on your system, it can help you attempt tweaks on X while it is at least partially running.

All of these utilities gather the same type of information needed to manually configure X. Your best bet for understanding these tools and what they want is to understand the underlying X configuration file's format and contents.

## The X Configuration Format

The X configuration file is organized into several sections. Each section begins with a keyword and ends with the keyword EndSection. The most common sections are:

**Server** - This section defines global server settings, such as the screen resolution and color depth.

**Device** - This section defines hardware devices, such as video cards and sound adapters.

**InputDevice** - This section defines input devices, such as keyboards and mice.

**Monitor** - This section defines monitor settings, such as refresh rate.

Here is an example of an "InputDevice" section:

```
Section "InputDevice"
Identifier "Keyboard0"
Driver "kbd"
Option "XkbModel" "pc105"
Option "XkbLayout" "us"
Option "AutoRepeat" "500 200"
EndSection
```

This section tells X about the keyboard—its model, layout, and so on. For the most part, the different X servers support the same sections and option names. A few exceptions to this rule do, though:

- The option isn't used in XFree86 3.3.6 and earlier. Instead, the option name (as XkbLayout or AutoRepeat in the preceding example) appears without quotes on the line.
- XFree86 3.3.6 and earlier don't use the Server section, described later.
- XFree86 3.6 and earlier lack the Identifier and Driver lines, which are common in the X4.x and Xorg configuration files.
- Some section-specific features vary between versions. I describe the most important of these in the coming pages.
