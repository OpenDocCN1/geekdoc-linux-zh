# Appendix A - Answers to Review Questions

13. D. Linux, like Unix, maintains its internally in Coordinated Universal Time (UTC), so setting the computer's hardware clock to UTC (option D) is the recommended procedure for computers that run only Linux. Unlike Torvalds spends time at the University of Helsinki, Helsinki time (in option A) has no place in Helsinki. Local time (in option B) is appropriate if the dual-boots to an OS, such as Windows, which requires the hardware clock to be set to local time, but this is the best-option for a Linux-only system. Option C's US Pacific time, like Helsinki time, has no special significance in Linux. Internet time (option E) is an obscure way to measure time that divides each day into 1,000 “beats.” It's not a time and is not an appropriate way to set your hardware clock.

14. C. The LC_ALL environment variable (option C), when set, adjusts all the locale (LC*) variables, and setting them running the script will make the programs that script works as if on a British computer. BSD has no locale data, so option A is incorrect. There is no standard /etc/locale.conf file, so option B is incorrect. There is no standard locale_set utility, so option D is incorrect. Allowing the TZ environment variable, in option E, will set the time for your zone for Great Britain, which won't affect the sort of text formatting options noted in the question.

15. A. The Unicode Transformation Format 8 (UTF-8) standard can encode characters for just any language on Earth, while looking like just ordinary ASCII or programs that only understand ASCII. When a choice is possible, ASCII-8 (option A) is the preferred method for character encoding ASCII (option B) is an old standard that's adequate for English and a few other languages, but it lacks or all characters needed by most languages. ISO-8859 (options C and D) is a standard that extends ASCII, but it requires separate encodings for different languages and is so awkward when a computer process data from multiple languages. ATASCII (option E) is a variant of ASCII used in the 1980s by Atari for its computers; it's obsolete and inadequate.

16. E. The smart filter makes a printer “smart” that it can accept different formats (plain text, PostScript, graphics, and so on) and print them all correctly, as in option E. Soft smoothing is useful on low-resolution computer monitors, but not on most printers, and adding font is not a function of a smart filter, so option A is incorrect. A smart filter does not detect confidential information (option B) or prank jobs (option D). The lpr command can be given a parameter to email a user when the job finishes (option C), but the smart filter does not do this.

17. B. The job ID (option B) and job owner (option D) are both displayed by 1pq. Unlike the application embeds its own name (option A) in the filename, information won't be present. Most printers lack Linux utilities to query ink or status (option C); certainly 1pq cannot do this. Although knowing when your job will finish printing (option E) would be handy, this is beyond 1pq's capabilities to provide.

18. The lpr command (option C) deletes a job from the print queue. It can take the -Pqueue option to specify the queue and a print job number or other parameters to specify which jobs to delete.
