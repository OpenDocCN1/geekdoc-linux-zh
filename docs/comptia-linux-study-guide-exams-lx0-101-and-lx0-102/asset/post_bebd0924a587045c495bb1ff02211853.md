
The device is the filesystem device file, such as /dev/sda7. This command explains several options, most of which are obscure. The most important option is probably -h, which causes the utility to omit information about group descriptors. (This information is helpful in very advanced filesystem debugging but not for basic filesystem tuning.) For information about additional options, consider the man page for dump2fs. Unless you're a filesystem expert and need to debug a corrupted filesystem with the -h option, the result is about three dozen lines of output, each specifying a particular filesystem option, like:

```
Last mounted on: <not available>
Filesystem features: has_journal filetype sparse_super
Filesystem state: clean
Inode count: 657312
Block count: 1313305
Last checked: Sun Feb 26 14:23:23 2012
Check interval: 15552000 (6 months)
```

Some of these meanings are fairly self-explanatory; for instance, the filesystem was last checked with fsck, in "Checking Filesystems" on February 26, 2012. Other options are not obvious; for instance, the Inode count may be puzzling. Each count contains information for one file, so the number of inodes supported by the filesystem limits the number of files you can store.

The next sections describe some of the options you may want to change. For now, you should know that you can retrieve information about how your filesystems are configured using dump2fs. You can use this information when modifying the configuration; if your current settings seem reasonable, you can leave them alone; if they seem ill-adapted to your configuration, you can change them.

Unlike many low-level disk utilities, you can safely run dump2fs on a filesystem that is currently mounted. This can be handy when you're studying the filesystem to decide what to modify.

Most filesystems lack an equivalent to dump2fs, but XFS provides something with at least some surfaces: xfs_info. To invoke it, pass the name of the partition that holds the filesystem you want to check:

```

```

Instead of the partition name, you can pass the mount point, such as /home or /usr/local/. Unlike most filesystem tools, xfs_info requires the filesystem to be mounted. The information returned by xfs_info is fairly technical, mostly related to block sizes, sector sizes and so on.

Another XFS tool is xfs_metadump. This program copies the filesystem's metadata (file names, sizes, and so on) to a file. For instance, xfs_metadump /dev/sda7 ~/dump-file1 copies the metadata to ~/dump-file1. This command does not copy actual file contents and isn't useful as a backup tool. Instead, it is intended as a debugging tool; if the filesystem is behaving strangely, you can use this command and save the resulting file for XFS developers for study.

## Adjusting Tunable Filesystem Parameters

The tune2fs program enables you to change many of the filesystem parameters that are reported by dump2fs. This program's syntax is fairly simple, but it hides a great deal of complexity:

```
tune2fs [options] device
```

The complexity arises because the large number of options that the program accepts. Each feature that tune2fs enables you to adjust its own option:

- **Adjust the Maximum Mount Count**: Ext2fs, ext3fs, and ext4fs require a periodic disk check with fsck. This is designed to prevent errors from creeping onto the disk undetected. You can adjust the number of times the disk may be mounted without a check with the -c counts option, where counts is the number of mounts. You can trick the system into thinking the filesystem has been mounted a certain number of times with the -C counts option; this sets the mount counter to counts.

- **Adjust the Time Between Checks**: Periodic disk checks are required based on time as well as number of mounts. You can set the time between checks with the -i interval, where interval is a number with the character d, w, or m, to specify days, weeks, or months, respectively.

- **Add a Journal**: The -j option adds a journal to the filesystem, effectively converting an ext2 filesystem into an ext3 filesystem. Journal management is described in more detail in "Maintaining a Journal."

- **Set the Reserved Blocks**: The -m percent option sets the percentage of disk space that is reserved for root. The default value is 5, but this is excessive on multi-gigabyte hard disks, so you might want to reduce it. You may want to set the reserved space to 0 to remove blocks used to store user files. You can also set the reserved space in blocks, rather than a percentage of disk space, with the -r blocks option.

The options described here are the ones that most likely to be useful. Several other options are available; consult tune2fs's man page for details.

With most low-level disk utilities, you shouldn't tune2fs to adjust a mounted filesystem. If you want to adjust a key filesystem, you should unmount it first.

## Interactively Debugging a Filesystem

In addition to reviewing flags, you can use debugfs on Linux. You'll see the debugfs prompt:

```
# debugfs /dev1
debugfs:
```

You can type commands at this prompt to:

- **Display Filesystem Superblock**: The showstat command produces superblock information, similar to dump2fs.

- **Display Inode Information**: You can display the inode of a file by typing stat.

- **Undelete File**: You can undelete a file by typing undelete inode, where inode is the number of the deleted file. You must know the inode associated with the deleted file to use.

- **Extract a File**: You can extract a file from the filesystem by typing internal external-file, where internal is the name of the file and external-file is the destination. This facility can be handy if a file is badly damaged and you want to recover.

- **Manipulate Files**: Most of the commands work within debugfs. You can change your directory with cd, create links with ln, remove a file with rm, and so on.

- **Obtain Help**: Typing help or ? produces a summary of available commands.

- **Exit**: Typing quit quits the program.

This summary just scratches the surface of debugfs's capabilities. In the hands of an expert, this program can help rescue a badly filesystem or at least critical data from it. To learn more, consult the program's man page.

> Although debugfs is a useful tool, it's potentially dangerous. Don't use on a mounted filesystem, don't use unless you have to, and be careful when using it. If in doubt, leave the adjustments to the experts. Be aware that the exam cover debugfs, though.

The closest XFS equivalent to debugfs is xfs_db. Like debugfs, xfs_db provides an interactive tool to access and manipulate a filesystem, but xfs_db provides fewer tools that are amenable to novice or intermediate use. Instead, xfs_db is a tool for XFS experts.
