# Chapter 4 • Managing Files

Depending on your distribution, you may need to configure the quota package's system startup scripts to run when the system boots. Chapter 5 describes script management detail. Typically, you'll type a command as chconfig quota on, but you should check on the SysV scripts installed by your distribution's quota package. Some distributions require the use of other commands as chconfig to do this, as described in Chapter 5. Whatever it does, this startup script runs the quota command, which activates quota.

After installing software and making configuration file changes, you must activate the systems. The simplest way to do this is to reboot the computer, and this step is necessary if you had to recompile your kernel to add quota support directly into the kernel. If you didn't do, you should be able to get by with less disruptive measures: using modprobe to install the kernel, or necessary; running the startup script for the quota tools; and remounting the filesystems on which you intend to use quotas by mounting -o remount /mount-point, where mount-point is your point in question.

# Setting Quotas for Users

At this point, quota support should be fully active on your computer, but the quotas themselves aren't set. You can set the quotas using edquota, which starts the Vi editor (described in Chapter I, "Exploring Linux Command-Line Tools") on a temporary configuration file (/etc/quotat) that controls the quota for you specify. When you use it, edquota uses the temporary configuration file to write the quota information to low-level data structures that control the kernel's quota mechanisms. For instance, you might type edquota salty to edit salty's quotas. The contents of the editor show your current quota information:

Disk quotas for user salty (uid 21810):
| Filesystem | blocks | soft | hard | inodes | soft | hard |
| /dev/sd4 | 97104 | 104856 | 104856 | 1242 | 0 | 0 |

The temporary configuration file provides information about both the disk blocks in use and the use of inodes. (Each file or multiple consumes an inode, so the inodes are effectively limits on the number of files a user may use). Disk blocks vary depending on the filesystem and filesystem options, but typically ranging from 512 bytes to 8KB. Changing the information (under the blocks and inodes) has no effect; these columns report how many blocks or inodes the user is actually consuming. You can alter the soft and hard limits for both blocks and inodes. The hard limit is the maximum number of inodes that the user may consume; the kernel won't permit a user to surpass these limits. Soft limits are somewhat less stringent; they issue warnings. Soft limits also interact with a grace period; if the soft quota limit is exceeded for longer than the grace period, the kernel begins treating it like a hard limit and refuses to allow the user to create more files.
