# Creating User cron Jobs

To create a user cron job, you use the crontab utility, not to be confused with the /etc/
crontab configuration file. The syntax for crontab is as follows:

```
crontab [- u] -l | -e | -r] [file]
```

If given without the -u user parameter, crontab modifies the cron job file (or user
crontab) associated with the current user.

> The word crontab has three related but distinct meanings: It can refer to
theontab program, to the /etc/crontab file, or to the file that holds
user jobs. This multiplicity of meanings can be obviously confusing.
in this book, I refer to the program by using a monospaced code font, and I include the complete path to /etc/crontab, and I do not use
monospaced font when referring to crontabs. A user's crontab file can
define multiple cron jobs.

The crontab utility may become confused by the use of su to change the current user
identity, if you use this command, it's safest to use -u user, even when you're
modifying your crontab.

If you want to work directly on a crontab, use the -l, -r, or -e option. The -1
causes crontab to display the current crontab; -r removes the current crontab; and -e
op an editor so that you can edit the current crontab (Vi is the default editor, but you
can change this by setting the VISUAL or EDITOR environment variable).

Alternatively, you can create a cron job configuration file and pass the filename to
crontab using the file parameter. For instance, crontab -u taker my-cron causes the
crontab program to use my-cron for taker's jobs-that is, it copies taker's my-cron
file into the directory where it stores crontabs, making a few changes along
the.

Whether you create a cron job and submit it via the file parameter or edit it via -e,
the format of the crontab file is similar to that described earlier. You can set environment
variables by the form VARIABLE=value, or specify a command preceded by
five fields or wildcards when the job is to run. In a user cron job, you do
specify the username to execute the job, as you do with system cron jobs. That
information is derived from the owner of the crontab. Listing 7.2 shows a sample user
crontab file. This file runs two programs at different intervals: the fetchmail program
runs 30 minutes (on the half and hour mark), and clean-adouble runs on Mondays
at 2:00 a.m. Both programs are specified via complete paths, but you can include a PATH
environment variable and omit the complete path specifications.
