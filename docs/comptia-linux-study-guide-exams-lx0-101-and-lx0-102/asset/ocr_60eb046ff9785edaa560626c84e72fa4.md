Linux's internal use of UTC can change the hardware clock. Ideally, the hardware clock should be set to UTC; but if your system multi-boots Linux and an OS expects the hardware clock to be in local time, you will have to set it and configure Linux to deal with this fact. For the most part, this configuration works well but you may have to watch the clock the first time you reboot in the spring or fall changing your clocks because of a daylight saving time. Depending on your Linux and other OS settings, your hardware clock may be reset in one OS or the other not.

Both the hardware clock and the software clock are notoriously unreliable on standard x86 and x86-64 hardware; both clocks tend to drift, so your clock can easily end up being several minutes off the correct time within a minute or two of being. To deal with this problem, Linux supports various network protocols for setting the time. The most popular of these is the Network Time Protocol (NTP), which is described in the upcoming section “Using NTP.”

# Manually Setting the System Time

You can manually set your system’s clock—or more precisely, because clocks, as noted earlier, Linux maintains two clocks: the hardware clock and the software clock. The main tool to set the software clock is date, which has the following syntax when setting the clock:

```
date [-u|--utc] [[CC]YY][[MMDDhhmm]][[.ss]]
```

Without any options, this command sets the current date and time. This format contains a month, a day, and a minute at a minimum, all in two-digit codes (MMDDDhmm). You can optionally add a 2- or 4-digit year and the seconds within a minute if you like. You should specify the time in a 24-hour format. For instance, to set the time to 3:02 p.m. on October 27, 2013, you’d type the following command:

```
# date 10271502223
```

By default, you are specifying the time in local time. If you want to set the clock in UTC, include the -u, --utc, or --universal option.
