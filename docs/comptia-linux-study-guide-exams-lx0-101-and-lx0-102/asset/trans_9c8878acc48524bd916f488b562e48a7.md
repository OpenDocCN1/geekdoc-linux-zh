

# 附录 A - 复习题答案

11. B. Yum 使用 `/etc/yum.reposd` 目录下的文件来定位其仓库，因此你可以通过向该子目录添加内容来扩展仓库列表（选项 B 所示），通常通过安装 RPM 或手动添加文件。选项 A 描述了向使用 APT 的计算机添加仓库的方法。选项 C 的 `add-repository` 子命令是虚构的。虽然选项 D 和 E 描述的 `/etc/yum.conf` 文件确实存在，但它并不存储仓库数据。

12. B. `/etc/ld.so.conf` 文件持有全局路径，因此编辑它是首选方法。然后你必须运行 `ldconfig` 让系统更新其库路径。选项 B 是正确的。虽然你可以通过修改 `LD_LIBRARY_PATH` 环境变量（如选项 A 所示）将目录添加到库路径，但这种方法不是首选的，所以选项 B 是正确的。选项 C 不起。选项 D 不作用，尽管链接单个库文件是可以行的，但对于整个目录来说，这种方法不是首选的。`ldd` 显示可执行文件的库信息，因此选项 E 不起预期效果。

13. D. 库是由程序员选择的，而不是用户或系统管理员。如果你不喜欢某个库提供的小部件（widgets），你没多少选择，选项 D 是正确的（许多小部件提供了很强的配置性，因此你可能可以通过其他方式解决问题）。选项 A、B 和 E 描述了 `ldconfig`、`rpm`、`dpkg` 和内核的虚构选项。选项 C 不作用；使用 Qt 的程序在发现没有预期的 Qt 库而是只有 GTK 库时将会崩溃。

14. D. `kill -9` 命令接受数字或命名形式的值（在本例中为 9）以及进程 ID 号（在本例中为 1128）。信号 9 对应 `SIGKILL`，这是杀死无法运行进程的极端方式。因此，选项 D 描述了该命令的效果。虽然你可能使用 `kill -11` 来杀死网络进程，但你无法这样做，所以选项 A 是错误的。程序不会显示关于已杀掉进程数量的信息，这使得选项 B 是正确的。要执行 C 所示的操作，你需要告诉 `kill -11` 发送 `SIGHUP`（信号 1），因此命令将是 `kill -11 -1 1128`，选项 C 是错误的。`kill -11` 命令无法更改进程的属性，所以选项 E 是正确的。

15. C. `top` 实用显示进程的动态列表，按 CPU 使用率排序，并带有额外的系统信息，包括负载平均值（load averages），所以选项 C 是正确的。如果你只需要特定时刻的平均值，`uptime`（选项 D）可能更好，因为它提供了冗余信息——它显示当前时间、系统启动以来的时间、活动用户数和负载平均。选项 A 的 `ld` 与显示负载平均无关（它是一个将进程模块链接到可执行程序的编程工具）。Linux 中没有名为 `load`（选项 B）或 `Ia`（选项 A）的标准 Linux 程序。

16. A. `ps` 的 `--forest` 选项显示父子关系，在 `ps` 输出的进程名称之间创建视觉链接，这使得选项 A 是正确的（列表 2.4 显示了这种效果）。选项 B 和 C 都是有效的，但都没有创建指定的效果。选项 D 描述了一个虚构的 `ps` 选项。由于选项 B、C 和 D 是错误的，选项 E 也必然是错误的。

# 附录 A：复习题答案

17. CPU 密集型程序通常会消耗 90% 或更多的可用 CPU 时间，但并非所有系统都运行此类程序。此外，某些类型的程序可能会产生 CPU 负载。因此，选项 A 是正确的，你必须调查这个问题。什么是 `dump`？它被设计为 CPU 密集型程序吗？它是在持续消耗这些 CPU 时间吗，还是只是短暂的活动高峰？选项 B、C、D 和 E 都在草率下结论，或者为行为正常或异常提供了虚构的理由。

18. `jobs` 命令汇总了从当前 shell 启动的进程。当没有进程运行时，`jobs` 不返回任何内容，所以选项 E 是正确的。`jobs` 命令不检查或汇总 CPU 负载，所以选项 A 是错误的。`jobs` 命令也不检查来自当前 shell 其他 shell 的进程，所以选项 B 是错误的（以用户名运行的进程可能是从另一个 shell 或 GUI 环境启动的）。Linux 中没有标准的 `jobs`，所以选项 C 是错误的。因为 `jobs` 的输出仅限于你运行的 shell 中的进程，空白输出并不表示系统崩溃，所以选项 D 是错误的。

19. `nice` 命令以降低的优先级启动程序（在本例中）。当指定 `nice` 时，默认优先级为 10，而 `nice` 也将将优先级设置为 10，选项 C 和 E 是等等的。选项 A 不是有效的 `nice`，因为 `nice` 没有 `--value` 选项。选项 B 是一个有效的 `nice`，因为它将优先级设置为 -10 而不是 10。尽管选项 C 和 D 的形式相似，但选项 D 是无效的且是错误的。要传递数字 `nice`，你必须使用前置连字符 `-n`。

20. Linux 限制了用户之间的相互操作，此规则也适用于 root；root 可以修改其他用户的优先级，所以选项 D 是正确的。同样，root 只能增加进程的优先级，以防止用户将优先级设置为最高优先级并抢夺他人的 CPU 时间，所以选项 E 是正确的。选项 A 正确地降低了优先级，但不是通过 `nice`；`nice` 的意义在于能够改变别人的优先级。
