## Querying and Setting Your Locale

To localize your locale, you must first understand what a locale is in Linux parlance. Once you understand the basics, you can identify your current locale and other locales available to you. If necessary, you may need to install another locale's data. You can then set your computer to use that locale.

## What Is a Locale?

In Linux, a locale is a way of specifying the computer's (or user's) language, country, and related information for customizing displays. A single locale takes the following:

```
[language_..territory][[.codet][@modifier]]
```

Each part of this string has a set of specific acceptable forms. For instance, language can be en (English), fr (French), ja (Japanese). These are two or three-letter codes for languages.

The territory can be US (United States), FR (France), JP (Japan), and so on. These are codes for specific regions—generally nations.

The charset is defined as ASCII, UTF-8, or other encoding names. The American Standard Code for Information Interchange (ASCII) is the oldest and most primitive encoding method; it supports 7-bit encodings (generally stored in 8-bit bytes) that can handle English, including punctuation and symbols. ASCII can't handle characters used in non-English languages, though it's awkward at best for international use. ISO-8859 was an early attempt to extend ASCII; it employs an eighth bit to extend ASCII by 128 characters, giving room for the characters needed by a small number of non-Roman alphabets. ISO-8859 broken down into many standards, each of which handles one language or group of languages. ISO-8859-1 covers Western European languages and ISO-8859-5 provides Cyrillic support, for instance.

The latest codepage is the 8-bit Unicode Transformation Format (UTF-8). Like ISO, UTF-8 starts with ASCII but extends it by supporting variable-byte extensions so that a single character can take anywhere from one to four bytes to be encoded. This provides the ability to encode any text supported by Unicode, which is a character set designed to support as many languages as possible. The big advantage of UTF-8 over ISO-8859 is there's no need to specify a standard, such as ISO-8859-1 or ISO-8859-5; UTF-8 handles all of its variants automatically.

The *modifier* is a locale-specific code that modifies how it works. For instance, it may affect the sort order in a language-specific manner.

## What Is Your Locale?

A locale code can be assigned to one or more of several environment variables. To learn how these are set on your system, issue the locale command without any arguments:

```
$ /usr/bin/locale
LANG=en_US.UTF-8
LC_TYPE=en_US.UTF-8
LC_NUMERIC=en_US.UTF-8
LC_TIME=en_US.UTF-8
LC_COLLATE=en_US.UTF-8
LC_MONETARY=en_US.UTF-8
LC_MAGES=en_US.UTF-8
LC_PAPER=en_US.UTF-8
LC_NAME=en_US.UTF-8
LC_ADDRESS=en_US.UTF-8
LC_TELEPHONE=en_US.UTF-8
LC_MEASUREMENT=en_US.UTF-8
LC_IDENTIFICATION=en_US.UTF-8
LC_All=
```

As you can see, few locale variables exist. When programs pay attention to these variables, they adjust appropriately for your locale. For instance, a word processor may default to using paper sizes (such as 8.5 × 11 inches) when territory code is set to US, European paper sizes (such as A4, 210 mm) when territory is set to a country where those paper sizes are common.

Most of locale variables set specific and obvious features, such as LC_PAPER (paper size), LC_MEASUREMENT (measurement units), and so on. The LC_ALL variable is sort of master override—if it's, it overrides all other LC_* variables. A related environment is LANG. It sets the same type of locale specification as LC_* variables. It sets the locale in case LC_* variables aren't set.

While you're using the locale command, you should try it with the -a option, which identifies all locales that are available:

```

In this example (from Ubuntu system), very few locales are installed. Some systems may have hundreds.

## Changing Your Locale

If you want to change your locale, you should first verify that an appropriate one is available by using locale -a. If don't see appropriate codes, you may need to install additional packages. Unfortunately, names for these packages arent't standardized. Your best bet is to use a GUI package manager such as yum or synaptic (described in Chapter 2) to search on names and descriptions that include locale or language. In the case of Ubuntu system that provided just a few locales, many more could be installed.

Temporarily change your locale, the simplest method is to set the LC_ALL environment variable. For safety, you should also set LANG. For instance, set the locale for Great Britain rather than the United States, you can type:

```
$ LANG=en_GB.UTF-8
$ LC_ALL=en_GB.UTF-8
```

The result should be that all locale variables change for that session. There will also be changes in the output of programs that handle locale. Note that this change affects only the current shell and the programs you launched from it; not those that are already running or that launch from another shell.

To permanently change your locale, you can adjust your bash startup files, such as .bashrc or /etc/profile, as described in Chapter 1, Exploring Command-Line Tools. Shell scripting is described in more detail in Chapter 9, but setting or adjusting the LANG and LC_ALL environment variables is fairly straightforward.

X's configuration file (xorg.conf) includes an option XRConfig in the keyboard's InputDevice section. This option takes a partial or complete locale specification but converted to lowercase—for instance, us or en_us.utf-8. Adjusting this option can provide you with access to language or country-specific keys. After changing this option, you'll have to restart X for the changes to effect.

Some programs and sets of programs may require you to set the language independent of the overall locale. Thus, you may need to adjust the language for certain programs. If a program doesn't seem to respond to the overall locale setting, check its documentation or browse through its menus to find and adjust its defaults.

## Modifying Text-File Locales

Sometimes it's necessary to access textual data that originated on a system that used one encoding but process the data with a program that doesn't support encoding. For instance, your preferred text editor might support UTF-8 but not ISO-8859. If you deal exclusively with English text files in ASCII, this isn't a problem; but if you receive an ISO-8859-1 text file with a few non-Roman characters, such as characters with umlauts, your editor might display those characters strangely.

To overcome this problem, the iconv utility converts between character sets. Its syntax is as follows:

```
iconv -f encoding -t encoding [inputfile]...
```

The -f and -t options specify the source and destination encodings.(You can obtain a list of encodings by typing iconv --list.) If you omit the target encoding, iconv uses your current locale for guidance. The program sends output to standard output, so if you want to store the data in a file, you must redirect it:

```
$ iconv -f iso-8859-1 -t UTF-8 umlfile > umlfile-utf8.txt
```

> Localization support is, to some extent, the responsibility of each program's author. It's entirely possible to write a program that supports one language or a small subset of languages. Thus, you won't be able to get every program to support your desired language, particularly if it's an unusual one.
