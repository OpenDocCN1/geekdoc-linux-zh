# Using lsof

The lsof program nominally lists open files. It can be used to identify what files are open in a directory, finding who's accessing them, and so on. The definition of file used by lsof instead of netstat for some tasks, including listing servers, is that you can use lsof instead of netstat. In its most basic form in this role, you should pass the -i parameter to lsof:

```
# lsof -i
COMMAND PID USER FD TYPE SIZE NAME
sh 2498 root rodmith 3u IPv4 3292662 TCP-* (ESTABLISHED)
exim4 4822 Debian-exim 5 IPv4 336956 TCP=*:smtp (LISTEN)
ssh 4997 root 3u IPv4 12373 TCP=*:ssh (LISTEN)
```

As in the output of netstat shown early, this output is truncated for brevity's sake. This example shows two types of connections. The first non-header line, which begins with ssh, shows an connection from ness.rodbooks.com (the system on which the command was sent) to the ssh port on seeker.rodbooks.com. Such connections are identified by the existence of two hosts in the NAME column and by the keyword ESTABLISHED in the same column. The next two lines, which begin with exim and ssh, show two servers that are listening for connections on the smtp and ssh ports, respectively. These lines are identified by the fact that the NAME column takes the form *:service (LISTEN), where service is the service name or port number. Other columns in the output provide additional information, such as the PID and username associated with the port access.

> If you use lsof -i as an ordinary user, you'll see only your own network connections; then, in order for this command to be a useful diagnostic for your security, you must run it out.
