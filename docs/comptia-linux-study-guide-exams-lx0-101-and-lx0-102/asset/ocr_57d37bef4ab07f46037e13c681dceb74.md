In the majority of cases, you won't need to use the TZ environment variable. It can be useful, in the event that you're using a computer remotely—say, if you're logging into a work computer that is physically located in San Francisco while you're traveling to London. TZ will enable programs that use this variable to display the correct date and time in London, despite the fact that the computer's global time is (presumably) for San Francisco.

In practice the might use TZ for a single login is to issue a command like the following:

```
$ TZ=:/usr/share/zoneinfo/Europe/London
```

This example sets the time zone to London for a single session but from the shell you type this command. You can add this command to a user startup script if you want it to regulate. You should not use this if all a computer's programs should use the target time zone; instead, set it by adjusting the /etc/localtime file, as described earlier in "Setting a Linux Computer's Time Zone."

# Querying and Setting Your Locale

To localize your locale, you must first understand what a locale is in Linux parlance. Once you understand the basics, you can identify your current locale and other locales available to you. If necessary, you may need to install another locale's data. You can then set your computer to use that locale.

# What Is a Locale?

In Linux, a locale is a way of specifying the computer's (or user's) language, country, and related information for customizing displays. A single locale takes the following:

```
[language_..territory][[.codet][@modifier]]
```

Each part of this string has a set of specific acceptable forms. For instance, language can be en (English), fr (French), ja (Japanese). These are two or three-letter codes for languages.

The territory can be US (United States), FR (France), JP (Japan), and so on. These are codes for specific regions—generally nations.
