In an ideal world, any RPM package will install and run on any RPM-based distribution that uses an appropriate CPU. Unfortunately, compatibility issues can grow up from time, introducing the following:

- Distributions use different versions of RPM utilities. This problem can completely prevent an RPM from one distribution from being used on another.
- An RPM package for one distribution may have dependencies that are unmet in another. A package may require a newer version of a library than is present on the distribution. This problem can usually be overcome by installing or upgrading the package, but sometimes the underlying source code also needs.
- An RPM package may be built on a package of a particular name, such as samba-client depending on samba—but if you're using has named the package differently, the RPM utility will object. You can override this by using the --nodeps switch, but the package won't work once installed.
- Even when a dependency appears to be, different distributions include slightly different files in their packages. For this reason, a package for one distribution may not run correctly when installed on another. Sometimes installing an additional package fix this.
- Some programs include distribution-specific scripts or configuration files. This is particularly acute for servers, which may include startup scripts in /etc/rc.d/ or elsewhere. Overcoming this problem usually requires you to remove the offending package after installing and starting the server. In most cases, it's best to use the RPMs intended for your distribution. RPM managers, such as Yum, can simplify locating and installing packages. Mixing and matching RPMs from different distributions usually works well for most programs. This particularly true if the distributions are closely related or rebuild from a source RPM. If you have trouble with an RPM, though, you may well try to find an equivalent package that was built with your distribution in mind.

## rpm Command Set

The main RPM utility program is known as rpm. Use this program to install or upgrade a package at the prompt. The rpm command has the following syntax:

```bash
rpm [operation][options] [package-names]
```

Table 2.1 summarizes the most rpm operations, and Table 2.2 summarizes the most important operations. Be aware, however, rpm is a complex tool, so this listing is necessarily incomplete. For information about operations and options more obscure than those listed in Table 2.1 and 2.2, see the man pages for rpm. Many of rpm's less-used features are devoted to the creation of RPM packages by software developers.

### 2.1 Common rpm operations

| Operation | Description |
| :--- | :--- |
| -i | Installs a package; system must not contain a package of the same name |
| -U | Installs a new package or upgrades an existing one |
| -F or --freshen | Upgrades a package only if an earlier version already exists |
| -q | Queries a package--finds whether a package is installed, files it contains, and so on |
| -V or --verify | Verifies package--checks that its files are present and unchanged since installation |
| -e | Uninstalls a package |
| -b | Builds a binary package, given source code and configuration files; moved to the rpmbuild program with RPM version 4.2 |
| --rebuild | Builds a binary package, given a source RPM file; moved to the rpmbuild program with RPM version 4.2 |
| --rebuilddb | Rebuilds the RPM database to fix errors |

### 2.2 Most-important rpm options

| Option | Used with operations | Description |
| :--- | :--- | :--- |
| --root dir | Any | Modifies the Linux system having a root directory located at dir. This option can be used to maintain one Linux installation discrete from another one (say, OS installation or emergency maintenance). |
| --force | -i, -U, -F | Forces installation of a package even when it means overwriting files or packages. |
| -h or --hash | -i, -U, -F | Displays a series of hash marks (#) to indicate the progress of the operation. |
| -v | -i, -U, -F | Used in conjunction with the -h option to produce a uniform number of hash marks for each package. |
| --nodeps | -i, -U, -F, -e | Specifies that no dependency checks be performed. Installs or removes the package if it relies on a package or file that's not present or is required by a package that's not being uninstalled. |
| --test | -i, -U, -F | Checks for dependencies, conflicts, and other problems without actually installing the package. |
| --prefix path | -i, -U, -F | Sets the installation directory to path (works only for some packages). |
| -a or --all | -q, -V | Queries all packages. |
| -f or --file | -q, -V | Queries the file. |
| -p or package-file | -q | Queries the package. |
| -i | -q | Displays the package information. |
| -l or --list | -q | Displays the files in the package. |

## Using RPM

To use rpm, you combine one operation with more options. In most cases, the -U operation is generally the most useful because it enables you install the package without manually uninstalling the old one. This one-step operation is particularly helpful when packages contain many dependencies; rpm detects these and can perform the operation should the new package fill the dependencies provided by the old.

To use rpm to install or upgrade a package, issue a command similar to this:

```bash
rpm -Uvh samba-3.6.5-86.fc17.x86_64.rpm
```

You can also use rpm -Uvh in place of rpm -U if you don't already have a samba package installed.
