
磁盘格式化（word formatting）的定义有些模糊。它可以指低格式化，即在磁盘介质上创建扇区和磁道的结构；也可以指高格式化，即创建一个文件系统。硬盘在工厂时已经经过了低格式化，通常永远不需要再次进行低格式化。然而，软盘既可以进行低格式化也可以进行高格式化。这里描述的工具可以对软盘和硬盘进行高格式化。要对软盘进行低格式化，你必须使用 `fd` 命令，例如 `fdformat /dev/fd0`。此命令不能用于硬盘。

## 常见文件系统类型

Linux 支持多种不同的文件系统，包括 Linux 原生的以及为其他操作系统设计的系统。其中一些后者的系统可以在 Linux 下运行，即使它们并不支持 Linux 对原生文件系统所期望的所有功能。在准备 Linux 系统时，你将使用一个或多个原生文件系统来处理大部分或所有分区：

**Ext2 第二代扩展文件系统 (ext2fs 或 ext2)** 是传统的 Linux 原生文件系统。它是为 Linux 创建的，在 20 世纪 90 年代后期一直是主导的文件系统。Ext2fs 以可靠的文件系统而闻名。此后它被其他文件系统取代，但它仍然有其用处。特别是，如果你选择使用 /boot 分区，ext2 可以是一个不错的选择，对于较小的（1GB 以下的）可移动式磁盘也是如此。在较小的分区上，ext2 的限制可能会成为真实问题。不带日志的 ext2 稍后会有更详细的描述。ext2 文件系统类型为 ext2。

**Ext3 第三代扩展文件系统 (ext3fs 或 ext3)** 基本上是一个与 ext2 一样可靠的文件系统，但它从断电和系统崩溃中恢复得更快。ext3 文件系统类型为 ext3。

**Ext4 第四代扩展文件系统 (ext4fs 或 ext4)** 是该文件系统的下一代。它增加了处理超大磁盘（超过 1TB）和超大文件（超过 GB）的能力，并添加了用于提高性能的扩展。它的文件系统类型为 ext4。

**ReiserFS** 该文件系统从零开始被设计为 Linux 的日志文件系统。它特别擅长处理大量的小文件（例如，小于 32KB 的文件）。因为 ReiserFS 使用各种技巧将文件的末端挤入未使用的空间中，当文件较小时，这些节省的空间可以累积成文件大小很大比例。你可以使用 reiserfs 作为此文件系统的类型。

## 创建分区和文件系统

从 Linux 内核 3.6 开始，ReiserFS 是当前的标准。一个名为 Reiser4 的从零重写的版本正在开发中，尽管开发速度已经放缓到人们不确定 Reiser4 是否会被包含在主内核。

**JFS** IBM 为其 AIX 操作系统开发了日志文件系统 JFS，其 OS/2 版本随后被捐赠给了 Linux。JFS 是一个技术上复杂的日志文件系统，如果你熟悉 AIX 或想在双启动系统上使用高级文件系统，那么你可能对它感兴趣。正如你预期的那样，该文件系统的类型是 jfs。

**XFS** 硅图形 (SGI) 为其 IRIX 操作系统创建了扩展文件系统 XFS，像 IBM 一样，后来也被捐赠给了 Linux。和 JFS 一样，XFS 是一个技术上非常复杂的文件系统。XFS 在 IRIX 上以健壮、快速和灵活性闻名，但某些在 IRIX 上可以实现的特性在 Linux 下并不受支持。使用 xfs 作为此文件系统的类型。

**Btrfs** 该文件系统（读作 "butter fs" 或 "bee tree fs"）是一种受 Sun ZFS（Z 文件系统）启发的高级文件系统。和 ext4 一样，Btrfs 是一个高性能系统，能够处理非常大的磁盘和文件。从 3.6.0 内核开始，Btrfs 被认为是实验性的；然而，它的高级特性使其成为流行文件系统的可能继任者。

在实践中，大多数管理员创建 ext3、ext4 或 ReiserFS 作为主文件系统；JFS 和 XFS 运行良好，某些管理员更倾向于使用它们，特别在大磁盘上。Ext4 也能处理大文件。关于每个文件系统优缺点的硬性数据很难获得，即使存在这些，人们也怀疑文件系统的性能与许多其他因素相互作用。例如，正如前面提到的，ReiserFS 可以比其他文件系统在较小空间内挤入更多小文件，但如果你存储的大都是大文件，这个优势就并不重要。

如果你使用的是 x86 或非 x86-64 平台，务必检查该平台上的文件系统开发情况。文件系统在某个 CPU 上可能快速且可靠，但在另一个 CPU 上可能缓慢且不可靠。

除了这些 Linux 原生文件系统外，你可能经常需要处理其他系统，包括以下：

**FAT** 文件分配表 (FAT) 文件系统旧而原始——但无处不在。它是 DOS 和 Windows 9x/Me 支持的唯一硬盘格式。由于此原因，每个主流操作系统都理解 FAT，使其成为在移动磁盘上交换数据的极佳文件系统。FAT 有两个正交变体：大小不同（12、16 位或 32 位指针），并且支持长文件名（Linux 会自动检测 FAT 大小，你不需要担心这个）。要使用限制为字符的原始 FAT，使用 Linux 文件类型 mdos。要使用 Windows 风格的长文件名，使用文件类型 vfat。

**NTFS** 新技术系统 (NTFS) 是 Windows NT/2000/XP/Vista 的常用文件系统。遗憾的是，Linux 对它的支持非常原始。从 2.6.x 系列开始，Linux 可以可靠读取 NTFS 并覆盖现有文件，但 Linux 内核无法向 NTFS 分区写入文件。

**HFS 和 HFS+** Apple长期在其 Mac OS 中使用分级文件系统 (HFS)，Linux 提供了读写支持。这不像 FAT 那么可靠，因此在与 Mac 用户交换文件时你可能希望 FAT。Apple 扩展了 HFS 以支持大磁盘，即 HFS+。
