# Appendix A - Answers to Review Questions

11. B. Yum uses files in the /etc/yum.repos d directory to locate its repositories, so you can add to the repository list by adding to this subdirectory, option B specifies, typically by installing an RPM or by adding a file manually. Option A describes a method of adding a repository to a computer that uses APT. Option C's add-repository subcommand is fictitious. Although the /etc/yum.conf file described in options D and E is, it doesn't store repository data.

12. B. The /etc/ld.so.conf file holds the global path, so editing it is the preferred approach. You must then ldconfig to have the system update its library path. Option B is correct. Although you can add a directory to the library path by altering the LD_LIBRARY_PATH environment variable, as in option A, this approach isn't the preferred one, so option is correct. Option C won't work. Option D won't work, although linking individual library files would. This method isn't the preferred one for a whole directory, The ldd displays information on libraries by executable files, so option E won't have the desired effect.

13. D. Libraries are selected by programmers, not by users or system administrators. If you don't like the widgets provided by one library, you have few options, and option D is correct (Many widget provide a great deal of configurability, so you may be able to work around the problem in other ways). Options A, B, and E describe fictitious options to ldconfig, rpm, dpkg, and the kernel. Option C won't work; Qt-using programs would crash when they found GTK libraries in place of the Qt libraries they were expecting.

14. D. The kill11 command accepts values in numeric or named form 9 (in this example) along with process ID number (1128 in this example). Signal 9 corresponds to SIGKILL, which is an extreme way to kill processes that cannot run. Thus, option D describes the effect of this command. Although you might use kill11 to kill network processes, you cannot it so option A is incorrect. The program won't display information about the number of processes that have been killed, making option B correct. To do as C suggests, you'd need to tell kill11 to SIGHUP (signal 1), so the command would be kill11 -1 1128, and option C is incorrect. The kill11 command can't change the property of a process, so option E is correct.

15. C. The top utility displays a dynamic list of processes ordered according to their CPU use along with additional system information, including load averages, so option C is correct. If you want only the average at a specific moment, uptime (option D) may be better because it presents extraneous information—it shows the current time, the time since the system was booted, the number of active users, and load averages. Option A's ld has nothing to do with displaying load averages (it's a programming tool that links process modules into an executable program). There are no standard Linux programs called load (option B) or Ia (option A).

16. A. The --forest option to ps parent-child relationships creating visual links between process names in the ps output, making option A correct (Listing 2.4 shows this effect.) Options B and C are both valid, but neither created the specified effect. Option D describes a fictitious ps option. Since options B, C, and D are incorrect, option E is also necessarily incorrect.
