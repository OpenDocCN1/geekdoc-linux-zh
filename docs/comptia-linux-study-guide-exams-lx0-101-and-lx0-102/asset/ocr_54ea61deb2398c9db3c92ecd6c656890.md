In XFS, the xfs_admin command is the equivalent of tune2fs. Some options you may want to adjust the following:

**Use Version 2 Journal Format** The -j option enables version 2 (journal) format, which can improve performance in some situations.

**Obtain the Filesystem Label and UUID** You can use the -l and -u options to obtain the filesystem's name (label) and unique identifier (UUID), respectively. The name is seldom used in Linux but can be used in some cases. The UUID is a long code that is increasingly used by distributions to specify a filesystem to mount, as described in "Permanently Maintaining Filesystems."

The blkid command can display the label and UUID of any partition's filesystem, not just an XFS partition.

![](bbox=[0.143, 0.373, 0.213, 0.413])

**Set the Filesystem Label and UUID** You can change the filesystem's label or UUID using the -l label or -u option, respectively. The label is at most 12 characters in length. Normally you use the -u option to set the UUID to a known value (such as the UUID used prior to it being reformatted); or you can use generate as uuid to have xfs_admin create a new UUID. You should not set the UUID to a value that's in another partition!

In xfs, xfs_admin might look something like this:

```
# xfs_admin -L av_data /dev/sda
writing all S8s
new label = "av_data"
```

This example sets the name of the filesystem on /dev/sda7 to av_data. As with tune2fs, xfs_admin should be used only on unmounted filesystems.

# Interactively Debugging a Filesystem

In addition to reviewing and changing filesystem flags using dumpefs and tune2fs, you can provide the attributes of dumpefs, tune2fs, and any of Linux's normal file-manipulation tools that rolled into one. Use the program, its name followed by the device filename corresponding to the filesystem you want to manipulate. You'll see the debugfs prompt:

```
# debugfs /dev/sda1
debugfs:
```
