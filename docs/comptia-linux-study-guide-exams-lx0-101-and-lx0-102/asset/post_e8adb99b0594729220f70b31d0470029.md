**Misconfiguration** Poor configuration of an email server can cause problems. Email servers are not designed to provide login access, as they are unlikely to be abusable to gain login access. Instead, the risk is a configuration that will make your system a menace to the Internet. The most common misconfiguration of this nature is an open relay, which is a computer that will mail from any computer to any other. In the past, hackers made use of open relays as a way to hide their true identities; nonetheless, some still abuse open relays. To guard against bugs, you should ensure that your server is updated to the latest version. Chapter 2 describes management. Major Linux distributions configure their email servers so they do not open relays; however, a misconfiguration can open your server. Various sites provide tests for such misconfigurations. Check http://www.abuse.net/relay.html or http://spamhelp.org/openrelay/ to verify that your server is not an open relay. These sites, like others, run a series of tests. If your server is properly configured, it will report that it is unable to connect or that it was unable to relay. If your server is able to relay, though, you'll need to learn more to configure your server. The steps vary from one server to another, and they require relatively advanced configuration, which is beyond the scope of this book. You can learn about closing open relays in your server's documentation.

## Managing Data with SQL

The Structured Query Language (SQL), as its name suggests, is a language used for retrieving data from a database. In practice, SQL is implemented in several database products. Thus, you should know a little about the principles of SQL use and move on to actual storage and retrieval. There is a distinction that is marked between a network protocol (such as SMTP) and the servers that implement it (such as sendmail, Postfix, and Exim). In principle, you can use any SQL package to satisfy your database needs. Some common choices in Linux include:

## Picking a SQL Package

- MySQL owns this SQL implementation, which has been released under the GPL. For a complete installation, you'll probably need to install a client, a server, and perhaps development tools. You can learn more at http://www.mysql.com.
- PostgreSQL This SQL implementation evolved from the earlier Postgres software (the name PostgreSQL is a compressed format of Postgres). It's available under the BSD license and is available as multiple packages in Linux distributions. With MySQL, you'll most likely have to install a client, a server, and additional support. PostgreSQL is headquartered at http://www.postgresql.org.
- SQLite This package, based at http://www.sqlite.org, is a library that implements SQL. As it's not a stand-alone database; it's intended as a way to provide programs with a way to store data using a SQL interface. If you install a program that uses SQLite, your distribution's package manager should install the relevant libraries for you. If you want a a program that requires database access and don't want to install a complete client-server package such as MySQL or PostgreSQL, SQLite may be just what you need.

There are many SQL database products for Linux. For the purpose of learning, MySQL or PostgreSQL should do fine, or you can use another implementation if you prefer. If you have a specific purpose in mind for using SQL, though you should research SQL packages in detail. You may need a particular package for compatibility with other software, or you may need a SQL package that provides specific features. As just noted, some SQL packages, including MySQL and PostgreSQL, operate on a client-server model: One program (the server) manages the database, while another (the client) provides users and programs with access to the database. Such implementations work over a network, enabling users at multiple client systems to access a centralized database server.
