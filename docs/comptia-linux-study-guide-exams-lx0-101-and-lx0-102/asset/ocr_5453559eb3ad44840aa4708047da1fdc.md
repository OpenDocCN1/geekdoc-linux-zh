# Using System Log Files

Record logger PID The -i option returns the process ID (PID) of the logger process
along with other data.

Output to Standard Error You can echo data to standard error, as well as to the log
file, by the -s option. An interactive script might use this feature to alert users to
problems.

Log Using Datagrams The -d option causes logger to use datagrams rather than a stream
connection to the system socket. This is an advanced feature that you should use
only if you're instructed to do so in documentation or if you understand the networking
issues.

Log a File You can log contents of a file using the -f option. Be cautious with
this option; if file is big, your system log file can grow to ridiculous size!

Identify a Priority The -p pri option specifies a priority, as described earlier.

By default, logger includes its name in the log file as a tag. You can change this
with the -t tag option. This is useful if you want to identify a script or program that
created the log entry and doesn't record the fact that logger was involved in the process.

Specify a Socket Ordinarily, logger calls the system log tools to do its job. You
can log directly to a network socket using the -u socket if you prefer.

Specify a Message If you don't specify a file using -f file, logger will log whatever
type other options as the message to be logged. If you don't provide a message on the
command line, logger accepts your input on subsequent lines as information to be
logged. You should terminate input by pressing Ctrl+D.

As an example, suppose you want to log the message "shutting down for system maine-nance" to the system log. You can do so by typing the following command:

```
$ shutting down for system maintenance
```

The result will be an entry like the following, probably in /var/log/messages:

```
Jul 29 14:09:50 nessus logger: shutting down for system maintenance
```

Parameters changes the details of what gets logged, as described. You can place
a call to logger in a script as a way of documenting the script's activities. For instance, a
system backup script might use logger to record details as its start and stop times and
the number and size of the files it has backed up.

# Rotating Log Files

Log files are to retain information about system activities for a reasonable period
of time, but system logging daemons provide means to control the size of log files. Left
unchecked, log files can grow to consume all the available space on the partition
on which they reside. To avoid this, Linux employs log file rotation tools. These
tools rename and optionally compress the current log files, delete old log files, and force the
logging system to begin using new log files.
