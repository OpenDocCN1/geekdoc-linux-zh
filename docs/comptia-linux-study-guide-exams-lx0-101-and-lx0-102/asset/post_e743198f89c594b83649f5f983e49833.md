
## Using File Management Commands

I recommend restricting non-alphanumeric symbols to the dot (.), the dash (-), and the underscore (_). Some programs create backup files that use the tilde (~), as well. Although Linux filenames can contain spaces, and although such filenames are common in some OSs, they must be escaped in the Linux command line by preceding the space with a backslash (\) or by enclosing the entire filename in quotes ("). This requirement makes a bit awkward in Linux, so most Linux users substitute dashes or underscores.

A few characters have special meaning and should never be used in filenames. These include the asterisk (*), the question mark (?), the forward slash (/), the backslash (\), and the quotation mark ("). Although you can create files that contain all of these characters except for the forward slash (which serves to separate directory elements) by escaping them, they're likely to cause confusion with other symbols.

Linux filename length depends on the filesystem. In use ext2fs, ext3fs, ext4fs, ReiserFS, XFS and many others limit 255 characters. If you've used DOS, you're probably familiar with the 8.3 filename limit: DOS filenames are restricted to eight characters with an optional three-character extension. These two components are separated by a dot. One-to-four-character extensions are common in Linux, Linux filenames can contain an arbitrary number of dots. In fact, filenames can begin with a dot. So-called files are hidden from most utilities that display files, they're popular for storing configuration files in your home directory.

> If you access a File Allocation Table (FAT) filesystem on a removable disk or partition used by DOS, you can do so using either of two filesystem codes: mdos, which limits you to 8.3 filenames; or vfat, which supports Windows-style long filenames. In addition, the umdos filesystem type code is a Linux-only extension that supported Linux-style long filenames. UDOS support was discontinued after the 2.6.11 kernel.

Two filenames are particularly special. A filename that consists of a single dot (.) refers to the current directory, whereas a filename that consists of a double dot (..) refers to the parent directory. For instance, if your current directory is /home/jerry, then .. refers to that directory and .. refers to /home.

One critical difference between Linux filenames and many other OSs is that Linux treats filenames in a case-sensitive way: in other words, Filename.txt is different from filename.txt or FILENAME.TXT. All three can exist in a single directory. Under Windows, although Windows 95 and later retain the cache of the filename, they ignore it when refer to an existing file, and they don't permit files whose names differ only in case to-exist in a single directory. This difference isn't a major problem for people who migrate from Windows to Linux, but you should be aware of it. It can also cause problems when you try to read a FAT disk using the Linux vfat driver because Linux has to follow the Windows rules when managing files on that disk.

## Chapter 4 • Managing Files

You can use wildcards with many commands. A wildcard is a symbol or set of symbols that stands for other characters. Three classes of wildcards are common in Linux:

- A question mark (?) stands for a single character. For instance, b??k matches book, balk, buck, or any other four-character filename with b and ends with k.
- An asterisk (*) matches any character or set of characters, including no character. For instance, b*k matches book, balk, buck, and just as b??k. b*k matches matches, bbk, and backtrack.
- **Bracketed Values** enclosed in square brackets ([]) normally match any character in the set. For instance, b[ao] matches balk but not back or back. It's also possible to specify a range of values; for instance, b[a-z] matches back, buck, and other four-letter filenames whose second character is a lowercase letter. This differs from b—Linux treats filenames in a case-sensitive way and matches any character (not just lowercase letter), b[a-z] doesn't match bB or b3ck, although b9ck matches both of these filenames.

Wildcards are implemented in the shell and passed to the command you call. For instance, if you type `ls b??k`, and that wildcard matches the three files balk, book, and buck, the result is precisely as if you'd typed `ls balk book buck`. The process of wildcard expansion is known as file globbing or simply globbing.

## File Commands

A few-manipulation commands are extremely important to everyday file operations. These commands enable you to list, copy, move, rename, and delete files.

## The ls Command

To manipulate files, it's helpful to know what they are. This is the job of the ls command, whose name is short for list. The ls command displays the names of files in a directory. Its syntax is simple:

```
ls [options] [files]
```

The command supports a huge number of options; consult ls’s man page for details. The most useful options include the following:

## Using File Management Commands

**Display All Files** Normally, ls omits files whose names begin with a dot. Adding -a displays these.

**Color Listing** The --color option produces output in color.

**Directory Names** Normally, if you use -d, ls displays only the directory itself.

**Long Listing** The -l option includes information such as permissions, owner, size, and date.

**Display File Type** The -F option appends a character to the end of each name to indicate its type:
- / Directory
- @ Symbolic link
- = Socket
- | Pipe

**Recursive Listing** The -R option allows ls to list subdirectories recursively.

```
$ ls -1 *
-rwxr-xr-x 1 root users       111 Apr 11 13:48  test
-rw-rr-- 1 root users    176322 Dec 16 09:34  thttp-2.20.rpm
-rw-rr-- 1 root users    1838045 Apr 24 18:52  tomsbr-1.7.269.tar.gz
-rw-rr-- 1 root users    3265021 Apr 22 23:46  tripwire.rpm
```

This output includes the permission strings, ownership, file sizes, and file creation dates. This example also illustrates the use of the * wildcard, which matches anything—thus, * matches any filename.

> You can combine multiple options by merging them with a single dash, as in -1F to get a listing that includes file type.

## The cp Command

The cp command copies a file. Its basic syntax is as follows:

```
cp [options] destination
```

The source is normally one or more files, and the destination may be a file (when the source is a single file) or a directory (when the source is one or more). When copying to a directory, cp preserves the original filename; otherwise, it gives the new filename indicated by destination. The command supports a large number of options; see man page for more. Some of the useful options enable you to modify the command's operation in helpful ways:

- Force Overwrite The -f --force option forces the system to overwrite any existing files without prompting.
- Use Interactive Mode The -i or --interactive option causes cp to ask you before overw any existing files.
- Preserve Ownership and Permissions The -p or --preserve option preserves ownership and permissions, if possible.
- Perform a Recursive Copy If you use the -R or --recursive option and specify a directory, the entire directory, including its subdirectories, is copied.
