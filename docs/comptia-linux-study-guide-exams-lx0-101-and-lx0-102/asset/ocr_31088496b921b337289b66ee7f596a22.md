# Chapter 1 • Exploring Linux Command-Line Tools

**Transpose Text** Ctrl+T transposes the character before the cursor with the character under the cursor. Pressing Esc and T transposes the two words immediately before (or under) the cursor.

**Change Case** Pressing Esc and U converts text from the end of the word to uppercase. Pressing Esc and C converts text from the cursor to the end of the word to lowercase. Pressing Esc and C converts the letter under the cursor (or the first letter of the next word) to uppercase, leaving the rest of the word unaltered.

**Invoke an Editor** You can launch a full-fledged editor to edit a command by pressing Ctrl+X followed by Ctrl+E. The shell assists to launch the editor defined by $FCEDIT or $EDITOR environment variable or Emacs as a resort.

These editing commands are the most useful ones supported by bash; consult its manual to learn about more obscure editing features. In practice, you're likely to make heavy use of command and filename completion, the command history, and perhaps a few features.

> If you prefer the Vi editor to Emacs, you can use a Vi-like mode in bash by typing set -o vi (Vi is described in Chapter 5, "Booting Linux and Editing Files").

The history command provides an interface to view and manage the history. Typing **history** alone displays all the commands in the history (typically the latest 500 commands); which causes a number only of the latest commands to appear. You can execute a command by number typing an exclamation mark followed by its number, as in !210 to execute command 210. Typing **history -c** clears the history, which can be handy if you've recently typed commands you'd rather not have discovered by others, such as commands that include passwords.

The bash history is stored in the .bash_history file in your home directory. This is an ordinary plain-text file, so you can view it with a text editor or a command such as less (described later, in "Paging Through Files with less").

> Because your bash history is stored in a file, it can be examined by anyone who can read that. Some commands enable you to type passwords or other sensitive data on the same line as the commands themselves, which can be risky. The ~/.bash_history file does not record what you type in other programs, just what you type at the bash prompt itself. Thus, if you have a choice, you should let commands that require passwords or other sensitive data prompt you to enter this as data, rather than enter such as options to the command at the bash prompt.
