
The best possible passwords are random collections of letters, digits, and punctuation. Unfortunately, passwords are difficult to remember. A reasonable compromise is to build a password in two steps:

- 1. Choose a base that's easy to remember but difficult to guess.
- 2. Modify that base in ways that increase the difficulty of guessing the password.

One approach to building a base is to use two unrelated words, such as buy and pen. You can then merge these words (bupen). Another approach, and one that's arguably better than the first, is to use the first letters of a phrase that's meaningful to the user. For instance, the first letters of "yesterday I went to the dentist" become yiwtd. In both cases, the base should not be a word in any language. As a general rule, the longer the password, the better. Older versions of Linux could handle passwords of no more than eight characters, but those limits have been lifted. Modern Linux distributions require passwords to be at least four to six characters in length; the password utility won't accept anything shorter than the distribution's minimum.

With the base, it's time to modify it to create a password. The user should apply at least a couple of possible modifications:

**Adding Numbers and punctuation** One possible modification is to insert random numbers or punctuation in the base. This method might help, for instance, bu3n&6n and y#9wttd. As a general rule, add at least two symbols or numbers.

**Mixing Case** Linux uses case-sensitive passwords to improve security. Applying this rule might help Bu3n&PE and y#19WttD, for instance.

**Reversing Order** A change that's very weak by itself but can add somewhat to security when used in conjunction with the others is to reverse the order of some or all letters. You might apply this to one word of a two-word base. This could yield Bu3n&EP and Dtt9wi#, for instance.

**Growing the Haystack** A would-be-attacker of discovering a password has been like needing a needle in a haystack. In password terms, this means making a password harder is to increase the size of the haystack. You can do this by using longer words or phrases, but this can make a password harder to remember and type. Even an increase in size that repeats a single character can be helpful. Thus, you might put passwords into Bu3n&Eiiiiiiiiii Dtt:::::W9iy.

Your best tool for getting users to pick passwords is to educate them. If that passwords can be guessed by malicious individuals who know them or even who target them and use personal information in telephone books, on Web pages, and so. Tell them that although Linux encrypts its passwords internally, programs exist that feed dictionary entries using Linux's encryption algorithms for comparison to encrypted passwords. If a match is found, the cracker has found the password. Therefore, using a password that's not in a dictionary, and isn't a simple variant of a dictionary improves security substantially. Tell your users that their accounts might be used as a first step compromising the entire computer or as a launching point for attacks.

## Administering Local Security

Explain to users that they should never reveal their passwords to others, even people claiming to be system administrators—this is a common scam, real system administrators don't need users' passwords. You should also warn them not to use the same password on multiple systems because doing so turns a compromised account on one system into a compromised account on all the systems. Telling your users these things will help them understand the reasons for your concern, and it's likely to help motivate at least some of them to pick good passwords.

If your users are concerned after being told these things (and in any large installation, some will be), you have to rely on the checks possible in passwd. Most distributions' implementations of this utility require a minimum password length (typically up to four characters). They usually check the password against a dictionary, thus weeding out some of the absolute worst passwords. Some require that a password contain least one or two digits or punctuation.

Another password security issue is password changes. Frequently changing passwords minimizes the window of opportunity for crackers to do damage; if a cracker obtains a password but it changes before the cracker can further damage using the compromised account), the password change has averted disaster. As described shortly, you can configure an account will stop accepting logins after time the password is approaching. (You can configure the system to warn users when their time is approaching.) This is a very good option to enable on sensitive systems or those with many users. Don't expire the time too low, if users have to change their passwords too frequently, they will probably just switch between a couple of passwords or pick poor ones. Precisely what "too low" a password change time depends on the environment. For some systems, six months is preferable.

## Tools for Managing Passwords

Most Linux distributions use passwords by default, and for the most part, this chapter is written with the assumption that this feature is active. In addition to providing extra security by moving passwords out of the world-readable /etc/passwd and into more secure /etc/shadow file, shadow passwords add extra account information.

### Limiting root Access

Because root can do anything on a Linux computer, this access must be limited. In a system with a single administrator, this can be accomplished by having the administrator set a root password that everyone knows. This user can then log directly as root or use su to acquire root privileges. The su commands stands for switch user, and it's used to change a user's identity. Typing su also results in a prompt for the root password. If the user types password correctly, the session becomes a root session. You can also type a username after su to acquire that user's privileges. When root does, no password is required. (This is sometimes for investigating problems reported by a single user.) Use -c to specify the program name, as in su -c 'lsof -i' to run lsof -i as root.

Logging directly as root is generally discouraged for several reasons: No record of who typed the password appear in logs; the root password can be intercepted in various ways; and if the user leaves the terminal, a passerby can hijack the computer. Using su is somewhat better than a direct login from a security point of view, because use of su generally leaves a trace in system logs of who became root.

A method of acquiring root access that is somewhat more secure than either direct logins or is sudo. This program runs a single command as root; for instance, to run lsof -i as root, you type

```
$ sudo lsof -i
```

In this example, the computer prompts for the user's (georg's) password, not for the root password. The idea behind sudo is that you first configure the computer to accept certain users as sudo users. Those users may use their own password to perform superuser tasks, even if they don't have the root password. (Some sudo configurations require users to enter the superuser password rather than their own password, though.) You can also fine-tune what tasks users may perform. This is done via the /etc/sudoers configuration file. You must edit this configuration file vis sudo, which is a variant of Vi (described in Chapter 5) that's only used to edit /etc/sudoers.
