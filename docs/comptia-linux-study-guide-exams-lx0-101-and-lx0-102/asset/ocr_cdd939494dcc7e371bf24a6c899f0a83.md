# Boot Loader Principles

In one way or another, your computer's firmware reads the boot loader into memory from the hard disk and executes it. The boot loader, in turn, is responsible for loading the Linux kernel into memory and starting it. Thus, configuring a hard disk (or at least your boot disk) is not complete until the boot loader is configured. Although Linux distributions provide semi-automated methods of configuring a boot loader during system installation, you may need to know more, particularly if you recompile your kernel or need to set up an advanced configuration—say, one to select between several OS.

The although example might interest you only the Basic Input/Output System (BIOS) firmware, beginning in 2011 the Extensible Firmware Interface (EFI) and its Unified EFI (UEFI) variant have becoming increasingly important. Thus, I describe the principles upon which BIOS and EFI computers' boot loaders are.

# BIOS Boot Loader Principles

The boot process can be a bit convoluted, in part because so many options are available. Figure 5.1 depicts a typical configuration, showing a couple of possible paths. In both cases, the boot process begins with the BIOS. As described in Chapter 3, "Configuring Hardware," you tell the BIOS which boot device to use—a hard disk, a floppy disk, a CD-ROM drive, or something else. Assuming you pick a hard disk as the primary boot device (or if higher-priority devices are bootable), the BIOS loads code from the Master Boot Record (MBR), which is the first sector on the hard disk. This code is the primary boot loader. In theory, it could be about anything, even a complete (if tiny) OS.
