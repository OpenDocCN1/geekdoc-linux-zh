# Chapter 5 • Booting Linux and Editing Files

Both Upstart and systemd provide runlevel commands for compatibility with SysV.
Alternatives do not technically use runlevels, though, the information is a sort of
"translation" of what the startup system is using SysV terms.

# Changing Runlevels on a Running System

Sometimes you might want to change runlevels on a running system. You might do this to get
more services, such as going from a console to a graphical login runlevel, or to shut down
reboot your computer. This can be accomplished with the init (or telinit), shutdown,
halt, reboot, and poweroff commands.

# Changing Runlevels with init and telinit

The init process is the first process run by the kernel, but you can also use it to have
system read the /etc/inittab file and implement changes it finds there or change
a new runlevel. The simplest case is to have change to the runlevel you specify.
instance, to change to runlevel 1 (the runlevel reserved for single-user or maintenance mode),
you would type this command:

```
# init 1
```

To reboot the system, you can use init to change to runlevel 6 (the runlevel reserved for
reboots);

```
# init 6
```

A variant of init is telinit. This program can take a runlevel number just like init to
change to that runlevel, but it can also take the Q or q option to have the tool reread /etc/
inittab and implement any changes it finds there. Though, if you've made a change to the run-
level in /etc/inittab, you can immediately change that by typing telinit q.

> NOTE The pages for these commands indicate slightly different syntaxes;
but telinit is a symbolic link to init, and in practice init
ponds like telinit to the Q and q options.

The Upstart and systemd tools provide init and telinit commands that work much as
they do on SysV-based computers.
