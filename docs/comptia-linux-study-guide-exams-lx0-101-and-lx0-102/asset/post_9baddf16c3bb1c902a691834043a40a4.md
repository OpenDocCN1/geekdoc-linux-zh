# Obtaining a Word Count with wc

The wc command produces a word count (that's what gets its name), as well as line and byte counts, for a file:

```
$ wc file.txt
```

```
308 2343 15534 file.txt
```

This file contains 308 lines (or, more precisely, 308 characters); 2,343 words; and 15,534 bytes. You can limit the output to the newline count, the word count, the byte count, or a character count with --lines (-l), --words (-w), --bytes (-c), or --chars (-m) option, respectively. You can also limit the maximum line length with the --max-line-length (-L) option.

# Using Regular Expressions

> **NOTE**
> For an ordinary ASCII file, the character and byte counts will be identical. These values may diverge for files that use multi-byte character encodings.

Many Linux programs employ regular expressions, which are tools for describing or matching patterns in text. Regular expressions are similar in principle to the wildcards that can be used to specify multiple filenames. At their simplest, regular expressions can be plain text without adornment. Certain characters are used to denote patterns, though. Because of their importance, I describe regular expressions here. I also cover two programs that make heavy use of regular expressions: grep and sed. These programs search for text files and permit editing of files from the command line, respectively.

# Understanding Regular Expressions

Two forms of regular expression are common: basic and extended. Which form you must use depends on the program; some one form or the other, but others can use either type, depending on the options passed to the program. (Some programs use their own minor or major variants on of these classes of regular expression.) The differences between basic and extended regular expressions are complex but, the fundamental principles of both are similar.

The simplest type of regular expression is an alphabetic string, such as Linux or Haddr. These regular expressions match any string of the same size or larger that contains the regular expression. For instance, the Haddr regular expression matches Haddr, This is Haddr, and The Haddr is unknown. The real strength of regular expressions lies in the use of non-alphabetic characters, which activate advanced matching rules:

- **Bracket Expressions** enclosed in square brackets [] constitute bracket expressions, which match any character within the brackets. For instance, the regular expression b[aeiouj] matches the words bag, beg, big, bog, and bug.
- **Range Expressions** A range is a variant on bracket expression. Instead of listing every character, range expressions match the start and end points separated by a dash (-), as in [a-z]. This regular expression matches a2, a3, and a4z.
- **Any Single Character** The dot (.) represents any single character except a newline. In instance, a z matches abz, abb, a0z, or any other three-character string that begins with a and ends with z.
- **Start and End of Line** the caret (^) represents the start of the line, and the dollar sign ($) denotes the end of a line.
- **Repetition Operators** A full or partial regular expression may be followed by a special symbol to denote how many times a matching item must exist. Specifically, an asterisk (*) denotes zero or more occurrences, a plus sign (+) matches one or more occurrences, and a question mark (?) specifies zero or one match. The asterisk is often combined with the dot (in .*) to specify a match with any substring. For instance, A.*Lincoln matches any string that contains A and Lincoln, in that order—Abe Lincoln and Abraham Lincoln are just possible matches.
- **Multiple Possible Strings** The vertical bar (| separates two possible matches; for instance, car|truck matches either car or truck.
- **Parentheses (())** surround subexpressions. Parentheses are often used to specify which operators are to applied; for example, you parenthesis around a group of words that are concatenated with the vertical bar, to ensure that the words are treated as a group, any one of which may match, without involving parts of the regular expression.
- **Escaping** If you want to match any of the special characters, such as a dot, you must escape—that is, precede it with a backslash (\). For instance, to match a computer hostname (say, twain.example.com), you must escape the dots, as in \twain\.example.com.

The preceding descriptions apply to extended regular expressions. Details are different for regular expressions. In particular, the ?, |, (, and ) symbols lose their special meanings. To perform the tasks handled by these characters, some programs, like grep, allow. Whether you use basic or extended regular expressions depends on which program supports. Which you choose is mostly a matter of personal preference.

- Regular expression rules can be confusing, particularly when you're first introduced to them. Some examples of these, in the context of the programs that you use, help. The next couple of sections provide such examples.

# Using grep

The grep command is extremely useful. It searches for files that contain a specified string and returns the name of the file and (if it's a text file) a line of context for that. The basic grep syntax is as follows:

```
grep [options] regex [files]
```

The grep is a regular expression, as described. The grep command supports a large number of options. Some of the common options enable you to modify the way grep searches:

- **Count Matching Lines** Instead of displaying context lines, grep displays the number of lines that match the specified pattern.
- **Specify a Pattern Input** The -f file option takes the specified file rather than from the command line.
- **Ignore Case** You can perform a case-insensitive search, rather than the default case-sensitive search, by using the -i or --ignore-case option.
- **Search Recursive** The -r or --recursive option searches in the specified directory and all subdirectories rather than simply the specified directory.
- **Use Extended Regular Expression** The grep command interprets regexp as a basic expression by default. To use extended expression, you can pass the -E or --extended-regexp option. Alternatively, you can call egrep rather than grep; this variant command uses regular expressions by default.

A simple example of grep uses a regular expression with no components:

```
$ grep -r eth0 /etc/* own```

This example finds all files in /etc that contain the string eth0 (the identifier for the first Ethernet device on most Linux distributions). Because the example includes the -r option, it searches recursively, so files in subdirectories are examined in addition to /etc. For each matching text file, the line that contains the string is printed.

> Some files in /etc can't be read by ordinary users. Thus, if you type this command as a non-root user, you will see some error messages relating grep's inability to open files.

Ramping up a bit, you want to locate all the files in /etc that contain the string eth0 or eth1. You can enter the following command, which uses a bracket expression to specify both devices:

```
$ grep eth[01] /etc/*
```

A more complex example searches all files in /etc that contain the hostname .example.com or bronto.pangeea.edu, and later on the same line, the number 127. This task requires using one of the regular expression features. Using extended regular expression, the command looks like:

```
$ grep -E "twain.example.com|bronto.pangeea\.edu" .*127* /etc/*
```

This command illustrates another feature you may need to use: shell quoting. Because the shell treats characters, such as the vertical bar and the asterisk, for its purposes, you must enclose regular expressions in quotes lest the shell attempt to parse the regular expression and a modified version of what you want to grep.
