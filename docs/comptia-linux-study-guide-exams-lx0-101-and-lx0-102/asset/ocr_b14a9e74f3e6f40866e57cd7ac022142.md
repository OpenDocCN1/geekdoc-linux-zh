# Understanding Command-Line Basics

tcsh This shell is based on the C shell (csh). It's a fairly popular shell in some circles, but no major Linux distributions make it the default shell. Although in many respects, some operational details differ. For instance, you don't assign environment variables in the same way in tcsh as in bash.

csh The Original C shell isn't used on Linux, but if a user is familiar with csh, tcsh makes a good substitute.

ksh The Korn Shell (ksh) was designed to take the best features of the Bourne shell and the C shell and extend them. It has a small but dedicated following among users.

 The file /bin/sh is a symbolic link to the system's default shell—normally /bin/bash for Linux. This enables you to point to a shell, at the start of a simple shell script, as described in Chapter 9, "Writing Scripts, Configuring E-mail, and Using Databases" and ensure that a shell will be called, even if the system's available shells change. This feature is particularly important when developing shell scripts that might be run on other computers, as described in Chapter 9.

# Using a Shell

Linux shell is fairly straightforward for anybody who used a text-mode OS before: You type a command, with possible options to it, and the computer executes the command. For the most part, Linux commands are external—that is, they are separate programs from the shell. A few commands are internal to the shell, though, and knowing the distinction is important. You should also know some of the tricks that can make using the command shell easier—how to have the computer complete a long command or line, retrieve a command you've recently run, or edit a command you've recently used (or haven yet finished).

> One class of commands—those for handling basic file management—is very important but isn't described here in great detail. For more information on these commands, consult Chapter 4, "Managing Files."

# Starting a Shell

If you log into Linux using a text-mode login screen, chances are you'll be dropped directly into your default shell—the shell is what presents the prompt and accepts subsequent commands.
