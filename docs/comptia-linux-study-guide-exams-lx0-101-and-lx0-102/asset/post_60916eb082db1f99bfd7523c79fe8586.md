systems.

Linux for a Linux system.

**Print All Information** The -a or --all option returns all available information.

In practice, you're most likely to use uname -a at the command line to learn some of the
basics about your kernel and system. The other options are useful in multi-platform
scripts, which can use these options to quickly obtain critical information to help them
adjust their actions for the system on which they're running.

## Examining Process Lists

One of the most important tools in process management is ps. This program displays
processes' status (hence the name, ps). It sports many helpful options, and it's useful
in monitoring what is happening on a system. This can be particularly critical when the
computer isn't working as it should—for instance, if it's unusually slow. The ps program
supports an unusual number of options, but just a few of them will take you a long
way. Likewise, interpreting ps output can be tricky because so many options modify the program's output. Some ps-like programs, most notably top, also deserve attention.

## Using ps Options

The official syntax for ps is fairly simple:

```
ps [options]
```

This simplicity of form hides considerable complexity because ps supports three different types of options, as well as many options within each type. The three types of options are as follows:

Unix: These single-character options may be grouped together and are preceded by a single dash (-).

BSD: These single-character options may be grouped together and must not be preceded by a dash (-).

Options that may be grouped together can be clustered without spaces between them. For instance, rather than typing ps -a -f, you can type ps -af. The reason for so much complexity is the ps utility has historically varied from one OS to another. The version of ps that ships with many Linux distributions attempts to implement features from all of its ps versions, so it supports many personalities. However, you can change its behavior by setting the PS_ENVIRONMENT variable to posix, linux, bsd, digit1, or others. The rest of this section describes the ps behavior on most Linux systems.

Some of the useful ps features include the following:

- **Display Help**: The --help option summarizes some of the common ps options.
- **Display All**: By default, ps displays only processes that were run from its own terminal (xterm, text-mode login, or remote login). The -A and -e options cause it to display all processes on the system, and x displays all processes owned by the user who gives the command. The x option increases the amount of information that is displayed about each process.
- **Display One Processes**: You can display processes owned by a user with -u user, U, and --user options. The user variable may be a username or user ID.
- **Display Extra Information**: The -f, -j, l, u, and v options all expand the information provided in the ps output. Most ps output formats include one line per process, but ps can provide enough information that it is impossible to fit it all on an 80-character line. There, these options provide various mixtures of information.
- **Display Hierarchy**: The -H, -f, and --forest options group processes and use indentation to show the family of relationships between processes. These options are useful if you're trying to trace the parentage of a process.
- **Display Wide Output**: The ps command output can be more than 80 columns wide. Normally, ps truncates its output so that it fits on your screen or xterm. The -w and W options tell it not to do this, which can be useful if you direct the output to a file, as in ps w > ps.txt. You can then examine the output file in a text editor that supports wide lines.

You can combine these ps options in many ways to produce the output you want. You'll probably need to experiment to learn which options produce the desired results because each option modifies the output in some way. Even those that would seem to influence just the selection of processes sometimes modify the information that's provided about each process.
