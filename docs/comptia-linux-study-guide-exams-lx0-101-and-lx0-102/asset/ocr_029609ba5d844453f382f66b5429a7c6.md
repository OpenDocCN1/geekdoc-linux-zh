+   3. The udev software creates and manages a dynamic /dev directory tree, adding entries to directory devices that exist on the system, option E is correct. The udev software has nothing to do with software development (option A). It doesn't unload drivers (option B) or load drivers (option C), although it does respond to the loading of drivers by creating entries in /dev. It also doesn't store BIOS configuration options in a file (option D).

+   4. SATA disks are usually handled by Linux's subsystem and are referred to as /dev/sda; however drivers handle these disks if they are PATA disks and so refer to /dev/hdx. Thus, option E is correct, and both options A and C are correct. The /dev/mapper directory holds device files for LVM and RAID configurations, not partition identifiers, option B is correct. Option D (C) is how Windows would likely refer to the first partition on the disk, but Linux doesn't use this type of disk identifier.

+   5. A, C, D. There are no files /proc/ioaddresses or /proc/hardware, so options B and E are both incorrect. All the other files contain useful information; /proc/ holds information about I/O ports, /proc/d holds information about DMA port usage, and /proc/interrupts holds information about IRQs.

+   6. Logical partitions are 5 up, and they reside in an extended partition with a number 1 and 4. Therefore, one of the first two partitions must be an extended partition that holds partitions 5 and 6, making option B correct. Because one of the first two partitions is an extended partition, the other must be a primary partition, and there can be no other of type of partition. This makes option A incorrect. Gaps in the range of partitions 1-4 are normal in MBR disks, contrary to option C. Logical partitions are numbered starting at 5, their numbers won't change if /dev/sda3 is subsequently added, so option D is incorrect. On MBR disks, partitions 1-4 are primary or extended; logical partitions are numbered 5 and up. Thus, option E is incorrect.

+   7. The /etc/fstab file contains the mapping of partitions to mount points, so /etc is an ordinary directory on the root partition, not on a separate partition, making option E correct. A statement that the system won't boot is correct, it is not; /home uses files, not critical system files. Option B and C describe restrictions that don't exist. Option D would be correct if /etc is not a separate partition.

+   8. The /home directory (option D) is frequently placed on its own partition in order to isolate it from the rest of the system and sometimes to enable use of a particular filesystem or filesystem mount options. The /bin and /sbin directories (options A and B) should never be split off the root (/) filesystem because they contain critical executable files
