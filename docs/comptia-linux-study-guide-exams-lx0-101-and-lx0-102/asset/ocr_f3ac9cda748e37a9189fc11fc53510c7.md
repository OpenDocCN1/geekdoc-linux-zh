# Chapter 6 • Configuring the X Window System, Localization, and Printing

Some programs and sets of programs may require you to set the language independent of the overall locale. Thus, you may need to adjust the language for certain programs. If a program doesn't seem to respond to the overall locale setting, check its documentation or browse through its menus to find and adjust its defaults.

One setting requires special attention: LANG=C. When you set LANG to C, programs see this environment variable display output without passing it through locale translations. This can be helpful in some cases if a program's output is being corrupted by the locale—say by having convolutions with UTF-8 characters that need to be preserved as 8-bit entities. Thus, setting LANG=C can help to avoid some types of problems, particularly in pipelines and scripts that pass one program's data to another program in binary format.

> Localization support is, to some extent another, the responsibility of each program's author. It's entirely possible to write a program that supports one language or a small subset of languages. Thus, you won't be able to get every program to support your desired language, particularly if it's an unusual one.

# Modifying Text-File Locales

Sometimes it's necessary to access textual data that originated on a system that used one encoding but process the data with a program that doesn't support encoding. For instance, your preferred text editor might support UTF-8 but not ISO-8859. If you deal exclusively with English text files in ASCII, this isn't a problem; but if you receive an ISO-8859-1 text file with a few non-Roman characters, such as characters with umlauts, your editor might display those characters strangely.

To overcome this problem, the iconv utility converts between character sets. Its syntax is as follows:

```
iconv -f encoding -t encoding [inputfile]...
```

The -f and -t options specify the source and destination encodings.(You can obtain a list of encodings by typing iconv --list.) If you omit the target encoding, iconv uses your current locale for guidance. The program sends output to standard output, so if you want to store the data in a file, you must redirect it:

```
$ iconv -f iso-8859-1 -t UTF-8 umlfile > umlfile-utf8.txt
```
