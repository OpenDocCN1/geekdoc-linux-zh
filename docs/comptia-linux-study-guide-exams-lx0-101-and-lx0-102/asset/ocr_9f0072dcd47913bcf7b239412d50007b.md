# Listing 10.1: Sample xinetd configuration entry

service ftp

```
{
    socket_type = stream
    protocol    = tcp
    wait        = no
    user        = root
    server      = /usr/sbin/in.ftpd
    server_args = -1
}
```

One additional xinetd.conf parameter is commonly present: disable. If you include the line `disable = yes in a server definition, xinetd ignores the entry. Some server packages install startup files in /etc/xinetd.d that have this option by default; you must edit the file and change it to read disabled = no to enable the server. You can also disable a set of servers by listing their name in the defaults section of the main xinetd.conf file on a line called disabled, as disabled = ftp shell.

As with inetd, after you make changes to xinetd's configuration, you must restart the super server. You do this by typing a command similar to the one used to restart inetd. With that command, you can use reload or restart, with similar effects:

```
# /etc/init.d/xinetd restart
```

# Controlling Access via xinetd

Security is handled on a server-based basis through the use of configuration parameters in /etc/xinetd.conf or the server-specific configuration files. Some of these options are similar to the function of hosts. `allow` and `deny`:

**Network Interface** The bind option allows xinetd to listen on only one network interface for the service. For instance, you can specify `bind=192.168.23.7` on a router to listen only on the Ethernet card associated with that address. This feature is extremely useful in routers, but it isn't useful for computers with no network interface. You can however, use this option to bind a server only to the loopback interface, 127.0.0.1, if a server should be available only locally. You might do this with a configuration tool like the Samba Web Administration Tool (SWAT). A synonym for this option is interface.

**Allowed IP or Network Addresses** You can use the `only` option to specify IP addresses, networks (as in `192.168.78.0/24`), or computer names on that line, separated by spaces. The result is that xinetd will accept connections from these addresses, to TCP Wrappers' `allow` entries.

**Disallowed IP or Network Addresses** The `no_access` option is the opposite of `from_`, you list computers or networks that you want to blacklist. This is similar to the `hosts.deny` file of TCP Wrappers.
