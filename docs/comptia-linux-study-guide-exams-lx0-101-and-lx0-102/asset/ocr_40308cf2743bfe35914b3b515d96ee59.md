> If you've forgotten the root password for a computer, you can boot with an emergency recovery system and copy the contents of a password field for an account whose password you remember. Normally log as root, and change the password. In a real pinch, you can delete the contents of the password field, which results in a root account with no password (that is, none is required to log in). If you do this, be sure to immediately change the root password after rebooting!

**Last Password Change** The next field (3505 in this example) is the date of the last password change. This date is stored as the number of days since January 1, 1970.

**Days Until a Change Is Allowed** The next field (0 in this example) is the number of days before a password change is allowed.

**Days Before Change Is Required** This field is the number of days after the last password change before another password change is required.

**Days of Warning Before Password Expiration** If your system is configured to expire passwords, you may set it to warn the user when an expiration date is approaching. A value of 7, in the case example, is typical.

**Days Between Expiration and Deactivation** Linux allows for a gap between the expiration of an account and its complete deactivation. An expired account could not be used or requires that the user change the password immediately after logging in. In either case, the password remains intact. A deactivated account is erased, and the account can't be used until it is reactivated by the system administrator.

**Expiration Date** This field shows the date on which the account will expire. As the last password change date, this is expressed as the number of days since January 1, 1970. This is helpful in the case of students, interns, auditors, contract staff, seasonal workers, and temporary users.

**Special Flag** This field is reserved for use and normally not used or contains a meaningless value. This field is empty in the preceding example.

For fields relating to date change, a value of -1 or 99999 indicates that the relevant feature has been disabled. The /etc/shadow values are generally best left to modification through the usermod commands which can be tricky to set manually—it's easy to forget a leap year or when computing a date of the days since January 1, 1970. Similarly, because of its encrypted nature, the password field cannot be edited effectively except through a compatible file or use crypt, You can cut and paste a value from a compatible file but it's generally easier to use password. Copying encrypted passwords from other systems is somewhat risky because it means that the users will have the same passwords on both systems, and this fact will be obvious to anyone who's acquired both encrypted password lists.
