
# Chapter 5 • Booting Linux and Editing Files

Both Upstart and systemd provide runlevel commands for compatibility with SysV. Alternatives do not technically use runlevels, though, the information is a sort of "translation" of what the startup system is using SysV terms.

## Changing Runlevels on a Running System

Sometimes you might want to change runlevels on a running system. You might do this to get more services, such as going from a console to a graphical login runlevel, or to shut down or reboot your computer. This can be accomplished with the init (or telinit), shutdown, halt, reboot, and poweroff commands.

## Changing Runlevels with init and telinit

The init process is the first process run by the kernel, but you can also use it to have system read the /etc/inittab file and implement changes it finds there or change to a new runlevel. The simplest case is to have change to the runlevel you specify. instance, to change to runlevel 1 (the runlevel reserved for single-user or maintenance mode), you would type this command:

```bash
# init 1
```

To reboot the system, you can use init to change to runlevel 6 (the runlevel reserved for reboots);

```bash
# init 6
```

A variant of init is telinit. This program can take a runlevel number just like init to change to that runlevel, but it can also take the Q or q option to have the tool reread /etc/inittab and implement any changes it finds there. Though, if you've made a change to the runlevel in /etc/inittab, you can immediately change that by typing telinit q.

> NOTE: The pages for these commands indicate slightly different syntaxes; but telinit is a symbolic link to init, and in practice init responds like telinit to the Q and q options.

The Upstart and systemd tools provide init and telinit commands that work much as they do on SysV-based computers.

## Changing Runlevels with shutdown

Although you can shut down or reboot the computer with init, doing so has some problems. One issue is that it's simply an unintuitive command for this action. Another is that changing runlevels with init causes an immediate change to the new runlevel. This may cause other users on your system some aggravation that they'll be no warning about the shutdown. Thus, it's better to use the shutdown command in a multi-user environment when you want to reboot, shut down, or switch to single-user mode. This command supports extra options that make it friendlier in such environments.

The shutdown program sends a message to all users who are logged into your system and prevents other users from logging in during the process of changing runlevels. The shutdown command also lets you specify when to effect the runlevel change so that users have time to edit editors and safely stop processes they may have running.

When the time to run runlevels is reached, shutdown signals the init process for you. In the simple format, shutdown is invoked with an argument like this:

```bash
# shutdown now
```

This changes the system to runlevel 1, the single-user or maintenance mode. The new parameter allows the change to occur immediately. Other possible time formats include hh:mm, for a time in 24-hour clock format (such as 6:00 a.m. or 13:30 p.m.), and +m for a time minutes in the future.

You can add extra parameters to specify that you want to reboot or halt (that is, power off) the computer. Specifically, -r reboots the system, -h halts it (terminates operation but doesn't power it off), -P powers it off. The -h option may power off the computer, but usually it powers it off. For instance, you can use shutdown -r +10 to reboot the system in 10 minutes.

To give people warning about the impending shutdown, you can add a message to the end of the command:

```bash
# shutdown -h +15 "system going down for maintenance"
```

If you schedule a shutdown but change your mind, you can use the -c option to cancel it:

```bash
# shutdown -c "never mind"
```

Upstart and systemd provide shutdown commands of their own that function like the shutdown command of SysV. You may want to check your computer's man page for shutdown to verify that it works in the way described here; with development active in the realm of startup systems, you may find many surprises!

## Changing Runlevels with the halt, reboot, and poweroff Commands

Three additional shortcut commands are halt, reboot, and poweroff. (In reality, reboot and poweroff are usually symbolic links to halt. This command behaves differently depending on the name with which it's called.) As you might expect, these commands halt the system (shut it down without powering it off), reboot it, or shut it down and (on hardware that supports this feature) turn off the power, respectively. As with telinit and shutdown, these commands are available in SysV, Upstart, and systemd.

## EXERCISE 5.1

### Changing Runlevels

This exercise will demonstrate the effects of changing the runlevel in various ways on a working system. Be aware that some of the effects will be different from one system to another, depending on both the distribution and the system-specific configuration of the computer. Also, in the course of running this exercise, you'll reboot the computer, so you shouldn't use it on a system that anyone else is using. To manage your runlevels, follow these steps:

- 1. Log in root, or acquire root privileges by using su or by sudo using each of the following commands. Use a text-mode or remote login; some of the activities will shut down X.
- 2. Type runlevel to learn your runlevel. Recall that the first character returned to the previous runlevel (N denotes no runlevel; it hasn't changed since the system booted). The second output character is the current runlevel. This is likely to be 2 on Debian or Debian-derived systems and 3 or 5 on Red Hat or Red Hat-.
- 3. If your system reports it's in runlevel 5, type telinit to switch to runlevel 3. Chances are your X server will stop working. (Pressing Alt+F7 from a text-mode console will show a blank text-mode screen rather than the X display this keys would normally reveal).
- 4. If your system initially started a runlevel of 3, type telinit to switch to runlevel 5. This will probably cause the screen to blink two or three times and possibly display a message.
- 5. If your system initially started a runlevel of 3, type telinit to switch to runlevel 1. This changes the system to runlevel 1, the single-user or maintenance mode. The new parameter allows for the change to occur immediately.
- 6. If your system initially started a runlevel of 3, type telinit to switch to runlevel 5. This will probably cause the screen to blink two or three times and possibly display a message.
- 7. If your system reports it's in runlevel 5, type telinit to switch to runlevel 3. Chances are your X server will stop working. (Pressing Alt+F7 from a text-mode console will show a blank text-mode screen rather than the X display this keys would normally reveal).
- 8. Reboot the computer by typing reboot now.
- 9. Log in as root, and type runlevel to verify that you're in the runlevel specified in step 7.
- 10. Edit /etc/inittab to restore it to its original state, or restore it from its backup.
- 11. Type telinit 6. This enters runlevel 6, which reboots the system. The computer should be running as well as before you began this exercise.
