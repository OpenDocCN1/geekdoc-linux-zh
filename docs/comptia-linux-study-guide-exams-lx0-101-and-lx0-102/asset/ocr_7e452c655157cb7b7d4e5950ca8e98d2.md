# Listing 7.2: A Sample User crontab

```
SHELL=/bin/bash
MAILTO=tbaker
HOME=/home/tbaker
0,30 * * * * /usr/bin/fetchmail -s
0 2 * * * mon /usr/local/bin/clean-adouble $HOME
```

Utimately, your crontab files are stored in the /var/spool/cron, /var/spool/cron/crontabs, or /var/spool/cron/crontabs. Each file in this directory is named after the user whose name it runs; for example, tbaker's file may be called /usr/spool/cron/tabs/tbaker. You shouldn't directly edit the files in this directory; instead, use crontab to make changes.

Access to the cron facility may be restricted in several ways:

**Executable Permissions** The permissions on the cron and crontab programs may be restricted using standard Linux mechanisms, as described in Chapter 4. Not all distributions configure themselves in this way, but for that do, users who should be able to schedule cron jobs using cron you should check the group owner and permissions on the /usr/sbin/cron and /usr/bin/crontab programs to be sure.

**Allowed Users List** The /etc/.allow contains a list of users who are permitted to access cron. If this file is present, only users whose name appears in the file may use cron; all others are denied access. If this file isn't present, anybody may use cron, assuming access not restricted by executable programs or a disallowed-users list.

**Disallowed-Users List** The /etc/.deny file contains a list of users who should be denied access to cron. If this file is present, any user whose name appears in the file is denied access to cron, but all others may use it, assuming executable permissions and the disallowed-users list restrict access.
