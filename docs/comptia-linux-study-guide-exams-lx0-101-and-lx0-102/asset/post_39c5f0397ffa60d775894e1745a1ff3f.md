
# TABLE 3.5 Important filesystem options for the mount command

| Option | Supported filesystems | Description |
| --- | --- | --- |
| defaults | All | Causes the default options for this filesystem to be used. It's used primarily in the /etc/fstab file to ensure that the file includes an options column. |
| loop | All | Causes the loopback device for this mount to be used. Allows you to mount a file as if it were a disk partition. For instance, mount -t vfat image.img /mnt/ mounts the file image .img as if it were a disk. |
| auto or noauto | All | Doesn't mount the filesystem at boot time or when root issues the mount -a command. The default is auto, but noauto is appropriate for removable media. Used in /etc/fstab. |
| user or nouser | All | Allows or disallows users to mount the filesystem. The default is user, but user is often appropriate for removable media. Used in /etc/fstab. When included in this file, allow users to type mount /mountpoint (where /mountpoint is the assigned mount point) to mount a disk. Only the user who mounted the filesystem may unmount it. |
| users | All | Similar to user, except that any user may unmount a filesystem once it's mounted. |
| owner | All | Similar to user, except that the user must own the device file. Some distributions, such as Red Hat, assign ownership of some device files (such as /dev/fd0) to the console user, which can be a helpful option. |
| remount | All | Changes one or more mount options without explicitly mounting a partition. To issue a mount command on an already-mounted filesystem use remount along with any options you want to change. This feature can be used to enable or disable access to a partition, for example. |
| ro | All | Specifies a read-only mount of the filesystem. This is the default for filesystems that include no write access and for some with particularly unreliable write support. |
| rw | All read/write file systems | Specifies a read/write mount of the filesystem. This is the default for most read/write filesystems. |

# Mounting and Unmounting Filesystems

# Using amount

The amount command is simpler than mount. The basic amount syntax is as follows:

```
mount [-afnrv] [-t ftype] [device] | mountpoint
```

Most of these parameters have meanings similar to their meanings in mount, but some differences deserve mention:

**All** Rather than mount partitions listed in /etc/mtstab, the -a option causes the system to attempt to mount all partitions listed in /etc/mtstab, the file that has information about mounted filesystems. On a normally running system, this operation is likely to succeed only because it won't be able to mount some key filesystems, such as the root partition.

**Force** You can use the -f option to tell Linux to force an unmount operation that might otherwise fail. This feature is helpful when unmounting NFS mounts shared by servers that become unreachable.

**Fall Back to Read-Only** The -r option tells mount that if it can't unmount a filesystem, it should attempt to remount in read-only mode.

**Unmount Partitions of a Specific Filesystem** The -t ftype option tells the system to mount only partitions of the specified type. You can list multiple filesystems by separating them with commas.

**The Device and Mount Point** You only need to specify the **device** or the **mountpoint**, not both.

As with, normal users can't ordinarily use amount. The exception is if the partition or device is listed in /etc/fstab and specifies the user, or **owner** option, in which case normal users can unmount the device. (In the case of user, only the user who mounted the partition may mount it; in the case of owner, the user issuing the command must also own the device file, as mount.) These options are most useful for removable-media devices.

![](img/35f616c7eba4e79e12bfd762129c5d27_217_0.png)

Be cautious when removing floppy disks or unplugging USB disk-like devices (USB flash drives or external hard disks). Linux caches to most filesystems, which means data may not be written to the disk until some time after a write command. Because of this, it's possible to corrupt a disk by ejecting or unplugging it, even when the drive is not active. You **always use amount** command before mounting a device. (GUI tools do this behind the scenes, so using a desktop's unmount or eject option is equivalent to using amount.) After issuing the amount command, wait for the command to return, and if the disk activity indicators, wait for them to stop blinking be sure Linux has finished using the device. Another way to write to the cache is to use the sync command; but because this command does not fully unmount a filesystem, it's not a substitute for amount.

# Permanently Mounting Filesystems

The /etc/fstab controls how Linux access partitions and removable media. The /etc/fstab consists of a series of lines that contain six fields; the fields are separated by one spaces or tabs. A line that begins with a hash mark (#) is a comment. Listing 3.1 shows a sample /etc/fstab.

Listing 3.1: Sample /etc/fstab file

| device | mount point | filesystem | dump | fsck |
| --- | --- | --- | --- | --- |
| /dev/hdl | /home | ext4 | defaults | 1 1 |
| UUID=3631a288-673e-40f5-92e6-639fec68e9 | / | | | |
| /user | reiserfs | defaults | 0 0 |
| /home | /home | reiserfs | defaults | 0 0 |
| /dev/db5 | /windows | | uid=500,umask=0 | 0 0 |
| /dev/vdc | /media/cdrom | iso9660 | users,noauto | 0 0 |
| /dev/sda | /media/home | auto | users,noauto | 0 0 |
| server:/home | nfs | | users,exec | 0 0 |
| /winsrv/shr | /other | cifs | users,credentials=/etc/creds | 0 0 |
| /dev/hda4 | swap | | defaults | 0 0 |

The meaning of each field in this file is as follows:

**Device** The first column specifies the mount point. These are usually device filenames that reference hard disks, floppy disks, and so on. Most distributions specify partitions by their labels or UIDs, as in the LABEL=/ and UUID=3631a288-673e-40f5-92e6... in Listing 3.1. When Linux encounters such an entry, it tries to find the partition that has the specified name or UUID and mount it. This practice can help reduce problems if partition numbers change, but some filesystems keep these labels. It's also possible to list a network drive, as in server:/home, which is the /home export on the computer called server; or in /winsrv/shr, which is the share on-the Windows or Samba server called winsrv.
