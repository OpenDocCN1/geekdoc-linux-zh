Restoring individual files is also impossible unless the backup device is a random access device that can be mounted; if you back up to tape, you must restore everything (at least to a temporary file or partition) to recover a single file. Finally, you can't easily restore data to a partition that's smaller than the original partition; when restoring to a larger partition, you will end up using most of the space available on that partition.

Despite these problems, dd can be handy in some situations. It can be a good way to make an exact copy of a removable disk (including an optical disk), for instance. You can use dd to copy a disk which lacks filesystem drivers. If you need to create multiple identical Linux installations, you can do so by using dd to copy an installation to multiple computers, as long as they have the same size.

You can also use dd in some other scenarios. For instance, if you need an empty file of a particular size, you can copy from the /dev/zero (a Linux device that returns zeros) to a target file. You will need to use the bs=size and count=length options to set the block size and length of the file, though:

```
$ dd if=/dev/zero of=empty.file bs=1024 count=720
```

This example creates a 720KiB (1024 × 720 bytes) empty file. You might then manipulate this file, by example, creating a filesystem on it with mkfs.

# Backing Up Optical Media

Optical media requires special backup procedures. Normally, cdrecord accepts input from a program like mkisofs, which creates an ISO-9660 or UDF filesystem—the type of filesystem that's most often used on CD-ROMs and DVDs.

One option for backing up optical disks is to use mkisofs and then cdrecord to copy files to the disk. If you copy files "raw" this way, you'll lose some information, such as write permissions. You'll have better luck if you create a tar or cpio archive on disk. You then use mkisofs to place that archive in an ISO-9660 or UDF filesystem and then burn the image to the optical device. The result will be a disc that you can mount and contain an archive you can read with tar or cpio.

A more direct option is to create an archive file and burn it directly to the optical disc using cdrecord, bypassing mkisofs. Such a disc won't be mountable in the usual way, but you can access the archive directly by using the CD-ROM device file. On restoration, this works much like a tape restore except that you specify the optical device filename (such as /dev/cdrom) instead of the tape device filename (such as /dev/st0).

# Managing Links

In Linux, a link is a way to give file multiple identities, similar to shortcuts in Windows and aliases in Mac OS. Linux employs links to help make files more accessible, give commands multiple names, enable programs that look for the files in different locations to access the files, and so on. Two types of links exist: hard links and symbolic links (aka soft links). (Their differences are described in more detail shortly.) The ln command creates links. Its syntax is similar to that of cp:

```
ln [options] source link
```

The source is the original file, and the link is the name of the link you want to create. This command supports options and has several effects:

- **Remove Target Files**: The -f force option allows ln to remove existing links or files that have the target name. The -i or --interactive option has a similar effect, but it queries before replacing existing links.

- **Create Directory Hard Links**: Ordinarily, you can't create hard links to directories. The root user can attempt to do so, by passing the -d, -F, or --directory option to ln. (Symbolic links to directories aren't a problem.) In practice, this feature is unlikely to work because most systems don't support it.

- **Create a Symbolic Link**: The ln command creates hard links by default. To create a symbolic link, use the -s or --symbolic option to the command.

A few options exist to perform more obscure tasks; consult ln's page for details.

By default, ln creates hard links, which are produced by creating two directory entries that point to the same file (precisely the same inode). Both filenames are valid and prominent; one is a "truer" filename than the other, except that one was created first (when creating the file) and the other was created second. To delete the file, you must delete both hard links to the file. Because of the way hard links work, they must exist on a single low-level filesystem; you can't create a hard link from say, your root (/) filesystem to a separate filesystem you've mounted, such as /home (if it is a separate filesystem). The underlying filesystem must support hard links. All Linux-native filesystems support this feature, but non-Linux filesystems don't.

Symbolic links, by contrast, are special types. The symbolic link is a separate file whose contents point to the linked-to file when you try to access the symbolic link, so in most respects accessing a symbolic link works just like accessing the original file. Because symbolic links are basically files that contain filenames, they can point across low-level filesystems—you can point from the root (/) filesystem to a file on a separate filesystem.
