
Like RPM, the Debian package format is normal with respect to both OS and CPU type. Debian packages are extremely rare outside Linux, although various systems that used the Debian package system and software library atop non-Linux kernels have been attempted, and largely abandoned, with the exception of FreeBSD (http://www.debian.org/ports/freebsd-gnu/);

The original Debian distribution has been ported to many different CPUs, including x86, x86_64, IA-64, ARM, PowerPC, Alpha, 680x, MIPS, and SPARC. The original architecture was x86, and subsequent ports exist at varying levels of maturity. Derivative distributions generally only exist on x86 or x86_64 systems, but this could change in the future.

Debian packages follow a naming convention similar to that for RPMs; but Debian packages sometimes omit codes in the filename to specify a package's architecture, particularly on x86. When these codes are present, they may differ from RPM conventions. For an instance, a file ending in 1386.deb indicates an x86 binary, powerpc.deb deb a CPU-independent package, such as documentation or scripts. As RPM files, this file-naming convention is only—a convention. You can rename a file as you fit, to either include or omit the processor code. There is no code for Debian source packages, as described in the upcoming section "Debian Packages Compared to Other Package Formats," Debian source packages consist of several separate files.

## dpkg Command Set

Debian packages are incompatible with RPM packages, but the basic principles of operation are the same across both package types. Like RPMs, Debian packages depend on information, and the Debian package utilities maintain a database of installed packages, files, and so. Use the dpkg command to install a Debian package. This command's syntax is similar to that of rpm:

# Using apt-cache

The APT suite of tools includes a program, apt-cache, that's intended solely to provide information about the Debian package database (known in Debian terminology as the package cache). You may be interested in using several features of this tool:

**Display Package Information** Using the showpkg subcommand, in apt-cache showpkg samba, displays information about the package. The information displayed is different from returned by dpkg's informational.

**Display Package Statistics** You can learn how many packages you've installed, how dependencies are recorded, and various other statistics about the package database by passing the stats subcommand, in apt-cache stats.

**Find Unmet Dependencies** If a program is reporting missing libraries or files, typing apt-cache unmet may return information about unmet dependencies, which help you track down the source of missing-file problems.

**Display Dependencies** Using the depends subcommand, in apt-cache depends samba, shows all of the specified package-related dependencies. This information can be helpful in tracking dependency-related problems. The deplets subcommand finds reverse dependencies—packages that depend on the one you specify.

**Locate All Packages** The pkgnames subcommand displays the name of all packages installed on the system. If you include a second parameter, in apt-cache pkgnames sa, the program returns only those packages that begin with the specified string.

Several subcommands and options exist, but these are the ones're most likely to use. Several apt-cache subcommands are intended for package managers and debugging serious package database problems rather than day-to-day system administration. Consult the main page for apt-cache for more information.
