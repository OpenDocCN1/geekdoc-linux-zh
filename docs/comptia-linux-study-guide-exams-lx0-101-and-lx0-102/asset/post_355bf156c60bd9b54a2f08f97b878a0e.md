The Field(s) criteria appears as a comma-separated list of columns. In this example, the criteria were listed in the reverse order from their order in the database, and so they appear in the reverse order in the output.

A more interesting way to retrieve data is to use WHERE conditions. This tool has already been mentioned, in reference to updating data. You can use conditions to retrieve specific data in several ways:

- Exact Matches: Using a column name, an equal sign, and a value to match returns only those rows that match the specified value. For instance, typing SELECT * FROM objects WHERE color='green'; returns the two entries for green objects (lizard and tree).

- Numeric Tests: You can retrieve data that match numeric criteria. For instance, to retrieve data on objects that are greater than 10 inches in size, you can type SELECT * FROM objects WHERE size>10;

- Alphabetic Tests: The greater-than (>) and less-than (<) operators work on letters as well as numbers. This can be used to retrieve data based on the first letter of a string, as SELECT * FROM objects WHERE name>'b'; to retrieve records for the name begins with b or later letters in the alphabet. (Although this example uses a greater-operator, it does not match the letter b).

- Multiple Tests: You can combine criteria using the AND and OR operators. For instance, to retrieve data on soft objects valued more than $75.00, you can type SELECT * FROM objects WHERE hardness='soft' AND value>75;

You have MySQL return the data as an ordered list by specifying a field name after the ORDER BY keyword:

```
mysql SELECT * FROM objects WHERE hardness='soft' ORDER BY value;
```

# Combining Data from Multiple Tables

As noted, a database may contain multiple tables. This feature of SQL enables to create tables for different functions. For instance, Figure 9.2 might represent a database of object characteristics that are of interest for some reason. You might also have a database containing the locations and conditions (on a 10-point scale) of different objects, as shown in Table 9.4. Sometimes you might want to combine these two tables to create a master table on which you can perform queries. In order to do so, the two tables must have one matching field that can be used to bind the two tables, and each table must have one field whose value uniquely identifies each row. This uniquely identifying field is known as a primary key. In the case of Figure 9.2, the first column (called name) can serve as a primary key. In the case of Table 9.4, the Object ID column will do the job.

You can create this table using locations you created the first:

```
mysql> CREATE TABLE locations (id INTEGER, name VARCHAR(30),
  > location VARCHAR(30), condition INTEGER);
mysql> INSERT INTO locations VALUES(1, 'banana', 'kitchen', 9);
```

Additional INSERT will fill out the table. At this point, you can use the SELECT operator to select data based on fields from both tables. For instance, suppose you want to know where all the green objects are located. The first table (objects) contains color data but not locations, whereas the second table (locations) holds locations but not color data. You can accomplish the goal by using a few tricks:

```
mysql SELECT objects.name, objects.color, locations.location
-> FROM objects, locations
-> WHERE objects.name=locations.name AND objects.color='green';
```

MySQL automatically combines the two tables and produces output based on the criteria. The final output in this example includes the name, color, and location of the objects, even though each has just two of those values.

A way to combine data from multiple tables is to use JOIN. This approach is very similar to the preceding one, but you specify one table using FROM and the other using JOIN:

```
mysql SELECT objects.name, objects.color, locations.location
-> FROM objects
-> JOIN locations
-> WHERE objects.name=locations.name AND objects.color='green';
```

Combining data enables you to simplify the structure of your database in certain situations. The examples used here illustrate this fact, albeit with very small data sets. The data in the tables describes objects generically, whereas the data in the locations table describes objects specifically. A retail business might use similar tables to describe its inventory—something analogous to the objects table while the locations table can specify where each box holding a particular product is shelved, perhaps even across multiple warehouses or stores. This design enables each table to be relatively small. If all the data were stored in a single table, that table would require multiple entries for each item, duplicating a lot of data. By splitting the data across tables, each table can be much smaller, reducing storage space.

A retrieval command requires special method GROUP BY. This command is used in conjunction with mathematical operators, such as SUM(), to restrict the operation of the operator to the specified columns. For instance, suppose you want to know the total value of all objects in the database, grouped by object type. You can do so as follows, combining data from both:

```
mysql SELECT objects.name, objects.value, SUM(value)
-> FROM objects, locations
-> WHERE locations.name=objects.name
-> GROUP BY value;
```

# Deleting Data

Sometimes your data needs to be deleted. Table 9.4 suggests that the tree in the back yard is ill—its condition rating is 2 on a 10-point scale. Perhaps you'll decide to cut it down and remove it from the database. To do so, you'll use the DELETE command, which takes the following form:

```
DELETE FROM table
```

For instance, to delete the tree, you can type the following command:

```
mysql> DELETE FROM locations
-> WHERE name='tree' AND location='back yard';
Query OK, 1 row affected (0.05 sec)
```

In this specific case, the WHERE condition is more detailed than it needs to be, because the back yard tree is the only one in the table. As when deleting sort of data on a computer, it's better to be cautious than sloppy.

Before deleting data, using SELECT to see what data your WHERE condition matches. This will help you prevent accidentally deleting too much data.

You can delete all the data from a table by using the DELETE command: DELETE FROM locations; This command deletes all the table's data without deleting the table. This may be useful if the table is hopelessly messed up from experimentation. An even more drastic deletion is DROP: DROP TABLE locations; This example completely completes the locations table. Naturally, this is an extremely dangerous command, but you might want to use it when cleaning up your SQL session practice.
