For instance, at the top of each stack is a program that uses the stack, such as an email client. You can switch from one client to another without much difficulty; both rest atop the same stack. Likewise, if you change a network card, you change the driver for that card, which constitutes a very low layer in the stack. Applications above that driver can remain the same.

Each computer in a transaction requires a compatible protocol stack. When they communicate, the computers pass data down their respective stacks and send data to the partner system, which passes the data up its stack. Each layer on the receiving system sees the data as packaged by its counterpart on the sending computer.

Protocol stacks are frequently represented in graphics like Figure 8.2, which shows the configuration of the TCP/IP protocol stack that dominates the Internet today. As shown in Figure 8.2, clients at the application layer initiate data transfers. These requests pass through the transport, internet, and link layers on the client, whereupon they leave the client system and pass to the server system. (This transfer involve a lot of complexity not depicted in Figure 8.2.) On the server, the process reverses itself, with the server program running at the application layer replying to the client program. This reply reverses the journey, traveling down the server computer's stack, across the network, and up the stack on the client. A full-fledged network connection can involve many back-and-forth data transfers.
