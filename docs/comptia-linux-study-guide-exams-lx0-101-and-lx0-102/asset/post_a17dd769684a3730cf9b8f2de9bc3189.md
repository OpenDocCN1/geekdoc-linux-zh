Another text-based Debian package manager is aptitude. In interactive mode, aptitude is similar to dselect in a rough way, but aptitude adds menus accessed by pressing Ctrl+T and rearrangements around features. You can also pass various commands to aptitude on the command line, for instance, **aptitude search samba**, which searches for packages related to Samba. Features accessible from the command line (or the interactive interface) include the following:

**Update Package Lists** You can update package lists from the APT repositories by typing **aptitude update**.

**Install Software** The install command-line option installs a named package. This command has several name and syntaxes that modify its action. For instance, typing **aptitude install zsh** installs the package, while typing **aptitude install zsh-** (with a trailing dash) and **aptitude remove zsh** both uninstall zsh.

**Upgrade Software** The full-upgrade and safe-upgrade options upgrade all installed packages. The safe-upgrade option is conservative about removing packages or installing new ones and so may fail; full-upgrade is less conservative about these actions and so is more likely to complete its tasks, but it may break software in the process.

**Search for Packages** The search option, noted earlier, searches the database for packages matching the specified name. The result is a list of packages, one per line, with summary codes for each package's install status, its name, and a brief description.

**Clean Up the Database** The autoclean option removes already-downloaded packages that are no longer available, and clean removes all downloaded packages.

**Obtain Help** Typing aptitude results in a complete list of options.

Broadly speaking, aptitude combines the interactive features of dselect with the command-line options of apt-get. All three programs provide similar functionality, so you can use whichever you prefer.

A tool's similar to dselect and aptitude in some ways is Synaptic, but Synaptic is a GUI X-based program and is easier to use. Overall, dselect, aptitude, and Synaptic are useful tools, particularly if you need to locate software but don't know its exact name—the ability to browse and search the available packages can be a great boon. Unfortunately, the huge package list can be intimidating.

## Reconfiguring Packages

Debian packages often provide more extensive initial setup options than do their RPM counterparts. Frequently, the initial script included in the package asks a handful of questions, such as querying for the name of an outgoing mail relay server for a mail server program. These questions help the package set up a standardized configuration that has nonetheless been customized for your computer.

In the course of your system administration, you may alter the configuration files for a package. If you find you have made a mess of things, you may want to revert to the initial standard configuration. To do so, you use the dpkg-reconfigure program, which runs the initial configuration script for the package you specify:

```bash
# dpkg-reconfigure samba
```

This command reconfigures the samba package, asking the package initial installation questions and restarting the Samba daemons. Once this is done, the package should be closer to its initial state.

## Debian Packages Compared to Other Package Formats

The overall functionality of Debian packages is similar to that of RPMs, although there are differences. Debian source packages are not single files; they're groups of files—the original source tarball, a patch file that's used to modify the source code (including a file that controls the building of a Debian package), and a .desc file that contains a "signature" to help verify the authenticity of the collection. The Debian package tools can combine and compile the package to create a Debian binary package. This structure makes Debian source packages slightly less convenient to transport because you must move at least two files (the tarball and patch file; the .dsc file is optional) rather than just one. Debian source packages also support just one patch file, whereas source packages may contain multiple patch files. Although you can certainly combine multiple patch files into one, doing it makes it less clear which patch comes from, making it harder to back out of any given change.

These source package differences are mostly of interest to software developers. As a system administrator or end user, you need not be concerned with them unless you recall a package from a source form—and even then, the differences between the formats are not overwhelming. The exact commands and features used by each system differ, but they accomplish overall goals.

Because all distributions that use Debian are derived from Debian, they tend to be more compatible with one another (in terms of their packages) than RPM-based distributions. In particular, Debian has defined its startup scripts and many features to help Debian packages install and run on any Debian-based system. This helps Debian-based systems avoid the sorts of incompatibilities in startup scripts that can cause problems using one distribution's RPMs on another distribution. Of course, some future distribution could violate Debian's guidelines for these matters, so this advantage isn't guaranteed to hold over time.

As a practical matter, it can be harder to locate Debian packages than RPM packages for some exotic programs. Debian maintains a good collection at http://www.debian.org/ and some authors make Debian packages available as well. If you can find an RPM but not a Debian package, you may be able to convert the RPM to Debian format using a program called *alien*, as described shortly in “Converting Between Package Formats.” If all else fails, you'll lose the advantages of the Debian package database.

## Configuring Debian Package Tools

With the exception of the APT sources list, Debian package tools don't usually require configuration. Debian installs reasonable defaults (as its derivative distributions do). On occasions, you may want to adjust some of these defaults. Doing so requires you to know where to look for.

The main configuration file for *dpkg* is `/etc/dpkg/dpkg.cfg` or `~/.dpkg.cfg`. This file contains *dpkg* options, as summarized in Table 2.5, but without the dashing. For instance, to have *dpkg* always perform a test run before actually installing a package, you'd create a `dpkg.cfg` file with one line:

```text
no-act
```

For APT, the main configuration file you're likely to modify is `/etc/apt/sources.list`, which was described earlier in “Using apt-get.” Another file is `/etc/apt/apt.conf`, which controls APT and dselect options. With *dpkg*, you won't need to modify *apt.conf*. If you need to make changes, the format is more complex and is modeled after those of the Internet Software Consortium's (ISC) Dynamic Host Configuration (DHCP) and Berkeley Internet Name Domain (BIND) servers' configuration files. Options are grouped together by open and close braces ({}):

```text
APT
{
  Get
  {
    Download-Only "true";
  }
}
```

These lines are equivalent to permanently setting the download-only option described in Table 2.7. You can, of course, set many more options. For details, consult apt.conf's man page. You may also want to view the sample configuration file, /usr/share/doc/apt/examples/apt.conf. (The working /etc/apt/apt.conf file is typically extremely simple, or missing and therefore not very helpful as an example.)

You should be aware that Debian's package tools rely on various files in the /var/lib/dpkg directory tree. These files maintain lists of available packages, lists of installed packages, and so on. In other words, this directory tree is effectively the Debian installed file database. As such, you should be backed up when you perform system backups and be careful about modifying its contents.

## Converting Between Package Formats

Sometimes you are presented with a package file in one format, but you want to use another format. This is particularly common when you use a Debian-based distribution and can find only tar or RPM files of a package. When this happens, you can keep looking for a package file in the appropriate format, install the tools for the foreign format, create a package from a source tarball using the standard RPM or Debian tools, or convert between package formats with a utility like aian.

This section focuses on this last option. The aian program comes with Debian and a few other distributions, but may not be installed by default. If it's not installed install it by apt-get install aian on a system that uses APT, or use the Rpmfind or Debian site to locate it. This program can convert between RPM packages, Debian packages (used by Stampede Linux), and tarballs.

You need to be aware of some caves. For one thing, aian requires that you have appropriate package manager software installed—for instance, both RPM and Debian to convert between these formats. The aian utility doesnt always convert all dependency information completely correctly. When converting from a tarball, aian copies the files directly as they had been in the tarball, aian works only if the original tarball has files that should be installed off the root (/) directory of the system.
