# Appendix A - Answers to Review Questions

3. A. The change command varies account expiration options. The -M parameter sets the maximum number of days for which a password is valid, and in the context of the given command, time is a username. Option A is correct. Options B, C, D, and E are all made up.

4. B, D. As stated in option B, Linux usernames may not begin with numbers, so the username (sa1ly) is invalid. The /etc/passwd entries have third and fourth fields of the UID and the GID, but this line has only one of them (which is intended to determine); this example's fourth field is clearly the field of a valid entry. Option D is correct. Option A is incorrect because, /bin/passwd is an unorthodox login shell, it is perfectly valid. This configuration may be used, say, a Samba server to enable users to change their passwords without SSH login access. Option C is a correct but an incorrect one; the username and the user's home directory name not match. The encrypted password is officially stored in the second field (x in this example), but in practice, Linux computers use passwords, and an x for the value is consistent with this, so option E is correct.

5. Option D shows a valid /etc/group that has the desired effect. (Note that the order of users in the comma-separated list is important.) Option A has two problems: It's missing a password field (x in the correct entry), and the usernames are separated by spaces rather than commas. Option B also has two problems: It's missing a password field, and its usernames are separated by colon rather than commas. Option C has one problem: Its usernames are separated by colon than commas. Option E has two problems: Password and GID fields are reversed, and its usernames are separated by backslashes rather than commas.

6. B, C. Files from /etc/ske are copied from this to new users' home directories by create-account tools. Files you want in all new users' home directories should reside in /etc/ske. Options B, C, and D all describe reasonable possibilities, although none is ideal. Including a copy of /etc/shadow in /etc/ske (option A) would be a very bad idea, this would give all users access to all other users' encrypted passwords, at least at the cost of account creation. You wouldn't likely find package management databases (option E) in /etc/ske, since users don't have privilege to this data, nor do they need individualized copies of it.

7. The user deletes an account, and the -r option to userdel (option C) causes it to delete the user's home directory and mail, satisfying the terms of the question. Option A deletes the account but leaves the user's home directory. Option B has the same; the -f option forces account deletion and removal from some circumstances, but -r is also used. Option D's rm command deletes the user's home directory (assuming it's in the conventional place, given the username) doesn't delete the user's account. Option E's command can modify accounts, including locking them, but it cannot delete accounts. Furthermore, the -D option is fictitious.

8. E. The emerg priority code (option E) is the highest code available and is higher than all the other options. The panic code is valid but is not one of the options.) From highest to lowest, the codes given as options are emerg, crit, warning, info, and debug.
