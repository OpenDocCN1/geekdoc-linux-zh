# Chapter 4: Managing Files

+   1. B. The touch updates a file's time stamps, as option B specifies. (If the file doesn't exist, touch creates an empty file.) You can't move files with touch; that's the job of the mv command, so option A is incorrect. Various tools can convert end-of-line formats, but touch is not one of them, so option C is incorrect. Testing the validity of disk structures, as option D, is normal on a whole-filesystem with fsck and related tools; touch can't do this. You can write cached data to a disk by unmounting it or by using sync, but touch can't do this, so option E is incorrect.

+   2. A. The -s and --symbolic options are equivalent, and both create a symbolic (aka) soft link. Thus, option A and D are both correct. Options B, C, and E are all fictitious.
3. A. The -1 parameter produces a long listing, including file sizes. The -a parameter produces a list of all files in a directory, including the dot files. Combining the two produces the desired information (along with about other files), so option A is correct. The -p, -R, -d, and -F don't have the specified effects, so the remaining options are incorrect.

+   4. D. When moving from one partition to another, mv must necessarily read and copy the file then delete the original if that copy was successful, as stated in option D. If both filesystems support ownership and permissions, they'll be preserved; mv doesn't need an --preserve option to touch, and this preservation does not rely on having exactly the same filesystem types. Thus, option A is incorrect. Although mv doesn't work when copying to a separate low-level filesystem (such as from a hard drive to a pen drive); if the data isn't written to the new location, it won't be able to insert the directory into another computer. Thus, option B is incorrect. Not all filesystems support ownership and permissions, many do, and these attributes are preserved when moving files between them, so option C is incorrect. FAT a common choice on removable media because of its excellent cross-platform support, filesystems will work on disks, so option E is correct.

+   5. A. If you try to create a directory that doesn't exist, mkdir returns no such file or directory. The --p parameter allows mkdir to automatically create all parent directories in such situations, so option A is correct. You can also do this by creating necessary directory separately, so option B is also correct. (It's possible that mkdir would be necessary in this case if the directory one already existed. No harm will come from trying to create a directory that already exists, mkdir will return a File exists error.) Touching /bin/mkdir as C suggests, will likely result in an error message as a normal user and won't help if typed as root, so this option is incorrect. Clearing away directories in the one/two/three tree won't help, so option D is incorrect. Option E's mkdir command is fictitious.
