- 7. A, The env command displays all environment variables, so option B satisfies the question. (In practice, you might use pipes through grep to find the value of a specific environment variable). The echo command, when passed the name of a specific environment variable, displays its value, option D is also correct. DISPLAY is an environment variable, but it's not a command for displaying variables, so option B is incorrect. You can use the export command to create an environment variable but not to display the current settings for, so option C is incorrect. E's cat command concatenates or displays the contents of a file to the screen, but it doesn't display environment variables.

- 8. Scripts, like binary programs, normally have at least one executable bit, but they can be run without this feature. Thus, you should use chmod to set the user-ID (SUID) bit, as in option E. You would not, however, use chmod to set the set-user-ID (SUID) bit, as in option A, since this would be a security risk. There is no standard /usr/bin/scripts directory for programs, and scripts can run in any directory, so option B is incorrect. Making option C is incorrect (Typing bash script will execute the script). Viruses are extremely rare in Linux, and if you created the script, the only ways it could possibly contain a virus would be if you were already infected or if you wrote it as a virus. Thus, option D is incorrect.

- 9. The cp command is the only one called in the script, and that copies files. Because the script passes the arguments $1 and $2 to cp in reverse order, their effect is reversed—where cp copies its first argument to the second name, the cp copies the second argument to the first name. Thus, option C is correct. Because the order of arguments is reversed, option A is correct. The cp command has nothing to do with compiling (option B) or converting (option D) or C++ programs. The reference to /bin/bash in the first line of the script identifies the script itself and does not cause the script to be run as bash scripts, so option E is incorrect.

- 10. Conditional expressions enable the script to execute sets of instructions depending on some condition, as described in option C. They have nothing to do with license conditions (option A), the computer's environment (option B), or Pavlovian conditioning (option D). Although code readability can be influenced by proper or improper use of many programming features, including conditional expressions, this isn't the primary purpose of conditional expressions, so option E is incorrect.

- 11. B, D. Valid scripts begin with the characters # ! and the complete path to a program that can run the script. Options B and D both meet this description, /bin/bash is a shell program that's installed on virtually all Linux systems and /bin/sh is a link to /bin/bash or to some other valid shell. There is no standard /bin/script program, so option A is incorrect. Options C and E are both correct; /bin/tcsh and /bin/zsh are valid shells on many systems, but the order of the first two is reversed, so option B is incorrect.

- 12. A, B, D. For, while and until statements are all looping statements in bash, options A, B, and D are all correct. There is no go statement in bash's scripting language, option C is incorrect. The case statement is a conditional, not a looping, statement in bash, option E is incorrect.

- 13. E. All SMTP email servers are supposed to accept email postmaster. Linux systems typically do so by using an alias to forward the mail to another local user, occasionally. option E is correct. Option A would be rude and pointless, although this type of request is used by some administrators when receiving mail from known sites, as to degrade spam operations. Options B and D describe non-delivery of the message, in violation of proper email server configuration. Option C is effectively the same as option D creation of the postfix account is imminent, and an email server would have no way of knowing this.

- 14. C. The Fetchmail program is a tool for retrieving email from POP or IMAP servers and injecting it into a local (or remote) SMTP email queue. As such, it is not an SMTP server, option C is correct. Postfix (option A), sendmail (option B), Exim (option D), and qmail (option E) are all SMTP email servers for Linux.

- 15. B. The -s option to mail sets the subject line, and -c sets carbon copy (cc :). Input redirection (<) reads the contents of a line into mail as message. A mail command line normally terminates with the primary recipient. Thus, option B correctly describes the effect of the specified line. Options A, C, D, and E are all confused in their interpretation of the effects of mail parameters. Options B and D also confuse input and output redirection, and option A incorrectly suggests that a script (or mail program) can change its status to root privileges.

- 16. D. SMTP servers accept mail for delivery if their Internet connections are down. If the SMTP server cannot connect recipient servers, the SMTP server holds the mail and attempts delivery later, option D is correct. Because SMTP servers don't check for the availability of remote servers until email is accepted for delivery, option A is incorrect. Option B cannot be correct unless there is a backup Internet connection, which wasnt specified in the question. Option C is incorrect because the SMTP server will hold the mail and attempt delivery later. How recipients retrieve their mail is not under their control, option E is incorrect.

- 17. B. The /etc/aliases file configures system-wide email forwarding. The specified line as option B is correct. A configuration like this one is common. Option A has things reversed. Option C is not a valid conclusion from this evidence, although the presence of an FTP server is not, by itself, grounds for suspicion. Similarly, in option D, /etc/aliases is a configuration file, not an account configuration file.
