# Using System Log Files

In addition to setting default environment variables and otherwise modifying users' text-mode login environment by adjusting their bash configuration files, you can adjust the default set of files created by useradd. As described earlier, in “Adding Users,” useradd copies files from the skeleton directory (/etc/skeleton) by default into a newly created home directory. Typically, /etc/skeleton contains a handful of user configuration files, such as .bashrc. You can add files (and directories) to this directory, including configuration files, a README file for new users, and anything else you like. Because these files are copied into users directories and given ownership of the copies, users can read, change, and delete these copies of these files. Thus, you shouldn't place any options in these files that are sensitive from a security point of view or that should not be able to change. (In truth, unless you place in global configuration files they can be edited individually via manual bash commands or other configuration files, too.) Also, be aware that any change you make to the global files won't automatically be moved into users' copies of these files; changes will affect all the files received by new users. This makes the global files (such as /etc/profile) preferable to /etc/skeleton for any changes you want to implement system-wide, particularly if you expect to modify your changes.

Various programs set environment variables themselves, and some are maintained automatically by bash. For instance, bash sets the P environment variable, so you shouldn't try to set it in a configuration script. Also, be aware that adjusting the bash configuration files affects only bash. If a user's default shell is something else or if a user doesnt a text-mode shell (say, if the user logs into X and launches programs from a GUI menu), setting environment variables in the bash configuration files will do no good.

# Using System Log Files

Linux maintains log files that record various key details about system operation. You may be able to begin using log files immediately, but knowing how to change the log file configuration can also be important. You do this by configuring syslog daemon (a daemon is a program that runs continuously in the background waiting for an event to trigger it to perform some action). Some servers and other programs perform their logging and must be configured independently of syslog. You may even want to configure one computer to send its log files to another as a security measure. You should also be aware of issues surrounding log file rotation; if your computer doesntn properly manage existing log files, they can grow to consume all your available disk space, at least on the partition on which theyre stored. In addition to configuring logging, you must be able to use the log files that the system generates.
