# Configuring the Firmware and Core Hardware

> > WARNING The /proc/interrupts files list IRQs that are use in Linux, but Linux doesn't begin an IRQ until the relevant driver is loaded. This may not happen when you try to use the hardware. The /proc/interrupts list may not show all the interrupts that are configured on your system. For instance, the preceding example shows nothing for IRQ 7, which is reserved for the parallel port, because the port hadn't been used prior to viewing the file. If the parallel port were used and /proc/interrupts viewed again, an entry for IRQ 7 and the port0 driver would appear.

Although IRQ conflicts are rare on modern hardware, they do occasionally still crop up. When this happens, you must reconfigure one or more devices to use different IRQs. This topic is described shortly, in "Configuring Expansion Cards."

# I/O Addresses

I/O addresses (also referred to as I/O ports) are unique locations in memory that are reserved for communications between the CPU and physical hardware devices. I/O addresses are commonly associated with specific devices and should not ordinarily be shared. Table 3.2 lists Linux device filenames along with the equivalent names in Windows, as well as the common IRQ and I/O address settings.

# TABLE 3.2 Common Linux devices

| Linux device | Windows name | Typical IRQ | I/O address |
|---|---|---|--|
| /dev/devtyS0 | COM1 | 4 | 0x03f8 |
| /dev/devtyS1 | COM2 | 3 | 0x02f8 |
| /dev/devtyS2 | COM3 | 4 | 0x03e8 |
| /dev/devtyS3 | COM4 | 3 | 0x02e8 |
| /dev/lp0 | LPT1 | 7 | 0x0378-0x037f |
| /dev/lp1 | LPT2 | 5 | 0x0278-0x027f |
| /dev/fd0 | A: | 6 | 0x03f0-0x03f7 |
| /dev/fd1 | B: | 6 | 0x0370-0x0377 |

> > NOTE Although the use is deprecated, older systems sometimes use /dev/cuax (where x is a number 0 or greater) to indicate an RS-232 serial device. Thus, /dev/devtyS0 and /dev/cua0 refer to the same physical device.
