# Encrypting X Connections with SSH

The SSH protocol is a useful remote-access tool. Although it is considered a text-mode protocol, SSH also has the ability to tunnel network connections—that is, to carry another protocol through its encrypted connection. This feature is most useful for handling remote X access. You can perform the steps described in “Using Remote Clients” but omit steps 3 and 5 and the host command in step 7. This greatly simplifies the login process and adds the benefits of SSH's encryption, which X doesn't provide. On the other hand, SSH's encryption is likely to slow down X access, although if you enable SSH's compression features, this may be reduced in severity. Overall, tunneling through SSH is the preferred method of remote access, particularly when any network in the process isn't totally secure.

SSH tunneling require certain options to be set. In particular, you must either use the -X or -Y option to the ssh client program or set the ForwardX11 or ForwardXTrusted option in /etc/ssh_config on the client system. You must also set the X11Forwarding option to yes in the /etc/sshd_config file on the SSH server system. These options enable SSH's X forwarding feature; without these options, SSH's X won't work.

As a security measure, many Linux distributions configure X to ignore network connections. If your distribution is so configured, the preceding steps won't work; when you try to launch an X program from the remote system, you'll get an error message. To work around this problem, you must make an additional change, depending on how X is located:

+   - GDM Older versions of GDM, check the GDM configuration file (typically /etc/X11/gdm/gdm.conf): look for the line DisallowTCP=true, and change it to read DisallowTCP=false. On newer versions of GDM, edit /etc/gdm/custom.conf, and add a line that reads DisallowTCP=false to the [security] section (adding it if required).
- KDM These two XDMs both rely on Xservers (in /etc/X11/xdm for XDM, and in this location or other highly variable location for KDM). Look for the line that has :0. This line contains the command that KDM or XDM uses to launch the X server. If this line contains -nolist tcp, remove that from the line.

Special OPENUSE Configuration In openSUSE, you must edit /etc/sysconfig/displaymanager and DISPLAYMANAGER_XSERVER_TCP_PORT_6000_OPEN option to yes.
