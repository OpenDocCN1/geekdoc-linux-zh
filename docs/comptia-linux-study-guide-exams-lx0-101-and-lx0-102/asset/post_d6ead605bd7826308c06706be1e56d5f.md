Three compression tools—gzip, bzip2, and xz—are often used with tar, applies compression to the tarball rather than to the individual files. Of the three compression tools, gzip is the oldest and provides the least compression, bzip2 provides improved compression, and xz is the newest and provides the best compression. Typically, files compressed with these utilities have .gz, .bz2, or .xz extensions, respectively. Tarballs use their own special extensions, such as .tgz for gzip or .tb for one compressed with bzip2.

An example of tar in use, consider archiving and compressing the my-work subdirectory of your home directory to a USB flash drive mounted at /media/pen. The following command will do the:

```bash
$ tar cvfz /media/pen/my-work.tgz ~my-work
```

If you transfer this flash drive to another system, mount it at /media/usb/ and to extract the archive, you can do so with another command:

```bash
$ tar xvfz /media/usb/my-work.tgz
```

Instead of using the compression options, you can use a pipe to connect a compression tool to tar when extracting data. For instance, gunzip -c tarball.tgz | tar xvf uncompresses tarball.tgz.

The preceding command creates a subdirectory my-work in the current directory and populates it with the files from the archive. If you don't know what's in an archive, it's a good practice to examine it with the --list command before extracting its contents. Tarballs usually contain a single subdirectory, sometimes tarballs contain many files without a “carrier” subdirectory. Extracting such tarballs drops these files in your current directory, which can make it difficult to determine which files come from the tarball and which were already present.

# The cpio Utility

The cpio program is similar to tar, but the details of its operation differ. With tar, you can direct its output to a tape device or to a regular file. Backing up a tape device can be a convenient way to back up the computer because it requires no intermediate storage. To restore data, you use cpio to read directly from the tape file or a regular file.

The cpio utility has three operating modes:

**Copy-Out Mode**: This, activated by the -o or --create option, creates an archive and copies files into it.

**Copy-In Mode**: You activate copy-in mode by the -i or --extract option. This mode extracts data from an existing archive. If you provide a filename or a pattern to match, cpio extracts only the files that match the pattern you provide.

**Copy-Pass Mode**: This is activated by the -p or --pass-through option. It combines the copy-out and copy-in modes, enabling you to copy a directory tree from one location to another.

The copy-out and copy-in modes are named confusingly. Think of them as referring to copying out of or in the computer's main directory tree, rather than the archive file.

In addition to the options used to select the mode, cpio accepts many other options, the most important of which are summarized in Table 4.3. To create an archive, you combine the --create (or -c) option with one or more of the options in Table 4.3; to restore data, you do the same, but you use --extract (or -i). In either case, cpio acts on filenames that you type in the console. In practice, you'll probably use the redirection operator to pass a filename.

TABLE 4.3: Options for use with cpio

| Option | Abbreviation | Description |
| :--- | :--- | :--- |
| --access-time | -a | Resets access time after reading. |
| --append | -A | Appends data to existing archive. |
| --create | -c | Creates an archive. |
| --file=filename) | -F | Uses specified filename for archive. |
| --format=format | -H | Common values for format include... |
| --input | -I | Uses specified filename as standard input. |
| --no-absolute-filenames | -n | In copy-in mode, extracts relative paths. |
| --output | -O | Uses specified filename as standard output. |
| --list | -t | Displays table of contents. |
| --unconditional | -u | Replaces files without asking. |
| --verbose | -v | Displays filenames as they are added to or extracted. |

To use cpio to archive a directory, you must pass a list of files to standard input. You can do this with the find utility (described later):

```bash
$ find ./my-work | cpio -o > /media/usb/my-work.cpio
```

The resulting archive is uncompressed. To compress the data, you must include a compression utility, such as gzip, in the pipe:

```bash
$ find ./my-work | cpio -o | gzip > /media/usb/my-work.cpio
```

Extracting data from an uncompressed archive (say, on another computer with the file mounted at /media/usb) entails using the -i option, but no pipe is required:

```bash
$ cpio -i < /media/usb/my-work.cpio
```

If your archive is compressed, you must decompress it with gunzip. By using the -c option to this, you can pass its output to cpio in a pipe:

```bash
$ gunzip -c /media/usb/my-work.cpio.gz | cpio -i
```

To decompress an compressed archive with bzip2, you would use bunzip2 -c in the pipe rather than gunzip -c. If the archive is compressed with xz, you would use unxz -b in the pipe.

# The dd Utility

Sometimes you want to archive a filesystem at a very low level. For instance, you may want to create a representation of a CD-ROM that you can store on your hard disk or back up a filesystem Linux can't understand. To do so, you can use the dd command. This utility is a low-level copying program, and when you give it the device file for a partition as input, it copies that partition's contents to the output file you specify. This output file can be another partition identifier, a tape device, or a regular file, to name.

```bash
$ dd if=/dev/sda3 of=/dev/st0
```

This command backs up the /dev/sda3 partition to /dev/st0 (a SCSI tape drive). The result is a very low-level backup of the partition that can be restored by swapping the if and of= options:

```bash
$ dd if=/dev/st0 of=/dev/sda3
```
