

# 配置 NTP 服务器

当你设置网络以使用 NTP 时，请选择一个系统（对于连接有几十个或更多计算机的网络，可能需要选择两个）作为主 NTP 服务器。你的计算机不需要非常强大，但它必须能够始终访问互联网。你可以安装 NTP 服务器并对其进行配置。

大多数 Linux 发行版都通过一个名为 `ntp` 或 `ntpd` 的包分发 NTP 软件。寻找此包，如果它尚未安装，请安装它。如果你能找到此包，可以检查 http://www.ntp.org/downloads.html。该网站托管 NTP 源代码，你可以对其进行编译和安装。如果你没有安装发行发行版的 NTP 包，你将需要创建自己的 SysV 启动脚本，或者通过其他方式启动 NTP 守护进程。

一旦安装了 NTP，寻找它的配置文件 `/etc/ntp.conf`。此文件包含各种 NTP 选项，但最重要的的是服务器行：

```
server clock.example
server ntp.pangeea.com
server time.luna.com
```

这些行中的每一行都指向一个 NTP 服务器。当你的本地 NTP 守护进程启动时，它会连接 `/etc/ntp.conf` 中指定的所有服务器，测量它们之间的准确性，并确定其中一个作为它的主源。通常，你为一个系统列出三个上游服务器，这允许你过滤掉任何提供错误时间的服务器，并且当上游服务器临时或永久不可用时，它可以提供自动回退。如果你的 NTP 服务器本身没有为许多计算机提供服务，你可能想最初将其配置为三个服务器，然后在两天后删除你不再使用的作为主源的系统。这将减少你服务器的负载。

你可能想要清理你的配置文件以移除不需要的条目。例如，配置文件可能包含对你不会使用的服务器的引用，或其他带有注释的选项，这些注释让你认为它们是不适当的。通常情况下，除了引用服务器行外，你不应该调整 `ntp.conf` 文件中的条目，特殊配置或默认文件可能让你进行更改。

一旦你完成了更改，启动或重启你的 NTP 守护进程。通常，这是通过 SysV 启动脚本实现的：

```
# /etc/init.d/ntp restart
```

在第一次启动 NTP 时，你可能需要更改文件路径、SysV 脚本文件名或选项（将 `restart` 改为 `start`）。大多数发行版在配置第 5 章“启动 Linux 和编辑文件”时提供了更改此配置的详细说明。

要验证你的 NTP 是否运行，请使用 `ntp`，它是一个接受各种命令的交互式程序。图 7.2 显示了它的运行，显示了 `peers` 命令的输出，该命令显示了你的 NTP 服务器连接的服务器。在图 7.2 中，列出了三个外部服务器，加上 `LOCAL(0)`，这是你计算机时钟最后的参考源。`refid` 列显示了每个系统同步的服务器，`st` 列显示了服务器的层级（stratum），其他列显示了更多技术信息。与你的系统同步的服务器用星号 (`*`) 表示，具有良好时间的其他服务器用加号 (`+`) 表示，其他符号（如 `x` 和 `-`）表示由于各种原因丢弃的服务器。你可以通过向 `ntpq` 传递 `-p` 或 `-peers` 来获取列表，例如在交互模式下使用 `ntpq -p`。控制台 `ntpq` 的 man 页面提供了关于其操作的更多信息。

# 图 7.2 `ntpq` 程序允许你验证 NTP 服务器是否运行正常。

```
ntpq
remote peers      refid             st reach poll delay  offset Jitter
=====================================================================
clock,example.c 128.227.205.3      2   186 377  23.016 -0.624 10.787
tppega.de       172.21.152.1      2   186 377  41.664  0.018 1.528
time,luna       18.145.0.30      10   186 377  20.183 -0.223 0.366
ntpq            LOCAL(0)          10   186 377   0.000  0.000 0.001
```

在你重启 NTP 守护进程几分钟之后，你才会看到某个服务器作为源。这是因为你的本地 NTP 进程需要一段时间时间来确定哪个源提供了最佳信号。

# 配置 NTP 客户端

一旦你配置了一个或多个 NTP 服务器，你就可以配置你的其余计算机指向它们。配置工作只需在少数例外外即可完成：

- 你将你的 NTP 客户端设置为引用你配置的 NTP 服务器（或多个服务器），而不是外部 NTP 源。这样，你的本地系统就不会对你选择的外部 NTP 服务器产生不必要的负担。
- 你确保你的 NTP 客户端不能作为服务器被访问。这是一个安全措施。你可以通过 `iptables` 规则或使用 `ntpq.conf` 中的 `restrict default ignore` 行来实现此。此行告诉服务器忽略所有入站的 NTP 请求。理想情况下，你应该同时使用这两种方法。

一旦你配置了客户端，重启你的 NTP 守护进程。然后你可以使用 `ntpq` 检查其状态。你应该看到它只引用你网络自己的服务器。这些系统应该被列为属于某个层级。# 第 7 章 管理系统

在某些情况下，更简单的方法是使用 SysV 启动脚本来设置时间。在 Linux 中，你可以是：

```
/etc/init.d/ntp
```

大多数发行版在第 5 章，“启动 Linux 和编辑文件”中配置了更改此配置的详细说明。
