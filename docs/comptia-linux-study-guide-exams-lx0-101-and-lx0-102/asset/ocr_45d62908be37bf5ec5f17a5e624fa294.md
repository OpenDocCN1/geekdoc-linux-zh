Valid codes for the priority debug, info, notice, warning, warn, error, err, crit, alert, emerg, and panic. The warning priority is identical to warn, error is identical to err, and emerg is identical to panic. The error, warn, and panic priority names are deprecated; you should use their equivalents instead. Other than these identical pairs, priorities represent ascending levels of importance. The debug level logs the most information; the emerg level logs the least. The emerg priority logs the most important messages, which indicate very serious problems. When a program sends a message to the system logger, it includes a priority code; the logger logs the message to a file if configured to log messages of that level or higher. If you specify a priority code of all, the system will log messages that are classified as alert or emerg but not crit. An exception to this rule is if you precede the priority code by an equal sign (=), as in crit, which describes what to do with messages of priority crit. For instance, crit causes messages below crit to be logged. A priority of * reverses the meaning of a match and refers to all facilities.

You can specify multiple selectors for a single action by separating the selectors with a semicolon (;). Note that commas are used to separate multiple facilities within a single selector; whereas semicolons are used to separate multiple selectors for a while. Examples of completes answer shortly.

Most commonly, the log is a filename, located in the /var/log directory tree. The messages, syslog and secure files in this directory contain many important log files, although not distributions use all of these. Other possible locations include a device filename for a console (such as /dev/console) to display data on the screen, a remote machine preceded by an @ to log to the specified system, and a list of individuals who would see the message if they're logged in. For some of these options, an asterisk (*) means logged-in users.

Some examples help clarify these rules. First is a fairly ordinary and simple example:

```
mail.*    /var/log/mail
This line logs all entries identified by the originating program related to mail to the /var/log/mail file. Most of the entries in a default /etc/syslog.conf resemble this one. Together, they typically cover all of the facilities mentioned earlier. Some messages may be handled by multiple rules. For instance, another rule might look like this:
```

```
This line sends all emerg-level messages to the consoles of all users who are logged into the computer using text-mode tools. If this line or the earlier mail.* selector are both present, emerg-level messages related to mail will be logged to /var/log/mail and displayed on users' consoles.
```
