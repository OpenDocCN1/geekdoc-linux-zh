# When to Create Multiple Partitions

One problem with splitting off lots of partitions, particularly for new administrators, is that it can be difficult to settle on appropriate partition sizes. As noted in Table 3.4, the appropriate size of various partitions can vary substantially from one system to another. For instance, a workstation is likely to need a fairly small /var (say, 100MiB), but a mail or news server may need a /var partition that is gigabytes in size. Guessing wrong isn't fatal, but it is annoying. You'll need to resize your partitions (which is tedious) or set up symbolic links between partitions so that subdirectories are on other partitions. LVM can simplify such after-the-fact changes, but as noted earlier, LVM adds its own complexity.

For this reason, I generally recommend that new Linux administrators use simple partition layouts. The root (/) partition is required, and swap is a very good idea. Beyond this, /boot can be kept on hard disks of more 8GB with older distributions or BIOS which is seldom needed since 2000. As data (in home or elsewhere), most Linux installations in 2012 require 5–25GB, so appropriate size for /home is relatively easy for new administrators to guess, or you can devote all your disk space after creating root (/) and swap to /home. Beyond these points, I recommend that new administrators proceed with caution.

As you gain more experience with Linux, you may want to break out other directories into their own partitions on subsequent installations or when upgrading disk hardware. You use the du command to learn how much space is used by files within any given directory.

# Partitioning a Disk

The traditional Linux tool for disk partitioning is called fdisk. This tool name is short for fixed disk, and the name is the same as a DOS and Windows tool that accomplishes the same task. (When I refer to the DOS/Windows tool, I capitalize its name, as in FDISK. This tool's name is always either lowercase.) Both DOS's FDISK and Linux's fdisk are very different in operational details.

Although fdisk is the traditional tool, several others exist. One of these is GNU Parted, which can handle several different partition table types, not just the MBR that fdisk handle. If you prefer fdisk to GPTed but must use GPT, you can use GPT fdisk
