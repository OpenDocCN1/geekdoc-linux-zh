When you are installing Type 1 fonts, Linux needs the fonts with names that end in .pfa or .pfb; these fonts contain the actual font data. The .pfa and .pfb store the data in slightly different formats, but the two files are equivalent.) Additional fonts distributed with Type 1 fonts are not necessary for Linux. Linux uses fonts in the same format as Mac OS, Windows, OS/2, and most other OSs. Earlier versions of Mac OS used font files in format Macintosh—“suitcases,” which Linux cannot use directly. If you want to use fonts in Linux, you must convert them. The FontForge program (http://fontforge.sourceforge.net) can do this conversion, among other things.

Once you've copied fonts to a directory, you prepare a summary file that describes the fonts. This file is called .dir, and it begins with a line that specifies the name of fonts that are described. Subsequent lines provide a font name and a logical font description (XLFD), which is a tedious-looking description of the font. A complete fonts .dir line can be reterinating:

```
courb.pfa -ibm-Courier-bold-r-normal--0-0-0-0-m-0-iso-iso8859-1
```

Fortunately, you needn't create this file manually; programs exist to do so automatically. In XFree86 4.3 and in X.org-X11, the simplest way to do the job is to use mkfontscale:

```
# mkfontsscale
# mkfontsdir
```

The mkfontsscale program reads all the fonts in the current directory and creates a .scale file, which is just like a .dir file but describes only outline fonts. The mkfontsdir program combines the .scale file with the .dir file, creating it if it doesn't already exist.

Other programs to perform this task also exist. Most notably, tmkfontdir creates a .dir file that describes TrueType fonts, and type1font does the job for Type 1 fonts. The mkfontscale program is preferable because it handles both font types, but if you're using an older distribution that lacks this program or if it's not doing a satisfactory job, you can try one of these alternative programs.
