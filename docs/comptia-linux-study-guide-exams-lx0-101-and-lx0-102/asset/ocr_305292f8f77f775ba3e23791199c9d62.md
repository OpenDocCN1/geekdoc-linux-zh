# Displaying Shared Library Dependencies

If you run programs that don't launch because of missing libraries, the first step is to check which libraries the program use. You can do this with the ldd command:

```
$ ldd /bin/ls
librt.so.1 => /lib/rt.so.1 (0x00000002a956c000)
libcurses.so.5 => /lib/libcurses.so.5 (0x00000002a95784000)
libcacl.so.1 => /lib/libcacl.so.1 (0x00000002a958eae000)
libc.so.6 => /lib/libc.so.6 (0x00000002a959f10000)
libthread.so.0 => /lib/libthread.so.0 (0x00000002a95c17000)
lib64-ld-linux-x86-64.so.2 (0x00000002a95560000)
libattr.so.1 => /lib/libattr.so.1 (0x00000002a95d5ad000)
```

Each line of output begins with a library name, such as librt.so.1 or libcurses.so.5. If the library does not contain a complete path, ldd attempts to find the library and displays the complete path with symbol =>, as in /lib/libcurses.so.5. You needn't be concerned about the long hexadecimal number following the complete path to the library. The preceding example shows /lib64/ld-linux-x86-64.so.2) that refers to a complete path in the executable file.

The ldd command accepts a few options. The most notable of these is probably -v, which displays a list of version information following the main entry. This information may be helpful in tracking which version of a library a program is using, in case you have multiple versions installed.

Keep in mind that libraries themselves depend on other libraries. Thus, you can use ldd to discover which libraries are used by a library. Because of this potential for a dependency chain, it's possible that a program will fail to run though all its libraries are present. Using ldd to track down problems, be sure to check the needs of all the libraries of the program, and all the libraries used by the first tier of libraries, and so on, until you've exhausted the chain.

The ldd utility can be run by ordinary users, as well as root. You must run it as root if you can't read the program as an ordinary user.

# Rebuilding the Library Cache

Linux (or, more precisely, the ld.so and ld-linux.so programs, which manage the loading of libraries) every time a program runs. Instead, the system relies on a cached list of directories and the files they contain, stored in binary format in a format that's much more efficient than a plain-text list of files and directories. The drawback is that you must rebuild that cache every time you add or remove libraries. These additions and removals include both changing the contents of the library directories and removing library directories.

The tool to do this is called ldconfig. Ordinarily, it works without any options:

```
# ldconfig
```
