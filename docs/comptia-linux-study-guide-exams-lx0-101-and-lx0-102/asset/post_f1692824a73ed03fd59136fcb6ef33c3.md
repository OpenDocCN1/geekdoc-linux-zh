All OSs run atop hardware, and this hardware influences how the OSs run. Most obviously, hardware can be fast or slow, reliable or unreliable. Somewhat more subtly, OSs provide various—means of configuring and accessing the hardware—interface standards, disk partitioning, how to track disk usage, reading data from Universal Serial Bus (USB) devices, for instance. You must understand at least the basics of how Linux interacts with the hardware environment in order to effectively administer a Linux system, so this chapter provides that information.

This chapter begins with a look at firmware, which is the lowest-level software that runs on a computer. A computer's firmware begins the boot process and configures certain hardware-devices. This chapter then moves on on expansion cards and USB devices.

This chapter concludes with an examination of disk hardware and the filesystems it contains—disk partitioning, how to tune filesystems for optimal performance, how to check filesystems' internal consistency, and how to repair simple filesystem defects. Assuming a filesystem is in good shape, you may be able to mount it to be able to use it, so that topic is also covered here. (One topic, boot managers, is covered in Chapter 5, "Booting Linux and Editing Files.")

# Configuring the Firmware and Core Hardware

All computers start with a set of core hardware—most obviously, a central processing unit (CPU), which does the bulk of the computational work, and random access memory (RAM), which holds data. Many additional basic features help glue everything together, and some of these can be configured both inside and outside of Linux. At the heart of this hardware is the firmware, which provides configuration tools and initiates the OS booting process. You can use the firmware's user interface to enable and disable key hardware components, once Linux is booted, you may need to manage this hardware using Linux utilities. Key components managed by the firmware (and, once it's booted, Linux) include interrupts, I/O addresses, DMA addresses, the real-time clock, and Advanced Technology Attachment (ATA) hard disk interfaces.

# Understanding the Role of the Firmware

Many hardware devices include firmware, so any given computer can have many types of firmware installed—for the motherboard, for a plug-in disk controller, for modems, and so on. The most important firmware, though, is installed on the computer's motherboard. This initializes the motherboard's hardware and controls the boot process. In the past, the vast majority of x86 and x86-64-based computers have used a type of firmware known as the Basic Input/Output System (BIOS). Beginning in 2011, a new type of firmware, known as the Extensible Firmware Interface (EFI) or the Unified EFI (UEFI), has become all but standard on new computers. Some older computers use UEFI. Despite the fact that EFI is technically a BIOS, most manufacturers refer to it by name in their documentation. The exam objectives refer to the BIOS, but not to EFI. Nevertheless, in the real world you're likely to encounter EFI on newer computers. The differences between BIOS and EFI are particularly important, as described in Chapter 5.

The motherboard's firmware resides in erasable programmable read-only memory (EEPROM), flash memory. When you turn on a computer, the firmware performs power-on-test (POST), initializes hardware to a known state, and loads the boot loader. Historically, a further purpose of BIOS was to provide fundamental input/output (I/O) services to the operating system and application programs.

> In this book, I use the term EFI to refer to newer UEFI.

Older PowerPC-based Macs use OpenFirmware (Intel-based Macs use UEFI). Although OpenFirmware, EFI, and other programs differ, if you must administer a computer with unusual firmware, you should take some time to research how its operates.
