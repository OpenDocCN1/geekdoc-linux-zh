# Chapter 7 • Administering the System

+   A slash, used in conjunction with some other multi-value option, specifies stepped values—a range in which some members are skipped. For instance, */10 in the minute field indicates a job's runs every 10 minutes.

After the first fields, /etc/cronontab entries continue with the account name to be used when executing the program (root in the following example) and the command to run (run-parts /etc/cron.daily in this example). The default /etc/cronontab entries generally use run-parts, cronloop, or a similar utility that runs any executable within a directory. The preceding execution runs all scripts in /etc/cron.daily at 4:02 a.m. every day. Most distributions include monthly, daily, weekly, and system cron jobs, each corresponding to scripts in a directory called /etc/cron.interval, where interval is a word associated with the frequency. Others place these scripts in /etc/cron.d/interval directories.

The exact times chosen for system cron jobs to vary from one to another. Normally, daily and longer-interval cron jobs run early in the morning—before midnight and 6:00 a.m. Check your /etc/crontab to determine when your system cron runs.

To create a new system job, you may create a script to perform the task you want (as described in Chapter 9, “Writing Scripts, Configuring Email, and Using Databases”) and copy that script to the appropriate /etc/cron.interval directory. When the runtime runs around, cron will run the script.

Before submitting a script as a cron job, test it thoroughly. This is particularly important if the cron job will run when you're not around. You don't want a bug in your cron job script to cause problems by filling the hard disk with useless files or producing thousands of email messages when you are not present to quickly correct the problem.

If you need to run a cron job at a time interval or via /etc/cronontab, you can either modify the file to change or add the cron job runtime or create a cron job, as described shortly. If you choose to modify the system cron job facility, model your changes over an existing entry, changing the times and cron storage directory as required.

![](bbox=[0.135, 0.795, 0.225, 0.825])

System cron job storage directories should be owned by root, and only root be able to write to them. If ordinary users can write to a system cron directory, unscrupulous users can write scripts to give themselves superuser privileges and place them in the system cron directory. The next time cron runs these scripts, the users will gain full administrative access to the system.
