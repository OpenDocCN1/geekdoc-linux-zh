# Chapter 7 • Administering the System

In some cases, a simpler way to set the time on a client is to use nptdate. This program is part of the NTP suite, and it performs a one-time clock setting. To use it, type the command name followed by the hostname or IP address of an NTP server:

```
# ntpdate clock.example.com
```

Some NTP packages include a call to nptdate in their NTP daemon startup scripts in order to ensure that the system is set to the correct time when it starts. The nptdate command, has been deprecated and could disappear from the NTP package at any time. Instead, you can start nptdate with its -g option, which enables it to perform a one-time clock setting to a value that's wildly different from the current time. (Ordinarily, nptpd exits if the system time differs by more than five minutes.)

# Serving Time to Windows Systems

If your network hosts both Linux and Windows computers, you may want to use a Linux system as a time source for Windows clients or conceivably use a Windows server as a time source for Linux clients. One way to do this is to run NTP on Windows. Consult http://www.meinberg.org/english/ntp.htm or perform a Web search to locate NTP software for Windows. For Windows 2000/XP/Vista, you can type NET TIME /SETSNP:time.server, where time.server is the name of your local NTP server. This command performs a one-time setting of the clock but doesn't run in the back-ground like the full NTP package does on Linux. Running this command in a Windows login script may be adequate for your purposes. Windows 7 users can use W32TIME /CONFIG /MANUALPEELIST:time.server instead of the NET TIME command.

For older Windows 9x/Me, you can type NET TIME \SERVER /SET /YES to have the system set the time maintained by SERVER, which must be a Windows or Samba file or print server. This command doesn't use NTP, but if you have a Linux system that runs both NTP and Samba, it can be a good way to get the job done.

# Running Jobs in the Future

Some maintenance tasks should be performed at regular intervals and are highly automated. For instance, the /tmp directory which holds temporary files created by many users to collect useless data files, which may want to delete. Linux provides a means of scheduling tasks to run at specified times to handle such issues. This tool is the cron program, which runs as cron jobs. A related tool is at, which enables you to run a command on a one-time basis in the future as opposed to doing so on a regular basis, as cron does.
