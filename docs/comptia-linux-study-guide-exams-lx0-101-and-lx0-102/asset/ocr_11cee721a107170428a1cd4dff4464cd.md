# Locating Files 209

Like the FSSTND, the FHS comes in numbered versions. Version 2.3, the latest version as I write, was released in January 2004. The URL for FHS's official Web page is http://www.pathname.com/fhs/.

Some Linux vendors—most notably Fedora—are beginning to make changes that deviate from the FHS. For instance, Fedora 17 and later now place all binaries in /usr/bin and /usr/sbin. The /bin directory is a symbolic link to /usr/bin, and /sbin to /sbin. This layout complicates some types of configurations, such as those that require a separate /sbin partition.

# Important Directories and Their Contents

The FHS defines some directories precisely, but details for others are left unresolved. For instance, users files normally in the /home directory, but you may have reason to call this else or use two or more separate directories for users' files. Overall, the most common directories defined by the FHS or by convention are the following:

+   * Every Linux filesystem tree its roots to a single directory, known as / (pronounced, and often referred to, as root filesystem or directory). All other directories branch off this one. Linux does not use drives; every filesystem is mounted at a point within another partition (/ or something else). Critical subdirectories, such as /etc and /sbin, must reside on the root partition, but others can be on separate partitions.boot static and unreachable files related to the initial booting of the computer.

/boot directory contains static and unreachable files related to the initial booting of the computer. Higher-level startup and configuration files reside in another directory;/etc. Some systems impose particular limits on /boot. For instance, x86 BIOSs and older versions of the Linux Loader (LILO) may require that /boot reside below the 1,024 cylinder of the disk. Similarly, EFI boot methods work best with a /boot partition that uses ext2 or ReiserFS. These requirements sometimes, but not always, necessitate that the /boot be a separate partition.

/bin This directory contains critical executable files, such as /ls, cp, and mount. These commands are accessible to all users and constitute the most important commands that ordinary users use. You will not find commands for big application programs in /bin (although the Vi editor is located here). The /bin directory contains static files. In some sense the /bin files are shareable, they're so important to the basic operation of a computer, the directory is almost never shared—any potential clients must have their local /bin directories.

/sbin This directory is similar to /bin, but it contains programs that are normally run only by the system administrator—tools like fdisk and effsck. It's static and theoretically shareable, but in practice, it makes no sense to share it.
