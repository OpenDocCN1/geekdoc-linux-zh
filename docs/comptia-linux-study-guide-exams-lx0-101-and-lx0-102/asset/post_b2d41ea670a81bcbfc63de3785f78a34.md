Another way of expressing a netmask is a single number representing the number of network bits in the address. This number usually follows the IP address and a slash. For instance, 172.30.9.102/16 is equal to 172.30.9.102 with a netmask of 255.255.0.0—the last number shows the network portion to two solid 8-bit bytes and is 16 bits. The longer notation using all 4 bits of the mask is referred to as *dotted quad notation*. IPv6 networks work just like IPv4 networks, except that larger numbers are used instead of IPv4; IPv6 addresses use hexadecimal decimal notation.

On IPv4 networks, netmasks are often described in *Classless Inter-Domain Routing (CIDR)* form. Each network can be broken at any bit boundary for any address. For instance, 172.168.1.7 could have a netmask of 255.255.0.0, 255.255.255.0, 255.255.255.255, or other values. (Keeping each bit at 0 or 255 reduces the odds of human error causing problems but seems impractical, depending on the required or desired sizes.) Traditionally, IPv4 networks have been broken into one of several classes, summarized in Table 8.1. Classes A, B, and C are for general networking use. Class D addresses are reserved for *multicasting*—sending data to multiple computers simultaneously. Class E addresses are reserved for future use. There are special cases within some of these ranges. For instance, the 127.x.y.z addresses are reserved for *loopback* (aka *localhost*) addresses—these addresses refer to the computer on which the address enters. Addresses in which all the machine bits are set to 1 refer to the network block itself—they’re used for broadcast address 255.*255.*, which sends data to all computers on a network segment. (Routers normally block packets delivered to this address. If they didn't, the Internet could easily be brought to its knees by a few people flooding the network with broadcast packets.)

# Understanding Network Addressing

Within each of the three general-use network classes is a range of addresses reserved for private use. Most IP addresses must be assigned to individual computers by suitability; two systems on the Internet try to use a single address. Anybody can use the reserved private address spaces, though. (These address blocks are sometimes referred to as RFC1918 addresses, after the standards document—RFC1918—in which they’re defined.) The caveat is that routers normally drop packets to these addresses, effectively isolating them from the Internet as whole. The idea is that these addresses may be safely used by small private networks. Today, they are often used behind Network Address Translation (NAT) routers, which enable arbitrary numbers of computers to “hide” behind a single system. The NAT router substitutes its own IP address on outgoing packets and directs them to the correct system. This is very handy if you want to connect more computers to the Internet than you have IP addresses.

> NOTE: I generally reserved private addresses for examples in this book. Unless otherwise specified, these examples work well on convention-assigned (non-private) IP addresses.

IPv6 has its equivalent to private addresses. IPv6 site-local addresses may be routed within a site but off-site. They begin with the hexadecimal number fec, fed, fee, or fef. Link-local addresses are restricted to a single network segment; they should not be routed at all. These addresses begin with the hexadecimal number fe8, fe9, fea, or feb. IPv4 classes were designed for simple routing; but as the Internet grew, they became restrictive. Thus, they serve mainly as a way to set default masks, such as 255.0.0.0 for Class A or Class C. Most configuration tools set these masks automatically, but you can override the settings if necessary. IP addresses and networks are extremely important for network configuration. If your network doesn’t use DHCP to assign IP addresses automatically, you must configure your system’s IP address manually. A mistake in this configuration can cause a complete failure of networking or subtle errors, such as an inability to communicate with some computers.

> NOTE: NetBEUI/IP stacks have their own addressing methods. NetBEUI uses machine names; it has no separate numeric addressing method. AppleTalk uses two 16-bit numbers. These addressing schemes are independent from IP addresses.

# Broadcasting Data

Earlier, I mentioned broadcasts. A broadcast is a type of network transmission that's sent to all the computers on a local network, or occasionally all the computers on a local network. In many cases, a broadcast is defined by the address 255.255.255, which sends data to all computers on a network segment. (Routers normally block packets delivered to this address. If they didn't, the Internet could easily be brought to its knees by a few people flooding the network with broadcast packets.)
