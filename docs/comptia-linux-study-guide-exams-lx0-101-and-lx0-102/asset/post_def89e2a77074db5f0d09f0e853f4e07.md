
## Configuring X Fonts

If you're adding fonts you've downloaded from the Internet or obtained from a commercial font CD-ROM, you may want to store these additional fonts elsewhere, such as /opt/fonts or /usr/local/fonts. (Chapter 4, “Managing Files,” includes information about the logic behind Linux’s directory system.) You may want to create subdirectories for fonts in different formats or from different sources.

When you are installing Type 1 fonts, Linux needs the fonts with names that end in .pfa or .pfb; these fonts contain the actual font data. The .pfa and .pfb store the data in slightly different formats, but the two files are equivalent. Additional fonts distributed with Type 1 fonts are not necessary for Linux. TrueType fonts as .ttf files, and that's all you need for Linux.

![](img/35f616c7eba4e79e12bfd762129c5d27_339_0.png)

Linux uses fonts in the same format as Mac OS, Windows, OS/2, and most other OSs. Earlier versions of Mac OS used font files in format Macintosh—“suitcases,” which Linux cannot use directly. If you want to use fonts in Linux, you must convert them. The FontForge program (http://fontforge.sourceforge.net) can do this conversion, among other things.

Once you've copied fonts to a directory, you prepare a summary file that describes the fonts. This file is called .dir, and it begins with a line that specifies the name of fonts that are described. Subsequent lines provide a font name and a logical font description (XLFD), which is a tedious-looking description of the font. A complete fonts .dir line can be reterminated:

```
courb.pfa -ibm-Courier-bold-r-normal--0-0-0-0-m-0-iso-iso8859-1
```

Fortunately, you needn't create this file manually; programs exist to do so automatically. In XFree86 4.3 and in X.org-X11, the simplest way to do the job is to use mkfontscale:

```bash
# mkfontscale
# mkfontsdir
```

The mkfontscale program reads all the fonts in the current directory and creates a .scale file, which is just like a .dir file but describes only outline fonts. The mkfontsdir program combines the .scale file with the .dir file, creating it if it doesn't already exist.

Other programs to perform this task also exist. Most notably, tmkfontdir creates a .dir file that describes TrueType fonts, and type1font does the job for Type 1 fonts. The mkfontscale program is preferable because it handles both font types, but if you're using an older distribution that lacks this program or if it's not doing a satisfactory job, you can try one of these alternative programs.

## Adding Fonts to X’s Font Path

Once you've set up fonts in a directory and created a fonts.dir file describing them, you must add the fonts to the X font path. You do this by editing the Files section of the XF86Config or xorg.conf file:

Section "Files":

```
FontPath /usr/share/fonts/100dpi:unscaled
FontPath /usr/share/fonts/Type1
FontPath /usr/share/fonts/truetype
FontPath /usr/share/fonts/URW
FontPath /usr/share/fonts/Speedo
FontPath /usr/share/fonts/100dpi
EndSection
```

![](img/35f616c7eba4e79e12bfd762129c5d27_340_0.png)

To add your new font directory to the font path, duplicate one of the existing FontPath lines, and change the directory specification to point to your new directory. The order of these directories is significant: when matching fonts, X traces each directory in turn, so if two fonts hold of the same name, the first one takes precedence. Thus, if you want your new fonts to override any existing fonts, place the new directory at the top of the list; if you want fonts to take precedence, add your directory to the end of the list.

> The :unscaled string in the first entry in the preceding example tells X to use bitmap fonts from this directory only if they exactly match the requested font size. Without this string, X will attempt to scale bitmap fonts from a directory (with poor results). Typically, bitmap directories are listed twice: once near the top of the font path with the :unscaled specification and again near the bottom of the list with :. This produces quick display of matching mapped fonts, followed by any matching fonts, followed by scaled bitmaps.

![](img/35f616c7eba4e79e12bfd762129c5d27_340_1.png)

Once you've added your font directory to X’s font path, you should test the configuration. The most reliable way to do this is to shut down X and restart it. (If your system boots directly into X, consult “Running an XDMCP Server” for information on doing this.) A quicker approach, but one that presents some opportunity for error, is to add the font path to a running system using the xset program:

```bash
$ xset fp+ /your/font/directory
$ xset fp refresh
```

The first of these commands adds /your/font/directory to the end of the font path. (Substitute +fp for fp+ to add the directory to the start of the existing font path.) The second command tells X to re-examine all the font directories to rebuild the list of available fonts. The result is that you should now be able to access the new fonts. (You'll need to restart any programs that use the new fonts.) One program to quickly test the matter xfont enables to select an X core font for display so you can check if the fonts you've added are available and display as you expect.

## Configuring a Font Server

A font server is how windy to deliver fonts to many computers from a central location. This can be a great time-saver if you want to add fonts to many computers—set them up to use a font server and tweak that server's font configuration. ## Chapter 6 • Configuring the X System, Localization, and Printing

X core fonts (including fonts delivered via a server) have several important drawbacks:

- They aren't easy to integrate between the screen display and printed output. This makes them awkward from the point of view of word processing or other applications that produce printed output.
- They're server-based. This means applications may not be able to directly access the font files because the fonts on a different computer than the application. This can exacerbate the integration problem.
- They provide limited or no support for kerning and other advanced features. Again, this is a problem for word processing programs and other programs that must generate printed output.
- They don't support font smoothing (aka anti-aliasing). This technology employs grey pixels (rather than black or white pixels) along curves to create an illusion of greater resolution than the display can produce.
