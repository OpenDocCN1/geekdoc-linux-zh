No matter how you run anacron, you should be sure to disable any cron jobs now. If you don't, those tasks will be performed twice, which may needlessly burden your system. Because anacron measures its run intervals in days, it's a useful utility for running hourly cron jobs. Thus, you shouldn't eliminate any hourly cron jobs when you edit your cron configuration for anacron.

# Using at

Cron jobs and anacron are overkill. You may simply want to run a single command at a specific point in the future on a one-time basis rather than on an ongoing basis. This link provides another: at. In ordinary use, this command takes a single option (although options to fine-tune its behavior are also available): a. This time can take any of several forms:

**Time of Day** You can specify the time of day as HH:MM, optionally followed by AM or PM if you use a 12-hour format. If the specified time has already passed, the operation is scheduled for the next occurrence of that—that is, for the next day.

**noon, midnight, or teatime** These three keywords stand for what you'd expect (teatime 4:00 p.m.).

**Day Specification** To schedule at job more than 24 hours in, you must add a date after the time-of-day specification. This can be done in numeric format MMDY, MM/DD or YY DD.MM. YY. Alternatively, you can specify the date by month-name day or month-name year.

**A Specified Period in the Future** You can specify a time using the keyword now, a plus sign (+), and a time period, as in now = 2 hours to run a job in two hours.

The command runs on a daemon, atd, to be running. If your system doesn't start automatically, you may need to configure a startup script to do so.
