# Listing 9.3: Script assignment and usage of it

```
#!/bin/sh
ip='route -n | grep UG | tr -s ' ' ' | cut -f 2 -d ' ''
ping='/bin/ping'
echo "Checking if $ip is up..."
$ping -c 5 $ip
```

In practice, use Listing 9.3 by typing the script's name. The result should be the Checking if 192.168.1.1 is up (with 192.168.1.1 replaced by the computer's default gateway system) and the output from the ping command, which should attempt to send five pings to the router. If the router is up and configured to respond to pings, you will see five return packets and summary information. If the router is down, you will see error messages to check that the host was unreachable.

> Listing 9.3 is of limited practice and contains bags. For instance, the script identifies the computer's gateway merely by the presence of the STRING in the router's output from route. If a computer has two routers defined, this won't work correctly, and the result is likely to be a script that misbehaves. The point of Listing 9.3 is not to be a flawless program but demonstrate how variables can be assigned and used.

Scripts like Listing 9.3, which obtain information from running one or more commands, are useful in configuring features that rely on system-specific information or information that varies with times. You can use a similar approach to check the current hostname (using the hostname command), the current time (using date), the time the computer's running (running uptime), free disk space (using df), and so on. When combined with conditional expressions (described shortly), variables become even more powerful because then you can perform one action when one condition is met, and in some other case. For instance, a script can install software that check free disk space and the installation if insufficient disk space is available.

In addition to assigning variables with the assignment operator (=), you can read variables from standard input using read, as in response to read input for subsequent access as $response. This method of variable assignment is useful for scripts that must interact with users. For instance, instead of reading the username from the command line, Listing 9.2 may be modified to prompt the user for the username. Listing 9.4 shows the result. To use this script, you type without username on the command line. The script will prompt for a username, and after you enter it, the script will attempt to create an account with that name.
