# Installing Boot Loaders

This description provides a somewhat simplified view of boot loaders. Most Linux loaders are much more complex than this. They can redirect the boot process to non-Linux boot sectors and present menus that enable you to boot multiple OSs or multiple Linux kernels. You can chain several boot loaders, including third-party boot loaders such as System Commander or BootMagic. Chaining boot loaders in this way enables you to take advantage of unique features of multiple boot loaders, such as the ability of System Commander to boot several versions of DOS or Windows on a single partition.

> The exam's objective 102.2 mentions the superblock. Despite its placement in an objective about boot loaders, the superblock isn't really a boot loader concept; rather, it is part of the filesystem. The superblock describes basic filesystem features, as the filesystem's size and status. The debugfs and dumpfs commands, described in Chapter 3, provide basic superblock information. On BIOS-based computers, the superblock can hold a portion of the boot loader, so damage to it can cause boot problems.

# EFI Boot Loader Principles

The BIOS boot process, as described, was designed in the 1980s, with the speed available for a BIOS in the computer's firmware was today's standards. Thus, the boot process had to be very simple, and a great deal of the complexity had to be pushed into software stored on the hard disk.

The newer EFI firmware is much more complex than the older BIOS, and so its boot process can be more sophisticated. Instead of relying on files stored in boot sectors or on the hard disk, EFI relies on boot loaders stored in a disk partition, known as the EFI System Partition (ESP), which uses the File Allocation Table (FAT) filesystem. Under Linux, the ESP is typically mounted at /boot/efi. Boot loaders reside in files with .efi extensions in subdirectories named after the OS or boot loader name under the EFI subdirectory of the ESP. Thus, you might have a boot loader /boot/efi/EFI/ubuntu/grub.efi or /boot/efi/EFI/e110.efi.

This configuration enables you to store a separate boot loader for each OS you install on the computer.
