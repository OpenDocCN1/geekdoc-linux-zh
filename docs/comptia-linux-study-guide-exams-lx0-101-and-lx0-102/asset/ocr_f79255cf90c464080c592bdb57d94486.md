# Locating Files

/tmp Many programs need to create temporary (hence variable) files, and the usual place to do so is in /tmp. Most distributions include routines that clean out this periodically and sometimes wipe the directory at boot. The /tmp directory is shared. Some administrators create a separate /tmp partition to prevent runaway processes causing problems on the root filesystem where processes create large temporary files. A similar directory exists as part of the /var directory tree (/var/tmp).

/dev Linux treats most hardware devices as if they were files, the OS must have them in a location where these files reside. The /dev directory is that place. It contains a large number of files that function as hardware interfaces. If a user has sufficient privileges, user may access the device hardware by reading and writing to the associated file. The Linux kernel supports a device filesystem that enables /dev entries to be an automatically virtual filesystem—the kernel and support tools create to the needs of specific drivers. Modern systems use this facility.

Knowledge of these directories and their purposes is invaluable in administering a Linux system. For instance, understanding the purposes of directories /bin, /sbin, /usr/bin, /usr/local/bin, and others will help you when time comes to install a new program. Placing a program in the wrong location can cause problems at a later date. For example, if you put a binary file in /bin when it should go in /usr/local/bin, that program may later be overwritten or deleted during a system upgrade when leaving it would be more appropriate.

# Tools for Locating Files

You use file-location to locate a file on your computer. Most frequently, these commands help you locate a file by name, but sometimes you can use other criteria, such as modification date. These commands can search a directory tree (including root, which scans the entire system) for a file matching the specified criteria in any subdirectory.
