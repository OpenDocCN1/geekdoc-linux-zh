# ### Printing to Network Printers
If your network hosts many Windows computers, you may use the Server Message Block/ Common Internet File System (SMB/CIFS) for file and printer sharing among Windows systems. Linux's Samba server also implements this protocol and can be used for sharing printers from Linux.

On the flip side, you can print to an SMB/CIFS queue from a Linux system. To so, select an SMB/CIFS queue in the printer configuration tool. When CUPS, it is called Windows Printer via SAMBA in step 2 in the preceding procedure. You must then provide your username, password, server name, and share, but the format isn't obvious from the Web-based configuration:

```
smb://username:password@SERVER/SHARE
```

This is a URI for SMB/CIFS share. You must substitute appropriate values for username, password, server, and SHARE, of course. Once this is and you've finished the configuration, you should be able to submit print jobs to the SMB/CIFS share.

> SMB/CIFS printers hosted by Windows systems are usually non-Postscript models, so you must select a Linux smart filter and Ghosts driver, just as you would for a local printer. Printers hosted by Linux systems running Samba, by contrast, are frequently configured to act like Postscript printers, so you should select a PostScript driver when connecting to them.

If you want to print to a Unix or Linux server that uses the lpd protocol, the URI format is simple but lacks your username and password:

```
lpd://hostname/queue
```

You can use the same format, but substitute ipp://lpd://, to print to a CUPS server if browsing is disabled on your network.
In practice, you may be faced with a decision: Should you use LPD, IPP, or SMB/CIFS for submitting print jobs? To be sure, not all printers support all protocols, and a Linux server may support them all. As a general rule, IPP is the simplest to configure because it supports browsing, which means CUPS clients shouldn't need explicit configuration to handle specific printers. This makes IPP the best choice for Linux-to-Linux printing, assuming both systems run CUPS. When CUPS isn't in use, LPD is generally easier to configure than SMB/CIFS, and it has the advantage of not requiring the use of a username or password to control access. Because SMB/CIFS security is password-oriented, clients typically store passwords in an unencrypted form on the hard disk.
