# Monitoring Disk Use by Directory

The df command is helpful for finding out which partitions are in danger of becoming overloaded, but once you've obtained this information you may fine-tune the diagnosis and track the directories and files that are chewing up disk space. The tool for this task is du, which has a syntax similar to that of df:

```
du [options] [directories]
```

This command searches directories and reports how much disk space each is consuming. Its search is recursive, so you can learn how much space the directory and all its subdirectories consume. The result can be a very long listing if you specify directories with many files, but several options can reduce the size of the output. Others can perform helpful tasks as:

**Summarize Files As Directories**: Ordinarily, du reports on the space used by the directories but not the space used by individual files. Passing the -a or --all option causes it to report on individual files as.

**Compute a Grand Total**: Adding the -h or --human-readable option causes it to add a grand total to the end of its output.

**Used Units**: The -h for instead of reporting the total disk space used as 8589784 blocks, it reports the size in 5.6G (5.6GB). The -H and -s options have a similar effect, but they use power-of-10 (1000, 1000000) and power-of-2 (1024, 1048576) as units. The -k (-kilobytes) and -m (-megabytes) options force their respective units.

**Count Links**: Ordinarily, du counts files that appear multiple times as hard links only once. This reflects true disk space, but sometimes you may want to count each independently—for instance, if you're creating a CD-R and the file will be stored for each link. To do so, include the -l (a lowercase L) or --count-links option. (Links are described in more detail in Chapter 4).

**Limit Depth**: The --max=n option limits the report to n levels. (The subdirectories' contents are counted if they aren't reported).

**Summarize**: If you don't want a level of output for each subdirectory in the tree, the -s or --summarize option limits the report to those files and directories you specify on the command line. This option is equivalent to --max-depth=0.

**Limit to One Filesystem**: The -x or --one-file-system option limits the report to the current filesystem. If another filesystem is mounted within the tree you want summarized, its contents aren't included in the report.

As an example of du in action, consider it to discover which of your users is consuming the most disk space in /home. Chances you're not concerned with the details of which subdirectories within each home directory are using the space, so you'll pass the -s option to the program:

```
-s /home/*
12 /home/ellen
35304 /home/freddie
1760 /home/jennie
12078 /home/lost+found
01110324 /home/mspiggy
```

In this example, the wildcard character (*) stands for all the files and directories in /home, producing summaries for all subdirectories. (For more on this topic, consult Chapter 4.) Clearly, mspiggy (or whoever owns the /home/mspiggy directory) is the biggest disk space—or at least, that directory is consuming the most space. You could investigate further, by typing du -s /home/mspiggy/* to learn where the disk space is being used within the /home/mspiggy directory. In the case of user files, if this space consumption is a problem, you may want to contact this user instead of trying to clean it up.

# Mounting and Unmounting Filesystems

Maintaining filesystems is necessary, but the whole reason filesystems exist is to store files—in other words, to be useful. Under Linux, filesystems are most used by being mounted—that is, associated with a directory. This task can be accomplished on an on-demand basis by using tools such as mount (and then unmount with) or persistently across reboots by editing the /etc/fstab file.

# Temporarily Mounting or Unmounting Filesystems

Linux provides the mount command to mount a filesystem to a mount point. The unmount command reverses this process. (Yes, ummount reverses this process). The syntax for mount is:

```
mount [options] [-type] [device] [mountpoint]
```

The preceding list is incomplete; you should consult mount's man page for information about additional options. Common parameters for mount:

- **All Filesystems**: The -a option causes to mount all filesystems listed in /etc/fstab.
- **Read-Only**: The -r option causes to mount read-only.
- **Verbose Output**: The -v option produces verbose output.
- **Read/Write**: The -w option causes Linux to mount read/write.
- **Specify the Filesystem Type**: Use the -t option to specify the filesystem type.
- **Limit Depth**: The --max=n option limits the report to n levels. (The subdirectories' contents are counted if they aren't reported).
- **Summarize**: If you don't want a level of output for each subdirectory in the tree, the -s or --summarize option limits the report to those files and directories you specify on the command line. This option is equivalent to --max-depth=0.
- **Limit to One Filesystem**: The -x or --one-file-system option limits the report to the current filesystem. If another filesystem is mounted within the tree you want summarized, its contents aren't included in the report.
- **Mount by Label**: The -L option tells mount to mount the filesystem with specified label.
- **Mount by UUID**: The -U option tells mount to mount the filesystem with specified UUID.
