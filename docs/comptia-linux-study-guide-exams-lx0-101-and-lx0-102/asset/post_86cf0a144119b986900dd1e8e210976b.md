# X Configuration Options

When editing the X configuration file, the best approach is usually to identify the feature that's not working and zero in the section that controls this feature. You can then edit that section, save your changes, and test the new configuration. In XFree86 4.x and X.org, the major sections described here are called Module, InputDevice, Monitor, Device, Screen, and Server. You're likely to have two InputDevice sections, one for the keyboard and one for the mouse. In XFree86 3.6 and earlier, the mouse is handled by a Pointer section. The section order doesn't matter.

# Loading Modules

The Module section controls the loading of X server modules—drivers for specific features or hardware. A typical example looks like this:

```
Section 'Module'
  Load 'dbe'
  Load 'extmod'
  Load 'fbdevhw'
  Load 'glx'
  Load "record"
  Load "freetype"
  Load "type1"
  Load "dri"
```

Each module is named (dbe, extmod, and so on) and is loaded by name using the Load option. Most of these modules can be deciphered with a bit of knowledge about the features they control. For instance, freetype and type1 handle TrueType and Adobe Type 1 font rendering, if you're referring to your Module section and sees modules you don't understand, you shouldn't worry about it; generally speaking, modules that are configured automatically for normal operation, or at least they do no harm.

For the most part, if an X configuration works, you shouldn't try to adjust the Module section, even if you need to tweak the X configuration. Sometimes, you'll need to add lines or remove lines from this section. This is particularly likely to be necessary if you're activating 3D acceleration support or some sort of exotic feature. In such cases, you should consult the documentation for the feature you want to activate.

# Setting the Keyboard

The keyboard is one of two common input devices configured via an InputDevice section:

```
Section "InputDevice"
Identifier "Keyboard0"
Driver "kbd"
Option "XkbModel" "pc105"
Option "XkbLayout" "us"
Option "AutoRepeat" "500 200"
```

The Identifier line provides a label that's used by another section (ServerLayout, described in "Putting It Together"). The string given it is arbitrary, but for a keyboard, a descriptive name such as this example Keyboard0 will help you understand the file.

The Driver line tells X which driver to use to access the keyboard. This should be kbd, or evdev, depending on your X server. The kbd and Keyboard drivers are, as you might expect, keyboard-specific drivers. The evdev driver, by contrast, is a generic device driver that works with many types of input devices. Unless your keyboard isn't working at all, you shouldn't adjust this line.

The Option line sets various options that adjust keyboard features, such as the model, and the layout. For the most part, the default works well; however, you may want to change the AutoRepeat option or add it if its not present. This option tells X when to begin repeating characters when you hold down a key and how often to repeat them. It takes two numbers as values, enclosed in quotes: the time until the first repeat and the time between subsequent repeats, both expressed in milliseconds (ms). In the preceding example, the system waits 500ms (half a second) for the first repeat and 200ms for each subsequent repeat (that is, five repeats per second).

Many desktop environments and other user-level utilities provide tools to set the keyboard repeat rate. Thus, the options you set in the X configuration file are used as defaults and may be overridden by user settings.

# Setting the Mouse

A second InputDevice section controls how X treats the mouse:

| Section | InputDevice |
| --- | --- |
| Driver | 'Mouse0' |
| 'mouse' | '/dev/input/mice' |
| Option | 'Protocol' 'IMPS/2' |
| | 'Emulate3Buttons' 'no' |
| | 'ZAXisMapping' '4 5' |

As with, the Identifier line is used in the ServerLayout section to tell which input device to use. The Driver line identifies the driver to use: mouse. (Many modern systems use evdev for the mouse). The Option line sets mouse control options. The most important of these are Device and Protocol.

The Device line tells X what Linux device file to read to access the mouse. In this example, it's /dev/input/mice, /dev/psaux (for the PS/2 mouse port), /dev/usbmouse (an older identifier for USB mouse), /dev/tty50 (the RS-232 serial mouse port), and /dev/tty51 (the RS-232 serial port port). If your mouse is working at all (even if erratic), don't change this line. If it isn't working, you may need to experiment.

The Protocol option tells X what signals to expect from the mouse for various movements and button presses. If it doesn't work, you can try more specific protocols, such as IMPS/2 and Emplorer5/2, which are very similar in practice. (Note that "PS/2" is both a hardware interface and a software protocol; USB mouse use the PS/2 mouse port even though they don't use the PS/2 mouse port). If your mouse has a scroll wheel, chances you should use one of these protocols. If your mouse is older, you may need to try an older protocol, such as PS/2, Microsoft, or Logitech.

Additional options are usually less critical than the Device and Protocol options. Emulate3Buttons option tells whether to treat a chord (a simultaneous press) of both buttons on a two-button mouse as it were a middle-button press. This option is usually disabled on three-button mice and scroll mice (the scroll wheel does double duty as a middle button). # Setting the Monitor

Some of the trickiest aspects of X configuration relates to the monitor. You set these in the Monitor section, which can be quite large. A modest Monitor section looks like this:

```
Section "Monitor"
Identifier "Monitor0"
ModelName "AOC e234F"
HorizSync 30.0 - 83.0
VertRefresh 55.0 - 75.0
Modeleline "1920x1080" 138.50 1920 1968 2000 2080 1080 1083 1111
EndSection
```

As in the keyboard and monitor configurations, the Identifier is a free-form string that contains to identify a monitor. The Identifier can be anything you want. Likewise, the ModelName option can be anything you like; it's used mainly for your own edification when reviewing the configuration file.

As you continue the section, you'll see the HorizSync and VertRefresh lines, which are critical; they define the range of horizontal and vertical refresh rates that the monitor can accept, in kilohertz (kHz) and hertz (Hz). Together, these values determine the maximum resolution and refresh rate. Despite the name, the HorizSync item alone doesn't determine the maximum horizontal refresh rate, the VertRefresh value, and the resolution determine the monitor's maximum refresh rate. X selects the maximum refresh rate that the monitor will support given the resolution you specify. Some X configuration utilities show a list of monitors or refresh rate combinations (such as "1024x768 at 72Hz"). You select an option, and the utility then computes the correct values based on selection. This approach is often simpler to handle, but it's less precise than entering the exact values. You should enter these values from your monitor's manual.

> WARNING Don't set random horizontal and vertical refresh rates; on older hardware, setting values too high can damage a monitor. (Modern monitors ignore signals presented at too high refresh rate.)
