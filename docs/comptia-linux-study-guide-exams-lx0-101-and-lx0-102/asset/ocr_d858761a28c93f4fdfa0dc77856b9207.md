The result should be a reprint that might be handy for taking notes on the configuration file. Caveat: though if the file contains lines that approach or exceed 80 characters in length, the result will be single lines that span across lines. The result will be disrupted by page boundaries. As a workaround, you can set a short page length with -1 and -f to ensure the printer receives feeds after each page:

```
$ cat -etc/profile | pr -df 50 | lpr
```

The pr command is built around assumptions about printer capabilities that were reasonable in the early 1980s. It's still useful today, but you might prefer to use GNU Encript (http://www.codento.com/people/genscript/). This program has many of the same features as pr, but it generates PostScript output that can take better advantage of modern printers.

# # Viewing the Starts of Files with head

Sometimes all you need to do is see the first few lines of a file. This may be enough to identify what a mystery file is, for instance; or you may want to see the first few entries of a file to determine when it was started. You can accomplish this goal with the head command, which echoes the first 10 lines or more lines to standard output. (If you specify multiple filenames, each one's output is preceded by a header to identify it.) You can modify the amount of information displayed by head in two ways:

**Specify the Number of Bytes** The -c num or --bytes=num option tells head to display *num bytes from the file* rather than the default 10 lines.

**Specify the Number of Lines** You can change the number of lines displayed with the -n num or --lines=num option.
