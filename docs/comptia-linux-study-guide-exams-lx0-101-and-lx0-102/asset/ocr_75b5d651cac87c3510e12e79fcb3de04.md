current group membership. For instance, to change to the project2 group, you might type the following:

```
$ newgrp project2
```

If the user typing this command is listed as a member of the project2 group in /etc/, the user's current group membership changes. Thereafter, files created by that user will be associated with the project2 group. Alternatively, users can change the group associated with an existing file by the chgrp or chown command, as described in Chapter 4, "Managing Files."

This group structure enables you to design a security system that permits collections of users to work on the same files while simultaneously keeping other users of the same computer from prying into files they should not be able to. In a simple case, you may create groups for different projects, classes, or workgroups, with each user restricted to one of these groups. A user who needs to access multiple groups can be a member of each of these—for instance, a student who takes two classes belongs to the groups associated with each class, or a supervisor may map to all the supervised groups.

# Mapping UIDs and GIDs to Users and Groups

As mentioned earlier, Linux defines users and groups by numbers, referred to as user IDs (UIDs) and group IDs (GIDs), respectively. Linux tracks users and groups by these numbers, not by name. For instance, the user may be tied to UID 523, and may 609. Similarly, the project1 may be GID 512, and project2 may be GID 523. For most part, these details take care of themselves—you use names, and Linux /etc/passwd or /etc/group to locate the number associated with the name. You may occasionally need to know how Linux assigns numbers when you tell it to do something. This is particularly true when you're troubleshooting or if you have to manually edit /etc/passwd or /etc/group.

Linux distributions reserve the first 100 user and group IDs for root (both the user and the group). The most important of these is 0, which is used by accounts and groups that are associated with specific Linux utilities and functions. For instance, UID 2 and GID 2 may be the daemon account and group, respectively, which are used by various servers; and UID 8 and GID 12 may be the mail account and group, which can be used by mail-related servers and utilities. Not all account and group numbers from 0 to 99 are in use; usually, only one or two dozens are. You can check your /etc/passwd and /etc/group files to determine which.

> Aside from UID 0 and GID 0, UID and GID numbers are not fully standardized. For instance, UID2 and GID 2 map to the daemon account and daemon group on Red Hat and SUSE, on Debian UID 2 and GID 2 map to the bin account and bin group; the daemon account and group correspond to UID 1 and GID 1. If you need to refer to a particular user or group, use the name rather than number.
