I've tried running a few of the big X11 and Wayland compositors in sequence and it was an enlightening experience. What I learned surprised me: Linux and X11 are not as close as I thought. Even though the X server and Wayland compositors are both talking to the GPU, the way they talk is not the same. In fact, it is quite different. What I found out was that the X server and the Wayland compositor are not even talking to the same interface. In fact, they are talking to two different interfaces. And the two interfaces are not even in the same direction.

In the late 1980s, the VESA (Video Electronics Standards Association) group defined a set of guidelines for how to do that. These guidelines were called VBE (VESA BIOS Extensions). The VESA BIOS standard was a way to write to the VGA framebuffer using the CPU and was the de facto standard for years. However, the VESA standard was not enough. The CPU was too slow and the GPU was not fast enough to handle the demands of modern graphics. So, in 1996, the VESA group defined a new set of guidelines called KMS (Kernel Mode Setting). KMS was a way to do display mode setting from the kernel, rather than from user space. The idea was that the kernel would have better control over the display and would be more efficient. KMS was a big step forward and is now the standard way to do display mode setting on Linux. However, KMS is not enough. The GPU is now so powerful that it can do a lot of the work that the CPU used to do. This is where DRM comes in. DRM stands for Direct Rendering Manager. It is a set of interfaces that allow the CPU and GPU to communicate with each other. DRM is now the standard way to do graphics on Linux.

Before KMS could even be implemented, it had to be defined first. And when we define something, we make choices. Some of these choices were made in the 1980s and 1990s, back when CPUs were slow and GPUs were fast. These choices were good at the time, but they are no longer as good as they once were. For example, the VESA standard was designed for a world where the CPU was the only way to do graphics. But now we have GPUs that can do a lot of the work that the CPU used to do. This is where the KMS standard comes in. KMS was designed for a world where the GPU is the primary way to do graphics. And it is a much better fit for the modern world.
