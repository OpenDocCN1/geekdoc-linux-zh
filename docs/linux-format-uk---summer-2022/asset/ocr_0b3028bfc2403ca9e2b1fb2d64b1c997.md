Graphics card performance varies depending on the model and driver. This one was a P100 that was a bit slow, but it worked.

If you are on a system where you don't need the 3D acceleration, you can still use the graphics card for 2D acceleration. This is useful for systems that don't have a dedicated GPU but still want to have fast 2D graphics performance.

+   *   **amdgpu** – AMD GPUs
+   *   **nvidia** – Nvidia GPUs
+   *   **intel** – Intel GPUs
+   *   **vmware** – VMware GPUs
+   *   **virtualbox** – VirtualBox GPUs
+   *   **vfio** – VFIO GPUs
+   *   **qemu** – QEMU GPUs
+   *   **gen** – Generic GPUs

The drivers for these GPUs are available in the mainline kernel. The only exception is the Nvidia driver, which is not available in the mainline kernel. You can use the external nvidia module or the nouveau driver for Nvidia GPUs.

```
```console
echo \'nvidia\' >> /etc/modprobe.d/blacklist.conf
echo \'nouveau\' >> /etc/modprobe.d/blacklist.conf
reboot
```
```

You can check which driver is being used by running `lspci -v | grep -i 'Kernel driver in use:'`. This will show the driver that is being used for each GPU. If the driver is not the one you want, you can use the `modprobe` command to load the correct driver.

# NVidIA'S CHANGE OF HEART

The driver situation has changed a lot in the last few years. Nvidia has started to release open source drivers for their GPUs. This is a big change from the past, where Nvidia was known for releasing proprietary drivers. The new open source drivers are called "NVIDIA Open Driver" and they are available for download from the Nvidia website.

```
```console
# Nvidia GPU's
modprobe nvidia
modprobe nvidia-modeset
modprobe nvidia-drm
modprobe nvidia-peermem

# AMD GPU's
modprobe amdgpu
modprobe amdkcl
modprobe amd_overdrive
```
