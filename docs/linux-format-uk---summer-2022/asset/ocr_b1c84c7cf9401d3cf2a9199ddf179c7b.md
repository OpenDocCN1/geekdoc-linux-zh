# Focus on classes

Now that we can control the individual blocks, it would be nice to create a block at a time, as a single object. So we want to have separate objects for a block at a time to represent a block. In this example, a tetromino is actually a collection of four blocks. But it seems to be more efficient to have blocks as one object and then we don’t have to think about the different types of blocks. That is the object we’ll focus on.

The class below has a constructor, init method which takes colour and a list of blocks that make up the Tetromino. Each block has x, y position (the block is a square with side=1). Each block stores its own x and y.

```
```
class Piece:
  def __init__(self,color,blocks):
    self.blocks=[]
    for b in blocks:
      x,y=b
      self.blocks.append([x,y,color])
```
```

+   - 5-Range
+   - Some other methods that the Piece object can have: move, rotate, check collisions

A move method allows the Piece to be moved in 2-D. A rotate method allows the Piece to be rotated around a point. Collisions are checked by looking at the current block and checking if it will collide with the wall or the ground.

In the constructor (the special method, init), a colour, a list of four blocks that make up the object are taken. In the constructor, we set self.color to color and self.blocks to the list of four x/y values.

+   - 1-Drop
+   - 2-Account for movement of the piece in 2-D

In this article, we are not concerned with rotation, but if you want to implement this, you will need to look at the four blocks and change the x/y values.

As you can see, we can use a class to create a single piece of data, and then use that to make multiple pieces. That gives a more modular and readable structure to the code.
