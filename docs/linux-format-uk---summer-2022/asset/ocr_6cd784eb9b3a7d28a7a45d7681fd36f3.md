There is the problem of concurrency and multi-threading. The OS has limited number of cores at its disposal, and it needs to decide how to run programs on these cores. Most modern OS have a scheduler which decides how to assign tasks to cores. This is the level of programming that we don't need to worry about in this article.

Rust has built-in support for concurrency and multi-threading. It uses the concept of threads. Each thread can run its own program. These threads can share memory, or they can be independent of each other. Rust's memory model is strict, which means that the compiler will prevent you from making mistakes that could lead to data corruption.

The standard library has a module called std::thread, which provides functions for creating and managing threads. The spawn function creates a new thread. You can pass a closure to it, which will be executed in the new thread. The join function waits for a thread to finish. This is useful when you need the result of a thread.

If you're just starting with a multi-core machine, you should use the std::thread::available_parallelism function to check how many cores are available. This will help you to decide how many threads to create.

So, how can you make use of these functions? Let's say you have a task that needs to be done, and you want to do it in parallel. You can use the spawn function to create a new thread. This will allow you to run the task in parallel with the main thread. When the task is done, you can use the join function to wait for the thread to finish. This will ensure that the task is done before the main program exits.

Another useful function is the sleep function. This will pause the execution of the current thread for a specified amount of time. This can be useful if you want to limit the amount of work that a thread does. For example, you could use the sleep function to limit the number of requests that a thread makes to a web server.

Concurrency and synchronisation

When you're programming in Rust, you need to be aware of the difference between concurrency and parallelism. Concurrency is the property of a system that allows it to execute multiple tasks at the same time. Parallelism is the property of a system that allows it to execute multiple tasks at the same time on different processors. These two concepts are related, but they are not the same.
