## 4.8 Linux commands

You may run a Linux program from the command line prompt. If so, there are several directories that contain commands that you can run. You can run these without knowing where they are because your search path includes a number of directories that will be searched whenever you try to execute a command. The search path is given by the environment variable PATH. You can view the content of this variable by running the following command:

```
echo PATH
```

If you want to find out where a command is located, execute the command:

```
where command_name
```

where command_name is the command you are looking for. If you want to find the command yast you can execute:

```
where yast
```

This will give you the following results:

```
yast: /sbin/yast
```

You notice that this command is located in the /sbin directory. Many of the major administrative commands will be found in the /sbin and /usr/sbin directories.

Another helpful command for finding files on your system is locate command will also list files that match the search name, if they are not in your current search path. To search for all README documents on SuSE Linux run the following command:

Since this will be a huge amount of output, you might want to redirect the output to a text pager as less or more:

```
locate README | less
```

This will enable you to look at the output page by page. Press q to leave less and return to the command line.

## 4.8.1 File system permissions

Linux has inherent features, the most noticeable being file system permissions. Setting permissions on files allows the system administrator to restrict access to parts of the file system.

File permissions can be set on files and directories. The easiest way to see an example of this is in the /home directory:

```
mail:home # -l
total i
drwx-xr-x 19 root 396 Nov 15 21:06
drwx-xr-x 22 root 467 Nov 15 21:20
drwx------ 6 dajev users 912 Nov 15 21:05 davej
drwx------ 6 george users 912 Nov 15 21:05 george
drwx------ 6 ivo users 912 Nov 15 21:05 invo
drwx------ 6 Jakob users 912 Nov 15 21:03 jakob
drwx------ 6 jasmin users 912 Nov 15 21:04 jasmin
drwx------ 6 june users 912 Nov 15 21:04 june
drwx------ 6 jashins users 912 Nov 15 21:02 jashins
drwx------ 6 Justin users 912 Nov 15 21:06 justin
drwx------ 6 linux users 912 Nov 15 21:05 linux
drwx------ 6 malcolm users 912 Nov 15 21:04 malcolm
drwx------ 6 rahel users 912 Nov 15 21:04 rahel
drwx------ 6 rafiu users 912 Nov 15 21:04 rafiu
drwx------ 6 ruediger users 912 Nov 15 21:04 rediger
drwx------ 6 rufus users 912 Nov 15 21:04 rufus
drwx------ 6 ted users 912 Nov 15 21:03 ted
drwx------ 6 uzi users 912 Nov 15 21:04 uzi
mail:home #
```

Taking the user linux as an example: we are most interested in is the file/directory permissions. The first character in the permissions signifies a lot of information in a short amount:

- d signifies that this is a directory.
- a signifies a normal file.
- c refers to files in the /dev directory. This signifies the file represents a character device.
- b refers to files in the /dev directory. This signifies the file represents a block device.
- rwx In this case allows only the owner of the file (in this case linux) to read, write and execute.

The format of the string is becoming a bit easier to understand.

| Type | Owner | Group | World |
| --- | --- | --- | --- |
| d | rwx | --- | --- |

In the example above, the owner of the file is the user who created the file. The group part is the group that owns the file (for example, users). The world part means everyone else. Setting a permission in the world sets the permission for every user, irrelevant of their group membership and so on.

Here is another example:

```
drwxr-rw-
```

you are saying that only the directory owner is allowed to execute something "inside" the directory. So if another user tries to change (cd) into this directory, they will get a "permission denied" error. This is exactly what happens with regards to user's home directories.

To change the permissions on a file, you use the chmod command. Only root users can modify files that do not belong to them. You must own the file to be able to change its permissions. The easiest way to change permissions is to use symbolic representations of what you want permissions to be.

> Note
> The other way to represent file permissions is to use octals. For more information about this and the chmod command see the chmod page.

```
chmod g+rw myfile
```

This is one of the simplest ways of changing a permission. You are saying that you want the file to allow all members of the group to be able to read and write it. If you used - (minus sign) instead of plus, you would be taking away those permissions. This would mean that members of the group would not be allowed to read or write to the file.

You can mix adding and removing permissions in the same command:

```
chmod u+rw myfile
```

This will allow executing the file, but will not allow reading or writing the file for the file owner.

Here is a summary of the symbolic representations available in chmod:

r - read
w - write
x - execute
- take away the permissions
+ add the permissions
s - set the SUID bit. This says that if the file is executable, it will be run as the owner of the file, not as the user that is running the file.
