What are we most interested in the file/directory permissions. This signifies a lot of information in a short amount of space:

- d - The first character in the permissions signifies that this is a directory. 
Other files are represented by:

- + - a normal file.
- l a symbolic link to another file.
- c refers to files in the /dev directory. This signifies the file represents a character device.
- b refers to files in the /dev directory. This signifies the file represents a block device.

rwx - In this case it allows only the owner of the file (in this case "linux") to read, write and execute this file.

| Type | Owner | Group | World |
| --- | --- | --- | --- |
| d | rwx | --- | --- |

The owner of the file is the user that created the file. The group part is the group that owns the file (for example, the group users). The world part means everyone else; setting a permission in the world part sets the permission for every user, the group can read and execute the file, and everyone can read and so on.

Here is another example:

```
-rwx-xr-x
```

This means that this is a normal file, the owner can read, write, execute the file, and everyone else can read the file, but not modify or execute it.

If you set a directory as:

```
drwxrrw-rw-
```

you are saying that only the directory owner is allowed to execute something "inside" the directory. If another user tries to change directory into it, they will get a "permission denied" error. This is exactly what happens with regards to home directories.

To change the permissions on a file, you use chmod. Only root can modify files that do not belong to them. You must own the file to be able to change its permissions.

The easiest way to change permissions is to use symbolic representations of what you want permissions to be.

Note: The other way to represent file permissions is to use octals. For more information about this see the chmod man page.

```
chmod g+rw myfile
```

The command above allows all members of the group to be able to read and write. If you used - (minus sign) instead of plus, you would be taking away those permissions. This would mean that members of the group would not be allowed to read or write the file. You can mix adding and removing permissions in the same command:

```
chmod u+x-rw myfile
```

This will allow executing the file, but not allow reading or writing for the owner. Here is a summary of symbolic representations available in chmod:

- r - read
w - write
x - execute
s - set the SUID bit. This says that if the file is executable, it will run as the owner of the file, not as the user.

## 6. Backup recovery

One of the items system administrators should maintain well-established routines for backup and recovery. Your data is very valuable. If it is lost, it costs you time and money to recreate. If you are unable to recreate the information, it could devastate your business. Modern hardware is quite reliable, but may still fail. The most critical parts of hardware for storing data are hard disks. Different RAID implementations minimize the consequences of hard disk failures. Even a RAID configuration may fail for one reason or the other. Software is unreliable by nature. Humans can make errors or be malicious and try to destroy data.

Therefore, back up your data. Be sure that the restoration and recovery of data from the backup media works reliably. The term recovery implies the restoration of files from backup tape(s) in a production environment and the recovery of a whole system after a possible crash. Backup and recovery are mainly planning and organizational tasks. Managing and protecting your data utilizing a Linux operating system can be easily accomplished with commercially available products (for BRU, Arkeia, BackupEDGE, etc.).

In a Linux environment, backup devices are named /dev/st for rewinding and /dev/nst for non-winding SCSI device. SCSI tape devices or "floppy" drives that some backup packages support may use a different naming scheme.

For more in-depth information about backup strategy, media and hardware, consult the IBM Redbook, Netfinity Tape Solutions, SG24-5218. This redbook can be downloaded from the following site:

```
http://www.redbooks.ibm.com/
```

You can also find valuable information in The Linux System Administrator's Guide by Lars Wirzenius and Joanna Oja. This book can be obtained in PDF format from the following site: http://www.linuxdoc.org/, then search on Backup Media.

Your first step in putting together a viable backup solution is to choose the backup media. It should be removable and stored in a safe place. It cannot be one of the disk drives in your system. Your selection of media should be either floppy, tape, ZIP media, or magneto-optical disk. Using copies as backup media can be unsuitable if a large amount of data should be backed up or unattended operation is an important issue. Mostly, SCSI or Atari tape is a suitable choice. The cost and availability may help you decide. If SCSI is your preferred choice, you have to choose between QIC, DAT, EXABY or DLT tapes of different capacities. The amount of data to be backed up and the cost of the backup device(s) and media may determine your decision. Some of the backup packages support libraries.

Choosing the right media may also depend on the backup tool you want to use and whether it supports your media.

Every IBM @server xSeries and Netfinity system has a built-in SCSI controller. We recommend you choose a SCSI device for your backup. You can choose between different technologies (QIC, DAT, EXABY, or DLT) depending on the amount of data to be stored and the speed required.
