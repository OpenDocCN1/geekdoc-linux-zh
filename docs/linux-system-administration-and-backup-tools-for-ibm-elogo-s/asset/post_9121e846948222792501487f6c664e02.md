## 3.3 User administration

Linux is a multi-user operating system. To differentiate between the various users, each has to log in with a unique user name and password. Each user belongs to a primary user group, but he can be a member of other groups (up to 16 groups). Each user name is associated with a user ID (UID), which is unique throughout the system. The same applies to user group names and group IDs (GIDs).

Usually each user has a personal home directory. This is space on the file system (usually a directory below /home, for example /home/username) which belongs to him and where he can store his files (for example, e-mail or text documents). Other users generally have no access to the files stored there.

It is one of the root user's tasks to add and remove user or group accounts. To do this from a menu you can use the program Linuxconf to add, modify or delete groups and users. In the next section we will provide details about user administration from the command prompt.

You should carefully consider adding user groups before adding users. Sometimes there are concerns about restricting access to some parts of the user system. You can do this by creating separate user groups to control access to various files and file systems. Also if you are going to be creating a system with many users, you should consider creating separate groups divided by what they are on the system. You can create an admin group for administrators, a db2user group for DB2 users, and so forth. Linux allows you to control access to all files and directories by both users, groups, and everyone on the system.

Another concern in setting up users and groups is what you may want to share files with other systems. This can be done by the CD, tape, diskette or similar device. You can use the network to share information with NFS, Samba, IPX and other network packages. If you use user and group names and characteristics that are not the same on all systems doing the sharing, then you can have file sharing and access problems.

If you are creating logins and groups on each system separate, it is often best to use a single system where all IDs can be created. This system is then used as a reference. It is not necessary that everyone actually log into the reference system. It exists only to coordinate ID and group creation and to prevent non-standard IDs and groups. A user cannot log into the reference system if the password is not enabled. This will prevent unauthorized access to the system. Red Hat Linux will automatically create a new group for each new user unless you tell it to.

You might consider network-wide user authentication and tracking schemes as NIS, NIS+ and various other network administration packages.

The explanation of the options shown in Figure 60 are as follows:

- - comment
This is a comment field about the user. It has been traditionally called the GECOS field and can include such information as office room numbers, phone numbers, etc. Any string of characters must be put double quotes. For example, `-c comment "John Doe, rm. 45, 78965"`.

- -d home_dir
The home directory location of the user. If this is not specified then the default is to append the login name to the end of the default value for HOME shown in Figure 6. For example, the home directory for jdoe will be /home/j unless specified here.

- -e expire_date
This is the date on which the user account will be disabled. The date is specified in the format MM/DD/YY where MM is the month, DD is the date, and YY is the year. (Note that though the date is represented in digits, there are no YK worries here.) The default is the value of EXPIRE.

- -f inactive_time
This gives the status of the account. A value of -1 says to disable the account when the password expires. The default is the value of INACTIVE.

- -g initial_group
The initial group a user logs with. This can be a name or number specified in the /etc/group file. The default group is GROUP.

- -G group,...
This is a list of any additional groups the user may belong to. Each group is separated by a comma.

- -m [-skeleton_dir]
The -m option says to create the user's home directory if it does not exist. The skeleton_dir is the location of files that are copied to a new directory. The default is /etc/skel.

- -s shell
This is the shell that the user will first log with. The default is SHELL.

- -u uid [-o]
This is the numeric UID or user ID number that is used by Linux to distinguish one user from the other. All UIDs must be unique unless the -o option is used. The -o option is used for creating IDs that have the same access rights, but different logins. The system looks only at the UID and GID values.

- -n
By default a group will be created whose GID is the same as the UID of the user. The -n option will turn off this Red Hat behavior.

- -r
This is used to create a system account whose UID is lower than a certain number defined in /etc/login.defs. You will also need to specify the -m option if you want to create the home directory. System accounts generally have UID values between 0 and 99.

- login
This is the login name that the user will log with. This will need to be unique on the system.

### 3.3.2 Modifying users

You can modify users with the `usermod` command:

```
root@root:~# usermod
usage: usermod [-u uid] [-o] [-g group] [-c group...]
      [-d home [-m] [-s shell] [-c comment] [-l new_name]
      [-f inactive] [-e expire mm/dd/yy] [-p passed] name
root@root:~#
```
