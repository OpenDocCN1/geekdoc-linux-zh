# dbench

dbench is a workload created to model another benchmark: NetBench. NetBench is the *de facto* industry standard benchmark for However, as with several benchmarks discussed later in this chapter, NetBench requires access to a large number of clients and a performance. With many benchmarks, the complexity of the benchmark makes it better suited to benchmark teams sponsored by usually after a product is generally available. NetBench is also poorly suited to help developers analyze code during the development cycle time for testing and the complex testing environment required.

Many Linux developers prefer to analyze the performance of various aspects of their code as that code is developed. That analysis easy to run, benchmarks that can be easily understood, and benchmarks that require minimal hardware configurations. dbench w the Windows file system support for Linux and achieves those goals. Their goal was to use dbench to analyze their code for complex performance, and scalability on Linux.

dbench was developed based on a set of network traces captured while running NetBench. The theory was that if you can simulate network from accessing a network file system, you can generate effectively the same load with a program that does nothing except NetBench used a more brute-force approach where each network client was an individual computer, generating file system accesses generate file system accesses. By effectively simulating the file system traffic on the local machine, the server portion of the netw stressed in much the same way.
