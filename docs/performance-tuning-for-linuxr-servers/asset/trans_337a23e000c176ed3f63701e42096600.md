
硬件配置、软件配置、调优变量等，然后将后续运行与过往结果进行比较。通过对比和衡量机器配置、成本以及关键性能参数，您可以就潜在的升级、调优可能性或能够改善工作负载整体性能和用户响应时间的额外软件做出明智的决策。现有的基准测试（Benchmarks）通常费尽心思以确保极高的可移植性、运行之间结果的一致性、在相似硬件和系统环境中的可比结果，以及关于传统工作负载常见方面的一般性信息指标。所有这些在标准化基准测试和一致性方面的努力，使它们成为评估您的工作负载潜在改进，或结合您提议的工作负载来评估硬件或软件解决方案的强大工具。

### LMBench

http://www.bitmover.com/lmbench/

LMBench 是一套真正意义上作为微观基准测试的简单基准测试套件。它包含一系列小型测试，用于测量所有 UNIX 或 Linux API 中最基本的部分。带宽测量包括测量从缓存文件读取、复制级别、通过 UNIX 管道传输数据的带宽，以及一些简单的 TCP 基准测试。通常，这些带宽测量会分配一块内存或在循环中发出 `write()` 调用，并在循环前后调用系统时钟。统计循环次数可以作为衡量各种 API 整体带宽的指标。然后可以在不同类型的硬件内存子系统等之间比较这些基本 API 的所选指标。

LMBench 还测量操作系统从用户级切换到保护模式的速度。由于此类事件的发生速度远快于系统的定时器粒度，一种常见的技术是运行一个简单的程序，在某个时间单位内执行大量对原始操作（primitive）的调用。相对简单的数学计算随后就可以得出平均完成速率。LMBench 测量的原始操作包括建立 TCP 连接、创建管道、创建进程等。LMBench 相当成熟，并且仔细考虑了实际系统中通常可能出现的一些更复杂的副作用。例如，进程创建测试考察了通过 `fork()` 创建进程的成本，以及 `fork()+exec()` 和 `fork()+system()` 的成本。描述如何解释结果的文档指出了各种硬件配置（包括不同大小的内存缓存）对性能的影响。LMBench 还通过推荐一种能为所有架构产生一致结果的通用编译器来考虑编译器差异。虽然可以在不同架构上使用不同的编译器，但性能分析师在比较结果时必须小心。尽管所有测试在概念上都比较简单，但其包含的丰富经验使其成为进行简单比较的更好基准测试。此外，公开可用的测试结果以及在此情况下的公开源代码，使得轻松比较不同环境中的差异成为可能。在以下结果中，一些信息提供了简单的度量，例如 `fork()` 或 `write()` 等系统调用的时间。其他结果显示了各种数据传输大小的吞吐量。
