## Disk Benchmarks

This section discusses the following disk benchmarks:

- Bonnie/Bonnie+

We have examined two classes of microbenchmarks: those that focus on the primitive, primary capabilities of the underlying process. Those that use simplistic workload simulations that exercise some of the more commonly used operating system components such as I/O mechanisms. Next, we’ll look at a few other classes of benchmarks that focus on other components of the system. These include tests of the subsystem, various file systems, and the networking subsystem. These components often have a higher correlation with specific customer workloads and therefore are quite valuable in isolating and identifying the key performance characteristics of the file systems and disk subsystems. Many of these benchmarks are developed from or related to traces of actual workloads running on specific file systems that create a stressful environment in which throughput can be measured in best-case and worst-case scenarios.

## Bonnie/Bonnie++

Bonnie is primarily a file system test useful to measure underlying file system performance and identify bottlenecks. Bonnie and Bonnie++ are sequential read and write tests and some random read/write testing. Bonnie measures both character-at-a-time reads and writes and block writes. The character-at-a-time test uses the operating system’s `getcc` and `putcc` functions to provide some measure of the overhead of character-level I/O. Meanwhile, the block transfer test uses the `read` and `write` system calls to provide a measure of the file system throughput and latency. The random tests run a user-specified number of threads, each of which seeks to a random location and performs a write while another thread performs a read on the same location.
