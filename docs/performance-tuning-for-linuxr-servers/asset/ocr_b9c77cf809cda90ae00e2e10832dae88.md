If the count is greater than zero, the psema() routine decrements the count by one and returns to the calling program. If the value of the semaphore is zero, the psema() routine blocks. The vs ema() operation increments the semaphore and never blocks. Our psema() and vs ema() routines are based on the semaphores(3) interfaces defined in section 3 of the manual (man 3 semaphores). Our interfaces take a name that enables us to debug them with more claritywe can print the name of the semaphore we are examining by inserting appropriate print statements. We use one semaphore to count the number of available threads (either pooled or nonpooled), one to count the number of tasks (jobs, work items, or whatever we want to call them), and one to count the number of active threads.

Finally, there are the queueing operations. Their job is to protect the data structures describing the queue of jobs coming in. The queue is operated with en que () and dequeue() operations. To support the queueing and dequeueing of data, lock and unlock implement locks on specified objects (the work queue in this case). You might ask why there are two counting mechanisms. The semaphore counting mechanism is specifically for counting. Because the numbers of threads (active and available) are strictly numbers, the only mechanism we need is counting. The queueing routines were written for more general queueing where objects could be queued. In this case, they require more than a simple count. For our particular demonstration here, they have been dutened to queue only integers (socket file descriptors); thus, they are similar in function to the semaphore operations.
