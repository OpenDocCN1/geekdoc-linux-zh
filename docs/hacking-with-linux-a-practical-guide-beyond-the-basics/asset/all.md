Linux itself is a kernel, not a complete operating system. Complete systems built around the Linux kernel use the GNU system, which offers a shell, utilities, libraries, compilers, and tools, as well as other programs such as text editors. For this reason, Richard M. Stallman of the GNU project asks users to refer to the complete system as GNU / Linux. In the appendix, there is more information about the GNU project.Linux development started from a personal project by a student at Helsinki University in Finland called Linus Torvalds. He intended to create a more sophisticated operating system than Minix, a relatively simple UNIX whose source code he had available. Linux follows the US government standard, POSIX. POSIX is the UNIX Application Programming Interface (API) standard, references for developers in the UNIX-like family. Since the introduction of Linux on October 5, 1991, by Linus Torvalds, a large number of people involved in programming have started to develop Linux. The name Linux derives from the junction Linus + UNIX = Linux.PortabilityLinux is a top ported kernel's operating system, It runs on systems from iPaq (a portable computer) to IBM S/390 (an enormously expensive mainframe), although this type of portability was not one of the primary goals of Linus Torvalds. His effort was to make his system portable enough to ensure ease for the compilation of applications on this system from different sources. Therefore, Linux initially became popular to some extent due to the power to get everyone's favorite GPL or other fonts to run on Linux.DistributionsThe complete operating system (GNU / Linux) is considered a Linux Distribution. It is a collection of free (and sometimes non-free) software created by individuals, groups, and organizations around the world, with the kernel at its core. Today, companies like Red Hat or SuSE, as well as community projects with Debian or Gentoo, compile the software and provide a complete system, ready for installation and use. In addition, there are personal projects such as Patrick Volkerding that provides a Linux distribution, Slackware.As soon as Linus Torvalds made Linux available, he only made the kernel available with a few basic commands. *   User: is the person who created the file. The owner of the File
*   Group: It is a category that brings together several users. Each user can be part of one or more groups, which allow access to files that belong to the corresponding group. By default, the initial user group is the same as your username. The group id is called gid (group id).
*   Other: This is the category of users who do not fit as file owners or groups.

Access permissions for owners, groups, and other users are independent of each other, thus allowing a different level of access.The root account is also called a superuser. Commands are executable files, usually found in predictable locations in the directory tree. System privileges and permissions are controlled largely through files. All system security depends largely on the combination of ownership and safeguards set on your files and your user accounts.The Hierarchical System, Directory Tree, Branch AssemblyUNIX has a hierarchical directory organization in a format known as the file system. On UNIX systems, all available disk space is combined into a single directory tree below /, where the physical location where a file resides is not part of the UNIX specification.Basic File Types: Plain Files DirectoryThe files are where the data is recorded. A file can contain text, song, program, etc. Every UNIX system recognizes at least three file types:

*   Common Files: Used to store data. Users can append data directly to common files, such as through an editor. Executable programs are also stored as common files.
*   Directory Files: A directory file contains a list of files. Each entry in the list consists of two parts: the file name and a pointer to the actual file on disk. On the other hand, directories behave exactly like common files, except that some commands used for handling common files do not work for directory files.
*   Special Files: These files are used to refer to physical devices such as terminals, printers, disks. They are read and written as common files, but such associations cause the physical device attached to it to activate.

Linux is case sensitive, meaning it is case sensitive in files. The directory, like any other file, is also case sensitive. In the same directory, there cannot be two files with the same name or a file with the same name from a subdirectory. Directories on Linux are specified by a "/."NOTE: We are used to seeing filenames as name.ext, where ext is the extension of the file type, for example .txt, .html, .doc. Inodes are disk data structures that describe and store file attributes, including its location. Some inode fields are: user, group, file type, creation time, access, mode (modification), number of links, size and address on disk.There are mechanisms that allow multiple names to refer to a single file on disk.These mechanisms are the links. There are two types of links: hard link (or symbolic) or soft link.

*   Hard link: associates two or more file names as the same inode. Hard links share the same block of data while functioning as independent directory entries.
*   Soft link: These are files pointers that point to another file name in the file system.

File Access PermissionsThe UNIX system provides an easy means of controlling how system users can access all three file types. This is to allow or restrict access to important system files and to ensure the privacy of every user who has an account on the system. The system differentiates three classes of users. First, every file has an owner, designated in the system by the user. The owner has full control over the restriction or permission to access the file at any time. In addition to individual ownership of the file, it is possible for one or more system users to own the file collectively in a group property type. A user who does not own the file may have access to it if they belong to the user group that has permission for this. However, this user cannot restrict or allow access to the file. Users who do not own or belong to a group that has access to the file from the last category, known simply as "others."

*   The owner (designated by u, user): who created the file.
*   Group (called g, from group): The group consists of one or more users who can access the file.
*   Other (referred to as o by others): Refers to any other system user.

The Unix system also allows three modes of file access: reading, writing and execution. The three access modes are relatively logical, but the meaning of these three access modes is different for directory files. The user with reading permission can read the directory contents, for example, with the command "ls." The user with write permission can use some privileged programs to write to a directory. Write permission is required to create or remove files from the directory.A user must have execute permission on a directory to have access to the files allocated there. If a user has read and write permission on a common file that is listed in a directory but does not have to execute permission for that directory, the system will not let him read or write the contents of that common file.A file that has its permissions like those in the example above could be read, written, or executed by the owner or anyone else. Chapter 6: Package ManagementIn Linux, the words program and package are often used interchangeably, although strictly speaking, they are not the same. However, for our current purposes, we can consider them equivalent. That way, when we refer to package management, we will be talking about programs. With that in mind, let's enter the exciting world of Linux software management.Essential ConceptsLet's start by defining package management as the set of tasks for installing, updating, and uninstalling software resources on our system. Today, software distribution on Linux is done in three main ways:

*   Repositories : they are central servers, generally maintained by a particular distribution, by the community, or by other third parties, where a collection of software is available for installation via the Internet or a local network. In simple terms, a repository in Linux (also called software source) is a collection of programs compatible with a given distribution. A repository can reside on a remote server (which is the most common) or on one (or several) local storage devices.

*   Precompiled files : they are compatible executable files for a particular distribution and can be installed both through the network and locally with a command-line tool (in a few minutes, we will see this in more detail).
*   Source code : it is the initial form by which software was distributed in Linux at the beginning. Although it has been surpassed by the previous two, it is still used to offer end users the possibility of compiling a given program with particular options. This software distribution method is also used to make a more up-to-date version available to the public that has higher performance than those present in the repositories.

Each distribution has different utilities for package management. Some of them (such as yum or apt-get, for CentOS and Debian, respectively, together with the members of each family) have the ability to install together with a program given their dependencies, that is, those additional packages that are necessary for the operation of the first. For that reason, they are more commonly known as package managers. Others, such as dpkg (Debian and derivatives) and rpm (CentOS and family), only install the program present in the .deb file or .rpm but without installing dependencies.More On RepositoriesFor practical reasons, not all available repositories are included in the initial installation of distribution but can be added later when needed.All distributions maintain their own official repositories and also have others that are maintained by the community or private users (in the latter case it is usually repositories that contain a few packages). 1.  The repositories in which you want to find software for our system are configured.
2.  Before using the newly configured repositories, it is necessary to update the local package index in a way that reflects the contents of the repositories.
3.  The package manager of each distribution is used to find information about a given package or directly to install it.

Jobs in UpstartUpstart [viii] is a non-sequential event-based boot process that has been included by default as of Ubuntu version 6.10.A job is a task or service that can be executed or stopped when an event is triggered, and that can also generate new events to manage other jobs that depend on it.A boot system of this type has the advantage of being able to launch the necessary tasks when the system recognizes the corresponding devices, without having to wait to finish the execution of previous tasks. Therefore, a kind of task execution tree can be defined.Upstart can emulate the way SysVinit works, defining execution levels for general system services. Basic Process ControlThe process can be understood as any program or command in execution. A process has the following characteristics:

*   Each process consists of code, data and stack zone.
*   The processes exist in a tree hierarchy (several children, one parent).
*   The system assigns a unique process identifier (PID) at the start of the process.
*   The task scheduler allocates a time-share for the process based on its priority (only root can increase the priority of a process).
*   Each process stores its identifier (PID) of its parent process (PPID), the owner and group of the process, and the environment variables.

The superuser must maintain control of the system at all times, making periodic reviews of the processes that are running on the server, which can avoid problems and abuses that affect the normal operation of the machine.The following table describes the most used commands for process control.

| Mandate | Description |
| ps | Presents a list of the active processes on the machine, indicating owner, process identifier (PID), parent process identifier (PPID), mandate, etc. |
| kill | Send an interrupt signal to one or several processes. It is usually used to finish its execution. |
| pgrep | List processes that meet certain criteria. |
| pkill | Send a signal to processes that meet certain criteria (take special care when executing this order). |
| nice | Change the priority of the processes. It is usually used to reduce the execution time of processes that saturate the system. |
| top | Presents an updated list of the processes that consume more resources. It also allows us to send signals and modify the priority of execution. |
| lsof | List the files and network connections opened by each process, also indicating the owner, PID, priority, command, etc. |

The lsof command is a powerful administrative tool, as it shows all files, named pipes, devices, and network connections opened by each process.
