
# Displaying readable file sizes: the -h option

Utilities that report on file sizes specify the size of a file in bytes. Bytes work well when you are dealing with smaller files, but the numbers can be difficult to read when you are working with file sizes measured in megabytes or gigabytes. Use the -h (or --human-readable) option to display file sizes in kilo-, mega-, and gigabytes. Experiment with the df -h (disk free) and ls -h commands.

Another convention allows utilities to work with arguments, such as filenames, that start with a hyphen. If a file's name is -l, the following command is ambiguous:

```
$ ls -1
```

This command could mean a long listing of all files in the working directory or a listing of the file -l. It is interpreted as the former. Creating files whose names begin with hyphens. If you do create them, many utilities follow the convention that a -- argument (two consecutive hyphens) indicates the end of the options (and the beginning of arguments). To disambiguate the command, you can type

```
$ ls -- -1
```

You can use an alternative format in which the period refers to the working directory and the slash indicates that the name refers to a file in the working directory:

```
$ ls ./-1
```

Assuming that you are working in the /home/max directory, the preceding command is functionally equivalent to

```
$ ls /home/max/-1
```

The following command displays a long listing of this file:

```
$ ls -1 -- -1
```

These are, not hard-and-fast rules, and number of utilities do not follow them (e.g., find). Following such conventions is a good idea; it becomes much easier to work with your program. When you write shell programs that require options, follow the Linux option conventions.

# PROCESSING THE COMMAND LINE

As you enter a command line, the Linux tty driver (part of the Linux kernel) examines every character to see whether it must take immediate action. When you press CONTROL-H (to erase a character) or CONTROL-U (to kill a line), the device immediately adjusts the command line as required; the shell never sees the character(s) or the line you killed. A similar adjustment occurs when you press CONTROL-W (to erase a word). When the character you entered does not require immediate action, the device driver stores the character in a buffer and waits for additional characters. When you press RETURN, the device driver passes the command line to the shell for processing.

When the shell processes a command line, it looks at the line as a whole and parses it into its component parts (Figure 7-2). Next the shell looks for the name of the command. Usually the name of the command is the first item on the command line after the prompt (argument zero).

optional The shell does not require that the name of the program appear first on the command line. Then you can structure a command line as follows:

This is a properly structured—albeit rarely encountered and possibly confusing—command line.

Absolute versus relative pathnames When you give an absolute pathname on the command line or a relative pathname that is not a simple filename (i.e., any pathname that includes at least one /), the shell looks in the specified directory (/bin in the case of /bin/ls command) for a file that you have permission to execute. When you give a simple filename, the shell searches through a list of directories for a filename that matches the specified name and for which you have execute permission. The shell does not look through all directories but only the ones specified by the variable PATH. Refer to page 319 for more information on PATH. Also refer to the discussion of the which and whereas is on page 178.

When it cannot find the executable file, the Bourne Again Shell (bash) displays a message such as

```
$ abc
command not found
```

One reason the may not be able to find the executable file is that it is not in PATH. Under bash the following command temporarily adds the working directory to PATH:

```
$ PATH=$PATH:.
```

For security reasons, you may not want to add the working directory to PATH permanently; see the one on page 320.

When the shell finds the program but cannot execute it (i.e., because you do not have permission for the file), it displays a message similar to

```
$ def
Permission denied
```

# EXECUTING THE COMMAND LINE

Process If it finds an executable file with the same name as the command, the shell starts a new process. A process is the execution of a command by Linux (page 328). The shell makes each command-argument, including options and name of the command, available to the called program. While the command is executing, the shell waits for the process to finish. At this point the shell is in an inactive state called sleep. When the program finishes execution, it passes its exit status (page 996) to the shell. The shell then returns to an active state (wakes up), issues a prompt, and waits for another command.

The shell does not process arguments Because the shell does not process command-line arguments merely passes them to the called program, the shell has no way of knowing whether a particular option or other argument is valid for a given program. Any error or usage messages about arguments come from the program itself. Some utilities ignore bad options.

# STANDARD INPUT AND OUTPUT

Standard output is a place that a program can send information, such as text. The program never “knows” where the information sends to standard output is going (Figure 7-3). The information can go to a printer, an ordinary file, or the shell.
