# # create new (empty) log files after rotating old ones
create

# uncomment this if you want your log files compressed
#compress

# packages drop log rotation information into this directory
include /etc/logrotate.d

```
# no packages own wtmp, or btmp -- we'll rotate them here
/var/log/wtmp {
missingok
monthly
create 0664 root utmp
rotate 1
}
```

```
/var/log/btmp {
missingok
monthly
create 0664 root utmp
rotate 1
}
```

# system-specific logs may also be configured here.

The logrotate.conf file sets default values for common parameters. Whenever log-
rotate reads another value for one of these, it resets the default value.
You have a choice of rotating files daily, weekly, or monthly. The number following
the rotate keyword specifies the number of rotated log files you want to keep. The
create keyword allows logrotate to create a new log file with the same name and
attributes as the newly rotated log file. The compress keyword causes log files to be compressed using gzip. The include keyword
specifies the /etc/logrotate.d directory for program-specific log speci-
cication files. When you install a program using dpkg (page 532) or a dpkg-based
utility such as aptitude (page 526), the installation script puts the logrotate specifica-
tion in this directory.

The last sets of instances in logrotate.conf take care of the /var/log/wtmp and
/var/log/btmp log file holds login records; you can view this file with the
command who /var/log/wtmp. The keyword missingok overrides the implicit
default value of nonmissingok for this utility only (because the value is within brack-
ets). This keyword allows logrotate to continue without introducing an error message if
t log file is missing. The keyword monthly overrides the default value of weekly.
The create keyword is followed by the arguments establishing the permissions,
owner, and group for the new file. Finally rotate establishes that rotated log file
s be kept.
