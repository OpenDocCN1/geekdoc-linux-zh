Passive versus active connections A client can ask an FTP server to establish a PASV (passive–give the command ftp -p or프트) or a PORT (active–the default when you use ftp) for data transfer. Some servers are limited to one type of connection. The difference between a passive and an active FTP connection lies in whether the client or the server initiates the data connection. In passive mode, the client initiates the connection (no port by 20 default); in active mode, the server initiates the connection (there is no default port; “Connection Parameters” on page 708 for the parameters that determine which a server uses). Neither approach is inherently secure than the other. Passive connections are more common because a client behind a NAT (page 881) can connect to a passive server and it is simpler to program a scalable server.

# FTP Clients

+   * Ubuntu supplies several FTP clients, including ftp (an older version of the BSD FTP utility). This discussion discusses ftp because most FTP clients, including sftp and lftp, provide a superset of ftp commands.

+   * Part of the OpenSSH suite (openssh-client package) is a secure and functionally equivalent alternative to sftp. The sftp utility is not a true FTP client—it does not understand the FTP protocol. It maps ftp commands to OpenSSH commands. See page 674 for more information.

+   * lftp utility (lftp package) provides the same security as sftp but offers more features. See the lftp page for more information.

+   * gftp utility (gftp package) is a graphical client that works with FTP, SSH, and HTTP servers. This client has many useful features, including the ability to resume an interrupted file transfer. See www.gftp.org and freshmeet.net/projects/gftp for more information.

+   * ncftp utility (ncftp package) is a textual client that offers many more features than ftp, including filename completion and command-line editing. For details see www.ncftp.com and freshmeet.net/projects/ncftp.
