Job control A job is one or more commands connected by pipes. You can bring a job into the background into the foreground using the fg builtin. You can put a foreground job into the background using the bg builtin, provided that you first suspend the job by pressing the suspend key (typically ctrl-Z). Use the builtin to see which jobs are running or suspended.

Variables The shell allows you to define variables. You can declare and initialize a variable by assigning a value to it; you can remove a variable using unset. Variables are local to a process unless they are exported using the export builtin to make them available to children. Variables are called user-created variables. The shell defines keyword variables. In a shell script you can run with the command-line (positional) parameters the script was called with.

Process Each process has a unique identification (PID) number and is the execution of a single linux command. When you give it a command, the shell forks a new (child) process to execute the command, unless the command is built into the shell. While the child process is running, the shell is in a stated cell. By ending a command with an ampersand (&), you can run a child process in the background and bypass the sleep so that the shell prompts immediately after you press RETURN. Each command in a shell forks a separate process, each of which may turn fork others. When a process terminates, it returns its status to its parent process. An exit status of zero signifies success; nonzero signifies failure.

History The history mechanism, a feature adapted from the C Shell, maintains a list of recently used command lines, also called events, that provides a way to execute previous commands quickly. There are several ways to work with the history list; one of the easiest is to use a command-line editor.

Command-line editors When using an interactive Bourne Shell, you can edit a command line from the history file, using either of the Bourne Shell's commandline editors (vim or emacs). When you use the command-line editor, you start in Input mode, unlike vim. You can switch between Command and Input modes. The emacs editor is modeless and distinguishes commands from input by recognizing characters as commands.

Aliases An alias is a name that the shell translates into another name or (complex) command. Aliases allow you to define new commands by substituting a string for the first token of a simple command.

Functions A function is a series of commands that, unlike a shell script, is parsed prior to being stored in memory. As a consequence functions run faster than scripts. Scripts are parsed at runtime and are stored on disk. A function can be defined on the command line or within a shell script. If you want the definition to remain in after login sessions, you can define it in a startup file. Like functions in many programming languages, a shell function is called by giving its name followed by any arguments.
