# ANATOMY OF AN iptables COMMAND

Command line This section lists the components of an iptables command line that follow the name of the utility, iptables. Except as noted, the iptables utility is not sensitive to the positions of arguments on the command line. The examples in this chapter reflect a generally accepted syntax that allows commands to be easily read, understood, and maintained. Not all commands have all components.

Many tokens on an iptables command line have two forms: a short form preceded by a single hyphen, and a long form, consisting of a word preceded by two hyphens. Most scripts use the short forms for brevity; using the long forms can get unwieldy. The following iptables command lines are equivalent and used as examples in this section:

```
$ iptables --append FORWARD --in-interface eth1 --out-interface eth0 --jump ACCEPT
$ iptables -A FORWARD -i eth1 -o eth0 -j ACCEPT
```

Table Specifies the name of the table the command operates on: Filter, NAT, or Mangle. You can specify a table name in any iptables command. When you do not specify a table name, the command operates on the Filter. Most examples in this chapter do not specify table names and, therefore, work on the Filter table. Specify a table as --tablename or --table tablename.

Command Tells iptables what to do with the rest of the command line—add, or delete a rule, display rules, or add a chain. The examples commands, -A and --append, add the rule by the command line to the specified table (defaults to Filter table). See page 885 for a list of commands.

Chain Specifies the name of the chain that this rule belongs to or that chain works on. The chain is INPUT, OUTPUT, FORWARD, PREROUTING, POSTROUTING, or the name of a user-defined chain. Specify a chain by putting the name of the command line without any preceding hyphens. The examples at the beginning of this section work with the FORWARD command.

Match There are two kinds of criteria: packet match, which match a network packet, and rule match, which match an existing rule.

Packet match Match criteria identify network packets and elements that take action on packets that match the criteria. The combination of match criteria and action is called a rule specification. Rule specifications provide the basis for filtering. The first example at the beginning of this section uses the --in-interface eth1 --out-interface eth0 rule match criteria. The second example uses the short form of the same: -i eth1 -o eth0. Both of these rules forward packets that come on device eth1 and on device eth0.

Rule match criteria Match criteria identify existing rules. An iptables command can modify, remove, or position a new rule adjacent to a rule by match criteria. There are two ways to identify an existing rule: You can use the same rule specification that was used to create the rule or you can use the rule's ordinal number, called a rule number.
