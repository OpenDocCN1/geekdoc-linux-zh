# # CONFIGURING OPENSSH CLIENTS

This section describes how to set up OpenSSH on the client side.

#  RECOMMENDED SETTINGS

The configuration files provided by Ubuntu a much most secure system and may not meet your needs. One OpenSSH parameter you may want to change is ForwardX11Trusted, which is set to yes by default. To increase security, and in some cases reduce usability, set ForwardX11Trusted (page 675) to no in the Ubuntu /etc/ssh/ssh_config configuration file. See page 681 for more information about X11 forwarding.

Two files list the hosts you have connected to and positively identified: ~/.ssh/known_hosts (user) and /etc/ssh/ssh_known_hosts (global). No one except the owner (root in the case of the second file) should be able to write to either of these files. No one except the owner should have any access to a ~/ssh directory.

When you connect to an OpenSSH server for the first time, the OpenSSH client prompts you to confirm that you are connected to the server and can help prevent a man-in-the-middle attack (footnote 3 on page 1114):

> > The authenticity of 'plum (192.168.0.10)' can't be established.
RSA key fingerprint is 9d:1b:5b:97:5c:80:e9:4b:41:9a:bc7:ea
Are you sure you want to continue connecting (yes/no)? yes
Warning: Permanently added 'plum,192.168.0.10' (RSA) to the list of hosts.

Before you respond to the preceding query, make sure you are logging in on the correct system and not on an imposter. If you are not sure, call a someone you know in that system can help verify that you are on the intended system. When you answer yes (you must spell it out), the client appends the server's public host key (the line in /etc/ssh/ssh_host_rsa_key.pub or /etc/ssh/ssh_host_dsa_key.pub file to the server's ~/.ssh/known_hosts file on the local system, creating the ~/. directory if necessary. So that it can keep track of which known_hosts applies to which server, OpenSSH prepends the name of the server and the server's IP address to the line.

When subsequently use OpenSSH to connect to that server, the client verifies that it is connected to the correct server by comparing this to the one supplied by the server. You can display the local system's RSA key fingerprint using ssh-keygen:

```
$ ssh-keygen -f /etc/ssh/ssh_host_rsa_key.pub
2048 9d:1b:5b:97:5c:80:e9:4b:41:9a:bc7:ea /etc/ssh/ssh_host_rsa_key.pub (RSA)
```
