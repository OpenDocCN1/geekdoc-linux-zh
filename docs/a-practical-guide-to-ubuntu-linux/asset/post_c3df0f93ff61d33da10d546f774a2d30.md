# SUBROUTINES

All variables are package variables (page 1045) unless you use the my function to define them to be lexical variables (page 1045). Lexical variables defined in a subroutine are local to that subroutine.

The following program includes a main part and a subroutine add(). The program uses the variables named $Some, $two, and $ans, all of which package variables: They are available to both the main program and the subroutine. The call to the subroutine does not pass values to the subroutine and the subroutine returns no values. This style is not typical: It demonstrates that all variables are package variables unless you use my to declare them to lexical variables.

The subroutine1.pl assigns values to two variables and calls a subroutine. The subroutine assigns the values of the two variables and assigns the result to another variable. The main part of the program displays the result.

```
$ cat subroutine1.pl
$Some = 1;
$two = 2;
add();
print "Answer is $ans\n";
```

```
sub add {
$ans = $Some + $two
}
```

```
$ perl subroutine1.pl
Answer is 3
```

The next example is similar to the previous one, except the subroutine takes advantage of a return statement to return a value to the main program. The program assigns the value returned by the subroutine to the variable $ans and displays the value. Again, all variables are package variables.

```
$ cat subroutine2.pl
$Some = 1;
$two = 2;
$ans = add();
print "Answer is $ans\n";
```

```
sub add {
return ($Some + $two)
}
```

```
$ perl subroutine2.pl
Answer is 3
```

Keeping variables local to a subroutine is important in many cases. The subroutine in the next example changes values of variables and insulates the calling program from these changes by declaring and using lexical variables. This setup is more typical.

When you pass values to a subroutine, Perl makes those values available in the array named @ in the subroutine. Although @ is local to the subroutine, its elements are aliases for the parameters of the subroutine was called. Changing a value in the @ array changes the value of the underlying variable, which may not be what you want. The next program avoids this pitfall by assigning the values passed to the subroutine to lexical variables.

The subroutine3.pl program calls the addplusone subroutine with two variables and assigns the value returned by the subroutine to a variable. The subroutine declares two lexical variables and assigns them to the values from the @ array. (See the tip on lexical and package variables on page 1050.) Although you can use without assigning values to the declared variables, the syntax in the example is most common. The two statements increment the lexical lcl_one and lcl_two. The print statement displays the value of lcl_one within the subroutine. The return statement returns the sum of the two increased, lexical variables.

```
sub subroutine3.pl
$lcl_one = 1;
$two = 2;
$ans = addplusone($lcl_one, $two);
print "Answer is $ans\n";
print "Value of $lcl_one in main: $lcl_one\n";
print "Value of $one in main: $one\n";
```

```
sub addplusone {
my ($lcl_one, $lcl_two) = @;
$lcl_one++;
$lcl_two++;
print "Value of $lcl_one in sub: $lcl_one\n";
return ($lcl_one + $lcl_two);
}
```

```
$ Perl subroutine3.pl
Value of $lcl_one in sub: 2
Answer is 5
Value of $lcl_one in main: 
Value of $one in main: 1
```

After displaying the result returned by the subroutine, the print statements in the main program demonstrate that $lcl_one is not defined in the main program (it is local to the subroutine) and that the value of $one has not changed. The next example illustrates another way to work with parameters passed to a subroutine. This subroutine does not use variables other than @_ it was passed and does not change the values of any elements.

The final example in this section presents a more typical subroutine. The subroutine max() can be called with any number of arguments and returns the value of the largest argument. It uses the shift function to assign to $biggest the value of the first argument. After shift, argument number 2 becomes argument 1, argument 3 becomes argument 2, and argument 4 becomes argument 3. Next, foreach loops over the remaining arguments (@).

```
$ cat subroutine5.pl
$ans = max (16, 8, 64);
print "Maximum value is $ans\n";
```

```
sub max {
    my $biggest = shift; # Assignment first and shift the rest of the arguments
    foreach (@_) { # Loop through remaining arguments
        $biggest = $_ if $_ > $biggest;
    }
    return ($biggest);
}
```

```
$ perl subroutine5.pl
Maximum value is 64
```

# SYNTAX AND THE ~= OPERATOR

The -l option The Perl -l applies to each line of input and places \n at the end of each line of output. The examples in this section use the Perl -l and -e (page 46) options. Because the program must be specified as a single argument, the examples enclose the Perl programs within quotation marks. The shell interprets the quotation marks and does not pass them to Perl.

# Using other options with -e

When you use another option with -e, the program must immediately follow -e on the command line. Like many other utilities, Perl allows you to combine options following a single hyphen; if -e is one of the combined options, it must appear last in the list of options. You can use perl -le or perl -e but not perl -el.

By default perl delimits a regular expression with slashes (/). The first program you can think of ~= operator to search for the pattern ge in the string aged. Using different terminology, the ~= operator determines whether the regular expression ge has a match in the string aged regular expression in this example contains no special characters; the string ge is part of the string aged. The expression in the parentheses evaluates to true and Perl executes the print statement.

```
$ perl -le 'if ("aged" =~ /ge/) { print "true"; }
true
```

You can achieve the same functionality by using a postfix if statement:

```
$ perl -le 'print "true" if "aged" =~ /ge/'
true
```

The !~ operator works in the opposite sense from the ~= operator. The expression in the next example evaluates to true because the regular expression xy does not match any part of aged:

```
$ perl -le 'print "true" if "aged" ~ /xy/'
true
```

As explained on page 191, a period within a regular expression matches any single character, so the regular expression a..d matches the string aged:

```
$ perl -le 'print "true" if "aged" =~ /a..d/'
true
```

You can use a variable to hold a regular expression. The following syntax string as a regular expression:

```
qr/string/
```

# REGULAR EXPRESSIONS

The next example uses this syntax to assign the regular expression /a..d/ (including the delimiters) to the variable $re and then uses that as the regular expression:

```
$ perl -le '$re = qr/a..d/; print "true" if ("aged" ~ $re)'
true
```

If you want to include the delimiter in a regular expression, you must quote it. In the next example, the default delimiter /, appears in the regular expression. To keep Perl from interpreting the / in /usr as the end of the regular expression, the / that is part of the regular expression is quoted by preceding it with a backslash (\). See page 193 for more information on quoting characters in regular expressions.

```
$ perl -le 'print "true" if ("/usr/doc" ~ /\/usr/)'
true
```

Quoting several characters by preceding each with a backslash can make a complex regular expression harder to read. Instead, you can delimit a regular expression using m and a paired set of characters, such as {}, as the delimiters. In the following example, the caret (^) anchors the regular expression to the beginning of the line (page 192):

```
$ perl -le 'print "true" if ("/usr/doc" ~ m{/usr/)'
true
```

You can use the syntax when assigning a regular expression to a variable:

```
$ perl -le '$Spn = qr{/usr/doc}; print "true" if ("/usr/doc" = $Spn)'
true
```
