# PROCESSING THE COMMAND LINE

Whether you are working interactively or running a bash script, bash needs to read a command line before it can start processing it—bash always reads at least one line before processing a command. Some bash builtins, such as if and case, as well as functions and quoted strings, span multiple lines. When bash recognizes a command that covers more than one line, it reads the entire command before processing it. In interactive sessions, bash prompts you with the secondary prompt (PS2, > by default; page 322) as you type each line of a multiline command until it recognizes the end of the command:

```
$ echo 'hi
> end'
hi
end
$ function hello () {
> echo hello there
> }
$
```

After reading a command line, bash applies history expansion and alias substitution to the line.

# HISTORY EXPANSION

“Reexecuting and Editing Commands” on page 332 discusses the commands you can give to modify and reexecute command lines from the history list. History expansion is the process that bash uses to turn a history command into an executable command. For example, when you give the command !!, history expansion changes that command line so it is the same as the previous one. History expansion is turned on by default for interactive shells; set +o histextend turns it off. History expansion does not apply to noninteractive shells (shell scripts).

# ALIAS SUBSTITUTION

Aliases (page 346) substitute a string for the first word of a simple command. By default aliases are turned on for interactive shells and off for noninteractive shells. Give the command opt -u expand_aliases to turn aliases off.

# COMMAND-LINE EXPANSION

Both interactive and noninteractive shells transform the command line using command-line expansion before passing the command line to the program being called. You can use a shell without knowing much about command-line expansion, but can use what a shell has to offer to a better advantage with an understanding of this topic. This section covers Bourne Again Shell command-line expansion.

The Bourne Again Shell scans each token for the various types of expansion and substitution in the following order. Most of these processes expand a word into a single word. Only brace expansion, word splitting, and pathname expansion can change the number of words in a command (except for the expansion of the variable @”—see page 1000).

1. Brace expansion (page 358)
2. Tilde expansion (page 359)
3. Parameter and variable expansion (page 360)
4. Arithmetic expansion (page 360)
5. Command substitution (page 362)
6. Word splitting (page 363)
7. Pathname expansion (page 363)
8. Process substitution (page 365)

> Quote removal After bash finishes with the preceding list, it removes from the command line single quotation marks, double quotation marks, and backslashes that are not a result of an expansion. This process is called quote removal.

# ORDER OF EXPANSION

The order in which bash carries out these steps affects interpretation. For example, if you use a command that uses brace notation, the shell expands the arguments within the braces.

```
$ echo chap_{one,two,three}
chap_one.txt chap_two.txt chap_three.txt
```

The shell expands the comma-separated strings inside the braces in the echo command into a space-separated list of strings. Each string from the list is prepended with the string chap_, called the preamble, and appended with the .txt, called the postscript. Both the preamble and postscript are optional. The left-to-right order of the strings within the braces is preserved in the expansion. For the shell to treat the left and right braces characters specially and for brace expansion to occur, at least one comma and no whitespace characters must be inside the braces. You can nest braces.

# BRACE EXPANSION

Brace expansion, which originated in C Shell, provides a convenient way to specify filenames when pathname expansion does not apply. Although brace expansion is often used to specify filenames, the mechanism can be used to generate arbitrary strings; the shell does not attempt to match the brace notation with existing files.

Brace expansion is turned on for interactive and noninteractive shells by default; you can turn it off with set +expand. The shell also uses braces to isolate variables (page 316).

The following example illustrates how brace expansion works. The ls command does not display any output because there are no files in the working directory. The echo builtin displays the strings that the shell generates with brace expansion. In this case the strings do not match filenames.

```
$ echo chap_{one,two,three}.txt
chap_one.txt chap_two.txt chap_three.txt
```

Brace expansion is useful when there is a long preamble or postscript. The following example copies main.c, f1.c, f2.c, and tmp.c—located in /usr/local/src/C/ directory to the working directory:

```
$ cp /usr/local/src/C/{main,f1,f2,tmp}.c
```

You can also use brace expansion to create directories with related names:

```
$ ls -F
file1 file2 file3
$ mkdir vrs{A,B,C,D,E}
$ ls -F
file1 file2 file3 vrsA/ vrsB/ vrsC/ vrsD/ vrsE/
```
