# CIDR: CLASSLESS INTER-DOMAIN ROUTING

CIDR (pronounced "cider") allows groups of addresses that are smaller than a class C to be assigned to an organization or ISP and then further subdivided and parsed out. In addition, it helps to alleviate the potential problem of routing tables on major Internet backbone and peering devices becoming too large to manage.

The pool of available IPv4 addresses has been depleted to the point that no one gets a class A address anymore. The trend is to reclaim these huge blocks, if possible, and recycle them into groups of smaller addresses. Also, as more class C addresses are assigned, routing tables on the Internet are filling up and causing overflows. The solution is to aggregate groups of addresses into blocks and allocate them to ISPs. The address class designations (A, B, and C) in the previous section are used less often today, although you may still encounter subnets. When you request an address block, your ISP usually gives you many addresses as you need—and no more. The ISP aggregates several smaller blocks and routes them to your location. This aggregation is CIDR. Without CIDR, the Internet as we know it would not function.

For example, you might allocate the 192.168.5.0/22 IP block, which could support 2⁰ hosts (32 – 2 = 10). Your ISP would set its routers so that any packets going to an address in that block would be sent to your router. Internally, your own routers might further subnet this block of 1,024 hosts into subnets, perhaps into four networks. Four networks require an additional two bits of addressing (² = 4). You could then set your router to support four networks with this allocation: 192.168.5.0/24, 192.168.6.0/24, 192.168.7.0/24, and 192.168.8.0/24. Each of these networks could have 254 hosts. CIDR lets you divide networks and subnetworks into increasingly smaller blocks along the way. Each router has enough memory to keep track of the addresses it needs to direct and aggregate the rest.

This scheme uses memory and address space efficiently. For example, you could take 192.16.8.0/24 and further divide it into 16 networks with 14 hosts each. The 16 networks require four more bits (⁴ = 16), so you would have 192.16.8.0/28, 192.16.8.32/28, and so on, up to the last subnet of 192.16.8.240/16, which would have the hosts 192.16.8.241 through 192.16.8.254.
