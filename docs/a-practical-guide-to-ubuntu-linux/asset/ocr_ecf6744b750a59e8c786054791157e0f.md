PAM file is not working properly. To prevent a malicious user from seeing informa-tion about PAM, PAM sends error messages to a file rather than the screen.

# Do not lock yourself out of the system

Editing PAM configuration files correctly requires careful attention. It is easy to lock-self out of the system with a single mistake. To avoid this, keep backup copies of the PAM configuration files you edit, test every change thoroughly. Keep a root shell open (using sudo -l) until you have finished testing. If a change fails and you cannot log in, use the root shell to replace the newly edited files with the backup copies.

# CONFIGURATION FILES, MODULE TYPES, AND CONTROL FLAGS

```
Login module $ grep '^[^#]*' /etc/pam.d/login
auth    required pam_security.so
auth    required pam_nologin.so
session required pam_env.so envfile=1
session required pam_env.so envfile=1/etc/default/locale
@include common-auth
auth    optional pam_group.so
session required pam_limits.so
session optional pam_lastlog.so
session optional pam_motd.so
session optional pam_mail.so standard
@include common-account
@include common-session
@include common-password
```

Each line tells PAM to do something as part of the authentication process. The first word on each line is a module type: account, auth, password, or session. The second is a control flag (Table 11-5, next page) indicates the action PAM should take if authentication fails. The rest of the line contains the name of a PAM module (located in /lib/security) and any arguments for that module. The PAM library itself uses the /etc/pam.d files to determine which modules to delegate to. Lines that begin with @include include the named file.
