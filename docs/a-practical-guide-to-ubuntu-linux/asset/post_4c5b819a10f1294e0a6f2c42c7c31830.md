
/etc/motd Contains the message of the day, which can be displayed each time someone logs in using a textual login. This file typically contains site policy and legal information. Keep this file short before users to see the message many times.

/etc/mtab When you call mount without any arguments, it consults this file and displays a list of mounted devices. Each time you (or an init script) call mount or unmount, these utilities make the necessary changes to mtab. Although this is an ASCII text file, you should not edit it. Also /etc/fstab.

## Fixing mtab

The kernel maintains its own internal mount table. You can display this table with the command /proc/mounts. Sometimes the list of files in /etc/mtab may not be synchronized with the partitions in this table. To bring the mtab file in line with the operating system's mount table, you can either reboot the system or replace /etc/mtab with a symbolic link to /proc/mounts (although some information may be lost).

```bash
$ rm mtab
$ ln -s /proc/mounts /etc/mtab
```

/etc/nsswitch.conf Specifies whether a system uses NIS, DNS, local files, or a combination as the source of certain information, and in what order it consults these services (page 475).

/etc/pam.d Files in this directory specify the authentication methods used by PAM (page 478) applications.

/etc/passwd Describes users to the system. Do not edit this file directly; instead, use one of the utilities discussed in "Configuring User and Group Accounts" (page 594). Each line in passwd has colon-separated fields that describe one user:

```text
login-name:password:userID:groupID:info:directory:program
```

The login-name is the user's name—the name you enter in response to the login prompt or on a GUI screen. The value of the password is the character x. The /etc/shadow file (page 497) stores the real password, which is hashed (page 1151). For security reasons, every account should have a password. By convention, disabled accounts have an asterisk (*) in this field.

The User-ID is a number, 0 indicating the root account and 1–999 being reserved for system accounts. The group-ID identifies the user as a member of a group. With 0–999 being reserved for system accounts; see /etc/group (page 492). You can change these values and set maximum values in /etc/login.defs.

The info contains various programs, as accounting and email programs, use to identify the user. Normally it contains the first and last names of the user. It is referred to as the GECOS (page 1150).

The directory is the absolute pathname of the user's home directory. The program that runs once the user logs in to a textual session. If program is not present, a value of /bin/bash is assumed. You can put /bin/zsh to log in using the Z Shell, assuming the shell you specify is the TCSh utility (page 457) which changes this value.

The program is usually a shell, but it can be any program. The following line in the passwd file creates a “user” whose only purpose is to execute the who utility:

```text
who:x:1000:1000:execute:/usr/bin/who
```

Logging in with who as a username causes the system to log in, execute the utility, and you log out. The output of who flashes quickly because the new login prompt clears the screen immediately after finish running. The passwd file does not provide a shell, so you cannot stay logged after finishes executing.

This technique is useful for providing special accounts that may only do one thing. The frp account, enables anonymous FTP (page 687) access to an FTP server. Because no one logs in this account, the shell is set to /bin/false (which returns a false status) or /usr/sbin/nologin (which does not permit a nonprivileged user to log in). When you put a message in /etc/nologin, nologin displays a message (except it has the same problem as the output of who: It is removed quickly that it is hard to see).

## Do not replace a login shell with a shell script

security Do not use scripts as replacements for shells in /etc/passwd. A user may be able to interrupt a shell script, giving him full access when you do not intend to do so. When installing a dummy shell, use a compiled program, not a shell script.

/etc/printcap The printer database for LPD/LPR (page 548). It is not used with CUPS (Chapter 14), Ubuntu’s default printing system. This file describes system printers and is derived from 4.3BSD UNIX. 

/etc/profile Contains a systemwide interactive shell initialization script for environment and startup programs. When you log in, the shell immediately executes the commands in this file in the same environment as the shell. (For information on executing a shell script in this manner, refer to the discussion of the .dot] command on page 296.). This file allows the system administrator to establish environment parameters that individual users can override in ~/.bash_profile (page 488). For example, this file can set shell variables, execute utilities, set as aliases, and care of housekeeping tasks.

The default Ubuntu /etc/profile file sets the prompt and executes the commands in /etc/bash.bashrc (page 492).

Following is an example of a /etc/profile file that displays the message of the day (the /etc/motd file), sets the file-creation mask (umask, page 459), and interrupts character to CTRL-C:

```bash
# /etc/profile
cat /etc/motd
umask 022
stty intr 'c'
```

/etc/protocols Provides protocol numbers, aliases, and brief definitions for DARPA Internet TCP/IP protocols. Do not modify this file.

/etc/init Holds Startup job definition files. See page 438 for more information.

/etc/init.d Holds SysVinit initialization scripts. See page 440 for more information.

/etc/resolv.conf The resolver (page 824) configuration file, which is used to access DNS. By default, this file is rebuilt by resolvconf when you run the bind9 init script. “named options” on page 834, “resolconf and resolv.conf” on page 835, and the resolver and resolv.conf man pages for more information.

The following example shows the resolv.conf file for the example domain. resolv.conf file usually contains two lines—a search line (optional) and a nameserver line:

```text
# /etc/resolv.conf
search example.com
nameserver 10.0.0.50
nameserver 10.0.0.51
```

The search keyword may be followed by a maximum of six domain names. The first domain name is interpreted one at a time to all DNS queries, shortening the time needed to resolve hosts that are not fully qualified. See FQDN on page 1149. When you search example.com in resolv.conf, any reference to a host within the example.com domain or a subdomain (such as marketing.example.com) can use the abbreviated form of the host. For example, instead of using the command speedy.marketing.example.com, you can use speedy.marketing.com. The following line in resolv.conf causes the marketing subdomain to be searched first, followed by sales, and finally the entire example domain:

```text
search marketing.example.com sales.example.com
```

It is a good idea to put the most frequently used domain names first to try outguess possible conflicts. If both speedy.marketing.example.com and speedy.example.com exist, the order of the search determines which one is selected when you invoke DNS. The longer the search, the more work DNS requests generated, and the slower the response.

The nameserver line(s) indicate which systems the local system should query to resolve hosts to IP addresses, and vice versa. These machines are consulted in the order they appear, with a timeout between queries. The first timeout is a few seconds; each subsequent timeout is twice as long as the previous. The preceding file sets this system to 10.0.0.50, followed by 10.0.0.51 when the first system does not answer within a few seconds. The resolv.conf file may be automatically updated when a PPP (Point-to-Point Protocol) or DHCP (Dynamic Host Configuration Protocol) controlled interface is activated.

/etc/rpc Maps RPC services to RPC numbers. The three columns in this file show the name of the server for the RPC program, the RPC number, and any aliases.
