# IMPORTANT FILES AND DIRECTORIES

+   * /dev/hda—The master disk on the primary IDE controller. The slave disk on the primary IDE controller is named /dev/hdb. This may be a CD-ROM drive.

+   * /dev/hdc—The master disk on the secondary IDE controller. The slave disk on the secondary IDE controller is named /dev/hdd. This may be a CD-ROM drive.

+   * /dev/sda—Traditionally the first SCSI disk; the now first-IDE drive, including SATA and USB drives. Other similar drives are named /dev/sdb, /dev/sdc, etc.

These names, as /dev/sda, represent the order of the disks on the bus devices are connected to. For example, if you swap the cables on the disks referred to as /dev/sda and /dev/hdc, the drive's designations will change. Similarly, if you remove the device referred to as /dev/sda, the device that was referred to as /dev/sdb will now be referred to as /dev/sda.

/dev/disk/by-path Holds symbolic local devices. The names of devices in this directory identifies them. Each entry points to the device in that it refers to.

```
$ ls -1 /dev/disk/by-path
lrwxrwxrwxrx 1 root 10 2010-04-09 09:42 pci-0000:10:0-scsi0:0:0:0--part-1 -> ..//sda
lrwxrwxrwxrx 1 root 10 2010-04-09 09:42 pci-0000:10:0-scsi1:0:0:0--part-2 -> ..//sda2
lrwxrwxrwxrx 1 root 10 2010-04-09 09:42 pci-0000:10:0-scsi1:0:0:5-part-5 -> ..//sda5
```

/dev/disk/by-uuid Holds symbolic links. The names of devices in this directory consist of the UUID (page 1179) numbers. Each entry points to the device in that it refers to. See page 510 for more information.

```
$ ls -1 /dev/disk/by-uuid
lrwxrwxrwxrx 1 root 10 2010-04-09 09:42 bbf66cc-f3d4-4acd-857a-99a2abcd3030 -> ..//sda5
lrwxrwxrwxrx 1 root 10 2010-04-09 09:42 e1adf66b-39e8-4658-832c-67f5ec82c4 -> ..//sda
```

/dev/null Also called a bucket. Output sent to this file disappears. The /dev/null file is a device file. It that redirect to come from this file appears as null values, giving one of the following commands:

```
$ cat /dev/null nothing
$ cp /dev/null nothing
```

or, explicitly using /dev/null,

```
$ > nothing
```

The last command returns the output of a command to the file with the same result as the previous commands. You can use any of these to truncate an existing file to zero length without changing its permissions. You can also use /dev/null to get rid of output that you not want:

```
$ grep prototype 2> /dev/null
```
