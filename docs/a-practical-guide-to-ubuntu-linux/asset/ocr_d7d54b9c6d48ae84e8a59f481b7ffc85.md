# GOING TO MULTIUSER MODE

Multiuser/graphical mode (runlevel 2) is the default state for Ubuntu Linux system. In this mode all appropriate filesystems are mounted, and users can log in from all connected terminals, dial-up lines, and network connections. All services and daemons are enabled and running. With the system in multiuser, Ubuntu displays a graphical login screen on the console.

If you booted into recovery mode to fix something, the system entered a reboot command and allow the system to come up in multiuser mode. If it automatically allow you to repair the filesystem, when you exit from the recovery shell, init brings the system to the default mode—usually multiuser. Alternatively, you can give the following command in response to the root prompt to bring the system to multiuser:

+   # telinit 2

The telinit utility (page 444) tells init which runlevel to change.
When it comes from recovery (single-user) to multiuser mode, the system executes the K (kill or stop) scripts and then the S (start) scripts in /etc/rc.rc2.d. For more information refer to "SysInit (rc) Scripts: Start and Stop Services" on page 440. Use sysv-rc-conf (page 441) to stop any of these scripts from running when the system enters the new runtime.

# LOGGING IN

Textual login: init. With a textual login, the system uses init, getty, and login to allow a user to log in; getty, and login uses PAM modules (page 478) to authenticate a user. Once the system is in multiuser mode, init is responsible for spawning a process on each of the lines

When you enter your username, getty establishes the characteristics of the terminal. It overlays itself with a login process and passes to the login process you entered in response to the login prompt. Using PAM, the login process checks the /etc/passwd file to see whether any username matches yours. Next, PAM examines the /etc/shadow file to see whether a password is associated with the username. If it is, login prompts you for a password; if not, it continues without requiring a password. When your username requires a password, login verifies the password you enter by checking the /etc/shadow file again. If either your username or password is not correct, login displays Login incorrect, pauses, and prompts you to log in again.
