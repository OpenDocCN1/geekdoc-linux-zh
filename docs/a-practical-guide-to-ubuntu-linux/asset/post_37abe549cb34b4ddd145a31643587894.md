# SUBNETS

Each host on a network must process each broadcast packet to determine whether the information in the packet is useful to that host. If the network includes numerous hosts, each host must process many packets. To maintain efficiency most networks—and particularly shared media networks as Ethernet—need to be split into subnet, or subnets. The more hosts on a network, the more dramatically network performance is affected. Organizations use router and switch technology to VLANs (virtual local area networks) to group similar hosts into broadcast domains based on function. For example, it is not uncommon to switch with different ports being part of different subnets. See page 462 for information on how to specify.

A subnet mask (or address mask) is a bit mask that identifies which of an IP address corresponds to the network address and the subnet portion of the address. This mask has 1s corresponding to the network and subnet numbers and 0s in the host number positions. When you perform a bitwise AND on an IP address and a subnet mask the resulting address contains except the host (hostid) portion.

There are several ways to represent a subnet mask: A network could have a subnet mask of 255.255.255.0 (decimal), FFFFF0 (hexadecimal), or /24 (the number of bits used for the subnet). If it is a Class B network (of which 16 bits are already fixed), these 2⁸ (24 bits — 16 bits = 8 bits, 2⁸ = 254) networks with 2⁸ - 2 (256 – 2 = 254) on each network.

For example, when you divide the Class address 192.25.4.0 into eight subnets, you get a subnet mask of 255.255.255.224, FFFFFE0, or /27 (27 bits). The result-networks are 192.25.4.0, 192.25.4.32, 192.25.4.64, 192.25.4.96, 192.25.4.128, 192.25.4.160, 192.25.4.192, and 192.25.4.224. You can use a Web-based subnet mask calculator to calculate subnet masks (refer to “Network Calculators” on page 1105). To use this calculator to determine the preceding subnet mask, start with an IP address of 192.25.4.0.

For more information refer to “Specifying a Subnet” on page 462.

# CIDR: CLASSLESS INTER-DOMAIN ROUTING

CIDR (pronounced "cider") allows groups of addresses that are smaller than a class C to be assigned to an organization or ISP and then further subdivided and parsed out. In addition, it helps to alleviate the potential problem of routing tables on major Internet backbone and peering devices becoming too large to manage.

The pool of available IPv4 addresses has been depleted to the point that no one gets a class A address anymore. The trend is to reclaim these huge blocks, if possible, and recycle them into groups of smaller addresses. Also, as more class C addresses are assigned, routing tables on the Internet are filling up causing overflows. The solution is to aggregate groups of addresses into blocks and allocate them to ISPs. The address designations (A, B, and C) in the previous section are used less often today, although you may still encounter subnets. When you request an address block, your ISP usually gives you many addresses as you need—and no more. The ISP aggregates several smaller blocks and routes them to your location. This aggregation is CIDR. Without CIDR, the Internet as we know it would not function. For example, you might allocate the 192.168.5.0/22 block, which could support 2¹⁰ hosts (3² = 10). Your ISP would set its routers so that any packets going to that block would be sent to your router. Internally, your own routers might further subnet this block of 1024 hosts into four networks. Four networks require an additional bits (² = 4). You could then set your router to support four networks with this allocation: 192.168.5.0/24, 192.168.6.0/24, 192.168.7.0/24, and 192.168.8.0/24. Each of these networks could have 254 hosts. CIDR lets you divide networks and subnet into increasingly smaller blocks along the way. Each router has enough memory to keep track and direct the rest. This scheme uses memory and address space efficiently. For example, you could take 192.168.8.0/24 and further divide it into sixteen networks with 16 hosts each. Sixteen networks require four more bits (⁴ = 16), so you would have 192.168.8.0/28, 192.168.8.16/28, and so on, to the last subnet of 192.168.8.240/28, which would have 15 hosts.

# HOSTNAMES

People find it easier to work with names than numbers, as Linux provides several ways to associate hostnames with IP addresses. The oldest method is to consult a list of names and addresses that are stored in the /etc/hosts file:

```
$ cat /etc/hosts
127.0.0.1       localhost
130.128.52.1   gw-example.com gw-example
130.128.52.2   bravo.example.com bravo
130.128.52.3   hurrah.example.com hurrah
130.128.52.4   kudos.example.com kudos
```

localhost—The 127.0.0.1 is reserved for the special hostname localhost, which serves as a hook for the system's networking software to operate on the local machine without going onto a physical network. The names of the other systems are shown in two forms: a fully qualified domain name (FQDN) format that is unique on the Internet and as a nickname locally.

As more networks joined, storing these name-to-address mappings in a text file proved to be inefficient and inconvenient. Hosts grew increasingly and became impossible to keep up-to-date. To solve this problem Linux softwares use DNS (Network Information Service, page 401), which was developed for Sun computers. DNS stores information in a database, making it easier to find a specific address, but it is useful only for host information within a single administrative domain. Hosts outside the domain cannot access the information.

The solution to this dilemma is DNS (Domain Name Service, page 399), DNS effectively addresses the efficiency and update issues by arranging the entire network namespace (page 1161) as a hierarchy. Each domain in the DNS manages its own namespace (and address resolution), each domain can easily query for any host or IP address by following the tree or down the namespace until it finds the appropriate domain. By providing a hierarchical naming structure, DNS distributes name administration across the entire Internet.

# IPv6

The explosive growth of the Internet has uncovered deficiencies in the design of the current address plan—most notably the shortage of addresses. In the next few years, a revised protocol, named IPv6 (IP Next Generation), also known as IPv6 (IP version 6), will be phased in. (It may take longer—the phase in is going slowly). This new scheme is designed to overcome the major limitations of the current approach and can be implemented gradually because it is compatible with the existing address base. IPv6 makes possible to assign many unique Internet addresses ($2^{¹⁸}$, or 340 undecillion $[10^{³⁶}]$). It also supports more advanced security and performance control features:

- IPv6 enables autoconfiguration. With IPv4, autoconfiguration is available using optional DHCP (page 470). With IPv6, autoconfiguration is mandatory, making it easier for hosts to configure their addresses automatically.
