# exec: EXECUTES A COMMAND

The exec builtin used for running a command has the following syntax:

# exec command arguments

exec versus. (dot) Insofar exec runs a command in the environment of the original process, it is similar to the .(dot) command (page 296). However, unlike the .command, which can run only shell scripts, exec can run compiled programs. Also, whereas the .command returns to the original script when it finishes running, exec does not. Finally, the command gives the new program access to local variables, exec does not.

exec does not return control Because the shell does not create a new process when you use, the command runs more quickly. However, because exec does not return control to the original program, it can be used only as the last command in a script. The following script shows that control is not returned to the script:

```
$ cat_demo
who
exec date
echo "This line is never displayed.",
```

```
$ ./exec_demo
zach pts/7 May 20 7:05 (bravo.example.com)
hls/1 May 20 6:59 (:0)
Mon May 24 11:42:56 PDT 2010
```

The next example, a modified version of the out script (page 959), uses exec to execute the final command the script runs. Because out runs either cat or less and terminates, the new process, named out2, uses exec with both cat and:

```
$ cat out2
if [ $ -eq 0 ]
then
techo "Usage: out2 [-v] filenames" 1>&2
texit 1
fi
if [ "$1" = "-v" ]
then
tshift
texec less "$0"
elelse
texec cat -- "$0"
fi
```

# exec: REDIRECT INPUT TO OUTPUT

The second major use of exec is to redirect a file descriptor—including standard input, output, or error—from a script. The next command causes all subsequent input to a script that would have come from standard input to come from the file named:

```
exec < infile
```
