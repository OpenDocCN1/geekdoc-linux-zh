+   * Avoid unused ports available in public areas. If a malicious user can plug a laptop to the network without being detected, you are at risk of a serious security problem. Network drops that will remain unused for extended periods be disabled at the switch, preventing them from accepting or passing network traffic.

+   * Many network switches have provisions for binding a hardware address to a port for enhanced security. If someone unplugs one machine and plugs in another machine to capture traffic, chances are the second machine will have a different hardware address. When it detects a device with a different hardware address, the switch can disable the port. This solution is no guarantee, however, as some programs enable you to change or mask the hardware address of a network interface.

# Install a small kernel and run all the programs you

security Linux systems contain a huge number of programs, although useful, significantly reduce the security of the host. Install the smallest operating system kernel that meets your needs. For Web and FTP servers, install the needed components and not install a graphical interface. Users may require additional packages.

+   * Do not allow NFS or NIS access outside the local network. Otherwise, it is a simple matter for a malicious user to steal the password map. Default NFS security is marginal to nonexistent (a common joke is that NFS stands for No File Security or Nightmare File System) such should not be allowed outside your network to machines that you do not trust. Experimental versions of NFS for Linux that support better authentication algorithms are now becoming available. Use IPSec, NFSv4 (which includes improved authentication), or firewalls to provide access outside of your domain.

+   * Support for VPN configuration is built into new firewalls or provided as a separate product, enabling your system to secure with the systems of your customers or partners. If you may allow business partners, contractors, or other outside parties to access local files, consider using a secure filesystem, as with NFS with Kerberos (page 1156), secure NFS (encryption authentication, not traffic), NFS over a VPN as IPSec, or cfs (cryptographic filesystem).

+   * Specify /usr (ro) in /etc/fstab. Following is an example of such configuration:

```
/dev/sda6 /usr ext2 ro 0 0
```

This approach may make your machine difficult to update, so use this tactic with care.
