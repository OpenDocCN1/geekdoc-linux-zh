
Because each argument is evaluated as a separate expression, you can assign values to more than one variable on a single line:

```
$ let COUNT = COUNT + 1 VALUE=*10+NEW
```

You need to use commas to separate multiple assignments within a set of parentheses:

```
$ ((COUNT = COUNT + 1, VALUE=*10-NEW))
```

## Arithmetic evaluation versus arithmetic expansion

Arithmetic evaluation differs from arithmetic expansion. As explained on page 360, arithmetic expansion uses the syntax $((expression)), evaluates expression, and replaces $((expression)) with the result. You can use arithmetic expansion to display the value of an expression or assign that value to a variable.

Arithmetic evaluation uses the let expression or ((expression)) syntax, evaluates expression, and returns a status code. You can use arithmetic evaluation to perform a logical comparison or an assignment.

You can use the ((expression)) syntax for logical expressions, although task is frequently left to [[expression]]. The next example expands the age_check script (page 360) to include logical arithmetic evaluation in addition to arithmetic expansion:

```
$ cat age2
!/bin/bash
echo -n "How old are you? "
read age
if ((30 && age < 60)); then
    echo "Wow, in $((60-age)) years, you'll be 60"
else
    echo "You are too young or too old to play."
fi
```

```
$ ./age2
How old are you? 25
You are too young or too old to play.
```

The test-statement for the if structure evaluates two logical comparisons joined by a Boolean AND returns 0 (true) if they are both true or 1 (false) otherwise.

## LOGICAL EVALUATION (CONDITIONAL EXPRESSIONS)

The syntax of a conditional expression is

```
[[ expression ]]
```

where expression is a Boolean (logical) expression. You must precede a variable name with a dollar sign ($) within expression. The result of executing this, is a return status. The conditions allowed within the brackets are a subset of those accepted by test (page 955). Where the test uses -a as a Boolean AND operator, [[ expression ]] uses &&. Similarly, where test uses -o as a Boolean OR operator, [[ expression ]] uses ||.

To see how conditional expressions works, replace the line that tests age in the age2 script with the following conditional expression. You must surround the [[ and ]] tokens with whitespace or a command terminator, and place dollar signs before the variables:

```
if [[ 30 < $age $age < 60 ]]; then
```

You can also use test's relational operators -gt, -ge, -lt, -le, -eq, and -ne:

```
if [[ 30 -lt $age $age -lt 60 ]]; then
```

The test builtin tests whether strings are equal. The [[ expression ]] syntax adds comparison tests for string operators. The > and < operators compare strings for order, "aa" = "bbbb". The operator tests for pattern match, not just equality; [[ string = pattern ]] is true matches. This operator is not symmetrical; the pattern must appear on right side of the sign. For example, [[ artist = a ]] is true (=0), whereas [[ a*= artist ]] is false (=1):

```
$ [[ artist = a ]]
$ echo $$
$ [[ a*= artist ]]
$ echo $?
```

The next example uses a command line that starts with a compound condition. The condition tests that the directory bin and the file src/myscript.bash exists. If this is true, cp copies src/myscript.bash to bin/myscript. If the copy succeeds, chmod makes myscript executable. If any of these steps fails, echo displays a message.

```
$ [[ -d bin -f src/myscript.bash ]] && cp src/myscript.bash \
/myscript && chmod +x bin/myscript || echo "Cannot make \
executable version of 'myscript'
```

## STRING PATTERN MATCHING

The Bourne Again Shell provides string pattern-matching operators that can manipulate patterns and other strings. These operators can delete from string prefixes or suffixes that match patterns. Table 27-7 lists the four operators.

| --- | --- |
| # | Removes minimal matching prefixes |
| ## | Removes maximal matching prefixes |
| % | Removes minimal matching suffixes |
| %% | Removes maximal matching suffixes |

The syntax for these operators is

```
${varname%pattern}
```

## Do not rely on rules of precedence: use parentheses

Do not rely on the precedence rules when you use compound commands. Instead, use parentheses to explicitly state the order in which you want the shell to interpret the commands. The postincrement, postdecrement, preincrement, and decrement work with variables. The pre-operators, which appear in the front of the variable name (as in ++COUNT and --VALUE), first change the value of the variable (++ adds 1; -- subtracts 1) and then provide the result for use in the expression. The postoperators appear after the variable name (as in COUNT++ and VALUE--); they first provide the unchanged value of the variable for use in the expression and then change the value of the variable.

```
$ N=10
$ echo $N
10
$ echo $((--N+3))
12
$ echo $N
9
$ echo $((N++-3))
6
$ echo $N
10
```

## Remainder

The remainder operator (%) yields the remainder when its first operand is divided by its second. For example, the expression $((15%7)) has the value 1.

## Boolean

The result of a Boolean operation is either 0 (false) or 1 (true).

The && (AND) and || (OR) Boolean operators are called short-circuiting operators. If the result of using one of these can be decided by looking only at the left operand, the right is not evaluated. The && or || operator causes the shell to test the exit status of the command preceding it. If the command succeeded, bash executes the next command; otherwise, it skips the remaining commands on the command line. You can use this to execute commands conditionally.

```
$ mkdir bkup && cp -r src bkup
```

This command creates the directory bkup. The contents of directory src is copied recursively to bkup.

The || also causes to test the exit status of the first command but has the opposite effect: The remaining command(s) are executed only if the first one failed (that is, exited with nonzero status).

```
$ mkdir bkup || echo "mkdir bkup failed" >> /tmp/log
```

The exit status of a command list is the exit status of the last command in the list. You can group lists with parentheses. For example, you could combine the two examples as

```
$ (mkdir bkup && cp -r src bkup) || echo "mkdir failed" >> /tmp/log
```

In the absence of parentheses, && and || have equal precedence and are grouped from left to right. The following examples use the true and false utilities. These utilities do nothing and return true (0) and false (1) exit statuses, respectively:

```
$ false; echo $?
1
```

The $ variable holds the exit status of the preceding command (page 996). The next two commands yield an exit status of 1 (false):

```
$ true || false
echo $?
1
```

Likewise the two commands yield an exit status of 0 (true):

```
$ false && false || true
$ echo $?
0
$ (false && false) || true
$ echo $?
0
```
