
## deb FILES

The dpkg management system works with .deb format files, frequently referred to as deb files. dpkg cannot download deb files from repositories, aptitude (page 526) typically performs this task. By default, aptitude downloaded deb files in /var/cache/apt/archives. The dpkg management system stores available package information in /var/lib/dpkg/available and installation information in /var/lib/dpkg/status.

You can manage, download, and install deb files. However, doing so can be tedious, especially when you find that a package is dependent on several other packages and that some of those packages are dependent on other packages.

You can create deb files, as you build a kernel. Page 579 has an example of building a kernel deb file: pages 536 and 582 show dpkg installing deb files.

### Binary files
A deb file can contain the following components, which are packed and unpacked using the ar (archive) utility. All packages contain an executable file; the other components are optional.

- binary—Binary executable files
- control—Package information including lists of dependent, recommended, and suggested packages
- configfiles—Package configuration files
- preinst—Preinstall script
- postinst—Postinstall script
- prerm—Premove script
- postrm—Postremove script

To unpack a deb file, first download it to /var/cache/apt/archives using the command aptitude download package. Copy the file to a directory with no other files in it and use ar -xv to unpack the deb file. You can then use tar (page 176) to unpack the tar files. The example shows how to extract the control files from the nfs-common deb file.

```
$ ls nfs-common*deb
nfs-common_1~31.2.0~ubuntu2_i386.deb
$ sudo ar -xv nfs-common*deb
x - debian-binary
x - control.tar.gz
x - data.tar.gz
$ sudo tar -xvf control.tar.gz /
./.postinst
./.preinst
./.prerm
./.postrm
./.configfiles
./.md5
./.control
```

### Source files
A source file package contains a description file, a source code file, and a diff file that contains Ubuntu-specific changes to the source file. See page 532 for instructions on how to use apt-get to download and unpack a source file.

### Installing a deb
When dpkg installs a binary package (page 536), it takes the following steps:

1. Extract controls.
2. If another version of the same package is installed on the system, executes the prerem script of the old package.
3. Runs the preinst script.
4. Back ups the old binary files and unpacks the new binary files, allowing dpkg to revert to the existing setup if installation fails.
5. If another version of the same package is installed on the system, executes the postrm script of the old package.
6. Back ups the old configuration files and unpacks the new configuration files, allowing dpkg to revert to the existing setup if installation fails.
7. Runs the postinst script.

### Removing a deb
When dpkg removes a binary package (page 536), it runs the prerm script, removes the files, and runs the postrm script.

## dpkg: THE FOUNDATION OF THE DEBIAN PACKAGE MANAGEMENT SYSTEM

The dpkg (debian package) utility installs (unpacks and configures), queries, and removes packages. Before querying the software package database, give the update-avail command (discussed next) to update the list of available packages.

## dpkg commands and options both start with hyphens

> tip Although command-line arguments that start with one or two hyphens are generally called options, the dpkg documentation divides these into commands and options. For example, --purge is a command and --simulate is an option.

Typically you will use one of the tools that act as a front-end for dpkg and not work with dpkg itself. In some cases you may find the following dpkg commands useful. View the dpkg man page or use the --help option for a list of commands.

## dpkg --update-avail: UPDATES THE LIST OF AVAILABLE PACKAGES

The list of available packages is kept in the /var/lib/dpkg/available file. The --update-avail dpkg command updates this list from the APT local package indexes (page 524).

```
$ dpkg --update-avail /var/lib/dpkg/available
Replacing available packages info, using /var/lib/dpkg/available.
Information about 1868 package(s) was updated.
```

## dpkg --list: DISPLAYS INFORMATION About A PACKAGE

dpkg --list (or -l) displays a line of information about packages you name as an argument. Package names can include wildcards as described in "Filename/Pathname Expansion" on page 256. You must quote wildcards on the command line.

The following command lists all packages names begin with apache2. The first two lines of the header are keys for the first two letters on each line that describes a package. The first line of the header, labeled Desired, lists the possible desired package selection states (Table 13-1). The second line, labeled Status, lists the possible package states (Table 13-1). The Name column lists the name of the package, while Version and Description describe the package.

```
$sudo dpkg --list "apache2"
Desired-Unknown/Install/Remove/Purge
Status=Not/Installed/Config-files/Unpacked/Failed-config/Half-installed
| Err?=(none)/Hold/Reinst-required/X=both-problems (Status,Err: uppercase=bad)
| Name                                Version Description
```

```
================================================================================================----------------------
pn apache2                <>             (no description available)
rc apache2-common       2.2.14-4ubuntu4   next generation, scalable, extendable web...
ii apache2-doc           2.2.14-4ubuntu4   documentation for apache2
un apache2-modules      <>             (no description available)
un apache2-mpm-perchil   <>             (no description available)
un apache2-mpm-prefork   <>             (no description available)
un apache2-mpm-threadad   <>             (no description available)
un apache2-mpm-worker    <>             (no description available)
pn apache2-utils         <>             (no description available)
```

In the preceding example, the apache2 package has a desired state of purged (p) and a state of not installed (n), meaning the package is not installed. The apache2-common has a desired state of removed (r) and a state of installed (i), meaning the package is installed. The apache2-doc has a desired state of unknown (u) and a state of installed (i), meaning the package is installed. The apache2-modules has a desired state of unknown (u) and a state of not installed (n), meaning the package is not installed. The apache2-mpm-perchil has a desired state of unknown (u) and a state of not installed (n), meaning the package is not installed. The apache2-mpm-prefork has a desired state of unknown (u) and a state of not installed (n), meaning the package is not installed. The apache2-mpm-threadad has a desired state of unknown (u) and a state of not installed (n), meaning the package is not installed. The apache2-mpm-worker has a desired state of unknown (u) and a state of not installed (n), meaning the package is not installed. The apache2-utils has a desired state of unknown (u) and a state of not installed (n), meaning the package is not installed.

### Table 13-1 dpkg codes

| Letter | Means that the package is | Desired (selection state) |
|---|---|---|
| u | unknown to dpkg | unknown |
| i | installed | install |
| r | removed | remove |
| p | purged | purge |
| h | held | hold |

### Table 13-1 dpkg codes (continued)

| Letter | Means that the package is | Status (package state) |
|---|---|---|
| n | not installed | not installed |
| i | installed | installed |
| c | config-files | not installed; only the configuration files exist |
| u | unpacked | unpacked, but not configured |
| f | failed-config | unpacked, but not configured; configuration failed |
| h | half-installed | partially installed; installation is not complete |
