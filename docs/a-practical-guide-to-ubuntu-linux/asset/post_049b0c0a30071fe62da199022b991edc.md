Alice Jones

```

## exec: EXECUTES A COMMAND OR REDIRECT FILE DESECTORS

The exec has two primary purposes: to run a command without creating a new process and to redirect a file descriptor—including standard input, output, or error—of a shell script from the script (987). When the shell executes a command that is not built into the shell, it typically creates a new process. The new process inherits global or exported variables from its parent but does not inherit variables that are not exported by the parent. For more information refer to “Locality of Variables” on 992.) In contrast, exec executes a command in place of (overlaps) the current process.

## exec: EXECUTES A COMMAND

The exec builtin used for running a command has the following syntax:

### exec command arguments

exec versus .(dot). In exec runs a command in the environment of the original process, it is similar to the .command (296). However, unlike the .command, which can run only shell scripts, exec can run compiled programs. Also, whereas the .command returns to the original script when it finishes running, exec does not. Finally, the command gives the new program access to local variables, exec does not.

exec does not return control Because the shell does not create a new process when you use, the command runs more quickly. However, because exec does not return control to the original program, it can be used only as the last command in a script. The following script shows that control is not returned to the script:

The next example, a modified version of the out script (959), uses exec to execute the final command the script runs. Because out runs either cat or less and terminates, the new process, named out2, uses exec with both cat and:

```
$ cat out2
if [ $ -eq 0 ]
then
echo "Usage: out2 [-v] filenames" 1>&2
exit 1
fi
if [ "$1" = "-v" ]
then
shift
exec less "$0"
else
exec cat -- "$0"
fi
```

## exec: REDIRECT INPUT TO OUTPUT

The second major use of exec is to redirect a file descriptor—including standard input, output, or error—from a script. The next command causes all subsequent input to be redirected. Standard output and error from the file are redirected, respectively:

```
exec > outfile 2>err
```
