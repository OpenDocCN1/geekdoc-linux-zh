The final example from fstab shows a remote-mounted home directory. Because dog is a local server and is connected via a reliable, high-speed connection, time is decreased and rsize and wsize are increased substantially:

```
dog/home /dog.home nfs timeout=4,rsize=16384,wsize=16384 0 0
```

# PREREQUISITES

Installation Install the following package:

+   * nfs-kernel-server

The portmap utility (which is part of the portmap package and is installed as a dependency when you use nfs-kernel-server; page 406) must be running to enable reliable file locking.

nfs-kernel-server When you install the nfs-kernel-server package, the dpkg postinst script starts the init script nfsd (the NFS kernel daemon). After you configure NFS, daemon calls the nfs-kernel-server init script to re directory hierarchies and restart the nfs daemon:

+   $ sudo service nfs-kernel-server restart
* Stopping NFS kernel daemon [OK]
* Unexporting directories for NFS kernel daemon... [OK]
* Exporting directories for NFS kernel daemon... [OK]
* Starting NFS kernel daemon [OK]

After changing the NFS configuration on an active server, reload in place of restart toexport directory hierarchies without disturbing clients connected to the server.

# NOTES

Firewall An NFS server uses TCP port 111 for portmap and TCP port 2049 for nfsd. In addition, if you instruct it otherwise the NFS server uses portmap to assign (all) random ports for the services it provides: rpc.statd, rpc.mountd, and (optionally) rpc.quota. It is better to set up a firewall to protect your server from random ports; it is much easier to specify which port of each of these services use, modify the lines in the following file as shown:

```
$ grep STATD /etc/default/nfs-common
NEED_STATD="--port 32765 --outgoing-port 32765
```

```
$ grep MOUNT /etc/default/nfs-kernel-server
RPCMOUNTS="--p 32767"
```

```
$ grep QUOTA /etc/default/quota
RPCQUOTADOPTS="--p 32769"
```
