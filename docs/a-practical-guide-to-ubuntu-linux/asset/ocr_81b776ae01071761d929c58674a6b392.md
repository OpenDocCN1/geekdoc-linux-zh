An entry in the anacrontab file has the following format:

```
period delay identifier command
```

where the period is the frequency in days (how often) after anachron executes the command, the delay is the number of minutes after anachron starts that it executes the command, and the identifier is the name of the file in /var/spool/anacron that anachron uses to keep track of when it last executed the command.

The cron.daily job in anacrontab runs the executable files in /etc/cron.day every day, five minutes after anachron starts. If the system is running at 7:30 AM, /etc/cron.d/anachron calls the anachron init script, and this job runs at 7:35 AM. When Ubuntu boots, the rc scripts call the anachron init script. If the system is not running at 7:30 AM, cron.daily job has not been run for at least a day, and change permissions not running on batteries, the job runs five minutes after the system starts.

# Running jobs at the right time

As installed, if the /usr/bin/anachron file is present and executable, cron uses anachron to run daily, weekly, and monthly jobs as soon as possible. Refer to "run-parts" on page 607 and the section on /etc/anacontab. An easy way to get cron to run these jobs as scheduled in /etc/crontab is to change permissions on the cron file so it is not executable:

```
$ sudo chmod 644 /usr/bin/anachron
```

If you need to reanchor, change its permissions by 755.

# RUNS OCCASIONAL TASKS

Like cron, at runs a job sometime in the future. Unlike cron, at runs a job only once. For instance, you can schedule an at job that will reboot the system at 3:00 AM (when all users are probably logged off)

```
$ at 3am
warning: commands will be executed using /bin/sh
at> reboot
at> CONTROL-<EOT>
job 1 2010-02-01 03:00
```

It is also possible to run an at job within an at job. For instance, an at job might check for new patches every 18 days—something that would be more difficult with cron. See the at man page for more information.

By default, Ubuntu is set up with restrictions that prevent some system accounts from running at. See @allow and at.deny on page 491 for more information.
