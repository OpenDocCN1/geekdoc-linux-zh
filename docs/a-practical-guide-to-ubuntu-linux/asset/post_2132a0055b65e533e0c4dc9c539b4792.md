Sending and receiving email require three pieces of software. At each end, there is a client, called an MUA (mail user agent), which is a bridge between a user and the mail system. Common MUAs are mut, Evolution, KMail, Thunderbird, and Outlook. When you send an email, the MUA hands it over to an MTA (a mail transfer agent, such as exim4 or sendmail), which transfers it to the destination server. At the destination, an MDA (mail delivery agent, such as procmail) puts the mail in the recipient's mailbox file. On Linux systems, the MUA on the receiving system either reads the mailbox file or retrieves mail from a remote MUA or MTA, such as an SMTP (Simple Mail Transfer Protocol) server, using POP (Post Office Protocol) or IMAP (Internet Message Access Protocol).

SMTP Most MUAs expect a local MTA as exim4 to deliver outgoing email. On some systems, including those with a dial-up connection to the Internet, the MTA sends email to an ISP's mail server. Because most MTAs use SMTP to deliver email, they are often referred to as SMTP servers. By default, when you install exim4 on an Ubuntu system, exim4 uses its own builtin MDA to deliver email to the recipient's mailbox.

You do not need to set up exim4 to send and receive email

Most MUAs use POP or IMAP to receive email from an ISP's server. These protocols do require an MTA as exim4. As a consequence, you do not need to install or configure exim4 (or another MTA) to receive email. Although you still need SMTP to send email, the SMTP server can be at a remote location, such as your ISP. Thus you may not need to concern yourself with it, either.

# INTRODUCTION TO exim4

When the network that was to evolve into the Internet was first set up, it connected a few computers, each serving a large number of users and running services. Each computer was capable of sending and receiving email and had a unique hostname, which was used as a destination for email.

Today the Internet has a large number of transient clients. Because these clients do not have fixed IP addresses or hostnames, they cannot receive email directly. Users on these systems usually maintain an account on an email server by their employer or an ISP, and they collect this email from account using POP or IMAP. Unless you own a domain where you want to receive email, you will not need to set up exim4 to receive mail from nonlocal systems.

You can set up exim4 on a client system so it sends mail for nonlocal systems to an SMTP server that relays the mail to its destination. This type of server is called smarthost. Such a configuration is required by organizations that use firewalls to prevent email from being sent out on the Internet from any system other than the company's official mail servers. As a partial defense against spam viruses, some ISPs block out port 25 to prevent their customers from sending directly to a remote computer. This configuration is required by these.

You can also set up exim4 as a server that sends mail to nonlocal systems and does not use an ISP as a relay. In this configuration, exim4 connects directly to the SMTP servers for the domains receiving the email. An ISP set up as a smarthost is configured this.

You can set up exim4 to accept email for a registered domain name as specified in the domain's MX record (page 828). However, most clients (MUAs) do not interact directly with exim4 to receive email. Instead, they use POP or IMAP protocols that include features for managing mail folders, leaving messages on the server, and reading only the subject of an email without downloading the entire message. If you want to collect your email from a system other than, you will need to set up exim4 to receive mail.

# 765# ALTERNATIVES TO exim4

sendmail The most popular alternative to exim4. Ubuntu configures exim4 as a drop-in replacement for sendmail. The exim4-daemon-light package, which is part of the exim4 virtual package, includes /usr/bin/sendmail, which is a link to exim4. Because the exim4 daemon accepts many of sendmail's options, programs that depend on sendmail will work with exim4 installed in place of sendmail.

Postfix The second alternative to exim4. Postfix is fast and easy to administer. See page 766 for more information on Postfix.

Qmail The third alternative to exim4. Qmail is flexible, but its configuration is complex. See page 767 for more.

Exim The fourth alternative to exim4. Exim is a modern MTA that is widely used in many distributions.

This section explains how to set up exim4.

# PREREQUISITES

Install the following:

- exim4 (a virtual package)
- mailutils (optional, which is handy for testing exim4 from command line)

exim4 init When you install the exim4 package, the dpkg postinst minimally configures exim and starts the exim4 daemon. After you configure exim4, call the exim4 init script to restart:

```bash
sudo service exim4
```

After the exim4 configuration on an active server, reload in place of restart to reload exim4 without interrupting the work. The exim4 init accepts several nonstandard arguments:

# service exim4
```bash
Usage: /etc/init.d/exim4 {start|restart|reload|status|[force-stop]}
```

The status argument display information about exim4. The force-stop argument immediately kills all exim4 processes.
