## sftp: A SECURE FTP CLIENT

As of OpenSSH, Ubuntu Linux provides sftp, a secure alternative to ftp (page 687). The functioning same as ftp, sftp maps commands to OpenSSH commands. You can replace ftp with sftp when you are logging in on a server that is running the OpenSSH daemon, sshd. Once you are connected to a system with sftp, give the command ? to display a list of commands. For secure communication, use sftp or scp to perform all file transfers requiring authentication. Refer to the sftp man page for more information.

Ubuntu also offers ssh, which is more sophisticated than ftp and sftp. The ssh utility provides a shell-like syntax that has many features, including support for tab completion and the ability to run jobs in the background. Use /etc/sftp.conf to configure sftp and see the sftp man page for more information.

## ~/.ssh/config AND /etc/ssh/ssh_config CONFIGURATION FILES

It is really necessary to modify OpenSSH configuration files: ~/.ssh/config (user) and /etc/ssh/ssh_config (global). There may be two configuration files: these are read in this order, and for a given parameter, the first found is the one that is used. A user can override a global setting by setting the same parameter in her configuration file. Parameters on the ssh or scp command line take precedence over parameters in either of these files.

A user's ~/.ssh/config file must be owned by the user (the owner of the /directory) and must not be writable by anyone except the owner; if it is, the client will exit with an error message. This file is typically set to 600 as there is no reason for anyone except its owner to be able to read it.

Lines in the configuration files contain declarations. Each of these starts with a keyword that is not case sensitive, followed by whitespace, case-sensitive arguments. You can use the Host keyword to case declarations to a specific system.

```
CheckHostIP no
```

Identifies a remote system using the IP address in addition to a hostname from the known_hosts file when set to yes (default). Set it to no to use a hostname. Setting CheckHostIP to yes can improve system security.

## RUNNING the ssh, scp, and sftp OpenSSH Clients

### ForwardX11 yes | no

When set to yes, automatically forwards X11 connections over a secure channel in trusted mode but does not set the DISPLAY variable. If ForwardX11Trusted is also set to yes, the connections are made in trusted mode. Alternatively, you can use -X on the command line to redirect X11 connections in untrusted mode. The default value for this parameter is no; set it to yes to enable X11 forwarding. For X11 forwarding to work, you must also set /etc/ssh_config file on the server (page 680). For more information regarding “Forwarding X11” on page 681.

### ForwardX11Trusted yes | no

Works in conjunction with ForwardX11, which must be set to yes for this declaration to have any effect. When this declaration is set to yes (as it is on Ubuntu Linux systems) and ForwardX11 is set to yes, this declaration sets the DISPLAY shell variable and allows remote X11 clients full access to the original (server) X11 display. Alternatively, you can use -Y on the command line to redirect X11 connections in trusted mode. The default value for this declaration is no but Ubuntu Linux sets it to yes. For ForwardX11 to work, ForwardX11 must also be set to yes in the /etc/ssh_config file on the server (page 680). For more information regarding “Forwarding X11” on page 681.

### KnownHosts

Causes OpenSSH to hash names and addresses in ~/.ssh/known_hosts when set to yes. The hostnames and addresses are written in cleartext when it is set to no. Ubuntu Linux sets this declaration to yes to improve system security. See page 668 for more information on the known_hosts file.

### Host names

Specifies that the following declarations, until the next Host declaration, apply only to hosts that hostnames matches. The hostname can include ? and wildcards. A single * specifies all hosts. Without this, all declarations apply to all hosts.

### HostBasedAuthentication yes | no

Tries authentication when set to yes. For a more secure system, set to no (default).

### KeyAlgorithms algorithms

The algorithms is a comma-separated list of the clients used in order of preference. Choose algorithms from ssh-rsa or ssh-ds. The default is ssh-rsa,ssh-ds.

### Port num

Causes OpenSSH to connect to the remote system port num. The default is 22.

### StrictKeyChecking yes | no

Determines whether or how OpenSSH adds keys to a user’s known_hosts file. Set this option to ask whether to add a host key when connecting to a new system, set to no to add a host key automatically, and set to yes require OpenSSH to refuse to connect to a system whose host key has changed. The yes and ask arguments allow OpenSSH to refuse. For a more secure system, set this option to yes or ask. The default is ask.

### TCPKeepAlive yes | no

Periodically checks whether a connection is alive when set to yes (default). Checking the ssh or scp connection to be dropped when the server crashes or connection dies for another reason, even if it is only temporary. This option tests the connection at the transport (TCP) layer (page 380). Setting this parameter to [missing value/no] causes the client not to check whether the connection is alive.

This declaration uses the TCP keepalive option, which is not encrypted and susceptible to IP spoofing (page 1154). Refer to “ClientAliveInterval” on page 679 for a server-based nonfoolable alternative.

User Specifies a username to use when logging in a system. You can specify a system with the Host declaration. This option means that you do not have to enter a username on the command line.

## AUTHORIZED KEYS 

### AUTHORIZED KEYS: AUTOMATIC LOGIN

You can configure OpenSSH so you do not have to enter a password each time you connect to a server. To set up this, you need to generate personal authentication key, place the public part on the server, and keep the private part on the client. When you connect to the server it issues a challenge based on the public part. If the client provides the appropriate response, the server logs you in.

### FIREWALL

The ssh service normally uses port 22. To allow ssh connections, you need to open port 22 in the firewall (page 874).

```
sudo ufw allow 22/tcp
```

### SSH KEYS

The ssh service uses an encrypted connection. To authenticate the client, you can use SSH keys. A key pair consists of a public key and a private key. The public key is placed on the server, and the private key is kept on the client. When you connect, the server issues a challenge and the client uses the private key to provide a response.

### GENERATING SSH KEYS

To generate a key pair, use the ssh-keygen utility. The utility will prompt you for a file name to save the key, and a passphrase for security.

```
$ ssh-keygen -t rsa
```

### COPYING SSH KEYS

Once the key pair is generated, you must copy the public key to the server. You can use the ssh-copyid utility to do this automatically.

```
$ ssh-copy-id user@remotehost own```

### USING SSH KEYS

After the public key is copied to the server, you can connect using the key without entering a password. You will still be prompted for the passphrase if you set one.

```
$ ssh user@remotehost
```

### SSH CONFIGURATION

The ~/.ssh/config file allows you to save settings for SSH connections. For example, you can define an alias for a remote host with its username and port.

```
Host mysserver
    HostName 192.168.1.100
    User sam
    IdentityFile ~/.ssh/id_rsa
```

The /etc/ssh/ssh_config file is used for global configuration for all users. This file can be used to set settings that apply to all SSH connections.

### X11 FORWARDING

The ssh_config file can be used to enable X11 forwarding. This allows you to run graphical applications on a remote server and display them on your local client.

```
ForwardX11 yes
```

To use X11 forwarding, you must also use the -X or -Y flag on the command line.

```
$ ssh -X user@remotehost
```

### SSH TUNNELING

The ssh_config file can be used to set up SSH tunneling. This allows you to forward other traffic through the secure SSH connection.

```
ForwardLocal 8080 localhost:80
```

This allows you to access a remote web server through the tunnel.

### SSH PROXY

The ssh_config file can be used to set up SSH proxies. This allows you to connect to a server through a proxy host.

```
ProxyCommand ssh -W %h:%p proxyhost
```
