PS3 After displaying the menu, select displays value of PS3, the select prompt. The default value of PS3 is #?, but it is typically to a more meaningful value. # Here DOCUMENT

A Here document allows you to redirect into a shell script from within the shell itself. A Here document is so named because it is here—immediately accessible in the shell script—instead of there, perhaps in another file.

The following script, named birthday, contains a Here document. The two less symbols (<<) in the first line indicate a Here document. The one or more characters that delimit the Here document follow the less symbols—this example uses a plus sign. The opening delimiter must appear adjacent to the less symbols, the closing delimiter must be on a line by itself. The shell sends everything between the two delimiters to the process as input. It is as example is how you have redirected standard input to get from a file, except that the file is embedded in the shell script:

```
$ cat birthday
grep - "1" <<
Max June 22
Barbara February 3
Darlene May 8
Helen March 13
Zach January 23
Nancy June 26
```

```
+ $ ./birthday Zach
Zach January 23
$ ./birthday june
Max June 22
Nancy June 26
```

The next script, named bundle, includes a clever use of a Here document. The bundle script is an elegant example of a script that creates a shell archive (tar) file. The script creates a file that is itself a shell containing containing other files as well as the code to re-create the original files:

```
$ cat bundle
!/bin/bash
# bundle: group files into distribution package

echo "To unbundle, this file"
for i in
  echo "echo i 1>&"
  echo "cat $i<<End of $i"
  cat $i
  echo "End of"
done
```

Just as the shell does not treat special characters that occur in standard input of a shell script as special, so the shell does not treat the special characters that occur between the delimiters in a Here document as special.

As the following example shows, the output of bundle is a shell script, which is redirected to a file named bothfiles. It contains the contents of each file given as an argument to bundle (file1 and file2 in case) inside a Here document. To extract the original files from bothfiles, simply give it as an argument to bash command. Before bothfiles is run:

# FILE DESCRIPTORS 987

As discussed on page 97, before a process can read from or write to a file it must open that file. When a process opens a file, Linux associates a number (file descriptor) with the file. A file descriptor is an index into the process's table of open files. Each process has its own set of open files and its own descriptors. After opening a file, a process reads from and writes to that file by referring to its descriptor. When it no longer needs the file, the process closes the file descriptor.

A Linux process starts with three files: standard input (file descriptor 0), standard output (file descriptor 1), and standard error (file descriptor 2). Often these are the only files the process needs. Recall that you redirect standard output with the symbol > and you can redirect standard error with the symbol &. Although you can redirect other file descriptors, they do not have any special meaning. The exception is in programs that you write yourself to control the file descriptors and can take advantage of redirection.

Opening a file The Bourne Again opens files using the exec builtin as follows:

```
exec n> outfile
exec m< infile
```

The first line opens outfile for output and holds open, associating with file descriptor n. The second line opens outfile for input and holds open, associating with file descriptor m.

Duplicating a file descriptor The & duplicates an input file descriptor; >& duplicates an output file descriptor. You can duplicate a file descriptor by making refer to the same file as another file descriptor, as standard input or output. Use the following format to open or redirect file descriptor n as a duplicate of file descriptor m:

```
exec n&m
```

Once you have opened a file, you can use it for input and output in two ways. You can use I/O redirection on a command line, redirecting standard output to a file descriptor with >& or redirect standard input to a file descriptor with <<. You can use the read (page 103) and echo built. If you invoke other commands, including functions (page 349), they inherit these open files and file descriptors. When you have finished using a file, you can use it using

```
exec n~
```

When you invoke the shell function in the next example, named mycp, with two arguments, it copies the file named by the first argument to the file named by the second argument. If you only provide one argument, the script copies the file named by the argument to standard output. If you invoke mycp with no arguments, it copies standard input to standard output.

# A function is not a shell script

+ tip mycp is a shell function; it will not work as expect if you execute it as a script. (It will work: The file created in a very short-lived subshell, which is probably of little use.) You can enter this function from the keyboard. If you put a function in a file, you can run it as an argument to the . (dot) builtin (page 296). You can also put the function in a startup file if you want it to be always available (page 351).

```
mycp () {
case $# in
  # Zero arguments
  # File descriptor 3 duplicates standard input
  # File descriptor 4 duplicates standard output
  exec 3<& 4-<1
  ;
1)
  # One argument
  # Open the file named by the argument for input
  # and associate it with file descriptor 3
  # File descriptor 4 duplicates standard output
  exec 3< $1 4-<1
  ;
2)
  # Two arguments
  # Open the file named by the first argument for input
  # and associate it with file descriptor 3
  # Open the file named by the second argument for output
  # and associate it with file descriptor 4
  exec 3< $1 4< $2
  ;
esac
}
```
