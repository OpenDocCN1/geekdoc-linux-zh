# CONFIGURATION DIRECTIVES 911

Default: none (Apache will not start without this directive)
Ubuntu: Listen 80

Redirect Tells the client to fetch a requested resource from a different, specified location.

Redirect [status] requested-path [new-URI]

where status is the status Apache returns along with the redirect. If you omit status, Apache assumes temp. The status can be an Apache error code in the range 300–399 or one of the following:

+   permanent Returns 301 (the resource has moved permanently)
temp Returns 302 (the resource has moved temporarily)
seeother Returns 303 (the resource has been replaced)
gone Returns 410 (the resource has been removed—does not take a new-URI argument)

The requested-path is the absolute pathname of the ordinary file or directory that Apache is redirect for. Apache redirects all requests that start with the absolute pathname by requested-path. (See the example below) Use RedirectMatch (discussed next) if you want to use a regular expression in this argument.

The new-URI is the URI that Apache redirects to. If the new-URI starts with a slash (/) and not http://, or a similar prefix, Apache uses the same prefix to fix that what it was called. Most Redirect directives require a new-URI argument.

A request must match all segments of the requested-argument. Assume the following directive:

Apache will redirect a request for http://www.example.com/pictures/mom.jpg to http://pictures.example.com/mom.jpg but, because the final segment does not match, it will not redirect a request for http://www.example.com/pictures_mom.jpg.

Contexts: server config, virtual host, directory, .htaccess

Specify in sites-available/*

RedirectMatch Tells the client to fetch a requested resource from a different location specified by a regular expression.

RedirectMatch [status] requested-path-re [new-URI]

This directive is the same as Redirect (discussed above), except that you can use a regular expression (Appendix A) in requested-path.

Contexts: server config, virtual host, directory, .htaccess

Specify in sites-available/*

Default: none

Ubuntu: none
