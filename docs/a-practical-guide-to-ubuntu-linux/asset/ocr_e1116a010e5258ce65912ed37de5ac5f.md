Graphical login With a graphical login, the init process spawns gdm (the GNOME display manager) on the first free virtual terminal, providing features similar to those offered by getty login. The getty utility starts an X server and presents a login window. The gdm display manager uses PAM to authenticate the user and runs the scripts in /etc/gdm/PreSession directory. These scripts inspect the user's ~/dmrc file, which stores the user's default session and language, and launch the user's session. The GNOME desktop environment stores the last saved session and attempts to restore it when the user logs in.

With NIS, login compares the username and the information with the appropriate name instead of (or in addition to) the password and shadow files. If the system is configured to use both methods (/etc/passwd and NIS), it checks the /etc/nwitch.conf file (page 475) to see in which order it should check.

PAM (page 478)—the Pluggable Authentication Module gives you greater control over user logins than the /etc/passwd and /etc/shadow files do. Using PAM, you can specify multiple levels of authentication, or parallel methods, each of which is itself sufficient to grant access to the system. For example, you can have different authentication methods for console and ssh logins. Similarly, you can require users to authenticate using two or more methods (such as a smartcard or badge reader and a password). PAM modules also provide security technology vendors with a convenient way to interface their hardware or software products with a system.

Initializing the session When both the username and password are correct, login runs the scripts in PreSession consult the appropriate services to initialize the user and group IDs, establishing the user's home directory, and determine which shell or desktop manager user works.

The login utility and PreSession scripts assign values to variables and look in the /etc/group file (page 492) to identify the users belong to. When login has finished its work, it overlays itself with the login session, which inherits the variables by login. In a graphical environment, the PreSession scripts start the desktop manager.

During a textual login, the login shell assigns values to variables and executes the commands in the system startup files (/etc/profile and /etc/bashrc). Some systems have other startup files as well. Although the actions performed by these scripts are dependent, they typically display the contents of the /etc/motd (message of the day) and /etc/issue files, let you know if you have one, and umask (page 459), the file-creation mechanism.

After executing the system startup commands, the shell executes the commands from the personal startup files in the user's home directory. These scripts are described on page 293. Because the shell executes the personal startup files after the system startup files, a sophisticated user can override any variables or conventions that established by the system. A new user, by contrast, remains uninvolved in these matters.
