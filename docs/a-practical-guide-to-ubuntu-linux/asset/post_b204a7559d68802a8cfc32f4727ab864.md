# HOST SECURITY

Your host must be secure. Simple security steps include preventing remote logins and leaving the /hosts.equiv and individual users' ~/hosts empty (or not having them at all). Complex security steps include IPSec for VPNs between hosts. Many other security measures, of which are discussed in this section, all for-where between these extremes. See Table C-1 on page 1124 for relevant URLs.

- Although potentially tricky to implement and manage, intrusion detection systems (IDS) are an excellent way to keep an eye on the integrity of a device which it runs. An IDS can warn of possible attempts to subvert the security of the host on which it runs. The great-grandaddy of systems is triwire. This host-based system check modification times and integrity of files by using strong algorithms (cryptographic checksums or signatures) that can detect the most minor modifications. A commercial version of triwire is also available. Another commercial IDS is Dragonsquire. Other free, popular, and flexible IDS include samhain and AIDE. The two IDS offer even more features and means of remaining invisible to users than triwire does. Commercial IDS that are popular in enterprise environments Cisco Secure IDS (formerly NetRanger), Elasticsearch Dragon, and ISS RealSecure.

- Keep Ubuntu systems up-to-date by downloading and installing the latest updates. Use the Update Notifier to update the system regularly (page 112). You can set the system up to automatically install security updates using the Software Sources, Updates tab (page 131).

- Complementing host-based IDS are network-based IDS. They monitor the network and nodes on the network and report suspicious occurrences (attack signatures) by user-defined alerts. These signatures can be matched based on known worms, overflow attacks against programs, or unauthorized scans of network ports. Such programs such as snort, klaxon, and NFR are used in this capacity. Commercial programs such as DragonSentry, also fill this role.

# LOGIN SECURITY

Without a secure host, good login security cannot add much protection. Table C-1 on page 124 lists some of the best login security tools, including replacement daemons for telnetd, rlogind, and rsh. Many sites use ssh, which comes as freware and a commercially supported package that works on UNIX/Linux, Windows, and Macintosh platforms.

The PAM family (page 478) allows you to set up multiple authentication methods for users in series or in parallel. In-series PAM requires multiple methods of authentication for a user. In-parallel PAM uses one of a methods for authentication.

Although not the most popular choice, you can configure a system to take advantage of one-time passwords. S/Key is the original implementation of one-time passwords by Bellcore. OPIE was developed by the U.S. Naval Research Labs, an improvement over the original Bellcore system. In one permutation of one-time passwords, the user gets a piece of paper listing a set of one-time passwords. Each time a user logs in, she enters a password from the piece of paper. Another type of secure login is becoming more common facilitated by a token or a smartcard. Smartcards are credit-card-like devices that use a challenge-response method of authentication. Smartcard and token authentication rely on something you have (the card) and something you know (a pass phrase, user ID, or PIN). For example, you might enter your username in response to the login prompt and get a password prompt. You would then enter your PIN and the number displayed on the token. The token has a unique serial number that is stored in a database of the authentication server. The token and authentication server use this serial number as a means of computing a challenge every 30 to 60 seconds. If the PIN and token number you match what should be computed by the access server, you are granted access to the system.

# REMOTE ACCESS SECURITY

Issues and solutions resolving remote access security overlap with those pertaining to login and host security. Local logins may be secure with a simply username and password, whereas remote logins (and all remote access) should be made more secure. Many breakins can be traced back to reusable passwords. It is a good idea to use an encrypted authentication client, such as ssh or kerberos. You can also use smartcards for remote access authentication.

Modems can also be an entry point into a system. Most people are aware of how easy it is to monitor a network line but they may take for granted security of the public switched telephone network (PSTN), also known as POTS–plain old telephone service. You may want to set up an encrypted channel dialing in a modem pool using ssh over PPP.

There are ways to implement stringent modem authentication policies so unauthorized users cannot use local modems. The most common techniques are PAP (Password Authentication Protocol), CHAP (Challenge Handshake Authentication Protocol), and Radius. PAP and CHAP are relatively weak compared to Radius, so the latter has rapidly gained in popularity. Cisco also provides a method of authentication called TACACS+/TACACS (Terminal Access Controller Control System).

One or more of these authentication techniques are utilized in a RAS (remote access server—in a network, a computer that provides network access to remote users via modem). Before purchasing a RAS, check what kind of security it provides and decide whether that level of security meets your needs.
