
The final example from fstab shows a remote-mounted home directory. Because dog is a local server and is connected via a reliable, high-speed connection, time is decreased and rsize and wsize are increased substantially:

```
dog/home /dog.home nfs timeout=4,rsize=16384,wsize=16384 0 0
```

# NOTES

Firewall: An NFS server uses TCP port 111 for portmap and TCP port 2049 for nfsd. In addition, if you instruct it otherwise, the NFS server uses portmap to assign (all) random ports for the services it provides: rpc.statd, rpc.mountd, and (optionally) rpc.quota. It is better to set up a firewall to protect your server from random ports; it is much easier to specify which port of each of these services use, modify the lines in the following file as shown:

```bash
$ grep STATD /etc/default/nfs-common
NEED_STATD="--port 32765 --outgoing-port 32765"
```

```bash
$ grep MOUNT /etc/default/nfs-kernel-server
RPCMOUNTS="--port 32767"
```

```bash
$ grep QUOTA /etc/default/quota
RPCQUOTADOPTS="--port 32769"
```

If you are not running rpc-quotad, you do not need to create or modify the quota file.
The ports used in the example are the ones suggested in the Linux NFS-HOWTO, and you can use any unused ports as you like. See wiki.debian.org/SecuringNFS for more information.

If the NFS server system is running a firewall, you need to open ports 111 and 2049. To do so, use gufw (port 876) to set a policy that allows NFS service. In addition, open the ports you specified in the files in /etc/default, as explained earlier.
Because gufw has no defined policy for these ports, you need to specify the ports manually when you add a rule in gufw.

The rpc-mountd daemon uses TCP wrappers to control access to the server.
As explained on page 465, you can set up /etc/hosts.allow and /etc/hosts.deny to specify which clients can contact rpc-mountd on the server and use NFS.
The name of the daemon in these files is mounted.
