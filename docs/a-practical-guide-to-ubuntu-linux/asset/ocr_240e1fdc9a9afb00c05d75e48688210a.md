When you install some packages, aptitude lists suggested packages. Suggested packages may be useful but are not required with the package you are installing.
The aptitude remove command removes a package but leaves its configuration files in place, allowing you to reinstall the package without having to reconfigure it. Use purge (discussed next) in place of remove to remove a package and its configuration files.

# $ sudo aptitude remove tcsh

The following packages will be REMOVED:
tcsh
packages upgraded, 0 newly installed, 1 to remove and 0 not upgraded.
Need to get 0B of archives. After unpacking 733kB will be freed.
Writing extended state information... Done
(Reading database ... 122327 files and directories currently installed.)
Removing tcsh ...

When you remove a package, it also removes the dependent packages automatically when it installed the original package. The following example remove apache2-common and its dependencies:

# $ sudo aptitude remove apache2.2-common

The following packages will be REMOVED:
apache2-utils(u) apache2-bin(u) apache2-2-common libapr1{u}
libaprutill1(u) libaprutill1-dbd-sqlite3{u} libaprutill1-ldap{u}
packages upgraded, 0 newly installed, 7 to remove and 0 not upgraded.
Need to get 0B of archives. After unpacking 9,994kB will be freed.
Do you want to continue? [Y/n]?

The next example uses an alternative approach—the aptitude purge command—to remove apache2-common, its dependencies, and all configuration files. The [p] following apache2-2-common indicates that aptitude is removing (purging) apache2-common's configuration files, as does the last line of the example.

# $ sudo aptitude purge apache2.2-common

The following packages will be REMOVED:
apache2-utils(u) apache2-bin{u} libapr1{u}
libaprutill1(u) libaprutill1-dbd-sqlite3{u} libaprutill1-ldap{u}
packages upgraded, 0 newly installed, 7 to remove and 0 not upgraded.
Need to get 0B of archives. After unpacking 9,994kB will be freed.
