
# ACLs: ACCESS CONTROL LISTS 223

In the line that starts with user, the two colons (:) with no name between them indicate that the line specifies the permissions for the owner of the file. Similarly, the two colons in the group line indicate the line specifies permissions for the group file. The two colons following other are there for consistency: No name can be associated with other.

The setacl --modify (or -m) option adds or modifies one or more rules in a file's ACL using the following format:

```
setacl --modify ugo:permissions file-list
```

where ugo can be u, g, or o to indicate that the command sets permissions for a user, a group, or all other users, respectively; name is the name of the owner or group that are being set; permissions is the permissions in either symbolic or absolute format; and file-list is the list of files to be applied. You must omit name when you specify permissions for others (o). Symbolic permissions use letters to represent permissions whereas absolute permissions use an octal number. chmod uses three sets of permissions or three octal numbers (one for each owner, group, and other users), setacl uses a single set or single octal number to represent the permissions being granted to the user or group represented by ugo and name. See the discussion of chmod on page 216 for more information about symbolic and absolute representations of file permissions.

For example, both of the following commands add a rule to the ACL for the report that gives sam read and write permission to that file:

```
$ setacl --modify u:sam:rw- report
```

```
$ setacl --modify u:sam:6 report
$ getacl report
# file: report
# owner: max
# group: max
user::rw-
user:sam:rw-
group::r--
mask::rw-
other::r--
```

The line containing sam:rw-- shows that the user named sam has read and write access (rw--) to the file. See page 215 for an explanation of how to read access permissions. See the following optional section for a description of the line that starts with mask.

When a file has an ACL, ls -l displays a plus sign (+) following the permissions, even if the ACL is empty:

```
$ ls -l report
-rw-rw-r---+ 1 max 9537 2010-01-12 23:17 report
```

# EFFECTIVE RIGHTS MASK

The line that starts with mask specifying the effective mask. This mask limits the effective permissions granted to ACL groups and users. It does not affect the owner of the file or the group file is associated with. In other words, it does not affect Linux permissions. However, because setfacl sets the effective rights mask to the least restrictive ACL permissions for the file, the mask has no effect unless you set it explicitly after setting up an ACL for the file. You can set the mask by specifying mask or by setting a name in a setfacl command.

The following example sets the effective mask to read for the report file:

```
$ setfacl -m mask:r-- report
```

The mask line in the following setfacl output shows the effective mask set to read (r--). The line displays Sam's file access permissions they still set to read and write. However, the comment at the right of the line shows that his permission is read.

```
$ setfacl report
# file: report
# owner: max
# group: max
user::rw-
user:sam:rw--
group::r--
mask::r--
other::r--
#effective:r--
```

As the next example shows, setfacl can modify ACL rules and set more than one ACL rule at a time:

```
$ setfacl -m sam:r--,u:zach:rw-- report
```

```
$ setfacl --omit-header report
user::rw-
user:sam:r--
user:zach:rw--
group::r--
mask::rw--
other::r--
```

The -x option removes ACL rules for a user or a group. It has no effect on permissions for the owner of the file or the group file is associated with. The next example shows setfacl removing the rule that gives Sam permission to access the file:

```
$ setfacl -x u:sam report
```

```
$ setfacl --omit-header report
user::rw-
user:sam:r--
user:zach:rw--
group::r--
mask::rw--
other::r--
```

You must not specify permissions when you use the -x option. Instead, specify only the -b option, followed by a filename, removes all ACL rules and the ACL itself from the file or directory you specify.

Both setfacl and getfacl have many options. Use the --help option to display brief lists of options or refer to the man pages for details.

# SETTING DEFAULT RULES FOR A DIRECTORY

The following example shows that the dir initially has no ACL. The setfacl command uses the -d (default) option to add two default rules to ACL for dir. These rules apply to all files in the dir directory that do not have explicit ACLs. The rules give members of the pubs group read and execute permissions and members of the admin group read, write, and execute permissions.

```
$ ls -ld dir
drwx------ 2 max 4096 2010-02-12 23:15 dir
$ getfacl dir
```

The following example shows the default rules:

```
$ setfacl -d -m g:pubs:rx,g:admin:rwx dir
$ touch file dir
$ getfacl dir
# file: dir
# owner: max
# group: max
user::rw--
group:pubs:r-x
group:admin:rwx
mask::rwx
other::r--
```

# LINKS

A link is a pointer to a file. Each time you create a file using vim, touch, or by another means, you are putting a pointer in a directory. This link associates a filename with a place on the disk.
