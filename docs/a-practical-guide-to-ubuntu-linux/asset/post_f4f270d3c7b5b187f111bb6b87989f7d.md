
# LOADING A MODULE

After you install a module with module-assistant, you must load it to make it available to the running kernel. Table 15-1 lists some of the tools available to help you work with modules. Refer to the corresponding pages for options and more information.

**Table 15-1** Tools for working with modules

| Tool/utility | Function |
| --- | --- |
| depmod | Works with dependencies for modules. |
| insmod | Loads modules in a running kernel. |
| lsmod | Lists information about all loaded modules. |
| modinfo | Lists information about a module. |
| modprobe | Loads, unloads, and reports on modules. When it loads a module, it also loads dependencies. |
| rmmod | Unloads modules from a running kernel |

# REBOOTING

Reboot the system by selecting Main menu: System-Quit and then clicking Restart. If you are working at the console, press CONTROL-ALT-DEL. You can also give a reboot command from the console, a character-based terminal, or a terminal emulator.

# GRUB: The LINUX BOOT LOADER

MBR A boot loader is a very small program that the bootstrap (page 1138) process uses as it brings a computer from off or reset to a fully functional state. The boot loader frequently resides on the starting sectors of a hard disk called the master boot record (MBR).

BIOS (page 1137), which is stored in an EEPROM (page 1147) on the system's motherboard, gains control of a system when you turn on or reset the computer. After testing the hardware, the BIOS transfers control to the MBR, which usually passes control to the partition boot record. This transfer of control starts the boot loader, which is responsible for locating the operating system kernel (kept in /boot directory), loading that kernel into memory, and starting it. The /boot directory, which may be mounted on a separate partition, must be present for the system to boot Linux. Refer to “Booting the System” on page 444 for more information on what happens from this point forward.

All newer hardware supports LBA (logical block addressing) mode. LBA permits the directory to appear anywhere on the hard disk. For LBA to work, it must be supported by the hard disk, the BIOS, and the operating system (GRUB in the case of Linux). Although both GRUB and GRUB legacy support LBA addressing mode, BIOSes do not. For this reason, it is a good idea to place the /boot directory in its own partition located near the beginning of the hard disk. With this setup, the root / can be anywhere on any hard drive that Linux can access regardless of LBA support. Also, systems with LVM require a boot partition. In some instances, without a separate /boot partition, the system may boot at first, but then fail as you update the kernel and the kernel files move further from the beginning of the disk.

GRUB stands for Unified Boot Loader. With release 9.10 (Karmic Koala), Ubuntu introduced GRUB 2, which this book refers to as GRUB. This book refers to the first release as GRUB legacy. GRUB 2 is a complete rewrite; few configuration files are the same.

# Upgrading from releases before Karmic Koala

Upgrading from Karmic Koala (9.10) or a previous release of Ubuntu will not upgrade GRUB legacy to GRUB 2. Visit wiki.ubuntu.com/Grub for instructions on upgrading from GRUB legacy to GRUB 2. A product of the GNU project, the GRUB loader conforms to the multiboot specification (page 1160), which allows it to load many free operating systems directly as well as proprietary operating systems (page 1140). The GRUB loader can recognize various types of filesystems and kernel executables, allowing to load an arbitrary operating system. When you boot the system, GRUB can display a menu of choices that is generated by /boot/grub/grub.cfg (page 587). At this point you can modify a menu selection, choose which operating system to boot, or not allow GRUB to boot the default.

# Configuring GRUB

As mentioned, GRUB 2 uses a different set of files than GRUB legacy. You can control most of the frequently changed aspects of GRUB by editing the /etc/default/grub file (discussed next) and running update-grub which generates /boot/grub/grub.cfg file (page 587). You can edit files in /etc/grub.d directory (page 586) to perform advanced configuration of the GRUB menu. The grub.cfg file is comparable to the GRUB legacy /boot/grub/menu.lst file, but it is a poor idea to edit the grub.cfg file because it is generated by update-grub each time utility runs.

# /etc/default/grub: The PRIMARY GRUB CONFIGURATION FILE

Changing the values of variables in /etc/default/grub allows you to modify many aspects of how the system boots and how GRUB displays its menu (Figure 11-1, page 446). In most cases, you can force GRUB to display its menu by holding down the SHIFT key as system boots (page 445).

The effects of the variables you set in /etc/default/grub depend on whether GRUB finds one or more bootable operating systems. Some variables do not need to be set. Toward this end, GRUB does not evaluate a line that begins with a hashmark (#); these lines are comments. Remove or add a hashmark to cause GRUB to evaluate or not evaluate an assignment. The beginning of the /etc/default/grub file is shown here. The first few variables are set; the last few are commented.

```
$ cat /etc/default/grub
# If you change this file, run 'update-grub' to update
# /boot/grub/grub.cfg.
```

You can assign values to the following variables:

GRUB_DEFAULT=num saved
The num specifies the ordinal number of the default menu entry. Menu entries are numbered starting with 0, so setting the variable to 0 specifies the first menu entry. The default menu entry is the one GRUB boots if you do not select a different entry as GRUB boots the system. Setting GRUB_DEFAULT to saved saves GRUB to boot the most rebooted entry.

GRUB_HIDDEN_TIMEOUT=num
The num specifies the number of seconds GRUB waits with a blank screen (the menu is hidden—thus it is a hidden timeout) or displays the image you specify in /etc/grub.d/05_debian_theme (page 587) before booting the system. Setting num to 0 causes GRUB to pause just long so that if the user is holding the SHIFT key to access the system menu, GRUB ignores it on systems with more than one bootable system.

GRUB_HIDDEN_TIMEOUT_QUIET=true
Specifies whether GRUB displays a countdown timer during a hidden timeout (see GRUB_HIDDEN_TIMEOUT). Set to false to display the timer or true not to display it.

GRUB_TIMEOUT=num
The num specifies the number of seconds GRUB waits before booting the system. Set num to -1 to cause GRUB to wait until the user selects a menu item. Setting num to 0 causes the SHIFT key to lose its effect: The user will not be able to display the GRUB menu before the system boots.
