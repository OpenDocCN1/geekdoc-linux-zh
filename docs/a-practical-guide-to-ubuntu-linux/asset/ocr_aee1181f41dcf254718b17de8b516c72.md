# (Dot) or source: RUNS A STARTUP FILE IN THE CURRENT SHELL

After you edit a startup file as .bashrc, you do not have to log out and log in to put the changes into effect. Instead, you can run the startup file using the (dot) or source builtin (they are the same command). With all other commands, the . must be followed by a SPACE on the command line. Using, or source is similar to running a script file, except these commands run the script as part of the current process. Consequently, when you use, . or source to run a script, changes you make to variables from within the script affect the shell you run the script from. If you run a startup file as a regular script and did not use it, the variables created in the startup file would remain in effect only in the subshell running. You can use the . or command to run any shell script—not just a startup file—but undesirable side effects (such as changes in the values of shell variables you rely on) may occur. For more information refer “Locality of Variables” on page 992.

In this example, .bashrc sets several variables and sets PS1, the prompt, of the name of the host. The builtin puts new values into effect:

```
$ cat ~/.bashrc
export TERM=vt100             # set the terminal type
export PS1="$(hostname -f): " # set the prompt string
export CDPATH=$CDPATH string  # add HOME to CDPATH string
stty kill='au'                # set kill line to control-u

$ ~/.bashrc
bravo.example.com:
```
