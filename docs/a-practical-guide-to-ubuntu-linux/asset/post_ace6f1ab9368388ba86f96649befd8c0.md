GRUB_CMDLINE_LINUX_DEFAULT=string

GRUB appends *string* to the boot line that GRUB passes to the kernel at time booting in normal mode (and not recovery mode; page 445). As supplied with Ubuntu, the *string* is *quiet splash*, which causes Ubuntu to display the splash screen and no messages as it boots. For more information reference to “Seeing Going On” on page 57. You can also add command-line parameters to *string*; page 82 for each word from the next with a SPACE and, if *string* includes SPACES, enclose *string* within double quotation marks.

GRUB_CMDLINE_LINUX=string

GRUB appends *string* to the boot line that GRUB passes to the kernel booting in normal and recovery modes (page 445). See the discussion of GRUB_CMDLINE_LINUX_DEFAULT for more information.

GRUB_TERMINAL=console

Commented by default. Remove the leading hashmark to uncomment this variable and disable the graphical terminal on PCs. Doing so speeds up work with the kernel in GRUB command-line mode.

GRUB_GFMODE=WxH

Commented by default. Remove the leading hashmark to uncomment this variable and set the resolution of the display for the boot menu. W is the width of the display and H is the height of the display, both in pixels. You must set this variable to a value that is valid for the graphics card. For example, 640x480 sets the resolution to 640 pixels by 480 pixels.

GRUB_DISABLE_LINUX_uuid=false

Commented by default. Remove the leading hashmark to uncomment this variable and specify whether GRUB passes the root=UUID=xxx parameter to the kernel. By default, GRUB passes this parameter to the kernel (false). See page 510 for more information on identifying partitions with UUID numbers.

GRUB_DISABLE_LINUX_recovery=true

Commented by default. Remove the leading hashmark to uncomment this variable and specify whether update-grub generates recovery-menu entries. By default, GRUB generates these entries (false).

GRUB_INIT_TUNE=beep frequency

Commented by default. Remove the leading hashmark to uncomment this variable and specify that GRUB is to output a beep when it starts. A typical value for beep frequency is 480 440 1. You must enclose beep frequency within double quotation marks.

# /etc/grub.d/*: GRUB CONFIGURATION TEMPLATES

The files in /etc/grub.d determine many aspects of the GRUB menu. The update-grub utility (discussed next) processes these files in shell expansion order, which for the default set of files means numerical order. The README file in this directory contains more information.

You can add files to this directory and modify the existing files, but it is usually safer to do so. Each of these files must be executable if update-grub processes it. If you do not update-grub to process one of the files, remove the execute bits from the file. For example, if you do not have memtest86+ included on the GRUB menu, give the following command:

```
$ chmod 644 /etc/grub.d/d20_memtest86+
```

By default, /etc/grub.d directory holds the following files:

- 00_header: Runs the initial GRUB setup and provides the header information that appears at the beginning of the grub.cfg file.
- 05_debian_theme: Sets the theme as well as the background and text colors.
- 10_linux: Creates a menu for each kernel specified by a file name /boot/vmlinuz-[version]-. If GRUB_DISABLE_LINUX_RECOVERY is set to false, this file also creates a recovery menu for each of these kernels.
- 20_memtest86: Creates a menu for memtest86 if the /boot/memtest86+ file exists.
- 30_os-prober: Creates menus for Linux and other operating systems on partitions other than boot.
- 40_custom: Accepts custom entries.

# update-grub: UPDATES THE grub.cfg FILE

The update-grub utility is a script that runs grub-mkconfig with the output file as /boot/grub.cfg. The grub-mkconfig utility creates or updates its output file based on the contents of the /etc/default/grub file (page 584) and files in the /etc/grub.d directory (page 586). A sample run of update-grub is shown here:

```
$ sudo update-grub
Generating grub.cfg ...
Found Linux image: /boot/vmlinuz-2.6.32-22-generic
Found initrd image: /boot/initrd.img-2.6.32-22-generic
Found Linux image: /boot/vmlinuz-2.6.32-21-generic
Found initrd image: /boot/initrd.img-2.6.32-21-generic
Found memtest86+: /boot/memtest86+.bin
done
```

By default, update-grub searches for Linux and other system kernel files and creates a new entry (specification) in grub.cfg for each kernel it finds. If /boot/memtest86+ and /etc/grub.d/20_memtest86+ file is executable, update-grub includes a menu entry for that. It also adds an initrd (initial RAM disk) line to grub.cfg for each file in /boot whose name starts with initrd- and whose version number matches one of the kernels found.

Each time update-grub runs, it searches for kernel files. If a kernel file is no longer present, it will no longer include a menu entry for that kernel. Similarly, if a new kernel file is present, it will include a menu entry for that kernel. You can remove a kernel's menu entry by removing the kernel package, which removes the kernel files.

The command uname -r displays the name of the kernel the system is running. The following commands display the name of the kernel the system is running and list the installed kernel packages. See page 535 for more information about the dpkg --list option.

```
$ uname -r
2.6.32-22-generic
```

```
$ dpkg list "linux-image*"
Desired=Auto/Unknown/Install/Remove/Purge/Hold
Status=Not-Installed/Config-Files/Failed/Half-installed/Try-wait/Pending
Err=7
```

# grub-install: INSTALLS THE MBR AND GRUB FILES

The grub-install utility installs the MBR (page 583) and the files that GRUB needs to boot. It takes a single argument—the name of the device. You can specify the device as a GRUB device name (e.g., hd0) or a device filename (e.g., /dev/sda). The following example shows grub-install files in the default location (/boot/grub):

```
$ sudo grub-install /dev/sda
```

Installation finished. No error reported.

# REINSTALLING THE MBR

To reinstall the MBR, as is necessary when it gets overwritten by a Windows installation, boot the system from an Alternate CD, Server CD, or an installation DVD, and select Rescue a Broken System (page 83). Then select Reinstall the GRUB from the Rescue Operations menu (page 84).

# dmesg: DISPLAYS KERNEL MESSAGES

The dmesg utility displays the kernel-ring buffer, where the kernel stores messages. When the system boots, the kernel fills this buffer with messages related to hardware and module initialization. Messages in the kernel-ring buffer are often useful for diagnosing system problems.

When you run dmesg, it displays a log of information. It is easy to pipe the output of dmesg through less or grep to find what you are looking for. For example, if you find that your hard disks are performing poorly, you can use dmesg to check whether they are running in DMA mode:

```
$ dmesg | grep DMA cmd
```

```
[ 23.25942 ] ata1: SATA max UDMA/133 cmd 0x9F0 ctl 0xBF2 bmdma 0xE000 irq 5
[ 23.25948 ] ata2: SATA max UDMA/133 cmd 0x970 ctl 0x872 bmdma 0xE008 irq 5
```

The preceding lines tell you each SATA device is operating in. If you are having problems with the Ethernet connection, search the dmes log for eth:

```
$ dmesg | grep eth
forcedeth.c: Reverse Engineered Nforce ethernet driver. Version 0.61.
eth0: forcedeth.c: subsystem: 0147b:1c00 bound to 0000:00:04.0
eth0: no IPv6 routers present
```

If everything is working properly, dmesg displays the hardware configuration information for each network interface.
