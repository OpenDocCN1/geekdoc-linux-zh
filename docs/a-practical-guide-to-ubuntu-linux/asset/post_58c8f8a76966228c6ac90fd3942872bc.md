The first time cat is called, the shell expands the variable a, interpreting the string w:x:z as a single word to be used as the argument to cat. The cat utility finds a file named w:x:z and reports an error for filename. If IFS is the colon (:); the shell expands the variable into four words, each of which is an argument to cat. Now cat reports errors for four files: w, x, y, and z. Word splitting based on the colon:) takes place only after the variable a is expanded.

The shell splits all expanded words on a command line according to the separating characters. When there is no expansion, there is no splitting. Consider the following commands:

```
$ IFS="p"
$ export VAR
```

Although IFS is set to p, the p on the export command line is not expanded, so the word export is not split.

The following example uses variable expansion in an attempt to produce an error:

```
$ IFS="p"
$ aa=export
$ echo $aa
```

This expansion occurs, so the character p in the token export is interpreted as a separator (as the echo command shows). Now you try to use the value of the aa to export the VAR variable, the shell parses the Sa command line as ex VAR. The effect is that the command starts the ex editor with two filenames: ort and VAR.

```
$ Sa VAR
2 files to edit
"ort" [New File]
Enter Ex mode. Type "visual" to go to Normal mode.
:q
E173: 1 file to edit
:q
$
```

If you unset IFS, only SPACES and TABs work as field separators.

## Multiple separator characters

Although the shell treats multiple SPACE or TAB characters as a single separator, it treats each occurrence of another field-separator character as a separator.

## CDPATH: BROADENING THE SCOPE OF cd

The CDPATH variable allows you to use a simple filename as an argument to the builtin to change the working directory to a directory other than a child of the working directory. If you have several directories typically work out of, this variable speed things up and save you the tedium of using cd with longer path-names to switch among them.

When CDPATH is not set and you specify a simple filename as an argument to cd, cd searches the working directory for a subdirectory with the same name as the argument. If the subdirectory does not exist, cd displays an error message. When CDPATH is set, cd searches for an appropriately named subdirectory in the directories of the CDPATH list. With CDPATH set, you can use cd and a simple filename to change the working directory to a child of any of the directories listed in CDPATH.

The CDPATH variable takes the value of a colon-separated list of directory pathnames (similar to the PATH variable). It is usually set in the ~/.bash_profile startup file by a command line such as the following:

```
export CDPATH=$HOME:$HOME/literature
```

This causes cd to search your home directory, the literature directory, and the working directory when you give a cd command. If you do not include the working directory in CDPATH, cd searches the working directory if the search of all the other directories in CDPATH fails. If you want cd to search the working directory first, include a null string, represented by two colons (;;), as the first entry in CDPATH:

```
export CDPATH=$:$HOME:$HOME/literature
```

If the argument to the cd builtin is an absolute pathname—one starting with a slash (/)—the shell does not consult CDPATH.

## PROCESSES

A process is the execution of a command by the Linux kernel. The shell that starts when you log in a command, or a process, like any other. When you give the name of a Linux utility on the command line, you initiate a process. When you run a shell script, another process is started and additional processes are created for each command in the script. Depending on how you invoke the shell script, the process is either run by the current shell, or more typically, by a subshell (child) of the current shell. A process is not started when you run a shell builtin, such as cd.

## PROCESS STRUCTURE

fork system call Like the file structure, the process structure is hierarchical, with parents, children, and even a root. A process forks a child process, which in turn can fork other processes. The term fork indicates that, as with a fork in the road, one process turns into two. Initially the two forks are identical except that one is identified as the parent and one as the child. You can also use the spawn; the words are interchangeable.) The operating system routine, or system call, creates a new process named fork().

When Linux begins when a system is started, it starts init, a single process called a spontaneous process, with PID number 1. This process holds the same position in the process structure as the root directory does in the file structure: It the ancestor of all processes and users work with. When a command-line system is multiuser, init runs getty or getty, which displays login prompts on terminals. When a user responds to the prompt and presses RETURN, getty hands control over to a utility named login, which checks the username and password combination. After the user logs in, the login process becomes the user's process.

## PROCESS IDENTIFICATION

PID numbers Linux assigns a unique PID (process identification) number at the inception of each process. As long as a process exists, it keeps the PID number. During one session the process is always executing the login shell. When you fork a new process—for example, when you use an editor—the new (child) process is different from that of its parent process. When you return to the login shell, it is still being executed by the same process and has the same PID number as you logged in.
