File Transfer Protocol is a method of downloading files from and uploading files to another system using TCP/IP over a network. File Transfer Protocol is the name of a client/server protocol (FTP) and a client utility (ftp) that invokes the protocol. In addition to the original ftp utility, there are many textual and graphical FTP client programs, including most browsers, that run under many different operating systems. There are also many FTP server programs.

# INTRODUCTION TO FTP

This chapter starts with an introduction to FTP which discusses security, describes types of FTP connections, and presents a list of FTP clients. The first JumpStart section covers ftp commands and includes a tutorial on using the ftp client. Next is a section that presents more details of ftp. The final section describes how to set up a vsftpd server.

First implemented under 4.2BSD, FTP has played an essential role in the propagation of Linux; this protocol is frequently used to distribute free software. The term FTP site refers to an FTP server that is connected to a network, usually the Internet. FTP sites can be public, allowing anonymous users to log in and download software and documentation. In contrast, FTP sites require you to log in with a username and password. Some sites allow you to upload programs.

# SECURITY

FTP is not a secure protocol: All usernames and passwords are exchanged in setting up an FTP connection is not encrypted, and the connection is subject to hijacking. Given these facts, FTP is best used for downloading public files. In most cases, the OpenSSH client, ssh (page 670), scp (page 672), and sftp (page 674), offer secure alternatives to FTP.

## Use FTP only to download public information

FTP is not secure. The vsftpd utility provides better security for all FTP functions other than allowing anonymous users to download information. Because vsftpd uses an encrypted connection, user passwords and data cannot be sniffed when you use this utility. You can replace instances of ftp in this chapter with sftp because vsftpd uses the same commands as ftp. See page 674 for more information on sftp.

### security

The vsftpd server does not make usernames, passwords, data, and connections more secure. However, it is secure in that a malicious user finds it difficult to compromise the directly system running it, if vsftpd is poorly implemented. One feature that makes vsftpd more secure than ftp is that it does not run with root privileges. See also “Security” on page 699.

# FTP CONNECTIONS

FTP uses two connections: one for control (you establish this connection when you log in an FTP server) and one for data transfer (FTP sets up this connection when you ask it to transfer a file). An FTP server listens for incoming connections on port 21 by default and handles user authentication and file exchange.

## Passive versus active connections

A client can ask an FTP server to establish a PASV (passive–give the command ftp -p or pasv) or a PORT (active–the default when you use ftp) for data transfer. Some servers are limited to one type of connection. The difference between a passive and an active FTP connection lies in whether the client or the server initiates the data connection. In passive mode, the client initiates the connection (no port by 20 default); in active mode, the server initiates the connection (there is no default port; “Connection Parameters” on page 708 for the parameters that determine which a server uses). Neither approach is inherently secure than the other. Passive connections are more common because a client behind a NAT (page 881) can connect to a passive server and it is simpler to program a scalable server.

# FTP Clients

- Ubuntu supplies several FTP clients, including ftp (an older version of the BSD FTP utility). This discussion discusses ftp because most FTP clients, including sftp and lftp, provide a superset of ftp commands.
- Part of the OpenSSH suite (openssh-client package) is a secure and functionally equivalent alternative to sftp. The sftp utility is not a true FTP client—it does not understand the FTP protocol. It maps ftp commands to OpenSSH commands. See page 674 for more information.
- lftp utility (lftp package) provides the same security as sftp but offers more features. See the lftp page for more information.
- gftp utility (gftp package) is a graphical client that works with FTP, SSH, and HTTP servers. This client has many useful features, including the ability to resume an interrupted file transfer. See www.gftp.org and freshmeet.net/projects/gftp for more information.
- ncftp utility (ncftp package) is a textual client that offers more features than ftp, including filename completion and command-line editing. For details see www.ncftp.com and freshmeet.net/projects/ncftp.

# RUNNING the ftp and sftp FTP Clients

This section describes how to use the ftp and sftp FTP clients. The commands described here work with both utilities.

## PREREQUISITES

The ftp and sftp utilities are installed on most Ubuntu systems. You can check for their presence by giving either these utilities' names as commands:

```
$ ftp
ftp> quit

$ sftp
usage: sftp [-1V] [-B buffer_size] [-b batchfile] [-F ssh_config]
[-o ssh_option] [-P sftp_server_path] [-R num_requests]
[-S program [-s subsystem | sftp_server]] host
sftp [[user]@host[:file]]
sftp [[user]@host[:dir]]
sftp -b batchfile [user]@host
```

Install the ftp (contains ftp and pftp) or openssh (contains sftp) package if needed.

# JUMPSTART I: DOWNLOADING FILES USING ftp

This Jump section is broken into two parts: a description of the basic commands and a tutorial session that shows a user working with ftp. Before you start, make sure ftp or sftp is installed on the local system as explained in the previous section.

## BASIC COMMANDS

Give the command

```
$ ftp hostname
```

where hostname is the name of the FTP server you want to connect to. If you have an account on the server, log in with your username and password. If it is a public system, log in as the anonymous (or ftp) and give your email address as your password. Use the ls and cd commands on the server as you would use the corresponding utilities from a shell. Command get file copy file put file from the local system to the server, status displays information about the FTP connection, and help displays a list of commands.
The preceding commands, except for status, are also available in sftp, ftp, and ncftp.
