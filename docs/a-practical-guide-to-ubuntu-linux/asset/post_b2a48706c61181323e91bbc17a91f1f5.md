
## ufw: The Uncomplicated Firewall 875

When you specify the name of a service (ssh in the preceding example) in a ufw command, ufw searches /etc/services to find the port number used by the service. When you specify the name of the application as listed by ufw app list (OpenSSH in the preceding example), ufw reads the rules from the file applications.d. The difference between these techniques is important with services/applications that use multiple ports or a range of ports. The /etc/services file cannot represent this information; the rules in the files in applications.d can.

When you give a status command with an argument of verbose, it reports that ufw is loaded, turned on, and the default policy is to deny incoming connections and allow outgoing connections. With or without verbose, status reports that ufw allows connections on port 22 (the port ssh uses).

```
$ ufw status verbose
Status: active
Logging: on (low)
Default: deny (incoming), allow (outgoing)
New profiles: skip
```

| To | Action | From |
| --- | --- | --- |
| 22 | ALLOW IN | Anywhere |

If you log in to the firewall from one remote system, you can make the firewall system more secure by limiting those systems you can log in. The following-allow command opens port 22 to connections from the system at 10.10.4.15 only: (page 589).

```
$ ufw allow from 10.10.4.15 port 22
Rule added
```

You remove a rule by using the same command as you used to establish the rule, preceded by the word delete:

```
$ ufw delete allow ssh
Rule deleted
```

```
$ ufw status
Status: active
```

| To | Action | From |
| --- | --- | --- |
| Anywhere | ALLOW | 10.10.4.15 22 |

By default, logging is turned on (ufw logging on) and ufw sends messages about intrusion attempts to the kern syslog facility (page 625). These messages go to the file /var/log/kern.log. The same information is given by dmesg utility.

```
$ ufw tail -1 /var/log/kern.log
Apr 8 14:27:05 100B2 kernel: [2095.405395] [UFW BLOCK] IN=eth0 OUT= MAC=00=:
SRC=10.10.4.16 DST=10.10.4.100 LEN=44 TOS=0x00 PRE=0x00 TTL=64 ID=19466 DF PROTO=TCP
SPIT=50166 DPT=22 WINDOW=5840 RES=0x00 SYN URRP=0
```

If you want to set up an Apache Web server that accepts requests on port 80 on the local system, you need to open port 80. The following commands open port 80 and verify the new rule:

- - sudo ufw allow 80
Rule added

- - sudo ufw status
...
80 ALLOW Anywhere

See the ufw man page for more information.

## gufw: THE GRAPHICAL INTERFACE TO ufw

The gufw utility is a graphical interface to ufw (page 874), the uncomplicated firewall. Any changes you make using one interface are reflected by the other, although you may have to close and reopen the gufw Firewall window to update its contents. You must install the gufw software package to run gufw.

## THE FIREWALL WINDOW

Before you enable ufw and add rules, the gufw Firewall window appears as shown in Figure 25-10; the shield appears in shades of gray. To display this window, select Main menu: System⇒Firewall configuration or enter the command gufw from a terminal or Run Application (ALT+F2).

To enable the firewall, put a tick in the check box labeled Enabled (the status Actual). When you enable the firewall, the shield takes on colors. Disable the firewall by removing the tick.

The drop-down lists in this window are Incoming and Going. Each of these lists provides three selections:
- Allow: Allow traffic to pass in the direction.
- Deny: Deny traffic to pass in the direction.
- Reject: Reject traffic to pass in the direction. 

Initially, Incoming is set to Deny and Going is set to Allow.

## ADDING RULES

To add a rule, click the button labeled Add (Figure 25-11). This window has tabs: Preconfigured, Simple, and Advanced.

## SETTING A FIREWALL

## THE PRECONFIG TAB

Initially, this window displays the Preconfigured tab with lists. From left to right they are:
- Disposition: Specifies what the firewall does with this traffic. Choices are Allow, Deny, Reject, and Limit.
- Direction: Specifies the direction of the traffic. Incoming indicates inbound. Outgoing indicates outbound.
- Source: Specifies the source of the traffic.
- Name: Specifies the name or service.

If the system is set up as ssh (page 67), you need to set up the firewall to allow inbound traffic. To do so, enable the firewall by putting a tick in the check box labeled (You cannot add rules when the firewall is disabled). Next click Add. Then set the four drop-down lists as appropriate.

## THE SIMPLE TAB

The Simple tab of the Add Rule window holds three drop-down lists and a text box. The first two drop-down lists are the same as the first two in the Preconfigured tab: Position and Direction. See the previous section for information on these lists. The third drop-down list specifies the Protocol: TCP, UDP, or Both. The text box specifies the rule controls. In this box you can specify a service as ssh, a port such as 22, several ports separated by commas as 22,24,26 (ports 22, 24, and 26), or a range of ports separated by a colon as 135:139 (ports 135 through inclusive).

## THE ADV TAB

The Advanced tab of the Add Rule window holds the same three drop-down lists as the Simple tab: Disposition, Direction, and Protocol. To the right of these lists are two rows of text boxes. The first row is labeled From and hostname. The box on the left in each specifies an IP address or hostname. The box on the right specifies a service, port, or range of ports in the same manner as the text box in the Simple tab. Using these text boxes, you can specify the origin and destination of the traffic rule applies to.
