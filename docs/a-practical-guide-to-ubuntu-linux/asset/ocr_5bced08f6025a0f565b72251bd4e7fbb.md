# CONFIGURING SPAMASSIN

Spamassassin looks in many locations for configuration files; for details, refer to the spassassin man page. The easiest configuration file to work with is /etc/mail/spamassassin/local.conf. You can edit this file to configure Spamassassin globally. You can override these global options and add their own options in ~/.spamassassin/user_prefs file. You can use the options discussed in this section in either of these files.

For example, you can configure Spamassassin keyword to rewrite the Subject line of email that it rates as. The rewrite_header keyword in the configuration files controls this behavior. The word Subject following this keyword tells Spamassassin to rewrite Subject lines. Remove the # from the following line to turn on:

```
# rewrite_header Subject *****SPAM****
```

The required_score keyword specifies the minimum score a email must receive before Spamassassin considers it to be spam. The default is 5.00. Set the value of this keyword to a higher number to cause Spamassassin to mark fewer pieces of email as spam.

Sometimes mail from addresses that should be marked as spam is not, or mail from addresses that should not be marked as spam. Use the whitelist_from keyword to specify addresses that should never be marked as spam and blacklist_from to specify addresses that should always be marked as spam:

```
whitelist_from sams@example.com
blacklist_from *@spam.net
```

You can specify multiple addresses, separated by SPACES, on the whitelist_from and blacklist_from lines. Each address can include wildcards. To whitelist everyone from example.com domain, whitelist_from *@example.com. You can use multiple whitelist_from and blacklist_from lines.

# RUNNING SPAMASSASSIN ON A MAIL SERVER

This section explains how to set up Spamassassin on a mail server so that it will process all email delivered to local systems before it is sent to users. Shows how to use procmail for the MDA and how procmail send email through spam.

Also make sure the procmail package is installed on the server system. If the /etc/procmail configuration file does not exist, create it so that this file is owned by root and has 644 permissions and the following contents. If it does exist, append the last two lines from the following file to it:

```
$ /etc/procmailrc
DROPPRIVS=yes
:0 fw
| /usr/bin/spamc
```
