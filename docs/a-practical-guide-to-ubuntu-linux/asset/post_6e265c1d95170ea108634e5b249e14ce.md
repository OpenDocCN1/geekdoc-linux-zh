
## 418 CHAPTER 11 SYSTEM ADMINISTRATION: CORE CONCEPTS

A well-maintained system

:

- Runs quickly enough so users do not get frustrated waiting for the system to respond or complete a task.
- Has enough storage to accommodate users' reasonable needs.
- Provides a working environment appropriate to each user's abilities and requirements.
- Is secure from malicious and accidental acts altering its performance or compromising the security of the data it holds and exchanges with other systems.
- Is backed up regularly, with recently backed-up files being readily available to users.
- Has recent copies of the software that users need to get their jobs done.
- Is easier to administer a poorly maintained system.

In addition, a system administrator should be available to help users with all types of system-related problems—from logging in obtaining and installing software updates to tracking down and fixing obscure issues.

## RUNNING COMMANDS WITH root PRIVILEGES

Some commands can damage the system or crash the operating system. Other commands can invade users' privacy or make the system less secure. To keep a Linux system up and running as secure, Ubuntu is not configured to permit ordinary users to execute some commands and access certain files. The default username of the trusted user with these systemwide privileges is root; a user with these privileges is also sometimes referred to as Superuser. In this section explains, Ubuntu has enabled ordinary users to run commands with root privileges while logged in as themselves.

A user running with root privileges has the following powers—and more:

- Some commands, such as those as add users, partition hard drives, and change system configuration, can be executed only by a user with root privileges. A user can configure tools, such as sudo, to give specific users permission to perform tasks that are normally reserved for a user running with root privileges.
- Read, write, and execute file access and directory access permissions do not affect a user with root privileges. A user with root privileges can read from, write to, and execute all files, as well as examine and work in all directories.
- Some restrictions and safeguards that are built into some commands do not apply to a user with root privileges. For example, a user with root privileges can change any user's password without knowing the old password.

### Console security

Ubuntu Linux is not secure from a person who has physical access to the computer. Additional security measures, as setting boot loader and BIOS passwords, can help secure the computer. However, if someone has physical access to the hardware, system console users typically do, it is very difficult to secure a system from that user.

### Least privilege

When you are working on any computer system, but especially when you are working as the system administrator (with root privileges), perform any task using the least privilege possible. When you can perform a task logged in as an ordinary user, do so. When you must run a command with root privileges, do use sudo so you have root privileges, complete the part of the task that has to be done with root privileges, and revert to an ordinary user as soon as you can. Because you are more likely to make a mistake when you are rushing, this concept becomes even more important when you have less time to spend.

When you are running with root privileges in a command-line environment, convention displays a special prompt to remind you of your status. By default, this prompt ends with a hash (#). You can gain root privileges in number of ways:

- When you begin in recovery mode (page 445), you can log in as root.
- The sudo allows certain users to log in as root. They can run commands with root privileges while they are logged in as themselves.
- sudo asks for your password when it starts. When you supply the password, you will have root privileges.
- Some programs ask for your password when they start. When you provide the password, you will be running with root privileges.
- The /etc/security/access.conf file must contain the name of all users/workstations that you want to be able to log in as. Initially every line in access.conf is commented out.
- The /etc/security/access.conf file controls which terminals (tys) a user can log in as root. See page 445 for deatils.
- Once the system is up and running in multiuser mode (page 448), you can log in as root. When you supply the password, you will be running with root privileges.

Some techniques limit how one can log in as root. For example, PAM (page 478) controls the who, when, and how of logging in. The /etc/security/access.conf file controls which terminals (tys) a user can log in as root. The /etc/security/access.conf file adds another dimension to login control (see the comments in the file).

- root-owned setuid programs are extremely dangerous Because root-owned setuid programs allow anyone who does not know the root password to use sudo to gain root privileges, they are tempting targets for a malicious user. Also, you can disable setuid programs at the filesystem level by mounting a filesystem with the nosuid option (page 508). See page 454 for a command that lists all setuid files on the local.

- The following techniques for gaining root privileges depend on unlocking the root account (setting up root password) command as explained on page 431:
- You can use a su (substitute user) command while you are logged in as yourself. When you provide the root password, you will have root privileges. For more information refer to “su: Gives Another User’s Privileges” on page 431.

- Do not allow root access over the Internet Prohibiting root users logging in over a network is the default policy of Ubuntu and implemented by the PAM security module. The /etc/security/access.conf file must contain the name of all users/workstations that you want to be able to log in as. Initially every line in access.conf is commented out.
- You can, log in root over a network using ssh (page 663). As shipped Ubuntu, ssh does not follow the instructions in security or access.conf. In addition, /etc/ssh/sshd_config, Ubuntu sets PermitRootLogin to yes to permit root to log in using ssh (page 680).

## sudo: RUNNING A COMMAND WITH root PRIVILEGES

Classically a user gained root privileges by logging in as root or by giving an su (substitute user) command and providing the root password. When an ordinary user executed a privileged command in a graphical environment, the system would prompt for the root password. Most recently the use of sudo (www.sudo.ws) has taken over these classic techniques of gaining root privileges.
