
## WORKING WITH FILES

This file handles case Perl program to work like many Linux units: It reads from standard input unless the program is called with one or more arguments, in which case it reads from the files named by the arguments. See page 248 for an explanation of how this feature works with cat.

The print statement in the first line of the next example includes the optional handle STDOUT; the next print statement omits this handle; the final print statement uses the STDERR file handle, which causes print's output to go to standard error. The first print statement prompts the user to enter something. The string that this statement outputs is terminated with a SPACE, so the user can enter information on the same line as the prompt. The second line then uses a magic file handle to read one line from standard input, which assigns to $. Because of the magic file handle, if you call file1.pl with an argument that is a filename, it reads one line from that file instead of standard input. The command line that runs file1.pl uses 2> (see "File descriptors" on page 297) to redirect standard error (the output of the third print statement) to the file1.err file.

```
$ file1.pl
print STDOUT "Enter something: ";
$userline = <STDIN>;
print "1>>$userline<<"
chomp($userline);
print "2>>$userline<<"
print STDERR "3. Error message.\n\n";
```

```
$ file1.pl 2> file1.err
Enter something: hi there
<<<
1>>>hi there<<<
2>>>hi there<<>
```

```
$ file1.err
3. Error message.
```

The two print statements following the user input in file1.pl display the value of $userline immediately preceded by greater signs (>) and by less than signs (<). The first of these statements demonstrates that $userline includes a NEWLINE. The less than signs removes the string entered after on the line following the string. The chomp function removes a trailing NEWLINE, if it exists, from a string. After chomp processes $userline, the print statement shows that $userline no longer contains a NEWLINE. (The chomp function is similar to chomp, except it removes any trailing character from a string)

The next example shows how to read from a file. It uses an open statement to assign the lexical file handle Simple to the file /usr/share/dict/words. Each iteration of the while structure evaluates an expression that reads a line from the file represented by Simple and assigns the line to $. When while reaches the end of file

This program copies /usr/share/dict/words to standard output. A pipe (l; page 170) is then used to send the output through head (page 166), which displays the first four lines of the file (the first line is blank).

```
$ cat file2.pl
open (my $infile, "/usr/share/dict/words") or die "Cannot open dictionary: $!\n";
while ($line = $infile) {
    print $line;
}
```

## $ perl file2.pl | head -4

- * A
- * A's
- * AOL

> The $! variable holds the last system error. In a numeric context, it holds the system error number; in a string context, it holds the system error string. If the words file is not present on the system, file2.pl displays the following message:

> Cannot open dictionary: No file or directory

> If you do not read permission for the file, the program displays the message:

> Cannot open dictionary: Permission denied

Displaying the value of $ gives the user more information about what went wrong than simply saying that the program could not open the file.

## Always check for error when opening a file

When a Perl program attempts to open a file, the program does not display an error unless open returns an error. In file2.pl, the operator in the open statement causes Perl to execute die (page 1059) if open fails. The die statement sends the message Cannot open the dictionary followed by the system error to standard error and terminates the program.

@ARGV The @ARGV array holds the arguments from the command line Perl was called with. When you call the program with a list of filenames, it displays the first line of each file. If the program cannot read a file, die (page 1059) sends an error message to standard error and quits. The foreach structure loops through the command-line arguments, as represented by @ARGV, assigning each argument to Filename. The foreach block starts with an open statement. Perl executes the statement preceding the or operator (or) or, if, Perl executes the statement following the or operator (die). The result is that either opens the file named by Filename and assigns IN as its handle, or if it cannot open that file, executes the die statement and quits. The print statement displays the name of the file followed by a colon and the first line of the file. When it accepts Sline = <IN> as an argument to print, Perl displays the value of Sline following the assignment. After reading a line from a file, the program closes the file.

```
$ cat file3.pl
foreach $filename (@ARGV) {
    open(IN, $filename) or die "Cannot open file '$filename': $!\n";
    print "$filename: ";
    $line = <IN>;
    close(IN);
}
$ perl file3.pl f1 f2 f3 f4
f1: 
f2: 
f3: 
f4:
```
