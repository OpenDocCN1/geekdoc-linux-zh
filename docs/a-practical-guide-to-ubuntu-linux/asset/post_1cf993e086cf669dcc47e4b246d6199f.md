
## swat: CONFIGURES A SAMBA SERVER

## Make a copy of /etc/samba/smb.conf

As installed, the /etc/samba/smb.conf contains extensive comments (page 207). The swat utility overwrites it, removing the comments. Make a copy of smb.conf for safekeeping before you run swat for the first time.

The `swat` (Samba Web Administration Tool, swat package) utility is a browser-based graphical editor for the /etc/samba/smb.conf file. For each of the configurable parameters, it provides Help links, default values, and a text box to change the value. The swat utility is a well-designed tool that it remains true to the lines in the smb.conf file you edit: You can use and learn from swat, so that, if you want to use a text editor to modify smb.conf, the translation will be straightforward.

The swat utility is in inetd when you install the swat package, which installs opensamba-inetd as a dependency and follows the policies in line with /etc/inetd.conf.

```
swat stream tcp nowait.400 root /usr/sbin/tcpd /usr/sbin/swat
```

This line enables when swat is running. If necessary, use the following command to restart inetd so that it reloads its configuration:

```bash
$ sudo service opensbd-inet restart superserver inetd
```

## SETTING UP A SAMBA SERVER 805

Now you should be able to run swat: From the local system, open a browser and enter either http://127.0.0.1:901 or http://localhost:901 in the location bar. When prompted, enter the *root* username and the *root* password. (You must use a *root* password to swat to change the Samba configuration; see page 431 for instructions.) If you use a username other than *root*, you will be able to view some configuration information but will not be able to make changes. From a remote system, replace `127.0.0.1` with the IP address of the server (but see the adjacent security tip). If a firewall is running on the local system and you want to access *swat* from a remote system, use TCP port 901 using gufw (page 876).

## Do not allow unencrypted access to swat

Do not allow access to swat from a remote system on an insecure network. When you do so log in, the *root* password is sent in cleartext over whatever connection you are and can easily be sniffed. If you want to access swat over an insecure network, use ssh to forward port 901 (page 681).

## 857 If you can no longer swat

If you can no longer swat, you probably changed the hosts allow incorrectly. In this case you need to edit /etc/samba/smb.conf manually and fix the line with:

```bash
$ grep hosts smb.conf
hosts allow = 127.0.0.1, 192.168.0.8
hosts deny = ALL
```

The preceding entries allow 192.168.0.8 only. They also allow swat to work. You do not need to restart Samba after changing smb.conf.
