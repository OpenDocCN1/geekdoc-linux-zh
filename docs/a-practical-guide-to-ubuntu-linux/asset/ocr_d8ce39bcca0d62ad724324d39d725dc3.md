# There is a root account, but no root password

tip As installed, Ubuntu locks the root account by not providing a root password. This setup prevents anyone from logging into the root account (except when you run sudo [445]). There is, however, a root account (a user with the username root—look at the first line in /etc/passwd). This account/user owns files (give the command -l) and runs processes (give the command -ef and look at the left column of the output). The root account is critical to the functioning of an Ubuntu system.

The sudo enables you to run a command as though it had been run by a user logged in as root. This book uses the phrase "working with root privileges" to emphasize that, although you are not logged in root, when you use sudo you have the privileges of the root.

Ubuntu encourages the use of sudo. In fact, as shipped, Ubuntu locks the root account (there is no password) so you cannot use the classic techniques. Using sudo rather than the root account for system administration offers many advantages:

+   * When you run sudo, it requests your password—not the root password—so you have to remember only one password.
* The sudo utility logs all commands it executes. This can be useful for retracing your steps if you make a mistake and for system auditing.
* The sudo utility logs the username of a user who issues a sudo command. On systems with more than one administrator, this log tells you which users have issued sudo commands. Without sudo, you would not know which user issued a command while working with root privileges.
* The sudo allows implementation of a finer-grained security than the use of su and the root account. Using sudo, you can enable specific users to execute specific commands—something with the classic root account setup.
* Using sudo makes it harder for a malicious user to gain access to a system. When there is an unlocked root account, a malicious user knows the username of the account she wants to crack before she starts. When the root account is locked, the user has to determine the username and password to break into a system.

Some users question whether sudo is less secure than su. Both rely on passwords, they share the same strengths and weaknesses. However, if the password is compromised, the system is compromised. However, if the password of a user who allowed by sudo to do one task is the entire system may not be at risk. Thus, if used properly, the finer granularity of sudo's permissions structure can make it a more secure tool than su. Also, when sudo is used to invoke a single command, it is less likely that a user will be tempted to keep working with root privileges if the user opens a root shell with.
