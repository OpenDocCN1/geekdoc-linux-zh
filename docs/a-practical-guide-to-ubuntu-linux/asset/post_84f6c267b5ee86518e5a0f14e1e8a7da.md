The $VARIABLE syntax is a special case of the more general syntax ${VARIABLE}, in which the variable name is enclosed by ${}. The braces insulate the variable name from adjacent characters. Braces are necessary when concatenating a variable value with a string:

```
$ PREF=counter
$ WAY=${PREF}clockwise
$ FAKE=${PREF}feit
$ echo SWAY $FAKE

```

# unset: Removes A VARIABLE

Unless you remove a variable, it exists in the shell in which it was created. To remove the value of a variable but not the variable itself, assign a null value to the variable:

You can use the readonly builtin to ensure that the value of a variable cannot be changed. The next example declares the variable person to be readonly. # KEYWORD VARIABLES

Keyword variables are either inherited or initialized by the shell when it starts. You can assign values to variables from the command line or a startup file. Typically you want variables to apply to all subshells you start.

# HOME: Your DIRECTORY

By default your home directory is the working directory when you log in. Your home directory is established when an account is set up; its name is stored in the /etc/passwd file.

```
$ grep sam /etc/passwd
sam:x:301:501:/home/sam:/bin/bash
```

When you log in, the shell inherits the pathname of your home directory and assigns it to the variable HOME. When you use a cd without an argument, cd makes the directory name stored in HOME the working directory:

```
$pwd
/max/laptop
$echo HOME
/home/max
$cd
$pwd
/home/max
```

This example shows the value of the HOME variable and the effect of the cd builtin. When you execute cd without an argument, the pathname of the directory is the same as the value of HOME.

The shell uses the value of HOME to expand pathnames that use the shorthand tilde (~) notation (page 206) to denote a user's home directory. The following example uses echo to display the value of this shortcut and then ls to list the files in Max's laptop directory, which is a subdirectory of home directory:

```
$echo ~/
/home/max
$ls ~laptop
tester count      lineup
```

# PATH: WHERE THE SHELL LOOKS FOR PROGRAMS

When you give an absolute or relative pathname rather than a simple filename as a command, it looks in the specified directory for an executable file. If the file with the pathname you specified does not exist, the shell reports command not found. If the file exists as specified but you do not have execution permission for it, or in the case of a shell script you do not read and execute permission for it, the shell reports Permission denied.

If you give a simple filename as a command, the shell searches through certain directories (your search path) for the program you want to execute. It looks in directories for a file that has the same name as the command and that you have execute permission for (a compiled program) or read and execute permission for (a shell script). The PATH shell variable controls this search.
