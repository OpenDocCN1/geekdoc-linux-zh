SOA Start of Authority Designates the start of a zone. Each zone must have exactly one
SOA record. An authoritative server maintains the SOA record for the zone it is
authoritative for.
All files must have one SOA resource record, which must be the first resource
in the file. The Name field holds the name of the domain at the start of the
zone. The Data field holds the name of the host was created on, the email
address of the person responsible for the zone, and the following information,
which must be enclosed within parentheses if the record does not fit on one line. If
this information is enclosed within parentheses (and it usually is), the opening
phesis must appear on the first physical line of the SOA record:

serial A in the range 1 to 2,147,483,647. A change in this number indicates the
zone has changed. By convention, this field is set to the string yyyymmddann
(year, month, day, change number). Along with the date, the final two digits—that is,
t change-day—should be incremented each time you change the SOA record.

refresh The elapsed time after the primary master server notifies slave (sec-
ondary) servers to refresh the record; and the time of updates between.

retry The time to wait after a refresh fails before trying to refresh again.
expire The elapsed time after the zone is no longer authoritative and the root
nyvers must be queried. The expire applies to slave servers only.

minimum The negative caching (caching 1161) TTL, which is the amount of time that
a nonexistent domain error (NXDOMAIN) can be held in a slave server's cache.
negative caching TTL is the same as a normal TTL except it applies to domains
that do not exist rather than domains that do.

The TTL directive (page 839) defines the zone TTL (the maximum
amount of time days in a slave server's cache). Jointly, the default zone TTL
and the negative TTL encompasses all types of records the server can generate.
If you will be adding domains or modifying existing domains frequently, the
negative TTL to a low number. A short TTL increases traffic for DNS for cli-
ents requesting that do not exist, but allows domains to propagate
quickly, albeit at the expense of increased traffic.
