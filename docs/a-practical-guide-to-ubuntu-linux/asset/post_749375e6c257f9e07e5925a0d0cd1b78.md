/home It is a common strategy to put user home directories on their own filesystem. A filesystem is usually mounted on /home. # Set up partitions to aid in making backups

tip Plan partitions based on data you want to back up and how often you want to back it up. One very large partition can be more difficult to back up than several ones.

/usr Separating the usr partition can be useful if you plan to port /usr to another system and maintain the security that a separate partition can give. Many administrators may use an ext2 filesystem on this partition because the data on it does not change frequently enough to justify the overhead of the ext4 journal. The size of /usr depends on the number of packages installed. On a default system, it is typically 2–4 gigabytes.

/usr/local Both /usr/local and /opt are candidates for separation. If you plan to install many packages in addition to Ubuntu Linux, such as an enterprise system, you may want to keep them on a separate partition. If you install the additional software in the same partition as the users' home directories, it may encroach on the users' disk space. Many sites keep all /usr/local or /opt software on one server; from there, export the software to other systems. If you choose to create a /usr/local or /opt partition, its size should be appropriate to the software you plan to install.

# RAID

RAID (Redundant Array of Inexpensive/Independent Disks) employs two or more hard disks or partitions in combination to improve fault tolerance and/or performance. Applications and utilities see these multiple drives/partitions as a single logical device. RAID, which can be implemented in hardware or software (Ubuntu gives you this), spreads data across multiple disks. Depending on which level you choose, RAID can provide data redundancy to protect data in the case of hardware failure. Although it can improve disk performance by increasing read/write speed, software RAID uses quite a bit of CPU time, which may be a consideration. True hardware RAID requires hardware designed to implement RAID and is not covered in this book (but see “Fake RAID” on the next page).

# RAID does not replace backups

The purposes of RAID are to improve performance and/or minimize downtime in the case of a disk failure. RAID does not replace backups.

Do not use RAID as a replacement for regular backups. If the system experiences a catastrophic failure, RAID is useless. Earthquake, fire, theft, and other disasters may leave the entire system inaccessible (if the hard disks are destroyed or missing). RAID also does not take care of the simple replacing of a file when a user deletes it by accident. In such situations, a backup on removable medium (which has been removed) is the only way you will be able to restore a filesystem.

RAID can be an effective addition to a backup. Ubuntu offers RAID software that you can install when you install an Ubuntu system or as an afterthought. The Linux kernel automatically detects RAID arrays (sets of partitions) at boot time the partition ID is set to 0xfd (raid autodetect).

Software RAID, as implemented in the kernel, is much cheaper than hardware RAID. Not only does this approach avoid the need for specialized RAID disk controllers, but it also works with the less expensive ATA disks as well as SCSI disks.

Ubuntu does not officially support motherboard-based RAID (known as fake RAID) but accepts it through the dmraid driver set. Linux software RAID is always better than fake RAID. See help.ubuntu.com/community/FakeRaidHowto for more information.

The partition editor on the Alternate CD gives you the choice of implementing RAID level 0, 1, or 5. For levels 1 and 5, be sure to put partitions on different drives. That way, if one drive fails, your data will be preserved.

- RAID level 0 (stripping)—Improves performance but offers no redundancy. The storage capacity of the RAID device is equal to that of the member partitions or disks.
- RAID level 1 (mirroring)—Provides redundancy, improving data reliability, and can improve the performance of read-intensive applications. The storage capacity of the RAID device is equal to one of the member partitions or disks.
- RAID level 5 (disk striping with parity)—Provides redundancy and improves performance (most notably, performance). The storage capacity of the RAID device is equal to that of the member partitions or disks, minus one of the partitions or disks (assuming they are all the same).
- RAID level 6 (disk striping with double parity)—Improves upon level 5 RAID by protecting data when two disks fail at once. Level 6 is inefficient with a small number of drives.
- RAID level 10 (mirroring and striping)—A combination of RAID 1 and RAID 0 (also called RAID 1+0). The storage capacity of the RAID device is equal to one-half that of the member partitions or disks.

# LVM: Logical Volume Manager

The Logical Volume Manager (LVM, which this book refers to as LVM) allows you group disk components (partitions, hard disks, or storage device arrays), called physical volumes (PVs), into a storage pool, or virtual disk, called a volume group (VG). See Figure 2-2. You allocate a portion of a VG to create a logical volume.

An LV is similar in function to a traditional disk partition in that you can create a file system on it. It is possible, however, to change and move LV partitions: when you run out of space on a filesystem, you can grow (expand) the LV and its filesystem into empty or new disk space, or can move the filesystem to a larger LV. For example, you can add a hard disk to a system and incorporate it into an LV to expand the capacity of that LV. LVM's disk space manipulation is transparent to users; service is not interrupted.

LVM also eases the burden of storage migration. When you outgrow the PVs or need to upgrade them, LVM can move data to new PVs. To read more about LVM, refer to the resources listed on page 26.
