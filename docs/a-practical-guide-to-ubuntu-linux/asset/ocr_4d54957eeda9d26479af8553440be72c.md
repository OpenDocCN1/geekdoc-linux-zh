# IMPORTANT FILES AND DIRECTORIES

This section details the files most commonly used to administer the system. For more information, to refer to “Standard Directories and Files” on page 213.

lost-found Holds pre-allocated disk blocks that fsck uses to store unlinked files (files that have lost their directory [and therefore filename] information). Having these available ensures that fsck does not have to allocate blocks during recovery, a process that could further damage a corrupted filesystem. See page 512 for more information on fsck.

Ext2, ext3, and ext4 filesystem contains a lost-found directory in the system’s root directory. If, for example, a filesystem is mounted at /home, there will a /home/lost+found directory. These are normally created by mkfs when it writes an ext2/ext3/ext4 filesystem to a partition. Although rarely necessary, you can create a lost-found directory manually using mkls+found.

~bash_profile Contains an individual user's shell initialization script. By default, Ubuntu does not create this file when it adds a user. The shell executes the commands in this file in the same environment as the time a user logs in. [For information on executing a script in this manner, refer to the discussion of [.dot] command on page 296.) The file must be located in a user's home directory. It is not run from terminal emulator windows because you do not log in those windows.

You can use bash_profile to specify a terminal type (for vi, terminal emulators, and other programs), run it to establish the terminal characteristics, set up aliases, and perform other housekeeping functions when a user logs in.

A simple .bash_profile file specifying a vt100 terminal and CONTROL-H as the erase key follows:

```
$ .bash_profile
export TERM=vt100
stty erase '^H'
```

For more information refer to “Startup Files” on page 293.

~bashrc Contains an individual user's interactive, nonlogin shell script. The shell executes the commands in this file in the same environment as the (new) shell each time a user creates a new interactive shell, including when a user opens a terminal emulator window. (For information on executing a script in this manner, refer to the discussion of the [.dot] command on page 296.) The .bashrc script differs from .bash_profile in that it is executed each time a new shell is spawned, just when a user logs in. For more information refer to “Startup Files” on page 293.

/dev Contains files representing pseudodev and physical devices that may be attached to the system. The following list explains the naming conventions for some physical devices:

+   * /dev0—The first floppy disk. The second floppy disk is named /dev/1.
