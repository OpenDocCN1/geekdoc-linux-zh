### Split configuration

Following is the list of configuration variables you can set in update-exim4.conf. Enclose all values within single quotation marks. For Boolean variables, exim4 interprets the null value (specified by '') as false.

- `CFILEMODE='perms'`
  Sets the permissions of config.autogenerated to the octal perms, typically 644.

- `dc_eximconf_configtype='type'`
  Specifies the type of configuration that exim4 will run, where type is one of the following:
  - internet: Sends and receives email locally and remotely. See "JumpStart II" on page 718 for an example.
  - smarthost: Sends and receives email locally and remotely, using a smarthost to relay messages to nonlocal systems. See "JumpStart I" on page 716 for an example.
  - satellite: Sends email remotely, using a smarthost to relay messages; does not receive mail locally.
  - local: Sends and receives local messages only.
  - none: No configuration; exim4 will not work.

- `dc_hide_mailname='bool'`
  Controls whether exim4 displays the local mailbox (from /etc/mailname, page 718) in the headers of email originating on local systems. Set to true (hide) the local name or false to display it. When you set this variable, exim4 uses the value of dc_readheader in headers.

- `dc_local_interfaces='interface-list'`
  The interface-list is a semicolon-separated list of interfaces that exim4 listens on. Set interface-list to the null value ('*') to cause exim4 to listen on all interfaces. Set it to 127.0.0.1 to prevent exim4 from accepting from other systems.

- `dc_local_delivery='lcl-transport'`
  Set lcl-transport to mail_pool to cause exim4 to store email in mbox format; set it to maildir_home for maildir format. See page 720 for more information.

- `dc_mailname_in_oh='bool'`
  Used internally by exim4. Do not change this value.

- `dc_minimaldns='bool'`
  Set bool to true to minimize DNS lookups (useful for dial-up connections) or to false to perform DNS lookups as needed.

- `dc_other_hostnames='bool-list'`
  The host-list is a semicolon-separated list of IP addresses and/or FQDNs the local system accepts (but does not relay) email for; localhost (127.0.0.1) is assumed to be in this list.

- `dc_readhost='hostname'`
  The hostname replaces the local mailname in the headers of email originating on local systems. This setting is effective only if dc_hide_mailname is set to true and dc_exim_configtype is set to smarthost or satellite.

- `dc_relay_domains='bool-list'`
  The host-list is a semicolon-separated list of IP addresses and/or FQDNs the local system accepts mail for, but not deliver to local systems. The local system relays mail to these systems. For example, the local system may be a secondary relay for these systems.

- `dc_relay_nets='bool-list'`
  The host-list is a semicolon-separated list of IP addresses and/or FQDNs of the local systems relay mail for. The local system is a smarthost (page 717) for these systems.

- `dc_smarthost='bool-list'`
  The host-list is a semicolon-separated list of IP addresses (preferred) and/or FQDNs the local system sends email for relaying to nonlocal systems (a smarthost; page 717). See “JumpStart” on page 716 for an example.

- `dc_use_split_config='bool'`
  Controls which files update-exim4.conf uses to generate the configuration file for exim4.conf. See “Split configuration” (page 725) for more information.

## dpkg-reconfigure: CONFIGURES exim4

The dpkg-reconfigure utility reconfigures the installed copy of a software package. It displays a graphical window that can be used from any character-based device, including a terminal emulator. The following command enables you to reconfigure exim4 interactively:

```bash
$ sudo dpkg-reconfigure exim4-config
```

The first window this command displays briefly shows the differences between the split and unset configurations (page 725), where you can find more information on this topic, and asks if you want to set up split configuration. If you choose to set up split configuration, update-exim4.conf merges the data from exim4.localmacros, update-exim4.conf, and all the files in the config.d directory to create config.autogenerated.

## SpamAssassin

### How SpamAssassin Works

The spamc utility is a filter. That is, it reads email from standard input, sends it to spamd for processing, and writes the modified email to standard output. spamd uses several techniques:

- Header analysis: Checks for tricks people use to make it legitimate.
- Text analysis: Checks the body of an email for characteristics of spam.
- Blacklists: Checks lists to see whether the sender is known for sending spam.
- Database: Checks the signature of the message against Vipul's Razor (razor.sourceforge.net), a spam-tracking database.

### Prerequisites

Install the following packages:

- spassassin
- spam
- procmail (needed to run SpamAssassin on a mail server; page 730)

When you install the spassassin package, the dpkg postinst does not start the spamd daemon. Before you start spamd, you must change the value assigned to ENABLED to 1 in /etc/default/spassassin. Typically you do not need to make other changes to this.

```bash
$ cat /etc/default/spassassin
...
# Change to one to enable spamd
ENABLED=1
```

spamassin script After making this change, start the spamd daemon with the following command:

```bash
$ sudo service spassassin start
StartingAssassin Mail Filter Daemon: spamd.
```

After modifying any SpamAssassin configuration files, give the same command, by replacing start with reload, to cause spamd to reread its configuration files.

With spamd running, you can see how spam works by sending it a string:

