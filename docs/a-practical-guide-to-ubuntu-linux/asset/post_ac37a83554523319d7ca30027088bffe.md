
When you create or update DNS information, you can use dig or host to test whether the server works as planned. The most useful part of the output from dig is usually the answer section, which gives the nameserver's reply to your query:

```
$ dig example.com
...
;; ANSWER SECTION:
example.com.      172800  IN  A       192.0.32.10
```

The preceding output shows that the example.com. domain has a single A record that points to 192.0.32.10. The TTL of this record, tells you how long the record can be held in cache, is 172,800 seconds (two days). You can also use dig to query other record types using the -t option followed by the type of record you want to query for (-t works with, host):

```
$ -t MX ubuntu.com
...
;; ANSWER SECTION:
ubuntu.com.      3587  IN  MX  10 mx.canonical.com.
```

If you query for a domain that does not exist, dig returns the SOA record for the authority section of the highest-level domain in your query that exists:

```
$ dig dominoesnototext.info
```

```
;; AUTHORITY SECTION:
info.             900 IN SOA a0.info.afilias-nst.info. noc.afilias-nst.info. ...
```

Because it tells the last zone that was queried correctly, this information can be useful in tracing faults.

TSIGs If two servers (page 845) fail to communicate, consider that the time is the same on both servers. The TSIG authentication mechanism is dependent on the current time. If the clocks on the two servers are not synchronized, TSIG will fail. Consider setting up NTP (page 1163) on the servers to prevent this problem.

## SETTING UP DIFFERENT TYPES OF DNS SERVERS

This section describes how to set up a fully-functioned nameserver, a slave server, and a split-horizon server.

## A FULL-FUNCTIONED NAMESERVER

Because the IP addresses used in this example are part of the private address space (page 1166), you can copy the example and run the server without affecting global DNS. Also, to prevent contamination of the global DNS, each zone has the notify option set to NO. When you build a nameserver that is integrated with the Internet,

you will want to use IP addresses that are unique to your installation. You may want to change the settings of the notify statements.

named.conf The **named.conf** file in this example limits the IP addresses that named answers queries from sets up logging (next page).

```
$ cat /etc/bind/named.conf
options {
    directory "/etc/bind";
    recursion NO;
    allow-query (127.0.0.1; 192.168.0.0/24);
};
zone "." IN {
    type master;
    file "db.root";
};
zone "0.168.192-in-addr.arpa" IN {
    type master;
    file "named.conf.local";
    notify NO;
};
zone "sam.net" IN {
    type master;
    file "sam.net";
    notify NO;
}
logging{
    channel "misc" {
        file "/var/log/bind/misc.log" versions 4 size 4m;
        print-time YES;
        print-severity YES;
        print-category YES;
    }
    channel "query" {
        file "/var/log/bind/query.log" versions 4 size 4m;
        print-time YES;
        print-severity NO;
        print-category NO;
    }
    category default {
        "misc";
    }
    category queries {
        "query";
    }
}
```

The allow-query statement in the Options clause specifies the IP addresses of systems the server answers queries from. You must include the local system as 127.0.0.1 if it is querying the server. The server is authoritative for the zone sam.net; the zone file for sam.net is /etc/bind/sam.net.

Logging Logging is turned on by the Logging clause. Logging is separate from named messages which goes to syslog. The Logging clause in the preceding example opens two logging channels: one logs information to /var/log/bind/misc.log and one that logs information to /var/log/bind/query.log. When either of these grows to 4 megabytes (size 4m in the file statement), it is renamed appending .1 to its file name and a new log is started. The numbers of these, similarly logs are incremented. Any log would have a larger number than specified by the versions keyword (4 in the example) is removed. See logrotate (page 622) for another way to maintain log files.

The print statements determine whether the time, severity, and category of information are sent to the log: specify as YES or NO. The category determines information is logged to the channel. The queries are sent to the query channel. Refer to the named.conf page for more details.

named.conf The origin for the reverse zone file (named.conf) is 0.168.192.in-addr.arpa (as specified in the Zone clause that refers to this in named.conf). Following the SOA and NS records, the first three PTR records equate address 1 in subnet 0.168.192.in-addr.arpa (192.168.0.1) with names.net., www.net., and ftp.net., respectively. The next three PTR records equate 192.168.0.3 with mark.net., and 192.168.0.4 with mail.net., and 192.168.0.6 with ns.net.

```
$ /etc/bind/named.conf
$TTL 3D ns.net. mgs@com. (
      2010501 : serial
      8H : refresh
      8H : retry
      4W : expire
      1D : minimum

      IN NS ns.net.
      IN PTR gw.net.
      IN PTR www.net.
      IN PTR mark.net.
      IN PTR mail.net.
      IN PTR ns.net.
```

sam.net The zone file for sam.net takes advantage of many BIND features and includes TXT (page 830), CNAME (page 828), and MX (page 828) resource records. When you query for resource records, named returns the TXT record along with the requested. The first of two NS records specify an unqualified name (ns) to BIND appends the zone name (sam.net), yielding a FQDN of ns.net. The second nameserver is specified with FQDN name that BIND does not alter. The MX records specify mail servers in a similar manner and include priority number at the start where numbers indicate preferred servers.

Resource records have a value in the Name field; those without a name inherit from the previous resource record. In a similar manner, the previous resource record may have an inherited name value, and so on. The five resource records following the SOA record inherit the @, or zone name, from the SOA record. These resource records pertain to the zone as a whole. The preceding example, the first TXT record inherits its name from the SOA record; it is the TXT record for the sam.net (give the command -t TXT sam.net to display the TXT record).

Following these five resource records are resource records that pertain to a domain within the zone. For example, the MX resource records that follow the A resource record with the Name field set to mark are resource records for the mark.sam.net domain.
