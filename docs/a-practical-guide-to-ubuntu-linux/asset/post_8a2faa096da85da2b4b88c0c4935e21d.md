
# PUTTING YOUR CONTENT IN PLACE

Place the content you automatically displays Apache in /var/www. As shown previously, Apache automatically displays the file named index.html in this directory. Give the following command to create a page, replacing the default page:

```
$ sudo tee /var/www/index.html
<html><body>This is <my> test page.</p></body></html>
<html><body>This is <my> test page.</p></body></html>
```

## CONTROL

The tee utility (page 254) copies input to the file you give as its argument and to standard output (page 243). Because of this redirection, tee repeats each line you type after you press RETURN. After you create this, refresh the page on the browser (if it is still running) or start it again and point it at the server. The browser should display the page you created.

# CONFIGURING APACHE

This section describes configuration tools you can use to make your job easier. It also tells you where you can find many of the files you need to work with as you set up and modify an Apache server. Most of the configuration files are in the /etc/apache2 hierarchy.

# CONFIGURATION TOOLS

This section describes the utilities that manage some of the files in the /etc/apache2 hierarchy. These utilities are part of the apache22-common package, which is installed as a dependency when you install apache2.

The a2mod (Apache 2 enable module) and a2dismod (Apache 2 disable module) enables and disables an Apache module. The /etc/apache2/mods-available directory holds files that contain LoadModule directives (page 928) and options for modules that are installed on the local system. The /etc/apache2/mods-enabled directory symbolic links into its configuration by using includes (next section). Apache incorporates these links in mods-available. The a2mod utility creates links in the mods-enabled directory from the available directory. It works on files whose basename is its argument.

```
$ sudo -1
# cd /etc/apache2
# ln -s mods-available/userdir*
mods-available/userdir.conf mods-available/userdir.load
# ln -s mods-enabled/userdir*
ls: mods-enabled/userdir: No such file or directory
# a2mod userdir
Enabling module userdir.
Run '/etc/init.d/apache2 restart' to activate new configuration!
# ls mods-enabled/userdir*
mods-enabled/userdir.conf mods-enabled/userdir.load
# exit $
```

The a2dis utility removes the symbolic links that a2enmod creates. You must reload Apache (902) after you give one or more of these changes before they will take effect.

The a2enmod and a2dis utilities simplify Apache administration. Instead of adding or commenting out a LoadModule directive in the httpd.conf or apache2.conf, you can use these programs to enable or disable a module. This setup enables APT or Synaptic, after it installs a package, to call a2enmod via dpkg postscript and then reload Apache so the change is functional until installation.

The a2ensite (Apache 2 site enable) and a2dissite (Apache 2 site disable) utilities enable and disable an Apache virtual host (page 937). These commands similarly described earlier. First design a virtual host file in the /etc/apache2/sites-available directory. Then you call a2ensite with the name of the site as an argument to create a symbolic link in the /etc/apache2/sites-enabled directory. The a2dissite removes the symbolic link, disabling the virtual host.

# INCLUDE DIRECTIVES

Under Ubuntu, the primary configuration file is /etc/apache2/apache2.conf. This file incorporates other files using Include directives (page 927):

```
$ grep '^Include' /etc/apache2/apache2.conf
Include /etc/apache2/mods-enabled/*..load
Include /etc/apache2/mods-enabled/*.conf
Include /etc/apache2/httpd.conf
Include /etc/apache2/ports.conf
Include /etc/apache2/conf.d/
Include /etc/apache2/sites-enabled/
```

apache2.conf Typically, when you configure Apache, you do not make changes to apache2.conf; use Include directives. You can also use the configuration tools described in the previous section. This setup allows updates to Apache to change apache2.conf without affecting the server.

When Apache reads its configuration files, if it finds more than one occurrence of the same directive, in an Include file, it uses the value assigned by the last directive it encounters.

In apache2.conf, the Include directive for the httpd.conf occurs after directives that set up the global environment, which includes various timeouts and limits as shown in Table 26-1. To change any of these directives, copy them to httpd.conf and make the changes. You must change directives that appear after the Include httpd.conf directive in other included files as explained in this section.

The Include directive for /etc/apache2/conf.d (it includes all files in this directory) appears after Include directive for httpd.conf, with only a few lines and the Include directive for /etc/apache2/ports.conf separating them. This directory is a good place to put small configuration snippets, or break out parts of httpd.conf if it is growing too large.

# FILES LAYOUT

This section lists the locations of binaries, scripts, and modules used by Apache:

- /etc/apache2/: Configuration files
- /usr/sbin/apache2: Starts and stops Apache
- /usr/sbin/apachectl: Controls Apache
- /usr/sbin/rotatelogs: Rotates log files
- /etc/apache2/mods-available: Holds files containing LoadModule directives (page 928)
- /etc/apache2/mods-enabled: Holds links to mods-available
- /etc/apache2/apache2.conf: The main configuration file
- /etc/apache2/envvars: Holds variables that modify the environment
- /etc/apache2/ports.conf: Holds the Listen directive (page 910)
- /etc/apache2/sites-available: Holds files containing virtual hosts
- /etc/apache2/sites-enabled: Holds links to sites-available
- /etc/apache2/httpd.conf: Holds local configuration directives
- /etc/apache2/conf.d: Holds configuration files
- /var/log/apache2/access_log: Logs requests made to the server
- /var/log/apache2/error_log: Logs request and runtime server errors
- /var/www/: Default for CGI scripts
- /usr/lib/cgi-bin: Holds CGI scripts (page 942)
- /usr/share/apache2/error: Holds default error documents
- /usr/share/apache2/icons: Holds icons used to display directory entries
