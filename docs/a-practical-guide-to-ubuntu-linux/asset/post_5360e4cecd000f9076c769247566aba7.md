Ubuntu CDs and DVDs hold programs compiled to run on a specific architecture (class of processors, or CPUs). The following list describes each of the architectures Ubuntu is compiled for. ## Should I install 32-bit or 64-bit Ubuntu on a 64-bit-capable processor?

The following information may help you decide whether to install 32-bit or 64-bit Ubuntu on a 64-bit-capable processor.

- EM64T/AMD64 can run either version of Ubuntu equally well.
- 64-bit distribution allows each to address more than 4 gigabytes of RAM. Larger address space is the biggest advantage of a 64-bit distribution. It is typically useful only for certain engineering/scientific computational work when you are running multiple virtual machines.
- A 64-bit processor is not faster than a 32-bit processor in general; most benchmarks show more or less performance. In some cases the performance is better and in some cases worse: there is no clear performance advantage for either type of processor.
- The memory for 64-bit Linux makes twice as big as those in 32-bit Linux. This size difference translates to a more than 5 percent usage increase, depending on the application. If a system is low on RAM, this overhead may make performance worse.
- ASLR (Address Space Layout Randomization) works better with the larger address space provided by 64-bit Ubuntu. ASLR can help improve system security. See en.wikipedia.org/wiki/Address_layout_randomization.
- Some multimedia encoders run 10–30 percent faster after 64-bit Ubuntu.
- Because more people are using 32-bit Linux, bugs in 32-bit Linux tend to be discovered and fixed faster than 64-bit Linux.
- Ubuntu can set up Flash and Java with a single click on 64-bit systems just as it can on 32-bit systems. However, for some applications, such as Skype, you must apply workarounds to run them.
- There is no simple way to go back and forth between 32-bit and 64-bit versions of Ubuntu without reinstalling.
- If you are not sure which distribution to use, install the version of Ubuntu.

## INTERFACES: INSTALLED AND INSTALLED SYSTEM

When you install Ubuntu, you have a choice of interfaces to use while you install it (to work with the installer). You also have a choice of interfaces to work with the installed system. This section describes the two basic interfaces: textual and graphical.

Textual (CLI) A textual interface, also called a command-line interface (CLI) or character-based interface, displays characters and some graphical symbols. It is line oriented; you give instructions using a keyboard only.

Graphical (GUI) A graphical user interface (GUI) typically displays a desktop (such as GNOME) and windows; you can give instructions using a mouse and keyboard. You can run a textual interface within a GUI by opening an emulator window (page 125). A GUI uses more computer resources (CPU time and memory) than a textual interface.

Pseudographical A pseudographical interface is a textual interface that takes advantage of graphical elements on a text-based display device such as a terminal. It may also use color. This interface uses text elements, including simple symbols, to draw boxes that emulate GUI windows and buttons. Pressing the TAB key moves the cursor to the next and pressing the return key selects the element the cursor is on.

A GUI is user-friendly, whereas the textual interface is cold, uses fewer resources, and can work on a text-only terminal or over a text-only connection. Because it is more efficient, a textual interface is useful for older, slower systems and systems with minimal amounts of RAM. Server systems frequently use a textual interface because it allows the system to dedicate more resources to carrying out the job, leaving fewer resources to pleasing the system administrator. Not running a GUI can also improve system security.

Even though it uses a graphical interface, Ubuntu's live installer installs Ubuntu faster than the textual installer. The live installer copies an installed system image to the hard disk and sets up the system, whereas the textual installer uses APT and dpkg to unpack hundreds of packages one by one.

Ubuntu provides a user-friendly graphical installer (ubiquity) as well as an efficient pseudographical installer (debian-installer) that offers more options and gives you greater control over the installation (Figure-2-1). Both interfaces accomplish the same task: They enable you to tell the installer how you want to configure Ubuntu.

## UBUNTU EDITION

Each Ubuntu release disk is called edition. Following is an overview of each disk.

DVD The DVD is a live/install DVD (page 26); you can use it to boot into a live session. You can install Ubuntu from a live session. This DVD is available for PC and 64-bit architecture (page 29), uses the graphical or textual installer, and installs an Ubuntu system.

Desktop The CD is a live/install CD (page 26); you can use it to boot into a live session. You can install Ubuntu from a live session. This CD is available for PC and 64-bit architecture (page 29), uses the graphical installer, and installs a graphical (desktop) Ubuntu system.

Alternate The Alternate Install CD is not a live CD; it is intended for special installations. It presents more advanced installation options than the Desktop CD does. This CD is available for PC and 64-bit architecture (page 29), uses the textual installer, and installs an Ubuntu system.

Server The Server CD is not a live CD; it is intended for installation only. This CD is available for PC, 64-bit PC, and SPARC architectures (page 29). It uses the textual installer and installs an Ubuntu system that displays a textual interface (no desktop).

Minimal Not an official edition, the Minimal CD is small (5–20 megabytes) and provides a quick installation. Because it downloads software packages while it installs the system, you do not have to update the packages immediately after you install the system. The Minimal CD installs only those packages required to install Ubuntu, so installing with this CD results in a minimal system. You can install additional packages once the system is up and running. The Minimal CD uses the textual installer (page 85), which also allows this to be compact.
