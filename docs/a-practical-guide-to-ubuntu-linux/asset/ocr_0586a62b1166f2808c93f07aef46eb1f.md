# REGULAR EXPRESSIONS 1075

The next example uses this syntax to assign the regular expression /a..d/ (including the delimiters) to the variable $re and then uses that as the regular expression:

```
$ perl -le '$re = qr/a..d/; print "true" if ("aged" ~ $re)'ntrue
```

If you want to include the delimiter in a regular expression, you must quote it. In the next example, the default delimiter a /, appears in the regular expression. To keep Perl from interpreting the / in /usr as the end of the regular expression, the / that is part of the regular expression is quoted by preceding it with a backslash (\). See page 1093 for more information on quoting characters in regular expressions.

```
$ perl -le 'print "true" if ("/usr/doc" ~ //usr/)'ntrue
```

Quoting several characters by preceding each with a backslash can make a complex regular expression harder to read. Instead, you can delimit a regular expression using m and a paired set of characters, such as {}, as as the delimiters. In the following example, the caret (^) anchors the regular expression to the beginning of the line (page 1092):

```
$ perl -le 'print "true" if ("/usr/doc" ~ m{/usr/)'ntrue
```

You can use the syntax when assigning a regular expression to a variable:

```
$ perl -le '$Spn = qr{/usr/doc}; print "true" if ("/usr/doc" = $Spn)'ntrue
```

Perl uses the syntax shown in the next example to substitute a string (replacement string) for a matched regular expression. The syntax is the same as found in vim and sed. In the second line of the example, as s before the regular expression instructs Perl to substitute the string between the second and third slices (worst; replace-string) for a match of the regular expression between the first two slices (best). Implicit in this syntax is the notion that the substitution is made in the slash held in the variable on the left of = operator.

```
$ cat rel10a.pl
$Stg = "This is the best!"
$Stg = s/best/worst/$Stg;
print "$$Stg\n";
```

```
$ perl rel10a.pl
This is the worst!
```
