# 858 CHAPTER 24 DNS/BIND: TRACKING DOMAIN NAMES AND ADDRESSES

To make named.conf easier to understand and maintain, zones in different View clauses have the same name but different zone files. Both local and public View in the example zones named zach.net: The public zach.net zone file is public.net and the local one is named local.net.

The Logging clause is described on page 852.

The zone files defining zach.net are similar to those in the previous examples; the public file is a subset of the local one. Following the SOA record in both file is a TXT, two NS, and two MX records. Here are three CNAME resource records that direct queries addressed to www.zach.net, ftp.zach.net, and mail.zach.net to the system named ns.zach.net. The next four resource records specify nameserver and two mail servers for ns.zach.net.

The final four resource records appear in the local zach.net zone and not in the public zone file; they are (A) resource records for local systems. Instead of keeping this information in /etc/hosts on each system, you can keep it on the DNS server, where it can be updated easily. When you use DNS instead of /etc/hosts, you must change the hosts line in /etc/nsswitch.conf (page 475)

```
$ cat local.net
; zach.net local zone file
```
