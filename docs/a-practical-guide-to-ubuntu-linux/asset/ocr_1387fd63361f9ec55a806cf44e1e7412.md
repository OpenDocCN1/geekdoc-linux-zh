# SETTING UP AN NFS SERVER

no_squash Does not change the mapping of users making requests of the NFS server. (all_squash) all_squash option maps requests from all users—just root—on remote systems to appear from the UID 65534, a nonprivileged user on the local system, or as specified by anonuid. This option is useful for controlling access to exported public FTP, now, and other directories.

anouid-un Set the UID and the GID of the anonymous account to un or gn, respectively. NFS anongid=gn uses these accounts when it does not recognize an incoming UID and GID and when it is instructed to do so by root_squash, all_squash.

# Where The System Keeps NFS Mount Information

A server holds lists of directory hierarchies it can export. The list that you as a system administrator works with is /etc/exports. The following discussion assumes that the local server, plum, is exporting these directory hierarchies:

```
$ cat /etc/exports
/home grape(rw,no_subtree_check)
/p16 192.168.0.12(rw,no_subtree_check) jam(rw,no_subtree_check)
```

As explained in more detail on page 791, exports displays the list of exported directory hierarchies:

```
$ exportfs
/home grape
/p16 jam
192.168.0.12
```

The important files and pseudofs that NFS works with are described next.

/var/lib/nfs/stab (export table) On the server, lists the directory hierarchies that are exported (can be mounted, but are not necessarily mounted at the moment) and the options they are exported with:

```
$ cat /var/lib/nfs/stab
/home grape(rw,wdelay,hide,nocrossmnt,secure,root_squash,no_all_s
quash,no_subtree_check,secure_locks,acl,mapping=identity,anouid=65534,
anongid=65534)
/p16 jam(rw,wdelay,hide,nocrossmnt,secure,root_squash,no_all_sua
sh,no_subtree_check,secure_locks,acl,mapping=identity,anouid=65534,ano
/p16 192.168.0.12(rw,wdelay,hide,nocrossmnt,secure,root_squash,
_all_squash,no_subtree_check,secure_locks,acl,mapping=identity,anouid=
65534,anongid=65534)
```

The preceding output shows that grape can mount /home and that jam and 192.168.0.12 can mount /p16. The stab file is initialized from /etc/exports when the system is brought up, read by plum when a client mounts a directory hierarchy, and modified by exportfs (page 791) as the list of exported directory hierarchies changes.
