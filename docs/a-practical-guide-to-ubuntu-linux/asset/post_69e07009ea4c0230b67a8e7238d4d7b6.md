# THE COMMAND LINE

The shell executes a program when you give it a command in response to its prompt. For example, when you give the ls command, the shell executes the utility named ls. You can cause the shell to execute other types of programs—such as shell scripts, application programs, and programs you have written—in the same way. The line that contains the command, including any arguments, is called the command line. This book uses the term command to refer to both the characters you type on the command line and the program that invokes.

# SYNTAX

Command-line syntax dictates the ordering and separation of the elements on a command line. When you press the RETURN key after entering a command, the shell scans the line for proper syntax. The syntax for a basic command line is

```
command [arg1] [arg2] ... [argn] RETURN
```

One or more SPACES must separate elements on the command line. The command is the name of the command, arg1 through argn are arguments, and RETURN is the keystroke that terminates all command lines. The brackets in the command-line syntax indicate that the arguments they enclose are optional. Not all commands require arguments: Some commands do not allow arguments; other commands allow a variable number of arguments; and still others a specific number of arguments. Options, a special kind of argument, are usually preceded by one or two hyphens (also called a dash or minus sign).

# COMMAND NAME

Some Linux commands consist of only the name of the command without any arguments. For example, ls itself lists the contents of the working directory. Commands that require arguments typically give a short error message, called a usage message, when you use them without arguments, with incorrect arguments, or with the wrong number of arguments.

# ARGUMENTS

On the command line each sequence of nonblank characters is called a token or word. An argument is such as a filename, string of text, number, or other object that a command acts on. For example, the argument to a vi or emacs command is the name of the file you want to edit.

The following command line shows cp copying the file named temp to tempcopy:

```
$ cp temp tempcopy
```

Arguments are numbered starting with the command itself, which is argument zero. In this example, cp is argument zero, temp is argument one, and tempcopy is argument two. The cp utility requires at least two arguments on the command line. One is the name of an existing file. Argument two is the name of the file to be created. Here the arguments are not optional; both arguments must be present for the command to work.

# Options

An option is an argument that modifies the effects of a command. You can frequently specify more than one option, modifying the command in several different ways. Options are specific to and interpreted by the program you calls.

By convention options are separate arguments that follow the name of the command and usually precede other arguments, as filenames. Most utilities require you to prefix options with a single hyphen. However, this requirement is specific to the utility and not the shell. GNU program options are frequently preceded by two hyphens. For example, --help generates a (sometimes extensive) usage message.

7-1 first shows the output of an ls command without any options. ls lists the contents of the working directory in alphabetical order, vertically sorted in columns. When the -r (reverse order) causes the ls utility to display the list of files in reverse alphabetical, sorted in columns. The -x option allows ls to display the list of files in horizontally sorted rows.

When you need to use several options, you can generally group multiple single-letter options into one argument that starts with a single hyphen; do not put spaces between them. You cannot combine options that are preceded by two hyphens in this way. Rules for combining options depend on the program you are running. 7-1 shows both the -r and -x options with the ls. Together these options generate a list of files in horizontally sorted columns, in reverse alphabetical. Most utilities allow you to list options in any order; ls -xr produces the same results as ls -rx.

Some utilities have options that require arguments. For example, the gcc utility has a -o option that must be followed by the name you want to give the executable file gcc generates. Typically an argument to an option is separated from its option letter by a SPACE:

```
$ gcc -o prog.c
```
