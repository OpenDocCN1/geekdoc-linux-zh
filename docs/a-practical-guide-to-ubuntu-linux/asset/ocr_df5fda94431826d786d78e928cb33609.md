# finger: DISPLAYS INFORMATION About REMOTE USERS

The finger utility displays information about one or more users on a system. The utility was designed for local use, but when networks became popular, it was obvious that finger should be enhanced to reach out and collect information remotely. in the following examples, finger displays information about all users logged in on the system named bravo:

```
[kudos]$ finger @bravo
[bravo.example.com]
Login Name Tty Idle Login Time Office Office Phone
sam The Great *1 1:35 Oct 22 12:23 (kudos)
max Max Wild 4 Oct 22 12:23 (::)
max Max Wild 5 19 Oct 22 12:23 (::)
zach Branch 7 2:24 Oct 22 8:45 (::)
h1s Helen Simpson 11 Oct 20 12:00 (::)
```

A user's name in front of the @ causes finger to display information from the remote system by the specified user. If the remote system has matches for that name, finger displays the results for all of them:

```
[kudos]$ finger @bravo
[bravo.example.com]
Login Name Tty Idle Login Time Office Office Phone
max Max Wild 4 19 Oct 22 12:23 (kudos)
max Max Wild 5 Oct 22 12:23 (::)
```

The finger utility works by querying a standard network service, the infinger daemon, runs on the system being queried. Although this service is available in the finger package for Ubuntu Linux, some sites choose not to run it to maintain the load on their systems, reduce security risks, or maintain privacy. When you use finger to obtain information about someone at a site, you will see an error message or nothing at all. The infinger daemon determines how much information to share and in what format. As a result, the report displayed for any given system may differ from the preceding examples.

# The in.finger daemon

The finger daemon (in.finger) gives away system account information that can aid a malicious user. Some sites disable finger or randomize user account IDs to make a malicious user's job more difficult. Do not install the package if you do not want to run the finger daemon.

The information for remote finger looks as much as it does when finger runs on the local system, with one difference: Before displaying the results, finger reports the name of the remote system that answered the query (bravo, as shown in brackets in the preceding example). The name of the host that answers your query may be different from the system name you specified on the command line, depending on how the finger service is configured on the remote system. In some cases, several hostnames may be listed if one finger daemon contacts another to retrieve the information.
