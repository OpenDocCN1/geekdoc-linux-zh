Resolver The resolver comprises the routines that are passed to DNS to be mapped to an IP address. The resolver can append several domains, one at a time, to an unqualified domain name, producing several FDNs that it passes, one at a time, to DNS. For each FQDN, DNS reports success (it found the FQDN and is returning the corresponding IP address) or failure (the FQDN does not exist).

The resolver always appends the root domain (.) to an unqualified domain name first, allowing you to type sobell.com instead of sobell.com (including the trailing period) in a browser. You can specify other domains to resolve if the root domain fails. Put the domain names, in the order you want them, and use the search keyword in /etc/resol.conf (page 496). For example, if your search domains include ubuntu.com., then the domains wiki.ubuntu.com, will resolve to the same address.

+   Subdomains Each node in the domain hierarchy is a domain. Each domain has a parent (that is, every domain except the root is a subdomain, regardless of whether it has children). All subdomains can resolve to hosts—even those with children. For example, ubuntu.com resolves to the host that serves the Ubuntu Web site, without preventing its children-domains as wiki.ubuntu.com—from resolving. The leftmost part of an FQDN is called the hostname.

+   Hostnames In the past, hostnames could contain only characters from the a–z, A–Z, 0–9, and . As of March 2004, however, hostnames can include various accents, umlauts, and so on (www.switch.ch/ifn/idn). DNS considers uppercase and lowercase letters to be the same (it is not case sensitive), so sobell.com is the same as WWW.soObell.com.

# ZONES

For administrative purposes, zones are grouped into zones that extend from a domain (Figure 24-3). A single DNS server is responsible for (holds the information required to resolve) all domains within a zone. The DNS server for a zone holds pointers to DNS servers that are responsible for the zones immediately below the zone it is responsible for. Information about zones originates in one file, one per zone.

+   Root domain The highest zone—the one containing the root domain—does not contain any hosts. Instead, this domain delegates to the DNS servers for the top-level domains (Figure 24-1, page 823).

+   Authority Each zone has at least one authoritative DNS server. This server holds all information about the zone. A DNS query returns information about a domain and specifies which DNS server is authoritative for that domain.

DNS employs a hierarchical structure to keep track of names and authority. At the top or root of the structure is the root domain, which employs 13 authoritative nameserver. These are the only servers that are authoritative for the root and top-level domains.
