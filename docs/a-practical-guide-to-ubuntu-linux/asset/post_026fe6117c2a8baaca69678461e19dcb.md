
# CREATING A SECRET KEY

A key is an encoded string of up to 512 bits. The dnssec-keygen utility, which is included with BIND, generates this key. The following command, which may take a while to run, generates a 512-bit random key using MD5, a one-way hash function (page 113):

```
$ /usr/bin/dnssec-keygen -a hmac-md5 -b 512 -n HOST keyname
Kkey.+157+475866
```

In the preceding command, replace keyname with a string that is unique meaningful. This command creates a key in a false name which is similar to the string Keyname.+157+475866.private, where keyname is replaced by the name of the key, +157 indicates the algorithm used, and +475866 is the hash of the key. If you run the same command again, the hash part will be different.

The key file is not used directly. Use cat with an argument of the private filename to display the key and information you will need in the next step:

```
$ cat Keyname.+157+475866.private
Private-format: v1.3
Algorithm: 157 (HMAC_MD5)
Key: uNPdoqWr7fvo/FyjykqKbqcHTd6Prm...
```

# USING THE SECRET KEY

The next step is to tell the nameservers about the secret by inserting the following code in the /etc/named.conf file on both servers. This code is a top-level clause; insert it at the end of the named.conf.local file (which is included in named.conf):

```
key keyname {
    algorithm "hmac-md5"
    secret uNPdoqWr7fvo/FyjykqKbqcHTd6Prm...";
}
```

The keyname is the name of the key you created. The algorithm is the string that follows algorithm in the output of cat, above. The secret is the string that follows secret in the output of cat. You must enclose each string within double quotation marks. Be careful when you copy the key; although it is long, you not break it into multiple lines.

Because key names are unique, you can insert any number of Keys clauses into named.conf. To keep a key secret, make sure users other than bind cannot read it: Either named.conf.local permissions that no one except bind has access to it or put the key in a file that only bind can read and incorporate it in named.conf.local using an include statement.

Once both servers know the key, use a server statement in named.conf.local to tell them when to use it:

# SETTING UP DNS SERVER 847

```
server 1.2.3.4 {
# 1.2.3.4 is the IP address of the other server using this key
keys {
  "keyname"
};
```

Each server must have a Server clause, each containing the IP address of the other server. The servers will now communicate with each other if they first authenticate each other using the secret key.

# RUNNING BIND IN a chroot JAIL

To increase security, you can run BIND in a chroot jail. See page 466 for information about the security advantages of, and how to set up, a chroot jail. The bind-chroot shell script (below), which sets up BIND to run in a chroot jail, creates a directory /var/lib/named that takes the place of the root directory (/) for ALL BIND files. The bind-chroot.sh installs the bind9 and resolveconf packages if they are not already installed and runs the bind9 and resolveconf scripts to start named. It adds the -t option to the options in /etc/default/bind9 so named chroots to the /var/lib/named directory before it reads its configuration files. The daemon is already set up to run as the user bind (-u bind).

After creating the necessary directories in /var/lib/named, the script moves the files from /etc/bind to /var/lib/named, creates a symbolic link from /var/lib/named back to /etc/bind, and creates and sets permissions on devices BIND may need. Next, bind-chroot.sh disables apparmor protection for named. Finally, the script starts named and resolveconf, and displays the end of the syslog file.

```
# cat bind-chroot.sh
!/bin/bash

# install -y stop bind
ptitude -y install bind9
service bind9 stop

# install and stop resolveconf
ptitude -y install resolveconf
service resolveconf stop

# add -t /var/lib/named to OPTIONS in /etc/default/bind9
sed -i 's:OPTIONS=(.*):OPTIONS=\1 -t /var/lib/named": /etc/default/bind9

# make the chroot directories
mkdir -p /var/lib/named/{etc,dev,var/cache/bind,var/run/bind,run}

# move the configuration to the chroot and link back to /etc
mv /etc/bind /var/lib/named/etc
ln -s /var/lib/named/etc /bind

# create devices and set permissions
mkod /var/lib/named/dev/null 1
mkod /var/lib/named/dev/random 1
chmod 666 /var/lib/named/dev/{null,random}
chown -R bind:bind /var/lib/named/*
chown -R bind:bind /var/lib/named/etc

#

# disable apparmor protection for /usr/sbin/named and restart
cd /etc/apparmor.d/disable
ln -s /etc/apparmor.d/usr.sbin/named
apparmor restart

# start resolveconf
service resolveconf start
service bind9 start

# check that everything started
tail /var/log/syslog
```
