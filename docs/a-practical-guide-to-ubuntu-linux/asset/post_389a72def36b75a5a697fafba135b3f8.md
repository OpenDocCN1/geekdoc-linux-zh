## INSTALLING Non-dpkg Software

Most software that is not in dpkg format comes with detailed instructions on how to configure, build (if necessary), and install it. Some binary distributions (those containing prebuilt executables) require you to unpack the software from the root directory.

## The /opt AND and /usr/local DIRECTORIES

Some application packages includes scripts to install themselves automatically into a directory hierarchy under /opt, with files in a /opt subdirectory is named after the package and executables in /opt/bin or /opt/package/bin.

Other packages allow you to choose where you unpack them. Because many different people develop software for Linux, there is no consistent method for installing it. As you acquire software, install it on the local system as consistent predictable manner as possible. The standard Linux file structure has a hierarchy under /usr/local for binaries (/usr/local/bin), manual pages (/usr/local/main), and so forth. Many GNU buildtools search the /usr/local hierarchy by default and find the wrong version of a utility if you install developer tools, putting these tools in /opt is a good idea.

To prevent confusion later and avoid overwriting or losing the software when you install standard software upgrades, installing nonstandard software in standard system directories like /usr/bin. On a multiuser system, make sure users know where to find the local software and advise them whenever you install, change, or remove local tools.

## GNU CONFIGURE AND BUILD SYSTEM

The Configure and Build System makes it easy to build a program that is distributed as source code (see www.gnu.org/software/autoconf). This process requires requires a shell, make, and gcc (the GNU C compiler). You do not need to work with root privileges to install the program.

The following example assumes you have downloaded the GNU program (ftp.gnu.org/pub/gnu/which; page 178) to the working directory. First unpack and decompress the file and cd to the new directory:

```
$ tar -xvzf which-2.20.tar.gz
which-2.20/
which-2.20/EXAMPLES
which-2.20/posixstat.h
which-2.20/configure.ac
which-2.20/COPYING

cd which-2.20
```

After reading the README and INSTALL files, run the configure script, which gathers information about the local system and generates the Makefile:

```
$ ./configure

## wget: DOWNLOADS FILES NONINTERACTIVE

### wget: DOWNLOADS FILES INTERACTIVE

The wget utility is a noninteractive, command-line utility that retrieves files from the Web using HTTP, HTTPS, or FTP. In the example on the next page, wget downloads the home page, named index.html, to the working directory.

```
$ wget http://www.ubuntu.com
Resolving www.ubuntu.com...
Connecting to www.ubuntu.com...
HTTP request sent, awaiting response... 200 OK
Length: 17903 (17K) [text/html]
Saving to 'index.html'
```
100%[====================> 17.9K/s   in 0.2s
```

With the --recursive (-r) option, wget downloads the directory hierarchy under the URI you provide. Be careful with this option it can download a lot of data (which may completely fill the partition you are working). The --background (-b) option runs wget in the background and redirects its standard error to a file named wget-log:

```
$ wget --recursive --background http://www.ubuntu.com
Continuing in background, pid 28839.
Output will be written to 'wget-log'.
```

The utility does not overwrite log files. When wget-log exists, wget writes sequences to wget-log.1, wget-log.2, and so on.

Running wget is useful when you need to download a large file to a remote system. You can start running from an ssh (page 670) session and then disconnect, allowing the download to complete without any interaction.

The wget --continue (-c) option continues an interrupted download. For example, if you decide to stop a download you can run it in the background, you can continue it from where it left off with this option.

The AND operator (&&) allows the execution of a subsequent command only if the previous step returned a successful exit status:

```
$ sudo ./configure && make
```
