# Running the ssh, scp, and sftp OpenSSH Clients

HashKnownHosts (page 65) is set to yes (the default), OpenSSH hashes the system name and address for security. Because it hostname and IP address separately, OpenSSH puts lines in known_hosts for each host. The following lines (which are two logical lines, each of which wraps on several physical lines) from known_hosts are used to connect to a remote system using RSA (page 1170) encryption:

```
### cat -~/ssh/known_hosts
|Pr1VuXqFVVnnLrykm1bByCnnXaC=|TVRAwaqi15E2jguFR5s3f1AR8= ssh-rsa
AAAAB3NlaCyc2EAAAABiWAAQEA7egm4a00j5/JGult3j5CFcRc38/RAUIxkZDaqj5fe
```

```
|P1Nm89U0e7sGT2CIUCIT8yqsc=|Ldm5/7K6v8d451219mw29jqb8= ssh-rsa
AAAAB3NlaCyc2EAAAABiWAAQEA7egm4a00j5/JGult3j5CFcRc38/RAUIxkZDaqj5fe
```

You can use ssh with the - option to remove a hostname from the hashed entry. The -F option to ssh-keygen displays a line in a known_hosts file that corresponds to a specified system, if the entry is hashed:

```
### ssh-keygen -F plum
# Host plum found: line 1 RSA
|Pr1VuXqFVVnnLrykm1bByCnnXaC=|TVRAwaqi15E2jguFR5s3f1AR8= ssh-rsa
AAAAB3NlaCyc2EAAAABiWAAQEA7egm4a00j5/JGult3j5CFcRc38/RAUIxkZDaqj5fe
```

OpenSSH stores keys from servers it has connected to in user-private files (./ssh/known_hosts). These files work only for the user whose directory they appear in. With root privileges and using a text editor, you can copy lines from a user's private list of known hosts to the public list in /etc/ssh/known_hosts to make a server known globally on the local system.

The following example shows how Sam, with administrative privileges, the hashed entry from his known_hosts file into the global ssh_known_hosts file. First, as himself, Sam sends the output of ssh-keygen through tail to strip the Host found line and redirects the output to a file named tmp_known_hosts. Next, with root privileges, Sam appends the content of the file he just created. This command creates the file if it does not exist. Finally, Sam removes the temporary file he created and returns to himself.

```
sam@:$ ssh-keygen -F plum | tail -1 > tmp_known_hosts
sam@:$ sudo -i
root@:~# cat -sam/tmp_known_hosts >> /etc/ssh/ssh_known_hosts
root@:~# exit
sam@:$ rm -sam/tmp_known_hosts
```

Because the output from cat is redirected, Sam creates a shell with root privileges (sudo -i) to execute the command. See page 424 for a discussion of redirecting output of a command run under sudo.
