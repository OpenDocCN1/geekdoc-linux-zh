## 内存/内核/用户空间

如果你来自 Windows 或 Mac OS X，你会发现 Linux 内存范围被分为内核空间、用户空间和一个不可访问区域。请注意，内核显示为红色，用户空间显示为蓝色。运行在内核空间的代码比运行在用户空间的代码权限更高。然而，用户空间无法访问内核空间。这种抽象允许我们在分析转储时无需考虑它在物理内存中是如何组织的。当我们查看进程转储时，我们只关心虚拟空间¹。在 Debian 系统上，如 /proc/sys/vm/mmap_min_addr 所示。

## 应用/进程/库

当一个应用加载时，其所有引用的库都会映射到虚拟内存空间。同一个文件的不同部分（如代码和数据）可能会被映射到内存的不同部分。相比之下，Windows 中的模块在虚拟内存空间中按顺序组织。然后设置一个进程进行运行，并为其分配进程 ID（PID）。如果你运行另一个这样的应用，它将具有不同的虚拟内存空间。

## 进程内存转储

当我们保存进程核心内存转储时，进程空间的用户空间部分会被保存，而不包含内核空间的内容。然而，除非发生内存泄漏，否则我们永远看不到如此大的核心转储。这是因为进程空间有未被代码和数据填充的间隙。这些未分配部分不会保存在核心转储中。但如果某些部分被交换到磁盘并存在于分页，通常会在保存核心转储之前将它们换回。

## 内核内存转储

在发生内核恐慌（kernel panic）时，如果配置了相应的机制，将保存内核内存转储（对于最近的发行版如 Ubuntu，通常默认开启）。然而，运行进程的虚拟内存不会被保存。对此，你需要各种物理内存获取方法和工具，而这些超出了本课程的范围。





缺乏完整内存转储的问题，可以通过转储单个进程，然后强制进行内核内存转储并进行分析来解决。我们将这种生成的转储类型称为 Fiber Bindle。

## 轻量级进程（线程）

现在，我们来看 Linux 核心转储分析中的另一个重要基础概念：线程或轻量级进程（LWP）。它基本上是一个执行单元，一个给定的进程可以拥有许多线程（LWP）（它们都共享同一个进程空间）。每个线程执行某些代码并执行各种任务。每个线程都有自己的 ID（LWP ID）。在本次培训中，我们还将学习如何在进程线程之间切换。请注意，线程通过 *libc* 动态库进入内核空间，类似于 Windows 上的 *ntdll* 和 Mac OS X 上的 *libsystem_kernel*。主线程之外的线程（POSIX 线程）源自 *libc* 和 *libthread* 动态库，类似于 Mac OS X 上的 *libsystem_c*。
