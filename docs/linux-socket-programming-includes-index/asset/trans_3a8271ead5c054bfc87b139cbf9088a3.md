在UDP连接上，`connect()` 系统调用仅仅记录了你发送消息的目标地址。你可以像使用TCP连接那样使用`read()`和`write()`，但你不具备可靠性和有序性的保证。列表4.1中展示的算法与TCP编程非常相似。

## 列表 4.1 简单的已连接数据报

```c
/**** Sample datagram example with connection ****/
/**** Excerpt from connected_peer.c ****/

int sd;
struct sockaddr_in addr;
sd = socket( PF_INET, SOCK_DGRAM, 0);  /* datagram socket */
bzero( &addr, sizeof( addr ) );
addr. sin_family = AF_INET;
addr. sin_port = htons( DEST_PORT );
inet_aton( DEST_IPADDR, &addr. sin_addr );
if ( connect( sd, &addr, sizeof( addr) ) == 0 )  /* connect! */
    perror("connect");

/**** Note: this is not a streamed send--- */
send( sd, buffer, msg_len);  /* send like TCP */
```

通常，在使用UDP时，你使用`sendto()`或`recvfrom()`系统调用（本章稍后会详细介绍）。`send()`系统调用假设程序已经通过`connect()`注册了目标地址。

等待连接的对等方（或服务器）可以使用相同的连接接口，也可以使用`sendto()`和`recvfrom()`。但是，为了使程序能够连接到对等方，对等方必须通过`bind()`系统调用来公布其端口号。关于`bind()`系统调用的完整描述，请参阅本章稍后的“发送直接消息”部分。

列表4.1中的示例代码片段引用了`DEST_PORT`。这个数字是两个程序之间约定的端口接口。监听的对等方通过调用`bind()`请求`DEST_PORT`来设置该端口。当你的消息到达时，目的地本身可能会发出一个`connect()`系统调用。

与TCP的`connect()`系统调用不同，你的程序可以在不关闭套接字的情况下，重新连接到其他对等方或服务器。对于TCP，除非你关闭并重新打开套接字，否则不能连接到其他对等方或服务器。UDP提供的一个最重要特性是能够在不关闭套接字的情况下向不同的目标发送消息。使用UDP协议的`connect()`系统调用仍然为你提供这种灵活性。再次强调，如果你以任何形式使用UDP，你就选择了随之而来的不可靠性。你可能会丢失数据包，或者数据包可能乱序到达。UDP的`connect()`系统调用仅记录目标地址，并不会增加两个程序之间通道的可靠性。

## 可靠投递消息 (RDM)

可靠投递消息（RDM）协议 [RFC908,RFC1151] 提供了TCP所保证的投递服务，同时也允许你拥有基于消息（非流式）的UDP速度。RDM仍然可能导致消息乱序，但它在UDP和TCP之间提供了一个良好的折衷方案。不幸的是，尽管该协议已在官方记录中存在多年，但Linux（以及其他UNIX操作系统）目前尚未支持它。

## 示例：连接HTTP守护进程

用户连接的最常见协议是HTTP。它描述了一个非常简单的接口，包含查询。服务器随后解释查询，并回复客户端能够理解的消息。该消息可以是简单电子邮件头格式内的任何文档。

接口的简单性向你展示了网络上的许多事务。大多数客户端-服务器交互都是基于单事务的。TCP接口和可靠性检查的所有开销在单事务上可能是浪费的。尽管如此，这仍是被接受的标准。

## 简化的HTTP协议

要向HTTP服务器发送请求，你只需要知道一条命令。这是HTTP协议的一种过度简化的表示。第6章“服务器入门”将更详细地介绍该协议：

```
GET <query> HTTP/1.0<cr><cr>
```

查询通常看起来像目录路径，但它可以接受参数和变量。当你在浏览器中输入URL `http://www.kernel.org/mirrors/` 时，你的浏览器会打开一个到`www.kernel.org`的套接字，并发送以下消息：

```
GET /mirrors/ HTTP/1.0<cr><cr>
```

它还可能发送许多关于它可以接收何种类型的数据的其他信息。这有助于数据转换。最后两个`<cr><p>`是换行符，表示消息的结束。客户端可以发送任意数量的参数和设置，但它必须以两个换行符结束消息。

连接是流式的，因此你不知道是否已经到达消息的末尾。这可能会导致无限期地等待一个永远不会到达的东西。这两个换行符告知服务器客户端已停止说话。

## 获取HTTP页面

构建查询是连接中最容易的部分。查询也给了你很多灵活性，让你添加所需的内容。唯一的要求是确保服务器能够理解你的消息。列表4.2展示了获取网页的一种方法。此程序打开命令行指定的连接，并发送HTTP请求。程序在stdout上打印结果。

### 列表 4.2 从HTTP服务器获取网页

```c
/****...
 * Excerpt from the http-client.c (on Web site) file. **/
int sd;
struct servent *servv;
if ( (servv = getservbyname("http", "tcp")) == NULL )
    PANIC("HTTP servent");
if ( ( sd = socket(AF_INET, SOCK_STREAM, 0) ) < 0 )
    PANIC("Socket");

/*---Initialize server address/port struct----*/
bzero(&dest, sizeof(dest));
dest.sin_family = AF_INET;
dest.sin_port = servv->s_port;        /* HTTP Server */
if ( inet_addr(Strings[1], &dest.sin_addr.s_addr) == 0 )
    PANIC(Strings[1]);

/*---Connect to server----*/
if ( ( connect(sd, &dest, sizeof(dest)) != 0 )
    PANIC("Connect");

/*---Compose the query and send it-----*/
sprintf(buffer, "GET %s HTTP/1.0\n\n", Strings[2]);
send(sd, buffer, strlen(buffer), 0);

/*---While there's data, read and print it---*/
do
{ bytes_read = recv(sd, buffer, sizeof(buffer)-1, 0); buffer[bytes] = 0; if ( bytes_read > 0 ) printf("%s", buffer); } while ( bytes_read > 0 );
```

列表4.2中的程序打开连接，发送命令行请求，并显示它接收到的所有内容，直到服务器关闭连接。HTTP协议的后续版本（1.1和建议中的HTTP-NG）包括保持通道开放的能力，利用TCP连接。再次强调，此功能凸显了告诉接收方发送方何时停止说话的需求。你可以在www.w3c.org找到的RFC中阅读更多关于新版HTTP的信息。

## 什么是无连接套接字？

并非所有通信都需要在对等方之间保持完全双向通道开放。如果电话是流式连接的例子，那么邮政系统最能代表基于消息（或无连接）的系统。就像邮政系统一样，UDP组合消息，分配目的地，并在消息传输到目的地的过程中不进行任何跟踪就将其发出去。（再次强调：数据报的不可靠性意味着它不提供任何投递保证。这并不意味着它不起作用。）

## 设置套接字的地址

完整的Linux发行版安装通常包含允许你与网络上其他工作站发送和接收便条的工具。这些工具只需要机器地址，有时还需要用户名。你可以使用UDP套接字自己实现这种类型的工具。为此，你需要检查当前用户是否是消息的接收者。

这些基于信使的工具使用两个数据片段（主机名和用户名）来唯一地识别接收者。该工具没有流式数据，因此你的实现可以使用无连接接口。

无连接接口不使用`connect()`系统调用，但你不能在没有连接的情况下调用`send()`或`recv()`。相反，操作系统提供了两个较低级别的系统调用，其中包含目标地址：`recvfrom()`和`sendto()`。这些调用类似于`recv()`和`send()`，但你必须将目标地址作为调用的一部分提供：

```c
#include <sys/socket.h> #include <resolv.h>
```
