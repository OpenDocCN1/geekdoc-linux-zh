# Samba service running?

First, try the smbclient from your Linux system to check that everything is running and being shared as you expect it to be. The smbclient command is a great tool for getting information about a Samba server and even accessing shared directories from both Linux and Windows computers. While logged in as root or any user that has access to your Samba server, type the following:

```
$ smbclient -L localhost
Password: ***********
added interface ip=10.0.0.10 bcast=10.0.0.255 nmask=255.255.255.0
Domain=[ESTREET] OS=[Unix] Server=[Samba 2.2.8a]

Sharename   Type   Comment
---------   ----   -------
homes       Disk   Home Directories
IPC$        TPC    IPC Service (Samba Server)
ADMIN$      Disk   IPC Service (Samba Server)
hp-ns1      Printer

Server       Comment
----------   --------
  PINE       Samba Server
  MAPLE      Windows XP
  NS1        Samba Server

Workgroup    Master
----------   -------
  ESTREET    PINE
```

This shows that the Samba server is running on the local computer. Shared directories and printers, as well as servers in the workgroup, appear here. If the Samba server is not running, you will see "Connection refused" messages. You need to start the Samba service as described in the "Starting the Samba service" section.

# Firewall open?

If the Samba server is running, it should begin broadcasting its availability on your LAN. If you try to access the server from a Windows or Linux client on your LAN, but are told "Connection refused," the problem may be that the firewall on your Red Hat Linux Samba server is denying access to the NetBIOS service. If you have a secure LAN, you can type the following (as root user) to flush your firewall rules for the moment:

```
# iptables -F
```
