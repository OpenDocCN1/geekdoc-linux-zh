# ## Open LDAP

I'm having problems with GSSAPI and LDAP. From the information available, I have narrowed the problem down to somewhere in the `acquire_cred1` or `gss_krb5_canonicalize_name` functions located in the GSSAPI module.

What I really need is to understand how the minor_status parameter got set, as that may tell me specifically where my issue lies. However, using strace on the `ldapwhoami` command only shows what the client is doing, and the problem is on the server side. The slapd service has got full log levels on, but it doesn't give me enough information, as it seems the problem is in GSSAPI, not slapd.

I have tried running slapd with strace, however, I can't seem to do so in such a manner that the slapd service runs as it would when invoked through the service slapd start line. Using strace seems to then cause all LDAP* commands to completely fail to find the LDAP service.

I don't even know if a strace on slapd would capture the information that I'm after. How can I capture the information in the GSSAPI module? Thanks!

Phil Coping

> The problem sounds like an issue with openldap, not GSSAPI – mainly that it doesn't have permission to access the files. This can be fixed though. First check the service is running as normal. Then do:

```
sudo pidof slapd
```

> This will give you the pid number, so then you need to run:

```
sudo strace -o /tmp/dumps/lapd.log -f -s 1024 -p <insert pid>
```

> Then open another terminal window and carry out your test in that. Once you've finished testing, hit Ctrl+C in the one where strace is running.

# ## Bookmarks

Most of my bookmarks are organised (albeit haphazardly) in folders according to the subject – there are a handful that live by themselves because they are so commonly used, and a much larger handful that have not yet been sorted or erased.

Yesterday I was started to see that one of the folders had vanished (ironically, the folder named Linux). I didn't think I could have erased it by error, but couldn't think of another answer and decided to recreate the list.

I was then surprised again when bookmarking LinuxUser.co.uk (for example), as it offered to edit the existing bookmark, claiming that it still existed in a folder named Linux. The same thing happened with each of the other bookmarks I attempted to replace.

This is hardly the end of the world – I have my bookmarks backed up and can simply start over if necessary. But I would like to know if that folder is retrievable and what went wrong in the first place.

Tsu J

> Hi Tsu. The usual reason that this happens is if you've done something silly by accident, such as dragging the Linux folder into another one. Accept the option to edit the bookmark and then try and restore the folder to its usual place. That should fix everything!
