## Tails 1.3

Privacy made better as the Tails team improves and upgrades their eponymous secure distribution.

Over the past year, Tails has been going from strength to strength, completing important updates to make it a complete product. Version 1.1 in particular has updated the codebase and some of the camouflage features to make it more accessible and give it a longer lifespan.

Since then, a lot of the updates seem to revolve around usability. Not just in the terms of workflow and privacy, but also making private ways of performing day-to-day activities easier. There have been bug fixes and package updates along the way and while they’re important from a security perspective, the ability to let people be private when they need to be and not hold them back from their life is the entire point of Tails to begin with.

Tails 1.3 is similar in this regard. On launch, you’ll get the same excellent set of default options that immediately connects you to Tor, enabling secure browsing. You can also set the root passwords and activate the Windows 8 camouflage, along with advanced MAC spoofing and other proxy settings before you even load into the desktop.

The desktop itself is more or less the same, although it has cut down on the notifications about what’s being set up, for ones letting you know what is ready. For most this is fine and we found the others fly past too fast to need to be mentioned. The new additions are mainly the Bitcoin wallet Electrum that lets you transfer money with minimal setup for accessing your wallet, and Keyringer where you can send ‘secrets’ via text documents in PGP mail and Git. Both work well and perfectly with Tails, although as the docs like to point out, while Electrum makes it easier to transfer Bitcoin it is still very traceable.

While they are the big new things, there are small privacy and security increases that make the experience better. Our only small gripe is that installation is a bit odd, but that can be worked on in the future.

Rob Zwaatsloot

### Summary

While it’s only minor improvements and additions, it’s still a very secure and private distro. It is now easier to be on the Internet and remain private using Tails, thanks to Electrum and Keyringer bringing a better way to pay for things and securely transmit messages.

#### FAQ: Codec licenses

**Q: What codecs are truly free on Linux?**
A: For audio you have your choice of FLAC, Vorbis and Theora as the more popular ones - the latter two you will usually find in an Ogg container, which in itself is also open. Ogg and Theora can also be used in video, along with the Matroska (mkv) container. WebM is also open but it is usually used on browsers as sort of a modern replacement for animated gifs.

**Q: So why am I able to play MP3, MP4, AVI, etc on Linux?**
A: A lot of Linux codec packs and streamers and such use non-free codecs in order to play some of these popular file types. The legality of them varies depending on the codec pack used, but usually some distros that consider themselves as truly free, like Fedora for example, do not include them at all.

**Q: Can I still get them on Fedora and other free distros?**
A: You, usually there is a workaround, such as installing the RPM Fusion software sources in Fedora, for example. You will need to do a Google search and find out what you need to do to add them to other distros. Speaking of installing RPM Fusion, check out our first question for advice on getting it up and running.

One thing that's bugging me though is that, although I am a fan of the completely free repos, it would be nice if I could get easier access to some ways to play my MP3 collection or watch videos a bit easier. Are there binaries I can grab for this or will I have to start compiling the software from source? I don't fancy the latter so much as I always seem to miss something with media software while compiling.

Hope you have an answer!

Pete Chan

We absolutely have a solution for you and it involves setting up the RPM Fusion repository in Fedora. This is an extra repository full of non-free software, and other free software, and it sets itself up pretty easily via a graphical binary method that you can access via the website here: rpmfusion.org/Configuration.

Otherwise, you can do it in the terminal in one command that adds the repos and configures them to be used with the original ones as well:

```bash
$ su -c 'yum localinstall --nogpgcheck http://download1.rpmfusion.org/free/fedora/rpmfusion-free-release-$(rpm -E %fedora).noarch.rpm http://download1.rpmfusion.org/nonfree/fedora/rpmfusion-nonfree-release-$(rpm -E %fedora).noarch.rpm'
```

Shrinking unallocated space seems very weird - there's nothing to shrink so you'd be expanding into it, that's usually how it works. If it's freezing and rebooting then there's going to be a corruption on the hard drive somewhere. **Usually this happens when you've shrunk some space and accidentally deleted part or all of an important file.**

Your best bet is to try and save all the data from this hard drive on an external device using an external drive and then installing the updated Fedora after you suggested. Try not to use LVMs or Extended partitions though, as these can be difficult to resize if you need to do so in the future.
