The books and the knowledge within them, and so held the levers of power. What makes the information in our age different is that, unlike the static media of the past, it is interactive. There is no effort necessary in making a copy. The Web is a universal library, an unparalleled repository for information, accurate and inaccurate, about everything and anything, that can be accessed instantly and at will, an encyclopedia at our fingertips. But if the Web is to fulfill this role, the issues of copyright and the ownership of ideas have to be tackled in a way that recognises the power and potential of the medium, so that power is transferred from the few to the many, and the creators, artists and writers receive their true reward.

Before the printing press, information was in the hands of the monks and scribes who were often the only members of their society who had the ability to read and write. Copyright law, to some degree, handed the power back to the writers and artists. The current anomaly of perpetual copyright where, for instance, ‘Happy Birthday To You’ is still under copyright over 100 years after the death of its composer, and the rewards go to a corporate entity, is less tenable. We may not fight wars over the right to copy a book today, but open access to common information, in the form of scientific documents that were never intended to be privately owned, and which is “increasingly being digitized and locked up by a handful of private corporations” is most definitely still a right worth fighting for.

**Reversing a string in C** poses problems. It’s not just finding a way to do your job, but also finding an efficient algorithm to do so. You can decide if the ‘reversed’ string will be stored in the existing memory space or if you want to allocate new memory space and a new variable. Using the existing memory space is difficult but is usually the desired task – we assume that no new memory space will be allocated apart from temporary variables.

C lets you to access a string in two ways: either as an array or using pointers. Despite the fact that C pointers can be the root of nasty bugs, pointers are super fast.

Given the string `p = "abc"`, you can access its three characters as follows. First, you can access them as `p[0]`, `p[1]` and `p[2]`, then you can access them using pointer arithmetic as `*p`, `*(p+1)` and `*(p+2)`, and you can traverse the string by increasing the value of the `p` pointer (`*p++`) and accessing it character by character.

If you access a string as an array, you will need to compute its length using the `strlen` C function. The same isn’t required when using pointers, as the ‘\0’ character that denotes the end of a string in memory enables you to find the end of the string in your programs – so a simple while loop can do your job! To make changes to the string it must be initialised using the following C statement:

```c
char s[] = "abcdefg";
```

The plain pointer version (see ‘PRevC’ file) also needs an additional pointer variable to mark the end of the string. The `p` pointer is initialised as the memory address of the first character of a string: `char *p = &s[0];` (nasty C code!). The end of the string can be found using an unusual yet fully functional while loop:

```c
while (*++p) ;
```

The previous while loop will make your code look odd so it won’t be used. The array version (see ‘RevC’) is easy to understand and works well, it does look like Perl or Python code. Additionally, if you have a smart C compiler, it may replace arrays with pointers and do the optimisation job for you. The tricky part of the whole process is finding out the length of the string, which varies depending on the string. The final version will use pointer arithmetic, arrays and the `strlen` function:

```c
for (i=0; i < len/2; i++) {
    temp = s[i];
    s[i] = *p;
    *p = temp;
    p--;
}
```

The code is efficient, stylish and simple. The initial value of the `p` pointer shows the end of the string: `char *p = &s[len-1];`. You can find all three C programs at www.filesio.co.uk or www.mtsoukalos.eu. Until the next article, keep programming!

### Cracking the coding skills enigma

Zach Samocha, director at software testing company Coverity, discusses the importance and prevalence of coding in the UK

![](img/c9d26cf718256f071c3af699b9670538_13_0.png)

**Zack Samocha** is a director at Coverity. In his current role he defines the company product strategy and manages the Coverity open source Scan program, which has grown under his leadership to 4,000 projects and 10,000 active users. Zack also initiated research comparing open source code quality with proprietary code.

**2014: the Year of Code** – or at least that's how many people viewed the 12 months that catapulted this precious skill into the limelight. Coding gained huge media attention last year, especially when it was added to the UK educational curriculum in September – a move that many people celebrated.

This was all really positive progress for the IT industry as a whole, even though the new-found attention on coding might take a little while to change businesses. Still, bringing up a wider range of talent with a greater set of skills is definitely a step in the right direction, especially considering the lack of skilled coders out there at the moment. Along with gadgets like the Raspberry Pi, these developments aim to spark a passion in young people early on in their lives about the mechanics of computing. Hopefully, their interest in this topic will grow throughout their teenage years and into their career.

The sheer volume of people learning how to code in the UK is exciting but important at the same time, as it is changing how we think about IT in this country. People are thinking more and more about the possibilities around apps and software, rather than just having to support and maintain the desktops, laptops and printers in offices around the country.

This is all great news for the coding community, but we can't get carried away.

Even though coding skills are becoming more popular in wider society, this popularity doesn't necessarily match up with a growth in code quality. Unfortunately, we have to consider whether the rising amount of programmers and the standard of code that they are producing will lower the standard of contributions to open source projects, for example, as an area that has seen a lot of progress in recent times.

Let's take driving as an analogy here; millions of us in the UK are legally allowed to drive as we have met all the requirements. We passed the practical and theory exams, bought a vehicle and paid road tax in order to maintain the roads we drive on. When coding, you don't need to have a licence, you only need to know how to do it and get your hands on the tools. Coding is available to everyone as there is no formal regulation, and as a result it attracts a lot of individual coders.

'Self-starters', if anyone, can create a range of software and applications without even thinking about having a formal qualification.
