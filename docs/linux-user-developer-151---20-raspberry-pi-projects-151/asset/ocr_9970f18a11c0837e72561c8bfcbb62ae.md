# ## 01 About Netstat

The main advantage of Netstat is that most of its command line options don't need root privileges to operate. Its other advantage is that it can be found on every Linux system as it's installed by default. Netstat also supports both IPv4 and IPv6 protocols.

Keep in mind that different UNIX systems support slightly different Netstat options, so your scripts may need to change a little in order to run on different UNIX variants.

# ## 02 Basic Netstat usage

When you're trying to solve problems related to a busy web server, you should execute the following command because it shows all established server connections:

```
`$ netstat -a | grep http | grep ESTA`
```

If your web server is using port number 8080 instead of the usual one (80), you can try the following variation instead:

```
`$ netstat -an | grep :8080 | sort ESTA`
```

The -n option shows numerical addresses instead of trying to determine symbolic host, port or user names. It can be combined with all other command line parameters.

# ## 03 Display routing information

This is the single most useful and frequent use of Netstat. Its output presents the routing information of the current machine — a wrong routing set-up is a common cause of networking problems, especially on machines that operate on more than two networks. You can simply view the routing information of your machine by executing either one of the following two commands:

```
```
$ netstat -r
$ netstat -rn
```
```

The more network interfaces you have, the more populated your output will be.

# ## 04 Get statistics for each protocol

The -s command line parameter displays statistics for each protocol and is very useful for finding out if there are too many errors on your machine.

```
`$ netstat -s | grep -n2 -i error`
```

The following Netstat version will display raw network statistics.

```
`$ netstat --statistics -raw`
```

The raw output is more difficult to interpret, but contains much more detailed information that can help you troubleshoot any tricky situations.

# ## 05 See all sockets

This is another very handy option as it displays both listening and non-listening Internet and local (UNIX) domain sockets on the machine. You can see all connections by executing the following command:

```
`$ netstat -a`
```

To display Internet (TCP and UDP) connections only, use these parameters:

```
`$ netstat -a -A inet`
```

You should use inet6 instead of inet to show the IPv6 connections. Similarly, to display local domain connections you are required to execute the following command:

```
```
$ netstat -a -A unix
$ netstat -a -A unix | wc
114 847 7351
```
```

# ## 06 View all listening connections

Sometimes you want to see listening connections only. This can be done with the -l command line option of Netstat:

```
`$ netstat -l`
```

The following form will display the Internet listening connections alone:

```
`$ netstat -l -A inet`
```

Similarly, the next variety will display listening TCP connections only:

```
`$ netstat -l -p tcp -A inet`
```

# ## 07 Find information about a specific protocol

With the help of the grep command, you can extract information about a specific protocol from the output of Netstat:

```
`$ netstat -a | grep -i ssh`
```

If you use the watch command, you can get a continuous list of SSH connections as follows:

```
`$ watch -d -n0 'netstat -a | grep -i ssh'`
```

To terminate the last command you will need to press Ctrl+C in order.

You can use the watch command with every presented usage of the netstat command.
