
Many preset aliases are shown as a result of typing the `alias` command without any options.

Many of these aliases are related to somewhat advanced use of the KornShell, such as job control. Others are useful to you right away. The `history` alias, for instance, lists the commands in the `.sh_history` file and precedes each entry by a line number. The `r` alias allows you to re-run the last command that appears in the history list.

You are not limited to using only preset aliases. You can set your own aliases. The following example shows setting an alias, producing a list of aliases to see whether indeed our new alias has been set, and then running our alias:

```
martyp $ alias lg="ls -al"
martyp $ alias
autoload='typeset -fu'
command='command '
functions='typeset -f'
history='fc -l'
hyper1=HHLIC='/opt/local/bristol/hyperhelp/licenses/hptct1;export HHLIC'
hyper36=HHLIC='/opt/local/bristol/hyperhelp/licenses/hptct36;export HHLIC'
hyper83=HHLIC='/opt/local/bristol/hyperhelp/licenses/hptct83;export HHLIC'
hyper95=HHLIC='/opt/local/bristol/hyperhelp/licenses/hptct95;export HHLIC'
integer='typeset -i'
local=typeset
ls='ls -al'
nohup='nohup '
r='fc -o -'
stop='kill -STOP'
suspend='kill -STOP $$'
martyp $ ls
total 26
drwxr-xr-x 2 martyp staff 512 Mar 15 11:37 .
drwxrw-xr-x 4 root sys 512 Mar 4 09:24 ..
-rw-r-r-- 124 martyp staff 124 Mar 15 11:36 .cshrc
-rw-r-r-- 1 martyp staff 562 Mar 4 09:24 .profile
-rw---- 1 martyp staff 9058 Apr 10 06:58 .sh_history
martyp $
```

![](img/75f39fc91296b889c0653851accdfd46_342_0.png)

The first command set an alias that executes `ls -al` whenever we type `lg`. I issued the `alias` command to see whether indeed the new alias would appear in the list of aliases. It appears right after `local` and right before `nohup` in the alphabetical list of aliases. The final command shows running `lg` (which was the alias set), which produces a listing that you would receive from having run the `ls -al` command.

You don’t have to keep an alias for the duration of your session after having set it. If you don’t like an alias, you can use the `unalias` command to remove an alias.

To see `unalias` work, let’s again produce a list of aliases, use `unalias` to unset the *history* alias, run the *history* command to see whether indeed it has been removed, and then run the `fc -l` command to which the *history* alias was mapped:

```
martyp $ alias
autoload='typeset -fu'
command='command '
functions='typeset -f'
history='fc -l'
hyper1=HHLIC='/opt/local/bristol/hyperhelp/licenses/hhptc1;export HHLIC'
hyper36=HHLIC='/opt/local/bristol/hyperhelp/licenses/hhptc36;export HHLIC'
hyper83=HHLIC='/opt/local/bristol/hyperhelp/licenses/hhptc83;export HHLIC'
hyper95=HHLIC='/opt/local/bristol/hyperhelp/licenses/hhptc95;export HHLIC'
integer='typeset -i'
local='typeset'
nohup='nohup '
r='fc -s -'
stop='kill -STOP'
suspend='kill -STOP $$'
martyp $ unalias history
martyp $ history
ksh: history: not found
martyp $ fc -l
131	ps
132	ls -alF
133	ls -al
134	alias ls="ls -al"
135	alias
136	ls
137	alias
138	unalias ls
139	ls
140	ls -al
141	alias
142	history
143	alias
144	unalias history
145	history
146	fc -l
martyp $
```

![](img/75f39fc91296b889c0653851accdfd46_343_0.png)

When we `unalias` *history* and then run *history*, `ksh` is unable to find it and produces the message *history: not found*. When we run `fc -l` a list of the most recently issued commands with their corresponding numbers is produced. This makes clear that when you run the *history* alias, you are actually running the `fc -l` command.

## Command and Path Completion

**ksh** sometimes knows what you're thinking. You can type part of a command or pathname and **ksh** can complete the remainder for you. You can type part of a command or pathname and press the *escape* key followed by the `=` key to complete the command. If, for instance, you wish to issue the **uname** command to view the current system run level but can't remember the full command, you can type "un" and *escape* followed by the "=" key and the command is completed for you.
