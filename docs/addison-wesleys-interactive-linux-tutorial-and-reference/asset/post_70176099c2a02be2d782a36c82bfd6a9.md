6. Does your *shell prompt* look like this: `$ _`? If it does, you may be using bash. You can find out what shells are available on your system with the `cshsh` command.

- a. At the shell prompt, type `cshsh -l`
- b. Press **<Enter>**

(Make certain that you leave a space between the second “h” and the dash but no space between the dash and the “l.”)

The l is called a *switch or argument*. A switch affects the output of the command. In this case, it tells the system to list the shells available.

The system will respond with a screen similar to Figure 3-2.

```
$ cshsh -l
/bin/bash
/bin/csh
/bin/ksh
/bin/tcsh
/bin/sh
/bin/zsh
$|
```

Figure 3-2 Listing of Available Shells

> While you were working on Exercise 4, we asked you why the shell prompt didn’t appear on the login screen. The answer, as you probably already know, is that you won’t see the shell prompt until your shell is running. And your shell won’t run until after you have logged in.

11. The **ps** command will usually list only the processes that you have initiated. What about the processes that the kernel starts—the daemons that we mentioned in the CBT course? To see all the currently running processes, you add a switch to **ps**:

- a. Type `ps -A`

The "A" switch means “all.”

- b. Press <Enter>

Linux will respond with a display similar to what you see in Figure 3-9. Note that your shell is listed as a process.

12. Did the display in the previous exercise run right off the bottom of the screen before you had a chance to see it? You can control this digital disappearing act with a handy utility called **more**. (We haven’t used **more** in the CBT course yet, but it fits right here.) Note the spaces in this command.

- a. Enter the following command:

Type `ps -A | more`

- b. Press <Enter>

To continue scrolling through this display, press <Enter> to move down one line at a time; or press the space bar to scroll down one entire screen.

Now you can see that the kernel is keeping track of a lot more than is obvious.
