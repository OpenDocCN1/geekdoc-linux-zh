Given the eight-character limitations of Linux's usernames, the username will have to be shortened to majordom. Thanks to /etc/aliases, no one else has to know this. You should also create a home directory for the majordomo user. This can be /home/major-dom if you like, or /usr/local/majordomo if you prefer, or anywhere you have space.

So majordomo,7 copy the majordomo.94.1.tar.gz file to the home direc-tory, and uncompress/tar file. Make any kinds of modifications to the majordomo.cf file; then just use the make command to create it. Once installed (which should be in the majordomo home directory) you need to make only one change to the /etc/sendmail.cf file. You should already have one OA (or O AliasFile) entries listed. Underneath that, put in

```
OA/home/majordomo/majordomo.aliases
```

This sets up an additional file to handle aliases. This makes it easier for the majordomo administrator to add new mailing lists, and that person does not need root access in order to modify the lists.

Now on creating the lists themselves. Let's create a (fictional) list called gastro. We will use an open list for sharing recipes, so anyone can join, and any-one can post a note to the group.

In the ~majordomo/majordomo.aliases file (I call it the alias file from now in case you choose to use the /etc/aliases instead) add the following:

```
gastro: * /home/majordomo/wrapper resend -l gastro gastro-list*
gastro-list: :include:/home/majordomo/lists/gastro
owner-gastro: mark
gastro-owner: mark
gastro-request: * /home/majordomo/wrapper majordomo -l gastro
gastro-approval: mark
```

This sets up the basics. The list itself will be "gastro@host", the owner will be mark, and any requests to join the list will be sent to majordomo as well. Normally, users would send E-mail@host to subscribe, but dif-fer mailing list software works in different ways.
