## Adding and Removing Newsfeeds

After modifying the newsfeeds file to add a new site to only feed, run the “ctlinnd begin <site>” command to start feeding the new site instead of reloading the entire server. It is also to run “ctlinnd checkfile” to make sure that any changes made to the newsfeeds file were syntactically correct, and INN automatically does this when the newsfeeds file is reloaded. All errors found will be reported to syslog.

If a site has been removed from the newsfeeds file but a batch file exists for it, running “ctlinnd drop <site>” will remove the site from the list of active feeds and flush out the batch file. Merely running a “ctlinnd flush <site>” will clear out the batch file. If no site is specified, then flush tries to clear out of the batch files and also writes the active and history files to disk, flushing the local server as well.

## Reloading the Server

After modification of any of the following files, the news server must be reloaded for any changes to take effect: history, hosts.ntmp, newsfeeds, active, overview.fmt. The reload command will also take an argument of “all” to reload all of the above files. If the argument passed to ctlinnd reload is history, then the history database is closed and reopened. If the argument is hosts.ntmp, then the nmtp access file is reread. If the argument is active or newsfeeds, then both the active and newsfeeds files are reloaded. If the argument is overview.fmt, then the overview format configuration file is reread.

## Stopping and Starting Connections

Ctlimnd is also used to control who can connect to the server to read, post, and feed articles over NNTP. To allow or disapp client readers, use the command "ctlimnd readers <flag> <reason>" where the <flag> starts with either "n", for disconnecting connections, or "y", for allowing connections, and the <reason> is the test fed to the client when it tries to connect. To recall connections the <reason> must match the <reason> given at the time of allowing or be an empty string. Similarly, issuing a "ctlimnd reject <reason>" command will reject any connection that would be handed off to nnrpd with the <reason> given as the explanation. To allow connections after a reject, issue the "ctlimnd allow <reason>" command where the <reason> must match that of the reject command or be an empty string.

To pause the server so that no incoming articles are accepted, issue the "ctlimnd pause <reason>" command and reenable connections with the "ctlimnd go <reason>" command. When pausing the server, no existing connections are closed but the history database is closed and written out to disk. This is only used for short-term locking, or when replacing the history file. Doing a pause also sends a note to the readers command so that no news may connect.

To stop incoming articles and sever all current connections, use the "ctlimnd throttle <reason>" command. This is a more long-term lock which closes the history base and sends a note to the readers command. To reenable connections, send a "ctlimnd go <reason>" command. Server throttling is normally done when expire is being run or extensive work is being done on some critical part of the news system.

## Expiring and Reporting

As mentioned above, expire is one of the news processes that shut down all connections to the server. Expire is one of the clean-up jobs that is from the script "news.daily" each night. The script news.daily is usually once a night but can be run more or less often if desired, from cron the news user.

## 10.6 Newsfeeds

Typically news.daily removes old articles from the news server, rotates logs, and sends reports but it can be configured to each individually. news.daily program takes several keywords as arguments, but we will only discuss the most commonly used flags.

If news.daily is running more than once a day, the flag "notdaily" can be specified for one or more of the cron runs so that log processing and rotation only get done once. The "norotate" argument only specifies that the news logs should not be rotated. If the logs are not rotated every time, you will see duplicate information in the subsequent reports. The argument "noexpire" can be used to specify that no old article removal should be done, and the argument "nomail" specifies that no reporting mail should be sent to the newsmaster.

## Article Expiration

If expiration is being done, the "expire.ctl" file is consulted by the "expire" process to determine which articles should no longer be kept on disk upon their age logged in the history file. The "expire" program oversees the removal of the articles and calls other programs that do the removal and updating of the history, overview, and active files. The "expireirm" program is a script that calls `fastrm` to remove the articles listed in the file specified as the argument. By default, expire uses the "expire.list" file in the news log directory.

The expire.ctl file tells the INN software how long to remember MessageIDs in the history file and after how many days in certain newsgroups or hierarchies should be removed. The news article removal can also be based on the type of group, whether it moderated (M), unmoderated (U), or all (A) groups. The first field of the colon-separated entry in the expire.ctl file is the wildcard match on the newsgroup name. The second field is either M, U, or A as matches the description above. The third field is the minimum time the article should be kept if its expiration header claims otherwise. The fourth field is the default number of days an article with no expiration header should be kept, and the fifth field is the date at which articles will be purged. To expire all newsgroups quickly because of space issues, put the following line in expire.ctl:

```
alt.binaries*:A:2:3:5
```

Several arguments to news.daily determine how and when articles are removed. The “expireover” argument tells INN that after the old articles have been removed, the overview databases should be updated to reflect the new status of the articles. If the “delayarm” argument is used, then the names of the articles to be removed are written to a separate file and then batched for removal by the programs “expire” and “expireover.” The “expireflags='<expire args>’ argument tells news.daily what flags to pass to expire if the “expireover” argument is specified. If delayarm is specified, news.daily passes the “-z” flag to both expire and expireover to tell them to use batch mode.

## Rotation and Reporting

While the expiration process is taking place, news.daily logs all of the output to a file. When the expiration is done, news.daily uses the “scanlogs” program and its supporting scripts to parse all of the log files that the server has built up for the past day (or since the logs were last rotated). Very detailed information about the number of articles accepted and transmitted and any errors that occurred are printed up and added to the expire data and mailed off in a report to the newsmaster. As its final step, the news.daily process rotates the old logs into a separate directory and then throttles or unpauses the server so connections are again accepted.
