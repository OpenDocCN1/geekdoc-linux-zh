
## 6.5 Printers on the Network!

Now let's hook printer into a network. 

When the printcap is set up, you'll need to restart the printer daemon (lpd) which should already be running and will be once Linux starts. To inform Linux of the changes on the /etc/printcap file, you can send a signal HUP (1 for Linux) to the lpd process. This will cause it to reread the /etc/printcap file and restart.

## UNIX

Once lpd is running, the names of the hosts that you want to have access to your printers in the /etc/hosts.lpd (for printer access only) or enter them in the /etc/hosts.equiv file. Once this has been done, your printer is available for access from other UNIX machines immediately. The “rm” option to the remote host, and have the “rp” option name the remote printer. The only other option that needs to be is the “sp” option (local spool directory). For added security, the “zs” option, if set on the print server side, will accept only print jobs from users on the remote machine that have accounts on the server machine. That is, a user account of the same name must exist on both machines before the print job will be accepted. The lpd monitors TCP/IP port 515(tcp) for activity from print clients.

> Using the hosts.equiv could be a security hole, especially if you're in a network of Linux or UNIX machines.

> You could also serve another Linux (or UNIX) machine running samba as well, but that would just be silly, but still in “the UNIX way.”

## SMB (Windows Networking)

The best way to get a Linux printer seen on a Windows network is to run Samba. We'll get into Samba in another chapter, but we'll focus on setting up print services. The important thing to know is that Samba should be configured to use all the configuration Linux needs to serve a printer to a Windows for Workgroups, Windows 95, or Windows NT machine. Users will be able to use the standard Windows print management tools (print queues) to see the entire printer queue, and even remove their job if they choose. Be sure to install a printer driver for Windows for the kind of printer you have installed, as the printer filter on Linux should just pass the data along to the printer.

To print from Linux to a Windows machine, the procedure is a bit different. RedHat allows you to via Server Message Block (SMB), and it takes care of the rest. The Windows machine finds the data and sends them off to the printer. In these cases, the print queue commands (see below) will probably not work, as Windows has its own protocol for handling the queues.

As you can see, it would be much easier and simpler for a printer to exist on a Linux server.

## 6.6 Managing Print Queues

Now that the printer is connected and working, people are going to try sending print data to it. At this point, it's time to put on the "print master" hat and get to work.

The print queues are FIFO (First In First Out) queues, so the first one in line gets to have access to the printer. If one job gets stuck, or the printer runs out of paper, the queue will begin to fill and you will be hounded by users desperately trying to find their printouts. Not to worry.

The commands you'll want to know about are the lpc, lprm, and lpq commands. The lpc command shows what's in the queue and gives you the current status of the printer, as lpc can figure that information out. Some printers will be able to tell lpc that they are out of paper, or that the connection is down, and these errors will show up in the lpq.

The lprm command will remove jobs from the queue. Only root and the person who submitted the print job can remove a job from the queue. If an accidental print job is 3 Mb in size and is currently tying the queue, it may be best to remove the job. As root, you can remove all the jobs owned by a particular user with the command lprm user.

The lpc command is the "lpc control." It can activate and deactivate queues and printers, rearrange jobs in the queue, and get a status of any printers listed in /etc/printcap to paraphrase the man manual.

Lpc can be run on the command line (lpc restart lpc) or run interactively, submitting many commands to various printers. Here's a list of some of the more important lpc commands:

## 6.7 Summary

- disable { all|printer }—Disable the named printer.
- down { all|printer }—Disable the named printer completely. No new jobs can be added, and printing stops.
- enable { all|printer }—New jobs can be added to the queue (reverse of disabled)
- restart { all|printer }—Try to restart a print daemon. The lpd process will die or get stuck, and this will try to restart a new daemon.
- status { all|printer }—Get a status of the printers. List whether or not queues are awake, whether printing is enabled.
- topq printer [job..]—Print the jobs listed at the top of the queue

The lpc man page has more on the commands available, but these get you started with the queue administration.

In the worst case scenario where the lpc commands do not work, you can use the /etc/rc.d/init.lpd.init stop command to stop the lpd program altogether. The /etc/rc.d/init.d/lpd.init command will start lpd up.

For more information or help on how the print services work, check out the Printing HOWTO and the Printing Usage HOWTO.

Here's a quick review of what was in this chapter:

- Serial, parallel, and ethernet printers all have their relative advantages, depending on what your printing needs.
- Linux uses the /etc/printcap file for controlling how the lpd program talks to the printer.
- Linux can talk to printers across the network, and Samba allows Windows machines to network with a Linux printer.
- The lpr, lprm, and lpc programs are used to manage the printers and print queues.

## Sendmail, mailing lists, E-mail clients, and POP/IMAP (remote connections).

This chapter shows how to set up sendmail, set up simple mailing lists for customers, clients, or groups of people, review some of the E-mail clients available, and set up remote connections using POP (Post Office Protocol) and IMAP(Internet Message Access Protocol) mail standards.

E-mail (electronic mail) was one of the first methods for communicating over what is now the Internet. E-mail allowed short messages to route across various machines. In those days (1987) you often had to manually specify all the machines (or hops) an E-mail message would have to route through to get to the end host. With TCP/IP as the communication method, things are a bit smarter in that you don't need to know how to get to the end host—as long as some machine along the way knows how to route the E-mail for you.

As aside, the technical name for the E-mail that get on the Internet is known as Simple Mail Transfer Protocol (SMTP). There are a few other protocols that work with SMTP, such as POP and IMAP, but we'll get to those later. You can find more information about SMTP in RFC 821.

The primary program that is Mail Agent (or MTA) is sendmail. There are others available, but sendmail is pretty much the standard for most Linux installations. You may have seen that really thick book with a bat on it that gets you into the nitty-gritty of sendmail.

The point of all this is that you don't always need it in order to set up a E-mail server. The one thing you should know about sendmail is this: Always be sure you have the latest version. Each version of sendmail, while patching various bugs, seems to have a security problem. Seems you need to upgrade your sendmail software more often than the Linux kernel.

Enough of that. Let's get to the typical sendmail options you'll see on startup. Most Linux installations have sendmail kick in bootup. RedHat (being SVISH) has an /etc/rc.init/sendmail.init script which runs on start-up. My installation starts the actual command like this:

```
echo -n "Starting sendmail :
daaemon sendmail -bd -qh
echo
touch /var/lock/subsys/sendmail
```

As you can see, the sendmail program starts with the -bd option and the -qih option. The -bd signifies that sendmail should start up as a daemon and run in the background waiting for connections, the same way that a Web server is always running, waiting for a connection. The -qih means that sendmail should go through its queue at least an hour and try to send any data in its queue.

There are many reasons that an E-mail message can be held in a queue. For example,

- If you have a dialup-only connection to the Internet, and you send a note while you're not connected.
- The remote host is not dialed (same thing in reverse).
- The remote host is down for upgrades or it crashed.
- There is no connection to the remote host (the network is down).

In any of these cases, you'll want to make sure that your E-mail gets through. Leaving the E-mail in sendmail's queue allows you to do this.
