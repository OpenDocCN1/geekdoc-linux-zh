# 5.2 INETD

In the home directory of that user, create a .ppprc file and add the following:

+   -detach
modem
crtsck
lock
192.55.123.100:192.55.123.111
proxyarp

This gives PPP some initial settings to work with. The -detach says to not detach from the console. The modem says to monitor the CD (Carrier Detect) line and terminate if CD drops. The lock will lock the device, preventing anyone else from using serial port. The two IP addresses are of the server (waiting for the call) followed by a colon and the IP address to assign to the client when it dials in. The proxy allows the server to put the PPP client in its ARP cache and respond to packets that are exposed to the client.

Once this has been completed, set up to monitor the serial ports, and dial in to sure the static IP addresses works. The pppstats command can give a running total of packets in and out for the line.

If you choose to use dynamic IP addresses instead of static IP's to save on IP addresses, create a /etc/ppp/options.ttyXX for each tty file that is attached to a modem. Replace the XX with the name of the serial port, for example, /etc/ppp/options.tty50 for /dev/tty50. The content of the options.ttyXX file is the same as the .ppprc file listed above.

If your PPP clients are going to be Windows 95 machines and you're using the default "Dialup Networking" you'll need to add the scripting tool to Windows 95. It's included in the CD-ROM as \Admin\Apptools\Dcript. A slightly better version is included in the Windows 95 Plus! pack.

# 5.2 INETD

The inetd daemon is used to start programs automatically when a request comes in on a specific TCP/IP port. What happens inetd monitors all the ports that are in its configuration file, and when a request comes in, it starts the application and returns to watching ports. There are two files that inetd needs to work: the /etc/services and /etc/inetd.conf files.
