```
/etc/rc.d/rc.dial
!/bin/sh
echo -n "Starting auto-dialer: "
/usr/sbin/dial /dev/modem accounting-log "/var/log/dial" -m ppp
defaultroute modem \ crtscts local 111.222.333.444 remote 0.0.0.0
connect /usr/sbin/chat -f /etc/ppp/ppp-chatfile*" fifo */etc/
dial.fifo
echo "dial"
```

At least the local option, and maybe the remote option, will have to be changed. If you have a dynamic IP (setting local to 0.0.0.0), this may cause some difficulties when telnetting to a machine on your local network. A static IP is highly recommended when using dial, or the IP masquerading in the following section. Also, if you know the remote IP, I would suggest it.

The FIFO figure is optional. The FIFO allows dial to communicate with a few programs that come with the dial distribution for monitoring the dial activity. If you notice that your connect is slow, or if ifconfig reports that there are lots of errors on the PPP link, you may wish to remove the FIFO option.

The accounting-log algorithm is also optional. This writes information about call duration to a file. It is useful if you wish to find out how long your modem has been active.

After customizing this file, you may either reboot, or just execute the file by hand. Depending on how recent your /etc/services file is, dial may complain about unknown services. A common one I've seen is tcp.www. If receive one of these errors, there are two solutions. One solution is to comment out the offending line in /etc/diald.conf and let the catchline halt at the bottom of /etc/diald.conf give service up-time. The other solution is to update your /etc/services file to contain the appropriate information. Ideally, you should update /etc/services; this will give you greater control over dial, as it will allow you to narrow down modem usage.
