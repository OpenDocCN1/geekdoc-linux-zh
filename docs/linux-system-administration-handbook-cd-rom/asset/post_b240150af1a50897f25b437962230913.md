## Procmail

procmail is installed as the Mail Delivery Agent (MDA) on your system (check the Mlocal entry in your sendmail.cf to find out), then you can immediately use procmail to filter all your incoming mail. If not, you can put a reference to procforward in procmail to run each time new mail arrives. Procmail is used to process mail as it comes in. This can include putting all E-mail from the "Plan9 MUSH Advisory Committee" in one mailbox from everything else, or filtering that annoying E-mail you get from billg@microsoft.com by sending it to /dev/null.

Procmail is set up to the default local mail handler, setting procmail for use is easy. Create a .procmail file and start adding rules for procmail to filter. If procmail is not your local mail handler, you have three options:

- 1. Make the local mail handler (the man page has the suggested changes you can make to the /etc/sendmail.cf file). If you're using m4 configuration files, add "FEATURE(local_procmail)" to your file.
- 2. Run procmail periodically or use cron to filter out an already existing mailbox. This allows you to use .forward (in the event of vacation and the like), but the mail is not always sorted and you have to wait.
- 3. Put a reference to procmail in .forward. Note that this won't let you forward all that easily. In the .forward file, put a line that looks like

```
|IFS=' &&exec /usr/local/bin/procmail -f-|exit 75 #YOUR_USERNAME
```

Anything to /dev/null is immediately discarded. This is called "the bucket." Thanks to the fact that Linux is a 32-bit OS, its bit bucket is one of the fastest.

:0

+   * ^From.*mark

:0

There are three sections to matching a line and performing some action on it, also called recipes. A recipe starts with a line that has at a :0 starting. After the :0, you can include some flags (for example, H will scan only the headers). Pattern matching is done for lines that start with an *. The rest of the line is sent to egrep⁶ literally. If all of the lines match (the lines ANDed together) then the appropriate action is taken. If not, it moves to the next recipe.

There can be only one action line, and this is the one that does not start with an * or :. An action starting with ! will forward the program to the specified user. Anything else will be assumed to be a filename to append (or if it doesn't already exist).

These two examples show that all mail has a From line and ends in mark (which will be your E-mail sent by me) will be put in the ~/Mail/from mailbox. The second example shows that all E-mail that starts with the word “Subject” and ends in “Flame” will be sent to /dev/null (the bucket).

The thing to know if you want to delete mail out of hand is you have to be absolutely sure that your logic is correct. For, if you delete all mail that has the word “Flame” in it, then you can potentially lose messages with a subject such as “Flame broiled burgers free until 10 AM.”

## 7.5 Mailing Lists

OK, so it's a poor example. You may want to store mail you want to delete for a while and examine it just to be sure you don't lose anything important.

Mailing lists allow larger groups of people to communicate via E-mail. In many cases, it is preferable to using USENET since

- Mailing lists do not need approval to be created. Anyone with a machine connected to the Internet can create a mailing list on any subject. Getting members to subscribe to it is a different issue, ever.
- Mailing lists can control who subscribes. The mailing list administrator can make it so that anyone can subscribe, or can make it so that the administrator is the only one who can add new members to the mailing list. The administrator can also remove offending members if a problem arises
- Mailing lists can control content. This isn't as bad as it sounds, since it is the alternative to the anarchy that is USENET. The administrator can set the list up to be open and provide a healthy discussion area (such as for developers working on a piece of software) or can set the list up such that the administrator has to approve each piece of E-mail that gets into the list (like the moderated USENET groups). The moderated lists are good for news releases, humor lists, or any other list where the amount of discussion should be low.

## Majordomo

The best mailing list program in use has to be majordomo. Majordomo provides all the features listed above, plus a few other features, such as sending out regular digests, or archiving for future use. We'll get back to this later on.

The first thing that needs to be set up is majordomo itself, if it's not already installed. The source for it is located on the CD-ROM. You need to have perl 5 installed on the system (as well as gcc) in order to use it. First, create a majordomo user. Given the eight-character limitations of Linux, the username will have to be shortened to major-dom. You should also create a home directory for the majordomo user. This can be /home/major if you like, or /usr/local/majordomo if you prefer, or anywhere you have space.

So majordomo, copy the majordomo.tar.gz file to the directory, and uncompress it. Make any kinds of modifications to the majordomo.cf file; then just use the make command to create it. Once installed (which should be in the majordomo home directory) you need to make only one change to the /etc/sendmail.cf file. You should already have one OA (or AliasFile) entries listed. Underneath that, put in

```
OA/home/majordomo.aliases
```

This sets up an additional file to handle aliases. This makes it easier for the majordomo administrator to add new lists, and that person does not need root access in order to modify the lists.

Now on creating the lists themselves. Let's create a fictional list called gastro. We will use an open list for sharing recipes, so anyone can join, and anyone can post a note to the group.

In the majordomo.aliases file (I call it the alias file from now in case you choose to use /etc/aliases instead) add the following:

```
gastro: * /home/majordomo/wrapper resend -l gastro-list*
gastro-list: :include:/home/majordomo/lists/gastro
owner-gastro: mark
gastro-owner: mark
gastro-request: * /home/majordomo/wrapper majordomo -l gastro
gastro-approval: mark
```

This sets up the basics. The list itself will be "gastro@host", the owner will be mark, and any requests to join the list will be sent to majordomo as well. Normally, users would send E-mail@host to subscribe, but different mailing list software works in different ways.
