
## 23.5 IP MASQUERADING

3. Set up the rules themselves, keeping in mind the rules are processed in order and do not continue after the first match.

- `ipfwadm-[FOIA] -a <accept | deny | reject | masquerade> [-V interface IP | -W interface name] -S <source IP> -D <destination IP>`

The -a option is an option to rule the list and should be followed by a policy. Valid policies are accept, deny, reject, and masquerade. Note: This does not apply to Accounting rules.

The -V and -W options are optional. They specify on which interface packet will be transmitted or received for this rule. If not specified, it is assumed that the packet will be accepted on all interfaces. Either the -V (IP number) or the -W (interface name) can be used, but not both. -S and -D refer to the Source and Destination of a packet, respectively. Source and Destination IPs can be the dotted quad number or hostnames. I suggest using IPs as it will not require a lookup.

The following pages include descriptions of simple masquerading firewall, with some minor protection from intruders. If more in-depth information is required, read the ipfwadm man pages and perhaps one of the many books dedicated to firewalls. Most books will not discuss ipfwadm specifically but will give theories that can be applied to your Linux box.

Below is a sample /etc/rc.d/rc.firewall. As with dial, you should call it from rc.local.

```bash
#!/bin/sh

PATH=/sbin/bin:/usr/sbin:/usr/bin

#
# /etc/rc.d/rc.firewall, define the firewall configuration,
# invoked from rc.local.
#
PATH=/sbin/bin:/usr/sbin:/usr/bin
MY_ETH0=192.168.1.1
MY_NET=192.168.1.0
MY_STATIC=111.222.333.444

# Forwarding rules
# first flush any old rules from memory
ipfwadm -F -f
# then set a default policy to deny everything
ipfwadm -F -p deny
```

```bash
# lastly, we want to masquerade the IPs from MY_NET (eth0)
# the ppp0 interface (but we may need to stop at the s0
# the interface if dialed needs to start the ppp connection!)
ipfwadm -F -a masquerade -W ppp0 -S $MY_NET/24 -D 0.0.0.0/0
ipfwadm -F -a masquerade -W s0 -S $MY_NET/24 -D 0.0.0.0/0
```

```bash
# Incoming rules
# first, flush all rules from memory
ipfwadm -I -f
# then set a default policy to deny everything
ipfwadm -I -p deny
```

```bash
# packets coming in from my local network (can only be eth0) to
# where else are allowed
ipfwadm -I - accept -W eth0 -S $MY_NET/24 -D 0.0.0.0/0
```

```bash
# packets pretending to be my local network that come from
# the outside is denied
ipfwadm -I -a deny -W ppp0 -S $MY_NET/24 -D 0.0.0.0/0
```

```bash
# packets going to the firewall, from a remote network is valid
# (i.e. if we are using the firewall machine for mail, or someone
# VALIDLY telnetting into the firewall)
ipfwadm -I -a accept -W ppp0 -S 0.0.0.0/0 -D $MY_STATIC/32
```

```bash
# We may also use localhost for testing, so make it valid
ipfwadm -I -a accept -V 127.0.0.1 -S 0.0.0.0/0 -D 0.0.0.0/0
```

```bash
# Outgoing rules (basically the reverse of the Incoming rules)
# as usual, flush all old rules
ipfwadm -O -f
# and setup a default policy of deny
ipfwadm -O -p deny
```

```bash
ipfwadm -O -a accept -W eth0 -S 0.0.0.0/0 -D $MY_NET/24
```

```bash
# deny someone trying to fake the masquerade
ipfwadm -O -a deny -W ppp0 -S 0.0.0.0/0 -D $MY_NET/24
ipfwadm -O -a deny -W ppp0 -S $MY_NET/24 -D 0.0.0.0/0
ipfwadm -O -a deny -W ppp0 -S 0.0.0.0/0 -D $MY_NET/24
```

```bash
# all outgoing data from the firewall is valid, and
# remember, we need to make it valid for sl0, just once
# dialed hasn't enabled ppp0 yet.
ipfwadm -O -a accept -W ppp0 -S $MY_STATIC/32 -D 0.0.0.0/0
ipfwadm -O -a accept -W s0 -S $MY_STATIC/32 -D 0.0.0.0/0
```

```bash
# and... yeah... localhost is still valid
ipfwadm -O -a accept -V 127.0.0.1 -S 0.0.0.0/0 -D 0.0.0.0/0
```

echo "done"

Following is a sample /etc/rc.d/rc.firewallAccounting script. This should be kept separate so that you can restart it and monitor different machines without disturbing the rest of the firewall. There is also a way to set all accounting rules to 0 bytes of traffic, but this allows you to easily add and delete machines from the accounting list. Once, this script expects a file named /etc/FirewallAcctList and contains a list of the machines you wish to monitor.

To monitor the traffic, a cron job can be created to view the output of the firewall accounting and via mail.

```bash
#!/bin/sh

PATH=/sbin:/bin:/usr/sbin:/usr/bin

#
# /etc/rc.d/rc.firewall, define the firewall configuration,
# invoked from rc.local.
#
PATH=/sbin:/bin:/usr/sbin:/usr/bin
MY_ETH0=192.168.1.1
MY_NET=192.168.1.0
MY_STATIC=111.222.333.444

echo -n "Starting accounting rules:"

# Kill the old rules
ipfwadm -F -f
# These are the system rules!! log all traffic as reference point
ipfwadm -A in -i -S $MY_NET/24 -D 0.0.0.0/0
ipfwadm -A out -i -S 0.0.0/0 -D $MY_NET/24

ipfwadm -A in -i -S $MY_NET/24 -D $MY_ETH0/32
ipfwadm -A out -i -S $MY_ETH0/32 -D $MY_NET/24

# These are to log traffic to individual machines named
# FirewallAcctList... just a list of IPs
for i in $(cat /FirewallAcctList); do
	echo -n "$i"
	ipfwadm -A in -i -S $i/32 -D 0.0.0/0
	ipfwadm -A out -i -S 0.0.0/0 -D $i/32
done
echo "done"
```

## 23.6 Summary

When connecting a LAN to the internet in a secure way there are items to consider: First, the selection of a private (routable) network. Second, connecting your firewall machine to the Internet via an on-demand dial line. Last, allowing certain machines on your LAN and disallowing access from external networks.
