## Oldies but Goodies

### FORTRAN

```
http://www.fortran.com/fortran/
```

FORTRAN is a venerable language designed mainly for numerical calculations. Its most common incarnation on Linux is in the form of g77. The latest specification is FORTRAN 90, which is not common as FORTRAN 77. Few compilers for FORTRAN 90 exist and no free ones exist for Linux.

### BASIC

```
http://www.Mainz/~ihm/basic.html
```

Not as old as FORTRAN, but still popular for its simplicity; Microsoft's Visual Basic has played a large part in keeping it popular. It has had and continues to have many incarnations both interpreted and compiled. Only recently has a BASIC compiler available for Linux.

### Pascal

```
http://sun011/~klaus/pascal/
```

Pascal is a language that has always been popular among computer scientists, both to teach good programming techniques and as a general purpose programming language. Free compilers exist for Linux, and one ships with most distributions.

### COBOL

```
http://www.cobol.org/
```

Despite the fact that nearly everyone knows COBOL, as of a couple years ago, more lines of COBOL code have been written than any other language. Its usage is almost completely confined to financial-related applications, but there are lots of banks, finance companies, and people interested in it else. It is not well suited for general tasks, but a free compiler exists and is shipped with some distributions.

### Of More Recent

Most of the languages we discuss next are somewhat newer than the previous ones. Also few of them are included in any Linux distribution. Regardless, these are useful and powerful tools which you may wish to consider in place of more common languages.

### Smalltalk

```
http://www.uiuc.edu/
```

It is one of the fastest growing languages on the planet. Its usage is estimated to be growing at around 60 percent a year. It is a very high-level programming language, which typically translates into short development time. Its syntax is easier to read and the language itself is also easy to learn. Smalltalk is about as object-oriented as it gets. Everything is an object, leading to consistent methods of handling things. Smalltalk claims that it was "designed with the human in mind."

### Icon

```
http://www.arizona.edu/icon/www/index.html
```

Icon is another high-level language, in fact. Its roots are in SBOL, though in its current incarnation there is little resemblance to C but with a much higher level of semantics. As a high-level compiled language it is certainly useful and used for compute-intensive tasks. Similar to Smalltalk, its high-level design allows for rapid development of applications. As an aside, the name Icon is not an acronym and was chosen for the language before the term "icons" referred to.

### Rexx

```
http://www.rexx.org/
```

According to its creator, Rexx is "a procedural language that allows programs and algorithms to be written in a clear and structured way." Rexx's syntax is not particularly unique or unusual. It was designed as a generic language which can be used with another application. When its parser encounters a function that doesn't recognize, it asks the application to handle it. This way, if Rexx is used as the language for multiple applications, users need to learn only one language and the functions for each application will presumably be known from normal use.

### Eiffel

```
http://www.eiffel.com/
```

Eiffel is a commercial, OO, compiled language designed for rapid development of clean reusable software. There is a strong emphasis on mechanisms and techniques to promote reliability and low bug rates. Although it is commercial, sellers frequently offer large discounts for personal, student, or educational use. Some companies offer Linux versions below other prices. If you want to develop in a fully OO, commercially supported, compiled language, Eiffel may be for you. Or if you can live without commercial support, you may want to look into the next item in this list of languages.

### Sather

```
http://www.icsi.berkeley.edu/~sather/
```

Sather's roots are in Eiffel. Early beta versions of it were nearly subsets of Eiffel 2.0; however, after a major release later both languages have gone their ways. Sather was and is developed at the University of California, Berkeley, and as you might expect a language developed at an educational institution, it is freeware. Sather has garbage collection, multiple inheritance, is strongly typed, and its code can be compiled into C code. Its public license is very liberal to encourage users to contribute to its library.

## 15.1 Web Server Software

There are a number of Web servers (HTTP daemons) available for Linux as both commercial and/or freeware. Additionally there is the choice of using a secure server versus a non-secure server. The difference between the two is the use of SSL (Secure S Layer, a protocol for encrypting/decrypting data via a network socket). Typically, non-SSL servers are free while those employing SSL are commercially developed and cost several hundred dollars.

In addition, a Web server can be forking or non-forking. Traditionally, HTTP daemons fork off child processes to handle incoming requests. Each child can typically handle a hundred or so requests, but it handles them seriously; this means that heavily loaded servers may need to have a large number of child processes, each of which takes up additional RAM and CPU. In a server with a large binary (especially a secure server) this can cause problems. The alternative is to have a server that multiplexes incoming connections internally. Now RAM has been and looks to remain inexpensive and CPU performance has been increasing by leaps and bounds, so one may be inclined to question whether a multithreaded server is worth the effort. However, it has certainly been one of the main aims of Linux to get as much out of a computer’s hardware as possible, which obviously writing efficient software. This said, there are no non-forking servers which equal the extensibility of the best of the foring servers. It seems likely, though, that soon the extensibility of the servers like Apache and the multiplexing of servers like Boa will be combined.
