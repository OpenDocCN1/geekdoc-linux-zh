The printcap man page has a list of all the options, what they're used for, and the default settings. If you're using a serial printer, you will want to add the following settings:

+   - br—Baud rate to use. Any valid baud rate will work.
- ms—Stty settings give to the serial port after opening and sending data. This is usually to set up things like hardware flow control.

A sample line addition of an 8-bit connection using hardware flow and running at a rate of 38.4 Kbps is

```
br#38400:ms=opost,cs8,-parenb,-cstopb,crtscks\
```

# 6.4 Print Filters

Print filters are programs that convert from multiple file types to one your printer can understand. In most cases, this will be either PostScript (really easy to do) or PCL (harder, but not much). The reason PostScript is so easy to use with printers is because most of the higher-end printers were connected to UNIX machines, and therefore the programs were written to output PostScript. Now that PCL is being used more often in the lower-end printers (like mine) and Linux is everywhere, you'll probably need some kind of converter. This is where the print filters come in. We've had some experience with magicfilter, which is a filter specifically for Linux, with much success. Other filters exist, such as apsfilter, and they work all about the same. On your machine, you'll need a number of programs installed (ghostscript, netppm, jpeg at the very least, probably TeX and the assembled dvi programs). During installation of the filters, the installation script queries your system to see what programs are available and makes the best guess to get from one graphics format to another. For example, to print out a JPEC image, the dpeg program would convert it to GIF format; then the gs program would convert from GIF if you expect to be printing files directly from the command line (lpr -Plp wayga.gif) or do not have RedHat, you may want to look at getting magic-filter or apsfilter installed.
