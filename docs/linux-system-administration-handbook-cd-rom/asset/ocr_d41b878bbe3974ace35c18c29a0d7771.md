# DNS Database Records

Let's look at the named.wayga file. This file has an example of many of
t features you'll want in your files:

```
@ IN SOA wayga.net. enry.wayga.net. (
1
3600
600
360000
10800 )\)

IN NS 208.197.103.125
IN NS 208.197.103.21
wayga.net. IN A 208.197.103.125
galeileo IN A 208.197.103.21
localhost IN A 127.0.0.1
wayga.net. IN MX 0 wayga.net.
www IN MX 10 galileo
mail IN CNAME wayga.net.
ftp IN CNAME wayga.net.
plan9 IN CNAME wayga.net.
```

The SOA line indicates the Start Of Authority line. This line tells
domain this file is working on. The SOA line is constant up to the point
after SOA. Then it has the following information:

+   * machine name acting as the DNS server.
* contact name (replace the @ in the E-mail address with a period).
* open parenthesis.
* serial number, which should be incremented every time you change the
file. Since this is the first revision of the file, it has a serial number of 1.
* refresh time in seconds, or how often to recheck the SOA record. The
3600 stays to refresh once an hour.
* retry time, or when a secondary server should retry contacting pri-
m server if something goes wrong.
* expire time, or when the secondary server should flush its cache if it
't contact the primary server.
* minimum time to live. This defines how long other servers should keep
records in their cache before it should be flushed. If it's too short,
named is spending too much requesting addresses it should
already know, and if it's too long, the wiring IP information may be
reported if a host changes ISPs or even IP addresses.
