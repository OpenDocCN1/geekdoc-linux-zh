sendmail 的配置选项通常位于 `/etc/sendmail.cf`。如果你愿意，可以检查该文件，但除非你确定自己在做什么，否则不要更改任何内容！微小的变化可能会导致你的电子邮件系统失效。一如既往，请备份你想要编辑的文件，以防万一。

你可能需要注意的几个选项：

- - OA—可以设置另一个包含别名（aliases）的文件。我们将在介绍 majordomo 时讨论这一点。
- - Mlocal—指定哪个程序作为邮件投递代理（MDA）。这可以是类似 `/bin/mail` 或 `/usr/bin/procmail` 的程序（我们之后也会介绍这些！）。
- - DS—配置指向智能中继主机的指针。如果你连接互联网的速度非常慢或者没有设置 DNS，你可以指定一台机器接收你所有的电子邮件并为你投递。对于拨号链路，你只需要发送一次电子邮件，永久连接到互联网的机器就可以将其保存在队列中。
- - Cw—如果你有一个具有多个名称的 Internet 主机（例如 wayga.net 和 ratatosk.org），此选项将生效。此条目允许你指定你希望作为哪个主机接收电子邮件。

## 7.1 使用 m4 文件

许多版本的 sendmail 都有选项自动生成你的 `sendmail.cf` 文件的。这允许你保留一个较小的文件，其中包含你想使用的大多数选项。在升级 sendmail 时，你只需要重新编译 `sendmail.cf` 即可让你的文件获得最新更新。m4 宏语言非常适合于此工作，并且包含了各种类型 `sendmail.cf` 文件的源文件。

如果你决定使用 m4 文件，请务必下载 sendmail 的源码，因为 RedHat 4.1 发行版默认不包含 m4 文件。m4 处理器默认安装，并位于 `/usr/bin`。

## 7.2 你有新邮件！

电子邮件已到达你的系统，在实际收到新邮件提醒之前，会有几件事发生。首先，sendmail 检查你的主目录下是否存在 `.forward` 文件。如果是，sendmail 将将电子邮件转发到 `.forward` 文件中指定的任何地址。如果你正在使用 procmail 并且有一个 `.procmail` 文件，sendmail 将运行 procmail 并遵循其中的规则。之后，sendmail 将电子邮件附加到名为 `/var/spool/mail/<USER>` 的文件中，其中 `<USER>` 是用户名。在创建新用户时，不需要创建该文件。创建别名允许将入站邮件路由到不同的用户或程序，即使系统中没有该名的用户账户。当你管理邮件列表时，这将产生很大影响。现在，你可能想检查 `/etc/aliases` 文件查看定义了哪些别名。这是一种拥有别名的方法。常见的 `/etc/aliases` 文件可能包含以下内容：

```
MAILER-DAEMON: postmaster
postmaster: root

# 通用重定向
daemon: root
games: root
nobody: root
uucc: root

# 已知别名
manager: root
operator: root

# 应该获取邮件的人
root: mark
mfk: mark
bren: brenda
bdk: brenda
```

如所示，你看到有很多别名，大多数都指向 root。在某些情况下（bin 和 nobody），这些账户存在，但不应该登录这些账户。在这种情况下，发送到 bin 的电子邮件仅仅被转发到 root。此外注意 postmaster 被设置为 root，在大多数情况下，管理邮件的人也管理系统的其余部分。MAILER-DAEMON 主要是用于邮件错误。稍后，你会看到一些用户别名。这些设置使得任何发送到“mfk@wayga.net”的电子邮件会自动进入 mark 账户。没有 mfk 账户，但人们可以发送到“bren@wayga.net”或“bdk@wayga.net”。小企业可能拥有 mark.komarinski, mfk.komarinski, markk.komarinski 以及其他名称变体的别名。这是一个经常被忽略但对于联系客户非常重要的事情。一旦邮件投递到正确的账户，comsat 就会运行；comsat 实际上告诉 shell 有新邮件。一旦 shell 获取了该信息，它可能会通知你。biff 会告诉你是否会收到通知，它还允许你开启或关闭它。y 开启，n 关闭。

现在你已经收到了电子邮件，你打算如何阅读它？这是 MUA（邮件用户界面）的工作。这是终端用户与之交互的唯一区域。从低功能（mail）到高功能全屏（elm, pine, mut）有几十个程序可用。你使用什么来读取邮件完全取决于你。例如，许多人喜欢用 pine 而不是 elm，但我发现 pine 进入实际邮件的菜单层太多了。如果你计划拥有许多用户，最好从 `/bin/mail` 安装几个 MUA。每个 MUA 都有优点。我的

## 7.3 MIME

当 SMTP 最初设计时，它只能处理 7 位（纯 ASCII）数据。因此，协议名称中有“Simple”（简单）。对于 JPEG 图像、音频文件、应用程序数据和压缩数据，必须有一种方法让这些二进制（8 位）数据通过 7 位流。处理此问题的种方法是通过 uuencode。该程序会将 2 字节 8 位数据转换为 3 字节 7 位数据。文件大小变大了，但它现在可以通过 SMTP 提供的 7 位路径。除了文件大小之外，另一个问题是远程必须解码数据（undecode）。这变成了一个繁琐的过程。

在 20 世纪 90 年代初开发了多用途互联网邮件扩展（MIME）来完成此工作，它现在被用于 Web 确定文件类型。MIME 对数据进行编码，以便使用标准方法定位和解码文件。一旦检测到文件类型，每个用户都可以拥有一个文件（.mailcap），其中列出你了解的文件类型，以及当你发现特定文件类型后要运行的应用程序。例如，如果发送了 JPEG 图像，接收端可能会启动 xv 程序。另一个用户可能将其设置为将图像转换为 PostScript 并直接发送到打印机。³大多数现代邮件程序都有处理 MIME 邮件的能力，作为管理员，你应该很少或完全不需要担心交互，除了为用户安装程序以及偶尔编辑 `/etc/mailcap` 文件（所有用户的默认 mailcap 文件）以添加你遇到的任何新条目。
