Despite these shortcomings, mSQL is still a very useful database server. For storing amounts of textual data that aren't too large, it is well suited. There are several other reasons you might want to use mSQL:

+   - It is lightweight, consuming only a small amount of system resources when simply running (as opposed to monsters like Oracle or Sybase which require many Mb of RAM simply to start up)
- It free for non-commercial use, and the shareware fee for commercial use is $200.
- Large install base and widespread support on the Net.
- As a side effect of its popularity, most of the more popular languages have support for mSQL, including C (the native API is for C), Python, Java, Perl, Tcl, PHP/I (a server-parsed scripting language which can be embedded (HTML)).

+   - Enhanced LIKE operators: RLIKE, which allows you to use the regular expression library and CLIKE, which is case-insensitive. Since there is a separate RLIKE that implements regex, LIKE and CLIKE do not need to do that and are thus faster than most other SQL operators typically implement at least a subset of regex's functionality.

# Lite and W3-mSQL

These two additional packages are part of the standard mSQL distribution.
Lite is a scripting language designed for use with mSQL. Its syntax is similar to Perl. Its variables are dynamically typed, its arrays are dynamically sized, and its variable names start with a $. Its chief advantage over other languages is its tight integration with mSQL.
