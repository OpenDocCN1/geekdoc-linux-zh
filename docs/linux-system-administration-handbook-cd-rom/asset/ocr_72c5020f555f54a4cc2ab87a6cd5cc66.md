# Stopping and Starting Connections

Ctlimnd is also used to control who can connect to the server to read, post, and feed articles over NNTP. To allow or disapp client readers, use the command "ctlimnd readers <flag> <reason>" where the <flag> starts with either "n", for disconnecting connections, or "y", for allowing connections, and the <reason> is the test fed to the client when it tries to connect. To recall connections the <reason> must match the <reason> given at the time of allowing or be an empty string. Similarly, issuing a "ctlimnd reject <reason>" command will reject any connection that would be handed off to nnrpd with the <reason> given as the explanation. To allow connections after a reject, issue the "ctlimnd allow <reason>" command where the <reason> must match that of the reject command or be an empty string.

To pause the server so that no incoming articles are accepted, issue the "ctlimnd pause <reason>" command and reenable connections with the "ctlimnd go <reason>" command. When pausing the server, no existing connections are closed but the history database is closed and written out to disk. This is only used for short-term locking, or when replacing the history file. Doing a pause also sends a note to the readers command so that no news may connect.

To stop incoming articles and sever all current connections, use the "ctlimnd throttle <reason>" command. This is a more long-term lock which closes the history base and sends a note to the readers command. To reenable connections, send a "ctlimnd go <reason>" command. Server throttling is normally done when expire is being run or extensive work is being done on some critical part of the news system.

# Expiring and Reporting

As mentioned above, expire is one of the news processes that shut down all connections to the server. Expire is one of the clean-up jobs that is from the script "news.daily" each night. The script news.daily is usually once a night but can be run more or less often if desired, from cron the news user.
