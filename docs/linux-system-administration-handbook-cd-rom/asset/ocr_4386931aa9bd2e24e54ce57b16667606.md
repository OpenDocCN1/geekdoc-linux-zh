Bar will run the SSHd (the SSH daemon) which gets started from either the inetd or bootup in daemon mode. If you have a lot of users with SSHd, it might be better to run in daemon mode as SSHd is always ready to make a connection.

The “configure” command sets the stage for compiling and then “make” compiles it. There are few other things you need to do for a typical installation.

The SSHd program runs on the server (bar) and should be started by startup. The client machine (foo) then issues an SSH command similar to login. The command to connect would look something like this:

```
ssh -l foo bar
```

If the bar host is not known to you, you'll get prompted if you want to add it to your list of known hosts. Add the host, and you'll be able to give your password to login.

The global configuration files are located in /etc. These files are /etc/ssh_config for server configuration and /etc/ssh_config for configuration. The options for these files are listed in the man pages for SSH and SSHd.

New hosts can be added to SSH in a global method using the make-SSHknown-hosts which finds all hosts in a domain that run SSH and gets their keys. Users can add their own hosts by copying the contents of /etc/ssh_host_key.pub into $HOME/.ssh/known_hosts. The public keys can be sent to any host—it doesn't matter if they're transferred in an insecure manner.

Users can create their own RSA keys using the SSH-key command, which creates a public/private key pair. If regular password authentication is not used, the RSA key generated by SSH-key is used. The public key (located in $HOME/.ssh/identity.pub) should be added to the $HOME/.ssh/authorized_keys of all the machines you want to log into.

# tcpd

The tcpd program can not only cut your off from a bad site but can also specify what sites can come in. This is a kind of “poor man's packet filter”, but it works pretty well for a small installation. The tcpd program matches an incoming IP address with a table. The “hosts.allow file, the connection is allowed. If the IP address is listed in the hosts.deny file, connection is refused. If the IP address matched neither, then access is granted.
