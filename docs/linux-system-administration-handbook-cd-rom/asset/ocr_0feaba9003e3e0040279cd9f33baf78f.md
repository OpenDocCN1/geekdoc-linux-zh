On top of all that, you can, since the code for the Linux kernels is freely available, compile your own custom kernel. This includes specifying drivers and features you wish to compile directly into the kernel and which you wish to leave as loadable modules.

The Linux developers have worked hard to make this as painless as possible, so this flexibility has not cost much ease of use as you might expect. The kernel has two menu-driven configuration options: X-based and the other screen-based. Additionally, there is the simple line-based, linear configuration.

# 18.2 Which Kernel?

If you are familiar with Linux, you probably already know that at any given time there are two current kernel versions: a production version and a developmental version (sometimes called experimental) kernels typically have experimental and sometimes buggy or unstable features, though it should be noted that a truly buggy release of either a production or developmental kernel will be fixed very quickly with a new version.

Production kernels always have an even release number, while development kernels are odd minor. The minor release number is the second of the three numbers that make up the kernel version number. For example, 1.3.88 is a development kernel, but 2.0.30 is a production kernel. The next minor revision up from a production kernel is developed in all with the production kernel (e.g., 1.2 and 1.3 were developed concurrently just as 2.0 and 2.1 are being developed concurrently now).

In general, unless you need a feature available only in a developmental kernel, it's usually best to stick with a recent production kernel. With the incredible flurry of version 1.3 releases (over a hundred!), the 2.0 kernel has a huge set of options to choose from and supports a wide range of hardware.
