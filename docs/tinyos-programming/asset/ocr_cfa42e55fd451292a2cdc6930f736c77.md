# 11.1.3 Atomic statements and the atomic keyword

The problems interrupts introduce means that programs need a way to execute snippets of code that won’t be preempted. nesC provides this functionality through atomic statements. For example:

```
command bool increment() {
  atomic {
    a++;
    b = a + 1;
  }
}
```

Listing 11.6 Incrementing with an atomic statement

The atomic block promises that these variables can be read and written atomically. In practice, on all current mote platforms, atomic statements are implemented by disabling and conditionally reenabling interrupts around the body of the atomic statement (this typically costs just a few cycles). In theory, a nesC implementation could allow incrementA and incrementC to preempt each other in this code snippet, as they access disjoint variables:

```
async command bool incrementA() {
  atomic {
    a++;
    b = a + 1;
  }
}
async command bool incrementC {
  atomic {
    c++;
    d = c + 1;
  }
}
```
