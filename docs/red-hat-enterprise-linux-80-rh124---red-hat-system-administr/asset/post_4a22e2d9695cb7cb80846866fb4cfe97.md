To troubleshoot problems, you might want to filter the output of the journal based on priority level. The journalctl -p takes either the name or the number of priority and shows the journal entries at priority above. When looking for events, you can limit the output to a specific time range. The journalctl command has options to limit the output to a specific time range, the --since and --until. Both options take an argument in the format "YYYY-MM-DD hh:mm:ss" (double-quotes are required to preserve the space). If the date is omitted, the command assumes the current day, and if the time is omitted, the command assumes yesterday and tomorrow. You can also specify all entries since a time relative to the present. For example, to specify all entries in the last hour, you can use the following:

```
[root@]# journalctl --since "-1 hour"
...output omitted...
```

In addition to the visible content of the journal, there are other fields that can be seen when verbose is on.

```
[root@]# journalctl -o verbose
Logs begins at Wed 2019-09-20 16:01:17 +07, and end Thu 2019-09-21 18:31:14 +07.
--output omitted...
```

The following list gives the common fields of the system journal that can be searched for lines relevant to a particular process:

- COMM The name of the command
- EXE The path to the executable
- PID The PID of the process
- UID of the user running the process
- SYSTEMD_UNIT The system unit that started the process

More than one of the system journal fields can be combined to form a granular search query with the journalctl command. For example, the journalctl command shows all entries related to the ssh.service system unit from a process with PID 1182.
