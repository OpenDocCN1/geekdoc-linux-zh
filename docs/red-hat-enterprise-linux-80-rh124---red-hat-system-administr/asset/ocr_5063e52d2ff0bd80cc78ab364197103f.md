# Monitoring and Managing Linux Processes

| SIGNAL NUMBER | SHORT NAME | DEFINITION | PURPOSE |
|---|---|---||}{
| 19 | STOP | Stop, unblockable | Suspends the process. Cannot be blocked or handled. |
| 20 | TST | Keyboard stop | Unlike SIGSTOP, can be blocked, ignored, or handled. Sent by sending SUSP key combination (Ctrl+Z). |

> > NOTE Signal numbers vary on different Linux platforms, but signal names and meanings are standardized. For command use, it is advised to use signal names instead of numbers. The numbers discussed in this section are x86_64 systems.

Each signal has a default action, usually one of the following:

+   - Term - Cause a process to terminate (exit) at once.
- Core - Cause a process to save a memory image (core dump), then terminate.
- Stop - Cause a process to stop executing (suspend) and wait to continue (resume).

Programs can be prepared to react to expected event signals by implementing handler routines to ignore, replace, or extend a signal's default action.

# Commands for Sending Signals by Explicit Request

You signal your current foreground process by pressing a keyboard sequence to suspend (Ctrl+Z), kill (Ctrl+C), or core dump (Ctrl+\). However, you will use signal-sending commands to send signals to a background process or to processes in a different session.

Signals can be specified either by name (for example, -HUP or -SIGHUP) or by number (the related -1). Users may kill their own processes, but root privilege is required to kill processes owned by others.

The kill command sends a signal to a PID number. Despite its name, the kill command can be used for sending any signal, not just for terminating processes. You can use the kill -1 to list the names and numbers of all available signals.

```
[user@host ~] kill -1
1) SIGHUP 2) SIGINT 3) SIGQUIT 4) SIGILL 5) SIGTRAP
6) SIGART 7) SIGBUS 8) SIGPIPEPE 9) SIGKILL 10) SIGUSR1
11) SIGSEGV 12) SIGUSR2 13) SIGPIPE 14) SIGALRM 15) SIGTERM

... omitted.
```
