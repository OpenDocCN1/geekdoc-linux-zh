## SSH HOST KEYS

SSH secures communication through public-key encryption. When an SSH client connects to an SSH server, the server sends a copy of its public key to the client before the login in. This is used to set up the secure encryption for the communication channel and authenticate the server to the client.

When a user uses the ssh command to connect to an SSH server, the command checks if it has a copy of the public key for that server in its local known hosts files. The system administrator may have pre-configured it in `/etc/ssh/ssh_known_hosts`, or the user may have a ~/.ssh/known_hosts/ file in their home directory that contains the key.

If the client has a copy of the public key, ssh will compare the key from the known hosts files for that to the one it received. If the keys do not match, the client assumes that the network traffic to the server will be hijacked or that the server has been compromised, and seeks the user's confirmation on whether or not to continue the connection.

> Set the StrictHostKeyChecking parameter to yes in the user-specific ~/.ssh/config file or the system-wide /etc/ssh/ssh_config to cause the ssh command to always save the connection if the public keys do not match.

If the client does not have a copy of the public key in its known hosts, the ssh will ask you whether to log in anyway. If you do, a copy of the public key will be saved in your ~/.ssh/known_hosts so that the server's identity is automatically confirmed in the future.

## SSH Known Hosts Key Management

If a server's key is changed the key was lost due to hard drive failure, replaced for some legitimate reason, you will need to edit the known hosts files to make sure the entry for the old public key is replaced with an entry of the new public key in order to log without errors.

Public keys are stored in the /etc/ssh/ssh_known_hosts and each users'/.ssh/known_hosts on the SSH client. Each public key is on one line. The first line is a list of hostnames and IP addresses that share public key. The second is the encryption algorithm used for the last key is the key itself.

```
[user01@host ~$] cat -/.ssh/known_hosts
remotehost,172.25.250.11 ecdsa-sha256-nistp256
AAAEYJZHHNLOYTTMIbbdhNYANTAAAMlDIhNYANTAAAABBOi0e+FlantG6jul8Ag5NJ
+R1ZI2bWe6Yur6+r1f0F0OEaGfZ1kM3VTfgXfH53DWhnIb+6zf8w==
```

Each SSH server must connect to its public key in the /etc/ssh directory files with the extension .pub.

```
[user01@remotehost ~$] ls -l /etc/ssh/*key.pub
/etc/ssh/ssh_host_ecdsa_key.pub /etc/ssh/ssh_host_ed25519_key.pub /etc/ssh/
_host_rsa_key.pub
```

> NOTE
it is a good practice to add entries matching a server's ssh_host_*.key.pub files to your ~/.ssh/known_hosts file or to the system-wide /etc/ssh/ssh_known_hosts file.
