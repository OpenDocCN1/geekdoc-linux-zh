# STANDARD INPUT, STANDARD OUTPUT, AND STANDARD ERROR

A running program, or process, needs to read input from somewhere and write output to somewhere. A command run from the shell prompt reads its input from the keyboard and sends its output to its terminal window.

A process uses numbered channels file descriptors to get input and send output. All processes start with at least three file descriptors. Standard input (channel 0) reads input from the keyboard. Standard output (channel 1) sends output to the terminal. Standard error (channel 2) sends error messages to the terminal. If a program opens separate connections to other files, it may use higher-numbered file descriptors.

![](img/59afb92e10b67a9cecc358a2c65e93b5_145_0.png)

Channels (File Descriptors)

| NUMBER | CHANNEL NAME | DESCRIPTION | DEFAULT CONNECTION | USAGE |
|---|---|---|---||-|
| 0 | stdin | Standard input | Keyboard | read only |
| 1 | stdout | Standard output | Terminal | write only |
| 2 | stderr | Standard error | Terminal | write only |
| 3+ | filename | Other files | none | read and/or write |

# REDIRECTING OUTPUT TO A FILE

I/O redirection changes how the process gets its input or output. Instead of getting input from the keyboard, or sending output and errors to the terminal, the process reads from or writes files. Redirection lets you save messages to a file that are normally sent to the terminal window. Alternatively, you can use redirection to discard output or errors, so they are not displayed on the terminal or saved.

Redirecting stdout suppresses output from the terminal. As seen in the following table, redirecting only stdout does not suppress stderr error messages from displaying on the terminal. If the file does not exist, it will be created. If the file exists and the redirection is not one that appends to the file, the file's contents will be overwritten.

If you want to discard, the special file /dev/null quietly discards channel output redirected to it and is always an empty file.

# Output Redirection Operators

| USAGE | EXPLANATION | VISUAL AID |
| :--- | :--- | :--- |
| > file | redirect stdout to overwrite a file | ![1 stdout -> PROCESS -> file, 2 stderr -> file](https://example.com/image1.png) |
| >> file | redirect stdout to append to a file | ![1 stdout -> PROCESS -> file, 2 stderr -> file](https://example.com/image2.png) |
| 2> file | redirect stderr to overwrite a file | ![1 stdout -> PROCESS, 2 stderr -> PROCESS -> file](https://example.com/image3.png) |

> IMPORTANT
The order of redirection operations is important. The following sequence redirects standard output to **file** and then redirects standard error to the same place as standard output (**file**).

```
> file 2>&1
```

However, the next sequence does redirection in the opposite order. This redirects standard error to the default place for standard output (the terminal window, so no no change) and then redirects only standard output to **file**.
```
2>&1 > file
```

Because of this, some people prefer to use the merging redirection operators:

| | >file 2>&1 |
|---|---|
| | &file instead of >&file instead of | >>file 2>&1 (in Bash 4 / RHEL 6 and later) |

However, system administrators and programmers who also use other shells related to **bash** (known as Bourne-compatible shells) for scripting commands that the newer merging redirection operators should be avoided, because they are not standardized or implemented in all of those shells and have other limitations.

The authors of this course take a neutral stance on this topic, and both syntaxes are likely to be encountered in the field.

# Examples for Output Redirection

Many routine administration tasks are simplified using redirection. Use the previous table to assist while considering the following examples:

- Save a time stamp for later reference.
- `[user@host ~$ date > /tmp/saved-timestamp`
- Copy the 100-line-log (Note: original text was cut off, assuming 'log' based on context)
- Copy the 100 lines from a log file to another file.
- `[user@host ~$ tail -n 100 /var/log/dmesg > /tmp/last-100-messages`
- Concatenate four files into one.
- `[user@host ~$ cat file1 file2 file3 file4 > /tmp/all-in-one`
- List the home directory's hidden and regular names into a file.
- `[user@host ~$ ls -a > /tmp/file-names`

- Append output to an existing file.
```
[user@host ~$ echo "new line of information" >> /tmp/many-lines-of-information
[user@host ~$ diff previous-file current-file >> /tmp/tracking-changes
```

The next few commands generate error messages because some directories are inaccessible to normal users. Observe the error messages are redirected. Redirect errors to a file while viewing normal command output on the terminal.

```
[user@host ~$ find /etc -name passwd 2> /tmp/errors
```

Save process output and error messages to separate files.

```
[user@host ~$ find /etc -name passwd > /tmp/output 2 /tmp/errors
```

Ignore and discard error messages.

```
[user@host ~$ find /etc -name passwd > /tmp/output 2 /dev/null
```

Store output and generated errors together.

```
[user@host ~$ find /etc -name passwd &> /tmp/save-both
```

Append output and generated errors to an existing file.

```
[user@host ~$ find /etc -name passwd >> /tmp/save-both 2>&1
```

# CONSTRUCTING PIPELINES

A pipeline is a sequence of one or more commands separated by the pipe character (|). A pipe connects the standard output of the first command to the standard input of the next command.

![](img/59afb92e10b67a9cecc358a2c65e93b5_148_0.png)

Pipelines allow the output of a process to be manipulated and formatted by others before it is output to the terminal. Useful mental image is to imagine that data is "flowing" through the pipeline from one process to another, being altered slightly by each command in the pipeline through which it flows.

> NOTE Pipelines and I/O redirection both manipulate standard output and standard input. Redirection sends standard output to files or gets standard input from files. Pipes send the standard output from one process to the standard input of another process.
