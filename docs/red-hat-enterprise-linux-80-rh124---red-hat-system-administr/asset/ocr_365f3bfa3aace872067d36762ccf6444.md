# MANAGING USER PASSWORDS

# OBJECTIVES

After completing this section, you should be able to set a password management policy for users, and manually lock and unlock user accounts.

# SHADOW PASSWORDS AND PASSWORD POLICY

At one time, encrypted passwords were stored in the word-readable /etc/passwd file. This was thought to be reasonably secure until dictionary attacks on encrypted passwords became common. At that point, the encrypted passwords were moved to a separate /etc/shadow file which is read only by root. This new file also allowed password aging and expiration features to be implemented.

Like /etc/passwd, each user has a line in the /etc/shadow file. A sample line from /etc/shadow with nine colon-separated fields is shown below.

```
user0:$6$sCsXx..output omitted...::17933:8:99999:7:2:18113:::
```

+   Username of the account this password belongs to.
The encrypted password of encrypted passwords is discussed later in this section.
The day on which the password was last changed. This is set in days since 1970-01-01, and is calculated in the UTC time zone.
The minimum number of days that have elapse since the last password change before the user can change it.
The maximum number of days that can pass without a password change before the password expires. An empty field means it does not expire on time since the last change.
Warning period. The user will be warned about expiring password when they log in for number of days before the deadline.
Inactivity period. Once the password has expired, it will still be eligible for login for many days. After this period has elapsed, the account will be locked.
The day on which the password expires. This is set in days since 1970-01-01, and is calculated in the UTC time zone. An empty field means it does not expire on time on a particular date.
The last field is used entirely and reserved for future use.

# Format of an Encrypted Password

The encrypted password field stores three pieces of information: the hashing algorithm used, the salt, and the encrypted hash. Each piece of information is delimited by a $

```
$6$sCsXxG1/42fHR/$2w6evvJaufZfpc0X.45JCH30E..output omitted...
```

+   The hashing algorithm used for this password. The number 6 indicates it a SHA-512 hash, which is defined in Red Hat Enterprise Linux 8. A 1 would indicate MD5, a 5 SHA-256.
The salt used to encrypt the password. This is originally chosen at random.
