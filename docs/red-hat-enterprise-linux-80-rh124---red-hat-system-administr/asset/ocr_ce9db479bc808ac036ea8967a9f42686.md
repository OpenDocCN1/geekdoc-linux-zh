For example, two variables that affect the shell history and the history command are NHISTFILE and HISTFILESIZIZE. If HISTFILE is set, it specifies the location of a file to save
shell history when it exits. By default it is the user's `/.bash_history`.
HISTFILESIZIZE variable specifies how many commands should be saved in that file from the
history.

Another example is PS1, which is a variable that controls the appearance of the shell prompt.
If you change the value, it will change the appearance of your shell prompt. A number of special
character expansions supported by the prompt are listed in the "PROMPTING" section of the
`bash(1)` page.

```
```
[user@host ~]$ PS1=\bash"
$ bash PS1="\u@\w \$
[user@host ~]
```
```

Two items to note about the above example: first, because the value set by PS1 is a prompt, it is
vually always desirable to end the prompt with a space. Second, regardless of the value of
a variable contains some form of shape, including a space, a tab, or a return, the value must be
srounded by quotes, either single or double: this is not optional. Unexpected results will occur
if the quotes are omitted. Examine the PS1 example above and note that it conforms to both
recommendation (trailing space) and rule (quotes).

# # CONFIGURING PROGRAMS WITH ENVIRONMENT_VARIABLES

The shell provides an environment to the programs you run from that. Among other things,
this environment includes information on the current working directory on the file system,
command-line options passed to the prompt, and the values of environment variables. The
programs may use these environment variables to change their behavior or their default settings.

Shell variables that are not environment variables can only be used by the shell. Environment
variables can be used by the shell and by programs from that shell.

> NOTE\NHISTFILE, HISTFILESIZIZE, and PS1, learned in the previous section, do not need
to be exported as environment variables because they are only used by the shell
itself, not by the programs that run from the shell.

You can make any variable defined in the shell into an environment variable by marking it for
export with the export command.

```
```
[user@host ~]$ EDITOR=vim
[user@host ~]$ export EDITOR
```
```

You can export a variable in one step:

```
```
[user@host ~]$ export EDITOR=vim
```
```

Applications and sessions use these variables to determine their behavior. The shell
automatically sets the HOME variable to the file name of the user's home directory when it starts.
This can be used to help programs determine where to save files.
