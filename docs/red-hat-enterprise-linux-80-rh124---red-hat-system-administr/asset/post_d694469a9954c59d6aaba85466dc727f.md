## The Minimum, Basic Vim Workflow

Vim has efficient, coordinated keystrokes for advanced editing tasks. Although considered useful with practice, Vim's capabilities can overwhelm new users.

The `i` puts Vim into insert mode. All text entered here is treated as content until you exit insert mode. The Esc key exits insert mode and returns Vim to command mode. The `u` key will undo the most recent edit. The `x` key deletes a single character. The `:w` writes (saves) the file and `:wq` writes (saves) the file and quits Vim. The `:q` quits Vim, discarding all file changes since the last write. Vim users learn these commands to accomplish any editing task.

## Rearranging Existing Text

In Vim, copy and paste is known as yank and put, using command `y` and `p`. Begin by positioning the cursor on the first character to be selected, and then enter visual mode. Use the arrow keys to expand the visual selection. When ready, press `y` to yank and `y` to put the selection into memory. Position the cursor at the new location, and press `p` to put the selection at the cursor.

## Visual Mode in Vim

Visual mode is a great way to highlight and manipulate text. There are three keystrokes:

- Character mode: `v`
- Line mode: `Shift+V`
- Block mode: `Ctrl+V`

Character mode highlights sentences in a block of text. The word VISUAL will appear at the bottom of the screen. Press `v` to enter visual mode. `Shift+V` enters line mode. VISUAL LINE will appear at the bottom of the screen.

Visual block is perfect for manipulating data files. From the cursor, press `Ctrl+V` to enter visual block. VISUAL BLOCK will appear at the bottom of the screen. Use the arrow keys to highlight the section to change.

> NOTE: Vim has a lot of capabilities, but you should master the basic workflow first. You do not need to quickly understand the entire editor and its capabilities. Get comfortable with those basics through practice and then you can expand your vocabulary by learning additional Vim commands (keystrokes).

### OBJECTIVES

## USING SHELL VARIABLES

The Bash shell allows you to set shell variables that can help run commands or to modify the behavior of the shell. You can also export shell environment variables, which are automatically copied to programs run from shell when they start. You can use variables to make it easier to run a command with a long argument, or to apply a common setting to commands run from that shell.

Shell variables are unique to a particular shell session.

### Assigning Values to Variables

Assign a value to a variable using the following syntax:

```
VARIABLE=value
```

Variable names can contain uppercase or lowercase letters, digits, and the underscore (_).

```
[user@host ~]$ COUNT=40
[user@host ~]$ first_name=John
[user@host ~]$ file1=abc
[user@host ~]$ ID=123
```

Remember, this change only affects the shell.

You can use the `set` command to list all variables that are currently set. (It also lists functions.) This list is long enough that you may want to pipe the output into `less` so you can view one page at a time.

```
[user@host ~]$ set | less
BASH:/bin/bash
BASHOPTS=checkwinsize:cdhist:complete_fullquote:extglob:
...
...
BASHSOURCE=Y
```

## Retrieving Values with Variable Expansion

You can use variable expansion to refer to a variable you have set. To do this, precede the name of the variable with a dollar sign ($). In the following example, the echo command prints the rest of the command line, after variable expansion is performed.

For the example, the following command sets the variable COUNT to 40.

```
[user@host ~]$ COUNT=40
```

If you enter the command echo COUNT, it will print the string COUNT.

```
[user@host ~]$ echo COUNT
COUNT
```

But if you enter the command echo $COUNT, it will print the value of the variable COUNT.

```
[user@host ~]$ echo $COUNT
40
```

A more practical example might be to use a variable to refer to a long file name for multiple commands.

```
[user@host ~]$ file1=/tmp/tmp.zp9W0Hqcc
[user@host ~]$ ls -l $file1
-rw------- 1 student student 1452 Jan 22 14:39 /tmp/tmp.zp9W0Hqcc
[user@host ~]$ rm $file1
[user@host ~]$ ls -l $file1
total 0
```

> IMPORTANT
If there are any trailing characters adjacent to the variable name, you might need to protect the variable name with curly braces. You can always use curly braces in variable expansion, but you will also see many examples in which they are not needed and are omitted.

In the following example, the first command tries to expand the nonexistent variable COUNTx, which does not cause an error but instead returns nothing.

```
[user@host ~]$ echo Repeat COUNTx
Repeat
[user@host ~]$ echo Repeat$(COUNT)x
Repeat 48x
```
