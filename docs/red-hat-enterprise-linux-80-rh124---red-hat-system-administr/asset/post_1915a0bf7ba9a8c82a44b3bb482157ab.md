
# CHAPTER IV | Configuring and Securing SSH

> NOTE
> When you run ssh-agent, it prints out some shell commands. You need to run these commands to set environment variables by programs like ssh-add to communicate with it. The eval ${ssh-agent} command starts ssh-agent and runs those commands to automatically set those environment variables for shell session. it also displays the PID of the ssh-agent process.

Once ssh-agent is running, you need to tell it the passphrase for your private key or keys. You can do this with the ssh-add command.

The following ssh-add command adds private keys for /home/user/.ssh/id_rsa (the default) and /home/user/.ssh/key-with-pass, respectively.

```
[user@host ~]$ ssh-add
Identity added: /home/user/.ssh/id_rsa (user@host.example.com)
[user@host ~]$ ssh-add .ssh/key-with-pass
Enter passphrase for .key-with-pass: redpass
Identity added: .ssh/key-with-pass (user@host.example.com)
```

After successfully adding the private keys to the ssh-agent process, you can invoke an SSH connection using the ssh command. If you use any private key other than the default /home/user/.ssh/id_rsa file, then you must use the -i option with the ssh command to specify the path to the private key.

The following example of the ssh command uses the default private key to authenticate to an SSH server.

```
[user@host ~]$ ssh user@remothost
Last login: Fri Apr 5 10:53:50 2019 from host.example.com
[user@remothost ~]$
```

The following example of the ssh command uses the /home/user/.ssh/key-with-pass (non-default) private key to authenticate to an SSH server. The private key in the following example has already been decrypted and added to your ssh-agent process, so the ssh command does not prompt you to decrypt the private key by interactively entering its passphrase.

```
[user@host ~]$ ssh -i .ssh/key-with-pass user@remothost
Last login: Mon Apr 8 09:44:20 2019 from host.example.com
[user@remothost ~]$
```

When you log out of the session that started ssh-agent, the process will exit and your passphrases for your private keys will be cleared from memory.

# GUIDED EXERCISE

# CONFIGURING SSH KEY-BASED AUTHENTICATION

In this exercise, you will configure a user to use key-based authentication for SSH.

You should be able to:

- Generate an SSH key pair without passphrase protection.
- Generate an SSH key pair with passphrase protection.
- Authenticate using both passphrase-less and passphrase-protected SSH keys.

- 8. Execute the hostname command on server remotely via SSH without accessing the remote interactive shell. Use /home/operator1/.ssh/key2 as the identity file. Specify redpass as the passphrase, which you set for the private key in the preceding step.

```
[operator1@server ~$ ssh -i .ssh/key2 operator1@server hostname
Enter passphrase for key '.ssh/key2': redpass
servera.lab.example.com
```

Notice that the preceding command prompted you for the passphrase you used to protect the key of the SSH key pair. This passphrase protects the private key. Should an attacker gain access to the key, the attacker cannot use it to access other systems because the key itself is protected with a passphrase. The ssh command uses a different passphrase than the one for operator1 on servera, requiring users to know both.

You can use ssh-agent, in the following step, to avoid interactively typing the passphrase while logging in with SSH. Using ssh-agent is both more convenient and more secure in situations where the administrators log in to systems regularly.

- 9. Run ssh-agent in your Bash shell and add the passphrase-protected private key (/home/operator1/.ssh/key2) of the SSH key to the shell session.

```
[operator1@server ~$ eval $(ssh-agent)
Agent pid@server ~$ ssh-add .ssh/key2
Enter passphrase for key '.ssh/key2': redpass
Identity added: .ssh/key2 (operator1@server.lab.example.com)
```

The preceding eval command started ssh-agent and configured this shell session to use it. You used ssh-add to provide the unlocked private key to ssh-agent.

- 10. Execute the hostname command on server remotely without accessing the remote interactive shell. Use /home/operator1/.ssh/key2 as the identity file.

```
[operator1@server ~$ ssh -i .ssh/key2 operator1@server hostname
servera.lab.example.com
```

Notice that the preceding ssh command did not prompt you to enter the passphrase interactively.
