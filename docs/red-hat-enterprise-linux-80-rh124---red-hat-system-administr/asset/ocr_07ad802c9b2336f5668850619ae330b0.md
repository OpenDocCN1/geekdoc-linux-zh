# CONFIGURING AND MONITORING CHRONYD

The chronyd service keeps the usually-inaccurate local hardware clock (RTC) on track by synchronizing to the configured NTP servers. If no network connectivity is available, chronyd calculates the clock drift, which is recorded in the driftfile at the /etc/chronyd.conf file.

By default, chronyd uses servers from the NTP Pool Project for time synchronization and does not need additional configuration. It may be useful to change the NTP servers when the machine in question is an isolated network.

The stratum of NTP time determines its quality. The stratum determines the number of hops the machine is away from a high-performance reference clock. The reference clock is a stratum 0 time source. An NTP server directly attached to it is a stratum 1, while a machine synchronizing from the NTP server is a stratum 2 time source.

The server and peer are the two types of time sources that you can use in the /etc/chronyd.conf configuration file. The server is one stratum above the local NTP server, and the peer is at the same stratum level. More than one server and more one peer can be specified, per line.

The first argument of the server line is the IP address or DNS name of the NTP server. Following a series of options for the server can be listed. It is recommended to use the iburst option, after the service starts, four measurements are taken in a short time period for a more accurate initial clock synchronization.

The following server line classroom.example.com iburst line in the /etc/chronyd.conf file causes the chronyd service to use the classroom.example.com NTP time source.

```
# Use public servers from the pool.ntp.org project.
...output omitted...
server classroom.example.com iburst
...output omitted...
```

After pointing chronyd to the local server, classroom.example.com, you should restart the service.

```
[root@host ~]# systemctl restart chronyd
```

The chronyd command acts as a client to the chronyd service. After setting up NTP synchronization, you should verify that the local system is seamlessly to synchronize the system clock using the chronyd sources command. For more verbose output with additional explanations about the output, use the chronyc sources -v command.
