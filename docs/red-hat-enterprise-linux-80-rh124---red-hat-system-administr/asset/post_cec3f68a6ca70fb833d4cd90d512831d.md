
## Creating Soft Links

The `ln -s` command creates a soft link, which is also called a "symbolic link." A soft link is not a regular file, but a special type of file that points to an existing file or directory.

Soft links have some advantages over hard links:

- They can link two files on different file systems.
- They can point to a directory or special file, not just a regular file.

In the following example, the `ln -s` command is used to create a new soft link for the existing file `/home/user/newfile-link.2` which will be named `/tmp/newfile-symlink.txt`.

```bash
[user@host]$ ln -s /home/user/newfile-link.2 /tmp/newfile-symlink.txt
[user@host]$ ls -l newfile-link.2 /tmp/newfile-symlink.txt
-rw-rw-r-- 1 user 1 user Mar 12 11:29 newfile-link.2
lrwxrwxrwx 1 user 1 user Mar 12 11:20:59 /tmp/newfile-symlink.txt -> /home/user/newfile-link.2
[user@host]$ cat /tmp/newfile-symlink.txt
Hello
```

In the preceding example, the first character of the long listing for `/tmp/newfile-symlink.txt` is `l` instead of `-`. This indicates that the file is a soft link and not a regular file. (A `d` would indicate that the file is a directory.)

When the original file gets deleted, the soft link still points to the target but the target is missing. A soft link pointing to a missing file is called a "dangling link."

```bash
[user@host]$ rm -f newfile-link.2
[user@host]$ ls -l /tmp/newfile-symlink.txt
lrwxrwxrwx 1 user 1 user Mar 12 11:20:59 /tmp/newfile-symlink.txt -> /home/user/newfile-link.2
[user@host]$ cat /tmp/newfile-symlink.txt
cat: /tmp/newfile-symlink.txt: No such file or directory
```

> IMPORTANT: The dangling soft link in the preceding example shows that if you later create a new file with the same name as the deleted file (`/home/user/newfile-link.2`), the soft link will no longer be "dangling" and will point to the new file.

Hard links do not work like this. If you delete a hard link and use normal tools (rather than `ln`) to create a new file with the same name, the new file will not be linked to the old file. One way to compare hard links and soft links might help you understand how they work:

- A hard link points to data on a storage device.
- A soft link points to another name that points to data on a storage device.
- A soft link can point to a directory. The soft link acts like a directory. Changing the soft link with `cd` will make the current working directory the linked directory. Some tools may keep track of the fact that you followed a soft link to get there, by default.

In the following example, a soft link named `/home/user/configfiles` is created that points to the `/etc` directory.

```bash
[user@host]$ ln -s /etc /home/user/configfiles
[user@host]$ cd /home/user/configfiles
[user@host]$ pwd
/home/user/configfiles
```

## MATCHING FILE NAMES WITH SHELL EXPANSIONS

### OBJECTIVES

After completing this section, you will be able to efficiently manage files using pattern matching.

### COMMAND-LINE EXPANSIONS

The shell has multiple ways of expanding command line: brace expansion, variable substitution. Perhaps the most powerful of these is globbing.

### Pattern Matching

Globbing is a shell operation that expands a wildcard to match file names. The following are common metacharacters and classes:

| PATTERN | MATCHES |
| :--- | :--- |
| `*` | Any string of more characters. |
| `?` | Any single character. |
| `[abc...]` | Any character in square brackets. |
| `[^abc...]` | Any character *not* in square brackets. |
| `[:alpha:]` | Any alphabetic character. |
| `[:lower:]` | Any lowercase character. |
| `[:upper:]` | Any uppercase character. |
| `[:alnum:]` | Any alphabetic or digit. |
| `[:punct:]` | Any printable character not alphanumeric. |
| `[:digit:]` | Any single digit from 0 to 9. |
| `[:space:]` | Any single white character. |

For the next examples, pretend that you have run the following commands to create some files.

```bash
[user@host]$ mkdir glob; cd glob
[user@host]$ touch alpha bravo charlie delta echo dog
[user@host]$ ls
alfa bravo charlie delta dog echo
```

The first example will use simple patterns with the asterisk (`*`) and question mark (`?`), a class of characters, to match those of files.

```bash
[user@host]$ ls a*
alfa alfa
[user@host]$ ls 'a*'
alfa bravo charlie delta
[user@host]$ ls ????
alfa alfa delta echo
[user@host]$ ls ????
baker bravo
```

## Tilde Expansion

The tilde character (`~`) matches the current user's home directory. If it starts a string of characters not a slash (`/`), the shell will interpret the string as absolute path to user name, if one matches, and replace the string with the absolute path to that user's home directory. If no user name matches, an actual tilde followed by the characters will be used instead.

In the following example the echo command is used to display the value of the tilde character. The echo command can also be used to display the values of brace and variable expansion, and others.

```bash
[user@host]$ ls ~root
/root
[user@host]$ ls ~user
/home/user
[user@host]$ ls ~glob
alfa bravo baker charlie delta dog echo
[user@host]$ echo ~glob
/home/user/glob
```

## Brace Expansion

Brace expansion is used to generate discretionary strings of characters. Braces contain a comma-separated list of strings, or a sequence expression. The result includes the text preceding or following the brace definition. Braces may be nested, one inside another. Also double-syntax `(...)` expands to a sequence such that `{m..p}` will expand to tom m n p.
