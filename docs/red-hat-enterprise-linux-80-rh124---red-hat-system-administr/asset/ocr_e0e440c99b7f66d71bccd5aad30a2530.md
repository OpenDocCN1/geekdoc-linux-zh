# LOGGING USERS ADMINISTRATIVELY

You may need to log other users for any variety of reasons. To name few of the many possibilities: the user committed a security violation; the user may have overwhelmed resources; the user may have an unresponsive system; or they may have access to materials. In cases, you may need to administratively terminate their session using signals.

To log off a user, first identify the session to terminate. Use the **w** command to list user logins and current running processes. Note the **TTY** and **FROM** columns to determine the sessions to close.

All user login sessions are associated with a terminal device (TTY). If the device name is of the form **pts/N**, it is a **pseudo-terminal** associated with a graphical terminal or remote login session. If it is of the form **ttyN**, the user is on a system console, alternate console, or directly connected terminal.

```
[user@host ~]$ w
12:43:06 up 27 min, 5 users,  load average: 0.03, 0.17, 0.66
USER     FROM             LOGIN   IDLE   JCPU WHAT
root     tty2             12:26  14:58  0.04  0.04s -bash
bob      tty3             12:28  14:42  0.02  0.02s -bash
user     pts/1            desk.example.com 12:41  2.06s  0.03s w
[user@host ~]$
```

Discover how long a session has been on the system by viewing the session login time. For each user, CPU resources consumed by current jobs, including background tasks and child processes, are in the **PCPU** column. Current foreground CPU consumption is in the **PCPU** column.

Processes and sessions can be killed individually or collectively signaled. To terminate all processes for one user, use the **kill command**. Because the initial process in a login session (**session leader**) is designed to handle session termination requests and ignore unintended keyboard signals, killing all of a user's processes and login shells requires the **SIGKILL** signal.
