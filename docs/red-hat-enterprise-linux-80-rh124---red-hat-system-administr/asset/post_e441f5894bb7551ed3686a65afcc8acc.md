## PROCESS CONTROL USING SIGNALS

A signal is a software interrupt delivered to a process. Signals report events to an executing program. Events that generate a signal can be an error, external event (such as an I/O request or an expired timer), or by explicit request (the use of a signal-sending command or a keyboard sequence).

The following table lists the fundamental signals used for routine process management. Refer to signals by either their short (HUP) or proper (SIGHUP) name.

## Fundamental Process Management Signals

| SIGNAL NUMBER | SHORT NAME | DEFINITION | PURPOSE |
|---|---|---|---|
| 1 | HUP | Hangup | Usedused to report termination of the controlling process of a terminal. Also used to request process reinitialization (configuration reload) without termination. |
| 2 | INT | Keyboard interrupt | Causes program termination. Can be blocked or handled. Sent by pressing INTR combination **Ctrl-C**. |
| 3 | QUIT | Keyboard quit | Similar to SIGINT, but also produces a process dump at termination. Sent by pressing QUIT combination **Ctrl+\**. |
| 9 | KILL | Kill, unblockable | Causes program termination. Cannot be blocked, ignored, or handled; always allows. |
| 15 default | TERM | Terminate | Causes program termination. Unlike SIGKILL, it can be blocked, ignored, or handled. The "polite" way to ask a process to terminate; allows self-cleanup. |
| 18 | CONT | Continue | Sent to a process to resume, if stopped. Cannot be blocked. Even if handled, always resumes the process. |

## Monitoring and Managing Linux Processes

| SIGNAL NUMBER | SHORT NAME | DEFINITION | PURPOSE |
|---|---|---|---|
| 19 | STOP | Stop, unblockable | Suspends the process. Cannot be blocked or handled. |
| 20 | TST | Keyboard stop | Unlike SIGSTOP, can be blocked, ignored, or handled. Sent by sending SUSP key combination (Ctrl+Z). |

> NOTE: Signal numbers vary on different Linux platforms, but signal names and meanings are standardized. For command use, it is advised to use signal names instead of numbers. The numbers discussed in this section are x86_64 systems.

Each signal has a default action, usually one of the following:

- Term - Cause a process to terminate (exit) at once.
- Core - Cause a process to save a memory image (core dump), then terminate.
- Stop - Cause a process to stop executing (suspend) and wait to continue (resume).

Programs can be prepared to react to expected event signals by implementing handler routines to ignore, replace, or extend a signal's default action.

## Commands for Sending Signals by Explicit Request

You signal your current foreground process by pressing a keyboard sequence to suspend (Ctrl+Z), kill (Ctrl+C), or core dump (Ctrl+\). However, you will use signal-sending commands to send signals to a background process or to processes in a different session.

Signals can be specified either by name (for example, -HUP or -SIGHUP) or by number (the related -1). Users may kill their own processes, but root privilege is required to kill processes owned by others.

The kill command sends a signal to a PID number. Despite its name, the kill command can be used for sending any signal, not just for terminating processes. You can use the kill -1 to list the names and numbers of all available signals.

```
[user@host ~] kill -1
1) SIGHUP 2) SIGINT 3) SIGQUIT 4) SIGILL 5) SIGTRAP
6) SIGART 7) SIGBUS 8) SIGPIPE 9) SIGKILL 10) SIGUSR1
11) SIGSEGV 12) SIGUSR2 13) SIGPIPE 14) SIGALRM 15) SIGTERM
16) SIGVTRT 17) SIGCHILD 18) SIGCONT 19) SIGSTOP 20) SIGTSTP
... omitted.
[user@host ~] ps aux | grep

Use kill to send a signal to one or more processes. The kill command includes selection criteria:

- Command - Processes with a pattern-matched name.
- UID - Processes owned by a Linux user account, real.
- GID - Processes owned by a Linux group account, real.
- Parent - Processes of a specific parent process.
- Terminal - Processes running on specific controlling terminal.

```
[user@host-$] ps aux | grep job

## LOGGING USERS ADMINISTRATIVELY

You may need to log other users for any variety of reasons. To name a few of the many possibilities: the user committed a security violation; the user may have overwhelmed resources; the user may have an unresponsive system; or they may have access to materials. In cases, you may need to administratively terminate their session using signals.

To log off a user, first identify the session to terminate. Use the **w** command to list user logins and current running processes. Note the **TTY** and **FROM** columns to determine the sessions to close.

All user login sessions are associated with a terminal device (TTY). If the device name is of the form **pts/N**, it is a **pseudo-terminal** associated with a graphical terminal or remote login session. If it is of the form **ttyN**, the user is on a system console, alternate console, or directly connected terminal.
