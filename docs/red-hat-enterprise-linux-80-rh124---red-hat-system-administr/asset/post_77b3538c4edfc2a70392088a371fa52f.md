# SUMMARY

In this chapter, you learned:

- Files have three categories to which permissions apply. A file is owned by a user, a single group, and other users. The most specific permission applies. User permissions override group permissions and group permissions override other permissions.
- The ls command with the -l option expands the file listing to include both permissions and ownership. The chmod command changes file permissions from the command line. There are two methods to represent permissions, symbolic (letters) and numeric (digits).
- The chown command changes file ownership. The -R option recursively changes the ownership of a directory tree.
- The umask command without arguments displays the current umask value of the shell. Every process on the system has a umask. The default umask values are defined in /etc/profile and .bashrc.

### DEFINITION OF A PROCESS

A process is a running instance of a launched, executable program. A process consists of:

- An address space of allocated memory
- Security properties including credentials and privileges
- One or more execution threads of program code
- Process state

The environment of process includes:

- Local and global variables
- A current scheduling context
- Allocated resources, such as file descriptors and network ports

An existing (parent) process duplicates its address space (fork) to create a new (child) process. Every new process is assigned a unique process ID (PID) for tracking and security. The PID and parent's process ID (PPID) are elements of the new process environment. Any process may create a child process. All processes are descendants of the first process, systemd on Red Enterprise Linux system. Through the fork routine, a child process inherits identities, previous and current file descriptors, privileges, and program code. A process may exit its own request (wait) to be signaled when the child completes. Upon exit, the parent process sleeps while the child has already discarded its resources and environment. The only remaining resource, called a zombie, is an entry in the process table. The parent, signaled when the child exited, cleans the process table of the child's entry, freeing the resource of the child process. The parent then continues with its own execution.

### DESCRIBING PROCESS STATES

In a multitasking system, each CPU (or CPU core) can be working on one process at a single point in time. As a process runs, its immediate requirements for CPU time and resource allocation are assigned a state, which changes as circumstances dictate.

# Linux Process States

| NAME | FLAG | KERNEL-DEFINED STATE AND DESCRIPTION |
|---|---|---|
| Running | R | TASK_RUNNING: The process is executing on a CPU or waiting to run. Process can be executing user routines or kernel routines (system calls), and be queued and ready when in *Running* (or *Runnable*) state. |
| | S | TASK_INTERRUPTIBLE: The process is waiting for some condition: a hardware request, system resource access, or signal. When an event satisfies the condition, the process returns to *Running*. |
| Sleeping | D | TASK_UNINTERTIBLE: This process is also *Sleeping*, but unlike S state, does not respond to signals. Used only when process interruption may cause an unpredictable device state. |
| | K | TASK_KILLABLE: Identical to the uninterruptible **D** state, but modified to allow a waiting task to respond to the signal that it will be killed (exit completely). Utilities frequently display *Killable* processes as **D** state. |

# KERNEL-DEFINED STATE AND DESCRIPTION

| NAME | FLAG | DESCRIPTION |
|---|---|---|
| | I | TASK_REPORT_IDLE: A subset of D. The kernel does not count these processes when calculating load used. For kernel threads, Flags TASK_UNINTERTIBLE and TASK_NOLOAD are set. Similar to TASK_KILLABLE, also a subset of state D. It accepts fatal signals. |
| T | TASK_STOPPED: The process has been Stopped (suspended), until being signaled by a user or other process. The process can be continued (resumed) by another signal to return to Running. |
| Z | TASK_TRACE: A process that is being debugged is also temporarily Stopped and shares the same T flag. |
| Zombie | EXIT_ZOMBIE: A child process signals its parent as it exits. All resources except for the process identity (ID) are released. |
| X | EXIT_DEAD: When the parent reaps (the remaining child process structure, the process is now released completely. This state will never be observed in process-listing utilities. |

# Why Processes Are Important

When troubleshooting a system, it is important to understand how the kernel communicates with processes and how processes communicate with each other. At each process, the system assigns the process state. The S column of the top command or the STAT column of the ps shows the state of each process. On a single CPU system, only one process can run at a time. It is possible to see several processes with a state of R. However, not all of them will be running concurrently. Some will be in waiting state.

```
@user@host~$ ps aux

...omitted....
```
