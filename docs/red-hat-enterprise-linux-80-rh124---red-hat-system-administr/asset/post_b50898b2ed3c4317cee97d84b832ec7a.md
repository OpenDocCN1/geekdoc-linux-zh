# UID Ranges

Specific UIDs and ranges of numbers are used for specific purposes by Red Hat Enterprise Linux.

-   * UID 0 is always assigned to the superuser account, root.

-   * UID 1-200 is a range of "system users" assigned statically to system processes by Red Hat file system. They are typically assigned dynamically from the available pool when the software that needs them is installed. Programs run these as "unprivileged" system users in order to limit access to the resources they need to function.

-   * UID 1000+ is the range available for assignment to regular users.

> NOTE
Prior to RHEL 7, the convention that UID 1-499 was used for system users and UID 500+ for regular users. Default ranges used by useradd and groupadd can be changed in the /etc/login.defs file.

useradd(8), usermod(8), userdel(8) man pages

# MANAGING LOCAL GROUPS

A group must exist before a user can be added to that group. Several command-line tools are used to manage local group accounts.

Creating Groups from the Command Line

-   The groupadd command creates groups. Without options the groupadd command uses the next GID from the range specified in the /etc/login.defs creating the groups.

-   The -g option specifies a particular GID for the group to use.

```
[user01@host ~]$ sudo groupadd -g 10000 group01
[user01@host ~]$ tail /etc/group
...output omitted...
group01:x:10000:
```

> NOTE
The automatic creation of user private groups (GID 1000+) it is generally recommended to set aside a range of GIDs to be used for supplementary groups. A higher range will avoid a collision with a system group (GID 0-999).

-   The -r option creates a system group using a GID from the range of valid system GIDs listed in the /etc/login.defs file. The SYS_GID_MIN and SYS_GID_MAX configuration items in /etc/login.defs define the range of system GIDs.

```
[user01@host ~]$ sudo groupmod -r group022 group02
[user01@host ~]$ tail /etc/group
...output omitted...
group02:x:988:
```

Modifying Existing Groups from the Command Line

-   The groupmod command changes the properties of an existing group. The -n option specifies a new name for the group.

```
[user01@host ~]$ sudo groupmod -n group022 group02
[user01@host ~]$ tail /etc/group
```

# Deleting Groups from the Command Line

-   The groupdel command removes groups.

```
[user01@host ~]$ sudo groupdel group022
```

> NOTE
You cannot remove a group if it is the primary group of any existing user. As with userdel, check all file systems to ensure no files remain on the system that are owned by the group.

# Changing Group Membership from the Command Line

-   The membership of a group is controlled by user management. Use the usermod -g command to change a user's primary group.

```
[user01@host ~]$ id user002
uid=1006(user02) gid=1008(user02)
[user01@host ~]$ sudo usermod -g group001 user002
[user01@host ~]$ id user002
uid=1006(user02) gid=1008(group001) groups=10000(group001)
```

-   Use the usermod -ag command to add a user to a supplementary group.

```
[user01@host ~]$ id user003
uid=1007(user03) gid=1009(user03) groups=1009(user03)
[user01@host ~]$ sudo usermod -aG group001 user003
[user01@host ~]$ id user003
uid=1007(user03) gid=1009(user03) groups=1009(user03), 10000(group001)
```

> IMPORTANT
The use of the -a option makes usermod function in append mode. Without -a, the user will be removed from any of their supplementary groups that are not included in the -G group's list.
