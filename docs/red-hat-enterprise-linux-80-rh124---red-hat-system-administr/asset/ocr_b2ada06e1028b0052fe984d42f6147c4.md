user can also run any command as root without a password because the last line of the AMI's /etc/sudoers file is set as follows:

```
ec2-user  ALL=(ALL) NOPASSWD: ALL
```

The requirement to enter a password for sudo can be re-enabled or other changes may be made to tighten security by the process of configuring the system.

> NOTE
In this course, you will frequently see sudo su - used instead of sudo -i. Both commands work, but there are some subtle differences between them.
The sudo su - command sets up the root user exactly like a normal login because the su ignores the settings made by sudo and sets up the environment from scratch.
The default configuration of the sudo -i command actually sets up details of the root user's environment differently than a normal login. For example, it sets the PATH environment slightly differently. This affects where the shell will look find commands.
You can make sudo -i behave like su - by editing /etc/sudoers with visudo. Find the line

```
Defaults secure_path = /sbin:/bin:/usr/sbin:/bin
```

and replace it with the following lines:

| Defaults secure_path = /usr/local/bin:/usr/bin |
| Defaults:root secure_path = /usr/local/bin:/sbin:/usr/local/bin:/sbin:/usr/bin |

For most purposes, this is not a major difference. However, for consistency of PATH settings on systems with the default /etc/sudoers file, the authors of this course mostly use sudo su - in examples.
