# MANAGING FILE SYSTEM PERMISSIONS FROM THE COMMAND LINE

# OBJECTIVES

After completing this section, you should be able to change the permissions and ownership of files using command-line tools.

# CHANGING FILE AND DIRECTORY PERMISSIONS

The command used to change permissions from the command line is chmod, which means "change mode" (permissions are also called the mode of a file). The chmod command takes a permission instruction followed by a list of files or directories to change. The permission instruction can be issued symbolically (the symbolic method) or numerically (the numeric method).

# Changing Permissions with the Symbolic Method

```
chmod whatwhich file|directory
```

+   * Who is u, g, o, a (for user, group, other)
* What is +, -, w = (for add, remove, set exactly)
* Which is r, w, x (for read, execute)

The symbolic method of changing file permissions uses letters to represent the different groups of permissions: u for user, g for group, o for other, and a for all.

With the symbolic method, it is not necessary to set a new group of permissions. Instead, use + or - to add remove permissions, respectively or = to replace the entire set for a group of permissions.

The permissions themselves are represented by a single letter: r for read, w for write, and x for execute. When using chmod to change permissions with the symbolic method, using a capital X as the permission flag will execute permission only if the file is a directory or already have execute set for user, group, or other.

> NOTE
The chmod supports the -R option to recursively set permissions on the files in an entire directory tree. When using the -R option, it can be useful to set permissions using the X option. This allows permission to set on directories that their contents can be accessed, without changing permissions on most files. Be cautious with the X option, however, because if a file has execute set, X will set the specified execute permission on that file as. For example, the following command recursively sets read and write access on demodir and all its children for their group owner, but only applies group execute permissions to directories and files that already have execute set for user, group, or other.

```
[root@host ~]# chmod -R g+wx demdir
```
