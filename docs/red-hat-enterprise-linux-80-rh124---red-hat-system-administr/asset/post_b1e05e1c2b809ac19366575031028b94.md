# ABSOLUTE PATHS AND RELATIVE PATHS

![](img/59afb92e10b67a9cecc358a2c65e93b5_74_0.png)

Figure 3.2: The common file viewer (left) is equivalent to the top-down view (right).

The path of a file or directory specifies its unique file system location. Following a file path traverses one or more subdirectories, delimited by a forward slash (/), until the destination is reached. Directories, also called folders, contain other files and other subdirectories. These can be referenced in the same manner as files.

> IMPORTANT
> A space character is acceptable as part of a Linux file name. However, spaces are also used by the shell to separate options and arguments on the command line. If you enter a command that includes a file that has a space in its name, the shell can misinterpret the command and assume that you want to start a new file name or other argument at the space.

It is possible to avoid this by putting file names in quotes. However, if you do not need to use spaces in file names, it can be simpler to avoid using them.

# Absolute Paths

An absolute path is a fully qualified name, specifying the files exact location in the file system hierarchy. It begins at the root (/) directory and specifies each subdirectory that must be traversed to reach the specific file. Every file in the file system has a unique absolute path, recognized with a simple rule: A path name with a forward slash (/) as the first character is an absolute path name. For example, the absolute path for the system message log is /var/log/messages. Absolute paths can be long to, so files may also be located *relative* to the current working directory for your shell prompt.

# The Current Working Directory and Relative Paths

When a user logs in and opens a command window, the initial location is normally the user's home directory. System processes also have an initial directory. Users processes navigate to other directories as needed; the terms *working directory* or *current working directory* refer to *their current location*.

Like an absolute path, a *relative path* identifies a unique file, specifying only the path necessary to reach the file from the working directory. Recognizing relative path follows a simple rule: A path with *anything other than a forward slash as the first character is a relative path name*. A user in the /var directory could refer to the message log as `log/messages`.

Linux file systems, but not limited to, ext4, XFS, GFS2, and ClusterFS, are case-sensitive. Creating `File.txt` and `file.txt` in the same directory results in two unique files.

Non-Linux file systems might work differently. For example, VFAT, Microsoft's NTFS, and Apple's HFS+ have *case preserving*. These systems are *not case-sensitive*, they display file names with the original capitalization used when the file was created. Therefore, if you tried to make the files in the preceding example on a VFAT file system, both names would be treated as the same file instead of two different files.

# NAVIGATING PATHS

The `pwd` command displays the full name of the current working directory for that shell. This can help you determine the syntax to reach files using relative paths. The `ls` command lists directory contents for the specified directory, or if no directory is, for the current working directory.

```
[user@host ~]$ pwd
/home/user
[user@host ~]$ ls Public Templates Videos
Desktop Downloads Music Pictures Videos
[user@host ~]$
```

Use the `cd` command to change your working directory. If you do not specify any arguments to the command, it will change to your home directory.

```
[user@host ~]$ pwd
/home/user
[user@host ~]$ cd Videos
/home/user/Videos
[user@host Videos]$ cd /home/user/Documents
[user@host Documents]$ pwd
/home/user/Documents
[user@host Documents]$ cd
[user@host ~]$ pwd
/home/user
```
