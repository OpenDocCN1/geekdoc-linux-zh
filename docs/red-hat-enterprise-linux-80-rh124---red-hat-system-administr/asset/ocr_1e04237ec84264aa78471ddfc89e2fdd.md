# Deleting Users from the Command Line

+   - The userdel username removes the details of username from /etc/passwd, but leaves the user's home directory intact.

+   - The userdel -r username removes the details of username from /etc/passwd and also deletes the user's home directory.

> WARNING
When a user is removed with userdel without the -r option specified, the system will have files that are owned by an unassigned UID. This can also happen when a file, having a deleted user as its owner, exists outside that user's home directory. This situation can lead to information leakage and other security issues.
Red Enterprise Linux 7 and Red Enterprise Linux 8, the useradd command assigns the first free UID greater than or to 1000, unless you specify it using the -u option.
This is how information leakage can occur. If the first free UID has been previously assigned to a user account that has since been removed from the system, the old user's UID will be reassigned to the new user, giving the new user ownership of the old user's remaining files.
The following scenario demonstrates this situation.

```
[root@host] #$ useradd user01
[root@host] #$ is -l /home
drwx--------. 3 user01 user01   74 Feb 4 15:22 user01
[root@host] #$ userdel user01
[root@host] #$ is -l /home
drwx------. 3 1000 1000   74 Feb 4 15:22 user01
[root@host] #$ useradd user02
[root@host] #$ is -l /home
drwx------. 3 user02          74 Feb 4 15:23 user02
drwx------. 3 user02          74 Feb 4 15:22 user01
```

Notice user02 owns all files that user01 previously owned.

Depending on the situation, one solution to this problem is to remove all unwanted files from the system when the user that created them is deleted. Another solution is to manually assign the unowned files to a different user. The root user can use the find /nouser -o -nogroup command to find all unowned files and directories.

# Setting Pass from the Command Line

+   - The password username command sets the initial password or changes the existing password of username.
