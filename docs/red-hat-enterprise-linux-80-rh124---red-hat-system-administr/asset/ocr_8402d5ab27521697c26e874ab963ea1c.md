# GUIDED EXERCISE

# ACCESSING THE REMOTE COMMAND
LINE

In this exercise, you will log into a remote system as different users and execute commands.

# OUTCOMES
You should be able to:

+   * Log in to a remote system.
* Execute commands with the OpenSSH secure shell.

# BEFORE YOU BEGIN
Log in to workstation, using student as the password.

On workstation, run lab ssh-access start to start the exercise. This script ensures the environment is set up correctly.

```
student@workstation ~$ lab ssh-access start
```

+   1. From workstation, open an SSH session to servera as student.

```
[student@workstation ~$ ssh student@servera
...output omitted...
[student@servera ~$]
```

+   2. Open an SSH session to serverb as student. Accept the host key. Use student as the password when prompted for the password of the student user on server.

```
[student@serverb ~$] ssh student@serverb
The authenticity of 'serverb (172.25.20.111)' can't be established.
ECDSA key fingerprint is SHA256:ERTdjjoIrWSZQqnp5or+bXfidiguddb3XBuWZa
Are sure you want to continue connecting (yes/no) yes
Warning: Permanently added 'serverb,172.25.20.111' (ECDSA) to the list of hosts
student@serverb's password: student
...output omitted...
[student@serverb ~$]
```

The host key is recorded in the /home/student/.ssh/known_hosts file on servera to identify serverb because the student has initiated the SSH connection from servera. if the /home/student/.ssh/known_hosts file does not already exist, it comes into existence as a new file with the new entry in. The ssh command fails to execute properly if the remote host has a different key than the recorded key.
