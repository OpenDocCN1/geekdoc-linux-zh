
The command tzselect is useful for identifying zoneinfo time names. It interactively prompts the user with questions about the system's location, and outputs the name of the correct time zone. It does not make any change to the time zone setting of the system.

The superuser can change the system setting to update the current time zone using the timedatectl set-timezone. The following timedatectl updates the current time zone to America/Phoenix.

```
[root ~]## timedatectl set-timezone America/Phoenix
[root ~]## timedatectl
  Local time: Fri 2019-04-05 14:12:39 MST
  Universal time: Fri 2019-04-05 21:12:39 UTC
  RTC time: Fri 2019-04-05 21:12:39
  Time zone: America/Phoenix (MST, -0700)
System clock synchronized: yes
  NTP service: active
  RTC in local TZ: no
```

> Should you need to use the Coordinated Universal Time (UTC) on a particular server, set its time zone to UTC. The tzselect command does not include the name of the UTC time zone. The timedatectl set-timezone UTC command to set the system's current time zone to UTC.

Use the timedatectl set-time command to change the system's current time. The time is specified in the "YYYY-MM-DD hh:mm:ss" format, where either date or time can be omitted. The following timedatectl command changes the time to 09:00:00.

```
[root ~]# timedatectl set-time 09:00:00
[root@server ~]$ timedatectl
  Local time: Fri 2019-04-05 09:00:27 MST
  Universal time: Fri 2019-04-05 16:00:27 UTC
  RTC time: Fri 2019-04-05 16:00:27
  Time zone: America/Phoenix (MST, -0700)
System clock synchronized: yes
  NTP service: active
  RTC in local TZ: no
```

The timedatectl set-ntp command enables or disables NTP synchronization for automatic time adjustment. The option requires either a true or false argument to turn it on or off. The following timedatectl command turns on NTP synchronization.

```
[root ~]# timedatectl set-ntp true
```

# CONFIGURING AND MONITORING CHRONYD

The chronyd service keeps the usually-inaccurate local hardware clock (RTC) on track by synchronizing to the configured NTP servers. If no network connectivity is available, chronyd calculates the clock drift, which is recorded in the driftfile at the /etc/chronyd.conf file.

By default, chronyd uses servers from the NTP Pool Project for time synchronization and does not need additional configuration. It may be useful to change the NTP servers when the machine in question is an isolated network.

The stratum of NTP time determines its quality. The stratum determines the number of hops the machine is away from a high-performance reference clock. The reference clock is a stratum 0 time source. An NTP server directly attached to it is a stratum 1, while a machine synchronizing from the NTP server is a stratum 2 time source.

The server and peer are the two types of time sources that you can use in the /etc/chronyd.conf configuration file. The server is one stratum above the local NTP server, and the peer is at the same stratum level. More than one server and more one peer can be specified, per line.

The first argument of the server line is the IP address or DNS name of the NTP server. Following a series of options for the server can be listed. It is recommended to use the iburst option, after the service starts, four measurements are taken in a short time period for a more accurate initial clock synchronization.

The following server line classroom.example.com iburst line in the /etc/chronyd.conf file causes the chronyd service to use the classroom.example.com NTP time source.

```
# Use public servers from the pool.ntp.org project.
...output omitted...
server classroom.example.com iburst
...output omitted...
```

After pointing chronyd to the local server, classroom.example.com, you should restart the service.

```
[root@host ~]# systemctl restart chronyd
```

The chronyd command acts as a client to the chronyd service. After setting up NTP synchronization, you should verify that the local system is seamlessly to synchronize the system clock using the chronyd sources command. For more verbose output with additional explanations about the output, use the chronyc sources -v command.

```
[root@host ~] chronyc sources -v
210 Number of sources = 1

  -- Source mode      '^' = server, '#' = local clock.
  / Source state '*' = current synced, '+' = combined, '-' = not combined,
 | /   '?' = unreachable, 'x' = time may be in error, '-' = time too variable.
 | ||               - xxxx [yyyy] +/- zzzz
 | ||               / xxxx = adjusted offset,
 | ||  Log2(Polling interval) - / yyyy = measured offset,
 | ||                                zzzz = estimated error.
 MS Name/IP address      Stratum Poll Reach LastRx sample
=================================================
^* classroom.example.com      8 6 17 23 -497ns[-7000ns] +/- 956us
```

The * character in the S (Source state) field indicates that the classroom.example.com server has been used as a time source and is the NTP server the machine is currently synchronized.
