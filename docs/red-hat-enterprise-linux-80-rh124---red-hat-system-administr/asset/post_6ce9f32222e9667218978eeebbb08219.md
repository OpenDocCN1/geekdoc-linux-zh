
# IMPORTANT

SIGKILL is commonly used too quickly by administrators.

Since the SIGKILL signal cannot be handled or ignored, it is always fatal. However, for termination without allowing the process to run self-cleanup routines. It is recommended to send SIGTERM, first try SIGINT, and only if both fail retry with SIGKILL.

First identify the PIDs to be killed using pgrep, which operates much like pkill, including the same options, except that pgrep lists processes rather than killing them.

```
[root@host #] pgrep -1 -u bob
6964 bash
6998 sleep
6999 sleep
7000 sleep
[root@host #] pkill SIGKILL -u bob
[root@host #] pgrep -1 -u bob
[root@host #]
```

When processes requiring attention are in the same session, it is not necessary to kill all of a user's processes. Determine the controlling terminal for the session using the w command, then kill only processes referencing the same terminal ID. Unless SIGKILL is specified, the session leader (here, the Bash login shell) successfully handles and survives the termination request, and all other processes are terminated.

```
[root@host #] pgrep -1 -u bob
7391 bash
7426 sleep
7427 sleep
7428 sleep
[root@host #] w -h -u bob
tty3 18:37 5:04 0.03s 0.03s -bash
[root@host #] pkill -t tty3
[root@host #] pgrep -1 -u bob
7391 bash
[root@host #] pkill SIGKILL -t tty3
[root@host #] pgrep -1 -u bob
[root@host #]
```

The same selective process termination can be applied using parent and child relationships. Using the pstree command to view a process tree for the system or a single user, the parent's PID to kill all processes they have created. There, the parent Bash login shell survives because the signal is directed only at its children.

```
[root@host #] pstree -p bob
bash(8391)--sleep(8425)
  └─sleep(8426)
  └─sleep(8427)
[root@host #] pkill -P 8391
[root@host #] pgrep -1 -u bob
```

# BEFORE YOU BEGIN

Log in to workstation as student using student as the password.

On workstation, run the **lab processes-kill start** command. The command runs a start script that determines whether the host, **servera**, is reachable on the network.

```
[student@workstation ~]$ lab processes-kill start
```

- 1. On workstation, open two terminal windows side by side. In this section, these terminals are referred to as **left** and **right**. In each terminal, use the **ssh** command to log in to servera as the student.

```
[student@workstation ~]$ ssh student@servera
Activate the web console with: systemctl enable -- cockpit.socket

[student@servera ~]
```

- 2. In left window, create a new directory called **/home/student/bin**. In the new directory, create a script called **killing**. Make the script executable.

```
[student@servera ~]$ mkdir /home/student/bin
```

- 2.2. Use the **vim** command to create a script called **killing** in the **/home/student/bin** directory. Press **I** to enter interactive mode. Use **:wq** command to save the file.

```
[student@servera ~]$ vim /home/student/bin/killing
#!/bin/bash
while true; do
echo -n $@ >> ~/killing_outfile
sleep 5
done
```

# NOTE
killing script runs until terminated. It appends line to ~/killing_outfile every 5 seconds.

- 2.3. Use the chmod command with +x to make the killing file executable.

```
[student@servera ~]$ chmod +x /home/student/bin/killing
```

- 3. In the left terminal, use the cd command to change into /home/student/bin/directory. Start killing the processes with arguments network, interface, and connection, respectively. Start processes called network, interface, and connection. Use the background (&) to start the processes in the background.

```
[student@servera ~]$ cd /home/student/bin
[student@servera ~]$ killing network &
[1] 3468
[student@servera ~]$ killing interface &
[2] 3482
[student@servera ~]$ killing connection &
[3] 3516
```

- 4. In the right terminal, use the tail command with -f option to confirm that all processes are appended to the file.

```
[student@servera ~]$ tail -f ~/killing_outfile

```

- 5. In the left terminal shell, use the jobs command to list processes.

```
[student@servera ~]$ jobs
```

- 6. Use the signal to suspend the network process. Confirm that the network process is Stopped. In the right terminal, confirm that the network process is no longer appending output to ~/killing_output.

6.1. Use the kill with -SIGSTOP option to stop the network process. Run the jobs to confirm it is stopped.

```
[student@servera ~]$ kill -SIGSTOP %1
[1]+ Stopped network
[student@servera ~]$ jobs
```
