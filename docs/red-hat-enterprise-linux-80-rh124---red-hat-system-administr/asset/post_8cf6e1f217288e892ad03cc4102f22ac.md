# CONFIGURING NETWORKING FROM THE COMMAND LINE

## OBJECTIVES

After completing this section, you should be able to manage network settings and devices using the nmcli command.

## DESCRIBING NETWORKMANAGER CONCEPTS

NetworkManager is a daemon that monitors and manages network settings. In addition to the daemon, there is a GNOME Notification Area app providing network status information. Command-line and graphical tools talk to NetworkManager and save configuration files in the /etc/sysconfig/network-scripts directory.

- A device is a network interface.
- A connection is a collection of settings that can be configured for a device.
- Only one connection can be active for one device at a time. Multiple connections may exist for different devices or allow connection to be altered for the same device. If you need to temporarily change network settings, instead of changing the configuration of a connection, you can change which connection is active for a device. For example, a device for a wireless network interface on a laptop might use different connections for the wireless network at a work site and for the wireless network at home.
- Each connection has a name or ID that identifies it.

## VIEWING NETWORKING INFORMATION

The nmcli dev status displays the status of all network devices:

# ADDING A NETWORK CONNECTION

The nmcli con add command is used to add new network connections. The following example nmcli con add assume that the name of the network connection being added is not already in use.

The following command adds a network connection named eno2 for the interface eno2, which gets IPv4 networking information via DHCP and autoconfig on startup. It also gets IPv6 networking settings by listening for router advertisements on the local link. The name of the configuration file is based on the value of the con-name option, eno2, and is saved to the /etc/sysconfig/network-scripts/ifcfg-eno2 file.

```
[root@]# nmcli con add con-name eno2 type ethernet eno2
```

The next example creates eno2 connection for the eno2 device with static IPv4 address, using the IPv4 address and network prefix 192.168.0/24 and default gateway 192.168.0.254, but still interconnects at startup and saves its configuration into the same file. Due to screen size limitations, the first line with a shell escape and complete the command on the next line.

```
[root@]# nmcli con add con-name eno2 type ethernet ifname eno2 \ ip4 192.168.0/24 gw 192.168.0.254
```

This final example creates eno2 connection for the eno2 device with static IPv6 and IPv4 addresses, using the IPv6 address and network prefix 2001:db8:0:1::c000:207/64 and the IPv4 address and network prefix 192.0.2/24 and default IPv4 gateway 192.0.2.1, but still interconnects at startup and saves its configuration into /etc/sysconfig/network-scripts/ifcfg-eno2. Due to screen size limitations, the first line with a shell escape and complete the command on the next line.

```
[root@]# nmcli con add con-name eno2 type ethernet ifname eno2 \ ip6 2001:db8:0:1::c000:207/64 gw 2001:db8:0:1::1 ip4 192.0.2/24 gw 192.0.2.1
```

# CONTROL CONNECTIONS

The nmcli up command activates the connection on the network interface it is bound to. Note that the command takes a connection name, the name of the network interface. Remember that nmcli show displays the names of all available connections.

```
[root@]# nmcli up static-ens3
```

The nmcli disconnect command disconnects the network interface and brings it down. This command can be abbreviated nmcli dev dis.

```
[root@]# nmcli dev dis ens3
```

# IMPORTANT

Use nmcli dev is normally the best way to deactivate a network interface. The nmcli down command brings down the connection. However, by default, most wired connections are configured with autoconnect. This activates the connection as soon as the network interface is available. Since the connection's network interface is still available, nmcli down brings the interface down unless the connection is entirely disconnected.
