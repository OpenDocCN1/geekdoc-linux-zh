# GATHERING NETWORK INTERFACE INFORMATION

# Identifying Network Interfaces

The ip link command will list all network interfaces available on your system:

```
[user@ ~]$ ip link
1: <LOOPBACK,UP,LOWER_UP> mtu 65536 disc noque state UNKNOWN mode DEFAULT
  group default qlen 1000
  link/loopback 00:00:00:00:00:00 br 00:00:00:00
2: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc mq state UP DEFAULT
  group default qlen 1000
  link/ether 52:54:00:00:00:0a br ff:ff:ff:ff:ff:ff
3: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc mq state UP DEFAULT
  group default qlen 1000
  link/ether 52:54:00:00:00:1e br ff:ff:ff:ff:ff:ff
```

In the following example, the server has three network interfaces: lo, which is the loopback that is connected to the server itself, and two Ethernet interfaces, ens3 and ens4.

To configure each network correctly, you need to know the MAC address of the interface connected to each network, because it is physically printed on the server or because it is a virtual machine and know it is configured. The MAC address of the device is listed after link/ether for each interface. So you know that the network with the MAC address 52:54:00:00:00:0a is the interface ens3.

# Displaying IP Addresses

Use the ip command to view address. A single interface can have multiple IPv4 or IPv6 addresses.

```
[user@ ~]$ ip show ens3
2: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc pfifo state UP
  qlen 1000
  link/ether 52:54:00:00:00:0a br ff:ff:ff:ff:ff:ff
  inet 192.168.1.188/24 scope global 192.168.1.188
  inet6 2001:db8::1/64 scope global 
  inet6 fe80::5544:fe00:b/64 scope link
```

# Displaying Performance Statistics

The ip command may also be used to show statistics about network. Counters for each interface can be used to identify the presence of issues. The counters record statistics for the number of received (RX) and transmitted (TX) packets, packet errors, and packets that dropped.

```
[user@host ~]$ ip -s link ens3
2: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc pfifo state UP
  qlen 1000
  link/ether 52:54:00:00:00:0a br ff:ff:ff:ff:ff:ff
RX: 269850 2931 0 0
TX: 300556 3250 0 0
```

# CHECKING CONNECTIVITY BETWEEN HOSTS

The ping command is used to test connectivity. The command continues to run until Ctrl+C is pressed unless options are given to limit the number of packets sent.

```
[user@host ~]$ ping -c 3 192.0.2.254
PING 192.0.2.254 (56) 64 bytes of data.
64 bytes from 192.0.2.254: icmp_seq=1 ttl=64 time=43.33 ms
64 bytes from 192.0.2.254: icmp_seq=2 ttl=64 time=3.48 ms
64 bytes from 192.0.2.254: icmp_seq=3 ttl=64 time=6.83 ms

192.0.2.254 ping statistics
3 packets transmitted, 3 received, 0% packet loss, time 203ms
rtt min/avg/max/mdev = 3.485/4.886/6.837/1.424 ms
```

The ping command is the ipv6 version of ping in Red Hat Enterprise. It operates over IPv6 and takes IPv6 addresses, but otherwise work like ping.

```
[user@host ~]$ ping 6 2001:db8:0:1::1 56 data bytes
PING 2001:db8:0:1::1(2001:db8:0:1::1) 56 bytes of data
64 bytes from 2001:db8:0:1::1: icmp_seq=1 ttl=64 time=18.4 ms
64 bytes from 2001:db8:0:1::1: icmp_seq=2 ttl=64 time=0.178 ms
64 bytes from 2001:db8:0:1::1: icmp_seq=3 ttl=64 time=0.100 ms
^C
2001:db8:0:1::1 ping statistics
3 packets transmitted, 3 received, 0% packet loss, time 201ms
rtt min/avg/max/mdev = 0.178/6.272/18.458/8.66 ms
```

When you ping link-local addresses and the link-all multicast group (ff02::), the network interface to use must be specified explicitly with a scope identifier (such as ff02::ens3). If this is not done, the error "invalid argument" is displayed. Ping can be useful for finding IPv6 addresses on the local network.
