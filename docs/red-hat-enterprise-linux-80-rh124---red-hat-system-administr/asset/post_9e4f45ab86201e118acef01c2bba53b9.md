# EXTRACTING A COMPRESSED ARCHIVE

The first step when extracting a tar archive is to determine where the archived files should be extracted, to create and change to the target directory. The tar command determines which compression was used and it is usually not necessary to use the same compression option used when creating the archive. If one chooses to do so, the correct decompression type must be used; otherwise tar yields an error about the decompression type specified in the options not matching the file's decompression type.

To extract the contents of a gzip compressed archive /root/etcbackup.tar.gz in the /tmp/etcbackup directory:

```
[root@host ~]# mkdir /tmp/etcbackup
[root@host ~]# cd /tmp/etcbackup
[root@host etcbackup]# tar -tf /root/etcbackup.tar.gz
etc/
etc/fstab
etc/crypttab
etc/mtab
...output omitted...
[root@host etcbackup]# tar -xzf /root/etcbackup.tar.gz
```

```
[root@#] mkdir /tmp/logbackup

...output omitted.
[root@logbackup] tar -xjf /root/logbackup.tar.bz2
```

> NOTE
> Additionally, gzip, bzip2, and xz can be used independently to compress single files. For example, the gzip etc tar command results in the etc.tar.gz compressed file, while the bzip2 abc.tar command results in the abc.tar.bz2 compressed file, and the xz myarchive.tar command results in the myarchive.tar.xz compressed.
> The corresponding commands to decompress are gzip, bunzip2, and unxz. For example, the gzip /tmp/etc.tar.gz command results in the etc.tar uncompressed tar file, while the bunzip2 abc.tar.bz2 command results in the abc.tar uncompressed file, and the unxz myarchive.tar.xz command results in the myarchive.tar uncompressed tar file.

# TRANSFERRING FILES USING SECURE COPY

OpenSSH is useful for running shell commands on remote systems. The Secure Copy, scp, which is part of the OpenSSH suite, copies files from a remote system to the local system or from the local system to a remote system. The command uses the SSH server for authentication and encrypts data when it is transferred.

You can specify a remote location for the source or destination of the files you are copying. The format of the remote location should be in the form [user@host:path]. The user portion of the argument is optional. If it is, your current username will be used to authenticate the remote server just like key-based authentication. When prompting for your password.

The following example demonstrates how to copy the /etc/yum.conf and /etc/hosts files on, to the remoteuser's home directory on the remotehost remote system:

```
$user@host ~$ scp /etc/yum.conf /etc/hosts remoteuser@remotehost:/home/remoteuser
remoteuser@remotehost's password: password
yum.conf             100%  813      0.8KB/s    00:00
hosts                100%  227      0.2KB/s    00:00
```

You can also copy a file in the other direction, from a remote system to the local file system. In this example, the file /etc/hostname on remotehost is copied to the local directory /home/user. The scp command authenticates to remotehost as the user remoteuser.

```
$user@host ~$ scp remoteuser@remotehost:/etc/hostname /home/user
remoteuser@remotehost's password: password
hostname             100%  22      0.0KB/s    00:00
```

To copy a directory recursively, use the -r option. In the following example, the remote directory /var/log on remotehost is copied recursively to the local directory /tmp/ on host. You must connect to the remote system as root to make sure you read all files in the remote /var/log directory.

```
$user@host ~$ scp -r root remoteuser:/var/log /tmp
root@remotehost's password: password
...output omitted...
```
