
# Pipeline Examples

This example takes the output of the ls command and uses less to display it on the terminal screen at a time.

```
[user@host ~]$ ls -l /usr/bin | less
```

The output of the ls command is piped to wc -1, which counts the number of lines received from ls and prints that to the terminal.

```
[user@host ~]$ ls | wc -1
```

In this pipeline, head will output the first 10 lines of output from ls -t, with the final result redirected to a file.

```
[user@host ~]$ ls -t | head -n 10 > /tmp/ten-last-changed-files
```

# Pipelines, Redirection, and the tee Command

When redirection is combined with a pipeline, the shell sets up the entire pipeline first, then it redirects input/output. If output is used in the middle of a pipeline, the output will go to the file and not the next command in the pipeline.

In this example, the output of the ls command goes to the file, and less displays nothing on the terminal.

```
[user@host ~]$ ls > /tmp/saved-output | less
```

The tee overcomes this limitation. In a pipeline, tee copies its standard input to its standard output and also redirects its standard output to the files named as arguments to the command. If you imagine data as water flowing through a pipeline, tee can be visualized as a "T" joint in the pipe which directs output in two directions.

# Pipeline Examples Using the tee Command

This example redirects the output of the ls command and passes it to less to be displayed on the terminal screen at a time.

```
[user@host ~]$ ls -l | tee /tmp/saved-output | less
```

If tee is used at the end of a pipeline, then the final output of a command can be saved and output to the terminal at the same time.

```
[user@host ~] ls -t | head -n 10 | tee /tmp/ten-last-changed-files
```

# IMPORTANT

Standard error can be redirected through a pipe, but the merging redirection operators (& and &&) cannot be used to do this.

The following is the correct way to redirect standard output and standard error through a pipe:

```
[user@host ~] find -name / passwd 2>&1 | less
```

# EDITING TEXT FILES FROM THE SHELL PROMPT

# OBJECTIVES

After completing this section, you should be able to create and edit text files from the command line using the `vim` editor.

# EDITING FILES WITH VIM

A key design principle of Linux is that information and configuration settings are commonly stored in text-based files. These files can be structured in various ways, as lists of settings in INI-like formats, structured as YAML, and so on. However the advantage of text files is that they can be viewed and edited using any simple editor. Vim is an improved version of the vi editor distributed with Linux systems. Vim is highly configurable and efficient for practiced users, including features as split screen editing, color formatting, and highlighting.

# Why Learn Vim?

You should know how to use at least one text editor that can be used from a text-only prompt. If you can edit text-based files from a terminal window, or from remote logins through `ssh`, you do not need access to a graphical desktop in order to edit files on a server that might not run a graphical environment. But why Vim instead of other options? The reason is that Vim is always installed on a server if any text editor is present. This is because `vi` was specified by the POSIX standard that Linux and many other UNIX-like systems comply with in large part. In addition, Vim is often used as the `vi` implementation on other operating systems or distributions. For example, macOS currently includes a lightweight installation of Vim by default. So learning Vim for Linux may also help you get things elsewhere.

# Starting Vim

Vim may be installed in Red Hat Linux in two different ways which can affect the features and commands available to you.

Your server might have the `vim-minimal` package installed. This is a lightweight installation that only includes the core feature set and the basic `vi` command. In this case, you can open a file for editing with `vim filename`, and all the core features discussed in this section will be available to you.

Alternatively, your server may have the `vim-enhanced` package installed. This provides a much more comprehensive set of features, an online help system, and a tutorial program. In order to start Vim in this enhanced mode, you use the `vim` command.

```
[user@host ~]$ vim filename
```

Either way, the core features we will discuss in this section will work with both commands.

NOTE
If vim-enhanced is installed, regular users will have a shell alias so that if they run the `vi` command, they will automatically get the `vim` command instead. This does not apply to root and other users with UIDs below 200 (which are used by system services).

If you are editing files as the root and expect vi to run in enhanced mode, it can be a surprise. Likewise, if vim-enhanced is installed and a regular user wants simple vi for some reason, they might need to use `vim` to override the alias.

Advanced users can use `vi --version` and `vim --version` to compare the features of the two commands.

# Vim Operating Modes

An unusual characteristic of Vim is that it has several modes of operation: command mode, extended command mode, edit mode, and visual mode. Depending on the mode, you may be issuing commands, editing text, or working with blocks of text. As a new Vim user, you should always be aware that your current mode keystrokes have different effects in different modes.

![](img/59afb92e10b67a9cecc358a2c65e93b5_156_0.png)

Figure 5.10: Moving between Vim modes

When you first open Vim, it starts in command mode, which is used for navigation, cut and paste, or other text manipulation. Enter each of the other modes with single character keystrokes to provide specific editing functionality:

- An i keystroke enters insert mode, where all text becomes file content. Pressing Esc returns to command mode.
- A V keystroke enters visual mode, where multiple characters may be selected for textulation. Use Shift+V for multiline and Ctrl+V for block selection. The same keystroke used to enter visual mode (v, Shift+V or Ctrl+V) is used to exit.
- The colon begins extended command mode for tasks such as writing the file (to save it), and quitting the Vim editor.
