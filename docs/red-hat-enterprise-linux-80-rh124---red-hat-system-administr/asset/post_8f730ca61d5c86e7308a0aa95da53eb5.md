# SHADOW PASSWORDS

The use of a password was stored in /etc/passwd until that point dictionary attacks became common. Red Hat Enterprise Linux 8 moved the password to /etc/shadow, which is readable only by root.

# Format of an Encrypted Password

The shadow file stores three fields: the hashing algorithm, the salt, and the encrypted hash. A sample line from /etc/shadow is shown below.

```
$6$sXx/42fJ//JaufZpc0X45JCH30E:17933:9999::
```

The number 6 indicates SHA-512, a 1 would indicate MD5, a 5 SHA-256. The salt used to encrypt the password is originally chosen at random.

# Password Verification

When a user tries to login, the system looks up the entry in /etc/shadow, combines the salt for the unencrypted password that was typed, and encrypts them using the hashing algorithm. If the result does not match the encrypted hash, the user typed in the wrong password and the login attempt fails. This method allows the system to determine if the user typed in the correct password without storing password in a format usable for logging.

# CONFIGURING PASSWORD AGING

The following diagram relates the relevant password aging parameters, which can be adjusted using the change command to implement a password aging policy.

![](img/59afb92e10b67a9cecc358a2c65e93b5_211_0.png)

```
user01@host~$ sudo change -m 0 -M 90 -W 7 -I 14 user03
```

The preceding change command uses the -m, -M, -W, and -I options to set the minimum age, maximum age, warning period, and inactivity period of the user's password, respectively.

The change -d user03 command forces the user03 to update its password on the next login.

The change -E 2019-08-05 user03 command causes the user03 user's account to expire on 2019-08-05 (in YYYY-MM-DD format).
