
# Block Device Naming

| TYPE OF DEVICE | DEVICE NAMING PATTERN |
|---|---|
| SATA/SAS/USB-attached storage | /dev/sda, /dev/sdb ... |
| virtio-blk virtualized storage (some virtual machines) | /dev/vda, /dev/vdb ... |
| NVMe-attached storage (many SSDs) | /dev/nvme0, /dev/nvme1 ... |
| SD/eMMC storage (SD cards) | /dev/mmcblk0, /dev/mmcblk1 ... |

> NOTE: Many virtual machines use the newer virtio-scsi virtualized storage that will have /dev/sd* -style naming.

# Disk Partitions

Normally, you do not make the entire storage device into one file system. Storage devices are typically divided into smaller chunks partitions.

Partitions allow you to compartmentalize a disk: the various partitions can be formatted with different file systems or used for different purposes. For example, one partition can contain user home directories where another contain system data and logs. If a user fills up the home directory with data, the system may still have available space.

Partitions are blocks in their own right. On SATA-attached storage, the first partition on the disk is /dev/sda1. The third partition on the second disk is /dev/sdb3, and so on. Paravirtualized storage devices have a similar naming system.

An NVMe-attached SSD device names its partitions differently. In that case, the first partition on the disk is /dev/nvme0p1. The third partition on the second disk is /dev/nvme1p3, and so on. On SD or MMC devices have a similar naming system.

A long listing of /dev/sda device reveals its special file type as b, which stands for block device:

```
[user@host ~]$ ls -l /dev/sda1
br-rw----. 1 root disk 8, 1 Feb 22 08:00 /dev/sda1
```

# Logical Volumes

Another way of organizing partitions and disks is with logical volume management (LVM). With LVM, one or more block devices can be aggregated into a storage pool called a volume group. Disk space in the volume group is partitioned out to one or more logical volumes, which are the functional equivalent of a partition residing on a physical disk.

The LVM system assigns names to volume groups and logical volumes upon creation. LVM creates a directory in dev that matches the group name and creates a symbolic link within that directory with the same name as the logical volume. That logical volume file is available to be mounted. For example, if a volume group is called myvg and the logical volume within it is called mylv, the full path to the logical volume device file is /dev/myvg/mylv.

NOTE
The form of logical device name mentioned above is actually implemented as a symbolic link to the actual device file to access it, which might vary between boots. There is another form of logical device name linked from files in /dev/mapper that are used, and are also symbolic links to the actual device file.

# EXAMINING FILE SYSTEMS

To get an overview of local and remote file systems and the amount of free space available, run the df command. When the df command is run without arguments, it reports total space, used disk space, free disk space, and the percentage of the total disk space used on all mounted file systems. It reports both local and remote file systems.

The following example displays the file systems and mount points.

```
[user@host]$ df
Filesystem     1K-blocks Used Available Use% Mounted on
detmpfs         0 912584 0 % /dev
tmpfs         0 936516 0 % /dev/shm
tmpfs         936516 16812 919704 2 % /run
tmpfs         936516 0 936516 0 % /sys/fs/cgroup
/dev/vda3      8377344 1411332 6966812 17 % /
/dev/vda1      1038336 169896 868440 17 % /boot
tmpfs         173800 0 173800 0 % /run/user/1000
```

The partitioning of the host shows two file systems, which are mounted on / and boot. This is common for virtual machines. The files written into tmpfs or devtmpfs disappear after system reboot.

To improve readability of the output sizes, there are two different human-readable options: -h or -H. The difference between these two options is that -h reports in KiB (2¹⁰), MiB (2²⁰), or GiB (2³⁰), while -H reports in SI units: KB (10³), MB (10⁶), or GB (10⁹). Hard drives use SI units when advertising their products.

Show a report on the file systems with the system which can be converted to human-readable format:

```
[user@host]$ df -h
Filesystem      Size Used Available Use% Mounted on
detmpfs          892M 0 892M 0 % /dev
tmpfs           915M 0 915M 0 % /dev/shm
tmpfs           177M 899M 2 % /run
tmpfs           915M 0 915M 0 % /sys/fs/cgroup
/dev/vda3       8.0G 1.4G 6.7G 17 % /
/dev/vda1       1014M 166M 840M 17 % /boot
tmpfs           183M 0 183M 0 %/run/user/1000
```

For more detailed information about space used by a certain directory tree, use the du command. The du command has -h and -H options to convert the output to human-readable format. The du command shows the size of all files in the current directory tree recursively.

Show a disk usage report for the /usr/share directory on host:

```
[root@host ~]# du /usr/share
...output omitted...
176 /usr/share/smartmontools
184 /usr/share/nano
8 /usr/share/cmake/bash-completion
8 /usr/share/cmake
356676 /usr/share
```

Show a disk usage report in human-readable format for the /share directory on host:

```
[root@host ~]# du -h /var/log
...output omitted...
176K /var/share/smartmontools
184K /var/share/nano
8.0K /var/share/cmake/bash-completion
8.0K /var/share/cmake
369M /var/share
```

# MOUNTING AND UNMOUNTING FILE SYSTEMS

# OBJECTIVES

After completing this section, you should be able to access the contents of file systems by adding and removing file systems from the file system hierarchy.

# MOUNTING FILE SYSTEMS MANUALLY

A file residing on a removable storage device needs to be mounted in order to access it. The mount command allows the root user to manually mount a file system. The first argument of the mount command specifies the file system to mount. The second argument specifies the device to use as the mount point in the file-hierarchy.

There are two common ways to specify the file system on a disk partition by the mount command:

- With the name of the device file in /dev containing the file system.
- With the UUID written to the file system, a universally-unique identifier.

Mounting a device is relatively simple. You need to identify the device you want to mount, sure the mount point exists, and mount the device on the mount point.

# Identifying the Block Device

A hot-plug storage device, whether a hard disk drive (HDD) or solid-state device (SSD) in a server cavity, or a USB storage device, must be plugged into a different port each time they are attached to a system.

Use the lsblk command to list the details of each block device or all the available devices.

| NAME | MAJ:MIN | RM | SIZE | RO | TYPE | MOUNTPOINT |
|---|---|---|---|---|---|---|
| vda | 253:0 | 0 | 0G | | disk | |
| - vda1 | 253:1 | 0 | 1G | | part | /boot |
| - vda2 | 253:2 | 0 | 1G | | part | [SWAP] |
| - vda3 | 253:3 | 0 | 11G | | part | / |
| vdb | 253:16 | 0 | 64G | | disk | |
| - vdb1 | 253:17 | 0 | 64G | | part | |

If you have detected a 64 GB storage device with one partition, then you can guess the preceding output that /dev/vdb1 is the partition you want to mount.

# Mounting by Block Device Name

The following example mounts the file system in the /dev/vdb1 partition on the directory /mnt/data.

```
[root@host ~]# mount /dev/vdb1 /mnt/data
```
