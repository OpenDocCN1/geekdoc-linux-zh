# EFFECT ON DIRECTORIES

| PERMISSION | EFFECT ON FILES | EFFECT ON DIRECTORIES | x (execute) | Files can be executed as commands. | Contents of the directory can be accessed. (You can change into the directory, read information about its files, and access its files' permissions allows it.) |

Note that users normally have both read and execute permissions on read-only directories so that they can list the directory and have full read-only access to its contents. If a user only has read access to a directory, the names of the files in it can be listed, but if no other information, permissions or time stamps, are available, nor they be accessed. If a user only has execute access on a directory, they cannot list the names of the files in it, but if they already know the name of a file that they have permission to read, then they can access the contents of that by explicitly specifying the name.

A file may be removed by anyone who has write permission to the directory in which the file resides, regardless of the ownership or permissions on the file itself. This can be overridden by a special permission, the sticky bit, discussed in this chapter.

> NOTE
Linux files work differently than the permissions system used by the NTFS file system for Microsoft Windows.
On Linux, permissions only apply to the file or directory on which they are set. That, permissions on a directory are not inherited automatically by the subdirectories and within it. Permissions on a directory can block access to the contents of the directory depending on how restrictive they are.
The read permission on a directory in Linux is roughly equivalent to List folder contents in Windows.

The write permission on a directory in Linux is equivalent, if write and the sticky bit are both set on a directory, then only the user that owns a file or subdirectory in the directory may delete it, which is close to the behavior of the Windows Write permission.

The root user on Linux has the equivalent of the Windows Full Control permission on all files. However, root may still have access restricted by the system's SELinux policy and the security context of the process and files in. SELinux will be discussed in a later course.

# VIEWING FILE AND DIRECTORY PERMISSIONS AND OWNERSHIP

The -l option of the ls command shows more detailed information about file permissions and ownership:

```
[user@host]$ ls -l test
-rw-rw-r-- 1 student student 0 8 17:36 test
```
