
# TRANSFERRING FILES USING THE SECURE FILE TRANSFER PROGRAM

To interactively upload or download files from a SSH server, use the Secure File Transfer Program, sftp. A session with the sftp command uses the secure authentication mechanism and encrypted data transfer to and from the SSH server.

Using just the scp command, the sftp command uses [user]@host to identify the target system and user. If you do not specify a user, the command will attempt to log in using your local user name as the remote user name. You will be presented with an sftp> prompt.

```
[user@host ~]$ sftp remoteuser@remotehost
remoteuser@remotehost's password: password
Connected to remotehost.
sftp>
```

The interactive sftp session accepts various commands that work the same way on the remote file system as they do in the local file system, such as ls, cd, mkdir, rdir, and pwd. The put command uploads a file to the remote system. The get command downloads a file from the remote system. The exit command exits the sftp session.

To upload the /etc/hosts from the local system to the newly created directory /home/remoteuser/hostbackup on remot. The sftp session always assumes that the put command is followed by a file on the local file system and starts in the connecting user's home directory; in this case, /home/remoteuser:

```
sftp mkdir hostbackup
sftp> cd hostbackup
sftp> put /etc/hosts
Uploading /etc/hosts to /home/remoteuser/hostbackup/hosts
/etc/hosts                               100%  227      0.8KB/s    00:00
sftp>
```

To download /etc/yum.conf from the remote host to the current directory on the local system, execute the command get /etc/yum.conf and exit the sftp session with the exit command.

```
sftp> get /etc/yum.conf
Fetching /etc/yum.conf to yum.conf
/etc/yum.conf                               100%  813      0.8KB/s    00:00
sftp> exit
[user@host ~]$
```

# SYNCHRONIZE FILES AND DIRECTORIES with rsync

The rsync command is another way to securely copy files from one system to another. The tool uses an algorithm that minimizes the amount of data copied by synchronizing the portions of files that have changed. It differs from scp if two files or directories are similar between two servers, rsync copies the differences between the file systems on the two servers, scp would need to copy everything.

One of the advantages of rsync is that it can copy files between a local system and a remote system securely and efficiently. The initial synchronization of a directory takes about the same time as copying it, any subsequent synchronization only requires the differences to be copied over the network, speeding updates substantially.

One of the most important options of rsync is the -n option to perform a dry run. A dry run is a simulation of what happens when the command executes. The dry run shows the changes rsync would perform when the command is run without the dry run option. You should perform a dry run before performing any rsync operation to ensure no files get overwritten or deleted.

The two common options when synchronizing files and directories with rsync are the -v and -a options.

The -v or --verbose option provides more detailed output as the synchronization runs. This is useful for troubleshooting and to see progress.

The -a or --archive enables "archive mode". This is a quick way to enable recursive and turn a large number of options to preserve most characteristics of the files. Enabled with rsync -a (Archive Mode)

| OPTION | DESCRIPTION |
| :--- | :--- |
| -r, --recursive | synchronize the whole directory tree |
| -l, --links | synchronize symbolic links |
| -p, --perms | preserve permissions |
| -t, --times | preserve time stamps |
| -g, --group | preserve group ownership |
| -o, --owner | preserve the owner |
| -D, --devices | synchronize device file |

# CHAPTER 12 | Archiving and transferring

Archive mode does not preserve hard links, because this can add significant time to the synchronization. If you want to preserve hard links, add the -H option.

> NOTE
If you are using advanced permissions, you might need to add two additional options:
* -A to preserve ACLs
* -X to preserve SELinux contexts

You can use rsync to synchronize the contents of a local file or directory with a file or directory on a remote machine, using each machine as the source. You can also synchronize the contents of two local files or directories.

For example, to synchronize the contents of the /var/log directory to the /tmp directory:

```
[user@host ~]$ su
Password: password
[root@host]# rsync -av /var/log /tmp list
receiving incremental file list
log/
README
boot.log
...output omitted...
tuned/tuned.log
sent 11,592,423 bytes received 770 bytes 23,186,404.0 bytes/sec
total size is 11,586,755 speedup is 1.00
[user@host ~]$ ls /tmp
log ssh-RLjdarkKiWi1
[root@host~]$ $
```

A trailing at the end of the source directory synchronizes contents of a directory without newly creating the subdirectory in the target directory. In this example, the log directory is not created in the /tmp directory. Only the content of the /var/log/ directory is synchronized into the /tmp directory.

```
[root@host]# rsync -av /var/log/ /tmp
sending incremental file list
/
README
boot.log
