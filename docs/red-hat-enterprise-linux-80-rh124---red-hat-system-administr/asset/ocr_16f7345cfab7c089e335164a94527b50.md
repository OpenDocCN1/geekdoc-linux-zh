# Block Device Naming

| TYPE OF DEVICE | DEVICE NAMING PATTERN |
|---|---|
| SATA/SAS/USB-attached storage | /dev/sda, /dev/sdb ... |
| virtio-blk virtualized storage (some virtual machines) | /dev/vda, /dev/vdb ... |
| NVMe-attached storage (many SSDs) | /dev/nvme0, /dev/nvme1 ... |
| SD/eMMC storage (SD cards) | /dev/mmcblk0, /dev/mmcblk1 ... |n

> NOTE\Many virtual machines use the newer virtio-scsi virtualized storage that will have /dev/sd* -style naming.

# Disk Partitions

Normally, you do not make the entire storage device into one file system. Storage devices are typically divided into smaller chunks partitions.

Partitions allow you to compartmentalize a disk: the various partitions can be formatted with different file systems or used for different purposes. For example, one partition can contain user home directories where another contain system data and logs. If a user fills up the home directory with data, the system may still have available space.

Partitions are blocks in their own right. On SATA-attached storage, the first partition on the disk is /dev/sda1. The third partition on the second disk is /dev/sdb3, and so on. Paravirtualized storage devices have a similar naming system.

An NVMe-attached SSD device names its partitions differently. In that case, the first partition on the disk is /dev/nvme0p1. The third partition on the second disk is /dev/nvme1p3, and so on. On SD or MMC devices have a similar naming system.

A long listing of /dev/sda device reveals its special file type as b, which stands for block device:

```
[user@host ~]$ ls -l /dev/sda1
br-rw----. 1 root disk 8, 1 Feb 22 08:00 /dev/sda1
```

# Logical Volumes

Another way of organizing partitions and disks is with logical volume management (LVM). With LVM, one or more block devices can be aggregated into a storage pool called a volume group. Disk space in the volume group is partitioned out to one or more logical volumes, which are the functional equivalent of a partition residing on a physical disk.

The LVM system assigns names to volume groups and logical volumes upon creation. LVM creates a directory in dev that matches the group name and creates a symbolic link within that directory with the same name as the logical volume. That logical volume file is available to be mounted. For example, if a volume group is called myvg and the logical volume within it is called mylv, the full path to the logical volume device file is /dev/myvg/mylv.
