# CONFIGURING SSH KEY-BASED AUTHENTICATION

# OBJECTIVES

After completing this section, you will be able to configure a user account to use key-based authentication to log in to systems securely without a password.

# SSH KEY-BASED AUTHENTICATION

You can configure an SSH server to allow you to authenticate without a password using key-based authentication. This is based on a public-private key scheme.

To do this, you generate a matched pair of cryptographic key files. One is a private key, the other matching public key. The private key is used as the authentication credential, and a password must be kept secret and secure. The public key is copied to the server the user wants to connect to, and is used to verify the private key. The public key does not need to be secret.

You put a copy of the public key on the server. When you try to log in, the SSH server will use the public key to issue a challenge that can only be answered by using the private key with your unique copy of the private key. As a result, your ssh client will automatically authenticate your login to the server you securely access systems in a way that doesn't require you to enter a password every time.

# Generating SSH Keys

To create a private key and matching public key for authentication, use the ssh-keygen command. By default, your private and public keys are saved in ~/.ssh/id_rsa and ~/.ssh/id_rsa.pub files, respectively.

If you do not specify a passphrase when ssh-keygen prompts you, the generated private key is not protected. In this case, anyone with your private key could use it for authentication. If you set a passphrase, then you will need to enter that passphrase when you use the private key for authentication. (Therefore, you would be using the private key's passphrase rather than your password on the remote host to authenticate.)

You can run a helper program called ssh-agent which can temporarily cache your private key passphrase in memory at the start of your session to get passwordless authentication. This will be discussed later in this section.

# Sharing the Public Key

Before key authentication can be used, the public key needs to be copied to the destination system. The ssh-copy-id copies the public key to the destination system.

```
[user@host ~]$ ssh-copy -i ~/.ssh/key-with-pass.pub user@remotehost

user@remotehost: password: redhat
Number of key(s) added: 1
```

Now try logging in: "ssh user@remotehost" and check to make sure only the key(s) you wanted were added. After the public key is successfully transferred to a remote system, you can authenticate to the remote system using the corresponding private key. If you omit the path to the private key while running the ssh command, it uses the default id_rsa file.

# Using ssh-agent for Non-interactive Authentication

If your private key is protected with a passphrase, you normally have to enter the passphrase for key authentication. However, you can use a program ssh-agent to temporarily cache the passphrase in memory. Any time that you use SSH to log in to another system with the private key, ssh-agent will automatically provide the passphrase for you. This is convenient, and can improve security by providing fewer opportunities for someone "shoulder surfing" to see the passphrase in

Depending on your local system's configuration, if you log into the GNOME graphical desktop environment, the ssh-agent program might automatically be started and configured for you.

If you log in on a text console, log in using ssh, or **sudo** or **su**, you will probably need to start ssh-agent manually for that session. You can do this with the following command:

```
[user@host ~]$ eval $(ssh-agent)
Agent pid 10155
[user@host ~]$
```
