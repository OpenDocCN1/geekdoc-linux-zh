# MANAGING NETWORKING

PERFORMANCE CHECKLIST
In this lab, you will configure networking settings on a Red Hat Enterprise Linux server.

OUTCOMES
You should be able to configure two static IPv4 addresses for the primary network interface.

BEFORE YOU BEGIN
Log in as the student user using student as the password.

From workstation run the lab net-review start command. The command runs a script that determine if the host, server, is reachable on the network.

```
[student@workstation ~]$ lab net-review start
```

- 1. Use the ssh command to log in to server as the student user. The systems are configured to use SSH keys for authentication, so a password is not required to log in to server.

- 2. Use the sudo -i command to switch to the root user. If prompted, use student as the password.

- 3. Create a new connection with a static network connection using the settings in the table.

| PARAMETER | SETTING |
| --- | -- |
| Connection name | lab |
| Interface name | ens3 (might vary, use the interface that has 52:54:00:00:fa:0b as its MAC address) |
| IP address | 172.25.250.11/24 |
| Gateway address | 172.25.250.254 |
| DNS address | 172.25.250.254 |

- 4. Configure the new connection to be autostarted. Other connections should not start automatically.

- 5. Modify the new connection so that also uses the address 10.0.1/24.

- 6. Configure the `hosts` file so that 10.0.1.1 can be referenced as `private`.

- 7. Reboot the system.

Determine the interface name and the active connection's. The solution assumes that interface name is ens3.

```
[root@serverb ~]# ip link
1: lo: <LOOPBACK,MULTICAST,UP> mtu 65536 
    link/ether 00:00:00:00:00:00 qdisc noqueue 
2: ens3: <BROADCAST,MULTICAST,UP> mtu 1500 
    link/ether 52:54:00:00:fa:0b brd ff:ff:ff:ff:ff:ff qdisc noodel
```

Create the new connection profile based on the information in the table. Associate the profile with your network name linked in the output of previous ip link command.

```
[root@serverb]# nmcli con add-name lab ifname ens3 type ether ip4 172.25.250.11/24 gw 172.25.250.254 dns 172.25.250.254
[root@serverb]#
```

- 4. Configure the new connection to be autostarted. Other connections should not start automatically.

```
[root@serverb]# nmcli mod "lab" connection.autoconnect yes
[root@serverb]# nmcli mod "Wired connection 1" connection.autoconnect no
```

- 5. Modify the new connection so that also uses the address 10.0.1/24.

```
[root@serverb]# nmcli mod "lab" +ipv4.addresses 10.0.1.1/24
```

- 6. Configure the `hosts` file so that 10.0.1.1 can be referenced as `private`.

```
[root@serverb]# echo "10.0.1.1 private" >> /etc/hosts
```

- 7. Reboot the system.

```
[root@serverb]# reboot
Connection to server closed by remote host.
Connection to server closed.
[student@workstation ~]$
```
