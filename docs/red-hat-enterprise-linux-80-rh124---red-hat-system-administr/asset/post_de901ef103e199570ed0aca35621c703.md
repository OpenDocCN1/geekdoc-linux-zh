# CONFIGURING HOST NAMES AND NAME RESOLUTION

## OBJECTIVES

After completing this section, you will be able to configure a server's static host name and name resolution and test the results.

## CHANGING THE SYSTEM HOST NAME

The hostname command displays or temporarily modifies the system's fully qualified host name.

```
[root@~]# hostname
host@example.com
```

A static host name may be specified in the /etc/hostname file. The hostnamectl command is used to modify this and view the status.

```
[root@server]# hostnamectl set-hostname example.com
[root@server]# hostnamectl status
Static hostname: example.com
Transient hostname: example.com
Icon name: vm
Deployment: vm
Kernel: Linux 4.18.0-348.el8.x6_64
Architecture: x86_64
```

# CONFIGURING NAME RESOLUTION

The stub resolver is used to convert names to addresses. The /etc/hosts file determines where to look.

```
127.0.0.1   localhost
::1         localhost ip6-loopback ip6-local
172.25.250.11 servera
172.25.250.12 serverb
```

The /etc/resolv.conf file contains nameserver addresses. NetworkManager updates this file as interfaces are started.

```
# Generated by NetworkManager
 NOT NOT EDIT..




......................



......com
nameserver 8.8.8.8
nameserver 1.1.1.1
```

To add the DNS server with IPv6, use the + symbol in front of the ipv6.dns argument.

```
[root@server]# nmcli con mod "static-ens3" +ipv6.dns 2001:4860::8888
```

![](img/59afb92e1067a9ce358a2c65e93b5)

Static IPv4 and IPv6 DNS settings all end up as nameserver directives in /resolv.conf. You should ensure there is, at minimum, an IPv4-reachable name server listed (assuming a dual-stack system). It is better to have at least one name server using IPv4 and a second using IPv6 in case you have network issues with either your IPv4 or IPv6 networking.

## Testing DNS Name Resolution

The host HOSTNAME command can be used to test DNS server connectivity.

```
[root@host ~]# host classroom.example.com
classroom.example.com has address 172.25.254.254
[root@host ~]# host 172.25.254.254
254.254.254.172.in-addr.arpa domain pointer classroom.example.com.
```

## IMPORTANT

DHCP automatically rewrites the /etc/resolv.conf file as interfaces are started unless you specify PEERDNS=no in the relevant interface configuration files. Set this using the nmcli command.

```
[root@host ~]# nmcli con mod "static-ens3" ipv4.ignore-auto-dns yes
```
