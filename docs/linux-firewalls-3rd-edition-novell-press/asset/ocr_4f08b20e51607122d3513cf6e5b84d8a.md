# TABLE 3.12
**multipart Match Extension**

| | --match **multipart** **OPTION** | DESCRIPTION |
|---|---|---|
| | --source-port <port> [,\u003cport>] | Specifies the source port(s). |
| | --destination-port <port> [,\u003cport>] | Specifies the destination port(s). |
| | --port <port>[,\u003cport>] | Source and destination ports are equal, and they match a port in the list. |

The **multipart** syntax can be a bit tricky. Some examples and cautions are included here. The following rule blocks incoming packets arriving on interface **eth0** destined for the UDP ports associated with NetBIOS and **SMB**, common ports that are exploited on Microsoft Windows computers and targets for worms:

```
iptables -A INPUT -i eth0 -p udp\
-m multipart --destination-port 135,136,137,138,139 -j DROP
```

The next rule blocks outgoing connection requests sent through the **eth0** interface to high ports associated with the TCP services NFS, **socks**, and **squid**:

```
iptables -A OUTPUT -o eth0 -p tcp\
-m multipart --destination-port 2049,1080,3128 --syn -j REJECT
```

What is important to note in this example is that the **multipart** command must exactly follow the protocol specification. A syntax error would have resulted if the --**syn** were placed between the -p tcp and the -m multipart.

To show a similar example of --syn placement, the following is correct:

```
iptables -A INPUT -i <interface> -p tcp \
-m multipart --source-port 80,443 ! --syn -j ACCEPT
```

However, this causes a syntax error:

```
iptables -A INPUT -i <interface> -p tcp ! --syn \
-m multipart --source-port 80,443 -j ACCEPT
```

Furthermore, the placement of source and destination parameters is not obvious. The following two variations are correct:

```
iptables -A INPUT -i <interface> -p tcp -m multipart \
--source-port 80,443 \
! --syn -d $IPADDR --dport 1024:65535 -j ACCEPT
```

and

```
iptables -A INPUT -i <interface> -p tcp -m multipart \
--source-port 80,443 \
-d $IPADDR ! --syn --dport 1024:65535 -j ACCEPT
```
