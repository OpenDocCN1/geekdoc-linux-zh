# ### local_dhcp_client_query and remote_dhcp_server_response

The `local_dhcp_client_query` and `remote_dhcp_server_response` chains contain the rules required of a DHCP client. Placement of these rules in the chain hierarchy is important in relation to any spoofing or generalized broadcast rules. Furthermore, the host will not configure its IP address until after receiving the DHCPOACK commitment message from the server. The destination address that the server uses in the DHCPOACK message depends on the particular server implementation. If you want to use this rule, you'll need to set `DHCP_CLIENT` to `1` and also define the `DHCP_SERVER` variable:

```
# Some broadcast packets are explicitly ignored by the firewall.
# Others are dropped by the default policy.
# DHCP tests must precede broadcast-related rules, as DHCP relies
# on broadcast traffic initially.
if [ "${DHCP_CLIENT}" = "1" ]; then
    DHCP_SERVER="my.dhcp.server"
```

```
# Initialization or re-binding: No lease or Lease time expired.

$IPТ -A local-dhcp-client-query \
    -s $BROADCAST_SRC \
    -d $BROADCAST_DEST -j ACCEPT
```

```
# Incoming DHCPPOFFER from available DHCP servers

$IPТ -A remote-dhcp-server-response \
    -s $BROADCAST_SRC \
    -d $BROADCAST_DEST -j ACCEPT
```

```
# Fall back to initialization
# The client knows its server, but has either lost its lease,
# or else needs to reconfirm the IP address after rebooting.

$IPТ -A local-dhcp-client-query \
    -s $BROADCAST_SRC \
    -d ${DHCP_SERVER} -j ACCEPT
```
