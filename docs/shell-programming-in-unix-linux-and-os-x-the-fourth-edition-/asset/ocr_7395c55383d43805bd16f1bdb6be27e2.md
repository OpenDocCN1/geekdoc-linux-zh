If the conditional test is valid, nothing is done. If it’s not valid, the error message is issued and the program exited.

To be fair, this particular example could be reversed by restructuring the grep statement (remember the ‘!’ argument to test?) but sometimes it’s easier to test for a positive condition and do nothing than a negative. In either case, this is where a well placed comment can do wonders when the code is read weeks or months later.

# The && and || Constructs

The shell has two special constructs that enable you to execute a command based on whether the preceding command succeeds or fails. In case you think this sounds similar to the if command, well it is. Sort of. It’s a shorthand form of the if.

If you write

```
```sh
command_1 && command_2
```
```

anywhere that the shell expects to see a command, command_1 will be executed, and if it returns an exit status of zero (success), command_2 will be executed. If command_1 returns a non-zero exit status (fail), command_2 is not invoked but is ignored.

For example, if you write

```
```sh
sort bigdata > /tmp/sortout && mv /tmp/sortout bigdata
```
```

then the mv command will be executed only if the sort is successful. Note that this is equivalent to writing

```
```sh
if sort bigdata > /tmp/sortout
then
        mv /tmp/sortout bigdata
fi
```
```

The command

```
```sh
[ -z "$EDITOR" ] && EDITOR=/bin/ed
```
```

tests the value of the variable EDITOR. If it’s null, /bin/ed is assigned to it.

The || construct works similarly, except that the second command gets executed only if the exit status of the first is nonzero. So if you write

```
```sh
grep "$name" phonebook || echo "Couldn't find $name"
```
```

the echo command will get executed only if the grep fails (that is, if it can’t find $name in phonebook, or if it can’t open the file phonebook). In this case, the equivalent if command would look like

```
```sh
if grep "$name" phonebook
then
    :
```
```
