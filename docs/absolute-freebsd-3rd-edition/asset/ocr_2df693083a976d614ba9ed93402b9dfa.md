```
# netstat -m
---snip--
132/372/404/25600 mbuf clusters in use (current/cache/total/max)
---snip--
0/0/0 requests for mbufs 0denied (mbufs/clusters/mbuf+clusters)
---snip--
```

Here we see how many mbuf clusters are used Ⓚ. You’d probably guess that these are related to mbufs, and you’d be right. You don’t have to know exactly what mbuf clusters are; the important thing is that you know how many you can allocate Ⓛ and can see that you’re under that limit.

Similarly, we can see how many different requests for mbufs the kernel has denied Ⓜ. This system hasn’t rejected any requests for mbufs, which means that we aren’t having performance problems due to memory shortages. If your system starts rejecting mbuf requests because it’s out of memory, you’re in trouble. See “Optimizing Network Performance” next.

While netstat -m produces a dozen lines of output, netstat -s runs for pages and pages. It provides per-protocol performance statistics. Much like netstat -n, you can break up these statistics into categories of how much was done and how many problems you had. Run both of these commands occasionally on your systems and review the results so you know what passes for normal on your servers and can recognize abnormal numbers when you have problems.
