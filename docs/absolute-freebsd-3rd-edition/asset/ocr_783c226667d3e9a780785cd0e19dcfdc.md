
The first line shows us column headers **1** for the provider name, the size of the partition, the amount of space used, the amount of space available, the percent of space used, and the mount point. We can see that the partition labeled `/dev/gpt/root` **2** is only 1GB in size but has only 171MB on it, leaving 785MB free. It’s 18 percent full and mounted on `/`.

If your systems are like mine, disk usage somehow keeps growing for no apparent reason. Look at the `/usr` partition **3** here. It’s 98 percent full. You can identify individual large files with `ls -l`, but recursively doing this on every directory in the system is impractical.

The `du(1)` program displays disk usage in a single directory. Its initial output is intimidating and can scare off inexperienced users. Here, we use `du(1)` to find out what’s taking up all the space in my home directory:

```
# cd $HOME
# du

5    ./.kde/share/appLnk/staroffice_52
6    ./.kde/share/appLnk
-- snip --
```
