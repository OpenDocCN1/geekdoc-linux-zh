The `rorder(8)` program sorts all the scripts in `/etc/rc.d` and `/usr/local/etc/rc.d` into the order used at system boot, using markers within the scripts themselves. If your rc scripts have any ordering errors, such as deadlocked scripts, those errors appear at the beginning of your `rorder(8)` output.

# ### A Typical rc Script

The rc script system is pretty simple—while scripts can get complicated, the complexity comes from the program the script runs, not the rc system. The script that starts the NFS server has a whole bunch of dependencies and requirements. The script for a simpler daemon, like `timed(8)`, illuminates the rc system.

```
#!/bin/sh
# PROVIDE: 1 timed
# REQUIRE: 2 DAEMON
# BEFORE: 3 LOGIN
# KEYWORD: 4 nojall shutdown
5 . /etc/rc.subr
6 name="timed"
7 desc="Time server daemon"
8 rcvar="timed_enable"
9 command="/usr/sbin/${name}"
10 load_rc_config $name
   run_rc_command "$1"
```

The `PROVIDE` label 1 tells `rorder(8)` the official name of this script. This script is called `timed`, after `timed(8)`.

The `REQUIRE` label 2 lists other scripts that must run before this script runs. Scripts that need `timed` to run before they can start list `timed` in `REQUIRE`. This script can run any time after the `DAEMON` script has been run.
