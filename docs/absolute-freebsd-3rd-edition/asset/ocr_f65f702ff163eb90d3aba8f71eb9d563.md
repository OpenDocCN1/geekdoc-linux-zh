We start by defining a macro for our interface name **1** so that if we change network cards, we won't need to rewrite all our rules.

The second line instructs PF not to filter on the lo0 interface **2**. The loopback interface is local to the machine. The only host that can communicate over it is the local machine.

Then, we scrub incoming traffic **3**, reassembling packets into a coherent whole and throwing away what can't be reassembled.

Now that we have a sensible stream of incoming data, we can filter it. This policy starts by blocking all incoming traffic **4**, setting a default deny policy. Everything not explicitly permitted is forbidden.

Outbound traffic gets a default allow policy **5**.

The final three rules in this policy address TCP, UDP, and ICMP. They have a similar format, which we'll dissect shortly.

First, we permit TCP traffic to ports 22, 53, 80, and 443 **6**.

Next, we permit UDP traffic to port 53 **7**. If this host offered more services than DNS, we'd have a longer list of ports.

The final rule allows vital ICMP traffic to our host and permits the host to respond **8**.

Let's take a closer look at the TCP rule.

```
`**1**pass in on $ext_if**6**proto tcp**4**from any**5**to {$ext_if}**8**port {22, 53, 80, 443}`
```

This host has a default deny policy on inbound traffic, so with the pass in statement **1**, we're carving out an exception to that policy.

The next chunk of the rule specifies which interface this rule applies to **2**. This rule applies to the interface defined by the macro `$ext_if`, or em1.

Then, we specify a protocol **3**. This rule applies to TCP connections.

You can write PF rules that apply only to specific source or destination addresses. This rule applies to traffic from any host **4**. You can drop this part of the rule if you're permitting any source address.
