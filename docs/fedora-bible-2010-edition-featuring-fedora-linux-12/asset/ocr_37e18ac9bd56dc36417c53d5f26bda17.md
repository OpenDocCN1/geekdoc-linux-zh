+   **Is the startup script set up to launch the service automatically?** Most networuk services are launched from startup scripts that cause daemon processes to listen to the networuk continuously for requests for the service. Type `service --status-all` to list the status of all services or `chkconfig --list` to see the run levels at which each service is on. See the “Networking Service Daemons” section for more information on how to find startup scripts and have them launch automatically.

+   **Does SELinux permit access to the service?** When SELinux is enabled (Enforcing), it puts an additional layer of security over selected network services. If a service is denying access that you think should be working, type `getenforce` to see if SELinux is in Enforcing mode. If it is, type `setenforce 0` to change SELinux to Permissive mode. If the service works, you can leave SELinux off (actually in Permissive mode) or turn it back on (type `setenforce 1`) and debug the SELinux issue as described in Chapter 9.

+   **Is the configuration file created for the service?** Even if the daemon process is listening for requests for a networuk service, one or more configuration files associated with the service should probably be set up before requests will be accepted. Table B-1 lists important configuration files for each type of server.

+   **Does the configuration file permit proper access to the service?** Within the configuration file for a service, there might be several levels of permissions that a user must go through to get permission to the service. For example, a configuration file might allow access to the service from a particular host computer, but deny access to a particular user. If the service has TCP wrappers for the service, host computers can be allowed or denied access to the service based on settings in the `/etc/hosts.allow` and `/etc/hosts.deny` files.

+   **Does the firewall permit access to the service?** When you set up a firewall, if you choose the default firewall, most services will not be available outside your local computer. Refer to Chapter 13 for information on how to change your firewall configuration to open ports that provide the different services.

+   **Are there other restrictions to the service being shared?** Some standard Linux security measures might block access to a service that is otherwise open to being shared. For example, you can share a Linux directory using NFS or FTP servers, but local file permissions might block access to the directory or files within the shared directory.

To begin determining where a service failure has actually occurred, look to the log files contained in the `/var/log` directory. The `messages` and `dmesg` files contain general messages about processing that occurs when services and hardware are initialized. Many services, such as Sendmail and Apache Web servers, have their own log files. Setting debug levels on service daemons is a way to get more details about how a service is working (see the “Debugging Services” sidebar).

The rest of this appendix provides an overview of the daemon processes, startup scripts, configuration files, and software packages that are associated with the networking services that come with Fedora.
