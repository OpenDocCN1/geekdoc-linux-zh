# Enabling SELinux

Security Enhanced Linux (SELinux) is enabled by default in Fedora. As it is implemented with targeted policies, most popular server types (including Web, FTP, and DNS) have policies set that restrict what intruders can do if they manage to break into the service. You should look over how policies are set on the SELinux Administration window (system-config-selinux command) for services you are offering.

There are two critical areas of protection you should be aware of if you are enabling SELinux for your server:

+   - **File contexts** — Every configuration file, log file, and shared content file has an SELinux file context associated with it. Type ls -lZ filename to see a file’s SELinux context. If you create new content directories or overwrite configuration files using the mv command, the context will most likely make those file inaccessible by the service when SELinux is in enforcing mode.

+   - **Booleans** — Some features that you may have enabled within a service may be blocked by default when SELinux is enabled. An example of that is when you enable an FTP server to allow regular Linux user accounts to access their home directories. Unless you turn on a Boolean in SELinux for that or other potentially insecure services, SELinux will block access to that feature when it’s in enforcing mode.

Refer to Chapter 9 for more information on Chapter 19. It will tell you how to turn Booleans on and off, as well as how to change file contexts so your service can access those files. SELinux man pages for each service (httpd_selinux, ftpd_selinux, and so on) describe SELinux features associated with each service.

# Checking logs and system files

By making your servers public, you also make them more open to attacks. Although firewalls are a good first line of defense, you still need to watch the activity on those ports that you leave open. A consistent program of monitoring traffic and checking changes to your server, therefore, becomes more critical. The following are a few techniques that you can use to help secure your servers:

+   - **General security** — Make sure that you protect all your user accounts by using good passwords and the correct file permissions settings.

+   - **Tripwire** — Use Tripwire to take a snapshot of your critical system files so that you can check later whether anyone’s altered those files. The tripwire package is included in the latest Fedora repository.

+   - **File System Saint** — As with Tripwire, File System Saint maintains a database of every file on your system. You can find out more information from the project’s SourceForge net site (http://sourceforge.net/projects/fss).
