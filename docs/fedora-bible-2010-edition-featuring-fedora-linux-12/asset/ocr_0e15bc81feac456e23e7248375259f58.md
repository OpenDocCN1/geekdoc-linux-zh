The *cachedir* (`/var/cache/yum/$basearch/$releasever`) is where the RPM files are downloaded to by yum when you ask to install or upgrade packages. The `$basearch` variable is replaced by your system's computer architecture and `$releasever` is replaced by the version number of your Fedora system.

The `keepcache=0` option causes all downloaded packages and headers to be erased after they are installed. If you select to save the RPM files (which some people do if they want to share packages with multiple machines, without multiple downloads), you need to set `keepcache=1` and make sure the directory has enough disk space to handle it. During a testing cycle, I ended up with about 1 GB of RPMs in my `/var/cache/yum` file system (of course, they can just be deleted after they are installed).

> NOTE: You can clean out a lot of the data cached by yum with the command `yum clean all`.

Messages related to yum processing are sent to `/tmp/yum.log` by default, using a debug level of 2 (0 to 10 is legal, with 2 producing minimal success or failure messages). The `exactarch` set to 1 indicates that you must match the name and release architecture exactly for a package.

The `obsoletes` option lets yum determine obsolete packages during updates. The `ggpcheck` indicates whether or not a check of the package's GPG key is done (1 indicates the check is done). The value of `metadata_expire` determines when the metadata you have from a repository expires, after which Fedora will check to see if there is new metadata to download on the next invocation of yum. The default of `metadata_expire=1.5h` causes metadata to expire in 1.5 hours after it is received. If you set this value, the number you use can be followed by an m (minutes), h (hours), or d (days). With no added letter, the number you enter is read as seconds. If you do not add this setting to the `yum.conf` file, then yum will use the default value.
