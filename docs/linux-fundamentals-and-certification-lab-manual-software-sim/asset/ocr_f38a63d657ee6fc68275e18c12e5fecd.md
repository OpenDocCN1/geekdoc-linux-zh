^ Match the expression at the start of a line. For example:
`[jsmith@Styx etc]$ ls | grep "^ns"`
nsd.conf
nsswitch.conf

$ Match the expression at the end of the line. For example:
`[jsmith@Styx etc]$ ls | grep "conf$"`
aep.conf
aeplog.conf
cdrecord.conf

[] Match any of the enclosed characters. Use a hyphen for a range, as in [a-z]. For example:
`[jsmith@Styx etc]$ ls | grep "[0-9]"`
a2ps.cfg
a2ps-site.cfg
gnome-vfs-2.0
gtk-2.0
iproute2
krb5.conf
pbm2ppa.conf
pnm2ppa.conf
rc0.d
rc1.d
rc2.d
rc3.d
rc4.d
rc5.d
rc6.d
w3m
X11

The special characters may need to be included as search items. For example, a user may need to look for a ^ within a file. Using the caret is difficult because the caret is a special character that tells grep to search the start of the line for the expression. To allow the expression to contain a caret, use the escape character (\). The expression to find a ^ within an expression would be “\\^”.

# USING VI AND OTHER EDITORS

**Objective 2.15** If you are using the CLI, you have to learn to use a text editor to edit text files. Most Linux and Unix operating systems use a program called vi (pronounced “vee-eye,” as two separate letters). The vi program has been around nearly as long as Unix and continues to be the most widely used text editor. vi is short for visual editor. In Linux, vi shows a window of 24 lines of text from a file. The vi text editor lets you add, change, and delete text only. vi does not have any formatting capabilities such as bold, underline, or line centering. There are other text editors, but mostly they emulate vi and usually offer a few improvements. The Red Hat Linux distribution uses vim (Vi Improved), which is open source and an improvement over vi (Figure 5–5).

GUI editors are similar to any other GUI-based program. They have a menu to select major options, a toolbar for shortcut commands, and support for keyboard and mouse input. GUI editors work within a window in the GUI environment. Figure 5–6 shows the GEdit program for the Gnome GUI environment.
