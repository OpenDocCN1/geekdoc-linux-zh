
- **File systems don’t mount.** The `/etc/fstab` file contains mount information for file systems that are to be automatically mounted during startup. Mounted file systems can be local file systems or remote file systems. This configuration file was explained in Chapters 4, 8, and 9.

- **Users can’t log in.** The `/etc/passwd` or the `/etc/shadow` file may be damaged or misconfigured. These files contain user account information. These files can be edited directly, or the utilities `passwd`, `useradd`, `groupadd`, `usermod`, and others can be used. These files can also be changed through GUI tools from an X desktop.

- **Can’t find remote computers.** The `/etc/hosts` file contains static translations of IP addresses to host names. Using TCP/IP networking, most systems have a DNS server available to provide address resolution; but on a small intranet this may not be the case. If the `/etc/hosts` file is used instead of DNS, every computer on the intranet should have the same file contents.

- **Can’t ftp into the server.** This is sometimes caused by the user’s shell not being listed in the `/etc/shells` file.

There are many configuration files. Any of these files can be misconfigured, accidentally deleted, or moved to the wrong location, causing the program it is designed to work with to not work. It is a good idea to document all configuration files as they are created. Configuration files should be backed up when they are changed.

# Server Software Problems

A server is any machine that provides services for users or other computers. Typically, a server is a network server, meaning that users and other servers on the network are the clients of the server. Services provided by a server are many and varied, such as network services, database services, application services, disk space services, printer services, and others.

## Network Server Software Problems

Common network services provided by a server include Dynamic Host Configuration Protocol (DHCP), Domain Name System (DNS), and remote login via Telnet or SSH. If network services fail, all user and computer clients could be unable to access the system. If DHCP is down, for example, all clients of the service will be unable to obtain an IP address and will not be able to interact with the network.

One way to ascertain information about network problems is through the log files. For example, if a user is not receiving an IP address via DHCP, the log file may contain information about the request. You can dynamically view log entries as they occur by using the `tail` command with the `-f` option. Figure 13–8 shows the `tail -f` command with the `/var/log/messages` file.

Network server software problems can be especially hard to solve because proper operation of network server software depends on the server, the network, and the client being configured correctly. For example, a client experiencing problems receiving a dynamic IP address must first be configured to use DHCP, the network must be operational and allowing access to the DHCP server, and the DHCP service must be available on the server. (DHCP server and client configuration was explained in Chapter 7.) A few things that can cause server software problems are the following:

- **A service not starting.** A service may not have started because of hardware failure, network failure, a conflict with another process, and other reasons. Often, a service that did not initially start can be started manually. Use the `status` option of the `service` command to determine if the service started.

```
# service sendmail status
sendmail is stopped
# service sendmail start
Starting sendmail:                                [ OK ]
Starting sm-client:                               [ OK ]
# service sendmail status
sendmail (pid 15556 15547) is running...
```

- **A service not responding.** The service may be running and configured correctly, but not serving clients. The first thing to check is that the firewall is not blocking access. You might want to temporarily stop `iptables` to check that it is not blocking access.

```
# service iptables stop
Flushing all chains:                               [ OK ]
Removing user defined chains:                     [ OK ]
Resetting built-in chains to the default ACCEPT policy: [ OK ]
```

- **Slow response.** A service may be working but extremely slowly. Use the `top` command to check that swap space and memory are available and that the CPU is not overworked. Any of these conditions could indicate that system resources need to be updated.

## Database and Application Server Software Problems

Many of the things that affect network services also affect database or application servers. You still need to check that the service is running and responding in a timely manner.

All applications require disk space, RAM, and swap space to operate, but a database application can grind to a halt if adequate resources are not available. For example, database applications have transient files that can grow to fill up all available disk space, causing the application to fail completely. Moving transient files to a separate hard drive can greatly improve performance and may prevent the system from crashing due to lack of available disk space.

## Disk Space Server Problems

Many servers provide disk space to users. The most common problem with providing disk space is that users tend to store large amounts of data to the space. The best way to limit the amount of disk space used is to implement quotas on the file system. Chapter 10 discussed how to implement quotas.

## Print Server Problems

In Chapter 9, configuring a printer was discussed. Problems encountered with the printer usually involve the print queue. A print queue can fill up with print jobs to the point that it can accept no more jobs. Usually, the cause of an overfilled print queue is a failure of the printing hardware. If the jobs can’t flush from the queue, the number of jobs will grow causing not only the print queue to fail, but the server to slow as well.

# Hardware Errors

No system is immune from hardware failures. Every component in a computer system will fail at some point. The most vulnerable components are the disk storage devices, power supply, keyboard, mouse, and modem. This doesn’t mean that other components won’t fail, just that they aren’t as likely to do so.

Most hardware failures on a computer system can be taken care of by the administrator. Before hardware problems can be solved, they must be diagnosed and the failed component identified.

## Identifying Malfunctioning Hardware Components

The easiest way to identify a component that has failed on a system that is under a manufacturer warranty is to let the computer vendor do it for you. Many systems have one-, two-, or three-year warranties, many of which perform warranty work on-site; but if you don’t have a warranty you need to identify the component that has failed.

The first step in identifying a failed component is to know what happens when power is applied to the system. The following is a chronological list of events that occur when a computer starts:

- **Power is applied to the system.** Often this is indicated by an illuminated LED on the front panel of the computer system and the soft starting of a cooling fan from the back of the case.

- **BIOS is loaded.** The BIOS, Basic Input/Output System, loads and then runs POST, Power-On Self-Test. The keyboard, mouse, video card, RAM, hard disk, and other devices are checked. If something is wrong with any component, a message is displayed.

- **The operating system kernel is loaded.** The OS kernel is loaded from a boot device. This is usually a hard disk, but can be a floppy disk, CD-ROM, or the network.

- **The OS kernel loads the operating system.** The operating system is a group of programs loaded by the kernel. These programs start the network, load servers, mount file systems, and perform other tasks required to start the OS.

- **The operating system checks and configures peripheral devices.** The programs started by the OS check devices, such as printers, scanners, and network connections, to ensure proper connection and function.

Start at the first step of computer startup and work through each process to find the device that is causing the problem. If the machine boots but a problem occurs after the operating system is loaded, you may be able to run a diagnostics program to perform a detailed check of system components.

Many computer systems come with a diagnostics disk that can be used to boot the system and check for failed components. On some systems the diagnostics program is built into the BIOS and can be run on startup.

## Replacing Components

Some systems are designed to replace components with no tools. However, your basic tool kit should include an assortment of screwdrivers, a static ground wrist strap, and a bright light.

The screwdrivers are usually needed to remove a hard disk or floppy drive, and sometimes to remove the computer case.

A static ground wrist strap is used to dissipate a static charge from your body and prevent damaging electronic components.

A bright light is needed to make sure that jumpers and cables are plugged in correctly.
