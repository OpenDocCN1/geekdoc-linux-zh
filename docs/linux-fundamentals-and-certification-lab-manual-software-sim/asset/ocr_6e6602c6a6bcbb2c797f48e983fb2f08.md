# ## Monitoring Storage Space

As any administrator will tell you, there is never enough disk space. The space used by applications, users, and data grows over time. Applications are revised to incorporate the latest GUI features, or patches are applied to fix problems, adding to required disk space. Users, as they become accustomed to available network storage, will store more and more information. The reasons are many, but two major ones are:

+   - Network storage is available. Users will find that they can keep a lot more information if they have a lot more storage space.
- Network storage is easily backed up and protected. If the Linux administrator manages the remote storage properly, part of the management policy will include backup of data. If users know that the backup of their important, or not-so-important, data will be done automatically, more storage will be used.

Disk space can be monitored manually or automatically. Most administrators use the df program to monitor disk space manually.

**Manual Monitoring of Storage Space** df displays the amount of disk space available on the file systems. It can display information about a specific file system or all the file systems. To run df to see all the file systems, type **df**:

```
```
# df
Filesystem     1K-blocks      Used Available Use% Mounted on
/dev/hda2        6049772    2469896   3272564  44% /
/dev/hda1         102454       9324     87840  10% /boot
/dev/hda3        2954168      32828   2771276   2% /dosfiles
none             159980          0    159980   0% /dev/shm
# 
```
```

Information about every file system is displayed, including the file system name, the amount of available 1K blocks, how much space is used, how much space is available, and the directory the file system is mounted to. To display only one file system, such as the root ( /) directory, use the following command:

```
```
# df /
Filesystem     1K-blocks      Used Available Use% Mounted on
/dev/hda2        6049772    2469900   3272560  44% /
# 
```
```

df is easy to use, but also easy to forget. Monitoring disk space must be done on a schedule. If an administrator fails to monitor disk space, the system may suddenly hang or fail to write information when data needs to be written.

**Automatically Monitoring Storage Space** An administrator may find that it is easier to monitor disk space automatically. Many administrators write their own scripts or purchase a commercial product to manage and monitor file systems.

Chapter 11 discusses the cron command, a useful tool for scheduling tasks. Commercial tools are available; for example, **Heros eQ** offers monitoring and management options for file systems and many more Linux properties. The **Webmin** program can monitor many system properties and, with third-party modules, can monitor disk space as well.
