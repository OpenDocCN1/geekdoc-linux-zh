## Starting X

There are several ways to start X. One that you are probably already using is to have it start when you first start Linux. This option was set during installation; if you are starting in run-level 3, however, you may want to start X to run a GUI program.

There is a script in /usr/X11R6/bin/startx that can be used to start X. It looks for startup information in the .xinitrc and .xserverrc files in the user's home directory. If those files cannot be found, it lets xinit start with its default values. This file may be customized for individual Linux systems.

Another way to start X is to use the telinit command to change the runlevel. The telinit command sends a signal to init, telling it which runlevel to change to. If you are in runlevel 3 and want to change to runlevel 5, type telinit 5.

Yet another way to start X is to set the default runlevel to 5. This can be done by changing the `id:3:initdefault:` line in the /etc/inittab (Figure 9–8) file. The X in the line represents the runlevel. Changing the value from 3 to 5, as in `id:5:initdefault:`, will set the default runlevel to automatically start X.

/etc/inittab file.

## Desktop Environments

Desktop environments provide an environment similar to Windows or Mac OS. A GUI interface makes using a computer for productivity much easier and much more feature-rich. The command-line interface is great for a Linux installation that is used as a server. Many, if not all, of the server functions are configured and run from the command line. Using a GUI for the same work unnecessarily uses additional resources on the system just to provide a more user-friendly environment. Using the GUI interface on a server can cause poor performance of any server software.

A GUI is a great tool for any user of the Linux operating system. Its point-and-click environment makes selecting tasks for the operating system easy. There are two predominant desktop environments for Linux—GNOME and KDE.

## PRINTERS

Printing is a task that is available on every computer system. Setting up a printer would seem to be a simple task, and in some cases it is; depending on the printer, however, it is not always so simple. New tools for Linux have changed printer administration for the better.

One caution when picking a printer for your Linux system: Be sure to ask the dealer whether the printer will work with Linux. Some printers are especially designed to work with Windows and are difficult, if not impossible, to use with Linux. Chances are that the printer dealer will not know whether the printer works with Linux, but almost every printer manufacturer has an online presence with the information you need. You can also check with www.linuxprinting.org for their Linux printer compatibility list. This can save you a lot of time and trouble.

There are several different types of printers. The two most prevalent types today are ink-jet and laser printers. An ink-jet printer sprays the ink on the paper to form the characters to be printed. A laser printer uses a modified copier engine. Images are formed in the laser printer's RAM, then transferred to the copier.

Several technologies are used to permit printing from Linux. Linux must have a printer driver to know how to deal with a printer. A printer driver database, called Foomatic, is used by most current Linux versions. It supplies common printer drivers, generating Adobe-compliant PPD files that allow easy setup of print queues with access to all driver options. Foomatic is an XML-based system that integrates the free software drivers with all common print spoolers.

> You can find the Foomatic printer driver database at 222.linuxprinter.org.

Extensible Markup Language (XML) is a specification developed by the World Wide Web Consortium (W3C). XML is designed to enable the definition, transmission, validation, and interpretation of data between applications.

A spooler is a program that controls print jobs in a queue. The spooler has the task of taking the print jobs one at a time and sending them to the printer in sequence.

Many applications use PostScript Printer Definition files (PPD). PPDs provide the printer driver and additional information about the printers. They are used by many Linux applications and are also used on Windows and Mac OS machines.

PostScript is a language developed by Adobe Systems for printing documents on laser printers; its technology, however, can be adapted to produce images on other types of devices. The printer drivers developed using PostScript technology are PPD files.

Non-PostScript printers can be defined with PPD files. These PPD files can be used to generate the appropriate form or printer driver by using Ghostscript. Ghostscript is a set of programs that, among other things, acts as an interpreter for the PostScript language. It has the capability to convert PPD files to many raster formats, view them on displays, and print them on printers that do not have PostScript language capability.

## Objective 2.16 Spooler and Queues

Printing within Unix and Linux in the past used one of two printing systems, the Berkeley Line Printer Daemon (LPD) and the AT&T Line Printer system. Vendors have added varying levels of support for other types of printers. Replacements for these systems, LPRng, Palladin, and PLP, have emerged, but none has substantially changed the fundamental capabilities of the original systems.

From these printing technologies proposed standards for network printing have emerged. The protocol that is fast becoming the standard now is Internet Printing Protocol (IPP), developed by the Internet Engineering Task Force (IETF) through the Printer Working Group (PWG). IPP defines extensions to the Hyper Text Transport Protocol (HTTP) to provide support for remote printing services.

Several types of print spoolers can be used on Linux systems. A print spooler queues and manages print jobs locally and remotely. The print spooler is the heart of the Linux printing system and controls all printing jobs. It manages the print queues on the system and communicates with printer drivers and input/output components.

## LPR/LPD

Line Printer Request/Line Printer Daemon (LPR/LPD) is the printing method most commonly used in TCP/IP networks (currently being replaced by CUPS, discussed later in this chapter). The LPR/LPD protocol is broken into two parts—LPR and LPD. LPR submits print requests to the LPD daemon for printing. This daemon receives and processes the requests from LPR. LPD is documented in RFC 1179.

LPD, LPRng, GNUlpr, and similar spoolers are supported through Foomatic with a program called the PPD-O-Matic PPD file generator.
