A useful command when dealing with file systems is the **du** command. The du command displays the estimated amount of space being used by files in a directory. If you type **du** at a shell prompt, the disk usage for each of the subdirectories will be displayed in a list with the grand total of file usage as the last line. To see only the total file usage, type **du -hs**.

Another command used with file systems is **df**. The df command displays the amount of disk space available on the file system. If no filename is given in the command, then the space available for all currently mounted file systems is shown. To show available disk space in 1K blocks, use the -k option. The syntax of the df command is **df [ -options] [file]**. To see available space on all file systems, type **df -k**.

## FILE PERMISSIONS

The primary function of file permissions is to deny access to unauthorized users. Permissions are used in conjunction with the UID and GID, or in other words, depending on the username and group assigned.

Linux provides two default levels of security. A user must supply a username and password for authentication. After the user is determined to have valid access to the Linux system, the second security level, file permissions, determines if the user is authorized to access the resource.

### Permission Categories

Using the `ls -l` command will display a listing similar to that shown in Figure 4–19. The first 10 characters are used to display the file type and the permissions for the owner, group, and all other users.

![](img/37f079cee226b270f2e09b37a2e4a05d_108_0.png)

![](img/37f079cee226b270f2e09b37a2e4a05d_108_1.png)

File type is indicated by the first character. A file is represented by a hyphen (-) and a directory is represented by the letter d. Sockets are indicated by the letter s, symbolic links with l, and block and character devices with b and c respectively. The next nine characters represent the permissions for the owner, group, and other users.

The owner is represented by the next three characters. The letter r represents read permission, w represents write permission, and x represents execute permission.

The second set of three characters represents group permissions. These are the permissions assigned to the group identified by this file. In this case the group is dengle, but could be any group assigned by the system administrator. Users in the same group can access each other’s files based on the group permissions.

The third set of three characters represents the permissions assigned to everyone else, that is, anyone that is not the owner and that does not belong to the group.

### Types of Permissions

Every file or directory has a set of permissions that determines who can access and what they can do to the file. Permissions are represented by the characters r, w, and x, which represent read, write, and execute, as seen in Table 4–1. The permissions are slightly different when assigned to a file or a directory.

**Table 4–1**

Permissions.

| Permission | Symbol | File Usage | Directory Usage |
| :--- | :--- | :--- | :--- |
| Read | r | File can be displayed or copied. | Directory can be listed with the ls command. |
| Write | w | File can be changed. | Directory files can be created or deleted. |
| Execute | x | Files can be executed if they are scripts or executables. | Directory files can be copied. A directory must have execute permission to allow files to be copied or moved. |

For example:

- `-rwx-----` indicates a file that has read, write, and execute permissions for the owner only.
- `-r-xr-xr-x` indicates a file that has read and execute permissions for the owner, group, or anyone else.
- `drwxr-x---x` indicates a directory that allows read, write, and execute permissions for the owner, read and execute for the group, and execute only for everyone else.

### Changing Permissions

The command to change permissions is **chmod**. Permissions can be changed using symbolic mode or octal mode. The chmod syntax is `chmod mode filename/directory` where mode is either a symbolic value or an octal value and filename/directory is the name of the affected file or directory.

- Symbolic mode uses letters and symbols to assign permissions to files or directories.
- Octal mode uses octal numbers to assign permissions to a file or directory.

Symbolic modes are composed of symbols for who, the operation, and the permission to be applied. Table 4–2 describes each symbolic value.

**Table 4–2**

Symbolic values.

| Who | | |
| :--- | :--- | :--- |
| | u | User or owner of the file or directory |
| | g | Group to which the file belongs |
| | o | Others, not owner or group |
| | a | All of the above |
| Operation | | |
| | = | Set permissions |
| | - | Remove access |
| | + | Give access |
| Permissions | | |
| | r | Read |
| | w | Write |
| | x | Execute |

The file list

```
-rw-rw-r-- 1 dngle dngle 0 Sep 15 15:59 mydocument
```

indicates that mydocument has read/write permissions for the owner and the group and read permission for everyone else. To change the owner permissions to read/write/execute, the execute permission would have to be added. To make the change using symbolic mode, type the command `chmod u+x mydocument`.

The u indicates the user or owner of the file, the plus (+) indicates to add the following permission, and the x indicates the execute permission. The results of an `ls -l` command after the change would be

```
-rwxrw-r-- 1 dngle dngle 0 Sep 15 15:59 mydocument
```

indicating that the owner permissions have changed.

The octal mode is based on the base eight number system, as the name implies. In base eight there are only eight symbols, 0 through 7.

Base eight numbers can be expressed in three binary numbers. Binary is the base two number system. Binary is used by all computer systems to process information. An example of a binary number is 101. This number represents the number 5 in octal. Following from right to left, the rightmost number is in the ones column and has the value of 1. The middle number is in the two's column and has a value of 0. The leftmost number is in the fours column and has the value of 4. In this case the values 1 + 0 + 4 give the octal value 5. All of the base eight symbols, as stated earlier, can be expressed in three binary values. Table 4-3 associates octal values with the full range of available permissions. Notice that a zero (0) in the binary position of the octal value translates to a dash (-) in the permission.

**Table 4-3**

Permission values.

| Binary Value | Octal Value | Permissions |
| --- | --- | --- |
| 000 | 0 | --- |
| 001 | 1 | --x |
| 010 | 2 | -w- |
| 011 | 3 | -wx |
| 100 | 4 | r-- |
| 101 | 5 | r-x |
| 110 | 6 | rw- |
| 111 | 7 | rwx |

Notice the relationship between the rwx combination and the binary ones in the same positions. For the last octal value 7 the binary value is 111 and indicates that the r, w, and x are all to be set.

To set permissions for the owner, group, and others, use three sets of octal numbers to indicate the permissions desired. For example, to express the permissions rwxr-xr-x the octal value 755 would be used—7 for the first group (rwx), 5 for the second group (r-x), and 5 for the third group (r-x).

To use chmod with octal mode to change the following expression from owner read/write, group read/execute, and others read to owner read/write/execute, group read/write, and others read, use `chmod 764 mydocument`.

```
-rw-rw-r-- 1 dngle dngle 0 Sep 15 15:59 mydocument
```

The 7 represents rwx, the 6 represents rw-, and the 4 represents r--. A subsequent listing with `ls -l` would display

```
-rwxrw-r-- 1 dngle dngle 0 Sep 15 15:59 mydocument
```
