Within the /var/log directory you see several files and corresponding numbered files. The files that have descriptive names, such as messages, are current log files. As events occur, these files will be updated immediately. The numbered files are log rotation files. Log rotation is necessary to ensure that log files do not continually use more and more disk space. Log files, if left unchecked, will grow until there is no more disk space. Most files are set to rotate four times. A log file with a .4 after its name is the oldest log file of that type on the system. The /etc/logrotate.conf file is used to configure when log files are rotated. A cron job bash script, logrotate, is used to start the log rotation.

> NOTE
> Log information is listed in date/time order. The most recent entries are at the end of the file.

> NOTE
> The daily cron jobs are located in the /etc/cron.daily directory. Use the `file *` command to see what type of files are located in the directory. Most are bash script files and can be edited with any text editor.

The /var/log directory contains several log files. Most of the files are simple text files and can be browsed using Linux tools, such as vi, cat, more, or less. Some of the more interesting log files include the following:

- /var/log/boot.log Contains messages from the boot sequence.
- /var/log/cron Contains a list of cron jobs which shows which tasks were started and when.
- /var/log/dmesg Contains messages from devices. This log file should be viewed to help track hardware problems.
- /var/log/maillog Contains messages about e-mail.
- /var/log/messages Contains all error messages. This is the main system log and should be viewed to help resolve any problems.
- /var/log/secure This log keeps track of who logged in and when. This file should be viewed if you suspect someone is attempting to crack into your system. Cracking attempts will have the word “refused” within the log lines. Use the following grep command to quickly view any refused connections.

```
grep refused /var/log/secure | more
```

An unauthorized user may try to connect using brute force. This type of attack occurs when an unauthorized user has a program that has a list of user names with a corresponding list of possible passwords, which are used to continually attempt connection until a user name/password combination is found. This type of attack will show an unusually large number of Failed password entries.

The main program for the Linux logging system is the syslogd daemon. This daemon is run from a startup script when the system boots. Almost any program on the system can use the log file, including applications, drivers, and other daemons.

Log entries have a standard format. Programs can write entries in any format, but most follow the convention. The entries use the following format:

```
date  time  system  facility  message
```

- **date** This is the date of the message.
- **time** This is the time the message was written.
- **system** This is the host name from which the message was generated. Systems on a network can share a log file on a central computer.
- **facility** This is the process name and PID that generated the message.
- **message** This is the text of the message.

## SUMMARY

Tasks can be executed automatically using cron. cron is a daemon that schedules tasks for the system or for individual users. System cron jobs are crons that perform systemwide periodic jobs. Individual users can create user cron jobs to accomplish tasks for themselves only.

System cron job schedules are defined with the /etc/crontab file. The file contains fields for minute, hour, day, month, and weekday, and what program to run at the selected time. The programs to be run are located in the /etc/cron.X directories. The X stands for daily, weekly, and so on.

User cron jobs are defined within the user's home directory with a text editor. The user then uses the crontab command to tell the system that the user has cron jobs to be executed. User cron jobs are in the /var/spool/cron directory.

Core dumps are listings of everything in memory when a program fails. These files can be viewed by a programmer to determine what caused a program to fail. Core dump sizes can be limited with the ulimit command. Core dumps can take a lot of disk space and should be backed up and removed.

Processes are programs that run on the Linux operating system. Processes should be monitored for running time and CPU usage. They can be viewed with the ps command. Tools are available to prioritize, kill, suspend, and restart processes.

Processes can also be viewed with the top program. top provides an interactive view of running processes, CPU usage, memory usage, and swap usage. GUI programs are available to view and manage processes. GUI applications are also available to show charts and graphs of memory and CPU usage.

The Linux operating system allows the configuration of file system quotas. Quotas let Linux restrict file system usage based on soft and hard limits. Soft limits are values that, when reached, only display a message warning that the soft limit has been reached. After hard limits are reached, no further writes by the user are allowed.

Linux provides logging with the syslog daemon. Log files are written in the /var/log directory and can be used by applications, drivers, and other daemons.
