### NOTE

> The mount -av command actually mounts all file systems other than the root file system. The root file system is mounted by the kernel at boot time.

The fstab file contains static information about the file systems. Each file system is described on a separate line with fields separated by tabs or spaces. The order of the records in fstab is important because the file systems are mounted in the order presented in the file. The fstab file contains six columns of information.

- The first column of the fstab file is the device name or remote file system to be mounted. Typically, device names are names like `/dev/cdrom` or `/dev/hda2`. This field may also have an entry for listing the host and directory, for example, **cs.ua.edu/home**.
- The second column contains the mount point for the file system. This is a directory where the file system will be mounted.
- The third column describes the file system type. As discussed previously, Linux can use many file system types, including ext3, vfat, tmpfs, and others.
- The fourth column describes the mount options associated with the file system.
- The fifth column is used by the dump command to determine which file systems need to be dumped. If the fifth column is not present, a value of zero is returned and dump will assume that the file system does not need to be dumped.
- The sixth column is used by the fsck program to determine the order in which file system checks are done at reboot time.

The fstab file contains one entry for **/proc**. This pseudo-file system contains information about system processes, available memory, and other system information the kernel knows about. /proc is a pseudo-file system in that it does not actually use disk space on the hard drive. The typical command to mount a file system manually is **mount -t [type] [device] [directory]**. For example, to mount an ext3 file system on device **/dev/hda2** to the directory **/home**, use the **mount -t ext3 /dev/hda2 /home** command.

Mounting file systems manually is not a common occurrence, but if a temporary mount is needed, the command is available. Most mounts occur during startup with the mount -av command.

Mounted file systems are automatically unmounted during a system shutdown. Should the system halt unexpectedly, file systems could be damaged. To repair or check a file system, use the **fsck** command. If no file system is specified, the fsck command will check all file systems in the fstab file serially.

To unmount a file system, the syntax is **umount [mount point or device name]**. For example, to unmount the /dev/hda2 from the /home directory type either **umount /dev/hda2** or **umount /home**, and the device is unmounted.

To check a file system of file type ext3 and a mount point of /home, type the **fsck -t ext3 /home** command.

The exit code returned by fsck is the sum of the following conditions:

| Code | Condition |
| :--- | :--- |
| 0 | No errors |
| 1 | File system errors corrected |
| 2 | System should be rebooted |
| 4 | File system errors left uncorrected |
| 8 | Operational error |
| 16 | Usage or syntax error |
| 32 | Fsck canceled by user request |
| 128 | Shared library error |

The fsck program runs interactively by default. If an error is discovered, the user is prompted as to what action to take. The **-a** option can be used to repair the file system automatically without any questions. To see a list of options for fsck, refer to the man page.

## Using a Floppy Drive

Your first step in using a floppy drive is to know its location in the file system. If you have a single floppy drive then it is typically located in **/dev/fd0**. You can verify the location by viewing the */etc/fstab* file (**cat /etc/fstab**). A valid entry in the fstab file for your floppy would be:

```text
/media/floppy /dev/fd0 /mnt/floppy auto noauto,owner,kudzu 0 0
```

where:

- **/dev/fd0** — The floppy device location
- **/mnt/floppy** — The mounted read/write location for the file system
- **auto** — The file system type
- **noauto, owner, kudzu** — Mount options
- **0** — File system dump frequency
- **0** — File system check frequency

To format the floppy disk at the above-mentioned location, use the **mkfs** command. The following will format the 1.44 MB floppy disk:

```bash
mkfs -t ext3 /dev/fd0 1440
```

After the floppy is formatted you can mount it using the command **mount /dev/fd0 /mnt/floppy**. The /mnt/floppy location is the mount point for the floppy disk. This command will not work unless there is a disk in the floppy drive.

After the floppy drive has been mounted you can use the mount point, /mnt/floppy, to read and write to the drive. To view the contents of the floppy drive, use the **ls** command. To view the newly mounted floppy drive, use the **ls /mnt/floppy** command. Use the **rm**, **cp**, **mv**, and other commands to manipulate files and directories within the floppy.

To unmount the floppy drive, use the **umount** command. To unmount the floppy mounted at /mnt/floppy, use the command **umount /mnt/floppy**.

To switch the floppy disk you are using you must first unmount the drive, swap the floppies, and then mount the drive again.

## Objective 2.9 Using a CD-ROM

Using a CD-ROM is similar to using a floppy drive. The CD-ROM must be mounted before use and unmounted after use. A CD-R or CD-RW can also be written with data using the **cdrrecord** command.

To mount a CD you must first find the device. View the */etc/fstab* file to see the available devices. Typically, the first CD-ROM will have the following entry:

```text
/dev/cdrom       /mnt/cdrom        udaf, iso9660     noauto, owner, kudzu, ro  0 0
```

Similar to the floppy device, this CD-ROM is located at /dev/cdrom and uses the mount point /mnt/cdrom. To mount the CD-ROM, use the command **mount /dev/cdrom /mnt/cdrom**.

After the CD is mounted you can read it using the **ls** or **cp** command. CD-ROMs are mounted as read-only devices.

To change the CD you can **unmount** the drive or use the **eject** command. You can use the eject command to eject the CD-ROM by typing **eject cdrom**. After the drive ejects the CD, insert the next CD and start over.

CD-Rs and CD-RWs can be written with data. The **cdrrecord** command is available and will work on almost all Linux systems. If the cdrrecord command is not loaded on your system you can download the package from the official site *ftp://ftp.berlios.de/pub/cdrrecord/.*

To find your CD writer, use the **-scdbus** option. Typing **cdrrecord -scdbus** will display drives that are installed and recognized. For example:

```text
# cdrrecord -scdbus

cdrrecord 2.0 (1686-pc-linux-gnu) Copyright (C) 1995-2002 Jörg Schilling
Linux sg driver version:  3.1.24
Using libscg version 'schily-0.7'

scsibus0:
  0,0,0  0) '  ' '48X12X50 CD-RW' '1.00' Removable CD-ROM
  0,1,0  1) *
```

The above display shows that the device is 0,0,0.

To burn an ISO image, use the following cdrrecord command:
**cdrrecord -v dev=0,0,0 speed=0 driveropts=burnfree -eject -data myfile.iso**
where:

- **-v** — Verbose
- **dev=0,0,0** — Sets the SCSI target for the CD recorder
- **speed=0** — Set the speed factor of the writing process
- **driveropts=burnfree** — Driver options burnfree turns on Buffer Underrun Free
- **-eject** — Ejects the CD when the process is completed
- **-data** — Uses CD-ROM mode 1
- **myfile.iso** — Use the ISO file myfile.iso

The options for cdrrecord can be found using the **man cdrrecord** command.

## SUMMARY

During startup, the Linux operating system performs a power-on self-test (POST), loads the BIOS from ROM, then displays boot options via the boot loader, usually GRUB or LILO.

The Linux kernel is loaded into memory from the boot device and control is passed to it. The init program is then executed and controls the remainder of the boot process.

Init uses several scripts during startup:

- */etc/rc.d/rc.sysinit* sets environment values such as path, starting swap, and checking file systems. rc.sysinit uses *etc/sysconfig* configuration files and scripts.
- */etc/inittab* describes how the system should be set in each runlevel.
