
3. Load the initrd command to set RAM disk space. For example, `initrd /initrd-2.4.20-8smp.img`.
4. Run the `boot` command to load the operating system.

## Using LILO

LILO is a little different than GRUB. It has no interactive command interface, it stores information about the location of the kernel on the MBR, and it cannot read ext2 partitions. LILO allows only one command with arguments. Changes to the LILO configuration file require rewriting the stage 1 LILO boot loader to the MBR using the command `/sbin/lilo -v -v`.

### Configuring LILO

The LILO configuration file is `/etc/lilo.conf` (Figure 6–12). The /sbin/lilo command uses this file when writing information to the MBR.

![](img/37f079cee226b270f2e09b37a2e4a05d_156_0.png)

Figure 6-12 shows a sample LILO configuration file. The following commands are commonly used in the `/etc/lilo.conf` file:

- `boot=<device_name>` Indicates where LILO will be installed. In Figure 6-12, LILO will be installed on the first SCSI hard disk.
- `default=\<"label_name"\>` The default operating system for LILO to boot. The `<label_name>` refers to the label entry described below the image name of the operating system.
- `prompt` Displays the contents of the message line.
- `message=<filename>` The message screen that LILO displays to let you select the operating system.
- `image=<kernel_name>` Indicates the Linux kernel to boot.
- `root=<partition_name>` Indicates which disk partition to use as the root partition.
- `label=<"title_name">` The name that is displayed by LILO and the name referred to by the default line.
- `initrd=<ram_disk_name>` The name of the initial RAM disk that will be used at boot time.

## LINUX BACKUP

![](img/37f079cee226b270f2e09b37a2e4a05d_157_0.png)

Even the most reliable computer system can fail. Doing a backup is one way to plan for computer disasters. Disasters in this case can mean the computer center was severely damaged by flood or fire, but more likely it means that the hardware has failed or someone accidentally erased a directory or a hard drive.

Computer failures can include hardware failure, software failure, environmental failure, and human error. Failures can be minimized in effect, but not eliminated altogether. For example, one method of configuring multiple hard disks is to use RAID. If a system is using RAID 0+1, the failure of a single hard drive is minimal and probably not even noticed by users of the system. The RAID of many systems supports hot-swapping of hard drives, making repair of a failed drive just a matter of replacing the damaged drive without even stopping the computer system.

Hardware failure of a computer system will happen. Even electronic parts with no moving parts have wear from heat. To keep the effects of hardware failures to a minimum you could:

- Set up a second system to take over if the primary system fails
- Have redundant technologies, such as RAID, so that failures can be repaired easily and quickly
- Have replacement parts readily available as well as someone with the skills needed to replace them
- Have automated monitoring and notifications in place so that issues can be resolved before a hard failure occurs

No software is immune from failure. Some programs are not likely to fail, especially those that have limited functions to perform. Many programs are very complex and often have many developers working on them. In more complex programs failures are much more likely. Some software failures can be minimal with almost no effect, whereas others can cause the operating system to fail completely. To keep the effects of software failures to a minimum you could:

- Set up a second system to take over processing if the primary system fails
- Test the software on a test system before installing it on a production system
- Make a backup of all data and programs before installing the software

Environmental failures include losing electricity, leaky roofs, and others. Minimizing the effects of environmental failures can be costly and, depending on the problem, it can be difficult if not impossible to prevent them. For example, protecting against the effects of an earthquake can be accomplished by having a second facility in another location take over, a very expensive solution; however, barring extreme circumstances like an earthquake, there are solutions to environmental problems. For example:

- Protect against power outages by employing a battery backup or power generator.
- Protect against extreme temperatures by providing an air conditioned environment.
- Protect against lightning by using proper grounding and lightning rods.

Human error can take many forms. It can include anything from someone accidentally turning off power to the computer system to just typing in the wrong command. One term that applies to human error is Garbage In Garbage Out (GIGO), meaning that if bad data is entered into the computer system, bad information will be the result. Human failures can be protected against by providing proper training of personnel and backing up the data and programs on a regular basis.

The term backup has a specific meaning when it refers to an operating system: copying data and programs from the computer to another medium. Backups can be performed several different ways and with several different programs.

The typical backup hardware is a tape drive; however, smaller installations also use removable hard drives, optical disks, and high-capacity floppy disk devices. Tape drives are the slowest backup devices; however, tape media is the least expensive per megabyte.

Tape drives offer huge amounts of readily available storage area, allowing backup of local and remote computer systems. Many tape drive systems contain several tapes at once as well as multiple drives to allow access to vast volumes of storage capacity. Tape devices are accessed through device files. For SCSI drives the filenames are /dev/stX, where X is the number of the device. EIDE drives are named /dev/htX. **Hard drives are the fastest of backup devices and the most expensive.** Even though the cost of hard drives has dropped significantly, the cost per megabyte is still quite high. Hard disk backups are good for small, immediate backup needs. For example, if you need to reinstall a program on a system, you might back up to a hard drive before installing. Tape drives have come a long way recently in terms of capacity and performance. Modern tape drives are faster than optical drives and rival disk drives in some cases. The shelf life of modern tape cartridges can exceed 30 years. The real advantage of disk media, whether it is hard disk or optical, is how quickly data can be restored. With disk media, direct access to data is possible; but with a linear tape the data may be located several hundred feet into the tape, so access to the data will take considerable time compared to disk. Hard disks are beginning to be used for backups, but in these cases backup data is usually initially written to disk and then copied or moved to tape. This procedure is sometimes referred to as *staging*, and it offers some advantages in how the data is organized on tape. Optical drives are most often used for archiving and near line storage. They are expensive backups and disaster recovery, tape is still the media of choice. **Optical drives are slightly faster than tape and have a longer storage life.** The cost of the optical media has dropped to a price comparable to that of tape. With newer drive systems that support “juke box” technology (the ability to have a large volume of optical media available), this is a viable option. **High-capacity floppy drives** provide up to 200 MB of storage on a floppy cartridge that is about the size of a standard floppy disk. The storage space is about the same as that of tape drives, but the media is considerably more expensive. A common type of high-capacity floppy drive is the Zip drive from Iomega. Generally, the backup device of choice is the tape drive. Even in a home system, a tape can be installed for under a hundred dollars, and because tapes are reusable the long-term cost is minimal; however, many newer machines are equipped with CD-R or CD-RW drives, and the CD-R media is inexpensive. On a single-machine system, the CD-R is a good choice for a backup. There are three basic types of backups: full, incremental, and differential. Full backups copy the entire volume of data and then mark the files as having been backed up. Incremental backups copy only those files that have been changed since the last backup and then mark the files as having been backed up. Differential backups copy only the files that have been changed since the last backup and do not mark the files as having been backed up. It is a good idea to keep multiple backups of your systems. Most administrators follow a three-backup pattern with daily backups. In this pattern you perform a full backup at a scheduled time once a week. During the week perform daily incremental backups, rotating the tapes over several days or weeks. At the end of the second week, start over with a new set of tapes for the full backup. At the end of the third week, do a full backup with another set of tapes. At the end of the fourth week, overwrite the first week’s full backup tapes. Rotate the tapes every week thereafter. Your backup rotation requirements may be different, but you get the idea. Never have only one backup. It is a good idea to have at least one full backup set off site. If disaster does strike and you lose the entire facility, you will have at least one backup set that will survive and can use it to get up and running. Linux has several different programs for backing up and restoring data. A backup program is needed to perform the backup itself, but a backup policy is needed to document how, what, and when to back up. How to perform a backup is covered in this chapter; however, what and when to back up can be different for every Linux installation. What to back up depends on the needs of the organization. When to back up depends on how critical the data is.
