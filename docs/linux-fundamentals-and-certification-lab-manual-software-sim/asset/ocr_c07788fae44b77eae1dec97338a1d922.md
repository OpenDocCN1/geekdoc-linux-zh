# VALIDATING INSTALLED PACKAGES

The old adage “you get what you pay for” is never more true than when used to describe Linux applications. Some packages are great and perform the work of other applications costing hundreds or even thousands of dollars; however, some packages are developed and then distributed over the Internet freely without much testing to prove their worth.

A Linux administrator cannot afford to install applications on the operating system and then forget them. Often, many users are dependent on the services provided by the installed programs and if the services fail, productivity can suffer, system performance can drop, and many other undesirable consequences may result. It is up to the administrator to maintain and monitor the programs installed on the system.

# Verifying Programs on a Test System

It is unwise to test a new program on an active production system. Some software can cause a system to fail completely, causing down-time of the Linux operating system. Even a simple upgrade can cause the entire operating system to fail. For this reason it is a good idea to test new software on a *test system*.

In a perfect world, the test system would be exactly the same type and size of computer system as the production system. And in a small shop with limited needs, a duplicate computer can be used as a test system with minimal cost. In a medium to large size business, however, the cost of providing two production quality machines and using only one for production is prohibitive. More likely, the test system will be an older system or, at most, a system of much lower quality. This makes testing the performance of programs in these systems very difficult.

At the very least, the test system must have the same version of operating system as the production system. Linux distribution versions can be very different, even within the same distributor. Kernel changes, updated libraries, and updated drivers can cause problems with some software.

If you have access to a test system that rivals your production system, testing software is much easier and more likely to provide accurate results. The best scenario is to install a mirror image from the production environment on the test system. After the production system is duplicated, the new software can be installed and then monitored and evaluated.
