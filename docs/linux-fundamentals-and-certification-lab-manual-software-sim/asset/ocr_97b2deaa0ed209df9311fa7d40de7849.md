+   * **/etc/cron.allow, /etc/cron.deny**  These files are optional and contain a list of users that are allowed or denied the use of cron. If the files are not present, the Linux operating system will automatically allow or deny all users access to cron, regardless of the Linux distribution. In Red Hat Linux, if the files are not present, all users are allowed access to cron.
* **/var/spool/cron**  On some systems, this directory is where the system crontab file, named root, is located. On systems with the system file /etc/crontab, this directory contains the crontabs for individual users only. The filenames used for the crontab file are the usernames. The cron process examines the /etc/passwd file to find a list of valid users and then looks for a file in /var/spool/cron that matches the username.

**User cron**  Each user can have his or her own cron jobs list. The list is maintained in the user's home directory. A program called crontab is used to create, delete, or list the tables used by the cron daemon.

To create a user cron, create a file in your directory with the following format:

MAILTO=user@domain
minute hour day month weekday command

To experiment with the command, create a cron job that lists the contents of your home directory at ten minutes after noon. We will send the results to your sendmail account (see the Note following the example).

Create a file called ~/crontab.jsmith with vi. (The filename does not matter—it can be called anything.) The file will contain the following data.

MAILTO=jsmith
10 12 * * * ls -l

Tell cron the name of your crontab file.

crontab ~/crontab.jsmith
