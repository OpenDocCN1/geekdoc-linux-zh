# # Finding Services That are Running

To determine what services may have been executed during startup, look in the following places:

+   * **/etc/xinetd.conf (or inetd.conf) file** This file contains a list of services that may be started when requested. Use the following grep command to view the contents of this file:

```
```
grep -v ^# /etc/xinetd.conf
```
```

This command will list all the contents of the xinetd.conf file, except for any line with a # in it. The # character is used as a comment in a script. If a service that you do not want to start is listed, just edit the file and place a # at the beginning of the line for that service.

+   * **/etc/rcN.d (where N is a runlevel number) directory** These directories have the S and K scripts (Startup and Kill scripts) for services on the Linux system.

+   * **netstat command** The netstat command can be used to view what services are listening on a system. Services that are listening are running. To view running services, type the command:

```
```
netstat -an | grep LISTEN
```
```

By adding the “-p” switch, the netstat command will print the process ID of the process that is holding the port open. That way, you can confirm what program is listening on the port. For example, if an intruder had previously gained access to your server and saw that a Web server was listening on port 80, he may have replaced the Web server with a telnet or web server listening on port 80 for later use as an easy entry method through the firewall.

The netstat command will print out several lines. Look at the second column for an entry like 0.0.0:0.80. The 0.0.0.0 can be an IP address or just zeros. The :80 is the port that is listening. In this case, the Web server is listening.

Be aware, not all services run on well-known ports. Many services can be assigned ports other than their default ports. (This is often done for security reasons.)

# # Configuring a Service

Both GUI and command-line commands can be used when dealing with services. The two most commonly used command-line tools are chkconfig and ntsysv.

+   * **chkconfig** This is a command-line tool for maintaining the /etc/rcN.d files. The --list option displays a list of services and the runlevels at which they will run. The partial list below indicates that kudzu is available in runlevels 3, 4, and 5.

```
```
# chkconfig --list
kudzu     0:off  1:off  2:off  3:on   4:on   5:on   6:off
syslog    0:off  1:off  2:on   3:on   4:on   5:on   6:off
netfs     0:off  1:off  2:off  3:on   4:on   5:on   6:off
```
```

You can turn a service on or off for a specific runlevel by using the --level option. The command **chkconfig --level 3 httpd off** turns the Web server service off for runlevel 3.

+   * **ntsysv** This is a simple text-based interface (Figure 8-7) that allows you to turn services on or off. The display shows a list of available services and allows a user to select or deselect each service by using the up and down arrow keys and then pressing the space bar to toggle the service on or off.

+   * **GUI Tools** Several implementations of service configuration tools are available for GUI interfaces. Figure 8-8 shows the Services Configuration tool for Red Hat. To start or stop a service, you place or remove a check from the check box or select the service and click the start/stop/restart button.
