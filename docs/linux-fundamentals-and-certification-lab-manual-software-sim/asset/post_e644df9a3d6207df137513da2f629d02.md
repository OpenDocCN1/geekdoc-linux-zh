## Configuring for Quotas

Configuring the Linux operating system to use quotas involves several steps. The first step is to change the mount options for the file system that will have quotas applied. In order to set quotas for users, you must add the option usrquota to the file system to be configured. To set quotas for a group, add the grpquota option to the file system.

The /etc/fstab file, discussed in Chapter 8, contains the file system mount information. The following display of this file shows the change made to the /dev/hda3 file system. The usrquota option is added. To add the option for group quotas, just add the grpquota option to the line.

```
# cat /etc/fstab
LABEL=/              /                 ext3    defaults              1 1
LABEL=/boot           /boot             ext3    defaults              1 2
none                  /dev/pts          devpts  gid=5,mode=620        0 0
/dev/hda3             /newDrive         ext3    defaults,usrquota     1 2
none                  /proc             proc    defaults              0 0
none                  /dev/shm          tmpfs   defaults              0 0
/dev/hda5             swap              swap    defaults              0 0
/dev/cdrom            /mnt/cdrom        udf,iso9660 noauto,owner,kudzu,ro 0 0
/dev/fd0              /mnt/floppy       auto    noauto,owner,kudzu    0 0
/dev/cdrom1           /mnt/cdrom1       udf,iso9660 noauto,owner,kudzu,ro 0 0
#
```

After the file system is prepared you must have a quota database in the file system's root (/) directory. After the database is used by the quota system, it is not in a human-readable format. All you have to do is create an empty file to be used. Create the empty file with the touch command. The database name for user quotas is **quota.user**, and the name for group quotas is **quota.group**. The `touch /newDrive/quota.user` command creates the quota.user file in the /newDrive (/dev/hda3) root directory.

To add entries to the quota.user file just created, use the **quotacheck** command. The quotacheck command examines each file system, builds a table of current disk usage, and compares the table against that recorded in the disk quota file for the file system. If there is a discrepancy, the quota file is updated. By default user quotas are checked. Use the `man quotacheck` command for a complete list of options. Some of the more common options include the following:

- **-v**   Causes a verbose output of the command.
- **-a**   Says to check all mounted non-NFS file systems.
- **-u**   Causes quotacheck to explicitly check user quotas.
- **-g**   Causes quotacheck to explicitly check group quotas.

To have quotacheck check all file systems' user quotas (the default) and give a verbose listing, use the following command:

```
# quotacheck -av
quotacheck: Scanning /dev/hda3 [/newDrive] done
quotacheck: Checked 6 directories and 18 files
#
```

The quotas for the system haven't actually been set yet, but you can view the information generated so far with the **repquota** command. The repquota command prints a summary of the disk usage and quotas for file systems. It uses basically the same options as the quotacheck command. To view the report for our current usage, use the following command:

```
# repquota -av
```

# Managing Quotas

After quotas are configured, you have to turn the quotas on, set user/group limits, and set a grace period. The command to start or restart using quotas is **quotaon**. The quotaon command has the same options available as quotacheck.

```
# quotaon -auv
/dev/hda3: user quotas turned on
```

## Objective 4.13 Limiting user resource limits

Limiting disk space for a user is only one resource of the Linux operating system. The **ulimit** command can be used in a bash shell to impose limits on other resources. The maximum size of core files, memory usage, open file descriptors, and other values can be defined on one or many users. For example, the command **ulimit -Sc 0** will disable core dumps, **ulimit -Su 100** will set a soft limit of 100 processes, and **ulimit -Hu 150** defines a hard limit of 150 processes. Type **help ulimit** for a comprehensive list of available options for **ulimit**.

```
# help ulimit
ulimit: ulimit [-SHacdflmnpstuv] [limit]
Ulimit provides control over the resources available to processes started by the shell, on systems that allow such control. If an option is given, it is interpreted as follows:
-S use the 'soft' resource limit
-H use the 'hard' resource limit
-a all current limits are reported
-c the maximum size of core files created
-d the maximum size of a process's data segment
-f the maximum size of files created by the shell
-l the maximum size a process may lock into memory
-m the maximum resident set size
-n the maximum number of open file descriptors
-p the pipe buffer size
-s the maximum stack size
-t the maximum amount of cpu time in seconds
-u the maximum number of user processes
-v the size of virtual memory
```

To use **ulimit** to restrict resources for a single user, include the command in the user's **.bash_profile** file (notice the period at the beginning of the name). To limit the user to a maximum of 100 processes, enter the following line:

```
ulimit -H -u 100
```

To limit all users to the same value, enter the same command into /etc/profile.

# Advanced Power Management—Advanced Configuration and Power Interface

Advanced Power Management (APM) is an Application Program Interface (API). An API is a set of routines, protocols, and tools for building applications that access services provided by some lower-level modules, such as the operating system or JVM. APM is an API developed by Intel and Microsoft that enables developers to include power management in BIOS. APM defines a layer between the hardware and the operating system that effectively shields the programmer from hardware details.

Advanced Configuration and Power Interface (ACPI) is an open industry power management specification developed by Hewlett-Packard, Intel, Microsoft, Phoenix, and Toshiba. ACPI enables the operating system to control the amount of power given to each device attached to the computer. This enables the operating system to turn off peripheral devices when they are not in use. ACPI is meant to supersede the older APM standard and to provide a generic interface for recognition and configuration of hardware devices.

The ACPI specification was released in 1996. The latest version is 2.0c, with the 3.0 specification under development (see www.acpi.info). The latest version extends to computer platforms with 64-bit and 36-bit addressing.

## Using APM

For APM to work, the system BIOS in the machine must support the APM standard. For APM to work with the Linux operating system, the system BIOS must support at least APM version 1.0. You can get information about APM version or support using the **dmesg** command. Excerpts of the dmesg output of two different machines are shown below. These indicate that APM is not supported in the BIOS on the first machine and APM BIOS version 1.2 is supported on the second machine.

The apm command tells the Linux operating system how to use the power management features. The syntax is **apm -options** where the options are one or more of those listed below.

- `-V, --version` Print the apm program version and exit immediately.
- `-v, --verbose` Print information about the APM BIOS version and Linux APM driver version.
- `-m, --minutes` Print the total minutes remaining instead of using the hh:mm format.
- `-s, --suspend` Put the machine in suspend mode.
- `-S, --standby` Put the machine in standby mode.
- `-i, --ignore` Ignore APM suspend and standby events when on AC power.
- `-n, --noignore` Do not ignore APM suspend and standby events when on AC power.
