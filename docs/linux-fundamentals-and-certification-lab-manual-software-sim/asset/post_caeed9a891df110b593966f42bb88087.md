
4. Ensure that the `/usr/sbin/pppd` command is in the `ppp` group. For example, `chgrp ppp /usr/sbin/pppd`.

5. Set the `/usr/sbin/pppd` command to run with root privileges even if the command is run by another user. For example, `chmod u+s /usr/sbin/pppd`.

6. Copy the scripts `ppp-on` and `ppp-off` from the directory `/usr/share/doc/ppp-version/scripts` (where *version* is the version of the `ppp` program) to the `/usr/sbin` directory. For example:

```
cp /usr/share/doc/ppp-2.4.1/scripts/ppp-on /usr/sbin
cp /usr/share/doc/ppp-2.4.1/scripts/ppp-off /usr/sbin
cp /usr/share/doc/ppp-2.4.1/scripts/ppp-on-dialer /usr/sbin
```

7. Change the owner of `ppp-on`, `ppp-off`, and `ppp-on-dialer` to root. For example, `chown root /usr/sbin/ppp-on`.

8. Change the group of `ppp-on`, `ppp-off`, and `ppp-on-dialer` to `ppp`. For example, `chgrp ppp /usr/sbin/ppp-on`.

9. Change permission of `ppp-on`, `ppp-off`, and `ppp-on-dialer` to read and execute for the owner and the group. For example, `chmod 550 /usr/sbin/ppp-on`.

10. Edit the `ppp-on` script by changing the following entries:

```
TELEPHONE = telephone number to dial
ACCOUNT = your ppp-account
PASSWORD = your password
```

11. Set the `exec /usr/sbin/pppd` line to the correct dial-out device. For example, `ttt0`.

12. Edit the `/etc/ppp/options` file so that it contains the following values:

```
lock
modem
-detach
crtscts
defaultroute
asyncmap 0
mtu 552
mru 552
```

If the server you are connecting to requires PAP/CHAP, information needs to be configured in the `/etc/ppp/pap-secrets` or `/etc/ppp/chap-secrets` file. They must be owned by user root, group root, and have file permissions 740 for security. PAP and CHAP actually authenticate host computers, not users. However, an ISP typically will provide a username and password for you to connect to its systems and these will be used to identify your machine.

The `/etc/ppp/pap-secrets` file contains the following fields:

```
# Secrets for authentication using PAP
# client      server secret       IP addresses
```

If your username with your ISP is `jsmith` and your password is `Up#39!dn`, the file would contain the following:

```
# Secrets for authentication using PAP
# client      server secret       IP addresses
jsmith        *         Up#39!dn
```

The *server* is the name of the remote server. ISPs often have a server farm receiving information from a single dial-in number. The asterisk (*) indicates that connection can be to any remote server.

The IP addresses field is often blank. ISPs usually do not allow a remote system to set the IP number for security reasons.

The only difference in PAP and CHAP configuration for the `/etc/ppp/chap-secrets` file is the addition of the remote server's authentication information. A second line is added containing the remote server username and secret (password).

You're finished. The client should now be configured. You can test the modem by using the minicom program. Use the man minicom command for a list of options and commands.

## ISDN Services

Integrated Services Digital Network (ISDN) was designed to solve bandwidth problems that small offices or dial-in users have with telephone dial-in services. ISDN was developed to use the existing telephone wiring system but provide a totally digital network. It works similar to a standard phone dial-up connection in that it places a call when needed.

ISDN has several advantages over traditional dial-up systems. ISDN can be used to transmit more than traditional computer data. It can provide access to digital video and telephone network services (voice) as well.

ISDN initially connects much faster than a modem because ISDN uses out-of-band signaling. This means that ISDN uses a separate channel for connection maintenance and does not use the same channel(s) that are used for data. This out-of-band channel is called the D channel. ISDN provides faster data transfer than a modem. A modem is limited to a maximum of 56 Kbps (actually slower), whereas an ISDN bearer channel (B channel) can provide 64 Kbps. ISDN can use multiple B channels to provide faster rates.

Two ISDN services are available—Basic Rate Interface (BRI) and Primary Rate Interface (PRI). BRI offers two B channels and one D channel, referred to as 2B+D. This delivers a total bandwidth of 144 Kbps, two 64 Kbps B channels, plus one 16 Kbps D channel. The D channel is used only for control of the connection, not data transfer, so the total usable bandwidth with 2B + D is 128 Kbps. PRI offers 23 B channels and one D channel. This provides a total bandwidth of 1.544 Mbps. The D channel provides 64 Kbps with PRI.

A terminal adapter is used to connect to the Network Terminating Unit that the communications company installed for your ISDN connection. The terminal adapter has serial interfaces that are used to connect to a computer system. Linux works with ISDN just as with any other serial device.

The Linux device names for ISDN use the format `/dev/ttyIn`, where n is the number of the device. For example, tty10 is similar to tty$0.

## DSL and Cable Modem Services

Digital Subscriber Lines (DSL) and cable modem services provide always-on service, meaning that the connection to the remote server is always available. Each of these services has advantages and disadvantages.

- DSL allows for transmission of voice, video, and data over existing telephone lines. The DSL modem usually has an Ethernet connection to your computer. DSL is a term that refers to a family of services, each with different characteristics.
- Asymmetric Digital Subscriber Line (ADSL) is the most popular DSL type. It supports up to 8 Mbps for downloading and 1 Mbps for uploading. ADSL Lite technology provides bandwidth downstream up to 1.544 Mbps and upstream up to 512 Kbps. The maximum range of ADSL service is 12,000 feet. You must be within this range of the provider in order to use this service.
- Symmetrical Digital Subscriber Line (DSL) uses a single pair of phone lines at the same speed in both the upstream and downstream directions. SDSL provides a maximum bandwidth of 1.544 Mbps at a maximum range of 15,000 feet. SDSL is often used for video conferencing, where the downstream and upstream speeds need to be the same.
- High bit-rate Digital Subscriber Line (HDSL) provides up to 2,048 Kbps with three phone lines at a maximum range of 20,000 feet. HDSL is similar to SDSL and is most commonly used to provide T1 lines to businesses.
- ISDN Digital Subscriber Line (IDSL) provides symmetric download and upload speeds from 64 to 144 Kbps on a single phone line. Its maximum range is 39,600 feet, which can be doubled with a repeater.
- Very high bit-rate Digital Subscriber Line (VDSL) is the fastest DSL technology. It provides 52 to 13 Mbps download and 1.5 to 2.3 Mbps upload speed. The range of VDSL is from 1,000 to 4,500 feet.

Cable modem service provides an always-on connection using RG6 coax connection. RG6 is the coax wire connection from your local cable provider. The cable modem usually has an Ethernet or USB connection to your computer. In theory, the maximum speed of cable modem service is 30 Mbps. In practice, the speed is significantly less. Most cable service providers restrict the bandwidth as well, usually offering up to 2 Mbps.

Cable modems have the disadvantage of using a shared medium. In other words, the users of cable service share the bandwidth with every other user on the network. Therefore, the more users on the network, the slower the service.

Both DSL and cable modem service provide an Ethernet connection to the local computer. Most DSL and cable service providers allow the connection of only one computer at a time to the connection. However, some provide for multiple computer connections.

Multiple connections to a DSL or cable modem or DSL connection can be provided by connecting a router to the device. Most routers used for this purpose assume the primary connection to the DSL or cable modem and then provide connections to multiple users that can be routed through as though they were directly connected. Typically, the router will act as a DHCP server and provide private addresses to computers that connect. Those private addresses are translated to the actual IP addresses of the DSL or cable modem connections and then sent on to their final destinations.

Setting up Linux for DSL or cable modem service is relatively easy. Usually, you just provide an Ethernet connection configuration using DHCP. The DSL, cable modem, or router will provide the address. The gateway and DNS servers can be obtained from the service provider.
