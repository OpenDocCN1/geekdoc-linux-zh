# INTRODUCTION TO LINUX

Some of these package tools are described below. A more detailed description of package management is given in Chapter 5.

+   * **RPM (Red Hat Package Manager)** The RPM package manager is a command-line package management system capable of installing, uninstalling, verifying, querying, and updating computer software packages. RPM was designed by Red Hat and is used by Red Hat and other Linux distributions. Each software package consists of an archive and package information. An API (Application Program Interface) is also available, permitting advanced developers to manage installations within a native coding language. The current release of RPM is 4.2 and is shipped with Red Hat version 9.

RPM checks for package dependencies, and provides for signed packages and check-sums. RPM requires a proprietary tool (rpm) to manipulate or view the package.

+   * **DEB** Debian packages contain all the files necessary to implement a set of related commands or features. DEB is designed by Debian, and is used by Debian and other Linux distributions. Two types of Debian packages exist:

+       * **Binary packages** Binary packages contain executables, configuration files, man pages, and other documentation. These are contained in a .deb file.

+       * **Source packages** Source packages contain .dsc files describing the source package, a .orig.tar.gz file that contains the original unmodified source in gzip compressed tar format, and usually a .diff.gz file that contains the Debian-specific changes to the original source.

Debian packages provide for signed packages, checksums, and dependency checking. They are also viewable and can be manipulated by standard Linux tools.

+   * **TAR (Tape ARchive)** Tar packages, called tar balls, are the oldest of the package formats. Tar gets its name from its initial use by Unix as a tape archive tool (a program used to back up data to a tape storage device). It has been around longer than Linux and was available in the earliest releases of Unix. Tar packages are used by all Linux distributions. Tar files unpack everything in a single directory, leaving the user to sort items to appropriate directories on the system. Most packages are available in tar format. Tar is used by the Slackware Linux distribution, but is available for all Linux distributions. Tar packages do not check for program dependencies before installing a package.
Tar files do not provide for signed packages, checksums, or dependencies. They do use standard tools for manipulation.

+   * **TGZ** TGZs are tar balls, compressed with the gzip compression program. TGZ files are designed by Slackware. Slackware has a utility, slapt-get, that is used to help manage package dependencies. TGZ files alone do not provide for signed packages, checksums, or dependencies. They do use standard Linux tools for viewing and manipulation.

+   * **SLP (Stampede Linux Package)** SLP format was made available through the Stampede Linux distribution. SLP uses tar and bzip2, a compression tool, as its foundation. It is coupled with a package management tool suite.
SLP packages do not provide for signed packages or checksums, but they do provide dependency checking. SLP files can be extracted, but cannot be created or viewed with standard tools.

+   * **PKG** PKG is a package management system used by FreeBSD and many Unix operating systems. As with most package systems, the packaged software can be installed from the command line or by using a GUI tool. Solaris Unix uses the command-line commands pkgadd, pkginfo, and pgmr, and FreeBSD uses the corresponding pkg_add, pkg_info, and pkg_delete. Sun Solaris also uses a GUI tool, Sun Control Station (Figure 1–1), to help manage packages.
