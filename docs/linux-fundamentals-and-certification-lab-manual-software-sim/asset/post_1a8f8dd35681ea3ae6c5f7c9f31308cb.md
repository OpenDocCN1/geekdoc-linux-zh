```
# inittab
#		This file describes how the INIT process should set up

#
# Author:	Miquel van Smoorenburg, <miquels@drinkel.nl.mugnet.org>

# Default runlevel. The runlevels used by Mandrake Linux are:
#	0 - halt (Do NOT set initdefault to this)
#	1 - Single user mode
#	2 - Multiuser, without NFS (The same as 3, if you do not have networking)
#	3 - Full multiuser mode
#	4 - unused
#	5 - X11
#	6 - reboot (Do NOT set initdefault to this)
#
id:5:initdefault:	*

#	System initialization.
s1:sysinit:/etc/rc.d/rc.sysinit
10:0:wait:/etc/rc.d/rc 0
```

> **NOTE**
> Be careful when editing the /etc/inittab file. A mistake can cause your system to be unbootable without using a boot disk or reinstalling the system.

Runlevels 2 and 4 are available to configure in whatever way makes sense for your system. By using runlevels 2 and 4 for custom configuration, runlevels 3 and 5 remain undisturbed.

> **NOTE**
> If the system does not boot due to a bad /etc/inittab or if the password is corrupted or forgotten, perform the following steps to boot into single-user mode:

- If you are using boot loader LILO, type **linux single** at the boot: prompt and press Enter.

- If you are using GRUB as the boot loader, enter single-user mode with the following steps:
  1. In the graphical GRUB boot loader screen, select the Linux boot label and press **e** to edit.
  2. Arrow down to the kernel line and press **e** to edit.
  3. At the prompt, type **single** and press Enter.
  4. After the GRUB screen with the kernel information is displayed, press **b** to boot the system into single-user mode.

A bare system will boot with a command shell, allowing changes to be made to the operating system.

## Shutdown

Shutting down the Linux operating system is needed to prevent damage to files and/or file systems. When you use the operating system, there may be files open that are being used by users or the operating system. If the system powers down without cleaning up these open files and unmounting file systems, errors can occur.

The commands to shut down Linux are:

- /sbin/shutdown -h now causes a system halt
- /sbin/shutdown -r now causes a system reboot

# MANAGING USERS AND GROUPS

A Linux system can have only a few users or can have hundreds of users, depending on the system's purpose. A network server that provides DHCP information may require only a few users, whereas a file server that provides file space for users may require many user accounts. One of the key administrative tasks with Linux is managing users and groups. The primary reason for user accounts is to verify the identity of each individual using a computer system. A secondary reason for user accounts is to permit the per-individual tailoring of resources and access privileges. Resources can include files, directories, and devices. Controlling access to these resources is a primary task of an administrator.

A user can represent either a person or an application. A user account that represents a person is used by an individual to gain access to the Linux operating system. An application such as Oracle has an account that is used to run the application. This practice is safer than using the root account to run everything because the permissions for the Oracle account can restrict access to areas that only Oracle uses, whereas the root account has no restrictions.

Groups are a logical expression of organization. Groups tie together users that have a common purpose. For example, an organization may have persons responsible for accounts payable and others responsible for payroll. By placing the user accounts in an accounts payable group common permissions can be given to all the members of that group. Members of the accounts payable group would not have access to the information and resources of the payroll group. Users within the same group have the same read, write, or execute privileges of group resources.

## Usernames

Each user account can have several properties assigned to it. The most commonly known properties are the username and the password.

Usernames have one major requirement: They must be unique. In other words, a username identifies only one account and no other user can have the same username. Because of this requirement, it is important to have a policy, or naming convention, that states how usernames will be created.

## Naming Conventions

Naming conventions make “thinking up” usernames much easier. By putting some thought into how usernames will be created, the same policy can be applied for all subsequent users. Naming conventions can be very simple or very complex. The convention used is a product of the type and structure of organization.

The size of an organization has to be considered because it determines how many usernames must be supported. For example, a very small organization could use first names as usernames, whereas a large organization would have to use something more unique.

In a very large organization it is appropriate to consider the organization structure when deciding on usernames. For example, using the department or plant name in the username would help make usernames unique and provide a way to identify where the associated user is. Some commonly used conventions include:

- First name (Huey, Dewey, Louie, etc.)
- Last name (Doe, Smith, Duncan, etc.)
- First initial followed by last name (ldoe, dsmith, lduncan, etc.)
- Department followed by the user’s first initial and last name (AP-ldoe, PR-dsmith, AR-lduncan, etc.)

Regardless of the naming convention used, eventually there will be two individuals that have the same username if the naming convention is followed. Part of the naming convention should take these cases into account.

An easy way to deal with similar usernames is to append sequence numbers, middle initials, or part of an employee number to the username. The drawback to these methods is that it becomes difficult for others to determine which user is associated with which username. This can result in misdirected e-mail on occasion.

## Passwords

A username identifies who a user is, and a password verifies that the associated user is the one in question. In other words, a password is used to authenticate a user. To utilize password authentication, passwords must be secret, must be resistant to guessing, and must be resistant to brute-force attacks. (A brute-force attack is obtaining an encrypted password and using the computer’s processing power and algorithms to break the encrypted values.)

All users should be educated about the importance of password secrecy. Passwords should never be posted on the face of the monitor, under the keyboard, in a drawer, or anywhere else for that matter. Passwords should never be shared with anyone. A password should be kept as secret as the pin number of a bank card.

A strong password should be at least eight characters in length, consisting of uppercase and lowercase letters, numbers, and special characters. Passwords should not have letters or numbers in sequence.

A strong password policy should require that passwords be changed periodically. Most administrators require that passwords be changed every 30 to 90 days. A further common requirement is that passwords cannot be changed earlier than 30 days.

Another good password policy is password aging. Password aging requires that passwords used during the past several password cycles not be reused. In other words, if you used a password in January and then, per the password policy, changed it in February, you could not use January’s password. For that matter, the password would be unusable for the next several months if the policy is enforced.

## Groups

A group is a logical grouping of users and resources. If Linux system resources are going to be shared by multiple users, groups are necessary to indicate which users have permission to access specific resources. It is a common practice to have a central server that makes specific directories available to other machines on the network. Users then have access to the shared directories to store data.

Shared data spaces accomplish two tasks.

- Users have a location to store data that is not physically on their workstation. If a system experiences a hard drive failure, the data is still safe.
- Data on shared spaces can be accessible to all users within the group. Users collaborating on projects can share documents and data files easily from the centrally shared location.

## Permissions

Permissions can be set for Linux system resources. There are three different permissions: read (r), write (w), and execute (x). These permissions are used to control the kinds of access allowed. Each of the symbols (r, w, x) indicate whether a resource can be read from, written to, or executed by a user, a group, or everyone.
