### Objective 2.16 Managing a Printer

After you have configured a printer, the next step is to manage it. The lpr, lpq, lpstat, and lprm commands can be used to manage print files. The lpr command is used to print a file. Use the `man lpr` command to view options.

To print a file, use the following command:

```
lpr filename
```

where *filename* is the name of the file to be printed.

To print a file to a specific printer, use the following command:

```
lpr -P printername filename
```

where *printername* is the name of the printer and *filename* is the name of the file to be printed.

The lpstat command is used to see what printers are configured. Use `man lpstat` to see available options. The following command:

```
lpstat -d -p
```

lists the default (-d) printer and lists the printers (-p) available and their status.

The lpq command is used to print a list of the print jobs that are running. The lpq command will display a listing similar to the following:

```
LinuxPr1 is ready and printing
 Rank        Owner        Job        File(s)          Total Size
 active      root           3        myfile.txt         1024 bytes
```

You can narrow the lpq report by asking about a specific print job by task ID (rarely used), by printer, or by user ID. For example, to get a report that identifies spooled files sent to a printer named LinuxPr1 you would use the following command:

```
lpq LinuxPr1
```

The print job number is 3, the filename is myfile.txt, and the file is 1024 bytes in length.

To delete a print job, use the `lprm` command. To delete the print job listed above, use the following command:

```
lprm 3
```

If you are root, you can use lprm with no options to delete all print jobs. If you are a normal user, only the print files you own are removed from the print spool. The lprm utility reports on the tasks it kills. The root user can kill all the print tasks issued by any user, by specifying a username. To remove all print jobs of jsmith use the following command:

```
lprm jsmith
```

## LPRng Permissions and Authentication

There are several security issues when printing. Most printers in today's work environment are TCP/IP printers. If a printer is on the public network then anyone on the Internet can print to the printer. Networked printers should be configured so that only certain host IP addresses will be accepted.

Different print queue types use different methods for securing the printer. On LPRng, an extended and enhanced version of Berkeley LPR print spooler, the /etc/lpd.perm file is used to specify permissions and authentication before printing. An incoming request is tested against a list of rules (/etc/lpd.perm), and the first match found determines the action to be taken. The action is either ACCEPT or REJECT. An ACCEPT accepts the incoming print request and sends the file to be printed to the print spooler. A REJECT will block printing, and will not send the file to be printed to the print spooler.

The following simple permission file first specifies that lpc commands from user root will be accepted. Any other lpc requests are then rejected. The third, fourth, and fifth command lines accept requests from the host and user that submitted the job to remove the print job from the queue. Finally, all other types of commands are allowed by default.

```
# allow root on server to control jobs
ACCEPT SERVICE_C SERVER REMOTEUSER_root
REJECT SERVICE_C
#
# allow same user on originating host to remove a job
ACCEPT SERVICE_M SAMEHOST SAMEUSER
# allow root on server to remove a job
ACCEPT SERVICE_M SERVER REMOTEUSER_root
REJECT SERVICE_M
# all other operations allowed
DEFAULT ACCEPT
```

A service can specify the following request types.

| Key | Request |
| :-- | :-- |
| C | LPC Control Request |
| M | LPRM Removal Request |
| P | Job Printing |
| Q | LPQ Status Request |
| R | LPR Job Transfer |
| S | LPC Status Request |
| X | Connection Request |

Other entries in the file specify the following:

- **DEFAULT** The rule to follow if no other rules match
- **REMOTEUSER** Information taken from the remote user that sent the service request
- **SAMEHOST** Indicates that the REMOTEHOST, retrieved by doing a reverse IP name lookup, and HOST, taken from the H information in the print job control file, must match.
- **SAMEUSER** Indicates that the REMOTEUSER, taken from the information sent with the service request, and USER, taken from the P information in the print job control file, must match.

Other actions can be found in the man file, or the LPRng Reference Manual can be downloaded from www.lprng.org.

## CUPS Permissions and Authentication

CUPS provides support for address, certificate and password-based (both basic and digest) authentication, and access control. Certificate and password authentication enables you to limit printer access based on an individual’s provided information. Address-based access control allows you to limit printer access to specified systems, networks, or domains. This doesn’t provide authentication, but it does prevent printing from locations other than your specified networks.

Several files are used to configure CUPS. All of the server files are located in the /etc/cups directory.

The /etc/cups/cupsd.conf file controls how the CUPS server operates, and it is normally edited by hand. The /etc/cups/printers.conf file contains information on each printer and is normally changed using the lpadmin command.

After you have made changes to a configuration file you must restart the CUPS server. In the Redhat Linux operating system the script used to restart CUPS is in the /etc/init.d directory and is called cups. To restart cups, use the following command:

```
# /etc/init.d/cups restart
Stopping cups: [ OK ]
Starting cups: [ OK ]
#
```

The /etc/cups/cupsd.conf directive that specifies which hostname, IP, or network is allowed to print is called Allow. Common directives are listed below:

```
Allow from All
Allow from None
Allow from *.domain.com
Allow from .domain.com
Allow from host,domain.com
Allow from nn.*
Allow from nn.nn.*
Allow from nn.nn.nn.*
Allow from nn.nn.nn.nnn
Allow from nn.nn.nn.nn/mm
Allow from nn.nn.nn.nnn/mmm.mmm.mmm.mm
```

The Allow directives that use the nnn values identify networks. For example, Allow 192.168.0.* indicates that this private network will allow all hosts within it.

The subnet mask, indicated by nn or mmm, can also be identified using either the full specification or the number of network bits. For example, Allow 192.168.0.12/24 and Allow 192.168.0.12/255.255.255.0 are equal.

The Deny directive specifies a hostname, IP address, or network that is denied access to the printer. The syntax is the same as that for Allow.
