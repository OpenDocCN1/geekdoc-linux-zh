
## PPR

PPR is a Unix/Linux printer spooler designed for PostScript printers. PPR supports PostScript printers connected to parallel ports, serial ports, or various networks including TCP/IP. Its best feature is that it is designed to work with large numbers of printers. PPR is specifically designed to use PostScript files, but it will accept non-PostScript files and convert them to PostScript.

The queue handling provided by PPR supports hold or cancel of submitted jobs. Any administrator can hold, release, cancel, or move a print job to another printer.

PPR is also supported through the PPD-O-Matic PPD generator for Foomatic. The foomatic-rip filter script can be used as a PPR RIP filter or as a PPR interface.

## PDQ

PDQ is a Unix/Linux printer spooler designed for PostScript and non-PostScript printing. It has many queue management features that are of great help to administrators. PDQ can monitor jobs through and after completion, filter out printing of specific file types, and perform other functions.

One of the nice features of PDQ is its GUI interface (Figure 9–11). PDQ provides a very user-friendly interface to its queue manager.

PDQ is also supported through the PPD-O-Matic PPD generator and the companion foomatic-rip filter script. Foomatic-rip provides for not only PostScript files, but also plain text, PDF, images, and others.

PDQ processes the entire job before sending it to the printer. With heavy print loads, this can cause serious delays when printing.

## CUPS

Common Unix Printer System (CUPS) uses IPP/1.1 to provide a complete printing system for Unix/Linux systems. It is free software provided under the terms of the GNU General Public License and the GNU Library Public License.

The CUPS scheduler is a HTTP server application that handles HTTP requests via IPP. It also acts as a Web server (Figure 9–12) for documentation, status, monitoring, and administration.

![](img/37f079cee226b270f2e09b37a2e4a05d_253_0.png)

The CUPS HTTP server can be reached on the local machine by using the URL http://127.0.0.1:631/admin. When asked for the administrator ID and password, use root or some other superuser account. The default CUPS configuration limits administration to the local machine. To open up access, edit the /etc/cups/cupsd.conf file and comment out the lines reading:

```
Order deny,allow
Deny from all
Allow from 127.0.0.1
```

### FIGURE 9-12 CUPS HTTP administration.

![](img/37f079cee226b270f2e09b37a2e4a05d_253_1.png)

CUPS is an extensible printing system and represents a leap forward for Unix/Linux print systems. The IPP protocol is a client/server protocol that allows the server side to be either a separate print server or a printer with embedded networking capabilities. CUPS supports legacy programs and can easily handle LPD requests and other requests.

## Configuring a Printer

Several applications can be used to configure a printer. The setup program in many Linux distributions allows users to configure a printer. Many distributions have their own printer configuration tools as well. Regardless of the tool used to configure the printer, most installations use either LPng or CUPS. Currently, many major Linux distributors recommend using CUPS. CUPS is the default on SuSE, Mandrake, Red Hat, and other Linux distributions. This section will outline the usage of printconf, a printer setup program available in Red Hat version 9. Both text and GUI versions will be used. The text version will add a local printer and will be demonstrated first.

### HARDWARE CONFIGURATION

NOTE: CUPS can be configured through the HTTP connection outlined earlier in this chapter.

1. From the command line, type **printconf** or **redhat-config-printer** and press Enter. If you are using a GUI screen, the GUI program will be displayed. The Red Hat Printer Config (Figure 9–13) screen is displayed.

### FIGURE 9–13 Red Hat printer configuration screen 1.

![](img/37f079cee226b270f2e09b37a2e4a05d_254_0.png)

NOTE: Use Tab to move from option to option. Press the spacebar to select a button or list item. The spacebar will open a list, indicated by a + symbol.

2. Select the **New** button to display the **Create a New Queue: Name and Type** (Figure 9–14) window. Every print queue has a unique name assigned to it. Multiple print queues can be assigned to the same service, but usually only one is assigned per type. The six print queue types are as follows:

- **Locally-connected**: This is a printer that is directly attached to the local computer.
- **Networked CUPS (IPP)**: This is a remote printer that will be accessed over a TCP/IP network using the Internet Printing Protocol. The remote computer has a printer attached using CUPS.
- **Networked UNIX (LPD)**: This is a printer attached to another Unix system over a TCP/IP network. The remote printer is configured to use LPD.
- **Networked Windows (SMB)**: This is a printer attached to a Windows computer over an SMB network.
- **Networked Novell (NCP)**: A printer attached to another printer using Novell NetWare.
- **Networked JetDirect**: A printer connected directly to the network instead of a remote computer.

3. Select the **Local Printer Device** and then select **Next** to display the **Setting up Local Printer Device** screen (Figure 9–15).

### FIGURE 9–15 Setting up local printer device.

![](img/37f079cee226b270f2e09b37a2e4a05d_255_0.png)

The **Setting Up Local Printer Device** screen shows the device to which the printer is connected. The default, /dev/lp0, is the local first parallel port. Selecting **Custom** will allow you to enter another device name.

To see a list of available devices, use the **lprinfo** command. The **-v** option shows available printer devices on the system.

```
# lprinfo -v
network socket
network http
network ipp
network lpd
direct parallel:/dev/lp0
direct scsi
serial serial://dev/ttyS0?baud=115200
serial serial:/dev/ttyS1?baud=115200
direct usb:/dev/usb/lp0
direct usb:/dev/usb/lp1
network smb
```

4. Select /dev/lp0 if your printer is connected to the parallel port. Click Next to display the Queue Driver (Figure 9–16) screen.

### FIGURE 9–16 Queue driver.

![](img/37f079cee226b270f2e09b37a2e4a05d_256_0.png)

5. Select the printer driver from the list. If your driver does not exist, you may need to find a driver from the manufacturer, or go to www.linuxprinting.org to check for a new driver. Click Next to display the Create New Queue: Name and Type (Figure 9–17) screen.

### FIGURE 9–17 Confirm create a new queue.

![](img/37f079cee226b270f2e09b37a2e4a05d_256_1.png)

6. Confirm your choices and then click Finish to complete the printer setup. You will return to the Red Hat Printer Config screen.

7. You may want to test the printer setup. Click the Test button on the Red Hat Printer Config screen to display the Test screen (Figure 9–18). A test page will be printed to the printer. If it does not print correctly, check your setup. If all is well, you may want to look for a different driver and try it.
