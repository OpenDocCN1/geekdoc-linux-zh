
## FIREWALLS

A firewall is a core component of network security. A firewall provides packet filtering, and can also provide a circuit-level gateway and an application-level gateway. Firewalls are typically located at the boundary of a network. All incoming and outgoing traffic should be routed through the firewall.

All traffic through a network is sent in the form of packets. Each packet contains a body and a header. The header has the source IP address, destination IP address, and other information. Packet filtering looks at the header, then decides if the packet is denied or allowed to pass through based on the IP address, port, or protocol.

A circuit-level gateway validates connections before allowing data to be exchanged. This determines if the connection is valid based on the destination, source, time of day, and other values. This enhances packet filtering.

An application-level gateway acts as a proxy for applications. All data exchange with the remote system is done by proxy, rendering the local computer invisible to the remote computer. The gateway performs detailed logging of traffic and monitoring of events on the host system. Application-level gateways are regarded as the most secure type of firewall.

All firewalls, regardless of type, provide inspection of incoming and outgoing data before it is sent on to the destination. Besides filtering content, firewalls can also provide Network Address Translation (NAT). NAT hides the internal IP addresses behind the firewall and provides IP addresses to the outside network.

Firewall technology is built into the Linux kernel. It is provided through netfilter (see www.netfilter.org) and iptables. The netfilter subsystem provides stateful or stateless packet filtering as well as NAT and IP masquerading services.

## IPTABLES

![](img/37f079cee226b270f2e09b37a2e4a05d_344_0.png)

The iptables tool inserts and deletes rules from the kernel’s packet filtering table. A computer with a single network connection can use iptables to configure packet filtering as a personal firewall. A computer with two connections, one connected to the outside (Internet) and one connected to the inside (intranet), can use iptables to configure a network firewall (Figure 12–16).

![](img/37f079cee226b270f2e09b37a2e4a05d_344_1.png)

iptables is initially configured with three lists of rules called chains. These are INPUT, OUTPUT, and FORWARD (Figure 12–17). A chain is a list of packet rules. If a packet matches a rule, the action indicated by the rule is performed. Packets that don’t match a rule are dropped.

![](img/37f079cee226b270f2e09b37a2e4a05d_345_0.png)

When a packet comes in, the kernel looks at the destination and determines the routing. If the routing is to localhost, the packet is sent to the INPUT chain. If the INPUT chain rules are met, the packet is passed to the internal processes.

If the routing is to another host, the packet is sent to the FORWARD chain. If the FORWARD chain rules are met, the packet is forwarded to the destination host.

A process running on the local host will send packets to the OUTPUT chain. If the OUTPUT chain rules are met, the packets are sent out.

To start the iptables service, use the `service iptables start` command.

Using ipchains is complicated and requires expertise and trial-and-error to get it right. For a complete list of ipchains options and actions, look at the man ipchains command. Some of the ipchains options are as follows:

- `-N` Create a new chain.
- `-X` Delete an empty chain.
- `-L` List the rules in a chain.
- `-F` Flush the rules out of a chain.
- `-Z` Reset the packet and byte counters on all rules in a chain.
- `-A` Append a new rule to a chain.
- `-D` Delete the first rule that matches in a chain or a chain rule number.
- `-j` Indicates the target. This can be another chain or one of the special values ACCEPT, DROP, QUEUE, or RETURN. ACCEPT lets the packet pass through to its destination. DROP terminates the packet, not allowing it to pass. QUEUE sends the packet to userspace. RETURN means to stop using this chain and to return the packet to the next rule in the previous chain.
- `-s` The source IP address or DNS name of the packet.
- `-p` The protocol to check against the packet. The specified protocol can be tcp, udp, icmp, all, or a numeric value representing a protocol.
- `-v` Verbose listing.

To add a rule to a chain, use the -A option. One way an unauthorized user gains access to a computer is by first determining that the computer is on the network. A computer can be found on the network by pinging its IP address. The following command pings the Linux server at address 192.168.0.21 from the local host IP address 192.168.0.3.

```
C:\>ping 192.168.0.21
Pinging 192.168.0.21 with 32 bytes of data:
Reply from 192.168.0.21: bytes=32 time=2ms TTL=64
Reply from 192.168.0.21: bytes=32 time=3ms TTL=64
Reply from 192.168.0.21: bytes=32 time=3ms TTL=64
Reply from 192.168.0.21: bytes=32 time=2ms TTL=64
```

Ping statistics for 192.168.0.21:

Packets: Sent=4, Received=4, Lost=0 (0% loss),

Approximate round trip times in milli-seconds:

Minimum=2ms, Maximum=3ms, Average=2ms

On the Linux server, append a rule to the INPUT chain to drop ICMP packets from 192.168.0.3. The following command will be applied:

`iptables -A INPUT -s 192.168.0.3 -p icmp -j DROP`

The `-A INPUT` designates that this rule will be appended to the INPUT chain. The `-s 192.168.0.3` is the source host the rule applies to. The `-p icmp` indicates that the icmp protocol is affected. The `-j DROP` says that if the rule is a match, drop the packet.

Try the ping after completing this rule. The following ping shows the result:

Pinging 192.168.0.21 with 32 bytes of data:

Request timed out.

Request timed out.

Request timed out.

Request timed out.

Ping statistics for 192.168.0.21:

Packets: Sent=4, Received=0, Lost=4 (100% loss),

To remove the rule we just added, use the following command:

`iptables -D INPUT -s 192.168.0.3 -p icmp -j DROP`

The `-D option uses the same rule as a match to remove the rule from the INPUT chain. To use this command, the rule must match the original exactly. You can also use the number of the rule in the list. To find which number position the rule is in, use the -L option to list the rules. The iptables command sequence lists all the chains:`

Chain INPUT (policy ACCEPT)

target prot opt source destination

RH-Lokkit-0-50-INPUT all -- anywhere anywhere

DROP icmp -- engle-ee102 anywhere

Notice that the destination is replaced with the name of the machine instead of the IP address. This is the name found in the `/etc/hosts` file. To show the counters as well, use the `-v option.`

iptables rules are applied in the order of appearance in the chain. If you want to give a host access to specific protocols but deny it access to all the rest, you should enter the ACCEPT rules first and then the DROP rule. If the DROP appears before the ACCEPT, no packets will get through.

## FILE SYSTEM SECURITY

File system security is not put in place just to deter the unauthorized user; you have files on your system that you do not want local users to view or execute as well. For example, if your system contains payroll information for a company, you do not want everyone to be able to view it. Your users will want to know that their files are safe from others viewing, executing, changing, or copying. The main tool to secure the file systems on a computer is file permissions, discussed in Chapter 4.

### File Permissions

Files in Linux have three types of access—read, write, and execute. These access permissions are applied to the owner of the file, the group the owner belongs to, and everyone else. The file permissions can be viewed by displaying a long list of a directory. The following is a directory listing of *jsmith.*

```
$ ls -l
 total 2652
 -rw-rw-r-- 1 jsmith jsmith 2693120 Oct 1 11:19 adom_11-01-2003.tar
 -rw-rw-r-- 1 jsmith jsmith 33 Nov 4 12:07 crontab.jsmith
 -rw------- 1 jsmith jsmith 1894 Nov 4 12:11 mbox
 -rw-rw-r-- 1 jsmith jsmith 30 Nov 4 11:59 mycrontab
 -rw-rw-r-- 1 jsmith jsmith 3 Nov 4 11:50 newfile
```

The access permissions are arranged in three groups of three permissions each. For example, the previous listing shows that the file newfile has permissions `-rw-rw-r--` indicating that the owner has read/write permissions, the group has read/write permissions, and others have read permissions. The script may have permissions of `-rwxr-xr-x`, indicating that the owner has read/write/execute permissions, and the group and others have read/execute permissions.

The three values, rwx, form an octal value for each permission group. A one in a permission position indicates that it is active and a zero indicates that it is not. For example, a file with read and write permissions would have the value `rw`. The values can be replaced with ones and zeroes as **110**. This forms an octal value of 6. Every combination of read/write/execute values can be replaced with an octal value (Figure 12–18).

![](img/37f079cee226b270f2e09b37a2e4a05d_347_0.png)

The permission value of a file is changed with the `chmod` command. To set permissions for the owner to read/write/execute, the group to read/execute, and others to read/execute use the value 755. The command to set newfile to 755 is `chmod 755 newfile`.

Listing the new file, as shown in the following, shows that the permissions have changed.

```
$ ls -l newfile
 -rwxr-xr-x 1 jsmith jsmith 30 Nov 16 15:00 newfile
 $
```

The default value of a file can be set with the `umask` command. The umask, or user mask, is an octal value that is used as a bit mask for values of 777 for directories and 666 for files. The value 777 gives the permission set of rwxrwxrwx for directories and rw-rw-rw for files. As a binary value, directories are 111-111-111 and files are 110-110-110. The umask value is used to replace any bit positions that have a value of one with a value of zero. The default umask is 002. Expressed as a binary value, this is 000-000-010.
