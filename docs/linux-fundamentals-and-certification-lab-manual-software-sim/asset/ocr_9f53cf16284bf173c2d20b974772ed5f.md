As you monitor system processes, you may find that some processes are taking too much CPU time. How much time is too much, you can learn only from experience on the particular machine the processes are running on. However, some problems with processes taking too much time are obvious. For example, if a process owned by jsmith takes 70% of CPU time consistently, you may have a problem with that process. The **renice** program can be used to change the priority of a process without disrupting its operation.

The **renice** command alters the priority of a running process. Priorities can be altered for a PID, process group (pgrp), or username. The syntax of renice is **renice priority [\[-p\] pid ...] [\[-g\] pgrp ...] [\[-u\] user ...]**, where pid is a list of process IDs, pgrp is a list of process group IDs, and user is a list of usernames. For example, to use renice to change the priority of the user jsmith to a lower value of 5, use the **renice +5 -u jsmith** command.

You can also change priority on more than one user or PID. For example, to change the priority of PID 14343 and the users jsmith and dangle to 10, use the **renice +10 14343 -u dangle jsmith** command. This command changes the priority of PID 14343 and all the processes owned by dangle and jsmith to 10.

# Killing, Suspending, and Restarting Processes

Processes don't always do what you expect. The reason may be a *bug* in the program or a hardware failure. For example, you may have written a script that performs a loop and contains a programming mistake causing the loop to never terminate. Examine the following script:

```
# cat forever_loop
#!/bin/bash
I=0
J=10
until [ $I -ge $J ]; do
	echo The value of I is $I
	sleep 1
done
#
```

![](bbox=[0.25, 0.62, 0.93, 0.72])

This bash script contains one until loop that just echoes the value of a variable, I. The loop checks that the value of I is greater than or equal to the value of J, and when the statement is true, it terminates. The problem with the script is that the value of I never changes; therefore, the condition will never be met, causing the script to run until terminated.

*The value of I is 0*
*The value of I is 0*
*The value of I is 0*
*The value of I is 0*
*The value of I is 0*
*The value of I is 0*
