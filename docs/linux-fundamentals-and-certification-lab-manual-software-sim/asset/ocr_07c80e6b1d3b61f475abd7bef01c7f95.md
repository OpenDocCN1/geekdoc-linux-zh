An unauthorized user may try to connect using brute force. This type of attack occurs when an unauthorized user has a program that has a list of user names with a corresponding list of possible passwords, which are used to continually attempt connection until a user name/password combination is found. This type of attack will show an unusually large number of **Failed password** entries.

The main program for the Linux logging system is the syslogd daemon. This daemon is run from a startup script when the system boots. Almost any program on the system can use the log file, including applications, drivers, and other daemons.

Log entries have a standard format. Programs can write entries in any format, but most follow the convention. The entries use the following format:

```
`date  time  system  facility  message`
```

+   • **date**  This is the date of the message.

+   • **time**  This is the time the message was written.

+   • **system**  This is the host name from which the message was generated. Systems on a network can share a log file on a central computer.

+   • **facility**  This is the process name and PID that generated the message.

+   • **message**  This is the text of the message.

# SUMMARY

Tasks can be executed automatically using cron. cron is a daemon that schedules tasks for the system or for individual users. System cron jobs are crons that perform systemwide periodic jobs. Individual users can create user cron jobs to accomplish tasks for themselves only.

System cron job schedules are defined with the /etc/crontab file. The file contains fields for minute, hour, day, month, and weekday, and what program to run at the selected time. The programs to be run are located in the /etc/cron.X directories. The X stands for daily, weekly, and so on.
