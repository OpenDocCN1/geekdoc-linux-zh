
The www.linux.org Web site is a good place to find lots of Linux information. Everything from distribution information to recommended books can be found there. Another site to find distribution download sites is www.linuxiso.org. This site provides links to all the most used Linux distribution sites and contains information on using ISO files (see note below). A Linux ISO is a file containing a CD-ROM disk image of a Linux distribution. When burned as a disk image, the ISO file is turned into a duplicate CD of the original CD. Depending on your Internet connection, a Linux distribution can take from an hour to several days to download. If you have a slow connection, it may not be possible to download a Linux distribution at all, so you will have to find other sources of the software.

> NOTE
>
> ISO is short for International Organization for Standardization, an international organization composed of national standards bodies from over 75 countries. ISO has developed a number of important computer standards. ISO is not an acronym; rather the name derives from the Greek word “iso,” which means equal. ISO files are the International Organization for Standardization’s standard for the volume and file structure of Compact Read-Only Optical Discs, also known as ISO 9660.

Linux distributions can be copied freely. If you know someone that already has a Linux distribution disk, you can legally copy the CDs. You will also find that many versions are available for retail sale at software houses, office supply stores, and discount stores. A recent search of these sites found Red Hat Linux version 9 for less than $40.

Linux, by current industry estimates, is the fastest growing server operating system. Sun Microsystems CEO, Scott McNealy, speaking to the Linux World Conference and Expo, has predicted that the number of Linux users will increase 30 percent a year for the next few years.

## LINUX APPLICATION COMPATIBILITY

![](img/37f079cee226b270f2e09b37a2e4a05d_20_0.png)

Linux has most, if not all, of the features found in any other operating system. For example, Linux includes sound utilities for playing CDs or for sound in video games, support for high-end video graphics, support for commercial database servers, and other features. Many of the software packages available are open source and allow the same functionality as commercially available packages for Windows or Mac OS.

To see a list of available applications, go to [http://www.linux.org/apps/index.html](http://www.linux.org/apps/index.html). The applications are organized by function, such as administration, multimedia, graphics, office, development, and others.

Many of the open-source programs offer compatibility to Microsoft and Mac OS applications. For example, OpenOffice.org, an office application suite with word processing, spreadsheet, and presentation tools, is similar and document-compatible with Microsoft’s Word, Excel, and PowerPoint applications.

Some commercial applications are available on multiple platforms. For example, the Oracle relational database management system is available on Windows, Sun SPARC, HP, AIX, and Linux. There are more and more commercial applications available daily.

## PACKAGES

Operating systems are defined by the files they install on the computer. Linux installs these files in directories such as `/bin`, `/sbin/`, `/usr/bin`, and others. When a program is updated, it is important to keep track of where the old program is installed and update all the necessary files. To keep track of installed programs with their documentation, called packages, several package maintenance utilities are available. Some of these package tools, such as RPM, Red Hat Package Manager, and DEB, Debian's package tool, are tightly integrated with the Linux distribution and provide a centralized mechanism for program updates.

Package management programs have several features that should be compared when deciding on a system to use. These have to do with security, usability by standard Linux tools, scalability, and metadata.

Security features include values that can be examined to ensure the package is valid and has not been modified. These include:

- **Signed packages** Support for PGP or GPG electronic signature to verify who created the package.
- **Checksums** A checksum ensures the package is complete and unmodified.

Standard Linux tools include tools that can be used to view packages without having a special tool for each package. Some package systems use tools that are included with every Linux distribution. These include:

- **Standard package tools** Can the package be manipulated by standard Linux tools, such as tar, gzip, bzip2, and others?
- **Package creation** Are standard Linux tools available to create the package?

Scalability features include how well the package format is able to grow to meet future needs. These include:

- **Version format** Can the version be determined by examining the package?
- **Hard programmed limits** Are limits designed into the package format?

Limits may prevent the package from expanding to meet future needs.

Metadata features include embedded information about a package. This information includes values such as package name, description, and other properties that may be changed within the package. Some of these properties are:

- **Name** The name of the package can be determined by data within the package.
- **Version** A version number within the package or the name of the package indicates the package version.
- **Dependencies** A dependency indicates what packages need to be installed before the package in question is installed.

Some comparisons are shown in Table 1-1. Many package management systems can be used on a single Linux distribution; however, it is strongly recommended that you use only one package management system. Dependencies usually cannot be determined between package management systems.

Table 1-1
Package comparisons.

| Feature | RPM | DEB | TGZ | PKG |
|---|---|---|---|---|
| Signed package | Yes | Yes | No | No |
| Checksums | Yes | Yes | No | Yes |
| Standard tools used to create | No | Yes | Yes | No |
| Name in metadata | Yes | Yes | No | Yes |
| Version | Yes | Yes | No | Yes |
| Dependencies | Yes | Yes | No | Yes |
| Hard limits | Yes | Yes | Yes | No |

## INTRODUCTION TO LINUX

Some of these package tools are described below. A more detailed description of package management is given in Chapter 5.

- **RPM (Red Hat Package Manager)** The RPM package manager is a command-line package management system capable of installing, uninstalling, verifying, querying, and updating computer software packages. RPM was designed by Red Hat and is used by Red Hat and other Linux distributions. Each software package consists of an archive and package information. An API (Application Program Interface) is also available, permitting advanced developers to manage installations within a native coding language. The current release of RPM is 4.2 and is shipped with Red Hat version 9.

RPM checks for package dependencies, and provides for signed packages and check-sums. RPM requires a proprietary tool (rpm) to manipulate or view the package.

- **DEB** Debian packages contain all the files necessary to implement a set of related commands or features. DEB is designed by Debian, and is used by Debian and other Linux distributions. Two types of Debian packages exist:
    - **Binary packages** Binary packages contain executables, configuration files, man pages, and other documentation. These are contained in a .deb file.
    - **Source packages** Source packages contain .dsc files describing the source package, a .orig.tar.gz file that contains the original unmodified source in gzip compressed tar format, and usually a .diff.gz file that contains the Debian-specific changes to the original source.

Debian packages provide for signed packages, checksums, and dependency checking. They are also viewable and can be manipulated by standard Linux tools.

- **TAR (Tape ARchive)** Tar packages, called tar balls, are the oldest of the package formats. Tar gets its name from its initial use by Unix as a tape archive tool (a program used to back up data to a tape storage device). It has been around longer than Linux and was available in the earliest releases of Unix. Tar packages are used by all Linux distributions. Tar files unpack everything in a single directory, leaving the user to sort items to appropriate directories on the system. Most packages are available in tar format. Tar is used by the Slackware Linux distribution, but is available for all Linux distributions. Tar packages do not check for program dependencies before installing a package. Tar files do not provide for signed packages, checksums, or dependencies. They do use standard tools for manipulation.

- **TGZ** TGZs are tar balls, compressed with the gzip compression program. TGZ files are designed by Slackware. Slackware has a utility, slapt-get, that is used to help manage package dependencies. TGZ files alone do not provide for signed packages, checksums, or dependencies. They do use standard Linux tools for viewing and manipulation.

- **SLP (Stampede Linux Package)** SLP format was made available through the Stampede Linux distribution. SLP uses tar and bzip2, a compression tool, as its foundation. It is coupled with a package management tool suite. SLP packages do not provide for signed packages or checksums, but they do provide dependency checking. SLP files can be extracted, but cannot be created or viewed with standard tools.

- **PKG** PKG is a package management system used by FreeBSD and many Unix operating systems. As with most package systems, the packaged software can be installed from the command line or by using a GUI tool. Solaris Unix uses the command-line commands pkgadd, pkginfo, and pkgr, and FreeBSD uses the corresponding pkg_add, pkg_info, and pkg_delete. Sun Solaris also uses a GUI tool, Sun Control Station (Figure 1–1), to help manage packages.
