
Linux has several different programs for backing up and restoring data. A backup program is needed to do the actual operation, but a backup policy is needed to document how, what, and when to back up.

## fsck Command

Disk drives will have errors. Most drives are rated to perform up to a specific number of hours, and thereafter failures can be expected. A hard disk is a delicate device, assembled in an industrial clean room under ideal conditions. If even one smoke particle gets into the drive, it can cause a head crash. A head crash occurs when the read/write head bumps into the metal platters of the disk, which are often spinning at over 7200 rpm. Catastrophic failures can be fixed only by replacing the hard drives and restoring the information from backup; however, often the errors are minor and may affect only a few files. Utilities can scan for damaged areas of the hard drive, the files can be moved to other areas, and the bad sectors can be marked. The fsck program is used to check and optionally repair one or more Linux file systems. The syntax for fsck is **fsck [ -options ] [ file system ]**. The file system to be checked should be unmounted first. If areas that require corrective action are found, you are prompted for a yes or no to correct the file system. The default answer is no. If you answer yes, the default for the next prompt will be yes. If you use the -y option, the default answer to all fsck questions is yes. An example listing follows:

```bash
# cat /etc/fstab
LABEL=/                     /                  ext3    defaults           1 1
LABEL=/boot                 /boot              ext3    defaults           1 2
none                        /dev/pts           devpts  gid=5,mode=620     0 0
/dev/hda3                   /newDrive          ext3    defaults,usrquota  1 2
none                        /proc              proc    defaults           0 0
none                        /dev/shm           tmpfs   defaults           0 0
/dev/hda5                   swap               swap    defaults           0 0
/dev/cdrom                  /mnt/cdrom         udf,iso9660 noauto,owner,kudzu,ro 0 0
/dev/fd0                    /mnt/floppy        auto  noauto,owner,kudzu   0 0
/dev/cdrom1                 /mnt/cdrom1        udf,iso9660 noauto,owner,kudzu,ro 0 0
# umount /newDrive
# fsck /newDrive
fsck 1.32 (09-Nov-2002)
e2fsck 1.32 (09-Nov-2002)
/dev/hda3: clean, 33/375360 files, 47132/750330 blocks
# mount -a
# cd /newDrive
# ls
dengle jsmith ksmith lost+found quota.user rbrown
# cd /
#
```

If the Linux operating system is suddenly powered off, file systems with open files have a high chance of being damaged. If that is the case, you will be prompted to run fsck during the next startup and a command prompt will be made available. Follow the onscreen instructions. When fsck repairs a file system, lost files may sometimes be found in the lost+found directory. One way to avoid a damaged file system is to use an uninterruptible power supply (UPS). A UPS is a battery that provides power to the computer system if main power is lost. Some UPSs have software that will communicate with the computer system to determine the battery status and shut down the system if necessary.

## Configuration File Problems

Many programs in the Linux operating system are controlled by configuration files. The configuration files are used for everything from user profile information to information on how to mount file systems. Most of these programs were discussed in Chapter 8.

### Boot Loader Configuration Problems

The first action your Linux system performs after computer startup is to load the boot loader. Problems with boot loader configuration files can prevent the system from starting. In the best-case scenario you copied the configuration files and can either copy the backup to replace the files or can retype in information needed to correct the problem. Most installations of the Linux operating system use either GRUB or LILO as a boot loader. Configuration files for these boot loaders were discussed in Chapter 6.

**/boot/grub/grub.conf** This is the configuration file for the GRUB boot loader. Problems with this file can prevent the system from starting. Figure 13-3 shows a sample grub.conf file with a menu of two startup options. The first loads the smp (symmetric multiprocessing) kernel as the default.

**/etc/lilo.conf** This is the LILO configuration file. This configuration file is not read at every startup. To solve boot loader problems you may want to use a boot disk. An emergency boot disk is just what the name implies, a boot disk to use in case of emergency. What constitutes an emergency? Usually, your system won't boot up. This problem can be caused by a number of things. The boot loader could have been damaged, the MBR could be damaged, or there could be other serious problems preventing the system from starting.

You may have created a boot disk during initial installation. One of the last options of the install is to create a boot disk. You probably did this the first time you installed, but if you have installed more than once, you probably skipped over this step because it takes too much time. It really doesn't take too much time, it just seems like it when you want to get the installation completed. You should create an emergency boot disk, otherwise you may not be able to boot your system.

If you did not create an emergency boot disk and find that you need one, you can still create it, even if your system won't start. The distribution CD has a boot disk image file that can be used to create a boot disk. You can also download the boot disk image from several Web sites, such as **http://ftp.redhat.com/pub/redhat/linux/9/en/os/i386/images/**. This boot disk image creates a boot disk using an image writing program, such as **rawrite**. rawrite is a DOS program that can be run from a Windows command prompt.

To create an emergency boot disk from the distribution CD (Figure 13-5), do the following:

- 1. From a DOS prompt, change to the CD drive by typing the drive letter of the CD, such as **E:**. The **E:\>** is displayed.
- 2. Change to the **dosutils** directory by typing **cd \dosutils** from the command prompt.
- 3. Run the **rawrite** utility program. The utility will ask where the image is located. The bootdisk.img file is located on the CD in the images directory.
- 4. When asked for the image source filename, enter **e:\images\bootdisk.img**.
- 5. When asked for a target diskette drive location, put a blank disk in drive **A:** and then enter **A:**. The diskette is created.

![](img/37f079cee226b270f2e09b37a2e4a05d_365_0.png)

An emergency boot disk needs to have a few more tools to be really useful. For example, if your system uses a non-standard hard drive, you may need drivers to access the drive in an emergency. Consider including the following programs on a floppy disk:

- **vi** Having access to a text editor will prove invaluable if you need to change a configuration file. vi takes a lot of space on a floppy, but it may be worth it.
- **fdisk, mkfs, fsck** Disk utilities may be needed if a file system needs to be restored or replaced.
- **tar** The tar program may be needed to restore data from tape or other storage media.

To use the emergency boot disk, put the disk in the floppy disk drive and restart the system. (Be sure to remove the CD if it is in the CD drive.)

**/etc/inittab Configuration File** This file controls the initial startup of the Linux operating system. It is read by the init process during startup. A typical problem this file can be used to correct is inability to start the X windowing system. On most installations the default startup is X. If something goes wrong with the X setup, such as the video card configuration or the rare unsupported video display, the default runlevel can be changed to start the CLI. To change the runlevel, locate the line id:X:inittab:default: (Figure 13–6), where X is the runlevel (the value for X is 5). Change the value of X to a CLI runlevel, usually 3. Upon rebooting the system, the default login will be the CLI.

![](img/37f079cee226b270f2e09b37a2e4a05d_366_0.png)

After login through the CLI, if you want to start X, use the startx program. The startx script is a front end to xinit, which allows running a single session of the X windowing system. startx uses the XF86Config configuration file (Figure 13–7) to supply the video driver, screen resolution, mouse type, and other X environment values.

![](img/37f079cee226b270f2e09b37a2e4a05d_366_1.png)

**Other Configuration File Problems** After Linux starts up, several configuration files can cause problems. Some of the problems that can arise include:

- **Modem or other devices won't work.** The /etc/modules.conf file may be damaged or misconfigured. As you know from Chapter 8, the /etc/modules.conf file contains information about automatically loaded kernel modules. These modules are loaded as needed by the system. If there is a problem with a device, this file can be edited to correct it.
