**Mounting a Partition**

A partition can be mounted with the mount command or within the /etc/fstab file. Mounting a partition with the mount command is useful if you only want to use it for the current session; however, if you want to have the mounted partition available every session automatically, use the /etc/fstab file. Add the following entry to the /etc/fstab file.

```
/dev/hda3  /newDrive  ext3  defaults  1  2
```

After the /etc/fstab file is changed, use the mount -a command. The -a option causes all file systems listed in the /etc/fstab file to be mounted.

```
# mount -a
# df
Filesystem      1K-blocks      Used Available Use% Mounted on
/dev/hda2        6049772   2533136   3209324  45% /
/dev/hda1         102454      9324      87840  10% /boot
none              159980         0     159980   0% /dev/shm
/dev/hda3         2954168    32828   2771276   2% /newDrive
```

This file system could also be mounted with the command mount /newDrive, which would only mount the /newDrive partition. This may be preferable when it isn’t desirable to mount all partitions. For example, on a busy system another administrator may have unmounted a partition for maintenance and using the mount -a command would remount it before the maintenance was complete.

# Swap Space

Some of the applications you install may be contained on several CDs. Each CD can contain about 700 MB of information. How does the Linux operating system run a program that takes up this much space? The answer is swap space.

Several terms are used to refer to swap space. Most operating system vendors refer to it as virtual memory. Regardless of how you refer to it, does the same function. The term swap space comes from the way the operating system swaps pages of an application between RAM and hard disk space. If a portion of a program is needed, it is paged from disk storage into RAM. The program works through the section needed and then writes the page of information back to the hard disk space. This process can continue until the program completes its given task.

If a program is too large to be run in computer memory, parts of the program can be stored on disk space and executed as needed. Of course, running a program from RAM is much faster, but not always feasible. The cost of RAM is much greater than that of hard disk space. You can check the amount of swap space by typing cat /proc/meminfo. The Linux command free will also display swap and memory usage and availability.

The use of swap space will cause a program to run extremely slow at times; however, most applications need only a small part of RAM at any given time, and storing portions of a program on a disk drive therefore has little effect on performance. The best solution for a performance problem is to add more RAM. If that is not a possibility, increasing swap space is a good second choice.

# **Increasing Swap Space**

How much swap space do you need? From Chapter 3, the recommendation for initial swap partition size was to use twice the amount of RAM. How much space you really need is determined by the actual processes running on the Linux operating system. For example, if you are supporting a database with lots of users, you may need more swap space than the recommended 2x. The system must be monitored and then the correct amount of swap space should be used. Every system is different.

When determining how much swap space you need, you also should consider where the swap space will be located. Consider, if swap space is being heavily used on the same physical disk as a database, performance will suffer. However, if you put the database on its own physical drive, separate from the swap partition, overall performance will improve. You will have two read/write heads moving to access data on the disk drives instead of only one.
