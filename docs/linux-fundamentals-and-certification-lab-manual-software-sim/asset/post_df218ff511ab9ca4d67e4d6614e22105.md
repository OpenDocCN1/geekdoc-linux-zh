MBR is the recommended install location for the boot loader. The MBR is a special area on your hard disk that is automatically loaded by your computer's BIOS.

The first sector of your boot partition is recommended if you already have another boot loader on your system. In that case, the other boot loader will take control first. You can configure that boot loader to start GRUB or LILO, which will then boot Linux.

Alternative boot loaders are available. You can use a boot diskette, LOADLIN, SYSLINUX, or a commercial boot loader. You will be prompted to create a boot diskette at the end of the installation program. LOADLIN is a simple DOS-based utility that loads the Linux kernel into memory from DOS. SYSLINUX is a boot loader that runs under DOS. A SYSLINUX floppy disk can be manipulated using standard DOS tools. Commercial programs include System Commander and Partition Magic. These are able to boot Linux, but still require that GRUB or LILO be installed in your Linux partition.

## Basic Networking

If you have a network device installed on your system, you will see the Network Configuration screen. Networking must be configured to access network resources.

By far the most common network interface card (NIC) you will encounter is the Ethernet card. Today's Ethernet devices provide access speeds of 10, 100, or 1000 Mbps (megabits per second).

To use a NIC, the operating system must have a protocol that allows other network devices to converse with it. The most common network protocol is Transmission Control Protocol/Internet Protocol (TCP/IP). TCP/IP is a suite of protocols used to do a variety of jobs. It includes protocols such as Domain Name Service (DNS), File Transmission Protocol (FTP), Telnet, and others.

Objective 1.10

Every network device that uses TCP/IP has a unique network address called an IP address. IP addresses are 32-bit values identified in four 8-bit values called octets. The values are written in decimal notation for easy use. For example, 10001011.10000000.00000000.00000000 translates to 139.128.0.0, a class B IP address.

There are three classes of IP addresses, class A, B, and C. Each class of IP addresses is made up of a network portion and a host portion. Class A addresses are divided at the first octet, class B at the second, and class C at the third. The host portion can be subdivided to provide subnets by using a subnet mask. A subnet mask is similar to an IP address in that it is 32 bits and divided into four octets. The default subnet mask for a class A network is 255.0.0.0, for a class B network is 255.255.0.0, and for a class C network is 255.255.255.0. Each octet can provide 256 values.

Subnets allow you to divide your network into segments with fewer computers, which are more manageable than large numbers of computers on very large segments. Computers on the same network segment can talk to each other, but must have a device, called a router, that will pass the information to another segment in order to communicate across large networks. The Internet, for example, has millions of computers communicating across vast distances continually. If every computer were on the same network segment, communication would not be possible.

For a computer to communicate across the Internet, it must have an IP address, a subnet mask, an address of the router that it will pass through, and an IP address of a domain name server (DNS). A DNS server looks up a named address, such as www.yahoo.com, that is easy to remember and converts it to an IP address.

The values required for a computer to communicate can be provided statically or dynamically. A static configuration requires an administrator to explicitly enter the IP address, subnet mask, and other values. Dynamic values can be entered through a service called DHCP (Dynamic Host Configuration Protocol) or BOOTP. A DHCP server is configured with a range of values that it will assign to network devices when queried. BOOTP is an older version of the DHCP service.

The network can be configured during install time by entering the static values or indicating that Linux should use DHCP. A system can have more than one NIC. Each NIC must be configured. The Network Configuration screen, shown in Figure 3–17, allows you to select which option you will use to configure your NIC.

## Objective 2.7

### Basic Security

Security on Linux is implemented through the use of passwords, permissions, and a firewall. This chapter discusses the use of a firewall during the installation process. Administration of passwords and permissions is discussed in Chapter 12.

A firewall is designed to prevent unauthorized access to or from a private network. Firewalls can be implemented in hardware and software. Firewalls are frequently used to prevent unauthorized Internet users from accessing private networks that are connected to the Internet. All messages entering or leaving the local network pass through the firewall, which examines all messages and blocks those that do not meet the security criteria.

Linux offers firewall protection. This firewall is software between the network and your other computer resources. It determines which resources on your computer remote users on the network can access. Red Hat has three predefined levels of security protection, as seen in Figure 3–18—High, Medium, and No Firewall.

![](img/37f079cee226b270f2e09b37a2e4a05d_74_0.png)

FIGURE 3–18
Red Hat firewall level configuration.

The **High** setting will not accept connections that are not explicitly defined by you. By default, only the following connections are allowed:

- DNS replies
- DHCP so any network interfaces that use DHCP can be properly configured

High security will not allow active-mode FTP, IRC DCC file transfers, RealAudio, and Remote X Window System access. If you are connecting to the Internet, but do not plan to run any server software, this is the safest choice.

The **Medium** setting will not allow remote machines to have access to certain resources on your system. By default, access to the following resources is not allowed.

- Ports lower than 1023. Ports with numbers below 255 are for public applications, such as 23 for Telnet, 21 for FTP, and 53 for DNS. Ports between 255 and 1024 are assigned to companies for marketable applications such as 389 for LDAP.
- The NFS server port 2049. NFS is disabled for both remote servers and local clients.
