or priorities. Separating a list of selector values with semicolons indicates that all values apply. For example, **info** means all messages with info severity will be sent, **\*.info;mail.none** means that all messages with info severity will be sent except for mail messages. Any message of the priority indicated or higher is recorded to the action location.

The action field of a rule specifies the location where the message will be sent. The action field can be a real file, a named pipe, a terminal or console, a remote machine, a list of users, or all users. Sending messages to a remote user or machine will ensure that messages survive if there is a severe hardware failure.

## messages Log File Messages from the /var/log/messages file contain most information about the Linux operating system. Information gathered from this file can be used to monitor system loads, to check that the system services are running properly, and to record any errors that occur.

System load is the normal level of processes, logins, file transfers, and other values that the Linux operating system provides on average each time period. Peak values should be expected and accounted for. If the system is reaching the maximum load more and more often, this may indicate that the system resources need to be increased. The first symptom of a system load increase is usually a decrease in performance, meaning that the system runs slower.

Error messages are one of the most direct indicators of a problem. An error message will point out a problem, but not always the problem’s source. For example, an error message that the sendmail process has stopped may indicate a sendmail problem, or it may indicate a system resource failure. Other messages will usually clarify the source of the error.

Intrusion detection can often be detected by the contents of the log files. A cracker may gain access to your system and change configuration files and logging levels, or even delete entries in the log files.

## secure Log File Messages from the secure log file are often used to detect unauthorized access attempts. A large list of rejected login attempts means that someone is trying to mount a brute force attack on your system. Login attempts to several services may indicate an attack as well. For example, if the same user attempts to gain access through sshd, telnet, ftp, and other services within seconds of each other, this may indicate an unauthorized user trying to gain access.

As with any log file, a cracker may try to cover up unauthorized access by deleting the file or removing entries from the file. Unless you check the logs often, these alterations will probably go undetected.

# ## System Status Tools

Several utilities can help in troubleshooting problems. Status tools will indicate the current status of a system, but not whether there is a problem. However, the information they provide can be used to compare to past data to determine if there is a problem.

+   • **ifconfig** ifconfig is used to configure or display network interfaces. Using ifconfig with no parameters or options will display information about all active network interfaces. This information includes the IP address, subnet mask, packets sent and received, MAC address, and other information. An invalid IP address could keep network connections from working properly. Packets that have been transmitted but have not returned indicate a network error.
