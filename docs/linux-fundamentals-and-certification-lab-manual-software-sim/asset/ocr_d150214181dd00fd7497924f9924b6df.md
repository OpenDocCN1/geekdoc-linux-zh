The `/etc/shadow` file is used when shadow passwords are enabled. This file is read-only by the root user, so other users cannot get to the `/etc/shadow` password file even if they are logged on the system.

If the password file cannot be copied and cracked on a remote computer, the only way an unauthorized user can break into the system is by using SSH or Telnet and trying passwords. This process is much slower and easily tracked using system logs. However, if the Linux users are using weak passwords, an unauthorized user may break into the system quickly; and even if the breach is detected, it is likely to be after the fact.

# **Strong Passwords**

It’s amazing how many users have passwords such as god, 1234, a birthday (such as 061064), jsmith, the name of their dog, and other easily guessed values—even the word “password.” These kinds of passwords can be figured out in a few minutes, especially if you know the user. Even without knowledge about the user, cracking software can figure the passwords out in very little time. Some password cracking programs use a dictionary as a database of possible passwords and, in some cases, can send passwords to the host computer until one works.

The best defense against this kind of attack is to use *strong passwords*. A strong password contains letters (uppercase and lowercase), numbers, special characters (!, $, #, etc.), and a minimum length of eight characters. Strong passwords can completely deter unauthorized users.

Passwords should be as long as possible; but as with any good security measure, they have drawbacks. Requiring users to type ten or more characters to log on may cause more confusion than it’s worth. You will find that users forget their passwords; or worse yet, they will write them down and tape them to a drawer, monitor, or keyboard. For that reason, eight characters tends to be enough to deter the occasional unauthorized user while still making it somewhat easier for a user to remember.

The Linux operating system is case sensitive, so mix uppercase and lowercase letters within the password. Using uppercase and lowercase letters increases the number of possible passwords exponentially. Add special characters such as !, $, or # and numbers, and the possibilities increase even more.

Using strong passwords is important to deny access to unauthorized users; but strong passwords will not be used if they are too hard to remember. Some tips for designing passwords as well as remembering them follow.

Start with a mnemonic that you will remember; for example, a song lyric such as “Are you lonesome tonight, do you miss me tonight.” Write down the first letter of each word as a beginning password. Preserve the case of the letters and keep any punctuation within the song lyric:

*Aylt,dy mmt*

Replace certain letters with numbers. For example, replace any letter o with a zero (0), or any letter d with a number six (6), so the password now reads:

*Aylt,6ymmt*

Replace certain letters or numbers with special characters. For example, replace a small letter a with the “at” sign (@), a letter i with an exclamation point, and so on. Now our password looks like:

*Ay!t,6ymmt*

You have the idea. Be consistent with your replacements and you will always remember your password and have a very strong password.

Change passwords often. Even though you use strong passwords, that doesn’t mean they will never be cracked. Recently, a user received an e-mail supposedly from the LAN administrator requesting the user’s password to fix a problem that had been discovered. Of course, the user sent the password. You never know where a compromised password will come from. The maximum amount of time a user should keep a password is 90 days.
