### Using TCP Wrappers
TCP wrappers are installed by default with a server type installation. Most services, such as SSH, Telnet, and FTP, make use of TCP wrappers.

TCP wrappers do not provide full security against unauthorized users. But TCP wrappers do provide basic access control. When a request for services, such as SSH or Telnet, comes in to the Linux operating system the TCP wrappers program provides an authentication request, banners, and other services before allowing the connection. For example, if a request for FTP comes to the system, the TCP wrappers program performs several actions:

- It will log access attempts, successful or not.
- It will look at the `/etc/hosts.allow` and `/etc/hosts.deny` files to determine if the source IP address is allowed or denied. Denied hosts are not given a login prompt.
- If the service is allowed, the username is requested; then TCP wrappers checks the username and displays a banner, if configured.
- If the user is valid, a password prompt is presented.

### Create a Banner
A login banner does nothing to prevent unauthorized access except to warn the user attempting access that there could be consequences to their actions. Often, a warning is all it takes to deter unauthorized access. A banner may be a supporting document in a court case if you catch an unauthorized user accessing the resource and decide to prosecute them.

Banners are relatively easy to configure. As an example, configure a banner for all SSH connections. The same procedure can be done for most connection services.

Create the banner text location. You can create a directory anywhere. For example, create a directory called `banner` in the `/etc` directory:

```bash
mkdir /etc/banner
```

Create the banner text file. Your banner can say whatever you want. If you are within a large organization there may be policies and standards that must be followed when displaying a login banner. Because this banner is for the service `sshd`, create a file called `/etc/banner/sshd`.

```bash
vi /etc/banner/sshd
```

Type your banner message, such as the one shown in Figure 12–13. This message should not indicate where the system is connecting. It should indicate that not all are welcome. Basically you should create a sign that says “No trespassing. Violators will be prosecuted.”

## Verifying Listening Ports
As an administrator, one of the tasks you must do regularly is check what ports on your system are listening for connections. When an unauthorized user cracks into a system, they often open a port for their access. So any open ports can indicate an intrusion into the system.

### NOTE
> A common term for an unauthorized user that cracks a system is *cracker*.

The best way to check for open ports is with a port scanner. Crackers use port scanners to find open ports that they can exploit. You can use the same tool to determine which ports are vulnerable to attacks. The `nmap` program is included with most Linux distributions; however, if you don't have it you can download the latest version from [http://www.insecure.org/nmap/map_download.html](http://www.insecure.org/nmap/map_download.html).

`nmap` determines what hosts are available on the network, what services (application name and version) they are offering, what operating system (and OS version) they are running, what type of packet filters/firewalls are in use, and dozens of other characteristics. `nmap` runs on most types of computers, and both console and graphical versions are available. `nmap` is free software, available with full source code under the terms of the GNU GPL.

To determine what ports are listening for TCP connections use the `nmap -sT -O localhost` command. The output is displayed in Figure 12-15.

The `nmap` command has several options, such as the following.

- `--sS` SYN scan. A TCP network connection is established by sending a SYN (synchronize) bit to the remote system and then waiting for an ACK (acknowledgment). `nmap` sends a SYN packet and waits for the ACK. If the SYN/ACK is received, the port is open. Very few sites will log this port scan type. This option requires root privileges.
- `--sT` TCP connect() scan. The connect() system call is used to open a connection to every interesting port on the machine. If the port is listening, the connection will succeed. This type of port scan is logged and easily detected by the system administrator. This option is available for all users.
- `-O` This activates remote host identification. It will return information about the remote operating system.
- `-v` Verbose. This will give more information about the scan. Use it twice for even more information.

Another method of viewing port status is with the **netstat** and **lsof** commands. These commands do not connect through the network port, but rather check on the local machine to see what is running.

The `netstat` command is used to print network connections, routing tables, interface statistics, and other values. To use `netstat` to view open ports, type the `netstat -an | more` command.

### NOTE
The system administrator should certainly be aware of any port that is open on a server he is responsible for. The administrator should also be aware of which program is holding the port open.

The `netstat` command with the `-p` switch can provide this information. If `nmap` reveals that port 873 is open the command `netstat -ap | grep 873` should provide a line of output containing the PID of the process holding the port open. Then `ps -fp <pid>` will provide more information about the program. Additional information can be obtained about the process by using `lsof` to see which files the process has open, and `strace` can show all system calls made by the process.

The **lsof** command returns a list of open files. Use this command with the `-i` option to list Internet files. To use `lsof` to view open ports, type the `lsof -i | more` command.

## VIRTUAL PRIVATE NETWORK
How do you allow remote users to access your local network? Traditionally, a remote office would pay for a leased line or Frame Relay connection. Dedicated connections are very expensive, but offered a level of security unattainable by any other means, until the *Virtual Private Network* (VPN) was introduced.

A VPN provides the same network connectivity for remote users over a public connection as over a private connection. A VPN provides an extension to a Wide Area Network (WAN) without the expense. With a VPN, you can send data over a public network in a manner that emulates a point-to-point private connection. A VPN creates a secure tunnel between two networks and routes IP packets through it.

A secure tunnel is obtained using protocols developed by the Internet Engineering Task Force (IETF). Internet Protocol Security (IPSec) uses strong cryptography to provide both authentication and encryption services. Authentication ensures that packets are sent by whom they say they are from. Encryption prevents unauthorized users from reading packets in transit.

Most Linux distributions include the Crypto IP Encapsulation (CIPE) package to implement a VPN. CIPE is developed for Linux and uses encrypted IP packets that are encapsulated in User Datagram Protocol (UDP), encrypted, and sent over IP to a remote network host.

Another VPN solution is FreeS/WAN (www.freeswan.org), a free software implementation of VPN. It is a Linux implementation of the IPSec protocols. FreeS/WAN supports site-to-site VPN, remote users (Road Warriors), RSA keys for authentication, and Layer 2 Tunneling Protocol (L2TP) for VPNs. It is released under the GNU Public License.

In addition to software implementations of VPN hardware versions are also available. For example, Cisco provides VPN routers that provide managed IP VPN, among other services. A hardware VPN takes the workload of the VPN software off a server and puts it on a dedicated device designed to take large loads. Hardware devices are a good choice for enterprise-wide deployments.
