**User Feedback** If you're not paying attention to your users, you aren't doing your job as a Linux administrator. In many cases the sole purpose of the Linux operating system is to support users by providing network services, database services, disk space, and other services. Users can provide invaluable feedback for troubleshooting your system.

As an administrator, you don't have the time to run and evaluate every program that a Linux system can provide; however, Linux users do use the services of the Linux system and can provide feedback about problems and performance issues.

Some user problems are solved through user education. If users are new to Linux they should be educated to differences from other operating systems. For example, unlike many other operating systems, commands in the Linux operating system can be case sensitive.

There is one sure thing when it comes to users and your operating system: If things are not running well, you can depend on users to let you know about it. A user expects to have a responsive operating system and will let you know when it is sluggish. After a slow system is identified, the user should be queried about how they were using the system. If they typically run a CPU- or memory-intensive job, consider upgrading the computer. If the user experiences delays with a disk-intensive program, the file system needs to be evaluated. Network delays can cause a user to perceive the Linux system as slow. Many different things can cause a slow system. User feedback can guide you to the right resource to check.

**Information from Configuration Files** Most services on a Linux operating system use configuration files to provide startup information. Configuration files are changed occasionally after initial setup, but usually these files are static. Part of your documentation should be listings of configuration files. A copy of a configuration file can be invaluable to set services back to their original condition if a system has to be reinstalled or if an intrusion has been detected or is suspected.

Configuration files can be compared to earlier versions to help track down problems with the affected systems. For example, if a user complains that their login looks different, a copy of their _.bash_profile_ file can be used to restore settings.

**Information about Processes** What processes should be running on your computer? So many processes run on systems that it is very difficult to answer that question. The *ps* and *top* programs can provide valuable information about running processes.

A copy of the *ps* command result should be saved as part of system documentation. If there are complaints about system performance, this listing can help evaluate if processes are running that should not be. A list of commonly running processes will help track down programs that were executed by system intruders as well.

The results of the *top* command at various loads and times can provide valuable information about poorly running systems. A listing comparison to current values will help determine where the problems exist.

# SOFTWARE ERRORS

Software errors are the most difficult errors to troubleshoot. A software error can appear to be a hardware error, can hang up a system, or can do really odd things that make diagnosis very difficult. Software errors can be caused by file system problems, configuration problems, or development problems.

On some operating systems other than Linux, the solution to software problems is to restart the computer system. Sometimes you have to restart a Linux operating system as well, but usually any software issues can be solved by stopping and restarting the affected process.
