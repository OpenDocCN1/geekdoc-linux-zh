## Monitoring Storage Space

As any administrator will tell you, there is never enough disk space. The space used by applications, users, and data grows over time. Applications are revised to incorporate the latest GUI features, or patches are applied to fix problems, adding to required disk space. Users, as they become accustomed to available network storage, will store more and more information. The reasons are many, but two major ones are:

- Network storage is available. Users will find that they can keep a lot more information if they have a lot more storage space.
- Network storage is easily backed up and protected. If the Linux administrator manages the remote storage properly, part of the management policy will include backup of data. If users know that the backup of their important, or not-so-important, data will be done automatically, more storage will be used.

Disk space can be monitored manually or automatically. Most administrators use the `df` program to monitor disk space manually.

**Manual Monitoring of Storage Space**

`df` displays the amount of disk space available on the file systems. It can display information about a specific file system or all the file systems. To run `df` to see all the file systems, type `df`:

```bash
# df
Filesystem     1K-blocks      Used Available Use% Mounted on
/dev/hda2        6049772    2469896   3272564  44% /
/dev/hda1         102454       9324     87840  10% /boot
/dev/hda3        2954168      32828   2771276   2% /dosfiles
none             159980          0    159980   0% /dev/shm
#
```

Information about every file system is displayed, including the file system name, the amount of available 1K blocks, how much space is used, how much space is available, and the directory the file system is mounted to. To display only one file system, such as the root (/) directory, use the following command:

```bash
# df /
Filesystem     1K-blocks      Used Available Use% Mounted on
/dev/hda2        6049772    2469900   3272560  44% /
#
```

`df` is easy to use, but also easy to forget. Monitoring disk space must be done on a schedule. If an administrator fails to monitor disk space, the system may suddenly hang or fail to write information when data needs to be written.

**Automatically Monitoring Storage Space**

An administrator may find that it is easier to monitor disk space automatically. Many administrators write their own scripts or purchase a commercial product to manage and monitor file systems.

Chapter 11 discusses the `cron` command, a useful tool for scheduling tasks. Commercial tools are available; for example, **Heroix eQ** offers monitoring and management options for file systems and many more Linux properties. The **Webmin** program can monitor many system properties and, with third-party modules, can monitor disk space as well.

**NOTE**

You can find more information on Heroix eQ at www.heroix.com/products/detail_eq.htm. Check out www.webmin.com to get more information about Webmin.

The Red Hat Linux operating system offers the program **diskcheck** as a monitoring tool. `diskcheck` runs once an hour and sends an e-mail report of problem file systems. The program can be configured with the `/etc/diskcheck.conf` file.

## Adding Storage

Several tasks need to be performed to add storage. The same tasks that occurred during installation must be accomplished manually when adding storage.

- **Physically add the hard drive.** This was discussed in general terms in Chapter 3. For this discussion, it is assumed that the hard drive is already in the Linux system.
- **Partition the hard drive.** In most cases, this was done automatically using *Disk Druid* during installation. To accomplish the task manually, you will use the `fdisk` program.
- **Format the partitions created.** After the partitions are created, they must be formatted with parameters that Linux understands.
- **Update the /etc/fstab configuration file.** This was done automatically during installation. The `mount` command and the `/etc/fstab` configuration file were discussed in Chapters 7 and 8.

**Partitioning with fdisk**

After a hard disk is installed, it must be partitioned before Linux will be able to use it. Partitions were discussed in Chapters 2 and 3. To partition a hard drive manually, use the `fdisk` program.

If you aren't sure what the new drive is called, you may want to review Chapters 2 and 3. You can also run the `dmesg` command. The `dmesg` command displays boot messages, which will display all disk drives on the system. Either filter `dmesg` through `more`, or pipe the results to a file and edit it. To filter through `more`, use the `dmesg | more` command.

`fdisk` is a tool that allows an administrator to change or create partitions on a disk drive. The command to start `fdisk` is `fdisk <device>`, where *device* is the name of the new hard drive you have installed. To partition a new drive `/dev/hdb`, use the `fdisk /dev/hdb` command.

The `fdisk` program displays a command line. A menu can be displayed by pressing `m`. The partition is not changed until the `w` command (write table to disk and exit) is used.

```text
Command (m for help): m
Command action
a toggle a bootable flag
b edit bsd disklabel
c toggle the dos compatibility flag
d delete a partition
l list known partition types
m print this menu
n add a new partition
o create a new empty DOS partition table
p print the partition table
q quit without saving changes
s create a new empty Sun disklabel
t change a partition's system id
u change display/entry units
v verify the partition table
w write table to disk and exit
x extra functionality (experts only)
```

To create a new partition:

1. Define the type of partition, either extended logical (`l`) or primary (`p`). For this example, the `p` for a primary partition is used.
2. After you select the partition type, you are asked for beginning and ending cylinders. In this case, the first cylinder is 828 (the next cylinder after the previous partition) and the last cylinder is 1224.

```text
Command (m for help): n
Command action
l logical (5 or over)
p primary partition (1-4)
```
