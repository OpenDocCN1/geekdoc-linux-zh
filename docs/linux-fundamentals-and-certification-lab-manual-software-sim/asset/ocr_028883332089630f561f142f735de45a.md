POP3 provides client access to retrieve queued e-mail from the messaging server. Normally e-mail is downloaded and then deleted from the message store. Information about POP3 can be found in RFC 1939.

IMAP4 is a protocol that enables a client to connect with a messaging server and download queued e-mail to the local workstation. IMAP4 is much more robust than POP3 and provides the ability to manage folders and mailboxes on the server. IMAP4 gives you the flexibility to store messages locally or on the server, or both. Information about IMAP4 can be found in RFC 2060.

HTTP is used by messaging servers to provide access to e-mail via any standard Web browser. In most cases, WebMail, using HTML and java script, provides an interface to a messaging backend. Message data is translated into HTML pages for viewing through a browser. HTML forms are used to create messages, which are then sent using SMTP. Messaging servers provide a message store to hold e-mail until it is retrieved by the client. With POP3 the client retrieves e-mail and then the e-mail is deleted from the store. With IMAP4 the client retrieves e-mail and then has the option to leave it on the server or delete the message from the store.

A messaging server, sendmail, is included with Linux. Many e-mail servers are available, both open source and commercial. A quick search of the Internet will show several dozen open-source e-mail servers and clients, including SquirrelMail and Open WebMail. Commercial servers include Sun/One’s Application Server 7 and Zeus Web Server.

As with other servers, the size of the server depends on its usage. If you are managing a personal mail server you can use a personal desktop machine. But if you are providing a messaging solution for a business you will need a dedicated server to manage the system and sufficient disk space to contain the e-mail.

In a corporate environment, one or more mail servers would be positioned outside a firewall and at least two mail servers would be within the firewall. The systems outside the firewall serve to restrict access to the intranet. The inside systems are typically for performance issues. Depending on the number of users accessing e-mail, one group of intranet mail servers will provide message storage for users to read mail from, and another group for outgoing e-mail, providing enhanced performance for overall messaging.

**Enterprise Server** An enterprise server provides server services while maintaining high availability. Enterprise servers are usually high-end machines with redundant components that are hot-swappable (replaceable while powered). Typically, an enterprise server is a group of servers that are operated in a cluster. A cluster provides:

+   * Shared storage All cluster members have access to the same storage.
* Service failover Services provided by the enterprise server are always available. The cluster detects failures and recovers from them automatically.
* IP load balancing Provides the capability to load-balance incoming IP network requests across a farm of servers. An IP load balancing cluster appears as one server.

An enterprise server is usually a group of high-end machines attached to a common RAID. The Linux distribution that provides this type of service is not usually available for free download.
