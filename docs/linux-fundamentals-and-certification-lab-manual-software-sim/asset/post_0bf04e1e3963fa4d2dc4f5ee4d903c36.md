
## Objective 4.1 & 4.6: Suid Programs

Two methods are used to provide users root access to programs—su and sudo. Both commands allow a user access to limited or all root programs.

### Using su

The `su` command allows a user to log in as another user. By default, `su` will log in as root. The `su` command sets environment variables HOME and SHELL from the passwd entry for USER. If the dash (`-`) option is used, a login shell is presented. To log in as root, use the `su -` command (you will be asked for the root password).

Figure 12–3 shows a normal login session. jsmith logs in as a normal user. He wants to create a directory off the root directory, but receives a message that he does not have permission to create it. jsmith then logs in as root with the `su -` command and retries the command. jsmith is effectively the root user once the login is complete. To exit the root user, just type `exit` and press Enter.

![](img/37f079cee226b270f2e09b37a2e4a05d_335_0.png)

```text
jSmith@Typic:
Login as: jsmith
Sent username 'jSmith'
jSmith@192.168.0.21's password:
$ mkdir /jSmith
mkdir: cannot create directory '/jSmith': Permission denied
$ su -
Password:
# mkdir /jSmith
```

### Using sudo

If allowing a user full access to a machine makes you squeamish, you may want to use the `sudo` command instead. Each user that is to be given access to a restricted program must be configured to do so.

To configure a user for access to restricted resources, the `/etc/sudoers` file (Figure 12–4) must be updated. User entries in the `/etc/sudoers` file allow users to use the `sudo` command to execute restricted programs using their own passwords. `sudo` doesn't log in as root, but rather allows a user to run a program with root privileges from the user account. To add jsmith as a user with root administrative rights, add the following line to the file:

```text
jsmith ALL=(ALL) ALL
```

![](img/37f079cee226b270f2e09b37a2e4a05d_335_1.png)

```text

# Cmnd alias specification
```

**NOTE**

An additional advantage of using `sudo` is that all commands executed via `sudo` are logged to the log file `/var/log/secure`. This is sometimes very useful to system administrators.

The `/etc/sudoers` file can be fine-tuned to enable specific users to access specific restricted programs. For example, to give user dengle permission to start or stop sendmail, add the following lines to the file (Figure 12–6):

```text
dengle ALL=/sbin/service sendmail stop
dengle ALL=/sbin/service sendmail start
```

## PERSONAL FIREWALLS

A personal firewall is a single point of defense that all network traffic must go through in order to communicate with applications on a computer. It’s also a program running on a workstation computer that prevents unauthorized access to the computer via the network connection. A personal firewall is a pain to use, but necessary in many cases.

Do you need a personal firewall? A personal firewall is another line of defense against those that are trying to break into your system. If you are participating in a private network in which all hosts are trusted, you probably don't need a personal firewall. If you are connected to a large public network, such as the Internet, you do. Testing the packets that are directed to your computer on a public network will probably show that your computer is assaulted from a number of sources. These could be anything from a ping request to an attempted login.

A personal firewall examines packets as they arrive and then allows or denies the traffic based on a set of rules. The rules can be customized to allow traffic from networks, from individual computer systems, or based on the type of packet.

As with any security measure, with a personal firewall you give up some of your freedom to protect your assets. For example, you would probably need to refuse Telnet connections because they are too easily cracked. Telnet was nice to use because it was supported by hundreds of applications, was easy to implement, and fast. An alternative to Telnet is SSH, which, while easy to use, is slower because of the security it provides.

Firewall applications are available, such as NetBSD, Sygate, and Trustix; however, most personal firewall applications are based on the netfilter/iptables that is built into Linux. netfilter/iptables is the framework inside the Linux 2.4.x kernel that enables packet filtering, network address translation (NAT), and other packet manipulation. netfilter/iptables is discussed in more detail in the Firewalls section later in this chapter.

>

## SERVER SECURITY

- **Objective 4.11**
  If your Linux system is acting as a server, its security becomes much more important. A server may provide services such as remote disk space, DNS, and e-mail for many users.

- **Objective 4.12**
  Therefore, a server must be protected, similar to a workstation. Critical services must be updated to ensure that any discovered vulnerabilities are patched, boot loader passwords should be used, root access to processes should be limited, and so on.

### Securing Services

The most secure services on a server are those that are not running. The first step in securing services is to audit what services are available and stop those that are not needed or are not secure. For example, enabling sshd and disabling telnet is a good idea because SSH is secure, whereas Telnet is not.

### View and Stop Services

One way to view the services running on the system is to use the `ps` command. To view the services running on the Linux server, use the `ps -xf | more` command (Figure 12–9).

Look for commands such as `sshd` or `cupsd`. Daemons usually end with the letter `d`. Of course, this command requires that you know something about services. If you are still unfamiliar with available services, you may choose to view the services through a GUI application instead (Figure 12–10).
