
NIS can be configured during installation or by using the setup or linuxconf programs after installation. You must have the domain and server name in order to connect to the NIS server.

## NIS

The tools we’ve discussed so far are for managing a single Linux machine. NIS (Network Information Service) is a tool for a group of networked machines. NIS provides a simple network look service consisting of databases and processes. The purpose of NIS is to provide information to all machines of a network and it can host data like login IDs and passwords, group information, or host names and IP values.

One common purpose of an NIS server is to provide a central location to authenticate all the computers in your network. NIS enables an administrator to add new users to only one machine and provide the results to any machine in the network.

There can be one or more NIS servers in a network. These servers can support the same domain or individual domains. If they support the same domain there is one primary server and one or more slave servers. Slave servers are notified of any change to NIS and automatically retrieve the necessary changes to synchronize their databases.

## Configuring NIS

For this configuration, we will first configure an NFS server called NFSServer and an NFS client called NFSClient. After the NFS server and client are configured we will then configure NIS on NFSServer to do the following.

First, provide access to the /home directory to users. Allow NFS mounts of the /home directory with read/write access by adding the following entry to the /etc/exports file:

```
/home *(rw,sync)
```

Let NFS read the /etc/exports file for the new entry and make /home available to users of the network:

```bash
exportfs -a
```

Ensure that the required NFS, NFS lock, and port mapper daemons are both running and configured to start after the next reboot.

```
# exportfs -a
# chkconfig nfslock on
# chkconfig nfs on
# chkconfig portmap on
# /etc/init.d/portmap start
Starting portmapper: [ OK ]
# /etc/init.d/nfslock start
# /etc/init.d/nfs start
Starting NFS services: [ OK ]
Starting NFS quotas: [ OK ]
Starting NFS daemon: [ OK ]
Starting NFS mountd: [ OK ]
#
```

On NFSClient move the existing old /home directory and create a new directory called /nfs/home, then create a logical link to the new home directory called /home.

```
# mv /home /home.save
# ls /home
ls: /home: No such file or directory
# ln -s /nfs/home /home
# ll /
. . .
drwxr-xr-x 66 root root 8192 Jul 27 20:34 etc
lrwxrwxrwx 1 root root 9 Jul 27 20:55 home -> /nfs/home
drwxr-xr-x 12 root root 4096 Jul 27 20:49 home.save
...
```

Make sure you can mount NFSserver’s /home directory on the /nfs/home directory on NFSclient.

```
# mount NFSserver:/home /nfs/home/
# ls /home
davidengle guest home ksmith myuser test1
dengle hello jsmith lsmith rbrown test2
# umount /nfs/home/
#
```

Configure autofs auto-mounting. Edit the `/etc/auto.master` file to refer to the file `/etc/auto.nfs` for mounting the data anytime the /nfs directory is accessed. After five minutes autofs will unmount the directory.

```
# cat /etc/auto.master
# $Id: auto.master,v 1.2 1997/10/06 21:52:03 hpa Exp $
# Sample auto.master file
# Format of this file:
# mountpoint map options
# For details of the format look at autofs(8).
# /misc /etc/auto.misc --timeout=60
/nfs /etc/auto.nfs --timeout=600
```

Edit the file `/etc/auto.nfs` to do the NFS mount whenever the /home directory is accessed.

```
# cat /etc/auto.nfs
# $Id: auto.misc,v 1.2 1997/10/06 21:52:04 hpa Exp $
# This is an automounter map and it has the following format
# key [ -mount-options-separated-by-comma ] location
# Details may be found in the autofs(5) manpage
cd -fstype=iso9660, ro, nousid, nodev :/dev/cdrom
# the following entries are samples to pique your imagination
#linux -ro,soft,intr
ftp.example.org:/pub/linux
#boot -fstype=ext2 :/dev/hda1
#floppy -fstype=auto :/dev/fd0
#floppy -fstype=ext2 :/dev/fd0
#e2floppy -fstype=ext2 :/dev/fd0
#jaz -fstype=ext2 :/dev/sdc1
#removable -fstype=ext2 :/dev/hdd
home -fstype=nfs NFSserver:/home
```

Start autofs and make sure it will start after the next reboot with the chkconfig command.

```
# chkconfig autofs on
# /etc/init.d/auto.fs restart
Stopping automount: [ OK ]
Starting automount: [ OK ]
#
```

NIS was formerly known as Sun Yellow Pages (YP). NIS is a name change only. The service is the same. The name was changed because of copyright infringement; however, the programs are still named beginning with yp.

First tell Linux to add the NIS domain you will be using. Edit the /etc/sysconfig/network file and add the NIS domain name to be used. For this example we will use the name NIS-LINUX-NETWORK.

```
# cat /etc/sysconfig/network
NETWORKING=yes
HOSTNAME=localhost.localdomain
NISDOMAIN="NIS-LINUX-NETWORK"
```

NIS servers have to be NIS clients as well. Next we’ll edit the NIS client configuration file /etc/yp.conf to list the domain’s NIS server as the localhost.

```
# cat /etc/yp.conf
# /etc/yp.conf - ypbind configuration file
# Valid entries are
#
#domain NISDOMAIN server HOSTNAME
#    Use server HOSTNAME for the domain NISDOMAIN.
#
#domain NISDOMAIN broadcast
#    Use broadcast on the local net for domain NISDOMAIN
#
#ypserver HOSTNAME
#    Use server HOSTNAME for the local domain. The
#    IP-address of server must be listed in /etc/hosts.
#
ypserver 127.0.0.1
```

Start the necessary NIS daemons in the /etc/init.d directory. Use the chkconfig command to ensure that the daemons start after the next reboot and then initialize the NIS domain. Six commands will be used to start NIS: portmap, yppasswd, ypserv, ypbind, and ypxfrd.

- **portmap** The RPC daemon that NIS runs under.
- **yppasswd** Lets NIS users change their passwords on the NIS server from NIS clients.
- **ypinit** The ypinit command builds the domain subdirectory of /var/yp for the current default domain and builds a complete set of administrative maps for your system.
- **ypserv** The main NIS server process.
- **ypbind** The main NIS client process.
- **ypxfrd** The program used to speed up transfer of very large NIS maps.

```
# /etc/init.d/yppasswd start
Starting YP passwd service:    [ OK ]
# /etc/init.d/ypserv start
Setting NIS domain name NIS-LINUX-NETWORK: [ OK ]
Starting YP server services: [ OK ]
# chkconfig yppasswd on
# chkconfig ypserv on
#
```

Use the **ypinit** command to initialize the NIS domain. This program will make normal user accounts available to NIS clients.

```
# /usr/lib/yp/ypinit -m
```

After the NIS domain files have been created, you can start the **ypbind** and **ypxfrd** daemons.

```
# /etc/init.d/ypbind start
Binding to the NIS domain:
              [ OK ]
Listening for an NIS domain server.
# /etc/init.d/ypxfrd start
Starting YP map server:
              [ OK ]
# chkconfig ypbind on
# chkconfig ypxfrd on
```

Add NIS users by using the **useradd** command. Change the password with the **passwd** command. After you have created the user you have to update the NIS domain's authentication files by executing the **make** command in the /var/yp directory. This procedure will make all normal user accounts available to NIS including data stored in the /etc/passwd and /etc/group files.

```
# useradd -g users nisuser1
# passwd nisuser1
Changing password for user nisuser1.
New password:
Retype new password:
password: all authentication tokens updated
successfully.
```
