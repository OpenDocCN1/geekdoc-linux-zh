Another method of viewing port status is with the **netstat** and **lsof** commands. These commands do not connect through the network port, but rather check on the local machine to see what is running.

The netstat command is used to print network connections, routing tables, interface statistics, and other values. To use netstat to view open ports, type the **netstat -an | more** command.

# NOTE

The system administrator should certainly be aware of any port that is open on a server he is responsible for. The administrator should also be aware of which program is holding the port open.

The netstat command with the -p switch can provide this information. If nmap reveals that port 873 is open the command `netstat -ap | grep 873` should provide a line of output containing the PID of the process holding the port open. Then `ps -fp pid` will provide more information about the program. Additional information can be obtained about the process by using lsof to see which files the process has open, and strace can show all system calls made by the process.

The **lsof** command returns a list of open files. Use this command with the -i option to list Internet files. To use lsof to view open ports, type the **lsof -i | more** command.

# VIRTUAL PRIVATE NETWORK

How do you allow remote users to access your local network? Traditionally, a remote office would pay for a leased line or Frame Relay connection. Dedicated connections are very expensive, but offered a level of security unattainable by any other means, until the *Virtual Private Network* (VPN) was introduced.

A VPN provides the same network connectivity for remote users over a public connection as over a private connection. A VPN provides an extension to a Wide Area Network (WAN) without the expense. With a VPN, you can send data over a public network in a manner that emulates a point-to-point private connection. A VPN creates a secure tunnel between two networks and routes IP packets through it.

A secure tunnel is obtained using protocols developed by the Internet Engineering Task Force (IETF). Internet Protocol Security (IPSec) uses strong cryptography to provide both authentication and encryption services. Authentication ensures that packets are sent by whom they say they are from. Encryption prevents unauthorized users from reading packets in transit.

Most Linux distributions include the Crypto IP Encapsulation (CIPE) package to implement a VPN. CIPE is developed for Linux and uses encrypted IP packets that are encapsulated in User Datagram Protocol (UDP), encrypted, and sent over IP to a remote network host.

Another VPN solution is FreeS/WAN (www.freeswan.org), a free software implementation of VPN. It is a Linux implementation of the IPSec protocols. FreeS/WAN supports site-to-site VPN, remote users (Road Warriors), RSA keys for authentication, and Layer 2 Tunneling Protocol (L2TP) for VPNs. It is released under the GNU Public License.

In addition to software implementations of VPN hardware versions are also available. For example, Cisco provides VPN routers that provide managed IP VPN, among other services. A hardware VPN takes the workload of the VPN software off a server and puts it on a dedicated device designed to take large loads. Hardware devices are a good choice for enterprise-wide deployments.
