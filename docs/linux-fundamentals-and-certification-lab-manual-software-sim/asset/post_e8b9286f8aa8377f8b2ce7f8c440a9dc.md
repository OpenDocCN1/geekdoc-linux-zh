
milliseconds. The RTTs tell you how long the packets took to get from your machine to the router and back. This is the latency between the two machines.

Sometimes the RTTs may be shown as an asterisk (*) indicating that the remote machine is up and running but not responding. This is a normal response from many remote devices.

If the only indication on a line is a row of asterisks, it means that the remote system could not be reached. (Specifically it means that the packets did not make it back to your system.) This could be an indication of a problem, or it could be that the packets were blocked by a firewall.

The output can also contain several message symbols, such as !H or !N. These symbols are briefly described as follows:

- !H Host unreachable. The router has no route to the target system.
- !N Network unreachable.
- !P Protocol unreachable.
- !S Source route failed.
- !F Fragmentation needed. Usually indicates that the router is misconfigured.
- !X Communication administratively prohibited.

It may be useful to traceroute from a different location. This can give you more information about network traffic paths and the types of connections. If you want to traceroute from a different location on the Internet, go to the Web site www.traceroute.org.

### telnet
This utility is a terminal emulation program for TCP/IP networks. The client machine runs a telnet program, of which there are many. The server runs a telnet service that allows a client to connect and then enter commands through the telnet program. Commands run from a telnet session run the same as from the console. This allows you to control the server from a remote location.

telnet is an insecure program that sends information in clear text. When you connect to the server you are prompted for username and password, which anyone listening on the network can intercept. For this reason, the use of telnet is discouraged. Consider using SSH instead.

From an OSI model standpoint, if a telnet session is achieved, you will have verified that all seven layers of the model have been traversed. This indicates a properly running system.

Figure 13-10 shows an SSH session to a computer called pythia from a computer called Styx. The command from a Linux operating system to use SSH is `ssh <remote_computer_name_or_IP_address>`. You are then asked for a password, which is sent encrypted. On the first connection an RSA key will be generated for the connection between the two systems.

### dig
The dig (domain information groper) utility is used for DNS lookups. It is used to troubleshoot name server problems and is a replacement for the nslookup program.

dig will query your default system resolver, or you can query a specific server by listing it on the command line. For example, to use DNS from 192.168.0.20 to find information about yahoo.com, use the command:

`dig @192.168.0.20 www.yahoo.com`

The dig command results in a lot of information:

- At the top of the result the version of dig is listed together with the command line options that were entered.
- Next is status information. This listing shows the NOERROR status, indicating that there were no errors when the name was retrieved.
- The QUESTION and ANSWER sections are next. The QUESTION section indicates the query that was done. In the listing below, an A record, the default, was looked up. You can specify NS, PTR, MX, and others as domain lookup types (see RFC 1035).
- The AUTHORITY and ADDITIONAL sections (not shown) come next. The AUTHORITY section lists primary and secondary name servers for this domain. The ADDITIONAL section provides the IP addresses for those name servers.
- The last section displays information about the query, such as when the query was done, the server and port that were used, and the returned message size.

### host
This utility returns the IP address or addresses when given a hostname. In its simplest form, it returns only the IP address.

```
# host yahoo.com
yahoo.com has address 66.218.71.198
```

Use the `-t ns` option to list authoritative name servers for the domain.

```
# host -t ns yahoo.com
yahoo.com name server ns1.yahoo.com.
yahoo.com name server ns2.yahoo.com.
yahoo.com name server ns3.yahoo.com.
yahoo.com name server ns4.yahoo.com.
yahoo.com name server ns5.yahoo.com.
```

Use the `-t mx` option to list the mail servers for the domain. Three MX records were returned for this query to yahoo.com. A priority number is returned indicating that mx1 and mx2 are the preferred mail servers and mx4 is used if the other two are unavailable.

```
# host -t mx yahoo.com
yahoo.com mail is handled by 1 mx1.mail.yahoo.com.
yahoo.com mail is handled by 1 mx2.mail.yahoo.com.
yahoo.com mail is handled by 5 mx4.mail.yahoo.com.
```

### netstat
This command prints information about the Linux networking system. The information displayed is controlled by the first command line argument. The available arguments are displayed below:

- **(none)** No argument displays a list of open sockets.
- **--route** Displays the kernel routing table.
- **--groups** Displays multicast group membership information.
- **--interface[=iface]** Displays a table of all network interfaces, or the specified interface.
- **--masquerade** Displays a list of masqueraded connections.
- **--statistics** Displays summary statistics for each protocol.
