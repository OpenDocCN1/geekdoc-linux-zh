
## /etc/fstab

- The third field describes the type of file system. File systems supported by Linux include ext2, ext3, vfat, tmpfs, and others. An entry of swap indicates a partition used for swap.
- The fourth field is used to describe mount options of the associated file system. For most entries the option will be defaults. Use the `man mount` command to display options for non-NFS file systems. Use the `man nfs` command for NFS file system options.
- The fifth field is used by the dump command to determine which file systems need to be dumped. A value of zero or blank indicates that dump is not needed.
- The sixth field is used by the fsck program to determine the order file system checks are done at reboot time. File systems on the same drive will be checked sequentially, but file systems on different drives will be checked at the same time. A value of zero indicates that the file system does not need to be checked.

## /etc/modules.conf

The Linux kernel contains drivers for hardware and file systems. Some drivers can be compiled into the kernel, while other drivers are installed as modules. Modules, or driver files, provide information to Linux about how to control the devices they are designed to run.

Modules can be loaded and unloaded dynamically as needed by Linux. This allows the operating system to “free up” system resources that are not required at the moment. For example, a floppy drive may not be used most of the time and so Linux could load its driver as needed.

modprobe is a high-level program for handling loadable modules. This program makes the Linux modular kernel more manageable for all users. It can load a single module, a group of modules, or all modules. The behavior of modprobe can be modified by the configuration file /etc/modules.conf.

The /etc/modules.conf file (Figure 8–4) contains information about modules. This configuration file contains a list of drivers and the devices they are associated with. Linux usually writes the appropriate lines to the file when it detects a new device.

## THE SYSCONFIG DIRECTORY

The /etc/sysconfig directory (Figure 8–6) contains files that control what happens when a Linux system is booted up and shut down. This section outlines some of the files found in this directory. A more complete list that includes options can be found in /usr/share/doc/initscripts-version-number/sysconfig.txt.

![](img/37f079cee226b270f2e09b37a2e4a05d_228_1.png)

- **apmd**
  This file contains various parameters used in Advanced Power Management (APM). It contains information for what power settings to start, stop, or change on suspend or resume. The apm daemon is a monitoring program that works with power management code within the Linux kernel. It will alert users of low battery power on laptops and other power settings.

- **authconfig**
  This file sets the kind of authorization to be used on the host. For example, it may contain the following:

  ### NOTE
  Many other options can be viewed in the sysconfig.txt file.
  
  - `USELDAP=no`: Determines whether or not LDAP is used as a naming service. If this option is not set, authconfig examines the passwd setting in /etc/nsswitch.conf.
  - `USENIS=no`: Determines whether or not NIS is in use. If this option is not set, authconfig examines the passwd setting in /etc/nsswitch.conf.
  - `USEKERBEROS=no`: Determines whether or not Kerberos is in use. If this option is not set, authconfig examines the settings in /etc/pam.d/system-auth.
  - `USEMD5=no`: Determines whether or not MD5-based hashing should be used when setting passwords. If this option is not set, authconfig examines the settings in /etc/pam.d/system-auth. This option affects authentication using both local files and LDAP.
  - `USESHADOW=no`: Determines whether or not shadow passwords are in use. If this option is not set, authconfig checks for the existence of /etc/shadow.

- **clock**
  This file controls the interpretation of values read from the system hardware clock. For example, this file contains entries ZONE, UTC, and ARC.
  - `ZONE=<time zone>`: Indicates the time zone or a filename containing the time zone. Example: America/Chicago
  - `UTC=<true/false>`: Indicates whether or not the hardware clock is set to UTC (true) or local time (false)
  - `ARC <true/false>`: Has a value of true only on an alpha machine

- **desktop**
  Indicates the default desktop for new users.

- **mouse**
  Configures the mouse values.

## STARTING AND STOPPING SERVICES

Before you start and stop a service, you need to know what a service is. A Linux service is a program running under the Linux operating system that allows users, computers, or other services access to data the service provides.

For example, a Linux system that provides access to Web content to users is running a http service. If a Linux system provides network information via DHCP, that is a service. If a Linux system provides remote login with Telnet or SSH, that is a service. As discussed in Chapter 7, each of these services uses a well-known port to identify its service traffic.

Services must be started to provide access. Often, services are provided at startup, but some services must be explicitly started.

Services, occasionally, require stopping. For example, if the Web server stops responding to user requests, the httpd service may need to be restarted. Or, if a user was allowed access to a file via FTP, the FTP service should be stopped for security reasons when the user finishes.

Programs are vulnerable to attacks. If a service is running on its well-known port, it can broadcast its presence or listen on its port, allowing others on the network to find an intrusion point into the server that is using the running service. Intrusion points are caused by flaws in the service program. Updating programs with the latest patches can prevent network intrusion, but often hackers that exploit such flaws are faster than the programmers patching the software.

### Finding Services That are Running

To determine what services may have been executed during startup, look in the following places:

- **/etc/xinetd.conf (or inetd.conf) file**
  This file contains a list of services that may be started when requested. Use the following grep command to view the contents of this file:
  
  ```bash
  grep -v ^# /etc/xinetd.conf
  ```
  
  This command will list all the contents of the xinetd.conf file, except for any line with a # in it. The # character is used as a comment in a script. If a service that you do not want to start is listed, just edit the file and place a # at the beginning of the line for that service.

- **/etc/rcN.d (where N is a runlevel number) directory**
  These directories have the S and K scripts (Startup and Kill scripts) for services on the Linux system.

- **netstat command**
  The netstat command can be used to view what services are listening on a system. Services that are listening are running. To view running services, type the command:
  
  ```bash
  netstat -an | grep LISTEN
  ```
  
  By adding the “-p” switch, the netstat command will print the process ID of the process that is holding the port open. That way, you can confirm what program is listening on the port. For example, if an intruder had previously gained access to your server and saw that a Web server was listening on port 80, he may have replaced the Web server with a telnet or web server listening on port 80 for later use as an easy entry method through the firewall.
  
  The netstat command will print out several lines. Look at the second column for an entry like 0.0.0:0.80. The 0.0.0.0 can be an IP address or just zeros. The :80 is the port that is listening. In this case, the Web server is listening.
  
  Be aware, not all services run on well-known ports. Many services can be assigned ports other than their default ports. (This is often done for security reasons.)

### Configuring a Service

Both GUI and command-line commands can be used when dealing with services. The two most commonly used command-line tools are chkconfig and ntsysv.

- **chkconfig**
  This is a command-line tool for maintaining the /etc/rcN.d files. The --list option displays a list of services and the runlevels at which they will run. The partial list below indicates that kudzu is available in runlevels 3, 4, and 5.
  
  ```text
  # chkconfig --list
  kudzu     0:off  1:off  2:off  3:on   4:on   5:on   6:off
  syslog    0:off  1:off  2:on   3:on   4:on   5:on   6:off
  netfs     0:off  1:off  2:off  3:on   4:on   5:on   6:off
  ```
  
  You can turn a service on or off for a specific runlevel by using the --level option. The command **chkconfig --level 3 httpd off** turns the Web server service off for runlevel 3.

- **ntsysv**
  This is a simple text-based interface (Figure 8-7) that allows you to turn services on or off. The display shows a list of available services and allows a user to select or deselect each service by using the up and down arrow keys and then pressing the space bar to toggle the service on or off.

- **GUI Tools**
  Several implementations of service configuration tools are available for GUI interfaces. Figure 8-8 shows the Services Configuration tool for Red Hat. To start or stop a service, you place or remove a check from the check box or select the service and click the start/stop/restart button.
