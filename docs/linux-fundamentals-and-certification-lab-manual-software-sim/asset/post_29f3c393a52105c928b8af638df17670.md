## MANAGING CRON JOBS

Many tasks can be performed when system usage is low. For example, you may want to run a backup of user files at 2:00 am when most users are not connected to the system. An administrator could be available during late hours to run the job; however, a better solution would be to have the job run automatically at the given time. A system administrator can use automated tasks to perform almost any task at any given time.

cron jobs are used to run jobs that are repeated regularly. If a job needs to be run only once at a specific time, the **at** or **batch** command can be used. The **at** command accepts read commands from standard input or from a file and then executes the commands at a specified time using the environment variable shell of the requesting user.

## Understanding cron

*cron* is an acronym for *command run on and* is a Unix scheduler. *cron* is a daemon that can be used to execute scheduled tasks. *cron* is also a service, meaning that once started, it remains running while the system is up. *cron* responds to the system or individual users based on time. A *cron* can be scheduled to run hourly, daily, weekly, or monthly. *cron* wakes up once a minute, examines its configuration file(s) for changes, and executes commands if the time matches.

cron jobs are used by the system and by users. *System cron jobs* are *cron*s that are used to perform systemwide periodic jobs. For example, the */tmp* directory can grow in size and get cluttered with files that are no longer needed. A system *cron* will check the */tmp* directory daily and clean it up.

*User cron jobs* are *cron*s that are created for individual users. These could be anything from reminders of appointments to periodic backups of data files.

**System cron** The system *cron* job files on newer versions of Linux are contained in */etc*. The */etc* directory also contains other *cron* directories for hourly, daily, weekly, and monthly *cron* jobs. The configuration files are described as follows.

- **/etc/crontab** This file contains a schedule of when jobs are to be done. The *cron* table (*crontab* for short) contains which shell to run with, the path to the *cron* programs, a MAILTO to send results of tasks, the home directory of the cron owner, and the schedule of when jobs are to be accomplished.

The schedule lines are space- or tab-separated fields of time-related information and the programs to run. Table 11-1 describes the schedule fields.

### Table 11-1 Schedule fields.

| Field | Value | Description |
| :--- | :--- | :--- |
| Minute | 0-59 | The minute of the hour that the command will be executed. |
| Hour | 0-23 | The hour of the day the command will be executed. |
| Day | 1-31 | The day of the month the command will be executed. |
| Month | 1-12 | The month of the year the command will be executed. |
| Weekday | 0-6 | The day of the week the command will be executed. Sunday = 0, Monday = 1, ... |

In the crontab file, the first line under run-parts defines the hourly cron jobs to be run at one minute after the hour. The line is interpreted as:

| Minute | Hour | Day | Month | Weekday |
| :--- | :--- | :--- | :--- | :--- |
| 01 | * | * | * | * |
| One minute after the hour | Any hour | Any day | Any month | Any weekday |

The programs to be run hourly are contained in the /etc/cron.hourly directory.

The third line is interpreted as:

| Minute | Hour | Day | Month | Weekday |
| :--- | :--- | :--- | :--- | :--- |
| 22 | 4 | * | * | * |
| Twenty-two minutes after the hour | Four a.m. (24 hour clock) | Any day | Any month | Only on Sunday |

The programs to be run are contained in the /etc/cron.weekly directory.

The remaining lines are interpreted in the same way. Programs to be executed are located in the /etc/cron.X directories, where X is hourly, daily, weekly, or monthly. Any of the time/date values can contain an asterisk indicating any or all, or a comma-delimited list. For example, if a cron job needed to be done at five minutes after two on Monday, Wednesday, and Friday, the line would be

`*05 2 * * 1,3,5 command*`

- **/etc/cron.X** Contains the scripts to be executed when the crontab entries match the system date and time. Figure 11–2 shows the contents of the /etc/cron.X directories.

![](img/37f079cee226b270f2e09b37a2e4a05d_303_0.png)

- **/etc/cron.allow, /etc/cron.deny** These files are optional and contain a list of users that are allowed or denied the use of cron. If the files are not present, the Linux operating system will automatically allow or deny all users access to cron, regardless of the Linux distribution. In Red Hat Linux, if the files are not present, all users are allowed access to cron.
- **/var/spool/cron** On some systems, this directory is where the system crontab file, named root, is located. On systems with the system file /etc/crontab, this directory contains the crontabs for individual users only. The filenames used for the crontab file are the usernames. The cron process examines the /etc/passwd file to find a list of valid users and then looks for a file in /var/spool/cron that matches the username.

**User cron** Each user can have his or her own cron jobs list. The list is maintained in the user's home directory. A program called crontab is used to create, delete, or list the tables used by the cron daemon.

To create a user cron, create a file in your directory with the following format:

MAILTO=user@domain
minute hour day month weekday command

To experiment with the command, create a cron job that lists the contents of your home directory at ten minutes after noon. We will send the results to your sendmail account (see the Note following the example).

Create a file called ~/crontab.jsmith with vi. (The filename does not matter—it can be called anything.) The file will contain the following data.

MAILTO=jsmith
10 12 * * * ls -l

Tell cron the name of your crontab file.

crontab ~/crontab.jsmith

View your mail to see the result. The result should be similar to Figure 11–3. The mail is sent from root and contains the listing of the directory.
