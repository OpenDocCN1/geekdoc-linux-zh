
The scripts in each runlevel have filenames that start with either an S or a K followed by a sequence number and a name. S indicates a start script and K indicates a kill script.

As scripts are executed during the startup process, they read their respective configuration files. For example, when the Web server starts, it reads the `httpd.conf` file for configuration information.

The following lists some common configuration files. All configuration files are in the `/etc` directory unless listed otherwise.

- **/boot/grub.conf** The grub.conf file is read by the GRUB boot loader during startup. Changes made to this file are used when the system reboots. The grub.conf file was discussed in Chapter 6.
- **lilo.conf** The LILO boot loader configuration file. Changes to this file are executed when the system reboots. The lilo.conf file was discussed in Chapter 6.
- **fstab** This file describes what file systems are mounted automatically. The mounts listed are the partitions defined during the installation process, but new file systems can be added to the list. File systems can be mounted from remote sources by using SMD or NFS.
- **/etc/X11/XF86Config** The XF86Config file contains information about X. It defines screen resolution, mouse type, keyboard type, and other information for configuring X.
- **modules.conf** This file contains a list of modules for Linux to load. The list contains drivers that are not designed into the kernel.
- **passwd** The user's configuration file. This file contains the username, password, UID, GID, a comment, the home directory, and the default shell. The values are separated by colons (:).
- **shadow** This file contains the user's encrypted password information. Its fields include username, password (encrypted), last password change, days until change allowed, days before change required, days warning before password expiration, days between expiration and deactivation, expiration date, and special flag.
- **group** This file contains group information. Its fields are group name, password, GID, and user list. User list is a list of all users belonging to the group.
- **xinetd.conf** The xinetd service is a replacement for inetd. It provides better configuration options and better security. xinetd and inetd can start processes when requested instead of letting them use network resources all the time.
- **/etc/samba/smb.conf** This is the configuration file for the Samba program.
- **exports** This file lists the directories to be exported to other systems via the NFS protocol.

Many other configuration files will need to be changed. Information for other files can be found in the man files or from individual application documentation.

All configuration files are text files, editable using standard editors such as vi. Most system startup files are bash scripts and are easily customized.

## EDITING COMMON CONFIGURATION FILES

Most of the files used to start up the services of a Linux operating system can be customized. Almost all programs either use configuration files or are bash scripts that can be changed.

Configuration files are lists of input values that must be provided to set the environment for an application. But these values are also provided from environment variables.

### Environment Variables

The Linux operating system is very complex. It's made up of many different programs that require certain values as parameters when they start; however, instead of entering all the required values, you can set them once and forget them with environment variables.

You use only a few commands with environment variables, but lots of possibilities exist for values and uses. The three most commonly used commands are set, export, and echo.

- **set**
  Set is used to set shell attributes. Several options can be used; use the man set page to view them. Using set by itself will display all values used by the shell.

  ```bash
  # set
  PATH=/usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin:/usr/X11R6/bin:/root/bin
  PIPESTATUS=( [0]='0' )
  PPID=3954
  PROMPT_COMMAND='echo -ne \033]0;${USER}@${HOSTNAME%.*}:${PWD/#$HOME/~}\007'
  ```

- **export [-fn] [name = word]**
  The supplied name is marked for automatic export to the environment. The -f option refers to the name of a function, and -n removes the named variable. To export an environment variable called ORACLE_HOME with a value of /opt/oracle/product/9.2.0/, use the following command:

  ```bash
  # export ORACLE_HOME=/opt/oracle/product/9.2.0/
  # echo $ORACLE_HOME
  /opt/oracle/product/9.2.0/
  #
  ```

- **echo [name]**
  The echo command displays information to standard output. The echo command can display anything, and is often used from a script to display onscreen instructions. To display environment variables, you use the dollar sign ($) in front of the variable name. By convention, environment variables are capitalized. To view the PATH variable, use the following command:

  ```bash
  # echo $PATH
  /usr/local/bin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin:/usr/X11R6/bin:/root/bin
  #
  ```

Variables are used with shell programming. In Chapter 6, the variables $1, $2, and so on were used to identify the command-line position of a parameter passed to a script. Variables were also used with the let statement to assign values that were to be used later in the script. Environment variables can be used by all scripts. Variables can be defined in the user's ~/.bash_profile file to make them available for a specific user (Figure 8-1).

![](img/37f079cee226b270f2e09b37a2e4a05d_224_0.png)

Variables can also be assigned in the /etc/profile file to make them available globally (Figure 8–2).

An environment variable can be changed or modified after it is defined. For example, to change the PATH variable, adding /opt/oracle to the path, use the following commands:

```bash
# echo $PATH
/usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin:/usr/X11R6/bin:/root/bin
# export PATH=$PATH:/opt/oracle
# echo $PATH
/usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin:/usr/X11R6/bin:/root/bin:/opt/oracle
#
```

**NOTE**
The PATH environment variable lists the directories for the system to check when executing a program. Paths are separated using the colon (:).

### Configuration Files

Configuration files give an administrator an easy way to change how a program works. After values in a configuration file have been changed, the program that uses it will behave differently. For example, if the value **id:5:initdefault:** in the inittab configuration file is changed to **id:3:initdefault:** , the user will automatically be in the command-line interface instead of the GUI interface the next time the Linux operating system starts.

Before you make any changes to a configuration file, you should back it up. For example, before changing the **/etc/inittab** file, you may want to copy it to **/inittab.backup** . You should also know what the configuration file is used for and the possible values of its variables. Values and fields for common configuration files, in many cases, can be discovered in the man files. For example, to get information about the /etc/inittab file, you can enter the command **man inittab** .

**/etc/inittab**

The inittab file describes which processes are started at bootup and during normal operation. Entries within the file have the following format:
*id:runlevels:action:process*

- **id** Identifies an entry in inittab. This is a unique sequence of one to four characters.
- **runlevels** Lists the runlevels for which the action should be taken.
- **action** Describes how init handles the process. Some common values are:
  - **respawn** The process will be restarted if it terminates.
  - **wait** Linux will start the process and then wait for its termination. This is typical for initialization scripts. Often, one process must complete before another process can start.
  - **initdefault** This specifies which runlevel should be entered after the system boots. If no initdefault entry exists, init will ask for a runlevel.
  - **ctrlaltdel** This process will be executed when someone presses the CTRL+ALT+DEL key combination.
- **process** The name of the process to be executed.

The /etc/inittab contains getty programs. A getty program opens a tty port, prompts for a login name, and runs the /bin/login command. The getty program may be getty, agetty, mingetty, and others. (mingetty is a minimal getty used on virtual consoles.)

**/etc/fstab**

The **/etc/fstab** file contains information about the various file systems. When you create file systems during the Linux installation the entries are automatically entered in /etc/fstab. It is up to the Linux administrator to create and maintain the /etc/fstab file thereafter. This file is read during startup or shutdown to mount and unmount the file systems listed. File systems are mounted and unmounted in the order that they are found on the list.

The /etc/fstab (Figure 8-3) file contains the following six fields.

![](img/37f079cee226b270f2e09b37a2e4a05d_226_0.png)

- The first field contains the block special device or *remote* file system to be mounted. For ordinary mounts it will hold a block special device for the device to be mounted, for example, /dev/fd0 for the first floppy drive. For NFS mounts, the entry name will be *host:directory*, for example, *myserver.linuxplus.com:/opt/oracle*.
- The second field describes the mount point for the file system. For example, root is described as / and the boot partition is described as */boot*. A swap partition will have the word “swap” in this field.
