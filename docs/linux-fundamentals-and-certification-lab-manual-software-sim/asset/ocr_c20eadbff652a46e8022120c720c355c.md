+   - **File systems don’t mount.** The `/etc/fstab` file contains mount information for file systems that are to be automatically mounted during startup. Mounted file systems can be local file systems or remote file systems. This configuration file was explained in Chapters 4, 8, and 9.

- **Users can’t log in.** The `/etc/passwd` or the `/etc/shadow` file may be damaged or misconfigured. These files contain user account information. These files can be edited directly, or the utilities `passwd`, `useradd`, `groupadd`, `usermod`, and `others` can be used. These files can also be changed through GUI tools from an X desktop.

- **Can’t find remote computers.** The `/etc/hosts` file contains static translations of IP addresses to host names. Using TCP/IP networking, most systems have a DNS server available to provide address resolution; but on a small intranet this may not be the case. If the `/etc/hosts` file is used instead of DNS, every computer on the intranet should have the same file contents.

- **Can’t ftp into the server.** This is sometimes caused by the user’s shell not being listed in the `/etc/shells` file.

There are many configuration files. Any of these files can be misconfigured, accidentally deleted, or moved to the wrong location, causing the program it is designed to work with to not work. It is a good idea to document all configuration files as they are created. Configuration files should be backed up when they are changed.

# Server Software Problems

A server is any machine that provides services for users or other computers. Typically, a server is a network server, meaning that users and other servers on the network are the clients of the server. Services provided by a server are many and varied, such as network services, database services, application services, disk space services, printer services, and others.

**Network Server Software Problems** Common network services provided by a server include Dynamic Host Configuration Protocol (DHCP), Domain Name System (DNS), and remote login via Telnet or SSH. If network services fail, all user and computer clients could be unable to access the system. If DHCP is down, for example, all clients of the service will be unable to obtain an IP address and will not be able to interact with the network.

One way to ascertain information about network problems is through the log files. For example, if a user is not receiving an IP address via DHCP, the log file may obtain information about the request.
