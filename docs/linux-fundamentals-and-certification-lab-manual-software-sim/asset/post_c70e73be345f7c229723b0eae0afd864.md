Today, it is not uncommon to find a single hard disk with over 100 GB of disk space. Most operating systems will allow you to format the drive and take advantage of the larger capacity, but finding information in such a large storage space can become very difficult over time. Some file systems are designed for a limited capacity of disk space and a limited number of individual files.

To solve the problem of managing large-capacity drives you can divide the hard disk into *partitions*. (File systems are discussed further in Chapter 12.) A partition allows you to divide a disk drive into logical segments that each act as a separate drive. Each partition can use a different file system, allowing for the installation of more than one operating system.

The partitions on a computer system are maintained in the partition table. The master boot record (MBR) is the first sector on a hard disk and contains the partition table for the disk. An MBR can contain four partitions, either four primary partitions that can contain one logical drive each, or three primary partitions and one extended partition with multiple logical drives. Within an extended partition, there is no fixed limit to the number of logical partitions.

A partition table is divided into four sections, one for each partition. Each partition table entry contains information about where the partition starts and ends on the disk, whether the partition is active (it usually is), and the type of partition. ## Partitioning a Drive for Linux

A drive can be in four partition states when you get ready to install Linux. It can already have data, using all available space, it can have unpartitioned free space available, it can have an unused partition available, or it can have free space available in an actively used partition.

If all available space is being used, your choices are limited. You have to either reformat the existing partitions or install a second hard drive. This is necessary when using an existing system and often when using a new preconfigured system.

If you have unpartitioned free space, you can create partitions within the free space without interfering with existing partitions. Usually if you have this condition, it is a new install or you are installing more than one operating system.

If you have an existing partition that is no longer needed, you can use it for Linux. To reuse a partition, you need to delete the partition and then create a Linux partition.

Free space in an actively used partition is a little more difficult to use. To use this type of partition you have to back up the existing data, remove the existing partition, create two or more new partitions; restore the data, and then install the Linux operating system. If there is an operating system on the drive you are repartitioning, you will have to reinstall the operating system.

> **NOTE**
>
> The Logical Volume Management (LVM) partition type provides for increasing and decreasing existing partitions. This is discussed in Chapter 12.

### Device Names

If you are familiar with partitions in a DOS/Windows environment, you know that the first hard drive partition is C, the second is D, and so on. Linux uses a different approach. Instead of using single letters to indicate partitions it uses a file-based schema to name a device. Device names are usually in the form:

*/dev/xyN*

where

- `/dev` is the name of the directory where all devices are stored
- `xx` indicates the type of device (hd for IDE, sd for SCSI)
- `y` indicates which physical device the partition is on (hda for the first IDE hard disk, sdb for the second SCSI drive)
- `N` indicates which partition of a drive. The first four partitions are numbered 1 through 4; logical partitions start at 5.

To use the device, you link it to a mount point.

### Mount Points

In DOS or Windows, the mount points are easily distinguished by drive letters. If you refer to the first partition you use C, and so on through the alphabet. In Linux, the mount points are part of a single set of files and directories. For example, if you want user data to be stored on /dev/hdb4, you can mount /home on that partition. /home will appear as any other directory in the file system, but it will actually be a drive or partition separate from other directories on the system.

This process is useful when tuning your system for performance. If high-use areas are mounted to multiple drives, work can be spread across the drives, improving overall performance. For example, data for a relational database could be mounted on its own drive, and access log files for the database could be mounted on a second drive. This not only increases performance by spreading data across multiple drives, but also reduces the possibility of running out of disk space and causing the database to crash.

> **NOTE**
>
> The possibility of running out of disk space always exists. To recover from a database crash, a backup of the disk drive should be completed. Backup and recovery are discussed in Chapter 5.

## How Many Linux Partitions?

There are varying opinions as to how many partitions you need and why. You must examine your individual needs and make a decision based on them. That said, you should have at least three partitions. Each of these partitions is mounted to a specific directory within the file system hierarchy, such as root (/) or /boot:

- **swap** This partition is used by the computer to page information in and out of memory to disk space, which allows you to run programs that otherwise would not have room in memory to run. The size of the swap partition is determined by the amount of RAM in your system and the amount of space available on your hard drive. Generally, swap space is from the size of memory to twice the size of memory.
- **/boot** This partition is the area where the Linux kernel resides. Typically, this is 100 MB.
- **/** The root (/) partition is where all other files are stored. Depending on the type of installation, this needs to be anywhere from 500 MB to 2.5 GB. Some special-use systems will have less space.

Any high-use directory should be mounted to its own partition or drive. For example, the database listed in the previous section should be mounted to its own partition or drive. Another directory that is heavily used is the /var/log directory. The /var/log directory is where the system and applications write log entries. Logs can grow very large if they are not properly managed.

## Common Optional Partitions

If you have more than one disk, you must have more than one partition, one for each disk drive. One disk drive could store programs and another could store user data. Other reasons for more partitions are security, data growth, backup, and data sharing.

- **Security** Placing directories on different partitions provides another level of security. For instance, you may want to make a partition read only, reducing the chance of damaging program files.
- **Data Growth** Some files grow substantially during normal use. These *transaction files* can grow to the point that they completely use all available disk space and can cause an application to crash for lack of space. Placing these files on separate partitions reduces the chances of this problem.
- **Backup** Backup devices are often limited in capacity when compared to total hard disk storage. A tape drive, for instance, may have a 40 GB capacity and the hard disk may have 120 GB capacity. Backup of a fully utilized hard disk will take at least three tapes and will require user intervention to change tapes during the backup. By creating smaller partitions and adjusting the backup schedule you can ensure that one tape will contain the backup of particular resources.
