# NOTE

Many other options can be viewed in the sysconfig.txt file.

+   USELDAP=no Determines whether or not LDAP is used as a naming service. If this option is not set, authconfig examines the passwd setting in /etc/nsswitch.conf.
USENIS=no Determines whether or not NIS is in use. If this option is not set, authconfig examines the passwd setting in /etc/nsswitch.conf.
USEKERBEROS=no Determines whether or not Kerberos is in use. If this option is not set, authconfig examines the settings in /etc/pam.d/system-auth.
USEMD5=no Determines whether or not MD5-based hashing should be used when setting passwords. If this option is not set, authconfig examines the settings in /etc/pam.d/system-auth. This option affects authentication using both local files and LDAP.
USESHADOW=no Determines whether or not shadow passwords are in use. If this option is not set, authconfig checks for the existence of /etc/shadow.

+   clock This file controls the interpretation of values read from the system hardware clock. For example, this file contains entries ZONE, UTC, and ARC.
ZONE=<time zone> Indicates the time zone or a filename containing the time zone. Example: America/Chicago
UTC=<true/false> Indicates whether or not the hardware clock is set to UTC (true) or local time (false)
ARC <true/false> Has a value of true only on an alpha machine

+   desktop Indicates the default desktop for new users.

+   mouse Configures the mouse values.

# STARTING AND STOPPING SERVICES

Before you start and stop a service, you need to know what a service is. A Linux service is a program running under the Linux operating system that allows users, computers, or other services access to data the service provides.

For example, a Linux system that provides access to Web content to users is running a http service. If a Linux system provides network information via DHCP, that is a service. If a Linux system provides remote login with Telnet or SSH, that is a service. As discussed in Chapter 7, each of these services uses a well-known port to identify its service traffic.

Services must be started to provide access. Often, services are provided at startup, but some services must be explicitly started.

Services, occasionally, require stopping. For example, if the Web server stops responding to user requests, the httpd service may need to be restarted. Or, if a user was allowed access to a file via FTP, the FTP service should be stopped for security reasons when the user finishes.

Programs are vulnerable to attacks. If a service is running on its well-known port, it can broadcast its presence or listen on its port, allowing others on the network to find an intrusion point into the server that is using the running service. Intrusion points are caused by flaws in the service program. Updating programs with the latest patches can prevent network intrusion, but often hackers that exploit such flaws are faster than the programmers patching the software.
