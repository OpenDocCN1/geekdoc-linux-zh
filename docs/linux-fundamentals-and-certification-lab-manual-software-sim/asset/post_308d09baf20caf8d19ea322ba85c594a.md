### LINUX CONFIGURATION FILES

Many Linux operating system functions are controlled through configuration files. During initialization, when loading services, and when logging in a user, configuration files are read by the processes to control how applications will run. Linux has two basic types of configuration files—user and system configuration files. User configuration files contain values such as what colors are used on GUI windows, e-mail server information, how the shell prompt displays information, and others. System configuration files have values that affect the working of server functions. System files are critical to the operation of the computer.

There is no standard format for all configuration files within Linux. This is because the development of all the operating system applications was done by many individuals, often not working in concert with each other; however, the major files between different Linux distributions are the same.

### User Configuration Files

User configuration files are stored in the home directory of the user. A user directory is usually in the /home directory. For example, user jsmith would have a home directory of /home/jsmith. When a user logs on to the Linux system they always start in their home directory.

A user’s configuration files are contained within the user’s home directory. User configuration files usually begin with a dot ( . ). Files that begin with a dot are not displayed unless the -a option is used with the ls command. Dot files are hidden for security reasons and to prevent accidental deletion.

There are a number of command-line shells and GUI applications a user can log into. The more common of these are described in the following sections.

### bash Startup Files

bash uses several configuration files when it is first started and when it closes. The bash commands within the files are executed at initial login or when a shell is opened.

When bash is invoked it first reads and executes commands from the file /etc/profile. bash then looks for ~/.bash_profile, ~/.bash_login, and ~/.profile in that order and executes the commands from the first one that exists.

### NOTE

The tilde (~) character is used in a path variable as a shortcut for the HOME shell variable. Remember from the cd command description that several shortcut characters can be used in the bash shell. For example, the file `~/.bashrc` represents the path /home/username/.bashrc.

- **/etc/profile** The /etc/profile file contains common shell information for all users.
- **~/bash_profile** The ~/bash_profile is executed every time you log in. This file executes the `~/.bashrc` file and then the other commands within the file.
- **~/bashrc** The ~/bashrc file is executed when an interactive shell that is not a login shell is started. This file determines the behavior of interactive shells. This file is used to set up environment variables, define functions, and set the umask. (umask is the file mode creation mask, which determines the default permissions for any file created by the process.)

### GNOME Configuration Files

GNOME is a Windows-equivalent desktop environment. A desktop environment allows a user to control all programs within the operating system using a GUI interface.

The GNOME desktop is very configurable. Configuration information is stored in files that are read every time GNOME starts. GNOME has more than a few configuration files. Several *hidden* directories contain configuration information for user. The main directories are described as follows. (Other directories are described in the GNOME user and admin manuals at `http://www.gnome.org`.)

- **~/.gconf** Contains the GConf configuration source for the user. When the user sets a preference, the new preference information is added to this location.
- **~/.gconfd** Contains the GConf daemon details
- **~/.gnome** Contains user-specific application data that is not stored in the GConf repository
- **~/.gnome-desktop** Contains information about objects on the desktop

### Other Configuration Files

In addition to the files listed, you may see a wide range of other files, depending on how you use Linux. For example, if you are using the KDE desktop, your configuration files will be in the `~/.kde` directory. As with shell and GUI desktop configuration files, almost every application that you run will store configuration information as well.

### System Configuration Files

System configuration files are usually located in the /etc directory. Most of them reside directly in this directory, but some have subdirectories beneath /etc. For example, OpenSSH configuration files are contained in the /etc/ssh subdirectory.

Two startup processes are common to Linux operating systems—SysV and BSD. SysV, derived from an old Unix version System V, is the most commonly used startup process. BSD, Berkeley Standard Distribution, runs fewer but larger startup scripts and is used in all open-source BSD operating systems.

The SysV startup starts when the init process is run. The init process reads the /etc/inittab configuration file and searches for an initdefault entry, which contains the initial runlevel of the system. The init process then performs a boot and bootwait to mount file systems before users log in. The init process then runs the start scripts of the default runlevel found in inittab.
