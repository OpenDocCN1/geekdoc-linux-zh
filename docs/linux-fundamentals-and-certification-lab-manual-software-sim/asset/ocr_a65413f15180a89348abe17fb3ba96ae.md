+   • Collect as much information as possible by speaking with users and testing the system. Testing may be just basic functionality testing. Log in to the server and look at file systems, logs, and processes. Often a pattern characterizing the problem will emerge.
Before you get too involved with troubleshooting a problem, try the following.
• Scan for viruses. Computer viruses can cause some strange problems. You should always make sure your virus scanning software is up-to-date with the latest virus signatures. Virus scans should be run often. Several virus scanning software packages are available for Linux. One free package is F-Pro (www.f-prot.com).
• Read the documentation. The documentation often has a troubleshooting section that may have just what you need to correct a problem.
• Roll back any recent changes. You may have made a change to the system that you think is unrelated to your problem. If your problem started after this change, it could be coincidence; but chances are the change is the cause.

# COLLECTING INFORMATION

System information should be collected at all times, even if no problems exist. This is simply monitoring your system. Collecting the information and analyzing it will help you see trends in performance and establish a baseline of how the system is running. The baseline information is used to determine how the system is performing with a heavier workload due to more users, additional programs, or a change in services. Many sources for collecting information are available on a Linux operating system.

# Using Log Files to Identify Problems

Log files in the Linux operating system contain a wide range of information, including information and errors for the kernel, applications, and users. Most logs are maintained in the /var/log directory. The most important logs are /var/log/messages and /var/log/secure. Most messages and the files to which they are sent are controlled by the /etc/syslog.conf file (Figure 13–1). This file specifies rules for logging. Each rule consists of two fields—selector and action.

![](bbox=[0.06, 0.61, 0.2, 0.65])

```
# root@5: /etc
# Log anything (except mail) of level info or higher.
# Don't log private authentication messages!
*.info;mail.none;authpriv.none;cron.none					/var/log/messages

# The authpriv file has restricted access.
authpriv.*								/var/log/secure

# Log all the mail messages in one place.
mail.*								/var/log/maillog

# Log cron stuff
cron.*								/var/log/cron

# Everybody gets emergency messages
*.emerg								*

# Save news errors of level crit or higher in a special file.
ucp,news.crit								/var/log/spooler

# Save boot messages also to boot.log
local7.*								/var/log/boot.log
```

The selector field has two parts—facility and priority. The facility is where the message is coming from. Priority is the severity of the message. Available values for facility are auth, authpriv, cron, daemon, kern, lpr, mail, mark, news, security, syslog, user, uucp, and local0 through local7. Priority values are debug, info, notice, warning, warn, err, error, crit, emerg, and panic. An asterisk (*) can be used to represent all facilities
