
Swap partitions have a size limitation. On an x86 type system, the limit is two gigabytes. Other systems can provide more; for example, an UltraSparc can support up to three terabytes of swap space. A system can have multiple swap partitions if needed.

Remember from Chapter 2 that everything in the Linux directory hierarchy is a file or directory. File systems are mounted to directories and treated as if they were all one system. The same applies to swap partitions. Typically, a permanent partition is assigned to be a swap partition, but a file can be assigned to act as temporary swap space. To increase the swap space, do one of the following procedures.

## Increasing the Swap Partition

A swap partition is created exactly the same as any other partition, with the file system type being 82 from the fdisk menu. There are two ways to increase the swap partition size.

The first way is to add another partition of swap type. Follow the procedure discussed earlier in this chapter to create the partition.

![](img/37f079cee226b270f2e09b37a2e4a05d_268_0.png)

> To add partition space, you must have available unallocated space on the existing hard drive, or add a second hard drive to the computer.

To increase an existing partition, you must delete the partition and then re-create it with fdisk. To increase partition space, there must be unallocated space on the existing hard drive.

After the partition is created, you must format it. To format a Linux swap area, use the command **mkswap**. For example, to format the /dev/hda5 swap partition you would use the **mkswap /dev/hda5** command.

To use the swap space immediately, use the **swapon** command. The swapon command enables a device or file for swapping. The **swapoff** command disables the device or file. For example, to mount the /dev/hda5 device for swap, use the **swapon /dev/hda5** command.

To mount the swap partition to mount on startup, add an entry to the /etc/fstab file. For example, to add a swap partition from /dev/hda5, add the following line.

```
/dev/hda5            swap      swap      defaults    0     0
```

If multiple swap partitions are created, they can be assigned priorities. Swap partitions with the highest priority will be used first, and if swap partitions have equal priority they will be striped. So for tuning multiple swap partitions for performance you can assign lower priority to swap partitions from lower performance disks, or if all swap disks are equal in performance you can assign the same priority. The priority can be set by adding **pri=value** to the options field in the fstab file or with the **-p** switch when using the **swapon** command manually.

## Adding a Swap File

You should increase the swap partition if you are adding a new hard drive or repartitioning a hard drive. If you need to increase swap space and don't want to repartition or add a drive, you can use a swap file.

A swap file is an ordinary file that has been configured as swap space. To add a swap file, use the following procedure. You can have up to eight swap files, each up to 16 MB in size.

- 1. Select a drive for the swap file. This drive should have sufficient space, be a local hard drive (as opposed to a network file system), and be on a drive that typically has low usage.
- 2. Create a file to be used. To create a file, determine the size swap file needed in megabytes and multiply it by 1024. Two values are needed to create a swap file, block size (**bs**) and the number of blocks to copy (**count**). To create an empty file of the appropriate size, copy bytes from /dev/zero, a device file that returns bytes with the value of 0 to the swap file. For example, to create a 64 MB swap file, use the following command:

  ```
  dd if=/dev/zero of=/swapfile bs=1024 count=65536
  ```

- 3. Set up the swap file as you would a partition.

  ```
  mkswap /swapfile
  ```

- 4. Enable the swap file.

  ```
  swapon /swapfile
  ```

## KERNEL MODULES

The kernel in your Linux distribution contains several modules that are compiled into it. These modules give Linux basic functionality for using the keyboard, mouse, and other devices; however, to load every module that could conceivably be needed would make the kernel cumbersome, slow, and probably too large to run in the RAM space available. For this reason, most modules are loaded only as needed.

A Loadable Kernel Module (LKM) is loaded dynamically by the Linux kernel. For example, if an application needs to use a sound card, the kernel will load the module for the sound card. (Another term for a module is driver.)

During installation, the installer program will probe the hardware and load needed modules automatically. After installation, if new hardware is installed, the module information must be provided. Some installations run a program during system boot that automatically detects new hardware and then makes the necessary changes to the configuration files. All installations contain programs to add modules manually, such as modprobe or lsmod.

### Kernel Module Configuration Files

The Linux kernel module configuration is contained within two files, /etc/modules.conf (Figure 9–25) and /lib/modules/X/modules.dep (Figure 9–26), where X represents the Linux kernel version. The modules.conf file contains modules that are used for specific tasks and information about how to load and unload the modules automatically.

**FIGURE 9–25**  
/etc/modules.conf file.

![](img/37f079cee226b270f2e09b37a2e4a05d_269_0.png)

The /etc/modules.conf file contains several directives. The most common are the following:

- **alias** This directive gives alias commands to modules. It tells the kernel what modules to load. For example, from Figure 9–25, when the eth0 is needed, the e100 module is loaded.
- **options** The options directive specifies options that are to be used by the modules when they load. From Figure 9-25, the isfsearial module uses **options serialmajor=240 calloutmajor=241** when loading.
- **pre-install** This is a command to execute before installing a specified module.
- **post-install** This is a command to execute after installing the specified module. From Figure 9-25, the **/bin/aumix-minimal** command is executed after **sound-slot-0** is executed.
- **pre-remove** This command is executed before a module is removed.

If all goes well, the modules.conf file will not have to be edited. The Linux operating system usually maintains this file without user intervention; however, if you have a device that is not normally used or that is of a new type, you may need to configure it here. Consult the manufacturer's documentation for configuration information.

Another good example of using the options directive is when it is desired to force a network device into a specific mode. If a 10/100 auto-negotiating NIC card is connected to a switch port that has been forced to 100 full-duplex mode by the network administrator, the NIC may not perform well unless it is forced to 100 full-duplex mode as well. Often in these cases the NIC is in 100 half duplex, which drastically degrades network bandwidth. The tool mi-tool will display the current mode of an e100 card. The following options directive will force the e100 to 100 full-duplex mode at startup:

```
options eth0 e100_speed_duplex=4
```

The **/lib/modules/<linux version>/modules.dep** file contains information about module dependencies. The syntax of the file is the name of a module, a colon (:), and then a backslash (\) listing of dependencies (modules that must be present for this module to work). For example, the line from Figure 9-26:

```
/lib/modules/2.4.20-8/kernel/crypto/ciphers/cipher-aes.o: /lib/modules/2.4.20-8/kernel/crypto/cryptopapi.o
```

indicates that the cipher-aes.o module requires cryptopapi.o to be present.
