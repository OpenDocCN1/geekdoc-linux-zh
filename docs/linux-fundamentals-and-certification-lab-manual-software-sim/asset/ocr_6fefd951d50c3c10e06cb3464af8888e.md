Regardless of the naming convention used, eventually there will be two individuals that have the same username if the naming convention is followed. Part of the naming convention should take these cases into account.

An easy way to deal with similar usernames is to append sequence numbers, middle initials, or part of an employee number to the username. The drawback to these methods is that it becomes difficult for others to determine which user is associated with which username. This can result in misdirected e-mail on occasion.

# ## Passwords

A username identifies who a user is, and a password verifies that the associated user is the one in question. In other words, a password is used to authenticate a user. To utilize password authentication, passwords must be secret, must be resistant to guessing, and must be resistant to brute-force attacks. (A brute-force attack is obtaining an encrypted password and using the computer’s processing power and algorithms to break the encrypted values.)

All users should be educated about the importance of password secrecy. Passwords should never be posted on the face of the monitor, under the keyboard, in a drawer, or anywhere else for that matter. Passwords should never be shared with anyone. A password should be kept as secret as the pin number of a bank card.

A strong password should be at least eight characters in length, consisting of uppercase and lowercase letters, numbers, and special characters. Passwords should not have letters or numbers in sequence.

A strong password policy should require that passwords be changed periodically. Most administrators require that passwords be changed every 30 to 90 days. A further common requirement is that passwords cannot be changed earlier than 30 days.

Another good password policy is password aging. Password aging requires that passwords used during the past several password cycles not be reused. In other words, if you used a password in January and then, per the password policy, changed it in February, you could not use January’s password. For that matter, the password would be unusable for the next several months if the policy is enforced.

# ## Groups

A group is a logical grouping of users and resources. If Linux system resources are going to be shared by multiple users, groups are necessary to indicate which users have permission to access specific resources. It is a common practice to have a central server that makes specific directories available to other machines on the network. Users then have access to the shared directories to store data.

Shared data spaces accomplish two tasks.

+   • Users have a location to store data that is not physically on their workstation. If a system experiences a hard drive failure, the data is still safe.

+   • Data on shared spaces can be accessible to all users within the group. Users collaborating on projects can share documents and data files easily from the centrally shared location.

# ## Permissions

Each of the symbols (r, w, x) indicate whether a resource can be read from, written to, or executed by a user, a group, or everyone.
