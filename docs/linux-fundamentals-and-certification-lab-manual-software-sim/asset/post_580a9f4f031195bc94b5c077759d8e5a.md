
A typical file would contain the following entries:

```
order hosts,bind
multi on
```

/etc/hosts

The /etc/hosts file contains the name and IP address of local hosts. If a host’s name is in this file, the system does not need to query the DNS server to get its IP address. The disadvantage to using the /etc/hosts file is that a change to the list of hosts on a network requires manually changing the entries in the file. You can specify more than one hostname per line.

An /etc/hosts file will minimally contain one entry for the **localhost** loopback. localhost is a special hostname with a special IP address. It always references your own machine. The IP address associated with localhost is 127.0.0.1.

The remainder of the /etc/hosts file contains entries identifying IP addresses with hostnames. Typically, each line identifies at least two hostnames, one fully qualified domain name (FQDN) and one with just the hostname. Typical entries are described as:

```
127.0.0.1 localhost loopback
192.168.0.20 myserver.linuxplus.com myserver
192.168.0.24 myclient1.linuxplus.com myclient1
```

## CONFIGURING REMOTE CLIENT ACCESS

![](img/37f079cee226b270f2e09b37a2e4a05d_193_2.png)

Dial-up communications between computers are accomplished with the Point-to-Point Protocol (PPP). PPP encapsulates IP traffic over point-to-point links. This just means that PPP allows you to connect one computer to another computer, which then puts the TCP/IP packets onto the Internet.

Configuring for remote access is partially the same as configuring for network access. Besides needing a hostname, domain name, and DNS server IP address, the remote server usually wants a user that is dialing in to authenticate. The two most commonly used methods for authentication are password authentication protocol (PAP) and challenge handshake authentication protocol (CHAP).

**PAP** provides a simple method for a remote host to establish its identity to the server. The remote client and the server establish a connection using PPP, and then the remote client sends a username/password pair until the server acknowledges authentication or the connection is terminated.

PAP is not a strong authentication protocol. Passwords are sent in clear text from the remote client to the server. With PAP the username and password are sent to the server repeatedly until authentication is successful or terminated. This gives an opening for an unauthorized user to attempt a repeated trial-and-error attack.

**CHAP** provides authentication of a remote client to a server while providing more security than PAP. CHAP periodically verifies the identity of the remote client during the connection, whereas PAP verifies only once. CHAP does not permit the remote client to attempt authentication without first receiving a challenge from the server.

### Objective 1.12 Configuring a Modem and PPP

A modem must first be installed and recognized by Linux. Older internal modems and almost any external modem are usually the easiest to configure. Modems are serial devices and the older modems are configured like standard serial ports. External modems connect directly to a serial port, which will already be configured. Some newer modems and win-modems are difficult—if not impossible—to install. Win-modems are software-driven modems designed to run under the Windows operating system.

If the modem in the computer is not readily recognized by Linux, the first thing to do is to contact the modem manufacturer for help. Some modem manufacturers provide online support, including connection documentation and drivers for specific Linux distributions.

For each serial port there is a special file in the /dev directory. The /dev/ttyS0 is a special file for the serial port COM1. These special devices act as conduits for data. For example, you could send information from a file directly out com1 by typing the command `cat myfile > /dev/ttyS0`. The S represents serial and tyS0 is for COM1, tyS1 for COM2, and so on.

### NOTE

The **tty** is an abbreviation for teletype. A teletype is a type of terminal where a modified typewriter is designed to accept input from a communication line that operates it from a remote location.

Other device names can be used as well. For example, for the HSF modem found in Figure 7-21, the device name is /dev/ttySHSF0.
