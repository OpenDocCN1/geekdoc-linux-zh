Network server software problems can be especially hard to solve because proper operation of network server software depends on the server, the network, and the client being configured correctly. For example, a client experiencing problems receiving a dynamic IP address must first be configured to use DHCP, the network must be operational and allowing access to the DHCP server, and the DHCP service must be available on the server. (DHCP server and client configuration was explained in Chapter 7.) A few things that can cause server software problems are the following:

+   * **A service not starting.** A service may not have started because of hardware failure, network failure, a conflict with another process, and other reasons. Often, a service that did not initially start can be started manually. Use the `status` option of the `service` command to determine if the service started.

```
```
# service sendmail status
sendmail is stopped
# service sendmail start
Starting sendmail:                                [ OK ]
Starting sm-client:                               [ OK ]
# service sendmail status
sendmail (pid 15556 15547) is running...
#```
```

+   * **A service not responding.** The service may be running and configured correctly, but not serving clients. The first thing to check is that the firewall is not blocking access. You might want to temporarily stop `ipchains` to check that it is not blocking access.

```
```
# service iptables stop
Flushing all chains:                               [ OK ]
Removing user defined chains:                     [ OK ]
Resetting built-in chains to the default ACCEPT policy: [ OK ]```
```

+   * **Slow response.** A service may be working but extremely slowly. Use the `top` command to check that swap space and memory are available and that the CPU is not overworked. Any of these conditions could indicate that system resources need to be updated.

**Database and Application Server Software Problems** Many of the things that affect network services also affect database or application servers. You still need to check that the service is running and responding in a timely manner.

All applications require disk space, RAM, and swap space to operate, but a database application can grind to a halt if adequate resources are not available. For example, database applications have transient files that can grow to fill up all available disk space, causing the application to fail completely. Moving transient files to a separate hard drive can greatly improve performance and may prevent the system from crashing due to lack of available disk space.

**Disk Space Server Problems** Many servers provide disk space to users. The most common problem with providing disk space is that users tend to store large amounts of data to the space. The best way to limit the amount of disk space used is to implement quotas on the file system. Chapter 10 discussed how to implement quotas.

**Print Server Problems** In Chapter 9, configuring a printer was discussed. Problems encountered with the printer usually involve the print queue. A print queue can fill up with print jobs to the point that it can accept no more jobs. Usually, the cause of an overfilled print queue is a failure of the printing hardware. If the jobs can’t flush from the queue, the number of jobs will grow causing not only the print queue to fail, but the server to slow as well.
