One useful feature of CLI is command-line completion. All current shells have this feature. The command-line completion feature uses the Tab key to complete a command.

To illustrate the command, suppose that jsmith wants to view the contents of the file *my_summer_vacation_in_south_beach_journal*. The filename is very long and cumbersome to type. However, you can type **view my[tab]** (press the Tab key where indicated by [tab]), and the CLI will display **view my_summer_vacation_in_south_beach_journal**. You can then just press Enter.

If the characters that you enter are not unique to the file you want, the CLI will display a list of all files that meet the current criteria and you can type enough characters to make the file unique, then press Tab again.

Auto-completion is also available for usernames, machine names, or environment variables. The characters for each of these are \~, @, and $. Type each of these characters in the CLI and then press Tab.

# Redirection and Pipes

Processes under Unix/Linux use a minimum of three file descriptors—standard input, standard output, and standard error. The numbers associated with these descriptors are 0, 1, and 2 respectively. Furthermore, these descriptors are associated with the terminal from which the process was started. The purpose of redirections and pipes is to redirect these descriptors to a different location. For example, instead of having the output of a process go to the screen, you can redirect it to a text file.

## Redirections

Suppose that you want to run a specific program and cannot remember the name of the program. It would be helpful to see a list of all the programs available, but so many files are listed it is difficult to view them satisfactorily. One way to view the files at your leisure is to copy the directory contents to a file and then view the file.

To redirect standard input or output, use the redirection symbols greater than (> ) or less than (<). You should think of the redirection symbols as showing the direction to redirect. The > is used to redirect output, or away from the command. The < is used to redirect input, or into the command.

The > symbol redirects the output that would normally go to the screen to wherever you point. For example, if you wanted to redirect a directory listing (ls -l) to a file called myfile, you would type the command `ls -l > myfile`.

The < symbol redirects the input that would normally come from the keyboard to come from a file instead. For example, if you wanted to count the number of lines in the file myfile, you could either count the lines by hand or use the word count (wc) program to count them for you. To use wc, type `wc -l < myfile`.

The -l option says to count lines, and the < myfile redirects input to the wc command from the file myfile.

> For more information on wc refer to the man pages.

Now suppose that you are the user jsmith and want a list of all programs in the /sbin directory. Follow the next few steps:

- Log in to the CLI as jsmith.
- After you are logged in, change directories to /sbin with the cd command: `cd /sbin`
- List a long list directory, directing the output to a file called myfiles instead of to the screen: `ls -l > myfiles`
- View the contents of myfiles with the following command: `view myfiles`.

> The view command is a subset of the vim (Vi MImproved) command. The standard editor for Linux CLI is vi (often referred to as virtually impossible). The new and improved version of vi is vim. Using the command view opens a file with vim in read-only mode. You can then use the up/down arrow keys to browse the file. Use man vim for a complete description.

## Pipes

A pipe is in some ways an input/output redirection. It is used to send the output of one command to the input of another program. Suppose that you want to know how many JPEG images are in your pictures directory.

# NOTE

Linux does not require extensions for filenames, but often filenames contain extensions by convention. Therefore, JPEG files should end with **jpg** indicating the type of file.

You could use the **ls** command with a wildcard and type **ls *.jpg** to view a listing of the .jpg files. Next, you could count the files by hand. You might also redirect the listing to a file and then use the **wc** command with the **-w** option to count the words:

```
ls *.jpg > mypictures
wc -w < mypictures
```

However, a quicker method is to just pipe the output of the first command to the input of the second. In other words, instead of using the mypictures files as an intermediary, you can send the listing directly to the **wc** command and just display the count: **ls *.jpg | wc -w**. The bar (|) is the pipe symbol. Another command often used with piping is the **more** command. The more command takes the standard output and causes it to stop at each full page with the message **--More--** displayed. To list the current directory using more, type **ls | more**.

# NOTE

The Enter key displays the next line, the space bar displays the next page, and the q key quits the display.

## Objective 3.12 Environment Variables

The environment of a Linux operating system is determined by the hardware and software installed and running. Many programs running within Linux require information to complete certain tasks. For example, a system running an Oracle database needs to know where the oracle home is located. To establish the oracle home in the Linux environment, the environment variable, **ORACLE_HOME** is created. This environment variable points to the directory **/opt/oracle/product/9.2.0**. When a program needs this directory, the variable **$ORACLE_HOME** is used.

Environment variables can be created as needed. The environment variables currently defined on the Linux machine can be viewed with the **printenv** command. At the CLI type **printenv**. All the environment variables will be displayed.

By default several environment variables are defined. These can be viewed with the **echo** command. For example, to view the pathname of jsmith’s home directory, type **echo $HOME** and **/home/jsmith** will be displayed.

Environment variables are identified with a $ and are usually defined in uppercase letters. Environment variables can be used in place of their assigned values. For example, to change to the oracle home directory type **cd $ORACLE_HOME** and the current directory will change to **/opt/oracle/product/9.2.0**.

Some common environment variables include:

- **$HOME** contains the path to the current user’s home directory.
- **$USER** contains the name of the current user.
- **$UID** contains the UID of the current user.
- **$SHELL** the current shell being used.
- **$PATH** the pathname list to be used to find programs.

For a complete listing of environment variables in bash look at the bash manual from the Free Software Foundation at http://www.gnu.org/software/bash/bash.html.

The most critical of these environment variables is $PATH. A Linux distribution can have thousands of programs and data files when installed. If the operating system had to look at every file on the hard drive every time it had to execute a program, the system would run extremely slowly. A way to narrow down where the system looks for programs is to build a PATH environment variable that points the operating system to the most commonly used file locations. To execute the command **sqlplus** from the oracle directory the command would be /opt/oracle/product/9.2.0/bin/sqlplus.

If this command had to be executed often, typing the long statement would become very tedious. To shorten the number of characters to type, add the pathname to the PATH variable. In bash, type **export PATH=$PATH:/opt/oracle/product/9.2.0/bin**.

This statement combines the current path ($PATH) with /opt/oracle/product/9.2.0/bin and assigns it back to PATH.

The first PATH does not have a $ in front of it. This is because PATH is the actual variable, not the contents of the variable. The $PATH refers to the contents of the PATH variable. The colon (:) is a separator that is used between multiple paths. Export writes the PATH variable to the environment space for the shell.

Changing the PATH with the export statement is valid only for the current session. That means the same export command will have to be executed to have the same path available the next time the user logs on. A convenient way to set the path and have it automatically set every time the user connects is to set the path in the user's profile. For the bash shell the user profile is a file called **.bash_profile** in the user's home directory (Figure 5–2). Any local environment variables for this user can be set within the profile.

![](img/37f079cee226b270f2e09b37a2e4a05d_125_0.png)

```
#root@localhost:
# .bash_profile

# Get the aliases and functions
if [ -f ~/.bashrc ]; then
. ~/.bashrc
fi

# User specific environment and startup programs
PATH=$PATH:$HOME/bin
BASH_ENV=$HOME/.bashrc
USERNAME="root"

export USERNAME BASH_ENV PATH
```
