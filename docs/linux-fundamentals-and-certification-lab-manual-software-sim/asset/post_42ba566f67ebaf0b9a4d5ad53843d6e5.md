
# /etc/samba/smb.conf

The /etc/samba/smb.conf file is a configuration file for the Samba suite. It contains the runtime configuration for the Samba programs. The file contains name/value pairs of information within sections.

A section name is the name of the shared resource. A section can be named almost anything, but usually it is named something that describes what it is meant to share. For example, if the directory to be shared is the /opt/oracle directory, the section name might be **oracle**.

Some special section names are used in Samba, **global**, **homes**, and **printers**. Not all special names have to be used.

- The **global** section provides default values for all Samba shares. These are parameters that apply to the Samba service, not just individual shares.
- The **homes** section provides shares for individual clients on the network. This is often called *home space*.
- The **printers** section provides information for clients to connect to a printer. Shares in Samba are either a file directory or a printer.

The following listing is a sample smb.conf file listing. This file has only two sections—**[global]** and **[tmp]**. **[global]** contains information about general Samba share properties, and **[tmp]** contains information about a directory to share.

```
[global]
  workgroup=linuxplus.com
  security=user
  encrypt passwords=yes
  guest account=guest
  wins server=192.168.0.21
  local master=yes
  os level=99
  hosts allow=192.168.0. 127.
  interfaces=eth0
[tmp]
  path=/tmp
  writeable=yes
```

The **[global]** section contains the following properties:

- **workgroup** Windows machines participate on a network within a workgroup. Windows machines can participate in a peer-to-peer network with a workgroup, or in a network with a dedicated server providing a domain. The workgroup can be in either of these.
If you are using a Windows client, the computer's workgroup can be found by right-clicking the My Computer icon and selecting Properties. The computer name and workgroup or domain are under the Computer Name tab (Figure 8-10).

- **security** This tells Samba to run in user-level security mode and to challenge any user that is connecting for a user ID and password. From a Windows client, a connection dialog box asking for the ID and password of an account on the Linux Samba server will be displayed. If the user is connecting from a Linux client, the Linux server will ask for the password of the account the client is using. In both cases you must have an account on the Linux server to access the Samba share.

- **encrypt** This tells Samba to exchange passwords in encrypted mode. Encryption should always be used for security, unless the share is an anonymous share that all can use.

Enabling encrypted passwords requires that Samba use its own password file.  
This will cause an administrative headache if many users need access.

**NOTE**

Administration of encrypted passwords is easier if the Samba server is configured to authenticate with an existing user account's database like an NT domain or an LDAP server. In that case users and groups would still need to be created, but password management would not be required on the Samba server, which will relieve some of the administrative headache. Usually password file entries for users who are intended only to have access to shares specify /bin/false as the user's shell, preventing them from being able to log on to the machine but allowing share access.

- **guest** Linux allows a guest account to be used for access. This line indicates that the guest account is called guest. The guest account often does not have a password assigned to it.

- **wins server** WINS is a service running on a Windows network that provides an IP address of local computers using their computer name. This is similar to DNS, but is designed to work only with Windows and only uses the Windows-friendly name of the hosts.

Samba must have access to a WINS server to participate on the Windows network. If a WINS server is already on the network, use the wins server property to identify it. If there is no WINS server, Samba can handle the service by using the property

```
wins support=yes
```

which indicates that Samba will become a WINS server for your network.

- **local master** The Windows network requires a central location that keeps track of what machines and workgroups exist on the local subnet. This is called a local master. Any Windows machine can be the local master browser. Setting the local master to *yes* indicates that Samba can be that machine.

- **os level** A machine on a Windows network becomes the local master by broadcasting its presence. The os level of Windows machines is hard coded to cause the most advanced version of the operating system to be the local master. By setting the os level to 99, you beat every Windows machine, which allows the Linux Samba server to become the local master.

- **hosts allow** The hosts allow entry sets which IP networks are allowed to access the network share. In this case the networks are **192.168.0.** and **127.**. The network portion of the IP address is listed, not the host portion. The 127 network is localhost.

- **interfaces** If your Linux server has more than one Ethernet adapter, you can specify which adapter will be used for Samba.

The next section, **[tmp]**, is the name of a share. On Windows this share will display as a directory on the Linux server. Figure 8-11 shows the Linux server Styx with its tmp directory displayed. If any printers are available on the Linux Samba server, they will be displayed as well.

Your very basic smb.conf file is configured. You can test the content of the file by using the Samba-provided utility **testparm**. Any errors to the configuration file will be displayed. Follow the instructions from the displayed list to correct any errors.

# Creating Samba Users

Before a client can access our share, there must be a valid user ID and password in the Samba password file. In this Samba installation the password file is /etc/samba/smbpasswd. This file contains the user ID and an encrypted password string for each authorized user. Entries in the smbpasswd file must have corresponding entries in the Linux main /etc/passwd file.

To add a user to the smbpasswd file, use the *smbpasswd* command. To add the user jsmith to the Samba password file, use the **smbpasswd -a jsmith** command.

After the command is entered, a new SMB password is requested. You must type the password a second time to ensure it is correct. If the user does not exist in the Linux system, an error is displayed. The following is a sample listing of the command adding the user jsmith. Figure 8-12 shows the resulting /etc/samba/smbpasswd file.

```
# smbpasswd -a jsmith
New SMB password:
Retype new password:
Added user jsmith.
#
```

# Starting Samba

Only two processes need to be started to use Samba---**smbd** and **nmbd**. smbd provides the SMB/CIFS services to clients. This provides file and print sharing services to Windows clients.

nmbd provides the NetBIOS over IP naming service to clients. The NetBIOS over IP naming service allows the Linux Samba server to participate in the Windows *Network Neighborhood* view.

The following entries perform two tasks. The command *ps -ef | grep search\_name* determines whether smbd and nmbd are running. The second line of each entry starts the service.

```
# ps -ef | grep smbd
root 14592 14535 0 08:16 pts/1 00:00:00 grep smbd
# ps -ef | grep nmbd
root 14594 14535 0 08:16 pts/1 00:00:00 grep nmbd
# smbd
# nmbd
```

```
# ps -ef | grep smbd
root 14596 1 0 08:16 ? 00:00:00 smbd
root 14600 14535 0 08:16 pts/1 00:00:00 grep smbd
# ps -ef | grep nmbd
root 14598 1 0 08:16 ? 00:00:00 nmbd
root 14602 14535 0 08:16 pts/1 00:00:00 grep nmbd
#
```
