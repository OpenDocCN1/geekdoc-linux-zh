
The basic syntax of tar is `tar -options filename1 [filename2...] [dirname1...]`. Tar has many options. Some of the most common are:

- **-A** append tar files to an archive
- **-c** create a new archive
- **-d** find differences between archive and file system
- **--delete** delete from the archive
- **-f** use archive file
- **-l** stay in one file system
- **-p** extract all protection information
- **-r** append files to the end of an archive
- **-t** list the contents of an archive
- **-u** only append files that are newer than the copy in the archive
- **-x** extract files from an archive
- **-v** verbose list of files processed
- **-z** filter the archive through gzip

Tar has three basic modes—create, compress, and list. Tar can also compress and uncompress through a filter. The options for each of these modes are:

- **tar -c** for create mode
- **tar -x** for extract mode
- **tar -t** for list mode
- **tar -z[x/c/t]** compresses or uncompresses the tar ball

Except for the mode options, -v and -f are the most commonly used options. The -v option tells tar to give a verbose message. Without the -v option, tar just runs with no indication of what is going on. This can be very disconcerting. The -f option tells tar to use a file with a specified name.

## Creating a tar File

To tar an entire directory, use the following syntax: `tar -cvf new_tar_name.tar directory_name`, where new_tar_name.tar is the name of the newly created tar file, and directory_name is the name of the directory that will be archived. For example, to archive the directory /home/jsmith/adom into the tar file adom_11-01-2003.tar (Figure 6-1), use the `tar -cvf adom_11-01-2003.tar /home/jsmith/adom` command:

## Listing a tar File

Often the name of a tar file is cryptic and does not indicate what is in the file. Listing the contents of a file indicates what is in the file and where it will be placed when the file is un-tarred. The syntax is `tar -tvf tar_filename.tar`, where tar_filename.tar is the tar file to be listed. For example, to list the contents of the tar file adom_11-01-2003.tar (Figure 6–2), use the `tar -tvf adom_11-01-2003.tar` command:

## Extracting a tar File

Extracting files from a tar archive is one of the most common tasks of a Linux administrator. Files that are transmitted over a network are commonly tarred to make administration easier. The syntax is `tar -xvf tar_filename.tar`, where tar_filename.tar is the name of the tar to extract. For example, to extract the contents of the tar file adom_11-01-2003.tar into the current directory (Figure 6–3), use the `tar -xvf adom_11-01-2003.tar` command:

![](img/37f079cee226b270f2e09b37a2e4a05d_145_1.png)

```bash
[jsmith@Styx jsmith]$ ls -l
total 2636
-rw-rw-r-- 1 jsmith jsmith 2693120 Oct 1 11:19 adom_11-01-2003.tar
[jsmith@Styx jsmith]$ tar -xvf adom_11-01-2003.tar
adom/
adom/adom
adom/manual.doc
adom/readme.lst
adom/adomfaq.txt
[jsmith@Styx jsmith]$ ls -l
total 2640
drwxr-xr-x 2 jsmith jsmith    4096 Aug 6 2001 adom
-rw-rw-r-- 1 jsmith jsmith 2693120 Oct 1 11:19 adom_11-01-2003.tar
[jsmith@Styx jsmith]$ ls adom/
adom adomfaq.txt manual.doc readme.lst
[jsmith@Styx jsmith]$
```

To extract a single file or group of files from a tar, use the following syntax: `tar -xvf tar_filename.tar filename`, where *tar_filename.tar* is the name of the tar file and *filename* is the name of the file to be extracted. For example, to extract the file *adomfaq.txt* from the archive *adom_11-01-2003.tar*, use the following command:

```bash
tar -xvf adom_11-01-2003.tar home/jsmith/adom/adomfaq.txt
```

### NOTE

Files extracted from a tar will be placed in the same directory structure that they were archived from, starting in the current directory. For example, extracting the tar file *adom_11-01-2003.tar* while in the `/home/jsmith` directory will extract the files to `/home/jsmith/home/jsmith/adom`.

Be careful not to accidentally overwrite existing files. When you extract a file from a tar, if a file with the same name exists you will be prompted to replace the file or not. It is possible to have files on the system that have the same name, but are used for different purposes. For example, it is very common to have a file named *readme.txt* that describes the usage of a program in an archive. This same name can be used in many different files. When you extract a new program to a pre-existing directory that has other files, you risk overwriting an existing file with the same name.

## Updating an RPM Package

Most good programs are continually changing. As computer hardware improves, the programs it runs are updated to exploit the new features. Programs also evolve over time to meet the needs of program users. As new programs are released, existing programs can be updated.

Because RPM keeps a database of characteristics and storage locations, it can easily update existing programs. The syntax is similar to that of an RPM install (Figure 6-4), `rpm -options rpm_filename.rpm`, where *rpm_filename.rpm* is the name of the new RPM package. To upgrade an RPM package called *tftp-server* with the new package *tftp-server-0.32-4.i386.rpm* (Figure 6-5), use the following command:

```bash
rpm -Uvh tftp-server-0.32-4.i386.rpm
```

```bash
[root@Styx root]# ls

adom                    mytar.tar.z
adom-100-eif.tar.gz.tar squidrealme1-1.4.0-1.noarch.rpm
anaconda-ks.cfg        tftp-server-0.32-4.i386.rpm
install.log
[root@Styx root]# rpm -lvh tftp-server-0.32-4.i386.rpm
Preparing...                        ########################################### [100%]
     1:tftp-server                 ########################################### [100%]
[root@Styx root]#
```

## Querying an RPM Package

To determine if an RPM package is installed on the Linux operating system, use the query option (-q). The syntax is `rpm -q rpm_package_name`, where rpm_package_name is the name of the RPM package to be queried. To query the RPM system, asking if the tftp-server package is installed (Figure 6-6), use the `rpm -q tftp-server` command:

![](img/37f079cee226b270f2e09b37a2e4a05d_147_0.png)

```bash
[root@Styx root]# rpm -q tftp-server
tftp-server-0.32-4
[root@Styx root]#
```

The RPM system responds with the package name, version, and release number of the package. Use the query option to verify that a package is installed on the system.
If you aren't sure of the exact name of the installed RPM try the following:

```bash
[root@www engie005]# rpm -qa | grep -i ftp

gftp-2.0.14-2
ftp-0.17-17
vsftpd-1.1.3-8
[root@www engie005]#
```
