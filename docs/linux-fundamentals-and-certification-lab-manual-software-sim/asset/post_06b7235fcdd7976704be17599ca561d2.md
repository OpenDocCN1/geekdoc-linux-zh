
One environment value that users often change is **PROMPT_COMMAND**. Just before bash prints each primary prompt, PROMPT_COMMAND is checked for a non-null value. If it has an assigned value, it is executed the same as if it had been typed on the command line. For example, to display the date and time before each prompt, enter the `export PROMPT_COMMAND=date` command, and the date and time will display before each prompt:

```
[jsmith@Styx jsmith]$ export PROMPT_COMMAND=date
Thu Sep 18 22:25:55 CDT 2003
[jsmith@Styx jsmith]$
```

The primary prompt can be changed by changing the value of **PS1**. PS1 is an environment variable that stores the value of the shell prompt. It does not appear in the output of the env command. In the Red Hat Linux implementation of bash, the default prompt displays as follows:

```
[jsmith@Styx jsmith]$
```

The PS1 value for this prompt is:

`$PS1 = "\u@\h\W\$"`

Special characters such as **\u** or **\h** are used to display environment variables within the prompt. In the prompt, **\u** represents the user and **\h** represents the hostname. Some of the available prompt variables include:

- \d The date in “day month date” format
- \h The hostname, up to the first ‘.’
- \H The hostname
- \l The base name of the shell’s terminal device name
- \n A new line
- \r A carriage return
- \t The time in 24-hour format
- \T The time in 12-hour format
- \@ The time in 12-hour am/pm format
- \u The username of the current user
- \w The working directory
- \W The basename of $PWD
- \$ If the UID is 0, display #, otherwise display $

The PROMPT_COMMAND and the PS1 value assignment can be included in the .bash_profile to set the values when the user logs in.

## COMMON COMMANDS

![](img/37f079cee226b270f2e09b37a2e4a05d_126_0.png)

A shell is an environment to execute operating system commands and programs necessary to manage and maintain the Linux operating system, and to run applications for users to access. The following section provides information concerning executing commands and scripts and explains some of the more common utilities.

### Execution of Scripts and Programs

All programs and scripts that run from the command line have a similar command syntax: First the command (program) name, followed by options and then arguments. For example, to list all the files that end with `.conf`, type `ls -1 *.conf` where `ls` is the command, `-1` is an option, and `*.conf` is an argument.

> **NOTE**
>
> To discover the options and arguments available for most commands, use the man command. Use the `man man` command to display the manual pages for the man command.

Commands and scripts are similar in the way they function, but are different in the way they are designed. A command is a compiled program in binary format. A script is a text file that contains commands and logic syntax to execute a group of commands in a particular sequence.

Commands start as source code, typically in the C programming language. The source code is processed by a compiler that translates each statement into symbolic code, which is then linked to the system. The result is a machine language program that performs a specific task. Commands contain binary information, and their contents are unreadable if displayed.

Scripts, as shown in Figure 5-3, are strictly text files. Besides containing commands, a script can also contain comments (preceded by the # symbol) and logic structures, such as case statements, if statements, and other programming constructs. Scripts save time by combining system and shell commands that are executed often into a single package. Otherwise, running a complex list of commands can be time consuming and, with a larger number of statements, increase the chances of making a mistake. Scripts can be interactive or automatic, providing greater flexibility in managing Linux.

### FIGURE 5-3
Script.

```
#
# $Header: dbshut.sh.dp 03-apr-2001.13:38:20 jboyce Exp $
# dbshut.sh.dp Copyr (c) 1991 Oracle
#
##############################################
#
# usage: dbshut
#
# This script is used to shutdown ORACLE from /etc/rc
(.local).
# It should ONLY be executed as part of the system boot
procedure.
#
##############################################

ORATAB = /etc/oratab

trap 'exit' 1 2 3
case $ORACLE_TRACE in
T) set -x ;;
esac
```

Commands and scripts have read and execute permissions. Figure 5-4 is a typical listing, showing that the root user has read/write/execute permissions, whereas everyone else has read/execute permissions.

### Useful Utilities

Most commands have multiple options and features available. Spend some time viewing man pages to see a list of options. Don't try to remember all the options (they are always available online); just become familiar enough with these options to remember that they are available. Some important basic commands include:

- **man**: Formats and displays the online manual pages. Example: `man ls`
- **ls**: List a directory. The option, -l, will give a detailed listing, -F will list the file types, and -a will list hidden files. Example: `ls -la`
- **cd**: Change directory. Example: `cd /etc`
- **mkdir**: Make a directory. Example: `mkdir /home/jsmith/mymusic`
- **rm**: Remove files and directories. To remove a directory, use the -r (recursive) option. To remove a file, type `rm` and then the name of the file. Example: `rm myfile` or `rm -r mydir`
- **chmod**: Change file access permissions. (Discussed earlier in this chapter.) `chmod` can use symbolic mode or octal mode. Example: `chmod a+x myfile` and `chmod 755 myfile` (both give execute permission to all users)
- **chown**: Change file owner and/or group. `chown` changes the ownership of a file. This command is most often used when the root user creates a file, then transfers ownership to another user. Anyone with full permissions on a file can change the ownership of the file. The syntax for the command is `chown [option] owner[:group] file`

One useful option is -R, which causes `chown` to act recursively. This means that the ownership can be changed to a directory and all the files within the directory will be changed as well. Suppose that root owns a file called data1 and wants to change ownership to user jsmith in group admin. The command from the directory that data1 is in would be `chown jsmith:admin data1`.

- **chgrp**: Change the group of a file. `chgrp` lets a user change the group ownership of a file. The syntax is similar to the syntax for `chown`:

`chgrp [options] group file`

Suppose that a file named data1 is owned by root, and the root user wants to change group ownership from the root group to the database group. The command from the directory that data1 is in would be `chgrp database data1`.

- **mv**: Move a file. Use this command when the file needs to be moved or renamed (renaming a file is the same as moving it). The syntax is `mv [options] source destination` where source is the current file location and destination is where you want it to be relocated.

Suppose that root wants to move the data1 file to jsmith's home directory. The current location of the file is /root. The command to move the file is:

`mv /root/data1 /home/jsmith`

If the file needs to be renamed, the new filename can be appended to the end of /home/jsmith. For example, to move data1 and change the name to jsmithdata, use the following:

`mv /root/data1 /home/jsmith/jsmithdata`

If jsmith wants to rename the file within his directory to mydata, he would use the command:

`mv jsmithdata mydata`

The pathnames are not necessary because the file is moved within the same directory.

- **cp**: Copy a file. cp has the same syntax as mv: `cp [options] source destination`. The difference between mv and cp is that cp leaves the source file in the current location whereas mv removes it from the current location.

Suppose that root wants to copy the file **data1** to jsmith's home directory. The current location of data1 is /root. The command to copy the file is:

`cp /root/data1 /home/jsmith`

If the new copy of the file needs to be renamed, append the new name to the destination path. For example, to copy the data1 file to jsmith's directory with the name jsmithdata, type the following:

`cp /root/data1 /home/jsmith/jsmithdata`

- **ln**: Linked files can be symbolic or hard links. Symbolic links are pointers to programs, files, or directories located elsewhere. The linked file can be manipulated in the same way as the actual file. Symbolic links provide a way to easily reach files even though they are not in the current directory.

The rcX.d directories that contain the files to start or kill during startup and shutdown of Linux contain symbolically linked files. Using linked files enables the system to provide the correct files for each runlevel without having to duplicate the files.

To create a symbolic link to the /etc/hosts file from the /root home directory, type the following:

`ln -s /etc/hosts`

To display a list of linked files use the command `ls -F`. Linked files are displayed with the at (@) symbol after them.

Deleting a symbolically linked file removes the link, but not the original file. Deleting the target of a symbolically linked file breaks the link.

Hard linked files are pointers to programs and files, but not to directories. Like symbolic links, hard links provide access to files located in other locations. Unlike symbolic links, hard links must be on the same disk drive. Hard linked files point to the same disk address as the original file.

To create a hard link from a file called /home/jsmith/myfile.txt to a file in the /root directory called /root/myfilehardlink.txt, type the following:

`ln /home/jsmith/myfile.txt /root/myfilehardlink.txt`

Deleting a hard linked file removes the link, but not the original file. Deleting the target of a hard linked file does not break the link.

- **cat**: Print the contents of a text file to standard output. The syntax is `cat [options] filename`. To view the contents of a text file named data1, type the following:

`cat data1`

- **more**: View files on the screen through the more filter. more is a filter for paging through text. The text can be in a file or piped from another program. The basic syntax is `more filename`. more will display text to the screen one full screen at a time, pausing at the end of each screen for the user to continue to the next screen. To view a file named data1, type the following:

`more data1`

To view the results of the ls command one screen at a time, pipe the results to the more command:

`ls | more`

- **less**: The less command, like more, is used to view a file, but also allows backward movement through the file. The basic syntax for less is `less [options] filename`. To view the file /etc/inittab with the less command, type the following:

`less /etc/inittab`
