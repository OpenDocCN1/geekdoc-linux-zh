Enabling encrypted passwords requires that Samba use its own password file.  
This will cause an administrative headache if many users need access.

NOTE

Administration of encrypted passwords is easier if the Samba server is configured to authenticate with an existing user account's database like an NT domain or an LDAP server. In that case users and groups would still need to be created, but password management would not be required on the Samba server, which will relieve some of the administrative headache. Usually password file entries for users who are intended only to have access to shares specify /bin/false as the user's shell, preventing them from being able to log on to the machine but allowing share access.

guest Linux allows a guest account to be used for access. This line indicates that the guest account is called guest. The guest account often does not have a password assigned to it.

wins server WINS is a service running on a Windows network that provides an IP address of local computers using their computer name. This is similar to DNS, but is designed to work only with Windows and only uses the Windows-friendly name of the hosts.

Samba must have access to a WINS server to participate on the Windows network. If a WINS server is already on the network, use the wins server property to identify it. If there is no WINS server, Samba can handle the service by using the property

```
wins support=yes
```

which indicates that Samba will become a WINS server for your network.
