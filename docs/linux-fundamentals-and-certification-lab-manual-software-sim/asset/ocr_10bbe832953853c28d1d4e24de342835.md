All security implementations require a trade-off between user productivity and security measures. The goal of security is to provide the maximum security with minimum impact to user productivity.

# # SECURITY UPDATES

Most software, especially networking software, is not perfect. TCP/IP networking protocols provide the tools to accomplish every networking task. They also provide a way for unauthorized users to access a system. Every time a door to the computer system is open someone can exploit its access. If the software does not completely protect the system, someone will take advantage of the *security hole* it provides.

Some programs consist of thousands, even tens of thousands, of lines of code. The chances are great that an error can be present, and the chances are astronomical that a developer can forget or not think of some piece of code that needs to be changed or added. Most of these large programs are constantly under development. During normal usage someone will discover that the computer system can be compromised through a program error or oversight and report it to the developer. The developer then makes changes to the program and provides an update. The update is applied, and the cycle of update, test, report, and change starts over again.

If you are working in the Microsoft Windows environment, you are familiar with critical updates. As program errors are discovered, updates are generated and then provided for download and installation. It is a never-ending process.

The same is true with every operating system. For the Linux operating system, updates are regularly made available in the form of packages. Most Linux operating system distributors have a Web site that lists the updates available for their version and provides the packages for download. For example, on Red Hat Linux, the errata page provides updates at http://www.redhat.com/apps/support/erratal. A similar Web link is available for almost every Linux distribution.

Some Linux distributions even provide automatic updates similar to those from Microsoft Corporation. Red Hat Linux, for example, provides updates through the Red Hat Network. The Red Hat Network requires a System Profile, containing hardware and software information about the system you want to update. The Red Hat Update Agent software then determines whether any errata updates are available and then downloads and applies them.

Be careful where you get updates. One method that individuals use to exploit computer systems is to provide an update package with the same version number as the actual package, but with exploits built-in. After these packages are installed the affected system is completely controlled by the unauthorized user. Often, this type of exploit goes undetected.

Always download updates from a secure, trusted Web site or from a CD provided by the Linux distributor. A secure, trusted Web site is achieved through asymmetric encryption and other technologies.

# ## Asymmetric Encryption

Asymmetric encryption is often referred to as public-key encryption. Asymmetric encryption provides two encryption keys—public and private—that are different but complementary. The private key is assigned to a specific individual or computer system, and the public key is used by everyone else. The algorithm for public/private keys is complicated, but the result is the generation of two very large random numbers. One number becomes the private key; the other, the public key.

Two common public-key algorithms are the Rivest-Shamir-Adleman (RSA) algorithm and the El Gamal algorithm. Public-key encryption algorithms are rarely used for data confidentiality because of their performance constraints. Instead, public-key encryption algorithms are typically used in applications that involve authentication using digital signatures and key management. In other words, the public key system is used to ensure that the information received is from the source it says it is from.
