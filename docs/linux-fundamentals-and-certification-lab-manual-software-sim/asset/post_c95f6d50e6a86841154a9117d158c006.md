
- Collect as much information as possible by speaking with users and testing the system. Testing may be just basic functionality testing. Log in to the server and look at file systems, logs, and processes. Often a pattern characterizing the problem will emerge.
Before you get too involved with troubleshooting a problem, try the following.

- Scan for viruses. Computer viruses can cause some strange problems. You should always make sure your virus scanning software is up-to-date with the latest virus signatures. Virus scans should be run often. Several virus scanning software packages are available for Linux. One free package is F-Pro (www.f-prot.com).
- Read the documentation. The documentation often has a troubleshooting section that may have just what you need to correct a problem.
- Roll back any recent changes. You may have made a change to the system that you think is unrelated to your problem. If your problem started after this change, it could be coincidence; but chances are the change is the cause.

# COLLECTING INFORMATION

System information should be collected at all times, even if no problems exist. This is simply monitoring your system. Collecting the information and analyzing it will help you see trends in performance and establish a baseline of how the system is running. The baseline information is used to determine how the system is performing with a heavier workload due to more users, additional programs, or a change in services. Many sources for collecting information are available on a Linux operating system.

# Using Log Files to Identify Problems

Log files in the Linux operating system contain a wide range of information, including information and errors for the kernel, applications, and users. Most logs are maintained in the /var/log directory. The most important logs are /var/log/messages and /var/log/secure. Most messages and the files to which they are sent are controlled by the /etc/syslog.conf file (Figure 13–1). This file specifies rules for logging. Each rule consists of two fields—selector and action.

![](img/37f079cee226b270f2e09b37a2e4a05d_357_0.png)

```
# root@5: /etc
# Log anything (except mail) of level info or higher.
# Don't log private authentication messages!
*.info;mail.none;authpriv.none;cron.none /var/log/messages

# The authpriv file has restricted access.
authpriv.* /var/log/secure

# Log all the mail messages in one place.
mail.* /var/log/maillog

# Log cron stuff
cron.* /var/log/cron

# Everybody gets emergency messages
*.emerg *

# Save news errors of level crit or higher in a special file.
ucp,news.crit /var/log/spooler

# Save boot messages also to boot.log
local7.* /var/log/boot.log
```

The selector field has two parts—facility and priority. The facility is where the message is coming from. Priority is the severity of the message. Available values for facility are auth, authpriv, cron, daemon, kern, lpr, mail, mark, news, security, syslog, user, uucp, and local0 through local7. Priority values are debug, info, notice, warning, warn, err, error, crit, emerg, and panic. An asterisk (*) can be used to represent all facilities or priorities. Separating a list of selector values with semicolons indicates that all values apply. For example, **info** means all messages with info severity will be sent, **\*.info;mail.none** means that all messages with info severity will be sent except for mail messages. Any message of the priority indicated or higher is recorded to the action location.

The action field of a rule specifies the location where the message will be sent. The action field can be a real file, a named pipe, a terminal or console, a remote machine, a list of users, or all users. Sending messages to a remote user or machine will ensure that messages survive if there is a severe hardware failure.

## messages Log File

Messages from the /var/log/messages file contain most information about the Linux operating system. Information gathered from this file can be used to monitor system loads, to check that the system services are running properly, and to record any errors that occur.

System load is the normal level of processes, logins, file transfers, and other values that the Linux operating system provides on average each time period. Peak values should be expected and accounted for. If the system is reaching the maximum load more and more often, this may indicate that the system resources need to be increased. The first symptom of a system load increase is usually a decrease in performance, meaning that the system runs slower.

Error messages are one of the most direct indicators of a problem. An error message will point out a problem, but not always the problem’s source. For example, an error message that the sendmail process has stopped may indicate a sendmail problem, or it may indicate a system resource failure. Other messages will usually clarify the source of the error.

Intrusion detection can often be detected by the contents of the log files. A cracker may gain access to your system and change configuration files and logging levels, or even delete entries in the log files.

## secure Log File

Messages from the secure log file are often used to detect unauthorized access attempts. A large list of rejected login attempts means that someone is trying to mount a brute force attack on your system. Login attempts to several services may indicate an attack as well. For example, if the same user attempts to gain access through sshd, telnet, ftp, and other services within seconds of each other, this may indicate an unauthorized user trying to gain access.

As with any log file, a cracker may try to cover up unauthorized access by deleting the file or removing entries from the file. Unless you check the logs often, these alterations will probably go undetected.

# System Status Tools

Several utilities can help in troubleshooting problems. Status tools will indicate the current status of a system, but not whether there is a problem. However, the information they provide can be used to compare to past data to determine if there is a problem.

- **ifconfig**
ifconfig is used to configure or display network interfaces. Using ifconfig with no parameters or options will display information about all active network interfaces. This information includes the IP address, subnet mask, packets sent and received, MAC address, and other information. An invalid IP address could keep network connections from working properly. Packets that have been transmitted but have not returned indicate a network error.

```

 RX packets:20911318 errors:0 dropped:0 overruns:0 frame:0
 TX packets:42990305 errors:0 dropped:0 overruns:0 carrier:0 collisions:0
txqueuelen:100
 RX bytes:2086593897 (1989.9 b) TX bytes:2818666890 (2688.0 b)
 Interrupt:19 Base address:0xfee0 Memory:fe701000-fe701038
```

- **df**
This command will tell you how much disk space is available on all of your file systems. Files, especially log files, can grow in size until all available disk space is used. If this happens your system may fail. Some computer viruses will write information to the disk until all disk space is used. The df command should be run often to track the amount of disk space used.


- **lpq**
This utility shows the current print queue status. The current print jobs are displayed. A job displayed, but not printing, could indicate that the printer cannot be found or is offline.

```

```
