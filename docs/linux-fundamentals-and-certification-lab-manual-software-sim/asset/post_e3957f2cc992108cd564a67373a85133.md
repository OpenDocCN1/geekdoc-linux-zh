
## CONFIGURING NFS

Network File System (NFS) was developed by Sun Microsystems as a standard for sharing files over a network. This service allows you to integrate a file system into a remote system, where it is used seamlessly with other local file systems.

NFS is a security hole that needs to be carefully configured. The term *security hole* means that there is a chance that unauthorized users can use the information shared.

The following section outlines how to configure the server side of an NFS share. Before configuring NFS, make sure your firewall will allow NFS traffic. Use the client procedure from Chapter 7 after the NFS server is started.

### NFS Server Configuration Files

There are three main configuration files for NFS—/etc/exports, /etc/hosts.allow, and /etc/hosts.deny. A fourth file, /etc/hosts (described in Chapter 7), allows including entries that are used instead of first making a DNS lookup.

**/etc/exports**
This file contains a list of entries that describe local file systems, which remote computer(s) may share them, and the access permissions. Each line contains an export point, a list of clients separated by spaces, and a comma-separated, parenthesized list of export options. Use the `man exports` command to see a more complete list of the configuration file. An entry in /etc/exports would contain the following fields:

```
export_point client1(option, ...) client2(option, ...)
```

- **export_point** is the directory to be shared. This could be an entire disk drive, or a directory within it.
- **client1** is the remote computer name. This gives access to a specific computer or group of computers. It can be expressed as a DNS name, a /etc/hosts name, or an IP address.

Remote clients can be expressed with wildcards. Sharing a directory with many remote clients can be time consuming. Using wildcards lets you express a group of commonly named machines. For example, if you wanted to share with all the computers in the linuxplus.com domain, you could use `*.linuxplus.com` as the client name. This would enable all machines in the domain to access the share.

The remote clients can be expressed as IP (sub)network(s). For example, to allow all hosts on the 192.168.0.0 network, use `192.168.0.0/255.255.255.0` as the client host entry.

- **option** is one of a list of options, including `rw`, `async`, and others. The default option is `ro`, which means read only, so does not allow any writes to the shared directory.
  - **ro** The directory is available for read only. No writing is allowed to the share.
  - **rw** The directory is available for read and write.
  - **async** This option allows the NFS server to reply to a request before any changes made by the request have been committed to storage. For example, if a remote client copies a file to a share, the NFS server will respond that the copy has occurred, even though the process is not complete. This option improves server response time with the client, but if the server fails before writing the data, the file system can be corrupted.

For example, if you wanted to share the root directory (/) with a remote system called client1 at IP address 192.168.0.25 with read and write privileges, you would use the following line:

```
/ 192.168.0.25(rw)
```

Directories listed in the /etc/exports file will share all their subdirectories if they are on the same file system.

**/etc/hosts.allow and /etc/hosts.deny**
These files specify which computers on the network are allowed or denied access to services on the server. Each line of these files is an access control list entry. In its simplest form, each file has a list of machine names. Not having /etc/hosts.allow or /etc/hosts.deny opens access to any machine. The files are read in the following order:

- /etc/hosts.allow is read first to see if the machine making the request is on the list. If it is, access is allowed.
- /etc/hosts.deny is checked next to see if the remote machine is on the list. If it is, access is denied.
- If the machine is on neither list, access is allowed.

A more complex form of the files allows the control of access to services handled by the `xinetd` (or `inetd`) program. In this case, restriction is done for each service. Use the commands `man host.allow` and `man host_options` for more information.

### Starting NFS Services

After NFS is configured, you are ready to start the services. Before starting the services, make sure the NFS package is installed. Usually, this just means you have a relatively updated kernel.

TCP/IP networking should be running and you should confirm that you can *see* all machines involved. “Seeing” a machine just means that you can ping the machines. From the command line, type the command `ping IP_Address` of a machine whose connectivity you want to check. *IP_Address* is the IP address of the remote machine. Ping will contact the remote machine, which will respond with an echo, indicating the machine is alive and responding to requests.

**Starting the Portmapper**
The portmapper is a service that converts Remote Procedure Calls (RPC) program numbers into DARPA protocol port numbers. In other words, the RPC is assigned the well-known port numbers for the services involved.

When an RPC server is started, it tells portmap what port number it is listening to, and what RPC program numbers it is prepared to serve. A client can contact portmap on a remote machine to determine which port number the RPC packets should be sent to.

To start the portmap service, use the following command:

```
service portmap start
```

To stop the portmap service:

```
service portmap stop
```

To restart the portmap service:

```
service portmap restart
```

To check the status of the portmap service:

```
service portmap status
```

**NFS Daemons**
The NFS service is comprised of five daemons. A daemon, pronounced DA-y-mun, is a process that runs in the background and performs specific tasks. This term was used in Unix systems and comes from Greek mythology, where daemons were guardian spirits.

- **rpc.nfsd** This program implements the user level part of the NFS service. This program starts the threads used by the RPC process. The number of threads started is one by default. The number of threads actually needed by NFS depends on the workload created by NFS clients. A suggested starting point for threads is eight. The `nfsstat` program can be used to display statistics about NFS client and server activity.
- **rpc.lockd** This program starts the NFS lock manager on kernels that don’t start it automatically.
- **rpc.statd** This program implements the NSM (Network Status Monitor), which implements a reboot notification service. It is used by rpc.lockd to implement lock recovery when the NFS server crashes and reboots.
- **rpc.mountd** When rpc.mountd receives a mount request from a NFS client, it checks the request against the list of exported file systems. If the client is one of the permitted clients, it obtains a file handle; otherwise, the request is denied.
- **rpc.rquotad** This file handles user file quotas on exported volumes.

As with the portmap service, you can use start, stop, restart, and status with the `service` command. To start NFS, use the `service nfs start` command.

### Verifying NFS

You can verify that the NFS daemons are running by using the `rpcinfo` command. This command makes an RPC call to the RPC server and reports what it finds. For a complete list of options, use the `man rpcinfo` command. To print a list of all registered RPC programs, use the `-p` option (Figure 8-9).

```
rpcinfo -p
```

### Changes to /etc/exports

Adding and removing directories to be shared and changing which users have permission to use them are common administrative tasks. Changes to the /etc/exports file may not be implemented immediately. To force nfsd to reread the /etc/exports file, use the `exportfs -ra` command.

## CONFIGURING SAMBA

![](img/37f079cee226b270f2e09b37a2e4a05d_234_1.png)

Samba is the Linux answer to Windows NT server. Windows uses the SMB protocol to share resources between computers on a network. Linux provides the SMB protocol with Samba, a suite of programs that provide the same functionality as a Windows NT server.

Configuring Samba is a straightforward process. It requires configuring the /etc/samba/smb.conf file (which may be in a different location, depending on the Linux distribution), adding users to access the share, making sure that the server and clients can find each other on the network, and starting the services. The following sections explain the files and processes needed to make a Linux server act as a Windows file server.

Samba shares are designed to emulate Windows shares. The Windows servers that provide access to the shares use Windows Internet Naming Service (WINS). WINS is similar to DNS in that it determines the IP address associated with a computer name. WINS uses NETBEUI as its protocol. To introduce a Linux Samba share, the WINS network server must know the Linux machine’s name. A Linux Samba server can provide the WINS service for the network.
