## PATCHING THE KERNEL

Patching the kernel is not really a troubleshooting exercise, but it may prevent you from having to troubleshoot the system. Patching the kernel requires updating the source files and then recompiling the kernel.

Linux kernel version numbers consist of three numbers separated by periods. The first number is the major version number, the second is the minor revision number, and the third is the patch level version. Stable releases of the Linux kernel are identified by an even number as the second number of the release. Development releases are identified by an odd number as the second number of the release. For example, the current stable release is 2.4.22 (the second number 4 is even), and the current development release is 2.5.75.

Kernel patches are released to offer new functionality and to address security issues. New functionality could include new drivers for recently released devices. Security patches are released when a program exploit is detected. Patches are not immediately available; they can often take weeks (or longer) before being available.

Updating the kernel does not always go smoothly. Before actually applying the newly compiled kernel, you should make a backup of the system.

## Finding Kernel Patches

Patching an existing kernel allows you to retain your configuration from previous kernel compilations. Patching a kernel is a good choice if you are patching to the next consecutive level. For example, if you are currently using version 2.4.20 and want to go to 2.4.21, a patch is a good choice. However, if you are using version 2.4.3 and want to go to 2.4.21, you would be better off downloading the 2.4.21 kernel because patching would require applying each patch from 2.4.3 to 2.4.21.

Kernel versions and kernel patch versions can be found in several places on the Internet. One of the most popular sites is the Linux Kernel Archives at www.kernel.org or ftp.kernel.org. This FTP site has almost every Linux kernel ever created. You can download the current patch version, current stable version, current development version, and current test version of Linux. From this site, download the current patch for your Linux update. For purposes of discussion, the patch downloaded will be patch-2.4.21.bz2.

To apply the patch, do the following:

- Move the downloaded patch to the `/usr/src/linux` directory.

![](img/37f079cee226b270f2e09b37a2e4a05d_384_0.png)

The linux directory is usually a symbolic link to the source directory. For example, if you are using linux 2.4.20 as your working version, /usr/src/linux would point to /usr/src/linux-2.4.21. To make a symbolic link, use the ln command. To create the symbolic link here, use the `ln -s /usr/src/linux-2.4.21 /usr/src/linux` command.

- Change to the /usr/src/linux directory.
- Uncompress the file. If you downloaded the patch with the `.bz2` extension, use the `bunzip2 patch-2.4.21` command. If you downloaded the patch with the `.gz` extension, use the `gunzip patch-2.4.21` command.
- The file `patch-2.4.21` should be in the directory. To apply the patch to the kernel source tree, use the `patch -p1 < patch-2.4.21` command.

## Configuring the Kernel

Configuring the kernel is your chance to customize the modules that are available for your system. You configure the kernel by using a menu-driven utility to pick the modules you want to include with your kernel. For example, you can select sound modules, video modules, ISDN modules, and others. The menu can be displayed from the CLI or from the GUI. From the `/usr/src/linux` directory, execute the `make menuconfig` command for the CLI menu interface.

The kernel configuration menu is displayed (Figure 13-11). To select a menu item, use the up and down arrow keys to highlight the selection and then press Enter. Use the space bar to enable or disable an item. Use the left and right arrow keys to choose Select, Exit, or Help. The instructions are onscreen.

## Compiling the Kernel

After you have configured the kernel it is time to compile it. Several steps are involved. You must identify kernel dependencies, compile the kernel, compile the modules that the kernel will need, move the modules to the correct directory, move the kernel to the correct directory on the system, and, finally, modify your boot loader to recognize the new kernel.

**make** The make utility is a group of shell scripts that evaluate a set of dependencies, and then execute commands. make is one of the original Unix tools for software development. Other tools for software development include language compilers and shell programming tools.

Invoking make usually involves typing `make` and waiting for the command to finish. Sometimes, however, the process is a little more involved.

Usually, make looks for a file called Makefile. Makefile has instructions for a specific project and describes the relationships among files in your program. Typically, the executable file is updated from object files, which in turn are made by compiling source files. Most source programs you will download will have a Makefile provided.

The make program uses the Makefile database and the last-modification times of the files to decide which files need to be updated. For each of those files it issues the commands recorded in the database.

**Makefile** The Makefile has instructions for the project to be compiled and installed on the operating system. Makefile is composed of the following components: comments, dependency lines, rules, and shell lines.

![](img/37f079cee226b270f2e09b37a2e4a05d_386_0.png)

- **Comments** These are the simplest Makefile statements. A # sign indicates that any text following it is user comments and is not to be read by the compiler.
- **Rules** A rule tells the make utility when and how to make a file. The syntax of a rule is as follows:

```
target : prerequisite
    command
```

*   *target* is usually the name of a file that is generated by a program. This is most often an executable or an object file. The target can also be the name of an action.
*   *prerequisite* is a file that is used as input to create the target.
*   *command* is an action that make carries out. This can consist of several commands. Each command is typed on a different line.

The rule `main.obj : main.c bcc -ms -c main.c` says to compile main.c with the bcc compiler.

Dependency lines Determine when the target is to be rebuilt. The dependency line `myfile.exe : main.obj io.obj` indicates that myfile.exe depends on main.obj and io.obj to compile. At run time make compares the time at which myfile.exe was last changed and the times at which main.obj and io.obj were last changed. If myfile.exe is older, it is compiled.

Shell lines Shell lines are typically indented lines following a dependency line.

The rule

```
main.obj : main.c
    bcc -ms -c main.c
```

contains the shell line `bcc -ms -c main.c` to compile main.c source code.

The following Makefile example generates the executable `myfile` from the C files `main.c`, `files.c`, and `utils.c`.

```
# myfile is the executable to be created.
myfile : main.o files.o utils.o
    cc -o edit main.o files.o utils.o

main.o : main.c defs.h
    cc -c main.c

files.o : files.c defs.h buffer.h command.h
    cc -c files.c

utils.o : utils.c defs.h
    cc -c utils.c

clean :
    rm edit main.o kbd.o command.o display.o \
        insert.o search.o files.o utils.o
```

The executable is `myfile`, which will be created from the prerequisite object files `main.o`, `files.o`, and `utils.o`. The object files are created from the prerequisite C programs using header files, such as defs.h. The target `clean` is not a file, but the name of an action. It will be used to remove the files that were created so the files can be recompiled. The clean target does not have a prerequisite, only a command.

The make command has more options and features than can be discussed here. Use the `man make` command for more information.

Execute the following commands in sequence from the /usr/src/linux directory.

1. `make dep` This identifies kernel dependencies to be resolved at compile time.
2. `make clean` This removes any old object files from previous builds.
3. `make zImage` This compiles the kernel. If you get a message about the system being too big, try using bzImage instead of zImage. Compiling can take several minutes.
4. `make modules` This compiles all the modules the kernel may need. These are the loadable modules that will be loaded by the kernel when needed.
5. `make modules_install` This moves the module object files to the correct directories.
6. `make install` This moves the kernel and its associated files to the correct directories. This command will also modify the `/etc/lilo.conf` file.
7. `/sbin/lilo` This will update the system to use the new `/etc/lilo.conf` file.
8. `REBOOT` You are done. The system should restart with no problems. If it doesn't, however, you may have to restore your system from backup.

If everything completed with no errors, you have a newly updated kernel. If things didn't go so well, the next section identifies other troubleshooting sources that you can use.
