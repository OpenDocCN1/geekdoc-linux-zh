- **Make sure that any static charge you have is dissipated.** Use a wrist strap and make sure it is grounded properly. Always touch the metal on the power supply to bleed off any residual charge.
- **Never force a connection.** Many of the connectors on a computer are designed as a group of small metal pins. These pins are very easy to bend or break, often without realizing it.
- **Never disconnect a cable by pulling the wire.** Most computer connectors are delicate and will separate easily. Pulling the wires can separate them from the connector.
- **Label everything.** Until you feel proficient in computer repair, label everything. Connectors are usually keyed to allow connections in only the proper direction, but a determined individual can force them to connect anyway. Hard cables in a computer system look the same. Labeling will save you time later on.
- **Read the manual.** Most systems have a service manual available. Read the directions and follow them.

### Hard Drive Problems

On most Linux systems the hard disk will generally run flawlessly beyond its rated life. However, errors can always occur. The fsck program will take care of most problems. If a catastrophic failure occurs with the hard drive, the hard drive should be replaced and the data restored from backup. Replacing a hard drive is the same procedure as installing a second hard drive, covered in Chapter 2.

**EIDE/ATA Hard Drive Problems**

Most personal computers use EIDE/ATA hard drives. After a hard drive is installed and functioning, the major problem encountered is a performance problem. If you have a new system that is designed to work with the Linux operating system, your hard drive may be optimized for the system. However, not all systems are designed for Linux and not all Linux distributions are optimized for all hard drives. Moreover, Linux distributors usually opt for stability over performance, so the hard disk may not be performing near its optimum performance.

The Linux operating system provides the `hdparm` tool to both test and to improve the performance of hard drives; however, **`hdparm` can cause unexpected data corruption. Use it at your own risk.** Make sure you back up your system before attempting any hard disk changes. The syntax of the `hdparm` command is `hdparm [flags] [device]`, where device is a hard drive device name, such as /dev/hda, and flags are from zero to many options. Some of the most common include:

- **no flags**: If no flags are given, the -acdgmrrrw flags are assumed. Running the `hdparm` command with no flags shows that the hard drive is set to safe values. These values help ensure that the Linux operating system runs with the widest range of hard drives.

```bash
# hdparm /dev/hda

/dev/hda:
    multcount    = 16 (on)
    IO_support   = 0 (default 16-bit)
    unmaskirq    = 0 (off)
    using_dma    = 0 (off)
    keepsettings = 0 (off)
    readonly     = 0 (off)
    readahead    = 8 (on)
    geometry     = 1310/240/63, sectors=19807200, start=0
```

- **-T**: This flag tells `hdparm` to perform timings of cache reads for benchmark and comparison purposes. This command should be run several times on a machine that is basically at rest, running only necessary processes. This flag displays the speed of reading directly from the Linux buffer cache without disk access, which measures the throughput of the processor, cache, and memory of the system. Including the `-t` flag will provide a correction factor based on the outcome of `-T` in the final result.

- **-t**: This flag directs `hdparm` to perform timings of device reads for benchmark and comparison. This command also should be run several times on a system at rest. This displays the speed of reading through the buffer cache to the disk without any prior caching of data. This is a measurement of how fast the drive can sustain sequential data reads.

```bash
# hdparm -Tt /dev/hda

/dev/hda:
Timing buffer-cache reads: 128 MB in 1.43 seconds = 89.51 MB/sec
Timing buffered disk reads: 64 MB in 14.12 seconds = 4.53 MB/sec
```

- **-i**: This flag causes `hdparm` to display identification information from the hard drive that is obtained at boot time.

```bash
# hdparm -i /dev/hda

/dev/hda:
Model=WDC AC310100B, FwRev=32.02S32, SerialNo=WD-WTE6390094409
Config={ HardSect NotMFPM HDSw<15uSec SpinMotCtl Fixed DTR>5Mbs FmtGapReq }
RawCHS=16383/16/63, TrkSize=57600, SectSize=600, ECCbytes=22
BuffType=DualPortCache, BuffSize=512kB, MaxMultSect=16, MultSect=16
CurCHS=16383/15/63, CurSects=19807200, LBA=yes, LBAsects=19807200
PIO modes: pio0 pio1 pio2 pio3 pio4
DMA modes: mdma0 mdma1 mdma2
UDMA modes: udma0 udma1 *udma2
AdvancedPM=no WriteCache=enabled
Drive conforms to: device does not report version: 1 2 3 4
```

The output of the `hdparm -i` command shows information about the hard drive. It says that DMA is supported and that udma2 is the default.

- **-X `<value>`**: This flag is used to set the IDE transfer mode and is typically combined with the `-d1` flag, enabling Direct Memory Access (DMA). DMA is a technique for transferring data from main memory to a device without passing it through the CPU. (Computers with DMA channels can transfer data to and from devices much more quickly than computers without a DMA channel.) For multivord DMA, the value used is the desired DMA mode number plus 32, and for UDMA the value is the UltraDMA plus 64.

The result of the `hdparm /dev/hda` command showed that the DMA is off. To turn on DMA2, use the `hdparm -d1 -X34 /dev/hda` command. The `-d1` flag says to enable DMA. The `-X34` flag says to use DMA2. The following code shows the timings of /dev/hda with DMA disabled, sets DMA2, and shows the resulting timings.

```bash
# hdparm -Tt /dev/hda

/dev/hda:
Timing buffer-cache reads: 128 MB in 1.42 seconds = 90.14 MB/sec
Timing buffered disk reads: 64 MB in 14.10 seconds = 4.54 MB/sec
# hdparm -d1 -X34 /dev/hda

/dev/hda:
setting using_dma to 1 (on)
setting xfermode to 34 (multiword DMA mode2)
using_dma=1 (on)
# hdparm -Tt /dev/hda

/dev/hda:
Timing buffer-cache reads: 128 MB in 1.41 seconds=90.78 MB/sec
Timing buffered disk reads: 64 MB in 5.08 seconds=12.60 MB/sec
```

Significant performance improvement can be seen with the above options. There are others that may improve performance with you. Use the `man hdparm` command to view all available options.

### SCSI Hard Drive Problems

SCSI hard drives have changed over the years, as has most technology. The first hard drives, called SCSI 1 or Narrow SCSI, used a 50-pin connector that ran at a maximum data rate of 5 MHz. To increase the bandwidth, the bus speed was increased to 10 MHz, creating the new standard SCSI 1 or Fast SCSI. The current SCSI technology under development is called ULTRA 320 and provides for bus speeds of 320 MHz, or up to 320 MB/s data transfer. Table 13-1 shows a partial list of bus speeds and SCSI terminology, as endorsed by the SCSI Trade Association (STA).

**Table 13-1: Bus speeds and SCSI terminology**

| STA Terminology | Bus Speed, MB/s | Maximum Devices Supported |
| :--- | :--- | :--- |
| SCSI 1 | 5 | 8 |
| Fast SCSI | 10 | 8 |
| Fast Wide SCSI | 20 | 16 |
| Ultra SCSI | 20 | 16 |
| Wide Ultra SCSI | 40 | 16 |
| Ultra2 SCSI | 40 | 8 |
| Wide Ultra2 SCSI | 80 | 16 |
| Ultra 160 SCSI | 160 | 16 |
| Ultra 320 | 320 | 16 |

Changes in SCSI technology make changes necessary in the requirements for cabling and termination. For example, the faster the bus speed, the shorter the cable connecting the devices must be.

The `hdparm` command can be used to test performance, but it cannot be used to change the parameters of the hard drive. Usually, problems encountered with SCSI devices can be traced to hardware issues.

Often a SCSI controller has firmware that is accessible by the user during the boot process, which may help troubleshoot SCSI device problems.

**Proper termination** is essential to SCSI hard drive function. A pulse propagating along the SCSI bus will reflect from any part of the bus that is different from the rest. These reflections add and subtract in odd combinations and cause the original pulse to be distorted and corrupted. To prevent or minimize reflections from the ends of the bus, terminators are added to absorb the energy from the pulses.

Terminators must be present at two positions on the SCSI bus, at the beginning and the end of the bus, and must occur within four inches of the physical ends of the SCSI bus. Termination can be internal or external.

**Internal termination**: SCSI drives provide termination within the workings of the drive and can be enabled/disabled with jumper settings.

**External termination**: is done with inline, or feed-through, terminators. These are close-ended terminator plugs connected to the end of the bus.
