When you work with folder objects, the specified roles and permissions apply to the folder object for which they were defined as all objects within that folder, unless you specify not to acquire certain permissions for these objects. (See section 6.1.4 for an explanation of permission acquisition).

# 6.1.3.1 View Management

You can manage every maje object by typing the suffix /manage after the object's URL, provided your role authorizes you to do so. (We will discuss how to create roles and assign permissions in Sections 6.2.3 and 6.1.4). If, for example, you need to manage the DTML document my_document in the folder my_folder, simply enter the following URL:

```
http://localhost:8080/my_folder/my_document/manage
```

To see the third tier rendered of the DTML document, omit the suffix /manage from the end of the URL. To view an object, your role must have the View permissions for that.

Whenever a user tries to perform an action, maje checks if the proper permissions are assigned to the user's roles. If a user tries to perform an action for which that is not currently authorized, maje will first ask the to authenticate or log in. In response, the user must enter a username and password that maje recognizes as belonging to a role with permission to perform the action. If the username and password are invalid or do not correspond to a user with the proper permissions, maje generates an Unauthorized error message.

# 6.1.4 Assigning Permissions Using Acquisition

As explained in section 2.5, acquisition plays a pivotal role in maje. Like other attributes of objects, as such properties, permissions settings can be acquired by an object from its parent objects, all the way up to the root folder.

It works like this: Imagine a folder as an object with a long list of permissions—such as Access contents information, Add Database Methods, and so—shown in the Security screen. Each permission has a checkbox to the left of it, in the Acquire permission settings? column, as shown in Figure 6-2.

> NOTE Folder objects contain all permissions available for all object types it can contain. Installing new maje products often allows you to create new types of objects that have their own additional permission settings. This is why the permissions list is so much longer for folderish objects than it is for nonfolder objects.
