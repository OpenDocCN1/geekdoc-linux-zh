# 15.2.1 Bootstrapping the Product

We need a mechanism that will provide us with an instance of the product—something that will actually create an instance for us. This mechanism must be included in our product so that the Zope manager can create an instance using the Zope management screen.

Constructors coded in Python by Zope can also be used elsewhere in our product (see section 15.4 for more information on the main constructor method of the Website product).

Among other things, registering these methods causes the product to appear in the add menu of folder objects, with a name that is the metype we assign to our product's class. Our example will be users choose the metype "Website".

The product also provides a form that users complete when the product's metype from the add menu. When this is submitted, the appropriate constructor method is called to create the product instance in the Zope folder.

To accomplish these operations, your product will include not only Python code and modules, but also DTML files for the forms, management, and user interface of your product, as well as additional files such as images, data, and configuration files. These ancillary files are often exposed to Zope via wrapper classes that, for example, can convert a DTML text file into a DTML method object (see section 15.4.3 for details).

With all objects in Zope (and Python object-oriented languages as a whole), a product is based on one or more classes that ensure that essential elements are "inherited" by each instance of the product. This class defines, among other things, the methods each instance of the product requires to perform its functions. The methods in our sample product are addUserUser() and deleteWebsiteUser().

For a product to create instances within Zope, a class must be assigned to it and associated with the appropriate methods and other elements, such as icons. In our example product, we also call this class "website" (see section 15.4.2.3, "Class Definitions").

# 15.2.2 Necessary Components

To working a product, we must create the following components:

+   - A subdirectory in lib/python/Products to contain the product's files. When you start the Zope server, it will search the Products directory and register all it finds, including new or changed ones (See section 15.4.1).

+   - The product directory must contain an __init__.py file, which Zope executes at startup to initialize and register the product. If you create Python modules in additional subdirectories inside your product, each subdirectory must also have an __init__.py file (See section 15.4.5.1 for more information.)
