manageLocalRoles(userid, ['role1', 'role2', ...])
This method takes a userid as an argument and a list of roles. If the method is called using inappropriate arguments, the userid (if it exists) is created with the relevant role as a local role. You can do the same thing using the method setLocalRoles(userid, 'role1', 'role2', ...).

# manage_defined_roles(submit, REQUEST)

With this method you can add or delete roles using 'Add role' or 'Delete role' for submit. To use this method, first specify a role, such as Role2, in the REQUEST under the variable roler.

```
<xml-call expr="REQUEST.set('role', 'Role2')">
```

Once you have specified a role you can call the method manage_defined_roles in both forms:

```
<xml-call expr="manage_defined_roles('Add role', REQUEST)'>
```

or

```
<xml-call expr="manage_defined_roles('Delete role', REQUEST)">
```

# manage_delete_LocalRoles(userids, REQUEST)

This method allows you to delete local roles you have set. It requires a list of users (userids) and REQUEST as arguments.

# permission_settings()

This method returns all permissions for an object in the form of a list of dictionaries. Each element has the following form:

```
{
  'acquire': 'CHECKED',
  'roles': [ {'name': 'por0', 'checked': ''},\n    {'name': 'p01', 'checked': ''},\n    {'name': 'p02', 'checked': 'CHECKED'},
    {'name': 'p03', 'checked': ''} ],\n\n  'name': 'Access contents information'
}
```

**acquire** 'CHECKED' If Acquire permission settings? is octiv for the relevant permission, otherwise on empty string is returned.

**roles** Contains list of dictionaries as a value. The value for 'name' is a combination of letters and numbers (porb). 'p00', for example, indicates the zero permission (p=permission) of the zero role (r=role). (Zero is used because Python starts counting from zero.) If the value of 'checked' is 'CHECKED', the role hos this permission.
