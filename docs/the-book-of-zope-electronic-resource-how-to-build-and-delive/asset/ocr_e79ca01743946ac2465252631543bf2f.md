# Listing 10-9: The DTML method DeleteConfirm_html

```
1: <html-var standard_html_header>
2: <H2>Really Delete Book &em&quot;
3: <html-var expr="REQUEST.id"&quot;&lt;/em&gt;&lt;/h2>
4: <form action="Delete_html">
5: <input type=hidden name="id" value="html-var expr="REQUEST.id">">
6: <input type=submit name="delete" value="Delete">
7: &nbsp;&nbsp;
8: <input type=submit name="cancel" value="Cancel">
9: </form>
10: <html-var standard_html_footer>
```

DeleteConfirm_html is a simple form with two buttons, Delete and Cancel. The id of the Book instance to be passed to the Delete_html action using a hidden field (Line 5). Delete_html passes this value to the appropriate Zope method to delete the instance.
Let's create the DTML method delete_html by entering the code shown in Listing 10-10:

# Listing 10-10: The DTML method Delete_html, which you can use to create books

```
1: <html-if name="delete">
2: <html-call expr="manage_delobjects(ids=[REQUEST.id])">
3: </html-if>
4: <html-call expr="RESPONSE.redirect('admin_html")">
```

Here again we first check for a name in our namespace. In this case, we check for delete (Line 1), which tells the method the user clicked in the DeleteConfirm_html. If so, the built-in method manage_delobjects is called on the current folder, passing an argument name ids (Line 3). The method expects a list of string values in its ids argument containing the ids of the objects to be deleted from the folder. We have one object to delete, the Book instance, so its id, passed from the form in REQUEST, is made into a list by placing square brackets around it and is passed as the value for ids. Finally, we redirect the user back to the admin_html page (Line 4), which will show that the Book instance was deleted.
