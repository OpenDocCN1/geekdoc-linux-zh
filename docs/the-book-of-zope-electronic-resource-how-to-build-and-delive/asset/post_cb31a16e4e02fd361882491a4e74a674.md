
## 2.5.1 Standard Objects

As you have noticed, the root directory contains a number of objects created upon installation of the Zope server. These standard objects ensure a consistent appearance for objects created using Zope, and because they are in the root directory, they can be called by all objects.

### 2.5.1.1 Standard HTML Header and Footer

For example, the standard objects define the header and footer in each text object and standard_html_footer define the inserted into every DTML method and document by default. The code in these files looks like that shown in Listings 2-1 and 2-2.

Listing 2-1: The standard header

```
`<HTML><HEAD><TITLE><html-var title_or_id></TITLE></HEAD><BODY BGCOLOR="FFFFFF">`
```

Listing 2-2: The standard footer

```
<p>
<dt-var ZopeAttributeButton
</p>
</BODY></HTML>
```

These objects define an HTML header and footer. Both can be called at the start and end of DTML methods and documents to embed them in a basic HTML structure; they are missing only the body of the HTML document.

### 2.5.1.2 index_html

The method index_html defines the welcome screen from which you access the Zope management screen, among other screens. It looks like this:

```
<dt-var standard_html_header>
<dt-var zope_quick_start>
<dt-var standard_html_footer>
```

> NOTE: To create a new "home page" on your Zope server, you can modify this method.

### 2.5.1.3 standard_error_message

The method standard_error_message is used to display Zope error messages in a uniform and consistent way. This can be modified to display error messages in any desired format.

### 2.5.1.4 Modifying Standard Objects

You can modify these standard objects to suit your own needs, but if you do, you must observe the acquisition mechanism. Remember that changing the contents of any methods in the root directory affects all objects that use that method.

To change only the appearance of specific objects, copy the applicable methods (see section 2.4.3), for example standard_html_header, to the folder at or above the objects you want to change, change the copied methods. Thus, only the objects in the folder containing the changed methods (or in folders below) will be affected by the modifications; all other objects will still use the original methods.

### 3.1.2 The Edit Tab and Edit Screen

You can edit nonfolder Zope objects on the Edit screen, including the title and source text of DTML.

To open an object's Edit screen, use the Edit tab. Figure 3-2 shows the object.

![](img/43a28cce5475b2f487bf455365567fb6_58_0.png)

You can edit the source text in the window using the following buttons:

- **Taller**: Lengthens the text window.
- **Shorter**: Shortens the text window.
- **Wider**: Widens the text window.
- **Narrower**: Narrows the text window.

The Save Changes button saves your changes. If there are no syntax errors in the code, your changes will be saved, and you will be returned to the Edit screen.

### 3.1.3 The View Tab

The View tab, available on any object that can be viewed through a browser, lets you preview any modifications you make to an object. When you click the View tab on a nonfolder object such as a DTML method, the edited object is displayed just as it would to a visitor to the web page.

When you click the View tab on the Contents screen of a folderish object, Zope attempts to display index_html. If index_html is not found in the current folder, Zope displays the next available index_html object, created by the acquisition rules. The acquisitions rules tell Zope to look in the parent folder if an object is not in the current one; if the object is not found there, to continue searching the upper folder. As a result, if the index_html is contained only in the Zope root folder, the View tab will show it in every folder.

### 3.1.4 The Ownership Tab

All Zope objects, with the exception of the Control Panel and the root folder, can be assigned to an owner using the Ownership tab. When you create an object, you can become its owner.

The Ownership screen tells whether an object has an owner and offers an opportunity to make ownership permissions for a user either explicit (set directly on the object) or implicit (based on the owner of the parent folder). For more information, see section 6.1.2.
