+   * You can place Zope and the database server on separate computers for enhanced performance and security.

+   * Programs other than Zope will be able to directly access data in the database.

+   * You can access and manipulate existing databases in your organization through Zope without "reinventing the wheel."

+   * You can more readily separate the data from the code in your application.

Consider the disadvantages of using an external database:

+   * Having a separate database is more complex and requires more planning, development time, and maintenance.

+   * Additional database software and/or hardware may be more costly.

+   * Hierarchical data models do not always map well onto relational databases, whereas they map directly to the ZODB.

+   * The storage and retrieval of large data quanta (such as file or image data) are often less efficient in a database than in the ZODB.

+   * You must be able to program and debug at both the database level and the Zope level.

+   * You lose the versioning and capabilities that you would have with data stored in the ZODB.

+   * You may need to create additional interfaces through Zope to administer your database.

For each application, you will need to weigh whether the ZODB or an external database is the right option. If you find that you need to use an external database system in your application, your first task will be to learn how to connect it to Zope.

# 12.2 RDBMS

Relational databases are the industry standard to store and retrieve large quantities of tabular data. These systems consist of server programs, which are database backends (or engines) that respond to commands from client programs, including Zope. These commands are given in the SQL language, an accepted standard database query language.
