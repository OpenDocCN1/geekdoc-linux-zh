allows you write code that uses variables without specifying its name directly inside the code. Instead, you specify the name outside the code as a property value, from the result of calling a function, or by passing the name when the code is executed. Thus you can modify the behavior of a piece of code without changing the code itself.

For example, there is a property in the namespace called "message" with the value thank_you_message, and a DTML method with the id thank_you_message in the namespace as well. You could insert this DTML method using the following code:

```
<dtml-var expr="[message]">
```

Notice there are no quotes around message, which tells Zone to use the value of the variable message and look it up in the namespace. In our example, the value is thank_you_message, so the DTML method with that name is found and rendered. If the value of the message variable is different the next time this DTML code is executed, it would insert different data from the object with the name corresponding to the new value. If the value of the message is not the name of any variable in the namespace, a Zone error will occur.

For a more complex example, say you wanted a page to present a different message depending on the day of the week. To do this, you could use the ZoneTime object's Day function and the underscore variable to insert the variable data corresponding to the current day of the week, as follows:

```
<dtml-var expr="[ZoneTime().Day()]">
```

ZoneTime.Day()’’ will return the string "Monday" or "Tuesday" or Wednesday and so on appropriate. Placing this function inside the brackets following the underscore variable (without quotes) will look up the variable data associated with the name of the current day returned. For this to work properly, you must also create the seven variables as properties or objects containing the message for each day.

> The namespace object always attempts to call or execute the object referenced if it can. This behavior is the same as the name="" syntax. However, if you want to access an object and not just the result of calling it, using the _getitem() function, described below.
