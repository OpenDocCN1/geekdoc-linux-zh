# 16.2.2 Defensive Coding

Large project is without errors in its first version, so you may well count on errors occurring from the outset and write your program to make debugging easier using these guidelines:

+   - Use informative names for variables, objects, objects, functions and comment your code so that you (and others) can understand it later. Be consistent in your naming conventions and coding style.
- Always write your code as if another person will be debugging it, even if that person will be you.
- Code your programs in the simplest and most straightforward way possible. Avoid clever tricks and shortcuts that merely save typing.
- Never write more than one instruction per line so that you can output your variable assignments in each line.
