
The ownership of an object is especially important for executable objects such as DTML Methods or documents. When an executable is rendered (executing its code), the permissions granted to its owner's roles are used to determine the permissions available to the executing code. If the owner does not have sufficient permissions (via their roles) to execute the code in the object, the code cannot be run by any user, even if the user viewing the object has permissions (via their roles) to execute the code. This prevents so-called "Trojan Horse" attacks, where a user with lesser security privileges writes harmful code that they cannot execute, and then deceives a user with greater privileges into executing it for them.

## Managing Users

The sections show how to create and manage users using the management screen and discuss how to create new roles.

Users are managed in Zone with User Folders (acl_users). However, you create only one User Folder per role, and you cannot copy a User Folder or cut and paste it into another folder (This is a security feature: if users could switch their access permissions to different areas in Zone, security would be undermined.) Users in a User Folder can log in anywhere at or below the folder where the User Folder lies in the hierarchy. ### 6.2.1 Creating Users

To create a new user in Folder A, first open the acl_users folder in Folder A. If Folder A does not contain an acl_users folder, create one by clicking the Add Objects menu for the Folder A and selecting User Folder.) When you click on acl_users, the Contents screen opens, where you can edit or create users. To create a new user you will need the following, as shown in Figure 6-9. (The Name, Password, Confirm, and Roles fields must be completed: Domains is optional).

- **Name**: The user's name (if you want that to be log in on). Usernames consist of one or more words separated by spaces and contain special characters. (Multiple spaces are reduced to just one space.) You cannot change a user's name once it has been created.
- **Password**: Enter the user's password for logging on.
- **Confirm**: Re-enter the password. If the password and confirmation do not match, click "OK" in the dialog box. You will be returned to the Management screen for the User, where you must recreate the user.
- **Roles**: Users must be assigned at least one role. To select multiple roles, hold down the CTRL button and click on the desired ones. The permissions available to the user are determined by adding all of the permissions granted to all of the roles assigned to that user. If a user has the Monager role, no other roles are generally needed because the Monager role is granted every available permission.
- **Domains**: This optional field lists the Internet domains that this user can log in from. contain any other IP addresses, subnets, or domain names separated by a space. Restricting the user can log in from helps prevent a malicious user from logging as Manager over the Internet, instance. If you leave this field blank, the user will be able to log in from anywhere.

### 6.2.2 Modifying a User

To delete a user, go to the User Folder and activate the checkbox in front of the name of each user, then click on the Delete button. To change the properties for an existing user, click on the relevant user to open a form like the one for creating a user. Use this form to change the user's password, domains, or role(s).

NOTE: You will notice that the number of characters in the password field may not match that user's actual password. This happens because, as a security feature, the actual password is not populated in the form.

### 6.2.3 Creating New Roles

If you want to assign roles other than the standard ones in Zope, you can create new roles in the Security screen of any folderish object. These new roles apply in the hierarchy from the point at which they were created; they will not be available to objects higher in the hierarchy. To define a role that applies throughout Zope, create it in the root folder.

To create a new role:

1. Enter the name of the new role in the Security screen's User defined roles input field (Figure 6-10).

NOTE: Roles are not assigned any permissions. After creating a role, you will need to assign its permissions on the appropriate objects.
