## 4.1.2 Variables

Zope regards nearly everything as objects, including methods, functions, documents, and so on. These objects can also act as variables.
A variable in the traditional sense consists of an indicator with a changeable value. For example, in the expression

```
x = a + b
```

The value of x depends on a and b. Zope variables act very much the same way. Like a and b in the expression above, the value of a Zope object depends on the time of day, which is automatically determined by the Zope system.

> NOTE
> ------------------------------------------------------------
> In the following discussion, all references to variables refer to Zope objects or attributes as such properties.

## 4.1.3 The DTML Namespace

A DTML namespace is an object that contains names. Each DTML object has a namespace containing all names available to the object and its associated data. A name, therefore, is the indicator by which a variable is referred to and that ultimately returns a value. The DTML namespace is dynamic, meaning its content may vary; names are defined at one time and disappear later. When a variable is accessed, it is referred to by its name in the namespace. Names are case sensitive, so be sure they are correctly capitalized in your DTML code.

Names come into the namespace of Zope's automatic process of acquisition (see section 2.5) or by explicitly adding them with certain DTML constructs (the "With the Tag" and "The let Tag," sections 4.3.8 and 4.3.9). This creates an aggregate of the available object and attribute names called the namespace stack by moving upward toward the object hierarchy and adding the objects and attributes found along the way. The object lowest in the hierarchy (usually the executing object or its parent) is topmost in the namespace stack. When a variable is accessed, the namespace is searched from the top down until its name is found or the entire stack is checked. ## 4.2 DTML Syntax

The DTML programming language is intended to be easy to learn, and if you are familiar with HTML, you should soon become proficient in it. Zope supports several types of DTML syntax, the most common of which is similar to HTML.
Like HTML, DTML tags are enclosed within angle brackets. The opening bracket is followed by dtml as `<dtml ...>`, and the space between the brackets contains the name.
DTML tags can have one, several, or no attributes. The value of an attribute (the value being optional) is enclosed within quotation marks after the equals sign. If the value assigned to an attribute does not contain spaces, tabs, line break, or double quotation marks, it need not be enclosed in quotation marks.

```
index_html
standard_header
standard_footer
```
Figure 4-5: The namespace stack of the hierarchy in Figure 4-4

> It is generally considered good practice to surround all attribute values with quotation marks in DTML unless you have a specific reason not to, because unquoted values are sometimes treated differently by certain DTML tags, such as dtml-let.

The resulting structure is

```
<dtml-tag name="Value" Attribute="value" ...>
```

For example, the following code displays in uppercase letters the name of the user accessing the document.

```
<dtml-var name="AUTHENTICATED_USER" capitalize>
```

In this example, the first attribute, called name, is assigned the variable AUTHENTICATED_USER as its value. The second attribute, capitalize (which is responsible for displaying the username with its first letter capitalized), requires no value assigned to it.

### 4.2.1 Empty and Non-Empty Tags

The example above is known as an empty tag because it stands alone; it encloses no text between itself and an end tag. Non-empty DTML tags (also known as container tags) contain a body between start and end tags.
The start tag (Line 1) follows the attribute structure described above. The end tag (Line 3) is similar except that it contains no attributes and the opening bracket is followed by a forward slash:

```
<dtml-tag name="Value" Attribute="value" ...>
DTML Tag Body
</dtml-tag>
```

The tag body (Line 2) contains text, HTML instructions, or additional DTML tags. If the tag used to formulate a simple if-then-else construction is not an empty tag, it follows:

```
<dtml-if expr="true">
<br>
<h2>Two is always greater than 1</h2>
</dtml-if>
```

Here, the expression in the start tag (Line 1), true (which is obviously true), is evaluated and the content of the tag body is output. The end tag (Line 4) limits the tag body.

## 4.2.2 Old DTML Syntax

If you use DTML a lot, you will frequently encounter older versions of DTML tag syntax. These older syntaxes continue to work in current versions of Zope but are generally avoided in favor of the `<dt-tag>` syntax illustrated above. Let's take a look at two of them, just in case you come across some of them.

### 4.2.2.1 Syntax from Zope Version 1.x

The example given in section 4.2, which outputs the name of the user currently logged on, would look like this using Zope 1.x syntax (also known as "server-side include" syntax):

```
<!--#var name="AUTHENTICATED_USER" capitalize -->
```

This syntax follows the following form:

```
<!--#tag Attribute="Value1" Attribute="Value2" ...>
<!--#tag-->
```

### 4.2.2.2 Python String-Format Syntax from Zope 1.x

This format derives from the Python string formatting syntax used to dynamically create text strings in Python programs.

```
%(tag Attribute="Value1" Attribute="Value2")s
```

## 4.2.3 Abbreviating Attributes

Two special attributes, name and expr, can be assigned to virtually any HTML tag. There is a standard way to abbreviate each. For example, we could abbreviate the use of name in our earlier example—which was shown as

```
<html-var name="AUTHENTICATED_USER" capitalize>
```

to

```
<html-var AUTHENTICATED_USER capitalize>
```

To use the abbreviated form, omit the name attribute label, the equals sign, and the quotation marks. The first piece of information in the tag is automatically regarded as the name's value. The expr attribute (used to evaluate complex expressions) takes a similar approach, as shown below:

```
<html-var expr="1+1">
```

is abbreviated

```
<html-var "1+1">
```

NOTE An expression must always be contained within quotation marks.

Because the quotation marks are retained, the term between the quotation marks is regarded as an expression of the expr attribute.
