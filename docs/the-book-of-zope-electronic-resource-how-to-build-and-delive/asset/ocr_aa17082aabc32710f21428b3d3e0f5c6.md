2. Large companies consist of several departments in which various have overall responsibility. If this type of company wants to establish an Internet presence, care must be taken to ensure that no individual user in a group (in this case, a department) can make changes in another department's areas, and if problems do arise, it is easy to determine who is responsible.

These are only two of the many ways that Zone's roles and permissions allow you to achieve the desired distribution of responsibility and control.

# 6.1.1 User Roles

Each user has a specific role (or roles) within Zone, regardless of whether that works directly managing Zone or merely with pages published by Zone on the Internet or intranet. Through those roles, each user is assigned specific permissions and access rights. Roles may have been previously created, or they can be created as needed by authorized users.

# 6.1.2 Zone Roles: Anonymous, Manager, Owner

The roles already present in Zone are Anonymous, Manager, and Owner. New roles can be created and assigned only by users who have the rights or permissions needed to do.

The permissions assigned to each role (and hence each user assigned to that role) determine what the user can carry out with regard to the objects and management functions in Zone. Permissions determine whether and where users can view, create, or modify Zone objects or perform management tasks.

# 6.1.2.1 Anonymous

By default, Zone automatically assigns the Anonymous role to all users who have not explicitly logged in. Users assigned the Anonymous role can only view pages for which the View permission has been assigned to the Anonymous role, which by default is all Zone objects except the Control_Panel folder.

Of course, the permissions for the Anonymous role can be expanded to include actions other than View, which we'll describe in Section 6.1.4. In addition, when you create a new user in Zone (see Section 6.2.1), you specify the role(s) assigned to that user and define new roles and permissions.

By default, the role Anonymous has the Access contents information and View permissions for all objects. (In section 8.3.4, "Assigning Permissions for login_html," we will remove this permission from the Anonymous role for a specific object to restrict anonymous users' access to that object.

# 6.1.2.2 Manager

By default, the Manager role is assigned all existing permissions, for all objects. Whereas you can change the permissions assigned to the Manager role for specific objects, we recommend doing so because it is very easy to deactivate the wrong permissions, removing access to the object instead.
