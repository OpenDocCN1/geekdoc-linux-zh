
Conditions are checked one after other (Lines 1, 3, and 5) until one is fulfilled, at which point the instructions formulated within the tag are carried out. Once a condition is fulfilled, all subsequent tags are ignored. If no conditions are satisfied, no actions are carried out. Therefore, you should pay particular attention to the sequence in which you code the conditions.

In the following example, we request the age of the current user (Line 1), then display a greeting appropriate to that person's age (Lines 2 through 4), then grant or restrict access to the site (Lines 5 and 6). To do so, the value "age" is taken from an HTML form and checked:

```
1: <dml-if expr="REQUEST.age >= 21">
2: <h1>Welcome, </h1>
3: You have unrestricted access to this site.
4: <dml-elif expr="REQUEST.age >= 18">
5: <h1>Welcome, </h1>
6: We're sorry . . but your access to this site has been restricted.
7: </dml-if>
```

(Remember that form values are put into the REQUEST object.)

This example works by first checking whether the user is 21 years of old or older (Line 1); if not, a further check is carried out to determine whether the user is 18 years of age or older (Line 4). Depending on the result, the user is provided with either unrestricted or restricted access to the website.

Let's look at the sequence in which the conditions are formulated in the tag are so important. If the first check determined whether the user is 18 or older, users over 21 would also be given restricted access only. The second condition would be ignored, and it would not be possible to carry out any further differentiation.

The problem with this example is that users under 18 receive no message. To resolve this problem, we can add an else tag, as shown in this listing:

```
1: <dml-if expr="REQUEST.age >= 21">
2: <h1>Welcome, </h1>
3: You have unrestricted access to this site.
4: <dml-elif expr="REQUEST.age >= 18">
5: <h1>Welcome, </h1>
6: We're sorry . . but your access to this site has been restricted.
7: <dml-else>
8: We're sorry . . but we are not allowed to access this site.
9: </dml-if>
```

Now users under 18 receive a message as well as those over 18. Conditional operators that can be used in dml-if expressions are shown in Table 4-9. The logical operators in Table 4-10 can be used to create complex conditional logic.

## Table 4-9: Conditional Expression Operators

| Operator | Description | Example |
|---|---|--|
| == | True if operands are equal | "username == 'vincentp'" |
| != | True if not equal | "size != 1" |
| >= | True greater than or equal to | "size >= min_size" |
| <= | True less than or equal to | "size <= max_size" |
| > | True greater than | "x > y" |
| < | True less than | "z < y" |

## Table 4-10: Logical Operators

| Operator | Description | Example |
|---|---|---||
| not | Negation: False values become true and true values become false. | "not title" (returns true if title is empty) |
| and | True only if both operands are true. | "size!=i and size<=max_size" |
| or | True if any operand is true. | "xy or zy" |

## 4.3.7 The unless Tag

Like the if, the unless tag is used to insert text subject to certain conditions, but it carries out instructions only if a defined condition is not fulfilled (is a false value). The unless tag is a non-empty block tag and accepts the name and expr attributes, using the following structure:

```
<html-unless Condition>
Instructions
</html-unless>
```

> Unlike the if, the unless tag cannot have else tags within it.

## 4.3.8 The with Tag

The with tag is used to manipulate the DTML namespace. It is very useful in the following cases:

- To access different variables with the same names.
- To define new variables for a short period of time in the DTML namespace.
- To access objects or properties that are not in the default because they are not in the namespace.

Often you may need to access attributes of objects, such as title or id, that have the same names as those of the object containing the DTML code or method. Because the current object (depending on whether you are in a DTML document or method) is in the namespace stack, its names will match those of other objects. To get around this, we can use the tag to temporarily alter the namespace stack to search for the desired object:

```
<dt-with name="someObject">
The title of someObject is: <dt-var name="title">
The size of someObject is: <dt-var name="size">
</dt-with>
```

Inside with tag, someObject is placed at the top of the namespace stack. This means that variable names will be sought in it before the current object. With tag inserts an additional namespace at the top of the namespace stack. The object whose namespace is defined in the start tag of the dt-with body contains the instructions to be carried out and can also contain other tags.

```
<dt-with Object>
Instructions
</dt-with>
```

Here's how to access variables from subobjects not normally acquired by default:

```
<dt-with name="Subfolder">
The subfolder title is: <dt-var name="title">
</dt-with>
```

Also, with the aid of the underscore variable's namespace, you can use dt-with to temporarily set a new variable—at the top of the namespace stack. This can be used to store the value of a calculation within the block or to override an existing variable in the namespace. In the following example, a function get_cost is called. This function looks up the cost of an item given its SKU number from an external database. The SKU number is passed from CGI variable. The get_cost function is complex and time consuming, so to increase the efficiency of our code we store its value in a temporary variable named "cost". Further calculations and formatting will be performed on this value inside the block.

```
<dt-with expr="_namespace(get_cost(SKU))">
Price breakdown for SKU <dt-var name="SKU">
Cost: <dt-var name="cost" fmt="dollars-and-cents">
Markup: <dt-var expr="cost * 1.33" fmt="dollars-and-cents">
Retail Price: <dt-var expr="cost * 1.33" fmt="dollars-and-cents">
</dt-with>
```

Inside the block, the variable cost contains the result returned by the get_cost function. After the final tag, the original namespace stack is restored and the variable cost is no longer defined.

## 4.3.8.1 The only Attribute

The only attribute can be used in the namespace stack of the object specified, allowing you to completely replace the namespace stack inside the block. For example, in the following listing the REQUEST variable will output:

```
<dt-with name="REQUEST" only>
<dt-if name="id">
  The id is specified: <dt-var name="id">
  <dt-else>
  No id was specified.
</dt-if>
</dt-with>
```

Because the REQUEST object is at the bottom of the namespace stack, it will be the only object acquired from inside the block.

> NOTE The only attribute does not turn off acquisition. Using merely replaces the current namespace stack with that of another object, rather than just adding that object's namespace to the current one. Because of this, the only attribute has limited utility.

## 4.3.9 The let tag

The let tag is another construct for adding variables temporarily to the namespace. It is designed as a shortcut to using the _namespace() function as above. The let tag is a non-empty tag.

Let's say we wanted to place a new namespace at the top of the stack and then populate it with some variable data. Among other things, the let tag functions as if you were using the tag and the namespace variable. The two examples below are functionally equivalent:

### Example 1

```
<dt-let cost="get_cost(SKU)">
<dt-var name="cost" fmt="dollars-and-cents">
</dt-let>
```

### Example 2

```
<html-expr="_namespace(cost+get_cost(SKU))">
  <html-var name="cost" fmt="dollars-and-cents">
</html-with>
```

The first line of each example creates a new namespace at the top of the namespace stack and adds a variable named "cost" to it. The value of cost is set to the result of the function get_cost, defined elsewhere. Because this new namespace is at the top of the stack, this value for the name cost supersedes any other variable data that might exist further down in the namespace stack. The second line inserts the new cost variable into our document, formatted as dollars and cents. The third and last line closes the block and removes, or pops, the namespace containing cost from the top of the namespace stack.

Multiple variables can be assigned to a namespace within a single let block. Each attribute of let defines a new variable name. The expressions and names are evaluated and referred one after another. Thus, variables can be assigned based on other previously defined variables in the same tag as below:

```
<html-let x="5" y="10" z="y" result="x*y">
  <html-var name="result">
</html-let>
```

In this example, x, y, z, and result are evaluated in succession where z result arises from the previous assignments. The value of the result variable, 500, is output.

> If the value following the variable name is double-quoted, the contents are evaluated as an expression just like the expr attribute of other tags. However, if you omit the quotes around the value, it is called by name—similar to using the name attribute. This can be useful when the desired value is the result of a callable object, such as a DTML method or ZSQL database query.

## 4.3.10 The in tag

Using the tag, sequences such as a list or the result set of a database query can be run in a loop, with the sequence to be defined in the start tag. The tag contains the instructions to be used for each individual list element. Before the tag body code is executed on each element, html-in creates a namespace containing any attributes of the element and some other helpful variables that can be used by the body code.

```
<html-in Sequence Attribute>
  Instructions
</html-in>
```
