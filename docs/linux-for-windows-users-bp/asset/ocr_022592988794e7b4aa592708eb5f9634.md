# Autostart

The “Autostart” icon provides access to a folder that contains programs or links to programs that must be run when KDE starts up. This is the equivalent of the autostart folder that exists in MS/DOS and the Startup folder in Windows 95/98. Each user that has their own “Autostart” folder can have their own set of programs that they want running when KDE starts. In fact each user effectively has his or her own KDE desktop which can be customized to suit individual requirements.

# Templates

The “Templates” folder is, as you might have guessed, for storing template files. Do not concern yourself with this one for the time being. Many programs can use templates to save time when producing standard letters, book layouts, or whatever. Should you start using templates they can be stored in this folder.

# The Panel

The Panel is the bar across the bottom of the screen, and in Windows terminology this is a form of toolbar, but is has similarities with the Windows taskbar. The KDE 1.0 Panel looks rather more bulky than a quick means to run current programs there are icon areas that “one” for “four”. Both versions have four “buttons” labelled rather fewer: These are useful for switching between the KDE equivalent of virtual consoles. But they are “virtual” consoles. When using the graphical user interfaces, you can unlink multi-tasking, and there are two ways of tackling tasks, too: simply “two” or more programs on one desktop, much as the Windows taskbar, or put each program on its own, separate desktop, so you can “four” programs on four desktops. Both methods, with several programs running on each virtual desktop.

It will be necessary to have access to two programs at once, such as obviously necessary to drop a tile from one window to another. They must then be open, and there is no need for the second program to be open on the same desktop. If you drag and separate programs are opened on different desktops. To switch between them, simply click on the appropriate “virtual console” at the bottom of the screen, or use the desktop switcher in the Panel. Both methods are described below in more detail.

Though switching from one to the other is multi-tasked, Bear in mind that the more programs that are multi-tasked, the greater the system resources that will be needed. For complex multi-tasking to

work, well it is essential to have plenty of memory available. With the current low cost of PC memory, this is not normally a major problem.

To the left of the buttons used to switch between virtual consoles are the tools the “pop-up” shell is used to launch programs. It is used to log out of the KDE session.

This takes the system back into a console mode and the command line interpreter. On operating this button you get a chance to change your mind (in case you operated it by accident) or to continue with the “log out”-accounting you may be given further options such as shutting down the system, returning to a console, or rebooting. The lower of the two small buttons is the screen-locking button.

# Now you see it...

You will notice that the Panel has an arrow at each end. If you try left clicking on the right-hand end of the arrow you will find that the Panel expands onto the right-hand side of the screen. Similarly, left clicking on the left-hand button causes the Panel to retract onto the left-hand side of the screen. In either case the arrow remains as an “on” indicator that the panel can be “popped” out of its “home” position. You will also notice that when you move your cursor to the top of the screen, it causes the Panel to pop back out. Again, when you move your cursor away from the area above the panel, the area above the panel retracts, and the panel will remain at the top of the screen.
