
## Free disc space

Information on free disc space is something that most users need to keep under scrutiny, and this information can be obtained via the free command line interpreter. If you simply need to know how much free space there is on the hard disc, use the `df` (disc free) command. This can be used without any option flags, as in this example:

```bash
df
```

The `df` command will respond with four figures which are the total disc capacity in kilobytes, the number of kilobytes used, the number of kilobytes free, and the percentage of the disc that is actually used. The fourth figure is therefore the all-important one that tells you how much disc space is free. Once this figure is known, you'll get the approximate size of the file. If the disc space is free, you'll get an accurate estimate of the amount of space available.

The chances of this happening are about the same as winning the lottery, but you can check the current state of things using the `df` command and the `-i` (inode) option, like this:

```bash
df -i
```

This gives four figures, as before, but this time it is the total number of available inodes, the number used, the number free, and the percentage of available inodes that are used. On my PC the disc is 54 percent full, but only 12 percent of the available inodes are used, so I normally do not worry about the disc capacity, so it runs without worries.

The `du` (disc usage) command is another command line disc utility which can be useful. It shows how much disc space (in kilobytes) each directory (or directories) contains. If there are directories beneath the subdirectory, it will also list them. The basic use of the `du` command provides a listing for the current directory, but you can easily specify the directory at the end of the command. For example:

```bash
du /home/fred
```

Produces a listing for `/home/fred` and its subdirectories.

A size for a file can be obtained simply by specifying a file rather than a directory. This example would give the size of the file called “testfile” in the current directory:

```bash
du testfile
```

Note that the size of a file can be determined from within KDE by locating the file using KFM, right-clicking on its icon, and then selecting Properties from the pop-up menu. The file size will be included on the first screen of information. Alternatively, simply place the pointer over a file icon and give its size in the status line at the bottom of the KFM window. Unfortunately neither method works with a directory. The Properties window will simply say “Is a directory” instead of giving a size, and the status line will just say “Folder”.

There are various option flags that can be used with the `du` command, and this command option flags will bring up a list of them:

```bash
du --help
```

The “-max-depth=N” option is a useful one if you only require details of the current directory and are not interested in subdirectories several levels beneath it. This command will list the size of the current directory and the subdirectories immediately below it:

```bash
du --max-depth=1
```

### Also need to know

If you only need to know the size of the current directory use this command:

```bash
du -m -max-depth=0
```

For large directories it is helpful to use the “-m” option so that the size of the large directories is given to the nearest megabyte. This command will give the size of the current directory in megabytes:

```bash
du -m -max-depth=0
```

## Printing

Printing a standard text file under MS/DOS is quite easy provided you have a printer that can handle ordinary ASCII files. You simply copy the file to the appropriate port. Printing practically anything under Windows is also quite easy. Windows provides a useful and virtual printer which can be able to communicate with the printer driver and fully exploit it (in theory anyway). Things are far less straightforward under Linux, but if it is possible to output directly it would be good to do so. Most of the files you wish to print out will be produced using an application such as StarOffice or WordPerfect, all of which have their own ways of printing out to the printer. Some applications program, but others will only print out to a PostScript compatible printer. It is really a matter of taking each application as it comes.

Applications programs might go totally their own way with the handling of the printer, but it is advisable to have printer properties installed in Linux anyway. This will normally be included in the installation process, but it is possible to add or alter the printer configuration later. There is more than one installation and configuration and Administration program to use Linux distributions. It is possible to print direct from the command line and it is just a matter of copying the file to the port the printer is connected to. This will usually be in the file system `/dev/lp0`, so to copy the text file “text” in the current directory to the printer this command would be used:

This will probably work quite well if the printer understands ASCII text and like a graphics file or a text file having embedded formatting instructions with formatting. However, do not be surprised if there are usual text printing problems. The KDE fields and line spacing printing tends to use the Printer Queue utility that can be launched from the file “K” menu by selecting Printing System KIOSK and printing. If you have opted for a printer icon on the desktop, then just left-click on printer and the K30 window should appear. Files dragged from KFM to the main area of this window will be printed, and again this is only usable with simple text files and will usually be produced for your type of printer. It should ever work with mixed text and graphics files that have been formatted to suit the printer. Using the Kicker text and click boxes at the top of screen you can opt to have lines printed immediately or queued.
