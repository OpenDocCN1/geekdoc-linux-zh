# **Owner (User)**

This will usually be the user who created the file. The owner has full
control over permissions and can assign them as he or she thinks fit.

# **Group**

The user is a member of a group associated with the file. Groups are
useful when there are large numbers of users using the computer for
different purposes. For example, one group might be involved with
despatching goods, another group might deal with later sales, and



another group could deal with the accounts, and so on. This is an easy
way to give access to the people who need to use the file, but prevents
access by all others. Each user can belong to any number of groups,
but a file can only be associated with one group at a time.

# **Others**

A user who does not own the file, and is not a member of a group related
to the file.

These are the three switches.

# **Read (R)**

This switch allows the contents of the file to be inspected, but does not
permit its contents to be altered.

# **Write (W)**

This switch permits the contents of the file to be altered, which includes
deleting it altogether.

# **Execute (X)**

In the case of a file, this switch permits the file to be run as a program.
For a directory it enables the directory to be entered using the `cd`
command, or opened in KFM or a similar program.

Files always have some permissions granted by default, and in normal
circumstances you only need to give special consideration to the
permissions that you want to apply, such as the read-only permissions
available when the file is opened in a text editor. It is rarely necessary
to set the execute permission, since when creating the file it has been
created in a location which is accessible by the user. If you are using
the KFM permissions screen you will need to control user permissions
from the KFM permissions screen should now start to make sense. If we

the tick in the read permission box, it turns off by making the box

default settings on the KFM permissions screen for a file created by a
