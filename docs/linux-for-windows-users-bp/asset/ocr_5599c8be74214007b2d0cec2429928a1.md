# RPM

Many programs are distributed as tar files, or more usually zipped tar files. In order to use one of these the readme file is read to determine what to do next. This will often entail running an installation program on how to get included documentation should give useful instructions on how to get the software “up and running”. The main alternative to tar files is the RPM format. RPM in this context stands for Red Hat Package Manager, and although this software was produced by Red Hat it is freely available and any recent version of Linux should be equipped to deal with this type of file. You will often find far too many of the options of installing software from some form of tar file or an RPM file. RPM files have definite advantages, so given the choice it is almost certainly better to opt for the RPM route.

At first sight they may seem to be no need for RPM or any form of package installation program. Why not simply load a program file onto the hard disc and run it? This type of thing was the norm in the days of MSDOS and other relatively simple operating systems, but few programs are heavily dependent on libraries or shared object files so it is quite difficult to just drop these files on a hard disc and get them to work. Many of these shared files are used by a number of programs, and with modern computing systems came with complex with all the files it would require, easier to create. With RPM it is much easier to do this. With RPM files there are many advantages to this approach so long as one is aware of its duplications and waste disc space.

The drawback of the shared approach, and each program being dependent on support files is that there is plenty of opportunity for things to go wrong. If a program requires certain files to be present on the computer, are those files already installed? RPM is designed to ensure that present, are they the correct versions? It will not only detect any problem, but also offer solutions. Many of the original support files are already present and some of the required support files are also installed by other programs so there are often conflicting dependencies. These dependencies may be resolved by installing new software or upgrading existing software. There are often different versions of the same support files, and this can be a source of problems. However, with some form of support, it is possible to make the system more consistent.

```
tar xfV /mnt/floppy/but1.tar /root/temp
```

to extract the files from an archive takes this form:

tar options archive destination
The destination is optional, and if it is not specified the files will be placed in the current directory. This command would reverse an earlier example, and take the files from but1.tar on a floppy disc and place them in /root/temp

```
tar xfV /mnt/floppy/but1.tar
```

There is a potential trap here in that tar removes the leading “./” from filenames, and so files are stored here as relative to the current directory. This will mean that if you have absolute paths, when archiving files using tar. Another way round this is not use absolute paths when archiving files using tar. This command would archive the files in the current directory to file but1.tar on the floppy disc:

```
tar cf /mnt/floppy/but1.tar *
```

This would extract but1.tar and place them back in the current directory:

```
tar xf /mnt/floppy/but1.tar
```

Note that it is not just files that tar archives, any subdirectories and their contents will be treated as part of the directory being archived. Extracting files from a device is much the same as extracting them from a file, but the device rather than a file is specified as the source. This would reverse the example of archiving to a device given previously:

```
tar xf /dev/fd0 /root/temp
```

With multi-volume archives the “W” option must be included, as in this example:

```
tar xfWV /dev/fd0 /root/temp
```

The correct floppy discs must be inserted in the drive when requested by the program, and you will be in trouble if they were not numbered when the archive was created.

tar is undoubtedly a rather complex program to use, but for some simple tasks, such as extracting files from an archive, it is very useful. When dealing with a rather large number of files, you might want to use a more sophisticated method. There are plenty of graphical tools that make dealing with archives much easier, and they are well worth reading through the on-line help sections.
