## Software selection

With most installation programs you will be given at least some control over which packages to be installed. There can be a choice of various standard installations along the lines of small, medium, large, and very large, and groups of programs for selecting individual packages or groups of various types. This is obviously a personal choice to some extent, and it is difficult to start with a fairly complete selection of the standard packages. This leaves you with the choice of selecting the packages you want. In order to get the most from Linux you will need the X Window system and some of the applications. Software such as the C and C++ development tools is likely to be of little interest to most users.

There will inevitably be some questions pertaining to networking. Here we are only concerned with Linux used on a work station. You can not totally ignore the networking capability. But you are unlikely to install Linux as part of a network, nor will you actually be networked to another Computer. Obviously you just answer the questions asked. If a network card is installed in the computer, the installation program will probably ask for the settings, such as the IP address of the host name, and the network mask. These can be asked for. As there is no need to worry about a hostname, just leave it blank.

For the network. Either accept the default name, which will be something like “nodomain_newhere”, or replace it with a name of your own choice. The basic format of the name must be the same as the default name.

## LILO

Linux normally boots up via a program called LILO and this may need a little amount of configuration. It is basically just a matter of selecting which part of the hard disk LILO will be installed, what options, if required, to include, and the default operating system to be booted.

There are two main places for LILO to install. The first primary partition is the master boot record (MBR) before the disk partitions. The default option is in the MBR. This will ensure that a disk can be used to select an alternative operating system. The delay time can be configured for Linux if you want to reduce the delay if this option is offered.

You may also be asked to select the Linux kernel to install. Unless you know exactly what you are doing and have good reason to do so, simply select the default kernel.

## Passwords

During the installation process you will be asked to provide at least one password. As a minimum the password for the user `superuser` (or root account) must be set. It is often a good idea to set up a second password as well. It is often a good idea to set up two passwords. The second password is often set up as the password for the root account, which you may use when your system settings are changed. You may be asked also to set up a password for the second password. This is often called the admin password.

It is important to remember that the password set up is not stored in plain text, but it is hashed. This means that the password is not stored directly, but a hash of the password is stored. This is a one-way process, meaning that the password cannot be recovered from the hash. This is a good thing for security, but it also means that if you forget your password, you will have to reinstall the system to get the password back. It is therefore a good idea to write down your password and store it in a safe place.

You may also be asked to set up at least one user account. Even where you may only use one user, many prefer to log in as the standard user, rather than the root user. By doing this you can avoid many of the risks of accidentally making unwanted changes to the system, especially if you are less familiar with the Unix file system.

If you are more or less limited to running the system, the root password can be set up later if required. A user account can be created later if required. A user can create a user account with the adduser command. If you are asked for a group ID, enter the same as the user ID. If you are asked for the group name, enter the same as the user name. If you are asked for the group GID, enter the same as the user ID. The install process is fairly flexible in its handling of these settings, and it will accept most reasonable input.

During the install process you will also be asked for the password for the root account. You may also be asked for the password for the user account that you are creating. If you are not going to set up a user account, you can just press return at the password prompt.

Note that the password is not displayed on the screen when you type it in. This is normal, and does not mean that you are not typing it in.

It is often a good idea to use a different password for each account, and to change your password regularly. It is also a good idea to use a strong password, which includes a mix of upper and lower case letters, numbers, and symbols.

The more complex your password, the harder it will be for anyone to guess it, but also the harder it will be for you to remember it.

The installable program will give some guidance about choosing an acceptable password, but it normally has to be four or more characters in length, and can consist of upper and lower case letters, plus numbers and punctuation marks. The more complex the password, the harder it will be for anyone to guess it, but the harder it will be for you to remember it.

It will be for the user to remember. If you should forget the root password it will not be possible to make changes to the Linux installation, and it might become necessary to reinstall Linux. Do not use the popular and predictable passwords such as the date of your birthday or your name as spelt or misspelt (e.g. believing rather than wellbrow) with a place where you misspell (eg. spelling backwards). These should stick in your mind but should not be easy for anyone to crack.

## X Windows

Assuming you have elected to install the X Windows system, this will probably require a certain amount of manual configuration. With some recent versions of Linux the installation process will try to determine the hardware present by a system of software probing; if this is successful the probing process will be less than manual configuration, but it is likely that you will still have to do some manual configuration. The X config file contains a large amount of configuration information about the type of mouse you use; probing is only used for this. You will also need to know the amount of memory on the video card, or something else. The initial XFree86 Setup program is normally achieved using the XF86Setup program.

Manual configuration is normally achieved using the XF86Setup program. It asks if you wish to run this now or later. I would suggest choosing “later” because the “Now” option actually means it will be postponed until a little later! When the configuration program is finally run it provides an initial help screen (Figure 1.5), which helps with navigation around the program. Some information about the type of mouse in use is usually requested prior to the XF86Setup program being run, and it is very easy to navigate your way around so it will be working from the outset. It then runs a menu of items including the mouse configuration options. The page in Figure 1.5 is used to control this until the mouse is working. Assuming you know exactly what type of mouse you are using there should be no problem getting it to work properly.

One area of confusion concerns Logitech mice. The Logitech mouse does not work with modern Logitech serial mouse, and does not support my slightly ancient Logitech mouse, unless you have a genuine antique ‘Logitech mouse’ it is the Microsoft option that should be used. If there is a generic serial mouse option this should also work for practically any serial mouse. Many computers are supplied with serial mice that are not produced by one of the main mice manufacturers. Again, the Microsoft or generic serial mouse options should give good results.
