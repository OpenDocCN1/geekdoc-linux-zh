Colour | | White | Green | Blue | Red | Cyan

You have given the colour of normal files as white, but this colour will be the normal text colour for the display. This will usually be either white or grey. The color option can be used when listing the contents of something other than the current directory, and the command then takes this form:

```bash
ls /usr/lib —color
```

In this version of the command will also work, because the hyphens in front of the word color will ensure that Linux does not interpret it as the directory to be listed:

```bash
ls -color /usr/lib
```

There are other controls that can be used to modify the way in which the `ls` command functions, and you can get brief details of these by using the on-screen help system. To get help on a command simply type the command followed by `—help`, as in this example:

```bash
ls -help
```

Many of the controls enable the list to be sorted in various ways, which can obviously make life easier when dealing with large lists of files. Hidden files are included if the `-a` switch is used. To have the file size in kilobytes included use both the `-s` and `-k` controls, as in this example:

```bash
ls -s -k
```

You can have the controls as separate entities, as in the above example, but it works just as well in this form, with two or more merged into a single entity:

```bash
ls -sk
```

If you investigate the Linux file system the large number of directories and files may surprise you. To some extent the large number of files is just the way it is done with discrete items of hardware. It also has to be borne in mind that a typical Linux installation includes more than just the operating system. There may well be dozens of application programs or word or text processors, and games.

### Directories

Adding and removing directories is handled in much the same way as it is under MS-DOS. New directories are created using the `mkdir` (make directory) command, but note that this can not be abbreviated to an MS-DOS style `md`. This command can produce a subdirectory off the current directory, and it will be called "temp":

```bash
mkdir temp
```

A new directory can be placed anywhere in the file structure by including the full name and path in the command. This example produces a subdirectory called `temp`, and places it off the root directory:

```bash
mkdir /root/temp
```

The `rmdir` command is used to remove unwanted directories, but note that it can not be abbreviated to just `rd` in Linux. Also note that a directory can only be removed if it is empty. In this context "empty" means that it must not contain any files at all, or subdirectories even if those subdirectories are empty. The `rmdir` command, and these two examples would remove the directories made using the two `mkdir` examples given previously:

```bash
rmdir temp
rmdir /root/temp
```

Sometimes you may wish to remove a directory, complete with all the files it contains. This can be achieved from the parent directory using the `rm` command and the `-r` (or recursive) modifier. The example shown here will remove the directory called "testdata" and all its contents:

```bash
rm -r testdir
```

Obviously great care needs to be taken when deleting files, and even more care must be exercised when removing complete directories.

### Files

In the normal course of events users generate files using applications, but for experimental purposes you can generate dummy files using the operating system. This can be achieved using the "touch" command, as shown in this example, which would generate a file called "test":

```bash
touch test
```

The file would be placed in the current directory, but it could be placed anywhere in the file structure by including the directory path in addition to the file name. Files can be removed using the `rm` command, and this command would remove the file generated in the previous example.

```bash
rm temp
```

Of course, for this to work the file would have to be in the current directory. By specifying the full path and file name it is possible to remove files in other directories. The path structure depends on the system default, you may be asked if you want to remove the file, and you must then reply y, Y or r for yes, there is no built-in file retrieval system, so if files you delete for it will be regarded as lost and gone forever.

With MS-DOS it is possible to delete all the files in a directory, using the `*` wildcard symbol. This is also possible in Linux, as in this example:

```bash
rm /root/*
```

This will delete all the files in the /root directory, but depending on the default setup of your system it might be necessary to confirm the removal of each file.

### Filenames

Users of MS-DOS will notice that the MS-DOS `*.*` has been replaced with just `*` in Linux. MS-DOS filenames can have up to eight characters plus up to three characters in an extension. The extension follows the main filename, and is separated from it by a full stop. These three-character extensions are normally used to indicate file type, such as “txt” for a text file or “.jpg” for a JPEG graphic file. Filename extensions can also be used in Linux systems, but the full stop does not have the same significance as it does in MS-DOS. The full stop character is almost just another character as it does in Linux. The filename “ch1.txt” is just as valid in Linux as “chapter1.txt”. The filename “bk.chapt1” is just as valid as a text file by a program that was designed to recognise the “.txt” extension. Here are some useful points to remember when thinking up Linux filenames:

#### Maximum characters

Up to 256 characters can be used in a Linux filename. However, things get a much more manageable if you limit yourself to no more than about 40 or so.

#### Case sensitivity

Both upper and lower case letters can be used in filenames, and unlike MS-DOS, Linux regards them as two separate sets of characters. In MS-DOS files called “london”, “LONDON” and “London” would all have the same name, but in Linux they would each have a different name.

#### Allowable characters

Numbers and most other characters are allowed in filenames, but there are certain characters that should not be used as they have special meanings to the shell and could cause confusing results. These are the characters to avoid:

- Ampersand &
- Apostrophe `
- Asterisk *
- Circumflex ^
- Forward slash /
- Hyphen -
- Question mark ?
- Quote “” ‘’
- Vertical bar |

The space character should also be avoided as the shell might otherwise interpret the filename as two or more filenames separated by spaces.

#### Wildcards

With some MS-DOS commands it is possible to use wildcards instead of giving a complete filename. Things operate in much the same way with Linux. The asterisk character was used in an earlier example, the asterisk can be used to represent any number of characters. The question mark can be used in place of a single character. Suppose you required a list of the files in a directory that start with “Fig”, this command would list them:

`Fig*`

If you needed to know which files started with “Fig” had two characters and then ended with “.gif”, this command would do the job:

`Fig??.gif`

When using the question mark wildcard bear in mind that it will only work in the number of question marks matches up with the number of characters in the filename. For instance, the previous example with three “Fig12.gif” all right, but it would not match with “Fig1.gif” or “Fig100.gif”. These would both be catered for by this command:

`Fig*.gif`

There is a third wildcard in Linux, which is the square bracket. In MS-DOS the third wildcard has the same effect, but to know a pair of square brackets ([ ]). Suppose you wanted to know which files called “fig6a.gif”, “fig6b.gif” and “fig6c.gif”. You could search for specifically for these files using the square brackets:

`fig6[abc].gif`

Under most circumstances there is probably no point in using the square brackets, but they can be useful in circumstances where the other wildcards would not be specific enough.

### Copying files

Files are copied using the `cp` command, which must specify the file to be copied and its destination directory. The copy retains the filename of the original. This example would copy the file called “test” from the current directory to the /root directory:

`cp test /root`

This assumes that the file called “test” is in the current directory. If the source file is in the current directory the full path must be supplied in addition to the filename, as in this example:

`cp /bin/test /root`

Use “.” as the destination directory if you wish to copy a file from another directory to the current directory. This command would copy the file called “test” in the /bin directory into the current directory:

`cp /bin/test .`

The name of the file can be changed during the copy operation, and it is just a matter of giving the new file name when specifying the destination in the file called “nice” in the /bin directory is copied to the current directory as the file called “bad”. Of course, if “bad” was a directory, the file would be copied into this directory under its original name.

`cp /bin/nice /bad`

It is possible to copy several files from one directory to another by specifying several source files in the `cp` command. This command will copy the files called “test” and “test1” from the current directory to the /root directory:

`cp test test1 /root`

Rather than copying a file you can simply move it using the `mv` instruction. This operates in much the same way as the `cp` command, but the original file is deleted. This command would move the file called `temp` in the /usr directory to the /usr/temp/:

`mv /usr/temp /usr/temp/`

This version of the command has the same effect, but the moved file is renamed “hello” during the move.

`mv /usr/temp /hello`

If a complete directory or even a directory structure must be copied, the `mv` or `cp` can test with the “-R” option argument. This example would copy all the directories and files in the /usr directory as a subdirectory of the current directory. The directory and file names remain unaltered.

`cp -R /usr/test_ .`

An entire directory or directory structure can be moved using the `mv` command, and the `-r` modifier is not needed. This command has the same effect as the previous example, but the original directory structure is removed.

`mv /usr/test .`

There would seem to be no Linux equivalent to the MS-DOS `diskcopy` command, and Linux is less disc oriented than MS-DOS. The contents of a disc are copied to another disc by run `diskcopy` means of course.
