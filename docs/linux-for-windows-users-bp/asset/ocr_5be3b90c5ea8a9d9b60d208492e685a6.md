This sequence of events will provide the desired result.

+   * Make a temporary directory
+   * Mount the floppy disc
+   * Copy the contents of the disc to the temporary directory
+   * Unmount the floppy disc
+   * Mount the floppy disc
+   * Move the contents of the temporary directory to the copy disc
+   * Unmount the copy disc
+   * Remove the temporary directory

This does not give a true clone of the original disc. If you are copying from a system disc, then you must copy to a system disc in order to produce a bootable copy. Copying files from one disc to another is probably easier using KDE and the KFM file manager, which has copy and paste facilities, but it still remains a slightly less than straightforward process.

# Renaming

With MS/DOS it is possible to rename files using the ren command, but there is no exact equivalent to this in Linux. However, the mv command can be used to move the contents of a file to a file of a different name but with the same directory. In other words the file is renamed. This command will take the file in the current directory called “test” and rename it “renamed”:

```
mv ./test ./renamed
```

When working with a directory name, but you need to be very careful when renaming directories. Doing so can render applications or Linux itself unable to locate the files they require.

# Reading a file

MS/DOS can be used to read a text file, such as a “readme.txt” file, using the type command. The nearest Linux equivalent to this is cat, which will simply print a file to the screen. This command displays the contents of the groups.1 file in the /usr/man/man1/groups.1 directory.

```
cat /usr/man/man1/groups.1
```

The cat command is only usable with short files or if you only wish to view the end section of a file. This is due to the fact that it does not give any control over the way the file is displayed, and with a small monitor the text is scrolled off the screen almost instantly. You stand no chance of to exit the less reader a few words at a time. In fact the less command is better for large amounts of text, because it displays the text one screen at a time. Simply press the spacebar to move on to the next screen and the H (return) key to move one line at a time. If the control c is not to exit the less reader. For instance, you can use control z to run more Key controls available. To move one line at a time, press the q key. This will display the next less command line.

However, it is suggested that, to scroll up and down through the text, it may be easier to use the arrow keys instead. These commands will load the file into a “proper” window accessor of text editor.

There are two further text-reading commands that are worth mentioning. The head command displays the first few lines. By default, ten lines are displayed, but this can be altered using the -x control. Where x is the number of lines to be displayed. These two commands would therefore display the first 20 and last 15 lines in the text file /root/readme

```
head -10 /root/readme
tail -15 /root/readme
```

# Links

Earlier in this chapter it was pointed out that ls command can be made to display the names of the main files types in differently, but what exactly, can ls tell us about a file? This is where the find and which commands become useful. The find command will list all the files in a specific directory, but the which command can be used to find a specific file within a directory.

To create a link to a file, the command ln -s oldfile newfile is used, where oldfile is the file or directory to link to, and newfile is the name of the new link. The -s option creates a symbolic link, which is a pointer to the original file. This is the default type of link on most systems.

It is also possible to create a hard link, which is a direct copy of the file in the directory. This is the only type of link that can be used on a file system that does not support symbolic links. To create a hard link, use the ln oldfile newfile command.
