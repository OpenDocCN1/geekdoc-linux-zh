# ### Indirect printing

If you have an application that refuses to “talk” properly to your printer
and just sends a stream of text (such as PostScript data, for instance),
the best (for print only) approach: WordPerfect is supplied with many Linux
distributions, and it works with a wide range of printers. It can import
text files and various forms of graphic files. It is often possible to use an
“awkward” application to save a file to disc in a standard format, after
which it can be imported into WordPerfect, and printed out. This is a
roundabout way of doing things, but the print quality is likely to be limited
by the printer rather than any file format conversions. Graphics can be
easily dragged to the required size with WordPerfect and then printed
out at the required size.

Another indirect approach is to use the ghoscript application that will
almost certainly be installed on the system. This program can take a
PostScript file and convert it into output that is suitable for a range of
popular printers such as Hewlett Packard DeskJets, LaserJets, and
compatibles. Many Linux applications can “print” their PostScript output
to a file on the hard disc, and can therefore be made to drive a range of
non-PostScript printers via ghoscript/Print. If ghoscript/5.10 is on the system
doc. The 5.10 porting path is /usr/share/ghoscript/5.10/
If you are not using this path is the version number, and will be different

This is a command line utility, and it is not the most straightforward of
programs to use. Find the easiest way to use it to send the output of
a file, and to then print the file via the Printing Queue utility. Suppose
you have a PostScript file in the current directory called Picture.ps,
and you wish to produce a Laserjet printer file called Print.ps. This
command would have the desired effect:

```
```bash
gs -dEVEICE=laserjet -sOutputFile=Print.ps Picture.ps
```
```

Be careful to use upper and lower case letters in the appropriate places.
Having a printer file is convenient if you need to print the document
again later, but otherwise there should be no problem in sending the
output direct to the printer, as in this version of the command.

```
```bash
gs -dEVICE=laserjet -sOutputFile=/dev/lp0 Picture.ps
```
```

Of course, if the printer is at other than /dev/lp0 the appropriate path
