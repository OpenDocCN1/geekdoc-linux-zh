
## Open a terminal (console)

Use Control-T from the keyboard, or operate the terminal button in the Panel (the one with the monitor icon).

## Run a program

If it is not in the “K” menu, locate the program file using KFM and then left click on its icon or filename.

## Put a program icon on the desktop

Locate the program file using KFM, and drag it onto a vacant area of the desktop. Select Link from the pop-up menu. Left clicking on the icon will then run the program.

## Change virtual desktops

To move to another desktop simply left click on the appropriate desktop button on the panel (the buttons labeled from one to four). Alternatively, hold down the Control key and then keep pressing the Tab key to cycle through to the desktop you require.

## Make a window visible in all desktops

Click on the Sticky or Pin button in the title bar. Operating this button makes the window visible only when using that particular desktop.

## Start KFM

Click on the house icon in the panel. This starts a KFM in the Home directory, but you can move to the required directory from there.

## Make a new folder

Open the parent directory using KFM. Right click on a vacant area of the main window, select New from the popup menu, and then Folder. Type the name of the new folder in the edit box that appears and then left click on OK.

## Hide the Panel

Left click on an arrow at one end of the Panel. Left clicking on this arrow again restores the Panel.

## Autostart a program

Locate the program file using KFM and then drag it to the Autostart icon. Then select Link from the pop-up menu.

## Stop a program from starting automatically

To reverse the process left click on the Autostart icon. This opens a copy of KFM showing the contents of the Autostart folder. Simply delete the links for any programs that you do not require at start-up.

## Make a window visible in all desktops

Activate its Sticky icon.

## Move a window from one desktop to another

Activate its Sticky icon, switch to the desktop where it is required, and then deactivate the Sticky icon.

Note that some menu options and certain buttons are not operational under all circumstances. Inappropriate menu options are greyed-out (shown in light grey rather than black) and can not be selected. Similarly, inactive buttons do not appear to protrude slightly from the desktop, and can not be operated. This is the same method that is used in Windows and most other graphical user interfaces.

## 4. Also need to know

### Multi-user

The three previous chapters covered the things you need to know in order to get Linux installed on your PC, and use the system to run applications, copy files etc. using either the command line interface or KDE. In this chapter we will delve a little deeper, covering a range of topics that you need to know about in order to use a Linux system effectively.

As we saw in previous chapters, in order to use Linux it is necessary to log in under a user name, and to give the corresponding password. This is much more work than the boot process takes even on a small, modern, fast PC: to make the computer run a simple program might require a login and password, and then perhaps one or more mouse clicks or a series of keystrokes in order to make the computer. This extra time and effort means that even using a very fast computer requires a reasonable amount of thought to use the machine. Provided each user does not require much time at a time. The problem with this approach is that there is a lack of privacy for the users. This is not just a matter of other users having access to what might be someone else's private information. With a free-for-all approach to things there is a real danger of one user accidentally altering or erasing data belonging to other users. In fact the system could gradually degrade into a complete shambles.

With a multi-user operating system such as Linux you login under a name and password so that the operating system always knows who is using the computer. It would be an exaggeration to say that the system looks completely different to each user, and that it is like each one having their own PC. However, to some extent the computer will be personalised for the current user. The differences are perhaps more obvious when running KDE than when using the command line interface. Even when working at the command line there is a clear difference after logging in. The command line prompt is preceded by some text that includes the login name. Also, the system is in a directory specific to that user. For example, the system will normally be in /root if you log in as “root”, or /home/Fred if you log in as “Fred”. Apart from “root”, each user has a /personal directory that is a subdirectory of the /home directory.

If you run KDE here, there are more obvious differences. The KFM program that runs automatically at start-up is the appropriate directory for that user. You can upgrade the computer, but the difference is the software you use frequently. If you put up program icons for login to KDE. Less obviously, these will not be present on the KDE desktop of any other user unless they also add them. Although by default KDE desktop, Templates and Autostart folders are added for you, other users can not use your Trash folder. The Trash folder holds to access anything you place in your Trash folder, where “fname” is the login name of the user: /home/fname/Desktop/Trash. It is apparent that that folder such as Autostart folder for each user and any folders beneath that folder such as the “root” user is at /root/Desktop incidentally, and not in /home directory.

### Permissions

It is not just a matter of having personal KDE desktops for each user. This would still allow user access to the files of every other user. In an experiment, you could try logging in as “root” and placing one or two dummy files in Trash. There are graphics and text editing programs available via the “K” menu button that can be used to make dummy files, such as a drawing containing one line or a one-word text file. Having made files and loaded them into the folder, log out of KDE and then login again as another user. If you try to navigate from the /root/Desktop/Trash to the /root/Desktop folder, you should find that you can not. The system will produce a window displaying the error message (Figure 4.1) stating that it was not possible to list the contents of the directory. This is other way round, with some files being placed in the Trash folder of an ordinary user, it will be possible to access them. If you login as root, you should be able to view and even delete the Trash folder that contains them. As root you can do pretty much anything you want, and this includes the login name of an ordinary user you can only access the files which that user has permission to access.
