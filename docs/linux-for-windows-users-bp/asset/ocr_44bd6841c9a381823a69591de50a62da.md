# **Files**

In the normal course of events users generate files using applications, but for experimental purposes you can generate dummy files using the operating system. This can be achieved using the "touch" command, as shown in this example, which would generate a file called "test":

```
```
touch test
```
```

The file would be placed in the current directory, but it could be placed anywhere in the file structure by including the directory path in addition to the file name. Files can be removed using the `rm` command, and this command would remove the file generated in the previous example.

```
```
rm temp
```
```

Of course, for this to work the file would have to be in the current directory. By specifying the full path and file name it is possible to remove files in other directories. The path structure depends on the system default, you may be asked if you want to remove the file, and you must then reply y, Y or r for yes, there is no built-in file retrieval system, so if files you delete for it will be regarded as lost and gone forever.

With MS-DOS it is possible to delete all the files in a directory, using the `*` wildcard symbol. This is also possible in Linux, as in this example:

```
```
rm /root/*
```
```

This will delete all the files in the /root directory, but depending on the default setup of your system it might be necessary to confirm the removal of each file.

# **Filenames**

Users of MS/DOS will notice that the MS/DOS `* *` has been replaced with just `*` in Linux. MS/DOS filenames can have up to eight characters plus up to three characters in an extension. The extension follows the main filename, and is separated from it by a full stop. These three-character extensions are normally used to indicate file type, such as “txt” for a text file or “.jpg” for a JPEG graphic file. Filename extensions can also be used in Linux systems, but the full stop does not have the same significance as it does in MS/DOS. The full stop character is almost just another character as it does in Linux. The filename “ch1.txt” is just as valid in Linux as “chapter1.txt”. The filename “bk.chapt1” is just as valid as a text file by a program that was designed to recognise the “.txt” extension. Here are some useful points to remember when thinking up Linux filenames:





# **Maximum characters**

Up to 256 characters can be used in a Linux filename. However, things get a much more manageable if you limit yourself to no more than about 40 or so.

# **Case sensitivity**

Both upper and lower case letters can be used in filenames, and unlike MS/DOS, Linux regards them as two separate sets of characters. In MS/ DOS files called “london”, “LONDON” and “London” would all have the same name, but in Linux they would each have a different name.

# **Allowable characters**

Numbers and most other characters are allowed in filenames, but there are certain characters that should not be used as they have special meanings to the shell and could cause confusing results. These are the characters to avoid:

+   - Ampersand &
+   - Apostrophe `
+   - Asterisk *
+   - Circumflex ^
+   - Forward slash /
+   - Hyphen -
+   - Question mark ?
+   - Quote “” ‘’
+   - Vertical bar |

The space character should also be avoided as the shell might otherwise interpret the filename as two or more filenames separated by spaces.

# **Wildcards**

With some MS/DOS commands it is possible to use wildcards instead of giving a complete filename. Things operate in much the same way with Linux.
