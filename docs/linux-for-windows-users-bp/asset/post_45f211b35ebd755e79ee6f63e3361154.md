
## Autostart

The “Autostart” icon provides access to a folder that contains programs or links to programs that must be run when KDE starts up. This is the equivalent of the autostart folder that exists in MS/DOS and the Startup folder in Windows 95/98. Each user that has their own “Autostart” folder can have their own set of programs that they want running when KDE starts. In fact, each user effectively has his or her own KDE desktop which can be customized to suit individual requirements.

## Templates

The “Templates” folder is, as you might have guessed, for storing template files. Do not concern yourself with this one for the time being. Many programs can use templates to save time when producing standard letters, book layouts, or whatever. Should you start using templates, they can be stored in this folder.

## The Panel

The Panel is the bar across the bottom of the screen, and in Windows terminology this is a form of toolbar, but it has similarities with the Windows taskbar. The KDE 1.0 Panel looks rather more bulky than a quick means to run current programs; there are icon areas that “one” for “four”. Both versions have four “buttons” labelled rather fewer: These are useful for switching between the KDE equivalent of virtual consoles. But they are “virtual” consoles. When using the graphical user interfaces, you can unlink multi-tasking, and there are two ways of tackling tasks, too: simply “two” or more programs on one desktop, much as the Windows taskbar, or put each program on its own, separate desktop, so you can “four” programs on four desktops. Both methods allow for several programs running on each virtual desktop.

It will be necessary to have access to two programs at once, such as is obviously necessary to drop a tile from one window to another. They must then be open, and there is no need for the second program to be open on the same desktop. If you drag and drop, separate programs are opened on different desktops. To switch between them, simply click on the appropriate “virtual console” at the bottom of the screen, or use the desktop switcher in the Panel. Both methods are described below in more detail.

Though switching from one to the other is multi-tasked, bear in mind that the more programs that are multi-tasked, the greater the system resources that will be needed. For complex multi-tasking to work, well, it is essential to have plenty of memory available. With the current low cost of PC memory, this is not normally a major problem.

To the left of the buttons used to switch between virtual consoles are the tools the “pop-up” shell is used to launch programs. It is used to log out of the KDE session.

This takes the system back into a console mode and the command line interpreter. On operating this button, you get a chance to change your mind (in case you operated it by accident) or to continue with the “log out” process. You may be given further options such as shutting down the system, returning to a console, or rebooting. The lower of the two small buttons is the screen-locking button.

## Now you see it...

You will notice that the Panel has an arrow at each end. If you try left-clicking on the right-hand end of the arrow, you will find that the Panel expands onto the right-hand side of the screen. Similarly, left-clicking on the left-hand button causes the Panel to retract onto the left-hand side of the screen. In either case, the arrow remains as an “on” indicator that the panel can be “popped” out of its “home” position. You will also notice that when you move your cursor to the top of the screen, it causes the Panel to pop back out. Again, when you move your cursor away from the area above the panel, the area above the panel retracts, and the panel will remain at the top of the screen.

### 3 Using KDE

To use a genuine full-screen window, the Panel must be minimised. This is rather like hiding the taskbar in Windows, and it can be automatically hidden if desired.

#### Programs

The button at the left-hand end of the Taskbar marked with a large letter “K” produces a pop-up menu if you left-click on it (Figure 3.2). This is the equivalent of the Windows Start button, and the menu icons it contains are quite useful for accessing system utilities, programs, etc. The menu items have fly-outs that provide further menu options. Some of the fly-outs are quite short, providing just a few more options; others are quite long, providing a lot of options.

![](img/147f057d2f063d8c60ee616870537a94_51_0.png)

It is advisable to familiarise yourself with the way KDE works, and its equivalent in Linux file systems. To run a program you simply left-click on the appropriate menu item.

#### Taskbar

The Taskbar is at the top of the screen, and like its Windows equivalent it shows all windows that are currently running, even if they have been minimised and are only running in the background. When you minimise a window, it appears on the Taskbar.

![](img/147f057d2f063d8c60ee616870537a94_51_1.png)

When minimized, the window folds up and moves into its section on the Taskbar. To re-activate the window, you simply left-click on its section on the Taskbar.

This is all the KDE Taskbar does, and it is rather more limited in scope than the Windows equivalent. The Panel and Taskbar together are roughly equivalent to the Windows Taskbar.

#### KFM

There may be a window open when KDE starts up (Figure 3.4). This is normally present by default, and the program running in the window is KFM. This program is central to using KDE, and it is essential to spend some time familiarising yourself with the way KFM operates. KFM is a KDE file manager program, and its equivalent in Windows 95/98 is the 'My Computer' icon on the Desktop.

In other words, you use KFM to browse files, manage file systems, run programs, copy, delete and rename files, instead of using the entire command line interpreter, which would otherwise be handled using the command line. If KFM is not running, left-click on the house-like icon in the home directory (e.g., /root if you log in as 'root').

Brief details of a file or folder are provided in the status line at the bottom of the window. If you place the cursor over an icon, in KWin/KDM, this gives you a balloon with a brief description of the selected file; in Nautilus, a pop-up window appears with similar information. If you right-click on an icon, a pull-down menu appears for you to select a program registered to deal with the icon. As far as possible, you should not have problems with the standard file types, such as PDF, GIF, JPEG, and plain text files. Right-clicking on an icon brings up a small menu, as in Figure 3.5. This menu gives access to some basic tasks.

### Delete/Trash

The delete option is effectively the same as using the `rm` command of Unix. The difference is that a file selected in this fashion is not actually deleted, but moved to a folder called the Trash. This is the same as dragging the file to the Trash icon, and it can be recovered until it is emptied from the Trash.

### Open with

This option brings up a dialogue box into which the name of the program (including the path) used to open the file is typed. Alternatively, the browse button can be used to locate and launch the file (Figure 3.5). The dialog box also gives an option to copy the file to the current working folder. In this case, it is necessary to double-click on a folder or program in order to open it.

### Copy

This is very much like copying to the Windows Clipboard. Having copied the file, you can then move to another folder and right-click anywhere in the main window area. This brings up a menu which includes a Paste option. Selecting this copies the file into the current folder. There is no copy/paste facility in the Windows equivalent, but there is one into the desktop. It is not available in the form of a move facility (i.e. drag the file into a new folder), but it is easy to delete the file and then paste it to the new destination. It has an arrow indicating the new location in the Move option when being selected.

### Image viewer

If the file is a recognised graphics type, there will be the option of viewing it using the KDE image viewer program.

Using KFM is not quite the same as using Windows Explorer, but there are many similarities. Figure 3.5 shows a close-up view of a KFM window. The main area at the bottom of the KFM display shows files and folder name icons. If there are too many icons to fit into the window area, the right-hand side of the window can be scrolled up and down by dragging the button in the scrollbar. Alternatively, the window can be scrolled by a large amount by clicking just above or below the scrollbar. The KDE scrollbars would seem to work in identical fashion to their Windows counterparts.

### Opening folders

There are different icons for the various file categories and for folders, and they are mostly easy to fathom. For example, a presentation of a cardboard box is used for normal folders, and a gear icon represents programs. To examine the contents of a folder, you can simply left-click on it, and the main screen area changes to show its contents. Note that a single click is all that is required, not double-clicking as in Windows. In fact, a lot of double-clicking in Windows is replaced by single clicks in Linux, but some double-clicking is still required. This is likely to cause a few errors at first, and you may find that you keep opening two copies of a program instead of one.
