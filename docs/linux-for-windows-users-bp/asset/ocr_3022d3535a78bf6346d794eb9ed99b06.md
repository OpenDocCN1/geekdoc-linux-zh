shown here, with anyone able to read the file but only the user having permission to edit or erase it. Suppose that you were not happy with the default settings, and you decided to make the file totally inaccessible to Others, and you wanted anyone in the group to be able to edit it. The set-up would have been changed, as in this modified table.

|       | Read | Write | Execute |
|-------|------|-------|---------|
| User  | On   | On    | Off     |
| Group | On   | On    | Off     |
| Other | On   | Off   | Off     |

The Execute switch only applies to program files, and can be used to prevent unauthorised use of software. However, this is not something that is normally needed, and it is access to data files that you will wish to restrict to certain users.

# ## Listing

If you wish to display permissions for a file when using the command line, the interpreter use the *l* option with *ls* *l* when using the command line interpreter, use the *l* option, as in this example:

```
ls -l textdoc
```

Information on the file is displayed in the form of ten text characters. The first character is the file type, and is a hyphen for normal files. There is a range of other choices, such as “d” for directories and “l” for links. This leaves the next nine characters to represent the nine permissions switches. This is the order in which they appear:

+   1. Owner Read
+   2. Owner Write
+   3. Owner Execute
+   4. Group Read
+   5. Group Write
+   6. Group Execute
+   7. Others Read
+   8. Others Write
+   9. Others Execute

The default for an ordinary data file would therefore be “-RwR----R-”. The other information provided are the Owner and Group names plus the date and time that the file was created or last modified. It is possible to change file permissions using the *command* line interpreter and the *chmod* command. This works on the basis of using numbers to represent different types of permission, with the total value for the required permissions being used in the command. The total values needed are the number and the type of permission each one represents:

| Number | Permission Type     |
|--------|---------------------|
| 0      | No permission at all|
| 1      | Execute permission  |
| 2      | Write permission    |
| 4      | Read permission     |

If a file had read and write permission but you needed to change it to a read-only file, a number of ways it could be done would be: ConquiseLy, if the file was owned by the user, you can just use the built-in command line editor, if you just wish to set up a read-only file, a modified version of the *chmod* command will set up a read-only file, so as to keep people with other access types out of that particular file. This particular case there are three types of permission which can be used: (4+2+2=6). If, for example, a user wanted to restrict the permission for a file so that only the file owner could read it, the command could be: chmod *640* *lexdoc*. If you need to change permissions for two or three files at the same time, this is possible and just requires all the filenames to be included in the command with a space between each one. Of course, the same level of permission will be set for all the files included in the command. This version of the command would also set permissions for the files called “text1” and “text2”:

```
chmod 640 textdoc
chmod 640 lexdoc text1 text2
```

Changing permissions from the command line is not that difficult, but it is fairly easier using KDE and KFM. Where possible it is probably better to stick with KFM for this type of thing.

# ## Other Switches

If you look at the Properties window in KFM, you will notice that there are three other switches, all in the Special header. These are the Sticky, and the Set User ID switch. The exact function of these a bit obscure, but the basic idea seems to be to set the ID of a running program so it can have special powers. The Set Group ID switch is similar, but sets the ID for group programs.
