
## Saving in Emacs

The insert and overwrite modes can be toggled using the insert key. Unfortunately, this does not work with Emacs (or other Linux software), and pressing the insert key simply produces a warning "beep". I do not know if there is an override mode, but I have never found a way of switching into it. Once you have completed the test file, you can save the file by pressing Ctrl-x followed by Ctrl-s. Virtually all Emacs commands require the user to simultaneously press the Control key and another key, or the Meta key plus another key. In some cases, as in this example, the commands require a sequence of two pairs of key presses. To exit Emacs, use the Control-x and Control-c sequence. As long as these commands are executed correctly, the file will be saved.

- The list of available Emacs commands is huge, but you can get away with using just a few of them. This is a list of some of the more important Emacs commands.

### Save

- Control-x Control-s Saves to disc
- Control-x Control-w Save as
- Alt z Save text to disc and exit

### Open

- Control-x Control-f Open
- Control-x Control-i Opens file which replaces the contents of the current buffer
- Control-x Control-p opens file and inserts it at the current cursor position

### Cursor Movement

- Control-f Move forward one character
- Control-b Move backward one character
- Control-a Move to beginning of line
- Control-e Move to end of line
- Control-n Move to next line
- Control-p Move to previous line

### Delete/Insert

- Control-c Control-d: Delete next character
- Control-c Alt-d: Delete next word
- Control-c Control-k: Delete to end of line
- Control-c Return: Insert a new line
- Control-c Control-i: Insert a tab character (implied from context, or simply Control-i)
- Control-c Space: Insert a space character (implied, though usually just space)

*Note: The original text listed "Control-c" repeatedly with separate descriptions. Based on standard Emacs keybindings and the context "Insert a space character", "Delete next character", etc., the mappings are likely:*
- Space: Insert a space character
- Control-d: Delete next character
- Alt-d: Delete next word
- Control-k: Delete to end of line
- Return: Insert a new line

## Adding users

Linux is, of course, a multi-user system, and it is possible to have a large number of users share the same computer. This is a subject that is covered in more detail in chapter 4, and here we will only cover the addition of users to the installation process. At least one user account must be created during the installation process, and this is the "root" account for the superuser. The "root" account has complete access to the system and can make drastic changes to the system. For this reason, due care has to be exercised when logging in as "root", or the system could be inadvertently trashed. The normal way of handling things is to log in as "root" when changes must be made to the system, but to log in as a normal user at other times, even if you are the only person who will use the computer.

There may be an opportunity to add users during the installation process, and if this is the case, I would advise adding at least one user (you) at this stage. In fact, it is a good idea to add further accounts later on if it will be needed. If the command line needs to be used to add further users, the `adduser` command can be used from the command line. This is necessary to add users in most typical installations, but it might be included in the installation if you have installed some form of non-typical distribution. Note that the `adduser` command is only available when you are logged in as "root". To add a user called "Fred", you would use this command:

```bash
adduser Fred
```

Looking for first available UID... 501
Looking for first available GID... 500
Adding login: Fred... done.
Creating home directory: /home/Fred... done.
Creating mailbox: /var/spool/mail/Fred... done.
Don't forget to set the password.

This output tells you that Linux has found the next available user identity (UID) and group identity (GID) numbers, which it has used, and that it has added the name Fred to the login process. It has also produced the directories that will be needed by the new user. The last line reminds you that the password for the new user must be set; otherwise, the account will not be usable. To set or change the password for the 'Fred' account, we simply run `passwd` in a shell. As we wish to set the password for the 'Fred' account to 'hello', the following command would be used:

```bash
passwd Fred
```

Note that you must be logged in as 'root' for this to work. You will be asked for the new password, and having typed it once, you will be asked for a repeat to ensure that you have not made a mistake when typing it in the first time. As usual, the password will not be displayed on the screen, so it is difficult for any onlookers to see what you are typing. To set the password as 'hello', you would therefore type in 'hello' twice:

```bash
hello
hello
```

Having set the password for the 'Fred' account, it should then be possible to log in as 'Fred' using the 'hello' password. In order to change a password, you simply log in as the appropriate user and then issue this command:

```bash
passwd
```

When prompted, you must supply the old password, followed by the new password twice. The new password is then in operation and must be used whenever you are required to authenticate as that user. Suppose the password for the user 'fred' was set to 'too-simple'; the system might reject simple passwords or those lacking complexity. In that case, the 'passwd' command will prompt you to try again, and keep trying until it accepts a choice of password.

## Tar

When using Linux, you are likely to encounter *tar* files before too long. These are tape archive files, and the *tar* command is primarily intended as a simple backup facility. The basic action of the *tar* command is to take a group of files and merge them into one long file. The same program can be used to restore the original files. Modern versions of this command can also compress the files so that they require less storage space. This command is more or less the Linux equivalent of a MSDOS or Windows ZIP compression program.

Modern computer storage tends to deal more in gigabytes than in megabytes, and compressive backing up is not impractical unless your computer is equipped with some form of mass storage device that can read and write data with the same kind of swiftness that the hard disk can read and write. Unless you have an Iomega Zip, Iomega Jaz, or a similar device of the same sort, then you are not going to be able to make a backup of 750 megabytes of data in 5 minutes. However, using a CD-R or CD-RW, you can back up 750 megabytes in about 15 minutes. If you want to back up your files, you can use a USB device with at least 1GB of storage. This will allow you to back up your files in a matter of minutes.

Even if you do not use tar files from time to time, *tar* will most certainly have to deal with the use of tar files. Programs are often distributed as *tar* files. It is quite likely that there will be problems with *tar* files that are larger than 1.5GB. The reason is that a traditional tar file is limited to 1.5GB. If you want to back up files larger than 1.5GB, you can use the `-G` option (or similar splitting options depending on the version) to create a multi-volume tar archive. This will allow you to back up files larger than 1.5GB.

The *tar* program is reasonably simple to use, but matters are complicated somewhat by the large number of options available. For full details of the options available, refer to the online manual. These are just some of the common *tar* options.
