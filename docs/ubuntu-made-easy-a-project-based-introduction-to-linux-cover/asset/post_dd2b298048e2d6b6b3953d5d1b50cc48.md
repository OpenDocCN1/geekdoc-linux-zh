
You should use the rmd command, like the rm command, with caution. There are no do-overs with rmd once you remove a directory or folder with this command, it is gone for good.

To try this command, you can get rid of that sub folder you created. Type rmdir command_exp/sub and press ENTER. The sub folder should now be gone. Finally, to run out the fun, use the rmdir command once to get rid of the command_exp folder you created earlier. You know the drill: rmdir command_exp and press ENTER.

## # § chmod

In Chapter 7, you learned how to change file permissions via the Nautilus interface. This is without a doubt an easy way to go about such things, sometimes it might be easier to use the command-line approach.

The command for changing file permissions is chmod (change mode). To use it, type the command followed by the permissions you want to extend to a file and the location of the file itself. For example, let's say you copied a JPEG file, mybirthday.jpg, from a CD to the personal subfolder within the Photos folder on your hard disk and the file is protected. To change the file so that you have write permissions (meaning that you can alter the file), you would type the following and then press ENTER:

```
chmod 644 ~/photos/personal/mybirthday.jpg
```

To change the permissions of all the files and subfolders (and all the files within those subfolders) in one sweep, you can add the -R (recursive) flag to the chmod command. The command would be as follows:

```
chmod -R 744 ~/photos/personal
```

The number 744, by the way, extends read and execute (run) permissions to the owner, but gives read-only permissions to everyone else. This is a pretty safe choice when in doubt. If you want to figure out permissions numbers for yourself, it's pretty easy. You are basically dealing with three position numbers, each of which has eight possibilities (0–7). The left slot represents permissions for the owner, the center slot represents permissions for the group, and the third slot represents permissions for others. The meanings of the numbers themselves as follows:

- 7 Read, write, and execute permissions
- 6 Read and write permissions
- 5 Read and execute permissions
- 4 Read-only permissions
- 3 Write and execute permissions
- 2 Write-only permissions
- 1 Execute-only permissions
- 0 No permissions

Figure 8-5 points out the meaning of each of these numbers and what each number slot represents. In fact, if you don't mind a bit of simple addition, things are even easier to understand. To start with, remember that 1 = execute, 2 = write, and 4 = read. Add any of those numbers together, and you get the other permission combos. For example, 1 (execute) + 4 (read) = 5 (read and execute). As you can see, permissions aren't all that complicated.

![](img/d35fa962e6f9664d66dc83916f426418_171_0.png)

Figure 8-5: The meaning of permission numbers

If you're more of a letters than numbers sort of person, you'll be happy to know that there is another way to change permissions that is probably even easier. With this approach, you only have to deal with two groups of letters and the symbols + and -.

The first group consists of the following:

- + User (specified group of users)
- - Others (anyone who is not the user or a member of the group)
- - All (all of the above)

The second group consists of the following:

- + Read
- - Write
- - Execute

You might be able to figure out how this is all going to work, but I'll spell it out in case your intuition is worn out for the day. Let's say you want to change the permissions of a file (butterhaters.txt), for example) so all users on your machine can read and write to it. After opening a Terminal window, you can make the change by typing chmod +rw butterhaters.txt

Oops! Just remembered that don't want anyone changing the content of the file, eh? Well, to take back the write permissions for that file, just need to type chmod a-rw butterhaters.txt and press ENTER. As you can see, the + gives permissions, while the - takes away.

That's much simpler, you've got to admit.

## # $ sudo

When you tried to install software from the Ubuntu Software Center in chapter 6, you were asked to input your password. The reason for this, as mentioned, is that the Ubuntu Software Center installs the files it downloads in various folders throughout your system, almost all of which are protected. By supplying your password, you are telling the system that you, as holder of the password, you have the right to allow the Ubuntu Software Center to do that.

The command-line version of that same process is the sudo command. To perform an operation in a folder that is write protected, you would first type sudo and then the command you want to perform. For example, if you wanted to copy an icon image—let it be myicon.png—to the globally-located and write-protected pixmaps folder (/usr/share/pixmaps), you would type cp myicon.png /usr/share/pixmaps.

After typing a command preceded by the sudo and pressing ENTER, you will be prompted for your password and press ENTER again, the command will be executed. I should mention that once you input your password, it will stay in memory for about five minutes, so you won't be prompted for your password when using the sudo command.

## # $ locate

Now that you are familiar with the sudo command, let's take it out for a spin by working with the locate command. The locate command is essentially a command-line alternative to the graphical Search tool found in the Places menu. Using the command is quite easy: Simply type the command followed by a space and the name of the file you want to find.

Before you can use this command, though, you should update the database of filenames that locate uses. This is where the sudo command, along with another command, updated, comes into play. Just type sudo updated and press ENTER. Type your password when asked to do so—and then it will seem as though nothing is happening. But don't worry. As long as the cursor in your Terminal is blinking, the process is being made, and when your user prompt returns, you will have successfully created the database file. After that, you can use the locate command.

Oh, and in the future if you think that the process seems to be taking longer and longer, don't worry—it is. The more files and applications you add to your system, the longer it will take to catalog them all.

To make this new command, let's look for LibreOffice icon, libreoffice.png. Just type the following and ENTER:

locate libreoffice.png
