
# I Get an Error About Unauthenticated Packages

If you get an error message about unauthenticated packages when you try to install a program, try the following:

- Update the Update Manager from the Dash.
- Click the Check button and, if prompted, enter your password. The package list will be updated, along with all the files that are used to check whether your packages are "authentic".
- When the Update Manager has finished updating the package list, close and try to install your program again.

If you're still getting the error message, you may have added a software repository without adding its GPG key required to do the authentication stuff that the error message is talking about. If this is the case, look at "Adding Extra Software Repositories" on page 88 for instructions on how to add the GPG key for a repository.

# I Get a dpkg error

There are couple of common reasons why you might get an error message related to dpkg when you try to install, update, or remove a software package.
If you get an error saying E: Sub-process /usr/bin/dpkg returned an error code (1), you could have a broken package on your system. Here are some techniques you can try to fix a broken package:

- Open the Terminal and searching for it in the Dash.
- Type sudo apt-get install --fix-broken and press ENTER. Type your password when prompted and press ENTER again. This command looks for broken packages and tries to fix them.
- With any luck, this will fix the problem; try installing a package via the Ubuntu Software Center to see whether you still get the dpkg error.
- If you still get the error message, sudo dpkg --configure -a into the Terminal and press ENTER. This command tries to fix half-installed packages if there are any.
- Try installing a package from the Ubuntu Software Center. At this point, if you're still getting an error message, ask for help on the Ubuntu forums.

If you get an error message saying E: Could not lock /var/lib/dpkg/lock - open (11: Resource temporarily unavailable) or E: Unable to lock the administration directory (/var/lib/dpkg/), you might be running more than one manager (APT frontend). For example, if you are installing a package using the apt-get command in a Terminal while simultaneously trying to install a program with the Ubuntu Software Center, you will get this error message.

Wait until one of the package managers finishes what it's doing, and close it and try to use the other one again. If no other package managers are running, you won't get this error message. If you don't have any other package managers running, the Update Manager could be running in the background and causing the problem. Wait for a few minutes for the Update Manager to finish what it's doing and try again.

NOTE You might also receive these error messages if you are using the apt-get command in the Terminal without prefixing it with sudo. See Chapter 8 for the correct commands to use.

# I Have a Broken Update

If you update your computer using Update Manager but receive an error message saying that you have a broken update, try the instructions in "Get a dpkg Error" on page 397 to fix the problem. If that doesn't work, try asking the Ubuntu forums for help—there may be a bug in the package that was updated when the error occurred.

# A Software Repository/PPA That I Added Doesn't Show Up in the Software Center

"Adding Extra Software Repositories" on page 88, I mentioned that might take a while for any repository you add to show up in the Ubuntu Software Center. This is because APT is updating its list of software sources in the background, unfortunately, doesn't let you know when it has finished. If you've been waiting for a while and have already tried closing and reopening the Software Center (as suggested in Chapter 6) to no effect, then it might be time to break out the big guns and force the Software Center to take notice of the new repository.

To do this, first close the Ubuntu Software Center. Then bring up a Terminal, and use sudo apt-get update. Enter your password when prompted and for APT to update its list of software sources. Open the Software Center again and click the arrow immediately to the right of the All Software button to see if the repository/PPA has finally appeared.

If that still hasn't done the trick, there could be a problem with the repository itself. If this is the case, you might have seen an error message when you typed the apt-get command in the Terminal. For example, if the repository no longer exists, you would have seen an error message starting with "Failed to fetch. There's nothing you can do if the repository has vanished, I am afraid!

Alternatively, there could have been a problem with the GPG key for the repository, which will prevent the Software Center from recognizing it. Follow the instructions in "Adding Extra Software Repositories" on page 88 to manually download and add the correct GPG key for the repository if you suspect that is the problem.

# Common Problems with Applications

So many applications are available for Ubuntu that it it would be impossible to go through each one and point out what might possibly, someday, go wrong. Instead, in this section I've chosen to provide some general advice on how to deal with behaving programs, plus I've given you a sneaky little on a common Firefox problem. If you need to handle something specific, it's never a bad idea to try looking at the help files for a given program. Selecting Help Contents should get you to a manual for most software. Failing that, a Google search often gets you the trick for it.

# Firefox Says It's Already Running

When you exit Firefox, sometimes takes a while to close itself down properly—the window will disappear, but Firefox could still be running somewhere in the murky depths of your computer. When you try to open Firefox again, you may receive a message that Firefox is running in the background so you can't open a new window. This is no good because you want a Firefox that you can see! If this happens, open a Terminal, killall firefox, and press ENTER. (The command you're typing in all lowercase). This will force Firefox to shut down immediately. With that done, if it's still not working, try to open Firefox again, and the window should pop up as normal. Following the advice at help://://support.mozilla.org/en-US/hb/Firefox%20is%20already%20running%20but%20is/%20not_responding/.

# A Program Always Crashes

If you have a program that keeps crashing, running it in a Terminal to see what's going wrong. You'll have to get the name of the command to run the program first—see “Reporting a Bug” on page 355 for information on how you can find it. Once you have the command, type it into the Terminal and press ENTER. The program should run as normal, so keep using until it crashes. When it does, look at the Terminal to see whether it leaves any clues to what's going wrong. Error messages in the Terminal can be cryptic, so you might want to ask on the forums or IRC (which of both are discussed in Chapter 21) if he knows what it means.

If the messages in the Terminal are no help, you should report a bug. See “Bugs, Bugs, Glorious Bugs” on page 354 for details.

# A Program Won't Start

If a program doesn't start when you click it in the Dash, try running it in the Terminal, as described in the previous section. It could be crashing after starting and might leave some information about the crash in the Terminal.

# My Computer Is Running Slowly

Certain tasks take up lots of computing power and cause your computer to run slowly. Burning a CD, installing software, and converting music files to a different format all to strain your system, so you shouldn't be surprised if things feel a little sluggish like something that is running. But what if your computer is running slowly even if you're not doing anything? You can investigate the cause by opening System Monitor with the Dash. Select the Processes tab and click the % CPU heading—this will sort the list of processes in order of how much of the processor they are using.
