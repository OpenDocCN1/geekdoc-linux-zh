As in previous examples, RPM executes the $\S prep$, $\S build$, and $\S install$ sections, handles any special documentation files, creates a binary package file, and cleans up after itself.

The final step in the build process is to create a source package file. As the output shows, it consists of the $\S pec$ file and the original sources. A source package may optionally include one or more patch files, although in our example, $\S cdplayer$ requires none.

At the end of a build using the $-\S a$ option, the software has been successfully built and packaged in both binary and source form. But there are a few more build-time options we can use. One of them is the $-\S l$ option.

# 12.1.6. $\S rpm \S -b\S l$: Check $\S files$ List

There’s one last option that may be specified with $\S rpm \S -b$, but unlike the others, which indicate the stage at which the build process is to stop, this option performs a variety of checks on the $\S files$ list in the named $\S pec$ file. When $\S l$ is added to $\S rpm \S -b$, the command does the following:

+   Expands the $\S pec$ file’s $\S files$ list and checks that each file listed actually exists.
+   Determines what shared libraries the software requires by examining every executable file listed.
+   Determines what shared libraries are provided by the package.
