

你也可以使用私钥对消息进行身份验证。如果主机A使用其私钥对消息进行加密，并将该消息发送给主机B，那么主机B（以及网络上的任何其他主机）都可以轻松地从主机A那里获取匹配的公钥来解密该消息。通过成功解密消息，主机B证明了该消息必定是使用主机A的私钥加密的。由于主机A是网络上唯一拥有此私钥的计算机，因此主机B已证明该消息是由主机A发送的，而非由其他冒充该消息的计算机发送的。

在Linux系统上提供非对称加密的两种最常见技术是**Secure Shell (SSH)**和**GNU Privacy Guard (GPG)**。

## 使用SSH

回顾第12章可知，SSH允许你通过加密两台计算机之间传输的所有流量来安全地管理远程Linux系统。默认情况下，SSH使用**Rivest Shamir Adleman (RSA)**非对称算法加密数据，并使用**Digital Signature Algorithm (DSA)**非对称算法对数据进行数字签名。

系统范围的RSA和DSA公钥/私钥对是在SSH守护进程首次启动时生成的。这些密钥对存储在/etc/ssh目录中，以供所有后续会话使用：

- `ssh_host_dsa_key` 包含DSA私钥
- `ssh_host_rsa_key` 包含RSA私钥
- `ssh_host_dsa_key.pub` 包含DSA公钥
- `ssh_host_rsa_key.pub` 包含RSA公钥

对于远程管理而言，系统范围的密钥已经足够，但SSH也可以用于保护其他网络服务所使用的网络流量，方法是将网络流量封装在加密的SSH数据包内（该过程称为**隧道化**）。如今，SSH隧道被各种各样的程序所使用。

![](img/c27875544958897d817484d558c208c8_685_1.png)

大多数使用SSH隧道的程序要求使用这些程序的所有用户都拥有自己的SSH密钥。回顾第12章可知，`ssh-keygen`命令可以生成或重新生成SSH密钥。如果你运行`ssh-keygen -t rsa`命令，将在~/.ssh目录中创建以下文件：

- `id_rsa` 包含用户的RSA私钥
- `id_rsa.pub` 包含用户的RSA公钥

![](img/c27875544958897d817484d558c208c8_686_0.png)

图14-5 密码和密钥工具

或者，如果你运行`ssh-keygen -t dsa`命令，将在~/.ssh目录中创建以下文件：

- `id_dsa` 包含用户的DSA私钥
- `id_dsa.pub` 包含用户的DSA公钥

![](img/c27875544958897d817484d558c208c8_686_1.png)

> `ssh-keygen`命令会提示你选择一个可选的密码短语来保护私钥。如果你设置了密码短语，每次使用该私钥时都需要输入该密码短语。

然后可以使用这些密钥来保护与其他计算机的通信。然而，在SSH用于加密数据之前，每个用户都需要先对其他计算机进行身份验证。由于私钥也可以用作一种身份验证形式，你可以为用户账户创建一个**SSH身份**（使用**ssh-add**命令），并使用**SSH代理**（`ssh-agent`）通过数字签名自动与其他计算机进行身份验证。在包含桌面环境的系统中，可能有一个额外的实用程序提供SSH代理和SSH身份功能。例如，在Fedora 20中，SSH代理和SSH身份由GNOME密钥环守护进程（`gnome-keyring-daemon`）提供，并由图14-5中所示的密码和密钥实用程序进行管理。你可以在GNOME桌面环境中通过导航至 Activities, Open Applications, Utilities, Passwords and Keys 来启动此实用程序。

## 使用GPG

GPG是Pretty Good Privacy (PGP)系统的开源版本，该系统在1990年代非常流行，用于在将电子邮件和电子邮件附件发送到互联网上的其他主机之前对其进行加密。每个GPG用户都有一个公钥/私钥对，用于加密以及身份验证。GPG身份验证使用一种信任模型，涉及用户使用其私钥对其他用户的公钥进行数字签名。例如，假设用户A对用户B的公钥进行了数字签名，反之亦然。这使得用户A和用户B可以在无需身份验证的情况下发送和接收电子邮件。如果用户B对用户C的公钥进行了数字签名，反之亦然，那么用户A、用户B和用户C可以在无需身份验证的情况下发送和接收电子邮件。

与SSH一样，GPG通常分别使用RSA和DSA密钥对进行非对称加密和数字签名。这些密钥及相关GPG配置选项存储在每个用户的~/.gnupg目录中。

虽然你可以使用**gpg**命令来管理密钥、加密数据以及对其他用户的公钥进行数字签名，但使用图形化工具（如Fedora 20中的密码和密钥实用程序）要容易得多。此外，许多Linux图形化电子邮件程序（如Evolution）都内置了GPG管理工具和向导，允许你轻松配置GPG密钥。

## 检测入侵

虽然你可以在Linux计算机上采取许多安全措施，但总有可能有人通过本地或跨网络的方式获得对你系统的访问权限。幸运的是，日志文件包含可以指示是否确实发生入侵的信息或不规则性。为了充分利用存储在日志文件中的信息，你应该定期分析日志数据库的内容（如果系统使用Systemd）以及与在你的计算机上运行的网络服务相关的/var/log目录中的日志文件。

至少，你应该审查与身份验证相关的系统事件，以检测是否有未经授权的用户登录了系统。对用户进行身份验证的网络应用程序通常通过**Pluggable Authentication Modules (PAM)**来实现。PAM在使用Systemd的系统上会将信息记录到journald数据库中，在其他系统（如/var/log/secure或/var/log/auth.log）上则记录到/var/log目录下的日志文件中。你还应该检查/var/log/wtmp日志文件，该文件列出了登录系统并获得BASH shell的用户。由于此文件为二进制格式，你必须使用`who /var/log/wtmp`命令来查看它，如下面的输出所示：

如果黑客获得了对你系统的访问权限，他们很可能修改了硬盘上的某些文件以获取更多访问权限、修改敏感数据或破坏服务。**ls**（列出打开的文件）命令可用于列出当前正在被用户和系统进程编辑的文件。因此，你可以使用`lsof | grep root`命令列出root用户当前在系统上打开的文件。如果输出中列出了你当前未正在编辑的关键配置文件，则黑客可能已入侵你的系统。

黑客经常使用缓冲区溢出漏洞来尝试在文件系统内创建由root用户拥有且设置了SUID位的可执行文件。这使得该可执行程序能够以root用户身份运行并访问整个Linux系统。因此，你应该定期使用`find / -type f -perm +4000`命令搜索文件系统中设置了SUID位的文件。

并非所有漏洞利用都需要以root用户身份执行。例如，黑客可能使用用户下载的恶意程序在用户的家目录中创建.forward文件。然后，用户接收到的任何电子邮件都会被转发到.forward文件中列出的电子邮件地址，这通常是一个包含脚本的电子邮件服务器，该脚本会记录用户的电子邮件地址并以该用户的名义发送不需要的电子邮件。为防止此类攻击，你可以在每个用户的家目录中创建一个空的.forward文件，该文件由root用户拥有且权限为0000，以防止用户修改它。

> 如果你创建并运行自定义shell脚本来执行安全检查，可以使用**logger**命令创建系统日志条目，以提醒你潜在的问题。

![](img/c27875544958897d817484d558c208c8_688_0.png)

由于黑客可以在系统上修改的潜在文件列表很长，许多Linux管理员使用诸如tripwire之类的程序来检查重要文件和目录的完整性。你可以使用tripwire对关键系统文件进行校验和，并定期检查这些文件的校验和，以确保它们未被入侵者修改。由于tripwire可用于检测Linux系统上的入侵者，因此被称为入侵检测系统（IDS）。有许多适用于Linux的IDS程序可用于检测试图获得对你系统的访问权限或已经获得访问权限的黑客。表14-5列出了一些常见的IDS程序。

表14-5 常见的Linux入侵检测系统

| 名称 | 描述 |
| :--- | :--- |
| Advanced Intrusion Detection Environment (AIDE) | tripwire的替代方案，具有检查文件和目录完整性的附加功能。 |
| Integrity Checking Utility (ICU) | 一个基于PERL的程序，旨在与AIDE配合使用，以通过网络远程检查Linux计算机的完整性。 |
