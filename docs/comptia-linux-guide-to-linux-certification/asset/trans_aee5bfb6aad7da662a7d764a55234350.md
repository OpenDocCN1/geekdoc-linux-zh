## Linux进程

在本书中，“程序”和“进程”这两个术语是互换使用的。在工作场所也是如此。然而，这两个术语之间存在细微的区别。从技术上讲，**程序**是硬盘上的可执行文件，当执行它时可以被运行。另一方面，**进程**是正在内存和CPU上运行的程序。换句话说，进程是正在运行的程序。

如果在登录到终端时启动一个进程，该进程将在该终端中运行，并被称为**用户进程**。用户进程的例子包括 `ls`、`grep` 和 `find`，更不用说您在本书中执行的大多数其他命令。请记住，不与终端关联的系统进程被称为**守护进程**；这些进程通常在系统启动时启动，但您也可以手动启动它们。大多数守护进程提供系统服务，如打印、调度和系统维护，以及网络服务器服务，如Web服务器、数据库服务器、文件服务器和打印服务器。

每个进程都有唯一的**进程ID (PID)**，使内核能够唯一地识别它。此外，每个进程可以启动无限数量的其他进程，称为**子进程**。相反，每个进程必须由一个现有的进程启动，称为**父进程**。因此，每个进程都有一个**父进程ID (PPID)**，标识启动它的进程。图9-1描绘了父进程和子进程之间关系的例子。

![](img/c27875544958897d817484d558c208c8_417_0.png)

PID不一定按顺序分配给新进程；每个PID都由Linux内核使用的进程表中的空闲条目生成。

请记住，虽然每个进程可以有无限数量的子进程，但它只能有一个父进程。

由Linux内核启动的第一个进程是初始化（或init）守护进程，其PID为1，PPID为0，后者指内核本身。然后，init守护进程在系统初始化过程中启动大多数其他守护进程，包括允许用户登录的守护进程。在您登录系统后，登录程序启动一个BASH shell。BASH shell然后解释用户命令并启动所有用户进程。因此，通过检查PPID系列，Linux系统上的每个进程都可以追溯回init守护进程，如图9-2所示。

## 查看进程

虽然有几个Linux实用工具可以查看进程，但最通用和最常见的是 `ps` 命令。没有参数时，`ps` 命令简单地显示当前shell中运行的进程列表。以下示例显示了用户在tty2上登录时该命令的输出：

```
[root@server1 ~]# ps
PID TTY          TIME CMD
2159 tty2       00:00:00 bash
2233 tty2       00:00:00 ps
[root@server1 ~]#
```

上述输出显示，当 `ps` 命令执行时，在终端tty2上运行了两个进程。每个进程启动的命令 (CMD) 列在其占用的CPU时间 (TIME)、其PID和终端 (TTY) 旁边。在这种情况下，进程运行时间不到一秒，因此经过的时间读数为无。若要了解有关这些进程的更多信息，可以使用 `ps` 命令的 -f 或完整选项，如下所示：

```
[root@server1 ~]# ps -f
UID          PID    PPID  C STIME TTY          TIME CMD
root        2159     2156  0 16:18 tty2     00:00:00 -bash
root        2233     2159  3 16:28 tty2     00:00:00 ps -f
[root@server1 ~]#
```

此列表提供了有关每个进程的更多信息。它显示启动进程的用户 (UID)、PPID、启动时间 (STIME) 以及CPU利用率 (C)，后者从零开始，随着进程在CPU上运行的每个处理器周期而递增。

`ps -f` 命令提供的最有价值的信息是每个进程的PPID和谱系。bash进程（PID = 2159）显示shell提示符并解释用户输入；因为它启动了 `ps` 进程（PID = 2233），所以 `ps` 进程的PPID为2159。

由于守护进程不与终端关联，它们不会通过 `ps -f` 命令显示。要显示跨所有终端并包括守护进程的完整进程列表，您可以将 -e 选项添加到任何 `ps` 命令，如下面输出所示：

```
[root@server1 ~]# ps -ef
UID          PID    PPID  C STIME TTY          TIME CMD
root          1       0  0 21:22 ?        00:00:00 /usr/lib/systemd/systemd
root          2       0  0 21:22 ?        00:00:00 [kthreadd]
root          3       0  0 21:22 ?        00:00:00 [ksoftirqd/0]
```
