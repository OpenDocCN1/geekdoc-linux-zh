
## 13.1 incr Tcl

The following example is adapted from the [incr Tcl] introduction (itcl-intro/itcl/tree/tree2.itcl). It implements a tree structure, similar to that developed in Chapters 5 and 6 of this book.

The class command defines the Tree class with the private data members key, value, parent, and children.

The class methods are defined with the method command and can be defined either in line (as the methods add, clear, and parent are defined) or similarly to function prototypes (as the get method defined). When a method is defined as a function prototype, the code that implements the method can be placed later in the script or in a separate file.

### Example 13.1-1

```
class Tree {
    private variable key ""
    private variable value ""
    private variable parent ""
    private variable children ""

    constructor (n v) {
        set key $n
        set value $v
    }
    destructor {
        clear
    }

    method add {obj} {
        $obj parent $this
        append children $obj
    }
    method clear {} {
        if {$children != ""} {
            eval delete object $children
        }
        set children {}
    }
    method parent {pobj} {
        set parent $pobj
    }
```

```python
public method get {option}
method contents () {
  return $children
}
body Tree::get {{option -value}} {
  switch -- $option {
    -key { return $key }
    -value { return $value }
    -parent { return $parent }
  }
  error "bad option \$option"
}
```

### Example Script

```bash
# Create a Tree
#
Tree topNode key0 Value0
#
# Add two children
#
topNode add [Tree childNode1 key1 Value1]
topNode add [Tree childNode2 key2 Value2]
#
# Display some values from the tree.
#
puts "topNode's children are: [topNode contents]"
puts "Value associated with childNode1 is [childNode1 get -value]"
puts "Parent of childNode2 is: [childNode2 get -parent]"
```

### Script Output

```text
topNode's children are: childNode1 childNode2
Value associated with childNode1 is Value1
Parent of childNode2 is: ::topNode
```

Expect adds commands to Tcl that make it easy to write scripts to interact with programs that use a character-based interface. This includes programs such as telnet and FTP that use a prompt/command type interface or even keyboard-driven spreadsheet packages as sc.

Expect can be used for tasks ranging from changing passwords on remote systems to converting an interactive hardware diagnostics package into an automated test system. When you link the expect extension with the Tk libraries, you get an interpreter (expecttk) that is ideal for adding a GUI to dialog-based programs.

There are three indispensable new commands in expect:

```
Syntax: spawn options commandName commandArgs
```

- *spawn* Starts a new process and connects the process's stdout to the expect interpreter.
- *options* The spawn command supports several options, including
  - -noecho The spawn will echo the command line and arguments unless this option is set.
  - -openfileID The -open option lets you to process the input from a file handle (returned by open) instead of executing a new program. This allows you to use an expect script to evaluate program output from a file well as directly controlling a program.
- *commandName commandArgs* The name of the process to start and the command line arguments.

```
Syntax: expect ?-option? pattern1 action1
```

- *expect* Waits for a pattern to appear in the buffer.
- *?-option?* Options that control the matching are:
  - -exact Match the pattern exactly.
  - -re Use regular expression to match the pattern.
  - -glob Use glob rules to match the pattern.
- *pattern1* The pattern to look for.
- *action1* The command to execute when the pattern is matched.
- *pattern2 action2 ...* Additional pattern-action pairs.

The following example shows how a set of interactions with an archie server can be automated. Note that when spawn is defined, a variable named spawn_id is created in the global scope to allow other commands to access it. If a pattern is recognized, the associated action is executed. If the process is closed, the eof action will be evaluated. This is similar to the default behavior of the switch command, but you don't need to check for the timeout the "unknown" or "unreachable" strings.

- *exp_send* Sends a string to the slave process.
- *expect_user* Waits for input from the user and echoes it back.
- *expect_spawn* Starts a new process.
- *expect_close* Terminates the process.
- *set_timeout* Sets the maximum time to wait for a pattern.

### Example 13.2-1

```expect
#!/usr/bin/expect
set timeout_type c
set timeout 10
set site "expect.nist.gov"
set user "guest"
set password "guest"

spawn telnet $site

expect {
    "login:" { exp_send "$user\r" }
    "Password:" { exp_send "$password\r" }
    "Welcome"
    timeout  { puts "Timed out waiting for login"; exit 1 }
    "eof"     { puts "Connection closed"; exit 1 }
}

loop {
    expect {
        "*" {
            exp_send "help\r"
            continue
        }
        "quit" {
            exp_send "quit\r"
            exit
        }
        "result" {
            puts $
        }
    }
}
```
