## 3.4 Input/Output in Tcl

It's difficult to perform any serious programming without accepting data and delivering results. Tcl abstracts the input and output into two input commands and one output command. Using these three commands, you can read or write to any file, pipe, device, or socket. All I/O in Tcl is done through channels. A channel is an abstraction model similar to the Unix stream. The Tcl channel abstraction is extended beyond the stream layer to include sockets and pipes. Channels are accessed by handles, which are treated as files. The Tcl commands that open channels are gets and read. These channels are predefined in Tcl:

- stdin Standard input: keyboard or redirected file.
- stdout Standard output: usually the screen.
- stderr Error output: usually the screen. Note that Windows does not distinguish between stdout and stderr.

### 3.4 Output

The puts command sends output to a channel. It requires a string as an argument. By default, this command will append a newline character to the string.

```
Syntax: puts ?-noneline? ?channel? outputString
```

```
puts Send a string to a channel.
?-noneline? Do not append a newline to the output.
?channel? Send output to this channel. Else, send to standard output.
outputString The data to send.

## 3.4.2 Input

The Tcl commands that input data are gets and read commands. The gets command will read a single line of input from a channel and strip off any newline character. The gets command may return the data that was read or the number of characters read. The read command will read a certain number of characters, or until the end of data, and always returns the data. The gets command is best for interactive I/O. The read command is best used when there is a large body of text to read, such as a file or a socket connection that will have a large amount of data to deliver to the program.

Syntax: gets channelID ?varName?

-   gets Read a line of data from a channel.
-   channelID Read from this channel.
-   varName? If this variable is present, the data will be stored in this variable, and the number of characters read will be returned. If this argument is not present, the line of data will be returned.

# Example 3.4.2-1

```
% gets stdin # A user types "Hello, World" at keyboard.
Hello, World
% gets stdin # A user types "Hello, World" at keyboard.
Hello, World
% puts $inputStream
Hello, World
```

The read command can be invoked to read characters from a channel until the specified number of characters are read, or to read until an End-of-File is returned by the read. If the read command is invoked to read a certain number of characters and an End-of-File is encountered before the requested characters are read, it does not generate an error. The read command returns the characters read. The read command may strip off the final newline character but by default leaves newlines intact.

Syntax: read channelID numBytes

-   read Read a certain number of characters from a channel.
-   channelID The channel to read data.
-   numBytes The number of bytes to read.

Syntax: read ?-nonline channelID

-   read Read data from a channel until an End-of-File (EOF) condition.
-   ?-nonline Discard the last character if it is a newline.
-   channelID The channel to read data.

## 3.4.3 Opening Channels

A channel can be created by an open command or by a socket command. The open command can be used to open a channel to a file, a device, or pipe to another program. The socket command can be used to open a client socket to a server or to open a server socket that will listen for clients.

The open command is used to create a channel to a file, device, or pipe to another program.

Syntax: open fileName ?access? ?permissions?

-   open Open a file, device, or pipe to another program.
-   fileName The name of the file to open.
-   access? The mode in which the file is opened (e.g., r, w).
-   permissions? If a new file is created, this will be used to set the permissions.

# File Output and Input Example

```
# Open a file for writing
set outputFile "testfile" "w"

# send a line to the file.
puts outputFile "This is line 1"
puts outputFile "This is line 2"
puts outputFile "This is line 3"

# Close the file
close $outputFile

# Reopen the file for reading
set inputFile "testfile" "r"

# Read a line of text
set numBytes [gets $inputFile string]

# Display the line read
puts "Gets returned $numBytes characters in the string: $string"

# Read the rest of the file
set string2 [read $inputFile]
puts "Read: $string2"

```
