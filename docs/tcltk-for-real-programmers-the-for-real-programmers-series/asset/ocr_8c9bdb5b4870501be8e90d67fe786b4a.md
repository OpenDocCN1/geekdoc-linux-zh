# 2.3.3 Evaluating a Tcl Script File under Unix

Under Unix, you can use the technique of placing the name of the interpreter in the first line of the script file. Unfortunately, the shells will only search /bin and /usr/bin for interpreters. If you keep tclsh in another directory (for instance, /usr/foo/bin), you'll need to start your script files with the complete path:

```
#!/usr/foo/bin/tclsh
```

This makes a script less portable, since it won't run on a system that has tclsh under /usr/bin/bin.

A clever workaround for this is to start your script file with these lines:

```
#!/bin/sh
\
exec "$0" "$@"
```

The trick here is that both Tcl and the shell interpreter use the "# to start a comment, but the Bourne shell does not treat the \ as a line continuation character, so it evaluates the third line (exec "$0" "$@") while Tcl does.

The first line (#/bin/sh) invokes the Bourne shell to execute the script. The shell reads the second line (\), a comment, and does not process the "\" as a continuation character, so it evaluates the third line (exec "$0" "$@"). At this point, the shell invokes the wish interpreter to evaluate the script, using the $PATH information as the search path for wish.

When the wish interpreter reads the script, it interprets the first line as a comment and ignores it the second line (\) as a comment to the next line. This causes the Tcl interpreter to ignore exec "$0" "$@" as part of the comment started on the previous line and the wish interpreter starts to evaluate the script.

The last step to making a tclsh or wish script executable is to chmod the file to set the execution bits:

```
chmod 755 foo.tcl
```

or

```
chmod +x foo.tcl
```
