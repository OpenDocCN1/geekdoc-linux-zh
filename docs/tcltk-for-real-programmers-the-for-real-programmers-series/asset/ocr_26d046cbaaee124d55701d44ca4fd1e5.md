# 1.3.1 Tcl/Tk Compared with Visual Basic

The currently available languages, Visual Basic is probably the closest in functionality to Tcl/Tk. Here are a few of the reasons why Tcl/Tk is a better choice.

+   - Tcl/Tk scripts run on multiple platforms. Although the primary market may be the MS-Windows market, you might also want to have Apple and Unix markets available to your sales staff.

+   - Tcl/Tk scripts have support for Internet-style distributed processing, security levels.

+   - Tcl provides more and finer control of widgets. Which allows you to bind actions to objects as small as a single character in a text window or as an application window.

+   - Tcl has better support for library modules and version levels. A Tcl script can check for a particular version of its libraries and not run if they aren't available.

The one reason to prefer Visual Basic over Tcl is that you are writing a package that will interact only with the Microsoft applications that use Visual Basic as their scripting language. Tcl does not provide good hooks into the Microsoft applications that are designed to work with Visual Basic. However, future versions of Tcl may support OLE, etc.
