
## 15.2 Tcl as a Glue Language: The exec Command

These arguments can be either a program name, a program argument, or a pipeline descriptor. There are many pipeline descriptors. Some of the commonly used ones are:

- `|` Separates distinct programs in the command line. The standard output of the program on the left side of the pipe symbol (|) will be used as the standard input for the program on the right of the pipe symbol.
- `<fileName` The first program in the list will use the contents of fileName as the standard input.
- `>fileName` The standard output from the last program in the list will be written to fileName.

The following examples create compressed archives of files in a directory under Unix or Windows using the exec command.

### Example 15.2-1
# Creating a Gzipped Tar Archive under Unix

```bash
# This script is called with the name of a directory to
# archive archive as the first argument in the command line,
# and the name of the archive as the second argument.

set directory [index $argv 0]
set archive [index $argv 1]

# Get a list of the files to include in the archive.
set fllist [glob $directory/*]

# Create the tar archive, and zip it.
eval exec tar -cvf $archive $fllist
exec gzip $archive
```

### Example 15.2-2
# Creating a Zip Archive under Windows

```bash
# This script is called with the name of a directory to
# archive as the first argument in the command line
# and the name of the archive as the second argument.
set directory [index $argv 0]
set zipfile [index $argv 1]

# The file "distfiles" will contain a list of files for
# this archive.
set outfl [open distfiles "w"]
# Get a list of the files to include in the archive.
set fllist [glob $directory/*]

# And write that list into the contents file, one
# filename per line
foreach fl $fllist {
    puts outfl "$fl"
}
close outfl

# Execute the winzip program to make an archive.
eval "exec C:/winzip/winzip32.exe -a $zipfile @distfiles"
```

## 15.3 Common Mistakes

There are several common mistakes programmers make as they learn Tcl. Cameron Laird has collected many of these from the questions and answers posted in comp.lang.tcl (at http://Starbase.NeoSoft.COM/~claird/comp.lang.tcl/fmm.html). This section is a sampling of common errors not yet discussed in the previous chapters.

### Problems using the exec command.

The previous description of the exec command looks straightforward, but there are some common mistakes people make trying to use the exec command.

- *The tcl shell is not the Unix shell.*

Many problems appear when people try to use shell expansions or shell escapes with the exec command. For example, the wrong way to write the `exec tar...` command in the previous example would be:

```bash
exec tar -archive $directory/*
```

In this case, the tcl shell would substitute the name of the directory (for example, foo) for $directory and would pass that string (foo/*) to the tar program. The tar program would fail to identify any file named "*" in that directory. When you type a command with a "*" at the shell prompt (or in a script), the shell automatically expands the "*" to the list of files. This expansion is done by the glob command.

In the same way, if you try to group an argument to exec with single quotes it meaning to the Unix shell interpreter (disable substitutions) but is just another character to the Tcl interpreter.

- *The tcl shell is not COMMAND.COM.*

This is the Windows equivalent of the previous mistake. Remember that DIR, COPY, and DEL commands are part of COMMAND.COM, not standalone programs. You can't get a directory within a Tcl script with a command like:

```tcl
# Won't work
set filelist [exec C:*.*]
```

There is no DIR.EXE or DIR.COM for the Tcl shell to execute. The best workaround for this is to use the Tcl glob, file copy, file delete, and file rename commands. Another workaround (if you really need the DIR output) is to exec the COMMAND.COM program with /C option. This option tells the COMMAND.COM program to evaluate the string after the / as though it had been typed in a command prompt:

```tcl
# This will get a list of files
set filelist [glob C:*.*]
```

```tcl
# This will get the output of the dir command
set filelist [exec COMMAND.COM /C dir C:*.*]
```

Note that filelist will contain all the output from the DIR, not just a list of the files.

- *A Tcl list is passed as a single argument to a procedure.*

Notice the eval in the `eval exec tar -cvf $archive $flist` line in the previous Unix example. If you simply used

```tcl
# won't work
exec tar -cvf $archive $flist
```

The contents of $flist would be passed as a single argument to the exec command, which would pass them as a single argument to the tar program. Since there is no file named file1 file2.., this results in error. The eval command concatenates all of the arguments into one string and evaluates that string. This changes the list from single argument to as many arguments as there are file names in the list.

- *exec cd $Directory is probably not what you want.*

The change directory command is part of a shell. It changes the current directory within the shell. It's not an external program. Use the built-in Tcl command cd if you want to change the working directory for your script.
