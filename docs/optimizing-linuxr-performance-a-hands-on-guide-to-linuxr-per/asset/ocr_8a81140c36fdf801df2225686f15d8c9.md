# 11.7. Compile and Examine the Source

So now that we have some idea about which the application is taking all of the time, we will download the source and compile it. Until now, all of our analysis was possible using the binary packages that Red Hat provides. However, now we need to dive into the source code to examine why the hot functions are called and then, when we figure out, we make changes in the source to alleviate the performance problem. As we did for GIMP, when we generate debugging symbols by setting CFLAGS -g before we call the configure.

In this case, we downloaded and installed Red Hat's rpm for nautilus, which places the source of nautilus in /usr/redhat/SOURCES/. Using Red Hat's source package, we have the source and patches that Red Hat used to create the binary in the package. It is important to investigate the source that we used to create the binaries that we are investigating, because another version might have different performance characteristics. After we extract the source, we can begin to figure out where the bonobo_window_add_popup is called. We can search all the files in the nautilus directory using Listing 11.9.

# Listing 11.9.

```
nautilus ] -type f | xargs grep bonobo_window_add_popup
```

Fortunately, it appears as if bonobo_window_add_popup is only called from a single function, create_popup_menu, as shown in Listing 11.10.

# Listing 11.10.

```
static GtkMenu *create_popup_menu (FMDirectoryView *view,
const char *popup_path)
{
GtkMenu *menu;

menu = GTK_MENU (gtk_menu_new ());
gtk_menu_set_screen (menu, gtk_widget_get_screen(GTK_WIDGET(view)));

gtk_widget_show (GTK_WIDGET);

bonobo_window_add_popup (get_bonobo_window (view), menu,
popup_path);

gtk_signal_connect_object (menu, "hide",
G_CALLBACK (popup_menu_hidden),
G_OBJECT (view),
G_CONNECT_SWAPPED);

    return menu;
```
