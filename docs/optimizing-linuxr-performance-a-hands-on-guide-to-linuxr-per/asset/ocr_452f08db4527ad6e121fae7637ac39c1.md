# 12.3. Find a Baseline/Set a Goal

Once again, the first step is to determine the current state of the problem.

However, in this case, it is not easy to do. We do not know when the problem will begin or how long it will last, so we cannot really set a baseline without more investigation. As far a goal, ideally we would like the problem to disappear completely, but the problem might be caused by essential OS functions, eliminating it entirely not be possible.

First, we need to do a little more investigation into why this problem is happening to figure out a reasonable baseline. The initial step is to run top as the slideshow is happening. This gives us a list of processes that may be causing the problem, or it may exist even at the kernel.

In this case as in Listing 12.1, we run top and ask it to show only不超过 processes (by pressing <1> top runs).

The top in Listing 12.1 has several important properties. First, notice that no process is hogging the CPU; using less than 2 percent of the total CPU time. Second, the system is spending 91 percent waiting for I/O. Third the system is not using any of the swap space, so the grinding is NOT caused by swapping. Finally, an unknown process, prelink, is running when the problem happens. It is unclear what the prelink command is, so we will remember that application name and investigate it later.

Our next step is to run vmstat to see what the system is doing. Listing 12.2 shows the result of vmstat and confirms what we saw with top. That, -90 percent of the system is waiting for I/O. It tells us the disk subsystem is reading in around 1000 blocks a second of data. This is a significant amount of I/O.
