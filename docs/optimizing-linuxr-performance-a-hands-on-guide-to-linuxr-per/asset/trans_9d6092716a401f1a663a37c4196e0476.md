## 为什么性能如此重要？

如果你曾坐等电脑完成某项任务（一边敲击桌子，一边咒骂，一边心想“为什么要花这么长时间？”），你就知道拥有一个快速且调优良好的计算机系统是多么重要了。尽管并不是所有的性能问题都能轻松解决，但理解系统变慢的原因意味着：你可以从软件层面修复问题、升级缓慢的硬件，还是干脆把整台电脑扔出窗外。幸运的是，大多数操作系统——特别是 Linux——都提供了工具来查明机器运行缓慢的原因。通过使用一些基础工具，你可以确定系统在何何处变慢了，以及哪些部分运行效率低下。

虽然系统缓慢对终端用户来说特别令人烦恼，但对于开发者来说，性能调优应用程序有一个更重要的理由：高效的应用程序可以在更多系统上运行。如果你编写了运行缓慢且需要高性能电脑的程序，你就排除了那些拥有较慢电脑的客户，从而缩小了潜在用户群。此外，调优良好的应用程序可以被更多客户使用；当潜在客户在两个功能相似的不同应用程序之间做出选择时，他们通常会选择运行更快或效率更高的那一个。最后，一个生命周期较长的应用程序可能会经过几轮优化以应对不同的客户需求，因此知道如何追踪性能问题是关重要的。

如果你是一名系统管理员，你就有责任向系统用户确保其运行在适当的性能水平。如果系统运行缓慢，用户就会抱怨。如果你能快速确定问题并修复它，他们就会停止抱怨。作为额外的回报，如果你调优了应用程序或操作系统（从而避免了他们购买新硬件），你就能让公司的财务算师们感到高兴。了解如何有效地使用性能工具，可能意味着在解决性能问题时，是花费几天时间还是只花几个小时时间。

## Linux：优势与劣势

如果你使用 Linux、维护 Linux 并在其上进行开发，那么你处于一种奇特但良好的境地。你能够以以前所未有的权限访问源代码、开发者和邮件列表，这些邮件列表通常会在设计决策做出后记录其背景。Linux 是一个寻找和修复性能问题的绝佳环境。这与专有环境形成了对比，在专有环境中，很难直接接触软件开发者，可能很难找到关于大多数设计决策的讨论，而且几乎无法访问源代码。除了这种高效的环境外，Linux 还拥有强大的性能工具，让你能够发现并修复性能问题。这些工具可以与其专有系统的对手媲美。

尽管有这些令人印象深刻的优点，Linux 生态系统仍然面临需要克服的挑战。Linux 性能工具散落在各地。不同目标的群体开发这些工具，导致工具并不集中在某处。某些工具包含在标准的 Linux 发行版中，如 Red Hat、SUSE 和 Debian；另一些则散落在互联网各处。如果你试图解决性能问题，你首先必须知道你需要的工具确实存在，然后弄清楚在哪里可以找到它们。由于你还需要学会如何联合使用这些工具来确定哪里出了问题，这可能是一门艺术，但随着经验的增加会变得更容易。尽管大多数通用策略都可以记录下来，但 Linux 并没有任何指南告诉你如何聚合性能工具来实际解决问题。大多数工具或子系统都有关于如何调优特定子系统的信息，但没有关于如何将其与其他工具配合使用的。许多性能问题跨越了系统的多个领域，除非你知道如何集体使用这些工具，否则你无法解决问题。

## 为什么要学习使用性能工具？

为什么有人应该投入精力去调优系统或应用程序？

- 调优良好的系统可以用更少的资源完成更多工作。
- 调优良好的应用程序可以在旧硬件上运行。
- 调优良好的桌面系统可以为用户节省时间。
- 调优良好的服务器为更多用户提供更高的服务质量。

如果你知道如何有效地诊断性能问题，你就可以采取针对性的方法来解决问题，而不是盲目尝试并希望有效。如果你是一名应用程序开发者，这意味着你可以快速确定是哪部分代码导致了问题。如果你是一名系统管理员，这意味着你可以弄清楚系统的哪个部分需要调优或升级，而无需浪费时间去尝试不同的解决方案。如果你是终端用户，你可以找出哪些应用程序在卡顿，并向开发者报告问题（或者在必要时更新你的硬件）。

Linux 正处于一个十字路口。大部分功能已经完成。Linux 及其应用程序的下一个演进步骤是经过调优来竞争并超越其他操作系统的性能。某些性能优化（例如显著提升线程性能的 NativeIX Thread Library 库，以及改进应用程序启动时间的 objectlinking）刚刚开始集成到 Linux 中。Linux 亟待改进。

## 我可以进行性能调优吗？

性能调优最棒的一点是，你不需要了解整个应用程序或系统的细节就能有效地修复性能问题。性能调优需要与典型的应用程序开发者互补的技能集。

你需要敏锐且执着。寻找和消除性能问题需要的比程序员更像侦探。当你开始时，性能可能非常糟糕。但一旦你追踪到原因并将其根除，如果你足够好，系统随后就会快一倍。*搞定！*

要到达最后，你必须理解强大但有时令人困惑的 Linux 性能工具世界。这需要努力，但最终是值得的。这些工具可以向你展示你从未想过的应用程序和系统的方面。
