# 10.6. Run Application and Performance Tools

Next, we run the application and take measurements using the performance tools. Because the lic filter is called directly from the GIMP, we have to use tools to catch and monitor an already running process.

In case of profile, we can start profile, run the filter, and then stop profile after the filter has been completed. The lic filter takes approximately 90 percent of the CPU when running, the system-wide collects will be mainly relevant for the lic. When lic starts, we start profile in another window; when lic finishes in that window, we stop profile. The starting and stopping of profile is shown in Listing 10.4.

Listing 10.4.

```
[root@localhost ezolt]# opcontrol --start
[root@localhost ezolt]# opcontrol --dump
[root@localhost ezolt]# opcontrol --stop
Stpping running.
```

ltrace must be run a little differently. After the filter has been shown, ltrace can be attached to the running process. Unlike, attaching ltrace to a process brings the process to a crawl. This can accurately inflate the amount of time taken for each library call; however, it provides information about the number of times each call made. Listing 10.5 shows a listing from ltrace.

To get the full list of library calls, it is possible to let ltrace run until completion; however, it takes a really long time, so in this case, we pressed <Ctrl-C> after a period of time elapsed. This worked because an application may go through different stages of execution, and if it stops early, you may not get a complete picture of what functions the application is calling. However, this short sample will give us a starting point for analysis.
