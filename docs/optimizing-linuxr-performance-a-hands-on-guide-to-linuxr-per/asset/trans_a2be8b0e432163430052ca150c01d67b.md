

## 6.3. 缺失了什么？

Linux 上的磁盘 I/O 工具提供了有关特定磁盘或分区的利用率信息。遗憾的是，在您确定某个特定磁盘是瓶颈后，没有任何工具可以查查出是哪个进程导致了所有的 I/O 操作。

通常，系统管理员对哪些应用程序在使用磁盘有相当的了解，但并不总是如此。很多时候，例如，我正在使用 Linux 系统时，磁盘开始无缘无故地剧烈作响。我通常可以运行 `top` 并寻找可能导致问题的进程。然而，通过排除我认为没有在进行 I/O 的进程，我通常能找到罪魁祸首。这需要对各种应用程序应该执行的功能有所了解。这种方法也容易出错，因为对哪些进程导致问题的推测可能是错误的。此外，对于拥有许多用户或运行多个应用程序的系统，确定哪个应用程序可能导致问题并不总是可行或容易的。其他 Unix 系统支持 `ps` 命令的 `inblk` 和 `cublk` 参数，这些参数可以显示代表特定进程发出的磁盘 I/O 流量。目前，Linux 内核并不跟踪进程的 I/O，因此 `ps` 工具没有办法获取这些信息。

你可以使用 `lsof` 来确定哪些进程正在访问特定分区上的文件。在列出所有访问文件的 PID 后，你可以使用 `strace` 挂接到每个 PID 上，并查出哪一个正在进行大量的 I/O。虽然这种方法有效，但它真的是一个“治标不治本”的方案，因为访问分区的进程可能很多，挂载并分析每个进程的系统调用非常耗时。这还可能会漏掉短生命周期进程，并在它们被追踪时导致进程运行变得无法接受地缓慢。

这是 Linux 内核可以改进的领域。快速跟踪产生 I/O 的进程的能力将允许更快地诊断与 I/O 性能相关的问题。

## 6.4. 章总结

本章介绍了 Linux 磁盘 I/O 性能工具，这些工具用于提取有关系统级 (vmstat)、设备特定 (vmstat, iostat, sar) 和文件特定 (isof) 的磁盘 I/O 使用情况信息。它解释了不同类型的 I/O 统计数据以及如何从 Linux I/O 性能工具中提取这些统计数据。它还讨论了当前工具的一些重大局限性以及未来的增长领域。

## 第 7 章 性能工具：网络

本章介绍了 Linux 上可用的某些网络性能工具。我们主要关注分析单机网络流量的工具，而不是全网范围的管理工具。虽然网络性能在完全孤立的状态下通常没有意义（因为节点通常不会与自己通信），但调查网络上单个系统的行为是有价值的，可以识别本地配置和应用程序问题。此外，了解单个系统上网络流量的特征可以帮助定位其他有问题的系统，或者定位减慢网络性能的本地硬件和应用程序错误。

读完本章后，你应该能够：

- 确定系统中以太网设备的传输速率和双工模式设置 (mii-tool, ethtool)。
- 确定流过每个以太网接口的网络流量大小 (ifconfig, sar, gkrellm, iptraf, netstat, etherape)。
- 确定流出系统的 IP 流量类型 (gkrellm, iptraf, netstat, etherape)。
- 确定流入和流出每种类型 IP 流量的大小 (gkrellm, iptraf, etherape)。
- 确定哪些应用程序正在产生 IP 流量 (netstat)。

## 7.1. 网络 I/O 简介

Linux 以及所有其他操作系统中的网络流量被抽象为一系列硬件和软件层。链路层（或物理层）包含了以太网设备等网络硬件。在移动网络流量时，该层负责工作。虽然网络性能在完全孤立的状态下通常没有意义（节点通常不会与自己通信），但调查网络上单个系统的行为是有价值的，可以识别本地配置和应用程序问题。此外，了解单个系统上网络流量的特征可以帮助定位其他有问题的系统，或者定位减慢网络性能的本地硬件和应用程序错误。
