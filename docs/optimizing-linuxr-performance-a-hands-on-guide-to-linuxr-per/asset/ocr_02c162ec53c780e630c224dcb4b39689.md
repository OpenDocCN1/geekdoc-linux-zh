# 11.3. Find a Baseline/Set a Goal

As the previous thought, the first step is to determine the current state of the problem. To make our lives little easier, and to avoid some of the problems mentioned in the preceding section, we are going to create a little and the pop-up menu problem look more similar to the long-running CPU-intensive tasks that we measured before. The amount of time it takes for a single pop-up to appear is in the millisecond range, which makes it hard to accurately measure with our performance tools. As mentioned previously, it will be difficult to start and stop them in interest (that is, the amount of time spent to open the actual menu). Here we we what we are interested in (that is, the menu where we click. Instead of opening the menu just one time, we will open the menu 100 times in rapid succession. This way, the total amount of spent menus will increase by a factor of 100. This enables us to use our profiling tools to capture information about how the menu is executing.

Because right-100 times would be tedious, and a human (unless well trained) could not reliably open up a pop-up menu 100 times in a repeatable manner, we must automate it. To reliably open up the pop-up menu 100 times, we rely on the automation package. The xautation package is available at http://httpajoo.net/projects/xautation.html. It can send any Window events to the X server, mimicking a mouse click. After downloading the xautation file, unzipping and compiling it, we can use it to automate the mouse click.

Unlike the GIMP, we cannot simply measure the amount of CPU time used by nautilus to evaluate the created 100 pop-up menus. This is mainly because nautilus does not start immediately before a menu is opened and end immediately after. We are going to use wall-clock time to see how much time it takes to complete this task. This requires the system to have no other things running while we run.

Listing 11.1 shell script of xautation commands that are used to open 100 pop-up menus in the nautilus window. When we run it, we have to make sure that we have oriented the nautilus window so that none of the clicks actually opens a pop-up menu on a folder, and instead all the pop-ups occur on the background. This is important because the code paths for the different pop-ups could be radically different.

# Listing 11.1.

```
#!/bin/bash
for i in seq 100;

  echo $ 
  ./xte 'mousemove 100 100' 'mouseclick 3' 'mouseclick 3'
  ./xte 'mousemove 200 100' 'mouseclick 3' 'mouseclick 3'

```

The commands in Listing 11.1 move the cursor to (100,100) on the X screen, and click the right button (3). This brings up a menu. Then we click the right mouse button again, and closes this menu. Then they move to X position(100,100), and repeat the process.

Next, we use time to see how much of these 100 iterations takes. This is our baseline time. With our optimizations, we will check them again to see what we have improved. Baseline time for the Fedora 2 nautilus is 26.5 seconds.
