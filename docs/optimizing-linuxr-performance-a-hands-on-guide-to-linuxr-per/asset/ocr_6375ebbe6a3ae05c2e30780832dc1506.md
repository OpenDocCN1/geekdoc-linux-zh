# 11.6. Run Application and Performance Tools

Next, we run the application and take measurements using the performance tools. Because we already suspect that a complex interaction of many processes and libraries might be the cause of the problem, we are going to start with profile and see what it has to show.

Because we only want profile to measure events when we are opening the pop-up menu, we are going to use the command line shown in Listing 11.3 to start and profile the profiling immediately before and after we run our script (script.sh) that opens and closes 100 pop-up menus.

# Listing 11.3.

```
opcontrol -start ; ./script.sh opcontrol -stop
```

As you can see, the function is in many different libraries. It is not clear at all application is responsible for making those calls. In particular, we have no idea which processes have called the libobject. Fortunately, profile provides a way to record the shared libraries' functions that an application uses during a run. Listing 11.5 shows how to configure profile's collection to separate the samples by library, which will attribute the samples in shared libraries to the programs called.

# Listing 11.5.

```
opcontrol -p library; opcontrol ---reset
```
