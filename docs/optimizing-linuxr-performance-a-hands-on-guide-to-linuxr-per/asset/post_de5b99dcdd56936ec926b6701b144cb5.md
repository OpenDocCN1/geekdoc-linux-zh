### 2.2.1. vmstat (Virtual Memory Statistics)

vmstat stands for virtual memory statistics, which indicates that it will give you information about the virtual memory system performance of your system. Frankly, it does much more than that. vmstat is a great command to get a rough idea of how your system performs as a whole. It tells you:

- How many processes are running
- How the CPU is being used
- How many interrupts the CPU receives
- How many context switches the scheduler performs

It is an excellent tool to get a rough idea of how the system performs.

### 2.2.1.1 CPU Performance-Related Options

vmstat can be invoked with the following command:

```
vmstat [-n] [-s] [delay [count]]
```

vmstat can run in two modes: sample mode and average mode. If no parameters are specified, vmstat runs in average mode, where vmstat displays the average for all the statistics since system boot. However, if a delay is specified, the first will samples every few seconds and reports out the statistics. Table 2-1 describes the options that vmstat accepts.

#### Table 2-1. vmstat Command-Line Options

| Column | Explanation |
|---|---|
| -n | By default, vmstat periodically prints the column headers for each performance statistic. This option disable feature that after the initial header, only performance data displays. This proves helpful if you want to import the output of vmstat to a spreadsheet. |
| -s | This displays a one-shot details of system statistics vmstat gathers. The statistics are all the statistics since system booted. |
| delay | This is the amount of time between vmstat samples. |

## Chapter 3. Performance Tools: System Memory

This chapter covers the system-wide Linux memory performance tools. This chapter discusses the memory statistics that these tools can measure and how to use the individual tools to gather those statistics. After reading this chapter, you should:

### 3.1. Memory Performance Statistics

Each-wide Linux performance tool provides different ways to extract similar statistics. Although no tool displays all the statistics, some of the tools display the same. The beginning of this chapter reviews the details of these statistics, and those descriptions are then referred referred as the tools described.

### 3.1.1. Memory Subsystem and Performance

In modern processors, saving information and retrieving information from the memory subsystem usually takes the CPU executing code and manipulating that information. The CPU usually spends a significant amount of idle time, waiting for instructions and data to be retrieved from memory before it execute or operate on them. Processors have varying levels of cache to compensate for the slow memory performance. Tools such as profile can show where various processor cache misses occur.

### 3.1.2. Memory Subsystem (Virtual Memory)

Any Linux system has a certain amount of RAM or physical memory. When addressing this physical memory, Linux breaks it into chunks or "pages" of memory. When allocating or moving around, Linux operates on page-sized blocks rather than individual bytes. When reporting some memory statistics, the Linux kernel reports the number of pages per second, and this value can vary depending on the architecture it is running on. Listing 3.1 creates a small application that displays the number of bytes per page for the current architecture.

Listing 3.1:

```c
#include <unistd.h>
int main(int argc, char *argv[])
{
    printf("System page size: %d\n", getpagesize());
}
```

On the IA32 architecture, the page size is 4KB. In rare cases, page-sized chunks of memory can cause too much overhead, to which the kernel manages memory in bigger chunks, known as HugePages. These are on the order of 2048KB larger than 4KB and greatly reduce the overhead for managing large amounts of memory. Applications, such as Oracle, use these huge pages to manage it. If HugePages are not completely filled with data, these can waste a significant amount of memory. A half-filled normal page wastes 2KB of memory, whereas a half-filled HugePage can waste 1,024KB of memory.

The Linux kernel can scatter a collection of these physical pages and present to applications a well-laid virtual memory space.

#### 3.1.2.1 Swap (Not Enough Physical Memory)

All systems have a certain amount of RAM or physical memory. The Linux kernel allows applications to run if they require more memory than available using the hard drive as temporary memory. This hard drive is called swap space. Although swap is an excellent way to handle processes, it is truly slow—up to 1000 times slower than physical memory. It can help determine how much swap your system is using.

## 3.2. Linux Performance Tools: CPU and Memory

Here begins our discussion of performance tools that enable you to extract information previously described.

### 3.2.1. vmstat (Virtual Memory Statistics) II

As you have seen before, vmstat can provide information about many different performance aspects—although its primary purpose, as shown next, is to provide information about virtual memory system performance. In addition to the CPU statistics described in the previous chapter, it can tell you the following:

- How much swap is being used
- How the physical memory is being used
- How much memory is free

### 3.2.1.1 System-Wide Memory-Related Options

In addition to the CPU statistics vmstat can provide, you may invoke vmstat with command-line options when investigating memory statistics:

```
vmstat [-a] [-s] [-m]
```

As before, you can run vmstat in two modes: sample mode and average mode. The added command-line options enable you to get the performance statistics about how the Linux kernel is using memory. Table 3-1 describes the options that vmstat accepts.

#### Table 3-1. vmstat Command-Line Options

| Option | Explanation |
|---|---|
| -a | This changes the default output of memory statistics to indicate the active/inactive amount of memory rather than information about buffer and cache usage |
| -s (procps) | This prints out the vm table. This is a bag of statistics about the system since it has booted. It cannot be run in sample mode. It contains both memory and CPU statistics. |
| -m (procps) | This prints out the kernel's slab info. This is the same information that can be retrieved by typing cat/proc/slabinfo. This describes in detail how the kernel's memory is allocated. |

Table 3-2 provides a list of memory statistics that vmstat can provide. With the CPU statistics, when running in normal mode, the first line vmstat provides the average values for all rate statistics (so and i) and the instantaneous value for all numeric statistics (swpd, free, buff, cache, active and inactive).
