## 11.8. Using gdb to Generate Call Traces

To solve this, use one of gdb's features, gdb can execute a set of commands when it hits a breakpoint. By using the command we can tell gdb to execute bt; cont every time it hits the breakpoint. Now the backtrace displays, and the application continues every time it hits. 

Now we have to see the actual traces. We can set the breakpoint in g_type_check_is_a at the start of nautilus, and gdb would show tracing information when it is called when we are creating a pop-up menu. We would need to limit tracing to only when we are popping. To do this, we set another breakpoint at the beginning and end of the fm_directory_view_pop_up_context_menu function. When we reach the first breakpoint, we start the tracing in g_type_check_is_a; when we reach the second breakpoint, we stop the debugger. This limits the backtrace to that which is generated when we are creating a pop-up menu. Finally, we need to be able to save this backtrace information for post-processing. We can use gdb's log to output it to a file as shown in Listing 11.12.

# Listing 11.12.

# Turn on logging to a file (default: gdb.txt)
