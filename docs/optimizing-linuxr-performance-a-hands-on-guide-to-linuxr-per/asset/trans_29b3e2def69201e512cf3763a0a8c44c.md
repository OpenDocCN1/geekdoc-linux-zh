

## 5.2. 内存性能工具

本节将介绍各种内存性能工具，这些工具可以帮助你调查特定应用程序是如何使用内存子系统的，包括进程正在使用的内存数量和不同类型、内存何时被分配，以及进程使用处理器缓存的效率。

### 5.2.1. ps

`ps` 是一个跟踪进程动态内存使用的极佳命令。除了已经提到的 CPU 统计信息外，`ps` 还提供了关于应用程序所用内存量以及该内存使用如何影响系统的详细信息。

### 5.2.1.1 与内存性能相关的选项

`ps` 有许多选项，并可以检索有关运行应用程序状态的许多统计数据。正如你你在上一章中看到的，`ps` 可以检索进程正在使用的 CPU 的信息，也可以检索关于进程正在使用的内存数量和类型的信息。可以使用以下命令行来调用它：

```
[-o vssz,rss,tsiz,dsiz,majflt,minflt,pmem,command] <PID>
```

表 5-1 描述了 `ps` 可以为指定的 PID 显示的不同类型的内存统计数据。

#### 表 5-1. ps 命令行选项

| 选项 | 解释 |
| - | - |
| -statistic | 允许精确指定你想要跟踪的进程统计数据。不同的统计数据用逗号分隔的列表指定，且没有空格。 |
| vssz | 静态：虚拟大小（virtual size）是应用程序使用的虚拟内存量。由于 Linux 只在应用程序尝试使用时才分配物理内存，因此它的值可能大于应用程序使用的物理内存量。 |
| rss | 静态：驻存大小（resident size）是应用程序当前使用的物理内存量。 |
| tsiz | 静态：文本大小（text size）是程序代码的虚拟大小。再次，这不是物理大小，而是虚拟大小；然而，它是程序大小的一个良好指标。 |
| dsiz | 静态：数据大小（data size）是程序使用部分的虚拟大小。它是应用程序数据结构和栈大小的良好指标。 |
| majflt | 静态：主缺页（Major faults）是导致 Linux 从磁盘读取的页错误次数。如果进程访问了位于磁盘上的某部分数据或指令，且 Linux 为应用程序无缝加载了它，就可能发生这种情况。 |
| minflt | 静态：次缺页（Minor faults）是 Linux 在不诉诸磁盘读取的情况下完成的错误次数。如果应用程序碰了由内核分配的内存块，就可能发生这种情况。在这种情况下，没有必要访问磁盘 |

## 5.3. 本章总结

本章介绍了用于诊断内存性能问题的各种 Linux 工具。它演示了显示应用程序消耗多少内存（`ps`/`/proc`）以及应用程序内部哪些函数正在分配内存（`memprof`）。它涵盖了可以监控缓存和内存子系统的工具（`cachegrind`、`kcachegrind` 和 `profile`）。最后，描述了一个监控共享内存使用的工具（`ipcs`）。结合使用这些工具，可以跟踪每一次内存分配、这些分配的大小、在应用程序中的功能位置，以及应用程序在访问这些分配时使用内存子系统的效率。

下一章将离开内存，研究磁盘 I/O 瓶颈。

## 第 6 章 性能工具：磁盘 I/O

本章涵盖了帮助你评估磁盘 I/O 子系统使用情况的性能工具。这些工具可以显示正在使用哪些磁盘或分区、每个磁盘处理多少 I/O，以及发送到这些磁盘的 I/O 请求等待处理需要多久。

读完本章后，你应该能够：

- 确定系统中磁盘 I/O 的总量和类型（读/写）（`vmstat`）。
- 确定哪些设备处理了大部分磁盘 I/O（`vmstat`、`iostat`、`sar`）。
- 确定特定磁盘处理 I/O 请求的效率（`iostat`）。
- 确定哪些进程正在使用一组文件（`lsof`）。

## 6.1. 磁盘 I/O 简介

在深入研究性能工具之前，有必要了解 Linux I/O系统的结构。大多数现代 Linux 系统有一个或多个磁盘驱动器。如果它们是 IDE 驱动器，通常命名为 `hda`、`hdb`、`hdc` 等；而 SCSI 驱动器通常命名为 `sda`、`sdb`、`sdc` 等。磁盘通常被分为多个分区，分区设备是通过在基础设备名称后添加分区编号生成的。例如，系统中的第一个 IDE 硬盘通常标记为 `/dev/hda2`。每个单独的分区通常包含文件系统或交换分区。这些分区挂载到 Linux 根文件系统中，如 `/etc/fstab` 中指定的所示。这些挂载的文件系统包含了应用程序读取和写入的文件。

当应用程序执行读或写操作时，Linux 内核可能在其缓存中存储了文件的副本，或者直接返回请求的信息。如果 Linux 内核在内存中没有该数据的副本，则会访问磁盘。请求被放入 I/O 队列，如果磁盘当前忙碌，请求将等待磁盘可用，然后被处理。

## 6.2. 磁盘 I/O 性能

本节将介绍各种 I/O 性能工具，这些工具可以让你调查应用程序是如何使用磁盘子系统的、磁盘被使用的繁忙程度、内核缓存工作是否良好以及应用程序打开了哪些文件。

### 6.2.1. vmstat (ii)

正如你在第 2 章“性能工具：系统 CPU”中所，`vmstat` 是一个提供系统使用情况的的工具。除了 CPU 和内存统计信息外，`vmstat` 还可以提供 I/O 性能的视图。

### 6.2.1.1 与 I/O 性能相关的选项和输出

在使用 `vmstat` 检索系统的 I/O 统计数据时，你可以如下方式调用它：

```
vmstat [-D] [-d] [-p partition] [interval] [count]
```

表 6-1 描述了影响 `vmstat` 显示 I/O 统计数据的命令行参数。

#### 表 6-1. vmstat 命令行选项

| 选项 | 解释 |
| - | - |
| -D | 显示 Linux I/O 子系统的总统计数据。此选项可以让你很好了解 I/O 子系统是如何使用的，但不会提供单个磁盘的统计数据。给出的统计数据是启动以来的，而不是本次采样与上一次采样之间的 |
| -d | 每隔间隔显示一次单个磁盘统计数据。统计数据是启动以来的，而不是本次采样与上一次采样之间的 |
| -p partition | 每隔间隔显示一次指定分区的性能统计数据。统计数据是启动以来的，而不是本次采样与上一次采样之间的 |
| interval | 采样之间的时间长度 |
| count | 采样的总数 |

如果你在不带除 [interval] 和 [count] 其他参数的情况下运行 `vmstat`，它将显示默认输出。该输出包含三个与磁盘 I/O 性能相关的列：bo、bi 和 wa。这些统计数据在表 6-2 中。

#### 表 6-2. vmstat I/O 统计数据

| 统计数据 | 解释 |
| - | - |
| bo | 表示上一个间隔内写入磁盘的总块数。（在 vmstat 中，磁盘块大小通常为 1,024 字节） |
