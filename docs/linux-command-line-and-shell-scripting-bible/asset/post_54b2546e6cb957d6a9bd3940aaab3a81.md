# Creating user accounts

After creating the database, the next step is to create a user account that has access to it for your scripts. As you've already seen, user accounts in PostgreSQL is one of things that is significantly different from MySQL.

User accounts in PostgreSQL are called Login Roles. The PostgreSQL server manages Login Roles to the Linux system user accounts. Because of this, there are two common thoughts about creating Login Roles to run shell scripts that access the PostgreSQL database:

- Create a special Login account with a matching PostgreSQL Login Role to run all your shell scripts.
- Create PostgreSQL accounts for each Linux user account that needs to run shell scripts to access the database.

For this example I'll choose the second method and create a PostgreSQL account that matches my Linux system account. This way, I can run shell scripts that access the PostgreSQL database directly from my Linux user account.

First, you must create the Login Role:

```
test=# CREATE ROLE rich login;
CREATE ROLE
test=#
```

That was simple enough. Without the login parameter, the role is not allowed to log in to the PostgreSQL server, but this type of role is called a Group Role.

Group Roles are great if you're working in a large environment with lots of users and tables. Instead of having to keep track of which user has which type of privileges for tables, you can just create Group Roles for specific types of access to tables, then assign the Login Roles to the proper Group Role.

For simple scripting, you most likely won't worry about creating Group Roles, and just assign privileges directly to the Login Roles. That's what I'll do in this example.

However, PostgreSQL handles privileges a bit differently than MySQL. It doesn't allow you to grant privileges to all objects in a database that filter down to the table level. Instead, you'll need to grant privileges for each individual table you create. While this is somewhat of a pain, it certainly enforces strict security policies. You'll have to hold off assigning privileges until you've created a table. That's the next step in our process.

# Working with Tables

Now that you've got your MySQL or PostgreSQL server running, created a new database and a user account for accessing it, it's time to start working with data! Fortunately, both mysql and postgres use standard SQL to create and manage data tables. This section walks you through the SQL to create tables, insert and remove data, and querying existing data in all environments.

# Creating a table

Both the MySQL and PostgreSQL servers are considered relational databases. In a relational database, data is organized by data fields, records, and tables. A data field is a single piece of information, such as an employee's last name, record or a salary. A record is a collection of related data fields, such as the employee ID number, first name, address, and salary. Each record indicates one set of the data fields.

The table contains all of the records that hold the related data. Thus, you'll have a table Employees which holds for each employee.

To create a table in the database, you need to use the CREATE TABLE SQL command:

```
$ mysql test -u root -p
Enter password:
mysql> CREATE TABLE employees (
  -> empid int not null,
  -> lastname varchar(30),
  -> firstname varchar(30),
  -> salary float,
  -> primary key (empid);
Query OK, 0 rows affected (0.14 sec)

mysql>
```

# Inserting and deleting data

Not surprisingly, you use the INSERT SQL to insert new data records into the table. Each INSERT command must specify the data field values for the MySQL or PostgreSQL server to accept the record.
The format of the INSERT SQL command is:

```
INSERT INTO table VALUES (...)
```

The values are a comma-separated list of the data values for each data field:

```
# mysql test -u test -p
Enter password:
mysql>
Query OK, 1 row affected (0.35 sec)
```

or, in PostgreSQL:

```
[rich@textbox ~] psql test
Welcome to psql 8.2.6, the PostgreSQL interactive terminal.

t=> INSERT INTO employees VALUES (1, 'Rich', 25000.00);
INSERT 0 1
t=>
```

Since the new user account in both MySQL and PostgreSQL has privileges to insert data, you can log in using that account. The INSERT command pushes the data values you specify into the data fields in the table. If you attempt to add another record that duplicates the empid field value, you'll get an error message:

```
mysql> INSERT INTO employees VALUES (1, 'Barbara', 45000.00);
ERROR 1062 (23000): Duplicate entry '1' for key
```

However, if you change the empid value to a unique value, everything should be OK:

```
mysql> INSERT INTO employees VALUES (2, 'Barbara', 45000.00);
Query OK, 1 row affected (0.00 sec)
```

You should have two data records in your table.

If you need to remove data from your table, you use the DELETE SQL command. However, you need to be very careful with it.

The basic DELETE command format is:

```
DELETE FROM table;
```

where table specifies the table to delete records from. There's just one small problem with this command: it removes all of the records in the table.

To specify a single record or a group of records to delete, you must use the WHERE clause. The WHERE clause allows you to create a filter that identifies which records to remove. You use the WHERE clause like this:

```
DELETE FROM employees WHERE empid = 2;
```

This restricts the deletion process to all of the records that have an empid value of 2. When you execute this command, the mysql program returns a message indicating how many records matched the filter:

```
mysql> DELETE FROM employees WHERE empid = 2;
Query OK, 1 row affected (0.29 sec)
```

As expected, only one record matched the filter and was removed.
