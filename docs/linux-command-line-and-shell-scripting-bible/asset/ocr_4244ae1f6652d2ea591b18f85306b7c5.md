# The zsh Shell

As you probably figured out by now, every user on the system executes the commands in the /etc/zlogout at logout, while each individual user has a $HOME/.zlogout file. The zsh shell will execute any commands in these files before logging out of the current shell.

This doesn't include exiting from an interactive shell. Thus, if you just start another zsh shell from an existing shell session, the zsh shell will not execute the logout files when you exit the shell. However, if you start a login shell, the logout files should execute upon exiting:

```
% zsh
This is the /etc/zhenv file.
This is the .zhenv file in HOME.
This is the .zprofile file.
This is the .zprofile file in HOME.
This is the /etc/zshrc file.
This is the .zshrc file in HOME.
This is the /etc/zlogin file.
This is the .zlogin file in HOME.
% exit
This is the .zlogout file in HOME.
This is the /etc/zlogout file.\%
```

Notice that the shell executes the .zlogout file before the global zlogout file, which is in the opposite order from the other zsh file types.

# Environment variables

Just like any other shell, the zsh provides standard environment variables for tracking system and shell information. The zsh uses a combination of lower-case variable names and upper-case variable names.

There are a few environment variables for which the zsh shell provides both a lower-case and upper-case version. The reason for this is in the way the zsh handles arrays, and compatibility with other shells.

The zsh shell uses a space-separated list of words to define an array. Many Bourne-style shells use a colon to separate array elements in multi-value variables, such as the PATH variable in the bash shell.
