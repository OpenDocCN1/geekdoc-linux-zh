Different Linux handle devices using different device names. In IBM, the sda device is the first SCSI hard drive, and the tty devices are the standard IBM PC COM ports. The listing all of the sda devices that were created on the sample Linux system. Not all are actually used, but they are created in case the administrator needs them. Similarly, the listing shows all of the tty devices created.

The fifth column is the device node number. Notice that all of the sda devices have the same major device node, 8, while all of the tty devices use 4. The sixth column is the minor device node number. Each device within a major number has its own unique minor device number.

The first column indicates the permissions for the device file. The first character of the permissions indicates the type of file. Notice that the SCSI hard drive files are all marked as block (b) device, while the COM port device files are marked as character (c) devices.

# Filesystem management

Unlike some operating systems, the Linux kernel can support different types of filesystems to read and write to hard drives. Besides having a dozen filesystems of its own, Linux can read and write to filesystems by other operating systems, such as Microsoft Windows. The kernel must be compiled with support for all types of filesystems that the system will use. Table 1-1 lists the standard filesystems that a Linux system can use to read and write data.

Any hard drive that a Linux server accesses must be formatted using one of the filesystems listed in Table 1-1.

The Linux kernel interfaces with each filesystem using the Virtual File System (VFS). This provides a standard interface for the kernel to communicate with any type of filesystem. VFS caches information in memory as each filesystem is mounted and used.
