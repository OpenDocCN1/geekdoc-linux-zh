
# Running scripts before processing data

The program also allows you to specify when the program script is run. By default, awk reads a line of text from the input, executes the program script on the data in the line of text. Times you may need to run a script before processing data, such as to create a header section for a report. To do that you use the BEGIN keyword. This forces awk to execute the program script specified after the BEGIN keyword before reading the data:

```
$ awk 'BEGIN { print "This is a test report" }'
This is a test report
```

You can place any type of awk command in the BEGIN section, such as assigning default values to variables.

# Running scripts after processing data

Similar to the BEGIN keyword, the END keyword allows you to specify a program script that awk executes after reading the data:

```
$ awk 'BEGIN { print "Hello World!" } { print $0 } END { print "byebye" }'
Hello World!
This is a test
This is a test
This is another test.
This is another test.
byebye
$
```

The awk program executes the code in the BEGIN section first, then processes any data in the input stream, then executes the code in the END section.

# The awk variables

The awk program is more than just an editor; it's a complete programming environment. As such, there are lots of commands and features associated with awk. This section shows the features you'll need to know for programming with awk.

# Built-in variables

The awk program uses built-in variables to reference specific features within the program data. This section describes the awk built-in variables available for you to use in your awk programs, and demonstrates how to use them.

The awk program defines data as records and data fields. A record is a line of data (delineated by the newline characters by default), and a data field is a separate data element within the line (delineated by a white space character, such as a space or tab, by default).

The gawk program uses data field variables to reference data elements within each record. Table B-3 describes these variables.

| $1 | The first data field in the record. |
| $2 | The second data field in the record. |
| $n | The nth data field in the record. |

You can use the built-in variables anywhere in the gawk program script, including the BEGIN and END sections.

# Assigning variables in scripts

Assigning values to variables in gawk programs is similar to how you do it in a shell script, using an assignment statement:

```
$ gawk '
BEGIN{
  testing="This is a test"
  print testing
}'
```

This is a test.

Once you assign a value to a variable, you can use that variable anywhere in your gawk script.

# Assigning variables in the command line

You can also use the gawk command line to assign values to variables for the gawk program. This allows you to set values outside of the normal code, changing values on the fly. Here's an example of using a gawk command variable to display a specific data field in the file:

```
$ cat script1
BEGIN(FS="-")
 print $n
$ gawk -f script1 n=2 datal
$ gawk -f script1 n=3 datal
```

This feature is a great way to process data from your shell scripts in the gawk script.

# The gawk program features

There are a few features of the gawk program that make it handy for manipulating data, allowing you to create gawk scripts that can parse just any type of text file, such as log files.

# Regular expressions

You can use either Basic Regular Expression (BRE) or Extended Regular Expression (ERE) to filter lines. When using regular expression, the regular expression must appear before the left brace:

```
$ awk 'BEGIN(FS="."); /test/{print $1}' datal
This is a test
```

# The matching operator

The matching operator allows you to restrict regular expression to data field. The matching operator is the tilde symbol (~).

# Mathematical expressions

Besides regular expressions you can also use mathematical expressions. This feature comes in handy when matching numerical values. For example, if you want to display all the system users who belong to the root group (group 0), you could use this script:

```
$ awk -F: '$4 == 0 {print $1}' /etc/passwd
```

This script displays the first field value for all lines that contain the value 0 in the fourth field.

# Structured commands

The gawk program supports the following structured commands:

The if-then-else statement:

```
if (condition) statement1; else statement2
```

The while statement:

```
while (condition)
{
  statements
}
```

The do-while statement:

```
do {
  statements
} while (condition);
```

The for statement:

```
for(variable assignment; condition; iteration process);
```

This provides a wealth of programming opportunities for the gawk script. You can write gawk programs that rival the functions of just any higher-level language.

# Appendix C

# Comparing Shells

With the wealth of shells available in the Linux environment, sometimes it's hard to decide which shell best suits your needs. Other times you're limited to using a specific shell and need to determine which features you use in shell scripts in your default shell are available in the new shell and which ones aren't. This appendix provides a quick comparison between the features of the different shells that are commonly used in the Linux environment.

# Variables

Each shell supports environment and user-defined variables, but they differ on just how they support variables. This section describes the things you need to watch out for working with variables in your shell scripts.

# Environment variables

The bash, dash, ksh93, and zsh shells use all uppercase letters for environment variables. The zsh provides both upper- and lower-case environment variables for the common variables, so if you refer to upper-environment variables in your script, they'll work just fine in the zsh shell.

Unfortunately, the tcsh shell uses lower-case variables for special variables. However, it provides a limited number of upper-environment variables that match some of the Bourne shell environment variables to provide limited compatibility. If your script relies heavily on bash shell environment variables, you'll want to check to make sure that those variables are available in the tcsh shell.
