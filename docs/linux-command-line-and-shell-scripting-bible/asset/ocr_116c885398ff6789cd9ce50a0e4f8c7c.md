As you can see, there's lot of overlap between the Unix and BSD style. Most of the information you get from one you can also get from the other. Most of the time one you use depends on which format you're more comfortable with (for example, if you were used to a BSD environment before using Linux).

When you use the BSD-style parameters, the ps command automatically changes the output to simulate the BSD format. Here's an example using the ps parameter:

```
$ ps 1 UID PID PPID NI VSZ RSS WCHAN STAT TTY COMMAND
0 500 3081 20 0 4692 1342 Ss pts/0 0:00 -bash
0 500 3081 20 0 4468 844 - R+ pts/0 0:00 ps 1$
```

Notice that many of the output columns are the same as when we used the Unix-style parameters, there are a couple of different ones:

+   - VSZ: The size in kilobytes of the process in memory
- RSS: The physical memory that a process has used that isn't swapped out
- STAT: A two-character state code representing the current state

Many system administrators like the BSD-style ps parameter because it produces a more detailed state code for processes (the STAT column). The two-character code more precisely defines exactly what's happening with the process than the single-character Unix-style output.
