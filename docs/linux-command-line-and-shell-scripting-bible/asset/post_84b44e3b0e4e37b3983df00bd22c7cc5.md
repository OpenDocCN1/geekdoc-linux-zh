## Creating an hourly archive script

If you're in a high-volume production environment where files are changing rapidly, a daily archive might not be good enough. If you want to increase the archiving frequency to hourly, you'll need to take another item into consideration.

If you're backing up files hourly, and trying to use the date command to timestamp each file name, can get pretty ugly quickly. I don't think you'd want to have to sift through a directory of filenames like this:

Instead of placing all of the archive files in the same folder, you would be better off: creating a hierarchy for your archived files. Figure 27-3 demonstrates this principle.

The archive directory contains directories for each month of the year, using the month as the directory name. Each month's directory in turn contains folders for each day of the month (using the numerical value as the directory name). This allows you to timestamp the individual archive files, place them in the appropriate directory for the day and month.

Now you have a new challenge to solve. Your script must create the individual month and day directories automatically, and know that if they already exist, they don't need to be created. As it turns out, this isn't as hard as it sounds!

If you use the line options for the mkdir command (see Chapter 3), you'll find the -p command line option. This option allows you to create directories and subdirectories in a single command, plus the added benefit in that it doesn't produce an error message if the directory already exists. Perfect!

We're now ready to create the archive-hourly script. Here's what it looks like:

```bash
$ cat archhourly
#!/bin/bash
# archive a working directory hourly

DAY=`date +%d`
MONTH=`date +%m`
TIME=`date +%k%M`
```

```bash
SOURCE=/home/rich/test
BASEDEST=$home/rich/archive

mkdir -p $BASEDEST/$MONTH/$DAY

DESTINATION=$BASEDEST/$MONTH/$DAY/archive$TIME
tar -cf $DESTINATION $SOURCE 2>/dev/null
gzip $DESTINATION
```

The script retrieves the day and month values from the command line, along with the times-used to uniquely identify the archive file. It uses that information to create the archive directory for the day (or just list if it already exists). Finally, the script uses the tar and gzip commands to create the archive and compress it.

Just as with the daily script, it's a good idea to test the archhourly script before putting it in the cron table:

```

$ ./archhourly

drwxr-xr-x 3 rich rich 4096 2008-02-06 13:19 ..
-rw-rw-r-- 1 rich 3145 2008-02-06 13:19 archive1319.gz
```

The script worked the first time, creating the appropriate month and day directories, creating the archive file just to test things, I ran it a second time to see if it would have a problem with the existing directories. The script again just fine and created the server archive file. It's now ready for the cron table!

## Creating the script

The mailarch script creates an archive file as you did with the daily and hourly scripts. Once it creates the archive file. Here's the script:

```bash
$ cat mailarch
#!/bin/bash
# archive a working directory and mail it out

MAIL=`mutt`
DATE=`date +%y%m%d`
FILE=archive$DATE
SOURCE=/home/rich/test
DESTINATION=/home/rich/archive/$FILE

tar -cf $DESTINATION $SOURCE 2>/dev/null
zip -a $DESTINATION
```

One thing you might notice about the mailarch script is that it uses the compression utility instead of the gzip command. This allows you to create a file that is more easily handled on non-Linux systems, such as Windows workstations.

## Running the script

The mailarch script runs the same as the daily script, by placing it in the cron table to run at a specific time of the day (usually at night). When the script runs, it creates the archive file, compresses it using the zip command, then sends it off in an e-mail message. Figure 27-4 demonstrates what the e-mail message should look like.
