# Basic Script Building

Save this script in a file called test1, and you are almost ready. I say "almost" because there are still a couple of things to do before you can run your new shell script.

If you try running the file now, you'll be somewhat disappointed to see this:

```
$ test1
bash: test1: command not found
```

The first hurdle to jump is getting the bash shell to find your script file. If you remember Chapter 5, the shell uses an environment variable PATH to find commands. Looking at the PATH environment variable explains my problem:

```
$ echo $PATH
/usr/local/bin:bin:/usr/bin:/usr/X11R/bin:/usr/X11R/bin
```

The PATH environment variable is set to look for commands only in a handful of directories. To get the shell to find my script file, I need to do one of these:

+   - Add the directory where my script file is located to the PATH environment variable.
- Use an absolute or relative filepath to reference my script file in the prompt.

> Some Linux distributions add the $HOME/bin directory to the PATH environment. This creates a place in every user's HOME directory to place files where the shell can find them to execute.

For this example, I will use the second method to tell the shell exactly where my script file is located. Remember, to reference a file in the current directory, you can use the dot operator in the shell:

```
$ ./test1
bash: ./test1: Permission denied
```

Now the shell will execute script file just fine, but there's another problem. The shell indicates that I don't have permission to execute the file. A quick look at the file permissions should show what's going on here:

```
$ ls -l test1
-rw-r--r-- 1 rich 73 Sep 24 19:56 test1
```

When I created the new test1 file, my umask value determined the default permission settings for the new file. Since my umask is set to 022 (see Chapter 6), the system created the file with only read/write permissions for myself.
