You set these environment variables just as you would any other environment variable before using the Lynx program:

```
$ http_proxy=http://myproxy.com:8080
$ lynx
```

To specify a proxy server, you must provide the protocol, the server name, and the port used to communicate with the proxy server. If you need this variable setting, it's usually a good idea to include it in a common startup file for your shell (such as the .bashrc file for a graphical screen) so you don't have to enter it every time.

## Capturing data from Lynx

When you use Lynx in a shell script, most likely you're trying to obtain a specific piece (or pieces) of information from a Web page. The technique to accomplish this is screen scraping. In screen scraping, you are trying to proactively find data in a specific location on a graphical screen so you can capture it and use it in your shell script.

The easiest way to perform screen scraping with Lynx is to use the -dump option. This option doesn't bother trying to display the Web page on the terminal screen. Instead, it displays the Web page text directly to STDOUT:

```
$ lynx -dump http://localhost/RecipeCenter/
```

Once you have all of the text data from the Web page, you probably know what tools we're going to get out of the toolbox to start on extracting data. That's right, our old friends the sed and gawk programs (Chapter 16).

First, let's find some interesting data to collect. The Yahoo! weather Web page is a great source for finding the current conditions anywhere in the world. Each location uses a URL to display weather information for that city (you can find the specific URL for your city by going to the site in a normal browser, and entering in your city's information). The Lynx command for finding the weather in Chicago, Illinois, is:

```
lynx -dump http://weather.yahoo.com/forecast/US025.html
```

This command dumps lots and lots of data from the Web page. The first step is to find the precise information you want. To do that, redirect the output from lynx command to a file, then search the file for data. After doing that, I found this text in the output:

Current conditions as of 5:54 pm EDT
Feels Like: 50°
Barometer: 29.3 in
Humidity: 23°
Visibility: 4 mi
Dewpoint: 48°
Wind: 16 mph

That is just all the information about the current weather that you'll need. There's just one problem with this output: you'll notice that the numbers are on the line below the heading. Trying to extract individual numbers will be difficult. The key to solving this is to write a sed script that can search for the heading. When you find it, you can then go to the correct line to extract the data. We're fortunate in this example all the data we need are on lines by themselves. We should be able to solve this with just the sed script. First, you need to create a sed script that will look for the Current conditions, then skip two lines to get the text that describes the current weather, and print it. Perfect. Now you can use these sed scripts in a shell script that first captures the Lynx output of the Web page to a temporary file, then applies the sed scripts to the Web page to extract only the data you're looking for. Here's an example of how to do:

```bash
#!/bin/bash
# extract the current weather for Chicago
URL="http://weather.yahoo.com/forecast/US025.html"
LYNX=`which lynx`
TMPFILE=`mktemp tmpXXXXXX`
$LYNX -dump $URL > $TMPFILE
conditions=`cat $TMPFILE | sed -n '2p'`
temp=`cat $TMPFILE | sed -n '3p'`
rm -f $TMPFILE
echo "Current conditions: $conditions"
echo "The current temp outside is: $temp"
```

Current conditions: Light Rain
Current temp outside is: 49°

The weather script connects to the Yahoo! weather page for the desired city, saves the Web page to a temporary file, extracts the appropriate text, removes the temporary file, and displays the weather information. The beauty of this is once you have extracted the data from a website you can do whatever you want with it, such as create a table of temperatures. You can then create a cron job (see Chapter 13) that runs every day to track daily temperatures.

> CAUTION The Internet is a dynamic place. Don't be surprised if you spend hours working out the precise location of data on a Web page, only to find that it moved a couple of weeks later, breaking your scripts. In fact, it's possible that my example won't work by the time you read this. The important thing is to know the process for extracting data from Web pages. You can then apply that to any situation.

## cURL Program

The popularity of Lynx has spawned another similar product, called cURL. The cURL program allows you to automatically transfer files from the command line using a specified URL. It currently supports the FTP, FPS, HTTP, HTTPS, SCP, SFTP, TFTP, DICT, Telnet, LDAP, LDAPS, and FILE protocols as specified in URLs.

While cURL isn't used as a Web page browser per se, it allows you to easily send or retrieve data unattended from the command line, or your shell scripts, by using a simple command. This provides a great tool to have in your shell scripting toolbox. This section walks through the process of installing and using cURL in your shell scripts.

> CAUTION There's also a programming language called curl, owned and marketed by the Sun Microsystems Corporation. Don't confuse cURL with the curl programming language.

## Installing cURL

With its growing popularity, cURL is installed by default in many Linux distributions. It's not available for your Linux distribution, or if you just want to use the latest version, you can download the source code and compile it on your Linux system. Again, the standard disclosures apply; you must have the C development libraries installed on your Linux system for it to work.

Here are the steps for downloading and installing cURL:

1. Go to the main cURL Web site at curl.haxx.se, and click the Download link on the left side of the page.
2. Click the link for the latest version of cURL in the archive format of your choice (such as .tar.gz).
3. Change to the resulting working directory curl-7.18.0:
cd curl-7.18.0
4. Execute the configure script in the directory:
./configure
5. Execute the utility to compile the source code and create the executable file:
make
6. As the root user, copy the curl executable file to a common directory in your PATH, such as the /usr/local/bin directory.
