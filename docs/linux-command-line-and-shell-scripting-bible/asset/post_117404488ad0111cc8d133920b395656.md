# Part V Advanced Topics

Before using the command line to send e-mail messages, you'll need to know how e-mail works in the Linux environment, and what applications you'll need to have installed and configured. The Linux e-mail environment consists of three elements, a Mail Transport Agent (MTA) program, a Mail Delivery Agent (MDA) program (which is often part of the MTA program), and a Mail User Agent (MUA) program.

The MTA program is responsible for sending and receiving mail messages for the Linux system. It must know how to pass incoming mail messages to the proper user mailboxes, as well as how to send outbound mail messages destined for remote mail servers. Often the MTA program will use a proxy server (also called a smart host) to do the detailed mail delivery. It forwards any message destined for a user on a remote mail server to the smart host to make the delivery on its.

The MDA program is responsible for ensuring that mail destined for local users ends up in the proper local mailbox. Sometimes this is performed directly by the MTA program. However, if you require advanced mail features, such as out-of-office notifications or spam filtering, you can configure the MTA program to pass to the MDA program, which often has these capabilities built in.

The easiest way to send e-mails from your shell script is to use the Mailx program. This program allows you to specify the subject header and recipients on the command line. You create the message body by redirecting text to the Mailx program. You can do this using either the echo command or the cat command to redirect the contents of a file to the mail message.

Mutt is a more advanced command line MUA program that provides the ability to attach files to the mail message rather than including text inside the body. This allows you to attach large files that customers can easily save for other programs, such as spreadsheets or word processing.

The last chapter covers an important part of shell scripts. If you're a Linux administrator, most likely you'll run into a situation where you'll want to regularly monitor the status. By creating a shell script and placing it in a cron job, you can easily monitor what's going on.

## Monitoring Statistics

One of the core responsibilities of the Linux administrator is to ensure that the system is running properly. To accomplish this task, there are lots of different statistics that you must monitor. Creating automated shell scripts to monitor specific situations can be a lifesaver. This section shows how to create simple shell scripts that monitor and report problems as soon as possible, without ever having to log in to the Linux system.

## Monitoring disk space

One of the biggest problems with multi-user Linux systems is the amount of available disk space. In some situations, such as in a file sharing, disk space can fill up immediately because of one careless user. To automatically monitor the available space, the best command to monitor disk space is the df command (see Chapter 4). The basic output of the df command looks like:

```
$ df
FileSystem     K-blocks  Used Use% Mounted on
/dev/hd1      319728 258980  81% /
/dev/sda1     127544 103444  81% /var/run
/dev/sda2     127544    5200   4% /var/lock
/udev         127544    44000  4% /dev
/dev/shm      127544         0   0% /dev
/dev/hd3      801636 631328  79% /
```

The df command shows the disk statistics for all the real and virtual disks on the system. For the purposes of this exercise, we'll monitor the size of the root filesystem. We'll first need to parse the results of the df command to extract only the line for the root filesystem.

There are a couple of different ways to do this. The easiest is to use the sed command to search for the line that ends with a forward slash:

```
/dev/hd1      319728 258980  81% /
```

The sed script to build this uses the dollar sign (to indicate the end of the line), and the forward slash (which you'll need to escape since it's a sed special character). That will look like:

```
$ df | sed -n '\/\$/p'
/dev/hd1      319728 258980  81% /
```

Now that you've got the statistics for the root filesystem, the next step is to isolate the percentage value used in the line. To do that, you'll need to use the awk command:

```
$ df | sed -n '\/\$/p' | awk '{print $5}'
81%
```

This is close, but there is still one small problem. The awk command lets out the fifth data field, but the value also includes the percent symbol. You'll need to remove that so you can use the value in a mathematical expression. That's easily accomplished by using the sed command:

```
$ df | sed -n '\/\$/p' | awk '{print $5}' | sed 's/%//'
81
```

Now you're in business! The next step is to use this information to create the script.

## Creating the script

Now that you know how to extract the used disk space value, you can use that formula to store the value to a variable. You can then check the variable against a predetermined number to indicate when the used space has exceeded your set limit.

Here's an example of code using this technique:

```bash
cat diskmon
!/bin/bash
# monitor available space

SPACE=`df | sed -n '/$$$/p' | awk '{print $5}' | sed 's/%//'

if [ $SPACE -ge 90 ]
then
echo "Disk space on root at $SPACE used" | mail -s "Disk warning" rich
fi
```

And you have it. A simple shell script will check the available disk space on the filesystem and send an e-mail message if the used space is at 90% or more.
