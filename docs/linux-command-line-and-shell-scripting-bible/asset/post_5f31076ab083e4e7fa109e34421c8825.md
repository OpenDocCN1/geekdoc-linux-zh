
## Graphics capabilities

The most important part of terminal emulation is how it displays information on the monitor. When you hear the phrase "test mode," the last thing you'd think to worry about is graphics. However, even the most rudimentary dumb terminals supported some method of manipulation (such as clearing the screen and displaying text at a specific location on the screen).

This section describes the graphics features that make each of the different terminal types unique, and what to look for in the terminal emulation packages.

## Character sets

All terminals must display characters on the screen (otherwise, text mode would be pretty useless). The trick is in what characters to display, and what codes the Linux system needs to send binary commands that the Linux system sends to display characters. There are several character sets that are supported by various terminal emulation packages:

- ASCII The American Standard Code for Information Interchange. This character set contains the English characters stored using a 7-bit code, and consists of 128 English letters (both upper and lower case), numbers, and special symbols. This character set was adopted by the American National Standards Institute (ANSI) as AS-ASCII. You will often see it referred to in terminal emulators as the ASCII character set.
- ISO-8839-1 (commonly called Latin-1) An extension of the ASCII character set developed by the International Organization for Standardization (ISO). It uses an 8-bit code to support the standard ASCII characters as well as special foreign language characters for Western European languages. The Latin-1 character set is popular in multilingual terminal emulation packages.
- ISO-8859-2 ISO character set that supports Eastern European language characters.
- ISO-8839-6 ISO character set that supports Arabic language characters.
- ISO-8859-7 ISO character set that supports Greek language characters.
- character set that supports Hebrew language characters.
- ISO-10646 (commonly called Unicode) This 2-byte character set contains codes for most English and non-English languages. This single character set contains all of the codes defined in all ISO-8859-x series of character sets. The Unicode character set is quickly becoming popular among open source applications.

By far the most common character set we use today in English-speaking countries is the Latin-1 character set. The Unicode character set is becoming more popular, and may very well one one day become the new standard in character sets. Most popular terminal emulators allow you to select which character set to use in the terminal emulation.

## Control codes

Besides being able to display characters, terminals must have the ability to control features on the monitor and keyboard, such as the cursor location on the screen.

Common control code functions are the carriage return (return the cursor to the beginning of the line), line feed (put the cursor on the next horizontal row), horizontal tab (shift the cursor over a preset number of spaces), arrow keys (up, down, left, and right), and the page up/page down keys. These control codes mainly emulate features that the cursor is placed on the monitor, there are also other control codes, as clearing the entire screen, and even a bell ring (emulating the old typewriter end-of-carriage bell).

Control codes were also used in controlling the communication features of dumb terminals. Dumb terminals were connected to the computer system via some type of communication channel, often a serial communication channel. Times data were needed on the communication channel, so developers devised special control codes for data communication purposes. While these codes are not necessarily required in modern terminal emulators, many support these codes to maintain compatibility. The most common codes in this category are the XON and XOFF codes, which start and stop data transmission to the terminal.

## Block mode graphics

As dumb terminals became more popular, manufacturers started experimenting with rudimentary graphics capabilities. By far the most popular type of "graphical" dumb terminal used in the Unix world was the DEC VT22 series of terminals. The turning point for dumb terminals came with the release of the DEC VT100 in 1978. The DEC VT100 was the first terminal to support the complete ANSI character set, including block mode graphics characters.

The ANSI character set contains codes that not allowed monitors to display text but also rudimentary graphics symbols, as boxes, lines, and blocks. By far one of the most popular dumb terminals used in Unix operations during the 1980s were the VT102, an upgraded version of the VT100. Most terminal emulation programs emulate the operation of the VT102 display, supporting all of the ANSI codes for creating block mode graphics.

## Vector graphics

The Tektronix produced a series of terminals that used a display method called vector graphics. Vector graphics deviated from the DEC method of block mode graphics making all screen images (including characters) a series of line segments (vectors). The Tektronix 4010 terminal was the most popular graphical dumb terminal produced. Many terminal emulation packages still emulate its capabilities.

The 4010 terminal displays images by drawing a series of vectors using an electron beam, like drawing with a pencil. Since vector graphics does not use to create lines, it has the ability to draw geometric shapes with higher precision than most dot-oriented graphics terminals. This was a popular feature among mathematicians and scientists.

Terminal emulators use software to emulate the vector graphics capabilities of the Tektronix 4010 terminals. This is still a popular feature for people who need precise graphical drawings, or those who still run applications that used the vector graphics routines to draw complicated charts and diagrams.

## Display buffering

A key to graphics displays is the ability of the terminal to buffer data. Buffering data requires having additional memory within the terminal to store characters not currently displayed.

The DEC series of terminals utilized two types of buffering:

- Buffering data as it scrolled off the main display (called history)
- Buffering a completely separate display window (called alternate screen)

The first type of buffering is known as a scroll region. The scroll region is the area of memory the terminal has that enables it to remember, as it scrolls off the screen. A standard VT102 terminal used an area for 25 lines. As the terminal displays a new line of characters, the previous line is scrolled up. When the terminal reaches the bottom of the display, the next line calls the top line to scroll off the display.

The internal memory in the VT102 allowed it to save the last 64 lines that had scrolled off the display. Users had the ability to lock the current display and use arrow keys to scroll through the previous lines. Terminal emulation packages allow you to use either a scrollbar or a mouse scroll button to scroll through the data without having to lock the display. For course, full emulation, most terminal emulation packages also allow you to lock the display and use arrow and page up/page down to scroll through the saved data.

The second type of buffering is known as an alternate screen. Normally, the terminal writes directly to the normal display area on the monitor. A method was used to quickly implement animation by using two screen areas to store data. Control codes were used to signal the terminal to write to the alternate screen instead of the current display screen. Data was held in memory. Another control could signal to switch the display between the normal screen data and the data contained in the alternate screen instantaneously. By storing successive pages in the alternate screen, then displaying them, you could crudely simulate moving graphics.

Terminals that emulate the VT100 series of terminals have the ability to support the alternative screen method.
