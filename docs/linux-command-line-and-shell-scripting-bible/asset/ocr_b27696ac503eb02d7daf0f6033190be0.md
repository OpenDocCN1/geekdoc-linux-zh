5. Run the configure script to build the necessary files for compiling Mutt on your system:
./configure

6. As the root user, run the make utility with the install option to create and install Mutt:
make install

This will install the Mutt program on your Linux system for you to use from the command line.

# The Mutt command line

The Mutt command provides parameters for you to use to control how Mutt operates. Table 26-7 shows the command line parameters available to you.

With the myriad of command line parameters you can customize your e-mail message directly from the command line, which is exactly what'll want to do in your shell scripts.

Much as with the Mailx program, there's one thing that you can't specify on the command line with the Mutt program, and that's the message body text. If you don't redirect the text to the Mutt program, it'll start in text-graphics mode with an editor window for you to type the message body.

This is not a good thing for the shell script, so you'll always want to redirect some of text for the message body, even if you're using the attachment option to specify a file to attach. The next section demonstrates how to do this.

# Using Mutt

Now you're ready to start using the Mutt program in your shell scripts. To create the basic mut command in your shell script, you'll want to include command line options that specify the sub- of the message, the attachment file, and all the recipients of the message:

```
mutt -s Subject -a file recipients
```

The recipients list is a space-separated list of the e-mail addresses to send the message to. If you want to attach more than one file, you'll need multiple -a options, as each option can only declare one filename. The file parameter must be an absolute pathname, or a relative pathname relative to the current working directory from which you're running the mut command.

There's one other catch with the mut command. If you don't redirect the text to an editor window, Mutt will automatically go to full-screen mode for you to enter the text in an editor window. Most likely this is what you don't want to do, so be sure to redirect some text for the message body, even if it's an empty file:

```
# echo "Here's the log file" | mutt -s "Log file" -a
/var/log/messages rich
```
