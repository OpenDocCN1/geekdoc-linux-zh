
## Basic bash Shell Commands

On my Fedora Linux system, it looks like this:

```bash
[rich@testbox ~]$
```

You can configure the prompt to provide basic information about your environment. The first example above shows three pieces of information in the prompt:

- The username that started the shell
- The current virtual console number
- The current directory (the tilde sign is shorthand for the home directory)

The second example provides similar information, except it uses the hostname instead of the virtual console number. There are two environment variables that control the format of the command line prompt:

- PS1: Controls the format of the default command line prompt
- PS2: Controls the format of the second-tier command line prompt

The shell uses the default PS2 prompt for initial data entry into the shell. If you enter a command that requires additional information, the shell displays the second-tier prompt specified by the PS2 variable.

To display the current settings for your prompt, use the echo command:

```bash
rich[1~]$ echo $PS1
\u@1[W]\$
rich[1~]$ echo $PS2
>
rich[1~]$
```

The format of the prompt environment variables can look pretty odd. The shell uses special characters to signify elements within the command line prompt. Table 3-2 shows the special characters that you can use in the prompt string.

Notice that all of the special prompt characters begin with a backslash (\). This is what delineates a prompt character from normal text in the prompt. In the earlier example, the prompt contains both prompts and a normal character (the "@" sign, and the square brackets). You can create any combination of prompt characters in your prompt. To create a new prompt, just assign a string to the PS1 variable:

```bash
rich@testbox ~]$ PS1="[\t][\u]$
[14:40:32]$rich]$
```

This new prompt now shows the current time, along with the username. The new PS1 definition only lasts for the duration of the shell session. When you start a new shell, the default shell prompt definition is reloaded. In Chapter 5 you'll see how you can change the default shell prompt for all sessions.

## The bash Manual

Most Linux distributions include an online manual for looking up information on shell commands, as well as lots of other GNU utilities included in the distribution. It is a good idea to become familiar with the manual, as it is invaluable for working with utilities, especially when trying to figure out various command parameters.

The man command provides access to the manual pages on the Linux system. Entering the man command followed by a specific utility name provides the manual entry for that utility. Figure 3-1 shows an example of looking up the manual pages for the date command.

The man page divides information about the command into separate sections, as shown in Table 3-3.

You can step through the man pages by pressing the spacebar or using the arrow keys to scroll forward and backward through the man page text (assuming that your terminal emulation supports the arrow functions).

To see information about the bash shell, look at the man pages for it using the command:

```bash
$ man bash
```

This allows you to step through the entire man pages for the bash shell. This is extremely handy when building scripts, as you don't have to refer back to books or Internet sites to look up specific formats for commands. The manual is always there for you in your session.

## Filesystem Navigation

As you can see from the shell prompt, when you start a shell session you are usually placed in your home directory. Most often, you will want to break out of your home directory and to explore other areas in the Linux system. This section describes how to do that using command lines. Before we do that, we should take a tour of just what the Linux filesystem looks like we know where we're going.

## The Linux filesystem

If you're new to the Linux system, you may be confused by how it references files and directories, especially if you're used to the way that the Microsoft Windows operating system does. Before exploring the Linux system, it helps to have an understanding of how it's laid out.

The first difference you'll notice is that Linux does not use drive letters in pathnames. In the Windows world, the physical drives installed on the PC determine the pathname of the file. Windows assigns a letter to each physical disk drive, and each drive contains its own directory structure for accessing files stored on it.

For example, in Windows you may be used to seeing file paths such as C:\Users\Documents\test.doc.

> You'll notice Linux uses a forward slash (/) instead of a backward slash (\) to denote directories in filepath. The backslash character in Linux denotes an escape character, and causes all sorts of problems when you use it in a filepath.

The tricky part about the virtual directory is how it incorporates each storage device. The first hard drive installed in a Linux PC is called the root drive. The root drive contains the core of the virtual directory. Everything else builds from there.

On the root drive, Linux creates special directories called mount points. Mount points are directories in the virtual directory where you assign additional storage devices.

The virtual directory causes files and directories to appear within these mount point directories, even though they are physically stored on a different drive.

Often the system files are physically stored on the root drive, while user files are stored on a different drive, as shown in Figure 3-2.
