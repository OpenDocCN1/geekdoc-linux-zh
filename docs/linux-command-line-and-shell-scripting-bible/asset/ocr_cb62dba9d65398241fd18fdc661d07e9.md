# # Default Isof Output

| Column | Description |
|---|---|n| COMMAND | The first nine characters of the name of the command in the process |
| PID | The process ID of the process |
| USER | The login name of the user who owns the process |
| FD | The file descriptor number and access type (r - read, w - write, u - read/write) |
| TYPE | The type of file (CHR - character, BLK - block, DIR - directory, REG - regular file) |
| SIZE | The device numbers (major and minor) of the device |
| NODE | If available, the size of the file |
| NAME | The node number of the local file |

Now, let's take a look at the results of the lsof command from inside a script that's opened a couple of alternative file descriptors:

```
$ cat test18
#!/bin/bash
# testing lsof file with file descriptors

exec 3> test18file1
exec 6 > test18file2
exec 7 < testfile

/usr/sbin/lsof -a -p $$d0.1.2.3.6.7
$ /test18
COMMAND PID USER TYPE DEVICE SIZE NODE NAME
test18 3594 rich 0u CHR 136.0 2 /dev/pts/0
test18 3594 rich 2u CHR 136.0 2 /dev/pts/0
est18 3594 rich CHR 136.0 2 /dev/pts/0
18 3594 rich 3w REG 253.0 0 360712 /home/rich/test18file1
18 3594 rich 6w REG 253.0 0 360715 /home/rich/test18file2
18 3594 rich 7r REG 253.0 73 360717 /home/rich/testfile
$
```

The script creates three file descriptors, for output (3 and 6) and one for (7). When the script runs the lsof command, you can see the new file descriptors in the output. I truncated the first part of the output so that you could see the results of the file name. The filename shows the complete pathname for the files used in the file descriptors. It shows each of the files as type REG, which indicates that they are regular files on the filesystem.
