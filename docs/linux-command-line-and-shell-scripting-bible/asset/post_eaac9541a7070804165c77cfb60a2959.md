# Getting Graphic

If you're looking for even more graphics for your interactive scripts, you can go step further. But the KDE and GNOME desktop environments (see Chapter 1) have expanded on the dialog command idea and include commands that produce X Windows graphical widgets for their respective environments.

This section describes the kialog and zenity packages, which provide graphical window widgets for the KDE and GNOME desktops, respectively.

# The KDE environment

The KDE graphical environment includes the kialog package by default. The kialog package uses the kialog command to generate standard windows, similar to the dialog-style widgets, within your KDE desktop. This allows you to produce Windows-quality user interfaces directly from your shell scripts!

# kialog widgets

Just like the dialog command, the kialog command uses line options to specify what type of window widget to use. The format of the kialog command is:

```
kialog display-options window-options arguments
```

The window-options options allow you to specify what type of window widget to use. The available options are shown in Table 15-5.

As you can see from Table 15-5, all of the standard dialog box types are represented. However, when you use a kialog window widget, it appears as a separate window in the KDE desktop, not inside the terminal emulator session!

The checklist and radiolist widgets allow you to define individual items in the lists, and whether they are selected by default:

```bash
$ kialog --checklist "Items I need" 1 "Toothbrush" on 2 "Toothpaste" off 3 "Hair brush" on 4 "Deodorant" off 5 "Slippers" off
```

You can use kdialog window widgets in your shell scripts similarly to how you use dialog widgets. The big difference is that kdialog window widgets output values using STDOUT instead of STDERR. Here's a script that converts the sys admin created earlier into a KDE application:

```bash
#!/bin/bash
# using kdialog to create menu
temp=`mktemp -t temp`
temp2=`mktemp -t temp2`
```

```bash
function diskspace {
  df > $temp
  kdialog --textbox $temp 1000 10
}
```

```bash
function whoseon {
  who > $temp
  kdialog --textbox $temp 500 10
}
```

```bash
function memusage {
  cat /proc/meminfo > $temp
  kdialog --textbox $temp 300 500
}
```

```bash
while [ 1 ]
do
  kdialog --menu "Sys Admin Menu" "1" "Display disk space" "2" "Display users" "3" "Display memory usage" "0" "Exit" > $temp2
if [ $? -eq 1 ]
then
    break
fi
```

```bash
selection=$cat $temp2
case $selection in
1)
  diskspace ::
2)
  whoseon ::
3)
  memusage ::
0)
  break
*)
  dialog --msgbox "Sorry, invalid selection"
esac
done
```

There isn't much difference from using kdialog command and the dialog command. The resulting menu is shown in Figure 15-10. Now things are looking like a real application! There's no limit to what you can do with your interactive scripts.

# zenity widgets

Just as you expect, zenity allows you to create different windows widgets using command line options. Table 15-6 shows the different widgets that zenity can produce. The zenity program works different than the kdialog and dialog programs. Many of the widget types are defined using additional options on the command line, instead of including them as arguments to an option.

The zenity program offers some pretty cool basic dialog windows. The calendar produces a full month calendar, as shown in Figure 15-11. When you select a date from the calendar, zenity returns the value to STDOUT, just like kdialog:

```bash
$ zenity --calendar
```
