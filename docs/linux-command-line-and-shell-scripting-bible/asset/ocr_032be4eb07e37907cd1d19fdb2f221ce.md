The caret anchor character checks for the pattern at the beginning of each new line of data,
determined by the newline character:

```
$ cat data3
This is a test line.
this is another test line.
A line that tests this feature.
Yet more testing of this
$ sed -n '/^this/p' data3
this is another test line.
$ 
```

As long as the pattern appears at the start of a new line, the caret anchor will catch it.

If you position the caret character in any place other than the beginning of the pattern, it'll act
as a normal character and not as a special character:

```
$ echo "This ^ is a test " | sed -n '/s /^/p'
This is a test
$ 
```

Since the caret is listed in the regular expression pattern, the sed editor uses it as a
normal character to match text.

> If you need to specify a regular expression pattern using only the caret character, you
don't need to escape it with a backslash. However, if you specify the caret character
, followed by additional text in the pattern, you'll need to use the escape character before the
caret character.

# Looking for the ending

The opposite of looking for a pattern at the start of a line is looking for it at the end of a line.
dollar sign ($) special character defines the end anchor. Add this special character after a text
pattern to indicate that the line of data must end with the text pattern:

```
$ echo "This is a good book" | sed -n '/book$/p'
This is a good book
$ echo "This book is good" | sed -n '/book$/p'
$ 
```

The problem with an ending pattern is that you must be careful of what you are looking for:

```
$ echo "There are a lot of good books" | sed -n '/book$/p'
$ 
```

Making the book plural at the end of the line means that it no longer matches the regular
expression pattern, even though book is in the data stream. The text pattern must be the last
th on the line for the pattern to match.
