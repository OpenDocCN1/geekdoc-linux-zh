## Linux LiveCD

A relatively new phenomenon in the Linux world is the bootable Linux CD distribution. It lets you see what a Linux system is like without actually installing it. Most modern PCs can boot from a CD instead of the standard hard drive. To take advantage of this, some Linux distributions create a bootable CD that contains a sample Linux system (called a Linux LiveCD). Because of the limitations of the single CD size, the sample can't contain a complete Linux system, but you'd be surprised at all the software can cram in. The result is you can boot your PC from the CD and run a Linux distribution without having to install anything on your hard drive!

This is an excellent way to test various Linux distributions without having to mess with your PC. Just pop in a CD and boot! All of the Linux software will run directly off the CD. There are lots of LiveCDs that you can download from the Internet and burn onto a CD to test.

Table 1-8 shows some popular LiveCDs that are available.

You may notice a familiarity in this table. Many specialized Linux distributions also have a Linux LiveCD version. Some Linux LiveCD distributions, such as Ubuntu, allow you to install the Linux distribution directly from the LiveCD. This enables you to boot with the CD, test the Linux distribution, and then if you like it, install it on your hard drive. This feature is extremely handy and user-friendly.

As with all good things, Linux Live CDs have a few drawbacks. Since you access everything from the CD, applications run more slowly, especially if you're using older, slower computers and CDs also. Also, since you can't write to the CD, any changes you make to the Linux system will be gone the next time you reboot.

But there are advances being made in the Linux LiveCD world that would help to solve some of these problems. These advances include the ability to:

- Copy Linux system files from the CD to memory
- Copy system files to a file on the hard drive

- Store system settings on a USB memory stick
- Store user settings on a USB memory stick

Some Linux LiveCDs, such as Puppy Linux, are designed with a minimum number of Linux system files and copy them directly into memory when the CD boots. This allows you to remove the CD from the computer as soon as Linux boots. Not only does this make your applications much faster (since applications run faster from memory), but it also gives you a free day for ripping audio CDs or playing video DVDs from the software included in Puppy Linux.

Other LiveCDs use an alternative method that allows you to remove the CD from the tray after booting. It involves copying the core Linux files onto the Windows hard drive as a single file. After the CD boots, it looks for that file and reads the system files from it. The dyneolic Linux LiveCD uses this technique, which is called docking. Of course, you must copy the system to your hard drive before you can boot from it.

A very popular technique for storing data from a live Linux CD session is to use a common USB memory stick (also called a flash drive and a thumb drive). Just about every Linux LiveCD recognizes a plugged-in USB memory stick (if the stick is formatted for Windows) and read and write files to it. This allows you to boot a Linux LiveCD, use the Linux applications to create files, store them on your memory stick, and then access them from your Windows applications later (or from a different computer). How cool is that?

## Terminal Emulation

Back before the days of graphical desktops, the only way to interact with a Unix system was through a text interface provided by the shell. Because of this restriction, output devices did not have to be very fancy. Often a dumb terminal was nothing more than a monitor and keyboard (although later on they started fancier by utilizing a mouse) connected to the Unix system via a communication cable. This simple combination provided an easy way to enter data

As you well know, things are significantly different in today's environment. Just about every Linux distribution uses some type of graphical environment. However, to access the shell you still need a text

One way to get to a CLI is to take the Linux system out of graphical mode and place it in text mode. This provides nothing more than a simple shell on the monitor, just like the days before graphical desktops. This mode is called the Linux console, as it emulates the old days of a hard-wired console terminal, and is a direct interface to the Linux system.

The alternative to being in the Linux console is to use a terminal emulation package from within the graphical desktop. A terminal emulation package simulates working on a dumb terminal, all within a graphical window over the desktop. Figure 2-1 shows an example of a terminal emulator running in a Linux environment.

Each terminal emulation package has the ability to emulate one or more specific types of dumb terminal. If you're going to work with the shell in Linux, unfortunately you'll need to know a little bit about terminal emulation. Knowing the core features of the dumb terminals will help you decide which emulation type to select when you're using a graphical terminal emulator, and all of the available features to their full capabilities. This section describes these features and how they relate to the different types of terminal emulators.
