> j' data2
This is the header test.
This is the starting data line.
This is the second data test.
This is the last test.
$

The first substitution command looks for the pattern text first. If it matches the pattern in the line, it replaces the text, and the test command jumps over the subsequent substitution command. If the first substitution command doesn't match the pattern, the second substitution command is processed.

Using the test command, you can clean up the loop you tried using with the branch command:

```
$ echo "This, is, a, test, to, remove, commas." | sed -n '(
:start
s/,//lp
t test
)'
This is, a, test, to, remove, commas.
This is a, test, to, remove, commas.
This is a test, to, remove, commas.
This is a test to remove, commas.
This is a test to remove, commas.
This is a test to remove commas.
$
```

When there are no more substitutions to make, the test command doesn't branch and continues with the rest of the script.

# Pattern Replacement

You've seen how to use patterns in the sed commands to replace text in the data stream. However, the problem is that sometimes when using wildcard characters it's not easy to know exactly what text will match the pattern.

For example, say that you want to place double quotation marks around a word you match in a line. That's simple enough if you're just looking for one word in the pattern to match:

```
$ echo "The cat sleeps in his hat." | sed 's/cat/"cat"/'
The "cat" sleeps in his hat.
$
```

But if you use a wildcard character in the pattern to match more one word:

```
$ echo "The cat sleeps in his hat." | sed 's/.at/".at"/g'
The ".at" sleeps in his ".at".
$
```
