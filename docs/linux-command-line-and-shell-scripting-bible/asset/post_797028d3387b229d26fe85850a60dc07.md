
# The Korn Shell

The -l and -u parameters work great in converting strings on the fly:

```
$ types -u testing
$ testing="This is a test"
$ echo $testing
THIS IS A TEST
$
```

It doesn't get any easier than that!

Use the -n parameter to allow one variable to reference the value in a separate variable. This can get confusing, so be careful when using it. Here's an example of how this works:

```
$ ntest1=100
$ typeset -n ntest1=ntest2
$ ntest2=1
$ echo $ntest1
1
$ ntest1=100
100
$ echo $ntest2
$
```

The typeset command forces the ntest1 variable and the ntest2 variable to reference the same memory location. Whatever value you assign to one, the other one also references. When I assigned a value of 1 to the ntest2 variable, it replaced the existing value in ntest1. When I displayed the value of the ntest1 variable, it showed the same value as assigned to ntest2. The same applied to ntest2 when I assigned a value to the ntest1 variable.

# Using arrays

Just like the bash shell, the ksh93 supports the use of numerical array variables:

```
$ mytest=(one two three five)
$ echo $mytest
one
$ echo \${mytest[2]}
tree
$ echo \${mytest[*]}
one two three five
$
```

The ksh93 also supports associative arrays. Associative arrays allow you to use strings as the index values instead of numbers. Before you can define the values in an associative array, you must declare the variable you'll use. You do that with the typeset command:

```
$ typeset -A test2
$
```

Once you declare the variable as an associative array, you can assign keys and values using the format:

`variable=([key1]=value1 [key2]=value2 ...)`

Each key can be any length string, and each value can be a number or a text string:

```
$ test2=([fruit]=banana [vegetable]=carrot [age]=18)
$
```

Once you define the elements in the associative array, you can access them based on the key:

```
$ echo $[test2[fruit]]
banana
$ echo $[test2[age]]
18
$
```

The problem with associative arrays is that unlike numeric arrays, where you can cycle through the index numbers, you have no way of knowing the key values that exist. To solve this problem, the ksh93 provides a special format for displaying the key values of an associative array:

```
$ echo $[!test2[@]]
fruit age vegetable
$
```

Notice that the order the keys were printed in doesn't match the order in which they were defined. This is an important thing to remember. There is no guarantee ksh93 will store the associative array values in the same order in which you define them.

While this may seem confusing, it's not really all that bad. When you display all of the element values, you'll see:

```
$ echo $[test2[*]]
banana 18 carrot
$
```

When you display the element values, they appear in the same order as the keys. This allows you to easily match the keys with their values.

Associative arrays provide a method for you to match string keys with values in your shell scripts, which can be a very powerful tool.

# Compound variables

The ksh93 supports yet another feature with variables called compound variables. A compound variable is similar to an associative array, but references the values in a slightly different manner.

To define a compound variable, you use the format:

```
variable=(subscript1=value1 subscript2=value2 ...)
```

The subscript is a text value, similar to the key in the associative array. The values can be any text or numerical values:

```
$ test3=( fruit=banana vegetable=carrot age=18)
$
```

Once you assign the subscripts and values, you can reference an individual subscript value with the format:

```
variable.subscript
```

Here's how this looks:

```
$ echo $(test3.fruit)
banana
$ echo $(test3.age)
18
$
```

Each individual subscript value can be extracted by referencing the subscript name with the variable.

# Special variable subscripts

There are several special subscripts that are available in the ksh93 shell. These subscripts define current information about the shell, as well as current information about the currently running process in the shell. Table 22-4 lists the special ksh93 shell variables.

Since the subscript variables use periods in their names, you must use braces around them when referencing them:

```
$ echo ${.sh.version}
Version M 1993-12-28 r-
$
```

The subscript variables used in discipline functions are discussed later in the "Discipline functions" section.

# Built-in commands

The ksh93 built-in commands should look a lot like the bash commands, since they're based on the Bourne shell. Table 22-5 shows the ksh93 built-in commands.

As you will, the ksh93 contains a fair amount of built-in commands, making it a robust shell to use for scripting. You should recognize most of these commands from the bash shell.

The ksh93 uses the echo, print and printf commands for displaying data.

## Table 22-4: Subscript Variables

| Variable | Description |
| :--- | :--- |
| .sh.version | The version of the shell. |
| .sh.command | The current command. |
| .sh.char | The character position of the cursor. |
| .sh.mode | The discipline mode. |
| .sh.file | The pathname of the file. |
| .sh.match | An indexed array which stores the match. |
| .sh.name | The name of the variable. |
| .sh.script | The current script name. |
| .sh.subshell | The current depth of subshells. |
| .sh.value | The value of the variable. |
