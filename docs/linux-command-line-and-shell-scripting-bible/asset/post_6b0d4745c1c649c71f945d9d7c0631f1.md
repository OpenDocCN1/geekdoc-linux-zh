
# Understanding Linux File Permissions

Some Linux distributions place the Linux user and group utilities in the /usr/sbin directory, which may not be in the PATH environment. If that's the case in your Linux distribution, either add the directory to your PATH or use the absolute filepath to run it.

The -D parameter shows what the useradd command uses if you do not specify them in the command line when creating a new user. This example shows the following default values:

- The new user will be added to a common group with group ID 100.
- The new user will have a HOME account created in the directory /home/loginname.
- The account will not be disabled when the password expires.
- The new account will not be set to expire at a set date.
- The new account will use the bash shell as the default shell.
- The system will copy the contents of the /etc/skel to your user's HOME directory.
- The system will create a file for the default user to receive mail.

The next-to-last-value is interesting. The useradd command allows an administrator to create a default HOME directory configuration, then uses that as a template to create the new user's HOME directory. This also allows you to place default files for the system in every new user's HOME directory automatically. On my Linux system, the /etc/skel directory has the following:

```bash
# ls -al /etc/skel
total 48
drwxr-xr-x 2 root 4096 2001-11-01 00:23 ..
drwxr-xr-x 107 root 12288 2007-09-20 16:53 ..
-rw-r--r-- 1 root 33 2007-02-12 10:18 .bash_logout
-rw-r--r-- 1 root 176 2007-02-12 10:18 .bash_profile
-rw-r--r-- 1 root 124 2007-02-12 10:18 .bashrc
```

You should recognize this file from Chapter 5. These are the standard startup files for the bash environment. The system automatically copies these default files into every user's HOME directory you create.

You can test this by creating a new user using the default system parameters and then looking at the HOME directory for the new user:

```bash
# /usr/sbin/useradd test
# ls -al /home/test
total 40
drwx------ 2 test test 4096 2007-09-20 18:23 .
d-rwxr-xr-x 7 root 4096 2007-09-20 18:23 ..
-rw-r--r-- 1 test test 33 2007-09-20 18:23 .bash_logout
-rw-r--r-- 1 test test 176 2007-09-20 18:23 .bash_profile
-rw-r--r-- 1 test test 124 2007-09-20 18:23 .bashrc
```

# The Linux Command Line

As expected, the useradd command created the new HOME directory, using the files in the /etc/skel directory to override.

If you want to override a default value when creating a new user, you can do that with command line parameters. These are shown in Table 6-1.

As you can see, you can override all of the system default values when creating a new user account just by using line parameters. However, if you find yourself having to override a value all the time, it's easier to change the system default value.

You can change the system default user values by using the -d parameter, along with a parameter representing the value you need to change. These parameters are shown in Table 6-2.

## TABLE 6-1
### The useradd Command Line Parameters

| Parameter | Description |
| :--- | :--- |
| -c comment | Add text to the new user's comment field. |
| -d home_dir | Specify a different name for the home directory other than the login name. |
| -e expire_date | Specify a date, in YYYY-MM-DD format, when the account will expire. |
| -f inactive_days | Specify the number of days after a password expires when the account will be disabled. A value of 0 disables the account as soon as the password expires; a value of -1 disables this feature. |
| -g initial_group | Specify the group name or ID of the user's login group. |
| -G group... | Specify one or more supplementary groups the user belongs to. |
| -k | Copy the /etc/skel directory contents into the user's HOME directory (use -m as well). | |
| -m | Create the user's HOME directory. |
| -M | Don't create a user's HOME directory (used if the default setting is to create one). |
| -n | Create a new group using the same name as the user's login name. |
| -r | Create a system account |
| -p passwd | Specify a default password for the user account. |
| -s shell | Specify the default login shell. |
| -u uid | Specify a unique UID for the account. |

## TABLE 6-2
### The useradd Change Default Values Parameters

| Parameter | Description |
| :--- | :--- |
| -b default_home | Change the location of users' HOME directories created. |
| -e expiration_date | Change the expiration date on new accounts. |
| -f inactive | Change the number of days after a password has expired before the account is disabled. |
| -g group | Change the default group name or GID used. |
| -s shell | Change the default login shell. |

Changing the default values is a snap:

```bash
# useradd -D -s /bin/tsch
# useradd -D
GROUP=100
HOME=/home
INACTIVE=-1
EXPIRE=
SHELL=/bin/tsch
SKEL=/etc/skel
CREATE_MAIL_SPOOL=yes
#
```

Now, the useradd command will use the tsch shell as the default login shell for all new accounts you create.

# Removing a user

If you want to remove a user from the system, the userdel command is what you need. By default, the userdel command only removes the user information from the /etc/passwd file. It does not remove any files the account owns on the system.

If you use the -r parameter, userdel will remove the user's HOME directory, along with the user mail directory. However, there may still be other files owned by the deleted user account on the system. There could be a problem in some environments.

Here's an example of using the userdel command to remove an existing user account:

```bash
# /usr/sbin/userdel -r test
# ls -al /home/test
ls: cannot access /home/test: No such file or directory
#
```

# The Linux Command Line

After using the -r parameter, the user's /home/test directory no longer exists.

> **CAUTION** Be careful when using the -r parameter in an environment with lots of users. Never know if a user had important files stored in his or HER HOME directory that are used by someone else or another program. Always check before removing a user's HOME directory!

# Modifying a user

Linux provides a few different utilities for modifying user accounts. Table 6-3 shows these utilities.

## TABLE 6-3
### User Modification Utilities

| Command | Description |
| :--- | :--- |
| usermod | Edits user account fields as well as primary and secondary group membership |
| passwd | Changes the password for existing user |
| chpasswd | Reads a list of login name and password pairs and sets them |
| chage | Changes the password expiration date |
| chfn | Changes the user's comment |
| chsh | Changes the default shell |

Each of these utilities provides a specific function for changing user accounts.

# usermod

The usermod command is the most robust of the utilities. It provides options for changing most of the fields in the /etc/passwd file. To do that you just need to use the line parameter that corresponds to the value you want to change. The parameters are mostly the same as the useradd parameters (such as -c to change the comment, -e to change the expiration date, and -g to change the default group). However, there are couple of additional parameters that might come in handy:

- -1 to change the login name of the user
- -L to lock the account so the user can't log in
- -p to change the password
- -U to unlock the account so the user can log in

# Understanding Linux File Permissions

The -L parameter is es handy. Use this to lock an account so a user can't log in. To return the account to normal, use the -U parameter.

# passwd and chpasswd

A quick way to change the password for a user is the passwd command:

```bash
# passwd test
Changing password for user test.
New UNIX password:
Retype new UNIX password:
passwd: all authentication tokens updated successfully.
#
```

If you use the passwd command by itself, it will change your own password. Any user in the system can change their own password, but only the root user can change someone else's.

The -e option is a handy way to force a user to change the password on the next log in. This allows you to set the user's password to a simple value, then force them to change it to something harder they can remember.

If you ever need to do a mass password change for lots of users on the system, the chpasswd command can be a lifesaver. The chpasswd command reads a list of login name and password pairs (separated by a colon) from the standard input, and automatically encrypts the password and sets it for the user.

# chsh, chfn, and change

The chsh, chfn, and change utilities are specialized for specific functions. The chsh command allows you to quickly change the default login shell for a user. You must use the full pathname for the shell, and not just the shell name:

```bash
# chsh -s /bin/csh test
Changing shell for test.
Shell changed.
#
```

The chfn command provides a standard method for storing information in the comments field of the /etc/passwd file. Instead of inserting random text, such as names, nicknames, or even leaving the comment field blank, the chfn command uses specific information used in the Unix finger command to store information in the comment field. The finger command allows you to easily find information about people on your Linux system:

```bash
# finger rich
Login: rich
Name: Rich Blum
Directory: /home/rich
Shell: /bin/bash
```
