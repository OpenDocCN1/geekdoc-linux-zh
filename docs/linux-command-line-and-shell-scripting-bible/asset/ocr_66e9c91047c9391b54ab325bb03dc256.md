# Presenting Data

```
$ ls -al test badest test2 2> test5
-rw-r-- 1 rich 158 2007-10-26 11:32 test2
$ cat test5
ls: cannot access test: No such file or directory
ls: cannot access badest: No such file or directory
$
```

The normal STDOUT output from the ls command still goes to the default STDOUT descriptor, which is the monitor. Since the command redirects file descriptor 2 (STDERR) to an output file, the shell sends any error messages generated directly to the specified redirection file.

# Redirecting errors and data

If you want to redirect both errors and the normal output, you'll need to use two redirection symbols. You will need to precede each with the appropriate file descriptor for the data you want to redirect, then have them to the appropriate output file for holding the data:

```
$ ls -al test test3 badest test2 1> test6
$ cat test6
ls: cannot access test: No such file or directory
ls: cannot access badest: No such file or directory
$ cat test7
-rw-r--r-- 1 rich 158 2007-10-26 11:32 test6
-rw-r--r-- 1 rich rich 0 2007-10-26 11:33 test7
```

The shell redirects the normal output of the  ls command that would have gone to STDOUT to the test7 file using the 1> symbol. Any error messages that would have gone to STDERR were now redirected to the test6 file using the 2> symbol.

You can use this technique to separate normal script output from any error messages that occur in the script. This allows you to easily identify errors without having to wade through thousands of lines of normal output data.

Alternatively, if you want, you can redirect both STDERR and STDOUT output to the same output file. The bash provides a special redirection symbol just for this purpose, the &> symbol:

```
$ ls -al test test3 badest &> test7
$ cat test7
ls: cannot access test: No such file or directory
ls: cannot access badest: No such file or directory
-rw-r--r-- 1 rich 158 2007-10-26 11:32 test6
-rw-r--r-- 1 rich rich 0 2007-10-26 11:33 test7
```

Using the &> symbol, all of the output generated by the command is sent to the same location, both data and errors. You'll notice that one of the error messages is out of order from what you'd expect. The error message for the badest file (the last file to be listed) appears second
