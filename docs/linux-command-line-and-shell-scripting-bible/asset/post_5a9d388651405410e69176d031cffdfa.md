There are a couple of things to notice in the file listing. First, you'll notice that the test5 file has a different inode number than the test1 file, indicating that the Linux system treats it as a separate file. Second, the file size is different. A linked file is to store only information about the source file, not the actual data in it. The filename area of the listing shows the relationship between the two files.

Instead of using the cp command, if you want to link files you can also use the ln command. By default the ln command creates hard links. If you want to create a soft link, you'll still need to use the s parameter.

Be careful when copying linked files. If you are linked to another source file, you're all making another copy of the source file. This can quickly get confusing. Instead of copying the linked file, you can create another link to the original file. You can have many links to the same file with no problems. However, you also don't want to create soft links to other soft-linked files. This creates a chain of links that can not be confusing but also easily broken, causing all of problems.

## Renaming files

In the Linux world, renaming files is moving. The mv command is available to move both files and directories to another location:

```bash
$ mv test2 test6
$ ls -il *
1954793 -rw-r--r-- 2 rich rich 6 Sep 09:51 test1
1954888 -rw-r--r-- 1 rich rich 0 Dec 25 2008 test3
1954793 -rw-r--r-- 2 rich rich 6 Sep 09:51 test4
1954891 lrwxr-xr-x 1 rich rich 5 Sep 09:56 test5 -> test1
1954794 -rw-r--r-- 1 rich rich 0 Sep 09:39 test6
```

Notice that the moving changed the filename but kept the same number and the time-value. Moving a file with soft links is a:

```bash
$ mv test1 test8
$ ls -il *
total 16
1954888 -rw-r--r-- 1 rich rich 0 Dec 25 2008 test3
1954793 -rw-r--r-- 2 rich rich 6 Sep 09:51 test4
1954891 lrwxr-xr-x 1 rich rich 5 Sep 09:56 test5 -> test1
1954794 -rw-r--r-- 1 rich rich 0 Sep 09:39 test6
1954793 -rw-r--r-- 2 rich rich 6 Sep 09:51 test8
[rich@test2 clsc]$$ mv test8 test1
```

The test4 file that uses a hard link uses the same inode number, which is perfectly fine. However, the test5 file now points to an invalid file, and it is no longer a valid link.

You can also use the mv command to move directories:

```bash
$ mv dir2 dir4
```

## Deleting files

Most like some point in your Linux career you'll want to be able to delete existing files. Whether it's to clean up a filesystem or to remove a software package, there's always opportunities to delete files.

In the Linux world, deleting is called removing. The command to remove files in the bash shell is rm. The basic form of rm command is quite simply:

```bash
$ rm -i test2
rm: remove 'test2?' y
$ ls -l
total 16
drwxr-xr-x 2 rich rich 4096 Sep 1 09:42 dir1/
drwxr-xr-x 2 rich rich 4096 Sep 1 09:45 dir2/
-rw-r---- 2 rich rich 6 Sep 1 09:51 test1
-rw-r---- 1 rich rich 0 Dec 25 2008 test3
-rw-r---- 2 rich rich 6 Sep 1 09:51 test4
lrwxrxr-xwx 1 rich rich 5 Sep 1 09:56 test5 -> test1
$
```

Notice that the command prompts you to make sure you're serious about removing the file. There's no trashcan in the bash shell. Once you remove a file it's gone forever.

Now, here's an interesting tidbit about deleting a file that has links to it:

```bash
$ rm test1
$ ls -l
total 12
drwxr-xr-x 2 rich rich 4096 Sep 1 09:42 dir1/
drwxr-xr-x 2 rich rich 4096 Sep 1 09:45 dir2/
-rw-r---- 1 rich rich 0 Dec 25 2008 test3
-rw-r---- 1 rich rich 6 Sep 1 09:51 test4
lrwxrxr-xwx 1 rich rich 5 Sep 1 09:56 test5 -> test1
$ cat test4
hello
$ cat test5
cat: test5: No such file or directory
$
```

I removed the test1 file, which had both a hard link with test4 file and a soft link with the test5 file. Noticed what happened. Both of the linked files appear, even though the test1 is now gone (although on my color terminal the test5 filename appears now in red).

I look at the contents of the test4 file that was a hard link, it shows the contents of the file. When I look at the contents of the test5 file that was a soft link, bash indicates it doesn't exist any more.

Remember that the hard link file uses the same inode number as the original file. The hard link file maintains that inode number until you remove the linked file, preserving the data! All the soft link file knows that the underlying file is now gone, so it has nothing to point to. This is an important feature to remember when working with linked files.

One other feature of the rm command, if you're removing lots of files and don't want to be bothered with the prompt, is to use the -f parameter.

Be careful, as this can be dangerous.

## Directory Handling

In the Linux world, there are some commands that work for both files and directories, and some that only work for directories. We'll look at directories first.

## Creating directories

The system creates a new directory when you ask. To create a directory, use the mkdir command:

```bash
$ mkdir dir3
$ ls -l *
total 16
drwxr-xr-x 2 rich rich 4096 Sep 1 09:42 dir1/
drwxr-xr-x 2 rich rich 4096 Sep 1 09:45 dir2/
-rw-r---- 2 rich rich 6 Sep 1 09:51 test1
-rw-r---- 1 rich rich 0 Dec 25 2008 test3
-rw-r---- 2 rich rich 6 Sep 1 09:51 test4
lrwxrxr-xwx 1 rich rich 5 Sep 1 09:56 test5 -> test1
drwxr-xr-x 2 rich rich 4096 Sep 1 09:50 dir3
```

## Deleting directories

Most like some point in your Linux career you'll want to be able to delete existing directories. Whether it's to clean up a filesystem or to remove a software package, there's always opportunities to delete directories.

In the Linux world, deleting is called removing. The command to remove directories in the bash shell is rmdir. The basic form of rmdir command is quite simply:

```bash
$ rmdir dir3
rmdir: dir3: not empty
```

By default, the rmdir command only works for empty directories. Since there is a file in the directory, the rmdir command refuses to remove it. You can remove nonempty directories using the --ignore-fail-on-empty parameter.

Our friend rm command can also help us when handling directories.

If you try using it without parameters, you'll be somewhat disappointed:

```bash
$ rm dir1
rm: dir1: is a directory
```

However, if you really want to remove a directory, you can use the -r parameter to recursively remove the files in the directory, then the directory itself:

```bash
$ rm -r dir2
rm: descend into directory `dir2?` y
rm: remove `dir2/test1?` y
rm: remove `dir2/test3?` y
rm: remove `dir2/test4?` y
rm: remove directory `dir2?` y
$
```

While this, it's somewhat awkward. Notice that you still must verify every file that gets removed. For a directory with lots of files and subdirectories, this can become tedious.

The ultimate solution for throwing caution to the wind and removing an entire directory, all all, is the rm command with the -r and -f parameters:

```bash
$ rm -rf dir2
$
```

That's it. No warnings, no fanfare, just another shell prompt. Of course, is an extremely dangerous tool to have, especially if you're logged in as the root user account. Use it sparingly; only after triple checking to make sure you're doing exactly what you want to do.

You may have noticed in the last example that I combined two line parameters using one dash. This is a feature in the bash shell that allows us to combine command line parameters to help cut down on typing.
