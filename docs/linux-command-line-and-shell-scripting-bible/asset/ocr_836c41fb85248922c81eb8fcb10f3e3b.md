In this example, the shell is looking for a file called *.txt, instead of matching any file that ends
.txt.

The -n command line option is not used in interactive shells, but if you use it in your shell script,
the shell will scan the script, but not actually run. Here's a quick example:

```
$ cat test2
!/bin/ash -n
# test run a script
```

echo "This is a test"
echo "This is a bad line"
$ ./test2
./test2:5:Syntax error: Unterminated quoted string
$

The shell doesn't execute the good code statement, since the bad code statement contained an
error. However, the shell does indicate that there's an error in the bad code statement line, so at
least you know where to look for the problem (the error message tells you the line number).
is is a great way to quickly troubleshoot coding problems in your shell scripts without
actually running the entire script line by.

# The original ash built-in commands

Since the original shell was designed to be lightweight, it contains just a subset of the Bourne
ash built-in commands. The trick is knowing which commands you can use and which ones
you can't. Table 20-2 shows the built-in commands available in the original ash shell.

As you see from Table 20-2, the ash shell contains some of the bash commands that you're
used to, but there are quite a few things missing. The original shell doesn't provide many
bells and whistles in its command environment. It provides a bare-bones environment for
running programs. Of course, this feature is what makes it so popular in low-memory operations,
such as embedded Linux devices.

# The bltinash command

You can use the bltinash command when you want to run a built-in command in situations when
there's another command available with the same name. When you're running shell scripts, if
there's more than one script with the same name, you can just specify the full pathname to the
proper script. With a built-in command, you can't do.

To solve this problem, the ash shell provides the bltin command (its name is changed to
built in the bash shell). This forces the ash to look for a built-in command using the
specified name instead of a shell script.
