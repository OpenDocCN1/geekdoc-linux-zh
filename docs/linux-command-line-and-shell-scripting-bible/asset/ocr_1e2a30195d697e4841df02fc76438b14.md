$ sed -n './at/p' data6

This test is at line four.

You should be able to figure out why the first line failed and why the second and third lines passed. The fourth line is a little tricky. Notice that we matched the at, but there's no character in front of it that match the dot character. Ah, but there is! In regular expressions, spaces count as characters, so the space in front of the at matches the pattern. The fifth line proves this, by putting the at in the front of the line, which fails to match the pattern.

# Character classes

The dot special is great for matching character position against any character, but what if you want to limit what characters to match? This is called a character class in regular expressions.

You can define a class of characters that would match a position in a test pattern. If one of the characters from the character class is the data stream, it matches the pattern.

To define a character class, you square brackets. The brackets should contain any character you want to include in the class. You then use the entire class within a pattern just like any other wildcard. This takes a little getting used to at first, but once you catch on it can generate some pretty amazing results.

Here's an example of creating a character class:

```
$ sed -n '/[ch]at/p' data6
The cat is sleeping.
That is a very nice hat.
$
```

Using the same file as in the dot special example, we came up with a different result. This time we managed to filter out the line that contained the word at. The only words that match this pattern are cat and hat. Also notice that the line that started with didn't match as well. There must be a character in the character class that matches with the appropriate position.

Character classes come handy if you're not sure which case a character is in:

```
$ echo "Yes" | sed -n '/[[Yy]es/p'
Yes
$ echo "yes" | sed -n '/[[Yy]es/p'
y$
```
