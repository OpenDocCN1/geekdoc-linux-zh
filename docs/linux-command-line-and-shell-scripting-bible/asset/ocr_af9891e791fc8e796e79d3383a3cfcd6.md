# Part I The Linux Command Line

| Variable | Description |
| --- | --- |
| SECONDS | The number of seconds since the shell was started. Assigning a value resets the timer to the value. |
| SHELLOPTS | A colon-separated list of enabled bash options. |
| SHLVL | Indicates the shell level, incremented by one time a new bash shell is started. |
| TIMEFORMAT | A format specifying how the shell displays time values. |
| TIMOUT | The value of how long (in seconds) the select and read commands should wait for input. The default of zero indicates to wait indefinitely. |
| UID | The numeric real user id of the current user |

You may notice that not all of the default environment variables are shown when I used the set command. The reason for this is that although these are the default environment variables, not all of them are required to contain a value.

# Setting the PATH Environment Variable

The PATH environment variable seems to cause the most problem on Linux systems. It defines where the shell looks for commands you enter on the command line. If it can't find the command, it produces an error message:

```
$ myprog
-bash: myprog: command not found
```

The problem is that often applications place their executable programs in directories that aren't in the PATH variable. The trick is ensuring that your PATH environment includes all of the directories where your applications reside.

You can add new search directories to the existing PATH environment without having to rebuild it from scratch. The individual directories listed in the PATH are separated by a colon. You need to do reference the original PATH value, and add any new directories to the string. This looks like this:

```
$ echo $PATH
/usr/kerberos/bin:/usr/lib/ccache:/usr/local/bin:/usr/bin:/usr/bin:/home/rich/bin
$ PATH=$PATH:/home/rich/test
```
