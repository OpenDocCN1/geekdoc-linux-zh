
## Defining an editor in the command line

By default, the sed editor applies the specified commands to the STDIN input stream. This allows you to pipe data directly to the sed editor for processing. Here's a quick example demonstrating how to do this:

```
$ echo "This is a test" | sed 's/test/big test/'
This is a big test
$
```

This example uses the s command in the sed editor. The s command substitutes a second text for the first text string specified between the forward slashes. In this example, I substituted the words "big test" for the word test.

When you run this, it should display the results almost instantaneously. That's the power of using the sed editor; you can make multiple edits to data in the same time it takes for some of the interactive editors to start up.

Of course, this simple test just edited one line of data. You should get the same speed results when processing complete files of data:

```
$ cat datal
The quick brown fox jumps over the lazy dog.
The quick brown fox jumps over the lazy dog.
The quick brown fox jumps over the lazy dog.
The quick brown fox jumps over the lazy dog.
$ sed '/s/dog/cat/' datal
The quick brown fox jumps over the lazy cat.
The quick brown fox jumps over the lazy cat.
The quick brown fox jumps over the lazy cat.
The quick brown fox jumps over the lazy cat.
$
```

The sed command executes and returns the data almost instantaneously. As it processes every line of data, the results are displayed. You'll start seeing results before the sed editor completes processing the entire file.

It's important to note that the sed editor doesn't modify the data in the text file itself. It only sends the modified edit to STDOUT. If you look at the text file, it still contains the original data:

```
$ cat datal
The quick brown fox jumps over the lazy dog.
The quick brown fox jumps over the lazy dog.
The quick brown fox jumps over the lazy dog.
The quick brown fox jumps over the lazy dog.
$
```

## Part III Advanced Shell Scripting

## Using multiple editor commands in the command line

To execute more than one from the sed command line, just use the -e option:

```
$ sed -e 's/brown/green/; s/dog/cat/' datal
The quick green fox jumps over the lazy cat.
The quick green fox jumps over the lazy cat.
The quick green fox jumps over the lazy cat.
The quick green fox jumps over the lazy cat.
$
```

Both commands are applied to each line of data in the file. The commands must be separated with a semicolon, and there shouldn't be any spaces between the end of the command and the semicolon.

Instead of using a semicolon to separate the commands, you can use the secondary prompt in the bash shell. Just enter the first quotation mark to open the script, and bash will continue to prompt you for more commands until you enter the closing quotation mark:

```
$ sed -e '
> s/brown/green/
> s/fox/elephant/
> s/dog/cat/' datal
The quick green elephant jumps over the lazy cat.
The quick green elephant jumps over the lazy cat.
The quick green elephant jumps over the lazy cat.
The quick green elephant jumps over the lazy cat.
$
```

You must remember to finish the command on the same line that the closing single quotation mark appears; once the bash shell detects the closing quotation mark, it'll process the command. Once it starts, the sed command applies each command you specified to each line of data in the text file.

## Reading editor commands from a file

Finally, if you have a lot of sed commands you want to process, it's often easier to just store them in a separate file and use the -f option to specify the file in the sed command:

```
$ cat script1
s/brown/green/
s/fox/elephant/
s/dog/cat/
$ sed -f script1 datal
The quick green elephant jumps over the lazy cat.
The quick green elephant jumps over the lazy cat.
The quick green elephant jumps over the lazy cat.
The quick green elephant jumps over the lazy cat.
$
```

## Introducing sed and gawk

In this case, you don't put a semicolon after each command. The sed editor knows that each line contains a separate command. Just as with entering commands on the command line, the sed editor reads them from the file.

We'll be looking at some features of gawk that come in handy. The gawk program is a more powerful version of sed, allowing for more complex processing.

### The gawk program

While sed editor is a handy tool for manipulating text, gawk provides a more robust environment for data processing. Using gawk allows you to:

- Define variables to store data
- Use arithmetic and string operators
- Use structured programming, such as if-then statements and loops
- Generate formatted reports

The gawk program is often used to filter and reorganize data within files. The power of gawk is in its ability to handle complex data processing tasks.

### The gawk command

Table 16-2 shows the options available with gawk. We'll be looking more closely at these as we explore.

### Reading the program script from the command line

An awk program script is defined by opening and closing braces. You must place script commands between the two braces. Since the gawk command line assumes that the script is a single text string, you must also include your script in single quotation marks. Here's an example of a simple awk program script specified on the command line:

```
$ gawk '[print "Hello John!']
```

The program script defines a single command, the print command. The print command does what it says, it prints text to STDOUT. If you try running this command, you will be disappointed, and nothing will happen right away. Since no filename was defined in the command line, the gawk retrieves data from STDIN. When you run the program, it waits for text to come in via STDIN.

If you type a line of text and press the Enter key, gawk will run the text through the program script:

```
$ gawk '[print "Hello World!']
This is a test
Hello John!
hello
Hello John!
This is another test
Hello John!
$
```
