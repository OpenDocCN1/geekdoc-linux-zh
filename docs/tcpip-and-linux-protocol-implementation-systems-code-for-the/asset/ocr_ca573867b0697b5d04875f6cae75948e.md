To summarize the above, on startup the protocol family (PF_INET) is registered. Each socket created has a set of socket operations (inet_stream_ops or inet_dgram_ops). Each protocol, TCP or UDP, has a set of protocol functions (tcp_prot or udp_prot). Throughout the code, calls are made to these functions.

The first operation on most sockets after creation is a connect call. This appears in the kernel as sys_connect in net/ipv4/socket.c. Here the socket is found (by looking up its file descriptor) and the memory block containing this socket is to be connected to is moved to the kernel. Then the connect function out of sock->ops is called. For UDP this will be inet_dgram_connect (if in_inet.c), which itself calls in the sk->prot structure, for UDP will be udp_connect. Other operations are passed to the relevant function in this way.
