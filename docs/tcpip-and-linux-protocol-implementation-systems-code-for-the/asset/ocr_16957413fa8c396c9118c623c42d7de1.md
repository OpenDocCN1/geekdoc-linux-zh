# 7.4.8 TCP Behavior

Looking in some detail at TCP, latest theory and measurement by Padhye et al. (1998), shows how it really behaves:

```
$B = \min \left( \frac{W_m}{RTT}, RTT^{\frac{2bp}{3}} + T_0 \min(1, 3\sqrt[8]{p})p(1+32p^2)\right) \quad (7.1)$
```

This equation is for long-lived transfers. There is more work by Cardwell and others on short-lived transfers (the majority of Web usage consists of today). However, just looking at this equation, we can see a lot of single-instance specific parameters that affect the performance radically. For example, $W_m$ and the range of $T_0$ and $b$ in implementations, could be quite large. Another problem here that we should consider when thinking about the range of values for $RTT$—in some theoretical work, $RTT$ is used as a measure of resource usage. However, it is actually a real value measured from the path path... Another problem with such proposals is that the loss rate $p$ is considered as congestion feedback, and therefore as a proportional resource utilization indication, it depends on the instantaneous load in the queue seen by a single packet, not the average over some period. Loss is also due to interference on wireless networks, and so is it a very noisy signal. Proposed Internet replacements for loss such as Explicit Congestion Notification also need specifying with regard to the sampling interval; if a switch switches congestion over some interval, this must be known to the sources that receive congestion feedback, out of band, so that they can estimate the significance of some number of packets arriving with the ECN bit set.
