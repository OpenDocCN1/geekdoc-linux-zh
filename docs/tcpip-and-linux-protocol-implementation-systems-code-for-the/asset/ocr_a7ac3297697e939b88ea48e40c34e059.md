# 5.3 Bottom Up: Interrupts, DMA, and So On

Now network interrupts are dealt with under software interrupts

Instead, Linux now has a structure for tasks that happen in an interrupt context, and thus can be per processor in an SMP machine.

Figure 5 Task queue structure—copyright statement: linux/include/linux/tqueue.h.

```
/*
* tqueue.h --- task queue handling for Linux.
* 
* Mostly based on a proposed bottom-half replacement code written by
* Kai Petzke, wpp@marie.physik.tu-berlin.de.
* 
* Modified for use in the Linux kernel by Theodore Ts'o,
* tsmito@mit.edu. Any bugs are faulty, not Kai's.
* 
* The original comment follows below.
 */

#ifndef _LINUX_TQUEUE_H
#define LINUX_TQUEUE_H

#include <linux/spinlock.h>
#include <linux/list.h>
#include <asm/bitops.h>
#include <asm/system.h>

/*
* New proposed "bottom half" handlers
* (C) 1994 Kai Petzke, wpp@marie.physik.tu-berlin.de
*
* Advantages:
* Bottom halves are implemented as a linked list. You can have as many
* of them, as you want.
* No more scanning of a bit field is required upon call of a bottom half.
* Support for chained bottom half lists. The run_task_queue() function can be
* used as a bottom half handler. This is for example useful for bottom
* halves, which want to be delayed until the next clock tick.

* Notes:
* Bottom halves are called in the reverse order that they were linked into
* the list.
 */
```
