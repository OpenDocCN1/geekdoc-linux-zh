## 7.4 Transmission Control Protocol

In multiplexing, TCP provides other transport layer services such as reliability, flow control, and congestion control. These are described here followed by a description of the TCP header and the implementation in Linux.

### 7.4.1 Functionality

The data sent by the application arrive exactly in the same order, are none lost, and are subject to errors. These aims are achieved in a number of ways:

- Firstly, each segment is checksummed in the same way as UDP. If a packet fails, it is dropped by the receiving stack.
- Secondly, each segment transmitted is subject to acknowledgment. If the acknowledgment does not arrive after a predetermined interval then the segment is retransmitted.
- Thirdly, each packet is given a sequence number. If two packets arrive with the same value, then a duplicate has been detected. Sequence numbering also provides detection of out-of-order arrivals and allows the receiving stack to reorder these, saving on retransmissions.

### Reliability

The sliding window ensures that data falls into one of the following categories:

- Data that have been sent and acknowledged.
- Data that have been sent but not acknowledged.
- Data that can be sent but haven't been yet.
- Data that can't yet be sent.

The data in the center represent those data that the receiver is willing to receive. These data are encompassed by a window—the sliding window. As acknowledgments are received for data at the left-hand edge of the window, the whole window can slide to the right bringing further data into the category of data that can be sent.

### Flow Control

Flow control employs a mechanism called a sliding window (see Figure 7.11). In the simple case, the sender could wait for every packet to be acknowledged before sending the next packet. This, while being inefficient in bandwidth use, is relatively easy to implement. For example, two geographically separate points with a round trip time of 5 ms will only allow one new packet every 5 ms, which will be an effective bandwidth use of only (1000 × 8)/.005 = 1.6 Mbps, that is, 1.6 percent of the available bandwidth.
