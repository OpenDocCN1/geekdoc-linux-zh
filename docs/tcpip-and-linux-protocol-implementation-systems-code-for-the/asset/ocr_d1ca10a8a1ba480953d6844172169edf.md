+   * receiver must not, for example, scan through a packet looking for a

+   * We do exactly this. This is a protocol bug. We can't decide after
* seeing an unknown discard-with-error TLV option if it's a
* ICMP error message or not (errors should never be sent in reply to
* ICMP error messages).

+   * But I see no other way to do this. This might need to be reexamined
* when Linux implements ESP (and maybe AUTH) headers.

+   * --AK
* This function parses (probably truncated) exthdr "hdr"
* of length "len", "nexthdr" initially points to some place,
* where type of the first header can be found.

+   * It skips all well-known extrheaders, and returns pointer to the start
* of unparsable area i.e. the first header with unknown type.
* If it is not null nexthdr is updated by type/protocol of this header.

+   * NOTES: if packet terminated with NEXTHDR_NONE returns NULL
* it may return pointer pointing beyond end of packet,
* if the last recognized header is truncated, then all parsed headers are skipped,
* it returns NULL.
* First header is skipped, not-first ones
* are considered unparsable
* ESP is unparsable for now and considered like
* normal payload protocol.
* Note also special handling of AUTH header. Thanks to Ipsec guards.
* --ANK (980726)
