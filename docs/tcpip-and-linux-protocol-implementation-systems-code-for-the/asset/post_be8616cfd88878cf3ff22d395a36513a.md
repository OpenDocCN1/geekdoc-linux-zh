static int
red_drop(struct qdisc *skb)
{
    struct sk_buff *skb;
    struct red_sched_data *q = (struct red_sched_data *)skb->data;
    skb = NULL; __skb_dequeue_tail(skb->q);
    if (skb) {
        skb->stats.backlog -= skb->len;
        skb->stats.drops++;
        q->stat.other++;
        kfree(skb);
        return 1;
    }
    PSCHED_GET_TIME(q->qidlestart);
    return 0;
}

static void red_reset(struct qdisc *sch)
{
    struct red_sched_data *q = (struct red_sched_data *)skb;
    struct sk_buff *skb;

    while ((skb = skb_dequeue(sch->q)) != NULL) {
        kfree(skb);
        sch->stats.backlog = 0;
        PSCHED_GET_PASTERFECT(q->qidlestart);
        q->qave = 0;
        q->count = -1;
    }
}

A data flow obeys TBF with rate R and depth B, if for any time interval t...f the number of transmitted bits does not exceed B + R*(t-t_i).

Packetized version of this definition: The sequence of packets of sizes s_i served at t_i obeys TBF, if for i<k:
s_i+...+t_k <= B + R*(k-t_i)

Algorithm.

Let N(t_i) be B/R initially and N(t) grow continuously with time as:
N(t+delta) = min(B/R, N(t) + delta)

If the first packet in queue has length S, it may be transmitted only at the time t*: when S/R <= N(t_*), and in this case N(t_*) jumps
N(t_* + 0) = N(t_* - 0) - S/R.

Actually, QoS requires two TBF to be applied to a data stream. One of them controls steady burst rate size, another one with rate P (peak rate) and depth M (equal to link MTU) limits bursts at a smaller time scale.

It is easy to see that P=R, B=M. If P is infinite, then TBF is equivalent to a single one.

When TBF works in reshaping mode, latency is estimated as:
lat = max ((L-B)/R, (L-M)/P)

This means, that with depth B, the maximal rate is
R_crit = B*HZ
F.e. for 10Mbit ethernet and HZ=100 the minimal allowed B is 10Kbytes.
Note that the peak rate TBF is much more tough; with MTU 1500
P_crit = 150Kbytes/sec. So, if you need greater peak rates, use alpha with HZ=1000 :-)
