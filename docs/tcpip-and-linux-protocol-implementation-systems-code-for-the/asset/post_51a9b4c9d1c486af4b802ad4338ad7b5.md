# 8.8 Managing IP-Level State

From user space, the ip command acts to glue all the rtlink API calls into a single application for manual configuration or access. For those familiar with BSD-like, this command incorporates the combined functionality of ifconfig, route, netstat, arp and other. Many of the things managed by this command have been covered in Chapter 6, so we just summarize its capabilities here.

ip [ Options ] Command [ Arguments ]

- **Options.** -V, -s, -f, for version, family (inet, inet6), or use DNS instead of addresses.
- **Object.** This is what we are trying to manage—each corresponds roughly to a separate command on systems, with the exception of firewalls and traffic control, which are managed through separate commands that we discuss in Chapter 9 and 10 respectively.
- **Command.** Takes some action on the object named, typically, add, delete, set, show, or some other command.
- **link.** Basically manage device level information. For example, ip link set <name> | [up|down] | arp [on|off] | multicast [on|off] | txqlen <n> | mtu <n> | address <link> | broadcast link address or ip show.
