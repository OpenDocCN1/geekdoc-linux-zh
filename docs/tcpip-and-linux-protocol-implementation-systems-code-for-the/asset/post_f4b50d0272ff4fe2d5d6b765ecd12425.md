# Figure 7.46 TCP sequence check.

```c
/* Check sequence number for validity.
 * Segment controls are considered valid, if the segment
* fits the window after truncation to the window. Acceptability
* of data (and SYN, FIN) is checked separately.
 * See tcp_dequeue(), for example.
 * Also, controls (RST is not main) are accepted using RCV.WUP instead
* of RCV.NEXT. Peer did not have advance SND.UNA when
* delayed ACK, so his RCV.WUP.
* (borrowed from skb)
 */
static inline int tcp_sequence(struct tcp_opt *tp, u32 seq, u32 end_seq) {
    return !before(end_seq, tp->rcv_wup) &&
           !after(seq, tp->rcv_nxt + tcp_receive_window(tp));
}
```

# Figure 7.47 TCP receive window.

```c
/* Compute the actual receive window we are currently advertising.
 * RCV_NEXT can be after the window if our peer push data
* than the offered window. */
static inline u32 tcp_receive_window(struct tcp_opt *tp) {
    s32 win = tp->rcv_wup + tp->rcv_snd - tp->rcv_nxt;

    if (win < 0)
        win = 0;
    return (u32)win;
}
```

# Figure 7.48 ACK sending code.

```c
/*
* Check if sending an ack is needed.
 */
static inline void _tcp_ack_snd_check(struct sock *sk, int ofo_possible) {
    struct tcp_opt *tp = &(sk->tpinfo.tcp);
    /* More than one frame received... */
    if ((tp->rcv_nxt - tp->rcv_wup) > tp->ack_mss)
        /* ... and right edge of window are far enough.
         * (tcp_rcvmsg()) will send acknowledgment. Or...
         */
    if (tcp_select_window(sk) >= tp->rcv_wnd ||
        /* We ACK each frame or... */
        tcp_in_quickack_mode(tp) ||
        /* We have out of order data. */
        (ofo_possible && skb_peek(tp)->out_of_order_queue) != NULL) {
        /* Then ack it now */
        tcp_send_ack(sk);
    } else {
        /* Else, send delayed ack. */
        tcp_send_delayed_ack(sk);
    }
}

static __inline__ void tcp_ack_snd_check(struct sock *sk) {
    struct tcp_opt *tp = &(sk->tpinfo.ack);
    if (tcp_ack_scheduled(tp)) {
        /* We sent a data segment already. */
        return;
    }
    _tcp_ack_snd_check(sk, 1);
}
```

The fast path in this function uses the header prefix of RFC 1223, that is, the expected sequence number is the same as that of the incoming packet. Here the timestamp option, if present, is decoded, and PAWS (see later) is checked. If the packet is ignored, we call tcp_ack if it is too small then it is discarded, and if it contains data then it is queued for the owning socket. Another optimization is here if the current process is the task that owns the socket, as the data can be copied directly to the iovec. The checksum is checked in this function, and the tcp->rcv_nxt value is updated.

In the slow path, first PAWS is checked (see later). Whether the packet is in sequence is checked with the tcp_sequence function (see Figures 7.46–7.47).
