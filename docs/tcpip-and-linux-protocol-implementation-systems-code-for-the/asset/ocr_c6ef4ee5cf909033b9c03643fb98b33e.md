# 6.63 Fragmentation–deal with arrival of a fragment: linux/net/ipv4/ip_fragment.c

```
/* Process an incoming IP datagram fragment. */
struct sk_buff *skb = deffrag(struct sk_buff *skb)
{
    struct iphdr *iph = skb->nh.ip;
    struct ipq *qp;
    struct net_device *dev;

    IP_INC_STATS_BH(IpReasmReq);

    /* Start by cleaning the memory. */
    if (atomic_read(&ip_frag_mem) > sysctl_ipfrag_high_thresh) {
        ip_evictor();
    }
    dev = skb->dev;

    /* Lookup (or create) queue header */
    if ((qp = ip_find(skb->buff)) != NULL) {
        spin_lock(&qp->lock);
        ip_frag_queue(qp, skb);
        if (qp->last_in == (FIRST_IN|LAST_IN) && qp->meet == qp->len) {
            int ret = ip_frag_reasm(qp, dev);
            spin_unlock(&qp->lock);
            ip_put(qp);
            return ret;
        }
    }

    IP_INC_STATS_BH(IpReasmFails);
    kfree(skb);
    return NULL;
}
```

# 6.2.6 Internet Protocol Options

IP options in IPv4 are curious things. They have a high potential value, but since (for over two decades) they have remained relatively unused, most routers process them in the slow path. The slow path is the uncommon case code, and contains many more checks than so-called fast-path processing. In fact, when router throw hardware solutions at a problem, they are committing designs to silicon that are costly, so they reduce the number of options to zero.
