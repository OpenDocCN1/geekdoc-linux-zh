# 2.5 A Day in the Life of a Process

A process starts life as a compiled program sitting on a disk, and a user with a desire to run the program. By interacting with the system (via some program, e.g., a shell, or perhaps via cron), the user informs the system that they want this program to run.

A process lives in a memory address space of its own, made out of set of pages, and runs with the CPU in user mode. A process can extend its memory (using the sbrk call via malloc()) and share memory (see Chapter 4 on IPC). It can also memory map files.

Processes live in a family tree, and new processes are spawned through fork() and various forms of the exec() system calls copying the process table entry, creating a new process ID, and then overlaying or allocating new memory for a new executable, and loading it from disk. In some cases, we clone many copies of a process (e.g., for Web serving in very old CERN HTTP daemons). Nowadays, this is more commonly done through a threads system.
