# 10 Queuing Discipline

Linux 2.4 supports a wide variety of queuing disciplines, ranging from simple schedulers to complex, multi-tiered systems. The current list is:

- **FIFO**: Represents the default, best-effort service.
- **Priority**: A well-known queue management technique for distributing fairness amongst rate-adaptive (TCP-friendly) flows.
- **Generalized RED**: A special version of RED.
- **Differentiated service marker**: The queuing discipline needs to do marking rather than dropping.
- **Stochastic fairness queue (SFQ)**: An approximate technique for fairness.
- **Token bucket**: Token policing queue.
- **Traffic equalizer (FQ)**: Traffic equalization is special.
- **CBQ**: Techniques for combining other queuing disciplines into a structure. This is necessarily hierarchical.
- **CSZ**: David Clark, Scott Shenker, and Linia Zhang carried out some of the earliest integrated services research.

```c
/*
Short review.

This file consists of two unrelated parts:
1. Queuing discipline manager frontend.
2. Traffic classes manager frontend.

Generally, queuing discipline (qdisc) is a black box, which is able to enqueue packets and dequeue them (when device is ready to send something) in order and at times determined by algorithm hidden in it. qdiscs are divided into two categories:
- "qdiscs", which have no internal structure visible from outside.
- "schedulers", which split all the packets to "traffic classes", using "packet classifiers" (look at cls_api.c).

In turn, classes may have child qdiscs (as rule, queues) attached to them etc. etc. etc.
The goal of the routines in this file is to translate information supplied by user in the form of handles to more intelligible kernel form, to make some sanity checks and part of work, which is common to all qdiscs and to provide rtnlink notifications.

All real intelligent work is done inside qdisc modules.

Every discipline has two major routines: enqueue and dequeue.
```

### dequeue TCP/IP and Linux Protocol Implementation

```c
dequeue returns an skb to send. It is allowed to return NULL, but does not mean that queue is empty, it just means that discipline does not want to send anything this time. Queue is really empty if q->q.len == 0. For complicated disciplines with multiple queues q->q is not real packet queue, but however q->q.len must be valid.
```

### enqueue

enqueue returns 0 if packet was enqueued successfully. If packet (this one or another one) was dropped, it returns a non-zero error code.
- **NET_MIT_DROP**: This packet dropped. Expected action: do not backoff, but wait until queue will clear.
- **NET_MIT_CN**: Probably this packet enqueued, but another one dropped. Expected action: backoff or ignore.
- **NET_MIT_POLICED**: Dropped by police. Expected action: backoff or error to real-time apps.
```
