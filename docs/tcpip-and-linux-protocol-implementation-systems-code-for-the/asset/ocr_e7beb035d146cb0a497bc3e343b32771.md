The idea was that there were typically three different-size networks: the core networks such as ARPANET and SATNET—would be given 8-bit network addresses (class A), and there could be only up to 256 of them; the site networks such as Berkeley, MIT, UCLA, and UCL—were given 16-bit network addresses (class B) and there could be 65,536 of them, each with 65,536 hosts on; finally, there would be local networks, with only 256 hosts on—but there could be up to $2^{24}$ of them, which is 16,777,216 class C networks.

There are two big problems with this approach. Firstly, not one size fits "all", but in fact three sizes didn't fit all either; many networks have a topology that allows more than 256 hosts to be attached locally, but if given class C network, not all these hosts would be reachable; conversely, many networks only attached 100 hosts to a class B network. More critically, the routing system had to know all the addresses, in practice (and this is unrelated to the first point), many sites had a single way to reach the whole world, even when they had several networks internally.

The first step away from a globally visible network numbering system was the introduction of *subnet addressing*. The second step away from a globally visible topology was the hierarchical allocation of addresses to organizations. Consideration of the size and topological location of an organization would lead to the assignment of a network number, together with a mask, which indicates how many bits of the address are free to be used for allocation to hosts, and how many are for advertising the network as reachable to the next level of topology (see Figure 8.2).

The downside of this is that it leads to the requirement for hosts, routers, and routing protocols to know or discover the mask associated with their region of the network. The upside is that it leads to the possibility that address fixes may be hierarchically aggregated. In other words, on the edge of the network, we only care about towards the core, while in the core of the network, we only need now about the highest levels of aggregation. Hopefully, these would usually be long masks, or shorter network prefixes, leading to a reduction in routing table requirements.

The scheme has worked well for local and global routing table management for several years. Recent trends in multihoming have emerged from the requirement for sites to have high availability. Multihoming for a site is done transparently, this requires network to advertise the site prefix through at least one path along which the address is not aggregatable.

An important consideration for implementors of classless interdomain routing is that a router must now compare destination addresses in packets with multiple possible routing entries. Which entry to pick? Clearly, the *most specific entry is the one nearest to the destination*.
