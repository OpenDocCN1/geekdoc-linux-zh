## 9.197 CSZ departure times: linux/net/sched/sch_csz.c.

We calculate the time until the last bit of packet is sent:

```
E_a^i(t) = \{ m_a(t) - \delta_a(t) / r_a \},
```

where $\delta_a(t)$ is number of bit drained since $t_i$.
We evaluate $E_a^i$ for all queued packets, then find the packet with minimal $E_a^i$ and send it.

This sounds good, but direct implementation of the algorithm is absolutely infeasible. Frankly, if flow rates are scaled proportionally, the equations have a simple solution.

The differential equation for $E_a^i$ is:

```
d E_a(t) / dt = \{ d \delta_a(t) / dt \} \{ i / r_a \} =
B / \sum(in \in A) r_a
```
with initial condition
```
E_a^i(t_i) = \{ m_a(t_i) / r_a \}.
```

Let's introduce an auxiliary function $R(t)$:

## 9.198 CSZ--the round: linux/net/sched/sch_csz.c.

```
--- Round number.
Consider the following model: we rotate over active flows, sending $R_a$ bits from every flow, so that we send $\sum(in \in A) r_a$ bits per round, that takes $\sum(in \in A) r_a$ seconds.

Hence, $R(t)$ (round number) is a monotonically increasing linear function of time when $S_a$ is not changed
```
d R(t) / dt = \{ i / \sum(in \in A) r_a \}
```
it and is continuous when $S_a$ changes.

The central rotation is that the quantity $F_a^i R(t) = F_a(t)/R(t)$ does not depend on time at all! $R(t)$ does not depend on flow, so $F_a$ can be calculated only once on packet arrival, and we need not recalculate $S_a$ numbers and resorting queues.
the number $F_a^i$ is called finish number of the packet. it is just the value of $R(t)$ when the last bit of packet is sent out.

# Forwarding 791

Maximal finish number on flow is called finish number of flow minimal one is "start number of flow". Appropriately, flow is active if and only if $F_a \leq R$.

## 9.199 CSZ-the round: linux/net/sched/sch_csz.c.

When a packet of length $L_i$ bit arrives at $s$ at time $t_i$, we calculate $F_a^i$ as:

If flow was inactive ($F_a < R$):
$F_a^i = R(t) + (L_i / B \cdot r_a)$
otherwise
$F_a^i = F_a + \{L_i / B \cdot r_a\}$

These equations complete the algorithm specification.

static int
fifo_drop(struct Qdisc* sch)
{
    struct sk_buff *skb;
    skb = __skb_dequeue_tail(&sch->q);
    if (skb) {
        sch->stats.backlog -= skb->len;
        kfree(skb);
        return 1;
    }
    return 0;
}
```

Unfortunately, rate estimation is not very easy task. I did not find a simple way to estimate the current peak rate and even failed to formulate the problem. I preferred not to build an estimator into the scheduler, but run this task separately. Ideally, it should be kernel thread(s), but for now it runs from timers, which puts apparent top bounds on the number of flows has minimal overhead on small, and is enough to handle controlled load service, sets of aggregates.

We measure rate over $A=(1\ll1)$ seconds and evaluate EWMA:

```
avrate = avrate*(1-W) + rate=W
```

where $W$ is chosen as negative power of 2: $W = 2^{-ewma\_log}$

The resulting time constant is:

```
T = A/-ln(1-W)
```

NOTES.

- The stored value for avbps is scaled by $2^5$, so that maximum rate is 1Gbit, avpps is scaled by $2^{10}$.
- Minimal interval is $Hz/4=250msec (it is the greatest common divisor for $HZ=100$ and $HZ=1024 (8)$, maximal interval is $(HZ/4)+2\_EST\_MAX\_INTERVAL = 8sec$. Shorter intervals are too expensive, longer ones can be implemented at user level painfully.
