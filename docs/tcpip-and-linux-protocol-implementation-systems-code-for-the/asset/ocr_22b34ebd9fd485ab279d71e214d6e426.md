# 2.2.1 MultiUser

Since then the 1970s, there has been a saying that "Everything in UNIX is a file." What is meant by this is that the standard abstraction for any object on the system is provided by the overloading of the concept of a file.

Of course, normally, files are stored on disk. Files are organized in filesystems (and Linux supports a few different ones) consists of a way of organizing storage devices (file-stores), a way of organizing files within a naming hierarchy (directories, files within directories, and so on), and a way of formatting data files within files (UNIX has traditionally kept this as simple as can be). UNIX unifies the view of a number of objects in the system by using the filename space to name, and therefore provide access to, devices and devices (in modern UNIX systems) processes, as well as to simple stored data. This makes system programmers' tasks easier—there are fewer interfaces than in other families of operating systems. We will see throughout how the book makes access to the communications facilities straightforward. We also see that in some cases, this unification comes at cost—sometimes the analogy between a file and some other type of object stretches the use of the system call interface in some other odd ways, and this shows in the use of some of the parameters.

An important aspect of the filesystems is the identification of ownership of files. In any, whether it is a normal plain file, a directory, a handle on a device, or even a process, there are fields that show the ownership of the file and the permissions associated with different users (user, group, others). This data is stored with files on disk, and is kept in memory when a file is opened by a program—the data structure that stores all is called an inode. At the root of all things, all files have an inode number.

Traditional interaction between the user and the system was via command line interfaces (the shell). Of course, in modern systems, we expect to use a graphical user interface (GUI). The underlying system for this on UNIX is X-Windows, which for 20 years now has provided networked graphical interfaces to programs running on remote systems. GUI comes into play when multitasking systems—it is common for many classes of user to combine and overlap a number of loosely related tasks (e.g., editing and previewing a letter, or programming, debugging and viewing documentation, or browsing the net and taking notes). A windowing system combined with a tasking system is essential to the modern user. Let's look a bit further at tasks.
