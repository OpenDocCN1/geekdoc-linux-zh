```c
* allocate additional space.
* This is used when the caller wishes to modify the data and needs a
* private copy of the data to alter as well more space for new fields.
* Returns -NULL on failure or the pointer to the buffer
* on success. The returned buffer has a reference count of 1.
* You must pass GFP_ATOMIC as the allocation priority if this function
* is called from an interrupt.
*/
struct sk_buff *skb_copy_expand(const struct sk_buff *skb,
    int headroom,
    int tailroom,
    int gfp_mask)
{
    struct sk_buff *n;
    /* Allocate the copy buffer */
    n=alloc_skb(headroom + (skb->tail - skb->data) + tailroom,
        gfp_mask);
    if(!NULL)
        return NULL;
    skb_reserve(n, headroom);
    /* Set the tail pointer and length */
    skb_put(n, skb->len);
    /* Copy the data only. */
    memcpy(n->data, skb->data, skb->len);
    copy_header(n, skb);
    return n;
}
```

# 5.7.1 Socket and Route-Related Transport State

For historical reasons, some state associated with the transport protocol is kept in the socket structure (it is, in any case, per connection per process for connection-oriented unicast protocols, so this is not a terrible error, although in the future for reliable multicast transport protocols with multipleers and receiving processes potentially on the same machine, this could be a problem).

The route-related state is discussed in Chapter 8. In any case, one of the most formidable data structures in the Linux communications protocol stack implementation is contained in the innocently named file sock.h.
