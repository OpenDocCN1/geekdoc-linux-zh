At the end of tcp_rcv_established, tcp_data_queue is called. This is shown in Figures 7.51–7.54. Here the path is the most common packet, that is, in sequence and in the current window. Again there is an optimization for the current task that is owning the socket, otherwise memory must be reserved and the socket buffer queued. The rcv_nxt variable can be updated for the current connection, and if the socket buffer contains some data, then tcp_event_data_rcv is called to schedule an ACK. If there are packets on the out-of-order queue, then this segment may have filled a gap, in which case an immediate ACK
