A naive approach to implementation might be to carry out a linear search of the routing table. This may be all right in local routers, but in the routers core of the Internet, we find tens of thousands of route entries. If a single hash table is used, we do not know the order with which entries with different length prefixes will occur. Other solutions are required, otherwise we end up with a linear search, which results in the same order of number of lookups for every single packet to be forwarded as there are route entries, which can be very large.

**Trees and tries.** The old BSD UNIX approach to the forwarding table was to keep three levels of information: host, route, and default. The search involved hashing into the host table, and if a miss occurred, hashing into the route table, and finally, if that failed, searching the list of default gateways. In BSD UNIX 4.3 radix trees were developed. These are a form of Patricia Trie-a tree is just a name for the type of tree structure that stored information at each internal node as well as the leaves. The BSD UNIX 4.3 radix tree is a binary tree, which, starting at the root, stores the prefix address and mask so far. As you move down the tree, more bits are matched going one down the tree. If they don't match, the other branch holds the entry required.
