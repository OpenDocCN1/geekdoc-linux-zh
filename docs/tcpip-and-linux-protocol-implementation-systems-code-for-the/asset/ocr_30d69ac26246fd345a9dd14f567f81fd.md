# Locking Sockets

As discussed in Chapters 3 and 4, this is the layer in which a lot of concurrency can occur (between user processes and kernel transport protocols), thus there needs to be support for mutual exclusion and synchronization. Here is some of it.

**Figure 5.53 Socket interface code–lock code: linux/net/socket.c.**

```
/* The strategy is: modifications net_family_vector are short, do
 sleep and veesery rare, but read access should be free of any exclusive
 locks. */
static void _net_family_write_lock(void)
{
	spin_lock(&net_family_lock);
	while (atomic_read(&net_family_lockct) != 0) {
		sspin_unlock(&net_family_lock);
		current->policy |= SCHED_YIELD;
		schedule();
	}
	spin_lock(&net_family_lock);
}
nstatic __inline__ void _net_family_write_unlock(void)
{
	spin_unlock(&net_family_lock);
}
```
