# Figure 8.37 FIB semantics--the big picture: linux/net/ipv4/fib_semantics.c.

```c
/*
Picture
------
Semantics of nexthop is very messy by historical reasons.
We have to take into account, that:
a) gateway must be actually local interface,
so that gateway route is direct.
b) gateway must be on-link address, possibly
decoupled by an add, but also by a direct route.
c) if both gateway and interface are specified, they should not
contradict.
d) If we use tunnel routes, gateway could not be on-link.
*/
```

# 574 TCP/IP and Linux Protocol Implementation

Attempt to reconcile all of these (alas, self-contradictory) conditions
results in pretty ugly and hairy code with obscure logic.

I chose to generalized it instead, so that the size
code does not increase practically, but it becomes
much more general.

Every prefix is assigned a "scope value: "host" is local address,
link" is direct route,
[... "site" "interior" ...]
and "universe" is true gateway route with global meaning.

Every prefix refers to a set of "nexthop" (gw, oif),
where gw must have narrower scope. This recursion stops
when gw has LOCAL scope or if "nexthop" is declared ONLINK,
which means gw is forced to be on link.

Code is still hairy, but now it is apparently logically
consistent and very flexible. F.e. as by-product it allows
to coexist in peace independent exterior and interior
routing processes.

Normally it looks as following.

```
(universe prefix) -> (gw, oif) [scope link]
|
|-> (link prefix) -> (gw, oif) [scope local]
|
|-> [local prefix] (terminal node)
*/
```
