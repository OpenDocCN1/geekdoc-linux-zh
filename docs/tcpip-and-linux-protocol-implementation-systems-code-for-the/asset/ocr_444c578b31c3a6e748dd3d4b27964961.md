# 9.13.12 Stochastic Fairness Queuing

Figure 9.288 Stochastic fairness queuing scheduler–introductory remarks: linux/net/sched/sch_sfq.c.

```
41    /* Stochastic Fairness queuing algorithm.
42    =====================================
43
44    Source:
45    Paul. E. McKinney "Stochastic Fairness Queuing"
46        IEEE INFOCOMM/90 Proceedings, San Francisco, 1990.
47
48    Paul. E. McKinney "Stochastic Fairness Queuing"
49        "Interworking: Research and Experience", v.2, 1991, p.113-131.
50
51
52    See also:
53    M. Shreedhar and George Varghese "Efficient Fair
54    Queuing using Deficit Round Robin", Proc. SIGCOMM 95.
55
56
57    This is not the thing that is usually called (W)FQ nowadays.
58    It does not use any timestamp mechanism, but instead
59    processes queues in round-robin order.
60
61
62    ADVANTAGE:
63
64    - It is very cheap. Both CPU and memory requirements are minimal.
65
66    DRAWBACKS:
67
68    - "Stochastic" -> It is not 100% fair,
69    When hash collisions occur, several flows are considered as one.
70
71    - "Round-robin" -> It introduces larger delays than virtual clock
72    based schemes, and should not be used for isolating interactive
73    traffic from non-interactive. It means, that this scheduler
74    should be used as lease of CRQ or P3, which put interactive traffic
75    to higher priority bound.
76
77    We still need true WFQ for top level CZ, but using WFQ
78    for the best effort traffic is absolutely pointless:
79    SFQ is for this purpose.
80
81    IMPLEMENTATION:
82    This implementation limits maximal queue length to 128;
83    mtu to 2518-1; number of hash buckets to 1024.
84    The only goal of these restrictions was that all data
85    fit into one 4k page (-). Struct sfq_sched_data is
86    organized in anti-cache manner: all the data for a bucket
87    are scattered over different locations. This is not good,
88    but it allowed me to put it into 4K.
89
90    It is easy to increase these values, but not in flight. */
```
