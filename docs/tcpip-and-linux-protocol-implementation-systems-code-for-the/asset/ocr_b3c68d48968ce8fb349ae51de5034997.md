Notice that if this discipline is followed systematically, there is at most one copy (ignoring the DMA from a device into memory), and even this can be eliminated (and has been in some research Linux systems) by carrying out the kernel/user space mapping via memory management and marking the buffer as copy-on-write.

The sk_buff structure is critical to understanding the networking code. It is used to hold a plethora of different types of network data, although principally this is packet buffers (including their nested headers and so forth).

In the next two listings in Figures 5.119 and 5.120, you can see the way that these structures are part of a linked list, and in fact can be in several lists. They can be owned by a socket that is sending or receiving them (high-level interface), and have a link to a device that either arrived on or will be sent on (low-level interface. It is a timestamp associated with when they were last timestamped (it depends on the use or last protocol that touched the field and how it wishes to communicate with the network one—this can be particularly useful in scheduling packet output, as discussed in Chapter 9).

The socket buffer structure overlays a number of possible interpretations of the actual contents of the memory it points to—the headers to include transport, network, and link layer information for fast access and multiplexing/demultiplexing, but for each protocol layer, the union of all types of different packet header for the different available protocols at that layer is used for programming convenience.
