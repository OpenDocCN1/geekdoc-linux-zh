# Figure 6.145 ICMP, router requirement conformance: linux/net/ipv4/icmp.

+   * RFC 1812 (IPv4 Router Requirements) Status (even longer):
* 4.3.2.1 (Unknown Message Types)
* MUST pass messages of unknown type to ICMP user iface or silently discard
then (OK)
* 4.3.2.2 (ICMP Message TTL)
* MUST initialize TTL when originating an ICMP message (OK)
* 4.3.2.3 (Original Message Header)
* SHOULD copy any data from the offending packet as without
* the length of the ICMP datagram exceeding 576 bytes (OK)
* MUST leave original header of the offending packet, but we're not
* required to undo modifications made (OK)
* 4.3.2.4 (Original Message Source Address)
* MUST use source address for the interface of the orig, packet arrived as
* source address (OK)
* 4.3.2.5 (TOS and Precedence)
* MUST leave TOS set to the same value unless the packet would be
 discarded for reason (OK)
* MUST use TOS=0 if not possible to leave original value (OK)
* MUST leave Precedence for Source quench messages (OK -- not sent
at all)
* SHOULD use Precedence = 6 (Internet Control) or 7 (Network Control)
* for all error messages (OK, we use 6)
* MAY allow configuration of Precedence (OK -- not done)
* MUST leave Precedence and TOS for reply messages (OK)
* 4.3.2.6 (Source Route)
* SHOULD use reverse source route UNLESS sending Parameter Problem on source
* routing and the packet will be immediately discarded (NOT YET)
* 4.3.2.7 (When Not to Send ICMP Errors)
* MUST NOT send ICMP errors in reply:
* ICMP errors (OK)
* Packets failing IP header validation tests unless otherwise noted (OK)
* Broadcast-multicast datagrams (OK)
* MAC broadcasts (OK)
* Non-initial fragments (OK)
* Datagram with a source address that isn't a single host. (OK)
