# Clark/Shenker/Zhang Scheduling

Clark, Shenker, and Zhang [19] suggested a different structure for a hierarchical classification architecture.

Figure 9.195 Clark/Shenker/Zhang scheduling--initial comment: linux/net/sched/csz.sc.c

```
/*
 * Clark-Shenker-Zhang algorithm.
 * ============================
nSOURCE:
David D. Clark, Scott Shenker and Lixia Zhang
"Supporting Real-Time Applications in an Integrated Services Packet
Network: Architecture and Mechanism"

CSZ presents a flexible universal algorithm for packet scheduling,
but it has poor delay characteristics.
Round-robin scheduling and link-sharing goals
appletely contradict minimization of network delay and jitter.
Moreover, correct handling of predictive flows seems to be
imposible in CSZ.

CSZ presents a more precise but less flexible and efficient
approach. As I understand, the main idea is to create
WFQ for each guaranteed service and to allocate
the bandwidth to dummy flow-0. Flow-0 comprises
the predictive services and the best effort traffic;
it is handled by a priority scheduler with the highest
priority bound allocated for predictive services, and the rest
to the best effort packets.

Note that in CSZ flows are NOT limited to their bandwidth. It
is proposed that the flow admission control at the edge
of the QoS network and it doesn't need further shaping. Any
attempt to improve the flow or to shape it to a token bucket
at intermediate hops will introduce undesired delays and raise
jitter. *
```
