# TCP/IP and Linux Protocol Implementation

Device driver details manage specifics like:

+   - Bus interface/memory/I/O address of device registers
- DMA and timer chip use
- IRQS, and so on

Notice the asymmetry of input and output—output is requested, whereas input arrives unexpectedly (i.e., at this level we could never sensibly implement a device driver by polling Input results in packets being queued, and netif_rx() called to find out which higher-level protocol function to dispatch.

The traditional cach interface is via the ioctl() call. This allows one to set and get a number of network-specific device control parameters—for example:

+   - Link up/down
- Broadcast address
- ARP (see Chapter 6)
- MTU
- Statistics, and so on

We can see this by saying ifconfig <dev>. The command netstat -i will tell you what network devices you have. We look at this further in Chapter 6.

Address resolution is either done algorithmically, through a table, or through a helper task that runs the Address Resolution Protocol (ARP). ARP is invoked when the IP address is known but the destination layer (strictly, Media Access Control) address is unknown. ARP is demultlexed in netif_rx() for input frames with ARP type—it makes sure it enters table updates and maintains these with a lifetime so that they expire when not used in a timely fashion. It can be overridden by configuration management.

In general, output is multiplexed by frametype (IP, ARP, or other). Output demultplex, by looking at frametype, and using upcall the right higher level (from inside netif_rx()), from the input interrupt.

As discussed, buffer disciplines are asymmetric: for output, the high level allocates buffer and a stack of routines, and the lowest level frees; for input, the low level has a pool, hands up to the upper level, which, when done with a buffer, frees.

What if the packet is not for us? Basically, it will bridge, route, or discard. Bridging is intensive (it requires the Ethernet interface to be in promiscuous mode, which is expensive in packet discard). We don't discuss this further.
