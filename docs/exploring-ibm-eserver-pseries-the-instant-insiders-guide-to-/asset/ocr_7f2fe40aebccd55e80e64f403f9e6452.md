Systems that employ multiple main processors working in parallel can achieve extremely high levels of performance and are called highly parallel or massively parallel systems (depending on the number of main processors used in the system). A common industry term is Massively Parallel Processing (MPP). This may sound much like the SMP systems that we discussed earlier, but a Cluster 1600 system is quite different. Each P5series (or LPAR thereof) within the cluster is an independent SMP server in its own right, having its own operating system, disk, memory, and adapters. The Cluster 1600 allows up to 128 operating system images to be managed as a single computing resource. Each operating system image (sometimes called a logical “node”) is controlling multiple processors (depending on the size of server or LPAR), so the cluster can contain hundreds of processors.

An additional piece of hardware called the Control Workstation (CWS) is required for a Cluster 1600 configuration. The CWS can be one of several deskside or rack-mounted systems. Options are the p5series 610 Model 6E1, the p5series 620 Model 6F1, or for RS/6000 Model 170. The p5series 610 Model 6C1 and the p5series 660 Model 6H1 are the rack-mounted choices. The CWS manages all the servers and is the repository for the Single System Image (SSI). The SSI gives a single interface to the users and administrators of the cluster. This is typically the most daunting challenge to put tens or hundreds of processors together on a single task—making it look like just one system when it is in fact many systems and hundreds of processors. The SSI provides a single copy of the AIX5L operating system, which is proliferated to each logical node.

UNIX clusters are popular in large-scale numeric environments such as research centers and universities. These organizations apply parallel processing to such applications as computational fluid dynamics, gene sequencing, environmental modeling, and petroleum reservoir simulation. In the commercial area, Cluster 1600 systems are often used with parallel database software such as Oracle Versions 7 and 8 and IBM’s DB/2 Universal Database (UDB) for processing large databases.
