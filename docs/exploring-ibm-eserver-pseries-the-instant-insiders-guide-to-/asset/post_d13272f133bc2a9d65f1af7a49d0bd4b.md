However, it is difficult to judge how large a given file system needs to be until the system has been in productive use for a while. Because it is difficult to increase the size of a file system after the system is in productive use, herein lies a problem with the disk management approach taken by most traditional UNIX operating systems. Another limitation commonly found in UNIX operating systems is that a single file cannot span more than one physical disk. That is, the file size is limited by the size of each individual disk drive installed in the computer system rather than by the total amount of disk storage in the computer system. As application programs grow more sophisticated, file systems larger than a single physical drive are desirable.

To address these limitations, the AIX 5 operating system has expanded on the file system of the UNIX operating systems (and earlier AIX versions) with the Logical Volume Manager (LVM). The LVM conceptually partitions a group of physical disks (up to 128) into equal-sized sections called physical partitions. A logical volume is a collection of these physical partitions, conceptually equivalent to a file system. One difference in this approach is that a single logical volume can consist of physical partitions from multiple disk units in the computer system. This means that a logical volume can be larger than any individual disk unit in the system if necessary. Another difference is that physical partitions can easily be added to a logical volume to increase its size without disrupting normal operation or moving any other partition.

One function of the LVM is mirroring. This feature allows for multiple (or mirror) copies of a logical volume to be automatically maintained in disk storage. Each physical partition of a mirrored volume has one or two other physical partitions allocated on different physical disks to hold identical copies of the data. If a permanent disk error occurs while reading a mirrored volume, the LVM will automatically read the data from one of the mirrored physical partitions and write any new data to a new area of disk. Thus the mirroring function of the LVM often allows a pSeries system to recover from permanent errors without disrupting normal system operation. Systems providing redundancy for automatic error-recovery purposes are said to be designed for high availability. Be aware, however, that you are keeping multiple copies of information in the disk system, more disk space will be required when the mirroring function is used.

# Application Development

Many organizations find that writing their own custom application programs is the best method of solving problems through computers. We will discuss various features within AIX 5L and additional products that can be used to develop applications. A large number of development tools are available for AIX; after all, that's UNIX begins, as a development system. First, let's look at what comes with AIX 5L itself.

# AIX 5L Development Tools

With the AIX 5L operating system, several development tools are available to you. AIX 5L comes with the "vi" full-screen editor and tools to support the development and maintenance of custom application programs. These include traditional UNIX commands and utilities such as the Make command, used to easily rebuild complex systems of programs after changes have been made. Another UNIX operating system function supported by AIX 5L is the Source Control System, which provides a mechanism to record and control when, why, and by whom changes are made to the source of a program during development. Subroutine libraries provided include libc.a, the enhanced floating-point math library, the 4.3 BSD compatibility library, and a DCE compatibility library.

AIX 5L also provides a type of programming structure for automating a series of operating system commands, called "shell scripts." Shell scripts can be used to issue a single operating system command or to define a complex series of operating system commands with menus and initiate other application programs. # Compilers

The IBM VisualAge C Compiler, a separately ordered product for AIX 5L, supports the development of programs written in the popular programming language. A programming language can be thought of as a library of instructions from which a programmer constructs a program. The instructions of C (and other programming languages) are designed to be easily understood by the programmer, facilitating productivity while writing programs. However, the resulting of instructions (the program) cannot be directly understood by the pSeries hardware. The VisualAge C Compiler takes the list of C instructions written by the programmer and automatically converts them to a series of instructions that are executable by the pSeries processor.

Other languages include C++ and FORTRAN. Additional compilers for AIX 5L are also available from companies other than IBM. All of these compilers are designed to meet existing standards. The language you select depends on the requirements of the application and the skills of your.

Although not a tool in the same sense as compilers, it is important to note that AIX 5L provides runtime execution for programs written in the popular language. One may think of this capability as a interpreter. Both the 64-bit and 32-bit kernels of AIX 5L are fully compatible.

# Libraries

Several subroutine libraries are offered for AIX 5L programming environment, including the AIX Engineering Subroutine Library (ESSL). These subroutines use algorithms tailored to specific operational characteristics of the hardware such as cache size, page size, and floating-point operations. ESSL provides prewritten routines for such things as matrix operations, eigensystem analysis, interpolation, linear algebraic equations, Fourier transforms, convolutions and correlations, and others. This subroutine library is designed to accelerate program development by allowing the programmer to employ highly tuned, prewritten mathematical routines rather than write them from scratch.

Through the X development environment, AIWindows (discussed earlier in the chapter) provides a multivindow (on OSF/Motif) programming environment. This allows an application programmer to do such things as executing source code in one window and monitor the program in another. Alternately, programmers may be accessing X 5L on-line documentation in one window while writing a program in another, looking at both simultaneously. AIWindows also provides tools to ease the development of graphical user interfaces for programs—namely, the Windows Graphics Support Library and Display PostScript for AIWindows products.

Support for three-dimensional (3D) graphics is provided by two components for use with IBM's UNIX workstations—OpenGL and GL 3.2, and PHIGS. The OpenGL and GL 3.2 component provides support for the popular Graphics Library developed by Silicon Graphics. The PHIGS component provides a set of subroutines for generating and manipulating images through the ANSI and ISO standard as the Programmer Hierarchical Interactive Graphics System (PHIGS). Programs specifically written to these APIs can usually be migrated to AIWindows with minimal programming efforts.
