# What Is Multiprocessing?

Whereas “multiuser” refers to the ability for many users to share the resources of a system concurrently and “multitasking” means that the system can run many different applications simultaneously, the term “multiprocessing” refers to the ability of an operating system to support many processors, all of which share system resources such as memory and input/output devices. A multiprocessor-capable operating system, such as AIX, allocates work to the available processor(s), thus increasing the performance of the system above would be possible if there were only one processor available. The user does not have to worry about which specific processor is running his or her application. In this book we have described many pSeries models as symmetric multiprocessing (SMP) systems, and you should have noticed that the larger the system (i.e., the more processors), the higher the performance.

The word “symmetric” simply means that the processors share memory and I/O devices equally.

In an SMP system, it is possible for one application to “hog” all the system resources. To overcome this, AIX Workload Manager is an important software tool that allows the systems administrator to allocate a certain amount of processing power for specific applications, ensuring a basic level of processing power for each major application. So, if the system is very busy, an application will always get at least a predetermined level of processing power. And, if the system is less heavily loaded, that application may run even faster, since the operating system can allocate more processing power to it.

# What Is Logical Partitioning?

As explained in the section on logical partitioning in “A Closer Look” in Chapter 1, logical partitioning is really a capability of the pSeries hardware, namely the POWER4 and POWER+ processors and the system firmware or microcode. LPAR allows the pSeries system to be partitioned into “virtual servers within a server”, each having at least one or several processors assigned to it and each LPAR running its own copy of the operating system. The allocation of processors, memory, and I/O is flexible and does not conform to physical boundaries, such as how many processors are on a multiprocessor module (MCM) or which PCI bus the I/O slots are on. The number of LPARs depends on the size of the pSeries server. A p690 can have up to 16, a p650 up to eight, and the p655 and p630 up to four LPARs.

Although not an operating system, LPAR is supported and enhanced by the operating system in several ways. On each partition can run any of three operating systems—AIX 5L v5.1, AIX 5L v5.2, or Linux. The functions available in each “virtual server” depend on the operating system. Each LPAR running AIX 5L v5.1 or v5.2 will have the support of all the autonomic computing and systems management capabilities of AIX 5L. Since Linux does not currently support all the functions available in AIX 5L, LPARs running Linux will be limited to the functions provided by that operating system. Two examples of such functional differences are dynamic deallocation of processors and PCI buses (which help increase system availability) and AIX Workload Manager (which allows the administrator to assign resources to various application workloads). For LPARs running AIX 5L, these capabilities work just as they do on a pSeries SMP server without LPAR, but LPAR running Linux will lack those functions. On the other hand, the reason for running Linux in some LPARs is to have compatibility with the Linux applications the user requires and, presumably, those applications will run fine without the AIX 5L capabilities.

AIX 5L v5.2 enhances LPAR with the ability to add or remove processors, memory, or adapters to a partition without rebooting the LPAR or the system. In order to assign resources to LPARs running AIX 5L v.1 or Linux, the partition must be restarted (static LPAR). Also, the dynamic LPAR capability provided by AIX 5L v5.2 works with processor and memory CuOD (Capacity Upgrade on Demand) to allow newly activated processors or memory to be assigned immediately to the appropriate LPARs and to allow dynamic processor sparring.

Local partitioning offers the user many advantages. For example, an application or set of applications can run in a specific logical partitioning, guaranteeing the availability of the assigned resources for that partition.

# AIX 5L—An Overview

The UNIX operating system was originally developed by AT&T's Bell Labs. Over the years, it has continuously been enhanced by various organizations (both academic and business), resulting in a powerful and flexible operating system. It became popular for several reasons:

- First, AT&T licensed the operating system to many different manufacturers.
- Second, the UNIX operating system became prevalent in colleges and universities. As students learned the UNIX operating system in academic environments, it was only natural that they would seek out the business world.
- Finally, the C programming language fostered by the UNIX operating system is highly popular.

The operating system has evolved to be the basis for the open-system marketplace, in which compatibility with industry standards is the hallmark. Compatibility means that programs written for one brand of “open system” can easily be migrated to another brand. The open-system concept is good for application developers because they can easily offer their products on many brands of computers. This is good for users because they have a multitude of software to choose no matter what brand of open system they buy.

IBM took the UNIX operating system and incorporated many enhancements developed by other organizations (e.g., the University of California at Berkeley), and came with its version, called the Advanced Interactive Executive. This system approach was a departure from IBM’s proprietary systems such as the AS/400 or MVS operating system for IBM’s S370 and S/390 mainframes. pSeries computers running the AIX operating system are IBM’s third generation of UNIX platforms (The IBM RT System was the first, and RS/6000 systems were the second generation).
