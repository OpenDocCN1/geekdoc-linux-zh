There are five basic elements in the original RS/6000 processor architecture, each made up of thousands of circuits packaged in several designed chips:

+   1. Instruction cache/branch processor

+   2. Fixed-point processor

+   3. Floating-point processor

+   4. Data cache

+   5. I/O unit

Figure 1.24 is a block diagram showing how these elements are organized to make the original RS/6000 hardware architecture. To see how this architecture can do multiple operations at the same time, let's quickly trace the flow of information through the system. It starts when the user executes a command to start a program, which causes the instructions of that program to be retrieved from disk storage and loaded into main memory (shown at the bottom of the diagram). After the program is loaded into main memory, the processor requests the first instruction (4 bytes) in the program. In compliance with the request, the first instruction is retrieved from the main memory along with the next several instructions (a total of 64 sequential bytes) and loaded into the Instruction Cache Unit (ICU). The instruction cache is a group of very high-speed memory circuits contained in the ICU chip. It is used as a temporary holding area (8 KB in size) for instructions that are likely to be next in line to be executed.

When the processor requests the next instruction, it first looks in the ICU. The next instruction needed will already have loaded into the ICU, eliminating the delay associated with getting the instruction from slower main memory. This is called a cache hit. Because the instruction cache can respond more quickly than the system's main memory, the system's performance is dramatically improved with every cache hit. If the needed instruction is not already loaded into the ICU (called a cache miss), another 64 bytes starting with the needed instruction are automatically loaded from the main memory into the ICU. In the case of a cache miss, loading the ICU takes longer than simply getting the needed instruction from main memory
