There is also a large S390 system with custom application programs and many terminals and printers attached. This system provides inventory management, basic accounting, order entry, and other financial functions.

Although the inventory and order-entry systems have been performing quite well for Atele, recent expansion of Atele's product line has forced unforeseen upgrades to the S390. In addition, Atele's homegrown financial software is beginning to dull the company's competitive edge. Continuous "enhancements" through the years have caused any new features to take many employee-hours to implement. Facing an upgrade of the mainframe environment and replacement of the financial package, Atele looks for a way to solve both problems at once: Purchase a new to run an up-to-date, off-the-shelf financial product. Maintaining the "rock-solid reliability" is paramount. Any new system must provide excellent reliability, communicate with the S390, be able to support, and meet the budget objectives for a new system.

Atele evaluated several financial products and selected PeopleSoft p690 system running the AIX 5.v5.2 operating system and also selected the IBM High Availability Cluster Multiprocessing software. With the large installed base of UNIX workstations at Atele, the support staff is comfortable that they can support the pSeries and implement the high-availability configuration that is planned. The dynamic partitioning capability of the p690 allows flexibility of adjusting system resources to the workloads of various applications. The Capacity Upgrade on Demand (CuOAD) features help manage cost of ownership by allowing installation of hardware at acceptable cost, with the ability to activate it when the need arises to handle heavier workloads or to install new applications.

Figure 5 shows the dual pSeries 690 configuration. One p690 (12-way 1 GHz POWER4+) with four inactive CuOD processors will comfortably support the production users of the financial applications connected via Gigabit Ethernet LAN. The other p690 (12-way with four inactive processors) serves as the failover (backup for production) HACMP system and the development system. Atele decides to configure both systems the same, even though this is not required for normal workload on the development system.
