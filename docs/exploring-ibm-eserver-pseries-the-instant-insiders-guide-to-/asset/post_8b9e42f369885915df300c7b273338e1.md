Systems that employ multiple main processors working in parallel can achieve extremely high levels of performance and are called highly parallel or massively parallel systems (depending on the number of main processors used in the system). A common industry term is Massively Parallel Processing (MPP). This may sound much like the SMP systems that we discussed earlier, but a Cluster 1600 system is quite different. Each P5series (or LPAR thereof) within the cluster is an independent SMP server in its own right, having its own operating system, disk, memory, and adapters. The Cluster 1600 allows up to 128 operating system images to be managed as a single computing resource. Each operating system image (sometimes called a logical “node”) is controlling multiple processors (depending on the size of server or LPAR), so the cluster can contain hundreds of processors.

An additional piece of hardware called the Control Workstation (CWS) is required for a Cluster 1600 configuration. The CWS can be one of several deskside or rack-mounted systems. Options are the p5series 610 Model 6E1, the p5series 620 Model 6F1, or for RS/6000 Model 170. The p5series 610 Model 6C1 and the p5series 660 Model 6H1 are the rack-mounted choices. The CWS manages all the servers and is the repository for the Single System Image (SSI). The SSI gives a single interface to the users and administrators of the cluster. This is typically the most daunting challenge to put tens or hundreds of processors together on a single task—making it look like just one system when it is in fact many systems and hundreds of processors. The SSI provides a single copy of the AIX5L operating system, which is proliferated to each logical node.

UNIX clusters are popular in large-scale numeric environments such as research centers and universities. These organizations apply parallel processing to such applications as computational fluid dynamics, gene sequencing, environmental modeling, and petroleum reservoir simulation. In the commercial area, Cluster 1600 systems are often used with parallel database software such as Oracle Versions 7 and 8 and IBM’s DB/2 Universal Database (UDB) for processing large databases. A third application area for clusters is called server or LAN consolidation. Instead of having servers geographically distributed throughout an enterprise at locations where system administrators might not be available, a cluster allows a common pool of administrative personnel to manage all the servers, sharing backup devices, printers, and storage.

# Performance Overview

One important aspect of a computer system is the speed at which the computer can perform work, known as the performance of the computer. The greater the performance, the more work the computer can do. Many things—such as the processor, cache memories, main memory, disk storage, and program efficiency—affect the performance of a computer system. It is difficult and often misleading to predict overall performance by looking at selected specifications of the individual components that make up the system. Things like as drive rotational velocity, seek times, and processor clock speeds are important, but they do not get the whole picture.

A better way to compare the overall performance of different computers is to perform benchmark testing. This testing involves running the same set of programs on each computer being compared and measuring how each system behaves under the workload. Many elements of the system come into play through this benchmark testing, and the overall performance of selected systems can be meaningfully compared.

The best programs to use for a benchmark test are the application programs that are actually going to run on the system. The widely varying characteristics of application programs can have a significant effect on overall system performance. Therefore, running the actual programs on each computer will give the most realistic comparison. In many cases this is not practical, so computer manufacturers and others in the industry typically perform benchmark testing using industry-standard programs specially designed to quantify and document the performance characteristics of various computers.

IBM has conducted benchmark testing to document the performance of the various pSeries models. This testing was done by loading the computers with specially written programs, each designed to exercise the pSeries systems as they would be used in various environments. It should be understood that to perform benchmark testing, the test group must make assumptions about the kind of work being done and the behavior of the users and programs. For this reason, the performance measurements in this benchmark may vary significantly from what one finds if one's specific environment does not replicate the assumptions made in the testing. However, because all assumptions are the same for all computers included in the benchmark testing, one can get a good feeling for the relative performance of the systems. Because pSeries systems are designed for use in both commercial and technical environments, we will examine benchmark test results for all categories.

Figure 1.22 shows the SPECint2000 and SPECfp2000 ratings for selected pSeries models. These numbers represent the composite result of benchmark testing (with the fastest processor available for each model) using a series of application programs from different disciplines. It is important to note that these particular benchmarks demonstrate only the power of the processor and not the power of the total system. For example, the SPECint2000 result of 935 for the p650 is the same whether the configuration of the p650 is 2-way or 8-way.

For SPECint2000, the test involves 12 programs ranging from text compression to software development. This group of programs makes up the Systems Performance Evaluation Cooperative (SPEC) Suite SPECint2000 set of benchmarks and is designed to test the processor's ability to perform integer arithmetic (while numbers such as 1, 67987). Those intending to use a pSeries system for applications such as database access, accounting, and software development should consider the SPECint2000 rating because benchmark was specifically designed to document the processor's ability to perform the types of calculations that dominate these applications.

In the case of SPECfp2000, the benchmark is the composite result of testing using a series of 14 highly mathematical application programs ranging from quantum chemistry to weather prediction. This group of programs makes up the Systems Performance Evaluation Cooperative Suite SPECfp2000 set of benchmarks and is designed to test the computer's ability to perform numerically intensive and floating-point (fractional numbers such as 0.5, 56.888989, and 3.141) mathematics.
