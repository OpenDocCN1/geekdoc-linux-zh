The p655 can run any of three operating systems—AIX 5L v5.1, AIX 5L v5.2, or Linux (SuSE SLES 8). Up to LPARs can be defined on the p655, running a copy of one of these operating systems.
(Note: In order for Linux to run in a p655 LPAR, at least one LPAR must run on AIX 5L). If AIX 5L v5.2 is running in the LPAR, then resources can be assigned to that partition dynamically. If running AIX 5L v5.1 or Linux, then only static LPAR is supported. Further detail on LPAR and the terminology is used later in this chapter.

As many as 64 p655 servers running as a “full system partitioning” (i.e., as an SMP server without LPAR) are supported in Cluster1600 maximum of 128 operating system images. Connection to the Cluster1600 can be made with 10/100 Mbps or Gigabit Ethernet, or for maximum performance, through the SP Switch2 using the SP Switch2 PCI-X adapter.

# pSeries 660 Models 6H1, 6H0, and 6M1 Specifics

The pSeries 660 Models 6H0 and 6H1 are identical except that the Model 6H0 is a 1-, 2-, and 4-way SMP, and the Model 6H1 also provides a 6-way option. The pSeries 660 Model 6M1 is a 2-, 4-, 6-, and 8-way system with more expansion capacity than Models 6H1 and 6H0. All three models connect a CEC drawer or one more I/O drawers, and they all run AIX 5L and AIX v4.3.3.

The reason IBM offers the similar rack Models 660H0 and 6H1 is the same as that given earlier for the p620-6F0 and p620-6F1. That is, users need the maximum in performance growth (Model 6H1) others want to take advantage of workgroup database pricing (Model 6H0). Workgroup pricing is available (in the United States and other countries) from database vendors such as Oracle and IBM on systems with a maximum of 4-way SMP capacity. If a system can be expanded above 4-way (even if the customer is not using capacity), then enterprise database pricing applies.
