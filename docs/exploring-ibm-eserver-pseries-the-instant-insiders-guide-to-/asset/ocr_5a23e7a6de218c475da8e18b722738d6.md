There are other advantages of a more technical nature. Since an LPAR runs its own copy of the operating system and is isolated from other LPARs, a software failure in one LPAR affects only that "virtual server" and allows applications running in other LPARs to continue unaffected. Or, if a particular software application does not scale well in order to take advantage of a large SMP server, such as a 16-way p670 or p32-way p690, multiple copies of the application can be run in separate partitions.

The system administrator controls the configuration and operation of LPARs from an IBM 7315-C01 Hardware Management Console, which is a dedicated workstation that provides the necessary interface for configuring and operating the LPARs, including activation and deformation of Capacity Upgrade on Demand capabilities. LPAR involves the POWER4 processor architecture, the system firmware (microcode), and the operating system. The key element is the "hypervisor" function, a very complex control layer implemented in the system firmware and supported by POWER4 and POWER4 processors. A detailed discussion of the hypervisor is the scope of this book. The hypervisor controls memory and I/O device management, including system interrupts and DMA (Direct Memory Access) addresses. It also manages the interfaces to the HMC and to protected facilities and memory locations.

There are few differences in the operating system when running in an LPAR, and LPAR is transparent to the partition. The application software needs to be certified only to the relevant operating system image (AIX 5L, v5.1 or v5.2, or Linux). The system administrator determines whether the operating system in any particular LPAR is allowed to update system firmware, as firmware changes affects the entire server. Each LPAR requires at least one processor, 256 MB of memory (expandable in increments of 256 MB), access to a boot disk, and access to the HMC. So, in at least two I/O slots per LPAR are required, and these must be controlled by separate PCI bridge chips in order to allow each LPAR to be controlled independently. It is advisable to have media devices, such as a CD-ROM or tape drive, assigned to their own SCSI adapters so that they can be moved among LPARs as required for installing software or backing up data.
