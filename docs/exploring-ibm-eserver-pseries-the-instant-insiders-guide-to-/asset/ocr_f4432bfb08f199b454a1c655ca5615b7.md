What about the operating system and device driver layers? The ability to run earlier UNIX operating system software is not important for several reasons. Operating systems typically represent only a small fraction of the user's software investment; they can be upgraded without changing the user's view of the computer system. Further, a new operating system is usually necessary to allow users to access to new features of the computer system not considered by the programmers of the old operating system. Of course, one of the purposes of the device driver layer is to allow the computer hardware to change without affecting compatibility with the operating system and application programs. This is done by changing the way a device driver interacts with hardware without changing the way the device driver interacts with the operating system or application programs. The user is supplied with new device drivers to support pSeries hardware.

# Inside pSeries Compatibility

To understand pSeries compatibility, you must understand a little about how application programs are written. First, a programmer writes an application program's instructions or code using a programming language (e.g., C++, FORTRAN, etc.). A programming language is basically a library of computer instructions from which a programmer may choose to write programs. The list of programming language instructions that make an application program is called the program's source code. In order to run the application program on a computer, the source-code instructions must be converted into instructions a computer can understand. This process is compiling the program. When the source code is compiled, the result is called object code and can be directly executed by the computer hardware.
