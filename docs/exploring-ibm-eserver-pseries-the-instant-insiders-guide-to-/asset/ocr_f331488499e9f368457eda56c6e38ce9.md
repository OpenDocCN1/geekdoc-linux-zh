When a controlling device, called an initiator (e.g., the SCSI I/O controller), wants to perform an information transfer with another device (e.g., a disk unit), called a target, the initiator arbitrates for control of the SCSI bus. Once the initiator has control of the bus, it issues one of the commands defined in the SCSI standard protocol. While the target device processes the command, the SCSI bus is available for any other SCSI bus traffic. When the target device is ready, it gains control of the bus and supplies the requested information along with a completion status indicator to the original initiator.

One of the primary differences between SCSI and earlier disk interfaces is that each SCSI device must have local processing capability to participate in the SCSI command protocol. That is, each SCSI device attached to the bus is responsible for much of its own processing (e.g., error checking, error correction, and retry of failed operations). Earlier disk interface standards put the responsibility for managing the various devices in a centralized I/O controller rather than distributing the responsibility among the connecting devices.

The advantage of the SCSI approach is that work (e.g., error correction and error retries) is distributed over the processing capabilities of all SCSI devices, which off load the main controller system and put the work where it can done more efficiently. Also, activities such as the read-ahead function used in pSeries systems can be implemented completely in the disk unit itself, making it transparent to the pSeries systems and the SCSI I/O controller (“Read-ahead” means that the SCSI disk unit loads extra information from the disk platter to a buffer area in anticipation of the next request from the SCSI I/O controller.) When the next request comes, if the needed information is already available in the buffer area, it can be sent to the SCSI I/O controller immediately, eliminating the mechanical delays associated with disk seek time, latency, and so on. The result is highly efficient transfer of information between the SCSI I/O controller and the disk units.

Although we have used the term “SCSI” in this discussion, the reader will notice terms like “Ultra-SCSI” and “Ultra3-SCSI” used in descriptions of pSeries systems. Multiple versions of SCSI are used with pSeries systems. The maximum instantaneous transfer rate over the SCSI bus is 4 Mbps, whereas SCSI-2 runs at 10 or 20 Mbps.
