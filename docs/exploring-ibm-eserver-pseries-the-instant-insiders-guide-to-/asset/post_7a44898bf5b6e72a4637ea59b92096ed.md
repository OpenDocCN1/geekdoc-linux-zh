There are other advantages of a more technical nature. Since an LPAR runs its own copy of the operating system and is isolated from other LPARs, a software failure in one LPAR affects only that "virtual server" and allows applications running in other LPARs to continue unaffected. Or, if a particular software application does not scale well in order to take advantage of a large SMP server, such as a 16-way p670 or 32-way p690, multiple copies of the application can be run in separate partitions.

The system administrator controls the configuration and operation of LPARs from an IBM 7315-C01 Hardware Management Console, which is a dedicated workstation that provides the necessary interface for configuring and operating the LPARs, including activation and deactivation of Capacity Upgrade on Demand capabilities. LPAR involves the POWER4 processor architecture, the system firmware (microcode), and the operating system. The key element is the "hypervisor" function, a very complex control layer implemented in the system firmware and supported by POWER4 and POWER5 processors. A detailed discussion of the hypervisor is the scope of this book. The hypervisor controls memory and I/O device management, including system interrupts and DMA (Direct Memory Access) addresses. It also manages the interfaces to the HMC and to protected facilities and memory locations.

There are few differences in the operating system when running in an LPAR, and LPAR is transparent to the partition. The application software needs to be certified only to the relevant operating system image (AIX 5L, v5.1 or v5.2, or Linux). The system administrator determines whether the operating system in any particular LPAR is allowed to update system firmware, as firmware changes affect the entire server. Each LPAR requires at least one processor, 256 MB of memory (expandable in increments of 256 MB), access to a boot disk, and access to the HMC. So, in at least two I/O slots per LPAR are required, and these must be controlled by separate PCI bridge chips in order to allow each LPAR to be controlled independently. It is advisable to have media devices, such as a CD-ROM or tape drive, assigned to their own SCSI adapters so that they can be moved among LPARs as required for installing software or backing up data.

# Main Memory

The main memory, set of electronic chips that provide a “workspace” for the main processor, is also a very important part of a computer. It holds the information (program instructions and data) being used by the main processor. The main memory is called RAM because it can store and retrieve information independent of the sequential order in which the information was originally stored.

The smallest RS/6000 system available, the Model 150, stands with 128 MB (about 128 billion bytes) of main memory, and the least amount of standard memory on pSeries servers is the 256 MB on the p640. The largest system, the p690, has 8 GB (about 8 billion bytes) standard, and can support up to 512 GB of main memory—half a terabyte. When you have this much main memory in a system, schemes detect and correct memory defects become necessary to protect the integrity of the information stored in the computer system's main memory. The pSeries uses several techniques to protect the integrity of its main memory. The ECC technique used in the pSeries family can detect single-bit and double-bit errors and correct single-bit errors. This is done by appending several bits (called ECC bits) onto every word (32 bits) in main memory. The seven ECC bits are automatically generated and stored. When a word is read from main memory, the ECC bits are checked. In this case, the error is detected and corrected on the fly.

Chipkill allows the system to continue in the presence of complete chip failure. Whereas bit steering redirects bits of memory, the Chipkill design scatters all bits into four words. Even if the entire chip fails, the ECC algorithms recover the data. In any computer system, a great deal of information is moving in and out of main memory. For this reason, the design of the main memory significantly affect overall performance. There are two reasons why so much time is spent moving information in and out of the main memory. First, the programming instructions of the program(s) reside in the main memory. Therefore, every instruction in the program must at some point be retrieved from the main memory. Second, the main memory holds and data used in the program(s) being executed. If the overall information flow to and from main memory (assisted by the instruction cache unit and the data cache unit) cannot keep pace with the main processor, the main processor will be delayed and system performance will suffer. For this reason, the main memory must be designed to keep up with the speeds achievable by the main processor. The design of the pSeries processor and its main memory are balanced through the use of separate data and instruction caches and the wide path between main memory and the caches, or "bus" discussed earlier. To further balance the system, the path or bus between caches and main memory (which can exceed 200 Gbps in the p690) is independent from the I/O bus used for input/output activity as disk information transfers. This prevents interference between main memory activity and input/output activity, which can increase the overall performance of the system.
