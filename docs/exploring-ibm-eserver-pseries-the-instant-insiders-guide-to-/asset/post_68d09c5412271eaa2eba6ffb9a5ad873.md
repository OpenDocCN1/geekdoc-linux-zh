## POWER4 and POWER4+ Microprocessors

IBM's POWER4 microprocessors, running at clock rates of 1.1 GHz and 1.3 GHz (more than one billion cycles per second), were introduced on the pSeries 690. Using the same architecture, coupled with enhanced chip fabrication technology, POWER4+ processors running at clock rates from 1.2 to 1.7 GHz are now available on all focus pSeries servers—p615, p630, p650, p655, p670, and p690. POWER4+ processors, which contain more than 180 million transistors, are manufactured with IBM's 0.13 micron fabrication process, whereas the 0.18 micron process was used for POWER4 chips. The energy-saving copper and SOI technology is used in both POWER4 and POWER4+ processors. The combination of smaller chip size and SOI technology make it possible for the higher processor speeds available with POWER4+ processors. The same architecture is used for the original POWER4 and the latest POWER4+ processors. The POWER4 processor architecture is the result of a long development cycle guided by several goals: optimization for SMP designs and ability to extend to very high frequency, and binary compatibility with 32-bit and 64-bit PowerPC applications.

The POWER4 chip (Figure 1.20, shown previously) has two processors, each with an L1 data and instruction cache, sharing a L2 cache structure through a crossbar switch (CIU). Each of the three independent L2 cache controllers can provide 32 bytes (256 bits) from L2 to either the data cache or the instruction cache in one of the processors per cycle. The Fabric Controller is the hub of the chip, providing the high-bandwidth paths required to meet the objectives of a balanced design for memory and I/O access, and for optimized SMP performance. That means that the POWER4 processor is designed with multiple execution units (for floating-point, fixed-point, load/store, branch) and look-ahead logic to maximize the utilization of every clock cycle that the processor is never idle, waiting for data, instructions, or computation results. The “speculative” part means there is very complex logic that predicts which branches in a string of instructions will be taken or not and acts accordingly (calculating addresses, fetching information, etc.). This logic helps to maximize execution speed because the system does not have to wait and see the results of some calculation on which the conditional branch-to-information depend before fetching.

## Logical Partitioning

Logical partitioning technology, introduced to the pSeries family by the p690, is also available on p630, p650, p655, and p670. The only POWER4-based system that does not support LPAR is the 1-way p615, which is too small a server to take advantage of it.

LPAR allows the system administrator to assign processors, memory, and I/O slots (and the attached devices) to create, in effect, several independent systems or "virtual servers" running on a single server. Each partition can run different operating systems—AIX 5L v5.1, v5.2, or Linux. The allocation of processors, memory, and I/O is flexible and does not have to conform to physical boundaries, as to how many processors are on a multipitch module or which PCI bus the I/O lots are on. For LPARs in which AIX 5L v5.2 is running, resources can be assigned or removed without having to reboot to partition the system ("dynamic LPAR"). LPARs running AIX 5L v5.1 or Linux only "static LPAR," meaning that the partition must be rebooted in order to reassign resources.

Logical partitioning offers the user many advantages. For example, an application or set of applications can be run in a specific logical partition, guaranteeing the availability of the assigned resources for workload. Since different applications can run in each LPAR, possible scenario is to have a production LPAR running the tested software version of an application, while in another LPAR there is a test system running a new version of the application.
