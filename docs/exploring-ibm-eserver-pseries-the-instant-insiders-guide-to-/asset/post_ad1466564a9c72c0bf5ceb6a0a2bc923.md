Often this throughput is well worth the coding effort for database developers. If you are purchasing a database, however the development and tuning has already been done for you. Often, database users will be able to bring forward all of their investment in queries, screens, reports, and so on. They may require only a minor modification or recompilation when moving the uniprocessor version of the database to the SMP version.

As one might expect, this architecture, which processors are running independent (App2 and AppN) or coordinated (App1a and App1b), can lead to several bottlenecks in performance as programs contend for vital resources such as memory or disk storage. Additional complexities develop as processors start to cache data. Let's go back to our example in which variable X, stored in main memory, has been modified by App1a and is still resident in the cache of CPU1. Now App1b needs to read variable X, CPU2 must now talk to each other and main memory to be sure to get the correct value of variable X into the cache on each processor. The coordination of current versus stale data between processors is known as cache coherency and is a prerequisite for a chip design to be considered for use in an SMP system. All the processors used in pSeries systems are cache coherent.

# Storage

Various kinds of storage devices are commonly used in all computers, providing a relatively inexpensive way to store data and programs. Devices with removable media (e.g., CD-ROMs, diskettes, tapes) also make it possible to interchange information between systems. The information stored on these devices can be easily modified or kept unchanged over long periods of time as an archive. Because storage is nonvolatile, the stored information remains intact whether the computer is turned on or off. The pSeries use four types of storage: diskettes, disk drives, magnetic tape, and optical disks. Let's look more closely at each of these types of storage.

# Diskette Storage

Diskettes, a portable storage medium with relatively low capacity and slow performance, are familiar to most readers because they have been used on PCs for years. Although still used in most pSeries systems, diskette drives will probably be phased out over the next few years as new technologies such as writable CD-ROMs and DVD-RAMs become more pervasive and more systems are connected via the Internet. The diskette consists of a flexible disk with a magnetic surface permanently enclosed in a square protective jacket and is manually inserted into the diskette unit, which spins the circular disk inside the diskette. The read/write head inside the diskette unit makes contact with the spinning disk as a record player's needle contacts the disk spins, the head mechanically reads and writes information on the disk's surface.

Most pSeries systems still offer 3.5-inch diskette drives, but the availability of higher capacity technologies such as DVD-RAM and writable CD-ROM is beginning to render the diskette obsolete in the server environment. Diskettes allow exchange of information between pSeries systems and PCs because read or write diskettes (either 720 KB, 1.44 MB, or 2.88 MB) in a format compatible with PC systems running either the DOS or Windows operating systems.

# Disk Storage

All pSeries systems use disk storage—the high-capacity, high-speed magnetic storage devices commonly used in all types of computers from notebook-sized computers to the largest supercomputer systems. Sometimes you will hear the terminology "hard disk" (an old term used to differentiate disk storage from "floppy" diskettes) or "DASD" (IBM parlance for Direct Access Storage Device). We will use the terms "disk" or "disk drive."

The primary function of disk storage is to hold information that must be readily available to the computer system. It contains programs and data, and provides a temporary holding area used by pSeries systems. Information in disk storage must be loaded into main memory before the computer system can use it. pSeries systems are available with many different disk configurations. The largest system, the p690, can have about 18.7 TB of disk storage in its I/O drawers—not to mention the possibility of attaching external storage devices for even greater capacity. Disk storage subsystems, which are attached by a cable to a storage adapter in the pSeries server, can significantly expand the disk capacity of a pSeries system beyond the maximum internal configuration. Some of these external storage devices will be discussed in Chapter 2.

Disk subsystem performance is important to the overall performance of a computer in most applications. This is especially true in virtual storage or LAN server environments in which there is heavy transfer of information between the disk storage and main memory. Performance of a disk seek to the rate at which information can be located and transferred between the disk drive and the disk controller circuitry. As traditional record albums, information on disk is stored in concentric rings on the disk platter surface. Each ring is called a track. To read information from a track, the actuator must first move the read/write head to the proper track. The time it takes (on the average) for the actuator to move the read/write head over the proper track (or “seek the track”) is called the average seek time—usually expressed in milliseconds (1/1000 sec).

Once the read/write head is located over the right track, it must wait until the disk rotation brings the right part of the track under the head. The time it takes for this to happen (on the average) is called the average latency of the drive, also expressed in milliseconds. Finally, after the proper track and proper part of the track are positioned under the read/write head, the information is transferred between the disk controller circuitry and the disk bit at a time in a continuous stream as the disk surface passes underneath the read/write head. The speed at which this is done is called the data transfer rate and is expressed in millions of bytes per second (Mbps). The shorter the access time and latency, the better the data transfer rate, the better. All of factors determine how the disk subsystem will contribute or hinder overall system performance. Chapter 2 provides the specifications for the disk drives available for pSeries systems.

Each disk drive affects transfers to and from pSeries systems through control circuitry located either on the system board or on an adapter card in one of the PCI slots. Most internal and many external disk drives used with pSeries systems attach to Small Computer System Interface I/O controller circuitry.

# SCSI Disk Storage

SCSI (pronounced "scuzzy") is an industry-standard way of connecting devices (disks, tape, CD-ROM drives, etc.) to computer systems. The SCSI controller circuitry (often more than one controller) resides on the system board in all pSeries systems or on the I/O backplane. Depending on the system configuration and application requirements, SCSI storage devices are often attached via a SCSI adapter card plugged into a PCI or PCI-X slot. In either case, the SCSI controller circuitry is built around a microprocessor specially programmed to implement the SCSI protocol.
