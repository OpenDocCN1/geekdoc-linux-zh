# Memory Capacity Upgrade on Demand

The p690 offers memory CuOD, an innovation that works with AIX 5L v5.2 (not AIX 5L v5.1 or Linux) to allow standby memory to be dynamically activated in 4 GB increments. Memory CuOD is available on p670 and p650 systems, as well. The memory CuOD options are the following:

- pSeries 690—16 GB with 8 GB active and 32 GB with 16 GB active
- pSeries 670—16 GB with 8 GB active and 32 GB with 16 GB active
- pSeries 650—4 GB with 0 GB active and 8 GB with 0 GB active

Memory CuOD is available independent of whether processor CuOD is used on the system. The activation process is the same as activating CuOD processors. That is, the appropriate 4 GB activation feature is ordered, and IBM provides an encrypted key (activation code), which the user applies when more memory is needed.

# On/Off Capacity on Demand

On p690, p670, and p650 systems with CuOD processors installed, another type of processor activation is available—on/off or temporary CoD. This capability does not apply to memory CuOD, but only to processors. Rather than purchasing a permanent activation feature for a pair of processors, as described in "Capacity Upgrade on Demand," an On/Off CoD feature provides a way to activate processors for infrequent workload increases. For instance, a business may have infrequent seasonal workload or may need extra processing power for a short time to test a new application.

On/Off CoD works like a prepaid phone card. Each feature entails the customer to 60 processor days of usage, measured for each 24-hour period during which a processor is activated. Processors are still activated in pairs. If more than two CuOD processors are available, multiple pairs of processors can be activated using a single On/Off CoD activation feature. Like the activation features for processor and memory CuOD, the user is sent an encrypted key to activate one or more pairs of processors.

A processor usage day is charged beginning when the pair of processors is turned on and then each 24-hour period of continuous usage thereafter. The minimum usage time measured is one day. For example, if a pair of processors is turned on at eight o'clock in the morning and then at five o'clock in the afternoon, two processor days are charged. Or, if four processors are activated at eight o'clock one morning and are deactivated at noon the next day (28 hours later), eight processor days are charged (four processors times two days).

On/Off CoD is a valuable tool for some businesses, but it is not for everyone. Companies who are seeking to minimize their investment while preparing to handle growing workloads will probably find their requirements adequately met with processor and memory CuOD. On/Off CoD is designed as a buffer against unexpected or very infrequent spikes in workload.

# Trial Capacity on Demand

The last innovative “on demand” function available on p690, p670, and p650 systems is Trial CoD. Trial CoD is a no-charge function provided to customers who either processor or memory CuOD features. They allow them a one-time opportunity to activate all or part of their standby resources (processors or memory) for a period of 30 consecutive days. Use of Trial CoD might be for a company to activate standby resources in order to evaluate the effect on system operations. Another situation could be when immediate activation of resources to meet rapidly increasing workload demands is needed, but it will take a few days to process a purchase order for a permanent CuOD activation feature.

If processor and memory CuOD features are installed, the trial opportunities for processors and memory may be executed independently. There is no need to get an activation code or key from IBM for Trial CoD. In the case of processor CuOD, the trial opportunity is enabled when a feature is installed. For memory CuOD, the trial opportunity is one system.

# Reliability, Availability, and Serviceability (RAS)

In addition to the POWER4 architecture and logical partitioning, the third major innovation in the p690 is the RAS capabilities. The p690 offers all the self-management features—hot-swappable disk drives, hot-plug PCI slots, Chipkill memory, dynamic error recovery, redundant power and cooling. In addition, it offers:

- memory, L2 and L3 caches
- Optional redundant battery backup units
- “Blind-swap” PCI slots (allowing adapters to be hot-plugged without moving the I/O drawer)
- PCI error recovery
- Design of internal storage to reduce single points of failure

# IBM @pSeries—An Overview

The design of the p690 hardware and firmware, combined with the self-management capabilities of the AIX 5L operating system, provides First Failure Capture, error logging, uncorrectable error handling, dynamic error recovery, and predictive failure analysis on processors, memory, I/O, and disk drives. The pSeries 690 design for high availability is important for datacenter operations, where the probability of unplanned system outages must be minimized. For even higher availability, the pSeries 690 can be clustered using HACMP.

For the HPC computations and multiprocessor database applications, up to 32 pSeries 690 servers and/or 16 p690 LPARs are clustered and managed from a single point of control using IBM Parallel Support Programs (PSSP) for AIX or IBM Cluster Management (CSM). When running PSSP, the p690 can be clustered with other pSeries servers with the latest higpeed switch technology, SP Switch2. # IBM eServer Cluster 1600

The IBM eServer Cluster 1600 was announced in November 2001 to bring together into a single system identified by one serial number all the elements of UNIX nodes, including RS/6000 SP nodes, although SP nodes are no longer available for purchase. Long leader in UNIX cluster technology, IBM now offers cluster software products—IBM Parallel Support Programs for AIX, IBM Cluster Management for AIX 5L, and the General File System (GPFS)—as building blocks for configuring large UNIX clusters using the latest pSeries servers. Even though the hardware packaging of these servers (except for the pSeries 635) differs from the form factor of the older RS/6000 SP nodes, the architecture based on a single point of control using PSSP is unchanged. The SP Switch2, available in a standalone frame, provides a high-speed, low-latency, point-to-point connection to make distributed applications more efficient. The supported interconnection options for Cluster 1600 are the following:

- Ethernet LAN (gigabit or 10/100 Mbps)
