## Distributed Computing

Among the most far-reaching extensions to AIX 5L are the AIX Distributed Computing Environment products. In the open-system environment, many different brands of computers are typically found in the same communications network. An environment in which many small computers (rather than one central computer) are used to satisfy the computing needs of users is a distributed computing environment. Although the computer systems are physically attached via the network, the application program(s) running on one computer system or operating system can't interact effectively with an application program running on a different computer system or operating system—even when no one is breaking open-system rules. This problem becomes more apparent as networks grow and users on one workstation (a client workstation) need access to the resources located on another computer (a server).

One way to address the need for a more homogeneous environment for distributed computing is to provide a set of common services that are always present in a distributed computing environment. Then any application programs that are designed to use only those services will work on any type of computer system and network. The Open Group (discussed earlier in this chapter in “AIX 5L—An Executive Overview”) has selected and endorsed a set of distributed computing technologies taken from many different vendors and collectively called them the distributed computing environment. IBM’s AIX DCE products are built on the Open Group’s DCE.

Many of the base “run-time” services of DCE and its major service, the Distributed File System (DFS), are integrated into AIX 5L. These clients include configuration, security, cell directory, time, RPC, and DFS. The DCE base services allow users to share files stored in a network of computers without knowing the physical location of the files.

## Communications Support

Communications facilities included in AIX 5L allow a properly equipped pSeries system to communicate with almost any variety of ways. Traditional open systems used terminals and printers that communicated with the computer system over asynchronous communications using the American Standard Code for Information Interchange protocol. With this communications method, character at a time (letter, number, period, comma, and so on) was sent from the computer’s communications port through a simple cable to the port of the attached device. This is how ASCII terminals and printers communicated with the UNIX operating system. This simple ASCII method was also used to send information from one computer to over a similar type of cable. Although pSeries systems and AIX 5L still use ASCII communications with other computer systems, they are much less used than the methods described here.

As more and more vendors offered computer systems and the need for intercomputer protocols evolved, the Transmission Control/Internet Protocol (TCP/IP) was developed. As an industry standard, TCP/IP allows systems from many vendors to communicate with each other in a single network. The AIX 5L operating system supports TCP/IP over Ethernet/802.3 networks, Token-Ring networks, the Enterprise Systems Connection (ESCON), Asynchronous Transfer Mode (ATM), and the Block Multiplexer Channel Adapter if the computer systems are near each other (for example, on the same campus). AIX 5L also supports the TCP/IP protocol between distant computer systems—over asynchronous communications networks or X.25 packet-switching networks, for example.

Communications functions have emerged to meet the needs of sophisticated communications environments, such as the Network File System (NFS) and the Distributed Computing Environment, both of which are supported in the AIX5 operating system. The NFS and application programs written to use allow one computer system to access information located on another computer system over a local network or other networks using TCP/IP. This allows information to be distributed in a network so as to make that information most available to those who need it and that it can be managed. The DCE extensions to AIX5L application programs designed to take advantage of DCE by distributing a computer’s workload across the various computer systems in a network. However, with recent advances in communications technology, DCE is of less importance today than in the past.

Although the requirement for pSeries users to access applications on other types of systems in native mode (e.g., emulating an IBM 3270 or 5250 terminal) is rapidly going away, AIX5 supports the IBM Host Client Package for Multiplatforms v3.0 product. IBM Host Client Package provides access to applications and data on iSeries (5250), zSeries (3270), and DEC/UNIX (VT) hosts for traditional and Web users in either intranet or SNA networks. AIX5L is supported by both a client and as a server.

Tivoli NetView7 provides network management tools based on the Simple Network Management Protocol (SNMP) commonly used in the open-system environment. NetView works like this: When a device in the network (the SNMP agent) senses a problem, it sends an SNMP message to the computer running NetView (the SNMP manager). NetView notifies the network support personnel that a problem has been detected and provides detailed information about the problem. Thus, NetView allows for centralized management of a distributed, open-system network, which typically improves the productivity of the network support personnel and the availability of the network. Tivoli NetView also provides firewall support with a single unidirectional port for e-business networks and provides the systems administrator tools for managing the network, including diagnostic aids and a graphical representation of the network.

AIX Fast Connect allows the PC and the pSeries system to cooperate in such a way that the user can take advantage of the best of both. The PC can be used for such operations as spreadsheets, graphs, and word processing, providing functions and response times tuned to these applications. At the same time, the pSeries system contributes information security, centralized systems management, large disks, intensive communications, high-speed printers, and so forth. For example, information in pSeries files can be brought down to the PC and manipulated using a spreadsheet. Further, a file created on the PC (using a word processor, for example) can be transferred up to the pSeries system and accessed by AIX 5L like any other file. Finally, the pSeries disks can be used as an extension to the PC's disk space through the use of shared volumes—areas of the disk that can be accessed by either a PC or AIX 5L.
