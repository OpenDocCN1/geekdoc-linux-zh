# Memory Management

The way in which a computer system uses available main memory and disk storage, called the computer’s memory management scheme, is basic to the capabilities of the computer. Understanding the basics of this memory management will give insight into one of the features of pSeries systems. Figure 1.3 shows conceptually the levels of memory between the processor and disk storage in POWER4-based pSeries systems. Others using POWER3-II and RS64 IV processors do not have Level 3 caches. We have tried to show in Figure 1.3 the relative number of CPU cycles of latency among the various caches because the movement of data to the caches is very complex and the speeds of both memory and disk drives are changing very rapidly. Suffice to say that the objective of all caching schemes is to ensure that the processor is almost never waiting for either instructions or data to execute at its maximum rate. Caches and main memory are contained inside the system’s CEC. Disk storage may be internal to the server, in an I/O expansion drawer, or in a separate storage subsystem.

When the pSeries system is first turned on, information vital to an early startup and smooth operation is automatically copied from disk storage to the main memory. Once normal system operation is established, users can begin to do their work. During the course of this work, the user will start various computer programs. As each program is started, it is copied from disk storage to the main memory and then executed. Based on the work done by the user, the computer programs manipulate various sets of data that are also loaded from the disk storage to main memory. It doesn't take long to realize that the memory in a computer can quickly become filled with programs and data as the system is called up to do more and more work. In earlier days of computing, the main memory size limited the amount of work a computer could manage at any time. The number of programs that could be run concurrently, the number of users who share the system, and so on. In today's environment, a technique called virtual memory allows the need to squeeze all programs and data into main memory. In computers that support virtual memory, the computer basically feels out the main memory than it actually has. The largest of today's pSeries systems have 512 GB of main memory, an amount that only a few years ago would seemed impossible. Sixty-four pSeries systems allow 1 trillion TB of virtual memory to be addressed. Virtual memory allows more programs, data, and users to be simultaneously active on the system than can be supported in real memory without virtual memory. That is, allows you to make the most out of whatever size main memory you have.

Here's how virtual memory works. A user tells the computer to start a word-processing program. The computer would first attempt to load the needed portion of the word-processing program into main memory. If no space is left in main memory, some space will be made available by overwriting an inactive portion of some program or “swapping out” some inactive data to a temporary space in disk storage. The needed portion of the word-processing program can then be loaded into the available space and the user can begin typing. If the program that was overwritten or the data that was swapped out is needed again, it will be reloaded from disk storage to some other available main memory area. swapping programs and information between main memory and disk storage (robbing Peter to Paul and vice versa).

Virtual memory allows the maximum size program or combination of all programs and data to be limited by the combined amount of main memory and disk storage rather than the amount of main memory alone. The advantage of having this virtual memory hocus built into the pSeries hardware and AIX 5 operating system is that neither the programmers nor the users of it need to be concerned with paging. Virtual memory is a powerful system feature, but it comes at a price. The paging between disk and main memory is processing overhead that can reduce overall performance. A little paging will not appreciably hurt performance, but the more paging there is, the more system performance will be reduced. When the paging performed by a virtual memory system becomes excessive, the system is said to thrash, spending too much time paging.

The virtual memory concept is implemented in most of today to some degree. pSeries systems implement their virtual memory through a concept called single-level storage. This means that in pSeries systems, no distinction is made between disk storage and main memory. All storage appears to be one homogenous sea of main memory. This consistency provides for a simple and efficient virtual memory implementation for example. Other virtual memory implementations must create and manage separate address spaces, and they often treat programs differently than they do data.

# Symmetric Multiprocessor Implementation

The design of pSeries multiprocessor systems combines functions of both the processor and the AIX 5L operating system, with complex logic for accessing memory and I/O buses. The basic design of any SMP system (Figure 1.32) involves multiple processors (CPUs) accessing a common, shared set of resources (for example, memory, fixed disk, communication adapters, and operating system). The processors communicate with each other and main memory via a bus.

Each processor in the system will be performing separate jobs or running different programs at any point in time (for example, database access, terminal interaction, or network communication). Figure 1.32 gives you a look inside a symmetric multiprocessor system at a single point in time. It is important to say “single point in time” because, in a true multitasking environment, in the next few ticks of the system clock, these applications have an equal chance to be rescheduled on the same or other CPUs. The applications will also be swapped out when they have exhausted their time-slice to let other programs run.
