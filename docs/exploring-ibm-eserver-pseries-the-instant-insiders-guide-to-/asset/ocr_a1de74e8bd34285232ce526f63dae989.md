To help compare the commercial performance of pSeries systems, IBM has derived its metric, dubbed rPerf (for "relative performance"), which is an indicator of commercial throughput for pSeries and RS/6000 servers derived from an IBM-defined workload used in its analytical model. Figures 1.1a and 1.1b show the rPerf numbers for pSeries and RS/6000 servers, respectively. The pSeries 640 1-way server using the 375 MHz POWER3II processor and 4 MB of L2 cache is the reference system and has an rPerf value of 1.0. The p640 was selected as the reference system it was the entry-level system for the pSeries servers and offered a 1-way 375 MHz POWER3II processor option. The rPerf value should be used only to compare relative performance among pSeries servers. This ratio does not equate to any official TPC-C workload or results and should not be compared with competitive systems.

# A Closer Look

Many elements together provide the functions and performance of pSeries computers. Not only must each element be highly efficient, but each must be able to “keep up” with all other elements that make up the computer system. It doesn’t matter how fast a processor is, for example, the I/O subsystem is the “bottleneck” that limits the overall speed at which the computer can perform work. A high-speed Fibre Channel adapter will be handicapped if the expansion slot in which it resides is unable to keep up with information flow rates. pSeries designers use computer modeling and other tools to simulate various design approaches with the goal of achieving computer systems with balanced performance.
