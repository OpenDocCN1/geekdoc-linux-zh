pSeries Communications

The standard features and options of pSeries systems, along with the AIX 5L operating system and its extensions, provide users with flexibility to configure systems for various communications environments. However, this flexibility can also cause confusion when trying to determine which options and programs are needed for a particular environment. This chapter will help guide you through the communications options available for pSeries systems.

Chapter 2, "Options and Peripherals," examined some communications hardware options used with pSeries systems and provided a brief tutorial on communications interfaces and protocols. Chapter 3 looked at a few of the communications software offerings available with the AIX operating system. This chapter will examine some of the most popular communications environments and provide example configurations for each.

## Computer Communications—An Introduction

In today's fast-paced and connected world, the impact and importance of communications are obvious. For both personal and business reasons, we communicate with people all over the world using telephones and e-mail. For businesses, which are the customers for pSeries systems, it is vital that timely, accurate information be available to decision makers and employees be able to share information rapidly. It is also vital that business communications be secure so that personal information about customers and employees is kept confidential and a company's assets are protected. As improvements are made in communications within an organization, it is very likely that improvements in productivity and effectiveness will follow. Ironically, as an organization grows, it becomes more important and at the same time more difficult to maintain efficient, secure, and accurate communications—the very thing that facilitated growth in the first place. Communications difficulties grow with the size of the organization.

Today’s businesses, universities, research facilities, and government agencies are quickly finding customers in communications unequaled in significance. Bell invented the telephone. Communications can occur in several ways—between a server and the users at their personal computers (PCs), between two computers, or among a group of computers in a complex communications network. pSeries systems, together with AIX 5L and its extensions, provide the hardware features and software support needed for operation in almost any communications network.

## Distributed Computer Communications

In some cases, the computing needs of an organization can be satisfied by a very simple communications arrangement. Users work at PCs attached by a local area network (LAN) to a single pSeries server. For outside communications (e.g., to the Internet), the server is attached by an appropriate modem. Such an arrangement is adequate for small organizations where most computer users are at a single location. The needs of an organization require multiple systems, then a more complex communications network is required. For example, a retail chain may want a computer system at each retail location as well as a computer system at headquarters (Figure 4.1). As shown, all computer systems are joined through a communications network that allows them to easily move information (such as daily cash register receipts) from place to place as necessary. This is called a distributed computer network.

Benefits occur when you place (or distribute) the computer systems at the sites where they are needed. First, because all users are locally attached to their respective computer systems, they enjoy improved system performance (reduced response time) compared with relatively attached workstations, which are often slowed down by communications-line limitations.

Further, the distributed computer system can act to consolidate communications. This is especially true at remote locations with many users, since it avoids the need for a large number of communications lines to support all of the remote users directly. Instead, the remote users are locally attached by LAN to the distributed system at their location, and they communicate to the central site through the distributed system using a single communications line. Although a large distributed computer network is more difficult to manage than a single computer system, pSeries systems and AIX 5 are designed for such distributed environments. When the size of the network grows to hundreds of systems, possibly a heterogeneous mix of systems running other operating systems, the Tivoli management products provide additional network management tools to help ease the task. We will look at two of the types of distributed networks in which pSeries systems are used: pSeries distributed networks, and pSeries and zSeries distributed networks.

## pSeries Distributed Network

Multiple pSeries systems can be attached together through communications lines to create a distributed computer network. Our example distributed network consists of three small pSeries systems (e.g., pSeries 610), each distributed to a remote location, and a larger pSeries server (e.g., pSeries 670) at the organization's headquarters. Figure 4.2 shows an hardware and software configuration for the location and one of the remote locations. The remote configuration (pSeries 610) would be duplicated for every remote location. Further, the pSeries system at each end would be equipped with the appropriate local workstations to support the users at the respective locations. These are not shown in the figure so not to be confused with options needed to support the communications link.

The pSeries 610 at the remote location is equipped with an X.25 Interface adapter. This adapter, with a modem, allows the pSeries system to communicate over an X.25 network. Because the remote pSeries 610 system communicates only with the central pSeries 670 system, this is the only adapter needed.

![](img/29c52a1767a1e621ce6343faa9399737_271_0.png)

Figure 4.2. Example configuration used to communicate between distant pSeries computers.

The TCP/IP functions furnished with the AIX 5L operating system and the AIX 5L link/X.25 product provide the necessary programming to support the TCP/IP protocol.

At the central location, the pSeries 670 is in constant communication with all remote locations. It collects the summary information needed by headquarters to consolidate all remote location activity. In our example, one communications is used for each remote location. This means that the central pSeries system must have at least three X.25 interfaces, so the 4-Port Multiprotocol Communications Controller (#2947) is a logical choice. At the central site there is one modem for each communications line, for a total of three.

With communications configuration, the distributed pSeries systems can work together in many ways. First of all, the AIX 5L mail facilities are fully available, allowing any user to, for example, send a document to any other user attached to the distributed network. Further, the basic networking utilities included with the AIX 5L operating system allow users attached to the central p670 to sign on to remote p610 systems just if the users were physically attached to those systems. This can be specially convenient if a user of the central system provides technical support to other nodes, because he or she can now directly sign on any pSeries system in the network. These utilities also allow users to execute commands and run application programs on any pSeries system in the network or to freely exchange files between systems. Further, application programs can interact directly with other application programs to provide information to users without the users having to know where the needed information is located.

When least one of the pSeries systems in the network has the NetView product, more tools are provided to manage the network. Special messages called Simple Network Management Protocol (SNMP) Traps can be sent by any pSeries system (or any other open system) reporting the popular SNMP to report problems to NetView. Once a problem is detected, the Tivoli Framework provides tools with which to diagnose and fix the problem.
