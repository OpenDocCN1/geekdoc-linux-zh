# IBM @serverSeries—An Overview 85

The instruction and processing units in the processor allow a system to execute a great many programming instructions in a very small amount of time. However, it's not enough to make a processor architecture that offers high performance, users must also be able to efficiently move the data on the programming instructions are to operate between the processor and main memory. This is where the data cache unit comes in. The data cache unit operates like the instruction cache unit, only the data cache unit provides a temporary holding area for data needed during program execution rather than programming instructions. When a program requires data to operate, the data cache unit is first checked to see if the needed data has already been loaded. If the data cache contains the needed data (a cache hit), it can very quickly provide the needed information and dramatically boost system performance. If the data cache unit does not have the requested data, a cache miss occurs, which negatively impacts system performance. In the event of a cache miss, the needed data are automatically loaded from the slower main memory to the data cache unit.

In this way, the data cache unit continuously accumulates the data most likely to be needed during upcoming calculations, increasing the likelihood of cache hits. As with the ICU, the more cache hits there are, the better the system performance. Statistically speaking, the larger the data cache, the higher the percentage of cache hits and the higher the overall system performance. At this time this processor was in use, the base models of the RS/6000 family had a data cache 32 KB in size, whereas the larger models had a 64 KB data cache, accounting in part for their higher performance. Those models with 64 KB data cache were also designed to move twice as much information between main memory and the data cache. That is, the models with the 64 KB data cache path provide a more efficient path (for example, a 128-bit-wide data path vs. 64-bit-wide data path with the 32 KB data cache) between main memory and the data cache, which also serves to boost system performance. All pSeries and RS/6000 use a scheme set associativity to reduce the number of instruction and cache misses by allowing for more efficient sharing of the data cache among multiple programs running simultaneously.

Finally, the I/O Unit of the processor manages data between all input/output devices and the rest of the system. These includes things as the disks, communications adapters, and other devices such as tape drives. Often, the information will flow directly between the I/O device and main memory, called Direct Memory Access
