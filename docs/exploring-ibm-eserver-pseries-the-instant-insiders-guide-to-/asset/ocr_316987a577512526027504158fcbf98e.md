Virtual memory allows the maximum size program or combination of all programs and data to be limited by the combined amount of main memory and disk storage rather than the amount of main memory alone. The advantage of having this virtual memory hocus built into the pSeries hardware and AIX 5 operating system is that neither the programmers nor the users of any pSeries system need to be concerned with main memory. To them the system seems to have as much memory as they need, and they are never aware that information is constantly being swapped from main memory to disk storage and back again. The computer hardware and AIX 5L operating system efficiently manage this swapping (also called paging) automatically.

Virtual memory is a powerful system feature, but it comes at a price. The paging between disk and main memory is processing overhead that can reduce the overall system performance. A little paging will not appreciably hurt performance, but the more paging there is, the more system performance will be reduced. When the paging performed by a virtual memory system becomes excessive, the system is said to thrashing, or spending too much time paging between disk storage and main memory. Thrashing can be reduced by increasing the amount of main memory in the pSeries system through the installation of memory expansion options described in Chapter 2. Increasing the size of the main memory system will provide more room for programs and reducing the amount of virtual memory paging.

The virtual memory concept is implemented in most of today to some degree. pSeries systems implement their virtual memory scheme through a concept called single-level storage. This means that in pSeries systems, no distinction is made between disk storage and main memory. All storage appears to be one homogenous sea of main memory that is accessed in the same way. This consistency provides for a simple and efficient virtual memory implementation that is the same for programs, data, temporary holding areas, and so on. Other virtual memory implementations must create and manage separate address spaces, and they often treat programs differently than they do data, for example. The simplicity of the single-level storage design results in a consistent and more complete virtual memory system than that of most other implementations.
