The instruction and processing units in the processor allow a system to execute a great many programming instructions in a very small amount of time. However, it's not enough to make a processor architecture that offers high performance, users must also be able to efficiently move the data on the programming instructions are to operate between the processor and main memory. This is where the data cache unit comes in. The data cache unit operates like the instruction cache unit, only the data cache unit provides a temporary holding area for data needed during program execution rather than programming instructions. When a program requires data to operate, the data cache unit is first checked to see if the needed data has already been loaded. If the data cache contains the needed data (a cache hit), it can very quickly provide the needed information and dramatically boost system performance. If the data cache unit does not have the requested data, a cache miss occurs, which negatively impacts system performance. In the event of a cache miss, the needed data are automatically loaded from the slower main memory to the data cache unit.

In this way, the data cache unit continuously accumulates the data most likely to be needed during upcoming calculations, increasing the likelihood of cache hits. As with the ICU, the more cache hits there are, the better the system performance. Statistically speaking, the larger the data cache, the higher the percentage of cache hits and the higher overall system performance. At this time this processor was in use, the base models of the RS/6000 family had a data cache 32 KB in size, whereas the larger models had a 64 KB data cache, accounting in part for their higher performance. Those models with 64 KB data cache were also designed to move twice as much information between main memory and the data cache. That is, the models with the 64 KB data cache path provide a more efficient path (for example, a 128-bit-wide data path vs. 64-bit-wide data path with the 32 KB data cache) between main memory and the data cache, which also serves to boost system performance. All pSeries and RS/6000 use a scheme set associativity to reduce the number of instruction and cache misses by allowing for more efficient sharing of the data cache among multiple programs running simultaneously.

Finally, the I/O Unit of the processor manages data between all input/output devices and the rest of the system. These includes things as the disks, communications adapters, and other devices such as tape drives. Often, the information will flow directly between the I/O device and main memory, called Direct Memory Access (DMA). Other times, the program may directly control the information between the main processor and the I/O device, called programmed I/O.

The activities of the five processor elements are coordinated by an electronic signal called the system clock. The system clock is the heartbeat of the computer system, stepping the main processor through each step in the execution of a program. It is the time reference of the main processor and sets the pace for all processor activity. The speed at which the system clock runs is the system clock rate and is measured in millions or trillions of clock steps per second, or megahertz or gigahertz. For example, the RS/6000 Model 595 runs at 135 MHz and the Model 397 at 160 MHz. Today's POWER4+ processor runs at speeds up to 1.7 gigahertz (GHz). The principles just described for the original POWER architecture are still in use, although as we shall see, the POWER4 architecture is much more complex.

# PowerPC RS64 Microprocessors

Stages of development followed the original RS/6000 multipip RISC processor. These included the RISC Single Chip (RS) implementation and three PowerPC implementations. The PowerPC 601, 603, and 604/604 resulted from an alliance formed by IBM, Motorola, and Apple. The PowerPC designs introduced support for multiprocessing, power management features, and enhancements in pipelining.

Next came the PowerPC RS64 microprocessor (Figure 1.25), which was the RS/6000's first 64-bit processor. The RS64 was optimized for performance of commercial application OLTP (on-line transaction processing), which has a heavy demand on accessing large data sets from memory. As a result, its design focused on large cache sizes and data paths having high bandwidth and low latency rather than floating-point processing, as would be needed in a microprocessor designed primarily for scientific applications.

The RS64 processor had separate 4-way associative 64 KB caches for instructions and data. Also, it had an L2 cache controller and a dedicated 16-byte interface to a private external 2-way set-associative 4 MB L2 cache, with a separate 16-byte bus interface. The RS64 processor core was designed to optimize branch processing, and as part of the branch preprocessor function included a 4K branch history table and an integrated four-link stack. The RS64 had four execution units that could sustain a decode and execution rate of three instructions per cycle. All the arrays in the RS64 had redundancy and ECC for greater system availability.

Like PowerPC chips (except the 603), the RS64 was SMP enabled. It consumed about 225 watts of power at a clock rate of 125 MHz. Following the RS64, a family of superscalar processors called RS64 II, RS64 III, and RS64 IV have continued to be optimized for commercial workloads that place heavy demands on memory. They have very large cache sizes and data paths having high bandwidth and low latency.

The RS64 IV continues to be used in the pSeries 620 and 660 with operating frequencies of 500 MHz to 750 MHz. These chips are manufactured with IBM’s silicon-on-insulator technology, which reduces the capacitance along the boundaries, which in turn lowers signal to noise ratios and allows faster operation with less heat dissipation. Less heat means that less power is consumed and that reliability is improved. The RS64 IV technology uses a 1.8-volt power supply.

# POWER2 and POWER3 Microprocessors

The POWER2, IBM's initial superscalar implementation of the POWER architecture, was implemented initially in eight semicustom chips and later in a single-chip design. The POWER2 differed from the original implementation in several key aspects. First, the instruction cache was enlarged to 3 KB. The POWER2 implementation had dual fixed-point and dual floating-point units rather than dual fixed-point and single floating-point units. This design allowed the POWER2 implementation to execute up to two floating-point instructions and two fixed-point instructions in one cycle—double the capacity of the original implementation—and brought the total operations per cycle up to eight.

Other differences were a larger data cache (128 KB or 256 KB, depending on the model), some new instructions (for example, floating-point Sort and Convert to Integer) to improve efficiency for commonly needed operations, and higher system clock rates enabled by technology and design improvements.

IBM's POWER3 processors integrated the high-bandwidth and floating-point capabilities of its POWER2 architecture predecessor to a fully scalable 64-bit PowerPC SMP implementation. With excellent floating-point and integer performance, POWER3-based systems are particularly targeted at the HPC, high-analysis, graphics, graphical workstation, and entry-level server markets. To satisfy computation-intensive requirements, the POWER3 design contains a highly superscalar core that employs four execution units, fed by a high-bandwidth memory interface supporting four floating-point operations per cycle.

The POWER3 processor provides an instruction cache of 32 KB and a data cache of 64 KB. All caches are nonblocking. The instruction cache supports two outstanding misses, and the data cache supports up to four misses. Designed for high bandwidth, the POWER3 processor was implemented with a separate, independent 16-byte memory bus and a 32-byte L2 bus, with separate address, data, and control lines, achieving 6.4 GBps throughput to the L2 at 200 MHz.
