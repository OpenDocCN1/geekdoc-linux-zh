The chip also contains logic for power-on sequencing, self-test, performance monitoring, interfacing to the service processor (JTAG), error detection, and the like. The two POWER4 cores on the chip appear to the software as simply a 2-way SMP. Hence, the phrase “SMP on a chip” has sometimes been used to describe the POWER4 architecture.

The details of the POWER4 core are shown in Figure 1.27. The technical name for this architecture is “speculative superscalar-out-of-order design”. That means that the POWER4 processor is designed with multiple execution units (for floating-point, fixed-point, load/store, branch) and look-ahead logic to maximize the utilization of every clock cycle that the processor is never idle, waiting for data, instructions, or computation results. The “speculative” part means there is very complex logic that predicts which branches in a string of instructions will be taken or not and acts accordingly (calculating addresses, fetching information, etc.). This logic helps to maximize execution speed because the system does not have to wait and see the results of some calculation on which the conditional branch-to information depend before fetching.

The “out-of-order” description means that the POWER4 processor will, possible, execute instructions before all the preceding instructions in a sequence have been performed to keep all execution units busy. This logic is extremely complex, since dependencies between instructions (data, condition codes, etc.) must be considered. Some groups of instructions must be executed serially, and the POWER4 execution pipeline, shown in Figure 1.28, indicates the multiple cycles from instruction fetch (IF) and decoding to the mapping (MP) units, whose dependencies are determined, to the issue queues (ISS), and then through execution (EX), write-back (WB), and transfer (Xfer) to completion (CP).
