# pSeries Hardware Architecture

The internal organization of the hardware elements composing a pSeries system is known as the system's hardware architecture. The architecture of pSeries computers contributes a great deal to the performance offered by these systems. The architectures of pSeries servers are enhanced versions of the Reduced Instruction Set Computing architecture originally developed by IBM in the 1970s. As the name RISC implies, the instruction set or total number of instructions that can be executed within the computer is reduced compared with more traditional Complex Instruction Set Computing (CISC). Because the instructions in RISC systems are very simple, they can be executed using high-speed computer hardware within a very short period of time (for example, one clock cycle). Further, the simple instruction set of a RISC computer typically can be carefully employed to perform even complex functions in a more efficient manner.

This original RISC architecture was first used in the IBM RT system, which had limited success. The RS/6000 family employed IBM's second-generation RISC architecture, called the Performance Optimized With Enhanced RISC architecture. This architecture used a blend of the original RISC architecture and some traditional CISC concepts with an emphasis on doing multiple operations at the same time. The smallest piece of information the main processor and main memory use is called a bit. # The Processor

The processor is the heart of a computer system because it is the control center for information flow inside the computer. It is the main processor that does the data manipulation or “thinking” necessary to perform tasks for the user. The speed of the circuits making up the main processor, along with its architecture, determines the overall processing speeds achievable by the computer.

Many different (though compatible) RISC processor designs have been used in the RS/6000 and pSeries families. The following section gives an overview of the original implementation and describes some of the enhancements that have been made over the years as new generations of RISC processor technology were developed. Finally, there is a more detailed description of the latest IBM RISC processors—POWER4 and POWER4+.

# Original Implementation

Although the original implementation has been out of production for a long time, the concepts used in its architecture apply to all of the implementations that followed.

There are five basic elements in the original RS/6000 processor architecture, each made up of thousands of circuits packaged in several designed chips:

- 1. Instruction cache/branch processor
- 2. Fixed-point processor
- 3. Floating-point processor
- 4. Data cache
- 5. I/O unit

Figure 1.24 is a block diagram showing how these elements are organized to make the original RS/6000 hardware architecture. To see how this architecture can do multiple operations at the same time, let's quickly trace the flow of information through the system. It starts when the user executes a command to start a program, which causes the instructions of that program to be retrieved from disk storage and loaded into main memory (shown at the bottom of the diagram). After the program is loaded into main memory, the processor requests the first instruction (4 bytes) in the program. In compliance with the request, the first instruction is retrieved from the main memory along with the next several instructions (a total of 64 sequential bytes) and loaded into the Instruction Cache Unit (ICU). The instruction cache is a group of very high-speed memory circuits contained in the ICU chip. It is used as a temporary holding area (8 KB in size) for instructions that are likely to be next in line to be executed.

When the processor requests the next instruction, it first looks in the ICU. The next instruction needed will already have loaded into the ICU, eliminating the delay associated with getting the instruction from slower main memory. This is called a cache hit. Because the instruction cache can respond more quickly than the system's main memory, the system's performance is dramatically improved with every cache hit. If the needed instruction is not already loaded into the ICU (called a cache miss), another 64 bytes starting with the needed instruction are automatically loaded from the main memory into the ICU. In the case of a cache miss, loading the ICU takes longer than simply getting the needed instruction from main memory

Next, the branch processor component of the ICU examines each programming instruction in turn and independently executes any condition register or branch instructions. Condition register instructions manipulate the contents of working storage locations (condition registers) within the main processor that store information about the results of calculations performed earlier in the program. Branch instructions are commonly used type of programming instruction that direct the flow of the program, usually taking different paths depending on the contents of the condition register. Branch instructions that are executed within the ICU (while other operations are happening in the other processor elements) are said to occur in zero system cycles.

While the branch processor intercepts and executes branch and condition registers, the remaining instructions are fed to and executed by the fixed-point processor and the floating-point processor. The fixed-point processor performs mathematical and logical operations with things that don't have decimal points, such as numbers (for example, the integers 1, 5, and 6) and numeric representations of text (such as ASCII codes). These fixed-point instructions are common in almost any computing environment. The floating-point processor performs mathematical and logical operations (IEEE 754-1985) with things that have a decimal point (that is, numbers such as 53.254376, 4.6, and 3.3133). These floating-point instructions are common in engineering/scientific applications and others requiring sophisticated graphics.

For those who aren’t counting, that makes four independent operations going inside the system at the same time:

- 1. A branch instruction
- 2. A condition register instruction
- 3. A fixed-point instruction
- 4. A floating-point instruction

In fact, if the floating-point instruction happens to be the multiply-add (A × B + C) or the multiply-subtract (A × B – C) instruction, these can be counted as two floating-point operations, making a total of five operations being performed at once. This architecture is therefore said to be a superscalar implementation.
