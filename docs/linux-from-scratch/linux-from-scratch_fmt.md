
# Linux 从零构建指南

![](img/5d380cfe124be661028a03d22e6e9695_0_0.png)

## 产品描述

Linux From Scratch 描述了如何从已安装的 Linux 发行版开始，仅使用所需的软件源代码，从零开始创建自己的 Linux 系统的过程。

作者引言：

“在使用过许多不同的 Linux 发行版后……

这个在当时看来非常疯狂的想法似乎非常困难，有时几乎是不可能的。大多数问题的原因在于我对某些程序和步骤缺乏了解。在处理了各种依赖问题、编译问题等之后，一个手动构建的 Linux 系统被创建并完全运行。我将这个系统称为 LFS 系统，代表 Linux From Scratch（从零构建 Linux）。”

# 前言

## 谁会想读这本书

本书面向那些想要进一步了解 Linux 内部原理以及操作系统各个部分如何组合在一起的 Linux 用户。本书将引导你仅使用所需的软件源码，从零开始逐步创建一个属于你自己的自定义构建 Linux 系统。

这本书也面向那些希望摆脱现有的往往臃肿的商业版和免费发行版的 Linux 用户。使用现有的发行版还会迫使你使用它们所选择的文件系统结构、启动脚本结构等。通过这本书，你可以完全按照你喜欢的方式创建自己的结构和方法（这些可以基于本书提供的那些）。

此外，如果你有安全方面的考虑，你不希望依赖预编译的软件包。因此，你希望从零开始编译所有程序并自己安装它们。这可能是你想要构建自定义 Linux 系统的另一个原因。



这些只是人们想要构建自己的 Linux 系统的众多原因中的几个。如果你是其中之一，那么这本书就是为你准备的。

## 谁不想读这本书

不想从零开始构建整个 Linux 系统的用户可能不想读这本书。然而，如果你确实想了解在幕后发生了什么，特别是从开启电脑到看到命令提示符之间发生了什么，那么你应该阅读《从通电到 Bash 提示符》`P2B` `HOWTO`。这个 `HOWTO` 以与本书类似的方式构建一个精简系统，但它更多地关注于安装一个可启动的系统，而不是一个完整的系统。

要决定你是想读这本书还是 `P2B` `HOWTO`，你可以问自己一个问题：我的主要目标是获取一个自己构建的运行良好的 Linux 系统，并在过程中学习并构建系统中每个组件的作用，还是仅仅学习部分是我的主要目标？如果你想边构建边学习，请读这本书。如果你只想学习，那么 `P2B` `HOWTO` 可能是更好的阅读材料。

《从通电到 Bash 提示符》`HOWTO` 可以从 `http://learning.taslug.org.au/power2bash` 下载。

### 介绍

在使用过许多 Linux 发行版后，从未对其中任何一个感到满意。我不喜欢它们的安排。我意识到，当我对一个 Linux 系统完全满意时，我必须从零开始构建，理想情况下只使用源码。这个想法一度看起来是非常疯狂，有时是不可能的。大多数问题源于我对某些程序和程序的缺乏了解。在解决了各种依赖问题、编译问题后，一个自定义的 Linux 系统被创建并正常运行。我将这个系统命名为 `LFS`，意为 Linux From Scratch（从零开始的 Linux）。

# 第 2 章 重要信息

## 关于 `$LFS`

请仔细阅读以下内容：在本文中，你将经常看到变量名 `$LFS`。`$LFS` 必须始终替换为挂载包含 LFS 系统的分区的目录。如何创建和挂载该分区将在第 4 章中进行详细说明。在我的情况下，LFS 分区挂载在 `/mnt/lfs`。如果我读到必须运行此命令：`cp initab $LFS/etc`，如果我亲自读到并在某处看到 `$LFS`，我会假装我读的是 `/mnt/lfs`。如果我读到必须运行此命令：`cp initab $LFS/etc`，我实际上会运行：`cp initab /mnt/lfs/etc`



重要重要的是，无论你在哪里阅读它；无论是在提示符上输入的命令中，还是在你编辑或创建的某些文件中，都必须这样做。

如果你愿意，可以设置环境变量 `LFS`。这样你就可以直接输入 `$LFS` 而不是将其替换为 `/mnt/lfs` 之类的内容。这通过运行 `export LFS=/mnt/lfs` 实现。

如果我读到 `cp initab $LFS/etc`，我确实可以直接输入 `cp initab $LFS/etc`，shell 会自动将此命令替换为 `cp initab /mnt/lfs/etc`。

不要忘记始终设置 `$LFS` 变量。如果你没有设置该变量并在命令中使用它，`$LFS` 将被忽略，并将执行剩余的部分。在未设置 `LFS` 变量的情况下执行 `cp initab $LFS/etc` 命令，将导致 `initab` 文件复制到 `/etc` 目录，这将覆盖你系统的 `initab`。像 `initab` 这样的文件并不是多大问题，因为可以很容易恢复，但如果你在安装 C 库期间犯了这种错误，可能会严重破坏你的系统，如果你不知道如何修复它，你可能需要重新安装。

## 如何下载软件

在本文中，我假设你已经将下载的所有包存储在 `$LFS/usr/src` 某处。

我使用 `$LFS/usr/src/` 目录的习惯。在 `sources` 下，你会找到 0–9 目录以及通过 z 的目录。诸如 `sysvisint-2.78.tar.gz` 的包存储在 `$LFS/usr/src/sources/s/`。诸如 `bash-2.04.tar.gz` 的包存储在 `$LFS/usr/src/sources/b/`，以此此类推。你当然不需要遵循这个习惯，我只是举了一个例子。最好将包放在 `$LFS/usr/src` 之外，并将它们移动到子目录，这样我们就会有一个干净的 `$LFS/usr/src` 目录，可以在其中解压包并处理它们。

在实际开始对包进行任何操作之前，你需要先解压它。通常你会发现包文件被 tar 包并压缩了（你可以从 `.tar.gz` 或 `.tgz` 扩展名看出这一点）。我不会每次都写如何解压缩和提取 tar 档。我将在这一段告诉你如何这样做。你还可能遇到 `.bz2` 文件。这种文件使用 `bzip2` 程序进行 tar 包并压缩。`Bzip2` 比常用的 `gzip` 有更好的压缩率。为了使用 bz 存档，你需要安装 `bzip2` 程序。并不是每个发行版都带有该程序。如果没有，请使用你发行版的安装工具安装。

首先，通过运行进入 `$LFS/usr/src` 目录：

```bash
root:~# cd $LFS/usr/src
```

当你有一个压缩的文件，运行以下命令之一来解压，取决于文件名格式：

```bash
root:/usr/src# tar xfz filename.tar.gz
root:/usr/src# tar xfz filename.tgz
```

当你有一个压缩压缩的文件，运行以下命令来解压：

```bash
root:/usr/src# bzcat filename.tar.bz2 | tar xv
```

某些 tar 程序（大多数而非所有）经过了微调，可以使用 I 或 y 参数直接使用 bzip2 文件，这与处理 gzip 存档的 z 参数相同。

当你有一个 tar 包，运行以下命令来解压：

```bash
root:/usr/src# tar xvf filename.tar
```

存档解压后会在目录下创建一个目录（本文假设你在 `$LFS/usr/src` 目录下解压存档）。在继续安装说明之前，你需要进入该新目录。每本书要安装一个程序，都由你解压源码包。

安装包后，你可以对其做两件事。你可以删除包含源码的目录或保留它。如果你决定保留，对我没问题。但如果你在随后的章节中需要同一个包，需要在再次使用它之前删除该目录。如果不这样做，可能会遇到麻烦，因为使用了旧设置（适用于你普通 Linux 系统的设置，但并不总是适用于 LFS 系统）。

# 第 5 章 准备 LFS 系统

## 操作方法及原理

在本章中，我们将安装所有属于基础 Linux 系统的软件。完成本章后，你将拥有一个完全可以运行的 Linux 系统。剩余章节将涉及网络设置、创建启动脚本以及在 `lilo.conf` 中添加条目，以便你启动你的 LFS 系统。

本章中的软件将进行静态链接。这些程序将在下一章中重新安装并进行动态链接。先使用静态版本的原因是我们的普通的 Linux 系统与你的 LFS 系统可能未使用相同的 C 库（C Library）版本。如果第一部分的程序链接到旧版本的 C 库，那么这些程序在 LFS 系统上可能无法正常工作。

学习 Linux 运行机制的关键在于确切知道哪些包是做什么的，以及你或系统为什么需要它们。每个软件包的详细描述将位于该软件包的“安装”小节之后，并在附录 A 中提供。

我们即将开始安装第一组软件包。正如之前提到的，这些软件包将进行静态链接。

在开始之前，如果你计划使用 LFS 环境变量，请运行以下命令确保其已设置：

```
root:~# echo $LFS
```

### 安装 Bash

安装 Bash

运行以下命令安装 Bash：

```bash
root:bash-2.04# ./configure --enable-static-link \
> --prefix=$usr --disable-nls

```

#### 内容

Bash 软件包包含 `bash` 程序

#### 描述

Bash，即 Bourne–Again SHELL，是 Unix 系统上广泛使用的命令解释器。Bash 是一个从标准输入（键盘）读取内容的程序。你输入某些内容，程序将评估你输入的内容并对其进行处理，例如运行一个程序。

#### 描述

Binutils 软件包包含 `ld`, `ar`, `nm`, `objcopy`, `objdump`, `ranlib`, `size`, `strings`, `strip`, `c++filt`, `addr2line` 和 `nlmconv` 程序

#### 描述

`ld` 合并多个对象文件和归档文件，重定位它们的数据并连接符号引用。在构建用于运行的新编译程序时，最后一步通常是调用 `ld`。

#### `as`

`as` 主要用于汇编 GNU 编译器 `gcc` 的输出，以供链接器 `ld` 使用。

#### `ar`

`ar` 程序创建、修改和从归档中提取内容。归档是一个单一文件，它以结构形式持有一组文件，这种结构使得检索原始单个文件（称为归档成员）成为可能。

#### `nm`

`nm` 列出对象中的符号。

#### `objcopy`

`objcopy` 工具将对象文件的内容复制到另一个。`objcopy` 使用 GNU 库 BFD 来读写对象文件。它可以以与源文件不同的格式写入目标对象文件。

#### `objdump`

`objdump` 显示一个或多个对象文件的信息。选项控制显示哪些特定信息。这些信息对于正在开发编译工具的程序员最有有用，而不是对于那些只想让自己的程序编译并运行的程序员。

#### `ranlib`

`ranlib` 生成归档内容的索引并将其存储在归档中。索引列出了由归档中可定位对象文件成员定义的每个符号。

#### `size`

`size` 列出列表中每个对象文件 `objfile` 的节大小——以及总大小。默认情况下，每个对象文件或归档中的每个模块生成一行输出。

#### `strings`

对于每个文件，`strings` 会打印长度至少为 4 个字符（或程序选项指定的数量）且后跟着不可打印字符的可打印字符序列。默认情况下，它只打印对象文件中已初始化和加载部分的字符串；对于其他类型的文件，它会打印整个文件的字符串。

`strings` 主要用于确定非文本文件的内容。

#### `strip`

`strip` 从对象文件中丢弃所有或特定的符号。对象文件列表可能包含归档。必须提供一个对象文件。`strip` 修改参数中指定的文件，而不是以不同的名称写入修改后的副本。

#### `C++filt`

C++ 提供了函数重载，这意味着你可以编写同名的函数（只要每个函数接受不同类型的参数）。所有 C++ 函数名都被编码为低级汇编标签（此过程称为修饰/mangling）。`c++filt` 程序执行反映射：它将低级名称解码（反修饰）为用户级名称，以便链接器防止这些重载函数发生冲突。

#### `addr2line`

`addr2line` 将地址转换为名称。

#### `nlmconv`

`nlmconv` 将可定位文件转换为头文件。

### cp

### df

`df` 显示包含每个文件名参数的文件系统上可用的磁盘空间。如果没有提供文件名，则显示所有当前挂载文件系统的可用空间。

### ls, dir and vdir

`dir` 和 `vdir` 是 `ls`的不同版本，具有不同的默认输出格式。这些程序列每个文件或目录名称。目录内容按字母排序。对于 `ls`，如果标准输出是终端，文件默认按列列出并垂直排序；否则每行显示一个。对于 `dir`，文件默认按列列出并垂直排序。对于 `vdir`，文件默认以长格式列出。

### dircolors

`dircolors` 输出设置 `LS_COLOR` 环境变量的命令。`LS_COLOR` 变量用于更改 `ls` 及相关工具使用的默认颜色方案。

### du

`du` 显示每个参数以及目录参数的每个子目录使用的磁盘空间。

### install

`install` 复制文件并设置它们的权限模式，如果可能，还会设置它们的所有者和组。

### ln

### mkdir

### mkfifo

`mkfifo` 为每个给定名称创建 FIFO（先进先出文件）。

### mknod

`mknod` 用指定的文件名创建 FIFO、字符设备文件或块设备文件。

### mv

`mv` 根据给 `mv` 的参数将文件从一个目录移动到另一个目录或重命名文件。

### rm

`rm` 删除文件或目录。

### rmdir

`rmdir` 删除空空目录。

### sync

`sync` 强制将更改的块写入磁盘并更新超级块。

### touch

`touch` 将每个给定文件的访问和修改时间更改为当前时间。不存在的文件将创建空文件。

### 调试符号和编译器优化

大多数程序和库默认使用带有调试符号和 2 级优化级别（`gcc` 选项 `-g` 和 `-O2`）并针对特定 CPU 进行编译。在 Intel 平台上，软件默认是为 `i386` 处理器编译的。如果你不想在自己的机器以外的其他机器上运行软件，你可能希望更改默认编译器选项，以便它们以更高的优化级别编译、不带调试符号，并为你的特定架构生成代码。让我先解释一下什么是调试符号。



使用带有调试符号编译的程序意味着你可以通过调试器运行程序或库，并且调试器的输出将是用户友好的。这些调试符号还会显著增大程序或库的体积。

要从二进制文件（必须是 `a.out` 或 `ELF` 二进制文件）中移除调试符号，请使用 `strip --debug filename`。如果你需要从多个文件中移除调试符号，可以使用通配符（类似于 `strip --strip-debug SLFS/usr/bin/*`）。另一种更简单的方法是在编译程序时不带调试符号。大多数人可能永远不会在软件上使用调试器，因此通过省略这些符号，你可以节省大量的磁盘空间。

在使用这些调试符号之前和之后会有巨大的差异，以下是一些统计数据：

- 带有调试符号的动态二进制文件：1.2MB
- 不带调试符号的动态二进制文件：478KB
- 带有调试符号的 `/lib` 和 `/usr/lib`（`libc` 和 `gcc` 文件）：87MB
- 不带调试符号的 `/lib` 和 `/usr/lib`（`libc` 和 `gcc` 文件）：16MB

大小取决于使用了哪种编译器以及使用哪种 C 库链接动态程序，但如果你比较带和不带调试符号的程序，结果将是类似的。在我完成这一章并从所有 LFS 二进制文件中删除所有调试符号后，我找回了超过 102 MB 的磁盘空间。差异确实很大。

更改默认编译器选项的方法有几种。一种是编辑软件包中的 `Makefile` 文件，例如 `CFLAGS` 和 `CXXFLAGS`（一个设计良好的软件包使用 gcc 编译器选项和 CXX 编译器选项），并更改它们的值。`binutils`、`gcc`、`glibc` 等软件包在子目录中有许多 `Makefile` 文件，因此需要花费大量时间。相反，有一种更简单的方法：创建 `CFLAGS` 和 `CXXFLAGS` 环境变量。大多数脚本都会读取 `CFLAGS` 和 `CXXFLAGS` 变量并在 `Makefile` 中使用。少数软件包不遵循这一惯，这些软件包需要手动编辑。

在下一节中，我们将创建 `SLFS/root/bash_profile`，其中包含以下优化：

```
CFLAGS=-O3 -mcpu=xxx -march=xxx
CXXFLAGS=$CFLAGS
```

### 描述

`Bison` 是一个解析器生成器，是 `YACC` 的替代品。`YACC` 代表 Yet Another Compiler Compiler（又一个编译器编译器）。什么是 `Bison`？它是一个用于生成能够分析文本文件结构的程序。你不需要编写实际的程序，只需指定各项应如何连接，并根据这些规则构建出一个分析文本文件的程序。

在很多需要结构的示例中，计算器就是其中之一。

给定字符串：

`1 + 2 * 3`

你可以轻松地得到结果 7。为什么？因为有了结构。你知道如何解释这个字符串。计算机并不知道，而 `Bison` 是一个工具，通过以以下方式向编译器呈现字符串来帮助它理解：

```
+
/\
* 1
/\
2 3
```



你从树的底部开始，遇到数字 2 和 3，它们由乘法符号连接，因此计算机将 2 乘以 3。该乘法的结果被记录下来，计算机看到的下一个内容是 `2*3` 的结果和数字 1，它们由加号符号连接。在之前的结果基础上加上 1 得到 7。在计算时，最复杂的计算可以拆分为这种树状格式，计算机只需从底部开始逐向上工作，即可得到正确答案。当然，Bison 不仅用于计算器。

Binutils 软件包包含 `ld`, `ar`, `nm`, `objcopy`, `objdump`, `ranlib`, `size`, `strings`, `strip`, `c++fitt`, `addr2line` 和 `nlmconv` 程序

#### ld

`ld` 连接多个对象文件和归档，重定位它们的数据并连接符号引用。

#### as

`as` 主要用于汇编 GNU C 编译器 `gcc` 的输出，供链接器 `ld` 使用。

#### ar

`ar` 程序创建、修改和提取归档。归档是一个包含其他文件的单个文件，其结构使得能够检索原始单个文件（称为归档成员）。

#### nm

`nm` 列出对象文件中的符号。

#### objcopy

`objcopy` 工具将一个对象文件的内容复制到另一个文件中。`objcopy` 使用 GNU BFD 库来读取和写入对象文件。它可以以不同于源对象文件的格式写入目标对象文件。

#### objdump

`objdump` 显示一个或多个对象文件的信息。选项用于控制显示哪些特定信息。这些信息对于正在编写编译工具的程序员来说最有用，而对于只想让自己的程序编译并运行的程序员来说则不然。

#### ranlib

`ranlib` 生成归文件内容的索引并将其存储在归文件中。该索引列出了归文件中每个作为可重定位对象文件的成员所定义的每个符号。

#### size

`size` 列出其列表中每个对象文件（objfile）的节段大小以及总大小。默认情况下，每个对象文件或归档中的每个模块都会生成一行输出。

#### strings

对于每个文件，`strings` 会打印长度至少为 4 个字符（或程序选项指定的数字）且后跟一个不可打印字符的可打印字符序列。默认情况下，它只打印对象文件中已初始化和加载段的字符串；对于其他类型的文件，它会打印整个文件的字符串。

`strings` 主要用于确定非文本文件的内容。

#### strip

`strip` 从对象文件中丢弃所有或特定的符号。对象文件列表可能包含归文件。必须至少给出一个对象文件。`strip` 修改参数中指定的文件，而不是以不同的名称写入修改后的副本。

#### C++filt

C++ 语言提供了函数重载，这意味着你可以编写同名的函数（只需每个函数带有不同类型的参数）。所有 C++ 函数名都被编码为低级汇编标签（此过程称为修饰/mangling）。`c++filt` 程序执行反向映射：它将低级名称解码（去修饰）为用户级名称，以便链接器防止这些重载函数发生冲突。

#### addr2line

`addr2line` 将程序地址转换为文件名和行号。给定一个地址和一个可执行文件，它使用可执行文件中的调试信息确定与给定地址相关的文件和行号。

#### nlmconv

`nlmconv` 将可重定位对象文件转换为 NetWare 可加载模块（NLM）文件，可选地读取头文件以获取 NLM 头信息。

安装 Ldso

运行以下命令安装 Ldso：

```
root:ld.so-1.9.9# cd util
root:util# make lddconfig
root:util# cp ldd /bin
root:util# cp lddconfig /sbin
root:util# cd ../
root:man# cp ldd.1 /usr/share/man/man1

root:man# rm /usr/bin/ldd

```

"`-r`" 命令用于让 `bash` 忘记之前执行过的命令的位置。如果你之前执行过 `ldd`，`bash` 期望在 `/usr/bin` 中找到它。由于我们将其移动到了 `/bin`，因此需要清除缓存，以便在你想要执行它时 `bash` 能在 `/bin` 中找到它。

你可能注意到我们没有对该软件包使用编译器优化。原由于是覆盖 `CFLAGS` 变量会导致编译问题。你必须编辑 `Config.mk` 文件并为 `CFLAGS` 变量添加适当的值，然后编译该包。如果你想这样做，随你的意。不过我不认为这值得麻烦。`ld` 和 `ldd` 程序通常很少使用。

#!/bin/sh
# Begin /etc/init.d/functions
COL=70
SET_COL="echo -en \033${COL}G"
NORMAL="echo -en \033[0;39m"
SUCCESS="echo -en \033[1;32m"
FAILURE="echo -en \033[1;31m"
evaluate_retval()
{
  if [ $? = 0 ]; then
    print_status success
  else
    print_status failure
  fi
}
print_status()
{
  if [ $# = 0 ]; then
    echo "Usage: print_status {success|failure}"
    exit 1
  fi
  case "$1" in
    success)
      $SET_COL
      echo -n "["
      $SUCCESS
      echo -n "OK"
      $NORMAL
      echo -n "]"
      ;;
    failure)
      $SET_COL
      echo -n "["
      $FAILURE
      echo -n "FAILED"
      $NORMAL
      echo -n "]"
      ;;
  esac
}
loadproc()
{
  if [ $# = 0 ]; then
    echo "Usage: loadproc {program} [signal]"
    exit 1
  fi
  base='basename $1'
  pidlist=`pidof -o $$ -o PID -o %PPID -x $base`
  pid=""
  for apid in $pidlist
  do
    if [ -d /proc/$apid ]; then
      pid="$pid $apid"
    fi
  done
  if [ ! -n "$pid" ]; then
    evaluate_retval
  else
    print_status failure
  fi
}
killproc()
{
  if [ $# = 0 ]; then
    echo "Usage: killproc {program} [signal]"
    exit 1
  fi
  base='basename $1'
  if [ -n "$2" ]; then
    runlevel=$2
  else
    runlevel=1
  fi
  pidlist=`pidof -o $$ -o PID -o %PPID -x $base`
  pid=""
  for apid in $pidlist
  do
    if [ -d /proc/$apid ]; then
      pid="$pid $apid"
    fi
  done
  if [ -n "$pid" ]; then
    if [ "$runlevel" = 1 ]; then
      kill -TERM $pid
      if ps -h $pid >/dev/null 2>&1; then
        :
      fi
    else
      kill -KILL $pid
    fi
    if ps -h $pid >/dev/null 2>&1; then
      print_status failure
    else
      rm -f /var/run/$base.pid
      print_status success
    fi
  fi
}
reloadproc()
{
  if [ $# = 0 ]; then
    echo "Usage: reloadproc {program} [signal]"
    exit 1
  fi
  base='basename $1'
  if [ -n "$2" ]; then
    runlevel=$2
  else
    runlevel=1
  fi
  pidlist=`pidof -o $$ -o PID -o %PPID -x $base`

      kill -TERM $pid
      if ps -h $pid >/dev/null 2>&1; then
        :
      fi
    else
      kill -KILL $pid
    fi
  fi

# 创建 setclock 脚本

以下脚本仅在你的硬件时钟（也称为 BIOS 或 CMOS 时钟）未设置为 GMT 时间时供实际使用。推荐的设置是将硬件时钟设置为 GMT，并使用 `/etc/localtime` 符号链接将时间转换为本地时间。但如果一个不支持不支持 GMT 时钟的操作系统（最著名的是微软操作系统），你可能希望将时钟设置为本地时间，以便在这些操作系统上正确显示时间。此脚本会将内核时间重置为硬件时钟，而不转换 `/etc/localtime` 符号链接。

即使你的硬件时钟已设置为 GMT，如果你想在系统上使用此脚本，请将下面的 `UTC` 变量更改为 1

```bash
#!/bin/sh
# Begin /etc/init.d/setclock
source /etc/init.d/functions
source /etc/sysconfig/clock
CLOCKPARAMS="--hctosys"
case "$UTC" in
  yes)
    CLOCKPARAMS="$CLOCKPARAMS -u"
    ;;
esac
echo -n "Setting clock..."
/sbin/hwclock $CLOCKPARAMS
evaluate_retval
# End /etc/init.d/setclock
```

创建一个新文件 `/etc/sysconfig/clock` 并包含以下内容：

```bash
# Begin /etc/sysconfig/clock
UTC=1
# End /etc/sysconfig/clock
```

如果你的硬件时钟（也称为 BIOS 或 CMOS 时钟）未设置为 GMT 时间，请将 `/etc/sysconfig/clock` 文件中的 `UTC` 变量设置为 0（零）。

# Bison

Bison 是一个解析器生成器，是 YACC 的替代品。YACC 的是“又一个编译器编译器”（Yet Another Compiler Compiler）。那么 Bison 是什么呢？它是一个用于生成分析文本文件结构的程序。你不需要编写实际程序，只需指定内容应该如何连接，程序就会根据这些规则构建出一个分析文本文件的程序。

在很多场景下都需要用到结构，其中之一就是计算器。

给定字符串：

```
1 + 2 * 3
```

你可以很容易地得到结果 7。为什么？因为有了结构。你知道如何解释这个字符串。计算机并不知道，而 Bison 是一个工具，它通过以以下方式向编译器呈现字符串来帮助计算机理解：

```
+
/\ 
  * 1
/\ 
  2 3
```

你从树的底部开始，会遇到数字 2 和 3，它们通过乘法符号连接，计算机将 2 乘以 3。乘法的结果被记录，计算机看到的下一个内容是 2*3 的结果和数字 1，它们通过加法符号连接。在上一个结果上加上 1 得到 7。在进行最复杂的计算时，可以以这种树状格式进行分解，计算机只需从底部开始逐层向上，即可得到正确答案。当然，Bison 不仅用于计算器。

# Sysvinit

## 目录

Sysvinit 软件包包含 `pidof`, `last`, `lastb`, `mesg`, `utmpdump`, `wall`, `halt`, `init`, `killall5`, `poweroff`, `reboot`, `runlevel`, `shutdown`, `sulogin` 和 `telinit` 程序。

## 描述

### pidof

`pidof` 查找指定命名程序的进程 ID (pids)，并将这些 ID 打印到标准输出。

### last

`last` 反向搜索 `/var/log/wtmp` 文件（或由 `-f` 标志指定的文件），显示自该文件创建以来所有登录（注销）的用户列表。

### lastb

`lastb` 与 `last` 相同，不同之处在于默认显示 `/var/log/btmp` 文件的日志，该文件包含了所有错误的登录尝试。

### mesg

`mesg` 控制其他对你终端的访问。它通常用于允许或禁止其他用户写入你的终端。

### utmpdump

`utmpdump` 以用户友好的格式将文件（通常为 `/var/run/utmp`）的内容打印到标准输出。

### wall

`wall` 向所有 `mesg` 权限设置为 yes 的登录用户发送消息。

### halt

`halt` 在 `/var/log/wtmp` 文件中记录系统已关闭，然后告诉内核停止、重启或关机系统。如果在系统不在运行级别 0 或 6 的情况下调用 `halt` 或 `reboot`，则将调用 `shutdown`（带有 `-h` 或 `-r` 标志）。

### init

`init` 是所有进程的父进程。它的主要作用是从存储在 `/etc/inittab` 文件中的脚本创建进程。该文件通常包含一些条目，导致 `init` 在用户可以登录的每一行生成 `getty`。它还控制任何特定系统所需的自主进程。

### killall5

`killall5` 是 SystemV 的 `kill` 命令。它向除自身会话进程外的所有进程发送信号，因此它不会杀死运行该脚本的 shell。

### poweroff

`poweroff` 等同于 `shutdown -h -p now`。它停止计算机并关闭电源（当使用兼容 APM 的 BIOS 且内核中启用 APM 时）。

### reboot

`reboot` 等同于 `shutdown -r now`。它重启计算机。

### runlevel

`runlevel` 读取系统 `utmp` 文件（通常为 `/var/run/utmp`）以定位运行级别记录，然后将之前的和当前的系统运行级别打印到标准输出，中间用单个空格分隔。

### shutdown

`shutdown` 以安全的方式关闭系统。所有登录用户都会收到系统即将关闭的通知，并阻塞登录。

### login

`init` 在系统进入单用户模式时调用 `slogin`（这是通过 `/etc/inittab` 中的条目实现的）。当 `init` 从启动监视器（例如 LILO）接收到 `-b` 标志时，它也会尝试执行登录。

### telinit

`telinit` 向 `init` 发送相应的信号，告诉它更改到哪个运行级别。

### elvtune

# Syslogd

Syslogd 软件包包含 `klogd` 和 `syslogd` 程序。

## 描述

### klogd
`klogd` 是一个系统守护进程，用于拦截并记录 Linux 内核消息。

### syslogd
`Syslogd` 提供了许多现代程序使用的日志类型。每条日志消息至少包含一个时间和主机名字段，通常还包含程序名称字段，但这取决于日志记录程序的可靠性。

# Sysvinit

Sysvinit 软件包包含 `pidof`, `last`, `lastb`, `mesg`, `utmpdump`, `wall`, `halt`, `init`, `killall5`, `poweroff`, `reboot`, `runlevel`, `shutdown`, `sulogin` 和 `telinit` 程序。

## 描述

### pidof
`Pidof` 查找指定命名程序的进程 ID (pids)，并将这些 ID 打印到标准输出。

### last
`last` 反向搜索 `/var/log/wtmp` 文件（或由 `-f` 标志指定的文件），显示自该文件创建以来所有登录（注销）的用户列表。

### lastb
`lastb` 与 `last` 相同，不同之处在于默认显示 `/var/log/btmp` 文件的日志，该文件包含了所有错误的登录尝试。

### mesg
`Mesg` 控制其他对你终端的访问。它通常用于允许或禁止其他用户写入你的终端。

### utmpdump
`utmpdump` 以用户友好的格式将文件（通常为 `/var/run/utmp`）的内容打印到标准输出。

### wall
`Wall` 向所有 `mesg` 权限设置为 yes 的登录用户发送消息。

### halt
`Halt` 在 `/var/log/wtmp` 文件中记录系统已关闭，然后告诉内核停止、重启或关机系统。如果在系统不在运行级别 0 或 6 的情况下调用 `halt` 或 `reboot`，则将调用 `shutdown`（带有 `-h` 或 `-r` 标志）。

### init
`Init` 是所有进程的父进程。它的主要作用是从存储在 `/etc/inittab` 文件中的脚本创建进程。该文件通常包含一些条目，导致 `init` 在用户可以登录的每一行生成 `getty`。它还控制任何特定系统所需的自主进程。

### killall5
`killall5` 是 SystemV 的 `kill` 命令。它向除自身会话进程外的所有进程发送信号，因此它不会杀死运行该脚本的 shell。

### poweroff
`poweroff` 等同于 `shutdown -h -p now`。它停止计算机并关闭电源（当使用兼容 APM 的 BIOS 且内核中启用 APM 时）。

### reboot
`reboot` 等同于 `shutdown -r now`。它重启计算机。

### runlevel
`Runlevel` 读取系统 `utmp` 文件（通常为 `/var/run/utmp`）以定位运行级别记录，然后将之前的和当前的系统运行级别打印到标准输出，中间用单个空格分隔。

### shutdown
`shutdown` 以安全的方式关闭系统。所有登录用户都会收到系统即将关闭的通知，并阻塞登录。

### sulogin
`init` 在系统进入单用户模式时调用 `sulogin`（这是通过 `/etc/inittab` 中的条目实现的）。当 `init` 从启动监视器（例如 LILO）接收到 `-b` 标志时，它也会尝试执行登录。

### telinit
`telinit` 向 `init` 发送相应的信号，告诉它更改到哪个运行级别。

`cal` 命令用于显示日历。默认情况下，它显示当前月份的日历。如果提供了 `month` 和 `year` 参数，它将显示指定月份和年份的日历。

**示例：**

```
cal 7 2025
```

显示 2025 年 7 月的日历。



# Syslogd
目录

Syslogd 软件包包含 `klogd` 和 `syslogd` 程序。

### 描述
### klogd

`klogd` 是一个系统守护进程，用于拦截并记录 Linux 内内核消息。

### syslogd

`Syslogd` 提供了许多现代程序使用的日志类型。每条日志消息至少包含一个时间和主机名字段，通常还包含程序名称字段，但这取决于日志记录程序的可靠性。

# Sysvinit
目录

Sysvinit 软件包包含 `pidof`, `last`, `lastb`, `mesg`, `utmpdump`, `wall`, `halt`, `init`, `killall5`, `poweroff`, `reboot`, `runlevel`, `shutdown`, `sulogin` 和 `telinit` 程序。

### 描述
### pidof

`Pidof` 查找指定命名程序的进程 ID (pids)，并将这些 ID 打印到标准输出。

### last

`last` 反向搜索 `/var/log/wtmp` 文件（或由 `-f` 标志指定的文件），显示自该文件创建以来所有登录（注销）的用户列表。

### lastb

`lastb` 与 `last` 相同，不同之处在于默认显示 `/var/log/btmp` 文件的日志，该文件包含了所有错误的登录尝试。

### mesg

`Mesg` 控制其他对你终端的访问。它通常用于允许或禁止其他用户写入你的终端。

### utmpdump

`utmpdump` 以用户友好的格式将文件（通常为 `/var/run/utmp`）的内容打印到标准输出。

### wall

`Wall` 向所有 `mesg` 权限设置为 yes 的登录用户发送消息。

### halt

`Halt` 在 `/var/log/wtmp` 文件中记录系统已关闭，然后告诉内核停止、重启或关机系统。如果在系统不在运行级别 0 或 6 的情况下调用 `halt` 或 `reboot`，则将调用 `shutdown`（带有 `-h` 或 `-r` 标志）。

### init

`Init` 是所有进程的父进程。它的主要作用是从存储在 `/etc/inittab` 文件中的脚本创建进程。该文件通常包含一些条目，导致 `init` 在用户可以登录的每一行生成 `getty`。它还控制任何特定系统所需的自主进程。

### killall5

`killall5` 是 SystemV 的 `kill` 命令。它向除自身会话进程外的所有进程发送信号，因此它不会杀死运行该脚本的 shell。

### poweroff

`poweroff` 等同于 `shutdown -h -p now`。它停止计算机并关闭电源（当使用兼容 APM 的 BIOS 且内核中启用 APM 时）。

### reboot

`reboot` 等同于 `shutdown -r now`。它重启计算机。

### runlevel

`Runlevel` 读取系统 `utmp` 文件（通常为 `/var/run/utmp`）以定位运行级别记录，然后将之前的和当前的系统运行级别打印到标准输出，中间用单个空格分隔。

### shutdown

`shutdown` 以安全的方式关闭系统。所有登录用户都会收到系统即将关闭的通知，并阻塞登录。

### slogin

`init` 在系统进入单用户模式时调用 `slogin`（这是通过 `/etc/inittab` 中的条目实现的）。当 `init` 从启动监视器（例如 `LILO`）接收到 `-b` 标志时，它也会尝试执行登录。

### telinit

`telinit` 向 `init` 发送相应的信号，告诉它更改到哪个运行级别。
