Let's deconstruct this script, so you can see what happened to the original value and why it's still there, even though you exported a different value for $SCHEESE. Let's take the script line by line:

+   ► **Line 1**—The shebang that sets which shell to use
+   ► **Line 2**—A comment reminding you what the filename is
+   ► **Line 3**—The echo of the original value of $SCHEESE
+   ► **Line 4**—The tricky export of the new value for $SCHEESE
+   ► **Line 5**—The incorporation of $SCHEESE as the value for STYPE
+   ► **Line 6**—An echo showing that the new values work
+   ► **Line 7**—An echo of the damning evidence, or so it appears

The key to all this tomfoolery with variable values and exporting of those values is to remember that the use of the export command makes the exported variable and its value available to the current shell and all subshells. In other words, when you run the script, it runs in a subshell of the current shell, which is why the original value for $SCHEESE is available to the script. However, when you exit the script (and the subshell), the exported value of $SCHEESE declared within the script goes away with the subshell, leaving the original value of $SCHEESE.

> **ALERT** This concept is key for the exam. You will be tested on your knowledge of how subshells and variable exports work. Many mistake the export of a variable as being the equivalent to making that variable available throughout the system, when it's really available only for the current shell and subshells.
