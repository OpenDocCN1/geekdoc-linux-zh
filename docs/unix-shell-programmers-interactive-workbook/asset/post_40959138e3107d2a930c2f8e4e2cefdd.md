- * What happens if you assign a value with a fraction to an integer?
Answer:Your interaction should look like the following:
```
[0000]: integer i j k
[0001]: float x y z
[0002]: i=3.5 j=4.9 k=99.999
[0003]: x=3.5 j=$j k=$k x=$x y=$y z=$z
[0004]: print i=$i j=$j k=$k x=$x y=$y z=$z
i=3 k=4 z=9
```

The float variables, x, y, and z retain their fractional parts, but not how large the fractional part of an integer variable, the shell silently drops the fractional part. The fraction is not rounded up, it is simply truncated. Also, because the range of a float variable is much larger than an integer variable, there is a possibility that integer overflow will occur, leaving the integer variable with an incorrect value.

> The shell does not indicate when overflow occurs; it just leaves you the wrong answer, so you need to be careful about this possibility when you write your code.

What happens if you assign the value of a string variable, such as m n, to integer or float variables?
Answer:Your interaction should look like the following:
```
[6009]: m=3.7 n=Howdy! i=$m j=$n x=$m y=$n
sh: Howdy! arithmetic syntax error
[6010]: print m=$m n=$i i=$j j=$j x=$s y=$y
m=3.7 n=Howdy! i=3 j=0 x=3.7 y=0
[6011]:
```

If n, the variable has a value that doesn't look like a number or valid arithmetic expression, the shell assigns value zero to numeric variable and generates an error (Arithmetic expressions are covered in the next exercise). However if m, the variable has a value that looks like a number (or arithmetic expression), the shell assigns the value of that number to the numeric variable. If the string looks like a number with fractional part and the variable receiving the value is an integer, the fraction is lost.

![](img/694fa9f0320e707804a4c650b96a09b4_293_0.png)

> Avoid mixing string and numeric variables.

![](img/694fa9f0320e707804a4c650b96a09b4_293_1.png)

The shell is very flexible letting you intermix string and numeric variables, which makes shell programming much easier than conventional languages like C, C++, and Java in which every variable must have declared type, and the rules for what can be assigned to what are rigid. The tradeoff is that it's relatively easy to make mistakes in shell programs if you forget what variables hold types.


- f) What bases were used to display the values of i and j?
Answer:Your interaction should look like the following:
```
[6016]: typeset -i i=20
[6017]: typeset -i16 j=20
[6018]: print i=$i j=$j

[6019]:
```

The number after the -i is the radix that the shell to use when displaying the value of the integer. Decimal 20 in binary is 10100 (1*16 + 0*8 + 1*4 + 0*2 + 0*1), which the shell displays as 2#10100. The hexadecimal representation of 20 is 14 (1*16 + 4*1), which the shell displays as 16#14. You can use numbers between 2 and 64 for the radix.

# Lab 6.1: Typed Variables and Scope

```
[6020]: print i=$i j=$j
i=20 j=20
[6021]:
```

The values of the two variables are both $20_{10}$, regardless of the radix specified in the typeset command. In the code here, the typeset command takes away the radix specification for the two variables without changing their values. When you print the variables, the shell uses the default radix, 10.

```
typeset -F3 x=1.23456
print x=$x
typeset -F2 x
print x=$x
typeset -F9 x
print x=$x
```

- h) What does the digit after the F do to the value, and how is it displayed?
Answer:Your interaction should look like the following:
```
[6021]: typeset -F3 x=1.23456
[6022]: print x=$x
x=1.235
[6023]: typeset -F2 x
[6024]: print x=$x
x=1.23
[6025]: typeset -F9 x
[6026]: print x=$x
x=1.234560000
[6027]:
```

The digit after the F determines how many decimal places the shell will use when it prints the value of the variable. The number of places does not affect the value of the variable, only how it is displayed. Thus, for example, line 6022 shows that the shell rounds the displayed variable according to the normal rounding rules of arithmetic. Then line 6026 shows that the value of the variable was not changed, even after truncating it on line 6023.

> The "digit" after the F can be any number you want, but the computer's accuracy is limited, so that too many digits will result in a lot of trailing zeros. Still, this is a valuable feature if you want to print columns of numbers that line up with one another.
