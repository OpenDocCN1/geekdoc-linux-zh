Run the following commands:

print ?(re)read*

- c) What printed, and why?

Answer: Your interaction should look like the following:

```
[1025]: print ?(re)read*
read rereaded rereading
[1026]: print +(re)read*
rereaded rereading rereaded rereading
[1027]: print @(re)read*
rereaded rereading
[1028]: print *(re)read*
read reading rereaded rereading rereaded \
rereading
[1029]:
```

Line 1025 prints each file name that starts with zero or one occurrences of "re," followed by "read," so it prints "read" and "reading," as well as the two words prefixed by "re," but it does not print the names that start with "rere."

Line 1026 matches one or more occurrences of "re," followed by "read," so it prints everything that starts with "reread," which eliminates "read," "reading," and all the "un" words.

Line 1027 matches exactly one occurrence of "re," followed by "read," so it prints the two names shown, but not words that start with "read," "rere," or "un."

### 10.2.2 USE SUBSTITUTION FOR THE VALUE OF A PARAMETER

Here is the first part of a script that illustrates the same kind of command substitution as the previous exercise, as well as providing a parameter to the script:

```bash
#!/bin/bash
# Usage: s1022 [report_name]
# Where "report_name" is the name of a text file to start or continue editing.
# The user may not start a new report until a previous one has been completed.

current_report=$(cat ~/.s1022_currentfile)

case $# in
  0) [[ $current_report == "" ]] && (
      print -u You must give the name of a new report to start.
      return 1
    )
    ;;
  1) [[ $current_report != "" ]] && $current_report != "$1" ]] && (
      cat << END
You are already working on "$current_report", so you may not start a report named "$1".
If this is not correct, remove the file ~/.s1022_currentfile.
END
      return 1
    )
    print --$1 |> ~/.s1022_currentfile
    ;;
  *)
    print -u Usage: s1022 [report name]
    return 1
    ;;
esac

# Now edit the report ...
vi -- "$(cat ~/.s1022_currentfile)" 1>/dev/tty
```

a) What happens the first time you run the script if you do not provide a file name?
b) What happens if you run the script with a file name, and there is no file named ~/.s1022_currentfile?
c) What happens if you run the script and do not provide a file name but have already run it once with a file name?
d) What happens if you run the script with a file name that is not the same as the contents of ~/.s1022_currentfile?
