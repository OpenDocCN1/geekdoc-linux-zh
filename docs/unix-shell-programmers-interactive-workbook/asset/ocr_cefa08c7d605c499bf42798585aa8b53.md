If your error message says mn: not found instead of mn: line 1: p: not found, it means the shell couldn't find the command instead of the p command as expected.This problem could be because (1) you didn't use the chmod +x to make the script executable, (2) you used a different name for the command when you built it, (3) your current directory is not one of the places the shell looks to for commands, or (4) there is an invalid 'she-bang' (#!) in the first line of your script. In the case of (3), you can use /mn to run the command, and in the case of (4), you should refer to Chapter 1, “Setting Up,” to see how to use she-bang, if you need it at all.

Why doesn't the script work? Explain the error message.

Answer: The format of the message is <command name>: <line number>: <command name>: <message>. The shell reports that the first line of the command file mn contains the command p but the shell cannot find a command by name to execute.

In other words, the alias command for p that you typed in before does not apply to command lines inside the script.

How can you get p to work as an alias for print inside your script?

Answer:You would have to put the alias p=print command inside the script file.

Aliases are used to save typing during interactive sessions. Inside scripts, you should use the names of actual commands instead.

Why was the script called mn?

Answer: It's a UNIX-style command name, short for “my name.” whence -a ls to see where the ls external command is in your file system.

What are the results?

Answer:Your results should be similar to the following:

```
$ -a ls
ls is a tracked alias for /bin/ls
$
```
