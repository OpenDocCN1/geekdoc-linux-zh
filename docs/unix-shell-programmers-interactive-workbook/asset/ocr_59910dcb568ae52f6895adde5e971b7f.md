+   e) What is inefficient about the second version compared with the first version?

Answer: In the second version, two shell commands are executed for every line of the input file, whereas the cp command executes no commands to do the copy.

Shell commands, even built-in ones such as read and print, almost always take longer to execute than the equivalent machine language instructions inside an external "binary" command.

![](bbox=[0.033, 0.383, 0.133, 0.423])

The reason for using a shell program to read a file is so that you can do something special with its contents. If you can, use the external commands that came with your system, such as cp, mv, grep, sort, uniq, head, and tail to do "standard" things with files.

+   f) What are four things the user could use to cause this script to stop executing?

Answer: (.), q, Ctrl-D, or Ctrl-C.

The program checks whether the user types a dot or a q as the first token on the command line, and exits the outer while loop (by executing return in either case). Because the outer while loop continues for as long as the read command returns true, the user can press Ctrl-D (or Ctrl-Z on DOS/Windows systems, whatever the user has set as his/her end-file character, to use the system's stty stof command) to indicate end of input. Finally, if the user types Ctrl-C (or whatever her interrupt character is to use the system's stty intr command), the program will terminate abruptly.

+   g) What is the purpose of the print command at the end of the script?

Answer: It positions the cursor properly in the case user presses Ctrl-D.

Because the cursor does not move to the start of a new line in this case, the script does a print command if execution gets past the end of the outer while loop.
