On line 6073, export_test does not "see" the value of the variable x and prints nothing for its value in the "Before assignment" message. The script successfully assigns a value to x, as the second line of output following line 6073 shows, but that value is not assigned to the variable x defined at the command-line level, and line 6074 prints the value assigned to before export_test was run. When export_test is run again after declaring that x is an exported variable, the script has a variable named x with the value hello when it starts running, and is again able to change the value of that variable successfully. However, the variable x inside the script is a copy of the variable defined from the command line, and changing its value inside the script does not affect the value of the command line variable, as shown by the output from line 6077.

A variable that is passed to a script using export is an environment variable. A program's environment is a list of variables and their values that are defined when the program starts running. When you run set (with no options or parameters) from the command line, the shell prints its own environment, which includes environment variables.

```
unset x y z
. s614
print x=$x y=$y z=$z
```

i) How does dotting the script affect the values of the three variables?
Answer: Your interaction should look like the following:

```
[6078]: unset x y z
[6079]: . s614
x=3 y=5 ksh x=abc y=2 z=7
Inside f614_ksh x=abc y=2 z=7
Inside f614 posix x=def y=1 z=7
def y=1 z=7
[6080]: print x=$x y=$y z=$z
def y=1 z=7
[6081]:
```

When you look at the variables from the command line (line 6080), they have the same values as the last time they were printed by the script (def, 1, and 7) because they are the same variables. There are no copies made; they are simply the same variables inside the script and outside it.
