Having the final buffer constructed as a string is a very important piece of information. The C programming language makes use of null-terminated strings,[390](https://www.offensive-security.com/penetration-testing-with-kali-linux/390) meaning that functions such as `strcpy` and `strcat` determine the end and the size of a string by searching for the first occurrence of a NULL byte in the target character array. Since the allocation size of our initial padding buffer is 780, by setting the last byte to 0x00 (Listing 442), we end up concatenating (strcat) a string of “A” ASCII characters that is 779 bytes in length. This explains the misaligned overwrite of the EIP register.

We can quickly fix this by increasing the requested memory size defined by the `initial_buffer_size` variable by 1.

```
int initial_buffer_size = 781;
char \*padding = malloc(initial_buffer_size);
memset(padding, 0x41, initial_buffer_size);
memset(padding + initial_buffer_size - 1, 0x00, 1);
```
