- NEWDB This option adds the basic database support under Linux systems. It provides both hash and tree databases. This one option provides all you need to build and access most Sendmail databases.

- MAP_REGEX This option adds a new feature to Sendmail that permits databases to be searched with regular expressions. Anyone who has used regular expressions with grep knows that they are much more powerful than simple wildcard characters. This added feature is powerful when you need to create complex rules to block spammers.

- USERDB This option adds support for the user database, which can be used to process email addresses on both inbound and outbound e-mail. A related option is UDB_DEFAULT_SPEC, which defines the default path to the user database. The path can be set with the CONFUSERDB_SPEC define in Sendmail configuration, as we saw in the readme.mc file in Chapter 5, "Understanding a Vendor's Configuration." I prefer setting the value in the configuration instead of compiling it Sendmail because it is more easily changed when it is set in the configuration. However, some path value must be explicitly defined before Sendmail can use the user database.

- NIS This option provides access to Network Information System (NIS) databases. These are administrative databases, such as /etc/mail/aliases and /etc/hosts, stored on the NIS server. The related option databases NISPLUS and YCOMPAT are early used on Linux systems. NIS+, which is an upgraded version of NIS, is not often used in Linux environments; YCOMPAT creates compatibility with a version of NIS that has not been produced in several years. YCOMPAT permits the use of plus syntax, in which a+ is placed at the end of a local administrative database to tell the system to search the local database and then search the database on the NIS server; with YCOMPAT and a+ at the end of the /etc/mail/aliases database, Sendmail first checks the local aliases database and then checks the one on the NIS server. AUTO_NIS_ALIASES option does exactly the thing. It tells Sendmail to check the local aliases database first and then check the NIS server, and it does without the outdated plus syntax. (Details of setting up an NIS server on a Linux system are covered in the Linux DNS Server Administration book of this series.)

To force Sendmail to use these four database options, you could either edit the devtools/os/linux.m4 or create a file in the devtoolsSite directory that contains the following line:

```
define(CONFDEFMAP, '-DNEWDB -DNIS -DMAP_REGEX -DUSERDB')
```

Once the line is inserted in the file of your choice, recompile Sendmail to put the options effect. (See Chapter 3 for instructions on compiling Sendmail).

However, before going to all this trouble, check which your Sendmail program is already using. The default database option settings vary based on the database libraries detected by the Sendmail source distribution's build routine. On a Linux system, the default is DNEWDB. But build does a good job of detecting the capabilities of your system, so your Sendmail program could include additional options. # Configuration Options

As noted at the beginning of this section, the aliases database is the only database available to Sendmail by default. All the other databases described in this chapter must be added to the Sendmail configuration before they can be used. The following defines and features are used to configure support for the other databases, as well as some important files:

```
define(USERDB_SPEC, /etc/mail/userdb.db)
```

The USERDB_SPEC option tells Sendmail to apply the user database to local addresses after the aliases database is applied and before the forward file is applied. The path argument given with this option is the full pathname of the database. There is no default for the path unless Sendmail is compiled with USERDB_DEFAULT_SPEC. Setting the path with USERDB_SPEC is much simpler and more flexible than using DB_DEFAULT_SPEC. The following define enables the user database and tells Sendmail that it can be found in /etc/mail/userdb.db.

```
define(CONFFILE, /etc/mail/config)
```

The CONFFILE option tells Sendmail to add the list of hosts permitted to relay mail from the specified file to the relay variable. The full pathname of the file can be provided as an argument. If the pathname is not provided, it defaults to /etc/mail/relay-domains for Sendmail 8.11.

```
FEATURE(use_ct_file, /etc/mail/trusted-users)
```

The use_ct_file feature tells Sendmail to add trusted users from the file to the access class. The full pathname of the file is an optional argument. If the pathname is not provided, Sendmail 8.11 defaults to /etc/mail/trusted-users.

```
FEATURE(use_cw_file, /etc/mail/local-hosts)
```

The use_cw_file feature tells Sendmail to add hostname aliases from the file to the warning class. The full pathname of the file is an optional argument. If the pathname is not provided, Sendmail 8.11 uses /etc/mail/local-hosts as the default.

# Adding Database Support

FEATURE('access_db', '/etc/mail/access') The access_db feature tells Sendmail to use the access database to control mailing and delivery based on the source of the mail. An optional database specification can be provided to define the database type and the full pathname of the database. By default, the database type is hash and the database path is /etc/mail/access.

FEATURE('mailertable', '/etc/mail/mailertable') The mailertable feature tells Sendmail to use the mailer to map the domain name in a delivery address to a specific mailer and host for delivery. An optional database specification can be provided to define the database type and the full pathname of the database. By default, the database type is hash and the database path is /etc/mail/mailertable.

FEATURE('virtertable', '/etc/mail/virtertable') The virtertable feature tells Sendmail to use the virtertable database to map the recipient address in incoming e-mail to a different recipient address. This function is similar to the one performed by aliases database, except that the virtertable aliases domain names, not just usernames. An optional database specification can be provided to define the database type and the full pathname of the database. By default, the database type is hash and the database path is /etc/mail/virtertable.

FEATURE('generictable', '/etc/mail/generictable') The generictable feature tells Sendmail to use the generictable database to map the sender address on outbound to a different sender address. An optional database specification can be provided to define the database type and the full pathname of the database. By default, the database type is hash and the database path is /etc/mail/generictable.

FEATURE('domaintable', '/etc/mail/domaintable') The domaintable feature tells Sendmail to use the domain table to map one domain name to another. An optional database specification can be provided to define the database type and the full pathname of the database. By default, the database type is hash and the database path is /etc/mail/domaintable.

FEATURE('uucpdomain', '/etc/mail/uucpdomain') The uucpdomain feature tells Sendmail to use the uucpdomain database to map UIP sites domain names. An optional database specification can be provided to define the database type and the full pathname of the database. By default, the database type is hash and the database path is /etc/mail/uucpdomain.

FEATURE('bitdomain', '/etc/mail/bitdomain') The bitdomain feature tells Sendmail to use the bitdomain database to map BITNET hostnames to Internet domain names. BITNET is an outbound IBM network that you won't use. An optional database specification can be provided to define the database type and the full pathname of the database. By default, the database type is hash and the database path is /etc/mail/bitdomain.
