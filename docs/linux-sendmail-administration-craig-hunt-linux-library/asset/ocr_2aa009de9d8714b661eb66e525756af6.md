The relay_based_on_MX feature is another feature that grants relaying to a group of hosts. This feature will relay mail for any host for which the local host is an MX server. This is a useful feature if there handles inbound mail for your clients or the system that handles outbound mail. The MX record that routes mail through the server to its clients can also be the signal to relay outbound mail from those same clients. The weakness of this approach is that the Sendmail administrator cannot control all of the MX records in the domain name system. A remote site could relay mail through your server by simply adding an MX record to their domain. Despite this weakness, this feature is still an effective defense against spammers. Because they want to hide their source of spam, spammers don't send mail to their own domain names, and they thus cannot write MX records for the domain names they use.

The last feature that relaxes relaying restrictions is probably the most dangerous. The FEATURE ('promiscuous_relay') current versions of Sendmail block all relaying. The promiscuous_relay feature returns to relay all mail by default. This is the opposite of earlier versions of Sendmail to relay all mail from any source. This is exactly the configuration spammers hope to find and is the configuration they love to exploit. This feature can only be used if your server is completely off from the Internet, either because you have no connection or because your connection is a firewall that does not allow any external mail delivery to the server. Regardless of your network connection, I recommend against using this feature because it exposes your system to exploitation.

All of the features listed in this section weaken the barrier to mail relaying, although are worse than others. promiscuous_relay should not be used because it returns to the past and makes you a potential spam relay. Avoid the relay_local_from feature because it is very easy for spammers to write anything they want in the MAIL From: header, including your local domain name. Be careful when using any of the features described in this section that you not weaken the Sendmail configuration so much you you become a spam source.
