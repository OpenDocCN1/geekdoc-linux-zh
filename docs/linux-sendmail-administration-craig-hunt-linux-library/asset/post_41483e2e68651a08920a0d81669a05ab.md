
Each section is examined in detail in this chapter. It is unlikely that you will directly modify the **sendmail**.cf file except for the smallest of changes. Changing the macro configuration and rebuilding a new sendmail.cf is the preferred technique for making configuration changes. Yet understanding the structure of the sendmail.cf file, and the syntax and purpose of the configuration commands it contains, is an essential skill for every Sendmail administrator. Understanding the **sendmail**.cf file helps you understand the purpose of the macro configuration commands and lets you observe your impact on the underlying configuration. More importantly, the Sendmail test tools work with the sendmail.cf configuration file. To effectively monitor a test, you need to understand the test output, which is often based on the structure of the **sendmail**.cf file.

Our analysis of the sendmail.cf file begins at the beginning with the first section, Local Info, and moves section by section through the entire file. The Local Info section contains the widest variety of configuration statements, and it is the part of the sendmail.cf file that is most often modified by system administrators.

## The Local Info Section

The first section in the sendmail.cf file contains information that is specific to the local host: information such as the hostname, the names of any relay hosts, and the domain name. It also contains information specific to your copy of Sendmail, such as the name that Sendmail uses to identify when it returns error messages, and the version number of the Sendmail distribution you're running. Additionally, the Local Info section contains the definitions of the optional databases used by Sendmail. This collection of diverse information is gathered together at the beginning of the **sendmail**.cf file to make it easier to locate in case manual editing is required.

The Local Info section of the sendmail.cf file generated for Sendmail 8.11 from redhat.nc file is shown in Listing 7.1. It has been edited to reduce the number of unused lines. It should be nearly identical to the Local Info section on your Linux system, but it won't be exactly the same. Don't worry about the differences; they are all related to comments and the number of blank lines. The commands are unchanged.

Blank lines are ignored. Lines that begin with # comments are invaluable aids to understanding the arcane sendmail.cf file. Lines that begin with an uppercase character are configuration commands. Listing 7.1 commands the D, C, F, and K.

The local information is defined by D commands that define macro variables, C commands define class variables, F commands that load class values from files, and K commands that define databases of information. The sendmail.cf command syntax is very terse. The commands are only one character long and many variables have one-character names. Add this to the fact that the value assigned to the variable is crammed right next to the variable name and you have configuration commands that are terse hard to read. Let's take a closer look at the D, C, F, and K commands so that we can decipher what is happening in the Local Info section.

## The Define Macro Command

The define command D defines a variable and assigns a value to it. Once the variable defined, the stored value is used by other sendmail.cf commands and directly by Sendmail itself. Variables provide the flexibility that permits the same basic sendmail configurations to run on many different systems, simply by modifying a system-specific macro variables.

Traditional variable names are a single ASCII character, with user-created macro variables using uppercase letters and Sendmail internal macros using lowercase letters and special characters as names. These rules have changed. Now Sendmail defines the meaning of several variables with uppercase names, and in Sendmail version 8.11 variable names are not restricted to a single character. Long variable names are enclosed in curly braces e.g., {WebHost} is a valid variable name. However, a quick check of the sendmail.cf shows that not a single long variable name was used. Listing 7.2 shows a grep that displays every D command contained in the sendmail.cf.

## Listing 7.2 The Define Macro Commands Found in sendmail.cf

```
DS
DR
DH
DM
DnMAIL-DAEMON
D8M
```

Listing 7.2 shows some interesting things. First, most of the variables are not set. The first three D commands set values for the S, R, and H variables. Each of these variables identifies an external mail relay.

- The S variable stores the name of the relay host defined by the SMART_HOST variable in the m4 configuration. The SMART_HOST relay is a central mail server that handles all outgoing mail.
- The R variable holds the name of a relay host that handles local mail. The LOCAL_RELAY define command in m4 configuration sets the value for R. When R is set, the local computer does not handle its own local mail. Mail addressed to local user kathy is not handled by the local mail; it is relayed through the server specified by the R variable.
- The H variable stores the mail server name by the MAIL_HUB command in the m4 configuration. The MAIL_HUB handles all local mail in which the recipient address includes the name of the local host. Furthermore, while mail addressed to kathy may be handled by the LOCAL_RELAY, mail from any user logged into foobirds.org would be relayed through the MAIL_HUB server.

It is easy to see why these variables are not set on our sample system. These external relays are used only when the local system does not handle its e-mail—for example, in a client configuration.

The fourth variable is not set is M. It has nothing to do with relaying. The M variable holds the masquerade value. We will play with Mail Later in this chapter and have much more over masquerading in Chapter 9, "Special m4 Configurations."

Only two of the variables in Listing 7.2 have a value assigned to them. The n variable holds the sender name that Sendmail uses to generate error messages. This value can be set in the macro configuration with the MAIL_NAME option. But if it is not set, it defaults to MAILER-DAEMON, which is exactly what happened in our sample configuration.
