# Chapter 6 Using Sendmail Databases

[root]# makemap hash virtertable < virtertable
[root]# sendmail -bv sales@bridal-gowns.com
sales@bridal-gowns.com... deliverable: mailer local, user jill

The virtertable database is built with the makemap command and tested using sendmail with the -bv argument. the -bv argument causes the sendmail command to process the address on the command line as a delivery address. The test shows that the address sales@bridal-gowns.com will be delivered via the local mailer to the user account Jill. This is just what we expected based on the first line of the virtertable file.

In Listing 6.11 we examine the contents of the local-host-names file and the virtertable source file. The local-host-name file shows that all of the virtual domains have been added to class w. If the virtual domains are not added to class w (VirHost), the sendmail -bv produces the following result:

```
[root]# sendmail -bv sales@bridal-gowns.com
sales@bridal-gowns.com... deliverable: mailer smtp
host bridal-gowns.com, user sales@bridal-gowns.com
```

This test shows Sendmail believes that bridal-gowns.com is an external domain that can be reached through the smtp mail. If we defined the virtual domain in the local-names file and forgot to provide the mapping in the virtertable, either by not including it in the file or not running makemap, sendmail -bv produces the following result:

```
[root]# sendmail -bv info@patient-rights.org
info@patient-rights.org... deliverable: mailer local, user info
```

The virtual domain is accepted, but the host is not mapped to the external host as we wished. A simple sendmail -bv test can tell you if the virtertable is working and can indicate what's wrong if it isn't.

There are many good reasons to use the virtertable, particularly if you run an ISP that provides service to a large number of customers or run an e-business site. It is easy to see why Red Hat includes this in their default Sendmail configuration. The last database included in the redhat.mc file, the mailertable, is more rarely used.

# The mailertable

The virtertable is rarely needed. It maps domain names to the internal mailer that should handle mail bound for that domain. The reason that this database is rarely needed is that Sendmail usually routes mail to the correct mailer without any help from You.
