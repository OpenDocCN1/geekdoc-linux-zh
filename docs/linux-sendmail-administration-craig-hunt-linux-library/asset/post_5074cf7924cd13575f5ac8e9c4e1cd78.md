The filename local-host-names may be more logical than the name sendmail.cw, but since when did logic have anything to do with Sendmail configuration? Back to Listing 5.3. The last line in the generic.m4 file is the EXPOSED_USER macro. The EXPOSED_USER macro adds usernames to class E. The users listed in class E are not quarantined, even when masquerading is enabled.

Some usernames, such as root, occur on many systems and are therefore not unique across a domain. For those usernames, converting the host portion of the address makes it difficult to sort out where the message really came from, and root@owner.foobirds.org and root@foobirds.org is passed through a server that converts both addresses to root@foobirds.org. There is no way for the recipient to know exactly where the message originally originated, and the remote user could not reply to the correct address. The EXPOSED_USER command in Listing 5.3 prevents from masquerading by ensuring that root is not masqueraded.

The primary reason this macro is included in the generic.m4 file is to serve as a warning to the Sendmail administrator that something has changed. Sendmail administrators may think that root is already part of class E because prior to Sendmail 8.10, root was the default value for class E. In Sendmail, there are no default values in class E. If you want to protect root from masquerading, the EXPOSED_USER command in your configuration must be added. Of course, this command has no real effect in the generic.m4 file because this configuration does not include any commands to enable masquerading.

The EXPOSED_USER command in your configuration illustrates the main purpose of the generic.m4 file—it is intended as a tool to show you the type of commands you should include in your own domain source file. The generic file is just an example and should be specific to your environment. If you use one, you're expected to create it yourself. ## The Essential Mailers

The two MAILER commands in the generic-linux.mc file are found in most Sendmail configurations. These commands identify the sets of mailers included in the Sendmail configuration.

MAILER(local) macro includes the local mailer that is used to deliver local mail between users of the system and the mailer used to send mail to programs running on the system. Even though these mailers are added by default, MAILER(local) is traditionally included in the configuration. This arises from the fact that most configurations are built from a sample configuration file and all of them include the MAILER(local) macro. It takes more effort to remove the mailer than it does to leave it in, and it costs nothing. In fact, it provides the slight benefit of making the configuration "self-documenting."

MAILER(smtp) macro includes all of the mailers needed to send SMTP mail over a TCP/IP network. The mailers included in this set are:

- smtp This handler can handle only traditional seven-bit ASCII mail. It is outdated because most modern mail networks handle a variety of data types.
- smtp This mailer supports Extended SMTP (ESMTP). It understands the ESMTP extensions and can deal with complex message bodies and enhanced data types of MIME. This is the default mailer used for SMTP.
- smtp8 This mailer sends eight-bit data to the remote server, even if the server does not indicate that it can support eight-bit data. Normally, a server that supports eight-bit data also supports ESMTP and thus can advertise its support for eight-bit data in response to the EHLO command. (See Chapter 1, "Internet Protocols," for a description of the SMTP protocol and the EHLO command.) It is possible, however, to have a connection to a remote server that can support eight-bit data but does not support ESMTP. In rare circumstances, this mailer is available for use.
- smtp This mailer allows the destination system to retrieve mail queued on the server. Normally, the source system sends mail to the destination in what might be called a "push" model, where the source pushes out to the destination. SMTP allows the destination to "pull" mail down from the mail server when it is ready to receive the mail. This mailer implements the ETRN command that permits on-delivery (See Chapter 1 for a description of the ETRN command).
- relay This mailer is used when SMTP mail must be relayed through another mail server. Several mail relay hosts can be defined.

Every server that connects to or with the Internet uses the MAILER(smtp) set of mailers, and most systems on isolated networks use these mailers because they use a TCP/IP network. Despite the fact that a majority of Sendmail services require these mailers, installing them is not the default. To support SMTP mail, you must add the MAILER(smtp) macro to your configuration.

In addition to these two important sets of mailers, there are nine other sets of mailers available with the MAILER command, all of which are covered in Appendix A, "m4 Macro Command Reference." Most of them are of little interest for an average Linux configuration. The two sets of mailers included in the generic-linux.mc configuration are the only ones that most administrators ever use.

## Tweaking the Mailer Configurations

Let's diverge for a moment from the discussion of the generic-linux.mc configuration file to talk about mailer configuration. You're strongly encouraged to create your own source file in the domain directory. You might even be bold to create an OSTYPE file for your Linux distribution in the ostype directory. MAILER source files are different. The mailers loaded by the MAILER macros are defined in the mailer directory. You will never directly edit a file in the directory or add any files to it. To modify the settings of a specific mailer, use the configuration variables created for this purpose. Table 5.1 lists the variables used to tune the local and prog mailers and all of the mailers included in the set of SMTP mailers.
