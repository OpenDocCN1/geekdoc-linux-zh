# Table 8.5 Sendmail Error Code Keywords (continued)

| Keyword | Meaning |
|---|--|
| tempfail | A temporary failure was detected. |
| unavailable | A delivery resource is not available. |
| usage | The syntax of the delivery address is bad. |

An error message using an error code would look something like the following:

```
$R<$+> #error S $:user address required
```

This works, but is not the recommended format. In fact, a single error message in the sendmail.cf file delivered with Sendmail 8.11.0 uses the keyword format. The preferred format is to use a DSN code in place of the key. The codes are clearly defined in an Internet standard and are understood by all mailers. DSN codes are composed of three dot-separated components:

class Provides a broad classification of the status. Three values are defined for class in the RFC: 2 means success, 4 means temporary failure, and 5 means permanent failure.

subject Classifies the error messages as relating to one of eight categories:

+   - 0 (Undefined) The specific category cannot be determined.
- 1 (Addressing) A problem was encountered with the address.
- 2 (Mailbox) A problem was encountered with the delivery mailbox.
- 3 (Mail system) The destination delivery system is having a problem.
- 4 (Network) The network infrastructure is having a problem.
- 5 (Protocol) A protocol problem was encountered.
- 6 (Content) The message content caused a translation error.
- 7 (Security) A security problem was reported.

detail Provides the details of the specific error. The detail value is only meaningful in context of the subject code. For example x.1.1 means a bad destination user and x.1.2 means a bad destination host, while x.2.1 means the mailbox is disabled and x.2.2 means the mailbox is full. There are far too many detail codes to list here. See RFC 1893 for a full list.
