Unlike Chapter 1, this time the sendmail command is not run with the -t option. Instead, the address of the remote recipient is typed in the command line, and the contents of a file are provided to Sendmail to be used as the mail message. The recipient is craig@foobirds.org and the file is the null device, /dev/null. Clearly, the null device will not provide any real content, so we are in sending an empty message. The sole purpose of this test is to observe the protocol interactions.

> TIP Don't send empty messages to other users just to test e-mail. To test your system, get a free e-mail account explicitly for this purpose and send the tests to yourself at that. To test a specific remote system, make arrangements with the administrator of system before you start test mail.

Listing 10.2, of course, begs the question "Why do you want to look at the protocol actions?" SMTP has been around for a very long time. It is a simple protocol. Everybody does it correctly. You're not looking for errors in the SMTP protocol. What you're really looking for a test like this is an unexpected result, either from changes to your own configuration or from prompts at the remote end. You want to make sure that:

- The remote end answers.
- The remote server supports the extended SMTP protocol features that your system needs.
- Your system sends the remote server a valid address, and the remote server accepts it.
- The delivery address your system sends is a valid address for the remote system.

Sendmail run in verbose mode primarily when you have a problem and you are trying to gather clues to help you analyze the problem. But the -v option is not just to run Sendmail in verbose mode. It is also used to increase the level of detail displayed when the sendmail command run with one of the command line options that request information—not mail delivery. One of these options is -bh, which is also known as the hoststat command.

## The hoststat Command

The -bh command-line option asks Sendmail to display the host status. On most systems the host status request produces no response, because the default Sendmail configuration does not persistent host status. Normally, Sendmail internally tracks the status of its outbound network connections only as long as needed. Before the -bh option can be used to any effect, the configuration must be changed so that Sendmail will write a permanent log of these connections.

Define conf_STATUS_DIRECTORY in your m4 configuration to enable persistent host logging and to identify the directory where the status will be stored. The argument provided to conf_STATUS_DIRECTORY is the pathname of the directory where the status is logged. Listing 10.3 shows a configuration that will log host status in /var/state/sendmail.

### 10.3 Using the Host Status

```bash
# diff sendmail.mc host-status.mc
define('conf_STATUS_DIRECTORY', '/var/state/sendmail')
# m4 host-status.mc > host-status.cf
# diff /etc/sendmail.mc host-status.cf
# HostStatusDirectory=/var/state/sendmail
[root]# mkdir /etc/sendmail.cf
[root]# cp /etc/sendmail.cf /etc/sendmail.cf.bak
[root]# cp host-status.cf /etc/sendmail.cf
cp: overwrite /etc/sendmail.cf
[root]# /etc.init.d/sendmail restart
OK
```

Listing 10.3 opens with a diff that shows the only difference between sendmail.mc macro configuration used to build sendmail.cf and the new host-status.mc is a single define command. The command defines conf_STATUS_DIRECTORY and gives it the value /var/state/sendmail. The new configuration file is processed through m4 to create host-status.cf. A diff comparing that file to the current sendmail.cf shows that the only difference is a single option. The option sets the HostDirectory option to /var/state/sendmail. Setting this option is the only effect that conf_STATUS_DIRECTORY has on the mail configuration.

Notice that in the original sendmail.cf the HostDirectory option is commented out; notice also that it has a default value that would be used if # removed from the beginning of the line. The default path is .hoststat, which is a relative path. If a relative path is used, the host status is a subdirectory in the mail directory. The mail queue directory is defined in m4 configuration with QUEUE_DIR and set in sendmail.cf as QueueDirectory. On our sample Linux system, it is /var/spool/queue. For configuration, we decide not to use a relative path. Instead we put the host status log in /var/state/sendmail.

Before the directory can be used to log status, it must be created, which we do in Listing 10.3 with a mkdir command. We then move the new configuration to /etc/sendmail.cf, which is where the Red Hat system looks for the Sendmail configuration, and then we restart Sendmail. Now Sendmail is logging the host connection status. A few minutes later, running the sendmail command with -bh and -v produces the output in Listing 10.4.

### Listing 10.4 A Sample Host Status Report

```
[root]# sendmail -bh -v
-- Hostname -- How long ago ---------------------------
ibis.foobirds.org 00:02:30 250 2.0.0 eA1BCq
Message accepted for delivery
goat.mammals.org 00:01:50 Deferred: Network is unreachable
```

## Simple Command-Line Options

NOTE The -bh command-line option can be invoked with the hstat command. Like the -bd option covered in Chapter 3 ("Running Sendmail") that can be run using the smtpd command, and the -b1 option covered in Chapter 6 ("Using Sendmail Databases") that could be invoked with the new aliases, the -bh option has a synonym. In this chapter, we will also see that -BH can invoked with the purgestat and -bp can be invoked with the mailq command. The command in Listing 10.4 could have been written hstat -v.

Listing 10.4 was reformatted slightly to fit a book page, but basically it is the type of host status report that will be seen soon after host status logging enabled. Inbound connections are not logged. The log show two outbound connections. Each entry has three fields:

- The first provides the complete domain name of the remote host.
Long ago The second field indicates how long the status was updated. The format of this field is dd:hh:mm:ss, where dd is days, hh is hours, mm is minutes, and ss is seconds. Both of these entries were made in the last few minutes because this report was printed out after host status logging enabled. However, this is a persistent status report. Over time, these status entries will grow, unless the status of one of the host changes. For example, the network connection to goat could be restored.
Results The third field displays the result of the last attempt to deliver to the host identified by the hostname field. Unless the -v option is used with -bh, the results may be truncated.

The entry in Listing 10.4 shows a successful delivery to ibis.fobirds.org took two and a half minutes ago. That's entry field contains the full response received from the remote system, SMTP response code, DSN code, message ID, and text. Results fields are not always complete; a successful connection might generate a result of goat.
