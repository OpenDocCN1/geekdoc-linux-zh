Most switches fall into the category of configuration options that you will never use. The -m switch verifies that a key exists but does not return the value for the key. This is rarely used because a successful lookup in a normal database both validates the key and returns the value for the key. The -f switch appends a fixed string to the value returned for a lookup. For example, -foibirds adds the string, foibirds.org to every response from the database. This switch is rarely used, because if every value in a database needs to have a specific value appended, it can easily be done when the database is originally without any manual modification of the sendmail.cf file.

The most commonly used, and most important, switch is -o -ells Sendmail that a database is optional. With this switch, a K command can be included in sendmail in anticipation of the need for a database without requiring that database be present. Without the -o switch, Sendmail will fail on the first command that attempts to access the database if the database file cannot be found. Using -o makes Sendmail more forgiving and more robust.

We have covered most of the K command syntax: the database name, the database type, and the switches. The last field in the K command is the path. This is simply the pathname of the database, generally written without the file extension. (The K command adds the correct extension—for example, .db—to the pathname based on database type.) The path value is only required if the database is external to Sendmail. As the list of data types make clear, several of the databases declared by K commands are internal to Sendmail. When an internal database is used, no path is needed. Sample K commands from the sendmail.cf file will make the structure of the command clear.
