In Listing 8.5, we create a ruleset RemoveAngles that contains only one rule. The pattern in the rule matches any number of tokens ($*) before a literal < and any number of tokens ($*) between the literals < and >. The template in the rule writes the indefinite tokens without the address angle brackets.

The send -bt in Listing 8.5 shows that the rule works; it removes all of the angle brackets from the address craig<<@wren>. Don't assume, however, that it removes all of the angle brackets in one pass. The first time the address matches the pattern it is rewritten as craig<<@wren>. The rewritten address is again compared to the pattern and it again matches. This time it is rewritten as craig<<@wren>, which again matches the pattern. Finally, it is rewritten as craig@wren, which doesn't have the angle brackets to match the pattern.

When the pattern no longer matches, no further processing is done by this rule and the address is passed to the next rule in line. The RemoveAngles ruleset from Listing 8.5 contains no other rules processing stops, but most rulesets have more than one rule. Rules in a rules are processed sequentially, although a few symbols can be used to modify this.

The recursion built into rules creates the possibility for infinite loops. The $ and the : templates are used to control processing and prevent loops. If the rule begins with the $ symbol, the entire rule is rewritten and the remainder of the template is returned by the rule. Use $ to exit a rule at a specific rule.

In Listing 8.3, the $ symbol was used to control the flow inside the ClassTest rules. The template in each rule that starts with the $ symbol, if so a pattern is found, the template is applied and the rule exits. Suppose the $ was not used on the first rule in list. In that case, the test of the address christopher@robin would have produced the response "Wrong" instead of "Found" that we expected. Here's why. The address christopher@robin matches the pattern of the first rule, which is $*w. Therefore, the address is rewritten to Found. If the $ symbol was not used, the address is again compared to the pattern $*w in the first rule. It doesn't match. The address is processed by the next rules in line. It does not match the pattern of the second rule, which is $*w. The address it is therefore passed on to the third rule in line. This time it matches the pattern $*, which essentially matches anything that hasn't been caught by the first two rules. The third rule rewrites the Found it into the address Wrong format-not of course, what we wanted. To get the result we want, every rule in ruleset ClassTest requires a flow control symbol, even the third rule.
