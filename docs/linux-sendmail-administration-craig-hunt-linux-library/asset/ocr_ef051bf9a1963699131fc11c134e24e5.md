# Chapter 9 Special m4 Configurations

If header address masquerading isn't sufficient for your configuration, there are two features available to extend masquerading to other types of addresses. These are:

FEATURE (masquerade-envelope) This feature causes Sendmail to masquerade envelope addresses. If this had been set, the third test in Listing 9.2 would have resulted in wen.foobirds.org being masqueraded as foobirds.org in the envelope address. This feature is useful if masquerading is done to satisfy the security policy. They like to be thorough!

FEATURE (allmasquerade) This feature causes Sendmail to masquerade recipient addresses. Generally, this is not a good idea. Masquerading is for hiding source addresses on outbound mail. Changing the address on inbound mail does not make sense, as the user of a local system already knows the real name of that system. Additionally, adding a masqueraded hostname to an inbound address can cause the mail to bypass the alias process. Don't use the allmasquerade feature.

As mentioned above, the second limit of the default masquerading settings is that only class w is masqueraded. This default makes sense, because the server masquerading is often the server that will accept inbound mail. A server accepts mail for local delivery only for hosts in class w. Limiting masquerading to systems in class w creates a balance between inbound mail and outbound mail. But this only makes sense when the system masquerading also collects the mail for every system that it masquerades. It is not always the case. A mail relay server may relay out bound and yet no role in collecting inbound mail. There are some m4 macros and features that allow you to create a more flexible configuration.

Class M holds a list of hosts that should be masqueraded. The values stored in Class M are added to hosts in class w for masquerading. Values in class M are not, equivalent to values in class w aliases for the local host. The local system will not accept mail addressed to hosts in class M local mail. Class M provides a finer level of control by permitting masquerading without granting any type of access.

The limited_masquerade feature further refines your control over masquerading. By default, values in both class w and class M are masqueraded. To limit masquerading to only those values defined in class M, use the limited_masquerade feature. When masquerading is enabled, masquerading local host aliases is the logical thing to do, but class w can hold more than just local host aliases. In Chapter 6, "Using Sendmail Databases," we added virtual domain names to class w. You may not want to masquerade virtual domain names in outbound mail because you want external customers to believe that the virtual domains are real domains.
