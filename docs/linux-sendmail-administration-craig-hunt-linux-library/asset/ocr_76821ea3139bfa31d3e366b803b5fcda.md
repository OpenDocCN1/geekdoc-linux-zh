This is the worst-case scenario. We had hoped everything would be easy sailing. Now we need to track down all of the packages needed by Sendmail 8.11, install those packages, and then attempt to install sendmail-8.11.0-1.i386. This bit of unpleasantness is a blessing in disguise. If we installed Sendmail 8.11 from source code and did not know that openssl and libsas are required, some of the features of Sendmail would not work as advertised. It could take a long time tracking down the problem, RPM makes sure that we know about the problem from the start. We could force RPM to install sendmail-8.11.0-1.i386 without the dependencies by adding the --noodepeps argument to the rpm command line. But that's asking for trouble. The best thing to do is track down and install the required packages.

A search of www.rpmfind.net informs that we need three different RPM packages to fix the six dependencies: openssl-0.9.sa-1.i386, rpm, libsasf1999-1.i386, rpm, and cyrus-sasl-1.5.11-2.i386. The first two packages, openssl and libsas, are pretty obvious because RPM lists them as the first dependencies needed by sendmail-8.11.0-1.i386. An examination of the type of files provided by each package shows that they provide every dependency except libsas1.so.7. A search for libsas1.so.7 tells us that it is found in cyrus-sasl-1.5.11-2.i386. We download the three packages and install them as shown in Listing 3.8.

# Listing 3.8 Fixing Dependency Problems for Sendmail 8.11

```
[root] rpm -i openssl-0.9.sa-1.i386.rpm
error: file /usr/share/man/passwd.1 from install openssl-0.9.sa-1
conflicts with file from package passwd-0.58-1
[root] rpm -i --replacefiles openssl-0.9.sa-1.i386.rpm
[root] rpm -i libsasf1999-1.i386.rpm
[root] rpm -i cyrus-sasl-1.5.11-2.i386.rpm
[root] rpm -i U sendmail-8.11.0-1.i386.rpm
[root] rpm -q sendmail
sendmail-8.11.0-1
```

Even this installation didn't go completely perfectly. The openssl-0.9.sa-1.i386 package creates a new passwd man file. The problem is, it doesn't own the old page. That page was put on the system by the passwd-0.58-1.i386 package. RPM won't let a new package change a file that belongs to another package unless you tell it to. In this case, we want the new passwd documentation so we use the --replacefiles argument with the rpm command to replace the old passwd documentation with the new documentation.
