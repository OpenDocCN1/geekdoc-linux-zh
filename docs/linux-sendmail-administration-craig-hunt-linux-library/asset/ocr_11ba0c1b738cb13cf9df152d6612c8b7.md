The ps command reveals whether or not Sendmail is running on your system:

```
[root]# ps -C Sendmail
PID TTY      TIME CMD
542 ?       00:00:36 sendmail
```

The low process ID (PID) shows that this process was started during the boot. Running this ps command on Linux systems will show that Sendmail is running because, generally, Sendmail becomes part of the boot process when you first install Linux.

Many systems are running the Sendmail daemon unnecessarily. It is not necessary to run Sendmail as a daemon in order to send mail. Running the sendmail command with -bd option is required only if your system directly receives SMTP mail. A Linux mail client can collect inbound mail from the mailbox using POP or IMAP and relay outbound mail through the mail relay server without running the Sendmail daemon. Deciding which systems should run the Sendmail daemon is part of planning your e-mail architecture. Unneeded daemons consume system resources and provide holes through which intruders can slider. Take care when selecting systems really need any daemon, including Sendmail.

It is possible to disable Sendmail after the system is installed, and there are easy tools to do this. These tools vary on the type of start-up procedures used. Some Linux systems use BSD-style start-up procedures, while others use V-style procedures.

On Linux distributions that use V-style boot procedures, the script that starts Sendmail is usually found in the /etc/rc.d/init directory, where it is stored under a name as sendmail, or mta. On distributions that use BSD-style boot procedures, the commands that start Sendmail are stored in one of the rc scripts. For example, on Solaris 4.0, the commands to start Sendmail are found in the /rc.m script located in the /etc/rc.d directory. Regardless of the name of the script used for this purpose, some start-up script is used to start Sendmail at boot time.

> To locate the Sendmail directory that holds start-up scripts and run the command grep sendmail to search every file for references to Sendmail. Not sure where the start-up scripts are stored? Go to /etc and look for files or directories that begin with the string rc. Those are start-up files and directories.
