# Chapter 6 Using Sendmail Databases

There are more databases available for Sendmail than you will ever use. A couple of little or no value to Linux sites—the bitdomain database converts addresses for a network that no Linux uses and the uuucdomain database converts UUCP “bang” addresses, the old hostuser email addresses, and almost no one uses them. Other available databases have overlapping functions that might mean you don't need to use both of them at all. The redhat.mc configuration delivered by the RPM contains fewer than half of the defines and features listed above, and that probably has more database capabilities that you will really need. To help you evaluate which databases you need, we'll examine all of them in more detail.

# The Cr, Cw, and Ct Files

The first three databases we cover are not, in the strict sense of the word, databases. They are disk files used to load sendmail.cf variables. The “cr” and “cw” files perform important roles in configuring Sendmail, but changes in the security atmosphere of the network mean that the “ct” file no longer has a useful role.

The file that loads the t class is often called the “ct” file because the traditional name of this file was /etc/sendmail.ct. In Sendmail 8.11 the default name of this file is /etc/mail/trusted-users, but the function of the file remains the same. It is used to add usernames to the list of users who are trusted to send mail under other user's name. By default, ct class contains the usernames daemon, root, and uucp.

You will never need the /etc/mail/trusted-users file, and there are some reasons why you won't. First, it is a bad idea to let people send out mail under other people's names. In general, you don't want to expand the list of trusted users. Second, if you decide absolutely must add usernames to the trusted user list, for example, you might want to add the username “mail” to the trusted user list. You could edit the macro configuration file to add the FEATURE(use_ct_file) command, rebuild sendmail.cf file, and create a trusted-users file containing the single word mail1. But why would you? You could easily edit the macro configuration file to add the define’CONTRUSTED_USERS, ‘mail!’ command, rebuild the sendmail.cf file, and be done with it. Not is only this second approach slightly easier, it is safer because there is one fewer file created and thus fewer file where the permissions could be set incorrectly.

> WARNING Despite this example, neither CONTRUSTED_USERS nor use_ct_file is recommended because you shouldn't add any users to the trusted user list. Trusting users is a bad idea in this age of spammers and security crackers.
