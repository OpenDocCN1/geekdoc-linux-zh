tokens (craig, ., and hunt) before the literal @ and six tokens (ibis, ., foobirds, ., org,
) between the literals < and >.

Literals are an important part of patterns but they lack the flexibility needed to create
general purpose configuration that can work on any system. That's where variables can
in. In our first example we used the pattern:

+   - $- @ $- .foobirds.org.

The problem with this pattern is that it only works with addresses that have the domain
foobirds.org works fine at our site, but isn't much
help if we need this configuration to our friends at mammals.org. What we actually
wanted to check was whether or not the address had the local domain name. The local
domain name is stored by Sendmail in the m variable, so we can use $ in the pattern to
match the domain name. The following pattern is equivalent to the pattern above
except that it works on any system:

+   - $- @ $- $.m

Here we look for addresses that have exactly one token ($-), a literal @, exactly one token
(-$), a literal ,, and the value return from variable m.

Class variables also be used in pattern matching. In fact, pattern matching is the only
place where class values are useful. The symbols $= and $~ are designed to test whether
or not a value from the input address is a member of the class. We can demonstrate this
with the simple, although contrived, ruleset. The ruleset shown below is the test .cf
we created in Chapter 4:

# SClassTest

```
R+ @ $w          $ Found it
R+ @ $~          $ Not in class w
R$*             $: Wrong format
```

The S command starts the ruleset and names it ClassTest. It contains three R commands.
ClassTest addresses addresses in the user @host. The pattern in the first rule
matches one or more tokens (+) before a literal @ and any value in class w (=). The pat-
 in the second rule matches one or more tokens ($+) before a literal @ and any value
that is not in class w (~). The pattern in the last line catches everything that falls
to complain that the address didn't contain a literal @. The templates are
contrived examples that will display a message when Sendmail is in test mode, as it
is in Listing 8.3.
