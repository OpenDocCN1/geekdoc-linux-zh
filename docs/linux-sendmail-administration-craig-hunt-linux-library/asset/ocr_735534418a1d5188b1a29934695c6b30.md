Blank lines are ignored. Lines that begin with # comments are invaluable
aids to understanding the arcane sendmail.cf file. Lines that begin with an uppercase character are configuration commands. Listing 7.1 commands the D, C, F, and K.

The local information is defined by D commands that define macro variables, C com-nmands define class variables, F commands that load class values from files, and K
mands that define databases of information. The sendmail.cf command syntax is
very terse. The commands are only one character long and many variables have one-character names. Add this to the fact that the value assigned to the variable is crammed
right next to the variable name and you have configuration commands that are terse
hard to read. Let's take a closer look at the D, C, F, and K commands so that we can deci-pher is happening in the Local Info section.

# The Define Macro Command

The define command D defines a variable and assigns a value to it. Once the vari-able defined, the stored value is used by other sendmail.cf commands and directly by
Sendmail itself. Variables provide the flexibility that permits the same basic sendmail
configurations to run on many different systems, simply by modifying a system-specific macro variables.

Traditional variable names are a single ASCII character, with user-created macro vari-ables using uppercase letters and Sendmail internal macros using lowercase let-ters and special characters as names. These rules have changed. Now Sendmail defines
the meaning of several variables with uppercase names, and in Sendmail version 8 vari-able names are not restricted to a single character. Long variable names are enclosed in
curly braces-e.g., {WebHost} is a valid variable name. However, a quick check of the
sendmail.cf delivered with the Red Hat RPM shows that not a single long variable name was used with a define macro command. Listing 7.2 shows a grep that displays every D
command contained in the entire sendmail.cf file.
