The message in Listing 1.4 contains three different Content-Type: headers, each of which I marked in bold to make them easier to find. The first identifies this as a message of type multipart. it is in fact composed of three distinct parts. (The subtype report was not defined in RFC 2046; it was added later.) Two parameters are also defined in the first Content-Type: header. The report-type argument tells us this is a delivery-status report. The boundary argument defines the line that is used to separate each part in this multipart message. The boundary lines are also in bold to make them easier to find in the listing.
