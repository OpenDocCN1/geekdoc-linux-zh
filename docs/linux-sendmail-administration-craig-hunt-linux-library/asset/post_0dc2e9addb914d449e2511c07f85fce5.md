
This is the worst-case scenario. We had hoped everything would be easy sailing. Now we need to track down all of the packages needed by Sendmail 8.11, install those packages, and then attempt to install sendmail-8.11.0-1.i386. This bit of unpleasantness is a blessing in disguise. If we installed Sendmail 8.11 from source code and did not know that openssl and libsas are required, some of the features of Sendmail would not work as advertised. It could take a long time tracking down the problem, RPM makes sure that we know about the problem from the start. We could force RPM to install sendmail-8.11.0-1.i386 without the dependencies by adding the --noodeeps argument to the rpm command line. But that's asking for trouble. The best thing to do is track down and install the required packages.

A search of www.rpmfind.net informs that we need three different RPM packages to fix the six dependencies: openssl-0.9.sa-1.i386, rpm, libsasf1999-1.i386, rpm, and cyrus-sasl-1.5.11-2.i386. The first two packages, openssl and libsas, are pretty obvious because RPM lists them as the first dependencies needed by sendmail-8.11.0-1.i386. An examination of the type of files provided by each package shows that they provide every dependency except libsas1.so.7. A search for libsas1.so.7 tells us that it is found in cyrus-sasl-1.5.11-2.i386. We download the three packages and install them as shown in Listing 3.8.

## Listing 3.8 Fixing Dependency Problems for Sendmail 8.11

```
[root] rpm -i openssl-0.9.sa-1.i386.rpm
error: file /usr/share/man/passwd.1 from install openssl-0.9.sa-1
conflicts with file from package passwd-0.58-1
[root] rpm -i --replacefiles openssl-0.9.sa-1.i386.rpm
[root] rpm -i libsasf1999-1.i386.rpm
[root] rpm -i cyrus-sasl-1.5.11-2.i386.rpm
[root] rpm -i U sendmail-8.11.0-1.i386.rpm
[root] rpm -q sendmail
sendmail-8.11.0-1
```

Even this installation didn't go completely perfectly. The openssl-0.9.sa-1.i386 package creates a new passwd man file. The problem is, it doesn't own the old page. That page was put on the system by the passwd-0.58-1.i386 package. RPM won't let a new package change a file that belongs to another package unless you tell it to. In this case, we want the new passwd documentation so we use the --replacefiles argument with the rpm command to replace the old passwd documentation with the new documentation.

All of the other installations run smoothly. Once the dependencies are resolved, sendmail-8.11-0.1.i386.rpm installs without complaint. A quick query to RPM shows that the new package is installed.

Next, restart Sendmail to make sure the newly installed daemon is running, and run a quick test to make sure the new daemon is alive and servicing the SMTP port. Listing 3.9 shows these two commands.

## Installing Sendmail

The -V option prints out a line for each file in the package. Each letter or number indicates a failure and each dot indicates a test that passed. Values are printed at the beginning of the line to indicate which tests were failed. The possible values are:

- S indicates that the file has the wrong size.
- M indicates that the file has the wrong type.
- 5 indicates that the file has an incorrect MD5 checksum.
- D indicates that the file is located on the wrong device.
- L indicates that the file is a symbolic link.
- U indicates that the file has the wrong user ID (UID).
- G indicates that the file has the wrong group ID (GID).
- T indicates that the file has the wrong creation time.
- C indicates that the file is a configuration file that is expected to change.

In the previous example, two files have the wrong checksum and the wrong creation date, and they are the wrong size. These are all things you would expect because these are not the original files. The file that were installed over the original is the S0sendmail script we deleted in Listing 3.3. All of the other files associated with the Sendmail RPM check out. But even these three errors might set off alarm bells with the system's computer security officer. For this reason, clean out the RPM installation before installing Sendmail from source code as described in the following section.
