# AUTH DIGEST-MD5 The AUTH keyword advertises the type of authentication supported by this server. In this case, the server supports Message Digest 5 (MD5) for authentication. The AUTH extension is defined in RFC 2554 (“SMTP Service Extension for Authentication”).

There are also a few keywords in this list that are not standard services. VERB sets the remote mail server in verbose mode. ONEX limits the SMTP session to the transfer of a single message. XUSR is used when a mail agent sends mail directly to a remote server instead of passing it through a mail transfer agent, such as Sendmail. (I don't know of any mail agents designed to work this way.) VERB, ONEX, and XUSR are specific to Sendmail version 8; they are not defined in an RFC.

# Mailbox Protocols

SMTP moves mail between e-mail servers, and MIME allows that mail to contain anything the user want to send. SMTP is the protocol implemented by Sendmail, but it is not the only protocol used in delivering the mail to the end. As we saw in List 1.3, Sendmail stores the mail it receives in a mailbox on the Linux server. Any user that can log to the server can read their mail. Many users, however, cannot or don't read their mail on the server. Those users want to move the mail from the server box to a mail reader located on their desktop systems. There are two popular protocols designed to move mail from the mailbox server to the desktop client: Post Office Protocol (POP), which is the traditional mailbox protocol, and Internet Message Access Protocol (IMAP), which has recently become more popular.

A Sendmail server turns into a mailbox server when it runs either the POP or the IMAP daemon. All Linux systems can run both. Both POP and IMAP can be installed during the initial installation or later using a package manager like RPM. The POP and IMAP protocols are simple command/response protocols very similar to SMTP.

# Post Office Protocol

The POP protocol verifies the user's login name and password, and moves the user's mail from the user's local mail reader. There are two versions of POP: POP2 and POP3. Both protocols perform the same basic functions, and they both create connections using TCP to ensure reliability and data sequencing. The two protocols are incompatible. POP2 uses TCP port 109 and POP3 uses TCP port 110. Linux systems with both versions of POP, but most clients use POP3. For that reason, this section describes only the POP3 protocol.
