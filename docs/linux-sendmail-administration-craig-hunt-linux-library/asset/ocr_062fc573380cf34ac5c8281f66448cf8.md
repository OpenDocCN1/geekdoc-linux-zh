+   - Use either the genericstable or the user database to process sender addresses, don't use both. If you use the user database, don't use maildrop to replicate recipient names already covered by the aliases.

+   - Use the access database to control mail delivery and relaying. It provides finer control than the relay-domains file. Only use relay-domains where it is adequate to the task, such as small departmental systems that don't need the full range of services provided by the access database.

+   - Use the virtertable if you truly need to support virtual domains. Data-base only applies to e-business sites and ISPs.

+   - Use the mailertable if you use procmail for non-local mail. Most other uses of the mailertable are less optimal solutions for real problems. For example, upgrading the external system to accept Extended SMTP is a better solution than using the mailertable to force mail through smtp8.

+   - Solve DNS transition problems with proper DNS configuration. Avoid using domaintable as anything other than a short-term fix.

+   - Don't use the trusted-users file, the bitdomain database, or uucpdomain database.

The Sendmail databases are the final topic in Part 2, “Essential Configuration,” and they are the most frequently used tools of basic configuration. But they can. In the next part of this book, we drill deeper into the configuration and look at ways we can customize Sendmail at this deep level.
