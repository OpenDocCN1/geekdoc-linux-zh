# 168 Chapter 6 Using Sendmail Databases

Returning error messages is not the only thing that can be done with the mailertable that replicates a feature of the virtertable. It is possible to use the mailertable to route mail for a virtual domain. For example, the following entry routes mail addressed to anyone in the bridal-gowns.com virtual domain to the user account jill:

.bridal-gowns.com local:jill

The advantage of using the mailertable for virtual domains is that, if you are already using the mailertable for some other purpose, you can do everything in one file. The disadvantage is that you cannot specify individual users in the virtual domain, only domain names, and you don't get the cool features of the virtertable, such as the ability to capture and retrieve usernames with the %1 variable. I prefer virtertable.

One other thing you can do with the mailertable is to use it to route all of the mail to a central mail server. Suppose you have a Red Hat Linux system that you wanted to configure sending all of its mail to mailserver.foobirdsorg for processing. You could create a custom map configuration on the client with a define command that sets SMART_HOST to mailserver.foobirds.org, or you could simply create a mailertable with a single entry:

esmtp:mailserver.foobirds.org

SMART_HOST is a variable in the map configuration file that can be set to the name of a mail server that handles all outbound mail for the client. The mailertable entry does essentially the same. The dot (.) in the first field matches all domain names. This means that all non-local mail will be sent through the essmtp mailer to .foobirds.org for delivery. This is exactly what we want for our imaginary client, and it has nothing to do with what the SMART_HOST define have given us. But this is simpler.

Once a mailertable source file is built, it must be processed through makemap. By default, Sendmail expects not to deal with a server that cannot handle standard Internet mail. Time has already solved most of the incompatibilities that made the mailertable and the wide variety of mailers necessary. The other uses of the mailertable can be performed by other databases. This command has nothing to do with the FEATURE(local_procmail) command. The local_procmail feature causes Sendmail to use procmail as the local mailer.
