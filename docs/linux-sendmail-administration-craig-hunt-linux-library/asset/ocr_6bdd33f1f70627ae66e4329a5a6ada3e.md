Assume the following input address:

```
rebafroeagle
hawk %1<mailhub.aol.com>
eagle %1<mailhub.yahoo.com>
dove %1<mailhub.excite.com>
```

Further, assume the database with the internal Sendmail name of "hubs":

Finally, assume the rewrite rule:

```
R$+-@$ ($$ $2 $1 $)
```

The input address rebafro@eagle matches the pattern because it has one or more tokens
(rebafro) before the literal and exactly one token (eagle) after it. The pattern match
creates two indefinite tokens. The template calls the database hubs and passes it token $2
as the key. The template also contains $0 that says that token $1, which contains
afro, is passed to the database as an argument. The database program uses the key
e to retrieve %1@mailhub.yahoo.com, then uses the rebafro to replace %1,
an returns rebafro@mailhub.com to Sendmail.

Before a database can be used, it must be defined in the configuration. This is done with
t K command. To define the database file used in the example above, we might
enter the following command in the sendmail.cf file:

```
Hubs hash /etc/mail/hubs
```

The sample hubs database is shown only to illustrate the syntax used to access a database
from a rewrite rule's template. In reality, there are already many databases available
for Sendmail that you use without creating any of your own. (See Chapter 6,
"Using Sendmail Databases.") It is far likely that you will use one of the databases
that come with Sendmail than you will create one of your own. Listing 8.9 demon-
strates the database syntax using the standard virtuous database we created in
Chapter 6.
