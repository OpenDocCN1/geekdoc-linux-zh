from foobirds.org if MASQUERADE_AS(`foobirds.org`) is used with the default settings. But if FEATURE(`limited_masquerade`) is also used, the mail goes out as mail from bridal-gowns.com, unless you explicitly add bridal-gowns.com to class M.

Use MASQUERADE_DOMAIN to add individual values to class M. For example, to add hawk.foobirds.org to class M, adding the m4 macro to the macro configuration file:

```
MASQUERADE_DOMAIN(`hawk.foobirds.org`)
```

The MASQUERADE_DOMAIN is most useful when only a few values need to be added to class M and when those values change infrequently. Use the MASQUERADE_DOMAIN_FILE to load class M from a file when you have more than a few domain names you wish to masquerade. Assume that you want to load class M from a file named /etc/mail/masquerade-domain-names. You could add the following m4 macro to the configuration file:

```
MASQUERADE_DOMAIN_FILE(`/etc/mail/masquerade-domain-names`)
```

As the name MASQUERADE_DOMAIN implies, the values stored in class M do not have to be hostnames; they can be full domain names. By default, the hostname portion of the input address must exactly match a value in class or class M to be rewritten to the masquerade value. Thus, if class M contains terms.foobirds.org, the input address kerstan.terms.foobirds.org is rewritten unless the address kerstan.sooty.terms.foobirds.org is not rewritten. This means that if the name of the domain is found in class or M use FEATURE(`masquerade_entire_domain`) to change this default behavior so that every component of a domain in class or class M is masqueraded. If masquerade_entire_domain is specified and class M contains terms.foobirds.org, the input address kerstan.terms.foobirds.org is rewritten and so the address kerstan.sooty.terms.foobirds.org. Listing 9.4 illustrates the effect that these have options on masquerading.
