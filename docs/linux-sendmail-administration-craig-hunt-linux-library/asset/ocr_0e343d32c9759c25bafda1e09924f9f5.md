All of this information—the internal name, the base type, and the file that holds the database—defined by the K command is the direct result of the FEATURE(`access_db`) command from our sample marco configuration file. The access database, which is used to control mail relaying and delivery, is covered in Chapter 6.

The two K commands define the virtuer and mailertable databases that result from the following commands found in the sample marco configuration file:

```
FEATURE(`mailertable`, `hash -o /etc/mail/mailertable`)
FEATURE(`virtuerable`, `hash -o /etc/mail/virtuerable`)
```

Both are hash databases, and both the -o switch, which means that Sendmail will run even if these files are not found. The K command for the access database did not use the -o switch. If /etc/mail/access.db is not found, Sendmail will fail if a command attempts to use the access database. Even if you don't have entries for the access database, create an empty /etc/mail/access.db file in order to make Sendmail robust, as in this example:

```
[root]# touch /etc/mail/access
[root]# makemap /etc/mail/access < /etc/mail/access
```

The mailertable, the virtuerable, and the access database are all covered in Chapter 6. The other databases, however, were not covered in Chapter. Both the ar and devote databases are pseudo-databases. That means they are not real databases. Instead they are internal Sendmail routines that are accessed by rewrite rules as they were databases. The devote map, which has already been discussed, is used to remove quotation maps from addresses. The arith map is used to do arithmetic functions for STARTTLS security. STARTTLS is covered in Chapter 12.

The four commands, D, C, F, and K, illustrate everything that is in the Local Info section of the sendmail.cf file. The Local Info section is the most important section of the file from the standpoint of a system administrator trying to configure sendmail.cf, because it defines the configuration information that varies from system to system. We have covered every command in the Local Info section of our sample system, but before moving on to the Options section, we should cover the only configuration command that occurs before the Local Info—the version command.
