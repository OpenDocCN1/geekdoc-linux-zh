
The sendmail.cf file is created from a macro configuration (.mc) file that usually contains fewer than 20 lines of m4 commands. The m4 commands that you will use to build a basic Sendmail configuration are listed in Table 4.1.

## Table 4.1 Common m4 Commands

| Command | Usage |
| --- | --- |
| define | Defines a value for a configuration variable. |
| divert | Directs the output of the m4 process. |
| dnl | Deletes all characters up to, and including, the next newline character. |
| DOMAIN | Selects a file containing attributes for your specific domain. |
| FEATURE | Identifies an optional Sendmail feature to be included in the configuration. |
| MAILER | Identifies a set of mailers to be included in the sendmail.cf file. |
| OTYPE | Selects a file containing operating system-specific attributes. |
| undefined | Clears the value set for a configuration variable. |
| VERSIONID | Defines version control information for the configuration |

The commands shown in Table 4.1 are the most used m4 macro commands. All of the commands shown in uppercase are macro commands defined in cfhead. The commands shown in lowercase are built-in m4 commands. The subset of commands shown in Table 4.1 is all you need to build a basic configuration. As such, they deserve a more thorough explanation.

## Controlling m4 Output

The m4 program is a stream-oriented macro processor. It views the data it handles as a stream of text characters. It collects input data from various files, expands macros embedded in those files, and directs the output stream of characters to another file. Two of the commands in Table 4.1 are used to control the stream of output characters: divert and dnl.

## The m4 Macro Language

The divert command directs the output stream to different targets. As of Sendmail 8.11, there are 11 different targets for the data stream. The 11 possible divert values are listed in Table 4.2.

## Table 4.2 Possible Values for the divert Command

| Value | Meaning |
| --- | --- |
| -1 | Discard output. |
| 0 | Send this data through normal processing. |
| 1 | Use this data for hostname resolution. |
| 2 | Add this data to ruleset 3. |
| 3 | Add this data to ruleset 0. |
| 4 | Add this data to the UUCP-specific sections of ruleset 0. |
| 5 | Use this data to define domain names this server will relay. |
| 6 | Add this data to the Local Info section of the sendmail.cf file. |
| 7 | Save this data as a mailier definition. |
| 8 | Use this data to define spammers blacklist. |
| 9 | Add this data to ruleset 1 or 2. |

Most of the values that can be specified with divert are used only by the Sendmail developers, who are in use, as buffers to hold data for specific parts of the sendmail.cf file. The data is collected in these buffers and then moved to the sendmail.cf file in the final stage of processing. It is possible to use any of these values in a configuration, but unlikely and unnecessary commands exist send data to the correct buffers without resorting to divert commands. For any reasonable configuration, the divert command is used with only two settings:

- divert is set to -1 to discard the output. divert(-1) is found at the start of a block of text that is not written to the sendmail.cf file. While the block of text could be anything that's not intended for the output file, it is usually the copyright statement that is found at the beginning of many of the sample configuration files. The divert(-1) command at the start of the copyright means that the copyright is treated as a large comment.

- divert is set to 0 to divert the stream to the output file—e.g., sendmail.cf. If the divert(-1) command is used at the start of a large comment, divert(0) is used at the end of the comment to redirect the stream to the output file.

The dnl command also used to control the output stream. The dnl accepts arguments. Its two basic functions are determined by its position on the command line:

- If the dnl occurs at the end of a line, after another m4 command, it is used to clean up unblank lines from the output file. For example, dnl on the line OSTYPE(linux)dnl ensures that any extraneous output generated after the linux OSTYPE command is expanded to get written to the sendmail.cf file.

- If the dnl occurs at the beginning of the line, the line is treated as a comment. For example, the line lineNext define the domain name is a comment. The sample line did not begin with dnl, m4 would interpret “define” and “domain” as m4 commands. Messy! Always start each comment line with dnl, unless it is a large comment bracketed by divert commands.

The divert and dnl commands direct m4 output but do not define or generate the out data. The other m4 commands are used to generate the actual configuration file.

## The Basic Commands

In terms, there are two types of files used to build an m4 configuration. One of these is the macro configuration file, which is traditionally identified by the .mc extension. macro configuration file is the input file for the m4 command, and its name appears on the m4 command line. The other files are m4 source files that are referenced by the macro configuration file. Traditionally, m4 source files are given the file extension .m4. Almost all m4 commands from Table 4.1 can appear in either type of file, although the three of the commands are generally found only in the macro configuration file:

- OSTYPE The m4 is required, and it is always found in the macro configuration-file. The OSTYPE command loads an m4 source file that defines operating system-specific information. File and directory paths, mailnames, and system-specific mail arguments are the kind of information generally found in an OSTYPE file. The Sendmail source distribution provides more than 40 predefined operating system macro files, and you can create one for a specific Linux distribution if you like. (We discuss this option when we evaluate the vendor-supplied macro configuration files in the next chapter.) The only argument passed to OSTYPE command is the name of the m4 source file that contains the operating system-specific information. Here is the command that processes the linux.m4 OSTYPE source file:

```
OSTYPE(linux)
```

- DOMAIN The DOMAIN macro loads a file that contains information specific to your domain. The DOMAIN source file is a perfect place for commands that affect hostnames and domain names, and define values, such as relay names, because the information is specific to your domain, you must create your own DOMAIN file. The Sendmail code distribution provides a sample DOMAIN file, named generic.m4, that you can use as a starting point for creating your own. As you created a DOMAIN source file called foobirds.m4. The following command, placed in the macro file, uses foobirds.m4 to help in building the sendmail.cf:

```
DOMAIN(foobirds)
```

The DOMAIN command is optional. When it is used, it normally appears only in the macro configuration file.

- MAILER The MAILERS identify the various sets of macro definitions that should be included in the sendmail.cf. A usable configuration must have at least one MAILER command; almost every Linux configuration has the following two:

MAILER(local) The MAILER(local) macro command adds the local mailer and the prog mailer to the configuration. The local and prog mailers are essential, so any usable configuration will have this MAILER command.

MAILER(smtp) The MAILER(smtp) macro adds mailers for SMTP, Extended SMTP, eight-bit SMTP, directed SMTP, and relayed mail. Every Linux system that sends SMTP mail, whether directly or through a mail server, has this MAILER command.

In addition to these two important sets of mailers, there are nine other sets of mailers available with the MAILER command. Most of them are very little interest to the average system administrator, but for the sake of completeness they are all covered in Appendix A, "m4 Macro Reference."

OSTYPE, DOMAIN, and MAILER are generally found only in the macro configuration file. The other four commands are found in Table 4.1 in both macro configuration and macro source files:

VERSIONID The VERSIONID macro defines version control information. This macro is optional, but is found in m4 files. The command has no required format for the argument. Use any version control information you desire. The basic format of the VERSIONID macro is:

```
VERSIONID(`version-control-data`)
```
