NOTE newaliases is not really a program; it is a link to Sendmail. The aliases database can also be built by running sendmail with the -bi argument-e.g., sendmail -bi.

The next 15 lines in Listing 6.5 define aliases for special names. All of these, except the webmaster alias that I added, were pre-configured in the Red Hat aliases file. The first two, MATLER-DAEMON and postmaster, are aliases that people expect to find on any system Running Sendmail. Most of the others are assigned to the daemon usernames that are found in the /etc/passwd file. No one can actually log on the daemon usernames, so any mail that may be directed to these pseudo accounts is forwarded to the root user account. In the example, this mail is forwarded to the root user account.

Of course you don't want people logging onto the root account just to read mail, so the aliases also has an alias for root. In the example, I edited the root entry to forward all mail addressed to root to staff, which is another alias. Notice how aliases point to other aliases. Doing so is very useful because it allows you to update one alias instead of many when the root user account that the mail is delivered to changes.

The staff alias is a mailing list. A mailing list is simply an alias with multiple recipients. In the example, several people are responsible for maintaining this mail server. Messages addressed to root are delivered to all of these through the staff mailing list.

Two aliases are associated with the mailing list. The owner-staff alias is used by Sendmail for error messages reporting to the staff mailing list. The format Sendmail requires for this special alias is owner-list, where list is the name of the mailing list. The other special alias, staff-request, is not required by Sendmail but it is expected by remote users. By convention, manual mailing list maintenance requests, such as being added or deleted from a list, are sent to the aliases list-request, where list is the name of the mailing list.

The last nine lines are user aliases I added to the file. These lines direct mail received at the mail server to the computers that users read directly. The first alias directs the mail server receives for Jill (Refer back to Listing 6.3). Remember that we discussed class w, it was pointed out that simply adding a hostname to w does not mean that the server will be able to handle the mail for a specific user on remote host. The user needs either an account on the server or an alias in the aliases database. This alias means that it is not necessary to create a user account for Jill on the mail server because her mail is forwarded to egret.foobirds.org. it is egret's job to see that Jill gets her mail.
