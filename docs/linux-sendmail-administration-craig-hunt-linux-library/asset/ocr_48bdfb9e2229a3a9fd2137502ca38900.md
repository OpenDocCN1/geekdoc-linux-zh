# Securing a Sendmail Server

Many discussions of Sendmail security focus on spam controls and relay configuration. In those discussions, sendmail is viewed as a form of denial of service called theft of service. I find that view of mail too extreme: service is an annoyance; it isn't a security threat. Real Dos attacks overwhelm the server and effectively block inbound and outbound bound. (For example, a mail-bombing attack delivers so rapidly to a single target that the target system is unable to keep up with the workload.) Sendmail provides a few parameters that can be used to deal with real denial of service attacks.

MAX_DAEMON_CHILDREN This parameter defines the maximum number of Sendmail processes that can be running simultaneously. Every system has an upper limit on the number of processes it can effectively handle. A variety of Dos attacks are designed to overwhelm a system by launching so many processes that the system is no longer able to do any productive work. The confMAX_DAEMON_CHILDREN parameter protects the operating system from this type of attack.
