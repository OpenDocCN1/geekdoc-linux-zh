## More Rulesets

The rules described so far are only called directly by Sendmail. There are many more rules defined in the sendmail.cf file. For example, the sendmail.cf file created by the redhat.mc macro configuration has 47 rulesets. Other rulesets provide additional address processing. They include those rulesets identified as S and R in Figure 8.1 and those called from inside the sendmail.cf file by individual rewrite rules or H commands. Rulesets are called using the $name syntax, where name is the name or number that identifies the called ruleset. We'll see more of the $name syntax later when we discuss rewrite rules.

Table 8.1 lists the rulesets you will find in the Rewriting Rules section of your sendmail.cf file. It identifies each ruleset by name, and when applicable by number, and provides a short description of the purpose of the ruleset. The rulesets are listed in the order in which they occur in the Rewriting Rules section.

| Name | Number | Purpose |
| --- | --- | --- |
| canify | 3 | Puts addresses in a standard internal format. |
| final | 4 | Converts addresses to external formats. |
| parse | 0 | Selects the mailer for a delivery address. |
| localaddr | 5 | Processes local addresses. |
| Mailertable | 90 | Matches domain names against the mailertable. |
| MasqHdr | 93 | Masquerades header names. |
| MasqEnv | 94 | Masquerades envelope names. |
| LookupDomain | | Finds domain names in the access database. |
| LookupAddress | | Finds hostnames in the access database. |
| ParseRecipient | | Converts recipient addresses to the proper address format for relaying. |
| check_relay | | Checks relaying for the anti-spam features. |
| check_mail | | Checks sender addresses for the anti-spam features. |
| check_rcpt | | Checks recipient addresses for the anti-spam features. |
| trust_auth | | Tests whether or not the AUTH parameter should be trusted. |
| tls_client | | Verifies the TLS connection to a client. |
| tls_server | | Verifies the TLS connection to a server. |

Table 8.1 shows only part of the rulesets found in the Rewriting Rules section. There are several other rulesets that are subroutines of these rulesets or are called by these rulesets to complete their tasks.

## Basic Rulesets 223

- canonify has a subsection named Canonify2, also known as ruleset 96, which is used to obtain canonical hostnames from DNS.
- parse has two subsections named Parse0 and Parse1, and a subroutine named ParseLocal (ruleset 98) that it calls to handle local addresses.
- Mailterable MailerToTriple, which is also known as ruleset 95, to help convert mailterable entries to mail deliveries, and it uses CanonLocal to put local names from the mailterable into a standard format.
- ParseRecipient uses Addr to put addresses into the standard format, which Addr does by simply calling Parse0 and Canonify.
- The bulk of the work of check_relay, check_mail, and check_rcpt is handled by subsections named Basic_check_relay, Basic_check_mail, and Basic_check_rcpt. In turn, Basic_check_rcpt calls RelayAuth to check client authentication when required. SearchList is another routine called by check_mail and check_rcpt to process an internal syntax used by these anti-spam filters. Recall the (src) class mentioned in Chapter 7; SearchList is what is used.
- tls_client and tls_server call tls_connection to get the connection verified. tls uses turn max to determine the appropriate number of cipher bits used. Transport layer security is discussed in Chapter 12, "Sendmail Security."

Rulesets with rulesets rulesets rulesets segment the complex task of processing e-mail. This makes the task of processing mail manageable in turn creates confusion for the system administrator trying to understand what these rulesets do. My advice is: "Don't worry about it." A general idea of what these rulesets do is all that is required for Sendmail mastery. You don't need to modify the rulesets of Sendmail, even to create an advanced custom configuration. Instead, Sendmail provides empty rulesets for your hooks:

- sender (ruleset 1) is available for custom processing of sender addresses. See the LOCAL_RULE discussion in Chapter 9.
- recipient (ruleset 2) is available for custom processing of recipient addresses. See the LOCAL discussion in Chapter 9.
- localaddr (ruleset 5) is available for custom processing of local addresses.
- check_relay is available for custom processing of relaying. See the relay discussion in Chapter 9.
- check_mail is available for custom processing of sender addresses. See the mail discussion in Chapter 9.
- check_rcpt is available for custom processing of recipient addresses. See the rcpt discussion in Chapter 9.
- trust_auth is available for custom processing of the AUTH parameter. See the auth discussion in Chapter 9.
- tls_client is available for custom processing of the TLS connection. See the client discussion in Chapter 9.
- tls_server is available for custom processing of the TLS connection. See the server discussion in Chapter 9.

## Mailer Rules

Despite the large number of rulesets found in the Rewriting Rules section, it is not the only place in sendmail.cf where rulesets are found. The Mailer Definitions include three rulesets:

```
MAILER(local)
MAILER(smtp)
MAILER(proc)
```

Most of these rulesets deal with rewriting sender and recipient addresses in the envelope and the header. That's to be expected. After all, the S and R parameters of the mailer command (M) identify the rulesets used to rewrite sender addresses and recipient addresses for a specific mail. It is only natural that these rulesets are included in the Mailer Definitions section of the sendmail.cf file.

## Listing 8.1 Two Simple Rulesets

```
#
# Envelope recipient rewriting
#
EnvToL=20
R$+ <@ $ >       $: $1               strip host part

#
# Header sender rewriting
#
SHdrFromL=30
R<$>             $n               errors to mailer-daemon
R<@ @ $%         $n               temporarily bypass Sun bogosity
R$+               $: $>AddDomain $1  add local domain if needed
R$*               $: $>Masqdr $1     do masquerading
```
