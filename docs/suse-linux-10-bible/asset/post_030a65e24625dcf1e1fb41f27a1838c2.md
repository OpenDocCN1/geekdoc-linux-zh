## Configuring Your Sound Card

YaST will detect the sound card and set it up automatically. During a standard installation, you are not required to intervene in this process; it happens. In almost all cases, that is all you need to know. The rest of this section concerns what you can do after installation if it turns out that sound was not configured correctly during the installation.

After the installation is complete, confirm that sound is working by attempting to play a music CD or music file (for example, an MP3 file using the x mms player program). If you don't hear sound at this stage, first check the physical connection to the speakers. Then (if you are using KDE) check that the KDE volume control is a sensible setting and not disabled or turned down to zero. In the unlikely event that sound fails to work, you can rerun the YaST sound module in expert mode. The sound module is found in YaST's Hardware section. You will find three possible setup modes:

- **Quick automatic setup**—This is the default and the one that is used during installation.
- **Normal setup**—This enables to test the sound card. There is a volume control and a test button. When you have set the module, a test sound is played when you press test.
- **Detailed installation of sound cards**—If you choose this option, you will be taken to a screen where any configurable options for the particular sound card that has been detected can be set. On the particular card, this may include settings to enable a joystick and MPU (midi processing) ports.

If even experiment with the detailed installation options fails, you can find the low-level alsconf program. As root, type **alsconf** to start the program. It is a text-based program that, in fact, provides the back end for YaST's sound configuration module, but running it standalone gives you the opportunity to use its command-line options, including alsconf -i which writes a log file to /tmp/alsconf.log that may give you a clue to the problem.

> [!TIP]
> The ALSA (Advanced Linux Sound Architecture) home page can be found at www.alsa-project.org. This is the best place to start if you have any difficulties with configuration of sound on Linux.

## Commonly Used Shell Features

### 101: The Shell

Commands issued on the command line on any computer system are read and executed by a program known as a command interpreter. A command interpreter does the following:

- Reads the commands and any options that you provide
- Translates or expands any special characters such as * and ? used as wildcard
- Locates the command that you want to execute
- Executes with the appropriate options and displays any output

On Linux and Unix systems, a command interpreter is known as a shell. Linux and Unix systems offer many different shells, each of which has its own special features and devotees. There are several shells included in the SUSE system, including ash, csh, ksh, tch, and zsh. They all have their advantages and disadvantages, and some users have strong preferences for one shell over another. bash has become the effective standard on Linux, and from now on all the examples in the book will assume that you are using the bash shell.

Tip: Linux systems, the list of "legal" shells is maintained in the file /etc/shells. The contents of this file list the shells that can be started when you log in on the system.

In addition to being able to execute standard Linux commands for you, each of these shells supports its own command language. Files written in the command language provided by a shell are known as shell scripts. The first line of a script typically identifies the shell that should be used to run the command script. If no shell is identified in the first line, a shell script is executed by the sh shell, which is usually the same as the bash shell.

By default, when you use the command line on a SUSE system, you are using the bash shell. If you have not used bash or a similar shell in the past, particularly if you have bad memories of the DOS command line, you may not realize how powerful the command line can be. Experience shows that people who come to Linux from a Windows background tend to start trying to use graphical tools (for example, copying files by dragging from one Konqueror window to another) but gradually realize the command line is both a quicker and easier way to perform many tasks.
