## mutt
mutt is a more feature-filled command-line mail client that can display your mail in a formatted list and also employs mail message threading. It is a lot more interactive than mail, but can be used on the command line as your daily mail client. If you want to use mutt, install it through the YaST package manager.

## The Graphical Mail Clients

For Linux users, the choice of mail client usually boils down to the desktop product they use. KDE comes with the kmail client, whereas Gnome comes with the Evolution mail client. Both are quite different beasts.

## kmail

kmail is a very nice, well-rounded mail client that can connect to POP, IMAP, and also local spool to read your mail. You can set up rules to send mail to specific folders based on certain parameters and can also connect to mail servers over SSL.

## Evolution

Evolution is more of an “Outlook for Linux” application that it incorporates not only mail, but calendaring, address book, and tasks under the same roof. Whereas kmail you use separate applications for this functionality, Evolution has them built in.

> Recently, Ximian opened their Connector product, which also enables you to connect your Evolution client to a Microsoft Exchange 2000/2003 server and access your calendars and so on.

## Mail Systems on Linux

Mail on Linux is a funny thing; there are many ways to provide mail services on any Unix system in general, from using sendmail or Postfix as an MTA to Qpopper or Cyrus as an MDA, all the way to choosing among numerous MUAs for reading your mail. At the end of the day, it is up to how you want to configure mail on your system. We've given you enough information to proceed, and you will quickly find the variety of choices available will enable you to implement a solution that meets your needs.

Regardless of how you feel about Microsoft Windows, it's impossible to ignore that most businesses use it for day-to-day activities. The prevalence of Windows makes it important for Linux systems to be able to access Windows resources such as Windows file servers and printers. Similarly, the power of Linux as a corporate computing makes it important for Windows systems to be able to access file servers from Linux. Interoperability with other types of computer systems and network communication mechanisms is an important aspect of the power and flexibility of Linux and is one of the keys to being adopted in both the home- and enterprise-computing environments.

Interoperability between Windows and Linux network resources is provided by a set of client/server applications known as the Samba software. Linux systems that need to be able to access resources (and therefore need to be able to act as a client of Windows resources) do so by running a Samba client. Linux systems that need to export resources to Windows users do so by running a Samba server that makes those resources available over the network in a form that Windows systems can access.

This chapter explains how to configure both Samba clients and servers, explains various authentication models for Samba servers, and discusses graphical and command-line utilities that make it easier to explore and interact with Windows resources from your SUSE Linux system. The last section highlights the Samba-based packages that are available in SUSE distribution and explains how to locate and install any that you might not have initially installed on your system.

## A Bit of Background

The SUSE Linux kernel features built-in connectivity with networked Windows resources by supporting the Windows Server Message Block (SMB) protocol that underlies most native Windows networking mechanisms. The SMB protocol is now considered a part of Microsoft's more general Internet File Services (CIFS), but its name lies on the Samba software suite.

Acronyms reign supreme in the network world, most of which are related to history of various standards and protocols. This is especially true for the long list of network protocols used by DOS and Windows. When Microsoft decided network support was a goal, it began introducing the NetBIOS (Network Basic Input/Output System) in 1984 to define and control the characteristics of network communication from a DOS or Windows system. To implement this transport, Microsoft provided the NetBEUI (NetBIOS Extended User Interface) protocol. NetBEUI worked fine on small networks of the day but was missing basic features, such as routing, that were required as networks became larger and distinction between connected became increasingly important. From 1985 through 1988, Microsoft worked with IBM and introduced to popularize SMB, which is a NetBIOS implementation that runs over TCP/IP networks. If you are collecting acronyms, SMB is the most common example of what is generally known as NBT (NetBIOS over TCP/IP), also known as NetBT.

As discussed in Chapter 6, TCP/IP has been the networking protocol associated with Linux and Unix systems. Samba was originally developed by Andrew Tridge (“tidal”), who initially began development of what would later become Samba on DEC and Sun workstations in 1991. He began work on port Samba (then known as NetBIOS for Linux or smserver) in 1992. J.R. Coullin and Dave Fenwick introduced an SMB-related newsgroup, comp.protocols.smb, as a forum for discussing Samba development; server renamed Samba in 1994 because of conflicts with the name of an existing product, and the rest is history.

Today, Samba is used on Linux, FreeBSD, FreeBSD, Solaris, AIX, HP-UX, and any Unix and Linux-system. SUSE provides an up-to-date version of Samba 3 introduces several significant enhancements over previous versions, including the following:

- Support for Microsoft Active Directory. This also provides support for Samba servers as member servers in Active Directory domains.
- Improved Unicode and internationalization.
- Improved support for the updated printing system used by Windows 2000 and XP.

For detailed information on Samba 3.0 and migration issues for other servers, we see the Samba HOWTO collection. These sets of documents is installed on your system as part the samba-doc package. When you have installed the samba-doc package, the Samba HOWTO collection is available in the file /usr/share/doc/packages/samba/Samba-HOWTO-Collection.pdf. You can also find the Samba HOWTO collection online.

## Setting Up and Using a Samba Client

Most desktop SUSE users who work in an environment where Windows systems are also used to configure and start a Samba client on their machines. A Samba client on your system enables you to access Resources such as printers and file servers on your local network. A Samba client does not enable your system to export filesystems and printers to your local network — to do that, you will need to configure and start a Samba server on your system, as explained in “Setting Up a Samba Server,” later in this chapter.

## Configuring a Samba Client

Like most administrative tasks on a SUSE Linux system, configuring and starting a Samba client is mostly easily done by YaST. If you are running the X Window system KDE desktop environment, you can execute by YaST from the Control Center menu, which is available by clicking the SUSE icon at the bottom-left corner of your KDE desktop. If you start YaST as the root user, the YaST dialog box is displayed.

> Note

If you start YaST as any other user, the KDE su dialog box is displayed. Enter your root password, and the system will start YaST for you as the root user.
