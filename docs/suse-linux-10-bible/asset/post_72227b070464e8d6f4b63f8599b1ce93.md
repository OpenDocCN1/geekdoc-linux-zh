To create a partition, press n (new partition). After entering n, fdisk prompts for the type of partition that that you want to create: p (primary) or e (extended). As you already have three partitions, creating an extended partition will use all of your primary partitions. However, as you are creating an extended partition, you can add more logical partitions when needed.

After entering e to create an extended partition, fdisk prompts you with a suggested value for the starting cylinder for the new partition. This is always the first available cylinder on the disk—which is not already allocated to an existing partition. Unless you have a specific reason not to do so, always accept the suggested first cylinder by pressing Return to accept the default value (in Listing 3-5 as <CR>, carriage return).

Next, fdisk prompts you for the size or cylinder of the partition that you are creating. You enter +2G to show that you want a 2GB partition, at which point the fdisk prompt replays. After entering p to the new partition map, you can see that you have created a 2GB-sized extended partition. This enables you to create logical partitions within it totaling no more than 2GB collectively.

> **Caution**  
> As mentioned previously, it is safe to experiment with fdisk on your primary system as long as you never write out the updated partition table. When you start fdisk, it creates an in-memory map for the specified disk and makes all of its changes. Never update your disk unless you actually use the (w) write command. Never write the command in fdisk unless you want to save your changes and update your disk. This can usually be undone, but if you have accidentally updated the partition table for your system boot drive, and have changed any existing partition definitions, your system may crash the next time it tries to read from disk. If you accidentally saved a bad partition table, you may recover it by booting from a disk and manually recreating the old partition table before you attempt to check the consistency of the drive (by using fsck). Unfortunately, this is impossible to guarantee, so be very careful when experimenting with fdisk.
