# groff

The document formatting system groff is used by the man system to create formatted pages (which are written in plain text with markup) from their source. It can also produce nicely formatted output.

This is not the place to talk about groff in general. However, you may have seen noticed justified files with a straight right-hand margin and wondered how they are produced. The same effect is seen in pages, and there is no accident because you can use groff (which is used to format pages) with the -Tascii option to produce formatted text in that way. It adds spaces to reduce the need for splitting words, and hyphenates reasonably sensibly. It certainly looks nice, and if you are writing a file that will be read in text format (for example, a long README file to distribute with some software), it gives a nice impression to format it in this way.

```
usersbible:> groff -Tascii filename
```

# a2ps

The a2ps command converts a file to PostScript and creates a file or sends it to the printer. If you simply type a2ps file, the file will be printed with a nicer header and footer showing the filename and datestamp, the name of the user who printed it, and the date of printing. You can control the way a2ps works with a variety of options; for example, this command:

```
a2ps -j -B -columns=1 file -o output.ps
```

# mpup and mpage

Although technically off for this topic, this is a good place to mention mpup and the other PostScript scripts use theutils package. mpup can take a PostScript file and create a new file with multiple pages per physical page. If you want to save trees and toner, this is something you might want to do. For example:

```
mpup -4 file.ps:fileup.ps
```

puts four pages file.ps per physical page in the output file.

For reasons known only to SUSE, SUSE distributions do not ship with mpage, which does what mpup does, but often does it better. The mpage RPM shipped with the current version of Fedora Linux install and run correctly on SUSE.
