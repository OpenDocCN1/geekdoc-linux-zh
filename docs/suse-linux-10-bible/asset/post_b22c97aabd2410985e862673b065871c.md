# Working with DVDs, CDs, and Floppies

It is very useful to be able to take a floppy disk, CD, or DVD and create an image file from it on your hard disk from which you can create new copies of the disk, possibly by modifying them first. You can even create a disk image of a hard disk partition or either hard disk if you have sufficient disk space.

# Creating and Using Images of Existing Disks

Linux makes it easy to work with disk images copying a disk (a floppy disk or CD or a hard partition) to a file is a simple matter.

```
user@bible:~ dd if=/dev/fd0 of=floppy.img
```

The dd command reads the raw data from the device /dev/fd0 (the floppy) and writes it to the image file floppy.img.

You can now mount this image (you may need to become root):

```
root@bible:~ ~ mount floppy.img /mnt -o loop
```

If you look in /mnt you see exactly the same files that you would have mounted the floppy disk. You need the option -o loop to the mount command to mount a filesystem from a file rather than a disk device. The -o loop option is discussed in more detail later in the chapter.

If you want to write the image back to another floppy, use the following:

```
user@bible:-> dd floppy.img of=/dev/fd0
```

This is exactly the same process in rescue: Now the input to the dd command is the image file, and you are writing to the floppy disk.

![](img/e4e45c9f32e76fb35fabbd21a96f1a1e_430_0.png)

> Be careful with the dd command. If you mix up the if= with the of= you could end up doing very seriously, particularly if one of them is a hard disk partition.

You can do the same with disk partitions:

```
root@bible:~ # dd if=/dev/hda of=imagefile
```

In this case it is certainly best if /dev/hda is not mounted at all.

This is what you might find yourself doing in the rescue system. For example, it's possible to imagine circumstances in which you might run the rescue system, get on the network, mount an NFS share from somewhere on the network, and copy the disk partitions to share to back them up before doing drastic changes to the system.

When you have copied the partition to a file, you can simply mount the file with the -o loop option:

```
root@bible:~ # mount imagefile /mnt -o loop
```

A CD image (ISO image) will work in exactly the same way; to copy a CD to an ISO, do the following:

```
user@bible:-> dd if=/dev/cdrom of=cdimage.iso
```

Again, you can mount it:

```
root@bible:~ # mount cdimage.iso /mnt -o loop
```

Just as you can copy a partition to a file and mount it using the loopback device (using the -o loop option), you can create a file and create a filesystem on it as if it were a disk partition. You can then write it out to a partition or to a removable device.

```
root@bible:/tmp # dd if=/dev/zero of=image.disk count=1440k bs=1
1474560+ records in
1474560+ records out
```

What you are doing is creating a file of exactly the same size as a standard floppy disk image (1440k) by reading from the /dev/zero device (which simply outputs a stream of null bytes).

Now you can create a filesystem on the file image.disk (which you need to root to do this):

root@bible:/tmp # mkfs -ext2 image.disk

# Creating ISO CD and DVD Images

Data CDs and DVDs almost always use the ISO filesystem (so called after the international standard that defines it). These are therefore referred to as ISO images. You could also create CD or DVD images, CDs, and DVDs using standard Linux filesystems (ext2, for example), but these will not be useful for exchanging data with users of other operating systems.

It is not essential to use the ISO 9660 filesystem when you create images to burn to CD; you can create a sizable EXT2 loopback filesystem and simply copy the files you want to. Under the 2.6 kernel, this is no longer the case. If you want to create a CD or DVD, the tool is mkisofs. The tool for creating ISO images is mkisofs. The difference is that mkisofs both creates the filesystem and writes to it.

The -J and -r options indicate that the ISO has Joliet and Rock Ridge extensions (this should mean it works on Windows, Mac OS). The -o indicates the name of the output file.

# Burning CDs from the Command Line

There have been changes recently in the way CD writers. Under the 2.4 kernel series, CD writers used the ide-scsi driver, which meant they worked using SCSI emulation. In 2.6, this is no longer the case. As a result, the userspace tools had to change.

If you want to burn disks from the command line, the tool to use cdrecord. If you are running a 2.6 kernel and your CD writer is an ATAPI device (almost all), then you will need to do something like:

```
root@bible:~ ~ cdrecord -v dev=/dev/hdc speed=8 -dao -data filename.iso
```

Here we are burning filename.iso to CD. The CD burner device is /dev/hdc (the second device on the IDE channel), and we are burning in disk at once mode (-dao) to produce a CD (-data). The speed has been specified as 8. This example assumes that you are running a 2.6 kernel.

If you are using a 2.4 kernel, ATAPI CD writers are treated as emulated SCSI devices using the ide-scsi module. In this case, the dev parameter will refer to the SCSI device (for example, typically dev=0,0,0 on a system with no SCSI devices: cdrecord --scanbus helps to find the correct device numbers).
