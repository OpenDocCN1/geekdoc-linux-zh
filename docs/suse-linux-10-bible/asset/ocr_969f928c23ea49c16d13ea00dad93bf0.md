# Chapter 25 ◆ Working with LDAP in SUSE

You can connect to the LDAP server with an anonymous bind, which means you have not presented authentication credentials to the LDAP server, and you are limited in what you can read and write to the server based on the default access control (ACL) settings.

# Listing 25-1: Authenticating to the LDAP Server

```
bible:etc/ldap ldapsearch -x -D "cn=admin,o=Acme,c=UK" -W
Enter LDAP Password:
# extended LDIF

# LDAPv3
# base <> with scope sub
# filter: (objectclass*)
# requesting: ALL
#
# search result
search: 2
result: 2 No such object

# numResponses: 1
```

As you do not have anything in the LDAP server, you will not receive any responses.

The ldapsearch command is extremely powerful, not only for diagnostic purposes, but also for viewing data in the LDAP server. In Listing 25-1, we used the -D option to specify the bindDN with to connect to the LDAP server, as well as the -W option to tell ldapsearch to ask for the password.

We used the -x option to tell ldapsearch to do a simple bind to the LDAP server. If you do not use -x, you need to bind using a Simple Authentication and Security Layer (SASL) mechanism. We will not discuss SASL authentication in this chapter because this is just an introduction to LDAP. For more information on configuring OpenLDAP with SASL, refer to the OpenLDAP documentation in /usr/share/doc/packages/openldap.
