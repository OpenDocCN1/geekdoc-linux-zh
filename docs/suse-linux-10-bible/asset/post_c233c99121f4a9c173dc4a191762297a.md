## Host Specification

If you have a specific host that needs except settings, you can set this with the host section in `dhcpd.conf`.

For the host specification to work, you need to specify the hardware address of the machine you want to configure. This can be found by issuing the `ifconfig` command for the interface in question on the client machine. See List 20-2 for an example.

### List 20-2: Output of ifconfig

```
eth0-# ifconfig
eth0  Link: HWaddr 00:03:ff:69:68:12
      inet addr:192.168.131.70 Broadcast:192.168.131.255 Mask:255.255.255.0
      inet addr:fe80:203:fff:69:68/64 Scope:Link
      UP BROADCAST MULTICAST RUNNING MULTICAST MTU:1500  Metric:1
      RX packets:30256 errors:0 dropped:0 overflows:0 frame:0
      TX packets:35690 errors:0 dropped:0 overflows:0 carrier:0
      collisions:0 txqueuel:1000
      RX bytes:404865 (3.8 Mb) TX bytes:34473633 (32.8 Mb)
      Interrupt:1 Base address:0x1080
```

You can see that in the preceding output for ifconfig, you have found the hardware address (HWaddr) 00:03:ff:69:68:12 for the eth0 interface.

Once you have found the hardware address of the machine in question, you can define a host entry in `/etc/dhcpd.conf`.

```
host {
  option host-name "bible.wiley.com";
  hardware ethernet 00:03:ff:69:68:12;
  fixed-address 192.168.0.8;
}
```

The important parts of the host configuration are the hardware ethernet and the fixed-address parameters:

- *The hardware ethernet parameter needs to be the HWaddr that is specified through the ifconfig command.
- *The fixed-address parameter is the IP address that will be used for this host specifically.

## Defining Host Groups

If you need to specify explicit configurations for a group of machines, you can use a group definition. A group definition enables you to define a group of machines with a specific configuration that also inherits the global configuration. Consider List 20-3.

### List 20-3: Defining a Host Group

```
group {
  option subnet-mask 255.255.255.0;
  option domain-name-server 192.168.0.2, 192.168.0.3;
  option domain-name "wileybible.com";

  host bible {
    option host-name "bible.wiley.com";
    hardware ethernet 00:03:FF:69:12;
    fixed-address 192.168.0.8;
  }

  host sospan {
    option host-name "sospan.wiley.com";
    hardware ethernet 00:03:FF:69:13;
    fixed-address 192.168.0.9;
  }
}
```

We now have two machines, bible and sospan, defined as static hosts in dhcpd.conf. Specifically for these machines we have defined only their host name (host-name) and their IP address (fixed-address). As we have defined a group that passes the hosts, these hosts also inherit the subnet mask, DNS servers, and domain name settings.

> Make sure you do not forget the opening and closing curly brackets when you define a group.

## Specifying Leases

A DHCP keeps its information for a finite amount of time. You can specify the amount of time (in seconds) a client keeps the DHCP information using the default-lease-time. If the client does not specify an expiry time, the server's preference will be used. If a client specifies a lease time, the server can enforce a maximum time, max-lease-time, overriding the client's preference.

Specifying both options puts a limit on the upper and lower lease time allowed for clients to hold the DHCP configuration. (Again, you add options to /etc/dhcpd.conf.)

```
default-lease-time 43200 # 12 hours
max-lease-time 86400 # 24 hours
```

This example specifies a lower limit of 12 hours, and an upper limit of 24 hours until a lease is renewed on the client.

## Other DHCP Options

DHCP is an extremely powerful configuration tool when you have many client machines that must be configured. It is not just limited to IP address allocation and can be extended to encompass a large proportion of network configuration, from WINS servers to network time servers.

View the dhcp-options page for more information on what options your DHCP server can present to your network clients.

## Starting and Stopping DHCP Clients

To be able to use DHCP, your client machines must know how to actually send requests to the network for configuration. In SUSE, you can use Network Configuration of YaST (Network Devices: Network Card) to configure a network interface using DHCP. Another way to send a DHCP request is using ifup-dhcp and ifdown-dhcp. If you are using a wireless network, or want to bring up a network interface temporarily, you can use ifup-dhcp:

```
ifup-dhcp eth0
```
This starts the DHCP client and attaches it to the eth0 interface. In the event that you want to remove a DHCP client from a network interface, its dynamic configuration, you need to use ifdown-dhcp:

```
ifdown-dhcp eth0
```
This removes the DHCP client from the network card specified.

## Troubleshooting Clients and Servers

You will rarely encounter problems with starting or using a DHCP server, which makes these problems more frustrating when they occur. On the other hand, DHCP client problems are quite common, usually resulting from the presence of multiple DHCP servers on your network. This section provides some tips for identifying and resolving DHCP client and server problems.

Most of the problems that you see in DHCP environments are related to DHCP clients somehow retrieve erroneous information. This is almost always the result of people starting DHCP servers that serve different ranges. Regardless of the type of erroneous information that DHCP clients are retrieving, you can use dhcpcd-test utility (part of dhcpcd package) to examine the information that they are retrieving. To use this utility, execute dhcpcd-test command by the name of an Ethernet interface on your system.
