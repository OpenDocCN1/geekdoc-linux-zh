# Chapter 6 ✦ Understanding Your Linux Network

Subnetting is something that we have not come across often in the real world, as the class-based network design is usually enough to represent a logical network layout. Small/medium organizations are capable of splitting their departments into a rough estimation of the IP class system. In larger organizations, you will find that countless IP addressing is quite common, although such organizations usually limit the network based on an IP alignment—that is, a traditional routable Class A network is subnetted down to a Class C subnet.

One thing that you should take away from this discussion of subnetting is that it is controlled on a local level. The Internet routers rarely know how an administrator has subnetted a network because there is no way to propagate information about the whole Internet.

> CIDR is an exception to this rule. CIDR is Classless Routing, and is an interim solution to the lack of IPv4 addresses that are available. CIDR is a group of subnet addresses that are controlled by larger organizations and have been registered by ISPs as a domain of control. This is further subnetted by the ISP to provide a larger number of IP networks, but a lower number of hosts. Usually if you ask your ISP for a few IP addresses, they will give you a subnet mask as opposed to a network mask. It is up to the distinguish between the standard class-based system and the classless addressing scheme. It is unlikely that an organization would need 253 routable addresses, or ISPs can split their allocation of public addresses down to the 4 or 8 addresses that you really need.

# Routing

We have talked about the addressing of hosts on a network, but what about communicating with hosts on a different network. This is an important part of TCP/IP and how the protocol is so scalable. Even though you can have non-routable addresses, you still have to make these machines are able to communicate with machines on other logical networks (whether subnetted local networks or public Internet machines) and the Internet.

The Linux routing table contains network routes for a few specific networks. When you add an IP address for a specific network, a route is created based on the IP address and network mask you assign. If TCP/IP communication is needed to a machine that is in the same network or subnet as your machine, the traffic will be sent out through that network interface for local delivery.

If the routing algorithm is unable to find the destination address of the machine in your routing table based on the network mask, it attempts to send the TCP/IP to your default route.

To see the kernel routing table, use route -n (see Listing 6-1). This displays your routes without looking up host names (this saves a lot of time).
