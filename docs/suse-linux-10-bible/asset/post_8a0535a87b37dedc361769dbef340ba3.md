# How Does a DNS Search Work?

We can take a look at how a DNS search takes place to put the idea of a distributed, hierarchical system into context.

1. Take our laptop as an example—the name lookup system is configured to get all name translations from our DNS server at 192.168.1.1. When we go to www.google.com, the laptop contacts 192.168.1.1 and asks it for the address of www.google.com. As our DNS server is a caching server (we talk about this later in the chapter), it contacts a DNS server to see if it knows.
2. The public DNS server at 194.106.56.6 accepts our request and attempts to find the IP address of Google for us. As this public DNS does not know the address directly (it does not control the Google domain), it asks a root DNS server if it knows the IP address of Google. Because the root servers do not control the Google domain, they tell our Internet service provider's domain server that it should ask.
3. The public DNS queries the .com server for the address. As the public DNS does not know the address, it refers to the DNS server.
4. The ISP asks the root server if it knows the address of google.com. This time we strike lucky, the DNS server knows the address.
5. When the ISP's DNS server knows the address, it returns this back to our laptop.

As you can see, the DNS system works by servers cooperating with each other to find the answer. This helps to alleviate the burden on single root servers.

# Caching

You can imagine that all the machines in the world wanting the IP address of Google would severely impact the performance of the root. To combat this, most DNS servers cache the result of a query for a period of time that is TTL (Time to Live). Until this countdown is reached, subsequent lookups for google.com will be answered by the local server.

# Configuring BIND for Caching and Forwarding

After installing the BIND server using YaST, you need to edit its main configuration /named.conf. When you are configuring BIND as a central DNS server for your home or organization, it is always a good idea to tap into your Internet service provider's DNS server as a resource to provide you with public DNS lookups. When you rely on another DNS server to go and find your lookups, it is called a forwarder because it literally forwards your DNS look to another server with the added benefit of caching the response.

> BIND is available with both the Professional and Enterprise versions of SUSE.

To edit DNS server settings from now on, you will have to be logged in as the root user.

You can also configure your DNS client and server through YaST. This chapter concentrates on direct configuration of the services so that you know how the system works. If you want to configure a DNS server, start YaST and navigate to Network Services: If you want to configure your DNS client, navigate to Network Services: DNS and Host Name.

The following entry in /named.conf is the forwarders declaration. A forwarder is a DNS server that your server passes requests to when your DNS installation does not know the answer.

```
forwarders { 194.106.56.56; 192.106.33.42 };
```

We have used two DNS servers for resilience purposes in this example, so that if the first DNS server cannot be contacted, the second one will be used. Note that a semicolon separates the forwarders, and the line is delimited with a semicolon.
