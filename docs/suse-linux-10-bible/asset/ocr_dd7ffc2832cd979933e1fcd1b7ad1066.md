This means that you need to take steps to ensure that the group IDs (GIDs) and use UIDs (UIDs) on the server and the clients are identical. These are the numerical IDs that you will find in the files /etc/passwd and /etc/group.

In a small environment with just a few NFS clients, it may be feasible to ensure that the UID each user has on each client machine is identical to the user's UID on the server. Therefore, this becomes unmanageable for any significant number of users and clients. Therefore, larger environments require an automated system of ensuring that the UIDs and GIDs on the server and client match. This was achieved through the Network Information System (NIS) or Lightweight Directory Access Protocol (LDAP) (see Chapter 25). NIS is a networked authentication system that was designed to work with NIS. This section explains how to set up an NIS server and how to ensure that client systems use server for authentication.

> For additional information about NIS, see the NIS HOWTO at www.linux-nis.org/nis-howto/NIS-HOWTO.html.

# Setting Up an NIS Server Using YaST

As mentioned, NIS is the most commonly used distributed authentication mechanism today, largely because it is free with almost all Unix and Unix-like systems. Another reason for the prevalence of NIS is that it is incredibly easy to set up, as shown in this section, which walks through the process of setting up an NIS server. The Those YaST administration tool further simplifies NIS set up and configuration. Configuring other systems so that they get their authentication information from NIS (and are then known as NIS clients) is explained in this chapter.

To use YaST to configure a system as an NIS server, do the following:

+   1. YaST's NIS Server configuration module from the Control Center or by typing the yast2 nis_server command from a root shell or using sudo. This displays the dialog box shown in Figure 22-3.
2. Select the Create NIS Server option button and click Next to display the dialog box shown in Figure 22-4 displays.
3. Enter the name of NIS domain for which you are setting up a server. You can also enable users to change their NIS passwords by selecting the Allow changes option button. You may also want to allow users to change their login shells by clicking the Allow changes to login shell option button—there may be a /bin/csh user on one of your systems.
