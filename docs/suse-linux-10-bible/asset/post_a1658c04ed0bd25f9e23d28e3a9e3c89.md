## The Root Partition

After the space has been created, you need to configure the root (/) partition (see Figure 1-13). The root (/) partition is the most important data partition on any Linux or Unix system, and it is the only non-swap filesystem that is required to boot a Unix or Linux system. The root partition takes its name from the fact that it is mounted at the root of the Unix/Linux filesystem, which is the directory mounted on which to successfully boot a Linux system. The root filesystem contains core directories required to boot Linux, such as /dev; the directory containing system administration, configuration, and initialization files (/etc); the directory in critical system libraries, kernel modules, security, and informational information located at (/lib); and directories containing system binaries (/bin, /sbin, and so on).

A journaling filesystem dedicates a specific part of the filesystem for use as a cache of pending writes to it; this ensures that updates occur in a clean, atomic fashion; and allows for recovery if the system is not cleanly shut down. Ordinarily, when a Linux system is shut down, it ensures that all writes to each filesystem are completed, and then deletes filesystems (known as unmounting) to guarantee that all system data is consistent before the system is turned off. Using a journaling filesystem does not make safer to power off the machine, as data loss can still occur when data is not completely written to the disk.

## Data Partitions

Data partitions is a generic term for partitions that are formatted as a filesystem in which both the system and its users can store data. The partition designated as the root filesystem is a special case of a data partition because it is required to boot a Linux system.

The preceding sections explain how to create the swap and root partitions that must be present to successfully boot a Linux system. However, you can also create other partitions, format them as filesystems, and specify their mount points during the installation process. On Linux systems, a mount point is a Linux directory through which a filesystem is available to the system, known as mounting that filesystem. Using regular directories as mount points is a key part of the design of Unix and Linux. If you run out of disk space on a given partition, you can add another disk to your system, create data partitions, copy the data from where it was originally located, then mount the new partitions on the directory where the data was originally located, effectively increasing the amount of storage available to an existing system.

Today's larger disks make it attractive to create other partitions. You may have various reasons to consider creating multiple partitions on today's days:

- When you boot a Linux system, the system checks the consistency of each of its filesystems (as defined in the file /etc/stab — more about in Chapter 3). Checking the consistency of a single, non-journaled filesystem can take a bit of time.

- Filesystem corruption can occur as a result of a number of problems, such as a system crash, sudden power loss, or hardware problems. Whenever a filesystem is corrupted, repairing it (which is mandatory) can cause you to lose data. Creating multiple partitions reduces the extent to which filesystem corruption can affect a single data partition.

- Keeping data on multiple partitions limits the chance that you can lose data during a subsequent system upgrade. Using upgrades reforms the root partition or recreates its directory structure. If your user data is stored on other partitions, it will not be affected by changes to the root filesystem.

- Some Linux backup software backs up data per-partition basis. Backing up a single partition can take a bit of time. Also, if backups fail (such as when a partition is corrupted), you may not be able to use the backups to restore your system. Creating multiple partitions limits problems related to a backup failure to a single partition.

Chapter 3 provides more detail about creating multiple partitions and the types of filesystems supported by Linux and provides additional reasons why you may want to create multiple partitions on your Linux system. Most types of Linux filesystems can be resized after they have been created, enabling you to customize your system's partitioning, even after the system has been installed and is running.

If you want to create multiple partitions during the installation process, you can do this by making sure that the root partition does not completely fill your disk and then creating partitions in the remaining space of your disk. Common parts of a Linux system that you want to put on separate data partitions are /boot, /home, /opt, /tmp, /var, and /usr/local. For more information on these partitions and the types of information stored there, see Chapter 3.
