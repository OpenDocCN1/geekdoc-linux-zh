## Finding Files with find and locate

The find command searches the filesystem for files that match a specified pattern. The locate command provides a faster way of finding files but depends on a database that it updates and refreshes at regular intervals. The locate command is fast and convenient, but the information it displays may not always be up-to-date—this depends on whether its database is up-to-date. To use the locate command, you need to have the package findlocate installed.

find is a powerful command with many options, including the ability to search for files with date stamps in a regular format (useful for backups) and to search for files with permissions, owners, and other attributes. The documentation for find can be found in its pages: info find.

- find . -name *.rpm — Finds RPM packages in the current directory
- find . | grep page — Finds files in the current directory and its subdirectories with the string page in them
- locate traceroute — Finds files with names including the string traceroute on the system

## Editing Text with vi and emacs

The vi (visual) and emacs (editor macros) text editors are the two most important editors in Linux. You need to learn basic editing using vi whatever you do because it is almost always available on Unix and Linux systems. The emacs editor has immense power but may not be installed on every system you use.

- vi /etc/exports — Edits the file /etc/exports with vi
- emacs /etc/exports — Edits the file /etc/exports with emacs

The differences between these two editors lie in their commands sets and approach to editing files. The vi is a modal editor, in which you are either in edit mode, typing characters into a file, or in command mode, moving around in the file or executing commands on portions of the file. The emacs is a modeless editor in which you are always in edit mode—you use special key sequences as escape to move around or execute commands on portions of the file. The arguments between devotees of the two editors and approaches to editing text are legendary, and we shall not get into those discusses.

See 11 for more details on these text editors and the similarities and differences between them.

## Basic User and Group Concepts

Linux is a multiuser operating system. The system of users and groups in Linux is inherited from the Unix tradition, and among other things provides a very clear and precise distinction between normal users can do and what a privileged user can do (such as the root user, the superuser and administrator on Linux system). The fact that the system of users and groups and the associated system of permissions is built into the system is fundamentally secure in a way that Windows is not. Although modern versions of Windows have a similar concept of users and groups, the associated concept of the permissions with which a process can run a lot to be desired is why there are so many Windows vulnerabilities that are based on exploiting the scripting capabilities of programs that run with user privileges but turn out to be capable of subverting the system.

> If you're interested in the differences between the major operating systems, Eric Raymond, noted open source guru philosopher, offers some interesting comparisons and discussion at www.catb.org/-esr/writings/tacoup/ch03s2.html.

![](img/e4e45c9f32e76fb35fabbd21a96f1a1e_106_1.png)

Every Linux system has a number of users accounts: Some of these are human users, and some of them are system users, which are user identities that the system uses to perform tasks.

The users on a system (provided it an authentication locally) are listed in the file /etc/passwd. Look at your user entry in /etc/passwd; it will look something like this:

```
roger:x:1000:1000:Roger Whittaker:/home/roger:/bin/bash
```

This shows, other things, that the user username roger has the real name Roger Whittaker, and his home directory is /home/roger, and that his default shell is /bin/bash (the bash shell).

There will almost certainly be an entry for the system user postfix looking like this:

```
postfix:x:51:51:Postfix Daemon:/home/postfix:/sbin/shell
