# Chapter 24 ✦ Implementing Firewalls in SUSE Linux 621

Setting up a rule for connections, you really need to know how the protocol works. In the case of SSH, it is well known that it is a TCP protocol, running on port 22. With this in mind, it is relatively easy to write a rule for it.

It is up to you how you want to write the rule regarding the state of the connection, because the initial INPUT state rule has allowed all ESTABLISHED and RELATED connections, you do not need to explicitly set the state to NEW because you have effectively allowed all connection types for SSH by not explicitly setting them.

> If you do not specify something explicitly with iptables, it is assumed that you want the default setting. For example, if you did not set the interface for the incoming connection, netfilter would have allowed an SSH connection on all network interfaces. This is indeed the same for the protocol type and the destination port. Be very careful when you write your rules, and make sure you explicitly set everything you want to control; otherwise you will probably let in more than you think.

For any incoming connections you want to have on a firewall, you can append a rule in the same way you do with the SSH connection.

# The Order of Rules

You must be very conscious of the order you set rules in a chain because netfilter passes the TCP/IP packet through the rules in the order they are inserted into the kernel. If you want to insert a rule at the top of the list (that is, making it the first rule that is executed), you can use the -I (insert) parameter to iptables.

For example, if you are allowing SSH into your firewall from the Internet, you know that you do not want a specific IP address to have access to SSH, you have to insert the REJECT/DROP rule before the general SSH rule:

```
iptables -A INPUT -p tcp --dport ssh -i eth0 -j ACCEPT
iptables -I INPUT -p tcp --dport ssh -i eth0 -s 10.32.1.4 -j DROP
```

In this example, using the -s option to specify a source IP address, we have inserted the DROP rule before the general ACCEPT rule.

When a TCP/IP packet has been inserted into a chain, it is checked in order with each rule. If one of the rules matches the TCP/IP packet, it is sent to the target specified (ACCEPT, DROP, REJECT) immediately. In the case of inserted SSH DROP rule, it fires off packets for the SSH port to the DROP target before it gets to the ACCEPT rule.

In essence, all TCP/IP packets sequentially go through every rule in the chain until they are dropped. If none of the rules fires off a packet to a target, that packet is dealt with by the default policy, which is to kill the packet in this case.
