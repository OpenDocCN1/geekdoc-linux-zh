Here, the symbol ^ represents the start of a line. Similarly, the symbol $ represents the end of the line, so bat$ searches for the string bat at the end of a line:

```
user@bible:-> grep bat$ file2
bat
dingbat
```

To search for lines containing a letter d followed by any number of characters followed by a letter t, use the following:

```
user@bible:-> grep d.*t file2
debit
doubt
dingbat
```

The * symbol represents zero or more repetitions of the previous character.

And these examples just scratch the surface of what can be done.

grep -v means output lines not containing the expression. For example here you find the lines that do not contain the string bat and do not start with the letter d:

```
user@bible:-> grep -v bat file2| grep -v ^d
bit
Batman
```

The following is a more practical example:

```
# grep [0-9]* /var/log/2/access.log | grep -i coglebot
```

(probably) lists all entries in the Apache log file 9 June that do not refer to accesses from the Google search engine robot. Of course, this is slightly naive; you are not specifying which field of the log string coglebot is appearing.

# Regular Expressions and grep

Looking for regular expressions in a log is the kind of thing you want to build up employing for the most. It's also in this situation that you are likely to build long commands of the form grep [grep]|grep-v . . . .

Take, for example, a grep involving United Kingdom (UK) postcodes. UK postcodes look like this: OX5 2AX, N1 5JD, and AL13 4RG. To search (again again) for strings of type in a file, you use the following:

```
# grep -E `[a-zA-Z]{1,2} *[0-9]{1,2} [a-zA-Z]{1,2}` file
```
