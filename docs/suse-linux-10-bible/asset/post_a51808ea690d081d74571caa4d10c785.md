## Mounting a Shared Windows Drive

There are many ways to mount a shared Windows drive on your SUSE system, the easiest of which is to use the standard Linux mount command. For example, to mount an SMB share named vwh that is available on an SMB server named home, mount that on the directory /mnt/smb, and access those files as the Windows user vwh, you would execute a command as the following with the root user:

```bash
# mount -t smbfs -o username=vwh //home/vwh /mnt/smb
```

The previous command line can be broken down as follows:

- -t smbfs—Identifies the type of filesystem that you are mounting as smbfs filesystem (SMB filesystem).
- -o username=vwh—Passes the username to the mount command, which identifies your Windows user login as vwh.
- /home/vwh—The name of the Windows directory that you want to mount on your SUSE system. In this example, this is a directory named vwh on your Windows server named home.
- /mnt/smb—The directory on your SUSE system where you want to mount the specified Windows directory.

The directory on which you want to mount the SMB share must already exist. The mount command actually executes a command called smbmount, which is usually a symbolic link to the command /sbin/mount.smbfs. After executing this command, you will be prompted for the Windows password associated with the specified user.

![](img/e4e45c9f32e76fb35fabbd21a96f1a1e_548_0.png)

You can also execute a command as a user other than the root user by using sudo, which lets users execute privileged (sudo) commands with a specific user ID. The privileged commands and the users who can perform them are listed in the /etc/sudoers. If you have a valid entry in the /etc/sudoers, you will be prompted for your password and then again for the Windows password associated with the specified user. If you do not have a valid entry in the /etc/sudoers file, there isn't much point in using the sudo command, but if you do enable privileged commands by executing the visudo command as the root user, which enables you to edit the /sudoers file using the vi editor. For more information about the sudo command, execute the man sudo in a console window or term. For more information about the sudoers file, execute the man sudoers.

![](img/e4e45c9f32e76fb35fabbd21a96f1a1e_548_1.png)

Just like other partitions or network drives, you can automatically mount SMB shares when your system boots by adding them to your system's /etc/fstab file. To do this, create the:

```text
//home/vwh /mnt/vwh smbfs username=vwh,password=foc,uid=578,gid=0 0 0
```

The first field defines the name of the SMB share that you want to mount, the second field is the directory on your system where you want to mount the drive, and the third field is the type of filesystem that you are mounting. The fourth field options that you want to use when mounting the SMB share, and the fifth and sixth fields define when you want to back up the filesystem and when you want to check the consistency of the filesystem. These values are always 0 (zero) for networked filesystems, which means never.

For SMB shares, the parameters that you have to pass in the mount options include the username that you want to use for authentication with the Samba server, your password, and the user and group IDs that you want to associate with the mounted filesystem so that you only can read and write files in the Samba share. Because you have to enter your password, you should also make sure that the /etc/fstab file is not publicly readable by executing a command such as chmod 600 /etc/fstab, or else anyone in the network can view the file and find out your Windows password—probably not a good idea.
