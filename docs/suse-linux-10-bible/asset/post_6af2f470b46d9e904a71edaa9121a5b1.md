
# Chapter 2 ♦ Linux Fundamentals

The bash shell provides a powerful command-line interface that offers many features that the DOS command line lacks. The most important of these are command history and command completion:

- **Command history** — You can see a history of the commands you typed by pressing the up arrow repeatedly. You can then edit the command and reuse it.
- **Command completion** — If you are part of a command and press the Tab key, bash will complete the command as far as it is able to do so uniquely.

These two features together make working with the shell extremely quick and easy with a little practice. The command history is also searchable in more than one way: If you type `history`, you will see a list of the commands you have typed. Each of these is numbered: If you type followed by the number of the command, you can run it. If you press Ctrl-R (hold down the Control key and r), you can search the command history by typing part of the command you are looking for. If the first command is not the one you have in mind, repeat the Ctrl-R until it appears. You can also recall a previous command by typing ! followed by the first letter or letters of the previous command.

# Environment Variables

As you guess from the discussion of command history in the previous section, the bash maintains a significant amount of information about the commands that it has executed, the settings for various configuration parameters, the environment in it is operating, and so on. Much of this information is stored in variables in the shell, which are therefore known as environment variables. You can display all of the environment variables set within your current shell and their definitions by typing `printenv`, in the following example:

```bash
$ printenv
HOSTNAME=home.user
TERM=xterm
SHELL=/bin/bash
HISTSIZE=1000
ENCRIPT=-1
PROMPT=\u@\h:\W\$
PATH=/usr/local/bin:/usr/local/sbin:/usr/sbin:/usr/bin:/bin
PWD=/home/user
JAVA_HOME=/usr/lib/jvm/java
LANG=en_US.UTF-8
PS1=\$
DISPLAY=:0
```

As you can see from example, names of environment variables typically comprise underscores and are used in a variety of ways. For example, the value of the HOME environment variable is a single string that contains the name of user's home directory. The PATH environment variable is a colon-separated list of directories that the shell searches in order looking for a command. The PS1 environment variable defines the structure and content of the prompt that is displayed by the shell. The last environment variable (the last line of example) holds the full path of last command executed.

Environment variables can be seen in a number of places:

- System-wide configuration files as those located in /etc/profile, /etc/profile.local, and the directory /etc/profile.d on a Linux system. These are system-wide files that are executed to initialize your working environment each time you log in.
- System wide configuration files such as /etc/bashrc. These are typically executed by user's personalized bash configuration file each time you start a new shell.
- User-specific configuration files such as .bashrc that are read each time you start a new shell.
- Within shell scripts using these scripts to be exported to the command-line environment.
- From the command line for your convenience or within shell functions executed by the shell.

The environment variables that you want to make available to all subsequent shells are made available using the export command. For example, suppose that you want to set an environment variable named SAVEME to the name of the current directory that you can remember it. If the current directory is /home/user, you can set the SAVEME environment variable to this directory with the following:

```bash
export SAVEME=/home/user
```

One common task involving environment variables is to add a new directory to the colon-separated value of the PATH environment variable so that your shell looks in that directory for executables. For example, suppose you've just installed the popular Linux Firefox on your system. Firefox is typically installed in the directory /usr/local/firefox, and the binary program that you actually execute to run the browser is /usr/local/firefox. You can always execute Firefox by typing the full path of firefox command, which is a bit tedious. A better solution is to add /usr/local/firefox to the value of your PATH environment variable (generally referred as “adding to your path”). You can do this within the current shell by executing the following command:

```bash
export PATH=$PATH:/usr/local/firefox
```

After typing this command, you can execute the firefox command from that shell by simply typing firefox and pressing Return.

> The export command tells the shell to export a new value for the PATH environment variable, where that value consists of the directory /usr/local/firefox prefixed to the previous value of the PATH environment variable. The first reference to the PATH variable identifies the name of the variable you want to set. Any environment variable preceded by a $ means that you are referring to the value of that, not its name.

When you've customized the value of your PATH environment variable, you will probably want to do that same customization each time you log in and in every shell that you start (in xterm, and so on). You can do this by adding the previous command to any existing PATH setting in your startup file, which is the file .bashrc in your home directory, or by putting this as the last command in your .bashrc file. See the section “Configuring User Preferences” later in this chapter for more information about the .bashrc configuration file.

When you've set an environment variable, you can unset it at any time using the unset command. The unset command removes the environment variable and its associated value from the shell in which you execute. You would not want to unset an environment variable such as the PATH environment variable because the shell would not know where to find commands. However, you might find useful to unset environment variables that are used only by certain programs. For example the ENSCRIPT environment variable, shown in the previous output of printf, is used to specify arguments for encript command, which produces nicely formatted output from text files. To execute encript command without those arguments (in other words, using its internal default), you could execute the command ENSCRIPT before printing.

# Wildcards and Pattern Matching

All Unix and Linux shells support several ways of locating file and directories that match a specified pattern. As you might expect, working from the command line, one of the most common things you will want to do is specify the names of one or more files as arguments to other commands. To make it easier to identify specific files without having to type every filename in its entirety, Linux shells provides a number of ways to specify patterns that can be used to match specific filenames.

The most basic pattern matching provided by Linux shells such as bash are two special characters known as wildcards, which means that these characters can match any other character. Linux shells support two basic wildcards:

- Asterisk (*) — Also referred as star, can represent any number of characters (including none at all) in a row
- Question mark (?) — Represents any single character

In addition to these wildcards, Linux shells support two other ways to match specific patterns within filenames:

- By specifying ranges of values separated by a dash within square brackets. For example, the expression [1-3] will match any instance of the numbers from 1 to 3, inclusive.
- By specifying lists of comma-separated values enclosed within braces (also known as curly brackets). For example, the expression (1,3) will match either the number 1 or the number 3.
