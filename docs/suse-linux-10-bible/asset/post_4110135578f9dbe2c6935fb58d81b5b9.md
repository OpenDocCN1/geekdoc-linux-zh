
## Chapter 9 - Configuring the System with YaST

XML files allow for a very high degree of detailed control over the installation of the particular machine: Different machines can have different specific XML control files. Essentially, the XML file contains an answer to every question that the installer asks the user in an interactive installation.

## Mode of Operation

The machine that is being installed has to be booted seamlessly. The possibilities are to boot it from a floppy disk, from a bootable CD-ROM, or by PXE network booting.

- SUSE uses a GRUB boot floppy for starting an installation that is capable of network booting in conjunction with a Trivial FTP (TFTP) or Dynamic Host Protocol (DHCP) server.
- Alternatively, the system can be booted from an installation CD, but can be given a boot parameter as `install-https://192.168.1.1/install/`. If a DHCP server is available, the machine obtains an IP address and finds the installation files from the information given at boot time. This information can also be placed in a file held on a floppy disk to be read at the start of the installation.
- The most elegant method, if it is available, is PXE booting (supported by most modern hardware). In this case, little more is needed on the installation server: You need to run a DHCP server and a TFTP server together with the special files (from the package pxe) required to start the boot process. The DHCP server offers an IP address based on the client's hardware address; the TFTP server then gives a file based on the IP address, which references the XML installation control file on the server.

In any of these cases, when the installer has booted and opened the relevant XML file, the XML file controls the rest of the installation as if a human interacts with the installer.

The installation server can offer the installation files by HTTP, NFS, or FTP. In the case of SUSE Professional, it is sufficient that the contents of the installation CDs and DVD (or a mirror of the installation set on the FTP site) be available by one of these methods.

## Text Manipulation

This chapter introduces some of the tools available on Linux for text manipulation. They provide a way to get information out of files, alter them, or search for text within them.

Typically, you might have a file containing some structure, but you want to view only certain parts of it. For example, you might have a file that contains many lines and you want to number only those that are not blank.

In this chapter we describe some of these tools and offer how they work in simple cases. These tools can be combined to perform more complex tasks.

## Reading Lines from Files

Most of the commands introduced in this section are part of coreutils package and are the GNU versions of commands that have long been part of the Unix toolkit.

### cat

The cat command is so called because (in the words of its man page) it "concatenates files and prints them to standard output." So the command:

```bash
cat /etc/passwd
```

simply prints the content of the /etc/passwd to the screen.

If you cat a number of files, you will see them printed to the screen in the order they are named:

```bash
cat file file2 file3
```

So far, this is not very useful, but you can now redirect the output to a new file:

```bash
cat file file2 file3 > bigfile
```

You now have a combined bigfile containing the contents of the three original files.

## Numbering Lines in a File

The cat command has the sometimes-useful capability of being able to number the lines in a file. This is done with the -n option. If you have a file fruits:

```bash
user@bible:-> cat fruits
apple
banana
cherry
```

```bash
user@bible:-> cat -n fruits
1 apple
2 banana
3 cherry
```

The -b option numbers only non-blank lines. It quite often happens that for reason you have a file that contains hundreds of blank lines as well as some information you actually want: You could simply use cat -b and direct the output to a new file.
