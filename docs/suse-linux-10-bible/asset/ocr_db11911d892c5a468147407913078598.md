To put this all together, you need to specify a subnet class that defines the address scheme and the options discussed previously (see Listing 20-1).

# Listing 20-1: /etc/dhcpd.conf Configuration for a Test Network

```
authoritative;
ndns-update-style none;

subnet 192.168.0.0 netmask 255.255.255.0 {

  range 192.168.0.10 192.168.0.250;
  option routers 192.168.0.1;
  option domain-name-server 192.168.0.2, 192.168.0.3;
  option domain-name "wileybible.com";
  option time-servers 192.168.0.2;
}
```

Putting all this together, we have verified that this DHCP server is authoritative for the local network and we are not using dynamic DNS.

Next, we specify a subnet on the network (192.168.0.0/24).

In this subnet we are allocating IP addresses from a pool between 192.168.0.10 and 192.168.0.250, with a default gateway of 192.168.0.1, and the DNS servers are located at 192.168.0.2 and 192.168.0.3 with a search domain of wileybible.com.

We have also told the client machine that it should synchronize its time with the server 192.168.0.2 (option time-servers).

When configured, you need to specify which interface DHCP server will listen on to provide its service. To do this, edit the /etc/sysconfig/dhcpd file and edit the DHCP_INTERFACE. If you have multiple Ethernet adapters in your system, it is important to set this explicitly; otherwise, you will probably find your DHCP server running on the wrong network portion. For example, to tell DHCP to work with the eth0 network interface, use the following:

```
DHCPD_INTERFACE="eth0"

```

When we start, (or restart currently running) the DHCP server with rcdhcp start.

> Make sure dhcp starts when your system boots up, use chkconfig -a dhcp.
