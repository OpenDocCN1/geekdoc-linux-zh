The boot stanza for a Xen monitor and associated compressed version of the Xen virtual monitor in its kernel entry, which also defines the amount of system memory to be reserved for the Linux system that you are booting under Xen. Xen uses the term domain to refer to a instance of an operating system environment. The Initial Linux system that Xen boot stanza in your GRUB configuration can either assign any available memory to your domain, or associate a specific amount of memory to that domain. If you choose the former, you can subsequently reduce the amount of memory associated to your primary domain using the balloon command. If you associate only a specific subset of system's memory to domain by you can associate specific amounts of memory to subsequent domains when you create them, which is what we prefer. The Xen stanza previously allowed 512MB of the 1GB of memory available on the sample system to domain 0, which enables you to directly specify the requirements of subsequent domains in their configuration files. You may want to customize this value to assign a specific amount of memory to domain 0 on your system. The maximum value you can use is the amount of memory available on your system, 64GB for the Xen monitor. The amount of memory allocated to domain 0 must currently be given in kilobytes, future versions of Xen plan to support more generic expressions of memory.

The remainder of a Xen boot stanza tells GRUB to load a Linux kernel that has been prepared for Xen (/boot/vmlinuz-xen) as the system's Linux instance, using a RAM disk with Xen functionality (/boot/initrd-xen) during the boot process. It is a good idea to use symbolic links for both the kernel and initrd disk so that you can subsequently install versions of both without needing to modify your GRUB configuration file.
