It is customary to source your NTP synchronization to a secondary time server, and for primary servers to synchronize to secondary servers only for general use.

When configured, your machine will attempt to synchronize to the NTP server specified in the configuration window. If you want to synchronize to more than one server, select Configuration. Unless you are running a server that is extremely sensitive to time, the default usually suffices. If you are running an SLP-aware server on your network, clicking the Lookup button causes the system to attempt to discover services.

### Printer Configuration

One of the biggest things that annoyed Linux users in the past was the configuration of printers. In the Windows world the addition of a printer is painless, but in Linux the process was always marred by drivers and configuration options. Common Unix Printing System (CUPS) drivers help to provide a unified printer architecture for Unix in general, and with distributions such as SUSE, the problems have become less apparent.

A more detailed description of CUPS is given in Chapter 9. To configure your printer:

1. Select Hardware from the initial YaST menu and Printer from the right pane. YaST displays the Printer Configuration screen (see Figure 9-8). It then attempts to discover local printers connected to your machine and guides you through the installation of the printer as a default on your system.

![](img/e4e45c9f32e76fb35fabbd21a96f1a1e_276_0.png)

Figure 9-8: Adding a printer to the system

2. If your printer is not local to the system you will have to manually configure it. This is not as difficult as it used to be and is now easy to do as in other operating systems. Click the Configure button and you are taken to the Printer Type screen shown in Figure 9-9 to select the type of printer you are configuring.

| LPD Network | Similarly, if you are using the traditional Unix print server as a central resource, select this option. |
| SMB Network | If you are trying to connect to a printer connected to a Windows machine, select this option. |

3. Select Direct to a Network Printer. Click Next and you are prompted for the protocol used for printing to this network printer (see Figure 9-10).

![](img/e4e45c9f32e76fb35fabbd21a96f1a1e_278_0.png)

Figure 9-10: Printing protocol

- **Direct Printing**: Sends the printing job in raw form. This is usually safe for most modern network printers.
- **LPD Protocol**: If your network printer understands the LPD protocol, you can use this option.
- **IPP Printing**: Sends print jobs to the printer with the Internet Printing Protocol.

4. Select the direct printing protocol and click the Next button.

5. You are prompted for the IP address of the network printer you want to connect, or you can attempt to scan for available network printers on your network with the Lookup button.

6. If your printer has been detected successfully on the network, you can click the Test Access button to see if the printer accepts print jobs before continuing.

7. Click the Next button to move on configuring the printer name, description, and location (see Figure 9-11). These are free-form strings that will help you identify the printer from your applications. Two options of note are Local Filtering and Automatically Prepare Queues.

- **Do Local Filtering**: Relevant when the remote printer you connected is not intelligent enough to prepare a print job before putting it on paper. In this case, to take the burden off your printer, you can do the preparation of page layout and so on on your local network and then send the finished, prepared job to the printer.
- **Automatically Prepare Queues**: Used when the system that hosts your printer uses different queues to reflect different printer configuration options, such as black and white printing, color printing, and so on. The available printer queues are usually contingent on those supported and created by the printer driver.

As we are doing local filtering in this example, we are able to print a test page at this point because we need to set up our printer model. If your printer is intelligent enough to handle raw print jobs, you can attempt to print a test page. Otherwise, you may find your printer printing garbage.

8. Click Next to view the Printer model page (see Figure 9-12). On the left you will be presented with a list of printer manufacturers. When you select a manufacturer, you will see a list of specific printer models on the right.

In the unlikely event your printer is not listed, you may be able to use the PPD printer file in Windows to define your printer configuration.

If you have a PPD file, select Add PPD. You can either select the PPD file locally or download a PPD file from the SUSE portal.

### PPD Files

PostScript Description files (PPD) control how information is sent to the printer. These files are relevant only to printers that do not use PCL (Printer Control Language). If you are not happy with your printer, you may also find PPD files on the Internet. SUSE has a great resource of PPD files at http://www.suse.com/products/printerdrivers.html.

9. When you have selected your model, click the Next button to view an overview of settings.

10. If anything is not correct with your test page, go back and try to change any settings.

11. If you are happy with your printer configuration, press OK to return to the overview screen where you were presented when you started the configuration.

12. Press the Finish button to complete the configuration and save your changes to the system.

### Setting Up a Scanner

YaST's scanner module automatically detects and sets up a scanner if it can; USB and SCSI scanners are supported, as well as all-in-one (scanner-printer-fax) devices and network scan stations. The ancient port scanners are not supported and cannot be configured with this module. In most cases, if a USB or SCSI scanner is detected, YaST sets it automatically. If one or two scanners require a firmware file to be installed; if this is required, YaST warns you of the fact, but you may have to obtain this file from the installation media that came with the scanner or from the manufacturer's site.

> Note
The definitive source of information about using a scanner with Linux is www.sane-project.org. You may also find information about problems with specific scanners by searching for the word scanner on the SUSE portal's support database: http://portal.suse.com/PM/page/search.pm.
