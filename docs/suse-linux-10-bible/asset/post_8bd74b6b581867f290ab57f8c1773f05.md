## Cyrus IMAPD

POP3 is a good mail delivery agent for most situations, but if you like your mail controlled from a central server, with access to all your mail and folders from a remote regardless of whether your mail is stored locally, then IMAP is the answer.

IMAP is a connection-based protocol. What means is that you need a connection to the server to read your mail. Some MUAs enable you to read your mail locally and offline when not connected, the server holds the up-to-date representation of your mail.

There are two main contenders in the Unix IMAP server, University of Washington and Cyrus IMAPD. Both IMAP servers are extremely good at what they do, and we have chosen Cyrus as our focus because it is the IMAP server of SUSE (it is the IMAP server used in OpenExchange).

The Cyrus IMAP server is extremely stable and capable of handling thousands of mail accounts. If more scalability is needed, you can use a Murder of Cyrus (a cluster of Cyrus servers) to provide a distributed IMAP server farm.

To use Cyrus, you need to add a system user (in our case, we use justin) to the Cyrus database. All authentication is still handled through the user's system password, but the Cyrus database needs to provide a namespace for the user, including folders and access control lists.

## Configuring the Cyrus User

Cyrus has been installed through YaST, a few administrative tasks need to take place before you can log in as a user. First, we need to talk about how Cyrus works and interacts with the system. The Cyrus IMAP process is controlled by the user Cyrus. With some daemons, the user who owns the process is usually a placeholder for the daemon and nothing else. In the case of Cyrus, the system user plays an important part by not only running the IMAPD process but also by being the user that IMAP administration is conducted.

With this in, you need to set a password for the cyrus user. To do this, as root, run the password command for the cyrus user.

```
bible:~ # password cyrus
Changing password for cyrus.
New password:
Re-enter new password:
Password changed
```

## Adding Users to Cyrus

When those users are started, you need to add users to the Cyrus Database to provide mail services for them. We will take the user justin (who must exist in the system) as add a user to the Cyrus system, become the Cyrus user and connect to the Cyrus IMAP server with the cyradm command (Cyrus administration):

```
bible: # su - cyrus
cyrusservice-> cyradm localhost
IMAP Password:
localhost>
```

When connected, you can use the cm (create mailbox) command to create the user justin's inbox:

```
localhost> cm user.justin
localhost> lm
user.justin (HasNoChildren)
localhost>
```

Here have told Cyrus to create the mailbox user.justin. This may seem odd, but it is a standard way to configure Cyrus for mailboxes. Cyrus works on a hierarchical mailbox structure, not only for the users, but also for system mailboxes. These system mailboxes could be mailboxes that are shared between many users for bulletins, for example.

## Creating a Shared Mailbox

If you want to create a mailbox that is shared between certain users, use the cm command to create the mailbox and also set the access control list (ACL) for users on the mailbox.

For example, if you have three users, justin, roger, and aimee, on the system, and you want them to be able to store and view messages in this folder, but not be able to delete any, you can look up the access codes in Table 17-1 and set the ACL on that folder using the sam command (set ACL).

If you ever need to find out what Cyrus commands you can use, type help in the Cyrus shell.

| Table 17-1 Cyrus ACL Settings | ACL Code | Description |
|---|---|---|
| L | List the folder—that is, be able to view the folder. |
| r | Read the contents of the folder. | |
| s | Set the seen flag on a message in the folder. | |
| w | Write to the folder—that is, store a message in the folder. |
| i | Insert or append a message to the folder. | |
| p | Send a mail to the folder. | |
| c | Create or delete the folder. | |
| d | Delete a message in the folder. | |
| a | Administrative rights on the folder. | |

To set an ACL on the folder, you need three pieces of information: the user you want to set the ACL for, the mailbox, and the ACL settings. Consider the example in Listing 17-5.

Listing 17-5: Setting ACLs on Shared mailbox
- localhost> sam aimee
- localhost> sam roger
- localhost> sam justin
- localhost> sam roger
- localhost> sam justin
- localhost> sam aimee

We allowed the users justin, roger, and aimee to list the folder, read the contents of the folder, set the seen flag on a message, store a message in the folder, and also send a message to the folder. We have not allowed them to delete any messages in the folder, so all is wanted.

When set, the ACLs come into effect immediately. Copying mails to the shared folder will work, but deleting them will not. This enables you as the administrator to set up non-destructive mail store for a group of users with fine-grained access controls.

## Integrating Cyrus and Postfix

So now that you know Cyrus works, you need to set up Postfix to use Cyrus to store the user's mail. In /etc/postfix/main.cf, you need to set the mailbox_transport to use Cyrus. The service is preconfigured in /etc/postfix/master.cf. This file contains definitions for SMTP services as well as any user-defined services that can be used in parameters such as mailbox_transport. So you edit /etc/postfix/main.cf and change the mailbox_transport as:

```
mailbox_transport = cyrus
```

When /etc/postfix/main.cf is edited, restart Postfix with postfix reload. To make sure Cyrus or any other service (as inetd, or cyrus in this chapter) starts when you boot the system, use config -a. Any mail sent to users will be delivered to the mailboxes using the Cyrus service. The Cyrus service calls the deliver command to take the mail message and deliver it to the defined user's mailbox for retrieval instead of the local mail pool.

## Setting an Alias for Root's Mail in Cyrus

One thing you need to consider when using Cyrus in this type of environment is that any mail to a user that is not in the Cyrus database will be rejected by Cyrus. This is especially true for the root user. It is not a good idea to store the root mail in Cyrus, but most people configure an alias for root's mail to be delivered to a non-administrative user. Here we configure root's mail to be delivered to the user justin:

1. Open the file /etc/aliases and add an entry for the root user:
   root: justin
   This tells Postfix that any mail for root should actually be delivered to the user justin.
2. When /etc/aliases is edited, run the postfix command:
   ```
   bible:~ # postfix new /etc/aliases
   ```
3. You need to reload Postfix's databases to commit the new alias.

## Choosing a Mail Client

When your mail server is configured, you will need to be able to read your email. You will find many mail clients available, the most popular being mutt, pine, kmail, and evolution. We briefly describe the benefits of all of the systems and where they are most commonly used.

## Command-Line Clients

If you have only command-line access to your mail, you will probably want to send mail or mutt.

### mail

The mail command is the most basic mail client of all and is used to send mail and receive it using the command line. If you want to send mail with the mail command, it just mail the person you want to send mail to.

```
bible-- # mail just@wileybible.com
Subject: Hello there
This is a test

EOT
```

Here we have asked for the subject of the mail, and we are ready to type our mail message. Notice that at no point during this transaction are we given advice on what to do. This is stereotypical Unix commands at their best!

When the message has been entered, you will need to enter a period on a line by itself and press Enter/Return. This will send the mail to the recipient specified.

To read mail with the mail command, enter mail in the command line and press Enter/Return.

You are presented with a list of mails in your mailbox that you can read. Read a message, just enter the number of the mail you want to read:

```
bible-- # mail
mailx version 10.6 11/15/03. Type ? for help.
"/var/mail/justin/": 1 message 1
>N 1 just@wileybible.com  Thu Sep 30 11:30  14/452  "Hello there"
&
```

Press 1 and Return will show you the mail message you have just sent.

mail is installed by default on Unix systems and can be used as a resort to read your mail. It is also good because you can use the mail command to send mail through a script if you have a list of email addresses you need to send some-thing to (but not spam).
