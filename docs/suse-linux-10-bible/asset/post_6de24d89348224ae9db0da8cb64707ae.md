## Remote Graphical Login

It is also possible to log in graphically and remotely to wiley from bible and see exactly what you would see if you were in front of wiley's monitor.

To make this possible, you will need to do some configuration on wiley; its kdm (or if you are not using KDE, its gdm or xdm) configuration file needs to be fixed so that it allows remote logins.

- 1. For kdm, on wiley, edit the file /etc/opt/kde3/share/config/kdm/kdmrc and the section header [Xdmcp] change the line

```
Enable=false
Enter=true
```

- 2. Now, assuming that no graphics are running on bible (you have issued the command start 3 and you are logged in at a text console), do this:

```
userbible:-> X -query wiley
```

You should see wiley's graphical login screen; you can log in to wiley as any user on wiley and work in your desktop environment.

If graphics are running on bible but you want to be able to log in graphically to wiley (and switch between the two sessions), that is also possible. Simply specify a display on bible that is not in use:

```
userbible:-> X -query wiley :1
```

This starts a new X session with wiley's login screen on bible's second display (the first display is number 0, the second is number 1). You can even run the preceding command from the existing graphical session. The existing display on bible will still be there, and you can switch to it with Ctrl+Alt+F7. You can switch to the new display with Ctrl+Alt+F8.

> To do the same sort of thing automatically, you can use XConfig environment settings or use the yast2 Remote Administration panel. Setting the appropriate UseConfig variable by changing the value of the DISPLAYMANAGER_REMOTE ACCESS to "yes" in the file /etc/sysconfig/displaymanager or by using yast2 Network Service*Remote Administration panel.

## Graphical Connection from Windows

There are ssh clients for Windows, the best known is PuTTY. If you want to view your Linux desktop from a remote Windows machine, one easy way is to use PuTTY together with Virtual Network Computing (VNC). You will need to have tightvnc package installed on Linux, and you will need to have PuTTY and a VNC viewer on Windows.

These applications are provided in the dosutils directory on your SUSE distribution media, but you can always get the latest and greatest versions directly from their home sites. PuTTY is available from www.chiark.greenend.org.uk/~sgatham/putty/. A VNC viewer for Windows is available from www.realvnc.com. It appears that version 3.3.5 of the VNC viewer works best with the tightvnc package included in current versions of SUSE.

Use PuTTY to log in your Linux machine from Windows. When you are logged in, do this:

```
user@bible:->vncserver
You will require a password to access your desktops.
Password:
```

When you have the password, you will see something like this:

```
New 'X desktop is bible:1
Creating default startup script /home/user/.vnc/xstartup
Starting applications specified in /home/user/.vnc/xstartup
Log file is /home/user/.vnc/bible:1.Log
```

You can start the VNC viewer on the Windows machine and connect to bible:1 (or the appropriate IP number followed by :1). The is the display number; the VNC server connects the next available display number, and you have to supply the same number to connect to. You will see a Linux desktop (in fact, running twm as a window manager). If you normally use KDE and you would like to see your usual KDE desktop, you need to edit the file - ~/.vnc/xstartup and replace twm & with startde &

Note that you can also connect to the VNC server through a (Java-enabled) browser by using the address http://bible:5801 — the port number is 5800 to plus the display number.

You can do the same by activating Remote Administration capabilities in YaST.

## Desktop Sharing

The krfb desktop sharing program is also included in part of KDE in SUSE; this allows you to share your current session with another user using the VNC protocol. The krfb program creates a session password and offers the invitation for a limited period of time. Someone can connect to the session from any VNC client elsewhere on the network, but in this case they will be literally sharing the same desktop session — both users can use the keyboard and mouse and the effects will be seen on both displays.

Of course, you can also run a VNC server on Windows and access the Windows desktop using the Linux vncwiew or krdc programs, or you can use these to access your Linux desktop from another Linux machine.

## Cygwin/X

Cygwin/X is available from http://x.cygwin.com/ and is easy to install and run on Windows. When you run the installer, you will find that dependencies, you must install a considerable portion of the Cygwin environment in order to run X. You can then click the Cygwin icon to get a shell, type (for example) X-query, and you can log in graphically to the remote Linux machine.

There are also many affordable of these X server implementations for Windows. The best and most affordable of these are Labtam's XConnect software, available at www.labtam-inc.com. Other companies, such as Humming Communications exceed (www.hummingbird.com/products/nc/exceed/), provide similar capabilities for Windows users who require interoperability.

## Diskless X Terminals

To act as a display for programs that are running elsewhere does not require a great deal of physical resources; the idea of using legacy hardware does to do this an interesting one. We will not discuss this in any detail, but interest is growing in a client-thin approach to desktop computing using Linux.

In a true-client situation, the client machine uses network booting to get its kernel, its directory tree across the network from a NFS (Network File System), and runs programs on the server, with only the display taking locally. In certain variations, some applications are executed locally.

The best-known method for this is the Linux Server Project (LTSP) at www.ltsp.org. At present, LTSP is not included in SUSE distributions. However, recent rumors (which have been confirmed) that Novell's Linux team is interested in improving LTSP and offering it as part of Enterprise solution.

LTSP consists of a directory structure that is exported by NFS to the clients and an adapted kernel. The clients boot by either PXE booting (Intel's Preboot Execution Environment) or etherboot (which allows a network card to boot across the network either from a special floppy or a bootrom added to the card). Installation and setup of LTSP is relatively easy, and LTSP has huge advantages. The hardware used for the clients can be machines that otherwise you would throw away, but the user experience will be similar to a new machine provided the server is powerful enough to support all the clients. No configuration is needed on the clients—if hardware fails, you can simply replace a client machine and everything will still work. Your user files are, of course, on the server.
