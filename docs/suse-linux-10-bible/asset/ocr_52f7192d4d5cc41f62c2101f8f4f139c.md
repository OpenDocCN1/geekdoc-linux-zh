# Destination NAT

Destination NAT (DNAT) is a nice feature when building netfilter firewalls. It does the exact opposite of the SNAT function by translating the destination address of the network packet into another address.

Imagine in the example Figure 24-2 that you had a mail server on your desktop machine. If you want to access that machine to Internet users, you can't just tell the firewall that everyone want to access the IP 192.168.1.3 over port 25, because this is a non-routable address. Internet users would never be able to reach it. To combat this, you can use netfilter that any traffic destined for port 25 on the public firewall address be redirected to the machine 192.168.1.3. Any return traffic to the initiating machine will have the source address of the firewall, making the connection rout. And as the initiating machine is concerned, it has no idea that the machine it is actually talking to is hidden behind a firewall and is on a non-routable address.

To create the illusion, you need to add a DNAT rule to the NAT table for the Simple Mail Transport Protocol (SMTP) service.

```
#: iptables -t nat -A PREROUTING -p tcp --dport smtp -i eth0 -j DNAT --destination=192.168.1.3
```

Here, iptables has been told to work on the NAT table (-t nat) by appending to the PREROUTING chain. You have stated that traffic is TCP (-p tcp)-based, with a destination port of SMTP (25), and entering the firewall on eth1 should be destination-NAT to 192.168.1.3.

In this case, all traffic for port 25 (SMTP) on the public network interface of the firewall will have its destination address changed to 192.168.1.3. The port destination of 25 will be untouched (which will come to this).

> When DNating, you insert the rules into the PREROUTING chain as a routing decision has to be made on the final destination of the packet. At this point the netfilter processing in the PREROUTING chain, the final destination address has not been inserted into the packet, so the routing decision is still yet to be made after this for successful delivery.

In the same regard as SNAT, you still need to allow traffic destined on port 25 to 192.168.1.3 to be forwarded through the firewall.

```
#: iptables -A FORWARD -p tcp --dport 25 -d 192.168.1.3 -i eth1 -o eth0 -j ACCEPT
```
