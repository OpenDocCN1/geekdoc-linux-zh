# Persistent Naming of Network Interfaces

In SUSE 9.3, SUSE changed how the network cards and interfaces were detected. In the past, network configuration and hardware initialization went hand in hand. In 9.3 the hardware-configuration is separate from network configuration. If, for example, a network card has failed, the next network card to be detected will allocate the interface name eth0, for example). In multihomed environments, this can quite you. If you need to be able to work with a specific network card, you should add the PERSISTENT_NAME=nic0 to the configuration file for the network (/etc/sysconfig/network/ifcfg-nic0 is the persistent name you give to the card). This cannot be a mal interface name (eth0,wlan0, or so on) and must be unique so that it does not interfere with the way SUSE 9.3 works with the network.

The problems caused by network interfaces changing their names if persistent names were not been were solved in SUSE 10, which has a means of remembering the name for each interface in the file /etc/udev/rules.d/30-net_persistent_names.rules. PERSISTENT_NAME no longer needs to be set in the /etc/sysconfig/network/ifcfg- files.

To view a specific network interface, you can pass the interface name to the ifconfig command. If you want to view details about eth0 (Ethernet 0) only, use ifconfig eth0.

# Configuring an Interface with ifconfig

To configure an address for an interface with ifconfig, you need to specify the interface in question, the IP address, and traditionally the state of the interface (up or down). Consider the following example, which assigns an IP address to an interface with ifconfig:

```
1:~ # ifconfig eth0 192.168.0.1 up
```

This configures the device eth0 with an IP address of 192.168.0.1 and sets the interface into an active configuration. When you are setting an IP address, the network and broadcast addresses are automatically set based on the IP address given (in a class-based configuration). If you want to set a network mask for this interface, add the netmask option to the ifconfig command.

> If you want to set a classless IP address to split the IP address into subnets, you could set up the interface with ifconfig eth0 192.168.0.1 netmask 255.255.255.240 up. This sets the network mask for the interface, which is used by the kernel to make routing decisions. Subnetting is discussed in more detail in Chapter 6.

# Virtual Interfaces

If you have one Ethernet adapter on your machine with the IP address of 192.168.0.5/24, but you have a machine on that network segment with the IP address of 10.0.2.3/24, you are going to have a tough time communicating with the 10.0.2.3 machine because your only network connection is on a different subnet than 10.0.2.3. The only way to communicate with this machine is to set your IP address to a machine in the 10.0.2/24 network. However, this is usually not an option for your connectivity to the outside world would probably be likely.

The quickest and easiest way to resolve this is to use a virtual interface. A virtual interface (also called a virtual adapter) is something you create and for all intents and purposes is seen as a physical network interface. A virtual interface uses the physical connectivity of an existing network interface (in this case eth0) to send and receive data. This does not affect the work of the main interface address.

One of the most common reasons for using virtual interfaces is when you need to access multiple subnets. For example, if you need to connect to two different networks, 192.168.0.0/24 and 10.0.0.0/24, you can create a virtual interface for each network. This allows your machine to communicate with both networks simultaneously.

To set up a virtual interface, you use the ifconfig command. For example:

```
1:~ # ifconfig eth1 10.0.0.5 up
```
This creates a virtual interface named eth1 and assigns it the IP address 10.0.0.5. You can then use this interface to communicate with the 10.0.0.0/24 network.

# Setting Up Routes

The route command is used to manage the routing table. The most common entry is the default route. The default route is used as a catchall for all traffic you do not know about.

Taking 192.168.0.0/24 as an example, if you look at your routing table, you can see there is an entry for that network.
