Either way, converting an EXT2 filesystem to EXT3 is a painless operation involving two steps: using the tune2fs command to add an EXT3 journal to each EXT2 filesystem that you want to upgrade and updating your system's filesystem table (/etc/fstab) to identify the upgraded partition(s) as EXT3 filesystems rather than EXT2 filesystems. As mentioned earlier, you should not upgrade EXT2 filesystems to EXT3 filesystems in certain circumstances, specifically if your EXT2 filesystem holds data files such as Oracle databases that have their own built-in journaling mechanism. Running two journaling mechanisms on the same file may cause data corruption or may cause your database to crash.

When this command completes, simply bring the file /etc/fstab in your favorite text editor, search for the line related to that partition you upgraded, and change the value ext2 to ext3. After saving the file, you can reboot your system to take advantage of the journaling capabilities of your new EXT3 files.

## Creating a ReiserFS Filesystem

In most cases, you will create ReiserFS partitions when you install your system. However, if you subsequently add a new disk drive to your system, you will need to partition it and create filesystems on those partitions. The ReiserFS filesystem is an excellent choice for most filesystems, especially user filesystems and mail or web server partitions where you will be creating and deleting large numbers of small files. As discussed earlier, the design of the ReiserFS makes it a fast filesystem in which to locate files also helps you get the most out of your available storage by handling small files (less than 4K).

Unfortunately, there is no automatic way to convert an existing filesystem of some other type to a ReiserFS. To convert an existing filesystem to ReiserFS, you would have to back up all data from one of your partitions, create a new ReiserFS partition on that partition, and then restore your data there.

List 3-9 shows (and related output) used to create a ReiserFS filesystem from scratch on /dev/hda5 using the default parameters. Although this example uses the mkfs.reiserfs command directly, you could do exactly the same thing by executing the command mkfs -t reiserfs /dev/hda5.

## Benchmarks

As you can see in the benchmarks, ReiserFS is very good at dealing with small file operations, whereas EXT2 is good at reading large files. XFS copies files sequentially well (not as well as EXT2), whereas JFS proves the best at reading.

| :--- | :--- | :--- | :--- | :--- |
| UNTAR KERNEL 2.4.26 | 24.9 | 23.5 | 21.1 | 22.2 |
| TAR KERNEL 2.4.26 | 17.8 | 23.6 | 24.9 | 27.0 |

| COPY KERNEL 2.4.26 | 18.9 | 46.6 | 38.1 | 34.5 |
| CREATE 1GB FILE | 28.3 | 22.2 | 20.8 | 24.9 |

The benchmarks represented in the graph are as follows:

- UNTAR the kernel 2.4.26: represents a large amount of small files created on the filesystem.
- TAR the same source tree: represents a large amount of small files queried and read.
- REMOVE the kernel 2.4.26: represents a large amount of files removed from the filesystem.
- COPY the kernel 2.4.26: represents reading a large file many times.
- CREATE 1GB FILE: shows how well the filesystem handles the creation of a large file.
- COPY 1GB FILE: shows how well the filesystem deals with both reading and writing a large file.
- CAT 1GB FILE TO NUL represents how well the filesystem can read a file.

These tests are no means conclusive, but they are here to give you an idea of how well the systems perform. Choosing one is a matter of judging how data is manipulated on your system and how you see changing in the future. # Mounting Filesystems

After a filesystem has been created, you will probably want to use it. The process is different from that of other operating systems, such as Windows, where all filesystems are automatically loaded. In Unix, a filesystem has to be mounted by the operating system. Mounting is the process where the root of the filesystem is attached to your system's file hierarchy by associating it with a directory. This may seem like an archaic way of accessing your data, but it does provide you with a transparent way of accessing all the data (local and remote) under a single administrative domain.
