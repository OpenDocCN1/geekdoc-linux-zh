# Listing 12-6: Removing a Dependent Package

```
bible:media/dvd/suse/i586 # rpm -e blackbox
error: Failed dependencies:
blackbox is needed by (installed) bbtools-2005.1.24-3
```

In this example, you have been told that the package bb-tools depends on the Blackbox package we are trying to remove. To resolve this, you have two options, one and one bad bad:

+   The option, which can prove marginally useful during both installation and removal of packages, is to tell RPM to ignore package dependencies. This should never be used when removing a package, because in the case of bbtools, other packages will stop working.

However, during package installation, you may know (for certain that a dependency RPM is aware of is resolved by a source-compiled library you have installed, or are testing). Tell RPM not to check for dependencies, use the --nodeps parameter as the usual rpm -Uvh.

+   The good option (you want to be a good administrator, don't you?) is to remove the dependent package as well as the package you originally wanted to remove, as shown in the following:

```
bible:media/dvd/suse/i586 # rpm -e blackbox bbtools
```

You may have noticed a very important characteristic of package removal, one with many things in Unix - that is, when you are root, you are not warned that you are removing files. This holds true when removing packages. You were not asked to confirm the removal of bbtools and blackbox; rpm assumed you knew what you were doing.

# Verifying RPM

If you want to verify whether an RPM is correctly installed, you can use the rpm -V command. Use the verify command will check the files, its permissions, and also if the package's dependencies are installed so that it can function correctly.

```
bible:- # rpm -V logcheck
bible:- # #
```

If rpm -V returns nothing, then the RPM itself has been successfully verified and all is well.
