# How Mail Sent and Received

When mail is sent to a user, many things have to happen behind the scenes. Here we take an example of Roger sending an email to Justin at different domains.

+   1. Roger, a KDE user, uses kmail to compile a message to justin@palmcoder.net. Roger's mail configuration states that his SMTP (outbound) mail server is mail.disjunctive.org, so kmail connects over 25 (SMTP) to the host and attempts to send the mail to justin@palmcoder.net.
2. When connected, Roger's mail server checks the sanity of the connection and the mail itself (which is discussed later in this). All being well, the mail is accepted, and Roger's mail server then attempts to send the mail to its final recipient, Justin.
3. Roger's mail server knows that palmcoder.net is not handled by his local MTA and proceeds to an MX lookup for palmcoder.net.

An MX Exchange domain name system (DNS) points to the mail server for palmcoder.net. The MX record is the backbone of Internet and provides means for any domain to be resolved to a specific host that handles it for.

In the case of address@palmcoder.net, the DNS MX record is

```
10 mail.palmcoder.net.
```

In Chapter 21, we talk more about how a DNS record works, but for now, realize that the MX record for palmcoder.net points to mail.palmcoder.net.

After mail has been delivered to your mailbox, it is stored until you retrieve it. It is the MDA that actually presents the mail to the user for retrieval. Do not confuse your mail client with an MDA; it is used only to retrieve your mail and to read it!

Popular MDAs are POP3 and IMAP; these two protocols enable users to log in to a mail server and retrieve their messages, an MDA should do. These are discussed later in the chapter.
