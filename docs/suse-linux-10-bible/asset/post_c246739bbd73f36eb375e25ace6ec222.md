This means that you need to take steps to ensure that the group IDs (GIDs) and use UIDs (UIDs) on the server and the clients are identical. ## Setting Up an NIS Server Using YaST

As mentioned, NIS is the most commonly used distributed authentication mechanism today, largely because it is free with almost all Unix and Unix-like systems. Another reason for the prevalence of NIS is that it is incredibly easy to set up, as shown in this section, which walks through the process of setting up an NIS server. The Those YaST administration tool further simplifies NIS set up and configuration. Configuring other systems so that they get their authentication information from NIS (and are then known as NIS clients) is explained in this chapter.

To use YaST to configure a system as an NIS server, do the following:

- 1. YaST's NIS Server configuration module from the Control Center or by typing the yast2 nis_server command from a root shell or using sudo. This displays the dialog box shown in Figure 22-3.
- 2. Select the Create NIS Server option button and click Next to display the dialog box shown in Figure 22-4 displays.
- 3. Enter the name of NIS domain for which you are setting up a server. You can also enable users to change their NIS passwords by selecting the Allow changes option button. You may also want to allow users to change their login shells by clicking the Allow changes to login shell option button—there may be a /bin/csh user on one of your systems. Click Next to display the dialog box shown in Figure 22-5.

## Setting Up an NIS Server Manually

This section explains how to set up an NIS server from the command line. YaST removes the need to do this, and you don't need to follow the instructions in this section if you set up an NIS server using YaST. However, it's still convenient to know exactly what changes are made under the hood or in order to set up an NIS server. An NIS server that is configured using the instructions in this section exports the default password, group, host, and on maps (files) found on the NIS server system. In a production environment, you would want to substantially more customization before initiating NIS throughout your computing environment. You would also want to configure the NIS configuration files `/var/yp/securenets`, `/etc/yp.conf`, and `/etc/ypmap.conf`.

To set up an NIS server, log in or use the su command to become root on the system you will be configuring as and do the following:

- 1. Make sure that the NIS software is installed on your Linux system. At a minimum, you will need the `/bin/domainname`, `/usr/sbin/ypserv`, and `/usr/lib/yp/ypinit` programs.

## Configuring Clients for NIS

This section explains how to set up an NIS client of the server started in the previous section. With setting up a NIS server, NIS clients can be configured using command-line utilities or by taking advantage of Ya's graphical administrative interface. The following two sections explain how to configure an NIS client using each of these methods.

### Configuring NIS Client using YaST

YaST makes NIS client configuration almost trivial, using a single dialog box to collect information about the NIS domain that you want your client to use. To configure a system using an NIS client YaST, do the following:

- 1. Start YaST's NIS client configuration by executing the command yast2 nis as root or sudo. This displays the dialog shown in Figure 2-7.
- 2. Click the NIS option button, and enter the name of the NIS domain you want the client to contact for authentication information. If your client system uses DHCP to deliver NIS server information, click Automatic Setup (through DHCP).
- 3. If you want the NIS Client to search the local network by broadcasting if a connection to the specified NFS server fails, click the Broadcast option button.
- 4. Finish. YaST modifies your system's configuration files to use NIS and exits after those modifications have been made.
