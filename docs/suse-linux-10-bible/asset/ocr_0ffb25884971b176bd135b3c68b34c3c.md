The way in which the `ls` displays its output depends on a set of options, which are stored in the `LS_OPTIONS` environment variable. This setting is in set up in the file `/etc/bash.bashrc`. If you examine the contents of this file, you will find something like the following:

```
user:- > echo LS_OPTIONS
-N --color=tty -T 0
```

This means that these options are passed to `ls` whenever it is run. You can override these options by setting and exporting a different `LS_OPTIONS` variable:

```
user@bible:- > export LS_OPTIONS='color-never -T'
```

Then you will see the same layout, but without any colorized entries. Any options that can be passed to `ls` can be included in this variable.

If you want a permanently different option for yourself, you can set and export the `LS_OPTIONS` variable by adding a line similar to that just to give to your `.bashrc` file.

> The color scheme that `ls` uses to colorize its output is determined by the `LS_COLOR` variable. By default this is taken from the file `/etc/DIR_COLORS`, but you can override the defaults by copying that file to `~/dir_colors` and editing it as required.

# Using mv

It strikes people all that `mv` is a command for moving and for renaming. It is quite logical: what happens is if you move a file from the directory to somewhere else, the file appears over and disappears here. If you rename the file, the copy with the new name appears, and the copy with the old name disappears. And of course you can copy the file to a new location and a new name with just one invocation of the `mv` command. For example:

```
user@bible:-> mv afile /tmp/
```
