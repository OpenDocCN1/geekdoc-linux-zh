# Shell Variables

As a script is essentially just a string of shell commands, it understands the current environment variables. For example:

```bash
#!/bin/bash
echo "Hello" $USER
echo "Your current directory is" $PWD
```

Here $USER and $PWD are the environment variables that are already accessible to the shell representing the current user and the working directory, respectively.

If you save in a file scr1.sh, you have a simple shell script. The first line tells the system to interpret the script using /bin/bash. This line applies if you make the script executable and run it directly, and it is important because it is possible that the user might be running a different shell. In fact, you can run the script in two ways:

- Under the current shell by sourcing it:
  credibleible-> source scr1.sh
  Hello fred
  Your current directory is /home/fred
- Use a dot as the source command:
  credibleible-> . scr1.sh
  Hello fred
  Your current directory is /home/fred

You can also run the script by explicitly calling bash:

```bash
credible-> bash scr1.sh
```

Or, because /bin/bash is a symbolic link to /bin/bash, you can do the following:

```bash
credible-> sh scr1.sh
```

Alternatively, you can make the script executable and run it as a program. This is done by the chmod command, which adds executable permissions for all. Note that if you want to run the script in this way, it must have the first line:

```bash
#!/bin/bash
```

A shell script can include the types of logical structures that one would expect to find in any programming language. For example, a for loop:

```bash
#!/bin/bash
for i in 1 2 3 4 5
do
echo $i
done
```

Here $i represents the variable i, which takes the successive values in the loop.

Save this as scr2.sh, make it executable, and run it as you have previously, and you'll see the following:

```bash
fred@bible:-> chmod +x scr2.sh
fred@bible:-> ./scr2.sh
1
2
3
4
5
```

Although you are unlikely to use numerical variables often as basic counters in keeping track of a repeating process, you can do arithmetic in shell scripts:

```bash
#!/bin/bash
a=12
echo "a is $a"
echo "a+1 is $((a+1))"
```

This script produces output like this:

```bash
a is 12
a+1 is 13
```

> Note that there should be no white space around the = sign; if there is, the variable will not be assigned. Notice also the way that extra brackets were needed in $((a+1)).

Variables can equally represent strings:

```bash
#! /bin/bash
a=ABCDE
echo $a
echo ${a}FGHIJ
```

```bash
ABCDE
ABCDEFGHIGHJ
```

Here, to get the desired result, you had to write ${a}FGHIJ rather than $aFGHIJ, which would have represented a new and undefined variable (named aFGHIJ). This ensures that bash interprets the last line as a to echo the variable, which we defined as a, followed immediately by the string FGHIJ.

Suppose you want to produce word count for all the files with the file extension .txt in the current directory.

```bash
#! /bin/bash
for i in *.txt
do
wc -l $i
done
```

This produces output as shown in the following lines, indicating that you can loop over a set of files produced by globbing—the use of a notation such as *.txt.

```bash
3 1.txt
8 2.txt
17 3.txt
```

Clearly you could take this idea further to select, for example, certain lines from each set of files and append them to a file:

```bash
#! /bin/bash
for i in *.html
do
grep -i \<title> $i >>titles.list
done
```

This creates a file containing all lines of the form:

```html
<title>Page Title</title>
```

from any of the HTML files in the current directory. Or you could do anything else that can be done with one or more commands acting on each file and direct the output to another.

# 401 Working with the System

To test for the existence of a file with a given name, do the following:

```bash
#! /bin/bash
if [ -f masterpiece.doc ]
    then echo "found masterpiece"
else
    echo "a cultural tragedy for the whole of humanity"
fi
```

Note that the f has to be closed with fi. Note also that you need a space after the square bracket and before the -f.

In system scripts you will often see a test for the existence of a file; if the file exists, the script may, for example, source it, delete it, rename it, or rewrite it.

# File Tests

There are many different tests including -e (simple existence of a file), -f (existence of a regular file rather than a directory or device file), and -d (a directory), as well as tests based on permissions and modification dates, among others.

You can see examples of these in the standard .profile on SUSE, which contains these lines (commented out as it happens):

```bash
if -x /usr/bin/fortune ]; then
echo
/usr/bin/fortune
echo
fi
```

These lines cause the fortune program to run when you log in it if it is installed.
The test -x checks the current user has execute permission on /usr/bin/fortune. (If you don't have installed, you might enjoy trying it out.)

As another example, in /etc/init.d/xntpd, you can see these lines:

```bash
NTP_CONF="/etc/ntp..conf"
if [ -f $NTP_CONF ]; then
    echo -n "Time configuration file, ${NTP_CONF} does not exist."
```

In other words, if you find that the required file is not there, you output a statement to effect that.
