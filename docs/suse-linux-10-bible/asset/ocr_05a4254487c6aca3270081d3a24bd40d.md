# Chapter 15 ♦ Linux Networking 429

If you want to connect to the SSH server as another user, you have two options;
either the -l switch to specify the user or the more compact username@server
notation. For example:

```
just::-> ssh root@
Password:
Last login: Tue Jul 6 04:23:05 2005
Have a lot of fun...
bible: #
```

Because we specified the username on the command line, we were asked for that
user's password and not ours. In this case, we logged in as the user root.

# Public and Private Keys

If you are bored of typing in passwords, or you want to make the process of remote
authentication secure, you can use public and private keys to identify yourself.

A PPK (Public Private Key) pair consists of two keys:

+   - One key that you keep to yourself and share with no one else (the private
key).

+   - The other is a public key that you install on all servers you want to log in
that can be read by anybody.

PPKs are useless if you do not have the pair of keys. Even if someone finds your
public key, they cannot use it detrimentally, because it is used only as the partner
of the private key you have kept secret.

To create a PPK, you need to run the ssh-keygen command. The ssh-keygen com-
mands a few arguments, but we will create a standard SSH2 key pair for
purposes. Consider the example in Listing 15-11.

# Passphrases

You have two options for how you want to create your key pair — or without a pass-
phrase. A passphrase is a long string of characters that can be thought of as your password.
A passphrase could be a sentence, a piece of text you can remember, and can contain
spaces. This makes the PPK much more secure even if your private key has
compromised, the user still needs to know your passphrase. If you do not set a
passphrase, you can then log in to a machine without entering a password or a passphrase
and rely on the security of the PPK partnership and nothing else. If security is a big
thing for you (and it should be), you should set a passphrase when asked.
