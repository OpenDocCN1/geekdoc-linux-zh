Thread-local storage, is implemented in current versions of glibc and its associated threading package, can cause problems with applications running under Xen. Its implementation under Xen can also be very slow. To disable thread-local storage under Xen and thus fall back to the simpler mechanisms used by earlier versions of glibc, move the file /lib/tls to /lib/tls.disabled in each filesystem that you use with a Xen domain. If you do not, you will receive a warning message in the console log for each Xen domain that you start other than dom 0.

# Creating Swap Space for Xen Domains

After you have created a root filesystem for a new Xen domain, you should also prepare a swap file or partition for that domain. Like any Linux system, any operating system running under Xen must also have an swap partition. This partition can be a file or disk partition, and formatted using the standard mkswap command.

Make sure that an entry for the swap partition exists in the /etc/fstab file in the root filesystem for your Xen domain. With the root filesystem, the entry for the swap partition in fstab will reflect the name of the swap partition as seen by the Xen domain that you are creating, which will usually differ from their names on the Linux system where the files or partitions are actually stored. See the following section, "Creating Xen Configuration Files," for information on how to specify the name by which your Xen domain will see your swap partition.
