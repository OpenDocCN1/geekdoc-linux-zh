## Connecting Commands and Redirecting Input and Output

Unix and Linux commands are designed with a KISS (Keep It Simple, Stupid) philosophy. Some operating systems feature thousands of specialized commands that perform many specific, but similar, tasks. Unix and Linux take the opposite approach, providing many small, simple commands that you can combine to perform complex tasks.

For example, some operating systems might provide a specialized command to print a list of the current directory. On a Linux system, you would perform this task by combining the existing list (ls) and print (grep) commands into a single sequence of commands in which the output of the ls command is provided as input to the grep command by connecting the two commands using a special symbol (|), as in the following example:

```
ls | grep
```

Linux shells provide this capability by connecting the output from one command to the input by another. In Linux terms, this is connecting the standard output from one command to the standard input of another. The pipe symbol automatically ties the two commands together and sends the output of the first to the second as input.

Linux actually provides two ways of specifying that the output of one command is meant to be another — by using a pipe to connect the two commands, or by what is known as redirecting IO, for redirecting input/output.

The output of a file can also be redirected to a file, using the greater sign (>), which simply creates a file containing the output of the command, as in the following:

```
ls > listing.out
```

This command takes the output of the ls command and sends it to the file listing.out.

Linux supports combining commands and redirecting input and output by recognizing three different aspects of program and output:

- stdin — The standard input stream that is read by a program
- stdout — The standard output stream to which program output is sent
- stderr — A specialized output stream known as standard error to which program error messages are written

You will encounter these terms as you become more familiar with executing shell commands because these are the cornerstones of creating complex commands by stringing together simple ones. Like the regular expressions discussed in the previous section, redirecting input and output is an extremely powerful feature of Linux shells. Entire books have been written about shells such as bash and tsh — search your online bookseller for these if you want to become a true shell expert and amaze your friends with various complex shell tricks.

## Getting Help for Linux Commands

The man and info commands are basic ways to view program documentation on Linux. To view the man or info help for a specific command, you use the man or info followed by the name of the command that you want to see on.

The man command provides access to the traditional Unix and info manual, displaying formatted help that you can page through. The info command is a newer online help mechanism that displays text for commands in a customized version of emacs with hypertext capabilities that enable you to jump from one topic to another. Many commands maintain their help only in info format rather than supporting both. In general, info help for a command is always as up-to-date and complete as the equivalent man help for that command.

The info interface is a little confusing for beginners; it is actually a form of hypertext. SUSE also offers pinch, which is slightly easier to use, and the ability to view man and info pages using the Konqueror browser. See Chapter 5 for more details.

- man ls — Views the page for the ls command
- man -dk — Looks for man referring to the word disk
- info coreutils — Looks at the info page for the coreutils package

> A number of excellent books and info references are available that provide detailed information about standard Linux commands, shells, and so on. One of the best sources of information about Linux is the Linux Documentation Project, available at www.tip.org. In the true spirit of Linux, the Linux Documentation Project provides hundreds of free documents, HOWTO files, and compilations of frequently asked questions (FAQs) that explain different aspects of using standard Linux systems.

## Listing Files

The ls (list) command lists files in the current directory. The command ls has a large number of options, but what you really need to know is that ls -l gives a "long" listing showing file sizes and permissions, and that the -a option shows "hidden" files—those with a dot at the start of their names. The shell expands the character to mean any string of characters not starting with '.'; See the discussion of wildcards in Advanced Shell Files section for more information how and why this works. Therefore, *.doc is interpreted as a filename ending with .doc that does not start with a dot and * means "any filename starting with the letter". For example:

- ls -la Gives a list of all files in the current directory including hidden files with names starting with a
- ls a* Lists all files in the current directory whose names start with a
- ls *.doc Gives a list of all files in the current directory whose names end with .doc

## Copy Files

The cp (copy) command copies a file, files, or directory to another location. The option -r allows you to copy directories recursively (in general, -R or -r commands often have the meaning of "recursive"). If the last argument is a directory, the files mentioned will be copied into that directory. Note that by default, cp will clobber existing files; in the second example that follows, if there is already a file called a in the directory /home/bible, it will be overwritten without asking for confirmation. Consider the following examples:

- cp file.bak Copies the file file to a new file.bak.
- cp file /home/bible/ Copies the file file from the current directory to the directory /home/bible/
- cp * /tmp/ Copies all nonhidden files in the current directory to /tmp/.
