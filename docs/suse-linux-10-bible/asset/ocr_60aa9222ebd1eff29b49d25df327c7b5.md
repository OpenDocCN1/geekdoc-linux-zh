+   2. When the suffix and the rootdn have defined, you need to configure the administrator password. There are a few ways to do this—insecure and secure. Obviously, you want to set up the password securely.

> Note The rootdn is not an entry in the LDAP directory but do account for the information for the LDAP administrator.

To produce an encrypted password, you need use the slapppasswd command:
bible:/etc/ldapd # slapppasswd
New password:
Re-enter password:
{ SSH }F13k4cAbh0IAxbpKNhH7vTcL4HGszsJ+
bible:/etc/ldapd #

> Caution You can define the password using cleartext (the password is entered into the slapd.conf), if you want to do a quick and dirty implementation, but is highly advisable to insert the encrypted form of the password.

+   3. After you enter the password to use twice, the slapppasswd command returns an encrypted password that can be used in slapd.conf.

+   4. When you have the encrypted password, you need to find the rootpw entry in slapd.conf and enter it there.

```
rootpw { SSH }F13k4cAbh0IAxbpKNhH7vTcL4HGszsJ+
```

# Testing the LDAP Server

When the initial slapd.conf configuration has taken place, you need to start the LDAP server with rceld:

```
bible:/etc/ldapd # rceld start
Starting ldap-server
```

When started, you can use the ldapsearch command to bind (connect) to the LDAP server with the administrator account (see Listing 25-1). Unlike an anonymous bind, we are authenticating to the LDAP server.

> Tip To start OpenLDAP automatically when the system boots, use chkconfig: chkconfig -f - ldap.
