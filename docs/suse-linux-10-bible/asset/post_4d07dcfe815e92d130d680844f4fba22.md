
#!/bin/bash
case $1 in
happy)
echo "What a nice day it is today"
;;
sad)
echo "What a gloomy day it is today"
;;
esac
```

The script is deciding what it will output on the basis of the value of a variable (in this case the argument that was given). Such conditional branching is a key feature of any kind of programming.

```bash
$ ./case.sh happy
What a nice day it is today

$ ./case.sh sad
What a gloomy day it is today

$ ./case.sh mad
```

Notice that the alternative tests are followed by a newline, and the conditional block as whole is terminated by a semicolon. The whole set of conditions is closed by esac.

## Mailing from a Script

You may want to be informed of the progress or success. One way to achieve this is using the `mail` command. It will look something like

```bash
echo "many returns" | mail -s "Happy Birthday" user@domain.net
```

This sends an email with the subject "Happy Birthday" to the address. The message body could have been obtained from a file on the system. Of course it's more likely that the kind of message sent is something like "complete," but there are almost certainly system administrators who use cron job to avoid forgetting their birthdays!

## The Limits of Shell Scripting

A large amount of the infrastructure of the system rests on shell scripts. In particular, the whole init and runlevel system depends on a large number of interdependent shell scripts. These are also read from /etc/sysconfig/ and elsewhere. They may have heavy use of basic commands as awk, sed, and grep work efficiently.

However, as a user or system administrator, you may not necessarily consider that shell scripts are the easiest or most elegant way to execute some logic to get done. In general, shell scripts are best for the kinds of things they commonly do: relatively small scripts working at a low level. For more complex tasks, people often turn to dedicated scripting languages. In practice, this means either Perl or Python (or Ruby). If you are interested in creating dynamic web content, look also at PHP scripting as well as CGI scripts written in either Perl or Python, and take your choice.

## Scripting Languages

Just as there are "religious wars" between the followers of vi and the devotees of emacs (as we discuss in Chapter 11) or the lovers of KDE and the true GNOME believers, in the case of scripting languages something of a division exists between Perl and Python users.

- Perl is far common and arguably more versatile, if only because of the very large number of modules that have been written for. It is possible to write much more code in Perl, which is full of shorthand and special notations.
- Python is newer, cleaner, and arguably more elegant. It is certainly the easiest language to learn, and it is much easier to read another person’s Python code than another person’s Perl code.

The difference between them is perhaps best summed up the Perl slogan, "There is more than one way to do it," and the Python response to that, "There should be one—and preferably only one—obvious way to do it."

This is not the place to briefly introduce these language; again there are many resources available on both of them (see the "Comments and Resources" section in the chapter for some resource options).

If you know the place of them and want to do useful scripting quickly, we advise you to learn Python. However, if you are likely to be working in an environment where you are required to maintain scripts that others have written, then Perl will probably be the right first choice.
