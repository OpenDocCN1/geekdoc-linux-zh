# Network Address Translation

While one of the main uses of netfilter is its packet filtering functions, another important aspect of netfilter is its NAT functions.

Network Address Translation (NAT) is the process whereby the source or destination IP of a packet is seamlessly changed when it passes through the firewall.

+   Chapter 6 contains more information about NAT.

# Source NAT

Source NAT (SNAT) works on packets forwarded through the firewall before a packet leaves for the outbound network. For this work, you must deal with the packets before any routing decisions have been made, and the POSTROUTING chain must be used to implement Source NAT.

The main purpose of SNAT is to hide private networks behind a firewall with a public IP address. This drastically reduces the cost of acquiring public IP addresses and allows you to use non-routable addresses in your internal network.

The POSTROUT chain deals with any packets that are to be sent out to the network card. This includes any packets that are routed onto other destinations. In the case of SNAT, this is the only chain that you want to use as destinations, for example, it makes no sense to use NAT traffic coming into the INPUT chain.

Figure 24-2 details how a network uses netfilter to SNAT its internal network.

In this scenario, all of the machines are behind a netfilter firewall that will not protect the machines, but also provides NAT for outgoing connections. For SNAT to work, IP forwarding must be enabled. To do this, enter a 1 into /proc/sys/net/ipv4/forward.

```
: echo 1 > /proc/sys/net/ipv4/forward
```

This will immediately enable IP forwarding on your Linux machine. This is a volatile operation, and once your machine has been rebooted, IP forwarding will be turned off by default.

To set IP forwarding by default, edit the file /etc/sysconfig/sysctl and change IP_FORWARD from no to yes and re-run SUSEconfig. While editing the sysctl file, make sure that DISABLE_ECN is set to yes.
