## The Wonderful World of ARP

On the level of Ethernet, station (node) listens for traffic destined to its physical (MAC) address. In Chapter 6, we talked about the layered model of the ISO OSI. This model can help your understanding here because TCP/IP traffic has been encapsulated into an Ethernet frame, the destination Ethernet address is also added. However, at this level, the IP address does not come into play because it is purely Ethernet-based addressing. So does the sending machine know what Ethernet address local traffic should have?

TCP/IP uses Address Resolution Protocol (ARP) to map an IP address to a local (to the network) address. When a machine needs to send data to a machine on its local network, it sends an ARP broadcast asking "Who has the IP address 192.168.0.237? The 192.168.0.233 (if alive) will respond, "I have IP address, and my MAC address is XYZ." The sender uses this MAC address as the destination in the Ethernet frame when it needs to send data to the 192.168.0.233.

Now, if every time data needs to be sent to 192.168.0.233 the sending host were to do an ARP lookup, would slow down the transfer of data. To combat this, Linux keeps an ARP cache. This cache contains a lookup table, correlating the IP address to the destination MAC address.

To view the ARP table, use the command arp (see Listing 15-6). In the following output, you can see how an IP address is correlated to a MAC address (for example, IP 192.168.0.1 is associated with MAC (hardware) address 00:00:00:00:01).

### Listing 15: Viewing the ARP Cache

```bash
bible: # arp -n
Address          Type        Hardware        Flags   Interface
192.168.0.1     ether       00:00:00:00:01  C       eth0
192.168.0.233   ether       00:00:00:00:02  C       eth0
```

Here, you have told arp not to resolve machine addresses as this will slow the operation. Most network-based operations can use the -n parameter to stop host name lookups.

> If you want to remove an entry from the ARP cache (if the machine is taken down and another machine has the IP address associated with a stale hardware address), you can use the arp -d command. To remove the 192.168.0.1 ARP entry, use arp -d 192.168.0.1.

![](img/e4e45c9f32e76fb35fabbd21a96f1a1e_466_0.png)

You can see the IP address of the nodes in question, the hardware type (ether or Ethernet), hardware address, and the flags associated with these entries.

The ARP flags explain the status of a specific ARP entry. C means this is a complete associated entry. M specifies a permanent entry (it will not get flushed from the cache), and a published entry is signified by a P. A published entry is way to allow your machine to answer ARP requests on behalf of other hosts. By default, your ARP cache is concerned only with your own machine communications.
