# The Filter

Listing 7-5 gives an example of a syslog-ng filter.

| Listing 7-5: The Filter |
| f_iptables { facility(kernel) and match("IN") and match("OUT"); }; |

A filter in syslog-ng is the same as the first field in the syslog.conf file but has the capability to be much more granular. In the example shown in Listing 7-5, you are defining a filter named f iptables. This filter filters out messages that have the log-facility of kernel and uses a regular expression to match a message if it contains the words IN or OUT. The regular expression capabilities of syslog-ng enable to eliminate or redirect logging messages based on their contents.

> We talk about iptables in detail in Chapter 24. Now, you can use iptables to log messages about TCP/IP packet with a message prefix. For example, you can say that a message has been denied Into your machine/network, then the message is prefixed with the word IN. It is true for any messages that have been denied OUT of your network. In this case, you could tell syslog-ng to log these facts into a separate file for your perusal at a convenient time.

# The Log Destination

Listing 7-6 shows an example of a log destination.

| Listing 7-6: The Destination |
| destination firewall { file("/var/log/firewall"); }; |

By default, SUSE comments this line out in order to send these messages to its default location. With most services in SUSE, all output is sent to the /var/log/messages file because there is not a logging facility for each specific service. So we assume we have uncommented the destination for use on our system that firewall goes to a specific destination. The destination specifies that the custom definition firewall will write log messages to the file /var/log/firewall. This enables you to examine firewall-related messages (produced by the iptables facility, which filters network packets) by simply examining a specific log file.
