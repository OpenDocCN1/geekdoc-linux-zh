If you want to get a full recursive listing of all files beneath a directory, the command `ls -lAR` is what you want. This can be particularly useful if you are doing some detective work to find out, for example, what is being changed when you make some change to a system using a graphical or other configuration tool, but you don't know which file or files are being changed. If you use `ls -lAR` before making the change, writing the output to a file, you can compare the two files and work out what has happened.

```
root@bible: # ls -lAR /tmp/listing1
```

(Some to change the system.)

```
root@bible: # ls -lAR /tmp/listing2
root@bible: # diff /tmp/listing1 /tmp/listing2
```

Here we have made some change to the system at the step marked "Some to change system," before and after we created separate files containing a listing of files existing at that time. Using `diff`, you can see what has changed.

The way in which the `ls` displays its output depends on a set of options, which are stored in the `LS_OPTIONS` environment variable. This setting is set up in the file `/etc/bash.bashrc`. If you examine the contents of this file, you will find something like the following:

```
user:- > echo LS_OPTIONS
-N --color=tty -T 0
```

This means that these options are passed to `ls` whenever it is run. You can override these options by setting and exporting a different `LS_OPTIONS` variable:

```
user@bible:- > export LS_OPTIONS='color-never -T'
```

Then you will see the same layout, but without any colorized entries. Any options that can be passed to `ls` can be included in this variable.

If you want a permanently different option for yourself, you can set and export the `LS_OPTIONS` variable by adding a line similar to that just to give to your `.bashrc` file.

# Using mv

It strikes people all that `mv` is a command for moving and for renaming. It is quite logical: what happens is if you move a file from the directory to somewhere else, the file appears over and disappears here. If you rename the file, the copy with the new name appears, and the copy with the old name disappears. And of course you can copy the file to a new location and a new name with just one invocation of the `mv` command. For example:


moves afile to the /tmp directory and

# Using rm

Take care. The `rm` command removes files and doesn't (by default) give you any second chances, so it is dangerous. There are various ways to use rm to make it less final, but none of them are totally satisfactory.

You may choose to use `rm` in place of `rm -i`; this makes it interactive, and you will be prompted before the file is actually removed:

```
userfile:~/directory ls
afile
userfile:~/directory rm -i afile
rm: remove regular empty file `afile`? y
userfile:~/directory
```

If you like this, you can create an alias in the file `.alias` in your home directory (or in your .bashrc file) to make `rm` always behave like `rm -i`. You can add a line like this:

```
alias rm='rm -i'
```

to ~/.bashrc. When you log in the next time, you will see this behavior:

```
userfile:~/directory ls
afile
userfile:~/directory rm afile
rm: remove regular empty file `afile`? y
userfile:~/directory
```

# File Managers

A file manager is a tool that enables you to look at the layout of the files and directories on your system and to perform various actions on the files (copy, move, delete, and so on). There are three particularly useful choices for a file manager: Konqueror, Nautilus, and m c. If you are using KDE, then by default you are likely to use Konqueror as your file manager. If you are GNOME, the same applies to Nautilus. m c (Midnight Commander) is a text-based file manager that has some very useful features.

# Konqueror as a File Manager

If you want to use Konqueror as a file manager, Konqueror's file manager is powerful. It has the advantage that you can show views of some of the files as it lists them. (You can configure this behavior to extent in Konqueror's settings). When selecting files, remember KDE's interface: People who use Windows will tend to left-click a file and then surprised when it opens in an application.

A right-click inside a directory brings up a menu that includes the ability to create new directories or operations on the selected file such as Copy to Move Move.

Konqueror has recently added some functionality, including the ability to open a KDir window (displaying directory statistics: the sizes of files and subdirectories displayed graphically). You can also bring up a graphical tool that will string replacement on all files in a directory (KFileReplace).

As we have noted elsewhere, Konqueror displays files across the network and includes the ability to display files on a machine accessed by ssh as if they were local.
