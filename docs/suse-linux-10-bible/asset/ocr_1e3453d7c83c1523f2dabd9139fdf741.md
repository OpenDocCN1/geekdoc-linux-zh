# Using SSH for Virtual Terminals

Like its poorer cousin, the prime use of SSH is to log securely to servers. SSH does not provide you with a login and password prompt as Telnet does. SSH takes in the user authentication process when the connection is being negotiated (you will see why later). Because of this, SSH needs to know the username you want to connect to the server before it attempts a connection. If you use SSH to connect to a remote server, the SSH client will assume you want to connect to the server as your current userid (see Listing 15-10).

> Listing 15-10: Using SSH to Log in to a Remote Server as the Current User

```
justinible:--> ssh bible
The authenticity of host 'bible (192.168.0.1)' can't be established.
RSA key fingerprint is e3:04:b1:de:55:80:e4:7d:5f:86:f2:8da
Are you sure you want to continue connecting (yes/no)? yes
Warning: Permanently added 'bible,192.168.0.1' (RSA) to the list of hosts.
Password:
Last login: Wed May 12 13:30:36 2005 from console
Have a lot of fun...
justinible:-->
```

If you look at the output in the preceding listing, you notice quite an important thing happening when we attempted to log in the machine bible. We were told that the machine has not recognized and thus is not trusted. This is part of the security of the SSH protocol. You will see this warning for every machine you log in for the first time. If you want to proceed and log in to the server, your client will make a note of the fingerprint of the remote server.

If you try to log to the server again, but someone has maliciously tricked you into thinking you were connecting to your original server (in fact it was a bogus server with the same name), SSH knows that the fingerprint of the machine is bogus and warns you of this when you log in.

As you can see, we were not asked for a username because the SSH client already knew we wanted to connect as the user justin.
