# Using rm

Take care. The rm command removes files and doesnt (by default) give you any second chances, so it is dangerous. There are various ways to use rm to make it less final, but none of them are totally satisfactory.

You may choose to use rm in place of rm; this makes it interactive, and you will be prompted before the file is actually removed:

```
userfile:~/directory ls
afile
userfile:~/directory rm -i afile
rm: remove regular empty file `afile`? y
userfile:~/directory
```

If you like this, you can create an alias in the file .alias in your home directory (or in your .bashrc file) to make rm always behave like rm -i. You can add a line like this:

```
alias rm='rm -i'
```

to ~/.. When you log in the next time, you will see this behavior:

```
userfile:~/directory ls
afile
userfile:~/directory rm afile
rm: remove regular empty file `afile`? y
userfile:~/directory
```

So rm is behaving like rm -i. If you don't want to be prompted, you will now need to use rm -f.

> Note The only problem with this is that it gives you a false sense of security: if you are logged in on a system where you have not set up the alias, you may remember too late that this safety blanket was not available. In some ways the best advice is to always think about what you're doing before you press the Return key (and always keep regular backups).
