Wouldn't it be nice to be able to run one or two Windows applications that you need without the overhead and storage of a completely embedded Windows system?

Providing the ability to run Windows applications natively on Linux and other Unix-like systems is the precise goal of the Wine (Wine Is Not an Emulator) Project (winehq.com). Wine is an open source implementation of the application programming interface (API) provided by Microsoft Windows and used by all Microsoft Windows applications. Wine runs in the Windows system environment on Linux and Unix. SU Linux includes a stable and tested version of Wine to enable many Windows applications to install and execute normally on SUSE systems.

Wine is one of the most misunderstood open source projects. Unlike emulators, which simulate the behavior of a given operating system or graphical environment and support its applications within that environment, Wine is a complete reimplementation of the API used by Windows applications. It does not need to translate API calls into equivalent Linux or X system calls on the fly. Applications running under Wine call the same graphical APIs that they always called, but the implementation these APIs immediately performs X system functions rather than the Wine functions that one would need if the application was running on a Microsoft Windows system. Very cool!

Wine is installed on SUSE Linux as part of the Office applications package. To install a Windows software package on Linux, execute the wine command, followed by the name of the installer for that package. For example, to install the Windows NX Client on your Linux system, you would execute the following command:

```
$ wine rxclient-1.4.0-92.exe
```

Figure 28-3 shows a Windows installer running on a SUSE system under Wine. The first time you run it on your Linux system, Wine creates a mock Windows directory hierarchy, as indicated by the message in the Console in Figure 28-3. This mock Windows directory structure is located in the directory ~/.wine, and contains a configuration directory, a devices directory that provides DOS/Windows drive letter mappings, a drive_c that mirrors the directory structure that Windows expects to find on its boot drive, and files that contain various system and user information and represent the Windows registry.

After you have installed a software package under Wine, you can execute any of the applications it contains by specifying the wine command followed by the full pathname of the program you want to run, as in the following example:

```
$ wine ~/drive_c/Program\ Files/Windows/rxclient.exe
```

## The box Emulator

The box project goes a long way. It is a free (licensed under the LGPL) PC hardware emulator that provides a complete emulation of PC hardware in software. As is the case with QEMU and VMware (see later in the chapter), you can install an operating system into box. However, box means there is no virtualization of the underlying hardware. This means that it can be built and run on any Unix-like platform on any hardware architecture. For most practical purposes, if you want to run x86 operating systems as virtual machines on x86, then either QEMU (free) or VMware (proprietary and commercial) will probably be a better choice.

A box package is included in SUSE Linux. Install it in the usual way, and type the command box. A set of text menus appears in which you can set options. You can write these to create a configuration file for use. After you have set the options, or box menus read from a configuration file, a graphical window will appear. Provided box knows how to find its virtual CD drive, you can begin installing an operating system, and you have created and configured a virtual hard disk.

Because box is so slow, unless you have very powerful hardware to run it on, or you have an academic interest in the workings of emulation and the x86 processor family, you will probably conclude that for purposes either QEMU or VMware is a more useful solution, particularly if you want to get real work done with your guest operating system.

## Virtual Machines Using QEMU

QEMU is an open source hardware emulator. It can emulate an x86 system on x86, but can also both emulate and run on some other architectures. In particular, it can emulate and run on the PowerPC architecture.

QEMU packages are included in the SUSE distribution. QEMU is developed by Fabrice Bellard, and the latest version is always available from http://fabrice.bellard.free/qemu/.

You can install x86 operating systems in QEMU, including most versions of Windows and most Linux distributions.

QEMU manages to achieve reasonable speeds (between 5 to 10 times slower than native) using dynamic translation of binary code. The author, Fabrice Bellard, also offers a QEMU accelerator known as kvm for the Linux operating system. The accelerator is a special kernel module that improves the performance of QEMU very considerably (the QEMU web claims that guest operating systems will run better than half native speed if the accelerator is running; this is nothing as good as Xen or VMware, but is far better than box). It works by QEMU to get access to the underlying hardware, as VMware does. Certainly informal tests show that for Microsoft Word on Windows 2000 QEMU with the accelerator is considerably more responsive than the same version of Word running on the machine.

The QEMU accelerator is distributed without cost licensed as proprietary software—which the author is still undecided about its eventual license status, and is looking for some kind of commercial sponsorship of the project). It seems that there are fairly widespread hopes that it will be released at some point under a free software license.

## Installing and Running QEMU

To use QEMU without the accelerator module, all you need to do is to install the package on the SUSE media.

If you want to try a version that is newer than the one currently offered by SUSE, you can download a binary distribution from the QEMU web site, which can be installed simply by copying it to the root directory and unpacking it:

```
cp qemu-0.7.1-i386.tar.gz /
cd /
t xzf qemu-0.7.1-tar.gz
```
