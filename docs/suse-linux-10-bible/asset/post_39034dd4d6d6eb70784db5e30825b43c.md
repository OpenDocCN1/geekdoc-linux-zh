If you do not have free space to install SUSE Linux and YaST cannot auto-matically resize your existing operating system partition(s), you have the following alternatives:

- Add another disk to your system and install SUSE there.
- Reuse an existing Windows partition after manually moving the data from that partition into another partition. To move data from one Windows partition to another, you must boot Windows and drag and drop folders from one to another. For example, you can consolidate the data from any Windows partition other than C: drive to the C: drive. You cannot use this method to move the contents of your Windows boot to another partition and reliably expect your system to be bootable because you must also hide files that cannot be selected for drag and drop. Also, applications that were directly installed on the Windows partition that you are clearing out no longer function correctly because of internal references to its drive.
- Abort the SUSE install process, remove the installation media, and reboot into your operating system. You must then have free disk space and clean up the organization of your operating system partition(s) using a utility such as Windows' Defragmenter. If there is sufficient unused space on your Windows partition after this cleanup, you should be able to restart the SUSE installation process and let YaST select appropriate partitioning and resizing for you.

These are really your only options for installing Linux on an Windows system where sufficient space to install Linux is not available or cannot be reclaimed from your Windows partitions by the SUSE install process.

## Manually Partitioning an Existing Windows System

If the SUSE installer cannot reprint an existing Windows partition automatically, you can use the Linux parted (Partition Editor) utility to manually resize an existing partition, usually when your entire disk is occupied by a Windows partition. The parted utility is available from the SUSE install when you select the Rescue System from the main menu of the SUSE install CD or DVD. The SUSE Rescue System* later in this chapter—this section focuses on repartitioning after you have booted in this phase.

> Caution Using software such as parted that directly manipulates partitions, you should make sure that you have a full backup of any critical data on the partition that you are resizing, and that the backup is readable. The parted utility is quite stable, but problems do occur, and we can't think of anything more depressing than finding that you cannot use a backup that you were depending on in order to restore critical data that may have taken you years to amass.

After you have identified the Windows partition that you want to resize, you can use the `resize` command's `resize` command to resize the partition. The `resize` command takes three arguments:

- The minor number of the partition that you want to resize
- The starting position of the filesystem in megabytes
- The end of the resized filesystem in megabytes

The end of the resized filesystem in megabytes must be larger than the current size of the partition. For example, to resize a Windows partition, you would enter a command such as:

```
parted resize 1 2048 10000
```

When this completes, use the `print` command to verify that the partition has been resized.

## Sharing Data on Windows and Linux

The previous sections explained how to mount Windows partitions under Linux. This section discusses how to share data between the two systems. If you have a dual-boot system, you may need to access the Linux partition from Windows or vice versa.

## Accessing Windows Partitions from Linux

Linux has provided support for FAT and FAT32 (another name for VFAT filesystem) for some time. Support for NTFS filesystems in the 2.4.x series of Linux kernels has been integrated into the 2.6 series (such as on SUSE).

To mount a Windows partition under Linux, use the mount command discussed in Chapter 3. The directory /mnt/c is a sample command to mount a VFAT partition (which must be created before attempting to mount):

```
mount -t vfat /dev/hd1 /mnt/c
```

If you are mounting an NTFS partition and do not need to write to it, you can use a command such as the following to mount it in read-only mode:

```
mount -t ntfs -o ro /dev/hd1 /mnt/c
```

## Accessing Linux Partitions from Windows

Accessing Linux partitions from Windows is trickier than the reverse because Windows does not provide built-in support for any of the partitions used by Linux. However, a number of utilities and drivers are available for Windows that enable you to mount and access EXT2 or EXT3 filesystems under Windows. These range from commercial products to public domain and open source utilities:

- **Explore2fs** (http://uranus.it.swin.edu.au/-jn/linux/explore2fs.htm) — EXT2 filesystem access from Windows 9X, 2000, XP, and ME.
- **EXT2 IFS** (http://uranus.it.swin.edu.au/-jn/linux/ext2ifs.htm) — Install filesystem driver for EXT2 under Windows NT, 2000, and XP.
- **Ext2fsnt** (http://ashedled.chat.ru/ext2fsnt/) — EXT2 access to Windows NT. This driving code has been incorporated in Paragon Software's Mount Utility.
- **FSDEXT2** (http://www.ipton.domain.co.uk/content.html#FSDEXT2) — Mounts EXT2 partitions on Windows 95, although read-only. (No longer under active development, then neither is Windows 9.5.)
