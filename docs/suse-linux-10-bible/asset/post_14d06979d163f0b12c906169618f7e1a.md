An issue with the Basic authentication is that the username and password must be verified every time a request is made for a resource from the server, be it an HTML page, an image, or any other resource from the protected directory. This can slow down a little in regards to the responsiveness of the web server. In fact, the amount that the web server slows down is proportional to the size of the password file. Remember the Apache server has to open that file and go down the list in order of users until it gets to the user, every time a page is loaded.

A consequence of this is that there is a practical limit to how many users can be listed in one page. While the limit will vary depending on the configuration of a particular server, changes are after a few hundred entries the performance of the web server suffer and a different authentication method may be needed.

Such a method can be found using the mod_auth_dbm module. mod_auth_dbm provides the use of files used with the dbmange program. Another possible option is mod_auth_mysql. The mod_auth_mysql allows the Apache server to connect to a backend MySQL database where username and passwords can be stored and accessed with greater efficiency.

# The Common Gateway Interface

The Common Gateway Interface (CGI) defines a way in which a web server can interact with external programs, referred to as CGI programs or CGI scripts, for generation of dynamic content based on a client request. To configure the Apache server to interact with a CGI program the first task is to let the web server know where the CGI programs reside.

One method is with the ScriptAlias directive, which tells Apache that a particular directory has been set aside for CGI programs. Apache will attempt to execute every file in a given directory as a CGI program. Thus the web server will execute a program when a client requests a particular resource. The ScriptAlias directive is much like the Alias directive, which defines a URLspace that is mapped to a particular directory on the filesystem. Consider the following example:

# Chapter 16 Setting Up a Web Site with the Apache Server 457

ScriptAlias /cgi-bin/ /srv/www/cgi-bin/

For the given example, the directive marks the target directory, /srv/www/cgi-bin, containing CGI scripts that will be processed by the Apache mod_cgi module 'cgi-script handler. Moreover, the mapping by this directive would result in any request for resources at http://ourservicever/cgi-bin/ causing the server to run a script in /srv/www/cgi-bin/.

However, CGI programs can be invoked from arbitrary directories. For CGI programs to reside anywhere in the directory of a site, two configuration steps need to be completed. First, the cgi-script handler must be activated using the AddHandler directive. Second, ExecCGI must be specified in the Options directive for any directory or subdirectories that may contain a CGI program.

```
<Directory /srv/www/htdocs/dir
Options +ExecCGI
</Directory>
```

The AddHandler directive serves to treat all files with the .cgi file extension as CGI programs. In addition the <Directory> container with the Options +ExecCGI directive tells Apache to permit execution of CGI programs that reside in the /srv/www/htdocs/dir or any subdirectories therein.

# Creating Dynamic Content with PHP

The Apache server is a modular server. The most popular module for use it is mod_php. PHP is short for what is officially called Hypertext Preprocessor was created by Rasmus Lerdorf, a developer who in 1994 was looking for a tool to keep track of who was looking at his resume. PHP is a robust open-source development language that provides the tools and flexibility to accomplish any task.

A server-side technology means that the client viewing the page has no special application, because it is the web server, with PHP installed, that takes the extra step of processing any code within the requested document before sending it to the user. From this extra step PHP can then perform any operation such as accessing a database. This enables a web developer to dynamically construct a web page based on data gathered from a third source and communicate through any means provided by the Internet.

How is this different from a CGI script written in Perl? First unlike a CGI script—which will run as a separate process, invoking an interpreter to run the script and piping the output to stdout for the web server—PHP runs an interpreter within the Apache server processes to run at a moment's notice. However, the real benefit can be seen in what users can do with little or knowledge of the inner workings of the CGI and, for example, a backend with which the script may be communicating.

> The Perl scripting language can also be embedded in the Apache web server using mod_perl. With mod_perl and some modification to existing CGI scripts in Perl you can see the same runtime advantages as scripts written with PHP.

To include the basic functionality of PHP in the core server, extending the LoadModule directive. Apache will also need to know what files to parse using the PHP module. This is done using the AddType directive. After you restart the Apache daemon, all will be set.

```
LoadModule php4_module libexec/libphp4.so
AdType application/x-httpd-php .php own```
