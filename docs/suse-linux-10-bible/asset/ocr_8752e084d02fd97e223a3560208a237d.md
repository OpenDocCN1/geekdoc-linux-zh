When you are running a DNS server in a network where you control the IP address allocation (for example, using non-routable-addresses), a reverse zone is possible.

We will be taking the following zone as the internal forward representation (see Listing 21-4) and work back from that.

# Listing 21-4: Internal DNS Representation

```
intpalcmoder.net. IN ns.intpalcmoder.net. admin.intpalcmoder.net. ( 
200407111
10800
3600
604800
38400 )
NS zen
MX 10 mail
nmail A 192.168.0.2
files A 192.168.0.5
inranet A 192.168.0.10
```

In this definition, we have used the default zone values as before, with the addition of a nameserver entry of zen.palcmoder.net and a mail exchanger entry of mail.palcmoder.net. We have also defined address entries for mail. palcmoder.net of 192.168.0.2,files.palcmoder.net with an address of 192.168.0.5, and intranet.palcmoder.net with an address of 192.168.0.10.

Now that we have the internal network configuration, we can create the reverse zone to allow our internal IP addresses to be resolved into their respective host names (see Listing 21-5).

# Listing 21-5: Reverse Zone for 192.168.0.24

```
@ IN ns.intpalcmoder.net. admin.intpalcmoder.net. ( 
200407111
10800
3600
604800
38400 )
NS ns.intpalcmoder.net.
mail.intpalcmoder.net.
2 PTR mail.intpalcmoder.net.
5 PTR files.intpalcmoder.net.
10 PTR intranet.intpalcmoder.net.
```
