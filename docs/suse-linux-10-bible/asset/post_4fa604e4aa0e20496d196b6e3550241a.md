
## Chapter 2 ♦ Linux Fundamentals

Permission to write to a file includes the right to overwrite or delete it.

So for example:

```
ls -l screenshot1.png
-rw-r--r-- 1 root users 432686 2004-05-17 20:33 screenshot1.png
```

This file can be read and written by its owner (roger), can be read by members of the group users, and can be read by others.

```
ls -l /home/roger/afile
-r--r--r-- 1 users 0 2004-05-17 21:07 afile
```

This file is not executable and writable, and can be read only by owner (roger). Even roger would have to change the permissions on this file to be able to write it.

```
ls -l /etc/passwd
-rw-r--r-- 1 root 1598 2004-05-17 19:36 /etc/passwd
```

This is the shadow file—it is owned by root (and the group to which root belongs), is readable by anyone, but is group writable by root.

```
ls -l /etc/shadow
-rw-r--r-- 1 root 796 2004-05-17 19:36 /etc/shadow
```

This is the shadow file, which holds the encrypted passwords for users. It can be read by root and the system group shadow and can be written by root.

```
ls -l /usr/sbin/traceroute
-rwxr-xr-x 1 root 14228 2004-04-06 02:27 /usr/sbin/traceroute
```

This is an executable file that can be executed by anyone, but written by root.

```
ls -ld /home
drwxr-xr-x 6 root root 4096 2004-05-17 19:36 /home
```

This is a directory (note the use of the -d flag to the command and the d in the first position in the permissions). It can be read and written by the root user, and read and executed by everyone. When used in directory permissions, the x (executable) translates into the ability to search or examine the directory—you cannot execute a directory.

```
ls -ld /root
drwxr------- 18 root root 584 2004-05-14 08:29 /root
```

In the preceding code, /root is the root user's home directory. No user apart from root can access it in any way.

```
ls -l /bin/mount
-rwxr-xr-x 1 root root 87296 2004-04-06 14:17 /bin/mount
```

This is a more interesting example: notice the s where until now we only saw an x. This indicates that the file runs with the permissions of its owner (root) even when it is executed by another user: such a file is known as being root (setuid execution). There are a small number of executables on the system that need to have these permissions. This number is kept as small as possible because there is a potential for security problems if ever a way be found to make such a file perform a task other than what it was written for.

```
ls -l alink
-rwxrxr-x 1 root users 8 2004-05-17 22:19 alink -> file.bz2
```

Note the first position: This is a symbolic link to file.bz2 in the same directory.

## Numerical Permissions

On occasions when permissions are discussed, you will see them described in a three-digit numerical form (sometimes more digits for exceptional cases), such as 644. If a file has permissions 644, it has read and write permissions for the owner and read permissions for the group and others. This works because Linux actually stores file permissions as sequences of octal numbers. It is easiest to see by example:

```
42412421
-rw-r--r-- 644
-rwxr-xr-x 755
-r--r--r-- 444
-r------ 300
```

So for each owner, group, and others, a read permission is represented by 4 (the high bit of a 3-bit octal value), a write permission is represented by 2 (the middle bit of a 3-bit octal value), and an execution permission is represented by 1 (the low bit of a 3-bit octal value).

## Changing Ownership and Permissions

You can change the ownership of a file with the command chown. If you are logged in as root, you can issue a command like this:

```
chown harpo:users file.txt
```

This changes the ownership of the file file.txt to the user harpo and the group users.

To change the ownership of a directory and everything in it, you can use the command with the -R (recursive) option, like this:

```
chown -R harpo:users /home/some_directory/
```

The chmod command is used to change file permissions. You can use chmod both the numerical and rwx notation we discussed earlier in the chapter. Again, this is easiest to follow by looking at a few examples:

- chmod u+x file — Adds permissions for the owner of the file
- chmod g+r file — Adds read for the group
- chmod o-r file — Removes permission for others
- chmod a+w file — Adds write for all
- chmod 644 file — Changes the permissions to 644 (owner can read and write; group and others can only read)
- chmod 755 file — Changes the permissions to 755 (owner can read and execute; group and others can only read)

If you use chmod with rwx notation, u means the user, g means the group, o others, and a means all. In addition, + means add permissions, - removes permissions, while r, w, and x still read, write, and execute, respectively. When setting permissions, you can see the translation between the two notations by executing the chmod command with the -v (verbose) option.

```
chmod -v 755 file
mode of 'file' changed to 755 (rwxr-xr-x)

chmod -v 600 file
mode of 'file' changed to 600 (-rw-------)
```

## Using umask

When a user creates a file, it is created with certain permissions. What controls the permissions with which a new file gets created is something called umask. By default on a SUSE system, a normal user's umask is 022, which means that the permissions for a new file will be 666, while the permissions for a new directory will be 777. SUSE's defaults are relatively generous and open—the fact that the users are all members of the same group (users) and the default umask of 022 means that files created by one user can be read by another. If you want to change a user's umask, you can change it in the .bashrc file; see the section on user preferences.

You can create an empty file with the touch command:

```
touch newfile
```

If you list the file you will see something like this:

```
ls -l newfile
-rw-r--r-- 1 roger users 2004-05-18 10:00 newfile
```

The file has been created with the permissions 644.

## Configuring User Preferences

Linux stores most user preferences in so-called "dot files" in the user's home directory. If a filename starts with a dot, it will not be displayed by the ls command unless you use the -a option and is therefore regarded as "hidden". Both files and dot directories are used to hold preferences for most of the programs you use. Many programs write a dot file in your home directory when you run them for the first time.

Many of these dot files have names that include the letters rc—this comes from the initial letters of run command and is an old Unix legacy. The same letters rc will be seen in KDE commands for starting and stopping services. In particular, the KDE desktop uses a directory .kde in a user's home directory to store preferences for all KDE programs and your desktop settings. This directory contains multiple subdirectories and preferences for all KDE applications.

The behavior of bash shell is determined by the user's file .bashrc. Exactly how bash preferences are set is complicated; as mentioned, the system-wide files /etc/profile and /etc/profile.local are also read, and the user's file .profile is read at login.

You can modify various aspects of how bash behaves by editing .bashrc. In particular, you could simply change your umask by adding a line at the end of .bashrc like this:

```
umask 077
```

If you were then to log in and create a file, you would find that it has permissions -rw------- or 600, so it would not be readable or writable by any other user apart from root. Similarly, if you created a directory, it would have the permissions drwx------, so that it could not be explored by any other user.

The file .bashrc can also be used to control the appearance of the prompt and set environment variables.

The user's file .xrc (if it exists) controls the behavior of the X Window system when it is started by the user. In particular, the window manager could be used with specified lines in .xrc near the end of the file like this:

```
WINDOWMANAGER=/usr/X11/bin/twm
$MANAGER
```

You probably don't want to make exactly that, but it serves to illustrate what is possible. You might also want to include a command to start xterm, which is a command-line terminal application that runs within the X Window system, immediately before starting the window manager:

```
WINDOWMANAGER=/usr/X11/bin/twm
xterm &
$MANAGER
```

It can sometimes be useful to remember that if you are having difficulties with the behavior of programs as a user, removing (or better, hiding) the relevant dot file may help you diagnose the problem. For example, you could do this:

```
mv .emacs .emacs.trouble
```

The next time you start emacs, it will start without a preferences file so you can look through your one to solve the problem.

## Mounting and Unmounting Filesystems

Mounting a filesystem is what you need to do to make its files available, and the mount command is what you use to do that. In Linux, everything is part of one big tree of files and directories. Those that are physically partitions, disks, or remote machines are "grafted" onto the system at a particular place — a mount point, which is usually an empty directory.

To find out what is currently mounted, simply type the command mount on its own.

We discuss the mount command further in Chapters 14 and 22.
