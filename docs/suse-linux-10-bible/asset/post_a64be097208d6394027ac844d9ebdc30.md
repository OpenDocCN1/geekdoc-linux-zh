
## Chapter 3: Partitions, Filesystems, and Files

### Creating Filesystems

The utilities used to create EXT2 and EXT3 filesystems (mkfs.ext2 and mkfs.ext3) are actually hard links to the mke2fs utility (as is the mkfs.ext3 utility discussed in the next section). mke2fs utility was written long ago, before the filesystem-type naming convention was developed. mke2fs utility takes different options and behaves differently upon invoked in the command line.

### Creating an EXT2 Filesystem

The version of mkfs for each type of filesystem provides some options that are specific to that type of filesystem. One of the most interesting options for the mkfs.ext2 command is the -T option, which enables you to invoke predetermined filesystem definitions that are designed to optimize the filesystem for a specific usage pattern. The mkfs.ext2 man page lists the following -T options:

- news per filesystem block. In this case, each inode would have a 4K block allocated for data. If you have a large amount of small files on your system (less than 4K), this will provide one inode per filesystem block.
- largefile One 1MB of data allocation. This would be used where most of your files are about 1MB in size. This makes the dispersal of data across the filesystem less granular but optimizes the amount of inodes needed.
- largefile4 One 4MB of data allocation. If your filesystem will primarily store huge files, this will optimize the amount of inodes needed on your system for larger files.

If you are using this filesystem for general purposes, such as for the operating system itself, it is a bad idea to use these options because they are not designed for general purpose environments. Linux system partitions as the root filesystem contain a diverse mixture of small and large files. Under- or over-allocating inodes can prove either disastrous or overzealous for general-purpose use.

The next few sections show how to create different types of journaling filesystems and provide some guidance on mounting and using these types of filesystems.

The following list shows the filesystem-specific versions of mkfs that are found on a standard SUSE system:

```
# ls /sbin/mkfs

```

The choice of filesystems provided by Linux is quite large, and depending on your needs, you can choose one that is reliable to read and write to. SUSE Linux is usually good at finding a machine that can boot both Linux and Windows. If you want to monitor the performance of your storage devices, the access times and data integrity are significant factors, with both ReiserFS, JFS, and XFS all excellent filesystems to consider. For users, getting the most out of your storage is a primary concern, in which case ReiserFS is a good choice. If you want to migrate EXT2 filesystems or are simply concerned about having the best possible set of diagnostic tools, the EXT3 is probably your best choice.
