
Linux is now ready for the enterprise, it has been for the past 18 months, and it can only get stronger with vendors pushing the acceptance with knowledge transfer and tools that the enterprise is used to having.

## Linux Enterprise Hardware: The Big Players

We have already alluded to the fact that many of the big technology players are involved with Linux and bringing Linux into the enterprise. This section somehow covers the major companies and technologies that have placed Linux so firmly in the enterprise space.

We have always been fans of ridiculously expensive hardware that runs Linux, and we think that is for most uber-geeks (although we would never admit to being them!). The de facto hardware in the industry has to be Intel-based servers, and the lower-end to mid-range workhorses.

Categorizing hardware in this is very common when talking about the enterprise:

- The lower-end servers usually constitute file/print servers, mail servers, and infrastructure servers in the SMB (Small/Medium Business) market.
- Mid-range servers are usually the Unix-based servers—AIX, HPUX, and Solaris machines—and this is where Linux is gaining its ground at the moment. IBM and HP are well aware of this and have made sure Linux is a selection of their mid-range servers. Sun Microsystems is still firmly gripping onto this market with Solaris and is unlikely to have invested so much in the pursuit of this market.
- The high-end market is the massively parallel single-footprint servers—for example, the SGI Altix, IBM’s powerhouse, the System/390 (zSeries).

## IBM

Two of IBM’s platforms, the pSeries and zSeries, have proved to be amazingly good at running Linux, IBM has invested a lot into code development for Linux to take advantage of the mid- and high-end hardware architectures.

## The zSeries

IBM’s zSeries machines hold a special place in one of the authors’ hearts as they started working on these machines when SUSE started its development lifecycle of Linux for the hardware.

The IBM zSeries has a long history within IBM and recently celebrated its 40-year history in the organization. The zSeries does not contain terabytes of memory, does not have the fastest processors in the world, and is not considered a supercomputer, but it is one of the most exciting things that has happened to Linux in recent years. The zSeries is extremely good at shifting data around in its system and moving data from disk, and it is very, very good at managing resources.

The zSeries has proved so popular with Linux users because you can potentially have 40,000 Linux systems running in one all relatively well. What most people have a few servers and there fail to recognize the utilization of their servers. The traditional utilization of a server is 15 to 20 percent. This means that 80 percent of the cost of your server is not being returned to the company.

With the zSeries, you can run all of your Linux servers in one manageable machine and ensure your workloads are at 99 percent hardware utilization. It manages this through partitioning of the system resources into a virtual machine Linux to run on.

You can do this in a couple of ways:

- Using IBM's LPAR (Logical Partition) you can split the server into a number of partitions to run Linux under. This is good when dealing with a small number of virtual machines.
- These logical partitions can run z/OS (zSeries operating system), MVS (Multiple Virtual System), or VM (Virtual Machine). The operating system is extremely powerful and allows many systems to run under the zSeries.

Using VM's resource management, you can dynamically allocate CPU power to a Linux image when the workflow needs it and with this model, you can guarantee that your hardware's cost is actually returning your investment. The zSeries machines should not be considered when you have the need for huge processing because they do not fit well with this profile. If you need powerful processing you should consider the pSeries or other vendors.

## The pSeries

The pSeries machines are considered mid-range in IBM and are ideally suited for intense compute environments (HP). They run Linux both natively and in LPARs (the same as zSeries), and they are extremely fast. With the release of the Power architecture, they have produced a 64-bit processor that has a very efficient core, which of course is able to take the advantage created by IBM has added new features to the kernel and has designed around its use in Linux. Apple licensed this technology for its 64-bit OS, and whether you believe the hype or not, the benchmark results are very impressive.

## Hewlett-Packard

HP is the second big player in the arena and has been very strong in the traditional Unix space. The Superdome servers provide a very scalable hardware platform that can be partitioned to run multiple operating systems across the hardware. The Superdome uses the Itanium processor to be able to run a mixture of Linux, Windows, and HP-UX. The partitioning (up to 16 partitions) allows consolidation of both low and high workloads into one manageable server.

## 64-bit Platforms

It is obvious in the datacenter by the fact that 32-bit architecture will eventually die. This can be backed up by ISVs that work in the enterprise releasing their software for 64-bit platforms. SUSE has been a driving force in the 64-bit space as the hardware vendors have routinely called upon SUSE to implement the port to a new 64-bit architecture. SUSE has managed to control a large portion of the enterprise base because it is considered de facto platform in the area. The datacenter is not bound by the normal laws of the IT industry because it relies on a single application to provide a service. In an office environment, servers usually run a mixture of very specific applications on one server (or at least more than one application on a server).

The 64-bit architectures available at the time of writing are the Itanium, Opteron, Athlon, and the IBM POWER:

- The Itanium had a lot of bad press since its release, mainly because of its inability to run legacy 32-bit applications with any increase in performance from a comparable Xeon processor at the same clock speed. We say this is an unfair point if it weren't for the price of servers with Itanium processors in them. Unless you are running a pure 64-bit environment, it is unlikely you will consider an Itanium.

The AMD Opteron is really a success of the 64-bit story as it is relatively cheap with impressive performance statistics. You can now buy Opteron-based desktop machines for the home, and SUSE has realized this with the inclusion of a 64-bit SUSE distribution included with the boxed product.

Intel offers 64-bit processors with backward compatibility, in response to AMD's Opteron and AMD64 processors. Most Xeon processors are EM64T (Extended Memory) and are compatible with AMD's 64-bit architecture—the 64-bit SUSE versions originally designed for Opteron run perfectly on these systems.

For any user installing the 64-bit version, you will see no difference during installation, or in the system of itself. The main difference is that the kernel, libraries, and applications have been compiled for the 64-bit environment. Faster application pipes, larger memory access, and legacy support for 32-bit applications are in the distribution and work very well. The distribution has been accepted as a great way to take advantage of your shiny new Opteron.

The IBM JS20 is specifically designed for the BladeCenter architecture and is definitely aimed at the consolidation of datacenter services. The SUSE series runs on the base, and Linux was the first officially supported operating system on the architecture. We were lucky enough to borrow a BladeCenter with six JS20 blades for an expo in London recently, running DB2 WebSphere; the demo went very well, and the bundle was stable as a 32-bit distribution on the JS20 (Xeon) blades.

If you need large memory, a massive execution pipe, and a resilient system, the 64-bit systems are ripe for picking. The problem you have is now very similar to picking a Linux distribution (SUSE); you need to choose a specific 64-bit technology.
