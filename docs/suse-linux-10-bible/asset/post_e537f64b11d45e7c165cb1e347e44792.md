
## Backing Up, Restoring, and Archiving Files

After you've done any real work on your SUSE system, to make sure that you've backed it up somewhere in case of hardware failure or accidental deletion of your data. Linux provides a variety of ways to create archive files that contain files and directories. You can then copy these archive files to another machine over your network or write to removable media such as the CD-ROM to protect yourself against calamities. This section introduces some of the most popular commands used to create archive files on a Linux system, either as a standard Linux archive file or as an ISO file that you can subsequently burn to a CD for archival purposes.

## Creating and Reading Simple Archives

We mentioned gzipped archives earlier—if you want to back up the current state of a directory with all file permissions, date stamps, and symbolic links preserving, creating such an archive is the best way to do it. To create a gzipped archive of the directory work, execute a command as the following:

```
tar zcvf work.tgz/
```

The options zcvf mean "compressed, create, verbose, file," respectively. If you copy the archive somewhere else and you want to unpack it:

```
tar xvzf work.tgz
```

where xzvf mean "compressed, extract, verbose, file."

If your aim is simply to back up the directory on a remote machine, you can create the file on your local machine and copy it as explained in the previous section. You could also use ssh and tar to together copy the directory tree, like this:

```
tar cvf - work/ | ssh faraway "cd /home/bible/incoming; tar xvf -"
```

What this does is to create an archive of the directory work on standard output, which is pushed through the pipe () to ssh, which changes directory and unpacks the archive that it is receiving on standard input.

SUSE includes a very nice tool called pax that can create both archives and easily move a directory tree from one place to another, preserving all file attributes. To create an archive of the directory work, you can do this:

```
pax -wf work.p/
```

To unpack this again, do the following:

```
pax -rvf work.p
```

One of the nice features of pax is that it can deal with archives in both the traditional Unix formats tar and cpio. It is also a very convenient tool for copying a directory tree unchanged from one place to another, like this:

```
pax -rvw work /tmp/
```

Another tool for synchronizing directory trees, whether locally or remotely, is rsync. For example:

```
rsync -r localdir faraway:/home/bible/incoming/
```

will will create a directory localdir on the remote machine. One of the advantages of rsync is that it only transfers the parts that have changed since the last sync.

## Creating an ISO Image

An ISO file is a file that contains an image of an optical disc, such as a CD or DVD. ISO files are widely used and can be burned to media. To create an ISO image, you can use:

```
mkisiso -o work.iso
```

To mount the ISO image, use the following:

```
mount work.iso /mnt
```

To unmount the ISO image, use:

```
umount /mnt
```

If you need to burn the ISO to a CD, you can use:

```bash
dd if=work.iso of=/dev/sr0 status=progress
```

Ultimately, the goal is to ensure that your data is safe and accessible. This chapter has introduced various ways to manage your files effectively.

## Partitions, Filesystems, and more

We touched upon partitions during the installation of SUSE, and the configuration of these is relatively easy. The next sections cover:

- Creating partitions
- Selecting and creating filesystems
- Mounting filesystems

Partitions are physical or logical portions of a disk. A filesystem is the arrangement of data on a partition. In many operating systems, such as older DOS/Windows systems, the operating system software behind the manufacturing capabilities of disk drives, partitions were necessary to divide large disks into sections that the system could address. In general, partitions provide both manageability and logical separation of data. Dividing a disk into partitions makes it easier to back up data because backups are generally done on a per-partition basis. Partitioning also limits the potential problems related to partition failures. Even if a partition of your drive becomes unreadable, the other partitions are still accessible.

### Types of Partitions

There are three type of partition definitions, and each provides different functionality for differences:

- **Primary partitions**: These are the standard physical partitions you use if you did not need to segment your disk too much. Linux supports a total of four primary partitions on a disk, which is usually a limitation for people with large disks who would like to have some segmentation in the way they organize their data or critical files.
- **Extended partitions**: This is a special type of primary partition that acts as a container for logical partitions. It allows you to bypass the four-primary partition limit.
- **Logical partitions**: These are partitions that exist within an extended partition. You can have as many logical partitions as you need, providing great flexibility for organizing your data and files.

> You can still access SUSE's graphical partitioning utility after system installation by running the Center Control, resizing the YaST Modules, selecting System, and clicking the Expert mode. This enables you to create partitions in unallocated space. Resize existing partitions, you can use the /usr/sbin/parted (partition editor) utility.
