# Integrating Cyrus and Postfix

So now that you know Cyrus works, you need to set up Postfix to use Cyrus to store the user's mail.

In /etc/postfix/main.cf, you need to set the mailbox_transport to use Cyrus. The service is preconfigured in /etc/postfix/master.cf. This file contains definitions for SMTP services as well as any user-defined services that can be used in parameters such as mailbox_transport. So you edit /etc/postfix/main.cf and change the mailbox_transport as:

```
mailbox_transport = cyrus
```

When /etc/postfix/main.cf is edited, restart Postfix with rcpostfix.

> To make sure Cyrus or any other service (as inetd, or cyrus in this chapter) when you boot the system, use chconfig -a servicename.

Any mail sent to users will be delivered to the mailboxes using the Cyrus service. The Cyrus service calls the Cyrus deliver command to take the mail message and deliver it to the defined user's IMAP mail box for his or her retrieval instead of the local mail pool.

# Setting an Alias for Root's Mail in Cyrus

One thing you need to consider when using Cyrus in this type of environment is that any mail to a user that is not in the Cyrus database will be rejected by Cyrus. This is especially true for the root user. It is not a good idea to store the root mail in Cyrus, but most people configure an alias for root's mail to be delivered to a non-administrative user. Here we configure root's mail to be delivered to the user just:

+   1. Open the file /etc/aliases and add an entry for the root user:
root: justin
This tells Postfix that any mail for root should actually be delivered to the user junction.
2. When /etc/aliases is edited, run the postfix command:
bible:- # postfixias /etc/aliases
3. You need to reload Postfix's databases to commit the new alias.
