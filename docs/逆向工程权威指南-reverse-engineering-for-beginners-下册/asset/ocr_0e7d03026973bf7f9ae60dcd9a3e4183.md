# add rsp, 8

Linux; BSD和Mac OS系统中的应用程序，会优先使用RDI,
RSI; RDX; RCX; R8; R9这6个寄存器传递函数所需的6个参数，然后
使用数据传递剩余的参数。[6]

因此，64位的GCC编译器使用EDI寄存器（寄存器的32位）存储
字符串。EDI不是EDI寄存器中地址较低的32位地址部分。为什么
GCC不使用整个EDI寄存器？

需要注意的是，64位汇编在写入R-寄存器时的低32位地址写入
时候，对EDI-寄存器进行操作的时候，会同时清除R-寄存器中的
高32位地址[7]。以“MOV RAX,01123344”能够对RAX寄存器
进行赋值操作，因为该指令会将（零）高位的内容。

如果打开GCC生成的obj文件，我们就能看到全部的内容。[8]

# 指令编译器3.9 GCC 4.4.66

```
.text:000000000000040D   main proc near
.text:000000000000040D 48 83 EC 08   sub rsp, 8
.text:000000000000040D 48 FE 08 05 40 00   mov edi, offset
format ;,"hello,\n\"
.text:000000000000040D 39 D8 C6 0xor eax, eax
.text:000000000000040DB E8 82 FE FF FF   call _printf
.text:000000000000040E 31 C0               xor eax, eax
.text:000000000000040E 48 83 C43 08   add rsp, 8
.text:000000000000040E C3                   retn
.text:000000000000040E                 main endp
```

在地址0x4004d处，程序对EDI进行了写入操作，这部分代码的
opcode使用了5个字节；相比之下，对于RDI进行写入操作的opcode会占
7个字节。显然，由于空间方面的考虑，GCC进行了相应的优化
理。此外，对于32位地址（指针）能够描述的地址不会超过4GB，我们
可以据此判断这个程序的数据地址不会超过4GB。

在调用printf之前，程序清空了EAX寄存器，这是x86-64架构的
系统规范决定的。在系统与应用程序接口的规范中，EAX寄存器用来表
用用的的量寄存器(vector registers).[9]
