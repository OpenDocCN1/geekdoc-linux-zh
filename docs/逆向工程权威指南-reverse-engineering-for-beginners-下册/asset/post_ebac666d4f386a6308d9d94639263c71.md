第一个MOV指令字符串“Hello World!”的偏移量，0x1686赋值到R0寄存器。

“MOV R0, #0”将写入R0寄存器的高16位。在ARM模式里，常规的MOV指令可以操作字符串的低16位，而单条ARM指令最多32位字。当然，寄存器之间的数据传递没有这种限制。所以对寄存器的高位（第16位到第31位）进行赋值操作的MOV指令应运行而。然而此处的MOV指令可有不可，因为在执行一条指令“MOV R0, 0x1686”时，R0寄存器的高16位就会被清零。这或许就是编译器智能化的缺陷。

“ADD R0, PC”将PC和R0进行加法，计算出字符串的绝对地址。之前介绍了“位置无关”，我们知道程序运行之后的起始地址并不固定。程序对这个地址进行执行了必要的修正。

然后，通过BL指令调用puts()函数，而没有前文那样调用printf()函数。这种差异来自于GCC编译器[20]，编译器将第一个printf()函数替换为puts()函数（两个函数的参数完全相同）。

所谓“几乎”就意味着它们在差异实质上，如果printf()函数支持“%”开头的控制，而puts()函数则不支持这类字符串字符控制。如果参数中有这类类控制符，那么两个函数的输出结果还会相同。

为什么GCC编译器会做这种替换？大概是因为这种情况下puts()的效率更高。由于puts()函数不处理控制符（%），只是把每个字符输出到stdout设备，所以puts()函数的运行速度更快[21]。

后面的“MOV R0, #0”将R0寄存器清零。

- Thumb-2模式的16位指令对，其opcode以2-1-4-3的顺序显示。

上述指令的stp（Store Pair）将两个寄存器（如X29, X30）的值存储到堆。虽然这个指令在实质上可以将这两个值存储到内存中的任意地址，由于该指令用了SP，所以它就是这种方式存储这两个。ARM64平台的寄存器都是64位的，每个寄存器可以存储8字节。此程序需要分配16字节来存储寄存器的值。该指令带有感叹号，意味着其标注的数值会被执行。即该指令先将SP减去16，在此之后将两个寄存器的写入里。这属于“预索引/pre-index”指令。此外还有“延迟索引/post-index”指令。有关两者的区别，请参见本书28。

以更易懂的x86指令来解读，这条指令相当于PUSH X29和PUSH X30。在ARM64平台上，X29寄存器是帧指针FP，X30起LR的作用，所以这两个寄存器在函数的序言和尾处理出现。第二指令将SP的复制给X，即FP。这用来设置栈帧。

ADRP和ADD指令相互配合，把“Hello!”字符串的指针传递给X0寄存器，而当函数参数传递时被调用。受到指令方面的限制，ARM无法通过单条指令把一个较大的数值放入寄存器（可以看本书28.31节）。所以，编译器要组合多个立即数来实现立即赋值。第一条ADRP获取页面地址传递X0，然后用第二条ADD进行加法运算给出最终的指针地址。详细解释请参见本书28.4节。

```
0x400000 + 0x648 = 0x400648。这个数位于rodata数据中的Hello!”的地址。
```
