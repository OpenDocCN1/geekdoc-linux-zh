一个双字数0x1122334。只要不进行优化编译，编译器就会按照变量声明的顺序来分配存储空间。因此，我们可以在编译后的可执行文件中验证这个存储关系：双字数random_value正好排列在array[]数组之前。

运行这个刚编译出来的可执行文件，可以看到程序运行的结果:

```
first element 0
second element 1
last element 9
array[-1]=11, array[-2]=22, array[-3]=33, array[-4]=44
```

注意x86平台的小端序现象。

在调试工具OllDB的窗口里，我们可以看到内存数据的布局如下:

| CPU Stack | Value |
| --- | --- |
| 001DFBC | /001DFBD3 ; fakearray pointer |
| 001DFBD0 | |11223344 ; random_value |
| 001DFBD4 | /03020100 ; 4 bytes of array[] |
| 001DFBD8 | /07060504 ; 4 bytes of array[] |
| 001DFBC | /00CB90B8 ; random garbage + 2 last bytes of array |
| 001DFBE0 | /0000000A ; last i value last bytes after loop is finished |
| 001DFBE4 | /001DFCC2 ; saved EBP value |
| 001DFBC | /00CB129D ; Return Address |

现在，内存地址与数值的对应关系是:

+   - 数组[]的地址是0x001dfbd4，它数组[]的地址0x001dfbd4落后增加了一个字节（数组是反向增长的存储结构）。

虽然这确实是某种意义上的hack，但是确实不靠谱（编译结果可能和预期差差异）。因此，本书不建议在生产环境下使用这种代码。即使如此，本例仍然不失为典型的演示程序。
