# 11.1 无用代码 Dead Code

在编译术语中，程序中第二次调用printf()函数的代码统称为“无用代码/dead code”。无用代码永远不会被执行。所以，在启用编译器的优化选项后，编译器会将这种无用代码删除得干净净。

# 第12章 条件转移指令

## 12.1 数值比较

本章围绕以下程序进行演示：

```c
#include <stdio.h>

void f_signed (int a, int b)
{
    if (a>b)
        printf("a>b\n");
    if (a==b)
        printf("a==b\n");
    if (a<b)
        printf("a<b\n");
}

void f_unsigned (unsigned int a, unsigned int b)
{
    if (a>b)
        printf("a>b\n");
    if (a==b)
        printf("a==b\n");
    if (a<b)
        printf("a<b\n");
}

int main()
{
    f_signed(1, 2);
    f_unsigned(1, 2);
    return 0;
}
```

### 12.1.1 x86

在关闭优化选项时，使用MSVC编译上源程序，可得到f_signed()函数。

指令清单12.1 Non-optimizing MSVC 2010

```
a$ = 8
b$ = 12
f_signed PROC
	push ebp
mov ebp, esp
mov eax, DWORD PTR_a$[ebp]
cmp eax, DWORD PTR_b$[ebp]
jle SHORT LN30f_signed
	push OFFSET SIG737
call _printf
	add esp, 4

LN30f_signed:
mov ecx, DWORD PTR_a$[ebp]
cmp ecx, DWORD PTR_b$[ebp]
jne SHORT LN20f_signed
	push OFFSET SIG739
call _printf
	add esp, 4
LN20f_signed:
mov edx, DWORD PTR_a$[ebp]
cmp edx, DWORD PTR_b$[ebp]
jge SHORT LN40f_signed
	push OFFSET SIG741
call _printf
	add esp, 4
LN40f_signed:
ret 0
f END
```

第一个条件跳转指令是JLE，“Jump if Less or Equal”。如果上一条CMP指令的操作第一个表达式小于（不大于）第二个表达式，JLE将跳转到指令标识的地址；如果不满足条件，则运行一条指令，例如程序将会调用printf()函数。第二个条件跳转指令是JNE，“Jump if Not Equal”。如果CMP的两个操作数不等，则进行跳转。

第三个条件跳转指令是JGE，“Jump if Greater or Equal”。CMP的第一个表达式大于或等于第二个表达式（不小于），则跳转。这段程序，如果三个跳转条件都不满足，将不会调用printf()函数；除非特殊情况，这种情况不会发生。

在我们观察f_unsigned() 函数的汇编。f_unsigned()函数和f_signed()函数相同。它们的区别体现在条件跳转上：f_unsigned()函数使用的条件跳转是JBE和JAE，而f_signed()函数使用的条件跳转则是JLE和GE。使用GCC编译上述程序，可以得到f_unsigned()的汇编：

# 指令12.2 GCC


GCC编译的结果和MSVC编译的结果相同。GCC编译后，f_unsigned()函数使用的条件跳转是JBE（Jump if Below or Equal，相当于JLE）和JAE（Jump if Above or Equal，相当于JGE）。JA/JAE/JBE/JG/JL的区别在于它们检查的标志位：前者检查进位位CF（意味着无符号）和零标志位ZF（意味着零），后者检查符号位SF（意味着异号）和零标志位ZF。从指令的角度看，前者适用于无符号类型数据的运算，而后适用于有符号类型数据的运算。
