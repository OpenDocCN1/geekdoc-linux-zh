ADRP和ADD指令相互配合，把“Hello!”字符串的指针传递给X0寄存器，而当函数参数传递时被调用函数。受到指令方面的限制，ARM无法通过单条指令把一个较大的立即数值放入寄存器（可以看本书的28.31节）。所以，编译器要组合多个立即数指令来实现立即赋值。第一条ADRP获取页面的地址传递X0，然后用第二条ADD进行加法运算并给出最终的指针地址。详细解释请参见本书28.4节。

```
0x400000 + 0x648 = 0x400648。这个数位于rodata数据中的“Hello!”的地址。
```

接下来，程序使用BL指令调用puts( )函数。这部分内容的解读可以参见3.4.3节。

MOV指令传递给X0寄存器清零。WO是X0寄存器的低32位，如下所示。

| 高32位 | 低32位 |
|---|---|
| | WO |

main()函数通过X0寄存器传递函数返回值0。程序后续的指令依据准备这个返回值。为什么这里要把返回值存储到X0寄存器的低32位，即WO0寄存器？这种情况和x86-64平台相似：出于兼容性和向下兼容的考虑，ARM64平台的int型数据仍然是32位数据。对于32位的int型数据来说，X0寄存器的低32位足够了。

为了演示，我对源代码进行了小幅度的修改，使main()返回64位值。

指令样例3.16 main()返回uint64_t 类型数据

```
#include <stdio.h>
#include <stdint.h>

uint64_t main()
{
    printf("Hello!\n");
    return 0;
}
```
