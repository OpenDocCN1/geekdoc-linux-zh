# 68.3 Windows SEH

# 68.3.1 我们暂时把MSVC当作

Windows操作系统中，结构性异常处理机制（Structured Exception Handling, SEH）是用来处理异常情况的响应机制。然而，它是与语言无关的，与C++面向对象的编程语言（Oriented Object Programming, OOP）无任何关联。本节将离C++与MSVC的相关特性，单独讲解SEH的特性。

每一个运行的都有一个SEH链，线程信息块（Thread Information Block, TIB）有SEH的最后一个锚。当出现异常时（比如出现了被除零、地址访问不正确或程序主动用RaiseException()回调函数），此时就会出现异常处理时与CPU有关的状态。操作系统会在信息块TIB中寻找SEH的最后一个锚（包含寄存器的值）。找到SEH锚，此时异常处理函数就会开始检查是否能应对这种异常情况。如果答案是肯定的，那么异常处理函数就会接手。如果异常处理函数无法处理这种情况，就会通知操作程序无法处理，此操作程序就会逐一尝试异常处理链中的其他程序，直到找到能够应对这种异常的异常处理程序为止。

在异常处理链的末尾有一个大大家都接触过的异常处理程序；它显示一个标准的对话框，通知用户进程已崩溃，崩溃时CPU的状态是什么情况，用户是否愿意把这些这些信息发送给微软的开发者。
