# 63.4 内快照”对比

这种内存“快照”的对比技术可以凸出内存中化的数据，过去就常见于8游戏的作弊领域。

如果你在您的8位游戏程序（这些机器通常不大，而游戏本身占据的内存很少）启动一个游戏，你就可以看到部分游戏帧镜像。现在有100个弹子。这时就可以将所有的内存空间做一个镜像。把镜像作为文件保存后，你可以先开枪，这时弹子的剩余数量就会显示为99。这时，你再对整个内存空间另做一个镜像。我们对这两个内存空间镜像进行对比，肯定某些数值的从100下降到99。

考虑到这些8位游戏程序都是汇编语言编写，而且变量都是全局变量。由于基于以上的对比结果，我们可以分析出内存地址存放着游戏的数量。对于这个有关的突破，我们就可以在游戏的汇编代码（需要引入反汇编指令）。在搜索时引入了这些指令，就不会发现弹子总数减少的异常的操作指令。然后，我们将游戏修改指令POKE，保证游戏总数不受100影响。

在8位游戏运行的程序逻辑，总是会被加载在固定的地址此处。此外，同游戏的版本的版本比较短（（一旦结束就不会再进行后续升级了）。由于这些玩家们知道如何修改地址就能“黑掉”这些游戏了。他们通常使用BASIC语言的单词指针指令POKE直接向地址地址写入游戏字节。甚至在一些杂志中，通常会出现一个关于地址的POKE指令列表。

与此类似，修改游戏排行榜排序比较容易，而且它不仅适用于8位游戏。首先，记录下自己的游戏得分并将存档备份出来。每当排行的总分发生变化时，再备份一次数据。接下来，我们可以使用系统自带的DOS进制文件比较工具FC对比两个文件（存档文件是二进制文件）。两个文件肯定有几个字节发生了变化，直接修改这些值就可以调整游戏得分。然而，在游戏开发团队通过非常清楚这些伎俩，因此可能会发生程序来对应这些措施。
