## 25.2 SIMD实现strlen()

根据msdn(http://msdn.microsoft.com/en-us/library/y0dh78(VS.80)).aspx)，在C/C++程序中插入特定的宏即可调用SIMD指令。在MSVC编译器的库文件之中，intrins.h文件就使用了这种宏。

我们可以把字符串分段处理，使用SIMD指令实现strlen()函数。这种算法比常规实现法快2~2.5倍。它每次把16个字符加载到1个XMM寄存器里，然后检测标记位为零的结束符。

```c
size_t strlen_sse2(const char *str)
{
    register size_t len = 0;
    const char *s=str;
    bool str_is_aligned=((unsigned int)str) & 0xFFFFFFF0 == (unsigned int)str);

    if (str_is_aligned==false)
        return strlen(str);

    m128i xmm0 = _mm_setzero_si128();
    m128i xmm1;
    int mask = 0;

    for (;)
        xmm1 = _mm_load_si128((m128i *)s);
        xmm1 = _mm_cmpeqi_epi8(xmm1, xmm0);
        if ((mask = _mm_movemask_epi8(xmm1)) != 0)
        {
            unsigned long pos;
            BitScanForward(&pos, mask);
            len += (size_t)pos;
            break;
        }
        s += sizeof(_m128i);
    }
    len += sizeof(_m128i);
}
```

程序首先检查str指针是否已经对16字节边界对齐。如果这个地址没有对齐，就用常规的strlen()函数计算字符串长度。

然后通过MOVVDQA指令将16字节数据加载到XMM1寄存器。

但读者似乎会认为：如果不直接使用要求针对16字节边界对齐了，我们可以使用MOVVDQA指令；否则，就使用速度慢的MOVDQU指令。

但是本文在强调：

在Windows NT操作系统中，以及其他操作系统里，内存的最小分页单位是4KB（4096字节）。虽然虚拟独立空间的4KB可以使用，但是实际上部分会受到物理内存和分页方法的限制。如果程序试图访问不存在的内存，将会引发错误。这是虚拟内存的工作方式决定的，详情参见 http://en.wikipedia.org/wiki/Page_(computer_memory)

所以，如果函数一次加载16字节数据，可能会跨虚拟内存的内存边界。例如，操作系统可能在地址为0x00c0000的物理内存处给这个程序分配了8192（0x2000）字节的内存。那么这个程序的内存就在0x00c0000与0x00c01ff之间。

在这个内存在之后，即位于0x008c2000以后的物理内存都不可被程序访问。换言之，操作系统没有给这个程序分配那块内存。如果程序访问这块不可用的内存地址就会引发错误。

我们再研究下一个程序。程序可能在内存的末端5个字符。这种分配方法是合合理的。

```
0x008c1ff8 'h'
0x008c1ff9 'e'
0x008c1ffa 'l'
0x008c1ffb 'l'
0x008c1ffc 'o'
0x008c1ffd '\x00'
```

当采用常规strlen()函数处理这个字符串时，首先把指针指向地址是否16字节对齐，每次读取16字节。“hello”的第一个字节，即地址0x008c1ff8。遇到0x008c1ffd的字节，函数就结束。

假如我们编写strlen()函数考虑字符串地址对齐问题，无论指针地址是否16字节对齐，那么它可能从0x008c1ff8读取到0x008c2000，这将引发错误。显然，应当避免这种错误。只有在字符串地址对齐的情况下，才可以使用SIMD技术。另外，操作系统在内存对齐时也是16字节边界对齐的，我们的函数不会访问非法内存。下面继续介绍我们的函数：

- `_mm_setzero_si128()`：清空XMM寄存器，相当于xor xmm0。
- `_mm_load_si128()`：MOVDQA。它从指定地址加载16字节到XMM寄存器。
- `_mm_cmpeq_epi8()`：PCMPEQB。它以字节为单位，比较两个XMM寄存器的值。如果某个字节相等，该字节返回xff，否则返回0。

举例来说：

| 运行前 | XMM1 |
|---|---|
| 运行前 | 112233445567788000000000 |
| 运行前 | ab34400778111111111111 |
| 运行后 | ff000000f0000000000 |

本例用“xor xmm0,xmm0”将xmm0寄存器清零，然后从16字节进行比较。另一条指令是_mm_movemask_epi8，即PMOVMSK指令。这个指令通常与PCMPEQB配合：

```assembly
pmovmskb eax, xmm1
```

XMM1的第一个字节是1的情况下，设置EAX器的最高位为1。如果XMM1寄存器的值是xff，那么EAX器的最高位还会赋值为1。它XMM1的第二个字节是xff的情况下，设置EAX器的次高位为1。总而言之，这个指令的作用是判断XMM1的每个字节为0。如果n字节是FF，则设置EAX的n位为1，否则EAX的n位为0。另外，不要忘记算法遇到的实际问题：指针指向的字符串可能包含结束符和脏数据。例如：

| 15 | 14 | 13 | 12 | 11 | 10 |
|---|---|---|---|---|---|
| "h" | "e" | "l" | "o" | 0 | 脏数据 |

一次读取16字节到XMM寄存器，并将XMM0里的零进行比较，可能会得到这样的结果（从左到右是LSB到MSB）：

| XMM1 | 0000ff0000000000 |
|---|--- |

0000ff0000000000就是说它找到了零。在这种情况下PMOVMSKB指令将设置EAX为（二进制）：n001000000000000。我们的函数必须以结束符为准，忽略数据里的结束符。下一条BSF（Bit Scan Forward）指令将二进制里的第一个1，将其位清零，并将结果存储到操作符里。在EAX=001000000000000的情况下，执行 `bsf eax, eax`，那么EAX将保留第5位（从开始）。MSVC这里对应的是BitScanForward。代码的其他部分容易理解。如果找到了0，就把它的位置累加到计数器里，从而获取字符串长度。应当注意到MSVC编译器优化了循环的部分。Intel Core i7处理器推出了SSE4.2。它提供了新的指令极大了字符串的处理。感兴趣的读者可以参见：

### 26.1 x86-64

x86-64框架是一种兼容x86指令集的64位微处理器架构。从逆向工程来说，这种框架的主要区别在于：

- 除了位于FPU和SIMD的寄存器之外，几乎所有的寄存器都变为了64位寄存器。所有指令都可以通过R-头的寄存记符（寄存器名称）调用64位寄存器。而且x86-64框架的CPU比x86框架的CPU多8个通用寄存器。这些通用寄存器分别是：RAX、RBX、RCX、RDX、RBP、RSI、RDI、R8、R9、R10、R11、R12、R13、R14、R15。
- 它向下兼容，允许程序使用GPR的32位寄存器的寄存记符、操作该寄存器的低32位数据。例如，程序可以通过寄存记符访问AXAX器的低32位。

| | (字节号) | 6th | 5th | 4th | 3rd | 2nd | 1st | 0th |
|---|---|---|---|---|---|---|---|
| RAX | | | | | | | |
| | | | | | | EAX | |
| | | | | | | AH AL |

64位寄存器特有的R8~R15寄存器仅有相应的（低）32位助记符，即R8D~R15D（32位），而且还有相应的（低）16位标识符R8W~R15W。
