# 本数的第34章详细介绍哈希函数。

就这个程序而言，我们可以据此判断加密狗的“有/无"
信息。这款加密狗上不包含内存存档；换句话说
这个程序不会向加密狗写数据。后连续出现的数字字符就是指令
码，由SSC()函数接收和处理。其他字符串的哈希值是用16进制的
形式存储在加密狗里。因为厂商的加密算法是私有的，所以编
写程序替换它，或者用插件加密的方法并不通行。但是，“截
所有访问加密狗的操作、继而找到加密对的哈希值”确实得得
不麻烦的话，我们还可以模拟程序逻辑、基于私有的加密哈希
函数再重建一个软件，而是使用自制软件替代原软件对数据进行
加密。

代码51/52/53用于选择LPT打印接口。3/4x用于选择相应的
加密狗“系列”。不同类型的Sentinel Pro加密连接在同一个LPT
口上，区分加密狗的工作应当由程序完成。

除了字符串“012345678”以外，传递哈希值的都是双字
字符的字符串。然后，函数返回的哈希值是一系列有效值进行比较。如
若该值有效，全局变量ctl_model将被赋值为0C或0B。

此外，程序还定义了字符串“PRESS KEY TO CONTINUE:”
这应当通过加密狗认证之后的提示信息。不过整个程序没有调用
这个字符串，恐怕属于源程序的bug了。
