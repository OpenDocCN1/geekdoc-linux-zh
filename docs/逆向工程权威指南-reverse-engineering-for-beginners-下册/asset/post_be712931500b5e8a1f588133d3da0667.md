Thumb和Thumb-2程序的opcode长度并不固定。这一特征更接近x86系统。

它的程序代码里有一个专门用于存储case从句信息（default以外）的表。这个表负责记录case从句的数量、偏移量和标签，程序可以进行精确的寻址。程序通过这个单进行跳转，常规处理相应的分支语句。

因为需要转移跳转并进行后续处理，所以这个程序使用了专用函数 ARM_common_switch8_thumb。这个函数的第一指令是“BX PC”，它将运行模式切换到32位的ARM模式，然后在32位下进行跳转。后续函数负责查询和分析跳转表。具体指令非常复杂，本文在这里只是简单介绍一下，暂时不详解。

比较的是，这个程序使用了LR寄存器指向的跳转。在这个函数之后，LR寄存器存储了LL_arm_switch8_thumb的后续指令的地址，就是开始的地址。

这个程序出现了每个switch语句都会复用的专用函数，有明显的结构特征。可能是编译器为了避免生成重复代码而的处理。

IDA自动识别这个函数和对应的跳转表。IDA还能给相应的条目添加合理的注释。例如，IDA就给添加了000000FA这样的注释。

## 13.3 case从对一的情况

多个case触发一系列操作相同并不常见，例如：

#include <stdio.h>

void f (int a)
{
  switch (a)
  {
    case 1:
    case 2:
    case 7:
    case 10:
      printf("1, 2, 7, 10\n");
      break;
    case 3:
    case 4:
    case 5:
    case 6:
      printf("3, 4, 5\n");
      break;
    case 8:
    case 9:
    case 20:
    case 21:
      printf("8, 9, 21\n");
      break;
    case 22:
      printf("22\n");
      break;
    default:
      printf("default\n");
      break;
  }
};

int main ()
{
  f(4);
};

如果编译器直接刻板按照每种可能的逻辑分支逐一分配对应的指令组，那么程序将包含大量的重复指令。一般而言，编译器会通过某种机制来降低代码的冗余。
