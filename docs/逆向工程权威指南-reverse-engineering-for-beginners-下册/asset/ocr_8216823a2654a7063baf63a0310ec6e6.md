然后运行程序。我们的程序里没有printf()的源代码，所以GDB无法显示相应的源代码。但是，这并不影响我们调试程序。

```
(gdb) run
Starting program: /home/dennis/polygon/1
Breakpoint 1, _printf(format=0x80484f0 "a=%d; b=%d; c=%d") at printf.c:29
    printf.c: no such file or directory.
```

继续让GDB显示第10个数据，其中左侧第一列是地址域。

```
(gdb) x/10x esp
0xbfffffc1: 0x804844a4 0x80484f0 0x00000001 0x00000002
0xbfffffc2: 0x00000003 0x80484460 0x00000000 0x00000000
0xbfffffc3: 0x007e2905 0x00000001
```

第一个元素就是返回地址RA(0x804844a4)。为了验证这些，我们让GDB显示出这个地址开始的指令:

```
(gdb) x/5 0x804844a4
0x804844a4: <main+45>: mov    $0,%ax
0x804844af: <main+50>: leave
0x80484450: <main+51>: ret
0x80484451:             xchg   %esp,%ax
0x80484453:             xchg   %esp,%ax
```

ret之后的XCHG指令与NOP指令等。x86平台并没有专用的NOP指令，实际上我们用RISC的CPU的指令集也没有专用的NOP指令。

栈中的第二个数据(0x80484f0)是字符串格式的内存地址（指针：）

```
(gdb) x/s 0x80484f0
0x80484f0: "a=%d; b=%d; c=%d\n"
```

接其后的三个数据，是传递printf()函数的剩余的三个参数。栈中其余的数据，可能是数据，可能是其他函数的数据或局部变量等数据。没有进行深究。

此，我们执行“finish”指令，调试器将执行剩余的指令，直接到函数结束为停止”。在我们的例子里，这条指令将引导GDB执行printf()函数，直到它退出为止。

```
(gdb) finish
Run till exit from #0 _printf(format=0x80484f0 "a=%d; b=%d; c=%d")
at printf.c:29nmain() at l:1:6
```
