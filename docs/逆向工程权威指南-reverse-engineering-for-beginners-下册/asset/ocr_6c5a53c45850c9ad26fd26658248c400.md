```
; ECX - 1st argument
; EDX - 2nd argument
; RDX - 3rd argument
mov [rsp+arg_10], r8d, edx
mov [rsp+arg_8], edx
mov [rsp+arg_0], ecx
mov eax, [rsp+arg_0]
imul eax, [rsp+arg_8]
add eax, [rsp+arg_10]
ret
endp
```

```
mainsub rsp, 28h
mov r8d,3 ; 3rd argument
mov edx,2 ; 2nd argument
mov ecx,1 ; 1st argument
mov f
call f
mov edx, eax
lea rcx,$SG2931 ; "%\d\n"
call printf
return 0
xor eax, eax
add rsp, 28
ret
endp
```

比较的是，原本位于寄存器的3个参数都被推到了堆里。这种现象叫做“阴影空间/shadow space”[1]。每个Win64程序可以（但非必须）把4个寄存器的值存到阴影空间里。使用阴影空间有两个优点：1）通过传递参数，避免寄存器消耗（可能会占用4个寄存器）；2）便于调试器debugger在程序中断时找到寄存器参数（请参见：
https://mdn.microsoft.com/en-us/library/ew572%28vs=VS.90.29.aspx

)。大型函数可能会存在参数阴影空间，但是小型函数（如例）可能就不会使用阴影空间。

在用阴影空间时，由调用的函数分配空间，由被调用函数根据需要将寄存器参数存储到它的阴影空间中。
