# Optimizing GCC

聪明的你一定会问，既然CMP比较的是相同的值，比较之后的标志位状态也是相同，那么还有必要对同样的参数进行多次比较呢？或者MSVC真的不能再智能一些了？但是启用优化选项后，GCC 4.8是否能够进行这种深度优化。

指令清单12.4 GCC 4.8.1 f_signed()

```
eax, DWORD PTR [esp+8]
cmp DWORD PTR [esp+4], eax
jg .L6
je .L7\jnge .L1
mov DWORD PTR [esp+4], OFFSET FLAT:.LC2 ; "a<b"
mov puts
```

```
.L6:
mov DWORD PTR [esp+4], OFFSET FLAT:.LC0 ; "a>b"
mov puts
```

```
.L1:
rep
ret
```

```
.L7:
mov DWORD PTR [esp+4], OFFSET FLAT:.LC1 ; "a==b"
mov puts
```

很明显，它使用用jmp替代了肿胀的“CALL ......puts ...... RETN”指令。本书在13.1节将详细解答这种编译技术。

我们不得不说在x86的系统中，这种程序比较容易。MSVC 2012做不到GCC那种程序的深度优化。另一方面，汇编语言的程序员学会Joc指令连用的技巧。所以，如果你遇到了了这种精简的程序，而且能够判断出它是GCC编译出来的程序，那么基本上可以判断出它是手写的汇编程序。

即使开启了同样的优化选项，f_unsigned()函数对应的指令也没有精致。
