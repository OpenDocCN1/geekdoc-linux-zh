从程序我们可以看到，函数调用采用了指令 RET带一个操作的方式返回栈指针。借此可以判断，调用函数通过栈传递了多少个外部参数。

# 64. 3.1 GCC regparam

从某些意义来说，GCC regparam由fastcall进化而来。这种规范允许程序员通过编译选项“-mregparam”设置通过寄存器传递的参数总数（最大值为3）。换句话说，这种规范最多可以通过3个寄存器，即EAX、EDX和CX传递函数参数。

当然，如果“-mregparam”的值小于3，那么就不会全部使用这三个寄存器。

这种约定要求调用函数在调用过程结束后后调整栈指针，将参数恢复到其初始状态。

有关案例请参阅本书的19.1.节。

# 64. 2 Watcom/OpenWatcom

这被称为“寄存器调用规范”。四个参数由寄存器EAX、EDX、EBX和CX传递，其余的所有参数都通过栈传递。在使用这种调用约定时，函数必须其函数函数名前添加标识符“__watcom”，与与其他不同的调用规范的函数分开来。

# 64. 4 thiscall

是一种为C++类成员函数用this指针而特别指定的调用规范。

MSVC用ECX寄存器传递this指针。

而GCC把this指针作为被调用函数的第一个参数传递。在汇编层面，这个指针显而易见：所有的类函数都比源代码多出来一个参数。

有关详情，请参阅本书的51.1.1节。
