选用以下命令进行编译：

```
cl no_crt.c user32.lib /link entry:main
```

+   - 上述指令最终生成一个大小2560字节的可执行文件。该文件具备标准的PE头部，调用MessageBox的指令，其数据段明了两个字符，并从库文件user32.dll引入MessageBox函数。可执行文件没有其他的内容。

虽然程序确实可以正常运行，但是这个程序无法获取WinMain数据的4个参数。确地确实地，程序可以启动起来，是在程序运行的时候外部参数并没有被准备或传递的。

不能采取包括4个参数在的主函数WinMain()的方式，而不是采用main函数。更精确一点来说，虽然传递参数，但是参数不是在程序执行时才被传递的。

另外，通过编译器限制段为更小地对齐（默认值是4096字节），那么，编译器将生成尺寸更小的exe：

```
cl no_crt.c user32.lib /link entry:align:16
```

链接器Link显示：

> LINK : LNK4018: ALIGN specified without /DRIVER; image may not run

上述命令将生成一个长度为720字节的可执行文件。它可以运行在x86架构的Windows 7上，但是不能运行在64位的Windows 7上（执行的时候，系统会输出错误）。从这里可以看到，我们我们可以想办法让执行文件变得更小一些，但同时兼容性问题也会越来越出来。

# 68.2 Win32 PE文件

PE (Portable Executable) 格式，是微软Windows环境可移动执行文件（exe, dll, vxd, sys和vdm）的标准格式。

与其他类型的PE文件的不同的是，exe和sys文件只有导入表而没有导出表。

其他的PE文件一样，DLL文件也有一个原始入口点EP（就是DllMain函数的地址）。是DLL的这个函数通常我们不会去调用

sys文件通常是一个系统驱动程序。在读取PE文件时，操作系统需要在PE文件中保存它的正确性，并验证它的校验（彼就可以验证该校验和）。

从Vista开始，所有的Windows程序必须具备数字签名，否则系统会拒绝加载它们。

每个PE文件都由一段头部“This program cannot be run in DOS mode.”的DOS程序头部开始。如果在DOS或者Windows 3.1环境下运行这个程序，那么就只会看到上述字符串。由于DOS和Windows 3.1系统不能识别PE格式的文件。
