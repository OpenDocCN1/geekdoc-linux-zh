# 第30章 有符号数的表示方法

有符号数通常以二进制补码[1]的形式存储于应用程序里。维基百科介绍了各种表示方法，感兴趣的读者可以参见 http://en.wikipedia.org/wiki/Signed_number_representations

- 本节摘录了一些典型的单字节数值：

| 二进制 | 十六进制 | 无符号值 | 有符号值(补码) |
|---|---|---|---|
| 01111111 | 0x7f | 127 | 127 |
| 01111110 | 0x7e | 126 | 126 |
| ... | ... | ... | ... |
| 00000010 | 0x2 | 2 | 2 |
| 00000001 | 0x1 | 1 | 1 |
| 00000000 | 0x0 | 0 | 0 |
| 11111111 | 0xff | 253 | -1 |
| 11111110 | 0xfe | 254 | -2 |
| ... | ... | ... | ... |
| 10000010 | 0x82 | 130 | -126 |
| 10000001 | 0x81 | 129 | -127 |
| 10000000 | 0x80 | 128 | -128 |

如果0xFFFFFF和0x00000000都是无符号数，则第一个数(4294967294)比第二个数(2)大。如果这两个值表示的是有符号数，那么第一个数（-2）反而比第二个数（2）小了。所以，为了正确操作符号数和无符号数，条件转移指令（参见本书第12章）特别分为JG/JL系列（signed型）和JA/JBE系列（unsigned型）两套指令。

为了便于记忆，我们总结其特点如下：

- 同一个数值就可以表示有符号数，也可以表示无符号数。
- C/C++的符号型数据：
  - int64_t（范围从-922337203685475808至922337203685475807，即从0x8000000000000000至0xFFFFFFFFFFFFFFFF）
  - int（取值范围从-2147483648至2147483647，即从0xFFFFFF）
  - char（取值范围从-127到128，即从0x7F到0x80）
  - size_t。
- 无符号型数据：
  - uint64_t（范围从0到184467440370951615/0xFFFFFFFFFFFFFFFF）
  - unsigned int（取值范围从0到4294967295，即从0到0xFFFFFFFF）
  - unsigned char（取值范围从0到255，即从0到0xFF）
  - size_t。

有符号数的最高数位是符号位：1代表负数，0代表正数。

从数据宽度较小的数据转换为数据较大的数据是可行的。参见前面24.5节。

负数的补码和源码的双向转换过程是相同的，都是位求非再加1。这种运算过程简单记忆：同一个值的正负数是相反的值，所以要求非；求非之后再加是因为是因为的“零”占据了一个数的位。

加减运算不区分有符号数和无符号数，它们的加减运算指令完全相同。但是乘除法运算还是有别的：在x86指令集里，有符号的乘除指令是IMUL/IDIV，而无符号数的指令是MUL/DIV。

- 此外，有符号的操作指令更多一些。例如 CBW/CWD/CWDE/CDQ/CDQE（附录A.6.3）、MOVSX（15.1.1节）、SAR（附录A.6.3）。

[1] two’s complement; 简称为“补码”。

# 第31章 字节序

字节序是指多字节类型的数据在内存中的存放顺序，通常可分为小端、大端两种字节序。小端字节序（Little-endian）指低端数据存放在内存地址处，高阶数据存放在高地址处；大端字节序（Big-endian）是高阶数据存放在低地址处，低阶数据存在高地址处。

## 31.1 大端字节序

采用大端字节序时，0x12345678在内存中的存储如下：

| 内存地址 | 字节值 |
|---|---|
| +0 | 0x12 |
| +1 | 0x34 |
| +2 | 0x56 |
| +3 | 0x78 |

Motorola、IBM POWER系列采用大端字节序。

## 31.2 小端字节序

采用小端字节序时，0x12345678在内存中的存储方式所示：

| 内存地址 | 字节值 |
|---|---|
| +0 | 0x78 |
| +1 | 0x56 |
| +2 | 0x34 |
| +3 | 0x12 |

Intel x86系列采用小端字节序。

## 31.3 举例

为了演示，可以在QEMU的虚拟环境中安装MIPS接下来在MIPS里编译程序：

```c
#include <stdio.h>

int main()
{
    int v, i;
    v=123;
    printf("%02X %02X %02X %02X\n",
      *(char*)&v,
      *(char*)&v+1,
      *(char*)&v+2,
      *(char*)&v+3);
}
```

然后运行上述指令：

```bash
root@debian-mips:~# ./a.out
00 00 00 7B
```

其中0x7B就是十进制。在采用小端字节序的平台上，例如x86-64上，第一个字节就是0x7B。但是MIPS采用的大端字节序，数值最高的字节排列在最后。正是因为MIPS硬件平台可能采用不同的字节序，所以MIPS Linux分为大端字节和小和小字节序。在一种字节序平台上编译出来的程序，不可能在另一种字节序平台上运行的。本节介绍了MIPS大端字节序的特征。

## 31.4 双端二元格式

ARM,PowerPC,SPARC,MIPS,IA64等CPU采用双端二元格式（Bi-endian），就可以工作于小端字节序切换到大端字节序。

## 31.5 转换字节序

BSWAP指令可在汇编层面转换字节序。TCP/IP数据的封装规范采用大端字节序，所以采用小端字节序平台的就需要专门的转换字节序函数。常用的字节序转换函数是htons()和ntohs。

在TCP/IP的术语里，大端字节序又称为“网络字节序（Network Byte Order）”，主机的字节序叫作“主机字节序”。x86和其他平台的主机字节序是小端字节序，但是IBM POWER等服务器系列均采用大端字节序。因此，在主机字节序为大端字节序的平台上使用htonl()或htons()函数转换字节序，其实不会真正意义的字节重排。

# 第32章 内存布局

C/C++把内存划分为若干区域，主要的内存区域有：

- 全局内存空间，又称为（全局）静态存储区 static memory allocation。不需要全局变量和静态变量明确划分存储空间，全局变量、全局数组，编译器能够在段或常量数组为其分配适当的存储空间。由于整个程序都可以访问这个区域的数据，所以人们认为使用这种存储数据会破坏程序的结构化体系。此外，在全局内存空间出现的缓冲区溢出问题，往往将覆盖内存中相同位置的变量或缓存（请内核本书7.2节）。

- 栈空间，由程序分配的存储区域。它是由编译器自动分配、释放的存储区域，用于存放函数的参数和局部变量。在特定情况下，局部变量可能被其他指针访问（局部变量的指针传递给被调用函数）。在指令层级，“分配和释放栈空间的实质就是调整寄存器的值，因分配和释放栈空间的速度非常快。

- 编译器只能为那些在编译阶段确定大小的局部变量划分栈空间。因此，不需要预留存储空间的缓冲区类型类型即缓冲区缓冲区动态数组不会被被到栈空间里。在栈空间发生的缓冲区溢出问题，通常会修改栈里的重要数据（请内核本书18.2节）。

- 堆，即“动态内存分配”。C语言的malloc()/free()函数或C++的new/delete语句即可分配、释放堆空间。“不事先声明堆空间的大小”即“在程序启动后再确定堆块的‘容量’”这一特征构成了它的独有的便利性。另外，程序员可以动态调整(realloc()函数)内存内的大小，只是调整空间的操作并不理想。在内存分配操作中，申请、释放空间是最慢的。区域发生的缓冲区溢出通常会覆盖堆结构。空间管理不当，所有分配的堆空间应当被明确释放，否则出现内存泄露问题。另外，“调用free()函数之后再次使用这块内存”同样带来非常严重的问题。

# 第34章 哈希函数

哈希(hash)函数能够生成可靠性较高的校验(Checksum)，CRC32算法就是一种不太复杂的算法，哈希值是一种固定长度的信息摘要，从加密角度看，可以根据哈希值反向“推测”信息。无论CRC32算法的信息有多长，它只能生成32位的校验。当然，多个哈希函数（Cryptographic hash function）的任务了。此外，人们普遍使用MD5、SHA1等哈希算法生成哈希值，然后把密码存储在数据库中。实际上在网上，存储的哈希信息并不是密码，否则容易发生数据泄露。当用户登录网站时，应用程序校验并不是密码，而是校验的是哈希值：如果用户名和哈希值与数据库中的记录匹配，它将被授予相应的访问权限。此外，常见的破解工具都是通过穷举的方法。

# 单向函数与不可逆

单向函数（one-way function）具有特点：对于每一个输入，哈希值容易计算（多项式时间）；但是根据函数值对原始输入进行逆向推算就比较困难（无法在多项式时间内完成计算）。本节将解释不可逆性。

假设函数的输入值由10个介于~9之间的数值构成的一组向量，且向量中的数值只出现一次。例如：

```
4 6 0 1 3 5 7 8 9 2
```

下列算法即可实现简单的单向函数：

- 取第0位的值作为参数1（本例而言是4）。
- 取第1位的值作为参数2（本例而言是6）。
- 交换参数1、2位置处（第4、6位）的值。

本例中的第4位和第6位数字分别是：

```
4 6 0 1 3 5 7 8 9 2
```

进行最终变换后：

```
4 6 0 1 7 5 3 8 9 2
```

即使我们知道具体的算法和最终的函数值，我们也无法确定初始的输入值是什么。因为最初的位置参数可能是0也可能是1，这两个参数可能会被交换位置。

实际应用中的单向函数远比本例复杂。
