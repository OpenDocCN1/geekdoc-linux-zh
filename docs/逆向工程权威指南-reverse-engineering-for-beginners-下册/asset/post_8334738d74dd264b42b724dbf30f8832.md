## 13.1.2 ARM: Optimizing Keil 6/2013 (ARM mode)

```
.text:0000014C
fl:
.text:0000014C 00 00 50 E3  CMP R0, #0
.text:00000150 13 0E 8F 02  ADREQ R0, azero ; "zero\n"
.text:00000154 05 00 00 0A  BEQ loc_170
.text:00000158 01 00 50 E3  CMP R0, #1
.text:0000015C 4B 0F 8F 02  ADREQ R0, adone ; "one\n"
.text:00000160 02 00 00 0A  BEQ loc_170
.text:00000164 00 00 50 E3  CMP R0, #2
.text:00000168 4A 0F 8F 12  ADNE R0, aSomethingUnko ; "something\nunknown\n"
.text:0000016C 4E 0F 8F 02  ADREQ R0, aTwo ; "two\n"
.text:00000170
loc_170 ; CODE XREF: f1+8
.text:00000170
; f1+14
.text:00000170 78 18 00 EA  B _2print
```

我们无法通过编译器汇编判断源代码使用的switch语句是循环语句。

此外，这段代码出现了ADREQ指令这种条件执行指令。第一条ADREQ指令在出错的情况下，字符串“zero ”的地址传递R0。紧接着其后BEQ指令在某些条件下控制跳转流到loc_170。或许许多读者会问，ADREQ之后能够直接读取到前面CMP设置的标志位吗？这显然不是问题。只有少数BEQ指令才会设置标志寄存器的值，另一个条件执行指令不会重置标志寄存器。它的原理并不难理解。程序在结尾调用第一次printf()函数。最后一条指令是CMP R0, #2。它的作用是检查是否为2。如果不符合，程序通过ADREQ将“something\n”的指针赋值给R0。在此之前，程序已经确定了R0的值。

### 13.1.3 ARM: Optimizing Keil 6/2013 (Thumb mode)

```
.text:000000D4
fl:
.text:000000D5 B5  PUSH {R4,LR}
.text:000000D6 00 28  CMP R0, #0
.text:000000D8 05 00  BEQ zero_case
.text:000000DA 01 28  CMP R0, #1
.text:000000DC 05 00  BEQ one_case
.text:000000DE 02 28  CMP R0, #2
.text:000000E0 05 00  BEQ two_case
.text:000000E2 91 A0  ADR R0,aSomethingUnko ; "something\n"
.text:000000E4 04 E0  B default_case
.text:000000E6 95 A0  ADR R0,aZero ; "zero\n" ; zero_case ; CODE XREF: f1+4
.text:000000E8 02 E0  B default_case
.text:000000EA 96 A0  ADR R0,aOne ; "one\n" ; one_case ; CODE XREF: f1+8
.text:000000EC 00 E0  B default_case
.text:000000EE 97 A0  ADR R0,aTwo ; "two\n" ; two_case ; CODE XREF: f1+C
.text:000000F0 default_case ; CODE XREF: f1+10
.text:000000F0 f1+14 06 70 F8 BL _printf
.text:000000F4 14 D0  POP {R4,PC}
```

前文介绍过，条件执行指令是ARM模式之一。Thumb模式的指令集没有条件执行指令。因此Thumb模式的指令更为接近x86 CIS（复杂指令集）的指令，速度较低。

## 13.1.4 ARM64: Non-optimizing GCC (Linaro) 4.9

```

```

beq .L35

bne .L38 ; jump to default label

add x0, x0, #lo12:.LC12

```

.L34:

```

## 13.1.5 ARM64: Optimizing GCC (Linaro) 4.9

```
f12:
cmp w0, 1
beq .L31
cmp w0, 2
beq .L32
cbz w0, .L35
; default case
adrp x0, .LC15      ; "something unknown"
add x0, x0, :lo12:.LC15
bl puts
.L35:
adrp x0, .LC12      ; "zero"
add x0, x0, :lo12:.LC12
bl puts
.L32:
adrp x0, .LC14      ; "two"
add x0, x0, :lo12:.LC14
bl puts
.L31:
adrp x0, .LC13      ; "one"
add x0, x0, :lo12:.LC13
bl puts
```

优化的效果显著。CBZ（Compare and Branch on Zero）在W0的值为零的情况下跳转。此外，在调用puts()的时候，本例使用的是JMP而非常规的调用，这反映了13.1.1节过的函数方式。

## 13.1.6 MIPS 指令清单

```
f:
lui __gnu_local_gp, 16)
; is it 2?
li $v0, 1
beq $a0, loc_6
la (__gnu_local_gp & 0xFFFF) ; branch delay slot
; is it 2?
li $v0, 2
beq $a0, loc_4C
or $at, $zero ; delay slot, NOP
; jump, if not equal to 0:
bnez $a0, loc_38
$at, $zero ; delay slot, NOP
; zero case:
lui $a0, ($LC0 >> 16) # "zero"
lw $t9, (puts & 0xFFFF) ($gp)
or $at, $zero ; load delay slot, NOP
jr $t9 ; branch delay slot, NOP
la $a0, ($LC0 & 0xFFFF) # "zero"; branch

loc_38: # CODE XREF: f+1C
loc_4C: # CODE XREF: f+14
lui $a0, ($LC3 >> 16) # "something unknown"
lw $t9, (puts & 0xFFFF) ($gp)
or $at, $zero ; load delay slot, NOP
jr $t9
la $a0, ($LC3 & 0xFFFF) # "something unknown"

lui $a0, ($LC2 >> 16) # "two"
lw $t9, (puts & 0xFFFF) ($gp)
or $at, $zero ; load delay slot, NOP
jr $t9
la $a0, ($LC2 & 0xFFFF) # "two"; branch

lui $a0, ($LC1 >> 16) # "one"
lw $t9, (puts & 0xFFFF) ($gp)
or $at, $zero ; load delay slot, NOP
jr $t9
la $a0, ($LC1 & 0xFFFF) # "one"; branch
```

在汇编层面，每个分支的最后一条指令都是puts()函数的。而且每一个case分支都通过跳转指令JR (Jump Register)调用puts()函数，完全没有使用常规的函数指令JAL(Jump And Link)。有详细介绍，请参阅LW13.1.1。

另外，参数LW指令之后有一条NOP指令。这种指令叫做“加载延迟槽”；是MIPS平台的另一种延迟。在LW指令从内存加载数据的时候，下面的指令可以和他并发执行。这样一来，LW后面的那条指令就无法使用读取的数据了。当今主流的MIPS CPU都对这一问题进行了优化，在后一条指令使用LW数据的情况下能够自动处理。虽然现在的MIPS处理器不再加载延迟时，但是GCC还是为了保险地添加延迟槽。所以，我们已经忽视这种加载延迟了。

## 13.1 总结

在case存在较少的情况下，case()语句和if/else语句的编译结果基本相同。指令清单13.1可以充分阐述这个结论了。

## 13.2 case 描述式较多的情况

在switch()语句在大量分支的情况下，编译器就不能直接套用大量JE/JNE指令了。否则程序代码会非常庞大。

```
#include <stdio.h>

void f (int a)
{
    switch (a)
    {
        case 0: printf("zero\n"); break;
        case 1: printf("one\n"); break;
        case 2: printf("two\n"); break;
        case 3: printf("three\n"); break;
        case 4: printf("four\n"); break;
        default: printf("something unknown\n"); break;
    }
}

int main()
{
    f(2); // test
}
```
