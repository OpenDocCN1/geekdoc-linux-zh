```
mov DWORD PTR [rsp+32], 5
call f1

xor eax, eax
add rsp, 72          ; 00000048H

```

即使我们使用编译器的优化选项编译上述代码，编译器仍然会生成基础相同的指令；只是它不再分配上面提到的“零散空间”，因为已经不需要了。

另外，我们看到：在启用优化选项之后，MSVC 2012 将是一一条指令（请阅读附录 A.6.2）进行数值传递。笔者并不确定它分配的这种指令是否能够提升运行效率，或许真有此作用吧。

C/C++ 编译器会使用 RCX 寄存器传递对象的 this 指针、用 RDX 寄存器传递函数所需的第一个参数。对于这个方面的例子，可以查看本书的 51.1.1。

# 64.5.2 64 位的 Linux

64 位Linux 程序传递参数的方法和 64 位Windows 程序的传递方法几乎相同。区别在于，64 位Linux 程序使用 6 个寄存器（RDX, RSI, RDX、RCX, R8, R9）传递前几项参数，而 64 位Windows 则只利用 4 个寄存器传递参数。另外，64 位Linux 程序没有上面提到的“零散空间”这种概念。如果被调用函数的寄存器数量紧张，它就可以用栈存储外来参数，相关寄存器腾出来使用。
