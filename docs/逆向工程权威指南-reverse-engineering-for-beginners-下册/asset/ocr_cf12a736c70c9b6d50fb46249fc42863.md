```
#define GENERIC_READ (0x80000000L)
#define GENERIC_WRITE (0x40000000L)
#define GENERIC_EXECUTE (0x20000000L)
#define GENERIC_ALL (0x10000000L)
```

毫无疑问，在API声明中，CreateFile()函数的第二个参数为
“GENERIC_READ | GENERIC_WRITE” = 0x80000000 | 0x0C000000。

CreateFile()函数如何检测标志位呢?

我们可以在Windows SP3 下的KERNEL32.DLL中，找到CreateFile
函数的相关代码。

# 指令解析19.3 KERNEL32.DLL (Windows SP3 x86)

```
.text:7C8D429    byte ptr [ebp+dwDesiredAccess+3], 40h
.text:7C8D432    dov     [ebp+var8], 1
.text:7C8D434    jz      short 7C8D417
.text:7C8D436    jmp     loc_7C80817
```

比较讲解的是TEST指令。在这里，它没有使用整个第二个参数，而是
只拿取它的最高的一位字节（ebp+dwDesiredAccess+3）和0x40（对应
GENERIC_标志位）进行运算。

TEST与AND指令的唯一区别是前者不保存运算结果，CMP指令和SUB指令之
间存在这种差异（请参见本书7.3.1节）。

即，上述可执行的源代码逻辑：

```
if (dwDesiredAccess&0x40000000) == 0 goto loc_7C8D417
```

如果此处的与(&(&的结果是1，则会清零ZF标志位，而不会触发JZ
跳转。只有在dwDesiredAccess变量&0x40000000的计算结果为0的情况下，
条件转移跳转指令会被触发；即与运算(&(&)的结果是零、ZF标志位为1，从而
触发条件转移指令。
