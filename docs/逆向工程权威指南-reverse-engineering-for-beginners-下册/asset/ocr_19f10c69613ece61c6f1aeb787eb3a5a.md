无论是否优化选项，GCC 4.4.1的代码和MSVC生成的代码相似，只是GCC不会发布任何警告。

ARM程序也使用寄存器保存返回地址，只是不同。在3.4节中，我们看到“Hello, World!”程序的返回地址保存在LR（link register）寄存器里。如果是，ARM程序还要继续使用其他函数，就需要调用其他函数之前保存LR寄存器的值。通常，函数在启动过程中（序言）保存LR寄存器的值。我们通常在函数函数中看到“PUSH R4-R7, LR”，并在函数尾声处看到“POP R4-R7”。这些指令会对使用的寄存器进行保护，把它们的值存放在栈中——当然了，其中也包括LR寄存器。

如果一个函数不调用其他函数，它就像树的末端的叶子那样。这种函数就叫做“叶函数（leaf function）”。[3]叶函数的特点是，它不保证LR寄存器的值。如果叶函数的代码用到没几个寄存器，那么它也可能根本不使用数据。如果是，所调用函数确实可能不会涉及与栈的操作。这种情况下，因为函数不在外部RAM中进行与栈有关的操作，所以它的运行速度可以超过x86系统[4]。在没有分配内存或者不可用的内存时候，这类函数就会显得“寸有所长”的优势。

本书介绍了很多函数。请参阅8.2节、8.3节、15.2节、15.4节、17.3节、19.4节、19.33节演示的程序。

# 5.2.2 参数传递

在x86平台的程序中，最常用的参数传递约定是cdecl[5]。以cdecl方式处理参数，它的下方大致是这样的：

```
push arg3
push arg2
push arg1
call f
add esp, 12; 4*32
```

被调用函数（Callee functions）通过函数指针获取所需的参数。

在运行f()函数时，传递的参数将以以下格式存在内存里。

| | 返回地址 |
|---|---|
| ESP+4 | arg1, 它在IDA里为arg_0 |
| ESP+8 | arg2, 它在IDA里为arg_4 |
