之后的“MOVW R0, #0x1D8”将立即数写到R0寄存器的低16位地址，同时清除寄存器的高16位。

“MOVT.W R0, #0”的作用与前面一个例子中Thumb模式的MOVT的作用相同，但此处是Thumb-2的指令。

在这两个程序中，最显著的区别是Thumb-2模式“BLX”指令。此处的BLX与Thumb模式的BL指令有根本的区别，它不仅了puts()函数的返回地址RA存入了LR寄存器，并将控制交给了ARM/Thumb模式的ARM处理器，而且处理器也负责在函数退出时把处理器的运行模式进行还原。总之，它实现了模式转换和控制权的交给，对于执行了下面的ARM模式的指令：

```
_symbolst:00003FEC _puts ; CODE XREF
hello_world+E _symbolst:00003FEC 44 F0 F9 E5 LDR PC, =_imp_puts
```

懂的读者可以看出，此处为什么不直接调用puts()函数？

直接调用的空间会销大。

所有的程序都会调用动态链接库，详细来说Windows的程序基上都会加载DLL文件，Linux程序通常都不会被调用SO文件、MacOSOS系统的程序多数也会调用dylib文件。通用的函数库通常放在动态链接库中。本例例的标准C函数——puts()函数也不例外。

可执行的二进制文件（Windows的PE可文件，ELF或Mach-O）都有一个输入表（import section）。输入表表明了该程序需要通过模块加载的符号链接（函数名称和全局变量），并且含有模块模块名等信息。

在操作系统执行二进制文件时，可加载程序（OS loader）会根据这个表找到加载程序所需的模块。在它加载程序主模块时，对导入的符号链接进行挂载，逐步匹配符号链接的地址。

在本例中，_imp_puts是操作系统加载程序（OS loader）为helloworld程序提供的外部函数地址，属于32位变量。程序只需要LDR指令取出这个变量，并将其赋值PC寄存器，就可以调用puts()函数。
