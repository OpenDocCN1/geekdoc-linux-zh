+   • 数据标识为IMAGE_SCN_CNT_INITIALIZED_DATA、IMAGE_SCN_MEM_READ或IMAGE_SCN_MEM_WRITE标记。

+   • 未初始化的数据的空段的标识为IMAGE_SCN_CNT_UNINITIALIZED_DATA、IMAGE_SCN_MEM_READ或IMAGE_SCN_MEM_WRITE。

+   • 常数段（其中的数据不可被重新赋值）的标识是IMAGE_SCN_CNT_INITIALIZED_DATA以及IMAGE_SCN_MEM_READ，但是不包括IMAGE_SCN_MEM_WRITE。如果重新尝试在这个数据段写入数据，那么整个进程就会崩溃。

PE可执行文件的每个段都可以拥有一个段名。然而，名称是段的重要特征。通常来说，代码段的名称是text，数据的段名称是data，常数段的名称rdata（只读数据）。其他类型的段名还有：

+   - .idata: 导入段。IDA可能会给这个段分配一个伪名；详情请参阅参考书籍68.2.1节。

+   - .edata: 导出。这个段十分罕见。

+   - .pdata: 这个段存储的是用于异常处理的函数项。它包含了Windows NT For MIPS、IA64以及x64全部的异常处理信息。详情请参看本书的68.3.3节。

+   - .reloc: 重定位段。

+   - .bss: 未初始的数据段（BSS）。

+   - .tls: 线程存储段（TLS）。

+   - .rsrc: 资源。

+   - .CRT: 在早期版本的MSVC编译的可执行文件中，可能出现这个段。

经过加密或者压缩处理之后，PE文件section段的名称通常会被替换或混沌。

此外，开发者还可以控制MSVC编译器、设定任意的段名。有关信息请参阅：https://msdn.microsoft.com/en-us/library/windows/cc307397.aspx

部分段（例如MinGW）和链接器可以在生成的执行文件中加入带有调试号、或者其他的调试信息的独立段。然而新版本的MSVC不再支持这项功能。为了方便专业人员分析和调试应用，MSVC推出了全称为“程序数据库”的PDB格式。
