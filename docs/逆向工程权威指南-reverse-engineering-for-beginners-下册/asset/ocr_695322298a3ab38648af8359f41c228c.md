# 指令令83.1 Andrey "hermit1" Baranovich: 11 bytes

```
0000000: B05C      mov      al,05C      ; '\\'
      read AL byte from random place of memory
0000002: AE               scasb
      PF = parity(AL - random_memory_byte) = parity(5Ch -
      random_memory_byte)
0000003: 7A02              jp       00000007
0000005: B02F              mov      al,02F      ; '//'
00000007: CD29              int        ; output AL to screen
00000009: EBF5              jmp      00000000 ; loop endlessly
```

SCASB计算“AL-[随机地址]”，并设置相应标识。JP指令比较少，触发JP的条件是奇偶PF1(数值)。在这个程序里，输出的字符并不由随机字母的每个比特位决定，而是由这些字符的每个比特位共同决定，这个程序的散列数组有望比更好一些。

如果使用86未包含的SAL指令（RETSEAL），单指令完成“SET CF”，那么整个程序就可以运行了。这个指令最早出现在NEC语言里。用自然语言解释的话，它的功能就是“有标识位填充AL寄存器；CF为1，则AL的值就会0xFF；否则的值就是0。受到AL兼容性的影响，任80/8088平台上无法运行

# 指令令83.2 Peterie: 10 bytes

```
AL is random at this point
0000000: AE               scasb
      CF is set according subtracting random memory byte by AL.
      so it is somewhat random at this point
00000001: D6               setalc
      AL is set to 0FF if CF=1 or to 0 otherwise
00000002: 242D              and        al,02D      ;'-'
      if AL is 0x2D or 0
00000004: 02F              add        al,02F      ; '//'
      AL is 0CX or 02F
00000006: CD29              int        ; output AL to screen
00000008: EBF6              jmp      00000000 ; loop endlessly
```

因此，完全没有彻底放弃转移指令。反扣（""）和斜扣（/）的ASCII值分别是0x5C和0x2F。其余的问题就是根据CF的（仿随机）状态AL寄存器的设置为0x5C和0x2F。

实际解决方法非常简单：无论AL的值是0还是0FF，我们把它和0x2D进行“与”运算，就能得到0和0x2D再把这个值与0x2F相加，得到了0x2F和0x5C。然后把AL寄存器的值打印到屏幕上即可。
