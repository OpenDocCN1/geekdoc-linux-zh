现在EIP的值（PC）是015。这不是合法的程序地址——至少对于win32系统来说这个值是有问题！程序在此处发生异常。有趣的是，此时EBP的值是014，ECX和EDX的值是01D。

我们一起回一遍主栈结构。

等待程序进入main()函数时，程序使用用来保存EBP寄存器的值。然后程序分配了84个字节，用于存储分组和变量i。计算方法是
* “(20+1)*sizeof(int)” 堆指针EIP现在指向内存中的变量i，在执行PUSH内存操作之后它会指向i的下一个地址。

即，main()函数的结构如下：

| ESP | i7所用的4字节 |
| ESP+4 | a[20]占用的80字节 |
| ESP+84 | 保留的EBP |
| ESP+88 | 返回地址 |

赋值给a[19]的时候，数组a[]已经被全部赋值。

赋值给a[20]，实际值是EBP。

观察程序崩溃时的寄存器状态。本例将20（0x14）赋值给a[19]。在程序退出时，CPU通过栈恢复EBP的初始值。本例它会收到的值是20（0x14）最后执行RET指令，相当于执行POP指令。

> RET指令将程序传递给返回的地址（该地址为CRT内部调用main()的地址），不过这里RA的值改为了21（0x15）。CPU寻找0x15的代码，以便继续程序，如果该地址没有执行代码，程序就会崩溃了。

惊喜！你已经了解了缓冲区溢出的精妙之处。

设想一下：用字符串替换int函数，刻意构造这个长字符串，把字符串传递给程序；因为函数不会检查字符串长度，会直接赋值给较短的缓冲区，您就可以强制这个程序跳转到另一个程序的地址。纸上谈兵虽简单，但是无论实际情况如何重变化，其原理都是一样的。
