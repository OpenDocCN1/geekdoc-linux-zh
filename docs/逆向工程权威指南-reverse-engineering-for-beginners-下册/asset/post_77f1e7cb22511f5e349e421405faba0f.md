# 第15章 C语言字符串的函数

## 15.1 strlen()

本章是循环控制语句的具体应用。通常，strlen 函数由循环语句 while() 语句实现。参照MSVC标准库对strlen()函数的定义方法，我们讨论上述的程序:

```
int my_strlen (const char * str)
{
    const char *eos = str;
    while(*eos++ );
    return(eos - str - 1);
}
```

```
int main()
{
    // test
    return my_strlen("hello!");
}
```

### 15.1.1 x86

使用MSVC 2010编译上述程序可得到:

```
_eos = -4          ; size = 4
_str$ = 8          ; size = 4
_strlen PROC
    push    ebp
    mov     ebp, esp
    push    ecx
    mov     eax, DWORD PTR _str$[ebp]; 将指针指向字符串
mov    DWORD PTR $eos[ebp], eax; 指向局部变量eos
$LN2_strlen:
mov    ecx, DWORD PTR $eos[ebp]; ECX=eos
ret

    ; take 8-bit byte from address in ECX and place it as 32-bit value
to EDX with sign extension

movsx   edx, BYTE PTR [ecx]
mov    eax, DWORD PTR $eos[ebp]; EAX=eos
add    eax, 1; ; ECX++
mov    DWORD PTR $eos[ebp], eax; EAX还原为
test   edx, edx
je     SHORT $LN1_strlen; ; EDX = 0 ? yes, then finish loop
jmp    SHORT $LN2_strlen; ; continue loop
$LN1_strlen:
    ; we calculate the difference between two pointers

mov    eax, DWORD PTR $eos[ebp]
sub    eax, DWORD PTR _str[ebp]
sub    eax, 1; ; subtract 1 and return result
mov    esp, ebp
pop    ebp
xor    edx, edx
$strlen_   
```

这里出现了两个新指令：MOVX和TEST 数据，并把它存储到32位。

此处，MOVX从内存中读取8字节（单字），并把它存储到32位寄存器里。MOVX是mov带有Sign-Extend的缩写。在小空间数据转换为大空间数据时，存在填充高位数据的问题；例如中，MOVX将原始数据的位数据填充到EDX寄存器的低位；如果原始数据是负数，该指令将使用第8位到31位（高24位），否则使用024位。

是为了保证符号型数据在类型转换后的数值不变char（有符号）数据。现在设有一把char型数据转换为整数型（都是有符号数）的情况：假设char型的原始值是-2（0xFE），直接将整个字节复制到整数型数据的低8位时，整数型的值变成0x000000FE，以有符号数据的角度看会被转换为254，而没有保持原始值-2。对的int型数据是0xFFFFFFFF。所以，在原始数据复制到符号位扩展后，还要使用符号标记填充剩余的数据，而这就是MOVX的功能。

本书30章会更详细地介绍符号型数据转换的方法。

并不是确定数据是否有必要分配EDX寄存器专门保存char型数据，看上面只使用了寄存器的低8位（相对于DX）。显然，编译器根据自己的寄存器分配规则进行了相应的分配。

你将在后面看到“TEST EDX,” 指令。本书在第19章详细介绍TEST指令。在本例中，它的功能是检查EDX的值是否为零，并设置相应的标志位。

## Non-optimizing GCC

使用GCC 4.4.1（未启用优化选项）编译上述程序，可以得到:

```
public strlen
proc near
eos = dword ptr -4
arg_0 = dword ptr 8

push ebp
mov ebp, esp
sub esp, 10h
mov eax, [ebp+arg_0]
mov [ebp+eos], eax
ret

loc_8043f0:
mov eax, [ebp+eos]
movzx al, byte ptr [eax]
test al, al
setnz al
add [ebp+eos], 1
test al, al
jnz short loc_8043f0
mov eax, [ebp+arg_0]
mov ecx, eax
sub eax, 1
leave
strlen
```

GCC的结果和MSVC差异。这里没有使用MOVX，而是用了MOVZX。MOVZX是mov with Zero-Extent。将8位或16数据转换为32位的时候，它可以复制原始数据到目标寄存器的相同，并且使用0填充剩余区域。另一方面，编译器可以生成“mov al, byte ptr [eax]; test al, al”这样的代码，但是像EAX寄存器的值将会存在随机。不像，这就是编译器的短板——编码（人类）可读性。本例还介绍了SETNZ指令。从前面一条指令开始：如果AL的值是0，test指令会将标志寄存器ZF置0；SETNZ (Not Zero)指令在ZF=0的时候设置AL=1。用来说：如果AL等于0，则跳转到loc.8043F。编译器出来的代码中并没有实际意义，这是因为我们没有开启。

## Optimizing MSVC

使用MSVC（优化选项/Ob）编译上述程序，得到如下所示指令:

```
str = 8                ; size = 4
_strlen PROC
    mov     edx, DWORD PTR _str[-4] ; 用EDX作为指针
    mov     eax, edx                      ; 复制EAX
$LL2@strlen:
    mov     cl, BYTE PTR [eax]            ; CL = *EAX
    inc     eax                           ; EAX++
    test    cl, cl                        ; CL=0?
    jne     SHORT $LL2@strlen             ; no, continue loop
    sub     eax, edx                      ; 计算指针变量
    dec     eax, edx                      ; decrement EAX
    ret
_strlen ENDP
```

编译器生成的程序短了很多。不必说，只有在函数短且局部的情况下，编译器才会做这种优化。inc/dec指令就是递减指令，句话相当于“++”。
