
## 27.4 机器精度

本书在22.2节将介绍机器精度的具体算法。在这一节里，我们把它编译为如下所示的64位应用程序。

指令清单27.11 Optimizing MSVC 2012 x64

```
v = 8
calculate_machine_epsilon PROC
mov dx, QWORD PTR v$[rsp], xmm0
movaps xmm1, xmm0
inc QWORD PTR v$[rsp]
movsd xmm0, QWORD PTR v$[rsp]
subsd xmm0, 0
ret
calculate_machine_epsilon ENDP
```

由于INC指令无法对128位的XMM寄存器进行操作，程序首先要把寄存器的值传送到内存中的某个地址。

然而这并不是必须的。如果在此直接使用ADDSD (Add Scalar Double-Precision Floating-Point Values)令，就能对XMM寄存器的低64位进行加法运算，同时保持寄存器的高64位为值。或许，我们不得不说MSVC 2012还有改进的余地。

我们再看看这个程序，在完成减法运算之后，程序把返回值再次传回了XMM寄存器，然后对XMM寄存器进行减法（比较）操作。SUBSD的全部是“Subtract XMM Scalar Double-Precision Floating-Point Values”。它对128位寄存器的低64位进行操作。最后，减法的返回值保存在XMM寄存器中。

## 27.5 仿生成程序（续）

现在，我们再次使用MSVC 2012编译指令清单22.1的程序。这个版本的MSVC编译器能够直接分配FP/SIMD指令。

指令清单27.12 Optimizing MSVC 2012

```
_real@3f800000d 03 3f800000r      ; 1

tv128 = -4
tmp$ = -4
?float_rand@YAMXZ PROC
    push
    ecx
    call ?my_rand@YAIXZ
; EAX=pseudorandom value
```

```
and eax, 8388607 ; 007ffffF
or eax, 1065353216 ; 3f800000H
; EAX=pseudorandom value & 0x007ffff | 0x3f800000
; store it in local stack:
mov DWORD PTR tmp$[esp[4]], eax
; reload it as float point number:
mov xmm0, DWORD PTR tmp$[esp[4]]
; subtract 1.0:
subss xmm0, DWORD PTR real$8000000
; move value to ST0 by placing it in temporary variable:
mov DWORD tv128[esp[4]], xmm0
... and reloading it into ST0:
fld DWORD tv128[esp[4]]
pop
ecx
ret
?float_rand@YMXZ ENDP
```

编译器大量使用了“-SS” 后的指令。这个后缀是“Scalar Single”的写法。“Scalar（标量）”表明寄存器里只有一个值，“Single”则表示该值是单精度float类型的数据。

## 27.6 总结

在 XMM 寄存器存储 IEEE 754 格式浮点数的时候，本章的所有程序都只用到了 128 位寄存器空间的 64 位。

这是由操作指令决定的。本章中的指令带有-SD（Scalar Double-Precision）后缀。如此，所有操作的数据类型都是 IEEE 754 格式的双精度浮点数。这种数据只会使用 XMM 寄存器的 64 位。

SIMD 指集比 FPU 的指令更易理解。过去那些 FPU 指令远离语言语义，而且它们还要往返涉及 FPU 寄存器的结构，不如 SIMD 指令直观。

如果本章的数据类型都改为 double，那么操作浮点数的指令将改为-SS 后（Scalar Single-Precision）。您将看到 MOVSS/ADDSS/SS指令。

> “Scalar”就是“标量”的意思，表示寄存器里含有一个值。如果一个寄存器存有多个值，那么对这些寄存器进行操作的指令名字就会带有“packed”字样。还需要的是，SSE指令的操作都是 IEEE 754 格式的64 位数据，而 FPU 内部使用 80 位格式，误差较小，精度较高。

## 第28章 ARM指令详解

### 28.1 立即数（#）

在Keil编译器的眼里，以及在objdump程序显示ARM的汇编指令时，立即数（汇编指令中的常量）前面都有“#”标识。然而GCC 4.9编译文件中没有这种立即数标识。请对照一下14.1节和9.3节中的指令。本章列举了很多例子，它们是由多种编译器生成的汇编代码。这种问题或许谈不上。

### 28.2 变址寻址

变址寻址标识为：

```
ldr x0, [x29, #24]
```

上述指令从X29寄存器中取值，把这个值与24相加，将地址复制给X0寄存器。注意X29和24都在号之中。如果24不在号里，指令的涵义就完全不一样。我们来看：

```
ldr w4, [x1], #28
```

上述指令在X1寄存器标识的地址取值，然后进行加减运算。ARM可以在取值前进行寻址，还可以在取值后进行运算。x86汇编指令不支持这种操作。但是包括旧式的PDP-7平台内，许多其他平台都支持这种运算。PDP-1平台的指令支持前增量（pre-increment）、后减量（post-decrement）、后增量（post-increment）、后减量（post-decrement）运算。这大体可以属于C语言的*ptr++、++ptr、*ptr--类的指令。在C语言中，这些指令确实难以掌握。本文将处理如下：

| C术语 | ARM术语 | C语言 | 工作原理 |
| :--- | :--- | :--- | :--- |
| 后增量 | 后变址址 | *ptr++ | 使用ptr的值后，再递增运算 |
| 后减量 | 后变址址 | *ptr-- | 使用ptr的值后，再递减运算 |
| 前增量 | 前变址址 | ++ptr | ptr先递增，取ptr的值 |
| 前减量 | 前变址址 | --ptr | ptr先递减，取ptr的值 |

前变址址的指令带有符号标识。例如，指令清单3.15的第二条指令“stp x29, x30, [sp #-16]”。Dennis Ritchie（C语言的作者之一）曾经提到过，变址寻址是Ken Thompson（另一位C语言的作者）根据PDP-7平台开发的指令。现在在C语言编译器仍然保持这种兼容性，只要硬件处理器支持，编译器就可以进行相应的优化编译。

变址寻址的优越性集中现在数组方面。

## 28.3 常量赋值

### 28.3.1 32位ARM

所有的Thumb模式的汇编指令都是2字节指令，所有的ARM模式的汇编指令都是4字节指令。ARM指令和32位的立即数都占用4字节，又如何进行32位立即数赋值呢？我们来看：

```
unsigned int f() {
    return 0x12345678;
}
```

指令清单28.1 GCC 4.6.3 -03 ARM mode

f:
```
ldr r0, .L2
lr
.L2: .word 305419896 ; 0x12345678
```

可见，0x12345678存储在内存之中，供其他指令调用。但是这种指令增加了CPU访问内存的次数。我们可以改善这一状况。

指令清单28.2 GCC 4.6.3 -03-march=armv7-a (ARM mode)

```
movw r0, #22136 ; 0x5678
mov r0, #4660 ; 0x1234
lr
```

上述指令将一个立即数分为两个部分，并依次存储到同一个寄存器里。它使用MOVW将立即数的低位部分存储到寄存器里，然后使用MOV存储这个数的高位部分。这就是说，ARM模式的程序需要两个指令才能加载32位的立即数。除了0和1之外，程序很少用到常量，所以这种赋值的方法不会造成实际问题。有人会问，这种一分为二的做法不会造成性能的下降呢？虽然比单条指令的效率要低，但是现在的ARM处理器能够检测到这种指令序列并能够对这种指令进行优化。

另外，IDA这样的工具能够识别出一分为二指令，并在显示的时候它们合为一。

```
MOV R0, #012345678
```

### 28.3.2 ARM64

```
uint64_t f() {
    return 0x12345678DEF01;
}
```

指令清单28.3 GCC 4.9-03

```
mov x0, 0x6185,lsl #16
movk x0, 0x5678,lsl #32
movk x0, 0x1234,lsl #48
```

其中，MOVK是“MOV Keep”的缩写。它把16位数值存储到寄存器里，保留其他比特。实际上几个MOVK指令使用LSL移动了16、32、48，再次进行赋值。即程序通过四条指令把一个64位数值存储到寄存器里。

## 28.4 重定位

我们已经知道ARM64的指令是4字节（汇编）指令。4字节的容量有限，无法封装很大的数据。尽管如此，程序可能会被操作系统加载到内存中的任意地址，就需要基址重定位（relocations/relocs）来修正。有关重定位的详细介绍，见本书的6.2节。

ARM64对ADRP和ADD指令传递64位指针，ADRP指令获取地址所在处（例如main）的4KB页地址，而ADD指令负责存储偏移量的其余部分。在Win32下GCC(Linaro) 4.9编译了“Hello, world!”程序（即第6章的第一个程序），使用objdump工具分析的目标文件。

## 第29章 MIPS的特点

### 29.1 加载常量

```
unsigned int f() {
    return 0x12345678;
};
```

MIPS和ARM平台的指令都是定长指令。MIPS程序的指令都是32位opcode。在MIPS平台上，我们可能无法使用单条指令就完成对32位赋值的操作。此类操作至少分两步进行：首先传递32位的高16位，然后通过ORI向寄存器传递立即的低16位。

指令清单29.1 GCC 4.4.5-03 (assembly output)

```
li $2,305397760 # 0x12340000
j $2,0x052678 ; branch delay slot
```

IDA能够识别此类组合指令。为了方便阅读，它对后面的Ori指令进行了处理：用伪指令Li替换了Ori指令，且用完整的32位替换了值的低16位。

指令清单29.2 GCC 4.4.5-03 (IDA)

```
lui $v0,0x1234
jr $ra
li $v0,0x12345678 ; branch delay slot
```
