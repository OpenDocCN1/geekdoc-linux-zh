
# 第94章 8086的寻址方式

在MS-DOS和Win16（参见本书第73节和35.5节）平台的16位应用程序中，我们可以看到程序指针指向两个16位内存构成。这是什么情况？不得说是MS-DOS和8086的另一个怪异的特性。

虽然8086/8088属于16位CPU，但是它却有20位的RAM地址空间（内存总线有20个引脚），即它可以寻址的存储空间有1MB。这1MB的外部内存空间又被划分为最大640KB的ROM、显内存、EMS卡等等。

16位的8086/8088 CPU实际上发展而来的。8080 CPU的地址空间只有16位，所以可以控制的内存只有64KB。大概是8086的设计哲认为64KB空间不够用，而且8086还要兼容旧平台的程序，所以把1MB的内存划分成若干段使用。这就是早期玩具的虚拟内存的技术。8086的寄存器只有两个16位寄存器，为了进行更大范围（20位）的寻址，它就得借助新出的段寄存器。从此CPU就有CS、DS、ES和SS寄存器。20位的内存指针通过短寄存器和地址寄存器（DS:BX）来实现：

```
real_address = (segment_register << 4) + address_register
```

举例来说，通过PC兼容的主机，但是显卡（EGA、VGA）的显示都只有64KB。要写显存，就要在某个段寄存器里（例如DS）写入0xA000。如此一来，程序就可以DS:0~DS:FFFF访问整个显存。虽然地址总线是20位的，超过了16位寄存器的表达范围，但是PC可以借助段寄存器毫无障碍地访问0xA000~0FFFF。

程序还能直接访问固定的内存地址，例如0x1234，但是操作系统加载程序到起始地址不是固定的。段寄存器的出现，解决了这种问题——它可由段寄存器进行相对寻址，程序不需要关心自己加载到了什么RAM地址。

事实上，MS-DOS系统下的指针由段地址和段内构成，可由两个16位的数值表示。20位指针总线足以满足这种寻址方式的需求。不是，程序员就需要重新计算内存地址了：他们要不停地考虑空间和效率的平衡，仔细规划数据分配情况。

另外，8086的寻址方式决定了每个内存块不能大于64KB。

8086平台仍然继承了段寄存器（segment registers），只是远远不同而已。

在支持更大RAM的80386 CPU时代，市面上流行的仍然是MSDOS。有一批叫DOS extenders的粉丝在Windows系统以后继续坚守DOS阵地。他们甚至开发出了像一样的OS系统。这种系统不仅实现了CPU保护模式的切换功能，而且大幅地改进了内存API，可以继续支持MS-DOS的应用程序。著名的有：DOS/4GW（游戏做DOOM就是面向它编译的）、Phar Lap和PMODE。

在Win32之前，16位的Windows 3.x仍然沿用了这种寻址方式。

## 95.1 PGO的优化方式

PGO是Profile-guided optimization的缩写，中文中有“配置引导的优化”等译法。经PGO方式优化后，程序中的某些基本块（basic block），指的是程序里执行的语句顺序。基本块由第一个语句构成入口，由最后一句语句构成出口。在执行程序时，不可从入口以外进入该基本块（被跳入），也不可从出口以外的地址跳出该基本块。（可能被调整到执行文件的任意位置。

很明显，函数中的程序代码存在执行频率的差异。例如，循环语句类代码的执行频率必然很高，而错误报告、异常处理之类代码的执行频率较低。

在未使用PGO时，编译器首先会生成一个可运行细节的特殊程序。后，研发人员通过运行的手段收集程序的各项统计信息。最后，编译器根据这些统计信息对可执行文件进行调整和优化，把执行率较小的基本块移动到其他地方。

在PGO优化后的程序，频繁执行的函数代码会被调整得更为紧凑。PGO优化了条件跳转的性能，提高了CPU分支预测的准确率。这些特性有助于提升程序性能。
