## 第38章 网络地址计算实例

众所周知，IPv4下的TCP/IP地址由4个数字组成，每个数字都在0~255（十进制）之间。因此IPv4的地址可以表示为4字节数据。4字节数据就是32位的整数。因此IPv4的主机地址、子网掩码和网络地址都可以表示为一个32位的整数。

从使用者的角度来看，子网掩码由4个数字组成，写出来就是255.255.255.0。此类形式的数字。但是网络工程师或者系统管理员更喜欢使用更为紧凑的表示方法，也就是CIDR规范的“/8”、“/16”——类的表示方法。CIDR格式的子网掩码从MSB（最高数位）开始计数，统计子网掩码里面有多少个1并将统计数字转换为10进制数。

这里举一个简单的例子：将子网掩码应用到主机地址，从而计算的网络地址。

```c
#include <stdio.h>
#include <stdint.h>

uint32_t form_IP(uint8_t ip1, uint8_t ip2, uint8_t ip3, uint8_t ip4)
{
    return (ip1<<24) | (ip2<<16) | (ip3<<8) | ip4;
}

void print_as_IP(uint32_t a)
{
    printf("%d.%d.%d.%d\n",
           (a>>24) & 0xFF,
           (a>>16) & 0xFF,
           (a>>8) & 0xFF,
           (a) & 0xFF);
}
```

```c

{

    uint32_t netmask=0;

int main()
{
```

## 计算地址函数calc_network_address()

计算地址函数calc_network_address()实现起来简单：将主机地址和网络掩码进行AND运算，得到的结果就是实际地址。

MSVC采用参数优化：

```asm
_ip1 = 8               ; size = 1
_ip2 = 12              ; size = 1
_ip3 = 16              ; size = 1
_ip4 = 20              ; size = 1
_netmask_bits = 24      ; size = 1
_calc_network_address PROC
    push      edi
    push
    push      DWORD PTR _netmask_bits$[esp]
    call      form_netmask
    push      OFFSET $SG304 ; 'network='
    mov       eax, edi
    call      _print_as_IP
    push      edi
    
    push      OFFSET $SG306 ; 'network address='
    ; ... (省略中间IP计算逻辑)
    push      DWORD PTR _ip4$[esp+16]
    push      DWORD PTR _ip3$[esp+20]
    push      DWORD PTR _ip2$[esp+24]
    push      DWORD PTR _ip1$[esp+28]
    call      form_IP
    and       eax, edi      ; network address = host
    call      _print_as_IP
    add       esp, 36
    pop       edi
    ret
_calc_network_address ENDP
```

在第22行，我们可以看到重要的指令AND，就是计算网络地址，实现了核心功能。

## 函数form_IP()

form_IP()函数将IP的4字节转换为一个32位数值。它的运算如下：

- 给返回值一个变量，并赋值为0。
- 取最低的4字节，与返回值进行OR操作，即可含有第4字节的32位。
- 第3个字节，移8位，生成0x0000bb（其中bb就是第3个字节的数值）。此后与返回值进行OR运算。如果上一步的返回值如果是0x0000aa，执行OR操作后，就会得到0x00aabb。取第二个字节，移16位，生成0x0000含有第二个字节的32位，再进行OR运算。由于上一步的结果是0x00bbaa。
- 取最高位，移24位，生成0xdd0000有一个字节信息的32位，再进行OR运算。由于上一步的结果是0xccbbaa。MSVC进行优化，可以得到下列指令：

指令清单38.2 非优化的MSVC2012实现

```asm
_ip1 = 8      ; size = 1
_ip2 = 12     ; size = 1
_ip3 = 16     ; size = 1
_ip4 = 20     ; size = 1
_form_IP PROC
    push     ebp
    mov      ebp, esp
    movzx    eax, BYTE PTR _ip1$[ebp]
    ; EAX=00000dd
    shl      eax, 24
    movzx    ecx, BYTE PTR _ip2$[ebp]
    ; ECX=00000cc
    shl      ecx, 16
    ; ... (省略后续)
```

操作的顺序不同。当然不会影响最后的运算。在启用优化后，MSVC2012另外一种算法：

指令清单38.3 优化的MSVC2012实现

```asm
_ip1 = 8      ; size = 1
_ip2 = 12     ; size = 1
_ip3 = 16     ; size = 1
_ip4 = 20     ; size = 1
movzx    eax, BYTE PTR _ip1$[esp-4]
; EAX=000000d
movzx    ecx, BYTE PTR _ip2$[esp-4]
; ECX=000000cc
shl      eax, 8
or       eax, ecx
; EAX=0000dd00
movzx    ecx, BYTE PTR _ip3$[esp-4]
; ECX=000000bb
shl      eax, 8
or       eax, ecx
; EAX=00ddcc00
movzx    ecx, BYTE PTR _ip4$[esp-4]
; ECX=000000aa
shl      eax, 8
; EAX=ddccbb00
or       eax, ecx
; EAX=dcccbbaa
pop      ebp
ret
_form_IP ENDP
```

这个过程还可以描述为：每个字节都写入其返回值的最低8比特，并且左移一个字节，将其与返回值进行或操作。重复四次，就能完成功能。就足够了。然而遗憾的是，可能没有其他的办法来实现上述逻辑。正如著者所知，目前的CPU以及ISA还不能把规定比特或字节直接复制到其他类型里。所以一般都是通过位移和OR运算才能把IP地址转换为32数据。
