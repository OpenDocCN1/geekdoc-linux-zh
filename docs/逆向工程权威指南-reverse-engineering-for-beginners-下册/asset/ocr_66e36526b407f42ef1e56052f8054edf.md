```
.text:00000000 10 B

.text:00000002 03 23 MOVS R3, #3
.text:00000004 02 22 MOVS R2, #2
.text:00000006 01 21 MOVS R1, #1
.text:00000008 02 A0 ADR R0, =AADBCCD;="a=%d; b=%d; c=%d"
.text:0000000A F00 FD 8F BL _printf

.text:00000010 10 B POP {R4,PC}
```

这段代码和前面段ARM程序没有太多的差别。

开启优化选项的Keil 6/2013 (ARM模式) + 无返回值

我们对源代码略作修改，删除“return 0”的语句

```
#include <stdio.h>

void main() {
    printf("a=%d; b=%d; c=%d", 1, 2, 3);
n}
```

相应的汇编指令将会显著的差别：

```
.text:00000014 main
.text:00000014 03 30 A0 MOV R3, #3
.text:00000018 02 20 A0 MOV R2, #2
.text:0000001C 01 10 A0 MOV R1, #1
.text:00000020 1E 0F 8F E2 ADR R0, =AADBCCD;="a=%d; b=%d; c=%d\n"
.text:00000024 18 00 EA B _printf
```

在某些优化选项（--03）之后，源代码编译为ARM模式的代码。这次，程序的最后一条指令变成了B指令，不再使用之前的BL指令。另外，与前面没有用过优化选项的例子相比，本例上来说并没有出现POPR0和LR寄存器的函数赋值或函数尾声。这形成了一个显著的差异。B指令仅跳转到另一个地址，不会根据LR寄存器的值进行返回。大体上，它和x86平台的JMP指令非常相似。为什么编译器会如此处理呢？实际上，这些指令与前面（未用优化选项）的运行结果相同。主要原因有两个：
