(2)调用printf() 函数是程序的最后一条指令;调用之后再无其他操作。

即使未使用优化选项，在完成printf()函数的工作之后，程序只是要回到LR寄存器里存储的返回地址而已。LR的值并没有因为调用printf()函数发生变化，且程序也没有调用printf()函数之外的函数。因为没有指令修改LR的值，所以程序不必保存LR的状态。另外，在调用这个函数之后，程序也没有其他操作。而编译器都会进行了相应的优化。

当程序最后的语句是另一个函数时，编译器通常会进行这种优化。

书13.1.1节“指令清单13.2”再次出现了这种优化技术。

\非优化的GCC

指令清单6.8 非优化的GCC (Linaro) 4.9

```
.LCL
.string "a=%d;b=%d;c=%d"
f2:
  ; save FP and LR in stack frame:
  stp x29, x30, [sp, -16]!
  ; set stack frame (FP=SP)
  add x29, sp, 0
  adrp x0, .LCL
  add x0, x0, :lo12:.LCL
  mov w1, 1
  mov w2, 2
  mov w3, 3
  bl printf
  mov w0, 0
  ; restore FP and LR
  ldp x29, x30, [sp], 16
```

第一条(Store Pair)指令将FP(X29)和LR(X30)的值送入内存。第二条“ADD X29, SP, 0”指令创建帧，它只是SP的值复制给X29。

后面的“ADRP/ADD”指令构建了字符串的指针。

在传递给printf()的格式字符串里，%d是32位int型数据。因此，程序使用了寄存器的32位存储之后的数据1、2、3。

即使启用了GCC (Linaro) 4.9的优化选项，它生成的指令与此相同。
