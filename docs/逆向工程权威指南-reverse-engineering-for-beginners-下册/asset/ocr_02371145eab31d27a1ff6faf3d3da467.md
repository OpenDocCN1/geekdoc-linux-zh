```
movzx ecx, BYTE PTR [rbx+rdx]
test cl, cl              ; is it zero? exit then
jeje .L9
cmp cl, 10             ; is it '\n'?
jeje .L12
cmp cl, 13             ; is it '\r'?
jeje .L12
.L9:
    return "s"
    mov rax, rbx
    pop
    ret
```

实现更为复杂的。在循环体执行前的代码只执行一次，而且它还会检查结束是否回车或换行CR/LF。这难道不是多此一举吗？

一般来说，实现主体的流程是这样的：

+   ① 循环开始，检查CR/LF结束，进行判断。

+   ② 保存零字符。

但是，GCC编译器会将这两步逆序执行。因此，第一步肯定不会保存零字符，而是进行下述判断：

+   ① 看看第一个字符是CR/LF，如果不是的话，就会退出。

+   ② 循环开始，保存零字符。

+   ③ 根据检查字符是否为CR/LF决定程序的执行。

这种处理之后，主体就小了很多，更适用于目前的CPU。这种中间的变量是str_len，而是str_len-1。或许是因为后者更适用于作为缓冲区数据的索引符号（嵌套数组）。很明显，GCC注意到了，str_len-1使用了两次。因此最好的办法是分配一个变量，其值总是比目前的字符串的长度小1，然后将其递减（按照变量str_len的递减方式递减）。
