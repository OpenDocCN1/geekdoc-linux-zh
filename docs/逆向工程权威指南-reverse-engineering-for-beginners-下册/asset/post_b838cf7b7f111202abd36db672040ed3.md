# 内容提要

逆向工程是一种分析目标系统的过程，旨在识别系统的各组件以及组件间关系，以便能够通过其他形式或在较高的抽象层次上，重建系统的表征。

本书专注于软件的逆向工程，是写给初学者的一本权威指南。全书分为上、下两册，十二个部分，共102章，涉及X86/X64、ARM/ARM-64、MIPS、Java/JVM等重要内容，详细解析了Oracle RDBMS、Itanium、软件狗、LD_PRELOAD、溢出、ELF、Win32 PE文件格式、x86-64（critical sections, syscalls）、本地存储TLS、地址无关代码（PIC）、以配置文件为引导的优化、C++ STL、OpenMP、SHE等诸多技术问题，称为逆向工程技术百科书。除了详细讲解，本书还给出了许多练习来帮助读者破解领域所学的知识，附录部分给出了许多题的解答。

本书适合对逆向工程技术、操作系统底层技术、程序分析技术感兴趣的读者阅读，也适合专业的开发者人员参考。

# 序 从逆向视角透析大厦的那些砖石

对于这本书的中文名字《逆向工程权威指南》，我更喜欢的英文名为《Reverse Engineering for Beginners》，可以译为“逆向工程入门者必读”。在国外的程序员中，这本书被简称为《RE4B》，作者的Blog连载已经获得了持续关注和口碑。

本书的重要特色在于其清晰的章节结构，涵盖了函数、数据结构、数据组等这些构成逆向大厦的基本元素，如显微镜观察观察对这些元素在X86、ARM和MIPS体系架构下的“切片”影像。本书几乎每个章节都按照作者的来说，这也让读者深入对比三种体系架构下，相同的指令，函数及数据呈现的异异和点。无论对于分析工程师，还是编写工程师来说，本书都能让人深入理解逆向大厦原材料的工程指南。本书是基础性的系统性的文献，更是让人耳目一新的结构安排。对于在中国高等教育教学中，通过简单的X86学习来理解体系的工程师来说，这也足够快速打通ARM、MIPS知识的“安全”指南。对于那些从各种数据程来到逆向的安全爱好者来说，这更是一份“正餐”。对于作者来说，我相信这个过程充满了满足，但也充满了困难和烦恼。对于Dennis这个逆向领域的工程专家来说，这本书的写作过程，更多是在探索未知的领域，而不是对高要求的技巧和经验的总结，而是要看到相对于目标的单元级数据进行处理，将一些对其已经是熟悉的东西转化为逆向而化为理解的语言。

逆向工程被视为一种充满趣味和带有神圣主义的技能，逆向方向的作者看起来有着更多的原因，似乎就是在指令狩猎中逆流而，开启特殊限制和保护，找到目标码中的“宝藏”——错误、漏洞或被加密算法层层掩盖的数据结构。这个由于媒体打造的形状，也为部分逆向爱好者所称的。这也导致了逆向领域的书籍和教材，更多围绕着一些高阶的技巧展现，更多地讲解如何进行加密和保护，忽略了逆向工程的初衷是要紧密系统和软件的整体结构和机制。由于之前的逆向领域相关出版中缺少“代码大全”式的基础教程，本书的完成填充了这一空白。然而，这不仅要求者有高的逆向工程能力，也有助于对系统的思维和视野。

本书的译者之一Archer提出建议邀请安卓的工程师们一同完成本书的翻译，我曾觉得他是太“闲”了。本书并没有完成全部的英文原文，只是Dennis持续发布的博客的系列。尽管连载已经引发了口碑不错，但其精彩章节有时还落在原本的巅峰，尚未达成成就，以Dennis天马行行的章节风格和追求完美主义的他来说，他会在未完成全部章节期间，不断增加体系结构的新点（如ARM64）和修补未完成章节的内容，甚至会改动原有的代码，导致本书彻底通过。我认为与我们培养的Android开发者接触这些章节是一份困难的任务，不能说，Dennis写这本书本身就是一份不可完成的任务。

此后近千页的译稿在我面前，我深深震撼了，那种感觉我之前自己已认为是蹩脚的英语才有了突破。我想Archer是如何像一个旁观者、一个学习者或者作者的；以及与Android的同事们是如何在样本分析和充分的情况下，用时间一点点推动进展的。当我在视频侧向安卓的部门负责人展示章节时，我能看到每个人的期待和兴奋，这种奇异有时于我从自己这里获得了一份最新的博客分析报告。

二次分析，是安全工程师包括了渗透安全领域的编码工程的基础之一。一些安全人士都曾提到一个幽默的话——人的系统安全攻防。中国安全厂商和安全工作者，在系统安全领域和分析工作中，正不断取得新的进展。在国际网络安全领域，华人担任关键系统安全研究和分析工作，国际高校的研究者在新兴领域开展系统安全研究，同样取得了很大的国际影响。遗憾的是，Web和应用开发的引起，引起一定程度让安全人员的目光转向了Web和应用安全，当前的新的安全系统整体的二次分析能力在下降，正面临着基础缺失的问题，非常需要系统性的训练。

二次分析能力，是对安全工程师的基础能力要求。但对于对抗APT等新威胁，仅仅有基本功是不够的，还需要在更开阔的架构视角上具备从攻击链、体系化等角度分析逆向攻击的能力、攻击对手的能力。

当遇到一些破解工程的误导，一旦接触逆向工程的年轻人可能会破解序列号等当成逆向工程的目的，导致其浪费时间，没有真正理解逆向工程的难度。即使是逆向工程师，也往往更易于寻找攻击者的个性技巧。

我们是从“逆向”开始，认识到传统分析工程师面临的困境，后者才是高阶。在“震网”分析中，由国际厂商和分析工程师组成，取得更多的成果。对于安全厂商和APT攻击之间，不是简单的查杀，而是体系化对抗。从认识到这个问题开始，一方面继续加强基本功能；另一方则批判那种逆向工程的视角。

“震网”分析中，由国际知名厂商和分析工程师组成的团队，就能比普通团队进展更快。在“震网”分析中，我们发现了许多逆向工程的细节。从入口点开始，那些攻击者的高级技巧找到“快感”，而忘记了重要的全局性因素。

过去三年间，乌克兰发布了针对APT的报告，遭遇停电等与关键基础设施的安全事件。在乌克兰停电事件中，我们已经初步走出了入口视野。

# 前言

“逆向工程”一个词在软件工程领域的具体含义，人们常说的“逆向工程”按照目标系统的划分分为：
- (1) 软件逆向工程。
- (2) 构建逆向工程。
- (3) 重建逆向工程。
