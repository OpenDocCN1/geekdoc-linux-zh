## 7.5 Debugger: 运行scanf函数之后

全局变量x出现在数据段中。在调试运行PUSH指令之后，变量x的指针被推入栈，我们可以在右侧点击右键的地址选择“Follow in dump”，以及在左侧的内存窗口观察它。

在控制台输入123之后，内存里的字段变成0x7B（左侧窗口的高亮显示）。

您有没有想过，为什么第一个字节是0x7B?考虑字节数时，此处应该是“小端序/LITTLE-ENDIAN”的典型特征。x86系统是低位优先的“小端序”。小端序属于“字节序/endianness”的一种，它的第一个字节是数值最低的字节，数值最高的字节会排列在最后。本章将在第31章详细介绍字节序。

此后，EAX寄存器将存储这个地址的32位值，并将之传递给printf()函数。

本例中，变量x的内存地址是0x00053394。

## 7.2.3 GCC: x86

在汇编指令层面，Linux与Windows的编译结果却不大。它们的区别体现在字段（segment）名称和字段属性上：Linux生成的GCC的未初始化变量出现在bss段，对应的ELF文件描述了这个字段属性。

- Segment type: Uninitialized
- Segment permissions: Read/Write

如果这个变量分配了初始值，比如10，那么这个变量就会出现在_data段，并且具有属性。

- Segment type: Pure data
- Segment permissions: Read/Write

## 7.2.4 MSVC: x64

指令清单7.6 MSVC 2012 x64

```
DATA SEGMENT
COMMON x:DWORD
$SG2924 DB 'Enter X: ', 0AH, 00H
$SG2925 DB '%d', 00H
$SG2926 DB 'You entered %d.. ', 0AH, 00H
_DATA ENDS
```

```
TEXT SEGMENT
main PROC
$LN3:
sub rsp, 40

lea rcx, OFFSET FLAT:$SG2924 ; 'Enter X: '
call
printf
lea rcx, OFFSET FLAT:x
call
lea rcx, OFFSET FLAT:$SG2925 ; '%d'
call
scanf
mov edx, DWORD PTR x
lea rcx, OFFSET FLAT:$SG2926 ; 'You entered %d...'
call
printf

return 0
xor eax, eax
add rsp, 40
ret
ENDP
_TEXT
TEXT ENDS
```

这段64代码与x86的代码没有明显的区别。请注意变量x的传递过程：scanf()函数通过LEA获取地址。
