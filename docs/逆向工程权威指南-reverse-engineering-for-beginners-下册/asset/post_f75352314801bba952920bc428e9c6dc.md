## 6.5 其他

在x86、x64、ARM和MIPS平台上，函数参数的方法相同。这种差异表明，函数参数的方法与CPU并不是密切。为了方便记忆，采用调用约定，MIPS的4~7号寄存器也叫A0-$A7。实际上，程序员完全可以使用$zero之外寄存器传递数据，也可以采取其他的约定。汇编语言的编写者完全采取不同的方法来传递参数。虽然基本都是利用寄存器传递，但是传递参数的顺序并不讲究，甚至可以通过全局变量传递。不过，这样的程序运行取决于full stack和empty stack。

### 7.1 演示案例

```c
#include <stdio.h>

int main() {

    scanf("%d", &x);

    return 0;
}
```

好吧，程序如果大量使用scanf()就不会有什么问题。本文仅用这个函数演示指针的传递过程。

### 7.1.1 指针介绍

在计算机科学中，“指针”属于基础的概念。如果直接向函数传递大量数组、结构体或数据，程序的开销就会很大。毫无疑问，使用指针将降低效率。不使用指针的作用：如果不使用指针，而是由调用函数传递数据组或结构体（同时返回这些数据），那么参数的传递将复杂的。所以，调用函数传递数据组或结构体的地址，让调用函数处理数据，是最简单的做法。

在C/C++的概念中，指针是指描述内存地址的数据。

x86系统使用32位（4字节数据）描述指针；x64系统使用64位（8字节数据）。从数据空间来看，64位的指针比32位的指针增加了一倍。当人们从x86平台开发到x64平台开发的时候，就不难以适应这种变化了。

程序员可以在所有的程序里使用无类型指针一种指针。例如，在C中使用memcpy()函数、在构造函数中复制数据时，程序员完全不需要知道类型，直接用一个void*指针复制数据。这种情况下，地址本身的数据类型并不重要，重要的是存储空间的大小。

指针还广泛用于实现返回值的处理。本书的第10章详细介绍这部分内容。scanf()就可以返回多个值。它不仅分析调用方法传递了多少参数，还能读取多个参数的值。

在C/C++的编译过程中，编译器只在类型检查阶段才会检查指针的类型。在编译器生成的程序里，没有指针类型的任何信息。

### 7.1.2 x86 MSVC

使用MSVC 2010编译上述代码，可以得到下汇编指令:

```asm
CONST    SEGMENT
$SG3381 DB      'Enter X:', 0AH, 00H
$SG3382 DB      '%d', 00H
$SG3383 DB      'You entered %d...', 0AH, 00H
CONST    ENDS
PUBLIC   _main
EXTRN    _scanf:PROC
EXTRN    _printf:PROC

; Function compile flags: /Ot
TEXT     SEGMENT
x$=4          ; size = 4
_main    PROC
               push        ebp
               mov         esp, ebp
               mov         ecx
               push        OFFSET $SG3381 ; 'Enter X: \n
               call        _printf
               add         esp, 4
               lea         eax, DWORD PTR _x$[ebp]
               push        eax
               push        OFFSET $SG3382 ; '%d'
               call        _scanf
               add         esp, 8
               mov         ecx, DWORD PTR _x$[ebp]
               push        ecx
               push        OFFSET $SG3383 ; 'You entered %d...'
               call        _printf
               add         esp, 8
               xor eax, eax
               mov         esp, ebp
               pop         ebp
               ret
_main END
TEXT ENDS
```

C标准要求：函数内部应当可以访问局部变量，外部不能访问局部变量。为了方便记忆，采用调用约定，所有x86平台的编写者都使用这种方法来存储局部变量。在函数运行期间，EBP指向当前的帧（stack frame）。这样通过EBP+offset的方式访问局部变量以及外部参数。ESP的值经常变化，在函数启动之初利用EBP寄存器保存ESP值不变。在32体系里，典型的栈（stack frame）结构所示：

| | |
|---|---|---|
| EBP-8 | 局部变量2 | 标记为var8 |
| EBP-4 | 局部变量1 | 标记为var4 |
| EBP | EBP的值 | |
| EBP+4 | 返回地址 | |
| EBP+8 | 参数1 | 标记为arg0 |
| EBP+C | 参数2 | 标记为arg4 |
| EBP+10 | 参数3 | 标记为arg8 |

本例中的scanf(x)有两个参数。第一个参数是一个指针，指向含有%d”的格式字符串。第二个参数是局部变量x的地址。首先，“lea eax, DWORD PTR x$[ebp]”指令将x的地址放入EAX寄存器。“lea”是load effect的缩写，能够将源的有效地址（offset）传递给第一个参数。此处，将EAX寄存器的值与x求值，然后使用EAX寄存器存储计算结果；等于lea eax, [ebp-4]。程序会对EAX寄存器的值减去x并把这个结果存储到EAX寄存器。将EAX寄存器的值推入栈内存后，程序开始调用scanf(x)函数。在调用printf()函数之前，程序传给它第一个参数，即格式字符串“You entered %d...\n”指针。printf(x)所需的第二个参数通过“mov ecx, [ebp-4]”间接取值。ecx的值是ebp-4指向的值（x的值），而不是ebp-4表达的地址。此后的指令将ecx推入栈内存，然后启动printf(x)函数。
