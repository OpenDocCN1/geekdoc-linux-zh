首条指令MOV R3, R0属于冗余指令。即使此处有这条指令，后面的MLA指令直接复用有的的寄存器也不会出现任何问题。因为我们没有启用优化选项，所以编译器对没有进行优化。

BL指令程序的控制流将LR寄存器的地址，而且在必要的时候切换处理器的运行模式（Thumb模式和ARM模式之间进行模式切换）。被调用函数f并不知道它会被切换成什么模式的代码，不知道调用函数切换的功能还是必要的。如果它被成了Thumb模式的代码，BX指令将进行跳转，还会把处理器调整为Thumb。如果它被成了ARM模式的指令[4]调用，就不会进行模式切换。

# 8.3.2 Optimizing GCC (1/3) ARM

```
:00000098 f
:00000098 21 20 20 E0 MLA R0, R1, R2
:0000009C 1E FF 2F E0 BX LR
```

在启用最大限制的优化函数（-O3）之后，前面那条MOV指令被优化了，或者被删除了。MLA直接复用所有寄存器的参数，并将返回值保存在R0寄存器里。调用函数函数而从R0寄存器获取取值。

# 8.3.3 Optimizing GCC (1/3) Thumb mode

```
:0000005E 48 43 MULS R0, R1
:00000060 80 18 ADDS R0, R1, R2
:00000062 70 47 BX LR
```

因为Thumb模式的指令集里没有MLA指令，所以编译器将其分为两个指令。第一条MULS指令计算R0和R1的积，将运算结果存储在R0寄存器里。第二条ADDDS计算R1ROR2的，并且计算结果存储在R0寄存器里。

# 8.3.4 ARM64

Optimizing GCC (Linaro) 4/9

ARM64的情况简单一些。MADD指令可以一次进行乘法和加法的混合运算，与此前的MLA指令类似。全部3个参数都用X-头的寄存器的低32传递。这是因为这些参数都是32位整数型。函数的返回值存储在W0寄存器。

```
f:
	mtmadd w0, w0, w1, w2
main:
	ret
```
