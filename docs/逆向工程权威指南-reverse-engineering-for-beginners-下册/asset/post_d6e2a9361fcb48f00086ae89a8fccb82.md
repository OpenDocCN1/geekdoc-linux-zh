
最后一条LE指令，等于“MOV ESP, EBP”和“POP EBP”两条指令。可见，这个指令之前调整了数据取指针，将EBP的数值恢复到调用这个函数的初始状态。毕竟，程序在开始部分对EBP和EBP进行了操作（MOV EBP, ESP/AND ESP, ...），所以函数要在退出之前恢复这些寄存器的值。

在上述代码里，由小数点开头的指令就是宏。这种形式的汇编语大量使用汇编宏，可读性较差。为了演示，我们将中字符以外的宏忽略（也可以启用GCC的编译选项-fno-asynchronous-unwind-tables，直接忽略为没有cfi的汇编指令），将会得到如下指令：

# 指令列表3.6 GCC 4.7.3生成的指令

```
pushl %ebp

subl $16, %esp
mov $.LC0, (%esp)
call printf
mov $0, %eax
leave
ret
```

在继续读这个代码之前，我们先介绍一下Intel语言和AT&T语言的区别：

- * 运算符表达式（operands，即运算符单元）的书写顺序相反。
- Intel 格式：<指令><目标>。
- AT&T 格式：<指令><源><目标>。
- 如果您认为Intel语言的指令使用等号（=）是赋值，那么您可以认为AT&T语法结构使用右箭头（→）进行赋值。应当说明的是，这两种格式里，部分标准函数的运算符单元的书写格式确实是相同的，例如memcpy(), strcpy()。
- AT&T语言中，在寄存器名称之前使用百分号（%）标记，在立即数之前使用美元符号（$）标记。AT&T语言使用圆号，而Intel语言则使用方号。
- AT&T语言里，每个运算符操作都需要声明数据的类型：

- ○ q-quad(64位)
- ○ l指代32位long型数据。
- ○ w指代16位word型数据。
- ○ b指代8byte数据。
- ○ 其他区别参考公司发布的x86 Assembly Manual。

现在再来说hello world的AT&T语言，就会发现它和IDA看到的没有区别。有些人可能注意到，用于数据对齐的按照32型数据进行写入后，就会发现两者一致。此外，在main()时，处理EAX寄存器的指令是MOV而不是XOR指令。某些硬件框架有更为直观的“LOAD”、“STORE”指令。

## 3.2 x86-64

### 3.2.1 MSVC-x86-64

若用64位MSVC编译程序，则得到如下指令。

指令清单3.7 MSVC生成的汇编指令

```
main PROC
    push   rbp
    mov    rbp, esp
    sub    rsp, 40h
    lea    rcx, OFFSET :LC0
    call   printf
    xor    eax, eax
    add    rsp, 40h
    pop    rbp
    ret
main ENDP
```

在x86-64框架的CPU上，所有的寄存器都被扩展为64位寄存器。为了尽可能利用寄存器减少内存访问次数，编译器会利用寄存器传递参数（参见64.节）。也就是说，编译器会选用寄存器传递剩余的参数。Win64程序使用RCX、RDX、R8、R9这6个寄存器传递参数。稍后看到这种情况：printf()使用RCX传递参数，而像32位程序那样使用栈传递。在x86-64平台上，寄存器和指针都是64位的。为了兼容性，64位寄存器的低32位充当32位。

### 3.2.2 GCC-x86-64

我们使用64位Linux的GCC编译上述程序，可以如下所示的指令。

指令清单3.8 GCC生成的汇编指令

```
.LC0:
.string "hello, world\n"
main:
    pushq %ebp
    movq  %esp,%ebp
    subq  $16,%esp
    leaq  .LC0(%rbp),%di  # 注意：此处原文应为di
    movl  $-16,%esp
    subl  $16,%esp
    movl  (%esp),edi
    call  printf
    movl  $0,%eax
    leave
    ret
```

在x86-64兼容的CPU中，RAX/EAX/AL的关系如下：

| 7th(字符) | 6th | 5th | 4th | 3rd | 2nd | 1st |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| RAX | | | | | | |
| EAX | | | | | | |

main()函数的返回值是整数，但是出于兼容性的考虑，编译器仍然使用32位的零。然而，即使是64位的应用程序，在程序结束时EAX的值是零，而RAX的值一定会零。此时，数据栈对应空间里留有40字节的数据。这部分空间有一个专用的名词，即shadow space。本书将在8.2节详细介绍。

## 3.3 GCC的其他特性

只要C语言里使用了字符常量（参照3.1节），编译器就会把这个字符串置于常量区，以保证内容不会变化。不过GCC有一个有趣的特征：它可能会把字符串分开使用。我们来看这段程序：

```c
#include <stdio.h>
void f1() {
    printf("world\n");
}
void f2() {
    printf("hello world\n");
}
int main() {
    f1();
    f2();
}
```

多数的C/C++编译器（包括MSVC编译器）会分配两个对应的字符串，不过GCC 4.8.1编译结果更为可见。指令3.10 在IDA中观察GCC 4.8.1汇编

```
proc near
    push   rbp
    mov    rbp, esp
    sub    esp, 1Ch
    lea    rcx, OFFSET :LC0
    call   printf
    add    esp, 1Ch
    pop    rbp
    ret

proc near
    push   rbp
    mov    rbp, esp
    sub    esp, 1Ch
    lea    rdx, OFFSET :LC0
    call   printf
    add    esp, 1Ch
    pop    rbp
    ret
```

在打印"hello world"的时候，这两个指针的地址实际上是相邻的。在调用的puts函数输出时，函数本身不知道输出字符串分为两个部分。实际上我们在编译清单中可以看到这两个字符串并没有被分开。在f1()调用puts函数时，它输出字符串“world”和前面的字符串（数值为零），由于puts函数不知道字符串可以连起来形成最终的字符串，编译器这种技术来节省内存。

### 3.4.1 Keil未启用优化功能的ARM模式

使用下述指令编译ARM架构的汇编：

```
armcc.exe --arm -c -o0 hello.c
```

虽然armcc编译器生成的汇编采用了Intel语体，但程序所具有ARM处理器的特性。我们来看它的细节：

指令清单.1 使用IDA观察Non-optimizing Keil (ARM模式)

```
.text:00000000          main
.text:00000000 402D E9      STMFD SP,{R4,LR}
.text:00000004 1E8F E2      ADR     R0,aHelloWorld;hello,
.text:00000008 1519 E8      BL      printf
.text:0000000C 00A0 E3      MOV     R0,#0
.text:00000010 108E ED      LDMFD SP,{R4,PC}
.text:00000014 6665 6C      DCB     "hello,world",0
; DATA XREF: main+4
```

在本例中，每条指令都占用4个字符。正如您看到的，确实要把程序编译为ARM模式，而不是把它编译为Thumb模式。回到代码，第一句“SP!, {R,LR}”相当于x86的PUSH指令。它把寄存器和LR（Link Register）寄存器的数值推放到栈中。此处，差异是“相对于”，而非“完全是”。因为ARM模式的指令集没有PUSH指令，只有Thumb模式的指令集才有PUSH/POP。在IDA中可以清楚地看到这种差别，推荐使用IDA分析。STMFD指令能够存储多个寄存器的值，Thumb模式的指令也可以这样使用。实际上x86指令中并没有这样的指令。STMFD指令看作是增强版本的PUSH指令，它不仅能够存储SP的值，能够存储任何寄存器的值。换句话说，STMFD可用于指定的内存空间存储多个寄存值的指令是“ADR R0,aHelloWorld”。

接来的操作，它首先对PC进行取值操作，然后把“hello, world”字符串的偏移量（可能为负值）与PC相加，将其结果存储到R0中。有些读者可能明白此处PC寄存器的作用。严谨地说，编译器通常帮助PC来某些指令强制修改为“位置无关代码/position-independent code”。在（许多）操作系统程序加载在内存中时，OS配给程序代码的内存地址是不固定的；但是程序内部定义的指令地址和偏移量是固定的（由二进制程序文件决定）。这种情况下，要在程序内部进行指令寻址（例如跳转等情况），就需要借助PC指针。ADR将当前指令的地址与字符串指针的地址（偏移量）传递给LR。程序借助PC指针找到字符串指针的偏移量，从而操作系统确定字符串变量在内存中的绝对地址。

“BL printf”调用printf函数。

实例上：

- 将一条指令的地址，即地址0xCF“MOV R0, #0”的地址，写入LR寄存器。
- 然后将printf()函数的地址写入PC寄存器，以引导系统执行该函数。

当printf()完成后，计算机就需要知道返回地址，它应当从哪里开始继续执行下一条指令。所以，每次执行BL命令调用其他函数之前，都要把BL命令的下一个指令的地址存储到LR寄存器。
