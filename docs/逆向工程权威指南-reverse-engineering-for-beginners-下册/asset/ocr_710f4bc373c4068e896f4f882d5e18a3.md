替代器其实指向节点的指针，而list.begin()和list.end()分
别返回/节点的指针的值。

```
node at .begin:
ptr=0x000349a0_Next=0x00028fe90_x=3 y=4
node at .end:
ptr=0x00028fe90_Next=0x000349a0_Prev=0x00034b40_x=5 y=6
```

事实上，最后一个节点的Next指针指向第一个节点，而一个元素的
Prev指针指向的是最后一个元素。因此我们很容易想到这就是一个循环
链表。

所以，可以利用第一个节点的指针（即本文的实例1）顺藤摸瓜找到
序列的最后一个节点，而不必遍历整个链表。利用这种结构，我们还可以毫不不费
力的链尾之后插入其他节点。

算符“++”和“--”就是替代器的值为[当前节点->prev]或
[当前节点->next]的值。反向迭代器（reverse iterators, rbegin
and rend）的作用与它们相似，只是方向相反。

算符“*”用于返回节点结构的指针，即自定义的数据结构
的起始，，函数就是指向节点项数据（例中是x）的指针。

在链表里插入和删除节点时，我们只需要分配（或释放）节点的存储空
内存，然后更新相关的链域指针，即可保证整个链表的有效性。

在删除节点之后，相邻节点的替代器（链域）可能会指向被删除的无
效节点，此时替代器就会失效。指向无效节点的替代器又叫“逸逸指针”
和“悬空指针”（dangling pointer）。这种指针就不能再使用了。

在GCC（4.8.1版本）编译std::list的实例，它不会存储链的节
总数。这意味着内置函数size()的运行速度十分缓慢，因为它必须遍历
完整链表才能返回节点个数。因此，那些与节点总数有关所有的函数
例如(n)的时间开销和链表性能接近底层。
