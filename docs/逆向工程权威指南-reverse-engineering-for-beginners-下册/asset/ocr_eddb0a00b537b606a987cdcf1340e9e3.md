几坐尘不变。也就是说，shellcode可以根据基础信息直接调用系统函数。

为了避免这个问题，地址空间的随机化ASLR技术应运而生。它能够将程序以及
所需模块加载到无法确定的随机地址。

在PE文件中，我们通过设置一个标识来实现ASLR。这个标识的名称是 IMAGE_DLL_
CHARACTERISTICS_DYNAMIC_BASE。

# 68.2.3 子系统

PE文件中有一个系统字段。这个字段的内容通常有下列之一：

+   - NATIVE（系统驱动程序）

+   - console控制台程序。

+   - GUI（非控制台程序，它就是最常见的图形界面程序）。

# 68.2.4 操作系统版本

PE文件指定了可加载的Windows操作系统最低版本号。如需版本号和
Windows发行名称的完整列表，请参阅：
https://en.wikipedia.org/wiki/Windows_NT_Releases

举个例子，MSVC 2005编译的exe文件只能运行在Windows NT4（版本号为4.00）以及
以后的操作系统。但是MSVC 2008编译调整应用程序（版本号为5.00）不兼容NT4系统，
只能运行在Windows 2000以及之后的操作系统。

在2012年生成的exe文件，操作系统版本号的默认值为6.00。这个程序仅
向Windows Vista及后期推出的操作系统。我们可以通过选项强制编译器生成支持
Windows XP的应用程序。请参阅
https://blogs.microsoft.com/vcblog/2012/10/08/windows-xp-targeting-
with-c-visual-studio-2012/

# 68.2.5 段

所有的可执行文件都可分为若干（sections）。段是代码、数据、以及常量
其他数据的组织形式。

+   - 带有IMAGE_SECTION_CNT_CODE或IMAGE_MEM_EXECUTE的段，封装的是可执行代码。
