当操作系统的加载器需要这个模块加载到不同的基址时，它会遇到一张重位表中所所有基址，这些基址所指向的数据作为模块的地址指针，减去初始基址（这样就能获得RVA，也就是相对虚拟基址），并加上新的基址。

如果模块被加载到它的原始基址上，那么操作系统就不会进行重定向处理。

所有全局变量的处理过程都是如此。

重定向的数据结构并不唯一，- Windows for x86程序的重定向一般采用IMAGE_REL_HIGHLOW的数据结构。

# 68.2.7 导出和导入

我们知道，任何执行文件都必须或或少地调用由操作系统的提供者或者DLL动态库。

广泛地，由于某个模块（来说是DLL）声明的所有函数，最终会被其他模块（.exe文件或其他的DLL）的指令来调用，只是调用方式不同而已。

为此，每一个DLL动态库文件都有“导出/exports”表。导出表声明了该模块的函数名称和基址。

同时每一个exe和DLL文件还有一个“导入”表。这个表声明了执行该模块所需的函数名称、以及对应的DLL的文件。
在加载可执行文件主体的之后，接着在DLL的导出列表中查找所需的函数地址，最后把这些地址写到，模块的IAT中。

由此可见，操作系统的加载器的进程过程中要对比大量的函数名称。但是字符串搜索的效率不会太高。后来又引入了“排序”或“命中”（对应相关数据结构的Hints或Ordinal表）的导出符号表示法，把函数名称排列为排序，以此解决脱序操作的效率问题。

因此，DLL只需要在导出表里标注函数的函数“序号”。这显著提升了DLL文件的加载速度。

举例来说，调用MFC的程序就能通过“序号”调用mfc;DLL动态链接。而这种程序就不需要导入的数据表（Import Name Table, INT）中使用字符串存储MFC函数名称。

我们在我们在中加载这样的程序后，IDA会查询mfc.dll的路径以获取外部函数函数名称。如果我们没有指定MFC的存储路径，那么函数名称就是mfc80_123之类的字符串。
