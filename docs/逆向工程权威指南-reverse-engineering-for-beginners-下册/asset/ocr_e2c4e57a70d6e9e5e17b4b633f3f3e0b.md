```
var_20      = dword  ptr -20h

push        ebp
mov         ebp, esp
and         esp, 0xFFFFFF0h
push        ebx
mov         ebx, 2 ; i=2
sub         esp, LCh
```

```
; aligning label loc_80484D0 (loop body begin) by 16-byte border:
op
loc_80484D0:
; pass (i) as first argument to printing_function():
mov         [esp+20h+var_20], ebx
add         ebx, 1 ; i++
call        printing_function
mp          ebx, 64; i=100?
nz         short loc_80484D0 ; if not, continue
add         esp, LCh
xor         eax, eax ; return 0
pop         ebx
mov         esp, ebp
retn
```

这就与MSVC 2010 /0x编译出来的代码差异不多。唯一的区别是，GCC用EBX寄存器当变量的专用寄存器。因为GCC能够判断后面的函数调用函数不会修改这个专用寄存器的值，所以它才会这样分配寄存器。在GCC不能进行相应调整，但是当决定局部变量分配专用寄存器的时候，它就会使用局部变量的那个函数序言和尾部分别添加相应指令，利用数据保存和恢复专用寄存器的原始值。我们可以在main()函数里看到这种现象：它在函数的序言和尾部分别存储和恢复局部变量专用寄存器ebx的原始值。
