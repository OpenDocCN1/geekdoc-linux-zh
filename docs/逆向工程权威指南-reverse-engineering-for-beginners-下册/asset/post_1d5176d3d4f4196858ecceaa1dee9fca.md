
为什么说是它是加密文件而非压缩文件呢？我们可以看到数值为0x1A的字节（右箭头字符）多次出现，而压缩文件则不会发生这种情况。我们还看到了大量拉丁字符的片段，只是这些字符串不可自然解释。

因为文件多次出现了0x1A，所以我们按照加密文件进行处理，并且假设该文件是经异或/XOR加密的密。我们可以在Hiew里清楚地看到，当使用0x1A对每个字节进行异或或运算时，文件里出现了亲切的英语文字。如图84.2所示。

84.2 Hiew XORing with 0x1A

对每个字符进行XOR运算是一种初级的加密方法。不要因为它简单就想不起这种分析方法，实际的分析工作中就会频繁遇到这种技术。

现在，我们大致理解了0x1A出现很多的原因。在进行异或运算后，数值为0的字符变为0x1A的密文。应当注意：加密会导致文件增大。在解密时，我们应当尝试0~255之间的数字，再分析一下文件变成什么样子。有关Norton的文件格式，请参见：http://www.dave.org/norton-guides/file-format/

在加密领域，信息熵（entropy）属于重要的指标。它有一个特性：加密后的明文和密文，其信息熵不变。本节将介绍使用Wolfram Mathematica 10来计算熵的方法。

```
In[1]= input = BinaryReadList["X86.NG"];
In[2]= decrypt[]
Out[2]=52724
In[3]= decrypted = Map[BitXor[#, input] &, input];
In[4]= Export["X86_decrypted.NG", decrypted, "Binary"]
Out[5]=52724
In[6]= Entropy[2, "Shakespeonnets"]
Out[6]=42366
```

上述指令分别用于加载文件、计算熵、解密、保存明文熵。我们选取了莎士比亚的十四行诗进行分析，其信息熵与一个句子相同。对英文进行字符XOR加密之后，其信息熵与原文相同。但是，如果加密单元大于字符，那么信息熵就是另一种情况。本节分析的英文原文可在下载：http://beginners.re/norton_guide/X86/

Wolfram Mathematica 计算的精确指数为基数，而UNIX工具以2为基数，使得指定“2为基数”的结果相同。即使XOR算法采用多字节密钥，例如4字节密钥，方法也没有。本节以Windows Server 2008的Kernel32.dll为例，源文件所示。

通过观察文件，就可以看到一组循环出现的字符串。实际上并不困难，因为PE文件头包含了大量的零。
