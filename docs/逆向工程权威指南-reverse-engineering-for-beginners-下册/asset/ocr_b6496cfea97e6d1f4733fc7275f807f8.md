在使用IN读取数据时，返回值必须写到AL寄存器里，所以后面出现数据交换指令xchg。

# 83.1.2 笔者对Trixter算法的改进：27位字符

这个程序并没有使用计时器查询确切时间，而是用它来生成伪随机数。因此，我们没有必要屏蔽中断，我们只需要返回的低8位数据即可。

笔者对Trixter程序稍作修改，把它改为27位字符的程序：

```
00000000 mov  cx,07D0 ; limit output to 2000 characters
00000003 31CO xor ax,ax ; command to timer chip
00000005 E643 out  043,al
00000007 E440 in    al,040 ; read 8-bit of timer
00000009 D1EB shr   ax,1 ; get second bit to CF flag
0000000B D1EB shr   ax,1
0000000D B05C mov  al,05C ; prepare '\'
0000000F 7202 jc   00000013
00000011 B02F mov  al,02F ; prepare '/'
; output character to register
00000013 B40E mov  ah,00E
00000015 CD10 int   010
00000017 E2EA loop 00000000
; exit to DOS
00000019 CD20 int   020
```

# 83.1.3 从内存地址读取随机数

MS-DOS系统完全没有内存保护机制的概念。换句话，应用程序可以任意访问内存数据。不仅如此，在使用LDSB从DS:读取字节数据的时刻，即使程序没有预先设置寄存器值也没有问题——它会从任意地址读取一个字符;

> Trixter甚至在网页里[3]推荐初始化相关寄存器就直接使用LDSB指令。

原文建议使用SCASB替代LDSB指令，因为者可以在读取数据的同时，根据数据直接设置标识位。

此外，使用DOS系统的syscall INT 29h还能对程序进行一步精简。这个技巧可以在屏幕上输出AL寄存器的字符。
