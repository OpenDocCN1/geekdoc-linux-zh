# 1.1 指令集架构

在x86的指令集架构（ISA）里，opcode（汇编指令对应的机器码）的长度不相同。为了兼容性的考虑，后来来的64位CPU指令集架构并没有大动干戈地弃原有指令集架构。很多早期16位8086 CPU的指令，不仅被x86指令继承，而且被当作最新的CPU指令集继续沿用。

ARM作为RISC[1] CPU，它的指令集在设计之初就力保持了opcode的一致。在过去，这一特性的表现出了它的优越性。最初的时候，所有ARM指令的机器码都被封装在4个字里[2]。人们把这种运行模式称为“ARM模式”

后，他们就发现这种模式并不打算。在实际的程序中，大多数CPU指令[3]很少用4个字。所以他们又推出了一种把每条指令封装在2个字里的“Thumb”模式的指令集架构。人们把用这种指令集编码的指令叫做“Thumb模式”。然而Thumb指令并不能够所有ARM的指令，它本身封装在指令的边界。当，在一个程序里可以同时存在在ARM模式和Thumb模式两种模式之间

之后，ARM的创造者们决定决定Thumb指令。他们ARM v7就开始了Thumb-2指令。Thumb-2模式被封装在2个字的机器码中，2个字封装下的指令由4个字封装。现在，很多人还误认为是“Thumb-2指令是ARM指令和Thumb指令的复合体”。实际上，它是一种充分处理器性能、与ARM模式媲美的独立的模式。在扩展了Thumb模式的指令集之后，Thumb-2现在和ARM模式互相上下。由Xcode编译器默认采用Thumb-2指令编译，现在主流的iPhone/iPad应用程序都使用了Thumb-2指令。

64位的ARM处理器连接到它。这种CPU的指令集架构再次使用固定长度的4字节opcode，对指令集不支持Thumb模式的指令。相应的，64位的ARM工作为了自己的。受到指令集架构的影响，ARM指令集分为三类：ARM模式指令集、Thumb模式指令集（包括Thumb-2）和ARM64的指令集。虽然这些指令集之间存在千差万别的联系，需要强调的是：不
