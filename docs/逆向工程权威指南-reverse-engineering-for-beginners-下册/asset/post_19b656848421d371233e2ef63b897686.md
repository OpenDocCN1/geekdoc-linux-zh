
## A. 6.4 FPU指令

FPU指令有很多“-R”或“-P”后缀的派生指令。带有R后的指令与常规指令相反，其操作数的排列顺序与常规指令相反。带有P后的指令的，在运行计算后，会从内存里抛出一个数据；带有PP后的指令则从内存抛出两个数据。P/PP后的指令可在计算释放后内存存储的计算因子。

- FABS：计算ST(0)绝对值的指令。ST(0)=abs(ST(0))。
- FADD op：单因子加法运算指令。ST(0)=ST(0)+op。
- FADD ST (0), ST (i) ：加法运算指令。ST(0)=ST(0)+ST(i)。
- FADDP ST (1) ：相当于ST(1)=ST(0)+ST(1)；求和之后，再从内存里抛出一个因子。即，使用计算求得的“和”替换计算因子。
- FCHS：减法运算指令。ST(0)=-1ST(0)。
- FCOM：比较ST(0) 和 ST(1)。
- FCOM op：比较ST(0) 和 op。
- FCOMP：比较ST(0) 和 ST(1)；然后执行1次出栈操作。
- FCOMPP：比较ST(0) 和 ST(1)；然后执行2次出栈操作。
- FDIV op：ST(0)=op/ST(0)。
- FDIV ST (i), ST (j) ：ST(i)=ST(j)/ST(i)。
- FDIVRP op：ST(0)=op/ST(0)，然后执行1次出栈操作。
- FDIVRP ST (i), ST (j) ：ST(i)=ST(j)/ST(i)，然后执行2次出栈操作。
- FDIV op：ST(0)=ST(0)/op。
- FDIV ST (i), ST (j) ：ST(i)=ST(j)/ST(j)。
- FDIVP op：ST(1)=ST(0)/ST(1)，然后执行1次出栈操作。即，被除数替换为商。
- FILD op: 将整数转化为长精度数据，并存入ST (0)的指令。
- FIST op: 将 st (0)以整数保存到op。
- FISTP op: 将 st (0)以整数保存到op，再从栈里抛出ST (0)。
- FLD1: 把1推入栈。
- FLDCW op: 从16位的操作里提取FPU控制字（参见附录A.3）。
- FLD op: 把op推入栈。
- FMUL op: ST(0)=ST(0)*op。
- FMUL ST (i), ST (j) : ST(i)=ST(i)*ST(j)。
- FMULP op: ST(0)=ST(0)*op; 然后执行1次出栈操作。
- FMULP ST (i), ST (j) : ST(i)=ST(i)*ST(j); 然后执行1次出栈操作。
- FSINCOS: 一次计算Sin和Cosine结果的指令。

调用指令时，ST (0)存储角度参数tmp。ST(0)=sin(tmp); PUSH ST(0) (即ST1存储Sin值); 之后再次计算ST(0)=cos(tmp)。

- FSQRT: ST(0)=√ST(0)。
- FSTCW op: 检查尚未处理的、未被屏蔽的浮点异常，再将FPU的控制字（参见附录A.3）保存到op。
- FNSTCW op: 将FPU的控制字（参见附录A.3）直接保存到op。
- FSTSW op: 检查尚未处理的、未被屏蔽的浮点异常，再将状态字（参见附录A.3）保存到op。
- FNSTSW op: 将状态字（参见附录A.3）直接保存到op。
- FST op: 保存实数ST(0)到op。
- FSTP op: 将ST(0)复制op，然后执行1次出栈操作 (ST(0))。
- FSUBR op: ST(0)=op-ST(0)。
- FSUBR ST (0), ST (i) : ST(0)=ST(i)-ST(0)。
- FSUBRP: ST(1)=ST(0)-ST(1),然后执行1次出栈操作。即被减数替换为差。
- FSUB op: ST(0)=ST(0)-op。
- FSUB ST (0), ST (i) : ST(0)=ST(0)-ST(i)。
- FSUSBP ST (1) : ST(1)=ST(1)-ST(0)。
- FUCOM ST (i) : 比较ST (0) 和 ST (i)。
- FUCOM: 比较ST (0) 和 ST (1)。
- FUCOMP: 比较ST (0) 和 ST (1),然后执行1次出栈操作。
- FUCOMPP: 比较ST (0) 和 ST (1),然后从栈里抽出2个数据。

上述两个指令与FCOM的功能相似，但是它们在处理QNaN型数据时不会报错，仅在处理NaN时进行异常汇报。

- FXCH ST (i) : 交换ST (0) 和 ST (i) 的数据。
- FXCH: 交换ST (0) 和 ST (1) 的数据。

### B.1 术语

初代ARM处理器就是32位CPU。所以它的word型数据都是32位数据。这方面它和x86有所不同。

## B.2 版本差异

- ARMv4: 开始支持Thumb模式。
- ARMv6: 用于第一代iPhone、Samsung Galaxy S（支持Thumb-2）。

- word 32位数据。声明word数组和变量是DCD。
- doubleword 64位数据。
- quadword 128位数据。

## B.2 版本差异

- ARMv4: 开始支持Thumb模式。
- ARMv6: 用于第一代iPhone、Samsung Galaxy S（支持Thumb-2）。
- ARMv7: 实现了Thumb-2。用于iPhone 4（Cortex-A8）、iPad 2（Cortex-A9）以及新的指令。
- ARMv8: 64位CPU，叫做Arch64。64位平台不支持Thumb模式，只有指令。

## B.3 32位ARM (Arch32)

### B.3.1 通用寄存器

- R1~R12. 通用寄存器GPRs。
- R13. SP (Stack Pointer/栈指针)。
- R14. LR (link register/链接寄存器)。
- R15. PC (程序计数器)。

R0~R3称为临时寄存器（scratch registers）。它们用于传递参数；在函数结束时，需要恢复。

### B.3.2 程序状态器/CPSR

CPSR的全称是Current Status Register，其规格如下：

| 位序 | 描述 |
| :--- | :--- |
| 0~4 | M—处理器控制位 |
| 5 | T—Thumb模式位 |
| 6 | F—FIQ禁止位 |
| 7 | I—IRQ/中断位 |
| 8 | A—imprecise data abort |
| 9 | E—数据状态位 |
| 10..15, 25, 26 | IT—if-then状态位 |
| 16..19 | GE—greater-than-or-to |
| 20..23 | DNM—Do Not Modify |
| 24 | J—state |
| 27 | Q—sticky overflow（各个独立溢出）标识位 |
| 28 | V—Overflow溢出标识位
| 29 | C—进位/借位/扩展位 |
| 30 | Z—零标识位 |
| 31 | N—负位/小于位 |

### B.3.3 VFP（浮点）和NEON寄存器

| 0~31bits | 32~64 | 65~96 | 97~127 |
| :--- | :--- | :--- | :--- |
| Q0128bits | | | |
| S0~32bits | S1 | S2 | S3 |

S寄存器为32位寄存器，用于存储单精度数。

D寄存器64位寄存器，用于存储双精度数。

D寄存器和S寄存器的存储地址相通。程序可以通过S寄存器的辅助访问D寄存器的数据。虽然这种操作毫无意义，但是可行。

与之相似的是，NEON的Q寄存器是128位寄存器，与其他浮点寄存器共用CPU的物理存储空间。

VFP里有32S寄存器，即S31。VFP2里新增了16D寄存器，实际上这些D寄存器使用的是S0~S31的存储空间。

后来，VFPv3 (NEON或者叫做“Advanced SIMD”）再次添加了16D寄存器，形成了D0~D31。这几个新增的寄存器，即D16~D31寄存器的存储空间，终于和S寄存器的存储空间相互独立。

NEON或Advanced SIMD也有16个128位Q寄存器，它们使用的是D寄存器（D0~D31）的存储空间。

## B.4 64位ARM (AArch64)

### 通用寄存器

64位ARM的寄存器总数，是32位ARM的两倍之多。

- X0. 用于传递函数计算结果。
- X0~X7. 传递函数参数。
- X8.
- X9~X15. 临时寄存器，供被调用函数使用，函数退出时无需恢复。
- X16.
- X17.
- X19~X29. 被调用函数使用的寄存器，在函数退出时需要恢复原值。
- X29. 用作指针/FP（至少GCC把它当作FP）。
