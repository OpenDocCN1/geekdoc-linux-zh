它比MSVC优化生成的程序还要短。值得注意的是，它直接使用了EAX寄存器的部分空间——EAX寄存器的第8到第15节（第1个字符），即AH寄存器。

| 7th (字节号) | 6th | 5th | 4th | 3rd | 2nd | 1st | 0th |
|---|---|---|---|---|---|---|---|n| RAX x64 | | | | | | |
| | | | | | EAX | |
| | | | | | AX | |
| | | | | AH | AL |

在早期的16位8086 CPU里，AX寄存器分为两个AX寄存器——即AL/AH寄存器。而80386并不把所有的寄存器都扩展为32位，但是为了兼容性的考虑，后续的CPU保留了AH/AL寄存器的命名。

世世界上16位的8086 CPU，有了32位的x86 CPU。在早期16位CPU上运行短程序，其opcode在32位CPU上运行的opcode要短。所以，操作AH寄存器的“or ah, 40h”的指令只占用了3字节的opcode。似乎使用“or eax, 0400h”这样的指令更符合合理，但是就会占用5字节的opcode；如果第一个字节不是AX寄存器，同样的指令甚至会使用6字节的opcode。

# Optimizing GCC and regparam

如果同时开启优化选项“-03”和寄存器分配选项“regparam=3”，生成的指令会更短。

# 指令19.14 Optimizing GCC

```
public f
proc near
push ebp
or ah, 40h
mov eax, esp
and ah, 0FDh
pop ebp
retn
endp f
```

第一个参数原本在EAX寄存器里（fastcall规范），可以直接使用EAX寄存器。函数引言的“push ebp / mov ebp, esp”指令，以及函数尾尾的“pop ebp”完全可以忽略；GCC做不到这种程度的优化。这种代码可以作为内联函数（参见第43章）来使用。
