本文将分次修改可执行程序，分别完成三个任务：

- 强制修改第一个跳转指令。
- 强制拦截第二个跳转指令。
- 强制触发第三个跳转指令。

故需要修改三条指令（三个字符）：

- 把第一个跳转指令改为jmp，并保留原始的偏移量（jump offset）。
- 第二个跳转指令的触发条件一定成立，无论条件是否，都要跳转下一条指令。所以我们将偏移量设置为零。
- 第三个跳转指令的修改方法和第一个跳转指令相同。我们只需要将跳转替换为JMP（无跳转）即可。

# Optimizing GCC

聪明的一定会问，既然比较的值相同，比较之后的标志位也是相同，还有必要对同样的参数进行多次比较？或者MSVC真的不能智能一些？但是启用优化选项后，GCC 4.8是否能够这种深度优化。

### GCC 4.8.1 f_signed()

```
f_signed()
   mov eax, [esp+8]
   cmp [esp+4], eax
   jg  .L6
   je  .L7
   mov [esp+4], .LC2 ; "a<b"
   puts

.L6:
   mov [esp+4], .LC0 ; "a>b"
   puts

.L1:
   ret

.L7:
   mov [esp+4], .LC1 ; "a==b"
   puts
```

很明显，它使用jmp替代了肿胀的“CALL ...... RET”指令。本书在13.1节将详细解答这种技术。不得不说在x86系统中，这种程序比较容易。MSVC做不到GCC那种深度优化。另一方面，汇编语言的程序员学会跳转用的技巧。所以，如果你遇到了这种精简的程序，而且能够判断它是GCC编译出来的，那么基本上可以判断它是手写的汇编程序。即使开启了同样的选项，f_unsigned()对应的指令也没有精致。

### GCC 4.8.1 f_unsigned()

```
f_unsigned:
   push esi
   push ebx
   sub esp, 20
   mov esi, [esp+32]
   mov ebx, [esp+36]
   cmp esi, ebx
   ja  .L13
   cmp esi, ebx          ; instruction may be removed
   je  .L14
.L10:
   jb .L15
   add esp, 20
   pop ebx
   pop esi
   ret
.L15:
   mov [esp+32], .LC2 ; "a<b"
   add esp, 20
   pop ebx
   pop esi
   jmp puts
.L13:
   mov [esp], .LC0 ; "a>b"
   call puts
   cmp esi, ebx
   jne .L10
.L14:
   mov [esp+32], .LC1 ; "a==b"
   add esp, 20
   pop ebx
   pop esi
   jmp puts
```

程序中只有两条CMP指令，至少它优化去了一个CMP指令。可见，GCC 4.8.1的优化算法还有改进的空间。

ARM模式的许多指令都带有条件执行。这些产生出来的指令只会在标记位为有效时，后面可能会出现这种执行。举来说，执行ADD时就是ADD。如果ADD被无条件，在32位的指令中，条件字段是被封装在指令前的（最高位）一个字段（field）里。即使是无条件B指令，B仍然是跳转，只不过它的条件字段是AL。对于来说，AL的作用是标识寄存。ADGT指令的代表（大于）。该指令依据若干前CMP指令的比较结果，判断跳转。只有当比较第一个值大于第二个值时，ADGT指令会跳转（ADR）指令。后面的BLQ带有回访。在相同情况下，只有当比较第一个值大于第二个值时，BLQ指令会执行BLQ。在这个条件时刻，ADGT指令已经加载字符串“a/b”的地址给R0寄存器，成为了printf()的参数，BLQ负责printf()。可见，并且只有当R0的值（变量a）大于R4的情况下，机会运行那组带有BLGT后的指令。显然，这是一组相互关联的指令。ADREQ和BLEQ是在“Great or Equal（大于等于）”的情况下进行LDMF（Load Multiple Descending）操作的指令。此类类，“LMDGE SP! (R4-R6, PC)”指令起到函数的作用。

f_unsigned函数与f_signed函数的功能分类。不同之处是使用了ADRH、BLHI和LMFSD标识，命令部的HI-代表Unsigned Higher Carry Set (greater than or equal)。由于数据类型没有变化，这两个函数的具体区别。

可见，ARM模式的程序完全不依赖条件转移指令。

这样做有什么优点呢？精简指令集（RISC）ARM处理器采用流水技术（pipeline）。简单来说，这种技术使得ARM模式的程序完全不依赖条件转移指令。
