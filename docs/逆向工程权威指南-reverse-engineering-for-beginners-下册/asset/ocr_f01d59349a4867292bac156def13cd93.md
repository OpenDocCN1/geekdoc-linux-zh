```
and eax, 8388607 ; 007ffffF
or eax, 1065353216 ; 3f800000H
; EAX=pseudorandom value & 0x007ffff | 0x3f800000
; store it in local stack:
mov DWORD PTR_tmp$[esp[4], eax
; reload it as float point number:
mss xmm0, DWORD PTR_tmp$[esp[4]
; subtract 1.0:
subss xmm0, DWORD PTR_real$8000000
; move value to ST0 by placing it in temporary variable:
mov DWORD tv128[esp[4], xmm0
... and reloading it into ST0:
fld DWORD tv128[esp[4]
pop
ecx
ret
?float_rand@YMXZ ENDP
```

编译器大量使用了“-SS” 后的指令。这个后续是“Scalar
Single”的写法。“Scalar（标量）”表明寄存器里只有一个值，
“Single”则排列该值是单精度float类型的数据。

# 27.6 总结

在 XMM 寄存器存储 IEEE 754 格式浮点数的时候，本章的所有程序都
只用到了 128 位寄存器空间的 64 位。

这是由操作指令决定的。本章中的指令带有-SD（Scalar Double-
Precision）后。如此，所有操作的数据类型都是 IEEE 754 格式的双精度
浮点数。这种数据只会使用 XMM 寄存器的 64 位。

SIMD 指集比 FPU 的指令更易理解。过去那些 FPU 指令远离语言语义较
，而且它们还要往返涉及 FPU 寄存器的结构，不如 SIMD 指令直观。

如果本章的数据类型都改为 double，那么操作浮点数的
指令将改为-SS 后（Scalar Single-Precision）。您将看到
MOVSS/ADDSS/SS指令。

> “Scalar”就是“标量”的意思，表示寄存器里含有一个值。如果
一个寄存器存有多个值，那么对这些寄存器进行操作的指令名字就会
带有“packed”字样。

还需要强调的是，SSE2 指令的操作都是 IEEE 754 格式的 64 位数据，而
FPU 内部使用 80 位的格式存储，误差较小，精度较高。
