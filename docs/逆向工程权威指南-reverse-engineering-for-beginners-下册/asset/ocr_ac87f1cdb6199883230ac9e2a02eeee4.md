# 第66章 系统调用（syscall-s)

我们都知道，在所有操作系统中运行的进程可以分成两类：一类进程对具有硬件的全部访问权限，运行于内核空间（kernel space）；另一类进程不能直接访问硬件地址，运行于用户空间（user space）。

操作系统的内核以及常规的驱动程序都运行于内核空间。普通的应用程序通常运行于用户空间。

具体来说，Linux的内核运行于空间；而Glibc（底层API）则运行于空间。

这种空间隔离措施对于操作系统的安全性至关重要。若没有隔离措施，所有程序都可能干扰其他进程甚至破坏操作系统的内核。另一方面来看，即使实现了两种空间的隔离措施，一旦运行于内核的驱动程序发生错误、或者操作系统的内核组件存在问题，整个内核就会崩溃直到发生BSOD（Black Screen of Death）“蓝白屏故障”。

虽然x86 CPU引入了特权等级的概念，将进程权限分为ring0~ring3，由于Linux和windows只使用了其中的两个级别控制进程权限：ring0（内核空间）和ring3（用户空间）。

由操作系统提供的系统调用（syscall）构成了ring0和ring 3之间的访问机制。可以说，系统调用就是操作系统为应用程序提供的编程接口API。
