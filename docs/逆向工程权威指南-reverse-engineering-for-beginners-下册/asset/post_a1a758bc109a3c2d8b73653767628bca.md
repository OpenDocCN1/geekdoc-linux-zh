
```c
void bzero(uint8_t* dst, size_t count)
{
    int i;

    if (count&~7)) {
        // work out 8-byte blocks
        for (i=0; i<count>>3; i++) {
            *(uint64_t*)dst=0;
            dst=dst+8;
        }
    }

    // work out the tail
    switch (count & 7) {
        case 7: *dst++ = 0;
        case 6: *dst++ = 0;
        case 5: *dst++ = 0;
        case 4: *dst++ = 0;
        case 3: *dst++ = 0;
        case 2: *dst++ = 0;
        case 1: *dst++ = 0;
        case 0: // do nothing
            break;
    }
}
```

我们来看看这个计算是如何完成的。处理内部内存区域的大小是64位数据，它分为两个部分。

| 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |
|---|---|---|---|---|---|---|---|
| ... | B | B | B | B | B | S | S | |

备注：B代表大小8字节的内存，S代表大小不足8字节的尾部内存。

当我们将输入的内存的大小除以8，其实就是该值右移3位。然而不足8字节的内存总数，即通过减法计算的余数，恰恰是刚刚移出去的最后一个三位。可见，把目标空间大小/变量count右移3位，可得它包含多少个8字节的内存；线性变量counter与数字7进行逻辑与运算可得它有多少字节的尾部内存。

当然，我们也得首先看看这目标空间是否足够进行一次字节的清除操作。因此首先就要检查count是否大于7。为此，我们就要将变量count的最低位清零并将结果进行比较。如果该数为零，则表示这个count大于7，我们就可以进行字节的操作。当我们不需要知道它到底比7大多少，只需要知道它是否为7，即count的高位为零。

当之所以能这样做，主要是因为8是2的次方，而且“某数除以n的次方”通过位移计算可以实现，其他类型的数字就不能通过位移运算进行判断了。

很难说这些技术是不值得采取的，毕竟这种技巧明显降低的可读性。然而它已经属于常见技术了。如果是资深的程序员，你让他尝试实现该装置，他也能够理解这种技巧的程序。

第一部分非常简单，用64位的零填充整个内存缓存。

第二部分的难在于循环开展开发。后装置利用的是switch()语句的作用。用人的语言会将变量count与数字进行逻辑与运算，得到结果，然后把它们逐个。如果尾数为0，就直接跳转到尾声后执行任何操作。如果尾数为1的话，就跳转到switch()语句对应的位置执行清除操作；由于滑梯效应的存在，会导致清除2个字节的空间，以此此类推。尾数值为最大7的时候，它就会执行7次相同操作。在这个算法，不会出现尾数大于7，也就是8的情况，因为第一部分已经清除了所有8字节的内存。

换而言，达夫装置是循环开展技术的一种特种。在老式设备中，它的运行速度比普通循环的运行速度更高。然而，对于现代的大多数CPU来说，一些短的循环效率反而比循环开展的执行速度更快。也许对于目前低成本的嵌入式MCU（微处理器，例如单片机）处理而言，达夫设备更有意义了。

## 第4章 除以9

我们来看一个简单的函数：

```c
int f(int a)
{
    return a/9;
}
```

### 4.1 x86平台编译

```asm
_a = 8          ; size = 4
_f:
    push   ebp
    mov    ebp, esp
    mov    eax, DWORD PTR [ebp+8]
    cdq             ; sign extend
    mov    ecx, 9
    idiv ecx
    pop    ebp
    ret
```

IDIV指令是除法指令。它从寄存器EAX中提取除数，从EDX中提取分子。计算结束后，它把商存储在EAX里，余数存储在EDX里。

### 4.2 MSVC优化

```asm
_a = 8             ; size = 4
_f PROC
    push   ebp
    mov    ebp, esp
    mov    eax, DWORD PTR [ebp+8]
    cdq             ; sign extend
    mov    ecx, 9
    idiv ecx
    pop    ebp
    ret
ENDP
```

编译器用乘法指令转换为实际除法。大家知道乘法比除法运行很快。使用这里的方法可以提高程序效率、节省时间。在优化中，我们常常将其称为“强度减轻”。若使用GCC编译此程序，即使刻意启用优化，结果和MSVC相似。

### 4.4 ARM处理器

ARM处理器和其他RISC处理器一样，“纯洁”不支持硬件除法指令。此外，这种CPU还很难“直接”进行32常量的乘法（opcode容不下32常量）。因此，在除法运算时，编译器会混合加减和位移运算、变相实现除法运算（详参阅第9章）。本节参考书中“32位除以10”的例子，分别计算商和余数。

```asm
; takes argument in r0
; returns quotient in r0, remainder in r1
; cycles could be saved if only divide or remainder is required
sub  r2, r0, #10        ; keep (x-10)
shr r1, r2, lsr #2
add  r1, r1, lsr #4
add  r1, r1, lsr #8
add  r1, r1, lsr #16
mov  r1, r1, lsr #3
add  r3, r1, asl #2      ; calc (x-10)*10
subs r2, r3, asl #1      ; fix-up quotient
add  r1, r1, #1
add  r2, r2, #10        ; fix-up remainder
mov  pc, lr
```

### 4.2.1 ARM模式，采用Xcode 4.6(LLVM)优化

```asm
@text:00002C58 39 1E 08 E3 18 E3 MOV R1, 0x38E3E39
@text:00002C60 10 F1 50 E7 SMMUL R0, R0, R1
@text:00002C64 C0 10 A0 E1 MOV R1, R0, ASR#1
@text:00002C68 A0 0F 81 E0 ADD R0, R1, 
@R0,LSR#31
@text:00002C6C 1E FF 2F E1 BX LR
```

这里的代码和采用优化算法时的MSVC与GCC基本相同。显然，LLVM采用了相同的算法的读者可能会问：那么这个程序又是怎样处理情况的？

细心的读者可能会问：既然ARM模式的单条指令不能把32位立即数赋值给寄存器，那么这个程序又是怎样做到MOV赋值的呢？实际上，原始指令并不是显示的MOV指令。仔细观察寄存器就会发现，那某指令占据了4个字符，而标准的ARM指令只有4个字符。原始指令的两步完成32位赋值：首先用MOV将低16位（本例是常见的0x8E39）复制到寄存器的低16位，再用MOVT将立即数的高16复制到寄存器的高16。AMD能够识别出这种指令组合，为了便于读者理解，把两条指令“排插”为一条“伪指令”。8个字符实际上是两条指令。

SMMUL is Signed Most Significant Word Multiply的简称。它是32位带符号数的乘法运算，会把64位结果的高32位存在寄存器。
