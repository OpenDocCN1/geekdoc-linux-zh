
经过这种处理之后，结构体只占用10字节空间，其中的char数据占用10字节。这将提高代码的空间利用率，不过这样做会时降低CPU的10倍读取效率。

main()函数同样使用结构体复制了传入的信息，再把临时结构体传递给其他函数。对于这10字节数据一个字段一个字段地、按字节声明的指令需要4次复制才能完成。编译器的分配3mov指令复制它们。为什么不是对齐指令呢？这是因为编译器认为是：在复制10字节数据时，3mov指令对（字节对齐）值的效率要高。这是编译器常用的优化手段。编译器使用MOVmemcpy函数的情况十分普遍，如需解答这方面详细知识，请参见书43.1.5节。

当然，如果某个结构体被多个源文件、目标文件（object files）调用，那么在编译这些程序时，结构封装格式和数据跨平台（/Zp/n）必须完全匹配。

MSVC编译器指定的结构体对齐标准的/Z选项。此外，还可以在源文件中设置#pragma pack的方法指定这个选项。MSVC和GCC都支持这种方法的编码。
