# 64.1 带有可变参数的函数

在C/C++语言的标准函数中，printf一类的可能是存的带有可变参数的函数。借助这类类的函数的帮助，我们可以比较容易看出printf和stdcall调用用范围的区别。我们首先规定编译器知道printf()的参数个数。然而，在Windows环境下，printf属于预先准备好的函数直接由MSVCRT.DLL提供。所以，我们无法从它的函数代码获取可变参数的处理方式；但是另一方面，我们它可能会规定格式化字符串。如果printf()采取了stdcall规范、根据格式化字符串计参参数的数量并在函数函数里恢复指针，那么这种局面就十分危险了：万一程序员打错了几个字母，程序就会崩溃。由此可见，对于那些带有可变参数的函数，cddecl规范比stdcall规范更好。

# 64.3 fastcall

这个调用约定优先使用寄存器传递参数，无法通过寄存器传递的参数则通过栈传递给函数函数。由于fastcall约定在内存层面的访问压力比较小，在早期的CPU平台上fastcall规范的比stdcall和cddecl规范的性能更好。但是在现在的、更为复杂的CPU平台上，fastcall的性能优势就不太明显而了。

这种约定并没有一种统一的规范，不同的编译器有着各自不同的实现方法。因此在使用这种约定时，我们需要特别关注：如果用两个不同的编译器定义了两个相互调用的、遵循fastcall规范的DLL库，那么这种这种相互调用的访问操作基本都会发生故障。

不是MSVC都是GCC用ECX和EDX传递第一个和第二个参数，用栈传递其余的参数。此外，应该由被调用函数调整指针，把参数恢复恢复到调用之前的初始状态（这一点与stdcall类似的）。
