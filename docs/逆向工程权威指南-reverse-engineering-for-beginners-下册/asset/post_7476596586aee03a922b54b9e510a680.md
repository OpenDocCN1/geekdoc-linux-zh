```assembly
_TLS SEGMENT
_rand_state DD 01H DUP (?)
_TLS ENDS

DATA SEGMENT
$SG84851 DB    '%d', 0AH, 00H

TEXT SEGMENT
```

```assembly
_init$ = 8                               ; size = 4
my_rand PROC
    ; FS:0=address of TIB
    mov     eax, DWORD PTR fs:_tls_array ; displayed in IDA as FS:2Ch
    ; EAX=address of TLS of process
    mov     ecx, DWORD PTR  _tls_index
    mov     ecx, DWORD PTR [eax+ecx*4]
    ; ECX=current TLS segment
    mov     eax, DWORD PTR  _init$[esp-4]
    mov     dword PTR  _rand_state[ecx], eax
    ret
_my_rand ENDP
```

```assembly
_my_rand PROC
    ; FS:0=address of TIB
    mov     eax, DWORD PTR fs:_tls_array ; displayed in IDA as FS:2Ch
    ; EAX=address of TLS of process
    mov     ecx, DWORD PTR  _tls_index
    mov     ecx, DWORD PTR [eax+ecx*4]
    ; ECX=current TLS segment
    imul    eax, DWORD PTR  _rand_state[ecx], 1664525
    add     eax, 1013940223 ; 3C6EF35FH
    mov     dword PTR  _rand_state[ecx], eax
    and     eax, 32767
    ret     0
_my_rand ENDP
_TEXT ENDS
```

参数 `rand_state` 现在位于 TLS 段中。此后每个线程都会拥有自己的 `rand_state`。这里表示的是如何寻址：从 FS:2Ch 调用线程信息块（Thread Information Block, TIB）的地址。如果需要，再增加一个格外的索引，最后再计算 TLS 段的地址。

这种程序的线程可以通过 ECX 寄存器访问各自的 `rand_state` 变量，因为该变量在每个线程的地址上不再相同。

FS 段选择器并不陌生。它其实就是 TIB 的专用指针，用于提高线程数据的加载速度。GS 选择器是 Win64 程序使用的额外的索引寄存器。在这个程序里，TLS 的地址是 0x58。

### 初始化的TLS数据

编程人员通常会给变量 `rand_state` 设置一个固定的初始值，以防止后期忘记它进行初始化。如下述代码第 9 行所示，我们对它进行初始化赋值。

```c
1 #include <stddef.h>
2 #include <windows.h>
3 #include <winnt.h>
4
5 // from the Numerical Recipes book:
6 #define RNG_a 1664525
7 #define RNG_c 1013904223
8
9 __declspec( thread ) uint32_t rand_state=1234;
10
11 void my_rand (uint32_t init)
12 {
13 rand_state=init;
14 }
15
16 int my_rand ()
17 {
18 rand_state=rand_state*RNG_a;
19 rand_state=rand_state+RNG_c;
20 return rand_state & 0x7fff;
21 }
23
23 int main ()
24 {
25 printf("%d\n", my_rand());
26 }
```

以上的代码看起来并没有什么不同，但是在 IDA 下我们可以发现：

```asm
.tls:00400000 ; Segment type: Pure data
.tls:00400000 ; Segment permissions: Read/Write
.tls:00400000 _tls segment public 'DATA' use32
.tls:00400000 assume cs: _tls
.tls:00400000 ; org 404000h
.tls:00400000 db 0 ; XREF:.rdata:TlsDirectory
.tls:00400001 db 0
.tls:00400002 db 0
.tls:00400003 db 0
.tls:00400004 dd 1234
.tls:00400008 TlsEnd ; XREF:.rdata:TlsEnd_ptr
```

我们关注的是这里显示的 1234。每当启动新的线程时，都会分配一个新的 TLS。此后，包括 1234 在内的所有数据都会复制到新建段。

一个典型的场景：
- 启动线程 A，系统创建线程用的 TLS，并将 `rand_state` 赋值为 1234。
- 此后，线程 A 多次调用 `my_rand()`，`rand_state` 的值将不再是初始值 1234。
- 启动线程 B，系统创建线程用的 TLS，`rand_state` 也会被赋值为 1234。也就是说，在线程 A 和 B 里，同名变量会有不同的。

### TLS回调

如果 TLS 中的变量必须填充某些数据，并且不是常规的方式怎么办？比如有下面的任务：程序员忘记调用 `my_rand()` 函数来初始化随机发生器（PRNG）。在这种情况下，可以采用 TLS 回调（通用性更好）。毕竟，本例只是演示性质的。它只是构造一个在进程/线程启动前就被系统调用的回调函数（`tls_callback()`），回调函数 `GetTickCount()` 函数的返回值来初始化随机发生器（PRNG）。

```c
#include <stdint.h>
#include <windows.h>
#include <winnt.h>

// from the Numerical Recipes book:
#define RNG_a 1664525
#define RNG_c 1013904223

__declspec( thread ) uint32_t rand_state;

void my_rand (uint32_t init)
{
    rand_state=init;
}

void NTAPI tls_callback(PVOID a, DWORD dwReason, PVOID b)
{
    my_rand (GetTickCount());
}

#pragma data_seg(".CRT$XLB")
PIMAGE_TLS_CALLBACK p_thread_callback = tls_callback;
#pragma data_seg( )

int my_rand ()
{
    rand_state=rand_state*RNG_a;
    rand_state=rand_state+RNG_c;
    return rand_state & 0x7fff;
}

int main ()
{
    // rand_state is already initialized at the moment (using GetTickCount())
    printf("%d\n", my_rand());
};
```

我们在 IDA 中查看一下，代码如下：

```asm
.text:00401020 TlsCallback_0 proc near ; DATA
XREF:.rdata:TlsCallbacks
.text:00401020 call ds:GetTickCount
.text:00401026 push eax
.text:00401027 call my_srand
.text:0040102C pop ecx
.text:0040102D retn 0Ch
.text:0040102D TlsCallback_0 endp

...
.rdata:004020C0 TlsCallbacks dd offset TlsCallback_0 ; DATA
XREF:.rdata:TlsCallbacks_ptr

.rdata:00402118 TlsDirectory dd offset TlsStart
.rdata:0040211C TlsEnd_ptr dd offset TlsEnd
.rdata:00402120 TlsIndex_ptr dd offset TlsIndex
.rdata:00402124 TlsCallbacks_ptr dd offset TlsCallbacks
.rdata:00402128 TlsSizeOfZeroFill dd 0
.rdata:0040212C TlsCharacteristics dd 300000h
```

在调试过程中中使用 TLS回调函数，可起到消除混淆的作用。经验不足的分析人员通常会感到回头转向，无法分析原始入口/OEP 之前就已经运行的回调函数。

## 第66章 系统调用（syscall）

我们都知道，在所有操作系统中的进程分成两类：
- 第一类进程对硬件具有访问权限，运行于内核空间（kernel space）；
- 另一类进程不能访问硬件，运行于用户空间（user space）。

操作系统的内核以及驱动程序都运行于空间。普通的应用程序通常运行于用户空间。具体来说，Linux 内核运行于空间；而 glibc（底层API）则运行于空间。这种空间隔离对于操作系统的安全性至关重要。如果没有隔离措施，所有程序都可能干扰破坏操作系统的内核。另一方面，即使实现了空间的隔离，一旦内核驱动程序发生错误、或者内核组件存在问题，整个内核就会崩溃直到 BSOD（蓝屏）。

### 66.1 Linux

Linux 程序通过 80 号中断/INT 80 调用系统调用。在调用系统调用时，程序应当通过 EAX 寄存器指定调用函数的编号，再使用其他寄存器声明系统调用的参数。

### 使用系统调用 syscall 的简单实例

```asm
section .text
global _start:
_start:
    mov    edx,len ; buffer len
    mov    ecx,msg ; buffer
    mov    ebx,1   ; file descriptor. 1 is stdout
    mov    eax,4   ; syscall number 4 is for sys_write
    int     0x80

    mov    eax,1   ; syscall number 1 is for sys_exit
    int     0x80

section .data
msg    db 'Hello, world!',0xa
len    equ $ - msg
```

编译指令如下：

```bash
nasm -f elf32 l.s
ld l.o
```

完整的 Linux 系统调用列表可以参考：http://go.yiche.com/17319

需要获取或追踪 Linux 系统调用的访问过程，可以使用书71章介绍的 strace 程序。

## 66.2 Windows

Windows 程序可以通过 0x2e 中断/int 0x2e 或 x86 专用指令 SYSENTER 访问系统调用。这里使用的中断数是 0x2e，或者采用 x86 下的特殊指令 SYSENTER。完整的 Windows 系统调用列表可以参考：http://go.yichev.com/17320

进一步的阅读，可以参阅 Piotr Bania 编写的 Windows Syscall Shellcode 一书：http://go.yichev/17321
