微的PDB文件没有把参数命名为limit。为了讨论，本文给它起名为limit。可见，Rand()函数的返回值是介于0~limit之间的整数。

Rand()函数的回调函数也只有一个StartGame() 函数。而且StartGame()应该是安卓雷的函数：

```
.text:010036C7    push      xBoxMac
.text:010036CD    call      Rnd(x)
.text:010036D2    push      yBoxMac
.text:010036D8    mov       esi,eax
.text:010036DA    inc       esi
.text:010036DB    call      Rnd84    ; Rnd(x)
.text:010036E0    mov       ecx,eax
.text:010036E1    shl       ecx,5     ; EAX=ECX*32
.text:010036E6    test      rgBlk[ecx+esi],esi
.text:010036EE    jnz       short loc_10036C7
.text:010036F0    shl       eax,5      ; EAX=32
.text:010036F3    lea       rgBlk[easi]
.text:010036FA    or        byte ptr [eax],80
.text:010036FD    dec       cBombStart
j.text:01003703    short loc_10036C7
```

因为击雷允许你设置棋盘位置，所以X(xBoxMac)和Y(yBoxMac)都是全局变量。Rand()函数根据这两个数组生成坐标轴，而在0x10036F6的OR指令设置雷。如果这个坐标在之前已经设置了地雷，那么0x10036E6的TEST和JNZ指令将再次生成一次坐标。

cBombStart不是设置地雷总数的全局变量，是循环控制变量：

SHL/左移设置棋盘宽度是32：

全局索引rgBlk的容量可以通过数据结构rgBlk标签的地址与下一个数据的地址推出来。数据数组应该是这两个数据之间的差，0x360(864)。

```
.data:01005340    rgBlk          360 db dhword ? ; DATA REFERENCE
MainWndProc(x,x,x,x) +574
.data:01005340                ; DisplayBlk(x,x)+23
.data:010056A0        dd      ? ; DATA REFERENCE
FixMenu(+2)+
```

棋盘的元素数量为：864（总量）/32=27。

那么，rgBlk是不是27×32的棋盘呢？我们把棋盘设置为100×100的矩阵，它会自动回旋为24×30的棋盘。所以棋盘的最大值就是这个值，且无论棋盘有多大，程序都把棋盘数据存储在这个数组里。
