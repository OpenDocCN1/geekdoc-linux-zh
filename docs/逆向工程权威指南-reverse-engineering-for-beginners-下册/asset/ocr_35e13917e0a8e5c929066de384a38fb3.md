# MSVC

前文介绍，Win64使用RCX、RDX、R8、R9寄存器传递前4个参数，使用来传递剩余的参数。我们将在本例中观察到这个现象。在下面的例子里，编译器使用了MOV指令对内存地址进行直接操作并没有使用PUSH指令。

指令清单 6.3 MSVC 2012

```
$SG2923 DB    'a=%d; b=%d; c=%d; d=%d; e=%d; f=%d; g=%d; h=%d', 0aH

main      PROC
sub       rsp, 88

mov      DWORD PTR [rsp+64], 8
mov      DWORD PTR [rsp+56], 7
mov      DWORD PTR [rsp+48], 6
mov      DWORD PTR [rsp+40], 5
mov      DWORD PTR [rsp+32], 4
mov      r9d, 3
mov      r8d, 2
mov      edx, 1
lea      rcx, OFFSET FLAT:$SG2923
call     printf

      ; return 0
xor      eax, eax

add      rsp, 88
ret
main      ENDP
_        TEXT
END
```

在64位系统中，整型数据只占用4字节空间。那么，为什么编译器给整型数据分配了8个字节？其实，即使数据的存储空间不足64位，编译器也会分配8字节的存储空间。这并不是为了方便每个参数进行内存地址，而且编译器会对数据进行对齐。所以64位系统为相同类型的数据保留8字节空间。同样，32位系统也为相同类型的数据保留4字节空间。

# GCC

x86-64的NIX系统采用与Win64类似的方法传递参数。它优先使用RDI、RSI、RDX、RCX、R8、R9寄存器传递前六个参数，然后利用栈传递剩余的参数。在生成汇编代码时，GCC字符串指针存储到了EDI寄存器，而不是完整的RDI寄存器。在前面的3.2节中，GCC生成的汇编代码也出现了这个现象。
