## 第74章 修改任务管理器 (Vista)

如果主机上安装的是四个CPU，那么Windows任务管理器应当通过GetSystemInfo()函数确保显示出4个CPU的性能计划图。本章将要微调任务管理器，让它显示更多的CPU运行核心。

首先需要了解的问题是：任务管理器如何知道CPU有多少个运算核心？虽然GetSystemInfo()函数可以确保反馈这一信息，但是任务管理器taskmgr.exe没有直接调用这个函数。多次通过NTAPI中的NtQuerySystemInformation()函数获取的各种系统信息，也是通过后者来理解具体的状况。

NtQuerySystemInformation()函数有四个参数：第一个参数是查询的系统类型；第二个参数是指针，用于返回的HandleList；第三个参数是程序员指定的HandleList内存空间；第四个参数是NtQuerySystemInformation返回的HandleList的大小。获取CPU信息，就要获取它的时候把第一个参数设置为常量0。我们将它的调用拆解为“NtQuerySystemInformation(0, ?, ?)”。第一步使用IDA打开taskmgr.exe。在微软官方程序过程中，IDA能够与之相关的PDF文件。易见的，任务管理器是用C++编写的，它使用的函数名称和类名是不知的。它使用的类名中，我们可以看到Adapter、Net、CProc、TaskPage和UserPage。这些类和任务管理器窗口有对应关系。在跟踪NtQuerySystemInformation()函数的每次调用之后，我们可以算出函数的第一个参数。在图74.1可以看到，部分调用里的第一个数值明显为零，所以标记了“Not Zero”。还有一些函数调用的情况非常特殊，本章将进行详解。总之，我们要找那些参数为零的NtQuerySystemInformation()函数的语句。

从微软下载对应的PDB文件之后，调试就能给变量分配正确的名称。我们从调试中找到全局变量Processors。传递NtQuerySystemInformation函数的第二个参数（即缓冲区）是var_C58。var_C20和var_C58的差值是0xC58-0xC20=0x38(56)。根据MSDN的官方说明，可知的数据格式如下：

```
typedef struct _SYSTEM_BASIC_INFORMATION {
    BYTE Reserved[24];
    PVOID Reserved[4];
    CHAR NumberOfProcessors;
} SYSTEM_BASIC_INFORMATION;
```

因为本例是在x64系统上的，VOID占用8字节。两个reserved字段占用24+8=32字节。这意味着var_C20很可能是SYSTEM_BASIC_INFORMATION里的NumberOfProcessors字段。我们将来验证一下。把C:\Windows\System32里的taskmgr.exe复制出来，我们在副本上进行修改以防Windows补丁机制自动还原。使用Hiew打开后的文件，找到74.2所示的程序地址：
