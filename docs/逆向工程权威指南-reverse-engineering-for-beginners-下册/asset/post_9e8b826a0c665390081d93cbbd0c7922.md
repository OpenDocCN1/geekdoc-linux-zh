
## A. 4.2 SSE与AVX寄存器

SSE都有XMM0~XMM7这8个128位寄存器，x86-64系统还有额外的8个寄存器（XMM8~XMM15）。

而支持AVX指令的CPU，它们把XMM*寄存器扩充为256位寄存器。

## A. 5 FPU调试寄存器

调试寄存器（Debugging registers）用于实现基于硬件的断点控制：

- DR0为第1个断点的地址（线性地址）
- DR1为第2个断点的地址
- DR2为第3个断点的地址
- DR3为第4个断点的地址
- DR6为调试状态寄存器。在调试程序异常时，它负责报告产生异常的原因。
- DR7用于控制断点调试。

### A. 5.1 DR6规格

| 序序（掩码） | 描述 |
| --- | --- |
| 0（1） | B0: 触发了断点DR0 |

| 位序（掩码） | 描述 |
| --- | --- |
| 1 (2) | B1: 触发了断点DR1 |
| 2 (4) | B2: 触发了断点DR2 |
| 3 (8) | B3: 触发了断点DR3 |
| 13 (0x2000) | BD: 仅在DR7的GD为1的情况下。只有当一条指令访问某个寄存器的时候，BD被置位（1） |
| 14 (0x4000) | BS: 当单步调试的时候，即EFLAGS的TF标识位置位的时候，BS被置位。单步调试具有最高的优先级，不受标识位影响 |
| 15 (0x8000) | TF: 任务切换标识，单步调试断点是在执行一条指令之后。设置EFLAGS（附录A.2）的TF标识，即可单步调试。 |

### A. 5.2 DR7规格

DR7用于控制断点类型：

| 位序（掩码） | 描述 |
|---|---|
| 0 (1) | L0: 在当前任务的DR0处设置断点 |
| 1 (2) | G0: 在所有任务中设置DR0 |
| 2 (4) | L1: 在当前任务的DR1处设置断点 |
| 3 (8) | G1: 在所有任务中设置DR1 |
| 4 (0x10) | L2: 在当前任务的DR2处设置断点 |
| 5 (0x20) | G2: 在所有任务中设置DR2 |
| 6 (0x40) | L3: 在当前任务的DR3处设置断点 |
| 7 (0x80) | G3: 在所有任务中设置DR3 |
| 8 (0x100) | LE: P6以后的处理器不支持标识位。如果被置位，FPU会在当前任务中追踪精确断点 |
| 9 (0x200) | GE: P6以后的处理器不支持标识位。如果被置位，FPU会在所有任务中追踪精确断点 |

| 序序（掩码） | 描述 |
|--- | --- |
| 13 (0x2000) | GD: 如果置位，当MOV指令修改DRx寄存器时，FPU将进行异常处理 |
| 16, 17 (0x3000) | 断点DR0的触发条件 |
| 18, 19 (0xC000) | 断点DR0的断点长度 |
| 20, 21 (0x30000) | 断点DR1的触发条件 |
| 22, 23 (0xC0000) | 断点DR1的断点长度 |
| 24, 25 (0x300000) | 断点DR2的触发条件 |
| 26, 27 (0xC00000) | 断点DR2的断点长度 |
| 28, 29 (0x3000000) | 断点DR3的触发条件 |

| 序序（掩码） | 描述 |
| --- | --- |
| 30, 31 (0xC00000) | 断点DR3的断点长度 |

其中，断点DRx的触发条件又分为:

- 00: 执行指令。
- 01: 数据的写操作。
- 10: 读写I/O (User mode下)。
- 11: 写数据。

可见，FPU断点的触发条件里没有“读取数据”这一项。

FPU断点长度的规格如下:

- 00: 1个节。
- 01: 2个节。
- 10: 32系统中未定义，64位系统中代表8个节。
- 11: 4个节。

## A. 6 指令

标记为 (M) 的指令通常不是编译器生成的指令。这种指令属于手写的汇编代码，或者属于编译器的内部指令（参见本书第90章）。

本节列举某些常见指令。如果要查看完整的指令说明，请参见《Intel® 64 和 IA-32 Architectures Software Developer’s Manual Combined Volumes:1, 2A, 2B, 2C, 3A, 3B, and 3C》《AMD64 Architecture Programmer’s Manual》。

### A. 6.1 指令前

LOCK: 数据总线锁。在执行LOCK之前的汇编指令时，它可以独占数据总线。简单来说，在执行这种指令时，多处理器的其他CPU将暂停、等待该指令执行结束。这种指令常见的各种关键字、（硬件）信号和原子操作。

禁止处理器修改数据总线上的数据，起到锁总线的作用。该指令的执行不影响任何标志位。它作为ADD、AND、BTR、BTS、CMPXG、OR、XADD、HOR指令的前缀。本书的第68章第4节介绍了。

cc: 条件转移指令。的写法。
JA: 大于。
JBE: 小于等于。
JB: 小于。
JC: 小于。
JE: 等于。
JGE: 大于等于。
JG: 大于。
JLE: 小于等于。
JL: 小于。
JNAE: 小于（不大于且相等）。
JNA: 大于。
JNBE: 大于等于。
JNB: 小于。
JNC: 小于。
JNE: 不相等。
JGE: 不大于不等于。
JNG: 大于。
JNLE: 不大于不相等。
JNL: 不小于。
JNO: 不溢出。
JNS: SF标识位为0。
JNZ: 不相等。
JO: 溢出。
JPO: PF标识位为零。
JP/JPE: PF标识位为1。

LAHF: 标识位跳转指令。它把标识位复制到AH寄存器。数据关系如下表所示。

| 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |
|---|---|---|---|---|---|---|---|
| SF | ZF | | AF | | PF | | CF |

LEAVE: 等于MOV ESP, EBP“POP”指令的组合。即这条指令释放栈中的局部变量，恢复栈指针（ESP）和EBP寄存器的初始状态。

LEA: 有效地址。这个指令并不修改源寄存器的值，也不会进行地址运算。它可以利用基址、索引和位移计算某个有效地址。LEA指令有一个特点——它不会影响CPU的状态。对于乱序执行的处理器来说有利于降低数据依赖性。

```
int f(int a, int b) {
    return a+b;
}
```

使用MSVC优化得到：

```
a = 8                      ; size = 4
b = 12                 ; size = 4
_f PROC
    mov      ecx, DWORD PTR [esp-4]
    mov      edx, DWORD PTR [esp-4]
    lea      eax, DWORD PTR [ecx+4] ; eax = a
    ret
ENDP
```

例如：
```
int f1(int a) {
    return a;
}
```

Intel C++生成的汇编代码如：

```
_f1      NEAR
mov      ecx, DWORD PTR [4+esp]    ; ecx = a
lea      edx, DWORD PTR [ecx+8] ; edx = a
lea      eax, DWORD PTR [ecx+4] ; eax = a
ret
```

尽管如此，两条指令的执行效率仍然超过单条指令。MOVSB/MOVSW/MOSD/MOVSQ：复制8位字节数据(Byte)/16位数据(Word)/32位字数据(D)/64位字数据(Q)。默认情况下，它将SI/ESI/RSI寄存器的值充当源操作地址，目标数的地址取自DI/EDI/RDI。与REP前缀组合时，它会把CX/RCX作为循环变量进行操作。这种情况下就像C语言中的memcpy函数那样工作。如果编译器在编译阶段能够确定每个的大小，通常使用REP指令内联实现memcpy()。例如，memcpy (EDI, ESI) 等效于：

```
; copy 15 bytes
CLD      ; set direction to "forward"
MOV      ECX, 3
REP MOVSD ; copy 12 bytes
MOVS      ; copy 2 bytes
MOVSB     ; copy remaining byte
```

复制字节的内容。MOVSX: 以符号扩展的方法实现signed数据的类型转换（见本书15.1节）。

MOVZX: 用零扩展的方法实现unsigned数据的类型转换（见本书15.1节）。

MOV: 数据传输指令。“MOV”这个名字与“MOVE”（移动）拼写相似，不过它的功能是复制数据而非移动数据。在某些平台上，这条指令是“LOAD”或者类似的名字。值得的是，当用MOV指令给32位寄存器的低16位时，寄存器的高16位不会变化。使用MOV指令给64位寄存器的低32位赋值时，寄存器的高32位会被清零。64位寄存器的高32位被自动清零的特性，可能是为了在x86-64系统上兼容32位程序而有意设计的。

MUL: unsigned数据的乘法指令。

NEG: 求补码指令（非补码指令）。NEG op得到-op。
