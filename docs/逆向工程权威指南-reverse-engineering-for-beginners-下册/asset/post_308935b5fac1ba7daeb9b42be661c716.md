## 24.5.1 x86

指令清单24.19 Optimizing MSVC 2012

```asm
$a$ = 8
_f
PROC
mov eax, DWORD PTR _a$[esp-4]
mov edx, DWORD PTR _a$[esp]
cdq
ret
ENDP
```

在这种情况下，我们需要把32位有符号扩展为64位。对于符号数来说，最高位是符号位，不能直接把高位设置为0。这里使用了CDQ指令进行符号转换。它把EAX的值扩展为64位，将结果存储到EDX寄存器。换句话说，CDQ指令获取EAX寄存器中的符号位（最高位），按照符号位的不同把高位填充为0或1。CDQ的作用和MOVSX指令相似。生成的汇编指令使用了inline乘法运算。其他部分和MSVC的编译结果大体相同。

## 24.5.2 ARM

指令清单24.20 Optimizing Keil 6/2013 (ARM mode)

```asm
||f| PROC
ASR r1,r0,#31
BX lr
ENDP
```

Keil for ARM的编译方法与MSVC不同：它把参数向右移31位，用了算术右移。MSB是符号位，而位移指令用符号位填充产生的空位。在执行“ASR r1,r0,#31”指令的时候，如果输入值是负数，那么R1就是xFFFFFFFF否则R1的值就是零。在生成64位值的时候，高32位应当存储在R1寄存器里。换句话说，这个指令用最高位填充R1寄存器以形成6位数。

## 第25章 SIMD

SIMD意为“指令流多数据流”，其全称为“Single Instruction, Multiple Data”。顾名思义，这类指令可以一次处理多个数据。在x86的CPU中，通过专用FPU进行计算实现。之后，CPU通过MMX指令提升了SIMD的运算功能。支持这种技术的CPU里都有8个64位寄存器，如MMX~MM7。每个MMX寄存器都是8字节寄存器，可以容纳2个32位数据，或者4个16位数据。使用SIMD指令进行操作数据时，它可以把8个数据分为4组数据同时运算。

平面图像可以视为一种二维矩阵的数据结构。在美工人员图像编辑程序对每个像素的亮度系数进行加减乘除运算。简单来说，图像的每个像素有灰度系数，而且处理系统是8位数据（1个字节）。为了满足这种需要，处理器厂商后来专门推出了基于SIMD的亮度调整指令。这种颜色调整甚至能够越界保护功能，能够避免亮度调整时可能产生的上溢（overflow）和下溢（underflow）。

在刚刚推出MMX技术的时候，SIMD使用了FPU的寄存器（别名）。这有利于FPU或MMX的混合运算。有人说Intel是为了节省晶体管，其实操作更为简单：操作系统不会增加新的寄存器，而是会数据保存到FPU上。只有满足“支持MMX技术的CPU”+“合适的操作系统”+“利用MMX指令的程序”才能发挥优势。

## 25.1 矢量化

SSE技术是SIMD扩展，把它寄存器扩展为128位。支持SSE技术的CPU已经有了单独的寄存器。AVX是另外一种技术，它的通用寄存器都是256位。现在从正面引入，看看SIMD的具体应用。SIMD技术能够用于复制（memcopy）和内存比较（memcmp）等用途。此外还可用DES的运算。DES (Data Encryption Standard)是对分组密码，它采用了分组对56位密钥，将64位输入通过序列变换得到64位的输出。

## 25.3 举例

下面的循环采用了矢量化：

```c
for (i = 0; i < 1024; i++)
{
  C[i] = A[i]*B[i];
}
```

上述代码从数组A和数组B取值，把这两个元素进行乘法运算，并将得到的存储在数组C里。如果数组中的每个元素都是32int型数据，就可以把A的四个元素放在MMX寄存器中，再把B的四个元素放在另一个MMX寄存器里，然后通过PMULLD (Multiply Packed Dword Integers and Low Result)和PMULHW (Multiply Packed Signed Integers and Store Result)指令进行并行乘法运算。这可以获得4个的结果。这样一来，循环体的执行次数不再是1024，而是1024/4。换句话说，程序的性能将提高4倍。某些编译器具有简单的矢量自动功能。Intel C++编译器就有这样的智能优化功能，详参见http://www.intel.com/intelxpress/sum_vmm.htm
