
然后运行FADD指令，求得的结果会被存储在ST(0)寄存器中。同时，指令会清空ST(1)寄存器。如图17.5所示。

在FPU的运算指令结束之后，运算结果存储在ST(0)寄存器中。main()函数相加后会从这个寄存器提取运算结果。

值得注意的是ST(0)寄存器——它的值是13.93......这是什么？

“FADD指令将运算结果推入栈，然后执行了出栈操作”，但是实际上这条指令把寄存器调整了栈顶指针寄存器的值。所以，确切地说是，寄存器构成了循环缓冲区（circular buffer）。

## 17.5.2 ARM: Optimizing Xcode 4.6.3 (LLVM) (ARM mode)

在ARM平台上浮点运算标准之前，许多厂商都推出了各自的扩展指令来实现浮点运算。后来，有VFP (Vector Floating Point)成为了行业的标准。

x86平台的FPU有自己的；但是ARM平台上并没有结构域，只能操作寄存器。

### 指令17.3 Optimizing Xcode 4.6.3 (LLVM) (ARM mode)

```
f
VLDR	D16,=3.14
MOV	D17, R0, R1; load "a"
MOV	D18, R2, R3; load "b"
VDIV.F64	D16, D17, D16; a/3.14
VLDR	D17,=4.1
VMUL.F64	D15, D17, D18; b*4.1
VADD.F64	D16, D17, D16; +
MOV	R0, R1, D16
BX
```

```
db1_2ca9	DCFD 3.14 ; DATA XREF: f
db1_2ca0	DCFD 4.1 ; DATA XREF: f+10
```

上述程序使用了D字母头的寄存器。ARM平台有32个64位的D寄存器。这些寄存器都可以用来存储（双精度）浮点数，又可用于单一指令多数据流运算/SIMD (ARM平台上这种运算NEON)。ARM平台还有32个字母头的寄存器S。

S字符寄存器用于处理单精度点数据。简单来说，S字符寄存器用于存储单精度浮点，而D字符寄存器用于处理双精度浮点。详细规格请参阅B. 3.3。

本例中的两个浮点数都用IEEE 754的格式存储在内存中。

望来说，VLDR和MOV指令是操作D字符寄存器的LDR和MOV指令。这些V字符的指令和D字符的寄存器，不仅能够处理浮点类型数据，而且可以用于SIMD（NEON）运算。

即使涉及浮点运算，它还是ARM平台的配置，还会通过ARM规范的S字符寄存器传递参数；双精度浮点数据是64位数据，对于每次传递一个双精度浮点数据就需要两个S字符寄存器。

“MOV D17, R0, R1”与指令从R0和R1读取64位数据的两个部分，并将最终值存储在D17寄存器中。

“MOV R0, R1, D16”与上述指令的作用相反。它把D16寄存器的值（64位）分解成32位，分别存储到R0和R1寄存器。后面出现的DIV、VMUL、VADD都是浮点运算。使用Xcode生成的Thumb-2的代码，会跟程序相同。

## 17.5.6 MIPS

MIPS平台支持多个处理器。第0个处理器专门用于FPU。与ARM处理器相似，MIPS的不是栈机（stack machine），而是32位寄存器（F0~F31）。有关FPU寄存器的介绍，参见附录C.2节。在处理64位双精度浮点数时必须一对32位。
