```
push     ebp
mov      ebp, esp
and      esp, 0FFFFFFF
sub      esp, 10h
mov      eax, offset aHelloWorld; "hello, world\n"
mov      [esp+10h+var_0], eax
call     _printf
mov      eax, 0
leave
retn
```

GCC的汇编指令，与MSVC生成的结果基本相同。它首先把“hello. world”字符串在数据数据的地址（指针）存储到EAX寄存器里，再把数据存储在数据框里。

其中值得注意的还有开头部分的“AND ESP, FFFFFFFF”指令。它将地址（ESP的值）向16字节对齐（成为16的整数），属于初始化的。如果地址没有对齐，那么CPU可能需要访问两次内存才能获得载数据。虽然在字节边界对齐就可以满足32x86 CPU和64位CPU的需求，但是主流编译器的规则规定“程序访问的地址必须向16字节对齐（被整除）”。人们还是为了提高指令的执行效率而特意制定了这条指令规范。[5]

“SUB ESP, 10h”将栈中展开10字节，即16字节。我们在后看到，程序只会用到栈空间。但是因为编译器对堆地址（ESP）执行了16字节对齐，所以每次都会分配16字节的空间。

而后，程序将字符串地址（指针的值）直接写入数据框。此处，GCC使用的是MOV指令；而MSVC使用的是PUSH指令。其中var_10是局部变量，用来后面来的printf()函数传递参数。

随即，程序调用printf()函数。

GCC和MSVC不同，除非人工指定优化选项，否则会与源代码对应的“MOV EAX, 0”指令。但是，我们已经知道MOV指令的opcode肯定要比XOR指令的opcode长。
