程序把索引列表的返回值作为关键字，在第二个转移表里进行查询，以完成相应的跳转（第14行指令的作用）。

需要注意的是，输入值为0的情况没有相应的case从从。如果a=0，则“dec eax”指令会继续进行计算，而SL10#f的查询是从开始的。可见，没有必要为这个特殊的设置单独的。

这是一种通用的编译技术。

表面看来，这种双表结构似乎不占优势。为什么它不像前文（参见13.2.1）那样使用一个统一的指针结构呢？在双表结构中，索引采用的是byte数据，所以双表结构前面单表结构更为紧凑。

# 13.3 GCC

在编译这种多对的switch语句时，GCC会生成统一的转移表。它的代码格式和13.2.1的相似。

# 13.3.3 ARM64: Optimizing GCC 4.9.1

因为输入值为零的情况没有对应的处理方法，所以GCC从输入值为1的特殊例开始划分每个分支，以便转移表压缩尽可能。

GCC 4.9.1 ARMARM64的编译更为优越。它可以把所有的偏移信息编码为8字节类型，在跳转指令中使用opcode。前文介绍，ARM64程序的每条指令都对应4个字母的opcode。在本例这种代码中，各分支偏移的具体数值不会很大。GCC能够充分利用这一现象，构造出单字符指针构成的转移表。

> 指令列表13.1 Optimizing GCC 4.9.1 ARM64

```
f14:
; input value in W0
	sub		w0, w0, #1
	cmp		w0, 21
	; branch if less or equal (unsigned):
	bls		l9
L2:
; print "default":
	adrp		x0, .LC4
	add		x1, x0, :lo12:.LC4
	b	puts
L9:
; load jumpable address to X1:
	adrp		x1
	add		x1, x1, :lo12:.L4
```
