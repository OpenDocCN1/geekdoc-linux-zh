.text:000005B6    add esp, 1Ch
.text:000005B9    retn
.text:000005B9 f1    endp

上述代码的关键在于：每个函数在启动之前调整了字符
串"returning %d\n"和global_variable的指针。
\_x86_get_pc_thunk_bx 函数通过EBX返回一个指向自身的指针。而
位于其基（偏移量0x570）的指令再次对ebx进行了修正。这是一种
获取PC指针（RIP）的通用方法。

常数0x1A84是函数的起始地址“全局偏移表（global offset
table GOT”（Procedure Linkage Table）PLT）和“过程链接之间的
地址。在可执行文件中，GOT、PLT都有各自的相同段
(section)。global_variable的指针相对于全局偏移量
GOT之后。为了便于我们理解偏移量和表之间的关系，IDA对显示的
偏移量进行了某种挑战。这部分的指令实际上是:

```
.text:00000577    call _x86_get_pc_thunk_bx
.text:0000057C    add ebx, 1A84h
.text:00000582    mov [esp+1Ch+var_4], esi
.text:00000586    mov [ebx-0Ch], eax
.text:0000058C    mov ebx, [esi]
.text:0000058E    lea eax, [ebx-1A30h]
```

EBX寄存器存储了GOT的指针（相应section的起始地址）。因
在此计算全局变量global_variable的指针时（该指针保存在GOT
中），必须从EBX减去地址，即常数0xC。在计算"returning
%d\n"的字符串指针时，必须从EBX减到0x1A30。

实际上，AMD的指令支持基于RIP的相对寻址就是简化了PIC
代码的操作。

然后，我们用旧版本的GCC将这段代码编译为64位目标文件。

IDA在显示代码的时候隐藏了那些RIP的寻址细节。因此，我们
通过objdump查看汇编代码：

