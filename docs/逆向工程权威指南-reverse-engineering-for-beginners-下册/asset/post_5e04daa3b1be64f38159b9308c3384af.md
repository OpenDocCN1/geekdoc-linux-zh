本质上说，这个程序的关键指令（下文称为“核心指令”）只有：

```
B4 09    MOV AH, 9
BA 1C 01    MOV DX, 11Ch
CD 21    INT 21h
CD 20    INT 20h
```

INT 21的第9号功能（AH寄存器）的作用是显示字符串。系统中DS:DX获取字符串的指针，然后把它输出到屏幕上。另外，这种字符串必须以“$”字符结尾。当前的操作操作系统显然继续兼容了这种指令。此过的指令属于CP/M（Control Program for Microcomputers），来自MS-DOS还要古老的磁盘操作系统。

由此可见，EICAR的主要功能是：

- 奇寄存器（AH和DX）传递预定值。
- 在内存中准备INT 21和INT 20的opcode。
- 执行INT 21和INT 20。

严格地讲，核心指令的基本都都不是显示字符。EICAR采用“拼凑”指令的方法，把核心指令拼凑成了可存储在字符串里的显示字符组合。这项“拼凑”技术还通用于shellcode。

有关“用显示字符表示的opcode”，请参见本书附录A. 6. 5。

# 83.1.3 从内存读取随机数

MS-DOS系统完全没有保护机制。换句话，应用程序可以访问内存数据。不仅如此，在使用DSB读取数据的时刻，即使程序没有先设置寄存器值也没有问题——它从任意地址读取一个字符。建议使用SCASB替代DSB，因为可以在读取数据的同时，根据数据直接设置标识位。

# 83.1.4 Andrey "hermit" Baranovich：11 bytes

```
00000000:B05C      mov       al,05C  ; '\' read byte from random place of memory
00000002:AE       scasb      PF = parity(AL - random_memory_byte) = parity(5Ch - random_memory_byte)
00000003:7A02      jp       0000007
00000005:B02F      mov       al,02F  ; '/'
00000007:CD29      int       ; output AL to screen
00000009:EBF5      jmp      0000000 ; loop endlessly
```

SCASB计算“AL-[随机地址]”，并设置标识。JP指令比较少，触发JP的条件是奇偶PF数值）。在这个程序里，输出的字符并不由随机字母比特位决定，而是由这些字符的比特位共同决定，这个程序的数组有望更好。如果包含SAL指令（完成SET CF），那么整个程序就可以运行。这个指令最早出现在NEC语言里。用自然语言解释的话，它的功能就是标识位填充AL寄存器；CF为1，则AL的值就是FF；否则的值就是0。在80/88平台上无法运行。
