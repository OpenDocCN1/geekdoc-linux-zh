上面这个32位指令如何封装浮点数1.5呢？在ARM64的FMOV指令里，有8个特殊的位符。这8位空间用于编排浮点型数据。通过VFPEExpandImm函数的算法，编译器将把浮点数封装在FMOV指令的空隙里。这种算法又叫@fminloat[1]，实现方法参见[ARM13a]。我测试了几个浮点数，发现编译器能够通过函数把30.0和31.0编在8位指令空间里。但是这8位空间无法封装32.0。根据IEEE 754规范，32.0占用8个空间。

```
double a()
{
    return 32;
}
```

# 28.4 重定位

我们已经知道ARM64的指令是4字节（汇编）指令。4字节的容量有限，无法封装很大的数据。尽管如此，程序像可能会被操作系统加载内存中的任意地址，这就就需要（基址）重定位（relocations/relocs）来get修正。有关重定位的详细介绍，请见本书的68.2.6节。

ARM64对使用ADRP和ADD指令来传递64位指针，ADRP指令来获取地址所在处（例如main）的4KB页地址，而ADD指令则负责存储偏移量的其余部分。在Win32下使用GCC(Linaro) 4.9编译了“Hello, world!”程序（即第6章的第一个程序），然后使用objdump工具分析的目标文件。
