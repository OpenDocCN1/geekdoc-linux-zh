GCC编译器的代码生成器这样做，或许是为了便于“记住”整个寄存器已经分配给了char类型，以保证寄存器的高位（bits）不会含有噪音数据。

接下来将要介绍的是NOT指令。NOT指令对操作的所有位（bit）都进行非运算。这条指令XOR ECX, 0xffffffff开始等价。“not ecx”的结果与某数相异，相加某数后减去ECX和1。在程序开始执行的时候，ECX保存了字符串首字符的地址（指针），EAX寄存器存储的是终止符的地址。对于ECX求异，再与eax相加，就是计算eax-ecx-1的值。这种运算可以得到正确的字符串长度。

它的数学问题，请参见第30章。

换句话说，在执行完循环语句之后，函数进行了如下操作：

```assembly
ecx=str;
eax=0;
ecx=(-ecx)-1;
eax=eax+ecx
return eax
```

它得到的结果与下述运算完全相同:

```assembly
ecx=str;
eax=eos;
eax=eax-ecx;
eax=eax-1;
return eax
```

GCC编译器这这么编译代码的具体原因不明。我们能够确定的，即使GCC和MSVC分别选择不同的算法，计算的结果肯定相同。

如果不指定优化选项，LLVM编译器生成的代码会很啰嗦。但是这种长的代码会有帮助我们理解它处理局部变量的结构。本例只用了两个局部变量，eos和str。

在IDA的反汇编结果中，我把var_8重命名为原始变量名eos，把var_4重名为str。

程序的前几条指令将输入传递给变量str和eos。

循环的起始地址是loc_2CB8。

循环内的第3条指令（LDR, ADD, STR）将eos的值存在R寄存器里，然后将这个差值增（+1），再将修改后的差值衔接到栈内的局部变量。

接着“LDRB, RO, [RO]”（Load Register Signed By）指令从RO所指向的地址读取一个字节，并将转换为32位符号数据（Keil也也将Char类型视为有符号数）。该指令类似于x86的MOVS指令（参见15.1.1节）。在震惊中定义准Char类型的变量是Signed型数据，编译器就会就把这个值当作Signed型数据处理。

应当注意的是，虽然x86系统可以把32位寄存器拆分为8位寄存器或16位寄存器单独使用，但是ARM系统没有寄存器拆分、分别使用的技巧。的确地，x86的这种特性是兼容性的要求的；为了运行16位81086指令，该指令必须向下兼容。而ARM系统的处理器最初就是32位RISC处理器。所以，在使用ARM系统的寄存器时，只能把它当作完整的32位寄存器。

此后，LDRB指令将字符串逐字符传递到R寄存器。其后的CMP和BEQ指令，检查字符串是否为零字节。如果这个字符不是0，则再次进行循环；如果这个字符是0，则结束循环。

函数在结束时检查eos和str的差值，再把这个差值减去1，作为函数的返回值，保存在寄存器中。整个没有将寄存器推入栈的操作。按照ARM函数的约定，R3寄存器的作用是传递参数；函数在退出以后已经完成了。另外，程序没有用到其他的寄存器，所以在函数结束时，唯一需要的工作就是跳转指令（BX）交给LR。

在进行优化的时候，编译器识别寄存器已经足够用了，不必使用变量str。在循环结束之前，编译器使用R0寄存器存储eos。LDRW R2, [R1], #1从R1指向的地址读取字节，将其转换为32位符号数据（signed）之后存储在R2里。上述操作之后把R1寄存器的值加1（递增）。这种指令属于延迟寻址（Post-indexed address，又称后索引寻址）。

2节详细介绍索引寻址。循环和BNE指令判断循环结束条件。它们在读取到数值为零的字符后处于备状态。MVNS (Move Not)指令相当于NOT指令，而在ADD指令配合“eos-str”的运算。15.1节中详细介绍了各种细节，这里不再重复。LLVM编译器与GCC都认为这种代码效率更高。
