## 51.4.2 std::list

`std::list`是众所周知的双向链表的容器，它的每个元素可以通过指针（链域）串连接逻辑意义上的线性表。这种结构的每个元素都有2个指针，一个指针指向一个元素，另一个指针指向下一个元素。

链域的存在决定了，每个节点比单纯的数据节点元素占用2个字节的空间，即32位系统下占用8字节，而64位系统下会占用16字节。

C++的标准模板类只是给结构体扩展了“next”“previous”指针，使之形成逻辑上的有序序列。

## 我们以2个变量组成的结构体为例，演示std::list链结构。

虽然C++标准（ISO/IEC 14882:2011 (C++ 11 standard））没有明确这种数据结构的具体实现方法，但是MSVC编译器和GCC编译器不约而地选择几乎一致的实现方法。我们就以下源代码举例进行说明：

```cpp
#include <stdio.h>
#include <list>
#include <iostream>

struct a {
    int x;
    int y;
};

struct List_node {
    struct List_node* _Next;
    struct List_node* _Prev;
    int x;
    int y;
};

void dump_List_node(struct List_node *n) {
    printf("ptr=0x%p _Next=0x%p _Prev=0x%p x=%d y=%d\n", n, n->Next, n->Prev, n->x, n->y);
}

void dump_List_vals(struct List_node* n) {
    struct List_node* current=n;
    for (;;) {
        dump_List_node(current);
        current=current->Next;
        if (current==n) // end
            break;
    }
}

void dump_List_val (unsigned int *a) {
#ifdef MS_VER
    // GCC implementation does not have "size" field
    printf("_Myhead=0x%p, Mysize=%d\n", a[0], a[1]);
#endif
    dump_List_vals ((struct List_node*)a);
}
```

```cpp
int main()
{
    std::list<struct a> l;

    printf("* empty list:\n\n");

dump_List_val((unsigned int*)(void*)&l);
}
```

## GCC

我们首先讲解GCC编译器的编译方式。

运行上述程序时，将会得到很多输出数据。我们进行分段讲解：

- * empty list:
ptr=0x0028fe90 _Next=0x0028fe90 _Prev=0x0028fe90 x=3 y=0

此时它还是个空链。虽然我们还未对其进行赋值操作，但是变量x和变量y已经有数据了（也就是常人所说的虚节点/dummy node）。而且，“next”和“prev”指针都指向该节点自己。

![](img/a13a81a53f805f5074b2e5d2ec75b6_778_0.png) (image 778_0.png)

在这个时候，迭代器.begin（开始）和.end（结束）值相等。然后程序创建了3个节点，此后整个链表的内部数据变为：

- * 3-elements list: _Next=0x00003498 _Prev=0x0028fe90 x=3 y=4
ptr=0x000034a0 _Next=0x000034b0 _Prev=0x000034a0 x=1 y=2
ptr=0x00003498 _Next=0x000034b0 _Prev=0x00003498 x=5 y=6
ptr=0x0028fe90 _Next=0x000034a0 _Prev=0x000034b0 x=5 y=6

最后一个元素的地址是0x0028fe90。实际上的释放之前它的地址发生变化。这两个节点的字段x和y仍然是随机的，这时它们的值是5和6。巧妙的是，这些值和上一个元素的相同。这种巧妙不会持续下去。此时3个节点存储内存分布所示。

![](img/a13a81a53f805f5074b2e5d2ec75b6_880_0.png) (image 880_0.png)

变量I指向第一个节点的迭代器，开始()和结束不是变量，双向链表通常采用这种特殊节点（英文称为 sentinel node/哨兵）实现。这种方法具有简化链结构和提升效率。迭代器其实指向节点的指针，而list.begin()和list.end()返回节点的值。

- node at .begin:
ptr=0x000034a0 _Next=0x0028fe90 x=3 y=4
- node at .end:
ptr=0x00003498 _Next=0x000034b0 _Prev=0x000034a0 x=5 y=6

事实上，最后一个节点的Next指向第一个节点，一个元素的Prev指针指向最后一个元素。因此很容易想到一个循环表。所以，可以利用第一个指针（即实例）顺摸找到最后一个节点，不必遍历整个链。利用这种结构，我们还可以费尾插入其他节点。算符“++”和“--”就是迭代器的[当前节点->prev]或[当前节点->next]的值。反向迭代器（reverse iterators）的作用与其相似，只是相反。算符“*”用于返回节点的自定义结构起始。在链表里插入和删除节点时，我们只需要分配（或释放）节点的内存，然后更新相关的域指针，即可保证整个表的有效性。在删除节点之后，相邻的迭代器（链域）可能会指向删除的无效节点，此时迭代器就会失效。指向无效节点的迭代器又叫“dangling pointer”。这种指针不能再使用了。在GCC（4.8版本）编译std::list实例，它存储总数。这意味着内置函数size()的运行缓慢，因为它必须遍历完整表才能返回个数。因此，那些与节点数有关的所有函数例如(n)的时间开销和表性能接近底层。
