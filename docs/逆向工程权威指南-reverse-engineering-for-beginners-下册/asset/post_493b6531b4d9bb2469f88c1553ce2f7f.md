## 4 Windows NT 临界区域

在任何线程环境下，临界区是保护数据一致性和操作的重要方法。临界区确保了同一时间内只有一个线程访问某些数据。在Windows的数据结构中，CRITICAL_SECTION关键字定义如下：

```c
typedef struct _CRITICAL_SECTION {
    // The following fields control entering and exiting the section
    LONG LockCount;
    LONG RecursionCount;
    HANDLE OwningThread; // size on 64-bit systems
    ULONG_PTR SpinCount;
} RTL_CRITICAL_SECTION;
```

## 指令清单68.15 Windows 2008/ntdll.dll/x86（开始）

下面的代码描述了EnterCriticalSection()的工作原理：

```asm
RtlEnterSection@4 proc near
arg_0 = dword ptr 8
mov edi, edi
push ebp
mov ebp, esp
push esi
mov esi, [arg_0]
add dword ptr [esi+8], 0xFFFFFFFF ; RecursionCount
jne short loc_7DE9B2
push ebx
push edi
lea edi, [esi+4] ; LockCount
mov dword ptr [esi+0Ch], 0
mov ebx, 1
mov eax, edi
lock xadd [eax], ebx
inc ebx
cmp ebx, 0xFFFFFFFF
jnz loc_7DE8EB7
loc_7DE9B2:
pop edi
pop ebx
loc_7DE9B2:
xor eax, eax
push esi
ret 4
```

在该段中最最重要的指令是BTR（及其LOCK前缀）：指令第一个操作数的第0位复制CF，然后把这个CF清零。由LOCK前缀修饰的原子操作，可以让CPU阻止其他读取或修改内存地址。如果LockCount的第0位是1，则将其重置并退出函数——CPU现在处于临界区，否则，则表示其他线程占用临界区，CPU将等待操作结束。等待期间运行的函数是WaitForSingleObject()。下述代码描述了LeaveSection 函数的工作机制：

```asm
RtlLeaveSection@4
arg_0 = dword ptr 8
mov edi, edi
push ebp
mov ebp, esp
push esi
mov esi, [arg_0]
add dword ptr [esi+8], 0xFFFFFFFF ; RecursionCount
jnz short loc_7DE9B2
push ebx
push edi
lea edi, [esi+4] ; LockCount
mov dword ptr [esi+0Ch], 0
mov ebx, 1
mov eax, edi
lock xadd [eax], ebx
inc ebx
cmp ebx, 0xFFFFFFFF
jnz-wait,0
loc_7DE9B2:
pop edi
pop ebx
loc_7DE9B2:
xor eax, eax
push esi
ret 4
```

HADD-LOCK指令的功能是先交换操作数的值，然后再进行加法运算。在本例中，它将LockCount与数字1的存储于一个操作数，同时将LockCount的初始值传递EBX寄存器。但是EBX里的这个值会被立即被后面的INC递增，最终与LockCount的值同步。因为它带有LOCK前缀，所以属于原子操作。这意味着所有的CPU（不管是多核的）都不能同时访问那片内存区域。

LOCK前缀非常重要。不同的CPU或者CPU核心（core）可能会加载同一个进程的不同线程。若未使用LOCK前缀的指令操作临界区的数据，可能发生无法预料的情况。

想要更多信息，可以参考Igor Schoch编写的文章“Compiler Internals: Exceptional and RTTL（编译器内核:例外）”。除了例外之外，pdata段存储了几乎所有函数的起始和结束的地址。由此可见，pdata段是自动分析的重点。Igor Schoch编写的文章“Compiler Internals: Exceptional and RTTL（编译器内核:例外）”。Matt Pietrek的文章“A Crash on the Depth of Windows32 Structured Exception Handling（Win32结构异常处理）”。
