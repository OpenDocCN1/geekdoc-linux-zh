# 第一章 CPU简介

CPU是执行程序的硬件单元。简单来说，其相关概念有以下项：

- 指令码：CPU受理的底层命令。典型的底层命令有：将数据在寄存器间转移、操作内存、计算运算等。Instruction Set Architecture (ISA) 机器码：发送给CPU的代码。一条指令通常封装为若干字节。
- 汇编语言：为了让人易读易记的代码，有很多类似宏的功能。
- CPU寄存器：每种CPU都有固定的通用寄存器（GPR）。x86 CPU一般的8个GPR，而64位ARM则是16个GPR。您可以认为CPU寄存器是一种存储单元，能够存储所有类型的变量。如果您使用高级语言，并且使用32位变量，那么光靠寄存器就能完成不少任务！
- 那么，机器码和高级语言（PL）在哪里？CPU不像人类一样能够理解C/C++、Python等编程语言。汇编语言更接近底层的具体语言。在不久的将来，可能会让你直接执行高级语言的CPU必定比现在的复杂。如果人类直接使用底层汇编语言编写程序，其难度也很高——因为很容易出现大量的错误。我们需要用高级语言转换为底层汇编语言。

## 1.1 指令集架构

在x86的指令集架构（ISA）里，opcode（指令对应的机器码）长度相同。为了兼容性的考虑，后来的64位CPU指令架构并没有放弃原有指令集。很多早期16位086 CPU的指令不仅继承，而且当作最新的指令集继续沿用。

ARM作为RISC[1] CPU，它的指令集在设计之初就保持了opcode的一致。在过去，这一特性表现出了优越性。最初的时候，所有ARM指令的机器码都被封装在4字节里[2]。人们把这种模式称为“ARM模式”。后，他们就发现这种模式并不打算。在实际程序中，大多数CPU指令[3]很少用4字节。所以他们又推出了一种每条指令封装在2字节里的“Thumb”模式的指令架构。人们把用这种指令集编码的指令叫做“Thumb模式”。然而Thumb指令并不能够所有ARM指令，它本身封装在指令的边界。在一个程序里可以同时存在ARM模式和Thumb模式两种模式之间。

之后，ARM的创造者们决定改进指令。ARM v7就开始了Thumb-2指令。Thumb-2模式被封装在2字节的机器码中，2字节封装下的指令由4字节封装。现在，很多人还认为是“Thumb-2指令是ARM指令和Thumb指令的复合体”。实际上，它是一种充分性能、与ARM模式媲美的独立的模式。在扩展了Thumb模式的指令集之后，Thumb-2现在和ARM模式互相。XcodeXcode默认默认采用--2，现在主流主流的iPhone/iPad应用程序使用了Thumb-2指令。

64位的ARM处理器连接到它。这种CPU的指令集架构再次使用固定长度的4字节opcode，不支持Thumb模式。相应的，64位的ARM工作。受到指令集架构的影响，ARM指令集分为三类：ARM模式指令集、Thumb模式指令集（包括Thumb-2）和ARM64的指令集。虽然这些指令集之间存在千差万别的联系，需要强调的是：同样的指令集属于不同的指令架构；一个指令集绝非一个指令集的变种。相应地，本书会以3种指令集重复演示同一程序的指令段，充分介绍ARM程序的特点。

除了ARM处理器之外，还有许多处理器都采用了精简指令集。这些处理器大部分使用了固定长度的32位opcode。例如MIPS、PowerPC和Alpha AXP处理器就是如此。

- [1] Reduced instruction computing /精简指令集。
- [2] 这种固定长度的指令集，特别便于计算前后指令的地址。有关特性将在13.2.2节介绍。
- [3] 即MOV/PUSH/CALL/Jcc等指令。

## 2.2 ARM

ARM模式是什么？

指令清单2.3 Optimizing Keil（ARM模式）
```asm
f PROC
    MOV r0,#123
    BX  lr
ENDP
```
ARM程序使用R0传递返回值，指令将数值23赋值给R0。ARM程序使用寄存器（Link Register）存储函数之后的返回地址（RA）。x86程序使用栈存储上述地址。可见BX的作用是跳转到返回地址，然后执行调用者的后续指令。如您见，x86和ARM指令的MOV指令对应“move”。

## 2.3 MIPS

在MIPS指令里，寄存器有两种命名方式：一种是以数字（$0），另一种是以伪名（$VA）。

指令清单2.4 Optimizing GCC（汇编输出）
```asm
li $v0, 123
```
然而IDA显示寄存器的伪名。

指令清单2.5 Optimizing GCC（IDA）
```asm
jr $ra
li $v0, 0
```
根据名和寄存器的关系可知，寄存器都是$v0。此处LI指令是英文词Load Immediate（加载立即数）的缩写。其中J和JR都属于跳转指令，它们把执行流交给调用者，跳转到RA寄存器中的地址。这个器相当于ARM平台的LR寄存器。此外，为什么赋值指令LI和转移指令J/JR的位置反过来？这属于RISC精简指令特性之一——分支延迟（Branch delay slot）现象。简单来说，不管分支发生与否，位于分支后面的一条指令（延时槽里的指令），总是先于分支提交。这是RISC精简指令的一种特例，我们不必在此深究。总之，转移指令后面的这条赋值实际上是在转移指令之前运行。习惯上，MIPS领域的寄存器名称和指令名称都使用小字母。为了在排版风格上与其他指令架构保持一致，本书采用大字母排版。

## 3.1 x86

### 3.1.1 MSVC

我们将通过下列指令，使用MSVC 2010编译这个程序：

```bash
cl 1.cpp /Fa.asm
```
其中/Fa项将编译器生成汇编清单文件（assembly listing file），并指定汇编列表名为1.asm。上述命令生成的1.asm内容如下：

指令清单3.1 MSVC 2010
```asm
CONST SEGMENT
$SG330 DB      'hello, world', 0AH, 0OH
CONST ENDS
PUBLIC      _main

EXTRN    _printf:PROC
; Function compile flags: /Ot (优化速度)
TEXT SEGMENT
_main
    push    ebp
    mov     ebp, esp
    push    OFFSET $SG330
    call    _printf
    add     esp, 4
    xor     eax, eax
    pop     ebp
    ret
    ENDP
_TEXT ENDS
```
MSVC的汇编清单文件采用了Intel语体。汇编语言存在两种主流语体，即Intel语体和AT&T语体。本书将在3.1.3节中讨论之间的区别。在生成1.asm之后，编译器会生成1.obj再链接为可执行文件1.exe。在hello world这个例子中，文件分为两个段，即CONST和_TEXT段，它们分别代表数据段和代码段。在本例中，C/C++程序为字符串常量“hello, world”分配了一个指针（const char[]），在代码中这个指针的名称并不明显（参照下列Bjarne Stroustrup. The C++ Programming Language, 4th Edition. 2013的第176页，7.3.2节）。接下来，编译器进行了了自己的处理，并在内部字符串常量命名为$SG330。因此，上述过程的源代码等于：

```c
#include <stdio.h>

const char *SG330[]="hello, world\n";
int main()
{
    printf($SG330);
    return 0;
}
```
在1.asm文件时，我们会发现编译器在字符串常量的尾部添加了十六进制数字0H。依据x86的标准，编译器为函数的结束添加了数值为0（单个字节）。有关参照本书的第1节。在代码段里有标志性的函数开头（prologue）和尾声（epilogue）。所有的函数都有这样的序言和尾声。在序言之后，我们看到调用printf函数的指令：通过PUSH指令将字符串指针推入内存。这样printf函数结束后，程序的控制流返回到main函数。此时，字符串地址（指针）仍然留在栈中。这时候就需要调整指针（ESP）。一个语句是“ADD ESP,4”，把ESP寄存器释放（4字节）数据。为什么要加上“4”？这是因为x86平台的内存地址使用4字节对齐。某些编译器（如MSVC编译器）不会使用ADD指令来释放数据，而是使用POP ECX指令。Intel编译器会进行齐齐。另一个理由就是，POP ECX的OPCODE（1字节）比ADD ESP（3字节）要短。

## 3.1.2 GCC

接下来，我们使用GCC编译这个hello程序：

```bash
gcc l.c -o 1
```
我们使用反汇编工具IDA（Interactive Disassembler）查看main函数的具体情况。IDA输出的汇编指令格式与MSVC生成的相同，它们采用Intel语显示。

指令清单3.3 在IDA中观察到的汇编指令
```asm
Main
  proc near
  var_10      = dword ptr -10h

push     ebp
mov      ebp, esp
and      esp, FFFFFFFF
sub      esp, 10h
mov      eax, offset aHelloWorld ; "hello, world\n"
mov      [esp+10], eax
call     _printf
mov      eax, 0
leave
retn
```
GCC的汇编指令与MSVC生成的结果基本相同。它首先把“hello, world”字符串的地址（指针）存储到EAX寄存器里，再把数据存储在数据段里。其中值得注意的还有开头部分的“AND ESP, FFFFFFFF”指令它将地址（ESP的值）向16字节对齐（成为16的整数），属于初始化。如果地址没有对齐，那么CPU可能需要访问两次内存才能获得数据。虽然在字节边界对齐就可以满足32位86 CPU和64位CPU的需求，但是主流编译器的规定“程序访问的地址必须向16字节对齐（被整除）”。人们为了提高指令的执行效率而特意制定了这条规范。[5]。“SUB ESP, 10h”将栈中展开10字节，即16字节。我们在后面看到，程序只会用到栈空间。但是因为编译器对地址（ESP）执行了16字节对齐，所以每次都会分配16字节的空间。而后，程序将字符串地址（指针的值）直接写入数据段。此处，GCC使用的是MOV指令；而MSVC使用的是PUSH指令。其中var_10是局部变量，用来后面来的printf函数传递参数。随即，程序调用printf函数。GCC和MSVC不同，除非人工指定优化选项，否则会与源代码对应的“MOV EAX, 0”指令。但是我们已经知道MOV指令的opcode肯定要比XOR指令的opcode长。
