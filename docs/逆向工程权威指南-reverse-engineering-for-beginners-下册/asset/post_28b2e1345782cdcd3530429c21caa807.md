
...
m eax, offset dummy_data2 ; PE or ELF
reloc here
add eax, 200h
push eax
call dump_string
...
p
```

这个程序执行时，我们只能在IDA工具中看到dummy_data1和dummy_data2的reference（调用信息）。它不能正常显示字符串序列message1和message信息。

全局变量或函数数也可以这样混淆。

## 51.1 类

### 51.1.1 一个简单的例子

从编译层面看，C++类（class）的组织方式和结构数据完全一致。

我们演示一个含有两个变量、两个构造函数以及一个方法的类型数据:

```
#include <stdio.h>

class c
{
private:
    int v1;
    int v2;
public:
    c() // default ctor
    {
        v1=667;
        v2=999;
    };

    c(int a, int b) // ctor
    {
        v1=a;
        v2=b;
    };

void dump()
{
    printf("%d; %d\n", v1, v2);
}

int main()
{
    class c c1;
    class c c2(5,6);
    c1.dump();
    c2.dump();
    return 0;
}
```

使用MSVC编译上述程序，可得到如下方所示的代码。

### 指令清单51.1 MSVC

```
_c2$ = -16; size = 8
_c1$ = -8; size = 8
_main PROC

push ebp
mov ebp, esp
sub esp, 16
lea ecx, DWORD PTR _c1$[ebp]
call ??0c@QAE@@XZ ; c::c
push 6
push 5
lea ecx, DWORD PTR _c2$[ebp]
call ??0c@QAE@@XZ ; c::c
lea ecx, DWORD PTR _c1$[ebp]
call ??0c@QAEXXZ ; c::dump
lea ecx, DWORD PTR _c2$[ebp]
call ??0c@QAEXXZ ; c::dump
xor eax, eax
mov ebp, esp
pop ebp
ret 0
_main ENDP
```

我们来看程序是如何实现的。程序为每个对象（类的实例）分配了8个字节内存，正好存储2个变量。

在初始化c1时，编译器调用了无参函数@@0c@@QAE@@XZ。在初始化另一个实例（即c2）时，编译器向有参函数@@0c@@QAE@@HH传递了2个参数。

在传递整个类对象（C++的语言是this）指针时，指针通过ECX寄存器传递给被调用函数。这种调用用规范应当符合thiscall规则，详细请参见阅本的51.1节。

MSVC通过ECX寄存器传递this指针。不过，这种调用约定并没有一种的技术规范。GCC编译器以传递第一个函数的参数的方式传递this指针，其他的编译器多数都遵循了GCC的规则。

为什么这些函数有些很奇怪的名字（见上面？）其实是编译器对函数名称进行的改修名称（name mangling）的结果。

C++的类可以包含相同但不同的方法（类成员函数[ebp]）的多样性。当然，不同的类可以有重命名不同的方法。

名称编码（name mangling）是一种在编译过程中，使用ASCII字符串连接、变量的名称重新改修的机制。改修后的（类成员函数）名称就会被用作程序内部的函数名。这完全是因为编译器的Linker和加载DLL的OS加载器均不能识别C++或OOP（面向对象的语言）的数据结构。

函数()调用了两次。我们再次来看构造函数的指令代码。
```

```
优化编译器的代码这样的。我们需要注意的是：在调用构造函数时，并不是通过“add esp”指令来恢复其初始状态。另一方面，这是因为通过thiscall调用（参见51.1节而且还通过stdcall规范：应当被调用函数恢复参数的初始状态）。使用“add esp”指令把堆恢复到栈，然后程序控制给调用函数。读者还可以参考本书第64章，了解各种调用规范的详细约定。MSVC-x86在86-64环境下的应用程序使用RCX、R8和R9等4寄存器传递函数的前4参数，其他的参数通过栈传递。然而，在调用涉及类成员函数的时候，编译器通过RCX寄存器传递对象的指针，用RCX寄存器传递第一个参数，以此类推。我们可以在类成员函数c(int a, int b)中看到这一点。
```
