```
.LC8:.string "%ld\n"
```

这两段代码的f()函数部分相同。在采用64位参数之后，程序使用了整个64位X 寄存器。通过两条指令才能把长数据类型的64位值存储到寄存器里。本书在 28.3.1节详细介绍64位数据的有关操作。

Non-optimizing GCC (Linaro) 4.9

在没有优化选项的情况下，编译器生成的代码稍冗长：

f:

```
sub    sp, sp, #16
str    w0, [sp,12]
str    w1, [sp,8]
str    w2, [sp,4]
ldr    w1, [sp,12]
ldr    w0, [sp,8]
mul    w1, w0
ldr    w0, [sp,4]
add    w0, w1, w0
add    sp, sp, #16
ret
```

函数f()传入的参数存在数据里，以防止后期的指令占用W0~W2 。可以防止后续指令覆盖函数参数，这种技术叫做“寄存器保护区/Register Save Area” [参见ARM13c]。但是，本例的这种被调用函数可以不这样保存参数。寄存器保护区与8.2.1节介绍的影空间十分相似。

在启用优化选项后，GCC 4.9 会把部分寄存器存储指令删除。这是因为优化功能判断后后续指令就不会操作函数参数的相关地址，所以另用W0~W2中存储的数据。

此外，上述代码使用了MUL/ADD指令，而没有使用MADD指令。
