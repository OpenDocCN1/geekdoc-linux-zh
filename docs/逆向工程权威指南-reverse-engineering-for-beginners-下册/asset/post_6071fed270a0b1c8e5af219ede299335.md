## 14. 1.4 ARM
Non-optimizing Keil 6/2013 (ARM mode)

```
main
  STMFD SP, {R4,LR}
  MOV R4, #2
  B   loc_368
loc_35C ; CODE XREF: main+1C
  MOV R0, R4
  BL  printing_function
  ADD R4, R4, #1
loc_368 ; CODE XREF: main+8
  CMP R4, #0xA
  BLT loc_35C
  MOV R0, #0
  LMFD SP, {R,PC}
```

上述代码中的R4寄存器用于存储循环计数器（即变量i）。

“MOV R4, #2”给变量进行初始化值。

“MOV R0, R4”和“BL printing_function”指令构成循环体。前者负责向被调用函数传递参数，后者则直接调用printing_function ()函数。

“ADD R4, R4, #1”指令在每次迭代之后进行自增的运算。

“CMP R4, #0xA”指令会比较变量和数字10（十六进制的0xA）。下一条指令BLT（Branch Less Than）会在<10的情况下跳转；否则执行。

## 14.1.6 其他

您可能注意到了，在对循环控制变量/初始化赋值值之后，程序首先检查变量是否满足循环条件。在满足循环表达式的情况下，才会运行循环体的指令。这恐怕是有意为之的。如果循环变量的初始值不能满足循环条件，那么整个循环体就不会被执行。例如，下面例子中的循环体可能不会被执行。

```
for (i=0; i<total_entries_to_process; i++)
  loop_body;
```

如果变量total_entries_to_process等于零，就不应当执行循环体。否则，循环控制变量有必要首先检查循环的初始值是否满足循环条件。

在启用优化项后，如果编译器能够判断循环语句的初始状态可能满足循环体的执行条件，那么它可能不会生成该循环体的检测指令和循环体的对应指令。在启用编译器的优化功能之后，内存复制可以做到。
