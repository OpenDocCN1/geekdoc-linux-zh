# On the amanda server

To offer these services to the network in Red Hat Linux, you need to configure the xinetd daemon to listen for those services. You do this by enabling the services in the amandaidx and amixtape files in the /etc/xinetd.d directory. In each of those files, you need to change the disable line to no, as follows:

```
disable        = no
```

This enables Amanda to accept requests from the client system and to start the backup process without any user intervention. You need to tell the xinetd daemon to reload the /etc/xinetd.d files before this change takes place. You can do this by typing the following as root user:

```
# /etc/init.d/xinetd restart
```

# On each amanda client

You next need to configure the .amandahosts file in the /var/lib/amanda directory on each computer (client) that the amanda server will backup from. This file should contain the fully qualified host and domain name of any backup servers that will connect to this client. For example, to create an .amandahosts file on the system dexter.glaci.com that will enable the backup server ratbert.glaci.com to connect, do the following:

```
$ echo ratbert.glaci.com >> /var/lib/.amandahosts
```

You also need to make sure that the amanda client daemon is configured to run on the client. You do this by enabling the service in the amanda file in the /etc/xinetd.d directory. To do that, you need to change the disable line to no, as follows:

```
disable        = no
```

This enables the amanda client to communicate with the amanda server. You need to tell the xinetd daemon to reload the /etc/xinetd.d files before this change takes place. You can do this by typing the following as root user:

```
# /etc/init.d/xinetd restart
```

# Performing an Amanda backup

Now that everything is configured, you are ready to perform an Amanda backup. While logged in as root, type the following command:

```
# /usr/sbin/amdump normal
```

This runs the amdump command and tells it to read the configuration files it finds in the /etc/amanda/normal directory. It then works its way down the list of systems and partitions in the disklist file, backing up each partition in the order it occurs.
