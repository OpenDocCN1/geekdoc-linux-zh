# Table 25-1: Zones and related zone files in DNS example

| Zone | Zone file (in the /var/named directory) |
|---|---|
| . (a single dot representing Internet root servers) | named.ca |
| localhost | localhost.zone |
| 0127.in-addr.arpa | named.local |
| yourdomain.com | yourdomain.com.db |
| 0.0.10.in-addr.arpa | yourlan.db |

Be very careful editing the /etc/named.conf file. Forgetting a semicolon is all too easy, resulting in the entire file not loading. To make sure that the /etc/named.conf file doesn't contain any syntax errors, you can run the following command (as root user):

```
# named-checkconf
```

If a syntax error is present, a message tells you the line that's the problem and what seems to be wrong with it. If the syntax is correct, continue on to create the zone files in the /var/named directory.

# Setting up the zone files

The /var/named directory contains the zone files that the /etc/named.conf file names. For the example, you need to create only two zones from scratch. You can (and should) leave the others as they are.

> **NOTE:** You can replace the root name server's file that comes with the bind package, /var/named/named.ca, with a newer version from ftp.rs.internic.net. You probably don't need to do so, however, because the file doesn't change very often. (It hasn't changed since August 1997.)

The zone files are where most of the real work of the domain name server occurs. In the example, the yourdomain.com.db file contains the basic records for the yourdomain.com domain. The following is an example of the yourdomain.com.db file:

```
$TTL    86400
@       IN      SOA     yourdomain.com.  hostmaster.yourdomain.com.
(
                       2002052701  ; Serial
                       28800       ; Refresh
                       14400       ; Retry
                       3600000     ; Expire
                       86400 )     ; Minimum
; Name servers
                    IN NS       ns1.yourdomain.com.
```
