
To start the new service, type the following (replacing *service* with the name of the service you want to start):

```bash
# /etc/init.d/service stop
```

Providing that the new service was configured properly, it should now be available to the users of your computer.

## Using mail and printing alternatives

The printing and mail-transport services that the alternatives facility allows you to change rely on many of the same command names. For example, both printing services use the `lpr` command to print and the `lpq` command to see a printer queue. Both Postfix and Sendmail have `newalias` command and `mailq` commands for updating aliases and checking the mail queue, respectively.

So, to the user, a change in mail or printing services should (in theory) be nearly invisible. Users can print documents using the same commands they always used and the documents will be printed. Users can send mail as they always did and the fact that a different mail transport is being used should make no difference.

## Getting Linux Software "up2date"

Fixes and improvements continue after a distribution, such as Red Hat Linux 7.3, is released. You can incorporate those fixes and features into Red Hat Linux, using a connection to the Internet and one of several tools for grabbing updated Red Hat software. The tool that Red Hat prefers for keeping its software up to date is called `up2date`.

This section tells you how to determine which updates are available to your Red Hat Linux system. Then it describes how you can register to use the Red Hat Network and use the `up2date` tool to gather those updates.

> **NOTE:** The `up2date` service is for getting fixes to your Red Hat Linux system. It is not used to pick up every change that occurs to the software packages included with Red Hat Linux.

### Checking for updates

How do you know when you need to upgrade the kernel or software packages that make up Red Hat Linux? One way to keep abreast of changes is to visit the Red Hat Errata page. (Red Hat errata information is also available from the Red Hat Network, described in the "Getting updates from the Red Hat Network" section later in this chapter.) Another is to check for updates with maintainers of individual projects whose software is included in Red Hat Linux.

#### Red Hat Errata page

Red Hat gathers information you need to upgrade your system on the Red Hat Errata page (www.redhat.com/errata). As the page proclaims, this is your means of finding “Security Alerts, Bugfixes, and Enhancements” for Red Hat Linux. Select the link to the current release. The list of advisories that appears contains package names, a synopsis of the problem addressed by the corrected packages, and the dates the updates were released.

Many of the advisories are intended to plug potential security holes. In particular, package fixes that address vulnerabilities in network services or mishandled permissions are often included with these advisories. Click on a package name in the list to get a detailed description of the package update, as well as a list of links to sites from which you can download the updated package.

Going directly to the Red Hat Errata page is probably the best way to check on vulnerabilities and bugs relating to your version of Red Hat Linux. Then you can either download and install each new package individually or use the update application (described later in this chapter) to install multiple updates at once.

#### Project Web sites

Most open-source projects have Web sites that are used to track software development, post news, and answer questions about the project. In some cases, critical bugs or security issues may be described at a project's Web site before Red Hat hears of them. If you're operating a public server on the Internet, you might be particularly interested in keeping up with potential problems relating to the network services you are running.

For example, if you are using wu-ftpd as your FTP server software, you can refer to the WU-FTPD Development Group site (www.wu-ftpd.org). Recent news items are posted at that site, of which the security issues might be particularly useful to you. You can also subscribe to wu-ftpd mailing lists from this site. If you don't want to be overrun by e-mail, you might simply want to subscribe to the wuftp-announce list to get occasional announcements about security problems.

Here are some other project sites that you might want to check for information about problems and issues that arise:

- Apache Software Foundation (www.apache.org) — Get updates about Apache Web-server issues.
- Samba.org (www.samba.org) — Find information relating to Windows file- and print-sharing issues.
- Netfilter (Iptables) Firewall (www.netfilter.org) — Find out the latest issues relating to iptables and related firewall tools.

In most cases, you will want to get any updates for Red Hat Linux right from Red Hat. Red Hat does a good job getting critical fixes out in a timely manner. Also, just taking the source code and trying to build and install it directly from a project site, instead of from Red Hat, will probably result in files going to the wrong places and RPMs getting out of sync. The following sections describe how to get your updates directly from Red Hat.

## Getting updates from the Red Hat Network

Red Hat has created a system that automatically notifies you of available updates and lets you easily download and install them on your Red Hat Linux system. The service is called Red Hat Network. Registering with the Red Hat Network allows you to run the `update` program from your Red Hat Linux computer whenever you are ready to do the updates.

Red Hat Network provides a mechanism that can:

- Alert you of the latest fixes and enhancements available for Red Hat Linux
- Install the packages that include those changes to your system

A lot of information about the Red Hat Network is available from its Web page (rhn.redhat.com). This section provides an overview of how the service works and steps you through the registration process.

If you don't mind giving out your e-mail address, street address, and phone number, there are some pretty good reasons for creating a Red Hat Network (RHN) account for yourself. With a free RHN account you can register your Red Hat Linux system and create system profiles. Just registering your first machine also entitles you to receive all updates for that machine. To get more services (or entitle more machines), you can purchase a subscription to RHN.

> **NOTE:** Because Red Hat Network is fairly new and constantly evolving, it is possible that many of the features and entitlements described in this section will change. I recommend that you check the Red Hat Network site (rhn.redhat.com) for information on new features if the procedures in this section seem outdated.

### Running rhn_register

To register your system with Red Hat Network you can use the `rhn_register` command. Using `rhn_register` requires a connection to the Internet and root access to your computer—latter because the registration process needs to access your computer's RPM database. Though only the first computer you register can receive free automatic updates, you can register as many computers as you want with this tool. Here is how it works:

1. Open a Terminal window as root user.
2. Type `rhn_register`. A Network Settings window appears, enabling you to add proxy-server settings in case you need to go through a proxy server to reach the Internet.
3. Enter the proxy information (only if required) and click OK. A Red Hat Registration window appears. (If no GUI is present, the procedure runs in text mode instead.)
4. Read the explanation of the registration procedure and click Next. The Red Hat Privacy Statement appears. This statement includes how your personal information is used and how Red Hat uses cookies to track activities.
5. Read the privacy statement and, if it is acceptable, click Next. The Register or Update User Account window appears.
6. Add information to create a user account and click Next. The information you provide includes:
   - User name — Type a name that you choose.
   - Password — Type a password (then type it again in the next box to verify it).
   - E-mail address — Type the address at which you would like Red Hat to contact you.
   - Organization ID — If you are registering as part of an existing organization, type the organization ID.
   - Organization password — If you entered an organization ID, type the password associated with that ID.
   
   The Register a User Account window appears.
7. Add whatever optional information you feel comfortable about sharing and click Next. This information may include, name, address, phone number, fax number, and information about how you would like to be contacted (e-mail, regular mail, phone, fax, or e-newsletter).
   
   A “Register a System Profile — Hardware” window appears. This window asks you for information about your Red Hat Linux version, host name, IP address, CPU mode, CPU speed, and memory.
8. Select a profile name (the host name is used by default) or service ID number (which can be the computer’s serial number) and click Next.
   
   The registration process begins building a list of packages installed on your computer. These are gathered so they can become part of your system profile. These packages are then displayed in the “Register a System Profile — Packages” window.
9. Check that the packages that appear in the window are all okay to include in your system profile (unselecting the ones you don’t want to include) and click Next.
   
   The Send Profile Information to Red Hat Network window appears.
10. Click Next to register the system-profile information with the Red Hat Network. (Or choose not to send the information by clicking Cancel.) Your information is sent and the Registration Finished window appears.
11. Click Finish to end the session.
    
    After you have finished registering with Red Hat Network you can go to the RHN site and log in to use the service. You are also ready now to run the `up2date` command to update your software packages.
