# ## Using mail and printing alternatives

The printing and mail-transport services that the alternatives facility allows you to change rely on many of the same command names. For example, both printing services use the `lpr` command to print and the `lpq` command to see a printer queue. Both Postfix and Sendmail have `newalias` command and `mailq` commands for updating aliases and checking the mail queue, respectively.

So, to the user, a change in mail or printing services should (in theory) be nearly invisible. Users can print documents using the same commands they always used and the documents will be printed. Users can send mail as they always did and the fact that a different mail transport is being used should make no difference.

# # Getting Linux Software "up2date"

Fixes and improvements continue after a distribution, such as Red Hat Linux 7.3, is released. You can incorporate those fixes and features into Red Hat Linux, using a connection to the Internet and one of several tools for grabbing updated Red Hat software. The tool that Red Hat prefers for keeping its software up to date is called `up2date`.

This section tells you how to determine which updates are available to your Red Hat Linux system. Then it describes how you can register to use the Red Hat Network and use the `up2date` tool to gather those updates.

> > **NOTE:** The `up2date` service is for getting fixes to your Red Hat Linux system. It is not used to pick up every change that occurs to the software packages included with Red Hat Linux.

# ## Checking for updates

How do you know when you need to upgrade the kernel or software packages that make up Red Hat Linux? One way to keep abreast of changes is to visit the Red Hat Errata page. (Red Hat errata information is also available from the Red Hat Network, described in the "Getting updates from the Red Hat Network" section later in this chapter.) Another is to check for updates with maintainers of individual projects whose software is included in Red Hat Linux.
