
- **Command, alias, or function** — If the text begins with regular characters, the shell tries to complete the text with a command, alias, or function name.
- **Host name** — If the text begins with an @ (at) sign, the shell completes the text with a host name taken from the /etc/hosts file.

> **TIP:** To add host names from an additional file, you can set the HOSTFILE variable to the name of that file. The file must be in the same format as /etc/hosts.

Here are a few examples of command completion. (When you see <Tab>, it means to press the Tab key on your keyboard.) Type the following:

```bash
$ echo $0S<Tab>
$ cd -ro<Tab>
$ fing<Tab>
$ mailx root@loc<Tab>
```

The first example causes $0S to be expanded to the $OSTYPE variable. In the next example, -ro is expanded to the root user’s home directory (~/root/). Next, fing is expanded to the finger command. Finally, the address of root@loc is expanded to the computer named localhost (the local computer).

Of course, there will be times when there are several possible completions for the string of characters you have entered. In that case, you can check the possible ways text can be expanded by pressing Esc+? at the point where you want to do completion. Here is an example of the result you would get if you checked for possible completions on $P.

```bash
$ echo $P<Esc+?>
$PATH $PPID $PS1 $PS2 $PS4 $PWD
$ echo $P
```

In this case, there are six possible environment variables that begin with $P. After the possibilities are displayed, the original command line is returned, ready for you to complete it as you choose.

If the text you are trying to complete is not preceded by a $, -, or @, you can still try to complete the text with a variable, user name, or host name. Press the following to complete your text:

- Alt+~ — Complete the text before this point as a user name.
- Alt+$ — Complete the text before this point as a variable.
- Alt+@ — Complete the text before this point as a host name.
- Alt+! — Complete the text before this point as a command name (alias, reserved word, shell function, built-in, and filenames are checked in that order). In other words, complete this key sequence with a command that you previously ran.
- C+x+/ — List possible user name text completions.
- C+x+$ — List possible environment variable completions.
- C+x+@ — List possible host name completions.
- C+x+! — List possible command name completions.

# Additional command line completions

A new set of shell completion rules is available in Red Hat Linux 7.3. These rules are defined in the `/etc/bash_completion` file. Most of these rules let you complete command lines with files that are appropriate to the commands you are running.

NOTE: The bash-completion package must be installed in order to use the completion features described in this chapter. That package causes the `/etc/bash_completion` file to be activated (sourced in) from the `/etc/profile.d/bashopts.sh` file when your bash shell starts after login. If these features don't work, type `source /etc/bash_completion` from the shell. If you get a “No such file or directory” message, you need to install the bash-completion package. If the bash-completion package is not included with the Red Hat Linux distribution (they were considering cutting it at the last moment), you can get it on the Internet by typing `rpmfind bash-completion`.

Here is a quick tutorial that will let you try out some of the bash completion features:

1. Type `cd /tmp` to change to the `/tmp` directory.
2. Create a few files with different file extensions. For example:

```bash
$ touch test.mp3 test.gz test.jpg
```

3. With `/tmp` still as your current directory, type the `ee` command, type the word `test`, and press the Tab key as follows:

```bash
$ ee test<Tab>
```

The word `test.jpg` should appear. This is because the `ee` command (Electric Eyes) can display image files. So bash completion will complete any files ending in `.jpg`, `.gif`, `.png`, `.bmp`, `.xpm`, and several other extensions that indicate image files.

4. Press Ctrl+C to clear the line. Then type the `gunzip` command, type the word `test`, and press the Tab key as follows:

```bash
$ gunzip test<Tab>
```

The word `test.gz` should appear. This is because the `gunzip` command can uncompress compressed file that normally come with file extensions of `.gz`, `.Z`, `.tgz`, and `.Gz`.

5. Press Ctrl+C to clear the line. Then type the `xmms` command, type the word `test`, and press the Tab key as follows:

```bash
$ xmms test<Tab>
```

The word test.mp3 should appear. This is because the xmms command can play audio files that normally come with file extensions of .mp3, .MP3, .ogg, .pls, and .OGG.

If there had been multiple types of files that each command would handle, the completion would have stopped at “test” and allowed you to press Tab again. At that point you would have seen all the files that would have matched the file types supported by the command. For example:

```bash
$ gunzip test<Tab>.<Tab>
test.gz      test.Gz      test.tgz      test.Z
$ gunzip test.
```

Because, in this example, there were four different files in the current directory that matched types supported by gunzip, those four files were displayed after the second Tab. Then the original command line returns, ready for you to type more letters to choose a file or try to match again.

# Command line recall

After you type a command line, that entire command line is saved in your shell’s history list. The list is stored in a history file, from which any command can be recalled to run again. After it is recalled, you can modify the command line, as described earlier.

To view the contents of your history list, use the `history` command. You can either type the command without options or follow it with a number to list that number of the most recent commands. Here’s an example:

```bash
$ history 8
382 date
383 ls /usr/bin | sort -a | more
384 man sort
385 cd /usr/local/bin
386 man more
387 useradd -m /home/chris -u 101 chris
388 passwd chris
389 history 8
```
