+   • The `clienttimeout` parameter sets the number of seconds a connection to a client can be idle before it is dropped. By default, the value is set to 1800 (30 minutes) as follows:
+   
+   clienttimeout: 1800

+   • The `nrnpdcheckart` parameter sets whether or not the INN server daemon should check if an article is on the server before listing it as so. By default, this value is on as follows:
+   
+   nrnpdcheckart: true

+   • The `nrnperlaouth` parameter can be used to cause the INN server to use "Perl hook" to check that readers are valid. If `nrnperlaouth` is `true`, then the connection is not authenticated using the `readers.conf` file, as it would be otherwise. This value is `false` by default, as shown here:
+   
+   nrnperlaouth: false

+   • The `nrnpythonaouth` parameter can be used to cause the INN server to use "Python hook" to check that readers are valid. If `nrnpythonaouth` is `true`, then the connection is not authenticated using the `readers.conf` file, as it would be otherwise. This value is `false` by default, as shown here:
+   
+   nrnpythonaouth: false

+   • With the `noreader` parameter set to `true`, incoming connections from unknown hosts (that is, those not listed in `incoming.conf`), will be rejected. With this value set to `false`, an additional INN server daemon is launched to handle incoming connections from hosts not listed in `incoming.conf`. The default is `false`, as follows:
+   
+   noreader: false

+   • The `readerswhenstopped` parameter can be used to allow newsreaders to connect to the INN server, even if the server is in a paused or throttled state. This feature is only available if the server is spawned from the `innd` daemon process (which it is not by default in Red Hat Linux). The default is `false`, as follows:
+   
+   readerswhenstopped: false

+   • The `readertrack` parameter can be used to enable a system that tracks client reading and posting of articles. Client tracking is off by default (`false`), as follows:
+   
+   readertrack: false

The INN server supports the feature of creating keyword databases from the body of news articles. For large feeds, this could cause a substantial performance hit on the INN server. Before you set any of these parameters, you should stop the INN server (`innd`) and remove the current overview database.
