
# AUTOMATE BACKUPS ACROSS YOUR NETWORK

Set up a smart backup system that monitors folders and duplicates the data to your server

Setting up a centralised backup solution on your network is very useful for your clients; they don't have to worry about doing it. You can conveniently back up at a location of your choice across the network. UrBackup is a free open source backup with support for Unix and Windows clients. While UrBackup is minimal it has some essential features that are important, easy to use and efficient (if the same file is backed from multiple clients it only keeps one copy), reliable backup for files in us, and an easy setup process.

UrBackup can be installed on most of the Linux distros as well as Windows devices like Synology. We will be installing UrBackup on Ubuntu. We will have the UrBackup server using the following:

```
$ sudo apt-get update
sudo apt-get install urbackup-server
```

During the installation, the installer will ask for the backup location. Choose the folder with the most free space available. If you want to compress the backups then you set the location on either a Btrfs or ZFS formatted partition. For added data protection you also consider storing backup files on RAID 5 so that in the event of disk failure data can be easily recovered. After all, a centralised backup server is essential.

Once UrBackup server is running you can access the web interface from http://localhost:5684. By default the credentials are admin/password. Go to Settings, then click "create". Enter the user password here and click create. If you want to receive notifications via email configure the SMTP settings by going to Settings > Mail. If you want to edit the backup folder location you can find from General > Backup Storage Path. For everything else, the default is.

Rsync is an incremental network and remote file copy. You can use rsync to copy files or directories with each other over the network. Rsync only transfers parts of files which are not already transferred. For files, it checks which parts of files have changed and only transfers those parts. Rsync is a very popular tool for transfer. For files on the same computer you can use the following command:

```
$ rsync -fr source
```

This command is simple to use but with differences: in this case the transfer will preserve file permissions and keep partial files. If for some reason you were to cancel the transfer in the middle, this will be resumed. If you disconnect from the network, well. Keep in mind that in this case, rsync needs to be installed on both the sending and receiving systems.

```
$ rsync -fr kun@192.168.1.48:/downloads
```

# ACCESS FILES REMOTELY WITH SSH AND VNC

Log in to your server via command line from anywhere the world, or share your desktop with a remote machine to get a GUI

SSH (Secure Shell) is a common way to log in to a system remotely. OpenSSH is the most popular SSH implementation is available across all the popular platforms: Linux, Windows, Android, OS. To install the OpenSSH-server, use:

```
$ sudo apt-get install openssh-server
```

Once installed, openssh-server is ready for action without further configuration. Log in from a remote machine using:

```
$ ssh username@hostname
```

The username should already exist on the server. By default, OpenSSH is configured for password authentication. A far more secure method is to use public key authentication. On the remote machine, generate public/private pair:

```
$ ssh-keygen -t rsa
```

The above command gives you two files. These are located in ~/.ssh/id_rsa and id_rsa.pub. id_rsa is your private key - do not share this with anybody. Copy the content of id_rsa.pub (public key) and place it in the folder ~/.ssh/authorized_keys on the remote server. Next time, you will log in without a password.

# TIGHTVNC FOR REMOTE DESKTOP SESSIONS

VNC is a desktop sharing system implemented using RFB protocol to share your current desktop over the network. VNC can provide to multiple users of the server with an isolated desktop environment simultaneously. This means all users can run their own desktop in their desktops without interfering with each other.

```
$ sudo apt-get install tightvncserver xfce4-goodies xfce4-server
```

We are also installing a lightweight desktop environment Xfce, which we will use to boot the GUI session for remote users. Autocut is used in order to add copy-paste support between host and the client. We need to configure the desktop environment, to create ~/.vnc/ and add:

```
$ /bin/bash
startxfce4 &
```

Make this executable using sudo chmod +x startup. For each user, a service instance must be created, and for the VNC server, you will set the display number and resolution for multiple users accessing their own desktops you then you need to create a startup file for each user, and assign different display numbers to user in the service file.

You can start the VNC using the following command. Here, the display number on which the VNC server is running. Based on the display number, vncserver will be at :5900. If the display number is 1 it will be at 5901. Now you will need to use any VNC client and connect the server, in which case it would be <serveraddress>:5900.

# SET UP FILE AND MEDIA SERVERS TO SHARE DATA

Stream your movies, music and photo galleries around the house. Below Plex has a UI that makes it easy to follow along with the setup A file server. One of the most used servers is Samba. Due to its sharing protocol it works on all platforms including Linux, OS, Windows, Android. To install the Samba server, refer to the following packages:

```
$ sudo apt-get install samba-common
```

You can configure the server for Samba by editing the file /etc/samba.conf. Let's start with the global section. Here we are setting up the workgroup used to identify the server:

```
workgroup = GROUP
server string = Samba
map to guest = Bad User
```

To set up the log:

```
log file=/var/log/samba
```

To set up the guest account:

```
guest account = myguestuser
```

To set up a guest share (with no password):

```
[SharedFolder]
path=/media/SharedFolder
```

This share will be mapped to the guest account you want to make sure user has full write permissions to access /MyShared/SharedFolder. You can access the shared folder from Windows, Linux and Mac computers. This file is accessible using the URL //Server:IPAddress/MyShared. In order to create a password-protected share, add a group

```
$ sudo adduser smbgrp
```

Adding the user to this group:

```
adduser user1 -G smbgrp
```

Then create the Samba password for the user:

```
$ smbpasswd -a user1
```

Now you have a user that you want to share: user1. This user will have all the necessary permissions to access the folder. The last step is to create the share in smb.conf:

```
[ProtectedShare]
path=/home/user1/shared
```
