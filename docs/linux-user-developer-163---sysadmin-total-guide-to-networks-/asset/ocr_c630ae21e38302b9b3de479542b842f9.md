# Formatting, starting and stopping the daemons

A new HDFS installation needs to be formatted before use, as the formatting process creates an file system by creating the storage directories; the hdfs deformat command is used to stop the daemons across the cluster and the node manager, but before you need to restart Hadoop which is part of the cluster. The slaves files in Hadoop configuration directories contain a list of the hostname or IP addresses that are part of the cluster per node. The slaves file lists the machines that the node manager should run.

resources per cluster and Node Managers running on all the nodes that are used to launch and monitor containers. To run an application on YARN the client contacts the resource manager, then the resource manager directs to the node manager, which launches the application master container.

The configured parameters are:

+   - yarn.nodeman.hostname - the hostname of the node where the resource manager runs
- yarn.nodeman.local-dirs - a list of directories where node manager stores logs and meta-data
- yarn.nodeman.aux-services - a list of auxiliary services run by the node manager
- yarn.nodeman.resource.memory-mb - amount of memory in MB that may be allocated to the container in question
- yarn.nodeman.resource.cpu-cores - number of cores that may be allocated to the container

The HDFS daemon is started with the command start-dfs.sh. This starts the NameNode and by executing hdfs getnamenode, it starts the DataNodes listed in the slaves file, and starts the SecondaryNameNode on the other machines which are executed by executing hdfs getsecondarynamenode. In addition, the other daemons are also started by the start-yarn.sh.

# Other properties

If we need to add or remove nodes of the cluster then you need to configure them in a file that contains a list of authorised machines that join the cluster. The slaves file contains host.dfs.hosts-file. The default buffer size for HDFS is 4KB which can be set by setting the value using the io.file.buffer.size in core-site.xml. Hadoop has a trash facility, which deletes files for a certain period before permanently deleted; use the property trash.interval property to specify the time interval.
