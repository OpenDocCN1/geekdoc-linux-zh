# # TOOLS TO DIAGNOSE
YOUR NETWORK

Sometimes you need to troubleshoot whether host is a mobile client on the network or a remote server. Here, we will talk about some tools that help you with various aspects of the network:

+   * ifconfig: ifconfig can be used to monitor the network interfaces. Without any arguments, ifconfig will list all of the active interfaces.

+   * eth0: Link detected (ethernet) MAC 00:00:56:d2:24:11
  inet 192.168.1.102 netmask 255.255.255.0 broadcast 192.168.1.255

+   * route: the route command will show you the routing table of the system:

| Gateway | Destination | Flags | Metric | Ref | Interface |
| --- | --- | --- | --- | --- | --- |
| 192.168.1.1 | 0.0.0.0 | UG | 0 | 0 | eth0 |
| 192.168.1.0 | 192.168.1.0 | U | 0 | 0 | eth0 |

In the output you can see that traffic with destination network 192.168.1.0 should go via eth0 without any gateway. Default gateways are used when the other destination is not specified.

+   * traceroute: you can find out if a host is reachable through the network or not:

```
$ traceroute google.com
1  192.168.1.1 (192.168.1.1) 1.221 ms 0.941 ms 0.842 ms
2  172.217.16.142 (172.217.16.142) 1.964 ms 2.234 ms 2.237 ms
3  209.852.145.146 (209.852.145.146) 8.600 ms 8.552 ms 8.662 ms
```

+   * ping: you can use ping to verify if a host is reachable on the network or not. It also tells you how long it takes to get a response from the host.

+   * dig: dig is a DNS utility used to verify if your DNS server is behaving correctly. In the following command we will check:
$ dig google.com 8.8.8.8

+   * nettop: is used to monitor the network traffic by process. It helps in identifying which processes are consuming the bandwidth.

| PID | USER | PROGRAM | SENT | RECV | DURATION | BANDWIDTH |
| --- | --- | --- | --- | --- | --- | --- |
| 6487 | root | /usr/bin/python | | 0.548 | 100.0 | KB/sec |

In the output above we can see that the router is running Python, which is consuming 200 KB/Sec. Unlike the other tools used here you will need to install.

Port forwarding through routers. This method works across other routers

```
auto eth0
iface eth0 static
  address 192.168.1.2
  netmask 255.255.255.0
  gateway 192.168.1.1
```

In the above we configure the eth card with the IP address of 10.0.0.2. This can be the service provider's (ISP) gateway or the router's gateway. If so, we are configuring the Ethernet card, which is connected to our local network:

```
auto eth0
iface eth0 static
  address 192.168.1.2
  netmask 255.255.255.0
  gateway 192.168.1.1
```

The next step is to enable Forwarding and Masquerading, using iptables to enable the Linux kernel forwarding:

```
iptables -t nat -A POSTROUTING -o - -j MASQUERADE
iptables -A FORWARD -i eth0 -j ACCEPT
```

You can install and use a package iptables-persistent to save your rules and load them after boot. This can be done by editing /etc/iptables/conf. Add or uncomment the following line:

```
net4.ip_forward=1
```

To make this change without rebooting the system:

```
$ echo 1 > /proc/sys/net/ipv4/ip_forward
```
