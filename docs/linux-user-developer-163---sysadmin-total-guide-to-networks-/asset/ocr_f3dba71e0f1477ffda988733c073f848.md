# Join the swarm

Connect to one of the nodes, i.e. 192.168.0.201, and start the auto_join-swarm.sh script. This will query you the IP address of eth0 and then advertise to connect to the swarm manager.

Start an equal number of node:clusters linking them to the redis containers.

```
# /docker-arm/script/auto_join_swarm.sh
```

You will see the swarm running under docker ps. Check docker logs if you want to see its output. Repeat this step on each of the nodes.

```
# docker run -p 6379:6379 -d \
--name redis-redis \
--link redis:1:redis \
expressis.x redis
```

Final run on the balancer node:

```
# DOCKER_HOST=tcp:// docker run -d --name=balancer -p 80:80 nginx_dynamic
```

# Example: distributed web application

We now set up a distributed database in Redis environment where we increments a counter-field. We will run several instances of it and use an nginx load balancer to handle the traffic. We can then use Apache Bench to test it.

# Direct the traffic to your swarm

If you pull down the docker client on one of them, you can use the DOCKER_HOST variable to point to any swarm nodes without having to log into the Pis. Swarm client creates keys enabling you to scale up a web service from one container to more than one.

These containers need to be started in the correct order, starting with Redis, and finally nginx.

# Start the redis and node containers

First start us in the swarm clusters, giving them a name

```
# docker run -p 6379:6379 -d --name=redis-1 
alexellisiz/redis-arm
```

# Wrapping

We repeat the setup to have enough agents in your cluster. One of the benefits is the distribution of work across nodes, but Swarm also handles the coordination of the nodes. You can find this idea in our Raspberry Pi creations, which might connect some sensors through the GPIO pins and take advantage of your Pi's hardware!
