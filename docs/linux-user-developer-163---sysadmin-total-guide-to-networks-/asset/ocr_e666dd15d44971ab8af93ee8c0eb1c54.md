# Develop server processes that can be unchained from the terminal to run in the background as daemons

A server process is a special kind of process with unique characteristics. The most common feature of processes is that they run in the background without having a controlling terminal associated with them.

As usual, most of the presented code will be written in C. However, you are also going to see examples in Python and Go because these languages allow you to leverage existing modules and libraries. When developing a server for a production system, the server should behave perfectly; therefore, we do not recommend anything except that you plan on a production environment without proper planning, documentation and testing.

First of all, processes usually call fork() to generate a child and terminate the parent process using exit(). Then, they call setsid() to create a new session, because a server should detach from the terminal and run in the background without the need for a terminal.

Servers change their current working directory to root, in order to ensure they are independent of the filesystem structure. They also define the PATH environment variable on their. As you will also see, they usually write their process ID to a file in /tmp the operating system. They use the logging functionality of the system to write various types of messages to log files. Next, they change the file mask in order to interact with the system they run. Finally, they change the creation mask to a known state using umask().
