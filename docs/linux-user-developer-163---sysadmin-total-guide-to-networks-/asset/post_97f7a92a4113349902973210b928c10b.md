# The structure of the tree

A binary tree is a tree where each node may exist at most two other nodes. "Most" means that it can be connected to two or no other node. The height of a tree is defined as the longest path from the root to a node, whereas the depth of a node is the number of edges from the node to the root. A tree is balanced when the length from the root to a node is at most one more than the shortest path.

# The theory

Strictly speaking, a "tree" is a directed acyclic graph that satisfies the following:
- it has a root that is the entry point to the tree
- every vertex, except the root, has one and only one entry point;
- there is a path to every node;
- the edges have a direction
- it has no cycles.

If a binary tree is balanced, its search, insert and delete operations take about log(n) steps where n is the total number of elements. Additionally, the height of a balanced tree is approximately log2(n), which means a tree with 1000 elements has a height of about 10, a tree with 100,000 elements will be about 17, and a tree with 1,000,000 elements will be about 20. Putting a significantly large number of elements into a balanced binary tree does not change the speed of the tree. You can reach any node in 1,000,000 nodes in under 30 steps. The adjacent diagram shows a graphical representation of a small binary tree. You can see that all values are smaller than all values in the sub-tree with the root. In other words, all keys in a binary tree are ordered by design. The good thing is you do not have to take special care with them; putting an element in its right place keeps them ordered. As you will find out, deleting an element from a tree is not trivial because of the way trees are constructed.

	if (root == NULL) {
		if (root->left == key) {
			return 1;
	}
		if (root->right == key) {
			return 1;
	}
		return 0;
