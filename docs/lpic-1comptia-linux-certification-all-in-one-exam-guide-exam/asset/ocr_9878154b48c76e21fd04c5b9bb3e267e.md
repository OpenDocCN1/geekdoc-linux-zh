As you can see in this example, this file simply contains a list of paths in the file system where shared library files are stored. Applications that are linked to functions in these files can search through these paths to locate the appropriate libraries.

**TIP** The `/lib/` and `/usr/lib/` directories are always assumed to contain shared libraries, so they aren't listed in the `/etc/ld.so.conf` file.

To view a list of all shared libraries available on your Linux system, enter `ldconfig -p` at the shell prompt. Here is an example:

```
ws1:~ # ldconfig -p
1423 libs found in cache '/etc/ld.so.cache'
libzypp.so.7.06 (libc6,x86-64) => /usr/lib64/libzypp.so.7.06
libzio.so.0 (libc6,x86-64) => /usr/lib64/libzio.so.0
libz.so.1 (libc6,x86-64) => /lib/libz.so.1
libz.so.1 (libc6) => /lib/libz.so.1
libz.so (libc6,x86-64) => /usr/lib64/libz.so
libzy2util.so.4 (libc6,x86-64) => /usr/lib64/libzy2util.so.4
libzy2.so.2 (libc6,x86-64) => /usr/lib64/libzy2.so.2
libyui.so.3 (libc6,x86-64) => /usr/lib64/libyui.so.3
libyycpvalues.so.3 (libc6,x86-64) => /usr/lib64/libycpvalues.so.3
...
```

**NOTE** If you're not logged in as root, you must specify the full path to `ldconfig` in the command (`/sbin/ldconfig`).

You can also view the shared libraries required by a specific application using the `ldd` command. The syntax is: `ldd -v executable_filename`. For example, if you wanted to see what shared libraries are required by the `ip` command (which is used to manage network connections), you would enter `ldd -v /sbin/ip` at the shell prompt.

**NOTE** You need to specify the full path to the executable along with the executable's filename with the `ldd` command.

An example is shown next:

```
ws1:~ # ldd -v /sbin/ip

\[linux-vdso.so.1 => (0x00007ffe4ab20000)

libdl.so.2 => /lib64/libdl.so.2 (0x00007f7c07e7d000)

libc.so.6 => /lib64/libc.so.6 (0x00007fc081d000)

/lib64/ld-linux-x86-64.so.2 (0x00007fc08081000)
```
