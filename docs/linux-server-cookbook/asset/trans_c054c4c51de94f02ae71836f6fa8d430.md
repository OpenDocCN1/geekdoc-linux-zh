## 结论

良好的**备份**计划定义了策略、需要执行的**恢复**测试以及要使用的存储介质，并指定了**恢复时间目标 (RTO)** 和**恢复点目标 (RPO)**。通常，在企业中，**备份**往往被低估，只有当灾难发生时才会被视为优先事项。

随着**云**及新技术如**容器**的采用，**备份**仍然至关重要，但方法有所不同。可以使用**自动化**从头重建新系统，应用程序以**映像**形式存储。因此，只需存储所需的数据即可。

市面上有多种商业**备份解决方案**，例如 **EMC Networker**、**HP Data Protector** 或 **Symantec NetBackup**。此外，还有成熟的、提供支持的开源解决方案可供使用。本章主要介绍了**Bacula** 作为主要的开源解决方案，以及**Relax-and-Recover (Rear)** 作为完美的裸机灾难恢复解决方案。

### 关键事实

- 良好的**备份计划**对于避免灾难性状况至关重要。
- 需要经常测试**恢复**，以确保副本和恢复协议的完整性。
- 现代系统需要重新思考应在**备份**中存储哪些内容。
- **灾难** **恢复**计划对于关键环境是有用且必需的。
- **Bacula** 是一个成熟的、适用于企业级的开源**备份解决方案**。
- 在*裸机*环境中，**Relax-and-Recover (Rear)** 是完美的解决方案。

# 第 15 章
## 多云管理

### 引言

正如本书所述，许多公司通过迁移到**虚拟化**（不仅包括计算，还包括网络和存储）以及**容器化**环境来现代化其**IT 基础设施**。另一个重大转变是从**本地**基础设施迁移到**公有云**。这种迁移带来了许多优势，但也有一些需要考量的因素。

在多个**云**环境（如 **Amazon Web Services**、**Microsoft Azure**、**Google Cloud** 或 **Alibaba Cloud**）中工作带来了自动化和环境管理方面的新挑战。将**私有云**（如 **OpenStack**）与公共提供商结合被称为**混合云**。

本章将重点介绍不同的**云**提供商、它们提供的不同服务以及它们之间的比较。它将描述使用**公有云**的优势以及劣势。它还将描述管理**多云**的不同策略以及为此使用自动化工具 **Terraform**。

### 结构

在本章中，我们将讨论以下主题：

- 云提供商简介
- 云服务
- 多云管理
- 基础设施即代码
- Terraform

### 云提供商简介

**云提供商**负责提供要消费的各种服务。**云提供商**在过去几十年中已经从提供简单的**计算服务**和**存储服务**发展到提供数百种服务。**云提供商**负责所有基础设施，包括存储、网络、计算和安全。目前提供的一些分类服务如下（Amazon Web Services 提供的类别）：

- **基础设施软件：** 此类别中的服务提供与基础设施相关的解决方案。
  - **备份和恢复：** 用于存储和备份的服务。
  - **数据分析：** 用于数据分析的服务。
  - **高性能计算：** 高性能计算服务。
  - **迁移：** 用于迁移项目的服务。
  - **网络基础设施：** 用于创建网络解决方案的服务。
  - **操作系统：** Linux 和 Windows 操作系统的映像。
  - **安全：** 基础设施的安全服务。
  - **存储：** 与存储相关的服务。
- **DevOps：** 此类别中的服务提供专注于开发人员及开发团队的工具。
  - **敏捷生命周期管理：** 用于敏捷开发的服务。
  - **应用开发：** 用于应用开发的服务。
  - **应用服务器：** 用于应用开发的服务器。
  - **应用堆栈：** 用于应用开发的堆栈。
  - **持续集成和持续交付：** 用于 CI/CD 的服务。
