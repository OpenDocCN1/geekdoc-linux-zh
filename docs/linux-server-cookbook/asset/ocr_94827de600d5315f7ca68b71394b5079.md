# Variable precedence

As described previously, a *variable* can be defined in many different places. If a variable is defined in different places, *Ansible* will use the definition with higher-order precedence. When writing a *Playbook* it is important to define the name of the variables correctly, to avoid accidentally variable overriding. For example, a variable named **port** is a bad option. If we are defining the port for one application, then it is recommended to prefix it with the name of the application, such as **httpd_port**. The following list shows the order of precedence from least to greatest (the last listed variables override all other variables):

+   1. Command line values (for example, `-u my_user`, these are not variables)

+   2. Role defaults (defined in `role/defaults/main.yml`)

+   3. Inventory file group vars

+       a. inventory **group_vars/all**

+       b. inventory **group_vars/\***

+   4. Inventory file host vars

+       a. inventory **host_vars/\***

+   5. Host facts

+   6. Play option **vars**
