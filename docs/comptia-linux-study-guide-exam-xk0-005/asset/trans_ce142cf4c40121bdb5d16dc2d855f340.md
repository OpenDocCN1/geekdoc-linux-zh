

| 选项 | 描述 |
| :--- | :--- |
| -I <i>chain index rule</i> | 将此*新规则*插入到此*链*的此*索引*位置。 |
| -D <i>chain rule</i> | 将此*规则*从此*链*中删除。 |
| -R <i>chain index rule</i> | 将此*规则*从此*链*的此*索引*位置移除。 |
| -F [<i>chain</i>] | 移除（刷新）此*链*中的所有*规则*。如果未指定*链*，则移除所有*链*中的所有*规则*。 |
| -P <i>chain policy</i> | 为此*链*定义此默认*策略*。 |

若要快速查看过滤表中的链和规则，请使用超级用户权限并在 iptables 命令上加上 -L 选项。Listing 18.6 展示了 Fedora 系统上的一个片段示例。

### Listing 18.6: *查看过滤表的链和规则*

```bash
$ sudo iptables -L
Chain INPUT (policy ACCEPT)
target     prot opt source               destination
ACCEPT     udp  --  anywhere             anywhere            udp dpt:domain
[...] 
Chain OUTPUT (policy ACCEPT)
target     prot opt source               destination
ACCEPT     udp  --  anywhere             anywhere            udp dpt:bootpc
OUTPUT_direct all  --  anywhere             anywhere
$
```

请注意，在这种情况下不需要 -t filter 选项。这是因为 iptables 命令默认将命令应用于过滤表。

![](img/c0a399aca0d18f8822d714ad0a173123_592_0.png)

如果你想阻止所有从 Linux 系统发出的数据包，只需将默认的 OUTPUT 链更改为 DROP 策略。请小心，如果你是通过 ssh 进入系统的，这将导致你的连接数据包也被丢弃！Listing 18.7 展示了在 Fedora 系统上阻止所有出站数据包的片段示例。请注意，在此修改后，ping 命令的操作不再被允许。

### Listing 18.7 使用 `iptables` 命令丢弃所有出站数据包

```bash
$ sudo iptables -P OUTPUT DROP
$
$ ping -c 3 192.168.0.105
PING 192.168.0.105 (192.168.0.105) 56(84) bytes of data.
ping: sendmsg: Operation not permitted
[.. .]
$ sudo iptables -P OUTPUT ACCEPT
$
$ ping -c 3 192.168.0.105
PING 192.168.0.105 (192.168.0.105) 56(84) bytes of data.
64 bytes from 192.168.0.105: icmp_seq=1 ttl=64 time=0.062 ms
[.. .]
$
```

在 Listing 18.7 中，当默认的 OUTPUT 链改回 ACCEPT 策略后，ping 数据包被允许通过。

> iptables 服务防火墙仅通过 iptables 命令管理 IPv4 数据包。如果你有 IPv6 数据包经过你的网络，你也必须使用 ip6tables 命令。

要更改链规则，你需要在 iptables 命令中使用一些额外的命令行选项。这些规则选项如表 18.3 所示。

### TABLE 18.3 `iptables` 命令常用的链选项

| 选项 | 描述 |
| :--- | :--- |
| -d address | 仅对具有此目标地址的数据包应用规则 |
| -s address | 仅对具有此源地址的数据包应用规则 |
| -i name | 仅对通过 name 网络接口进来的数据包应用规则 |
| -o name | 仅对通过 name 网络接口出去的数据包应用规则 |
| -p protocol | 仅对使用此协议的数据包应用规则，如 tcp、udp 或 icmp |
| -j target | 将此目标动作（规则）应用于选定的数据包 |

表 18.3 中的 -j 选项需要稍作解释。这是实际应用于已识别数据包的规则。最常用的不同 target 值如下：

- ACCEPT：将数据包传递到下一个链。
- DROP：不将数据包传递到下一个链。
- REJECT：不传递数据包，并向发送方发送拒绝通知。

将规则组合起来并添加到链中有点棘手，因此一个例子会有帮助。在片段 Listing 18.8 中，显示了一个 IP 地址为 192.168.0.104 的 Ubuntu 系统成功地向 IP 地址为 192.168.0.105 的远程 Fedora 系统发送 ping。

### Listing 18.8: 成功向远程系统发送 ping

```bash
$ ip addr show | grep 192.168.0.104
inet 192.168.0.104/24 brd 192.168.0.255 [...] enp0s8
$
$ ping -c 1 192.168.0.105
PING 192.168.0.105 (192.168.0.105) 56(84) bytes of data.
64 bytes from 192.168.0.105: icmp_seq=1 ttl=64 time=0.305 ms

--- 192.168.0.105 ping statistics ---
1 packets transmitted, 1 received, 0% packet loss, time 0ms
rtt min/avg/max/mdev = 0.305/0.305/0.305/0.000 ms
$
```

现在，在 Fedora 系统上，使用超级用户权限，发出以下命令：`sudo iptables -I INPUT -s 192.168.0.104 -j REJECT`

这条新规则将被插入（-I）到 INPUT 链的过滤表中，索引为 1（链中的第一条规则）。任何来自源（-s）地址 192.168.0.104（Ubuntu 系统）的数据包都将被拒绝（REJECT）。现在既然此规则已就位，当 Ubuntu 系统尝试 ping Fedora 系统时，它将失败，如片段 Listing 18.9 所示。

### Listing 18.9: 阻止向阻止数据包的远程系统发送 ping

```bash
$ ping -c 1 192.168.0.105
PING 192.168.0.105 (192.168.0.105) 56(84) bytes of data.
From 192.168.0.105 icmp_seq=1 Destination Port Unreachable

--- 192.168.0.105 ping statistics ---
1 packets transmitted, 0 received, +1 errors, 100% packet loss, time 0ms
$
```

![](img/c0a399aca0d18f8822d714ad0a173123_594_0.png)

你不必局限于 'iptables' 的默认链——你实际上可以创建自己的链。如果你想使用 LOG 目标创建特定数据包的日志文件，这尤其有用。请在 iptables 以及 iptables-extensions 的手册页中查找更多详细信息。

虽然你不需要重新加载 **iptables** 服务才能让新修改的规则生效，但这些规则没有*持久性*。换句话说，如果系统重启或 **iptables** 服务重新启动，你将丢失所有这些新增或修改的 ACL 规则。

只要 **iptables** 服务被启用以在系统启动时启动，Red Hat 和基于 Red Hat 的发行版（如 Fedora 和 Rocky Linux）将自动加载存储在这些文件中的 **iptables** 规则：

- IPv4 规则：`/etc/sysconfig/iptables`
- IPv6 规则：`/etc/sysconfig/ip6tables`

Debian 和基于 Debian 的发行版（如 Ubuntu）需要安装并启用额外的软件包 **iptables-persistent**。此包用于加载持久规则的文件如下：

- IPv4 规则：`/etc/iptables/rules.v4`
- IPv6 规则：`/etc/iptables/rules.v6`

![](img/c0a399aca0d18f8822d714ad0a173123_595_0.png)

你不会在本书推荐的发行版版本中找到 **iptables** 服务的这些规则文件，因为它们使用较新的防火墙技术。如果需要，你可以使用 Fedora 版本 20 或更早版本来玩弄这些 **iptables** 文件。

如果你需要保存当前的 **iptables** 规则，请使用 **iptables-save** 命令。由于默认情况下它会将规则发送到 STDOUT，因此此实用程序需要将其输出重定向到文件。

要恢复保存的 **iptables** 规则，请使用 **iptables-restore** 命令。此实用程序需要将其输入从文件重定向。因此，如果你在测试一个工作不佳的 ACL 更改，你可以快速恢复 **iptables** 的原始规则。在较旧的 Fedora 发行版中，你使用超级用户权限并发出 **iptables-restore** < **/etc/sysconfig/iptables** 命令来恢复所有原始 IPv4 规则。

## 探索 nftables

你可能已经注意到，在 **iptables** 中创建规则的格式有时会变得相当复杂，尤其是与 **firewalld** 等工具相比。**nftables** 服务是一个很好的折中方案。

**nftables** 服务提供了类似 **iptables** 的低级访问 **netfilter** 链的能力，使其极其高效且快速。然而，**nftables** 中构建规则的命令语法已简化，使其更易于使用。

**nftables** 服务利用与 **iptables** 相同的表、链、策略和规则概念。你可以使用 **nft** 命令的 **list** 选项列出已定义的现有表，如 Listing 18.10 所示。
