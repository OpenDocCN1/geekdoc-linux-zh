
## 第 25 章：部署 Bash 脚本

- 1. B. `#!` 字符组合定义了 shebang（解释器指令），它告诉 Linux  shell 使用哪种 shell 来运行 shell 脚本代码，因此选项 B 正确。`>>` 字符组合将命令的输出追加到文件中，因此选项 A 错误。`|` 字符将命令的输出管道传输到另一个命令，因此选项 C 错误。`>` 字符将命令的输出重定向到新文件或覆盖现有文件，因此选项 D 错误。`2>` 字符组合将命令的错误消息重定向到文件中，因此选项 E 错误。

- 2. D. `>` 字符将命令的所有输出重定向到新文件，或覆盖现有文件，因此选项 D 正确。`>>` 字符组合将命令的所有输出追加到现有文件中，因此选项 A 错误。`#!` 组合定义了要使用的 shell，因此选项 B 错误。`|` 字符将一个命令的输出管道传输到另一个命令，因此选项 C 错误。`2>` 字符组合仅将命令的错误消息重定向到新文件，而不是所有输出，因此选项 E 错误。

- 3. C. `u+x` chmod 权限为文件所有者分配执行权限，使您可以在命令提示符下运行该文件，这使得选项 C 正确。`644` 八进制权限仅为文件所有者分配读和写权限，而不分配执行权限，因此选项 A 错误。`u+r` 权限分配读权限，而非执行权限，因此选项 B 错误。`u-w` 权限仅分配写权限，而不分配执行权限，因此选项 D 错误。`u-wr` 权限为文件所有者同时分配读和写权限，但不分配执行权限，因此选项 E 错误。

- 4. A. `$USER` 环境变量包含启动 shell 的用户账户的文本用户名，因此选项 A 正确。`$UID` 环境变量包含数字用户 ID，而非文本用户名，因此选项 B 错误。`$HOME` 环境变量包含用户账户的主目录位置，而非用户名，因此选项 C 错误。`$BASH` 环境变量包含 Bash shell 可执行文件的位置，而非启动 shell 的用户名，因此选项 D 错误。`$1` 变量是一个位置变量，而非环境变量。它用于从启动 shell 的命令行命令中检索数据，而非标识启动 shell 的用户，因此选项 E 错误。

- 5. C. 要为变量赋值，请使用等号，但变量名、等号和值之间不能使用空格，因此选项 C 正确。选项 A 使用了命令替换格式，这不会将值分配给变量，而是分配给命令的输出，因此选项 A 错误。选项 B 在变量名、等号和值之间放置了空格，因此选项 B 错误。选项 D 在值周围加上了引号，使其成为字符串值而非数值，因此选项 D 错误。选项 E 在值周围使用了反引号字符，这试图使用命令替换来运行它，这是不正确的。

- 6. B. `-f` 文件测试检查指定的对象是否存在，以及它是否是一个文件，因此选项 B 正确。`-e` 文件测试检查对象是否存在，而不检查对象类型，因此选项 A 错误。`-d` 文件测试检查对象是否存在但是一个目录而非文件，因此选项 C 错误。`-x` 文件测试检查当前用户账户对该文件是否具有执行权限，而非检查对象是否存在且是一个文件，因此选项 D 错误。`-w` 文件测试检查当前用户账户对该文件是否具有写权限，而非检查对象是否存在且是一个文件，因此选项 E 错误。

*注意：第 6 项中的 OCR 错误已根据标准的 Linux 文件测试标志（-f, -e, -d, -x, -w）进行了更正，这些标志被误识别为通用的 'file' 测试。*

- 7. C. 竖线字符（`|`）将一个命令的输出管道传输到另一个命令的输入，因此选项 C 正确。`>>` 字符组合将命令的输出追加到现有文件中，而非另一个命令，因此选项 A 错误。Shebang（`#!`）用于标识运行脚本时要使用的 shell，而非将命令的输出重定向到另一个命令，因此选项 B 错误。`>` 字符将命令的输出重定向到新文件，而非另一个命令，因此选项 D 错误。`2>` 字符组合将命令的错误消息重定向到新文件，而非另一个命令，因此选项 E 错误。

- 8. D. `exit` 命令允许您在 shell 脚本退出时返回特定的错误状态，因此选项 D 正确。`#!` shebang 定义了运行 shell 脚本时要使用的 shell，而非退出状态，因此选项 A 错误。`$?` 字符组合显示上一条命令的退出状态；它不会返回特定的错误状态，因此选项 B 错误。`$1` 变量包含在从命令行启动 shell 脚本时使用的第一个命令行参数；它不会为 shell 脚本设置退出状态，因此选项 C 错误。`while` 命令允许您迭代一组命令，直到满足特定条件；当 shell 退出时，它不会返回特定的退出状态，因此选项 E 错误。

- 9. E. `$()` 命令将命令的输出分配给 shell 脚本中指定的变量，因此选项 E 正确。`>` 字符将命令的输出重定向到文件，而非变量，因此选项 A 错误。`>>` 字符组合将命令的输出追加到现有文件，而非变量，因此选项 B 错误。`$[]` 命令在 Bash shell 中执行整数数学运算，因此选项 C 错误。`|` 字符将命令的输出重定向到另一个命令，而非变量，因此选项 D 错误。

- 10. C. `$[]` 命令在 Bash shell 中执行简单的整数数学运算，因此选项 C 正确。`>` 字符将命令的输出重定向到新文件，因此选项 A 错误。`>>` 字符组合将命令的输出追加到现有文件，因此选项 B 错误。`|` 字符将命令的输出重定向到另一个命令，因此选项 D 错误。`$()` 命令将命令的输出重定向到 shell 脚本中的变量，因此选项 E 错误。

## 第 26 章：自动化任务

- 1. B. 与号字符 (&) 告诉 shell 从控制台会话以后台模式启动命令，因此选项 B 正确。大于号 (>) 将命令的输出重定向到文件，因此选项 A 错误。管道符号 (|) 将命令的输出重定向到另一个命令，因此选项 C 错误。双大于号 (>>) 将命令的输出追加到文件，因此选项 D 错误。`nohup` 命令将会话与控制台会话断开，因此选项 E 错误。

- 2. E. `nohup` 命令将 shell 脚本与当前控制台会话断开，因此选项 E 正确。大于号 (>) 将命令的输出重定向到文件，因此选项 A 错误。与号 (&) 以后台模式运行 shell 脚本，因此选项 B 错误。管道符号 (|) 将命令的输出重定向到另一个命令，因此选项 C 错误。双大于号 (>>) 将命令的输出追加到文件，因此选项 D 错误。

- 3. C. Ctrl+C 键组合停止当前在控制台会话上以前台模式运行的任务，因此选项 C 正确。使用 `nohup` 命令启动命令会将任务与控制台会话断开，因此您无法通过控制台上的键命令停止它，这使得选项 A 错误。使用与号 (&) 命令启动任务会将任务置于后台模式，但不允许您停止该任务的运行，因此选项 B 错误。管道符号将 shell 脚本的输出重定向到另一个命令，因此选项 D 错误。`kill` 命令可以停止正在运行的 shell 脚本，但如果 shell 脚本在您的控制台会话中运行，您将无法从控制台提示符提交 `kill` 命令，因此选项 E 错误。
