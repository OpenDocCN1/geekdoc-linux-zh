
### 清单 18.10：在 nftables 中列出表

```bash
$ sudo nft list tables
table ip filter
table ip6 filter
table bridge filter
table ip security
table ip raw
table ip mangle
table ip nat
table ip6 security
table ip6 raw
table ip6 mangle
table ip6 nat
table bridge nat
table inet firewalld
table ip firewalld
table ip6 firewalld
$
```

请注意，在 Red Hat 系统中，`firewalld` 服务会在 `netfilter` 中创建自己的表，而 nftables 能够检测到这些表。要创建一个新表，请在 `nft` 中使用 `add table` 选项，如清单 18.11 所示。

### 清单 18.11：使用 nftables 创建新表

```bash
$ sudo nft add table ip rich
$ sudo nft list tables ip
table ip filter
table ip security
table ip raw
table ip mangle
table ip nat
table ip firewalld
table ip rich
$ sudo nft list table ip rich
table ip rich {
}
$
```

`add` 命令创建了名为 `rich` 的表，但如清单 18.11 所示，该表默认为空。

创建表后，下一步是创建链（chains），其中将包含您为防火墙定义所设定的规则。正如您预期的一样，`add chain` 选项用于执行此操作。`add chain` 选项的基本格式如下：

```text
nft add chain [family] table_name chain_name { type type hook hook priority value ; [policy policy ;] [comment "text comment" ;] }
```

`type` 值可以是 filter、router 或 nat（与 iptables 相同），而 `hook` 值可以是 prerouting、input、forward、output 或 postrouting（同样与 iptables 相同）。priority 值决定了链的处理顺序；较低的优先级值会先被处理。policy 值可以是 accept 或 drop。清单 18.12 展示了创建链的一个示例。

### 清单 18.12：使用 nftables 创建新链

```bash
$ sudo nft 'add chain ip rich test { type filter hook input priority 0; policy drop; }'
$ sudo nft list table ip rich
table ip rich {
    chain test {
        type filter hook input priority 0; policy drop;
    }
}
$
```

如清单 18.12 所示，您必须用单引号将 `add chain` 命令括起来。此链的默认策略设置为 `drop`，因此除非匹配到指示不同的规则，否则所有传入的数据包都将被丢弃。

一旦创建了链，您就可以使用 `add rule` 选项为链定义要应用的规则。规则的格式是 nftables 的一个卖点。该格式使用简单的语法，类似于流行的 tcpdump 监控程序所使用的语法。清单 18.13 展示了一个添加允许 SSH 流量的规则的示例。

### 清单 18.13：使用 nftables 添加新规则

```bash
$ sudo nft 'add rule ip rich test tcp dport ssh accept'
$ sudo nft list table ip rich
table ip rich {
    chain test {
        type filter hook input priority 0; policy drop;
        tcp dport 22 accept
    }
}
$
```

清单 18.13 显示规则已被添加到 `test` 链中。然后，您可以在同一链中创建额外的规则，或者创建具有不同优先级的额外链来包含更多规则。

要从表中删除规则，请使用 `flush` 表选项：

```bash
$ sudo nft flush table ip rich
$ sudo nft list table ip rich
table ip rich {
    chain test {
        type filter hook input priority 0; policy drop;
    }
}
$
```

要从表中删除链，请使用 `delete chain` 选项。要删除整个表，请使用 `delete table` 选项：

```bash
$ sudo nft delete table ip rich
$ sudo nft list tables ip
table ip filter
table ip security
table ip raw
table ip mangle
table ip nat
table ip firewalld
$
```

> 如果您决定使用 nftables 作为防火墙，建议禁用其他防火墙软件，例如 iptables、firewalld 或 ufw。因为它们都使用相同的 netfilter 服务，每个防火墙配置中的规则可能会发生冲突——或者至少当您试图弄清楚为何某些内容被阻止或允许时，会使事情变得极其复杂。

## 了解 UFW

Ubuntu 发行版的默认防火墙服务是简单防火墙（UFW）。它可以通过 `ufw` 命令行实用程序或 GUI 中的 `Gu fw` 进行配置。

![](img/c0a399aca0d18f8822d714ad0a173123_599_0.png)

默认情况下，UFW 服务是禁用的。您可以使用 `sudo ufw enable` 命令启动服务并设置其在启动时自动运行，但不要使用系统初始化工具，如 `sysv-rc-conf`。这是因为此处涵盖的防火墙服务不是传统的 SysV 或 systemd 服务，而是 netfilter 防火墙的接口服务。因此，如果您选择启动 UFW，请注意 iptables 或 firewalld 服务不能处于运行状态。

有几种 UFW 命令可以让您控制防火墙的状态以及查看其状态。这些命令显示在表 18.4 中。每一个命令都需要超级用户权限。

### 表 18.4 用于控制状态和查看状态的 ufw 命令

| 命令 | 描述 |
| :--- | :--- |
| `ufw enable` | 启动 UFW 防火墙并启用其在系统启动时启动 |
| `ufw disable` | 停止 UFW 防火墙并禁用其在系统启动时启动 |
| `ufw reset` | 禁用 UFW 防火墙并将其重置为安装默认设置 |
| `ufw reload` | 重新加载 UFW 防火墙 |
| `ufw status` | 显示 UFW 防火墙的当前状态 |

要查看 UFW 服务的当前状态，如果需要比仅 `status` 提供的更多信息，请使用 `sudo ufw status verbose`。启用 UFW 防火墙服务并查看其当前状态的片段显示在清单 18.14 中。

### 清单 18.14 启用 UFW 并查看其状态

```bash
$ sudo ufw enable
[...]
Firewall is active and enabled on system startup
$
$ sudo ufw status verbose
Status: active
Logging: on (low)
Default: deny (incoming), allow (outgoing), disabled (routed)
New profiles: skip
$
```

查看 UFW 防火墙的冗长状态提供的信息有助于解释其配置：

-   **状态**：UFW 服务正在运行并将在系统启动时启动（active），或者服务已停止且系统启动不会改变此状态（disabled）。
-   **日志记录**：该服务的日志记录功能可以设置为 off；记录所有被阻止的数据包（low），这是默认设置；记录所有被阻止、无效、无策略匹配和新连接的数据包（medium），并施加速率限制；记录 medium 日志级别的数据包和所有其他数据包（high），并施加速率限制；以及记录所有内容且不施加速率限制（full）。
-   **默认值**：显示传入、传出和路由数据包的默认策略，这些策略可以设置为允许数据包、丢弃（deny）数据包，或拒绝数据包并发送拒绝消息。
-   **新配置文件**：显示自动将新配置文件加载到防火墙的默认策略，可以设置为 ACCEPT、DROP、REJECT 或 SKIP，其中 ACCEPT 被视为安全风险。

各种默认 UFW 策略存储在 `/etc/default/ufw` 配置文件中。首次安装时，这些设置允许所有传出连接并阻止所有传入连接。您可以使用 `ufw` 命令及其各种参数根据需要修改防火墙。表 18.5 展示了一些常用参数。

### 表 18.5 ufw 命令的常用参数

| 参数 | 描述 |
| :--- | :--- |
| `allow <Identifiers>` | 将 `<Identifiers>` 标识的规则设置为允许数据包 |
| `deny <Identifiers>` | 将 `<Identifiers>` 标识的规则设置为拒绝（丢弃）数据包 |
| `reject <Identifiers>` | 将 `<Identifiers>` 标识的规则设置为拒绝数据包 |
| `delete RULE \| NUM` | 删除由 RULE 或 NUM 标识的规则 |
| `insert NUM RULE` | 在索引 NUM 处插入规则 |
| `default POLICY DIRECTION` | 修改默认 DIRECTION 策略，其中 POLICY 为 allow、deny 或 reject，direction 为 incoming、outgoing 或 routed |
| `logging LEVEL` | 设置日志记录级别，其中 LEVEL 为 on、off、low（默认）、medium、high 或 full |

在创建新的 UFW 规则时，您可以使用简单或完整语法。简单语法涉及仅使用端口号或其服务名称来指定规则。您还可以将协议添加到端口号中，如清单 18.15 所示。
