# Notes

GNU mv is implemented as in and rm. When you execute the mv utility, it first makes a link (ln) to the new-file and then deletes (rm) the existing-file. If the new-file already exists, mv may delete it before creating the link.

As with rm, you must have write and access permission to the parent directory of the existing-file, but you do not need read or write access to the file itself. If the move would overwrite an existing file that you do not have write permission for, mv displays the access permission and waits for a response. If you enter y or yes, mv renames the file; otherwise, if you do not use the -f option, mv does not prompt you for a response but simply overwrites the file.

If the existing-file and the new-file directory are on different filesystems, GNU mv copies the file instead of renaming it. In this case, after a file is copied, the user who moved it becomes the owner of the file.

Although earlier versions of mv could move only ordinary files between filesystems, mv can now move any type of file, including directories and device files, from one filesystem to another.

# Examples

The first command line renames letter, a file in the working directory, as letter.1201:

```
$ mv letter.1201
```

The next command line renames the file so that it appears, with the same filename, in the /usr/archives directory:

```
$ mv letter.1201 /usr/archives
```

The following command line renames all the files in the working directory whose names begin with memo so they appear in the /usr/backup directory:

```
$ mv memo* /usr/backup
```

# nice

Changes the priority of a command

nice [option] [command line]

The nice utility reports the priority of the shell or alters the priority of a command line. An ordinary user can decrease the priority of a command. Only Superuser can increase the priority of a command. The TC Shell has a nice builtin that has a different syntax. Refer to “Notes."

The command line is the command line you want to execute at a different priority. Without any options or arguments, nice reports the priority of the shell running the nice command.

# Arguments

# Options

Without an option, nice defaults to an adjustment of 10, typically from 0 to 10. (As you raise the priority value, the nice command runs at a lower priority.)

- - n value Changes the priority by an adjustment of value. The range of priorities is from -20 (the highest priority) to 19 (the lowest priority). A positive value lowers the priority, whereas a negative value raises the priority. Only Superuser can specify a negative value. When you specify a value past either end of this range, the priority is set to the limit of the range.

# Notes

The TC Shell has a nice builtin. Under test, nice ±value command line changes the priority at which command line is run. You must include the plus sign for positive values.

Higher (more positive) priority values means that the kernel schedules a job less often, whereas (more negative) values causes the job to be scheduled more often.

When Superuser schedules a job to run at the highest priority, it can impact the performance of the system for all other jobs, including the operating system itself. For this reason use nice with negative values carefully.

# Example

The following command executes find in the background at the lowest possible priority. The ps -l command displays the nice value of the command in the NI column:

```
# nice -n 19 find / -name core -print corefiles.out &
[1] 2610
# ps -l
F UID PID PPID C PRI NI ADDR SZ WCHAN TTY TIME CMD
100 S 0 1099 1097 0 75 0 605 wait4 pts/0 00:00:00 bash
100 R 0 2610 1099 0 99 19 634 - pts/0 00:00:03 find
100 R 0 2611 1099 0 99 19 634 - pts/0
```

# nohup

Runs a command that keeps after you out

nohup [command line]

The nohup utility runs a command and keeps it running after you log out. The TC Shell has a nohup-like builtin. Refer to "Notes."

# Arguments

The command line is the command line you want to execute.

# Notes

The nohup utility allows you to run a command even after you log out. The TC Shell has a nohup-like builtin.

# od

Dumps the contents of a file

od [options] [file-list]

The od (octal dump) utility dumps the contents of a file, which is useful for viewing executable (object) files and text files with embedded nonprinting characters. This utility takes its input from the file you specify or standard input.

# Arguments

The file-list includes the pathnames of the files od displays. When you do not specify a file-list, od reads from standard input.

# Options

- --address-radix=base A base used when displaying the offsets shown for positions. By default, offsets are given in octal.
-format=type t type Determines the output format to use when displaying data from the file. You can repeat this option with different types to see the file in several formats. The possible values for type are
- Named character. Nonprinting characters are displayed using their official names. For example, FORMFEED is displayed as ff.
- ASCII character.
- d Signed decimal.
- f Floating point.
- o Octal (default).
- u Unsigned decimal.
- x Hexadecimal.

The od utility displays certain nonprinting characters as printing characters preceded by a backslash (Table III-22). It displays nonprinting characters that are not in the file as three-digit octal numbers.

# Symbol

| | |
| \0 | NULL |
| \a | BELL |
| \b | BACKSPACE |
| \f | FEED |
| \n | NEWLINE |
| \r | RETURN |
| \t | HORIZONTAL TAB |
| \v | VERTICAL TAB |

By default od dumps a file as 2-byte octal numbers. You can change both the type of number it dumps and the number of bytes it reads to compose each number. The types in Table III-23 can be suffixed by length indicators from Table III-24.

# type

| | |
| d (decimal) | Displays data as signed decimal values |
| o (octal) | Displays data as unsigned octal values |
| u (unsigned decimal) | Displays data as unsigned decimal values |
| x (hex) | Displays data as unsigned hexadecimal values |

The length indicators in Table III-24 can follow any of the d, o, u, or x types to indicate how many bytes should be read to compose each number.
