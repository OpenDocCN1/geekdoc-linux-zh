The first if statement in lnks tests whether lnks was called with zero or more than two arguments:

```
if [ $ -eq 0 -o $- -gt 2 ]; then
echo "Usage: lnks file [directory]" 1>&2
exit 1
```

If these conditions are true, lnks sends a message to standard error and exits with a status of 1. The double quotation marks around the brackets prevent the shell from interpreting the brackets as special characters. The brackets in the usage message indicate to the user that the directory argument is optional.

The second statement tests to see whether $1 is a directory (the -d argument) returns a true if the file exists and is a directory:

```
if [ -d$1" ]; then
echo "First argument cannot be a directory." 1>&2
echo "Usage: lnks file [directory]" 1>&2
exit 1
else
file="$1"
```

If it is a directory, lnks presents a usage message and exits. If it is not a directory, lnks saves the value of $1 in the file variable later in the script sets the command line arguments. If the value of $1 is not saved before the command is issued, its value is lost.

The next section of lnks is if...then...elif statement:

```
if [ $ -eq 1 ]; then
directory="."
elif [ -d $2" ]; then
directory="$2"
else
echo "Optional second argument must be a directory." 1>&2
echo "Usage: lnks file [directory]" 1>&2
exit 1
```

The first test-command determines whether the user specified a single argument on the command line. If the test-command returns 0 (true), the user-created variable directory is assigned the value of the working directory (.). If the test-command returns a false value, the elif statement tests whether the second argument is a directory. If it is a directory, the directory variable is set equal to the second command line argument, $2. If $2 is not a directory, lnks sends a message to standard error and exits with a status of 1.
