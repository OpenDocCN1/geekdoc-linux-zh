The -f option causes ps to display the full command line, which includes the name of the shell running the script. The $0 variable holds the name of the calling program, so grep looks through the lines output by ps -f for the name of the program. It displays two lines: one for tsh and the other for grep, which is running under tsh.

If you do not follow the # with the name of an executable program, the shell reports that it cannot find the command you asked it to run. You can optionally follow #! with Spaces. If you omit the #! line and try to run, for example, a script from bash, the shell generates error messages, or the script may not run properly.

# Begins a Comment

Comments make shell scripts and all code easy to read and maintain by you or others. The comment syntax is common to the Bourne Again, TC, and Z Shells. If a pound sign (#) in the first character position of the first line of a script is not immediately followed by an exclamation point (!) or if a pound sign occurs in any other location in a script, the shell interprets it as the beginning of a comment and ignores everything between the pound sign and the end of the line (the next newline character).

# Startup Files

When a shell starts, it runs startup files (scripts) with commands in them to initialize itself. While the shell runs depends on whether it is a login shell, an interactive shell that is not a login shell, or a noninteractive shell—one used to execute shell scripts.

When bash starts as a login shell or if you use the -login option when starting bash, bash first reads /etc/profile for commands. Then a bash shell looks in your home directory for .bash_profile and executes it. Otherwise, it executes .bash_login. If neither of these files exists, bash executes .profile file. When you log out, this shell reads and executes commands from the .bash_logout file in your home directory, if it exists (Table 12-1).

When bash is started as a noninteractive shell (such as when by getting the command bash), bash reads only the .bashrc file. However, this shell inherits any environment (exported) variables from the parent shell, so environment variables set in /etc/profile and .bash_profile are passed to the nonlogin shell.

Finally, however, noninteractive shells (shells that have standard input and standard output not connected to your terminal) look for the environment variable BASH_ENV and then ENV, if BASH_ENV does not exist. If either of these environment variables has a value, the shell reads and executes commands from this file.
