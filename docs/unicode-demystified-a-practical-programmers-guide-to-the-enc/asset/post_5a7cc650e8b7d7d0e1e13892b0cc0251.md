```
who:x:1000:1000:execute who:/usr/bin/who
```

# Do Not Replace a Login Shell with a Shell Script

Be careful when using special shells in place of login shells in /etc/passwd. Do not use scripts
as replacements for shells. A user may be able to interrupt a shell script, giving him or her full shell
access when you did not intend to do so. When installing a dummy shell, use a compiled program, not as shell script.

Following is an example of an /etc/profile file that displays the message of the day (/etc/motd), sets the file-creation mask (umask), and sets the interrupt character to CTRL-C:

```
# cat /etc/profile
cat /etc/motd
umask 022
stty intr '^'C'
```

Take a look at the /etc/profile file on your system as another example. Following is a more extensive /etc/profile file:

```
# cat /etc/profile
# /etc/profile

# System wide environment and startup programs
# Functions and aliases go in /etc/bashrc

PATH="$PATH:usr/X11R/bin"

PS1="[\u@\h \W]\$"

	ulimit -c 1000000
	if [ $(id -gn) = 'id -un' -a 'id -u' -gt 14 ]; then
	umask 022
else
	umask 022
fi

USER=$(id -un)
LOGNAME=$USER
MAIL="/var/spool/$USER"

HOSTNAME='/bin/hostname'
HISTSIZE=1000
HISTFILESIZE=1000
LESSOPEN="/usr/bin/lessipe.sh %s"

export PATH HOSTNAME HISTSIZE USER LOGNAME MAIL LESSOPEN
export LESS=-X
export HISTCONTROL=ignoreddups
shopt -s cdspell

for i in /etc/profile.d/*.sh; do
	if [ -x $i ]; then
	. $i
done
unset i
```

The init program executes several commands each time it changes state or runlevel. The /etc/rc.d/init.d directory holds all the scripts. Each runlevel has a dedicated directory within /etc/rc.d. For example, runlevel 3 has the /etc/rc.d/runlevel3 directory. The files in each of these directories are links to the files in init.d. The rc scripts perform such tasks as mounting files (when the system goes multiuser, removing temporary files when the system is returned to single-user mode). For more information refer to “rc: Start and Stop Services” on page 944.

/etc/shadow Contains encrypted MD5 hashed passwords. Each entry occupies one line composed of nine fields, separated by colons:

```
login-name:password:last-mod:min:max:inactive:expire:flag
```

The login-name is the user enters in response to the login prompt or the password puts into this file. If unauthorized access is not a problem, the password field can be null. When logging in, the user first can run passwd to select a password. Otherwise, you can run passwd while being root to assign a new password. The last-mod indicates when the password was last modified. The min is the minimum number of days that must elapse before the password can be changed; max is the maximum number of days before the password must be changed. warn specifies how much inactive (in days) gives the user before the account expires. The number of days between login sessions exceeds the inactive field. The account will also be closed as the date in the expire field. The last field in an entry, flag, is reserved for future use. The shadow file should be owned by root and not be publicly readable or writable, making it more difficult for someone to break into your system by identifying accounts without passwords or using specialized programs. A number of conventions exist for making shadow entries. An entry of * in the password field indicates locked and different from an empty password implying that this is an administrative account that never logs in directly. Occasionally programs run with the privileges of this account for maintenance functions. These accounts are set up under the principle of least privilege. Entries in the shadow file must appear in the same order as the passwd file. There must be one and only one shadow for each passwd.

/proc The /proc filesystem provides a window into the Linux kernel. Through /proc you can obtain information on any process running on your computer, including its current state, memory usage, terminal, parent, group, and more. You extract information directly from the files in /proc. An example follows:

```
$ sleep 1000 &
[1] 17924
$ cd /proc/17924
$ ls -l
total 0
-r----r-- 1 alex alex      Feb 2 17:13 cmdline
lrwx------------ 1 alex alex      Feb 2 17:13 cwd -> /home/alex
-r----r-- 1 alex alex      Feb 2 17:13 environ
lrwx------------ 1 alex alex      Feb 2 17:13 exe -> /bin/sleep
dr-x------ 2 alex alex      Feb 2 17:13 fd
pr-r--r-- 1 alex alex      Feb 2 17:13 maps
-rw------- 1 alex alex      Feb 2 17:13 mem
lrwx------------ 1 alex alex      Feb 2 17:13 root -> /
-r----r-- 1 alex alex      Feb 2 17:13 stat
-r----r-- 1 alex alex      Feb 2 17:13 statm
-r----r-- 1 alex alex      Feb 2 17:13 status
$ cat < status
Name: sleep
State: S (sleeping)
Pid: 17924
PPid: 17090
TracerPid: 0
Uid: 0 0 0
Gid: 0 0 0
FDSize: 256
Groups: 0 1 2 3 4 6 10
VmSize: 1144 kB
Vlock: 0 kB
VmRSS: 420 kB
VmData: 20 kB
...
```

In this bash creates a background process (PID 17924) for sleep. Next, the user changes directories to the directory in /proc that has the same name as the PID of the subject background process (cd /proc/17924). This directory holds information about the process for which it is named. In case it holds information out the sleep process. The ls -l command shows that some of the entries in this directory are links (cwd is a link to the process that was started from, and exe is a link to the executable file that this process is running), and some appear to be regular files. All appear to be empty. When you attach one of these files (status in the example) to standard input of cat, you get the output shown earlier. Obviously this not a regular file.
