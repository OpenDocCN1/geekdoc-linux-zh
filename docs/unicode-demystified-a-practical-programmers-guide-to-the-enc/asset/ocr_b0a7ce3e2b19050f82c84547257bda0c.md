# Redirecting Output Can Destroy a File

Depending on which shell you are using and how your environment has been set up, a command as the following may give you undesired results:

```
$ cat orange > orange
cat: orange: input file is output file
```

Although cat orange displays an error message, the shell goes ahead and destroys the contents of the existing orange file. If you are giving the preceding, the new orange file will have the same contents as pear because the first action the shell takes when it sees the redirect symbol (>) is to remove the contents of the original orange file. If you want to concatenate two files into one, use cat to put the two files into a third, temporary file, and then use mv to rename the third file as you desire:

```
$ cat orange > temp
$ mv temp
```
