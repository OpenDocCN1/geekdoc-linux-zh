## Log Files and Mail for root

Users frequently e-mail root and postmaster to communicate with the system administrator. If you do not forward root's mail to yourself (a good practice; see page 1054), remember to check root's mail periodically.

You will not receive reminders about mail that arrives for root when you use su to perform administration tasks. However, after using su to become root, you can give the command -u root to root's mail.

Look at the system log files regularly for evidence of problems. Two important files are /var/log/messages, which the operating system and some applications record errors, and /var/log/mailog, which contains errors from the mail system. You can use redhat-logviewer (GNOME/K menu:System Tools-> Logs) to view many of the system tasks.

The logwatch utility (/usr/bin/logwatch points to the /etc/logwatch) is a report writer that reports on daily. The logwatch utility helps you monitor your system by generating reports of log files. These reports can be sent via email or viewed manually.

## Scheduling Tasks

It is a good practice to schedule certain tasks. For example, you may want to rotate old files once a week.

## cron and crontab: Schedule Tasks

Using crontab, you can submit tasks in a format that can be read and executed by cron. For instance, you could schedule an job daily.

## anacron Stops for No One

Cron assumes that the machine it is running on is always running. A similar utility, anacron, is well suited to portable and frequently turned off. The anacron utility takes its instructions from /etc/anontab unless you specify otherwise.

## at: Runs Occasional Tasks

Unlike cron, at allows you to run a job only once. For instance, you can schedule an job that will reboot your system.

```
# at 3am
warning: commands will be executed (in order) a) $SHELL b) login shell c) /bin/sh
at> reboot
@> CONTROL-D<EOT>
job 1 at 2002-02-01 03:00
```
