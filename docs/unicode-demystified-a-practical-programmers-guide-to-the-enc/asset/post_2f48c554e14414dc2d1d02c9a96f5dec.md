## Communicate over a Network

Many commands that you can use to communicate with other users on a single computer system have been extended to work over a network. Three examples of extended utilities, all of which were introduced in Chapter 3, are electronic programs (such as ping), information-gathering utilities (such as finger), and communications (such as talk). These utilities are examples of the UNIX philosophy: Instead of creating a new, special-purpose tool, modifying an existing one.

Many understand a convention for the format of network addresses: user@host (spoken as at host). When you use an @ sign in an argument to one of these utilities, the utility interprets the text that follows as a remote host. When it does not include an @ sign, the utility assumes that you are requesting information from or corresponding with someone on your LAN.

The prompts shown in the examples in this chapter include the hostname of the machine you are using. When you frequently use more than one system over a network, you may find it difficult to keep track of which system you are using at any particular moment. If you set your prompt to include the hostname of the current system, it will always be clear which system you are using. To identify the system you are using, run hostname or username -n:

```bash
$ hostname
kudos
```

See 579 and 749 for information on how you can change your prompt.

## finger: Displays Information about Remote Users

The finger utility displays information about one or more users on a system. The finger utility was designed for local use, but when networks became popular, it was obvious that finger should be enhanced to reach out and collect information remotely. In the following examples, finger displays information about all the users logged in the system named bravo:

```bash
[kudos]$$ finger @bravo
bravo.tcorp.com
```

| Login Name | Tty | Idle | Login Time | Office | Office Phone |
| :--- | :--- | :--- | :--- | :--- | :--- |
| root | root | *1 | Idle 1:35 | Oct 22 5:00 | |
| alex | Alex Watson | 4 | Oct 22 12:23 | (kudos) | |
| alex | Alex Watson | 5 | 19 Oct 22 12:33 | (:) | |
| jenny | Jenny Chen | 7 | 2:24 Oct 22 8:45 | (:) | |
| hls | Helen Simpson | 11 | 2d Oct 20 12:23 | (:) | |

A user's login name in front of the @ sign causes finger to display information from the remote system for the specified user. If there are matches for that name on the remote system, finger displays the results for all of them.

```bash
[kudos]$ finger alex@bravo
bravo.tcorp.com
```

| Login Name | Tty | Idle | Login Time | Office | Phone |
| :--- | :--- | :--- | :--- | :--- | :--- |
| alex | Alex Watson | 4 | Oct 22 12:23 | (kudos) | |
| alex | Alex Watson | 5 | 19 Oct 22 12:33 | (:) | |

The finger utility works by querying a standard network service, the finger daemon, although this service is supplied with Red Hat Linux, some choose not to run it to minimize the load on their systems, reduce security risks, or maintain privacy. When you use finger to obtain information about someone at a site, you will see an error or nothing at all. It is the remote finger daemon that determines how much information to share with your user and in what format. As a result, the report displayed for any given system may differ from the preceding examples.

## Network Utilities

Network Utilities

Make use of a networked environment, it made sense to extend certain tools, some of which have already been described. Networks also created a need for new tools to control and monitor them; this led to ideas for new tools that took advantage of network speed and connectivity. This section describes concepts and utilities for systems attached to a network; without a network connection, they are of little use.

## Trusted Hosts

Some commands, including rcp and rsh, work only if the remote system trusts your local computer (that is, the remote system knows your local computer and believes that it is not pretending to be a system that it is). The /etc/hosts file lists trusted systems. For reasons of security, Superuser account does not rely on this file to identify Superusers from other systems.

Host-based trust is largely obsolete. The rcp, login, and rsh commands are deprecated in favor of ssh (page 374) and scp (page 376). Because there are many ways to subvert trusted host security, including subverting DNS systems and IP spoofing (page 1474), authentication based on IP address is widely regarded as insecure. In a small homogeneous network of machines with local DNS control, it can be "good enough." The ease of these situations may outweigh the security concerns.

## Do Not Share Your Login Account

You can use a .hosts file to allow another user to log in as from a remote system without knowing your password. This setup is not recommended. Do not compromise the security of your files or the entire system by sharing your login account. Use ssh instead of rsh and rcp whenever possible.
