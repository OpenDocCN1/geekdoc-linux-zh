## Commands for Expressions and Tokens.

| CONTROL-META-f | Moves forward over an expression. The exact behavior for CONTROL-META-f depends on what character lies to the right of Point (or left of Point, depending on which direction you are moving Point):\n* If the first nonwhitespace is an opening delimiter (parenthesis, bracket, or brace), Point is moved just past the matching closing delimiter.\n* If the first nonwhitespace is a token, Point is moved just past the end of this token. |
| CONTROL-META-b | Moves backward over an expression |
| CONTROL-META-k | Kills an expression forward. It leaves Point at the same finishing position as CONTROL-META-a but kills the expression it traverses. |
| CONTROL-META-@ | Sets Mark at the position CONTROL-META-@ would move to but not change Point. To see the marked region clearly, you can look at both ends with a pair of CONTROL-X CONTROL-X commands to interchange Point and Mark. |

## Function Definitions

In emacs a balanced expression at the outermost level is considered to be a function definition and is often called a defun, even though that term is specific to Lisp alike. Most generally, it is understood to be a function definition in the language at hand.

In C mode a function definition is understood to include the return data type, the function name, and the argument declarations appearing before the { character. Table 11-18 shows the commands for operating on function definitions.

## Function Definitions table 11-18

| CONTROL-META-a | Moves to the beginning of the most recent function definition. Use this command to scan backward through a buffer one function at a time. |
| CONTROL-META-e | Moves to the end of the next function definition. You can use this command to scan forward through a buffer one function at a time. |
| CONTROL-META-h | Puts Point at the beginning and Mark at the end of the current (next, if between) function definition. This command sets up an entire function definition for a Region-oriented operation such as like. |

## Indention Style

The emacs editor now believes that an opening brace at the left margin is part of a function definition. This is a heuristic to speed up the reverse scan for a definition's leading edge. If your code has an indentation style that puts opening brace elsewhere, you may get unexpected results.

## Indention

The emacs C mode has extensive logic to control the indention of C programs. Furthermore, you can adjust the logic for many different styles of C indention (Table 11-19).

## Indention Commands

| TAB | Adjusts the indention of the current line. TAB inserts or deletes whitespace at the beginning of the line until the indention conforms to the current context and rules in. Point is not moved at all unless it lies in the whitespace area, in that case, it is moved to the end of that whitespace. TAB does not insert anything except leading whitespace; so you can hit it at any time and at any position in the line. If you really want to insert a tab in the text, you can use CONTROL-META-TAB. |
| LINEFEED | Shorthand for RETURN followed by TAB. The LINEFEED key is convenience for entering new code, giving you an autindent as you begin each line. \nThe following two commands each indent multiple lines with a single command. |
| CONTROL-META-q | Reindents all the lines inside the next pair of matched braces. CONTROL-META-q assumes that the left brace is correctly indented and drives the indention from there. If the left brace itself needs help, type TAB on its line before giving this command. All the lines up to the matching brace are indented as if you had typed TAB on each one |
| CONTROL-META- | Reindent all the lines in the current Region between Point and Mark. Put Point just to the left of a brace and then give the command. All the lines up to the matching brace are indented as if you typed TAB on each one. |

## Customizing Indention

Many styles of C programming have evolved, emacs does its best to support automatic indentation for all of them. The emacs coding was completely rewritten for emacs version 19; it supports C, C++, Objective-C, and Java. The emacs syntactic analysis is much more precise and is able to classify any syntactic element of each line of program into a single syntactic category (of about 50), such as statement, string, else-clause, and so on. With that analysis in hand, emacs goes to an offset table c-offsets-alist and looks up how much this line should be indented from the preceding line.

In order to change the offset table. It is possible to define a completely new offset table for each customized style but much more convenient to feed in a short list of exceptions to the standard rules. Each mainstream style (GNU, K&R [Kernighan and Ritchie], BSD, and so on) has such an exception list; all are collected in c-style-alist. Here is one entry from c-style-alist:

```
"gunu"
(c-basic-offset . 2)
(c-comment-only-line-offset . (0 . 0))
(c-offsets-alist . ((statement-block-intro . +)
(knr-argdec1-intro . 5)
(substatement-open . +)
(label . 0)
(statement-case-open . +)
(statement-cont . +)
(arglist-intro . c-lineup-arglist-intro-after-paren)
(arglist-close . c-lineup-arglist)))
```

Constructing your own custom style is beyond the scope of this book; if you are curious, the long story is available in emacs online info, beginning at “Customizing C Indention.” The sample .emacs file adds a very custom style and ranges to use it on every .c file that is edited.

## Comments

Each buffer has its own comment-column variable, which you can view with the CONTROL-H v comment-column RETURN help command. The commands listed in Table 11-20 facilitate working with comments.

## Comments table 11-20

| META-; (semicolon) | Inserts a comment on this line or aligns an existing comment. Its behavior differs according to the current situation on this line.\n* If no comment is on this line, an empty one is created at the column.\n* If a comment exists on this line, emacs aligns it with the previous comment in the buffer.\n* If no comment exists in the buffer, emacs creates a new comment at the column. |
| CONTROL-X | If no comment is on this line, emacs creates a comment at the column. |
| CONTROL-U-X | If a comment exists on this line, emacs aligns it with the previous comment in the buffer. |
| CONTROL-U | If no comment exists in the buffer, emacs creates a new comment at the column. | |

## Special-Purpose Modes

The emacs editor has a third family of Major modes that are not oriented toward a particular language or toward editing. Instead they perform some function. These modes, which may define their own key bindings and commands, are

- Rmail: reads, archives, and composes e-mail
- Dired: moves around in a display and operates on files
- VIP: simulates a complete vi environment
- Shell: runs an interactive subshell from inside emacs

## Shell Mode

One-time shell commands and Region filtering were discussed earlier. Refer to “Foreground Shell Commands” on page 503. In Shell mode, however, each emacs buffer has an underlying shell permanently associated with it. This shell takes its input from the line of the buffer and sends its output to the buffer, advancing Point as it goes. The buffer, if not edited, is a record of the complete shell session.

The shell runs asynchronously, whether or not you have your buffer in view. The emacs editor uses idle time to read the shell's output and add to the buffer.

Type Meta-x shell to create a buffer named *shell* exists, emacs just switches to that buffer. The name to run is taken from one of the sources:

- The Lisp variable explicit-shell-file-name
- The environment variable SHELL
- The environment variable SHELL

If you really want to start a second shell, first use Meta-x rename-buffer to change the name of the existing shell's buffer. This process can be continued to create many subshells and buffers as you want, all running in parallel.

In Shell mode a special set of commands is defined (Table 11-21). They are bound to two-key sequences starting with CONTROL-C. Each sequence is meant to be similar to the ordinary control characters found in UNIX but with leading CONTROL-C.

| Shell Mode || 11-21 |
| RETURN | If Point is at the end of the buffer, emacs inserts the RETURN and sends this (the last) line to the shell, If Point is elsewhere, it copies this line to the end of the buffer, peeling off the old shell prompt (see the regular expression shell-prompt-pattern), if one existed. Then this copied line, now the last in the buffer, is sent to the shell. |
