# Editing the Command Line

You can reexecute any event in the history list. This feature can save you time, effort, and aggravation. Not having to reenter long command lines allows you to execute events more easily, quickly, and accurately than you could if you had to retype the entire command line. You can recall, modify, and reexecute previously executed events in three ways: You can use the fc builtin (covered next); the readline Library, which uses a one-line vi or emacs-like editor to edit and execute events (page 598); or the TC commands (page 594). If you are more familiar with vi or emacs and less familiar with the TC Shell, fc or the readline Library. If you are more familiar with the TC Shell and less familiar with vi and emacs, use the TC Shell commands. If it is a toss-up, try the Readline Library; it will benefit you in other areas of GNU/Linux more learning than the TC Shell commands will.

# fc: Displays, Edits, and Reexecutes Commands

The fc (fix command) builtin enables you to display the history file and to edit and reexecute previous commands. It provides many of the same capabilities as the command line editors.

# Viewing the History List

When you call it with the -l option, fc displays commands from the history file on standard output. Without any arguments, fc -l lists the 16 most recent commands in a numbered list. The list of events is ordered from the oldest at the top of the list to the most recent at the bottom:

```
$ fc -l
190 lpr memo.0795
191 lpr memo.0795
192 mv memo.0795 memo.071195
193 cd
194 view calendar
195 cd Work
196 vi letter.adams01
197 aspell -c letter.adams01 > adams01
198 roroff letter.adams01 > adams01
199 roroff less.adams.out
200 lpr adams.out
201 rm adams.out
202 cd ../memos
203 ls
204 rm *0486
```
