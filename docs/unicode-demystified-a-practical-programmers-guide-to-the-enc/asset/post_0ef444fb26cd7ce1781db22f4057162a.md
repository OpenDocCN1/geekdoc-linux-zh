## Turning the Power Off

Once the system is in single-user mode, shutting down is quite straightforward. Give the command tinit 0 (preferred) or halt to bring the system down. You can build a kernel with apm so that it turns the machine off at the appropriate time. If your machine is not set up this way, power off when the appropriate prompt appears or the system starts rebooting.

## Crash

A crash occurs when the system suddenly stops/fails when you do not intend it to. A crash may result from software or hardware problems or a loss of power. As a running system loses power, nothing is regular or predictable. In a fraction of a second, some components are supplied with enough voltage and others are not. Buffers are not flushed, corrupt data may be written to the hard disk, and IDE drives do not behave as predictably as SCSI drives under these circumstances. After a crash, you must bring the operating system up carefully to minimize possible damage to the filesystems. Frequently there will be little or no damage.

## Repairing a Filesystem

Although the filesystems are checked automatically during the boot process if you will need to check them manually if a problem cannot be repaired automatically. To check the filesystems manually after a crash, boot the system up to emergency mode (page 948). Do not mount any devices other than root, which Linux mounts automatically. Run fsck on all the local filesystems that were mounted at the time of the crash, repairing them as needed. The fsck.ext3 module of fsck handles ext3 (journaled) filesystems. Depending on how your system is set up, when fsck cannot repair a filesystem automatically, the system enters single-user mode so you can run fsck manually (refer to "Single-User Mode" on page 949). Make note of any ordinary files or directories that you repair (and identify), and inform owners that they may not be complete or correct. Look in the lost+found directory in each filesystem for missing files. For more information, refer to "Notes" on page 1177. After successfully running fsck, type exit to exit from the single-user shell and resume booting.

If files are not correct or are missing altogether, you may have to recreate them from a backup copy of the filesystem. For more information, refer to "Backing Up Files" on page 997.

## When the System Does Not Boot

When you cannot boot the computer from the hard drive, use your rescue floppy or the first of your installation CD-ROMs (refer to "mkbootdisk: Creates a Rescue/Emergency/Boorp Floppy Disk") on page 920). If that works, run fsck on the root filesystem and try rebooting from the hard drive again.

When all else fails, perform an "upgrade" to your current version of Red Hat. Red Hat Linux can perform a nondestructive upgrade and fix quite a bit in the process.

## Important Files and Directories

This section details the most common files used to administer the system. Also refer to "Important Standard Directories and Files" on page 112.

~/.bash_profile contains an individual user login initialization script. The shell executes the commands in this file in the same environment as the shell each time a user logs in. The file must be located in a user's home directory.

The .bash_profile file usually specifies a terminal type (for vi, terminal emulators, and other programs), runs stty to establish terminal characteristics desired by the user, and performs other housekeeping functions when a user logs in.

A typical .bash_profile file specifying a vt10 terminal and CONTROL-H as the erase key follows:

```bash
$ cat .bash_profile
export TERM=vt100
stty erase '^H'
```

When you log in from more than one type of terminal, you may want to construct a more elaborate routine, such as the following one, which asks for your terminal type each time you log in:

```bash
$ cat .bash_profile
echo -n "Terminal type: "
read TERM
export TERM
stty erase '^H'
```

For more information, refer to "Startup Files" on page 565.

./.bashrc Contains an individual user, interactive, nonlogin shell initialization script. The shell executes the commands in this file in the same environment as the (new) shell each time user creates a new interactive shell. The .bashrc script differs from .bash_profile in that it is executed time new shell is spawned, not only when you log in. For more information, refer to "Startup Files" on page 565.

./.login Performs the same function for tsh as .bash_profile does for bash: It is the individual user login shell initialization script.

./.tcsh Performs the same function for tsh as .bashrc does for bash: It is the individual user, interactive, nonlogin shell initialization script.

/dev/null Output to this file disappears, also called a bit bucket. The /dev/null is device file and must be created with mknod. Input that you take from this file contains an infinite string of zeros (nulls or numerical, not ASCII, zeros). You can fill a file (as a swap file—page 967) or overwrite a file with zeros with a command such as the following. The od utility shows the contents of the new file:

```bash
$ dd if=/dev/zero of=zeros bs=1024 count=10
10+0 records out
10+0 records out
$ ls -l zeros
-rw-r--r-- 1 alex 10240 Dec 3 20:26 zeros
$ od -c zeros
0000000 \00 \00 \00 \00 \00 \00 \00 \00 *
0024000
```

When you try to do with /dev/zero what you can do with /dev/null, quickly fill the partition you are working in:

```bash
$ cp /dev/zero bigzero
cp: writing 'bigzero': No space left on device
$ rm bigzero
```

/etc/aliases Used by the mail system (typically sendmail) to construct aliases for users. Edit this file to suit your local preferences. This file contains a number of good examples showing how you can create aliases for users, creating mailing lists, and direct e-mail to files. After editing this file, run newaliases to rebuild the aliases database. Refer to "aliases: Setting up E-Mail Aliases" on page 1054.
