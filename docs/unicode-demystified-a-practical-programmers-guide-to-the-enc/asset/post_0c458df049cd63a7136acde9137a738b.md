
## whence: Displays the Absolute Pathname of a Utility

The whence builtin is similar to the which builtin, telling you the absolute pathname of a utility:

```bash
zsh % whence grep
bin/grep
```

In this whence reports only the name of an alias, function, or builtin. Use the -v option to report on the type of any command or reserved word that you can use in the Shell:

```bash
zsh % whence pwd
pwd
zsh % whence -v pwd
pwd is a shell builtin
zsh % whence -v myfunc
myfunc is a shell function
zsh % whence -v if
is if a reserved word
```

The type builtin is a synonym for whence -v.

## trap: Catches a Signal

The builtin trap causes a shell script to execute a command when it receives an error or signal when it exits from a function or script. The syntax of trap is similar to the Bourne Again Shell's trap (page 667), including the ability to use signal names in place of numbers:

```bash
trap 'command' event
```

Quote the command, because it must be passed to trap as a single argument. The event arguments are names of signals (for example INT, TERM), signal numbers, or one of those in Table 15-19.

| Event | Occurrence | table 15-19 |
|---|---|---|
| DEBUG | Occurs after every simple command. The following command causes your script to append the line number of the script and the pathname of the working directory to /tmp/trace after each command: `trap 'echo $LINENO $PWD >> /tmp/trace' DEBUG` | | |
| EXIT or O | Occurs whenever the script exits. | | |

```bash
trap 'echo $LINENO $PWD >> /tmp/trace' DEBUG
```

Without any arguments the trap builtin lists all traps in a form that can be saved and read later by the shell.

The following script, named debug, demonstrates how trap works. Modify the script and experiment with it to get a better feel for how to use: Look the out in trace; ZERR is called when the script tries to run cpasswd (assuming we are not logged in as root); INT is called when you press CTRL-C while the script is running. In addition, cpasswd displays its error message:

```bash
zsh % cat debug
#!/bin/zsh
trap 'echo $LINENO $PWD >> trace' DEBUG
trap 'echo ERROR: ZERR' ZERR
trap 'echo INTERRUPT;exit INT' INT
trap 'echo EXIT' EXIT
count=4
```

```bash
while [ count -gt 0 ]
do
	echo "hi there"
	/usr/sbin/cpasswd
	sleep 1
	echo $count
	((count = count - 1))
done
```

In the final pass through the do loop ((count = count - 1)) yields a 0 and sets return status of 1. (This expression returns a 0 if the result is not 0)
When control passes from this statement, ERR is set and displays ERROR.

## Command Line Editing

The Z Shell allows you to edit the current command line. If you make a mistake, you do not need to back up to the point of the mistake and reenter the command from there or press the line kill key and start over. You can use one of the command editors to modify the command line. You can also access and edit previous command lines stored in your history file (page 796).

The Z Shell provides two command line editors: one similar to vim (Chapter 10), and the other similar to emacs (Chapter 11). Depending on how the Z Shell is set up on your system, you may be able to use one, both, or neither of the editors.

Use the following command to set up your environment so that you can use the command line editor:

```bash
zsh % bindkey v
```
