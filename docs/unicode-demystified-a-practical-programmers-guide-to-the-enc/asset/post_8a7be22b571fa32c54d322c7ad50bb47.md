## Redirecting Standard Input

Just as you can redirect standard output, you can redirect standard input. The redirect symbol (<) instructs the shell to redirect a command's input from the specified file instead of the keyboard (Figure 5-9). The format of a command line that redirects input is

```
command [arguments] < filename
```

where command is any executable program (such as an application program or a utility), arguments are optional arguments, and filename is the name of the ordinary file shell redirects the input from.

Figure-5-10 shows cat with its input redirected from the supply_orders file that was created in Figure 5-8 and standard output going to the screen. This setup causes cat to display the sample file on the screen. The system automatically supplies EOF (end of file) signal at the end of an ordinary file, so no CTRL-D is necessary.

Giving a cat command with input redirected from a file yields the same result as giving a cat command with the filename as an argument. The cat utility is member a class of GNU/Linux utilities that function in this manner.

The shell provides a feature called nolobber (page 554) that stops you from inadvertently overwriting an existing file using redirection. When you enable this feature by setting the nolobber variable and you attempt to redirect output to an existing file, the shell presents an error message and does not execute the command. If the preceding examples result in one message of the following messages, the nolobber feature is in effect. The following examples set nolobber, attempt to redirect the output from `echo` into an existing file, and then unset nolobber in each of the major shells:

```bash
bash $ set -nlobber
bash $ echo "hi there" > tmp
bash: tmp: Cannot overwrite existing file
bash $ set +nlobber
```

## Redirecting Output Can Destroy a File

Depending on which shell you are using and how your environment has been set up, a command as the following may give you undesired results:

```
$ cat orange > orange
cat: orange: input file is output file
```

Although cat orange displays an error message, the shell goes ahead and destroys the contents of the existing orange file. If you are giving the preceding, the new orange file will have the same contents as pear because the first action the shell takes when it sees the redirect symbol (>) is to remove the contents of the original orange file. If you want to concatenate two files into one, use cat to put the two files into a third, temporary file, and then use mv to rename the third file as your desire:

```
$ cat orange > temp
$ mv temp
```

What happens with the type in the next example can be even worse. The user giving the command to search through files a, b, and c for the word apple and redirect the output from grep (page 64) to the file a.output. Instead, the user enters the filename as a output, omitting the period and leaving a space in its place:

```
$ grep a b c > a output
grep: output: No such file
```

The shell obediently removes the contents of a. The error message takes a moment to appear, giving you sense that you destroyed a.

## Appending Standard Output to a File

The append symbol (>>) causes the shell to add new information to the end of a file, leaving intact any information that was there. The following commands demonstrate the action of append output:

```
$ cat orange
this is orange
$ cat pear >> orange
$ cat orange
this is orange
this is pear
```

You first see the contents of the orange file. Next, the contents of the pear file is added to the end of it (catenated with) the orange file.

## /dev/null: Data Sink

The dev/null device is a data sink, commonly referred to as a bit bucket. You can redirect output that you do not want to keep or see to /dev/null. The output disappears without a trace:

```
$ echo "hi there" > /dev/null
```

When you read from /dev/null, you get a null string. Give the following cat command to truncate a file named messages to zero length while preserving the ownership and permissions of the file:

```
$ ls -1 messages
-rw-r--r-- 1 alex pubs 25315 Oct 24 10:55 messages
$ cat /dev/null > messages
$ ls -1 messages
-rw-r--r-- 1 alex pubs 0 Oct 24 11:02 messages
```
