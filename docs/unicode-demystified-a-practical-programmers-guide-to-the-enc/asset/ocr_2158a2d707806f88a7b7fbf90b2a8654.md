# Parameter Expansion

The second step of parsing the command line is parameter expansion. Refer to “Expanding Shell Variables” on page 751. Variables are not expanded if enclosed within single quotation marks or the leading dollar sign is escaped by preceding it with a backslash. If they are enclosed within double quotation marks, they are expanded, but the resulting text is not subject to filename generation (page 805).

Any string within double quotation marks is used as a single line argument, so variables that are expanded within double quotation marks are treated as part of a single argument. Outside of double quotation marks, the type of the variable helps determine what happens. For scalar variables, if the Z Shell SH_WORD_SPLIT is set, the expanded value is split into individual arguments on the command line, using the first field separator in the IFS variable. Normally SH_WORD_SPLIT is left unset, so the result of expanding the scalar $variable is separated into individual arguments on the command line:

```
zsh % scalar="a b c d"
zsh % echo $scalar
ab b c d
zsh % set $scalar
zsh % echo $1
ab b c d
zsh % set -o SH_WORD_SPLIT
zsh % set $scalar
zsh % echo $1
a
zsh % array=(a b c d)
zsh % echo $Array
ab b c d
zsh % set $array
zsh % echo $1
a
zsh % set "Array"
zsh % echo $1
```

# Command Substitution

The third step of parsing the command line is command substitution. A command in the form $(command) is executed within a subshell, and the command, parentheses, and dollar sign are replaced by standard output of the command. The Z Shell also provides the older `command` syntax:

```
zsh % ls -l $(find . -name README -print)
```
