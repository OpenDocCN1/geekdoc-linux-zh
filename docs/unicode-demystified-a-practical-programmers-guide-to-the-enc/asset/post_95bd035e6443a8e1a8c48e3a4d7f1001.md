# Variables

Like bash and tsh, zsh allows you to create and use variables. The rules for naming and referring to variables are similar in all shells (page 566). As in the Bourne Again Shell, you assign values to variables with the following syntax:

VARIABLE=value

There can be no whitespace on either side of the equal (=) sign. If you want to include SPACES in the value of the variable, put quotation marks around the value or quote the SPACES.

In zsh, in bash and tsh, you reference the value of a variable by a dollar sign and enclosing it in braces, as ${VARIABLE}. The braces are optional unless the name of the variable is followed by a letter, digit, or underscore. Also, the Z Shell refers to the arguments on its command line by position, using the special variables $1, $2, $3, and so forth to $9. If you wish to refer to arguments past the ninth, you must use braces, as in ${10}. The name of the command is held in $0.

You can unset one or more variables with the unset builtin

```zsh
zsh % unset PREF SUFF
```

This removes the variable's value and attributes.

# Variable Attributes

In the Z Shell, as in the Bourne Again Shell, you can set a variable's attributes that control the values it can take on. The typeset builtin sets attributes. The following example assigns the uppercase (-u) attribute to the variable NAME. A variable with this attribute translates all letters in it to uppercase:

```zsh
zsh % typeset -u NAME
zsh % NAME=Barbara Jackson
zsh % echo $NAME
BARBARA JACKSON
```

Similarly, you can assign a variable the lowercase attribute with typeset -l.
The integer attribute is very useful. By default the values of Z Shell variables are stored as strings. However, if you want to do arithmetic on a man, the string

The integer builtin is almost identical to typeset -i, the string is converted into a number, manipulated, and then converted back to a string. A variable with this integer attribute is stored as an integer. This makes arithmetic much faster. Assign the integer attribute as follows:

```zsh
zsh % typeset -i COUNT
```

You can assign a base other than 10 to an integer variable. The Z Shell then uses this base to display the value. If base is not 10, the value is displayed as base (in base 2, 20 is written as 10):

```zsh
zsh % typeset -i B
COUNT=20
```

The export attribute is similar to the export builtin (page 57). If a variable has this attribute, a copy of it is inherited by all child processes. The Z Shell exports the attribute and also provides typeset -X to set the export attribute. You can set the export attribute for functions as well as for variables; it is available in all subshells.

The Z Shell supports several variable attributes that are useful for formatting output. You can assign a particular width (number of columns) to a variable and specify that it is left or right justified. Leading zeros can be added or suppressed. Table 15-4 shows the corresponding options to typeset

| | |
|---|---|
| -L | Left-justifies within a width of width |
| -R | Right-justifies (blank filled) within a width of width |
| -Z | Right-justifies (zero filled) within a width of width |

If you omit width, zsh uses the width of the first value assigned to the variable (establishing a width of two characters) then assigned a value, which is displayed in a two-character field with a trailing blank:

```zsh
zsh % typeset -L FRUIT1 FRUIT2
sh % FRUIT1=apple
sh % FRUIT2=watermelon
sh % echo $FRUIT1
apple 
sh % echo $FRUIT2
watermelon
sh % typeset -Z DAY
sh % DAY=4; echo $DAY
04
sh % typeset -L MONTH
sh % MONTH=1; echo $MONTH/$DAY
1/04
sh % MONTH=8; echo $MONTH/$DAY
8/02
```

You can give the readonly attribute to a variable to prevent its value from being changed. You must assign values to variables before you give them this attribute:

```zsh
sh % PATH=/usr/bin:/usr/local/bin/games
sh % typeset -r PATH
sh % PATH=/usr/bin:/usr/local/bin/games
sh: read-only variable: PATH
```

You can use the readonly builtin in place of types -r:

```zsh
sh % readonly TMP=/tmp
```

Without any arguments types displays a list of variables with their attributes and values. To see the value of a variable, use types:

```zsh
sh % types DAY
DAY=2
```

Use types followed by an option to see which variables have a certain attribute

```zsh
sh % types -Z
DAY=2
```

# Locality of Variables

By default, Z Shell variables in shell are global; they are recognized throughout the current shell session and all subshells. You can also create variables that are local to a function. A variable that is local to a function is recognized only within that function. If a function has a local variable with the same name as a global variable, all references to that variable within the function refer to the local variable, whereas all references outside the function refer to the global variable.

Local variables are helpful in a function for general use. Because the function is called by many scripts, perhaps written by different programmers, to make sure that names of the variables within the function do not interact with variables of the same name in the programs that call the function. Local variables help eliminate this problem.

One of the typeset builtin is to declare a variable to be local to the function it is defined in (unless ALL_EXPORT [page 825]):

# typeset varname

The next example shows the use of a local variable in an interactive session. This is not a shell; if you put a function in a file do not attempt to execute it. If you save this function in a file named count, you can place it in your environment with the . (dot) builtin (for example, . count). Refer to "Running a Startup File with the . (Dot) or source builtin" on page 581.

This example uses two variables count. The first is declared and assigned a value of 10 in the login shell. Its value never changes, as is verified by echo before and after running count_down. The other count is declared, via typeset, to be local to the function. Its value, which is unknown outside the function, ranges from 6 to 1, as the echo command within the function confirms.

The example shows the function being entered from the keyboard. Once you start entering the function, zsh prompts you with function> to remind you that you are entering a function. While you are typing in the while loop, zsh prompts you with while:

```zsh
zsh % count=10
zsh % function count_down {
function> typeset count
function> count=$1
function> while [ count -gt 0 ]; do
function> echo "$count..."
function> while ((count=count-1))
function> sleep 1
function> while> done
function> echo "Blast Off!"
function> return
function> }
zsh % echo $count
10
zsh % count_down 6
6...
...
```
