(To avoid a recursive plunge, the 1s in the replacement text, although an alias, is not expanded a second time.)
When given a list of aliases without the =value or value field, the alias builtin responds by displaying the value of each defined alias. The alias builtin reports an error if an alias has not been defined:

```
$ alias 1l 1s wx
alias 1l='1s -l'
alias 1s='1s -F'
alias: 'wx' not found
```

When you give an alias builtin without any arguments, the shell displays all of the defined aliases:

```
$ alias
alias 1l='1s -1l'
alias 1l='1s -ltr'
alias 1s='1s -F'
zap='rm -i'
```

You can avoid alias substitution by preceding the command with a backslash (\)

```
$ \1ls
Test_Emacs XTerm.ad flute.ps maptax.icn
Tiger fixtax.icn floor testdir
```

The rest of the command line, any arguments are still received by the command that gets executed after the replacement of an alias name with alias value

```
$ 11 fo
-rw-r--r-- 1 alex group 641 Apr 1 2003 fixtax.icn
-rw-r--r-- 1 alex group 30015 Mar 1 2002 flute.ps
-rxr-xr-x 1 alex group 485 Oct 21 08:03 floor*
```

You can remove an alias with the unalias builtin. When the zap alias is removed, it is no longer displayed with the alias builtin, and its subsequent use in an error message:

```
$ unalias zap
$ alias
alias 1l='1s -1l'
alias 1l='1s -ltr'
alias 1s='1s -F'
$ zap maptax.icn
bash: zap: command not found
```
