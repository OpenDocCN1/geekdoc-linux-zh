OpenSSH is a free version of the SSH protocol suite and is the basis for many secure network tools. Whereas telnet and login send all communications, including passwords, as cleartext, ssh (one of the OpenSSH tools) performs the same functions while encrypting everything, including passwords, that goes over the network. Its encryption eliminates eavesdropping, connection hijacking, and other network attacks. The OpenSSH tools also provide secure tunneling capabilities (page 375) and several methods of authentication.

Both ssh (the client or the one who logs on the server) and sshd (the server that the ssh logs in) are quite easy to set up. On the client side, give the command ssh hostname when you have the same login name on both machines or ssh -l login hostname to use login-name as your login name on the remote machine named hostname.

The client machine must have permission to connect to the remote machine, and the user must present a valid name and password to the remote machine. In addition, the server must positively identify itself to the client to prevent a person-in-the-middle attack (refer to footnote 3 on page 141). The easiest way to give a client access to a host is to put the client's host (and domain) names in the /etc/hosts.equiv file on the server.

The ~/known_hosts file on the client machine contains electronic fingerprints of all the hosts you have connected to using OpenSSH tools. We use this to identify a server positively. When you launch an ssh session, the client (local) machine verifies the fingerprint and returns information stored in known_hosts. This process is normally transparent to you.
