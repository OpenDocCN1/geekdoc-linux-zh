Expressions follow these rules:

1. The shell evaluates a missing or null argument as 0.
2. All results are decimal numbers.
3. Except for != and ==, the operators act on numeric arguments.
4. You must separate each element of an expression from adjacent elements by a SPACE, unless the adjacent element is &, |, <, >, (,, or ).

Following are some examples that use @:

```bash
216 $ count = 0
217 $ echo $count
0
218 $ count = ( 10 + 4 ) / 2
219 $ echo $count
7
220 $ result = ( $count < 5 )
221 $ echo $result
0
222 $ count += 5
223 $ echo $count
12
224 $ count++
225 $ echo $count
13
```

Event 216 declares the variable count and assigns a value of 0 to it. Event 218 shows the result of an arithmetic operation being assigned to a variable. Event 220 uses @ to assign the result of a logical operation involving a constant and a variable to result. The value of the operation is false (= 0) because the variable count is not less than 5. Event 222 is a compressed form of the following assignment statement:

```tcsh
tcsh $ count = $count + 5
```

Event 224 uses a postfix operator to increment count by 1. You can use the prefix increment (++) and decrement (--) operators only in expressions containing a single variable name, as shown in the following example:

```tcsh
tcsh $ count = 0
tcsh $ count++
tcsh $ echo $count
1
tcsh $ next = $count++
@ Badly formed programming number.
```

Unlike in the C programming language, expressions in tcsh cannot use prefix increment and decrement operators.

# Arrays of Numeric Variables

You must use the set builtin to declare an array of numeric variables before you can use @ to assign values to the elements of the array. The set builtin can assign any values to the elements of a numeric array, including zeros, other numbers, and null strings.

Assigning a value to an element of a numeric array is similar to assigning a value to a simple numeric variable. The only difference is that you must specify the element, or index, of the array. The format is

`@ variable-name[index] operator expression`

The index specifies the element of the array that is being addressed. The first element has an index of 1. The index cannot be an expression but rather be either a numeric constant or a variable. In the preceding syntax the brackets around index are part of the syntax and do not indicate that index is optional. If your index is too large for the array you declared with set, tsh displays @: subscript out of range.

```bash
226 set ages = ( 0 0 0 0 0 )
227 $ @ages[2] = 15
228 $ @ages[3] = ($ages[2] + 4)
229 $ echo ages[3]
19
230 $ echo ages
0 15 19 0 0
231 $ set index = 3
232 $ echo ages[$index]
19
233 $ echo ages[6]
```

Elements of a numeric array behave as though they were simple numeric variables. The difference is that you must use set to declare a numeric array. Event 226 in the preceding example declares an array with five elements, each having a value of 0. Event 227 and 228 assign values to the elements of the array, and event 229 displays the value of one of the elements. Event 230 displays all the elements of the array, 232 specifies an element by using a variable, and 233 demonstrates the out-of-range error message.

# Braces

With bash and zsh, tsh allows you to use braces to distinguish a variable from surrounding text without the use of a separator. For more information, refer to "{ } Brace Expansion" on page 607.

# Special Variable Forms

The special variable with the following syntax has the value of the number of elements in the variable-name array:

```
$#variable-name
```

You can determine whether variable-name has been set by looking at the value of the variable with the following syntax:

```
$variable-name
```

This has a value of 1 if variable-name has been set and 0 otherwise:

```tcsh
tcsh $ set days = (mon tues wed thurs)
tcsh $ echo $days
1
tcsh $ unset days
tcsh $ echo $days
0
```

# Reading User Input

Within a shell script, you can use the builtin to read a line. The following prompts the user and reads it into a variable:

```bash
read -p "Enter input: " line
```

# Shell Variables

This section lists some of the variables that are available in tcsh.

# Shell Variables That Take Values

**argv** This array contains the command line arguments (positional parameters). The array is indexed starting at 1, so argv[1] contains the first command line argument. You can change any element of this array, use argv[*] to reference all the together, and $n (short for argv[n]). Refer to "Positional Parameters" on page 581, but note that bash does not use the argv form, only the abbreviated form. Use $0 to refer to the name of calling program.

**$argv or $@** Holds the number of elements in the argv array. Refer to “Special Variable Forms” on page 706.

**autolist** Controls command and variable completion (page 694).

**autologout** Enables tesh’s automatic logout facility, which logs out if you leave the idle for too long. The value of the variable is the number of minutes that tash waits before logging out. The default is 60 minutes if you are Superuser; otherwise, this variable is unset.

**cdpath** Affects the operation of **cd** in the same way as CDPATH variable (page 580). It takes on an array of absolute paths (see **path**, following) and is usually set in the .login file with a command line like:

```bash
tsh $ set cdpath = /home/scott /home/scott/letters
```

When **cd** with a simple filename, it searches the working directory for a subdirectory with that name. If one is not found, **cd** searches the directories listed in **cdpath** for the file.

**correct** Set to cd automatic spelling correction of command names, to all to correct the entire command line, and to complete automatic completion of command names. On corrections that you make after you press RETURN. Refer to “After You Press RETURN” on page 697.

**cwd** The shell sets this variable to the name of the working directory. When you access a directory through a symbolic link, tesh sets **cwd** to the name of the symbolic link. Refer to “Symbolic Links” on page 126.

**dirstack** The shell keeps the stack of directories used with the **push**, **pop**, and **dirs** built in this variable.

**ignore** You can set this variable to an array of suffixes that should be ignored during file-name completion.

**gid** The shell sets this variable to your group ID.

**histfile** Gets the full pathname of the file to be used to save the history list between login sessions. If not set, the default file, /.history, is used.
