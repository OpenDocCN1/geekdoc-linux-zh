## cp versus ln

The following commands verify that ln does not make an additional copy of a file. Create a file, use ln to make an additional link to the file, change the contents of the file through one link, and verify the change through the other link:

```
$ cat file_a
This is file A.
$ ln file_a file_b
$ cat file_b
This is file A.
$ vi file_b
```

```
$ cat file_b
This is file B after the change.
$ cp file_a
This is file B after the change.
```

## Symbolic Links

```
$ cat file_c
This is file C.
$ cp file_c file_d
$ cat file_d
This is file C.
$ vi file_d
```

```
$ cat file_d
This is file D after the change.
$ cat file_c
This is file C.
```

You can also use ls with the -l option, followed by the names of the files you want to compare, to see that the status information is the same for two links to a and different for files that are not linked. In the following example the 2 in the links field (just to the left of alex) shows there are two links to file_a and file_b:

```
$ ls -l file_a file_b file_c file_d
-rw-r-- 2 alex pubs 33 May 24 10:52 file_a
-rw-r-- 2 alex pubs 33 May 24 10:52 file_b
-rw-r-- 1 alex pubs 16 May 24 10:55 file_c
-rw-r-- 1 alex pubs 33 May 24 10:57 file_d
```

Although it is easy to guess which files are linked to one another in this example, it does not explicitly tell you.

Use ls with the -i option to determine without a doubt which files are linked. The -i option shows the inode number for each file. If the two filenames have the same inode number, they share the control structure for a file and are links to the same file. Conversely, when two filenames have different inode numbers, they are different files. The following example shows that file_a and file_b have the same inode number and that file_c and file_d have different inode numbers:

```
$ ls -i file_a file_b file_c file_d
3534 file_a 3534 file_b 5800 file_c 7328 file_d
```

All links to a file are of equal value: The operating system cannot distinguish the order in which multiple links were made. When a file has two links, you can remove either one and still access the file through the remaining link. You can remove the link used to create the file and, as long as there is a remaining link, still access the file through that link.

The links that are described in the preceding, optional section are hard links. In addition to hard links, GNU/Linux supports called symbolic links, soft links, or symlinks. A hard link is a pointer to a file (directory entry → inode), whereas a symbolic link is an indirect pointer to a file. A symbolic link is a directory entry that contains the pathname of the pointed-to file (a pointer to the hard link to).

Symbolic links were developed because of the limitations of hard links. No one can create a hard link to a directory; anyone can create a symbolic link to directory. Also, a symbolic link can point to any file, regardless of where it is located in the file structure, but a hard link must be in the same filesystem as the other hard link(s) to the file.

Often the GNU/Linux file hierarchy is composed of several filesystems. Because each filesystem separate control information (that is, separate inode tables) for the files, it is not possible to create hard links between files in different filesystems. When you create links only files in your own directories, you will not notice these limitations.

One of its advantages over hard link is that a symbolic link can point to a nonexistent file. This ability is useful if you need to link to a file that periodically gets removed and recreated. A hard link would keep pointing to the removed file, which the hard link would keep alive of being a hard link, even after a new file was created. A symbolic link would always point to the newly created file and not interfere with deleting the.
