# Process Identification

GNU/Linux assigns a unique PID number at the inception of each process. As long as a process exists, it keeps the PID number. During one session, the same process is always executing the login shell. When you fork a new process—for example when you use an editor—the PID number of the new (child) process is different from that of its parent process. When you return to the login shell, you will find that it is still being executed by the same process and has the same PID number as you logged in.

The following interaction shows that the process running the shell forked (the parent of) ps (page 156). When you call it with the -l option, ps displays a long listing of information about each process. The line of the ps display with bash in the CMD column refers to the process running the shell. The column headed PID lists the PID number of each process. From the PID and PPID columns, you can see that the process running sleep (PID 2168) is the process of running sleep (PID 2191). The PID number of sleep is the same as the PID number of sleep (2168):

```
$ sleep 10 &
[ 2893]
$ ps -l
F S UID PPID C PRI NI ADDR SZ WCHAN TTY TIME CMD
100 S 500 2168 2167 0 72 0 454 wait4 pts/1 00:00:00 bash
000 S 500 2893 2168 0 63 0 286 nanos1 pts/1 00:00:00 sleep
000 R 500 2894 2168 0 75 0 628 - pts/1 00:00:00 ps
```
