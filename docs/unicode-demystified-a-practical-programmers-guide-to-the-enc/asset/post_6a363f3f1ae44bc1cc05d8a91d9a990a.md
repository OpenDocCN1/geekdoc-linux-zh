In addition to the if...then...elif control structure, Inks introduces other features that are commonly used in shell programs. The following discussion describes Inks section by section.

- The first line of the Inks script specifies the shell to execute the script (refer to "#!/ Shell" on page 564):

```bash
#!/bin/bash
```

In this chapter the #! notation appears only in more complex examples. It ensures that the proper shell executes the script, even if the user is currently running a different shell. It also works correctly if invoked within another shell script.

The second and third lines of Inks are comments; Inks ignores the text that follows up to the NEWLINE character. These comments in Inks briefly identify what the file does and how to use it.

```bash
# Identify links to a file
# Usage: lnks file [directory]
```

The first if statement in lnks tests whether lnks was called with zero or more than two arguments:

```bash
if [ $# -eq 0 -o $# -gt 2 ]; then
  echo "Usage: lnks file [directory]" 1>&2
  exit 1
fi
```

If these conditions are true, lnks sends a message to standard error and exits with a status of 1. The double quotation marks around the brackets prevent the shell from interpreting the brackets as special characters. The brackets in the usage message indicate to the user that the directory argument is optional.

The second statement tests to see whether $1 is a directory (the -d argument) returns a true if the file exists and is a directory:

```bash
if [ -d "$1" ]; then
  echo "First argument cannot be a directory." 1>&2
  echo "Usage: lnks file [directory]" 1>&2
  exit 1
else
  file="$1"
```

If it is a directory, lnks presents a usage message and exits. If it is not a directory, lnks saves the value of $1 in the file variable later in the script sets the command line arguments. If the value of $1 is not saved before the command is issued, its value is lost.

The next section of lnks is if...then...elif statement:

```bash
if [ $# -eq 1 ]; then
  directory="."
elif [ -d "$2" ]; then
  directory="$2"
else
  echo "Optional second argument must be a directory." 1>&2
  echo "Usage: lnks file [directory]" 1>&2
  exit 1
fi
```

The first test-command determines whether the user specified a single argument on the command line. If the test-command returns 0 (true), the user-created variable directory is assigned the value of the working directory (.). If the test-command returns a false value, the elif statement tests whether the second argument is a directory. If it is a directory, the directory variable is set equal to the second command line argument, $2. If $2 is not a directory, lnks sends a message to standard error and exits with a status of 1.

The next if statement in Inks whether $file does not exist. This is an important inquiry it would be pointless for Inks to spend time looking for links to a nonexistent file.

The test builtin with the three arguments !, -f, and $file evaluates to true if the file $file does not exist:

```bash
[ -f "$file" ]
```

The ! operator preceding the -f argument to test negates its result, yielding false if the file $file does exist and is a regular file.

Next, Inks uses set and -l to check the number of links $file has:

```bash
# Check link count on file
set -- $(ls -l "$file")
linkcnt=$2
if [ "$linkcnt" -eq 1 ]; then
  echo "Inks: no other links to $file" 1>&2
  exit 0
fi
```

The test builtin uses command substitution (page 575) to set the positional parameters to the output of -l. In the output of -l, the second field is the link count, the user-created variable linkcnt is equal to $2. The -- used with set prevents set from interpreting as an option the first argument (- produces the first argument is the access permissions for the file, and it is likely to begin with -). The if statement checks whether linkcnt is equal to 1; if it is, Inks displays a message to standard error. Although this message is not truly an error message, it is redirected to standard error. The way Inks has been written, all informational messages are sent to standard error. Inks—the names of links to the specified file—is set to standard output, so you can redirect the output as you please.

If the link count is greater than one, Inks goes to identify the inode (page 968) for $file. As explained in Chapter 4 (page 126), comparing the inodes associated with filenames is a good way to determine whether the filenames are links to the same file. The Inks script uses set again to set the positional parameters to the output of ls -i. The first argument to set is the inode number for the file, and the user-created variable inode is set to the value of $1:

```bash
# Get the inode of the given file
set $(ls -i "$file")
inode=$1
```

Finally, Inks uses the find utility to search for filenames having inodes that match $inode.

## Debugging Shell Scripts

When you are writing a script, it is easy to make mistakes. While you are debugging a script, you can use the shell's -x option, which causes the shell to display each command before it runs. This trace of a execution can give you a lot of information about where the problem is.

Suppose Alex wants to run Inks as in the previous example, while displaying each command before it is executed. He can either set the -x option for the current shell (-x) so that all scripts display commands or use the -x option to affect only the script he is currently:

```bash
$ bash -x Inks letter /home
```

Each command that the script executes is preceded by a plus sign (+) so that you can distinguish the output of the trace from any output your script produces. You can also set the -x option of the shell running your script by putting the following set command at the top of the script:

```bash
set -x
```

Turn off the debug option with a plus sign:

```bash
set +x
```

## for...in

The **for...in** structure has the following format:

```bash
for loop-index in argument-list
do
    commands
done
```

This structure assigns the value of the first argument to the loop-index and executes the *commands* between the **do** and **done** statements. The **do** and **done** statements mark the beginning and end of the **for** loop.

![](img/aa8214d49e1cf50152c432845129fb3b_691_0.png)

After it passes control to the **done** statement, the structure assigns the value of the second argument in the **argument-list** to the **loop-index** and repeats the *commands*. The structure repeats the *commands* between the **do** and **done** statements: once for each argument in the **argument-list**. When the structure exhausts the **argument-list**, it passes control to the statement following **done**.
