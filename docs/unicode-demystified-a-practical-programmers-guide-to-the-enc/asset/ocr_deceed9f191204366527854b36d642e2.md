The second choice, Manual proxy configuration, allows you to specify the name or internal IP address of the proxy gateway/server and the port (page 1485) that the proxy service listens on for each of several types of proxies. You may need to set up one or two of these, such as HTTP and FTP. Once you are in the address and port for one or more of the services, click OK and that/service(s) will send and receive data to/from the corresponding proxy. The final item in this list is SOCKS Host (which you only if you are using SOCKS); below are two radio buttons that specify the version of SOCKS you are using. At the bottom of this list, just below the two radio buttons, is the No Proxy for text box, in which you can enter a Space-separated list of domains that you want to communicate directly (no proxy). Entries here are exceptions to the previous entries, Enter your domain name here so that you do not use a proxy when you communicate with local servers.

The third choice, Automatic proxy configuration URL, is the most flexible of the three proxy choices. The URL you enter in the text box contains a JavaScript program that is executed when you attempt to connect to a Web site. This program can contain text matches and control statements that connect to one proxy for one domain, another for another domain, and possibly a default no proxy for all other domains. In the same manner, it can deal differently with different services. The URL with its script is usually provided by your firewall administrator.

# hosts: Stores a List of /etc/hosts

The /etc/hosts file store the name, IP address, and optional alias of the other machines that your machine knows about. At the very least, the file must have the hostname and IP address that you have chosen for your local machine and a special entry for localhost. This entry is for a loopback service, which allows the local machine to talk to itself (for example, for RPC services). The IP address of the loopback service is 127.0.0.1. Following is a minimal /etc/hosts file for a machine named achilles:

```
# cat /etc/hosts
# Internet host table
#
127.0.0.1       localhost
10.0.0.1         achilles
```

If you are not using NIS, NIS+, or DNS to look up hostnames (called hostname resolution), you must include in /etc/hosts all the hosts that you want your machine to be able to contact. The order in which hostname resolution services are checked is controlled by the hosts entry in the /etc/nsswitch.conf file (page 1022).
