# Do Not Edit /etc/printcap by Hand

Each time the lpd daemon starts, it recreates the /etc/printcap file, and you will lose manual
changes. Use printconf-gui to edit this file. You can manually add an entry to /etc/printcap.local.
Although printconf-gui does not display entries in /etc/printcap.local, the lpd daemon reads it.

The lpd daemon can also forward jobs to another computer. If you have a
printer that you would like to share on a network, you need to have a printcap en-entry similar to those shown previously on the system that is directly connected to
the printer. On other systems, you need printcap entries that identify the remote ma-chine with the printer. For example, the following entry on a remote machine in-struct lpd to send files for the printer named bravo for printing:

+   # remote printer on bravo (600 dpi, postscript, and duplex)
hires:
- :lp=rm=bravo:sd=/usr/spool/lp4si:if=/var/log/lpd-errors.

The -Phires argument to lpr on a remote machine to cause lpd to forward the
print job to bravo for printing.

The /etc/hosts.lpd and/or the /etc/hosts.equiv files contain a list of remote sys-terms that are allowed to send print requests to the local system. The lpd daemon re-jects a print job from any machine not listed in these of files.

# Use hosts.lpd to Grant Permission to Print security

The /etc/hosts.equiv file allows users from a remote machine to do a lot more than print. Put the name of the remote system in /etc/hosts.lpd if you want to grant permission only to print.

When the remote printer is not available, your print requests are queued on your machine until that printer becomes available. This is handy if you have a lap-top computer, as print jobs are printed when you reconnect the laptop to the local network.

# sys-unconfig: Reconfigures Network Services

On an installed system the easiest way to (re)configure network services is to run the sys-unconfig utility, which first uses touch to create the file named /.configured (this file is just a flag; its contents are not important) and halts the system. When the system comes back up, /etc/rc.d/sysinit runs passwd (for root), netconfig (to configure networking), timeconfig (to set the time zone), authconfig (to configure authentication), and nitrosconfig (to configure services). You can manually give the commands that sys-unconfig uses. The next sections discuss some of the network services and the files that control them.

# hosts: Stores a List of /etc/hosts

The /etc/hosts file store the name, IP address, and optional alias of the other machines that your machine knows about. At the very least, the file must have the hostname and IP address that you have chosen for your local machine and a special entry for localhost. This entry is for a loopback service, which allows the local machine to talk to itself (for example, for RPC services). The IP address of the loopback service is 127.0.0.1. Following is a minimal /etc/hosts file for a machine named achilles:

```
# cat /etc/hosts
# Internet host table
#
127.0.0.1       localhost
10.0.0.1         achilles
```

If you are not using NIS, NIS+, or DNS to look up hostnames (called hostname resolution), you must include in /etc/hosts all the hosts that you want your machine to be able to contact. The order in which hostname resolution services are checked is controlled by the hosts entry in the /etc/nsswitch.conf file (page 1022).
