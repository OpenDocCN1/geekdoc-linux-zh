
# Parameters (Continued)

| Parameter | Description |
| :--- | :--- |
| Automatic Write | By default vim asks before writing out the Work buffer when you have not explicitly told it to do so (as you give a command to edit the next file). The autowrite option causes vim to write the Work buffer automatically when you use commands, as in, to edit another file. You can disable this parameter by setting the noautowrite or noawrite. |
| Show Match | This parameter is useful for programmers working in languages that use braces ({}) or parentheses as expression delimiters (Lisp, C, Tol, and so on). When showmatch is set and you are entering code (in Input mode) and type a closing brace or parenthesis, the cursor will jump briefly to the matching brace or parenthesis (that is, the preceding corresponding element at the same nesting level). After it highlights the matching element, the cursor resumes its previous position. When you type a brace or parenthesis that does not have a match, vim noshowmatch to turn off automatic matching. |
| Report | Causes vim to display a report on the status line whenever you make a change that affects at least n lines (set report=). If report is set to 5 and you delete five lines, you will see the message lines deleted. When delete four or fewer lines, vim does not display a message. The default for report is 5. |
| Shift Width | Controls the functioning of CONTROL-I and CONTROL-D in Input mode when automatic indentation is on. Set the parameter shiftwidth=nn, where nn is the spacing of the indention positions. Setting the shift width is similar to setting the TAB stops on a typewriter; with shiftwidth, however, the distance between TAB stops is always constant. |

# Advanced Editing Techniques

This section presents several commands that you may find once you have become comfortable using vim. While you are using vim, you can set and use markers to make addressing more convenient. Set a marker by giving the command mc, where c is any character. (Letters are preferred because characters, such as a single quotation mark, have special meanings when used as markers.)

# Optional

## Using Markers

Once you have set a marker, you can use it in a manner similar to a tick, to jump to a line number. The vim editor does not preserve markers when you stop editing a file.

You can move the cursor to the beginning of a line that contains a marker by preceding the marker name with a single quotation mark. For example, to set marker t, position the cursor on the line you want to mark, and give the command mt. During this editing session, unless you reset t or delete the line marks, you return to the beginning of the line you marked with the command 't'.

You can delete all text from the current line through the line containing marker r with the following command:

```
d'r
```

You can use a grave accent ('—also called a grave mark, back tick, or reverse single quotation mark) to go to the exact position of marker on the line. After setting t, you can move the cursor to the location of this marker (not the beginning of the line containing the marker) with the command 't. The following command deletes all text from the current line up to the character where the marker was placed; the rest of the line containing the marker remains intact:

```
d'm
```

You can use markers in addresses of commands in place of line numbers. The following command replaces all occurrences of The on all lines from marker m to the current line (marker m must precede the current line):

```
:'m,s/The/THE/g
```

## Editing Other Files

The following command causes vim to edit the file you specify with filename:

```
:e[!] [filename]
```

If you want to save the contents of the Work buffer, you must write it out (using w) before you give this command. If you do not want to save the contents of the Work buffer, vim insists that you use an exclamation point to show that you know you will lose the work you did since the last time you wrote out the Work buffer. If you do not save a filename, vim edits the file you are currently working on.

You can give the command :e to start an editing session over again. This commands the Work buffer to the state it was in the last time you wrote it out, or if you have not written it out, the state it was in when you started the editing file. This is useful when you make mistakes editing a file and decide that it would be-ier to start over than to fix the mistakes.

# Macros and Shortcuts

Because this command does not destroy the contents of the Named buffers, you can store text from one file in a Named buffer, use a :e command to edit a file, and put text from the Named buffer in the second file. A :e command destroys the contents of the General-Purpose buffer and any markers you have set.

The command :e attempts to close the current file and open the last file you were editing, placing the cursor on the line that it was when you last closed the file. If you do not save the file before you give this command, vim will prompt you, reminding you to save the file you are closing. Setting the autowrite parameter (page 455) will not stop vim from prompting you.

The :e command can help you copy blocks of text from one file to another. Call vim with the names of several files as arguments. You can use :e to edit the file, :e: to edit the file you just edited, :rew to rewind the sequence of files so that you are editing the first file again. As you move between files, you can copy text from one file (into a Named buffer [page 448]) and paste it.

The vim editor allows you to create your own macros and shortcuts. The following command allows you to use another shell:

```
:set shell=bin/sh
```

The following command is used to create abbreviations:

```
:abbrev ZZ
```

## Executing Shell Commands from within vim

You can execute shell commands in several ways while you are using vim. You can create a new interactive shell by giving the following command and pressing RETURN:

```
:sh
```

The shell parameter determines what kind of shell is created (usually bash or tsh). By default it is the same as your login shell. After you have done what you want to do in the shell, you can return to vim by exiting from the shell (press exit).

## :sh Does Not Work Correctly

It is possible for the :sh command to behave strangely, depending on how your shell has been configured. You may get warnings with the :sh command, or it may even hang. Experiment with the :sh command to be sure it works with your configuration. If it does not, you might want to try using a different shell by setting the vim parameter to another shell before using :sh. For example, the following command causes vim to use zsh with the :sh command:

```
:set shell=bin/zsh
```

You may need to change the SHELL environment variable after starting :sh to show the correct effect.

## Edit Only One Copy of the File

When you create a new shell by using :sh, you must remember that you are still using vim. A common mistake is to try to editing the same file from the new shell, forgetting that vim is already editing the file from a different shell. Because you can lose information by editing the file from two instances of an editor, vim warns you when you start to edit a file that is already being edited. Refer to "File Locks" on page 425 to see an example of the message that vim displays.

You can execute a shell command line from vim by giving the command, replacing command with the command line you want to execute. Terminate the command with a RETURN:

```
!:command
```

The vim editor spawns a new shell that executes the command. When the command runs to completion, the newly spawned shell returns control to the editor.
