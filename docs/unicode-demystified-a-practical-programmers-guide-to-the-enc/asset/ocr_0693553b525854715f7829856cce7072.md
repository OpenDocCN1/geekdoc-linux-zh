- loose Performs pattern matching when trying to locate where patches go in target-file. In particular, any sequence of whitespace in the patch matches any sequence of whitespace in target-file.

- prefixes strips prefixes from the files to be patched. The value n is the number of slashes to remove from the start of pathnames (any directories between these slashes are removed). Using 0 for n -p causes the pathnames to be unchanged. If you omit this entirely, the entire pathname to the simple filename is removed. This option makes it possible for you to patch files that you have in a location other than the location used by the person who built the patch-file.

-R reverse Attempts to apply the patch in reverse. See "Discussion".

-s silent Reports only errors. Normally patch displays a bit of information about the work it is doing.

# Discussion

The patch utility is designed to simplify the task of keeping the source code for large software applications up-to-date. If you are a software developer, this makes it easier for you to provide updates to users. If you are a user, patch makes it easier for you to obtain and install updates. For example, the entire source distribution for version 2.4.18 of the Linux kernel can be obtained as a compressed archive file of nearly 30 megabytes. However, the patch to change version 2.4.17 into version 2.4.18 is a compressed file smaller than 1 megabyte. If you have 2.4.17 installed and wish to upgrade to version 2.4.18, using the patch is much faster and simpler than downloading and installing the source for 2.4.18.

The patch utility works by reading the patch-file and locating hunks. Each hunk describes the changes needed to change part of a file into the new version. When it finds a hunk, patch locates the affected portion of the target file and performs the changes indicated in the hunk. The patch utility is able to extract hunks that are embedded in mail messages and other text, making it easy to apply patches: Simply feed the mail message as input to the patch program.

If patch finds a hunk that cannot be applied to the target file, the hunk is rejected. All rejected hunks are saved in a file by adding the filename extension .rej to the name of the target file. When patch is successful in making changes to a file, a copy of the original target file is kept with the extension .orig. This makes it possible for you to compare the original and changed versions to examine the changes that were made.
