
```
$ mount
/dev/hdb1 on / type ext2 (rw)
/dev/hdb4 on /tmp type ext2 (rw)
/dev/hda5 on /usr type ext2 (rw)
/dev/sda1 on /usr/X386 type ext2 (rw)
/dev/sda3 on /usr/local type ext2 (rw)
/dev/hdb3 on /home type ext3 (rw)
/dev/hda1 on /dos type msdos (rw,umask=000)
none on /proc proc (ro,noexec,nosuid,nodev)

```

The utility gets this information from the /etc/mtstab (page 961). Which covers mount filesystems; refer to page 1019 for information on NFS to mount remote filesystems.

The first six entries in the preceding example show disk partitioning standard Linux ext2 and ext3 filesystems. Disk partitions on three disks: two IDE disks (hda, hdb) and one SCSI disk (sda). Disk partition /dev/hda1 has a DOS (ms) filesystem mounted at the directory /dos in the Linux filesystem. You can access the DOS files and directories on this partition as if they were Linux files and directories, using GNU Linux utilities and applications. The line starting with none shows the special /proc filesystem (page 966). The last line shows that a CD-ROM has been mounted on a SCSI CD-ROM drive (/dev/scd0).

On occasion the list of files in /etc/mtstab may not be synchronized with the partitions that are mounted. You can remedy this by rebooting the system, or you can refer to the contents of /proc/mounts file, which may have slightly different information than mtab is always correct. You can replace mtab with a symbolic link to /proc/mounts:

```bash
# rm /etc/mtstab
# ln -s /proc/mounts /etc/mtstab
```

## Do Not Mount Anything on Root (/)

Always mount network filesystems and removable devices at least one level below the root level of the filesystem. The root filesystem is mounted on /, you cannot mount two filesystems in the same place. If you were to try to mount something on /, all files, directories, and filesystems that were under root would no longer be available, and the system would crash.

When you add a line for a filesystem to the /etc/fstab file (page 959), Superuser can mount a filesystem by giving the associated mount point (or the device) as using the argument to mount. For example, the SCSI CD-ROM listed was mounted using the following command:

```bash
$ mount /mnt/cdrom
```

This command worked because /etc/fstab contains the additional information needed to mount the file:

```
/dev/scd0 /mnt/cdrom iso9660 user,noauto,ro
```

You can also mount filesystems that do not appear in /etc/fstab. For example, when you insert a floppy disk that holds a DOS filesystem into your floppy drive, you can mount that filesystem by using the command

```bash
# mount -t mdsdos /dev/fd0 /mnt/floppy
```

-t mdsdos specifies a filesystem type mdsdos. You can mount DOS filesystems only if you have configured your Linux kernel (post 1031) to accept DOS filesystems. You do not need to mount a DOS filesystem in order to read and write to it; refer to “Mtools” on page 1256. You need to mount a DOS filesystem for a disk in (for example, vi) to use GNU/Linux commands on the disk.

## Mount Options

The mount utility takes many options which you can specify on the command line or in the /etc/fstab file (page 978). For a complete list of mount options for local filesystems, see the mount man page; for remote filesystems, the nfs mount page.

The noauto option means that the filesystem will not be automatically mounted. The nosuid option forces mounted executables to run with regular permissions (no effective user ID change) on the local system (the system that owns the filesystem).

Unless you specify the user, users, or owner option, only Superuser can mount and unmount filesystems. The user option means that any user can mount the filesystem, but it must be unmounted by the same user who mounted it; users means that any user can mount and unmount the filesystem. These are frequently used for CD-ROM and floppy drives. The owner option, used only under special circumstances, is similar to the user option except that the user mounting must own the device.

## Mounting a Linux Floppy

Mounting a floppy is similar to mounting a partition of a hard disk. Put an entry similar to the following in /etc/fstab for the first floppy drive.

```
/dev/fd0 /mnt/floppy ext2 noauto,users 0 0
```

Create the /mnt/floppy directory if necessary. Insert a diskette and try to mount the first command it. In the following examples, the error message following the first command usually indicates that no filesystem is on the diskette: Use mkfs (page 1057) to create a filesystem, but be careful, mkfs destroys the data on the disk:

```bash
# mount /dev/fd0

# mkfs /dev/fd0
```

Try the mount command again:

## umount: Unmounts a Filesystem

The unmount utility unmounts a filesystem as long as it does not house any files or directories that are in use (open). For example, a logged-in user's working directory must not be on the filesystem you want to unmount. The next command unmounts the CD-ROM shown earlier:

```bash
$ unmount /mnt/cdrom
```

To unmount all filesystems except for the one mounted at /, which can never be unmounted, use

```bash
# unmount -a
```

Unmount a floppy or a remote filesystem the same way you would unmount a partition of a hard drive.

The mount utility uses /etc/fstab to get the necessary information and then unmounts the appropriate filesystem from its server. When a process has a file open on the filesystem that you are trying to unmount, mount displays a message similar to

```
mount: /home: device is busy
```

## When You Cannot Unmount a Device Because It Is In

When a process has a file open on the device you need to unmount, use fuser to determine which process has the file and to kill it. For example, when you want to unmount the floppy, the command fuser -ki /mnt/floppy, which, after checking with you, kills the process using the floppy.

You can mount all filesystems using the -a option, and you can combine that option with the -t option to mount filesystems of a given type. For example, use the following command to mount all nfs filesystems that are not being used:

```bash
mount -at nfs
```

## fstab: Keeps Track of Filesystems

The system administrator maintains the /etc/fstab file, which lists local and remote filesystems, most of which the system mounts automatically when it boots. The fstab file has six columns; a dash keeps the place of a column that has no value. The six columns are:

- **Name:** The name of the block device (page 971) or remote filesystem. A remote filesystem appears as *hostname:pathname*, where *hostname* is the name of the host that houses the filesystem, and *pathname* of the directory that is to be mounted. You can substitute the volume label of the filesystem by using the form LABEL=xx, where xx is the volume label. Refer to elabel page 1057.
- **Mount point:** The name of a directory that the filesystem is to be mounted over. If it does not exist, create this directory with mkdir.
- **Type:** The type of filesystem that is to be mounted. Local filesystems are generally ext2 or ext3, and remote ones are *nfs*. See Table 17-8 on page 973 for a list of filesystem types.
- **Mount options:** A comma-separated list of mount options, such as whether the filesystem is mounted for reading and writing (rw, the default) or readonly (ro). Refer to the mount man page for a list of options.
