You can become Superuser in a number of ways.

+   1. When you bring the system up in single-user mode (page 949), you are Superuser.

+   2. Once the system is up and running in multiuser mode (page 950), you can log in as root: When you supply the proper password, you will be Superuser.

+   3. You can give an su (substitute user) command while you are logged in as yourself, and, with the proper password, you will have Superuser privileges. For more information refer to “su: Gives You Another User’s Privileges” on page 900.

+   4. You can use sudo selectively to give users Superuser privileges for a limited amount of time on per user and per command basis. The sudo utility is controlled by the /etc/sudoers file, which must be set up by root. Refer to the sudo man page for more information.

+   5. Any user can create a setuid (Set User ID) file (page 121). Setuid programs run on behalf of the owner of the file and have all the privileges that the owner has. While you are running as Superuser, you can change the permissions of a file owned by root to setuid. When an ordinary user executes a file owned by root with setuid permissions, the program has full root privileges. In other words, this program can do that root can do and that the program needs to do. The user’s privileges do not change. When the program finishes running, all user privileges are back to the way they were before the program was started. Setuid programs that are owned by root are extremely powerful and extremely dangerous to system security, which is why very few of them are on the system. Examples of root programs include passwd, and crontab. The following example shows two ways for Superuser to give a program setuid privileges:

```
# ls -1 my ☆
-rwxr-xr-x  1 root  other  24152 Apr 29 16:30 myprog
-rwxr-xr-x  1 root  other  24152 Apr 29 16:31 myprog2
# chmod 755 myprog
# chmod u+s myprog
# ls -1 my ☆
-rwxr-xr-x  1 root  other  24152 Apr 29 16:30 myprog
-rwxr-xr-x  1 root  other  24152 Apr 29 16:31 myprog2
```

Refer to chmod (page 1103) and ls (“Notes” on page 12.37) in Part III for more details on creating and identifying programs that are setuid.
