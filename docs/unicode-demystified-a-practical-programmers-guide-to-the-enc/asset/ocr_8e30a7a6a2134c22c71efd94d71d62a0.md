# Notes

GNU mv is implemented as in and rm. When you execute the mv utility, it first makes a link (in) to the new-file and then deletes (rm) the existing-file. If the new-file already exists, mv may delete it before creating the link.

As with rm, you must have write and access permission to the parent directory of the existing-file, but you do not need read or write access to the file itself. If the move would overwrite an existing file that you do not have write permission for, mv displays the access permission and waits for a response. If you enter y or yes, mv renames the file; otherwise, if you do not use the -f option, mv does not prompt you for a response but simply overwrites the file.

If the existing-file and the new-file directory are on different filesystems, GNU mv copies the file instead of renaming it. In this case, after a file is copied, the user who moved it becomes the owner of the file.

Although earlier versions of mv could move only ordinary files between filesystems, mv can now move any type of file, including directories and device files, from one filesystem to another.

# Examples

The first command line renames letter, a file in the working directory, as letter.1201

```
$ mv letter.1201
```

The next command line renames the file so that it appears, with the same filename, in the /usr/archives directory:

```
$ mv letter.1201 /usr/archives
```

The following command line renames all the files in the working directory whose names begin with memo so they appear in the /usr/backup directory:

```
$ mv memo* /usr/backup
```
