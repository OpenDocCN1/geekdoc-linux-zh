
# Control Structures

Whereas this book refers to a control structure or control flow command, the Z Shell documentation refers to a complex command. This chapter will stay with the term control structure or control flow command for consistency with the rest of the book. The control flow commands are used primarily for shell programming, although they can also be useful in interactive work. The Z Shell control structures that control the process flow are if...then, for...in, while, case, repeat, and select. All these except repeat are also present in bash, although zsh provides several different syntactic forms for most of these commands (page 771).

The if (page 626), while and until (page 647) structures have in common use of a test-command (not the test builtin bash). You can use the same syntax for Z Shell-test-commands that you use in the Bourne Shell. You can use the test builtin [[...]] builtin or any other command as the test-command. The syntax of the [[...]] builtin is

```zsh
[[ conditions ]]
```

The result of executing this builtin, the test builtin, is a return status. The conditions allowed within the brackets are almost a subset of those accepted by the test (page 1352). Where the test uses -a as a Boolean AND operator, the Z Shell uses &&. Similarly, where test uses -o as a Boolean OR operator, the Z Shell uses ||. The Z Shell adds the tests listed in Table 15-14.

# Test

| -o option | True if the option named option is set |
| ( expression ) | True if expression is true |
| ! expression | True if expression is false |
| expression1&&expression2 | True if expression1 and expression2 are both |
| expression1 || expression2 | True if either expression1 or expression2 is true |

You can use test's numeric relational operators -gt, -ge, -lt, -lc, -eq, and -ne with [[...]]. The Z Shell allows you to use arithmetic expressions, not just constants, as the operands:

```zsh
zsh % [[ $(( ${HOME} + 14 )) -lt ${PWD} ]]
zsh % echo $?
```

In this example the condition is false (1). The condition would be true (0) if the length of the string represented by the variable HOME plus 14 was less than the length of the string represented by PWD. See the escript on page 588 for more about $?.

# Optional

The test builtin tests whether strings are equal or unequal. The [[...]] builtin adds comparison tests for string operators: The > and < operators compare strings for or-der(that so, for example, "aa" < "bbb"). The = operator tests for pattern match, not just equality: [[string = pattern]] is true if string matches pattern. This operator is not symmetric; the pattern must appear on the right side of the equal sign. For example, [[ artist = a* ]] is true, whereas [[ ae = artist ]] is false (=1):

```zsh
zsh % [[ artist = a* ]]
zsh % echo $?
0
zsh % [[ a* = artist ]]
zsh % echo $?
1
```

The next example has a command list that is started by a compound condition. The condition tests that the directory bin and the file src/myscript.bash exist. If this is true, it copies src/myscript.bash to bin/myscript. If the copy succeeds, chmod makes myscript executable. If any of these steps fails, echo displays a message:

```zsh
zsh % [[ -d bin && -f src/myscript.bash ]] && cp src/myscript.bash \
bin/myscript && chmod +x bin/myscript || echo "Cannot make \
executable version of myscript"
```

The [[...]] builtin is useful by itself, but you will probably use it as the test command for control structures. This builtin also allows an arithmetic test. This test appears inside double parentheses (( )) instead of brackets. As shown in the next example, these double parentheses are not preceded by a $, and the value of this test is not a numeric value, only a true or false exit status:

```zsh
zsh % a=45 b=20
zsh % (a < b)
zsh % echo $?
1
```

```zsh
zsh % ((a > b))
zsh % echo $?
0
```

You can use all the logical arithmetic operators shown on page 762. You can write one of the following:

```zsh
if [[ $((${HOME} + 14 )) -lt ${PWD} ]]
then ...
```

or

```zsh
if [[ $((${HOME} + 14 )) < ${PWD} ]]
then ...
```

or

```zsh
if (( ${HOME} + 14 < ${PWD} ))
then ...
```

The last two commands use comparison operators that are similar to arithmetic and may be more natural for you to use.

The Z Shell recognizes the tokens [[ and (( and treats them as special symbols, not commands. Thus you need not follow [[ or (( with a SPACE.)

# repeat

The repeat control structure allows you to specify how many times a sequence of commands is to be executed. The syntax of repeat is

```zsh
repeat word
do  commands
done
```

Here word is expanded and then evaluated as an arithmetic expression. The value of that expression determines how many times the commands are repeated.

```zsh
zsh % repeat 3
do
echo "hello"
done
```

# Alternative Syntax for Control Structures

Unlike other shells, the Z Shell provides several syntaxes for many commands. The for structure has:

```zsh
for i (a b c)
do
  echo $i
done
```

or

```zsh
for i in a b c
do
  echo $i
done
```

The while structure can be written as:

```zsh
while condition
do
  commands
done
```

# Option Processing

The way that utility interprets its command line is up to the utility. Most utilities conform to certain conventions. Refer to “Command Line” on page 37. In particular, any option the utility takes is indicated by a hyphen:

```zsh
zsh % ls -l
```

Options usually precede other arguments, such as filenames. Most utilities accept options that are combined behind a single hyphen:

```zsh
zsh % ls -lt
```

Some utilities have options themselves require arguments. Typically, an argument is separated from its option by a SPACE:

```zsh
gcc -o prog.c
```

Another convention allows utilities to work with filenames that start with a hyphen. If you have a file whose name is -, the following command is ambiguous:

```zsh
zsh % ls -1
```

It could mean a long listing of all files in the directory or a listing of the file named -. It is interpreted as the former. Avoid creating files whose name begin with hyphens, but if you do, many utilities follow the convention that -- (two consecutive hyphens) indicates the end of options (and the start of arguments). To disambiguate the command, you can type

```zsh
zsh % ls --1
```

or

```zsh
zsh % ls ./-
```

These are conventions, not hard-and-fast rules, and a number of utilities do not follow them (for example, find). Following such conventions is a good idea; it makes much easier for users to learn to use your program. When you write programs that require options, follow the GNU/Linux option conventions.
