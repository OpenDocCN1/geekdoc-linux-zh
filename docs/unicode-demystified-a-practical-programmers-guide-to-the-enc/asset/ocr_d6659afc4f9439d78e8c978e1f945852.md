ZERR

Occurs whenever a command completes with nonzero exit status.
The following command to execute cleanup (a
user-defined function) and then exit from the script with a status of
1:

```
trap 'cleanup'; exit 1 ZERR
```

If command is a null string, the corresponding signal or event is ignored.
atattempt to ignore or set a trap for the KILL (9) signal is ignored. If you have used
trap to set the action for a signal event and when you want to reset it to its default be-
havier, use a hyphen (-) as the action. Without any arguments the trap builtin
all traps in a form that can be saved and read later by the shell.

The following script, named debug, demonstrates how trap works. Modify the
script and experiment with it to get a better feel for how to use: Look the
out in trace; ZERR is called when the script tries to run cpasswd (assuming we
are not logged in as root); INT is called when you press CTRL-C while the script is
running. In addition, cpasswd displays its error message:

```
zsh % cat debug
!/bin/zsh
trap 'echo LINENO $PWD >> trace' DEBUG
trap 'echo ERROR: ZERR:
trap 'echo INTERRUPT;exit INT
trap 'echo EXIT'
count=4
```

```
while [ count -gt 0 ]
do
	echo "hi there"
	usr/sbin/cpasswd
	sleep 1
	echo $count
((count = count - 1))
done
```

In the final pass through the do loop ((count = count - 1)) yields a 0
ands sets return status of 1. (This expression returns a 0 if the result is not 0)
When control passes from this statement, ERR is set and displays ERROR.
