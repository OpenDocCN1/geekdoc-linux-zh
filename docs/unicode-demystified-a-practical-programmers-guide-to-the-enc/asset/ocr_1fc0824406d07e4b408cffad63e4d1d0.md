The test builtin with the three arguments !, -f, and $file evaluates to true if the file $file does not exist:

```
[ -f "$file"]
```

The ! operator preceding the -f argument to test negates its result, yielding false if the file $file does exist and is a regular file.

Next, Inks uses set and -l to check the number of links $file has:

```
# Check link count on file
set -- $(ls "$file")
linkcnt=$2
if [ "$linkcnt" -eq 1 ]; then
  echo "Inks: no other links to $file" 1>&2
  exit 0
```

The test builtin uses command substitution (page 575) to set the positional parameters to the output of -l. In the output of -l, the second field is the link count, the user-created variable linkcnt is equal to S2. The -- used with set prevents set from interpreting as an option the first argument $l - produces the first argument is the access permissions for the file, and it is likely to begin with -). The if statement checks whether linkcnt is equal to 1; if it is, Inks displays a message to standard error. Although this message is not truly an error message, it is redirected to standard error. The way Inks has been written, all informational messages are sent to standard error. Inks—thenames of links to the specified file—is set to standard output, so you can redirect the output as you please.

If the link count is greater than one, Inks goes to identify the inode (page 968) for $file. As explained in Chapter 4 (page 126), comparing the inodes associated with filenames is a good way to determine whether the filenames are links to the same file. The Inks script uses set again to set the positional parameters to the output of ls -i. The first argument to set is the inode number for the file, and the user-created variable inode is set to the value of $1:

```
# Get the inode of the given file
set $(ls -i "$file")\inode=$1
```
