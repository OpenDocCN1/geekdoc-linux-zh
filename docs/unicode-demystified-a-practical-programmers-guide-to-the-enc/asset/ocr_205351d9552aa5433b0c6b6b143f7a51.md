[kudos]
The remote system prompts you for a login name and password. By default the system expects that your login name is the same on both systems; just RETURN if it is. In this case it is not, so Alex enters watson before pressing RETURN. Then he enters his password.

Although it is not necessary in this case, Alex gives a bin (binary) command as a matter of habit; he establishes binary transfer mode as soon as he logs in. With ftp in binary mode, you can transfer ASCII and binary files. ASCII mode can guarantee the successful transfer of ASCII files only.

Binary mode performs an exact, byte-for-byte image of a file. ASCII mode performs end-of-line conversions between different systems and is slower than binary mode. DOS/MS Windows, Macintosh, and UNIX/Linux use each different characters to indicate the end of a line of text. For example, Microsoft operating systems uses a RETURN (CONTROL-M) followed by a NEWLINE (CONTROL-J) to mark the end of a line, whereas UNIX/Linux uses a NEWLINE by itself. Use ASCII mode to transfer plain text files (sometimes indicated by a .txt filename extension) only. Transfer Microsoft Word and other word processing documents in binary mode, as they are not plain text files. Unless specifically need to convert the end-of-line characters, use binary mode.

Before transferring the file, Alex uses ftp's cd command to change directories on the remote system (use lcd to change directories on the local system). Then the put command, followed by the filename, transfers the file to the remote system in the working directory (demos).
The ftp utility makes no assumptions about filesystem structure, because you can use ftp to exchange files with non-UNIX/Linux systems (whose naming conventions can be different).

+   18. The netftp utility, which is included with Red Hat Linux, takes care of the binary issue and others automatically. It is a front end for standard ftp that runs in place of ftp. See the netftp page for more information.
