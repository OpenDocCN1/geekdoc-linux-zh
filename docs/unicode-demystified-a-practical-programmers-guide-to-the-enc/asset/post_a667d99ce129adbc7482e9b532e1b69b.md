## Proxy Server

A proxy is a network service that is authorized to act for a system while not being part of that system. A proxy server or proxy gateway provides proxy services; it is a transparent intermediary, relaying communications back and forth for an application, such as a browser and a server, usually outside of your LAN and frequently on the Internet. When more than one process uses proxy gateway/server, it must keep track of which processes are connecting to hosts/servers or that it can return the return messages to the proper process. The most common proxies that a user encounters are e-mail and Web proxies.

A proxy/gateway isolates the local computer from all other computers or from specified domains using at least two IP addresses: one to communicate with your local computer and one to communicate with a server. The proxy server/gateway examines and changes the header information on all packets that it can encode, route, and decode them properly. The difference between a proxy gateway and a proxy server is that the proxy server usually includes cache (page 1459) to store frequently used Web pages so that the next request for that page is available locally and quickly whereas a proxy gateway usually does not use cache. The terms proxy server and proxy gateway are frequently interchanged. Proxy servers/gateways are available for such common Internet services as HTTP, HTTPS, FTP, SMTP, and SNMP. When an HTTP proxy sends queries from local machines, it presents a single organization-wide IP address (the internal IP address of the proxy server/gateway) to all servers. It funnels all user requests to servers and keeps track of them. When the responses come back, it fans them out to the appropriate applications, using each machine's IP address, protecting local from remote/specified servers. Proxy servers/gateways are generally just one of an overall firewall strategy to prevent intruders from stealing information or damaging an internal network. Other functions, which can be combined with or be separate from the proxy server/gateway, are packet filtering, which blocks traffic based on origin and type, and user activity reporting, which helps management learn how the Internet is being used.

Refer to "Proxies" on page 1016 for practical information on setting up a proxy.

## RPC Network Services

An RPC (remote procedure call) is a call to a procedure (page 1486) that acts across a network. The procedure itself is responsible for accessing and using the network. The RPC libraries make sure that network access is transparent to the application. RPC runs on top of TCP/IP or UDP/IP. The etc/rpc file lists servers for RPCs.¹ This file has three columns: the name of the server for the RPC program, the RPC program number, and the names of programs that use the RPC program.

When an RPC server is initialized, it picks an arbitrary port (page 1485) that it communicates over. The server registers this port with the RPC portmapper on the same machine, using the portmap utility. The portmapper utility always listens on port 111 for both TCP and UDP.

When it wishes to execute an RPC against an RPC server, a client contacts port on the remote machine and asks which RPC server (for example rpc.statd) is listening. The portmapper looks in its tables and returns a UDP or TCP port number. The client connects the server on that port.

The client sends arguments, just as a local function call or procedure would; the RPC libraries take care of transmission; the remote procedure executes with the arguments and generates a result; the RPC libraries encode the result and return it over the network to the client.
