# Discussion

Although the most common use of make is to build programs from source code, also a general-purpose build utility suitable for a wide range of uses. Any place where you can define a set of dependencies to get from one state to another can be an ideal candidate for make.

Much of the power of make comes from the features you can use inside a makefile. For example, you can define variables using the same syntax found in the Bourne Shell. Always define the variable SHELL inside a makefile; set it to the pathname of the shell you want to use when running construction commands. To define the variable and assign it a value, follow the line near the top of your makefile:

```
SHELL=/bin/sh
```

Assigning the value /bin/sh to SHELL allows you to use the makefile on other operating systems. On GNU/Linux systems /bin/sh is generally linked to /bin/bash. The make uses the value of the environment variable SHELL if you do not set SHELL inside the makefile. If this is not the shell you intend to use, this may cause your construction commands to fail.

Other features perform the following tasks:

+   Run specific construction commands silently by preceding them with a @ sign. For example, the following lines will display a short help message

```
help:
echo "You may make the following:"
echo ""
echo "Tibbuf.a -- the buffer buffer"
echo "Bufdisplay -- display any-format buffer"
echo "Buf2ppm -- convert buffer to pixmap"
```

(This technique works because no file is named help in the working directory, so make runs the construction commands in an attempt to build this file. Because the construction commands only print messages and do not, in fact, build the file, you can run make repeatedly with the same result.)

+   Ignore the exit status of specific commands by preceding them with a character. For example, the following line allows make to continue whether the call to /bin/rm is successful (the call to /bin/rm fails if libbuf.a does not exist):

```
~/bin/rm libbuf.a.
```

+   Special variables to refer to information that might change from one make to the next. Such information might includes the files that are newer than the target, or the files that match a pattern. For example, you can use the variable $ in a construction command
