# rc Scripts: Start and Stop System Services

The first script that init runs is /etc/rc.sysinit, the rc.sysinit script also performs for the duration of the boot process: performs basic system configuration, including setting the system clock, hostname, and keyboard mapping; setting up swap partitions; checking the filesystems for errors; and turning on quota management.

Next, the /etc/rc.d/ runs the scripts that handle the services that need to be started when you first bring the system up and to be started or stopped when the system goes from single-user to multiuser mode and back down. Many of the rc (command) scripts are shell scripts—located in the /etc/rc.d/init.d—via symbolic links in the /etc/rc.d/rc.n directory, where n is the runlevel the system is entering.

/etc/rc.d directories contain scripts whose names begin with K (K15htpd, K72autofs, K30sendmail, and so on) and scripts whose names begin with S (S5kudzu, S10network, S13port, and so on). When entering a new runlevel, each of the K (kill) scripts is executed with an argument of start, and then each of the S (start) scripts is executed. The S files run similarly. This setup allows the person who sets up these files to control which services are started and which are stopped and in order, whenever the system enters a runlevel. Using scripts with start and stop arguments is flexible because it allows one script to both start and stop, depending on the argument it is called with.

To customize system initialization, you can add scripts to the /etc/rc.d/init.d directory and add links to the files in init.d from /etc/rc.d/rc.n directories. The following examples show several links to the lpd daemon. These links are called to start or stop the lpd daemon on runlevels.
