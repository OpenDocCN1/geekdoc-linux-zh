Each of the numbers in the IP address is in the range of 0–255 because each segment of the IP address is represented by 8 bits (an octet), capable of taking on two values; the total number of values is $2^8 = 256$. When you start counting at 0, 1–256 each IP address is divided into a network address (netid) portion (which is part of the class) and a host address (hostid) position. See Table 9-2.
The first set of addresses, defining networks, is for extremely large corporations, such as General Electric (3.0.0.0) and Hewlett-Packard (15.0.0.0), or for ISPs. One bit (0) in the first position designates a class network, 7 bits hold the network portion of the address (netid), and 24 bits hold the host portion of the address (hostid, Table 9-2). This means that Ge can have $2^{24}$, or approximately 16 million hosts on its. Unused address space and subnets (page 145) lower this number quite a bit. The 127.0.0.0 subnet is reserved (page 368), as 128.0.0.0 and others.
Two bits (10) in the first two positions designate a class B, 14 bits hold the network portion of the address (netid), and 16 bits hold the host portion of the address, for a potential total of 65,534 hosts. A class C uses three bits (100), 21 net bits (2 million networks), and 8 host bits (254 hosts). Today a large customer will not receive a class A or B network but is likely to receive a class C or several (usually contiguous) class C.
Other classes of networks exist. Class D networks are reserved for multicast (page 1480). When you run `netstat -nr` on your GNU/Linux system, you can see whether your machine is a member of a multicast network.
