Security holes (a type of bug) can compromise the security of the system, allowing malicious users to read and write files, send mail to your contacts in your name, or destroy all the data on the system, rendering the system useless. If engineers fixed all the bugs, there would still be feature requests as long as anyone used the software. Bugs, feature requests and security holes are here to stay and must be tracked if the developers are to fix the most dangerous/important bugs first, users are to research and report bugs in a logical manner, and users are able to apply the developer's fixes quickly and easily.

Early on, Netscape created an internal bug-tracking system BugSplat. Later, after Mozilla became an Open Source project, the Mozilla team decided that it needed its own bug-tracking system. Netscape's IS department wrote a very short-lived version of Bugzilla. Then Terry Weissman, had had been maintaining BugSplat, wrote a new one in Perl for a couple of months later.

Bugzilla belongs to a class of programs formally known as Defect Tracking Systems, of which Bugzilla is preeminent. It is the tool that almost all GNU/Linux developers use to track problems and enhancement requests for their software. Red Hat uses Bugzilla to track bugs and bug fixes for the GNU/Linux distribution; Red Hat Network takes advantage of Bugzilla to notify users and to distribute these fixes.

## Errata: Security Alerts, Bugfixes, and Enhancements

In Red Hat's nomenclature, software enhancements and solutions or fixes to software are referred to as errata. The enhancement requests and bugs are divided into three classes: *security, bugfixes, and enhancements*. To announce the availability of an erratum, Red Hat adopts the term alert to its class: Security Alerts, Bugfix, and Enhancement Alerts. The easiest way to learn of new errata and to obtain them is to use Red Hat Network (page 936).

As the GNU/Linux community, including Red Hat, has fixes operating system and software package bugs, including security holes, Red Hat generates rpm files (page 928) that contain the code that fixes the problems. Installing a new version of a package is almost the same as installing the package in the first place. When running rpm, use -U (upgrade) in place of the -i option. The upgrade option is the same as the install option except that it removes the earlier version of the package.

Lists of errata for all recent releases of Red Hat Linux are available at www.redhat.com: Support and Docs Errata. Click the release you are using and the package you are interested in to view a summary of errata. A lot of information is on this page, including Bug IDs that link to Red Hat's internal Bugzilla system, a list of architectures this errata applies to, and a list of lists to the appropriate rpm files for each of the applicable Red Hat releases. Under each heading that names a release of Red Hat Linux are subheadings, the first of which is SRPMS. The rpm under this heading contain source files that you must compile; they work on any architecture that runs the corresponding version of Red Hat Linux. Next are the RPMs (binary) files; choose them with regard to the architecture you are running. The subheads specify the architecture the binary files within the rpm were compiled on.

The rpm files are available via anonymous FTP from ftp://updates.redhat.com or from one of its mirrors (see footnote 6 on page 905). In one of these FTP sites as anonymous, and give your e-mail address as your password (your browser may do this for you). When you are downloading updates, you will be presented with a list of release numbers. Choose the release number you are using, and follow the hierarchy until you find the rpm number you want. Your path will look similar to ftp://sunsite.ualberta.ca/pub/linux/redhat/updates/8.0/en/i386. The part of the path proceeding redhat varies from site to site, but the part to the right of redhat is always the same for a given file. When you select a site from the Update column of mirror.html, you start in the directory named updates and see the list of version numbers. When you are working from a browser, double-click the icon next to the file/version number that you want to look in or the file that you want to download. When you are running ftp from a command line, refer to “ftp: Transfers Files over a Network” on page 378. Red Hat Network (next) provides an automated way of keeping your system up-to-date.

## Subscribing to Red Hat Network

Perform the following tasks to start using RHN. Although you can perform the tasks in a different order, the following order is convenient, and works:

- When you click the Red Network Alert Notification Tool (a blue icon with a check mark or a red icon with an exclamation point) on the panel, or select the GNOME menu: System Tools⇒Red Hat Network to open the configuration window. Refer to **up2date-config: Configures the RHN Update Agent** on page 940 for help with this window.

When you choose the configuration window, the RHN Update Agent window opens.

- First, the Red Hat Privacy Statement window opens. If you are comfortable with the information in this window, click Forward.
- Then the Register or Update a User Account window opens. Fill in the information in the Required Information frame. RHN will recognize your information if you are already registered with RHN or establish an account for you if you are not registered. Fill in the Org info frame if you are registering as part of a registered organization. Click Forward.
- Then the Hardware window opens. This window establishes a profile name for your computer. The default name is your node (machine) name. You can put any information to help you identify this in this text box. The window also confirms that you want to include the hardware and network information in the profile information that you will send to RHN at the end of this process. When you click Forward, the program compiles a list of all the rpm packages that are installed on your machine.
- Then, the Register a System Profile - Packages window opens (there are two Step 3 windows). This window confirms that you want to include your installed rpm packages as part of your system profile and gives you the option of removing packages from your profile so they do not get updated. Click Forward.
- Finally, click Forward to send your profile to RHN, or click Cancel and not be sent.

Entitle your system. The error: Not enabled for server profile: "profile" means that your system is not entitled. If you get this message, go to rhn.redhat.com, and log in with the user name and password you set up in Step 2, preceding.
