
To see a list of the current aliases, give the command alias. To view the aliases for a particular name, give the command alias followed by the name.

## Differences between the tsh and bash Mechanisms

The alias builtin and substitution used in bash are patterned after the alias builtin found in the Z Shell. It is slightly different from the alias builtin used in tsh, which is patterned after the alias builtin found in the TC Shell. The syntax of the version used by tsh

alias name value

The tsh version of alias (next section) lets you to substitute the command arguments. To do something similar in bash, you have to use a shell function (672).

## History Substitution in an Alias

You can substitute command line arguments by using the history mechanism, with a single exclamation point representing the input line containing the aliases. Modifiers are the same as those used by history (page 686). The exclamation points are quoted in the following example so that the shell does not interpret them when building the aliases (which would produce incorrect results):

- 21% alias last echo !$
- 22% last this is just a test
- 23% alias fn2 echo :2:t
- 24% fn2 /home/jenny/test /home/alex/temp /home/barbara/new

Event 21 defines for an alias that displays the last argument. Event 23 defines for fn2 an alias that displays the simple filename, or tail, of the second argument on the command line.

## Job Control

Job control in bash (page 554) and in tsh is similar. You can move commands between the foreground and background, suspend jobs temporarily, and get a list of the current jobs. The % character references a job when followed by a job number or a string prefix that uniquely identifies the job. You will see a minor difference when you run a multiple-process command line in the background. Bash displays only the PID of the last background process in each job, tsh displays the numbers for all the processes belonging to a job. The example from page 554 looks like this:

```
tsh $ find -print | sort | lpr & grep -1 alex /tmp/ * > alexfiles & &
[1] 18839 18840 18841
[2] 18876
```

## Filename Substitution

The TC Shell expands the characters *, ?, and [] in a pathname as bash does (page 157). The * matches any string of zero or more characters, ? matches any single character, and [] defines a character class, used to match characters appearing within a pair of brackets.

The TC Shell expands command line arguments with a tilde (~) in filenames the same way that bash does (page 694), with the ~ standing for the user's home directory or the home directory of the user whose name follows the tilde. (The special expansions ~+ and -- are not available in tsh.)

Brace expansion is available in tsh, and like brace expansion, is regarded as an aspect of filename substitution. This is true even though brace expansion can generate strings that are not the names of actual files.

In tsh and its predecessor, csh, the process of using patterns to match filenames is referred to as globbing, the pattern itself is called a globbing pattern. If tsh is unable to produce a list of one or more files that match a globbing pattern, it reports an error (unless the pattern contains a brace). Setting the shell variable noglob suppresses filename substitution, including both tilde and brace interpretation.

## Manipulating the Directory Stack

Directory stack manipulation in bash (page 557) and in tsh does not differ much. The dirs builtin displays the contents of the stack, and the pushd popd builtins push directories onto pop directories off the stack.

## Command Substitution

The $(...) for command substitution is not available in tsh. In its place you must use the original '...' format. Otherwise, the implementation in bash and tsh is identical. Refer to (page 575) for more info on command substitution.

## Redirecting Standard Error

All major shells use a greater than symbol (>) to redirect standard output. However, the Bourne Again and Z Shells' syntax to combine and redirect standard output and error output (page 552) differs from that in the TC Shell, which uses a greater than symbol followed by an ampersand (&&). The following examples, like the bash example (page 552), reference the file which does not exist, and the file y, which contains a single line:

## 692 Chapter 14 The TC Shell

```
tcsh $ cat x
cat: x: No such file or directory
tcsh $ cat y
This is y.
tcsh $ cat x > &hold
tcsh $ cat hold
cat: x: No such file or directory
This is y.
```

Unlike bash and zsh, tcsh does not provide a simple way to redirect standard error separately from standard output. A workaround frequently provides a reasonable solution. With an argument of y in the preceding example, cat sends a string to standard output, whereas an argument of x causes cat to send an error message to standard error. A subshell runs cat with both arguments and redirects standard output to a file named outfile. Output sent not touched by the subshell and is sent to the parent shell, where both it and standard output are combined and sent to stderr. Because standard output has already been redirected, stderr contains only output sent to standard error:

```
tcsh $(cat x y > outfile) >&outfile
tcsh $ cat outfile
This is y.
tcsh $ cat outfile
cat: x: No such file or directory
```

It is useful to combine and redirect output when you want to run a slow command in the background and not want its outputing your terminal screen. For example, because the find utility often takes a while to complete, it is a good idea to run it in the background.

The next command finds in the filesystem hierarchy all the files that are named bibliography. The command runs in the background and sends its output to a file named findout. Because the find utility sends to standard error a report of directories that do not have permission to search, you have a record in the findout of any files named bibliography that are found, as well as a record of the directories that could not be searched. The find utility does not require -print in the following command; it is implied by the logic of an action:

```
tcsh $ find -name bibliography -print >& &
```

In this example, if you did not combine standard error with standard output and redirected only standard output, the error messages would appear on your screen, and findout would only contain the list of files that were found.

While you are running in the background command that has output redirected to a file, you can look at the output by using tail with the -f option. The -f option causes tail to display new lines as they are written to the file:

```
tcsh tail -f findout
```

To terminate the tail command, press the interrupt key (usually CONTROL-C). Refer to Part III for more information on find (1165) and tail (1340).

As with the bash coverage, the history (page 686) and alias (page 689) expansions are not included in the following discussion because they cannot be used in a shell script.

The TC Shell scans each token for the various types of expansion in the following order:
