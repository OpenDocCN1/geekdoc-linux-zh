# automount: Mount Filesystems Automatically

With distributed computing you can log in on any machine on the network, and all your files, including startup scripts, will be easily available. A distributed computing environment commonly has all machines able to mount filesystems on all servers: Whichever machine you log in, your home directory will be waiting for you.

Having all machines mount all the time can be problematic. Suppose that machine A mounts some filesystems from machine B and B mounts from machine A. What happens when you bring one of these machines down for maintenance or it crashes? In what order do you reboot when they depend on each other to be up? In a large network you can have one machine mounting disks from tens or hundreds of others for software files and home directories.

One way around this problem is to mount filesystems only on demand. GNU/Linux machines mount daemon is handled by the autofs system (the automount daemon), which is replacing the older, less efficient amd (automounting daemon). Because autofs runs in kernel space (and runs in user space), you need to have support for it in the kernel (Filesystems/Kernel support). For example, when you issue the command /home/auto.home map finds that alex is a key that says to mount franklin/export/homes, and mounts the remote filesystem.

Once the filesystem is mounted, Is displays the list of files you want to see. If after this mounting you give the command /home, Is shows that alex is present within the /home directory. The df utility shows that alex is mounted from franklin. By the default automount daemon automatically unmounts this filesystem after five minutes of inactivity.

Automounting filesystems is similar in concept to MS Windows 9nx network neighborhood.
