You will not receive reminders about mail that arrives for root when you use su to perform administration tasks. However, after using su to become root, you can give the command -u root to root's mail.

Look at the system log files regularly for evidence of problems. Two important files are /var/log/messages, which the operating system and some applications record errors, and /var/log/mailog, which contains errors from the mail system. You can use redhat-logviewer (GNOME/K menu:System Tools-> Logs) to view many of the system tasks.

The logwatch utility (/usr/bin/logwatch points to the /etc/log.d/scripts/logwatch.pl Perl script) is a report writer that reports on log files daily. By-fault the script is run daily (/etc/cron.daily/000-logwatch also points to /etc/log.d/scripts/logwatch.pl) and e-mails its output to root. Refer to the logwatch manual and to the script itself for more information.

# Scheduling Tasks

It is a good practice to schedule certain routine tasks to run automatically. For example, you may want to remove old core files once a week, summarize accounting data daily, and rotate system log files monthly.

# cron and crontab: Schedule Routine Tasks

Using crontab, you can submit a list of commands in a format that can be read and executed by cron. As Superuser you can put commands in one of the /etc/cron.* directories to be run at intervals specified by the directory name, such as cron.daily. Refer to page 1129 in Part III for more information on crontab.

> cron Stops for No One; Try anacron

The cron assumes that the machine it is running on is always running. A similar utility, acorn, does not make assumption and is well suited to portable and home computers that frequently turned off. The anacron utility takes its instructions from the /etc/anacontab unless you specify otherwise. Refer to the anacron and anacontab (Section 5) man pages for information
