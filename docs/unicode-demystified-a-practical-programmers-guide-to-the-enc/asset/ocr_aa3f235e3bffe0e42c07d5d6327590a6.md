# .xinitrc

The ~/.xinitrc is a user's X initialization file. The xinit utility starts the X server and an initial client. When X starts, it locates a virtual console, switches the display to show that, and executes the commands in the user's .xinitrc (if there is one). If your system is configured to use xdm to manage X sessions, use .xsession instead of .xinitrc to customize your X environment. Set up .xsession just as you would .xinitrc. By default X Hats unset.

When you not specify a client and do not have a .xinitrc file, xinit begins up xterm.^2 Because you are running without a window manager, you cannot move or resize xterm, the mouse buttons have no effect outside of xterm, and there is no decoration around xterm. If you create another instance of xterm by giving an exit command from the first xterm, the new xterm appears on top of the first. Because you cannot move the xterm, you cannot use the first xterm until you exit from the second by giving an exit command. After giving an exit command, you will have an instance of xterm over a plain screen.

If a .xinitrc is present in your home directory, X reads commands from that file. This makes .xinitrc a convenient place to start commonly used applications and the window manager of your choice. For example, if you use KDE and want a clock and a terminal window present on your screen when you start X, you could use the following .xinitrc:

```
$ cat .xinitrc
/usr/bin/X11/clock &\n/usr/bin/X11/xterm &
/usr/bin/startkde
```

The commands in .xinitrc are executed sequentially. Leaving the ampersand (&) off the clock line would prevent the initialization of your X session from continuing that past and xterm, and KDE would not start until you exited from xclock, which you cannot because the window manager is not running. For the same reason, it is necessary to run xterm in the background.

The last command is left as a foreground job returns to the virtual console when it finishes executing all the commands in .xinitrc. Usually, you put the command for starting your window manager. In the example startkde will shell scripts KDE, the klein window manager, and many other programs. Take a look at it in /usr/bin/startkde
