## The vim Editor

This chapter begins with a history and description of vi, the original, powerful, sometimes cryptic, interactive, visually oriented text editor. The chapter continues with a tutorial that shows how to use vim (a clone supplied with Red Hat Linux) to create and edit a file. Following the tutorial, the chapter delves into the details of many vim commands and explains the use of parameters for customizing vim to meet your needs. The chapter concludes with a quick reference/summary of vim commands.

# History

Before vi was developed, the standard UNIX system editor was ed (available on your Red Hat system), a line-oriented editor that made it difficult to see the context of your editing. Next come ex, a superset of ed. The most notable advantage of ex has over ed is a display-editing facility that allows you to work with a full screen text instead of just a line. While using ex, you can bring up the display-editing facility by giving a vi (Visual mode) command. The display-editing facility of ex so extensively that the developers of ex made it possible to start the editor with the display-editing facility already running, without having to start ex and give the vi command. Appropriately, they named the program vi. You can call the Visual

mode of ex, and you can go back to ex while you are using vi. Start by running ex; give a vi command to switch to Visual mode, and give a Q command while in Visual mode to use ex.

GNU/Linux offers a number of versions, or clones, of vim. The most popular clones found on GNU/Linux are Elvis, ni, nv², and vim. Each clone offers additional features beyond those provided with the original vi.

The examples in this chapter are based on vim. Red Hat supports two versions of vim. The version in /bin/vi is a minimal build of vim: compact and faster to load but with fewer features. The version in /usr/bin/vim is a full-featured version of vim. If you use one of the other clones, you may notice slight differences from the examples presented in this chapter. The vim (vi improved) editor is compatible with almost all commands and runs on many platforms, including MS Windows, macOS, and GNU/Linux. Refer to the vim home page (www.vim.org) for more information.

The vim editor is not a text formatting program. It does not justify margins or provide the output formatting of a sophisticated word processing system. Rather, vim is a sophisticated text editor meant to write code (C, HTML, Java, and so on), short notes, and input to a text formatting system, such as groff or troff.

Because vim is so large and powerful, only some of its features are described here. Nonetheless, if vim is completely new to you, you may find the limited set of commands described in this chapter overwhelming. The vim provides a variety of ways to accomplish any specified editing task. A useful strategy for learning vim is to begin by learning a subset of commands to accomplish basic editing tasks. Then, as you become more comfortable with the editor, you can learn other commands that enable you to do things more quickly and efficiently. The following tutorial introduces a basic set of vim commands and features that create and edit a file.

Because vim takes advantage of features that are specific to various kinds of terminals, you must tell it what type of terminal or terminal emulator you are using.
