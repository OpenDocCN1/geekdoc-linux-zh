If the argument to the bash builtin is an absolute filename—one starting with a slash (/)—the shell does not consult PATH or cdpath.

# Running a Startup File with the . (Dot) or source Built

After you edit your startup file (such as bash_profile or .bashrc) to change the values of keyword shell variables, you do not have to wait until the next time you log in to put the changes into effect. You can run the startup file using the (dot) or source builtin (page 728). As with all other commands, the must be followed by a SPACE on the command line. Using the . or source builtin is similar to running a shell script, except that commands run the script as part of the current process. Consequently, when you use . source to run a script from your login shell, changes you make to the variables within the script affect the shell. You can use the . or source command to run any script, not simply a startup file, but undesirable side effects (such as having the value of shell variables you relied on) may occur. If you run it as a regular script and did not use the . source, the new variables will be in effect only in the subshell running the script. Refer to "export: Makes a Variable Global" on page 571.

In the following example, bash_profile sets several variables and sets PS1 to the machine name. The . puts the new values into:

```
cat .bash_profile
TERM=vt100
PATH=/bin:usr/sbin:/home/alex/bin
export PS1="$hostname -f"
export CDPATH=$HOME
stty kill ''
$ .bash_profile
bravo.tcorp. $
```

# Positional Parameters

When you call a shell script, the command name and arguments are the positional parameters. They are called positional because within a shell script, you refer to them by their position on the command line. Although you can reference them, only the set bash builtin allows you to change the values of positional parameters (page 584).
