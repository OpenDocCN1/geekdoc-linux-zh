## chkconfig: Config Services III

The chkconfig character-based utility duplicates much of what redhat-config-services does: it makes it easier for a system administrator to maintain the /etc/rc.d directory hierarchy. This utility can add, remove, start-up information, and check the state of system services. To see a list of all services, give the following command:

```bash
# chkconfig --list
hcrelay  0:off  2:off  3:off  4:off  5:off  6:off
dhcpd   0:off  1:off  2:off  3:off  4:off  5:off
syslog   0:off  1:off  2:on  3:on  4:on  5:off
atd     0:off  1:off  2:off  3:on  4:on  5:off
gpm     0:off  1:off  2:off  3:on  4:on  5:off
```

```text
xinetd based services:
charger:     off
rsync:      off
charger:     off
daytime-udp: off
daytime:     off
```

All the services that run their own daemons are listed, one to a line, followed by their configured state for each runlevel. Following that, chkconfig displays each of the xinetd-based services and their current status. You can check on a specific daemon by adding its name to the previous command:

```bash
# chkconfig --list ssh
sshd     0:off  1:off  2:on  3:on  4:off  5:on  6:off
```

In the next example, chkconfig configures the /etc/rc.d hierarchy so that sshd will be off in runlevels 2, 3, 4, and 5 and confirms the change.

```bash
# chkconfig --level 2345 sshd off
# chkconfig --list sshd
sshd     0:off  1:off  2:off  3:off  4:off  5:off  6:off
```

But both ps and service confirm that even though chkconfig sets up so that sshd would be off in all runlevels, it is still running. The chkconfig utility did not shut down sshd. In the following example, the second command line shows that when you give a service command by the name of a daemon, you get the usage for the daemon's script (in this case /etc/rc/init.d/sshd):

```bash
# ps -ef | grep sshd
root 697 1 Oct01 ? 00:00:00 /usr/sbin/sshd
root 172185 21650 0 15:15 pts/4 00:00:00 grep sshd
# service sshd
Usage: /etc/init.d/sshd {start|stop|restart|reload|status}
# service sshd status
sshd (pid 697) is running...
```

When you reboot the machine, sshd will not start, but you can stop it more easily:

```bash
# service sshd stop
Stopping:
# ps -ef | grep sshd
root 17209 21650 0 15:16 pts/4 00:00:00 grep sshd
# service sshd status
sshd is stopped
```

## ntsys: Configure Services IV

The ntsys utility uses a character-based/pseudographical interface that allows you to configure services run at which runlevels. This utility works with services at the current runlevel unless you use the --level option. Follow this option with the levels you want to affect, with no separators between them (--level 345 levels 3, 4, and 5). Use the TAB key to move between sections of the ntsys display and the ARROW keys to scroll the list of services. Press the SPACEBAR to place an asterisk (*) in or remove it from the brackets on the highlighted line. An asterisk indicates that the service will run at the specified runlevel; the absence of an asterisk means that it will not run.

## Single-User Mode

With the system in single-user mode, only the console is enabled. You can perform maintenance that requires filesystems unmounted. The scripts in /etc/rc.d/rc1.d run as single-user initialization.

## Going Multiuser

After you have determined that all is well with all filesystems, you can bring the system up to multiuser mode. When you exit from your single-user shell, init brings you to the default runlevel (usually 3 or 5). Or, the following command brings the system to multiuser mode:

```bash
# telinit 3
```

The telinit utility tells init what runlevel to enter. The telinit executable is a symbolic link to the init executable, but by convention, running telinit is preferred to running init.
