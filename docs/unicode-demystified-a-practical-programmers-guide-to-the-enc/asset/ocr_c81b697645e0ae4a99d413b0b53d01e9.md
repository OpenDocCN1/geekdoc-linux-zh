# Security and xhost // security

Allowing a remote machine access to your display using xhost means that any user on the remote computer can watch everything you type in a terminal emulation, including passwords. For this reason some software packages, such as the Tcl/Tk development system (tcl.sourceforge.net), restrict their capabilities when xhost is used. If you are concerned about security or want to take full advantage of systems like Tcl/Tk, you should use a safer means of granting access to your X session. See the xauth man page for information about a more secure replacement for xhost.

# Remapping Mouse Buttons

Throughout this chapter each description of a mouse click has referred to the button by its position (left, middle, or right) because the position of a mouse button is more intuitive than an arbitrary name or number. In X terminology the leftmost mouse button is button 1, the middle one is button 2, and the right one is button 3.

If you are right-handed, you can conveniently press the left mouse button with your index finger; X programs take advantage of this by relying on button 1 for the most common operations. If you are left-handed, your index finger rests most conveniently on button 3 (the right button).

When you are running GNOME, use the GNOME menu: Preferences->Buttons (page 241) to change to a left- or right-handed mouse. From KDE choose X: Preferences->Peripherals->Mouse->General->Button Mapping (page 327).

You can also change how X interprets the mouse buttons by using xmodmap. If you are left-handed, the following command causes X to interpret the right mouse button as button 3:

```
$ xmodmap -e 'pointer' = 3 2 1'
```

Or with a two-button mouse:

```
$ xmodmap -e 'pointer' = 2 1'
```

When you remap the mouse buttons, remember to reinterpret the descriptions in this chapter accordingly. When this refers to the left button, use the right button instead.
