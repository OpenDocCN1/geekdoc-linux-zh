The second major use of exec is to redirect standard input, output, or error from within a script. Following the next command in a script, all the input to the script is redirected from the file named infile:

```
exec < infile
```

Similarly, the following command redirects standard output and error to outfile and errfile, respectively:

```
exec > outfile 2> outfile
```

When you use exec in this manner, the current process is not replaced with a new process, and exec can be followed by other commands in the script. When a script prompts the user for input, it is useful to redirect the output from within the script to go to the terminal. This redirection ensures that your prompt appears on the user's terminal, even if you have redirected the output from the script. When redirecting the output in a script, you can use /dev/tty as a synonym for the user's terminal. The /dev/tty is a pseudonym the system maintains for the terminal or window the user is using. This pseudonym allows you to refer to the user's terminal without knowing which device it is. By redirecting the output from a script to /dev/tty, you ensure that prompts go to the user's terminal, regardless of which terminal the user is logged in. The following command redirects the output from a script to the terminal the user is on:

```
exec > /dev/tty
```

## Programming the Bourne Shell

When it traps a signal, a script takes whatever action you specify: remove files or finish any processing, display a message, terminate execution, or ignore the signal. If you do not use trap in a script, trap resets the trap to its initial condition, which is usually to exit from the script. If the commands part is present, the shell executes the commands when it catches one of the specified signals. After executing the commands, the shell resumes executing the script where it left off. If you want to prevent a script from exiting when it receives a signal but not run any commands explicitly, you can use trap with a null (empty) builtin, as shown in the locktty script (page 649). The following command trap signal number 15, and the script continues:

```
trap '' 15
```

If you trap without any arguments, the command displays a list of commands associated with each signal. The following script demonstrates how the trap builtin can catch the terminal interrupt signal (2). You can use SIGINT, INT, or 2 to specify the signal. The script returns an exit status of 1:

```
$ cat inter
#!/bin/bash
trap 'echo PROGRAM INTERRUPTED; exit 1' INT
while true

    echo "Program running."
    sleep 1
done
$ inter
Program running.
Program running.
Program running.
CONTROL-C
PROGRAM INTERRUPTED
$
```
