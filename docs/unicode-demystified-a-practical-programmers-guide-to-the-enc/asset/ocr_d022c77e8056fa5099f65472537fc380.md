The following Makefile uses macros, as well as implied dependencies and con-
structions:

```
# makefile: report, print, printf, printf
#
CC=gcc
CFLAGS = -O3
# comment out the two lines above and uncomment the
# two below when you are using the Portland Group's compiler
#CC=pgcc
#CFLAGS = -fast
FILES = in.c out.ratio.c process.c tally.c
OBJECTS = in.o out.ratio.o process.o tally.o
HEADERS = names.h companies.h conventions.h

report: $(OBJECTS)
	$(LINK) -o report $(OBJECTS)

ratio.o: $(HEADERS)

tally.o: $(HEADERS)

print:
	pr $(FILES) $(HEADERS) | 1p

printf:
	pr $(FILES) | 1p

rinth:
	pr $(HEADERS) | 1p
```

Following the comment lines, the make uses the CFLAGS macro to cause
always to use the optimizer (-O3 option) when it invokes the C compiler as
t result of an implied construction. (The CC and CFLAGS definitions for the gcc
C compiler perform the same functions when they are uncommented and you are
using gcc, except that you use -fast with gcc in place of -O3 with gcc.) Whenever
you put a construction line in a Makefile, the construction line overrides the corre-
spponding implied construction line, if one exists. If you want to apply a macro to a
construction command, you must include the macro in that command. This was
done, for example, with OBJECTS in the construction command for the report tar-
get. Following CFLAGS, the Makefile defines the FILES, OBJECTS, and HEADERS
macros. Each of these macros defines a list of files.

The first dependency line shows that report depends on the list of files that OB-
JECTS defines. The corresponding construction line links the OBJECTS and
executable file named report.
