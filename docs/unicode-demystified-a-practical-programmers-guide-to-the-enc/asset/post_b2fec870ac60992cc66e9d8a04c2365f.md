# Note

The test command is built into bash, tsh, and zsh.

# Examples

The following examples show how to use the test utility in Bourne Again scripts. Although test works from a command line, it is more commonly used in shell scripts to test input or verify access to a file.

The first two examples show incomplete shell scripts. They are not complete because they do not test for upper- as well as lowercase input or inappropriate responses and do not acknowledge more than one response.

The first example prompts the user, reads a line of input into the variable `user_input`, and uses test to see whether the user variable `user_input` matches the string:

```
$ cat user_in
echo -n "Input yes or no: "
read user_input
if [ "$user_input" = yes ]
then
echo You input yes.
```

Refer to Chapters 12 and 13 for more information on variables, read, and if.

The next example prompts for a filename and then uses test to see whether the user has read access permission (-r) for the file and (-a) whether the file contains information (-s):

```bash
$ cat validate
echo -n "Enter filename: "
read filename
if [ -r "$filename" -a -s "$filename" ]
then
    echo File $filename exists and contains information.
    echo You have read access permission to the file.
```

The -t criterion checks whether the process running test is sending output to a terminal. If it is, the test utility returns a value of true (0). Following is a listing of the shell script term that runs test:

```bash
$ cat term
test -t 1
echo "This program is (=0) or is not (=1)
sending its output to a terminal:"
```

First, -t is run with the output going to the terminal, that is, the output is not redirected to a file. The test utility returns a 0. The shell stores this value in the shell variable that records the condition code of the last process. The echo utility displays this value:

```bash
$ term
This program is (=0) or is not (=1)
sending its output to a terminal:
```

The next example runs term and redirects the output to a file. The contents of the file show that test returned 1, indicating that its output was not going to a terminal:

```bash
$ term > temp
$ cat temp
This program is (=0) or is not (=1)
```

# top

top [options] dynamically displays process status of your GNU/Linux system, including information about current processes. This utility is similar to ps but periodically updates the display, enabling you to watch the behavior of your system over time.

# Options

Although top does not require the use of hyphens with options, it is a good idea to include them for clarity and consistency.
- -d Specify n as the delay from one update to the next. The default is 5 seconds.
- -n Number of updates: top updates the display n times and exits.
- -q Runs without any delay. Superuser uses this option, top runs at the highest priority.
- -s Runs in Secure mode. This restricts the commands you can use while top is running to those that pose no risk.
- -S Causes top to run in Cumulative mode. When you use this option, CPU times reported for processes include any times accumulated by child processes that are now dead.

# Discussion

The first few lines of top provide a summary of the status of your system. You can turn each of these lines on or off with interactive keys. The first line is the same as the output of the top utility and displays the current time, how long your system has been running since it was booted, the number of users logged in, and load averages from the last 1, 5, and 15 minutes. The second line displays information on the number of processes currently running. The three lines report on CPU, memory, and swap space. The rest of the display reports on individual processes, listed in descending order by CPU usage (the most CPU-intensive process is first). By default top displays only the number of processes that fit on your display.

Table III-31 describes the meaning of the fields displayed for each process.

| Field Name | Description |
|---|---|
| PID | Process identification |
| USER | Login name of the owner of the process |
| PRI | Current priority |
| NI | Nice value (see page 163) |
| SIZE | Current size of process, measured in kilobytes |
| RSS | Number of kilobytes of physical memory currently used |
| SHARE | Number of kilobytes of shared memory used |
| STAT | Status of the process (see STAT on page 290) |
| %CPU | Percentage of the total CPU time that the process is using |
| %MEM | Percentage of physical memory that the process is using |
| TIME | Total CPU time used so far by the process |
| COMMAND | Command line used to start the process |

While top is running, you can use the following commands to modify its behavior. Some of the commands are disabled when running top in Secure mode (-s option).
- -age Sorts processes by age.
- -kill Displays a summary of the commands you can use while running. Allows you to kill a process. Unless you are Superuser, you own it. When you use this command, top prompts you for the PID of the process and the signal to send to the process. You can enter either a signal number (for example, 9) or a name (for example, KILL). This command is disabled when running in Secure mode.
- -memory Sorts processes by resident memory usage.
- -number When you give this command, the top utility asks you to enter the number of processes you want it display. If you enter 0, the default, top shows as many processes as it can fit on the screen.
- -CPU Sorts processes by CPU usage. This is the default sort.
- -quit Terminates top.

renice Changes the priority of a running process. (Refer to nice on page 163.) Unless you are Superuser, you can change the priority only of your own processes and even then to lower the priority by entering a positive value. Superuser can enter a negative value, increasing the priority of the process. This command is not available when top is running in Secure mode.

seconds Prompts you for the number of seconds to delay updates to the display—seconds by default. You may enter an integer, a fraction, or 0 (for continuous updates). This command is unavailable when top is running in Secure mode.

switch Switches back and forth between Cumulative mode and Regular mode. See the –S option for default.

top Writes top's current configuration to ~toprc. This is a good way to write a configuration file for top.

# Notes

The top utility shows only as much as the command line for each process fits the current line of the display. If a process is swapped out, top replaces the command line by the name of the command in parentheses.

The top utility uses proc filesystem. When proc is not mounted, top does not work.

Requesting continuous updates is almost always a mistake: The display updates too quickly, and the system load goes dramatically.
