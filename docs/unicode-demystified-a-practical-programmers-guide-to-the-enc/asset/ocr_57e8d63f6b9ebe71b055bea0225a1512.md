If you select the autolist variable in the following example, the shell choices
automatically when you invoke completion by pressing TAB; you do not have to press
CONTROL-D:

```
tcsh $ set autolist
tctsh $ up $ightarrow$ TAB $ightarrow$ (BEEP)
update update-nox update_scrhot_page\dupdate-config updatedb uptime
tctsh $ up $ightarrow$ TAB $ightarrow$ uptimeRETURN
10:01am up 31 days, 15:14, 7 users, load average: 0.20, 0.06, 0.02
```

If you set autolist to ambiguous, the shell lists the choices when you press TAB only
of the word you enter is the longest prefix of a set of commands. Otherwise,
TAB causes the shell to add one or more characters to the word until it is the longest
prefix; pressing TAB then lists the choices:

```
tcsh $ set autolist-ambiguous
tctsh $ echo $h $ightarrow$ TAB (BEEP)
histfile history
tctsh $ echo $hi $ightarrow$ TAB $ightarrow$ echo $histtab
histfile history
tctsh $ echo $histo $ightarrow$ TAB $ightarrow$ echo $history RETURN
1000
```

The shell must rely on the context of the word within the input line to determine
whether it is a filename, a user name, a command, or a variable name. If the
word is the first on an input line, it is assumed to be a command; if it begins
with the special character $, it is viewed as a variable name, and so on. In the-
following example the second command does not work properly, the
context of the word makes it look like a filename prefix to tcsh, not a command
prefix. The TC Shell supplies with an argument of updates, a nonexe-
cutable file; which displays an error message:

```
tcsh $ is up$=
updates
tctsh $ which updatedb ups uptime
/usr/bin/updatedb
/usr/local/bin/ups
/usr/bin/uptime
tctsh $ which up $ightarrow$ TAB $ightarrow$ which updates
updates: Command not found.
```
