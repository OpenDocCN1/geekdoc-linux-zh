# The mail Environment

You can establish your mail environment by assigning values to mail variables by using the set command in ~/.mailrc. The set command has the following format:

```
set [name=value]|
```

The name is the name of the mail variable that you are setting, and the value is the optional value you are assigning to the variable. The value may be a string or a number. If you use set without a value, mail assigns the variable null (the values of some mail variables are not relevant; it is important only that they are set).

The following is a list of some of the more important mail variables.

- ask: Prompts for the subject of each message.
- askcc: Prompts for the names of people to receive copies of messages you send.
- crit-number: Assign number to this variable if you mail messages containing or more lines be piped through the variable PAGER. If you are using a standard terminal, set number to 2.
- dot: If set, you can terminate mail by entering a period (.) on a line by itself. Unless ignore is also set, entering CONTROL-D on a line still serves to terminate mail.
- ignore: Ignores interrupts while you are composing and sending messages. Setting ignore can make your job easier if you are working on a noisy line.
- record=filename: Copies outgoing messages to filename.
- ignoreof: Causes mail not to save your messages when you quit while composing a message.
- PAGER=pathname: Sets the location to pathname for the pager you want to use for messages that do not fit on your screen. The default pager is vi.
- VISUAL=editor: Sets the editor you want mail to use when you are composing a message.

By default the Bourne Shell checks every 60 seconds for new mail. If mail has arrived, bash presents a message before the next prompt. You can change the frequency of checks by setting the MAILCHECK variable to the number of seconds you want the shell to wait between checks for new mail. Shell does not check for new mail if MAILCHECK is not set.

The following example shows using mail to read messages. After calling mail and seeing that he has two messages, he gives the command to display the second message (simply 2 is enough), followed by RETURN:

```
$ mail

# make

## Keeps a set of programs current

make [options] [target-files] [arguments]

The GNU make utility keeps a set of executable programs current, based on differences in the modification times of the programs and the source files each is dependent on. The executable programs, or target-files, are dependent on one or more prerequisite files. The relationships between target-files and prerequisites are specified in dependency lines in a makefile. Construction commands follow the dependency line, specifying how make can update the target-files.

Refer to page 849 for more information about makefiles. Refer to the make info page and the GNU Make Manual at www.gnu.org/manual/make.

## Arguments

The target-files refer to dependency lines in the makefile. When you do not specify a target-file, make updates the target on the first dependency line in the makefile. Arguments of the form name=value set the variable name to value inside the makefile. See “Discussion” for more information.

## Options

If you do not use the -f option, make takes its input from a file named GNUmakefile, makefile, or Makefile (in that order) in the working directory. Following, this file is referred to as make. Many users prefer to use the name Makefile because it shows up earlier in directory listings.

- -f input file: Runs up to n commands at the same time instead of the default of one. This is especially effective if you are running GNU/Linux on a multiprocessor system.
- -n jobs: Continues with the next file from the list of target-files instead of quitting when a construction command fails.
- -n no execution: Displays the commands it would execute to bring the target-files up-to-date but does not execute the commands.
- -s silent: Does not display the names of the commands being executed.
- -touch: Updates modification times of target files but does not execute any construction commands. Refer to touch on page 1359.

# Discussion

Although the most common use of make is to build programs from source code, it is also a general-purpose build utility suitable for a wide range of uses. Any place where you can define a set of dependencies to get from one state to another can be an ideal candidate for make.

Much of the power of make comes from the features you can use inside a makefile. For example, you can define variables using the same syntax found in the Bourne Shell. Always define the variable SHELL inside a makefile; set it to the pathname of the shell you want to use when running construction commands. To define the variable and assign it a value, follow the line near the top of your makefile:

```
SHELL=/bin/sh
```
