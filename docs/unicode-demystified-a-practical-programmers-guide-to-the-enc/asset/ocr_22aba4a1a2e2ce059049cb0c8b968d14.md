uses a leading colon in optstring to specify that you set for and handle errors in your code; when getops finds an invalid option, it sets varname to ? and OPTARG to the option letter. When it finds an option that is missing an argument, getops sets varname to ? and OPTARG to the option lacking an argument.

The ? case specifies the action to take when getops detects an invalid option. The : pattern specifies the action to take when getops detects a missing option argument. In both cases getops does not write any error message; it leaves that task to you.

If you omit the leading colon from optstring, both an invalid option and a missing option argument cause varname to be the assigned string ?. OPTARG is not set, and getops writes its own diagnostic message to standard error. Generally this method is less desirable because you have less control over what the user sees when there is an error.

Using getops will not necessarily make your programs shorter. Its primary advantages are that it provides a uniform programming interface and it enforces standard option handling.

# # Input and Output

A programming language needs commands for input and output. In the Z Shell, the input command is read, and the output command is print.

# ## read: Accepts User Input

The syntax of read `read` is similar to the Bourne Again Shell's `read` (page 573), but the Z Shell read provides additional functionality: 

```
read [-prs] [-un] [varname?prompt] [varname...]
```

The variable names are optional. The following command is valid as it states:

```
zsh % read
```

It reads an entire input line from standard input into the variable REPLY. When you supply arguments on the command line, read assumes that they are variable names and splits the input line (using the characters in IFS as separators), assigning each word sequentially to a varname argument. If there are not enough variables, the last variable is assigned a string equal to the remainder of the input line. If there are not enough words, the leftover variables are set to null (page 575).
