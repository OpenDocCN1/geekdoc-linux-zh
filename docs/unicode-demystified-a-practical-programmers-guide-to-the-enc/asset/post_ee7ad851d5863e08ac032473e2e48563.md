
Double quotation marks do not prevent the substitution; single quotation marks or a backslash (\)

Because they do not prevent variable substitution but do turn off the special meanings of other characters, double quotation marks are useful when you sign values to variables and when you use those values. To assign a value that contains SPACES or TABs to a variable, use double quotation marks may not be required, it is a good idea to place them around variables whose values you are using, as you can see from the second example:

```
$person="alex and jenny"
$echo $person
alex and jenny
```

When you reference a variable that contains TABs or multiple adjacent SPACES, you need to use quotation marks to preserve the spacing. If you do not quote the variable, echo collapses each string of non-blank characters into a single SPACE when it copies them to standard output:

```
$person="alex  and jenny"
$echo $person
alex and jenny
$echo "$person"
alex and jenny
```

When you execute a command with a variable as an argument, the shell replaces the name of the variable with the value and passes that value to the program to be executed. If the value of the variable contains special characters, such as * or ?, the shell may expand that variable.

The first line in the following sequence of commands assigns the string alex* to the variable memo. The Bourne Again Shell does not expand the string, because dash does not perform pathname expansion (page 157) when assigning a value to a variable. All shells process a command line in a specific order. Within this order the Bourne Again Shell (but not test) expands variables before it interprets commands. In the following echo command line, the double quotation marks quote the asterisk (*) and prevent the Bourne Again Shell from expanding the memo variable before passing its value to the echo command:

```
$memo=alex*
$echo "$memo*"
alex*
```

All shells interpret special characters as special when you reference a variable containing a special character that is not quoted. In the following example the shell expands the value of the memo variable because it is not quoted:

```
$ ls
alex.report
alex.summary
$ echo memo
alex.report alex.summary
```

The preceding example shows that when you do not quote memo, the shell matches the value alex* to two files in the working directory: alex.report and alex.summary.

## unset: Removes a Variable

Unless you remove a variable, it exists as long as the shell in which it was created exists. To remove the value of a variable but not the variable itself, set the value to null (use set person = in tcsh):

```
$ person=
$ echo person
```

You can remove a variable with the unset builtin. To remove the variable person, give the following command:

`unset person`

## readonly: Makes a Variable Permanent

You can use the readonly builtin to ensure that the value of a variable cannot be changed. The next example declares the variable person to be readonly. You must assign a value to a variable before you declare it to be readonly; you cannot change its value after the declaration. When you attempt to change the value of a readonly variable, the shell displays an error message:

```
$ person=jenny
$ echo person
jenny
$ readonly person
$ person=readonly
bash: person: readonly variable
```

If you use the readonly builtin without an argument, it displays a list of all read-only shell variables. This list includes keyword variables that are automatically readonly, as well as any keyword or user-created variables that you have declared as readonly.

## export: Makes a Variable Global

Variables are ordinarily local to the process in which they are declared: A shell script does not have access to variables declared in your login shell unless you explicitly make the variables available (global). You can use export to make a variable available to a child process. Use setenv from the TC Shell to replace the assignment and the exporting required by bash (page 699). The examples in this section work with all shells you use the proper syntax for assigning values to variables and making them global.

Once you use the export builtin with a variable name as an argument, the shell places the value of the variable in the calling environment of child processes. The call by value gives each child process a copy of the variable for its own use.

The following test1 script assigns a value of american to the variable cheese and displays its filename (test1) and the value of cheese. The test1 then calls subtest, which attempts to display the same information. When subtest finishes, it returns control to the parent process, which is executing test1. Then test1 displays the value of the original cheese variable.

```
$ cat test1
cheese=american
echo "test1 1: $cheese"
subtest
echo "ext1 2: $cheese"
$ cat subtest
echo "subtest 1: $cheese"
cheese=swiss
echo "subtest 2: $cheese"
```

```
$ test1
extest1 1: american
subtest 1:
subtest 2: swiss
extest1 2: american
```

The subtest script never receives the value of cheese from test1, and test1 never loses the value. Contrary to, a child can never impact its parent's attributes. When it attempts to display the value of a variable that has not been declared, as is the case with subtest, a process displays nothing; the value of an undeclared variable is that of a null string.

The following script, test2, is the same as test1 but uses export to make cheese available to the subtest script:

```
$ cat test2
cheese=american
echo "test1 1: $cheese"
subtest
echo "ext1 2: $cheese"
$ cat subtest
echo "subtest 1: $cheese"
cheese=swiss
echo "subtest 2: $cheese"
```

```
$ test1
extest1 1: american
subtest 1:
subtest 2: swiss
extest1 2: american
```

The subtest script never receives the value of cheese from test1, and test1 never loses the value. Contrary to, a child can never impact its parent's attributes. When it attempts to display the value of a variable that has not been declared, as is the case with subtest, a process displays nothing; the value of an undeclared variable is that of a null string.

## declare: Sets Attributes and Values

The declare (as typeset) builtin allows you to set attributes and values for variables. You can associate several attributes with declare:

- The -a option declares a variable as an array.
- The -f option makes a variable a function name (functions are discussed on page 67).
- The -i option marks a variable so that integer values are stored efficiently (variable).
- The -r option makes a variable readonly.
- The -x option marks a variable for export.

The following commands declare several variables and set some attributes. The first line declare person1 and assigns it a value of:

```
$ declare person1=alex
$ declare -r person2=jenny
$ declare -rx person3=helen
$ declare person4
```

The readonly and export builtins are synonyms for the commands declare -r and declare -x, respectively. It is legal to declare a variable without assigning a value to, as the preceding declaration of person4 illustrates. This declaration makes person4 available to all subshells, until an assignment is made to it, it has a null value.

Also, you can use the + character in place of - if you want to remove an attribute from a variable. After the following command, making an assignment to person3 does not result in an error:

```
$ declare +r person3
```

If the declare builtin is given with options but no variable names as arguments, the command lists all shell variables that have the indicated attributes set. For example, the option -r with declare gives a list of all shell variables. After the declarations in the preceding example have been given, the results are as:

```
$ declare -r
declare -ar BASH_VERSINFO='([0]="2" [1]="05b" [2]="0" [3]="1" ... )'
declare -ir UID="936"
declare -ir SHELLOPTS="braceexpand:emacs:hashall:histexpand:history:..."
declare -ir UID="500"
declare -ir person2="jenny"
declare -rx person3="helen"
```

The first five entries are keyword variables that are automatically declared readonly. Some of these variables are also stored as integers, the option -i indicates. -a option indicates that BASH_VERSINFO is stored as an array variable; the value of each element of the array is to the right of the equal sign. If you had used readonly to make a keyword variable readonly, the keyword variable would also appear in the list. Another way to get the same list of shell variables is by using readonly with no arguments. Without any arguments or options, the declare lists all the shell variables. The same list is output when you run set (page 584) without any arguments. Another name for declare is typeset. You can list the options to declare separately in any order. The following is equivalent to the declaration of person3:

```
$ declare -x -r person3=helen
```

You can also use the + character in place of - to remove an attribute from a variable.
