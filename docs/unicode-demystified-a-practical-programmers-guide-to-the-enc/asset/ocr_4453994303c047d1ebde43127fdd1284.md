# su: Gives Another User’s Privileges

The (substitute) utility can create a shell or execute a program with the identity and permissions of any user. Follow su on the command with the line name of a user; if you are root or if you know that user's password, take on the identity of that user. When you give a su command without an argument, su defaults to Superuser that you take on the identity of root (you have to know the root password).

To be sure that you are using the system's official version of su (and not one planted on your system by a malicious user), specify su's absolute pathname (/bin/su) when you use it.

When you give a su command to become Superuser, you spawn a new shell, which displays the # prompt. You return to your normal status (and your former shell and prompt) by terminating this shell: Press CTRL-D or give an exit command. Giving a su command by itself changes your user and group IDs but makes minimal changes to your environment. You still have the same PATH when you logged in as yourself. When you run a utility that is normally run by root (in /sbin or /usr/bin), you need to specify an absolute pathname for the utility (as in /sbin/runlevel). When you give the command su -l or --login place of the dash, you get a root login shell: It is as though you logged in as root. Not only are your user and group IDs those of root, but your your environment is that of root. The login shell executes the appropriate start-scripts before giving you a prompt, and your PATH is set to what it would be if you had logged in as root, typically including /sbin and /usr/bin.

You can see the changes in your user and group IDs and the groups you are associated with giving the id command:

```
$ id
uid=500(alex) gid=500(alex) groups=500(alex)
$ 
Password:
# id
uid=0(root) gid=0(root) groups=0(root),1(bin),2(daemon),3(sys), ...
```

You can use su with the -c option to run a single command with root privileges, returning to your original shell when the command finishes executing. The following example shows that a user is not permitted to kill a process. With the use of su -c and the root password, the user is permitted to kill the process. The quotation marks are necessary because su -c takes its command as a single argument.

```
$ kill -15 4982
-bash: kill: (4982) - Operation not permitted
```
