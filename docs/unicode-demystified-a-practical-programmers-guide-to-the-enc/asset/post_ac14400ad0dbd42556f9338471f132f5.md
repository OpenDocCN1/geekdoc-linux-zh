# The TC Shell

The TC Shell (tesh) performs the same function as the Bourne Again Shell, the Z Shell, and other shells: It provides an interface between you and the GNU/Linux operating system. The TC Shell is an interactive command interpreter as well as a high-level programming language. Although you use only one shell at any given time, you should be able to switch back and forth comfortably between them the need arises. Because many of the concepts covered in Chapters 12 and 13 apply to tesh as well as bash and zsh, those chapters provide a good background for this chapter, as well as for use in general. This chapter highlights features of tesh that differ from those of bash, or are absent from bash altogether, or are traditional tesh features that have not taken a strong hold in bash.

The TC Shell is an expanded version of the C Shell (ksh), which originated on Berkeley UNIX and is now included with System V UNIX. The T in TC Shell comes from the names of TENEX and TOPS-2 operating systems, which inspired the command completion (and other) features in the TC Shell. The TC Shell comes with Red Hat Linux. A number of features not found in csh, including file and user name completion, command line editing, and spelling correction. As with csh, you can customize shell to make it more tolerant of mistakes and easier to use. Although some of the functionality of tsh is present in bash and zsh, there are differences in the syntax of some commands. For example, the tsh assignment statement has the following syntax:

```
set variable = value
```

Having SPACES on either side of the equal sign, though illegal in bash, is optional in tsh. The default prompt is a greater sign (>), but Red Hat sets it to a $ character followed by a SPACE. The examples in this chapter use a prompt of tsh $ to avoid confusion with the bash prompt.

# Shell Scripts

With tsh you can execute files containing TC Shell commands, just as bash and zsh can execute files containing Bourne Again and Z Shell commands. The concepts of writing and executing scripts in the two shells are similar. However, the methods of declaring and assigning values to variables and the syntax of control structures are different.

You can run bash, tsh, and zsh scripts while using any one of the shells as a command interpreter. Various methods exist for selecting the shell that runs a script. Refer to “#! Specifies a Shell” on page 564 for more information.

If the first character of a shell script is a pound sign (#) and the following character is not an exclamation point (!), the TC Shell executes the script under tsh. If the first character is anything other than #, tsh calls bash to execute the script.

# echo: Getting Rid of the RETURN

The tcsh echo builtin accepts either a -n option or a trailing \c to get rid of the RETURN that echo normally displays at the end of a line. The zsh echo works the same way, whereas the bash echo accepts only the -n option (refer to "read: Accepts User Input" on page 573).

# Entering and Leaving the TC Shell

You can execute tcsh by giving the command tcsh. If you are not sure which shell you are, use the ps utility to find out. It shows whether you are running tsh, zsh, bash (linked to bash), or possibly another shell. The finger command followed by your login name also displays the name of your login shell, which is stored in the /etc/passwd file. If you want to use tcsh as a matter of course, you can use the chsh (change shell) utility to change your login shell:

```
bash$ chsh
Changing shell for sam.
Password:
New shell [/bin/bash]: /bin/tcsh
Shell changed.
bash$
```

You can leave tsh in several ways. The way you choose depends on two factors: the shell ignoreof is set and whether you are using the shell you logged in (your login shell) or another shell you created after you logged in. # Startup Files

When you log in on the TC Shell, it automatically executes various startup files. They are normally executed in the order shown, but you can compile tsh to use a different order.

- /etc/csh.login
- /etc/csh.crc

These files contain systemwide configuration information, such as the default path, check for mail, and so on.

- ~/.tshrc (or if it does not exist, ~/.tshrc)

This file runs each time a tsh process starts up (the ~ indicates that the file is located in your home directory). You can use the .shrc file to establish variables and parameters that are local to a shell: Each time you create a new shell, tsh initializes these variables for the new shell. In the following sample .tshrc, the tilde (~) represents the pathname of your home directory (refer to “~ Tilde Expansion” on page 609):

```
tsh $ cat ~/.tshrc
set noclobber
set ignoreof
set history=256
set path = (~/bin $path /usr/games)
alias h history
alias ll ls -1
```

This .tshrc file sets several shell variables, establishes two aliases (page 689), and adds two new directories to path: one at the start of the list and one at the end.
