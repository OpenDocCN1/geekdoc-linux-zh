To avoid these kinds of problems, GNU/Linux includes utilities for managing and tracking changes to files. These comprise two source code management systems: RCS (Revision Control System, www.gnu.org/software/rcs) and CVS (Concurrent Versions System, www.cvsh.org), which is built on top of RCS. Although they can be used on any file, these tools are often used to manage source code and software documentation. RCS is oriented towards managing version control over the files in a single directory, CVS expands version control across a hierarchical set of directories. CVS is based on RCS and is designed to control the concurrent access and modification of source files by multiple users.

A graphical front to CVS, tkCVS (www.twobarolecorns.com/tkcvs.html), simplifies the use of CVS, especially if you do not use it frequently enough to memorize its commands and options. Another excellent front is cervisia, which comes with Red Hat.

All three programs/interfaces control who is allowed to update files. For each update, the programs record who made the changes and include notes about why they were made. Because they store the most recent version of a file and the information needed to recreate all previous versions, it is possible to regenerate a version of a file.

A set of file versions for several files may be grouped to form a release. An entire release can be recreated from the information stored with each file. Saving the changes for a file rather than a complete copy of the file generally conserves a lot of disk space, well in excess of the space required to store each update in the RCS and CVS files themselves.

The following sections provide overviews of RCS, CVS, and tkCVS. CVS is built on RCS, these two systems function similarly; the RCS sections even if you are using CVS or tkCVS. As a general rule, you should pick one source code management system and use it for all your work. Which one you choose may depend on personal preference, the type of work put under control, and whether others are sharing the same files. See the CVS-HOW-TO Document for Linux for more information.

# RCS: Revision Control System

When you change a file and record the changes using RCS, the set of changes is called a revision. The revision is stored in an RCS file, which includes any previous revisions of the file, descriptive text for each revision, and additional identifying information. RCS filenames always end with ,v and are generally not edited. The file you are working with and possibly changing with an editor (for example, vi or emacs) is called the working file and has no special naming convention.
