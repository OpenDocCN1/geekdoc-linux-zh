# Functions

The syntax for a shell function has two formats (zsh accepts both formats, bash accepts only the first):

```bash
func_name()
{
  commands
}
```

or

```bash
function func_name
{
  commands()
}
```

The first brace ({) can appear on the same line as the function name. If the function definition includes the names of aliases, they are expanded when the function is read, when it is executed. You can use the break builtin inside a function to terminate its execution. The functions builtin lists all the defined functions.

Shell functions are useful as a shorthand as well to define special commands. The following function starts a process named in the background, with the output normally displayed by process saved in .process.out:

```bash
start_process() {
  process > .process.out 2>&1 &
}
```

There is no setenv builtin in zsh. The following function mimics the behavior of this command, which is available in zsh:

```zsh
zsh % setenv() {
if [ $ -eq 2 ]; then
  export $1=$2
else
  echo "Usage: setenv NAME VALUE" >&2
fi
```

If there are two arguments, the setenv function assigns the value of the second argument to the name of the first and exports the first. The Shell builtin is identical to bash's [page 571]. If there are not two arguments, the function displays a usage message. The unset builtin deletes function definition:

```bash
unset func_name
```

The Shell stores functions in memory so that they run more efficiently than shell scripts. If you define too many functions, the overhead of a shell (as you run a script) becomes unacceptable. You can also store functions in files so that they are read into memory the first time they are called. The autoload builtin notifies zsh that a function is stored in a file. When autoload is executed (normally when you start a new shell), the shell does not load the function into memory but keeps track of its name (it declares as undefined). When a script calls autoload, zsh searches through directories listed in FPATH for a file with the same name (the syntax of autoload is identical to PATH [page 577]). It is your responsibility to ensure that the function definition and the file are stored in the same name. Typically you have one directory with many small files, which, when working on several projects that use different functions, are recognized as special by zsh and excluded by specific times.

### alias: Shortcut for a Command

The zsh builtin is similar to the one in bash, with some added features. A zsh alias does not accept an argument (similar to bash—unlike tsh). A zsh function—similar to bash functions (page 672)—when you need to use an argument. The syntax to establish an alias is `alias [-g] [name=value]` When you are creating an alias, the -g (global) option causes the shell to expand the alias no matter where it appears on a command line. Without this option, aliases are expanded only when they appear as the command name. Aliases are saved from session to session, so users typically establish aliases in a startup file (page 737). Without any arguments alias lists active aliases. When you are listing aliases, the -g option lists global aliases, -r lists regular (nonglobal) -m lists all the aliases that have names matching a pattern that follows the command line, and -L displays aliases so that they are in an appropriate format to enter into a startup file:

```zsh
zsh % alias -m "ps"
alias='less -f'
cd=cd
pages='less -s'
```

You may need to enclose the pattern in single or double quotation marks to keep the shell from expanding before running aliases. Calling alias with an argument of an active alias displays the value of that alias:

```zsh
zsh % alias pages
pages='less -s'
```

The next example creates and then uses a global alias:

```zsh
zsh % alias -g n=alex
zsh % echo n
alex
```

To remove an alias, use unalias with an argument of the name. The following example removes the alias delete:

```zsh
zsh % unalias delete
```

For more information refer to “Alias Substitution” on page 801.

# kill: Aborts a Process

The kill builtin sends a signal to a process or job, using the same syntax as bash. If you do not specify a signal, kill sends a TERM (software termination, 15) signal. For more information on signal names and numbers, see Table 13-5 on page 667. In the following format the n is the signal number, and PID is the identifier of the process that is to receive the signal:

```
kill -n PID
```

The shells also support named signals. To send a signal to a job, you can refer to the signal by name:

```zsh
zsh % kill -TERM %1
```

This command sends the TERM signal to job number 1. Because TERM is the default signal for kill, you can also give the command as kill %1. Use the command -l to display a list of signal names.

Generally any of the signals terminates a process. A program that interrupted has things in an unpredictable state. Temporary files may be left behind (when they are removed), and permissions may be changed. Well-written applications trap, detects, the arrival of signals and cleans up before exiting. Most carefully written applications trap the INT, QUIT, and TERM signals. Try first (press CTRL-C, if the job is in the foreground). Because an application can be written to ignore these signals, you may need to use the KILL signal, which cannot be trapped or ignored; it is a “sure kill.” Refer to page 1224 in Part III for more information on kill.
