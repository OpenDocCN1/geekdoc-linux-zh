
文档优先。某些 Linux 发行版对某些日志文件系统检查程序进行了特殊处理。例如，Mandriva 使用从 /sbin/fsck.reiserfs 到 /bin/true 的符号链接。这种配置在 ReiserFS 分区被标记为自动检查时能加快系统启动速度，但如果你需要手动检查文件系统，这种配置可能会造成混淆。在这种情况下，请运行 /sbin/reiserfsck 来完成这项工作。类似地，/sbin/fsck.xfs 通常只是一个脚本，建议用户运行 fsck_check 或 xfs_repair。

## 监控磁盘使用情况

磁盘的一个常见问题是它们可能会填满。为了避免这个问题，你需要工具来告诉你文件正在消耗多少空间。这正是 df 和 du 程序的任务，它们分别按分区和按目录的方式总结磁盘使用情况。

### 按分区监控磁盘使用情况

df 命令的语法如下：

```
df [options] [files]
```

在最简单的情况下，你可以输入命令名来查看系统所有分区的磁盘空间使用情况摘要：

```
$ df
Filesystem     1K-blocks      Used Available Use% Mounted on
/dev/sdb10         5859784   4449900    1409884  76% /
/dev/sdb12         2086264    991468    1094796  48% /opt
/dev/hda13         2541468    320928    2220540  13% /usr/local
/dev/hda9         15361340  10174596    5186744  67% /home
/dev/hda10        22699288  13663408    7882820  64% /other/emu
/dev/hda6           101089     22613      74301  24% /boot
/dev/sdb5          1953216   1018752     934464  53% /other/shared
none                256528         0     256528   0% /dev/shm
speaker:/home       6297248   3845900    2451348  62% /speaker/home
//win/music        17156608   8100864    9057744  48% /win/mp3s
```

此输出显示了与文件系统关联的设备文件、文件系统的总空间量、文件系统的已用空间、文件系统的可用空间、已用空间的百分比以及挂载点。通常，当已用空间超过 80% 左右时，你应该考虑清理该分区。不过，合适的上限因系统和分区而异。在经常更改文件的分区上风险最大——特别是如果该分区上可能会创建大文件，即使只是临时性的。

你可以通过传递多个选项来微调 df 的效果。每个选项都以特定方式修改 df 的输出：

- **包含所有文件系统** -a 或 --all 选项会在输出中包含大小为 0 的伪文件系统。这些文件系统可能包括 /proc、/sys、/proc/bus/usb 等。
- **使用缩放单位** -h 或 --human-readable 选项会导致 df 缩放并标注其单位；例如，它不会报告分区有 5859784 个块，而是将大小报告为 5.6G（即 5.6GB）。-H 和 --si 选项有类似的效果，但它们使用的是 10 的幂（1,000、1,000,000 等）单位，而不是 2 的幂（1,024、1,048,576 等）单位。-k（--kilobytes）和 -m（--megabytes）选项强制以各自对应的单位输出。
- **总结 inode** 默认情况下，df 总结可用的和已用的磁盘空间。你可以通过传递 -i 或 --inodes 选项来接收关于可用和已用 inode 的报告。如果分区中有大量小文件，这些信息可能会有帮助，因为这些文件会比消耗可用磁盘空间更快地耗尽可用的 inode。

![](img/f339a9f48c4b443e61c74acb4c9c3da4_215_0.png)

> -i 选项对 ext2、ext3、ext4、XFS 以及创建固定数量 inode 的其他文件系统效果很好。其他文件系统，如 ReiserFS，是动态创建 inode 的，这使得 -i 选项变得毫无意义。

- **仅限本地文件系统** -l 或 --local 选项会导致 df 省略网络文件系统。这可以加快操作速度。
- **显示文件系统类型** -T 或 --print-type 选项会在 df 显示的信息中添加文件系统类型。
- **按文件系统类型限制** -t fstype 或 --type=fstype 选项仅显示指定类型文件系统的信息。-x fstype 或 --exclude-type=fstype 选项具有相反的效果；它将从报告中排除指定类型的文件系统。

此列表并不完整；关于更多选项的详细信息，请参阅 df 的手册页。除了这些选项外，你还可以指定一个或多个文件给 df。这样做时，该程序将其报告限制在指定文件或目录所在文件系统上。例如，要了解 /home 分区上的磁盘空间使用情况，你可以输入 df /home。或者，你可以提供设备文件名，如 df /dev/hda9。

### 按目录监控磁盘使用情况

df 命令有助于找出哪些分区有过载的危险；但一旦你获得了这些信息，你可能需要进一步诊断并追踪正在消耗磁盘空间的目录和文件。完成此任务的工具是 du，其语法与 df 类似：

```
du [options] [directories]
```

此命令搜索你指定的目录并报告每个目录消耗的磁盘空间量。此搜索是递归的，因此你可以了解该目录及其所有子目录消耗了多少空间。如果你指定了包含许多文件的目录，结果可能是一个非常长的列表，但有几个选项可以减少此输出的大小。其他选项也可以执行有用的任务：

- **总结文件以及目录** 通常，du 报告目录中文件使用的空间，但不报告单个文件使用的空间。传递 -a 或 --all 选项会导致 du 也报告单个文件。
- **计算总计** 添加 -c 或 --total 选项会导致 du 在其输出的末尾添加一个总计。
- **使用缩放单位** -h 或 --human-readable 选项会导致 du 缩放并标注其单位；例如，它不会报告使用的总磁盘空间为 5859784 个块，而是将大小报告为 5.6G（即 5.6GB）。-H 和 --si 选项有类似的效果，但它们使用的是 10 的幂（1,000、1,000,000 等）单位，而不是 2 的幂（1,024、1,048,576 等）单位。-k（--kilobytes）和 -m（--megabytes）选项强制以各自对应的单位输出。
- **计算硬链接** 通常，du 仅将作为硬链接出现多次的文件计算一次。这反映了真实使用的磁盘空间，但有时你可能希望独立计算每个链接（例如，如果你正在创建 CD-R，且文件将为每个链接存储一次）。要这样做，请包括 -l（这是小写字母 L）或 --count-links 选项。（链接在第 4 章中进行了更详细的描述。）
- **限制深度** --max-depth=n 选项将报告限制在 n 个级别。（即使不报告子目录的内容，也会计算这些内容。）
- **总结** 如果你不想要树中每个子目录都有一行输出，请传递 -s 或 --summarize 选项，该选项将报告限制为你在命令行上指定的文件和目录。此选项等效于 --max-depth=0。
- **限制为单一文件系统** -x 或 --one-file-system 选项将报告限制在当前文件系统。如果另一个文件系统挂载在你想要总结的树内，其内容将不包含在报告中。

此列表并不完整；你应查阅 du 的手册页以获取有关附加选项的信息。

作为 du 实用示例，考虑使用它来发现哪个用户正在 /home 中消耗最多的磁盘空间。很可能你并不关心每个主目录内哪些子目录在使用空间，因此你会向程序传递 -s 选项：

```
$ du -s /home/*
12    /home/ellen
35304 /home/freddie
1760  /home/jennie
12078 /home/jjones
0     /home/lost+found
10110324 /home/mspiggy
```

在此示例中，通配符（`*`）代表 /home 中的所有目录，从而生成所有这些子目录的摘要。（有关此主题的更多信息，请查阅第 4 章。）显然，**mspiggy**（或拥有 /home/mspiggy 目录的人）是最大的磁盘空间使用者——或者至少，该目录的内容消耗了最多的空间。你可以进一步调查，例如输入 du -s /home/mspiggy/* 来了解磁盘空间在 /home/mspiggy 目录内的哪些地方被使用。对于用户文件，如果这种空间消耗是个问题，你可能希望联系该用户，而不是试图自己清理。

> 许多类型的文件不应仅仅被删除。例如，如果你决定删除大多数程序文件，应该通过系统的软件包管理系统来移除它们。（此主题在第 2 章“管理软件”中涵盖。）如果你不确定某个文件是什么或应该如何移除它，不要删除它——尝试进行网络搜索，输入 man filename，或以其他方式研究它以确定它是什么。

## 挂载和卸载文件系统

维护文件系统是必要的，但文件系统存在的整个原因就是存储文件——换言之，是为了有用。在 Linux 下，文件系统最常通过*挂载*——即与目录关联——来使用。这项任务可以通过使用诸如 `mount`（然后用 `umount` 卸载）之类的工具一次性完成，或者通过编辑 /etc/fstab 文件在重启后持久化。

### 临时挂载或卸载文件系统

Linux 提供 `mount` 命令将文件系统挂载到挂载点。`umount` 命令反转此过程。（是的，`umount` 拼写正确；它缺少第一个 `n`。）在实践中，使用这些命令通常不难，但它们支持大量选项。

### `mount` 的语法和参数

`mount` 的语法如下：

```
mount [-alrswv] [-t fstype] [-o options] [device] [mountpoint]
```
