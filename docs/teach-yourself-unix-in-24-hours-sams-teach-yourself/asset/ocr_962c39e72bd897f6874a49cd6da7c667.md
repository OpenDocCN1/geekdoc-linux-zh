# Task 5.6: Establish Default File and Directory Permissions with the umask Command

When I created files, they've had read+write permissions for the owner and group, but no access to anyone else. When you create files on your system, you might find that the default permissions are different.

![](bbox=[0.205, 0.43, 0.283, 0.453])

The controlling variable behind the default permissions is the file creation mask, or umask for.

Inexplicably, umask doesn't always list its value as a three-digit number, but you can find its value in the same way you figured out the numeric permissions strings for chmod. For example, when I enter umask, the system indicates that your umask setting is 07. A leading zero has been dropped, so the actual value is 007, but British M16 could not appreciate!

007 doesn't mean that the default file is created with read+write+execute for everyone else and no permissions for the owner or group. It means quite the opposite, literally.

The umask command is a filter through which permissions are pushed to ascertain what remains. Figure5.8 demonstrates how this works.

Think of your mask as a series of boxes: if the value is true, the information can't excite through the box. If the value is false, it can. Your mask is the direct opposite to how you want your permissions to be set. In Figure 5.8, I want to have 770 as the default permission for any new file or directory I create, so I want to specify the exact opposite of that, 007. Sure enough, with this umask value, when I create new files, the default permission allows read and write access to the owner and group, but no access to anyone else.
