As you can see, it's quite different from the display shown when vi starts up. The status line at the bottom of the display offers useful information as you edit the file at different points, and it also reminds you at all times of the name of the file, a feature that can be surprisingly helpful. emacs can work with different kinds of files, and here you see by the word Fundamental in the status line that emacs is prepared for a regular text file. If you're programming, emacs can offer special features for your particular language.

Already you can see there are some dramatic differences between emacs and vi. If you're comfortable with multiple key sequences such as C-x C-c to quit, I think you're going to enjoy emacs. If not, stick with it anyway. If you never use emacs, it's good to know a little bit about it.

Why about a tool you're not going to use? In this, the answer is UNIX people need to be polarized around the question of which editor is better. Indeed, the debate between vi and emacs is referred to as a 'religious war' because of the high levels of heat and low levels of actual sensitivity of the participants. My position is that different users find different tools best for them. If emacs is closer to how you edit files, that's wonderful, and it's great that UNIX offers emacs as an alternative to vi. Ultimately, the question is whether one is better than the other, but or not you can edit your files more quickly and easily in one or the other.
