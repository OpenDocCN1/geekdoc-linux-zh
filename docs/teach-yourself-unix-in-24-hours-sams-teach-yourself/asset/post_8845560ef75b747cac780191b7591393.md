## Task 4.12: Shrink Big Files with the compress Program

### DESCRIPTION

Now that you can figure out how much space you're using with the files in your directory, you're ready to learn how to save space without removing any files. UNIX has a built-in program—the `compress` program—that offers this capability.

### ACTION

- 1. In this example, the `compress` program is given a list of filenames and then compresses each of the files, renaming them with a .2 suffix, which indicates that they are compressed.

```
% ls -L LIST
-rw------- 1 taylor 106020 Oct 10 13:37 LISTS
% compress LISTS
% ls -l LISTS.Z
-rw------- 1 taylor 44103 Oct 10 13:37 LISTS.Z
```

Compressing the file reduced its size from 106KB to a little more than 44KB (a savings of almost 60 percent in disk space). If you expect to have large files on your system that you won't access often, using the `compress` program can save lots of disk space.

- 2. Using `compress` on bigger files can show even greater savings:

```
% ls -l huge.file
-rw-r--r-- 1 root 3727360 Sep 27 14:03 huge.file
% compress huge.file
% ls -l huge.file.Z
-rw-r--r-- 1 taylor 2121950 Sep 27 14:03 huge.file.Z
```

In this example, it took a powerful Sun computer with no other users exactly 20 seconds to compress huge.file. This single command was able to free up 1.5MB of disk space. If you're using a PC to run UNIX, or if you are on a system with many users (which you can easily ascertain by using the `w` command), it might take a significant amount of time to compress files.

![](img/f32f6f53c129de2ebafcd2b4ff01b1c9_95_0.png)

- 3. To reverse the operation, use the companion command `uncompress`, and specify either the current name of the file (that is, with the .Z suffix) or the name of the file before it was compressed (that is, without the .z suffix).

```
% uncompress LISTS
% uncompress -I LISTS
-rw------ 1 taylor 106020 Oct 10 13:47 LISTS
```

![](img/f32f6f53c129de2ebafcd2b4ff01b1c9_96_0.png)

Why would you compress files? You would do so to save space. Before you use any of the compressed files, though, you must uncompress them, so the `compress` utility is best used with large files you won't need for a while.

JUST A MINUTE

- 4. For information on how well the `compress` program shrunk your files, you can add a -v flag to the program for verbose output:

```
% compress -v huge.file
huge.file: Compression: 43.15% -- replaced with huge.file.Z
```

Try using the `compress` program on some of the files in your directory, being careful not to compress any files (particularly preference or dot files) that might be required to run programs.

## Task 5.1: Understand File Permissions

In the last hour, you learned a bit about interpreting file permissions. Consider the following example:

```
% -l
total 403
drw-- 2 taylor 512 Sep 10 13:38 Archives/
drw-- 3 taylor 512 Oct 01 08:23 Info/

drw--rw-- 1 taylor 1031 Oct 07 15:44 newlists
drw-- 2 taylor 512 Oct 09 10:19 src
```

The first item on each line is what is key. You learned in the previous hour that the first item is called the permissions string or, more succinctly, the permissions. The permissions can be broken into four types: type, owner, group, and other permissions. The first character indicates the type: d is a directory and - is a regular file. There are a number of other types of files in UNIX, each is identified by the first letter of its permissions string, as summarized in Table 5.1.

| Type Character | Description |
| :--- | :--- |
| d | directory |
| - | regular file |
| l | symbolic link |
| c | character device |
| b | block device |
| s | socket |
| p | FIFO (pipe) |
