# Basic Shell Programming

The output here is just Joe is basically. The shell does not know to differentiate between the variables $learning and $learning. Because there is no value assigned to $learning. To solve this problem, enclose the variable in curly braces.

```
$ echo Joe is basically ${learning}
Joe is basically anti-taxes
```

If leaning is undefined, the output might not make sense. It would be Joe is basically taxes. Fortunately, the shell provides a mean to have default value if a variable is undefined:

```
$ echo Joe is basically ${learning:-pro}
Joe is basically pro to taxes
```

If leaning is undefined, the :- syntax tells the shell to use the following string, including the space character, leaving the output blank. This does not assign a value to the variable. If you need to use the variable repeatedly, you might want to assign a value to it, it is undefined. The :- character does this:

```
$ echo Joe is basically ${learning:-pro} ${learning}spending.
Joe is basically pro taxes and pro spending.
```

The first interpretation of the variable finds it undefined, the shell assigns *pro to the variable and outputs. The second time the variable is interpreted, it has the value *pro *.

Variables are assigned by the read command. This assigns an individual word to a specified variable, with the last variable in the list assigned the remaining words.

```
$ read city state message
Morristown, New Jersey Hi Mom!
$ echo Scity is city
Morristown, is city
$ echo $state is state
New is state
$ echo $message is message
Jersey Hi Mom! is message
```

As you can see, only New is assigned to state. The best way around this is to escape the space with a backslash:

```
$ read city state message
Morristown, New Jersey Hi Mom!
$ echo Scity is city
Morristown, is city
$ echo $state is state
New is state
$ echo $message is message
Jersey Hi Mom! is message
```

This can be a bit tricky at first.
