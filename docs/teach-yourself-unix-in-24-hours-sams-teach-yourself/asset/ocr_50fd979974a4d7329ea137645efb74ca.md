# Looking into Files

ASCII is the American Standard Code for Information Interchange and means that the file contains the letters of the English alphabet, punctuation, and numbers, but not much else. There are no multiple typefaces, italics, or underlined passages, and there are no graphics. It is the lowest common denominator of text in UNIX.

+   2. Now try using the asterisk (*)

```
% file *
Global.Software: English text
Interactive.Unix: mail folder
Mail: directory
News: directory
Src: directory
bin: directory
history.usetenet.Z: compressed data block compressed 16 bits
```

The asterisk is a special character in UNIX. By itself, it tells the system to replace it with the names of all the files in the current directory.

This time you can begin to see how file can differentiate files. Using this command, I am now reminded that the file Global.Software is English text, but Interactive.Unix is actually an electronic mail message (file can't differentiate between a single mail message and a multiple-message folder, so it always err on the side of saying that the file is a mail folder)

+   3. Mail folders are actually practical for the file command. One of the systems I use, the file command doesn't know what mail messages are, so asking to analyze mail folders in demonstration of how accuracy is related to the size of the file database.

On a Sun system, I asked file to analyze two mail folders, with the following results:

```
% file Mail/mailbox Mail/sent
Mail/mailbox: mail folder
Mail/sent: mail folder
```

Those two files on a Berkeley UNIX system, however, have very different results when analyzed:

```
% file Mail/mailbox Mail/sent
Mail/mailbox: ASCII text
Mail/sent: shell commands
Mail/sent: English text
```

Not only does the Berkeley version of UNIX not identify the files correctly, it doesn't even misidentify them consistently.
