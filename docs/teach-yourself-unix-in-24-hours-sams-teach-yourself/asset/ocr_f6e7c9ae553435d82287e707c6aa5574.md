# Task 6.2: Copying Files to New Locations using cp

DESCRIPTION One of the most basic operations in any system is moving files, the modern-office computer equipment of paper shuffling. On a computer, moving files is a simple matter of one or two commands: you can move a file to a different location, or you can create a copy of the file and move it to a different location.

The Macintosh has an interesting strategy for differentiating between moving and copying. If you drag a file to another location that's on the same device (a hard disk, example), then by the default computer moves the file to that location. If you drag a file to a location on a different device (from a floppy to a hard disk, instance), the computer automatically copies the file, placing the new, identically copy on the device.

UNIX lacks this subtlety. Instead, UNIX lets you choose which of the two operations you'd like to perform. The two commands are succinctly UNIX mnemonics: mv to move files, and cp to copy files. The mv command also serves the dual duty of renaming files.

> Pronounce cp as "sea pea." When you talk about copying a file, however, say "copy." Similarly, pronounce mv as "em ve," but when speaking of moving a file, say "move."

JUST A MINUTE

I find myself using cp than mv because it offers a slightly safer way to organize files: if I get confused and rename it so that it steps on another file (you'll see what I mean in a moment), I still have original copies of all the files.
