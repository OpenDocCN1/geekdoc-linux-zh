
These people are obsessed with counting the words in their articles, but how do they do it?
You can bet they don't count each word themselves. If they're using UNIX, they simply use the UNIX wc program, which computes a word count for the file. It can also indicate the number of characters (which -c indicates, too) and the number of lines in the file.

- Start by counting the lines, words, and characters in the testme file you created earlier in this hour:
% wc testme 12 121
% wc < testme 4 121
% cat testme | wc 4 12 121
All of these commands offer the same result (which probably seems a bit cryptic now). Why do you need to use three ways of doing the same thing? Later, you learn why this is helpful. For now, stick to the first form of the command.

The output is three numbers, which reveal how many lines, words, and characters, respectively, are in the file. You can see there are 4 lines, 12 words, and 121 characters in testme.

You can have list one of these commands, or a combination of two, by using different command flags: -w counts words, -c counts characters, and -l counts lines:
% wc -w testme 12 testme
% wc -l testme 4 testme
% wc -iw testme 12 4 testme
% wc -lw testme 4 121 testme

Now the fun begins. Here's an easy way to find out how many files you have in your home directory:
% ls | wc -l 37
The command lists each file, one per line (because you didn't use the -c flag).
The output of that command is fed to wc, which counts the number of lines it's fed. The result is that you can find out how many files you have (37) in your home directory.

## Task 8.3: Removing Extaneous Lines

Sometimes you're looking at a file, you'll notice that there are duplicate entries, either blank lines or repeated information. To clean up these files and shrink their size at the same time, you can use the uniq command, which lists each unique line in the file.

Well, sort lists each unique line in the file. uniq really compares each line with the previous line. If the lines are the same, uniq does not list the second line. You can use flags with uniq to get specific results: -u lists only lines that are not repeated, -d lists only lines that are repeated (the opposite of -u), and -c adds a count of how many times each occurred.

- 1. If you use uniq on a file that doesn't have any common lines, uniq has no effect.
- 2. A trick using the cat command that lists the contents of each file sequentially, even if you specify the same file over again, so you can easily build a file with lines:
% cat testme > newest
Examine newest to verify that it contains copies of testme, one after the other (Try using wc).
- 3. Now you have a file with duplicate lines. Will uniq realize these files have duplicate lines? Use wc to find out:
% wc newest
12 36 4
% uniq newest | wc
12 36 12

Remember, the uniq command removes duplicate lines only if they're adjacent.

- 4. Create a file that has duplicate lines:
% tail -n +1 testme > lastline
% cat lastline lastline > newtest2
Now you can see what uniq does:
% uniq newtest2

- 5. Obtain a count of the number of occurrences of each line in the file. The -c flag does that job:
% uniq -c newtest2
This shows that line occurs four times in the file. Lines that are unique have no number.

- 6. You also see what the -d and -u flags do, and how they have exactly opposite actions:
% uniq -d newtest2
% uniq -u newtest2

Why did the -u flag list nothing? The answer is that the -u flag tells uniq to list only those lines that are not repeated in the file. Because the only line in the file is repeated four times, there's nothing to display.

Given this example, you probably think uniq is of marginal value, you will find that it's uncommon for files to have many blank lines throughout the text. The uniq command is a fast, easy, and powerful way to clean up such files.

## Task 8.4: Sorting Information in a File Using sort

Whereas uniq is useful at the end of a pipeline of commands, sort is a filter, a program that is really designed to be tucked in the middle of a pipeline. Filters, of course, can be placed anywhere in a line. The common characteristic of UNIX filters is that they can read from standard input, process it in one manner, and leave the results in standard output. With file redirection, standard input and output are also files. To do this, you can either specify the filenames to the command (usually input only) or use the file-redirection symbols learned earlier in this hour (<, >, >>).

![](img/f32f6f53c129de2ebafcd2b4ff01b1c9_160_0.png)

# Filters and Piping

Standard input and standard output are two very common expressions in UNIX. When a program is run, the default location for receiving input is called standard input. The default location for output is standard output. When you are running UNIX from a terminal, standard input and output are your terminal.

There is a third I/O location, standard error. By default, this is the same as standard output, but you can redirect standard error to a different location than standard output. You learn more about I/O redirection in the book.

![](img/f32f6f53c129de2ebafcd2b4ff01b1c9_161_0.png)

One of the most useful filters is sort, a program that reads information and sorts it alphabetically. You can customize the behavior of this program, like all UNIX programs, to ignore the case of words (for example, to sort big and cat rather than before—most sorts put uppercase letters before the lowercase letters), and to reverse the order of a sort (z to a). The program sort also allows you to sort lists of numbers.
