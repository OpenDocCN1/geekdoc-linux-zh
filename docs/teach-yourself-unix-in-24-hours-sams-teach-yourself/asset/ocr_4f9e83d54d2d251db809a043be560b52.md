The UNIX equivalent of the paper shredder, the rm command allows removal of files. With the -r flag, you can clean out an entire directory. Nothing can be retrieved after the fact, so use great caution.

# Task 6.7: Minimizing the Danger of the rm Command

![](bbox=[0.125, 0.407, 0.236, 0.427])

At this point, you might be wondering why I am making such a big deal of the rm command and the fact that it is advertised to do—that is, removes files. The answer is learning a bit of paranoia now can save you grief in the future. It can prevent you from destroying a full of information you really needed to save.

For DOS, there are commercial programs (Norton Utilities, for instance) that can retrieve removed files. The trash on the Macintosh can be clicked and the files retrieved with ease. If the trash is emptied after a file is accidentally discarded, a program such as Symantec Utilities for the Macintosh can be used to restore files.

UNIX just doesn't have that capability, though, and files that are removed forever.

That said, there are a few things you can do to lessen the danger of using rm and give yourself the ability to remove unwanted files.

![](bbox=[0.125, 0.733, 0.236, 0.753])

You learn about the grep command a few hours from now.)
