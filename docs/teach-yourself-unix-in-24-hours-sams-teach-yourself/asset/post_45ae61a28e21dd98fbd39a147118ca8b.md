The first file, lib.b, demonstrates that file command regards the name of a file: Standard naming for C program files specifies that they end with the characters .c, as in test.c. The third file is an executable, demonstrating another way that file can indicate programs on a Sun workstation. The sendmail program is an interesting program: It is an executable, but it has new information that you haven't seen before. The set-uid indicates that the program is set up so when anyone runs it, it runs as the user who owns the file, not the user who launched it. A quick look can reveal more about this:

```
* ls -l /lib/sendmail
155648 Sep 14 09:11 -rwxr-sr-x 2 root sendmail
```

Notice that the fourth character of the permissions is s rather than the expected x for an executable. Also check the owner of the file in this listing. Combined, the two mean when anyone runs this program, sendmail will set itself to a different user ID (root in this case) and have access permissions. This is how you can send electronic mail without fuss, but you can view the mailbox.

## Looking into Files

Try to identify a few files that are similar in name to the ones I examined and see what file says about them:

```
% cat /dev
dev audio spx sr0 tty
dev: executable script
audio: character special (6/0)
spx: character special (37/35)
sr0: block special (16/0)
tty: character special (2/0)
```

UNIX has two different types of devices, or peripherals, that can be attached: those that provide information in chunks and those that are byte-by-byte. The former are called block devices and the latter character devices. You do not have to worry about the differences, but notice that file can differentiate between them: audio, spx, and tty are all character-files, where sr0 is a block-device.

The pair of numbers in parentheses following the description of each file are known as the major number and minor number of the file. The first indicates the type of device, and the second indicates the physical location of the plug, card, or other hardware that is controlled by the specific peripheral.

The good news is that you don't have to worry about what files are in /dev, or any directory other than your home directory. There are thousands of people working each day without ever realizing these other directories exist, let alone what's in them. What's important is that you have learned the file command is quite sophisticated at identifying UNIX system files of various types. It can be a very helpful tool when you are looking around the file system and even when you are just trying to remember which files are which in your own directory.

## Task 7.3: Peeking at the First Lines with head

Now that you have the tools needed to move about in the file system, double check where you are, and identify the types of different files, it's time to learn about many tools UNIX offers for viewing the contents of files. The first on the list is head, a simple program for viewing the first lines of any file on the system.

The head program is more versatile than it sounds: you can use it to view up to the first few hundred lines of a very long file, actually. To specify the number of lines you want to see, you just need to indicate how many as a starting argument, prefixing the number of lines desired with a dash.

img/f32f6f53c129deebafcd2b4ff01bc9_143.png

The head command is the first of a number of UNIX commands that tend to work with their own variant on the regular rules of starting arguments. Instead of a typical UNIX command argument of -33 to specify 33 lines, head uses -n33 to specify the same information.
