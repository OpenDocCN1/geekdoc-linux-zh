A few hours ago, you learned that the UNIX shell finds a command by searching from directory to directory until it finds a match. The environment variable defines which directories to search and the order in which to search them is the PATH variable. Rather than keep the default settings, I've added a number of directories to search path, which is now as follows:|

+   - :/users/taylor/bin:/usr/bin:/usr/ucb:/usr/local:/etc
- :/usr/local/bin:/usr/unsup/bin:

I have told the always look for commands in the directory (.), then in my bin directory (/users/taylor/bin), and then in the standard directories (/usr,/bin,/usr/ucb,/usr/local). If the commands are not found in any of those areas, the shell should try looking in unusual directories (/etc,/usr,/usr/local/bin). If the shell has not found my command, it should check in a weird directory specific to my site: /usr/unsup/bin for unsupported software, /usr/unsup/elm for programs related to the Elm Mail System, and /usr/local/web for the AT&T Writers Work-bench programs.

> I admit it; using as the first entry in the PATH variable is a security hazard. Imagine this: A devious chap has written a program that will do bad things to my directory when I invoke that program. But how will me invoke it? The easiest way is to give the bad program the same name as a standard UNIX utility, which as is, and leave it in a commonly accessed directory, as /tmp. So what happens? Imagine that the (current directory) is the first entry in my PATH, and I change directories to /tmp to check something. While I'm in /tmp, I enter is without thinking, and voila! I've run the bad program without knowing it. Having at the end of the search path would avoid all this because then the default is command is the correct version.
