
# Moving About in the File System

It’s no surprise that the original UNIX developers decided to have a directory labeled “binaries” to store all the executable programs on the system. Remember the primitive teletypewriter discussed the last hour? Having a slow system to talk with the computer had many ramifications that you might not expect. The single most obvious one was that everything became concise. There were no lengthy words like binaries or listfiles, but successive abbreviations: bin and is, respectively, the UNIX equivalents.

The bin directory where all the binaries were kept in early UNIX. Over time, as more and more executables were added to UNIX, having all the executables in one place became unmanageable, and the bin directory split into multiple parts (/bin, /sbin, /usr/bin).

## The dev Directory

Among the most important portions of your computer are device drivers. Without them, you wouldn’t have any information on your screen (the information arrives courtesy of the display driver). You wouldn’t be able to enter information (the information is read and given to the system by the keyboard driver), and you wouldn’t be able to use your floppy disk drive (managed by the floppy device driver).

Earlier, you learned how anything in UNIX is considered a file in the file system, and the dev directory is an example—often numbering into the hundreds—are stored as separate files in the standard UNIX dev (devices) directory. Pronounce this device name “dev,” not “dee-ee-vee.”

## The etc Directory

UNIX administration can be quite complex, involving management of user accounts, the file system, security, device drivers, hardware configurations, and more. To help, UNIX designates the etc directory as the storage place for all administrative files and information.

Pronounce the device name “ee-tea-sea,” “et-sea,” or “etetera.” All three pronunciations are common.

## The lib Directory

Like your neighborhood community, UNIX has a central storage place for function and procedural libraries. These specific executables are included with specific programs, allowing programs to offer features and capabilities otherwise unavailable. The idea is that if programs want to include certain features, you can reference the shared copy of that utility in the UNIX library rather than having a new, unique copy.

In the previous hour, when you were exploring the calculator, you used the command de -l math to access trigonometric functions. The -l math was to let you know that you wanted to include the functions available through the math library, stored in the lib directory.

Many of the most recent UNIX systems also support what-called dynamic linking, where the library of functions is included on-the-fly as you start the program. The wrinkle is that instead of the library reference being resolved when the program is created, it's resolved when you actually run the program itself.

Pronounce the directory name "lib" or "lib" (to rhyme with the word *bib*).

## The lost+found Directory

With multiple users running many different programs simultaneously, it's a challenge over the years to develop a file system that can remain synchronized with the activity of the computer. Various parts of the UNIX kernel—the brains of the system—help with this problem. When files are recovered after any sort of problem or failure, they are placed here, in the *lost+found* directory, if the kernel cannot ascertain the proper location in the file system. This directory should be empty almost all the time.

This directory is commonly pronounced "lost and found" rather than "lost plus found."

## The mnt and sys Directories

The *mnt* (pronounced "em-en-sys") and *sys* (pronounced "sis") directories are also safely ignored by UNIX users. The *mnt* directory is intended to be a common place to mount external media—hard disks, removable drives, and so on—in UNIX. On many systems, though not all, sys contains files indicating the system configuration.

## The tmp Directory

A directory that you can't ignore, the *tmp* directory—say "temp”—is used by many of the programs in UNIX as a temporary file-storage space. If you are editing a file, for example, the program makes a copy of the file and saves it in *tmp*, and you work directly with that, saving the new file back to your original file when you've completed your work.

On many systems, *tmp* ends up littered with various files and executables by programs that don't remove their temporary files. On one system I use, it's not uncommon to find 10–30 megabytes of files wasting here.

Even so, if you're manipulating files or working with copies of files, *tmp* is the best place to keep the temporary copies of files. Indeed, on some UNIX workstations, *tmp* can actually be the fastest device on the computer, allowing for dramatic performance improvements over working with files directly in your home directory.

## The usr Directory

Finally, the last of the standard directories at the top level of the UNIX file system hierarchy is the *usr*—pronounced "user”—Originally, this directory was intended to be the central place for all user-related commands. Today, however, many companies have their own interpretation, and there's no telling what you'll find in this directory.

## Other Miscellaneous Stuff at the Top Level

Besides the directories previously listed, a number of other directories and files commonly occur in UNIX systems. Some files might have slight variations in name, when you compare your listing to the following, be alert for potential spellings.

A file you might have to bring up UNIX is usually called unix or vunix, named after the specific version of UNIX on your computer. The file contains the actual operating system and must have a specific name be found at the top level. Hand-in-hand with the operating system is another called boot, which helps during initial setup of the hardware.

Notice on one of the previous listings that the files boot and dynix appear. (DYNIX is the name of the variant of UNIX used by Sequent computers.) By comparison, the listing from the Microsystems workstations shows boot and unix as the two files.

Another directory that you might find in your top-level listing is diag—pronounced "dye-ag”—which acts as a storehouse for diagnostic and maintenance programs. If you have any programs within this directory, it's best not to try them out without proper training!

The home directory, sometimes called users, is an easy way to find out what accounts are on the system, because by convention each account directory is named after the user's account name. On one system I use, my account is taylor, and my individual account directory is also called taylor. Home directories are created by the system administrator.

The not directory, if set up correctly, is a handy shortcut for accessing other computers over your network.

The ftpboot is a relatively new feature of UNIX. The letters stand for “trivial transfer protocol boot.” Don't let the name confuse you; though this directory contains versions of the kernel suitable for X Window System-based terminals and diskless workstations to run UNIX.

UNIX systems have directories named for specific types of peripherals that can be attached. On the Sun workstation, you can see examples with the directories cdrom and pets. The former is for a CD-ROM drive and the latter for DOS-format floppy disks.

There are many directories in UNIX, but this will give you an idea of how things are organized.
