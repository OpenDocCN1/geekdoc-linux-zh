# Task 8.5: Number Lines in Files Using cat -n and nl

It can be helpful to have a line number next to each line of a file. It's quite simple to do with the cat program by using the -n flag to number lines in the file displayed.

On many UNIX systems, there's a considerably better command for numbering lines in a file and for many other tasks. The command nl, for lines, is an AT&T System V command. A system that doesn't have the nl command will complain if: command not found. If you have this result, experiment with cat -n instead.

# Task 8.6: Cool nl Tricks and Capabilities

A program that precedes each line with a number isn't much of an addition to the UNIX command tool, so the person who wrote the nl program added some further capabilities. With different command flags, nl can either number all lines (by default it numbers only lines that are not blank) or skip line numbering (which means it's an additional way to display only the lines of contents of a file). The best option, though, is that nl can selectively show those lines that contain a specified pattern.

The command flag for nl is a bit more esoteric than you've seen up to point. The different approaches to numbering lines with nl are all modifications of the -b flag (for body). The four flags are -ba, which numbers lines; -bt, which numbers printable text only; -bn, which results in no numbering; and -bp pattern, for numbering lines that contain the specified pattern. One option is to insert a different separator between the number and the line telling nl to use -s, the separator flag.

![](img/f32f6f53c129de2ebafcd2b4ff01bc9_165_1.png)

Parts of Unix are poorly designed, as you have already learned. For example, if you use the echo command without arguments, you get no output. However, if you add an empty argument (a set of quotation marks with nothing between them), echo outputs a blank line. It doesn't make sense, but it works.

- 2. Now watch what happens when nl uses its default settings to number the lines in testme:

```
% nl testme
1 Global.Software News/ history.usenet.Z
2 Interactive.Unix Src/ testme
3 Mail/ bin/
4 Global.Software News/ history.usenet.Z
5 Interactive.Unix Src/ testme

```

You can accomplish the same thing by specifying nl -bt testme. Try this to verify that system gives the same results.

- 3. It's time to use one of the new two-letter options to number the lines, including the blank lines:

```
% -ba testme
1 Global.Software News/ history.usenet.Z
2 Interactive.Unix Src/ testme
3 Mail/ bin/
4 Global.Software News/ history.usenet.Z
5 Interactive.Unix Src/ testme
6 Mail/ bin/
```

- 4. If you align the contents of my testme file, you can see that two lines contain the word history. To have nl number just those lines, try the -bp pattern-matching option:

```
% -bphistory testme
1 Global.Software News/ history.usenet.Z
2 Interactive.Unix Src/ testme
3 Mail/ bin/
2 Global.Software News/ history.usenet.Z
2 Interactive.Unix Src/ testme
3 Mail/ bin/
```

Notice that the two lines have caused the rest of the lines to fall out of alignment on the display.

- 5. This is when the -s, or separator, option comes in handy:

```
% -bphistory -s: testme
1 Global.Software News/ history.usenet.Z
2 Interactive.Unix Src/ testme
3 Mail/ bin/
2 Global.Software News/ history.usenet.Z
2 Interactive.Unix Src/ testme
3 Mail/ bin/
```

In this case, I specified that instead of using a tab, which is the default separator between the number and line, nl should use a colon: As you can see, the output now lines up again.

Just about anything can be specified as the separator, as sensible or weird as it might be:

```
% nl -s", line is: * test
1, line is: Global.Software
history:
usenet.z
2, line is: Interactive.Unix
3, line is: Mail/
```

```
4, line is: Global.Software
history:
usenet.z
5, line is: Interactive.Unix
6, line is: Mail/
```

Notice the use of single quotation marks (*) in this example. I want to include spaces as part of my pattern, so I need to ensure that the program knows. If I didn't use the quotation marks, nl would use a comma as the separator and tell me that it couldn't open a file called line or is:

The command demonstrates that there are plenty of variations on simple commands. When you read earlier that you would learn how to number lines in a file, did you think that many subtleties were involved?
