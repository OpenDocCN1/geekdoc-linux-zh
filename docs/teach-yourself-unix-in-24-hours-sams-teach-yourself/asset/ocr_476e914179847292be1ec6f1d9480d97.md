The history mechanisms of the shells are wonderful timesavers when you're working with files. I find myself using the csh it and word mechanisms easily to build up complex commands (the previous example, in which I would build up very complex command, step by step) or to the most recently used edit commands. Table 15.1 summarizes the different csh history mechanisms available. I encourage you to learn and use them. They will become second nature and save you lots of typing.

# Task 15.1. C shell history commands.

| Command | Function |
| !! | Repeat the previous command. |
| !$ | Repeat the last word of the previous command. |
| * | Repeat all the first word of the previous command. |
| ^a^b | Replace a with b in the previous command. |
| in | Repeat command n from the history list |

# Task 15.3: Command Aliases

If you think the history mechanism has the potential to save you typing, just haven't learned the command-alias mechanism in the Korn and C shells. Using aliases, you can easily define new commands that do whatever you'd like, or even redefine commands to work differently, have different default flags, or more!
The general format for using aliases in csh is alias command--sequence, and in it is alias word=commands. If you enter alias without any specified words, the output shows a list of aliases you have defined. If you enter alias word in csh, the output lists the current alias, if there is one, for the specified command.

+   One of the most helpful aliases you can create specifies certain flags to is so that each time you enter is, the output will look as though you used the flags with the command. I like to have the -FC flags set.
