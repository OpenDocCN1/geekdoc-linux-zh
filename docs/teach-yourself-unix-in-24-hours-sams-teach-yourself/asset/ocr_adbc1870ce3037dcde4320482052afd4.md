You can see that each process is owned by a specific terminal but that these processes are all idle (that, they've been sleeping for more than 20 seconds). This probably means that these users have turned away for a while. Look back at the output generated by ps -axu, and you will see that newwait is also idle. Because the program runs in a loop: it sleeps for five minutes, checks for new mail, goes back to sleep again, and so on. Processes that have the W in the status column are processes that have been moved out of memory and are swapped out to disk. This is not a problem, and the users might not even realize anything has happened; the only something of this is that when the users wake up their programs, the programs will take an additional second or to return.

These are the "guts" of the UNIX operating system. Notice that none of these processes are actually associated with a terminal. Notice that some of these processes have incredibly low process ID numbers! One-digit process ID is a program that is part of the UNIX system and must be running for UNIX to be alive. Any two-digit process is also started by the system itself but is probably optional. The D status of these processes indicates that they're waiting for disk resources of some sort. Finally, how much time these processes have taken. I venture that you will never have a process that takes 20 minutes CPU time—ever!
