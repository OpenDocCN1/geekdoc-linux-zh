## Task 17.2: Foreground/Background and UNIX Programs

DESCRIPTION Now that you know how to suspend programs in their tracks, it's a true time to learn how to have them running in the background (using the bg command) while you're doing something else and how to have instantly instantly into the background (by using the & notation).

In the first hour, you learned that of the distinguishing characteristics of UNIX is that running programs at the same time. The best part is that you're not limited to just one! If you want to save a couple pages to a file, you can run those processes in the background while you are working on something else.

Once a job is stopped, you can enter fg to start it up as the program you're working with. (The fg command takes its name from foreground, which refers to the program that your display and keyboard are working with.) The process will continue without any output to the screen and without any requirement for input, you can use bg to move it into the background, where it runs until it is done. If the program needs to write to the screen or read from the keyboard, the system will stop its execution automatically and inform you. You then can use fg to bring the program into the foreground to continue running.

TIME SAVER You can use job control also to start up a couple programs and then use the fg command, with the job ID as an argument to start the one you want to work. Not entering the job ID will bring the most recently stopped job back to the foreground. If your system takes a long time to start up big applications (such as emacs or vi), this could save you lots of time.

JUST A MINUTE

A different strategy is to start a program in the background, letting UNIX manage it. If the program needs some input or output, it stops, just like processes you've put into the background with bg after they've started running. To have a program (or pipeline!) automatically start in the background, simply type an & at the end of the command line.

![](img/f32f6f53c129de2ebafcd2b4ff01b1c9_374_0.png)

- 1. Here's an example of a command that processes files without needing any input or offering any:

```bash
awk -F: '{print $1" = "$5"} < /etc/passwd | \
awk -F: '{print $1}' | \
awk '* { (NF > 2) print $0}' | \
sort > who.is
```

After 20 seconds, the prompt returns: it takes long to feed the password file through the three-part awk filter, sort the entire output, and save it to the file who.is.who.

> When you're working with long commands, it's useful to know that you can always move to the next line—even in the middle of entering something—by ending the current line with a single backslash. Note that the backslash must be the very last character on the line!

# Just A Minute

At this point, bg will continue the program, running it in the background:

```bash
% bg
[1] awk -F: '{print $1" = "$5"} < /etc/passwd | awk -F, '{print $1}'
| awk '{ if (NF > 2) print $0 }' | sort | who.is.who
%
```

The number in brackets is this job's control number in the shell. In a moment, you learn why this is a handy number to know:

On some systems, a completed job will notify you that it's done, but on most systems, after a completed job has finished, it waits until you press Return to get a system prompt before it lets you know. after 30 or 60 seconds. Press Return and see this:

```bash
%
[1] Done awk -F: '{print $1" = "$5"} < /etc/passwd | awk -F, '{print $1}
| awk '{ if (NF > 2) print $0 } | sort | who.is.who
%
```

- 3. Alternatively, a better strategy for moving a program into the background is to move process to the background automatically by adding & to the very end:

```bash
% awk &
awk -F: '{print $1" = "$5"} < /etc/passwd | awk -F, '{print $1}'
| awk '{ if (NF > 2) print $0 } | sort | who.is.who
```

This is interesting. This command shows with a control number of 1, but the four numbers listed after are the actual process numbers of each piece: 2756 is the first process, 2757 is the second process, 2758 is the third process, and 2759 is the fourth program. Again, when complete, pressing Return lets you know:

```bash
%
[1] Done awk -F: '{print $1" = "$5"} < /etc/passwd | awk -F, '{print $1}
| awk '{ if (NF > 2) print $0 } | sort | who.is.who
%
```

* Note

- 4. What happens if I try to automatically move to the background a program that has input or output?

```bash
% vi &
```

This looks fine. Pressing Return indicates otherwise, though:

```bash
%
[1] + Stopped (tty output) vi
```

You can see that this program has stopped because of some information it wants to display. The message would be Stopped (tty input). I can use fg to bring this program into the foreground and work with it, or even just quit. Because so much of the UNIX design focuses on running streams through filters and saving the output to a file, there are a number of commands that could be running in the background, freeing you up to do work in the meantime that take a fair amount of processing time and then display information on the screen. When it's time to write to the screen, the program will stop automatically until you enter fg to pull it into the foreground.

## Task 17.3: Finding Out Tasks Are Running

There are two ways to keep track of what programs are flying around. The easier way shows what you've stopped and moved into the background in the shell. Enter jobs, and each (or ksh) tells you what programs, if any. The alternative is a complex command called ps, which shows the status for the entire computer. The processor is another name for the computer itself. Unfortunately, any arguments shows the active or stopped programs with your terminal. The ps program actually has more flags than is I think. The vast majority of them, however, are never to be of value to any normal user. Worse, the flags are different from BSD and System V. The ones that are most helpful are summarized in Table 17.1.

# Table 17.1. Useful flags to the ps command, BSD-style.

| Flag | Meaning |
| :--- | :--- |
| -a | Shows all processes associated with terminals attached to the system. |
| -g | Shows all processes on the system (that is, all processes other than required by the operating system). |

![](img/f32f6f53c129de2ebafcd2b4ff01b1c9_376_0.png)

# Job Control

| Flag | Meaning |
| :--- | :--- |
| -l | Gives the long listing format for each line. |
| -t | Lists processes associated with the specified terminal. |
| -u | Produces user-oriented output. |
| -w | Uses wide output format. If repeated (-ww), it will show much of each command as possible. |
| -x | Shows all processes in the system. |

The -a, -g, and -x flags affect how much information is displayed by ps. To use either the -g or -x command, you must also use the -a command. On most machines, -ax yields considerably more than. The most commonly used flags (and combinations) are -u, to have only your processes in a friendly format; -aux, to see everything on the machine (you almost always want to pipe this to grep or more, to be overrun with hundreds of lines of information); and -wxx, to show all the processes associated with the terminal.

> The ps program varies from System V to Berkeley UNIX more than any other command. Unfortunately, the two or three most common flags are similar across the two systems. To explore more about the ps command on your system, you should start by reading the man page.
