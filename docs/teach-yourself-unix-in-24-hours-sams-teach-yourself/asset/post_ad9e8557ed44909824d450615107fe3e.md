# SUMMARY

You can use the cp command to copy an original file as a new file or to a specific directory (the format being original-file new-file-or-directory), and you can copy a bunch of files to a directory (cp list-of-files new-directory). Experiment with creating directories using mkdir and copying the files into the new locations. Use ls to confirm that the originals aren't removed as you go along.

# Task 6.3: Moving Files to New Locations mv

## DESCRIPTION

Whereas cp leaves the original file intact, making a sort of electronic equivalent of a photocopy of a paper I pick up at my desk, mv functions like a more traditional desk: papers are moved from one location to another. Rather than creating multiple copies of the files you are copying, mv physically relocates them from one directory to the other.

- 1. You use mv almost the same way you use cp:
% ls -l login.copy
-rw-- 1 taylor 1858 Nov 5 12:08 login.copy
% mv login.copy new.login
% ls -l login.copy new.login
login.copy not found
-rw-- 1 taylor 1858 Nov 5 12:08 login.login

- 2. Also, you move a group of files together mv almost the same way you use cp:
% cd NEWDIR
% ls
% cshrc.login.copy
% mv cshrc.copy login.copy -
% ls -l
-total 0
% ls
Archives/ mailing-lists.bitnet.Z
Infor/ PubAccessLists.Z new.login
LISTS/ runors.260ct.Z
Mail/ bnn/ cshrc. runors.5Nov.Z
NEWDIR/ educ
News/ login.copy src/

- 3. Because you can use mv to rename files or directories, you can relocate the directory NEWDIR. However, you cannot use mv to relocate the directory because you are inside it:

```
% mv -- new.dot
mv :: rename: Invalid argument
```

- 4. Both mv and cp can be dangerous. Carefully consider the following example trying it mv on your computer:

```
% ls -l login.copy cshrc.copy
-rw-- 1 taylor 1178 Nov 5 12:38 cshrc.copy
-rw-- 1 taylor 1858 Nov 5 12:37 login.copy
% cp cshrc.copy login.copy
% ls -l login.copy cshrc.copy
```

# Creating, Moving, Renaming, and Deleting Files and Directories

```
-rw---- 1 taylor 1178 Nov 5 12:38 cshrc.copy
-rw---- 1 taylor 1178 Nov 5 12:38 login.copy
```

Without bothering to rename it, UNIX copied the file cshrc.copy over the existing file login.copy. Notice that after the cp operation occurred, both files have same size and modification dates.

The mv command will cause the following problem:

```
% ls -l cshrc.copy login.copy
-rw---- 1 taylor 1178 Nov 5 12:42 cshrc.copy
-rw---- 1 taylor 1858 Nov 5 12:42 login.copy
% ls -l cshrc.copy login.copy
cshrc.copy not found
-rw---- 1 taylor 1858 Nov 5 12:42 login.copy
```

![](img/f32f6f53c129de2ebafcd2b4ff01b1c9_129_0.png)

> The good news is that you can set UNIX so it won't overwrite files. The bad news is that for many reasons systems don't default to this behavior. If your system is configured reasonably, when you try either of the two preceding examples, the system's response is to remove login.copy? You can press the Y key to replace the old file or Enter to change your mind. If your system cannot be set to respond this use the -i flag to both cp and mv to avoid this problem. Later, learn how to permanently fix this problem with a shell alias.

JUST A MINUTE

Together, mv and cp are the dynamic duo of UNIX file organization. commands enable you to put the information where you want it, leaving duplicates if desired.

# Task 6.4: Renaming Files by mv

## SUMMARY

Both the DOS and Macintosh systems have easy ways to rename files. In DOS, you can use RENAME to accomplish the task. On the Mac, you can select the name icon and enter a new filename.

## DESCRIPTION

![](img/f32f6f53c129de2ebafcd2b4ff01b1c9_129_1.png)

UNIX has neither option. To rename files, you use the mv command, which, in essence, moves the old name to the new name. It's a bit confusing, but it works.

## ACTION

- 1. Rename the file cshrc.copy with your own first name. Here's an example:
% ls -l cshrc.copy
-rw---- 1 taylor 1178 Nov 5 13:00 cshrc.copy
% mv cshrc.copy dave
% ls -l dave
-rw---- 1 taylor 1178 Nov 5 13:00 dave

- 2. Rename a directory, too:
```
% ls -ld NEWDIR
drwxwx---- 2 taylor 512 Nov 5 12:32 NEWDIR/
% mv NEWDIR New.Sample.Directory
% ls -ld New.Sample.Directory
drwxwx---- 2 taylor 512 Nov 5 12:32 New.Sample.Directory/
```

- 3. Be careful! Just moving with cp and mv can overwrite existing files, renaming using mv can overwrite existing files:
```
% mv dave login.copy
```
If you try to rename a new directory with a name that has already assigned to a file, the command fails:
```
% mv New.Sample.Directory rename
mv: New.Sample.Directory: Not a directory
```
The reverse situation works fine because the file is moved into the directory. It's the subtlety using the mv command to rename files.

- 4. If you assign a directory to an existing directory, some versions of mv will happily overwrite the existing directory with the new one:
```
% mkdir testdir
% mv New.Sample.Directory testdir
```

> Being able to rename files is another important part of building a useful UNIX cabinet for yourself. There are some dangers involved, however so tread carefully and always use in conjunction with cp and mv to ensure that in the process you don't overwrite or replace an existing file.

# Task 6.5: Removing Directories with rdir

## DESCRIPTION Now that you can create directories using the mkdir command, it's time to learn how to remove directories using rdir.

- 1. With rdir, you can remove any directory for which you have appropriate permissions:
```
% mkdir test
% ls -l
total 0
% rdir test
```
Note that the output of ls shows there are no files in the test directory.

- 2. The rdir command removes only directories that are empty:
```
% rdir test
% touch test/sample.file
% ls -l test
total 0
-rw-r---- 1 taylor 0 Nov 5 14:00 sample.file
rmdir: test: Directory not empty
```
To remove a directory, you must first remove all files there using the rm command. In this example, test still has files in it.

- 3. Permissions are important, too. Consider what happens when you try to remove a directory you don't have permission to:
```
% rdir /tmp
rmdir: /tmp: Permission denied
% ls -l /tmp
drwxrwxrwt 8 root 15872 Nov 5 14:07 /tmp/
```
The permissions of the parent directory, rather than the directory you're trying to remove, are the important consideration. There's no way to restore a directory you've removed, so be careful and think through what you're doing. The good news is that, because with rdir you can't remove a directory having anything in it (a reason the attempt to remove /tmp would have failed), you're reasonably safe from major gaffes. You are not safe with the next command, rm, because it will remove anything.

# Task 6. Removing Files Using rm

The rm command is the most dangerous command in UNIX. Lacking any sort of archival or restoration feature, the rm command removes files permanently. It's like throwing a document into a shredder instead of into dustbin.

- 1. Removing a file using rm is easy. Here's an example:
% ls -l login.copy
-rw-r---- 1 taylor 1178 Nov 5 13:00 login.copy
% rm login.copy
% ls -l login.copy
login.copy not found

If you decide that you removed the wrong file and actually wanted to keep the login.copy file, it's too late. You're out of luck.

- 2. You can remove more than one file at a time by specifying each of the files to the rm command:
```
% ls -l
Archives/ PubAccessLists.Z new.login
Infor/ bin/ rumors.260ct.Z
LISTS cshrc.copy rumors.5Nov.Z
Mail/ educ src/
News/ login.copy test/
OWL/ mailing-lists.bitnet.Z testdir/
% rm cshrc.copy login.new login
% ls -l
Archives/ OWL/ rumors.260ct.Z
Infor/ PubAccessLists.Z rumors.5Nov.Z
LISTS bin/ src/
Mail/ educ test/
News/ mailing-lists.bitnet.Z
```

- 3. Unfortunately, rm has a command flag to some degree help avoid accidental file removal. When you use the -i flag or rm (the i stands for interactive in all cases), the system will ask you if you're sure to remove the file:

```
% touch testme
% rm -i testme
rm remove testme? n
% ls -l testme
testme
% rm -i testme
rm remove testme? y
% ls -l testme
testme not found
```
Note that n is no and y is yes. Delete the file.

- 4. Another flag that is often useful but is very dangerous, the -r flag for recursive deletion of files (a recursive command repeatedly itself). When the -r flag to rm is used, UNIX will remove any specific directory along with all its contents:
```
% ls -ld test ; ls -lr test
drw-xr-xr-x 3 taylor Nov 5 15:32 test/
total 1
-rw-rw---- 1 taylor 0 Nov 5 15:32 alpha
drw-xr-xr-x 2 taylor 512 Nov 5 15:32 test/
test/
total 0
-rw-rw---- 1 taylor 0 Nov 5 15:32 file1
% rm -r test
% ls -ld test
test not found
```
Without any warning or indication that it was going to do something so drastic, Enter rm -r test caused just the test directory, but all files and directories inside it as well, to be removed.
