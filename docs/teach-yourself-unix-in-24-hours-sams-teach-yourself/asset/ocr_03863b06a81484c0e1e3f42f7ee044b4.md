+   3. Are you ready for another directory of weird files? It's time to move into the /lib directory to see what devices are present on your system and what type of files they are.

Entering Is will demonstrate quickly that there is a lot of files in this directory! The file command can tell you any of them. On my Sun computer, I asked for information on a few select files, of which you might also have on yours:

```
% file lib.b diffh sendmail
lib.b: c program text
lib300.a: archive random library
diffh: sparc pure dynamically linked executable not stripped
sendmail: sparc demanded dynamically linked set-uid executable
```

The first file, lib.b, demonstrates that file command regards the name of a file: Standard naming for C program files specifies that they end with the characters .c, as in test.c. So, while you might never have suspected that lib.b is a C program. The second file is an actual library and is identified here as an archive random library, meaning it's an archive and the information within can be accessed in random order (by appropriate programs).

The third file is an executable, demonstrating another way that file can indicate programs on a Sun workstation. The sendmail program is an interesting program: It is an executable, but it has new information that you haven't seen before. The set-uid indicates that the program is set up so when anyone runs it, sendmail runs as the user who owns the file, not the user who launched it. A quick can reveal more about this:

```
* ls -l /lib/sendmail
155648 Sep 14 09:11 /lib/sendmail*
-rwxr-xr-x 2 1 root
```

Notice that the fourth character of the permissions string is s rather than the expected x for an executable. Also check the owner of the file in this listing. Combined, the two mean when anyone runs this program, sendmail will set itself to a different user ID (root in this case) and have set of access permissions. sendmail run with permissions is how you can send electronic mail to someone without fuss, but you can view it or her mailbox.
