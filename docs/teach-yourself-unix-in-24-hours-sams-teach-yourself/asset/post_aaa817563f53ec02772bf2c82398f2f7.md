
# How Mac and PC File Systems Differ from the UNIX File System

Although the specific information is certainly different, some parallels exist between the hierarchical file system structures of the UNIX and the Macintosh systems.

For example, on the Macintosh, folders are distinguished by their icons. The common folders you'll find on all Macs include System Folder and Trash. Within the system folder, all Macs have a variety of system-related files, including Finder, System, and Clipboard. Folders include Extensions, Preferences, and Control Panels.

By comparison, DOS requires files be present for the system to be usable: `command.com` must be present, `autoexec.bat` and `config` are usually present. Most DOS systems have all the commands neatly tucked in the :DOS directory on the system, but sometimes these commands appear at the very top level.

# Directory Separator Characters

If you look at the organizational chart presented earlier in this hour, you can see that employees are identified simply as “employee” where each has a unique path upwards to the president, each has a unique identifier if all components of the path upward are specified.

For example, the rightmost of the four employees could be described as “Employee managed by Jr. Manager 4, managed by Senior Manager 3, managed by Vice-President 2, by the President.” Using a single character, instead of “managed by,” can considerably shorten the description: Employee/Jr. Manager 4/Senior Manager 3/Vice-President 2/President. Now consider the same path specified from the very top of the organization downward: President/Vice-President 2/Senior Manager 3/Jr. Manager 4/Employee.

Because only one person is at the top, that person can be safely dropped from the path without losing the uniqueness of the descriptor: Vice-President 2/Senior Manager 3/Jr. Manager 4/Employee.

In this example, the / (pronounce “slash”) serves as a directory separator character, a convenient shorthand to indicate different directories in a path.

The idea of using a single character is not unique to UNIX, but the slash is unusual. On the Macintosh, the system uses a colon to separate directories in a path.(Next time you're on a Mac, try saving a file called `test:file` and see what happens.) DOS uses a colon: :tmp indicates the tmp directory at the top level of DOS. The characters /tmp indicate the tmp directory at the top level of the UNIX file system, and :Apps is a folder Apps at the top of the Macintosh file system.

# The Difference Between Relative and Absolute Filenames

Specifying the location of a file in a hierarchy to ensure that the filename is unique known in UNIX parlance as specifying its absolute filename. That is, regardless of where you are within the file system, the absolute filename always specifies a particular file. By contrast, relative filenames are not unique descriptors.

To understand, consider the files shown in Figure 3.3.

Figure 3.3. A simple hierarchy of files.

![](img/f32f6f53c129de2ebafcd2b4ff01b1c9_63_0.png)

If you are currently looking at the information in the Indiana directory, Birds uniquely describes one file: the Birds file in the Indiana directory. That name, however, refers to a different file if you are in the California or Washington directories. Similarly, the directory Personnel leaves you with three possibilities until you specify which state you're interested in.

As a possible scenario, imagine you're reading through the Birds file for Washington and some people come into your office, interrupting your work. After a few minutes of talk, they comment about an entry in the Birds file in California. You turn to your UNIX system and bring up the Birds file, and it's the wrong file. You're still in the Washington directory.

These problems arise because of the lack of specificity of relative filenames. Relative filenames describe files that are referenced to an assumed position in the file system. In Figure 3.3, even Personnel/Taylor,D. isn't unique that can be found in both Indiana and Washington.

To avoid these problems, you can apply the technique you learned earlier, specifying all elements of the directory path from the top down. To look at the Blogs file for California, you could simply specify /California/Blogs. To check the Taylor, D. employee in Indiana, you'd use /Indiana/Personnel/Taylor,D., which is different, from the employee /Washington/Personnel/Taylor,D.

Learning the difference between these two notations is crucial to surviving the complexity of a hierarchical system used with UNIX. Without it, you'll spend half your time verifying that you are where you are, or worse, not moving about at, not taking advantage of the organizational capabilities.

If you're in doubt as to where you are what file you're working in UNIX, simply specify its absolute filename. You can always differentiate between the two by looking at the first character: If it's a slash, you've got an absolute filename the filename is rooted to the very top level of the file system. If you don't have a slash as the first character, the filename's a relative filename.
