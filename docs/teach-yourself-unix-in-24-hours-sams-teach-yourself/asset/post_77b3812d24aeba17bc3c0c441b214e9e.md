
## Ownership and Permissions 97

The command chmod is like a smorgasbord where you can choose any combination of items from either the first or last boxes, and stick your choice from the center box between them.

For example, if you wanted to add permission to the file test for everyone in your group, you would, working backwards from that description, choose g for group, + for add, and w for write. The finished UNIX command would be chmod g+w test.

If you decided to take away and execute permission for everyone not in your group, you could use chmod -rx test to accomplish the task.

![](img/f32f6f53c129de2ebafcd2b4ff01b1c9_108_0.png)

- 1. Turn to your computer and, using touch and ls, changing permissions and what happens.
% test
% ls -l test
-rw------- 1 taylor 0 Oct 11 18:29 test

- 2. The first modification I want to make is that people in my group should be able to read the file. Because I don't really want altering it, I will rescind-write permission for group members
% chmod g-w test
% ls -l test
-rw------- 1 taylor 0 Oct 11 18:29 test

- 3. But then boss reminds me that everyone in the group should have all access permissions for everyone in that group. Okay, I'll do so.
% chmod g-rw test
% ls -l test
-rw------- 1 taylor 0 Oct 11 18:29 test

I also could have done that with chmod g=, of course.

- 4. Wait a second. This file is just for my use, and nobody in my group should be looking at it. I'll change it back.
% chmod g-rw test
% ls -l test
-rw------- 1 taylor 0 Oct 11 18:29

Great, now the file is set so that I can read and write it, but nobody else touch it, modify it, or anything else.

- 5. If I wanted a bit, I could easily add, with one last command, read-only permission for everyone:
% chmod a+r test
% ls -l test
-rw-r-- 1 taylor 0 Oct 11 18:29

DESCRIPTION The second input accepts absolute numeric values. Before you can learn how to use this notation, you have to learn a bit about different numbering systems first. The numbering system you are familiar with, the one you use to balance and check the receipt from the market, is decimal, or base 10. This means that each digit—from right to left—has the value of the digit raised to a power of 10, based on the digit's location in the number. Figure 5.4 shows what the number 5783 is in decimal. You can see that in a base-10 numbering system, the value of a number is the sum of each digit multiplied by the numeric base raised to the nth power. The n is the number of spaces the digit is away from the rightmost digit. That is, in the number 5783, you know that the 7 is worth more than just 7, because it's three spaces away from the rightmost digit.

What does all this have to do with the chmod command? At its most fundamental, UNIX permissions are a series of on/off switches. Does the group write permission? One equals yes, zero no. Each digit in a decimal system can have 10 different values. A binary system is one in which each digit can have only two values: on or off, yes no. Therefore, you can easily and uniquely describe any permissions as a string of zeroes and ones—as a binary number. Figure 5.5 demonstrates.

### Figure 5.5.
Permissions as binary numbers.

| rwx-xr-- |
| :--- |
| r w x - r - - |
| 1 1 1 0 1 0 0 0 |
| 11101000 |

The convention is that if a letter is present, the binary digit is a 1—that permission is permitted—and if no letter is present, the digit is a zero. Thus, r--xr------ can be described as 10110000, and r--r--r-- can be described in binary as 10010010.

You've learned that the nine-character permissions string is really just a three-character permissions string tripled thrice for the three different types of user (the owner, group, and everyone else). That means that you can focus on learning how to translate a single tri-character permissions substring into binary and extrapolate for more than one permission.
