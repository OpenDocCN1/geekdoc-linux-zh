# Task 3.3: The Special Directories "." and ".."

- There are dot directories I haven't mentioned, although they show up in listing and most certainly show in your listing, too. They are dot and dot dot (..), and their shorthand directory names can be terribly convenient.

The dot-dot is shorthand for the current location in the directory hierarchy; the dot-dot moves you up one level, to the parent directory.

Consider again the list of files shown in Figure 3.3. If you were looking at the files in the California Personnel directory and wanted to check an entry in California quickly, either you'd have to use the absolute filename /home/taylor/California/Personnel, or with shorthand directories, you could enter it as ../

As directories move deeper into the directory hierarchy, the dot-dot notation can save you much typing. For example, if different states and related files were located in a new directory called business, in that case, the absolute filename for taylor in California would be /home/taylor/business/California/Personnel/taylor, which is an awful lot to type if you want to hop up one level! You can use more than one dot-dot notation, so if you're looking at taylor.file and want to check on ../.., you could save typing in the full filename by using ../.. Look at Figure 3.3 to see how that would work, tracing back one level for each dot. This explains why the dot-dot shorthand is helpful, but what about the single-dot notation that simply specifies the current directory?![](img/f32f6f53c129de2ebafcd2b4ff01b1c9_67_0.png)

I haven't stated it explicitly yet, but you've probably figured out the UNIX file system organization, combined with its capability to place applications anywhere in the file system, that the system needs some way to know to look for particular applications. Just as you were looking for something in a public library, in UNIX, having an understanding of its organization and a strategy for searching is imperative for success and speed. UNIX uses an ordered list of directories called a search path for this purpose. The search path typically lists five or six different directories on the system where the computer checks for any request.

The question arises: What happens if your own copy of an application has the same name as a system application? The answer is that the system always finds the standard application first if its directory is listed earlier in the search. To avoid this pitfall, you need to use dot notation, forcing the system to look in the current directory rather than search. If you want your own version of the ls command, for example, you'd need to enter ./ls to ensure that UNIX uses your version rather than the standard![](img/f32f6f53c129de2ebafcd2b4ff01b1c9_68_0.png)

- Enter ../ls on your computer and watch what happens.
- Enter ls without the dot notation, and notice how the computer searches through various directories in the search path, finds the ls program, and executes it automatically.

When you learn about cd later in the book, you will also learn other uses of the dot-directory, but the greatest value of the dot directory is that you can use it to force the system to look in the current directory and nowhere else for any file.

# Task 3.4: The env Command

You've learned a lot of the foundations of the UNIX file system and how applications remember your preferences through dot files. There's another way, however, that the system remembers specifics about you, and through your user environment, the user environment is a collection of specially named variables that have specific values.![](img/f32f6f53c129de2ebafcd2b4ff01b1c9_68_1.png)

# Moving About in the File System

1. To view your environment, you can use the env command. Here’s what I see when I enter the env command on my system:

```
% env
HOME=/users/taylor
SHELL=/bin/csh
TERM=vt100
PATH=/users/taylor/bin:/bin:/usr/bin:/usr/ucb:/usr/local/bin:/usr/unsup/bin:
MAIL=/spool/mail/taylor

```

Try it and compare your values with mine. You might find that you have more defined in your environment than I do because your UNIX system uses your environment to keep track of more information.![](img/f32f6f53c129de2ebafcd2b4ff01b1c9_69_1.png)![](img/f32f6f53c129de2ebafcd2b4ff01b1c9_69_2.png)

Many UNIX systems offer the printenv command instead of env. If you enter env and the system complains that it can’t find the env command, try using printenv instead. All examples here work with either env or printenv.![](img/f32f6f53c129de2ebafcd2b4ff01b1c9_69_3.png)

# Task 3.5: PATH and HOME

The two important values in your environment are the name of your home directory (HOME) and your search path (PATH). (as it’s known) HOME is the name of the directory that you always begin UNIX session within.

The PATH environment variable lists the set of directories, in left-to-right order, that the system searches to find commands and applications you request. You can see from the example that my search path tells the computer to start looking in /users/taylor/bin directory, then sequentially /bin:/usr/bin:/usr/ucb:/usr/local/bin:/usr/unsup/bin, and . before concluding that it can’t find the requested command.
