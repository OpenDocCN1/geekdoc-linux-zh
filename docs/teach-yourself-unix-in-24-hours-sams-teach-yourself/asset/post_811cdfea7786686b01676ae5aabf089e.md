# Key Terms

**command alias** A shorthand command mapping, with which you can define new command names that are aliases of other commands or sequences of commands. This is helpful for renaming commands so that you can remember them, or for having certain flags added by default.

**command history** a mechanism the shell uses to remember what commands you have entered already, and to allow you to repeat them without having to type the entire command again.

**job control** a mechanism for managing the various programs that are running. Job control enables you to push programs into the background and pull them back into the foreground as desired.

**login shell** The shell you use, by default, when you log in to the system.

**subshell** a shell other than the login shell.

# Task 15.1: The C Shell and Korn Shell History Mechanisms

If you went through school in the United States, you would doubtless have the aphorism "Those who do not study history are doomed to repeat it." UNIX stands this concept on its head. For UNIX, the aphorism is best stated, "Those who are aware of their history can easily repeat it."

Both the C shell and the Korn shell build a table of commands as you enter and assign them a command number. Each time you log in, the first command you enter is command 1, and the command number is incremented for each subsequent command you enter. You can review or repeat any previous command easily with a few keystrokes.

To review your history in the C shell, enter each prompt. Odds are nothing that will happen, because by default each remembers only the last command. To begin building a list of commands, you must turn on this feature through an environment setting history=n, where n is the number of commands you'd like to recall.

By contrast, sh has a default list size of 128 commands, plenty for anyone. To review your history in ksh, you can also use the history command. Actually, though, it's the more cryptic fc -. In Korn shell, you don't need to make any changes; the history mechanism is ready to use immediately.

# JUST A Minute

Notice at the end of the w command output, the system noted Broken pipe. This is nothing to be anxious about; it's an indication that there were more left in the pipeline when the program quit. You can see that head read only the first 10 lines. The first line of w shows that there are 103 users on the system, which means that head ignored 94 lines of output. Unlike real plumbing, this broken pipe doesn't allow the data to spill onto the basement floor!

- 4. Now, when I enter history, the shell remembers the previous commands, presenting them all in a neat, numbered list:

5. To turn this permanently, add the set history command to your .cshrc. If you want the shell to remember commands if you log out and log back in, also specify the setting savehistory. I choose to do this by entering vi +s .cshrc and adding the following line:

```
set noclobber system=limbo filec
umask 007

setprompt
endif

set history=100 savehistory=50
~
```

If you go back at the output of the set command, you can see that I already have both of these parameters set: 100 commands will remain in the history list while I'm working, and 50 commands will be retained for the next time I log in. What's particularly helpful is that any time I specify a number n for either history list, the shell actually saves the most recent n commands, so that I have the most recent 100 commands for review while I'm using the system, and the 50 most recent commands remembered when I log in later.
