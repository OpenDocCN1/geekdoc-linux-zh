
# Hour 6

## Creating, Moving, Renaming, and Deleting Files and Directories

In this hour, you learn the basic UNIX file-manipulation commands. These commands will explain how to create directories with mkdir, remove directories with rdir, use cp and mv to move files about in the file system, and use rm to remove files. The rm command has its dangers: you learn that there isn't an "remove" command in UNIX and how to circumvent the possible dangers that lurk in the program.

## Goals for This Hour

In this hour, you learn how to

- Create new directories using mkdir
- Copy files to new locations using cp
- Move files to new locations using `mv`
- Rename files using `mv`
- Remove directories using `rmdir`
- Remove files using `rm`
- Minimize the danger of using the `rm` command

![](img/f32f6f53c129de2ebafcd2b4ff01b1c9_123_0.png)

This hour introduces several tremendously powerful commands that enable you to create a custom file-system hierarchy (or wreak havoc on your files). As you learn these commands, you also learn hints and ideas on how to best use the UNIX system to keep your files neat and organized. These simple UNIX commands, all new in this hour, are found not only in all variants of UNIX, both BSD- and System V-based, but they can also be brought onto DOS through utilities such as the MKS Toolkit from Mortice-Kern Systems.

## Task 6.1: Creating New Directories Using `mkdir`

One aspect of UNIX that has been emphasized continuously in this book is that the UNIX file system is hierarchical. The UNIX file system includes directories containing files and directories, each of which can contain both files and directories. Your own home directory, however, probably doesn't contain any directories (except `.` and `..`, of course), prevents you from exploiting what I call the virtual file cabinet of the file system.

The command for creating directories is actually one of the least complex and most mnemonic (for UNIX, anyway) in this book: `mkdir`, called "make dir."

![](img/f32f6f53c129de2ebafcd2b4ff01b1c9_124_0.png)

> Pronounce the `mkdir` command as "make dir."

1. Turn to your computer, move to your home directory, and examine the files and directories. Here's an example:

```
% cd
% ls
Archives/
InfoId/
LISTS/
Mail/
News/
OWL/
bin/
educ/
mailing.lists.bitnet.Z
rumors.26ct.Z
rumors.5Nov.Z
src/
```

![](img/f32f6f53c129de2ebafcd2b4ff01b1c9_124_1.png)

2. To create a directory, you need to specify what you'd like to name the directory and where you'd like to locate it in the file system (the default location is your current working directory):

```
% mkdir NEWDIR
% ls
Archives/
InfoWorld/
LISTS/
Mail/
NEWDIR/
% News/
mailing.lists.bitnet.Z
% OWL/rumors.26Oct.Z
PubAccessLists.Z
rumors.5Nov.Z
bin/
src/
```

3. That's all there to it. You've created your first UNIX directory, and you can now list it to see what it looks like:

```
% ls -ld NEWDIR
drwx------x 2 author 24 Nov 5 10:48 NEWDIR/
% ls -la NEWDIR
total 2
drwx------x 2 author 24 Nov 5 10:48 ./
drwx------ 1024 Nov 5 10:48 ../
```

Not surprisingly, the directory is empty other than the two defaults of "." (the directory itself) and ".." (the parent directory, your home directory).

4. Look closely at the permissions of the directory. Remember that the permissions are a result of your umask setting. As you learned in the previous chapter, changing the umask setting changes the default permissions. Then, when you create a new directory, the new permissions will be in:

```
% umask 077
% umask 0
% mkdir NEWDIR
% ls -ld NEWDIR
drwx------x 2 author 24 Nov 5 10:53 NEWDIR2/
% umask 222
% mkdir NEWDIR
% ls -ld NEWDIR
dr-xr-xr-x 2 author 24 Nov 5 10:54 NEWDIR3/
```

5. What happens if you try to create a directory with a name that has already been used?

```
% mkdir NEWDIR
mkdir NEWDIR: File exists
```

6. To create a directory other than your current location, prefix the new directory name with a location:

```
% mkdir /tmp/test
% ls -l /tmp
-rwx------ 1 zhongqi 22724 4 Nov 5 21:33 /tmp/a.out*
-rw------ 1 julia 95594 4 Nov 5 23:10 /tmp/active.10122
-dr-xr-r-- 1 beast 572 Nov 5 05:59 /tmp/anon
```

## Task 6.2: Copying Files to New Locations using cp

DESCRIPTION: One of the most basic operations in any system is moving files, the modern equipment of paper shuffling. On a computer, moving files is a simple matter of one or two commands: you can move a file to a different location, or you can create a copy of the file and move it to a different location.

The Macintosh has an interesting strategy for differentiating between moving and copying. If you drag a file to another location that's on the same device (a hard disk, example), then the default moves the file to that location. If you drag a file to a location on a different device (from floppy to a hard disk, instance), the computer automatically copies the file, placing the new copy on the device.

UNIX lacks this subtlety. Instead, UNIX lets you choose which of the two operations you'd like to perform. The two commands are succinctly mnemonic: mv to move files, and cp to copy files. The mv command also serves the dual duty of renaming files.

> Pronounce cp as "sea pea." When you talk about copying a file, however, say "copy." Similarly, pronounce mv as "em ve," but when speaking of moving a file, say "move."

JUST A MINUTE: I find myself using cp than mv because it offers a slightly safer way to organize files: if I get confused and rename it so that it steps on another file (you'll see what I mean in a moment), I still have original copies of all the files.

### ACTION

1. The format of a cp command is to specify first the name of the file you want to copy and then the new filename. Both names must be either relative filenames (that is, without a leading slash or other indication of the directory) or absolute filenames. Start up by making a copy of your .login file, naming the new login.copy

```bash
% cp .login login.copy
% ls -id .login login.copy
-rw---- 1 taylor 1858 Oct 12 21:20 .login
-rw---- 1 taylor 1858 Nov 5 12:08 login.copy
```

You can see that the new file is identical in size and permissions but that it has a more recent date, which certainly makes sense.

2. What happens if you try to copy a directory?
```bash
% cp .newdir
cp: .newdir: Is a directory (not copied)
```
Generally, Unix won't permit you to use the cp command to copy directories.

> I found that this command worked—sort of—on one machine I have used. The system's response to the cp command indicated that something peculiar was happening with the following message:
cp .newdir: Is a directory (copying as plain file)
But, the system also created newdir as a regular, executable file. You may find that your system reacts in this manner, but you probably do not have any use for it.

![](img/f32f6f53c129de2ebafcd2b4ff01b1c9_127_0.png)

JUST A MINUTE

3. The cp command is quite powerful, and it can copy many files at once if you specify a directory as the destination rather than specifying a new filename. Further, if you specify a directory destination, the program automatically will create new files and assign them the same name as the original files. First, you need to create a second file to work with:
```bash
% cp .cshrc cshrc.copy
```
Now try it yourself. Here is what I did:
```bash
% cp login.copy cshrc.copy NEWDIR
% ls -l NEWDIR
total
-rw---- 1 taylor 1178 Nov 5 12:18 cshrc.copy
-rw---- 1 taylor 1858 Nov 5 12:18 login.copy
```
