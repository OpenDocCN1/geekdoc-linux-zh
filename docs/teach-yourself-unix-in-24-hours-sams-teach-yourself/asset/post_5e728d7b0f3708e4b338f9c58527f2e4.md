
# Getting the Most Out of the C Shell

Like much of UNIX, turning on the history mechanism of the C shell is quite easy once you learn the trick. In this case, simply remember that you need to specify a history value to have the shell begin remembering what's going on your interaction. In Korn, you don't need to make any changes; it's ready to use immediately.

## Task 15.2: Using History to Cut Down on Typing

There are three mechanisms for working with the history list. You can specify a previous command by its command number, by the first word of the command, or by using the most recently executed command, by a special notation that easily fixes any mistakes you might have made as you typed it.

Every history command begins with an exclamation point. If the 33rd command you can execute you can execute it by referring to its command number: enter 33 at the command line. You can execute it also by entering one or more characters of the command: iw, tw, or who; You must enter enough characters to uniquely identify it in the history list.

To edit a previous command, type a caret, then the correct pattern. If you just entered awk -F, 'print $2' and realize that you meant to put a colon, not a comma, the field delimiter, ^: will do the trick.

A very useful shorthand is !, which repeats the most recently executed command. Two other history references are valuable to know: $: expands to the last word of the previous line (which makes sense because $ always refers to the end of something, whether it be a line, the file, or in this case, a command), and #: expands to all words in the previous command except the very first. So, if I entered the command ls /usr /etc/dev and then immediately expanded the command echo !*,

Korn shell offers all of this and more. You can repeat commands by specifying rn, where n is the command number (for example, r33). You can also repeat by name with rn, as in who to repeat the most recent command. Much more useful is the capability to directly edit a command with the familiar vi or EMACS command keys, without leaving the command line. Without any arguments, r will repeat the previous command.

```
* * % history

* 56 cat buckaroo
* 57 history
* 58 date
* 59 w | head
* 60 history
```

Commands expanded by history mechanism are stored as the expanded command, not as the history command that actually entered. Thus, this is an exception to the earlier rule that the history mechanism always shows what was previously entered. It is an eminently helpful exception!

History commands are quite helpful for people working on a software program. The most common use for programmers is to edit-compile-run, over and over the commands. UNIX users most often probably fail if they try vi test.c, cc -o test.c, and test, to edit, compile, and run the program. Using the C shell history mechanism, a programmer can easily use tv to edit the file, te to compile it, and tt to test it. As your commands become longer and more complex, this function proves more and more helpful.
