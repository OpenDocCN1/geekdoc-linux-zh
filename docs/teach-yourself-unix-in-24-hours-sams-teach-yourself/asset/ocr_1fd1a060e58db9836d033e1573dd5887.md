# Task 9.3: Creating Sophisticated Regular Expressions

A regular expression can be as simple as a word to be matched for letter, such as acme, or as complex as the example in the printers script, "*[a-zA-Z]*wi*", which matches all lines that begin with an upper- or lowercase letter or contains zwi.

The language of regular expressions is full of punctuation characters and other letters used in unusual ways. It is important to remember that regular expressions are different from shell wildcards. It's unfortunate, but it's true. In C shell, for example, a* lists any file that starts with the letter a. Regular expressions aren't left, which means you need to specify ^a if you want to match only lines that begin with the letter a. The pattern a* only filenames that start with the letter a, has a different interpretation completely when used as part of a regular expression: a* is a pattern that matches zero or more occurrences of the letter a. The notation for regular expressions is shown in Table 9.1. The grep command has additional notation that you learn shortly.

| Notation | Meaning |
| c | Matches the character c |
| \c | Forces c to be read as the letter c, not as another meaning the character might have |
| ^ | Beginning of the line |
| $ | End of the line |
| [xy] | Any single character in the set specified |
| [^xy] | Any single character not in the set specified |
| c* | Zero or more occurrences of character c |

The notation isn't as complex as it looks in this table. The most important things to remember about regular expressions are that the * denotes zero or more occurrences of the previous character, and . is any single character. Remember that shell patterns use * to match any set of zero or more characters independent of the previous character, and ? to match a single character.
