On the Macintosh, you rarely encounter the directory delineator because the system has a completely graphical interface. Windows also offers a similar level of freedom from having to worry about much of this complexity, although you'll still need to remember "A:" is your floppy disk or hard disk drive.

# The Difference Between Relative and Absolute Filenames

Specifying the location of a file in a hierarchy to ensure that the filename is unique known in UNIX parlance as specifying its absolute filename. That is, regardless of where you are within the file system, the absolute filename always specifies a particular file. By contrast, relative filenames are not unique descriptors.

If you are currently looking at the information in the Indiana directory, Birds uniquely describes one file: the Birds file in the Indiana directory. That name, however, refers to a different file if you are in the California or Washington directories. Similarly, the directory Personnel leaves you with three possibilities until you specify which state you're interested in.

As a possible scenario, imagine you're reading through the Birds file for Washington and some people come into your office, interrupting your work. After a few minutes of talk, they comment about an entry in the Birds file in California. You turn to your UNIX system and bring up the Birds file, and it's the wrong file. You're still in the Washington directory.

These problems arise because of the lack of specificity of relative filenames. Relative filenames describe files that are referenced to an assumed position in the file system. In Figure 3.3, even Personnel/Taylor,D. isn't unique that can be found in both Indiana and Washington.
