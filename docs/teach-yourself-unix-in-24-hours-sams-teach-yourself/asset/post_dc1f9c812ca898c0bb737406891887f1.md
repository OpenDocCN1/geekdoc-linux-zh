Separating commands with a semicolon is the UNIX way of having multiple commands on a single line, so when I enter the alias netcom, for example, it's as if I'd entered all these commands one after another:

- 4. Two aliases worth examining closely are those for the cd and setprompt commands. As you learn in a few moments, you can set your prompt to be just about any characters you'd like. (Hang on for just a paragraph or two, and you will learn all of what's occurring in the next example!) I like to have my prompt indicate where the file system I'm currently working. To ensure the prompt is always up to date, I simply alias the command so that each time I change directories, the prompt is recalculated.

```bash
% alias cd
chdir ! : setprompt
% alias setprompt
set prompt="$System($cdw):! : "
```

> The cd command does the same thing as cd and is intended for use within aliases as shown. If you find chdir easier to remember than cd, you can use it.

# JUST A MINUTE

Aliases are what makes the C shell and Korn shell such great interfaces. I can, and do, easily customize the set of commands and the default flags (look at all the options I set as default values for the rm command). I turn off some commands that I don't want to run accidentally. Let your imagination run with aliases. If you decide you like one and if you're using csh, add the alias to your cshrc so it's permanent (.profile if you're using ksh). If you want to turn off an alias, you can use the unalias command, and it's gone until you log in again. For example, unalias netcom would temporarily remove from the shell the netcom alias shown earlier.

# Task 15.5: Setting Custom Prompts

Up to this point, the command prompt I've seen is a boring %. It turns out that the C shell lets you set your prompt to just about any possible value, with prompt="value".

The Korn shell is even easier: PS1="value". Note that PS1 must be all uppercase for this work.

- 1. I'm getting tired of UNIX being inhospitable. Fortunately, I easily can change how it responds to me:
```bash
% set prompt="Yes, master? "
Yes, master?
That's more fun!
```
The ksh equivalent is PS1="Yes, master?"

- 2. There are a lot of things you can tuck away in your prompt that can be of great help. The first useful variable is cwd, which holds the current working directory:
```bash
Yes, master? set prompt="In $Cwd, oh master:"
In /users/taylor, oh master:
What happens if I change directories?
In /users/taylor, oh master: cd /
In /users/taylor, oh master: pwd /
In /users/taylor, oh master:
```
This is not so good. Now you can see why it's necessary to alias cd to maintain the prompt.

- 3. Some special values can be added to the prompt definition, as shown in Table 15.2.

| Value | Expands to |
|---|---|
| $cmd | The results of executing cmd. |
| \! | The current command number. |
| $var | The value of var. |
| $var:t | The tail (last word) of the value of var. |

The number in parentheses is the command number, as used by the C shell history mechanism:

Every time I log in, I automatically set the variable to the name of the computer:
```bash
set prompt="$system(cwd)"
```

I like to include in my prompt the basename of the current directory, as shown in the following example. Basename means the closest directory name, so basename of /user/taylor is taylor. Also, I replace % with a colon which is a bit easier to read. There is a slight problem, however; having instead of % means I have to remember it in C shell (or Korn shell, as the case may be).

- 4. Now I glance back at aliases for prompt and cd, with all these things in mind:
```bash
alias cd=chdir!
alias setprompt="set prompt=$system(cwd)"
```
You can see the setprompt alias defines the C shell prompt as expected, although the actual line in .bashrc includes the backslash:
```bash
alias setprompt="set prompt=\$system(cwd)"
```

![](img/f32f6f53c129de2ebafcd2b4ff01b1c9_348_0.png)

Each time I change directories, I use the combined commands of alias chdir* to change the current directory, and then I use setprompt to compute the new prompt. The * notation in a shell alias expands to all the words you specify after the command line. For example, if you have an alias for dir="echo*", entering dir /home actually executes echo /home by ls /home.

# 15.6: Creating Shell Scripts

Command capability is a helpful way to cut down on entering short commands again, but what if you have a series of 5 or 10 commands to enter? That's where shell scripts can help. At their simplest, shell scripts are a series of shell commands that appear in a file in exactly the order which they'll be executed. If you change the permissions of the file to execute, you can run it as it were just another command.

Shell scripts can be short. The script /bin/true is only one line: exit 0. The script /bin/false contains the opposite command, and it contains only one line: exit 1. The helpful script print is also one line: ip -p $. Most of the others, however, are too complex to explain here.

```bash
#!/bin/sh
# Punt: punt a new article from "mail" to yourself.
trap '/bin/rm -f /tmp/point.$' 0 1 9 15

SENDTO=taylor@netcom.com

cat - > /tmp/point.$$

if [ "$1" != "" ]; then
    ADDRESS=$1
else
    ADDRESS=$SENDTO
fi

/usr/lib/sendmail $ADDRESS < /tmp/point.$$

echo Punted a 'wc -l < /tmp/point.$' line article to $ADDRESS

exit 0
```
