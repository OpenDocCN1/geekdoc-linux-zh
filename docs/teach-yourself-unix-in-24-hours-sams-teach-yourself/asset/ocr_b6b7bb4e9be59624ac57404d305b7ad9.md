2. Read permission on a directory enables you to read the "table of contents" of the directory but, by itself, does not allow you to examine any of the files therein. itself, read permission is rather bizarre:

```
% ls -ld testme
------ taylor 512 Oct 11 17:03 testme/
% ls -l testme
testme/file not found
total 0
% ls -l testme
testme/file not found
```

Notice that the system indicated the name of the file contained in the teste directory. When I tried to list the file explicitly, however, the system couldn't find the file.

3. Compare with the situation when you have execute permission—which enables you to examine the files within the directory—but you do not read permission, and you are prevented from viewing the table of contents of the directory:

```
% ls -ld testme
d------- taylor 512 Oct 11 17:03 testme/
% ls -l testme
testme unreachable
% ls -l testme/file
--rw-rw---- taylor 0 Oct 11 17:03 testme/file
```

With execute-only permission, you can set up directories so that people who know the names of files contained in the directories access those files, but people without knowledge cannot list the directory to learn the filenames.

4. I've never seen anyone have a directory in UNIX with execute-only permission, and certainly would never expect to set one to read-only. It would be nice if UNIX would warn you if you set a directory to have one permission and not the other. However, UNIX will not do that. So, remember for directories always be sure that you have both read and execute permission set. Table 5.3 summarizes the most common directory permissions.

# Table 5.3. The most common directory permissions.

| Permission | Meaning |
| --- | --- |
| --- | No access allowed to directory |
| r-x | Read-only access, no modification allowed |
| rwx | All access allowed |
