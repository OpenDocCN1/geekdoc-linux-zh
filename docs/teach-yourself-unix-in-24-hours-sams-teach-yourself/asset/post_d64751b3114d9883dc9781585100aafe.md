
# Task 3.6: Find Where You Are with pwd

1. You can use the echo command to list specific environment variables, too. Enter echo $PATH and echo $HOME. When I do so, I get the following results:

```bash
% echo $PATH
/users/taylor/bin:/bin:/usr/ucb:/usr/local/bin:/usr/unsup/bin::-
% echo $HOME
/users/taylor
%
```

Your PATH value is probably similar, although certainly not identical, to mine, and your HOME is /home/accountname (accountname is your account name).

So you've learned a lot about how the file system works but not how to move around the file system. With any trip, the first and most important step is to find out your current location—that is the directory where you are currently working. In UNIX, the command pwd tells you the present working directory.

1. pwd. The output should be identical to the output you saw when you entered env HOME because you're still in your home directory.

```bash
% env HOME
/users/taylor
% pwd
/users/taylor
%
```

Think of pwd as a compass, always capable of telling you where you are. It also tells you the names of all directories above you because it lists your current location as an absolute directory name.

# Task 3.7: Move to Another Location with cd

The other half of the dynamic duo is the cd command, which is used to change directories. The format of this command is simple, too: cd new-directory (where new-directory is the name of the new directory you want).

# Moving About in the File System

![](img/f32f6f53c129de2ebafcd2b4ff01b1c9_71_0.png)

1. Try moving to the very top level of the file system and entering pwd to see if the computer agrees that you've moved.

```bash
% cd /
% pwd
/
```

2. Notice that cd doesn't produce any output. Many UNIX commands operate silently like this, unless an error is encountered. The system then indicates the problem. You can see what an error looks like by trying to change your location by trying the /taylor directory to see what happens!

```bash
% cd /taylor
/taylor: No such file or directory
%
```

3. Enter cd without specifying a directory. What happens? I get the following result:

```bash
% cd
% pwd
/users/taylor
%
```

4. Here's where the HOME environment variable comes into play. Without any directory specified, cd moves you back to your home directory automatically. If you get lost, it's a shorthand way to move to a known location without fuss.
Remember the dot-dot notation for moving up a level in the directory hierarchy. Here is where it proves exceptionally useful. Use the cd command to move to your home directory, then use pwd to ensure that you've ended up.

5. Now, move up one level by using cd .. and check the results with pwd:

```bash
% cd
% pwd
/users/taylor
% cd ..
% pwd
/users
%
```

6. Use the ls -C -F command to list all the directories contained at this point in the file system. Beware, though; on large systems, this directory could easily have hundreds of different directories. On one system I, there are almost 550 different directories one level above my home directory in the file system!

| ls -C -F | | | | | |
| :--- | :--- | :--- | :--- | :--- | :--- |
| armstrong/ | christine/ | guest/ | laura/ | matthew/ | shake/ |
| bruce/ | david/ | higiggins/ | mac/ | rank/ | taylor/ |
| cedric/ | green/ | kane/ | mark/ | shalini/ | vicky/ |

Try using a combination of cd and pwd to move about your file system, and remember that without any arguments, cd zips right back to your home directory.

# Key Terms

**absolute filename** Any filename that begins with a leading slash (/); these uniquely describe a single file in the file system.

**binary** A file that contains machine-executable code.

**device** A hardware component that can be recognized and controlled by the operating system.

**directory** A container that can hold files and other directories, used to organize the file system.

**dot** The shorthand for the current directory.

**dot-dot** The shorthand for moving up one level in the directory hierarchy.

**dynamic linking** The process of resolving symbol references at runtime rather than compile time.

**executable** A file that can be run by the computer.

**hidden file** A file whose name starts with a dot, making it hidden from standard directory listings.

**preference file** A file that stores user settings for a program or the shell.

**kernel** The core part of the operating system that manages hardware and system resources.

**root directory** The directory at the very top of the file system.

**slash** The character '/' used to separate directories in a file path.

**search path** A list of directories that the shell searches to find commands.

**symbolic link** A file that points to another file or directory rather than having its own contents.

**user environment** A set of values that describe the user's current location and modify the behavior of the shell.

**working directory** The directory where the user is currently working.
