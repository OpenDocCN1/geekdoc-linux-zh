# Disk Recovery Tools

Every Linux distribution comes with a variety of disk recovery and maintenance tools. Many of these tools have roots in the Intel-based world, and you might think that few would apply, build, or even be useful in the PowerPC Linux environment. The good news is that many Macintosh computers today use IDE storage devices, such as hard drives or CD-ROMs. Because of this, many of the legacy Intel-based hardware tools work quite well!

# Using fsck

One of the first utilities you may run into when using PowerPC Linux (especially distributions with current 2.2-series Linux kernels) is the `fsck` command (more properly termed `e2fsck`). This command is used to check and repair ext2 filesystems on designated partitions.

Although designed for speed, `e2fsck` can still take quite a bit of time to check today's large hard drives, especially when you have partitions that are 5, 10, or 20GB (the limitation in 2.2-series Intel-based kernels is 27GB for an individual partition and 8 terabytes for the filesystem).

When `e2fsck` is run, it performs five passes over the specified filesystem, which is unmounted. The passes check file block locations, directories, links, the integrity of the filesystem (directory structure), and summary information about the partition. For example, to check a spare partition while running Linux, you can use `e2fsck` with its -t or force check option (as root), along with the partition's device name, like this:

```bash
# df -h
Filesystem    1k-blocks     Used Available Use% Mounted on
/dev/hda11     6102696  5320740    471936  92% /
/dev/hda13     7133580   654416   6116776  10% /D2
usbdevfs      1783395  1783395          0 100% /proc/bus/usb

# umount /D2
# e2fsck -f /dev/hda13
e2fsck 1.18, 11-Nov-1999 for EXT2 FS 0.58b, 95/08/09
Pass 1: Checking inodes, block, and sizes
Pass 2: Checking directory structure
Pass 3: Checking directory connectivity
Pass 4: Checking reference counts
Pass 5: Checking group summary information
/dev/hda13: 36/906752 files (47.2% non-contiguous), 192164/1811955 blocks
```

Note that the desired partition was first unmounted prior to running `e2fsck`. During the boot process, Linux will check all known partitions. If a problem occurs, you may see this (on a LinuxPPC 2000 Q4 system):

```text
### An error occurred during the filesystem check.
### Dropping you to a shell; the system will reboot
### when you leave the shell.
(Repair filesystem) #
```

At this point, you will need to enter the root password. After you press Enter, run `e2fsck` on the appropriate partition using its device name. You can then step through the program (if needed) to fix any errors. When finished, type `exit` and Linux will reboot.

After you log back in, you can also use the `hdparm` command to change settings for your IDE hard drive. Note that this will only work for those Macintosh computers using an internal or external IDE drive. The `hdparm` command has many different command-line options, but commonly used ones include:

- -a Toggle Direct Memory Access use; enabling this can result in a speedup of disk operations
- -c Display the drive's IDE power mode status
- -g Print drive geometry, such as cylinders, heads, and sectors
- -l Display Linux information about the drive
- -I Show information from the drive
- -s Set spindown timeout for the drive
- -y Force drive to low-power consumption and standby

You really should not have to change your drive's settings, because Linux generally works fine with default IDE hard drive settings. Some distributions, such as LinuxPPC 2000 Q4, include logic in the `/etc/rc.d/rc.sysinit` startup script that looks for a file named `hardisaks` under the `/etc/sysconfig` directory. This Red Hat-based approach provides for some optimizations of the system's IDE drive, such as using 32-bit Input/Output or DMA.

You can get information about your computer's internal hard drive by using one or more information options to the `hdparm` command (as root), like this:

```bash
$ hdparm -i /dev/hda
```

The first command line displays information received from the drive at boot time, while the second shows information by directly querying the drive. Note that sometimes it appears that the information does not match! Unless you know what you are doing, it is probably best to leave your drive's settings alone. However, a particular setting many PowerBook owners can use is `hdparm -S 0` or standby setting to set the spindown delay time to save power. For example, to set the internal drive to spin down after five seconds, use:

```bash
# hdparm -S 1 /dev/hda
/dev/hda:
setting standby to 1 (5 seconds)
```

However, even this approach may not be needed with some PowerPC Linux distributions. For example, SuSE PPC Linux includes a number of settings you can use for APM (*Automatic Power Management*) in a file named apmd.rc.config, which is found under the /etc/rc.config. a directory. You can choose many different default actions, such as hard drive spindown time, and control of sound, PCMCIA, and other services according to battery levels.

# On the Horizon

By the time you read this, many Linux distributions may incorporate a new form of filesystem for use during Linux sessions. One of the most requested features from vendors and corporate Linux users is for a new type of filesystem for Linux that can be checked quickly and easily and is a lot faster than using *fsck*.

The fact is that the current *ext2* filesystem has proven to be stable, robust, and now in common use across many platforms. What users desire is a new form of filesystem that provides small-file efficiency, the ability to handle directories containing hundreds of thousands of files, and one that can recover quickly following catastrophic disk or system failure. The need for a new filesystem for Linux becomes apparent when it can take several hours just to format required system media (perhaps nearing one or more terabytes). Running *fsck* on such a system could take half a day just to reboot!

One of the proposed solutions is *ext3*, which is a proposed modification of *ext2*. It is intended to add journaling, or the ability to continually snapshot the filesystem and recover quickly. Another possible solution (available for 2.4-series Linux kernels) is SGI's *xfs* filesystem, which provides a high-performance journaling filesystem that purportedly provides, according to SGI, “Sub-second filesystem recovery after crashes or power failures,” and support for “millions of terabytes, millions of files, and a million files per directory.”

Another solution that has already appeared and is available for the 2.2.19 Linux kernel is *ReiserFS*, which provides journaling and no use for *fsck* upon rebooting after a power outage.
