## Managing Resources

When you use Linux on your Macintosh as a stand-alone workstation, you are the only system administrator, root operator, user, and you also have access to the entire system’s resources. No one will be looking over your shoulder to check on how much disk space, memory, or other system resources you are using.

However, when Linux is used on a Macintosh as a server or multi-use workstation to provide support for numerous users, the system administrator must occasionally step in or have pre-defined rules of use for the system. If CPU or RAM resources are valuable, limits may need to be placed on users who want to rip audio CDs or conduct program development work using multiple instances of the *gcc* compiler. If hard drive space is at a premium, downloading entire CD-ROMs of data can pose a problem. Such actions can quickly exhaust resources for other users, and is certainly not fair.

As root, you can impose limits on your users through the use of CPU priority programs such as *nice* and *ulimit* settings in *bash* (to control file size, number of processes, and pipe size), and disk quotas (to control storage use). Setting disk quotas can sometimes be necessary, especially if you have many users sharing limited drive space.

## Quotas

Enabling disk quotas is easy. As with other services, quota enforcement may be started, stopped, restarted, or queried through the use of system initialization scripts. Under SuSE PPC Linux, *yast* may be used to set quotas, with the settings saved in the /*etc/rc* .config directory. A script named *quota* is used under the /*sbin/init* .d directory to start the service at boot time.

Under Linux/PPC 2000 Q4, quota use is determined by the /*etc/rc.d/rc*.sysinit script. With both Linux distributions, quota use can be controlled for groups or users through the use of files named *quota.group* *or* *quota.user*. However, you will also need to include an *usrquota* *mount* *command option* in your system’s filesystem table. For example, the original entry may look like this:

/dev/hda12 / ext2 defaults 1 1

To enable quotas, change the entry to look like this:

/dev/hda12 / ext2 defaults,usrquota 1 1

Next, as root, use the quotacheck command to initialize quota use on your system like this:

```
# quotacheck -avug
Scanning /dev/hda12 [/] done
Checked 6100 directories and 104649 files
Using quotafile /quota.user
```

To assign a quota for a particular user, implement the edquota command, along with its -u option, followed by a username (or -g, followed by a group's name), like this:

```
# edquota -u bbai
```

After you press Enter, you will be presented with a screen in which to enter quota settings. Following this, you should also use the edquota command with its -t option to set soft limits (limits that, when reached, issue a warning to the user).

> You must use a Linux kernel that has quota use enabled. According to SuSE, this is the default with its stock PowerPC Linux kernels. LinuxPPC 2000 Q4 does not ship with a kernel that enables use of quotas, so you will have to rebuild the default kernel in order to use quotas.

## Using Xvnc

AT&T Laboratories in Cambridge, England distributes a free software package named `xvnc`. This virtual networking software enables you to run remote computers using operating systems different from your desktop. This means that if you have computers using Windows or Mac OS on your LAN, you can run each computer in a window on your Linux desktop. This also means that you can sit down at a computer running Windows or Mac OS and run your Linux computer in a window from a remote desktop.

`xvnc` is a specialized variant of the X server installed on your system. Versions of `xvnc` are available for a number of computers, such as:

- DEC Alpha OSF1 3.2
- Java
- Macintosh OS (68K and PPC)
- Palm OS
- PocketPC
- Solaris 2.5 (SPARC)
- Win32 (such as Windows 9x/2000/NT)

The `xvnc` package provides a shell script named `vncserver`, the `xvnc` modified X server, and a remote desktop viewer client named `vncviewer`. There are versions of `xvnc` for all Linux PPC distributions.

After installing the software (most likely using the `rpm` command or `yast`), you can start `xvnc` on your system by using the `vncserver` script. This script allows you to set the default screen size and color depth by using its `-geometry` and `-depth` settings. For example, to start a session that offers an 800x600 desktop in thousands of colors, use the `vncserver` script, like this:

```
$ vncserver -geometry 800x600 -depth 16
```

You will be prompted to enter a password:

```
Password:
Enter a password used to allow remote access and press Enter. You will again be
asked to verify the password, like this:

Verify:
New 'X' desktop is cube:1

Creating default startup script /home/bball/.vnc/xstartup
Starting applications specified in /home/bball/.vnc/xstartup
Log file is /home/bball/.vnc/cubie:1.log
```

Note that the server returns a DISPLAY number (1 in this example). Users who wish to connect remotely will need to know this display number, along with your password in order to connect to your virtual session.

Your session settings are contained in a directory named .vnc in your home directory. The file named xstartup provides instructions on what X window manager to use for a session. You can edit this file to start any window manager you choose, like this:

```
#!/bin/sh

xrdb $HOME/.Xresources
/opt/kde2/bin/startkde
```

In this example, the K Desktop Environment is specified. When you or a remote user connects, that is the window manager in use for the session. Note that using vnc can be a resource drain; it is as if you are running another X session in memory!

Figure 17.1 shows a remote PPC Linux session (running the twm window manager) viewed from the desktop of another (Intel-based) Linux X session.

The Mac OS xvnc package also supports remote viewing. Download the Mac OS version from the xvnc home page. You will need to decompress the software. Next, double-click the VNC Server Installer script in the VNC PPC folder. The software will be installed in your System Folder, along with a VNC Controls control panel.

To enable a remote viewing session, first use the Monitors control panel to select a resolution for the Desktop. Your remote session will automatically use the size and color depth of the current Monitor's setting. Next, double-click the VNCServer PPC application and choose the Options menu item from the File menu.
