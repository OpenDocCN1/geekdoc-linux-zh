## Internet Security Issues

In a perfect world we wouldn’t have to worry about Internet security. And in the early days of the Internet, openness, sharing and lack of security were the rule, not the exception. Today however, with the explosion of the number of users on the Internet (millions of computers and millions more users), there are bad people out there who would love nothing more than to break into your system with stealth or wreak havoc on your files.

If you have a LAN connected to the Internet, chances are more than good that you or your system administrator has a `firewall` in place. A firewall can be built using software or hardware. But the basic idea is to protect your system from intruders whose ultimate aim is to gain access as the root operator. Once an intruder gains access as root, all is lost, and you are at someone else’s mercy.

### Basic Firewalling

If you don’t want to offer a tempting target, turn off all unwanted network services. Review your system’s `/etc/inetd.conf` file to see what services are turned on. If you see a service, such as Internet Relay Chat, and you don’t use it, turn it off! Make sure that you have system logging enabled (through the use of the `syslogd` daemon), and take the time to examine your logs once in a while. Nearly all Linux distributions log system and kernel activity to a file named `messages` under the `/var/log` directory. You can read this file (as root) by using a pager command, such as `less` like this:

```bash
# less /var/log/messages
```

Another thing you can do is turn to various software packages that can help provide a measure of security by filtering access into and out of your system.

First, don’t use a root password that is easily cracked. This includes using any word from your system’s dictionary, `/usr/dict/words`. Change your root password often, and review your system’s users often. Some Linux distributions also provide for password aging, and you can use the `expiry` command to set up rules for password aging.

If you have an Internet connection, physically separate your LAN from the Internet and place a hardware router, DSL router, or share partner between your LAN and the Internet. This spare computer will then have two Ethernet interfaces through which traffic is routed. If you’re ultra security conscious, install the OpenSSH (*Open Secure Shell Server*) and related `ssh` utilities.

Next, use `ipchains` (for 2.2.X kernels) to set up a ruleset for packet filtering. For advice on how to best set up a system, see Rusty Russel’s Linux IPCHAINS-HOWTO. Most Linux users create a shell script containing the necessary commands and rules. Once a ruleset has been devised for your system (to filter various service packets), use the `ipchains-save` command to save your settings.

If you use SUSE Linux, you can use the `yast` command to also perform some basic settings. Start `yast`, select System Administration, then Security Settings. Next, press Enter on Configuration of `/etc/login.defs`. You’ll see a dialog box as shown in Figure 15.12.

### Firewalling Utilities

If you use a DSL (*Digital Subscriber Line*) with Linux, you'll find that Roaring Penguin's *xp-pppoe* installer can also automatically configure a firewall ruleset for you. Other measures to take include installing an entirely separate Linux distribution, named *Trinux*, that can act as a firewall and software router for your LAN.

Although not really a firewall utility, one helpful package that can help you detect a break-in or break-in attempts is *Marty Roesch's* open source *Network Intrusion Detection System*, or *SNORT*. This software package is a network intrusion detection system, and will alert you to numerous types of probes or attacks on your system. There is a version available for *PPC Linux* through <http://www.snort.org>. You can then download the software, decompress and install it like this (as root):

```bash
# tar xzf snort*tgz
# cd snort*
# ./configure ; make install
```

You can then run the program like this (as root):

```bash
# snort -Afull -C snort.conf
```

This example command line uses a sample *snort.conf* file that contains your settings and rule-sets for watching your system. The SNORT package includes a sample set you can put to use right away. To see what is going on while SNORT is running, check its logs under the default log directory, */var/log/snort*.

You should always check your Linux distribution's home page for the latest bug fixes, errata, and upgrades. Many of the fixes involve security issues, that if undressed, can come back to haunt you.

## Samba

Samba is a set of software utilities you can use to integrate your PowerPC Linux system in a Windows LAN or environment. Using various Samba commands, such as *smbmount*, you can then access files from remote servers, or by editing */etc/smb.conf* and running the Samba daemon *smbd*, offer up your Linux partitions as shared volumes.

Mounting a remote shared volume is easy when you use the **smbmount** command. If your system does not allow users to use the **smbmount** command, you can (as root) change permissions for the command like this:

```bash
# chmod 4711 /usr/bin/smbmount
```

This will allow your system's users to mount remote shared volumes locally. For example, if a remote host named **gigi** has a shared volume named **public**, you can easily mount the volume (provided you have access as a user and password) like this:

```bash
$ mkdir gigi
$ smbmount //gigi/public gigi
Password:
$
```

In this example, a directory is first created as a mount point (although any other mount point may be used). Next, the **smbmount** command is used with the pathname syntax containing the name of the remote host and shared volume. At the end of the command line is the local mount point. After pressing Enter and entering a password, the contents of the volume are available under the new local mount point. If you are concerned about granting your users access to running the **smbmount** command, then have any required remote public shares mounted at directories on your system with restricted access permissions.

Configuring Samba to work with your system means editing (as root) the /etc/smb.conf file. Edit this file to tailor Samba for your LAN. For example, the **hosts allow** section:

```bash
hosts allow = 192.168.2.
```

This entry restricts access to hosts from the 192.168.2 subnet. You should also enable Samba passwords:

```bash
security = user
password level = 8
username level = 8
encrypt passwords = yes
smb passwd file = /etc/smbpasswd
```

These entries will require you to run the **smbpasswd** command to generate a user password. Finally, you should then define the shares you'd like to publish on your LAN:

```bash
[homes]
comment = Home Directories
browsable = yes
```
