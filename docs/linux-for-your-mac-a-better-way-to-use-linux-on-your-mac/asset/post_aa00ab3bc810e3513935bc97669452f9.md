
## Setting up for Remote Logins

If you have trouble pinging a remote host, make sure that **DNS** is working (check to make sure the addresses are listed in your `/etc/resolv.conf` file) or that the host's *name* is defined in your system's `/etc/hosts` file:

- 127.0.0.1 localhost localhost.localdomain
- 192.168.2.32 green.home.org green
- 192.168.2.33 stinkpad.home.org stinky
- 192.168.2.34 presario.home.org presario
- 192.168.2.35 thinkpad.home.org thinkpad
- ...

There are many other utilities you can use to test your network and connectivity with other networks. Read the manual pages for the *traceroute* and *dig* commands.

> Another handy command you can use to test the connectivity between two remote hosts (not just your machine) is the *binger* command. Like *ping*, *binger* reports the best, average, and slowest times for packet information to bounce between two computers.

Setting up your Linux box to accept remote logins is easy. There are several types of remote logins available to Linux users. You can allow other users to *telnet* into your computer using the *telnet*, *ssh*, or *ftp* commands. You can also allow people to dial in via an attached or internal modem, log in, and then use a shell. You can also set up a *dialup Point-to-Point Protocol* server to assign a dynamic or static IP address.

*Telnet* and *FTP* access are generally determined by settings in your system's `/etc/inetd.conf` or `/etc/xinetd.d` directory. For example, both *SuSE* and *LinuxPPC 2000* currently use the *inetd* or Internet superdaemon and its `/etc/inetd.conf` configuration file. In this text file you'll see:

```
...
#
ftp stream tcp nowait root /usr/sbin/tcpd in.proftpd
telnet stream tcp nowait root /usr/sbin/tcpd in.telnetd
#
```

These settings allow the availability of FTP and telnet services on your system. Other configuration files, such as `services` or `ttypesace`, may be used to fine-tune control and access by users from specific remote hosts.

## Editing `/etc/inittab`

To allow dial-in access, edit the `/etc/inittab` file, then use a line-monitoring and login utility such as `agetty`, `ugetty`, or `ngetty` to determine a user's access. For example, if you use SuSE Linux and perhaps have an internal modem on `/dev/ttyS0`, you can use the `agetty` command like this:

```
2:123:respawn:/sbin/agetty -w -I 'ATE0Q1&D2&C1S0=1,015' 115200 ttyS0 vt100
```

Use this entry to replace the default entry for runlevel 2:

```
2:123:respawn:/sbin/mingetty tty2
```

The `agetty` command will monitor your modem, then automatically answer the phone and provide a login prompt if a user calls in. The user must have an account on your system in order to log in.

## Handling Shell Accounts

Allowing remote shell accounts is a potential security hazard, but can also provide certain users better access to on-line tools and utilities. For example, if your server has Internet access, this allows remote users to take advantage of your services. Users can conduct business using text-based Internet utilities, such as `pine`, `elm`, `trn`, `slrn`, or `lynx` to send electronic mail, read news, or browse the Web.

You can also restrict activities on your system. For example, your server does not have Internet access, but is connected to a LAN. This way remote users are restricted to business activities, and all records, activities, and files created by employees are kept inside the business.

You can further restrict activities, but perhaps allow Internet access by assigning a single program to a user instead of a shell. For example, your server has Internet access, but in your remote user's `/etc/passwd` entry, substitute a shell entry with the name of a text-based e-mail client, such as `pine`:

```
bball::x:501:billy bally:/home/bball:/usr/bin/pine
```

When the user logs in, the `pine` program will be presented without access to the shell, and will be logged out when exiting the program.

> Make sure the pine has not been compiled with SUSPEND_ENABLE, or else the remote user has to do to access a shell is press Ctrl+z! You'll also want to make sure that pine is listed in /etc/shells.

## Setting up PPP Accounts

If you'd prefer just to provide a PPP account with a static IP address, create your remote user's account, but instead of providing a shell entry in the /etc/passwd file, use the name of a shell script, such as start_ppp.

For example:

```
bball:x:501:501:billy ball:/home/bball:/usr/local/bin/start_ppp
```

The start_ppp shell script looks like:

```
exec /usr/sbin/pppd detach
```

You'll also need a companion entry in the /etc/ppp directory to provide settings for your modem's port. Create a file named options.ttyS0 (to match your modem's port; for example if your modem is on /dev/ttyS1, then the name of the file should be options.ttyS1) that contains the IP address of the server and the IP address you'd like to assign to the remote computer, such as:

```
192.168.2.37:192.168.2.99
```

You'll also need an /etc/ppp/options file that contains:

- asympap 0
- netmask 255.255.255.0
- proxyarp
- lock
- crtscts
- modem

These settings are essential in order to support networking over your modem. You can now allow your remote user to dial in and connect!

## Setting up Web Services

This section includes a few pointers and information about files you'll need to edit in order to provide FTP and Web service on your system. You'll need to ensure that your system has an active Internet connection, and that networking services are up and running.

### Configuring FTP

Most Linux distributions enable FTP service by default. However, if your system does not allow you to FTP in from the command line, first check your `/etc/inetd.conf` settings (as shown earlier). Next, ensure that the inetd daemon has started by using its script (as root) like this:

```
$ /etc/rc.d/init.d/inetd status
INET up
```

You should now be able to use the ftp command to get into your system. For example, if you're working on a host named **cubie**, you should be able to FTP into cubie like this:

```
$ ftp cubie
Trying 192.168.2.66...
Connected to cubie.home.org.
220 cubie.home.org FTP server (Version 6.4/OpenBSD/Linux-ftpd-0.17) ready.
Name (cubie:ball1):
331 Password:
Password:
230- Have a lot of fun...
230 User ball1 logged in.
Remote system type is UNIX.
Using binary mode to transfer files.
ftp> exit
221 Goodbye.
```

Note that if you use `ftp` and log in with your username and password, you'll end up in your home directory. Outside users will log in with the username `anonymous` and then use their e-mail address as the password:

```
$ ftp titanium
Connected to titanium.home.org.
220 ProFTPD 1.2.0pre9 Server (ProFTPD) [titanium.home.org]
Name (titanium:ball): anonymous
331 Anonymous login ok, send your complete e-mail address as password.
Password:
230 Anonymous access granted, restrictions apply.
Remote system type is UNIX.
Using binary mode to transfer files.
ftp>
```

Under SuSE Linux, the default FTP directory is under `/usr/local/ftp`. When you use LinuxPPC 2000, the default directory is located under `/home/ftp`. These settings depend on how FTP is configured for your system. See the manual page for your system’s server, and read up on using `/etc/ftpaccess`, `/etc/ftpusers`, `/etc/ftpgroups`, `/etc/ftpconversions`, and `/etc/ftphosts`. You can use these files to change the default public access directory, grant access, restrict users, change greeting messages or add automatic file conversion utilities.

> If you’re still having trouble, make sure that the version of FTP server designated in your `/etc/inetd.conf` file is installed! There are several FTP distributions available for Linux, such as *wu-ftpd*, *ProFTPD*, and *ftpd*. Each may use a different configuration file. When in doubt, read the documentation included with the software package.

### Configuring Apache

Apache is the *de facto* standard Web server for Linux, although there are some commercial alternative software packages, such as *Zeus*. As you’ve already learned, the system script that starts, stops, and restarts Apache under SuSE Linux is named `/etc/rc.d/init.d/apache`, while under LinuxPPC 2000 (and other Red Hat-based systems) will be named `/etc/rc.d/init.d/htpd`.

With SuSE Linux, Apache is configured by editing the file named `/etc/httpd/httpd.conf`. With Red Hat-based systems, the `httpd.conf` file may be found under the `/etc/httpd/conf` directory. One of the most important settings is `DocumentRoot`, which specifies where your system’s initial Web page is located. For example:

```
#
# DocumentRoot: The directory out of which you will serve your
# documents. By default, all requests are taken from this directory, but
# symbolic links, and aliases may be used to point to other locations.
#
DocumentRoot  "/home/httpd/html"
```
