
## Each application-specific file contains strings of text that may be used to alter a client's appearance.

For example, in the file named `xcalc`, you will, in part, find:

```
...  
*Title: Calculator
*Cursor:		hand2
...
```

These two settings, in the form of `*resource name: resource_setting`, define the title used in the `xcalc` client's window and the type of pointer that appears when you use the client. If you change the resource setting, you will modify how that client appears. For example, you may change the `xcalc` settings to:

```
...
Xcalc.Title:  This Calculator belongs to Willie
Xcalc*Cursor: gumbly
...
```

The resource settings may then be stored in your home directory's `.Xdefaults` or `.Xresources` file to suit your system or personal preferences. You can also create your own `app-defaults` file, and then use the `XUSERFILESEARCHPATH` environment variable to point clients to your settings, like this:

```
$ export XUSERFILESEARCHPATH=$HOME/app-defaults/*
```

To find the settings that are recognized by your favorite client, see its manual page, documentation, or sample entry under the `app-defaults` directory.

### My .Xdefaults Changes Are Not Recognized!

You may have to merge the changes into your current X resource settings using the `xrd` client. You can do this quickly and easily by using `xrd`'s `-merge` option, followed by the name of the resource file like this:

```
$ xrd -merge .Xdefaults
```

After you press Enter, the affected client(s) should use your new settings. If not, make sure that your resource strings are correct. You can also use the `xres` or `editres` client to see and verify other client resource settings.

### Using .xsession

The `.xsession` file (generally a shell script) may be used instead of your `.xinitrc` file, though many Linux distributions default to using `.xinitrc`. The `.xsession` file is run automatically if you log in from an X terminal, and should contain commands similar to those of `.xinitrc` (such as loading in resource settings). Note that some distributions, such as LinuxPPC 2000 Q4, do not include the older companion `xsession` client, which can be used to switch between window managers. Most distributions use the `xsm` session manager instead.

A session manager is used to launch one or more groups of clients that you specify in `.xsession` (if you use `xdm`), or if you use `xsm`, in a file named `.xsmstartup` or a default `system.xsm` (the location of which depends on how the `xsm` was compiled). If you want to use `xsm`, the format of your `.xsmstartup` file can be as simple as:

```
twm
xprop
xcalc
xclock
xterm
```

Save the file, then use the `xsm` client, followed by an active X session’s display number like this:

```
$ xsm -display :0
```

You can then navigate to the active session by using the keyboard (if you are running a stand-alone workstation) by pressing Cmd+F7 (console 7 is the default Linux console used for X). The first time you use `xsm`, each client will launch, and you will see an `xsm` control dialog box, used to control the session. As you work, and possibly launch additional clients, you can then use `xsm` to save your work state with a session name.

For example, if you conduct an extensive word processing session with a text editor, calculator, and online dictionary, you can save the session as "My Editing Session." The next time you launch `xsm`, you will see a Session Menu as shown in Figure 8.1, from which you can pick your previously defined sessions.

![](img/1ea833f5a3e3c1547e3dd2891f52804a_191_0.png)

**Figure 8.1** The `xsm` client supports session management, even for X clients that do not fully support this feature.

Pick a session type using the Up and Down arrow keys, then click the Load Session button to launch your previously saved custom session. This is a powerful way to "remember" or organize your X sessions and keep track of what applications were in use. Using a session manager can also save time and effort if you have several different clients launched at the same time. Note that session-management is a staple feature in the KDE and GNOME desktop environments; `xsm` is only required for older window managers without session management.

Also, nearly every distribution includes a file (which is actually a shell script) named `.Xsession`, but it is employed when you use the `xdm` display manager to log into Linux and X. This shell script is used to configure and set up the login screen and dialog box. Although `.Xsession` has nothing to do with `xsm`, it may, especially on some Red Hat-based distributions, create a file named `.Xsession-errors` to log errors encountered while using X, and execute window managers and clients found in the home directory’s `.Xsession` file.

### Yet More X Files!

You may also find an `.Xclients` file in your home directory. This file, along with its system-wide counterpart `xclients` (possibly found under the `/etc/X11/xinit` directory), can be used like `.Xinitrc` to launch specific X clients. Another file, named `.xauthority`, is used to store authorization records when you log into X using a display manager.

### Using X11 Terminal Clients

As you use the Linux console, you will become more proficient at using the shell. Using the shell during an X session requires the use of a terminal client (although KDE’s Konsole client may be used for one-line commands). As with the vast choice of shells for Linux, you will also have a variety of terminal clients to choose from during your sessions.

Finding a terminal of choice may depend on your needs, personal tastes, or the client’s features. Nearly all terminal clients may be configured in some way to work a bit better, and nearly every window manager supports resizing of a terminal window so that it may fit more comfortably in your display area.

Use a terminal window that is at least 80 characters wide by 25 lines high. This is the default for many console-based applications, and some screen-oriented commands may refuse to run or not work properly at a reduced window size. Some terminals need special software libraries, and others may only work well or enjoy special features when used with a particular window manager.

### Launching and Quitting a Terminal

To launch a terminal client, click the appropriate menu item from your window manager's desktop panel or root display menu. As you have seen, you can also arrange to have a terminal launch before your X session. Once the terminal has launched you can move your pointer to its window and start using the shell. Whether or not you have to click on the terminal window to make it active depends upon your window manager's current focus policy settings.

You can then use the shell to launch additional X clients, preferably in the background (as a process in memory), and then go back to work. This is accomplished by using the shell's background operator, the ampersand (&), to launch a new instance of the `xterm` terminal. It is done like this:

```
$ xterm &
```

This approach detaches the `xterm` process from your shell command line, and the new `xterm` will be displayed in its own window. This is how you can (and most often should) launch nearly all graphical clients during an X session.

Quitting a terminal session can be accomplished in a number of ways. If the GNOME or KDE terminal has a File menu, select the Quit menu item. You can also type `exit` at the terminal's command line to close the terminal session. If the window manager provides window decorations such as a close box, then click the box to destroy the window. Finally, you can also use the shell's `kill` command, along with a process ID number, to kill the terminal's process (This is a messy and inconvenient, but is often a necessary way to close a terminal).

### Selecting a Terminal

You'll find quite a few terminal clients included with PPC Linux. Some clients are part of the GNOME and KDE distributions, while others, such as `xterm`, are default terminals included with XFree86. Table 8.1 lists several X terminal clients included with most Linux distributions.

Some of the features to look for when choosing a terminal are the terminal's ability to handle scrolling, color, different fonts, emulate different terminal protocols, and perhaps the use of background images or a transparent background (to give the illusion of translucency).
