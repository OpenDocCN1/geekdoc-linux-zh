To see what shell you have been assigned, examine the last field in your passwd file entry. You can do this quickly by using the *finger* command, your login or *username*, and the location and name of the *passwd* file or *pathname*, like this:

```
$ finger kbali /etc/passwd

bbali:x:500:100:William Balli:/home/bballi:/bin/bash
```

In this example, the default shell for the user *bbali* is *bash*. This shell may be used because it is listed in the system-wide list of approved shells, /etc/shells. Look at your system's list of approved shells by using the *cat* command, followed by the pathname to the file like this:

```
$ cat /etc/shells
/bin/ash
/bin/bash
/bin/bash1
/bin/csh
/bin/false
/bin/ksh
/bin/qsh
/bin/tcsh
/bin/true
/usr/bin/csh
/usr/bin/ksh
/usr/bin/passwd
/usr/bin/rbash
/usr/bin/tcsh
/usr/bin/zsh
```

This example, from a SuSE PPC 7.1 system, shows a number of shells (and other applications) that are deemed acceptable shells. Once you know that a shell is acceptable, you can then (as with root) edit your /etc/passwd entry to replace or change the default shell's pathname.

However, a much better (and safer) way to change shells is to use the *chsh* command. Use this command, followed by its *-s* command-line option and the pathname of the desired shell like this:

```
$ chsh -s /usr/bin/ksh
Password:
```

Note that you will be prompted for your password after pressing Enter. Type in your password and then press Enter again. The *chsh* command does have some error-checking, and will parse /etc/shells before allowing you to make a major mistake by entering a non-existent or bad pathname:

```
$ chsh -s /usr/X11R6/bin/ksh
Password:
/usr/X11R6/bin/ksh is an invalid shell.
```

Finally, if you want to become familiar or experiment with a different shell, simply log in to Linux, and enter a shell's name at the bash prompt:

```
bball@cubie:~> tcsh
/home/bball>
```

In this example, the tcsh shell has been launched. Note that the shell prompt has changed! To return to the previous instance of the bash shell, use the exit tcsh built-in command to log out of tcsh and return, like this:

```
/home/bball> exit
exit
bball@cubie:~>
```

After you press Enter, tcsh will echo "exit" and return you to bash.

# How to Use the Shell

This section introduces some basic concepts about using the shell, and offers examples that demonstrate some features of using a shell with Linux. You will learn how to share information between commands, create data on the fly, start programs in the background (in memory), and recall or kill programs running in the background. You will also learn how to use wildcards, or regular and extended expressions, which are a form of search syntax used on the command line.

The basics of using a shell can be quickly mastered in a few sessions; however, exploring advanced techniques and crafting creative command lines will require more experimentation.

## Input and Output Redirection

Under Linux, nearly every object is a file (including directories and devices). This includes the stream of information flowing into (the standard input, or stdin) and out of (the standard output, or stdout) commands or devices. The standard input can be your keystrokes, the contents of a text file, a graphic image, or data streaming in from a modem via a serial port. It can also be digital data in the form of audio or video, or a delimited (or specifically truncated) value. The standard output is used to redirect, forward, store, append, or discard data. Error messages from commands may also appear on a form of standard output known as `stderr`, or standard error. Input and output redirection with the shell is accomplished by using specific operators, such as `>`, `>>`, and `<<`.

## Using the Output Redirection Operator

For example, you can quickly create a text file containing a list of the current contents of your home directory by using the `ls` command, the output redirection operator `>`, and the pathname or file name like this:

```
$ ls >mydirectory.txt
```

In this example, the file `mydirectory.txt` will be created if it does not exist (or it will overwrite and replace any file with the same name), and will contain a list of visible files in the directory. Why will it contain only the visible files? Because any file with a name beginning with a period (.) is deemed invisible by default by the `ls` command. To get an entire list, use the `ls` command’s `-a` (list all) command-line option like this:

```
$ ls -a >mydirectory.txt
```

In this example, the file `mydirectory.txt` will be deleted if it exists, or created if it does not exist, and will contain a list of all files in your home directory.

> Be careful using output redirection! Use of this operator will quickly and silently overwrite files without warning. Always make sure you know where and what you are directing output to. This will help you avoid erasing existing files!

## Appending Data

Data can be added to the end of a new or existing file by using the append operator, `>>`. For example, you can quickly build a list of names and phone numbers by using the `echo` command and the append operator like this:

```
$ echo "Deb Cohen (607) 555-1212" >>phones.txt
```

This example will append the information between the quote marks (`"` ) up to the end of the file named `phones.txt`. If you used the output redirection operator, the current file would have been deleted if it existed, and replaced with the new information.

## Using the Input Redirection Operator

The input redirection operator is used to get information from a file or stream of data. For example, you have a text file named `foo.txt` containing a short list of words such as:

```
zoo
cat
water
insulin
dog
trimester
hardcore
```

You can then use the `sort` command to sort and display a new list of words like this:

```
$ sort < foo.txt
cat
dog
hardcore
insulin
trimester
water
zoo
```

You can also create short text files with the `cat` command by using input and output redirection at the same time, like this:

```
$ cat >foo.txt
This is a line of text
in a file named
foo.txt!
```

In this example, the `cat` command waits for its input from the standard input, or the console. After typing in the last line and pressing Enter, you then press `Ctrl+d` to signify the end of the file and close the new file. Another way to specify the end-of-file character is to use another input redirection operator known as the `here` operator. Using the previous example, instead of typing `Ctrl+d` to end the file, you can specify a delimiter, such as a string of Zs, like this:

```
# cat >foo.txt <<ZZZ
This is a line of text.
This is another line of text.
Lookout! "Here" comes the end of the file!
ZZZ
```

In this example, the file is closed, and typing ends when the here operator finds the string "ZZZ" by itself on a line.

## Using Pipes

One of the most important features added to the shell is the ability to use pipes, which are defined by the bar (|) operator. The ability to "pipe" the output of one program into the input of another program forms the basis of the UNIX philosophy, which is to use small programs that do one thing well and work together with all other programs.

Although you have seen how to redirect input and output to and from commands and files, the true power of the shell becomes apparent when you can combine the output of one program to create input for another program and so on. This is done in order to build new commands or files. Many Linux commands also have the ability to work with pipes and filter input to provide a changed output.

For example, you can search your system to find all files named **README** under the /usr directory by using the find command like this:

```
$ find /usr -name README -print
```

After you press Enter, a list of pathnames may scroll down your screen. You can then send the output of the find command to the input of the xargs command (using the cat command in this example) to list each file:

```
$ find /usr -name README -print | xargs cat
```

The result will be a single output of all the text contained in all the README files on your system. Is this useful? Perhaps it is not yet as useful as it will be. You can then add the tr command to take the output at this stage:

```
$ find /usr -name README -print | xargs cat | tr " " "\n"
```

The input stream to the tr command is then broken up by having each space found in every line of text turned into a carriage return. The result is a long list of words. This stream can then be manipulated by sorting with the sort command like this:

```
$ find /usr -name README -print | xargs cat | tr " " "\n" | sort
```

The result is a sorted list of words having many duplicates! In the grand UNIX tradition, there is a command to remove adjacent duplicate lines in a file, *uniq*:

```
$ find /usr -name README -print | xargs cat | tr " " "\n" | sort | uniq >dict.txt
find: /usr/share/doc/packages/gettyps: Permission denied
find: /usr/share/doc/packages/smeifl: Permission denied
...
```
