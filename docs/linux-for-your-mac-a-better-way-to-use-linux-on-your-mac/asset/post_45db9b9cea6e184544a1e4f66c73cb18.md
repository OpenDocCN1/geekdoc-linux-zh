
## Network Administration and Utilities

This section introduces graphical interface utilities you can use to create network interfaces and to then test those interfaces. You’ll see how SuSE’s **yast** command provides a text-based interface and how its **yast2** command provides a graphical interface. You’ll also see how to use a Red Hat-based system’s **netcfg**, **netconf**, or **linuxconf** tool to control networking.

Obviously, the first step is to assign your computer a hostname. This can be done by the root operator by using the **hostname** command, by creating a file named **HOSTNAME** with the system’s hostname under the /etc/directory, or through various graphical administration tools.

Under Red Hat systems, one way a system administrator can assign a hostname is to use the *netcfg* client, which requires an active X session. Start *netcfg* from the command line of an X11 terminal like this:

```
# netcfg &
```

After you press Enter, you’ll see a dialog box, as shown in Figure 15.3.

To assign a hostname, click, then type a name in the hostname field in the dialog box. When finished, click the Save button, then click the Quit button to exit. Another utility you can use as root is the *netconf* client (generally available through the *linuxconf* tool), which can be used from the console or an X terminal window like this:

```
# netconf &
```

## Creating Network Interfaces

Creating network interfaces while using Linux is easy. Network interfaces are created in memory using a variety of utilities. Some programs are command-line based, while others are graphic utilities you can use as a system administrator to quickly and easily set up networking and connect to another computer or a LAN. Obviously, you'll need to have an installed network card or PCMCIA network interface card in your system. Some Power Macs, such as the iBook or TiBook, have internal cards that are recognized by Linux at boot time. You can use the `dmesg` command to check to make sure the card is recognized like this:

```
$ dmesg
...
etht: GMAC at 00:30:65:f9:df:a0, driver v1.3k2
3c59x.c 15x8ep00 Donald Becker and others http://www.scyld.com/network/vortex.html
...
```

This example, from a TiBook running LinuxPPC 2000, shows that the card has been recognized. The driver should print the card’s Media Access Control address, an internal hardware address unique to each network card, along with other pertinent information. Once the card has been recognized and configured, you can assign an Ethernet address through the command line or a graphical utility.

### Creating Ethernet Devices

Under SuSE Linux, use the `yast2` command to create a network interface definition during an X session. Launch this client (as root) from the command line of an X terminal window like this:

```
# yast2 &
```

After you press Enter, you’ll see a dialog box as shown in Figure 15.5. Click the Launch module button to get started. The screen will clear, and yast2 will recognize and print the name of your network interface. Click the Next button to continue, and you’ll then see a screen, as shown in Figure 15.6.

If your network uses DHCP, your interface will be automatically assigned an IP address. If you prefer, you can also enter your own IP address manually. If you are behind a firewall, enter the IP address of your gateway computer in order to access the Internet. When finished, click the Next button.

In the yast2 window, configure your interface manually (to assign an IP address), or select a DHCP assignment.

The next screen, shown in Figure 15.7, is used to assign a hostname, domain, and IP addresses of your system's Domain Name servers. If you are connected to the Internet via an ISP, enter your ISP's DNS numbers and perhaps your ISP's domain name in the Domain Search list fields.

If you administer LinuxPPC 2000 or another Red Hat-based system, such as Yellow Dog Linux, one way to create an Ethernet interface is to again use the `netcfg` client.

In the main window (shown in Figure 15.3), click the Interfaces button, then click the Add button. You’ll see a small dialog box appear, as shown in Figure 15.8.

Click the Ethernet check box, then click the OK button. A new dialog box, as shown in Figure 15.9, will appear.

Type in a valid IP address, or if your system uses DHCP to dynamically assign IP addresses, click the interface configuration protocol button, then select DHCP from its drop-down menu.

![](img/1ea833f5a3e3c1547e3dd2891f52804a_399_0.png)

> You should only have one server on your LAN that acts as a DHCP server. This service can be started manually or by using an administration utility such as `linuxconf`, `ntsysv`, or `xast`.

When you have finished entering your information, click the Done button, then click the Save button. To start or stop your interface, click its name in the `netcfg` window, then click the Activate or Deactivate button. When finished, click the Quit button.

System administrators can also use the netconf command to create an interface. Start netconf, click the Basic Host information button, then click on the Adapter 1 tab, as shown in Figure 15.4. A dialog box, shown in Figure 15.10, will appear.

Note that you can select a type of boot configuration, such as DHCP, or assign an IP address manually. You can also use the Enable check box to enable or disable the interface. When finished, click the Accept button, then go through the netconf dialog box boxes to activate your changes.

### Basic Network Utilities

This section introduces a few basic utilities you, as the root operator, can use to create, manipulate, or test your interface. For example, you can manually create an Ethernet interface using the ifconfig command. This command generally takes arguments in the form of:

```
ifconfig interface hostname/IP_address status
```

For example, since the first Ethernet interface created on your system has the default name of eth0, you can create it quickly like this:

```
# ifconfig eth0 cubic.home.org up
```

If you have not assigned a hostname to your computer, you can also substitute its IP address like this:

```
# ifconfig eth0 192.168.2.66 up
```

After creating your system's Ethernet interface, you can check it using ifconfig like this:

```
$ /sbin/ifconfig eth0

eth0       Link encap:Ethernet  HWaddr 00:30:65:AB:F6:D6
           inet addr:192.168.2.66  Bcast:192.168.2.255  Mask:255.255.255.0
           inet6 addr: fe80::30:65ab:fed6:f6d6/10  Scope:Link
           inet6 addr: fe80::230:65ff:feab:fd66/10  Scope:Link
           UP BROADCAST RUNNING MULTICAST  MTU:1500  Metric:1
           RX packets:2233795 errors:0 dropped:0 overruns:0 frame:0
           TX packets:2115741 errors:0 dropped:0 overruns:0 carrier:0
           collisions:0
```

You should see the assigned IP address, along with the interface's MAC address. Another way to check your interface is to use the ping command to echo small packets of information off another computer, like this:

```
$ ping green.home.org
PING green.home.org (192.168.2.37): 56 data bytes
64 bytes from 192.168.2.37: icmp_seq=0 ttl=255 time=0.419 ms
64 bytes from 192.168.2.37: icmp_seq=1 ttl=255 time=0.328 ms
64 bytes from 192.168.2.37: icmp_seq=2 ttl=255 time=0.361 ms
64 bytes from 192.168.2.37: icmp_seq=3 ttl=255 time=0.360 ms
-- green.home.org ping statistics --
4 packets transmitted, 4 packets received, 0% packet loss
round-trip min/avg/max = 0.328/0.367/0.419 ms
```

The ping command will run forever until you press Ctrl+c (you can also set a predetermined number of echoes by using the command's -c option, followed by a number). If you run into trouble, first make sure that you have networking services enabled. Next, make sure that you also have a local loopback device enabled:

```
$ ifconfig lo

lo       Link encap:Local Loopback
           inet addr:127.0.0.1  Mask:255.0.0.0
           inet6 addr: ::1/128  Scope:Host
           UP LOOPBACK RUNNING  MTU:1924  Metric:1
           RX packets:45171 errors:0 dropped:0 overruns:0 frame:0
           TX packets:45171 errors:0 dropped:0 overruns:0 carrier:0
           collisions:0
```
