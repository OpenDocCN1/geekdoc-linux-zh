that control a particular process, service, or software package, according to the runlevel. For example, when Linux boots to runlevel 3, the system state which uses a text-only console, the symbolic links under /etc/rc.d/rc3.d to /etc/rc.d/init.d scripts are used:

```
K83ypbind --> ../init.d/ypbind

K84ypserv --> ../init.d/ypserv

K92anacron --> ../init.d/anacron

K92ipchains --> ../init.d/ipchains

K96irda --> ../init.d/irda

S10network --> ../init.d/network

S11portmap --> ../init.d/portmap

S14nfslock --> ../init.d/nfslock

S18autofs --> ../init.d/autofs

S20random --> ../init.d/random

S25netfs --> ../init.d/netfs
```

Note that not all the links are listed here. But the names of the links are important, and the order in which the links are executed is also important. Links with names beginning with K indicate a service to be stopped, while names beginning with S indicate services to be started. The numbering in the name determines when an action takes place when moving to the runlevel. The files for runlevel 3 above show that when the Linux system is in a particular state (such as starting, restarting, or shutting down) and going at a particular runlevel, the proper set of scripts are executed in a particular and proper order (even though many Red Hat Linux-based systems continue to start, then delay networking if PCMCIA services are used; a better approach is to start PCMCIA, then start networking service).

After Linux finishes executing the various scripts, other services may be started or stopped, depending on entries in other files, such as /etc/sysconfig or /etc/rc.d/rc.local (for Red Hat systems), or /etc/rc.config or /etc/rc.d/boot.local (for SuSE Linux). Initialization scripts that are executed directly before login may be ideal locations for local customization of your system, such as to configure key-board keys to emulate mouse buttons.
