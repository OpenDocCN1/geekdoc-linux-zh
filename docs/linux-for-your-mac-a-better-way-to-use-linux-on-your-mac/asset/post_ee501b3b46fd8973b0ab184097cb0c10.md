
![](img/1ea833f5a3e3c1547e3dd2891f52804a_356_0.png)

*Figure 14.9 The linuxconf client is a comprehensive tool you can use to manage your system.*

If you run `linuxconf` for the first time, you will see a large introductory dialog box. Press the *Quit* button, and its main dialog box will appear, as shown in Figure 14.9. The `linuxconf` dialog box splits tasks into configurations and controls. Configuration tasks include:

- **Networking.** Client tasks, such as hostname, nameserver, routing, and PPP configuration; server tasks such as NFS (*Network File System*), Apache, DNS (*Domain Name Server*), mail, Samba, and FTP; and miscellaneous tasks such as administrative network access.
- **User Accounts.** Normal users and groups; special accounts, such as PPP, SLIP, and POP; e-mail aliases; policies such as passwords expiration, shells, and the MOTD (*Message Of The Day*).
- **Filesystems.** Accessing mounted volumes; swap file management; and quotas.
- **Miscellaneous services.** Initial system services to use and modem management.
- **Boot mode.** Boot prompt management and shell assignment.

Control tasks available through the `linuxconf` dialog box include:

- **Control panel.** Change activation; reboot and shutdown; mounting and unmounting of filesystems; superserver schemas; configuration archiving.
- **Control files and systems.** Configure configuration; files; commands; file permissions; `linuxconf` modules and addons.
- **Logs.** Date, time, timezone control; `linuxconf` keyboard controls.

### Using SuSE's YaST Command and YaST2 Client

SuSE Linux is well known for providing a comprehensive, easy-to-install and manage, Linux system. One of the most impressive features about SuSE is the tight integration of system management tools and scripts. Although it is possible to manually configure a SuSE Linux system, unlike other Linux distributions, this Linux distribution is best administered using the `yast2` graphical client, or until recently, the `yast` console command.

Both clients provide access to SuSE's central resource configuration file, `/etc/rc.config`. This file contains settings for many different aspects of your system, and looks like (in part):

```text
...
# NIS(YP)/NIS+ domainname, ask the admin of the server.
#
YP_DOMAINNAME=""
#
# Start the rpc.ruserd daemon in multi-user? ("yes" or "no")
# rpc.ruserd is a server which returns information about users currently
# logged in to the system.
#
START_RUSERD="no"
#
# Start the rpc.rstatd daemon in multi-user? ("yes" or "no")
# rpc.rstatd is a RPC daemon which collects performance statistics from
# kernel on serving machine.
#
START_RSTATD="no"
...
```

The traditional, console-based `yast` command does not require an active X session, unlike many other graphical administration tools. This is extremely handy if you would like to administer a remote computer on your network through dial-up access. However, the `yast2` client does require an active X session, and it may be used over a higher-speed network to administer a remote computer. Both clients must be run as root.

Launch the console-based `yast` command from the command line like this:

```bash
# yast &
```

![](img/1ea833f5a3e3c1547e3dd2891f52804a_358_0.png)

*Figure 14.10 The yast command is SuSE's comprehensive administration tool.*

After you press Enter, its main dialog box will appear, as shown in Figure 14.10. The `yast` command provides user, system, network, and software management. Several of its initial menu items lead to further menus you can use to maintain your system. For example, choosing the Adjustments menu item provides for changing the language setup, keymaps, location of SuSE Linux installation software, and partition management. However, the main functions are found under the System administration menu item.

This menu provides for:

- **Hardware configuration.** New keyboards, pointing devices, printers, scanners, modem, CD-ROM drives, and networking interfaces.
- **Configuration.** For nearly all networking services, and devices.
- **Boot mode management.** Such as using an X11 display manager.
- **Managing users and groups.**
- **Performing system backups.**
- **Security settings.** To restrict system access or enable other security features.
- **Date, time, and time zone settings.**

To use the graphical `yast2` client, type its name on the command line of an X11 terminal window like this:

```bash
# yast2 &
```

After you press Enter, its main administration tool will appear, as shown in Figure 14.11.

![](img/1ea833f5a3e3c1547e3dd2891f52804a_359_0.png)

*Figure 14.11 The yast2 client is SuSE’s newest graphical administration tool.*

Like the `yast2` command, `yast2` provides device, software, networking, and remote system management. Its initial menu items launch administrative modules you can use to maintain your system. These include:

- **Hardware.** To configure printers and system sound services.
- **Software management.** To install, remove, or update system software.
- **Networking.** Configuration and control of server software, remote filesystems (such as NFS), and electronic mail.

- **Remote services.** Remote administration and installation allows a network administrator to launch `yast2` modules on remote computers, or install SuSE Linux via a serial networking connection.

### Other Legacy Tools

You may find one or more legacy graphical administrative tools included with Yellow Dog Linux and LinuxPPC 2000 Q4. These tools are console-based, and do not require an active X session. Although not as comprehensive as `yast` or `linuxconf`, these programs still fulfill a niche in system administration. One program named `ntsysv` is used to control which services should be started the next time the system is booted.

![](img/1ea833f5a3e3c1547e3dd2891f52804a_360_0.png)

*Figure 14.12 The `ntsysv` command is a useful legacy tool you can use to control services on a Red Hat-based PowerPC Linux system.*

Start `ntsysv` (as root) by typing its name on the command line of your console or an X11 terminal window like this:

```bash
# ntsysv
```

After you press Enter, the console will appear as shown in Figure 14.12.

This command works similarly to the manual `chkconfig` command, which can be used to reorder services in various runlevels. When using `ntsysv`, scroll through the list of services and press the spacebar to toggle whether or not you would like to use that service the next time your system boots.

You can quickly start, stop, or restart a particular service, such as Apache, by specifying its script name under the `/etc/rc.d/init.d` directory like this (as root):

```bash
# /etc/rc.d/init.d/httpd start
# /etc/rc.d/init.d/httpd stop
# /etc/rc.d/init.d/httpd restart
```

These command lines will start, stop, or restart (handy after making any service configuration changes) a specified service. To put a change into effect for a particular runlevel, use the `chkconfig` command. This program is used from the command line to make changes in the `/etc/rc*.d` directories, where *x* represents a particular runlevel.

You can also get a quick snapshot of your entire system's services configuration by using the `chkconfig` command with its `--list` option like this:

```bash
# chkconfig --list
syslog     0:off   1:off   2:on    3:on    4:on    5:on    6:off
crond      0:off   1:off   2:on    3:on    4:on    5:on    6:off
netfs      0:off   1:off   2:off   3:on    4:on    5:on    6:off
network    0:off   1:off   2:on    3:on    4:on    5:on    6:off
random     0:off   1:off   2:on    3:on    4:on    5:on    6:off
keytable   0:off   1:off   2:on    3:on    4:on    5:on    6:off
atd        0:off   1:off   2:off   3:on    4:on    5:on    6:off
gpm        0:off   1:off   2:on    3:off   4:off   5:off   6:off
sendmail   0:off   1:off   2:on    4:on    5:on    6:off
httpd      0:off   1:off   2:off   3:off   4:on    5:off   6:off
...
```

Not all the output is shown here. On a LinuxPPC 2000 Q4 system with a full installation, you will find nearly 60 different services you can control! Using `chkconfig`, you can quickly control the service that runs a particular runlevel. For example, to control the Apache Web server on your system, and to assign or restrict various runlevels, such as 3 (multi-user mode, text console login) or 5 (multi-user mode, graphical X login), use the command like this:

```bash
# chkconfig --level 3 httpd on
# chkconfig --level 5 httpd off
```

In these examples, Apache will be started if Linux is booted to runlevel 3, but will not be started if booted to a graphical X login (runlevel 5).

### Managing Software

This section introduces the ubiquitous `rpm` command, also known as the Red Hat Package Manager. RPM is a unique software management technology that provides package management, or the ability to securely bundle, distribute, install, remove, and otherwise manage software in the forms of packages. Used by software developers on many different computer platforms, RPM is also used on nearly every PowerPC Linux distribution, with the exception of Debian GNU/Linux, which uses a different packaging system and .deb software archives.

You will be introduced to the basics of using the `rpm` command from the command line, and will then learn how to launch and use two different graphical RPM clients that work under X11. You will also learn how to build and install software from scratch using `rpm`.
