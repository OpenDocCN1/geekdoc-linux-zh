These settings allow the availability of FTP and telnet services on your system. Other configuration files, such as `services` or `ttypesace`, may be used to fine-tune control and access by users from specific remote hosts.

# Editing `/etc/inittab`

To allow dial-in access, edit the `/etc/inittab` file, then use a line-monitoring and login utility such as `agetty`, `ugetty`, or `ngetty` to determine a user's access. For example, if you use SuSE Linux and perhaps have an internal modem on `/dev/ttyS0`, you can use the `agetty` command like this:

```
2:123:respawn:/sbin/agetty -w -I 'ATE0Q1&D2&C1S0=1,015' 115200 ttyS0 vt100
```

Use this entry to replace the default entry for runlevel 2:

```
2:123:respawn:/sbin/mingetty tty2
```

The `agetty` command will monitor your modem, then automatically answer the phone and provide a login prompt if a user calls in. The user must have an account on your system in order to log in.

# Handling Shell Accounts

Allowing remote shell accounts is a potential security hazard, but can also provide certain users better access to on-line tools and utilities. For example, if your server has Internet access, this allows remote users to take advantage of your services. Users can conduct business using text-based Internet utilities, such as `pine`, `elm`, `trn`, `slrn`, or `lynx` to send electronic mail, read news, or browse the Web.

You can also restrict activities on your system. For example, your server does not have Internet access, but is connected to a LAN. This way remote users are restricted to business activities, and all records, activities, and files created by employees are kept inside the business.

You can further restrict activities, but perhaps allow Internet access by assigning a single program to a user instead of a shell. For example, your server has Internet access, but in your remote user's `/etc/passwd` entry, substitute a shell entry with the name of a text-based e-mail client, such as `pine`:

```
bball::x:501:billy bally:/home/bball:/usr/bin/pine
```

When the user logs in, the `pine` program will be presented without access to the shell, and will be logged out when exiting the program.
