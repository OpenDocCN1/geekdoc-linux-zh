## Sound

One of the most joyful things about using Linux is its support for sound and the wealth of audio and multimedia utilities. However, if you are depending on sound support while using PPC Linux, choose your Power Mac model carefully. Sound may or may not be fully supported.

Unfortunately, there is no comprehensive list of the hardware and functions that are supported on each existing Apple Power Mac computer. However, in general, sound is supported on most machines by simply loading the `dnasound.o` kernel module. An exception is the Apple G4 Cube, which plays sound via USB (*Universal Serial Bus*) speakers. For this model, simply load the `audio.o` kernel module using the `insmod` command, like this:

```
# insmod audio
```

Other models, such as early iBooks, may require specially configured Linux kernels in order to play sound. Linux may not support sound yet on newer (Summer 2000) iBooks.

Another issue is the playing of audio CDs on slot-loading Power Macs. On most Intel-based PCs and notebooks, audio CDs can often be played even if sound is not supported by the computer's sound chip, because audio output from the CD drive is connected directly to the computer audio out hardware. This is not true of Apple's hardware, so even if sound is supported on your Power Mac, you may find that audio CD clients do not work.

You can solve this problem by loading IDE (Integrated Drive Electronics) SCSI (Small Computer Systems Interface) emulation using the ide-scsi kernel module, like this:

```bash
# insmod ide-scsi
```

Next, use the ln command to create a link named /dev/cdrom that points to your computer's CD-ROM device (as a SCSI device). The emulated SCSI device is /dev/sr0:

```bash
# ln -s /dev/sr0 /dev/cdrom
```

If your distribution, such as YDL 2.0 or LinuxPPC 2000, does not include /dev/sr0, use the mknod command like this to create the device:

```bash
# mknod /dev/sr0 b 11 0
```

Use your favorite text editor to create a shell script named mycdplay containing a command line, like this:

```bash
cdda2wav -t $1 -D /dev/cdrom -N -e -q -x -d0 -I cooked_ioctl1 $
```

Save the file, and then use the chmod command to make the file executable, like this:

```bash
# chmod +x mycdplay
```

You can now insert an audio CD into your slot-loading Power Mac running Linux and play tracks, such as 2-6, like this:

```bash
# ./mycdplay "2-6"
```

This approach works by using the cdda2wav command to strip, convert, and play selected audio tracks from an audio CD in a single step. It is not a perfect approach because other system activity, hard drive activity, or other active processes may cause a skip or two while playing; however, this command works well on faster G4 machines or slower machines that would otherwise be idle. Also, while this approach works without problems or requiring a kernel recompile with SuSE PPC 7.1 or LinuxPPC 2000 Q4, YDL 2.0 users may have to recompile the default kernel to enable SCSI emulation.

Do not be disappointed or frustrated if sound is not fully supported right away on your new Power Mac. Chances are good that as PPC Linux matures, support will improve, and you will soon be playing music and watching DVDs (see Chapter 13, "X11 Multimedia").

## USB

USB (*Universal Serial Bus*) support has improved at an amazing rate for Linux. Nearly all mice and keyboards, including PFU AMERICA, INC.'s USB Happy Hacking keyboard (used to write more than half this book), are supported. Many other USB devices, such as parallel-port, serial adapters, printers, and scanners are also supported.

One of the first places to check for USB support under Linux is the Linux USB project at http://www.linux-usb.org. Note however, that support for a particular device under PPC Linux is not assured; it all depends on how well the Intel-based driver works on the PowerPC platform. The good news is that many devices are well supported, and most work very well.

### Adding USB Devices

USB support is generally compiled into the Linux kernel, with support for different devices provided by loadable kernel modules. Look under the `/lib/modules/` `2.x.x/usb` directory, where `2.x.x` is the version of your Linux kernel. Under the `usb` directory you will find various kernel modules to support different devices. Some USB modules have names for a specific device, such as *keyspan_pda.o* for Keyspan's USB-to-serial PDA adapter. Other modules, such as *scanner.o*, support a wide variety of devices.

### Adding a Scanner

If you are a graphic artist, and want to use a scanner with PPC Linux, do not worry; there are many different scanners that work with PPC Linux and various Power Mac computers. In the past, most scanners for Mac OS have used SCSI interfaces. Today, however, most scanners are supported by the USB interface.

Support for USB scanners is contained in the `scanner.o` module. This module supports a wide variety of scanners. However, in order to use a scanner with Linux you need corresponding driver support. This support is usually provided by the SANE (*Scanner Access Now Easy*) collection of "back- and front-end" software utilities.

If you are considering getting a USB scanner and using it with Linux, you should first browse to the SANE home page at: http://panda.mostang.com/sane/ and check for support for your intended scanner (see Chapter 13, "X11 Multimedia", to learn more about using SANE). Next, check the Linux USB devices page to see if the scanner module supports your scanner.

At the time of this writing, the PPC Linux scanner driver supports many different scanner models, such as Acer's Prisa 620U, 640U, and 640BU; Agfa's Snapscan 1212U; Epson's GT-7000; Perfection 610U, 636U, and 640U; 1200U/Photo; and 1240U/Photo; and Hewlett Packard's 5100C, 5200C, and 6300C models.

If you use an Epson 640U USB scanner and SuSE Linux PPC, you need to add support for your scanner by editing the scanner module source, and rebuilding the scanner.c kernel module. Edit the file scanner.h under the /usr/src/linux/drivers/usb directory.

> You need to install the appropriate kernel source, kernel headers, and development libraries, utilities and commands (such as the gcc compiler) in order to rebuild kernel modules (or the Linux kernel). This requires at least an extra 150MB of hard drive space.

Look for the entry:

```c
/* Seiko/Epson Corp. */
{ 0x04b8, 0x0101 },  /* Perfection 636U and 636Photo */
{ 0x04b8, 0x0103 },  /* Perfection 610 */
{ 0x04b8, 0x0104 },  /* Perfection 1200U and 1200Photo */
```

You need to add the USB identification string information for your 640U, like this:

```c
/* Seiko/Epson Corp. */
{ 0x04b8, 0x0101 },  /* Perfection 636U and 636Photo */
{ 0x04b8, 0x0103 },  /* Perfection 610 */
{ 0x04b8, 0x010c },  /* Perfection 640U */
{ 0x04b8, 0x0104 },  /* Perfection 1200U and 1200Photo */
```

Next, navigate to the /usr/src/linux directory and rebuild your system's kernel modules, like this:

```
# make modules
```
