## Customizing an X Session

When you use Linux and X11, you will enjoy the use of a free operating system and a free graphical interface to that operating system. You will also enjoy the freedom to change and use a desktop that looks and feels the way you want it to. You are not bound to what a commercial software vendor thinks. Of course, this freedom comes at a price when you use X11: You will need to learn how to edit a few configuration files or use a few commands in order to effect your changes.

This section introduces you to a few important files that can affect what window manager you choose for your X session and which clients are started after you launch X. You will also learn how to change the appearance of those clients.

### Using the .xinitrc File

The `.xinitrc` file is an X startup script that may or may not be present in your home directory. You will always find a default system-wide `xinitrc` file, usually under the `/usr/X11R6/lib/X11/xinit` directory, a symbolic link to the `/etc/X11/xinit` directory. Although there are standard uses for this file, different Linux distributions will use this file in various ways.

`xinitrc` is a shell script used by the X Window System initializer client `xinit` to start X. The `xinit` client (which is generally launched by the `startx` script if an X display manager is not used on the system) will look for `.xinitrc` in your home directory, and if not found, will use the system default file `xinitrc`. If that file is not found, `xinit` is supposed to launch the X session without using a window manager, and provide a single `xterm` terminal window in the upper-left corner of your display.

As shell scripts, the system `xinitrc` file and the optional user's `.xinitrc` file should contain logic to first determine the availability of various clients, such as individual programs or window managers, read in any specific custom settings, and then launch the clients or windows managers for the X session. For example, on a SuSE PPC Linux system, a default `.xinitrc` file is installed in every user's home directory. In part, the logic in the file looks like:

```bash
... 
# choose a window manager

if test -n "$WINDOWMANAGER" ; then
    WINDOWMANAGER=`type -p $WINDOWMANAGER`
fi
if test -z "$WINDOWMANAGER" ; then
    if test -x /usr/X11R6/bin/kde ; then
        WINDOWMANAGER=/usr/X11R6/bin/kde
    elif test -x /usr/X11R6/bin/startkde ; then
        WINDOWMANAGER=/usr/X11R6/bin/startkde
    elif test -x /usr/X11R6/bin/fvwm2 ; then
        WINDOWMANAGER=/usr/X11R6/bin/fvwm2
    elif test -x /usr/X11R6/bin/wmlist ; then
        for i in '/usr/X11R6/bin/wmlist' ; do
            WINDOWMANAGER=`type -p $i`
            test -n "$WINDOWMANAGER" && break
        done
    fi
fi
...
```

In this example, the script checks for a designated window manager in the WINDOWMANAGER environment variable, and checks to see if its name is present in the system-wide list of window managers stored under the /usr/X11R6/bin directory. Other distributions, such as LinuxPPC 2000 Q4 may use a different scheme, such as using a script named xclients under the /etc/X11/xinit directory to parse the contents of the /etc/sysconfig/desktop file for a default window manager. This latter approach is used by a number of Red Hat-based Linux distributions, and the logic looks like this:

```bash
...
# check to see if the user has a preferred desktop
PREFERRED=
if [ -f /etc/sysconfig/desktop ]; then
    if [ -n "`grep -i Gnome /etc/sysconfig/desktop`" ]; then
        PREFERRED=gnome-session
    elif [ -n "`grep -i KDE /etc/sysconfig/desktop`" ]; then
        PREFERRED=startkde
    elif [ -n "`grep -i AnotherLevel /etc/sysconfig/desktop`" ]; then
        PREFERRED=AnotherLevel
    else
        PREFERRED=Default
    fi
fi
...
```

Here you can see that the window manager used for the X session is determined by the keywords Gnome, KDE, or AnotherLevel in the file named desktop under the `/etc/sysconfig` directory. Other distributions provide different mechanisms for choosing a window manager to be used for an X session. For example, the startx script provided by SuSE PPC Linux allows you to specify a window manager on the command line like this:

```bash
$ startx twm
```

After you press Enter, the Twm window manager will be used for the X session. But you can override any of these previous methods by defining your own X startup script in `.xinitrc` in your home directory. You are free to choose your own window manager by crafting your own `.xinitrc` file. For example, if you would prefer to set the root display to a light blue, then launch an xterm terminal client using the LessTif mwm window manager, and create an `.xinitrc` file containing these lines:

```bash
xsetroot -solid lightblue
xterm &
mwm
```

Save the file and then start an X session. Your new `.xinitrc` file will override any system defaults. This approach will work with any Linux distribution. Note that you may also want to make sure that any custom settings are read in before starting your session. Read on to learn how to do this.

### Using .Xdefaults

The `.Xdefaults` file contains what are known as X client resources, or strings of text that define default appearance and behavior for various X clients. The `.Xdefaults` file is normally installed in every user's home directory from a default file found under `/etc/skel`.

If you do not find a `.Xdefaults` file on your system, such as LinuxPPC 2000 Q4, do not worry. Every Linux distribution that uses X also installs a large repository of client settings in individual files under the `/usr/X11R6/lib/X11/app-defaults` directory.

![](img/1ea833f5a3e3c1547e3dd2891f52804a_189_0.png)

> Other resource files may be present on your system, such as a default Xresources file. This file may be located under the `/etc/X11`, `/etc/X11/xinit`, or `/etc/X11/xdm` directories, and contains resources for use by the X display manager, xdm. You can also create a local copy in your home directory named `.Xresources` or `.Xres,` and you may store local resource settings in this file.
