# # Scheduling and Alarms

Running regularly scheduled tasks on a Linux system is usually accomplished by the `cron` daemon. In many cases, this is used by the system administrator to perform system maintenance, gather information, do security checks, and retrieve hard drive space by cleaning up the file system. Using the `crontab` editor to place schedules and alarms in what is normally intended as the Linux main scheduling system seems like a bit of overkill, and also requires root access.

Keep in mind that a tenant of conducting productive and efficient Linux sessions is to reduce or minimize the amount of time spent at root. There are other software avenues available to mortal system users for scheduling and alarms. This section introduces the standard appointment software included with every Linux system, called the `at` command family, and also discusses a simple graphical client for X that features appointment reminders and alarms.

# ## Using the at Command

The `at` command is designed to offer the Linux user a way to schedule one-time personal reminders. Included with the `at` command is a family of commands, such as `atq` (which shows a list of pending jobs), and `atrm` (used to remove a pending job). Whether or not the `at` command is active on your system depends on your Linux distribution or site administrator.

The `at` service depends on whether or not the `atd` daemon is running and if proper permissions are authorized for users in the `/etc/at.allow` or `/etc/at.deny` configuration files. Some administrators may not want to enable services for security reasons, or because another scheduling mechanism is available on the system.

As the root operator, you can quickly check the status of the `atd` daemon by using its initialization script with the `status` keyword like this (on a SuSE Linux system):

```
```
# /etc/rc.d/init.d/at status
Checking for service at daemon: OK
