### Scheduling and Alarms

Running regularly scheduled tasks on a Linux system is usually accomplished by the `cron` daemon. In many cases, this is used by the system administrator to perform system maintenance, gather information, do security checks, and retrieve hard drive space by cleaning up the file system. Using the `crontab` editor to place schedules and alarms in what is normally intended as the Linux main scheduling system seems like a bit of overkill, and also requires root access.

Keep in mind that a tenant of conducting productive and efficient Linux sessions is to reduce or minimize the amount of time spent at root. There are other software avenues available to mortal system users for scheduling and alarms. This section introduces the standard appointment software included with every Linux system, called the `at` command family, and also discusses a simple graphical client for X that features appointment reminders and alarms.

#### Using the at Command

The `at` command is designed to offer the Linux user a way to schedule one-time personal reminders. Included with the `at` command is a family of commands, such as `atq` (which shows a list of pending jobs), and `atrm` (used to remove a pending job). Whether or not the `at` command is active on your system depends on your Linux distribution or site administrator.

The `at` service depends on whether or not the `atd` daemon is running and if proper permissions are authorized for users in the `/etc/at.allow` or `/etc/at.deny` configuration files. Some administrators may not want to enable services for security reasons, or because another scheduling mechanism is available on the system.

As the root operator, you can quickly check the status of the `atd` daemon by using its initialization script with the `status` keyword like this (on a SuSE Linux system):

```
# /etc/rc.d/init.d/at status
Checking for service at daemon: OK
```

In this example, (and yes, on a SuSE 7.0 PPC system, the word “daemon” is misspelled), the script checks to see if the daemon is running, and then prints ok. If the service is not running, you can use the script again, but this time with the keyword start. On a LinuxPPC 2000 system, the name of the script is atd, so to start the service, use (as root) a command line like this:

```
# /etc/rc.d/init.d/atd start

Starting at daemon: [ OK ]
```

The script will start at services and report with an [ OK ] in brackets, and you can begin using the service immediately. Normally, one would use ntsv or yast2 on a SuSE Linux system, ntsysv or linuxconf on a Yellow Dog Linux system, and linuxconf on a LinuxPPC 2000 system. These control whether or not services start every time your system boots.

The at command is easy to use, and only requires a time and command entry. For example, at the command line type in a time (specified in hours and minutes), along with the at command, like this:

```
$ at 18:30

warning: commands will be executed using /bin/sh

at> kcalc -display cubie:0.0 &

at> <EOT>
```

In this example, the KDE calculator, kcalc, will be launched at 6:30 PM and appear on DISPLAY 0.0 on the host named cubie. The EOT marker is actually a Ctrl+D, which is used to close and save the at session. Time entries can take many forms such as:

- at now + 20 minutes
- at now + 3 hours
- at 2am tomorrow
- at midnight
- at teatime
- at 9pm Aug 3

The teatime entry specifies 4 PM. You will find more examples by reading the at manual page. In addition, you can create a text file containing a list of commands to run, and have the list executed at a specific time by using the at command’s -f option like this:

```
$ at -f myjoblist.txt 7am

warning: commands will be executed using /bin/sh

job 6 at 2001-03-11 07:00
```

If you have entered multiple at commands, you can view the list of entries by using the atq command like this:

```
$ atq
3     2001-03-10 13:50 a bball
4     2001-03-10 14:50 a bball
5     2001-03-11 00:00 a bball
```

To manage your queue of at jobs, use the atrm command, along with a job number to delete like this:

```
$ atrm 3
```

This example will remove job number 3 from the list of pending at jobs.

#### Scheduling with the rclock Client

The rclock client, originally by Rob Nation, which is usually included as part of the xvrt X11 terminal client software package, is more than just another X11 clock client. In its own right, rclock is a highly configurable clock that may be customized to fit nearly any X11 desktop. This clock recognizes many of the X11 Toolkit command-line options. You can use the -display option to send the clock to a remote computer, the -geometry option to create a clock with a specific size, and the -bg, -fg, and -fn options to specify a background, foreground, and font for the clock face. If you use the -update option with a value of 1, then a second hand appears on the clock’s face.

For example, to create a 100x100-pixel clock with blue hour, minute, and second hands on a yellow clock face at the upper-right corner of your display, use a rclock command line like this:

```
$ rclock -geometry 100x100+0-0 -fg blue -bg yellow -update 1 &
```

After you press Enter, you will see a clock, as shown in Figure 12.1.

More importantly, rclock may also be used in lieu of the biff or xbiff command. If you use the -mail option, rclock will check for any incoming mail at a preset interval, then flash its face when mail arrives.

The most important feature may be rclock’s scheduling and appointments alarm. Every 10 minutes, rclock will check a file named .rclockrc in your home directory. This file can contain regular, recurring notifications, or one-time only appointments. As an added bonus, rclock can also launch other applications at a specified time as part of the alarm or notification process!
