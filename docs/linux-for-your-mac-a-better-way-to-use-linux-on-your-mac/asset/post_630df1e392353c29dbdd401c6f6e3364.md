
Now that you have installed Linux on your Power Mac, you may want to perform some additional configuration, adjust settings, and begin exploring the Linux operating system. This chapter provides some additional tips and hints on modifying various settings and configuring your hardware.

Linux works well on nearly any hardware platform and CPU. Your job as system administrator is to get Linux working with all your system's hardware. For many users, just getting Linux installed is enough. Savvy Linux users will want to enable all their available hardware.

The biggest hurdles in installing and configuring Linux are:

- Partitioning the hard drive.
- Booting to the install.
- Navigating through the install.
- Configuring X11 for your computer's graphics card.
- Configuring Linux sound to work with your system's sound card.
- Configuring your modem and getting connected to the Internet.
- Setting up Linux to work with your printer.
- Getting Linux to work with other hardware devices, such as a scanner.

You have probably already accomplished at least three or four of these tasks!

## Taking Your First Steps with Linux

If you are the only person using your computer, then there are at least two users on your system: you, as a normal user; and the root operator, or system administrator. It is up to you to take care of your system, monitor its health, install new software, and configure new hardware.

## What Is root?

The root operator has a different home directory than normal users. Most users' directories reside under /home in a directory with the user's login name. For example, Fred Smith will usually be the user named “fsmith,” and will have a home directory of /home/fsmith. On the other hand, the root operator has a home directory of /root.

Linux is organized into a simple set of directories. A typical system will look like this:

```
/
├── bin
├── boot
├── dev
├── etc
├── home
├── lib
├── mnt
├── opt
├── proc
├── root
├── sbin
├── tmp
├── usr
└── var
```

The `/` directory is known as the root or base directory, while root's home directory is `/root`. The `/bin` directory holds binary files that generally do not depend on shared libraries or that may be used during maintenance mode. The `/dev` directory holds device names, such as `/dev/modem`, which point to your system's internal modem or serial port with an attached modem. The `/etc` directory contains the majority of configuration files used by Linux and its software. The `/lib` directory contains software libraries used by foreign programs in order to run. The `/mnt` directory is a traditional place to mount foreign file systems, such as hard drives on remote computers on your LAN (Local Area Networks). The `/opt` directory generally holds large, complex software distributions separate from the Linux software tree. The `/proc` directory contains locations of values derived from processes running in memory. The `/sbin` directory contains programs generally run only by the root operator. The `/tmp` directory is a scratchpad for programs, installation logs, files, and other temporary files accumulated during a typical desktop session.

There are several ways to work as the root operator. One way is to boot Linux, then log in like this:

```
Login:  root
Password:
```

However, this is not recommended! Logging in and using Linux as the root operator is fraught with risk and danger. As root, or the superuser, you can do anything to any file on your system, including the following:

```
# rm -rf /*
```

This command line wipes out your entire Linux directory tree and any remote mounted drives, including mounted Mac OS HFS partitions! A much better way to work as root is to use the *su* command, which allows you to log in and become any user for a temporary time (in order to accomplish a specific task). This is much safer and will avoid the heartache of having to reinstall or rebuild a system. Linux works on the concept of user, group, and world permissions for reading, writing, and execution. You will learn more about permissions later on in this book. Suffice it to say that as root, you have permission to do anything.

The best approach to assuming root status is to log in with your normal username and password. Then, when you need to work as root, use the *su* command to accomplish a specific task, like this:

```
$ su -c "pico -w /etc/inittab"
Password:
```

In this example, the *pico* text editor is launched and opens the system's initialization table for editing. After you edit the file and close the application, you will be returned to your normal status. For more lengthy forays as root, you can also use *su*, like this:

```
$ su
Password:
#
```

Note how your command line or shell prompt changes after you use the *su* command. You are now working as the root operator. To quit working as root, use the shell's built-in *exit* command, like this:

```
# exit
$
```

As you can see, you will then return to your normal user status. You need to know how to work as root, especially after installing Linux on a new computer. You will use your accumulated Linux skills and knowledge to help overcome any problems or obstacles in configuring Linux to get the most out of your machine. Use your root status only when needed, and you will never get into trouble.

## Post-Installation Software Tools

Every Linux distribution is both similar and different. Different distributions from different vendors may use the same version of the Linux *kernel*, or core operating system, but the location of important configuration files, and the tools used to configure Linux may be different.

If you use LinuxPPC 2000 Q4 or Yellow Dog Linux, you are using a Linux distribution based on Red Hat, Inc.'s Intel version of Linux. If you use SuSE Linux PPC, you will be using a unique but proven brand of Linux. If you use Debian PPC Linux at this point, you are a true hacker and a budding high priest of the GNU generation.

Many tasks covered in this chapter require root permission. While some tasks are universal, and apply to all Linux distributions, this book concentrates on using Red Hat-based Linux distributions for the PowerPC or SuSE Linux PPC on Power Macs.

## Configuring X

Chances are very good that the installation software included with your PPC Linux distribution has successfully configured the X Window System to work with your system. However, if you need to make changes or reconfigure X to get a bit better performance, make sure to read Chapter 7, "X11 and Window Managers." That chapter’s section "Configuring X11" is chock full of details about using at least three different software configuration tools to get X working optimally with your computer.

Configuring X involves creating an accurate configuration file named *XF86Config*. This file is simply a text file containing directions for a software program called a *server*. When you use Linux without a graphical interface, you are using Linux in a text-based, or *console* mode. But when you use a graphical interface with Linux, you will use the X Window System and its server named *xfsess*.

X works very well with Apple’s Power Mac hardware. No major problems have been reported in getting X to work correctly on any model in the currently supported Power Mac model lines. This means that if you have an iBook, TiBook, or Apple G4 Cube, you can expect to configure a working graphical interface for Linux using X. If you do have problems, then check with your Linux distribution’s vendor for up-dates, errata, or bug fixes. You are sure to find an answer for any problem related to X.

## Keyboard and Mouse Issues

When you use Linux in the *console* mode, mouse support is provided by the general-purpose mouse driver, *gpm*. This is a *daemon*, or program that runs in the background while you use Linux, and gives support for highlighting, copying, and pasting of information. When you use X during an X session, your mouse cursor is known as a *pointer*, and is supported by the XFree86 server.
