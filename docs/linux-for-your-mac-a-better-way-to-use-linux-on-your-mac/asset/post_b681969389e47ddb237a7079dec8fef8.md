## Configuring PPP Scripts

You do not have to resort to fancy graphical connection programs in order to connect to the Internet. Savvy Linux dialup users build connection scripts using available commands installed with every Linux distribution. These commands include:

- **chat**: Used for establishing the link through the serial port and negotiating with the remote computer.
- **pppd**: This is the PPP daemon, responsible for handling transmission of information via an in-memory interface created during the connection process.
- **bash**: This command, or any other Linux shell, is used to make the scripts run.

## Connecting Manually

To connect manually, use Al Longyear's *ppp-on* and *ppp-on-dialer* scripts. These scripts are generally included in a sample directory in the pppd daemon's documentation directory (such as */usr/share/doc/pppd* or */usr/share/doc/packages/pppd*). Edit these scripts as the root operator to customize them for your system and ISP.

The scripts should be copied to the */etc/ppp* directory and then edited. The first script, *ppp-on*, is used to start the connection. It looks, in part, like this:

```
# These are the parameters. Change as needed.
TELEPHONE=2025551212		# The telephone number for the connection
ACCOUNT=yourname		# The account name for login (as in 'George Burns')
PASSWORD=mypassword	# The password for this account (and 'Gracie Allen')
LOCAL_IP=0.0.0.0        # Local IP address if known. Dynamic = 0.0.0.0
REMOTE_IP=0.0.0.0       # Remote IP address if desired. Normally 0.0.0.0
NETMASK=255.255.255.0  # The proper netmask if needed
#
...
```

In this example, the script has been edited to add the telephone number of the remote ISP, along with the username and password assigned by the ISP. The only other change that you might want to make is the default modem speed, detailed later on in the file. This portion of the script looks like this:

```
exec /usr/sbin/pppd lock modem crtscts /dev/modem 115200 \
asyncmap 20a0000 escape FF $LOCAL_IP:$REMOTE_IP \
noipdefault netmask $NETMASK defaultroute connect \
$DIALER_SCRIPT &
```

In this example, the default speed for the modem (located on /dev/modem) is set to 115200. Make any desired change and save the file. You can then create a PPP connection (as root) to your remote ISP by using the ppp-on script, like this:

```
# /etc/ppp/ppp-on
```

## Configuring the kppp Client

If you use the K Desktop Environment for your X sessions, you will want to set up the *kppp* client to do the dialing for you. This section includes instructions on how to set up a simple PPP connection. In only a few steps you will be able to configure your system to dial out and connect to your ISP. The *kppp* client is a mature, stable, and robust dialer that has been in use for several years by KDE fans. If you use KDE, you will certainly love *kppp*!

Start the client from the desktop panel menu or the command line of an X terminal, like this:

```
$ kppp &
```

After you press Enter, you will see a small dialog box. To set up your connection, click the Setup button. You will then see an Account setup dialog box. Click the New button to begin, and you will be asked if you want to use *kppp*'s Wizard setup. Do not choose the Wizard setup unless you live outside the United States, as the configuration is for foreign countries. Instead, click the Dial Setup button, and you will see a dialog box as shown in Figure 9.2.

Click in the Connection field and give the account a name. Next, click the Add button and type in a phone number that will connect you to your remote ISP.

![](img/1ea833f5a3e3c1547e3dd2891f52804a_213_0.png)

*Figure 9.2 Start configuring your dial-up account with kppp by entering a name and phone number.*

If your connection requires a special login sequence, click the drop-down Authentication menu and choose a script-based or terminal-based login. Most modern ISPs will use the PAP (*Password Authentication Protocol*), though some may use the CHAP (*Challenge Handshake Authentication Protocol*). These protocols are used to negotiate and verify remote logins that wish to start a PPP session.

Next, click the IP tab in the dialog box, and you will see a dialog box, as shown in Figure 9.3, that asks if you will use a dynamic or static IP assignment for the connection.

![](img/1ea833f5a3e3c1547e3dd2891f52804a_213_1.png)

*Figure 9.3 Choose a dynamic or static IP assignment.*

If you use a static IP address, enter it here. Most likely your ISP will dynamically assign your IP address. However, this is a handy setting to use, especially if you have configured your system to allow dial-up users and have assigned static IPs. See Chapter 15, “Managing Services,” to see how to do this. When finished, click the DNS tab, and you will see a dialog box as shown in Figure 9.4.

Chances are good that your ISP also provides DNS service. This is almost mandatory, especially with larger service providers. Click in the DNS IP Address field, type in the IP number, and then click the Add button when finished. kppp will save these settings, and when you attempt a connection, it will temporarily place these settings in your system's /etc/resolv.conf file.

When you have finished, click the OK button to save your settings. You will return to the Account Setup dialog box. To check your modem speed settings, click the Device tab, and you will see a dialog box, as shown in Figure 9.5.

Although few ISPs charge per-minute rates these days, most Linux users want the fastest available connection. Check your device settings to use the fastest speed supported by your modem. When finished, click the OK button. You will then be at kppp's main window, as shown in Figure 9.6.

> Even though the iBook and TiBook have 56K modems, you can try setting the speed to 115200 in the Device dialog box to see if you can get a slightly faster connection. Also, explore the Misc tab for options such as docking the kppp icon into the desktop's panel upon connection (which then shows a miniature modem with blinking red and green lights).

Make sure that your new service is selected in the drop-down menu, and then type in your username and password (assigned by your ISP, and not for Linux). Click the Show Log Window check box to watch the dialing progress. To connect, click the Connect button. You will see the dialing and negotiation in a new window, as shown in Figure 9.7.

After kppp connects and your username and password have been authenticated, a connection dialog box will minimize and dock in your desktop’s panel.

## Using Red Hat’s Dialup Command

If you use a Red Hat-based PPC Linux distribution, you can use Red Hat’s dialup configuration and connection tools to create accounts and get connected. The main components of the package are the ppp-config client and the ppp-setup connection tool. These graphical configuration tools will quickly and easily lead you through the steps to getting on the Internet.

```
# ppp-config &
```
