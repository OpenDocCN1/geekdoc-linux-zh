
## Using the `rpm` Command

The `rpm` command has an interesting lineage. Early Linux distributions use utilities such as `rp`, `pm`, and `pm` to handle software management, but all lacked features such as cross-platform compatibility, speed, and stability. The first version of `rpm` was developed in Perl, but all subsequent versions are coded in the C programming language. The version most often used on today's PowerPC Linux distributions is 3.0.4 or 3.0.6, although the current release is version 4.0.

From a system administrator's viewpoint, the `rpm` command provides the ability to install, verify, remove, or upgrade packages. The `rpm` command also has the ability to run other programs or internal scripts during the installation process. This has prompted security concerns for some users. In response, `rpm` now has the ability to include electronic signatures to ensure author authenticity.

Using `rpm`, you can view the contents of a package before it is installed, view a list of installed packages, verify a package is installed, and remove an installed package. These tasks are accomplished by using `rpm`'s `-q` (query option), `-i` (install option), `-u` (upgrade option), and `-e` (erase option).

For example, to view the contents of a package, use `rpm` and its `-q` option along with the `p` and `i` options (to list package contents) like this:

```bash
$ rpm -qpil xmms-1.2.4-1.rpm
/etc/X11/appdefaults/Multimedia/xmms.desktop
/etc/X11/wnconfig/xmms
/usr/bin/wxmms
/usr/bin/xmms
/usr/doc/xmms-1.2.4
/usr/doc/xmms-1.2.4/AUTHORS
/usr/doc/xmms-1.2.4/COPYING
/usr/doc/xmms-1.2.4/ChangeLog
/usr/doc/xmms-1.2.4/INSTALL
/usr/doc/xmms-1.2.4/NEWS
/usr/doc/xmms-1.2.4/README
/usr/lib/libxmms.so.1
/usr/lib/libxmms.so.1.0.0
/usr/lib/xmms/Effect/libecho.la
/usr/lib/xmms/Effect/libecho.so
/usr/lib/xmms/Effect/libstereo.la
...
```

Note that not all the contents are listed here. To get a summary of the package information, use the `i` (information) option like this:

```bash
$ rpm -qpi xmms-1.2.4-1.ppc.rpm
Name : xmms
Release : 1
Group : Applications/Multimedia
Size : 3482639
URL : http://www.xmms.org/
Summary : XMMS - Multimedia Player for the X Window System.
Description :
X MultiMedia System is a sound player written from scratch. Since it
uses the WinAmp GUI, it can use WinAmp skins. It can play mp3s, mods, s3me,
and other formats. It now has support for input, output, general, and
visualization plugins.
Relocations: (not relocatable)
Vendor: XMMS Development Team
Build Date: Tue Dec 26 09:34:03 2000
Build Host: ipa
Source RPM: xmms-1.2.4-1.src.rpm
License: GPL
```

To install a package, use the `-i` option. To see the progress of the installation, add the `v` (verbose) and `h` (hash marks) options like this:

```bash
# rpm -ivh wmbatppc-0.2-1.ppc.rpm
wmbatppc ########################################################
```

> **TIP**
>
> To see a long list of exactly what is going on during the installation, use two `-v`s on the installation command line.

A problem can arise during installation (or removal) if all the necessary components needed to support a package are not already installed. This is called a dependency error. This error will most often occur if a software library is missing during an attempted install or if removing a module would render an already installed software package unusable. This is one of `rpm`'s greatest features, but also a source of frustration, especially if, in the course of upgrading a package, you find that many other packages must be installed first.

After a package is installed, you can verify the installation by using the `-q` option, along with one or more `v` options like this:

```bash
# rpm -qv wmbatppc
wmbatppc-0.2-1
```

In this example, the `rpm` command responds with the package name, which verifies that it is resident on your system. To upgrade an installed package, use the `-u` option like this:

```bash
# rpm -Uvh packagename
```

New software or documentation components will be installed and will possibly overwrite parts of the existing package. To erase an installed package, use the `-e` option like this:

```bash
# rpm -e wm2tppc
```

>
> To see a long list of exactly what's going on during the removal, use two `-v`s on the erase command line.

## Using Graphical RPM Tools

You can use many graphical RPM clients during your X sessions with Linux. Of course, SuSE Linux users will want to (and perhaps should) use the `yast` command to install and remove software. Any PowerPC Linux user (as the root operator) can use these graphical tools to browse through installed software and perhaps manage Linux software.

### Using gnomrpm

If you use GNOME during your X sessions, you will find the `gnomrpm` client to be a handy graphical interface to the `rpm` command. This client provides dialog boxes, buttons, menus, and icons you can use when administering software on your system. You must run the client as the root operator.

Start `gnomrpm` (as root) by typing its name on the command line of an X11 terminal window like this:

```bash
# gnomrpm &
```

After you press Enter, it will start up, then read your system's RPM database (usually found under the `/var/lib/rpm` directory), and display a window as shown in Figure 14.13.

Your system's installed software will be displayed in a hierarchical list along the left side of the window. Click on a group of packages to see the applications or software installed in the group. Icons of packages will appear in the right window.

![](img/1ea833f5a3e3c1547e3dd2891f52804a_365_0.png)

*Figure 14.13 The `gnomrpm` client can be used to manage software on a RPM-based PowerPC Linux system.*

You can then install, query, verify, or uninstall packages by using `gnomrpm`'s toolbar buttons. To install a package, click the Install button (or use the Operations menu's Install menu item to select a package to install).

### Using kpackage

The `kpackage` client is the handy graphical interface to the `rpm` command when using KDE. Like `gnomrpm`, this client provides dialog boxes, buttons, menus, and icons you can use when administering software on your system. Again, you must run the client as the root operator.

Start `kpackage` (as root) by using the desktop panel's Utilities menu (Package Manager), or by typing `kpackage` on the command line of an X11 terminal window like this:

```bash
# kpackage &
```

After you press Enter, the client will start, query your system's RPM database (usually found under the `/var/lib/rpm` directory), and display a window as shown in Figure 14.14.

Your system's installed software will be displayed in a hierarchical list along the left side of the window. Click on a group of packages, and the associated applications and software installed in the group will be displayed. A vertical navigation toolbar is embedded in the window frame on the left side. Click on a package, and its information will be shown on the right side of the window. As with `gnomrpm`, you can then install, query, verify, or uninstall packages by clicking appropriate buttons in the window.

## Working As Root

Every Linux system should, at a minimum, have at least two users: the root operator, more of a functional user than a regular user; and a traditional, or regular user with restricted permissions (The only exception might be for using Linux on an embedded device).

Working as root operator is potentially dangerous, because you have permission to do anything to the system. This includes running commands such as:

```bash
$ rm -rf /*
```

This handy command will not only wipe out your entire Linux filesystem, but also any remote filesystems that are currently mounted. Every user should at least use the following alias, or command shortcut for the rm command:

```bash
alias rm='rm -i'
```

This alias definition, which can be placed in a user's `.bashrc` file, or applied system-wide in `/etc/profile` or `/etc/profile.local`, can at least protect against accidental deletion of files. It will not, however, protect against the wholesale slaughter of the `rm -rf` option.

Fortunately, many GNOME and KDE clients (and other administrative tools such as `yast2`) will recognize when root access is needed and will prompt for a password.
