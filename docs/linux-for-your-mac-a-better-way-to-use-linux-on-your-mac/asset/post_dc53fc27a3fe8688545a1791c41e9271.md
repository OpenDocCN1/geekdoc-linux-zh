
## Administering Users

This means that you can conduct business on your system without having to log in as the root operator. The idea is that root permission should only be used for a specific task during regular sessions.

Use the `su` command to temporarily grant root operator permission. This command is handy, for example, if you would like to make a quick edit to a restricted system file, such as `/etc/inittab`. Use the `su` command, along with its `-c` (command) option like this:

```bash
$ su -c "pico -w /etc/inittab"
Password:
```

After you press Enter, you will be prompted for the root operator’s password. When the command you request (delineated by quote marks) exits, you will be returned to your normal user prompt. Another command found with many Linux distributions is `sudo`, which allows execution of commands as root or another user, according to a configuration file, `/etc/sudoers`. For details, see the `sudo` manual page.

This section introduces a number of commands, clients, and tools you can use to perform user administration. The process of maintaining user accounts is a valuable service, especially at large computer installations or on systems that support many users. Properly administering users involves more than just creating and deleting accounts, but can also involve additional security considerations such as directory and file permissions, password expiration schemes, and quotas to reserve or limit CPU and storage resources.

These tasks are trivial when maintaining a small system, and can seem overwhelming at a large installation. But the initial considerations and policies implemented and enforced by the system administrator may be the same on either platform, and demand the same attention.

### Creating and Deleting Users

The basics of administering users involve creating and deleting user accounts. Traditionally, Linux users are assigned a username consisting of the first letter of a person’s name followed by the person’s last name (i.e., Deborah Cohen would become the user known as `dcohen`).

System administrators of Red Hat-based Linux systems can use the `linuxconf` command to create users. Under the configuration menu, click the Users accounts,

Fill in the blank fields, then click the Add button. This is one way of creating a user account. Another way is to use the `useradd` (or `adduser`) commands. Under LinuxPPC 2000, the `adduser` command is a symbolic link to `useradd`. Under SuSE Linux, there is only the `useradd` command. Use this command (as root), followed by the name of a new user like this:

```bash
# useradd fsmith
```

This will create an entry for Fred Smith in the system's `/etc/passwd` file, along with a home directory named `/home/fsmith`. The `/etc/passwd` file contains a list of your system's users, along with various information in different colon-delimited fields. Next, assign a password using the `passwd` command, like this:

```bash
# passwd fsmith
Changing password for user fsmith
New UNIX password:
Retype new UNIX password:
passwd: all authentication tokens updated successfully
```

The entry for `fsmith` in `/etc/passwd` could look like this:

```text
fsmith:x:502:100::/home/fsmith:/bin/bash
```

In this example, `fsmith` has a user ID of 502 and is assigned a group ID of 100. The home directory is `/home/fsmith`, and the default login shell is `bash`. To add more information to the account, you can (as root or as the user) use the `chfn` command. This information may be useful for accounting purposes, reports, security, or may be used by the `finger` command. The `chfn` command will add additional information to the `/etc/passwd` entry. For example:

```bash
# chfn -f "Fred Smith" -r 2508 -w "555-1212" -h "555-1212" fsmith
```

In this example, the root operator has updated the user's full name, office number, and work and home phone information. A peek at the resulting `/etc/passwd` entry may look like:

```text
fsmith:x:502:100:Fred Smith,2508,555-1212,555-1212:/home/fsmith:/bin/bash
```

> **TIP**
> Different `/etc/passwd` entry structure and `chfn` information exists between Linux distributions. While SuSE's `chfn` uses `-f`, `-r`, `-w`, `-h`, and `-o` (for other information), LinuxPPC 2000's `chfn` uses `-f`, `-o` (for office), `-p` (for office-phone), and `-h`.

Linux comes with a number of user-oriented commands and programs. Many common programs included with Red Hat-based and SuSE Linux PowerPC Linux distributions are listed in Table 14.1.

Removing a user can be accomplished by using a variety of commands, such as `userdel` (or even manually). To remove a user with `userdel`, include its `-r` option (to remove the user's home directory), followed by the user's login, like this:

```bash
# userdel -r fsmith
```

After you press Enter, *fsmith's* entry in the system's `/etc/passwd` file will be removed, and the entire contents of `/home/fsmith` will be erased.

### Setting Login Defaults

As you have already seen, you can set the default login shell for a user by editing the `/etc/passwd` entry. Users can also switch shells by using the `chsh` command like this:

```bash
$ chsh
Password:
Changing the login shell for bwall
Enter the new value, or press return for the default
Login Shell [/bin/bash]:
```

However, it is important that the new shell actually exist on the system, and that the shell is listed as an approved system shell in the `/etc/shells` file. As the system administrator, you can also restrict users to a particular program like this:

```text
luser:x:501:100::/home/luser:/usr/bin/emacs
```

After logging in, the user named `luser` will be immediately launched to the `emacs` editing session. Other defaults for newly created users may be set by editing files in the `/etc/skel` directory. This directory contains the default contents of a new user’s home directory. Under SuSE Linux, if you just perform a simple `ls` command, you may think the directory is empty. However, if you use the `-af` option to list all files, you will see:

```bash
# ls -af /etc/skel
.dvipsrc    .lyxrc      .utrc.console   .xim
..          .emacs      .muttrc         .utrc.vt100
.Xdefaults  .exrc       .nc_keys        .utrc.vt102
```

### Editing PATH

The **PATH** shell environment variable presents the pathnames of your system’s executable files to a user. You can quickly see your current **PATH** definitions by using the `printenv` or `env` command, along with the `fgrep` command like this:

```bash
$ env | fgrep PATH
...
PATH=/usr/local/bin:/usr/bin:/usr/X11R6/bin:/bin:/usr/lib/java/bin:/usr/games/bin:/usrX/games:/opt/gnome/bin:/opt/kde/bin:/usr/openwin/bin:.
```

Note that not all the **PATH** definitions are shown here. You may have one or more additional environment variables that define a particular **PATH** (such as the **MANPATH** variable, which points to various manual page directories on your system).

Commands on a Linux system are generally organized into directories according to use. For example, traditional user paths include `/bin`, `/usr/bin`, `/usr/local/bin`, `/usr/X11R6/bin`, and perhaps even `bin` in the home directory. Paths for the root operator usually include `/sbin`, `/usr/sbin`, and perhaps even `/usr/local/sbin`. Other paths may be defined and added to a user’s environment. This is especially helpful if software is installed elsewhere on your system, such as the `/opt` directory, a default location for software packages, or office suites such as Applixware or StarOffice.
