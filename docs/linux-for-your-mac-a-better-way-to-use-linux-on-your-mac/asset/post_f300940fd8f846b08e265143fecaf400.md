
approach is quite flexible, graphics drawing is not as fast as using software that talks directly to your graphics hardware.

Newer graphics hardware in G4 Power Macs, such as the ATI Rage video chips, is supported by XFree86 4.0.1 and its xfree86 server. This server uses loadable code modules for support of specific graphics hardware. Older Power Macs will probably use a frame-buffer server, such as XF86_FDV or included with XFree86 3.3.6. Some PowerPC computers may be able to use either one.

## Whoops! Am I Being Too Helpful?

One potential problem is that both LinuxPPC 2000 Q4 and SuSE Linux include automatic X configuration utilities that can be set up to generate a new configuration file every time Linux is booted. This is OK if that is what you want, but if the automatically generated configuration file does not work, and you have set Linux to boot directly to an X session, you will not be able to log in. Instead, the X server will repeatedly attempt to start, then fail, then attempt to start again in an endless loop. Your best resort is to reboot Linux in single user mode, or to a runlevel where X is not active, then disable automatic configuration, and attempt a proper configuration. With SuSE Linux, the potentially troublesome automatic X configuration is started through the /sbin/init.d/xsfb script (and can be controlled by editing /etc/rc.conf's `CREATE_FBCONF=""` setting), while under LinuxPPC 2000 Q4, the `xautoconf` service is used (and can be controlled by) the `ntsysv` command. These services can be helpful if you change video cards in your computer, but can cause trouble if your system requires a custom configuration.

There are a number of ways to configure X to work with your system. One method is through the auto probing of your graphics hardware. Another method is to use a console-based configuration program. Choosing an X configuration tool is generally a matter of personal preference or the choice of tools included with a distribution. Each tool aims to create a working XFree86 configuration file using the highest resolution (width and height of screen in pixels) and the greatest color depth (or number of colors available for the session). These values are generally expressed as 1600x1200 and 16bpp (*bit-planes per pixel*). Common resolutions are 1280x1024, 1152x768 (for the TiBook), 1024x768, 800x600, and 640x480. Common color depths are 8bpp (256 colors), 16bpp (thousands of colors), 24bpp (millions of colors), and possibly 32bpp (millions of colors).

![](img/1ea833f5a3e3c1547e3dd2891f52804a_161_0.png)

Yet another way to configure X is to boot Linux using proper base video values, and then use a graphical configuration client that starts a "safe" X session. These video values are kernel arguments passed to the Linux kernel by BootX or yaBoot, and generally take the form:

```
video=adapter:vmode:XX,cmode:XX
```

The `adapter` keyword (such as `ayfb`) denotes the type of graphics chipset used. The `vmode` setting is a one- or two-digit value (in the range of 1-20) that corresponds to a resolution. The `cmode` setting is a one- or two-digit value (8, 15, 16, 24, or 32) that corresponds to a color depth. These video settings may also be accomplished after Linux boots by using the `fbset` command.

You can also use XFree86 version 4.0's (or newer) X server to configure settings. And if all else fails, you can manually create your own configuration file (because it is a text file).

> It is generally not a good idea to use someone else's `XF86Config` file unless you use it for a matching video card and monitor combination. iBook and PowerBook users can share configuration files between same model notebooks.

![](img/1ea833f5a3e3c1547e3dd2891f52804a_162_0.png)

If you craft your own `XF86Config` file, there is a template file named `XF86Config.eg` located under the `/usr/X11R6/lib/X11` directory (you can read the sample for example entries). Manually creating your own `XF86Config` file can be challenging if you are new to X!

## Using the xf86config Command

The `xf86config` command is a text-based console application included with XFree86 and every Linux distribution. It can be used to configure a working `XF86Config` file. This command is a menu-driven program that uses various databases of monitors and video cards, which are installed under the `/usr/X11R6/lib/X11` directory to provide choices during the configuration process. You must be the root operator in order to configure X to work with your system. Start the `xf86config` command like this:

```
# xf86config
```

After you press Enter, you will start answering questions to configure X. You will be asked about your pointing device (mouse), keyboard, monitor, video card, desired color depth, and desired resolution. Be sure to have your equipment's manuals on hand, along with technical specifications for your graphics hardware, pointing device, and monitor.

Most seasoned X11 users use a three-button mouse for their X sessions. The mouse buttons are referred to as left, middle, and right (or 1, 2, and 3). They are used for selecting, clicking, highlighting, pasting, and special actions. PowerPC Linux users with only a one-button mouse (such as iBook or TiBook users) must remap two Fkeys to simulate the middle and right mouse buttons. This can be done for ADB pointing devices by passing kernel arguments before Linux boots, or in the case of a USB mouse, by echoing certain values to the system's USB device process directory. For example, Yellow Dog Linux iBook users can use the kernel argument (passed via BootX or yaboot.conf), ADB buttons=103, 111, which maps F11 and F12 to the middle and right mouse buttons. Linux PPC 2000 Q4 maps Fn+Ctrl and Fn+Option to the middle and right mouse buttons. PowerPC Linux users with a USB keyboard can use:

```
echo "1" > /proc/sys/dev/mac_hid/mouse_button_emulation
echo "87" > /proc/sys/dev/mac_hid/mouse_button2_keycode #F11
echo "88" > /proc/sys/dev/mac_hid/mouse_button3_keycode #F12
```

These lines map F11 and F12 to the middle and right mouse buttons. TiBook users can change the values 87 to 68 and 87, because F12 alone is a Mac OS media eject key and cannot be used for emulation. In this case, F12 and F11 are mapped as the middle and right mouse buttons—much better alternative than using Fn+Ctrl or Fn+Option, because these keys are needed to halt or escape a currently running X session!

When you have finished configuring X, a new XF86Config will be written by default in the /etc/X11 directory. You can, however, choose to have the file saved anywhere.

## Using Xconfigurator

LinuxPPC 2000 Q4 and Yellow Dog Linux include the Xconfigurator command, which can be used with or without X11 to create a working XF86Config file. This command provides a graphical, menu-driven interface for configuring X on your system. Again, you must be the root operator in order to configure X for your system. Start the Xconfigurator command like this:

```
# Xconfigurator
```

After you press Enter, you will see its initial dialog box, as shown in Figure 7.1. Use the Tab key to navigate through dialog box buttons, the Up and Down cursors to scroll, and the spacebar to select or unselect menu items. When you have finished using the program, a new XF86Config will be saved in the /etc/X11 directory (This is the same as the xf86config command).

## Using sax and Sax2

SuSE Linux provides two graphical X configuration tools named `sax` and `sax2`. These tools, like those previously discussed, provide an interface for configuring a working *XF86Config* file. The `sax` command is for configuring version 3.3.6 of XFree86 while the `sax2` command is used for configuring XFree86 4.0 and above. For example, to use the *sax2* client, type its name on the command line of an X terminal window like this:

# sax2
