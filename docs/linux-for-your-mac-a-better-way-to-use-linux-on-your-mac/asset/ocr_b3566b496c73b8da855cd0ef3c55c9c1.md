# # On the Horizon

By the time you read this, many Linux distributions may incorporate a new form of filesystem for use during Linux sessions. One of the most requested features from vendors and corporate Linux users is for a new type of filesystem for Linux that can be checked quickly and easily and is a lot faster than using *fsck*.

The fact is that the current *ext2* filesystem has proven to be stable, robust, and now in common use across many platforms. What users desire is a new form of filesystem that provides small-file efficiency, the ability to handle directories containing hundreds of thousands of files, and one that can recover quickly following catastrophic disk or system failure. The need for a new filesystem for Linux becomes apparent when it can take several hours just to format required system media (perhaps nearing one or more terabytes). Running *fsck* on such a system could take half a day just to reboot!

One of the proposed solutions is *ext3*, which is a proposed modification of *ext2*. It is intended to add journaling, or the ability to continually snapshot the filesystem and recover quickly. Another possible solution (available for 2.4-series Linux kernels) is SGI's *xfs* filesystem, which provides a high-performance journaling filesystem that purportedly provides, according to SGI, “Sub-second filesystem recovery after crashes or power failures,” and support for “millions of terabytes, millions of files, and a million files per directory.”

Another solution that has already appeared and is available for the 2.2.19 Linux kernel is *ReiserFS*, which provides journaling and no use for *fsck* upon rebooting after a power outage.
