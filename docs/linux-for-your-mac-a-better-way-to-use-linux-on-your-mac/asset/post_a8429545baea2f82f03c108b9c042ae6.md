## Emulating Mouse Buttons

If your Power Mac has a mouse with only one button (as most do), you may consider getting a three-button mouse. Linux and X are designed to support and use three-button rodents. This does not mean that you cannot use Linux and X productively using a single-button mouse, but life will be a bit easier if your mouse has at least two buttons.

If you have installed Linux on an iBook and want three-button emulation, you can pass a command string known as an argument to the Linux kernel at boot time. For example, the following setting in your `yaboot.conf` file enables F11 and F12 as the middle and right mouse buttons:

```
append="adb,buttons=103,111"
```

If you use SuSE Linux PPC and have a one-button USB mouse (included on newer desktop Power Macs), the following commands sent to the Linux kernel USB driver enables F11 and F12 as the middle and right mouse buttons (as root, you can add these lines to your SuSE system’s `/etc/rc.d/boot.1ocal1` file):

```
echo "1" > /proc/sys/dev/mac_hid/mouse_button_emulation
echo "87" > /proc/sys/dev/mac_hid/mouse_button2_keycode #F11
echo "88" > /proc/sys/dev/mac_hid/mouse_button3_keycode #F12
```

However, Apple TiBook users will find that pressing F12 by itself will not work for emulation as it is used for a media (CD-ROM) eject button. In this case, use the previous USB approach. In addition, map the middle and right mouse buttons to F10 and F11, like this:

```
echo "1" > /proc/sys/dev/mac_hid/mouse_button_emulation
echo "68" > /proc/sys/dev/mac_hid/mouse_button2_keycode
echo "87" > /proc/sys/dev/mac_hid/mouse_button3_keycode
```

> Yellow Dog Linux and TiBook users will find that the mouse-button and keyboard mapping is automatically configured. Pressing F11 during an X session emulates the middle mouse button. Pressing F12 emulates the right mouse button.

![](img/1ea833f5a3e3c1547e3dd2891f52804a_64_0.png)

Using a three-button mouse may solve some problems when using X11. A typical entry for a three-button USB mouse in the system’s XF86Config file (which can only be edited by root) looks like:

```
Section "Pointer"
    Device      "/dev/input/mice"
    Protocol    "IMPS/2"
EndSection
```

In this example the pointer should be properly recognized. However, using a scroll wheel mouse requires an additional setting to enable the scrolling, which must be added, like this:

```
Section "Pointer"
    Device      "/dev/input/mice"
    Protocol    "IMPS/2"
    ZAxisMapping 4 5
EndSection
```

Experienced Linux users have little trouble in diagnosing or tracking down problems and solutions. When you are new to Linux, it is important to understand the relationships between system configuration files and how Linux works.

Fortunately, Apple PowerPC users can draw on the accumulated knowledge and solutions of others in order to pinpoint and solve problems. Chances are good that someone with your model Power Mac has run across and overcome an obstacle you are currently facing. Make sure to take the time to carefully research any new model purchase, and if you are running into trouble with Linux on your Mac, check the Internet for Linux users using your machine.

## Setting Date, Time, and Locale

Keeping accurate time on your computer is important. It is also important to know that there are two times on your computer: the Linux system time, and your computer's hardware clock. Keeping accurate track of time can be critical, especially when dealing with other users, clients, or remote computers. Some tasks, such as backups, at times must be performed during certain hours of the day. Time and date stamps on electronic mail or documents can prove to be critical in business or the legal profession.

Many savvy Linux users keep the Power Mac's hardware clock set to UTC (*Coordinated Universal Time*) while setting the system time according to the computer's location (a plus or minus offset to UTC).

Because the world is split into many different time zones, every Linux system comes with a database of time zone information (found under the *`/usr/share/zoneinfo`* directory). This information is used in conjunction with different commands to help keep accurate time. Like UNIX, Linux system time is based on the number of seconds since Jan. 1, 1970, and many Linux time utilities use the returned value as a yardstick to determine the current local time.

Displaying the date and time is easy. All you need to do is run the *date* command, like this:

```
$ date
Fri May 11 14:47:08 EDT 2001
```

In this example, the system's current date and time are extrapolated from the number of seconds and are displayed in a readable format. The *date* command may also be used to set the system time. Use the *date* command (as root) with the month, day, hour, and minute in a single numerical string, like this:

```
$ date 06291200
Fri Jun 29 12:00:00 EDT 2001
```

On the other hand, to view your computer's hardware clock and its time, use the `clock` command with its `-r` option, like this:

```
# /sbin/clock -r

time in rtc is Fri May 11 23:07:07 2001

Fri May 11 23:07:07 2001
```

> On Intel-based Linux systems, `hwclock` is traditionally used to show and set the system's hardware clock. This command is only supported when using Linux on CHRP or PREP workstations, not Apple Power Macs. Use the `clock` command instead.

![](img/1ea833f5a3e3c1547e3dd2891f52804a_66_0.png)

The `clock` command has a terse syntax that looks like this:

```
# /sbin/clock --help

/sbin/clock: unrecognized option '-help'

`clock` [-u] -r|w|s|a|v

r: read and print CMOS clock

w: write CMOS clock from system time

s: set system time from CMOS clock

a: get system time and adjust CMOS clock

u: CMOS clock is in universal time

v: print version (1.4) and exit
```

This command, found under the `/sbin` directory, should not be confused with the OpenWindows `clock` client, which displays the current time in a graphical clock during an X session. The `/sbin/clock` command should only be run by the root operator (root should explicitly call `clock` using its full path). This command can be used to display and sync your computer's hardware clock with the Linux system clock by using its `s` option. To adjust the system time to the hardware clock, use the `s` option.

If you use a Red Hat-based distribution such as Yellow Dog Linux or LinuxPPC 2000, you can also use Red Hat's `timetool` client to set your system time. This X11 client may be started from the command line of an X11 terminal window, like this:

```
# timetool &
```

After you press Enter, you see window, as shown in Figure 3.1.

![](img/1ea833f5a3e3c1547e3dd2891f52804a_67_0.png)

Red Hat-based Linux uses a symbolic link named `/etc/localtime` to designate your current time zone. Under SuSE Linux this is a binary file derived from the system's time zone database. Under SuSE Linux, you can set your time zone by editing its system-wide configuration file, `/etc/rc.config`. Look for the following entry:

```
TIMEZONE=EST
```

After making changes, make sure to run SuSE’s `suseconfig` shell script to implement your change.

SuSE Linux also provides a console-based, comprehensive system administration tool named `yast`, along with a newer graphical version for X11 named `yast2`. When you use the `yast` command, you can jump right to a specific administrative task by using its `--mask` option, followed by a keyword such as backup, consolefont, gpm, help, keymap, modem, mouse, netprinter, printer, scanner, timezone, user, or vfree. To jump right to an easy time zone configuration, use `yast`, like this: `yast --mask timezone`.

![](img/1ea833f5a3e3c1547e3dd2891f52804a_67_1.png)

System administrators using KDE can use the `kcmclock` client to set the time and designate a time zone. Start the client from the command line of an X11 terminal window, like this:

```
# kcmclock &
```

When the client starts, click the time zone tab in the dialog box, as shown in Figure 3.2.

Click the drop-down GMT menu and select your time zone (as an offset to GMT).
