The X server will determine if your system can support the requested color depth and resolutions defined for your system. Typical values used for different color depths are 8, 15, 16, 24, or 32. If you use XFree86 version 3.3.6, the command line looks like this:

```
# startx -- -bpp 8 -dpi 100
```

You can even use the *startx* command to launch multiple X sessions, useful to test new window managers or run X sessions at different color depths. Thanks to Linux support of *virtual consoles*, or its console displays that are accessible through the keyboard, you can quickly navigate between sessions.

Start your first X session by using the *startx* command, along with a *display number*, which specifies an X server instance. You can include a color depth setting, and a number representing a virtual console like this:

```
# startx kde2 -- :0 -bpp 16 vt7
```

After the X session starts (using KDE2), press Ctrl+Alt+F2 to jump back to a text-only login prompt. Log in, and again use *startx* like this:

```
# startx afterstep -- :1 vt8
```

Another X11 session (this time using AfterStep) will appear. To jump to KDE2, press Ctrl+Alt+F7. Use Ctrl+Alt+F8 to return to AfterStep running under the second session. Start different clients in each session, or note the different color depth used. If you jump to another text-only console, use Alt+F7 or Alt+F8 to go back to either X session.

## Stopping an X11 Session

To stop an X session, use the window manager's logout menu. This can be accessed through a start menu, root display menu, or in the case of KDE or GNOME, through the desktop panel. You can also use a keyboard combination to kill the running X server if your XFree86 configuration file, `XF86Config`, contains the following:

```
# Uncomment this to disable the <Ctrl><Alt><B8> server abort sequence
# This allows clients to receive this key event.
#DontZap
```

To not allow users to kill an X session by using Ctrl+Alt+Delete (the Backspace key, and not the three-fingered salute, Ctrl+Alt+Del), remove the comment (pound sign) in front of `DontZap`. Under XFree86 4.0 and greater, this option is off by default, but may be placed under the `serverFlag` section. It looks like this:

```
Option    "DontZap"
```

## Configuring a Chooser

Three display managers that are commonly used with XFree86 and Linux are `xdm`, part of the XFree86 distribution; KDE's `kdm`; and GNOME's `gdm`.

Display manager use is controlled by your system's initialization table `/etc/inittab`, which is used by the `/sbin/init` command. This command is used for starting the first Linux programs according to the runlevel, or system state Linux is booting to. However, not every Linux distribution defines the same runlevels. For example, the Yellow Dog Linux and LinuxPPC 2000 distributions define the following runlevels like this:

```
# Default runlevel. The runlevels used by RHS are:
# 0 - halt (Do NOT set initdefault to this)
# 1 - Single user mode
# 2 - Multiuser, with out NFS (The same as 3, if you do not have networking)
# 3 - Full multiuser mode
# 4 - unused
# 5 - X11
# 6 - reboot (Do not set initdefault to this)
```

The runlevels most commonly used here are 1 (or single user mode), used for file system repair or administrative work; 3, used for normal console-login multi-user mode (for using startx); and 5, used for multi-user mode with a graphical X login using a display manager.

SuSE PPC Linux defines these runlevels like this:

```
# runlevel 0 is halt
# runlevel S is single-user
# runlevel 1 is multi-user without network
# runlevel 2 is multi-user with network
# runlevel 3 is multi-user with network and xdm
# runlevel 4 is unused
# runlevel 5 is unused
# runlevel 6 is reboot
```

Note that SuSE’s multi-user, console-mode uses runlevel 2, while a graphical login with a display manager and X is runlevel 3. The default runlevel is specified using the initdefault setting in /etc/inittab.

Under LinuxPPC 2000, booting to xdm uses:

```
id:5:initdefault:
```

With SuSE PPC Linux, use the following:

```
# default runlevel
id:3:initdefault:
```

The default display manager can be specified in /etc/inittab with a runlevel description like this:

```
x:5:respawn:/usr/bin/xdm -nodaedmon
```

However, both SuSE and Red Hat Linux-based PowerPC distributions use more complicated means to determine the default boot manager. Under SuSE Linux, the logic to determine the default boot manager is in:

```
13:3:wait:/sbin/init.d/rc 3
```

Under Red Hat Linux-based systems, a shell script named *prefdm*, found under the */etc/X11* directory, is implemented to determine the display manager being used:

```
x:5:respawn:/etc/X11/prefdm -nodaemon
```

The script contains logic that chooses the display manager, based on the contents of the file named *desktop* under the */etc/sysconfig* directory:

```
...
# Run preferred X display manager
preferred=
if [ -f /etc/sysconfig/desktop ]; then
    if grep -q GNOME /etc/sysconfig/desktop 2>/dev/null; then
        preferred=xdm
    elif grep -q KDE /etc/sysconfig/desktop 2> /dev/null; then
        preferred=kdm
    elif grep -q AnotherLevel /etc/sysconfig/desktop 2> /dev/null; then
        preferred=xdm
    fi
fi
...
```

The *desktop* file is parsed for the keywords **GNOME**, **KDE**, or **AnotherLevel** to determine the display manager to use: *gdm*, *kdm*, or *xdm*.

### Configuring xdm

The *xdm* client is controlled by a series of files under the */etc/X11/xdm* directory. These files determine the X server to use, access permissions, the hosts you may log onto, the default appearance of the chooser dialog box, and security settings for fail-safe or terminal usage. You can start the *xdm* client (as *root*) from the command line using its *-nodaemon* option like this:

```
# xdm -nodaemon
```

After you press Enter, the screen will clear, and you will see a *xdm* login screen. Type your username and password to log in.

The window manager used for your *X* session can be designated in your ~/.Xinitrc file.

> If you use a Red Hat Linux-based PowerPC distribution, and log in with the **xdm** display manager, use the *switchdesk* client after you log in to choose your default window manager.

### Configuring kdm

Unlike *xdm*, the *kdm* client and login dialog box offers a choice of window managers for your *X* session, which include a **Go!** button to launch the session, a **Cancel** button to cancel your login, and a **Shutdown** button that can be used to shut down, reboot your system, or restart your *X* server.

To log in, type your username, then your password. Before pressing Enter or clicking the **Go!** button, click the drop-down menu to select a window manager to use for your session. *kdm* can be configured during an active KDE session by the root operator using the *kdmconfig* client. This client may be accessed by using the KDE Control Center, or from the command line of an X11 terminal window like this:

```bash
# kdmconfig
```

After you press Enter, you will see a dialog box, as shown in Figure 7.15.

![](img/1ea833f5a3e3c1547e3dd2891f52804a_182_0.png)

Use different tabs and dialog boxes to navigate through `kdmconfig`'s configuration. You can change the greeting, select different wallpapers, control user access, or assign a graphic (or scanned photo) for each user.

## Configuring gdm

The gdm client, like `xdm`, provides a graphical login to Linux and X. This client may be used by editing `/etc/inittab` and a gdm runlevel five entry like this:

```
x:5:respawn:/usr/bin/gdm -nodadaemon
```

Note that under SuSE PPC Linux 7.0 this entry will look like this:

```
x:5:respawn:/opt/gnome/bin/gdm -nodadaemon
```

You can configure gdm (as root) by editing the file `gdm.conf` under the `/etc/X11/gdm` directory. The file is organized into different sections, such as daemon, security, xdmcp, gui, greeter, debug, and servers. For example, you can change the appearance of the login dialog box by editing the "greeter" section:

```
...
Icon=/usr/share/pixmaps/gdm.xpm
LocaleFile=/etc/X11/gdm/locale.alias
Logo=/usr/share/pixmaps/gnome-logo-large.png
QuitVer=0
SystemMenu=
Welcome=Welcome to &\n
...
```

In this example, the icon, logo, and welcome message of the dialog box can be changed. Another way to customize the desktop of your gdm login is to edit the file named `default` under the `/etc/X11/gdm/init` directory. For example, you can add the following:

```
/usr/bin/play /usr/share/sounds/retina.wav &
/usr/bin/xclock -bg '#363047' -fg yellow -update 1 -geometry 256x256+20+250 &
```

When the screen first appears, the user is asked to prepare for a retina scan prior to logging in (OK, it is a joke!). A large, floating clock with yellow hands will appear next to the login dialog box. (This is handy way to put idle terminals to use!)
