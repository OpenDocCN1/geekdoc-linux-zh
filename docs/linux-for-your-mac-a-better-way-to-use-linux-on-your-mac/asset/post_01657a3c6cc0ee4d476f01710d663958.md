Note that a number of shells listed in Table 5.1 are graphical programs with menus (choice, flin, mc, and webble) and do not fit the traditional definition for a Linux shell. Some of the features to look for in a shell include:

- The size of the binary. Is the shell statically linked, or does it depend on other software libraries? One function of the sash shell is that it can be used during troubleshooting or rescue operations as a shell, and does not depend on the availability of external software libraries. If you are crafting a minimal Linux installation, then you may want to consider using a smaller shell. Without a doubt, the bash shell is the largest and has the most features.

- The number of built-in commands. Every shell has a limited number of built-in commands that may be used in lieu of external binary commands. For example, some shells contain code that prints the current working directory (though most Linux distributions include a pwd command under the /bin directory). Other built-in commands are listed in Table 5.2.

- History. This feature allows you to scroll through a preset number of previous command lines, including those commands from a previous login. This can save time, especially if you need to recall and use complex commands.

- Job control. Offers the ability to send a currently running program into the background, start a new program, and then selectively recall and use running programs. This adds a new dimension to a single command line. Some shells, and a few but not all Linux programs, support this feature. Job control also features the ability to selectively destroy programs in memory.

- Command-line editing. This feature makes it easy to correct mistakes or edit recalled command lines before use. Not all shells feature editing of the command line.

- Language syntax. Conditional grammar and other language features can make writing shell scripts a lot easier, especially if a selected shell has a rich assortment of list and control operators.

- Built-in variables. Many shells feature an extensive list of built-in variables that may be modified and customized to suit your system or users’ needs. Some variables, such as PWD (the current working directory), are constantly updated, while others, such as HOSTNAME, OSTYPE, or MACHINETYPE, will depend on your system and its hardware. Some of the most important variables are HOME (the location or pathname of your home directory, usually /home/yourname) and PATH (the location of executable programs you can use on your system, typically /bin, /usr/bin, /usr/X11R6/bin, and possibly /usr/local/bin).

- Prompt functions. This feature usually operates according to the number and type of internal variables recognized by a shell. It allows you to redefine the shell prompt to provide useful information. At a minimum, the prompt should show the current working directory. Many Linux users use a shell prompt with the user’s name, computer hostname, and working directory.

- Expansion. If this feature is supported, the shell will be able to fill in, or expand the command line based on certain keystrokes. There are a number of types of expansion such as command, variable, arithmetic, and pathname.

### Aliases

Shells that provide this feature allow you to create an abbreviated shortcut or *alias* for longer commands. In some cases, this creates a much safer computing environment, especially if you are a Linux beginner. For example, many distributions do not provide an alias for the Linux *delete* command known as `rm`. This command will quickly and silently delete files without prompting or feedback, and can devastate your entire home directory if misused. However, the `rm` command's `-i` command-line option will prompt you to press `y` or `n` before deleting a file. Therefore, good system administrators will redefine the `rm` command to be `‘rm -i’`, which is much safer! (If you're running Linux on your Mac, **you** are the system administrator!) To do this, edit your system's `/etc/profile` (or `/etc/profile.local` or `/etc/skel/.bashrc`) and add: `alias rm='rm -i'`.

You will find that most of the popular shells for Linux support these features and more. Most of the shells are quite capable, extremely stable, and have been rigorously tested over time. The shell is, without a doubt, one of the most important types of programs included with Linux, and provides an essential platform for getting work done when using the console. The following sections include the most common shells available for Linux.

## bash

The **bash** shell is the default Linux shell on nearly every installed Linux system. Although somewhat larger and more memory intensive than the other shells that follow, *bash* has an extensive feature list that surpasses that of other shells. The **bash** shell is the most often used shell for Linux shell scripts because it has the ability to perfectly mimic the Bourne, or **sh** shell, which is a staple shell of commercial and free UNIX operating systems. The **bash** shell can also mimic other shells, depending on how it is launched (such as through a symbolic link).

bash has extensive built-in help you can access with its **help** keyword command:

```
$ help
```
