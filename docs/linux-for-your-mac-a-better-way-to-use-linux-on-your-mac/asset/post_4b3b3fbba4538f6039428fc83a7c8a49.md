## Linux, X11, and the Palm PDA

The Palm PDA has always been supported under Linux because of 3Com's, and later Palm Computing's willingness to share information about the Palm PDA platform with developers. This is in direct contrast to another commercial platform whose manufacturer is just starting to "get it." PDAs are becoming as ubiquitous as the small address book or day planner, and you can pick up a relatively inexpensive handheld device with an easy-to-use interface for less than $200 (US). Because Palm Computing does "the right thing" by sharing platform and operating system information, the Palm (and Handspring) PDAs rule the handheld industry with a greater than 80 percent market share.

### Linking with the pilot-link Suite

The pilot-link suite of utilities is the definitive and easy-to-use software for backing up, restoring, or syncing a Palm-type PDA with Linux. You will find this software included with nearly every Linux distribution. You can use the software to handle nearly any type of Palm OS file, such as programs or databases.

To get started, first create an environment variable named PILOTRATE like this (if you are using the bash shell):

```
$ export PILOTRATE=57600
```

This example will create the PILOTRATE variable, and lets the pilot-link software know how fast to communicate with your PDA. Communication between your Linux computer and the PDA is generally accomplished (by default) through the `/dev/pilot` device. On Intel-based PCs, this can be a link to a serial or USB port with a serial adapter (if your PDA uses a serial cradle).

One way PPC Linux users can operate a serial PDA cable with the Macintosh is to use a USB-to-serial adapter. One of the best on the market is the Keyspan PDA adapter, which plugs into a USB port on the Mac keyboard, iBook, Cube, or USB hub. Serial communication is then enabled on the `/dev/ttyUSB0` port by using (as root), the insmod command to load the usbserial and keyspan_pda modules like this:

```
# insmod usbserial
Using /lib/modules/2.2.16/usb/usbserial.o
# insmod keyspan_pda
Using /lib/modules/2.2.16/usb/keyspan_pda.o
```

These examples (from a SuSE 7.0 PPC system) show that the system has recognized and loaded the appropriate modules from the `/lib/modules/2.2.16/usb` directory. You can then check to make sure the Linux kernel recognizes the new devices by using the dmesg command like this:

```
# dmesg
...
usb.c: USB new device connect, assigned device number 5
usbserial.c: Looking at Keyspan PDA Vendor id=06cd Product id=0104
usbserial.c: descriptor matches
usbserial.c: found interrupt in
usbserial.c: found bulk out
usbserial.c: Keyspan PDA converter detected
usbserial.c: get_free_serial 1
usbserial.c: get_free_serial - minor base = 0
usbserial.c: Keyspan PDA converter now attached to ttyUSB0 (or usb/tts/0 for devfs)
```

Note that not all the output is shown here. However, you can see that the device has been assigned to `/dev/ttyUSB0`.

You can now create the PILOTPORT environment variable to point to this device if you wish, and the pilot-link software will automatically use the port. For example:

```
$ export PILOTPORT=/dev/ttyUSB0
```

This will create the `PILOTPORT` variable for use with the software. On the other hand, you can also (as root), create a symbolic link named `/dev/pilot`:

```
$ ln -s /dev/ttyS80 /dev/pilot
```

This will create the symbolic link `/dev/pilot`, which can then be used later, or in subsequent sessions. If the link is already present but points to another serial port, delete the existing entry and recreate `/dev/pilot` as above. Next, connect your PDA to its cradle or cable, and then get ready to use the `pilot-xfer` command. This command works with or without X, and may be used during console, or text-only sessions.

> You can (as root) use the `chmod` command to allow any user on your system to access the serial/USB port by setting the port's permissions like this: `chmod 666 /dev/ttyUSB0`.

![](img/1ea833f5a3e3c1547e3dd2891f52804a_314_0.png)

Using this command is easy. For example, to install a program on your PDA, use the command's `-i` or install option, followed by the name of a PDA program or database like this:

```
$ pilot-xfer -i myprogram.prc
```

The program will then upload into your PDA as soon as you press the cradle's Hot Sync button, or the button on the PDA's Hot Sync menu. To back up the contents of your PDA, use `pilot-xfer`'s `-b` or backup option, followed by the name of a directory like this:

```
$ pilot-xfer -b p3backup
```

The `pilot-xfer` will automatically create the directory (`p3backup` in this example), and then download and save the contents of your PDA followed by Hot Sync notification. To keep the backup up to date, use `pilot-xfer`'s `-u` (update) option like this:

```
$ pilot-xfer -u p3backup
```

Only changed or updated information in your PDA will be backed up. This is the preferred method of backing up (instead of using `-b`), because fewer files are transmitted, resulting in faster Hot Syncs. However, if something happens to the contents of your PDA, you can easily restore it with the `-r` option like this:

```
$ pilot-xfer -r p3backup
```

This command line will send the entire contents of the backup directory to your PDA. Other files are included with the `pilot-link` suite of programs. These include utilities that specifically work with the PDA address book, datebook, and mail client (see the `pilot-link` manual page for more information).

### Using Kpilot

The `kpilot` client, by Dan Pilon, is a KDE-compliant tool you can use with your Palm PDA. You will need an active X session, and KDE installed on your system in order to use `kpilot`. The program works by providing a Hot Sync daemon that detects when you have pressed the Hot Sync button on your PDA’s cradle or PDA’s Hot Sync menu.

To get started with `kpilot`, launch the application from the KDE desktop’s panel menu, or the command line of an X11 terminal window like this:

```
$ kpilot &
```
