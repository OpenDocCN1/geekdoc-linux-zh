```
/bcmn/ftp/pub 192.168.2.42(ro)
/d3 cubie (rw,no_root_squash)
```

In this example, the /d3/src directory is available to the host named _via_, and provides read-write access. The next entry, /d4/backup, is available to the host named _del_, again for read-write access. The _/music_ entry however, is only available to a host with an IP address of 192.168.2.38 (in reality, the host named _del_) and only for read access. The /home/ftp/pub directory (a handy place for a Red Hat Linux installation CD-ROM) is available to a host with an IP address of 192.168.2.42, and only for read access. Finally, an entry for _cubie_ shows that the /d3 volume will be made available for read and write access (at least by root).

Next, on host _cubie_, create a mount point for the remote directory. This can be created anywhere on your filesystem, although the traditional mounting points are generally found under the /mnt directory. For our purposes here, let us assume that _cubie_ does not have a /d3 mount point. Therefore, the root operator will first use mkdir to create the mount point:

```
# mkdir /d3
```

Next, root will use the _mount_ command to mount the remote directory. Include the _nfs_ filesystem type, along with the hostname, remote, and local directory like this:

```
# mount -t nfs green:/d3 /d3
```
