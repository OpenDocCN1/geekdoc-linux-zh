On the other hand, as a system administrator, you should be able quickly rebuild and install a new or revised Linux kernel easily. Once all the software and source code is installed, navigate to the /usr/src/linux directory. This directory should be a symbolic link to the current kernel source directory, which could have a name such as linux-2.2.18-4hpmac or linux-2.2.16, or if you are an intrepid user at the time of this writing, linux-2.4.2.

Directions for building and installing a kernel are contained in the file root. Set up the directory for a kernel build by using the make command like this:

```
# make mrproper
```

This command will clean up the source directories in preparation for the build. Next, use the make command with one of the following: config, menuconfig, or xconfig. The first form of the command presents a text-based configuration script that asks questions regarding what features to enable or disable in the resulting kernel. Start the configuration like this:

```
# make config
rm -f include/asm
(cd include ; ln -sf asm-generic asm)
if [ ! -s Documentation/lang/en/Configure.help ]; then \
cp Documentation/lang/config.lang.help.en Documentation/lang/en/Configure.help;\
cat Documentation/Configure.help >>Documentation/lang/en/Configure.help;\

make -C scripts cfixconv

make[1]: 'cfixconv' is up to date.
make[1]: Leaving directory '/usr/src/linux/scripts'
source scripts/set_headerfile.sh ; rm -f config.in.tmp ; \
scripts/cfixconv $headerfile <arch/ppc/config.in >config.in.tmp
/bin/sh scripts/Configure config.in.tmp
#
# Using defaults found in .config
#
.
```

Language of the Kernel configuration (English, German, French, Spanish) [English]

The first prompt asks for the language to be used for the configuration script. Default values are enclosed in brackets, which means that if you are satisfied with the value, you can just press Enter.

The second form of the command presents a console-based graphical configuration dialog box that uses menus and fields when asking what features to enable or disable in the resulting kernel. Start the configuration like this:

```
# make menuconfig
```

After you press Enter, you will see a dialog box, as shown in Figure 14.18.

Press Enter on a menu item with an arrow (-->) to enter the configuration sub-menu. Use the spacebar to select or unselect features. An asterisk (*) denotes a feature is enabled. An empty space denotes that the feature will not be enabled. In some instances, the spacebar will toggle between enabled, disabled, or if possible, building the feature as a module (in this final instance, an M will appear).

The third form of the command can only be used from the command line of an X terminal window during an active X session. The command will present an X window dialog box with buttons and check boxes that represent yes, no, or if possible, build a module. Start the configuration like this:

```
# make xconfig
```

After you press Enter, you will see the dialog box, as shown in Figure 14.19.

The order in which to proceed through the menus is not as obvious using a script or console-based dialog box. If you are building a new kernel for the first time, make sure you understand exactly what you would like to enable or disable in your new kernel. Also, make sure to proceed through all the menus so that you have a better understanding of the capabilities that the Linux kernel offers.

Save the file and exit after you have finished the configuration. Next, use the *make* command to create dependencies in the source tree (so that the compiler and linker know what elements to build and put together in the kernel), like this:

```
# make dep
```

After the dependencies have been created, you can then build the kernel like this:

```
# make vmlinux
```

After you press Enter, the compilation process will start. Depending on the speed of your system, you will find two new files in the `/usr/src/linux` directory: `vmlinux`, a new kernel; and `System.map`, a memory map of the new kernel. Your next step is to build any required kernel modules. Again, use the *make* command:

```
# make modules
```

After the modules are built, you can then install them with:

```
# make modules_install
```

However, you may want to make a backup copy of the current modules (which is found under the `/lib/modules/2.x.x` directory, where `x.x` represents the version of your Linux kernel).

To use your new kernel, copy the file `system.map` to the `/boot` directory. You can also copy `vmlinux` to the `/boot` directory. However, BootX and yaboot users will then need to copy `vmlinuz` to the appropriate Mac OS System Folder, and change BootX or yaboot's configuration file to use the new kernel.

## How Linux Starts and Stops

After Linux boots, it runs a program named **init**. The **init** command is responsible for starting, restarting, or stopping services on your computer. Although Linux distributions will differ in how the **init** command manages the services, all distributions use some form of interdependent shell scripts (many of them symbolic links) that are called in a particular order in response to a particular system state, or runlevel.

You can see how the **init** command is responsible for starting processes under Linux by using the **pstree** command, or other utility that shows the relationship between processes. For example, using the **pstree** command may return the following:

```

    |-kdeinit--kdeinit

            |
            |-2*[kdeinit--bash
            |
            |-kdeinit--bash--bash
            |
            |
```
