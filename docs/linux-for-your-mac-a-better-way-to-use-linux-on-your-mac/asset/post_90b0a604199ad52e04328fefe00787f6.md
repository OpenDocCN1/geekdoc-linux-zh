## Mounting and Unmounting Filesystems

The `mount` command can be used to mount and unmount a variety of filesystems. It is essential during the Linux boot process, as it brings the native Linux partitions on-line and makes them available for other programs during the boot process. This section provides a few simple examples you will use regularly during your Linux sessions.

SuSE Linux and Red Hat-based PowerPC Linux distributions include system daemons that you can set up and start to automatically mount removable media. Under LinuxPPC 2000 Q4, use the `amd` daemon, controlled by the `/etc/rc.d/init.d/amd` script and the `ntsysv` administrative tool. This daemon is configured by the file `etc/amd.conf`. Under SuSE Linux PPC, the task is handled by the `automount` daemon, and is controlled by the `/sbin/init.d/autofs` startup script. Configuration and mounting points are handled by the `/etc/auto.master`, `/etc/auto.misc`, and `/etc/auto.net` configuration files.

Use of an automount strategy can be convenient. However, many Linux users prefer to mount and unmount filesystems manually. For example, to properly mount a CD-ROM, insert the CD-ROM, and then use the `mount` command, a filesystem type, device name, and mounting point like this:

```
# mount -t iso9660 /dev/cdrom /mnt/cdrom
```

If you have your Mac's CD-ROM device already defined in your system's filesystem table, then you can abbreviate the mounting command like this:

```
# mount /mnt/cdrom
```

When you simply specify the mount point, the `mount` will then look in `/etc/fstab` for an associated entry and use that entry's information. With the addition of user options in `/etc/fstab`, normal system users may be allowed to mount and unmount removable media.

> By the way, if you have an Apple G4 Cube or Titanium G4 PowerBook, you have probably discovered that no current Linux PowerPC distribution can recognize or use the media ejection key used with these slot-loading computers. Do not worry! You do not have to resort to using an emergency CD-ROM eject pin. Instead, use the `eject` command! This command will also attempt to unmount the media before performing an eject.

![](img/1ea833f5a3e3c1547e3dd2891f52804a_426_0.png)

To unmount a filesystem, use the `umount` command, followed by the mount point, like this:

```
# umount /mnt/cdrom
```

If you attempt to unmount a device, you may receive an error message:

```
# umount /cdrom
umount: /cdrom: device is busy
```

This indicates that a user is operating the device, or has a current working directory in the path of the device (perhaps you are still inadvertently there; use the `pwd` command to check your current path). Your Linux system will use `umount` to unmount all active filesystems as part of the reboot or shutdown process. This is essential, as data in Linux memory is flushed and saved to your system’s hard drive(s). With today’s modern hard drives, this process may not happen immediately, as the disk cache needs to be written to disk.

To mount an HFS volume, use the `mount` command, the `hfs` option, device name, and mount point like this:

```
# mount -t hfs /dev/hda10 /mnt/mac
```

This will allow you to copy files back and forth between your Linux filesystem and Mac OS.

## Using the find Command

The `find` command is an indispensable tool for system administrators. It is used to quickly locate files across one or more filesystems according to a variety of search expressions, such as name, date, time, owner, and size. This command is used to quickly build practical logs of information about your system that can be used for back up operations or security.

For example, to find all files on your system (excluding externally mounted filesystems), which have changed in the last 24 hours use the `find` command like this:

```
# find / -mtime -1 -print -xdev | xargs ls -l > /root/seelog.txt
```

The results, which are saved in a file named `seelog.txt` under the `/root` directory, will list the details about all files that have changed in the last 24 hours. This is important if you are looking for any unauthorized changes to your filesystem.

The `find` command returns the pathnames to found files. Although the previous command line uses the `xargs` command to act on those filenames, you can also include this action in the `find` command line as well:

```
# find / -mtime -1 -print -xdev -exec ls -l '{}' {} > /root/seelog.txt &
```

Want to find the largest files on your system? Just use the `-size` option, followed by a minimum size as a search criteria. You will be surprised how many large files are on your system:

```
# find / -size +4096k -print -xdev
```

```
/var/lib/rpm/packages.rpm
/var/lib/rpm/fileindex.rpm
/var/lib/rpm/requiredb.rpm
/var/backup/rpmdt/packages.rpm-20010227.gz
/var/backup/rpmdt/packages.rpm-20010311.gz
/var/backup/rpmdt/packages.rpm-20010213.gz
/var/backup/rpmdt/packages.rpm-20010225.gz
/var/backup/rpmdt/packages.rpm-20010226.gz
...
```

In this example, the `find` command returns the pathnames to files that are greater than 4MB in size. You can use this approach to prune your filesystem and perhaps delete unneeded space hogs.

There are many uses for the `find` command. As you craft your own search tools, you can begin to use different command lines in different ways, such as for regularly scheduled tasks (discussed later in this chapter under “Scheduling with `crontab`”).

## Archiving and Backups

There is a difference between archiving data and backing up data. When you archive data, it is generally saved for long-term storage in a form that can be accessible. Backing up data is a system administration task that should be performed regularly, on schedule, and according to plan. This section briefly introduces and covers the subjects of archiving and backups for Linux.

Creating an archive is quite easy. For example, if you have the disk space, navigate to a new directory and use `mkdir` to create a directory to hold the archive contents:

```
$ mkdir home
```

Next, use the `cp` command with its `-ar` option to recursively copy the specified directory into your new home directory like this:

```
$ cp -ar /home/bball home
```

To create a CD-ROM image of the directory, use the `mkisofs` command with the name of the desired CD-ROM image and the specified directory like this:

```
$ mkisofs -r -o home.iso home
```
