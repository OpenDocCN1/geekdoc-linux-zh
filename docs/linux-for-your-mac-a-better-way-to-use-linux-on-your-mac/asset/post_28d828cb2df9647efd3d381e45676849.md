
## Using tkaysv

The `tkaysv` client is a runlevel editor that presents the myriad of inter-dependencies of various runlevels matched against installed system services. Launch this client by clicking its icon or from the command line of a terminal window like this:

```text
# tkaysv &
```

After you press Enter, you will see its window, as shown in Figure 14.2.

This editor can be used to rearrange, create, or delete services for various runlevels. Use its interface to assign actions for different services listed in its Available field. Note that the editor will not work on runlevels 0, 1, or 6. This is because these are the halt, single-user (maintenance), and reboot runlevels. This tool can be handy, for example, when having certain services start before or after each other (such as starting PCMCIA services and then starting networking after the interface has been configured).

# Linux is a Two-Timer!

There is a difference between the Linux system time and your computer's hardware clock. If the two are not in synch and your computer has a long uptime, you will find that the Linux system's idea of the time (as returned by the `date` command) and your hardware's idea of the time will drift apart. However, there are at least two commands you can use to keep your PowerPC hardware and Linux in synch.

The first command, `rdate`, is the easiest to use if you have an active Internet connection. As root, use the `rdate` command with its `-s` option, followed by the hostname of an open-access Internet time server offering your local time, such as `tick.usno.navy.mil` for EST/DST users. The `rdate` command will automatically set your system's time using the returned (and deemed authentic) values.

The other way Intel-based Linux users keep the computer and operating system in synch is with the `hwclock` command. For example, `hwclock --syssto...` sets the hardware clock to the system time. On the other hand, using `--hctosys` sets the system time according to the hardware clock. The `hwclock` command can also be used to learn, measure, and compensate for any drift between software and hardware.

Under PPC Linux however, this command does not work, and the clock command must be used instead. Use `clock -w` to set the hardware clock to the system time. Use `clock -s` to set the system time from the hardware clock. Don’t confuse the clock command with the X11 client named *clock*! You’ll find the hardware- and system-based `clock` command under the `/sbin` directory. The other *clock* client will be found under the `/usr/X11R6/bin` directory.

## Using helptool

The helptool client can be used to quickly search your system for helpful documents. Though not as glamorous or capable as SuSE’s, GNOME’s, or KDE’s built-in help, helptool is, however, helpful when attempting to find topical help on a variety of subjects. This client may be launched from the panel or the command line of an X11 terminal window like this:

```text
# helptool s
```

After you press Enter, the helptool dialog box will appear. Start your search by clicking in Search for: field, then click the Search button. After some time, you may see results such as those shown in Figure 14.6.

This client searches along predetermined paths, looking for matches in documents under specific directories. If you click the Configure button, you can customize your searches along specific paths or through specific documents. When results are returned, double-click on a filename and the file will be displayed in a separate window.

![](img/1ea833f5a3e3c1547e3dd2891f52804a_353_1.png)

*Figure 14.6 The helptool client searches pre-configured paths for topical matches in documents, manual pages, or GNU info documents.*

A simplistic command-line equivalent (limited to a single directory search) for help2conf would use the find, xargs, fgrep and less commands like this:

```text
$ find / | xargs fgrep searcbst | less
```

In this example, the find command feeds the xargs' fgrep command a list of filenames. The fgrep command will then only display matching lines containing searcbst, preceded by the file's path. By using the less pager you can then quickly browse through a list of documents that contain the search string.

## Using netcfg

The netcfg client is an easy-to-use networking tool that can quickly set up your system's /etc/resolv.conf, /etc/hosts, and networking device initialization scripts to support built-in Ethernet interfaces and PCI or PCMCIA network cards. As with all system administrative tools, this client requires root access. netcfg may be launched by clicking its icon on the panel, or from the command line of an X terminal window like this:

```text
# netcfg &
```

After you press Enter, its main dialog box will appear, as shown in Figure 14.7.

This client can be used to create and control PPP, PLIP, SLIP, Ethernet, and a variety of network interfaces for your system. You can also alter your system's routing table to accommodate other subnets, define a gateway, or determine how an interface is assigned an IP (Internet Protocol) address.

### Using modemtool

The `modemtool` client, shown in Figure 14.8, is a simple graphical interface client that merely creates a symbolic link named `/dev/modem` that points to your system's modem port. The actual modem port could be `/dev/ttyS0`, `/dev/ttyUSB0`, or even `/dev/ttyS14`, depending on your Macintosh hardware.

You can launch `modemtool` by using its icon on the panel, or from the command line of an X terminal window like this:

```text
# modemtool &
```

After you press Enter, its small dialog box will appear, as shown in Figure 14.8. Unfortunately, `modemtool` is brain-dead, with no built-in logic or search capability, as is possessed by the modem configuration feature of KDE's `kppp` client. You can accomplish the same task as `modemtool` by using the `ln` command like this:

```text
# ln -s /dev/ttyS0 /dev/modem
```

In this example, the `/dev/ttyS0` device is known to have an attached modem. The `ln` command is then used to create the symbolic link `/dev/modem`.
