# ## Managing Processes

One of the greatest things about using Linux is that the operating system is designed to isolate and protect the kernel from disruptive processes. Through the use of signals, permissions, scheduling, and memory management, your Linux sessions are generally quite safe from any program that has run amry and crashed. If you lose control of a program, you can generally get to another shell prompt and quickly kill it.

When each program starts, the kernel assigns a process ID number to the command. You can see a quick snapshot of these processes in memory by using the `ps` command, like this:

Note that not all the processes are shown here, but one thing Linux users can be sure of is that everything starts with just one command named `init`. The `init` command, launched after Linux boots, spawns a whole series of new processes to get your system up and running. You can verify this by using the `ps` new `pstree` command (included with SuSE and LinuxPPC). For example, on a graphical login-based Linux PPC system running X and the `twm` window manager, `pstree` reports:

