
For information on how to compose messages using mail, read its manual page. This command is a bare-bones way to read and reply to electronic mail, but its terseness and lack of features can actually be viewed as a unique quality. For example, you can quickly send a message with a subject line and separate file in the body of the message with a single command line, like this:

This makes the mail command an ideal candidate for use in automation scripts and for other system administration duties.

## Using pine

The pine e-mail program was developed by the University of Washington to provide students with an interactive electronic mail and Usenet newsreader. This versatile program also includes a separate, easy-to-use text editor named picco, which, in turn, is used for composing and replying to mail. Start pine from the command line of the console or an X terminal window, like this:

```
$ pine
```

The program will then create a directory named mail in your home directory. Pine also uses a resource file named .pinerc that contains your username, your domain, your ISP’s mail server, and other information (such as program settings). After starting pine, configure that program by typing an s and then a c. You will then see its configuration screen. Edit at least the first four values for the following:

personal-name             = your personal name
current-domain            = your ISP’s domain
smtp-server               = your ISP’s outgoing mail server
nntp-server               = your ISP’s news server

Use your cursor keys to scroll through the items, and then press a c to change an item. When finished, press s to exit the setup screen. You are now ready to read and reply to mail. Your changes will be saved in your .pinerc file.

> If you use multiple ISPs, you can create different resource files by first copying the default .pinerc file, and then saving the files with different names. You can then start pine and force the use of a specific set of resource settings like this: pine -f .mypinerc.

## Fighting SPAM

SPAM is one of the worst manifestations of the communications revolution, because it is much more personal and intrusive than postal junk mail. The good news is that legislators are finally listening to fed up consumers and many states now have laws with monetary penalties for the techno-idots who bombard our electronic mailboxes with their stupid hype.

You can use the procmail command to filter incoming mail to help reduce the clutter. This means that if you find yourself bombarded with unwanted messages that have some common element in the sender's address, subject line, or body of text, you can discard the mail quickly and easily.

In order to use procmail, create a file named .procmailrc in your home directory. This file should contain the following:

```
MAILDIR=$HOME/mail
PMDF=$HOME/.procmail
INCLUDERC=$HOME/.procmail/rc.mailfilter
```

These lines specify your incoming mailbox, *procmail*'s directory, and the name of your *procmail* settings (also known as *recipes*). Save the file, and then create a text file named `.forward` in your home directory which contains the following:

```
* IFS=' ' && exec /usr/bin/procmail -f- || exit 75
```

Substitute your personal username for *yourusername*. Next, use the `chmod` command to assign read and write permissions (to protect your recipe, but allow *procmail* access), like this:

```
$ chmod 644 .forward
$ chmod a-x .
```

Finally, create a directory named `.procmail`, and create your `rc.mailfilter` in the directory. This file contains your *procmail* recipes. For example, if you subscribe to a mailing list that regularly sends out messages with a subject line containing the word *agenda-digest*, create an entry that looks like this:

```
:0:
*"Subject:.*agenda-digest
agenda-digest
```

This entry will save any mail message with a subject line containing *agenda-digest* into a mail folder named *agenda-digest*. On the other hand, if you know that all your SPAM is coming from a certain domain, you can then create an additional recipe in the file that looks like this:

```
:0:
*"From:.*msn.com
/dev/null
```

Sending SPAM to your system's `/dev/null` device is a fitting and just end, because the files will simply disappear. For more information about using *procmail*, read its manual page or related HOWTO documents.
