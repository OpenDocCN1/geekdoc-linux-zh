
## Stopping a Print Job

If you start a print job, then decide you would like to stop it, use the `lprm` command, followed by the number of the print job. In order to know the job numbers, use the `lpq` command to list the current queue of print jobs. For example, if you start a print job, the `lpq` command may report a queue list like this:

```
$ lpq
lp is ready and printing
Rank Owner Job Files Total Size
active bhall 4 linuxpr.txt 13558 bytes
```

You can kill the print job by using the `lprm` command, followed by the "Job" number like this:

```
$ lprm 4
dfA004\cube dequeued
cfA004\cube dequeued
```

After you press Enter, the names of the spooled files that have been deleted will be printed.

## Managing the Print Queue

In a multi-user environment, there may be many users and print jobs vying for a printer's attention, and lined up in the print queue. As the *root* operator, you can manage this queue and your system's printer(s) with the `lpc` and `lprm` commands. Since *root* is the *superuser*, the root operator may remove pending print jobs that are owned by anyone (normal users may only remove owned print jobs).

Although normally not needed on a standalone workstation, the `lpc` command may be used by *root* in a networked printer environment to disable or enable any system printer, rearrange the print queue, start and stop printing, and hold and release print jobs. See the `lpc` manual page for more information.

This chapter introduces you to the graphical interface for Linux. It is known as the X Window System, X11R6, X11, or simply, X (pronounced "ex," rather than like Roman numeral "ten"). Unlike the traditional Mac OS (and more like the newer Mac OS X, which is pronounced "ten"), Linux uses an add-on software system that provides a graphical interface for the desktop. Properly configuring X to work with your computer's graphics hardware is essential if you want to enjoy the benefits of windows, icons, menus, and other screen elements, which were first brought to the corporate stage by Apple's Lisa, and then popularized by the 128K Macintosh.

In this chapter, you will learn about a version of X named XFree86, which is a free networking *client* and *server* software system. In this system the server component handles graphics requests from a remote client (application). It handles these requests independent of a remote computer's drawing capabilities.

X predates the commercial graphical desktop and server software from the industry's software monopoly, and was designed from the ground up to support the use of remote applications. In many ways X exceeds the capabilities of closed-source, proprietary commercial operating systems. It also comes with complete source code, which enhances its portability to new hardware platforms. X works quite well on nearly every hardware platform in existence. Even the XFree86 version of X has been ported to run under the new Mac OS X!

This chapter also includes information about special X clients, known as *window managers*, that are used to handle pointer clicks, icons, buttons, and window management for your graphical Linux sessions. You will also learn how to configure X using a variety of software tools, and see how to configure different graphical X login clients, known as *display managers*.

## What is X11?

X is a protocol and networking graphical interface. It was developed in 1984 by the Massachusetts Institute of Technology and the Digital Equipment Corporation as part of a project aimed to produce a distributed computing environment for thousands of users. Since then, X has gone through at least six major revisions, with the current version being X11R6.5. The source code to the X Window System is released under the stewardship of the X Consortium (http://www.x.org). Free versions of X are released by the XFree86 Project, Inc. It is a non-profit organization aimed at providing free versions of X for a number of platforms, including the PowerPC CPU.

X includes nearly 3,500 files in a 34MB compressed distribution (as distributed for the PowerPC platform). This distribution includes more than 1,000 fonts, 120 clients and utilities, 100 graphics, and 1,200 pages of documentation. A typical installation requires more than 70MB of hard drive space, and even more if additional X11 clients are installed.

### Features of X11

X is a portable graphical network interface for Linux, and works well on a stand-alone workstation, or as a graphics system for a large network. X works over slow serial dial-up lines or high-speed fiber-optic networks, and can easily serve one to 10,000 users. X provides for font management, the use of color and system- or client-specific *resources* or configuration files, includes source code, supports standardized command-line interfaces for clients known as *X Toolkit Options*, and has graphics device independence over a network.

Best of all, X is royalty free! Developers can build and distribute clients without licensing restrictions. And because of X’s portability, the version of XFree86 that runs on your Apple Macintosh has many of the same features as the version of X11 for an Intel-based PC, SPARC, or Alpha CPU.

This also means that any clients you develop on your PowerPC using X will nearly always build, install, and run exactly the same way on any other hardware platform supporting X.

### Configuring X11

Configuring X is one of the essential tasks of completing a successful Linux installation. Now an integral part of the install process for a majority of PowerPC Linux distributions, X configuration can generally be accomplished automatically as part of the install or booting process. This is great when everything goes OK, but if you run into problems, you may need to resort to one or more software tools to get things right.

### X under PPC Linux

Properly configuring X to work with your Mac’s hardware involves the creation of a file named *XF86Config*. This file may be located under the */root/,/etc,/etc/X11*, or */usr/X11R6/lib/X11* directories, and contains settings that match your computer’s graphics hardware (such as monitor frequencies and graphics card chipset information).

For X and the PowerPC, many installations default to using a *frame-buffer* server, in which the graphics hardware is modeled using the buffer memory of the computer’s video hardware.
