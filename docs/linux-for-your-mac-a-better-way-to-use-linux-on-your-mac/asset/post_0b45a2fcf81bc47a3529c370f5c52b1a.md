
Not all the output is shown here, but as you can see, this example output corresponds with the previous `/etc/lilo.conf` information. The Extended Mac OS partition resides on `/dev/hda9` and is about 6GB in size. The standard HFS volume (with the name `/boot`) is `/dev/hda10`. The root Linux partition is contained on `/dev/hda1`. The remaining partitions are a swap partition of more than 315MB, a secondary Linux volume labeled `/d2`, and a tiny bit of leftover and unused free hard space.

Other problems can be solved with proper configuration of the kernel (perhaps using kernel arguments) to work with a particular Power Mac's video hardware. In general, you can nearly always safely boot to an install or Linux session by using a framebuffer console, and not taking advantage of any special video hardware. For example, an ultrasafe YaBOOT or LILO kernel argument to use framebuffer console video might look like:

```
append="video=atyfb video=only"
```

A companion program named `fbset` is used to print diagnostic information or to set the console to a different resolution (if supported). For example, you can see the current framebuffer settings by using `fbset` at the console, like this:


In this example, `fbset` prints extended information (as requested by the `-i` option) about your current settings. These settings are changed by using the `fbset` command. This approach, however, will not do you any good if you have video problems after booting. The best approach is to use proper `vmode` and `cmode` arguments (according to your Power Mac model) in your Yaboot configuration file, perhaps like this:

```
append="video=atyfb:vmode=17,cmode=16"
```

In this example, video is set up for a vmode of 1024x768 at 75MHz with a cmode setting of thousands of colors.

Other problems, such as enabling internal hardware (like sound, Ethernet, or an internal modem) are generally solved by kernel updates or updated kernel modules. In nearly all instances, default base sound levels are set through the Mac OS sound settings. This means that by turning up the sound during a Mac OS session and then booting to Linux will enable you to increase volume under Linux. If sound is disabled or set too low during a Mac OS session and you boot to Linux, you may not hear sound at all.

If you run into trouble, check Linux PPC Web sites for information regarding your specific Power Mac model. You will generally find that someone before you has encountered similar problems and has published a solution.

This chapter introduces the Linux shell. The concept of using a shell may seem foreign to some Mac users and even repugnant to die-hard GUI (*Graphical User Interface*) fans. The shell, however, is an integral part of Linux, and can be used with or without the Linux GUI known as the *X Window System*.

Understanding how to use the shell can save you time and effort while learning Linux. Although you can jump right into using Linux without using the shell, you will find that there are some tasks more easily accomplished at the command line, especially if a comparable GUI client does not exist for a task.

In fact, there are many experienced Linux users who have happily abandoned the resource overhead imposed by a GUI and conduct productive and efficient on- and off-line sessions using Linux in its text-only, or *console* mode. Although you do not have to become proficient in using the shell in order to use Linux productively, knowing how to use a shell can certainly help during troubleshooting and maintenance sessions. Working behind the GUI is a commonplace task when using Linux, especially if you want to make quick modifications to your system.

Finally, you should know that many GUI clients available during an *X* session incorporate command-line utilities and use the shell during file or other operations.

# Linux without a Shell?

It is possible to use Linux without a shell. You can do this by editing a user's */etc/passwd* entry on your system, and replacing the field denoting what shell to run upon login with the pathname to a particular program (this is also a good way to check what type of shell you are using by default). When the user logs in, the program will run, instead of a shell. For example, a typical *passwd* entry looks like:

```
bball:x:500:100:William Ball:/home/bball:/bin/bash
```

In this example, the *bash* shell is designated as the login shell. You can replace this with the pathname to another program, such as the *emacs* editor like this:

```
bball:x:500:100:William Ball:/home/bball:/usr/bin/emacs
```

Note that this approach will only work if Linux is set to boot to *console mode*, and not a graphical login.

# What Is a Shell?

A shell is another Linux command. As its name implies, a shell handles interaction between you and the Linux kernel. A shell provides powerful features to the command line. Some of these features will be covered in this chapter.

As a program, a shell can contain its own commands and feature sets, in addition to providing traditional features expected of a shell (such as being a command and language interpreter). At the very least, a shell allows you to interact with the Linux kernel to launch other commands. Many shells also allow you to control other running programs (a feature known as *process control*), control your environment using pre-defined in-memory values known as *environment variables*, and scroll back and forth through previous command lines (a feature known as *history editing*).

As you learn more about using shells, you will also see that many provide an internal, interpreted language that can be used to write complex programs, a process known as *shell scripting*. A program written in a shell's language is known as a *shell script*. As you become more proficient with Linux, you will begin writing your own shell scripts.

In some ways, shell scripts can be as powerful as the Mac OS scripting language, AppleScript. In fact, shell scripting is similar to AppleScript. (It was, however, developed long before AppleScript.) Both facilities provide the following:

* Easily learned syntax
* Scripts developed on one computer that may be used on other computers
* Control of other commands or programs
* Automation of tasks on the computer
* Control of programs and other mechanisms over a network

Linux also includes other programs that can mimic a shell, even though they are part of other software packages. Some of these programs include TcI's *wish*, *tclwish*, *smsh*, and *ggcish*.
