In this example, the standard output or result is a sorted list of words, perhaps the imperfect beginning of a personal dictionary. Further filtering or cleaning will definitely be needed.

However, what about those annoying error messages? They represent the standard error output from the find and cat commands, but are not saved in the resulting file. Is there some way to handle the messages and save them as well? Of course!

Under Linux shells, the stdin, stdout, and stderr are assigned numbers or *file descriptors*. Using the above example (and the `bash` shell), you can save the error output in a file by specifying where to send the output like this:

```
$ find /usr -name README -print 2>errors.txt | \
  xargs cat 2>errors.txt | tr " " "\n" | sort | \
  uniq >out.txt 2>>errors.txt
```

In this example, you will not see any error output to the console, and each command will append any error messages to the file named `errors.txt`.

# Background Processing

Another great feature of using Linux and the shell is the ability to run commands in memory, or as a *background process*. To do this, use the shell's background operator, the ampersand (`&`), at the end of a command line. This is a handy way to have control of the command line returned immediately while another program (or programs) is running.

Our example from the previous section, which created a crude sorted word list and file of error messages, took about one minute on an Apple G4 Cube. Rather than waiting for the task to complete, the entire task could have been committed to memory as a background process like this:
