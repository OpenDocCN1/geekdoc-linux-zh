
# Administering Groups

As a user, you will immediately know if the `/sbin` directory is not in your `PATH`. For example, try using the `ismod` command like this:

```bash
$ ismod
bash: ismod: command not found
```

Adding a new `PATH` to your existing `PATH` is easy. For example, if you use the `bash` shell, use its built-in `export` command like this:

```bash
$ export PATH=$PATH:/usr/local/bin
```

In this example, the `/usr/local/bin` directory is appended to the existing `PATH` variable. Be careful when redefining your `PATH` so that you do not lose the `/bin` or `/usr/bin` pathnames! However, if you do, simply log out and log back in (using the `export` command is not a permanent change). However, when making changes on a system-wide basis as root, you should carefully avoid making editing mistakes.

The system-wide `PATH` variables may be defined in various places, but the `/etc/profile` file is generally used on many systems. Under SuSE Linux, edit the `/etc/profile.local` file to add custom `PATHs`.

Groups are used on a Linux system to associate sets of users. You can use group identification to allow access to groups of users to different files. Groups are defined in the `/etc/group` file on your system, with default group membership assigned to the group named `users` (with a group ID of 100) for all new users.

As a SuSE system administrator, you can use the `gpasswd` command to create new groups and assign membership. This is because SuSE Linux uses a shadow group, which is a more secure group system than LinuxPPC 2000. Although groups are listed in `/etc/group` on a SuSE Linux system, membership to the groups is hidden in a root-owned file named `/etc/gshadow`.

On a LinuxPPC 2000 system, you can see the groups and members by simply examining `/etc/group`. This file may look like (in part):

```text
root::0:root
bin::1:root,bin,daemon
daemon::2:root,bin,daemon
gys::3:root,bin,adm
adm::4:root,adm,daemon

wheel::10:root
users::100:
```

New groups and members are created by adding new entries in the file. For example, if you create a group named *admin*, and you want the users *bball*, *fsmith*, and *dcohen*, create a new entry that looks like this:

```text
admin::700:bball,fsmith,dcohen
```

The numerical entry is a new group ID, and it must be unique for your system. For SuSE Linux, a similar approach is the following sequence of commands:

```bash
# echo "admin:700:" >> /etc/group
# newgrp admin
# gpasswd -a bball admin
Adding user bball to group admin
# gpasswd -a fsmith admin
Adding user fsmith to group admin
# gpasswd -a luser admin
Adding user luser to group admin
# gpasswd admin
Changing the password for group admin
New Password:
Re-enter new password:
```

The first two commands create the new *admin* group definition. Next, three members are added to *admin*. Finally, a password is assigned to the group. Groups may be deleted by using *gpasswd* with its *-r* option, followed by a group's name.

Use the *groups* command to check your group membership. For example:

```bash
# groups
admin users uucp dialout audio video
```

To work in a new group, use the *newgrp* command, followed by the name of one of your groups, like this:

```bash
# newgrp admin
```

After pressing Enter, you will be working in the new group. To return to the default *users* group, type **exit** at the shell prompt and press Enter.

group for a file, you must either own the file or be a member of the new group that will own the file.

# Using Permissions

There are three types of permissions that apply to every Linux file: read, write, and execute. You may have permission to read a file, but if you do not have write permission you cannot change or delete it. On the other hand, you may have execute permission on a directory, but without read permission, you will not be able to see its contents (but you may be able to edit or delete files that you own inside!).

# Changing File Permissions

The `ls` command may be used to examine file permissions, including directory permissions. For example, if you create a file using the `touch` command, then use the `ls` command like this:

```bash
$ touch file
$ ls -l file
-rw-r--r-- 1 bball users 0 Apr 5 16:41 file
```

The `-rw-r--r--` notation designates user, group, and world (or global) permissions. This field notation can also be represented by numbers, such as 644. The user permissions are `rw-`, or $4+2$. The group and global permissions are `r--`, or 4. In this example, you, as the owner, can read and write the file. Members of the group named `users` and anyone else may only read the file. These three sets of permissions are used throughout your Linux filesystem, and through various combinations, are used to restrict or assign read, write, and execute permissions.

You can also view permissions of a directory or various devices. For example:

```bash
$ ls -ld foo2
drwxr-xr-x 2 bball users . 4096 Apr 5 16:52 foo2
$ ls -l /dev/tty80
crw-rw---- 1 root uucp 4, 64 Oct 4 2000 /dev/tty80
$ ls -l /dev/hda1
brw-rw---- 1 root disk 3, 1 Oct 4 2000 /dev/hda1
```

The first letter in the permission notation indicates the type of file, such a `d` for directory, `c` for character device, and `b` for block device. Note that the directory named `foo2` is viewable by anyone because it has `r-x` or read and execute permissions. Only the owner `bball` has `rwx` or read, write, and execute permission.

To change file permissions, use the `chmod` command. To change ownership of files or directories, use the `chown` command (as root). For example, you can create a simple shell script, such as:

```bash
#!/bin/sh
echo "Your system is:"
uname -r
uname -v

echo "Your name is:"
whoami
echo "Your contact info is:"
finger $USER
```

After you create the file (named `me`, in the following example), it will look like this:

```bash
$ ls -l me
-rw-rw-r--   1 bball    bball      124 Apr  6 17:18 me
```

You can then use the `chmod` command to make the file executable like this:

```bash
$ chmod +x me
```

The file will then look like:

```bash
-rwxrwxr-x  1 bball    bball      124 Apr  6 17:18 me
```

You can also take away permission by using the `chmod` command like this:

```bash
$ chmod -x me
```

Another way to add execute permission and restrict use for the owner is with the `chmod` command. This time, however, use the numerical values representing the permission notation for the file:

```bash
$ chmod 744 me
$ ls -l me
-rwxr--r--   1 bball     bball      124 Apr  6 17:18 me
```

Here you can see that only the owner, *bball*, has read, write, and execution permission (*rwx* = 7). All others only have read permission (*r* = 4).

# Changing Device Permissions

You will most often change permissions on your hardware's devices in order to allow users to access a device such as a serial port or modem. This is most often done so that normal users can dial out to establish a PPP connection. For example, trying to access a serial port may report:

```bash
$ echo "AT\n" >/dev/ttyS0

bash: /dev/ttyS0: Permission denied
```

Indeed, if you examine the permissions of the port, you may see:

```bash
$ ls -l /dev/ttyS0

crw-------  1 root  tty    4,  64  May  5  1998  /dev/ttyS0
```

To allow all users access to the modem, use the `chmod` command to grant read and write permission like this:

```bash
# chmod 666 /dev/ttyS0
```

For other devices, such as removable systems or CD-ROMs, the `chmod` command is not necessary. Permissions can be granted for your system’s users by modifying the device’s entry in your Linux filesystem table, `/etc/fstab`.

The filesystem table consists of separate lines for different local or remote file systems. Entries contain several fields, starting with a device name, such as `/dev/hda`. The next field is a mount point, or path where the device is mounted during use. The third field is the type of filesystem, such as `iso9660, hfs, vfat`, or `ext2`. The fourth field consists of mounting options. The fifth field is used during backup operations by the `dump` command. The last and sixth field is used by the `fsck` command to determine the order in which to check the devices during reboots.

For example, the default entry provided by `LinuxPPC 2000` for a CD-ROM may look like:

```text
/dev/cdrom  /mnt/cdrom  auto  noauto  0  0
```

If you attempt to mount or unmount the drive, you may see:

```bash
$ mount /mnt/cdrom

mount: only root can mount /dev/cdrom on /mnt/cdrom
```

On the other hand, `SuSE Linux` provides the following entry:

```text
/dev/cdrom  /cdrom  auto  ro,noauto,user,exec  0  0
```

This entry, with the addition of the `user` flag in the filesystem table entry, allows anyone to mount or unmount a CD-ROM device. The `auto` option following the mount point indicates that the `mount` command should try to automatically determine the filesystem used by the volume. The `exec` option indicates that programs may be run from the drive.

Whether or not you allow these actions may depend on your need for system security.
