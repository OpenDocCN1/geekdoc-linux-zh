Use `/dev/modem` as the designated modem device. Most Linux distributions come with a graphical system administration tool to create this link. For example, the `modemtool` client, included with Yellow Dog Linux and LinuxPPC 2000 and part of the control-panel client, can be used to quickly create the symbolic link by clicking on a button. Launch this client from the panel, or from the command line of an X terminal window, like this:

```bash
$ modemtool &
```

After you press Enter, you will see its dialog box, as shown in Figure 9.1. You must first click to select the proper device, and then click the OK button to create `/dev/modem`.

### Alternatives

If your internal modem is not supported, you can try using a USB serial adapter, such as the Keyspan Model USA-19. This adapter plugs into an available USB port and provides a male DB-9 RS232 adapter that you can hook up to an external modem (it is also handy for hooking up a digital camera for downloading pictures, or a Palm PDA for backup, restore, or software installation). To use this adapter, connect it, and then use the `insmod` command (as root) to load the `usbserial` and `keyspan_pda` kernel modules, like this:

```bash
# insmod usbserial
Using `/lib/modules/2.2.16/usb/usbserial.o`
# insmod keyspan_pda
Using `/lib/modules/2.2.16/usb/keyspan_pda.o`
```

You can then use the `dmesg` command to determine the proper serial device to use for your modem or serial operations, like this:

```bash
# dmesg
...
usbserial.c: Looking at Keyspan PDA Vendor Id=06dc Product Id=0104
usbserial.c: descriptor matches
usbserial.c: found interrupt in
usbserial.c: found bulk out

usbserial.c: Keyspan PDA converter detected
usbserial.c: get_free_serial -
usbserial.c: get_free_serial - minor base = 0
usbserial.c: Keyspan PDA converter now attached to ttyUSB0 (or usb/tts/0 for devfs)
```

Note that not all the output is shown here. In this example, the new serial port is designated as `/dev/ttyUSB0`. You can then use this port for modem operations.

## Network Setup Basics

If you are connecting your system via a LAN and Ethernet to the Internet, congratulations! The task of setting up a connection is a lot easier, and only requires a few simple steps. The good news is that Linux works very well on a network, and your PowerPC will feel right at home, even if the LAN is full of computers using one of those “other” operating systems.

## Required Information

You will first need to know your computer’s hostname and IP address. You can find the hostname by looking at a login or shell prompt, in the file named HOSTNAME under the /etc directory, or in the file named hosts under the /etc directory. If your LAN administrator uses DHCP (Dynamic Host Configuration Protocol) assignment for IP addresses, then you will be assigned what is termed a dynamic IP address. If you are assigned an IP number such as 192.168.2.55, then you have been assigned a static IP address. The difference between a dynamic and static IP address is that with a dynamic address, you will be assigned a new IP address each time you disconnect and then reconnect to your LAN while a static IP address stays the same.

> If you need dynamic addressing, make sure that you have installed the dhcp client on your system. For LinuxPPC 2000, this will be the dhcp-2.0 RPM file. Under SuSE PPC Linux, this will be the dhcp RPM file.

![](img/1ea833f5a3e3c1547e3dd2891f52804a_208_0.png)

You will also need to know the IP address of your LAN’s Internet gateway. A gateway is nothing more than the device that connects two or more networks; in this case, it is the workstation, server, firewall, or other hardware device that connects your LAN to the Internet.

Finally, you will need to know the IP address(es) of your LAN’s Domain Name Servers (that provide DNS). These are one or more computers that hold tables of constantly updated information that quickly translate a numerical IP address to a name (usually in the form of XXX.XXX.XXX.XXX). For example, www.prima-tech.com or www.applecomputer.com.

Once you have this information in hand, you are ready to configure your system. First, make sure your Ethernet interface is installed and recognized by Linux. Next, use one of the administrative tools covered in Chapter 15, “Managing Services,” to properly configure your interface. You can also do this quickly (as root) if you have a static IP address, by using the ifconfig command, like this:

```bash
# ifconfig eth0 yourIPaddress up
```

In this example, the interface is activated by using your assigned IP address. If you have an entry in your system’s /etc/hosts file for your computer and it is associated with your IP address, you can substitute your system's hostname for the IP address. For example:

```text
192.168.2.33  stinkypad.home.org  stinky
```

You can then use the abbreviated (alias) hostname, like this:

```bash
# ifconfig eth0 stinky up
```

After you press Enter, your Ethernet interface should be active. Next, edit your system's /etc/resolv.conf file to contain the one or two (most likely) DNS numbers:

```text
nameserver 199.45.32.38
nameserver 199.45.32.43
```

Following this, you should then be able to add your LAN's gateway (as root) to your Linux kernel's routing table (which is contained in memory) by using the route command, like this:

```bash
# route add default gw yourgateway
```

In this example, yourgateway could be a hostname or IP address. The route command will then force your system to send and receive packets of information through the gateway computer.

Congratulations! You should now be able to check your Internet connection.

> See the section "Network Administration and Utilities" in Chapter 15, "Managing Services" for information on using graphical configuration tools to create network interfaces.

## Checking Mac Connectivity

Linux comes with hundreds of networking utilities, but most users employ the ping command to check network connectivity after connecting to a LAN and the Internet. This command may be employed by any user, and its reports on the time (in milliseconds) that it takes to echo a packet transmission from a remote computer. Use this command with the name of a known remote Internet host, like this:

```bash
# ping -c 3 www.usu.com
PING www.usu.com (213.95.15.200): 56 data bytes
64 bytes from 213.95.15.200: icmp_seq=0 ttl=238 time=133.912 ms
64 bytes from 213.95.15.200: icmp_seq=1 ttl=238 time=133.524 ms
64 bytes from 213.95.15.200: icmp_seq=2 ttl=238 time=140.510 ms
-- www.usu.com ping statistics --
3 packets transmitted, 3 packets received, 0% packet loss
round-trip min/avg/max = 133.524/135.982/140.510 ms
```

In this example, the `-c` or count option is used to limit the number of echoes to three. This example also shows that the system’s Ethernet interface is active, that the connection is able to use DNS, and that there is an active Internet connection. There are other utilities you can use to check network connections, but `ping` seems to work well enough.

If you are able to ping other computers on your LAN, but not through the Internet (perhaps getting an "unknown host" error), check to make sure that you have the correct gateway information and that you have correctly entered the DNS IP addresses in your system’s `/etc/resolv.conf` file. If you are unable to ping other computers on your LAN, inspect your Ethernet card configuration. You should also be able to ping yourself. If you cannot, make sure that you have a local loopback interface and that networking services are active. You can check your Ethernet and loopback interfaces by using the `ifconfig` command, like this:

```bash
$ /sbin/ifconfig
eth0      Link encap:Ethernet  HWaddr 00:90:27:91:92:B5
          inet addr:192.168.2.37  Bcast:192.168.2.255  Mask:255.255.255.0
          UP BROADCAST RUNNING MULTICAST  MTU:1500  Metric:1
          RX packets:2043954 errors:0 dropped:0 overruns:0 frame:0
          TX packets:1860080 errors:0 dropped:0 overruns:0 carrier:0
          collisions:166406 txqueuelen:100
          Interrupt:10 Base address:0xd400
lo        Link encap:Local Loopback
          inet addr:127.0.0.1  Mask:255.0.0.0
          UP LOOPBACK RUNNING  MTU:3924  Metric:1
          RX packets:28705 errors:0 dropped:0 overruns:0  frame:0
          TX packets:28705 errors:0 dropped:0 overruns:0 carrier:0
          collisions:0 txqueuelen:0
```

This example shows the active `lo` (loopback) and `eth0` (Ethernet) interfaces.
