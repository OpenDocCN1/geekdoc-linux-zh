# Instance Numbers

So, what are these instance numbers that the `iocconfig` is keeping for us? An instance number is just a way of uniquely identifying a particular card. Card types are assigned a class by the driver that claims them. This class might be `tty` for a serial interface, `lan` for a LAN interface, or `ext_bus` for a device like a SCSI card that supports multiple remote devices. Within these categories, each card is given an instance number, so if, for example, we might have `ext_bus` numbers 0, 1, and 2 in a particular system. Each number corresponds to a particular card. The numbers are assigned by the G10 when they are bound to a driver, and they need not be sequential. They must be unique within a class but not across classes, so you can have only one `ext_bus0`, but you can also have a `lan0` and a `tty0`.

These numbers are generally represented as a part of the minor number of the device file. In our SCSI tape example the `ext_bus` instance was 0 (for the SCSI card 0) and is represented by the `eo` part of the device filename and by the `0x00` in the upper byte of the minor number.

1/0 Merging1 is important that these instance numbers not change once they've been discovered, which is why we have the `iocconfig` file. If we reassigned the instance numbers at each boot, then removing a card or adding a new card could cause the instance numbers to change, meaning that the device files would now be pointing to different devices.

1/0 merging is a technique to improve disk throughput by gathering together contiguous disk accesses. When a new disk 1/0 is started, rather than just tacking it on the end of the queue, the driver looks through the queue of 1/0s that are waiting to be started to see if any of them are scheduled to access adjacent data on the disk. If so, the new 1/0 is combined with the old so that the system will do one larger 1/0 rather than two smaller ones. This takes advantage of the disk device's ability to read ahead and cache data, and also of the physical nature of disks. A disk access is much quicker if the heads don't have to be moved.

When the 1/0 is completed, there is a corresponding process that unmerges the 1/0 back to the original requests.
