**SHMEM\_MAGIC**

The SHMEM\_MAGIC directive is very similar to the EXEC\_MAGIC in that it combines text and data objects in the process’s Q1. The big difference is that the Q2 does not contain private data but instead has been turned over for use for additional shared objects. It would do very little good to run only one process compiled with this option——after all, who could it share this new space with?

Again noting Figure 5-5, we see that with this option all four quadrants may be mapped to different virtual spaces. In general this option is used in conjunction with another relatively new option, Memory Windows. We examine memory windows in just a moment.

# More Magic

In addition to the three magic directives we have mentioned, there are several others. Compilers designed for HP-UX also understand DEMAND\_MAGIC and SHL\_MAGIC directives. Both of these are enabled by default and deal with the issue of demand page loading and the use of shared libraries located and linked at runtime. We also have RELOC\_MAGIC for loading a program in relocatable-only mode, AR\_MAGIC for linking in archive libraries, and DL\_MAGIC for the inclusion of dynamic libraries. This concludes our magic lesson for now. Let’s move on to memory windows.

# Memory Windows

The memory windowing system was introduced to HP-UX 11.0 as a patch (PHKL\_13810 and PHCO\_13811) and is part of the HP-UX 11.1 release. Figure 5-6 shows a greatly simplified example of a system VAS with memory windows implemented. To enable memory windows on a system, the kernel-tunable parameter max\_mem\_window must be set to the desired number of user windows. The kernel adds 1 to this value and initializes a memory-window array structure during system boot.
