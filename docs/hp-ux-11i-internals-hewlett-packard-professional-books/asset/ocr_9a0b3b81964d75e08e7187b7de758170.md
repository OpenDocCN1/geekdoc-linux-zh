# Calling exec( ) Immediately After vfork( )

In the `vfork( )` / `exec( )` case (where `vfork_state = VFORK_CHILD RUN`), we first need to request the creation of a new uarea for the thread along with minimal vas, pre gion, and region structures. Next, the content of the parent’s uarea (the one we are currently using) is copied to the new one, and another routine is called to switch the thread’s execution trace to the new uarea and kernel stack.

The `vfork_state` is changed to `VFORK_CHILD EXIT`, and we initiate the cleanup of the parent’s context. Once the parent uarea and stack have been restored, the parent wakes up and releases the `vfork_info` buffer as it resumes.

# Calling exec( ) after a fork( )

Following a call to `fork( )`, the newly created child has a vas, pre gions, private and shared regions, and an initial thread and uarea. In this case `get xfile( )` must dispose of most of the existing pre gions and regions. This function is performed by the kernel procedure `dispreg( )`.
