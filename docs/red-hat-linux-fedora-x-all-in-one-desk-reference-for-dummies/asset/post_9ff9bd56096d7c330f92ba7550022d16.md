This file contains NS and A resource records that specify the names of authoritative name servers and their addresses for the root zone (indicated by the . in the first field of each record) with a semicolon.

The comment lines in the file give you hints about the location of the root name servers. There are 13 root name servers for there; most root servers are located in the United States. This file is a necessity for any name server because the name server has to be reach at least one root name server.

## The var/named/localhost.zone file
The /etc/named.conf file includes a zone statement for the localhost zone that specifies the zone file as located in the /var/named directory of Fedora Core system. Here's a listing of what the /var/named/localhost.zone file contains:

```
$TTL 86400
$ORIGIN localhost.
@ 1D IN SOA
@ root ( serial (d. adams)
      42
      3H : refresh
      15M : retry
      1W : expiry
      1D ) minimum

1D IN NS
@ 1D IN A
127.0.1
```

This zone file starts with a $TTL directive that sets the default TTL to one day (86400 seconds) for subsequent records with undefined TTL. Next, a $ORIGIN directive sets the domain name to localhost. After these two directives, the /var/named/localhost.zone file contains three resource records (RRs): an SOA record, an NS record, and an A record. The SOA and the NS record specify localhost as the primary authoritative server. The A record specifies the address of localhost as 127.0.0.1.

## The var/named/named.local file
The third zone statement in /etc/named.conf specifies a reverse-mapping zone 0.1.0.127-in-addr.arpa. For this zone, the file is /var/named/named.local, which contains the following:

```
$TTL 86400
@ IN SOA localhost. (
2700 : Serial
2800 : Refresh
14400 : Retry
360000 : Expire
86400 ) Minimum

IN NS localhost.
IN PTR localhost
```

The SOA and NS records specify localhost as the primary name server. The SOA record also shows localhost as the email address of the technical contact for the domain (the zone format). When sending any email to the contact, you have to replace the first dot with @ and remove the final dot.

## Caching name server: startup and test
Now that you have the configuration files for the caching name server, you can start the name server and let it in operation. To start the name server, log in as root and type the following command in terminal:

```
service named start
```

This command starts the named daemon. To ensure that the name server starts every time you reboot the system, type the following command while logged in as root:

```
config named
```

## Configuring DNS
The named server writes diagnostic messages in /var/log/messages. After you start named, you can check the messages by opening /var/log/messages in a text editor. If no error messages are from named, you can proceed to test the server. Before you use the caching server, you have to specify name server as your primary one. To do so, make sure the first line in /etc/resolv.conf is the following:

```
nameserver 127.0.0.1
```

Now you can use host to test the name server. For example, to look up the IP address of www.google.com using the caching server on localhost, type the following command:

```
host www.google.com localhost
```

Here's the resulting output from the host command:

```
Using domain server:
Name: localhost
Address: 127.0.0.1#53
Aliases:
www.google.com has address 142.250.190.46
```

As the host command uses localhost as the DNS server and returns the IP address of www.google.com, if you get an output similar to this, the caching server is up and running.

## Configuring a primary name server
The best way to configure a primary name server is to start by configuring a caching server (as explained in the previous sections). Then, add master zones for the domains you want this name server to be the primary name server. For example, suppose I want to define a primary name server for the naba.net domain. Here are the steps I go through to configure that name server (after logging in root):

1. Add the following zone statements to /etc/named.conf file:

```
zone "naba.net" {
  type master;
  file "naba.zone";
}
zone "168.192.in-addr.arpa" {
  type master;
  file "168.192.zone";
}
```

2. Create the zone file /var/named/naba.zone with the following lines in it:

```
$TTL 86400
$ORIGIN naba.net.
@ root.naba.net (
    1D IN SOA
    100 : serial
    3H : refresh
    15M : retry
    1W : expiry
    1D ) : minimum

1D IN NS @
1D IN A 192.168.0.7
```

```
XP A 192.168.0.2
```

3. Create the zone file /var/named/168.192.zone with the following lines in it:

```
$TTL 86400
; Remember zone name is: 168.192.in-addr.arpa
@ IN SOA naba.net.root.naba.net (
    1 : Serial
    28000 : Refresh
    14400 : Retry
    360000 : Expire
    86400 : Minimum

IN NS naba.net.
```

```
7 IN PTR naba.net.
2 IN PTR wxp.naba.net.
```

4. To test the new configuration, restart the name server with the following command:

```
service named restart
```

5. Use dig or host to query the DNS server.

For example, here's how I use host to check the address of the host wxp.naba.net at the DNS server running on localhost:

```
host wxp.naba.net localhost
```

Here's the resulting output from the host command:

```
Using domain server:
Name: localhost
Address: 127.0.0.1#53
Aliases:
wxp.naba.net has address 192.168.0.2
```
