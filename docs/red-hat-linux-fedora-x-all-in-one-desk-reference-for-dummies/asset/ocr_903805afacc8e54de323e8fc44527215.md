# 398 Understanding Fedora Core Boots

You get an output listing that starts off like this:

```
PID TTY STAT TIME COMMAND
1 ? S 0:05 init [5]
```

The first column, with the heading PID, shows a number for each process.
PID stands for *process ID* (identification) — a sequential number assigned by the Linux kernel. The first entry in the process list, with a *process ID* (PID) of 1, is the *init* process. It's the first process, and it starts all processes in your Fedora Core system. That's why *init* is sometimes referred to as the “mother of all processes.”

What the *init* process starts depends on the following:

+   * The run level, identifier that identifies a system configuration in only a selected group of processes can exist
* The contents of the /etc/initabb file, a text file that specifies which start at different run levels
* A number of shell scripts (located in the /etc/rc.d directory and its subdirectories) that are executed at specific run levels

Fedora Core has seven run levels — 0 through 6 — and Table 1-1 shows its meanings.

![](bbox=[0.133, 0.468, 0.233, 0.545])

| Table 1-1 |
| Run Level | Meaning Run Levels in Fedora Core |
| 0 | Shuts down the system |
| 1 | Runs in single-user-stand-alone mode (no one else can log in; you work at the text console) |
| 2 | Runs in multiuser mode without the network services (multiuser mode, other users can log in) |
| 3 | Runs in full multiuser, with a text-mode login |
| 4 | Unused in Fedora Core |
| 5 | All services running and enables graphical login |
| 6 | Reboots the system |

The current run level, together with the contents of the /etc/initabb file, controls which processes *init starts*. The initial default run level is 3 for text-mode login screens and 5 for the graphical login screen. You can change the default run level by editing a line in the /etc/initabb file.
