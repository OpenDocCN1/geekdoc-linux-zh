The Linux operating system uses contents of the /etc/fstab file to mount various file systems automatically. From Fedora Core startup, the init process executes a script that runs mount -a command. That command reads the /etc/fstab file and mounts all file systems (except those with the noauto option). The third field on each line of /etc/fstab specifies the type of file system-device and the fourth field shows a comma-separated list of options that the command uses without mounting that file system. You find the defaults option in this field. The defaults option implies—among others that the device mounts at boot time; that the root user can mount the device; that the device mounts for reading and writing. If the options include noauto, the device doesn't mount the system boots.

The kudzu option in the fourth field of /etc/fstab entries indicates that these lines were added by fstab file by the kudzu hardware-detection utility — kudzu runs the updfstab command to add an entry in the /etc/fstab file for DRW/CD-ROM drives (/dev/cdrom and /dev/cdroml). You typically find that the /etc/entries for /dev/fd0 has the option in the fourth field. On a PC with an IDE drive, for instance, the /etc/fstab file has another entry by kudzu that associates the /mnt/zip mount point with the Zip drive (/dev/hhd4), as follows:

```
/dev/hhd4 /mnt/zip  auto noauto,owner,kudzu  0 0
```

# Sharing Files with NFS

Sharing files through the Network File System (NFS) is simple and involves two basic steps:

+   * On the NFS server, export one or more directories listing them in the /etc/exports file and by running the /usr/sbin/exportfs command. In addition, you must run the NFS server (you can do so by logging in as root and typing nfs server start).

+   * On each client system, use the mount command to mount the directories the server has exported.
