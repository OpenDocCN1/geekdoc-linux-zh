## Chapter 3: Writing Shell Scripts

### In This Chapter

- Trying out simple shell scripts
- Learning the basics of shell scripting
- Exploring Bash's built-in commands

Linux gives you many small and specialized commands, along with the plumbing necessary to connect these commands. By plumbing, I mean the way in which one command's output can be used as a second command's input (short for Bourne Again Shell) — the default in Fedora Core provides this plumbing in the form of I/O redirection and pipes. Bash also includes features such as the if statement that you can use commands only when a specific condition is true and the for statement that repeats a specified number of times. You can use these features of Bash when writing programs scripts.

In this chapter, I show you how to write simple shell scripts — task-oriented collections of commands stored in a file. Shell scripts are used to automate tasks. For example, when your Fedora Core system boots, many shell scripts stored in subdirectories in the /etc directory (for example, /etc/init.d) perform many initialization tasks.

### Trying Out Simple Shell Scripts

If you are not a programmer, you may feel apprehensive about programming. But shell scripting (or programming) can be as simple as storing few commands in a file. In fact, you can have a useful shell program that has a single command.

While writing this book, for example, I captured screens from the X Window System and used the shots in figures. I used the X screen-capture program, xwd, to store the screen images in the X Window (XWD) format. The book's production team, however, wanted the screens in TIFF format. Therefore, I used the Portable Bitmap (PBM) toolkit to convert the XWD images to TIFF format. To convert each file, I run two programs as shown follows:

```
xdtopnm < file.xwd > file.pnm
pnmotiff < file.pnm > file.tif
```

These commands assume that the xwdtopnm and pnmtiff programs are in the /usr/bin directory — one of the directories listed in the PATH environment variable. By the way, xwdtopnm and pnmtiff are two programs in the PBM toolkit.

After converting a few XWD files to TIFF format, I tired of typing the sequence of commands for each file, so I prepare a file named totif and save the following lines in:

```
#!/bin/sh
xwdtopnm < $1.xwd > $1.pnm
pnmtiff < $1.pnm > $1.tif
rm $1.pnm
```

Then I make the file executable by using this command:

```
chmod +x totif
```

The chmod command enables you to change the permission settings of a file. One of those settings determines whether the file is executable. The +x option means you want to mark the file as executable. You have to mark it that because Bash runs only executable files.

When I want to convert the file figure.xwd to figure.tif, I can do so by typing the following command:

```
./totif figure
```

The ./ indicates that the totif file is in the current directory — you don't need the ./ prefix in the PATH environment variable includes the current directory. The totif is a shell script (also called a shell program). When you run this script with the command totif figure, the shell substitutes figure for each occurrence of $1 (note that $1 refers to the first option that the user types on the command used to execute the script).

Shell scripts are popular among system administrators. If you are system administrator, you can build a collection of custom shell scripts that help you automate tasks you perform often. If a disk seems to be getting full, you may find files that exceed some size (say, 1MB) and have not been accessed in the past 30 days. In addition, you may want to send an e-mail to all users who have large files, requesting that they archive and clean up these files. You can perform all these tasks with a shell script. You might start with the following find command to identify large files:

```
find -type f -atime +30 -size +1000k -exec ls -l \; \ > /tmp/largefiles
```

### Trying Out Simple Shell Scripts 769

This command creates a file named /tmp/largefiles, which contains detailed information about old files taking too much space. After you get a list of files, you can use a few other Linux commands — such as sort, cut, and sed — to prepare and send mail messages to users who have large files to clean up. Instead of tying all these commands manually, place them in a file and create a shell script. That, in a nutshell, is the essence of shell scripts — to gather commands in a file so you can easily perform system-administration tasks.

Just as most Linux commands accept command-line options, a Bash script also accepts command-line options. Inside the script, you can refer to the options as $1, $2, and so on. The special name $0 refers to the name of the script itself.

Here’s a typical Bash script that accepts arguments:

```
#!/bin/sh
echo "This script's name is: $0"
echo Argument 1: $1
echo Argument 2: $2
```

The first line runs the /bin/sh program, which subsequently processes the rest of the lines in the script. The name /bin/sh traditionally refers to the Bourne shell — the first UNIX shell. In Fedora Core, /bin/sh, which is the executable program.

Save this simple script in a file named simple, and make file executable with the following command:

```
chmod +x simple
```

Now run the script as follows:

```
./simple
```

It displays the following output:

```
This script's name is: ./simple
Argument 1: 1
Argument 2: 2
```

The first line shows the script's name. Because you have run the script without arguments, the script displays no values for the arguments.

Now running the script with a few arguments, like this:

```
./simple "This is one argument" second-argument
```

### Learning the Basics of Shelling

Like any programming language, Bash supports the following features:

- Variables that store values, including special built-in variables for accessing command-line arguments to a shell script and other special values
- The capability to evaluate expressions
- Control structures that enable you to loop over several shell commands or to execute some commands conditionally
- The capability to define functions that can be called in many places within a script.

In the few sections, I illustrate some of these programming features through simple examples. (I'm assuming that you're already running Bash, in which case you can try the examples by typing them at the shell prompt in a terminal window.)
