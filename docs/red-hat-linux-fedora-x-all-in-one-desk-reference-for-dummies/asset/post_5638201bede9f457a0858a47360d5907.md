
## 450 Backing Up and Restoring Files

Use the du -s command to determine the amount of storage you need for archiving a directory. For example, here's how you can get the total size of the /etc directory in kilobytes:

```
du -s /etc
35,724K /etc
```

The resulting output shows that the /etc directory requires at least 35,724K of storage space to back up.

### Backing up on tapes

Although backing up on tapes is simple as using the right device name in the tar command, you have to know some nuances of the tape to use well. When you use tar to back up the device named /dev/st0 (the first tape device), the tape drive automatically rewinds after the tar finishes copying the archive to the tape. The /dev/st0 device name is what you want.

If you can hold several gigabytes of data, you may want to write several archives — one after another — to the same tape (otherwise much of the tape may be empty). If you plan to do so, your tape device can not rewind after the tar finishes. To help with scenarios like this, several tape devices are non-rewinding. The non-rewinding device is called /dev/st0. Use this device name if you want to write one archive after another on a tape.

After each archive, the non-rewinding tape writes an end-file (EOF) marker to save one archive from the next. To do so, use the mt command to move from one marker to the next or rewind the tape. For example, after you finish writing archives to a tape, you can force the tape to rewind with:

```
mt -f /dev/st0 1
```

This positions the tape at the beginning of the next archive. Now use the tar xvf command again to read this archive from the first disk:

```
tar -xvf /dev/st0
```

If you save multiple archives on a tape, you have to keep track of the archives yourself. The order of archives can be hard to remember, so you may be better off simply saving one archive per tape.

### Performing incremental backups

Suppose to back up your system's hard drive on a tape. Because such a full backup can take some time, you don't want to repeat this every night (besides, a small number of files may have changed during the day). To locate the files that need backing up, you can use the find command to list all files that have changed in the last 24 hours:

```
find / -mtime -1 -type f
```

This command prints a list of files that have changed within the last day. The -mtime 1 means the files that were modified less than one day ago. You can now combine this find command with the tar command to back up only those files that have changed within the last day:

```
tar -cvf /dev/st0 'find / -mtime -1 -type f'
```

When you place a command between single quotes, the shell executes that command and places the output at that point in the command line. The result is that the tar program saves only the changed files in the archive. What this process gives you an incremental backup of only the files that have changed since the previous day.

### Performing automated backups

In Chapter 1 of this book, I show how to use crontab to set up recurring jobs (called cron jobs). The Linux system performs these tasks at regular intervals. Backing up your system is a good use of the crontab strategy: as follows:

- Every Sunday at 1:15 am, your system backs up the entire disk on the tape.
- Monday through Saturday, your system performs an incremental backup at 3:10 a.m. by saving only those files that have changed during the last 24 hours.

To set up this automated schedule, log in as root and type the following lines in a file named backups (this example assumes that you use a SCSI drive):

```
15 1 * * 0 cvf /dev/st0 /
10 3 * * 1-6 cvf /dev/st0 'find / -mtime -1 -type f'
```

Next, submit this job schedule by using the following crontab command:

```
crontab backups
```

Now you are set for an automated backup. All you need to do is place a new tape in the tape drive every day. Remember to also give each tape an appropriate label.

## Accessing DOS/Windows File Systems

If you have Microsoft Windows 95/98/Me installed on your hard drive, you've probably already mounted the DOS partition under Fedora Core. If not, you can easily mount DOS partitions in Fedora Core. Mounting makes the DOS directory appear as part of the Linux file system. To identify the DOS partitions easily, you may want to mount the first DOS partition as /dos0, the second and so on.

To determine whether your DOS hard drive partitions are set up to mount automatically, type the grep command to look for the string vfat in the file /etc/fstab:

```
grep vfat /etc/fstab
```

If the output shows one or more lines that contain vfat, your Fedora system mounts DOS partitions automatically.

## Mounting a DOS

To mount a DOS partition in Fedora Core, use the following command:

```
mount -t vfat /dev/sda1 /dos0
```

If you want to unmount the DOS partition, use the unmount command:

```
umount /dos0
```

![](img/d9230b719dc0ef80851f363d8c6f571_478.png)

## Mounting a CD

To mount a CD drive in Fedora Core, use the following command:

```
mount -t iso9660 /dev /mnt/cd
```

If you want to unmount the CD drive, use the unmount command:

```
umount /mnt/cd
```

![](img/d9230b719dc0ef80851f363d8c6f571_479.png)

## Mounting a floppy disk

To mount a floppy disk in Fedora Core, use the following command:

```
mount -t vfat /dev/fd0 /mnt/floppy
```

If you want to unmount the floppy disk, use the unmount command:

```
umount /mnt/floppy
```
