Table 4-1 summarizes the one-letter control operators used in sendmail.cf. Each entry also shows an example of that operator. This table helps you understand some of the lines in sendmail.cf.

| Operator | Description |
| --- | --- |
| C | Defines a class; a variable (think of it as a set) that can contain several values. For example, Cwllocalhost adds the name localhost as the class w. |
| D | Defines a macro, a name associated with a single value. For example, DrMailer-DAEMON defines the macro n MAILER-DAEMON. |
| F | Defines a class that's been read from a file. For example, /etc/local-host-names reads the names of hosts from the file /etc/local-host-names [and] adds them to the class w. |
| H | Defines the format of header lines that sendmail inserts into a message. For example, H?Return-Path:<sg> defines the Return-Path: field of the header. |
| K | Defines a map (a key-value pair database). For example, Karith defines the map named as the compiled-in of the same name. |
| M | Specifies a mailer. The following lines define the procmailer: Procmail=/usr/bin/procmail/DFMSphnu9,FromSMTP/HFromSMTP,REnvToSMTP/HDrSMTP,T-DNS/RFC22/HDrUnX,Aprocmail -Y -m $f su. |
| 0 | Assigns a value to an option. For example, 0 AliasFile=/etc/aliases defines the AliasFile to /etc/aliases, which is the name of the sendmail alias file. |
| P | Defines values for the precedence field. For example, Pjunk-100 sets to -100 the precedence of messages marked with the header field Presence: junk. |
| R | Defines a rule (has a left-hand side and a right-hand side; if input matches the left side, the right-hand side replaces it - this rule is called rewriting). For example, the rewriting R$: $1 strips semicolons. |
| S | Labels a ruleset you start defining subsequent R controls. For example, Canonify=3 labels the ruleset as canonify or rules3. |
| T | Adds a username to the trusted class (class t). For example, Troot adds root to the class of trusted users. |
| V | Defines the major version number of the configuration file. For example, V10/Berkeley defines the version number as 10. |

### Other /etc/sendmail files

The /etc/mail directory contains other files that sendmail uses. These files are referenced in the sendmail configuration file, /etc/mail/sendmail.cf. For example, here's how you can search for the /etc/mail string in the /etc/mail/sendmail.cf:

```bash
grep "\etc/mail" /etc/mail/sendmail.cf
```

Here's what the grep command displays as a result of the search on my Fedora Core system:

- - Fw/etc/mail/local-host-names
- FR -o /etc/mail/mailertable
- Kmailertable hash -o /etc/mail/mailertable.db
- Kvirtuser hash -o /etc/mail/virtertable.db
- Kaccess hash -o /etc/mail/access.db
- #0 ErrorHeader=/etc/mail/error-header
- 0 HelpFile=/etc/mail/helpfile
- 0 UserDatabaseSpec=/etc/mail/userdb.db
- #0 ServiceSwitchFile=/etc/mail/service.switch
- #0 DefaultAuthInfo=/etc/mail/default-auth-info
- #0 CACertPath=/etc/mail/certs
- #0 CACertFile=/etc/mail/certs/cacert.pem
- 0 ServerCertFile=/etc/mail/certs/cert.pem
- 0 ServerKeyFile=/etc/mail/certs/key.pem
- 0 ClientCertFile=/etc/mail/certs/cert.pem
- 0 ClientKeyFile=/etc/mail/certs/key.pem
- Ft/etc/mail/trusted-users

You can ignore the lines that begin with a hash mark or number sign (#) because sendmail treats those lines as comments. The other lines are sendmail control lines that refer to other files in the /etc/mail directory.

Here's what some of these sendmail files are supposed to do (note that not all of these files be present in your /etc/mail directory and even some files may be empty):

- - /etc/mail/access: Names and/or IP addresses of hosts allowed to send mail (in stopping spam — unwanted-email)
- /etc/mail/access.db: Access database generated from /etc/mail/access file
- /etc/mail/helpfile: Help information for SMTP commands
- /etc/mail/local-host-names: Names by which this host is known
- * /etc/mail/mailertable: Mail table used to override how mail is routed (for example, the entry comcast.net smtp:smtp.comcast.net tells sendmail that mail addressed to comcast.net has been sent to smtp.comcast.net)
- * /etc/mail/relay-domains: Hosts that permit relay
- * /etc/mail/trusted-users: List of users allowed to send mail using their user's name without authority
- * /etc/mail/userdb.db: User database file containing information about each user's login name and real name
- * /etc/mail/virtertable: Database of users with virtual-domain addresses hosted on this system

If you edit the /etc/mail/mailertable file, you have to type the following command before the changes take effect:

```bash
makemap hash /etc/mail/mailertable < /etc/mail/mailertable
```

Here is an easier way to make sure that you rebuild everything necessary after making any changes — just type the following commands while logged in as:

```bash
cd /etc/mail
make
```

### The forward file

Users can redirect their own mail by placing a .forward file in their home directory. The .forward file is a plain-text file with comma-separated list of mail addresses. Any mail sent to the user is then forwarded to these addresses. If the .forward file contains a single address, all e-mail for that user is redirected to that single e-mail address. For example, suppose a .forward file containing the following line is placed in the home directory of a user named emily:

```
ashley
```

![](img/d9230b719dc0efd80851f363d8c6f571_688_0.png)

This line causes sendmail to automatically send all e-mail addressed to emily to the username ashley on the same system. User emily does not receive mail at all.

You can also forward mail to a username on another system by listing a complete email. For example, I added a .forward file with the following line to send my messages (addressed to my username, naba) to the mail address naba@comcast.net:

```
naba@comcast.net
```

Now suppose I want to keep a copy of the message on the original system, in addition to forwarding to the address naba@comcast.net. I can do so by adding the line to the .forward file:

```
naba@comcast.net
```

### Invoking procmail in the forward

An interesting use of .forward is to run procmail. For example, suppose you want to delete any from an address containing mailing_list. Here's what you do:

1. Create a .forward file in your home directory and place the following line:

```
/usr/bin/procmail
```

2. Create a text file named .procmail and place the following lines:

```
* ^mailing_list
/dev/null
```

3. Log in as root and set up a symbolic link in /etc/smsh to /usr/bin/procmail with the following command:
```bash
ln -s /usr/bin/procmail /etc/smsh
```

This step is necessary because sendmail uses the Restricted Shell—smsh—to run external programs. Instead of running /usr/bin/procmail, sendmail runs /etc/smsh/procmail. That's why you need the symbolic link. Now's It! If you receive any messages, the message is deleted.

With procmail, you can perform other chores, such as automatically storing messages in a file or forwarding messages to others. All you have to do is create an appropriate .procmail file in your home directory. To find out about procmail, type man procmail. To see examples of .procmail, type man procalex.

### The sendmail alias file

In addition to the sendmail.cf file, sendmail also contains an alias named /etc/aliases to convert a name into an address. The location of the alias file appears in the sendmail configuration file.

Each alias is typically a shorter name for an e-mail address. The system administrator uses the sendmail alias file to forward mail, creating mailing lists (a single that identifies several users), or to refer to a user by different names. For example, here are some aliases:

```
barkakati: naba
naba:naba@lnbsoft
all: naba, leha, ivy, emily, ashley
```

The first line that mail delivered to barkakati is delivered to the user naba on the local system. The second line indicates that mail for naba really is sent to the username naba on the lnbsoft system. The last line defines all as the five users naba, leha, ivy, emily, and ashley. That means mail sent to all goes to these five users.

After defining any new aliases in the /etc/aliases file, you must log in as root and make the new aliases active by typing the following command:

```bash
sendmail -bi
```
