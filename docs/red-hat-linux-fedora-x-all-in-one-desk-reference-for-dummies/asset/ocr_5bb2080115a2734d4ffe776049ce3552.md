# # Is the WEP stream cipher good enough?

WEP uses the RC4 encryption algorithm, which is known as a short secret cipher and generates an infinite stream of pseudorandom bits. Before sending data, the sending station performs an exclusive-OR operation between the pseudorandom bits and the bits representing the data packet, which results in 1 when bits are different and 0 they are the same. The receiver has a copy of the same secret key, and generates an identical stream of bits — performs an identical exclusive-OR operation between this pseudorandom stream and the received bits. So regenerates the original, unencrypted data packet.

Experts say that both these defenses are poorly implemented, WEP ineffective. IC and IV have two main problems:

+   * The Integrity Check is implemented by using a checksum exclusive 32-bit cyclic redundancy check (CRC-32); that checksum is then included as part of the data packet. Unfortunately, an attacker can flip bits in an encrypted message and correctly adjust the checksum to the resulting message appears.

+   * The 24-bit IV is in the clear (unencrypted). There are only 2^24 initial vectors (no choice for a fast machine), and maybe after running through all of them. In other words, after sending 2^24 or 16,777,216 packets, the IV is repeated. The number may also consider the case of a busy access point that sends 1,500-byte packets at a rate of 11 Mbps. Each packet has 8 × 1,500 = 12,000 bits. Each packet has 11,000,000/12,000 = 916 packets. At that rate, the access point sends 16,777,216 / 18,315 seconds. The IV is reused after 5 hours, and that is because many messages are smaller than 1,500 bytes. Thus an attacker has ample opportunity to collect two encrypted messages encrypted with the same key stream — and perform statistical attacks (which amount to try the possible "combinations") really fast) to decrypt the message.

Such method of stream cipher has few problems. If a bit is flipped (from a 0 to 1 or versa) in the encrypted data stream, the corresponding bit is flipped in the decrypted — which can help an attacker decrypt the encryption key. Also, an eavesdropper who intercepts two messages encoded with the same stream can generate the knowledge to mount attacks that can eventually break the encryption.

To counter these weaknesses, WEP uses defenses:

+   * Integrity Check (IC) Field: To make sure that data packets are not modified in transit, WEP uses an Integrity Check field in each packet.

+   * Initialization Vector (IV): To avoid encrypting two messages with the same key stream, WEP uses a 24-bit initialization vector (IV) that augments the secret key to produce a different RC4 key for each packet. The IV is also included in the packet.
