
## Checking Out TCP/IP Networks

### Sniffing network packets

Sniffing network packets — sounds like something illegal, doesn't it? Nothing like that. Sniffing refers to viewing the TCP/IP network packets. The concept is to capture all the network packets so you can examine them later.

![](img/d9230b719dc0efd80851f363d8c6f571_353_0.png)

If you feel like sniffing TCP/IP packets, you can use tcpdump, a command-line utility that comes with Fedora. As its name, it "dumps" (prints) the headers of TCP/IP network packets.

To use tcpdump, log in as root and type the tcpdump command in a terminal window. Typically, you want to save the output in a file for later. Otherwise, tcpdump starts putting out results that just flash by the window. For example, to convert the IP addresses to names, type the following command:

```
tcpdump -a c 1000 > tdout
```

After capturing 1000 packets, tcpdump quits. You can examine the output file, tdout. It's a text file, so you can simply open it in a text editor or use more **dump** to view the captured packets.

The output does some clues about what's going on — each line represents one network packet. Each line starts with a timestamp, followed by details of the packet, information such as where it originates and where it is going. I don't try to explain the details here, but you can type **man tcpdump** to find out more about some of the details (and, importantly, see what other you can use tcpdump).

### Configuring Networks at Boot Time

You want to start your network automatically every time you boot the system. For that to happen, various startup scripts must contain appropriate commands. You don't have to do anything special other than configure your network (either during installation or by using the Network Configuration tool at a later time). If the network fails at startup, however, you can troubleshoot by checking the files in this section.

To initialize your network, the network-activation script uses a set of files in the /etc/sysconfig directory. For example, the script checks the variables defined in the /etc/sysconfig/network file to decide whether to activate the network. in /etc/sysconfig/network, you see a line with the NETWORKING variable as follows:

```
NETWORKING=yes
```

The network activates only if the NETWORKING variable is set to yes.

A number of scripts in the /etc/sysconfig/network-scripts directory activate specific network interfaces. For example, the configuration file for activating the Ethernet interface eth0 is the file /etc/sysconfig/network-scripts/ifcfg-eth0. Here is what:

```
DEVICE=eth0
BOOTPROTO=dhcp
ONBOOT=yes
```

#### Building Your Home Network

If you want to connect the home network to the Internet through DSL or cable modem, you need a hub with enough ports. A hub allows you unique IP addresses. If you start with a hub, you can still add a router later on.

#### Things you need

To set up a home network, you need:
- Two or more PCs. Some have Ethernet built into, whereas others need plug-in cards.
- 10BaseT cables (also called CAT 5 UTP). You need as many cables as the number of computers you plan to connect to hub.

#### Steps to follow

Follow these steps to set up your network:

1. Connect one end of a Cat 5 UTP cable to the RJ-45 Ethernet plug on a computer's network interface and connect the other end to an RJ-45 plug on the hub (or router or switch). How want to snake the wire from the computer to the switch is up to you. For quick-and-dirty networking, simply stringing the wire along the wall may be okay, but for a more permanent setup, you may want to pull the wire through walls and/or ceilings.
2. Repeat Step 1 for each computer on the network.
3. Connect the hub to the power.
4. Configure TCP/IP networking on each PC.

If you are connecting the home network to the Internet through a NAT router (Chapter 1 of this minibook for more information), you can configure each PC to dynamically obtain an IP address because the router uses a DHCP server (a DHCP server can dynamically configure networking on a host). Otherwise, you can assign IP addresses with the 192.168.X prefix. Make sure all PCs have IP addresses that begin with 192.168.X where X is a number from 0 to 254. For example, you could use addresses like 192.168.0.1, 192.168.0.2, 192.168.0.3, and so on. (You get the idea.) See Chapter 2 of this minibook for more information on configuring TCP/IP networking.
