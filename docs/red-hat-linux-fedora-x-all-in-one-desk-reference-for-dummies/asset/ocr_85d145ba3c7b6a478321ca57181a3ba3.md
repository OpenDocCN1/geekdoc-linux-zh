# Resolving Other Installation Problems

I'm sure I haven't exhausted all the installations that are lurking out there. Nobody can. There are many different combinations of components in Intel x86 PCs where Murphy's Law practically requires some combination to exist that the installation cannot handle. This section lists a few known problems. For others, I advise you to go Google Groups (groups.google.com) and type in the symptoms of the trouble. Assuming that others are running into similar problems, you can get some indication how to troubleshoot your way out of your predicament.

# The fatal signal 11 error

Some people get a fatal signal 11 error message during installation and it stops the process. This error usually happens after the initial boot screen as the anaconda installer starts its GUI or text interface. The most likely cause of a signal 11 error during installation is hardware related to memory or the cache associated with the CPU (processor).

![](bbox=[0.107, 0.613, 0.213, 0.693])

Signal 11, also known as SIGSEGV (for Segment Violation), can occur in other Linux methods. A segment violation occurs when a process tries to access a memory location that is not supposed to access. The operating system catches the problem before it happens and stops the process by sending it a signal 11. When that happens during installation, it anaconda made an error while accessing memory, and the most likely reason is some hardware problem. A commonly cure for the signal 11 is to turn off the CPU in the BIOS. To do so, you need to enter SETUP while the PC boots (by pressing a function key such as F2) and then turn off the CPU cache in the BIOS setup menu.

If the problem is due to a hardware error in memory (in other words, the result of bad memory chips), you could swapping the memory modules around in their slots. You may also consider replacing an existing memory module with another memory module, if you have one.

You can read more about the signal 11 problem at www.bitwizard.nl/sig11/
