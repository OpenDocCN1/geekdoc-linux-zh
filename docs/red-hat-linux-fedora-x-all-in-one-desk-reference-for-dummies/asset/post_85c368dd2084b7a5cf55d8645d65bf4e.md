With this syntax, you use <VirtualHost> and </VirtualHost> to enclose a group of directives that applies only to the particular virtual host identified by the hostaddr parameter. The hostaddr can be an IP address or the fully qualified name of the virtual host.

You can place almost any Apache directives within the <VirtualHost> block. At a minimum, Webmasters include the following directives in the <VirtualHost> block:

- DocumentRoot, which specifies where this virtual host's documents reside
- ServerName, which identifies the server to the outside world (this name is a registered domain DNS supports)
- ServerAdmin, the e-mail address of this virtual host's Webmaster
- Redirect, which specifies any URLs to be redirected to other URLs
- ErrorLog, which specifies the file where errors related to this virtual host are to logged
- CustomLog, which specifies the file where accesses to this virtual host are logged

When the server receives a request for a document in a particular virtual host's DocumentRoot directory, it uses the configuration parameters in server's <VirtualHost> block to handle that request.

Here is a typical example of a <VirtualHost> directive that sets up the virtual host: lnsoft.com:

```
<VirtualHost *.lnsoft.com>
  DocumentRoot /home/naba/httpd/https
  ServerName www.lnsoft.com
  ServerAdmin webmaster@lnsoft.com
  ScriptAlias /cgi-bin/ /home/naba/httpd/cgi-bin/
  ErrorLog /home/naba/httpd/logs/error_log
  CustomLog /home/naba/httpd/logs/access_log common
</VirtualHost>
```

Here the name common in the CustomLog directive refers to the name of a format defined earlier in the httpd.conf file by the LogFormat directive, as follows:

```
LogFormat "%h %l %u %t \r%>s %b" common
```

File Transfer Protocol (FTP) is a popular Internet service for transferring files from one system to another. **Anonymous FTP** is another popular Internet service for distributing files. The neat about anonymous FTP is that if a remote system supports anonymous FTP; anyone can use FTP with the anonymous user ID and can download files from that system. Although anonymous FTP is useful for distributing data, it poses a security risk if it's not set properly.

Fedora Core comes with several FTP clients and the "very secure" FTP daemon (`vsftpd`), written by Chris Evans. Fedora Core also includes an RPM called `anonftp` that sets up the files you need to support anonymous FTP. In this chapter, I show you how to configure the FTP server through configuration files and how to control access to the FTP server. I also describe anonymous FTP — how it's set up and how to ensure that it's secure.

## Installing the FTP Server

During Fedora Core installation, you have the option to install the FTP server software. To check if the FTP server is already installed, type the following command:

```
rpm -q vsftpd
```

If the software is indeed installed, you see an output similar to the following:

```
vsftpd-1.2.1-2
```

# Configuring the FTP Server

Fedora Core comes with the very secure FTP daemon (vsftpd), written by Chris Evans. The executable file for vsftpd is /usr/sbin/vsftpd, and it uses a number of configuration files in the /etc and /etc/vsftpd directories. By default, the vsftpd server is disabled — if you want to use the FTP server, first you have to enable it. In this section, I show you how:

The vsftpd server is configured to run-alone, and an initialization script (or initscript) — /init.d/vsftpd — starts and stops the server. To start the vsftpd server, log in as root and type the following command:

```
service vsftpd start
```

You can also type the following command as root to turn vsftpd on it at system startup:

```
chkconfig --level 35 vsftpd on
```

After you the vsftpd server, the default settings are all you need to begin using the server. Because other FTP clients can now connect and request files from your FTP server. However, you need to know about the configuration files in case you need to customize them some other time.

## vsftpd configuration files

The vsftpd server contains a number of configuration files located in the /etc and /etc/vsftpd directories. These directories control many aspects of the FTP server such as whether it runs stand-alone, who can download

files, and whether to allow anonymous FTP. The key configuration files for vsftpd are the following:

- /etc/vsftpd/vsftpd.conf controls how vsftpd server works (for example, it allows anonymous logins, file uploads, and so on).
- /etc/vsftpd.ftpusers lists names of users who cannot access the FTP server.

You can usually leave most of these configuration files with their default settings. However, just in case you have to change something to make vsftpd suit your needs, I explain the configuration files briefly in the next sections.

## /etc/vsftpd/vsftpd.conf file

To find out what you can have in the /etc/vsftpd/vsftpd.conf file and how these lines affect the vsftpd server's operation, by looking at /etc/vsftpd/vsftpd.conf file that is installed by default by Fedora Core. The comments in this file tell you what each option does.

By default, vsftpd allows almost nothing. By editing the options in /etc/vsftpd/vsftpd.conf, you can loosen the restrictions so users can use FTP. You decide how loose the settings are.

Here are some of the options you can set in /etc/vsftpd/vsftpd.conf:

- anon_mkdir_write_enable=YES enables anonymous FTP users to create directories. This option is risky and you may want to set it to NO, if you allow anonymous users to upload files.
- anon_upload_enable=YES means anonymous FTP users can upload files. This takes effect only if write_enable is already set to YES and the directory has write permissions for everyone. Remember: Allowing anonymous users to write on your system can be very because someone could fill up the disk or use your disk for their personal storage.
- anonymous_enable=YES enables anonymous FTP (users can log in with the username anonymous and provide their e-mail address as a password). Comment out this line if you don't want anonymous FTP.
