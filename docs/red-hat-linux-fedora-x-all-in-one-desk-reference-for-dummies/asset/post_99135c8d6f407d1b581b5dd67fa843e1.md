
# Using Yellowdog Updater, Modified (Yum)

- 1. Log in as root, and choose Main Menu::System Tools::Red Hat Network. You can also type `update` in a terminal window.

The Red Hat Update Agent starts, and if you're updating for the first time, a dialog box prompts you to install a public key in your GPG key ring (GPG referring to GNU Privacy Guard or GnuPG, a program for encrypting, decrypting, and signing e-mail and other data using the OpenPG standard.) That public GPG key verifies that the package developer has secured the package that Update has downloaded. If prompted to do so, click Yes to install the public key.

- 2. Update displays a window with a welcome message. Click the Forward button to proceed.

- 3. Update displays a list of what it calls channels—repositories where it downloads package headers. Click Forward to continue.

By default, Update uses a channel that works with Yum — described in the next section — sections are identified in the configuration file `/etc/sysconfig/rhn/sources`. Besides Yum, Update can also access repositories for another package updater. After you click Forward, Update figures out what needs to be updated and retrieves a list of all headers from the specified channel.

- 4. Update downloads the headers, and displays a list of packages. You can scroll through the list and pick the packages you want to update; click the box to the left of a package name to select it. Click Forward to continue. Update then checks for any dependencies and begins downloading the packages. Progress bars show the status of the download.

- 5. After the download finishes, click the Forward button to proceed with the installation.

- 6. Update displays progress bar as it installs each update. Update displays a message about the package(s) it installs successfully.

- 7. Click Finish button to exit.

## Yellowdog Updater, Modified (Yum)

Yellowdog Updater, Modified (Yum) is a command-line utility for updating as well as installing and removing RPM packages. Yum downloads package headers from a specified website and then uses rpm utility to figure out what needs to be installed on your system. Yum is much faster than the alternative where you manually download RPM packages using rpm. Typically you keep your system up to date with the graphical Update Agent because it's easy to use. However, knowing how to run Yum from a command-line is good, in case you have problems with Update. You can read more about Yum and keep up with Yum news by visiting the Yum page at linux.edu/projects/yum/.

The command-line for Yum has the following syntax:

`yum [options] command [packages]`

where options is a list of Yum options, command specifies what you want to do, and packages are the names of packages on which Yum performs action. You must provide the command, but the options and packages are optional. That's why I show them in square brackets. Table 4-2 summarizes Yum commands and Table 4-3 lists some Yum options.

| Command | Yum Commands |
| :--- | :--- |
| check-update | Checks for available updates for your system. |
| clean | Cleans up the cache directory. |
| info | Displays summary information about the specified packages. |
| install | Installs latest versions of specified packages, making sure that all dependencies are satisfied. |
| list | Lists information about available packages. |
| provides | Provides information on which package provides a file. |
| remove | Removes specified packages as well as any packages that depend on the packages being removed. |
| search | Finds packages whose header contains what you specify as the package name. |
| update | Updates specified packages, making sure that all dependencies are satisfied. |

### Table 4-3 Some Yum Options

| Option | Causes Yum to Do the Following |
| :--- | :--- |
| --download-only | Downloads the packages, but does not install them. |
| --exclude=pkg | Excludes the specified package. (You can use this option more than once on the command line.) |
| --help | Displays a help message and quits. |
| --installroot=path | Uses the specified path name as the directory under which all packages are installed. |
| -y | Assumes that your answer to any question is yes. |

If you want Yum to update your system, just type the following (you have to be logged in as root):

```
yum update
```

Yum consults its configuration file, `/etc/yum.conf`, and does everything needed to update the packages installed on your system.

You can specify package names to update only some packages. For example, to update the kernel and xorg-x11 packages, using the following Yum command:

```
yum update kernel* xorg-x11*
```

This updates all packages whose names begin with kernel and xorg-x11.

You may use the options to further instruct Yum what to do. For example, if you want to download the packages, but not install them, type:

```
yum --download-only update
```

Another typical option is --exclude, which enables you to exclude one or more packages from the update process. Suppose you want to update everything except the GNOME packages (whose names begin with gnome) and the rhythmbox package. Then you type the following Yum command:

```
yum --exclude=gnome* --exclude=rhythmbox update
```

## Understanding Linux Devices

Linux treats all devices as files. As Figure 5-1 shows, applications can access a device as if it were a file. These are special files called *device files*, and they appear in the /dev directory in the Linux file system.

If you use the `ls` command to look at the list of files in the /dev directory, you see several thousand files. These files do not mean that your system has several thousand devices. The /dev directory has files for all possible types of devices.

How does the kernel know which device driver to use when an application opens a device file? The answer is in two numbers called the *major* and *minor* device numbers. Each device file is mapped to a specific device driver through these numbers.

To see an example of the major and minor device numbers, type the following command in a terminal window:

```
ls -l /dev/hda
```

You see a line of output similar to the following:

```
brw-rw-- 1 root disk 3, 0 Jul 23 14:50 /dev/hda
```

In this line, the major and minor device numbers appear just before the date. In this case, the major device number is 3 and the minor device number is 0. The kernel selects the device driver for this device file by using the major device number.
