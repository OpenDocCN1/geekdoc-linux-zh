You can use the mount command to manually mount a device on the Linux file system at a specified directory. That directory is the mount point. For example, to mount the DVD/CD-ROM drive at /mnt/cdrom directory, you type the following command (after logging in as root):

```
mount /dev/cdrom /mnt/cdrom
```

The mount command reports an error if the DVD/CD-ROM device is mounted already or if no CD or DVD media is in the drive. Otherwise, the mount operation succeeds, and you can access the DVD or CD's contents through /mnt/cdrom directory.

You can use any directory as the mount point. If you mount a device on a nonempty directory, however, you cannot access the files in that directory until you unmount the device by using the unmount command. Therefore, always use an empty directory as the mount point.

Fedora Core comes with the /mnt/cdrom directory for mounting DVDs and CDs and /mnt/floppy for mounting floppy drives.

To unmount a device when you no longer need it, use the umount command. For example, to unmount the DVD/CD-ROM device, type

```
umount /dev/cdrom
```

The umount command succeeds as long as no one is using the DVD/CD-ROM. If you get an error when trying to unmount the DVD/CD-ROM, check to see whether the current working directory is on the DVD or CD. If you're currently working in one of the DVD/CD-ROM's directories, that also qualifies as a use of the DVD/CD-ROM.

# Examining the /etc/fstab file

The mount command has the following general format:

```
mount device-name mount-point
```

However, you can mount the CD-ROM by typing one of the following

```
mount /dev/cdrom
mount /mnt/cdrom
```

![](img/d9230b719dc0efd80851f363d8c6f571_468_0.png)

You can mount by specifying only the CD-ROM device name or the mountpoint because of what's in a file named /etc/fstab. A line is in /etc/fstab for the /mnt/cdrom mount point. That entry specifies the CD-ROM device name and the file-system type. That's why you can mount the CD-ROM with a shorter mount command.

The /etc/fstab is a configuration file — a text file containing information that the mount and unmount commands use. Each line in the /etc/fstab file provides information about a device and its mount point in the Linux system. Essentially, the /etc/fstab associates various mount points within the file with specific devices, which enables the mount to work from the command line with only the mount point or the device.

Here is a /etc/fstab file from Fedora Core:

| LABEL=-/ | ext3 defaults 1 1 |
| :--- | :--- |
| LABEL=/boot | /boot ext3 defaults 1 2 |
| | /dev/pts devpts gid=mode=620 0 0 |
| | /dev/shm tmpfs defaults 0 0 |
| none | /proc procfs defaults 0 0 |
| none | /sys sysfs defaults 0 0 |
| /dev/hda6 | swap defaults 0 0 |
| /dev/cdrom | /mnt/cdrom udf.iso9660 auto,owner,kudzu.ro 0 0 |
| /dev/fd0 | | auto,owner,kudzu.ro 0 0 |
| /dev/cdrom1 | /mnt/cdrom1 udf.iso9660 auto,owner,kudzu.ro 0 0 |


The Linux operating system uses contents of the /etc/fstab file to mount various file systems automatically. From Fedora Core startup, the init process executes a script that runs mount -a command. That command reads the /etc/fstab file and mounts all file systems (except those with the noauto option). The third field on each line of /etc/fstab specifies the type of file system-device and the fourth field shows a comma-separated list of options that the command uses without mounting that file system. The defaults option in this field implies—among others—that the device mounts at boot; that the root user can mount the device; that the device mounts for reading and writing. If the options include noauto, the device doesn't mount. The option in the fourth field of /etc/fstab indicates that these lines were added by hand. You typically find the entries for /dev/fd0 has the option in the fourth field. On a PC with an IDE drive, for instance, the /etc/fstab has another entry that associates the /mnt/zip mount point with the device (/dev/hda4), as follows:

```
/dev/hda4 /mnt/zip auto,owner,kudzu 0 0
```

# Sharing Files with NFS

Sharing files through the Network File System (NFS) is simple and involves two basic steps:

- On the NFS server, export one or more directories listing them in the /etc/exports file and running /usr/sbin/exportfs. In addition, you must run the NFS server (you can do so by logging in as root and typing nfs start).
- On each client system, use the mount command to mount the directories the server has exported.

# 444 Sharing Files with NFS

The only problem using NFS is that each client system must support it. Most PCs do not come with NFS — that means you have to install NFS separately if you want to share files using NFS. If, however, all systems on your LAN run Linux (or other variants of UNIX with built-in support), NFS makes sense.

Note: NFS has security vulnerabilities. Therefore do not set up NFS on systems directly connected to the Internet. In the upcoming section, I walk through NFS setup using an example of two Linux PCs on a LAN.

# Exporting a file system with NFS

Start with the server system that exports — makes available to the client systems. On the server, you must run the NFS service and also designate one or more file systems to be exported. To export a file system, you have to add an appropriate entry to the /etc/exports file. For example, suppose you want to export the /home directory and you want to enable the host named fp75 to mount this file system for read-write operations (you can use a host's IP address in place of the host name). You can do so by adding the following entry to the /etc/exports file:

```
/home fp75(rw)
```

After adding the entry in the /etc/exports file, manually export the file system by typing /usr/bin/exports -a in a terminal window. This command exports all file systems defined in the /etc/exports file. Now start the NFS server — log in as root and type the following command in a terminal window:

```
service nfs start
```

To restart the NFS service, you can service nfs restart. When the NFS service is up, the server side of NFS is ready. Now you can try to mount the exported file system from a client system and access the exported file system. If you ever make any changes to the exported file systems listed in the /etc/exports file, remember to restart the NFS service. To do so, type service nfs restart in a terminal window.

# Mounting an NFS file system

To access an exported NFS file system on a client system, you have to mount that file on a mount point — which is, in practical terms, more than a local directory. For example, suppose you want to access the /home directory exported from the server named fp200 at the local directory /mnt/fp200 on the client system. To do so, follow these steps:

1. Log in as root, and create the directory with the following command:
   mkdir /mnt/fp200
2. Type the following command to perform the mount operation:
   mount fp200:/mnt/fp200
3. Change the directory to /mnt/fp200 with the command cd /mnt/fp200

Now you can view and access exported files from this directory.

To confirm that the NFS file system is mounted, log in as root on the client system and type mount in a terminal window. You see a line similar to the one about the NFS file system:

```
fp200:/home/public /mnt/fp200 type nfs (rw,addr=192.168.1.200)
```

# Selecting a backup strategy and media

Your Fedora Core system drive contains everything you need to keep the system running — as well as other files (such as documents and databases) that you have to back up these files so you can recover quickly and bring the system back to normal in case the hard drive crashes. Typically, you have to follow a strict regimen of regular backups because you can never tell when the hard drive may fail or the file system may corrupt. To implement such a regimen, first decide which files you want to back up, how often, and what storage media to use. This process is what I mean by selecting a backup strategy and backup media.
