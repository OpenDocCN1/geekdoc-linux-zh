Internally, the 2.6 kernel raises many internal limits for number of users to the maximum number of open files. For example, number of unique users and groups has been increased from 65,536 to over 4 billion. The maximum number of open files can now grow as needed. File systems can be as large as 16TB (that's about 16,000 gigabytes!).

Linux 2.6 also increases the limits on the major and minor device numbers, which were used to a maximum of 255 in earlier kernels. These device numbers translate to 255 types and 255 devices of a single type. In kernel version 2.6, the major device numbers can be up to 4,095 and minor device numbers can be more than a million. The upshot is that Linux 2.6 can support more device types and many devices of a single type.

## Improved device handling

Linux 2.6 has many of new features for handling devices — especially hot plug devices such as the ones that connect to USB and Firewire interfaces common in today's PCs. First, the kernel uses a virtual file system called sysfs which is meant to hold information about the devices on the system. The sysfs file system mounts /sys and it presents a hierarchical view of all the devices by device type, bus, and so on. Through sysfs, the 2.6 kernel makes available to other applications a lot of information about devices, including the name of a device, resources such as interrupts and I/O ports used by the device, the power status of device, and so on.

By using sysfs capabilities available in the 2.6 kernel, a separate device handling program called udev can now dynamically add devices when a device is added to a system. The udev program is invoked by the /sbin/hotplug script that runs when any hot plug device is plugged into the computer. udev gives each device a name that stays the same time device connects to the system. In Fedora Core, udev is not configured by default to manage the device files in /dev directory. Instead udev manages device files in the /udev directory. However, you can easily configure udev (through the /etc/udev/conf file) to manage the device files in /udev directory.

Other device handling improvements in Linux 2.6 include ensuring that device drivers are not unloaded while still in standardization the way in which device drivers make available information about devices they support. — kernel object — instead of the generic .o extension used for object files.

Linux 2.6 also has improved support for many devices such as USB 2.0 and wireless devices. As storage devices, the Integrated Drive Electronics (IDE) — also called AT Attachment (ATA) — Small Computer System Interface (SCSI) support was updated in Linux 2.6. For example, IDE CD-recorders are now accessed through the IDE instead of a special SCSI-emulation driver that was used in earlier versions of the kernel. The 2.6 kernel also supports the new Serial ATA (SATA) interface that can support data transfer rates of 150MB per second.

## Mandatory access control with Security Enhanced Linux (SELinux)

Linux kernel 2.6 includes the access control framework developed by Security Enhanced Linux (SELinux), which was developed by the National Security Agency (NSA), a U.S. government agency. SELinux is implemented as a Security Module (DSM) — an extension of the Linux kernel that allows security mechanisms to be easily added to the kernel. You can find more about SELinux at NSA's Web site, .www.nsa.gov/selinux/.

Without SELinux, access control is based on user and group owns a process or file. In this discretionary access control approach, the superuser (root) has absolute discretion and can do anything on the system. In contrast to this approach, SELinux views the system in terms of subjects (users or processes) and objects (files, devices, any system resources). Subjects can take different roles as normal user or system administrator. Each subject also has a domain and each object has a type. SELinux provides fine-grained control over who can access what in a Linux system by defining what controls and how one domain can transition into another through executes.

The mandatory access control rules are defined in the SELinux security policy. To support the fine-grained access control, all files need additional attributes that are stored in labels to define the file. Think of the contexts as information on how roles can access and do what with the file. When SELinux is enabled, all files in the file system have to be labeled with the security contexts. Only then SELinux can manage the fine-grained access control.

When you install Fedora Core, you can choose selinux at the installer's boot: prompt to install SELinux and select the level of access control you want SELinux to enforce. This option appears in the screen where you configure the firewall.

Note: SELinux can be very helpful in securing your organization's external Web and e-mail servers that are exposed to the Internet and, therefore, to attacks. With a well-designed security policy, SELinux can make Internet-facing servers resistant to damage from attacks, even if an attacker manages to gain superuser privileges. However, the additional effort involved in setting up and running SELinux may not be worthwhile for internal servers not directly connected to the Internet.

# What Fedora Core Includes

Fedora Core comes with the Linux kernel and a whole lot more software. These software packages include everything from the graphical desktops to Internet servers and programming tools to create new software. In this section, I briefly describe some software packages that come bundled with Fedora Core. Without this bundled software, Fedora Core wouldn't be as popular as it is today.

## GNU software

I start with a collection of software that came from the GNU Project. You get to know which GNU utilities only if you use your Fedora Core system through a terminal (or a graphical window that mimics one) — a basic command-interface that puts nothing on-screen but a prompt at which you type in your commands. The GNU software is one of the basic parts of Fedora Core.

As a Fedora user, you may not realize the extent to which Fedora Core (and, for matter, all distributions) rely on GNU software. Nearly all tasks you perform in a Linux system involve one or more software packages. For example, the GNOME graphical user interface (GUI) and the command interpreter (that is, Bash shell) are both GNU software programs. By the way, the shell is the command-interpreter application that accepts the commands you type and runs programs in response to those commands. If you rebuild the kernel or develop software, you do so with the GNU C and C++ compiler (which is part of the GNU software that accompanies Fedora Core). If you edit text files with the ed or emacs editor, you're again using a GNU software package. The list goes on and on.

## What is the GNU Project?

GNU is a recursive acronym that stands for GNU' Not Unix. The GNU Project was launched in 1984 by Richard Stallman to develop a complete UNIX-like operating system. The GNU Project developed nearly everything needed for the operating system kernel. All software distributed under the GNU General Public License (GPL) essentially requires that the software is distributed in source-code form and stipulates that any user may copy, modify, and distribute the software to anyone else in source-code form. Users may, however, have to pay for their individual copies of GNU software.

The Free Software Foundation (FSF) is a tax-exempt charity that raises funds for work on the GNU Project. To find out more about the GNU Project, visit its home page at www.gnu.org. You can find information about how to contact the Free Software Foundation and how to help the GNU Project.
