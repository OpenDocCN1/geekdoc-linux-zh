- **Domain name**: Contains the fully qualified name of the computer that has the file URL specifies. You can also provide an IP address in this field. The domain name is not case sensitive.
- **Port**: Port that is used by the protocol in the first part of the URL. The URL is optional; all protocols have default ports. The default port for HTTP, for example, is 80. If a site configures the server to listen to a different port, the URL has to include the port number.
- **Directory path**: Path of the file being referred to in the URL. For Web pages, this is the directory path of the HTML file. The directory path is case sensitive.
- **Filename**: Name of the file. For Web pages, the filename typically ends with .html or .htm. If you omit the filename, the Web server returns a default file (often named index.html). The filename is case sensitive.
- **HTML anchor**: Optional part of the URL that allows the Web browser to jump to a specific location in the file. If this starts with a question mark (?) instead of a hash mark (#), the browser takes the text following the question mark to be a query.

# Web servers and Web browsers

The Web server serves up the Web pages, and the Web browser downloads and displays them to the user. That's pretty much the story with these two cooperating software packages that make the Web work.

 a typical scenario, the user sits in front of a computer's connected to the Internet and runs a Web browser. When the user clicks a link or types a URL into the Web browser, the browser connects to the Web server and requests a document from the server. The Web server sends the document (usually in HTML format) and ends the connection. The Web browser interprets and displays the HTML document with text and graphics.
