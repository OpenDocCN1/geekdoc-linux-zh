# Checking connectivity to a host

To check for a network connection to a specific host, use the ping command is a widely used TCP/IP tool that uses a series of Internet Control Message Protocol (ICMP, pronounced eye-comp) messages. ICMP provides for an Echo message to which each host responds. The ICMP messages and replies, ping can determine whether or not the other system is alive and can compute the round-trip delay in communicating with that system.

The following example shows how I run ping to see a system on my network is alive:

```
ping 192.168.0.1
```

Here is what command displays on my home network:

```
PING 192.168.0.1 (192.168.0.7 : 56(84) bytes of data.
64 bytes from 192.168.0.1: icmp_seq=1 ttl=254 time=1.36ms
64 bytes from 192.168.0.1: icmp_seq=2 ttl=254 time=1.33ms
64 bytes from 192.168.0.1: icmp_seq=3 ttl=254 time=1.36ms
64 bytes from 192.168.0.1: icmp_seq=4 ttl=254 time=1.34ms

192.168.0.1 ping statistics
4 packets transmitted, 0% loss, time 302ms
trt min/avg/max/dev=1.338/1.351/1.366/0.038
```

In Fedora Core, ping continues to run until you press Ctrl+C to stop; it displays statistics showing the typical time it takes to send a packet between the two systems. On some systems, ping simply reports that a remote host is alive. However, you can still get the time information using appropriate command-line arguments.

# Checking network status

To check the status of the network, use the netstat command. This displays the status of network connections of various types (such as TCP and UDP protocols). The status of the interfaces with netstat -i, as you can view:

```
netstat -i
Kernel Interface table:
Interface MTU RX OK RX-ERR RX-DRV RX-FS TX OK TX-ERR TX-DRV TX-FS Flags
eth 1500 0 94237 0 0 0 74889 0 0 0 BMRU
eth1 1500 0 3942 0 0 0 24 1 0 0 BMRU
lo 16436 0 3255 0 0 0 3255 0 0 0 LRU
```
