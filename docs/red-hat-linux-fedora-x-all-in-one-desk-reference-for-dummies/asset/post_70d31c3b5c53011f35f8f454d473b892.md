## Creating a shared library

Creating a shared library for your own application is fairly simple. Suppose you want to implement an object in the form of a shared library (think of an object as a bunch of code and data). A set of functions in the shared library represents the object's interfaces. To use it, you load its shared library and invoke its interface functions.

Here is the source code for this simple object, implemented as a shared library (you might also include dynamically linked libraries)—save this code in a file named dynobj.c:

```c
/*
* File: dynobj.c
* Demonstrate use of dynamic linking.
* Pretend this is an object that can be created by calling init and destroyed by calling.
*/
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

/* Data structure for this object */
typedef struct {
    char *name;
    int version;
} OBJDATA;

/* init
* Initialize object (allocate storage).
*/
void* init(char *name) {
    OBJDATA *data = (OBJDATA*)calloc(1, sizeof(OBJDATA));
    if(name) {
        data->name = malloc(strlen(name) + 1);
        strcpy(data->name, name);
    }
    printf("Created: %s\n", name);
    return data;
}
```

```c
/* show
* Show the object.
*/
void show(void *data) {
    OBJDATA *d = (OBJDATA*)data;
    printf("show: %s\n", d->name);
}

/* destroy
* Destroy the object (free all storage).
*/
void destroy(void *data) {
    OBJDATA *d = (OBJDATA*)data;
    if(d) {
        if(d->name) {
            printf("Destroying: %s\n", d->name);
            free(d->name);
        }
        free(d);
    }
}
```

The object offers three interface functions:

- init to allocate any necessary storage and initialize the object
- show to display the object (here, it simply prints a message)
- destroy to free any storage

To build the shared library named libdynobj.so, follow these steps:

1. Compile all source files with the -fPIC flag. In this case, compile the dynobj.c file using this command:
   `gcc -fPIC -c dynobj.c`
2. Link the objects into a shared library with the -shared flag and appropriate flags for the linker. To create the shared library named libdynobj.so.1, use the following:
   `gcc -shared -Wl,-soname,libdynobj.so.1 -o libdynobj.so.1 dynobj.o`
3. Set up a sequence of symbolic links so that programs using the shared library can refer to it with a standard name.
   For the sample library, the standard name is libdynobj.so, and the following commands set up the symbolic links:
   ```bash
   ln -sf libdynobj.so.1.0 libdynobj.so.1
   ln -sf libdynobj.so.1.1 libdynobj.so
   ```
4. When you test the shared library, define and export the LD_LIBRARY_PATH environment variable using the following command:
   ```bash
   export LD_LIBRARY_PATH=$LD_LIBRARY_PATH
   ```

After you test the shared library and are satisfied that the library works, copy it to a standard location, such as /usr/local/lib, and run the ldconfig utility to update the link between libdynobj.so.1 and libdynobj.so.0. These are the commands you use to install your shared library for everyone's use (you will have to root to perform these):

```bash
cp libdynobj.so.1.0 /usr/local/lib
/sbin/ldconfig
cd /usr/local/lib
ln -s libdynobj.so.1 libdynobj.so
```

## Dynamically loading a shared library

Loading a shared library in your program and using the functions within the shared library is simple. In this section, I demonstrate the way you do this action. The header file <dlfcn.h> (that's a standard header file in Linux) declares the functions for loading and using a shared library.
