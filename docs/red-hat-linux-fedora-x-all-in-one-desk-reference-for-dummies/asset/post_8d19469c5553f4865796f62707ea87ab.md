## Building the software from source files

After you unpack the compressed tar archive, all source files are in a directory name which is usually that of the software package with a version suffix. For example, the XMMS version 1.2.10 source files extracts to the xmms-1.2.10 directory. To start building the software, change directories with the following command:

```
cd xmms*
```

You do not have to type the entire name — the shell can expand the name and change to the xmms-1.2.10 directory.

Nearly all software packages come with some sort of file name README or INSTALL file — a text file tells you how to build and install the package. XMMS is no exception; it comes with a README file you can type by merging README. An INSTALL file contains instructions for building and installing XMMS.

Most open-source software packages, including XMMS, also come with a file name COPYING. This file contains the text of the GNU General Public License (GPL), which spells out the conditions under which you can use and redistribute the software. If you are not familiar with the GNU GPL, read this file and show the license to your legal counsel for a full interpretation and assessment of applicability to your business.

To build the software package, follow the instructions in the README or INSTALL file. For the XMMS package, the README file lists some of the prerequisites (such as libraries) and tells you what commands to build and install the package. In the case of XMMS, the instructions tell you to use the following steps:

- 1. Type ./configure to run a script that creates your system configuration and creates a file named Makefile — a file make command used to build and install the package. You can type ./configure-help to see a list of options that configure accepts.

- 2. Type make to build the software. This step compiles the source files in all the subdirectories; source code converts each source file into an object file — a file binary instructions that your PC's processor can understand.

- 3. Type make to install the software. This step copies libraries and executable binary files to appropriate directories on your system.

Although these steps are specific to XMMS, most other packages follow these steps — configure, make, and install. The configure shell script guesses system-dependent variables and creates a Makefile with commands needed to build and install the software.

Usually, you don't have to do anything but type the commands to build the software, but you must install the Software-development tools when you install your system. You must install the Software Development package when you install Fedora Core. To build and run XMMS, you must also install the X Software Development package because it's an X application.

To begin building XMMS, type the following command to run the configure script (you must be in the xmms-1.2.10 directory when you type this command):

```bash
./configure
```

The configure script runs and prints logs of messages as it compiles various features of your system — from the existence of the C compiler to various libraries needed to build XMMS. Finally, the configure script creates a Makefile you can use to build the software.

If the configure script displays errors and fails, review the INSTALL and README files to find any clues to solving the problem. You may be able to circumvent it by providing some information to the configure script through command-line arguments.

After the configure script finishes, build the software by typing make. The make command runs the GNU utility, which reads the Makefile and starts compiling the source files according to information specified in the Makefile. The make command goes through all the source directories, compiles the source files, and creates the executable files and libraries needed to run XMMS. You see a lot of messages as each file is compiled. These messages show the commands used to compile and link the files.

The make command can take 10 to 15 minutes to complete. After make is done, you can install the XMMS software with the following command:

```bash
make install
```

This command runs GNU make, but the install argument instructs GNU make to perform a specific set of commands from the Makefile. These instructions essentially go through all the subdirectories and copy all files to their final locations. For example, the binary executable files xmms, gnomexmms, wmxmms, and xmms-config copy to the /usr/bin directory.

## Installing SRPMS

If you have the source CDs for Fedora Core (you can download the source-CD images from the sites listed at fedora.redhat.com/download/mirrors.html), you can install the source files and build applications directly from the source. Red Hat has the source-code files in RPMs, just as with executable binary files, and these source RPM are generally known as SRPMS (for source RPMs).

To install a source RPM and build the application, follow these steps:

- 1. Mount the DVD-ROM by typing /mnt/cdrom or waiting for the GNOME desktop to mount the DVD.

- 2. Typically source RPMs are in the SRPMS directory. Change to that directory by typing the following command:
```bash
 /mnt/cdcd/SRPMS





 3. Install the the RPM file using the the -i command.. For,, install the the server (httpdd source,
```bash
rpm -ivh httpd*.src.rpm
```

The files installs in the /usr/src/redhat/SOURCES directory. A spec file with a .spec extension is placed in the /usr/src/redhat/specs directory. The spec file describes the software and also contains information used to build and install the software.

- 4. Use the rpmbuild command with the spec file to build the software. You perform different tasks from unpacking the source files to building and installing the binaries by using different options with the rpmbuild command. For example, to process the entire spec file, type:
```bash
rpmbuild -ba packageName.spec
```

Here packageName is the name of the SRPM. This command typically builds the software and installs the binary files.
