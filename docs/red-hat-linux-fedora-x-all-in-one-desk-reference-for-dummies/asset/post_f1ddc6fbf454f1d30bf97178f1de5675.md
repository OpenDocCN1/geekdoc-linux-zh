The modprobe command consults the /etc/modprobe.conf file to convert an alias to the real name of a driver module as well as for other tasks, such as obtaining parameters for driver modules. For example, you can insert lines that begin with the options keyword to provide values of parameters that a driver may need.

For example, to set the debug level parameter for the Ethernet driver to 5 (this parameter generates lots of information in /var/log/messages), I add the following line to the /etc/modprobe.conf file:

```
options 3c59x debug=5
```

This line specifies 5 as the value of the parameter named debug in the 3c59x module.

If you want to know the names of the parameters a module accepts, use the modinfo command. For example, to view information about the 3c59x driver, I type

```
modinfo 3c59x | more
```

From the resulting output, I can tell that debug is the name of the parameter for setting the debug level.

Unfortunately, the information shown by the modinfo command can be somewhat cryptic. The only saving grace is that you may not have to do much more than using a graphical utility to configure the device, and the utility takes care of adding whatever is needed to configuration files, such as /etc/modprobe.conf.

# Managing USB Devices

Fedora Core comes with built-in support for the Universal Serial Bus (USB) — a bus that's gradually replacing the functionality of the PC's serial and parallel ports, as well as that of the keyboard and mouse ports. Nowadays, many peripherals — such as mouse, keyboard, printer, CD burner, scanner, digital camera, memory card, and so on — are designed to connect to the PC through a USB port.

USB version 1.1 supports data-transfer rates as high as 12 Mbps — 12 million bits per second or 1.5MB per second — compared with 11 Kbps on the bus or 0.115 Mbps transfer rate of a standard serial port. The bus can also chain up to 127 devices on a single USB bus, and you can attach or remove devices while the PC is running — a capability commonly referred to as hotplug or hot swap. USB version 2.0 (or USB 2.0 or USB2)

![](img/d9230b719dc0efd80851f363d8c6f571_512_0.png)

ups the ante by raising the data transfer rates to a whopping 480 Mbps, slightly faster than the competing IEEE 1394 (FireWire). Nowadays devices, such as CD burners and scanners, can come with the high-speed USB2 interface. If your PC has older USB 1.1 protocols, the USB2 devices can still work up, albeit at lower data-transfer rates. Fedora Core supports both USB 1.1 and USB2 interfaces.

Using USB devices in Fedora Core is easy. You can hotplug a device into a USB port, and the Linux kernel can detect and load the appropriate drivers so applications can use the device. To be more precise, the kudzu hardware detection takes care of the chores necessary to make the USB device accessible to applications. For USB storage devices, such as CD drives or hard drives, kudzu can also mount the device on the Linux file system. For examples of using USB mass-storage devices, see Book II, Chapter 4 where Linux detects a USB CD burner and how to access the ports in a digital camera through the USB interface.

To use a printer in Fedora Core, simply connect the printer to the USB port, power it up, and then follow the steps in Book I, Chapter 3 to configure a locally connected queue for the printer. The printer shows up with a device name as /dev/usb/1p0 (for the USB printer detected by kudzu), /dev/usb/1p1 (for the second USB printer), and so on.

Using scanners in Fedora Core is as simple as using USB printers. Just plug the scanner into the USB port, power it up, and you can access it by using xsane — a graphical front end for scanners that you can start by choosing Main Menu Graphics: Scanning. Of course, xsane must support the scanner make and model. To quickly check whether kudzu has detected your scanner, log in as root and type find-scanner in a terminal window.

The kernel can also automatically mount a USB mass storage device for easy access. Consider, for example, the USB keychain storage device. Just as the names say, these are small memory cards, capable of storing anywhere from 32MB to 1GB. You can carry them on a keychain — in effect, taking all your data with wherever you go. Here is how you can use a USB keychain storage device that's already formatted for use in Microsoft Windows.

- 1. Plug the keychain storage device to the PC's USB port. Sometimes the device plugs directly into the port, but for some devices you have to attach the keychain device to a USB cable and then plug the cable into the USB port.

Some USB keychain devices have a small switch on the side that controls whether the keychain is write-protected. If you plan to write the device, first make sure it is not write-protected or locked.

- 2. Kudzu detects the USB storage device and adds an entry in /etc/fstab that associates the USB device with the mount point /mnt/flash. Mount the device with the command:
`mount /mnt/flash`

- 3. To check that the USB device is mounted, look for a line in the output that shows /mnt/flash:
`df`
For example, the following line of output is for a 32MB USB keychain device:
`/dev/sda 31520 64 31456 1%/mnt/flash`
If you don't have any USB device plugged in, the device name is /dev/sda (USB storage devices appear as SCSI devices). The next USB storage devices gets the /dev/sda2 device name and so on.

Now you can access the files on the keychain at the /mnt/flash directory. To save a file to the USB keychain storage device, use a command of the following:
`cp filename /mnt/flash`
where filename is the name of the file you want to save.

When you're using the device, unmount the USB keychain with this command:
`umount /dev/sda`

That's it!

# Managing Print Queues in Fedora Core

PCs typically come with one parallel port, typically used to connect the printer to the PC. You can set up a printer fairly easily by using Fedora Core's graphical printer-configuration utility.

## Spool and print jobs

Spooling refers to the capability to print to a disk. When you print from a word processor, the output first goes to a disk. Then, while you continue working with the word processor, a background process sends that output to the printer. Fedora Core supports spooling.

## Managing Print Queues in Fedora Core

Print job refers to what you print with a single command. The printing environment queues print jobs by storing them in the spool directory. Fedora Core uses the Common UNIX Printing System (CUPS) for its printing. CUPS is a printing system based on the Internet Printing Protocol (IPP) — a protocol for distributed printing. IPP uses a client/server model with the client being an application provider and the server a “Printer” — an abstraction of an output device. IPP supports distributed printing with the clients and printers communicating over the Internet. The client application uses IPP to inquire about capabilities of a printer, submit print jobs, and inquire — cancel print jobs.

![](img/d9230b719dc0efd80851f363d8c6f571_515_0.png)

If you have set up CUPS print queue for a printer connected to your Fedora Core (following the directions in Book I, Chapter 3), you can print on that printer from Windows XP and 2000 systems on your local network area. Windows 2000 and XP have built-in support for IP — the protocol used by CUPS. To print on a CUPS print queue from a Windows XP system, add a network printer on the XP. In the Add Printer Wizard, select a Printer on the Internet or on a Home or Office Network and then enter the URL of the CUPS print queue. For example, for a CUPS print queue named HPLaserjet210 on a Fedora Core host whose address is 192.168.0.8, I enter the following URL for the print queue:

```
http://192.168.0.631/printers/HPLaserjet210
```

Although you typically have only one printer connected to your PC, one advantage of the CUPS printing system is the capability to print to a remote printer connected to another system on a network. Printing to a remote printer is handled in the same fashion as printing to a local printer; the local lp or lpr program sends the files to the remote system’s cupsd scheduler.
