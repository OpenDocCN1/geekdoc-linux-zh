X uses a configuration file, called Xorg.conf, to figure out the type of display card, monitor, and the kind of screen resolution you want. The Fedora installer prepares the configuration file, but sometimes the configuration is not correct.

To quickly create a working Xorg.conf file, follow these steps:

- 1. Type the following command:

```
/usr/X11R/bin/Xorg -configure
```

The screen goes blank and then Xorg exits after displaying some messages. The last line of the message says the following:

> To test the server, run 'X -xf86config //Xorg.conf.new'

- 3. Try the new configuration file by typing the following command:

```
/usr/X11R/bin/Xorg -xf86config //Xorg.conf.new
```

If you see a blank screen with an X-shaped cursor, the configuration file is working.

- 4. Press Ctrl+Alt+Backspace to kill the server.

- 5. Copy the new Xorg.conf file to the /etc/X11 directory with the following command:

```
cp /Xorg.conf.new /etc/X11/Xorg.conf
```

Now you have a working X configuration file.

- 6. Reboot the PC by pressing Ctrl+Alt+Del or typing reboot.

If all goes well, you go through the normal Fedora initial setup screens and (finally) get the graphical login screen.

## The fatal signal 11 error

Some people get a fatal signal 11 error message during installation and it stops the process. This error usually happens after the initial boot screen as the anaconda installer starts its GUI or text interface. The most likely cause of a signal 11 error during installation is hardware related to memory or the cache associated with the CPU (processor).

![](img/d9230b719dc0efd80851f363d8c6f571_87_1.png)

Signal 11, also known as SIGSEGV (for Segment Violation), can occur in other Linux methods. A segment violation occurs when a process tries to access a memory location that is not supposed to access. The operating system catches the problem before it happens and stops the process by sending it a signal 11. When that happens during installation, it anaconda made an error while accessing memory, and the most likely reason is some hardware problem. A commonly cure for the signal 11 is to turn off the CPU in the BIOS. To do so, you need to enter SETUP while the PC boots (by pressing a function key such as F2) and then turn off the CPU cache in the BIOS setup menu.

If the problem is due to a hardware error in memory (in other words, the result of bad memory chips), you could swapping the memory modules around in their slots. You may also consider replacing an existing memory module with another memory module, if you have one.

You can read more about the signal 11 problem at www.bitwizard.nl/sig11/

## Using kernel boot commands

When you boot the PC for installation, either from the DVD or the first CD-ROM, you get a text screen with the boot prompt. Typically, you press Enter at that prompt or do nothing and the installation begins shortly. You can, however, type a variety of commands at the boot prompt. The commands can provide options to the Linux kernel that takes care of the installation and controls various aspects of the installation such as whether the kernel should probe for hardware or whether to use GUI screens for the installation. Some of these commands can be helpful in bypassing problems that you may encounter during installation.

To use these boot commands, type linux followed by the boot command. For example, to perform text-mode installation and tell the kernel that your PC has 256MB of memory, you type the following at the boot prompt:

```
linux text mem=256
```

Consult Table 3-1 for a brief summary of some of the Linux boot commands. You can use these commands to turn certain features on or off.

Although I mention these Linux boot commands in the context of troubleshooting installation problems, you can use any of these commands when you boot a PC with any Linux distribution and you want to turn specific features on or off.
