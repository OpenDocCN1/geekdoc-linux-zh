# Making sense of version numbers

Both the Linux kernel and Fedora Core have their own version numbers, not to mention many other software programs (such as GNOME and KDE) that come with Fedora Core. The version numbers for the Linux and Fedora Core are unrelated, but each has particular significance.

# Linux-kernel version numbers

After Linux kernel 1.0 was released on March 14, 1994, the loosely knit Linux development community adopted a version-numbering scheme. Version numbers are 1.X.Y and 2.X.Y; where X is an even number, considered the stable versions. The last, Y is the patch level, which is incremented as problems are fixed. For example, 2.6.5 is a typical, stable version of the Linux kernel. Notice that these version numbers are in the form of three integers separated by — Major.Minor.Patch — where Major and Minor are denoting the major and minor version numbers, and Patch is another number representing the patch level.

Version numbers of the form 2.X.Y with an odd X are beta releases (for developers only); may be unstable, so you should not adopt versions for day-to-day use. For example, when you look at version 2.5.75 of the Linux kernel, the 5 — tells you it's a beta release. Developers add new features to these odd-numbered versions of Linux.

You can find out about the latest version of the Linux kernel online at www.kernel.org.

# Fedora Core version numbers

The Core development community, led by Red Hat, assigns the Fedora Core version numbers, such as 1 or 2. they are of the form X.Y; where X is the major version and Y the minor version. Nowadays if the minor version number is zero, it's simply dropped — as in Fedora Core 1 and Fedora Core 2.
