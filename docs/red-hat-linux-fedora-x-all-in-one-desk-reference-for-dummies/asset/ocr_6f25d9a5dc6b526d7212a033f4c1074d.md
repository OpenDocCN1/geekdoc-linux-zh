The output shows the status of each service for the run levels from 0 through 6. For each run level, the service is either on or off. At the very end of the listing, chconfig displays a list of the services which xinetd controls. Each xinetd-based service is also marked on or off, depending on whether or not xinetd is configured to start the service.

> Note: If you can configure services to run xinetd or on a standalone basis. For example, prior to version 8.1, Red Hat Linux started the FTP service using xinetd. Starting with version Red Linux 8.1 and Fedora Core, however, the Very Secure FTP server (vsftpd) is set up as a standalone server. Nowadays, if you have to start the FTP service, type service vsftpd starts the FTP service automatically at boot time. type chconfig vsftpd on.

# Using the service configuration utility

If you don't like typing the chconfig commands, use a graphical service utility program to configure the services. To run the service configuration utility, log in as root and choose Main Menu→System Settings→Services from GNOME or KDE desktop. You can then run services on or off from the Service Configuration window (as Figure 1-2):
