# The sendmail configuration file

You don't have to understand everything in the sendmail configuration file, /etc/mail/sendmail.cf, but you need to know how that file is created. That way, you can make minor changes to regenerate the /etc/mail/sendmail.cf file.

Before you can regenerate the sendmail.cf file, you have to install the sendmail-cf package. To check whether the sendmail-cf package is installed, type

```
rpm -q sendmail-cf
```

# Installing the Mail Server

If the command doesn't print the name of the sendmail-cf package, you have to install the package. This RPM file is in the DVD-ROM bundled with this book. To install that package, log in root and insert the DVD-ROM into the DVD-ROM drive. In GNOME or KDE, the DVD-ROM mounts automatically. Otherwise, you can mount the DVD-ROM with the following command:

```
mount /mnt/cdrom
```

Then install the package by typing the following commands:

```
cd /mnt/cdrom/Fedora/RPMS
rm -ivh sendmail-cf*
```

The sendmail-cf package you installed in the /usr/share/sendmail-cf directory all the files needed to generate a new sendmail.cf configuration file. As I explain in the next few sections, the sendmail.cf file is generated from a number of m4 macro files (text files in which each line expands to multiple lines that mean something to some program). These macro files are organized into a number of subdirectories in the /usr/share/sendmail-cf directory. You can read the README file in /usr/share/sendmail-cf to find out more about the creation of sendmail configuration files.

Now that you have taken care of the prerequisites, you can find how to regenerate the sendmail.cf file.

# m4 macro processor

The m4 macro processor generates the sendmail.cf configuration file, which comes with the sendmail package in Fedora Core. The main macro file, sendmail.mc, is included with the sendmail package, but that file other m4 macro files that are in the sendmail-cf package.

![](img/d9230b719dc0efd80851f363d8c6f571_678_0.png)

So what's a macro? A macro is basically a symbolic name for code that does some action, in a shorthand format that substitutes for a string of characters. A m4 processor usually reads its input and copies it to the output, processing the macros along the way. The processing of a macro generally involves performing some action and generating output. Because a macro generates more text in the output than merely the macro's, the processing of macros is referred to as m4 expansion.

The m4 macro processor is stream-based. That means it copies the characters to the output while it's expanding any macros. The m4 macro processor does not have any concept of lines, so it copies characters (that mark the end of a line) to the output. That is why we use the word dnl in most m4 macro files; dnl is an m4 macro that stands for delete through newline. The dnl deletes all characters starting at the dnl up and including the next newline character. The newline characters in the output do not cause any harm; they merely create unnecessary blank lines. The sendmail macro package uses dnl to avoid such blank lines in the output configuration file. Because dnl basically delete everything up to the end of the line, m4 macro files use dnl as a prefix for comment lines.

To see a simple example of m4, consider the following m4 macro file that defines two macros — hello and bye — and uses them in a letter format:

```
dnl #################################################
dnl # File: ex.m4
dnl # A simple example of m4 macros
dnl #################################################
define('hello', 'Dear Sir/Madam')dnl
define('bye', 'Sincerely,
Customer Service')dnl
dnl Now type the letter and use the macros
hello,

This is to inform you that we have received your recent inquiry.
We will respond to your question soon.

bye
```

Type this text (using your favorite editor) and save it in a file named ex.m4. You can name a macro file anything you like, using the .m4 extension for m4 files is customary.

Before you process the macro file using m4, note the following points about the example:

- Use the dnl macro to start all comment lines (for example, the first lines in the example).
- Each end macro definition with dnl. Otherwise, when m4 processes the macro file, it produces a blank line for each macro definition.
- Use the built-in m4 command define to define a new macro. Macro name and value are both enclosed between a pair of left and right quotes ('...'). Note that you cannot use the plain single quote to enclose macro name and definition.

Now process the macro file ex.m4 by typing the following command:

```
m4 ex.m4
```

m4 processes the macros and displays the following output:

Dear Sir/Madam,

This is to inform you that we received your recent inquiry.
We will respond to your question soon.

Sincerely,

If you compare the output with ex.m4 file, you see that m4 prints the letter on standard output, expanding the macros hello and bye into the defined values. If you want to save the letter in a file called letter, use the shell's redirection feature, like this:

```
m4 ex.m4 > letter
```

What if you use the word hello or bye in the letter without expanding? You can do so by enclosing these macros in a pair of quotes ('...'). You have to do for other m4 macros, such as define, as a plain word, not as a macro to expand, type 'define'.

# sendmail.mc file

The simple example in the preceding section gives you an idea of how m4 macros are defined and used to create configuration files such as sendmail.cf. Find many complex macros stored in files in /usr/share/sendmail-cf directory. A top-level file, sendmail.mc, described in this section, includes these macro files (to copy a file into the input stream). By defining its set of high-level macros in files located in /usr/share/sendmail-cf directory, sendmail essentially creates its own language. The sendmail macro uses the .mc extension. The primary sendmail file you configure is sendmail.mc, located in the /etc/mail directory. Unlike the /etc/mail/sendmail.cf, the sendmail.mc file is short and easier to work with. Here is the full listing of the /etc/mail/sendmail.mc file that comes with Fedora Core:

```
# This is sendmail macro config file for m4. If you make changes to /etc/mail/sendmail.mc, you will need to regenerate /etc/mail/sendmail.cf by confirming that sendmail-cf package is installed and then performing:

make -C /etc/mail
include(/usr/share/sendmail-cf/m4/cf.m4)
VERSION("linux") OSTYPE("linux")
# default logging level is 9, you might want to set it higher to debug the configuration
# define("LOG_LEVEL", "9")
# Uncomment and edit the line if your outgoing mail needs to be sent out through an external mail server
# define("SMART_HOST", "smtp.your.provider")
define("USER_ID", "8:12")
define("MAUTERREBUILD", "")
define("RETRY_CONNECT", "1")
define("RETRY_MAX_LIST", "true")
define("PROBE_INTERFACES", "true")
define("MAIL_PATH", "/usr/bin/procmail")
define("ALIAS_LIST")
define("STATUS_FILE", "/var/log/mailstatus")
define("MAILER_MAX", "200000")
define("USERDB_PATH", "/var/lib/userdb.db")
define("CONFTRAPY_FLAGS", "authwarnings,novfry,noexpn,restrictun")
define("CONFAUTH_OPTIONS", "A")
# The following allows relaying if the user authenticates, and disallows plaintext authentication (PLAIN/LOGIN) on non-TLS links
define("CONFAUTH_OPTIONS", "A")
# PLAIN is the preferred plaintext authentication method used by Mozilla Mail and Evolution, though Outlook Express and other MUAs use LOGIN. Other methods should be used if the connection is not guaranteed secure.
# Please remember that lastauth needs to be running for AUTH.
define("TRUST_AUTH_MECH", "EXTERNAL:DIGEST-MOS CRAM-MD5 LOGIN:PLAIN")
define("CONFAUTH_MECHANISMS", "EXTERNAL API DIGEST-MOS CRAM-MD5 LOGIN:PLAIN")
# Rudimentary information on creating certificates for sendmail:
# make -C /var/share/ssl/certs
# or use the included makedert.sh script
define("CERT_DIR", "/etc/mail/certs")
define("CONFACERT_PATH", "CERT_DIR")
define("CONFACERT_CERT", "CERT_DIR/cert.m4")
define("SERVER_CERT", "CERT_DIR/cert.m4")
define("SERVER_KEY", "CERT_DIR/key.m4")
define("CLIENT_CERT", "CERT_DIR/cert.m4")
define("CLIENT_KEY", "CERT_DIR/key.m4")
```
