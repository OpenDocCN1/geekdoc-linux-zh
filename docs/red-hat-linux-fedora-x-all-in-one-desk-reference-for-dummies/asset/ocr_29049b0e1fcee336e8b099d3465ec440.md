Each layer has its own set of protocols — conventions — for handling and formatting the data. If you think of sending data as something akin to sending letters through the postal service, a typical protocol is a preferred sequence of actions for the task such as addressing an envelope (first the name, then the street address and then city, and Zip or other postal code).

Here's each of the four layers, top to bottom:

+   **Application:** Runs the applications that users use, such as e-mail readers, file transfers, and Web browsers. Application-level protocols are Simple Mail Transfer Protocol (SMTP) and Post Office Protocol (POP) for e-mail; HyperText Transfer Protocol (HTTP) for the Web; File Transfer Protocol (FTP) for file transfers. Application-level protocols also have a port number you can think of as an identifier for a specific application. For example, port 80 is associated with HTTP or the Web server.

+   **Transport:** Sends data from one application to another. The most important protocols in this layer are Transmission Control Protocol (TCP) and User Datagram Protocol (UDP). TCP guarantees delivery of data; UDP just sends the data without ensuring it actually reaches the destination.

+   **Network:** This layer is responsible for getting data packets from one network to another. If the networks are far apart, the packets are routed from one network to the next until they reach their destination. The primary protocol in this layer is the Internet Protocol (IP).

+   **Physical:** Refers to the physical networking hardware (such as an Ethernet card or Token Ring card) that carries the data packets in a network.
