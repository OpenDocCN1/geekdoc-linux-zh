## Kernel hacking

This set of options enables you to debug the kernel and the SysRq key (usually the PrintScrn key on your keyboard) to get important information after a system crash. This information is useful if you're a Linux developer who expects to debug the kernel. Most users disable these options (because most users run a stable version of the kernel and don't expect to fix errors).

## Security options

Through these options, you can include support for the Security Enhanced Linux (SELinux), which was developed by the National Security Agency (NSA) — a U.S. government agency. SELinux can be turned off during booting by providing selinux=0 as a boot option. For information on SELinux, visit nsa.gov/selinux/.

# Building the Kernel and the Modules

After configuring the kernel options, click the Save and Exit button in the main configuration window (refer to Figure 6-7). You now have to build the kernel. This part can take a while. Depending on your system, making a new kernel can take anywhere from a few minutes to an hour.

Type the following on a single line to initiate the process:

```bash
make
```

The make command creates the new kernel as well as any modules that you have specified through the configuration step.
As the kernel is built, you'll see a lot of messages on-screen. A new kernel in the form of a compressed file named bImage is in the /usr/src/linux*/i386/boot directory.
To use the new kernel, you have to copy the kernel to the /boot directory under a specific name and edit the /etc/grub.conf file to set GRUB — the boot loader. Before you proceed with the kernel installation, however, you have to install the modules and build a new initial RAM disk.

# Installing the Modules

If you select any modules during the kernel configuration, the kernel building step also builds the modules. All you have to do is install them. Perform this task with the following commands:

```bash
cd /usr/src/linux*
make modules_install
```

The make modules_install command copies all the modules to a new subdirectory named 2.6.3-2.1.240custom in the /lib/modules directory. Appending the custom to the kernel version number creates the directory name.

Now you can install the kernel and make it available for GRUB to boot.

# Creating the Initial RAM Disk File

The new kernel needs a new RAM disk file that you can create by using the mkinitrd command. Usually, the initial RAM disk image is stored in a file whose name begins with initrd. As you might guess, initrd is shorthand for initial RAM disk, and the mkinitrd command is so because it makes an initrd file.

The mkinitrd program is in the /sbin and you have to log in as root and use a command line of the following to create the initrd file:

```bash
/sbin/mkinitrd /boot/initrd-filename.img module-directory
```

The initrd file has to be in the /boot directory where the kernel is also located. You can use any filename for initrd-filename. The module-directory is the name of the directory in /lib/modules where the modules for the new kernel are located. The make_install step places the modules in a directory whose name is the kernel version with the custom appended to it. For example, if your kernel version (reported by the uname -r command) is 2.6.3-2.1.240, the module-directory, after the make_install step, is 2.6.3-2.1.240custom.

Another common practice is to use an initrd filename by appending the directory name to the initrd-prefix. Thus, for module directory 2.6.3-2.1.240custom, the initrd file is initrd-2.6.3-2.1.240custom.

To create the initial RAM disk image for the newly built kernel, the following command:

```bash
/sbin/mkinitrd /boot/initrd-2.6.3-2.1.240custom.img 2.6.3-2.1.240custom
```

This command creates the file initrd-2.6.3-2.1.240custom.img in the /boot/ directory. You have to refer to this initrd file in the GRUB configuration file (/etc/grub.conf).

# Installing the Kernel and Setting Up GRUB

Fedora Core uses GRUB to load the Linux kernel from the disk. The configuration file (/etc/grub.conf lists the kernel binary file that GRUB runs. You can examine the contents of the GRUB configuration file by typing the following command:

```bash
cat /etc/grub.conf
```

Here is what I see when I run this command on one of my systems:

```
@ grub.conf
@ Note that you do not have a /boot after making changes to this file
@ NOTICE: This means that
@ all kernel and initrd paths are relative to /boot/, eg.
@ root=(hd0,2)
@ kernel/vmlinux-version root=/dev/hd5
@ @boot+=dev/hda
default=0
timeout=10
splashimage=(hd0,2)/grub/splash.xpm.gz
title Fedora Core (2.6.3-2.1.240)
root=(hd0,2)
vmlinux-2.6.3-2.1.240 root=LABEL=rhgb
initrd-2.6.3-2.1.240.img
title Windows XP
title rootoverify (hd0,1)
chainloader +1
```

Here's what the lines in /etc/grub.conf file mean (the lines that begin with # are comments):

- default=0: Specifies the first entry as the default that GRUB boots. If this line is set to 1, GRUB boots the second.
- timeout=10: Causes GRUB to boot the entry automatically after waiting for 10 seconds. If other boot entries are in the file, the user may select another from a boot menu GRUB displays.
- The four lines starting with title Fedora Core (2.6.3-2.1.240) constitute the first boot entry — and this entry defines a specific kernel file GRUB boot. You can make GRUB boot another kernel by adding a similar section to the configuration file. Here's the meaning of the lines in this entry:

![](img/d9230b719dc0efd80851f363d8c6f571_541_0.png)

- root (hd0,2): Sets the root device to the third partition of the hard drive. This partition is where the Linux kernel is installed on this particular system.
- kernel /vmlinuz-2.6.3-2.1240 root=LABEL=rhgb: Identifies the kernel loads if the user selects this boot entry. In this case, the kernel is vmlinuz-2.6.3-2.1240, which is located in the root device. In my system, that partition is mounted on the /boot device. In other words, GRUB loads the kernel file /boot/vmlinuz-2.6.3-2.1240. The items following the kernel name are options provided to the kernel. For example, the rhgb option enables a graphical boot that shows a nice graphical screen instead of scrolling text.
- initrd /initrd 2.6.3-2.1240: Specifies a file that contains an initial RAM disk (initrd image) that serves as a file system before the disks are available. The Linux kernel uses the RAM disk—a block of memory used as a disk—to get started; then it loads other modules and begins using the hard drive.
- The three lines with title Windows XP are the second boot entry and refer to the Windows XP operating system that happens to be on this system. The next text to the title line appears in the GRUB menu from which the user selects which operating system to boot.

To configure GRUB to boot the new kernel (the one you just built), follow these steps:

1. Copy the new kernel to the /boot directory.

The new, compressed kernel file is in the /usr/src/linux*/arch/i386/boot directory. The kernel filename is bImage. I simply copy that file to the /boot directory with the same name:

```bash
cp /usr/src/linux*/arch/i386/boot/bImage /boot
```

If the kernel filename is vmlinux, make sure change the kernel filename in /boot to anything you want, as long as you use the same filename when referring to the kernel in /etc/grub.conf file in Step 3.

2. Save the old System.map file in the /boot directory, and copy the new map file.

(I assume you have rebuilt kernel version 2.6.3-2.1240 after changing some configuration options):

```bash
mv /boot/System.map-2.6.3-2.1240 /boot/System.map-2.6.3-2.1240-old
cp /usr/src/linux*/System.map /boot/System.map-2.6.3-2.1240
cd /boot
ln -s System.map-2.6.3-2.1240 System.map
```
