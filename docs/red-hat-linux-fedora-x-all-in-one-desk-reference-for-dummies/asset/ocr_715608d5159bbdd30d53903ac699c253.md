# Using the Bash Shell

# Saving the output in a file

To save the output of a command in a file, redirect the standard output to a
file. For example, type cd to change to your home directory and then type
the following command:

```
grep typedef /usr/include/* > typedef.out
```

This command searches through all files in the /usr/include directory
for the occurrence of the text typedef — then saves the output in a file
called typedef.out. The greater-than sign (>) redirects stdout to a file. This
command also illustrates another feature of Bash: When you use an asterisk
(*), Bash returns the list of all filenames in the specified direct-
tory. Then, /usr/include/* means all the files in the /usr/include directory.

If you want to append a command's output to the end of an existing file
instead of saving the output in a new file, use two greater-than signs (>>) like
this:

```
command >> filename
```

# Saving error messages in a file

Sometimes you type a command and it generates a whole lot of error mes-
sages scroll so fast that you can't tell what's going on. One way to see all
the error messages is to save the error messages in a file so that you can see
what heck happened. You can do that by redirecting stderr to a file.

For example, type the following command:

```
find / -name COPYING 2> finderr
```

This command looks throughout the file system for names COPYING,
but saves all the error messages in the finder file. The number 2 followed
by the greater-than sign (2>) redirects stderr to a file.

![](bbox=[0.126, 0.696, 0.179, 0.735])

If you want to discard the error messages instead of saving them in a
file, use /dev/null as the filename:

```
find / -name COPYING 2> /dev/null
```

/dev/null is a special file — often called the bucket and sometimes
glorified by the Great Bucket in the Sky — that simply discards whatever
receives. So now you know what they mean when you use phrases such as,
"Your mail probably ended up in the bit bucket."
