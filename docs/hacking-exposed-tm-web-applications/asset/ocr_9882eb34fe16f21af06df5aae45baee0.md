# Server-Generated Session IDs

Modern Web servers have the capability to generate their own, (hopefully) random session IDs. The IDs generated by these servers tend to be large (32 bit), random numbers. This precludes many types of attacks, although they are all vulnerable to session replay attacks. Table 7-3 lists some common servers and their corresponding session tracking variables.

# Session Database

Applications that rely heavily on databases have the option of tracking sessions almost fully on the server. A session database is an extremely effective technique of managing sessions across several Web servers in a secure manner. The server still generates a unique number and passes it to the client; however, no additional information leaves the server.

When a user first logs in to the application, the application generates a temporary session ID. It stores the ID in a session table. All information is stored in the row as the session ID. Each time the user requests a new page, the application takes the session token and looks up the value in its session table. As long as the session ID is valid, the application grabs the current state from the row in the session table.

The advantage of a session database is that only one value needs to be passed to the client. State information cannot be sniffed, spoofed, or modified.
