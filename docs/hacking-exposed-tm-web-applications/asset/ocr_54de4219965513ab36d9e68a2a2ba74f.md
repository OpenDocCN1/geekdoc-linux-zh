# Hacking Exposed Web Applications

As we noted in Chapter 1, Web services are the latest rage in the computing world, currently enjoying backing and support from Internet technology juggernauts including Microsoft, IBM, and Sun. Web services theoretically will form the "glue" that will allow disparate Web applications to communicate with each other effortlessly, and with minimal intervention. Microsoft puts it, Web services provide "a loosely-coupled, language-neutral, platform-independent way of linking applications within organizations, across enterprises, and across the Internet."

The computing world has many previous attempts to design the perfect intercommunication protocols, and anyone who's been long enough to know RPC, IDCM, CORBA, and the like will know the track record for such endeavors is quite sorry-wise(although this is not necessarily due to the protocols themselves, but rather the ease with which they make application interfaces available).

Do Web services herald tomorrow new application security on the Internet, or are we merely at the cusp of yet another revolution in Web hacking as the technology matures and begins to proliferate across the network? This chapter will attempt to answer this by first discovering what a Web service is and how it might be attacked.

# WHAT IS A WEB SERVICE?

Simply stated, a Web service is a self-contained software component that performs specific functions and publishes information about its capabilities to other components over a network. Web services are based on a set of many-hyped Internet standards-in-development, the Web Services Definition Language (WSDL), an XML format for describing the connection points exported by a service; the Universal Description, Discovery and Integration (UDDI) a set of XML protocols and infrastructure for the description and discovery of Web services; and the Simple Object Access Protocol (SOAP), an XML-based protocol for messaging and RPC-style communication between Web services. Leveraging these three technologies, Web services can be made and matched to create innovative applications, processes, and value chains.

> You probably noted the centrality of the Xtensible Markup Language (XML) within Web technologies—because of the ease with which XML represents data in a structured fashion, it provides a strong backbone for interapplication communication. For this reason, Web services are often referred to as XML Services, although technically XML is not required to implement them.

Even more, Web services offer a coherent mechanism for alleviating the typically arduous task of integrating multiple Web applications, coordinating standards to pass data, protocols, platforms, and on. Web services describe their functionality, and search out and dynamically interact with other Web services via WSDL, UDDI, and SOAP. Web services provide a means for different organizations to connect their applications with one another to conduct e-business across a network, no matter what their application, design, or run-time environment (ASP, ISAPI, COM, PHP, JEE, and so on).
