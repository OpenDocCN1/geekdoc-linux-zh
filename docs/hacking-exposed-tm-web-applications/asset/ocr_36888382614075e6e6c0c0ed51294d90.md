# Cookies and Predefined Headers

Web application testers always review the cookie contents. Cookies, after all, can be manipulated to impersonate other users or escalate privileges. The application must read the cookie; therefore an equally valid test for script attacks. In fact, many applications interpret additional information that is particular to your browser. HTTP 1.1 defines a "User Agent" header that identifies the Web browser. You usually see some of "Mozilla" in this string.

Applications use the User Agent string to accommodate browser quirks (since no one likes to follow standards). The text-based browser, lynx, lets you specify a custom string:

```
$ lynx -dump -useragent="<script>" \nn http://www.victim.com/page2a.html?tw=tests\nnoutput truncated.
```

# Countermeasures

The most significant defense against script attacks is to turn all brackets into their HTML-encoded equivalents. The left bracket, "<", is represented by "&lt;" and the right bracket, ">", is represented by "&gt;". This ensures the brackets are always stored and displayed in an innocuous manner. A Web browser will never execute a "&lt;script&gt;" tag.
