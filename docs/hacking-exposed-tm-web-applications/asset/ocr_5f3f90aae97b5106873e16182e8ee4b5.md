Use UrlScan to Normalize Requests with URL Encoding As noted in our previous discussion of UrlScan, the UrlScan.ini configuration file can be configured to normalize HTTP requests containing suspicious encoding before sending them to IIS. Setting the following values in UrlScan.ini achieves this:

+   * NormalizeUrlBeforeScan=1 ; 1, canonicalize URL for processing
* VerifyNormalization=1 ; 1, canonicalize URL twice and reject request

Remember to restart IIS if you make changes to UrlScan.ini to load the changes.

Always Use NTFS for Web Volumes and Set ACLs Conservatively! With FAT and FAT32 file systems, file- and directory-level access control is impossible, and the IUSR account will carte blanche to read and upload files. When configuring access control on Web-accessible NTFS directories, use the least-privilege principle. IIS 5 also provides the Permissions Wizard that walks you through a scenario-based process of setting ACLs. The Permissions Wizard is accessible by right-clicking the appropriate virtual directory in the IIS Admin console.

Move, Rename, Delete, or Restrict Any Powerful Utilities Eric Schultze and David LeBlanc of Microsoft Corp. Recommend at setting the NTFS ACLs on cmd.exe and other powerful executables to Administrator and SYSTEM:Full Control only. We have publicly demonstrated that this simple trick stops Object-type sheidenigans cold because IUSR no longer has permissions to access cmd.exe. Schultze and LeBlanc recommend using the built-in cacs tool to set these permissions. Let's walk through an example of how cacs might be used to set permissions on executable files in the system directory. Because many executable files are in the system folder, if you use a simpler example of several files sitting in a subfolder called test1 using cacs in display-only mode, we can see the existing permissions on our test files are pretty clear

```
C:\cacs /t
C:\test1 Everyone: (OI) (CI) F
C:\test1\test1.exe Everyone:F
C:\test1\test1.txt Everyone:F
C:\test1\test2 Everyone: (OI) (CI) F
```
