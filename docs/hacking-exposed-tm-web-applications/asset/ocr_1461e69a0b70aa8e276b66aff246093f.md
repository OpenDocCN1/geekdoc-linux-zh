# Hacking Exposed Web Applications

```
Host: 192.168.234.222
Content-length: 38127
<?xml version="1.0"?>
<a:propind xmlns:a="DAV" xmlns:u="over">
<a:prop><a:displayname></u:[buffer][/></a:prop></a:prop>
</a:propind>
```

The value of [buffer] may be greater than 128,000 bytes. The first time such a request is sent, IIS responds with an HTTP 500 error. Upon the second request, the WSVC is started. Obviously, if several such requests are made to an IIS 5 server continuously, it can prevent the service from serving valid requests indefinitely. Georgi developed a proof-of-concept Perl script called v5.pl that needs two requests, sufficient enough to restart the Web service once.

Clearly, such behavior is undesirable from an availability standpoint, but also considers its utility to attackers who need to restart the Web service to implement some additional attack. One example might be an IIS privilege escalation exploit that requires the IIS's access token to be reset. The WebDAV Propfind Could also be used for such purposes.

It's noteworthy that IIS 5 implements an automatic restart following a crash of this nature, one of the hidden benefits of migrating to Win 2000 (older versions of IIS simply fail).

# Countermeasures for Specific DoS Vulnerabilities

Take a two-pronged approach to combating specific DoS vulnerabilities. One, get relevant patches. Disable any unnecessary Web server functionality. We'll use the IIS 5 WebDAV Propfind DoS as an example again to illustrate our points.

On the front patch, we'll slip in our usual recommendation that Web servers should avoid the cutting edge when it comes to vendor patches. If you haven't patched it, someone will find it. The specific patch for the IIS 5 WebDAV Propfind DoS can be found in Security Bulletin MS01-016.

As disabling unnecessary functionality, IIS 5's WebDAV feature can be disabled according to Microsoft Knowledge Base Article Q241520 (see "References and Further Reading" at the end of this chapter). You can also disable it using the IISLockdown tool (see the previous discussion in this chapter). Note that disabling WebDAV prevents WebDAV requests from being processed by IIS, and this could cause the loss of such features as:

+   - Web folders
- Publishing to the Web site using Office 2000 (but not via FrontPage Extensions)
- Monitoring on IIS 5.0 server via Digital Dashboard

Per our recommendations earlier in this chapter, we strongly believe that all extended IIS functionality should be disabled unless absolutely necessary, WebDAV.
