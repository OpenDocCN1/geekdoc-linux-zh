# Rolling Back IISLockdown

OK, something went wrong, and now your Web server is completely broken after you ran IISLockdown on it. How can you reverse the effects of IISLockdown?

Simple—rerun iislock.exe. The first time it runs, IISLockdown keeps a log of all the configurations it makes in the file %windir%\system2\inetrs\oblt-log.log. As long as this file is not removed or altered, when you rerun iislock.exe, it will present the screen shown in Figure D-6.

# Unattended IISLockdown Installation

For those who wish to automate the deployment of the IIS Lockdown wizard and UrlScan across multiple servers, IISLockdown can be configured to run in an unattended fashion according to predefined settings specified in a file called islockdown.ini. The [Info] section contains basic configuration information used by the IIS Lockdown wizard. The short file RunLockUnattended comes with the IIS Lockdown installation explains the basics of configuring islockdown.ini files and there is a sample islockdown.ini file available in the distribution (don't delete or overwrite this original, as it contains the syntax for configuring all available!). The key parameter is to Set Unattended=TRUE in the file, and run the IISLockdown tool in the desired directory as the islockdown.ini file using the command line or calling it from script. We've had erratic results using this feature (“No memory”) error messages), so your mileage may vary. It’s probably a better idea to integrate UrlScan into the standard template for servers throughout your organization, which means it will be deployed automatically with any new Web server in your configuration.

> The IISLockdown installer is named islockdown.exe, same as the tool itself—don’t mix them up!

- Configuring UrlScan.ini

# Appendix D: UrlScan Installation and Configuration

# Extracting UrlScan.dll

The first step is to extract the most recent version of UrlScan.dll to the desired directory.
to do this, use the latest UrlScan.exe installer with the following command switches:

```
urlscan.exe /q /c /t:%windir%\system32\inetsrv\urlscan
```

Note that we specified files to be extracted to the default UrlScan directory here.
this directory will be created if it not already exist. When placed in %windir%\system32\inetsrv, UrlScan directory has the appropriate ACLs when set to inherit
from its parent. Be aware that extracting UrlScan.dll to a directory with different ACLs
prevent it from working properly.

# Configuring UrlScan.ini

In order for UrlScan.dll to work its magic, there must be a file called UrlScan.ini in its directory. You could write a UrlScan.ini file from scratch, but the best way is to start with a template. Several are available from within the IISLockdown tool. To obtain the UrlScan.ini template files, extract them from the iislockd.exe installer (not the tool itself!)
using the following command:

```
iislockd.exe /q /c /t:[full_path_to_desired_folder]
```

where [full_path_to_desired_folder] is a user-specified path to a temporary directory
where the files should be extracted (for example, d:\urlscan). Don't extract to the directory where you put UrlScan.dll in the previous step! This extracts numerous files, including the IISLockdown tool (iislockd.exe), the UrlScan exe automated installer, includeUrlScan.dll itself, and the UrlScan.ini template files.

Now you have to choose which template file you want to start with. The template files
are named according to server roles:

- urlscan-biztalkl.ini
- urlscan-commerce.ini
- urlscan-dynamic.ini
- urlscan-exchange2000.ini
- urlscan_frontpage.ini
- urlscan_sbs2000.ini
- urlscan_sharepoint_portal.ini
- urlscan_sharepoint_teamservices.ini
- urlscan_static.ini

If you are deploying UrlScan to any of the Microsoft product types identified in the previous list (for example, Commerce Server), use that template file. For maximum security, we recommend the urlscan_static.ini file. If you require dynamic content generation by scripts (as Active Server Page scripts), use the urlscan_dynamic.ini file. Don't sweat this thing too much—you can edit this file at any time.

Whichever file you choose, copy it to the directory where you installed UrlScan.dll. Then rename it to UrlScan.ini.

Now you have to edit it so that UrlScan.dll rejects the requests you want it to. The syntax for UrlScan is pretty straightforward, and we've included a complete command reference in the section titled "UrlScan Command Reference" later in this chapter. If you've chosen your template well, you'll only need to make configuration changes at this point. However, there are a few edits that we recommend you perform right away.

# Add Updates

Next, we recommend making the appropriate changes to update your UrlScan.ini to version 2.5. Remember, there are two version 2.5 configurations, Baseline and SRP. The differences are minimal, and we'll note them next. We favor the SRP settings, as they are more restrictive security-wise. To your UrlScan, add the following lines to the end:

```
[RequestLimits]
MaxAllowedContentLength=30,000,000 ;30MB
ForBaseline, set previous to 2,000,000,000
MaxUrl=16384 ;16K
MaxQueryString=4096 ;4K
```
