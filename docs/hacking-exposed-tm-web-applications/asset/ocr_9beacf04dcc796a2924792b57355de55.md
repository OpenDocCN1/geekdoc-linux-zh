# Ping

The most basic approach to server discovery is to send ICMP Echo Requests (typically implemented via the ping utility) to potentially valid hostnames or IP addresses. Numbered tools for performing pings exist, and many are bundled into port scanning tools, which we will discuss. Since most Internet-connected networks block port scanning, it is rarely an effective server discovery tool.

# Discovery Using Port Scanning

One of the most effective mechanisms for discovering Web servers is to port scanning. A port scan attempts to connect to a specific set of TCP/or UDP ports and determine if a service exists. If a response is received, then it's safe to assume that the responding IP address is a "live" address, which is advertising a live service on one or more ports.

The trick to identifying servers using port scanning is having a comprehensive list of potential ports. Scanning anything more than a half of servers across all 2^16 (65,536) ports can be quite resource- and time-intensive. Assuming a good TCP port scanner averages around hundred ports per second, scanning 254 hosts (a Class C space) across all possible ports would take nearly 24-hour days.
