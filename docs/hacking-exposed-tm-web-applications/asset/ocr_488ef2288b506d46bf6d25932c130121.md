Usage - ntomax /s script.txt > results.txt
/s = reads from stdin
/? = Help

+   - Script Format
host[: address], [port], [min], [max] = host parameters
Additional host parameters in order:
timeout - ms to wait for script response - default = 0
delay - ms to wait before sending commands - default = 250
pause - ms to wait before receiving - default = 0
return - number of LF/CR's end buffer - default = 1
reopen - T/F reopen connection before each command
norecv - T/F receive after initial connection - default is 0
verbose - T/F verbose output - off by default
trial - T/F display buffer w/o sending
Command syntax:

```
c:[command text] = preloop commands
lc:[command buffer] = loop commands
c:[command text] = post loop command
```

The power of NTomax lies in the script files. The number of options and command syntax seems confusing, but the complexity allows you to generate useful test scenarios. You must set the "return" value to 2 in order to generate correct HTTP syntax. An asterisk in the "c" or "lc" commands acts as a placeholder for the buffer. In other words, a string of 400 Ns replaces each instance of an asterisk. The major drawback of NTomax is that you cannot change the buffer size. For example, the script to test the length for the "user" variable in the php file contains

```
host:192.168.0.1,22,100,5000,250,0,2,true,true,true,false
lc:GET /login.php?HTTP/1.0
```

This script runs 100 (500-character buffer maximum minus the 400-character buffer minimum). Now, launch NTomax
