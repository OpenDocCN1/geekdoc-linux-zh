# Chapter 8: Input Validation Attacks

You (probably) won't gain command execution or arbitrary file access from boundary checks. However, the errors they generate can reveal useful information about the application or the server. This check only requires a short list of values:

+   - Boolean Any value that has some representation of true or false (T/F, true/false, yes/no,0). Try both values, then a nonsense value. Use numbers for arguments that accept characters, use characters for arguments that accept digits.
- Numeric Set zero and negative values (0 and -1 work best). Try the maximum value for various ranges, such as 256, 65536, 4294967296.
- String Length limitations. When defining variables, such as name and address, accept punctuation characters.

# Manipulating the Application

Some applications have special directives that the developers used to perform tests. One of the most prominent is "debug=1". Adding this to a GET or POST request could return more information about variables, the system, or back-end database connectivity. A successful attack may require a combination of debug, db and T, or 1.
Some platforms may allow internal variables to be set on the URL.
Other attacks target the Web server engine. For example, %33jsp will return directory listings under JRun x.x and Tomcat 3.2x.
You can also attack weak permissions on Lotus Domino servers by changing the "?Openocument" command to "Edocument"
The hitsearch CGI runs are both the CGI and as a command-line program. The command-line program accepts the -[filename] in an alternate configuration file.
