# WS-Security

On April 11, 2002, Microsoft Corp., IBM Corp., and VerSign Inc. announced the publication of a new Web services specification called the Web Services Security, or WS-Security (see links to the specification in the "References and Further Reading" section at the end of this chapter). WS-Security subsumes and expands upon the ideas expressed in similar specifications previously published by IBM and Microsoft (namely SOAP, WS-Security, and WS-License).

In essence, WS-Security defines extensions to SOAP that can be used to implement authentication, integrity, and confidentiality in Web communications. More specifically, WS-Security defines a standard format for embedding digital signatures, data, and security tokens (including binary elements like X.509 certificates and Kerberos tokens) within Messages heavily leverages the previously mentioned XML specifications, XML Signature and XML Encryption, and is meant to be a building block for a slew of other specs that are related aspects of security, including WS-Policy, WS-Trust, WS-Privacy, WS-Conversation, WS-Federation, and WS-Authorization.

The best way to understand WS-Security is via an example. The following SOAP message contains the WS-Security header and an encrypted payload (we have left the numbers to the left to ease identification of individual message functions):

```
(001) <xml version="1.0" encoding="UTF-8">
(002) <Envelope xmlns="http://www.w3.org/2001/12/soap-envelope"
xmlns:ds="http://www.w3.org/2000/09/xmldig#"
xmlns:wse="http://schemas.soap.org/ws/2002/04/seext#"
xmlns:xenc="http://www.w3.org/2001/04/xmlenc#">
(003) <Header>
(004) <path xmlns="http://schemas.soap.org/rp/
```
