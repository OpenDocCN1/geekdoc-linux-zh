# Hacking Exposed Web Applications

FP is actually the client, while FP Server Extensions (FPSE) run on the server side, enabling content management to authorized users. FPSE ship as a default component of IIS 5, and are implemented as a set of HTML files, scripts, executables, and DLLs that reside in a set of virtual roots with the name *vti_*, where the asterisk represents any bin, cfg, log, pvt, and txt (FrontPage was purchased from Vermeer Technologies, hence the vti application). The following request/response is usually a good indicator that FP Server Extensions are:

```
C:\nc -vv luxor 80
luxor [192.168.234.34] 80 (http)
GET /vti_bin/shtml.dll HTTP/1.0
```

```
HTTP/1.1 200 OK
Server: Microsoft-IIS/5.0
Date: Thu, 07 Mar 2002 04:38:01 GMT
Content-Type: text/html; charset=windows-1252
```

```
<HTML>BODY>Cannot run the FrontPage Server Extensions'
Smart HTML interpreter on this non-html page: "</BODY></HTML>
```

FP communications are propagated over HTTP via a proprietary protocol calledPage Remote Procedure Call (RPC). Methods are POSTed to the relevant FP DLLs shown in the following example:

```
POST /test2/_vti_bin/vti_aut/author.dll HTTP/1.0
Date: Thu
```

```
method=open%3a%48%2e%2e%2e3406&service%5name=%2ftest2
```

The first line shows the DLL that is the target of the POST, and the last line shows the methods invoked (in this case, the FP client is trying to open the test2 application directory for editing, as you can see by the filename=/test2 syntax at the end of the line).
