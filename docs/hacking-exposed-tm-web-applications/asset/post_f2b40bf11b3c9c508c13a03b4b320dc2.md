Willy attackers will also seek out these interfaces as alternative avenues into a Web application. This section will discuss the pros and costs of the most common mechanisms.

## FTP

Per generally accepted security principles, you shouldn't be running anything but an HTTP daemon on your Web application servers. You can imagine what we're going to say about running FTP, with the ongoing parade of vulnerabilities in FTP server software like Washington University's wuftp package: DON'T RUN FTP ON YOUR WEB SERVERS! There is just too much risk that someone will guess your account password or find an exploit that will give them the ability to write to the file system, and it's only a short hop to Web defacement (or worse). The only exception we'd made to this rule is if access to the FTP service is restricted to a small range of IP addresses.

Nevertheless, it is always good to check for FTP in a comprehensive Web application audit to ensure that some developer hasn't taken the easy way out. FTP lives on TCP port 21 and can be found with any decent port scanner.

## SSH/scp

As noted in our discussion of Web management techniques earlier in this chapter, Shell version 2 (SSH2) is a recommended protocol for remote Web server management-given that it is properly maintained. There is a utility called Secure Copy (scp) that is available to connect to SSH services and perform file transfers right over (encrypted) SSH tunnels. If you're a command-line joker, this is probably your best bet, but it will seem primitive compared to graphical content management tools like FrontPage (see following section). Well, security does its price...sigh.

As we've noted, SSH lives on TCP port 22 if you're interested in checking for it and attempting password guessing attacks. There are also remote vulnerabilities associated with SSH daemons, as we noted earlier.

## FrontPage

Microsoft's FrontPage (FP) Web author tool is one of the more popular and easy-to-use platforms for managing Web site content. It is primarily targeted at low-midrange users who wish to create and manage content on individual Web servers, but it is commonly supported by large hosting providers who cater to individuals and businesses of all sizes.

FP is actually the client, while FP Server Extensions (FPSE) run on the server side, enabling content management to authorized users. FPSE ship as a default component of IIS 5, and are implemented as a set of HTML files, scripts, executables, and DLLs that reside in a set of virtual roots with the name *vti_*, where the asterisk represents any bin, cfg, log, pvt, and txt (FrontPage was purchased from Vermeer Technologies, hence the vti application). ```
GET /vti_bin/server.asp HTTP/1.1
Host: 192.168.1.10

HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Date: Thu, 07 Mar 2002 04:38:01
Server: Microsoft-IIS/5.0
```
