# Hacking Exposed Web Applications

Now you're working on the command line with HTTP and HTTPS. The applications are going to fail! So, instead of saving every file from your browser or running lynx:

```
[root@meddle]# # mkdir www.victim.com
[root@meddle]# # cd www.victim.com
[root@meddle:www.victim.com]# # get.sh www.victim.com /index.html > index.html
www.victim.com [192.168.33.101] 80 (http) sent 27, rcvd 2683: NOTSOCK
[root@meddle:www.victim.com]# # mkdir secure
[root@meddle:www.victim.com]# # cd secure
[root@meddle:secure]# # get.sh www.victim.com /secure/admin.html > admin.html
```

The "/dev/null in the final line of get.sh suppresses connection and error information. The "s_client" is more verbose than necat and always seeing its output turns for a while. As we go through the Web application, you will see how important the get.sh and getit.sh scripts become. Keep them handy.

You can download dynamically generated pages with the "getit" scripts as long as the page does not require a POST request. This is an important feature because the contents of some pages vary greatly depending on the arguments they receive. In another example, getit.sh retrieves the output of some menu.asp page, but for different users:

```
[root@main]# # get.sh www.victim.com \
> /menu.asp?userID=002 > menu_002.asp
www.victim.com [192.168.33.101] 80 (http) sent 40, rcvd 3654: NOTSOCK
[root@main]# # get.sh www.victim.com \
> /menu.asp?userID=007 > menu_007.asp
www.victim.com [192.168.33.101] 80 (http) sent 40, rcvd 5487: NOTSOCK
```

Keep in mind the naming convention for its pages. The program grammilers dislike vowels (usMenu.asp,Upld.asp,httpText.php?) Were they verbose (AddNewUser.pl)? Were they utilitarian with the scripts (main.asp has more functions than an Swiss Army knife?) The naming convention provides an insight into the programmers' mindset. If you find a page called UserMenu.asp, chances a page called AdminMenu.asp also exists. The survey of an application is not limited to what you find by induction. It involves a deerstalk cap and a good amount of deduction.

# Using Google to Inspect an Application

There is one more place where you can enumerate a Web application's pages: Google (www.google.com). We love Google. Google is a search engine whose database contains an extremely voluminous snapshot of the Internet. It's a good bet that Google has indexed the Web application at least once in the past. There are several benefits to running a search:

+   You can search for a specific site. Type "+www.victim.com" (with the quotation marks) to look for URLs that contain victim.com.
