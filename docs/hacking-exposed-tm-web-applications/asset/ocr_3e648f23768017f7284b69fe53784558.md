# Chapter 12: Web Client Hacking

+   - Configure Web client software as securely as possible, including the following settings:
- Disable rendering of active content in Web client software.
- Disable scripting of ActiveX marked "safe."
- Disable rendering of <META REFRESH> and <IFRAME> HTML tags in Web software to prevent unintended visits to Web pages or execution of arbitrary files.
- Disable prompt before accepting cookies from unfamiliar Web sites.
- Make sure e-mail readers are configured with the most extreme security settings!
- Keep up with client-side patches (Web browsers, e-mail readers, multimedia players, and so on).
- Refrain from “promiscuous habits”—remember, clicking a link can be your undoing! Try to resist the alluring beauty of hyperlinks from new on, OK?
- Perform strict input validation on all user input to your application. In particular, strip out <, &, > characters, the main culprits in cross-site scripting vulnerabilities.
- Avoid implementing client-side code that privileges agents (such as ActiveX, Java applets, or JavaScript); such controls or applets can be subverted.
- Avoid cookies in your Web application if at all possible. If you implement cookies, using appropriate encryption mechanisms to prevent users from trivially manipulating cookie values; don’t keep sensitive information or set security-related values in cookies.
