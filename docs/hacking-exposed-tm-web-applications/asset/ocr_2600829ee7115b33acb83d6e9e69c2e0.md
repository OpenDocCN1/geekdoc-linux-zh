# Hacking Exposed Web Applications

# The URL

Take another look at the FORM example from the previous section. There was another hidden "field" in the action element of the FORM:

```
<FORM name=login_form action=
https://login.victim.com/config/login?4fr0naidr6d method=post >
```

Session variables do not have to be in SETs for the order to track the them. The server can set parameters or redirects customized to a specific user. Other examples might look like this:

```
/redirect.html/103-673347-6580661/
/ViewBase#sidrS5J5iOEEACi6r0E2ksQJnUEiakKFH/
/index.php?session_id=E3DF0FC4C-E5F7-4844-8DD9-4808906D85
```

In the latter case, the "sid" name gives the session ID. Carrying the session ID in the URL is not insecure, but there are many points to keep in mind.

+   * HTTPS If the session ID can be decoded from another computer, a malicious user could cleartext HTTP connections in order to spoof other users.
* Bookmarks A user might bookmark a URL that includes a session ID. If the application session IDs or removes them (if it has a small pool), then the bookmark will be invalid when the user returns.
* Content This applies to any client-side session ID. If the content can be decoded or decrypted, then the session ID is insecure. Check out the "SessionID Analysis" section in this chapter for more information.

# HTTP Headers and Cookies

Cookie values may be the most common method for saving state information. Ephemeral (nonpersistent) cookies are used to track state for a single session. The IIS ASPSESSIONID values are a good example of these types of cookies. These cookie values are never stored on the user's computer. You will need a tool like Achilles to see these values.

Persistent cookies are stored on the user's computer and last between sessions. A-persistent cookie has the:

```
Set-Cookie: NAME=VALUE; expires=DATE; path=PATH;
domain=DOMAIN_name; secure
```

The cookie's value carries the state information. Sites that "Remember me" function use these types of cookies. Unfortunately, they also tend to be insecure. Here's an example:

```
Set-Cookie: autolog=bWlrZpteXMzY3IdA%3D%3D; expires=Sat, 01-Jan-2023
00:00:00 GMT; path=/; domain=victim.com
```
