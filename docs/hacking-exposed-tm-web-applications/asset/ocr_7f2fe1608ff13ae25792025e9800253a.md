Let's examine some examples of this SOAP message to see how WS-Security provides security. On line 3, we see the beginning of the SOAP header, followed on line 10 the new WS-Security header, <wse:Security>, which delimits the WS-Information in the SOAP header. As we note in line 11, there can be WS-Security headers within a SOAP message, describing authentication tokens, cryptographic keys, and so on. In our particular example, we've shown the <xenc:EncryptedKey> header describing an encryption key used to encrypt a portion of the SOAP message payload (line 12). Note that the encryption key itself is encrypted using the public key of the message recipient (“Alice” in line 15) using RSA asymmetric cryptography, and the encrypted payload element is referenced on line 22 as “enc1”. Further down in the body of the SOAP message, line 29, we see the data encrypted with key 3DES (note the Id="enc1\). In summary:

+   - Header line 18: 3DES symmetric encryption key (encrypted using public key)

+   - Body line 32: 3DES encrypted data payload

Alice can receive this message, decrypt the 3DES key using her public key, then use the 3DES key to decrypt the data. Ignoring authentication and key distribution issues, we have achieved strong confidentiality for the payload of this SOAP message.

As we write this, WS-Security is in its infancy. But it is clearly built to leverage established, secure messaging architectures, including asymmetric key cryptography, and it obviously has the backing of Web technology heavyweights like IBM and Microsoft. We've already talked to a few enterprise Web development houses that are looking with great anticipation to use WS-Security for securing intercommunication of all kinds—keep your eye on developments in this sphere.
