You can see in the Location: field internal address space is revealed (172.16.X.X addresses are part of the private addressing scheme for this proxy, you can actually perform the equivalent of a port scan on systems on the internal network. First, configure your Web browser's proxy to be the remote proxy (in the previous example, 216.033.004.02 on port 80—and yes, this is not a real address; we changed names to protect the innocent). Now you can simply use standard HTTP requests directed at the internal address space to try and determine if ports are listening.

```
GET http://172.16.128.118:25/ HTTP/1.0
```

If Tcp port 25 on 172.16.128.118 is open, then the server should return a 200 response to indicate the request is successful. Otherwise, a response of HTTP 400 or 500 is returned.

# Reverse Proxy Countermeasures

This problem affects almost every version of Netscape Enterprise and related products. To fix the problem, the administrator blocks the HTTP method and any HTTP proxy-related functionalities on the server. Binding the server to a specific name is also recommended.
