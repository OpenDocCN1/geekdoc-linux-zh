# Hacking Exposed Web Applications

Collecting arguments is a complicated task that is rarely the same between two applications. As you collect the variable names and values, watch for certain trends:

- User Identification: Look for values that represent the user. This could be a username, a number, the user's social security number, or another value that appears to be tied to the user. This information is used for impersonation attacks. Relevant strings are userid, username, user, name, uid.
/login?userid=24601

- Session Identification: Look for values that remain constant for an entire session. Cookies also perform session handling. Some applications may pass session information on the URL. Relevant strings are sessionid, session, sid, s.
/menu.asp?id=89CD9A347

- Database Queries: Inspect for any values that may be passed into a database. Common values are name, address, preferences, or other user input. These are perfect candidates for input validation and SQL injection attacks. There are no simple injections of a database value other than matching a URL's action with the data handles.
/submit.php?Title=Me&iPhone=8675309

- Search Queries: An application search page always accepts a string for the user's query. It may also hide fields or hard-coded values that handle how the search is performed, how many matches it returns, or what collection of files to search. Look beyond the query string and note every argument passed to the search function. Search pages will be evident in an application.
/search?q=*maxret=100&sort=true

- File Access: Do the arguments appear to be filenames? Applications that use templates or customizable pages pull the formatting information from somewhere. One of our favorite hacks involves manipulating these types of URLs. The relevant argument names are template, file, temp.
/open.pl1?template=simple

Finally, a few arguments that the application programmers may have left by mistake. For Boolean arguments (such as "debug"), setting their values to TRUE, T, or 1.

- debug
- dbg
- admin
- source
- show

# Back-End Connectivity

The final set of information to collect is evidence of back-end connectivity. Note when information is read from or written to the database (such as updating address information or changing the password). Highlight pages or contents pages that directly relate to a database or other systems.

WebDAV options enable remote administration of a Web server. A misconfigured server could allow anyone to upload, delete, modify, or browse the Web document root. Check if they are enabled:

# Server Headers

The HTTP headers returned by the server also reveal the operating system, server version, and additional modules. Headers cannot always be trusted, after all, it is vital to mask information. But when headers include WebDAV versions, use the information to get a picture of the application.

# TOOLS TO AUTOMATE THE SURVEY

Several tools automate the grunt of the application. They are basically spiders; once you point them to a URL, you can sit back and create a mirror of the site. This is not a comprehensive collection of every available link within the application.

# lynx

| | |
|---|---|
| Pro | Flexible, command-line, SSL support |
| Con | Clumsy for mirroring a site |
| Final Analysis | Great for checking single URLs |

lynx (lynx.browser) is a text-based browser found on many systems. It provides a quick way of navigating a site, although extensive JavaScript will inhibit it. It finds that one of its best uses is downloading specific pages.

The -dump option is useful for its "References" section. Basically, this instructs lynx to simply dump the page to the screen. You can redirect the output to a file. This might not seem useful at first, but it includes a list of all links embedded in the HTML. This is useful for enumerating links with long argument strings.

```
[root@mobile]# lynx -dump https://www.victim.com > homepage
[root@mobile]# cat homepage
... text removed for brevity...
```

If you want to see the HTML source instead of the formatted page, then use the -source option. Two other options, -crawl and -traversal, will gather the HTML and save to file. However, this is not a good method for creating a mirror of the site because saved files do not contain the HTML source.

lynx is an excellent tool for capturing simple URLs. Its major advantage over the "get" scripts is to perform HTTP basic authentication using the -auth option:
