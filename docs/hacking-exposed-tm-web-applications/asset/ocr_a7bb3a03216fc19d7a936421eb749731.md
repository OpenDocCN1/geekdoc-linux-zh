# Hacking Exposed Web Applications

Script injection is an attack that inserts client-scripts into the browser and executes code on the client side to send the cookies to the hacker. This attack is quite unique in that it weaknesses in Web sites to attack the browser, rather than the Web site. The attack works by injecting client-scripts, usually JavaScript, into a Web site. This can be a message board system or e-mail, in the case of the Hotmail attack. The malicious JavaScript contains code to send cookies to the hacker executed by the browser, and the hacker can now use these cookies to 'log in' without your username or password. We discuss script injection techniques (also referred to as cross-site scripting) in Chapter 12.

Eavesdropping with a sniffer is the easiest way to steal cookies. Web sites that do not use SSL to encrypt all traffic are at risk of leaking out. Cookies used for authentication are often not set with the secure flag, indicating that its sent encrypted. This oversight can lead to authentication cookies being in the clear and subject to eavesdropping.

Reverse-engineering the cookie can also prove to be a very lucrative attack. The best approach is to gather a sample of cookies with different input to see how the cookie changes. This can be done by using different accounts to log in at different times. The idea is to see how the cookie changes on time, username, access privileges and so on. Ideally, you'd only want to change one of these fields at a time to minimize the degrees of freedom, but it is not possible. The next step is to partition the cookie into different fields, since many cookies are often encoded using Base64 encoding, and that cookie may need to be decoded before it can be interpreted.

If none of these methods work, another attack used against cookies is to reverse-engineer the bit-flipping attack. This attack works by first using a valid cookie, and methodically modifying bits to see if the cookie is still valid, and whether access is gained. The success of this attack depends on how the cookie is compromised, and whether there are any redundancy checks in the cookie.

We'll go into more detail on cookie attacks in Chapter 7.

# Countermeasure

Cookies containing authentication are inherently sensitive. Due to a slew of vulnerabilities with modern browsers, care must be taken when handling authentication cookies. Preventing script injection is best handled by input validation.

If the integrity of the cookie needs to be protected (such as, the user identifier is stored in the cookie), a message authenticity code (MAC) should be used to prevent tampering.
