Using the netstat utility on a victimized Web server is great to identify any strange connections to high ports on the Web server. As we have seen, these are likely connections to netcat shells. Outbound connections are much harder to differentiate from legitimate connections with Web clients.

In the log directory representations of the overlong Unicode and \_ making it harder to determine if foul play is at. Here are some telltale entries from actual Web server logs that come from systems compromised by unicode (asterisks equals wildcard):


Interestingly, a clear difference exists between the existence of the Unicode and double decode exploits in the IIS logs. Double decode strings are actually entered into the logs using %255c:

```
http://victim.com/scripts/../%25c..%255c/system32/cmd.exe?c+dir+c:\
```

appears in the IIS logs:
21:48:03 10.0.2.18 /scripts/../%5c..%5cwin/system32/cmd.exe 200

This enables one to search more easily on the %5c string to identify attempts to abuse this vulnerability. Remember, there are many possible Unicode and double decode strings like %c0%af and %255c—don’t use one or two to grep your logs.
