## Stealth HTTP Scanner

| Pro: | Extensible, updated regularly |
| Con: | Version 3.0 costs $250 for one IP, unintuitive interface |
| Final Analysis: | If you get the hang of it, comprehensive checks |

One of the newer and initially impressive Web vulnerability scanners available today is Stealth HTTP Scanner by Felipe Monet. The latest commercial version as of this writing, N-Stealth 3.0, claims to scan for over 18,000 HTTP security issues, and custom checks can be added to it using an extraordinarily simple script language. The following information applies to Stealth 2.0 build 35, since we were not able to obtain N-Stealth in time for publication.

Regardless of whether you can scan a list of servers or just one, Stealth will perform analysis whether or not the specified port is available. This is probably one of its most annoying features, and really makes the tool too slow to scan large ranges of systems.

Custom checks are exported, and those are contained within .exp files. Several .exp files with Stealth 1.0 in the program's Db Files\Stealth\. Check out the doublecode.exe script that runs with the standard Stealth package—this script was written by Arjun Shunn, and is a good example of the comprehensiveness and flexibility that can be achieved with Stealth.

You can write your own .exp files and store them as well to make them accessible to Stealth (the Database tab | Stealth's Export to see the list of .exp files kept in the Db directory; if your custom .exp does not show up, hit the refresh button in the lower right). You can select .exp files you want to run, and then tell Stealth to use them during a scan by clicking the Scanner button, selecting the Hacking Techniques tab, and selecting the Include Stealth's Techniques check box.

Writing .exp files is fairly simple. There are two types of checks you can write: standard checks and buffer overflow tests. A standard sample check is:

```
#GET /null.printer #500
```

This is a simple check to see if an IIS 5 Web server is vulnerable to the Internet Printing Protocol vulnerability discussed in this chapter. You can see that the GET HTTP method to request /null.printer, and expect an HTTP 500 Internal Server Server Error in response, indicating that the server is probably vulnerable.

Here's how to code a simple buffer overflow test:

```
bofgen=/sample.exe?%bofstr,"bytes=9","chars=a"
```

The resulting check by Stealth to the target server is

```
GET /sample.exeaaaaaaaaaaaa
```

This is an interesting tool for experimenting with boundary conditions, with buffer overflow tests (as it does with standard checks), so it is of limited utility unless you're running a debugger on the target server or otherwise monitoring the effects of the requests.

Version 2.0 now includes an Expl Development tool that essentially puts a graphical end onto the .exp file development process. It allows you to specify request strings, expected responses, and options. Also included with 2.0 is an update utility that automatically goes out to a user-defined server and obtains and installs any updates.

## Typhon

| Pro: | Simple graphical interface, online updates |
| Con: | No custom vulnerability checks, one host at a time only |
| Final Analysis: | Wait for Typhon II |

Typhon is the reincarnation of Cerberus Internet Scanner (CIS), written by David Litchfield and rewired at their company, Cerberus Internet Security of the United Kingdom. David passed through the hands of @Stake for a brief period, and is now marketing Typhon on its own again through a new company, Next Generation Security Software (NextGenSS Ltd.).

Figure 3-7. Stealth HTTP Scanner

CIS was a basic security scanning tool—what it lacked in sheer number of checks, it made up for the quality of the checks it did perform. Typhon continues in this tradition, evaluating a variety of well-known security issues on the remote target host, including NT-, SNMP-, RPC-, SQL-, SMTP-, and FTP-related security holes. It even includes an integrated port scanner. Figure 3-8 shows the straightforward configuration for Typhon I.

In this course, we are primarily interested in the Web checks, and Typhon does not disappoint here if you are looking for Windows-oriented security holes. Typhon formats its results into a clean HTML report.

The main drawback to Typhon compared to other scanners we have reviewed so far is that you cannot write custom checks. Updates are available online, but they replace the entire Typhon binary and cannot be added modularly. Also, Typhon I only scan one host at a time, as compared to other scanners' ability to scan ranges of systems. In early 2002, NextGenSS released a commercial version of Typhon I called Typhon II that claims is much more robust. We were unable to obtain a copy for testing by publication time.

## WebInspect

| Pro: | Clean interface, fast, comprehensive, easy to update, detailed reports, rudimentary custom checks |
| Con: | Cost-ly, licensed by target IP address |
| Final Analysis: | Lots of potential, but pricey |

WebInspect from SPI Dynamics is an impressive Web server and application-level vulnerability scanning tool. It harvests site content and analyzes it for vulnerability application-level issues just looking for over 1,500 known Web server and application vulnerabilities, it as guessing of common Web files that may not be indexed, password guessing, parameter passing, and hidden parameter checks. The tool is easily updated, and it can be extended to use custom checks with the speed of these—it was able to perform a full analysis of a basic Web server in under four minutes, not including over 1,500 HTML pages.

WebInspect has some drawbacks. One is—we quoted a perpetual license-price of $5000 per server plus 20 percent annual maintenance and support at the time of this writing. Another gripe is that licenses are tagged to target IP ranges, a burdensome feature for large organizations. We were also intrigued with the message we received when scanning our test network with the demo version we received from SPI Dynamics:

> You are using a version of WebInspect that provides the IP address of all scanned sites to SPI Dynamics via a secure connection in order to authenticate your license.

Hopefully, this is only the case with the demo version.
One minor criticism we had was that scans need to be manually configured one site at a time—taking a text file of IPs would be much better for large environments. Overall, the tool has great promise, but is probably only accessible to well-funded organizations under the current pricing model. WebInspect is shown in Figure 3-9.
