## Query String

The query string is the extra data in the URI after the question mark (?) is used to pass variables. The query string is an ampersand-delimited list and can contain multiple values between the client and server. An example would be http://www.mail.com/mail.aspx?joe=joe&company=acme%20com. The query string is visible in the Location bar on the browser, and is easily changed without any special Web hacking tools. Things to try would be to change the URI to http://www.mail.com/mail.aspx?jane=jane&company=acme%20com attempt to view Jane's mailbox while authenticated as Joe.

## POST Data

Since queries in browsers are so easily modifiable, many Web application programmers prefer to use the POST method rather than GET with queries. This typically involves the use of forms. Since the browser normally doesn't display POST data, some programmers feel fooled into thinking that it is impossible or difficult to change the data. This is wrong! It is actually quite simple to change these values. There are several techniques to change these values. The most basic of techniques involves saving the HTML page, modifying the HTML source, and POSTing a fraudulent request. gets old due to repetitive tasks. Seasoned web hackers will use a proxy-based tool that would allow them to change this data on the fly, such as Achilles. Recently, more tools that hook into the IE API have emerged that do not require proxies.

One important thing to note on a POST request is the Content-Length HTTP header. This length specifies the length of the POST data in number of characters. This field has to be modified to make the request valid if the length is changed; however, tools like curl calculate this number authentically. For example, here's the curl syntax for a POST request to access bank account information:

```bash
curl -v -d 'authmask=8195' -d 'uid=213987755' -d 'a=viewacct' \
> url https://www.victim.com/
* Connected to www.victim.com (192.168.1.23)
> POST / HTTP/1.1
User-Agent: curl/7.9.5 (x86-pc-cywin) libcurl 7.9.5 (OpenSSL 0.9.6c)
Host: www.victim.com
Pragma: no-cache
Accept: image/gif, image/x-xmap, image/jpeg, image/jpeg, /**
Content-Length: 38
Content-Type: application/x-www-form-urlencoded

authmask=8195&uid=213987755&a=viewacct
```

Thus, you see how curl makes it easy to calculate the Content-Length header.

## Hidden Tags

Hidden tags are so-called "hidden" values used in forms to pass data to the server. They are often used to track a session, a necessary inclusion since HTTP is a stateless protocol. Some sites use hidden tags to track product pricing or sales tax. Although hidden tags are hidden from the user viewing a Web site through a browser, tags are still visible in the HTML source of the page. In the case where an application passes sales tax through hidden tags, you could modify the value from a positive value to a negative one—suddenly sales tax works like a rebate! Hidden tags are part of HTTP forms, so you will see their values being passed in GET or POST requests. You should still look for the actual tags, where the field name or HTML comments may provide additional clues to the tag's function.

## URI

The Universal Resource Identifier (URI) is the string in the Location of the browser. The URI will be composed of the hostname of the Web server, along with the file to be retrieved. By simply modifying the filename and the URI, a hacker can sometimes retrieve files that would not normally be viewable. For example, a site may have a link to http://www.victim.com/data/report12345.txt after you pay for access to report. Looking at the URI from a hacker's point of view, you would attempt to access http://www.victim.com/data/report12346.txt.

Another example of bypassing authorization is the Cisco IOS Authorization vulnerability. The URL of the Web-based administration interface contains a two-digit number between 16 and 99.

```
http://www.victim.com/level/NN/exec/...
```

By guessing of NN (the two-digit number), it is possible to bypass authorization and access the device's administration interface at the highest privilege.

Directory traversal is another example of bypassing an application's or Web server's authorization scheme. The well-publicized Unicode Directory Traversal attack for IIS took advantage of a weakness in the server's parsing and authorization engine. Normally, IIS blocks attempts to escape the Web document root with URIs like "/scripts/../../..../wwinnt". The Unicode representation for the slash (/) is "%c0%af". IIS did not interpret the Unicode representation during its authorization check, which allowed a malicious user to escape the document root with a URI like "/scripts/..%c0%af/..%c0%af/..%c0%af/wwinnt".

The Cisco and ActiveX examples should illustrate the point that the URI does not just mean the parameters in the query string. After all, we considered the parameters as a separate aspect. A careful survey of the application can reveal patterns in the convention for the application's pages. If a /user/menu directory exists, perhaps an /admin/menu exists as well. Hopefully, the application does not rely on obscurity to protect its administration front-end.

## HTTP Headers

HTTP headers are not normally used by Web applications that work with browsers. They are sometimes used by applications that have http-clients that use the HTTP protocol, however. This is a small percentage of Web applications. However, we include it in this section to illustrate that any input can be modified. Cookies are perhaps the most well-known headers, but authorization schemes can also be based on “Location:” and “Referer”(the HTTP definition misspells the term). The application might also rely on custom headers to track a particular attribute of the user.

One of the simplest authorization tests is the browser check. Many tools, curl included, enable the user to specify a custom User-Agent header. So, if an application requires Internet Explorer for popular reasons as opposed to technical ones (such as requiring a component), you can change this header to impersonate IE.

```bash
$ curl --user-agent "Mozilla/4.0 (compatible; MSI 6.0; Windows NT 5.0) \ --url www.victim.com
```

## Cookies

Cookies are a popular form of session management even though the use of cookies has been plagued with security vulnerabilities. However, their use is still common and are often used to store important fields such as usernames and account numbers. Cookies can be used to store any data, and all of fields can be easily modified using a program like CookieSpy. CookieSpy (http://www.codoproject.com/shell/cookiespy.asp) is a plug-in for Internet Explorer that opens a pane in the browser to display all of a site's cookies.
