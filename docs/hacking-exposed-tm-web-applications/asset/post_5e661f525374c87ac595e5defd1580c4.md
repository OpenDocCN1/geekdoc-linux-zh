### Default Internal Variables

Microsoft SQL Server has several built-in variables that return information about the server. These variables will be available even if the administrators lock access to the extended stored procedures (xp* commands). They also have the advantage of consisting of a single word. They don't require the database name prepended, as in master..xp_cmdshell. Table 9-2 lists the default SQL Server variables.

The procedures in table type return the most useful information. They only return a single datum—this comes handy in some circumstances, as manipulating ODBC error codes that operate on a single variable.

Each of the procedures can also be called with a select statement in the format: SELECT @@@variable.

### Extended Stored Procedures

The extended stored procedures, signed by the “xp_” prefix, provide robust system administration entirely from the comfort of SQL. We will cover countermeasures at the end of this chapter, but we’ll hint that one countermeasure involves removing these commands entirely. Table 9-4 lists some procedures that do not require a parameter. Table 9-5 contains a list of procedures that require a parameter.

These commands cover just about any aspect of system-level access. Also, before you're tempted to use xp_regread to grab the SAM file, you should know that technique only works against systems that do not have Syskey enabled. Windows 2000 enables this by default.

### Default Local Tables (the Useful Ones)

Also known as System Table Objects, these tables contain information about the database and the operating system. Table 9-6 lists tables that have the most useful information.

The easiest method to retrieve information from one of these tables is a SELECT * example:

```
SELECT * FROM sysfiles
```

However, if you are familiar with databases, then you can parse the request to certain fields—for example, view all stored procedures:

```
SELECT name FROM sysobjects WHERE type = 'P'
```

# General SQL Techniques

The previous section's focus on Microsoft SQL Server should not preclude you from trying SQL injection techniques against other databases. MS SQL Server merely has an extreme amount of functionality built into it that makes a SQL injection more devastating. There are several techniques that apply to SQL-based databases.

SQL Operators has a predefined list of keywords, set aside to have special meanings. When you select data from a table, you use the SELECT statement. A application gets a lot out of SELECT, FROM, and WHERE tokens—these constitute a basic query. SQL injection can extend the query in order to retrieve alternate information or generate an always true condition.

> TIP These represent data manipulation techniques. The manner in which they are injected varies from a single tick, to double dashes, to multiple ticks and parentheses. This is why it's so important to be able to walk through a series of SQL errors in order to find the right track into the database.
