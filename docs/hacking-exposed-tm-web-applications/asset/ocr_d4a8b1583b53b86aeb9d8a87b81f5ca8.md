# Potential Weaknesses with Forms Auth

As we've seen with Forms-based authentication, cookies are often used to temporarily store an authentication token so a user accessing a Web site does not have to constantly input the information over and over again. Cookies can sometimes be manipulated or stolen outright, and may disclose inappropriate information if they are not encrypted (note that ASP.NET was configured with 3DES-encrypt the cookie in our example). See Chapters 7 and 12 for more on attacking.

Hidden tags are another technique to store transient information about a user (we saw the hidden field “state” passed with authentication credentials in our previous example). Authentication credentials themselves also be stored within hidden tags, making them “hidden” from the user. However, as we've seen, hidden tags can be modified by attackers before they are POSTed to the server at login.

# Microsoft Passport

Passport is Microsoft Corporation’s universal sign-in (SSI) platform for the Internet. It enables the use of one set of credentials to access any Passport-enabled site, such as MSN, Hotmail, and Microsoft Messenger. Passport is not restricted to Microsoft Web properties. In fact, Microsoft encourages third-party companies to use Passport as a universal authentication platform (such sites are called Partners). Microsoft provides a Passport SDK and the Passport API to allow Developers to take advantage of the Microsoft authentication infrastructure.

Passport works essentially as follows. A browser to the Passport Registration site creates a user profile, including a username and password. The user is now registered Passport member, and his or her credentials are stored on the Passport servers. Meanwhile, abc decides to become a Passport Partner, downloads the SDK, and signs an agreement with Microsoft. abc.com receives a cryptographic key via email mail, and installs it on their web server(s), with the Passport Manager Tool login servers retain a copy of this cryptographic key.

Now, when a Passport member seeks content on abc.com’s site, they are redirected to the Passport’s login servers. They are then challenged with a login page that takes their Passport credentials as input. After successfully authenticating, the Passport’s login servers set an authentication cookie in the client browser (other data may be set as well, but it’s the auth cookie we’re interested in here).
