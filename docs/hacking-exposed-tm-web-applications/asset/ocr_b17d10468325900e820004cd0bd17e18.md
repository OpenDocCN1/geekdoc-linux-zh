# Hacking Exposed Web Applications

Web sites present data. The data range from Web journals to catalogs of widgets to real-time financial information. Users see the colorful front-ends that present them with personalized shopping, but they do not see the less glamorous database servers sitting behind the scenes like a great Oz, churning away silently to manage inventory, users, e-mail, and other data-related functions.

The unseen database server is untouchable. In this chapter we will show how variables—your username, for instance—can be modified to contain special instructions that affect how the database performs. These modifications, or drive to the heart of the application. After all, a Web merchant does not store credit card information in a file on the Web server—it’s in the database.

# SQL PRIMER

Remember the Web architecture presented in Chapter 1? We're focusing on the data store, let's review how the Web server interacts with the database. Where a Web server only understands the HTTP protocol, database servers only understand a specific language: SQL. We can draw on many examples of how the Web server connects to the database, and we’ll use the ubiquitous user login page.

When a user logs in to the site, the Web application collects pieces of information, the username and password. The application takes these two parameters and creates a SQL statement that will collect some type of information from the database. At this point, however, only the Web server (the login.php, for example) has performed any actions. Next, the Web server connects to the database. This connection must be established once and maintained for a long time, or the two servers need to communicate. Either way, the Web server uses its own username and password to authenticate to the database.

The server is now talking to the database. So, login.php passes the user credentials (username and password) as a SQL statement to the database. The database accepts the statement, executes it, then responds with something like “username and password match” or “username not found.” It is up to the application, login.php, to handle the response from the database.

SQL is a powerful part of the application. There are few other ways to store, query, and manage amounts of data other than using a database. That is also why why it is important to understand how a SQL statement can be misused.
