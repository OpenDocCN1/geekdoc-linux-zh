# Chapter 3: Hacking Web Servers

Use IISLockdown and UrlScan In 2001 (no comments on timeliness, please) Microsoft released a tool called the IISLockdown Wizard (see the "References and Further Reading" section of this chapter for a link). As its name implies, IISLockdown is an automated, template-driven utility for applying security configurations to IIS. It configures various settings related to the following items:

+   * Internet Services Allows disabling of the four IIS services (WWW, FTP, SMTP, and NNTP) as appropriate for the role of the server.
* Script Maps Allows disabling of ISAPI DLL script mappings as appropriate for the role of the server.
* Additional Security A catchall section that includes removal of default virtual directories like IISSamples, MSADC, IISHelp, Scripts, and so on; NTFS ACLs to prevent anonymous users from running system utilities like cmd.exe and writing to content directories; and disables WebDAV.
* UrlScan A template-driver filter that intercepts requests to IIS and rejects them if they meet certain criteria (in this presently).

This is a fairly comprehensive list of IIS-specific configuration issues, but there are some omissions. Lockdown does nothing about installing Service Packs and Hotfixes, it does not touch any other aspects of the Windows operating system that may be vulnerable, and it doesn't set up an appropriately configured firewall in the server. IIS Lockdown is a great simplifying tool, but don't rely on it to the point that you leave other doors open.

Since most of the IISLockdown Wizard can be configured manually, we think one of the most compelling features of IISLockdown is UrlScan. In fact, UrlScan can be extracted from the IISLockdown Installer (iislockd.exe) by running the Installer with the command line with:

```
iislockd.exe /q /c /t:\download_files
```

Once extracted, UrlScan can be manually installed on the server(s) that require protection (namely, running iislockd.exe without arguments will automatically install UrlScan from within the IIS Lockdown).

UrlScan consists of two files, UrlScan.dll and UrlScan.ini,which must be installed in IIS so it can intercept HTTP requests after IIS receives them, and UrlScan.ini is the configuration file that determines what HTTP requests the UrlScan API filter will reject. Rejected requests will be logged to a file called UrlScan.log in the same directory as UrlScan.dll and UrlScan.ini (log files may be named them UrlScan.MMDDYY.log if per-day logging is configured). UrlScan sends HTTP 404 "Object not found" responses to denied requests, frustrating attackers seeking any tidbit of information about the target server.
