# Attacks Against Passport

There have been a few attacks against Passport since its introduction in 1999. In 2000, David P. Korkmann and Ariel D. Rubin published a paper entitled Risks of the Passport Single Sign-On Protocol that described a series of attacks more generic to basic features like SSL, Netscape browser cookies, Javascript, and DNS sniffing. They also pointed out that anyone can spoof a Passport page and harvest member credentials (the “bogus Partner” attack), and speculated that Partner site keys were transmitted over the Internet in a vulnerable fashion. The entire paper known issues with Internet authentication services, and demonstrates real research into problems with Passport information.

In August 2001, Chris Shiflett published a paper on a vulnerability in Internet browsers prior to version 5.5 that allowed malicious sites or e-mail messages to read cookies on client machines. He also noted that if a Passport member opted to save his or her Passport cookies locally, an attacker that leveraged this vulnerability could be used to steal Passport cookies and masquerade as the victimized member. The IE hole has subsequently been fixed, and Chris rightly comments that users do not select the “Sign me in automatically” option when using Passport (which sets a persistent cookie on the user’s machine).

Later in 2001, security researcher Marc Slemo posted an analysis called “Microsoft Passport to Trouble”, in which he describes an exploit that would allow him to steal authentication cookies using script injection on Paypal that use Passport authentication. Microsoft has since fixed the problem, but this attack is an excellent example of how to steal authentication cookies.

The common theme of all of these attacks suggests that one of the greatest dangers in using authentication is replay attacks using Passport authentication cookies from unsuspecting users’ computers. Of course, assuming an attacker could steal authentication tickets would probably defeat most authentication systems out of the gate.
