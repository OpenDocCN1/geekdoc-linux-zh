# Chapter 7: Attacking Session State Management

TIP You'll notice that Perl becomes increasingly useful as we progress through this chapter. We encourage you to become familiar with this handy language.

MD5 hash is a one-way algorithm that is like a fingerprint for data. As a one-way algorithm it is not reversible, meaning that there is no way to decrypt an MD5 hash to figure out what it contains. Regardless of the input to an MD5 function, the output is always 128 bits. Consequently, the MD5 hash can be represented in three different ways:

+   - 16-Byte Binary Digest Each byte is value from 0 to 255 (16 * 8 = 128).
- 32-Byte Hexadecimal Digest The 32-byte string represents a 128-bit number. Think of four 32-bit numbers, represented in hexadecimal, concatenated in a single string.
- 22-Byte Base64 The Base 64 representation of the 128 bits.

Obviously, not every 22-character string you come across is going to be an MD5 hash. If you are sure that you've found a hash, the next thing you will want to do is figure out its contents. For example, you could use different combinations of login credentials:

```
$ perl -e 'use Digest:MD5; \\
> print Digest:MD5::md5_base64('userpassword') '
BZxQ5hVyDnyCZPUM89+g
$ perl -e 'use Digest:MD5; \\
> print Digest:MD5::md5_base64('passwduer') '
de1VfbC32z2ORIlwKhQ
$ perl -e 'use Digest:MD5; \\
> print Digest:MD5::md5_base64('passwordsalt') '
PQxfId2wlzfNopfweHnya
```

If the token is yours, you've figured it out (the username is prefixed to password). Sites that use MD5 often insert random data or dynamic value in order to defeat brute-force guessing attacks against the token. A more secure way of generating the token, especially if it is based on the password, involves secret data and a timestamp:

```
MD5( epoch time + secret + password )
```

Placing the most dynamic data at the beginning causes MD5 to "avalanche" quickly. The avalanche effect means that two values differing by only a few bits will produce two hashes that differ greatly. The advantage is that a malicious user has only one of the three pieces of the secret value. It wouldn't be hard to find the value for the epoch time (it may only be one of 100 possible values), but the server's secret would be difficult to guess. A brute-force attack could be launched, but success would be difficult. The disadvantage is it will be difficult for the server to re-create the hash. The server must track the token it was generated so it can make the proper seed.
