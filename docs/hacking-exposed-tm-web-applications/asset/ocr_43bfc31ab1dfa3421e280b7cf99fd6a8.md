Most of the power of HTML derives from its confluence with HTTP. When combined with HTTP’s ability to send and receive HTML documents, a vibrant protocol for communications is possible. Indeed, over HTTP is considered the lingua franca of the Web today. Thus, we will spend more time talking about HTTP in this book than HTTP by far. Ironically, despite the elegance and infuse of HTML, it is being supersed by other technologies. This is primarily due to HTML’s most obvious drawbacks: it is a static format that cannot be altered on the fly to suit the shifting needs of users. Most Web sites use scripting languages to generate content on the fly (which will be discussed in the upcoming “The Web Application”).

Finally, the asendance of markup language on the Internet has marked a decline in the use of HTML. Similar to HTML in its use of tags to document elements, the Extensible Markup Language (XML) is becoming popular for structuring data on the Web due to its extensibility and flexibility to represent data of all types. XML is well on its way to becoming the new lingua franca of the Web, particularly in the arena of Web services, which we will cover briefly later in this chapter and at length in Chapter 10.

OK, about HTTP? Let’s move to the basic component of Web applications that’s not likely to change anytime soon, HTTP.

# Transport: HTTP

As we mentioned, Web applications are largely defined by their use of HTTP as the medium of communication between client and server. Stateless, ASCII-based protocol defined in RFC 1945 (version 1.0 is a relatively version 1.1 is covered in RFC 2616). It typically operates over TCP port 80, but can exist on any unused port. Each of its characteristics—simplicity, statelessness, text base, TCP operation—is what we are briefly since is so central to the (in)security of the protocol. The discussion below is a very broad overview; we advise readers to consult the RFCs for more exacting detail.

HTTP’s simplicity derives from its limited set of basic capabilities, request and response. HTTP defines a mechanism to request a resource, and the server returns that if it is able.
