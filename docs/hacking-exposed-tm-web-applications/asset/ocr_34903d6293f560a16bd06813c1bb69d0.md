# Forms-Based Authentication

In contrast to the mechanisms we've discussed to this point, Forms-based authentication does not rely on features supported by the basic Web protocols like HTTP and SSL (such as Basic Auth or client-side certifications). It is a highly customizable mechanism that uses a form, usually composed of HTML with <FORM> and <INPUT> tags delineating fields for users to input their username/password information. The data is input via HTTP (or SSL), it is evaluated by server-side logic and, if the credentials are valid, some state or token is given to the client browser to use on subsequent requests. Because of its highly customizable and flexible nature, Forms-based authentication is probably the most popular technique deployed on the Internet. However, since it doesn't rely on any features of standardized Web protocols, there is no standardized way to perform Forms-based authentication.

The recent introduction of the FormsAuthentication class in Microsoft's ASP.NET is one of the first standards of Forms-based authentication.

Let's present a simple example of Forms-based authentication to illustrate the basically on which it is based. This will be based on Microsoft ASP.NET FormsAuthentication because of its simplicity, we will note key points that are generic to forms auth. Here's the scenario: a single directory on a Web server with a file, default.aspx, that should require forms auth to read. In order to implement ASP.NET forms auth, two other files are needed: a web.config file in the directory (or at the application root), and a login form to take username/password input (call it in login.aspx). The web.config file which will be protected by forms auth, and it contains a list of usernames and passwords that can be queried to validate credentials by users in login.aspx. Of course, any source of username/password information could be—for example, a SQL database. Here's what happens when someone requests default.aspx:

```
/default.aspx HTTP/1.0
```

Since the web.config file provides all resources in this directory require forms auth, the server responds with an HTTP 302 redirect to the login page, login.aspx:

```
HTTP/1.1 302 Found
Location: /login.aspx?ReturnUrl=%2fdefault.aspx
```
