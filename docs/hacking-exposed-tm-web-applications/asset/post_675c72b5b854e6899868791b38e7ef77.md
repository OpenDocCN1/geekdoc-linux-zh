# Active Content Countermeasures

Clearly, active technologies like JavaScript and ActiveX represent a double-edged sword—while they permit developers to create a more rich, and easily managed experience for Web users, the power inherent in their capabilities can easily be subverted for malice. We present some examples below that can be implemented on both the client and server (developer) sides to limit the security risks inherent in using active content.

# Chapter 12: Web Client Hacking

**Client-Side Countermeasures** From the end-user’s perspective, the only sure way to avoid active content exploits is to stay off the Internet completely, an unrealistic recommendation for most of us (although we know some governmental agencies where restrictive policies are applied in the interest of national security).

A less restrictive option is to use products that have traditionally been targeted by such attacks. The prime target at the time of writing is Internet Explorer, and the somewhatired Outlook and Outlook E-mail clients. A mind-numbering array of vulnerabilities in IE have been published over the years, and they become the regular grist for the virus/worm community as it continues to evolve new and more elaborate exploits. Whether this is due to the sheer popularity of IE or the prevalence of flaws in its codebase is debatable, but those who wish to avoid the issue can install Web browsers such as Opera or Netscape Navigator, and e-mail clients if they choose non-Microsoft clients:

- Non-Microsoft products have their bugs, especially the popular ones like Netscape and Eudora. Don't rely on other products as an excuse not to keep up with software patches and configuration best practices.

- IE and its related products (Outlook Express, Windows Media Player, and so on) are installed on Windows by default, and they are available for attack even if you use a different product to browse the Web. Although your risk may be reduced significantly if you do not actively use them, it is never 100 percent gone.

- Under the covers, many third-party clients rely on the IE HTML rendering functionality, even though you think you are using a product that isn't vulnerable to the latest IE exploit, you may be mistaken.

Of course, keeping up with security-related software patches is also one of the most important mechanisms for avoiding specific Web client attacks. If your browser’s vendor does not maintain a specific section of the Web dedicated to security, you’ve probably selected the wrong vendor (even if there aren’t many security bugs to talk about on the site).

It is sometimes helpful to be able to remove active content from your machine, when an adversary is posted (with the Gator Setup ActiveX control, for example). Microsoft Knowledge Base article Q15480 explains how to uninstall controls (see “References and Further Reading” at the end of this chapter). On IE 4 and later, the quickest way is to browse to the folder where ActiveX controls are cached (called the Occache), right-click on the question, and select Remove. Remember that multiple locations exist under Internet Explorer 4.0 and later—see the following Registry key to determine where they are:

```
HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Internet Settings\ActiveX
```
