# Hacking Exposed Web Applications

We have focused up to this point on identifying, exploiting, and patching common Web security holes, with an emphasis on server-side waves. But what about the client side?

As we discussed in Chapter 1, Web applications rely on client architectures, and often, very short shift is given to the thin end of this equation. This is a mistake—at as many security vulnerabilities exist on the other end of the Internet telescope, and numerous other factors make them just as likely to be exploited.

We will discuss these factors and related vulnerabilities in this chapter. We will begin with a brief overview of the challenges faced with client-side security, and we'll tackle several of the most severe types of vulnerabilities that we've seen in the real.

# THE PROBLEM OF CLIENT-SIDE SECURITY

After perusing nearly dozens chapters of the many problems faced on the server side of Apps, you may be tempted to dismiss client-side security as uninteresting or worthy of attention. If you're mistaken, the following events will hopefully illustrate:

+   August 2000 Silicon Valley computer consultant Dan B불어 releases a program he calls Brown Orange to demonstrate how he discovered that allow a Java app to take privileged actions on a client system when browsing a malicious website. Although no exploits are observed in the world, B불어's announcement caused a swirling media sensation focusing a great deal of negative PR on the Java platform.

+   September 2000 San Francisco computer programmer Jeff Baker reports on the Bugtra security mailing list that customer accounts at the online brokerage ETRADE are vulnerable to cross-site scripting and cookie manipulation attacks.

+   January 2002 security researcher Dave DeVry notifies readers of the Bugtraj mailing list that Citibank's online cash-payment site, C2IT.com, has fixed a cross-site scripting security flaw that he claims privately normed the company about September. DeVry says that the vulnerability would enable an attacker to see "credit-card numbers, bank-account numbers, security codes, and other data without obfuscation."

These are just a handful of cases that have suffered from client-side security disclosures in the recent past—others include such AOL, eBay, Microsoft, Yahoo, MSN, Elite, and Lycos. Clearly, some large organizations suffered a great deal of public relations damage from such disclosures, and have additionally suffered losses related to customer data exposure, system downtime to address the underlying technical issues, and potential legal costs. Even though these problems did not fall into the mold of a classic Internet hack, where a server is compromised over the Internet by a malicious intruder who steals data (or worse), the effect was nearly the same.
