```
C:\>fscan -qp 80 192.168.10.15-100

http://www.foundstone.com
```

Scan started at Thu Feb 14 20:32:33 2002

+   - 192.168.10.17 80/tcp
- 192.168.10.18 80/tcp

Note that we've used fscan's q for quiet switch, which doesn't attempt to ping the target address first. We've turned up several other servers in this range, probably all load-balanced, identical servers. Frequently, however, we encounter one or more servers in the farm that are different from the others, running an out-of-date software build or perhaps alters service like SSH or FTP. It's usually a good bet that these rogues have security misconfigurations of one and another, they can be attacked individually via their IP address.

One other thing to consider is virtual servers. Some Web hosting companies attempt to spare hardware costs by running different Web servers on multiple virtual IP addresses on the same machine. Be aware that port scan results indicating a large population of live servers at different IP addresses may actually be a single machine with multiple virtual IP addresses.

# SERVICE DISCOVERY

Once servers have been identified, it's time to figure out what ports are running HTTP (or SSL as the case may be). We call this process service discovery, and it is carried out port scanning for a list of common Web servers. We've listed the most common ports used in Web service discovery in Table 2-3, along with the Web service most associated with them. Note that many of these ports are Web-based administrative interfaces, which we will discuss in more detail in Chapter 11.
