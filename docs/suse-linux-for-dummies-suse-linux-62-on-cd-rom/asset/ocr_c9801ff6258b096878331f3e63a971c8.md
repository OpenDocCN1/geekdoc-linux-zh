# Chapter 13: File System Management

And sometime later, you see a message that looks like the following, which describes the existing partitions on the new disk (if any):

```
hdb: hdb1 hdb2 < hdb5 hdb6 hdb7 hdb8 >
```

A SCSI disk drive has messages that look like this:

```
SCSI device sdb: hdwr device=......
sdb: sdb1
```

If you see these messages, the kernel has seen your new disk, and you don't have to rebuild the kernel to use the new disk.

![](bbox=[0.053, 0.355, 0.138, 0.403])

The Linux distribution on the SuSE Linux for Dummies CD-ROM features block special files for each of IDE disks (hda – hdb) with nine partitions (1 – 9). Linux also has block special files for seven SCSI hard disk drives (sda – sdg), which can have eight partitions each (1 – 8). In addition, Linux has a special file for a SCSI CD-ROM (scd) with eight partitions (0 – 7). If you have lots of disks, or if your distribution of Linux doesn't enough partitions for your disk, you may have to create one or more special files for the device, like this:

```
cd /dev; makedev sd
```

This creates the block special files for SCSI disk 7. Note that in both IDE and SCSI disks, the letters and numbers correspond: a is for the first disk, b is for the second disk, and so on.

If you add a SCSI disk with a lower ID number than you already have, the new disk drive takes on nothing. Suppose that you have SCSI disk drives with hardware ID numbers of 0, 2, and 3. Linux gives these disks the names sda, sdb, and sdc, respectively. You make your partitions and, create your entries in /etc/fstab to show where the file systems are mounted. Now you get a new disk drive and set the hardware ID to 1. When you reboot, the new disk gets the sdb designation, and the disks with ID numbers of 2 and 3 are renamed to sdc and sdd, respectively. For this reason, for the very least, it's a good idea to add SCSI disk drives to your system starting with ID 0 and working up the number chain, with no gaps in the numbering.
