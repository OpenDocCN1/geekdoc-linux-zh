When bash looks at that line, it performs the following steps:

+   1. bash creates a new environment for the ls command to be executed and determines what should be standard input and standard output to the command. Standard input is normally the keyboard, and standard output is normally the video screen. (You find out about environment in a moment.)n2. bash expands * to match all the filenames in that particular directory. By expanding the filenames, we mean that certain special characters are used to identify groups of filenames. When these characters are used, the computer sees what filenames match with these special characters and supplies the filenames to the command, instead of the special characters.
3. For example, suppose that you have the files ert, wert, uint, and opgt in your current directory. If you typed

```
ls -1 *
```

to the ls command, it would look as though you typed

```
ls -1 ert wert uint
```

Note that the shell puts the names in alphabetical order before giving them to the command.

+   3. Next, bash searches the PATH environmental variable looking for a command called ls. The PATH variable holds names of directories that contain commands you may want to execute. If the command is not in the list, you have to explicitly tell the shell where it can find the command by typing a complete or relative pathname to the command.
4. bash executes the ls command in the new environment, passing to the command -1 argument and all the filenames, expanded, owing to the use of the * character in the command.
5. After ls runs, bash returns to the current environment, throwing away all the side effects that occurred in the new environment, such as an environmental variable changing its value.
