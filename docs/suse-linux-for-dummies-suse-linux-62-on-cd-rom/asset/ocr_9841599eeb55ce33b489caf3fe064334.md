# Incorrect parallel port

You can verify that you are using the correct parallel port by pushing a file straight to the printer (printing device) and bypassing the printing system (the software that manages the spooling and queueing of print jobs). We do imagine, this is possible using the following command:

```
root@localhost:~ # cat /etc/passwd > /dev/lpp0
```

This command bypasses the printing system and pushes the file (/etc/passwd) directly to the printer port (/dev/lpp0). Normally, the command /etc/passwd will display the contents of the file /etc/passwd on the screen. In the example we're using here, you use the redirect symbol > to redirect the output to the parallel port /dev/lpp0. As you can imagine, this is a powerful tool. The > symbol has an opposite as well: the < symbol. You can view the contents of the data coming from the parallel port by using

```
root@localhost:~ # cat < /dev/lpp0
```

If your printer is sending information to your system (as most printers do), you will see the message here. On our system, the message is:

```
@PJL STATUS DEVICE
CODE=41202
DISPLAY=LOAD LETTER PAPER
```

# Resource conflict

By default, the printer port in Linux is configured to use the ioport 0x378. Some modern BIOS allow you to select different iports for your parallel port. If the BIOS setting and the Linux configuration setting are different, it will cause problems. If this is the case, we recommend that you reset your BIOS to match ioport setting in Linux.

# Ending Your First Session

Logging off the system and restarting the logon process is simplicity itself.

If you are running the X Window System, press Ctrl+Alt+Backspace to shut down the graphics and get back to character-cell mode. Then type your logout. In a few seconds, the login: prompt appears, ready to have you (or someone else) log in.

If you want to turn the computer off, you must shut down the system. You do this by typing halt. If you want to reboot the system (to start another operating system, perhaps) you type reboot.
