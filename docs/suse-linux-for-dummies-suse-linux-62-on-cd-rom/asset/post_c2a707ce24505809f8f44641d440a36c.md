Suppose that your electricity went out and your system crashed. As the system reboots, you see messages similar to the following:

```
/dev/hda5 was not cleanly unmounted, check forced
/dev/hda5: Deleted inode 1456 has zero dtime. FIXED
/dev/hda5: Deleted inode 14577 has zero dtime. FIXED
/dev/hda5: Deleted inode 123753 has zero dtime. FIXED
Fix summary information? Yes
/dev/hda5: 46906/308400 files (1.6% non-contiguous),
      767485/1228801 blocks
```

And a little later, you see something like this for each one of your file systems:

```
fsck.ext2 -a /dev/hda7
/dev/hda7 was not cleanly unmounted, check forced
/dev/hda7: Deleted inode 1324 has zero dtime. FIXED
/dev/hda7: Deleted inode 15987 has zero dtime. FIXED
Fix summary information? Yes
/dev/hda7: 46906/356000 files (1.6% non-contiguous),
      765217/1283507 blocks
```

This is fsck with the -a option, which answers all the questions with yes. For the most part, it corrects any errors that occur when the power fails or when something breaks inside your computer, causing it to crash.

After fsck, it reports whether it modified any file systems.

## More Disk Storage

Sooner or later, you're likely to want to add more disk storage to your Linux system to hold more programs, to hold more data, or to enable more users in. Disk storage is usually added one or more disks at a time; each disk can have one or more disk partitions.

The disk partition is Linux's basic file storage unit. First you create the systems on the disk partitions, and then you combine the file systems to form a single directory tree. The directory tree structure can be on one disk or spread across many.

You can define disk partitions while adding a new disk or later. In most cases, Linux defines disk partitions during the original Linux installation. You may divide a disk into one, two, four, or more partitions, each of which may contain a file system or be used as a swap partition. Swap partitions allow very large programs or many small partitions to run even if they take up more memory than you have as RAM in your computer. The total of all your swap partitions and RAM is called virtual memory.

After you create a partition, you must create a file system. The file system occupies a single space on the disk that has a unique block file (device) name. This unique name accesses the file system regardless of whether the data is stored on all or part of a physical disk, or is an aggregation of multiple physical disks.

Linux developers are constantly supporting new file systems. The file system types are the major ones:

- ext, ext2, hpfs
- NFS: nfs
- Samba: SMB
- CD-ROM: iso9660
- DOS: mdsdos, umsdos, vfat
- Other: sysv, minix

If you want to add one of these types of file system, you have to make a new partition, which may mean adding a new disk drive. That's the subject of the next section.

## Adding a Disk Drive

The first step to increasing your disk space is to add a new disk drive. The following tasks are required to add a disk to your system (regardless of whether the disk is SCSI or IDE) and make it accessible to users:

- Attach the disk drive to your computer system.
- Provide a suitable device driver for the disk's controller in Linux. This may mean rebuilding the kernel of the Linux operating system, which is detailed in Chapter 14.
- Define at least one partition.
- Create the special files for the partition(s).
- Create a Linux file system(s) on any partition(s) to be used for user files.
- Enter the new file systems into /etc/fstab, the configuration file.
- Mount the file systems. (You may have to make a directory for your mount point.)

The following sections step you through the process of configuring a hard disk drive, a CD-ROM, and a floppy drive after they are physically installed.

## Configuring a drive

The business of adding a hard disk to your microcomputer is broken down into two steps:

- Physically adding the hard disk
- Logically making Linux aware of it

The first step is beyond the scope of this book because your drive may be either IDE or SCSI, and the setup of the physical disk is dependent on the rest of the hardware in the system. We suggest that you consult the hardware manual that may come with your system or have a reseller install your new disk. The Linux system is complicated by the fact that several operating systems—as DOS, Linux, and UNIX—may share the same disk.

![](img/96a9ce6a13d8d15ed05f867f41574278_255_0.png)

To complete the steps of installing a drive, you must know the disk's capacity, type, and partitions. For each disk, the Linux system reviews:

- Type
- Size
- Partitions

If you use the `fdisk` command, you will see something like this:

```
Device     Start         End   Sectors  Id  Type
/dev/sda1      2048  10485759    5046876 83 Linux
/dev/sda2  10485760   20971519   10485764 89 Linux
```

If you have a SCSI drive, the messages might look like this:

```
SCSI device sdb: sdb1
```

If you add a SCSI disk with a lower ID number than you already have, the new disk takes on nothing. Suppose that you have SCSI disk drives with hardware ID numbers of 0, 2, and 3. Linux gives these disks the names sda, sdb, and sdc, respectively. You make your partitions and, create your entries in /etc/fstab to show where the file systems are mounted. Now you get a new drive and set the hardware ID to 1. When you reboot, the new disk gets the sdb designation, and the disks with ID numbers of 2 and 3 are renamed to sdc and sdd, respectively. For this reason, for the very least, it's a good idea to add SCSI disk drives to your system starting with ID 0 and working up the number chain, with no gaps in the numbering.

In both IDE and SCSI disks, the letters and numbers correspond: a is for the first disk, b is for the second disk, and so on. If you use the `dmesg` command, you will see something like this:

```
cd /dev; makedev sd
```

This creates the block special files for SCSI disk.. Note that in both IDE and SCSI disks, the letters and numbers correspond: a is for the first disk, b is for the second disk, and so on.

The Linux distribution on SuSE Dummies CD-ROM features block special files for each of IDE disks (hda–hdb) with nine partitions (1–9). Linux also has special files for seven SCSI hard drives (sda–sdg), which can have eight partitions each (1–8). In addition, Linux has a special file for a SCSI CD-ROM (scd) with eight partitions (0–7).
