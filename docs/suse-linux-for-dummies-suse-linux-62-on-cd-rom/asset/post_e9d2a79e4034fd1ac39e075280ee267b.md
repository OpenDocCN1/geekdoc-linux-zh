## Files 101

A file is a collection of information with a distinct identification made up of a filename and a location (called a directory path) where the file is kept. Linux can store many files in the same directory — as long as the files have different names. Linux can also store files with the same name in different directories.

Confused? An example should help. Suppose you get a grand idea and decide to keep it in a file named idea in your directory called /wonderful. Now suppose you're having a very fertile day and come up with another idea. If you will be keeping your second file in the /wonderful directory, you would use a different name, such as /wonderful/idea. (We hope your ideas are more original than our filenames.) You can also, keep the file in another location — call it the /bizarre directory. If you decide to keep your second idea in /bizarre, you can call it, and the filename becomes bizarre/idea. Linux sees this file and the /wonderful/idea file as different files. Remember, though, that each directory may contain only one file with the same name.

Linux files can be as long as 256 characters. They can contain uppercase and lowercase letters (also known as mixed case), numbers, and special characters, such as the underscore (_), the dot (.), and the hyphen (-). Because filenames can be made of mixed-case names, we call them case sensitive. For example, the names FILENAME, filename, and FileName are unique filenames of different files; on some systems (such as Compaq's OpenVMS), however, they are the same filename.

Although filenames can technically contain wildcard characters, such as the asterisk (*) and the question mark (?), using them is not a good idea. Various command interpreters, or shells, will wildcards to match several filenames at one time. If your filenames contained wildcard characters, you would have trouble specifying only those files. We recommend that you create filenames that don't contain spaces or other characters that have meaning to shells.

## File types

Linux files can contain all sorts of information. Five categories of files that cover certain types of information will become the most familiar to you: user data files, system data files, directory files, special files, and executable files.

- User data files contain information you create. User data files, sometimes known as flat files, usually contain the simplest data, consisting of plain text and numbers. More complex user data files, such as graphics or spreadsheet files, must be interpreted and used by a special program. These files are most legible if you look at them with a text editor because the contents of these files are not always ASCII text. Changing these files generally affects only the user who owns them.

- System data files are used by the system to keep track of users on the system, logins, passwords, and so on. As system administrator, you may be required to view or edit these files. As a regular user, you will not be concerned with system data files except perhaps for those that you use as examples for your own startup files.

- Directory files hold the names of files — and other directories belong to them. These files and directories are called children. Directories in Linux (UNIX) are just another type of file. If you are in a directory, the directory above you is called the parent. Isn't that handy?

When you use the files with the ls -l command, lines containing directory begin with the d. For example:

```
maddog@shamet:~ > ls -ld plot
drxr-xr-x 2 maddog maddog 1024 Jul 11 1997 plot
maddog@shamet: ~
```

In this example, we use the d option of the ls to tell the command that we wanted to see the directory as if it were the only file in the directory. If we had not used the d option, we would have seen every file in the plot directory, along with the directory itself.

- Special files represent either hardware devices (such as a disk drive, a tape drive, or a keyboard) or some placeholder /dev is a directory that holds many special files. You can see this by typing the following:

```
ls -l /dev
```

- Executable files contain instructions (usually programs, or scripts) for your computer. A lot of these files are in /bin, /usr/bin, /sbin.

## Directories and subdirectories

A directory contained, or nested, in another directory is called a subdirectory. For example, the directory called /mother may contain a subdirectory called child. The relationship between the two is referred to as parent and child. The full name of the subdirectory is /mother/child, which would make a good place to keep a file about a family reunion. It could be /mother/child/reunion.

## The root directory

If you turned the tree so that the trunk was in the air and the branches were toward the ground, you would have an inverted tree — the Linux file system is normally drawn and represented (with the root at the top). Because we were talking about Mother Nature, you'd have a dead tree. Because this is computer technology, however, you have something that looks like an ever-growing, upside-down tree.

## What's in a name?

You name directories in the same way that you name files, following the same rules. Almost the only way that you can tell whether a is a filename or a directory name is the way that the slash (/) is used to show directories nested in other directories. For example, usr/local means that local is found in the usr directory. You know that usr is a directory because the trailing slash tells so, but you don't know whether local is a file or a directory.

![](img/96a9ce6a13d8d15ed05f867f41574278_161_0.png)

> If you issue the ls command with the -F option, directories are listed with a slash character at the end, as in local/, you would then know that local is a directory.

The simple way to tell the character indicates the root directory or separates directories, or directories and files, is to see whether anything appears before the slash character in the directory path specification. If nothing appears before the slash, you have the root directory. For example, you would know that /usr is a subdirectory or a file in the root directory because it has only a single slash character before it.
