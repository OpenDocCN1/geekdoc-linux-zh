bash creates an environment for commands to operate in. When a new command is executed, bash creates a clean copy of the environment, executes the command in it, and then throws away that environment, returning to the environment it started with.

Now look at a more complex example than just the one command ls -1:

```bash
cd /usr/lib
ls -1 * | more
```

In this case:

- 1. bash creates a new environment for the ls command to be executed and determines what should be standard input and standard output to the command. You can call this new environment child 1; the old environment is its parent.
- 2. bash creates another environment for the more command to be executed in, called child 2, and determines what should be standard input and standard output to the more command. Because the | symbol was used between the ls -1 * command and the more command, the standard output of the ls -1 * command is attached to the standard input of the more command. The standard output of more is attached to the standard output of the parent bash shell. The parent shell is the one into which you have been typing commands and information, and the standard output of that original bash shell is the screen.
- 3. bash expands * to match all the filenames in that particular directory, before.
- 4. Next, in the child 1 environment, bash searches the PATH variable looking for a command called ls. The same process occurs for the more command in child 2.
- 5. bash executes the ls command in the child 1 environment, passing to the command the -1 argument and all the filenames expanded, due to the use of the * character in the command.
- 6. more sees the output of ls -1 * as its input, and puts its standard output to the screen.
- 7. After the ls runs, bash returns to the parent environment, throwing away all the side effects that occurred in the child 1 environment.
- 8. more sees the end of its input from ls, puts the last of its data out to the screen, and terminates.
- 9. bash returns to its parent environment, throwing away all the changes that may have made to the child 2 environment.

## Chapter 10: Avoiding Shell Shock

The original bash shell is called the parent, and the two new environments bash created are called children, or child 1 and child 2.

Putting the standard output of one command into the standard input of the other, as was demonstrated with the command

```bash
ls -1 * | more
```

is called piping. The | symbol is called — you guessed it — the pipe symbol.

## History, herstory

One of the most useful features of bash is command-line editing, which is the capability to change parts of a command line without having to retype the entire command. Suppose that you typed the following:

```bash
username@hostname:~ > ls -1 * | more
```

Your mind was wondering because you meant to use the less command, not the more command, but you pressed Enter anyway.

You groan. You press Ctrl-C to halt the command. You would really like to reexecute the command, changing more to less, without having to type the entire command. Easy. Just do the following:

```bash
username@hostname:~ > more^less
```

This line resubmits the command to bash with the more changed to less, as follows:

```bash
ls -1 * | less
```

Output appears. If you have to stop the less command, press Q.

Note that the shell redisplays the first command with the change and then the command is reexecuted. How does the shell know about the first command? History. bash remembers all the commands you have typed (to a certain extent), and allows you to edit and submit them. Awesome.

We say “to a certain extent” because bash remembers only a certain number of commands, depending on a parameter in the environment. After bash holds that many previous commands, it throws away the oldest ones as you type in newer ones. Normally, this parameter is large (perhaps 1,000 commands), so bash will probably remember everything that you remember.

## Bang-bang

The fact that the shell remembers the command lines you have typed is useful for reexecution of commands at a later time. Simple reexecution commands are represented by exclamation points. In computerese, an exclamation point is called a *bang* and two exclamation points are called — you guessed it — bang-bang.

Here are two ways you can use the exclamation point:

- !! reexecutes the last command
- <partial command line> reexecutes the command line that started with <partial command line>

Here is an example. Type *cat* on the command line as follows. (Cat as <partial command line> mentioned in the preceding line.)

```bash
username@hostname: ~ $ cat
```

bash searches backwards through the previously executed commands in this session, looking for the first occurrence of a command line that started with the letters *cat*. When the program locates it, it is reexecuted.

A little timid about this? Perhaps your memory allows you to try it again. If you want to reexecute a command, you can use the !! command. If you want to reexecute a command that started with a certain string, you can type that string followed by !!.
