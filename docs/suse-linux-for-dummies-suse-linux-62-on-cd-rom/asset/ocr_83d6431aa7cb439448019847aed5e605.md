Note that a system with lots of idle time is not necessarily the best tuned; the CPU may be idle because programs waiting on I/O.

vmstat can output a one-line summary automatically while Linux runs. Enter a command in the following form (just substitute the time interval, in seconds, for x):

```
vmstat x
```

The number of programs you see are the programs inside the system, minus the activity of vmstat (although running vmstat does have some slight effect).

# Measuring performance with procinfo

procinfo is another program used to measure system performance. In many ways, it's nicer to use vmstat because it lists more information in one place and is formatted better (for human eyes). vmstat still has its uses, though, because its lack of formatting makes it easier to use inside shell scripts.

procinfo -a, shown in Figure 14-1, lists all information; procinfo lists a shortened version of that information. Note that the memory statistics at the top of Figure 14-1 are similar to those you get with vmstat.

Following is an explanation of all information in Figure 14-1:

+   The Bootup section is simply when the system was last booted. You might use this information as a security check because it may indicate that someone has rebooted your system without your knowledge.

+   Load average is the average number of programs running, followed by the average number of runnable processes and the total number of processes.

+   In the next group, values report the total amount of time that the system has spent in user, system, and idle modes (with percentages of time), along with a parameter showing how much time was spent with a niced (or lower priority) user-level program.

Running a command (especially in the background) at a lower priority is a nice thing to do, and makes the system more reactive to interactive jobs.
