# Virtual Work on Your Virtual Desk

You can see at this point that you can have lots and lots of windows on the screen. You might even lose a window behind other windows. Do you wish that your monitor was larger or that you have more than one monitor attached to your system, just so that you could open up more windows and do more things at one time? Or maybe you don't want to close down or minimize one application before going to another application.

Well, monitors are expensive, and a lot of systems can have only one graphics, but you are stuck with a single monitor. But you do not have to be stuck with one screen. X Window System (with the help of KDE) can give you virtual desktops.

A virtual desktop enables you to have a screen full of applications. By clicking a button or moving your cursor to a particular location, you can display an additional screen of different applications.

You may have noticed that on the bottom of your screen, in the middle of the panel, there are four buttons labeled One, two, three and four, as shown in Figure 11-8. These buttons represent the different virtual desktops that are available. The one labeled is the desktop that you are in right now.

# Scroll bars, menus, and buttons

|X Window System has gone through a lot of changes. The original goal was to make it informal, so that it could make windows, create patterns, draw lines, and so on, but was, not governed by policies about how scroll bars, menus, and buttons should look or work. Although everyone's scroll bars, menus, and buttons tended to look and feel almost the same, but not quite. It was hard to program every line of a menu and every character had to be coded by a skilled programmer, and programmers were continually reinventing the wheel (although the wheel had been around quite a long time before computers). Eventually, the X Window System community was fed up and developed a set of industry-standard libraries called Motif Open Software Foundation (OSF). These routines gave a common look and feel to software vendors of UNIX and workstation software. If you used OSF's sample code to implement a software product, you had to pay them royalties. But if you implemented yourself, looking only at the documentation of the standard, you did not owe them royalties. For a long time, other programming interfaces were used instead of Motif by the freely software community because they wanted to ship the software for all their code, and this wasn't possible with Motif from OSF. A group of programmers created a freely distributable version of Motif, which had the same programming interfaces and the same look and feel. They call this software lessif. Those programmers are humorous, aren't they?
