# I Grant You Permission

Files and directories in Linux have owners and are assigned a list of permissions. This system of ownership and permissions forms the basis for restricting and allowing access to files. Permissions can be used also to determine whether a file is executable as a command and how you can use the file or command. It is important to know because if you are the only one who uses your system, commands and databases are used by other users, including root (the superuser). Permissions on these files either allow or disallow you, the general user, from updating these files.

Using the ls -l option allows you to see the permissions of the files along with relevant information, such as who owns the file, what group of people have permission to access or modify the file, the size of the file or directory, the last time the file was modified, and the name of the file.

First, create a file with the touch command. The touch command is used for many things inside the UNIX and Linux communities, and one thing is for easily creating a little zero-length file:

```
maddog@shamet:~ > touch partytime
maddog@shamet:~ > ls -l partytime
-rw-r--r-- owner group 0 Oct 31 16:00 partytime
```

The -rw-r--r-- are the permissions for the partytime file; the owner is, and you are probably you could be someone or something else, depending on how your system is set up and administered.

You might be wondering how you can become the owner of a file. Well, you are automatically the owner of any file you create, which makes sense. As the owner, you can change the default permissions — and the ownership. If you change the file ownership, you lose ownership privileges.
