## I Don't Know How to Make X Window System Start at Boot Time

**Problem:** You don't have to log in to a command-line mode (such as DOS) and then type startx. Instead, you want to log in through X Window System.

**Solution:** We set up our machine so that it starts in character-cell mode and allows us to switch to X Window System. (Many times, we want to make a simple edit or look at something on the system, and logging in and out X Window System is simply faster.) If you like to see a graphical interface from the beginning, however, do the following. In the /etc/initab file, change this line:

```
id:2:initdefault:
```

to this:

```
id:3:initdefault:
```

Save your changes and reboot. X Window System starts at the end of the boot process, and you can then log in through the graphical interface. To go back to the old way of booting, change the line in the /etc/initab file back to the following:

```
id:2:initdefault:
```

and reboot the machine. Note that the same thing can also be accomplished through YaST:System Administration:Login configuration.

## I Never Seem to Have the Correct Time

**Solution:** Most UNIX systems keep their time using Universal Time (also known as Greenwich Mean Time, or GMT), but Microsoft systems keep their time as local time. When you set the time in either system, you set the CPU clock to that version of time. Then when you boot the system, it interprets what is in the CPU clock differently and reports a different time.

Linux enables you to store and think of the clock as either GMT or local time. You make this choice when you install the system. To change your choice, follow these steps:

- 1. **Log in as *root*.**
- 2. **Type yast.** Select System Administration from the YaST main menu and press Enter, then select Set Time Zone from the submenu and press Enter.
- 3. **Select the appropriate time zone.** You can see the entire list by scrolling down. When you find your time zone, press Enter.
- 4. **In the next dialog box, set your computer to GMT or local time as necessary.**

## Hardware Compatibility

The version of Linux on the SuSE Linux For Dummies CD-ROM supports a wide range of hardware but, like other distributions of Linux, it doesn't support all types of hardware.

We made every attempt to present correct material in this appendix. Some equipment listed, however, might not work with SuSE Linux. In addition, hardware is introduced all the time, and some of it might work with Linux but not here. The information in this appendix was taken from Linux Hardware Compatibility HOWTO by Patrick Reijnen and PCMCIA HOWTO by David Winds, as well as XFree8 organization.

After you have your system running, review some hardware HOWTOs to see any other hardware you might want to use in your system.

## Hardware Architectures

Linux runs on a variety of hardware architectures. These architectures are usually defined by the model name of the CPU, such as Intel, Alpha (Compaq), and SPARC (Sun). Linux has been ported to run on handheld devices and mainframes. Just recently, there was an article about a company that created a telephone that runs Linux! This book and its CD-ROM cover only Intel architecture, which includes AMD and Cyrix CPUs for Pentium.

In addition to the architecture of the CPU, you have to consider the bus. A bus is made up of electrical paths, wires, and sockets that transmit impulses to and from the CPU. ISA, VLB, and PCI buses have been around a long time and are all supported in Linux. Recently, the Microchannel bus has received support in the kernel, so it may not work on your system. Most modern systems are PCI-based, with one or two ISA slots for compatibility.

The combination of the CPU architecture and the bus could loosely be the motherboard (often pronounced BIOS). If Linux does not work on your system, and you suspect the motherboard is the problem, first check with the manufacturer to see whether they have any newer BIOS.

## Laptops

Laptops and Linux are problematic for a few reasons. First, except for the newest laptops, disks are tiny for use with Linux (which needs at least 80MB of space). Second, most older laptops have 4 to 8MB of memory, with really expensive upgrade to more. Third, to make laptops small and lightweight, only the newest electronic devices are used, often not expected by Linux. Fourth, many early notebooks use graphics chips from vendors who didn't give out specifications, making it difficult for XFree8 to provide video code. Finally, most early notebooks don't have a lot of peripherals inside, forcing you to use a PCMCIA card to hook up to a network or SCSI CD-ROM to get code onto the machine's hard disk.

Nevertheless, as prices dropped and more manufacturers cooperated with the Linux community, it became easier to install Linux on a notebook. Ideally, your notebook should have more than 32MB of main memory, more than 700MB of free disk space, and a built-in CD-ROM and floppy can both be installed and working at the same time.

## SMP Systems

The kernel on the SuSE Linux For Dummies CD-ROM does not support symmetric multiprocessors (SMPs) by default. If you are interested in taking advantage of your SMP machine, you will have to recompile your kernel with support for SMP.

## Memory

All memory typically found in PC computer systems works with Linux. When your system has large amounts of main memory, you must add the following to the /etc/lilo.conf file:

```
append="mem=<number>"
```

## Video

In character mode, Linux works with all video cards. Then you'll be able to get your system up and running, at a minimum. Likewise, most cards in VGA or SVGA mode, you'll be able to have X Window System running, although it will be a little slow and coarse-grained.

As a general rule, both the earliest and latest models of video cards are not supported. Early video cards were obsolete before Linux was introduced, and XFree86 (the people who provide most of the support for the video cards) never had time to retrofit support. The very latest cards are not supported right away because it takes time and effort to get the code ported to the video card. With help from vendors, lead times are becoming shorter.
