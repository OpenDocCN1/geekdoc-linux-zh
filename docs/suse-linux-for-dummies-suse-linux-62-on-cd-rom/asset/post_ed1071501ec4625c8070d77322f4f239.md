+   - dev
Treat special files in this file system as special files.

+   - nodev
Treat special files in this file system as filenames.

+   - exec
Permit execution of binary files from this file system.

+   - noexec
Prevent the execution of binary files from this file system. This is useful for file systems that have all data to prevent programs being introduced by system crackers or to prevent people from trying to execute programs that were meant to run on a different system, such as MS-DOS.

+   - nouser

+   - async
Write data to the file system asynchronously. The system is faster but you can lose data if a system failure occurs.

+   - suid
Write data to the file system synchronously.

The id access mode enables an executable program with the suid (setgid) permission bit to take on the personality and permissions of the owner (or the group) of the executable program. This can be a security hole; specifying the nosuid option prevents files in this file system from having the set user id (or setgid) access take effect.

| nosuid | Do not permit the suid access mode. |
| noauto | Do not automatically mount this file system when the -a option is used with the mount command. |
| usrquota | User quotas may be put in effect. |
| grquota | Group quotas may be put in effect. |
| defaults | A combination of rw, suid, dev, exec, auto, nouser, and async. |

+   - dump-freq is the frequency with which the file system may be backed up by the dump utility (not all systems use this).
- pass-number is a decimal number specifying the order in which fsck file system utility, checks the file systems. A pass-number of 1 indicates that this file system should be checked first. This is the pass-number assigned to root. All other file systems should have a higher number. Two systems in parallel to speed up, but file systems on the same drive can have different pass-numbers. For swap devices, the pass-number should be 0 (zero), which disables fsck checking.

Following are examples of typical /etc/fstab entries:

```
/dev/hdb1   ext2 defaults 1 1
/dev/hdb3  none swap    sw      0 0
/dev/hda1   /w95 mdsdos noauto  0 0
```

The first line enables mounting of the first partition of the second IDE disk as the root system. It is a Linux file system and uses the rw, suid, dev, exec, auto, nouser, and async options. The first entry in /etc/fstab file indicates that the root file system should be dumped (backed up) once a week (using the man dump command for details). Finally, the first entry of the /etc/fstab file indicates that the root file system should be the first file system to have fsck performed on after booting the system.

The second line shows that the third partition of the second IDE disk is a swap partition and has the format of a swap file. It should never be backed, nor should you perform the fsck command on the swap partition.

The third line of the /etc/fstab file points to the first partition of the first disk, which is a file system to be mounted on the /w95 directory. This file system properly holds Microsoft Windows 95 files, and you can read and write to this file system. It will not be automatically mounted with the -a option of mount. You should never use dump to back it up, nor should you do a file system check on it.

# Chapter 13: File System Management

After you set up the /etc/fstab configuration file, file systems can be mounted automatically at boot time. In addition after the /etc/fstab file is set up, the mount and ummount commands require only mount-point and block-special-file as their argument.

Normally, most of the /etc/fstab file is set up during installation, so you only have to update it over time as you add new disks or partitions.

In SuSE Linux, you can use YaST to update the /etc/fstab file, so that you don't have to edit the file with a text editor (although you still have this option). YaST is one of the features of SuSE Linux and is on the SuSE Linux for Dummies CD-ROM; you can update the /etc/fstab file as follows:

1. Log in as root.
2. Use YaST.
3. Click the YaST icon.
4. Select the Adjustments menu.
5. Select the Partitions/Filesystems option.
6. In the Target Partitions/Filesystems dialog box:
7. Select the partition you want to configure.
8. Click the Edit button.
9. If this is a new partition, you might also need to format it.
10. When you are finished with configuring mount points, press the Esc key to get back to the main YaST menu and select Exit.
