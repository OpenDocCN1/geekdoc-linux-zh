# Appendix B: The Linux man Pages 315

If you use cd to change to the /usr/man/man1 directory and issue the ls command, you see files such as cat.1 and grep.1. Oddly, you don't find a file called cd.1, because the cd command is built into the different shells, and its documentation is covered in the bash.1 file or the csh.1 file.

If you are using bash as a shell, you can get information about the rest of the built-ins as follows:

```
[maddog@localhost maddog] > help
```

The intro briefly describes the section of the manual and whether you need to know anything special about that section. Printing an intro page is simple. For example:

```
[maddog@localhost maddog] > man 2 intro
```

or

```
[maddog@localhost maddog] > man 3 intro
```

# Topics in the man Pages

Each man page is made up of several sections. In this part, we list the sections we think are most important in your quest to figure out how to read man pages. Note that some man pages don't contain all these sections, and other pages contain more sections than those outlined here.

# Name

The man is usually the command name, followed by a hyphen, followed by a one-line description of the command's functionality. This is usually what you see if you execute a man -k or an apropos command. Either of these commands, when followed by a word, lists the name field from every manual page that contains that word. Type the following:

```
[maddog@localhost maddog] > apropos cat
```

Your apropos command may produce few or no commands. Perhaps no one has generated the database map of command names and descriptions. To do this, either you or your systems administrator has to become superuser or root and then execute the following command line:

```
/usr/sbin/makethis
```
