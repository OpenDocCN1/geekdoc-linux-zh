The combination of the CPU architecture and the bus structure could loosely be the motherboard (often pronounced "muthaboard\). If Linux does not work on your system, and you suspect that the motherboard is the problem, first check with the manufacturer of the motherboard to see whether they have any newer BIOS, which is the code that tells the CPU of the bus structure and devices.

# Laptops

Laptops and Linux are problematic for a few reasons. First, except for the newest laptops, the disks are tiny for use with a Linux system (which needs at least 80MB of disk space for character-cell support and 200MB of main memory for X Window System). Second, most older laptops have 4 to 8MB of main memory, with really expensive upgrade paths to more memory (if you can find it). Third, to make laptops small and lightweight, only the newest electronic devices are used, and often in ways not expected by Linux. Fourth, many early notebooks use graphics chips from vendors who didn't give out the chips' programming specifications, making it difficult for XFree8 to provide video code that works. Finally, most early notebooks don't have a lot of peripherals inside, forcing you to use a PCMCIA card to hook up to a network or to a SCSI CD-ROM to get code from a CD-ROM and onto the machine's hard disk.

Nevertheless, as prices dropped and more manufacturers cooperated with the Linux community, it became easier to install Linux on a notebook. Ideally, your notebook should have more than 32MB of main memory, more than 700MB of free disk space, and a built-in CD-ROM and floppy that can both be installed and working at the same time.

# SMP Systems

The kernel on the SuSE Linux For Dummies CD-ROM does not support symmetric multiprocessors (SMPs) by default. If you are interested in taking advantage of your SMP machine, you will have to recompile your kernel with support for SMP.

# Memory

All memory typically found in PC computer systems works with Linux. When your system has large amounts of main memory, however, you must add the following to the /etc/lilo.conf file:

```
append="mem=<number of Mb>"
```
