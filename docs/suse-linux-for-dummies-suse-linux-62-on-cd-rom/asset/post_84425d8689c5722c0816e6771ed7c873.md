
# Chapter 10: Avoiding Shell Shock

## Your Wish Is My Command

We've been showing you interactive shell functions, a fancy term that simply means that you type something and the computer executes it immediately. After a while, you may notice that you're typing a certain series of commands over and over. Wouldn't it be nice to put them in a file and execute them all at once? Well, you can.

For the rest of this section, you work on creating shell scripts, which contain a series of commands that are executed every time you type the name of the script as command. First you create a simple shell script, and later you create a more complex one.

Suppose that you want to generate a report from time to time showing who owns the login accounts. You can simply print the /etc/passwd file, but that has a lot more information in it than you need. Plus, you're an organized type of person and want to format the report more nicely than the passwd file.

First, look at the following entry in the passwd file:

```
maddog:eyrtwuir:500:SuSE Linux
...,/home/maddog:/bin/bash own```

Each grouping of characters between the columns is called a field. For the report, you want only the first and fifth fields. The cut command is what you want to go. The man page for the cut command shows that the command to the first and fifth fields is follows:

```
cut -f 1,5 -d: /etc/passwd
```

The man pages are terse but complete descriptions of commands. To get to the man page for the cut command, type man cut on the command line.

You use the -f option for the cut command to list the fields you want printed, in this case the first and fifth fields. You use the -d option to specify the delimiter for the field, which in this case is a colon. The preceding gives lines of output formatted like this:

```
maddog:SuSE Linux User,...
```

Maybe you'd prefer to replace the colon with a hyphen, adding a space on each side to make the report easier to read. The stream editor sed is your ticket to formatting happiness. You can send the output of cut directly to sed with the following command line:

```
cut -f 1,5 -d: /etc/passwd | sed -e 's/:/ /g'
```

![](img/96a9ce6a13d8d15ed05f867f41574278_202_0.png)

The pipe symbol | takes the output of the cut command and feeds it to the sed command. Look at the part of the command line to the right of the pipe symbol and you can see that the -e option of the sed command tells the command to use the next string of characters (in this case, what is between the two apostrophes, or single quotation marks) as a command for the sed stream editor. (The command here is basically the same as the s command in the ed and ex editors, which you can read about Chapter 9). The command finds strings of characters between the first and second slash marks and replaces them with the characters between the second and third marks.

Note the quotation marks around '/s/:/ /'. This makes the shell think of the entire string of characters as one thing, and presents the string to the sed editor as the thing that sed has to work with. Without the single quotation marks, the shell should include the blanks in the string that three different things are in that string of characters: s, /, -, and /. In statements, unquoted blank space (called white space) is considered a separator.

![](img/96a9ce6a13d8d15ed05f867f41574278_203_0.png)

Continuing with your report, you want some type of header that states the subject of the report and the date. You can use the echo command (for the header) and the date command (for the date):

```
echo Report of login names and users on the Linux system
date
echo ============================
cut -f 1,5 -d: /etc/passwd | sed -e 's/:/ - /g'
```

These four lines are not difficult to type, but you would have to remember them and retype each time you run the report. If you like to save time whenever we can and our memory cells seem to be dropping like... ah, we forget. For those reasons, we want to use our favorite text editor to type the lines in a file.

![](img/96a9ce6a13d8d15ed05f867f41574278_203_1.png)

Our favorite editor is vi. If you want to use another editor, we won't stop you. But be sure to name your file quagmire so that the rest of the example will work.

In the following, we're using vi to edit a file named quagmire, entering the commands before into that file:

```
maddog@localhost:~ > vi quagmire
a
echo Report of login names and users on the Linux system
date
echo ============================
cut -f 1,5 -d: /etc/passwd | sed -e 's/:/ - /g'
<ESC>
:wq
```

The last line, :wq, writes the file to the disk and quits the editor.

Now you must tell Linux that it's okay to execute the file. To do this, you have to change the permissions to execute:

```
chmod ugo+x quagmire
```

For more permissions, check out Chapter 8. When you created the file, it was probably created with the permissions of the owner (u), the group (g), and the rest of the world (o) as at least read (r), if not write (rw). Just because a shell can be read does not mean it can be executed. You must explicitly tell the system that it's okay to execute.

Now, type the following:

```
./quagmire
```

and you see your report before your eyes!

```
./quagmire | more
```

and you see that quagmire program acts like any other. It allows piping to other programs (if you have one available):

```
./quagmire | more
```

But notice that for your program, you have to type ./ in front of the filename. If you don't include ./ you get the following message:

```
bash: quagmire: command not found
```

This is because your current directory, where quagmire script resides, is not in the list of directories. If you type the following:

```bash
echo $PATH
```

you probably see a line that looks like this:

```
/usr/local/bin:/bin:/usr/bin:/home/maddog/bin
```

![](img/96a9ce6a13d8d15ed05f867f41574278_204_0.png)

Each path of a directory is separated by a colon, so the directories searched for valid commands are (in order): /usr/local/bin, /bin, /usr/bin, and so forth. The one that is most interesting to you is probably the end of the line. It should be something like home/<username>/bin. Likewise, you should have a bin directory in your login directory. If you don't, make one as follows:

```
maddog@localhost:~ ~ mkdir ~/bin
```

Then move your quagmire file to the bin directory in your login account, type:

```
maddog@localhost:~ ~ mv quagmire ~/bin/
```

Now you can execute the quagmire program like any other program:

```
maddog@localhost:~ ~ ~/bin/quagmire
Report of login names and users on the Linux system
Sun Jul 6 08:57:01 1999
=============================
root - root
bin - bin
daemon - daemon
adm - adm
ip - ip
sync - sync

mail - mail
news - news
uucp - uucp

gopher - gopher
ftp - ftp
nbody - nobody
maddog - maddog
```

You just wrote a program. It's a simple program, and as far as Linux is concerned, it's as much a program as any other. What you just wrote is called a shell program, or a shell script. In many cases, shells are more efficient than writing hundreds of lines in C or Fortran. Shells are fairly easy to write, fairly easy to change, and even experienced C and Fortran programmers use them every day instead of writing complex programs using other languages. Systems administrators couldn't survive without scripting languages as shell.

## From the Simple to the Sublime

You have written a program, but it always works on the same file, which is hard-coded into the script. For the rest of this chapter, we show you how to create more flexible shell scripts, ones that can generate different filenames as needed and can automatically adapt to being run on different dates.

Suppose that you want to keep monthly copies of the passwd file and see the differences between them. First, write a program that saves a copy of the passwd file and stores it in a directory:

1. Use the cat command to create a script in your ~/bin directory called genreport.
The genreport script is simple. It copies the file /etc/passwd to standard output using the cat command; the redirection symbol puts it into a file.

2. For a filename that the script will generate when it is executed, start with the name passwd, but attach the year and the month to it:
For example, the passwd file for July 1998 would be passwd199807, and the one for August 1998 would be passwd199808.

To create these files, execute the date command inside the shell script and use it to append to the word passwd. If you use the backward single quotation mark (called accent grave) around the date, it generates the numbers 199807 to be appended to the string of characters passwd, if they are July 1998. The accent grave tells Linux to "execute what is between the accent grave symbols as a Linux command, and use the result of that as a string in the larger command." Therefore, the date command generates the string 199807, which is appended to the name passwd to create passwd199807.

If you're searching your keyboard for that accent grave character, you may find it under the tilde character.

3. When you make this file in your bin directory, don't forget to change its permissions to make it executable.

This is the program that we generated and an example of it running:

```
maddog@localhost:~/bin ~ cat ~/bin/genreport
cat /etc/passwd > passwd+%%Y%m
<CTRL+D>
maddog@localhost:~/bin ~ chmod u+x ~/bin/genreport
maddog@localhost:~/ ~ cd
maddog@localhost:~/ ~ mkdir reports ; cd reports;
maddog@localhost:~/reports > genreport
maddog@localhost:~/reports > ls
passwd199907
maddog@localhost:~/reports >
```
