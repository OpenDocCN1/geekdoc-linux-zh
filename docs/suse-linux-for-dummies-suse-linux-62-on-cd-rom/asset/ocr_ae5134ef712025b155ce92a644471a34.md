# Saving yourself

When you work with the text of a file, the text is kept in a buffer (a place in memory), and no changes are made to the file until you save and exit. My advice is to save your text early and often. Although Linux systems are stable, it would be just your luck to have a power failure after you've spent five hours typing a large, unsaved text file.

Saving your file is particularly useful when you are going to execute some large, complex command that will transform your text file dramatically. Most editors have an undo command that backs out the last one or two (or) commands and text you have given the text editor. Writing the buffer to disk, however, is foolproof.

When you make a mistake and you want the file back the it was when you did the last, must quit — rather than exit — the editor. Quitting usually means leaving the editor without doing one last save of the file. Exiting usually means saving changes that exist in the buffer and leaving the editor. Most editors have both functions.

Some editors have autosave, which is a nice feature for people who are forgot about saving their files. Autosave counts how many commands or changes you make to a file, and then automatically saves the buffer to the file after a certain number of changes. We, however, don't like autosave. For one, the autosave feature causes some editors to freeze during autosaving, and we find this annoying. Two, autosave can happen at the worst time. For example, if you execute a complex command that erases your buffer and then autosave kicks in, the undo command may be unable to undo that command.

If you use autosave, we recommend that you consciously save a manu-ally (which resets the autosave counter) right before you do a complex command. Then you can recover the file if necessary by quitting the editor without saving the buffer, getting back to the command prompt, and restarting the editor on the file again.

# Here's vi

The vi editor on your Linux system is really the vim editor, but you can invoke it by using vi because a symbolic link exists between vi and vim.

Like the ed editor, the vi editor has two modes of operation and the same type of single-letter commands. To start vi, you type vi at the command line. The screen clears displays tild (~). You are looking at an empty, unnamed buffer in memory, into which you can enter text until you save the text to a named file.
