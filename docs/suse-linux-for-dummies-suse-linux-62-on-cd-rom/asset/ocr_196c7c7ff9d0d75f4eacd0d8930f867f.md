Strictly speaking, the file has still not really moved. The data bits are still on the same part of the disk where they were originally. The file specification (the directory path plus the filename) that you use to talk about the file is different, so it appears to have moved.

In versions of UNIX, you were not allowed to use mv to move a file from one partition to another; you could only copy it using the cp(1) command. Linux allows you to use the mv command to move a file anywhere. Normally, mv renames the data in place and changes the file's name and the directory where the name is placed. But when the file is moved across partitions (for example, from /usr to /home in a Linux systems), the data is copied to the new disk partition, the new name is put in place in that partition's directory structure, and the name and file's data are removed from the old disk partition.

Copying a file moves some data. The syntax is

```
cp <source> <destination>
```

Look familiar? It is the same syntax you use for the move command.

Now, make a copy of the jewels file. Because you can't have two files of the same name in the same directory, you have to think of a new name, such as jewels2. (Hey, we're writing this early in the morning. How creative can we be?)

```
cp jewels2
```

If you want a copy of a file but in a different directory, you can use the same filename. For example, suppose that you want to duplicate a file moody to the ../work directory. You can keep the name moody because its full path-name work in it instead of santa_cruz:

```
cp moody .../work
```
