# Appendix B

# The Linux man Pages

UNIX and Linux systems are largely made up of small, terse commands executed on the command line. Typically, each command is associated with at least one man page. The Linux man pages have nothing to do with gender: The man stands for manual.

At one time, the man pages were the only documentation that came with UNIX systems. Somewhere I still have the thin book I received as a first-time UNIX user and systems administrator. All it contained were the man pages, and that I was supposed to install a UNIX system. Many years later, I still look at the man pages first to get a quick idea of what a command should do and what arguments to use on the command line or what values to set.

This appendix shows you how to use the man(1) command, how to read and understand the man pages, and how to locate other man pages that may help you understand the Linux command you're investigating.

# Using the man Command

To get started using the man pages, follow these steps:

1. With Linux up and running, log in as a user (either a general user or root).
2. Type the man command. The system asks what manual page want. The syntax of the man command (like many other commands) requires at least one argument.
3. Supply an argument by typing man. The first man is the command name and the second man tells you you want information on the manual itself. The system may tell you wait a moment it formats the page to your screen, and then displays the reference page for the command.
4. If a colon (:) appears at the bottom of the screen, press the spacebar to see the next page, or use the arrow keys to maneuver around.
5. To quit the program, press q.

# Sections in the man Pages

The man pages are usually found in several directories throughout the system: Each directory is broken up into subdirectories representing sections of the manual, as follows:

- man1: User commands
- man2: System calls
- man3: Library functions
- man4: Special files
- man5: Games
- man7: Miscellaneous
- man8: System administration nroff, troff, and groff macros

Note that most directories have more than section. Two sections may have an entry for a command of the same name. For example, section 1 has open command and section 2 has open system call. To make sure you're reading about the right one, you can specify the command on the man line. For example:

- man 2 open

Most sections of the man database (for that is basically what is) has two parts:

- An intro page represented by a file called intro.n, where n corresponds to section number.
- All commands, calls, library names, and filenames, represented by files with the name command.n, where n is section number.

# Topics in the man Pages

Each man page is made up of several sections. In this part, we list the sections we think are most important in your quest to figure out how to read man pages. Note that some man pages don't contain all these sections, and other pages contain more sections than those outlined here.

# Name

The man is usually the command name, followed by a hyphen, followed by a one-line description of the command's functionality. This is usually what you see if you execute a man -k or an apropos command. Either of these commands, when followed by a word, lists the name from every manual page that contains that word. Type the following: apropos cat

Your apropos command may produce few or no commands. Perhaps no one has generated the database map of command names and descriptions. To do this, either you or your systems administrator has to become superuser or root and then execute the following command line: /usr/sbin/makman

# Synopsis

The synopsis is a shorthand way to describe what the command is looking for for example: lpq [-a] [-Pprinter] [job ...] [user ...] is the synopsis for the lpq command (whose job is to show what is in the print queue). The command (lpq) is first, followed by a series of bracketed arguments. If an argument is enclosed in square brackets, the argument is optional. That means the lpq command needs no arguments. If you type lpq you will probably get a no entries message, which means nothing is waiting to be printed, or a list of people's jobs is waiting to be printed on the default printer.

If you want to see what is waiting to be printed on another printer, you use the option -P followed by the name of the printer. For example: -Pzklpsa

Now if you type that, you probably get a message like lpq: zklpsa: unknown printer, showing that your system does not know about a printer named zklpsa. If you get something else, let me know, because that may explain why my print jobs are going ..., no, just kidding.

In any case, the purpose of this section is not to show all the functionality of the lpq command. Rather, the synopsis section shows in a shorthand how the command should be used including which arguments are optional.

Another confusing thing you see is the ... notation. Looking back at the lpq command synopsis, you see it twice, once following the job # argument and once following the user argument. This notation tells you that you can list as many job numbers on the line as you want, separated by spaces, and as many user names as you want, separated by spaces.

Sometimes you see a command that begins with one hyphen (-) or two (--). These are technically known as options, whereas job # and user of the lpq command are arguments. Options tell the command how to manipulate arguments. You might see an option line that looks like this: cat [-benstuvAET] or even ls [-abcdefghijklmnpqrstuxABCGLNQRSUX1]
