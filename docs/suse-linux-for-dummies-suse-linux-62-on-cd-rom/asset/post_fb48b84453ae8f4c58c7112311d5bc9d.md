Linux comes with one but two text editors: ed and vi. The ed is a line-oriented text editor. It was one of the first editors for UNIX systems and traditionally is included with every UNIX and Linux system. It is also a small editor that can be included on small distributions of UNIX and Linux. You can always count on ed to be. The second editor included with Linux is vi. This full-screen editor also supports the command set of a line-oriented editor named ex. A third text editor for Linux is emacs; some people prefer this for most of their work.

![](img/96a9ce6a13d8d15ed05f867f41574278_181_0.png)

In Linux, ed and vi are emulated by another editor named vim. The commands for vi work just fine with vim. In addition, vim has more capability than vi. Therefore, a separate program is not supplied with Linux systems. When you type vi, you are really using vim, but this is invisible to you.

Although all three editors have different interfaces and capabilities, they all support the following standard features: reading and writing files, searching, inserting and deleting, and copying and moving text.

![](img/96a9ce6a13d8d15ed05f867f41574278_181_1.png)

We can't detail all the options editors offer. Before you get involved in some monstrous editing project, read the manual page for the editor you have. You may be surprised to find some handy shortcuts. Assuming you installed the manual pages on your Linux system, you can find the manual page on the editor by typing the following at a command prompt:

```
man editorname
```

where editorname is ed, vi, vim, or emacs.

## Two for one

Most editors use control keys or meta keys, which are indicated by Ctrl+ or Meta+, respectively in this book and sometimes shortened to C+ and M+. The Ctrl key is usually marked on your keyboard, but the Meta key may be hiding under an alias, such as the Alt key.

When you see Ctrl-Z, for example, press and hold down the Ctrl key while pressing the Z key. (Don't press Ctrl+Shift-Z). Likewise, Meta-H means to hold down the Meta key (in most cases, Alt) and press the H key. This is really much easier than rubbing your thumb and patting your head at the same time.

![](img/96a9ce6a13d8d15ed05f867f41574278_181_2.png)

Most UNIX books show meta keys without the + sign. For example, Ctrl+Z in this book (and Microsoft books) becomes Ctrl, ctl-z, or ^Z. Another frequent occurrence in UNIX texts is ^d as the symbol for ending a file, which is the same as pressing the Ctrl key and the D key at the same time.

## Saving yourself

When you work with the text of a file, the text is kept in a buffer (a place in memory), and no changes are made to the file until you save and exit. My advice is to save your text early and often. Although Linux systems are stable, it would be just luck to have a power failure after you've spent hours typing a large, unsaved text file.

Writing the buffer to disk, however, is foolproof. When you make a mistake and want the file back to how it was, most editors have an undo command that backs out the last one or two commands. Quitting means leaving the editor without saving. Exiting usually means saving changes that exist in the buffer and leaving the editor.

Some editors have autosave, which is a nice feature for people who forget about saving their files. Autosave counts how many commands or changes you make to a file, and then automatically saves the buffer to the file after a certain number of changes. However, I find this feature annoying because some editors freeze during autosaving, and the undo command may be unable to undo that command. If you use autosave, I recommend that you manually save (which resets the autosave counter) before you do a complex command. Then you can recover the file if necessary by quitting the editor, getting back to the command prompt, and restarting the editor.

The vi editor on your Linux system is really the vim editor, but you can invoke it because a symbolic link exists between vi and vim. Like the ed editor, the vi editor has modes of operation and the same type of single-letter commands. To start vi, you type vi at the command line. The screen clears (~). You are looking at an empty, unnamed buffer into which you can enter text until you save to a named file.

You can start the vi editor in a number of ways with different options, but the most common way is to start vi with only a filename as the argument, like this:

```
vi filename.txt
```

filename.txt is the name of either an existing file you want to edit or a new file you want to create. The vi editor has modes of operation:

- Visual command mode
- Colon command mode
- Text mode

When you invoke vi with a filename, the editor appears. At the bottom-left corner is the following line:

```
"filename" [New File]
```

This status line tells you what the editor is doing. In this case, the editor has opened a buffer and the save and quit option saves the contents of the buffer to the filename. If you indeed invoke vi with the following command:

```
vi filename.txt
```

the bottom-left corner would display the following line:

```
"filename.txt" [New File]
```

When you first invoke vi, you are in visual command mode, which is the default. You can use special commands to either locate text or transition to more complex commands:

- Forward search
- Backward search
- Continue the search in whichever you are currently going
- ex command (is the line editor included in vi)

In command mode, the characters you type are used as commands, not as input into the file. To use commands, type the character on the command line. For the first two search commands (/ and ?, the cursor moves to the bottom of the screen, where you then type the string you are searching for. When you press Enter, the search begins. If you want to search for an additional string, you can just press N to repeat the search.

When you type the : command, the cursor moves to the bottom of the screen and waits for you to enter a command or a command string. You must press the Enter key to execute the command.

Given that characters you type are interpreted as commands in command mode, how do you get from command mode to text mode? Simple. Enter a command to do something in text mode and vi will take you there. Here are some commands that can be used to illustrate how to switch from command mode to text mode:

- Insert text before the cursor
- Insert text after the cursor
- Insert text at the beginning of the current line
- Insert text at the end of the current line

As soon as you type any of these commands, you are placed in text input mode. Do not press Enter after entering the command. Any text you type after invoking the command is placed in a buffer and echoed to the screen.

You may be asking yourself (because the directions are skimpy or there is no one to ask), "How do I get out of text mode and back to command mode?" Again the answer is simple. If you want out, just press the Escape (Esc) key and you're immediately whisked back to command mode. That's pretty easy, isn't it?

If you don't know whether you are in command mode, just press Esc a few times.
