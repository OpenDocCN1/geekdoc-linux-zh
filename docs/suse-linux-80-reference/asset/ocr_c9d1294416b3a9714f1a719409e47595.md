+   - A printer forwarding queue is required wherever it says “forward” in the above examples. The data is forwarded without filtering.
+   - Where it says “prefilter” or “filter”, a print queue is required to filter the data. If filtering takes place on the client, this filter queue is a “prefilter” for the “printer forwarding queue” of the print server. If filtering takes place on the print server, the filter queue is one of the regular queues configured on the print server, such as `lp`.

# Prerequisites

The printer must be supported by SuSE Linux, since the prefilter produces printer-specific data in the same manner as for a locally connected printer (normally via Ghostscript). See Section *Connecting Printers Locally* on page 194 for more information on this.

There must be a working TCP/IP connection to the network printer. The name service especially needs to be set up properly.

# Configuration

Use YaST2 to configure the required prefilter and forwarding queues and test all queues defined. The division into prefilter and forwarding queues is the classical configuration of printer spoolers that use lpd protocol (according to RFC 1179).

With print server units or network printers, this may not work (see Section *In Case of Problems* on the following page. The LPRng spooler allows for other methods of accessing network printers or print server units. These methods are already, in part, supported by lprsetup. See `lprsetup --help` and the man page for `lprfilter` (man `lprfilter`). Detailed information for the LPRng spooler is outlined in the *LPRng Howto* in file: `/usr/share/doc/packages/lprng/LPRng-HOWTO.html`. The lpd protocol is also described there. file: `/usr/share/doc/packages/lprng/LPRng-HOWTO.html#NETWORKPRINTER` file: `/usr/share/doc/packages/lprng/LPRng-HOWTO.html#NETWORKPRINTER`.
