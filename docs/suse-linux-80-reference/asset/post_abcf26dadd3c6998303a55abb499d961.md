## Recording and Playing WAV Files

The ALSA sound package also offers arecord and aplay, which are also worth mentioning. They are included in the ALSA package and provide a simple and flexible interface for the PCM devices.

Audio data can be recorded and played in WAV format with arecord and aplay. The command `arecord -d 10 mysong.wav` records a ten-second WAV file. View a complete list of arecord and aplay options with the `-h` option. Keep the correct mixer setting in mind when recording. The controls for these settings in alsamixer are ‘Capture’ and, depending on the recording source, ‘Line’ and ‘MIC’. The recording source must also be properly specified. The signal source is digitized by an analog to digital converter when recording. For 16-bit converters, the maximum amplitude is 65535. Any signal higher than that will be distorted, because it will be converted to a signal with an amplitude of 65535.

### Printing Basics and Requirements

Printing basics and printer configuration with YaST2 are described in *Basics in the Chapter YaST2, Printer*. Here is a short summary of processes in the print system.

### Process of a Print Job

- 1. The user or an application generates a print job with the `lpr` command.
- 2. The data to print is written to the print queue, where the printer spooler subsequently relays it to the print filter.
- 3. The print filter can also define the type of the data to print and, if necessary, uses Ghostscript to convert this data to the language recognized by the given printer. Finally, the filter sends the printer-specific data to the printer.
- 4. After the print job has been sent to the printer in its entirety, the printer spooler deletes the print job from the queue.

### Examples of Default Printer Languages

- **ASCII text** — Normally, any printer is at least capable of outputting ASCII text.
- **PostScript** — PostScript is the default Unix and Linux language used to generate output, which can then be printed by PostScript printers directly.
- **PCL5e or PCL6** — These printer languages are common for laser printers.
- **PCL3** — This printer language is understood by most HP DeskJet printers and compatible models.
- **ESC/P, ESC/P2 or ESC/P dot matrix** — These printer languages are understood by nearly all Epson printers and compatible devices.

### GDI Printers

Printers that do not understand any of the default printer languages listed above, but can only be accessed via a proprietary protocol, are referred to as “GDI printers”. Such printers usually cannot be used in Linux. However, there are some GDI printers that also understand a default printer language on the hardware level. These printers need to be configured to use that language. Consult your printer manual for the necessary information.

### Defining a Suitable Printer Driver

In the lists mentioned in Section *Hardware and Software Requirements* on the page before, Ghostscript drivers for specific printer models are provided. If your supplier cannot give any Linux-specific information on your printer model, the following tips may help:

- Find out if your printer is compatible with a model that does run in Linux then use the Ghostscript driver for this compatible model. “Compatible in Linux” means that your printer can print correctly with the same binary control sequences as the compatible model — the printer can “understand” the same printer language directly (rather than just being capable of emulating it in Windows through the driver software).

  The fact that two printers have similar names is not always a guarantee that they are compatible. This is because printers with similar names do not always understand the same printer language directly.

- The best source of information about your printer’s native language is the manufacturer. In many cases, find the printer language listed among the technical data in the printer manual. Some examples of existing printer languages are given in Section *Examples of Default Printer Languages* on page 192.

### Connecting Printers Locally

### Parallel Ports

A printer can be connected to a Linux system via a parallel port. A printer on a parallel port is addressed by the kernel’s parport subsystem. The basic configuration of a parallel port with YaST2 is explained in the *Basics* manual in Section *Manual Configuration*, so only supplemental information is provided here. The parallel port must be made known to the parport subsystem by loading architecture-specific kernel modules. In this way, a number of devices in series can be used simultaneously via one parallel port. The numbering of the device files for parallel port printers begins with `/dev/lp0`. To print over the first parallel port, the modules `parport`, `parport_pc`, and `lp` must be loaded for a SuSE standard kernel. This is normally taken care of by the Kernel Module Loader, kmod (see Section *Kmod — the Kernel Module Loader* on page 232) as soon as the corresponding device file (e.g., `/dev/lp0`) is accessed.
