# Domain Name System

# DNS

DNS serves to alleviate the burden of having to remember IP addresses: DNS assists in assigning an IP address to one or more names and, vice versa, assigning a name to an IP address. In Linux, this conversion is usually carried out by a special type of software known as bind. The machine that takes care of this conversion is called a name server.

The names make up a hierarchical system whereby each name component is divided by points. The name hierarchy is, however, independent of the IP address hierarchy described above.

Examine a complete name:

```
laurent.suse.de
hostname.domain
```

A full name, referred to by experts as a “fully qualified domain name” or FQDN for short, consists of a host name and a portion of a domain. Here, the partial domain consists of any component of the domain — in the above example, suse — and the top level domain, TLD.

TLD assignment has become, due to historical reasons, quite confusing. For instance, three-letter domain names are used in the USA, unlike in the rest of the world, where the two-letter ISO national codes are the standard. In Table 13.6, various TLDs are listed. This overview is by no means complete.

| TLD | Description |
|---|---|
| `.com` | (Commercial) — US companies. |
| `.edu` | (Educational) — Schools, universities, and other non-commercial institutions in the United States. |
| `.gov` | (Government) — State institutions in the US. |
| `.org` | (Organizational) — Non-commercial and non-profit organizations in the US. |
| `.de` | Machines in Germany. |
| `.at` | Machines in Austria. |
