
`LIL-` The descriptor table in the map file is corrupt. This can either be caused by a geometry mismatch or by moving `/boot/boot.b` without reinstalling LILO.

`LILO` All parts of LILO have been successfully loaded.

## Resolving Causes of Error

The most common causes of geometry errors are neither physical defects nor invalid partition tables, but rather routine installation errors. Geometry errors result in particular when the 1024-cylinder limit is not taken into consideration (see Section *The 1024-Cylinder Limit* on the next page).

In most cases, problems can be remedied by taking the following measures:

1. Install the LILO data below the 1024-cylinder limit (if this has not already taken place). This applies to the Linux kernel required, the directory contents of `/boot`, and to the boot sector to adopt the LILO boot code.

2. As root, reinstall LILO using the `lilo` command. `lilo` will issue an informative log if you increase the verbosity and create log files by entering:

```text
earth: # lilo -v -v -v >/boot/lilo.log 2>/boot/lilo.logerr
```

If the boot configuration is correct, `/boot/lilo.logerr` should be empty. You should be able to follow exactly how LILO saves the locations of its files and which BIOS device numbers LILO uses for related hard disks in `/boot/lilo.log`.

3. Check the consistency of the hard disk geometry. This actually pertains to up to four aspects:

    - (a) **Geometry used by LILO** — See the log file mentioned above, which is influenced by the disk setting in `lilo.conf`. See the information on page 101.

    - (b) **Geometry recognized by the Linux kernel** — See the boot messages in `/var/log/boot.msg` or the output of the `dmesg` command. This is influenced by kernel parameters (to a certain degree). See Section *(E)IDE controllers and ATAPI devices* on page 248.

    - (c) **Geometry on which the partition table is based.** See the output of `fdisk -l`. It is influenced by `fdisk` expert commands and poses an extreme risk to your data. It is highly recommended to fully back up your data first.

    - (d) **Geometry detected by the BIOS.** This is the geometry LILO encountered, after the system is booted. LILO must work with it. See the BIOS setup and perhaps the SCSI host adapter setup as well if applicable. This geometry is influenced by the BIOS setup.

The best way to go about making your adjustments in the face of inconsistencies is often the path of least resistance. The following data must be analyzed before you can resolve these errors:

- `/etc/lilo.conf`
- Output of the `fdisk -l` command (partitioning)
- Log files mentioned above
- BIOS and SCSI-BIOS settings for your hard disks

## The 1024-Cylinder Limit

> **Note**
>
> Recent BIOS versions allow starting operating systems above the 1024-cylinder limit. The current LILO version can use this BIOS extension. YaST2 will inform you accordingly of these options for your BIOS while configuring LILO. If your BIOS does not include this extension, continue reading here.

As explained in Section *LILO Locations* on page 94, the entire LILO machinery — all data needed for booting — must be available to BIOS calls. The accessible cylinders were also discussed in that section. This restriction affects only the boot machinery. It is not really required that LILO be installed on the Linux root partition. It is even possible, but quite risky, to put the boot machinery onto partitions of other operating systems to which Linux has read and write access.

> **Caution**
>
> This does not apply to the LILO boot sector, which should never be installed onto an unknown partition, because the file system will be severely damaged.

- The best method is to create a primary partition (within the allowed section) and to install all LILO files (including the LILO boot sector) into this partition.

During installation with YaST2 a small partition `/boot` is created, only big enough to hold the files `boot.b`, `map`, and `message`, and the Linux kernels that LILO should boot.

A few megabytes are enough. It does not matter where you put the rest of your partitions. There are no more restrictions. As soon as the kernel runs, you have unrestricted access to all installed drives.

- If the first and preferable option of a boot partition is not possible, for whatever reason, write LILO on a boot disk or, if you are also running MS-DOS, use loadlin to boot Linux.

- Another alternative is to install the LILO boot machinery onto a non-Linux partition within the permitted section. Linux must have write access (e.g., a FAT or VFAT drive). Remember that the LILO boot sector cannot be installed on that partition. There are only two places to put it: at the start of an extended partition on the first drive—within the 1024-cylinder limit—or on the MBR.

Suppose that the partition in question is mounted as `/mnt`. You want to install LILO in the MBR of `/dev/hda` and also boot DOS from `/dev/hda1`. Proceed as follows:

- Create a new directory (e.g., `/mnt/LINUX`) and copy the LILO files mentioned above to it: `boot.b`, `map`, `message`, and the chain loader for your other operating systems (normally `chain.b`) and the Linux kernels LILO should boot.

- Create a `/mnt/LINUX/lilo.cfg` where all paths point to `/mnt/LINUX` (see File 8).

```text
# LILO Configuration file
# Start LILO global section
boot=/dev/hda                  # Installation target
backup=/mnt/LINUX/hda.xxxx    # backup of old MBR
install=/mnt/LINUX/boot.b     # Of course LILO and
map=/mnt/LINUX/map            # map file are in /mnt/LINUX!
message=/mnt/LINUX/message    # optional
prompt
timeout=100                  # Wait at prompt: 10 s
vga = normal                  #
# End LILO global section
#
# Linux bootable partition config begins
image = /mnt/LINUX/first_Kernel   # default
    root = /dev/Your_Root_Device  # Root partition!
    label = linux
# Linux bootable partition config ends
#
# System section for other kernels:
#
# End Linux
# DOS bootable partition config begins
other = /dev/hda1             # MSDOS system drive
    label = dos
    loader = /mnt/LINUX/chain.b
    table = /dev/hda
# DOS bootable partition config ends
```

*File 8: lilo.cfg for Other Partition*

- Install LILO with *this* `lilo.cfg`:

```text
earth: # /sbin/lilo -C /mnt/LINUX/lilo.cfg
```

After that, LILO should work. Boot MS-DOS and protect the LILO files as well as possible against write access (any write access disables LILO). At least, assign to all files in `X:\LINUX` (where the 'X' is the DOS drive mounted to `/mnt`) the DOS attributes *system* and *hide*.

Also read the two HOWTOs in `/usr/share/doc/howto/en/mini/` — LILO.gz and Large-Disk.gz.

## Special Boot Problems with Kernels from 2.0 Onwards

Problems booting with LILO — regardless of whether you are booting from a floppy or from a hard disk — might occur after part of the kernel has been loaded (e.g., a SuSE installation kernel). You can select a kernel at the LILO prompt and this kernel is loaded (some dots are output onto the screen), but starting the kernel fails. Before reaching "uncompressing Linux", the system crashes with different behaviors.

Possible error messages:

- System reboots
- System just hangs
- "crc-error"
- "no free space"
- "Error 0x00"
- "Error 0x01"
- "incomplete literal tree"

Access to the floppy is attempted, but the system hangs. The cause lies in a combination of a big kernel, LILO, and faulty hardware. This affects roughly one percent of all machines.

We assume that this is due to a faulty BIOS that has problems with fast memory access. This problem does not occur if:

- the machine is booted via loadlin (Section *Configuring the Boot Mechanism with loadlin* on page 120)
- the kernel has been copied to a floppy with `dd if=/vmlinuz of=/dev/fd0` and booted from there
- a smaller kernel, created with `make zImage`, is booted with LILO

The following BIOS settings also do not cause any problems:

- Disable Internal Cache
- DRAM Precharge Wait State value: *1*
- DRAM Wait Burst Timing value: `0x3333`
