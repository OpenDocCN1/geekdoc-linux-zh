LILO creates a backup of the target boot sector, writes its *first stage* into it, then generates a new map file (see also Section *The Components of LILO* on page 93). LILO issues a report on each installed system as shown in Output 4.

```
Added linux *
Added suse
Added windows
Added memtest86
```

When the installation is completed, the machine can be rebooted with `shutdown -r now`. While rebooting, the BIOS first performs its system test. Immediately afterwards, see LILO and its command prompt, where you can enter parameters and select a boot image from the recently installed configurations. `Tab` shows a list of all systems installed.

# Installation After Recompiling a Kernel

For including a freshly-compiled kernel in your LILO boot setup, the Linux kernel Makefile offers an all-in-one solution. All the commands to configure and create the kernel are put together in the `/usr/src/linux/Makefile`. Here, `INSTALL_PATH=/boot` is specified (see Section *Compiling the Kernel* on page 234). This Makefile has a target called `bzilo` that, after a kernel compilation, automatically copies the currently installed kernel `/boot/vmlinuz` (this used to be `/vmlinuz`) to `/boot/vmlinuz.old`, the new kernel to `/boot/vmlinuz`, then reinstalls LILO. This can be done by entering the command `make bzilo` instead of `make zImage`. This is only useful if you have edited `/etc/lilo.conf` in advance and if your current kernel really is located in `/boot/vmlinuz`. The new, as well as the old, kernel should now be listed. See File 3 on page 97 for an example of the resulting `/etc/lilo.conf`.

At the LILO prompt, launch either of the two kernels. This makes your boot more secure, because you can still boot your old kernel if the new one fails. For more on creating a new kernel, see Chapter *The Kernel and Kernel Parameters* on page 229.
