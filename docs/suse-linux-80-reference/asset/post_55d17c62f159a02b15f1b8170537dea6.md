## cron

Daily administration work on the system.

The cron daemon starts automatically certain programs at specified times. Cron is only started in runlevels 2 and 3. It is recommended to activate it on computers that run all the time. An alternative or supplement is the AT daemon.

```bash
MAX_DAYS_IN_TMP="0"
```

cron.daily can check for old files in tmp directories. It will delete all files not accessed for more than the days specified here. Leave it empty or set it to 0 to disable this feature.

```bash
TMP_DIRS_TO_CLEAR="/tmp /var/tmp"
```

Specify the directories from which old files should be deleted.

```bash
OWNER_TO_KEEP_IN_TMP="root"
```

Specify whose files should not be deleted, even after the time set.

```bash
CLEAR_TMP_DIRS_AT_BOOTUP="no"
```

Set this to yes to entirely remove (rm -rf) all files and subdirectories from the temporary directories defined in TMP_DIRS_TO_CLEAR on boot. This feature ignores OWNER_TO_KEEP_IN_TMP — all files will be removed without exceptions.

```bash
DELETE_OLD_CORE="no"
```

Should old core files be deleted? If set to no, cron.daily will tell you if it finds old core files. This feature requires RUN_UPDATEDB to be set to yes and package findutils-locate needs to be installed.

```bash
MAX_DAYS_FOR_CORE="7"
```

Maximum age of core files in days.

```bash
REINIT_MANDB="yes"
```

Should the manual page database (mandb and whatis) be recreated by cron.daily?

```bash
DELETE_OLD_CATMAN="yes"
```

Should old preformatted man pages (in /var/catman) be deleted?

```bash
CATMAN_ATIME="7"
```

How long (in days) should old preformatted man pages be kept before deleting them?

## sysctl

System control at kernel level.

```bash
IP_DYNIP="no"
```

Do you want the “dynamic IP patch” to be enabled at boot?

```bash
IP_TCP_SYNCOOKIES="yes"
```

Enable “syn flood protection”? See /usr/src/linux/Documentation/Configure.help.

```bash
IP_FORWARD="no"
```

If the host is supposed to forward to two network interfaces, set this variable to yes. This is usually interesting for routers or “masquerading”. The script /etc/init.d/boot.proc enables IP forwarding with an entry in the /proc file system.

```bash
ENABLE_SYSRQ="no"
```

If you set this to yes, you will have some control over the system even if it crashes, for example, during kernel debugging. Consult /usr/src/linux/Documentation/sysrq.txt for further information.

```bash
DISABLE_ECN="yes"
```

If you have trouble connecting to some machines on the Internet with your 2.4 kernel but there are no problems with 2.2, this may be due to broken firewalls dropping network packets with the ECN (early congestion notification) flag set. Set this to yes to have ECN disabled at boot.

```bash
BOOT_SPLASH="yes"
```

Set no to turn off the splash screen on console 1 at boot (after kernel load).

### xntpd

Starts the “Network Time Protocol (NTP) Daemon” of package xntp. Configuration is done in file `/etc/ntp.conf`.

```bash
XNTPD_INITIAL_NTPDATE="AUTO-2"
```

A space-separated list of NTP servers to query for current time and date before the local ntpd is started, e.g., "sun.cosmos.com". Set the value AUTO to query all servers and peers configured in `/etc/ntpd.conf`. The new default value is AUTO-2, which will query only the first two servers listed in `/etc/ntpd.conf`.

Radio and modem clocks have addresses of the form 127.127.T.U, where T is the clock type and U is a unit number in the range 0–3.

Most of these clocks require a serial port or special bus peripheral. The particular device is normally specified by adding a soft link `/dev/device-U` to the particular hardware device involved, where U corresponds to the unit number above. (See `/usr/share/doc/packages/xntp/html/refclock.htm`.)
