
LILO creates a backup of the target boot sector, writes its *first stage* into it, then generates a new map file (see also Section *The Components of LILO* on page 93). LILO issues a report on each installed system as shown in Output 4.

```
Added linux *
Added suse
Added windows
Added memtest86
```

*Output 4: Output After Launching LILO*

When the installation is completed, the machine can be rebooted with `shutdown -r now`. While rebooting, the BIOS first performs its system test. Immediately afterwards, see LILO and its command prompt, where you can enter parameters and select a boot image from the recently installed configurations. `Tab` shows a list of all systems installed.

## Installation After Recompiling a Kernel

For including a freshly-compiled kernel in your LILO boot setup, the Linux kernel Makefile offers an all-in-one solution. All the commands to configure and create the kernel are put together in the `/usr/src/linux/Makefile`. Here, `INSTALL_PATH=/boot` is specified (see Section *Compiling the Kernel* on page 234). This Makefile has a target called `bzilo` that, after a kernel compilation, automatically copies the currently installed kernel `/boot/vmlinuz` (this used to be `/vmlinuz`) to `/boot/vmlinuz.old`, the new kernel to `/boot/vmlinuz`, then reinstalls LILO. This can be done by entering the command `make bzilo` instead of `make zImage`. This is only useful if you have edited `/etc/lilo.conf` in advance and if your current kernel really is located in `/boot/vmlinuz`. The new, as well as the old, kernel should now be listed. See File 3 on page 97 for an example of the resulting `/etc/lilo.conf`.

At the LILO prompt, launch either of the two kernels. This makes your boot more secure, because you can still boot your old kernel if the new one fails. For more on creating a new kernel, see Chapter *The Kernel and Kernel Parameters* on page 229.

## Uninstalling LILO

> **Caution**
>
> Uninstalling a boot manager is tricky. Ensure *in advance* that you are able to boot Linux and other systems with their respective boot disks. You should have fdisk installed on every boot disk, to avoid being unable to access your hard disk at all.

To uninstall LILO, copy the former content of the boot sector over LILO. This requires a valid backup of that former content. See Section *Other LILO Configuration Options* on page 99, option backupr.

> **Caution**
>
> A boot sector backup is no longer valid if the partition in question has a new file system (for DOS users: has been formatted). The partition table of an MBR backup becomes invalid if the hard disk in question has been repartitioned in the meantime. Obsolete “backups” are time bombs. It is best to delete them as soon as possible. Unpacking old and invalid backups into system sectors is a direct route to data loss.

It is very simple to regain a DOS, Windows 95/98, or OS/2 MBR. Just enter the MS-DOS command (available since 5.0)

```
C:\> FDISK /MBR
```

or, on OS/2,

```
C:\> FDISK /NEWMBR
```

These commands only write the first 446 bytes (the boot code) into the MBR and leave partitions untouched. For other restorations, first make a backup of the LILO sector in question — just, to be on the safe side. Now check, at least twice, whether your old backup file is the correct one and if it is exactly 512 bytes in size. Finally, write it back, but do not confuse if= and of=:

- If LILO resides in partition yyyy (e.g., hda1, hda2):

  ```
  earth:  # dd if=/dev/yyyy of=New-File bs=512 count=1
  earth:  # dd if=Backup-Date of=/dev/yyyy
  ```

- If LILO resides in the MBR of zzz (e.g., hda, sda):

  ```
  earth:  # dd if=/dev/zzz of=New-File bs=512 count=1
  earth:  # dd if=Backup-Date of=/dev/zzz bs=446 count=1
  ```

The last command is “cautious” and does not overwrite the partition table. Again, *do not forget*: with `fdisk`, mark the desired starting partition as *bootable*. A boot sector backup is done quickly and easily. We recommend doing this frequently.

## Creating a Linux Boot Disk

A Linux boot disk consists (somewhat simplified) of one or more Linux kernels, possibly managed by LILO. It serves to start your system even if it is not possible to boot directly from hard disk (possible reasons: overwritten MBR, misconfigured boot manager, errors while installing).

A boot disk such as this loads *only* the kernel. Everything else, including working system programs and `init` start scripts, must be provided by the installation on the hard disk. The connection between the boot disk and the system on the hard disk is established by the fact that, in the kernel, the root partition in question is set as the root device.

Do not confuse this with the SuSE boot disk used for installation and emergencies. To create a new SuSE boot disk, copy the appropriate image from the directory `disks` on the SuSE CD-ROM to a floppy disk (see Section *The SuSE Rescue System* on page 285).

## Boot Disk Without LILO

Normally, if your hard disk controller support has been integrated into your kernel, your kernel does *not* need any additional command line with hardware information. The easiest way to create a boot disk is to write the actual kernel onto a raw disk and adjust the root device, if this has not been done before.

```
earth:  # /sbin/badblocks -v /dev/fd0 1440
earth:  # dd if=my_kernel of=/dev/fd0 bs=18k
earth:  # rdev /dev/fd0 my_root_partition
earth:  # rdev -R /dev/fd0 1
```

The last command makes sure the kernel initially mounts root as read-only (the start-up scripts expect this).

## Boot Disk with LILO

Create a more capable boot disk with a greeting prompt and kernel parameters by transferring the complete LILO booting start machinery onto the disk (see Section *The Components of LILO* on page 93). The disk needs a file system for this purpose. The Minix file system is best suited for this.

To do this, proceed as follows:

- Create a Minix file system on a new and empty floppy disk and mount the disk to, for example, `/mnt` with the commands.

  ```text
  earth:  # /sbin/mkfs.minix -c /dev/fd0 1440
  earth:  # /bin/mount /dev/fd0 /mnt
  ```

  If your floppy drive supports higher capacities, you can try different values, such as `/dev/fd0u1722` or `1722`.

- Now copy your kernel files and the LILO file `/boot/boot.b` to `/mnt`, for example, onto the floppy disk.

- Optional: create a message file `/mnt/message`.

- Create a `lilo.conf` on `/mnt`. — Specify the actual root partition instead of `Your_Root_Device`. See File 6 for an example.

  ```text
  # LILO Configuration file bootdisk
  # Start LILO global Section
  boot=/dev/fd0                 # Installation: Floppy
  install=/mnt/boot.b           # Of course LILO and
  map=/mnt/map                  # map fit onto floppy!
  message=/mnt/message          # optional
  prompt
  timeout=100      # Wait at prompt: 10 s
  vga = normal     #
  # End LILO global section

  # Linux bootable partition config begins
  image = /mnt/vmlinuz           # default
      root = /dev/Your_Root_Device  # Here is your root partition!
      label = linux
  # Linux bootable partition config ends
  ```

  *File 6: lilo.conf for a Boot Disk*

- If you are using an initrd, add it to `lilo.conf` as described in Section *Boot Loaders* on page 278.

- Install LILO with this `lilo.conf`:

  ```
  earth:  # /sbin/lilo -C /mnt/lilo.conf
  ```

- Unmount the floppy

  ```
  earth:  # /bin/umount /mnt
  ```

- Check your boot disk at the next system boot to verify it works.

## DOS/Windows 95/98 and Linux

*Requirements:* There must be at least a primary partition each for DOS/Windows 95/98 and Linux below the 1024-cylinder limit (Section LILO Locations on page 94).

For this case, we have already discussed a configuration (File 3 on page 97) — only the settings for root, image, and other need adaptation. LILO is installed in the MBR.

Save your `/etc/lilo.conf` and be sure you have a Linux boot disk. Windows 95/98 is especially inclined to eliminate “foreign” MBRs. If you can still boot Linux using your boot disk, this problem is quickly solved with the command

```
earth:  # /sbin/lilo
```

This completes your LILO installation.
