
- It takes into consideration the order of print jobs in the queue.
- It monitors the status of the queues and printer and provides relevant information when requested.
- It listens to port 515 to accept (or reject) print jobs from remote computers for local queues.
- It relays print jobs on queues to remote machines to their printer spoolers.

Details on the LPRng spooler can be found in the LPRng Howto in file: `/usr/share/doc/packages/lprng/LPRng-HOWTO.html`, in the man page for `printcap` (man printcap), and in the man page for `lpd` (man lpd).

## Management Tools for the Printer Spooler

You need root permission for numerous manipulations on the print queues. The management tools are outlined in the *Basics* manual, in Section *Commands for Managing the Print System* and in the LPRng HOWTO in file: `/usr/share/doc/packages/lprng/LPRng-HOWTO.html#LPRNGCLIENTS`. For this reason, we only summarize this information below.

**lpq -Pqueue** shows the print jobs in the queue specified. If `all` is given as an LPRng spooler queue, all print jobs will be shown in all queues. `lpq -l -Pqueue` shows more extensive information and `lpq -L -Pqueue` outputs a detailed status report good for troubleshooting. See *Showing Status for Remote Queues* for more information. Also take a look at the man page for `lpq` (man lpq) and file: `/usr/share/doc/packages/lprng/LPRng-HOWTO.html#LPQ` in the LPRng HOWTO.

**lprm -Pqueue jobnumber** deletes the print job with the given job number from the specified queue. Only root can delete jobs sent by other users. root can delete all print jobs in all queues in the LPRng spooler by entering the command `lprm -Pall all`.

More information is given in Section *Generating Print Jobs* on the next page, in the man page for `lprm` (man lprm), in file: `/usr/share/doc/packages/lprng/LPRng-HOWTO.html#LPRM`, and in the *Possible Problems* on page 193.

**lpc** controls the print queues: these can be specified by name or you can specify all. Most of the lpc commands listed below can only be executed by root. The most important options are:

- `help` — provides a brief overview of the options
- `status queue` — issues a status report
- `disable queue` — blocks new jobs from entering the queue
- `enable queue` — opens the queue for new jobs
- `stop queue` — stops the printing of jobs in the queue. The job currently being printed will be finished, however.
- `start queue` — resumes printing of jobs in the queue
- `down queue` — works like disable and stop together
- `up queue` — has the same effect as enable and start together
- `abort queue` — is the same as down, except that a job currently being printed will be stopped immediately. The jobs are retained in the queue and can continue to be processed after restarting the queue with up.

Pass these commands to `lpc` directly in the command line (e.g., `lpc status`) or run `lpc` without parameters so the dialog mode with its own prompt, `lpc>`, is started, awaiting the entry of `lpc` commands. End this dialog with `quit` or `exit`.

More information can be found in the man page for `lpc` (man lpc) and in file: `/usr/share/doc/packages/lprng/LPRng-HOWTO.html#LPRM` and in the Basics manual in Section Displaying and Managing the Queues.

> **Note**
>
> Print jobs remain in the queues even when you shut down the computer during printing and then start Linux again. A print job that has gone wrong should be removed from the queue with the commands shown above.

## Generating Print Jobs

The `lpr` command is described in the Basics manual in Section Generating a Print Job and in the LPRng HOWTO in file: `/usr/share/doc/packages/lprng/LPRng-HOWTO.html#LPR`, so we only provide some additional information below.

### Generating Print Jobs for Local Queues

The typical print command is `lpr -Pqueue file`.

If the option `-Pqueue` is omitted, the default is taken from the PRINTER environment variable. This is also true for the `lpq` and `lprm` commands — see the man page for `lpr` (man lpr), the man page for `lpq` (man lpq), and the man page for `lprm` (man lprm). The environment variable PRINTER is automatically set when you log in and can be checked with the command `echo $PRINTER` and reset to another queue with `export PRINTER=queue`.

### Generating Print Jobs for Remote Queues

Remote queues can also be accessed by the LPRng spooler via the `lpr` command with `lpr -Pqueue@printserver file`. Replace `printserver` with the name or the IP address of a print server and `queue` with the queue name on the print server. This, of course, also requires that the print server is configured so that you can print on its queues. For more information on this, see the item *Printer connected to a print server with filtering on the print server* in the section *Printing in the TCP/IP Network* below.

### Showing Status for Remote Queues

Query the remote queue using the commands:

```
newbie@earth:  > lpq -Pqueue@printserver
newbie@earth:  > lpq -l -Pqueue@printserver
newbie@earth:  > lpq -L -Pqueue@printserver
```

This status query can be helpful, particularly if you cannot print over the remote queue. Refer to the item *Verify remote lpd* in Section *Printing in the TCP/IP Network* below.

### Deleting Print Jobs in Remote Queues

All self-generated print jobs can be deleted in remote queues by entering the commands:

```
newbie@earth:  > lprm -Pqueue@printserver jobnumber
newbie@earth:  > lprm -Pqueue@printserver all
```

root does not have any access privileges to remote queues.

## The Print Filter

lpdfilter (package lpdfilter) is used as the print filter. The basic method of operation of the print filter is described in the *Basics* manual in Section *Print Job Procedure*. A detailed description of the print job procedure is presented in the following. For an exact analysis of the print filter, browse the print filter scripts (especially `/usr/lib/lpdfilter/bin/if`). You may also want to proceed as described in Section *Print Filter Troubleshooting* on page 215.

1. The print filter (`/usr/lib/lpdfilter/bin/if`) defines options passed to it directly from the spooler or reads the options from the print job’s “control file” and from the `/etc/printcap` and `/etc/lpdfilter/queue/conf` files of the respective queue (queue in the path name should be replaced by the actual queue name).

2. It defines the type of data to be printed. The script `/usr/lib/lpdfilter/bin/guess` uses the file command to find out the type of data. The command’s output defines the type of data to print depending on the specifications in the `/etc/lpdfilter/types` file.
    - If it is an ascii queue, the print filter is forced to treat the data to print as ASCII text.
    - If it is not an ascii queue, the print filter will attempt to detect the type of data to print.

3. Depending on the type of data to print and the queue, the data is then converted to printer-specific information:
    - If it is a raw queue, the data is usually relayed directly to the printer (or to another queue). However, depending on the settings in `/etc/lpdfilter/queue/conf`, it might also be converted with recode. If it is an absolute raw queue — without an lpdfilter — you must remove the line `:if=/usr/lib/lpdfilter/bin/if:\` in `/etc/printcap` of the respective queue.
    - If it is not a raw queue:
        - (a) If the print data is not PostScript, it will first be converted to PostScript with `/usr/lib/lpdfilter/filter/type2ps` (replace type with the actual type of the print data). In particular, ASCII text is converted to PostScript by way of `/usr/lib/lpdfilter/filter/ascii2ps` with the program `a2ps`, according to the country-specific encoding configured for the queue, so country-specific special characters can also be printed in simple text. Refer to the man page for a2ps (`man a2ps`) for more information.
        - (b) The PostScript data can be reformatted again, if needed, as long as there is a script located in `/etc/lpdfilter/queue/pre` (replace queue here with the actual queue name).
        - (c) If necessary, the PostScript data is then converted to another printer language.
            - If you have a PostScript printer connected, the PostScript data is sent directly to the printer (or to another queue). In addition, the bash functions “duplex” and “tray”, defined in `/usr/lib/lpdfilter/global/functions`, may be activated to enable duplex printing or paper tray selection using PostScript commands — provided that the PostScript printer can process these commands accordingly.
            - If you do not have a PostScript printer connected, a Ghostscript driver for your specific printer model will be used to generate printer-specific data, which can then be sent to the printer or to another queue. The parameters for the Ghostscript command are either stored right in the `/etc/printcap` file, in the `cm` line, or in the `/etc/lpdfilter/queue/app` file (replace queue here with the actual queue name). The Ghostscript output can be reformatted, if there is an appropriate script in `/etc/lpdfilter/queue/post` (replace queue here with the actual queue name).
        - (d) The printer-specific data will be sent to the printer (or to another queue). At the same time, printer-specific control sequences can be sent before and after the printer-specific data if specified in `/etc/lpdfilter/queue/conf`.

### Configuring the Print Filter

The print filter is usually configured in the process of setting up your print system with YaST2, as described in the Basics manual in Chapter YaST2, Printers.
