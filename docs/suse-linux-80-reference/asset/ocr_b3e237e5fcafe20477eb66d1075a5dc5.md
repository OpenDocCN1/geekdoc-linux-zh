If the printer works locally, you now know the correct Ghostscript driver and other parameters for the configuration of the prefilters. Now, configure the printer in the network as described above with the correct settings.

# Verify remote lpd

As user root, request a status report for the queue on the remote host (provided that lpd is running and it can receive direct requests) with:

```
earth: ~ # echo -e "\004queue" | netcat -w 2 -p 722 host 515
```

This report may be very long. Lack of response from the lpd may be the result of some fundamental network problems. If you do get a response from the remote lpd, it should indicate why nothing can be printed from the queue on the remote host. Examples:

```
lpd: your host does not have line printer access
lpd: queue does not exist
printer: spooling disabled
printer: printing disabled
```

*Output 13: Error message from lpd*

If you receive this type of response from the lpd, the source of the problem is the remote lpd.

# Network printer or print server unit does not work reliably

Sometimes problems may occur with the printer spooler located on the print server unit or network printer, especially when several clients are sending print jobs to the printer server unit or network printer simultaneously. As the problem is the printer spooler in the printer server unit or in the network printer, the easiest solution is to connect the printer directly to a print server or filter the print data on the client.
