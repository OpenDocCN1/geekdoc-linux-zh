
When the kernel module `parport_pc` is loaded without any special parameters, it will attempt to automatically detect and configure the parallel ports. In rare circumstances, this does not work and the parameters for the `parport_pc` module must be configured manually.

## Manual Configuration

If certain conditions for automatic configuration are not met or if you require a custom configuration, configure the parallel port manually.

## Hardware connection (port)

If YaST2 is able to detect the printer model automatically, it is assumed that the printer connection is working on the hardware level. If this is the case, no settings will have to be made here.

If the printer was not detected at all, the printer port needs to be configured manually. Start the YaST2 Control Center, select ‘Hardware’ then ‘Automatic Printer Detection’. An unrecognized printer is listed under the available printers as ‘Other (not recognized)’. Next, click ‘Configure’, choose your port in the following menu, and click ‘Next’. Then you will see the corresponding ports:

- `/dev/lp0` — first parallel port
- `/dev/usblp0` — port for a USB printer

At this point, run the test in YaST2 to determine whether your printer can be accessed over the selected port. Then, click ‘Next’.

Select your model now. Click ‘Info’ to obtain information about Linux support for each printer and, in case of GDI printers, where you might find Linux drivers.

If your printer model is not listed, click ‘Generic Printers’ and select one of the generic Ghostscript drivers for the standard printer languages.

> **Note**
>
> Consult the printer manufacturer if you do not know which printer language your model understands or whether it is compatible with one of the models listed in the printer database. Your printer must be able to “understand” the same printer language on the hardware level. Software emulation is not sufficient.

You get the best results when the printer is connected directly to the first parallel port and the following settings are specified in the BIOS:

- I/O address 378 (hexadecimal)
- Interrupt is not relevant (by default, no interrupt is used).
- Mode Normal, SPP, or Output Only (other modes do not always function)
- DMA is disabled (should automatically be disabled for any of the above modes)

If, despite these BIOS settings, the printer is still not accessible over the first parallel port, the I/O address must be explicitly entered under the detailed parallel port settings in accordance with the settings made in the BIOS in the format 0x378. If there are two parallel ports set to the I/O addresses 378 and 278 (hexadecimal), they usually have to be entered in the format of 0x378, 0x278.

## Printer name

Printer name refers to the “queue”, which will often have to be given when entering the command to print. Therefore, you should only use short names in lowercase letters. Numbers can also be used in the names. By default, lp is configured as the first queue.

A raw queue can be set up for use in certain situations. In a raw queue, the data to print is not converted by a printer filter, but is sent in raw form directly to the printer. For this reason, the data to print must already exist in the model’s respective printer language. A queue can be set up with or without “form feed”, depending on whether the printer spooler is doing a form feed after each printout, so the last page printed is ejected from the printer as well. Normally, the Ghostscript driver takes care of this, therefore no explicit formfeed needs to be configured.

## Ghostscript driver and printer language

Since the Ghostscript driver generates printer-specific data for non-PostScript printers, the configuration of the Ghostscript driver is key to determining the type of printout. First, the selected Ghostscript driver, then, the driver-specific settings define the print image. For one printer, different configurations can be set to get different print images.

If YaST2 automatically detected the printer model or the model is found in the printer database, you will be presented with a reasonable selection of compatible Ghostscript drivers. If the printer model is not included in the printer database, you will be provided with a selection of generic Ghostscript drivers for the standard printer languages.

> **Note**
>
> You might want to consult the manufacturer as to which printer language your model understands or with which model listed in the printer database your printer is hardware-compatible. The printers must be able to understand the same printer language in terms of hardware, without using additional emulation software.

If you want to use a Ghostscript driver that is not listed, you might find it listed under the manufacturer.

Specific parameters can often be set for each Ghostscript driver. The correlation between a selected value and its options can be seen in the structure of the selection menu itself — in the menu items and their respective subitems.

Not all combinations of driver settings work for every printer model — particularly if a high resolution is selected. Print the YaST2 test page to make sure your settings work. If the test print produces undesired results (e.g., a lot of blank pages with just some characters on them), the print job can be immediately stopped at the printer by taking out all the paper, then clicking the ‘Stop’ button. However, some printers will not print again later if you do that. Therefore, it is better to just click the ‘Stop’ button and wait for the printing to stop.

## Hardware-Dependent Settings

Although all the available options should produce the desired printout, you should still check the settings by printing out a test page.

- The page layout can only be specified for ASCII text printouts, not for graphics or documents produced by specific applications.
- An ascii queue can be configured for special cases. In ascii queues, the print filter is forced to output ASCII text. This is needed, for instance, when ASCII text files are not recognized as such by the print filter for whatever reason.
- Country-specific encoding relates to the display of special characters in ASCII text printouts and simple text output from Netscape HTML pages.

In simple text, every character is encoded as a given number. A code table defines the characters displayed for each number. Different characters can be displayed on the screen for the same encoding, depending on which code table an application uses. Only codes from 0 to 255 are possible for standard charsets. Codes 0 to 127 are the ASCII characters (the “normal” letters, numbers, and special characters, but no country-specific special characters). These are always the same. Codes 128 to 255 are used for country-specific special characters, such as umlauts, tildes, and accents. Since there are considerably more than 128 different country-specific characters, codes 128 to 255 are not the same everywhere, but reserved for specific national character settings depending on geographical location. ISO-8859-1 (or Latin 1) is the encoding for Western European languages, and ISO-8859-2 (or Latin 2) is the encoding for Central and Eastern European languages. According to ISO-8859-1 encoding, code 161 outputs an upside-down exclamation mark, but in ISO-8859-2, a large A with an ogonek.

## Configuring the Parallel Port

The parallel port `/dev/lp0` is configured by entering a line in `/etc/modules.conf` (File 15).

```
alias parport_lowlevel parport_pc
options parport_pc io=0x378 irq=none
# If you have multiple parallel ports, specify them this way:
# options parport_pc io=0x378,0x278 irq=none
```

*File 15: /etc/modules.conf: First parallel port*

io stands for the first address of the parallel port. The entry `irq=none` puts the parallel port into “polling mode” rather than interrupt driven mode. This is generally a better option and is slower only on very old computers.

For these settings to function, the following values for the parallel port (if available) must be set in the BIOS or over the computer’s firmware:

- I/O address 378 (hexadecimal)
- Interrupt 7 (irrelevant in polling mode)
- Mode Normal, SPP, or Output-Only (other modes do not always function)
- DMA is disabled (should be in Normal mode)
