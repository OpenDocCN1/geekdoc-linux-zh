
## Configuring Additional Parallel Ports

A second parallel port (/dev/lp1, which can be addressed by the standard I/O address 278 (hexadecimal; e.g., set by a jumper on an ISA interface card), is also configured by a line in /etc/modules.conf (File 16).

```text
alias parport_lowlevel parport_pc
# options parport_pc io=0x378 irq=none
# If you have multiple parallel ports, specify them this way:
options parport_pc io=0x378,0x278 irq=none
```

*File 16: /etc/modules.conf: Two parallel ports*

### Special Plug-In Cards: ISA PnP and PCI

If the I/O address of an additional parallel port is currently unknown, you will have to determine this.

**ISA PnP cards** If possible, define permanent values for I/O addresses and, if necessary, for interrupt and mode (e.g., via jumper).

Otherwise, the values for I/O address, interrupt, and mode will not be written to the ISA PnP card until Linux is started. The values entered can be verified by viewing the Linux boot messages in the /var/log/boot.msg file or with the help of the pnpdump command (package isapnp).

**PCI cards** The I/O addresses and the interrupt appropriate for a PCI card can be viewed by entering `/sbin/lspci -v | less`. The result is shown in Output 12.

**Output 12: Output of lspci -v for a PCI Interface Card**

```text
earth:  # /sbin/lspci -v | less

...
00:0a.0 Parallel controller: ...
        ...
        Flags: stepping, medium devsel, IRQ 10
        I/O ports at b400
        I/O ports at b000
        I/O ports at a800
        I/O ports at a400
...
```

Two I/O addresses 400 (hexadecimal) apart belong together to one parallel port — in our example one port has b000 and b400, and the other, a400 and a800. You may have to experiment to see which of either I/O address works. The configuration entry in /etc/modules.conf may then look like in File 17.

```text
alias parport_lowlevel parport_pc
options parport_pc io=0x378,0xb400,0xa800 irq=none,none,none
```

*File 17: /etc/modules.conf: PCI Card with 2 Parallel Ports*

### Activating and Testing the Parallel Port

After rebooting, the parallel port is activated. Rather than rebooting, as user root, it is sufficient to update the dependency list of the kernel modules and to unload then reload the kernel modules pertaining to the parallel port.

```text
earth: # depmod -a 2>/dev/null
earth: # rmmod lp
earth: # rmmod parport_pc
earth: # rmmod parport
earth: # modprobe parport
earth: # modprobe parport_pc
earth: # modprobe lp
```

If the printer is able to print ASCII text, you should be able to enter, as user root, the command

```text
earth: # echo -en "\rHello\r\f" > /dev/lp0
```

to print a page that contains the word Hello. This way, the word Hello is made print-compatible by preceding it with the ASCII character `\r` for the carriage return, followed by the ASCII character `\f` to trigger a line feed. /dev/lp1 should be used as a second parallel port and /dev/lp2 for the third.

## USB Connections

A USB interrupt must be activated in the computer’s BIOS. For example, in an Award BIOS, set the entry such as ‘USB IRQ’ to Enabled in the menu pertaining to ‘PNP AND PCI SETUP’.

Test the accessibility of the USB printer as user root by entering `echo -en "\rHello\r\f" >/dev/usb/lp0`. Provided that a printer is connected to the first USB port `/dev/usb/lp0` and can print ASCII text, the output should be a page with the word Hello.

At times, the USB printer can no longer be accessed, such as cases when the USB plug is pulled while printing. You normally only need to use these commands to restart the USB system:

```text
earth:  # rchotplug stop
earth:  # rchotplug start
```

If this does not help, all processes accessing `/dev/usb/lp0` need to be terminated. Then the kernel modules for the USB printer must be unloaded and reloaded. First, find out which USB modules (`usb-uhci`, `usb-ohci`, or `uhci`) are loaded and whether further module dependencies exist with the command `lsmod`.

```text
usbcore  ...  [printer usb-uhci]
```

This indicates that the module usbcore is required by the printer and usb-uhci modules. In a case like this, the printer and usb-uhci modules must be unloaded before usbcore.

Enter the following commands as user root. Depending on your system, you may have to substitute usb-uhci with usb-ohci or uhci:

```text
earth:  # fuser -k /dev/usb/lp0
earth:  # rchotplug stop
earth:  # rmmod printer
earth:  # rmmod usb-uhci
earth:  # umount usbdevfs
earth:  # rmmod usbcore
earth:  # modprobe usbcore
earth:  # mount usbdevfs
earth:  # modprobe usb-uhci
earth:  # modprobe printer
earth:  # rchotplug start
```

## Serial Ports

The *LPRng HOWTO* in `file:/usr/share/doc/packages/lprng/LPRng-HOWTO.html`, particularly the file `/usr/share/doc/packages/lprng/LPRng-HOWTO.html#SERIAL` section, and the man page for `printcap` (man printcap) describe how to operate a printer using an LPRng spooler on the serial port.

Here, you will find additional indications for BSD and plp spoolers.

1. You should use the plp printer spooler (package `plp` from series n) instead of the BSD spooler. If you still want to use the BSD spooler, proceed as described further below.

2. Check your `/etc/printcap` file. In addition to the usual entries, there need to be some entries specifying parameters for the serial port.

   ```text
   :br#9600:\
   :ty=ixon -imaxbel -ixany -ixoff -crtscts:\
   ```

   With br, the baud rate of the serial port is specified. ty stands for the stty options. You may need to adjust both values, depending on the hardware you have. Similarly, you might need to set the correct speed value to match your specific setup — normally one of these values: 2400, 4800, 9600, 19200, 38400, 57600, 115200, and 230400.

   With a HP DeskJet 500, for example, the following stty settings should do the trick:

   ```text
   :ixon ixoff imaxbel opost
   ```

   The man page for stty explains many of the available options.

3. If you use the BSD spooler: While this printer spooler does read the br entry in `/etc/printcap`, it does not know about the ty option. However, serial port parameters can also be configured using the commands `setserial` and `stty`.

   To set the parameters to the same values as defined via `/etc/printcap` in the example above, use the following command:

   ```shell
   earth: # stty 9600 ixon -imaxbel -ixany -ixoff \
       -crtscts </dev/ttyS(x)
   ```

   To achieve the desired result, use a sensible value for ttyS(x) — this should be ttyS0 or ttyS1 in most cases.

   Inserting the required setserial and stty commands into the file `/etc/init.d/boot.local` will ensure that they are run automatically on boot. In addition to that, edit `/etc/printcap`, removing any lines which look like this:

   ```text
   :br#9600:\
   :ty=ixon -imaxbel -ixany -ixoff -crtscts:\
   ```

   If you did not remove these lines, they would set the wrong default values for the serial port, because the BSD spooler does not know about the ty option. Remember that you want the serial port to be configured according to the above commands (maybe upon booting), without them being changed afterwards.

## Configuring the Print System with lprsetup

Normally, the printer system is configured with YaST2, as described in the *Basics* manual in Chapter *YaST2, Printers*. The lprsetup program is also available. It can be fully operated in command-line mode.

If a printer is configured with YaST2, YaST2 collects the necessary information then invokes lprsetup with the necessary options, creating the actual configuration. The lprsetup program is intended as an “expert” tool. In contrast to YaST2, lprsetup does not provide any assistance in choosing the right values for each of the options.

`lprsetup --help` briefly outlines the available options. More extensive information is available in the man page for `lprsetup` (man `lprsetup`) and the man page for `lpdfilter` (man `lpdfilter`).

For information relating to Ghostscript drivers and driver-specific parameters, see Section *A Little About Ghostscript* on page 215.

## The Printer Spooler and Its Management Tools

### The Printer Spooler (lpd)

By default, the LPRng (package `lprng`) is generally used as the printer spooler. The printer spooler lpd (Line Printer Daemon) is normally activated when booting by invoking the script `/etc/init.d/lpd`. The printer spooler daemon that runs in the background can be started and stopped manually by entering:

```text
earth:  # rclpd start
earth:  # rclpd stop
```

The printer spooler checks in the configuration file `/etc/printcap` what print queues are defined and organizes the handling of the “spooled” jobs:

- The printer spooler manages the local queues. It sends the data file of each job through the print filter, if necessary, then either directly to the printer or relays it to another queue.
