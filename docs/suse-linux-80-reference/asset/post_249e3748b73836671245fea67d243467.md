
## Some Tips on Drivers and Parameters

Before we present the list of parameters, here are some hints on recognizing hardware, adding parameters, and booting with the SuSE boot disk:

- Most drivers can do an *autoprobing*, such as testing different standard addresses where this hardware is usually located. While autoprobing, a driver might initialize an address that does not belong to it. This can cause the machine to hang.
- Some modules can be loaded successfully, even if their hardware is not installed. This applies mostly to 3Com network card drivers. You should try autoprobing first. Unused drivers can be easily removed. Hardware that is not automatically recognized must then be started using the appropriate parameters.
- Finally, there are some hardware components that have more than one driver (e.g., NCR 53C810, Ultrastor). As far as we know, there is no significant difference between the two Ultrastor drivers. The BSD driver for NCR53C810 also supports other NCR53C8xx products (e.g., 53C875), whereas the old NCR driver is the only one that recognizes CD writers. Use the one that suits your needs.

### Kernel Parameters at the Boot Prompt

The parameters listed in this section can only be passed to the kernel, for example, at the SYSLINUX prompt (boot disk included), at the LILO prompt, or with loadlin.

If you plan to install one of these drivers as a module, look at the parameters in Section *modprobe Parameters* on page 255.

> **Note**
>
> All parameters must be entered directly one after another, separated by commas. There should be no spaces between the parameters.

For example, to enter the parameters for aha1542 at the boot prompt, enter `linux aha1542=0x300`. Keep in mind that you always have to precede the parameters with the boot configuration’s name. On SuSE boot disks, this is the configuration with the name `linux`.

### General boot parameters

Certain parameters can be used to control the overall behavior of the Linux kernel.

- *Reboot mode* (shutting down Linux)  
  `reboot={mode}`

  Here, you have the following values for `{mode}`:

  | Variable | Values / Meaning |
  |---|---|
  | `warm` | warm reboot (no memory check) |
  | `cold` | cold reboot (with memory check) |
  | `bios` | BIOS reboot |
  | `hard` | CPU crash reboot (triple fault) |

  *Example:* `reboot=cold`

  This boots the machine after shutdown as if the reset button had been pressed.

- *Protecting memory segments (reserve)*  
  `reserve={start1},{range1},...,{startN},{rangeN}`

  This parameter allows you to reserve memory space for hardware that does not respond to the autoprobe (and perhaps reacts by crashing).

  Example: A “sensitive” network card can be protected from being auto-probed and initialized by entering `reserve=0x330,32 ether=5,0x330,eth0`. In this example, the network card has a 32-bit data bus which starts at address `0x330` and uses interrupt 5.

  For a full description of network card parameters, see Section *Other devices* on page 250.

- *Placing root partitions*  
  `root={partition}`

  | Variable | Values / Meaning |
  |---|---|
  | `{partition}` | e.g. `/dev/hda1`, `/dev/sdb5` |

  Example: `root=/dev/hda5`  
  This boots the kernel and tries to load the root partition from the first logical drive in the extended partition to the first (E)IDE hard disk.

- *Size of RAM (mem)*  
  `mem={size}`

  Enter the size of RAM in bytes, kilobytes (‘K’), or megabytes (‘M’). For 256 MB RAM, enter `mem=256M`.

  When using a Pentium clone, try `mem=nopentium`. It might make it work.

  The standard kernel included here for i386 and also in older SMP systems supports up to 4 GB. The standard SMP kernel is configured for 64 GB.

- *Number of CPUs when using SMP*  
  `maxcpus={number}`

  Set the maximum number of CPUs to `{number}` when using an SMP kernel.

  Example:  
  `maxcpus=1`

- *Serial console*  
  `console={device},{options}`

  Set the device for the system console. This parameter can be used several times.

  ```
  Examples:
  console=ttyS1,9600
  console=tty0
  ```

  See `/usr/src/linux/Documentation/serial-console.txt` for more examples.

### The SCSI controller and the SCSI subsystem

Most SCSI controllers can be configured with parameters.

- *SCSI Streamers*  
  `st={buffer},{threshold},{max}`

  | Variable | Values / Meaning |
  |---|---|
  | `{buffer}` | Buffer size (number of 1 KB blocks) |
  | `{write threshold}` | Write threshold (number of 1 KB blocks) |
  | `{max}` | Maximum buffer size (optional) (e.g. 2) |

  Example: `st=1000,2000`

- *Number of SCSI devices per ID*  
  `max_scsi_luns={number}`

  | Variable | Values / Meaning |
  |---|---|
  | `{number}` | `1..8` |

  Example: If you want to use only the first LUN, you need to set `max_scsi_luns=1`.

  This is typically used for CD changers where the amount of usable CDs equals the parameter `max_scsi_luns=1`.

- *Adaptec AHA-1520 / 1522 / 1510 / 1515 / 1505 SCSI host adapter*  
  `aha152x={ioaddr},{irq},{id},{rec},{par},{sync},{delay}[,{ext_tran}]`

  | Variable | Values / Meaning |
  |---|---|
  | ⟨id⟩ (SCSI ID of the host adapter) | 0, 1 |
  | ⟨rec⟩ (reconnect) | 0, 1 |
  | ⟨par⟩ (parity) | 0, 1 |
  | ⟨sync⟩ (synchronous) | 0, 1 |
  | ⟨delay⟩ | 100 bus delay, default value |
  | ⟨ext_trans⟩ | 0, 1 C/H/S translation |

  This driver is used to run multiple low-cost SCSI controllers. All sound cards with a SCSI controller (except for Pro Audio Spectrum) can be accessed using the installed Adaptec chip.

  For all non-original 152x, the fourth parameter (RECONNECT) seems to be necessary. For most types, it has to be set to ‘0’. Only the AHA2825 needs ‘1’.

  *Example:* `aha152x=0x300,10,7`

- *Adaptec AHA-1540 / 1542 SCSI host adapter*  
  `aha1542={addr}[,{buson}[,{busoff}[,{DMA speed}]]]`

  | Variable | Values / Meaning |
  |---|---|
  | ⟨buson⟩ | 2..15 |
  | ⟨busoff⟩ | 1..64 |
  | ⟨DMA speed⟩ | 5, 6, 7, 8, 10 |

  *Example:* `aha1542=0x300`

- *Adaptec AHA-274x / 284x / 294x host adapters*  
  `aic7xxx={modifier}[,{modifier}[,...]]`

  | Variable | Values / Meaning |
  |---|---|
  | `{modifier}` | `extended`<br>activates translation of hard disk geometry<br><br>`no_reset`<br>disables reset of the SCSI bus at the host adapter initialization<br><br>`irq_trigger:{x}`<br>Only for EISA systems<br>0 for edge triggered,<br>1 for level triggered<br><br>`verbose`<br>receive more messages<br><br>`reverse_scan`<br>If multiple cards are treated in the wrong order by the BIOS<br><br>`7895_irq_hack:{x}`<br>-1 only for Tyan II Motherboards<br><br>`pci_parity:{x}`<br>if pci_parity is not used at all<br>parity is even<br>0 no parity check<br>1 parity odd<br><br>`tag_info:xxxx`<br>Queue management for performance enhancement, for experts, see kernel sources |

  **Example:** `aic7xxx=no_reset`, if the machine hangs while resetting the SCSI bus. Parameters for aic7xxx-based SCSI host adapters are only necessary if they are faulty or malfunctioning.

  From BIOS version 1.3 onwards, the AHA-2940 AU causes no trouble. Updates may be obtained from Adaptec support.

  The SCSI host adapter Adaptec 2920 is driven by the Future Domain driver (see Section The SCSI controller and the SCSI subsystem on page 246).

- **Advansys SCSI host adapter**  
  `advansys={addr1},{addr2},...,{addrN}`

  **Example:** `advansys=0x110,0x210`

  This example tells the kernel to search for the Advansys host adapter at the given addresses.
