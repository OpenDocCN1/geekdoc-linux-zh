
```
earth: # cat ascii-file.ibmpc > /dev/lp0
```

should correctly output an ASCII text file on a printer that prints ASCII text and uses DOS/Windows characters. If this works, it is recommended to create a print filter that performs this conversion of the ASCII text file to the printer-specific format automatically.

## Example of a Custom Print Filter

First, create a subdirectory for your custom print filter. Then, change to this subdirectory (as user root):

```
earth: # mkdir /usr/local/myprinterfilter
earth: # cd /usr/local/myprinterfilter
```

Create a bash script (as an ASCII text file) with the name asciifilter, as shown in File 34.

```
#!/bin/bash

# make a temporary file
INPUT="$(mktemp /tmp/asciifilter.$$.XXXXXX)"

# First store everything from stdin in $INPUT
# to have the input as a regular file
cat >$INPUT

# Recode the INPUT
recode lat1..ibmpc $INPUT

# Add a FormFeed at the end of $INPUT
# to get the last page out of the printer
echo -en "\f" >>$INPUT

# Send $INPUT to stdout
cat $INPUT

# Remove the INPUT file
rm $INPUT
```

*File 34: /usr/local/myprinterfilter/asciifilter*

Make this script executable for all users with:

```
earth: # chmod -v a+x /usr/local/myprinterfilter/
earth: # chmod -v a+rx /usr/local/myprinterfilter/asciifilter
```

Use lprsetup to create an additional printer queue (see lprsetup --help).  
Here, af stands for “asciifilter”, the queue name.

```
earth: # lprsetup --add af --lprng --device /dev/lp0 --raw --sf
```

In the af entry of /etc/printcap search for the line and replace `/usr/lib/lpd/filter/bin/if` with `/usr/local/myprinterfilter/asciifilter`. The entire line should look like this:

```
af:\
        :cm=lpdfilter drv= method=raw color=no:\
        :method=ascii color=no:\
        :lp=/dev/lp0:\
        :sd=/var/spool/lpd/af:\
        :lf=/var/spool/lpd/af/log:\
        :af=/var/spool/lpd/af/acct:\
        :if=/usr/local/myprinterfilter/asciifilter:\
        :la=mx#0:\
        :tr=\f:
```

*File 35: /etc/printcap: Custom Filter*

Stop and restart the printer spooler with:

```
earth: # rclpd stop  
earth: # rclpd start
```

Now all users should be able to print with `lpr -Paf ascii-file`.

The standard SuSE kernel, written to disk during installation and found in a correctly installed system, under `/boot`, is configured to support as wide a range of hardware as possible. If you have made the right selection during the installation or update, this kernel will be specifically optimized for your processor. Therefore, it is not necessary to compile your own kernel. However, if you want to test experimental features and drivers, you might need to generate a new kernel. You will certainly get an interesting insight into the current state of development.

Several Makefiles are provided with the kernel to automate the process. These Makefiles handle nearly all the details for you. The only thing you have to do by hand is make selections for hardware settings and other kernel features.

### Kernel Sources

To build a kernel, the following packages must be installed: the kernel sources (package `kernel-source`), the C compiler (package `gcc`), the GNU binutils (package `binutils`), and the include files for the C compiler (package `glibc-devel`). They are located in series D (Development). In any case, it is highly recommended to install the C compiler, since the C language is inseparable from UNIX operating systems.

The kernel sources are located in `/usr/src/linux`. If you plan to experiment with different kernels, unpack them in different subdirectories and create a symbolic link to the current kernel source. Since there are software packages that rely on the sources being in `/usr/src/linux`, you should maintain this directory as a symbolic link to your current kernel source to provide an error-free compilation of system programs that need to access the kernel sources.

### Kernel Modules

Many drivers and features no longer have to be compiled directly into the kernel, but can be loaded at run time as kernel modules. The drivers to compile into the kernel and to load as run-time modules are defined in the kernel configuration. Kernel modules are located at `/lib/modules/<Version>`, where `<Version>` is the current kernel version.

Basically, components not required for booting the system should be built as modules. This makes sure the kernel does not get too big to be loaded by the BIOS or a boot loader. Drivers for ext2, the SCSI drivers on a SCSI-based system, and similar drivers should be compiled into the kernel. In contrast, items such as isofs, msdos, or sound, which are not needed for starting your computer system, may be built as modules.

### Handling Modules

The following commands are available:

- `insmod`  
  insmod loads the requested module after searching for it in a subdirectory of `/lib/modules/(Version)`. It is better, however, to use modprobe (see below) rather than insmod.

- `rmmod`  
  Unloads the requested module. This is only possible if this module is no longer needed. For example, the isofs module cannot be unloaded while a CD is still mounted.

- `depmod`  
  Creates the file `modules.dep` in `/lib/modules/(Version)` that defines the dependencies of all the modules. This is necessary to ensure that all dependent modules are loaded with the selected ones. If `START_KERNEL` is set in `/etc/rc.config`, this file will be rebuilt each time the system is started.

- `modprobe`  
  Loads or unloads a given module while taking into account dependencies of this module. This command is extremely powerful and can be used for a lot of things (e.g., probing all modules of a given type until one is successfully loaded). In contrast to insmod, modprobe checks `/etc/modules.conf` and therefore is the preferred method of loading modules. For detailed information on this topic, refer to the corresponding man page.

- `lsmod`  
  Shows which modules are currently loaded as well as how many other modules are using them. Modules started by the kernel daemon are tagged with `autoclean`. This label denotes that these modules will automatically be removed once they reach their idle time limit.

- `modinfo`  
  Shows detailed module information.

### /etc/modules.conf

`/etc/modules.conf` affects how modules are loaded. Refer to the man page for depmod (`man depmod`).  
Enter the parameters for modules that access hardware directly in this file. Such modules may need system-specific options (e.g., CD-ROM driver or network driver). The parameters entered here are for the most part identical to those given to the boot prompt of the kernel; for example, with LILO (see Section *Kernel Parameters at the Boot Prompt* on page 240), but in many cases the names used at the boot prompt are different (to compare these, see Section *modprobe Parameters* on page 255). If a module failed to load, try specifying the hardware in this file and use modprobe instead of insmod to load the module.

### Kmod — the Kernel Module Loader

The kernel module loader is the most elegant way to use modules. Kmod performs background monitoring and makes sure the required modules are autoloaded when modprobe is run as soon as the kernel’s functionality is activated. To use Kmod, set the corresponding variable in the kernel configuration 'Kernel module loader' (CONFIG_KMOD).  
Drivers needed to access the root file system should be compiled directly into the kernel. Do not configure your SCSI driver or your file system (normally: ext2) as modules.

> **Caution**  
> As SuSE Linux uses initrd (initial ramdisk) and integrates the SCSI driver, for example, via initrd, you must make sure after compiling your own kernel that you adjust the variable `INITRD_MODULES` in the file `/etc/sysconfig/kernel` (Section *Security and Local Administration Services* on page 316) and comment out the `initrd` line in `/etc/lilo.conf` (see Section *Possible Difficulties — Self-Compiled Kernels* on page 280). If you do not do this, the kernel will hang when booted.  
> **Caution**

Kernel modules come in handy for rarely-used functionality, such as parport and printer support, drivers for floppy drives, and for certain file systems used only sporadically.
