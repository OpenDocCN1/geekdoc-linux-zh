## DEFINING A PPP CONNECTION

After setting up the name server, you can start the PPP configuration to connect to your ISP from Linux.
From the linuxconf main menu, choose Config • Networking • Client Tasks • PPP/SLIP/PLIP. Then click the Add button (see Figure 3-4).
Select the PPP option and then click Accept to continue (see Figure 3-5).

![](img/3137cdda7122042e86dbeafe9840d4ed_101_0.png)

Figure 3-4: Adding a new connection

![](img/3137cdda7122042e86dbeafe9840d4ed_101_1.png)

Figure 3-5: Adding a PPP interface

Enter your ISP's dial-up access number, your PPP log-in name, and your password (see Figure 3-6). If your ISP uses PAP Authentication, be sure to check the Use PAP Authentication box. In most cases, this completes the PPP connection setup.

NOTE: A new feature in the Red Hat version 6 release is a graphical PPP configurator, which can be accessed by clicking on Gnome Foot • Internet • Dialup Config Tool. You can use this as an alternative to the Linuxconf method, but I found in my testing that it had some bugs, so I don't recommend it.

![](img/3137cdda7122042e86dbeafe9840d4ed_101_2.png)

Figure 3-6: Defining a PPP interface

Your ISP's terminal server may present a dialog box with prompts like this (many do):

```
Welcome to Ed's Garage Internet Services

Please enter your login: <your login here>
Please enter your password: <your password here>
Starting PPP ...
```

The PPP setup just defined will work without any changes. The default behavior of the PPP connection process is to wait for the login: prompt, enter the log-in name you provide, wait for the password: prompt, and enter the password you provide. If your screen looks like this, click Accept to complete the PPP setup and exit all the way out of linuxconf to the command prompt.

## CUSTOMIZING PPP CONNECTION PROMPTS

It's quite common for ISP terminal servers to operate in the manner just described, but let's assume the dialog box looks like the one shown here instead, where you have to supply a command to enter PPP mode first and then supply a log-in name and password. And just for fun, let's assume the ISP sends a username: prompt instead of a login: prompt.

```
Welcome to the CyberSurf Domain, Dude!

Options Menu

1 - Display Help
2 - Account Information and Rates
3 - Online signup form
PPP - Start a PPP connection

Enter command: PPP

Please enter your username: <your login here>
Please enter your password: <your password here>

Starting PPP ...
```

You will need to change your PPP setup so that the order of the Expect and Send prompts matches the order and spelling of the terminal server's prompts. In this case, click the Customize button and scroll down to the "Chat" section of the page. An example that will work for the terminal dialog box that expects you to respond to the command:, username:, and password: prompts, in that order is shown in Figure 3-7.

Your goal is to match the command prompts presented by your ISP's terminal server by filling in the Expect and Send prompts on this screen accordingly. Click Accept to complete the PPP setup and exit all the way out of linuxconf to the command prompt.

## STARTING PPP

Once your setup is complete, you can make a PPP connection to the Internet by clicking on Gnome Foot • Internet • RH PPP Dialer.

When the Waiting... dialog (Figure 3-7a) is replaced by the Network Monitor (Figure 3-7b), you should be connected and ready to launch your browser, email, or other Internet applications. To verify that your Internet connection was successful, examine the output of the ifconfig command (issue it with your connection up and running), which might look like this:

```
loo
Link encap: Local Loopback
inet addr:127.0.0.1 Bcast:127.255.255.255
UP BROADCAST LOOPBACK RUNNING MTU:2000 Metric:1

ppp0
Link encap: Point-Point Protocol
inet addr:205.161.119.112 P-t-P:205.161.119.3
UP POINTOPOINT RUNNING MTU:1500 Metric:1
```

The first few lines show the status of loo, your local loopback interface. The local loopback is like your intranet—a local network that allows you to exchange email with other users on your system, access files on the local Web server, and so on. The loo device will always have an IP address of 127.0.0.1, and the status line should say UP and RUNNING.
