2. **Symptom:** you get the error message “no route to host” when you run **telnet** or **ftp**, etc.

**Cause:** (trivial) the IP address you're connecting to doesn't exist. The error message is very misleading: it has nothing to do with routing and really means your machine can't ARP the destination

**Try it:**
\ \ \ \ `ftp 10.1.1.188`
where 10.1.1.188 is an IP address that doesn't exist on your LAN. On Linux this gives:
\ \ \ \ `ftp: connect: No route to host`
and running
\ \ \ \ `telnet 10.1.1.188`
from Linux gives
\ \ \ \ `telnet: Unable to connect to remote host: No route to host`
