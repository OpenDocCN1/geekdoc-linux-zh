You use this mask just like the others we saw, except that now you have to mask individual bits instead of whole bytes. This requires a little binary arithmetic instead of just replacing a byte with a zero, but that’s not a big deal.

Let’s look at an example, using this new netmask and the same IP address we used before, 212.140.133.181. Considering the last byte only (because the others are all 255 so they work exactly as before) masking gives us $10100000 \text{ binary} = 160 \text{ decimal}$ as shown below. Therefore the complete network part is 212.140.133.160. We chose the host part to have 5 bits $= 32$ addresses, so our range is
212.140.133.160–212.140.133.191
which is what we wanted – a range to accommodate at least 25 machines.
