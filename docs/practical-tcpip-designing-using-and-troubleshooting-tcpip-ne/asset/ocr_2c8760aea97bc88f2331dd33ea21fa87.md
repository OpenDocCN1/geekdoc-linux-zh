# ### 27.4 IPsec manual keying example

![](bbox=[0.12, 0.12, 0.83, 0.27])

Table 27.1 summarizes the security association (SA) configurations on the two VPN boxes. The table shows clearly that the keys box B uses to encrypt incoming packets are the keys that box A encrypted them with when it sent them, and vice versa.

Table 27.1 Security association configurations
| | VPN box A | VPN box B |
| :--- | :--- | :--- |
| **SA name** | A-to-B | here-to-A |
| **IPsec keying mode** | manual | manual |
| **security gateway address** | 1.2.3.87 | 192.0.2.42 |
| **SPI on outgoing packets** | 5001 | 7438 |
| **encryption method** | DES | DES |
| **encrypt key** | 1111111111111111 | 3333333333333333 |
| **authentication method** | MD5 | MD5 |
| **authenticate key** | 2222222222222222 | 4444444444444444 |
| | 2222222222222222 | 4444444444444444 |
| **SPI on incoming packets** | 7438 | 5001 |
| **decrypt method** | DES | DES |
| **decrypt key** | 3333333333333333 | 1111111111111111 |
| **authentication method** | MD5 | MD5 |
| **authenticate key** | 4444444444444444 | 2222222222222222 |
| | 4444444444444444 | 2222222222222222 |

Table 27.2 shows our two very simple security policy databases (SPDs).

Table 27.2 Simple SPDs

| :--- | :--- | :--- |
| **apply this SA** | A-to-B | here-to-A |
