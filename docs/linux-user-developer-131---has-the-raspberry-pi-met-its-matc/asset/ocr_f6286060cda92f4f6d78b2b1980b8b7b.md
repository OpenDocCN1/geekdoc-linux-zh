# ## Graphical Java

I’ve just upgraded my box to the Radeon drivers, and it’s so far proved to be a good idea. The box runs smoothly now. There are some issues with Java OpenJDK, though.

How do I get it to use OpenGL? There may well be the option to use Sun’s Java, but it needs AOSS – so, either I tweak the OpenJDK to not crash and use OpenGL/acceleration; or I use Sun’s JRE, but it would involve installing OSS.

**Chris Kimpton**

You’ve going to have to use a little hack so that Java knows where it’s located. Create it with:
```
$ nano /etc/ld.so.conf.d/
javaworkaround.conf
```

...and then enter the following into it:
```
/usr/lib/jvm/java-7-openjdk-amd64/
jre/lib/amd64
/usr/lib/xulrunner-17.0
```

...and run `ldconfig` as root. Choose `/home` for the user and `/libnppj2.so` file locations. The Oracle and OpenJDK versions of Java are linked to PulseAudio, so sound-wise you’re better off using PulseAudio.

There’s some Java OpenGL packages, too, that you might want to install with:
```
$ dpkg-query --list-avail -l
‘*jogl*’
```

Hopefully that should fix things up for you.

■ When connecting remotely, some settings are different for displays

> > Open the terminal while logged in as root, and then change to another user

```
```
$ su -1 <user>
```
```

This will allow you to open another shell to log in with and then try to open the terminal. Any errors will show up in the root terminal. What may likely happen is that you cannot even load into the shell.

This is because the user will not have access to connect to the X server because you are using it via VNC. To solve this, you just need to add the relevant users to the list that are allowed to make this connection. You can do this with `xhost` by typing:

```
```
# xhost local:<user>
```
```

...as root. Give the system a reboot and it should now be working fine.
