## OVERVIEW OF UBSFS

From the previous chapters, you know that the USB host file system is part of the uscore implementation. When the uscore module is loaded into the kernel, the USB host VFS is initialized, and it is ready to be mounted in the user space. The usbfs files are generally mounted to the /proc directory. The following terminal activity illustrates the step to mount the usbfs virtual file:
```bash
root@rajaram-laptop:/proc/bus/usb# mount -t usbfs none /proc/bus/usb
```

**Tip**

> The VFS of uscore was initially referred to as usdevfs and later renamed to usbfs to avoid confusion with the devfs file system.

## Overview of usbfs

Using usbfs, a key VFS file of the Linux USB subsystem, uscore exports USB device access to the user space. In the subsequent sections, you will learn about the usbfs file tree, which can help you understand how to develop a user space driver for USB on Linux. The following terminal activity displays the usbfs tree mounted on the /proc/bus/usb root directory.

The usbfs file creates two types of files. The first file is devices, which contains the information of all USB devices in text format. The second is a set of directories and files representing the USBs and devices connected to the system. The device tree is of structure BBB/DDD, where BBB represents the USB number and DDD represents the USB device number. The following sections detail both of these files and look into usbfs applications using them.

## usbfs: devices File

Sometimes during development as a system user, you may need to know the devices that are connected to a particular USB. Tools like the viewBox provide this topological view of the USB device tree with a graphical interface. The tools retrieve this information from the devices file and present usbfs information to the user in an interactive way. The following section explains how information is represented in the devices file. The devices file of usbfs contains USB- and device-related information in text format, as discussed earlier. This text information is arranged in a particular order and includes details of the USB descriptors. Each line in the file starts with a symbol (T, B, D, P, S, C, E).

| Symbol | Description |
| :--- | :--- |
| T | This line describes device topology. This includes bus number, level in tree, port number of parent device, count of devices at this level, speed of the device, and max children |
| B | This line describes bandwidth allocation and information specific to ISO and INTR transfers. This includes total bandwidth allocated to this bus, number of interrupt requests, and isochronous requests in the particular bus |
| D | This line provides device description information. This includes USB version, class, protocol, max packet size, and number of configurations |
| P | This line describes product-related information. This includes product ID, its version, and vendor ID |
| S | This line provides product-related information as a string. This includes details of product, manufacturer, and serial number |
| C | This line provides configuration-related information. This includes active configuration, number of interfaces, configuration number, its attributes, and max |
| E | This line provides endpoint-related information. This includes information on endpoints like endpoint number, max size, its intervals, and attributes |

A complete copy of the devices file is available on the CD-ROM as devices.txt. So that you can understand the format and how to use it, the following section extracts a portion of proc_devices.txt. In the example setup, a thumb drive is connected to bus number 07. Will you now dissect the contents specific to the thumb drive from the devices file.

The first line of the text information starts with the keyword T. The text in this line indicates that the thumb drive is a high-speed device with device address 3. From the line, you can also understand that the device is connected to port 02 of bus number 07. All this information is in decimal format.

```bash
T: Bus=07 Lev=01 Prnt=01 Port=02 Cnt=01 Dev#=3 Spd=480 MxCh=0
```

The second line starts with the keyword D indicates that the line contains device descriptor information. The line indicates that the thumb drive is a USB 2.0 device with one configuration.

```bash
D: Ver=2.00 Cls=00(1) Sub=00 Prot=00 MxPS=64 #Cfgs=1
```

The subsequent line starts with the keyword P contains product-specific information. The line provides the product and the vendor ID of the thumb drive.

```bash
P: Vendor=1221 ProID=3234 Rev=00
```

The line that starts with the keyword S provides information as a string. This includes the manufacturer name, the product name, and the serial number of the device.

- S: Manufacturer=Udisk
- S: Product=Udisk 2.0
- S: SerialNumber=013CCCFFFAE5D

The next line starts with the keyword C indicates device configuration-related information. The line indicates the thumb drive. The * indicates that the current configuration is the active one.

```bash
C*: #Ifs=1 Cfg#=1 Atr=80 MxPwr=10=0mA
```

The line that starts with the keyword I indicates interface-related information. The devices interface two endpoints and a storage device. Because it is a storage device, the usb-storage module is loaded as the driver for the interface.

```bash
I*: If#=0 Alt=0 #EPs=2 Cls=08(stor.) Sub=06 Prot=50 Driver=usb-storage
```
