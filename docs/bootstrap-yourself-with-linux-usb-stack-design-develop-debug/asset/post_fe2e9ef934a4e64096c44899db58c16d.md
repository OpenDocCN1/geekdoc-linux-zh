This host controller hardware is compliant and implements universal bus (USB) host interface (HCI) specifications defined by vendors such as Intel and Compaq. The software portion of the HCI acts as an interface to the system. The host controller driver (HCD) is the lowermost layer of the USB host framework that directly interacts with the host hardware. On Linux, the HCD acts as an interface between the usbcore and the host controller hardware, allowing the layers above it to manage and communicate with the connected device.

This chapter explores the Linux USB HCD framework that is essential for developers to bring up the host controller. It begins by discussing the essential data structures and interface functions of the Linux USB HCD. Then it explores the functional modules of the HCD and the sequence of activities that occurs inside the HCD. It concludes with a sample implementation of HCD.

# Bootstrap Linux USB HCD

The HCD framework implements a driver for USB host controllers and interfaces required by the Linux usbcore framework. The HCD framework also integrates the USB host controller to the platform and includes necessary functionality. Most of the HCDs are developed based on platform driver. Check out Chapter 12, “Peripheral Device Controller,” to understand the basics of the platform framework. This section explores the HCD data structures and methods.

The essential data structures for the HCD are `struct hc_driver` and `struct usb_hcd`, which are defined in include/linux/usb/hcd.h.

The `struct hc_driver` structure has methods that serve as an interface between the usbcore and the HCD. The data structure also contains members to describe the driver and the product.

```c
struct hc_driver {
    const char *description;
    const char *product_desc;
    size_t hcd_priv;
}
```

The HCD uses the `irq` variable to register its interrupt request (IRQ) handler.

```c
irq_t (*irq)(struct usb_hcd *hcd);
```

The `flags` member holds information on the version of USB that the HCD holds.

```c
int flags;
```

These interface methods initialize the HCD and the root hub drivers, generally resetting the host controller hardware.

```c
int (*reset)(struct usb_hcd *hcd);
int (*start)(struct usb_hcd *hcd);
```

This interface method allows the host functionality generally invoked by the uscore when the HCD is removed.

```c
void const (*stop)(struct usb_hcd *hcd);
```

This interface method powers down the host controller and is invoked as part of the platform driver's shutdown operation. The HCD framework provides `usb_hcd_platform_shutdown` as the wrapper function.

This interface method gets the frame number required during isochronous (ISO) transactions. The HCD framework provides the wrapper function `usb_get_current_frame_number` to invoke this function.


These interface functions manage the input/output (I/O) requests. The HCD framework provides `usb_hcd_submit_urb` and `usb_hcd_unlink_urb` methods for enqueue and dequeue, respectively.

```c
int (*urb_enqueue)(struct usb_hcd *hcd,
    struct urb *urb, gfp_t mem_flags);
int (*urb_dequeue)(struct usb_hcd *hcd,

```

This interface method synchronizes with the HCD to ensure the endpoint state is freed from the hardware. The HCD framework provides the `usb_hcd_disable_endpoint` interface method to use this callback. Call `usb_hcd_flush_endpoint` before disabling the endpoint.
