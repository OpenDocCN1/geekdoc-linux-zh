

# 第 18 章 使用 Linux USB 进行调试

![](img/779a74a6577501a55983f193067274a3_280_0.png)

**图 18.5** usbmon 的 URB 挂钩序列。

usbcore 在 `urb.c` 中使用 `usb_submit_urb`。在更新 URB 结构以包含额外信息后，URB 被传递给 usbcore 的 `hcd.c`。现在 URB 已完成，并准备好通过 `usb_hcd_submit_urb` 函数提交给主机控制器驱动。一旦 URB 到达 `usb_hcd_submit_urb`，就会调用包装器 `usbmon_urb_submit`。如果 usbmon 注册了它的回调接口，包装器将带有 URB 信息调用回调函数。

usbmon 模块会根据 usbcore 中可用的 USB 总线数量创建对应文件。文本模式会根据总线编号创建两个带有后缀 `u` 或 `t` 的文件。以 `t` 后缀的文件是已弃用的版本，而 `u` 后缀的文件包含更多细节，例如等时事务。你需要挂载 usbmon VFS 来查看这些文件，如下一节“如何使用 usbmon”所解释的那样。

usbmon 为用户扩展了三个主要文件操作：`open`、`read` 和 `release`，以便用户获取内核部分捕获的 URB 数据。

图 18.6 展示了当用户空间与 usbmon 模块交互时发生的动作序列。从图中可以推断，用户空间应用程序打开一个 usbmon 文件（可能是 `0u`），此时内部注册的打开文件操作（`mon_text_open`）被调用。操作处理句程序使用 `mon_reader_add` 为 usbmon 添加了文本读取器回调。这开始了在 `struct read` 操作中排队后续 URB 活动的过程，随后从用户空间应用程序中出队（dequeues）URB 活动并将其呈现给用户应用程序。当 URB 事件列表为空时，用户应用程序进程被添加到等待队列中，直到下一次 URB 事务发生。到为止，之前的章节重点关注了 usbmon 如何与其他模块交互。接下来的章节将探索如何使用 usbmon 来捕获 USB 事务。

# 如何使用 usbmon

usbmon 模块负责在初始化期间设置 USB 调试框架的根目录。它使用 `debugfs` 基础设施为 usbmon 初始化框架。usbmon 文件相对于其根路径。当你挂载 `debugfs` 时（例如在 `/sys/kernel/debug` 中），usbmon 文件可能位于 `/sys/kernel/debug/usbmon/` 目录下。因此，为了让 usbmon 正常工作，构建内核时需要包含 `debugfs` 模块。

因此，你需要挂载 `debugfs` 文件系统来查看 usbmon 文件。通常，它被挂载到 `/sys/kernel/debug`。以下终端活动显示了在加载 usbmon 模块之前如何挂载 debug 文件系统及其初始目录内容。

```
root@rajaram-laptop:~# mount -t debugfs none_debugs /sys/kernel/debug
root@rajaram-laptop:~# cd /sys/kernel/debug/
root@rajaram-laptop:~# ls /sys/kernel/debug#
kprobes
root@rajaram-laptop:~# /sys/kernel/debug#
```

在确保成功挂载 debug 文件系统后，你就可以将 usbmon 模块插入内核了。在成功 `modprobe usbmon` 后，该模块会为内核注册的每个 USB 总线创建 usbmon 文件。以下终端活动显示了成功插入 usbmon 模块后 usbmon 目录的内容。

```
root@rajaram-laptop:/sys/kernel/debug# modprobe usbmon
root@rajaram-laptop:/sys/kernel/debug# cd usbmon/
root@rajaram-laptop:/sys/kernel/debug/usbmon# ls
0 1s 1u 2t 3s 3u 4t 5s 5u 6t 7s 7u
0u 1t 2s 2u 3t 4s 4u 5u 6s 6u 7t
root@rajaram-laptop:/sys/kernel/debug#
```

在 Linux 中，USB 总线编号从 1 开始，usbmon 创建以总线号为前缀来捕获特定 USB 总线上的 URB 事务。usbmon 还会创建一个以 0 (`0u`) 前缀的文件来捕获所有总线的 URB 事务。要捕获连接设备的事务，你应该知道设备连接到哪个总线。要确定总线连接，你可以使用 `lsusb` 或查看由 usbfs 导出的设备，通常在 `/proc/bus/usb/devices` 中。在示例设置中，ID 为 1221:3234 的设备是有感兴趣的设备，`lsusb` 列出了设备列表以及总线号。

```
root@rajar-laptop:~# lsusb
Bus 007 Device 003: ID 1221:3234
Bus 007 Device 001: ID 0000:0000
Bus 006 Device 002: ID 064e:a103
Bus 006 Device 001: ID 0000:0000
Bus 005 Device 001: ID 0000:0000
Bus 004 Device 001: ID 0000:0000
Bus 003 Device 001: ID 0000:0000
Bus 002 Device 001: ID 0000:0000
Bus 001 Device 001: ID 0000:0000
```

示例连接的设备是连接到 USB 总线 7 的存储设备。要捕获大存储设备的 USB 事务，你可以编写一个简单的应用程序来读取并显示信息，或者使用 `cat` 命令将文件重定向到日志。在下面的终端活动中，感兴趣的设备连接到总线 7 并重定向到 `usbmog.txt`。

```
root@rajar-laptop:/sys/kernel/debug#
root@rajar-laptop:/sys/kernel/debug# cat 7u >usbmog.txt
root@rajar-laptop:/sys/kernel/debug#
```

你可以按照自己的节奏分析 `usbmog.txt` 中捕获的 URB 信息。随附的是完整日志文件。为了方便分析，只查看捕获大存储设备的日志部分。该片段包含了 Linux 主机和大存储设备之间发生的一些控制和批量事务。

如果你查看后续日志，可以将日志文件的第一行解释为针对总线 7 端点 0 的 `CONTROL` 传输。这是到 USB 地址 5 设备的控制传输。第二行捕获状态为 0 的 `SET_ADDRESS` URB 完成。

```

d2263a80 2613001276 C:7:0000:0
d2263a80 2613121192 S C:7:0005:0 80 06 0100 0000 0012 18 <
d2263a80 2613121399 C:7:0005:0 18 = 12010002 0000040 2112342 0006102 | 0301
```
