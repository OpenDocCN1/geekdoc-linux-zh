The composite driver module registers the struct usb_composite_driver to the composite framework. The composite framework in turn registers to the gadget framework for further activity; a similar sequence is followed when unregistering.

The next sequence of activity triggered after a successful registration is of the driver with the gadget driver. With a composite driver, the bind callback adds the composite driver configuration to the composite framework, as shown in Figure 14.7.

The configuration then binds the functions it intends to support using add_function, as illustrated in Figure 14.8.

Once the functions are added successfully, the device is ready for enumeration of the composite driver. The host decides which configuration to choose from the composite driver.
