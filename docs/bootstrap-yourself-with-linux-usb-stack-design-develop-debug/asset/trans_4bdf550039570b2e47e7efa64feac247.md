# 使用 UBSFS_SNOOP 进行调试

上一节讨论了 usbmon，这是一种低级工具，用于捕获 USB 流中通过 URB 事务，以便使用 Linux 调试 USB 系统。有时，调试 Linux USB 子系统并不需要如此详细的信息。这为 Linux 上提供的另一种更简单的方法铺平了道路，该方法可以嗅探 USB 事务。usbfs_snoop 是作为 uscore 的可用的一种调试机制，它可以在 USB 事务的更高层级嗅探 USB 数据，并将其作为系统日志的一部分打印出来。

功能是 usbcore 的一部分，图 18.9 在 usbcore 之外展示了该功能，以便更好地表示它 usbfs 和 usbcore 之间的作用。

在 uscore 中，`/drivers/usb/core/devio.c` 文件实现了 usbfs 文件操作，这是 usbfs_snoop 嗅探 URB 操作和 URB 状态的理想位置。在 `devio.c` 中实现的 `snoop_urb` 例程处理了这种嗅探活动。

```c
static void snoop_urb(struct usb_dev *udev, void *buffer, int pipe, unsigned long length, int timeout, enum snoop_status)
```

uscore 模块在 devio.c 中定义了模块参数 `static int usbfs_snoop;`。该模块允许用户在运行时配置配置和控制 usbfs_snoop 功能。要配置此 usbfs_snoop 参数，用户应拥有相应的权限来更新参数文件。

```c
static int usbfs_snoop;
module_param(usbfs_snoop, bool, S_IRU | S_IW);
MODULE_PAR_DESC(usbfs_snoop, "true to log all usbfs traffic");
```

通常，Linux 将其模块参数导出为文件，使用户可以在用户空间访问它们。该模块参数声明为 usbcore 的一部分，你可以在 `/sys/module/usbcore/parameters/` 中找到该参数。下面的终端显示了 uscore 模块的参数。

```bash
root@laptop:~ ls /sys/module/usbcore/parameters/
-rw-r--r-- 1 root 4096 May 28 autospend
-r----r-- 1 root 4096 May 28 lights
-r----r-- 1 root 4096 May 28 usb
-r----r-- 1 root 4096 May 28 old_scheme
-r----r-- 1 root 4096 May 28 usbfs_snoop
-r----r-- 1 root 4096 May 28 use_both_schemes
root@laptop:~ 
```

在早前的讨论中，你看到 usbfs_snoop 模块参数充当标志来控制嗅探调试信息。snoop 标志可以持有 true (1) 或 false (N)。下面的终端说明了如何读取 usbfs_snoop 参数的值并解释了如何配置它。要了解标志的当前状态，你可以在参数文件上运行 `cat` 命令。

```bash
root@laptop:~ cat /sys/module/usbcore/parameters/usbfs_snoop
```

要配置此 usbfs_snoop 参数，用户可以在参数文件上运行 `echo` 命令如下所示。

```bash
root@laptop:~ echo 1 > /sys/module/usbcore/parameters/usbfs_snoop
root@laptop:~ cat /sys/module/usbcore/parameters/usbfs_snoop
```

一旦设置标志，URB 信息就会被嗅探，你就可以准备收集内核日志的一部分调试数据。

注意

usbmon 和 usbfs_snoop 的主要区别在于，前者捕获内核和 uscore 之间的 URB 信息，而后者捕获用户应用程序和 uscore 之间的 URB 信息。另一个重要的点是，除非有用户文件操作，否则 usbfs_snoop 不会在枚举期间捕获 URB。要使用 usbfs_snoop 触发 URB 嗅探，你可以执行简单的实验，例如 `lsusb -v`，如下所示。


# 主机端 USB 的详细调试

详细调试方法并非 USB 子系统专用，但它是内核开发人员用于调试的一种更传统的方法。在这种方法中，调试信息由 DEBUG 宏控制，模块仅在调试模式下打印调试信息。在发布模式下，该宏被禁用，不会打印调试信息。USB 子系统详细消息是 Linux 上用于调试 USB 子系统的一种可用选项。你可以通过内核配置宏配置详细调试消息。图 18.10 展示了如何启用详细调试选项。USB 调试消息选项主要在 Linux 子系统的 USB 核心和集线器驱动程序的源码中交替生成调试消息。

有时需要在 uscore 的初始枚举过程中生成调试信息以隔离问题，因为 usbmon 还是 usbfs_snoop 无法覆盖这一点。例如，初始 USB 设备设置是通过 uscore 的集线器层完成的，这需要更具信息的调试消息来隔离错误。
