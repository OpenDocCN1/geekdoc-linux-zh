The device information in the devices file is organized sequentially like a descriptor tree because most of its information is collected from the device's descriptors. The bus and device information is placed hierarchically.

# Application Based on the device File

To better present information in the devices file to the user, interactive applications are available on Linux. There is a graphical application (USBView) and a simple command-line script (usbtree) that presents the information in a more readable format. You'll learn how to set up these tools in your system and how to use them in the following sections.

# Graphical User Interface: USBView

USBView displays the devices file graphically and presents the USB device topology of the Linux system. You can install USBView on the system from http://www.kroa.com/linux-usb/ or use apt-get install usbview or similar package installer options.

After a successful installation, you can invoke USBView through the command line in super mode or ensure that the user invoking the USBView has proper access levels. Also, for the tool to work properly, you must mount the ubsfs file system in the standard path. If the path is different, configure the tool with the mount path, as illustrated in Figure 16.3.

Once the devices file path is configured, USBView provides the topological view of the USB devices in the system with device-related information.

# Command Line: usbtree

Traditional Linux users prefer command-line tools to work with a graphical interface. To list the USB device topology on the command line, you can use the usbtree script. You can download the script, written using PERL, from http://www.linux-usb.org/usbtree. For the script to work properly, ensure that the PERL package is properly installed in your system.

# usbfs: BBB/DDD Files

The next files are the BBB/DDD files of the usbfs, which control and interact with a USB device. This directory tree is created based on the USB number (BBB) and the USB device number (DDD). Unlike the standard device file, these files allow for more granular control. The following terminal activity shows the structure of the usbfs directory:

```
/proc/bus/usb/007/002
```

The files in the BBB/DDD directory include:
- configuration: Contains the configuration descriptor.
- interface: Contains the interface descriptor.
- endpoint: Contains the endpoint descriptor.

By interacting with these files, applications can query the state of the device or trigger actions. For example, writing to a specific file might trigger a reset, though this is often restricted to root users.
