The .htaccess contains Apache configuration directives enforced each time a request connects from the directory where the .htaccess file is stored. These directives are recursive, expanding the scope to all subdirectories.

Most of the directives that can occur in a Directory block are also in .htaccess file. The AllowOverride directive lists all the options that can be enabled or disabled by way of .htaccess. A common use of this is to restrict ExecCGI, so the administrator chooses which users are allowed to run programs under the web server's identity (www-data user).

# Example 5.3 .htaccess File Requiring Authentication

```
Require valid-user
AuthName "Private directory"
AuthType Basic
AuthUserFile /etc/apache2/auth/passwd-private
```

The authentication system used in the example (Basic) has minimal security as the password is in clear text (it is only encoded as base64, which is a simple encoding rather than an encryption method). It should also be noted that documents protected by this mechanism also go over the network. If security is important, the entire HTTP session should be encrypted with Transport Layer Security (TLS).

The /etc/apache2/auth/passwd-private file contains a list of users and passwords; it is commonly manipulated by the htpasswd command. For example, the following command is used to add a user or change their password:

```
# htpasswd /etc/apache2/auth/passwd-private user
New password:
Re-type new password:
Adding password for user user
```

Restricting Access The Require directive controls access restrictions for a directory (and its subdirectories, recursively).

It can be used to restrict access based on many criteria; we will stop at access restriction based on the IP address of the client but can be much more powerful than that, especially when Require directives are combined with RequireAll block.

For instance, you could restrict access to the local network with the following directive:

```
Require ip 192.168.0.0/16
```
