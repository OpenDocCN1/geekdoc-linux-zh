
Two particular rights are relevant to executable files: setuid and setgid (symbolized with the letter "s"). Note that we frequently speak of bit, each of these boolean values can be represented by a 0 or a 1. These two rights allow any user to execute the program with the rights of the owner or the group, respectively. This mechanism grants access to features requiring higher permissions than that you would have.

## setuid and setgid executables

A setuid root program is systematically run under the super-user identity, it is very important to ensure it is secure and reliable. Any user who manages to subvert a setuid root program to a command of their choice could then impersonate the root user and have all rights on the system. Penetration testers regularly search for these types of files when they gain access to a system as a way of escalating their privileges.

A directory is handled differently from a file. Read access gives the right to consult the list of its contents (files and directories); write access allows creating or deleting files; execute access allows crossing through the directory to access its contents (for example, with the cd command). Being able to cross through a directory without being able to read it if the entries therein are known by name, but not to find them knowing their exact name.

The setgid bit applies to directories. Any newly-created item in such directories is automatically assigned the owner group of the parent directory, instead of inheriting the creator’s group as usual. Because of this, you don’t have to change your main group (with the group command) when working in a file tree shared between several users of the same dedicated group.

> The sticky bit (symbolized by the letter "t") is only useful in directories. It is especially useful for temporary directories where everybody has access (such as /tmp/); it restricts deletion of files so that only their owner or the owner of the parent directory can delete them. Lacking this, everyone could delete other users' files in /tmp/.

Three commands control the permissions associated with a file:

- chown user file changes the owner of the file
- Changing the user and group: chown user:group file
- chgrp group file alters the owner group
- chmod rights file changes the permissions for the file

There are two ways of representing rights. Among them, the symbolic representation is probably the easiest to understand and remember. It involves the letter symbols mentioned above. You can define rights for each category of users (u/g/o), by setting them explicitly (with =), by adding (+), or subtracting (-). Thus u=rw,g+rw,o gives the owner read, write, and execute rights, adds read and write rights for the owner group, and removes rights for other users. Rights not altered by the addition or subtraction in a command remain unmodified. The letter a, for all, covers all categories of users, so that a-rx grants all three categories the same rights (read and execute, but not write).

The (octal) numeric representation associates each right with value: 4 for read, 2 for write, and 1 for execute. We associate each combination of rights with the sum of the three figures, and a value is assigned to each category of users, in the user order (owner, group, others).

For instance, the chmod 754 file will set the following rights: read, write and execute for the owner (since 5 = 4 + 2 + 1); read-only for others. The 0 means nothing; thus chmod 600 allows read and write permissions for the owner, and no rights for anyone else. The most frequent rights are 755 for executable files and directories, and 644 for data files.

To represent special rights, you can prefix a digit to this number according to the same principle, which the setuid, setgid, and sticky bits are 4, 2, and 1. The command chmod 4754 associates the setuid bit with the previously described rights.

Note that the use of octal representation only allows you to set all the rights at once on a file; you cannot add it a new right, such as read for the group owner, you must take into account the existing rights and compute the new corresponding numerical value.

The octal representation is also used with the mask command, which is used to restrict permissions on newly created files. When an application creates a file, it assigns indicative permissions, knowing that the system automatically removes the rights defined with umask. Enter umask in a shell; you will see a mask such as 0022. This is simply an octal representation of the rights to be systematically removed (in this case, the write rights for the group and other users).

If you give it a new octal value, the chmod command modifies the mask. In a shell initialization file (for example, ~/.bash_profile), it will effectively change the default mask for your work sessions.

| Sometimes we have to change rights for an entire file tree. The commands above have a -R option to operate recursively in sub-directories |

### Recursive operation
The distinction between directories and files sometimes causes problems with recursive operations. That is why the "X" letter has been introduced in the symbolic representation of directories. It represents a right to execute which applies only to directories (and not to files lacking this right). Thus, chmod -R +X directory will only add execute rights for all categories of users (a) for all of the sub-directories and files for at least one category of user (even if their sole owner) already have execute rights.

The uname -a returns a single line documenting the kernel name (Linux), the hostname, the kernel release, the kernel version, the machine type (an architecture such x86_64), and the name of the operating system (GNU/Linux). All these commands provide run-time information, but when you need logs to understand what happened on your computer. In particular, the kernel emits messages that it stores in a ring buffer whenever interesting happens (such as a new USB device being inserted, a failing disk operation, or hardware detection on boot). You can retrieve the kernel logs with dmesg.

Systemd's journal also stores multiple logs (stdout/stderr output of daemons, syslog messages, kernel logs) and makes it easy to query them with journalctl. Without any arguments, it dumps all the available logs in a chronological way. With the -r option, it will reverse the order that newer messages are first. With the -f option, it will continuously print new log entries as they are appended to the database. The -u option can limit the messages to those emitted by a specific system unit (ex: journalctl -u ssh.service).

## 3.4.6. Discovering the Hardware

The kernel exports many details about hardware through the /proc/ and /sys/ virtual filesystems. Several tools summarize these details. Among them lspci (in the pciutils package) lists PCI devices, lsusb (in the usbt package) lists USB devices, and lspcmia (in the pciutils package) lists PCMCIA cards. These tools are very useful for identifying the exact model of a device. identification allows more precise searches on the web, which can lead to relevant documents. Note that the pciutils and usbt packages are already installed on the base Kali system but must be installed with apt install pciutils. We will discuss more about package installation and management in a later chapter.
