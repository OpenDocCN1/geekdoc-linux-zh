
## 5.4. Managing Services

Kali uses systemd as its init system, which is not only responsible for the boot sequence, but also permanently acts as a full featured service manager, starting and monitoring services.

systemd can be queried and controlled with systemctl command. Without any argument, it runs the systemctl list-units command, which outputs a list of the active units. If you run systemctl status, the output shows a hierarchical overview of the running services. Comparing both outputs, you immediately see that there are multiple kinds of units and services that are only one among them.

Each service is represented by a service unit, which is described by a service file usually shipped in /lib/systemd/system/, or /run/systemd/system/, or /etc/systemd/system/; they are listed by increasing order of importance, and the last one. Each is possibly modified by service-name.*.conf files in the set of directories. These units are plain text files whose format is inspired by the well-known *.ini files of Microsoft Windows, with value pairs grouped between [section] headers. Here we see a sample service file for /lib/system/ssh.service:

[Unit]
```
Description=Secure Shell server
After=network.target audit.service
ConditionPathExists=!/etc/ssh/sshd_not_to_be_run
```

[Service]
```
Environment=/etc/default/ssh
ExecStart=/usr/sbin/sshd -D $SSHD_OPTS
ExecReload=/bin/kill -HUP $MAINPID
KillMode=process
Restart=on-failure
RestartPreventExitStatus=255
Type=notify
```

[Install]
```
WantedBy=multi-user.target
Alias=sshd.service
```

Target units are another part of systemd's design. They represent a desired state that you want to attain in means activated units (which means a running service in the case of units). They exist mainly as a way to group dependencies on other units. When the system starts, it enables the units to reach the default.target (which is a symlink to graphical.target, and which in turn depends on multi-user.target). So all the dependencies of those targets get activated during boot.

Such dependencies are expressed with the Wants on the target. But you don't have to edit the target unit to add new dependencies, you can create a symlink pointing to the dependent unit in the /etc/systemd/system/target-name.target.wants/ directory. And this is exactly systemctl enable foo.service does. When you enable a service, you tell system to add a dependency on the targets listed in the WantedBy entry of the [Install] section of the service unit file. Conversely, systemctl disable foo.service drops the symlink and thus the dependency.

The enable and disable commands change nothing regarding the current status of the services. They only influence what will happen at next boot. If you want to run the service immediately, you should execute systemctl start foo.service. You can also inspect the current status of a service with systemctl status foo.service, which usefully includes the latest lines of the associated log. After having changed the configuration of a service, you may wish to reload or restart it: those operations are done with systemctl reload foo.service and systemctl restart foo.

## 5.5. Summary

In this chapter, we learned how to configure Kali Linux. We configured network settings, talked about users and groups, and discussed how to create and modify user accounts, set passwords, disable accounts, and manage groups. Finally, we discussed services and explained how to set up and maintain generic services, specifically SSH, PostgreSQL, and Apache.

Summary Tips:

- * In a typical desktop installation, you will have NetworkManager already installed and it can be controlled and configured through GNOME's control center and through the top-right menu.
- * You can configure the network from the command line using ifup and ifdown tools, which read their instructions from the /etc/network/Interfaces file. An even newer tool, systemd-network works with systemd init system.
- * By default, the database of users and groups consists of the files /etc/passwd (list of users), /etc/shadow (encrypted passwords of users), /etc/group (list of groups), and /etc/gshadow (encrypted passwords of groups).
- * You can use getent command to control the user database and other databases.
- * The adduser command asks a few questions before creating the account, which is a straightway to create a new user.
- * Several commands can be used to modify specific fields in the user database including: passwd (change password), usermod (change name and the GCOS field), chsh (change login shell), passwd -e (forces the user to change their password the next time they log in).
- * Each user can be a member of multiple groups. Several commands can be used to modify identity: newgrp changes the current group, setgid can be placed on a device, files created in that directory to automatically belong to the correct group. In addition, id command displays the current state of user membership.
- * You can manually start SSH with systemctl start or permanently enable it with systemctl enable which disables password-based logins for the root user, you must first setup SSH keys with sshkeygen.
- * PostgreSQL is a database server. It is rarely useful on its own but used by many others to store data.
- * A typical Linux installation includes the Apache web server. Being a network service, it is disabled by default. You can manually start it with systemctl start2.
- * With its default configuration, Apache listens on port 80 (as configured in /etc/apache2/ports.conf), and serves pages from the /var/www/html/ directory by default (as configured in /etc/apache2/sites-enabled/000-default.conf).
