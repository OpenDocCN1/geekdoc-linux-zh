#  8.3.1. Configuring APT

Before we dive into the configuration of APT, let's take a moment to discuss the configuration mechanism of the Debian system. Historically, configuration was handled by dedicated configuration files. However, in Linux systems like Debian and Kali, configuration directories with the .d suffixes are becoming more common. Each directory represents a configuration file that is split into multiple files. In this sense, all of files in /etc/apt/conf.d/ are instructions for the configuration of APT. APT processes the files in alphabetical order, so that the later files can modify configuration elements defined in the earlier files.

This structure brings some flexibility to administrators and package maintainers, allowing them to make software configuration changes through files without having to change an existing file. This is especially helpful for package maintainers because they can use this approach to adapt the configuration of other software to ensure that it perfectly co-exists with theirs, without breaking the Debian policy that explicitly forbids modifying files of other packages. Because of the .d configuration mechanism, you don't have to manually follow multiple package configuration instructions typically found in the package's /usr/share/doc/README.Debian file, since the installer can drop in configuration files.

> While APT has its use of /etc/apt/conf.d directory, this is not always the case. For some applications (like fim, for example), the .d directory is Debian-specific added used as input to dynamically generate the configuration file used by apt. In these cases, the packages provide an "update-* command (example: update-ext.conf) that will concatenate the files from the .d directory and overwrite the main configuration file. In those cases, you must not manually edit the main configuration file as your changes will be lost on the next execution of the update-* command, and you must not forget to run the former command after editing a file out of the .d directory (or your changes will not be used).
