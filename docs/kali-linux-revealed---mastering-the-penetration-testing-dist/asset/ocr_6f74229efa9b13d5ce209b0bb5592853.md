# Dealing with Outdated .config Files

When you provide a .config file that has been generated with another (usually older) kernel version, you will have to update it. You can do so with make oldconfig, which will interactively ask you the questions corresponding to the new configuration options. If you want to use the default answer to all those questions, you can make oldconfig. With make nooldconfig, it will assume a negative answer to all questions.

# 9.2.4. Compiling and Building the Package

# Clean Up Before Rebuilding

If you have already compiled a kernel in the directory and wish to rebuild everything from scratch (for example because you substantially changed the kernel configuration), you will have to run make clean to remove the compiled files. make distclean removes more generated files, including your .config file, so make sure to back it up.

Once the kernel configuration is ready, a simple make deb-pkg will generate up to five Debian packages in .deb format: linux-image-version, which contains the kernel image and the associated modules; linux-headers-version, which contains the header files required to build kernel modules; linux-firmware-image-version, which contains the firmware files needed by some drivers (this package might be missing when you build from the kernel sources provided by Debian or Kali); linux-image-dbg, which contains the debugging symbols for the kernel and its modules; and linux-libdev, which contains headers relevant to some user-space libraries like GNU's C library (libc).

The version is defined by the concatenation of the upstream version (as defined by VERSION, PATCHLEVEL, SUBLEVEL, and EXTRAVERSION in the Makefile), of the LOCALVERSION configuration parameter, and of the LOCALVERSION environment variable. The package version uses the same string with an appended revision that is regularly incremented (and stored in .version), except you override it with the KPKGVERSION variable

```
$ make deb-pkg LOCALVERSION=$custom deb_PKGVERSION=$(make kernelversion)-1
```
