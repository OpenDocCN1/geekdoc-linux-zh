This requires critical review of the target environment along with manual searching, creativity, and outside-the-box for indications of a successful attack.

In a more complex scenario, an application assessment can be conducted interactively in either a black or white box manner:

- Black Box Assessment: The tool (or assessor) interacts with the application with no special knowledge or access beyond that of a standard user. For instance, in the case of a web application, the assessor may only have access to the functions and features that are available to a user that has not logged into the system. Any user accounts used would be ones where a general user can self-register the account. This would prevent the attacker from being able to review any functionality that is only available to users that need to be created by an administrator.
- White Box Assessment: The tool (or assessor) will often have full access to the source code, administrative access to the platform running the application, and so on. This ensures a full and comprehensive review of all application functionality is completed, regardless of where functionality lives in the application. The trade-off with this is that the assessment is in no way a simulation of malicious activity.
