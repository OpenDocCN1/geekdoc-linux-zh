# 9.4.2. Setting Up Unencrypted Persistence on a USB Key

In this section, we assume that you have prepared a Kali Live USB Key by following the instructions at section 2.1.4,"Copying the Image on a DVD-ROM or USB Key" [page 19] and that you have used a USB key big enough to hold the ISO image (roughly 3 GB) and the data of the directories that you want to persist. We assume that the USB key is recognized by Linux as /dev/sdb and that it only contains the two partitions that are part of the default ISO image (/dev/sdb1 and /dev/sdb2). Be careful when performing this procedure. You can easily destroy data if you re-partition the usb key.

To add a new partition, you must know the size of the image that you copied so after the live. Then use parted to actually create the partition. The commands below analyze the ISO image name kali-linux-2016.1-amd64.iso, which is assumed to be present on the USB key as well:

```
# parted /dev/sdb print
Model: SanDisk Cruiser Edge (scsi)
Disk /dev/sdb: 32,GB
Sector size (logical/physical): 512B/512B
Partition Table: mdos
Disk Flags:

Number Start End Size Type File system Flags
1 32,8KB 2852MB 2852MB primary boot, hidden
2 2852MB 2945MB 93,4KB primary
# start=\$(du --block-size=1MB kali-linux-2016.1-amd64.iso | awk '{print $1}')
# echo "Size of image is $start MB"
Size of image is 2946 MB
# parted -a optimal /dev/sdb mkpart "${start}MB" 100%
Information: You may need to update /etc/fstab.
```
