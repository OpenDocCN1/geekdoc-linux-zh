## 4.3.1. Preseeing Answers

There are multiple ways to preseed answers to the installer. Each method has its own advantages and disadvantages. Depending on when the preseeing happens, the questions that can be preseeded vary.

### With Boot Parameters

You can preseed any installer question with boot parameters that end in the kernel command line, accessible through `/proc/cmdline`. Some bootloaders will let you edit these parameters interactively (which is practical for testing purposes), but if you want to make the changes persistent, you will have to modify the bootloader configuration.

You can directly use the full identifier of the debconf question (such as debian-installer/language=en) or you can use abbreviations for the most common questions (like language=en or hostname=duke). See the full list of aliases in the Debian installation manual.

There is no restriction on which questions you can preseed since boot parameters are available from the start of the installation process and they are processed very early. However, the number of boot parameters is limited to 32 and a number are already used by default. It is important to realize that changing the boot loader configuration can be non-trivial at times.

In section 9.3, "Building Custom Kali Live Images" [page 237] you will also learn how to modify the Ininusux configuration when you generate your own Kali ISO image.

### With a Preseed File in the Initrd

You can add a file named .cfg at the root of the installer's initrd (this is the initrd which is used to start the installer). Usually, this requires rebuilding the debian-installer source package to generate new versions of the initrd. However, live-build offers a convenient way to do this, which is detailed in section 9.3, "Building Custom Kali Live Images" [page 237].

This method also does not have any restrictions on the questions that you preseed as the preseed file is available immediately after boot. In Kali, we already make use of this feature to customize the behavior of the official Debian installer.

> https://www.debian.org/releases/amd64/apbs02#preseed-aliases

### With a Preseed File in the Boot Media

You can add a preseed file to the boot media (CD or USB key); preseeding then happens as soon as the media is mounted, which means right after the questions about language and keyboard layout. The preseed/file boot parameter can be used to indicate the location of the preeding file (for instance, /cdrom/preseed.cfg when installing on a CD-ROM, or /hd-media/preseed.cfg when installing on a USB-key).

You may not preseed answers to language and country options as the preseeding file is loaded later in the process, once the hardware drivers have been loaded. On the positive side, live-build makes it easy to put a supplementary file in the generated ISO images (see section 9.3, "Building Custom Kali Live OS Images" [page 237]).

### With a Preseed File Loaded from the Network

You can make a preseed file available on the network through a web server and tell the installer to download preseed file by adding the boot parameter preseed=http://server/preseed.cfg (or by using url alias).

However, when you use this method, remember that the network must first be configured. This means that network-related debconf questions (in particular hostname and domain name) and all the preceding questions (like language and country) cannot be proceeded with this method. This method is most often used in combination with boot parameters preseeding those specific questions.

This preseeding method is the most flexible one you can change the installation configuration without changing the installation media.

| Delaying the Language, Country, Keyboard Questions | To overcome the limitation of not being able to pre the language, country, and keyboard questions, you can add the boot parameter auto-install=enable-true (or auto=true). With this option will be asked later in the process, after the network has been configured and after download of the preseed file. |

The downside is that the first steps (notably network configuration) will always happen in English and if there are errors the user will have to work through English screens (with a keyboard configured in QWERTY).

## 4.3.2. Creating a Preseed File

A preseed file is a plain text file in which each line contains the answer to one Debconf question. A line is split across four fields separated by white space (spaces or tabs). For instance, d-i/suite string kali-rolling;

- The first field indicates the owner of the question. For example, “d-i” is used for questions relevant to the installer. You may also see a package name, for questions coming from De-bian packages (in this example: atftpd atftpd/use_inetd boolean false).

- The second field lists an identifier for the question.

- The third field lists the type of question.

- The fourth and final field contains the value for the expected answer. Note that it must be separated from the third field with a single space; additional space characters are considered of the value.

The simplest way to write a preseed file is to install a system by hand. Then the debconf-selections --installer command will provide the answers you provided to the installer. You can obtain answers directed to other packages with debconf-selections. However, a cleaner solution is to write the preseed file by hand, starting from an example and then going through the documentation. With this approach, only questions where the default answer needs to be overridden can be preseeded. Provide the priority–critical.

## 4.4. ARM Installations

Kali Linux runs on variety of ARM devices (laptops, embedded computers, devel-boards, for example) but they often have specific requirements of boot configuration. To make those devices more accessible to Kali, Offensive Security developed scripts are ready for use. They provide images for:

> https://github.com/offensive-security/kali-arm

Since these images are available, your task of installing Kali on ARM device is greatly simplified. Here are the basic steps:

- Download the image for your ARM device and ensure that the checksum matches the one provided on the website for how to do.

- Depending on the storage expansion slot available on your ARM device, acquire an SD card, micro card, or eMMC module that has a capacity of 8 GB.

- Copy the downloaded image to the storage device with dd. This is similar to the process of copying an ISO onto a USB key.

```bash
dd if=kali-image.img of=/dev/sd=512k
```

- Plug the SD-card/eMMC into your ARM device.

- Boot your ARM device and log into it ("root" or "toor"). If you don't have a screen connected, you will have to figure out the IP address that has been assigned by DHCP and connect to address over SSH. Some DHCP servers have tools or web interfaces show the current leases. If you don't have anything like that, use a sniffer for DHCP lease traffic.

- Change the root password and generate new SSH host keys, especially if the device will be permanently running on a public network.

- Enjoy your new ARM device running Kali Linux!

## 4.5. Troubleshooting Installations

The installer is quite reliable, but you may encounter bugs or face external problems such as: network-problems, bad mirrors, and insufficient disk space. Because of this, it quite useful to be able to troubleshoot problems that appear in the installation process.
