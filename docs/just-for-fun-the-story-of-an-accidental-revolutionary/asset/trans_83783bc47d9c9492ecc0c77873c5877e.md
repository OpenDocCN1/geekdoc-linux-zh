

## V. 我们一夜间成名

你读过那些宣传性新闻组吗？它们存在的全部目的就是为了宣扬某事物，而这意味着要贬低其他事物。所以当你逛这些新闻组时，只会发现诸如“我的系统比你的系统好”之类的废话。这是网络版手淫的一种形式。

我之所以提及宣传性新闻组，是因为尽管它们荒谬可笑，但它们确实提供了一条线索，让我们得以窥见当时正在发生什么。当各大公司最初认定 Linux 是操作系统中的宠儿时，日益增长的商业支持并未首先在媒体或弗里电子产品商店的收银台处被讨论，而是在宣传性新闻组上被热议。

让我回溯一下。1998 年春天，一位金发女孩进入了我的世界：Daniela Yolanda Torvalds 于 4 月 16 日出生，使她成为第一个拥有美国国籍的托瓦尔森家族成员。她和 Patricia 仅相差十六个月，就像 Sara 和我一样。但我保证，她们不会像我姐姐和我在成长过程中那样饱受煎熬——至少在 Tove 的调节影响下不会，她的空手道技艺更是加分项。

在 Daniela 出生前两周，开源社区——直到最近才被称为自由软件社区——迎来了有史以来最大的推动力。那就是网景公司将其浏览器技术的源代码在一个名为 Mozilla 的项目中开放。一方面，这个消息让新闻组上的所有人兴奋不已，因为它提高了开源的知名度。但这也让很多人，包括我在内，感到相当紧张。当时网景公司处境艰难，这在很大程度上归咎于微软，而开放其浏览器被视为一种某种程度上的绝望举措。（讽刺的是，该浏览器的根源在于开源。它最初是伊利诺伊大学的一个项目。）

新闻组上的人们表达了一种恐惧，担心网景会搞砸一切，从而损害开源的名声。现在将有两个知名的大型开源项目——网景和 Linux——其逻辑推理是：如果网景这两个中更知名的那个失败了，声誉也会波及 Linux。

在很大程度上，网景确实失败了。该公司花了很长时间才让开源开发者对这一项目产生兴趣。那只是一大堆代码，而唯一能够掌握这些代码的人只有网景的员工。

该项目之所以在某种程度上注定失败，不仅因为其规模庞大，还因为网景无法将所有内容都作为开源提供——只有开发版本，而在公司发布时，该版本相当不稳定。该公司不能将浏览器以 GPL 许可协议发布，因为并非所有代码都属于该公司——例如，Java 部分是从 Sun 公司获得许可的。新闻组上并非所有人都认同网景的许可协议。总体而言，该许可协议相当温和，但如果你像理查德·斯托曼那样，你就不会喜欢温和的东西。

我认为网景迈出这一步非常棒，但我并不将其视为个人的成就。我记得埃里克·雷蒙德对此事看得非常个人化。他为此感到极其高兴。他那篇出色地解释了开源哲学和历史的文章《大教堂与集市》，在前一年发布，并被引用为网景决策背后的原因之一。他一直在积极推广开源。他曾多次造访网景，试图说服他们开放浏览器。我只去了一次。事实上，埃里克曾带着开源信息造访过许多公司。我对技术感兴趣，而不是传教活动。

在 Mozilla 发布后的 24 小时内，一个自称为 Mozilla 密码学小组的澳大利亚团队创建了密码学模块。当时，非美国公民被禁止使用在美国土地上生成的加密。突然之间，一位来自澳大利亚的人完成了这项工作，这使得非美国公民处于可以使用它的位置。但有一个转折。鉴于当时的出口限制，Mozilla 项目无法采用澳大利亚的代码。如果它进入美国，就无法再出口。这意味着伟大的网景实验的第一项成功成果无法成为 Mozilla 的一部分。

我们都感到担忧，因为网景收到了大量的新闻报道。在第一年里，人们如履薄冰。没有人愿意说网景的任何负面言论，担心这会导致开源的负面报道，从而吓跑其他公司。

但在网景此举两个月后，Sun Microsystems 也加入了游戏，宣布将成为第一家加入国际 Linux 组织的主要硬件供应商。它将在其服务器上支持 Linux。这家因其 Jini 项目令人印象平淡的许可方案的公司，已决定认真对待 Linux。新闻组上充斥着自我祝贺。随着 Sun 的加入，Linux 的发展从互联网讨论扩展到了行业媒体。外部人士突然感兴趣了，但主要是技术型的外部人士。

然后是 IBM。

IBM 一向以相当保守著称，所以当该公司在 6 月宣布将销售和支持 Apache（当时用于 Web 服务器最受欢迎的商业 Linux 版本）时，所有人都感到惊讶。你可以在 AIX（IBM 的 UNIX 系统）上运行 Apache，这很可能就是许多购买 IBM 的人所做的事。这就是 Apache 引起 IBM 注意的原因。一定有人注意到大多数那些服务器机器最终都使用了 Apache，因此他们计算得出，如果拥有支持此类客户的内部专业知识，就能卖出更多的服务器。或者，也许他们是在响应客户的反馈，客户表示他们会购买 IBM 机器但会运行 Apache。

在计算机上安装 Linux 相对容易。但对于大多数公司来说，历史上的一大问题是：当出现故障时，我们该怪谁？显然，有 Red Hat 等提供支持的 Linux 公司，但让客户知道 IBM 会支持他们，这在心理上是一个优势。当 IBM 开始涉足开源时，许多人怀疑这只是口头支持。但事实证明并非如此。IBM 通过在服务器盒子上运行和支持 Linux，试探性地入了水，然后才完全深入。接下来是小型 PC 服务器，然后是普通 PC，再然后是笔记本电脑。该公司宣布今年将向 Linux 投入 10 亿美元。

IBM 的许多 Linux 工作都是独立完成的。我认为他们喜欢 Linux 的原因之一是因为他们可以随心所欲地行事，而无需处理许可问题。这家公司有过不少麻烦。IBM 在共同开发了操作系统 OS/2 后被微软坑了，结果 OS/2 只是加了料的 Windows。微软没有支持 OS/2，因为它对分享市场不感兴趣。Windows NT 是微软方面由此产生的结果。但 OS/2 从未回报 IBM 投入其中的数十亿美元。而且 IBM 还受困于 Java 的许可问题。我认为他们很高兴在 Linux 中不用遭受那些烦恼。

毫无疑问，IBM 是 Linux 的最大胜利。它在新组上引发的只是兴奋——不是由网景公告引发的偏执，也不是那些周期性（好吧：频繁地）使 Linux 爱好者分裂的商业反叛情绪。

到 7 月，Informix 宣布它将把其数据库移植到 Linux 上，这意味着即使你使用 Linux 来操作计算机，你也能运行 Informix 数据库。当时这并非大事。该公司一直处于财务困境中，但它仍然是排名前三的数据库供应商之一。Linux 人士对这一进展略感高兴，并在 Linux 宣传团体中撰写自我祝贺的文章。

在几周内，Oracle 也紧随其后。Oracle 主导了数据库市场。早在公告之前，就有关于该公司有一些内部 Linux 移植版本的传闻（在新闻组上）。而且，由于 Oracle 与 Unix 服务器同义，因此转向 Linux 并非重大飞跃。但如果你关注新闻组，我们确实进入了主流。Oracle 的公告产生了巨大的心理影响，即使其技术影响为零。

与此前 IBM 的公告类似，Oracle 的大动作不仅被 Linux 社区感受到，也被通常称为管理决策者的民众感受到，尽管有些人更喜欢用“西装人士”这个词。他们不再能说因为业务依赖数据库而不能使用 Linux 了。

虽然消息令人欣慰，但它并没有改变我的生活。Tove 和我正在照顾两个可爱的孩子。我大部分非家庭时间都花在了 Linux 维护上，无论是在家还是在办公室。为了避免偏向 Linux 的任何单一版本，我在工作使用 Red Hat，在家使用 SuSE（一个欧洲版本）。有一次我觉得自己运动不够，于是决定骑自行车往返六英里，从我们的公寓到 Transmeta 的总部。那是星期一。没有山坡可爬，但强风逆风而行，比我想的更具挑战性。十小时后我下班时，风向变了，但仍然是逆风。我给 Tove 打电话，她来接我。不用说，骑自行车上班再也没有发生过。
