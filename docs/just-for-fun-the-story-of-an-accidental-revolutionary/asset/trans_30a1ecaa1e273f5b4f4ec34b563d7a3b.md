
## 四。

改变我想法的事实是，Transmeta 简直是周围最神秘的公司。关于可以谈论的内容，只有一条规则，而且这条规则非常简单：“什么都别说。” 这不禁让 Linux 圈子的人有时好奇我到底加入了什么奇怪的邪教，以及我是否还会回来。我甚至不能告诉我的母亲我在忙什么——不过她本来也不会感兴趣。

我在 Transmeta 做的事情其实并不奇怪。我实际做的第一件事是修复 Transmeta 遇到的一些 Linux 问题。该公司使用了大量的多处理器 Linux 机器。我从未亲自处理过 Linux 的 SMP（对称多处理）问题，结果发现许多事情并没有按照预期的方式运行。我将其视为对我个人的冒犯，因此不得不修复它，这是理所当然的。

但我真正的工作其实是成为 Transmeta 垒球队的一员。

哦，我的意思是软件团队。我们并没有打多少垒球。硅谷的任何联盟都不允许我们加入，除非我们同意告诉他们我们在做什么。

我不知道人们对 Transmeta 的熟悉程度如何。就我写这段话的时候，我们实际上正处于 (拜托，上帝，请买我们的股票) IPO 之前的静默期，我们不再保密，但由于 SEC 关于首次公开募股的规则，我们又回到了隐身模式。让我们希望，当这本书出版时，每个人和他的狗都知道 Transmeta，并购买了一个或多个我们的 CPU。因为这就是 Transmeta 所做的——CPU。硬件。

但 Transmeta 做的不仅仅是硬件。这也很好，因为坦率地说，即使二极管踢我的头，我也分不清晶体管和二极管。Transmeta 做的是 *简单* 的硬件，依靠巧妙的软件让简单的 CPU 看起来比实际更强大——事实上，就像标准的 Intel 兼容 x86 一样。随着硬件变得更小更简单，CPU 的晶体管数量减少，进而使其功耗降低，正如大家意识到的那样，这在移动世界中将变得越来越重要。这就是为什么 Transmeta 拥有一个相当大的软件团队，也是我在那里工作的原因。

这一切都非常适合我。一家非 Linux 公司，做了一些技术上相当有趣的事情（这是今年的低调表达——我仍然不知道有其他公司真正尝试过 Transmeta 所做的）。而且是在我熟悉的领域：相当深奥的 80*86 系列 CPU 的低层编程。你无疑记得，正是因为在我拥有的第一台个人电脑上了解该 CPU，才最初启动了整个 Linux 项目。

Transmeta 不是一家 Linux 公司，这一事实对我来说也很重要。别误会我：我喜欢修复 Transmeta 的 Linux 问题，我参与过几个关于 Linux 的内部项目。（事实上，如今可能很难找到一家没有此类项目的严肃技术公司。）但在 Transmeta，Linux 是次要的——这正是我想要的。我可以继续做 Linux，但我不觉得我必须做出那些会让公司目标凌驾于 Linux 本身之上的技术妥协。我可以继续将 Linux 视为一种爱好，其中只有技术重要，其他任何事情都不控制我的决定。

所以白天，我为 Transmeta 工作。我编写并维护了“*86 解释器”，我们今天仍然在使用它（尽管现在其他人维护它）。解释器基本上是 Transmeta 软件的一部分，它一次查看一条 Intel 指令，并执行它们（即，它“解释”80*86 架构的语言，一次一条指令）。后来我做了其他事情，但这就是我进入硬件仿真这个奇怪而精彩的世界的方式。

晚上，我睡觉。

我与 Transmeta 的交易很清楚：我得到了模糊的保证，我也可以在工作时间研究 Linux。相信我，我充分利用了这一点。

很多人相信长时间工作和做双班、三班甚至四班倒。我不是其中之一。Transmeta 或 Linux 从未干扰过我一夜好眠。事实上，如果你想了解诚实的真相，我是睡眠的坚定信徒。有些人认为这只是懒惰，但我想把我的枕头扔给他们。我有一个完全合理的借口，并坚持它：如果你每天睡，哦，比如说十个小时，你可能会失去几个生产性的白天小时，但当你醒着的那几个小时，你神清气爽，你的大脑全功率运转。或者是四个汽缸，或者别的什么。

### 欢迎来到硅谷

我在这个奇怪的星系落地后做的第一件事之一，就是见明星。

我收到了一封来自史蒂夫·乔布斯秘书的电子邮件，说他希望见我，问我能否抽出一两个小时。不知道怎么回事，我说可以。

会议在苹果总部位于 Infinity Loop Drive。与会者有乔布斯和他的首席技术人员 Avie Tevanian。当时苹果正在开始开发 OS X，这是一个基于 Unix 的操作系统，直到 2000 年 9 月才发布。会议没有太多正式程序。基本上，乔布斯一开始试图告诉我，桌面上只有两个玩家，微软和苹果，他认为我能给 Linux 做的最好的事情就是与苹果“上床”，并尝试让开源人士支持 Mac OS X。

我留下来是因为我想了解新的操作系统。它是基于 Mach，卡内基梅隆大学开发的微内核。在 20 世纪 90 年代中期，Mach 被认为是终极操作系统，许多人对此感兴趣。事实上，IBM 和苹果使用 Mach 作为其不幸的 Taligent 合资操作系统的基础。

乔布斯特别强调 Mach 的低层内核是开源的。他有点淡化了这个设置的缺陷：谁在乎基本操作系统，真正的核心部分是否开源，如果你然后在上面有一层 Mac 层，它不是开源的？

他无法知道我对 Mach 的个人评价不高。坦白说，我认为它是一堆垃圾。它包含你可以犯的所有设计错误，甚至自己发明了一些。反对微内核的一个论点一直是性能。因此，许多人做了研究项目，旨在确定如何将微内核变成性能非常好的东西。所有结果的建议都进入了 Mach。结果是，它变成了一个带有自己规则的复杂系统。而且它的性能仍然不太好。

Avie Tevanian 当 Mach 还是一个大学项目时是 Mach 团队的一员。讨论他和史蒂夫认为的问题有点意思。与此同时，我们在技术问题上存在根本分歧。我真的认为没有理由让开源或 Linux 人士参与。当然，我理解他们为什么想要让更多的开源开发者进入他们的系统；他们看到了 Linux 背后的势头在积累。但我觉得他们看得不够多。我不认为乔布斯意识到 Linux 潜在的用户可能比苹果多，尽管用户群非常不同。我也不认为史蒂夫今天会比三年前那样急于将 Linux 作为桌面系统弃之不顾。

我解释了为什么我不喜欢 Mach。由于可以理解的原因，这反应并不太好。他们肯定以前听过这些论点。显然，我非常坚持 Linux，而 Tevanian 非常坚持 Mach。看看他们如何讨论一些技术问题很有趣。我能看到的立即问题之一涉及他们如何计划在新操作系统中支持旧 Mac 应用程序。他们希望用兼容层处理所有旧的东西。所有旧的 Mac 应用程序都将在一个新附加的进程中运行。但旧 Mac 的主要缺点之一是缺乏内存保护，这个解决方案并没有解决这个问题。只有新的 Mac 应用程序才有内存保护。对我来说，这没有道理。
