1 Introduction to Linux
T his chapter provides the motivation for learning the fundamental concepts of Linux. This chapter also briefly describes the structure of the Linux operating system, Linux distributions, and the Linux system architecture. Other concepts covered include types of shells, features of the Linux operating system, installation of a VirtualBox, how to create a virtual machine and the installation of Ubuntu on a virtual machine.
Why Linux?
With the rise of Artificial Intelligence, Machine Learning Engineering, DevOps, and Cloud Computing, the demand for Linux has increased. This is because most back-end jobs involving the deployment and release of applications can be efficiently done in Linux. If you want to break into the IT world or if you want to learn how to deploy software applications or machine learning models, you definitely need to know how to use Linux commands.
You will surely reap some benefits from learning how to use Linux commands. Moreover, Linux is one of the most reliable and secure operating systems. The Linux operating system powers local servers, remote servers, electronic devices, embedded systems, mobile phones, smart watches, smart TVs and so on.
Linux Operating System and Linux Distributions
Just like Microsoft Windows and macOS, Linux is an operating system. Compared to other operating systems, Linux is open source. Generally, an operating system is a software that directly manages a computer system’s hardware and resources such as the central processing unit (CPU) and memory storage.  An operating system connects software applications and physical resources in your desktop or laptop computer. Therefore, an operating system helps software applications to function, by managing the communication between computer software and hardware.
Linux has several versions (also called distributions) to suit various users. Some popular Linux distributions include Ubuntu, Red Hat, Debian, CentOS, Fedora, Linux Mint, etc.
Linux System Architecture
The Linux system architecture basically consists of the Linux kernel, system libraries, user applications and hardware, as shown in the figure below.
The kernel and system libraries are the key components of the Linux operating system. The kernel consists of various modules and interacts directly with the underlying hardware such as CPU, RAM, and I/O. That means, the kernel is used for the management of system resources:
  • Device management : all input and output devices are managed by the kernel.
  • Memory management: the kernel keeps track of used and unused memory, implements virtual memory, allocates memory for user programs and so on.
  • Process management : the kernel assigns enough time for processes and prioritizes processes.
  • Handling system calls : a user application can ask the kernel to perform certain tasks. Programs use system calls to execute certain operations.  System libraries are functions or programs used to access the kernel’s features. Standard libraries are procedures for communicating with the kernel. When applications place system calls for the kernel to perform certain tasks, the system calls are usually not invoked directly but through libraries.
Various applications are used to execute specific tasks inside a Linux computer. The shell is a special application, a user interface used to communicate with the kernel which in turn controls hardware components and processes. Though a single computer generally has a single kernel, several shells can run simultaneously on the operating system of the same machine.
Types of Shells
There are different types of shells in Linux, including the:
  • Bourne Again shell (bash)
  • Bourne shell (sh)
  • C shell (csh)
  • Korn shell (ksh)
  • TC shell (tcsh)
Note that, it is possible to have more than one type of shells installed on the Linux operating system.
Features of the Linux Operating System
Some key features of the Linux operating system are as follows:
Multi-user: Multiple users can use different shells to access the same system resources such as memory, hard disk, application programs at the same time.
Multi-tasking : Multiple applications can run on the Linus operating system at the same time.
Portable : The Linux operating system works in the same way across different platforms.
File system: Files and directories are arranged in a hierarchical manner and everything including regular files, folders, memory, I/O, and devices are treated as files.
Shell: This is a command line interface in Linux that allows a user to enter commands with a keyboard, to execute a program or accomplish a specific task.
Security: Linux provides security in three major ways, including:
  • Authentication - password protection is provided by assigning passwords and login IDs to users.
  • Authorization - users are provided with the permissions to read files, write on files or execute programs; hence users are restricted on what they may or may not do on the computer.
  • Encryption - files are converted into a format that is not readable.

A General Linux Directory Structure
The Linux file system starts with a root directory (/ ) which contains directories and files (regular files). The directories further contain sub-directories and so on. That means, any directory or file can be traced back to the root directory. Furthermore, any absolute file path starts with the root directory. The root directory is represented by a forward slash (/ ). It is important to note that there are no drive letters such as C:\ in the Linux system compared to the Windows system.

Types of Files in Linux
In Linux, everything is viewed as a file. There are different types of files, including regular files (-), directory files (d), and special files. 
Regular files are the most common types of files in the Linux system and can be created in different ways. For example; the touch command, the vi or nano editors can be used to create regular files. Examples of regular files are text files (.txt), Python files (.py), Java files (.java), etc. Directory files are folders and can be created using the mkdir command.
There are also various special files used for different purposes in Linux. For example:
  • Block device files are hardware files that control hardware such as drives and memory. Block devices are mostly found in the /dev directory.
  • Character files allow users and programs to communicate with hardware peripheral devices. Some classical examples of character files are files representing the keyboard, mouse, serial printer, etc. Character files are hardware files which read and write data in a character-by-character fashion.
  • Pipe files allow applications or processes that are not designed to explicitly work together to communicate within a single Linux machine.
  • Symbolic link files serve as links to other files. These files can be viewed as shortcuts or pointers to the original files.
  • Socket files are used to pass information between applications.
To display a file type in the Linux terminal, the ls -ld <file-name> command can be used.  For example, the ls -ld Downloads command below generates output that includes drwxr-xr-x. The d at the beginning of drwxr-xr-x, indicates that the Downloads file is a directory.
Alternatively, the file <file-name> command can be used to display the file type for a specific file.
File Naming
  • File names in Linux are case sensitive, which means a file called myfile is not the same as Myfile .
  • The characters used in file names may include uppercase and lowercase letters, numbers, dots(.), underscores (_), hyphens (-), and so on.
  • Special characters such as /, *, ?, :, &, <, >, { }, ( ), should not be used in file names.
  • It should be noted that file extensions have no significance but could be included to help us to easily identify file types. So, myfile is the same as myfile.txt.

5 Standard I/O Redirection and Piping
I n this chapter, we will learn about standard input redirection, standard output redirection, standard error redirection and how to chain multiple commands into a single command using piping.
What is Standard I/O?
Standard I/O refers to standard input and output. When you are working with the Linux terminal, the input is entered through the keyboard and the output is displayed on the terminal. That is, the standard input device is the keyboard while the standard output device is the terminal or simply the computer screen.  The symbol for standard input and standard output is stdin and stdout respectively. There is also standard error represented as stderr . Remember that everything in the Linux system is a file, including regular files, directories or even devices (special files). So, the standard input, standard output and standard error devices are all files associated with file descriptor numbers 0, 1 and 2 respectively.
Redirection is used to manipulate the input and output of commands. For example, instead of displaying the output on the terminal, the output can be redirected to a file. Through redirection, we can change the standard output and input devices. 
Standard Input Redirection
Normally, commands in the Linux terminal take some input. If the input is a regular file, we can supply the contents of the file through input redirection using the “<” symbol. Let’s supply a Python file to the cat command using input redirection.

Let's now consider another example where a file is supplied to the wc -l command with and without redirection. You would notice that, without redirection, the number of lines and the name of the text file is displayed. Redirection passes the file contents to the wc -l command, so the name of the file is not displayed.
We can use redirection to send an attached file to an email using the mail command. For example; mail -s “Data Analysis File” xyz@company.com < analysis.py will attach a file the analysis.py file to the xyz@company.com email and the subject of the email will be “Data Analysis File”.
Output Redirection
We can redirect the output using the greater than sign (> ). For example, instead of displaying the contents of a directory on the terminal, we can redirect the contents into a file using ls -l > <file-name>.
Note that if the file to which the output is being directed already exists, it will be overwritten. For example, let's print or echo a string into the listing.txt file.
If you don't want to overwrite the existing file, that is, if you want to add or append contents to the existing file, you can use the >> sign instead of > .
Note that we could use 1> to explicitly specify that the type of redirection is output redirection compared to standard error redirection where 2> is used.
Standard Error Redirection
When we run programs or commands, it is possible that an error message could be displayed as output. Instead of letting error messages clutter the output on the terminal, we can redirect the error messages to a file. This is a common practice among developers. Standard errors can be directed using 2> (compared to 1> used for directing standard output).
We can also redirect error messages that are not useful to /dev/null . Anything that goes into /dev/null cannot be retrieved.
Any output that goes into /dev/pts/0 is displayed on the terminal because /dev/pts/0 is basically the terminal.
Piping
Piping involves chaining a set of commands such that the output of the first command is passed as input into the second command. The pipe character or vertical bar (| ) is used for piping. For example, we can list the contents of a directory, then count how many items are in that directory using the command, ls | wc -l.
Consider a file, animals.txt containing names of animals. Let’s use the sort and uniq command to display unique animal names in a sorted order. We will use piping to chain the sort and uniq commands. Note that the uniq command only works for sorted items so we need to first sort the items, then pass the sorted items into the uniq command.
Other common examples of how piping is used include:
  • cat <file-name> | grep <“keyword”> : retrieves lines in a file having the specified keyword.
  • cat <file-name> | tail -5: displays the last five lines of text in a file.

Users and Groups
Users and groups are two main types of accounts in Linux. Accounts allow access into specific resources or files. Every user account is given an ID number (userid). Groups allow the system administrator to manage a collection of user accounts. Every Linux user belongs to at least one group (the primary group). If a user creates a file, that file belongs to both the user and to the primary group of the user. You can use the ls -l <file-name> to display files in a directory, as wells users and groups having access to a file.

8 Regular Expression
T his chapter focuses on how to use regular expressions. Regular expressions are special characters used for searching data by matching patterns. A regular expression is therefore a data matching mechanism used to search for data that matches a specified pattern.
Introduction to Regular Expressions
Let’s start by examining how regular expressions work. We can use ls -l *.py to list all the files that end with .py. The asterisk (*) matches zero or more characters.
Regular expression can be used with the grep command to display lines in a file that match a pattern. For example, cat names.txt | grep “e” will output lines with the letter “e” while cat names.txt | grep “e$” will search for lines that end with “e”.
Examples of Basic Regular Expressions
  • “ ^a ” will search for lines that start with the letter “a”. 
  • “ a.b ” will match any single character between “a” and “b”. 
  • “ a*b ” matches from 0 to more characters between “a” and “b”. 
  • [abc] will match a line that contains either “a”, “b” or “c”. Note that [abc] is the same as [a-c] . 
  • [abc]ef will match a line with three characters such as aef, bef or cef. 
  • [a-z] matches a single lowercase letter. [a-z] is the same as [:lower:] .
  • [A-Z] will match a single uppercase letter. [A-Z] is the same as [:upper: ]. 
  • [a-zA-Z] will match a single letter (uppercase or lowercase). [a-zA-Z] is the same as [:alpha:] .  
  • [0-9] will match a single number.  [0-9] is the same as [:digit:] . 
  • [a-zA-Z0-9] will match a single letter or number.
  • [:space:] will match a whitespace.
  • [:punc:] will match the punctuation. 
  • [^abc] or [^a-z] matches any character not enclosed. 
  • “ ^$ ” will match blank lines.
cat names.txt | grep “^[A-K]” will match names that start with letters between A and K, but cat names.txt | grep “^[^A-K]” will match names that do not start with letters between A to K. [^A-K] means other letters except letters between A to K.
We can use the -n option to include the line numbers in the output. Then we can also use the -v option to reverse or negate the matching pattern.

10 Process Management
T his chapter explores different types of processes as well as commands used for managing processes including ps , kill , nohup , and time . The chapter also covers how to use signals to communicate to processes. Job control commands such as jobs , fg , and bg are also discussed.
What is a Process?
A process is a program in execution or a program that is running. Remember that Linux is a multitasking system where multiple processes can occur simultaneously; and a multi-user system where multiple users can log into the system at the same time. Each process started is allocated a unique number called process identifier (PID). 
There are parent and child processes.  If process A creates process B, then process A is the parent of process B or process B is the child of process A. A process could have process identifier 0 (PID 0) or process identifier 1 (PID 1). PID 0 is a swapper or scheduler (sched) primarily responsible for paging. PID 0 is a process that is a part of the kernel rather than a user-mode process and starts the init process which is assigned the process ID 1. PID 1 is usually an init process primarily responsible for starting and shutting down the system. PID 1 is the parent of all processes.  So, the Linux system boot process has PID 0 and PID 1. Init is the first process started by the swapper (or scheduler).
Types of Processes
  • The interactive process (or foreground process): This process runs at the foreground or via the Linux terminal. Users interact with such processes.
  • Non-interactive process (or background process): This is the process that runs in the background and users do not have to interact with the process. To run a command in the background, we can include & (ampersand) after the command. The command runs in the background and the prompt is released back to the user.
  • Daemons are long running processes in the background waiting for some instruction.

○     Open PuTTY (putty.exe). Enter the hostname of the remote instance. The hostname could be written as instance-name@IPv4-DSN-address , for example: ubuntu@ec2-3-143-243-25.us-east-2.compute.amazonaws.com
○     Click on SSH and Auth . Then load the .ppk file and click on Open .
○     After clicking on Open, a PuTTY security alert will be displayed as shown below. Click on the Accept button to connect to the instance.
