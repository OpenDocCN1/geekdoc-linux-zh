## 4.3.5 Color scheme

**The color scheme (combination of colors) is a point not to be overlooked when you design your interface.**

**For multicultural environments, consider the culture where the application is executed; in this case, you have to define a color scheme specific for each culture your application targets (for example: the difference between Asia and the Occident for the color of the trend in financial markets: green <-> red).**

**The use of color is determinant in two foremost reasons:**

-   The look and feel of your application. The perception of the application by the user is conditioned, at least in part, by the use of a specific color scheme.
-   The highlighting of significant information on your window when you have a large amount of data displayed. You can choose flashy colors for getting the user's attention on what is important in the screen you display.

There are “standards” to help you in the conception of your color scheme:

-   Monochromatic: Each color is taken from the same base color (ex: multiple blues), generally it looks very smooth and produces a soothing effect.
-   Analogous: Use of one main color and the others are used to enrich the scheme.
-   Complementary: On a color wheel, the complementary colors are at the opposite of each other; there is a great effect of contrast produced.

You can also use a specialized tool; Adobe Color CC (as part of Adobe Capture CC) for producing elegant and pertinent color schemes for your application. The other software that seems to be a reference for the conception of color schemes is Paletton (“The color scheme designer”).

## 5.1 APPLICATION CONFIGURATION

In many cases, you will have to use a configuration file where you can store information like “connectionString” for database access, user’s credentials, services endpoints... You do not want to store these data in the database (because it does not change very often) but you cannot hard code it (because it might change). You have to use a configuration file.

In the .NET framework, it was handled by the famous “app.config” file (an XML formatted text file), but in .NET Core the things are a little bit different.

For .NET Core applications, you can still use INI, Config, or other custom-made configuration providers, but the standard way of storing configuration information is to use the “appSettings.json” file.

The XML format of the `app.config` has been replaced (you still can use XML formatting with the appropriate provider) by the JSON format, which is more compact. .NET Core 3 does not include a built-in configuration management system for doing so; you have to add the relevant NuGet package (this is the standard way for adding features with .NET Core 3).

That can be done by adding a specialized NuGet package(s) to your project (with Visual Studio 2019 “Package Manager”):

![](img/3d310cc066dda6e2dfa67a650614076f_61_0.png)

Now the data are stored in a JSON formatted file, but the main using techniques are still relevant.

Here is a sample of a basic `appSettings.json` file:

![](img/3d310cc066dda6e2dfa67a650614076f_61_1.png)

```json
{
  "firstname": "Dimitri",
  "lastname": "K"
}
```

Do not forget to copy the `appSettings.json` file to the target build folder by changing the properties of the file as described below (Figure 1):

![](img/3d310cc066dda6e2dfa67a650614076f_62_0.png)

*(Figure 1)*

The reading of this file can be performed with a few lines of code. As the JSON format is using raw values and retrieving text format, you have to convert them to the required type manually.

Here is a little program (ProgramConfig.cs) illustrating how to retrieve data from the configuration file previously described:

### ProgramConfig.cs

```csharp
using System;
using System.IO;
using Microsoft.Extensions.Configuration;
using Microsoft.Extensions.Configuration.Json;

namespace ConfigProgram {
  class Program {
    static void Main(string[] args) {
      var config = new ConfigurationBuilder()
        .SetBasePath(Directory.GetCurrentDirectory())
        .AddJsonFile("appsettings.json", true, true)
        .Build();
    }
  }
}
```
