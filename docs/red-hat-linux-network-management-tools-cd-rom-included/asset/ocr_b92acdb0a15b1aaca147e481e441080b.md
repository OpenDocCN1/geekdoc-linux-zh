Table 4.16 traceroute display codes (continued)

| Code | Meaning |
| :--- | :--- |
| 1F | Fragmentation was needed for a probe packet. In practice, this shouldn't happen, and if it does, it indicates a bug or problem with the router that generated the error |
| 1X | The path is blocked due to communication being administratively-disabled. In other words, the path is shut down or blocked from a software standpoint |
| 1N> | An ICMP error code where N is that number |

Some of these display codes come in handy when you debug network problems. For example, if a destination is not reachable (like www.whitehouse.gov) by the system that is running the **traceroute** command, executing

```
monet# traceroute www.whitehouse.gov
```

will produce

```
traceroute to www.whitehouse.gov (198.137.240.91), 30 hops max, 40
byte packets
1  monet (10.0.2.126)  4.281 ms 1N*  1.896 ms 1N
```

In this example, the network 198.137.240 can't be reached from the local system, and **traceroute** displays the error string 1N to indicate this problem. In this particular case, monet can't send any packets to 198.137.240 because no route to that network exists. The * means that the particular probe packet never received a response; the * is used as a timeout indicator. To further verify these results, use the ping command with the same destination. Thus the command

```
monet# ping www.whitehouse.gov
```

will show the same problem, except the error is a little more descriptive:

```
ICMP Net Unreachable from gateway monet (10.0.2.126)
for icmp from monet (10.0.2.126) to www.whitehouse.gov
```
