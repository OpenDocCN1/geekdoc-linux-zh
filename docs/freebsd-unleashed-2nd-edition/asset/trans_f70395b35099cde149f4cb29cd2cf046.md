
# 第 10 章
系统配置与启动脚本

与大多数类 Unix 操作系统一样，FreeBSD 的启动过程在提供命令提示符之前，会向用户提供大量信息。这种启动过程可能比 Windows 和 Mac OS 等操作系统更加复杂。但是，只要你在正确的硬件上运行正确的系统，完整的启动（包括启动所有系统服务或守护进程）可以像桌面操作系统一样快速。

由于每个类 Unix 操作系统的处理方式都略有不同，即使是有经验的 Linux 老手也可能对 FreeBSD 的启动过程感到陌生。例如，你不会看到方便的 fsck 进度条或某些 Linux 发行版中整齐排列的复选框列，而且引导管理器与 LILO（Linux 引导加载器）的工作方式大相径庭。FreeBSD 也不具备 Linux 和 Solaris 所拥有的多种运行级别（run levels）。由于 FreeBSD 的模型更简单直接，它可能更容易理解和处理，但它也拥有其他平台所不具备的陷阱和复杂性。

不过，通过一点探索，你将很快完全分析并掌控这一过程。

## 理解 FreeBSD 启动过程

FreeBSD 的自举（启动）过程是多阶段的，每个阶段通常具有非常有限的功能和范围，在执行一个关键步骤后将控制权移交给下一个阶段。本章将详细介绍这些阶段。你可能永远不需要了解系统启动时发生的详细情况，但了解它们并无害处！

## 本章内容

- 理解 FreeBSD 启动过程
- 资源配置脚本
- inetd 守护进程和 inetd.conf 配置文件
- 系统日志记录器 (syslogd) 和 syslog.conf 文件
- 关于 /etc/rc.local 文件的说明

当你第一次开机时，FreeBSD 所做的第一件事是运行由 BIOS 和 CMOS 配置指定的硬件检查和探测。这些硬件检查和探测包括内存检查以及你在屏幕首次清除之前看到的 IDE 或 SCSI 探索。这一步与操作系统无关；无论你在机器上安装了什么，它都会以相同的方式发生。

## 经过引导过程

在 BIOS 打印出显示其收集的硬件数据的表格后，它会读取主磁盘的主引导记录（MBR）以获取第一个初步*引导块*。这个引导块及其后的两个引导块的职责是找到并运行 `loader`，该程序负责配置和加载内核。每个引导块依次比前一个稍微复杂一些。前两个引导块的大小限制在 512 字节以内（受 MBR 大小和切片引导扇区大小的限制），因此它们都非常简单。以下是每个引导块及其功能：

- **引导块 0 (boot0)**—这个初步引导块位于 MBR 中，类似于 LILO，并且（如果安装了 FreeBSD 引导管理器）列出了可用的切片（紧随其后的 F 键命令），你可以从中选择要引导的内容：
  - F1 FreeBSD
  - F2 Linux
  - F3 ??
  - 默认：F1

你可以按相应的 F 键选择想要的切片，或者只是等待几秒钟，在这种情况下，引导块将选择默认选项并继续。

- **引导块 1 (boot1)**—这是一个非常简单的程序，运行自你在 `boot0` 中选择的切片的引导扇区，其职责是使用简化版的 `disklabel`（它将切片划分为 BSD 风格的分区，这在第 19 章“理解硬盘和文件系统”中进行了全面介绍）来找到并运行适当分区中的 `boot2`。`boot1` 没有用户界面部分。

- **引导块 2 (boot2)**—终于，我们达到了一个具有足够空间来包含必要复杂性的引导块，以便在可引导文件系统中读取文件。在早期版本的 FreeBSD 中，这个引导块曾经提供一个提示符，如果你不从可引导切片中的默认位置加载内核，可以告诉它从哪里加载内核。现在，它自动运行一个名为 `loader` 的程序，该程序提供了到内核命令行界面的接口以及更多功能。

- **loader** — 你可以在 /boot 目录中找到此程序。它读取 /boot/defaults/loader.conf 和 /boot/loader.conf 配置文件，并加载其中指定的内核和模块。（/boot/loader.conf 文件包含对 /boot/defaults/loader.conf 的覆盖，其方式类似于 /etc/rc.conf 的工作方式，我们将在本章后面介绍。）

loader 等待按键时会倒数 10 秒；如果没有按键，它将引导内核进入其默认状态。但是，如果你按 Enter 键，loader 会将你带入其命令提示符界面，在那里你可以精确控制内核引导过程。你可以以单用户模式引导（boot -s），引导旧内核（boot kernel_old），从 CD-ROM 引导（boot -C），逐个加载和卸载内核模块（load 和 unload），查看文件内容（more），或执行许多其他任务（有关详细信息，请参阅 man boot）。大多数时候，你不需要所有这些引导选项，因为你以默认配置进行引导。不过，假设你想在启动时加载某个特定的内核模块（/modules/portal.ko），而不是等待系统完全启动。你还想查看当前已加载的内核模块。你可以在 ok 提示符下按以下方式设置：

```
ok load portal.ko
/modules/portal.ko text=0x1d18 data=0x1f4+0x4 syms=[0x4+0x8d0+0x4+0x6bf]
ok lsmmod
0x100000: kernel (elf kernel, 0x355be4)
0x455be4: /boot/kernel.conf (userconfig script, 0x4c)
0x456000: portal.ko (elf module, 0x3efb0)
```

在 ok 提示符下输入 ? 会给你可用的命令列表。你刚刚看到的两个命令是 load（将模块加载到内核中）和 lsmmod（列出当前已加载的模块）。此命令在故障排除期间或使用必须按特定顺序加载的内核模块时非常有用。有关 loader 命令行可用选项的更多详细信息，请查阅 man loader。

这结束了自举过程中的引导块阶段。你现在已经走在让系统完全启动的道路上。引导过程的最后阶段是完整的 FreeBSD 系统开始发挥作用的地方。在那里，内核将其自身加载到内存中，探测可用设备，并运行“资源配置”脚本，以构建工作环境并启动各种系统服务。其余步骤如下：

- **内核** — 在 loader 移交控制权后，内核开始探测它能找到的所有设备，并且每个探测的结果都会回显到屏幕上。这是你会看到许多启动信息的时候。这些信息会被记录到 dmesg 文件中，如果需要查看内核对某个特定设备的评论，你可以使用 dmesg 命令读取。

> **提示**
> dmesg 命令是一个相当原始的工具，列出自系统上次启动以来在系统消息缓冲区中积累的内容。只需输入 `dmesg` 查看消息列表，或输入 `dmesg | less` 在交互式分页器中查看输出，以便更轻松地访问。

- **init**—在内核加载后，它将控制权移交给 init 进程，这是启动过程的最后阶段。这由“自动重启正在进行中”消息表示，涉及 init 运行资源配置脚本（/etc/rc）。该脚本首先检查 /etc/fstab 中所有文件系统设备的一致性，如第 8 章“FreeBSD 文件系统”中所述。

如果 fsck 没有找到它无法自行纠正的问题，它将挂载所有文件系统（使用 `mount -a -t nonfs`）并继续运行其余的启动过程。如果 fsck 发现磁盘存在无法解决的问题，它将退出到单用户模式，以便你手动运行 fsck 并修复损坏。退出单用户 shell 以继续重启到多用户模式。

最后，如果一切按计划进行，你会得到一个登录提示符。整个过程通常不超过一分钟。

## 保护引导过程

对于注重安全的系统管理员来说，一个令人担忧的事实是，默认情况下，如果你选择引导到单用户模式（在 loader 提示符下输入 boot -s），系统不会提示输入密码，而是自动以完全 root 权限启动。如果你与他人共享这台机器，使得这个人可以坐在机器前并在其想要时物理重启它，这就构成了一个严重且巨大的安全漏洞。

幸运的是，填补这个漏洞很容易。在 /etc/ttys 中，它包含各种访问方法（控制台、虚拟终端、串行终端和网络 [伪] 终端）的终端设置，你可以将控制台行上的设置从 secure 更改为 insecure：

```
console none				unknown off insecure
```

这告诉系统将控制台视为不安全的访问点，并向任何试图引导到单用户模式的人提出挑战（登录提示符）。需要通过 root 密码才能通过此挑战点。
