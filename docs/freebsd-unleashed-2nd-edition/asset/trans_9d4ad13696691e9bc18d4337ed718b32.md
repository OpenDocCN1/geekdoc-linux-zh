
虽然这条命令字符串现在可能看起来有些晦涩难懂，但它实际上非常强大。基本上，上面单行代码创建了一个简单的数据库，可以根据任何字段进行搜索，并以你想要的任何形式呈现输出。

为了让你看看这一行代码有多强大，下面是一个第二个示例，它略微修改了前面的示例以打印一个简单的邮件列表：

```
awk '{BEGIN {FS="-"} $3 == "Anytown" {printf "%s\n%s\n\n", $1,$2,$3,$4,$5}}' address.txt | lp
```

前面代码的输出如下：

- Doe, John  
  505 Some Street  
  Anytown, NY 55555

- Bar, Foo  
  501 Some Street  
  Anytown, NY 55555

对于那些愿意学习的人来说，Unix 是你能找到的最接近无限可定制和灵活操作系统的系统。Unix（因此也是 FreeBSD）内部蕴藏着巨大的力量，你可以释放并利用它来做你可能甚至不知道你电脑能做的事，而不必购买昂贵的软件。这本书将教你如何释放这种力量（因此得名）。

正是这种设计哲学使 Unix 没有变得过时，也没有像许多其他程序一样被抛在路边。

## FreeBSD 与其他操作系统的比较

在确定 FreeBSD 与其他操作系统如何比较时，重要的是要考虑如 Windows 2000/XP 和 Linux 等主要系统。本节探讨这些比较，以及其他基于 BSD 的操作系统。

### Windows 2000/XP

微软在倾听客户对操作系统的期望方面做得很好。Windows 2000/XP 不允许你“深入到底层”太多。它被设计为在没有用户学习系统内部结构的情况下，能够合理地为各种任务工作。这是以牺牲一些性能和效率为代价的。Windows 2000/XP 有相对较高的硬件要求，但许多用户愿意接受这一点以换取易用性。此外，由于 Windows 2000/XP 的图形化设计，“高级用户”很容易遇到限制。图形用户界面能做的事情终究是有限的。以下列表提供了 FreeBSD 和 Windows 2000/XP 之间的一些重要区别：

- **Windows 2000/XP 的内核无法定制。** 内核是操作系统的核心；它几乎控制着系统工作的每个方面。FreeBSD 允许你为操作系统构建一个新的内核，该内核针对你的特定系统进行了定制。这可以提高性能并减少内存使用。Windows 2000/XP 不允许你重新构建内核。这是 Windows 2000/XP 牺牲某些效率和性能以换取易用性的领域之一。
- **Windows 2000/XP 几乎为所有任务使用 GUI（图形用户界面），而 FreeBSD 更多地依赖于命令行。** Windows 2000/XP 中的 GUI 布局使得查找物品和执行政作变得容易。例如，在 Windows 2000/XP 中设置网络是通过网络控制面板完成的，还有引导你完成过程的“向导”。另一方面，FreeBSD 使用基于文本的配置文件进行网络配置。设置网络涉及手动编辑一个或多个配置文件。
- **Windows 2000/XP 的 GUI 始终在运行；FreeBSD 中的 GUI 是可选的。** 虽然 GUI 可以使工作站更容易使用，但对于后台服务器来说，由于没有人会看到其屏幕，它是一种浪费的开销。FreeBSD 提供关闭 GUI 或完全不使用它的选项。
- **Windows 2000/XP 需要专用软件进行远程管理。** 由于 FreeBSD 中的所有事情都可以从命令行完成，远程管理非常容易。在 FreeBSD 中，所有系统管理任务都可以从命令行完成。这使得远程管理变得容易。它可以从任何终端完成——甚至是从无法显示图形的终端。它也可以从任何能够运行终端模拟器的系统类型完成。FreeBSD 可以从另一个类 Unix 系统、Windows 系统、Macintosh 等进行管理。另一方面，Windows 2000/XP 需要 GUI 来完成许多任务。虽然 Windows 2000/XP 上的远程管理是可能的，但需要专用软件来完成。此外，大多数此类软件仅适用于 Windows。因此，大多数 Windows 的远程管理任务只能从另一个 Windows 系统完成。
- **就性质而言，任何 GUI（包括 Windows 2000/XP 的）都有命令行界面中不存在的限制。** 只有如此多的功能可以塞进 GUI。迟早，一个“高级用户”会想要做操作系统设计者没有考虑到的事情。例如，前一节中演示的简单地址簿数据库无法通过 Windows 附带的软件完成。类似的系统在 Windows 中需要第三方软件。邮件列表示例也无法通过 Windows 附带的软件完成。虽然对于此类简单任务有可用的第三方 GUI 软件，但在熟悉命令行之后，你实际上会发现，你输入命令行的速度比通过基于 GUI 的系统中的菜单要快得多。

### Linux

除非你在过去几年里住在洞穴里，否则你至少听说过 Linux，即使你不知道它是什么。Linux 是 Unix 的一个克隆，近年来变得相当流行。与 FreeBSD 一样，它是开源的，并由志愿者开发。与 FreeBSD 不同，Linux 没有一个单一的控制机构，并且有超过 30 个不同的 Linux 发行版。

FreeBSD 和 Linux 之间的相似之处多于不同之处。两者都是优秀的操作系统，都能很好地满足大多数用户的需求。虽然 Linux 上可用的软件比 FreeBSD 多，但 FreeBSD 可以运行几乎可用的所有 Linux 软件，所以这真的不是一个问题。当在 FreeBSD 下运行 Linux 软件时，性能也不是问题，因为 FreeBSD 实际上运行某些 Linux 软件比 Linux 本身更快。

以下是 FreeBSD 和 Linux 之间的一些最重要区别：

- **FreeBSD 只有一个发行版，而 Linux 有超过 30 个发行版。** FreeBSD 在所有安装它的系统中都以相同的方式工作。这对 Linux 来说并不成立。每个 Linux 发行版都有稍微不同的做事方式。例如，Slackware Linux 使用 BSD 类型的运行控制脚本。Debian Linux 使用 Sys V 运行控制脚本，而 Red Hat Linux 使用 Sys V 运行控制脚本，但将它们存储在与标准 Sys V Unix 不同的位置。对于那些从一个 Linux 发行版转移到另一个的用户来说，这可能会造成混淆，因为在另一个发行版中事情可能不会以相同的方式工作。
- **FreeBSD 是一个由核心团队维护的完整操作系统；Linux 是由 Linus Torvalds 维护的内核。** Linux 不是一个完整的操作系统。它是一个内核。如 Windows 部分所述，内核是操作系统的核心。它几乎控制操作系统的各个方面。销售 Linux 发行版的各个公司采用 Linux 内核，并包装一大堆设计用于与 Linux 配合的其他程序。由于每家公司对自己认为发行版应包含什么有自己的想法，你可能会发现在一个 Linux 系统上可用的程序在另一个 Linux 系统上不存在（虽然你可以下载并安装它）。这一事实还会导致升级 Linux 时的依赖性问题。例如，你可能升级了 Linux 内核，结果发现还需要升级其他几个软件包。由于 FreeBSD 是一个完整的操作系统，由于任何依赖项都会在同时升级，因此升级通常更容易进行。
