# WORLD-WRITABLE FILES

World-writable files may be exploited by malicious users to obtain root privileges. Consider a setuid executable script that is set to be writable by everyone. A malicious user may edit such script to execute any command as root.

Use the find command to search for world-writable files:

```
find / -type f -perm -2 -print 2 > /dev/null
```

# FILES OWNED BY BIN AND SYS

Some distributions incorrectly assign executable files to be owned by nonroot users such as "bin" and "sys."

For example, suppose /usr/bin/.telnet is owned and writable by the user "bin". If an intruder were to successfully mount the server's NFS /usr/share with the permissions of the user "bin", he or she would be allowed to replace /usr/bin/.telnet with a Trojan that would be executed with root permissions by inet or xinet every time an incom- connection received.

To check for "bin"owned files, run the following command:

```
find / -user bin -print 2 > /dev/null
```

Similarly, use the following command to check for "sys"owned files:

```
find / -user sys -print 2 > /dev/null
```

# THE umask VALUE

Every time a file or directory is created, it is given default permis- as specified by the "umask" value. Use the umask command to find out the umask value for the current user:

```
[bash]$ umask -p
umask 0002
```

The value of umask is determined by XORing the file permission octet values with 666 in the case of files and 777 for directories. In case of files, note the umask value does not allow for execute (x) permiss-ions to be set.

XOR stands for "exclusive OR." Following is a truth table for XOR:

| XOR | 0 | 1 |
|---|---|--|
|0 | 0 | 1 |
| 1 | 1 | 0 |
