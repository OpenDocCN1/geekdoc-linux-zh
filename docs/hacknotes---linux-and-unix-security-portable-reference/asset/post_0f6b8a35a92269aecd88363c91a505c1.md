
# Disable inetd or xinetd If No Services Are Enabled

If inetd or xinetd services have been disabled, there is no need to leave inetd or xinetd running. To stop inetd or xinetd from executing on startup, disable appropriate files in /etc/rc.d and /etc/rc.local.

# Ensure Logging Is Turned On

If running inetd, edit the inetsvc file and make sure inetd is invoked with the -t flag. In case of xinetd, edit the xinetd.conf and make sure the following line is present:

```
log_type = SYSLOG authpriv
```

In addition, edit syslog.conf and make sure *.info is enabled to log to /var/log/messages.

# WU-FTPD

FTP (file transfer protocol) is a protocol for transferring files from one host to the other. WU-FTPD is the most widely used FTP daemon on Unix and Linux. It is available from http://www.wu-ftpd.org/. Take these steps to harden WU-FTPD:

- Change the server banner. Edit /etc/ftpaccess and use the greeting directive to specify the new server. For example:
`greeting text No banner information available. Sorry.`

- Make sure /etc/ftpusers contains a list of users that should not be allowed to FTP in. Users such as root, bin, and http should not be allowed to FTP in.

- Edit inetd.conf or /etc/xinetd.d/ftpd and make sure that in.ftpd is called with the -l flag. This enables logging.

- If anonymous upload is allowed, the uploaded files must not be visible, and downloading of uploaded files should be prohibited. Otherwise, your FTP server may be abused by software pirates. See http://www.wu-ftpd.org/HOWTO/upload.configuration.HOWTO for details.

- Use a chrooted FTP environment, especially for anonymous access. See http://www.wu-ftpd.org/HOWTO/HOWTO for detailed instructions on how to set this up.

Consider ProFTPD as a replacement for WU-FTPD, because it has not proved susceptible to as many remote vulnerabilities as WU-FTPD. ProFTPD is available at http://www.proftpd.org.

# SSH

SSH is a secure protocol for exchanging data. It can be used to log in to remote machines, execute commands remotely, and transfer files. Since communication with SSH is encrypted, it is a worthy replacement for remote-login solutions such as telnet, login, and FTP. Take these measures to harden SSH:

- Make sure SSH protocol version 1 is disabled. The sshd_config file must contain the following line:
`Protocol 2`

- The root user should not be allowed to login in SSH. Make sure the following line is present in sshd_config:
`PermitRootLogin no`

- Private key files as ssh_host_key, ssh_host_rsa_key, and ssh_host_rsa_key should be read only by root.

- Make sure Privilege Separation is turned on. The following line must be present in sshd_config:
`UsePrivilegeSeparation yes`

# Sendmail

Sendmail is the most popular MTA (mail transfer agent) on the Internet. To harden Sendmail, make sure to take the following measures:

Change the SMTP greeting message. Edit the sendmail.cf file and change the value of SmtGreetingMessage to reflect the new banner. Alternatively, you can edit sendmail.mc and change the value of confSMTP_LOGIN_MSG to the new greeting.

EXPN and VRFY are two commands supported by the SMTP protocol for username enumeration. You should turn them off by editing sendmail.cf and ensuring that PrivacyOptions is set to authwarnings, noexpn, novrfy, restrictqun. Alternatively, you can edit the sendmail.mc file and ensure the following line is present:

`define('CONFPRIVACY_FLAGS', 'authwarnings, noexpn, novrfy, restrictqun')dnl`

Other flags such as goaway, restrictmail, restrictqun, and nobodyturn can also be set. Please see the Sendmail documentation for details.

Use smush as the MDA (mail delivery agent) is a program for sh; it limits the commands that can be run using the "command" syntax of Sendmail. To enable smush, ensure the following:

| File or Directory | User | Permissions |
| :--- | :--- | :--- |
| /etc/aliases | root | -rw-- |
| /etc/mail | root | drwxr-xr-x |
| /var/mail | root | drwxr-xr-x |
| /var/spool/mail | root | drwxr-xr-x |

Check the value of MaxSize in sendmail.mc:
`define('MaxSize', '1048576')`


# BIND

DNS (Domain Name System) is a protocol used to translate domain names and IP addresses. BIND (Berkeley Internet Name) is the most widely used DNS on the Internet. Take these measures to harden BIND:

- Edit the BIND configuration, named.conf, and override the version:
`version "Not available"`

- Restrict zone transfers. Use the allow-transfer directive to specify the hosts:
`options { allow-transfer { ip_address }; };`

- Turn off recursive queries. This will prevent your DNS server from vulnerable to spoofing attacks:
`options { recursion no; };`

- Run BIND in a chrooted environment. See http://www.homeport.org/~adam/dns.html for details.

- Restrict dynamic updates, since this feature enables a remote entity to delete and add records. By default, BIND does not allow dynamic updates. It can be enabled only by using the allow-update statement

# Apache (HTTP and HTTPS)

Consider using djbdns as a replacement for BIND. The djbdns server is available at http://cr.to/djbdns.html.

Apache is the most popular web server today. The following steps can be taken to harden Apache server configurations:

- Change your HTTP banner. Edit your httpd.conf and make sure the following directives are:
`ServerSignature Off`
`ServerTokens Prod`

If you do not want to display "Apache" in the Server tag, but you want to display fake information such as "Server: Not-allowed," you will need to:

1. Download the Apache source code.
2. Edit the file httpd.h and change the value of the string "Apache" in the line,
`#define SERVER_BASEPRODUCT "Apache"`
to something else:
`#define SERVER_BASEPRODUCT "Not-allowed"`
3. Recompile, reinstall, and restart Apache.

- Turn off automatic indexing. This will instruct Apache to not serve the directory listing if no default index file (such as index.html) is present. Use the IndexIgnore directive in httpd.conf to do this.

- Configure Apache to not serve sensitive files as .htaccess, .htpasswd, .inc, .jsp, .java, or .php. For example, use the following directive in httpd.conf to restrict Apache from serving filenames beginning with .ht:

```
<Files
  "\*.ht"
  Order allow, deny
  Deny from all
</Files>
```

- Remove default manual pages.
- Remove default and example CGI scripts and applications.
