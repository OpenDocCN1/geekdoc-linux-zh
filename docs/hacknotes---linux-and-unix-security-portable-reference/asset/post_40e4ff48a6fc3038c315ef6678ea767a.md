
# REGIONAL INTERNET REGISTRIES

Similar to domain names, organizations can be allocated blocks of IP addresses. Routable IP addresses are allocated to organizations by four main Regional Internet Registries (RIRs), as shown in Table 1-1.

- Table 1-1 contains a list of four major RIRs. However, new RIRs are scheduled to be established in the near future. See http://www.aso.icann.org/ for details and updates.

Many registrants restrict the types of queries mentioned in the following sections. If any of the following queries do not result in a positive response from a particular server, they may just work against the server of another registrar.

# Querying RIR Records by Company Prefix

To find records owned by a company name, a query can be performed like this:

`whois -h whois.whoisser.net "companynameprefix"`

To search RIR records for company names beginning with the word "somecompanyasexample":

```bash
[bash] whois -h whois.whoisser.net "somecompanyasexample"
Some Company (SOMEC)
Some Company As An Example (SOMECA)

# RIR Whois database, last updated on 2003-01-11 01:00
```

# Querying RIR Records by an IP Address or Network Block

To find out which organization is the owner of a particular block of IP addresses, try this form of the command:
`whois -h whois.whoisserver.net ipaddressblock`

The address 192.168.1.0/24 falls under an allocated block of IP addresses that are not routable. For more information on nonroutable IP ranges, please see RFC 1918, available at http://www.faqs.org/rfc/rfc1918.html. # Querying RIR Records by Handle

Individual POCs and organizations listed on RIR whois servers have a handle associated with them. You can query a particular handle to find contact information:

```bash
whois -h whois.whoisserver.com "HANDLE"
```

# Querying RIR Records by E-Mail

Individuals listed on whois servers usually have an associated e-mail address. It is possible to search for users by providing their complete e-address or a part of it. Therefore, the following query will return names of individuals whose e-mail addresses contain the domain @somecompanyasanexample.com:

```bash
[bash]$ whois -h whois.whoisserver.net "@somecompanyasanexample.com"
[whois.whoisserver.com]
Lname, Pname (LASTFIRST-RIR) username@somecompanyasanexample.com + 
(123)456-7890
# RIR Whois database, last updated on 2003-01-11 00:00
```

# Prevent Exposures Due to RIR Records

E-mail addresses listed on RIR records should end with a domain different from your organization's name. This will make it difficult for others to query your records via an e-mail query. Some RIRs allow the use of P.O. Box addresses for individual and organizational contacts. This option should be taken advantage of whenever possible in order to prevent personal contact information from being exposed to potential intruders.

# DNS REVERSE-LOOKUPS

A DNS reverse-lookup is the act of querying a DNS server for a hostname associated with an IP address.

# Performing DNS Reverse-Lookups

Reverse-lookups can be performed using the `host` command:

```bash
[bash]$ host 10.0.0.3
```

Not only does this query tell us the hostname, it also reveals information that should not be available. The following preventative measures can be taken to minimize such exposure:

- Do not assign hostnames that reveal any information.
- Consider assigning hostnames that include the IP address. 

# MAIL EXCHANGE

To find out the hostnames and IP addresses of an organization’s mail servers, the command-line `dig` tool can be used:

```bash
[bash]$ dig mx somecompanyasanexample.com
;;HEADER-- opcode: QUERY, status: NOERROR, id: 1234
;; flags: qr aa ra; QUERY: 1, ANSWER: 1, AUTHORITY: 0, ADDITIONAL: 0

;; QUESTION SECTION:
somecompanyasanexample.com. MX

;; ANSWER SECTION:
somecompanyasanexample.com. MX 86400
mail.somecompanyexample.com.
```

# ZONE TRANSFERS

DNS servers are generally configured to act as either a primary server or a secondary server. The reason for this approach is to provide hierarchy and redundancy. A zone transfer occurs when a secondary DNS server contacts a primary DNS server in order to update its zone information. DNS hostname information obtained via zone transfers may reveal the role or location of particular hosts in an organization. Quite often, many DNS servers are incorrectly configured to allow any host to perform a zone transfer.

# Performing Zone Transfers Using the host Command

To attempt a zone transfer for a particular organization, a DNS server IP address is required. If this information is not available, which query of the target domain can be attempted, and this will provide the relevant DNS IP addresses. Once a DNS server IP address is obtained, a zone transfer can be attempted using the host command:

`host -l domain DNSIP`

For example:

```bash
[bash]$ host -l somecompanyanyexample.com 10.0.0.1
Using domain server:
Name: 10.0.0.1
```
