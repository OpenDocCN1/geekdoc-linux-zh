The windbind functionality can be tested using the wbinfo command. Executing with the -u option shows all domain accounts translated and the -g option shows all domain groups.

```
[root@client1 root]# wbinfo -u

AD380+Guest
AD380+TsInternetUser
AD380+idsadmin
AD380+krbtgt
AD380+HOST|client1

```

> **Important:** The service called name cache daemon (nscd) interferes with proper functioning of windbind. Never run nscd on systems where windbind runs.

With these settings, the windbind daemon is able to translate domain accounts to local users. We let the system to use windbind by putting a reference in the Name Service Switch (NSS) configuration.

The configuration file for NSS is /etc/nswitch.conf. This file contains entries as:

passwd: files example

This means that when a request for a password comes in, first a routine in /lib/libnss.so is called to resolve it and then a routine in /lib/libnss_example.so. Once the request is resolved, the result is returned to the application. To add windbind to the resolve path, we change the following lines in /etc/nswitch.conf in the following manner:

```
passwd: files windbind
group: files windbind
```

To test this, execute the command:

```
getent passwd
```

This returns not only the entries in the file /etc/passwd, but also the domain accounts that were translated by windbind.
