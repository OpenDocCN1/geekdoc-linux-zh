# DCOP

When you log in to your KDE session, a program called kdeinit is started (by startkde). It triggers other applications, such as dcopserver and the KDE daemon ked, which are responsible for system configuration management and caching (sysoca), interprocess communication, and a lot more. If you really want to understand how this process works and which environment variables and configuration files can influence it, you should read the KDE for System Administrators Guide available at:

```
http://www.kde.org/areas/sysadmin/
```

You can explore your desktop environment and make DCOP calls with the command-line tool dcop, its graphical counterpart kcdop, or with the DCOP language bindings using Perl, Python, Ruby, Java, or any other language supported through the keddbindings package. The dcop command syntax is as:

```
dcop [ application object [function [arg1] [arg2] [arg3] ... ]
```

# Desktop automation with DCOP

To begin with your desktop automation, just call dcop, check the output, and go further down the pipeline. In Example F-3 on page 327, you can see how this works in practice. After listing all applications registered with the DCOP server (of which include process IDs, as console's process ID 366), we open a new KDE session and display the first session name afterwards. Next, we list our e-mail accounts, check e-mail, compact all e-mail folders, and open a new KMail composer window with a few defined values.

Example: F-3 DCOP in action

```
% dcop
konsole-366
kmail

% dcop console-366 console newSession
% dcop console-366 session-l sessionName
% dcop kMailIface accounts

% kmail default checkKMail
% kmail default compactAllFolders
% kmail default openComposer info@kde.org "" "Subject" "DCOP Rocks" 0
```

In Example F-4, we open our favorite URL in Konqueror and generate another browser window with two preloaded tabs. The new line switches Konqueror to full screen mode, which is useful for presentations or unattended Kiosk mode.
