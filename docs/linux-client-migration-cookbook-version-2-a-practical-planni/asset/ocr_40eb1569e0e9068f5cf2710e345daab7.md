Because of how windbind works (namely, handling the first out in the range to the first domain user has to authenticate and then storing the mapping), the mapping between domain user and uid is not the same on all clients. > Important: When windbind fails because the Kerberos connection is lost because of time skew, the daemon has to be restarted after fixing the skew.

The windbind daemon translates users and generates home directories and shells. These home directories are not created by windbind. We show you how to this in 9.4.3, "PAM and home directories" on page 212.

Using windbind creates the connection to the domain for translating users. To enable domain users to log on to the Linux client, we need a change in the PAM configuration, as shown in the section 9.4.1, "How to authenticate users using windbind and PAM" on page 208.

# 9.2.2 Alternate implementations of windbind

The primary difference in the alternative implementations is the way that uid and gid are generated by windbind. In the previous section, windbind chooses uid and gid for each user from the range provided. This generally happens with the order used, which means it is not the same on all clients in a domain.

- idmap_ad back end to obtain uid and gid from an AD with an extended schema (for example, extended with Services for UNIX)
