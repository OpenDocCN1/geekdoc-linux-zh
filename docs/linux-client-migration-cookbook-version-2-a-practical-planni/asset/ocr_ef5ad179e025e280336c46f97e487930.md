These idmap back-ends are quite new and, thus, still a bit experimental. Both remove one of the disadvantages of windbind as a solution in enterprise environments.

# idmap_rid backend

This back-end calculates a uid and gid for users based on the domain SID. To enable this option, include the lines in Example 9-8 in the smb.conf file.

Example 9-8 Example of entries in smb.conf to use the idmap_rid backend

| idmap uid = 10000-20000 |
| idmap gid = 10000-20000 |
| idmap backend = idmap_rid:AD6380=15000-20000 |
| allow trusted domains = no |

Use these settings and set the default domain to not clearly distinguish the domain accounts. Part of the output of getent passwd looks like Example 9-9.

Example 9-9 Partial output of getent passwd when using idmap_rid


It is clear from the output in Example 9-9 that this is no longer a simple algorithm for picking the uid and gid after the other in the allowed range. The major advantage of this is that the mapping is same for all clients within the AD6380 domain.

# idmap_ad backend

In the next section about LDAP, the concept of the Microsoft Services for UNIX (SFU) is explained. Using the SFU, the schema for the Active Directory is extended with uid and gid information. Using the idmap_ad backend, it is possible to get at this information and use with windbind.
