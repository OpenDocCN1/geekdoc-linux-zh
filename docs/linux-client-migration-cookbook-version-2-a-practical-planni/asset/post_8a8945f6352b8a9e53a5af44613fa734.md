## Components of a Linux Standards Base

Built from a foundation of existing standards, LSB delineates the binary interface between an application and a run-time environment. Existing standards that LSB draws from include Single UNIX Specification (SUS), System V Interface Definition (SVID), for the Intel Itanium processor, C++ ABI, and System V Application Binary Interface (ABI). At the same time, LSB builds on earlier efforts that attempted to prevent UNIX fragmentation, such as POSIX and SUS. In fact, it uses POSIX source code standards and SUS interface definitions.

Although LSB has incorporated the durable aspects of these precursors, because of this, the FSG has learned from the UNIX experience, and, of this, LSB has not adopted the limitations of POSIX and SUS. Notably, POSIX defined only programming interfaces and could not guarantee binary compatibility. The other end of the spectrum, such as OSF/1, which aimed for binary compatibility, were found to be too restrictive. LSB strikes a balance between the two approaches—It includes a binary compatibility layer that splits the difference between the approaches taken with POSIX and OSF/1.

LSB formalizes the framework for interface availability within individual libraries and itemizes the data structures and constants associated with each interface. Figure 1-2 on page 12 illustrates the component organization in the LSB 3.1 environment. These components include shared libraries required by developers (including C++), file system hierarchies (defining where files are located in the system), specifications for the behavior of public interfaces, application packaging details, application behavior pre- and post-installation, and so on.

## Difficulties in targeting the Linux Operating System

Ian Murdock, Chief Technology Officer of Free Standards Group, has been involved in standards development since the evolution of UNIX in the early 1990s. "Previously,"Murdock said, "developers would have to sit down and create the target—maybe Red Hat, Novell, and Debian—then create individual ports for each of distributions."

> LSB essentially provides a single platform that an application developer can target. Applications typically work across all distributions compliant with LSB. It is all about maximizing the addressable market.

Prior to 3.1, LSB has been focused primarily on core components such as C and C++ run-time environments, areas typically associated with server applications. With the LSB core firmly established as an ISO standard, the LSB 3.1 release targets a higher level up the stack.
