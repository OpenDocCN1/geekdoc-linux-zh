# Progression Desktop architecture

Some of the benefits to developing on Linux are the wide variety of higher-level languages available on the Linux platform. When developing for Progression Desktop, the majority of the engine code needed to be portable between the Windows and Linux versions. When looking for a high-level language that was equally supported on Windows and Linux, that provided robust run-time services, such as the Windows registry or GNOME GConf, the development environment that made the most sense to use was Microsoft Visual C# (pronounced "C sharp"). While first was created by Microsoft as a competitor to Java, the Mono project implemented the language and run time to provide a Linux compatible implementation as well. However, because a native user interface for all platforms was, a c#-based GUI program was not suitable for KDE-based desktops at the time of this writing. The Linux GUI uses another-level, flexible language; Python. Python was chosen in addition to its object-oriented nature and dynamic run-time flexibility, the PyGT and Qt libraries for developing graphical applications are quite mature. By creating Python base classes for each step and deriving a GTK and Qt version from those classes, Progression Desktop manages to provide a native look-and-feel in its Linux GUIs with only a minimal amount of duplicated code.

One of the major design goals of Progression Desktop was extensibility. With many unique choices of applications in both Windows and Linux for each of the common and targeted migration data sets, Progression Desktop needed to be able to migrate to several different configurations. For instance, a user who had been running Microsoft Outlook might want to migrate to Evolution, while another user might migrate from Mozilla Mail to Thunderbird. In order to achieve this goal and be able to run on both Windows and Linux, Progression Desktop utilizes a plug-in-based architecture and XML data files running on the .NET platform. The three main technologies developed for this are the PNP file format, the Settings Packages, and the plug-ins as Transforms and Accessories.
