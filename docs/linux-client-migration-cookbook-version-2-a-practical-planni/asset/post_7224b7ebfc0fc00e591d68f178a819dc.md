Given the open source of the Linux operating system and related software, it is also possible to use it completely free of license and support costs. For support, the organization is then completely dependent on the open source community and well-trained personnel within the organization.

## Hardware cost

Most Linux distributions run well on older hardware. Depending on your client application requirements, it is even possible to reuse hardware that has already been retired because it cannot support the latest Microsoft Windows performance requirements.

However, the new enterprise distribution offerings for the desktop have minimum memory requirements that approach the same requirements of Microsoft Windows. Because this is a memory requirement only, you might still be able to use existing or ever retired systems to support these distributions.

## Application cost for the base desktop client

The Linux distributions include large number of basic applications such as editors, imaging software, browsers, e-mail applications, instant messaging applications, and some office productivity tools such as word processing, presentation, and spreadsheet applications. This means that the cost for these basic applications when using a Linux client is small to none.

If an application is not included in the distribution, chances are that there is an OSS equivalent that can be installed free of cost.

## Management and support costs related to the client

In any medium to large enterprise, keeping any production desktop client operational and free of bugs and security exploits is usually one of the largest cost factors. This does not change in a Linux-based client strategy. But, the fact that the operating system is UNIX-like introduces a lot of innovative cost-saving strategies for consideration. For example, because the client can be remotely connected and managed using telnet or SSH protocols, it is possible to install scripts on the client that can easily be executed.

Using remote scripts, it is possible to monitor the clients for problems and to execute a task on all clients from a central server. For example, it is possible that a bugfix can be implemented on all clients by remotely executing a script on the client that is able to fetch a patch and install it, without user interruption.

A key consideration here is how the organization plans to use distributed system management tools. These management tool suites are available as additional add-ons, or from enterprise Linux vendors, included as part of the operating system packaging. Examples are Red Hat Network from Red Hat and the ZENWorks Suite from Novell.

> Note: For medium to large enterprises, you can expect that the business case for a migration cannot be entirely justified by a potential cost savings in operating system and application software licensing fees. In fact, in a client migration scenario, you should expect that the most important consideration that comes into play is the overall cost of *managing the client computing infrastructure on an ongoing basis*

As the size of the supported client base scales up, these costs (IT staffing, support and help desk, system upgrade and replacement, and protection from viruses and other attacks, and so on) greatly overshadow the costs of recurring operating system and application software licensing.

This is why we strongly recommend the approach of building a cost justification model for a client migration to Linux should emphasize the potential for introducing innovative ways to achieve savings in how enterprise client platforms are managed. The integrated management tool suites provided by IBM Linux business partners (Novell and their ZENWorks; Red Hat and their Red Hat Network) provide important value-added features that any enterprise must consider implementing as part of a Linux client plan.

Enterprise management tooling is discussed further in Best Practices, 6.8, "Use a systems management tool" on page 136, and details about several tooling platforms are included in Appendix B, "Using enterprise management tools" on page 255.

## 2.1.3 Manageability of the Linux client

As stated in the previous section, one of the major considerations related to client choice is the way the client can be managed. Some of the inherent properties of the Linux operating system, as well as tools developed in either the open source community or by vendors, make the Linux client very manageable client alternative.

The properties and tools we discuss in this section are:

- Modular structure of the operating system
- Update mechanism
- Inherent remote access
- Remote management and provisioning tools

## Modular structure of the operating system

The Linux kernel has, by design, a modular structure. This means that the kernel is not one monolithic binary. Instead, it consists of a central smaller kernel binary with various kernel modules. The kernel modules can be loaded when needed. Some of the modules have to be loaded at boot, because these need to read file systems or other peripheral hardware.

Not only is the kernel module, but the application framework around the kernel has a modular construction as well. The applications such as scripting engines (Perl, PHP, and Python) or editors (gedit, and vi) are not integrated into the operating system and can be replaced by others or new versions or less independently.

The modular nature of Linux means that updates or patches only affect a small part of the system, for example, either a single application binary or a library within the application framework or a single kernel module. This modularity is the main reason that an update or a patch almost does not require a reboot on Linux.

## Update mechanism

The update mechanism for Linux does not need to be central to the system. What we mean by this is that updating or patching is not destructive to the system state (in other words, a reboot), it can be done while others applications are running. Unless the update or patch impacts the core kernel or a running application, it can be done online.

This means that the mechanism that checks for new updates can be scheduled regularly and can be allowed to implement the changes automatically.

## Inherent support for remote access

The Linux operating system has inherent remote access through TCP/IP, like UNIX operating systems. This is a really powerful tool for systems management, because all management tasks can be done remotely, and since the advent of the secure socket layer can be done securely using SSH.

Remote access to the client is useful for two types of administrative tasks:

- Remote execution of administrative programs or scripts
- Access to the client from a central location to give support on the client

## Remote execution

Remote execution is used to execute applications or scripts from a central location, for example, to force all clients to update a virus scanner or fetch critical security patch. This can also be used to execute monitoring scripts that enable the administrator to do preventive work, for example, to clear a temporary directory before a file fills up.

## Remote support

Almost all on the client can be provided by accessing the client from a remote location. The only types of problems that still require hands-on interaction at the client are network problems. All other problems reported by the user can be handled by logging into the client remotely and studying the system configuration and the log files. This capability could improve the effectiveness of helpdesk staff significantly.

## Remote management and provisioning tools

There are a lot of tools available in the open source community as well as from commercial parties for remote management or monitoring and provisioning. Some of the most popular tools are:

- Webmin
- Big Brother/Big Sister
- Nagios

Webmin is mainly used for remote management of a single machine. Big Brother and Nagios are mostly used to monitor run-time properties of a network of machines, then to apply administrative tasks when system properties go outside of established limits.

Commercial tools are available for these tasks as well. For example, IBM provides Tivoli Configuration Manager and Tivoli Monitoring for automation of monitoring and remote management tasks.

Red Hat Linux distributions can use the Red Hat Network (RHN) to remotely manage individual systems or groups of systems. The RHN also offers automatic provisioning services as described in "Administration of Red Hat Desktop" on page 91.

Novell Linux Desktop distributions use ZENWorks software to remotely manage or provision systems, as described in "Administration of Novell Linux Desktop" on page 93. After Novell acquired Ximian, the SUSE Linux distributions adopted Ximing's Red Carpet product (now under the ZENWorks name) as the standard tool for their enterprise distributions.
