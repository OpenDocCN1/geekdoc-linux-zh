## 1.6 Linux overview and distribution choices

In 1984, the Free Software Foundation (FSF), started by Richard Stallman, began the GNU project to create a free version of the UNIX operating system. This system can be freely used, but even beyond that, the source code can be freely read, modified, and redistributed. A number of components were created, including compilers and test editors. However, it lacked a kernel. In 1991, Linus Torvalds began developing an operating system in a collaborative way. All information made available for anyone on the Internet to improve the operating system that was called Linux. Linux was exactly the operating system kernel the FSF needed.

In the community, different organizations have created different combinations of components built around the kernel and made them available as a bundle. These bundles are called distributions. Some of the most well-known distributions include Fedora and Red Hat Enterprise, openSUSE Linux, Debian, and a derivative of Debian, Ubuntu Linux.

Linux is a UNIX-like, POSIX-compliant operating system distributed under the GNU software license. This means that the operating system can be distributed for free. Linux supports all the major window managers and all the Internet utilities, such as File Transfer Protocol (FTP), telnet, and Serial Line Internet Protocol (SLIP). It provides 32-bit and 64-bit multitasking, virtual memory, shared libraries, and TCP/IP networking. It is coupled to a POSIX thread library for high-performance multithreading, symmetric multiprocessing (SMP) up to 16 logical CPUs or eight hyperthreaded CPU pairs, and massive parallel processing (MPP) up to 1000 AMD Opteron processors in a new Cray computer under development.

Linux has been developed to run on the x86, Itanium®, AMD64, and IBM System z™, System™, and System™ servers and S/390® architectures. A common source code base is used for all of them.

## From Server to Desktop: Linux Standard Base Engages Application Developers Worldwide

The opportunities and the promise of LSB as a stabilizing force to build greater acceptance for Linux at the enterprise level, particularly on the desktop, substantial.

For years, the open source development community has been engaged in the quest for a stable, unified, well-supported operating system (OS) — a reliable platform to provide the foundation for large-scale adoption at the enterprise level. While the UNIX* OS has fulfilled many of the requirements of large-scale organizations as a cost-effective, reliable server OS, its adoption at the desktop level has been less common. Part of the reason for this is the relative lack of full-featured applications for the desktop. The varied nature of non-standardized Linux makes it difficult or impossible to reach a global audience.

The substantial costs of porting applications impose a burden on developers targeting applications for various operating systems. Particularly in the case of Linux OS, ISVs have been forced to grapple with multiple distributions of the operating system, often supporting multiple versions of the kernel, libraries, and applications. To expand the availability of applications for the Linux OS platform and minimize the development tasks, standardization is vital. To avoid the mistakes of the past, many of those who were strongly involved with UNIX are committed to achieving wider acceptance. A positive step in that direction has been the emergence of Linux Standard Base (LSB).

The Free Standards Group (FSG) was founded to bring together participants and establish a working standard for the Linux OS that addresses binary portability and application development concerns. This purpose was achieved with the ISO/IEC ratification of LSB, which brings balance and order to the creation of desktop applications.

This landmark ratification by the International Standards Organization (ISO) and International Electrotechnical Commission (IEC) points toward the emergence of a thriving, competitive Linux ecosystem that will encourage innovation and increased market opportunities. Both software vendors (ISVs) and users benefit from the expanded options and increased flexibility in the selection of operating systems. Now is an excellent time for software companies and developers to become engaged in advancing LSB and producing innovative applications for this platform. The Linux Desktop Project, initiated in 2005 and discussed later in this paper, focuses on standardizing the Linux environment and establishing a commonality upon which developers can rely.

From a market perspective, the state of the Linux Desktop OS is relatively immature, but a number of indicators show that the arc of innovative development for the desktop is rapidly increasing. The latest Linux OS desktop versions available today enable a very friendly user experience. Also, the addition of application suites, such as OpenOffice 2.0, provide a viable alternative to proprietary desktop tools.
