# URL restrictions

It is possible to restrict URL-related actions by the Kiosk framework based on the action, the URL in question, or in some cases referring the URL. You can see in Example 7-5, the syntax is quite long, so we will explain some simple cases.

Example 7-5 URL restriction: General syntax

```
[KDE URL Restrictions]
rule_count=<N>
rule_1=<act>,.<ref_proto>,.<ref_host>,.<ref_path>,.<proto>,.<host>,.<path>.<enabled>
rule_N=<act>,.<ref_proto>,.<ref_host>,.<ref_path>,.<proto>,.<host>,.<path>.<enabled>
```

In the first part of Example 7-6, you can see how to disable browsing with KDE's file dialogs outside the $HOME directory by using the list action. The first rule disables browsing on the local file system, which enables browsing in the $HOME directory, which is exactly what you want. Usually, you can also see that KDE expands the environment variable $HOME. You have to put [$e] after the entry name, or even [$i] to prevent the application replacing the entry with the actual environment value after saving, but this is not necessary everywhere. The second part of Example 7-6 shows how to allow the user to open files in the $HOME and $STMP directories but nowhere else on the file system (opening files from the Internet is still possible though).

Example 7-6 URL restriction examples

```
[KDE URL Restrictions][$i]
rule_count=2
rule_1=list,....file,,false
rule_2=list,....file,$HOME.true
```
