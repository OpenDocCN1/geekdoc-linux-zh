After we start executing the command service vncserver start, we can connect to VNC client and work on the complete graphical interface.

> **Important:** Allowing complete access through VNC can be dangerous, because it enables connecting to the local X server from any place. If it is needed, editing /etc/hosts.allow or /etc/hosts.deny can allow you to limit who can access the workstation.

# Preparing to integrate with Windows network services

The next step in our migration is to connect the client to the existing networking services. In our existing environment, we integrate with Windows NT and Windows 2000 servers, so we follow the instructions in Chapter 9, "Integration how-tos"

Our first goal is the ability to use the services of the existing Windows domain, primarily using user authentication. In order to be able to log on to the Linux client using Windows usernames and passwords, it is necessary to set up windbind.

We edited /etc/samba/smb.conf for a proper setup in our network environment.

Example 8-2 Changes to smb.conf for Linux client domain authentication

```
workgroup = ITSAUSNT
security = domain
password server = ITSONT00,ITSONT01,ITSONT02,ITSONT03
...
windbind separator = +
idmap uid = 10000-20000
idmap gid = 10000-20000
windbind enum users = yes
windbind enum groups = yes
template homdir = /home/%U:%D%U
template shell = /bin/bash
```

# 8.3.2 Integrating existing network services

After the windbind daemon has started, the command wbininfo -u should deliver the current user list of the Windows domain. Before this works, it is necessary to join the domain with the Linux client. As long as there is no machine account in the domain for the client, it is not possible to fetch the list of users using windbind. Therefore, we have to join the domain with the following command:

```
net join - ITSAUSNT -U administrator
```
