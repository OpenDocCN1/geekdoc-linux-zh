## E-2 Editing gconf2 entries with the graphical gconf-editor

gcontool-2 is a command line application, which provides the access to the same information and is quite useful for scripting purposes. The number of configuration options that are available to the gcontool-2 tool are vast and too numerous to list in this book. To display the current options that are set for the GNOME desktop, enter the following command:

gcontool-2 -R /desktop

Although we do not cover all options, we show how we customize our desktop and explain each of the commands that are used. To list all the settings associated with the desktop background, enter the following command:

gcontool-2 -R /desktop/gnome/background

This displays the following default values:

```
color_shading_type = solid
secondary_color = #585768
primary_color = #585768
picture_filename=/usr/share/wallpapers/suse-1024x768.jpg
picture_options = stretched
picture_opacity = 100
draw_background = true
```

The following code changes the wallpaper to a corporate logo:

gconftool-2 --type string --set /desktop/gnome/background/picture_filename /usr/share/backgrounds/images/corporate_logo.jpg

Immediately after running the command, the wallpaper should change to the newly specified path.

For further information about how to make mandatory changes to GConf, 7.1.2, "GNOME lockdown options" on page 151.

# Desktop automation and scripting

In this appendix, we present details about several scripting and automation capabilities of Linux applications. These capabilities allow users and administrators to fully control their environment and automate many desktop management and configuration tasks.

## Scripting languages

Open source scripting languages for Linux as Perl, Python, Ruby, ECMAScript, or Tcl, have been ported to diverse operating systems, including Windows and Mac OS X. The typical Windows scripting language, Visual Basic, and the related project, Visual Basic for Applications (VBA), are not directly available for Linux; although there are similar projects available through commercial offerings (such as RealBasic, "Application porting" on page 329) or through free implementations (such as StarBasic in OpenOffice):

```
http://www.thefreecountry.com/compilers/basic.html
http://documentation.openoffice.org/How_TO/various_topics/VbaBasicXref.pdf
```

All of these Basic dialects are certainly relevant from a compatibility point of view (for example, for Excel migration), but they do not play a central role in the foundation of the GNOME or KDE environments, because there are many other natural choices.

## Shell scripting

The traditional way of scripting on Linux (and UNIX) machines involves shell scripting. Shell dialects include bash, ksh, and tosh. Shell scripts are the equivalent of batch files on Windows, except that they are significantly more powerful. Shell scripts are frequently used for startup routines (such as those found in /etc/init.d) or as wrappers around more complex programs (such as Mozilla or OpenOffice). More information about programming with shell scripts can be found at:

- Linux Shell Scripting Tutorial: http://www.frees.org/guides/lsst
- Advanced Bash-Scripting Guide: http://www.tdp.org/LDP/abs/html/

## Perl

Perl (Practical Extraction and Report Language) is a flexible and powerful scripting language. Perl was originally developed for text manipulation, and now can be used for much more. An impressive collection of third-party modules are available at the Comprehensive Perl Archive Network (CPAN). While enthusiasts say that Perl's philosophy of "TMTOWDI" ("More Than One Way To Do It") makes Perl easy to use, others can make a legitimate claim that such philosophy makes code difficult to read and maintain.

## Python

Python is a modern object-average scripting language that has remarkable power while still maintaining clear syntax. There are built-in libraries, which provide abstractions for many platform specific features (such as file access and threading), and many built-in or third-party open source libraries for graphical applications (such as PyGTK, PyQt, and wxPython, and bindings for Mac OS X and Microsoft Foundation Classes (MFC)). New modules can be written in either Python, C, or C++. While an entire application can be written in Python, it is also frequently used as an extension language for applications that have a built-in plug-system

Red Hat uses Python extensively in the installation process and at many other places. Tools, such as kudzu (which is also used for hardware recognition in the Debian-based Knoppix distribution), are available as Python modules, too. While using **kudzu --probe** is straightforward, the Python wrapper allows administrators to write their own hardware recognition scripts in a much more elegant fashion, as seen in Example F-1

Example: F-1 Hardware recognition with kudzu and Python

```
#!/usr/bin/env python

kudzu
print kudzu.probe(kudzu.CLASS_SOCKET, kudzu.BUS_PCI, kudzu.PROBE_ALL)
print kudzu.probe(kudzu.CLASS_NETWORK, kudzu.BUS_PCI, kudzu.PROBE_ALL)
```

```
devices = kudzu.probe(kudzu.CLASS_UNSPEC, kudzu.BUS_UNSPEC, kudzu.PROBE_ALL)
for dev in devices: print dev
```

## Embedded Scripting Languages

Most Linux scripting languages have wrappers for the GTK+, Qt, and wxWidgets libraries, and the whole GK/GNOME APIs. It is possible to write simple desktop applications or panel applets in a scripting language in order to allow for rapid development. Several applications also have embedded languages, which allow for user-customized actions. Such customization is often useful to tailor these applications for your exact business needs. The language used for these embedded capabilities often varies by application. For example, Perl and Python are used in Gnumeric and The GIMP, JavaScript, XUL are used in Mozilla and Mozilla-based projects (such as Firefox and Thunderbird), and Star Basic is used in OpenOffice.org.

## Qt for Applications

Trolltech decided to give ECMAScript (the standardized version of JavaScript) a dominant role in Qt by releasing the Qt Script for Applications (QSA), which is tightly integrated into their framework:

```
http://www.trolltech.com/products/qsa/
```

QSA plays the same role as VBA for Windows and is very easy to use for Qt programmers. It is released under a commercial license for Linux, Windows, and Mac platforms. In addition to that, QSA is released under the GNU GPL for free software.

## KJSEEmbed

A very similar approach is the KDE JavaScript Engine, KJSEEmbed. KJSEEmbed has bindings for Qt, KDE, and DCOP interprocess communication. You can find KJSEEmbed, which is licensed under LGPL, and a lot of documentation at:

```
http://xmelegance.org/kjsembed
http://www.sourceextreme.com/presentations/kjsembed
```

In Example F-2, you see how easy it is to write a simple HTML browser using this toolkit.

Example: F-2 Basic HTML browser by JavaScript

```
#!/usr/bin/env kjscmd

var url = 'http://www.kde.org/';
if (application.args.length)
url = application.args[0];

var mw = new MainWindow();
var box = new QHBox(mw);
mw.setCentralWidget(box);

var view = Factory.createROPart("text/html", box, "view");
view.connect(view.child(0),
  'openURLRequest(const KURL&,const KParts::URLArgs&)',
  'openURL(const KURL&)')
view.openURL(url);

mw.resize(650,500)
mw.show();

application.exec();
```

## Kommander

The developers of the Quanta+ Web development framework introduced a new toolkit called Kommander, which you can use to design KDE Dialogs and widgets by using **kmdr-editor** (a program derived from Qt Designer) and executing them with **kmdr-executor**. Kommander uses XML-GUI description files with embedded DCOP scripts, which can be written in any language to speak the DCOP protocol (such as Bash, Python, Perl, Java, or JavaScript). Kommander allows you to write KDE dialogs by using the powerful DCOP mechanisms itself. It is already used at many places inside Quanta+ (DCOP is also used for the inter-component communication in the KDE PIM framework Kontakt). Take a look at Figure F-1 to see how the integrated DCOP development with **kmdr-editor** looks and can be used for your own purposes. For more information:
