In-life penetration tests we will often gain privileged access to a system and we can leverage those privileges to extract password hashes from the operating system. We can also make and intercept Windows network authentication requests and use them in further attacks like pass-the-hash⁶642 or in relay attacks⁶643.

In this Learning Unit, we'll demonstrate how to obtain hashes from the Windows operating system. We will show how we can crack these hashes or use them to gain access to other systems. For this, we'll cover two different hash implementations on Windows: NT LAN Manager (NTLM)⁶644 hash and NT-NTLMv2⁶645.

# ## 13.3.1 Cracking NTLM

Before we begin cracking NLM hashes, let's discuss the NTLM hash implementation and how it is used. Then, we'll demonstrate how to obtain and crack NTLM hashes in Windows.

Windows stores hashed user passwords in the Security Account Manager (SAM)⁶646 database file, which is used to authenticate locate or remote users.

> To offline SAM database password attacks, Microsoft introduced the SYSKEY file in Windows NT 4.0 SP3, which partially extracts the SAM file. The passwords can be stored in two different hash formats: LAN Manager (LM)⁶647 and NTLM is based on DES⁶648 and is known to be very weak. For example, passwords are sensitive and cannot exceed fourteen characters. If a password exceeds seven characters, it is split into two strings, as hashed separately. LM is disable by default using Windows Vista and Windows Server 2008.
