## 13 Password Attacks

In this Learning Module, we will cover the following Learning Units:

- Attacking network services logins
- Password Cracking Hashes
- Working with Password Hashes

While there are many modern approaches to user account and service authentication (such as biometric authentication⁵593 or Public Key Infrastructure⁵594), simple password authentication remains the most dominant and basic approach.

In this Module, we will discover, reveal, and leverage passwords (and in some cases their implementation components) to gain access to a user account or system. We'll discuss network attacks, password cracking, and attacks against Windows-based authentication implementations.

### 13.1 Attacking Network Services Login

This Learning Unit covers the following Learning Objectives:

- Attack SSH and RDP logins
- Attack POST login forms

In the last decade, brute-force and dictionary attacks against publicly-exposed network services have increased dramatically. In fact, the common Secure Shell (SSH), Remote Desktop Protocol (RDP), and Virtual Network Computing (VNC)⁵595 services as well as web-based login forms are often attacked seconds after they are launched.⁵96

Brute-force attacks attempt every possible password variation, working systematically every combination of letters, digits and special characters. Although this may take a considerable amount of time depending on the length of the password and the protocol in use, these attacks could theoretically bypass any ill-protected password-based authentication system.

On the other hand, dictionary attacks attempt to authenticate to services with passwords from lists of common words (wordlists). If the correct password is not contained in the wordlist, the dictionary attack will fail.

In this Learning Unit, we'll use dictionary attacks to discover valid credentials for network services and HTTP login forms.

### 13.1.1 SSH and RDP

In this section, we execute dictionary attacks against the common SSH and RDP services using the open-source THC Hydra tool, which can execute a broad variety of password attacks against a variety of network services and protocols. We will also use the rockyyou.txt wordlist, which contains over 14 million passwords. Both of these are pre-installed on our Kali machine.

To begin, let's start the machine BRUTE (VM #1 under Resources). In the first example, we'll attack the SSH service (port 2222) on this machine, which has an IP address of 192.168.50.201. We'll attempt to determine the password for the user george.

> The IP address of BRUTE may differ in your environment.

```
kali@kali:- sudo nmap -sV -p 2222 192.168.50.201
```

The listing shows that we used a valid login for the george user. The attack worked because the password was contained in rocky.txt. However, if we didn't validate usernames, we would use enumeration and information gathering to find them. Alternatively, we could attack built-in accounts as root (on Linux) or Administrator (on Windows).

In this example, we will attempt to use a single password against a variety of usernames in a technique known as password spraying.

> There are many different ways to gain access to passwords, this is an extremely viable technique. For example, we may gain access using one of the techniques discussed in this Module, or we may find stored as plaintext in a file or through the use of an online password leak database. Services (such as ScatteredSecrets⁶⁰) track password leaks and compromises and select the plaintext. This can be very beneficial during a penetration test, but we must make sure that we do not violate the terms of these services, ensure that we cooperate with the legal owner, and we review the service carefully to determine if it's operating. For example, WeLeakInfo⁶⁰¹ was recently seized by the FBI and U.S. Department of Justice.

Let's demonstrate this by executing a spray attack on the RDP service by BRUTE2. To do so, let's shutdown the machine (VM #1) and start BRUTE2 (VM #2) under Resources. In this example, we assume we have already obtained a valid user password (SuperS3cure1337#), and we will attack that password against a variety of user account names.

We'll again use hydra, setting a list of usernames with -L /usr/share/wordlists/dirb/others.txt (which contains over thousand username entries) and a single password with -p 'SuperS3cure1337#'. We'll use the RDP protocol to test this and set the target 192.168.50.202.
