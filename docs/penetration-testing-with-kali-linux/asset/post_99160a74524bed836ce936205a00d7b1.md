Having obtained the NTLM hash of the krbtgt account, along with the domain SID, we can now forge and inject our golden ticket.

Creating the golden ticket and injecting it into memory does not require any administrative privileges and can be performed from a computer that is not joined to the domain. We will take the hash and continue the procedure from a compromised workstation.

On Client74 as the user, before generating the golden ticket, we will launch mimikatz and delete any Kerberos tickets with kerberos::purge

We supply the domain SID (which we get from whoami /user) to the Mimikatz kerberos:golden command to create the golden ticket. This time, we use the /krbtgt option instead of /rc4 to indicate the password hash of the krbtgt account user. Starting July 2022, we will need to provide an existing account, so let's get the golden ticket's username to jen.

## 2.2.2 Shadow Copies

A Shadow Copy also known as Volume Shadow Service (VSS) is a backup technology that allows creation of snapshots of files or entire volumes. To manage shadow copies, the Microsoft signed binary vshadow.exe is offered as part of the Windows SDK. As domain admins, we have the ability to use the shadow utility to create a Shadow Copy that will allow us to extract the Active Directory NTDS.dit database. Once we have obtained a copy of said database, we can extract every user credential on our local Kali machine.

To start off, we connect to the DC domain controller and launch the vshadow utility with -nw options to disable writers, which speeds up backup creation and include the -p option to save the copy on disk.
