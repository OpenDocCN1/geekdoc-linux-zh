## 13.3 Working with Hashes

In penetration tests, we will often gain privileged access to a system and can leverage those privileges to extract password hashes from the operating system. We can also make and intercept network requests and use them in further attacks like pass-the-hash. While in most assignments you face an Active Directory environment, this Learning Unit only covers local machines. In this Learning Unit, we'll demonstrate how to obtain from Windows and show how we can crack these hashes or use them to access other systems.

### 13.3.1 Cracking NTLM

Before we begin cracking NTLM hashes, let's discuss the NTLM implementation and how it is used. Then, we'll demonstrate how to obtain and crack NTLM hashes in Windows. Windows stores hashed passwords in the Security Account Manager (SAM) database, which is used to authenticate or locate remote users. The passwords can be stored in two different formats: LAN Manager (LM) which is based on DES and is known to be very weak. For example, passwords are case sensitive and cannot exceed fourteen characters. If a password exceeds seven characters, it is split into two strings, hashed separately. LM is disabled by default using Windows Vista and Windows Server 2008. On modern systems, the systems in the SAM are stored as NTLM. This implementation addresses many weaknesses of LM. However, NTLM hashes stored in the SAM database are not salted. Salts are random bits appended to a password before it is hashed. They are used to prevent an attack in which attackers precompute a list of hashes and then perform lookups on these precomputed hashes to infer the plaintext password. A list or table of precomputed hashes is called a Rainbow Table and the corresponding attack is called a Rainbow Table Attack. We "NTLM hash" to refer to the formally correct NTHash. Since "NTLM hash" is more commonly used in our industry, we use it in this course to avoid confusion. We cannot just copy, rename, or move the SAM database from C:\Windows\system32\config while the Windows operating system is running because the kernel keeps an exclusive file lock on the file. Frankly, we use the Mimikatz tool to do the heavy lifting for us and bypass this restriction. Mimikatz provides the functionality to extract plain-text passwords and password hashes from various sources in Windows and leverage them in later attacks like the hash. Mimikatz also includes the sekurl module, which extracts passwords from the Security Authority Subsystem (LSASS) process memory. LSASS is a process in Windows that handles authentication, password changes, and access token. LSASS is important because it caches NTLM hashes and other credentials, which we can extract using the sekurl Mimikatz module. We need to understand that LSASS runs under the SYSTEM user and is therefore more privileged than a process started as Administrator. Due to this, we can extract passwords if we are running Mimikatz as Administrator (higher) and have DebugPrivilege access right. This access right grants us the ability to debug not only our processes, but also all users' processes. We can also elevate privileges to the SYSTEM account with tools like PsExec or the built-in Mimikatz elevation function to obtain the required privileges. The token elevation function.
