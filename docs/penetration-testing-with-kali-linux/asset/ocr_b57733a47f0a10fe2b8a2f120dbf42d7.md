# OffSec Penetration Testing with Kali Linux

When a running nmap does not have raw socket privileges, Nmap will default to the TCP scan^260 technique. As Nmap TCP connect makes use of the Berkeley sockets API^261 to perform the three-way handshake, it does not require elevated privileges. However, because Nmap has to wait for the connection to complete before the API return the status of the connection, a TCP scan takes much longer than a SYN scan.

We may occasionally need to perform a connect scan using nmap, as scanning when certain types of proxies use. We use the -ST option to start a connect scan.

```
kali@kali:~ nmap -sT 192.168.0.149
```

The output shows that the connect scan revealed a few open services that are only active on the Windows-based host, especially Domain Controllers, as we'll cover shortly. One major takeaway, even from this simple scan, is we can infer the underlying OS and role of the target host.

Having reviewed the most common Nmap TCP scanning techniques, let's learn about UDP Scanning.

When performing a UDP scan, Nmap will use a combination of two different methods to determine if a port is open or closed. For most ports, we will use the standard "ICMP port unreachable" method described earlier by sending an empty packet to a port. However, for common ports, which is used by SNMP, we will send a protocol-SNMP packet in an attempt to get a response from answer bound to port. To perform a UDP scan, we'll use the -U option, with sudo to access raw sockets.

```
kali@kali:~ sudo nmap -U 192.168.0.149
Starting Nmap 7.70 ( https://nmap.org ) at 2019-03-04 11:46 EST
nmap scan report for 192.168.1.131
host is up (0.1ms latency).
not shown: 977 closed udp ports (port-unknown)
```
