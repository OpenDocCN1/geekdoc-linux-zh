# # OffSec Penetration Testing with Kali Linux

As an example, generic boolean-based blind SQL injections cause the application to return different and predictable values whenever the database queries a TRUE or FALSE result, hence the “boolean” name. These values can be reviewed within the application context.

> > Although 'boolean-based might not seem like a SQLi variant, the output used to infer results from the web application, not the database itself.

Time-based blind SQL injections infer the query results by instructing the database to wait for a specified amount of time. Based on the response time, the attacker is able to conclude if the statement is TRUE or FALSE.

Our vulnerable application (http://192.168.50.16/blindsqli.php) includes a code port affected by both types of blind injection vulnerabilities.

Once we have logged in with our offsec lab credentials, we will encounter the following page:

Closely reviewing the URL, we will notice that the application takes a user parameter as input, defaulting to offsec this is our current logged-in user. The application queries the user's record, returning the Username, Password Hash, and Description values.

To test for boolean-based SQLi, we can try to inject the below payload to the URL:

```
http://192.168.50.16/blindsqli.php?user=offsec' AND 1=1 --
```
