# 12.2.2 In-Memory Evasion

In-Memory Injections⁶⁴ also known as PE Injection, is a popular technique used to bypass antivirus products on Windows machines. Rather than obfuscating a malicious binary, creating new sections, or existing permissions, this technique instead focuses on the manipulation of volatile memory. One of the main benefits of this technique is that it does not write any files to disk, which is a commonly focused area for most antivirus products.

There are several evasion techniques⁵⁶ that do not write files to disk. While we will still provide a brief explanation for some of them, we will only cover in-memory injection using PowerShell as the others rely on a low-level programming background in languages as C/C++ and are outside of the scope of this Module.

The first technique we can cover is Remote Memory Injection, which involves injecting the payload into a process that is not valid. The most common method of doing this by leveraging a set of Windows APIs⁶⁷ First, we would use the OpenProcess⁶⁸ function to obtain a valid HANDLE a target process that we have permission to access. After obtaining the HANDLE, we allocate memory in the context of that process by calling a Windows API such as VirtualAllocEx Once the memory has been allocated in the remote process, we copy the payload to the newly allocated memory using WriteProcessMemory⁹ After the payload has been successfully copied, it is executed in a separate process using the CreateThread⁷¹ API.

This sounds complex, but we will use a similar technique in another example, for how PowerShell handles the heavy lifting and a very similar simplified attack targeting a local powershell.exe

Unlike DLL injection, which involves loading a malicious DLL from disk using the LoadLibrary⁷² API, the Reflective DLL injection attempts to load a DLL stored by the attacker in the process memory⁷³

The main challenge of implementing this technique is that LoadLibrary does not support loading a DLL from memory. Furthermore, the Windows operating system does not expose any APIs that can handle this. Attackers who choose to use this technique must write their own version of the API that does not rely on disk-based DLL.

The third technique we want to mention is Process Hollowing⁷⁴ When using process hollowing to bypass antivirus software, attackers launch a non-malicious process in a suspended state.
