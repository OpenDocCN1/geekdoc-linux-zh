# Listing 201 - Testing for boolean-based SQLi

Since 1=1 will be TRUE, the application will return the values only if the user is present in the database. Using this syntax, we could enumerate the entire database for other usernames or even extend our SQL query to verify data in other tables.

We can achieve the same result by using a time-based SQL query:

```
http://192.168.50.16/blindsqli.php?user=offsec AND IF (i=1, sleep(3),'false') //
Listing 202 - Testing for time-based SQLi
```

In this case, we added an IF condition that will be inside the statement itself, but will return false if the user is non-existent.

We know the user offsec is active, so if we paste the URL payload in our Kali VM's browser, we'll notice that the application hangs for about three seconds.

This attack can clearly be very time consuming, so it's often automated with tools like sqlmap, as we'll cover in the next Learning Unit.

# 10.3.1 Manual Code Execution

Depending on the underlying database system we are targeting, we need to adapt our strategy to code execution.

In Microsoft SQL Server, the $xp_cmdshell function takes a string and passes it to a command shell for execution. The function returns any output as rows of text. The function is disabled by default and, once enabled, must be called with the EXECUTE keyword inside SELECT.

In our database, the Administrator has the appropriate permissions. Let's explore xp_cmdshell by simulating a SQL injection via thepacket-mssql tool.

