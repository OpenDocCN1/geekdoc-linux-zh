# OffSec

An effective defensive technique to prevent tools such as Mimikatz from extracting hashes is to enable additional LSA Protection¹⁸. The LSA includes the LSASS process. By setting a registry key, Windows prevents reading memory from this process. We will discuss how to bypass this and other powerful defensive mechanisms in-depth in OffSec's Evasion Techniques and Breaching Defenses, PEN-300.

We can observe two types of hashes highlighted in the output above. This will vary by the functional level of the AD implementation. For AD instances at a functional level of Windows 2003 or later, NTLM is the only available hash. For instances running Windows Server 2008 or later, NTLM and SHA-1 (a common companion for AES encryption) may be available. On older operating systems like Windows 7, WDigest¹⁹ will be enabled. A different approach and use of Mimikatz is to exploit Kerberos authentication by using TGT and service tickets. As already discussed, we know that Kerberos TGT and service tickets for users currently logged on to the local machine are stored for future use. These tickets are also stored in LSASS, and we can use Mimikatz to interact with and retrieve our tickets as well as those of other users.

Let's open a PowerShell window and list the contents of the SMB share on WEB04 via UNC path `web04.corp.backup`. This will create and cache a service ticket.
