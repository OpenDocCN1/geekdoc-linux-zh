# 4.4.1 What is Executable Permission?

Every file on a Linux machine has a number of additional properties associated with it. These include when the file was created, what user created it, which has permissions to read the file, and even the name of the file itself.

File permissions are particularly important. They indicate whether or are not allowed to either read, write, execute a particular file. We think of the word in this context as our ability to make certain changes to a file. This could, for example, be set to not allow us to write to a file, which might keep that file from being accidentally deleted. The permissions might also be set to not allow us to read a file that has information in it we shouldn't be allowed to view.

These are called file permissions,¹⁵⁷ and they pertain to a different types of users who might be on our computer: the file owner, the user ownership, and anyone else. These different classes of users can be given (or denied) permission for each of the three actions above: read, write, and execute. For the sake of this Module, we'll focus only on the owner of the file, in this case.

Let's open a terminal and review how this works in practice. We'll touch¹⁵⁸ a file (filename.txt), which will create it and automatically make us the owner. We'll use the listing command ls¹⁵⁹ to gather information about the file, providing the -l parameter that will produce a long list including the file permissions.
