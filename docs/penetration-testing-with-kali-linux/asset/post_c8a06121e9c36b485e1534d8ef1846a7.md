
For example, the iptables-persistent89 package on Debian saves firewall rules in specific files under /etc/iptables by default. These files are used by the system to restore netfilter4 at boot time. These files are often left with weak permissions, allowing them to be read by any local user on the target system.

We can also search for files by the iptables-save command, which is used to dump the firewall configuration to a file specified by the user. This is then used as input for the iptables-restore command and to restore the firewall rules at boot time. If a system administrator has run it, we could search the configuration (/etc) or grep the file for iptables to infer the file location. If the file has insecure permissions, we could use its contents to find the firewall rules configuration running on system.

Next, letss examine scheduled tasks that attackers commonly leverage for privilege escalation attacks. Systems acting as servers periodically execute automated, scheduled tasks. ```

Each task to run is defined by a single line indicating different fields when the task will run. To define the time you can provide concrete values minute (m), hour (h), day of month (dom), month (mon), year (year) and day of week (dow) or use '*' in these fields (for 'any'). Notice that tasks will be started based on the cron's notion of time and timezones. Output of crontab jobs (including errors) is sent to the user unless redirected. For example, you can run backup of all user accounts every week with:

```
* 0 * * 0
```

```
joe@debian-privesc:~$ sudo crontab -l
* * * * * /bin/bash /home/joe/.scripts/user_backups.sh
```
