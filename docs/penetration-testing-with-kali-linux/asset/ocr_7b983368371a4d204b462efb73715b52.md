Our SOCKS port 1080 is listening on the loopback interface of the Kali machine.

Let's use this to connect to the SSH server on PGDATABSE01. In Port Redirection and SSH Tunneling, we created SOCKS proxy ports with both SSH remote and classic dynamic forwarding, and we use Proxchains to push non-SOCKS-native tools through the tunnel. But we've not yet run SSH itself through a SOCKS proxy.

SSH does not offer a generic SOCKS proxy command-line option. Instead, it offers the ProxyCommand* configuration option. We can either write this into a configuration file, or pass it as part of the command line with -

ProxyCommand accepts a shell command that is used to open a proxy-enabled channel. The documentation suggests using the OpenBSD version of Netcat, which exposes the -X flag to connect to a SOCKS or HTTP proxy. However, the version of Netcat with Kali does not support proxy.

Instead, we use Ncat*, the alternative written by the writers of Nmap. We install this on Kali with sudo apt install ncat
