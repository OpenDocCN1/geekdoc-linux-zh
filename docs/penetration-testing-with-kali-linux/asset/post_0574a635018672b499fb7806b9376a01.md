Listing 637 - options of ssh_login

There are various options to set this module. Fortunately, Metasploit already set some for us. In the example in Password Attacks, we assume we have identified the username. We can specify a single password or provide files containing users, passwords, or other. Finally we use HOSTS to 192.168.50.201 and RPORT to 22.

```
msf6 auxiliary(scanner/ssh/ssh_login) > set PASS_FILE /usr/share/wordlists/rockyou.txt
PASS_FILE => /usr/share/wordlists/rockyou.txt
msf6 auxiliary(scanner/ssh/ssh_login) > set USERNAME george
USERNAME => george
msf6 auxiliary(scanner/ssh/ssh_login) > set HOSTS 192.168.50.201
```

## 20.1.3 Exploit Modules

Now that we are acquired with basic MSF usage and the usage of auxiliary modules, let's get deeper into the business end of MSF: exploit modules.

Exploit modules most commonly contain exploit code for vulnerable applications and services. Metasploit contains over 2200 exploits at the time of this writing. Each was meticulously developed and tested, making MSF capable of successfully exploiting a wide variety of vulnerable services. These exploits are invoked in the same way as auxiliary modules.

In this example, we will leverage one of the exploit modules to get access to the target system WEB1. Let's assume we identified that the system runs an Apache2.4.49 web server and is vulnerable to CVE-2021-40739 vulnerability scan. We will attempt to use Metasploit and its exploit modules to exploit this vulnerability and get execution.

Create a new workspace for this section and search Metasploit modules related to "Apache 2.4.9."

```
msf6 auxiliary(scanner/ssh/ssh_login) > workspace -a exploits
[+] Added workspace: exploit
[+] Workspace: exploit
```

```
msf6 auxiliary(scanner/ssh/ssh_login) > search Apache 2.4.49
```
