Let's review the provided macro skeleton. The main sub procedure used in VBA macro begins with the Sub503 keyword and ends with End Sub. This essentially marks the body of our macro.

> A sub procedure is very similar to a function in VBA. The difference lies in the fact that sub procedures cannot be used in expressions because they do not return any values, whereas functions do.

At this point, our new macro, MyMacro(), is simply an empty sub procedure containing several lines beginning with an apostrophe, which marks the start of a single-line comment in VBA.

```
Sub MyMacro()
  'MyMacro Macro
  '
  End Sub
```

In this example, we'll leverage ActiveX Objects,504 which provide access to underlying operating system commands. This can be achieved with WScript505 through the Windows Script Shell object506.

Once we instantiate a Windows Script Host Shell object with CreateObject,507 we can invoke the Run508 method for Wscript.Shell in order to launch an application on the target client machine. For our first macro, MyMacro() will start a PowerShell window. The code for that is below.

```
Sub MyMacro()
CreateObject("Wscript.Shell").Run "powershell"
End Sub
```

Since Office macros are not executed automatically, we must use the predefined AutoOpen and Document_Open events. These procedures can call our custom procedure and run code when a Word document is opened. They differ slightly, depending on how Microsoft Word and the document were opened. Both cover special cases which the other one doesn't and therefore we use.
