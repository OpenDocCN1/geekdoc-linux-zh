# ## 16.3 Hidden in Plain View

Based on the information found in the previous section, we can assume that the users on CLIENTWK220 use a password manager. We should never underestimate the laziness of users when it comes to passwords and sensitive information. What was traditionally the Post-it note with the password under the keyboard is now often a file on the desktop. While browsing the home directory of our user or publicly accessible files, we can retrieve pieces of sensitive information, which may provide us a vector for privilege escalation.

For example, sensitive information may be found in meeting notes, configuration files, or onboarding documents. With the information we gathered in the situational awareness process, we can make educated guesses on where to find such files.

Let's search CLIENTWK220 for sensitive information. If KeepPass and XAMPP are installed on the system and therefore, we should search for password managers and configuration files of these applications.

For this, we connect to the system's bind shell. Let's begin our by entering C\ as argument -Path and *.kdb -Include to search for all password databases on the system with Get-Item765 in PowerShell.

```
PS C:\Users\dave Get-Item -Path C:\ -Include *.kdb -Recurse -ErrorAction SilentlyContinue
Get-Item -Path C:\ -Include *.kdb -Recurse -ErrorAction SilentlyContinue
```

Listing 388 shows that no password managers could be found in our search.
