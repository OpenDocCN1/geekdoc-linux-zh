
# OffSec

Before we head into the next section, let's briefly review modules again. As stated, modules are used to perform tasks in Metasploit as scanning or exploiting a target. The framework includes several thousand modules, divided into categories.

The categories are displayed on the splash screen summary, but we can also see them with the show-h command.

```
msf6 > show -h parameters for the "show" command are: all, encoders, nops, exploits, payloads, auxiliary, post, plugins, info, options
[*] Additional module-specific parameters are missing: advanced, evasion, targets, actions
```

### 626 Help for the show command

626 shows the categories of Metasploit's modules. To activate a module, we need to enter `use` with the module name. The modules all follow a common slash-delimited hierarchical syntax (module type/of, vendor, app, operation or protocol/module name), which makes it easy to explore and use the modules. We'll be begin exploring auxiliary modules in the next section and dive into exploit modules.

## 20.1.2 Auxiliary Modules

The Metasploit Framework includes auxiliary modules that provide functionality as protocol enumeration, port scanning, fuzzing, sniffing, and more. Auxiliary modules are useful for many tasks, including information gathering (under the gather/hierarchy), scanning and enumeration of services (under the scanner/hierarchy), and so on.

There are too many to cover here, but we will demonstrate the syntax and operation of two very auxiliary modules. To list all auxiliary modules, we can run the `show auxiliary` command. This will present a long list of all auxiliary modules as shown in the truncated output below:

msf6 > search type:auxiliary smb

### Listing 628 - Searching for all auxiliary modules in Metasploit

Listing 628 shows us SMB auxiliary modules the search has identified. As stated before, to activate a module we can use `follow` by the module name, or use the index provided from search results. Let's use the latter to activate the module `auxiliary/scanner/smb/smb_version` index 56.

```
msf6 > use 56
msf6 auxiliary(scanner/smb/smb_version) >
```

### Listing 629 - Activate smb_version

Listing 629 shows we have activated the module `auxiliary/scanner/smb/smb_version`. To get information about the activated module, we can enter `info`.

```
msf6 auxiliary(scanner/smb/smb_version) > info
```

### 630 - Displaying options of smb_version

The output of `info` shows the required arguments:

```
Name | Check | Rank | Description
|---|---|---|---|
RHOSTS | | normal | |
THREADS | | normal | | 
```

The output of `info` shows that `RHOSTS` is required. We can also use `show` to see the available options.

```
msf6 auxiliary(scanner/smb/smb_version) > show
```

### 631 - Displaying options of smb_version

Listing 631 shows that `RHOSTS` has no value set but is required. To set the `RHOSTS` value, can use the `set` command.

```
msf6 auxiliary(scanner/smb/smb_version) > set RHOSTS 192.168.50.20
msf6 auxiliary(scanner/smb/smb_version) >
```

RHOSTS => 192.168.50.20

### Listing 632 - Setting the value of RHOSTS manually

Instead of setting, we can also set the value of `RHOSTS` in an automated fashion by leveraging the results in the database. For example, we can use the `services` command.

```
msf6 auxiliary(scanner/smb/smb_version) > unset RHOSTS
Unsetting RHOSTS...

msf6 auxiliary(scanner/smb/smb_version) > services -p 445 --rhosts
Services =\
```

| host | port | name | state |
|---|---|---|---|
| 192.168.50.202 | 445 | tcp | microsoft-ds | open |

RHOSTS => 192.168.50.202

### Listing 633 - Setting RHOSTS in an automated fashion via Metasploit

Listing 633 uses Metasploit to set the value for the option `RHOSTS` based on the stored results in the database, which, in our case, is the IP of BRUTE2.

Now, that we have all required options, we can launch the module. Let's do this by entering `run`.

```
msf6 auxiliary(scanner/smb/smb_version) > run
```
