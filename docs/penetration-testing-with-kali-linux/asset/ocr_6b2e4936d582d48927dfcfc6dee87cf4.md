Listing 270 - Adding the rule function to the beginning and end of our current rule

The output shows that demo1.rule mutates the passwords by appending the first "1" and then "1". The other file, demo2.rule, appends "1" first and then the "1". This shows that the rule functions are applied from left to right.

The rule contained in demo1.rule mutates the passwords of our wordlist to fulfill the requirements of the password policy.

Now that we have an understanding of rules and how to create them, let's crack a hash with a rule-based attack. In this demonstration, let's assume we retrieved the MD5 hash "f621b6c92eb95ab53ae2ef4c67fe4cb860" from a target system. We'll use the rockyou.txt wordlist, and modify it for a password policy requiring an upper case, a numerical value, and a special character.

Let's create a rule file to access this password policy. Before, we'll use the c function for the capitalization of the first letter. Furthermore, we also use "l" again as special character. For the numerical values we'll append (ever-popular) "1", "2", and "123" followed by the special character.

```
kali@kali:~/passwordattacks$ cat crackme.txt
f621b6c92eb95ab53ae2ef4c67fe4cb860
```

```
kali@kali:~/passwordattacks$ cat demo3.rule
$1 c $
$2 c $
$1 $ $2 $ c $
```

Listing 271 - MD5 Hash and rule file

Next, we run Hashcat. We will disable debugging by removing the --stdout. Instead, we'll specify -m, which sets the hash type. In this demonstration, we want to crack MD5, with hash type 0, which we retrieved from the Hashcat example page. After the hash type, we'll provide the MD5 hash file (crackme.txt) and the rockyou.txt wordlist. Then we'll specify -r to provide our demo3.rule file. As our Kali VM does not have access to a GPU, we'll use -force to ignore related warnings from Hashcat.

```
kali@kali:~/passwordattacks$ hashcat -m 0 crackme.txt /usr/share/wordlists/rockyou.txt
-r demo3.rule --force
hashcat (v.6.2) starting
```
