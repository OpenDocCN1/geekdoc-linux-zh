> Listing 14 - Second attempt after chmod.

After we gave ourselves permission, we did a quick check with ls to find out if the output would change. It did! The output contains the "x" character, indicating that executable permission is allowed for all three users.

Next, we ran our script and, thankfully, we received the expected output time. The script provided us with a list of the current employees.

Let's now change back so that we no longer have permission to execute the file. To add the permission, we use chmod +x, this time we will use chmod -x.

```
kali@kali:- chmod -x find_employee_names.py
kali@kali:- ./find_employee_names.py
zsh: permission denied: ./find_employee_names.py
```

> Listing 15 - Putting things back the way they were

We're back where we started with the same error message as before. From this experiment, we should have a very basic understanding of the executable permission bit, the chmod tool, and the +x and -x options.

# 4.4.2 Going Deeper: Encountering a Strange Problem

Let's take a moment to remind ourselves that it is fine if we are not following all of the technical steps we've been covering. Some of the examples are specifically included to be interesting to students who have a better understanding of Linux.

Let's continue to explore and push our further learning.

We'll consider the fact that the chmod command is just a file. It follows the same rules as other files on the system, including the rules about permissions. It exists in a slightly different location (the /usr/bin/) as our script, but the only reason we are able to run the chmod +x find_employee_names.py command is because the chmod file has its permissions set allow us to run it as a program.
