## 10.1.1 SQL Theory Refresher

Structured Query Language (SQL) has been developed specifically to manage and interact with data stored inside relational databases. SQL can be employed to query, insert, modify, or even delete data and, in some cases, execute system commands. Since the SQL instance offers many administrative privileges, we will soon observe how arbitrary SQL queries can pose a security risk.

Modern web applications are usually designed around a user-facing interface referred to as the frontend, which is typically created using code blocks written in HTML, CSS, and JavaScript. After the client interacts with the frontend, it sends data to the backend application layer that is running on the server. Many different frameworks can be used to construct backend application written in various languages including PHP, Java, and Python. Next, the backend interacts with the data residing in the database in various ways, such as retrieving the password associated with a given username.

SQL syntax, commands, and functions vary based on relational database used. MySQL, Microsoft SQL Server, PostgreSQL, and Oracle are the most popular implementations, and we are going to inspect each variant's characteristics. An example, let's build a simple query to parse the users table and retrieve a specific user entry. We can use the SELECT statement to inspect the database that we want to retrieve records from a specific location defined by the FROM keyword and filter out records belonging to the user.

```
SELECT * FROM users WHERE username='leon'
```
Listing 177 - SQL query that parses the users table

To automate functionality, web applications often embed SQL queries within their source code. We can better understand this concept by examining the backend PHP portion for verifying user-submitted credentials:

```php
<?php
$uname = $_POST['username'];
$password = $_POST['password'];

$sql_query = "SELECT * FROM users WHERE username='$uname' AND password='$password'";
$result = mysqli_query($con, $sql_query);
?>
```
Listing 178 - SQL Query Embedded in PHP Source Code

Highlighted above is a pre-compiled SQL query that searches the users table for the username and its respective password, which are saved into $uname and $password variables. The query string is then stored in $sql_query and used to perform the query against the local database through the mysqli_query function, which saves the result of the query in $result.

Note: So far, we've described a very basic interaction between backend PHP code and the database. Reviewing the above code, we'll notice that both the username and password variables are retrieved from the user request and inserted directly into the sql_query string, without any prior check. This means that an attacker could modify the SQL statement before it is executed by the SQL database to circumvent the intended logic.

Let's consider an example. When the user types leon, the SQL server searches for the username 'leon' and returns the result. In order to search the database, the SQL server runs the query SELECT * FROM users WHERE username=leon. If instead, the user enters 'leon@#$', the SQL server will run the query SELECT * FROM users WHERE username=leon@#. Nothing in our code block checks for these special characters, and it's this lack of filtering that causes the vulnerability. We'll discover how these types of scenarios can be abused in the forthcoming sections.
