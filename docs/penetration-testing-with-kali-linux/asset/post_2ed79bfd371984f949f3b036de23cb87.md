## 888 - Git repository in the WordPress directory

Based on the output in listing 888, we can assume that Git is used as the version control system for the WordPress instance. Reviewing the commits of the Git repository may allow us to identify changes in configuration and sensitive information such as passwords. The directory is owned by root and not readable by other users as shown in listing 888. However, we can leverage sudo to use Git commands in a privileged context and thereafter search for sensitive information. For now, let's skip the rest of the linPEAS output and summarize what we've gathered so far.

WESR1 runs Ubuntu 22.04 and is not connected to the internal network. The sudoers file contains an entry for daniela /usr/bin/git providing elevated privileges. In addition, we learned that the WordPress directory is a Git repository. Finally, we obtained a clear-text password in the database settings. Based on this information we can define three privilege escalation vectors:

- Abuse sudo command /usr/bin/git
- Use sudo to search the Git repository
- Attempt to access other users with the database password

The most promising vector at the moment is to abuse the sudo command /usr/bin/git because we don't have to enter a password. Most commands that run with sudo can be abused to obtain an interactive shell with elevated privileges.

## 821 - Find potential abuses when a binary as git is allowed to run with sudo

On this page, we use git in the search bar and select it. Then, let's scroll down until we reach the Sudo section: If the binary is allowed to run as superuser by sudo, it does not drop the elevated privileges and may be used to access the file system, escalate or maintain privileges.

```
sudo PAGER='sh -c exec sh' git -p help
```

## 889 - Abusing git command by setting an environment variable

Unfortunately, the output states that we are not allowed to set an environment variable. Next, let's try the second abuse vector. This command opens the help menu in the default pager. On Linux, one of the most popular pagers is less. The commands to navigate the pager are similar to vi and can be used to execute code in the context of the user account that launched the pager.

```
daniela@websrv1$: sudo git -p help config
```

## 892 - Examining the Git repository

Figure 2 shows there are two commits in the repository. One is labeled as **Removed staging script and internal network access**. That's interesting as it indicates that the machine previously had access to the internal network. In addition, the first commit may contain a staging script that was removed.

We could switch back to a specific commit using **git checkout** and a commit hash. However, this could break the functionality of the web application and potentially disrupt the client's day to day. A better approach is to use **git show**, which shows differences between commits. In our case, we'll supply the hash of the latest commit to compare as we are interested in the changes after the first commit.

```
root@websrv1:/srv/www/wordpress# git show 612ff5783c53dbd1e088523dba8374a84aaf1
```
