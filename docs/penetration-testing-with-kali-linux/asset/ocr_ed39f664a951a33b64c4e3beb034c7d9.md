An effective defensive technique to prevent tools such as Mimikatz from extracting hashes is to enable additional LSA Protection¹⁰⁸⁸ The LSA includes the LSASS process. By setting a registry key, Windows prevents reading memory from this process. We will discuss how to bypass this and other powerful defensive mechanisms in-depth in OffSec's Evasion Techniques and Breaching Defenses, PEN-300.

A different approach and use of Mimikatz is to exploit Kerberos authentication by using TGT and service tickets. As already discussed, we know that Kerberos TGT and service tickets for users currently logged on to the local machine are stored for future. These tickets are also stored in LSASS, and we can use Mimikatz to interact with and retrieve our tickets as well as those of other users.

Let's open a PowerShell window and list the contents of the SMB share on WEB04 via UNC path `web04.corp.backup`. This will create and cache a service ticket.

```
PS C:\Users\jeff> dir \\web04.corp\backup

Directory: \\web04.corp\backup

Mode                LastWriteTime     Length Name
-a----             9/13/2022      2:52 AM           @ backup_schema.txt
```

Once we've secured the connection, we can use Mimikatz to show the tickets that are stored in memory by entering `sekurlsa::tickets`
