When using a network logon as WinRM or a bind, Get-CimInstance and Get-Service will result in a "permission denied" error when querying for services with a non-administrative user. Using an interactive logon such as RDP solves this problem.

```
PS C:\Users\dave Get-CimInstance -ClassName win32_service | Select Name,State,PathName | Where-Object {$.State -like 'Running'}
```

List 415 - List of services with binary path

Based on the output in List 411, the two XAMPP binaries Apache2.4 and mysql stand out as the binaries are located in C:\xampp directory instead of C:\Windows\System32. This means the service is user-installed and the software developer is in charge of the directory structure as well as permissions of the software. These circumstances make it potentially prone to service binary hijacking.

Next, let's enumerate the permissions on both binaries. We can choose between the traditional icac utility or the PowerShell Cmd Get-ACL.789 For this example, we'll use icls since itself both in PowerShell and the Windows command line.

The icls utility outputs the corresponding principals and their permission mask.790 The most relevant permissions and their masks are listed below:

| | Permissions |
| --- | --- |
| F | Full access |
| M | Modify access |
| RX | Read and execute access |
| R | Read-only access |
| W | Write-only access
