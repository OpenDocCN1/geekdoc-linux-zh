> Figure 14: Exploit Path to write authorized_keys.keys file in root home directory

Figure 14 shows the relative path for our authorized_keys file. If we successfully overwritten the authorized_keys file of root, we should be able to use our private key to connect to the system via SSH. We notice that the root user does not have SSH access permissions. However, we can't check for other users by example, by displaying the contents of /etc/passwd; this is our only option.

The target system runs an SSH server on port 2022. We use the corresponding private key of the public key in the authorized_keys file to try to connect to the system. We will use the -i parameter to specify our private key and -p for the port.

In the Directory Learning Unit, we connected to port 2022 on the host mountaindesserts.com and our Kali system saved the key of the root host. Since the target system of this section is a different machine, SSH will throw an error because it cannot verify the key we saved previously. To avoid this, we will delete the known_hosts file before we connect to the system. This file contains all host keys of previous SSH connections.

```
kali@kali:~$ rm -rf ~/.ssh/known_hosts
```
