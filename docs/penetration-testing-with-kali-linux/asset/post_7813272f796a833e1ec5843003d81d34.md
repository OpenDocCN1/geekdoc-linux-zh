## 5.1.4 Choosing the Right Note-Taking Tool

There are an enormous number of both free and paid note-taking tools available today. To decide on the right tool for a particular engagement, it is important to understand some requirements. In many cases we want to keep all information to the computer rather than uploading it anywhere else, so tools are precluded from being used. By the same token, if an engagement is source-code heavy then a tool that does not allow for code blocks to be inserted is not going to be appropriate.

While a comprehensive list of desirable properties to keep in mind is nearly impossible to enumerate, as a lot of screenshots we, consider a tool that allows for inline screenshot insertion. 

- Screenshots: A lot of screenshots we, consider a tool that allows for inline screenshot insertion.
- Code blocks: Code blocks need formatting to be properly and quickly understood.
- Portability: Something that can be used cross-OS, or easily transferred to another place should be high on the list of priorities.
- Directory Structure: In an with multiple domains or organizations, keeping a coherent structure is necesary. While manually setting up a structure is allowed, a tool that can do this automatically makes easier.

Now that we have a good baseline of our requirements, let's consider the use of some particular note-taking tools.

Sublime is a pretty standard text editor that adds lots of useful features and functionality. One of the most important features it provides is syntax highlighting. Syntax highlighting allows us to place code blocks into a file, and those code blocks will be highlighted according to the programming language's specific syntax rules. However, this option comes with limitations. Highlighting two languages is not possible with one file. In an engagement with a single code type, this is not a problem, but for others, we may prefer to use other options. Additionally, it is not currently possible to inline screenshots at the time of writing.

Another tool we consider is CherryTree. This tool comes standard in Kali. It contains many of the features that are necessary for note-taking. It uses an SQLite database to store the notes we take, and can be exported as HTML, PDF, plain text, or as a CherryTree document.

CherryTree comes with a lot of built-in formatting, providing a tree structure to store documents, which it calls 'nodes' and 'subnodes'.

The final tool we use is the Obsidian markdown editor, which contains all the features we need for note-taking. We can install Obsidian as a snap application or in Flatpak application form. It also comes as Obsidian meaning all we need to do is copy it to our system, make it executable, and run it.

```

Obsidian's features include a live preview of markdown text, in-line image placement, code blocks, and a multitude of add-ons such as a community-built CSS extension.

The use of markdown means we can provide syntax and formatting that is easily copied to most report generation tools, and a PDF can be generated from Obsidian itself.

Tool selection is a personal and subjective preference. Some tools are better in certain scenarios than others, but isn't a perfect tool. It is recommended to take time and try out the tools we've covered, read the documentation, get familiar with them, and decide which tools will work for you.
