## 4.3.3 Facing Difficulty

There is a common exception that "practice makes perfect". That be true, but it begs the question, what makes for ideal practice?

Let's consider the experiment that was performed in 1978.¹⁵² A group of 8-year-old children were divided into two groups to practice a simple task: toss a small bean bag into a target hole. After being introduced to the target at a distance of three feet (about 90 cm), the groups spent the next three months practising. One group kept with the same distance. The other aimed at a pair of targets - practising with distances of two feet (60 cm) and four feet (120 cm).

In the final test, the task was to toss the bean bags to a target three feet away. The group who had spent all of their practising at that exact distance was in fact beaten by the group who had practised at two and four feet.

This and other studies demonstrate that struggle is not only important to the learning experience, but it's actually more important than mere repetition for creating the neural pathways that help us learn new skills.

> ¹⁵² (Kerr and Booth, 1978), https://pubmed.ncbi.nlm.nih.gov/662537/

This necessity for struggle means that we do not make each repetition the OffSec learning materials. Since learning is self-directed, students seeking more repetition can return to specific parts of the material as many times as they would like.

In lieu of repetition, we often choose to take an indirect route to the finish line. For example, we might try things that do not work so we can experience the act of picking ourselves up and trying again. This is the metaphorical equivalent of moving the target around a bit.

Put simply, we feel memorizing syntax is less important than being familiar with challenges and comfortable with a bit of struggle as a necessary trait for someone in the field of information security.

Let's make one other note here we're on the subject. We expect that about every student will get stuck at some point in their learning journey. We don't see this as a negative.

Getting stuck isn't fun, but we believe that being comfortable in a situation where we might not have all of the information and working through the problem is critical to succeed in the field of cyber security. To do that, we even sometimes take an indirect route to the finish line (in order to encounter "getting stuck") and provide technical exercises that ask students to go beyond simply repeating covered material. Our goal is to help you get stuck enough that you become quite comfortable with recovering.

To that end, we have written about this notion, which we call The Try Harder Mindset, in greater detail and with specific strategies elsewhere.¹⁵³

## 4.3.4 Contextual Learning and Interleaving

Whenever, OffSec's learning materials will present a new skill as part of a realistic scenario. This can be difficult with more basic skills, like the command to rename a file, but as we move deeper and deeper into the materials, we will find ourselves working through scenarios that are as realistic as the real world.

Teaching this takes more time; however, learning new skills in a realistic context improves a student's retention and success¹⁵⁴

Students may also find that when information is presented in context, they are actually learning several things at once. For example, if we are learning about how an attack method might be both executed and detected at the same time, our brain can make more connections to help us learn effectively. This method is called interleaving¹⁵⁵

### 4.4.1 What is Executable Permission?

Every file on a Linux machine has a number of additional properties associated with it. These include when the file was created, what user created it, which has permissions to read the file, and even the name of the file.

File permissions are particularly important. They indicate whether or are not allowed to read, write, execute a particular file. We think of the word in this context as our ability to make certain changes to a file. This could, for example, be set to not allow us to write to a file, which might keep that file from being accidentally deleted. The permissions might also be set to not allow us to read a file that has information in it we shouldn't be allowed to view.

These are called file permissions¹⁵⁷ and they pertain to different types of users who might be on our computer: the file owner, the user ownership, and anyone else. These different classes of users can be given (or denied) permission for each of the three actions above: read, write, and execute. For the sake of this Module, we'll focus only on the owner of the file, in this case.

Let's open a terminal and review how this works in practice. We'll touch¹⁵⁸ a file (filename.txt), which will create it and automatically make us the owner. We'll use the listing command ls¹⁹ to gather information about the file, providing the -l parameter that will produce a long list including the file permissions.
