# OffSec

The Listing above shows the hashing of the Keepass database stored in keeppass.hash. Before we can crack the hashing, we need to modify it.

In our case, the JIR script prefilled the filename Database to the hash. The script does this to act as the username for the target hash. This is helpful when cracking databases, since we want to output the corresponding username and not only the password. Since Keeps uses a master password without any kind of username, we need to remove the "Database" with a string text.

After removing the "Database", the hash is in the correct format for Hash:

```
kali@kali:~/downloads$ cat keeppass.hash
keeppass$2=60+0*d74ec2a9272e938717d2a7d4577ba3486d20dec73a9db1a7fbc7a068c9aec6bd04b0
bdf878988ddcd4a3d436e--
```

Listing 276 - Correct hash format for Hashcat with "Database".

We're ready to look it up in the starting process, we need to determine the hash type for Keepass. We could use Hashcat or get the hashcat output as shown below:

```
kali@kali:~/downloads$ hashcat --help | grep -i "Keepass" | Password Manager
13400 | Keepass 1 (AES/2fish) and Keepass 2 (AES)
```

Listing 277 - Finding the mode for Keepass in Hashcat

The output of the command shows that the correct format for Keepass is 13400.

Let's step three (cracking time calculation) since this is a simple example and we won't take long, and move on to step four to prepare our attack. We'll use one of the Hashcat-provided rules (rockyou-30000), mentioned earlier, combined with the rockyou.txt wordlist.

This rule file is especially effective with rockyou.txt, since we created it for.

As we step five, we've prepared everything for our password attack. We'll use hashcat with the updated arguments and start cracking.

```
kali@kali:~/downloads$ hashcat -m 13400 keeppass.hash
/usr/share/wordlists/rockyou.txt -r /usr/share/hashcat/rockyou-3000.rule --nforce
hashcat (v6.2.5)
```
