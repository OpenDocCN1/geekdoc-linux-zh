System processes and services always run in session 0${136}$ as part of session isolation, which was introduced in Windows Vista. Because the WMI Provider Host is running as a system service, newly created processes through WMI are also spawned in session 0.

Translating this to PowerShell requires a few extra details. We need to create a PSCredential${137}$ object that will store our session username and password. To do that, we first store the username and password in the respective variables and then secure the password via the ConvertSecureString cmdlet. Finally, we will create a new PSCredential object with the given username and securestring object.

```
$username = 'jen'
$password = 'Nexus123!'
$secureString = ConvertToSecureString $password -AsPlaintext -Force
$credential = New-Object System.Management.Automation.PSCredential $username, $secureString;
```

Next, we want to create a Common Information Model (CIM) via the New-CimSession. We'll first specify DCOM as the protocol for the WMI session with the New-CimSessionOption cmdlet on the first. On the second line, we will create the new session over our target IP and supply the PSCredential object along with the session options. Lastly, we will define 'calc' as the payload to be executed by WMI.

List 827 - Creating a new CIM Session

As a final step, we need to tie all the arguments we configured previously by issuing the Invoke-CimMethod cmdlet and supplying Win32_Process and Create as ClassName and MethodName, respectively.

```
Invoke-CimMethod -Cim $session -ClassName Win32_Process -MethodName Create -Arguments @{CommandLine=$command}
```
