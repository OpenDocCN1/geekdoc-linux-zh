Listing 896 - Checking for valid credentials with CrackMapEx

Listing 896 shows that CrackMap identified one valid set of credentials. This isn't much of a surprise since we retrieved the username and password from the staging script on WEBSRV1. However, john could have changed their password in the meantime.

The output shows another great CrackMapEx feature: it identified the domain name and added to the usernames. This means that MAILSRV1 is a domain-owned machine and we have identified a valid set of domain credentials.

Now that we have valid credentials, we need to come up with a plan for our next steps. Reviewing the CrackMapEx output and the scan for MAILSRV1, we don't have many options. We have identified the valid server and SMB, but no services like WinRM or RDP. In addition, the scan showed that john is not a local administrator on MAILSRV1 as indicated by the missing Pwn3dl.

This provides us with two options: we can enumerate SMB on MAILSRV1 and check for sensitive information on accessible shares or we can perform a malicious attack and a phishing email to john to daniela and marcus.

> We should be aware that CrackMapEx executes STATUS_LOGON_FAILURE when a password for an existing user is not correct, but also when a user does not exist at all. Therefore, we cannot be sure at this point that the domain accounts daniela and marcus exist.

Let's choose option one and leverage CrackMapEx to list the SMB shares and permissions on MAILSRV1 by providing shares and john's credentials. We may identify accessible shares containing information that we can use for the second option.
