## 22.2.2 AS-REP Roasting

As we have discussed, the first step of the authentication process via Kerberos is to send an AS-REQ. Based on this, the domain controller can validate if the authentication is successful. If it is, the domain controller replies with an AS-REP containing the session key and TGT. This is also commonly referred to as Kerberos preauthentication¹¹⁰⁶ and prevents offline password guessing.

> ¹¹⁰⁶ (Microsoft TechNet, 2014), https://technet.microsoft.com/wiki/contents/articles/23559-kerberos-pre-authentication-why-it-should-be-disabled.aspx

By Kerberos authentication, an attacker could send to the domain controller on behalf of any user. After obtaining the AS-REP from AS-REQ the domain controller, an attacker could perform an offline attack against the encrypted part of the response. This attack is known as AS-REP Roasting.¹¹¹⁰⁷

By default, the AD user account "Do not require Kerberos preauthentication" is disabled, meaning that Kerberos preauthentication is performed for all users. However, it is possible to enable this account manually. In assessments, we may find accounts with this option enabled as policies and technologies require it to function properly.

Let's perform this attack from our Kali machine, first then Windows. On Kali, we can use impacket-GetNPUsers¹¹⁰⁸ to perform AS-REP roasting. We need to enter the IP address of the domain controller as an argument --dc-ip, the name of the output file in the AS-REP hash will be stored in Hashcat format --outputfile, and --request to request the TGT.

Finally, we need to specify the authentication information in the format domain/user. For this example, we will use pete with the password Nexus123! The following command is shown:

```bash
root@kali:$ impacket-GetNPUsers -dc-ip 192.168.0.50 -request --outputfile hashes.asreproast corp.com/pete-

```

## Penetration Testing with Linux

We've collected everything we need to launch Hashcat and the AS-REP hash. Let's enter the mode 18200, the file containing the AS-REP hash, rocky.txt, the list best64.rule, and use -force to force the cracking on our Kali VM.

```bash
root@kali:~ sudo hashcat -m 18200 hashes.asrepro /usr/share/wordlists/rocky.txt -r /usr/share/hashcat/rules/best64.rule --force
```

List 807 - Cracking the AS-REP hash with Hashcat

Very nice! Hashcat successfully cracked the AS-REP hash. List 807 shows that the user dave has the password.

> If you receive the Hashcat error "Not enough allocate device for this attack", shut down your Kali VM and add enough RAM. 4GB is enough for the examples and exercises of this Module.

As mentioned, we can also perform AS-REP Roasting on Windows. We'll use Rubeus as a tool for Kerberos interactions and abuses. To perform this attack, we will connect RDP as user jeff with the password. Next, we can start a PowerShell window and navigate to C:\Tools, where Rubeus can be found.

Since we're performing this attack as a non-privileged user, we don't have any other options besides Rubeus asrepost. Rubeus will automatically identify vulnerable users. We also add the flag /nowrap to prevent new lines adding to the resulting hashes.

```powershell
PS C:\Users\jeff> cd C:\Tools
PS C:\Tools> .\Rubeus.exe asrepost /nowrap
```
