## 10.2.2 UNION-based Payloads

When we're dealing with in-band SQL injections and the result of the query is displayed with the application-returned value, we should also test for UNION-based SQL injections.

The **UNION** keyword alerts exploitation it enables execution of a statement and provides the results in the application.

For **UNION** SQL injection to work, we need to satisfy two conditions:
1. The UNION query must include the same number of columns as the original.
2. Data types must be compatible.

To demonstrate this, we'll test the following query:

```
' UNION SELECT 1,2,3,4,5--
```

Listing 195 - Vulnerable Query

## OffSec

With this information in mind, we can attempt our first attack by enumerating the database name, user, and MySQL version.

```
' UNION SELECT database(), user(), version(), null, null //
```

Since we want to retrieve all the data from the customers, we'll use the percentage sign followed by a quote to close the search parameter. Then, we begin our injected query with a SELECT statement that dumps the database name, user, and version in the first, second, and third columns, respectively.

After launching our attack, we'll notice that the username and the DB version are present on the last line, but the database name is not. This happens because column 1 is typically reserved for the ID field consisting of an integer data type, meaning it cannot return the string we are requesting through the SELECT database() statement.
