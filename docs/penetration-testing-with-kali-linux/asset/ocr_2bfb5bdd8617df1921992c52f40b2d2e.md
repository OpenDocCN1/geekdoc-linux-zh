# 17.4.2 Abusing Sudo

On Unix systems, the sudo utility allows us to execute a command with elevated privileges. To be able to use sudo, our low-privileged user must be a member of the sudo group (on Debian based Linux distributions). The word "sudo" stands for "Super-Do", and we can think of it as changing the effective user-id of the executed command.

Custom configurations of sudo can be implemented in the /etc/sudoers file.866 We can use the sudo -list to list the allowed commands for the current user.

User joe may run the following commands on debian-privesc:\n(ALL) ALL /usr/bin/crontab -t, /usr/sbin/tcpdump, /usr/bin/apt-get\nListing 503 - Inspecting current user's sudo permissions

From the output list 503, we notice that crontab, tcpdump, and apt-utility are listed as allowed sudo commands.

If the /etc/sudoers are too permissive, a user could use the short-lived administrative root to obtain root access.

Since the first of the two permitted commands does not allow us to edit crontab, it's unlikely that we could use this to gain privilege escalation. The second command looks more promising, so let's browse GTFOObins.864 for suggestions on how to abuse it.

Running the hunted commands, however, reveals an unexpected outcome:

```
joe@debian-privesc:$ COMMAND='id'
joe@debian-privesc:$ TF=$(mktemp)
```
