
# OffSec Penetration Testing with Kali Linux

Now we have covered TCP and UDP scanning techniques, let's review a few common pitfalls that can occur problematic for several reasons.

UDP scanning can be problematic. First, UDP scanning is often unreliable; firewalls and routers may drop ICMP packets. This can lead to false positives and ports showing as they are open, in fact, closed. Second, many port scanners do not scan all ports, and usually have a pre-set list of "interesting ports" that are scanned. This means open UDP ports can go unnoticed. Using a protocol-specific UDP port scanner may help to obtain accurate results. Finally, penetration testers often forget to scan for open UDP ports, instead focusing on the "exciting" TCP ports. Although UDP scanning is unreliable, there are plenty of attack vectors lurking behind open UDP ports. A TCP scan also generates much more traffic than a UDP scan, due to overhead and packet retransmissions.

## 6.3.3 Port Scanning with Nmap

Having a solid understanding of port scanning fundamentals, let's now learn about Nmap, the de-facto tool for port scanning.

Nmap²⁵³ (written by Gordon Lyon, aka Fyodor) is one of the most popular, versatile, and robust port scanners. It has been actively developed for two decades and offers numerous features beyond port scanning.

Some of the Nmap scanning options we'll cover in this Module are using sudo. This is because a few Nmap scanning options require access to raw sockets²⁴ which in turn require root privileges. Raw sockets allow for surgical mapping of TCP and UDP packets. Without access to raw sockets, Nmap is limited as it falls back to crafting packets using the standard Berkeley socket API²⁵⁵.

Before exploring some port scanning techniques, we should understand the footprint that each Nmap scan leaves on the wire and the handed sockets.

A default Nmap TCP scan will scan the 1000 most popular ports on a given machine. Before we start running scans blindly, let's examine the amount of traffic sent by this type of scan. We'll scan one of the lab machines while monitoring the amount of traffic sent to the target host using iptables²⁶.

We will use iptables options. First, let's use the -I option to insert a new rule into a chain, which in this case includes the INPUT (Inbound) and OUTPUT (Outbound) chains, followed by the rule number. We use -s to specify an IP address, -d to specify a destination IP address, and -j to ACCEPT the traffic. Finally, we use the -Z option to zero the packet and byte counters in all chains.

```
kali@kali~$ sudo iptables -I INPUT 1 -s 192.168.0.149 -j ACCEPT
kali@kali~$ sudo iptables -I OUTPUT 1 -d 192.168.0.149 -j ACCEPT
```

On the other hand, we'll now explore some of Nmap's various techniques. The most popular Nmap scanning technique is SYN, or "stealth" scanning. SYN scanning is a TCP scanning method that involves sending SYN packets to various ports. If a port is open, SYN-ACK should be sent back from the target machine. At this point, the port scanner does not bother to send the final ACK to complete the three-way handshake.

```
kali@kali:~ sudo nmap -sS 192.168.0.149
Starting Nmap 7.92 ( https://nmap.org ) at 2022-03-09 06:33 EST
Nmap scan report for 192.168.0.149
Host is up (0.11s).
```

The next Nmap scanning method we'll explore is TCP Connect Scanning, which as the name suggests, performs a full TCP connection.

> Please note that term "stealth" refers to the fact that, in the past, firewalls fail to log incomplete TCP connections. This is no longer the case with modern firewalls and although the stealth moniker has stuck around, it could be misleading.
