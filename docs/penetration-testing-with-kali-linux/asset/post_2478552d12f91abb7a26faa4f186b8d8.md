
# OffSec Penetration Testing with Kali Linux

When a running nmap does not have raw socket privileges, Nmap will default to the TCP scan². As Nmap TCP connect makes use of the Berkeley sockets API¹ to perform the three-way handshake, it does not require elevated privileges. However, because Nmap has to wait for the connection to complete before the API return the status of the connection, a TCP scan takes much longer than a SYN scan.

We may occasionally need to perform a connect scan using nmap, as scanning when certain types of proxies use. We use the -ST option to start a connect scan.

```
kali@kali:~ nmap -sT 192.168.0.149

The output shows that the connect scan revealed a few open services that are only active on the Windows-based host, especially Domain Controllers, as we'll cover shortly. One major takeaway, even from this simple scan, is we can infer the underlying OS and role of the target host.

Having reviewed the most common Nmap TCP scanning techniques, let's learn about UDP Scanning.

When performing a UDP scan, Nmap will use a combination of two different methods to determine if a port is open or closed. For most ports, we will use the standard "ICMP port unreachable" method described earlier by sending an empty packet to a port. However, for common ports, which is used by SNMP, we will send a protocol-SNMP packet in an attempt to get a response from answer bound to port. To perform a UDP scan, we'll use the -U option, with sudo to access raw sockets.

```
kali@kali:~ sudo nmap -U 192.168.0.149
Starting Nmap 7.70 ( https://nmap.org ) at 2019-03-04 11:46 EST
nmap scan report for 192.168.1.131
host is up (0.1ms latency).
not shown: 977 closed udp ports (port-unknown)
```

Listing 61 - Using nmap to perform a combined UDP and SYN scan

Our TCP and UDP scan revealed additional open ports, disclosing which services are running on the target host. We can extend what we have learned from a single host and apply it to a full network range through Network Switching. To deal with large volumes of hosts, or otherwise to conserve traffic, we can attempt to probe targets using Network Switching techniques in which we begin with broad ranges of interest. When performing a network scan with Nmap using the -sn option, the discovery process consists of more than just sending an ICMP echo request. Nmap also sends a TCP SYN packet to port 443, a TCP ACK packet to port 80, and an ICMP timestamp request to verify whether a host is available.

```
kali@kali:~ nmap -sn 192.168.50.1-253
Starting Nmap 7.92 ( https://nmap.org ) at 2022-03-10 03:19 EST
Nmap scan report for 192.168.50.8
Host is up (0.12s latency).
Nmap scan report for 192.168.50.8
Nmap done: 254 IP addresses (13 hosts) scanned in 3.74 seconds
```

Searching for machines using the grep command on a standard Nmap output can be cumbersome. Instead, let's use Nmap's 'greppable' output, -oG, to save these results in a more manageable format.

```
kali@kali:~ nmap -v 192.168.50.1-253 -oG ping-sweep.txt
Starting Nmap 7.92 ( https://nmap.org ) at 2022-03-10 03:21
Initiating Scan at 03:21
Read data from: /usr/bin/../share/nmapmap done: 254 IP addresses (13 hosts) in 3.74 seconds

```
kali@kali~$ grep ping-sweep.txt | cut -d " " -f2

```

Listing 62 - Using nmap to perform a network sweep

We can use specific for TCP or UDP ports across the network to find systems that may be useful or have known vulnerabilities. This method can be more accurate than ping sweep.

Listing 65 - Using nmap to perform a twenty port scan, saving the output in greppable format

The 20 nmap results generated using the /usr/share/nmap/map-services file, which uses a simple format of three whitespace-separated columns. The first is the name of the service, the second contains the number and protocol, and the third is "frequency". Everything after the third column is ignored, which is typically used for comments as shown by pound sign (#). The frequency is based on how often the port was found during periodic scans of the internet.³³

```
kali@kali:~# cat /usr/share/nmap/map-services
finger 79/udp 0.008956 # www -http | World Web HTTP
http 80/tcp 0.068090 # World Web HTTP
http 80/tcp 0.484143
http 80/udp 0.035767 # World Web HTTP
hosts2- 81/tcp 0.012086 # HOST2 Name Server
hosts2-ns 81/udp 0.001085 # HOST2 Name Server
```
