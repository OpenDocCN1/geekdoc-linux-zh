Listing 675 - Display idletime from current user

Now that we have an active Metasploit session on Windows we can start exploring post-exploitation commands and features.

The first post-exploitation command is idletime. It displays the time for which a user has been idle. After obtaining information about the current user and operating system, this should be one of our first commands that indicates the target is currently in use or not.

The output shows that the user hasn't been interacting with the system for 9 minutes and 53 seconds, suggesting the user may have stepped away from their computer. If the result of the idletime command indicates that the user is away, we can take this as an opportunity to execute programs or commands which may deploy a command-line window as CMD or PowerShell for a brief moment.

For several post-exploitation features, we need administrative privileges to execute them. Metasploit contains the getsystem, which attempts to automatically elevate our permissions to NT AUTHORITY\SYSTEM. It uses various techniques using named pipe impersonation and token duplication. In the default settings, getsystem executes all available techniques (shown in the help menu) attempting to leverage SeImpersonatePrivilege and SeDebugPrivilege. Before we execute system, let's start an interactive shell and confirm that our user has one of those two privileges assigned.

```
meterpreter > shell
...
C:\Users\luiza> whoami /priv

```

| Privilege Name | Description | State |
| --- | --- | --- |
| SeImpersonatePrivilege | Impersonate a client after authentication | Enabled |


Listing 677 - Elevate our privileges with getsystem

Listing 677 shows that getsystem successfully elevated our privileges to NT AUTHORITY\SYSTEM using Named Pipe Impersonation variant as we did manually. Another important post-exploitation feature is migrate. If we compromise a host, our access to the machine is closed. In addition, depending on how the Windows binary containing Meterpreter payload is named, the process name may be suspicious if a defender is searching through the process list. We can use migrate to move the execution of our Meterpreter payload to a different process. Let's view all running processes by entering ps in Meterpreter command prompt.

meterpreter > ps

| PID | PPID | Name | Arch | Session | User | Path |
| --- | --- | --- | --- | --- | --- | --- |
| 2552 | 8500 | met.exe | x64 | 0 | ITWK0\luiza | C:\Users\luiza\met.exe |
| 8052 | 4892 | OneDrive.exe | x64 | 1 | ITWK0\offsec | C:\Users\offsec\AppData\Local\Microsoft\OneDrive\OneDrive.exe |

List 678 shows that the process met.exe has the process ID 2552. The name and path will easily make the process stand out to a defender reviewing the process list. The output shows that offsec started a process to OneDrive with process ID 8052. If our payload runs within this process, it is far less likely be detected by reviewing the process list. We should note that we are only able to migrate into processes that execute at the same (or lower) integrity and privilege level than that of our process. In the context of this example, we already elevated our privileges to NT AUTHORITY\SYSTEM so our choices are plentiful. Let's migrate our current process to OneDrive.exe of the user offsec by entering migrate and process we want to migrate.

```
meterpreter > migrate 8052
[*] Migrating from 2552 to 8052...
[*] Migration completed successfully.
```

Listing 679 - Migrate to process.exe

Listing 679 shows that we successfully migrated our process to the OneDrive process. When reviewing the process list, we will find our original process, met.exe with ID 2552, not exist anymore. Furthermore, we'll notice that the ps output contains less information than before. The reason for this is that we are now running in the context of the process with the ID 8052 and therefore, as user offsec.

```
meterpreter > getuid
Server username: ITWK01@offsec
```

Listing 680 - Command execute as user offsec instead of NT AUTHORITY\SYSTEM

Instead of migrating to an existing process or a situation in which we can't find any processes to migrate to, we use the Meterpreter command. This command provides the ability to create a new process by specifying a command or program.

To demonstrate this, let's start a Notepad process and migrate to it as user offsec. For this, we use execute with -H to create the process from hidden and _notepad as argument for -f to specify the command or run to. Then, we are migrated to the newly spawned process. 

```
meterpreter > execute -H -f notepad
Process 2720 created.
```

```
meterpreter > migrate 2720
[+] Migrating from 8052 to 2720...
[+] Migration completed successfully.
```

Listing 681 - Migrate to a newly spawned process

Listing 681 shows how we can migrate to the newly spawned process. Since we used the option -H, the notepad was spawned without any visual representation. However, the process is still listed in the process list of applications such as the task manager.
