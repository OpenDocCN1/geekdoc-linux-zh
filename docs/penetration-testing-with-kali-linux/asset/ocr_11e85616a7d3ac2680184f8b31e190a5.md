> Listing 162 - List of webshells in directory

Listing 162 shows us the frameworks and languages for which Kali already offers web shells. It is important to understand that while the implementation of a web shell is dependent on the programming language, the basic process of using a web shell is nearly identical across these frameworks and languages. After we identify the framework or language of the target application, we need to find a way to upload our shell. The web shell needs to be placed in a location where we can access it. Next, we can provide commands to it, which are executed on the underlying system.

We should be aware that the file types of web shells may be blacklisted via a filter or upload mechanism. In situations like this, we can try to bypass the filter in this section. However, there are other options to consider. Web applications handling and managing files enable users to rename or modify files. We could abuse this by uploading a file with an unexpected file type like .txt, then changing the file back to the original file type of the web shell by renaming it.

# 9.3.2 Non-Executable Files

In this section, we will examine why flaws in file uploads can have severe consequences even when there is no way to exploit the uploaded files. We encounter scenarios where we have an unrestricted file upload mechanism, but cannot exploit it. One example for this is Google Drive where we can upload any file, but cannot leverage to get system access. In situations such as this, we need to leverage another vulnerability as Directory Traversal to abuse the file upload mechanism.
