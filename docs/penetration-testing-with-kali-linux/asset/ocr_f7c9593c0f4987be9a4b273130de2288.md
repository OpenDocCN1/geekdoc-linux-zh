In order to simulate a real DNS setup, we can make FELINEAUTHORITY a functional DNS server
using dnsmasq. Dnsmasq is DNS server software that requires minimal configuration. Few
dnsmasq configuration files are stored in the `~/dnsmasq` folder, which we will use as part of
our DNS experiments. For this initial experiment, we'll use the very sparse dnsmasq.conf
configuration file.

```
kali@felineauthority:-$ cd dnsmasq_tunneling

kali@felineauthority:~/dnsmasq$ cat dnsmasq.conf
# Do not read /etc/resolve.conf or /etc/hosts
no-resolve
no-hosts

# Define the zone
auth-zone=feline.corp
auth-server=feline.corp
```

> Listing 600 - The basic configuration for our Dnsmasq server.

This configuration uses the /etc/resolve.conf and /etc/hosts files and only defines the auth-
zone and auth-server variables. We then use dnsmasq to act as the authoritative name server for the
feline.corp zone. We have not configured any records so far. Requests for anything on the
feline.corp domain will return failure responses.

Now that the configuration is set, we will start the dnsmasq process with the dnsmasq.conf
configuration file (-C), making sure it runs in "no daemon" (-d) mode so it runs in the foreground.
We can kill it easily later.
