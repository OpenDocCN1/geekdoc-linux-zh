Next, we will provide the long-form Executive Summary. This is a written summary of the testing that provides a high-level overview of each step of the engagement and establishes severity, context, and a "worst-case scenario" for the key findings during testing. It's important not to undersell or over the vulnerabilities. We want the client's mental model of security posture to be accurate. If we found an SQL injection that enables credit card details to be stolen, that represents a very different severity if we found an authentication bypass on a system hosting public data. We would certainly emphasize the former in the Executive Summary, but may not highlight the latter in this section.

We should make note of any trends that were observed in the testing to provide strategic advice. The executive doesn't need to be given the full details in this section, and technical staff will be able to find them as each will be expanded upon in later sections of the report. What we can do, is to describe the trends we identified and validate our concerns with summaries of one or two of the most important findings.

To highlight, we will group findings with similar vulnerabilities. Many vulnerabilities of the same type generally show a failure in that particular area. For example, if we found reflected XSS with SQL injection and file upload vulnerabilities, then user input is clearly not properly sanitized across the board. This must be fixed at a systemic level. This section is an appropriate place to inform the client of a systemic failure, and we can recommend the necessary process changes as the remediation. In this example, we may encourage the client to provide proper security training for their developers.

It is useful to mention things that the client has done well. This is especially true while management may be paying for the engagement, our working relationship is often with the technical security teams. We want to make sure that they are not personally looked upon. Even those penetration tests that find severe vulnerabilities will likely identify one or two areas that are hardened. Including those areas still have the impact on people, and make the client more accepting of the report as a whole.
