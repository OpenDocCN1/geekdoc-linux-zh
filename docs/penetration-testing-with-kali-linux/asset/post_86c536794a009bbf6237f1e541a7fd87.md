
# Ubuntu 16.04 LTS / 18.04 LTS / 20.04 LTS : Sudo vulnerabilities (USN-4705-1)

### Synopsis
The remote Ubuntu host is missing one or more security updates.

### Description
The remote Ubuntu 16.04 LTS / 18.04 LTS / 20.04 LTS has packages installed that are affected by multiple vulnerabilities referenced in the USN-4705-1.

- Sudo before 1.92 has a Heap-based Buffer Overflow, allowing privilege escalation via root subdivit and contains an argument that allows an arbitrary file write (CVE-2021-3156).
- The vulnerability of Sudo before 1.92 also has a heap corruption allowing arbitrary directory test bypass by using sudo_edit race condition in replacing a user-controlled directory by a symlink to an arbitrary path (CVE-2021-22952).

### Solution
Update the sudo and sudo-ldap packages.

### 7.3.1 NSE Vulnerability Scripts

As an alternative to Nessus, we can also use the NSE scripts³⁵ to perform automated vulnerability scans. NSE scripts extend the basic functionality of Nmap to a variety of networking tasks. These tasks are grouped into categories such as vulnerability detection, brute force, and network discovery. The scripts can also extend the version and information gathering capabilities of Nmap.
NSE script can have more than one category. For example, it can be categorized as safe and intrusive vuln. Scripts categorized as “safe” have no potential impact on stability, while scripts in the “intrusive” category might crash a target service or system. To avoid any stability

We can determine the categories of a script by browsing the NSE Documentation³⁶ or locally in the NSE scripts directory. In this section, we will focus on the vuln category to learn Nmap as a lightweight vulnerability scanner. On our Kali VM, the NSE scripts can be found in /usr/share/nmap/scripts/ directory. This directory also contains script.db file, which serves as an index to all available NSE scripts. We can use it to get a list of scripts in the vuln category.

```
kali@kali:$ cd /usr/share/nmap/scripts/
kali@kali:/usr/share/nmap/scripts$ cat script.db | grep "vuln"
Entry { filename = "af-path-vuln.nse", categories = { "exploit", "intrusive", "vuln" } }
Entry { filename = "avahi-dos.nse", categories = { "broadcast", "dos", "intrusive" } }

Each entry has a file name and categories. The file names represent the type of the NSE script in the NSE directory. Some of the standard NSE scripts are quite outdated. Fortunately, the vulners³⁷ integrated, which provides current vulnerability information about detected service from the Vulners Vulnerability Database³⁸ script itself has the categories safe, vuln, and external. Before we start our first scan with the NSE, we will examine the -script parameter. This parameter is responsible for determining which scripts get executed in scan. The arguments for this parameter can be a category, a Boolean expression, comma-separated lists, the file path or wildcard-name of script.db, or an absolute path to a specific script. Let's start with Nmap scan using all the NSE scripts from the vuln category. The command we'll use the previously mentioned -script parameter with the vuln argument which specifies all of the scripts with this. Furthermore, we will use -SV to activate Nmap's service detection capabilities. Finally, we use -p to scan port 443.

```
kali@kali:$ sudo nmap -SV -p 443 --script "vuln" 192.168.50.124

## 7.3.2 Working with NSE Scripts

In the previous section, we learned about the vuln NSE category and the vulners script provide an overview of all CVEs mapped to the detected version, we sometimes want to check for a specific CVE. This is especially helpful when we want to scan a network for the existence of a vulnerability. If we do this with the vulners script, we would need to review an enormous amount of information. For most modern vulnerabilities, we need to integrate dedicated NSE scripts manually.
