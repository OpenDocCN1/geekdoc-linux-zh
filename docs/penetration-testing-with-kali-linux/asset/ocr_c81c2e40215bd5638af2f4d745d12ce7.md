In addition to SIDs and tokens, Windows also implements what is known as Mandatory Integrity Control. It uses *integrity levels* to control access to securable objects. We can find these levels as hierarchies of trust Windows has in a running application or securable object.

When processes are started or objects are created, they receive the integrity level of the principal performing this operation. One exception is if an executable file has a low integrity level, the process's integrity level will also be low. A process with a lower integrity level cannot write to an object with a higher level, even if the permissions normally allow them to do.

From Windows Vista, processes run on four integrity levels:

+   - System: kernel, ...
- High: Elevated users
- Medium: Standard users
- Low: very restricted rights often used in sandboxed[^privesc_win_sandbox] processes or for directories storing temporary data

The PowerShell processes have the integrity level of High and Medium. Review Listing 375, we can infer that the *High integrity level process is started by the administrative user and the *Medium* integrity level process by the regular user.

Finally, another security technology we need to consider is User Account Control (UAC). UAC is a Windows security feature that protects the operating system by running most applications and tasks with standard user privileges, even if the user launching them is an Administrator. The first user obtains two tokens after a successful login. The first token is a standard token (*filtered admin token), which is used to perform non-privileged operations. The second token is a administrator token. It will be used when the user wants to perform a privileged operation. To leverage this, UAC consent prompt^742 needs to be confirmed.

This concludes our introduction to Windows privileges and access control mechanisms. We should now have a basic understanding of SIDs, access tokens, integrity, and UAC.
