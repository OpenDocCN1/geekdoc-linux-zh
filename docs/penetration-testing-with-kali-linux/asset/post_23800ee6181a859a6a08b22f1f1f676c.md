# 18.3.3 SSH Remote Port Forwarding

In our examples we've been able to connect to any port we on the WAN interface of CONFLUENCE01. This is challenging in the real world, more often than not, firewalls - both hardware and software are likely to get in the way. Inbound traffic only if we compromise credentials for an SSH user, allowing us to SSH directly into a network and port forward. We will only rarely be able to access ports that we bind to a network perimeter.

However, we will be able to bind SSH out of that. Outbound connections are more difficult to control than inbound connections. Most corporate networks will allow many types of common network traffic out - including SSH - for reasons of simplicity, usability, and business need. So while it likely wont be possible to connect to a port we bind to the network perimeter, it will be able to soften SSH.

This is where SSH remote port forwarding¹ can be extremely useful. In a similar way that an attacker may use a remote shell payload to connect back to an attacker-controlled listener, SSH remote port forwarding can be used to connect back to an attacker-controlled server, and bind the listening port. In local and dynamic port forwarding, the listening port is bound to the client, in remote port forwarding, the listening port is bound to the server. Instead of the packet forwarding being done by the server, packets are forwarded by the client.

However, in this scenario, the administrators need to improve security by implementing a firewall at the perimeter. We can connect from CONFLUENCE01 to our Kali machine over SSH. The TCP port 2345 is bound to the loopback interface on our Kali machine. Packets sent to this are pushed by the SSH server through the SSH tunnel to the SSH client. They are forwarded to the PostgreSQL database on CONFLUENCE01. Let's set this up in our lab. First, we'll need to enable the SSH server on the Kali machine. OpenSSH server is preinstalled - all we need is to start it.

# Penetration Testing with Kali Linux

Once we have a reverse shell from CONFLUENCE01, we have a TTY shell, then we SSH remote port forward back to our Kali machine.

In order to connect to the Kali SSH server using a username and password you may have to explicitly allow password-based authentication by setting PasswordAuthentication yes in /etc/ssh/sshd_config.

The SSH remote port forward option is -R, and has a very similar syntax to the local port option option. It also takes two sockets as the argument. The listening socket is defined first, and the forwarding socket is second.

In this case, we want to listen on port 2345 on our Kali machine (127.0.0.1:2345), and forward all traffic to the PostgreSQL server on CONFLUENCE01 (10.4.20.1532).
