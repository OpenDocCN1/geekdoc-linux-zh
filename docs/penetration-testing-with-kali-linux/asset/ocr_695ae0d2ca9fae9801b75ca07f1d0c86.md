Figure 308 shows that we can enter a path in this field, which will be used for storing the backup. We may abuse this functionality for a moment and force an authenticity of the underlying system.

Let's pause here for a moment and plan our next steps. At, there are two promising attack vectors.

The first is to upload a malicious WordPress plugin to INTERNALSERV1. By preparing and uploading a web shell or reverse shell, we may be able to obtain code execution on the underlying system.

For the second attacker, we have to review the BloodHound results and make some assumptions. As we have discovered, the local administrator account has an active session in INTERNALSERV1. Based on this session, we can make the assumption that this user account is used to run the WordPress instance.

Furthermore, it is not uncommon that the local administrator accounts for all computers in a domain are set up with the same password. Let's assume this is true for the target environment.

We also learned that the domain administrator becc has an active session on MAILSERV1 and therefore, the credentials of the user may be cached on the system.

Finally, we identified the Backup directory path field in the Word Backup Migration plugin containing the path for the backup destination. This may allow us to force such an authentication request.
