## 21.3.3 Enumeration Through Service Principal Names

So far, we have obtained a bit of information, and we are starting to see how things are connected within the domain. To wrap our discussion of user enumeration, we will shift our focus to Service Accounts,¹1042 which may also be members of high-privileged groups.

Applications must be executed in the context of an operating system. If a user launches an application, user account defines the context. However, services launched by the system itself in the context of a Service Account.

In other words, isolated applications can use a set of predefined service accounts, such as LocalSystem,¹1043 LocalService,¹1044 and NetworkService.¹1045.

For more complex applications, a domain user account may be used to provide the needed context while maintaining access to resources inside the domain.

When applications like Exchange,¹1046 MS SQL, or Internet Information Services (IIS) are integrated into AD, a unique service identifier known as Service Principal Name (SPN)¹1047 associates a service to a specific service account in Active Directory.

> Managed Service Accounts,¹1048 introduced with Windows Server 2008 R2, designed for complex applications, which require tighter integration with Active Directory.
