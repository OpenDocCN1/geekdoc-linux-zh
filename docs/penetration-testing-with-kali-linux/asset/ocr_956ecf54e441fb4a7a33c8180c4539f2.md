We previously examined the -rwr-xr-x portion of the output. We will also notice a number, "141776" in the case of the first command, in the output. This number indicates the size of the file. After we run the cat command, we will observe that the file name and the permissions are still the same as before, but the file is now "6448". This output indicates that the contents of the file have changed, but the permissions remained intact.

Let's return to the beginning and run it script chmod +x on our script.

```
kali@kali:- ./chmod +x find_employee_names.py
```

Excellent! We were able to restore our permission to execute our script and run it. It's certainly a relief to receive our list of employees again.

Let's go one step further and restore our system so that we don't run into this problem again. Let's try and run the chmod command on the original chmod file to fix things.

```
kali@kali:- ./chmod +x /usr/bin/chmod
./chmod: changing permissions of '/usr/bin/chmod': Operation not permitted
```

| Listing 23 - Another obstacle |

We've hit another obstacle. We don't have permission to modify /usr/bin/chmod
Whoever set up this system made so the average user could not interrupt system files in /usr/bin/ (like chmod). Copying the file of the file was clearly avoid, but we're trying to write a file in a folder, and we don't have permission to do that.

```
kali@kali:- sudo chmod +x /usr/bin/chmod
[sudo] password for kali:
```

This worked.
