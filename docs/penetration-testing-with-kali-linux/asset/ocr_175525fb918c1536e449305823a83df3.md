Due to access as new user, and therefore different permissions on files on the system, the process of searching for sensitive information begins again.

This is a great opportunity to zoom out here for a moment. With access to a new user, the process of searching for sensitive information starts again. This is not true for this specific case, but also for nearly all areas of a penetration test. The cyclical nature of a penetration test is an important concept for us to grasp, because it provides a mindset of continuously reevaluating and including new information and access in order to freely previously inapproachable or newly identified attack vectors.

In our search as dave we received a permission error on C:\xampp\mysql\bin\ini. Let begin check if we have access to it as.

```
PS C:\Users\steve type C:\xampp\mysql\bin\my.ini
# Example MySQL config file for small systems.
```

```
# The following options will be passed to all MySQL clients
[client]
backupadmin Windows password for backup job
password = admin123admin123!
port=3306
socket="C:\xampp\mysql\mysql.sock"
```

List 394 - Contents of the my.ini file

List 394 shows that we can access my.ini and bin in steve. The file contains the manually set password admin123admin123! Additionally, a comment states that this is also the Windows password for backupadmin.

Let's review the groups backupadmin is a member of find out if we can use services such as RDP or WinRM to connect to this system as this user.

```
PS C:\Users\steve> net user backupadmin BackupAdmin
...
Local Group Memberships *Administrators *BackupUsers
Global Group memberships *Users *None
The command completed successfully.
```

List 395 - Local groups backupadmin is member of

Unfortunately, backupadmin is not a member of the group Desktop Users or Remote Management Users. This means we need to find another way to access the system or execute commands as backupadmin.

Since we have access to a GUI we can use Runas⁷⁶⁵ which allows us to run a program as a different user. Runas can be used with local or domain accounts as the user has the ability to login to the system.

Without access to a GUI we cannot use Runas since the password prompt doesn't accept our input in commonly used shells, such as bash shell or WinRM.
