- Proxy Listeners
Burp uses listeners to receive incoming HTTP requests from your browser. You will need to configure one of the listeners as its proxy server.

| Add | Running | Interface | Invisible | Redirect | Certificate | TLS Protocols |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| Edit | [x] 127.0.0.1:8080 | Per-host | Default | | | |
| Remove | | | | | | |

Each installation of Burp generates its own CA certificate that Proxy listeners use when negotiating TLS connections. You can import or export this certificate for use in other tools or another installation of Burp.

Figure 88: Proxy Listeners

By default, Burp Suite enables a proxy listener on localhost:8080. This is the host and port that your browser must connect to for proxy traffic through Burp Suite.

> Burp Suite is now shipped with its own Chromium-based native web browser, which is preconfigured to work with all Burp's features. However, for this course we are going to exclusively rely on Kali's Firefox browser because it is a more flexible and modular option.

Let's demonstrate how to configure our local Kali machine with the Firefox browser to use Burp Suite as a proxy.

In Firefox, we can do this by navigating to about:preferences#general, scrolling down to Network Settings, then clicking Settings.

Let's choose the Manual option, setting the appropriate IP address and listening port. In our case, the proxy (Burp) and the browser reside on the same host, so we'll use the loopback IP address 127.0.0.1 and specify port 8080.

> In some testing scenarios, we might want to capture the traffic from multiple machines, so the proxy will be configured on a standalone IP. In such cases, we will configure the browser with the external IP address of the proxy.

Finally, we also want to enable this proxy server for all protocol options to ensure that we can intercept every request while testing the target application.

With Burp configured as our browser, we can close any extra open Firefox tabs and browse to http://www.megacorp.com. We should find the intercepted traffic in Burp Suite under Proxy > HTTP History.

On the left pane we can visualize the client request details, with the server response on the right pane. With another Burp feature, we can inspect every detail of each request performed, along with the response. We will make use of this feature when using Modules. Why does "detectportal.com" showing up in proxy history? A captive portal is a web page that serves as a gateway page when attempting to browse the Internet. To ignore this, simply enter about:config in the address bar. Firefox will prevent a warning, but we can proceed by clicking accept the risk! Finally, search for "network-captive-service" and double-click it to change the value to "false". This will prevent these messages from appearing in the proxy.

Beside the Proxy feature, the Repeater is another Burp tool. With the Repeater, we can craft new requests or easily modify the ones in history, and review the responses. To observe this in action, we can right-click a request from Proxy > HTTP History and Send to Repeater.
