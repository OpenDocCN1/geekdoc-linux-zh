# ## 17.3.2 Abusing Password Authentication

Without a centralized credential system such as Active Directory or LDAP, Linux passwords are generally stored in `/etc/shadow`, which is not readable by normal users. Historically however, password hashes, along with other account information, are stored in the world-readable file `/etc/passwd`. For backwards compatibility, if a password hash is present in the second column of `/etc/passwd` it is considered for authentication and it takes precedence over the respective entry in `/etc/shadow`. This means if we can write into `/etc/passwd`, we can effectively set an arbitrary password for any account.

Let's demonstrate this. In a previous section, we showed that our Debian can be vulnerable to privilege escalation due to the fact that `/etc/passwd` permissions were not correct. To escalate our privileges, let's add another superuser (root2) and the corresponding password hash to `/etc/passwd`. We will first generate the password hash using the openssl ⁸6¹ tool and the password argument. By default, if no option is specified, openssl will generate a hash using the crypt algorithm,⁸6² a supported hashing mechanism for authentication.

> The output of the OpenSSL password command may vary depending on the system executing it. On older systems, it may default to the DES algorithm, but on newer systems it could output the password in MD5 format.

Once we have generated the hash, we will add a line to `/etc/passwd` using the following format:

```
joe@debian-privesc:- openssl password w00t
Fdzt.eqJQ4s0g
joe@debian-privesc:- echo "root2:Fdtz.eqJQ4s0g:0:0:root:root:/bin/bash" \
/etc/passwd
joe@debian-privesc:- su root2
Password: w00t
```
