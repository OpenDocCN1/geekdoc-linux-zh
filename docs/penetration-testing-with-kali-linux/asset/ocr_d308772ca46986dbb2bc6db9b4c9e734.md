# 17.3. Abusing Cron Jobs

Let's focus on another family of privilege escalation techniques and learn how to leverage insecure file permissions. For this section, we will assume that we have already gained access to our Linux target machine as an unprivileged user.

In order to leverage file permissions, we must locate an executable that does not allow us to write, but also runs at an elevated privilege level. On a Linux system, the time-based job scheduler is a prime target, since system-level scheduled jobs are executed with root privileges and system administrators create cron jobs with insecure permissions.

For this example, we will use SSH to log into the joe user, using offsec as a password. In a previous section, we demonstrated where to check the filesystem for installed cron jobs on a target system. We also inspect the cron file (/var/log/cron.log) for running cron jobs:

```
joe@debian:~$ grep "CRON" /var/log/cron.log
Aug 25 04:56:07 debian-privsec cron[463]: (CRON) INFO (pidfile fd = 3)
Aug 25 04:56:07 debian-privsec cron[463]: (CRON) INFO (Running (reboot jobs)
Aug 25 04:57:01 debian-privsec cron[918]: (root) CMD (/bin/bash
/home/joe/.scripts/user_backups.sh)
```
