We can filter by any property of object type. In the example below we have made two changes. We have changed the filter to use the name property to only show information for jeffadmin. Additionally, we have added member to the S property to only display the groups jeffadmin is a member of:

```query
$dirsearch = New-Object System.Directory.Services.DirectorySearch($dentry)
$dirsearch.filter="name=jeffadmin"
$result = $dirsearch.FindAll()
ForEach($obj in $result) {
    ForEach($prop in $obj.Properties) {
        $prop.member
    }
    Write-Host "----------------------------------------------------------------"
}
```

We can use this to enumerate any object available to us in AD. However, in the current state, this would require us to make further edits to the script itself based on what we wish to enumerate.

Instead, we can make the script more flexible, allowing us to add the required parameters by the command line. For example, we could have the script accept the samAccountType we wish to enumerate as a command line argument.

There are many ways we can accomplish this. One way is to encapsulate the current functionality of the script into an actual function. An example of this is shown below:

```query
function LDAPSearch {
  param (
    [string]$LDAPQuery
  )
  $PDC = [System.DirectoryServices.ActiveDirectory.Domain]::GetCurrentDomain().PdcRoleOwner.Name
  $DistinguishedName = (([adsi]('ADRoot')).distinguishedName
  $DirectoryEntry = New-Object System.DirectoryServices.DirectoryEntry("LDAP://$PDC/$DistinguishedName")
  $DirectorySearcher = New-Object System.DirectoryServices.DirectorySearcher($DirectoryEntry, $LDAPQuery)
  return $DirectorySearcher.FindAll()
}
```

Listing 736 - A function that accepts user input

At the very top, we declare the function with the name of our choosing, in this case LDAPSearch. It then dynamically obtains the LDAP connection string and adds it to the $DirectoryEntry variable.

Afterwards, the $DirectoryEntry and $LDAPQuery parameter is fed into the DirectorySearcher. Finally, the search is run and the output is added into an array, which is displayed in our terminal depending on our needs.

To use the function, let's import it to memory.

```query
PS C:\Users\stephanie> Import-Module .\function.ps1
```

In order to print properties and attributes for objects, we'll need to implement the loops discussed earlier. For now, let's do this directly with the PowerShell command.

To enumerate every group available in the domain and display the user members, we can pipe the output into a new variable and use a foreach loop that will print each property for a group. This allows us to select specific attributes we are interested in. For example, let's focus on the CN and member attributes

```query
PS C:\Users\stephananie\Desktop foreach ($group in $(LDAPSearch -LDAPQuery "(objectCategory=group)"))
  $group.properties | select {.cn},{$member}
```

Even though this is somewhat small, we will receive a lot of output. Let's focus on the three groups we noticed in our enumeration with net.exe.


