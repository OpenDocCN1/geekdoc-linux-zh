# Linux Kernel - 4.13.9 (Ubuntu 16.04 / Fedora 27) - Local Privilege Escalation
linux/local/40510.c

Using searchsplit to find privilege escalation exploits for our target

Let's try the exploit as it targets local/45010.c, since it seems to be newer and matches our kernel version as it targets any version below 4.13.9.

We'll use gcc⁸⁷ on Linux to compile our exploit, keeping in mind that when compiling, we must match the target architecture. This is es important in situations where the target machine does not have a compiler and we are forced to compile the exploit on our attacking machine or in a sandboxed environment that replicates the OS and architecture.

> Listing 512 - Identifying the exploit code instructions.

Luckily, to compile the code into an executable, we need to use gcc and specify the C source code and the output filename. To simplify this process, we could rename the C source filename to match the one expected by the exploit's procedure. Once renamed, we can simply pass the exploit code's instructions to compile the C code.

```
kali@kali:-$ mv 45010.c cve-2017-16995.c
```

> Listing 513 - Renaming the Exploit

To make sure the compilation process goes as smooth as possible, we take advantage of the fact that our target is already shipped with GCC. For this reason, we can simply compile and run the exploit on the target. This allows us to use the correct version of libraries.

```
kali@kali:-$ scp cve-2017-16995.c user@192.168.1.23:
```

> Listing 514 - Transferring the source code

Once transferred, we connect to the target and invoke gcc to compile the source code.

```
user@ubuntu:~$ gcc cve-2017-16995.c -o cve-2017-16995
```

> Listing 515 - Compiling the target

To make sure the compilation process goes as smooth as possible, we take advantage of the fact that our target is already shipped with GCC. For this reason, we can simply compile and run the exploit on the target. This allows us to use the correct version of libraries.
