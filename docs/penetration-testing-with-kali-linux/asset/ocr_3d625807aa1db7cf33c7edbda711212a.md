# The Metasploit Framework

In this Learning Module, we will cover the following Learning Units:

+   - Getting Familiar with Metasploit
- Using Metasploit Payloads

As we have worked through previous Modules, it should be clear that locating, working with, and fixing public exploits is difficult. They must be modified to fit each scenario and tested for malicious code. Each uses a unique command-line syntax and there is no standardization in coding practices or languages.

In addition, even in most basic attack scenarios, there is a variety of post-exploitation tools, auxiliary tools, and attack techniques to consider.

Exploit frameworks aim to address some or all of these issues. Although they vary somewhat in form and function, each offering a variety of exploits, simplifying the use of exploits, easing lateral movement, and assisting with the management of compromised infrastructure. Most of these frameworks offer dynamic payload capabilities. This means that for each exploit in the framework, we can choose various payloads to deploy.

Over the past few years, several exploit and post-exploitation frameworks have been developed, including Metasploit,$964$ Covenant,$965$ Cobalt Strike,$966$ and PowerShell Empire,$967$ each offering some or all of these capabilities.

While frameworks like Cobalt Strike are commercial offerings, the Metasploit Framework (MSF, or simply Metasploit) is open-source, frequently updated, and the for this Module.

The Metasploit Framework, maintained by Rapid7,$968$ is described by its authors as an "advanced platform for developing, testing, and using exploit code." The project initially started as a portable network framework,$969$ and evolved into a powerful tool for penetration testing, exploit development, and vulnerability research. The Framework has slowly became the leading exploit collection and development framework for security auditors. Metasploit is frequently updated with new exploits and is constantly being improved and developed by Rapid7 and the security community.
