Penetration Testing with Kali Linux

One of the benefits of using tools that are popular with network administrators is that they will rarely flagged by traditional antivirus software. This makes them more appealing to attackers, since using them is relatively covert compared to more security-adjacent tools with similar functionality.

We'll use Plink in this security assessment, we will more likely have a shell than GUI access. The Plink manual<sup>590</sup> explains that much of the functionality the OpenSSH client is also built into Plink (although one notable feature Plink doesn't have remote dynamic forwarding.)

> 3rd-party SSH clients for Windows provide port forwarding features. We're using Plink in this case because it's common, lightweight, and specifically designed to run on the command line.

Let's get comfortable with Plink by using it in a revised scenario. In this scenario, we find that MULTSERVER03 has a web application on TCP port 80 exposed. All inbound ports are blocked by a firewall, RDP is no longer available either. The layout is much like the following diagram:

We can compromise MULTSERVER03 through the web application, drop a web shell on it, and gain a reverse shell using it. We have previously found credentials we could use to connect to the RDP service. This is blocked by the firewall, so we cannot connect directly. The OpenSSH client has also been removed, so we can't create a remote port forward using Plink.

However, we have another option: we can create a remote port forward using Plink.
