However, with its relative weaknesses, completely disabling and blocking NTLM authentication requires extensive planning and preparation¹107⁴ as it's an important fallback mechanism and used by third-party applications. Therefore, we will encounter enabled NTLM authentication in a majority of assessments.

Now we've briefly covered NTLM authentication, in the next section we will begin exploring Kerberos. Kerberos is the default authentication protocol in Active Directory and for associated services.

# 22.1.2 Kerberos Authentication

The Kerberos authentication protocol used by Microsoft is adopted from Kerberos version 5 by MIT. Kerberos has been used as Microsoft's primary authentication mechanism since Windows Server 2003. While NTLM authentication works via a challenge-response paradigm, Windows-based Kerberos authentication uses a ticket system.

A key difference between these two protocols (based on the underlying systems) is that with NTLM authentication, the client starts the authentication process with the application server itself, as discussed in the previous section. On the other hand, Kerberos authentication involves the use of a domain controller in the role of a *Key Distribution Center* (KDC)¹10⁷⁵ The client starts the authentication process with the KDC and not the application server. A KDC runs on each domain controller and is responsible for session tickets and temporary session keys to users and computers.
