### 22.1.1 NTLM Authentication

In Password Attacks, we briefly discuss what NTLM is and where to find it. In this section, we'll explore NTLM authentication in the context of Penetration Testing with Kali Linux

NTLM authentication is used when a client authenticates to a server by IP address (instead of hostname), or if third-party applications choose to use NTLM. The NTLM protocol consists of seven steps:

![](img/336d6ea891e7464f18ad64426619ced4_746_0.png)

Figure 282: Diagram of NTLM authentication

In the first step, the server sends a random value called the nonce. Next, the client encrypts the nonce with the username and sends it to the server. The server forwards the response along with the username to the domain controller. The validation is performed by the domain controller. If the two are equal, the authentication is successful.

> With its relative weaknesses, NTLM can be cracked quickly using top-of-the-line graphic processors

### 22.1.2 Kerberos Authentication

The Kerberos authentication protocol used by Microsoft is adopted from Kerberos version 5 by MIT. Kerberos has been used as Microsoft's primary authentication mechanism since Windows Server 2003. While NTLM authentication works via a challenge-response paradigm, Windows-based Kerberos authentication uses a ticket system.

A key difference between these two protocols (based on the underlying systems) is that with NTLM authentication, the client starts the authentication process with the application server itself, as discussed in the previous section. On the other hand, Kerberos authentication involves the use of a domain controller in the role of a Key Distribution Center (KDC)¹. The client starts the authentication process with the KDC and not the application server. A KDC runs on each domain controller and is responsible for session tickets and temporary session keys to users and computers.
