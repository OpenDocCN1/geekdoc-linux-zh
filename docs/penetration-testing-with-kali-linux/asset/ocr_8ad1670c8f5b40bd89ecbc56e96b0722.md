First, we'll create a Windows library file connecting to a WebDAV516 we'll set up. In the first stage, the victim receives a Library-ms file, perhaps via email. When they double-click the file, it will appear as a regular directory in Windows Explorer. In the WebDAV directory, we will provide a payload in the form of a .lnk shortcut file for the second stage to execute a PowerShell reverse shell. We must convince the victim to double-click our .lnk payload to execute.

At first glance, it may seem that we could accomplish this by serving the .lnk file for the second stage with a web server like Apache. The disadvantage is that we need to provide our link to the victim (again, by email). Most spam filters and security technologies analyze the contents of a link for suspicious content or executable file types. This means our links may be filtered before reaching the victim.

On the other hand, a majority of spam filters and security technologies will pass Windows library files directly to the server. When they double-click the file, Windows Explorer displays the contents of the remote location as if it were a local directory. In this case, the remote location is a WebDAV we share on our attack machine. Overall, this is a relatively straightforward process and makes it seem if the victim is double-clicking a local file.

To demonstrate this, we will set up a WebDAV on our Kali system. We'll use Wsgdav517 as the WebDAV server to host and serve our files. We can use pip3 to install Wsgdav.
