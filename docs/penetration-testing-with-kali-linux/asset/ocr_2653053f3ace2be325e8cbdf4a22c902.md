# OffSec

```
kali@kali:# touch filename.txt
kali@kali:# ls -l newfilename.txt
-rw-r--r-- 1 kali kali 6 Jun 12:31 filename.txt
```

In some cases, your touch command may fail because of directory permissions.¹ Although this is beyond the scope of this introduction, it's worth knowing that directory permissions apply to all files and directories within a directory. If the directory permissions don't allow us to create files in that directory, the touch command will obviously fail.

The touch command produced no output. The output of the ls command includes information about the permissions as indicated by the letters rwx, where the 'r' is for read, the 'w' is for write, and the 'x' is for execute. A dash indicates that the user class doesn't have the corresponding permissions. In this case, we have permission to read and write to our new file, but there is no 'x' character in the output, meaning no class has permission to execute.

As the owner of a particular file, we are granted read and write permissions by default when we created it, but we aren't granted executable permissions. In other words, if filename.txt is a program, we would not be able to execute it. This is a small security feature that prevents us from accidentally running something we might not want to.

Let's keep going. In this scenario, let's say we have a simple program that will give us a list of employee names. This program is a Python script we created find_employee_names.py. Try to run it.

```
kali@kali:$ ./find_employee_names.py
zsh: permission denied: find_employee_names.py
kali@kali:$ ls -l find_employee_names.py
-rw-r--r-- 1 kali kali 286 Jun 7 12:31 find_employee_names.py
```

We try running the script by simply entering the name of the file, find_employee_names.py, in the terminal. The ./ command instructs the system to find the file. This should work, but the output is not what we expected. (Zsh: permission denied) error message indicates that for some reason, we're not able to execute (or) our script.

We also ran ls command before. As with our newly created file, there's no "x" character in the output, means that we don't have permission to execute. This explains the 'permission denied' output.

Let's change the executable permission for the file and give ourselves permission to execute the file (put another way, to run it as a program). We can use chmod +x to add the executable permission to our script file. Let's do so and try running the script.
