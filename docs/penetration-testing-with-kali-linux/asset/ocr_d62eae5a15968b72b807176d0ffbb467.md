# 9.2.3 Remote File Injection (RFI)

Remote file injection (RFI) vulnerabilities are less common than LFIs since the target system must be configured in a specific way. In PHP web applications, for example, the allow_url_include option needs to be enabled to leverage RFI, just as with the data// wrapper from the previous section. As stated, it is disabled by default in all versions of PHP. While LFI vulnerabilities can be used to include local files, RFI vulnerabilities allow us to include files from a remote system over HTTP⁰ or SMB². The included file is also executed in the context of the web application. Common scenarios where we will find this option enabled is when the web application loads contents from remote systems e.g. libraries or application data. We can discover RFI vulnerabilities using the same techniques covered in Directory Traversal and LFI sections

Kali Linux includes several PHP webshells in the /usr/share/webshells/php/ directory that can be used for RFI. A webshell is a small script that provides a web similar to the command line interface, making it easier and more convenient to execute commands. In this example, we use the simple-backdoor.php webshell to exploit an RFI vulnerability in the "Mountain Desserts" web application.

First, lets review the contents of the simple-backdoor.php webshell. We'll use this to test the LFI vulnerability from the previous sections for RFI. The code is very similar to the PHP snippet used in previous sections. It accepts commands in the cmd parameter and executes them via the system function.
