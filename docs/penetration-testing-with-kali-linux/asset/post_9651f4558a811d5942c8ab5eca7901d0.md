We now have five passwords in our demo.txt wordlist. Let's mutate these passwords to fit the password policy, which must include a numerical value, a special character, and an uppercase letter.

The Hashcat Wiki<sup>229</sup> provides a list of all possible rule functions. If we want to add a character, the simplest form is to prepend or append it. We can use the $ function to add a character or ^ to prepend a character. Both of these expect one character after the function selector. For example, if we want to append "3" to every password in a file, the corresponding rule function would be `*3`.

When generating a password with a numerical value, many users simply add a "1" at the end of an existing password. Therefore, let's create a rule file containing `$1` to add to all passwords in our wordlist. We'll create a demo.rule with this function rule. We will need to escape the special character `\$` to echo it into the file correctly.

```bash
kali@kali:~/passwordattacks$ echo \$1 > demo.rule
```

Listing 267 - Rule function to add a '1' to all passwords

Now, we can use hashcat with our wordlist, providing the rule file with `-r`, and `-stdout`, which starts Hashcat in debugging mode. In this mode, Hashcat will not attempt to crack any hashes, but may display the mutated passwords.

```bash
kali@kali:~/passwordattacks$ hashcat -r demo.rule --stdout demo.txt
password1
iloveyou
princess1
rockyou
abc123
```

## OffSec

Now, let's address the upper case character of the password policy. When forced to use an upper case character in a password, many users tend to capitalize the first character. Therefore, we'll add the `c` function to our rule file, which capitalizes the first character and converts the rest to lower case.

Let's try an example using two same files: demo1.rule and demo2.rule. We will format these files differently.

In demo1.rule, the rule functions are on the same line by a space. Hashcat will use them consecutively on each password of the wordlist. The result is that the first character of each password is capitalized AND a "1" is appended to each password.

In demo2.rule the rule functions are on separate lines. Hashcat interprets the second function, on the second line, as new. In this case, each rule is used separately, resulting in two mutated passwords for every password of the wordlist.

```bash
kali@kali:~/passwordattacks$ cat demo1.rule
$1 c

kali@kali:~/passwordattacks$ hashcat -r demo1.rule --stdout demo.txt
Password1
iloveyou1
Princess1
Rocky1
Abc231

kali@kali:~/passwordattacks$ cat demo2.rule
$1
c

kali@kali:~/passwordattacks$ hashcat -r demo2.rule --stdout demo.txt
password1
Password
iloveyou1
iloveyou
princess1
Princess
```

Listing 269 - Using two rule functions separated by space and line

Good! We have adapted the demo1.rule file to two of the three password policies. Let's work on the third and add a special character. `!`, which is a very common special character.

Based on this assumption, we'll add `$1` to our rule file. Since we want all functions applied to every password, we need to specify the functions on the same line. Again, we will demonstrate this with different rule files to stress the effect of combining rule functions. In the first rule we will add `$1` to the end of the first rule. In the second rule we'll add it at the beginning of the rule.

```bash
kali@kali:~/passwordattacks$ cat demo1.rule
$1 c!

kali@kali:~/passwordattacks$ hashcat -r demo1.rule --stdout demo.txt
Password1!
```
