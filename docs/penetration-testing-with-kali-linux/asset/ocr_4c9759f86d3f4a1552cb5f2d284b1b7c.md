The listing shows that we successfully used a valid login for the george user.
The dictionary attack worked because the password was contained in the rocky.txt word and we knew the name of the user we wanted to attack. However, if we didn't validate usernames, we would use enumeration and information gathering techniques to find them. Alternatively, we could attack built-in accounts as root (on Linux) or Administrator (on Windows).

In this example, we will attempt to use a single password against a variety of usernames in a technique known as password spraying.⁵⁹⁹

> There are many different ways to gain access to passwords, this is an extremely viable technique. For example, we may gain access using one of the techniques discussed in this Module, or we may find stored as plaintext in a file or through the use of an online password leak database. Services (such as ScatteredSecrets⁶⁰⁰) track password leaks and compromises and select the plaintext passwords. This can be very beneficial during a penetration test, but we must make sure that we do not violate the terms of these services, ensure that we cooperate with the legal owner, and we review the service carefully to determine if it's operating legally. For example, WeLeakInfo⁶⁰¹ was recently seized by the FBI and U.S. Department of Justice for alleged illegal activity.

Let's demonstrate this by executing a spray attack on the RDP service by BRUTE2. To do so, let's shutdown the machine (VM #1) and start BRUTE2 (VM #2) under Resources. In this example, we assume we have already obtained a valid user password (SuperS3cure1337#), and we will attack that password against a variety of user account names.

We'll again use hydra, setting a list of usernames with -L /usr/share/wordlists/dirb/others.txt (which contains over thousand username entries) and a single password with -p 'SuperS3cure1337#'. We'll use the RDP protocol to test this and set the target with 192.168.50.202.
