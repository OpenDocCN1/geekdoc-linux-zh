
# Listing 576 - Connecting to the RDP server with xfreerdp.

In our RDP session, we can run cmd.exe as administrator to open a command window.

Using this window, we can run Netsh. We will instruct netsh interface to add a portproxy rule from an IPv4 port (v4ipv4). This will listen on port 2222 on the external-facing interface (listenport=2222 listenaddress=192.168.50.64) and forward packets to port 22 on PGDATABASE01(connectport=22 connectaddress=10.4.50.215).

```
C:\Windows\system32>netsh interface portproxy add v4ipv4 listenport=2222 listenaddress=192.168.50.64 connectport=22 connectaddress=10.4.50.215
```

```
C:\Windows\system32>
```

# Listing 580 - Nmap showing that port 2222 on MULTISERVER03 is filtered.

The response shows that port 2222 is filtered. It's most likely that the Windows Firewall is blocking inbound connections to port 2222.

![](img/336d6ea891e7464f18ad64426619ced4_609_0.png)

Figure 259: The Windows firewall blocking our attempt to connect to port 2222 on MULTISERVER03 from our Kali machine on the WAN network

To access it, we need to poke a hole in the firewall on MULTISERVER03.

> We'll also need to remember to plug that hole as soon as we're finished with it! We can use the netsh command to create the hole. We need to allow connections on port 2222 specifically for the local interface (ip=192.168.50.64) using a descriptive name "port_forward_ssh_2222". PWK - Copyright © 2023 OffSec Limited. All rights reserved.

```
C:\Windows\system32>netsh advfirewall firewall add name="port_forward_ssh_2222" protocol=TCP dir=in localip=192.168.50.64 localport=2222 action=allow
```

# Listing 581 - Poking a hole in the Windows Firewall with Netsh.
