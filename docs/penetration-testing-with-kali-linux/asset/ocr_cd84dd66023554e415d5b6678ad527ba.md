The steps MULTISERVER sent queries to the root name servers and TLD name server have been omitted for simplicity. In a normal network situation, these steps would precede the request to FELINEAUTHORITY.

An arbitrary DNS query from an internal host (with no other output connectivity) has found its way to an external server control. This may seem subtle, but it illustrates that we can transfer small amounts of information (exfiltrated data) from the network to the outside, without a direct connection, by making DNS queries.

Exfiltrating chunks of plaintext is one thing, but imagine we have a binary file to exfiltrate from PGDATABASE01. How might we do that?

This would require a series of sequential requests. We would convert a binary file into a hex string representation, split this string into a series of smaller chunks, then send each chunk in a DNS request for hex-string-chunk.feline.com. On the server side, we would log all the DNS requests and convert them from a series of hex strings back to a binary. We won't go into further details here, but this should clarify the general concept of DNS network exfiltration.

Now that we have covered the process of exfiltrating data from a network, let's consider how we might infiltrate data into a network.

The DNS specification includes various records,⁹⁹⁶ we're making an A record requests so far. An A record response contains an IPv4 address for the requested domain name.

But there are other kinds of records, some of which we can use to smug arbitrary data into a network. One of these is the TXT record. The TXT record is designed to be general-purpose, and contains "arbitrary string information”⁹⁹⁷
