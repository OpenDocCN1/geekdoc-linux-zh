Notes
=======
* You can use any number of search terms
* By default, search terms are not case-sensitive, ordering is irrelevant, and search between version ranges
* Use '-c' if you wish to reduce results by case-sensitive searching
* And/Or '-e' if you wish to filter results by using an exact match
* And/Or '-s' if you wish to look for an exact version match

The exploits that contain the search parameters are listed in the output. For demonstration, let's presume we want to use the two exploits highlighted during our engagement. We enumerated SMB servers that are vulnerable to SMBGhost and EternalBlue for the sake of this demonstration.

We can copy an exploit into our current working directory using the -m option if we need to modify it. An advantage of copying the exploit into the current working directory is that it will be easier to organize the exploits used in an engagement and correlate them to systems tested.

> All exploits are overwritten when a new package of exploitdb is released, modifying the exploits in their original locations would cause us to lose those changes

Let's copy the exploit with the -m option. We can do this with either the path or the EDB-ID of those exploits, which can be found in their path names.

```
kali@kali:$ searchsploit -m windows/remote/48537.py
```
