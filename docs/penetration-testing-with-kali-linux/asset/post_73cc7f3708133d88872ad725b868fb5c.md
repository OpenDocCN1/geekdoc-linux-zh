The output of Listing 9 may seem intimidating at first. Now, simply note that the last line of the output reads: 'Initialization Sequence Completed', indicating that we have successfully connected to the VPN. Make sure you can find it on your own connection!

We must keep this command open. Closing it will disconnect the VPN connection.

We can open another terminal by clicking File > New Tab.

Once we are connected to the PWK VPN, we will be provided with a TUN0 network interface, which we can view with the IP address. The address assigned to the TUN0 interface will be 192.168.119.x, where x is some value between 1 and 255. Every time we reconnect to the VPN, we might get a different value for x.

In addition, all lab machines in the PWK environment will have addresses that follow the format 192.168.x.y, where x is the same as the third octet of our TUN0 address, and y is the specific octet associated with the machine.

In the course material, we will use different IP addresses for our TUN0 network interface as well as for the lab machines. Please make sure you use the IP addresses assigned to you via TUN0 and the OLP so you can access the machines properly.

## 2 How to Approach the Course

This Learning Unit covers the Learning Objectives:

- Conceptualize a learning model based on increasing uncertainty
- Understand the different components included in PWK

### 2.2.1 A Model of Increasing Uncertainty

Penetration testing - information security in general - is fundamentally reasoning under uncertainty. Consider how a game like chess is different from a game like poker. In chess, you know everything that your opponent does about the game state (and vice versa). You may not know what they are thinking, but you can make predictions about their move.

In this regard, penetration testing is a lot closer to poker. When playing poker, we do not have all the information. We must make predictions based on incomplete data.

In our model of uncertainty, we do not know everything about the target. The only reason why hacking a machine takes time at all is because there are things about it we are not aware of. We therefore need to become comfortable with novel scenarios.

The object level of skills is taught explicitly via the Learning Objectives:
- Gather information
- Find and exploit perimeter defenses
- Escalate your privileges
- Move laterally between machines
- Pivot to other networks

All of this information is covered extensively inside the Modules.

However, the structure of the course enables a second order of learning. This second layer is arguably the most important, though it is much more difficult to quantify. It provides learners with a framework to think, feel, and act in novel scenarios.

PWK contains several learning modalities:

1. Learning Modules
2. Demonstration Module Exercises
3. Application Module Exercises
4. Capstone Module Exercises
5. Assembling the Pieces Module
6. Challenge Labs (type one)
7. Challenge Labs (type two)

We can think about these learning modalities as points along a spectrum, where our uncertainty about the space we're operating in increases as we progress through it. Let's consider each mode by one.

### 2.2.2 Learning Modules

As mentioned above, the text-based Learning Modules all cover specific penetration testing concepts, techniques, and skills. They are all approximately between 30 and 50 pages in length, and they are accompanied by videos that go over the concepts in a visual and interactive manner. They are logically ordered in a way that allows for progressively building on top of previously learned skills.

In our model of uncertainty, they are considered to be no/low uncertainty, because the learner needs to passively read or watch the content. However, we encourage you to start the relevant lab machines and follow along by typing commands and clicking around in the same manner. This helps you internalize the material.

### 2.2.3 Demonstration Module Exercises

There are several types of Module exercise. The objective of the first kind is for the learner to actually absorb the content by following the demonstration.

This type of exercise asks the learner to enter some factual, knowledge based answer to the question, or to obtain a randomized flag by copying the exact commands and input shown in the course material.

The amount of uncertainty is still very low, because the learner can obtain the solution by reading or watching the Module.

For example, the Client Side Attacks Module has a Learning Unit about exploiting Microsoft Office. In that Unit, the learner will be asked to perform the demonstrated techniques on a copy of the original used to create the demonstration.
