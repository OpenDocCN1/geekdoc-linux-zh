Windows services are managed by the Services snap-in, PowerShell, or the sc.exe command line. Windows uses the LocalSystem (includes the SIDs of NT AUTHORITY\BUILTAdministrators in their token), Network Service, and Local Service account to run its own services. Users or programs creating a service can choose one of these accounts, a domain user, or a local user.

Windows services are one of the main areas to analyze when searching for privilege escalation vectors. In this Learning Unit, we'll review three different ways to elevate our privileges by abusing services.

# ## 16.2. Service Binary Hijacking

Each Windows service is an binary file. These binary files are executed when the service is transitioned into a running state.

For this section, let's consider a scenario in which a software developer creates a program and installs an application as a Windows service. During installation, the developer does not secure the permissions of the program, allowing full Read and Write access to all members of the Users group. As a result, a low-privileged user could replace the program with a malicious one. To execute the replaced, user can restart the service or, in case the service is configured to start automatically, reboot the machine. Once the service is restarted, the malicious binary will be executed with the privileges of the service, such as LocalSystem.
