> Listing 131 - Adding "../" to the relative path

The number of ../ sequences is only relevant until we reach the root file system. Theoretically, we can add as many ../ as we want, since we know we are nowhere further back from /. This can be useful in certain situations, such as when we know our current working directory. In this case, we could specify a large number of ../ to ensure we reach the root file system from a relative path traversing.

# 9.1.2 Identifying and Exploring Directory Traversals

In this section we explore Directory Traversal, also known as path traversal attacks. This type of attack can be used to access sensitive files on a web server and typically occurs when a application is not sanitizing user input.

For a web application to show a specific page, a web server provides the file from the system. These files can be located in the web root directory or one of its subdirectories. In Linux systems, /var/www/html/ is often used as the web root. When an application displays a page, http://example.com/file.html for example, it will try to access /var/www/html/file.html. The link does not contain any of the path because the web root serves as a base directory for a web server. If a web application is vulnerable to directory traversal, an attacker may access files outside of the web root by using relative paths, accessing sensitive files like SSH private keys or configuration files.
