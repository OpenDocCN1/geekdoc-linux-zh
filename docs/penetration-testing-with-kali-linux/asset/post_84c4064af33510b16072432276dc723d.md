## 22.2.1 Password Attacks

In a previous Module, we examined several password attacks on network services and hashed information. Password attacks are also a viable choice in the context of AD to obtain user credentials. In this section, we'll explore various AD password attacks.

Before exploring these attacks, we need to account for one important consideration. When performing a brute force or wordlist authentication attack, we must be aware of account lockouts. Many might block the account for attacks and possibly alert system administrators.

To learn more about account lockouts, let's review the account's domain policy as jeff on CLIENT75. We can connect to the system with password HenchmanPutridBonbon11 via RDP. Next, we open a regular PowerShell window and execute net accounts to obtain the account policy.

```
PS C:\Users\jeff>
Force user logoff long after time expires?: Never
Minimum password age (days): 1
Maximum password age (days): 42
Minimum password length: 7
Length of password history maintained: 24
Lockout threshold: 5
Lockout duration (minutes): 30
Lockout observation window (minutes): 30
Computer role: WORKSTATION
The command completed successfully.
```

Listing 797 - Results of the net accounts command

There's a lot of great information available, but let's first focus on Lockout threshold, which indicates a limit of failed logins before lockout. This means we can attempt four logins before triggering a lockout. This might not seem like many, we should also consider the Lockout observation window, which indicates that after thirty minutes after the last login, we can make additional attempts.

With these settings, we can attempt 129 logins in a 24-hour period against every domain without triggering a lockout, assuming the actual users do not login again.

An attack like this might consist of compiling a short list of very common passwords and leveraging it against a massive amount of users. Sometimes this type of attack can reveal a few weak account passwords in the organization.

However, this would also generate a huge amount of traffic. Let's review three kinds of password spraying attacks that have a higher chance of success in an AD environment.

The first kind of password spraying attack uses LDAP and ADSI to perform a low and slow password attack against AD users. In the Active Directory Introduction and Enumeration, we performed queries against the domain controller as a logged-in user with DirectoryEntry. However, we can also make queries in the context of a different user by setting the DirectoryEntry instance.

In the Module Active Directory Introduction and Enumeration, we can provide three arguments, but we can use the LDAP path to the controller, the username, and the password:

```
PS C:\Users\$domainObj = [System.DirectoryServices.ActiveDirectoryDomain]::GetCurrentDomain()
PS C:\Users\$PDC = ($domainObj.PDCOwner)
PS C:\Users\$SearchString = "LDAP://"
PS C:\Users\$SearchString += $PDC + ""
PS C:\Users\$DistinguishedName = "DC=$($domainObj.Name.Replace('.','',DC=','))"
PS C:\Users\$SearchString += $DistinguishedName
PS C:\Users\$New-Object System.DirectoryServices.DirectoryEntry($SearchString,"pete","Nexus123!")
```

The second kind of password attack against AD uses SMB. This is one of the traditional approaches. For every authentication attempt, a full SMB connection must be set up and terminated. As result, this kind of password attack is noisy due to the generated traffic. It is also slow comparison to other techniques.

We can use crackmapexec on Kali to perform this kind of password spraying. We'll select SMB as protocol and use the IP address of any joined system as CLIENT75 (192.168.50.75). Then, we can provide a list of users and passwords to -u and -p. In addition, we will enter the domain name for -d and provide the option -continue-on-success to avoid stopping at the first valid credit. For this example, we will create a text file named users.txt containing a subset of the domain usernames dave, jen, and pete to spray the password against Nexus123!

List 802 shows that crackmapexec identified the two valid sets of credentials as Spray-Passwords.ps1 did. By prefixing the attempted credentials with a plus or minus, crackmapexec indicates whether or not each is valid.

We should note that crackmapexec does not examine the password policy of the domain before starting the password spraying. As result, we should be cautious about logging out users with this method.

As a bonus, the output of crackmapexec not only displays if credentials are valid, but also if the user has administrative privileges on the target system. For example, dave is a local admin on CLIENT75. Let's use crackmapexec with the password Flowers1 marked.

The third kind of password spraying attack we will discuss is based on obtaining a TGT. For example, using kerbrute on a Linux system, we can obtain and cache Kerberos TGT. We need to provide a username and password to do this. If the credentials are valid, we will obtain a TGT. The advantage of this technique is that it uses two UDP packets to determine whether the password is valid, as it sends only an AS-REQ and examines the response.

We could use Bash scripting or a programming language of our choice to automate this method. Fortunately, we can use the tool kerbrute implementing this technique to spray passwords. Since this tool is cross-platform, we can use it on Windows and Linux.
