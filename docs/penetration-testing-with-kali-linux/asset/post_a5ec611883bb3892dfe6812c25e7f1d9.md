Active Directory Services.¹1007 often referred to as Active Directory (AD), is a service that allows system administrators to update and manage operating systems, applications, users, and data access on a large scale. Active Directory is installed with a standard configuration, however, system administrators often customize to fit the needs of the organization.

From a penetration tester's perspective, Active Directory is very interesting as it typically contain a wealth of information. If we successfully compromise objects within the domain, we may be able to take full control over the organization's infrastructure.

In this Learning Module, we will focus on the enumeration aspect of Active Directory. The information we will gather throughout the Module will have a direct impact on the various attacks we will do in the attacking Active Directory Authentication and Lateral Movement in Active Directory Modules.

## 21.1 Active Directory - Introduction

This Learning Unit will cover the following Learning Objectives:

- Introduction to Active Directory
- Define our enumeration goals

While Active Directory itself is a service, it also acts as a management layer. AD contains critical information about the environment, storing information about users, groups, and computers, each referred to as objects. Permissions on each object dictate the privilege that object has within the domain

Configuring and maintaining an instance of Active Directory can be daunting for administrators, especially since the wealth of contained information often creates a large attack surface.

The first step in configuring an instance of Active Directory is to create a domain name as corp.com in which corp is the name of the organization itself. Within this domain, administrators can add various types of objects that are associated with the organization as computers, users, and group objects.

An AD environment has a critical dependency on the Domain Name System (DNS) service. As typical, a domain controller will also host a DNS server that is authoritative for a given domain.

To ease the management of various objects and assist, system administrators often organize these objects into Organizational Units (OUs).¹1008

OUs are comparable to file folders in that they are containers to store objects within the domain. Computer objects represent actual servers and workstations (part of the domain), and user objects represent accounts that can be used to log in to domain-joined computers. In addition, all AD objects contain attributes which will vary depending on the type of object. For example, a user may include attributes such as first name, last name, username, phone number,

AD relies on several components and communication services. For example, when a user attempts to log to the domain a request is sent to a Domain Controller (DC).¹1009 which checks whether or not the user is allowed to log in the domain. Or when more DCs act as the hub and core of the domain, since the DC is such a central domain component, we will pay attention to it as we enumerate AD.

Objects can be assigned to AD groups so that administrators can manage such object as a single unit. For example, users in a group could be given access to a file server or given administrative access to various clients in the domain. Attackers target high-privileged groups.

Members of Domain Admin¹1010 are among the most privileged objects in the domain. If an attacker compromises a member of this group (often referred to as domain administrators), they essentially gain control over the domain.

This attack vector could extend beyond a single domain since an instance can host more than one domain in a domain tree or multiple domains in a forest. While there is a Domain Admin group for each domain in the forest, members of the Enterprise Adm group are granted full control over all the domains in the forest and Administrator privilege over all DCs. This is obviously a high-value target for an attacker.

We will leverage these other concepts in this Module as we focus on the extremely important aspect of AD enumeration. This important discipline can ensure our success during the attack phase. We will use a variety of tools to manually enumerate AD, most of which rely on the Lightweight Directory Access Protocol (LDAP). Where we've introduced techniques, we will leverage automation to perform enumeration at scale.¹1011

## 21.1.1 Enumeration - Defining our Goals

Before we begin, let's discuss the scenario and define our goals.

In this scenario, we'll enumerate the corp.com domain. We have obtained target credentials through a phishing attack. Alternatively, the organization may have provided us with user credentials so that we can penetration testing based on an assumed breach. The user we have access to is steanie who has remote desktop permissions on a Windows11 machine. This user is not local administrator on the machine, which is something we might need to consider.

During a real-world assessment, the organization may define the scope and goals of the penetration test. In our case however, we are restricted to the PWK labs. Our goal will be to enumerate the full domain, finding possible ways to achieve the highest privilege (domain administrator).

In this Module, we will perform the enumeration from one client machine with the low privileged steanie. However, once we starting and we are able to gain access to additional users and computers, we may have to repeat parts of the enumeration from the new standpoint. This perspective shift (pivot) is critical during the enumeration process considering the complexity of permissions across the domain. Each pivot may give us an opportunity to advance our attack.

For example, if we gain access to another low-privileged account that seems to have the same access as steanie, we shouldn't simply dismiss it. Instead, we should always repeat our enumeration with that new account since administrators often grant individuals increased permissions based on their role in the organization. This persistent "rinse and repeat" process is the key to successful enumeration and works extremely well, especially in large organizations.
