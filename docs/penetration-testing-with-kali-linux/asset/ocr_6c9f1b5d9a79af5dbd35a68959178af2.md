# OffSec

It appears the password policy for Confluence is not very strong. After a few minutes of cracking, Hashcat returns passwords for the database, hr_admin and rdp_admin users.

We might suspect that these passwords are reused in other places throughout the network. After some more enumeration of the internal network, we'll find PGDATABASE01 is also running an SSH server. Let's try these credentials against its SSH server. With our new port forwarding, we can create a port forward on CONFLUENCE01 which will allow us to SSH directly from our Kali machine to PGDATABASE01.

First, we need to copy the Original socket process listening on TCP port 2345. We'll create a new port forward with Socat that listens on TCP port 2222 and forwards to TCP port 22 on PGDATABASE01.

```
confluence01:/opt/atlassian/confluence/bin$ socat TCP-LISTEN:2222,fork
TCP:10.4.50.215:22
$ socat TCP-LISTEN:2222, fork:10.4.50.215:22
```

There are only minimal differences between this and the previous network setup. Instead of forwarding to 2345, we are listening on 2222. Instead of forwarding to TCP port 5432 on PGDATABASE01, we are forwarding to TCP port 22 on PGDATABASE01.

We'll use our SSH client to connect to port 22 on CONFLUENCE01, as we are connecting directly to port 22 on PGDATABASE01. We can use the database_admin user, and the password we just cracked using Hashcat.

```
kali@kali:~$ ssh database_admin@192.168.0.53 -p 2222
The authenticity of host '[192.168.0.53]:2222' can't be established.
ED2551 key fingerprint is SHA256:3TRCI2ZwtlLXTS04hVZBn30LYFuVQHQJ]UqYzZo.
This key is not known by any other names
```
