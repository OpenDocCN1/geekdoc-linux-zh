While Nmap is not a vulnerability scanner in the traditional sense, we found that the NSE is a powerful tool that allows us to lightweight vulnerability scanning. In a penetration test, we can use Nmap when there is not a full-fledged vulnerability scanner available or when we want to verify findings from other tools.

However, we have the same factors to consider with any other vulnerability scanner. The NSE script categories can provide useful information, such as if a script is intrusive or safe, but we also need to keep in mind that an NSE script may contain malicious code that gives an attacker full access to our system. For that reason, we always need to verify that the NSE script not provides the needed functionality, but is also safe.

# 7.4 Wrapping Up

This Module provides an overview of vulnerability scanning with Nessus and Nmap, and it provided insight into the different types and considerations of a vulnerability scan.

Vulnerability scanning can be extremely helpful during any kind of security assessment. Configured correctly, vulnerability scanning tools provide a wealth of meaningful data. It is important for us to understand that a manual review of the results is still required and that scanners can only discover vulnerabilities that they are configured for. Finally, we should always keep in mind that vulnerability scanning tools can perform actions that could be detrimental to some networks or targets, so we must exercise caution when using them.

In this Module, we'll begin introducing simplified the web application attacks. Modern development frameworks and hosting solutions have simplified the process of building and deploying web-based applications. However, these applications usually expose a large attack surface due to multiple dependencies, insecure server configurations, a lack of mature application code, and business-specific application flaws.

Web applications are written using a variety of programming languages and frameworks, each of which can introduce specific types of vulnerabilities. Since the most common vulnerabilities are alike in concept and the various frameworks behave similarly regardless of the underlying technology stack, we'll be able to follow similar exploitation avenues.

# 8.1 Web Application Assessment Methodology

This Unit covers the following Learning Objectives:

- Understand web application security testing requirements
- Learn different types and methodologies of web application testing
- Learn about the OWASP Top10 and most common web vulnerabilities

Before we begin discussing enumeration and exploitation, let's examine the different application penetration testing methodologies.

As a penetration tester, we can assess a web application using three different methods, depending on the information we have provided, the source, and the particular engagement rules.

White-box testing describes scenarios in which we have unrestricted access to the application's source code, the infrastructure it resides on, and its design documentation.

Black-box testing (also known as a zero-knowledge test) provides no information about the target.

Grey-box testing occurs whenever we are provided with limited information on the target, including authentication methods, credentials, or details about the framework.
