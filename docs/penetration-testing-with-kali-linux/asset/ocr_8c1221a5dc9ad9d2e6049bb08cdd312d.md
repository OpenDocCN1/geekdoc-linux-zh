For Linux and macOS targets, SSH is used. While we use SSH on Windows, in cases, we can use Server Message Block (SMB)³²⁴ and Windows Management Instrumentation (WMI)³²⁵ to perform vulnerability scans against Windows targets. Both methods allow us to use local or domain accounts and different authentication options.

To get meaningful results in an authenticated vulnerability scan, we need to ensure that our target system is configured correctly. Depending on the authentication we want to use, we need to make sure there is no firewall blocking connections from our scanner. Furthermore, we find antivirus (AV) programs installed on both Linux and Windows targets. AV may flag the vulnerability as malicious and therefore, terminate our connection or render the results useless. Depending on the AV program, we can add an exception³²⁶ for the authenticated scan or temporarily disable it.

Another Windows security we need to consider is User Account Control (UAC)³²⁷ is a security feature that allows users to use standard privileges instead of administrator privileges. An administrative user will run most applications and commands in standard privileges and receive administrator privileges when needed. Due to the nature of UAC, it can also interfere with our scan. We can configure UAC to Ness or temporarily disable it³²⁸ We should consult the Tenable Documentation³²⁹ especially for Windows targets, before we start our authenticated scan.

Our scan is a Linux system without AV. Furthermore, we can click to Save and launch the scan. After the scan has finished, we can review the results. In the Vulnerabilities page, we get a list of the findings for the authenticated scan. In the last section, we have already grouped findings with the MIXED server. For our authenticated scan, let's disable grouping of findings by clicking on the web and selecting Disable Groups.
