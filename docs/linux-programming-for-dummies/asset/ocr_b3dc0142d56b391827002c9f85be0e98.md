The other way to begin \u0061\u007a is to specify the name of the file as you start up \u0061\u007a. Say, for example, that you want to create a file that you call myfirstprogram. Type the following on the command line:

```
$ vi myfirstprogram
```

The \u0061\u007a text editor first tries to find the myfirstprogram file in your current directory. If it finds the file, Linux displays the first page of the file on-screen within the \u0061\u007a text editor. If it doesn\u2019t find the file, however, Linux displays an empty page.

If you later want to save myfirstprogram to a file, you don\u2019t need to specify the name of the file, because the \u0061\u007a text editor automatically saves your work with the name that you specify as you start \u0061\u007a.

# No Mouse!?

All of us face life\u2019s disappointments.

The \u0061\u007a text editor is primitive if you compare it to today\u2019s standards for text-editing programs. You don\u2019t find any conveniences that you expect to see with a word processor. For one thing, you can move your mouse all you want, but the \u0061\u007a text editor ignores it (how dare it!) unless you\u2019re running \u0061\u007a in an X Windows environment. (X Windows is software that enables you to open multiple windows on-screen at the same time.)

So you must settle for either using the arrow keys or issuing one of the \u0061\u007a text editor commands to move the cursor around the page.

You can avoid frustration in trying to move the cursor in the \u0061\u007a text editor by forgetting the way you move the cursor in other programs. The sooner that you become comfortable using the arrow keys or issuing the necessary \u0061\u007a text editor commands, the sooner you can start writing your Linux program.
