This subroutine is passed from the CGI environment variable `HTTP_REFERER` when called. This variable is set to the URL, which called the script. For example, if the `register.html` form can be accessed from an URL such as `http://rhat.mitec.com/asb2/chi2/forms/register.html`, then when it is submitted to the `/cvs.dll/formwizard.p`l script, the CGI object $query sets up `HTTP_REFERER` to be `http://rhat.mitec.com/asb2/chi2/forms/register.html`. The `get_form_name()` code returns the `register.html` portion of the URL.

The script then stores the Web form name in a global variable called `$formName`.

The next code segment is:

```
my $templateDir = $cfg->val($formName, 'template_dir');
my @fieldInfo = $cfg->val($formName, 'form_field_info');
```

This segment passes the Web form name to the configuration object as a section name and retrieves configuration information for the current Web form's template directory and form field information. The information is stored in `$templateDir` and `@fieldInfo` arrays, respectively. The configuration file example, `formwizard.ini`, is shown in Listing 12-4, which shows a sample configuration for a Web form called `register.html`. The configuration file format is quite simple:

```
[section1]
key1 = value
key2 = value
key3 = value

key4 = <<MULTIPLE_VALUES
value1
value2
value3
...
valueN
MULTIPLE_VALUES
...
keyN = value
[section2]
```

This type of configuration file is common in the Windows world and is typically referred to as the ".ini" file. Hence, the module we used here is called `Config::IniFiles`. In our example `formwizard.ini` file, the section name is really the name of the Web form `register.html`. The `$templateDir` variable and the `@fieldInfo` array are set from these configuration lines:

```
[Register.html]

template_dir = /www/asb2/chi2/forms/register
form_field_info=<<FORM_FIELDS
name,text,required,max_chars=50,min_chars=3,case=ucfirst,exclude_
regex=[^a-z .],pattern=none
```
