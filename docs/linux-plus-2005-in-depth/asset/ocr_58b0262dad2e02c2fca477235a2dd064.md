Suppose, for example, your organization has three TCP/IP networks (1.0.0/8, 2.0.0/8, and 3.0.0/8) divided by two routers, as shown in Figure 15-3.

![](bbox=[0.089, 0.237, 0.889, 0.364])

**FIGURE 15-3** A sample routed network

RouterA has an entry in its route table that says it is connected to the 1.0.0/8 network via the network interface that has the IP address 1.0.0.1 and connected to the 2.0.0/8 network via the network interface that has the IP address 2.0.0.1. These two routes are automatically made when TCP/IP is configured. If RouterA receives a packet that is destined for the 3.0.0/8 network, it does not know where to forward it because it does not have a route for the 3.0.0/8 network in its routing table. To add the appropriate route to the 3.0.0/8 network on RouterA, you can run the following command on RouterA:

```
[root@server1 root]# route add net 3.0.0.0 mask 255.0.0.0 2.0.0.2
[root@server1 root]# _
```

Now, RouterA sends any packets destined for the 3.0.0/8 network to the computer 2.0.0.2 (RouterB). RouterB then forwards the packets to the 3.0.0/8 network because it has a route in its route table that says it is connected to the 3.0.0/8 network via the network interface that has the IP address 3.0.0.1.

Similarly, for RouterB to forward packets it receives destined for the 1.0.0/8 network, it must have a route that sends those packets to RouterA via the interface 2.0.0.1:

```
[root@server1 root]# route add net 1.0.0.0 mask 255.0.0.0 2.0.0.1
[root@server1 root]# _
```

Because the list of all routes on large networks such as the Internet is too large to be stored in a route table on a router, most routers are configured with a default gateway. Any packets that are addressed to a destination that is not listed in the route table are sent to the default gateway, which is a router that can forward the packet to the appropriate network or to its default gateway and so on until the packets reach their destination.
