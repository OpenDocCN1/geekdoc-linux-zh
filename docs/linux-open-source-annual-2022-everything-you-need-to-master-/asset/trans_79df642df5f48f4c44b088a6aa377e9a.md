用户创建的沙盒也会获得这种相同的访问权限。

当你运行接下来会看到的任何安装命令时，系统会提示你输入密码。这是因为 *Flatpak* 默认会执行系统级安装。这意味着该程序将对所有用户可用，并且其文件将存储在 */var/lib/flatpak* 目录中。

或者，如果你在命令中使用 `--user` 标志——它只会为你自己的账户安装（此时你不需要输入密码）。在这种情况下，文件将位于 $HOME/.local/share/flatpak。如果你没有系统管理员账户，这将非常有用。

或者，如果你想尝试位于系统其他地方的某个程序的尖端版本，也会用到这种方法。

之所以能进行用户级安装，是因为沙盒的构建方式。你可以这样理解：作为用户，你拥有运行应用程序的能力。该应用程序通过你的用户账户拥有在屏幕上创建窗口、向磁盘写入文件以及访问网络连接的权利。当你以用户身份安装 Flatpak 时，来自宿主系统的任何资源都受限于你使用“常规”程序所能访问的范围。

两个不同版本的 LibreOffice 在同一台机器上同时运行。这是魔法吗？不，只是 *Flatpak*。

```
$ sudo add-apt-repository ppa:alexlarsson/flatpak
$ sudo apt update
$ sudo apt install flatpak
```

安装完成后，你可以通过命令行安装 *Flatpak* 程序。但一些图形界面（GUI）包管理器也支持该格式。例如，KDE 的 *Discover*，如果你安装了合适的后端，就可以管理你的 Flatpak 文件。

在安装了正确的工具后，在开始寻找新应用之前，有一个快速的步骤需要执行。

### Flatpak 仓库中心（Hubs）

*Flatpak* 似乎采用了**仓库中心**（**hubs**）这一术语来描述软件集合，就像 RPM 或 DEB 软件仓库一样。*Flatpak* 官方站点托管了你首先应该添加的仓库中心：*Flathub*。使用你的包管理器在系统中注册它，或者在终端中使用以下命令：

```
$ flatpak remote-add --if-not-exists Flathub https://
flathub.org/repo/flathub.flatpakrepo
$ flatpak remotes
```

### 在菜单中

有几种不同类型的应用程序非常适合打包为 *Flatpak*。其中第一种是商业应用程序。如果商业产品的开发者不轻易让社区拆解他们的应用程序，那么打包一切完全取决于他们自己。

*Flatpak* 提供了一个单一的打包目标，该目标可以跨发行版工作，并且对应用进行沙盒化有助于降低支持成本。*Flathub* 中一些商业（但免费）程序的例子包括 *Steam*、*Slack* 和 *Sublime text*。

另一种适合制作 *Flatpak* 的应用程序类型是大型、复杂的应用程序。它们受益于 *Flatpak* 的原子升级，使更新过程稍微不那么痛苦，而回滚过程则更加轻松。*LibreOffice*（通常是一个 200MB 的更新）和 *Android Studio*（甚至更大），也作为*相对*更方便的 *Flatpak* 可用。

最后，跨平台应用程序已经有了两个完全不同的操作系统目标（至少在桌面端是这样，如果是移动端则更多）。开发者和打包者肯定不需要再为十几个 Linux 发行版的怪癖而烦恼。只需将你的应用打包为 *Flatpak*，即可一切就绪。

### 安装 Flatpak 程序

如果你习惯于在你的系统上使用 *apt* 或 *yum* 或 dnf，从 *Flatpak* 安装应用程序的感觉会非常熟悉。搜索命令会显示你提供的关键词在任何已配置的仓库中心中的命中结果：

```
$ flatpak search calibre
```

这将返回优秀的 Calibre 电子书管理器的结果，它在 Ubuntu 软件仓库中通常版本较旧。注意第一列，它以某种反向域名格式（先 com，然后是域名，依此类推）给出应用程序 ID。你需要将此提供给 Flatpak 的安装命令，以安装你的程序：

```
$ flatpak install com.calibre.ebook.calibre
```

此时 Flatpak 将开始下载并安装你的应用程序以及它所需的任何运行时（org.freedesktop — 见下图右侧截图）。运行时是一组库和其他软件，供应用程序使用。这是 Flatpak 为你解决依赖项的方式。

你或许会说：“等等，这不是 apt 和 yum 为我做的事情吗？”这是一个公平的问题。有几个显著的因素使运行时不同于常规的 Linux 依赖项管理。

- Flatpak 的沙盒环境确保你安装的任何内容都不会与系统本体发生冲突。
- 运行时是固定的一组软件，因此你知道你获得的正是运行该应用所需的确切内容——不多也不少。
- Flatpak 是针对特定运行时构建的，因此无需担心升级会突然导致你的程序崩溃。
- 这种权衡归结为对程序始终具备其运行所需条件的信心，但请注意，为此需要占用更多的磁盘空间。

你还可以使用其他几种方法来安装应用程序。如果你偶然发现了一个非官方的 Flatpak 并下载了它，请使用上面的命令从命令行安装它：

```
$ flatpak install somefile.flatpak
```

最后，Flatpak 提供了一种通过运行安装文件来安装应用程序的方法。这个名为 flatpakref 的文件包含有关程序的一些元数据，包括：

- 其完整名称。
- 应从哪个仓库中心下载。
- 其版本。
- 它是运行时还是应用程序。
- 其 GPG 签名。

从 flatpakref 文件安装与从本地下载的 Flatpak 文件安装相同：

```
$ flatpak install/somefile.flatpakref
```

你也可以使用图形界面包管理器，它应该像处理其他包一样显示并安装 Flatpak（前提是你安装了后端）。

### 运行 Flatpak 程序

安装程序后，你可以如下从命令行启动它：

```
$ flatpak run com.calibre.ebook.calibre
```

程序启动后，你会注意到有几件事。首先，你可以访问你所有正常的 $HOME 目录文件。“但是，但是，”你会问，“我以为 Flatpak 沙盒与系统其余部分是隔离的吗？”你非常敏锐。然而，运行一个无法与你的文件交互的程序没什么用。Flatpak 开发者已经解决了这个问题。

你还应该看到应用程序的条目出现在你的桌面菜单中。如果你没看到，请检查左侧的“快速技巧”，了解如何尝试修复此问题。实际上，在大多数情况下，你不应该能分辨出这些程序与你的发行版提供的程序之间的区别。你可以操作你的文件，播放多媒体文件，并像“常规”程序一样使用它们。

### 管理你的 Flatpak 安装

一旦你安装了一个或两个 Flatpak，当然，你可以使用图形界面包管理器来管理它们。但如果你更喜欢终端，下面的一些命令将很有用。你可以使用以下命令列出已安装的 Flatpak（包括应用程序和运行时）：

```
$ flatpak list
```

结果不仅显示已安装的模块，还显示其安装类型（system/user）。你可以用一条命令更新所有 Flatpak，就像原生包管理器一样：

```
$ flatpak update
```

如果你需要删除某个 Flatpak，请在提示符后输入以下内容：

```
$ flatpak remove [完整限定的应用名称]
```

如果你需要删除已配置的某个仓库中心，可以使用以下命令：

```
$ flatpak remove-remote [远程名称]
```

### 结论

Flatpak 格式的好处是很多的。它为开发者提供了针对多个发行版的选项，同时为用户提供了多种工具来安装由此产生的应用程序。它使程序能够访问其所需的资源，同时限制其访问不需要的内容。它以牺牲一点磁盘空间为代价，解决了传统打包格式中的一些依赖项问题。最后，它为开发者创造了机会，将传统上安装繁琐的应用程序打包成极其简单的格式。

因此，如果你想尝试 LibreOffice 的尖端版本或运行基于 Wine 的游戏（如《魔兽世界》），不妨试试 Flatpak。你真的不会出错！ [LF]

当一个 Flatpak 正在运行时，如果你运行 `ls /` 命令且没有看到任何差异，请运行以下命令：
