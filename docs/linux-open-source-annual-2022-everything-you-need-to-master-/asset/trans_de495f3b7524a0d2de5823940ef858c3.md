## 开放社交网络

受够了 Facebook 比他自己还了解他的情况，**Jonni Bidwell** 开始寻找一个更加开放、更少窥探意味的开放社交网络。

-   关于拥有如此丰富且精心策划的在线人格（这可能并不完全反映我们在现实世界中的真实自我）是否健康，这种争论我们可以留到以后再聊。但作为这本优秀杂志的读者，我们都认同一点：如果我们要将媒体内容和闲聊发布到网上，那么处理这些数据的服务网站最好是开源的，并且拥有清晰的数据使用政策。
-   更好的是，我们应该能够托管这些服务自己的实例。这并不像听起来那么遥不可及。去中心化和联邦架构允许不同的实例相互连接，因此在每个平台上拥有一个账号就足够了。这不像过去在 MySpace、Bebo 和 Geocities 之间关注大量博客的日子，也不像那个托管自己静态网站并撰写长篇大论哀叹网络商业化及利用“免费”却封闭平台之害处的家伙。

也许他的呼吁会被听到，但若不是我们被那些专有社交网络上大量的猫图、“网红”和迷因文化的兴起所分心的话……

社交网络已成为我们在线生活中越来越具有主导力的力量。这里的主要玩家——Facebook、Twitter、Instagram、Tumblr，甚至算上我们宽容地包括进来的 Google+——虽然平台功能各不相同，但它们有一些共同的关键点。

第一点是，它们都是由拥有商业利益的单一公司运营的、拥有庞大用户群的集中式服务。第二点是，它们能够提供免费服务是因为它们从广告中获利。第三点是，它们之所以能从广告中赚取大量收入，是因为它们能够向最高出价者提供高度精准的广告，这得益于它们掌握的用户大量信息。这些现状都不太令人鼓舞，然而不知为何，仍有很大一部分能够上网的人群在这些服务中的一个或多个上面注册了账号。从像 Twitter 这样的集中式服务迁移到像 Mastodon 这样的去中心化服务是一个赋能的过程。但它也可能是一个令人困惑的过程。任何人都可以托管一个 Mastodon 实例（我们将在接下来的页面中教你如何做），而且确实有很多人在这样做。因此，你有成千上万个实例可供选择。

### 主要的 Mastodon 实例

因此，人们提出的第一个问题通常是：“哪个是主要的实例？”这很容易让人发笑，并给出一些讽刺性的指引去查字典中“去中心化”的定义。然而令人困惑的是，实际上在 [https://mastodon.social](https://mastodon.social) 有一个类似旗舰的实例，那里可以找到一些 Mastodon 名人、网红和技术记者（*现在怎么说？——编者*）。该实例由 Mastodon 开发者 Eugen Rochko 管理，并且特别是向新注册关闭的。

即使它是开放的，查看其他实例也是值得的。甚至有一个方便的工具（[http://instances.social](http://instances.social)）可以帮助你根据自己的兴趣、语言和电影剧透容忍度找到一个实例。Mastodon 实例本身就是社区，有点像早期的论坛或今天的 subreddit（子版块）。有些紧密且小规模，有些庞大且松散连接。有些有严格的行为准则，有些容忍可能会冒犯某些人敏感点的内容，有些则简直怪异无比。

一旦你注册了一个实例，你就可以查看本地时间线（Local timeline），它包含该实例上所有人的帖子（toots）（按时间顺序排列，没有算法胡乱重排或推广帖子）。对于小型社区来说这很棒；对于大型社区来说，这就像是从消防水管里喝水——而且里面混杂着可饮用和不可饮用的液体。因此，就像在 Twitter 上一样（在 Mastodon 上被*贬义地*称为 birdsite），你可以关注实例上的个人，然后查看由这些账号组成的家庭时间线（Home timeline）。

Mastodon 巧妙之处在于，在一个实例上拥有账号可以让你关注其他实例上的账号。这在业内被称为联邦（federation），除了听起来相当“星际迷航”范儿外，这也是目前最流行的概念。其实这也并非新鲜事物。想想电子邮件是如何工作的：不同的提供商可以相互通信，甚至注册特定提供商的人可能享受到一些额外的亲近感（即时投递、更少的垃圾邮件过滤、该提供商特有的集成功能）。

![](img/3f314b57ad3c8b08d25e5d1ab47de56d_138_0.png)

联邦组件的集合称为联邦（federation），因此在 Mastodon 的语境中，该术语指的是所有的 Mastodon 实例。除了实例的本地时间线，你还可以查看其联邦时间线。它由该实例成员关注的所有账号的 toots 组成。这是发现其他实例上要关注的账号的好方法。更准确地说，除了知道某人的用户名外，目前这是唯一能发现外部用户进行关注的方式。如果你知道某人的用户名，你只需要在任何实例的搜索框中输入它，然后直接关注即可。

### MASTODON 不是 TWITTER

我们之前提到无法通过名称搜索个人。这是一种刻意的措施，旨在减少骚扰、保护隐私，并总体上使 Mastodon 联邦宇宙（fediverse）比 birdsite 成为一个更健康的地方（哦，*看你们都在行话上加油了——编者*）。事实上，Mastodon 实例只能通过使用标签（hashtags）进行搜索，所以如果你想让你的 toot 被发现，你需要按照英国内政大臣 Amber Rudd 那句不朽的话——理解必要的标签。Mastodon 社区可能对某些类型的言论容忍度较高或较低，但托管（潜在）冒犯性内容的实例可以被其他实例屏蔽或静音。

与 Twitter 的其他关键区别包括：toots 有 500 个字符的限制，以便讨论更有意义；以及关于谁可以看到一个人的 toots 具有更大的灵活性：它们可以对特定用户可见、对所有关注者可见、对公共时间线隐藏或完全公开。此外，Mastodon 对广告持有鲜明的“露齿”（不屑）态度。这并不是完全禁止企业推广，而是非常强调每个账号背后是一个单一的真实人类（即使是机器人也有其主人）。除非 Mastodon 管理员修改代码库（这只影响他们的实例），否则 Mastodon 没有付费广告或数据挖掘的机会——它是为了人类交流而设计的，而不是为了赚钱。

### 你在 @ 哪里？

与 Twitter 类似，给定实例上的用户名以 @ 为前缀。与 Twitter 不同的是，它们还以另一个 @ 后跟实例域名作为后缀。例如，Eugen Rochko 是 @Gargron@mastodon.social，而 Cory Doctorow（我们最喜欢的远见者、作家和 DRM 自由斗士）是 @doctorow@manot.fr。这些看起来很奇怪，但所有这些新奇的标签、句柄和 URI 模式让我们感到困惑。如果你在推文中提到与你处于同一实例上的人，则可以省略实例名称。网络的去中心化性质意味着一个人在某个实例上的句柄（用户名第二个 @ 之前的部分）可能与另一个人所在的其他实例上的句柄相同。这在一定程度上允许了冒充行为，应当报告给管理员，但这并不比其他平台上模仿用户名的情况更严重。

Mastodon 可能因为作为一个可行的 Twitter 替代品而获得大量报道，但它并非唯一的一个。Status.net 的分支 Free Social 引起了很多兴趣，并在某种程度上至今仍是，但它随后被纳入另一个微博客服务 GNU Social 的体系。GNU Social 使用 OStatus 协议系列不仅与其他 GNU Social 实例进行联邦化，还与任何实现 OStatus 的其他服务进行联邦化，包括（目前为止，见下文框图）Mastodon 和 Friendica。GNU Social 是你能找到理查德·斯托曼（Richard M Stallman）的唯一社交网络，尽管在那里他只是以概括其网站更新内容的脚本形式出现。

### 对抗 OSTATUS 现状

当去中心化社交网络的想法处于萌芽阶段（大约在 2009 年）时，设计了一个协议系列来适应这个勇敢的新世界。这个系列被称为 OStatus。OStatus 定义了允许标准社交网络活动的协议：

-   **Atom feeds**：用户可以发布摘要其最近帖子的源
-   **Activity streams**：一种基于 JSON 的格式，用于编码活动和事件元数据，如“喜欢”帖子
-   **WebSub**：前身为 PubSubHubbub (PuSH)，一种用于流、源等的实时通知协议
-   **Saloon**：一种消息交换协议，用于统一对帖子和文章的评论。提供单个评论线程，其中引用的源在不同地方被参考。之所以这样称呼，是因为沙龙里的马会逆水游泳（saloon swim upstream，双关语，saloon 也指西部牛仔酒馆）。
-   **WebFinger**：一种用于通过 URI 标识的实体的发现协议。这些可能是人，在这种情况下，该协议在功能上（但在结构上完全不）类似于 ARPANET 的 Finger 协议。

OStatus 设计的许多部分已被现代替代方案所取代：OStatus 原生不支持私有帖子，这意味着支持私有帖子的平台（如 Mastodon）必须使用额外属性来联邦化私信，而且没有保证其他平台会尊重这些属性。

但不要担心，因为从 1.6 版本（2017 年 9 月发布）开始，Mastodon 实现了新的、更灵活的 ActivityPub 协议。现在我们知道了当时不知道的事情，它有效地提供了分布式社交网络所需的一切。此外，它足够可扩展，能够提供未来所需的功能，并且已经用于比微博客多得多的用途——例如，它是 PeerTube 的核心。在此期间，Mastodon 将支持 OStatus 作为后备，直到 2.0 版本发布。对于这些协议的更详细分析和梳理，我们建议研究 JB Crawford 的优秀文章，可以在以下地址找到：https://lwn.net/Articles/741218。

### 实例 Mastodon

如果你想运行一个 Mastodon 实例，让其他人（甚至只有你自己）可以连接，你需要一台服务器来运行它。这可能是一台在你地下室运行的树莓派，或者一个 VPS（你可以租用一台小的，每月低至 5 美元），或者是任何东西。它应该 24/7 可访问，所以在你每晚关机或经常运行资源密集型游戏的家用电脑上运行它可能是个坏主意。此外，如果你选择在家运行 Mastodon，你需要配置路由器将流量转发到服务器，使用 NAT（针对 IPv4 地址）或通过防火墙设置例外（大多数家用路由器，理由充分，会阻止所有传入的 IPv6 连接尝试）。具体做法取决于所使用的光猫/路由器。你还需要为你的服务器设置一个域名（没有人喜欢通过 IP 地址访问这些服务），你可以使用商业注册商或免费服务（如 DuckDNS，它发行形如 example.duckdns.org 的子域名）来实现。新域名（以 .social、.xyz、.rocks 或其他所谓后缀结尾的域名）在 Mastodon 实例中很受欢迎。如果你只是在测试，可以使用虚构的域名名称，并在 /etc/hosts 中放置一条条目。

与许多 Web 应用程序一样，你无法在发行版的软件包仓库中找到 Mastodon，最好直接从源代码安装。设置好一切是一个漫长的过程。我们需要设置 Node.js、Ruby 和一个 PostgreSQL 数据库以及 Web 服务器（及相关证书）。你可能更喜欢使用 Docker 镜像。预构建的镜像可在 https://hub.docker.com/r/tootsuite/mastodon 获取，它们可以按原样使用或根据你的需求进行定制。在 Heroku 和 Scalify 上也有现成的付费服务。请阅读 https://github.com/tootsuite/ documentation#running-mastodon 以研究可用的选项。我们现在将详细介绍独立安装过程，该过程基于 Ubuntu 18.04 服务器，但除了少数外观上的差异外，其他发行版上的过程是相似的，如果你使用的是桌面版 Ubuntu，过程则完全相同。
