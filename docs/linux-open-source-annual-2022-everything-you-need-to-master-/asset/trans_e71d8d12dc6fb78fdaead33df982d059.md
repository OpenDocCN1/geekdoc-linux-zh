

# 用户体验

它们是福音还是负担？

无论是否轻量，桌面环境都是发行版中最关键的组成部分之一。无论发行版附带哪些功能或应用程序，往往正是桌面环境的外观与感觉、行为以及响应速度决定了你对某个发行版的选择。

也许这解释了为什么大多数主流发行版都会花费大量时间打磨桌面环境，以确保提供丰富且令人满意的用户体验。

但当你用轻量级替代品替换默认环境时，所有这些精心设计策略都变得无关紧要了。话虽如此，尽管这些桌面的主要目标是节省资源，但这并不意味着它们完全忽略了易用性方面。

毕竟，没有人愿意使用一个虽然占用内存极少但操作起来却极其麻烦的桌面。

**Equinox 桌面 7/10**

EDE 并不是最容易安装的桌面。如果你没有使用 Arch，很可能你必须手动从源代码编译它。

该桌面具有一种复古感，并从一个老式启动画面开始。EDE 遵循经典的桌面隐喻，屏幕底部有一个状态栏，最左侧是应用程序菜单。你使用应用程序菜单按钮旁边的文本框来运行命令，这也可以用来快速启动应用程序。还有一个分页器用于切换桌面。

右键上下文菜单提供传统选项，有助于在桌面上放置图标和更换壁纸。你可以使用桌面配置应用程序来微调其他设置，该应用程序提供了一组工具来定制其他基本元素。高级选项只能通过编辑 txt 文件来设置，这使桌面失去了一些易用性分数。

**Lumina 7/10**

根据我们的经验，让这个桌面在 Linux 上运行是一个非常繁琐的过程。它不稳定，并且在大多数发行版上表现异常，经常崩溃，并且桌面上粘贴着奇怪的图形伪影。

Lumina 没有传统的启动画面，而是显示一句名言。桌面布局整洁，底部有一个状态栏。右键上下文菜单有几个实用选项，包括应用程序菜单。这是好事，因为默认的应用程序菜单需要一点时间才能习惯。在默认视图中，它仅显示常用应用程序，要获取已安装应用程序的完整列表还需要额外点击一次。

还有一个文本框帮助你定位想要启动的应用程序。除了应用程序，你还可以从此菜单启动文件管理器和 Lumina 配置实用程序。

## 帮助与支持

当你陷入困境时该怎么做？

EDE 的官方 wiki 有针对各种桌面进行编译的说明，但大部分文档都是为了帮助开发者为项目做出贡献而编写的。此外，与本次综述中的其他同类产品不同，除了在 EDE 自己的网站上有一些报道外，它在其他网站上的关注度很少，这主要是因为其开发速度缓慢。

Lumina 是 TrueOS BSD 的默认桌面，但已被移植到各种其他 BSD 和 Linux 发行版。尽管它有自己的网站，但该桌面提供的入门帮助信息很少。该项目通过 Lumina Desktop Telegram 频道与社区互动。除此之外，没有其他的寻求帮助的途径，因此如果你陷入困境，最好将问题提交到你所在发行版的论坛。

Moksha 是 Bodhi Linux 的官方桌面，但也被移植到其他发行版。该桌面没有自己的支持基础设施，而是共享更广泛的 Bodhi Linux 项目的基础设施。相比之下，LXQt 拥有充足的文档和参与用户社区的途径，以便在你需要协助时提供帮助。既有针对用户也有针对开发者的邮件列表，还有相当活跃的论坛板块。还有一个 wiki，涵盖了各种发行版二进制包的安装以及从源代码编译桌面的说明。

同样，鉴于 Openbox 的历史悠久，该项目拥有来自官方和非官方来源的大量文档和支持。该项目的网站是一个 wiki，上面有很多信息有助于新用户熟悉环境。如果你陷入困境，你的发行版很可能有官方的支持渠道。

## LXQt

8/10

这个桌面环境是结合了基于 GTK 的轻量级桌面 LXDE 和 Razor-Qt 的产物，后者同样轻量级，但成熟度较低，使用的是 Qt 工具包。

得益于这种结合，LXQt 能够呈现出现代桌面的外观和感觉，而不会大量消耗资源。你可以在几乎所有发行版的软件仓库中找到 LXQt，如果你的首选发行版有针对低性能机器的版本，那么它很可能运行的是 LXQt。

它遵循古老但熟悉的桌面隐喻，屏幕底部有一个装满图标的状态栏。应用程序菜单包含传统分类的应用程序列表以及一个用于帮助启动应用程序的搜索框。LXQt 提供了一定数量的可调整选项，有助于定制桌面最常用的方面。

## Moksha 桌面

7/10

这是 Enlightenment 17 桌面的一个分支，并带有 Bodhi Linux 特定的更改，开发人员多年来一直在将这些更改修补到 E17 的代码中。

Moksha 相当直观且易于定制。它使用了许多视觉上有吸引力的部件来显示系统信息。这些部件可以放置在桌面上以及任务栏（在 Moksha 术语中称为 'Shelf'）中。桌面可以完全通过键盘控制，你可以定义自己的快捷键。你还可以使用设置面板来影响安装的外观和感觉。

然而，与 E17 不同，Moksha 在许多发行版的软件仓库中并不 readily available（容易获取）。该桌面的另一个问题是其应用程序菜单。虽然它可以访问应用程序之外的安装区域，但它没有可用于快速启动应用程序的搜索框。

![](img/3f314b57ad3c8b08d25e5d1ab47de56d_36_1.png)

## Openbox

7/10

Openbox 在大多数发行版的软件仓库中都可以 readily available（容易获取）。其极简主义但可定制的特性使其成为有经验用户的稳健选择。

其窗口管理器实际上非常基础，你甚至不会注意到它的存在。默认情况下，你只得到一个没有壁纸的背景和一个光标。

应用程序菜单仅出现在右键上下文菜单中。你可以使用该菜单启动应用程序，这些应用程序在带有常规控制的窗口内运行，表现符合你在任何桌面中预期的那样。窗口管理器通常与桌面上的各种其他轻量级元素结合使用。例如，你可以使用 Tint2、Plank 或 Docky 来创建任务栏，并使用 PCManFM 作为文件和桌面管理器。你还可以使用 obconf 工具定制窗口管理器的不同方面。大量的手动配置可能并不吸引所有用户。

## 性能

### 它们的实际表现是否优于功能完备的默认设置？

由于许多因素的影响，很难用绝对数值来衡量性能。由于我们无法将桌面环境与应用程序分离，我们实际上无法准确测量它们对资源的具体占用。这意味着消耗量会因机器而异，并可能根据安装的应用程序数量而增减。

此外，没有单一的测量点。例如，环境加载可能非常迅速，但由于后台预取或加载组件的事实，当其处于所谓空闲状态时，资源消耗可能非常高。

在我们的测试机器上，EDE 空闲时约为 150MB。启动应用程序时数字会增加，但关闭应用程序后会迅速回落。相关的是，它启动应用程序的速度相当快，LibreOffice 用时 4.3 秒。

然后是 Lumina，它并非为 Linux 设计——这可能就是其启动时间比 EDE 慢三倍左右的原因。它空闲时约为 210MB，但应用程序启动时间仅比 EDE 稍慢。其内存消耗也类似于 EDE，在应用程序首次启动时记录到高峰。

Moksha 与 EDE 一样轻量，但其启动时间和应用程序启动明显更快。虽然 LXQt 启动桌面所需时间稍长，但其应用程序启动时间与 Moksha 相当。

Openbox 比其他桌面快得多。窗口管理器的启动时间取决于它需要加载的元素数量。一旦加载完成，应用程序启动速度是最快的之一。
