
# Web Servers

## 正在寻找在家庭或办公室构建、测试和部署 Web 应用的选项吗？好吧，让我们来了解一下其中一些最好的选择！

### 我们的测试方法

由于我们的 Linux 机器能够在几分钟内构建并设置 Web 服务器，我们的本地机器是本教程中用于测试服务器的设备。为了完成测试，我们真正需要的只是在安装构建和测试软件时能够访问互联网。一旦完成，我们即可在没有互联网的情况下进行测试需求。由于浏览器如今是用户体验服务器性能的主要方式，浏览器响应时间将是关键测试。我们可以测试负载和交付，以产生一些非常有用的数据。

除了浏览器，我们还将使用 Apache 基准测试套件，它提供了非常有用的数据。这将帮助我们衡量服务器的效率，以及为什么某些服务器在特定情况下表现更好。除了原始性能之外，我们还将根据安装难易度、支持和文档的可用性、支持的设备范围、通用功能以及超出基本功能集扩展服务器的能力来评判每个服务器。

![](img/3f314b57ad3c8b08d25e5d1ab47de56d_125_0.png)

万维网的大部分内容用于显示可读的网页。从典型的 Web 开发角度来看，大多数网站和 Web 应用程序都是使用 Web 编码语言的组合构建的；如 HTML、CSS、JavaScript、PHP、Java 和 MySQL，这只是最常见的几种。深入细节一点，网页可以是基本的、速度优化的网页，也可以是具有幻灯片、数据报告和电子商务等功能等许多花哨功能的复杂 Web 应用程序。

由于网站形态各异，不能过分强调了解哪种 Web 服务器能为你所处理的内容提供最佳性能有多么重要。因此，这正是我们将要做的。我们将测试从最基础到更复杂的网站的各种内容示例，同时考察服务器的安装、性能和配置情况。

> “我们将测试从最基础到更复杂的网站的各种内容示例”

我们将研究的服务器是 Apache、Nginx、Lighttpd、Openlitespeed 和 Tomcat。所以，请留下来，我们将探索哪台服务器最适合你的需求。希望你会在这里的测试中发现，它们将影响你的实际托管选择，并使你能够托管响应更快的网站。

### 设备支持
## 在 Ubuntu 和 Raspbian 上安装 Web 服务器

![](img/3f314b57ad3c8b08d25e5d1ab47de56d_126_0.png)

在运行各种 Web 服务器的安装和测试时，由于这两种工具对典型的 Web 开发者都极为有用，我们使用了 Ubuntu 和 Raspbian。在某些情况下，Ubuntu 可以简单安装，而 2018 年最新版本的 Raspbian 没有软件包。幸运的是，我们花时间找到了五个可以相当快地在我们机器上安装的软件包。除了简单安装命令带来的安装问题外，在某些情况下，从源代码安装也会出现错误。因此，既然说到了这里，让我们仔细看看我们在进行安装时发现的设备支持情况。

使用 Apache、Nginx、Lighttpd 和 Apache Tomcat，所有产品都可以使用常见的 `apt-get install` 命令轻松安装在 Ubuntu 和 Raspbian 上。例如，安装 Apache 就像输入 `apt install apache2` 一样简单。

Openlitespeed 的文档声称可以从软件仓库安装，然后执行典型的 `apt-get install` 命令。然而，在 Ubuntu 和 Raspbian 上，该方法完全失败。这有点烦人，但还有其他选择。在两台设备上尝试从源代码安装 Openlitespeed 后，那也失败了。`./configure` 命令无法运行，因为下载压缩文件中缺少该文件。既然他们按从左到右的顺序排列安装方法，我们已经浪费了时间才到达最终手段。幸运的是，在第三次尝试中，Openlitespeed 通过单击一行代码的方法成功安装在 Ubuntu 上，但无法在 Raspbian 上安装。因此，在测试 Web 服务器方面，该产品在设备支持方面以多种方式名列底部。

除了 Apache 和 Tomcat，所有服务器都使用 80 端口打开网页。默认情况下，Tomcat 使用 8080 端口。因此，运行 Tomcat 并使用 `localhost:8080` 将打开它。不幸的是，如果我们已经使用 8080 端口用于其他服务，例如 Linux Motion，我们需要将其配置为使用另一个端口，如 7000。

所有服务器的一大优点是它们安装得相当快，因此，在执行命令后，我们几乎可以立即在设备上使用它们。

**结论**

| 服务器 | 得分 | 服务器 | 得分 |
| :--- | :--- | :--- | :--- |
| APACHE | 10/10 | TOMCAT | 9/10 |
| NGINX | 10/10 | OPENLITESPEED | 6/10 |
| LIGHTTPD | 10/10 | | |

Openlitespeed 在这里失利，因为它是不如其他服务器那么知名的服务器。

### 文档和支持
## 关于手册页和在线帮助的情况

![](img/3f314b57ad3c8b08d25e5d1ab47de56d_126_1.png)

从基本安装来看，只有 Lighttpd 和 Apache 拥有手册页条目。与此同时，所有五个测试产品都有在线手册页，Openlitespeed 除外。虽然手册页是一个很好的信息来源，但在线有极好的文档。

在首次设置和运行期间，在各供应商网站上花费了相当多的时间后，Apache、Tomcat 和 Nginx 似乎拥有组织良好、易于遵循的信息，允许轻松安装、修改和配置。

Openlitespeed 有多个选项，在 Ubuntu 和 Raspbian 上都需要大量的尝试和错误直到它起作用。在线看起来，它似乎是一个经过精心整理的商业产品，拥有流畅的图形用户界面，并与 WordPress 和其他软件很好地集成，但它缺乏家庭 Web 服务器和测试所需的努力。

Lighttpd 是另一个缺乏来源网络文档的 Web 服务器。幸运的是，它设置和使用的很容易，所以我们避免了徒劳无功。最后，幸运的是，我们有 Google 来寻找额外的解决方案。事实上，我们花了大部分时间来获取配置并让一切完美运行所需的解决方案。

对于 Nginx、Tomcat、Apache 和 Lighttpd，似乎有足够好的论坛问答可以解决我们的问题。Openlitespeed，尽管它在网络上的托管使用排名相当高，但似乎拥有最糟糕的信息和答案。这几乎就像我们的问题没有答案，而且家庭用户对这台服务器的参与非常少。

**结论**

| 服务器 | 得分 | 服务器 | 得分 |
| :--- | :--- | :--- | :--- |
| APACHE | 10/10 | TOMCAT | 9/10 |
| NGINX | 10/10 | OPENLITESPEED | 5/10 |
| LIGHTTPD | 7/10 | | |

Nginx 和 Apache 占据主导地位，在线帮助远超竞争对手。

### 部署和管理
## 服务器是否易于设置和使用？

Web 服务器将通过命令行安装。一些安装非常简单，使用 `apt-get install` 的单行命令，而其他一些需要使用几个额外命令从源代码安装。安装后，服务器可用于快速显示默认网页。由于我们将使用服务器端语言 PHP 和 MySQL 测试我们的服务器，我们将看到它们与每个服务器结合使用的难易程度。深入细节，我们将看到哪些软件与基本命令结合使用最容易，或者只需对配置文件进行非常基本的文本编辑。除此之外，我们将研究配置每个服务器，使其运行更高效，并帮助我们获得所需的结果：一个加载快速、不会让潜在访客因等待页面加载而感到沮丧从而放弃网站的网站。为了达到这个目标，我们使用 Apache 基准测试工具来计算我们 Web 文件的每秒请求率。该工具可以发出数千次请求并模拟并发用户。

### Apache 10/10

在 apache2 安装期间，我们可以安装 mysql-server、PHP、libapache2-mod-php 和 php-mysql。之后，我们可以简单地编写直接可用的 PHP 脚本，或使用 WordPress、Laravel 或 Magento 等流行工具构建完整的 Web 应用程序。Apache 安装和测试性能方面的易用性使其成为在上传并迁移到某种托管平台（无论是共享托管、VPS 还是专用托管）到互联网之前，构建和测试 Web 应用程序的绝佳选择。由于许多 Web 托管服务商仍在使用 Apache，它提供了一种一致、坚固、统一的测试系统。然而，使用 Apache 时，调整它可能非常重要，因为如果我们不充分利用它，它可能会很慢。为了使测试基本化，我们有一些工具，如浏览器检查器和 Apache 基准测试工具，帮助达到我们的速度目标。

![](img/3f314b57ad3c8b08d25e5d1ab47de56d_127_0.png)

### Nginx 9/10

在 Nginx 安装期间，我们還可以安装 php-fpm，以便能够构建和测试 PHP 应用程序。然而，这其中的内容远不止于此。为了能够在 Web 浏览器中打开 PHP 文件，我们还需要编辑文件 /etc/nginx/sites-available/default 并取消注释以 `location ~ \.php$ {` 开头的条目。在我们移除阻止 PHP 代码运行的注释后，我们可以重新加载 Nginx，PHP 运行良好。现在，我们可以运行和测试任何 PHP 应用程序，无论是自定义脚本、WordPress、Magento、Joomla、Drupal 还是如此长列表中的许多其他。现在，Nginx 表现非常出色，这是其近年来 popularity 增加的主要原因之一。并且由于 Nginx 设置和运行如此简单，它是第三方 Web 托管的一个绝佳选择。

### 速度和性能
## 基准测试每秒请求数

在我们的性能测试中，我们使用了浏览器和 Apache 基准测试工具。浏览器测试相当简单，我们在页面上右键单击，选择“网络”，刷新页面并单击显示我们 URL 的行。单击该行后，我们可以访问请求和响应头。这些头让我们能够看到一些性能方面的内容，如服务器本身（即 Nginx、Apache 或 Lighttpd）、Keep-alive、gzip 和缓存控制。就 Apache HTTP 基准测试工具而言，我们用它来测试获取图像 25,000 次，因为这是估算每台服务器每秒请求数的粗略想法的好方法。为了考验它们的能力，我们设置它们运行以获取 200Kb JPEG 文件的超过 25,000 次请求，并发请求（用户）为 50。

前两台服务器 – 都在八秒范围内 – 是 Nginx 和 Lighttpd（又称 Lighty）。紧随其后的是 Openlitespeed，出现在大约 14 秒处，Apache 在 19 秒，最后，Tomcat 以略超过 20 秒的成绩落在最后。

查看每秒请求数的细节，我们看到 Nginx 管理着大约 3,011 次，Lighttpd 紧随其后为 2,890 次。其余的稍微靠后地聚集在一起，Openlitespeed 为 1,776，Apache 为 1,314，Tomcat 为 1,229。尽管这些时间相当分散，肉眼无法分辨使用的是哪台服务器，因为所有平台上的图像和页面加载都足够快。因此，所有工具都适合在本地机器上测试 Web 应用程序。当使用完整的 URL 进行测试时，例如默认 WordPress 安装，各服务器在图像请求方面的速度差异结果非常相似。

**结论**

| :--- | :--- | :--- | :--- |
| APACHE | 7/10 | TOMCAT | 7/10 |
| NGINX | 10/10 | OPENLITESPEED | 8/10 |
| LIGHTTPD | 10/10 | | |

**Nginx** 和 **Lighttpd** 开箱即用的速度就是快。
