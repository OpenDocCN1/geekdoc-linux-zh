

## 发行版

很可能让事情变得更简单了。值得注意的是，FreeBSD 计划在即将到来的版本中提供直接的 UEFI 启动支持。

### 安装软件

FreeBSD 提供了两种获取软件的方式。第一种是 Ports Collection（端口集合）。如果你在安装时包含了它，可以探索 `usr/ports` 目录。或者，你也可以选择安装预编译的软件包。这些方式各有优缺点。安装预编译的软件包速度更快，并且可能更容易、更少出错。然而，在你的机器上构建软件能更好地针对你的硬件进行优化。第一步是在系统中设置好软件包工具。在 shell 中输入 `pkg`，如果它尚不存在，系统会提示你下载它。你的第一步应该是更新软件包数据库：

```
pkg update
```

然后，使用以下命令搜索你所需的程序：

```
pkg search [your desired term]
```

要安装某个东西，请使用此命令：

```
pkg install [package name]
```

你将在终端中看到安装的进度，包括依赖项的计算、所有软件的下载以及实际安装过程。如果你需要回溯，这也同样简单：

```
pkg delete [package name]
```

你可以使用以下命令查看已安装的所有软件包：

```
pkg info
```

再次强调，如果你是一位经常打开快速终端在 Ubuntu 或 Fedora 中搜索和安装软件的 Linux 用户，你只需 14 秒就能掌握这个用法。并且安装 Ports 同样简单。

### 日常使用

在日常生活中使用 FreeBSD 正好如前一节所述。当你浏览控制台时，你会发现很多东西非常熟悉。当然，应用程序在 FreeBSD 上的操作与在 Linux 上一致。只有两个领域需要做一些调整。第一个是系统配置。虽然 `/etc/` 目录存在并确实包含许多配置文件，但有一个对 FreeBSD 而言非常独特且有用的文件。在使用 FreeBSD 时，你会看到关于在 `rc.conf` 文件中创建条目的引用。该文件包含一系列重要的系统级设置。如果你打开它，你会看到一些你在安装期间设置的项（例如网络配置）。它非常短，但可以预料它随着你的个人配置而变长。

`bsdconfig` 实用程序可以帮助完成其中一些任务，它是在不安装包含控制面板的某种桌面的情况下你能得到的最接近控制面板的东西。它是一个菜单驱动的终端程序，与安装程序类似，你使用方向键和 Tab 键在对话框中跳转。这不会造成太大调整，因为即使一些现代软件包系统也会在配置单个软件包时使用这类对话框。

你还应该预料到在 FreeBSD 上需要做一些更多的故障排除。需要澄清的是，这并不是因为 FreeBSD 中的事物是损坏的，而是 FreeBSD 在设计上以不同的方式处理某些事情，Linux 用户必须通过研究来学习。例如：`pkg` 命令确实遵循依赖项，但方式并不完全像 Linux 用户预期的那样。

作者快速发出了 `pkg install lnx` 命令，输出指示将安装多个软件包。完成后，`startx` 命令因错误而失败。一些快速检查发现 LXQt 桌面已安装，但 Xorg 没有。当 X 安装后启动再次失败时，进一步探索显示，虽然基础 X 服务器和顶级 LXQt 桌面存在，但位于它们之间的 Qt 工具包仍缺失。即使安装了它，使用 `startx` 命令启动的默认 twm 基于 afloat。

### FreeBSD 的 Linux 兼容性

虽然 FreeBSD 可能与其他 BSD 不兼容，但它确实提供了一个允许你在其上运行 Linux 软件的功能。Linux 二进制兼容性层允许你安装 32 位和 64 位 Linux 应用程序，尽管看起来对基于 386 的软件支持正在减弱。要添加 Linux 兼容性，首先为 FreeBSD 内核添加 Linux 模块（需以 root 身份登录）：

```
kldload linux64
```

然后安装仿真层的软件包（或构建端口）：

```
pkg install emulators/linux-c7
```

将以下内容添加到 `/etc/rc.conf`（以确保在启动时加载 Linux 兼容性）：

```
linux_enable="YES"
```

此时，FreeBSD 系统已设置为运行 Linux 程序。你可能需要考虑的其他事项包括：

- 程序是否需要任何共享库？如果是，你需要找到并安装它们。
- 程序是否以特定的软件包格式提供？一些传统软件包如 .DEB 或 .RPM 很容易解压，但较新的如 Flatpak（详见 LxF 244 期的深入探讨）或 Canonical 的 Snap 可能没那么简单。
- 查阅手册（www.freebsd.org/doc/handbook/linuxemu-lbc-install.html）以了解有关这些及其他主题的更多信息。

手动添加一个带有以下内容的 .xinitrc 文件最终让 Starship 能够启动一个可用的 LXQt 桌面。再次强调，这并不意味着发生的事情是错误的。但基于过去的 Linux 经验，作者期望安装包含所有依赖项，并且启动脚本能“自动”启动所有内容。但在 FreeBSD 中，你需要“无视那些”来自己安装 X.org，以标准方式启动它，并确保你的环境设置为在启动时触发 LXQt。设备指定也有类似的差异。在 FreeBSD 中，你引用第一个内部驱动器为 `/dev/ada0`。分区也被称为切片，因此根据你查看的位置，第二个分区可能是 `/dev/ada0s1`。同样，默认的光盘驱动器表示为 `/dev/cd0`。使用“ada”来表示硬盘是“错误”的吗？谁知道！只需理解你可能需要在此期间进行一些术语的转换。

## FreeBSD 是 DIY

这体现了 BSD 的理念，即使用你想要的软件组装你想要的系统。在撰写本文的过程中，作者偶尔访问 FreeBSD 留言板（https://forums.freebsd.org）寻找关于 GUI 软件包管理器的提示。首先，FreeBSD 社区在论坛上非常活跃，并给出极其准确的答案。但对于像“FreeBSD 的 GUI 软件包管理器在哪里”这样的问题，回答是响亮的：“我们没有，我们喜欢 pkg 或 port。尽管随意尝试直到你找到一个你喜欢的。”这并非旨在轻蔑，而是鼓励发帖人构建符合其口味的平台。然而，FreeBSD 开发人员已经尽力在合理的情况下使组装变得简单。一个快速的坦白：这位作者完全准备好去寻找 Xorg 配置（或 XF86Config 文件，特定年龄的人会记得它们）并调整行距。在过去，这是让 Linux 系统运行极其痛苦的一部分。但在 FreeBSD 的 X.org 安装过程中，图形系统被配置，结果是一个看起来不错的桌面。因此，你可能会问，为什么上一节中出现的问题会发生？为什么整个桌面堆栈没有安装？这是因为 FreeBSD 并不假设这位作者想要使用 X.org。也许意图是 Wayland。从这种意义上说，FreeBSD 通常会“做你说的，做你意指的”。因此，在 FreeBSD 中发出命令之前，你应该明确你要做什么，特别是如果你不理解其功能（例如，有一个命令会愉快地从源代码重建你的整个系统，可能占用它几个小时）或如前几节提到的目标设备。换句话说，在开始格式化驱动器之前，理解 FreeBSD 关于磁盘分区的术语。

## 使用 Ports Collection

首先，在你的机器上导航到 Ports Collection：

```
cd /usr/ports
```

一个 Port 基本上是一个用于构建相关程序的配方。浏览各个子文件夹，你会开始看到一些老朋友，例如 X11-wm 文件夹中的桌面，/www 中的 Firefox 浏览器，以及（万岁！）/editors 中的 Emacs。为了搜索应用程序，我们需要首先对系统中所有的端口进行索引：

```
cd /usr/ports
make index
```

使用以下命令搜索某物：

```
make quicksearch name=[name_of_your_search_target]
```

这将显示结果名称、位置和简短描述。如果你找到了你想要的并希望安装它，可以使用下面的命令。只需记住你将在编译，而不仅仅是安装应用程序及其所有依赖项：

要构建和安装程序，导航到其 Port 目录并发出以下命令。请注意 clean 参数将确保任何临时构建文件在完成后被删除。

```
make install clean
```

坐下来看着信息滚动，几分钟后/几小时后/几天后（取决于应用程序的大小），你刚出炉的程序将准备就绪。卸载也同样简单（再次，从 Port 目录）：

```
make deinstall
```

有时安装二进制软件包是获取你想要软件的最快和最简单方式。并且像 Linux 软件包管理器一样，它是依赖项感知的。
