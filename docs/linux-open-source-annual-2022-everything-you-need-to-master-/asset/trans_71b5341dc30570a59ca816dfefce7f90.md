
## Lighttpd 10/10

在安装 lighttpd 期间，我们可以安装 `fast-cgi` 和 `fastcgi.php`，以便构建和测试 PHP 应用程序。但事情远不止于此。Lighty 安装速度非常快，输入命令后几乎能即时响应。此外，简单的命令为我们完成了繁重的工作，PHP 和 MySQL 数据库都能按预期正常工作。然而，我们必须注意，如果在安装 `fast-cgi` 后没有启用并重载 Lighty，我们的浏览器将会收到 403 错误。

Lighty 安装完成后，它会从 `/var/www/html` 文件夹中查找其中一个默认文件（index.html、index.lighttpd.html 和 index.php）。快速设置 Lighty 且所有文件和文件夹都位于与 Nginx 和 Apache 相同的路径这一事实，使其也成为一颗瑰宝。能够在一个位置构建并在同一地点测试所有服务器，而不是让文件散落各处，这确实很美好。

![](img/3f314b57ad3c8b08d25e5d1ab47de56d_128_0.png)

## Openlightspeed 8/10

在安装 Openlightspeed 期间，会创建一个 index.html 文件，用作默认网页。此外，PHP 开箱即用，因为它自带名为 LiteSpeed SAPI PHP 的处理器。与 Nginx、Apache 和 Lighttpd 不同，html 文件存储路径为 `/usr/local/lsws/Example/html/index.html`。

对于 Openlightspeed 而言，其优势在于测试根文件夹中的简单 HTML 和 PHP 文件。然而，一旦我们想要测试像 WordPress 或 Laravel 框架这样的实际应用，其默认配置就会显得力不从心。如果我们在子目录中工作，我们需要修改 `vhconf.conf` 文件并手动添加子文件夹。另一个问题是，那些能无缝配合 Nginx、Apache 和 Lighttpd 工作的 MySQL 安装，却无法直接配合 Openlightspeed 工作。我们之前用 PhpMyAdmin 构建的任何数据库都无法最初使用。

![](img/3f314b57ad3c8b08d25e5d1ab47de56d_128_1.png)

## Tomcat 9/10

Tomcat 安装后即刻可用。然而，与 Openlightspeed 类似，Tomcat 的文件默认位于不同于 Apache、Nginx 和 Lighttpd 的位置。实际上，它们位于 `/var/lib/tomcat7/webapps/ROOT` 目录中。此外，与其他在 80 端口运行的 Web 服务器不同，其默认端口是 8080。

与其他所有服务器不同，Tomcat 旨在提供 Java Servlets 和 JSPs。因此，对于 Java 项目，可以将 WAR（Web 归档）文件放入 Tomcat 进行部署。虽然 Tomcat 可用于提供浏览器解释的文件（如 HTML、CSS 和 JavaScript），但它也可以配置为解释 PHP 文件，尽管它并非为此目的设计，这使其成为 Java 编程的更专业化工具。考虑到 Tomcat 基于 Java，作为流行的 Web 服务器，它表现相当不错，似乎总能无问题地工作。

![](img/3f314b57ad3c8b08d25e5d1ab47de56d_128_2.png)

## 定制

添加和启用模块以及自定义目录选项。

由于大多数网站都会使用服务器端语言，例如 WordPress 安装或用于处理 HTML 联系表单的基础代码，让我们看看实施起来有多容易。

在某些其他服务器上扩展 Web 服务器更容易。然而，从简洁性角度来看，Apache 和 Lighttpd 都使得检查模块并根据需要启用它们变得非常容易。例如，Apache 中默认未启用的一个此类模块是 mod_cache。相反，Nginx 一开始就提供了很多功能，但启用和禁用它们的单个命令并不是程序的一部分。对于 Nginx 来说，添加和配置模块超出了新手的使用范围。

Openlightspeed 也不像 Apache 或 Lighttpd 那样直接明了，但它们至少都可以通过一些相对简单的命令为中级用户提供扩展。

除了向服务器添加模块外，总有一天我们会想要编辑服务器配置文件本身，或者向文件夹添加文件以进行自定义配置，例如在 `.htaccess` 文件中。

Apache 和 Tomcat 使得此类配置变得非常容易，因为我们可以在任何文件夹中添加 `.htaccess` 文件并创建自定义规则、浏览器缓存等。与此同时，Openlightspeed 有方法可以让我们将旧的 Apache `.htaccess` 迁移到其自身系统中并使用相同的重写规则，这便于从旧的 Apache 服务器过渡。

Lighttpd 在自身的 lighttpd.conf 中有创建自定义文件的方式。对于 Nginx 和 Lighttpd，大多数自定义规则都将在配置文件中完成。

Apache 非常灵活，因为我们可以使用单个 .htaccess 文件创建服务器规则，并使用单行命令启用和禁用模块。

## 基本功能

我们的 Web 服务器能开箱即用吗？

开箱即用，它们都能工作。然而，由于我们有不同且变化的需求，我们可以看看它们自带什么功能以及这如何适合我们。对于测试 HTML 和浏览器解释的代码（如 CSS 和 JavaScript），它们默认都显示静态内容。但是，一旦我们需要添加像 PHP 这样的服务器端语言，我们不仅需要安装它，还需要服务器能够与其有效通信和使用。好吧，对于所有软件包，真正需要的只有几个小调整就能实现这一点。花一两分钟配置 PHP 后，以便我们可以运行 Wordpress 等数据库应用程序，其余需要考虑的细节是速度优化和安全。所以，让我们过一遍列表，看看安装后我们有什么。

对于 Apache，默认启用的模块包括核心等瑰宝，如 core、module、alias、module、auth_basic、module、deflate、module、dir、module、env、module、php7_module 和 rewrite、module。除了开箱即用的模块外，Apache 还有许多其他模块可以用单个命令启用，包括 SSL 和 mod_expire。Nginx 也拥有一些不错的模块，如 fastcgi、ssl、gzip 和 geoip。Lighttpd 还有一系列默认使用的模块，即 mod_access、mod_alias、mod_compress、mod_redirect 和 mod_rewrite。这些可以在 /etc/lighttpd/lighttpd.conf 文件中找到。Openlitespeed 也能开箱即用，尽管它落后于 Nginx 和 Lighttpd。此外，Openlitespeed 需要更多中级用法才能进一步定制。Tomcat 适用于简单的静态文件和 WAR 文件，因此它是测试这些应用程序的首选解决方案。

> 许多有用的模块默认已启用，我们还可以使用浏览器检查标题以显示功能和一些我们应该隐藏的数据。

Apache 是唯一一个新手可以深入了解并使用基本命令进行配置的服务器。其他服务器更侧重于中级用户。

## 安全功能

我们能安全地托管网站吗？

当我们启动 Web 服务器并测试本地页面时，我们是唯一通过端口 80 访问我们网站的人。然而，一旦我们将网站部署到线上，我们就需要更认真地对待安全，因为我们的路由器将转发端口 80，以便外部用户可以访问该网站。让我们快速过一遍我们的 Web 服务器，看看我们需要做哪些更改。

对于默认的 Apache 安装，我们应该做几处更改；例如安装 mod_security 模块并对 /etc/apache2/conf-enabled/security.conf 和 /etc/apache2/apache2.conf 文件进行几处更改。对于 /etc/apache2/conf-enabled/security.conf 文件，我们应该取消注释 ServerSignature Off 和 ServerTokens Prod。我们还可以编辑 apache2.conf 文件以关闭目录浏览并限制大请求，以保护免受拒绝服务攻击。对于 Nginx，我们可以打开 /etc/nginx/nginx.conf 文件并将 server_tokens 设置为 off 以隐藏服务器版本。此外，我们有能力通过 IP 限制页面，使我们的管理员账户固若金汤。我们还可以对默认配置文件进行一些限制。Openlitespeed 在默认情况下控制文件方面表现出色。我们不得不编辑配置文件才能使用子文件夹等。为了增加更多的保护层，我们可以安装 mod_security 模块并使用带宽和连接节流。

对于 Lighttpd，我们可以按自己的喜好编辑 lighttpd.conf 文件。因此，我们可以设置最大连接数、最大保持活动、SSL、每个 IP 的最大连接数并防止图像劫持。Tomcat 需要相当多的配置调整才能部署实时网站。我们可以隐藏服务器头部、启用 SSL/TLS 并强制执行 HTTPS。我们还可以不以 root 身份运行 Tomcat、禁用 SHUTDOWN 端口、禁用发送 X-Powered-By HTTP 头部、禁用 Tomcat 显示目录列表以及限制连接器可用性。此外，我们应该修改 php.ini 文件，设置 expose_php = Off。为了进一步测试，我们总是可以安装 wapiti 和其他像 Monitor 这样的监控工具来测试和监控我们的本地网站。更进一步，我们可以使用 Kali Linux 进行渗透测试。

Nginx、Lighttpd 和 Apache 的配置文件使得添加更多安全措施变得容易。
