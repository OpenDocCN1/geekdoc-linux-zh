
## 下一代发行版技术

光鲜易用只是一方面，那么哪些发行版搭载了最新的 Linux 技术呢？继续往下读，答案即将揭晓……

Fedora 是 Red Hat 的社区发行版，新技术会先在这里经受锤炼，之后才会进入其商业产品——Red Hat Enterprise Linux（RHEL）。Fedora 是首个引入 systemd、PulseAudio 和 SELinux（由 NSA 提供的访问控制机制）的发行版。这些头衔或许会让部分读者感到不安，但不管你是否喜欢，它们都会长期留存。从历史上看，Fedora 一直是最能体验未加修饰的 Gnome 3（别再抱怨那个关闭动画了）的途径。该桌面环境提供了最佳的 Wayland 体验，而 Fedora 也是首个默认启用 Wayland 的发行版（还在为那个关闭动画抱怨吗？）。因此，它无疑是一个开先河式的发行版。

最新的 Fedora 32 甚至启用了 Firefox 的新 Wayland 后端。如果你想尝试点新花样，请参照我们在网络浏览器专题（第 42 页）中的指南，启用 Webrender 和 VA-API 加速（你可以顺便阅读 Martin Stransky 在 https://mastarsky.wordpress.com/2020/06/03/firefox-on-fedora-finally-gets-va-api-on-wayland 上的博客了解更多）。事实上，VA-API 加速早在一年多前就在 Fedora 的构建版本中首次亮相（此前曾出现在 Chromium 中）。既然 Fedora 能带来新功能、更流畅的浏览器体验，你为什么不使用它呢？

偶尔，Fedora 会因其对软件自由的哲学理念而被某些人绕开。如果你想要使用专有软件（包括 Nvidia 驱动程序）或受专利限制的多媒体编解码器，则需要通过第三方软件源（如 RPMFusion 或 Negativo 17）来添加。如今，编解码器的问题已不那么严重。主流流媒体网站都使用开放格式（或者至少像 h.264 这样存在开源编解码器的格式），且 MP3 在 2017 年成为了无专利格式。随后不久，一个免费的 AAC 编解码器也发布了，因此你可以开箱即用地播放那些多年前刻录的 CD。或者，你也可以再次将音频无损地刻录到免费格式（如 FLAC）中。

### 让一切更简单

配置传统的 Fedora 第三方软件源需要花费一定精力。这比配置 Ubuntu 的 PPA 更复杂，也许这就是为什么以前很难为 Fedora 找到某些小众软件的原因。请记住，PPA 泛滥绝对是导致许多 Ubuntu 安装失败的原因，而第三方构建版本始终应谨慎对待。如今，一项名为 Copr 的新技术消除了构建非官方 Fedora 软件包的所有麻烦。Fedora 甚至提供了一个 Copr 构建服务，将为您提供专属的 Dnf/Yum 软件仓库。只需上传一个源 RPM 文件，选择你的构建目标，即可完成。更多详情请参阅 https://developer.fedoraproject.org/deployment/copr/。当然，越来越多的开发人员正在转向 Flatpak 和 Snap（尽管在 Fedora 构建的 Gnome 软件中，后者默认是禁用的）。因此，Fedora 相对较小但经过精心筛选的软件仓库，绝不是避开它的好理由。

Fedora 最近因宣布 Lenovo 将出货搭载 Fedora Workstation 的笔记本电脑而登上了新闻。Red Hat 高级桌面经理 Christian Schaller 在其博客中写道：“Red Hat 的工程团队也一直在努力，确保我们能够很好地支持这些机型，无论是通过修复内核驱动程序中的 bug，还是完善 Linux 指纹识别支持等功能。”

我们经常收到读者关于笔记本电脑上 Linux 兼容性的咨询，而在手头没有特定机型的情况下，很难给出关于兼容性的坚实建议。现在，既然 Dell 和 Lenovo 都提供笔记本电脑，我们就能自信地将那些想要开箱即用、稳固可靠 Linux 体验的用户引导至这些产品。

在过去六年的 Red Hat 职业生涯中，Christian 一直坚着要“排干沼泽”（drain the swamp，此处比喻彻底解决陈年旧疾）。他指的不是任性的政客。相反，他在针对桌面系统中那些长期被草率修补、实际上需要从头重写的问题。在这个语境下，他最早是向 Jim Gettys 的一次演讲致敬。你可以在此阅读他的想法：https://mail.gnome.org/archives/foundation-list/2002-May/msg00005.html。最新的 Fedora 包含了 Gnome 3.36（与 Ubuntu 20.04 相同），让我们印象深刻的是，这里几乎没有“沼泽”。你过去可能遇到过 PulseAudio 问题，或者可能没看出 Wayland 相比 X11 有何优势，但这项技术就是为了解决问题而发明的。并且它们确实解决了问题。你可能还会发现 Fedora 默认包含了 PipeWire，这是 Wim Tayman 推出的统一媒体处理方案。PipeWire（参见 LXF232 功能介绍）现在几乎可以处理 Jack（一种用于专业音频设置的复杂接口）能做的一切，下一步将让 PipeWire 承担 PulseAudio 的职责。

如果你曾在内存不足的机器上运行过 Linux，就会知道事情会迅速变得非常糟糕。除了基于机械硬盘的交换空间速度慢（在某些系统上甚至不可用）之外，你可能会发现自己正处于 OOM（内存不足）杀手的掌控之下。应用程序会被或多或少随意地杀死。更糟糕的是，当 OOM 无法反应足够快时，你的桌面会完全卡死。你无法移动鼠标指针，无法切换到虚拟终端，甚至可能无法通过 SSH 登录来手动杀掉进程。我们在运行过多的虚拟机时（就像你正在写一篇关于许多发行版的大型专题，结果因此耽误了交稿——是指那个 OOM 杀手吃了你的作业吗？——编者注）遇到过几次这种内存压力情况。反正……Fedora 32 包含了 EarlyOOM 守护进程，它应该能在为时已晚之前介入。

Fedora 走在了桌面的更远方向。当然，它也有服务器版，并且我们已经提到了其基于 Flatpak 和容器的 Silverblue 桌面尝试。但由于 Red Hat 在 2018 年收购了 CoreOS，现在它负责管理前身为 CoreOS Container Linux、现更名为 Fedora CoreOS 的发行版。这很可能将成为未来安全地管理基于容器的工作流（尤其是大规模服务器部署）的方向。从非常大到非常小，Fedora IoT 就是为未来几年将运行我们城市和生活的那些微型设备提供服务的方案。

## 清晰的胜者

还有一个我们没怎么介绍，但也许应该介绍的发行版，即 Intel 的 Clear Linux。它面向使用 Intel 硬件进行容器和云技术高级操作的专业人士。用其自己的话说，它“并非旨在成为通用 Linux 发行版”。尽管如此，它在 Phoronix 的压力基准测试比较中一直表现优异，且提供了一个桌面版，所以你也值得一看。Clear Linux 将应用程序包抽象为“Bundles”（软件包束）的概念，允许一次性安装一组相关程序。由于 Clear Linux 拥有自己的软件仓库，你可能找不到你最喜欢的应用程序，但这正是 Flatpak 旨在解决的问题之一，而安装 Flatpak 包束也很简单。

Clear Linux 软件包束使用了编译器优化，在拥有相应硬件的设备上启用了 AVX512 向量指令。例如，如果你正在运行 TensorFlow，你将受益于内核调优、Glibc 中的 AVX 例程、Python 中的 AVX 优化，以及最终堆栈顶层 Tensorflow Eigen 公司的优化。

Clear Linux 使用无状态设计概念，因此整个操作系统可以通过清除 /etc 和 /var 来有效地恢复到出厂设置。这在旧版发行版上无法工作，所以请不要尝试。但请尝试我们在本文中提到的所有发行版，并欢迎发邮件给我们，对没有提到你最喜欢的下一代发行版提出意见。

## Arch 呢？

Arch 用户可能会很震惊地发现，在这个关于新技术的页面上竟然没有提到他们首选的发行版，而且也许他们确实有道理。但 Gentoo 或 Linux from Scratch 的用户也可能这么说，因为他们也能获取最新版本的软件，并且可以用适合其 CPU 的优化选项进行编译。相反，我们关注的是发行版开箱即用的功能。就 Arch 而言，甚至是 Gentoo，好吧，你几乎连个“箱子”都得不到。尽管如此，Jonni（作者自称）使用的是 Arch，你也应该使用 Arch。

Manjaro 做到了不可思议的事，让 Arch Linux 变得易于使用，并继续成为目前最受欢迎的桌面发行版之一。Manjaro 并不（直接）使用与其祖先相同的软件仓库，因为 Arch 的更新速度很快，而 Manjaro 需要遵循发布节奏（以及不希望破坏自身软件包的愿望）。因此，你在 Manjaro 中找不到完全相同的“切缘”版本（bleeding-edge），但它的软件选择绝不会过时。那些可能混入稳定版 Arch 软件仓库的 bug，在到达 Manjaro 时会被修复。我们喜欢 Manjaro 正在给予 Xfce 桌面环境更多关注。轻量化并不意味着功能简陋。如果你想要一个精美的 KDE Plasma 桌面体验，也可以通过 Manjaro 的 Plasma 版获得，我们上个月偷偷将其放进了我们的虚拟 DVD 中。
