## 插入并轻触你的 YubiKey

忘掉 U2F 吧。现在所有的年轻人都在使用 Authn 进行身份验证了。也请忘掉那个 https 小锁图标，指纹图标才是当下的趋势。

配置程序正在等待输入，因此请按下密钥上的按钮。如果你还有其他 U2F 密钥，你可能也想要注册它们。毕竟，这样设置之后，如果你的密钥丢失或损坏，你将无法登录。对于每个额外的密钥，请将其插入，运行命令：`pam-u2fcfg -a >>~/.config/YubiKey/U2F_keys`，并轻轻敲击以将该密钥添加到我们的配置中。`u2f_keys` 文件可以移出你的主目录以提供额外的安全性，但如果你这样做，就需要在我们即将添加的 PAM 指令中添加 `authfile` 参数。

首先，我们将进行一次快速的安全测试，以防设备出现故障，通过测试 `sudo` 命令来进行。期望的结果是，该命令将同时要求正确的密码和连接的 YubiKey。运行：`$ sudo nano /etc/pam.d/sudo`，然后输入你的密码以查看相关的 PAM 指令。

我们将添加一行，然后保持文件打开状态（这就是为什么这是一个安全测试，所以请仔细注意这部分），同时我们在另一个终端窗口中测试它。这样，如果设备或 PAM 模块表现异常，我们就不需要使用 `sudo` 命令（由于异常正在发生，该命令对我们不再有用）来撤销这些更改。如果我们直到将登录管理器绑定到 YubiKey 并注销后才发现这个问题，情况就会非常棘手。

在 `@include common-auth` 行下方添加以下内容：`auth required pam_u2f.so` 现在保存，但不要按 Ctrl-O, Enter 关闭文件。打开另一个终端并运行：`$ sudo echo It works`

系统会像往常一样提示你输入密码，但如果你输入正确，在你轻触密钥之前什么也不会发生。如果没有成功，请从仍然打开的文件中移除出错的那一行并安全退出，泡杯茶，并考虑其他可用的选项。

如果成功了，你可能仍然想要移除那一行。一旦我们使通过密钥登录我们的机器成为必需，保护 Sudo 的作用就变小了（除非你强制执行严格的登录后移除和隐藏密钥的仪式）。

使用以下命令编辑 GDM（或者你在非 Gnome 桌面上使用的任何显示管理器，语法是相同的）PAM 文件：`$ sudo nano /etc/pam.d/gdm-password`

再次在 `@include common-auth` 行下方添加 `pam_u2f.so` 模块，保存并关闭文件。

注销桌面并祈祷。显示管理器应该像往常一样启动，像往常一样询问你的密码，然后……没有任何反应。没有提示，但此时你应该轻触设备。如果你没有在 10 秒内这样做，你将收到一个不必要的、关于密码错误的错误提示。这种略显突兀的用户体验可能提供了一些通过混淆带来的安全性。

即使设备始终连接到机器，一个邪恶的实习生（你真的应该解雇他们–编者注）或其他访问你住所的人，尽管可能知道你的密码，但可能不知道还有另一部分拼图。如果你更有纪律，每次注销时移除设备并将其放在安全的地方，你就能赢得一些安全评分。

U2F 的无密码演进版本 FIDO2 始于 2018 年，带来了新的身份验证机制 WebAuthn，你应该在 https://webauthn.guide 上阅读有关它的信息。WebAuthn API 提供对指纹或面部识别传感器的支持。不过，目前你最好的选择是使用 TOTP。

许多网站现在允许通过由硬件令牌或移动应用程序（如 Google Authenticator）提供的基于时间的一次性密码（TOTP）进行身份验证。一旦各方协商好共享秘密（即当前时间），设备就会每 30 秒生成一个 6–8 位代码。这可以在服务器端进行验证，只要时钟保持同步，用户就可以登录。对于依赖时钟不令人满意的情况，有 HOTP，它在每次登录时增加计数器。

Yubico Authenticator 在谷歌支持的所有地方都有效，并且可以从 https://developers.yubico.com/yubiath-desktop 获取便携的 AppImage 版本。也有一个移动应用，并且值得考虑使用非手机（或嵌入其中）的硬件令牌的好处。手机有一个讨厌的习惯，就是容易丢失、损坏或闹脾气。

## 保护你的网络

使用 IPFire 为你的家庭防火墙保驾护航，这是一个专门用于保持你的网络端口安全的发行版。

**W**e 在上一期中介绍了防火墙，如果你想了解 Linux 上数据包过滤的细节，请查阅那期文章。现在我们再次介绍它们，但这次我们将采用更实用的方法，使用 IPFire，一个专门用于防火墙或其他网络设备的发行版。运行防火墙不需要任何特别特殊的硬件，旧机器或树莓派就足够了（我们包含了 32 位 x86 机器的 ISO 以及 64 位 PC 和 ARMv5 及以后设备的 USB/SD 卡镜像），但请注意，至少需要两个网络适配器。话虽如此，你也可以在虚拟机中运行 IPFire（你可以随意添加许多虚拟以太网适配器）。在合理的硬件和小型网络上，其性能将非常好，但如果宿主机被入侵，那么虚拟防火墙也会被入侵，因此以这种方式做事我们会失去一些安全评分。

如果你想为 IPFire 使用 VM，你可以使用光盘 *IPFire/* 目录中的 32 位 ISO。如果你真的愿意，可以从网站获取 64 位 ISO 镜像。对于小型安装，这不太可能有任何区别 – 内存要求很低。对于更大或更复杂的安装，你可能不想运行虚拟 IPFire 设备，不过得益于 virtio 网络和其他虚拟巫术（参见我们上一期的 *Virtualisation* 功能：https://linuxformat.com/archives/），这在简单设置下运行良好。VPN 流量的加密/解密需要相当多的 CPU 性能，因此如果你计划允许对 VPN 进行大量数据访问，请注意这一点。你可以在 IPFire 网站上找到如何在 AWS 和 Hetzner 云设置 IPFire 云实例的说明。

- 一旦我们将我们的 Ubuntu VM 设置为使用静态 IP，我们就能够连接到我们的 IPFire VM。

### 通过 IPFire 路由

你可以将整个家庭网络通过 IPFire 路由（通过将家庭路由器设置为默认网关并调整设置），或者你可以通过仅将选定的机器通过 IPFire 路由来避免打扰家庭网络的其他用户。安装（无论是真实还是虚拟）都很简单，但请注意整个目标驱动器将被擦除 – 安装程序不提供从单个驱动器双启动的方式。安装系统后，移除安装介质并重启以执行初始系统设置。一切都相当标准 – 本地化、用户等等 – 重要部分是最终的网络设置。

你将至少需要两个网络适配器，这是无法回避的。如果你运行的是 VM，你可以点击几下添加第二个适配器并重启以继续设置。如果你使用的是具有有线和无线网络连接的 Raspberry Pi 3B 或其他设备，那将工作得很好（前提是你使用 hostapd 设置接入点）。对于双适配器设置，我们必须将一个设备分配给 Green 网络，另一个设备分配给 Red 网络。你可以使用多达四个适配器，如果你这样做，事情会变得更加丰富多彩。如果你需要设置更多适配器，请使用第一个选项，并使用第二个选项将颜色分配给网络硬件。通常 Green 网络将是你的

### IP 附加组件

IPFire 拥有运行高级防火墙解决方案所需的一切甚至更多。但其功能可以扩展远超开箱即用的范围。首先，它拥有自己的发行版和自己的软件包管理器（Pakfire），可以直接使用或在幕后使用来安装额外功能。

我们稍后会简要谈谈 VPN 的优缺点，但如果你认为你需要一个，你可以通过 OpenVPN 只需几点击进行设置。提供两种配置 – 一个是听起来像末日的 Roadwarrior，另一个是描述性更强的 Net-to-Net。前者也可以被称为 client-to-net，它是一个远离安全网络连接范围的 Roadwarrior，用于将你的通信加密回你的可信服务器。

Tor，通常在与 VPN 相同的句子中提到，也可以在 IPFire 上轻松设置。你可以设置你的实例以访问 *onion* 节点，并仅让你的流量（或其特定部分）通过 Tor。或者，如果你有足够的剩余带宽，你可以设置一个中继节点，造福整个 Tor 社区。

更传统地，你还可以为你的实例添加一个无线网络（通常指定为 **BLUE** 接口）。我们提到过在 Pi 上可以做到这一点（它只有两个网络接口），但将其作为第三个接口可以避免你自己设置 Hostapd。
