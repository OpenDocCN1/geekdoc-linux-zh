要激活 SSH 服务器，请运行：

```bash
$ sudo systemctl start ssh
```

在基于 Red Hat 的发行版中，这将使用 `sshd` 而不是 `ssh`。然后，依次在每台机器上运行以下命令生成 SSH 密钥：

```bash
$ ssh-keygen
```

并按三次回车键。完成后，你可以将密钥复制到其他计算机中：

```bash
$ ssh-copy-id destination_machine
```

其中 `destination_machine` 是目标机器的主机名或 IP 地址。当提示时，输入目标机器的密码以允许复制发生。如果你有两台计算机，你需要执行两次此操作。

## 并行化！

到目前为止，这仅使用了你 CPU 的单核。既然在 2019 年你很难找到只有一核的计算机（约翰的 *Eee PC——编者注*），一个好的下一步是使用你机器上的所有核心运行，以获得你能得到的最高数值。要了解你的机器有多少核心，你可以查看规格，或者查看 `/proc/cpuinfo`（如果你的 CPU 有超线程，你需要除以二，因为 `Open MPI` 不认为那些是真正的核心）。将你得到的数字替换上面命令中的 1，以在所有核心上运行。例如，对于六核工作站，运行：

```bash
$ ./sombrero.sh -n 6 -s small
```

值得注意的是，由于 Sombrero 基于特定问题，它只能测试只能被 2 和 3 整除的核心数。例如，6 ($2 \times 3$)、24 ($2 \times 2 \times 2 \times 3$) 或 32 ($2 \times 2 \times 2 \times 2 \times 2$) 将有效，但 10 ($2 \times 5$) 或 14 ($2 \times 7$) 将无效，并会给出错误。

现在，你已经成功让整台机器停滞下来，那么如何对你的整个网络做同样的事呢？如果你有一台以上通过网络连接起来的 Linux 机器，你可以尝试在你有访问权限的每一台机器上运行 Sombrero，形成一个临时的 Beowulf 集群。首先，对于你希望参与的每台计算机，请按照迄今的说明进行操作。这将检查 Sombrero 能否在每台机器上单独正常工作，并设置可执行文件，以便 `Open MPI` 能够在每台机器上找到它。接下来，你需要配置 SSH，以便你能从一台机器无密码登录到另一台机器。

## » 什么是超级计算机？

现代超级计算机与家庭或办公网络并无太大不同。一堆 Linux 服务器（或节点），通常使用 Intel 处理器并安装在机架中，都可以独立运行，但位于公共网络上。在最快速的超级计算机中，每台服务器都安装了一个或多个 GPU 来执行繁重的计算任务。Red Hat Linux 是最常见的发行版，而基于 Debian 的发行版则较为罕见。

虽然典型的以太网连接可能用于管理节点并登录它们，但它们还通过 Infiniband 或 Omnipath 等超高速互连连接在一起。节点需要协作处理大型问题，并且不希望空闲等待数据到达，因此蜿蜒的网络布局是设计超级计算机的关键部分。虽然大多数机器使用相对熟悉的交换机层次结构，但一些针对特定应用程序的机器会围绕该应用设计网络，形成如蜻蜓和六维环面等奇特形状！

Intel CPU 将是高端服务器品种，因为这为每个节点提供了更多的核心：当前一代芯片在单个芯片上最多提供 24 个核心，而最高端的 Core i9 只有八个。GPU 将是专注于计算的 NVIDIA Tesla 卡——通常完全没有显示输出。

如果你没有多台机器可以折腾，你可以对任何可调整参数制作比较图。一个特别有用的图是比较不同的编译器选项，以查看哪个最快。

这是“异构计算”中经常出现的问题。对于许多问题，可以使用负载均衡技术来根据机器的能力调整每台机器所做的工作量；然而，大多数基准测试都不屑于这样做，既因为底层问题本身不适合这种方式，也因为将被测试的系统通常具有非常统一的组件。

### 关于 SSH 密钥分布的说明

在每台机器上做一次，如果你有三台机器，每台需要做两次，以此类推。这是因为每台机器上的 MPI 需要能够与所有其他机器通信，而一旦程序开始运行，你就无法再输入密码了。

现在，你需要告诉 Open MPI 你想使用哪些机器。为此，创建一个名为 *hostfile.txt* 的文本文件，并在其中写下你想使用的每台计算机的主机名。根据你希望在该机器上运行的进程数量重复名称；例如，如果你希望名为 *pgmy* 的双核笔记本电脑参与名为 *pyxis* 的六节点工作站的计算，*hostfile.txt* 将如下所示：

```text
pyxis
pyxis
pyxis
pyxis
pyxis
pyxis
pgmy
```

设置全部完成后，你可以使用以下命令测试你的新集群：

```bash
$ ./sombrero.sh -H hostfile.txt -s small
```

在理想情况下，这将比一台计算机的得分更快。然而，这并不保证——这取决于你的网络有多快以及其他计算机有多快。由于基准测试的各个步骤必须在整个集群中同步进行，过程将由最慢的机器决定。因此，从混合中移除特别慢的计算机可能会使事物加速。

## 追求速度

到目前为止，你一直在使用默认编译器设置运行 *Sombrero*，即 `-std=c++11`。现在，这些设置用于测试是没问题的，但无法获得你系统的最高可能性能数字。要做到这一点，你需要给编译器更多关于你想要它做什么以获取最佳性能的指示。你通过编辑 *Makefile* 文件来完成，该文件定义了供编译器读取的变量。在你的首选文本编辑器中打开此文件，你将看到：

```makefile
#Compiler
CC = mpicc
CFLAGS = -std=c++11
LDFLAGS =
```

由于我们之前安装了 GCC，你可能会期望看到 `CC= gcc`；相反，使用的是 `mpicc`。`mpicc` 是 Open MPI 提供的 GCC 包装器，并确保所有正确的通信库都被链接。

首先，`-g` 标志启用调试器符号。这在调试软件问题时很有用，但在某些情况下可能会使性能略微下降。现在移除此标志，并再次运行 `make`。现在重新运行 *Sombrero*，无论是在你的本地机器上还是在集群上，都应该揭示出与之前运行相比的轻微速度提升。下一步是告诉编译器你将在哪种处理器上运行。

默认情况下，GCC 只允许使用通用 x86-64 CPU 上的处理器特性——这将其限制在 2003 年发布的处理器特性上。自那以来，CPU 已经走了很长的路，因此通过添加标志 `-march=native` 来启用 GCC 使用这些新特性。如果你想在一台与编译所在不同的机器上运行，你可以向架构参数传递除 `native` 以外的其他选项；GCC 手册中有完整的说明。现在用 `make` 重新编译并重新测试，你应该会看到更显著的性能提升。

GCC 有数百个旋钮可供你调整，以尝试从你的机器中提取最佳可能性能。你可以在 `https://gcc.gnu.org/onlinedocs/gcc/Options.html` 浏览完整列表。这可能会被视为作弊，但这是基准测试和在大型机器上运行软件的重要组成部分。编译器是为广泛的软件和硬件设计的，因此有时需要帮助才能知道如何最好地让你的软件运行。在典型的桌面上，性能差异小到足以使从头编译每个软件并测试每个选项所花的时间超过它节省的时间。但是，当你工作的软件每周或每月在数百或数千台相同机器上运行时，你希望确保没有浪费可用功率的百分之五。

## » 大规模测试

由于超级计算机严重依赖其高速网络让计算分布在许多节点上，测试其工作效果非常重要。这有两种方法：弱扩展测试，其中问题大小随使用的节点数增长；以及强扩展测试，其中相同的问题被分成越来越小的块。*Sombrero* 支持这两种类型的测试，默认使用强扩展，因为那更难。如果你有足够多的计算机可用，你可以运行强扩展测试。首先，使用 2 和 3 的倍数设置一组节点列表，称为 `nodelist1.txt`、`nodelist2.txt` 等。

```bash
for N in 1 2 3 4 6 9; do
    ./sombrero.sh -H ${N}x$(NODES).txt -s small | awk \
        '{BEGIN {printf("%5d", "NODES")}; 
        /^\[RESULT\]/ {printf("%s %s", "$Glops", "seconds");}
        END {printf("\n");}' \
        >> strong.dat
done
```

然后，绘制结果：

```gnuplot
gnuplot> set style data linepoints
gnuplot> plot for [i:1:6] 'strong.dat' \ 
    using 1:column(+i) title 'SOMBRERO'
```

理想情况是一条直的对角线；在现实中，使用的节点越多，线条越偏离直线，因为越来越多的通信必须发生。
