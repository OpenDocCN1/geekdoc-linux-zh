
控制器管理器（Controller Manager）负责监控集群状态，并通过 API 服务器（API Server）在必要时尝试启动或停止 Pod，以使集群达到期望状态。它还管理一些内部连接和安全特性。

每个节点都运行一个 Kubelet 进程，该进程与 API 服务器进行通信并管理容器（通常使用 Docker），以及 Kube-Proxy，后者负责处理集群内的网络代理和负载均衡。

etcd 分布式数据库系统的名称源自 Linux 系统中的 /etc 文件夹，该文件夹用于存储系统配置信息，再加上后缀“d”，后者通常用来表示守护进程。etcd 的目标是以分布式、一致且容错的方式存储键值数据。

API 服务器将其所有状态数据保存在 etcd 中，并且可以并发运行多个实例。调度器（scheduler）和控制器管理器只能有一个活动实例，但使用租约（lease）系统来确定哪个运行实例是主节点。这意味着 Kubernetes 可以作为一个高可用系统运行，没有单点故障。

# 将所有部分结合起来

那么我们在实践中如何使用这些组件呢？下面是一个使用 Kubernetes 搭建 WordPress 网站的示例。如果你真想这样做，你可能会使用一种称为 Helm Chart 的预定义配方。许多常见应用程序都有可用的 Helm Chart，但在这里，我们将查看在 Kubernetes 上启动并运行 WordPress 网站所需的一些步骤。

```
kubectl create secret generic mysql-pass --from-literal-password=YOUR_PASSWORD
```

kubectl 将与 API 服务器进行通信，API 服务器将验证该命令，然后存储密码到 etcd。

我们的服务在 YAML 文件中定义，现在我们需要为 MySQL 数据库提供一些持久存储。

```
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: mysql-pv-claim
  labels:
    app: wordpress
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 2Gi
```

该规格说明应该大多不言自明。name 和 labels 字段用于从 Kubernetes 的其他部分引用此存储，在本例中是我们的 WordPress 容器。

一旦定义了存储，我们就可以定义一个指向预定义存储的 MySQL 实例。随后是定义数据库本身。我们为那个数据库指定一个名称和标签，以便在 Kubernetes 中轻松引用。

现在我们需要另一个容器来运行 WordPress。容器部署规格的一部分是：

```
kind: Deployment
metadata:
  name: wordpress
```

```
name: wordpress
labels:
  app: wordpress
spec:
  strategy:
    type: Recreate
```

策略类型“Recreate”意味着，如果组成应用程序的任何代码发生变化，那么运行实例将被删除并重新创建。其他选项包括能够循环引入新实例并移除现有实例，一个接一个地移除，从而在部署更新期间使服务继续运行。最后，我们为 WordPress 本身声明一个服务，包括 PHP 代码和 Apache。声明此服务的 YAML 文件的一部分是：

```
metadata:
  name: wordpress
  labels:
    app: wordpress
spec:
  ports:
    - port: 80
  selector:
    app: wordpress
    tier: frontend
  type: LoadBalancer
```

注意最后一行，将服务类型定义为 LoadBalancer。这指示 Kubernetes 使该服务在 Kubernetes 外部可用。如果没有该行，这仅仅是一个内部的“仅限 Kubernetes”服务。

就这么简单。Kubernetes 现在将这些 YAML 文件用作所需内容的声明，并设置所需的 Pod、连接、存储等，以使集群达到“期望”状态。

这必然只是对 Kubernetes 的高层概述，省略了系统的许多细节和功能。我们略过了自动扩展（包括 Pod 和组成集群的节点）、Cron Job（按计划启动容器）、Ingress（HTTP 负载均衡、重写和 SSL 卸载）、RBAC（基于角色的访问控制）、网络策略（防火墙）等等。Kubernetes 极其灵活且极其强大：对于任何新的 IT 基础设施，它必须是一个有力的竞争者。

## 防止恶意软件

**乔尼·比德韦尔（Jonni Bidwell）** 不确定恶意软件是否比他更能破坏他的电脑，但他真的不想去证实这一点……

- Linux 不是恶意软件的滋生地！“其用户基数很小，意味着没人有兴趣攻击它。从网络随机下载并运行内容的文化并不存在。它更安全。生态系统的碎片性对它有利的地方在于，使得针对特定发行版变得困难，”他们大声说道。

遗憾的是，这些都不是事实。Linux 服务器运行着互联网的大部分，还有数十亿台 Android 手机，以及基于 Arm 和 MIPS 的路由器和 IoT 设备。而且人们总是运行诸如 `curl...` `| sudo bash` 这样的命令——这是许多流行程序推荐的安装方法。因此，Linux 自满的时候已经过去，我们需要长密码、勤勉的 ossec 以及受迷惑的技术编辑的偏执抱怨的时刻已经到来。不过别担心，我们准备了对影响你的 Linux 主机的威胁及其缓解措施的综合调查。

> **恶意软件的范围**
>
> “通过你的网络摄像头或麦克风来监视你的软件怎么样？”

任何使用过 Windows XP 的人都知道广告软件（adware）和缠人软件（nagware）有多烦人。但更令人担忧的是收集电子邮件地址、密码或加密你文件的恶意软件。如果那没吓到你，那么通过你的网络摄像头和麦克风来监视你的软件怎么样？还有窃取你所有辛苦赚来的加密货币（或者如果你还相信那回事的话，是真实金钱）的恶意软件怎么样？这些威胁都非常真实，但我们会看到，一些简单的步骤（使用密码管理器、保持软件最新、不打开可疑文件、小心你访问的网站）将在很大程度上保护你。

我们将查看恶意软件如何得逞、它是如何被发现的以及攻击者的动机是什么。网络是一个危险的地方，我们越来越多地看到，无论运行在什么平台上，Web 浏览器都可能被攻破。因此，我们将深入探讨如何保护你的浏览器。我们还将深入 Linux 反病毒（小而世界）领域。

# Linux 上的恶意软件

在桌面 Linux 上运行确实使你是少数派，但恶意软件在针对你的操作系统时并不歧视。

“Linux 不会得病毒”这一阶段性的说法曾经很常见。现在依然如此，由该操作系统的粉丝甚至是发行版制造商（见*右文* [https://manjaro.org](https://manjaro.org)）。不幸的是，这种说法从来都不完全真实，而现在它比以往任何时候都更具误导性。当 Linux 还只是林纳斯眼中的一点星光时，UNIX 系统上就已经存在蠕虫、rootkit 和各种其他恶意程序。它们使用的许多技术在 Linux 平台成熟后得到了适配。

就桌面 Linux 而言，情况还算清晰：报告的攻击少得多，已知恶意软件菌株的列表远短于 Windows 机器。考虑到桌面 Linux 的市场份额（大约在百分之二左右），这是合理的——攻击者更倾向于攻击大众正在使用的东西。2006 年“Mac 不会得病毒”系列电视广告声称“Mac 不会得病毒”。自那以后，其桌面市场份额增长到大约百分之十，威胁数量也随之成比例增加。尽管苹果公司对软件安装采取了围墙花园式的做法。

如今，关于反病毒软件在 Windows 上是否有帮助的观点分歧，并不是因为它没有做它声称做的事情，而是因为有时（由于编程不佳）它会暴露系统给新的、潜在更危险的攻击。安全大师 Tavis Ormandy，Google Project Zero 安全团队的一部分，对此威胁特别直言不讳。以最高权限级别运行的程序，正如反病毒扫描系统文件或特权内存所要求的，需要无懈可击。如果这些有漏洞，那么系统也有漏洞，可能比没有运行此类反病毒时更严重。

通常你不需要依赖一个有漏洞的程序来利用系统：一个有漏洞的用户就足够了。编写一个程序来加密所有用户文件，记录/注入击键（至少在 X 中——见 [https://github.com/CoolerVoid/Rootstealer](https://github.com/CoolerVoid/Rootstealer)），启动 FTP 服务器（使机器文件对世界开放），甚至如果该用户具有 root 权限并且可以被骗输入密码时擦除所有本地存储——所有这些都很简单。技巧在于找到一个足够天真的用户来运行它。同样，对潜在灾难的了解，精心制作的钓鱼邮件可以欺骗他们访问一个可以从其中吞噬密码的假网站，打开一个有毒的 PDF，甚至只是运行一个恶意可执行文件——只要它没被邮件提供商或目标邮件客户端阻止。人类有一个坏习惯，当事情似乎来自他们认识的人时，他们会相信，因此很容易看到这些事情如何级联并变成大规模爆发。

## 我们 ♥ 统计

*Thycotic Black Hat 2018 黑客调查报告* [1] 指出，近 60% 的黑客认为社会工程学是攻破网络最快的方式。使用恶意软件（6%）和应用漏洞（20%）的可能性要小得多。得益于松散的安全实践和/或黑客的智慧，相当规模的密码转储（password dumps）公开可用。你可以通过访问 *Hunt* [*Have I Been Pwned*](https://havelbeenpwned.com) 来检查你的任何电子邮件地址是否与这些转储相关联。几年前加入的旧论坛的密码可能对黑客没什么用，但如果那个论坛账户可以与你的身份相关联（通过电子邮件地址、用户名或其他），并且你在那个论坛之外重用了那个密码或其简单变体，情况就不同了。调查发现，密码重用是黑客利用最多的行为（50%），公共 Wi-Fi 使用和中毒 USB 驱动器并列第二，各占约 20%。

当然，黑客使用十六进制编辑器、反汇编器和调试器做坏事的典型形象并不完全是虚构的，但如果只要礼貌地询问某人的密码就能解决问题，为什么要费那个劲呢。当然，这些不是确凿的数字，调查报告说“300+ 参与者”。
