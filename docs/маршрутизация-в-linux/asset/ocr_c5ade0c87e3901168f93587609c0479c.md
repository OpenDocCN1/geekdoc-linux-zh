Another complex substatement within ospf is the backbone statement. You must set up your OSPF backbone if you have more than one area because it's the backbone that carries inter-area communications. Following along with the earlier format examples, let's add on to it:

```
ospf on {
    defaults {
        option1;
        ...
        optionN;
    };
    statement1;
    ...
    statementN;
    backbone area value {
        option1;
        ...
        optionN;
    };
};
```

The value as mentioned in Table 5.14 is the area number you assigned to the area serving as your AS backbone. Within the backbone area statement there is a small collection of options you can set to define how this backbone interacts with the rest of the AS. These options are outlined in Table 5.15.
