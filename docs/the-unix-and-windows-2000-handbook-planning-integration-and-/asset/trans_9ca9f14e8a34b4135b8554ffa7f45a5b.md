

对操作系统来说，巨大的磁盘空间意味着不再需要细分磁盘来降低操作系统某个子系统耗尽所有可用资源的风险。

更大的磁盘还让系统管理工作变得更加轻松。使用较小的磁盘时，系统二进制文件可用的空间非常有限。虽然操作系统的初次安装不成问题，但在后续需要升级或修补系统时，问题就会出现。随着时间推移，操作系统的体积和功能都在不断增长。总体而言这是好事，但未来操作系统的大小无法预测。因此，适合某个操作系统版本的分区方案，通常无法适用于后续修订版本，导致管理员不得不花费大量精力重新分区并重装操作系统——而如果当初磁盘足够大，本可以轻松完成一次简单升级。

> 补丁（patch）是对代码的临时补充，通常用作针对 bug 或故障的快速但临时的解决方案。

表 2.4 展示了一个简化的磁盘分区方案，如果你计划仅使用磁盘来支持操作系统，则推荐采用该方案。本质上，选择所需的交换空间大小，然后将剩余的磁盘空间分配给根分区。虽然磁盘上的其余分区仍然存在，但它们保持未使用状态，或可视为大小为零。

**表 2.4：仅根分区方案**

| 分区 | 名称 | 说明 |
| --- | --- | --- |
| 0 | root | 操作系统使用除分区 1 中交换空间之外的整个磁盘。 |
| 1 | swap | 虚拟内存。 |
| 2 | overlap | 请不要修改此分区！ |
| 3 | unused |  |
| 4 | unused |  |
| 5 | unused |  |
| 6 | unused |  |

表 2.4 中的分区模型非常适合那些以最大化系统运行空间为首要目标的系统。文件服务器、打印服务器和通用服务器都符合这一模型。通过为这些功能提供最大的磁盘空间，可以减少磁盘资源问题的可能性，并提高系统的可靠性、稳定性和可维护性。虽然这是一个非常稳定的解决方案，但人们可能会怀疑“一刀切”的方法是否总是最好的，尤其是在操作系统并非充当服务器的情况下。

表 2.5 展示了一个混合分区模型，它在整合磁盘空间以简化系统管理的同时，也为用户和应用程序文件提供了文件空间。如你所见，添加了 `/home` 分区，以便为用户文件和应用程序提供空间。日志区域被设计用于高性能文件系统。该分区模型的优势在于：使用大磁盘时，你可以为操作系统功能、补丁和未来升级提供充足空间，同时为用户和应用程序提供足够的磁盘空间。该模型还将操作系统与应用程序和用户空间隔离开来，从而保证系统用户无法通过正常使用或误操作填满整个磁盘，导致系统问题。在只有一个磁盘但系统需要承担多种用途的场景下，这种混合分区标准将非常适用。

**表 2.5：混合分区模型**

| 分区 | 名称 | 说明 |
| --- | --- | --- |
| 0 | root | 操作系统。 |
| 1 | swap | 用于增加交换空间。 |
| 2 | overlap | 请不要修改此分区！ |
| 3 | home | 用户和应用程序文件。 |
| 4 | unused |  |
| 5 | unused |  |
| 6 | logging | 高性能文件系统的日志记录。 |

本部分介绍了三种不同的分区模型，你可以从中选择来构建自己的分区标准。在这些模型中，我们试图为构建分区标准提供一个基础。重要的经验是制定一个适合你自己的分区标准，并且可以在整个环境中复制使用。这可能需要一些时间和经验的反复调整，但最终会带来回报。
