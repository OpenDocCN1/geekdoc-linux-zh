## 保护文件

除了基础操作系统中内置的标准文件权限外，还有两种方法可以保护您的文件。这些方法是通过使用访问控制列表（ACL）和使用文件加密来实现的。

良好的主机控制始于控制哪些文件可以被特定用户访问，如下所示：

- 为了保护服务器本身。没有人希望一个没有受过教育的用户能够在UNIX下执行命令 `rm -rf /` 或删除Windows 2000下的 `winnt` 目录。
- 为了保护服务器上被处理的数据的真实性、完整性和机密性。

这些级别的保护是通过管理哪些用户可以访问哪些文件或目录，以及管理对这些资源的访问权限来实现的。在UNIX下，这是通过管理三类用户的三级权限（读、写、执行）来实现的（或最初是这样实现的，稍后将展示）：

- 文件或目录的所有者（创建它的用户）。只有所有者或root才能分配或修改文件或目录的权限。
- 一个组（由系统管理员定义的一组用户）。组要么通过编辑文件 `/etc/group` 在主机本地定义，要么通过NIS定义。
- 其他所有用户（系统上除文件所有者、root以及对该文件具有访问权限的组成员之外的所有其他用户）。

这种技术表现出明显的灵活性不足。假设我们有一个文件由 `user1` 拥有，系统管理员需要将读和写访问权限（但没有执行权限）分配给 `user2`。这可以通过标准UNIX权限来实现：首先创建一个组，例如命名为guser2，该组只有user2一个成员，然后将文件关联的组更改为guser2，并授予该文件的组读写访问权限。

现在，如果我们想将读和执行权限（但没有写权限）分配给另一个用户，例如user3，该怎么办？文件的默认访问权限设置为只读。正是为了解决这样的问题，1997年开始制定POSIX IEEE 1003标准。这项工作应该是关于文件上的访问控制列表（ACL）的标准。ACL有时被称为扩展ACL，以区别于原始的UNIX文件访问控制系统。然而，这项工作已经停止，标准草案已被撤回。Sun继续推进这项工作并开发了自己的ACL机制。该工作的摘要可以在 http://www.sunworld.com/swol-06-1998/swol-06-insidesolaris.html 找到。

ACL机制在Solaris 2.7、2.6和2.5.1中实现。ACL只能在UFS文件系统类型下使用。例如，从/etc复制到/tmp的文件将丢失其ACL，因为/tmp通常挂载为tmpfs文件系统。

让我们使用我们最初的例子来演示如何在Solaris下使用ACL：

```
>ls -l junk.txt
-rw-r--r-- 1 user1 gusers 1090 Nov 9 18:10
junk.txt
```

在初始状态下，user1对文件junk.txt拥有所有权利，组gusers只有只读访问权限。默认给所有人的访问权限是只读。我们现在需要给user2读和写访问权限，给user3读和执行访问权限，这个操作通过使用命令setfacl来执行：

```
>setfacl -m user:user2:rw- junk.txt
>setfacl -m user:user3:r-x junk.txt
```

命令setfacl，使用开关-m，在文件junk.txt上添加一个ACL条目。块user:user2:rw-表示新条目与一个用户user2相关，并且读和写访问权限也被授予user2。检查我们所做的ACL设置的方法是使用命令getfacl对文件junk.txt：

```
>getfacl junk.txt
# file: junk.txt
# owner: user1
# group: gusers
user::rwx
user:user2:rw-      #effective:r-
user:user3:r-x      #effective:r-
```
