It is very probable that one of your NIS servers may be performing multiple functions on the network. A function like email requires access to the passwd file for successful delivery to all accounts. It is much easier and more efficient to have all of the NIS servers be clients. Actions outlined in Table 7.4 will start the ypbind daemon at boot.

For those who are command-line challenged, AIX and HPUX offer a GUI alternative to the above procedures. AIX allows you to create an NIS master with the smit mk master command, which is a graphical front-end to set up the NIS master server. HPUX allows you to create a master server in SAM under the “Networking and Communications” area. All of the above steps can be accomplished in these GUI tools.

# NIS SLAVE SERVER CREATION

The first step is to ensure that the NIS master server is up and running NIS for this domain.

+   1. Set the domain name on the host to be a slave server as outlined in the “Startup Scripts” section.
