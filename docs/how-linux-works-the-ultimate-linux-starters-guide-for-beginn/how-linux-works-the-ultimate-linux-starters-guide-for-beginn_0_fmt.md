## 引言

在深入 GNU/Linux 系统世界之前，了解它们是如何产生的以及你在接触和使用它们时遇到的一些术语是非常重要的。我将从三大巨头：UNIX、Linux 和 GNU 的简史开始说。

UNIX 是一种专有的、基于命令行的操作系统，最初由 Dennis Ritchie 和 Ken Thompson（等人）于 20 世纪 60 年代后期和 70 年代初在 AT&T 的贝尔实验室开发。UNIX 几乎完全用 `C` 语言编写（同样由 Ritchie 发明），最初的设计目的是为程序员和研究人员提供一个可移植且方便的操作系统。由于涉及 AT&T、贝尔实验室和联邦政府的长久而复杂的法律历史，UNIX 和类 UNIX 操作系统日益流行，汤普森具有影响力的模块化、极简软件设计哲学也随之流行。

我们每天使用的现代操作系统（如 Windows 和 macOS）是由许多不同（且非常有技术性）组件组成的，包括帮助软件与硬件通信的内核，以及你在屏幕上看到的图形用户界面（GUI）元素。尝试思考一下，移动鼠标如何转化为光标在屏幕上的移动，或者文件是如何存储在你的固态硬盘上的。

当你理解执行这些任务的所有部分时，看似简单的任务其实是很复杂的。Windows 和 macOS 设计使得用户不需要理解背后的原理。换句话说，GUI 是功能性的。

现在让我们转向 Linux 发行版。发行版（distro 的缩写）最好被认为是组成 Linux 的组件包。考虑像 Fedora、ElementOS、Manjaro、Ubuntu 等发行版。

一个典型的 Linux 发行版包含 Linux 内核；GNU 工具和库；用于显示窗口的窗口系统；以及桌面环境。一些常见的桌面环境有 GNU 的 GNOME、KDE 的 Plasma、MATE 和 XFCE。不同口味的发行版使用不同的环境——更华丽或更精简，更或更像 Windows——但操作系统的核心组件是相同的。

软件公司或组织通常会将所有部分打包并创建一个 `ISO` 文件（技术上讲，是安装光盘或 DVD 的压缩镜像），用户可以将其下载并安装在计算机上。

平台系统同样复杂，但我将对它们的核心组件提供一个类似的简化版概述。macOS 的核心是一个名为 Darwin 的类 UNIX 操作系统，它构建在一个名为 `XNU`（X 不是 UNIX）的类 UNIX 混合内核之上。Aqua 和 Finder GUI 元素只是组成整个 macOS 系统的某些额外组件。Chrome OS 则基于 Chromium OS 和 Linux 内核。

Windows 10 是 Windows NT 家族的一员，使用混合内核和 Windows Shell。顺带提一下，微软继续为其 Windows 的 Linux 子系统（WSL）开发功能，该系统已为 Windows 10 添加了完整的 Linux 内核。

我必须指出，运行 GNU/Linux 系统与运行 macOS 或 Windows 不同，特别是对于普通用户而言。简单的任务并不总是能如你预期的那样运行。例如，即使你使用发行版的内置应用商店，安装程序也不总是一帆风顺的，因为那里可能没有各种程序的最新版本。对于此类任务，你至少需要学习终端或命令行界面的基础知识。

扫描仪、多功能打印机和其他外围设备也面临挑战，因为驱动程序的安装并不容易排查故障。请准备好花费大量时间重新学习如何以新方式完成基础任务，并在散布于网络各处的论坛搜索解决方案。如果你很容易对技术感到沮丧，那么 GNU/Linux 系统可能不是你的最佳选择。

根结底，开源操作系统是否是你的正确选择，取决于你如何使用电脑。如果你是一名程序员，你可能更倾向于稳定、精简的设计。如果你家里有一台闲置或旧 PC，一个轻量级的 GNU/Linux 发行版可能会让它焕发新生。

你可能考虑使用 GNU/Linux 发行版的主要原因之一是，许多版本在技术上是免费的，尽管你应该为你维护你所选发行版的社区尽一份绵之力。虽然在购买 PC 时通常不需要考虑操作系统的价格，但如果你自己组装台式机，这可能是一个考虑因素。你可以购买 Windows 10 家庭版许可，但这至少要花费 139 美元。除非你为 Apple 硬件付费，否则你无法获得 macOS。

对用户来说，另一个诱人胜的因素是开源 GNU/Linux 系统的可定制性和灵活性。正如前所述，发行版支持不同的桌面环境，每种环境都可以提供一种新颖的界面。另一个吸引点是长期支持。许多发行版维护者多年如一，如果你不想更新，他们就不会要求你更新。这有助于维护并确保减少崩溃。从 Windows 迁移到 Linux 的动力已经足够。

你可能也会喜欢指导 GNU/Linux 项目的一些术语。你会听到诸如 `Libre`（言论自由自由）、`FOSS`（自由且开源）以及 `FLOSS`（自由/自由且开源）。GNU 对软件内部的这些提供了更深入的解释。

然而，对于技术知识有限且不希望被意外的复杂问题困扰的学生和家庭用户来说，绝对想要一台能让生活更简单的电脑。对于这些用户，Windows 和 macOS 更加熟悉，因此更加直观，解决大多数问题不需要使用命令提示符（Command Prompt）或终端（Terminal）。

不过，并非一无所有。你仍然可以使用流行的浏览器，如 Chrome、Firefox 和 Tor 浏览器（微软也将把新的 Edge 引入 Linux）；如 Signal 和 Slack 等通信工具；如 VPN 和密码管理器等安全软件；以及如 VLC Player 等多媒体基础软件。提到 VPN，Linux 内核现在支持 `WireGuard` VPN 协议。Linux 的防毒病毒软件并不常见，但一些选项包括 ClamAV 和 Sophos。

Steam 可适用于基于 Debian 的 GNU/Linux OS，尽管如果你愿意确保你的操作系统符合安装要求，在其他发行版上你可能成功。或者，你可以使用 Valve 的以游戏为中心的 SteamOS 发行版，它本身也是基于 Debian。请注意，越来越多的游戏（包括 AAA 大作）要么原生支持 GNU/Linux，要么通过 Steam 的 `Proton` 工具获得支持。Valve 甚至宣布其最新的 VR 游戏《Half-Life: Aly》将为 Linux 平台完整发布。

目前暴雪的 Battle.Net、Epic 商店和 EA 的 Origin 还没有 GNU/Linux 系统的原生版本，但你可能可以通过 Steam 的 `Proton` 工具或 `Wine` 模拟器启动你喜欢的游戏以及非 Steam 游戏。

## 为什么要用 Unix 命令？这本书不应该是关于 Linux 如何运行的吗？当然是，但 Linux 本质上是一个 Unix 变体。你在这一章中看到的 "Unix" 单词会比 "Linux" 更多；你可以将学到的知识直接应用于 BSD 以及其他 Unix 变体。我尝试避免使用许多 Linux 特有的界面，不仅是为了让你在使用其他系统时有更好的背景，还因为它们往往不稳定。如果你熟悉这些命令，将能够更轻松地适应新版本。

### Bourne Shell: `/bin/sh`

Shell 是 Unix 系统中最重要的部分之一。Shell 是一个运行用户输入的这类命令的程序。Shell 还充当一个小型编程环境。Unix 程序员经常将任务拆分为许多微小的命令，并使用 Shell 来管理和将它们组合在一起。

系统的许多重要部分都是脚本——包含一系列命令的文件。如果你以前用用过 MS-DOS，可以把脚本想象成非常强大的 `.BAT` 文件。因为它们很重要，本章专门讲解了脚本。随着你阅读此书并获得实践，你将增加关于使用 Shell 操作命令的知识。Shell 最棒的一点之一是，如果你犯了错误，可以很容易看到你输入了什么以找出哪里出了问题，然后重试。

有许多不同的 Unix Shell，但它们的许多功能都源自 Bourne shell (`/bin/sh`)，这是由贝尔实验室为早期 Unix 版本开发的标准 shell。每个 Unix 系统都需要 Bourne shell 才能正常运行，正如你在整本书中看到的那样。Linux 使用了 Bourne shell 的增强版本，称为 `bash` 或 "再次 Bourne"（Bourne-again）。`bash` Shell 是大多数 Linux 发行版的默认 Shell，而在 Linux 系统上 `/bin/sh` 通常是指向 `bash` 的链接。在运行本书中的示例时，你应该使用 `bash` Shell。

注意：如果你将本章作为你在非系统管理员组织的 Unix 账户的指南，那么你的默认 shell 可能不是 `bash`。你可以通过 `chsh` 更改 shell，或向你的系统管理员寻求帮助。

#### 使用 Shell

当你安装 Linux 时，除了 root 用户之外，应该至少创建一个普通用户；这将是你的个人账户。对于本章，你应该以普通用户登录。

#### Shell 窗口

登录后，打开一个 Shell 窗口（通常称为终端）。从 Gnome 或 Ubuntu 的 Unity 等 GUI 执行此操作最简单的方法是打开终端应用程序，它会在新窗口中启动一个 shell。一旦打开了 shell，它顶部应该显示一个提示符，通常以美元符号 ($) 结尾。在 Ubuntu 上，该提示符看起来应该像

`name@host:path$`，在 Fedora 上，它是 `name@host:path$`。如果你熟悉 Windows，shell 窗口看起来会像 DOS 命令提示符；OS X 中的 Terminal（终端）应用程序本质上与 Linux shell 窗口相同。

本书包含了许多你将在 shell 提示符下输入的命令。

它们都以单个 `$` 符号开头，用来表示 shell 提示符。例如，输入以下命令（仅输入加粗部分，不要包含 `$` ）并按回车：

```
$ echo Hello there.
```

注意：书中的许多 shell 命令以 `#` 开头。你应当以超级用户（`root`）身份运行这些命令。这些命令通常需要格外小心。

现在输入此命令：

```bash
$ cat /etc/passwd
```

此命令显示 `/etc/passwd` 系统信息文件的内容，然后返回你的 shell 提示符。现在不用担心这个文件的作用；你稍后将在第 7 章中学习关于它的所有知识。

### `cat` 命令

`cat` 命令是最容易理解的 Unix 命令之一；它简单地输出一个或多个文件的内容。`cat` 命令的一般语法如下：

```bash
$ cat file1 file2 ...
```

当你运行此命令时，`cat` 会打印 `file1`、`file2` 以及你指定的任何其他文件（用 `...` 表示）的内容，然后退出。该命令之所以被称为 `cat`，是因为它在打印多个文件的内容时执行了连接（concatenation）操作。

#### 标准输入与标准输出

我们将使用 `cat` 来简要探索 Unix 的输入和输出（I/O）。Unix 进程使用 I/O 流来读写数据。进程从输入流读取数据并将数据写入输出流。流是非常灵活的。

例如，输入流的源可以是文件、设备、终端甚至是另一个进程的输出流。要查看输入流的工作情况，输入 `cat`（不带文件名）并按回车。这次你不会收回 shell 提示符，因为 `cat` 仍在运行。现在在每行的末尾输入任何内容并按回车。`cat` 命令会重复你输入的任何行。当你感到无聊时，在空行上按 `Ctrl-D` 终止 `cat` 并返回 shell 提示符。

`cat` 采用交互式行为的原因与流有关。因为你没有指定输入文件名，`cat` 从 Linux 内核提供的标准输入流读取，而不是连接到文件的流。在这种情况下，标准输入连接到你运行 `cat` 的终端。

注意：在空行上按 `Ctrl-D` 会停止来自终端的当前标准输入（通常会终止程序）。不要将其与 `Ctrl-C` 混淆，后者无论输入输出如何都会终止程序。

标准输出也是类似的。内核为每个进程提供一个标准输出流，可以在其中写入输出。`cat` 命令始终将其输出写入标准输出。当你在终端中运行 `cat` 时，标准输出连接到该终端，因此你在那里看到了输出。输入和输出通常缩为 `stdin` 和 `stdout`。许多命令的操作方式与 `cat` 相同；如果不指定输入文件，命令将从 `stdin` 读取。输出略有不同。某些命令（如 `cat`）只将输出发送到 `stdout`，但另一些可以直接可以将输出发送到文件。第三种标准 I/O 流称为 `stderr`。你将在第 2 节看到它。

流的特性之一是你可以轻松地操作它们，以读写终端以外的内容，正如你将在 2 节中学到的那样。

## 基本命令

现在让我们一些 Unix 命令。以下大部分程序都接受参数，并具有更改列表显示的选项。这是一份基本命令的简化列表；你目前不需要了解所有细节。

### `ls` 命令

`ls` 命令列出目录内容。默认是当前目录。使用 `-l` 进行详细列表，使用 `-F` 显示文件信息。

### 目录导航

Unix 拥有分级目录结构，从 `/` 开始，称为根目录。父目录是 `/`，而不是反斜杠。根目录下有几个子目录，如 `/home`。当你引用文件或目录时，请指定路径名。当路径以 `/` 开头时（例如 `/lib`），它是完整路径（或绝对路径）。路径分量后跟两个点（`..`）表示父目录。例如，如果你在 `/lib` 中工作，该路径将指向 `/`。一个点（`.`）引用当前目录；例如，如果你在 `/lib`，路径仍然是 `/lib`，而 `./X` 就是 `/lib/X`。你不需要经常使用 `.`，因为大多数命令默认指向当前目录。不以 `/` 开头的路径被称为相对路径。大多数时候，你会使用相对名称工作，因为你已经处于所需的目录中了。

现在你已经对基本目录有了初步了解，这里是一些方向性命令。

### `cd`

当前工作目录是进程（如 shell）所在的目录。`cd` 命令更改 shell 的工作目录：

```bash
$ cd dir
```

如果你省略了 `dir`，shell 将返回你的家目录，即你首次登录时所在的目录。

### `mkdir`

`mkdir` 命令创建一个新目录 `dir`：

```bash
$ mkdir dir
```

### `rmdir`

`rmdir` 命令删除目录 `dir`：

```bash
$ rmdir dir
```

如果 `dir` 不为空，此命令将失败。然而，如果你等不及，你可能想先删除 `dir` 内部的所有文件和子目录。你可以使用 `rm -rf dir` 删除目录及其内容，但要小心！这是少数引起严重损害的命令之一，特别是当你以超级用户运行时。`-r` 选项指定递归删除，`-f` 强制。在使用通配符（如星号 `*`）使用 `-rf` 标志时务必小心。而且，在运行命令之前务必双重检查。

### Shell 通配（通配符）

Shell 可以根据简单模式匹配文件和目录名，这一过程被称为通配（globbing）。这与其他系统的通配符类似。通配符是 `*`，它告诉 shell 匹配任意数量的字符。例如，以下命令列出当前目录下的文件：

```bash
$ echo *
```

shell 匹配包含通配符的参数，用文件名替换这些参数，然后运行修改后的行。这种替换被称为扩展，因为 shell 替换了所有匹配的文件。以下是使用 `*` 的某些方法：

- `at*` 扩展为所有以 `at` 开头的文件名
- `*at` 扩展为所有以 `at` 结尾的文件名
- `*at*` 扩展为所有包含 `at` 的文件名

如果没有匹配通配符，shell 不执行扩展，命令将带有字面运行。例如，尝试命令 `echo *dfkdsaf`。



注意：如果你习惯了 MS-DOS，可能会输入`*.*`来匹配所有文件。现在打破这种习惯。在 Linux 和其他版本的 Unix 中，你必须使用`*`来匹配所有文件。在 Unix shell 中，`*.*`只匹配名称中包含点（`.`）的文件和目录。Unix 文件名不需要扩展名，通常也不携带扩展名。

另一个 shell 通配符问号（`?`）指示 shell 匹配好一个任意字符。

例如，`b?`可以匹配`boat`和`brat`。如果你不想让 shell 在命令中展开通配符（glob），请将通配符括在单引号（`''`）中。例如，命令`echo *`会打印出一个星号。你会发现这对于下一节描述的某些命令（如`grep`和`find`）非常有用。

注意：务必记住，shell 在运行命令之前执行展开，且仅在此之后执行。

因此，如果通配符在未经展开的情况下传递给命令，shell 将不再对其做任何额外处理；将由命令本身来决定它想做什么。

现代 shell 的模式匹配能力还有更多内容，但你现在需要掌握的是`*`和`?`。

## 中级命令

以下章节描述了最核心的中级 Unix 命令。

### grep

`grep`命令打印来自文件或输入流的匹配表达式的行。例如，要打印`/etc/passwd`文件中包含`root`文本的行，请输入：

```bash
$ grep root /etc/passwd
```

在同时处理多个文件时，`grep`命令非常有用，因为它在打印匹配行的同时还会打印文件名。例如，如果你想检查`/etc`中每一个包含`root`单词的文件，可以使用此命令：

```bash
$ grep root /etc/*
```

两个最重要的`grep`选项是`-i`（用于不区分大小写的匹配）和`-v`（反向搜索，即打印所有不匹配的行）。此外还有一个更强大的变体称为`egrep`（它只是`grep -E`的同义词）。

`grep`理解被称为正则表达式的模式，这些模式基于计算机科学理论，并且在 Unix 工具中非常常见。正则表达式比通配符风格的模式更强大，并且它们有不同的语法。关于正则表达式有两点重要的内容需要记住：

* `.*`匹配任意数量的字符（类似于通配符中的`*`）。

* `.`匹配任意一个字符。

注意，`grep`手册详细说明了正则表达式，但读起来可能困难。要学习更多知识，你可以阅读*Mastering Regular Expressions*第 3 版（O'Reilly, 2006），或者*Programming Perl*第 4 版（O'Reilly, 2012）中的正则表达式章节。如果你喜欢数学并对正则表达式感兴趣，可以查找*Introduction to Automata, Languages and Computation*第 3 版（Pearson, 2006）。

### less

当文件很大或命令输出很长并滚出顶部时，`less`命令非常有用。要翻页像`/usr/share/words`这样的大文件，请使用`less /usr/share/words`。运行`less`时，你将一次查看文件内容。按空格键向后移动，按`b`键向上滚动。输入`q`退出。

注意：`less`命令是一个名为`more`的旧程序的增强版本。大多数 Linux 桌面系统都带有`less`，但在嵌入式系统和其他系统中并不是标准配置。如果你遇到无法使用`less`的情况，请尝试`more`。你可以在`less`内部搜索文本。例如，要向前搜索一个单词，输入`/word`；向后搜索则使用`?word`。当你找到匹配项时，按`n`继续搜索。

正如你将在第 2.4 节中学到的，你可以将任何程序的标准输出发送到另一个程序的标准输入。当你有一个具有大量输出需要筛选的命令，并想使用类似`less`的工具查看输出时，这一点特别有用。这里是将`grep`命令的输出发送给`less`的示例：

```bash
$ grep /usr/share/words | less
```

尝试运行这个命令。你可能会经常这样使用`less`。

### pwd

`pwd`（打印工作目录）程序简单地输出当前目录的名字。你可能会奇怪为什么需要这个，因为大多数 Linux 发行版在提示符中包含当前目录。有两个原因：第一，并不是所有的提示符都包含当前目录，你可能甚至想在自己的提示符中去掉它，因为它占用了大量空间。第二，你在第 2.17.2 节中将学习符号链接有时会模糊当前目录的真实完整路径。你可以使用`pwd -P`来消除这种困惑。

### diff

要查看两个文本文件之间的差异，请使用`diff`：

```bash
$ diff file1 file2
```

多个选项可以控制输出格式，默认输出格式通常对人类来说是最易理解的。然而，当程序员需要将输出发送给自动化工具以进行处理时，他们更倾向于使用`diff`的输出。

### find

如果你有一个文件且不确定它的格式，可以使用`find`命令来查找它：

```bash
$ find .
```

你可能会惊讶于`find`命令能做多少事情。当你知道某个文件在目录中但不知道在哪里时，按名称查找`find`：

```bash
$ find . -name file
```

像`find`这样的命令功能很多。它接受`-name`和`-print`等选项，但必须使用单引号（`*'`）来保护通配符（回顾第 2.4 节，shell 在运行命令前会展开通配符）。大多数系统还有`locate`用于查找文件。使用`locate`搜索比`find`快得多，但如果你查找比索引更新的文件，`locate`就找不到它。

### head and tail

要快速查看文件或数据流的一部分，使用`head`和`tail`命令。例如，`head /etc/passwd`显示密码文件的前 10 行，而`tail /etc/passwd`显示最后 10 行。要更改显示的行数，使用`-n`选项，其中`n`是你想要看到的行数（例如`head -5 /etc/passwd`）。要从第 n 行开始打印，使用`tail +n`。

### sort

`sort`命令按字母顺序对文件行排序。如果文件的行以数字开头且你想按数字顺序排序，使用`-n`选项。`-r`选项反转排序顺序。

### Changing Password and Shell

使用`passwd`命令更改密码。系统会要求输入旧密码，然后提示输入两次新密码。选择一个不包含任何语言真实单词的密码，不要尝试组合单词。创建密码最简单的方法之一是选取一个句子，产生缩写，然后用数字或标点符号修改缩写。这样你只需要记住句子即可。你可以使用`chsh`命令更改 shell（改为`ksh`或`tcsh`），但请记住本书假设你运行 bash。

### Dot Files

进入你的主目录，使用`ls`查看，然后运行`ls -a`。你看到输出的差异了吗？当你不带`-a`运行`ls`时，看不到被称为点文件的配置文件。这些是以点（`.`）开头的文件和目录。常见的点文件有`.bashrc`和`.login`，也有点目录，例如`.ssh`。点文件或目录并没有特别之处。某些程序默认不显示它们，这样当你列出主目录内容时就不会看到一团乱。

你使用`-`选项。此外，shell 通配符（globs）不会匹配点文件，除非你显式地使用如`.*`的模式。

注意：使用通配符可能会遇到问题，因为`.*`会匹配`.`和`..`（当前目录和父目录）。你可能希望使用如`.[^.]*`或`.??*`的模式来获取除当前和父目录以外的所有点文件。

# 环境与 Shell

## 变量

shell 可以存储临时变量，称为 shell 变量，其中包含 65 种文本字符串值。shell 变量对于跟踪脚本中的值非常有用，某些 shell 变量还会控制 shell 的行为。（例如，`bash` shell 在显示提示符之前会读取`PS1`变量。）

要给 shell 变量赋值，请使用等号（`=`）。这是一个简单的示例：

```
$ STUFF=blah
```

前面的示例将名为`STUFF`的变量值设置为`blah`。要评估此变量，请使用`$STUFF`（例如，尝试运行`echo $STUFF`）。

环境变量类似于 shell 变量，但它并不特定于某个 shell。Unix 系统上的所有进程都有环境变量存储。环境变量和 shell 变量的主要区别在于，操作系统会将你 shell 的所有环境变量传递给 shell 运行的程序，而 shell 变量无法在你运行的命令中被访问。

使用 shell 的`export`命令分配环境变量。例如，如果你想将`$STUFF` shell 变量变为环境变量，请使用以下命令：

```
$ STUFF=blah
$ export STUFF
```

环境变量是有用的，因为许多程序会读取它们来获取配置和选项。例如，你可以将最喜欢的`less`命令行选项放在`LESS`环境变量中，当你运行`less`时，它将使用这些选项。（许多帮助页都包含一个标记为`ENVIRONMENT`的章节，其中描述了这些变量。）

## 命令路径

`PATH`是一个特殊的环境变量，它包含命令路径（简称为路径）。命令路径是 shell 在尝试定位命令时会搜索的系统目录列表。例如，当你运行`ls`时，shell 会在`PATH`中列出的目录中搜索`ls`程序。如果路径中的多个目录中都出现了同名的程序，shell 将运行第一个匹配的程序。

如果你运行`echo $PATH`，你会看到路径组件是用冒号（`:`）分隔的。例如：

```
$ echo $PATH
/usr/local/bin:/usr/bin:/bin
```

要让 shell 在更多地方查找程序，请更改`PATH`环境变量。例如，通过此命令，你可以将目录`dir`添加到路径开头，这样 shell 在查找任何其他`PATH`目录之前会先查找`dir`。

```
$ PATH=dir:$PATH
```

或者你可以将目录名追加到`PATH`变量的末尾，导致 shell 最后查找`dir`：

```
$ PATH=$PATH:dir
```

注意：修改路径时要小心，因为如果你误写了`$PATH`，可能会意外删掉你的整个路径。如果发生这种情况，不要慌张！损坏不是永久的；你只需要启动一个新的 shell 即可。（若要产生持久影响，你需要在编辑特定的配置文件时弄错，即使如此这也不难。）恢复正常状态的最简单方法之一是关闭终端窗口并启动另一个。

## 命令行编辑

在你操作 shell 时，请注意你可以使用左右箭头键编辑命令行，还可以通过向上和向下箭头使用之前的命令。这在大多数 Linux 系统上都是标准配置。然而，忘记箭头键并使用控制键是一个好主意。如果你学会了它们，你会发现自己在使用这些标准按键的程序中更好地输入文本：

- `ctrl-B`: 光标向左移动

- `ctrl-F`: 光标向右移动

- `ctrl-P`: 查看上一个命令（或光标向上移动）

- `ctrl-N`: 查看下一个命令（或光标向下移动）

- `ctrl-A`: 光标移动到开头

- `ctrl-E`: 光标移动到末尾

- `ctrl-W`: 删除单词

- `ctrl-U`: 删除光标到开头的内容

- `ctrl-K`: 删除光标到末尾的内容

- `ctrl-Y`: 粘贴被删除的文本（例如，来自`ctrl-U`）

### 编辑器

说到编辑，是时候学习一种编辑器了。要开始使用 Unix，你必须能够在不损坏文件的情况下编辑文件。大多数系统使用配置文件（如`/etc`）。编辑文件并不困难，但你通常需要一个强大的工具来完成工作。你应该尝试学习两种文本编辑器之一：`vi`和`emacs`。大多数 Unix 高手对他们的选择非常挑剔，但不会列出来。自己选一个。

如果你选择了一个符合你工作方式的编辑器，你会发现更容易学习。基本上选择取决于：

- 如果你想要一个几乎可以做任何事情的编辑器，并且不在意通过额外输入来获得这些功能，请尝试`emacs`。

- 如果速度就是一切，尝试一下吧；它玩起来有点像视频游戏。在刚开始时，你可能会被友好的编辑器所吸引，例如`nano`或那里无数 GUI 编辑器之一，但如果你倾向于养成使用第一个工具的习惯，那么你不想走这条路。

注意：编辑将是你首次看到终端和 GUI 差异的地方。像`vi`这样的编辑器在终端窗口内部，使用标准的终端 I/O 接口。GUI 启动自己的窗口并呈现自己的界面，独立于终端。`emacs`默认在 GUI 中运行，也可以在终端窗口中运行。

# 用户环境

## 创建启动文件的指南

在设计启动文件时，要考虑到用户。如果你是机器上唯一的用户，你不需要太担心错误，因为错误只会影响你，而且很容易修复。然而，如果你创建的启动文件旨在作为机器或网络上所有新用户的默认设置，或者你认为可能有人拷贝你的文件并在不同的机器上使用，那么你的任务就会变得相当困难。如果你在一个为 10 个用户的启动文件中犯了错误，你最终可能需要修复 10 次这个错误。为其他用户创建启动文件时，请记住两个核心目标：

- 简单性：保持启动文件的数量尽可能少，并保持文件尽可能小且简单，以便于修改。每一项都是多一个可能出错的地方。

- 可读性：在文件中使用大量的注释，让用户能够很好地了解文件中每个部分的作用。

## 何时需要修改启动文件

在更改启动文件之前，请问问自己是否应该进行该更改。以下是一些更改文件的良好理由：

- 你想更改默认提示符。

- 你需要适应本地安装的软件。（尽管如此，先考虑使用脚本。）

- 你的启动文件损坏了。

## Shell 启动文件元素

Shell 启动文件中应该包含什么？某些内容似乎显而易见，例如路径和提示符设置。但路径中到底应该包含什么，启动文件中放多少内容才合适？接下来的几节将讨论 Shell 启动文件的核心要素——从命令路径、提示符、别名到权限掩码。

## 命令路径

任何 shell 启动文件中最重要的部分都是命令路径（path）。路径应该涵盖包含普通用户感兴趣的所有应用程序的目录。至少，路径应该按以下顺序包含这些组件：

```
/usr/local/bin
/usr/bin
/bin
```

这种顺序确保了你可以使用位于`/usr/local`的特定站点变体程序来覆盖标准的默认程序。

大多数 Linux 发行版会将几乎所有软件包软件的可执行文件安装在`/usr/bin`中。它们偶尔会有所不同，例如将游戏放在`/usr/games`，将图形化应用程序放在单独的位置，因此请先检查系统的默认设置。并确保系统上的每个通用程序都能通过上述列出的目录之一可用。如果不是这样，你的系统可能已经失控了。不要为了适应新的软件安装目录而更改你用户环境中的默认路径。适应独立安装目录的方法是在`/usr/local/bin`中使用符号链接。许多用户会使用自己的`bin`目录来存储 shell 脚本和程序，因此你可能想将此添加到路径的前端：

```
$HOME/bin
```

注意：较新的习惯是将二进制文件放在`$HOME/.local/bin`中。

如果你对系统实用工具（如`traceroute`、`ping`和`lsmod`）感兴趣，请将 sbin 目录添加到你的路径中：

```
/usr/local/sbin
/usr/sbin
/sbin
```

### 向路径中添加点（`.`）

有一个小但有争议的命令路径组件需要讨论：点（dot）。在路径中放置点（`.`）允许你在不在程序名前加`./`的情况下运行当前目录下的程序。

这在编写脚本或编译程序时可能看起来方便，但由于两个原因这是一个坏主意：

* 它可能导致安全问题。你不应该在路径开头放置点。这是一个可能发生的情况示例：攻击者可以在互联网分发的压缩包中放置一个名为`ls`的木马。即使路径末尾有一个点，你仍然容易受到`sl`或`ors`这样的拼写错误的影响。

- 它是不一致的且可能引起混淆。

路径中的点可能意味着命令将切换到当前目录。

### 手册路径

传统的目录路径由`MANPATH`变量决定，但你不应该设置它来覆盖`/etc/man`中的默认值。

### 提示符

经验丰富的用户倾向于避免长复杂的提示符。相比之下，新手会将所有内容拖入默认提示符中。你的提示符应该反映用户的需求；如果有帮助，将工作目录、主机名和用户名放在提示符中。

上述，避免使用对 shell 有特殊含义的字符，例如：`{`、`}`、`=`、`<`、`>`。避免额外的字符，如果你复制粘贴窗口输出的内容，这些字符可能会导致你的当前目录下产生异常的空文件。即使是 shell 的默认提示符也不理想。例如，默认提示符包含 shell 的名称和版本。bash 的这个简单提示符设置以`$`结尾（传统的是`%`）：

```
PS1='\u$'
```

`\u`是当前用户名的替换符（参考 bash 手册页中的提示符）。其他常用的替换符包括：

* `\h`主机名（短格式，不带域名）

* `\!`历史编号

* `\w`当前目录。因为这可能会变得很长，你可以使用`\W`将显示限制为最后一个组件。

* `\$`如果作为用户运行，`#`如果是 root

## 别名

在现代环境中，较为复杂的点之一是别名（aliases）的作用，这种 shell 特性在执行命令之前用一个字符串替换另一个字符串。这些可以是高效的快捷方式，节省一些字量。然而，别名也有这些缺点：

* 操作参数可能很麻烦。

* 它们令人困惑；shell 内置的`which`命令可以告诉某内容是否是别名，但它不会告诉你在哪里定义的。

* 它们在子 shell 和非交互式 shell 中是不受欢迎的；它们在其他 shell 中不起作用。

鉴于这些缺点，你应该尽可能避免别名，因为编写一个 shell 函数或完全全新的 shell 脚本更简单。现代计算机启动和执行 shell 的速度非常快，别名之间的差异对你来说可能毫无意义。当你希望用 shell 脚本更改环境时，别名会很有用，因为脚本作为子 shell 运行（你也可以定义 shell 函数来影响这一点）。

## 权限掩码



正如第 2 章所述，shell 内置的`umask`（权限掩码）设置了你的默认权限。你应该在其中一个启动文件中运行`umask`，以便你运行的任何程序创建的文件都具有你的权限。有两个选择：

- `077` 这种掩码是最严格的掩码，因为它不允许其他用户访问新文件和目录。这通常用于多用户系统，在你不希望其他用户查看你的任何文件。然而，当设置为默认值时，当用户想要共享文件但不如何设置权限时，有时会导致问题。
- `022` 这种掩码赋予其他人读取新文件和目录的权限。这在单用户系统中可能很重要，因为许多作为伪用户运行的守护进程无法看到使用严格的`077` umask 创建的文件和目录。

注意：某些应用程序（尤其是邮件程序）会覆盖 umask，将其更改为`077`，因为它们觉得文件是文件所有者的私事。

## 启动文件顺序和示例

现在你已经知道了 shell 启动文件中写什么，是时候看一些具体的示例了。惊讶的是，创建启动文件最困难、最混乱的部分之一是决定使用多个启动文件中的哪一个。接下来的章节介绍了最流行的 Unix shell：bash 和 tsh。

### Bash Shell

在 bash 中，你可以从启动文件名`.bash_profile`、`.profile`、`.bash_login`和`.bashrc`中选择。哪一个适用于你的命令路径、手册路径、提示符、别名和权限掩码？答案是，你应该有一个`.bashrc`文件，并配有一个指向`.bashrc`的`.bash_profile`符号链接，因为有几种 bash 实例类型。

两种主要的实例类型是交互式和非交互式，但在其中只有交互式 shell 是登录式的（login）。非交互式（例如运行脚本的 shell）通常不读取任何启动文件。

`.bash_profile`、`.bash_login`和`.profile`文件，系统只会运行它看到的第一个文件。

虽然听起来很奇怪，但可以将非交互式 shell 作为登录 shell 运行，以强制其运行启动文件。要这样做，请启动 shell 时使用`-l`或`--login`。

## 非登录 Shell (Non-Login Shells)

非登录 shell 是你登录后运行的额外 shell。简单来说，它就是任何不是登录 shell 的交互式 shell。窗口系统的终端程序（xterm、GNOME Terminal 等）除非你明确要求登录 shell，否则都会启动非登录 shell。

作为非登录 shell 启动时，bash 会运行`/etc/bash.bashrc`，然后运行用户的`.bashrc`。

## 两种模式的结果

### Shell 的种类

两种不同启动系统背后的逻辑是：在过去，用户通过带有登录 shell 的传统终端登录，然后通过窗口系统或屏幕程序启动非登录子 shell。

对于非登录子 shell，反复设置用户环境并运行一系列已经运行过的程序被认为是浪费的。

对于登录 shell，你可以在如`.bash_profile`等文件中运行复杂的启动命令，只将别名和其他“轻量级”内容留给`.bashrc`。

如今，大多数桌面用户通过图形化显示管理器登录。其中大多数启动时会带一个非交互式登录 shell，以保留上述登录与非登录的模型。如果它们没有这样做，你需要在`.bashrc`中设置整个环境（路径、手动路径等），否则，你将在终端窗口 shell 中永远看不到你的任何环境设置。

然而，如果你以后想在控制台或远程登录，你仍然需要一个`.bash_profile`，因为登录 shell 永远不会运行`.bashrc`。

### 示例 .bashrc

为了同时满足非登录 shell 和登录 shell 的需求，如何创建一个可以作为`.bash_profile`使用的`.bashrc`呢？这里有一个（足够的）示例：

```bash
## 命令路径。
PATH=/usr/local/bin:/usr/bin:/bin:$HOME:$PATH

### PS1 是常规提示符。
### 替换符包括：
### 用户主机名 当前目录
```

### 检查登录 shell 和交互式 shell

通过一个与`.bash_profile`匹配的`.bashrc`，你通常不需要为登录 shell 运行额外的。但是，如果你想为两者都定义不同的动作：

```bash
case $- in
*i*) # 交互式命令在此
    command --snip
    ;;
*) # 非交互式命令在此
    command --snip
    ;;
esac
```

## tcsh Shell

几乎所有 Linux 系统上的标准 shell 是 tcsh，这是一种增强型的 C shell，它普及了如命令行编辑以及多维文件名和命令补全等功能。即使你没有使用 tcsh 作为默认用户 shell（我们建议使用 bash），你仍然应该提供 tcsh 启动文件，以防你的用户碰巧遇到它。

你不需要担心 tcsh 中登录 shell 和非登录 shell 区别。启动时，tcsh 会寻找`.tcshrc`文件。如果没有，它会寻找 csh shell 的`.cshrc`启动文件。这种顺序的原因是，你可以使用`.tcshrc`文件处理 csh 中无法运行的 tcsh 扩展。

你可能应该坚持使用传统的`.bashrc`而不是`.tcshrc`；极不太有人会使用 csh 使用你的启动文件。而且如果用户确实在其他系统上遇到了 csh，你的`.cshrc`也能正常工作。

### 示例 .cshrc

```csh
## 命令路径。
set PATH=/usr/local/bin:/usr/bin:/bin:$PATH

### EDITOR 和 VISUAL 决定在请求编辑文件时，less 和 mail 等程序使用什么程序。
set EDITOR
set VISUAL

### PAGER 是 man 等程序的默认文本查看器。
### 这些是 less 的一些有用选项：
### (F=退出, R=重绘, X=不使用屏幕)
set PAGER=less

umask 022
```

## 默认用户设置

编写启动文件并为新用户选择默认值的最佳方法是使用测试用户。创建一个空目录的测试用户，并将自己的启动文件拷贝到测试目录。从零开始编写新文件。

当你认为你有一套可以运行的配置时，以所有方式登录测试用户（在控制台、远程等）。确保你测试了尽可能多的内容，包括窗口系统操作和菜单。当你对测试用户满意时，创建第二个测试用户。如果一切运行正常，你现在就有了一套可以分发给用户的新启动文件了。

### Shell 默认值

Linux 系统上任何新用户的默认 shell 应该是 bash，因为：

- 用户使用 shell 编写 shell 脚本（例如，csh 是一个臭名昭著的糟糕脚本工具——别去想它）。
- bash 是 Linux 上的标准。
- bash 使用 readline，因此它的界面与其他许多工具相同。
- bash 让你能够对 I/O 重定向和文件句柄进行精细、易于理解的控制。

然而，许多老练的高手使用 csh 和 tcsh 等 shell 仅仅是因为他们不忍切换。当然，你可以选择任何你喜欢的 shell，但如果你没有偏好，请选择 bash，并将其作为系统上任何新用户的默认 shell。（用户可以使用`chsh`命令更改其 shell 以适应个人偏好。）还有许多其他 shell（rc、ksh、zsh、es 等）。有些不适合作为初学者 shell，但 zsh 和 fish 有时受到寻找替代 shell 的新用户的欢迎。

### 编辑器

在传统系统上，默认编辑器应该是 vi 或 emacs。这些是唯一保证在几乎任何系统上存在的编辑器，这意味着从长远来看，它们给新用户带来的麻烦最少。

然而，Linux 发行版通常将 nano 配置为默认编辑器，因为它对初学者更容易用。与 shell 启动文件一样，避免大型默认编辑器启动文件。在 `.xrc` 启动文件中设置一点东西并无害，但要避免任何显著改变编辑器行为或外观的内容。

### 分页器

将默认`PAGER`环境变量设置为`less`是完全合理的。

### 启动文件陷阱

- 不要要在 shell 启动文件中放置任何类型的图形化命令。
- 不要在 shell 启动文件中设置`DISPLAY`环境变量。
- 不要在 shell 启动文件中设置终端类型。
- 在默认启动文件中不要吝于描述性注释。
- 不要在启动文件中运行会输出到标准输出的命令。
- 永远不要在 shell 启动文件中设置`LD_LIBRARY_PATH`（参见第 15.1.4 节）。

## 其他启动主题

由于本书仅涉及底层的 Linux 系统，我们不会涵盖窗口环境的启动文件。这确实是一个大问题，因为让你登录现代 Linux 系统的显示管理器有自己的一套启动文件，例如`.xsession`、`.xinit`以及无尽的 GNOME 和 KDE 相关项组合。

窗口环境的选择可能看起来令人困惑，而且 Linux 中没有启动窗口环境的通用方法。下一章将描述许多可能性中的一些。然而，当你确定了系统的功能时，你可能会与图形环境相关的文件过度着迷。这没关系，但不要把这种习惯带给新用户。在 shell 启动文件中保持简单的这一原则同样适用于 GUI 启动文件。事实上，你可能根本不需要更改你的 GUI 启动文件。

## 如何进行切换

### 从 Windows 切换到 Linux

微软终于于 1 月份停止对 Windows 7 的支持，这意味着你再也无法获得错误修复或安全更新。如果你是最后一批 Windows 7 的坚守者之一，并且不想被困在一个不安全的系统中，你有一个选择要做：升级到 Windows 10 或完全切换到其他系统。

如果你不喜欢微软在 Windows 10 上采取的方向，我们理解。它已经变得好了一些（通过一些调整你可以让它感觉更像 Windows 7），但它对“Windows 即服务”的新方法意味着将永远更加关注嵌入式广告、持续更新和数据收集。如果你一直在考虑跳转到 Linux，现在就是时机。

#### 选择你的发行版

与 Windows 和 macOS 不同，Linux 并不是只有一个版本。相反，Linux 被封装成许多不同的发行版（或“distros”），每个版本都有自己的界面和功能 set。有的使用带有 dock 和“应用商店”的类 Mac 界面，而另一些使用更极简的界面并从命令行安装应用。探索丰富的 Linux 发行版是一个有趣的部分，但对于你的第一次安装，你可能想要一个流行且对初学者友好的版本，这样在需要时可以轻松获得帮助。这就是为什么我推荐从 Linux Mint 开始。

![](img/index-1)

有很多功能上模仿 Windows 的发行版，例如 Zorin OS，但它们规模较小，你不会有一个大型社区来帮助你熟悉。另一方面，Ubuntu 可以说是桌面端最流行的发行版，但它现在看起来并不很像 Windows 了。Linux Mint 是一个完美的折中：它是为初学者设计的，提供了一个熟悉的环境，并且它基于 Ubuntu，所以当你需要帮助时，可以使用 Ubuntu/Mint 社区。你可以自由查看其他发行版，但我本指南将使用 Mint，我也建议你也这样做。它不是我最喜欢的发行版，但对于新的 Windows 迁移用户来说非常棒，而且一旦你在初学者友好的系统上下载了基础内容，探索其他版本就会更容易。

#### 创建你的安装驱动

前往 Mint 的下载页面并选择 64 位的“Cinnamon”版本。Cinnamon 是我向原 Windows 用户的桌面环境，虽然 MATE 也很像 Windows，尽管它稍微没那么现代。得益于其轻量资源占用，XFCE 是旧或低配置 PC 的理想选择。Mint 的下载页面根据你所在的地区提供了多个链接。如果你使用 BitTorrent，我建议获取 torrent 文件，下载速度会快得多。

安装程序将以 ISO 或磁盘镜像文件的形式提供。要在系统上安装它，你需要将其刻录到 DVD（在 Windows 7 中右键点击它并选择“刻录磁盘映像”）或 USB 闪盘。我们将使用一个名为`Rufus`的工具完成后者。安装`Rufus`，打开并插入一个 2GB 或更大的闪盘。（如果你有快速的 USB 3.0 驱动器就更好。）你应该能在`Rufus`主窗口顶部的 Device 下拉列表中看到它。

接下来，点击 Disk image 旁的 Select 按钮，选择你刚刚下载的 Linux ISO。按下 Start，如果提示下载新版本的 Linux，点击 Yes。注意，这将擦除你的驱动器，因此请在之前确保里面没有任何内容。完成后，你会看到一条消息，你的闪盘将被重命名为 LINUX MINT。备份你的数据，重启电脑并安装。

#### 在你的 PC 上安装 Linux

当电脑重启时，你应该会看到一条消息，提示你按某个键进入启动菜单（类似于 F12）。如果没有，你会看到一个进入设置的按键（通常是 Del）。按下这些按键之一并寻找从插入的 USB 启动的选项。如果你进入了完整的设置菜单，它将在 Boot 设置中，你需要在完成后退出菜单并再次重启。

![](img/index-32)

随后你将面对 GRUB，即 Linux Mint 的启动菜单，你可以在此处选择启动进入 Linux Mint。如果你遇到任何错误，你可能需要在 Google 上搜索解决方案。例如，我曾不得不为我的显卡启用`nomodeset`选项。其他人则可能需要在 BIOS 中调整或禁用 Secure Boot（安全启动）。

这个安装程序是我们所谓的 Live CD，你可以在安装之前实际上在其中尝试并使用 Linux Mint 桌面。这将给你一个机会，在不触碰系统驱动的情况下查看此特定的发行版是否吸引你。一旦你满意了，双击 Install Linux Mint 图标并通过向导。务必勾选 Install third-party software 旁边的框，因为它包含了你需要的有用驱动程序和解码器。

从这里开始，你有几个选项。你可以完全抹除硬盘，删除所有 Windows 的痕迹并使用 Linux 作为你的操作系统。（在这样做之前，务必确认你已备份了数据。）或者，你可以将驱动器划分多个分区，并在 Windows 旁双启动 Linux。这将允许你随时重启进入其中一个。请记住，Windows 7 将保持处于不安全状态，所以你不想在上面花费太多时间。至少，在完全移除 Windows 之前的过渡期间知道你有那个安全网是令人宽慰的。

从 Installation Type 中选择相关选项并点击 Install Now。该过程可能需要一些时间，但完成后，你会看到一条消息，你的闪盘将被重命名为 LINUX MINT。备份你的数据，重启电脑并安装。

# 熟悉 Linux

### 安装一些应用

当你重启后，你将进入 Linux Mint 桌面——只是这次它已安装在你的 PC 上了。基础操作非常熟悉：点击左下角的按钮查看应用程序，从底部任务栏管理窗口，等等。然而，Linux 中有几点工作方式与 Windows 不同，其中应用是差异最大的。

应用商店，其中包含许多应用程序的目录。你可以通过两种方式从仓库中安装应用程序：通过图形化软件管理器（同样，它看起来像应用商店）或通过命令行。

要打开 Linux Mint 的软件管理器，请点击左下角的菜单按钮，导航到“管理” > “软件管理器”（或者直接像在 Windows 中那样开始输入“software manager”）。在这里，你可以下载许多免费的开源应用程序。其中一些应用是它们在 Windows 上对应软件的 Linux 版本，例如 Steam 和 Spotify；而另一些则是是常用软件的开源替代品（Banshee 是一个类似于 iTunes 的音乐播放器，GIMP 是一个类似于 Photoshop 的图像编辑器）。你可以在这里进行浏览，也可以使用顶部的搜索栏搜索应用程序。

### 如何安装和卸载应用程序

如果你知道自己想要找什么，从命令行安装应用程序通常速度更快。虽然初开始看起来可能令人生畏，但 Linux 仍然依赖命令行来完成各种任务，因此习惯使用它可能对你是有益的。要安装一个应用程序——例如开源媒体播放器 VLC——请打开终端窗口并运行：

```
sudo apt update
sudo apt install vlc
```

让我们来分解一下：`sudo`告诉系统以 root 权限（或者在 Windows 中可能被称为管理员权限）运行命令，`apt`是 Linux Mint 包管理器的名称，而`update`确保可用应用程序列表是最新的。

第二个命令包含`install vlc`，这自言易懂。在安装任何应用程序之前，你应该运行`sudo apt update`，并将`vlc`替换为你任何想要安装的应用程序名称。如果你不确定仓库中对它的称呼，可以运行`sudo apt cache search vlc`来查看结果。

要卸载应用程序，只需运行：

```
sudo apt remove vlc
```

这将删除该应用程序，但不会删除你的配置文件，因此如果你以后决定重新安装它，你的设置将仍然存在。如果你想也删除配置文件，可以改运行：

```bash
sudo apt purge vlc
```

### 如何更新应用程序

你可能还需要定期更新这些应用程序，以获得最新版本。同样，你可以通过两种方式实现：通过图形化工具或命令行。对于图形化工具，点击右下角的盾牌图标，这将打开“更新管理器”应用。然后你可以点击“安装更新”按钮来更新你所有的软件。

更新 Linux Mint 另一种，你可以打开终端并运行两个命令：

```bash
sudo apt update
sudo apt upgrade
```



同样，`update` 命令检查软件是否有新版本，而 `upgrade` 命令实际上会升级你所有的应用程序。你需要一起运行这两个命令，就像你安装新应用程序时一样。

这些是你现在最需要了解的关键点，但请花时间浏览一下`Mint`的界面及其设置，看看它提供了哪些功能。启动时出现的“欢迎”窗口会有很大帮助——它的“第一步”区域将向你展示如何选择不同的布局、安装可能需要的媒体解码器，以及为你的硬件安装必要的驱动程序。

你会很快掌握基础操作的，但如果你遇到困难，`Mint`和`Ubuntu`论坛随时为你提供帮助。只需多搜索一下，因为很有可能在你之前已经有人遇到过同样的问题。
