Watchpoints let you interrupt the program when a memory location is written. This lets you look for code that is modifying a variable without knowing exactly which code is responsible for modifying the variable.

Exception handling lets gdb intercept exceptions in languages that support them (for example, C++.)

gdb supports programs that use multiple threads, and it lets you specify break- points that are active only for particular threads.

gdb supports sophisticated data examination commands that let you examine and print the contents of memory in various formats.

gdb supports many programming languages, including C, C++, assembler, FOR- TRAN, Java, Modula-2, and Scheme. gdb understands expressions written in these various languages.

# The Data Display Debugger

The Data Display Debugger (ddd) is an amazing graphical front-end to gdb. While gdb is powerful, its user-interface is a bit primitive. ddd remedies this by building a powerful graphical user interface on top of gdb.

Invoke ddd on the bad example:

```
$ ddd bad
```
