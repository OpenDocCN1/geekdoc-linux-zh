
## 备份策略

一种简单的备份方案是：先对所有数据进行一次备份，然后在经过一段时间之后，备份自上次备份以来发生更改的所有内容。第一次备份称为*全量*备份，后续的进行*增量*备份。全量备份通常比增量备份工作量更大，因为涉及的数据量更多。此外，从大型归档中恢复单个文件可能非常繁琐。然而，在大多数情况下，从多个增量备份中恢复往往比从单个全量备份中恢复的工作量大得多，因为每个增量备份都需要先恢复其前一个备份。

相应地，恢复过程也可以进行优化，使得您始终备份自上次全量备份以来的所有内容；这样一来，备份的工作量会稍大，但永远不需要恢复超过一个全量备份和一个增量备份。良好的备份和恢复策略能够确定何时需要执行全量备份，以及何时应改为执行增量备份。

> **注意**
> 如果您将 Open Linux 系统用于商业用途，务必制定备份策略。制定正式的定期保存关键信息计划对于防止因数据丢失而导致的任何财务损失至关重要。一旦制定了备份策略，请务必坚持执行。

Linux 使用备份级别的概念来区分不同类型的备份。全量备份被指定为级别 0 备份。其他级别表示需要备份自前一级别以来已发生更改的文件。例如，您可能在周五执行级别 0 备份（全量），然后在周一执行级别 1，这将备份自级别 0 备份以来已更改的所有文件。在周二晚上，您会执行级别 2 备份，这将仅备份自级别 1 备份以来已更改的那些文件。如果您有六卷磁带，并希望每个工作日（周一至周五）都进行备份，您可以使用磁带 1 在周五进行全量备份，使用磁带 2–5 在周一至周四进行增量备份（级别 1、级别 2、级别 3 和级别 4），然后在下一个周五使用磁带 6 进行全量备份。随后，您将再次使用磁带 2–5 开始进行增量备份。在您拥有磁带 6 上的第二个全量备份之前，不要覆盖磁带 1。一旦成功将全量备份制作到磁带 6，磁带 1 就可以移至异地存储，以防存放磁带的建筑发生意外。当再次需要制作全量备份时，使用磁带 1，并将磁带 6 放在其原本的位置。这是一个非常简单的策略，接下来的两个策略也是如此。

下表展示了仅使用两卷磁带的简单备份策略：

| 星期   | 级别 |
| :----- | :--- |
| 周日   | 0    |
| 周一   | 1    |
| 周二   | 1    |
| 周三   | 1    |
| 周四   | 1    |
| 周五   | 1    |
| 周六   | 1    |

这种策略的优点在于，它只需要两套介质，并且恢复完整系统时只需恢复全量备份和最后一个增量备份即可。这种方法的一个缺点是，备份的大小会在一周中逐渐增加，甚至可能增长到需要额外介质的地步。以下展示了另一种使用七卷磁带的简单策略：

| 星期   | 级别 |
| :----- | :--- |
| 周一   | 0    |
| 周二   | 1    |
| 周三   | 2    |
| 周四   | 3    |
| 周五   | 4    |
| 周六   | 5    |
| 周日   | 6    |

这种策略的优点在于，每个备份相对快速且容量较小，因此易于管理。然而，这种方案的缺点是它使用七套介质，并且为了恢复完整系统，必须使用所有七套介质。

> **注意**
> 备份级别还可以用于将文件系统恢复时间降至最低。例如，如果您有许多级别编号递增的增量备份，您需要按顺序恢复所有备份才能重建整个文件系统。相反，您可以使用能够减少恢复文件系统所需备份数量的级别编号。为了最小化恢复所需的磁带数量，您可以为每个增量磁带使用较小的级别。然而，制作备份所需的时间会增加（每个备份都会复制自上次全量备份以来的所有内容）。

在决定采用哪种备份方案时，您需要了解文件系统的用途。在大多数情况下，您希望尽可能多地备份，经常更改的文件优先于很少更改的文件。某些文件，如可以轻松重新安装的软件，不一定需要包含在备份中。但该软件的系统配置文件应该包含在内；否则，您将需要重新配置它们。某些目录，如 /tmp 和 /proc，永远不需要备份，尤其是 /proc，因为它只包含内核自动生成的数据。一些灰色领域包括新闻组池、日志文件以及 /var 中的许多其他内容。您必须决定哪些内容对您来说是重要的。备份的明显目标是用户文件（/home）和系统配置文件（/etc），以及文件系统中其他分散的重要数据。

## 使用 tar 和 cpio 执行备份

使用以下命令可以轻松简单地实现全量备份：

```
tar -c /
```

这将把整个文件系统备份到默认设备 /dev/rmt0。

使用以下内容也可以实现相同的结果：

```
tar --create --file /dev/rmt0 /
```

此示例使用了 GNU tar 可用的长选项名称。大多数 UNIX 系统上的传统 tar 版本仅理解单字符选项。

### 注意

Open Linux 附带的 GNU tar 版本还有几个用于文件压缩和多卷备份操作的有用选项。如果使用 -Z 选项，归档将使用 gzip 进行压缩；如果使用 -z 选项，归档也将使用 gzip 压缩。此外，要执行多卷备份或恢复，请在命令行使用 -M 选项。例如，要在多张软盘上制作 /usr/src 的压缩多卷归档，请使用以下命令：

```
tar -cMzF /dev/fd0 /usr/src
```

软盘在开始备份前应该已经格式化。

制作备份后，您应该检查备份以确保其正确制作。毕竟，您不希望等到需要数据时才发现备份已损坏。为此，您需使用带有 -compare (-d, -diff) 选项的 tar：

```
tar -compare -verbose -f /dev/rmt0
```

可以使用 tar 的 -N ( --newer ) 选项进行增量备份。例如，要备份自 1999 年 7 月 8 日以来 /usr/src 中所有已修改的文件，请如下使用 tar：

```
tar -cN '8 jul 1999' -f /dev/rmt0 /usr/src -v
```

不幸的是，当文件的 inode 信息（如权限位或文件名）发生更改时，tar 不会注意到。这可以通过使用 find 并将当前文件系统状态与之前备份的文件列表进行比较来解决。

### 注意

许多用于在增量备份中使用 find 的脚本和程序可以在大多数 Linux FTP 站点上找到。一个好的查找地点是 ftp://ftp.sunsite.edu/pub/linux/utils/compression。

正如之前所述，使用 find 命令进行增量备份比简单的备份需要更多的工作。find 命令能够查找自特定日期以来已更改的所有文件，或比指定文件更新的文件。利用这些信息，执行增量备份变得容易。以下命令查找今天已修改的文件并备份这些文件，使用 tar 在 /dev/ftape 上创建归档。

```
tar -cf /dev/ftape `find / -mtime -1 ! -type d -print`
```

! -type d（不等于类型 d）表示如果对象是目录则不归档它。这样做是因为 tar 会跟随目录，除非目录内的所有内容都发生更改，否则您不想备份该目录。当然，find 命令也可以与 cpio 一起使用。以下命令执行与上述 tar 命令相同的任务：

```
find / -mtime -1 | cpio -o > /dev/ftape
```

如前所述，find 命令可以查找比指定文件更新的文件，这使得在成功备份后触碰（touch）一个文件变得容易。然后在下次备份时，您只需搜索比您触碰的文件更新的文件。要使用 cpio 和 find 搜索并归档比文件 /tmp/backup 更新的文件，请使用以下命令：

```
find / -newer /tmp/backup -print | cpio > /dev/rmt0
```

使用 tar 时，以下命令可达到相同结果：

```
tar -cf /dev/rmt0 `find / -newer /tmp/backup -print`
```
