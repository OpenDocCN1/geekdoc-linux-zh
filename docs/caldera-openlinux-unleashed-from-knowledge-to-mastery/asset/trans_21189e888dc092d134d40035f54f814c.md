

## 基于名称的虚拟主机

基于名称的虚拟主机允许你在同一个 IP 地址上运行多个主机。你需要将这些附加名称作为 CNAME 添加到你的 DNS 中，指向相应机器。当 HTTP 客户端（浏览器）向你的服务器请求文档时，它会在请求中发送一个变量，指示其请求文档的服务器名称。基于此变量，服务器确定应该从哪个虚拟主机提供内容。

**注意：**

一些旧版浏览器无法看到基于名称的虚拟主机，因为这是 HTTP 1.1 的一个特性，而这些旧版浏览器严格遵循 HTTP 1.0 标准。然而，许多其他旧版浏览器部分支持 HTTP 1.1，而这是大多数浏览器已支持一段时间的 HTTP 1.1 功能之一。

基于名称的虚拟主机比基于 IP 地址的虚拟主机只需要多一步额外操作。你首先需要指示哪个 IP 地址拥有多个 DNS 名称。这通过 `NameVirtualHost` 指令完成。

```
NameVirtualHost 192.168.204.24
```

然后你需要为该地址上的每个名称设置一个章节，配置该名称的设置。与基于 IP 的虚拟主机一样，你只需要设置那些需要不同配置的主机。你必须设置 `ServerName` 指令，因为这是区分不同主机的唯一依据：

```
<VirtualHost 192.168.204.24>
ServerName bugserver.database.com
ServerAlias bugserver
DocumentRoot /home/bugserver/htdocs
ScriptAlias /home/bugserver/cgi-bin
TransferLog /home/bugserver/logs/access_log
</VirtualHost>
```

```
<VirtualHost 192.168.204.24>
ServerName pts.database.com
ServerAlias pts
DocumentRoot /home/pts/htdocs
ScriptAlias /home/pts/cgi-bin
TransferLog /home/pts/logs/access_log
ErrorLog /home/pts/logs/error_log
</VirtualHost>
```

### 提示

如果你在内网或内部网络上托管网站，用户经常会使用机器的短名称而不是完全限定域名。例如，他们可能在浏览器位置栏中输入 `http://bugserver/index.html`，而不是 `http://bugserver.database.com/index.html`。在这种情况下，Apache 不会识别这两个地址应该指向同一个虚拟主机。你可以通过为 `bugserver` 和 `bugserver.database.com` 都设置 `VirtualHost` 指令来解决这个问题，但简单的解决方法是使用 `ServerAlias` 指令，该指令列出了机器的所有有效别名：

```
ServerAlias bugserver
```

### 警告

如果你计划在你的系统上运行大量虚拟主机，你应该考虑将所有记录的信息发送到标准的 Apache 日志文件，而不是发送到单独的文件。原因是你可能会达到系统的文件描述符限制，因为每个日志文件都会消耗一个文件描述符。Linux 2.2 中每个进程的系统限制为 1024，但由于 `ulimit` 限制，实际可能低得多。此问题的症状包括诸如“无法 fork”、“日志文件未写入信息”或“HTTP 请求响应缓慢”等错误消息。

## 日志记录

Apache 几乎可以提供你感兴趣的任何来自 Web 访问的信息。运行 Apache 服务器时会产生两个标准日志文件——`access_log` 和 `error_log`。除了 `error_log` 之外的所有日志（默认情况下，这就是 `access_log`）都是按照 `CustomLog` 和 `LogFormat` 指令指定的格式生成的。这些指令出现在你的 `httpd.conf` 文件中。

可以使用 `LogFormat` 指令定义新的日志格式：

```
LogFormat " %h %l %u %t "%r" %>s %b" common
```

通用日志格式是创建自定义日志格式的良好起点。请注意，大多数可用的日志分析工具都假设你使用的是通用日志格式或组合日志格式，这两种格式都在默认配置文件中定义。

以下变量可用于 *LogFormat* 语句：

- `%b` 发送的字节数，不包括 HTTP 头。
- `%f` 文件名。
- `%(VARIABLE)e` 环境变量 *VARIABLE* 的内容。
- `%h` 远程主机。（*注意：* 如果你有高流量，不要包含此变量，因为它会导致每次命中都进行反向 DNS 查找。）
- `%a` 远程 IP 地址。
- `%(HEADER)i` 发送到服务器的请求中 *HEADER:* 头行的内容。
- `%l` 远程登录名（如果提供了 *identd*）。
- `%(NOTE)n` 来自其他模块的注释 *NOTE* 的内容。
- `%(HEADER)o` 回复中 *HEADER:* 头行的内容。
- `%p` 提供请求的服务器规范端口。
- `%P` 处理请求的子进程 ID。
- `%r` 请求的第一行。
- `%s` 内部重定向请求的原始请求状态。对于最后一个请求的状态，使用 `*%s*`。
- `%t` 时间，采用通用日志格式时间格式。
- `%(format)t` 时间，形式由 *format* 给出，应采用 *strftime(3)* 格式。
- `%T` 处理请求所花的时间，以秒为单位。
- `%u` 来自 *auth* 的远程用户；如果返回状态（`%s`）为 401，则可能是虚假的。
- `%U` 请求的 URL 路径。
- `%v` 提供请求的服务器的规范服务器名称。

在每个变量中，你可以在变量前面添加一个条件，以决定是否显示该变量。如果不显示，则会显示 `·`。这些条件的形式是数值返回值的列表。例如，`%401u` 将显示 *REMOTE_USER* 的值，除非返回代码是 401。

然后可以使用 *CustomLog* 指令指定日志文件的位置和格式：

```
CustomLog /var/log/httpd/apache/access_log common
```

如果未指定为绝对路径，则假设日志文件的位置相对于 *ServerRoot*。

## CGI 和 SSI

在网站上提供动态内容最常见的方法是使用 CGI（通用网关接口）程序。CGI 是服务器进程（如生成动态文档的程序）与服务器本身之间通信的规范。服务器端包含（SSI）允许将 CGI 程序或其他程序的输出插入到现有的 HTML 页面中。

### CGI

默认情况下，你可以将任何 CGI 程序放在服务器的 *ScriptAlias* 目录中。这些程序必须由运行服务器的用户可执行。这通常意味着你需要将文件的模式更改为 755，这样除了用户以外没有人可以执行它们。

```
chmod 755 program.cgi
```

为了在 *ScriptAlias* 目录之外执行 CGI 程序，你需要为该目录启用 *ExecCGI* 选项。这可以在你的 access.conf 文件或该目录中的 .htaccess 文件中完成。

CGI 程序可以用任何语言编写。最流行的 CGI 编程语言是 Perl 和 C。由于本书不是关于 CGI 的书，你可能需要找一本好的 CGI 编程书，例如 *《CGI Programming with Perl, Second Edition》*。

为了测试你是否正确配置了 CGI，请尝试以下用 Perl 编写的 CGI 程序，它显示 HTTP 环境变量的值。

```
#!/usr/bin/perl
print "Content-type: text/html\n\n";
print "<html><head><title>Simple CGI program</title></head><body>\n";
for (keys %ENV) {
    print "$_ = $ENV{$_}<br>\n";
}
print "</body></html>\n";
```

如果你打算用 Perl 编写 CGI 程序，你可能需要查看随 Perl 捆绑的 CGI 模块。

### SSI

服务器端包含是直接写入 HTML 页面的指令，服务器在向 Web 客户端提供页面时解析这些指令。它们可用于包含其他文件、程序输出或环境变量。
