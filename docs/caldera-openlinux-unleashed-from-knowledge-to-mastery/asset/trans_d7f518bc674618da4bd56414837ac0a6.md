在开始备份过程之前，您总是希望先“触摸”该文件，因为这可确保下一次备份将包含在当前备份过程中发生变化的任何文件。这意味着，对于您使用的每个不同备份级别，您都必须使用不同的文件。

## 磁带上有什么？

当您拥有一个归档磁带时，您可能不太确定上面有什么内容。它可能包含较旧的文件，因为损坏的文件有时要过很长时间才能被注意到。也许它来自增量备份，在这种情况下，它只包含在上一次备份之后发生变化的那些文件。这是一个令人困惑的问题，但这里有一个解决方案。tar 和 cpio 都提供了为备份创建目录（TOC）的方法。创建备份目录最方便的时间是备份过程中。以下命令展示了如何使用 tar 和 cpio 来实现这一点：

```bash
tar -cv / > /tmp/backup/monday.TOC
```

```bash
find / -print | cpio -ov >/dev/rmt0 2>/tmp/backup/monday.TOC
```

**注意**

如果每次备份时都要创建一个目录（TOC），那么这将是一个极佳的文件，可与 `--newer` 命令配合使用，以进行增量备份。这样一来，每天您只需“触摸”上一次备份生成的目录文件即可。

cpio 备份会自动将列表发送到标准输出（stdout）；因此，此命令只是捕获输出并将其写入文件。`-v`（`-verbose`）选项也会将文件列表发送到标准输出。

## 使用 tar 和 cpio 恢复文件

**注意**

tar 始终以顺序方式读取备份卷，因此对于大容量卷，速度相当慢。您还必须记住，在使用磁带驱动器或其他顺序介质时，无法使用随机访问数据库技术。

备份文件是一件好事；它就像一份保险单。但当灾难发生时，您必须准备好恢复数据。使用 tar 或 cpio 恢复文件都非常简单。

有时，在恢复之前，查看归档内容以了解确切需要恢复什么内容可能是一个明智之举。为此，您需要使用带有 `--list`（`-t`）选项的 tar 和 cpio。例如，要查看软盘上 tar 归档的内容，您可以使用以下命令：

```bash
tar --list --file /dev/fd0
```

如果使用 cpio 执行相同操作，则可以使用以下命令：

```bash
cpio -it < /dev/fd0
```

既然您知道如何检查归档中的特定文件内容，就可以继续提取所需的文件了。若使用 tar 进行提取，请使用 `--extract`（`-x`）选项。例如，要从软盘上的 tar 归档中提取所有文件，并保持所有权限完好无损，您可以使用以下命令：

```bash
tar --extract -pvf /dev/fd0
```

如果使用 cpio 执行相同操作，则可以使用以下命令：

```bash
cpio -im < /dev/fd0
```

tar 中的 `-p` 选项表示保留文件权限，`v` 选项表示显示详细信息（列出所有正在恢复的文件），而 `f` 选项表示在 `/dev/fd0` 上查找（请记住，tar 的默认设备是 `/dev/rmt0`）。cpio 中的 `-m` 选项与 tar 中的 `-p` 选项作用相同，即保留原始文件的所有属性。

![](img/df365d352a104b50fea29e59a052de4d_577_0.png)

知道如何恢复整个归档很重要，但如果您只需要恢复单个损坏文件呢？恢复整个归档既不经济也不实用。幸运的是，使用 cpio 和 tar 都可以通过在命令行中指定要恢复的文件名来提取并恢复特定的文件和目录（包括它们的文件和子目录）。例如，假设 `/usr/src` 已归档到 /mnt/ftape，且您正准备重新编译内核，但其中一个文件已损坏。您需要恢复该损坏文件，在本例中为 /usr/src/linux/include/linux/hdreg.h。操作如下：

```bash
tar -xpvf /dev/ftape usr/src/linux/include/linux/hdreg.h
```

如果使用 cpio 执行相同操作：

```bash
cpio -im '*'hdreg.h' < /dev/ftape
```

> **注意**
> tar 并不总能正确处理已删除的文件。如果您从全量和增量备份中恢复文件系统，且在两者之间删除了一个文件，恢复后该被删除的文件将再次存在。如果该文件因包含不应再可用的敏感数据而被删除，这可能成为一个安全问题。

## 压缩备份

备份可能会占用大量空间，这可能反过来导致需要购买昂贵额外介质的需求。为了最大化您已有的媒体空间，可以使用压缩技术。有几种方法可以做到这一点。如前所述，您可以将 -z 或 -Z 选项与 tar 一起使用，以便 tar 将整个输出通过 gzip 或 compress 程序进行处理，然后再将其写入备份介质。

不幸的是，压缩备份可能会因压缩工作方式而引发问题。如果有一个位错误，其余所有压缩数据都将无法使用。一些备份程序具有内置的错误纠正功能，但没有方法能处理大量错误。这意味着如果使用 tar 的 -z 选项对备份进行压缩，单个错误就意味着整个备份丢失，因为备份必须尽可能可靠，所以这种压缩方法未必是好主意。

另一种方法是单独压缩每个文件。这意味着如果压缩失败，只会丢失一个文件，但其他所有文件都安然无恙。

压缩需要时间，这可能会导致备份程序无法以足够快的速度向磁带驱动器写入数据。可以通过缓冲输出来避免这种情况，既可以在备份程序内部支持的情况下内部缓冲，也可以使用另一个程序在外部进行缓冲。这通常只在较旧、较慢的计算机上才会成为问题。

## 使用 BRU-2000 执行备份

购买 COL 2.2 商业版本的 OpenLinux 用户会发现 CD-ROM 上附带了一份 Enhanced Software Technologies 的 BRU PE。事实上，如果您执行了通过 Lisa 或 Lizard 推荐的安装，那么它已经安装好了。BRU-PE 是更强大的 BRU-2000 商业版中的个人版。虽然只是个人版，但它仍然是一个相当先进的备份和恢复实用工具。事实上，它支持：

- 用于 KDE 的命令行或图形界面
- 备份过程中的错误检测
- 数据完整性验证
- 活动文件系统的备份和恢复
- 在线帮助
- 自动识别压缩文件
- 用于计划备份的背景模式

BRU 软件实际上是两个程序：用于从控制台执行备份的标准 BRU，以及用于在 KDE 下使用的 GUI 程序 xbru。BRU-PE 在您的 Linux 系统上使用多个文件和目录。大部分图形界面支持位于 `/opt/xbru` 下，而配置文件 `/etc/brutab` 用于配置各种备份设备。

如前所述，如果您通过 Lisa 或 Lizard 执行了推荐安装，BRU-PE 已经安装好了。如果没有，您将需要手动安装它。为此，请挂载您的 COL 2.2 CD。然后，以 `root` 身份进入 CD 上的 `/OpenLinux/install/RPMS` 目录并发出以下命令：

```bash
rpm -ivh BRU+.rpm
```

要对系统执行全量或增量备份，必须以用户 `root` 身份登录。若要使用图形界面版本，您可以通过多种方式启动程序。您可以通过选择 K 菜单、实用工具、BRU-PE 备份实用工具来启动，或者按 Alt+F2 然后在出现的命令行框中输入 `xbru`。此时，应该会出现图 23.1 中看到的对话框。
