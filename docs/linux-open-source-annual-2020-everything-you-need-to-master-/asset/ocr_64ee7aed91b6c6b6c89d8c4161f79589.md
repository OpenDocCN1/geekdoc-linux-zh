Wayland is just a protocol, so we can't apply the same notion of a display server to it. A graphical program wanting to render through Wayland does so by means of a display compositor. The reference compositor for Wayland is called Weston. Modern X desktops have display compositors too – they're integrated into window managers now on fully featured desktops (GNOME has Mutter, KDE Plasma has Kwin), and on bare-bones window managers like i3 you can add a compositor like Compton.

In our LXF243 interview with Collabora graphics veteran Daniel Stone, we learned that there are two approaches to implementing a Wayland compositor. Either you have a single unified environment that handles everything (menus, docks, desktop add-ons), or you do things piecemeal: a small compositor program, with auxiliary utilities for handling everything else. We'll look at both approaches here.

There are all sorts of reasons why you might not be able to start a Wayland session. Most commonly, it's because you're using the proprietary Nvidia driver – although this won't be the case with a fresh install of Fedora, since Fedora doesn't include any proprietary blobs. Recent versions of GNOME and KDE, from Plasma 5.15 on, actually do support the driver's EGLStream APIs (all the other drivers use GBM), but whether or not it works is going to depend a lot on your particular hardware and driver version. One solution is to use the free Nouveau driver, although this is not a good idea if you like serious gaming.
