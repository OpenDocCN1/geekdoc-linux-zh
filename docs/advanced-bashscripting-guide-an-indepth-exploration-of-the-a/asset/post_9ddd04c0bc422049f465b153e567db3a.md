Example 11–6. Letting let do some arithmetic.

```bash
#!/bin/bash

echo
let a=11      # Same as 'a=11'
let a=a+5     # Equivalent to let 'a = a + 5'
              # (double quotes and spaces make it more readable)
echo 11 + 5   $a

let a <<=3    # Equivalent to let 'a = << 3'
echo "$a"    # (16) left-shifted 3 places $a

let a /=4     # Equivalent to let 'a = a / 4'
echo 128 / 4  $a

let a -=5     # Equivalent to let 'a = a - 5'
echo 32 - 5   $a

let a *=10    # Equivalent to let 'a = a * 10'
echo 27 * 10  $a

let a %=8      # Equivalent to let 'a = a % 8'
echo 270 modulo 8 = $a (270 / 8 = 33, remainder $a)

echo

exit 0
```

# Example 11–7. Showing the effect of eval

```bash
#!/bin/bash

y='eval ls -1'  # Similar to y='ls -1'
echo $y        # But linefeeds removed because 'echoed' variable is unquoted
echo
echo "$y"     # Linefeeds preserved when variable is quoted

echo; echo

y=eval df       # Similar to y=df
echo $y       # But linefeeds removed.

# When LF's not preserved, it may make it easier to parse output,
# using utilities such as "awk".

exit 0
```

# Example 11–9. Version of "rot13"

```bash
#!/bin/bash
# A version of "rot13" using 'eval'.
# Compare to "rot13.sh" example.

setvar_rot13() {
    "rot13" scrambling
    local varname=$1 value=$2
    eval varname=$(echo "$value" | tr a-z n-a-m)
}

setvar_rot_13 var "foobar"      # Run "foobar" through rot13.
echo $var                      # sbone

echo $var | tr a-z n-a-m      # Back to original variable.

# This example by Stephane Chazelais.

exit 0
```

The eval command can be risky, and normally be avoided when there exists reasonable alternative. An eval $COMMANDS executes the contents of COMMANDS, which may contain unpleasant እንደሚ as rm -rf *. Running an eval on unfamiliar code written by persons is knowing dangerously.

set

The set command changes the value of internal script variables. This one is used to help determine the behavior of the script. Another application for it is to reset positional parameters that a script sees as the result of a command (set command). The script can then parse the fields of the command output.

# Example 11–10. Using set with positional parameters

# Advanced Bash–Scripting Guide

```bash
#!/bin/bash

# script "set-test"

# Invoke this script with three command line parameters,
# for example, ./set-test one two three.

echo "Positional parameters before set:"
echo "Command-line argument = $1"
echo "Command-line argument = $2"
echo "Command-line argument = $3"

echo "Positional parameters after set:"
# $1, $2, $3 reinitialized to result of command
echo "Field #1 = $1"
echo "Field #2 = $2"
echo "Field #3 = $3"

exit 0
```

See also Example 10–2. The unset command deletes a variable, effectively setting it to null. Note that this command does not affect positional parameters.

```bash
unset PATH
echo $PATH
```

# Example 11–11. "unsetting" a variable

```bash
#!/bin/bash
# unset.sh
variable=hello # Initialized
echo "variable = $variable"
unset variable # Unset.
echo "variable = $variable" # variable is null.

exit 0
```

The export command makes available to all child processes of the running script or shell. Unfortunately, there is no way to export variables back to the parent process that called or invoked it. One important use of export command is in startup files, to initialize and make accessible to subsequent processes.

# Example 11–12. Using export to pass a variable to an embedded awk script

```bash
#!/bin/bash
# 'getopts' yet another version of "gettotal" script (gettotal.sh)
# that adds a specified column number in target file.
# This uses the environment to pass variable to 'awk'.

ARGS=2
if [ $# -ne "$ARGS" ]; then # Check for proper number of args.
    echo "Usage: $0"
    exit 1
fi

filename=$1
column_number=$2

# Same as original script, up to this point

export column_number
# Export column number to environment, so it's available for retrieval.

# Begin awk script.
awk '{ total += $ENV["column_number"] } END { print total }' $filename
# End awk script.

# Thanks, Stephanie Chazelas.

exit 0
```

declare, typeset

The declare and types commands specify and/or restrict properties of variables.

readonly

Same as declare -r, sets a variable as read-only, or in effect, as a constant. Attempts to change the variable fail with an error message. This is the shell analog of the C language const qualifier.

getopts

This powerful tools parse command line arguments to the script. This is the bash analog of getopt function familiar to C programmers. It permits passing and concatenating multiple options and associated arguments to a script (example scriptname -abc -e /usr/local).

The getopt constructs two implicit variables. $OPTIND is the option (Index) and $OPTARG (OptionArgument) the (optional) argument attached to an option. A colon following the option name in the declaration tags that it identifies as having an associated argument.

A gets usually comes packaged in a while loop, which processes the options and arguments one at a time, decrements the implicit $OPTIND variable to step to the next.

1. The arguments must be passed from the command line to script preceded by a minus (-) or a plus (+). It is the prefixed or + that lets getopt recognize command–line arguments as options. In fact, getopt will not process arguments without the prefixed - or +, will terminate option processing at the first argument encountered lacking them.
2. The getopt differs slightly from the standard while loop, in it lacks condition brackets.
3. The gets constructs replaces the obsolete getopt command.

```bash
while getopts ":abc:fg" opt
# Initial declaration.
# a, b, c, d, e, f, and g are the options (flags) expected.
# The : - after option 'e' shows it will have an argument passed with it.
do
  case $opt in
    a) Do something with variable 'a'.
    b) Do something with variable 'b'.
    e) Do something with 'e', and also with $OPTARG
        # which is the associated argument passed with option 'e'.
    g) Do something with variable 'g'.
  esac
done
shift $((OPTIND - 1))
# Move argument pointer to next.

# All this is not nearly as complicated as it looks <grin>.
```
