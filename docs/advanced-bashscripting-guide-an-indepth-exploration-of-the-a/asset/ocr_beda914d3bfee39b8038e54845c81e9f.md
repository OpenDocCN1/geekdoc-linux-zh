Directory changes made in a subshell do not carry over to the parent shell.

# Example 20–2. List User Profiles

```
#!/bin/bash
# allprofs.sh: print all user profiles

# This script written by Heiner Steven, modified by the document author.

FILE=.bashrc # File containing user profile,
#+ was ".profile" in original script.

for home in awk -F: '$(print $6)' /etc/passwd
do
    [ -d "$home"] || continue # If no home directory, go to next.
    [ -r "$home"] || continue # If not readable, go to next.
    cd $home; [ -e $FILE ] && $FILE
done

# When script terminates, there is no need to 'cd' back to original directory,
+# because 'cd $home' takes place in a subshell.

exit 0
```

A subshell may be used to set up a "dedicated environment" for a command group.

```
COMMAND1
COMMAND2
COMMAND3
(
IFS=-/bin
PATH=-C
unset TERMINFO
set -C
shift 5
COMMAND4
COMMAND5
exit 3 # Only exits the subshell.
```

# The parent shell has not been affected, and the environment is preserved.

COMMAND6
COMMAND7

One application of this is testing whether a variable is defined.

```
if (set -u ; $variable) 2 /dev/null
then
echo "Variable is set."
fi
```

```
# Could also be written
[[ $(variable-x) != $(variable-y) != != y ]]
# or
[[ $(variable-x) != x$variable ]]
# or
[[ $(variable+x) = x ]]
```

Another application is checking for a lock file:

```
if (set -C; : > lock_file) 2 > /dev/null
```
