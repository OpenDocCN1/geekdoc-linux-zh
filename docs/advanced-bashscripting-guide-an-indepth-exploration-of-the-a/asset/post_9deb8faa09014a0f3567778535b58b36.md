## string comparison

=
is equal to

```
if [ "$a" = "$b" ]
```

==
is equal to

```
if [ "$a" == "$b" ]
```
This is a synonym for =.

```
[[ $a == z* ]] # true if $a starts with "z" (pattern matching)
[[ $a == z* ]] # true if $a is equal to z*

[ $a == z* ]   # file globbing and word splitting take place
[ "$a" == z* ] # true if $a is equal to z*
```

- !=
is not equal to

```
if [ "$a" != "$b" ]
```
This operator uses pattern matching within a [...] construct.

- <
is less than, in ASCII alphabetical order

```
if [ "$a" < "$b" ]
```
```
if [ "$a" \< "$b" ]
```
Note that the "<" needs to be escaped within a [ ] construct.

- >
is greater than, in ASCII alphabetical order

```
if [ "$a" > "$b" ]
```
```
if [ "$a" \> "$b" ]
```
Note that the ">" needs to be escaped within a [ ] construct.
See Example 26–4 for an application of this comparison operator.

- -z
string is "null", that is, has zero length

- -n
string is not "null".

The -n test absolutely requires that the string be quoted within the test brackets. Using an unquoted string like -z, or even just the unquoted string alone within test brackets (Example 7–5) normally works, however, this is an unsafe practice. Always quote a tested string.

### Example 7–4. arithmetic and string comparisons

```bash
#!/bin/bash

a=4
b=5

# Here "a" and "b" can be treated either as integers or strings.
# There is some blurring between the arithmetic and string comparisons,
# since Bash variables are not strongly typed.

# Bash permits integer operations and comparisons on variables
# whose value consists of all-integer characters.
# Caution advised.

if [ "$a" -ne "$b" ]
then
    echo "$a is not equal to $b"
    echo "(arithmetic comparison)"
fi

if [ "$a" != "$b" ]
then
    echo "$a is not equal to $b."
    echo "(string comparison)"
fi
```
In this instance, both "-ne" and "!=" work.

### Example 7–5. whether a string is null

```bash
#!/bin/bash
# str-test.sh: Testing null strings and unquoted strings,
# but not empty strings and...

# Using if [ ... ]
# If a string has not been initialized, has no value.
# This state is called "null" (not same as zero).
if [ -n "$1" ]
then
    echo "$1 is not null."
else
    echo "$1 is null."
fi
# Wrong result.
# Shows $1 as not null, although it was not initialized.
```

### Example 7–6. zmost

```bash
#!/bin/bash
# View zipped files with 'most'

NOARGS=65
NOTFOUND=66
NOTZIP=67

if [ $# -eq 0 ]; # same effect as: if -z "$1" ]
  # $1 can exist, but be empty
then
  echo "Usage: basename $0 filename" >&2
  # Error message to stderr
  exit NOARGS
  # Returns 65 as exit status of script (error code).
fi

filename=$1

if [ ! -f "$filename" ]; # Quoting $filename allows for possible spaces.
then
  echo "File $filename not found!" >&2
  # Error message to stderr
  exit NOTFOUND
fi

if [ "${filename#*.}" != "gz" ]; # Using bracket in variable substitution.
then
  echo "File $1 is not a zipped file!"
  exit NOTZIP
fi

zcat $1 | most
```
# Uses the file viewer 'most' (similar to 'less').
# Later versions of 'most' have file decompression capabilities.
# May substitute 'more' or 'less', if desired.

exit $? # Script returns exit status of pipe.
# Actually returns $? unnecessary, as the script will, in any case
# return the exit status of the last command executed.

## compound comparison

- -a
logical and

expl1 -a exp2 returns true if both expl1 and expl2 are true.

- -o
logical or

expl1 -o exp2 returns true if either expl1 or expl2 are true.

These are similar to the Bash comparison operators && || used within double brackets.

```bash
[[ condition1 && condition2 ]]
The -and -a operators work with the test command or occur within single brackets.
if [ "$exp1" -a "$exp2" ]
```

## 7.4. Nested if/then Condition Tests

Condition tests using the if/then construct may be nested. The net result is identical to using the && || comparison operator above.

```bash
if [ condition1 ]
then
  if [ condition2 ]
  then
    do-something # But only if "condition1" and "condition2" valid.
  fi
fi
```
See Example 35–4 for an example of nested if/then condition tests.

## 7.5. Testing Your Knowledge of Tests

The systemwide xinitrc file can be used to launch the X server. This file contains a number of if/then tests, as the following excerpt shows.

```bash
if -f $HOME/.Xclients ]; then
  exec $HOME/.Xclients
elif [ -f /etc/X11/xinit/Xclients ]; then
  exec /etc/X11/xinit/Xclients
else
  # failsafe settings. Although we provide fallbacks in Xclients as well it can't hurt.
  xclock -geometry 100x500+5 &
  xterm -geometry 800x50+150 &
  if [ -f /usr/bin/netscape -a f /usr/share/doc/HTML/index.html ]; then
    netscape /usr/share/doc/HTML/index.html &
  fi
fi
```
Explain the "test" constructs in the above excerpt, then examine the entire file, /etc/X11/xinitrc, and analyze the if/then test constructs. You may need to refer to the discussions of grep, sed, and regular expressions.
