# Advanced Bash–Scripting Guide

This powerful tools parse command line arguments to the script. This is the bash analog of getopt library function familiar to C programmers. It permits passing and concatenating multiple options [25] and associated arguments to a script (example scriptname -abc -e /usr/local).

The getopt constructs two implicit variables. $OPTIND is the option (Index) and $OPTARG (OptionArgument) the (optional) argument attached to an option. A colon following the option name in the declaration tags that it identifies as having an associated argument.

A gets usually comes packaged in a while loop, which processes the options and arguments one at a time, decrements the implicit $OPTIND variable to step to the next.

![](bbox=[0.31, 0.273, 0.342, 0.29])

+   1. The arguments must be passed from the command line to script preceded by a minus (-) or a plus (+). It is the prefixed or + that lets getopt recognize command–line arguments as options. In fact, getopt will not process arguments without the prefixed - or +, and will terminate option processing at the first argument encountered lacking them.
2. The getopt differs slightly from the standard while loop, in it lacks condition brackets.
3. The gets constructs replaces the obsolete getopt command.

```
while gets ":abc:fg" Option
# Initial declaration.
# a, b, c, d, e, f, and g are the options (flags) expected.
# The : - after option 'e' shows it will have an argument passed with it.
do
case $getopt in
  a) Do something with variable 'a'.
  b) Do something with variable 'b'.

  e) Do something with 'e', and also with $OPTARG
      # which is the associated argument passed with option 'e'.

  g) Do something with variable 'g'.
esac
done
shift $((OPTIND - 1))
# Move argument pointer to next.

# All this is not nearly as complicated as it looks <grin>.
```
