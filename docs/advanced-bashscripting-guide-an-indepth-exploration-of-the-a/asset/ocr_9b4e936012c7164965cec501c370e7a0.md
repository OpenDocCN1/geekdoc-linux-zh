# Advanced Bash–Scripting Guide

The escape also provides a means of writing a multi-line command. Normally, each separate line constitutes a different command, but an escape at the end of a line escapes the newline character, and the command continues to the next line.

```
(cd /source/directory && tar cf - . ) | \
cd /dest/directory && tar xpvf -)
# Repeating Alex Cox's tree copy command,
# buf split into two lines for increased legibility.

# As an alternative:
tar cf -C /source/directory |
tar xpvf -C /dest/directory
# See note below.
(Thanks, Stephane Chazelas.)
```

If a script ends with a |, a pipe character then a \ an escape, is not strictly necessary. It is however, good programming practice to always escape the end of a line of code that continues to the following line.

![](bbox=[0.297, 0.351, 0.335, 0.363])

```
echo "foo
bar"
#foo
#bar
echo
echo 'foo
bar' # No difference yet.
#foo
#bar
echo
echo foo\
bar # Newline escaped.
#foobar
echo
echo "foo\
bar" # Same here, as \ still interpreted as escape within weak quotes.
#foobar
echo
echo 'foo\
bar' # Escape character \ taken literally because of strong quoting.
#foor\n#bar
```
