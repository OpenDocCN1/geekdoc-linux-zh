Both jot and seq come in hand in a for loop.

# Example 12–34. Using seq to generate loop arguments

```
#!/bin/bash

for a `seq 80` # or for a in $( seq 80 )
# Same as for a in 1 2 3 4 5 ... 80 (saves typing!).
# May also use 'jot' (if present on system).
do
echo -n "a"
done
# Example of using the output of a command to generate
# the [list] in a "for" loop.

echo;

COUNT=80 # Yes, 'seq' may also take a replaceable parameter.

for a in 'seq $COUNT' or for a in $( seq $COUNT)
do
echo -n "a"
done
echo

exit 0
```

The run–parts [33] executes all the scripts in a target directory, sequentially in ASCII–sorted filename order. Of course, the scripts have no execution permission.

The crond daemon invokes run–parts to run the scripts in the /etc/cron. * directories.

In its default behavior the yes command feeds a continuous stream of the character followed by a line feed to stdout. A control–c terminates it. A different output string may be specified, as yes different string, which would continually output string to stdout. One might well ask the purpose of this. From the command line or in a script, the output of yes can be redirected or piped into a program expecting user input. In effect, this becomes a sort of poor man's version of expect.
