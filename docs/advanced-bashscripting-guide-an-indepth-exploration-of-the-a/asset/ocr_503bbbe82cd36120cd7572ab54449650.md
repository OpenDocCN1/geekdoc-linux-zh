# These examples supplied by Stephen Chazelas.

Elements of a string assigned to a variable may be escaped, but the escape character may not be assigned to a variable.

```
variable=\necho "$Variable"
# Will not work - gives an error message:
# test.sh : command not found
# A "naked" escape cannot safely be assigned to a variable.
#
# What actually happens here is that the "\" escapes the newline and
#++ the effect is
variable="$Variable"\invalid variable assignment
```

```
variable=\n23skido
echo "$Variable"
# 23skido
# This works, the second line
#++ is a valid variable assignment.
```

```
variable=\\ escape followed by space
echo "$Variable"
# space
```

```
variable=\\necho "$Variable"
# \
```

```
variable=\\\\\
echo "$Variable"
# Will not work - gives an error message:
# test.sh : command not found
#
# First escape escapes second one, but the third one is left "naked",
#++ with same result as first instance, above.
```

```
variable=\\\\\
echo "$Variable"
# \\
# Second and fourth escapes escaped.
# This is o.k.
```

Escaping a space word splitting in a command's argument

```
file_list="/bin/cat /bin/gzip /bin/more /usr/bin/less /usr/bin/emacs-20.7"
# List of files as argument(s) to a command.
```

```
# Add two files to the list, and list all.
ls -l /usr/X11R/bin/xsetroot /sbin/dump $file_list
```

```
echo

# What happens if we escape a couple of spaces?
ls -1 /usr/X11R/bin/xsetroot /sbin/dump $file_list
# Error: the first three files concatenated into a single argument to 'ls -1'
```
