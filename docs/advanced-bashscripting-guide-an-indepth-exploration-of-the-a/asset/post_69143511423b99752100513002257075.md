
# Advanced Bash–Scripting Guide

By convention, a command reads its input from fd 0 (stdin), prints normal output to fd 1 (stdout), and error output to fd 2 (stderr). If one of these fds is not open, you may encounter problems:

```bash
bash cat /etc/passwd >&-
cat: standard output: bad file descriptor
```

For example, when xterm runs, it first initializes itself. Before running the user's shell, xterm opens the terminal device (/dev/pts/n or something similar) three times.

At this point, Bash inherits these three file descriptors, and command (child process) by Bash inherits them in turn, except when you redirect the command. Redirection means reassining one of the file descriptors to another (by a pipe, or anything similar). File descriptors may be reassigned locally for a command, a subshell, a while or if for loop or globally, for the remainder of the shell (using exec).

ls > /dev/null means running ls with fd 1 connected to /dev/null.

```bash
bash exec 2>/dev/null
bash lsof -a p -- -d0,1
COMMAND PID USER FD TYPE DEVICE SIZE NAME
lsof 3621 0u CH 136,1 3 /dev/pts/1
lsof 3620 1u CH 136,1 3 /dev/pts/1
lsof 3620 2w CH 136,1 120 /dev/null
```

```bash
bash bash -c 'lsof -a p -- -d0,1,2' | cat
COMMAND PID USER FD TYPE DEVICE SIZE NAME
lsof 3709 0u CH 136,1 3 /dev/pts/1
lsof 3709 1u CH 136,1 3 /dev/pts/1
lsof 3709 2w CH 136,1 3 /dev/pts/1
```

```bash
bash echo "$(lsof -a p -- -d0,1,2)" >&6
COMMAND PID USER FD TYPE DEVICE SIZE NAME
lsof 4226 0u CH 136,1 3 /dev/pts/1
lsof 4226 1w FIFO 0,0 7520 pipe
lsof 4226 2w FIFO 0,0 7520 pipe
```

This works for types of redirection.

## Appendix E. Localization

Localization is an undocumented Bash feature.

A localized shell script will export its text in the language defined as the system's locale. A Linux user in Berlin, Germany, would get script output in German, whereas his cousin in Berlin, Maryland, would get output from the same script in English.

To create a localized script, use the following template to write all messages to the user (error messages, prompts, etc.).

```bash
#!/bin/bash
# localized.sh

E_CERROR=65

error() {
  printf "%s" $@ >&2
  exit $E_CERROR
}
```

```bash
cd $var || error "Can't cd to %s." "$var"
read -p $"Enter the value: " var
#
```

```bash
bash -D localized.sh
"Can't cd to %s."
"Enter the value: "
```

This lists all localized text. The -D option lists double-quoted strings prefixed by $ without executing the script.

```bash
bash --dump-po localized.sh
#: a:6
msgid "Can't cd to %s."
msgstr ""
#: a:7
msgid "Enter the value: "
msgstr ""
```

The --dump-po option resembles the -D option, but uses gettext "po" format. Now, build a .po file for each language that the script will be translated into, specifying it. As example:

```po
fr
#: a:6
msgid "Can't cd to %s."
msgstr "Impossible de positionner le répertoire %s."
#: a:7
msgid "Enter the value: "
msgstr "Entrez la valeur :"
```

Then run msgfmt.

```bash
msgfmt -o localized.sh.mo fr.po
```

Place the resulting localized.sh.mo file in /local/share/locale/fr/LC_MESSAGES directory, and at the beginning of the script, insert the lines:

```bash
TEXTDOMAIN=/local/share/locale/localized.sh
```

If a user on a French system runs the script, she will get French messages. With older versions of Bash or other shells, localization requires gettext using the -D option. In this case the script becomes:

```bash
#!/bin/bash
# localized.sh
E_CERROR=65

error() {
    local format=$1
    shift
    printf "$(gettext -s "$format")" "$@" >&2
    exit $E_CERROR
}

cd $var || error "Can't cd to %s." "$var"
read -p "$(gettext -s "Enter the value: ")" var
```

The TEXTDOMAINDIR variables need to be exported to the environment. This appendix written by Stephane Chazelas.

## Appendix F. History Commands

The shell provides command-line tools for editing and manipulating a user's history. This is primarily a convenience, means of saving keystrokes.

Bash history commands:

- 1. history
- 2. fc

```bash
$ history
mount /mnt/cdrom
cd /mnt/cdrom
ls
```

Internal variables associated with Bash history commands:

- 1. $HISTCMD
- 2. $HISTCONTROL
- 3. $HISTIGNORE
- 4. $HISTFILE
- 5. $HISTFILESIZE
- 6. $HISTSIZE
- 7. !!
- 8. !#
- 9. !N
- 10. !-N
- 11. !-STRING
- 12. !STRING
- 13. ?!

Unfortunately, the Bash history tools find no use in scripting.

```bash
#!/bin/bash
# history.sh
# Attempt to use 'history' command in a script.

history

# Script produces no output.
# History commands do not work within a script.

```bash
./history.sh
```

## Appendix G. A Sample .bashrc File

The ~/.bashrc file determines the behavior of interactive shells. A good look at this file can lead to a better understanding of Bash. Emmanuel Rouat contributed the very elaborate .bashrc file, written for a Linux system. He welcomes reader feedback on it.

Study the file carefully, and feel free to reuse code snippets and functions from it in your own .bashrc file or in your scripts.
