
## Chapter 3. Exit and Exit Status

...there are dark corners in the Bourne shell, and people use all of them.

Bret Ramey

The exit command may be used to terminate a script, just as in a C program. It can also return a value, which is available to the script's parent process.

Every command returns an exit status (sometimes referred to as a return status). A successful command returns a 0, while an unsuccessful one returns a non–zero value that usually may be interpreted as an error code. Well-behaved UNIX commands, programs, and utilities return a 0 exit code upon completion, though there are some exceptions.

Likewise, functions within a script and the script itself return an exit status. The last command executed in the function or script determines the exit status. Within a script, an exit may be used to deliver an nnn exit status to the shell (nnn must be a decimal number in the 0–255 range).

![](img/1ce1edffaa36e4f698a85430e71c6d3b_12_0.png)

When a script ends with an exit that has no parameter, the exit status of the script is the exit status of the last command executed in the script (not counting the exit).

$ reads the exit status of the last command executed. After a function, $ gives the exit status of the last command executed. In Bash's way of giving functions a “return value”. After a script terminates, a $ from the command line gives the exit status of the script, the last command executed in the script, which is by convention, 0 on success or an integer in the range 1–255 on error.

### Example 3–1. exit / exit status

```bash
#!/bin/bash
echo hello
echo $ # Exit status 0 returned because command executed successfully.
lsdkf # Unrecognized command.
echo $ # Non-zero exit status returned because command failed to execute.
echo
exit 113 # Will return 113 to shell.
# To verify this, type "echo $?" after script terminates.

# By convention, an 'exit 0' indicates success,
# while a non-zero exit value means an error or anomalous condition.
```

$ is especially useful for testing the result of a command in a script (Example 12–8 and Example 12–13).

![](img/1ce1edffaa36e4f698a85430e71c6d3b_12_1.png)

The logical "not" qualifier reverses the outcome of a test or command, and this affects its [exit status](exit status).

### Example 3–2. Negating a condition using !

```bash
true # the "true" builtin. 
echo "exit status of \"true\" = $?  # 0

! true
echo "exit status of !true\" = $?  # 1
# Note that the "!" needs a space.
# !true leads to a "command not found" error
# Thanks, S.C.
```

Certain exit status codes have [reserved meanings](reserved meanings) and should not be user-specified in a script.

## Chapter 4. Special Characters

Special Characters Found In Scripts and Elsewhere

**Comments.** Lines beginning with a # (with the exception of #!) are comments.

```bash
# This line is a comment.
```

Comments may also occur at the end of a command.

```bash
echo "A comment will follow." # Comment here.
```

Comments may also follow whitespace at the beginning of a line.

```bash
# A tab precedes this comment.
```

![](img/1ce1edffaa36e4f698a85430e71c6d3b_14_0.png)

A command may not follow a comment on the same line. There is no method of terminating the same line, in order for "live code" to begin on the line. Use a new line for the next command.

Of course, an escaped # in an echo statement does not begin a comment. Likewise, a # appears in certain parameter substitution constructs and in numerical constant expressions.

```bash
echo "The # does not begin a comment."
echo 'The # does not begin a comment.'
echo The # here does not begin a comment.
echo The # here begins a comment.
```

```bash
echo ${PATH*:} # Parameter substitution, not a comment.
echo $((2*101011)) # Base conversion, not a comment.
```

Thanks, S.C.

The standard quoting and escape characters ("\") escape the #.

Certain pattern matching operations also use the #.

**Command separator.** [Semicolon] Permits putting two or more commands on the same line.

```bash
echo hello; echo there
```

Note that ":" sometimes needs to be escaped.

Terminator in a case option.

```bash
case "$variable" in
abc)    echo "$variable = abc";;;
xyz)    echo "$variable = xyz";;;
esac
```

"dot" command. [period] Equivalent to source Example 1–14. This is a builtin. In a different context, as part of a regular expression, "dot" matches single character. In another context, a dot is the filename prefix of a "hidden" file, a file that ls normally show.

```bash
$ touch .hidden-file
$ ls -al
total 10
--rw-r-- 1 user group 0 Jul 18 22 .addressfile
--rw-r-- 1 user group 0 May 25 13 .addressbook
--rw-r-- 1 user group 0 Dec 17 00 .addressbook.bak
--rw-r-- 1 user group 0 Aug 29 54 .hidden-file
drwxr-xr-x 3 user group 4096 Jul 18 22 ..
drwx------ 2 user group 0 May 25 13 .
--rw-r-- 1 user group 0 Dec 17 00 .addressbook.bak
drwxr-xr-x 3 user group 4096 Jul 18 22 .addressfile
--rw-r-- 1 user group 0 Aug 29 54 .hidden-file
```

partial quoting. [double quote] '"' preserves most of special characters within STRING. See Chapter 6.

full quoting. [single quote] ''' preserves all special characters within STRING. This is a stronger form of quoting using Chapter 6.

comma operator. The comma operator links together a series of arithmetic operations. All are evaluated, but only the last one is assigned.

```bash
let a = 9, b = 10
```

escape. [backslash] '\' escapes the character X. This has the effect of quoting X. '\'' may be used to quote '\'' literally.

**Filename separator.** [forward slash] '/' separates the components of a filename (as /home/projects/). This is also the division operator.

**command substitution.** [backticks] `command` makes the output of `command` available for setting a variable. This is also known as backquotes.

**null command.** [colon] ':' is the shell equivalent of NOP. The ":" command is a Bash builtin, and its exit status (0).

```bash
echo $? # 0
```

Endless loop:

```bash
while true
do
  operation-1
  operation-2
  ...
  operation-n
done
```

Placeholder in if/then test:

```bash
if condition
then
    : # Do nothing
else
  take-some-action
fi
```

Provide a placeholder where a binary is expected, see Example 8–2 and default parameters.

```bash
$ $(username=whoami) without the leading gives an error
# $(username=whoami) unless "username" is a command or builtin...
```

Evaluate string of variables using parameter substitution (as in Example 9–12).

```bash
${HOSTNAME} ${USER} ${MAIL}
# Prints error message if one or more of essential environmental variables not set.
```

Variable expansion. In combination with the > operator, truncates a file to zero length, without changing its. If the file did not previously exist, it creates it.

```bash
> data.xxx # File "data.xxx" now empty.
# Same effect as cat /dev/null >data.xxx
```

In combination with the >> operator, updates a file access/modification time. This is equivalent to touch.![](img/1ce1edffaa36e4f698a85430e71c6d3b_17_0.png)

This applies to regular files, pipes, symlinks, and special files.

May be used to begin a comment line, although this is not recommended. Using # for a comment turns off checking for the remainder of that line, so anything may be in a comment. However, this is not the case with :

```bash
> : This is a comment that generates an error, ( if $ x -eq 3 ).
```

The ":" serves as a field separator, in /etc/passwd, and in the PATH variable.

```bash
echo $PATH
/usr/local/bin:/usr/bin:/usr/X11R/bin:/bin:/usr/sbin:/sbin:/usr/games
```

reverse (or negate) the sense of a test or exit status. The ! operator inverts the exit status of the command to it is applied (Example 3–2) meaning a test operator. This can change the sense of "equal" (=) to "not-equal" (!). The ! operator is a Bash keyword.

In a different context, the ! also appears in indirect variable references.

![](img/1ce1edffaa36e4f698a85430e71c6d3b_17_1.png)

wild card. [asterisk] The * character serves as a "wild card" for filename expansion in globbing, as well as representing any number (or zero) characters in a regular expression.

A double asterisk, **, is the exponentiation operator.
