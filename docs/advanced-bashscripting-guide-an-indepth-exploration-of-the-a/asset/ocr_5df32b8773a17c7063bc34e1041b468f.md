The - option to mark a document limit string (<<LimitString) suppresses tabs (but not spaces) in the output. This may be useful in making a script more readable.

# Example 17–4. Multi-line message, with tabs suppressed

```
#!/bin/bash
# Same as previous example, but...

# The - option to here a document <<-
# suppresses tabs in the body of the document, but *not* spaces.

cat <<-ENDMESSAGE
This is line 1 of the message.
This is line 2 of the message.
This is line 3 of the message.
This is line 4 of the message.
This is the last line of the message.
ENDMESSAGE
# The output of the script will be flushed left.
# Leading tab in each line will not show.

# Above 5 lines of "message" preceded by a tab, not spaces.
# Spaces not affected by <<-

exit 0
```

A document supports parameter and command substitution. It is therefore possible to pass different parameters to the body of the document, changing its output accordingly.

# Example 17–5. Here document with parameter substitution

```
#!/bin/bash
# Another 'cat' here document, using parameter substitution.

# Try it with no command line parameters, ./script
# Try it with one command line parameter, ./script Mortimer
# Try it with one two-word quoted command line parameter,
# ./script "Mortimer Jones"

CMDLINEPARAM=1    # Expect at least command line parameter.

if [ $ -ge $CMDLINEPARAM ];
then
  NAME=$1
  # then just take the first.
else
  NAME="John Doe" # Default, if no command line parameter.
fi

RESPONDENT="the author of this fine script"
```
