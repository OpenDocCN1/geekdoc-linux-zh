# Example 10-26. Simple string matching

```bash
#!/bin/bash
# match-string.sh: simple string matching

match_string ()
{
MATCH=0
NOMATCH=1
PARAMS=$2 # Function requires 2 arguments
BAD_PARAMS=$1

  [ $# -eq $PARAMS ] || return $BAD_PARAMS

  case "$1" in
  "$2") return $MATCH;
  *) return $NOMATCH;
  esac
}

echo $?
```

# Example 10–27. Checking for alphabetic input

```bash
#!/bin/bash
# Using "case" structure to filter a string.

SUCCESS=0
FAILURE=-1

isalpha() # Tests whether *first character* of string is alphabetic.
{
if [ -z "$1" ] # No argument passed
then
return FAILURE
fi

case "$1" in
[a-zA-Z]*) return $SUCCESS; # Begins with a letter?
*) return FAILURE;
esac
}

# Compare this with "isalpha()" function in C.
isalpha() # Tests whether *entire string* is alphabetic.
{
[[ $# -eq 1 ]] || return FAILURE
case $1 in
*[!a-zA-Z]*|"") return FAILURE;
*) return $SUCCESS;
esac
}
```

```bash
check_var () # Front-end to isalpha().
{
if isalpha "$1"
then
echo "alpha"
else
echo "non-alpha"
fi
}

a=2
b=What
c=$(echo $b) # Command substitution.

check_var $a
check_var $b
```

select

The **select** construct, adopted from the Korn Shell, is yet another tool for building menus.

```bash
select variable[in list]
do
  command...
  break
done
```

This prompts the user to enter one of the choices presented in the variable list. Note that **select** uses the PS3 prompt by default, but that may be changed.

# Example 10–28. Creating menus using select

```bash
#!/bin/bash
PS3='Choose your favorite vegetable: '  # Sets the prompt string.
echo
select vegetable in "beans" "carrots" "potatoes" "onions" "rutabagas"
do
  echo
  echo "Your favorite veggie $vegetable."
  echo "Yuck!"
  break # if no 'break' here, keeps looping forever.
done
exit 0
```

If **list** is omitted, **select** uses the list of command line arguments ($@) passed to the script or to the function which the **select** construct is embedded.

Compare this to the behavior of **for variable[in list]** construct with the **in list** omitted.

# Chapter 11. Internal Commands and Builtins

A builtin is a **command** contained within the Bash tool, literally built in. A builtin may be a synonym to a system command of the same name, but Bash reimplements it internally. For example, the Bash **echo** command is not the same as `/bin/echo`, although its behavior is almost identical.

A *keyword* is a reserved word, token or operator. Keywords have a special meaning to the shell, and indeed are the building blocks of the shell's syntax. As examples, "for", "while", and "!" are keywords. Similar to a builtin, a keyword is hard-coded into Bash, but unlike a builtin, a keyword is not itself a command.

# I/O

echo

prints (to `stdout`) an expression or variable (see 5–1).

```bash
echo Hello
echo $$
```

An **echo** requires the `-e` option to print escaped characters. See 6–2.

Normally, each **echo** command prints a terminal newline, but the `-n` option suppresses it.

An **echo** can be used to feed a sequence of commands down a pipe.

```bash
if echo "$VAR" | grep -q txt; # if [[ $VAR == *txt* ]]
then
    echo "$VAR" contains the substring sequence "\txt\t"
fi
```

An **echo**, in combination with [command substitution] can set a variable.

```bash
a=``echo "HELLO" | tr A-Z a-z`
```

See Example 12–15, Example 12–2, Example 12–30, and Example 12–31.

Be aware that `echo command` deletes any newlines that the output of `echo` generates.

The **IFS** (internal field separator) normally contains ` ` (newline) as one of its whitespace characters. Bash splits the input into arguments by linefeeds. Then `echo` outputs these arguments, separated by spaces.
