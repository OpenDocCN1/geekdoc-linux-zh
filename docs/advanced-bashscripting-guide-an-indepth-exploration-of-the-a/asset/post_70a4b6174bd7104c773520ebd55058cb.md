stty

Chapter 13. System and Administrative Commands

Shows and changes terminal settings. This complex command, used in a script, can control terminal behavior and the output displays. See the info page, and study it carefully.

# Example 13–1. setting an erase character

```bash
#!/bin/bash
# erase.sh: Using "stty" to set an erase character when reading input.

echo -n "What is your name? "
read name
# Try to erase characters of input.
# Won't work.
echo "Your name is $name".

stty erase '#'
# Set "hashmark" (\#) as erase character.
echo -n "What is your name? "
read name
# Use # to erase last character typed.
echo "Your name is $name".

exit 0
```

# Example 13–2. secret password: Turning off terminal echoing

```bash
#!/bin/bash
echo -n "Enter password "
read passwd
echo "password is $passwd"
echo -n "If someone had been looking over your shoulder, "
echo "your password would have been compromised."

echo -e \n # Two line-feeds in an "and list".
stty -echo # Turns off screen echo.
echo -n "Enter password again "
read passwd
echo "password is $passwd"
echo

stty echo # Restores screen echo.
exit 0
```

A creative use of stty is detecting a userkeypress (without hitting ENTER).

# Example 13–3. Keypress detection

```bash
#!/bin/bash
# keypress.sh: Detect a user keypress ("hot keyboard")
echo
old_tty_settings=$(stty -g) # Save old settings.
stty -icanon

| Keypress=$(head -c1) | # $=$(dd bs=1 count=1 2 > /dev/null) |
| | # on non-GNU systems |

echo
echo "Key pressed was \"$Keypress\""
echo

stty $old_tty_settings # Restore old settings.

# Thanks, Stephane Chazelas.

exit 0
```

# terminals and modes

Normally, a terminal works in the canonical mode. When a user hits a key, the resulting character does not immediately go to the program actually running in this terminal. A buffer local to the terminal stores keystrokes. When the user hits the ENTER key, it sends all the keystrokes to the program. There is a basic line editor inside the terminal.

```bash
bash$ tty -a
speed 9600; rows 36; columns 96; line = 0;
intr = ^C; quit = ^I; erase = ^H; kill = ^U; eof = ^E; deol = ^D; <undefined>; ed2 = <undefined>
start = ^Q; stop = ^S; susp = ^Z; rprnt = ^R; werase = ^W; lnext = ^V; flush = ^O echon -noflush -xcase -topost -echort
```

Using canonical mode, it is possible to redefine the special keys for the local terminal line editor.

```bash
bash$ cat filexxxx
wha<ctl-W-I-H-foo bar<ctl-Uhello world<ENTER>
<ctl-D
bash$ cat filexxxx
hello world
bash$ bash wc -c < file
13
```

The process controlling the terminal receives only 13 characters (12 alphabetic, plus a newline), although the user hits 26 keys.

In non-canonical ("raw") mode, every key hit (including special editing keys as ctrl–H) sends a character immediately to the controlling process.

The Bash prompt disables both icanon and echo, as it replaces the Bash terminal line editor with its own more elaborate version. For example, when you hit ctrl-A at the Bash prompt, it's ^A echoed by the terminal, but Bash gets a \ character, interprets it, and moves the cursor to the beginning of the line.

# setserial

Set or display serial port commands. This must be run by root user and is usually found in a system setup script:

```bash
# From /etc/pcmia/dev/$DEVICE | sed -e 's/\.*/IRQ: /\*/
setserial /dev/$DEVICE irq 0 ; setserial /dev/$DEVICE irq $IRQ
```

# getty, agetty

The initialization process for a terminal uses getty or agetty to set it up for login by a user. Commands are not used within shell scripts. Their scripting counterpart is stty.

# mesg

Enables or disables write access to the current user's terminal. Disabling access would prevent another user on the network to write to the terminal.

> It can be very annoying to have a message about ordering pizza suddenly appear in the middle of the text file you are editing. In a multi-user network, you might therefore wish to disable access to your terminal when you need to avoid interruptions.

# wall

This is an acronym for "write all", i.e., sending a message to all users at every terminal logged into the network. It is primarily a system administrator's tool, useful, for example, when warning everyone that the system will shortly go down due to a problem (see Example 17–2).

```bash
bash$ System going down for maintenance in 5 minutes!
Broadcast message from bozo (pts/1) Sun Jun 8 13:53:27 2001...

System going down for maintenance in 5 minutes!
```

If access to a particular terminal has been disabled with mesg, then wall cannot send a message to it.
