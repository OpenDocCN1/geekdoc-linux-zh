## 安全测试？

安全测试被定义为一种代码测试，确保代码系统或应用程序区域免受任何可能导致重大损失的漏洞、威胁或风险。

任何程序的安全测试都涉及发现过程中所有潜在的间隙或漏洞，这些漏洞可能导致数据、收入、组织员工和成员的信誉遭受损失。

安全测试的目的是识别系统风险并计算其可能存在的漏洞，以确保系统不会停止运行或被操纵。它还有助于识别系统中所有可能存在的漏洞，并鼓励开发者通过编码来解决这些问题。

安全测试是软件测试的一种形式，旨在识别设备漏洞并评估其信息和资产是否免受可能入侵者的威胁。

关注领域：安全测试中（尤其是针对网站/应用程序）有四个主要的关注领域需要处理：

- 网络保护：这涉及发现网络基础设施（资源和策略）中的漏洞。
- 系统软件安全：包括确定程序运行运行的各种系统（操作系统、数据库系统和其他软件）的漏洞。
- 服务端应用安全：确保用户（浏览器或任何此类工具）不会被滥用。
- 服务端应用程序安全：包括确保数据库软件及其技术足够可靠，以避免任何入侵。

## 自动化利用

漏洞扫描器用于提供数据集。它们并不能保证风险仍然存在。我们甚至无法保证所搜索的内容是组织网络中可能出现的漏洞的完整列表。由于多种原因，扫描器可能会返回不完整的结果。首先，网络分段或模块可能被排除在扫描和信息处理之外，这在某些安全测试中很常见。另一种解释是扫描器被偏离了特定的服务端口。扫描器无法到达某些端口，因此它无法检测到该网络中可能发生的任何漏洞。

## 什么是利用程序

利用程序是利用应用程序中漏洞或缺陷的程序。它由安全研究人员或恶意攻击者编写，用于他们的操作。在使用时，利用程序允许攻击者远程访问网络、获取提升权限或进一步渗透网络。在某些情况下，利用程序可能作为多组件攻击的一部分。


无线渗透测试有许多优势。识别风险行为者可能利用的漏洞至关重要。检查你的安全策略的有效性并识别潜在缺陷，使得组织能够在这些问题实际发生之前进行修复。这种渗透检查也将作为对你业务威胁/漏洞管理的第三方验证。

最后，你必须记住 Wi-Fi 并不是黑客可以唯一无线技术。还有大量的蓝牙和低功蓝牙（BLE）技术。其他无线技术如 ZigBee、Z-wave 和 DECT（无线电话）也可用。

### 理解数据收集与评估

无线渗透测试有多个阶段。第一阶段是知识收集，然后是分析。为了让良好的测试人员知道如何从无线网络收集数据，测试人员需要理解信号泄漏。基本上，信号泄漏（或溢出）是任何超出覆盖区域的无线信号。无法完全消除这种泄漏。尽管如此，减轻信号泄漏并确保感知存在是最佳实践。无线专家需要理解无线操作中采用的安全协议。

《健康保险流通与与责任法案》（HIPAA）保障了患者健康信息的隐私。《家庭教育权利与隐私法》（FERPA）保护了学生教育数据的隐私。信息安全管理体系（ISMS）是一种策略和系统结构，涵盖了企业信息风险管理过程中涉及的所有法律、物理和技术控制。

深入了解这些不同的机构，将使你的无线渗透测试变得至关重要，能够根据你的技术进行定制，并充当你业务的第三方审计员。熟练的测试人员在无线技术方面应具备相关技能。这包括查看非 FAA 许可的点对点连接。研究蓝牙将有助于发现在你的网络中使用该软件时出现的任何缺陷。

无线渗透测试员不仅必须是一个出色的渗透测试员，还必须な一名高水平的无线工程师。在选择公司进行无线渗透测试时，要提问对你的业务或行业重要的问题。如果你这样做，你就能从更专业的人员中筛选出经验较少的使用者。

### 理解 Wi-Fi 测试技术

渗透测试的研究流程如下：

- 无线局域网 (WLAN) 评估
- 越权访问点 (Rogue AP) 分析
- 无线热点
- 加密协议

`WLAN` 评估包括几项操作：活动 AP 指纹技术、数据项泄露、以及对 `Kismet` XML 文件的服务器后处理分析。使用 `Kismet` 和 `Wireshark` 识别 `WLAN` 上使用的认证和加密方法，并绘制室内外 `WLAN` 的范围。评估在数据披露监测模式下收集的流量、通过 MAC 分析识别多播协议、分析加密流量和私有身份验证功能，均有助于判断你 `WLAN` 的强弱。



报告的维度是针对越权访问点（`AP`）的审查。测试人员将通过 `RSSI` 信号分析和三角定位法找到违规设备。渗透测试人员应当注意环境网络（`circumstantial networks`）。虚假的“免费 Wi-Fi”会开放网络并引入恶意的越权用户。只需确保测试人员正在寻找位于环境中、但连接到未获得贵公司许可的 `SSID` 的设备。

通过将公司资源连接到另一个 Wi-Fi 网络，可能会出于多种原因产生危险。其中一些包括区域单位度假地攻击、钓鱼攻击、中间人攻击 (`MITM`) 等。在2017 年，无线热点随处可见。进入咖啡店和披萨店确实非常方便，但对你的公司资产来说可能非常危险。在不涉及细节的情况下，如果你的员工进入开放网络，可能会让你的业务面临危险。成功的测试人员将寻找这一点，并查看这些热点在哪里以及 `SSID` 是什么。然后你就可以采取措施帮助告知用户并正确配置端点。

自从几年前 `WEP` 被破解以来，市场上出现了许多免费工具来帮助破解预共享密钥（`PSK`）。令人置信的是，这些设备甚至可以破解 `WPA` 和 `WPA2`。一个全面的渗透测试员应该检查是否能在短时间内（几小时或几天内）破解任何预共享密钥。这将作为一种冲击性因素，证明一个普通的 8 字符或 10 字符密钥被破解的速度有多快。筛选后，将 `PSK` 馈给密码强度工具中，以显示代码的相对强度。

## Web 应用

Web 应用测试是在进入生产环境之前检查 Web 应用程序漏洞的一种简单方法。

### 1. 功能测试

用于检查产品是否符合已概述的要求。

- 确保所有连接均正常。
- 检查断链。
- 确保表单按预期工作。
- 例如，如果用户未必填字段，将显示错误消息。
- `Cookie` 是网站用于记住活动用户会话的小文件，因此无需每次都登录。`Cookie` 监控包括检查在清除缓存或过期时删除 `Cookie`。删除 `Cookie` 并并在访问网站时请求详情。

### 2. 易用性测试

易用性测试由用户或目标用户的焦点小组进行。

- 测试网站导航：菜单、按钮和不同页面之间的链接应当清晰可见并保持一致。
- 审查内容：内容应可读且无拼写或语法错误。
- 图片必须包含 `alt` 文本。

### 3. 接口测试

此处需要评估三个领域——应用、互联网和数据库服务器。

- 应用：测试请求是否正确发送到数据库。此外，客户端的展示必须有效。任何错误都应被程序捕获，并仅显示给管理员，而不是终端用户。
- 互联网服务器：检查 Web 服务器是否处理所有客户端请求而不拒绝服务。
- 数据库服务器：确保发送到数据库的查询给出正常结果。

当三层之间无法建立连接时，检查设备回答以及正确的消息。

## 标准执行

确保遵循 `W3C`、`OASIS`、`IETF`、`ISO`、`ECMA` 和 `WS-I` 等原则。检查端到端的工作流场景，即引导消费者通过一系列网页完成操作。同样要检查负面场景，以便在客户采取意料操作时，你的 Web 应用程序能够显示正确的错误消息或支持。

- 4. 数据库测试：数据库是你的 Web 应用的基础部分，预计需要对其进行全面检查。研究任务将包括：
  - 测试在请求执行期间是否显示任何错误。
  - 在数据库中生成、修改或删除数据时，应维护信息的完整性。
  - 检查查询的响应时间，并在必要时进行调整。
  - 从你的数据库中恢复测试的数据将在你的 Web 应用程序工具中清晰显示，可以使用这些工具：`QTP`、`Selenium`。

- 5. 可靠性验证。

兼容性检查确保你的 Web 应用在不同设备上都能正确显示。这包括：

- 浏览器兼容性测试：同一个网站在多个浏览器中看起来可能不同。你需要检查你的 Web 应用是否通过浏览器正确显示，以及 `JavaScript`、`AJAX` 和加密是否工作正常。你也可以测试移动 App 的兼容性。
互联网元素（如按钮、文本字段等）的布局随操作系统的改进而变化。确保网站在 Windows、Linux、Mac 等各种操作系统以及 Chrome、Internet Explorer、Safari 等浏览器的组合下完美运行。可以使用软件：`NetMechanic`。

- 6. 速度测试：这将确保你的网站在所有负载下都能工作。软件测试任务将包括（但不限于）：
  - 在完全不同的关联速度下的网站应用响应时间。
  - 给你的互联网应用负载，以测试其在常规和峰值负载下的操作。
  - 对你的网站进行压力测试，以确定在被推向超过平均峰值负载时的崩溃点。
检查是否由于峰值负载导致崩溃、发生此类情况后页面如何恢复。确保允许使用 `gzip` 压缩、应用和服务器端缓存等优化技术以缩短加载时间。可以使用软件：`Loadrunner`、`JMeter`。

- 7. 合规性筛选：安全测试对于存储敏感客户信息（如信用卡信息）的电子商务网站非常重要。测试活动将包括：
  - 不允许对受保护站点进行未经授权的访问。
  - 不允许下载下载限制文件。
  - 检查 `Session` 在延迟后应自然执行。
  - 使用 `SSL` 证书时，网站必须切换到加密的 `SSL` 页面。
可以使用的工具：`Babel Enterprise`、`FBBTester` 和 `CROSS`。

- 8. 群组测试：你应该挑选大量个人（群体）来引导测试，这些测试本可以通过某种方式由业务中的精选人员完成。研究是一种令人兴奋且新兴的现象，有助于揭示大多数隐藏缺陷。

作为一名 Web 测试人员，需要注意的是 Web 测试是一个非常困难的过程，你不可避免会遇到很多障碍。当然，你将面临的主要问题之一是截止日的压力。昨天，一切都是必要的！代码需要更改的次数也令人心累。确保你安排好工作并了解他人对你的期望。最好的方法是识别 Web 测试涉及的所有活动，并创建一个工作图表，以便进行可靠的估计和调度。

前提条件：你希望了解 Web 是如何工作的，并理解在线页面（`page`）、网站（`site`）、在线服务器和搜索引擎之间的区别。

目标：你将学习什么是在线服务器，并且你可能对它的工作原理有一个通用的理解。

“Web 服务器”可能指设备或编程，或者两者共同工作。

在硬件方面，互联网|在线服务器可能是一个存储 Web 服务器代码和网站部分文件的 PC（例如 `HTML` 文档、图像、`CSS` 样式表和 `JavaScript` 文件）。它连接到互联网，并方便与连接到互联网的其他设备共享物理数据。



在软件方面，Web 服务器包含多个控制用户如何访问托管文件的部分，至少有一个 `HTTP` 服务器。`HTTP` 服务器是一段可以同时识别 `URL`（互联网地址）和 `HTTP`（一种用于...协议）的软件。

执行交易。你需要一个应用服务器来处理此类分配。（我们将在书的其他部分讨论这类编程。）`HTTP` 包含了关于客户端和服务器如何通信的清晰指南。稍后，我们将在专门的报告中介绍 `HTTP` 本身。现在，请记住这些点：用户可以发起 `HTTP` 请求，但随后只能由服务器发起。服务器只能对用户的 `HTTP` 请求做出响应。

客户端在通过 `HTTP` 请求文件时，必须提供该文件的 `URL`。

每个 `HTTP` 请求都必须由 Web 服务器处理，至少要返回一条错误信息。

以 `MDN 404` 页面作为此类错误页面的示例。`HTTP` 服务器负责处理和响应 Web 服务器上接收到的请求。

在收到请求后，`HTTP` 服务器首先测试请求的 `URL` 是否匹配当前目录。

如果是，在线服务器应该将文件夹的内容返回给用户。如果不是如此，应用服务器应该生成相应的文件夹。

如果没有可用的机制，Web 服务器将向浏览器返回错误信息，最常见的是 `404 Not Found`（未找到）（这种错误非常普遍，以至于许多设计师都会花时间创建 `404` 错误页面。）

### 静态内容与动态内容

数据库可以支持静态或动态内容。“静态”意味着“按原样提供”。静态网站最容易设置，因此我们建议将你的第一个页面设置为静态。

“动态”意味着服务器能够处理甚至从数据库中动态生成信息。这种方法提供了更大的灵活性，但技术框架变得越来越难以处理，使得构建网站变得非常有挑战性。

Web 服务器上有一个应用服务器，它从数据库获取内容，对其进行格式化，将其放入某些 `HTML` 模板中，并给你结果。在这种情况下，应用服务器被称为 `Django`，并使用 `Python` 创建（利用 `Django` 系统）。`Mozilla` 组计划 `Django` 用于满足 `MDN` 的特殊需求，然而，其广泛用途取决于许多不同的进展。

数据库服务器数量之多，很难推荐替代方案。许多数据库服务器针对特定类别的网站，例如论坛、维基百科或网商店；其他被称为 `CMS`（内容管理系统）的服务器则更通用。如果你正在创建一个复杂的网站，请花时间选择一个符合你需求的平台。如果你不需要在互联网服务器上进行关联编程（这是一个令人兴奋的领域！），你不应该构建自己的应用服务器。那是重造轮子。

数据库信息系统为不同的计算机提供服务，以便查看和检索信息系统中的数据。访问信息服务器将通过运行在区域的“前端”机器（例如 `phpMyAdmin`）或运行在信息服务器本身的“后端”机器（通过外部 shell ）进行。在收集完服务器中的信息后，数据请求者将发送给用户。

大多数组织使用数据库是为了存储目的。用户可以使用数据库特定的查询语言执行查询来访问数据。例如，`SQL` 就是查询语言的一个很好的例子。

## Web 攻击威胁应用程序和信息

针对网站、软件和基于互联网的 `API` 的广泛网络攻击使得安全比以往任何时候都更加困难。

Web 攻击会影响网站服务的可用性，违反你的信息的隐私和完整性和你的底线。看看最常见的攻击以及它们如何影响网站、应用程序和 `API` 的安全、隐私和信誉。

`DDoS` Web 针对你的核心互联网框架（例如 `DNS`）发起的攻击可能会导致你断开连接。即使你的 `DNS` 服务器受到完全保护，针对你的网络、网站、应用程序和 `API` 的 `DDoS` 攻击仍然可能导致公司崩溃。世界上每个 `IP` 地址都可能受到 `DDoS` 攻击者的攻击。连接到互联网的每个计算机，从智能灯泡到 Web 服务器，都可能是他们攻击的目标。

### 漏洞利用

能够以多种方式操纵额外信息的 Web 攻击。

最简单的方法是获取对存储你的信息或与其信息通信的系统的访问。最常见的攻击向量是利用这些系统运行的 `OS` 或应用程序中的漏洞。一旦发现漏洞，黑客就会编写利用程序，利用并公开利用互联网上的代码。

许多针对 `OS` 或应用程序的利用程序是专门设计的，并包含了某种缓冲区、堆栈或堆溢出，并结合了由由目标设备运行的远程代码。大多数情况下，这段代码允许黑客进入网络并安装额外的代码，允许他们在系统中停留很长时间。

针对你如何使用 `OS` 或软件的高级 Web 攻击通常是最难防御的。这些包括 `SQL` 注入、参数操纵、跨站脚本（`XSS`）、路径穿越和暴力破解攻击。例如，暴力破解可以通过用户名和密码身份验证尝试覆盖 Web 应用程序来获得对受保护信息的访问。

组织不仅需要准备可能影响其 Web 资源可用性的攻击，必须准备针对其信息隐私和完整性的攻击。制造商和程序员引入了许多漏洞，但公司使用 `OS` 或应用程序的方式造成了危险。如今的黑客充分利用了所有高层漏洞，对互联网安全造成了重大威胁。

## 什么是封闭式 XML 注入？

`XML` 实体注入（也称为 `XXE`）可能是一种互联网安全漏洞，允许攻击者干预应用程序对 `XML` 信息的处理。它通常允许攻击者查看应用程序服务器文件系统上的文件，或与应用程序本身可以访问的任何内部或外部系统进行通信。

在某些情况下，攻击者可以通过滥用 `XXE` 力量进行服务器请求伪造（`SSRF`）攻击，增强 `XXE` 攻击以获取隐藏的数据库或其他后端基础。

## XXE 是如何发生的？

大多数编程使用 `XML` 配置在客户端和服务器之间传输信息。`XXE` 漏洞的存在是因为 `XML` 规范包含了许多潜在危险的特性，而这些特性即使通常不被利用，也会被通用解析器接受。

`XML` 外部实体是自定义 `XML` 实体的一种，其特定值在声明期间从 `DTD` 加载。从安全角度来看，外部实体特别感兴趣，因为允许根据文件路径或 `URL` 识别对象。

## XXE 攻击的形式有哪些？

有不同类型的 `XXE` 攻击：使用 `XXE` 访问文件，其中包含内容的对象被定义并返回给请求响应。

滥用 `XXE` 执行 `SSRF` 攻击，其中外部书籍通过其指向后端框架的 `URL` 被识别。

通过盲 `XXE` 通过错误信息提取数据，其中攻击者可能会导致包含敏感数据的解析错误消息。

## 会话

会话（`sessions`）。我们需要询问会话以获取详情。让我们看看什么是会话以及会话是如何工作的。

会话是指两个计算机系统或单个系统的两个部分之间进行交互的特定时期。当你登录一个受密码保护的程序时，就会使用会话。会话会一直持续到接触结束。在某些情况下，例如上述，会话是由客户端发起的。也有由工程实施的会话。许多客户端使用会话，这些都是技术启动会话的示例。尽管如此，大多数成功的会话对用户是隐藏的。我们不知道会话何时开始和结束。会话是互联网通信的一个重要因素。

提到会话劫持（`session hijacking`），正如我们之前看到的，攻击者利用活动会话来执行攻击。大多数互联网通信都需要身份验证。认证通常采用多种策略。最常用的方法是要求用户在网站上输入预定义的用户名和密码。当客户端输入这些凭据时，程序会将其与存储的数据进行比对。如果输入的信息与存储的详情匹配，系统将允许用户访问特定的数据库或网站部分。

这种身份验证方法在通信开始时执行，一旦认证成功完成，会话就会开始并保持活跃，直到通信结束。会话劫持攻击发生在会话运行时，攻击者同时进行干扰并接管动态会话。这种干扰可能可以检测，也可能无法检测。每个会话都会有一个会话 `ID`，通常存储在 `cookie` 或 `URL` 中。这种攻击也被称为“`Cookie Hijacking`”。我们可以通过使用当前会话的网站行为来识别被劫持的会话攻击。如果网站对客户端的正常方式提交没有反应，或者由于某些不明原因完全停止工作，这可能是会话接管攻击的结果。

## 会话劫持是如何工作的？

如我们所知，`http` 通信使用了大量的 `TCP` 连接，因此服务器需要一种方法来识别每个用户的连接。最常用的技术是身份验证方法，因此服务器向用户请求者发送一个令牌（`token`）。该令牌由固定宽度的数组组成，可以有多种方式，例如在 `URL` 中、`http` 请求头的其他部分或 `http` 请求体中。该攻击通过窃取或预测合法的会话令牌来利用会话令牌，以获得对 Web 服务器的未经授权访问。会话令牌的泄露可以通过不同的方式发生。现在，我们将看到会话嗅探（`session sniffing`）和跨站脚本攻击（`cross-site script attack`）两种方式。

### 会话嗅探

如我们之前看到的，存在一系列令牌。这是当前会话的会话 `ID`。攻击者的第一步是获取这个会话 `ID`。入侵者使用嗅探器获取会话 `ID`。当会话 `ID` 被记住时，攻击者使用该会话 `ID` 获取对 Web 服务器的非法访问。

### 跨站脚本攻击

跨站攻击是一种获取会话 `ID` 以帮助用户运行恶意代码或脚本的方法。在这种攻击中，攻击者向合法的网站或 Web 应用程序执行恶意文件（也称为恶意载荷）。通过这种攻击，攻击者并不直接针对受害者，但攻击者可能会利用受害者访问的网站上的漏洞，并利用该网站将有害内容传递给不幸的受害者程序。

## 如何停止会话劫持？

正如我们之前看到的，通常用于窃取会话 `ID` 的方法是在客户端网站上安装恶意代码，从而获取 `cookie`。要避免会话劫持的最简单方法是从消费者角度提供保护。建议采取预防措施来防止会话客户端侧被劫持。用户应该运行活跃的防病毒软件、反恶意软件程序，并保持系统更新。



有一种技术使用引擎打印所有会话请求。除了监控 `IP` 地址和 `SSL` 会话 `ID` 外，引擎还会记录 `http` 头部。头部的任何调整都会为会话增加罚分，一旦分数达到一定数量，会话就会结束。这个上限可以被设置。这很重要，因为当入侵发生时，`HTTP` 头部命令将是唯一的。

这些是用户和服务器端应采取的建议预防措施，以避免会话被劫持。

## 密码破解？

`Password cracking`（密码破解）是一种尝试通过处理常用密码或猜测密码的算法来获取对受限系统未经授权访问的方法。换句话说，它是获取正确密码以访问受身份验证过程保护设备的艺术。

密码破解使用多种方法来实现其目标。破解可以包括与字典列表对比密码，或利用计算生成与破解应用程序代码匹配的密码。在本指南中，你将介绍流行的破解技术和应对措施，这些措施可以保护你的系统免受此类攻击。

编程语言主要有两种类型——直接从编写的源代码运行的语言（解释型或脚本语言）和首先通过一个系统将其渲染为机器可以直接执行的形式的语言（编译语言）。我们已经介绍了一些脚本语言，在本文我们将处理一些更常见的编译型语言。

值得注意的是，许多解释型语言（如 `python`、`perl` 或 `lua`）都有编译阶段，它们通常在该阶段被编译成虚拟机的字节码。在典型的基于 `Linux` 的系统（或者说是 `BSD`）上，你可以找到大量用 `C` 语言编写的代码。`Linux` 的部分和 `BSD` 的大部分都是用 `C` 语言编写的。大多数操作系统函数（如 `cp`、`ls` 等）可能都是用 `C` 编写的，除非你处于非常特殊的系统上。`C` 被认为是 `UNIX` 系统的标准编程语言，建议任何编写软件的人都应该意识到并熟悉 `C`，即使他们并不是每天经常编写它。大多数关于设备调用的手册页都是用 `C` 语言编写的。

1979 年，`Bjarne Stroustrup` 开始着手另一种编程语言，长期来看被称为 `C++`。`C++` 包含了 `C` 语言的各种结构和语义组件，现在它被视为一种完全独立的语言，恰好与 `C` 有一些相似之处。`C++` 受到一些由致力于编程模型的个人所维护的大型项目的青睐，也受到许多 `GUI` 创建者的喜爱。`Qt` 是基于 `C++` 的语言编写的。在那时，`KDE` 是由 `C++` 组成并编写的。`C++` 在 `Windows` 上也得到了支持，因为它是微软选定的应用程序编程语言。

`Objective C` 将 `C` 语言与 `Smalltalk` 的某些语法和语义结合起来。它受到那些不喜欢 `C++` 但希望默认比 `C` 更多的面向对象程序员的青睐。`GNeste` 软件大部分用 `Objective C` 编写。`Objective C` 在 `Mac OS` 系统上（`Mac OS`、`Mac OS X` 以及各种 `iOS` 变体）也支持。

尽管 `Java` 严格来说是一种编译语言，但它与脚本语言有相似之处，因为程序员针对的是虚拟机而不是编译器运行的机器码。这是 `Java` “编写一次，处处运行”这句话的基础。`Java` 受企业程序员青睐，也可以作为 `Android` 应用程序的语言。如 `Jenkins` 控制器或 `Eclipse` 构建的环境等资源是用 `Java` 编写的。



大多数人认为 `C#` 仅仅是微软 `.NET` 语言，但有了通用语言运行时（`CLR`），它不仅仅是一个微软接口。曾几何时，`mono` 在编写基于 `GTK+` 的桌面应用程序（如 `Tomboy`）非常流行。

许多微型实用和工具是用由一些 Google 工程师（以及其他人）开发的语言 `Go` 编写的。`Go` 正在吸引被 `C++`、`C#` 等吸引的应用程序程序员，因为它的语言特性似乎在设计时就考虑了它们。虽然有很多项目是用 `Go` 编写的，但在写这篇文章时，没有一个项目看起来是常见的应用程序。

`Haskell` 是编程语言中与上述语言完全不同的物。例如，`Haskell` 是一种函数式编程语言，而不是某种命令式语言。`Haskell` 已经存在很久了，但最近才作为全功能编程语言框架获得普及。在流行的操作系统上可以获得的惊人工具范围是用 `Haskell` 编写的。其中最广为人的是 John Macfarlane 的 `Pandoc` 和 Joey Hess 的 `git-annex`。

还有许多编译型编程语言，例如：`Algol`、`Pascal`、各种 `Basic`、各种 `Lisp` 以及各种类型的 `ML`，特别是 `OCaml`。发现编译语言的奇妙世界，并对其语法的范围和多样性感到惊，这些语法旨在编译成相同的形式以创建机器码。通常当你构建源码时，构建过程在许多不同类型的项目（如 Windows `ASP.NET`、移动应用等）中是非常常见的。构建过程在 `C#`、`Visual Basic`、`C++` 和 `F#` 等编程语言中是相似的。

## 编程错误的 3 种基本类型

对计算机编程感兴趣的人，特别是（可能尤其是）新手，都可能遇到各种类型的错误和 Bug，这使他们必须通过代码追踪原因并进行必要的调整。

当意想不到的错误出现并让你停下脚步时，可能会感到困惑和沮丧。但意识到可能发生的错误基本类型，至少能给你一个“战斗的机会”。以下是你可能遇到的三大类关键编码错误：

- 1. 我们将错误分为三类：逻辑错误、语法错误和语义错误。但请注意，这些类别在本质上可以是静态的（编译时）或动态的（运行时）。

逻辑错误是所有错误类型中最难发现且最麻烦的。我们并没有导致程序崩溃或完全无法运行，而是让它以某种方式“行为不当”，产生某种错误的性能。逻辑错误的一个例子是空引用。零引用错误导致了大量的代码 Bug，它们通常是涉及缺失或错误的“计算机逻辑”的非常基础的错误。可能是一个空属性/字段、一个阻止对象产生的条件，或者是一个声明但未初始化的局部变量字段。

逻辑错误在计算机语言本身看来是“合逻辑的”，但它们实际上并没有正确地嵌入软件中。

### 2. 语法错误

计算机编程中的语法错误与逻辑错误的不同在于，它们没有遵循计算机语言的正确顺序。

在编译语言中，你可以在编译时遇到任何语法错误，它们在程序运行之前必须被修正。在解释型语言中，语法错误可能会在运行时发生，你的错误信息可能不会说明这是一个语法问题。尽管如此，两种情况下，编译器/解释器都会发送你语法错误的位置，这使其非常容易找到。

通常，语法错误是较小的、通常是数字级的错误；而逻辑错误可以包含代码的大部分和代码的流。语法错误的示例将：行尾缺少分号或操作末尾缺少括号。

### 3. 语义错误

语义错误是对“代码语句”的不当使用。虽然有不同的语义错误定义，但这里指的是逻辑错误会产生错误的数据，而语义错误则毫无意义。

## 调试（Debugging）

调试是指工程领域修复代码错误的方法。换句话说，指的是错误的检测和消除。这一操作从代码无法正确运行开始，到成功检查程序结束。这被认为是一个极其复杂且耗时的过程，因为错误在调试的所有阶段都需要被解决。

调试过程：涉及的步骤包括问题的检测和文档准备：

- 将文档分配给软件工程师以验证其有效性。
- 通过建模、数据、识别和检查候选缺陷进行缺陷分析。
- 通过进行必要的更改进行缺陷修正。

调试策略：测试系统以理解该过程。这允许调试人员根据需要构建调试系统。对框架进行调查同样有效，以发现正在进行的更改。

回溯分析（Backward analysis）包括从错误信息回溯程序，以识别故障代码区域。对该区域进行详细研究以识别缺陷的原因。

正向分析（Forward analysis）包括使用断点在过程的不同点打印语句来跟踪程序的进展，并分析结果。获取错误输出的区域是需要定位以识别缺陷。

利用计算机工程经验。这种策略的有效性取决于调试人员的专业知识。

调试工具：调试工具可以是检查或修复其他程序的程序。有很多属性代码如 `gdb` 和 `dbx` 用于调试。它们需要基于控制台的界面。自动调试工具包括代码追踪器、性能分析器、解释器等。

最常用的调试器有：`Radare`、`WinDbg`、`Valgrind`。

调试与测试的区别：调试与测试不同。测试专注于发现 Bug、故障等，而测试在发现 Bug 后开始。（注：OCR 文字在这里似乎自矛盾，通常测试先于或伴随调试，此处保持原意）。

调试需要大量的知识和技能。它可以得到一些工具的支持。有多种测试类型，例如系统测试、集成测试、Alpha 和 Beta 测试。

## 信息组织（Organizing The Info）

一旦你开始创建、存储和处理知识与文件，它们就会变得杂乱。为了以后节省时间并防止错误，你和同事必须确定如何命名和组织文件。包含信息（或元数据）允许你为数据添加上下文，以便你和其他人解释它。

采用命名规范有助于确保连续性，更容易定位和正确识别文件，防止在协作处理文件时出现版本控制问题。仔细组织文件将帮助你在需要时找到所需内容，从而节省时间和压力。

无论你是在独立设备上还是网络机器上操作，建立一个允许你访问文件、防止重复并确保数据可以被备份的系统都需要一些准备。一个良好的阶段是创建一个合理的注册结构。以下提示将帮助你创建这样一个系统：

- 使用文件夹——将文件夹嵌套在文件夹中，以便将特定主题存储在一个位置
- 遵循当前程序——正确检查
- 命名——文件夹为相关的工作区域命名，而不是为个人研究人员或部门命名。这消除了员工成员离开时共享工作空间中的歧义
- 保持一致——一旦你约定了命名方案，遵守该方案是重要的
- 结构层级化——从为较大的主题创建有限数量的文件夹，然后在这些内部创建大量文件夹
- 分隔文件夹——当你开始创建大量目录和文件时，先进行分类是一个明智的计划

在创建文件名时，我需要记住什么？

在开始阶段就决定命名规范。有效的文件名应该是简洁的，并且对你和你的同事而言，这样你们就可以轻松找到它们。如果你的部门决定了以下元素，将非常有帮助：

- 词汇：为文件名选择通用的词汇，以便所有人都使用相同的语言。
- 标点符号：决定是否使用标点符号、连字符和空格——就按顺序出现的日期正确用法达成共识，例如 `YYYY-MM-DD`。
- 顺序：确认哪个元素应该排在第一，以便将相同主题的文件分组。
- 数字：指定命名时将使用的数字，以便对文件进行编号，例如 `01`、`002` 等。

我应该如何命名我的文件，以便知道哪一个是最新的？

很少有论文是由人一次性完成的。此外，并没有多少人会在很长的时间内关注某项工作，而缺乏适当的控制可能会导致对哪个版本是最新版本的产生困惑。这里是避免这种情况的一种方法：使用编号系统。文件的某些重大变化可以通过完整的数字显示，例如 `v01` 将是主版本，`v02` 是后续变体。细微的变化可以通过增加数字来表示，例如 `v01` 表示对第一个版本进行了更改，而 `v03` 表示对第三版本创建了修改。

当草稿区域设定了修订时，额外数据应当取决于创建这些修订的人。例如：文件名 `v01_20130816` 的文件表示某同事在 2013 年 8 月 16 日对第一个版本进行了更改。然后，主作者将对 `v01` 进行这些修改并更新文档编号系统。

为每个重要文档包含版本控制，列出修改内容及其日期，以及文档正确的版本号。如果有帮助，你可以将文档名称本身与版本号并列。请商定由谁来完成并标记它们。还有许多外部资源可以为你提供关于正确文件命名规范的建议，你可以在这里看到关于它们的大数据。

    - 最终项目文档和出版物
- 集合元数据：支持性文档应该经过组织，以便通过网络浏览器或基于数据库的存档进行识别和定位。
