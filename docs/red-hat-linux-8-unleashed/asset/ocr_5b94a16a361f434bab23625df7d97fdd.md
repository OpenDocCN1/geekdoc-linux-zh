# Patching the Kernel

A number of different entries are on the FTP archive site for 2.4.19, but because you are only interested in the full kernel for 2.4.9, it is only necessary to get the full package of source code. There are two of these packages:

linux-2.4.19.tar.gz
linux-2.4.19.b22

Although these are the same kernel packages, they're built using different compression utilities: the .gz extension is the gzip package, found on almost every Linux system available. the .bz2 is the newer BZip2 utility, which has better compression than gzip. Both packages have the same content, so download the one compressed with the program you use.

Once downloaded, move the package to a directory other than /usr/src and unpack it. If you downloaded the .gz package, the unpacking command is tar -xvf linux-2.4.19.gz. Otherwise, the BZip2 unpack is tar -xjvf linux-2.4.19.tar.bz2. Once unpacked, the package will create a new directory, and place all the files in it. Rename this directory linux-2.4.19 and copy it to /usr/src or move it there. Then, create a symbolic link of linux-2.4 to linux-2.4.18 (otherwise, some scripts won't work). Here's how to create the symbolic link:

```
# ln -s /usr/src/linux-2.4.19 /usr/src/linux-2.4
```

By creating a symbolic link to /usr/src/linux-2.4, it is possible to allow multiple kernel versions to be compiled and tailored for different functions: you'll just change the symbolic link to the kernel directory you want to work on.

> CAUTION
The correct symbolic link is critical to the operation of make. Always have the symbolic link point to the version of the kernel sources you are working with.

# Patching the Kernel

It is possible to patch a kernel to the newest Linux kernel version as opposed to downloading the entire source code. This choice could be beneficial for those who aren't using a highspeed broadband connection. (A typical compressed kernel source file is 26MB or a download time of about 10 minutes on a 512Kb DSL connection; adjust accordingly for your connection.) Whether you patching existing sources or downloading the full source, the end results will be identical.

Patching the kernel isn't a mindless task: it requires the user to retrieve all patches from her current version to the version she wants to upgrade to.
