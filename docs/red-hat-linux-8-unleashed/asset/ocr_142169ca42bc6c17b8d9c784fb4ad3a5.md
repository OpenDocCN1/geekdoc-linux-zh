When you receive mail from the list and you reply to an individual message, that message is sent to the Mailman list manager, and the message is then re-sent to everyone on the list. Red Hat maintains numerous mail lists and uses the mailing list manager Mailman to do it. Red Hat provides Mailman with Red Hat 8.0.

Mailman keeps track of who is subscribed and who does not have email addresses. The mail list list manager handles all new subscriptions and unsubscriptions through a Web interface and can even generate an archive of all the messages on the list.

For each list, a person is designated as the mail list administrator. The administrator has password-protected access to a special administration Web. He or she can manually add and delete members from the list and remove emails that are determined to be offensive. It is also possible to configure the list to be moderated, in which case a moderator reads all messages before they are passed on Mailman for distribution to the subscribers. The list can also be configured to allow nonmembers to post, but that option is rarely used because most administrators want to keep unauthorized posts off the list.

Some lists, known as "high-traffic" have a large number of messages posted daily. Other lists, known as "low traffic" lists, have few, if messages posted daily. One configuration option is to have all messages consolidated into a digest, so only one message is sent for a preestablished number of messages that are received by Mailman. The maximum message size also can be established, and attachments to messages can be prohibited.

> Part of the test testing and development for Red Hat 8.0 took place on a mail list. You can view the archives at https://listman.redhat.com/pipermail/limbo-list/ if you are curious.

With Mailman to manage a mail list, you must first have Sendmail installed and configured (see Chapter 19, "Handling Electronic Mail").

After installing the RPM (by using the package manager or manually, with # rpm -ivh), you can look at the installed documentation in /usr/share/doc/mailman-2.0.13, paying particular attention to the simple installation instructions in the README.REDHAT.

Here are some suggestions for installing and configuring Mailman:

+   - Set your password to something that is not easily guessed but so difficult that it will be forgotten.

+   - The default values found in the file /var/mailman/Mailman/mm_cfg.py are as fine as they are, but you might want to customize DEFAULT_HOST_NAME to your hostname from the default value localhost.localdomain. This is not necessary if you want to experiment with Mailman; you can change this value later.
