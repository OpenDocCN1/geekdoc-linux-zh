> NOTE
If you are recompiling the Red Hat kernel, the /usr/src/linux-2.4/configs/ directory contains several versions of configuration files for different purposes. Each is named for the special circumstance which it was created. It will be obvious on examination. You can copy the desired file to /usr/src/linux-2.4/.config.

Red Hat has a full set of .config files in the subdirectory configs, all named for the type of system they were compiled for. (For example, kernel-2.4.18-athlon-smp is a configuration file for a multiprocessor Athlon computer.) If you want to use one of these default configurations as the basis for a custom kernel, simple copy the appropriate file to /usr/src/linux-2.4 and rename it to .config.

4. Run the make mrprop utility to prepare the kernel source tree, cleaning out any old files or binaries.

5. Restore the .config file so that the command make mrprop will have been deleted, and edit the Makefile.

> NOTE
If you want to keep any current version of the kernel that was compiled with the same source tree, manually edit the Makefile with your favorite text editor and add some unique string to the EXTRAVERSION variable.

Here is an example to append the current date to the kernel:
EXTRAVERSION = '*date +%D|sed -e 's/\\/\\\-/g'

This creates a kernel with a name of 2.4.19.—with the current month, day, and year separated by a character. Thus, if you compiled the kernel on January 1, 2003, the kernel name would be linux-2.4.19-01-2003.

You can use any description you prefer, however.

6. Modify the kernel configuration file using make config, menuconfig, or make xconfig—we recommend the latter, but read the "Choosing a Configuration Interface" section for details.

7. Run the make dep utility to create the code dependencies used later in the compilation process.
