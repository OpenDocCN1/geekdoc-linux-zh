# CHAPTER 4 Post-Installation Configuration

This example specifies the kernel sound modules to load, along with the options that the system passes to required modules before loading. Sound service is started by the /etc/rc.d/rc.sysinit boot script and is specified in the file name soundcard under the /etc/sysconfig directory. The directory might look like this (and will only exist if you have used the sndconfig command):

```
# THIS FILE IS WRITTEN BY SNDCONFIG
# PLEASE USE SNDCONFIG
# TO CHANGE THIS FILE!
# There should be no spaces at the start of a line
# or around the '= ' 
CARDTYPE=SB16
```

As the example shows, this file is generated by the sndconfig command. Use this command if you install a new or different sound card in your PC. Start this command (root) like this:

+   - sndconfig

> NOTE you can also launch sndconfig using Red Hat's setup command like this:

# setup


After you press Enter, scroll down to the Sound card configuration item, and then tap the key to highlight the Run Tool button. The sndconfig command will start after you press Enter.

After you press Enter, sndconfig will probe for any installed sound hardware. Installing a sound card in a PC with built-in sound on the motherboard will usually disable the built-in sound chipset; however, you might need to specifically disable built-in sound hardware by changing the PC's BIOS settings.

# Configuring a New Sound Card

Probing problematic sound hardware can be disabled using the --noprobe command-line option when running sndconfig. You can manually select, configure, and test your sound hardware as in Figure 4.5.

Scroll through the list of sound cards using the Up or Down cursor keys to highlight your sound card, and then press Enter. You may be asked in a subsequent dialog to select IRQ or DMA settings, or you will see a dialog asking you to press Enter to play a test sound (the voice of Linus Torvalds pronouncing “Linux”).
