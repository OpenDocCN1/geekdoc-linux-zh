
## Partitioning Before and During Installation

NOTE

It is possible to create a dual-boot configuration, which allows the choice of booting Red Hat Linux and another operating system, such as Windows XP. To configure your system for dual-booting, you must first install Windows and then install Linux. Note that many Windows system-restore CD-ROMs will wipe out all data on your hard drive, including Linux. During installation of Red Hat Linux, you can install the GRUB Linux bootloader in the primary drive's Master Boot Record, or MBR. When properly configured, GRUB allows your system to reboot to Windows or Linux. See Chapter 24 for information on GRUB.

CAUTION

Before you partitioning your drive or installing Red Hat Linux, get your safety nets in order. First, back up all critical data. Any changes to your system's hard drive or operating system will put your existing data at risk. To prevent the loss of time and resources that inevitably follow data loss, do backups before you make any changes to your system. Create a bootdisk when you install Red Hat Linux, so you'll be able to at least boot Linux if something goes wrong. See Chapter 11, "Backing Up, Restoring, and Recovery," for information on backups on Linux.

## Choosing a Partitioning Scheme

Like deployment and installation of Linux, partitioning your hard drive to accept Red Hat Linux requires some foresight, especially if the target computer is going to be used other than as a home PC on which to learn.

If Linux is to be the only resident operating system, the Red Hat Linux installer can be used to automatically create and use a partition scheme according to the type of install-select during the install. If you plan to have a dual-boot system in which you can boot Linux or another operating system, you'll need to manually partition your hard drive before and possibly during the install.

The simplest and most basic scheme for a Linux system requires a Linux native root partition and a swap partition. On a single-drive system with 10GB storage and 128MB RAM, the scheme might look like this:

| Hard Drive Partition | Mount Point | Size |
| --- | --- | --- |
| /dev/hda1 | / | 9.74GB |
| /dev/hda2 | swap | 256MB |

On a system running Windows, the scheme might look like this:

| Hard Drive Partition | Mount Point | Size |
| --- | --- | --- |
| /dev/hda1 | /mnt/dos | 2GB |
| /dev/hda2 | / | 7.74GB |
| /dev/hda3 | swap | 256MB |

## Hosting Parts of the Linux Filesystem on Separate Partitions

The Red Hat installer can be used to automatically create a partition scheme according to the class of install. Your specific partitioning scheme will depend on how Red Hat will be used! However, on a system being designed for expansion, greater capacity, or the capability to host additional software or users, you can use separate partitions to host various parts of the Linux file system. Some candidates for these separate partitions include

- /home—Users will store hundreds upon hundreds of megabytes of data under their directories. This is important data, perhaps even more than the system itself. Using a separate partition (on a different volume) to store this user data helps make the data easier to find and it segregates user and system data. You'll have to decide ahead of how much storage to allocate to users. For a single workstation, you should reserve several gigabytes of storage.
- /opt—The home directory for additional software packages, this directory can have its own partition or remote filesystem. Red Hat does not populate this directory, but it may be used by other software packages you install on your Red Hat system. One gigabyte of storage should be adequate, depending on applications to be installed.
- /tmp—This directory can be used as temporary storage by users, especially if disk quotas are erased; such as, it could be placed on its own partition. This directory can be as small as 100MB.
- /usr—This directory holds the static binaries, libraries, and documentation.
- /var—This directory contains data that changes frequently, such as log files, spools, and temporary files that are preserved across reboot.
- /boot—This directory contains the files needed to boot the system, such as the Linux kernel and boot loader files.

To begin the automated installation process, you create the configuration file that will be used by kickstart. To configure the complex configuration file, log in as the root, and then run the ksconfig command, like so:

```
# /usr/sbin/ksconfig
```

After you press Enter, you will see the Kickstart Configurator dialog box, as shown in Figure 2.3.

Click to select various options, and then enter the specifies for the target system. Start by selecting the default system language, type of keyboard, mouse, and so on. On course, automated installations work best when installing to similar equipment. When finished, click the Save to File button, and the configuration is saved with the name ks.cfg. When you use the kickstart installation method, the kickstart file will be read by computers booting to the install. The kickstart language covers nearly every aspect of an install with the exception of sound card, printer, or modem setup.
