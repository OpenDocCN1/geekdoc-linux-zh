
# Choosing Backup Hardware and Media

Each CD-RW disk can hold 650MB to 700MB of data (the data comes in both capacities); larger chunks of data can be split to fit on multiple disks. Some backup programs support this method of storage. Once burned and verified, the shelf life for the media is at least a decade or longer. Prices increase with writing speed, but a serviceable CD-RW drive can be purchased for less than $100.

DVD-RW is similar to CD-RW, but more expensive and can store up 4.7GB of data per disk. These drives are selling for about $500.

# Network Storage

For network backup storage, arrays of hard drives provide one solution. With the declining cost of mass storage devices and the increasing need for larger storage space, network storage (NAS, or Network Attached Storage) is available and supported in Linux. These are cabinets full of hard drives and their associated controlling circuitry, as well as special software to manage all of it: These NAS systems are connected to the network and act as a huge (and expensive) mass storage device.

More modest and simple network storage can be done on a remote desktop-style machine that has adequate storage space (up to 160GB IDE drives is a lot of storage space, easily accomplished with off-the-shelf parts), but then that machine (and the local system administrator) has to deal with all the problems of backing up, preserving and restoring data, doesn't it? Several hardware vendors offer such products in varying sizes.

# Tape Drive Backup

Tape drives have been used in the computer industry from the beginning. Tape drive storage has been so prevalent in the industry that the tar command (used for archiving) is derived from Tape Archive. Modern tape drives use tape cartridges that can hold 70GB of data (more, in compressed format). Capacities and durability of tapes vary by type to range from a few kilobytes to hundreds of gigabytes with commensurate increases in cost for the equipment and media. Auto-loading tape-drive systems can accommodate archives that exceed the capacity of the filesystems.

> TIP
Older tape equipment is often available in the used equipment market and might be useful for smaller operations that have outgrown limited backup options.

The equipment is well supported in Linux and, when properly maintained, is extremely reliable. The tapes themselves are inexpensive, given their storage capacity and the ability to reuse them. Be aware, however, that tapes do deteriorate over time and, being mechanical, tape drives can and will fail.

```
# tar cvf /etc > etc.tar
```

All files in the /etc directory will be saved to a file named etc.tar. With an impressive array of options (see the main page), tar is quite flexible and powerful in combination with shell scripts. With the -z option, it can even create and restore g-zipped compressed archives while the -j option works with bzipped files.

# Creating Full and Incremental Backups with tar

If you want to create a full backup,

```
# tar cjf fullbackup.tgz /
```

will create a bzip2 compressed tarball (the j option) of the entire system.

To perform an incremental backup, you must locate all the files that have been changed since the last backup. (For simplicity, assume that you do incremental backups on a daily basis.) To locate the files, use this find command:

```bash
# find / -newer <name of last backup file> ! -type f -print
```

When run alone, find will generate a list of files systemwide and print it to the screen. The -type eliminates everything but regular files from the list; otherwise, the entire directory would be sent to tar even if the contents weren't all changed.

Pipe the output of our find command to tar as follows:

```bash
# find / -newer <name of last backup file> ! -type d -print | \
tar czT - <backup file name or device name>
```

Here, -T gets the filenames from a buffer (where the - is the shorthand name for buffer).

> NOTE
The tar command can back up to a raw device (with no filesystem) as well as a formatted partition, for example,

```bash
# tar -cvzf /dev/hdd /boot /etc /home
```

backs those directories to device /dev/hdd.

The tar command can also back up over multiple floppy disks:

```bash
# tar -cvmf /dev/fd0 /home
```

will back up the contents of and spread the file out over multiple floppies, prompting with this message:
Prepare volume #2 for /dev/fd0 and hit return:

# CHAPTER 11 Backing Up, Restoring, and Recovery

## Restoring Files from an Archive with tar

The x option in tar restore the files from a backup and preserve the file attributes as well, and will create any subdirectories it needs. Be careful when using this option because the backups might have been created with relative or absolute paths. You should use the tvf option with tar to list the files in the archive before extracting so that you'll know where they will be placed.

For example, to restore a tar archive compressed with bzip2,

```bash
# tar xjvf RHLutest.tar.bz2
```

To list the contents of a tar archive compressed with bzip2,

```bash
# tar tjvf RHLutest.tar.bz2
drwxr-xr-x  root      root      2002-09-04 18:15:05 RHLutest/
-rw-rw-r-- root      root      163 2002-09-03 22:33:49 RHLutest/
```

## Backing Up Files with cpio

The i option in cpio restore the files from a backup and preserve the file attributes as well, and will create any subdirectories it needs. Be careful when using this option because the backups might have been created with relative or absolute paths. You should use the tv option with cpio to list the files in the archive before extracting so that you'll know where they will be placed.

For example, to restore a cpio archive,

```bash
# cpio -iv RHLutest.cpio
```

To list the contents of a cpio archive,

```bash
# cpio -tv RHLutest.cpio
drwxr-xr-x  root      root      2002-09-04 18:15:05 RHLutest/
-rw-rw-r-- root      root      163 2002-09-03 22:33:49 RHLutest/
```
