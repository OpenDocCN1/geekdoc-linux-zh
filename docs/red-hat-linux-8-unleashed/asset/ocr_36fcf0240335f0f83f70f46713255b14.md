An IP (Internet Protocol) address helps a computer system identify a networked computer, but it won't help the average person make the identification. The DNS (Domain Name System) is now used universally on the Internet to provide recognizable hostnames, for networked computers.

Hostnames, like redhat.com, are merely a convenience for users. Communication with other computers still requires IP addresses. Each hostname, therefore, must be translatable into a unique IP address. This translation process is called name resolution and is performed by software known as a resolver.

This chapter introduces DNS concepts and practice using BIND (Berkeley Internet Name Domain), the de facto standard software for Unix. In this chapter, you learn some of the concepts that are basic to DNS and its functions, including how DNS structure information is stored, how DNS serves name information to users, and how name resolution actually works. You learn how to use BIND to configure nameservers and how to provide DNS for a domain. This chapter also teaches you some important techniques for keeping DNS functions secure, as well as the most important troubleshooting techniques for tracking down potential problems related to your DNS functions.

If you are not going to be a DNS administrator, much of the information in this chapter will be of no practical use to you. But the knowledge of DNS that you can gain in this chapter might help you understand DNS problems that occur—you'll realize that it is not your computer that is broken!
