# Using the Network File System

To have NFS automatically started when Red Hat boots, use command-line or graphical administrative utilities, such as chkconfig, ntsys, or redhat-config-services. Make sure to have the portmap service started because it is used as part of the service. You can manually start or stop NFS by directly calling its service control script nfs like this:

```
# /etc/rc.init.d/nfs start
Starting NFS services: [ OK ]
Starting NFS quotas: [ OK ]
Starting NFS daemon: [ OK ]
Starting NFS mounted: [ OK ]
```

In this example, NFS has been started. Use the stop keyword to stop the service. This approach at controlling NFS is handy, especially after configuration changes have been made. See the next section on how to configure NFS support on your Red Hat system.

# NFS Server Configuration

The server can be configured by editing the /etc/exports file. This file is similar to the /etc/fstab file in that it is used to set the permissions for the filesystems being exported. The entries look like this:

```
/file/systemyour(options) *.yourdomain.com(options) 192.15.69.0/24(options)
```

This shows three common clients to share /file/system to. The first, your, shares /file/system to just one host. The second, .yourdomain.com, uses the asterisk (*) as a wildcard to allow all hosts in yourdomain.com to access /file/system. The third share allows all hosts of the Class C network, 192.15.69.0, to access /file/share. For security, it is best not to use shares like the last across the Internet because all data will be readable by any network the data passes by.

Some options are shown in Table 13.3.

| Option | Purpose |
| :--- | :--- |
| rw | Gives read and write access |
| ro | Gives read only access |
| async | Writes data when the server feels the need, not the client |
| sync | Writes data as it is received |

The following is an example of an /etc/exports file:

```
# /etc/exports file for myhost.mydomain.com
/usr/local host(ro,show)
/home/jkennedy *.yourdomain.com(rw,hide,sync)
```
