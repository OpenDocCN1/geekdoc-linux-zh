## Using RPM for Software Management

```bash
# rpm -Uvh pine-4.44-7.i386.rpm
Preparing...
#################################### [100%]
########################################################### [100%]
1:pine
```

Note that it wasn't necessary to remove the currently installed software package—the upgrade option (saving the old configuration files), and it then automatically installs the new software.

You can also upgrade your system software by using the rpm command -F or "freshen" option, which will fetch a designated package from a remote FTP or HTTP server. For example, to upgrade the fetchmail-conf package, use rpm like this (the FTP URL has shortened in this example):

```bash
# rpm -Fv http://ftp.tux.org/linux/redhat/updates/7.3/en/i386/fetchmailconf-5.9.0-11.i386.rpm
```

Retrieving http://ftp.tux.org/linux/redhat/updates/7.3/en/i386/fetchmailconf-5.9.0-11.i386.rpm

Preparing packages for installation...
fetchmailconf-5.9.0-11

If you have broadband access, you can upgrade a system in place quickly without taking it to runlevel 1 (see Chapter 7, "Managing System Services"). This is a primary feature of Xim's version of GNOME, http://www.xim.com/. The rpm command will retrieve the designated package, and then upgrade the software on your system. You use the -e option, along with the name of a software package, to remove or erase software from your system with rpm. For example, to remove the pine email package, use the rpm command like this:

```bash
# rpm -e pine
```

Note that if the operation succeeds, no messages will be displayed on the system. You can quickly search for installed packages by piping the output of rpm to grep (see Chapter 7, "Managing System Services"):

```bash
# rpm -qa | grep pine
```

## Linux and Unix Software Management

The Red Hat RPM system is used by a number of Linux distributions. SuSE uses a different management system (using y2), and Mandrake uses rpm. Other Linux distributions, such as Debian, use a different management model (apt-get). FreeBSD, NetBSD, and OpenBSD also have different management systems based on pkg_add and pkg_delete. However, efforts are underway at http://www.openpackages.org/ to unify software delivery and management for BSD and other systems. The new package design will involve a new format, but aims to make the job of building, installing, and maintaining much easier.

## Extracting a Single File From RPM

Occasionally, it is useful to extract a single file from an RPM package. You can do so using the command line version of mc, the Midnight Commander, as shown in Figure 8.1. The Midnight Commander is a UNIX clone of the famous DOS Norton Commander, a file management utility. Using mc, just highlight the RPM file and press Enter; the contents of the RPM file will be displayed. In the listing, you can see the file structure of the RPM file and use mc to copy files from it. You might want to know what a .rpm file will do before you install the application. You can use the F3 key in mc to view the script files. If you want to look at the scripts without using mc, use this command:

```bash
# rpm -q --scripts filename | scripts.txt
```

This command pipes the scripts into a file, using a text editor. You could pipe it to the less pagination mode to view the scripts on your display:

```bash
# rpm -q --scripts filename | less
```

## Working with Source RPM Files

You might want to modify a source package for your own uses such as adding documentation, changing default settings, or patching the source code itself. Red Hat provides the source code to its distribution in the form of source RPM files. You can access the source code on disks 4 and 5 of the downloadable CD images or obtain them from the Red Hat ftp site.
