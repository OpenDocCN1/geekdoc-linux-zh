# Installing the Apache Server

You can install Apache from RPMs or build yourself from source code. The Apache
source builds on just any Unix-like operating system and on Win32.

If you're about to install a new version of Apache, it's probably a good idea to shut down
the old server. Even if it's unlikely that the old server will interfere with the installation
procedure, shutting down ensures that there will be no problems. If you don't know how
to stop Apache, look at the "Starting and Stopping Apache" section later in this chapter.

# Installing from the RPM

You can find the Apache RPM either on the Red Hat installation media, on the Red
Hat FTP server, or one of its many mirror sites. You'll want to check the
updates.redhat.com FTP site (or one of the mirrors) as often as possible to download
ates as they become available. In the directory corresponding to your Red Hat version,
you'll occasionally find updates for Apache. The updated RPM files usually contain import-
tant updates that fix bugs or security breaches. When an updated version comes out,
install it as quickly as possible in order to be secure.

> NOTE

> Check Hat's errata page for bug and security fixes to Apache or stay current using Red's
email advisory list. Browse to http://www.redhat.com/apps/support/errata/index.html for
links to updates. Subscribe to a support list (such as linux-security) at http://www.redhat.com/
mailing-lists/

> If you want the most recent, experimental version of Apache for testing, check Red Hat Rawhide
distribution, which is also available on Red Hat's FTP server (ftp://ftp.redhat.com/pub/
redhat/rawhide/). This distribution is experimental and always contains the latest
versions of all RPMs. However note that the Apache package (httpd) might depend on new
functionality in other RPMs in the Rawhide distribution. Therefore, you might need to
install many new RPMs from Rawhide. If you want to use an
Apache version from the Rawhide distribution for testing, a better option might be download
the source code (SRPM). That way, you will avoid dependencies on
other new packages. (Refer to the "Working with Source RPM Files" in Chapter 8,
"Managing Software and System Resources," for information about building and installing pack-\ages from RPM files).
