Users are then able to access other systems by using the hostname alias (such as balder). The format of /etc/hosts is easy to understand and easy to maintain, and can be used in conjunction with a Dynamic Host Configuration Protocol (DHCP) server on the same network. (Read more about DHCP in Chapter 13, "Network Connectivity.")

Two disadvantages of using /etc/hosts become readily apparent on a large network: maintenance and replication. Maintaining lists of IP addresses, hostnames, and aliases—along with ensuring changes are regularly updated to every host on the network—can be a challenge.

The /etc/hosts file, if it exists, will usually take precedence over nameserver settings in /etc/resol.conf. The file /etc/host.conf, known as the resolver configuration file, determines the order in which name resolution occurs. By default with Red Hat, this file contains

+   - hosts, bind

The order shown here is to first consult /etc/hosts and then use DNS (BIND). The file /etc/nswitch.conf also defines a search order for host information, but files such as /etc/hosts, DNS, and Network Information Service (NIS). One example could be

+   - files dns [NOTFOUND=return] nisplus nis

In this example, the order is as shown previously, but failed searches will default to NIS (nisplus and nis). NIS with Red Hat is the ypserv daemon. The configuration of /etc/nswitch.conf is handled automatically when you use the redhat-config-network tool.

Successful DNS lookups depend on the system's networking being enabled and correctly configured. You can learn more about how to accomplish that in Chapter 15, "Internet Connectivity."

# Essential DNS Concepts

We begin with a look at the ideas behind DNS, independently from the details of the software-used to implement it. An understanding at this level is invaluable in avoiding the majority of problems, as well as diagnosing and quickly solving the ones that occur. The following overview omits small details in the protocol because they aren't relevant to the everyday tasks of a DNS administrator. If you need more information about DNS, consult the DNS standards, especially RFC 1034. The RFCs related to DNS distributed with BIND. Red Hat installs them in /usr/share/bind-9.2.0/rfc/.
