
The items shown are networking parameters, and actually tweaking these values is beyond the scope of this book. If we wanted to change a value, however, the -w command is used:

```bash
# sysctl -w net.ipv4.tcp_retries = 20
```

This increases the value of that particular kernel parameter.

> NOTE
> Red Hat provides a graphical interface to the sysctl command in redhat-config-proc. It's a beta-quality application, and it must be launched from the command line. The interface itself is unremarkable, and it does not provide a means to manipulate all the possible values, but it offers useful help for the kernel variables' addresses.

If you find that a particular setting is useful, you can enter it into the /etc/sysctl.conf file. The format is as follows, with the earlier example:

```
net.ipv4.tcp_retries = 20
```

Of more interest to kernel hackers than regular users, sysctl is a potentially powerful tool that continues to be developed and documented.

> When Choice Is Not Good
> Whereas Mac and Windows users are typically provided with only one version of a productivity application (and only one desktop environment), Linux users are presented with many choices of both applications and desktop environments. Traditionally, the main menu has provided all applications for you. The necessity of choosing from a number of different desktop environments and, for example, dozens of text editors is a daunting task to the new Linux user, and it has been the source of many complaints from corporate users. Further, Red Hat must provide support for every application it includes in the distribution.

Beginning with version 8.0, Red Hat addressed these concerns by limiting the menu choices that are available from the main menu and limiting the overall number of available applications. Now, only a single application for any application category is presented in the main menu: only one processor, only one address book, and so on. In limiting, Red Hat has selected the productivity applications it believes are the best available, choosing an unofficial “Red Hat Suite” that is based on the OpenOffice.org suite. So that Red Hat has added applications taken from GNOME office applications and the KDE desktop.

The Red-selected office components are available in the main menu under the Accessories, Graphics, Office, and Sound & Video menus. All other applications are found in the Extras menu, which contains a duplication of the main menu. The Extras menu contains the menu entries for all the applications provided by Red Hat that did not make the cut to become the default choices. For the corporate IT manager and Red Hat, a simple edit to the menu configuration file removes the Extras from view and simplifies the support that must be provided.

For individual users, Red Hat’s approach causes a problem because Red Hat scatters applications throughout the menu tree. Worse, the default desktop environment chosen by Red Hat (GNOME 2.0) does not provide a menu editor. Obviously, Red Hat has not finished with its menu design, and it is likely it will change in the future. You will see those changes as you update your installation of Red Hat over time.
