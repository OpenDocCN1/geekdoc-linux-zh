# Controlling Apache with Red Hat’s service

Instead of directly calling the /etc/rc.d/init.d/httpd script, you can use Red Hat’s service command to start, stop, and restart Apache. The service command is used with the name of a service (listed under /etc/rc.d/init.d) and an optional keyword:

```
# service <name_of_script> <option>
```

For example, you can use service with httpd and any option discussed in the previous section like so:

```
# httpd restart
```

This restarts Apache if it’s running, or starts the server if it isn’t running.

# Controlling Apache with Red Hat’s chconfig Command

The chconfig command provides a command-line-based interface to Red Hat’s service scripts. The command can be used to list and control what services will be started, restarted, and stopped for a specific system state (such as when booting up, restarting, or shutting down) and run level (such as single-user mode, networking with multitasking, or graphical login with X).

For example, to view your current settings, take a look at Red Hat’s default run level defined in the system initialization table /etc/inittab using the grep command:

```
# grep id /etc/inittab
id:3:initdefault:
```

This example shows that this Red Hat Linux system will boot to a text-based login without running X11. You can then use the chconfig command to look at the behavior of Apache for that run level:

```
# chconfig --list | grep httpd
httpd 0:off 1:off 2:off 3:off 4:off 5:off 6:off
```

Here you can see that Apache is turned off for run levels 3 and 5 (the only in a default Red Hat system, although you could create a custom run level 4 for Apache). Use level, httpd, and the control keyword on set Apache to automatically start when booting to run level 3:

```
# chconfig --level 3 httpd on
```
