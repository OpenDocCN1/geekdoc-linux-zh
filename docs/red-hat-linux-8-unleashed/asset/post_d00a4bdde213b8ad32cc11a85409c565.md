In make menuconfig, you use the arrow keys to move the selector up and the spacebar to move the focus at the bottom of the screen to either Select, Exit, or Help.

If a graphical desktop is not available, menuconfig is the best you can do. However, both of these utilities offer an improvement over editing the config file directly, but if you want to configure the kernel through a true graphical interface—with mouse support and clickable buttons—make xconfig is the best configuration utility option. To use this, you must have the X Window System running. The application xconfig is really nothing but a Tcl/TK (a Window widget providing borders, menus, dialog boxes, and the like) interface used to wrap around data files that are parsed at execution time. Figure 24.3 shows the main menu of xconfig for the 2.4.19 kernel.

After loading this utility, you use it by clicking on each of the buttons that list the configuration options. Each button you click opens another window that has the detail configuration options. Three buttons are at the bottom of each window; Main Menu, Next, and Previous. Clicking the Main Menu button closes the current window and displays the main window. Clicking Next takes you to the next configuration section.

When configuring a kernel from scratch, click on the button Code Maturity Level Options, then continue to click the Next button in each subsection window to proceed through all the kernel configuration choices. When you have selected all options, the main menu is again displayed. The buttons on the lower right of the main menu are for saving and loading configurations. Their functions are self-explanatory. If you just want to have a look, go exploring! Nothing will be changed if you elect not to save it.

If you are upgrading kernels from a previous release, it isn't necessary to go through the entire configuration from scratch. You can use the directive **oldconfig**. It is the text interface that make **config** uses and it is non-interactive.

## Using xconfig to Configure the Kernel

For simplicity's sake, during this brisk walk, we will assume that you are using **make xconfig**. Prior to this, we also assume that you have completed steps 1–5 in our kernel compilation checklist shown previously.

As you learned in the preceding section, you compile the kernel using make xconfig by making choices in several configuration subsection windows. This subsection window contains specific kernel options. With hundreds of choices, the kernel is daunting to configure. We can't really offer you detailed descriptions of options to choose because your configuration will match your system and setup.

Table 24.1 provides a brief description of each subsection's options so that you can copy your kernel's .config file to /usr/src/linux-2.4 and run make xconfig from there. We recommend that an idea of what you might encounter. Explore all the options. As long as you don't save the file, absolutely nothing will be changed on your system.

### TABLE 24.1 Kernel Subsections for Configuration

| Name | Description |
| --- | --- |
| Code maturity level options | Allows development code to be compiled into the kernel even if it has been marked as obsolete or as testing code. This option should only be used by kernel developers or testers because of the possible unusable state of the code during development. |
| Loadable module support | Determines whether the kernel allows drivers and other non-essential code to be compiled as loadable modules that can be loaded and unloaded at runtime. This option keeps the basic kernel small so that it can run and respond more quickly; in that regard, choosing this option is generally a good idea. |
| Processor type and features | Several options dealing with the architecture that will be running the kernel. |
| General setup | This section contains several options covering how the kernel talks to the BIOS, should it use PCI or PCMCIA, should it use APM or ACPI, and what kind of Linux binary formats will be supported. |
| Binary emulation of other systems | Contains several options for supporting kernel structures necessary to run binaries for other systems without recompiling the program. |
| Memory Devices (MTD) | Options for supporting flash memory devices, such as EEPROM. Generally, these devices are used in embedded systems. |
| Parallel port support | Several options for configuring how the kernel will support port communications. |
| Plug and Play configuration | Options for configuring devices Universal Serial Bus (USB) Human Interface Devices (HID). These include keyboards, mice, and joysticks. |
| Block devices | Section for devices that communicate to the server in sequential characters. This is a large subsection containing the drivers for several motherboard chipsets. |
| Multi-device support (RAID and VLAN) | Options for supporting types of RAID. This includes options for local volume manager. |
| Networking options | Configuration options for network chipsets and card support. Covers AppleTalk, Arcnet, Ethernet, FDDI, HPPI, PCMCIA, and Token Ring cards. Amateur Radio support. |
| Telemetry Support | Support for devices that support the AX25 protocol. |
| ATA/IDE/MFM/RLL support | Large collection of options to configure the kernel using different types of data communication to mass storage. |
| SCSI support | Options for configuring the kernel to support Small Computer Systems Interface. This covers drivers for specific cards, chipsets, and tunable parameters. |
| Fusion MPT device support | Configures support for LSI's Fusion Message Passing Technology. This technology is for high performance SCSI and local area interfaces. |
| Network device support | Options for supporting Intelligent Input/O architecture. This architecture allows the hardware driver to split from the operating system driver, allowing a multitude of hardware devices to be compatible with any operating system in one implementation. |
| Amateur Radio support | Options for configuring support of devices that support the AX25 protocol. |
| IrDA (infrared) support | Options for configuring support of the Infrared Association suite of protocols and devices that use these protocols. |
| ISDN subsystem | Options to support Integrated Services Digital Networks protocols and devices. ISDN is a method of connection to a large area network digitally over conditioned telephone lines, found to connect users to ISPs. |
| Old CD-ROM drivers | Options to support obscure, older CD-ROM devices that don't conform to the SCSI or IDE standards. These are typically older CD-ROM drivers that are usually a proprietary type of SCSI. |
| Input core support | Options for configuring devices Universal Serial Bus (USB) Human Interface Devices (HID). These include keyboards, mice, and joysticks. |
| Character devices | Configuration options for devices that communicate to the server in sequential characters. This is a large subsection containing the drivers for several motherboard chipsets. |
| Multimedia devices | Drivers for hardware implementations of video and sound devices such as video capture boards, TV cards, and AM/FM radio adapter cards. |
| Cryptographic Hardware Support | Support for cryptography hardware. |
