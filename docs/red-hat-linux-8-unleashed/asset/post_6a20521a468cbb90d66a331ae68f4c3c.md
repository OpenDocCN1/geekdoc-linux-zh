If you reboot your system to mount the root filesystem read-only for maintenance (enter the maintenance mode, s, as described in Chapter 7,

```
# mount -o rw,remount /
```

will remain read-write and you can continue on. That's easier than unmounting and remounting the device.

## Converting an Existing ext2 Filesystem to ext3

An existing ext2 filesystem is easily converted to ext3 to take advantage of the benefits of journaling. When you convert an existing ext2 filesystem to ext3, any other operating system—including BeOS, Windows (with the appropriate drivers), and other UNIX systems that have drivers to access ext2 partitions—can access ext3 partitions. To those operating systems (and their drivers), your converted filesystem still looks just like an ext2 filesystem.

To begin the convert to ext3, use the tune2fs utility to add the journal to an existing ext2 filesystem. In this example, you are changing /dev/hda2, an already formatted ext2 partition.

```
# tune2fs -j /dev/hda2
```

It doesn't matter if hda2 is mounted or unmounted at the time of the migration; if it is mounted, you will see a new file, .journal1, in the directory.

Next, edit the line for /dev/hda2 in /etc/fstab and change the value from ext2 to ext3. It will be mounted as an ext3 filesystem the next time you reboot.

> NOTE
If you have decided to convert your root filesystem to take advantage of the benefits of the ext3 filesystem, bear in mind that you cannot run tune2fs - while it's unmounted because you can't mount the root filesystem. Because the filesystem is mounted when you run tune2fs -, the .journal1 file will be visible when you finish the migration.

When compiling a new kernel, make certain to include ext3 filesystem in your kernel by selecting that in your kernel configuration (see Chapter 24, "Kernel and Module Management"). Also, note that you do not need to perform the actions described in the next section if you have just freshly installed Red Linux.

## Making an Initial Ramdisk

You need to create an initrd image file to load the ext3 driver and mount the root partition as an ext3 partition. The initrd file is an initial ramdisk that contains a small kernel and enough of the Linux OS to load drivers so that the real kernel and the rest of the operating system can load.

> NOTE
If you forget to create the initrd file, your system will still boot, but it will mount the root partition as ext2. That's very clever—none of the other journaling filesystems are as forgiving.

To create the file, run the mkinitrd utility before you reboot.

```
# mkinitrd 2.4.18-3 initrd-2.4.18-3.img
```

The first argument after the mkinitrd command is the version of the kernel you want to use. The value you enter doesn't have to be the version you are currently using, but it must match the version you use when boot (and the kernel must support ext2). The second argument is the name of the initrd file that will be placed in the /boot directory. The name can be anything; the name shown here follows the usual naming convention; you can find a number of other naming options in the mkinitrd man page.

After you run the utility, edit /etc/lilo.conf or /grub.conf to change the initrd loaded at boot time. Add the following line to the appropriate LILO stanza:

```
initrd=/boot/initrd-2.4.18-3.img
```

If you are using GRUB, add the same line beneath the kernel line in the section that references your kernel.

```
initrd (hd0,0)/boot/initrd-2.4.18-3.img
```

## Examine an initrd Image File

The initrd.img file is automatically created during the installation process (if necessary) or with the mkinitrd command. You never need to examine it, but if you are curious about what's in the initrd.img file, just take a look: it's a gzipped ext2 filesystem. To examine it, first copy it to the /tmp directory and add the .gz suffix to it:

```
# cp /boot/initrd-2.4.18-3.img /tmp/initrd-2.4.18-3.gz
```

If your system doesn't have an initrd.img file in /boot, mount your boot floppy if it has one. Uncompress it as follows:

```
# gunzip /tmp/initrd-2.4.18-3.gz
```

mount it as follows:

```
# mount -o loop /tmp/initrd-2.4.18-3.img /mnt/
```

Not every system will have initrd.img file. It's typically used to load device drivers for filesystems (like Reiser) or hardware (like RAID controller) that must be placed before the system can continue. Some floppy-based Linux distributions use initrd.img to load a minimal operating system that can decompress and load the file from. You can mount .iso images in the same way, but remember that they are always read-only because of the nature of the underlying iso960 filesystem; if you want to read and write to iso, you must first copy the files to a device that is mounted read-write, make your changes, and then use mkisofs to create a new .iso image. This is a common "gotcha" for many users.

## Examine Floppy Image

The boot images on the installation CD have different configurations to address special situations. If you find the need to modify one for your unique situation or if you are curious to know what is in any of the boot images, mount the image as follows:

```
# mount -o loop /mnt
```

## Disk Tuning

Many Red Hat users love to tinker under the hood to increase the performance of their computers, and Linux gives you some great tools to do that. Whereas Mom used to tell me "Don't fix what is broken," Dad always said "Fix it until it breaks." In this section, you will learn about many of the commands used to tune or tweak your filesystem. Before you undertake the work with Red Hat Linux, however, keep a few points in mind. First, perform a benchmark on your system before you begin. Linux doesn't offer a well-developed benchmarking application, but availability changes rapidly. You can search online for the most-to-date information for benchmarking applications. Second, tweak only one thing at a time so you can tell what works, what doesn't work, and what breaks. Some of these tweaks might not work or might lock your machine.

> TIP
Be aware, although the resulting numbers generated by hdparm command to produce a disk transfer speed result appear quantitative, they are subject to technical qualifications beyond the scope of what is discussed and explained in this chapter. Simply put, don't accept values generated by hdparm as absolute numbers, but only as a relative measure of performance. Use hdparm device. Always have a working boot floppy handy and remember that you are personally assuming all risks for attempting any of these tweaks. Additional systemwide tuning tips can be found at Tune Linux site at http://www.tunelinux.com/.

## Using the BIOS and Kernel to the Disk Drives

One method of tuning involves adjusting the settings in your BIOS. Because the BIOS is not Red Hat Linux and every BIOS seems different, read your motherboard manual for better settings and make sure that all the drives are detected correctly by the BIOS. Change only one at a time. Linux provides a limited means to interact with BIOS settings during the boot process (mostly overriding them). In this section, you will learn about those commands.

Linux uses both hd.c and ide.c as IDE driver code. One or both can be compiled into the kernel; ide likely be a module. The hd.c code is used for compatibility with older IDE controllers and is used by default on ide0. If you have more hardware, the use of the new code using the LILO command parameter ide=0x1f0 can be entered at the initial LILO prompt, added by editing the GRUB boot menu, or placed in the append=line of /etc/lilo.conf or at the end of the kernel line in /boot/grub.conf. The use of this option might or not have benefit to you.

Other options are in the following list, and are more fully outlined in the BOOTPROM HOWTO and the kernel documentation. These commands can be used to force the IDE controllers and drives to be optimally configured. Of course, YMMV (Your Mileage Vary) because these don't work for everyone.

- ide=dna—This will DMA support to be turned on for the primary IDE bus, where x=0, or the secondary bus, x=1.
- ide=autune—This command will attempt to tune the interface for optimal performance.
- ide=ata66—If you have ATA66 drives and controllers, this command will enable support for it.
- hdx=scsi—This command will enable SCSI emulation of an IDE drive. This is required for CD-RW drives to work properly, and it might provide some performance improvements for CD-R drives as well.
- idebus=xx—This can be any number from 20 to 66, autodetection is attempted, but this can set it manually if dmesg says it is not autodetected correctly or if you set it in the BIOS to a different value (overclocked). Most PCI controllers will be happy with 33.
- pci=biosirq—Some motherboards might cause Linux to generate an error message saying that you should use this. Look in dmesg for if you don't need to use it.
