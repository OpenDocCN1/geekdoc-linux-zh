# CHAPTER 24 Kernel Module Management

At this juncture, you have two options:

+   - Fix the errors and recompile.
- Remove the offending module or option and wait for the errors to be fixed by the kernel team.

Most users will be unable to fix the errors because of the complexity of the kernel code, although you should not rule out this option. It is possible that the same error has been discovered by someone else testing of the kernel and has developed a patch for the problem. Check the Linux mailing list archive the problem might have been encountered before. If the problem is not mentioned there, a search on Google might turn up something.

If you are knowledgeable about coding and kernel matters, you might want to look in the Maintainers file in the /usr/src/linux-2.4/documentation directory of the kernel source and find the maintainer. The recommended course of action is to contact the maintainer and see if he is aware of the problems you are having. If nothing has been documented for the specific error, submitting the error to the kernel mailing list is an option. The guidelines for doing this are in the README in the base directory of the kernel source under the section "When Something Goes Wrong."

Finally, you should wish to take on the task of trying to fix the problem yourself, this is a great opportunity to get involved with the Linux kernel and make a contribution that could help many others.

The second option, removing the code, is the easiest and is what most people do in cases where the offending code is not required. In the case of the NTFS module failing, it is almost expected because NTFS is considered experimental and subject to errors. This is primarily because the code for the filesystem is reverse engineered instead of implemented with documented standards. Read-only support has gotten better in recent kernels; write support is still experimental.

# Runtime Errors, Boot Loader Problems, and Kernel Oops

Runtime errors occur when the kernel is loading. Error messages are displayed on the screen or written to the /var/log/messages file. Bootloader problems display messages to the screen; no log file is produced. Kernel oops are errors in a running kernel, and error messages are written to the /var/log/messages file.

Excellent documentation on the Internet exists for troubleshooting just about every type of error that LILO or the kernel could give during boot. The best way is to go to your search engine and type in the keywords of the error you received. You'll need to adjust the keywords you use as to focus your search.
