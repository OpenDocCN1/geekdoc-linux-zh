# The User Login Process

It's useful to know what happens when a user attempts to log in—if for nothing else than troubleshooting for that user in the accounting department who can't get logged on to run the payroll program and get the payroll checks printed on time. Understanding this process also involves understanding the purpose of the files that are found in /etc/skeleton. This section helps illuminate the login process for you.

The login process is used for entering, or “signing on” to a system.

The login process is summarized as follows:

+   1. Login prompts for a username.
2. If the /etc/nologin file exists and the user isn't root, a warning message is issued and the login process is halted. The /etc/nologin file is typically used when the system will be shut down and new logins should be restricted.
3. The /etc/tty file is examined to see if any restrictions are specified for the user. As a security measure, root logins can be restricted to specific terminals, and regular users can have the same restrictions placed on as necessary.
4. The system prompts for a password: it is checked against the encrypted password kept in /etc/shadow. Unsuccessful attempts are logged via the syslog facility and can be reviewed with the lastd command.
5. The UID and the GID of the tty (terminal) being used are set.
6. The TERM environment, if it has been set, is preserved.
7. The HOME, PATH, SHELL, TERM, MAIL, and LOGNAME environment variables are set. If the -p option is used, all preexisting environmental variables are preserved.
