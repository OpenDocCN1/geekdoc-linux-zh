# The FTP User

During the rpm installation, an FTP user was added to the /etc/passwd file. This user is not a normal user per se, but a name for anonymous FTP users. The FTP user entry in /etc/passwd looks like this

```
ftp:x:14:50:FTP User:/var/ftp:/sbin/nologin
```

The FTP user, as discussed here, applies to anonymous FTP configurations and server setup. The RPM package creates an entry for the FTP user, but it doesn't set a default shell or create the /var/ftp directory.

Also, note that other Linux distributions use a different default directory, such as /usr/local/ftp, for FTP files and anonymous users.

This entry follows the standard /etc/passwd format: username, password, password, user id, group id, comment field, home directory, and shell.

To learn more about /etc/passwd, see the section "The Password File" in Chapter 9, "Managing Users."

Each of the items in this entry is separated by colons. In the preceding example, you can see that the Red Hat system hosting the server has the shadow-utils package installed because it has an x in the password field. The shadow password system is important because it adds an additional level of security to Red Hat Linux; the shadow password system normally is installed during the Red Hat installation.

The FTP server uses this account to assign permissions to users connecting to the server. By using a default shell of /sbin/nologin for anonymous users versus /bin/bash or some other standard, interactive shell, an FTP user, will be unable to log in as a regular user. /sbin/nologin isn't a shell, but program assigned to an account that has been locked. As root inspection of /etc/shadow file shows (see Listing 18.1), it's impossible to log into this account, denoted by * as the password.

# LISTING 18.1 Shadow Password File Entry

```
# cat /etc/shadow
bin:*:18999:0:99999:7::
daemon:*:18999:0:99999:7::
adm:*:18999:0:99999:7::
lp:*:18999:0:99999:7::
ftp:*:18999:0:99999:7:::
```

The shadow file (only a portion of it is shown in Listing 18.1) contains additional information not found in the standard /etc/passwd file, such as account expiration, password expiration, when the account is locked, and the encrypted password. The * in the password field indicates that the account isn't a standard login, thus doesn't have a password. Although passwords are in our system, the password are not transmitted in a secure manner when using FTP. Because FTP was written before the necessity of encryption and security, it doesn't provide the mechanics to send encrypted passwords. Account information is stored in plain text on FTP servers; anyone with enough technical knowledge and a network sniffer can find the password for the account you connect to the server. Many sites use anonymous-FTP server specifically to prevent normal account passwords from being transmitted over the Internet.

# Setting Permissions to Secure Your FTP Installation

# Quick and Dirty FTP Service

Conscientious Red Hat administrators will take the time to carefully install, set up, and configure a production FTP server before offering public service or opening up for business on the Internet. However, you can set up a server very quickly on a secure LAN by following a few simple steps:

- 1. Ensure the FTP server RPM package is installed, networking is enabled, and firewall rules on the server allow FTP access. See Chapter 13, "Network Connectivity," to see how to use Red Hat's redhat-config-securitylevel client for firewall.
- 2. If anonymous access to server files is desired, populate the /var/ftp/pub directory. By doing this by mounting or copying your content, such as directories and files under this directory.
- 3. Edit, and save the appropriate /etc/xinetd.d configuration file (such as wu-ftpd or vsftpd) to enable access.
- 4. Start or restart xinetd like so: /etc/rc.d/init.d/xinetd restart.

# Setting Permissions to Secure Your FTP Installation

After installation, some cleanup might be necessary to ensure the most secure permissions are assigned to the files the server will use during a session. Execute the following commands as root to proper locked-down permissions.

```
chmod 111 /var/ftp/bin/* /var/ftp/bin /var/ftp/etc /var/ftp/lib
chmod 444 /var/ftp/etc *
chmod 555 /var/ftp /var/ftp/lib/* /var/ftp/pub
```

These permissions will modify the read, write, and execution permissions of files and directories /var/ftp. Files that are placed in /var/ftp/pub will be accessed during their FTP sessions, but should have the read permission for the FTP user only.

```
chmod 444 file_name
```

Additionally, you need to add and execute permissions to any subdirectories created in /var/ftp/pub to enable directory listings.

```
chmod 555 subdirectory_name
```
