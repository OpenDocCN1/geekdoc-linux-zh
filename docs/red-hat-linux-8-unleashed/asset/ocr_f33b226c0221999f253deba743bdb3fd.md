# The Mail Delivery Agent

SMTP was designed to deliver mail to systems that are always connected to the Internet. Dial-up systems only connect at the user command and for specific operations, and are frequently disconnected. To accommodate this, many systems also include a mail delivery agent, or MDA. The MDA transfers mail to systems without permanent Internet connections. The MDA is similar to an MTA (see next paragraph), but does not handle deliveries between systems and does not provide an interface to the user. Procmail or Spassassin are examples of MDAs; both provide filtering services to the MTA.

The MDA uses the POP3 and IMAP protocols for this process (see the Note for more information on these protocols). In a manner similar to a post office at the post office, POP3 and IMAP implement a “store and forward” process that alleviates the need to maintain a local mail server if all you want is read your mail. For example, dial-up Internet users connect to their ISP’s mail server to retrieve mail using "Fetchmail to Retrieve Mail," later in this chapter.

# The Mail User Agent

The mail user agent, or MUA, is another necessary part of the email system. The MUA is a client that uses the email engine to compose and provides the user interface. If the email application itself is not, most users are familiar with “email.” Some popular UNIX command-line MUAs are elm, pine, and matt. Red Hat also provides modern GUI MUAs: Mozilla Mail, Balsa, Evolution, Sylpeed, and Kmail. For comparison, common non-UNIX MUAs are Microsoft Outlook, Outlook Express, Eudora, and Netscape Messenger.

The Microsoft Windows and Macintosh MUAs often include some MTA functionality; UNIX does not for. For example, Microsoft Outlook can connect to your Internet provider’s mail server to send messages. On the other hand, UNIX MUAs generally rely on an external MTA. This might seem like a needlessly complicated way to do things, and it is for a single user connected to their IPS. For any other situation, it allows you much greater flexibility because you can use a great number of external programs to handle your email functions and customize the service. Having the process handled by different applications allows you to control how you provide email service to users on your network as well as individual and SOHO users.

- Use Sendmail to send your mail
- Use xbf to notify you when you have new mail
- Use Procmail to automatically sort your incoming mail based on sender, subject, or many other variables
- Use Spassassin to eliminate the unwanted messages
