# The Red Hat Linux Filesystem Basics

+   - Coda—Similar to NFS, Coda offers for disconnected operation and security caching (keeping a local copy of files in case the network connection is lost). Red Hat only provides compatibility with Coda; the actual client and server code is available from http://www.coda.cs.cmu.edu/

+   - InterMezzo—Similar in features to Coda, InterMezzo is a GPL project. The server daemon can be obtained from http://www.inter-mezzo.org/

+   - NCP—Used to mount Novelle Volumes, its is more fully described in the Linux Network Administrators Guide at http://www.tld.org/LDP/nag2/x-087-2-ipx.ncpfs.client.html.

+   - SMB—The network-focused Server Block protocol was developed by Microsoft. The Linux implementation is known as Samba and currently works well. It is typically used between Linux and Microsoft Windows peers. Netalk the Macintosh equivalent protocol.

Disk filesystems are found on a physical device; they are the hard drive in your desktop or laptop computer. Some common disk filesystems are

+   - FAT is a de-oriented, table-based (a linked list) filesystem used by Microsoft. It has been regularly extended to add functionality. Microsoft’s Enterprise-level filesystem is known as NTFS. (You learn more about this system in “DOS Filesystems,” later in this chapter.)

+   - ext2, ext3, and ReiserFS are inode-based. (You learn about ReiserFS in “The Reiser Files,” later in this chapter.)

> NOTE
The information that constitutes a file in the ext2/ext3 filesystem begins with the inode.

The JFS (Journaled File System from International Business Machines) and XFS (from Silicon Graphics, Inc.) filesystems are available for use with Red Hat Linux, but primarily as migration aids for those existing filesystems to Linux.

A journaling filesystem adds a, or hidden file, to the data on the drive. Because of the way data is written to a disk, the kernel might be holding some version of the data while it is deciding where to place it. If your computer were to suffer a failure, that cached data would be lost. A journaling filesystem keeps that data in a special place until the kernel decides to write it to the disk. If a system failure occurs, a special application (fsck) knows that the data was never formally written and will make sure it is written in the correct place. Journaling filesystems are actually much more complex than this, but the mechanisms of them are beyond the scope of this chapter. Journaling filesystems such as ext3, ReiserFS, JFS, and XFS are major improvements over older, non-journaling files.
