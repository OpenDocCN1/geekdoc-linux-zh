Which modes?
You enter one or more numbers to select the modes (which is useful if you want to try switching resolutions while using X), and then you press Enter. You are then asked about virtual resolution:

You can have a virtual screen (desktop), which is an area larger than the physical screen which is accessed by moving the mouse to the edge of the screen. If you don't have virtual desktop at a certain resolution, you cannot have modes that are larger. Each color depth can have a differently-sized virtual screen.

Please answer the following question with either 'y' or 'n'. Do you want a virtual screen that is larger than the physical screen?

Using X desktop with virtual resolution is necessary if you need to run a client that requires 1024x768 but your hardware is limited to 800x600. Fortunately, most monitors (and even laptops) now support the popular X session resolution of 1024x768. To set a virtual resolution, you type y and follow the prompts. After you finish the configuration, you select a resolution for each color depth:

For each depth, a list of modes (resolutions) is defined. The default resolution that the server will start-up with will be the first listed mode that can be supported by the monitor and card.
Currently it is set:

```
"640x480" "1024x768" "1280x1024" for 8-bit be"1024x768" for 16-bit
"640x480" "800x600" for 24-bit
```

Modes that cannot be supported due to monitor or clock constraints will be automatically skipped by the server.

- 1 Change the modes for 8-bit (256 colors)
- 2 Change the modes for 16-bit (32K/64K colors)
- 3 Change the modes for 24-bit (24-bit color)
- 4 The modes are OK, continue.

Enter your choice:

If possible, you should use a number that provides a 16-bit value because most Linux clients and X sessions work well at a color depth of thousands of colors. You can also choose a 24-bit setting (providing millions of colors) if it is supported by your hardware.
Next, you select a default color depth:

Please specify color depth you want to use by default:

- 1 1 bit (monochrome)
- 2 4 bits (16 colors)
- 3 8 bits (256 colors)
- 4 16 bits (65536 colors)
- 5 24 bits (16 million colors)

Enter a number to choose the default depth.

After you select a depth, you press Enter to finish the configuration, and you see the following:

I am going to write the XF6Config file now. Make sure you don't accidentally overwrite a previously configured one.

Shall I write it to /etc/X11/XF6Config?

You can save the file by entering y. You can enter n to write the file elsewhere or to write with a different name.

At this point you are done configuring the XF86Config file. However, you might want to examine, edit, or test the file before you use it. You test it by launching XFree86 and using the -xf86 option. Regardless of the configuration tool you used for the XF86Config file, when you start or boot to an X session, the server looks for an XF86Config file to use for launching X in the following locations:

- /etc/X11
- /usr/X11R6/etc/X11
- /etc
- /usr/X11R6/lib/X11
- /root

Note that the server is able to use a configuration file found under the /root directory only if you start an X session as root (which is advisable only when your PC is not connected to a network or for testing). After you test the XF86Config file, you should copy the resulting XF86Config file to its traditional location, /etc/X11, with the name XF6Config.

> NOTE If you have legacy video cards that are not supported by the current version of XFree86, you can go to http://www.xfree86.org to download XFree86 version 3.3.6. You might then be able to create a working environment on your platform.

# XFree86 to Configure X

You can create the XF86Config file manually by typing one from scratch using a text editor, but you can also create one automatically by using the XFree86 server or configuration utilities (as discussed in the previous sections). As the root operator, you can use the following on the server to create a test configuration file:

```
# XFree86 -configure
```
