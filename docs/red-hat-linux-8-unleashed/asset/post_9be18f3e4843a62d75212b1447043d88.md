
## CHAPTER 10 Managing the Filesystem

The syntax for mount is

```
mount -t type filesystem_to_be mounted mount_point
```

Here are the components of the mount command, and a brief explanation of each:

- -t: Always preceded by the -t argument and followed by a space, and then the type of filesystem you are mounting. Typical filesystems are: ext2, vfat, iso9660, umsdos, msdos, hpf, hfs, ntfs, and for many systems, mount can detect what type they are, and this argument is superfluous.
- filesystem_to_be: (as represented by the partition on which it resides)—This is the device name of the filesystem you want to mount, typically in the form of /dev/hdnx, /dev/scxn, /dev/fdx.
- mount_point: The place in the directory where you want to mount the filesystem. Curiously, you can mount a filesystem over part of an existing filesystem, if you have an existing directory at /etc/ with a single file name bar, and you mount a filesystem at /foo that includes a file named snafu, a listing of the directory /foo won't show the file bar, but only the file snafu. To show both files is a feature called transparency, which unfortunately isn't in the current Linux repertoire.

The only restriction to “mount anything anywhere” is that the critical system files in /bin, /etc, /lib, /dev, /proc, and /tmp need to be accessed at bootup, which typically means they need to be on the same physical disk. If they can't be accessed at bootup, Linux won't load and run.

Here are a few examples of using the mount command:

Mounting a floppy:

```
# -t vfat /dev/fd0 /mnt/floppy
```

Mounting a CD-ROM:

```
# -t iso9660 /dev/cdrom /mnt/cdrom
```

Mounting a Network File System (NFS) volume:

```
# -t nfs remote_host:/dir [options] /mount_point
```

Numerous mount options exist. These are used primarily in the /etc/fstab file. You can invoke a mount option by preceding it (or a, comma-delimited string of options) with the -o switch. The mount options are listed in the fstab section of this chapter.

## The umount Command

To unmount a filesystem, use the umount command with the following syntax:

```
umount mount_point
```

## Mounting Filesystems

You can also unmount device name:

```
umount device name
```

**CAUTION** Don't unmount -a everything bad that the system doesn't require to run (or isn't currently using). This is a particularly bad idea on a multiuser, networked system because your users will undoubtedly lose access to some or all of their files. So, as any good sysadmin will tell you, do not do that.

## Mounting Automatically with /etc/fstab

A special file, /etc/fstab, exists to provide the system with predetermined options and mountpoints so that the filesystems can be automatically mounted or manually mounted with minimal typing and having to recall arcane Linux syntax.

The /etc/fstab file can only be written to the superuser. The commands fsck, mount, and unmount all read information from /etc/fstab. Each filesystem gets its own line with the information separated by tabs.

On each line of file, the first field identifies the block device or remote filesystem that will be mounted. The second field identifies the mount point on the local system where the filesystem will be mounted. The third field is the filesystem type, and the fourth field is a comma-delimited list of mount options. Options include

- exec: If this option is specified, binaries cannot be executed from this filesystem.
- auto: This means that the -a option won't cause the filesystem to be mounted and it won't mounted at bootup.
- noexec: If this option is specified, binaries cannot be executed from this filesystem.
- nosuid: This option does not permit user-identifier or group-identifier bits to take effect.
- ro: This option mounts the filesystem as read-only.
- rw: This option mounts the filesystem as read/write.
- sync: Reading from and writing to the files are done synchronously.
- user: This option allows a regular (not just root) user to mount the filesystem, but it includes the options noexec, nosuid, and nodev by default unless they are overridden by exec, dev, and sued.

For iso9660 filesystems, the interesting option is to unhide, which shows hidden and associated files.
The fstab man contains an in-depth description of fstab and its options.

The fifth field of /etc/fstab is wiped by dump (a traditional UNIX backup program) to determine whether the filesystem should be dumped (backed up); 1 is yes, and 0 is no. Default values are set for you during the initial installation. They are of concern only if you actually use dump; then you would set the value to 1 for the filesystems you wanted to back up.

The sixth field is by fsck to determine how fsck interacts with the filesystem—0 means that fsck is never run on the filesystem (a FAT32 filesystem, for example); 1 means that fsck will be run on the drive at a predetermined time. 2 is recommended for non-root systems so that fsck isn't run as frequently as.

> NOTE
Device labels can be very useful. You can use the label in /etc/fstab, and if you have many devices, their labels might be easier for you to remember and track their device names. You can also shuffle partitions without editing /fstab, just by changing their labels. The e2label command is easier to remember than the analogue tune2fs command (Because UNIX commands aren't really that easy to remember, we are given many pages to refresh our memory).
The command e2label can display or change the label of a device (You can also change a device label with tune2fs -L). For example, to change the label of /dev/hda4 to archives,

```
# e2label /dev/hda4 archives
```

As mentioned earlier, you record mounting preferences in /etc/fstab during installation. As long as she understands the syntax and options of the fstab file, the superuser can edit it with any text editor.

## GUI Tools to Mount Filesystems

The usmount graphical filesystem management client is available for use with Red Hat. Although Red Hat provides usmount as the default filesystem tool, it is not as feature-rich as KDiskFree, which is installed when you select KDE desktop.

The K Desktop Environment (KDE) provides several disk- and filesystem-related utilities. You might find one or more available on your Red Hat system if you select KDE. Found in the Extras menu under System Tools, the KDiskFree menu displays all the filesystems noted in /etc/fstab provides information about them, and allows you to easily mount and unmount them (see Figure 10.4). KwiDisk is the panel applet for KDiskFree. You would normally right-click on the KDE panel and add the applet to the panel. Red Hat has omitted KwiDisk from the KDE panel but includes it with Red Hat. Launch it from a command line, and it will appear on the KDE panel. Clicking on the KwiDisk panel icon launches an abbreviated version of KDiskFree:

