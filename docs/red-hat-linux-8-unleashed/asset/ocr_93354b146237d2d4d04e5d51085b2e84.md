Providing DNS for a Real Domain

and create the zone file

```
$TTL 2D          ns1.example.com. hostmaster.example.com. (
@               SOA      2001090101 ; Serial
                               24h             ; Refresh
                               2h             ; Retry
                               3600000        ; Expire (1000h)
                               1h)             ; Minimum TTL

NS              ns1.example.com.
NS              ns2.example.com.
MX 5            mx1.example.com.
MX 10           mx2.example.com.
A               192.0.2.1
```

```
; Addresses
s1              A      192.0.2.1      ; Name servers
ns2             A      192.0.2.96
mx1             A      192.0.2.2      ; Mail servers
mx2             A      192.0.2.96
www             A      192.0.2.3      ; Web servers
dev             A      192.0.2.4
work            A      192.0.2.5      ; Workstations
play            A      192.0.2.6
```

```
; Delegations
foo             NS     dns1.example.com.
foo             NS     dns2.example.com.
dns1.foo        A      192.0.2.96
dns2.foo        A      192.0.2.1
```

The SOA record is similar to the one you saw before. (Note that the next five records all use the implicit @, which is short for example.com.)

The two NS records define ns1.example.com (our own server, 192.0.2.1) and ns2.example.com (our friend's server, 192.0.2.96) as authoritative servers for example.com.

The MX (Mail Exchanger) records specify each mail server for the zone. An MX RR takes two arguments: a priority number and the name of a host. In delivering mail to example.com, the listed MXes are tried in increasing order of priority. In this case, mx1.example.com (our own machine, 192.0.2.2) has the lowest priority and is always tried
