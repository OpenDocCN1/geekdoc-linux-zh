# Evolution

The default graphical email client provided by Red Hat is Xian's Evolution. If you have had experience with Microsoft's Outlook mail client, you will resemble. Like MS Outlook, Evolution provides integrated functions: calendar, scheduling, and the ability to receive news and information from Internet sites.

> NOTE
> Xian intends for Evolution to actually act as a replacement for Outlook. Xian is also working on a non-free replacement for Microsoft Exchange server so that businesses will have a choice and Linux are targeted to replace the functionality of the UNIX product. As you'll see later, Balsa and Karma are targeted toward the MS Outlook express.

Start Evolution from the Internet menu; it is listed only as “Email.” The first time you start Evolution, the Evolution Setup assistant presents you with a brief and simple configuration, as seen in Figure 19.4.

The next screen permits you to configure Evolution to use your MTA: POP, IMAP, the local spools found in /var/mail in either mailbox or maildir, a local MTA, or “none” if you simply want to use the other features of Evolution. As seen in Figure 19.5, you can also set your password.

# Attachments—Sending Binary Files As Text

The SMTP protocol can only transfer plain text, so to send images and binary files through email you must encode the binary data as text. You can then include the encoded data in ordinary email; the recipient converts the text back to a binary format. The penalty for using this method is that the text file sizes are much larger than the binary files they replace.

The Macintosh operating system uses a program named BinHex; UNIX has traditionally used encoding and more recently, MIME encodings. A new player in the field is yencoding which claims to be faster and compress to smaller sizes. When encoding and decoding files manually, they all work in a similar manner to the venerable uuencode, so we have provided a detailed example of how to use that one.

> NOTE
> Unfortunately, Microsoft uses an attachment protocol not readily accepted by default attachment settings in a Red Hat Linux (and other Linux) installation.

The attachment type you might have trouble with is TNEF, known as the Transport Neutral Encapsulation Format. To get around this problem, use the tne filter; the included documentation describes its integration to your MUA. If you'd prefer to use a separate graphical decoding client, you can download the fheader client.

The tne filter is available from http://sourceforge.org/projects/tnef/.

The fheader application is available from http://www.ffffff.com/

# BinHex

Apple Macintosh users encode binary files in BinHex 4.0 for attachment to email messages. Recipients need a decoder to view the attachment. Although not included with Red Hat Linux, several decoding tools are listed at Freshmail.net. See RFC-1741 for details about BinHex encoding.

# yenc

Jürgen Helbing, the author of yenc (the name is a munging of “My Encoder”), makes this encoder available with no copyright restrictions. Although now most used for Usenet messages, yenc can also be used for mail (support for yenc is included in the news reader, see Chapter 2, “News Server Management”). The site, http://www.yenc.org/linux.htm, hosts a page of links for yenc tools for Linux.

> TIP
> Frank Philofer offers a handy GPL'd encoding and decoding application for UNIX named UUDecode. It can be found at http://www.fp.de/fp/Software/UUDecode/. Although not included with Red Hat, it is a full-featured tool that makes the encoding and decoding task much easier. It supports Base64, BinHex, uuencoding, xxencoding, and yenc and handles multipart files. Philofer provides a library that you can integrate into your own applications.

# uuencode and uudecode

Red Hat includes a program called uuencode that encodes a binary file as plain text that can be transferred across email with SMTP. At the destination, a companion program called uudecode decodes the text file back into its original binary format. Many times, the uuencoding and decoding of binary files is handled automatically by the email client, but sometimes it isn’t.
