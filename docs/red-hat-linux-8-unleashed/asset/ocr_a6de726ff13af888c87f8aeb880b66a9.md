In the example in Figure 17.3, we have added a customer ID field to each customer record. This field holds a customer ID number that is the unique piece of information that can be used to link all other information for each customer, in order to track orders and invoices. Each customer is given an ID that is unique to that customer; two customers might have the same name in their data, but their ID values will never be the same. The Customer ID field data in the Orders and Orders table replaces the Last Name, First Name, and Shipping Address information from the Customers table. Now, when you want to run a search for any customer's order and invoice data, you can search based on one key rather than multiple keys. You get more accurate results in faster, easier-to-construct data searches.

Now that you have an idea of how data is stored in an RDBMS and how the RDBMS structure enables you to work with data, you're ready to learn how to input and output data from the database. This is where SQL comes in.

# Understanding SQL Basics

SQL (pronounced "S-Q-L," or "se-quel") is a database query language that is understood by virtually all RDBMS available. You use SQL statements to get data into and retrieve data from a database. As statements in any language, SQL statements have a defined structure that determines their meaning and function.

In most settings, SQL is programmed into front-end or middleware applications that users don't directly manipulate. Thus, most end users are unaware of SQL and its role, and they have little reason to be concerned about the structure of SQL statements.
