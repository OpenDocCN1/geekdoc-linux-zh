You use the redhat-config-printer tool to edit the newly defined printers on your Red Hat Linux system. The Edit Queue dialog appears, as shown in Figure 12.7.

# Creating Network Printers

Setting up remote printing involves configuring a print server and creating a remote entry on one or more computers on your network. This section introduces a quick method of printing from one Linux workstation to another Linux computer on a LAN. You also learn about printing using Samba and its utilities. Finally, this discussion discusses how to configure network-attached printers and use them to print single or multiple documents.

# Enabling Network Printing on a LAN

To set up printing from one Linux workstation to another across a LAN, you need root permission and access to both computers, but the process is simple and easy to perform. First, log in or ssh to the computer to which the printer is attached. Use the hostname or ifconfig commands to obtain the hostname or IP address.

Next, edit the file named /etc/lpd.perms. Scroll to the end of the file and look for the remote entry:

+   # allow local jobs only
REJECT SERVICE=X NOT

Remote printing is not enabled by default, so you must comment out the reject line with a pound sign (#):

+   # allow local jobs only
# REJECT SERVICE=X NOT

Save the file, and restart the lpd daemon:

```
# /etc/rc.d/init.lpd restart
```

Starting lpd: You can also use the service command to restart the print daemon as shown earlier in the chapter. This will allow incoming print requests with the proper queue name (name of the local printer) from any remote host to be routed to the printer. After you have finished, log out and go to a remote computer on your LAN without an attached printer.

> TIP
Print services can be restricted to single hosts, one or more specific local or remote users, all part of a domain, or a LAN segment (by specifying an IP range) by entries in /etc/lpd.perms. For example, to only allow print requests from hosts on 192.168.2.0, use an entry such as:

ACCEPT SERVICE=X REMOTEIP=192.168.2.0/255.255.255

The lpd.perms page contains an index of keywords you can use to craft custom permissions. Don't forget to restart the lpd daemon after making any changes to /etc/lpd.perms (or /etc/lpd.conf).

Again, use the redhat-config-printer client to create a new print queue. Enter a name for the remote printer, and then click the UNIX type in the dialog box shown in Figure 12.9.

> TIP
Choose a printer name you can easily remember or that provides a clue as to type or location. Good candidates might be 4th_floor for location, winky for a user, colorlaser for output type, hp348 for specific model identification, or tree-eater to denote a high-speed printer.

> NOTE
browse to http://www.faqs.org/rfcs/rfc1179.html to read more about using the Strict RFC1179 Compliance option when configuring Red Hat to be able to print to a remote UNIX printer. Click the Forward button after entering this information; then continue to configure the new entry as if the remote printer were attached locally (use the same printer driver setting as the remote printer). When finished, don't forget to save the changes and restart the lpd daemon. The new remote printer entry /etc/printcap may look something like this:

```
hp648:
:ml#=\n:mx#=\n:sd=/var/pool/lpd/hp648:\n:af=/var/pool/lpd/hp648/hp648.acct=\n:sh=\n:rm=192.168.2.35:\n:rp=lp1:
  :lpd_bounce=true:
:if=/user/share/printconf/util/mf_wrapper:
```

In this example, the :rm entry defines the remote host (an IP address is used), whereas :rp entry defines the remote queue (1 lp in this example). As before, test the new remote printer by clicking the Tests menu item and using the ASCII or PostScript test pages.
