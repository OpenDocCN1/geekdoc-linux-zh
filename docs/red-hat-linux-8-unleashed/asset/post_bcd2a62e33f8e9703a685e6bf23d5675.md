
# Putting Samba to Work

To start, stop, restart Samba using Red Hat Linux, use the service command, the redhat-config-services client, or the /etc/rc.d/init.d/smb script with a proper keyword, such as start, like so:

```
# /etc/rc.d/init.d/smb
```

## Using the smstatus Command

The smstatus command will report on the current status of your Samba connections. The syntax is

```
/usr/bin/smstatus [options]
```

Some of the available options are shown in Table 13.4.

# TABLE 13.4 smbstatus Options

| Option | Result |
| :--- | :--- |
| -b | Brief output. |
| -d | Verbose output. |
| -s /path/to/config | Used if the configuration file used at startup is not the standard one. |
| -u username | Shows the status of a specific user's connection. |
| -p | Lists current smb processes. This can be useful in scripts. |

## Connecting with the smbclient Command

The smbclient command allows users on other Linux hosts to access your smb shares. You can't mount the share on your host, but you can use it in a way that's very similar to an FTP client. Several options can be used with the smbclient command. The most will be -I by the IP address of the computer you are connecting to. The smbclient command does not require root access to run.

```
smbclient -I 10.10.10.20 --username=password
```

This will give you the following prompt:

```
smb: <current directory on share>
```

From here, commands are almost identical to the standard UNIX/Linux FTP commands. Note that you can omit a password on the smbclient command line. You will be prompted to enter the Samba share password.

## Mounting Samba Shares

There are two ways to mount Samba shares to your Linux host. Mounting a share is the same as mounting an available media partition or remote NFS directory, except that the Samba share will be accessed using SMB. (See Chapter 10, “Managing the Filesystem,” to see how to mount partitions. The first method uses the standard Linux mount command:

```
mount -t smbfs //10.10.10.20/homes /mount/point -o username=jennedy,dmask=777,fmask=777
```

> NOTE
> The hostname can be substituted for an IP address if your name service is running or the host is in your /etc/hosts file.

This command will mount jennedy's home directory on your host and will give all full permissions to the mount. The permissions are equal to the permissions on the chmod command.

The second method produces the same results using the smbount command as follows:

```
smbount //10.10.10.20/homes /mount/point -o username=jennedy,dmask=777,fmask=777
```

To unmount the share, use the standard

```
umount /mount/point
```

These commands can also be used to mount true Windows client shares to your Red Hat host. Using Samba, you can configure your Red Hat Linux host to provide any section that Windows can serve, and no one but you will ever know.

## Configuring Samba Using SWAT

The team of developers has made administering Samba a snap with the Samba Web Administration Tool, or SWAT. SWAT is a Web-based configuration and maintenance interface that gets close to a point-and-click Samba environment as possible. This section provides a very simple example of how to set up SMB to a user's Red Hat Linux home directory and how to share a directory.

You'll need to perform a few steps before you can start using SWAT. First, enable access to your Red Hat Linux system by editing the file /etc/xinet.d/swat by changing the following line:

```
disable = yes
```

Change the word yes to the word no, like so:

```
disable = no
```

## Putting Samba to Work

Save the file, and then restart the xinetd daemon, using either the redhat-config.services client or the xinetd shell script under /etc/rc.d/init.d like so:

```
# /etc/rc.d/init.d/xinetd restart
```

Next, start an X session, or if you are running X, select the desktop panel and click the Samba Configuration menu item from the Server Settings menu. Mozilla Web browser will launch, and you'll be presented with a login prompt to SWAT. That Apache does not need to be running on your system. Enter the root username and password, and then click the OK button. The screen will clear, and you'll see the main SWAT page, as shown in Figure 13.5.

 Wireless Networking

As stated earlier, Linux has support for wireless networking since the first standards were developed in the early 90s. With computers getting smaller and smaller, the uses for wireless networking increased; meanwhile, the transmission speeds are increasing all the time. There are different ways to create a wireless network. The following sections introduce you to several Linux commands you can use to initialize, configure, and manage wireless networking on your Red Hat system.

## Support for Wireless Networking in Red Hat Linux

With the 2.4 kernel, which ships with Red Hat now, support for wireless networking is now included in the kernel. Related wireless tools for configuring, managing, or displaying information about a wireless connection include:

- iwconfig—Used to set the network name, encryption, transmission rate, and other features of a wireless network interface
- iwlist—Displays information about a wireless interface, such as rate, power level, or frequency used
- iwpriv—Used to set optional features, such as roaming, of a wireless interface
- iwspy—Shows wireless statistics of a number of nodes
