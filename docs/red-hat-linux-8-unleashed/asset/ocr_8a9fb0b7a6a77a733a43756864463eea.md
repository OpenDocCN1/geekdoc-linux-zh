# Using the cds.o File System Module

Not included with Red Hat is an interesting kernel module cds.o. This filesystem module lists every track and image on a CD as a separate file. This is a useful tool for recovering data from multibission CDs. Each session is listed as an image filesystem that can then be mounted using the loopback filesystem. (Refer to Chapters 10, "Managing the Filesystems," and 11, "Backing Up, Restoring, and Recovery,") for examples of mounting image files in this way.) You can get cds.o from http://www.elis.rug.cz/~ronsese/cds/; you must compile it with your system using the ./configure, make and make install commands. Load it with `modprobe cds`, and mount a CD with `mount -t cds -o /dev/cdrom /mnt/cdrom`. Although the cdsfs module isn't the most elegant approach to CD filesystems, it's a handy tool for CD data recovery.

# Creating CDs from the Command Line

In Linux, creating a CD is a two-step process. You first create the iso9660-formatted image, and then you burn or write the image onto the CD. iso9660, as you learned in Chapter 10, is the default filesystem for CD-ROMs.

Use the mkisofs command to create the ISO image. The mkissoff has many options (see the main page for a full listing), but use the following for quick burns:

```
$ mkisofs -r -v -J -I /tmp/our_special_cd.iso /source_directory
```

The options used in this example are as follows:

+   -r—Sets permission of the files to make more useful values. UID and GID (individual and group user requirements) are set to zero, all files are globally readable and searchable, and all files are set as executable (for Windows systems).
- v—Displays verbose messages (rather than terse messages) so you can see what is occurring during the process; these help resolve problems if they occur.
- J—Uses the Juliet extension to ISO 9660 so your Windows-building candies can read the CD. Juliet (for Windows), Rock Ridge (for Unix), and HSF (for Mac) for the iso9660 standard are used to accommodate long filenames rather than the eight-character DOS filenames that the iso9660 standard supports.
- I—A lowercase L allows 31 character filenames; DOS doesn't like it, but everyone does.
-=Sets the directory where the image will be written (that is, the output). The /tmp directory is convenient for this purpose, but the image could go anywhere you write permissions.
-/Indicates the path to the source directory; that is, the directory that contains the files we want to include. There are ways to append additional paths and exclude directories (and files) under the specified path—it's explained in the main page if you need that level of complexity. Our simple solution is to construct a new directory tree and populate it with the files we want to copy, then make the image using that directory as the source.
