Each account entry contains a username (used for logging in), a password field containing an x (as passwords are really contained in /etc/shadow), a User ID (UID), and a Group ID (GID). The fifth field contains optional human ID information, such as real name, office location, phone number, and so on. The last two fields are the location of the user's home directory and the user's default login shell. The section "Password File" in this chapter for more information.

Red Hat use the traditional form of Unix file ownership and permissions. Each file (which includes directories and devices) can be read, write, and/or execution permission to an owner, a member of a group, or anyone on the system. (This information can be viewed with the ls command, using -l for files or -ld for directories.) Red Hat's file security is derived by combining ownerships and UIDs. It's the superuser's job to make sure that all users have proper filename, UIDs, and GIDs and that sensitive system files are protected from improperly permissive write assignment.

The superuser is also known by the name root. Although many system administrators might be on a large scale, only one root has (and) all privileges on the system. The root user is defined as having a user ID of zero and a Group ID of zero. (We'll discuss these IDs later in the chapter, but you can see how that ID is unique to root.)

The root user can use any program, manipulate any file, go anywhere in the filesystem, and doing anything within the Red Hat Linux system. For reasons of security, that kind of raw power should be given to a single trusted individual.

It's possible for power to be delegated by the root user to other users. This delegation is referred to as an elevation of privileges, and these individuals are known as superusers because they enjoy the same powers that root enjoys. This approach is normally used on large systems where one person cannot effectively act as the system administrator.

> NOTE
On your Red Hat desktop system, when you log in as root, you are root or the superuser. In this terms, the root user, superuser, system administrator, and sysadmin are used interchangeably, although they need not to be a single person.

The regular user is a person who logs on and uses the computer to accomplish some task. Regular users don't participate in the management or administration of the computer on a global scale, but they may be permitted to manage their own personal settings and configurations–if the root user doesn't take that privilege away.

Privileges are granted to regular users by the superuser by the means of file and directory permissions. (Those were covered in Chapter 5, "First Steps with Linux.") For example, if the superuser does not want you to change the settings in ~/.profile (the – is a shell shortcut for your home directory, see Chapter 22, "Shell Scripting"), he can alter the permissions so that you may read, but not write to file.
