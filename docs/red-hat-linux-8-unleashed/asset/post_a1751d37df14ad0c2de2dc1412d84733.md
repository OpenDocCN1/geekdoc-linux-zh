The next section of the configuration file provides the definition of the A:\ drive. This is
a floppy drive that many Windows applications expect to see.

If you don't have an A:\ drive (many laptops and desktops don't), change the last line of
definition to look like the c:\ drive and mount an image file at /mnt/floppy. That's enough
of Wine.

```
Drive A
"Path" = "/mnt/floppy"
"Type" = "floppy"
"Label" = "Floppy"
```

The fake C:\ drive that Wine creates the expected Windows file tree and populates it with own .dll files and configuration files; Windows programs behave as if drive is their home. It can be found on your Red Hat system at /usr/share/wine-c.

> CAUTION
You could change the mount point to a real Windows installation, but Wine will break the Windows registry. Alternatively, you can copy the "real" Windows installation to another location like /usr/share/wine-real and Wine there.

- [Drive C]
"Path" = "/usr/share/wine-c"
"Type" = "hd"

This is the definition for the CD-ROM drive; adjust as appropriate for your system, or duplicate this entry (with a different drive letter) if you have more than one CD-ROM drive.

- [Drive D]
"Path" = "/mnt/cdrom"

The following entry allows Wine access to /tmp for temporary files and sharing with other users:

- [Drive E]
"Path" = "/tmp"
"Type" = "hd"

With dll overrides, you can make Wine use native .dlls instead of the Wine versions of .dll: just reverse the order to "native, builtin". This selection can also be set from the command line (see Wine documentation) when needed to run a particular program. The documentation explains how it can be defaulted on a per basis here in the configuration file. The configuration would look like the following example taken from Crossover Wine configuration:

```
[AppDefaults\msiexec.exe\DllOverrides]
"ole32" = "builtin"
"ole2" = "builtin"
"compobj" = "builtin"
"storage" = "builtin"
"olepro32" = "builtin"
"ole2nls" = "builtin"
"ole2conv" = "builtin"
"ole2prox" = "builtin"
"ole2thk" = "builtin"
```
