Now that you are running fdisk as root, you can create a partition table. We will assume that you have installed a brand-new drive as /dev/hdb (the Primary IDE device) and want to partition the entire drive as a single partition. Launch fdisk with

```
# fdisk /dev/hdb
```

Use the n key to create a new partition, and fdisk will prompt you for the beginning cylinder:

Press the Enter key to accept the default of 1. Now, fdisk prompts

Using the default value of 1
			Last Cylinder or +size or +sizeM or +sizeK (2-9729, default 9729) :

Here, you can give the size in the cylinders, the size in kilobytes, the size in megabytes, and accept the default value (which is the last cylinder on the disk). Press the Enter key to accept the default.

Using default value of 9729

We are back at the fdisk prompt:\
			Command (m for help) :

Enter the w command to write the new partition table to the disk, and fdisk will exit, returning you to the command prompt.

# The sfdisk Command

An alternative to fdisk is sfdisk. The real power of sfdisk over fdisk is that its actions can be scripted, so you can write scripts that force sfdisk to do what you want to (and without telling it you). A sysadmin might want to use sfdisk if he were doing Linux installations on a hundred identical computers, writing scripts, and reformatting and restoring data to hard drives. See Chapter 22, “Shell Scripting,” for examples on shell scripting. The sfdisk command would be a good choice for use on a networked, multi-user system.

sfdisk has a number of safeguards built in it to prevent accidents caused by inexperienced users: For example, running the command alone generates only a listing of commands. Although the syntax is much different than that for fdisk, it is straightforward and accomplishes the same thing.
