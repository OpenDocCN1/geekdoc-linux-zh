Creating files with mknod is a straightforward process as long as you know what type of device you are creating for and what the device's major and minor numbers are.

The syntax of mknod is

```
# mknod [OPTION].. NAME TYPE [MAJOR MINOR]
```

The useful option -m allows you to set the mode at file creation instead of doing it separately.

You can obtain the values for NAME, TYPE, MAJOR, and MINOR from devices.txt, even when she has a block of experimental numbers if you are inclined to experiment.

# The Device Filesystem—devfs

An alternative device filesystem known as the Device Filesystem (devfs) will soon come into common use in Linux. It only has entries for devices that you have attached to your system, and the naming convention is different from the traditional system. It can be used in tandem with the traditional system. Although Red Hat supports devfs in the kernel sources, it is not enabled by default Red Hat does not believe it is stable for Enterprise use.

For example, /dev/hda1 is named /dev/ide/hd1/cd001 and is a symbolic link to /dev/ide0/host8/target/0/part1.

The Device Filesystem is the /proc filesystem that it is a virtual filesystem; the devices exist in memory and not as actual files on the drive. Why use devfs? There are some limitations to the use of major and minor numbers (128 maximum are available), which is why H. Peter Levin maintains devices.txt, and access to new device numbers is limited. The address space could be enlarged, that the /dev directory be on the root filesystem, so read-only root filesystems are difficult to use. You can't share a root filesystem using NFS, and you can't enable it in a ROM filesystem. Workarounds require creating a ramdisk and copying the contents of /dev there.

Non-Unix filesystems can't be mounted as the root filesystem because they don't support the special characteristics of UNIX files. The devfs can solve these types of problems and provide more flexibility to Linux. FreeBSD, BeOS, Plan9, and QNX devfs so it's not a new concept, just to Linux.

For details, read the Linux DEVFS FAQ at http://www.atnf.csiro.au/-rgooch/linux/docs/devfs.html.
