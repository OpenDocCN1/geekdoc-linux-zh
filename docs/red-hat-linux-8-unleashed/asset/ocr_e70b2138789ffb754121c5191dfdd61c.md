# Other Filesystems Available to Red Hat Linux

To run the fck command, use the name of the filesystem as the argument. If you want to fck the filesystem at /dev/hdc, for example, do this:

```
# fck /dev/hdc
```

The filesystem state is tracked in the ext3 filesystems. A special field in the superblock tells the kernel that, after the filesystem is mounted read/write, it is marked as not clean; when it is unmounted, it is marked as clean. If a filesystem is unmounted properly, it could contain corrupt data because all the file data might not have been written to it.(This is what the journaling filesystems such as ext3 strive to eliminate.) When the system is booted, this flag is checked and if it is not clean, the program fck is run. (Actually, fck is a wrapper program that provides the appropriate version of fck: fck.minix, fck.ext2, fck.ext3, fck.reiserfs, fck.msdos, fck.vfat.) If the kernel detects an inconsistency in the superblock field, the filesystem is marked erroneous, and the filesystem check is forced even if other indicators suggest that fck doesn't need to be run.

By default, the system will run fck on a filesystem after a periodic number of reboots regardless of the status of the clean flag. This is triggered by a mount counter kept in the superblock or after a predetermined amount of time that has elapsed since the last reboot (information also kept in the superblock). These parameters can be adjusted by tune2fs command, and this command can also be used to modify how the kernel handles the erroneous flag and, interestingly, the number of blocks reserved for the superuser, also known as root. This latter option is useful on very large or very small disks to make more disk space available to the user.

# Other Filesystems Available to Red Hat Linux

Although ext3 is certainly an acceptable root filesystem, there are other alternatives. No operating systems can support as many root filesystems as Linux. Every filesystem has its strengths and weaknesses. Some are better with large files, some are better at writing data, and some are better at reading data. Unfortunately, there is no one perfect filesystem. The following sections discuss some of the other common filesystems available for use with Red Hat Linux.

# The Reiser Filesystem (ReiserFS)

The other popular journaling filesystem for Linux is the written-from-scratch Reiser Filesystem, ReiserFS. It is used primarily in SUSE and Mandrake distributions, which support booting from a ReiserFS root filesystem. ReiserFS offers many features to ext3, but there is no easy migration path from an already existing ext2 partition, as you learn to do in "Converting an existing ext2 filesystem to ext3," later in the past. ReiserFS didn't work well over NFS mounts, but recent versions of nfsd daemon fixed those problems. Red Hat offers ReiserFS, but doesn't support booting from it as root partition filesystem, nor does it officially offer the choice to format non-root partitions as ReiserFS during the installation process.
