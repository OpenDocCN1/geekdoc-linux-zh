RCS and CVS can be used for more than than software development projects. These tools can be used for document preparation and workgroup editing of documents, and they can work with any text files. Both systems use registration and control files to accomplish revision management. Systems also offer the opportunity to revisit any step or branch in a revision history and to restore previous versions of a project. This mechanism is extremely important in cross-platform development and for software maintenance.

Tracking information is usually contained in separate control files; each document within a project might contain information that is automatically updated with each change to a project. A process called keyword substitution is used to perform these automatic updates. CVS and RCS use similar keywords, which are usually included inside C comment strings (/*) near the top of a document. The following are some of the available keywords:

+   - $Author$—The username of the person who performed the last check-in
- $Date$—The date and the time of the last check-in
- $Header$—The pathname of the document's RCS file, with the revision number, date and author, and state inserted
- $Ids$—Same as Header, but without a full name
- $Name$—A symbolic name (see the co man page)
- $Revision$—The assigned revision number (such as 1.1)
- $Source$—The RCS file's full name
- $State$—The state of the document, as Exp for experimental, Rel for released, or for stable

You can also use these keywords to insert information into compiled programs using character strings in program source code. For example, an extremely short C program named foo.c, you could use the following:

```
/* $Header$ */
#include <stdio.h>
static char rscid{} = "$Header";
```
