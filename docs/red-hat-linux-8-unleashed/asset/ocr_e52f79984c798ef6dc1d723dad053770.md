# CPU, Symmetric Multi-Processing (SMP), and Memory Problems

Red Hat supports all Intel-based CPUs. Code is included in the Linux kernel to recognize the CPU type when booting, and then to implement any required fixes for architecture bugs (such as the now-infamous divide-by-zero error). After you install Red Hat, you can rebuild the Linux kernel specifically to support and take advantage of the host PC's CPU. You may not realize improvements in computational speed, but you'll be assured that Linux is crafted for your CPU's architecture, which can help stability and reliability. Details rebuilding the Linux kernel are in Chapter 24. Some of the Intel-based CPUs with specific code include those from Advanced Micro Devices, Transmeta, and VIA Technologies.

The kernel also should automatically recognize and use the amount of installed RAM. The latest Linux kernel should also recognize and map out any memory holes in system memory (perhaps used for video graphics).

If you are installing Red Hat on a working, stable PC, you should not have any problems related to the system's memory. If you're putting together a new system, you need to avoid combining or configuring the system in ways that will interfere with your ability to process data. Some issues to be aware of

+   - Do not expect similar CPU performance across product lines from different manufacturers, such as AMD or VIA. Some CPUs offer better floating point or integer math operations, which are important for a number of CPU-intensive tasks (such as graphics, audio, and video rendering or conversion). If you need better performance, try to find a CPU compatible with your motherboard, or switch to a CPU with better Floating Point Unit (FPU) performance.

+   - Overclocking can cause problems with overheating, memory access, and other hardware performance, and it's not a good idea for the Red Hat Linux system. Overclocking is a popular geek pastime and a great way to get a bit of performance out of slower CPUs by altering voltage settings and/or clock timings via the BIOS. You can try to push your CPU to higher speeds, but this approach is not recommended if your aim is system stability. The Linux kernel will report the recognized CPU speed upon booting (using the dmesg command).
