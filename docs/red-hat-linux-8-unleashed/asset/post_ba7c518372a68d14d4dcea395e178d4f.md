The System Monitor menu item is found in the System Tools menu. It can be launched from the command line

# gnome-system-monitor

From the Process List viewing (chosen via the tab in the upper left portion of the screen), select a process and click on More Info at the bottom left of the screen to display details on that process at the bottom of the display. You can select from three views, available in the drop-down View list: All Processes, My Processes (those you alone), or Active Processes (All Processes that are active) to filter the display.

Choose Hidden Processes under the Edit command accessible from the top of the display to show any hidden processes (those that the kernel does not allow the normal monitoring tools to see). Select any process and kill it with End Process.

The processes can be reniced by selecting Edit, Change Priority. The view selection from the menu bar also provides a memory map. In the System Monitor tab, you can view a graph representing CPU and memory usage (see Figure 8.7).

These KDE monitoring clients include the following:

- ktimemon—A small KDE client or app that docks, or deposits, or an animated graph of CPU activity in your desktop's panel (known as KDE's kicker).
- kdf—A graphical interface to your system's filesystem table that displays free space and enables you to mount and unmount filesystems using a pointing device.
- kisandock—This panel app is used to monitor ISDN connections.
- ksysguard—Another panel app that provides CPU load and memory information in animated graphs.
- kcron—A graphical interface to your system's /etc/crontab file.

In this chapter, you learn how to perform the tasks necessary to manage users of your Red Hat Linux system. The control of these users is critical to the responsible management of the system resources. Allowing others access to a computer is more than just permitting them to sit at a terminal and type. You need to know how to establish new user accounts and place them in groups, how to create new home directories for those users, and how to populate the directories with an initial set of files. Managing users also requires that you know how to establish user passwords and how to grant users file and directory permissions, so they can access to files they need and are prohibited from accessing files they have no business using.

In this chapter, you learn how to accomplish all these tasks and others for managing user accounts. You will learn about the different types of users and the responsibilities of the superuser (that's typically the administrator of all system administrators or root) so that you'll have a better idea of what roles you will play as a system administrator. In addition, you'll learn how to delegate superuser power to others when it's appropriate.

# User Accounts

Three kinds of users are at work in the typical Red Hat Linux system environment: the superuser, the regular user, and the system user. All three have important roles and must work cooperatively to accomplish their tasks.

All users have accounts. Red Hat Linux uses the /etc/passwd file to hold user account information. Each user, regardless of type, will have a one-line entry of account information stored in the /etc/passwd text file. Each account entry contains a username (used for logging in), a password field containing an x (as passwords are really contained in /etc/shadow), a User ID (UID), and Group ID (GID). The fifth field contains optional human information, such as real name, office location, phone number, and so on. The last two fields are the location of the user's home directory and the user's default shell. The section "Password File" in this chapter for more information.

Red Hat use the traditional form of ownership and permissions. Each file (which includes directories and devices) can be read, write, and/or execution permission to an owner, a member of a group, or anyone on the system. (This information can be viewed with the ls command, using -l for files or -ld for directories.) Red Hat's file security is derived by combining ownerships and UIDs. It's the superuser's job to make sure that all users have proper UID and that sensitive system files are protected from improperly write assignment.

The superuser is also known by the name root. Although many system administrators might be on a large scale, only one root has privileges on the system. The root user is defined as having a user ID of zero and a Group ID of zero. (We'll discuss these IDs later in the chapter, but you can see how that ID is unique to root.)

The root user can use any program, manipulate any file, go anywhere in the filesystem, and doing anything within the Red Hat Linux system. For reasons of security, that kind of raw power should be given to a single trusted individual.

It's possible for power to be delegated by the root user to other users. This delegation is referred to as an elevation of privileges, and these individuals are known as superusers because they enjoy the same powers that root. This approach is normally used on large systems where one person cannot effectively act as the system administrator.

> NOTE
On your Red Hat desktop system, when you log in as root, you are root or the superuser. In this terms, the root user, superuser, system administrator, and sysadmin are used interchangeably, although they need not be a single person.

The regular user is a person who logs on and uses the computer to accomplish some task. Regular users don't participate in the management or administration of the computer on a global scale, but they may be permitted to manage their own personal settings and configurations–if the root user doesn't take that privilege away.

Privileges are granted to regular users by the superuser by the means of file and directory permissions. (Those were covered in Chapter 5, "First Steps with Linux.") For example, if the superuser does not want you to change the settings in ~/.profile (the – is a shell shortcut for your home directory, see Chapter 22, "Shell Scripting"), he can alter the permissions so that you may read, but not write to file.
