The GECOS field is used by traditional Unix programs such as finger and mail. For that reason, it is commonly referred to as the finger information field. The data in this field is delimited; the GECOS field can be changed with the chfn (change finger) command.

Note that a colon separates all fields in the /etc/passwd file. If no information is available for a field, that is empty, and all the colons remain.

If an asterisk appears in the password field, that user won't be permitted to log on. Why does this feature exist? So a user can be easily disabled and (possibly) reinstated without having to be created all over again. The system administrator would manually edit this field, which is the traditional way of accomplishing this task. Red Hat provides better functionality with the passwd -1 command mentioned earlier.

## Shadow Passwords

It is considered a security risk to use the encrypted passwords found in /etc/passwd because anyone with read access can run a cracking program on the file and obtain the passwords with little trouble. To avoid this, shadow passwords are used so that only an x or an * appears in the password field of /etc/passwd; the rewards are kept in /etc/shadow, a file that can only be read by the sysadmin (PAM, the Pluggable Authentication Modules authentication manager; see the sidebar for an explanation of PAM).

Special versions of the traditional password and login programs must be used to enable shadow passwords. Shadowed passwords are automatically enabled during the installation phase of the operating system on Red Hat systems.

Let's examine a partial listing of the shadow companion to /etc/passwd, the /etc/shadow file:

```bash
# /etc/shadow
root:$1$Bcw2?$3uR663j2gd1NNu3Ac.a.:*118117:09999:7:
bin:*118117:09999:7:
daemon:*118117:09999:7:
adm:*118117:09999:7:
lp:*118117:09999:7:
sync:*118117:09999:7:
shutdown:*118117:09999:7:
halt:*118117:09999:7:
mail:*118117:09999:7:
news:*118117:09999:7:
ldap::118117:09999:7:
postfix::118117:09999:7:
pvm::118117:09999:7:
hoy:$2_TY.VI$1Mzyd$3W91zWtD2Qu9FS:*118118:09999:7:
```

The fields are separated by colons and are, in order:

- The user's login name.
- The encrypted password for the user.
- The number of days since Jan 1, 1970 that the password will expire.
- The number of days before the password is changed.
- The number of days after the password was changed.
- The minimum number of days between password changes.
- The maximum number of days a password is valid.
- The comment field.

## Managing Users

The sysadmin has control, with settings in the /etc/shadow file, or how often the password must be changed.
