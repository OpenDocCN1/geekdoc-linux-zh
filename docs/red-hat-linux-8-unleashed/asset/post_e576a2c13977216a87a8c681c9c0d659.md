
# CHAPTER 6 The X Window System

## The Red Hat Desktop

The version of Red Hat 8.0, code named null, initially caused quite a stir among veteran Linux users due to Red Hat's decision to introduce consistency in the menus, dialogs, and client look and feel of GNOME and the K Desktop Environment (KDE). This action, part of the natural evolution of Red Linux, provides a basic framework for the Red Hat desktop as a base Linux platform in upcoming product lines. The new desktop, as discussed in this chapter, allows Red Hat to more easily integrate advanced products, such as enterprise-level Web, database, application, or development server software.

The new Red Hat desktop, while considered heresy by some die-hard users on both sides of the GNOME and KDE camps, actually helps new Red Hat users easily migrate from other operating systems by enabling them to learn a single set of controls and preferences for working in a graphical interface.

Red Linux offers you the choice of to use the Red Hat desktop. You are entirely free to use a different desktop and configure GNOME or KDE to look entirely different from the default graphical desktop. Red Hat also includes alternative and legacy window managers with Red Linux, such as Window Maker, the Motif Window Manager, and the twm window manager (which are discussed later in this chapter).

## Basic Concepts

The underlying engine of X11 is the X protocol, which provides a system of managing displays on local and remote desktops. The protocol uses a client/server model that allows an abstraction of the drawing of client windows and other decorations locally and over a network. X server draws client windows, dialog boxes, and buttons that are specific to the local hardware and in response to client requests. The client, however, doesn't have to be specific to the local hardware. This means system administrators can set up a network with a large server and clients and enables users to view and use those clients on workstations with totally different CPUs and graphics displays.

> As an example of X's support for remote client use, much of the original text of this chapter was written using the Micros StarOffice office suite, but the keyboard and display used for writing attached to an Apple G4 Cube running Linux and PowerPC version of XFree86; StarOffice was launched from an Intel-based PC running Red Hat Linux. Subsequent revisions were made on a shoebox-sized computer running Red Hat 8.0, the open-source Office.org office suite, launched from a headless (that is, no attached monitor, keyboard, or mouse) dual-cpu server running Red Hat 7.3.

X11's form of distributed processing means that Red Hat Linux, along with XFree86, can be used as a stable, cost-effective desktop PC platform for clients launched from a more powerful server, minicomputer, or mainframe. The X model provides a way to continue using legacy PCs when more powerful systems are put in place, and it can help centralize the job of system management.

## Using XFree86

X is popular with UNIX and Linux users, system administrators, and network engineers for a number of reasons. X is extremely portable and works with nearly every hardware-based graphics system on the market. This allows X to be deployed and used with high-end workstations and diminutive embedded devices. X also provides portable and multiprogram programming standards that truly allow write-once, cross-platform development.

Another attractive feature of X is its networking capabilities, which easily manage thousands of workstations, deployment of thin-client desktops, remote launching of applications, and standardization of installations—all working over a variety of media, as Ethernet and wireless network connections. Although early releases of X supported only a handful of display architectures, subsequent versions have enabled the use of *shaped* (that is, nonrectangular) windows, and a graphical login manager, known as a *display manager* (see the section "Using a Display Manager," later in this chapter). X provides a mechanism for customizing how X clients appear: It allows you to edit text files that contain window or button appearance settings. These settings, known as resources, are available for every X11 client.

Many small office/home (SOHO) environments and computer hubs run Red Hat Linux and X locally on noned PCs. But small, academic, corporate, and enterprise-class environments can also reap the benefits of adopting and using X and Red Hat for network computing. By using X, administrative staff, and in-house developers can enjoy custom or standardized desktops, and applications can be stored and launched from a single location. This can make the job of system and software maintenance a lot easier.

## Using XFree86

XFree86 is the server that is used with Red Hat. The base XFree86 distribution consists of nearly two dozen RPM packages, which contain the server, along with support and development libraries, fonts, various clients, and documentation. An additional 1,000 or more X clients, fonts, and documentation are also included with Red Hat Linux.

> NOTE
A full installation of X and related XFree86 files can consume more—usually much more—than 170MB of hard drive space. This is because Red Hat places additional clients, configuration files, and graphics (such as icons) under the `/usr/bin` and `/usr/share` directory trees. You can pare excessive disk requirements by judiciously choosing which X-related packages (such as games) to install on workstations. However, with the increased capacity of most desktop PC hard drives today, the size requirements are rarely a problem, except in configuring thin-client desktops or embedded systems.

The `/usr/X11R` directory and its subdirectories contain the majority of XFree86's software. Some important subdirectories are:

- /usr/X11R/bin—This is the location of the X server and various X clients. (Note that all X clients require active sessions.)

- /usr/X11R/include—This is the path to the files that are necessary for developing X clients and graphics as icons.

- /usr/X11R6/lib—This directory contains required software libraries to support the X server and clients.

- /usr/X11R6/lib/X11—This directory contains default client resources, system resources, documentation, and other files that are used during X sessions and for various clients. You'll also find a symbolic link to this directory, named x11, under the /usr/lib directory.

- /usr/X11R6/lib/modules—This path to drivers and the X server modules are used by the X server enables use of various graphics cards.

- /usr/X11R6/man—This directory contains directories of manual pages for X11 programming and clients.

The main components required for an active local X session will be installed on your Red Hat system if you choose to use a graphical desktop. These components are the X server, miscellaneous fonts, a terminal client (that is, a program that provides access to a shell prompt), and a client known as a *window manager*. Window managers, which are discussed later in this chapter (see the section Selecting and Using Window Managers), administer onscreen displays, including overlapping and tiling windows, command buttons, bars, and other decorations and features.

## Elements of the X86Config File

The single most important file to launch X on a desktop is the XF86Config configuration file. This text file is configured during Red Hat Linux installation, and is usually found the /etc/x11 directory. It contains hardware descriptions, and specifications needed by the X server in order to work with the computer's graphics card and display monitor.

You'll be better equipped to troubleshoot configuration problems and remove features of the X session if you understand the contents of the X86Config file. The components, or sections, of X86Config specify the X session, or server layout, along with paths for files used by the server, server options, optional support modules to load, descriptions of the mouse and keyboard, graphics device, monitor, screen layout, and video modes to use. Of the 12 sections of an XF86Config file, these are the essential components:

- ServerLayout—Defines the display, defines one or more screen layouts, and names input devices

- Files—Defines the location of colors, fonts, or port number of the font server
