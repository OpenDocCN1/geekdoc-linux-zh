The value of the default entry, the initdefault line in /etc/initt, determines the particular system state in which Red Hat Linux will be when the login prompt is finally presented.

```
id:5:initdefault:
```

In this example, Red Hat Linux boots to runlevel 5, a networking, multiuser mode with an active X system and a graphical login. The value 5 is forwarded to the script name rc under /etc/rc.d directory. This script is used when booting or changing runlevels; it also acts as an interpreter when you boot Red Hat Linux in “Interactive” mode by pressing any during boot.

Assuming that the value is 5, the rc script executes all the scripts under the /etc/rc.d/rc.5 directory and then launches the graphical login.

After /etc/rc.d/rc.sysinit has finished, init uses the corresponding /etc/initt entry that matches a designated default runlevel. Using the previous example, the line in /etc/initt would be

```
1:5:wait:/etc/rc.d/rc 5
```

Under the /etc/rc.d directory is a series of directories that correspond to each runlevel:

```
$ ls /etc/rc.d
init.d rc0.d rc2.d rc4.d rc6.d rc.sysinit
rc1.d rc3.d rc5.d rc.local
```

The rc5.d links are prefixed with a letter, such as K15 or S10. The (K) or (S) in these prefixes indicate whether a particular service is killed (K) or started (S) and a value of stop to start the /etc/rc.d/init.d script in a particular order. # Booting to a Non-Default Runlevel

After you select a default runlevel, runlevel will be selected every time you restart the system from a power-off state. There might come a time when you do not want to boot into runlevel. You might want to enter the maintenance mode or start the system without an active X server and graphical login in order to modify the X server or desktop manager. You'll need to follow several specific steps to boot to a non-default runlevel if you use the default bootloader, GRUB.

If you have a GRUB password, you must first press p, type your password, and then press Enter before using this method. The GRUB bootloader passes arguments or commands to the kernel at boot. Among other things, arguments are used to tell GRUB which the kernel is located and also to pass specific parameters to the kernel, such as how much memory is available or how special hardware should be configured.

To override the default runlevel, you can add an additional kernel argument to GRUB as follows:

At the graphical boot screen, press e (for edit), scroll down to select the kernel, and press e again. The spacebar, type single or 1 (some versions of init allow s as well), and press Enter. Finally, press b to boot, and you'll boot into runlevel 1 instead of the default runlevel listed in /inittab.

If you use LILO as a bootloader for launching Red Hat Linux, you can boot directly to a specific runlevel through the LILO prompt: LILO is much easier to use than GRUB in this area. This method is similar to passing a kernel argument through LILO's /etc/lilo.conf file, and works like:

```
boot: valinux 3
```

In this example, after you access LILO's boot prompt by pressing Ctrl+X at the LILO boot screen, Red Hat Linux boots to runlevel 3. Here, the kernel is named valinux, a link in /boot to the actual kernel. Pressing the Tab key at LILO prompt will list the kernel names available. To boot to a rescue or maintenance mode, use a boot prompt like this:

```
boot: vmlinuz single
```

or

```
boot: vmlinuz 1
```

Be warned that LILO will be removed in a future version of Red Hat Linux. You'll need to learn how to use GRUB at some point.

Red Hat Linux includes several command-line and graphical system administration utilities you can use to start, stop, reorder, or restart services in different runlevels. These commands (discussed later in this chapter) work by renaming, removing, or creating symbolic links from /etc/rc.d/init.d to /etc/rc.d/rc* as appropriate. Many administrators use these commands to change the symbolic links to the scripts under each /etc/rc.d/rc* directory rather than do it by hand.

The locations of symbolic links can also be confusing. Red Hat has traditionally kept them in one place, and the Linux Standards Base requires that they now be located elsewhere. Because other scripts reference these files and it would be difficult to change them, Red Hat places symbolic links in the places specified by the LSB.

# Init Scripts and the Final Stage of Initialization

Each /etc/rc.d/init.d script, or init script, contains logic that determines what to do when receiving a start or stop value. The logic might be a simple switch statement for execution, in this example:

```
case "$1" in
start
  ;
stop
  ;
restart
  ;
reload
```
