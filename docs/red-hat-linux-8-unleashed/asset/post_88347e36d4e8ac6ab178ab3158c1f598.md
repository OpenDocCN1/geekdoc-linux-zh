## Managing Users

We have mentioned users previously, but in this section, we will examine how the sysadmin can manage users. Users must be created, assigned a UID, provided an initial set of files for their home directory, and assigned to groups that they may use the system resources securely and efficiently. The system administrator might elect to restrict a user’s access not only to files, but to the amount of disk space they use (learn more about that in the “Managing Quotas” section at the end of this chapter).

## User Management Tools

Red Hat provides several command-line tools for managing users as well as graphical tools. Many experienced sysadmins prefer the command-line tools because they are easy to use and can be included in scripts if the sysadmin desires a repetitive task.

useradd—This command is used to add a new user account to the system. Its options permit the sysadmin to specify the user's home directory and to create the user with the default home directory and group assignments.

useradd -G—This command sets the defaults for the user's home directory, account expiration date, default group, and shell. Used without any arguments, it displays the defaults for the system. The set of files for a user are found in /etc/skel. This is very convenient for the system administrator because any special files, links, or directories can be placed in /etc/skel and will be duplicated automatically with appropriate permissions for each user.

```
ls -al /etc/skel
total 44
dr-xr-x -2 root root Aug 29 11
dr-xr-x -2 root root Aug 29 14 ..
-rw-r-- -1 root root Aug 07 06 .bash_logout
-rw-r-- -1 root root Aug 21 06 .bash_profile
-rw-r-- -1 root root Aug 07 06 .bashrc
-rw-r-- -1 root root Aug 06 07 .bash_login (or .bashprofile)
-rw-r-- -1 root root Aug 09 17 .canna
-rw-r-- -1 root root Aug 16 21 .emacs
-rw-r-- -1 root root Aug 12 49 .gtkrc
dr-xr-x -2 root root Aug 05 26 .kde
```

Each line provides the name, the number of files housed under that directory, the file owner, the file size, creation date, and the filename. As you see, root owns everything, but the adduser command (a symbolic link to the actual command named useradd) copies everything in /etc/skel to the new home directory and resets ownership and permissions. If certain files exist that the system administrator doesn't want the user to change, permissions for files in /home/username can be reset so that the user can read them but can't write to.

userdel—This command will completely remove a user's account (thereby eliminating the user's home directory and all files it contains).

passwd—This command makes the user inactive without eliminating the files. The sysadmin often makes users inactive—for example, if they are terminated, on vacation, or need to have their computer access suspended for some reason. By changing the user's password, you lock the user out of the file.

TIP To lock a user out of his account, use the command `passwd -l`. This prepends an l to the user's encrypted password; the command to reverse the process uses the -u option. This is a more elegant and preferred solution to the problem than the traditional Unix way of manually editing the file.

usermod—This command changes several user attributes. The most commonly used arguments are -s to change the default and -u to change the UID. No changes can be made while the user is logged in or running a process.

chsh—This changes the user's default shell. For Red Hat Linux, the default shell is /bin/bash, known as Bash or Bourne Shell.

## Adding New Users

The command-line approach to adding this user is actually quite simple and can be accomplished on a single line. In the example shown here, the sysadmin will use the useradd command to add the new user kevin. The command adduser (a variant found on Unix systems) is a symbolic link to useradd, both commands work the same. In this example we use the -p option to set the password the user requested; we use the -s to set his special shell, and the -u option to specify his UID. If we created a user with the default settings, we would not need to use these options. All we want to do can be accomplished on one line with

```
useradd kevin -p guitar -s /bin/zsh -u 549
```

## Managing Users

Monitoring user activity is part of the sysadmin's duties and an essential task in tracking how system resources are used. The w command will tell the sysadmin who is logged in, where he is logged in, and what he is doing. The w command can be followed by a specific user's name to show only that user. The ac command provides information about the total connect time of a user measured in hours. It accesses the /var/log/wtmp file for the source of its information. Interestingly, a phenomenon known as “timewarp” can occur in an entry into the wtmp files jumps back into the past and will show unusual amounts of time accounted for users. Although this can be attributed to some innocuous factors having to do with the system clock, it is worthy of investigation by the sysadmin since it can also be the result of a security breach. This command is most useful in shell scripts to generate reports on operating system usage for management.

## Monitoring Activity on the System

The accounting system on your computer keeps track of user usage statistics and is kept in the current /var/log/wtmp file. That file is managed by the init and login processes. If you want to explore the depths of the accounting system, use the GNU user info: info accounting.

The last command searches through the /var/log/wtmp file and will list all the users logged in and out since that file was created. The user “reboot” exists so that you might know who has logged in since the last reboot. A companion to last is last, which shows all failed, or bad, logins. ## Managing Passwords

Passwords are an integral part of Linux security, and they are the most visible part to the user. In this section, you’ll learn how to establish a minimal password policy for your system, where the passwords are stored, and how to manage passwords for your users.

## System Password Policy

An effective password policy is a fundamental part of a good system administration plan. The policy should cover

- Allowed and forbidden
- The frequency of mandated password changes
- The retrieval or replacement of lost or forgotten passwords
- Password handling by users

## The Password File

The password file is /etc/passwd, and it is the database file for all users on the system. The format of each line is as follows:

```
username:password:uid:gid:gecos:homedir:shell
```
