File Transfer Protocol (FTP) was once considered the primary method to transfer files over a network from computer. FTP is still heavily used today, although many graphical FTP clients supplement the original text-based interface command. As computers have evolved, so has FTP, and Red Hat Linux now includes many ways with to use a graphical user interface, or GUI, to transfer files using the FTP protocol.

This chapter contains an overview of the available FTP software-included with Red Hat Linux, with some details concerning its set up, configuration, and use of FTP-specific clients. Red Hat includes two FTP software packages and a number of associated programs you can use to transfer files with the FTP protocol. The following sections provide an overview of how to choose, install, and configure an FTP server.

# FTP Servers

FTP uses a client/server model. As a client, FTP accesses a server, and as a server, FTP provides access to files or storage. Just about every computer platform available software written to allow a computer to act as an FTP server, but Red Hat Linux provides the average user the ability to do this without paying hefty licensing fees and without regard for client usage limitations.

There are two types of FTP servers and access: anonymous and standard. A standard FTP server requires an account name and password from anyone trying to access the server. Anonymous servers allow anyone to connect to the server to retrieve files. Anonymous servers provide the most flexibility,

# Choosing an Authenticated or Anonymous Server

When you are preparing to set up your FTP server, you must first make the decision to install either the authenticated or anonymous service. Authenticated service requires the entry of a valid username and password for access. Anonymous service allows the use of the mail address anonymous and an email address as a password for access. (Note that even if the mail address is bogus, many FTP sites will accept the anonymous login.)

Authenticated FTP servers are used to provide some measure of secure data transfer for remote users, but will require maintenance of user accounts as username and passwords are used. Anonymous FTP servers are used when user authentication isn't needed or necessary, and can be helpful in providing an easily accessible platform for customer support or public distribution of documents, software, or other data.

If you use an anonymous FTP server in your home or business Red Hat Linux system, it is vital that you properly install and configure it to retain a relatively secure environment. Generally, that host anonymous FTP servers place them outside of the firewall on a dedicated machine. The dedicated machine contains only the FTP server and should not contain data that cannot be restored quickly. This dedicated-machine setup prevents malicious users who compromise the server from obtaining critical or sensitive data. For an additional, but by no means a more secure setup, the FTP portion of the file system can be mounted read-only from a separate hard drive partition or volume, or mounted from read-only media, such as CD-ROM, DVD, or other optical storage.

Red Hat Linux includes two FTP server packages with its distribution, but other FTP packages also work with Red Hat Linux. The following sections discuss FTP servers in both categories.

Several FTP servers are available for Linux, and wu-ftpd and vsftpd come bundled with Red Hat Linux. These servers will be covered in this chapter.

# Other FTP Servers

Although wu-ftp is a respectable FTP server, it isn’t the optimal FTP server for sites that need to provide access to a high number of concurrent users. One alternative server is NcFTPd, available from http://www.ncftp.com. This server operates independently of xinetd (which is used to enable and start the wu-ftp server; see the section “xinetd Configuration” later in this chapter) and provides its optimized daemon. Additionally, NcFTPd has the capability to cache directory listings of the FTP server in memory, increasing the speed with which users can obtain a list of available files. Although NcFTPd has many advantages over wu-ftp, NcFTPd isn't GPL software, and its licensing fees vary according to the maximum number of simultaneous connections ($99 for 50 concurrent users and $99 for 50 concurrent users). Because of this, Red Hat doesn't include NcFTPd with its distribution, and you won't find it on this CD-ROM.

> Do not confuse the ncftp client with ncftpd. The package ncftp-3.1.3-13.rpm on the CD-ROM is the client, a replacement for ftp-0.17-13. ncftpd is the FTP server, which can be downloaded from www.ncftp.com.

Another FTP server package is ProFTpd, licensed under the GNU GPL. This server works well with Red Hat Linux and is by many Linux sites, including ftp.kernel.org and ftp.sourceforge.net. ProFTpd is actively maintained and updated for bug fixes and security enhancements. Their developers recommend that you use the latest release (1.2.5 at the time of writing) to avoid exposure to exploits and vulnerabilities. Browse to http://www.proftpd.org to download a copy.

Yet another FTP server package is BSDftp-ssl, which is based on the BSD Unix ftp (and distributed under the BSD license). Bsdftp-ssl offers simultaneous standard and secure access using security enhancements; access requires a special client. For more details, browse to http://bsdftp-ssl.sc.ru/.

Finally, another alternative is to use Apache (and the HTTP protocol) for serving files. Using a Web server to provide data downloads can reduce the need to monitor and maintain a separate software service (or directories) on your server. This approach to serving files also reduces system requirements and gives more flexibility (such as enabling them to download multiple files at once). See Chapter 16, “Apache Web Server Management,” for more information about using Apache.
