# User Accounts

> CAUTION

Because of the potential for making a catastrophic error as the superuser (rm -rf /* comes to mind), always use your system as a regular user and root only temporarily to do sysadmin duties. While you are on a multiuser system, you should consider this advice an absolute rule; if root were to delete the wrong file or kill the wrong process, the results could be disastrous for the business. On your home system, you can do as you please and running as root makes many things easier, but less safe. In any setting, however, the risks of running root are significant.

The system user is not a person, but a process running on the computer that requires ownership of files and processes that it can do its job in a secure manner. (Red Hat calls local users.) For example, the system user named "apache" owns the Web server (assuming that you are using Apache) and all the associated files. No one else (except root) may access those files in a way that apache does not permit. Unlike regular users, system users do not have a home directory or password and cannot log in like a regular user.

You will find a list of all the users on a system in the /etc/passwd file. Red Hat refers to these users as the Standard Users because they will be found on every Red Hat computer.

# User IDs and Group IDs

A computer is a number-oriented machine. It identifies users and groups by numbers known as the User ID (UID) and the Group ID (GID). The alphabetic names displayed are exclusively for the convenience of the biological entities that often annoy the computer.

As was already mentioned, the root user is UID 0. Numbers from 1 through 499 and 65534 are the system, or logical, users. Regular users have UIDs beginning with 500; Red Hat assigns them sequentially beginning with this number.

With only a few exceptions, the GID is the same as the UID. These exceptions are system users that need to act with root permissions: sync, shutdown, halt, and operator.

Red Hat has a private GID for every UID of 500 and greater. The system administrator can add other users to a GID or create a totally new group and add users to it. A group cannot be a member of another group.
