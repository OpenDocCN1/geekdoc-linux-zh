# An Introduction to DNS

DNS is essential for many types of network operations, and especially so when providing connectivity to the outside world via the Internet. DNS was designed to make the assignment and translation of hostnames fast and reliable and provide consistent, portable namespace for network resources. Its database is maintained in a distributed fashion to accommodate its size and need for frequent updates. Performance and bandwidth utilization is improved by the extensive use of local caches. Authority over portions of the database is delegated to people who are able and willing to maintain them in a timely manner so that updates are no longer constrained by the schedules of a central authority.

DNS is a simple but easily misconfigured system. Hostname resolution errors might manifest themselves in far from obvious ways, long after the changes that caused them were made; making naming errors can lead to unacceptable and embarrassing service disruptions.

An understanding of the concepts and processes involved in working with BIND will help make sure that your experiences as a DNS administrator are pleasant ones.

# Practical DNS for Regular Users

Typically, only system administrators need to worry about Domain Name Server configuration. DNS isn't a concern for Red Hat Linux users working at a standalone workstation or when connected to a LAN. The important task of mapping IP addresses to hostnames and back is generally handled by a remote DNS server that is managed by your Internet service provider (ISP) or the system administrators of a business or organization.

# Configuring DNS

Although this chapter focuses on setup and configuration in order to provide DNS, the important user setup and configuration for DNS will likely have been accomplished during the initial installation of Red Hat. After the initial installation, DNS configuration can be accomplished by one of these methods:

+   Using Dynamic Host Control Protocol (DHCP)—in which case, system settings are updated by the dhclient without intervention by a local or remote administrator or user

+   Using the redhat-config-network GUI configuration tool

+   Manually editing the system's /etc/resol.conf configuration file to add nameserver, domain, or search definition entries

For example, from a Red Hat user perspective and need-to-access naming service, a simple, but usable /etc/resolv.conf generally contains at least two nameserver entries, specifying a primary and secondary nameserver (using fictitious internal IP addresses):

```
nameserver 192.168.2.1
nameserver 192.168.2.2
search mydomain.com
```
