# The fdisk Command

The Linux fdisk command edits the partition table.

You must be the superuser (root) before you can run the console tool fdisk (also said in Linux shorthand as "run fdisk as root"). Only hard drives (IDE and SCSI) can be accessed with fdisk, and you must use the device name as an argument. USB hard drives are accessed under SCSI emulation and are treated just if they were SCSI devices. For example, to open fdisk and use it on the first IDE drive on the system, you would type this

```
# fdisk /dev/hda
```

and you would see something like this:

```
# fdisk /dev/hda
```

The number of cylinders for this disk is set to 4982. There is nothing wrong with it, but this is larger than 1024, and in certain setups could cause problems with software that runs at boot time:

- 1) software that runs at boot time (e.g., old versions of LILO)
- 2) booting and partitioning software from other OSes (e.g., DOS FDISK or the OS/2 FDISK)

> TIP
> fdisk is only dangerous to explore if you write the partition table. Because you are specifically asked whether you want to do this, poke around to satisfy your curiosity and avoid pressing the w key when you're done; use q to quit. Armed with this knowledge, don't feel too shy if you're curious about the partition table. But if you really don't want to take a chance on breaking anything, play it safe and use the -l (that's the letter L, not the numerical 1) as in

```
# fdisk -l /dev/hda
```

fdisk happily prints the contents of the partition table to the screen (often referred to as stdout, or standard output) and without leaving you in the edit mode.

It's always a good idea to keep a hard copy of your edited partition table. You can redirect the output of fdisk -l to file

```
# fdisk -l device > mypartitiontable.txt
```

or send it to the printer with

```
# fdisk -l device | lpr
```

In the first example, a redirector symbol (>) is used to redirect the listing from stdout to a file. In the second example, we used a pipe (|) to send the output to the printer (assuming that you have one connected).

# Creating a Filesystem

Now that you are running fdisk as root, you can create a partition table. We will assume that you have installed a brand-new drive as /dev/hdb (the Primary IDE) and want to partition the entire drive as a single partition. Launch fdisk with

```
# fdisk /dev/hdb
```

Use the n key to create a new partition, and fdisk will prompt you for the beginning cylinder: Press the Enter key to accept the default of 1. Now, fdisk prompts Last Cylinder or +size or +sizeM or +sizeK (-9729, default 9729): Here, you can give the size in cylinders, the size in kilobytes, the size in megabytes, and accept the default value (which is the last cylinder on the disk). Press the Enter key to accept the default value 9729. We are back at the fdisk prompt: Command (m for help): Enter the w command to write the new partition table to the disk, and fdisk will exit, returning you to the command prompt.

# The sfdisk Command

An alternative to fdisk is sfdisk. The real power of sfdisk over fdisk is that its actions can be scripted, so you can write scripts to do what you want. A sysadmin might want to use sfdisk if he were doing Linux installations on a hundred identical computers, writing scripts, and restoring data to hard drives. sfdisk would be a good choice for use on a networked, multi-user system. sfdisk has a number of safeguards built in to prevent accidents: For example, running the command alone generates only a listing of commands. Although the syntax is much different than for fdisk, it is straightforward and accomplishes the same thing. sfdisk can be a little awkward to use. Figure 10.1 shows the help screen.

# The Parted Command

In the past, Red Hat used a partition editor during its installation process named Disk Druid; the underlying code for Disk Druid has been replaced by GParted (also known simply as parted, the name of the command itself). Gnupart is the GNU partition editor and a very powerful utility. You used create, delete, move, resize, and copy ext2 and FAT32 partitions. Although Gnupart displays a GUI interface during the installation process, it is also a console utility. It can be used from the command line or through scripts with sfdisk.

# Creating the Filesystem on the Partitioned Disk

After you have partitioned the disk for a specific filesystem, you can create the filesystem on it. In the DOS world, this two-part process is described by DOS as low-level formatting (creating the partitions and partition table) and formatting (creating the filesystem). In this section, you will learn to create a filesystem in Linux.

An unformatted storage device (a floppy disk, hard disk drive, or removable media) typically arrives to you with a low-level format, which has been done with a tool such as fdisk or superformat. Although the disk might have a boot block and partition information, it typically lacks the file structure needed for a filesystem.
