# Undleting Files

Up this point, we have discussed backing up data and restoring data. In some situations, however, you need to restore data that has not been backed up because you accidentally deleted it. File recovery (and system recovery, which you learn about in a later section) require a high level of expertise to successfully complete. There are data recovery businesses that are good at data and system recovery, and they exist because the task is difficult. The information presented here, along with practice on your part, can assist you in attempting to fix it yourself or to recognize when a professional service is warranted.

# Using the Ext2fs Undeletion Process

On multiuser systems, when files are deleted, their inodes are made available immediately for use by the system. In that case, recovering data intact is very unlikely, although not impossible. The first rule in deleting a file is to stop all disk writes as soon as possible. The ext2/3 filesystem immediately returns inodes to the system for use. (ext3 doesn't need to be defragmented like A filesystem.) If the system is used, the old inode will likely be overwritten quite soon. The sooner you stop disk writes after deleting a file, the better chance you have of restoring the file.

After you have unmounted the filesystem containing the deleted files, you must attempt to methodically find the deleted parts of the file and reassemble them. Essentially, this involves examining the raw data on the disk using pattern matching to identify candidates for recovery, and then decoding the candidates node information to re-link the files if possible. It is a time-consuming process and should be reasoned enough to back up the files in the first place. On a single user system, the chances of recovery are better because fewer writes to the disk occurred after the deletion.
