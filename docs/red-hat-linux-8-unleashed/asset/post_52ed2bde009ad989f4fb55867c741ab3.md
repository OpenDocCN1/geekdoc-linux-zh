# Using FTP

FTP is a client/server used to connect to the server. Nearly all FTP clients allow file transfers and display remote directories. If enabled, clients can also allow users to create or modify remote directories.

Note however, using FTP can pose a security risk: Usernames and passwords are transmitted in clear text across a LAN or the Internet. For this reason, many sites enable anonymous login and file retrieval. The following sections discuss the different types of traditional and newer interfaces to FTP and their usage.

# Using sftp for Secure FTP Transactions

Use the sftp command, a component of the OpenSSH distribution, to bypass the use of an FTP server and enable secure file transfer. The sftp client uses the sftp-server which is not set up or configured as an FTP server, but is part of the ssh daemon. Sftp provides the benefit of username and password encryption when logging in, and your username and password will not be transmitted in clear text across a network. Although sftp does not have the directory listing features (with wildcard expressions), it has built-in commands with similar capabilities.

You can use sftp to access a server of OpenSSH (which consists of RPM packages) installed and the ssh daemon is running. Secure access is by default, but can be controlled by editing the subsystem in /etc/ssh/sshd_config and restarting sshd (see Chapter 7, “Managing Services,” to see how to start, stop, or restart). A companion command can also be used to transfer files, but requires prior knowledge of the remote computer's file system and a specific pathname on the command line. Data rates will take a hit because of the overhead.

# The FTP Interface

In Red Hat Linux, you can use either a graphical or text-based FTP interface. No matter which type you choose, you can improve your understanding and use of FTP if you learn how to use the text-based client. The text-based interface helps understand what each action does. In this situation, a binary file is transferred as an ASCII file and conversely, an ASCII file is transferred as a binary with a control character at the end of each line. Because Linux is a text-based operating system, some of the following common commands are used in a typical FTP session:

- ascii—Sets an ASCII file type for the FTP session. Use this command before file transfers when sending or receiving text files.
- bin—Sets a binary-type transfer for the FTP session. Use it before file transfers such as images or compressed archives.
- bye—Use this command to close the connection.
- close—Closes a connection to a remote server during an FTP session. Use this command instead of quit or return to the ftp prompt.
- get—Initiates a transfer of a single file from the FTP server to the user’s local machine. Use this command to retrieve a single file (such as get.jpg).
- hash—Sets use of a hash mark (#) during file transfer. Use this command to get visual indication of the progress of a transfer.
- mget—Initiates a transfer of multiple files from the FTP server to the user’s local machine. Use this command to download (receive) multiple files (such as mget *).
- mput—Initiates a transfer of multiple files from the user’s local machine to the FTP server. Use this command to upload (send) multiple files with a single command (such as mput *).
- open—Opens a connection to a remote server using an IP address or hostname. Use this command when working at the ftp prompt (such as open ftp.redhat.com).
- prompt—Is an interactive command that asks the user for input on whether to get a specific file when the mget or mput command is issued. If the user initiates mget *, the client will prompt the user to transfer each file that the wildcard matches. This can be particularly useful when several files in a directory need to be transferred, with one or two that are unwanted. By default, prompting is turned.
- put—Initiates the transfer of a single file from the user’s local machine to the FTP server. Use this command to upload (send) a single file (such as put inventory.doc).
- send—The same command as put.
- quit—The same command as bye.

# A Typical FTP Session Using the ftp Command

When you have configured the server, you will need to test your configuration. A simple test will help ensure that the server is running properly, is responding to FTP requests, and offering the directories and files you want to share.

Begin the test by initiating a connection to the server.

```
$ ftp phenix
Connected to phenix.
220 phenix FTP server (Version uW-2.6.1-18) ready.
Name (phenox:tdc): anonymous
```
