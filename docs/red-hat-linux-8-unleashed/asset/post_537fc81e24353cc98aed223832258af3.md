Although each Mtool is only a symlink to the solitary mtools binary, each has its own managepage. There are more than twenty Mtools, and you can identify their functions by their m* name. The most useful Mtools are:

- mdir--The DOS directory command
- mcopy--The DOS copy command
- mformat--The DOS format command

You use the Mtools as you would their DOS counterparts.

Note that the mformat command only does a high-level format of the filesystem and you need to use the Linux format command first; formats higher than 1.4M are possible with mformat. MtoolsFM is a graphical front end to the mtools that can be down-loaded from http://www.core-cutainville.org/MtoolsFM/; they provide an RPM file for download because Red Hat does not include the tool, as shown in Figure 27.11.

# HFSUtils

HFSUtils is a set of tools similar to Mtools, but written for manipulating Macintosh HFS volumes. The HFSUtils use the same command format as Mtools, with h appended to the HSF command name. Each tool has a manpage describing its use. There are more than a dozen of these tools, but the most useful ones are:

- hdir—The HSF directory command
- hcopy—The HSF copy command
- hformat—The HFS copy format command

# Using Binary Emulation in Red Hat Linux

The format of a compiled binary application is important because it's structured in the way the kernel expects to see the code when it's loaded into memory to be executed. If it is not in a format that can be used by the kernel, it simply can't run. The Linux kernel can perform emulation of binary formats used by other operating systems. By compiling into the kernel or by loading the appropriate module, Linux can load and run binaries that have been compiled for UNIX systems as they were native to Linux and its own ELF format. In addition, the following binary formats are supported by Linux so that it can load them:

- UnixWare 7.x
- Solaris 2.x
- iBC (Intel Binary Compatibility)
- ISC
- OpenServer 5
- Xenix
- Wyse V/
- COFF (Common Object File—UNIX System V)
- x.out (Unix-286)
- a.out (BSD and early Linux)

Many of the supported binaries are obsolete, but they might be useful in environments where very old software is still productively used. The home page of this feature can be found at http://www.kernel.org/linux/binfmt.html, and the kernel documentation is found at /usr/src/linux-2.4/binfmt.txt. You should always follow the licensing requirements of any software you run on your Linux system.

# Web Search Tips

Troubleshooting problems with Linux by searching the Web can be an efficient and productive way to get answers to vexing problems. One of the most basic rules for conducting productive searches is to use specific terms. For example, if you simply search for “Red Hat Linux,” you’ll end up with too many links and too much information. But if you search for “Red Hat Linux sound,” you’re more likely to find the information you need. If you’ve received an error message, use it; otherwise, use the Linux kernel diagnostic message as your search criterion.

Other effective techniques

- Using symbols in the search string, as the plus sign (+) to force matches of Web pages containing both strings (if such features are supported by the search engine used by Web search site)
- Searching within returned results
- Sorting results (usually by date to get the latest information)
- Searching for related information
- Stemming searches; for example, specifying returns for not only “link” but also “linking” and “linked”

Invest some time and experiment with your favorite search engine’s features—in addition to sharpening your search skills, also take time to choose the best search engine for your needs.
