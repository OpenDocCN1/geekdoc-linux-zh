
satisfy directive to All (if the default) or Any. When set to All, access control
methods must be satisfied before the resource is served. If satisfy is set to Any, the
resource is served if any access condition is met.

Here's another access control example, again using the previous server-status example.
This time, combine access methods so that all users from the Gnulix domain are allowed
access and those outside the domain must identify themselves before gaining access.
You can do so with the following:

```
<Location /server-status>
SetHandler server-status
Order deny,allow
Deny from all
Allow from gnulix.org
AuthType Basic
AuthName "Server status"
AuthFile *gnulixusers
Require valid-user
Satisfy Any
</Location>
```

There are more ways to protect material on your Web server, but the methods discussed
here should get you started and probably be more than adequate for most circum-
stances. Look to Apache's online documentation for more examples of how to secure areas
of your site.

## Apache Modules

The Apache core does relatively little; Apache gains its functionality from modules. Each
module solves a well-defined problem by adding necessary features. By adding or remov-
modules to supply the functionality you want Apache to have, you can tailor Apache
server to suit your exact needs.

Nearly 50 core modules are included with the basic Apache server. Many more are avail-
able from other developers. The Apache Module Registry is a repository for add-on
modules for Apache, and it can be found at http://modules.apache.org. The modules
are listed in the modules directory /etc/httpd/, but this directory is a link to the
/usr/lib/httpd modules directory where the modules reside:

| mod_access.so | mod_cern_meta.so | mod_log_config.so | mod_setenvif.so |
| mod_actions.so | mod_cgi.so | mod_mime_magic.so | mod_speling.so |
| mod_alias.so | mod_dav_fs.so | mod_mime.so | mod_ssl.so |
| mod_asis.so | mod_dav.so | mod_negotiation.so | mod_status.so |
| mod_auth_anon.so | mod_dir.so | mod_perl.so | mod_suexec.so |
| mod_auth_dbm.so | mod_env.so | mod_proxy_connect.so | mod_unique_id.so |

Each module adds directives that can be used in your configuration files. As you might guess, there are far too many extra commands, switches, and options to describe all them in this chapter. The following sections briefly describe those modules available with Red Hat’s Apache installation.

## mod_access

mod_access controls access to areas of your Web server by IP addresses, hostnames, or environment variables. For example, you might want to allow anyone from your own domain to access certain areas of the Web. Refer to the "File System Authentication and Access Control" section for more information.

## mod_alias

mod_alias manipulates the URLs of incoming HTTP requests, such as redirecting a client request to another URL. It can also map a part of the file system into your Web hierarchy. For example,

```
Alias /images/ /home/wsb/graphics/
```

would fetch contents from the /home/wsb/graphics directory for any URL that starts with /images/. This is done without the client knowing anything about it. If you use redirection, the client will be instructed to go to another URL to find the requested content. More advanced URL manipulation can be accomplished with mod_rewrite.

## mod_asis

mod_asis is used to specify, in fine detail, all information to be included in a response. This will completely bypass headers that Apache might otherwise have added to the response. All files with an .asis extension will be sent straight to the client without any changes.

As a short example of the use of mod_asis, assume that you've moved content from one location to another on your site. You must inform people who try to access this resource that it has moved, as well as redirect them to the new location automatically. To provide this information and redirection, you can add the following code to a file with an .asis extension:

```
Status: 301 No more old stuff!
Location: http://gnulix.org/newstuff/
Content-type: text/html

```

<HTML>
<HEAD>
<TITLE>We've moved...</TITLE>
</HEAD>
<BODY>
<P>We've moved the old stuff and now you'll find it at:</P>
<A HREF="http://gnulix.org/newstuff/">New stuff</a>!.
</BODY>
</HTML>
```

## mod_auth

mod_auth uses a simple user authentication scheme, referred to as Basic authentication, which is based on storing usernames and encrypted passwords in a text file. This file looks much like Unix's /etc/passwd file, and is created with the htpasswd utility. Refer to the "File System Authentication and Access Control" section for more information.

## mod_auth_anon

The mod_auth_anon module provides anonymous authentication for users. It allows users to access certain areas of the server without providing credentials. This is useful for public information.

## mod_auth_dbm

mod_auth_dbm uses DB instead of text to store user information. This can be more secure than using a plain text file.

## mod_auth_digest

mod_auth_digest uses MD5 to hash passwords. This is more secure than Basic authentication because the passwords are not sent over the network.

## mod_auth_mysql

mod_auth_mysql uses a MySQL database to store user information. This allows you to manage users through a database.

## mod_auth_pgsql

mod_auth_pgsql uses a PostgreSQL database to store user information. This is similar to mod_auth_mysql.

## mod_imap

mod_imap provides server-side handling of imagemap files. Clickable regions are defined in a .map file. Six directives are available for use in the .map file. The directives are used to describe the layout of the regions as well as the URLs they lead to.

## mod_include

mod_include enables the use of server-side includes on your server. See the “Dynamic Content” section later in the chapter for more information about how to use SSI.

## mod_info

mod_info provides comprehensive information about your server’s configuration. For example, it will display all the installed modules, as well as all the directives used in its configuration files.

## mod_autoindex

The mod_autoindex module creates a list of files when a directory is requested and there is no index file is present.

## mod_cgi

mod_cgi allows execution of CGI programs on your server.

## mod_dir

mod_dir controls environment variables to be passed to CGI.

## mod_expires

mod_expires is used to add an expiration date to content. This is useful for caching.

## mod_headers

mod_headers is used to manipulate the headers of your responses. You can add, merge, or delete headers as you see fit.

## mod_proxy

mod_proxy implements proxy and caching capabilities for an Apache server. It can proxy cache FTP, CONNECT, HTTP/0.9, and HTTP/1.0 requests. This isn’t an ideal solution sites that have a large number of users and therefore have very high proxy and cache requirements. Here’s, more than adequate for a small number of users.

## mod_rewrite

mod_rewrite is the Swiss Army Knife of URL manipulation. It enables you to perform any imaginable manipulation of URLs using powerful regular expressions. It provides rewrites, redirection, proxying, and so on. There’s very little that you can’t accomplish using this module.
