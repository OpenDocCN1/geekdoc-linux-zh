
## CHAPTER 10 Managing the Filesystem

> NOTE
If you are preparing to create a filesystem on any device other than a floppy disk, examine it with fdisk or any other utility of your choice and modify the partition table accordingly (following the instructions you were in the preceding sections of this chapter).

Zip disks are typically delivered with a single partition numbered 4. This has some arcane relevance to Apple computer users, but is of no importance to Linux users who are free to use any valid number you choose.

To create the filesystem structure, you need to do what is referred to as a high-level format. For FAT systems, this is accomplished by the format command. In Linux, you use the mke3fs command to create an ext3 filesystem.

> NOTE
If you are creating a Reiser filesystem, use the miserfs command. To create a DOS filesystem, use the mkdosfs command. Other commands for other filesystems include:

- mkfs.bfs—The SCO filesystem
- mkfs.ext2—The ext2 filesystem
- mkfs.minix—The minix filesystem
- mkfs.msdos—The MS-DOS filesystem
- mkfs.vfat—The FAT32 filesystem

The special tools used to manipulate the FAT and MS-DOS filesystems are known as the Mtools and are covered in Chapter 27, "Using Emulators and Other Cross-Platform Tools in Red Linux," along with their counterparts for the Macintosh HFS filesystem.

## Using mke2fs to Create the Filesystem

The mke2fs command is used to create both the ext2 and ext3 filesystems. At its simplest, the command is used as:

```
# mke2fs device
```

Here are some of the most useful options for mke2fs:

- -c—This option checks for bad blocks during filesystem creation.
- -N—This option overrides the default number of inodes created. (The default number is usually a good choice, but you might need to use this option to allow additional disk space.)
- -m—This option frees up some space on the disk, but you do so at your peril. By default, the system allocates 5% of the blocks to the superuser—to be used in file recovery during fsck. You can lower that allocation, but you might not leave enough blocks for fsck to recover enough files.
- -L—This option gives the volume label, which is useful if you need to be reminded what the filesystem is used for; it also provides flexibility in identifying volumes in /etc/fstab.
- -S—This option is a last-ditch effort for recovering a mung filesystem; it writes only the superblock and descriptors, leaving the information in the inodes unchanged. Always run fsck after using this option.

As you can see, mke2fs offers a few options to make more space available for the regular users. But that space always comes from the superuser's space for recovering damaged files. The default settings accommodate most users, so think carefully before using one of these options. Hard disks are getting less expensive all the time, so adding another might be a better solution.

Using mk2fs.ext3
to make a new ext3 filesystem, use the mk2fs command with the -j or -J option, or call the command as mk2fs.ext3 (There is no mk3fs command). Use the tune2fs command on an existing ext2 filesystem to add journaling. (You learn how to convert an existing ext2 filesystem into an ext3 filesystem in this chapter.)

## tune2fs /dev/hdxn -j
Some arguments you can use with this command include:

- -j—This option adds an ext3 journal to the new filesystem using the default values. Note that you must be using a kernel that has ext3 support to actually make use of the journal.
- -J journal-options—This option overrides the default ext3 journal parameters so that you can choose the options using the -size=size=journal-size—This creates a journal of journal-size megabytes. With a minimum size of 1,024 blocks, it can't be more than 102,400 blocks. There must be enough free space in the filesystem to create a journal of that size.
- -device=journal—This option associates the filesystem with a journal not contained within the filesystem (one must have already been created with the command mk2fs -O journal_device journal_name); in other words, the journal and the data files don't have to be on the same device.

> NOTE
The latter two options in the arguments list are mutually exclusive.

To select the ext3 journaling mode, you must add the appropriate entry in /etc/fstab.

Because the ext3 filesystem is a new version of the ext2 filesystem with journaling added, it supports the same options as ext2, as well as the following additions:

- -noad—This option disables the ext3 file system's journal when mounting; it becomes an ext2 filesystem.
- data=journal / data=ordered / data=writeback—This option specifies the journaling mode; "ordered" is the default. Metadata is always journaled.
- journal—The slowest, most secure mode because all the data is written to the journal before it is written to the regular filesystem.
- ordered—This is the default mode in which all data is written to the main filesystem prior to its metadata being committed to the journal.
- writeback—With this option, data can be written into the main filesystem after its metadata has been committed to the journal. This option allows old data to appear in files after a crash and journal recovery, it is the fastest option.

## Using mkreiserfs

The Reiser filesystem joins file data and handles smaller files more efficiently than the ext3 filesystem. Although it is suitable for use as root filesystem, Red Hat does not officially support its use in that way. You may use the mkreiserfs command to create a Reiser filesystem. The default values for mkreiserfs work well. To create a Reiser filesystem, use:

```
# mkreiserfs device
```

## Creating a DOS Filesystem with mkdosfs

It's possible to create DOS files without owning any Microsoft software using the mkdosfs command. To create a DOS filesystem in an image file (useful with some emulators such as Bochs; see Chapter 27), use the -c option. The -n option allows you to specify a volume label. To create a 1.4M DOS filesystem as an image file the sector size (-S) should be 512 and the block count should be 1440. Use the -v option to provide verbose output that we can observe what happens.

```
# mkdosfs -n dosfloppy -C floppy.img -S 512 1440
```

To create a DOS filesystem on a disk drive, use:

```
# mkdosfs -n dosfloppy device
```

## Mounting Filesystems

Filesystems in UNIX are very flexible; they need not be physically present; you can have network access to other filesystems. The Linux filesystem (the Virtual Filesystem we spoke of at the beginning) makes it all appear local. As the system administrator, you decide what filesystems are to be made available and where they will be attached, or mounted, to the root filesystem. The standard arrangement of such is found in the File Hierarchy Standards. Although a detailed discussion of these standards is beyond the scope of this section, they can be examined at http://www.pathname.com/fhs/. In this section, you learn how to mount filesystems and add filesystems to the system, and you learn the traditional method of commonly used

In Linux (and its UNIX cousins), all filesystems—local, remote, images on a disk, or in memory—are mounted on a single point called root (which isn't the same as the root operator also known as the superuser). This mount point is written as a forward slash /. Once mounted, the physical location of the file is unimportant. Even if the files are different (FAT, ext2, HPFS, nfs, and so), the Linux kernel modules and the VFS make them all as part of the directory as native files. This obviates the need for any applications to be aware of the physical location of the file or the true nature of the native filesystem. This simplifies programming these applications because they only have to work with native files.

## The mount Command

Filesystems are mounted with the mount command and unmounted, curiously enough, with the mount command.

During the installation, you have the opportunity to decide where and how your partitions will be mounted. You indicate your choices and Red Hat automatically store them in /etc/fstab, the Filesystem Table, The mount command looks at the /etc/fstab and mounts the filesystem according to those set preferences.
