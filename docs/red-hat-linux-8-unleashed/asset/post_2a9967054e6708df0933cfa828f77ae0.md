The Ext2fs Undeletion mini-HOWTO (http://www.tldp.org/HOWTO/mini/Ext2fs-Undeletion.html) has been written to detail the process. ## Reformatting with the -S Option When Experiencing Unrecoverable Filesystem Errors

In attempting to recover data from a damaged disk with filesystem errors that can’t be fixed with fsck, you run the mkefs command with the -S option like this (if you are having trouble with the ext2 partition on /dev/sda1)

```bash
# mkefs -S /dev/sda1
```

The -S argument writes new superblock information, but doesn’t write new nodes; this might make the missing data salvageable, or it might not depend on the damage. You must run e2fsck on the unmounted partition after using the mkefs command in this manner.

Because a directory is a file as well, the same techniques for file recovery can be used to recover directory entries. The Ext2fs Undeletion of Directory Structures mini-HOWTO (http://www.tldp.org/HOWTO/mini/Ext2fs-Undeletion-Dir-Struct/index.html) is written as a companion to the Ext2fs Undeletion mini-HOWTO—both of which should be on everyone’s reading list if you want to successfully delete any files. The manual technique described in the HOWTOs is too long and complex to be covered in this book.

## Undeleting Using mc

The Midnight Commander can use of a virtual filesystem and includes an undelete filesystem that can be used on ext2/3 partitions. The mc utility is an interface to the ext2fs library, and the virtual filesystem handles for the nitty-gritty details of the filesystem that the previous paragraph alluded to. With any simplified solution to complex issues, mc must make some assumptions for you that might result in less data recovered than if you use the manual method. For that reason, using mc for recovering deleted files is not a standard method.

To use the recovery filesystem, you must cd in one of the panels to the special filename formed by combining the prefix #undel: with the partition name where your deleted file resides. For example, to attempt to recover a deleted file on /dev/hda1, do this:

```bash
# cd #undel:/hda1
```

Be patient because it will take a while for the deleted files to be displayed. You will see a list of nodes that you can examine with the text editor (using the F4 key); then use the F12 key to perform Save operation, renaming the file to something appropriate for your use. Repeat this process until you have named and saved all the files. Press the F10 key to exit when done. Note that you might be able to recover only pieces of files and might not be able to recover any at.

## System Rescue

There will come a time when you need to engage in system rescue. This arises when the system will not start so you can recover files. This is frequently a problem with the bootloader or partition table (discussed in Chapter 8), but it could be critical system files have been inadvertently deleted or corrupted. If you have been making backups properly, these kinds of system failures are easily, though not quickly, recoverable through a full restore. Some valuable data might not have been backed up since the last scheduled backup, and the backup are found to be corrupt, incomplete, or missing. If the problem causing the system failure is simply a damaged bootloader, a damaged partition table, a missing library, or misconfiguration, a quick fix can get the system up and running and the data can be retrieved.

## CHAPTER 11 Backing Up, Restoring, and Recovery

In this section, we will examine a way to back up and restore the bootloader itself, having failed to do that, restore it by hand. We'll look at a few alternatives to booting the damaged system that we can inspect, fix it, or retrieve data from it.

### Backing Up and Restoring the Master Boot Record

The Master Boot Record (MBR) is the first 512 bytes of hard disk. It contains the bootloader in the next 446 bytes and the partition table in the next bytes; the last bytes identify as MBR. It can become corrupted, so it makes sense to back to it as well. To back it up, this example uses the dd command and will back up the entire MBR. If the bootloader code changes from the time you make this image and restore the old code, the system won't boot; it's easy enough to keep a boot floppy handy and then re-run LILO if that's what you are using.

To copy the entire MBR to a file, use this:

```bash
# dd if=/dev/hda of=/tmp/hda bs=512 count=1
```

To restore the MBR, use this:

```bash
# dd if=/tmp/hda of=/dev/hda bs=512 count=1
```

To restore only the partition table, skipping the bootloader code, use this:

```bash
# dd if=/tmp/hda of=/dev/hda skip=446 count=6
```

Of course, it would be prudent to move the copy of the MBR to a floppy or other storage device. You will need to run dd on the system in order to restore it (which means that you will be using the Red rescue disk as described later, or any equivalent to it).

### Manually Restoring the Partition Table

A different way of approaching the problem is to have a hard copy of the partition table that can be restored by hand using the Red Hat rescue disk and the fdisk program. We can also make a listing of the partition table with fdisk using the L option, as follows:

```bash
# fdisk /dev/hda -l /tmp/hdconfig.txt
```

We can also copy the file /tmp/hdconfig.txt to the backup floppy for safekeeping as well.

Now that we have a hard copy of the partition table, it is possible to restore the MBR by hand. Use the Red Hat Rescue Disk for this process. Simply boot from the first install CD-ROM and enter linux rescue at the LILO prompt. You will have the opportunity to mount your system/write, not to mount your system, or to mount any Linux partitions as read-only. If you plan to make any changes, you will need to have any desired partitions mounted with write permission.

Once logged on (you are root by default), start fdisk on the first drive:

```bash
# fdisk /dev/hda
```

Use the p command to display the partition information and compare it to the hard copy you have. If the entries are identical, you will have a problem somewhere else; it's not the partition table.

If there is a problem, use the d command to delete all the listed partitions. Now use the n command to create new partitions that match the partition table of your hard copy. Make certain that the partition types (ext2, FAT, swap) are the same. If you have a FAT partition at /dev/hda1, make certain that you set the bootable flag for it; otherwise, Windows or OS does not boot.

If you find that you have made an error somewhere along the way, just use the q command to quit fdisk without saving any changes and start over. When the partition table shows on your screen matches your printed version, write the changes to the disk with the w command; you will be automatically exited from fdisk. Restart fdisk to verify your handwork, and then remove the rescue disk and reboot.

### Booting the System from the Rescue CD

For advanced Linux users, you can use the rescue CD to boot the system (rather than the the operating system on the CDROM) if the bootloader on your computer is damaged or incorrect. To Use the Rescue CD to boot your system from /dev/hda1, for example, first boot the CD and press the F1 key. In the LILO prompt, enter something like this example:

```bash
linux rescue root=/dev/hda1
```
