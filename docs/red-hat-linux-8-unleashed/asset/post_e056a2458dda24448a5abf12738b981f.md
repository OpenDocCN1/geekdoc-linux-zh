- The default values found in the file /etc/sysconfig/sendmail are fine as they are not and need to be changed.

- You must manually add conf/httpd-mailman.conf to the file /etc/httpd/conf/httpd.conf by using a text editor. This is a surprising omission on Red Hat's part, considering the other Red Hat has given to setting up Mailman. That line should be added automatically by the RPM installation. There is already a line in the file that begins with Include. You need to find that line and add the new line below it, and then save the file.

You can restart httpd when you are finished adding the text:

```bash
service httpd restart
```

If you experience any problems with the Mailman installation and setup, you can look for additional configuration and troubleshooting tips in the INSTALL, README.SENDMAIL, README.EXIM files are provided by Mailman, to provide configuration information for those who use the Postfix or Exim program instead of Sendmail.

All the Mailman commands are kept in /var/mailman. Although they are owned by root, they are in the mailman group.

To manually run the Mailman commands, you change directories to /var/mailman/bin and run them from there. You'll need to precede all Mailman commands with ./ because they are not in your path (on purpose, security reasons), so the doctor tells the shell to start looking for the command in the current directory rather than the default path.

To create a new mail list, use the newlist command, like this:

```bash
./newlist
```

After you run the command, you are prompted for the name of the new mail list and for the list administrator's email address and the password; the newlist command then sends an email message to the administrator, with instructions telling the administrator that the list is active. The message also provides a URL for administration of the list and a password. Although administration on the mail list can be done manually from the /var/mailman directory if you are root, the easiest and recommended way to manage the list is through the Web interface.

If you're the list manager and didn't see that notification message, you can point your browser to http://localhost/mailman/admin, select the appropriate list, and enter the password. You are then directed to the options page for that list, shown in Figure 20.10. You scroll down to this screen to modify the options. Beside the description of every item you can modify is a linked name (Details); you click that link to display a context-sensitive help screen.

## Relevant Red Hat Linux Commands

You can use the following commands to manage newsgroups and other collaborative communication processes in Red Hat Linux:

- emacs—The premiere editing environment that can also be used (surprise!) to read Usenet news
- inn—The INN daemon and its plethora of associated commands
- knode—KDE's graphical Usenet newsreading client
- mozilla—The mail and newsgroups component of the open-source Mozilla browser
- pan—An easy-to-use Usenet reader for GNOME
- pine—A text-based mail client that can also read Usenet news
- slrn—A text-based graphical Usenet newsreader
