# Avoiding Printer-Support Problems

Troubleshooting printer problems can be frustrating, especially if you find that your brand new printer is not working properly with Linux. First, keep in mind that nearly all printers on the market today work with Linux. However, there are some vendors with higher batting averages in the game of supporting Linux. If you can read a scorecard, browse to http://www.linuxprinting.org/vendors.html.

# All-in-One (Print/Fax/Scan) Devices

Problematic printers, or printing devices that may or not work with Red Hat include multi-function, or all-in-one type printers that combine scanning, faxing, and printing services. You would be well-advised to research any planned purchase, and avoid any vendor unwilling to support Linux with or development information.

One shining in the field of Linux support for multi-function printers is Hewlett Packard/Compaq's (whatever it is called nowadays) support of the HP Linux project at http://hoj.sourceforge.net/. Printing and scanning is supported on many models, with fax support in development.

# Using USB and Legacy Printers

Other problems can arise because of a lack of a printer's USB vendor and device information—a problem shared by some USB scanners under Linux. For information regarding USB printer support, you can check with the Linux printing folks (at the URL in the start of this section) or with the Linux project at http://www.linux-usb.org.

Many newer printers require Universal Serial Bus (USB), excellent support still for legacy parallel-port (IEEE-1284) printers with Linux, allowing sites to continue using older hardware. You can take advantage of Red Hat Linux workarounds to set up printing even if the host computer does not have a traditional parallel port printer or if you want to use a newer USB printer on an older computer.

For example, to host a parallel-port bridge on a USB-only computer, attach the printer to the computer using an inexpensive USB-to-parallel converter. USB-to-parallel converters typically provide a Centronics connector; one end of that connector is plugged in the older printer, whereas the other end is plugged in a USB connector. The USB connector is then plugged in your hub, desktop, or notebook USB port. On the other hand, you can use an add-PCI card to add USB support for printing (and other devices) if the legacy computer does not have a built-in USB. Most PCI interface cards add at least two ports, and devices can be chained via a hub.

# Networking with TCP/IP

The basic building block for any network based on UNIX hosts is the Transport Control Protocol/Internet Protocol (TCP/IP) suite of three protocols. The suite consists of the Internet Protocol (IP), Transport Control Protocol (TCP), and Universal Datagram Protocol (UDP). IP is the base protocol. The TCP/IP suite is packet-based, which means that data is broken into little chunks on the transmit end for transmission to the receiving end. Breaking data up into manageable packets allows for faster and more accurate transfers. TCP/IP, all data travels via IP packets, which is why addresses are referred to as IP addresses. It is the lowest level of the suite.

# CHAPTER 13 Network Connectivity

TCP is a connection-based protocol. Before data is transmitted between two machines, a connection is established between them. When a connection is made, a stream of data is sent to the IP to be broken into the packets that are then transmitted. At the receiving end, the packets are put back in order and sent to the proper application port.

On the other hand, UDP is a connectionless protocol. Applications using this protocol choose their destination and starting point. UDP is normally used for small amounts of data or on fast and reliable networks. If you're interested in the internals of TCP/IP, see the “Reference” section at the end of this chapter for places to look for more information.

# Red Hat and Networking

Chances that your network card was configured during the installation of Red Linux. You can, however, use the ifconfig command at the prompt or Red Hat's graphical configuration tools, such as redhat-config-network, to edit your system's network device information or add or remove network devices. Hundreds of networking commands and utilities are included with Red Linux—far too many to cover in this chapter and more than enough for coverage in two or three volumes.

Nearly all Ethernet cards can be used with Red Hat Linux, along with many PCMC wired and wireless network cards. However, you won't find many network devices working with Red Hat Linux (as a few are working with the latest kernels at the time of this writing, and the situation might improve; check the Linux USB Project at http://www.linux-usb.org for the latest developments). After reading this, you might want to learn about other graphical network clients for use with Linux. The GNOME ethereal client, for example, can be used to monitor all traffic on your LAN or specific types of traffic. Another client, Nmap, can be used to scan a specific host for open ports and other running services.

# TCP/IP Addressing

To understand networking with Red Hat Linux, you need to know the basics of TCP/IP addressing. Internet IP addresses (also known as public IP addresses) are different from those used internally on a Local Area Network, or LAN. Internet IP addresses are assigned (for the United States and some other hosts) by the American Registry for Internet Numbers, available at http://www.arin.net/. Entities that need an Internet address apply to this agency to be assigned address. The agency assigns Internet service providers (ISPs) one or more blocks of IP addresses, who then assign them to subscribers.

You'll quickly recognize the current form of TCP/IP addressing, known as ipv4. In this method, a TCP/IP address is expressed of a series of four decimal numbers—a 32-bit value expressed in a format such as 192.168.120.135. Each set is known as an octet (eight ones and zeros, such as 10000000 to represent 128) and ranges from zero to 255.
