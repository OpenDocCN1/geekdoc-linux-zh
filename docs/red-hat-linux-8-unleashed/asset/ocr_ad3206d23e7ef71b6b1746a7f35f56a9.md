# Using Service Management to Troubleshoot Problems in Red Hat Linux

Change to runlevel 3 by switching to another virtual console with Ctrl+Alt+F2, logging in as root, and running the command telinit 3. This switch to runlevel 3 will stop the X server from attempting to restart itself.

Now you can easily examine the X server and attempt to fix it.

First, try to start the X server “naked” (without launching the window manager). If you're successful, you'll get a green screen with a large X in the middle. If so, kill X with the Ctrl+Alt+Backspace combination, and look at your window manager configuration. (This configuration varies according to which window manager you have chosen.)

Let's assume X won't run “naked”. If we look at the log file for XFree86 (it's clearly identified in the /var/log directory), we'll pay attention to any line that begins with (EE), the special error code. We can also examine the error log, .xsessions-error, in home directory if such a file exists.

If we find an error line, the error might appear to us or not. The nice thing about the Linux community is that it is very unlikely you are the first person to ever experience an error. Enter the error message (or a unique part of it) into http://www.google.com/linux and discover what others have had to say about the problem. You might need to adjust your search to yield usable results, but level of detail is beyond the scope of this chapter. Make adjustments and retest as before you achieve success.

Fix the X configuration and start X with # startx. Repeat as necessary.

> CAUTION

Before making any changes to any configuration file, always make a backup copy of the original, unmodified file. The practice is to append the extension .original to the copy because that is a unique and unambiguous identifier.

If you need to restore the original configuration file, don't rename it, but copy back to its original name.

When this advice has saved you time and effort—and it will—you can express your appreciation by buying a copy of this book as a gift for a friend.

Of course, you should always consult the XFree86 documentation as well. It's found on your computer in the /usr/share/doc/ directory, with a plethora of other information installed on your system.
