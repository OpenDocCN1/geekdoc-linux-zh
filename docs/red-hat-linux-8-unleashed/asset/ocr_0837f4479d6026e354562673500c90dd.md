# Managing Software Projects with RCS and CVS

Although may be used to manage a software project, larger software projects require document management, source code controls, security, and revision tracking as the source code goes through a series of changes during its development. RCS and CVS provide source code version control utilities for this kind of large software project management. You can find both of these utilities in RPM packages on your Red Linux CD-ROMs.

The RCS and CVS systems are used to track multiple versions of files, and they can be used to backtrack or branch off versions of documents inside the scope of a project. They can also be used to prevent or resolve conflicting entries or changes that are made to source code files by multiple developers.

Although RCS and CVS provide similar features, RCS uses a locking and unlocking scheme to control access to many revisions; CVS, on the other hand, provide a modification and merging approach to working on old, current, or new versions of software. RCS uses different programs to check in or out of a revision under a directory; CVS uses a number of administrative files in a software repository of source code modules to merge and resolve conflicts.

RCS uses at least the following eight separate programs to track source code revisions:

+   - ci-Checks in revisions
- co-Checks out revisions
- ident-Starts the keyword utility for source files
- rcs-Changes file attributes
- resclean-Cleans up working files
- rsdiff-Starts the revision comparison utility
- rcmerge-Merges revisions
- rlog-Activates the logging and information utility

Source code control with CVS requires the use of at least the following six command options on the cvs command line:

+   - checkout-Checks out revisions
- update-Updates your sources with changes made by other developers
