# Resetting the Date and Time

Red Hat Linux will query you for installation date time settings, and or not your computer's hardware clock is set to Greenwich Mean Time (GMT)—more properly known as UTC, or Coordinated Universal Time.

Linux provides a system date and time; your computer hardware provides a hardware clock-based time. In many cases, it is possible for the two to drift apart. Linux system is based on the number of seconds elapsed since Jan. 1970. Your computer's hardware time depends on the type of chips installed on your PC's motherboard, and many motherboard chipsets are notoriously subject to drift.

Keeping accurate time is not only on a single workstation, but also critically important in a network environment. Backups, scheduled downtimes, and other network-wide actions need to be accurately coordinated.

Red Hat Linux provides several date and time utilities you can use at the command line or during an X session, including these:

- date—Used to display, set, or adjust the system date and time from the command line
- hwclock—A root command to display, set, adjust, and synchronize hardware and system clocks
- redhat-config-date—a graphical date, time, and network time configuration tool

# Using the date Command

The date command to display or set your Linux system time. This command requires you to use a specific sequence of numbers to represent the desired date and time. To see your Linux system's idea of the current date and time, use the date command like this:

```
# date
Sep 22 15:53:19 EDT 2002
```

To adjust your system's time (say, to September 23, 2003 at 8 a.m.) use a command line, with the month, day, hour, minute, and year, like so:

```
# date 09230802003
Tue 23 08:00:00 EDT 2003
```

# Using the hwclock Command

The hwclock command to display or set your Linux system time, display or set your PC's hardware clock, or to synchronize the system and hardware times. To see your hardware date and time, use hwclock with its --show option like so:

```
# hwclock --show
Sun 22 Sep 2002 03:59:58 PM EDT -0.719146 seconds
```

Use hwclock with --set and --date to manually set the hardware clock like so:

```
# hwclock --set --date "09/23/03 08:00:00"
# hwclock --show
Tue 23 Sep 2003 08:00:00 AM EDT -15178 seconds
```

In these examples, the hardware clock has been set using hwclock, which is then used to verify the new date and time. You can also use hwclock to set the Linux system time using your hardware clock's values. For example, to set the system time from your PC's hardware clock, use the --systoc like so:

```
# hwclock --systoc
```

To set your hardware clock using the system time, use the --systic option like so:

```
# hwclock --systic
```


# Managing PCMCIA

Red Hat notebook users take advantage of PCMCIA slots to add 70-pin, credit-card sized devices to support Ethernet LAN connectivity, wireless operations, Firewire devices, Compact Flash hard drives, external storage devices, serial ports, and modems. Many different types of PCMCIA cards and Compact Flash form factors are supported by the Linux kernel and Card Services software.

Power is provided by PCMCIA devices and adapters directly through the card slot, although some external hardware might require an additional power source. PCMCIA support is enabled and configured at boot time according to the /etc/sysconfig/pcmia file and /etc/rc.d/init.d/pcmia startup script. The /etc/sysconfig/pcmia file might look like this:

```
PCMCIA=yes
PCIC=socket
PCIC_OPTS=
CORE_OPTS=
```

Previous incarnations of Red Linux and PCMCIA used specific controller information in this file. With the newer Linux kernels however, support is provided by kernel modules or direct Linux kernel support.

# Using PCMCIA

PCMCIA Card Services software provides diagnostic information by one or more high or low beeps upon insertion. One high and one low beep indicate that a card is recognized, but failed to be configured. A single beep indicates that the card was only recognized. Two high beeps indicate that a card was recognized and configured.

For example, if you use a compact storage device and insert it into your notebook while using Red Hat, you should hear two high beeps. You can then check to see what device has been assigned to the card by using the dmesg command:

```
$ dmesg
hde: SunDisk SDCFB-8, ATA DISK drive
ide2 at 0x100-0x107,0x10e on irq 3
ide-floppy driver 0.99.ide
hde: 15680 sectors (8 MB) w/1KiB Cache, CHS=245/2/32
hde: hde1
```

Not all the output is shown here, but the example shows that the card has been recognized and configured as the /dev/hde device (with a single partition, /dev/hde1). You can then use the device as any other storage medium (see Chapter 10, “Managing the Filesystem,” for more information on using hard drives with Red Hat).

Other devices can be similarly recognized and configured. For example, if you have a combination Ethernet and modem PCMCIA card and insert it into your notebook, you should hear two sets of beeps (to indicate successful configuration of the network interface and modem). The Linux kernel will report the interface and device information:

```
$ dmesg
eth0: NE2000(DL1019) rev 05: io 0x300, irq 3, hw_addr 00:E0:98:06:84:C5
ttyS4 at port 0xaf8 (irq 3) is 16450
```

Here, the network interface has been recognized as eth0 (see Chapter 13, “Network Connectivity,” to see how to connect to a network). The modem is configured to use /dev/ttyS0.

Again, troubleshooting problems with PCMCIA cards can be difficult, especially with the explosion in popularity and 802.11b networking cards. Such troubleshooting is likely to require downloading, building, and installing new drivers.

NOTE
If you have trouble and using a PCMCIA card, browse to the Linux PCMCIA home page at http://pcmia-cs.sourceforge.net/. Click the .CARDS link to see if your card is supported. Click the known problems to see if others with the same card are having problems, or if the card is not fully supported. If a new version of the PCMCIA kernel drivers are available and changes have been made to your card’s drivers (or if a new driver has been developed), download and install the new software. “Kernel and Module Management,” see Chapter 24, for information on installing the new PCMCIA modules, or follow the directions included with the PCMCIA software.
