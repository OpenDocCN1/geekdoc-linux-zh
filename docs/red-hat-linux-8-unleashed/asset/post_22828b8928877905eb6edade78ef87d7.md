# Configuring a Fax Modem

Red Hat Linux recognizes and configure a designated serial port (such as /dev/ttyUSB in the example) when the device is plugged in. Red Hat Linux also comes with a number of fax utilities that can be used to configure a system to receive fax phones. One of the easiest to configure fax utilities is the fax command. As root, you can configure the software by editing a few entries in the /usr/bin/fax shell script:

```
DEV=modem
FROM="1 555 555-1212"
NAME="Company Name"
```

The most important entry is DEV=, which won't need to be changed as long as /dev/modem points to an active fax-capable modem. You can also edit /usr/bin/fax to customize other entries, such as the fax viewing command. Use the test command-line option to check the settings like:

```
# fax test
```

Sending a fax using the fax command is straightforward:

```
# fax send 5551212 document.txt
```

Use the minicom or xminicom script (for launching minicom in a terminal window during an X session) for dial-up connections and terminal sessions to remote Red Hat Linux systems. # Configuring Controllerless Modems for Laptops

Other issues regarding modems focus on notebook users with laptops using controllerless modems. These modems use proprietary software to emulate hardware. Despite the release of binary-only drivers to enable use of some modems, these remain the bane of notebook and desktop users. # Configuring Power-Management in Red Hat Linux

Advanced Power Management (APM) allows workstations and servers to automatically turn off when instructed to shut down. Most often used by Red Hat Linux mobile users, APM can help extend battery life through the use of intelligent circuitry, CPU "throttling" (similar to, but not the same as thermal throttling incorporated by Pentium III and IV CPUs), and control of displays and hard drives. Most PCs support APM via the BIOS and hardware. APM support is configured, enabled, and then incorporated in the Linux kernel information is constantly updated in the file /proc/apm, which can look like this:

```
# /proc/apm
14 0x03 0x01 0x09 10800
```

This example provides information about battery charge, along with time and percentage of time remaining. From left to right the example is the driver version, BIOS version, AC status, battery status, battery state, and number of seconds of life remaining. Some X11 clients, such as apm and apload, parse this file and display information in an easier format. These clients can be especially helpful for notebook users. APM is supported by all kernels included with Red Hat. However, problematic hardware or APM misconfiguration can cause kernel panics with some hardware, resulting in the inability to boot. When this happens, you must reconfigure APM, and then build and install a new Linux kernel (Refer to Chapter 2 for more information).

Basic kernel APM configuration options include:

- CONFIG_APM—Whether or not to configure APM support
- CONFIG_APM_IGNORE_USER_SUSPEND—Ignore keyboard suspend
- CONFIG_APM_DO_ENABLE--Enable APM at boot
- CONFIG_APM_CPU_IDLE--Idle CPU when not used
- CONFIG_APM_DISPLAY_BLANK--Enable monitor or LCD panel blanking
- CONFIG_APM_RTC_IS_GMT--Determine clock setting
- CONFIG_APM_ALLOW_INTS--Allow interrupts during APM use (such as serial port activity)
- CONFIG_APM_REAL_MODE_POWER_OFF--Enable powering down

Red Hat Linux includes several APM-related commands—such as apm that prints APM information and apmsleep, used to sleep and wake notebook hardware at a specific time. Red Hat Linux notebook users can use the apm command like this:

```
$ apm -v
APM BIOS 1.2 (kernel driver 1.16)
AC on-line, battery status: 95%
```

Other power management incorporated in the kernel includes control of Peripheral Component Interface (PCI) devices and Display Power Management Signaling (DPMS) for monitors, which can help energy costs by placing devices in a low-power state after a preset time. Screen saving, as astute Red Hat Linux system administrators and users know, is no longer necessary to protect displays from image "burn-in." And password protection enabled by the screensaver only provides a medium of physical security.

Hardware monitoring is supported by the lm_sensors software package, which acquired some notoriety when early versions altered IBM ThinkPad notebooks to suffer permanent damage. However, system administrators managing desktop PCs can benefit from using applications such as the sensors command takes advantage of the hardware monitoring features of the lm_sensors libraries.

You can customize the output of the sensors by editing the (root) file /etc/sensors.conf, but the default settings should work for your computer. To enable sensor reading, use the sensors-detect command to determine what kernel modules to load to enable sensor output:

```
# /usr/sbin/sensors-detect
```

This program will help you determine which I2C/SMBus modules you need to load to use lm_sensors most effectively.

You need to have done a 'make install', issued a 'depmod -a' and made sure /etc/conf.modules (or /etc/modules.conf) contains the appropriate module path before you can use some functions of this utility. Read doc/modules for more information.

Also, you need to be 'root', or at least have access to the /dev/i2c/-]* files for some things. You can use prog/mkdev.sh to create these /dev files if you do not have them already.

If you have patched your kernel and have drivers built-in you can safely answer NO if asked to load some modules. In this case, things may seem a bit confusing, but they will still work.
