An IP (Internet Protocol) address helps a computer system identify a networked computer, but it won't help the average person make the identification. The DNS (Domain Name System) is now used universally on the Internet to provide recognizable hostnames, for networked computers.

Hostnames, like redhat.com, are merely a convenience for users. Communication with other computers still requires IP addresses. Each hostname, therefore, must be translatable into a unique IP address. This translation process is called name resolution and is performed by software known as a resolver.

This chapter introduces DNS concepts and practice using BIND (Berkeley Internet Name Domain), the de facto standard software for Unix. In this chapter, you learn some of the concepts that are basic to DNS and its functions, including how DNS information is stored, how DNS serves information to users, and how name resolution actually works. You learn how to use BIND to configure nameservers and how to provide DNS for a domain. This chapter also teaches you some important techniques for keeping DNS secure, as well as the most important troubleshooting techniques for tracking down potential problems related to DNS.

If you are not going to be a DNS administrator, much of the information in this chapter will be of practical use to you. But the knowledge of DNS that you can gain in this chapter might help you understand DNS problems that occur—not realize your computer is broken!

## An Introduction to DNS

DNS is essential for many types of network operations, and especially when providing connectivity to the outside world via the Internet. DNS was designed to make the assignment and translation of hostnames fast and reliable and provide consistent, portable namespace for network resources. Its database is maintained in a distributed fashion to accommodate its size and need for frequent updates. Performance is improved by the extensive use of local caches. Authority over portions of the database is delegated to people who are able and willing to maintain them in a timely manner so that updates are no longer constrained by a central authority.

DNS is a simple but easily misconfigured system. Hostname resolution errors might manifest themselves in far ways after the changes were made, leading to unacceptable service disruptions. An understanding of the concepts and processes involved in working with BIND will help make sure your experiences as a DNS administrator are pleasant.

## Practical DNS for Users

Typically, only system administrators need to worry about Name Server configuration. DNS isn't a concern for Red Hat users working at a standalone workstation or connected to a LAN. The important task of mapping IP addresses to hostnames back is generally handled by a DNS server that is managed by your Internet service provider (ISP) or organization.

## Configuring DNS

Although this chapter focuses on setup and configuration in order to provide DNS, user setup and configuration for DNS will likely have been accomplished during the initial installation of Red Hat. After the initial installation, DNS configuration can be accomplished by one of these methods:

- Using Dynamic Host Protocol (DHCP)—in which case system settings are updated by dhclient without intervention by a local or remote user
- Using the redhat-config-network GUI tool
- Manually editing the system's /etc/resolv.conf file to add nameserver, domain, or search entries

For example, from a Red Hat user perspective and need naming service, a simple but usable /etc/resolv.conf generally contains at least two nameserver entries, specifying a primary and secondary nameserver (using fictitious IP addresses):

```
nameserver 192.168.2.1
nameserver 192.168.2.2
search mydomain.com
```

The IP addresses listed in the /etc/resolv.conf are usually assigned by an ISP and represent the remote namesvers. Other optional keywords, such as domain and search, are used to specify a local domain and search list for queries; these are mutually exclusive, however.

The information in /etc/resolv.conf can be configured from the redhat-config-network tool by launching the tool from the Network item in the System settings menu. The DNS tab allows you to enter or edit the DNS information, as shown in Figure 14.1.

## Understanding the /etc/hosts File

The redhat-config-network tool is also used to configure the /etc/hosts file—a file that contains a table of local hosts (hostnames and IP addresses) used for local DNS-type lookups. Using /etc/hosts to provide hostnames and hostname aliases can be effective when used on small networks. For example, a short /etc/hosts file might look like this:

```
192.168.2.30 odin.home.org odin
192.168.2.31 thor.home.org thor
192.168.2.32 balder.home.org balder
192.168.2.33 migard.home.org migard
```

...

This example shows a short list of hosts. The format of the file is an IP address, hostname/domain name, and an alias (such as odin). Using this approach, a system administrator would maintain and update a master hosts list, and then replicate the /etc/hosts file to every computer on the LAN. Users are then able to access other systems by using the hostname alias (such as balder). The format of /etc/hosts is easy to understand and easy to maintain, and can be used in conjunction with a Dynamic Host Configuration Protocol (DHCP) server on the same network. (Read more about DHCP in Chapter 13, "Network Connectivity.")

Two disadvantages of using /etc/hosts become readily apparent on a large network: maintenance and replication. Maintaining lists of IP addresses, hostnames, and aliases—along with ensuring changes are regularly updated to every host on the network—can be a challenge.

The /etc/hosts file, if it exists, will usually take precedence over nameserver settings in /etc/resolv.conf. The file /etc/host.conf, known as the resolver configuration file, determines the order in which name resolution occurs. By default with Red Hat, this file contains

- hosts, bind

The order shown here is to first consult /etc/hosts and then DNS (BIND). The file /etc/nswitch.conf also defines a search order for host information, but files such as /etc/hosts, DNS, and Network Information Service (NIS). One example could be

- files dns [NOTFOUND=return] nisplus nis

In this example, the order is as shown previously, but failed searches will default to NIS (nisplus and nis). NIS with Red Hat is the ypserv daemon. The configuration of /etc/nswitch.conf is handled automatically when you use the redhat-config-network tool.
