# CHAPTER 13 Network Connectivity

TCP is a connection-based protocol. Before data is transmitted between two machines, a connection is established between them. When a connection is made, a stream of data is sent to the IP to be broken into the packets that are then transmitted. At the receiving end, the packets are put back in order and sent to the proper application port.

On the other hand, UDP is a connectionless protocol. Applications using this protocol choose their destination and starting point. UDP is normally used for small amounts of data or on fast and reliable networks. If you're interested in the internals of TCP/IP, see the “Reference” section at the end of this chapter for places to look for more information.

# Red Hat and Networking

Chances that your network card was configured during the installation of Red Linux. You can, however, use the ifconfig command at the prompt or Red Hat's graphical configuration tools, such as redhat-config-network, to edit your system's network device information or add or remove network devices on your system. Hundreds of networking commands and utilities are included with Red Linux—far too many to cover in this chapter and more than enough for coverage in two or three volumes.

Nearly all Ethernet cards can be used with Red Hat Linux, along with many PCMIA wired and wireless network cards. However, you won't find many wireless network devices working with Red Hat Linux (as a few are working with the latest kernels at the time of this writing, and the situation might improve; check the Linux USB Project at http://www.linux-usb.org for the latest developments).

After reading this, you might want to learn about other graphical network clients for use with Linux. The GNOME ethereal client, for example, can be used to monitor all traffic on your LAN or specific types of traffic. Another client, Nmap, can be used to scan a specific host for open ports and other running services.

# TCP/IP Addressing

To understand networking with Red Hat Linux, you need to know the basics of TCP/IP addressing. Internet IP addresses (also known as public IP addresses) are different from those used internally on a Local Area Network, or LAN. Internet IP addresses are assigned (for the United States and some other hosts) by the American Registry for Internet Numbers, available at http://www.arin.net/. Entities that need an Internet address apply to this agency to be assigned address. The agency assigns Internet service providers (ISPs) one or more blocks of IP addresses, who then assign them to subscribers.

You'll quickly recognize the current form of TCP/IP addressing, known as ipv4. In this method, a TCP/IP address is expressed of a series of four decimal numbers—a 32-bit value expressed in a format such as 192.168.120.135. Each set is known as an octet (eight ones and zeros, such as 10000000 to represent 128) and ranges from zero to 255.
