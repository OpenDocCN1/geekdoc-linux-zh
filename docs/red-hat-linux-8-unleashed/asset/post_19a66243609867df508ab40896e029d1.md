# Configuring a PPPOE Connection Manually

The basic steps involved in setting up a DSL connection using Red Hat Linux involve connecting the proper hardware, and then running a simple configuration script if you use rp-from Roaring Penguin.

First, connect your DSL modem to your phone line, and then plug in your Ethernet cable from the modem to your computer's network interface card. If you plan to share your DSL connection with the rest of your LAN, you’ll need at least two network cards—designated eth0 (for your LAN), and eth1 (for the DSL connection).

The following example assumes you have more than one computer and will share your DSL connection on a LAN.

First, log in as root, and ensure that your first eth0 device is enabled and up (perhaps using the ifconfig command). Next, bring up the other interface, but assign a null IP address like this:

```
# ifconfig eth1 0.0.0.0 up
```

Now use the adsl-setup command to set up your system. Type the command like this:

```bash
# adsl-setup
```

You’ll be presented with a text script and be asked to enter your username and the Ethernet interface used for the connection (such as eth1). You’ll be asked to use “on demand” service or have the connection stay all the time (until brought down by the root operator). You can also set a timeout in seconds, if desired. You’ll then be asked to enter the IP addresses of your ISP’s DNS servers if you haven’t configured the system’s /etc/resolv.conf file.

After that, you will be prompted to enter your two passwords, and then will have to choose the type of firewall and IP masquerading to. You learned about IP masquerading in the section “Using IP Masquerading in Red Hat Linux,” in Chapter 13). The actual configuration is done automatically. Using a firewall is essential nowadays, so you should choose this option unless you intend to craft your own set of rules—a discussion of which is beyond the scope of this book. After you have chosen your firewall and IP masquerading setup, you’ll be asked to confirm, and implement your settings.

Changes will be made to your system's /etc/ppp/pppoe.conf, /etc/resolv.conf, /etc/ppp/pap-secrets, and /etc/ppp/chap-secrets files.

After configuration finished, use the adsl-start command to start a connection and DSL session, like this:

```bash
# adsl-start
```

The DSL connection should be nearly instantaneous, but if problems occur, check to make sure that your DSL modem is communicating with the phone company's central office by examining the status LED's on the modem. Because this varies from modem to modem, consult your modem's manual.

Check to make that all cables are properly attached, that your interfaces are properly configured, and that you have entered the correct information to the setup script.

If IP masquerading is enabled, other computers on your LAN on the same subnet address (such as 192.168.2) can use the Internet, but most have the /etc/resolv.conf nameserver entries and a routing entry with the DSL-connected computer as a gateway. For example, if the host computer with the DSL connection has an IP address of 192.168.2.32, and other computers on your LAN use addresses in the 192.168.2.XXX range, use the route command on each computer like:

```bash
# route add default gw 192.168.2.32
```

Note that you can also use a hostname instead if each computer has an /etc/hosts file with hostname and IP address entries for your LAN. To stop your connection, use the adsl-stop command like this:

```bash
# adsl-stop
```

Here are a few troubleshooting tips pulled from many years of experience:

- If your modem connects and hangs up, you're probably using the wrong word or dialing the wrong number.
- If you get connected but can't reach Web sites, it's likely a resolver problem, meaning that DNS isn't working. If it worked yesterday and you haven’t “adjusted” the associated files, it's probably a problem at the ISP's end. Call and ask.

# Configuring a Dial-in PPP Server

If you want to access high-speed Internet when you are away, a simple dial-in connection can be used. Red Hat Linux provides a set of tools for this purpose, the most common being the ppp daemon. To set up a dial-in connection, you must first configure the `/etc/ppp/user` file. This file contains the username and password for the dial-in service.

```
username password
```

Then, you need to configure the `/etc/ppp/accessopts` file. This file defines the options for the connection, such as the authentication protocol, compression, and encryption.

```
speed 56000
async
auth-chap
opt no-compress
```

Once these files are configured, you can start the dial-in connection using the ppp command:

```bash
# ppp dial-inS0
```

The connection should be nearly instantaneous, but if problems occur, check to make sure that your DSL modem is communicating with the phone company's central office by examining the status LED's on the modem. Because this varies from modem to modem, consult your modem's manual.

# CHAPTER 15 Internet Connectivity

Many modems can use vgetty to answer calls. vgetty is a program that allows you to accept incoming phone calls on a modem. It provides a similar interface to getty, but for incoming connections.

To set up vgetty, you must first configure the `/etc/vgetty/vgetty.conf` file. This file defines the options for the connection, such as the speed and the device name.

```
speed 56000
/dev/S0
```

Once these files are configured, you can start the vgetty daemon using the vgetty command:

```bash
# vgetty -d S0
```

# Red Hat Linux Voice Messaging

If you're the fortunate owner of a vgetty-supported voice modem, such as the Elsa MicroLink S6K modem, you can download, install, and use the vgetty command to monitor the modem and have your system provide data, and fax services. Edit the file /etc/mgetty/voice.conf, create your answering voice messages in /var/spool/voice/messages, and then use a vgetty /etc/initab entry such as S0:2345:respawn:/sbin/vgetty tty1

In order to host your outgoing message, you'll need to use the wavopvf and pvfspeed commands to convert your voice sound into formats used by the modem, like this:

- # wavopvf myymessage.wav myymessage.pvf
- # pvfspeed -s 7200 myymessage.pvf | pvftorm Elsa 4 > myymessage.rmd

To play your outgoing message (which should be stored in /var/spool/voice/messages with the name stamp.rmd), use the following command line:

```bash
# rmdtopvf myymessage.rmd | pvfspeed -s 8000 | pvftobasic /dev/audio
```

This technique can be used to listen to any messages left by callers (which ends up in the /var/spool/voice/incoming directory).

Browse to http://alpha.greenie.net/vgetty/ to download vgetty and its documentation.
