# Using Wine to Run Windows Programs in Red Hot Linux

The Wine config developers who wrote this description might call it "network", but it is your root partition:

```
[Drive Z]
"Path" = "/"
"Type" = "network"
"Label" = "Root"
"Filesystem" = "win95"
```

> Some people require comment to prevent allow the three entries in their entirety (for drives E, F, and Z) as a safety or security measure. You may not want a Windows application to have access to your home files or the root filesystem.

Here are the definitions of standard file locations that Windows likes to use. If you need an entry for your path, add it to the "Path" line—noting the special \\ syntax used in the pathname.

```
[wine]
"Windows" = c:\windows
"System" = c:\windows\system
"Temp" = e:\
"Path" = c:\windows;c:\windows\system;e:\e:\test;f:\
"Profile" = c:\windows\Profiles\Administrator
"GraphicsDriver" = "x11drv"
```

You can uncomment the following code to allow the use of symlinks, which are one of the most powerful UNIX file characteristics. The only danger is creating recursive symlinks—this will create endless loops for Win32 apps that read directory listings, effectively locking up Wine. Create symlinks with caution so that they are not recursive. Symlinks are covered in Chapter 10, "Managing the Filesystem."

+   ; Wine doesn't pass directory symlinks to Windows programs by default.
; Enabling this may crash some programs that do recursive lookups of a whole
; subdir tree of a symlink pointing back to itself.
;"ShowSymlinks" = "1"
;'ShellLinker" = "winshellink"
