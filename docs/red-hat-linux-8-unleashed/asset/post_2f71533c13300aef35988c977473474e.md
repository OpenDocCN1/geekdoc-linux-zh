
# Logging In and Out from a Remote Computer

Although you can happily log in and use Red Hat on your computer, an act known as a local log in, you can also log in to your Red Hat computer via a network connection from a remote computer. Red Hat Linux provides a number of remote access commands you can use to log in to other computers on your Local Area Network (LAN), Wide Area Network (WAN), or the Internet. The point is not only must you have an account on the remote computer, but also the remote computer must be configured to support remote logins—otherwise, you won't be able to log in.

> NOTE
> See Chapter 13 to see how to set up network interfaces with Red Hat Linux to support remote network logins and Chapter 7 to see how to start remote services (such as ssh).

The best and most secure way (barring future exploits) to log in to a remote Linux computer is to use the ssh or Secure Shell. Your login and session are encrypted while you work on the remote computer. The ssh client features many different command-line options, but can be simply used with the name of the remote computer, like this:

```
[winky@shuttle winky]$ ssh shuttle2
The authenticity of host 'shuttle2 (192.168.2.70)' can't be established.
RSA key fingerprint is 45:93:1ca:ae:02:32:bd:eb:c6:71:ce:26:97:17:5f:0b.
Are you sure you want to continue connecting (yes/no)? yes
```

The first time you connect with a remote computer using ssh, Linux displays the remote computer's encrypted identity key and asks you to verify the connection. After you type and press Enter, you're warned that the remote computer's identity (key) has been entered in a file named hosts under the .ssh directory in your home directory. You're also prompted to enter your password:

```
Warning: Permanently added 'shuttle2,192.168.2.70' (RSA) \
to the list of known hosts.
winky@shuttle2's password:
/usr/X11R/bin/xauth: creating new authority file /home/winky/.Authority
[winky@shuttle winky]$
```

After entering your password, you can then work on the remote computer. Again, everything you enter on the keyboard in communication with the remote computer is encrypted. Use the exit or logout commands to exit your session and return to the shell of your computer.

# CAUTION

The next remote access command, telnet, is shown as an example because it is included with Red Hat Linux, but you shouldn't use it: telnet transmits your username and password in clear text across the network, posing huge security risk for your system. Also, note that this service must be explicitly turned on and allowed on the remote computer (by editing the file named telnet under the /etc/xinetd/ directory and restarting xinetd; see the section "Starting and Stopping Services" in Chapter 7 for more information on starting or restarting a Red Hat system service).

The telnet command can be used, with the name of a remote host or Internet Protocol (IP) address, to log in to a remote computer. For example, to log in the host named shuttle2 from the host named shuttle,

```
[winky@winky]$ telnet shuttle2
```

After you press Enter, you'll see some information presented by the remote computer, and you will then be prompted for your username on the remote system:

```
Trying 192.168.2.70...
Connected to shuttle2.home.org (192.168.2.70)
Escape character is '^'.
```

Linux 2.4.18-11 (shuttle2.home.org) (15:43 on Friday, 30 August 2002)

```
login: winky
```

After you type your username (winky in this example), press Enter and you'll be prompted for your password on the remote system:

Password:

```
Last login: Fri Aug 30 15:42:26 from 192.168.2.68
[winky@shuttle2 winky]$
```

After you type your password and press Enter (your password is not echoed back), you'll be informed of the last time you logged in, and you can then work on the remote computer. Use the exit or logout commands to exit your session and return to the shell on your computer.

Although it is possible to use telnet to log in to a remote computer over a wired or wire-less network, such use is not recommended, especially via the Internet. When you type your username and then press Enter and type your password, are transmitted without encryption over the network. Transmitting usernames and passwords over a network without encryption is a bad idea for obvious reasons. However, if you have a physically secure internal network not connected to the Internet, have fire-wall policies in place, and don't use wireless networking, there is nothing with using telnet. In fact, the encryption overhead of using ssh can reduce network transmission rates in some cases.

> NOTE
> It is possible to securely use telnet over an encrypted Virtual Private Network (VPN), but that is beyond the scope of this chapter and book.

# Changing Your User Information

Linux users are assigned a name, known as a username, by the root operator. One method of assigning usernames is to use one's first initial and last name; for example, Beth Smith would have bsmith. Each user must also have a password, either graphical or text-based.

> NOTE
> Older versions of Red Hat limited usernames to eight characters. The current version allows usernames to 32 characters. Good passwords should contain upper and lowercase letters, along with numbers. Random passwords can be generated using mkpasswd.

You cannot change your username, but you can change your information, such as address, phone, and so on. You make these changes using chfn. For example, type chfn at the command line and press Enter:

```
$ chfn
Changing information for peterovich.
Password []: 
Name []: Pete Jovanovich
Room []: Suite 120, Arlington Blvd.
Phone []: 202-555-1212
Information changed.
```

You're led through a series of prompts to enter new or updated information. Note that chfn will not let you use commas when entering information. You can verify this information in a couple of ways, for example, by looking at the contents of /etc/passwd.

```
$ grep peterovich /etc/passwd
peterovich:x:501:501:Pete Jovanovich,Suite 120,Arlington Blvd.,202-555-1212:/home/peterovich:/bin/bash
```

You can also verify the updated information by using the finger command:

```
$ finger peterovich
Login: peterovich              Name: Pete Jovanovich
Directory: /home/peterovich    Shell: /bin/bash
Office: Suite 120, Arlington Blvd.  Phone: 202-555-1212
Never logged in.
```

# Reading Documentation

Although you learn the basics of using Red Hat Linux in this book, you need time and practice to master and troubleshoot more complex aspects of the operating system. As with any operating system, you can expect to encounter some problems or perplexing questions as you continue to work with Red Hat Linux. The first place to turn for help with these issues is the documentation included with your system; if you can't find the information you need there, check Red Hat's site.

> Checking Red Hat's Web for security updates and bug fixes is a good idea. Browse to http://www.redhat.com/apps/support/errata/index.html.

Linux, like UNIX, is a self-documenting system, with manual pages accessible through the man command. Red Hat Linux offers many other helpful commands for accessing its documentation. You can use the apropos command—for example, with a keyword such as partition—to find commands related to partitioning, like this:

```
+   $ apropos partition
GNU Parted [parted] (8) - a partition manipulation program
fdisk (8) - Partition table manipulator for Linux
iostat (1) - Report Central Processing Unit (CPU) statistics and input/output statistics for devices and partitions
lvmdiscan (8) - scan for all disks / multiple devices / partitions available
mkfs.jfs [mkfs] (8) - create a jfs formatted partition
mpartition (1) - partition an MSDS hard disk
pvcreate (8) - initialize a disk or partition for use by LVM
sfdisk (8) - Partition table manipulator for Linux
```
