
# Using the Network File System

To have NFS automatically started when Red Hat boots, use command-line or graphical administrative utilities, such as chkconfig, ntsys, or redhat-config-services. Make sure to have the portmap service started because it is used as part of the service. You can manually start or stop NFS by directly calling its service control script nfs like this:

```
# /etc/rc.init.d/nfs start
Starting NFS services: [ OK ]
Starting NFS quotas: [ OK ]
Starting NFS daemon: [ OK ]
Starting NFS mounted: [ OK ]
```

In this example, NFS has been started. Use the stop keyword to stop the service. This approach at controlling NFS is handy, especially after configuration changes have been made. See the next section on how to configure NFS support on your Red Hat system.

# NFS Server Configuration

The server can be configured by editing the /etc/exports file. This file is similar to the /etc/fstab file in that it is used to set the permissions for the filesystems being exported. The entries look like this:

```
/file/systemyour(options) *.yourdomain.com(options) 192.15.69.0/24(options)
```

This shows three common clients to share /file/system to. The first, your, shares /file/system to just one host. The second, .yourdomain.com, uses the asterisk (*) as a wildcard to allow all hosts in yourdomain.com to access /file/system. The third share allows all hosts of the Class C network, 192.15.69.0, to access /file/share. For security, it is best not to use shares like the last across the Internet because all data will be readable by any network the data passes by.

Some options are shown in Table 13.3.

| Option | Purpose |
| :--- | :--- |
| rw | Gives read and write access |
| ro | Gives read only access |
| async | Writes data when the server feels the need, not the client |
| sync | Writes data as it is received |

The following is an example of an /etc/exports file:

```
# /etc/exports file for myhost.mydomain.com
/usr/local host(ro,show)
/home/jkennedy *.yourdomain.com(rw,hide,sync)
```

# CHAPTER 13 Network Connectivity

This file exports (makes available) /usr/local/ localhost. The mount is read-only (which is good for a directory of binary files that don't get written to). It also allows users on yourself to see the contents of filesystems that may be mounted on /usr/local. The second export mounts /home/kennedy to any host in yourdomain.com. It doesn't allow subsidiary filesystems to be viewed, but you can read and write to the filesystem.

After you have finished with the /etc/exports file, the following command

```
# /usr/sbin/exportsfs -r
```

will export all the filesystems in the /etc/exports file to a list named xtab under /var/lib/nfs directory, which is used as a guide for mounting when a remote computer asks for a directory to export. The -r option to the command reads the /etc/exports file and mounts all the entries. The exportsfs command can also be used to export specific files temporarily. An example using exports to export a file system would be

```
/usr/sbin/exportsfs -o async localhost:/usr/tmp
```

This command will restart /usr/tmp to localhost with the async option.

Make sure to restart the NFS server after making any changes to /etc/exports. If you prefer, you can use Red Hat's redhat-config-nfs graphical client to set up NFS while using the X Window System. Start by clicking the NFS Server menu item on the desktop panel's Server settings menu. You can also start the client from the command line of an X terminal window, like so:

```
$ redhat-config-nfs &
```

After you press Enter, you will be prompted for the root password. Type in the password, click OK, click the Add button, and you'll see the Add NFS Share dialog box, as shown in Figure 13.4.

In the Directory text box, type in a name of a directory to be exported; in the Host(s) text box, type in a hostname or IP address of a remote host that is to be allowed access to the directory. By default, a directory is exported read-only, but you can choose read and write access by clicking either export option in the Basic Permissions area of the dialog box. When finished, click the OK button, click the Apply button, and then use the File menu to quit.

# NFS Client Configuration

To configure your host as an NFS client (to acquire remote files or directories), edit the /etc/fstab file as you would mount any local filesystem. However, instead of using a device name to mount (such as /dev/hda1), remove the remote host and desired filesystem to be imported. For example, one entry might look like this:

| Device | Mount Point | Type | Options | Freq | Pass |
| :--- | :--- | :--- | :--- | :--- | :--- |
| yourhost:/usr/local | /usr/local | nfs | nvers=3,ro | 0 | 0 |

The options column uses the same names as standard fstab file entries with some additional entries as nfsvers=3, which specifies the third version of NFS. You can also use the mount command, to quickly attach a remote directory to a local filesystem by using a remote host's name and exported directory. For,

```
# mount -t nfs 192.168.2.167:/music /music
```

After you press Enter, the entire remote directory will appear on your filesystem. You can verify the imported filesystem using the `df` command like so:

```
# df
Filesystem 1k-blocks Available Use% Mounted on
/dev/hda2 18714368 9462600 8121124 55% /
/dev/hda1 46636 13247 30981 30% /boot
none 120016 0 120016 0% /
```
