# Restoring Files from an Archive with *cpio*

The -i option in cpio will restore the files from a backup and preserve the file attributes as well. Whereas tar will create any subdirectories, the -d option needs to be explicitly added to cpio for the same result. Be careful because the backups might have been created with relative or absolute paths. You should use -tv with cpio to list the files in the archive before extracting them so that you'll know where they will be placed.

To restore a cpio

```
# cpio -im RHLutest.cpio
```

For example, to list the contents of a cpio file,

```
# cpio -otv RHLutest.cpio
drwxwxr-xr-x root/hoty 0 2022-09-04 18:15:05 RHLutest/
-rw-rw-r-- root/hoty 163 2022-09-03 22:30:49 RHLutest/RHLU_screenshots.txt
-rw-rw-r-- root/hoty 840 2022-09-01 19:27:59 RHLutest/RHLU_guideline.txt
-rw-rw-r-- root/hoty 1485 2022-09-01 18:14:23 RHLutest/style_sheet.txt
-rw-rw-r-- root/hoty 931 2022-09-01 19:02:00 RHLutest/RHLU_COG.txt
```

Note that the pathnames do not start with a backslash, they are relative pathnames and will install in your current working directory. If they were absolute pathnames, they would install exactly where the paths state.

> NOTE
The of the oldest and most primitive UNIX applications are the dump and restore commands. dump examines files on an ext2 filesystem and determines which files need to be backed up. The backups can span multiple media and levels. (Levels the amount of data to be backed up.) The dump archives are restored using the restore program. You can restore across a network and restore full and incremental backups. These bare-metal UNIX applications are feature-rich but awkward to use, for some UNIX old-timers; for that reason, they don't cover their use in this chapter. Most users prefer the GUI network backup utilities, such as those you learn about in “Alternative Backup Software,” later in this chapter.
