# Directory Permissions

Directories are also files under Linux. For example, again use the ls command to show permissions like this:

```
$ mkdir foo
$ ls -id foo  2 bball  bball  4096 Jul 23 12:37 foo
drwxr-xr-x
```

In this example, the mkdir command is used to create a directory. The ls command and its -id option is used to show the permissions and other information about the directory (not its contents). Here you can see that the directory has permission values of 775 (read+write+execute or 4+2+1, read+write+execute or 4+2+1, and read+execute or 4).

This shows that the owner and group members can read and write to the directory and, because of execute permission, also list the directory’s contents. All users can only list the directory contents. (Directories require execute permission in anyone to be view their contents.)

You should also notice that the ls command’s output shows a leading d in the permissions field. normal files will have a blank field in place. Other files, such as those specifying a block or character device, will have a different letter (see the section “The Disk Defined” in Chapter 10, “Managing the Filesystem,” for more information about block devices).

For example, if you examine the file for a Linux serial port, you'll see

```
$ ls -l /dev/tty0
crw-rw---- 1 root  uucp  4 Mar 23 23:38 /dev/tty0
```

Here, /dev/tty0 is a character device (such as a communications port and designated by a c) owned by root and available to anyone in the uucp group. The device has permissions of 660 (read+write, read+write, no permission).

On the other hand, if you examine the file for an IDE hard drive, you'll see

```
$ ls -1 /dev/hda
brw-rw---- 1 root  disk  3, Mar 23 23:37 /dev/hda
```
