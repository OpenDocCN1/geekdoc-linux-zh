Here is an example to append the current date to the kernel:
`EXTRAVERSION = '*$(date +%D|sed -e 's/\//\-/g')`

This creates a kernel with a name of 2.4.19.—with the current month, day, and year separated by a character. Thus, if you compiled the kernel on January 1, 2003, the kernel name would be linux-2.4.19-01-2003.

## Compiling the Kernel

> TIP
> If you have a multi-processor machine, you can use both processors to speed up the make process by inserting -jx after the command—where, as a rule of thumb, x is one more than the number of processors you have. You might try a larger number and even try this on a single processor machine; it will only load your CPU. For example,

```bash
# make -j3 bImage
```

All the processes except make dep work well with this method of parallel compiling.

- 8. Run make clean to prepare the sources for the actual compilation of the kernel.
9. Run make bImage to create a binary image of the kernel.

> NOTE
> Several exist, although the most common ones are as:
- zimage—This directive compiles the kernel, creating an uncompressed file called zimage.
- bImage—This directive creates a compressed kernel image necessary for some systems that require the kernel to be a certain size for the BIOS to be able to parse; otherwise, the new kernel won't boot. It's the most commonly used.
- bzDisk—This directive does the same thing as bImage, but it copies the new kernel image to a floppy disk for testing purposes. This is helpful for testing new kernels without writing kernel files to your hard drive. Make sure that you have a floppy disk in the drive because you will not be prompted for one.

- 10. Run make modules to compile any modules your new kernel needs.
11. Run make modules_install to install the modules in /lib/modules.
12. Run make install to automatically copy the kernel to /boot, create any other files it needs, and modify the bootloader to boot the new kernel by default.
13. Using your favorite text editor, verify the changes made to /etc/lilo.conf or /boot/grub/grub.conf; fix if necessary and rerun /sbin/lilo if needed.
14. Reboot and test the new kernel.
15. Repeat the process if necessary.

## Verifying Your Compiling Tool Versions

If you have just installed Linux from the CD in this book and Red Hat 8.0 is still the current release, you will have all the current versions of the software you need to compile software. Over time, situation will change, and you will need to keep up with changing versions. Here's how you do that.

The process that you learned in the earlier section, "Getting the Kernel," you begin to compile operation by obtaining and unpacking the new kernel code. Now it's time to verify that your system has the necessary version of tools the kernel requires to compile run. This task has been automated with a script called ver_linux, located in the /usr/src/linux-2.4/scripts directory.

Just about every version of operating systems tools used to compile the kernel has a version argument. The ver_linux script calls all the commands that the kernel relies on to query versions. It formats it into a nice output that is easily compared against /usr/src/linux-2.4/Documentation/Changes file, using a text editor to view the file.

To run the script, navigate to the /usr/src/linux-2.4/scripts directory and then execute the ver_linux script like this:

```bash
./ver_linux
```

The output shown here is from a beta Hat 8.0 installation. Comparing the versions to the Changes file, it is apparent that all requirements have been met. If any utilities are older than required by the source code, download the latest versions from the sites listed in the Changes file, install them and you'll be ready to start compiling the kernel.

## Choosing a Configuration Interface

Over time, the process for configuring the Linux kernel has changed. Originally, you configured the kernel by responding to a series of prompts for each configuration parameter (though you can still configure Linux this way, make config). Most users find this type of configuration confusing and inconvenient; moving back through prompts to correct errors, for instance, is impossible.

The make config utility is a command-line tool. The utility presents a question regarding kernel configuration options. The user responds with Y, N, M, or ?. (It's not case sensitive). Choosing M configures the option to be compiled as a module. A response of ? displays context help for specific options, if available (If you choose ? and no help is available, you can turn to the vast internet resources to find information). We recommend that you use the make config utility, shown in Figure 24.1.

If you prefer not to use a command-line interface, you can use menuconfig to configure the Linux kernel. Menuconfig provides a graphical wrapper around that interface. Although it is not as raw as make config, menuconfig isn't a fancy graphical interface either; you can't use a mouse, but must navigate through it using keyboard commands. The same information presented in make config is presented by menuconfig, but as you can see in Figure 24.2, it looks a little nicer. Now you can move back and forth in the selection process in case you change your mind or make a mistake.
