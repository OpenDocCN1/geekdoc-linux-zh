Using RPM for Software Management

Because it's a .bz2 (BZip2 compressed) tar file, un-tar it with

```
# tar xjvf freetype-2.0.9.tar.bzz
```

and cd to the new directory:

```
# cd freetype-2.0.9
```

Using the text editor of your choice, edit the file include/freetype/config/fptoption.h
and find the line

```
#undef TT_CONFIG_OPTION_BYTECODE_INTERPRETER
```

Change it to

```
#define TT_CONFIG_OPTION_BYTECODE_INTERPRETER
```

Save it and exit the text editor.

Next, re-create the compressed archive:

```
# cd /tmp
# tar cfj freetype-2.0.9.tar.bz2 ./freetype-2.0.9/
```

Put it back in your source directory:

```
# mv freetype-2.0.9.tar.bz2 /usr/src/SOURCES
```

Now edit the .spec file in /usr/src/redhat/SPECS to change the line beginning with
Release to increment the number found there. (We are changing the version number by
doing this, so will not conflict with the version of the application we will be replacing.)nMake any changes to the %description line to describe your changes if you desire, and
save the file.

Build the binary RPM with

```
# rpm -ba freetype.spec
```

During the build process, RPM will detect a patch and asks you about the patch; press y
for "yes" to continue.

The new RPMs (actually four of them) are found in /usr/src/redhat/RPMS/i386. We only
need the one named freetype-2.0.9; you can install it with rpm -U. (This is why we
changed the version number; if we had not, RPM would not upgrade to the "same"
version.)
