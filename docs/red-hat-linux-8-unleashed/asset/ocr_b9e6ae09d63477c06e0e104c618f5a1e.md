Getting started with RCS is as simple as creating a project directory and RCS directory under the project directory and creating or copying initial source files in the project directory. You can then use the ci command to check in documents. Getting started with CVS requires that you initialize a repository by first setting the $CVSROOT environment variable with the full pathname of the repository and then using the init command option with CVS command, like:

```
# cvs init
```

You can find documentation for RCS and CVS in various man pages, under the /usr/share/doc directories for each of them, and in GNU information management documents.

> TIP
Though they're free, RCS and CVS are powerful software project management tools. Many organizations use CVS and RCS to manage the source for their projects. Commercial-management tools (also called version-control programs) also exist that include fancy interfaces, homogenous platform support, and greater flexibility than RCS and CVS. But those tools require dedicated administrators and significant licensing costs—both of which are major disadvantages.

# Making Libraries with ar

C and C++ project management tools help ease the process of building large applications; the ar command is an example of such tool. If different programs use the same functions, they can be combined into a single library archive. You use the ar command to build a library. When you include the library on the compile line, the archive is searched to resolve any external symbols. Listing 22.1 shows an example of building and using a library.

# LISTING 22.1 Building and Using a Library

```
$ gcc -c sine.c
$ gcc -c cosine.c
$ gcc -c tangent.c
$ ar c libtrig.a sine.o cosine.o tangent.o

$ gcc -c mainprogram.c
$ gcc -o mainprogram mainprogram.o libtrig.a
```
