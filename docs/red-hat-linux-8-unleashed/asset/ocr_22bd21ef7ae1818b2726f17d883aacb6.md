Older versions of fdisk would default to /dev/hda. The author of fdisk decided that wasn't a good thing, so you must always type the device name.

> TIP
The fdisk is only dangerous to explore if you write the partition table. Because you are specifically asked whether you want to do this, poke around to satisfy your curiosity and avoid pressing the w key when you're done; use q to quit. Armed with this knowledge, don't feel too shy if you're curious about the partition table. But if you really don't want to take a chance on breaking anything, play it safe and use the -1 (that's the letter L, not the numerical 1) as in

```
# fdisk -1 /dev/hda
```

fdisk happily prints the contents of the partition table to the screen (often referred to as stdout, or standard output) and without leaving you in the edit mode.

It's always a good idea to keep a hard copy of your edited partition table. You can redirect the output of fdisk -1 to file

```
# fdisk -1 device > mypartitiontable.txt
```

or send it to the printer with

```
# fdisk -1 device | lpr
```

In the first example, a redirector symbol (>) is used to redirect the listing from stdout to a file. In the second example, we used a pipe (|) to send the output to the printer (assuming that you have one connected).
