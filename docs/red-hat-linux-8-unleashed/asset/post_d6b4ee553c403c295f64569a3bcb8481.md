
# Basic Sendmail Configuration and Operation

Because Sendmail is the Red Hat Linux default client (and the mostly widely used client), the following sections use the explanation and examples for configuring and operating your email system. As mentioned earlier, however, Sendmail is an extremely complex program with a very convoluted configuration. As such, this chapter covers some of the basics. For more information on Sendmail, as well as other MTAs, see the “Reference” section at the end of this chapter.

Sendmail configuration is handled by files in the /etc/mail/ directory with much of the configuration being handled by the sendmail.cf. The actual syntax of the configuration file, sendmail.cf, is cryptic (see the following example). In an attempt to make it easier to configure Sendmail, the sendmail.mc file was created. The following example believes that goal, however, the sendmail.mc file must be processed by the m4 macro processor to create the sendmail.cf file; we will learn how to use it later, and we will look at a Perl script that animates and simplifies the entire process. First, let’s examine some basic configuration you might want to do with Sendmail.

> sendmail.cf has some strange syntax because of the requirements of the m4 macro processor. You't understand the details of m4, but note the quoting system. The starting quote is a backtick (`), and the ending quote is simply a quote ('). Also, the dnl sequence means to "delete to new line" and causes anything from the sequence up to including the newline character to be deleted in the output.

Here's a look at an excerpt from the sendmail.cf file:

```
CP.
# "Smart" relay host (may be null)
DS
# operators that cannot be in local usernames (i.e., network indicators)
CO @ % !
# a class with just dot (for identifying canonical names)
C..
# a class with just a left bracket (for identifying domain literals)
C[
# access_db acceptance class
C(Accept)OK RELAY
C(Res)OKR
# Hosts for relaying is permitted ($=R)
FR-o /etc/mail/relay-domains
```

And's here a quote from the sendmail.mc file for comparison:

```
dnl define(`SMART_HOST`, 'smtp.your.provider')
define(`CONF_USER_ID`, '8:12'`)dnl
undefined(`UCPET_RELAY`)\dnl
undefined(`BITNET_RELAY`)\dnl
dnl define(`CONFAUTO_REBUILD`)\dnl
define(`CONFTO_CONNECT`, 'im')\dnl
define(`CONTRY_NULL_MX_LIST`,true)`\dnl
```

You can see why it is described as `cryptic`.

The script automates the configuration of Sendmail by prompting you for information and then doing all the heavy work by modifying the Sendmail configuration file itself. When you're done, Sendmail and Fetchmail will be configured. Running the script not only prompts you for all the necessary information, but it even provides some explanation and help along the way.

You should have Sendmail and Fetchmail installed on your system before you begin. The script is available for download at http://cork.linux.ie/projects/install-sendmail/. Simply uncompress the archive:

```

```

Of course, you can always configure Sendmail by hand, especially if you need any advanced options. The following five sections address some commonly used advanced options.

## Configuring Masquerading

Sometimes you might want to have Sendmail masquerade as a host other than the actual host. This is useful when you want your mail to appear to be coming from a different domain than the actual hostname of the machine. To do this, you need to configure the MASQUERADE_AS option in your sendmail.mc. For example:

```
MASQUERADE_AS(`example.com`)
```

## Using Smart Hosts

If you want to route your mail through another mail server, you can use a smart host. A smart host is a server that takes responsibility for delivering mail to other servers. To configure a smart host, you need to set the SMART_HOST variable in sendmail.mc. For example:

```
define(`SMART_HOST`, 'smtp.your.provider')
```

## Setting Delivery Intervals

Sendmail can be configured to control how often it attempts to deliver mail. This is done by setting the DELIVERY_INTERVAL option in sendmail.mc. To change the interval, you can change the number of minutes. For example:

```
define(`DELIVERY_INTERVAL`, 30)
```

## Building the sendmail.cf

After you have made all changes to sendmail.mc, you need to rebuild the sendmail.cf file. First, back up your old file:

```
# mv /etc/mail/sendmail.cf /etc/mail/sendmail.cf.old own```

You must run sendmail.mc through the m4 processor to generate a usable configuration file. A command, as the following, is used to do this:

```
# m4 /etc/mail/sendmail.mc > /etc/mail/sendmail.cf
```
