
# CHAPTER 10 Managing the Filesystem

## ReiserFS

ReiserFS is offered primarily for compatibility with existing ReiserFS partitions you might want to access. Although the Reiser filesystem can be used as root filesystem (meaning Linux can be booted from), Red Hat has chosen not to support that. The Reiser filesystem has undergone a major update and release with Reiser4. The project, sponsored by the Defense Advanced Projects Agency (DARPA), aims to introduce improvements in number of areas, such as maximum number of directories, files and size of the filesystem (nearly unlimited terabytes). Other improvements include performance and encryption.

## JFS and XFS

Two commercial UNIX systems have ported to allow them to be used in Linux. IBM has provided its Journaled File System JFS that is used with AIX. Silicon Graphics, Inc. (SGI) has provided its XFS filesystem which are generally suited for Enterprise rather than small office systems, it seems likely that they are offered in Red Hat to ease the transition of IRIX and AIX users by eliminating the need for these users to reformat their very large files.

## DOS Filesystems

The extent of DOS filesystem support in Linux is often surprising to newcomers, but the DOS filesystem proved to be a viable option in the early years of Linux. Because Microsoft has been the dominant operating system on computers, Linux has always worked toward co-existence with DOS. Microsoft and the consumer-oriented Windows systems use filesystem known as FAT (File Allocation Table). FAT32 is the typical system used today. The FAT name indicates the size of the space; more contiguous space can be identified. FAT32 is the most recent version of FAT, and its backward compatible with all versions of FAT. Linux kernel can access all versions of FAT partitions (including floppy disks) by the vfat module.

## CD-ROM Filesystems

If you use CD-ROM or DVD-ROM media, you need to understand little bit about the filesystem and how it works with Linux. To the average user, the filesystem of CD-ROM looks just like native filesystem. It's not the native filesystem, but features of Virtual File System make it possible for it to appear that way. CD-ROM filesystem continues to evolve to accommodate new technology.

## iso9660

The filesystem typically used on CD-ROM is known as iso9660, the standard that defines the format. Each operating system translates the iso9660 into native filesystem of the operating system (with some restrictions). Several extensions have been created to address certain needs. The Rock Ridge extension allows long filenames and symbolic links. The Joliet extension allows Unicode characters and long filenames, useful when dealing with non-English languages. CDs contain bootable image and, with suitable BIOS, can boot system from the CD.

## Universal Disk Format (UDF)

This is the filesystem used on DVD-ROMs, and is known as Universal Disk Format. It has built-in features such as larger files, better file descriptors, and packet writing that iso9660 cant easily accommodate. The UDF format is the next step in compact disc technology.

## Creating Filesystem

To create a filesystem on a disk that has never had partition table on it or to change the partition table (called partitioning the disk), you must first create the new partition table. In this section, you begin learning about the basic structure and workings of the disk as a storage device. This information is fundamental to your understanding of filesystem creation process. You then learn to create a partition table using fdisk, sfdisk, and parted commands. With all Linux commands, each has its own strengths and weaknesses and none is a perfect choice for all situations. In the end, you learn to create the filesystem using commands appropriate for the type of filesystem you want to create.

> The Microsoft version of fdisk creates both a partition table and the bootloader. In Linux, fdisk only creates the partition table. The bootloader is created later by LILO, GRUB, or another bootloader; no bootloader is necessary to create filesystem and store data on a disk, just a partition table.

In fact, IDE disks installed as something other than /dev/sda (such as /dev/hdc, the secondary master drive) won't have bootloader written to them; the space where loader code normally resides will likely be blank. For SCSI disks, the drive designated by the BIOS as the bootable drive will have the bootloader written to it.

## The Disk As a Storage Device

Because data storage devices are central to filesystem, it's important to understand the workings of the most common data storage device—the hard drive. Although they work with a different medium, the basic functions of floppy disks and removable disk drives are similar to those of the hard disk.

Mechanically, the hard drive is a metal box that encloses disks, also known as platters, which have a magnetic coating on each side. Multiple disks are typically connected to the same spindle and rotated by motor. The read and write heads for each side of the disk are moved by a second motor to position them over the area of the disk where the data you are looking for is stored. Each platter is organized into cylinders (the default size is 512 bytes) and sectors, and each platter has a head. Each drive has electronics on a controller card, along with the disk controller card on the motherboard of the computer, are able to place the heads at the correct space to retrieve the data.

The three components, cylinders, heads, and sectors (CHS), are referred to as the *geometry* and are used to identify specific locations on the drive. The CHS information for the drive is detected by the system BIOS and passed to the operating system.

The first section of the disk is called the MBR, or Master Boot Record. It is the most important section on the disk because it contains the bootloader code and the partition table (the table containing partitions to beginning and end of the logical partitions on the disk). The BIOS gets the system's hardware ready, and then executes the bootloader code. The *bootloader code* and the bootloader program load the kernel and turn over control of the system to the kernel. Then, Linux is on its way to providing us with one of the best operating systems in the world.

The MBR is 512 bytes long; the first 446 bytes contain the bootloader code. The next 64 bytes contain the partition table, and the final two bytes contain a special code (the hexadecimal values of 55 and AA, respectively) that identify the sector as the MBR. More details about the MBR can be found Chapter 11, “Back Up, Restoring, and Recovery."
