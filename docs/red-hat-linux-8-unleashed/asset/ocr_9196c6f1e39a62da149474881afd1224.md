# Console-Based Monitoring

Traditional UNIX systems have always included the ps or process display command. The command lists running processes on the system and identifies who owns them and how much of the system resources are being used.

Because of the architecture of the Linux kernel and its memory management, Linux also provides some process reporting and control via the command line. This feature can be manually accessed through the /proc filesystem, the pseudo-filesystem used as a direct interface to the kernel. (You see how it's used in the upcoming discussion of the ps command.) The /proc filesystem is primarily used by application programmers, who construct an interface for the kernel and its information. This process is too complex to adequately deal with in the context of this chapter and you can benefit from reading the man page and /usr/src/linux-2.4/Documentation/filesystems/proc.txt to examine the list and description of the scores of kernel values. You can then write scripts (Chapter 22, "Shell Scripting") to use those values as needed.

Processes can be controlled at the command line as well. When a command is launched on your Red Hat Linux system, the process started by the kernel is assigned an identification number, called a PID or process ID. This number is (generally) displayed by the shell if the process is launched in the background, like this:

```
$ xview &
[1] 11670
```

In this example, the xview client has been launched in the background, and the (bash) shell first reports a job number ([1]). A job number or job control is a shell-specific feature that allows a different form of process control (such as sending or suspending programs to the background and retrieved background jobs to the foreground; see your shell's manual pages for more information if you are not using bash).
