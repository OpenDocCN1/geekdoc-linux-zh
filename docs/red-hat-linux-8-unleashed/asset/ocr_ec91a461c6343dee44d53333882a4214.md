/usr/src/redhat/SOURCES/—This directory might contain a tar archive containing the source code for Apache, and in some cases, patches for the source. You must have installed the Apache SRPM for these files to be created.

When Apache is being run, it also creates files in the following directories:

+   - /var/lock/subsys—The startup script adds a lock file, called httpd.

+   - /var/run—Apache creates a file, httpd.pid, containing the process ID of Apache's parent process.

If you're upgrading to a newer version of Apache, RPM doesn't write over your current configuration files. RPM moves your current files and appends the extension .rpmnew for them. For example, srm.conf becomes srm.rpmnew.

# Building the Source

There are several ways to obtain the source code for Apache. The Red Hat distribution has RPMs containing the source code of Apache, which sometimes includes patches to make it work better with Red's distribution. The most-to-date, stable version for Red Hat is at http://updates.redhat.com. When you install one of these RPMs, a tar archive containing the Apache source is created in /usr/src/redhat/SOURCES/.

You can download the source directly from http://www.apache.org/. The latest version at the time of this writing (2.0.42) is a 4.5MB compressed tape archive. After you have the tar file, you must un it in a temporary directory somewhere nice, such as /tmp. Unrolling this file creates a directory called apache_version_number, where version_number is the version you've downloaded (for example, apache_1.3.20).

There are two ways to compile the source—the old, familiar way (at least, to those of us who have been using a configure script), and the new, easy way using a configure script. The configure script offers a way to have the source software automatically configured according to your system. However, manually editing the configuration files before building and installing Apache provides more control over where the software is installed and what capabilities or features are built into Apache.
