# iso96660

The filesystem typically used on a CD-ROM is known as iso96660, the name of the standard that defines the format. Each operating system translates the iso96660 into the native filesystem of the operating system (with some restrictions). Several extensions have been created to address certain needs. The Rock Ridge extension allows long filenames and UNIX-like symbolic links. The Joliet extension allows Unicode characters and long filenames, useful when dealing with non-English languages. El Toronto CDs contain a bootable image and, with a suitable BIOS, can boot an operating system from the CD.

# Universal Disk Format (UDF)

This is the filesystem used on DVD-ROMs, and is known as the Universal Disk Format. It has a number of built-in features such as larger files, better file descriptors, and packet writing that the iso96660 filesystem can't easily accommodate. The UDF format is the next step in compact disc technology.

# Creating a Filesystem

To create a filesystem on a disk that has never had a partition table on it or to change the partition table (called partitioning the disk), you must first create the new partition table. In this section, you begin learning about the basic structure and workings of the disk as a storage device. This information is fundamental to your understanding of the filesystem creation process. You then learn to create a partition table using the `fdisk`, sfdisk, and Gparted commands. With all similar Linux commands, each has its own strengths and weaknesses and none is a perfect choice for all situations. In the end, you learn to create the filesystem, using commands appropriate for the type of filesystem you want to create.

> The Microsoft version of `fdisk` creates both a partition table and the bootloader. In Linux, `fdisk` only creates the partition table. The bootloader is created later by LILO, GRUB, or another bootloader; no bootloader is necessary to create a filesystem and store data on a disk, just a partition table.

In fact, IDE disks physically installed as something other than `/dev/sda` (such as `/dev/hdc`, the secondary master drive) won't have a bootloader written to them; the space where the loader code normally resides will likely be blank. For SCSI disks, the drive designated by the BIOS as the bootable drive will have the bootloader written to it.
