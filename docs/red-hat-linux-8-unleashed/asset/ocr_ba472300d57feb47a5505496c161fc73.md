PPP uses several components on your system. The first is a daemon called pppd, which controls the use of PPP. The second is a driver called the high-level data link control (HDLC), which controls the flow of information between two machines. A third component is a routine called that dials the other end of the connection for you when you want it to. Although PPP has many "tunable" parameters, the default settings work well for most people.

# NOTE

You can check to whether PPP is installed on your system by running the pppd command from root from a command line with the --help argument, like this:

```
# pppd --help
```

This list the current version number and describe a few available options if PPP is installed. If PPP isn't installed on your system, use Red Hat's rpm command to install the PPP package from the second Red Hat Linux CD-ROM or use the Packages item from the System Settings menu. Chapter 8, "Managing Software and System Resources," covers the details of using rpm and the graphical package manager.

# Configuring a Dial-up Connection Manually

The first step in manually configuring PPP is to log in as root to copy and edit the necessary files. After you're logged in, you will use the chat command, the pppd daemon, and several files to configure PPP:

```
/etc/ppp/ppp-on--Used to start a PPP connection. This file contains the ISP's phone number, your username and password, as well as various options such as IP address options, the modem device and its settings (such as baud rate) for the connection.
/etc/ppp/ppp-off--Used to terminate a PPP connection.
etc/ppp/ppp-dialer--Used to perform dialing and negotiation with the chat command; the chat script creates error-handling and negotiation responses between the remote system and the chat script.
```

# CAUTION

Many software demons will not work with Linux because the manufacturers won't release programming information about them or provide Linux drivers. An external serial port modem or ISA modem will almost work; USB and PCI modems are still problematic. It is suggested that you do a thorough Google search using your modems' name and model number to see how others have solved problems with that particular modem. There are links to software modem sites at the end of this chapter.
