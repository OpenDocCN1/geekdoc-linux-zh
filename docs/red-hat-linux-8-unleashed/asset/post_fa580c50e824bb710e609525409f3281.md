> NOTE
Most IP are dynamically assigned by ISPs; they have a pool of addresses, and you get whatever address is available. From their viewpoint, a small number of addresses can serve a large number of people because not everyone will be online the same time. For most Internet services, a dynamic IP works because it's the ISP's job to provide information to you, and you sit in the middle—between you and the service you use. But a dynamic IP changes, and if someone needs to find you at the same address (if you run a Web site or a file transfer, for example), an IP that changes every time you log on won't work well. For that, you need a static IP. Because your ISP can't reuse that with its other customers, the average consumer doesn't need the benefit of a static IP, they are happy paying for a dynamically assigned IP. Also, the DNS information can be provided automatically by the ISP by the Dynamic Host Configuration Protocol, DHCP. This is discussed in Chapter 13, "Network Connectivity."

If you are using DSL access or a cable modem, you may have a dynamic IP provided through DHCP, or you may be assigned a static IP. You will be provided with the DNS servers automatically if you use DHCP, or you will need to manually set up DNS (in which case, you will need to know the IP addresses of the DNS servers).

In all cases, you will need to know your username, your password, and for the configuration of other services, the names of the mail servers, and the name of the news server. This information can be obtained from your ISP if you specifically ask for it.

> NOTE
The information in this book will help you understand and avoid many connection issues, but you might experience connection problems. Be aware that few ISP's offer Linux support, and you might need to seek help from a Linux-savvy friend or a Linux user's group if your special circumstances can't be handled from the knowledge you gain from this book.

## Laying the Foundation: The localhost Interface

Prior to connecting to the Internet or network, you must create a dummy or localhost interface. This interface, known as lo (loopback interface), is used by the TCP/IP protocol to assign an IP address to your machine and is required for establishing a PPP interface. The lo interface is also used by many network-aware applications and is easy to set up.

### Checking for the Availability of the Loopback Interface

Red Hat normally takes care of setting up this interface during the installation. You can use the ifconfig command to see if it is already available. The command and its response will look similar to this if lo is available:

```
# /sbin/ifconfig
lo Link encap:Local Loopback
  inet addr:127.0.0.1 Mask:255.0.0.0
  UP LOOPBACK MTU:16384 Metric:1
  RX packets:1 errors:0 overflows:0 carrier:0
  TX packets:0 errors:0 overflows:0 txuel:0
  RX bytes:760 (760 bytes) TX bytes:760 (760 bytes)
```

The sample output shows that the loopback interface is active and running, that it has been assigned the loopback IP address 127.0.0.1, that the broadcast mask of 255.0.0.0 is used, and the interface hasn't had much traffic (RX = receive and TX = transmit). If you don't see something similar to the example, you may need to configure the localhost interface by hand after reading the remainder of this section. Otherwise skip to the next section.

### Configuring the Loopback Interface Manually

The localhost interface's Internet Protocol (IP) address is defined in a text file that can be used by Linux to store network address. This file is called /etc/hosts and should exist on a system even if it is empty. The file provides IP addresses and associated hostnames to the Linux kernel and other network-related utilities. Prior to configuring network interfaces, you may find that the /etc/hosts file only contains a single line:

```
127.0.0.1 localhost.localdomain
```

This line defines the localhost interface and assigns an IP address of 127.0.0.1. You might hear or read about terms such as localhost, loopback, and dummy interface; all these terms refer to the use of the IP address 127.0.0.1. The term loopback interface indicates to Linux networking, it looks though the machine is talking to a network that consists of only one machine; the kernel sends traffic to and from itself on the same computer. Dummy interface indicates that the interface doesn't really exist as far as the outside world is concerned; it exists only for the local machine. You can read more about networking in Chapter 13.

Each networked machine on a LAN will use this same IP address for its localhost. If some reason a Red Linux computer does not have this interface, edit the /etc/hosts file to add the localhost entry, and then use the ifconfig route commands as root to create the interface like this:

```
# ifconfig lo 127.0.0.1
# route add 127.0.0.1 lo
```

These commands will create the localhost interface in memory (all interfaces, such as eth0 or ppp0, are created in memory when using Linux), and then add the IP address 127.0.0.1 to an internal (in-memory) table so that the Linux kernel's networking code can keep track of routes to different addresses.

Use the ifconfig command as shown previously to test the interface. You should now be able to use the ping command to check that the interface is responding properly like this (using either localhost or its IP address):

```
# /bin/ping -c 3 localhost
PING localhost.localdomain (127.0.0.1) 127.0.0.1: 56(84) bytes of data.
64 bytes from localhost.localdomain (127.0.0.1): icmp_seq=0 ttl=255 time=21 ms
64 bytes from localhost.localdomain (127.0.0.1): icmp_seq=1 ttl=255 time=20 ms
64 bytes from localhost.localdomain (127.0.0.1): icmp_seq=2 ttl=255 time=20 ms

--- localhost.localdomain ping statistics ---
3 packets transmitted, 3 packets received, 0% packet loss
round-trip min/avg/mdev = 0.050/0.114/0.070 ms
```

The -c option is used to set the number of pings, and (as it was previously), will return information regarding the round-trip speed of sending a test packet to the specified host.

## Configuring Dial-up Internet Access

Most ISPs provide dial-up connections using PPP because it is a fast and efficient protocol for TCP/IP over serial lines. PPP is designed for two-way networking; TCP/IP provides the transport protocol for data. One hurdle faced by new Red Linux users is how to set up PPP and connect to the network. It isn't necessary to understand the details of the PPP protocol in order to use it, and setting up a PPP connection is easy. You can configure the PPP connections manually using the command line, or graphically during an X session using Red Hat's Internet Configuration Wizard. Each approach produces the same results.

PPP uses several components on your system. The first is a daemon called pppd, which controls the use of PPP. The second is a driver called the high-level data link control (HDLC), which controls the flow of information between two machines. A third component is a routine called pslack that dials the other end of the connection for you when you want it to. Although PPP has many "tunable" parameters, the default settings work well for most people.

> NOTE
You can check whether PPP is installed on your system by running the pppd command from root from a command line with the --help argument, like this:

```
# pppd --help
```

This list the current version number and describe a few options if PPP is installed. If PPP isn't installed on your system, use Red Hat's rpm command to install the PPP package from the second Red Linux CD-ROM or use the Packages item from the System Settings menu. Chapter 8, "Managing Software and System Resources," covers the details of using rpm and the graphical package manager.

### Configuring a Dial-up Connection Manually

The first step in manually configuring PPP is to log in as root to copy and edit the necessary files. After you're logged in, you will use the chat command, the pppd daemon, and several files to configure PPP:

- /etc/ppp/ppp-on: Used to start a PPP connection. This file contains the ISP's phone number, your username and password, as well as various options such as IP address options, the modem device and its settings (such as baud rate) for the connection.
- /etc/ppp/ppp-off: Used to terminate a PPP connection.
- /etc/ppp/ppp-dialer: Used to perform dialing and negotiation with the chat command; the chat script creates error-handling and negotiation responses between the remote system and the chat script.

> CAUTION
Many software demons will not work with Linux because the manufacturers won't release programming information about them or provide Linux drivers. An external serial port modem or ISA modem will almost work; USB and PCI modems are still problematic. It is suggested that you do a thorough Google search using your models name and model number to see how others have solved problems with that particular modem. There are links to software modem sites at the end of this chapter.
