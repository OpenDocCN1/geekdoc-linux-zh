
> When you've learned how to use the command line with Red Hat Linux, you'll be comfortable with a UNIX command line. This chapter, then, can provide the foundation information you need to work with other UNIX operating systems, such as FreeBSD.

There are two types of users on a Linux system: normal users (the section "Basic Linux User Skills") and the root operator, also known as the superuser. At big computing installations, one or more system administrators might have root access or superuser power on the system (perhaps for one-time tasks). Normal users rarely, ever interact with the root operator.

However, if you use Red Hat Linux on your PC or notebook as a standalone workstation, you will be both a user and the root operator. Root access is required to perform nearly all system and hardware configuration. This might be one of the primary reasons that some new users hold the view that Linux requires a steep learning curve. Red Hat, Inc., has put a lot of effort into making system administration easier for new users by improving graphical administration utilities. Because of the way Linux is designed, however, you must become comfortable working with the command line and doing some root-level work, especially if using Linux on a standalone PC.

## Working with the Red Hat Linux File System

Red Hat Linux uses a file system, or layout of hierarchical directories similar to that used by other UNIX variants (such as Mac OS X). Nearly all Linux distributions use a similar structure, and Linux distribution vendors have generally agreed on the naming and location of critical files and directories.

The effort to build a consensus regarding the Linux directory structure began in 1993 with the Filesystem Hierarchy Standard (FHS), a draft proposal that addressed only Linux issues, but also BSD. Red Hat has stated that it is committed to stay compliant with the FHS, which specifies the location and names of files and directories. For more FHS, see the link in the References section at the end of this chapter.

The universal layout of directories and file locations for Linux is extremely helpful for those creating distributions, packaging applications, and crafting system administration utilities. For example, knowing that the useradd command is in usr/sbin directory can simplify the creation of administrative shell scripts designed to be used by system administrators. This information can also help you if you use other UNIX operating systems or other Linux distributions, and need to troubleshoot software installation, or plan the addition of major software packages onto your Red Hat system.

## Working with the Red Hat Linux System

To gain the full benefits of this universal layout, you must know how Red Hat Linux is organized, what the contents of files and directories on your system, and where files and software should be installed. Understanding the Linux system is part of learning how to administer and use Linux.

## Viewing the Red Hat Linux File System

Look at the layout of a Red Hat Linux system by using the list directory contents, ls, like this:

```bash
$ ls /
bin dev home lib misc opt root tftpboot usr
boot etc initrd lastfound+found mnt proc sbin tmp var
```

> NOTE
The section provides an overview of the Red Hat file system. You might find fewer or more directories discussed here in your own system. ## Use Essential Commands from the /bin and /sbin Directories

The /bin directory (about 78MB if you do a full install) contains essential commands used by the system when running and booting Linux. In general, the root operator uses the commands in the /sbin directory. Many (though not all) of these commands are statically linked; such commands do not depend on software libraries residing within the /lib or /usr/lib directories. Nearly all the other applications on your system are dynamically linked—meaning they require external software libraries (also known as shared libraries) to run in.

> Because the system contains dynamically linked applications, you might sometimes get “dependency errors” when installing or upgrading software packages; in those situations, a supporting library (or application) might not be present. See Chapter 8, "Managing Software and System Resources," for more information.

## Store the Booted Kernel and View Stored Devices in /boot and /dev Directories

The /boot directory contains the Linux kernel at boot time, with other files that describe the kernel or provide information for booting Linux. When you rebuild a new kernel, the kernel and related files are placed in this directory (see Chapter 24, “Kernel and Module Management”).

Linux device files are contained under the /dev directory. The directory contains more than 7500 files representing devices that may or not be in use. Some of the most commonly used devices in this directory include

- IDE (Integrated Drive Electronics) hard drives, such as /dev/sda and /dev/hdb
- CD-ROM drives, some of which are IDE, whereas others are CDRW (CD read/write) drives emulated as SCSI (Small Computer Systems Interface) devices as /dev/scd0
- Serial ports, such as /dev/tty0 for COM1, /dev/tty1 for COM2, and so on
- Pointing devices, including /dev/mouse
- Printers, such as /dev/lp0

> NOTE
Network interfaces (such as eth0 or ppp0) are not represented by Linux device files, but are created in memory when activated. Chapter 13, “Network Connectivity,” for more information.

## Use and Edit Files in the /etc Directory

More than 20MB of system configuration files and directories reside under the /etc directory if you install all software included with this book. Some major software packages, such as Apache, OpenSSH and xinetd, have directories of configuration under /etc. Other important system-related configuration files in /etc are

- fstab—The filesystem is a text file listing each hard drive, CD-ROM, floppy or other storage device attached to your PC. The table indexes each device's partition with a place in your Linux file system (directory layout), and lists options for each device used with Linux (see Chapter 10, “Managing the Filesystem”)
- init—The system initialization file defines the default runlevel. This file can determine whether your system boots to a graphical or text login, as well as whether or not dial-up access is enabled. (You can learn about default runlevels in the section “Red Linux Runlevels” located in Chapter 7, “Managing Services.”) See the section “Starting X” located in Chapter 6 to learn more about changing init to boot to a graphical interface. Chapter 15, “Internet Connectivity,” in the section “Setting Up a Dial-up PPP Server” discusses editing init to enable dial-up remote access.
- modules.conf—This configuration file contains directions and options used when loading kernel modules to enable various types of hardware, such as sound, USB, networking, and so on (discussed in the section “Building and Installing Modules” in Chapter 24).
