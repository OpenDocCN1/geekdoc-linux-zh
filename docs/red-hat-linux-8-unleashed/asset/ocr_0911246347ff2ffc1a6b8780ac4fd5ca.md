To patch up to several versions in a single operation, you can use the patch-kernel script located in the kernel source directory for the version you currently using. This script applies all necessary version patches to bring your kernel to the latest version.

The format for using the patch-kernel script looks like this:

```
patch-kernel <source_dir> <patch_dir> <stopversion>
```

The source directory defaults to /usr/src/linux if none is given, and the patch_dir defaults to the current working directory if one isn't installed.

For example, assume that you have a 2.4.7 kernel code tree that needs to be patched to the 2.4.9 version. The 2.4.8 and 2.4.9 patch files have been downloaded from ftp.org and are placed in the /patch directory in the source tree. You issue the following command in the /usr/src/linux-2.4 directory:

```
# scripts/patch-kernel /usr/src/linux-2.4.7 /usr/src/linux-2.4.7/patch
```

Each successive patch file is applied, creating a 2.4.9 code. If any errors occur during this operation, files named xxx# or xxx.rej are created, where xxx is the version of the patch that failed. You will need to resolve these failed patches manually by examining the errors and looking at the source code and the patch. An inexperienced person will not have any success with this because you need to understand C programming and kernel programming to know what is broken and how to fix it. This was a stock 2.4.7 code tree, the patches were all successfully applied without errors. If you are attempting to apply a non-standard third-party patch, the patch may likely fail.

When you have successfully patched the kernel, you are ready to begin compiling the code as if it were a stock 2.4.9 kernel tree.

# Using the patch Command

If you have a special, non-standard patch to apply—such as a third-party patch for a commercial product, for example—you can use the patch command rather than the special patch-kernel script that is normal for kernel updates. Here are some quick tips and an alternative method of creating patch and leaving the original code alone.

+   1. Create a directory in your home directory and name it something meaningful, like mylinux.

+   2. Copy the pristine source code there with
cp -ravd /usr/src/linux-2.4/* ~/mylinux

+   3. Copy the patch file to that directory with
cp <patch_filename> ~/mylinux
