
## The Basics of Writing, Creating, and Executing a Shell Script

Why should you write and use shell scripts? Shell scripts can save you time and typing, especially if you routinely use the same command line times every day. Although you could also use the history function (press the Up or Down keys while using bash or use the history command), a shell script can add flexibility with command-line argument substitution and built-in help.

Although a shell script won't execute faster than a program in a computer language such as C, a shell program will be smaller in size than a compiled program, and it does not require any additional library support other than the shell or, if existing commands installed on your system. The process of creating and testing shell scripts is also generally simpler and faster than the development process for equivalent C commands.

> A number of Red Hat Linux commands are actually shell scripts, and many other good shell script examples are available over the Internet—a quick search will yield numerous tutorials and scripts from fellow Linux users and developers. For example, the start command, to start an X session from the console, is a shell script used every day by Red Hat Users. Sending facts can be accomplished by using the fax command, which is a shell script you can customize to include your name, phone number, and other information. To learn more about scripting with bash, see the Advanced Bash-Scripting Guide, listed in the "Reference" section at the end of this chapter. You'll also find Sams Teach Yourself Programming in 24 Hours a helpful guide to learning more about using the shell to build your commands.

When you are learning to write and execute your shell scripts, start with scripts for simple, but useful tasks. Begin with short examples, and then expand the scripts as you build your experience and knowledge. Make liberal use of comments (lines preceded with a pound # sign) to document each aspect of your script. Include an author state and overview of the script as additional help, along with a creation date or version number. Write shell scripts using a text editor as vi because it does not automatically wrap lines of text. Line wrapping can break script syntax and cause problems. If you use the pico editor, include its -w flag to disable line wrap.

## Creating and Executing a Simple Shell Program with bash

In this section, you learn how to write a simple shell script to set up a number of aliases (command synonyms) whenever you log on ("Forwarding Email with Aliases" in Chapter 19, "Handling Electronic Mail"). Instead of typing all the aliases every time you log on, you can put them in a file using a text editor, as vi, and then execute the file. Normally these changes are saved in systemwide shell configuration files under the /etc directory to make the changes active for all users or in your .bashrc, .cshrc (if you use tsh), or .bash_profile files in your home directory.

Here is what is contained in myenv, a sample shell script created for this purpose (for bash):

```
#!/bin/sh
alias l11='ls -1'
alias ldir='ls -AF'
alias copy='cp'
```

This simple script creates command aliases, or convenient shorthand forms of commands, the l11 provides a long directory listing: for the ls and cp commands. The ldir alias is the ls1 command, but prints indicators (for directories or executable files) in listings, and the copy alias is the same as the cp command. and add your own options or create aliases of other commands with options you frequently use.

You can execute myenv in a variety of ways under Linux. As shown in this example, you can make myenv executable using the chmod command and execute it as you would any other Linux command:

```
$ chmod +x myenv
```

This line turns on the executable permission of myenv, which can be checked with the ls command and it shows -1 option like this:

```
$ ls -1 myenv
-rwxr-xr-x 1 winky winky 11 Aug 26 17:38 myenv
```

## Running the New Shell Program

You can run your new shell program in several ways. Each method will produce the same results, which is a testament to the flexibility of using the shell with Linux. One way to run your shell program is to execute the file myenv from the command line as if it were a Linux:

```
$ /myenv
```

A second way to execute myenv under a particular shell, such as pdksh, is as follows:

```
$ pdksh myenv
```

This invokes a new pdksh shell and passes the filename myenv as the parameter. A third way will require you to specify the location. You can then run the program without specifying the path, so:

## Interpreting Shell Scripts Through Specific Shells

The majority of shell scripts use a bang line (#1) at the beginning to control the type of shell used to run the script. For example, if you write a shell script using bash, but want the script to execute as run by the Bourne shell, the first line of your script will contain:

```
#!/bin/sh
```
