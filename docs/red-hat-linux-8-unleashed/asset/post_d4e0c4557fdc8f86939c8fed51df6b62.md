
There are two ways to run commands with root privileges. The first is useful if you are the superuser and the user; the second if you aren't the regular user (as on a large, multiuser network).

## Temporarily Changing User Identity with the su Command

What if you are also root, but logged on as a regular user because you're performing non-administrative tasks and you need to do something that the superuser can do? The command is available for this purpose. Contrary to popular belief, su means substitute user, not superuser; you can substitute the identity of any user for the one you are currently using as long as you know the password.

Because all Linux filesystem security revolves around file permissions, it can be useful to occasionally use a different user with permission to access files belonging to other users or groups or to access certain files (such as the communications port /dev/tty8 when using a modem or the sound device /dev/audio when playing a game). You can use the command to temporarily switch to another identity and switch back. The command spawns a new shell, changing the UID and GID of the existing user and automatically changes the environmental variables associated with that user, inheriting the environment. See Chapter 5 for more information on environmental variables.

The syntax for the su command is this:

```bash
$ su username arguments own```

The main page for su gives more details, but some highlights of the su command are:

- -c COMMAND: execute a command and then terminate
- -m: preserve the environment
- -s SHELL: specify the shell
- -l: login-like shell

You can invoke the su command in different ways. By using su alone, you can become root. Note that the working directory does not change unless you use the -l option. To return to your original identity, simply type:

```bash
$ exit
```

## The User Login Process

It's useful to know what happens when a user attempts to log in—if for nothing else than troubleshooting that user in the accounting department who can't get logged on to run the payroll program and get the payroll checks printed on time. Understanding this process also involves understanding the purpose of the files that are found in /etc/skeleton. This section helps illuminate the login process for you.

The login process is used for entering, or “signing on” to a system.

The login process is summarized as follows:

- 1. Login prompts for a username.
- 2. If the /etc/nologin file exists and the user isn't root, a warning message is issued and the login process is halted. The /etc/nologin file is typically used when the system will be shut down and new logins should be restricted.
- 3. The /etc/tty file is examined to see if any restrictions are specified for the user. As a security measure, root logins can be restricted to specific terminals, and regular users can have the same restrictions placed on as necessary.
- 4. The system prompts for a password: it is checked against the encrypted password kept in /etc/shadow. Unsuccessful attempts are logged via the syslog facility and can be reviewed with the lastd command.
- 5. The UID and the GID of the tty (terminal) being used are set.
- 6. The TERM environment, if it has been set, is preserved.
- 7. The HOME, PATH, SHELL, TERM, MAIL, and LOGNAME environment variables are set. If the -p option is used, all preexisting environmental variables are preserved.
