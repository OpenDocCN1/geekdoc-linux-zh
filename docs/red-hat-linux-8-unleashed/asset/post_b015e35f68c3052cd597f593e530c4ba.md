
If you're interested in the details, you can get more information using the regex (5) section of the manual.

Although replacing one string with another might seem a rather trivial task, the code required to do the same thing in another language (for example, C) is rather daunting, unless supported by additional subroutines from external libraries.

## Access to the Shell

Perl is useful for Administrative functions because it has access to the shell. That means Perl can perform for any process you might ordinarily perform by typing commands to the shell. To run Linux commands in your Perl programs use the syntax. For example, the code in Listing 23.4 prints a directory listing.

LISTING 23.4 Using Backticks to Access the Shell

```
$Scurr = `pwd`;
@list = ls -la;
print 'Listing for $Scurr_dir\n';
foreach ($file (@list) {
    print "$file"
}
```

> NOTE
> `` `` notation uses the backtick found above the Tab key (on most keyboards), not the single quotation mark.

You can also use the Shell module to access the shell. Shell is one of the standard modules that you use with Perl; it allows creation and use of a shell-like command line. Look at the following code for example:

```
use Shell qw(cp);
cp ("/home/httpd/logs/access.log", "/tmp/httpd.log");
```

This code looks like it's actually importing the command-line functions directly into Perl. Although it's not really happening, you can pretend that the code is similar to a command line and use this approach in your Perl programs.

A third method of accessing the shell is via the system function call:

```
$rc = 0xffffffff & system('cp /home/httpd/logs/access.log /tmp/httpd.log');
if ($rc == 0) {
    print "system cp succeeded\n";
}
```

## Switches

Perl has a variety of command-line options (switches) that can be used to change one or more aspects of Perl's behavior. Some switches will change how input data is handled (such as end-of-line characters), while others toggle Perl's internal behavior (such as to turn on debugging). These switches can appear on the command line or can be placed at the #1 line at beginning of the Perl program.

> NOTE
> Several command-line switches can be stacked together, -pie is the same as -p -i -e.

The following list describes all available command-line switches:

- -O[digits]-Specifies the input record separator ($/) as an actual number. $/ is usually a newline, so you get one line per record. For example, if you read a file into an array, this gives you one line per element. The value 00 is a special case and causes Perl to read in your file one line per record.
- -a-Turns on Autos mode when used with -n or -p. That means each line of input is automatically split into the @F array.
- -c-Enables native support and system interfaces for wide characters (multibyte character sets).
- -c-Tells Perl to perform syntax checking on the specified Perl program without executing it. This is invaluable, and the error messages are informative, readable, and tell you where to begin looking for the problem, which is a rarity in error messages.
- -Dflags-Sets debugging flags. perlrun for more details.
- -d—Runs the script under the Perl debugger. See perdebug for more information.
- -d:foo—Runs the script under the control of a debugging or tracing module installed as Devel::foo. For example, -dDprof executes the script using the Devel::Dprof profiler. See perdebug for additional information on the Perl debugger.
- -e commandline—Indicates that what follows is Perl code. This enables you to enter Perl code directly on the command line, rather than running code contained in a file.

```
$ perl -e 'print join ", ", keys%ENV;'
```

- -Fpattern—Specifies the pattern to split on -a is also in effect. This is " " by default, and -F enables you to set it to whatever works for you, such as ' ' or ';'. The pattern can be surrounded by //, """, or ''.
- -h—Typing perl -h lists all available command-line switches.
- -idirectory—Directories specified by -I are prepared to search the path for modules (INC). -extension—This indicates that files are to be edited in place. If the extension is provided, the original is backed up with that extension. Otherwise, the original file is overwritten.
- -l[octanum]—Enables automatic line-processing, which means end-of-line characters are automatically removed from input and put back on output. If the optional octal number is unspecified, this is the newline character.
- -m[module|M]—Loads the specified module before running your script. There's a subtle difference between n and M. See perlrun for more details.
- -n—Causes perl to loop around your script for each file provided to the command line. Perl does not print the output. The following example, from perlrun, deletes all files older than a week:

```
$ find -mtime +7 perl -nle unlink;
```

- -P—This causes your script to run through the C preprocessor before compilation by Perl. -p—This is just like n, except that each line is printed.
- -S—This searches for the script using the PATH environment variable.
- -s—This performs some command-line switching and puts the switch into the corresponding variable in the Perl script. For example, the following script '1' if run with the -fubar switch. Your perl could look like this:

```
#!usr/bin/perl -s
print $fubar;
```

When you execute it, you would enter

```
$myperl -fubar
```

- -T—This enables taint checking. In this mode, Perl assumes that all user input is tainted, or insecure, until the programmer tells it otherwise. This helps protect you from people trying to exploit security holes in your code and is especially important when writing CGI programs.
- -U—This enables you to do unsafe things in your Perl program, such as unlinking directories running as superuser.
- -V—This tells Perl to dump core after compiling this script. With much time and patience, you could presumably use this to create an executable file.
- -V—This prints a summary of the major Perl configuration values and the current value of $INC.
- -V:names

This parameter displays the value of the names configuration variable.
- -v—This prints the version and patch level of your Perl executable. For example:

```
$ perl -v
This is perl, v5.8.0 built for i386-linux-thread-multi
```

- -W—This tells Perl to display all warning messages.
- -w—This tells Perl to display warning messages about potential problems in the program, such as variables used only once (maybe be a typo), using = instead of == in a comparison, and like this one which is often used in conjunction with the -c flag to do a thorough program check.

$ perl -cw assignment.pl

Perl throws away everything before a line starting with !, containing the string 'perl', and everything after __END__. If a directory is specified, Perl changes to the directory before executing the script.

## Modules and CPAN

> NOTE
> The Perdoc documentation is referred to a few times in this section. perdebug, perln, permod, and permodlib, for example, are documents from the Perl documentation. To see these documents, just type perdoc permodlib at the shell prompt. You can also see all the documents online at http://www.perl.com/. CPAN is the Comprehensive Perl Archive. See the "Modules and CPAN" section later in this chapter for more information.

Perl documentation is written in POD (plain old documentation) format and can be converted into any other format, such as TeX, ASCII, or HTML, with the pod2 tools that ship with Perl. For example, to produce HTML documentation on Fubar module, you would type pod2html Fubar.pm > Fubar.html.

A great strength of the CPAN community (and the Linux community) is the fact that it's an Open Source community. This community support is expressed for Perl via CPAN, which is a network of mirrors of a repository of Perl.

Most of CPAN is made of modules, which are reusable chunks of code that do useful things, similar to software libraries containing functions for C programmers. These modules help speed development when building Perl programs and free Perl hackers from repeatedly reinventing the wheel when building a bicycle.

Perl comes with a set of standard modules installed. These modules should contain much of the functionality you'll initially with Perl. If you need to use a module installed with Red Hat Linux, use the CPAN module (which is one of the standard modules) to download and install other modules onto your system. At http://www.perl.com/CPAN/, you'll find the CPAN Multiplex Dispatcher, which will attempt to direct you to the CPAN site closest to you.

Typing the following command will put you into an interactive shell that gives you access to CPAN. You can type help at the prompt to get more information on how to use the CPAN program.

```
$ perl -MCPAN e shell
```
