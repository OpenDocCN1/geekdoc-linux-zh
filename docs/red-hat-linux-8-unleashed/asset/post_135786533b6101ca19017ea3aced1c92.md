> An important part of the RPM is called the .spec file. It tells RPM how to behave with the particular source.

As an example, we use information found at http://elektron.its.tudelt.fr/~rbos36/mdfreetype2.html to install the freetype2 library provided by Red Hat in order to enable the package interpreter. It has been disabled by default because of licensing concerns. Enabling it will result in improved rendering of the TrueType fonts. We use the file from Red Hat 7.3 as our example, the source file will work well as.

Begin work by first installing the source RPM package with rpm -i. It will be placed in the /usr/src/redhat/SRPMS. In this example, the freetype-2.0.9-2.src.rpm and install it with rpm -i. The source files are placed in /usr/src/redhat/SOURCES.

Copy the source file (it's a compressed tar file) to /tmp, and then cd (change directories) to unpack and modify it:

```
# cp freetype-2.0.9-2.tar.bz2 /tmp
# cd /tmp
```

Using RPM for Software Management

Because it's a .bz2 (BZip2 compressed) tar file, un-tar it with

```
# tar xjvf freetype-2.0.9.tar.bz2
```

and cd to the new directory:

```
# cd freetype-2.0.9
```

Using the text editor of your choice, edit the file include/freetype/config/fptoption.h
and find the line

```
#undef TT_CONFIG_OPTION_BYTECODE_INTERPRETER
```

Change it to

```
#define TT_CONFIG_OPTION_BYTECODE_INTERPRETER
```

Save it and exit the text editor.

Next, re-create the compressed archive:

```
# cd /tmp
# tar cfj freetype-2.0.9.tar.bz2 ./freetype-2.0.9/
```

Put it back in your source directory:

```
# mv freetype-2.0.9.tar.bz2 /usr/src/SOURCES
```

Now edit the .spec file in /usr/src/redhat/SPECS to change the line beginning with Release to increment the number found there. (We are changing the version number by doing this, so will not conflict with the version of the application we are replacing.) Make any changes to the %description line to describe your changes if you desire, and save the file.

Build the binary RPM with

```
# rpm -ba freetype.spec
```

During the build process, RPM will detect patch and asks you about patch; press y to continue. The new RPMs (actually four of them) are found in /usr/src/redhat/RPMS/i86. We only need the one named freetype-2.0.9; you can install it with rpm -U. (This is why we changed the number; if we had not, RPM would not upgrade to the same version.)

The font server needs to be restarted to use the new library, so we use the service command as shown in Chapter 7, “Managing Services.”

```
# service restart
```

Enjoy your new look, provided by better rendering of the fonts. When you compile applications from source, they won't show up in the RPM database and can't be managed by RPM. You can provide management for these applications by using a program named checkinstall. At its simplest, checkinstall is a drop-in substitute for the make install step building from source. For example, when compiling from source, you would traditionally use

```
# ./configure
# make
# make install
```

Using checkinstall, the steps would look like this:

```
# install
```

Checkinstall will create a binary RPM package and install the application from it. This makes the application part of the RPM database. The new .rpm file is left for you in /usr/src/redhat/RPMS/i86. The application can be uninstalled with rpm -e. Some applications arrive in the frame of a shell wrapper. Using the shell script as an argument checkinstall will provide a .rpm file of the installed files and add them to your RPM database. Not all applications will install with checkinstall. Read its accompanying documentation carefully. Checkinstall can be downloaded from http://linux.com/checkinstall/index.php.

## Graphical Package Management

The Red Hat graphical package management tool, Package Management, is actually an application named redhat-config-packages. This application replaces rpm which is no longer provided. Package Management allows you to select packages arranged in categories and install or remove them. You cannot add your own packages to the Red Hat graphical tool. Launch the new Red Hat GUI by clicking the Start button on your desktop, and then choose System Settings, Packages. The Package Management tool launches with Add or Remove Packages screen shown in Figure 8.2.

The packages listed on the screen are organized into Desktops, Applications, Servers, Development, and Systems groups. To choose individual package groups for installation or removal, check the box to the left of the package group name (the package group is shown in Figure 8.2). The bracketed numbers on the right of the package group name identify the number of packages installed on your system and the total number of packages available in the group. In Figure 8.2, you can see that 31 of possible GNOME packages have been installed, for example.

Other compressed files such as those created with the compress command (ending in .gz) or bzip2 files (ending in .bz2), are also supported by arch. ## Debian Package Tools

The Connectiva Linux distribution popular in South America is based on Red Hat. However, it uses a version of the Debian Package Manager that is modified to work with .rpm packages. The Debian Package Manager (known as apt) consists of a number of software tools used for package management. Debian Linux software management is provided through their dpkg command. You can also use a handful of other utilities, such as dpkg-name, dpkg-buildpackage, dpkg-getchanges, dpkg-scanpackages, dpkg-getcontrol, dpkg-distfile, dpkg-source, dpkg-parselog, dpkg-shdeeps, dpkg-deb, and dpkg-split. Browse to http://www.debian.org for more information.

A version of Synaptic (the graphical front end to apt) is specifically modified for Red Hat 8.0 is available from http://psyche.freshrpm.net/. It offers access to more RPMs many features than the very limited Red Hat Package Manager GUI.
