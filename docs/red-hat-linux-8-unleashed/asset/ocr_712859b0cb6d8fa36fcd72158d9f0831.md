You can use the -b option to display a list of the blocks that are marked as “bad” and use the -f option to force dump2fs to ignore any problems it might have with filesystem flags it can't read.

You can use the next two options in recovering lost data. The stressed out and desperate system administrator (you) would be the “filesystem wizard” referred to.

+   - superblock—Use a alternate superblock when examining the filesystem. This option isn't usually needed except by a filesystem wizard who is examining the remains of a badly corrupted filesystem.

+   - bsize—Use blocks of “blocksize” bytes when examining the filesystem. This option isn't usually needed by a filesystem wizard who is examining the remains of a very badly corrupted filesystem.

Another program, debugfs, can be used to manipulate a filesystem as well as repair and recover a damaged filesystem. Because it is such a powerful command, it doesn't run by default with the capability to write any changes to the filesystem; that functionality must be explicitly enabled when the command is run. By entering the help command at the debugfs prompt, a menu of command options is displayed; the q command exits the program.

# Mounting a Partition As Read-Only on a Running System

Remember that to do almost any kind of filesystem manipulation (formatting, checking, and so on), the filesystem should be unmounted to avoid any writes made to the filesystem, which it would corrupt.

How do you remount partitions on a running system? For example, to remount /home partition (assuming it's on a separate physical partition from root) as read-only to run fsck on it and then remount it as read-write, use the remount option for mount:

```
mount -o,remount /home
```

> NOTE
Remounting won't work if a normal user is logged in because /home will be busy (in).

We can run fsck on the partition. When done,

```
mount -o rw,remount /home
```

puts it back in service.
