
# CHAPTER 24 Kernel and Module Management

> NOTE

The stock Red Hat 8.0 kernel included with this book is the 2nd major version, the 4th minor level, the 18th patch level, and an extra version level of 14. The extra version level indicates a Red Hat specific implementation of the 2.4.18 kernel, which generally adds some code in the stock kernel necessary for special applications or hardware support.

The version number for Red Hat 8.0 is 2.4.18-14.

Even-numbered minor versions are stable kernels, whereas odd-numbered minor versions are development releases. Version 2.4.X is the stable production kernel, whereas 2.5.X is the development Linux kernel. When a new version of the stable kernel is started, it may be labeled 2.6.X or possibly 3.0.X.

For production machines, you should always use the kernels with even minor numbers. The odd minor numbers introduce new features, so you might want to use those on a test machine if you need features you provide.

# AC Patches

Alan Cox has produced the "ac" series of Linux patches to include new code being tested by developers. Alan is an accomplished kernel developer and Red Hat employee who became Linux's right-hand man. His job for the 2.4 kernels has been subsumed by Marcelo Tosalti, a four-year veteran of Connectica Linux. AC patch releases are distinguishable by -ac at the end of the kernel version. linux-2.4.9-ac10, is the ninth release of the 2.4 Linux kernel, with the 10th Alan Cox patch. Many of -ac patches have been included in the kernel that Red Hat provides. Some patches, like ACPI, are in the kernel; but they are unselected or marked as experimental, allowing you a wider range of choices.

# Obtaining the Kernel Sources

The Linux kernel has always been freely available to anyone who wants it. If you just want to recompile the existing kernel, install the kernel-sources RPM from the CD using rpm from the command line or the Red Hat graphical tool to get the latest "vanilla" version, open an FTP connection to ftp.kernel.org using your favorite ftp client and log in as anonymous. Because you are interested in the 2.4 kernel, change change to /pub/linux/kernel/v2.4. The latest stable kernel as of this writing is 2.4.19.

> NOTE

ftp.kernel.org receives more than its share of requests for download. It is considered a courtesy to use a mirror site to reduce the traffic that ftp.kernel.org bears. http://www.kernel.org/mirrors/ has a list of all mirrors around the world. Find one close to your geographic location and substitute address for ftp.kernel.org.

# Patching the Kernel

A number of different entries are on the FTP archive site for 2.4.19, but because you are only interested in the full kernel for 2.4.9, it is only necessary to get the full package of source code. There are two of these packages:

- linux-2.4.19.tar.gz
- linux-2.4.19.b22

Although these are the same kernel packages, they're built using different compression utilities: the .gz extension is the gzip package, found on almost every Linux system available. the .bz2 is the newer BZip2 utility, which has better compression than gzip. Both packages have the same content, so download the one compressed with the program you use.

Once downloaded, move the package to a directory other than /usr/src and unpack it. If you downloaded the .gz package, the unpacking command is tar -xvf linux-2.4.19.gz. Otherwise, the BZip2 unpack is tar -xjvf linux-2.4.19.tar.bz2. Once unpacked, the package will create a new directory, and place all the files in it. Rename this directory linux-2.4.19 and copy it to /usr/src or move it there. Then, create a symbolic link of linux-2.4 to linux-2.4.18 (otherwise, some scripts won't work). Here's how to create the symbolic link:

```
# ln -s /usr/src/linux-2.4.19 /usr/src/linux-2.4
```

By creating a symbolic link to /usr/src/linux-2.4, it is possible to allow multiple kernel versions to be compiled and tailored for different functions: you'll just change the symbolic link to the kernel directory you want to work on.

> CAUTION
The correct symbolic link is critical to the operation of make. Always have the symbolic link point to the version of the kernel sources you are working with.

# Patching the Kernel

It is possible to patch a kernel to the newest Linux kernel version as opposed to downloading the entire source code. This choice could be beneficial for those who aren't using a highspeed broadband connection. (A typical compressed kernel source file is 26MB or a download time of about 10 minutes on a 512Kb DSL connection; adjust accordingly for your connection.) Whether you patching existing sources or downloading the full source, the end results will be identical.

Patching the kernel isn't a mindless task: it requires the user to retrieve all patches from her current version to the version she wants to upgrade to. For example, if you are currently running 2.4.7 and want to upgrade to 2.4.18, you must retrieve the 2.4.8, and 2.4.9 patch sets, and so on. Once downloaded, the patches must be applied.

# Using the patch Command

If you have a non-standard kernel, such as one created for hardware support, you can use the patch command. Here are some quick tips:

- 1. Create a directory in your home directory and name it something, like mylinux.
- 2. Copy the patch file there
- 3. Change to that directory
- 4. Apply the patch
- 5. If the patch applies successfully, you are done.
- 6. Copy your new code to /usr/src

# Compiling the Kernel

If you want to update the kernel from new source code you have downloaded, or you have applied a patch to add new functionality or hardware support, you'll need to compile and install a new kernel to actually use that functionality. Compiling the kernel involves translating the kernel's contents from human-readable code to binary format. Installing involves putting all the files where they belong in /boot and /lib.

The process of compiling the kernel is almost completely automated by the make utility as is the process of installing. By providing the necessary arguments and following the steps next, you can recompile and install a custom kernel for your use.

Here's a checklist of steps to compile and configure the kernel:

- 1. Verify your bootdisk for the old kernel to be able to reboot your system in case something went wrong with the new kernel.

> CAUTION

Before making any changes to your current, working kernel, make sure that you have a backup copy on a floppy disk. This will allow you to boot into your system with a new kernel in case something went wrong during configuration. The command to do this follows:

```
# mkbootdisk --device /dev/fd0 -uname -r
```

This assumes that your floppy drive is /dev/fd0. (Here's a good shell script tip: the character tells the shell to execute within 'first and then returns that output as part of the input of the mkbootdisk command.) On this machine, the result is

```
# mkbootdisk --device /dev/fd0 2.4.19-7.80
```

This command won't be echoed to your screen, but it is what the system will execute.
