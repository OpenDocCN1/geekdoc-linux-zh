# Troubleshooting Post-Installation Configuration Problems

As Linux continues to be developed, it has become increasingly fault-tolerant, meaning that if errors are encountered during the boot process, the errors won't cause a complete kernel or boot failure. Often, your computer might appear to be running fine, even some device or process isn't working correctly. Sources of such problems might include modules that didn't load, services that didn't start, or devices that are being used at suboptimal levels (such as high drive speeds).

You'll find clues to problems in dmesg output, or in /var/log/messages file, a simple text file you can view in any editor. Take a moment to review this file after installing or configuring new hardware; you'll see that it shows the progress of booting and starting services your system. The messages are generated by the kernel, other softrun by /etc/rc.d/rc.sysinit, and Red Hat's runlevel scripts. You might find what

When troubleshooting error messages, remember that “Google is your friend.” Simply copy part or all of the error message and paste the information into a search field at http://www.google.com/linux/ and at http://marc.theamsgroup.com/. You might find links to pages with information to help you solve the problem. You're likely not the first person to encounter the problem. Reading the manual page for modules.conf and having perused /usr/src/linux-2.4/Documentation/devices.txt (and other files) will go a long way in helping you troubleshoot any problems.

Remember to solve one problem at a time and always make a backup copy of any system file before you modify it. Don't use the common extension .bak files with that extension can be overwritten. Here is a good method of copying the file:

```
# cp filename filename.original
```

And when restoring from backup, don't rename the file, just copy it, like so:

```
# cp filename.original filename
```

- kbdconfig—Configure a keyboard for Linux
- kppp—KDE's PPP connection can detect and use modem
- lsmod—View loaded kernel modules
- mouseconfig—Configure pointing device for Linux
- nsys—Control services started when booting

# CHAPTER 5 First Steps with Linux

Red Hat Linux offers a wonderful graphical interface for the desktop (see Chapter 6, “The Window System”), along with many capable graphical administration tools, but you can't manage or use Linux effectively if you don't know how to use text-based programs at the command line. In some situations, the command line offers the only means of interacting with a running system.

In this chapter, you learn the basics of how to use Red Hat Linux and how to accomplish many routine tasks at the command line. These basic operations include how to read files or other Red Hat documentation, list directories, move, copy, and rename files. New Red Hat system administrators will get an introduction to using the command line to create new users, manage file permissions, and to properly reboot or shut down Red Hat system.

Some of the basic command-line skills covered in, in this chapter include

- Performing routine tasks—Logging in and using the text console, changing passwords, listing and navigating directories.
- Basic file management—Creating, renaming, and deleting files and directories.
- Basic user management—Creating or deleting users from the command line.
- Basic system management—Shutting down or rebooting, reading manual pages or other documentation, and using text-based tools to edit system configuration files.
