
Win4Lin uses the native Windows programs and dlls, but modifies some of them during the installation of the Windows CD. After installing the CD, each user must install his own copy of Windows, using a legitimate MS Windows license; the root user is prohibited from running a Win4Lin desktop for security reasons. Do you really want Windows to have root authority over your computer? The installation of Windows will proceed normally, just faster than you're used to.

## Configuring Win4Lin

As the root user, you can make systemwide settings in Win4Lin and enable hardware through a GUI interface. You access the interface by running winsetup from an xterm command line from the root desktop, like this:

```
$ winsetup
```

Win4Lin has some command-line options, but they are awkward to use—it's less trouble to install a minimal desktop environment for root (if one does not exist) in order to use the GUI tools. The root user only handles systemwide administration of Win4Lin; she cannot use Win4Lin to run Windows as root.

### As an individual user

> TIP
> You must enable Cut and Paste in the winsetup program, and even then it might not work correctly in Win4Lin. Red Hat provides the xcutsel utility to Cut and Paste buffers to be swapped. Launch xcutsel from a command line (you might want to create a desktop link for ease of use) and experiment with buffer swapping. The xcutsel utility might be of use with other applications as well.

## Starting a Win4Lin Session

Start a Win4Lin session from the command line to launch either a Windows or DOS session:

```
$ win
```

or

```
$ dos
```

Win4Lin can provide an MS DOS environment as well because it's included with Windows. That DOS might be more useful and configurable than the one provided by FreeDOS running under Bochs. Although command-line options exist, all but the most esoteric options are handled through the winsetup application. Those esoteric options are holdovers from the time when Win4Lin's predecessor application, Merge, ran 16-bit Windows binaries and needed to access the advanced memory management features of 8086 Intel processors.

When launched, Win4Lin provides an MS Windows desktop in an X window running your Linux desktop. You can export Win4Lin to another computer just as you do your X session. The single-user version of Win4Lin only supports one user at a time; the server version of the product is available. An unsupported application named apprapper.exe (available on the Netverse Web site) can be used to display a single application running in Win4Lin rather than the entire desktop—useful if you want to restrict a user's choice of applications for security reasons.

## Comparing Wine, Win4Lin, and VMware

So how do the Win4Lin and VMware emulators compare to the Wine program each other? The benefits of Wine versus VMware are that it costs less and uses fewer resources. On the other hand, Win4Lin cannot handle the range of operating systems that VMware can, and hardware support is more limited.

Win4Lin has some benefits not found in Wine, as well. Win4Lin can run a wider range of applications and is more stable than Wine; it is surprisingly faster and more stable than a native Windows installation on the same hardware. Win4Lin does cost more than Wine, however, and you must also have a licensed copy of Windows in order to use it.

Win4Lin is well suited for running a wide range of business-related applications like MS Office (office-oriented as opposed to home- or multimedia-oriented DirectX/3D is not supported) in an environment where stability is important and a licensed copy of Windows is available.

## Mac OS Emulation

Apple has provided an operating system that has attracted millions of loyal followers and for which a plethora of applications exist. For the emulator developers, emulating the Apple Macintosh operating systems on Intel hardware is a challenge. Apple software is designed to be run on a non-Intel processor and on hardware that is unlike that found on many Intel-based PCs. A significant hurdle is the necessity of possessing a legitimate version of the Apple ROM code. Red Hat does not provide any Apple emulators.

In this section, we'll look at the most popular and mature Apple emulators available and see what they have to offer an Apple user. If you already have an Apple and have accumulated software for it, these emulators can breathe new life and usability into them by allowing to use all your applications on a single computer.

## EXECUTOR

ARDI's Executor is a commercial software emulator that runs legacy Mac OS applications under Linux. A demonstration version can be downloaded for testing before purchase from http://www.ardi.com. Executor emulates a Motorola MC68040 CPU running System 6.0.7 and supports near 400 Macintosh applications. Some of the features and hardware not supported, however, are serial ports, LocalTalk, Control Panels, or INITs. On the other hand, Executor does not require the Apple Mac OS System files or binary ROM images.

> NOTE
> Executor will not run newer OS X applications. However, you can download and install Apple Computer's Darwin distribution by browsing to http://gnu-darwin.sourceforge.net/. It doesn't include the proprietary OS X graphical interface, however, so it won't run those applications either. You would be better off installing the full version of BSD that Darwin is based on: http://www.freebsd.org.

The software is installed with the rm command under the /executor/bin directory with symbolic links to the /usr/local/bin directory. The client started like this:

```
$ executor
```

After you press Enter, the main window will appear as shown in Figure 27.9.

The software obeys X11 window settings. The left Alt key is used as the Apple Command key, whereas the right Alt key is used as the Option key. Press Alt+Shift+5 to set preferences.

## Basilisk II

Basilisk II is a free Macintosh emulator that provides PowerPC emulation of Mac OS in order to run selected Mac software. A copy of earlier versions of Mac OS and a binary of an Apple ROM chip are required to run Basilisk II. It supports several versions of OS, up to version 8.1. Red Hat Linux does not support the latest Hierarchical File System (HFS+), but does support the earlier HFS.

Basilisk II also supports Ethernet, serial, SCSI, and Apple Desktop Bus (ADB) drivers. You configure settings in Basilisk using a graphical editor; you can edit preferences in a file named .basilisk_prefs in your home directory. You can use this to specify various hard drive, floppy diskette, video resolution, window geometry, color depth, sound, keyboard, mouse, network, and server-port settings, along with the location of required files, allocated memory, and boot mode.

You have download and build the Basilisk II emulator from scratch. You'll find the source code on the Basilisk II home page ("Reference" later) in a compressed archive or RPM package. An excellent Web reference for Basilisk II issues and installation is http://www.karning.net/-mhoffman/basiliskII/system7/linux/.

## Remote Computer Operating

Modern operating systems support remote management and access tools; Linux is no exception. Many of the legacy UNIX commands, such as rep and telnet, have been superseded by more capable—and more secure—clients. This section provides an overview and introduction to the use of VNC. VNC is a popular networking client included in your Red Hat CD-ROMs. It allows you to display a window on your computer that is the desktop of a remote computer. Your local mouse and keyboard control the remote computer as if you were sitting in front of it. In this section, we examine VNC and show you how to install and run it, as well as some useful variations of VNC.

## Virtual Network Computing

Virtual Network Computing, or VNC, is a virtual network management application manufactured by AT&T Laboratories in Cambridge, England. VNC includes the vserver and vncviewer components; you use VNC to access remote desktops on networked computers. The host must run a native version of vnc, but you can run it anywhere. Free downloadable versions of VNC are available for dozens of different operating systems.
