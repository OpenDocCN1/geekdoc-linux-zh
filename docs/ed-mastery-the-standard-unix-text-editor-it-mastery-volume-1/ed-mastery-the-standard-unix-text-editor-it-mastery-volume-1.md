# 第 0 章：引言

让我在这里明确：`ed(1)` 是标准的 Unix 文本编辑器。

Unix 的共同创建者 Dennis Ritchie 曾这样宣告。面对一个不需要使用玻璃电打字机¹就能编写完整操作系统的专家，你又什么可以反驳？

许多年轻的系统管理员天真地举起旗帜捍卫 `ex`、`vi` 甚至是极其臃肿的 `nvi` 这样过度扩张、过度设计的文本编辑器。有些人迷失至于投身于仅供普通用户的冗长编辑器，如 `vim` 和 `Emacs`。这不仅表现了令人震惊的系统管理水平，更是道德的缺失。作为系统管理员，你必须有足够的脑力来记住你输入了什么，在脑海中保持上下文，并在深层且个人的层面上与机器进行真正的交流。

大多数 Unix 主机存在是为了执行实际工作，例如支持数据库或提供网页服务。当你指定系统的内存、处理器和磁盘 I/O 时，你考虑的是运行这些任务所需的硬件数量。任何可用的系统资源都是为了支持非寻常的峰值，而不是某个可怜的过度设计的文本编辑器。当你为了运行一个花哨的编辑器而占用额外的千字节——更糟，是兆字节——时，你是在窃取主机的资源。

依赖 `vim` 之类的系统管理员？他们正在积极地危害系统。不要信任他们。

- 你知道的，玻璃电打字机。那孩子一直管它叫“显示器”，尽管我们知道显示器是音频制作中使用的参考扬声器。

对于普通用户来说，不能使用 `ed` 并不不可耻。我没有资格成为海陆突队。我甚至没有资格成为那种躺在沙滩上叫叫的海豹。这没关系。世界上到处都是计算机。如果你无法处理 `ed` 那种波动的荣光，就用那些友好的“点击式”系统吧。你正是那些系统存在的意义。不过，我推荐那些没有键盘的平板电脑，因为明亮、鲜艳的图标对那些无法教育的人非常有帮助。

不使用 `ed(1)` 并不是系统管理成就的巅峰；它是最低要求。你必须具备这种能力来管理这台计算机。

如果你在读这本书，是因为你想加入精英行列。你想成为信息技术领域“海陆突队”成员的一员。你想成为一个真正的系统管理员，而不是那些需要花哨玩具才能喜欢“显示器”的伪君子之一。是的，我们的人有显示器，但仅仅是因为这些软弱的现代笔记本电脑没有内置行式打印机。

真正的系统管理员不仅工作，他们还凭借智慧和行式打印机真正蓬勃发展。我们欢迎任何证明自己值得加入我们行列的人。

这本书涵盖了标准 `ed`。许多操作系统开发者无法抵制住为 `ed` 添加额外功能的冲动。这就是之后 `ex` 和 `yi` 发生悲剧的原因。虽然这些开发者想要参与像 `ed` 这样重大意义的事物的冲动完全可以理解，但本书不会涵盖特定操作系统的扩展，例如 Linux 的 `x` 和 `y` 命令以及 FreeBSD 的加密支持。

不过，我应该警告你：有些系统管理员反对这本书。他们真诚地认为，最好的系统管理员是通过学习操作系统的源代码，或最坏情况下阅读帮助手册（`man` page）来学习的。

然而，这些人中的许多忘记了自己的年轻。你无法自学计算知识。即使是最明智的 Unix 管理员也有导师。

在这个阴暗的时代，搜索引擎算法挖掘出组装粗劣的 HOWTO 并将其当作权威文档，为下一代系统管理员提供支持是我们作为一个职业所面临的最重要任务之一。我不希望存储我退休资金的服务器由所谓的系统管理员管理——只要你身边有这本书，结合一本良好的 C 参考书（例如受尊敬的 Brian Kernighan 和 Dennis Ritchie 编写的1978年版《C 语言程序》）。如果他们能使用行式打印机输出来编写一个完整的操作系统，你就能处理好你的小任务。

只有傻蛋才会因为你试图超越限制并成为一名真正的系统管理员而轻视。不幸的是，由于社会偏见，如果你把这本书视为珍贵的秘密，我不能怪你。如有必要，你可以从最近的 Gopher 站点获取如何用棕纸袋制作保护书的说明。

真正的系统管理员理解计算机是如何工作的。我们明白，渴望已久的“所见即所得”（WYSIWYG）编辑器只不过是营销部门的一个有害谎言。我们骨子里都清楚，以 `.txt` 结尾的文件并不一定是文本文件——事实上，文本文件可以有任何名字。超越这些欺骗是实现真正的系统管理员精通的必要步骤。标准的 Unix 编辑器并不假装是处理文本引擎之外的东西。

而它是多么伟大的引擎。

# 第 1 章：Ed 基础

从本质上说，`ed(1)` 是一个文本编辑器。尽管它是在计算机还没有显示器的时代编写的。计算机可以将数据写入磁带或打印机。但那时的打印机并没有浪费地一次运行整张纸；像条形机和打字机一样，这些行式打印机一次打印一行。

系统管理员会输入命令，仅在需要时打印结果。或者，如果你愿意的话，每当你丢失思路，噼啪作响的打印机就会向听力范围内的每个人宣告。真正的系统管理员可以专注于工作并记住上下文。

`Ed` 是一个行编辑器。它在打印机打印的文本行上工作。如果你不幸地被困在那些新奇的“显示器”上，它在上面也能运行得很好。

我们将从几个基本任务开始探索 `ed`：启动程序、考虑模式、保存和退出。

## 启动 Ed

通过输入 `ed` 和你想编辑的文件名来运行 `ed(1)`。在这里，我想编辑一个包含我最喜欢的诗的文本文件，卡罗尔的《奇幻角》。

```
$ ed jabberocky.poem
```

数字 963 在诗中任何地方都没有出现。它为什么在这里？

当你编辑文件时，`ed` 将整个文件读入内存缓冲区。就像内存中的其他一切一样，系统关闭或程序退出时缓冲区就会消失。当你编辑文件时，你更改的是缓冲区中的副本。在某些时刻你可能会用缓冲区覆盖原始文件。可以将缓冲区写入不同的文件或新文件。当你启动 `ed` 时，它会告诉你它读取了多少字节。记住，真正的软件不使用不必要的内存。

文本在哪里？这就是你的文件。你不想每次打开一个文件都浪费很多行纸吧？下次尝试使用 `head(1)` 在加载编辑器之前查看文件内容，或者翻阅旧的打印件来识别文件。

## 命令与模式

`Ed` 是命令驱动的，这是一种说法，意味着它是一个文本处理 shell。你将在 `ed` 命令提示符处发布命令。现在试一下，按 `ENTER`。

```
?
```

`Ed` 只有一个错误消息，一个简单的问号。它意味着“我不懂你”。当你收到错误消息时，检查你输入的命令并弄清哪里错了。`ENTER` 不是一个有效的 `ed` 命令³

`h` 要求 `ed` 解释上一个错误。关闭详细错误消息后，再次尝试 `ENTER`，然后使用 `h` 解释错误。

`Ed` 可以处理 emoji，但这样做对你永恒的危险几乎和使用 `nano` 一样大。

## 地址

现在一切都变得非常清晰了，对吧？也许可能没有，但我们将在第 10 章讨论地址。

如果你有无限的墨水预算，可以开启详细错误消息。单独输入 `H` 即可切换详细错误消息的开启与关闭。

### H

`Ed` 回应了你发送给打印机的命令。现在再次尝试 `ENTER`。

```
?invalid address（无效地址）
```

默认开启详细错误消息既浪费纸张又浪费阅读时间，但我们都曾有过那种经历：盯着自己的命令看了太久，试图弄清楚自己到底做错了什么。我们都需要学习。



另一个你可能觉得有用的命令是开启或关闭命令提示符。`ed` 的命令提示符是一个星号 `*`。当你回查看旧的打印输出并需要识别命令时，或者当你拥有一个带有视频终端的高级系统时，它非常有用。输入 `P` 开启或关闭命令提示符。

## `P`

如果你正在使用视频终端，将立即看到命令提示符。打印机用户将在显示下一条命令的行中看到命令提示符。

逐条输入命令。其中某些命令（如正则表达式，第 101 章）可能非常复杂并包含许多字符，但每个命令都需要单独占一行。在这里，我尝试同时开启详细错误消息和命令提示符。

## `HP`

?

我弄混了 `ed`。让我们查看细节。

# 第 10 章：地址

在 `ed` 的术语中，地址是缓冲区中的行号。你的命令影响某个地址。许多命令按逐个地址产生效果，例如“删除地址”或“在地址 5 之后插入”。`ed` 还有一个“当前地址”的概念，它是默认位置。你可以告诉 `ed` 你正在处理第 5 行，然后更改或以其他方式破坏文件中的该位置。`ed` 大量使用地址。选择和设置地址是使用 `ed` 的重要部分。

我们将使用一个包含卡罗尔诗歌《Jabberwock》的文件来演示地址。虽然我确定我的大多数读者（作为正直且有价值的人）并不熟悉也没有背过这首诗，但附录 A 为那些饱受人文教育不足痛苦的人提供了副本。它全长 34 行（包括段落之间的空行），因此包含 34 个可能的地址。少数 `ed` 命令（但并非所有）可以接受零地址，意味着“地址 1 之前”。

许多 `ed` 命令期望你将受影响的地址放在命令之前。像 `4,5` 这样的命令表示“在地址 4 到 5 之间执行命令”。一个单独的地址意味着“在地址 1 之前”。两个逗号分隔的地址表示起始和结束地址，包含它们之间的所有内容。

当你设置地址时，`ed` 会打印该行。为了增长见识，在启动 `ed` 时设置 `h` 命令。

任何单个字符都匹配其自身。如果你想按顺序匹配字母“t”、“h”和“e”，你需要使用像如 `/the/` 这样的正则表达式。

正则表达式使用句号（`.`）作为通配符。它可以匹配任何字符。字符类出现在方括号（`[]`）中。一个类描述了表达式中可能出现的一组字符。我们将在本章稍后的“字符类”中详细介绍这些内容。

转义字符允许你在正则表达式中包含具有特殊目的的字符。最显而易见的例子是你可能需要在正则表达式中包含一个斜杠。斜杠被用于分隔正则表达式，所以你不能直接用 `//`。你需要使用反斜杠（`\`）作为转义字符，告诉系统该字符应该被视为字文字，而不是表达式的一部分。转义后的反斜杠看起来是 `\\`，匹配斜杠的正则表达式将变为 `/\//`。搜索点需要 `\.`，而搜索方括号需要 `\[` 或 `\]`。转义还可以将普通字符转换为特殊字符，例如用于计数的的大括号和反向引用所需的括号。

什么时候该用哪一个？如果你阅读源代码，这一切都完全合理，但现在只需点头、微笑并遵循示例即可。

让我们看看正则表达式在几个高度人工的示例中是如何工作的。

## 子表达式与反向引用

子表达式是正则表达式的一部分。使用子表达式将一行拆分成若干块，如“我们关注之前的所有内容、我们关注的内容、以及之后的所有内容”。子表达式用括号标记，例如 `([a-zA-Z0-9])`。与大括号类似，你必须转义括号，以告诉 `ed` 你正在将它们用于子表达式。否则，`ed` 会查找字面上的括号字符。在引入子表达式时，我们将跳过反斜杠。

为了让 `ed` 记住整行，子表达式必须匹配包含字符串的整行。点和通配符在这里非常有用。虽然 `/the/` 匹配包含字符串“the”的行，但记住整行需要使用 `.*`：任意多个字符、我们真正想要的、然后任意多个字符。将正则表达式括在括号中让 `ed` 将其视为子表达式：`/(.*)`

反向引用允许你引用子表达式匹配的字面文本。你可以在搜索中使用反向引用，但它们大量出现在替换中。`ed` 按你定义的顺序调用子表达式。你的第一个子表达式是第一个引用，第二个是第二个，以此此类推。用反斜杠和数字指示反向引用，如 `\1`、`\2` 等。

我们的示例正则 `/(.*)` 告诉 Ed 记住一个子表达式。只有一个反向引用 `\1`。

如何使用子表达式和反向引用？你可能想搜索包含起始和结束引号的所有行。人类是非常一致的，所以这些字符串使用单引号或双引号。我定义了一个包含两种引号的字符类 `['"]`。该类包含括号以声明它是子表达式：`(['"])`。在我们之后可以是任何数量的字符，直到下一次出现与子表达式匹配的内容：`.*`。我们在子表达式中找到的任何字符都是我们的第一个反向引用，或 `\1`。将所有内容组合成正则 `(['\).*\1`。我想在搜索命令中使用它，所以我需要转义括号以告诉 `ed` 这是一个子表达式：`\(['\\].*\1`。使用 `g` 命令打印匹配此正则的行。

```

'bleeeeeep'
unconscious 'people'
```

第一行对我们的目标正则表达式进行搜索，选择包含“the”的行。命令被分为两行，因此 `ed` 会打印匹配的行。第二行执行替换，添加字符串 `HIT-`，然后添加 `\1` 反向引用来调用第一个也是唯一的子表达式。我在末尾添加了 `p` 以在替换后打印结果，显示替换前后的效果。每个匹配字符串都具有所需的前缀。

# 第 111 章：脚本

脚本是系统管理中至关重要的组成部分。在脚本中使用 `ed` 不仅会简化某些任务，还将证明你相对于所谓的系统管理员的道德优越性。

考虑我们上一章中在每行上对正则表达式加下划线的命令。你真的不想在每次需要这种转换时都输入一遍，对吧？一个可重用、可编辑的脚本要好得多。

脚本的关键在于记住 `ed` 与平级编辑器不同，它接受来自标准输入的指令。它不需要区分人类输入和脚本输入。你不能在 `ed` 脚本中包含注释，但你有各种运行它的方法。

## Ed 命令文件

使用 `ed` 脚本的最简单方法是创建一个包含要运行的所有 `ed` 命令的文件。然后像这样运行它。

```
$ ed textfile < ed-commands.ed
```

命令文件只包含你想运行的 `ed` 命令。

当你学习任何脚本方法时，从创建一个复制匹配正则表达式行的脚本开始。打开你的编辑器并跟随操作。
