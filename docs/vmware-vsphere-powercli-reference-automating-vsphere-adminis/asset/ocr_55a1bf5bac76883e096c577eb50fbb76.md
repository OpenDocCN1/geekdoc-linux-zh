# Snapshots

One of our favorite vSphere features is the ability to take snapshots of virtual machine, but when unmanaged, snapshots can be catastrophic. The problem with snapshots is that they tend to be forgotten once created. For each snapshot you create, vSphere creates a new disk underwater, also referred to as a delta disk, for every disk that's affected by the snapshot operation. These delta disks keep track of the changes made to their parent disk and grow as more data is modified. When the snapshot is kept for a long time, these delta disks grow large and eventually occupy all the free space on your datastore. Large disks can slow down the performance of your VM, and when you eventually want to delete the snapshot, it can take hours until all the changes are committed to the parent disks, which in turn can lead to unavailability of your VM. Snapshot information is retrieved using the Get-Snapshot cmdlet. Let's create a simple overview of all snapshots, in your infrastructure:

```
Get-VM | Get-Snapshot
```

| Name | Description | PowerState |
|---|---|---|
| Snap001 | Before upgrade | PoweredOff |
| VM001_Snap001 | Installation test 1 | PoweredOn |
| VM003_01 | Before patches | PoweredOn |

There are other interesting properties that aren't shown by default, the SizeGB and Created properties calculates the total size of all related snapshot files on disk. In the real world, you use this property to monitor the size of your snapshot files on disk so that they don't become too large. This way, you can avoid the havoc caused by large snapshots.
