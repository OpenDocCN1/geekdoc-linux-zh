## Set Up the Network

Networking is at the heart of vSphere configuration. After the physical network cables have been patched into your ESXi hosts, you will need to create vSwitches and port groups in order to make management connections to your hosts, vKernel ports to connect to iSCSI and NFS storage (for vMotion), and virtual port groups so that your VMs can communicate with other servers—both in the virtual and physical worlds.

## Standard and Distributed vSwitches

First, you need to create at least one switch. You have two possible options: standard vSwitch or a distributed vSwitch. A standard vSwitch extends only to the boundary of an individual host; a distributed vSwitch can extend across that boundary and can be accessed by multiple hosts. This relaxes the requirement that individual standard vSwitches be configured exactly across the same hosts. a distributed vSwitch appears the same to each host. Toward the end of this, we will demonstrate how to migrate VMs from a standard to a distributed vSwitch.

> NOTE Distributed vSwitches require Enterprise Plus licensing for each ESXi host you wish to use with them. Not everyone has access to Enterprise Plus licensing.

## Standard Switches

Let's take a look at configuring standard vSwitches (VSS) and some of the options you have when working with them. Standard vSwitches must be configured identically across all hosts in a cluster to ensure that technologies like vMotion work correctly. Consequently, PowerCLI is a great choice for this job because you can easily make each vSwitch consistent.

Apart from those switches VMware refers to as internal (switches that are isolated from the physical network), which each create must be assigned to at least one network card. So, before creating your vSwitches, it's a good idea to know which network adapters are present in your host. You can use the Get-VMHostNetworkAdapter cmdlet to examine this information (Listing 3.1).

It is possible to extract Cisco Discovery Protocol information from the ESXI host and pass it on to the network team, who can then help you assign the right NICs to vSw. Get-VMHostDetailedNetworkInfo returns this information for an individual host or all hosts in a cluster (Listing 3.2).

### Listing 3.2 Retrieving ESXi host networking information

```powershell
function Get-VMHostDetailedNetworkInfo {
<#n.SYNOPSIS
Retrieve ESXi Host Networking Info.
.DESCRIPTION
Retrieve ESXi Host Networking Info using CDP.

.PARAMETER VMHost
Name of Host to Query

.PARAMETER Cluster
Name of Cluster to Query

.EXAMPLE
Get-VMHostDetailedNetworkInfo -VMHost VMHost01 -Verbose

Get-VMHostDetailedNetworkInfo -Cluster Cluster01 | Sort-Object Host, PNIC | Export-Csv C:\Scripts\CDP.csv -NoTypeInformation
#>
[CmdletBinding(DefaultParameterName="VMHost")]
param (
    [Mandatory=$true, ParameterSetName="VMHost"
    Position=0)]
    [NotNullOrEmpty()]
    [String]
    $VMHost,

    [Mandatory=$true, ParameterSetName="Cluster"
    Position=0)]
    [NotNullOrEmpty()]
    [String]
    $Cluster
)

Write-Verbose "Gathering VMHost objects"

$arrHostSystemPropertiesToGet = "Name", "ConfigManager", "NetworkSystem", "Config.Network"

if ($Cluster) {
    $vmhosts = Get-Cluster $Cluster | Get-VMHost |
    Where-Object {"Connected", "Maintenance" -contains $_.ConnectionState} |
    Get-View -Property $arrHostSystemPropertiesToGet
} else {
    $vmhosts = Get-VMHost $VMHost -State Connected, Maintenance |
    Where-Object {"Connected", "Maintenance" -contains $_.ConnectionState} |
    Get-View -Property $arrHostSystemPropertiesToGet
}

$MyCol = @()
foreach ($vmwarehost in $vmhosts) {
    $ESXHost = $vmwarehost.Name
    $networkSystem = $vmwarehost.ConfigManager.Network
    foreach ($pnnic in $networkSystem.VirtualSwitch) {
        $pnnicInfo = $networkSystem.Query($pnnic)
        $record = 0
        while ($record -lt $pnnicInfo.Subnet.Length) {
            $obs = $pnnicInfo.Subnet[$record]
            $VLAN = $obs.VlanId
            if ($VLAN -eq $null) {
                $strVLAN = $VLAN.ToString()
                $MyCol += [PSCustomObject]@{
                    Host = $ESXHost
                    PNIC = $pnnic
                    Speed = $obs.Speed
                    MAC = $obs.Mac
                    DeviceID = $obs.DeviceID
                    PortID = $obs.PortID
                    Observed = $obs.Observed
                    VLAN = $VLAN
                }
            }
            $record++
        }
    }
}
```

Now that you know which NICs should be allocated to vSwitch, it's time to start creating the switches. By default, an install of ESXi creates a virtual port group on the same vSwitch as the management NIC. Since you will have NICs dedicated to virtual traffic, let's use it. The Get-VirtualSwitch cmdlet to retrieve the default vSwitch, the Get-VirtualPortGroup cmdlet to identify the default VM network port group, and Remove-VirtualPortGroup to remove it (Listing 3.3).

### 3.3 Removing the default VM network port group

```powershell
Get-VirtualSwitch -VMHost vesxi105* -Name vSwitch0 |
Get-VirtualPortGroup -Name "VM Network" |
Remove-VirtualPortGroup -Confirm:$false
```

Now let's create a new vSwitch to serve virtual machines. In List 3.4, we assigned switches to vmnic4 and vmnic5 that we earlier identifying as allocated for this vSwitch.

### LISTING 3.4 Creating a new standard vSwitch

```powershell
$vSwitch = New-VirtualSwitch -VMHost vesxi05* -Name "vSwitch" -Nic vmnic4,vmnic5
```

> TIP The technique we used for this last example, storing the results of an interactive command, is a good way to save time when you are working in the command shell. Rather than having to repeatedly type commands to work with the same object, you can return at object and store it in an easily accessible variable.

### LISTING 3.5 Creating a new port group

```powershell
New-VirtualPortGroup -VirtualSwitch vSwitch -Name VM220 -VlanID 220
```

In addition to vSwitches and port groups for virtual machines, it is also high likely that you will need to create VMkernel port groups for use with technologies like vMotion or fault tolerance. As mentioned earlier, VMkernel port groups are also a requirement for iSCSI or NFS storage.

Let's create a VMkernel port group for vMotion; we'll create it as an additional port group for vSwitch0 (you'll see this in the next section when we look at switches and port groups resilient).
