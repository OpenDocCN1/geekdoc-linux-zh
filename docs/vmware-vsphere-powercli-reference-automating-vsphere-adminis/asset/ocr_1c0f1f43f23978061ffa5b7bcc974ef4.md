Now, let's use the Add-Member cmdlet to add a numVM property to the cluster object that holds the number of virtual machines:

```
$clusterReport = @()
foreach ($cluster in Get-Cluster) {
  $cluster | Add-Member -MemberType NoteProperty -Name numVM \
    -Value @($cluster | Get-VM).count
  $clusterReport += $cluster
}
$clusterReport | Select Name, numVM
```

# New-Object

When your reporting requirements call for information from different objects, it's so much easier to create your own custom object rather than extend an existing object. The best way to create a report is to define a custom object that includes all the properties you need. A custom object can be created using the New-Object cmdlet and properties can be defined with the Add-Member cmdlet:

```
$myObject = New-Object Object
$myObject | Add-Member -MemberType NoteProperty -Name Vm $null
$myObject | Add-Member -MemberType NoteProperty -Name Host $null
$myObject | Add-Member -MemberType NoteProperty -Name ClusterName $null
```

# New-Property

One of the features that introduced in PowerShell 4.1 is the New-Property cmdlet. This cmdlet lets you add your properties to a specified PowerShell object type. Because you are adding the type (not just a single existing instance like the Add-Member cmdlet), the new property will be available on the next retrieval of the corresponding objects. Let's illustrate this with an example:

```
Get-VM | Get-View | Select-Object Name, @(Name="ToolsVersion"; Expression={$_.Config.Tools.ToolsVersion})
```

Using script, you are forced to use the Get-View cmdlet to access the underlying SDK to retrieve the Tools Version. Using the New-Property cmdlet, you can create a new property to hold this information, so you don't need to retrieve the underlying SDK anymore:

```
New-Property -Name toolsVersion -ObjectType VirtualMachine -ValueFromExtensionProperty 'Config.Tools.ToolsVersion'
Get-VM | Select Name, toolsVersion
```
