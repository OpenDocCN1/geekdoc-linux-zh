# Connecting to vCloud Director

Before you work within the vCloud Director environment, you must log on to the target private cloud to authorize the PowerShell session. You can then connect to vCloud Director using the Connect-CIServer command:

```powershell
Connect-CIServer -Server vCD.vmwarelab.com -User Administrator
-Password VMware!
```

At times, it is beneficial to run multiple PowerShell sessions against vCloud Director at the same time. This may be through the use of PowerShell jobs, scripts invoking other scripts, and so on. You can leverage a single vCD login across multiple sessions by grabbing the SessionSecret from your main vCloud session when logging into vCloud Director:

```powershell
$connection = Connect-CIServer -Server vCD.vmwarelab.com -User Administrator \
-Password VMware!
```

You can also run this command without placing your credentials in your code by using the Get-Credential cmdlet:

```powershell
$connection = Connect-CIServer -Server vCD.vmwarelab.com -Credential \
(Get-Credential)
```

When prompted, enter your username and password without revealing it within your script. Once you've used that line of code to connect to vCloud Director, you can see your SessionSecret:

```powershell
$connection.SessionSecret
526da858-94d1-2760-7d90-4d30fc4635aa
```

You can use the SessionSecret to log into vCloud Director in your other PowerCLI sessions using the -SessionID parameter:

```powershell
Connect-CIServer -Server vCD.vmwarelab.com -SessionID
$connection.SessionSecret
```

This allows you to log on to other sessions without entering a username and password as long as the main connection stays active.

# Manage Organizations

vCloud Director Organizations (also known as orgs) are the topmost containers where the rest of the private cloud is created. Within these organizations, administrators can create vDCs (virtual datacenters), add local users, create vApps, manage items, and allocate virtual resources. Service providers may find it necessary to create new orgs from time to time, as well as disable or remove orgs. This section will cover the administration and management of orgs.

# Creating Organizations

Organizations are one of the objects that can be created using PowerCLI. The New-Org requires two parameters: Name and FullName.

```powershell
New-Org -Name Customer1 -FullName Customer_X_Seattle
-Description "This is Customer X in Seattle"
```

Org names and descriptions can be easily updated using the Set-Org cmdlet as:

```powershell
Get-Org -Name Customer1 | Set-Org -FullName Customer_Y_Orlando \
-Description "This customer is based out of Orlando"
```

# Enabling/Disabling Organizations

Once a new org is created, it is enabled by default. Generally this is fine, but sometimes administrators need to disable an organization. When this happens, it is fine to use PowerCLI to disable the target organizations:

```powershell
Get-Org -Name Customer1 | Set-Org -Enabled:$false
```

When an org is disabled, it cannot deploy or power on any additional vApps until it has been re-enabled. An org must be disabled before it can be removed.

# Manage Organizations

vCloud Director Organizations (also known as orgs) are the topmost containers where the rest of the private cloud is created. Within these organizations, administrators can create vDCs (virtual datacenters), add local users, create vApps, manage items, and allocate virtual resources. Service providers may find it necessary to create new orgs from time to time, as well as disable or remove orgs. This section will cover the administration and management of orgs.

# Creating Organizations

Organizations are one of the objects that can be created using PowerCLI. The New-Org requires two parameters: Name and FullName.

```powershell
New-Org -Name Customer1 -FullName Customer_X_Seattle
-Description "This is Customer X in Seattle"
```

Org names and descriptions can be easily updated using the Set-Org cmdlet as:

```powershell
Get-Org -Name Customer1 | Set-Org -FullName Customer_Y_Orlando \
-Description "This customer is based out of Orlando"
```

# Enabling/Disabling Organizations

Once a new org is created, it is enabled by default. Generally this is fine, but sometimes administrators need to disable an organization. When this happens, it is fine to use PowerCLI to disable the target organizations:

```powershell
Get-Org -Name Customer1 | Set-Org -Enabled:$false
```

When an org is disabled, it cannot deploy or power on any additional vApps until it has been re-enabled. An org must be disabled before it can be removed.

# Organization Networks

Each org requires its own vDC network. More org VDC networks can be associated to each org. These networks fulfill different purposes within the org. There are three network types that can be used within the org:

- **Internal**: An internal connection is a completely isolated network for all machines within the org vDC. No network traffic can traverse the org vDC boundary to any other organization's network or an external network.
- **Direct**: A direct connection is just what it sounds like. It provides a direct connection to the external network.
- **Routed**: A routed connection allows the org vDC to communicate with other networks via a router.
