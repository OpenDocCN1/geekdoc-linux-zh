# CHAPTER 2 • AUTOMATING VSPHERE HYPERVISOR DEPLOYMENT AND CONFIGURATION

For example, to attach the host name PROD01 to a vSphere host named vsphere03, run the following command:

```
$HostProfile = Get-VMHostProfile -Name PROD01
$VMHost = Get-VMHost vSphere03*
Invoke-VMHostProfile -Entity $VMHost
-Profile $HostProfile
-AssociateOnly
```

At this point, the PROD01 host profile is attached to vsphere03. Now you need to test your profile against the host. If the profile has additional information that needs to be answered before the profile can be applied, the Invoke-VMHostProfile will return a hash table of settings. Therefore, after placing the host in maintenance mode you could capture the output of this action in a variable for:

```
$AdditionalConfiguration = Invoke-VMHostProfile \
-Entity $VMHost
-ApplyOnly
```

In this case, it's a hash table of IP settings:

```
$AdditionalConfiguration | Select-Object Name
```

Name

```
network.hostPortGroup["key-vim-profile-host-HostPortgroup-Profile-isSCI"].ipConfig.IPAddressPolicy.address
network.hostPortGroup["key-vim-profile-host-HostPortgroup-Profile-vMotion"].ipConfig.IPAddressPolicy.subnet
network.hostPortGroup["key-vim-profile-host-HostPortgroup-Profile-vMotion"].ipConfig.IPAddressPolicy.address
network.hostPortGroup["key-vim-profile-host-HostPortgroup-Profile-isSCI"].ipConfig.IPAddressPolicy.subnet
```

Before you apply your profile, you must provide values for these settings. You can accomplish this by addressing each entry in the hash table and setting a simple string value:

```
$AdditionalConfiguration['network.hostPortGroup["key-vim-profile-host-HostPortgroup-Profile-isSCI"].ipConfig.IPAddressPolicy.address'] = '10.10.10.1'
$AdditionalConfiguration['network.hostPortGroup["key-vim-profile-host-HostPortgroup-Profile-isSCI"].ipConfig.
```
