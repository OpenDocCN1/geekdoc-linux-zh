EVC is a handy feature to enable vMotion within a cluster of multigenerational servers, but it has some nuances. For example, you can increase the level of EVC without powering down all VMs in the cluster, but you cannot decrease the level without powering down the VMs first. Similarly, if you vMotion from a cluster with a higher EVC setting to a lower setting, you will need to power down the VM.

With this workflow in mind, you can seamlessly replace an entire cluster's worth of servers without having to vMotion across clusters:

- 1. Ensure that EVC is enabled for the old servers' CPU level.
- 2. Add the new servers; EVC will mask the new CPU features automatically.
- 3. Remove the old servers.
- 4. Increase the EVC mode to the maximum available for the new servers.
- 5. Reboot the VMs at your convenience; they will automatically begin using the new CPU features.

# vFlash Read Cache

vSphere Flash Read Cache (vFRC) is a feature that was introduced by VMware with vSphere 5.5. This feature uses SSDs local to the physical host to provide an accelerated read-only cache for individual VMDKs of virtual machines hosted by that server. This has a tremendously positive effect on the read performance of the virtual machine by using local, low-latency, high-performance drives that don't have to traverse the storage network. It also works with VMFS, NFS, and even raw device mapping (RDM) disk devices, providing up to 200 GB (by default, but this can be expanded to 400 GB) of cache per VMDK.

If you are familiar with the feature introduced in vSphere 5.1 to swap to SSD, this is a replacement for and an extension of that feature. Both the ESXi host and the VMs can be configured to swap to the SSD instead of a datastore. vFRC is different from this swap-to-SSD functionality in it acts as a read cache specifically for the VMDKs that have been assigned. Be aware that when vMotioning a VM with vFRC enabled, you will need to specify what action to take with the cache: copy it to the new host or discard the cache.

Administering vFRC is relatively easy; it requires the web client and must be done on a per-VMDK basis. Doing so is tedious when you have a large number of hosts to enable and VMDKs to assign capacity for. To expedite the configuration of vFRC on the host, we have created a simple PowerShell function (Listing 5.5) that uses all of the available SSDs to create a single VFS filesystem on the host.

# LISTING 5.5 The Enable-VMHostvFRC function

```powershell
Enable-VMHostvFRC {
  # SYNOPSIS
  Enable vFlash Read Cache for a host.

  DESCRIPTION
  Function to enable vFRC on a host leveraging the available SSDs to create the VFS file system. Use all available SSDs as determined by the system.

  EXAMPLE
  Enable vFRC for a particular host
  Enable-VMHostvFRC -Host (Get-VM someVM)

  Use the pipeline to enable vFRC for a cluster
  Get-Cluster | Get-VM | Enable-VMHostvFRC

  PARAMETER VMHost
  The host to enable vFRC on.}

.INPUTS
[VMware.VimAutomation.ViCore.Impl.V1.Inventory.VMHostImpl]

.OUTPUTS
PSCustomObject

[CmdletBinding()]
param(
  [parameter(Mandatory=$true,ValueFromPipeline=$true)]
  [VMware.VimAutomation.ViCore.Impl.V1.Inventory.VMHostImpl]
$VMHost

process {
  # get views for the objects we will interact with
  $HostView = $VMHost | Get-View -Property ConfigManager.StorageSystem, ConfigManager.FlashManager
  $HostStorage = Get-View -Property $HostView.ConfigManager.StorageSystem
  $HostVflash = Get-View -Property $HostView.ConfigManager.FlashManager

  # get the device path for each of the available SSDs
  $availSSDs = $HostStorage.QueryAvailableSSDs() | Foreach-Object {
    $_.Value
  }

  # report if no SSDs were found
  if ($availSSDs -eq $null) {
    Write-Verbose "No available SSDs on host $($VMHost)"
  }
  try {
    # reconfigure to create the vFRC filesystem
    $task = $HostVflash.ConfigureResourceEx($availSSDs)

    # update the view to check the status
    $HostVflash.UpdateData("VFlashConfigInfo")

    # report the status
    $HostVflash.VFlashConfigInfo.VResourceConfigInfo
  } catch {
    Write-Error "Unable to assign available SSDs to new vFRC"
  }
}
```

First, let's determine the current settings for a VMDK. To do this, we have created a simple function (Listing 5.6). This can be used to quickly determine which VMDKs are using vFRC, what their allocation is, and what the cache settings.

# LISTING 5.6 The Get-HarddiskVFRC function

```powershell
function Get-HarddiskVFRC {
<.SYNOPSIS
    Get the status of vFRC for a virtual machine disk.

.DESCRIPTION
    Determines if vFRC is enabled for a VM hard disk. If enabled, will determine the settings and return them.

.EXAMPLE
    Get the vFRC status for a hard disk
    Get-HarddiskVFRC -Disk (Get-VM someVM | Get-VMHarddisk)

.EXAMPLE
    Use the pipeline to get the vFRC status for all hard disks in a vApp
    Get-vApp "My Application" | Get-VM | Get-VMHarddisk

.PARAMETER Disk
The disk to check vFRC status on.

.INPUTS
[VMware.VimAutomation.ViCore.Impl.V1.VirtualDevice.HardDisk]

.OUTPUTS
PSCustomObject
#>
[CmdletBinding()]
param(
  [parameter(
    Mandatory=$true,
    ValueFromPipeline=$true
  )]
  [VMware.VimAutomation.ViCore.Types.V1.VirtualDevice.HardDisk]
  $Disk
)
process {
  # get the owning VM based on the disk's parent id
  $parentVm = Get-VM -Id $Disk.ParentId

  # create an anon object to store vFRC relevant data
  $info = "" | Select-Object VM,DiskName,ReservationMB,CacheType,CacheMode,BlockSizeBytes,VFlashModule
  $info.VM = $parentVm.Name
  $info.DiskName = $Disk.Name

  # read the disk object's info and put it into our custom object
  if ($Disk.ExtensionData.VFlashCacheConfigInfo -ne $null) {
    $info.ReservationMB = $Disk.ExtensionData.VFlashCacheConfigInfo.ReservationInMB
    $info.CacheType = $Disk.ExtensionData.VFlashCacheConfigInfo.CacheConsistencyType
    $info.CacheMode = $Disk.ExtensionData.VFlashCacheConfigInfo.CacheMode
    $info.BlockSizeKB = $Disk.ExtensionData.VFlashCacheConfigInfo.BlockSizeInKB
    $info.VFlashModule = $Disk.ExtensionData.VFlashCacheConfigInfo.VFlashModule
  }

  $info
}
```
