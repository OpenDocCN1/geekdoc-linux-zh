## Updating a Baseline

Once you've created baselines, either static or dynamic, you can manipulate them and keep them up-to-date for any new requirements with the Set-Baseline cmdlet.

Let's take an example where the static baseline created earlier in the chapter for hosts contains a patch (ESXi550-2014001-BG) that causes issues in your organization. You now need to update your baseline to exclude this patch.

First, retrieve a new set of patches to manage the issue. Then, update the static baseline to remove this patch from the list of patches to be deployed, applying the updated set of patches to the baseline (Listing 14.6).

### LISTING 14.6 Updating patches in a baseline

```powershell
$UpdatedPatches = Get-Patch -TargetType -Vendor VMware* \
-Product 'embedded ESX 5.0.0' -After 2014-01-01 \
Where-Object {$_.IdByVendor -ne 'ESXi550-2014001-BG'} \
Get-Baseline -Name 'ESXi' -Current (Static) | \
Set-Baseline -IncludePatch $UpdatedPatches
```

The number of patches now present in this baseline is seven, one less than the previous:

`((Get-Baseline -Name 'ESXi' -Current (Static)').CurrentPatches).count`

Other properties or search criteria used to create baselines can also be modified using the Set-Baseline cmdlet.

## Attaching and Detaching Baselines

You have learned how to automate the creation of baselines, but they are not much until they are attached to a host or VM. To be able to scan a host or VM to discover what patches are required and subsequently deploy them, you must have one or more baselines attached. You can attach a baseline directly to a host or VM or allow it to be inherited from a parent object such as a cluster or datacenter.

The Attach-Baseline cmdlet is used to connect a baseline with a vCenter object. Although it is possible to attach a baseline directly to all hosts in a cluster, it is easier to attach the baseline at the cluster level and let the hosts inherit it. This means that any new hosts in the cluster will automatically inherit the correct baseline.

To attach a baseline at a cluster level, simply return the cluster object and attach the baseline to that object (Listing 14.7).

### LISTING 14.7 Attaching a baseline to a cluster

```powershell
Get-Cluster Cluster01 | Attach-Baseline -Baseline \
(Get-Baseline 'ESXi - Current (Dynamic)')
```

When a baseline is no longer required, use the Detach-Baseline cmdlet (Listing 14.8).

### LISTING 14.8 Detaching a baseline from a cluster

```powershell
Get-Cluster Cluster01 | Detach-Baseline -Baseline \
(Get-Baseline 'ESXi - Current (Dynamic)')
```

## Work with Upgrades and Patches

Now that you have patch baselines created and attached, either directly to hosts or via cluster and datacenter objects, it's time to look at how to deploy patches to hosts.

### Scanning a Host

To determine which patches a host needs to have installed, you must first scan it against an attached baseline(s). The Scan-Inventory cmdlet can accept pipeline input from the typical Get-VMHost Get-Cluster cmdlets, or in fact, the Get-Inventory cmdlet.

As with the VUM GUI, you have the option to specify the type of scan to carry out: host patch, host upgrade, VDS upgrade, VM patch (for backward compatibility), VM hardware upgrade, VM tools upgrade, and Virtual Application upgrade. In Listing 14.9, we scan all the hosts in Cluster01 for patch of previously attached baselines.

### LISTING 14.9 Scanning a cluster for hosts patches

```powershell
Get-Cluster Cluster01 | Scan-Inventory -UpdateType HostPatch
```

The obvious question that comes to mind after a scan complete is whether the hosts or VMs in question are compliant against the attached baselines. The Get-Compliance cmdlet can be used to retrieve this information. It returns results for any attached baseline. The example in Listing 14.10 retrieves compliance data for each of the hosts in Cluster01. Note that we use the -Detailed parameter to find out the exact number of patches required. Later in this chapter, we will use this cmdlet to produce a more extensive compliance report.
