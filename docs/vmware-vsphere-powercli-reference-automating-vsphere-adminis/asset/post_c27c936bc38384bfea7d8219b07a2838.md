# Alternative Method to the PowerShell Plug-in

There is no denying the fact that configuring the PowerShell plug-in, even within a lab environment, can be challenging at times with the various protocol and authentication methods available. Take this into a corporate environment with internal firewalls, security policies, and Windows operating systems and there is real scope for significant headaches. The note in the "Configuration" earlier in this chapter lists URLs that illustrate some of the hurdles that may encounter.

Additionally, once the configuration of the PowerShell plug has been completed there are further issues commonly experienced as difficulties with PowerShell Remoting multi-authentication and also with the use of external commands and PowerShell modules. Detailed discussion of these issues is beyond the scope of this book, but it is useful to have an alternative method in your toolbox faced with any of these challenges.

This section will demonstrate a method for using PowerShell within vRO without the PowerShell plug-in.

# Requirements

vRO and PowerShell have requirements for using PowerShell within vRO without the PowerShell plug-in:

- **vRO**: As mentioned earlier in this chapter, the alternative method is only available when vRO is installed on Windows, it's not available when using the vRO Linux-based appliance.
- **PowerShell**: v4 should be made available on the vRO Windows server.

# Configuration

The following elements need to be configured for the Alternative PowerShell method:

- **PowerShell**: Ensure that PowerShell has an execution policy that permits the running of scripts, as per the PowerShell plug-in configuration.
- **vRO**: For vRO do not need to make any configuration steps listed for vRO with the PowerShell plug-in. However, we need to make sure that vRO can execute local processes: Edit the file C:\Program Files\VMware\Orchestrator\app\server\vmo.properties to include:
```
com.vmo.js.allow-local-process=true
```
Restart both vRO services.

# Receiving a Return Code from a Local Script

For the alternative PowerShell method we need a new workflow for receiving a return code from a local script since we are not using a remote PowerShell host. We also need an updated version of Test-ReturnCode.ps1 script since, when using this alternative method, we need to use the exit keyword rather than the return keyword to pass the return code through vRO. Listing 21.12, Test-ReturnCode.ps1, contains updated code using the exit keyword.

## LISTING 21.12 Example of return codes: Test-ReturnCode.ps1

```powershell
param ($a)

try {
    $Random = Get-Random -Minimum 10 -Maximum 21

    Write-Host "Random number is $Random"

    $Result = $Random * $a

    Write-Host "Result is $Result"

    if ($Result -lt 40){
        Write-Host "Result is less than 40"
        exit 0
    } else {
        Write-Host "Result is greater than 40"
        exit 1
    }
} catch [Exception] {
    Write-Host "There was an error"
    exit 2
}
```
