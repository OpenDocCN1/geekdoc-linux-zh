This is quite handy, but let's expand a bit by exploring functions and reusing them across many scripts. Executing a script from a file works well, but quickly gets cumbersome to manage a directory of all code blocks that you want to reuse. You have seen functions throughout this book. They are an extremely convenient method of providing reusable code snippets across all your scripts. Let's create a simple function that will return all virtual machines from vCenter. Listing 25.3 shows the code for this function.

### 25.3 Sample function that returns all Windows machines
```powershell
function Get-WindowsVM {
  Get-VM | Where-Object {$_.Name -like "*windows*"} |
    Select-Object Name, NumCPU, MemoryGB |
    Sort-Object -Property MemoryGB -Descending
}
```

Saving this function to a PowerShell script allows you to have it available at any time, but you cannot execute it yet. Instead, you need to dotsource the script file. Dotsourcing a file is different than simply executing for one reason: when you execute code from a script, everything is destroyed and no longer accessible after the script ends, but when you dotsource the script, all its functions and variables remain accessible to the session that sourced it. This means that after the dotsource operation on the script file saved in Listing 25.3, your function is available to use. Listing 25.4 shows how to dotsource a script file and then execute the function that is contained in the file.

### 25.4 Dot-s a script file
```powershell
# dot source the file
.\vm_report.ps1

# execute the function
Get-WindowsVM
```

# Scheduling a Script

Sometimes you need an action to happen at a specific time, or after a certain event that you may or may not be present. Maybe you want to run a report every morning before you arrive, or you may want to schedule a check each time the server reboots. Regardless, these tasks are accomplished using the Windows Task Scheduler to execute PowerShell scripts at a configured interval.

To schedule a PowerShell script to be run by Windows, you can create the task like any other task. From the Computer Management console expand the Task Scheduler and browse to the Task Scheduler Library. Create a new basic task, give it a name, and set when it is executed. For example, you'll select Start A Program.

The program you want to execute is the PowerShell executable: powershell.exe. To specify which script you want to execute, in the Add Arguments field enter -file C:\path\script.ps1, where the latter part is the actual path to your script (see Figure 25.2).

Remember that you may need to adjust which user is executing the task to ensure that you have permissions to access the files and other resources that may be needed.

Alternatively, you can use PowerShell to create the scheduled task:

```powershell
# The action is what the scheduled task will execute
$action = New-ScheduledTaskAction -Execute "powershell.exe" \
-Argument "-File C:\path\script.ps1"
```

```powershell
# execute the task every day at a specific time
$trigger = New-ScheduledTaskTrigger -Daily -At 3am
```
