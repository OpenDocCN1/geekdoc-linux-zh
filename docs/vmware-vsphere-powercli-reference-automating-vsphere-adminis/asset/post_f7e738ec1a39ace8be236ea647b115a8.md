Let's take a closer look at the parameters that this method requires. (On screen, optional parameters have a red asterisk beside them.) Instead of passing an object, you can pass the `null` value.

The `testType` parameter requires an array of strings with the names of the tests that should be executed. But where can you find the tests? For such questions, it is always good to start with the enumeration types. Type **test** in the Quick Index field of Enumerated Types (Figure 18.10).

Now that we've solved the mystery of the test parameter, let's return our focus to the CheckMigrateTask method (see Figure 18.9). Attentive readers might have noticed that the CheckrateTask method apparently only handles vMotion. What seems to be confirmed by the reference to the MigrateVM_Task method. But what about SVMMotion?

In the first line of the parameters for the CheckMigrate_Task method, we notice the _this entry, which points to the managed object on which the method is called, VirtualMachineProvisioningChecker. When you go to the VirtualMachineProvisioningChecker object (Figure 18.13), it provides several methods. One is the CheckRelocate_Task method (Figure 18.14). That method seems to be intended to test the feasibility of the RelocateVM_Task—in other words, the SVMMotion task.

Walking the SDK documentation might seem complex, but rest assured it all links nicely together, and after your first scripts that use vSphere API, it will become a natural exercise.

## Use Managed Objects

### Managed Types

The Get-Datastore cmdlet returns an object for each datastore that is known in your session. Take a look at the VIOject the cmdlet returns. The object is a derived type off the base Datastore. Most of the VIObjects will have a name that ends with Im. That allows a script to recognize when an object comes from. You'll find yourself type-casting parameters on a function, but it also allows you to interpret the results returned by the GetType method (Table 18.4).

```
$dsImpl = Get-Datastore -Name DS1
$dsImpl.GetType()
```

TABLE 18.4 Results returned by the GetType method

| Characteristic | Return value |
|--- |--- |
| IsPublic | True |
| IsSerial | False |
| Name | DatastoreImpl |
| BaseType | VMware.Automation.ViCore.Impl.V1.DatastoreMan... |

Now, let's use the Get-View cmdlet to get the vSphere object. Notice that the object returned is a Datastore type. This object is documented in the vSphere API Reference under the Managed Object Types. (You'll remember that a VIOject contains a subset of all the available properties. The subset is a selection by the developers.)

```
$ds = Get-Datastore -Name DS1 | Get-View
$ds.GetType()
```

| IsPublic IsSerial Name | BaseType |
|--- --- --- |--- |
| True False Datastore | VMware.Vim.ManagedEntity |

As we said earlier, the VIOjects have a selection (defined by the PowerCLI Development Team) of properties and methods attached. You can use the Get-Member method to view their selection.
