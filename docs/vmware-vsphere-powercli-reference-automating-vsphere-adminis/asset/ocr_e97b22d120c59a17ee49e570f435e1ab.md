# Listing 7.13 Deploying a Linux guest from a template

```
$Template = Get-Template -Name 'Ubuntu4' `
$VMHost = Get-VMHost -Name 'vSphere' `
New-VM -Template $Template -Name 'WEB001' -VMHost $VMHost
```

Wait! That looks very similar to the Windows guest deployed in Listing 7.9. The only difference is the VM name and the template. Now let's add a customization specification and configure the postdeployment (see Listing 7.14).

# Listing 7.14 Using a customization spec to configure a Linux guest postdeployment

```
# Clone our Spec
$Spec = Get-CustomizationSpec 'Ubuntu4' `
New-CustomizationSpec -Name 'tmp01' -Type NonPersistent
# Update Spec with our desired IP information
Get-CustomizationNicMapping -Spec $Spec | `
Set-CustomizationNicMapping -IPMode StaticIP `
-IPAddress '192.168.2.145' `
-SubnetMask '255.255.255.0' `
-DefaultGateway '192.168.2.1' `
# Update updated Spec
$Spec = Get-CustomizationSpec -Name 'tmp01'
$Template = Get-Template -Name 'Ubuntu4'
$VMHost = Get-VMHost -Name 'vSphere' `
# Deploy VM
New-VM -Name 'WEB001' `
-VMHost $VMHost `
-Template $Template `
-OSCustomizationSpec $Spec | `
Start-VM
```

Again, this code looks almost identical to the code from Listing 7.11. That's one of PowerCLI's strengths: the scenes, VMware has built an amazing abstraction layer in guest customizations. PowerCLI takes that abstraction layer and abstracts it again. This means that it is either incredibly easy or difficult to perform guest customization. Either the guest is supported and it's a snap, or it's not and guest customization requires custom scripting. Fear not! With Invoke-VMScript, any custom work can be integrated in any PowerCLI script.
