# Interact with the Guest OS

From time to time, administrators need to interact with a guest operating system (OS). It could be simple, quick stuff like finding the letter of the CD-ROM drive in a Windows guest or discovering whether a Microsoft hotfix is installed on your system. Any number of guest OS-specific items may be required. Several options are available when you need to interact with the VM's guest OS. For instance, native tools like Windows Management Instrumentation (WMI), Secure Shell (SSH), or PowerShell Remoting let you interact with the guest, but these techniques might fail due to system policies or firewalls. In such situations, options are not reliable. PowerShellCLI contains some cmdlets to help in such instances. Before exploring what PowerShell has to offer, it may be helpful to briefly cover the guest's native tools. # USING NATIVE TOOLS

Guest native methods rely on an active network connection between the PowerShellCLI management station and the guest. Since these protocols require network connectivity, they can be blocked by any network or guest firewalls. However, blocking instances are increasingly rare. Scale-out management is a standard feature of all modern operating systems; the ports used by those protocols are well known and are part of any standard firewall rule set.

Obviously the PowerShellCLI method is the only method that doesn't require a connection from the PowerShellCLI management station to the guest and therefore is a uniform method that can be used in almost all cases. The only exception is when you happen to have an unsupported guest OS running that cannot run the VMware Tools package.
