As you can see, the faults that are returned are often cryptic. But, when you investigate the return code and display some of the Error properties, it will become a clearer to tell the script users (yourself) that something went wrong. In this instance, we supplied the MoRef for the correct Type of Managed Object to the entity property of the method. A quick review would reveal our mistake and a simple update to pass in the vSphere host's MoRef would result in a successful invocation.

+   Whenever you write a script, take a few moments to consider what could cause that script to throw an error. Spend a few minutes writing descriptive, decipherable error messages for each of those faults. You'll thank yourself when one of those faults occurs and you are in a position to rapidly troubleshoot and repair the problem.

# Waiting for an Asynchronous Task

In your scripts you can construct a simple loop to wait for the completion of asynchronous tasks. The following script shows one way to do this:

```
$taskMoRef = <any_call_to_an_asynchronous_method>
$task = Get-View $taskMoRef
while("running","queued" -contains $task.Info.State){
$task.UpdateData("Info")
Start-Sleep -Seconds 1
}
```

The script loops until the status of the task is no longer queued (waiting to run) or running. The script looks at a copy of the Task object, we had to refresh the Task object contents periodically. We used the UpdateData method and specified that only the Info property needed to be refreshed.
