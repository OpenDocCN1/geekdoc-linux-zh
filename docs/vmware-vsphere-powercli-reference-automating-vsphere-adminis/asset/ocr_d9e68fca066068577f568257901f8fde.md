In the past many would refer to any virtualized workload as a virtual application, or vApp, whereas others vApp to refer to a VM that has been exported to an Open Virtualization Format (OVF) template. As of vSphere 4.1, the term vApp has referred to a virtual container to a resource pool. A vApp can contain one or more VMs and is managed as a single logical unit. The modern vApp can be powered on or off and even cloned as a standard VM. vApps allow you to simplify complex applications by providing vSphere with valuable metadata about a group of VMs. For instance, within vSphere, you can capture the startup/shutdown sequence for a v farm. Then, simply power on or off the vApp and vSphere handles the rest. In this chapter you will learn to import appliances, create and manage vApps, and automate some of the more advanced vCenter features surrounding vApps.

# Import Virtual Appliances

2006, VMware opened the VMware Virtual Appliance Marketplace. The idea was that third-party developers could provide whole VMs preconfigured, thereby eliminating complex installers and simplifying the deployment of new applications. The Marketplace has proven to be a little hit or miss, but the concept itself has a smash hit. Virtual appliances have become mainstream, and virtually all software/hardware vendors offer them. vApps are distributed in either Open Virtual Appliance (OVA) or Open Virtualization File (OVF) formats. In reality, they are identical as any OVF contains a tape archive (TAR)-compressed copy of an OVF.

The installation of a vApp is straightforward. Simply download the zip file containing the OVA, or the self-contained OVA, and then import the appliance. This does bring a slight complication. Most OVA/OVF appliances contain configuration data that is used at the initial power-on to automatically configure the vApp. When importing through the vSphere web client, this is all done in one step, when importing from PowerShell you must first inspect the configuration data to determine the settings. This is accomplished with the Get-OvfConfiguration cmdlet. Listing 10.1 will read the metadata and return an object with all the configurable parameters in the OVF/OVA.
