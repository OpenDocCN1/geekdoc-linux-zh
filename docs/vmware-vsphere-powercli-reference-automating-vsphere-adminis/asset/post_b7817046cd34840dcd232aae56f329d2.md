### Working Without Host Profiles

That's all well and good, but what if you don't have access to host profiles? You're going to need a bigger script, most of which will be filled with code. You'll have a little storage, network, authentication, and so on. But wanting to be as complete as possible, I'll highlight a few cmdlets you'll find.

### NTP

When you're configuring NTP, you should know that the Add-VMHostServer cmdlet will do more than just set the NTP server. It can also enable and start the NTP service when it is stopped:

```powershell
Add-VMHostServer -NtpServer time.nist.gov `
-VMHost vSphere2.domain.local
```

### Syslog

Syslog can be configured only on ESXi. If you're running any consoles, use the Set-VMHostLogServer cmdlet to set up Syslog on vSphere:

```powershell
Set-VMHostLogServer -SyslogServer " "
-VMHost vSphere2.domain.local
```

### Root Password

You can change the root password using the Set-VMHostAccount cmdlet. You will have to connect directly to the host to do this:

```powershell
Connect-VIServer -Server vSphere2.admin.local `
-User root `
Set-VMHostAccount -User root -Password ""
```

### SNMP

SNMP has been around for ages and is a critical tool for monitoring. This is also a cmdlet that requires you to connect directly to the vSphere host.

#### Enabling SNMP

```powershell
Get-VMHostSnmp | Set-VMHostSnmp -Enabled $true
```

#### Configuring Communities

```powershell
Set-VMHostSnmp -ReadOnlyCommunity $communityName `
-HostSnmp (Get-VMHostSnmp)
```

#### Adding a Target

```powershell
Set-VMHostSnmp -TargetHost $sendTraps `
-TargetCommunity $sendCommunity `
-AddTarget `
-HostSnmp (Get-VMHostSnmp)
```

### Advanced Options

To optimize your infrastructure, you will eventually have to set an option or two—tasks easily performed via the Set-AdvancedSetting cmdlet. To enable vMotion, you run the following:

```powershell
Get-AdvancedSetting -Entity (vSphere2) \
-Name Migrate.Enabled | \
Set-AdvancedSetting -Value 1
```

You could configure a set of options all at once using a hash table to loop through the settings and apply the Set-AdvancedSetting cmdlet. For instance, to connect vSphere to NFS on a NetApp FS system, you run:

```powershell
@{
    'NFS.MaxVolumes' = 256
    'Net.TcpHeapMax' = 512
    'Net.TcpHeapSize' = 32
    'NFS.HeartbeatFrequency' = 12
    'NFS.HeartbeatTimeout' = 5
    'NFS.HeartbeatMaxFailures' = 10
    'NFS.MaxQueueDepth' = 64
}.GetEnumerator() | ForEach-Object {
    Get-AdvancedSetting -Entity (vSphere2) \
    -Name $_.Name \
    Set-AdvancedSetting -Value $_.Value
}
```

Using the cmdlets we have highlighted, and the automation workflow in the chapter, you can create a zero-touch installation for any environment. Now that you have both a zero-touch vSphere installation via Kickstart and a fully automated host configuration script, it's time to glue these together and deliver on the promise of a fully automated host provisioning lifecycle. To accomplish this, we adapted a technique originally documented by VMware. The general workflow looks like this:

1. Kickstart your vSphere host, configuring at a minimum management network.
2. As part of the first boot process, execute a small Python script that will "touch" a midwife host.
3. The midwife will be listening with a simple PowerCLI script and will execute our host configuration script when notified.

The PowerCLI script features a custom PowerCLI function, shown in Listing 2.15.

#### LISTING 2.15 The Trace-Port function

```powershell
function Trace-Port {
```
