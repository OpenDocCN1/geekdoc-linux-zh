# LISTING 5.14 Enabling FT

```
(Get-VM "HMIC").ExtensionData.CreateSecondaryVM_Task($null)
```

Optionally, you could designate VMHost the secondary VM is created by supplying the VMHost managed object reference, or MoRef (see Listing 5.15).

# LISTING 5.15 Specifying where the secondary VM should be created

```
$VMHost = Get-VM -Name 'vSphere01*'
$VM = Get-VM -Name 'HMVIC'
$VM.ExtensionData.CreateSecondaryVM_Task($VMHost.Id)
```

As we just showed, it's simple to enable FT. It's just as simple to disable, by Listing 5.16.

# LISTING 5.16 Disabling FT

```
$VM = Get-VM -Name 'HMVIC' | Where-Object {
$._ExtensionData.Config.FtInfo.Role -eq 1}
$VM.ExtensionData.TurnOffFaultToleranceForVM()
```

You will find that this highly protected state carries with some restrictions. For instance, you cannot modify any configuration or settings for the VM while protected with FT. You will need to follow these steps:

+   1. Disable FT on the VM.

+   2. Make the change (virtual hardware, SvMotion, vSphere vStorage API for Data Protection [VADP]).

+   3. Enable FT on the VM.

Fortunately, it's relatively easy to wrap the change in a PowerShell script. Listing 5.17, we demonstrate changing the RAM allocation on an FT-protected VM.

# LISTING 5.17 Modifying FT-protected VMs

```
Get the VM
$VM = Get-VM -Name 'HMVIC' | Where-Object {
$._ExtensionData.Config.FtInfo.Role -eq 1}
# Disable FT
# Add memory
Set-VM -VM $VM -MemoryMB 4096 -Confirm:$false
```
