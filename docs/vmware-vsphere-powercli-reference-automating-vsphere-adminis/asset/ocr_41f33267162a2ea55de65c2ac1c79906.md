# Creating Multiple Datastores from a Data Source

In course, using PowerCLI you can automate the creation of single or multiple datastores. The data used to create a datastore is supplied to you by a data source. Let's take a look at a couple of examples to show how you can save time and effort when the information to create the datastores is available from that source.

In the first example, your storage team has created some LUNs on a Fibre Channel SAN and has supplied you with the necessary details via a CSV file. The CSV file contains the HostID, LunID, and Identifier for each Lun. You agreed that it would be a good idea to include the HostIDs and LunIDs in the vSphere datastore naming. The CSV file looks like the one shown in Figure 4.1.

FIGURE 4.1 Fibre Channel LUN details

![](bbox=[0.265, 0.37, 0.905, 0.51])

You can use the standard PowerShell cmdlet Import-CSV to access the data source and then feed data into the New-Datastore cmdlet to create your datastores. You can also use the supplied HostIDs and LunIDs to build the name of the datastore each time, store that in the $Name variable, and use it with the Name parameter of New-Datastore (Listing 4.11).

# LISTING 4.11 creating Fibre Channel datastores from a data source

```
Import-CSV FibreLuns.csv | Foreach {$Name = 'Fibre_Host' + \
_.HostID + '_Lun' + $_.LunID; New-Datastore -Vmfs -VMHost \
veski05* -Name $Name -Path $_.Identifier }}
```
