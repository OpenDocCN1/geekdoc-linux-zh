This will result in output like that shown in Figure 25.3, depending on the status of the virtual machine.

There is rarely too much logging happening, especially when you are debugging or trying to find errors. We recommend when writing PowerCLI scripts you log as much as needed to determine the status of the script, and this is particularly important when you are executing the script from a scheduled task. Scheduled tasks do not store the console output, so you must write those logs to a location that can be accessed to verify the actions.

# # Commenting Code

Comments are a favor to the future. Writing scripts can be difficult. You are creating a script based on something that you know to do right now, because you have been trying to do it for a few minutes, hours, or even days. You know it completely, so you create a script to be able to do repeatedly, and distribute it to the other administrators in the organization so they can accomplish automated task with ease.

Time goes on, things happen, and at some point you have to revisit your script. Maybe new version of PowerCLI has been released, or an updated vSphere environment that necessitates an update to your script. Do you remember how it works? Do you remember you wrote the code to do a particular action another ways?

Commenting code is tedious. Maybe you look at your script and say to yourself, “I know exactly what’s happening here; I’ll never forget that!” But time has a way of making all of us forget these things. Putting in code is possibly the most essential part of creating a script. It makes the script supportable and maintainable, and ensures that you (or anyone else) can understand exactly what’s happening and, more importantly, it’s happening in your script.
