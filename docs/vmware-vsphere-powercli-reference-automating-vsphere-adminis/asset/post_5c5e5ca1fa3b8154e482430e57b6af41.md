The remediation of the script removed user vPiney_local from the list of users with DCUI access; the investigating that access has long since been completed, and we want to maintain "just enough access" to keep things more secure. Notice that setting this value wasn't additive but it overwrote the original value with the new value that we supplied, root. So, we effectively removed the given user by specifying the value of just the users we want to retain access. If normal lockdown mode is enabled, DCUI Access setting allows a list of highly trusted users to override lockdown mode and access the DCUI. Remediation might go the other direction, and require you to add users who need access through DCUI to the authorized lists. To do so, specify users who retain access as the value of - Value of Set-AdvancedSetting.

A related guideline, ESXI.audit-exception-users, deals with DCUI access as addressed in the previous guideline). Lockdown exception users do not lose their permissions when the host enters lockdown mode. The Hardening Guide assigns Audit Only action type to this guideline. The PowerShell commands provided in this guideline to report on the current lockdown exceptions for hosts write much of the data to the PowerShell console, whereas automated operations generally prefer objects (for further manipulation and consumption down the pipeline). The code in List 13.2 will get you such objects.

## 13.2 Get VMHost lockdown exceptions

```powershell
Get-View -ViewType HostSystem -Property Name,ConfigManager.HostAccessManager |
ForEach-Object {
$ThisHostSystem = $_ 
$ThisHostAccessMgr = Get-View -Id $_.ConfigManager.HostAccessManager
New-Object -Type PSObject -Property ([ordered])@{
    Name = $ThisHostSystem.Name
    LockdownException = $ThisHostAccessMgr.QueryLockdownExceptions()
    HostAccessManager = $ThisHostAccessMgr
    MoRef = $ThisHostSystem.MoRef
}
}
```

Listing 13.2 returns informational objects like the following:

Notice that these returned objects show that the myacct is in the lockdown exception list for two of our VMHosts. Auditing is handled for this guideline; you can easily export the resulting data to your favorite format—for example, CSV, XML, or JSON.

But if we need to remove this item and remove a lockdown exception? PowerCLI and the vSphere API are there for you, of course. Using the HostAccessManager object for a given ESXI System, you can run the UpdateLockdownExceptions method (which is why we returned HostAccessManager as a property for the output objects from Listing 13.2). Let's say that you assigned the objects returned by the code to $arrLockdownExceptionInfo. Now you can use that information to remove the exception from your user environment as:

```powershell
$arrLockdownExceptionInfo | Foreach-Object {
$_.HostAccessManager.UpdateLockdownExceptions($null)
}
```

Some environments might have a legitimate to have accounts in the lockdown exception list. For convenience, we created a function for setting lockdown exception users (see Listing 13.3).

## LISTING 13.3 Setting VMHost lockdown exception users

```powershell
function Set-VMHostLockdownException {
#.Description
Function to set the Lockdown exception users for a VMHost.
#.Example
Set-VMHostLockdownException -UserName dom\mySvcAcct
Set user as the only Lockdown exception for all VMHosts (effectively
removes other users)

.Example
Set-VMHost *dev.dom.int | Set-VMHostLockdownException -UserName dom\mySvcAcct2 -Append
Add given user to the lockdown list of users for targeted VMHosts
.Example
Set-VMHostLockdownException -UserName:$null -Id $arrHostSystems.MoreRef
Clear the list of Lockdown exception for users VMHosts from myCluster;
$arrHostSystems array Host View objects for the VMHosts in cluster "cluster", and accessing the MoreRef property of the array gives all of the HostSystems' MoreRefs as the value to -Id

PSObject with information about the new lockdown exceptions for given
VMHost

#
[CmdletBinding(SupportsShouldProcess=$true,
DefaultParameterName="VMHost")
```
```powershell
## User name(s) with which to update lockdown exceptions. Remove to all
## user exceptions, specify $null as the value. For Active Directory
## user, specify name in "domain\\user"
[Parameter(Mandatory=$true)][AllowNull()][string[]]$Username,
## VMHost for which to select lockdown exceptions. If not specified, will act
## all VMHosts
[Parameter(ValueFromPipeline=$true, ParameterSetName="VMHost")]
[VMware.Vim.Automation.ViewBase.Inventory.VMHost[]]$VMHost,
## ID of VMHost for which to select exceptions
[Parameter(Mandatory=$true, ValueFromPipeline=$true,
ParameterSetName="VMHostId")] [Alias("MoreRef", "Id")[VMware.Vim.ObjectReference[]]$HostId,
## Switch: append given user to existing list of exceptions? If not,
## replaces current list with specified user
[Switch]$Append
```
```powershell
begin {
$shParamForGetView = @{Property = "Name",
ConfigManager.HostAccessManager"}
}

process {
## get other params for Get-View for getting the desired HostSystems
Switch ($Cmdlet.ParameterName) {
"VMHost" {
if ($null -ne $VMHost) {$shParamForGetView["Id"] = $VMHost.Id}
## else, add param that will get all HostSystems
else {$shParamForGetView["View"] = "HostSystem"}
break
}
"VMHostId" {$shParamForGetView["Id"] = $HostId}
}
}
```
```powershell
## get the Host System objects for which make updates, then do it
Get-View @shParamForGetView | Foreach-Object {
$ThisHostSystem = $_
$ThisHostAccessMgr = Get-View -Id $_.ConfigManager.HostAccessManager
## make the list of LockdownexceptionsToSet = if ($Append) {
@($ThisHostAccessMgr.QueryLockdownExceptions()) + $Username
else {$Username}
```
```powershell
$strShouldProcessMsg = if ($null -eq $arrLockdownExceptSet) {
"Remove Lockdown exceptions"
} else {
"Set Lockdown exceptions to '$($arrLockdownExceptSet -join ', ')"
}

if ($Cmdlet.ShouldProcess "VMHost '$($ThisHostSystem.Name)',
  $strShouldProcessMsg) {
  try {
    ## update the Lockdown exceptions
    $ThisHostAccessMgr.UpdateLockdownExceptions($arrLockdownExceptSet)
    $arrNewLockdownExceptions =
      $ThisHostAccessMgr.QueryLockdownExceptions()
    ## return info object
    New-Object -Type PSObject -Property ([ordered])@{
      Name = $ThisHostSystem.Name
      LockdownExceptionUser =
        if ($arrNewLockdownExceptions.Count -ne 0) {
          $arrNewLockdownExceptions.MoRef
        }
    })
  } catch { Throw "encountered issue setting Lockdown exceptions for
    VMHost '$($ThisHostSystem.Name)'. The error: $_"
  }
}
```

> TIP While you can add lockdown exceptions, and may need to in certain cases, the API reference advises against doing so for human accounts. Human user access promises the promise of lockdown mode. For more information, see the VMware vSphere API reference page at
https://pubs.vmware.com/vsphere-60/index.jsp?topic=%2Fcom.vmware.wssdk.apiref.doc%2Fvim.HostAccessManager.html

So, robot accounts only, please—no humans allowed as a general rule—only when absolutely necessary.

You should be aware that the UpdateLockdownExceptions API method requires you to specify the full list of lockdown exceptions–it is not additive. The function in Listing 13.3 takes this into account, and provides for appending users by specifying the -Append switch parameter.

A possibly more handy feature (and more in keeping with tighter security), the Set-VMHostLockdownException function in Listing 13.3 makes it easy to empty the lockdown exception list. You can give the Null value to the -UserName parameter to do so. The result is similar to the direct API call to UpdateLockdownExceptions, but nicely encapsulated in a function that returns the resulting configuration.

```powershell
Set-VMHostLockdownException -UserName $null
```
