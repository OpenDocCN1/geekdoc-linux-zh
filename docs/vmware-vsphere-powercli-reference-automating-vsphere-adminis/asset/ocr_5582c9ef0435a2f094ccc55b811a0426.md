# ESXi Hosts

For the ESXi.* guidelines in the 6.0 Hardening Guide, there are several for which VMware has not yet provided assessment and/or remediation code. So, for these, we need to make our own assessment and remediation code. Of these guidelines, many requiring setting values for advanced settings of the ESXi hosts for remediation.

First, let’s look at the ESXi.set-dcui guideline. This item deals with the list of authorized users using Direct Console User Interface (DCUI). By using the Get-Set-AdvancedSetting cmdlets, you can assess and, as needed, remediate this advanced ESXi setting. DCUI Access. Listing 13.1 gives an example of assessing this setting, and remediating the to limit the DCUI access and keep the target VMHosts that much safer. Now you won't have to worry about potential attack vector, because we removed the extraneous access that was somehow left over when vPiney was doing testing and adding this access for his local account.

# LISTING 13.1 Assessing/remediating ESXi.set-dcui-access

| Entity | Name | Value |
| --- | --- | --- |
| desxi07.dom.int | DCUI.Access | vPiney_local, root |
| desxi08.dom.int | DCUI.Access | vPiney_local, root |

```
## remediate/remove user
Get-VMHost | Get-AdvancedSetting -Name DCUI.Access | Set-AdvancedSetting \
-Value root -Confirm:$false | Select-Object Entity,Name,Value
```
