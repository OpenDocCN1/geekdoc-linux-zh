# Working with Host Profiles

At this point, you have a fairly high level of automation in play. Let's bring it to the next level by leveraging host profiles. Keep in mind that you must have the Enterprise Plus license to take advantage of host profiles, but remember that you can use PowerShell to apply all the settings manually.

Most settings within host profiles have three possible settings:

+   * User Specified Setting Will Be Applied
* Prompt User If No Default Is Provided
* Use The Following When Applying

As shown in Figure 2.4, your selection within the host profile will determine how you script against. If you select User Setting Will Be Applied, you will always have to supply the setting. If you prompt User If No Default Is Provided, you should test whether a value is necessary before providing one. Finally, if you choose a static or dynamic value—that is, a static IP or DHCP—you don't have to provide a value. The interdependency mesh of host profiles led to a lot of confusion on the topic. We'll go over several techniques to show how to handle each scenario before we circle back and use host profiles in a vSphere host configuration.

+   1. Attach a profile.
2. Apply the profile and test only needed for needed values.
