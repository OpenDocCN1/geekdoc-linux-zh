Once the virtual machine is deemed useless, the snapshot can be removed using the Remove-Snapshot cmdlet.

```powershell
Get-Snapshot -VM VM001 -Name "Before Patch" | Remove-Snapshot
```

Or for multiple VMs, as just before, simply modify the Get-VM cmdlet and let pipeline do the rest:

```powershell
Get-VM Win* | Get-Snapshot -Name "Before Patch" |
  Remove-Snapshot
```

Whenever something goes wrong during a change to the VM, you can revert to the snapshot. Reverting to a snapshot is done using the Set-VM cmdlet:

```powershell
$snap = Get-Snapshot -VM VM001 -Name "Before Patch"
Set-VM -VM VM001 -Snapshot $snap -Confirm:$false
```

With the basics of snapshots established, it is time to discuss how to maintain snapshots in a larger environment.

## Maintaining Snapshots

The ability to create a snapshot is very useful, but it is critical to managing snapshots. Monitor them regularly to detect snapshots that are getting old and large. Fail to do so and datastores might run out of space.

To keep track of snapshots within the vSphere Web Client, you would need to check each VM to see how many snapshots have been created. This clearly doesn’t scale. A simple check for how much space was being used on a datastore by the snapshots could take hours (days). Other than going through the folder on each datastore, there is no easy way within the vSphere Web Client. PowerCLI, however, makes this very easy. The following code lists all the snapshots belonging to a VM and includes information about the size of the snapshots and the rate they were created:

```powershell
Get-VM | Get-Snapshot | Select VM, Name, SizeGB, Created
```
