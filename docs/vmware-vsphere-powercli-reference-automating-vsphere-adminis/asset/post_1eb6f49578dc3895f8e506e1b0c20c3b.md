
## Getting Started

Since the vRanger cmdlets are part of a PowerShell Snap-in, you can add them to your PowerShell session using the Add-PSSnapin cmdlet (Listing 11.5). Alternatively, a default install of vRanger places a vRanger Console in the Dell folder of the Windows Start Menu. Choosing this will open a PowerShell session with the vRanger cmdlets already loaded.

## LISTING 11.5 Adding vRanger.API to a PowerShell session

```powershell
Add-PSSnapin vRanger.API.PowerShell
```

Before you can start creating backup jobs, you must first connect vRanger to a source of servers. The product is capable of backing up VMs from VMware vCenter and Microsoft Hyper-V, as well as physical machines, and contains cmdlets for connecting to these source types. We will focus on the VMware vCenter.

## Connecting vRanger to vCenter

As part of connecting vRanger to vCenter, you will need a set of credentials to establish the connection and have permission to back up the intended machines. It is good practice to use a dedicated service account for this purpose and grant the permissions in vCenter that it will require. Then, use the AddVirtualCenter cmdlet (Listing 11.6) to make the connection.

## LISTING 11.6 Connecting vRanger to Credentials

```powershell
$vCenterCredentials = Get-Credential
Add-VirtualCenter -DNorIP vcenter01.sunnyydale.local -Username $vCenterCredentials.UserName -Password ($vCenterCredentials.GetNetworkCredential()).Password
```

## Create a Repository

You need a repository as a target for your backup jobs to store the backup data. vRanger 7.1.1 supports the following target types: Windows Share (CIFS), SFTP, FTP, NFS, NetVault SmartDisk (NVSD), EMC Data Domain Boost (DDB), and Dell Rapid Data Access (RDA). There are separate cmdlets for creating each type of repository. In Listing 11.7, we create an NFS repository to use as our backup job target.

## PROVID POWERSHELL SUPPORT FOR CORPORATE BACKUP APPLICATIONS

> TIP: When creating an NFS repository for vRanger, there is a requirement that the NFS contains a top-level folder for backup data storage. This folder must be pre-created on the NFS share prior to creating the vRanger repository.

## LISTING 11.7 Creating an NFS repository

```powershell
Add-NfsRepository -Name SynologyNFS -Server synology.sunydale.
  -ExportDirectory 'volume8/vRanger' -TargetDirectory Backups
```

## Retrieve an Entity from the Source Inventory

Another requirement for a backup job is to identify the VMs you wish to include part of the backup. vRanger allows you to supply these as any of vCenter objects: a vCenter Cluster, Datacenter, Folder, ResourcePool, Virtual Center, ESXi Host, or a specific list of VMs. An advantage of using a vCenter object such as a Cluster or Folder rather than a specific list of VMs is when the VMs contained within those objects change, there is no need to amend the backup job.

You can use the Get-InventoryEntity cmdlet to list the possibilities. Listing 11.8 demonstrates how to retrieve all VMs, specific VMs, all clusters, and a specific cluster. No filtering is done at the cmdlet level; the standard PowerShell cmdlet Where-Object must be used to filter the results appropriately. When it is time to create the backup job, use Get-InventoryEntity to supply the VMs or vCenter object to include.

## LISTING 11.8 Retrieving VMs and clusters as entities from the source inventory

```powershell
Get-InventoryEntity -Type VirtualMachine |
Get-InventoryEntity -Type VirtualMachine |
Where-Object {$_.Name -eq 'Server01'}
```

```powershell
Get-InventoryEntity -Type ClusterComputeResource
Get-InventoryEntity -Type ClusterComputeResource |
Where-Object {$_.Name -eq 'Cluster01'}
```

## Schedule

For our example backup job, we also need to create the schedule for the job will run. The vRanger Snap-in provides five cmdlets for creating a schedule depending on your requirements: New-DailySchedule, New-IntervalSchedule, New-MonthlySchedule, New-WeeklySchedule, and New-YearSchedule. Listing 11.9 demonstrates how to create a schedule for Monday–Friday, inclusive, starting at 8 p.m.

> NOTE: In Listing 11.9, notice that the days of the week be in a single string separated by commas. From a PowerShell usability perspective, you would typically expect to supply the days of the week as individual strings, so don't get tripped up by this.

## LISTING 11.9 Creating a Monday–Friday schedule

```powershell
$Schedule = New-WeeklySchedule -ExecutionDays \
'Monday, Tuesday, Wednesday, Thursday, Friday' -StartTime 20:00
```

## Backup Job Template

You now have all the elements in place required to create a backup job template. Listing 11.10 creates a backup job for all VMs in the Cluster Cluster01, stores the data in the SynologyNFS repository, and uses the schedule created in Listing 11.9. There are a multitude of other options for creating a backup job; a few are used in Listing 11.10. However, it is well worth checking the help for Add-BackupJobTemplate to see what is available.

## LISTING 11.10 Creating a backup job template

```powershell
$ClusterEntity = Get-InventoryEntity -Type ClusterComputeResource | Where-Object {$_.Name -eq 'Cluster01'}
Add-BackupJobTemplate -Cluster $ClusterEntity -Repository SynologyNFS -Schedule $Schedule
```

## Multiple Backup Templates

Creating a single backup template in PowerShell is not necessarily going to save time over the GUI. However, when you create multiple backup templates, that's when time savings can be seen.

## LISTING 11.1 Creating multiple backup templates (from later context)

```powershell
$Clusters = 'Cluster01', 'Cluster02', 'Cluster03', 'Cluster04', 'Cluster05'
$Repository = Get-Repository -Type NFS | Where-Object {$_.Name -eq 'SynologyNFS'}
$InitialStartTime = [DateTime]"20:00"
$i = 0
foreach ($Cluster in $Clusters) {
  $ClusterEntity = Get-InventoryEntity -Type ClusterComputeResource | Where-Object {$_.Name -eq $Cluster}
  $BackupTime = $InitialStartTime.AddHours($i)
  $Schedule = New-WeeklySchedule -ExecutionDays 'Monday, Tuesday, Wednesday, Thursday, Friday' -StartTime $BackupTime
  Add-BackupJobTemplate -Name "Backup-$Cluster" -Cluster $ClusterEntity -Repository $Repository -Schedule $Schedule
  $i++
}
```

## Restore Job Template

To restore a VM from a backup with vRanger, you need to create a restore template. This can be done via the Add-RestoreTemplate cmdlet. Every time vRanger backup run, a Savepoint is created for each VM, and depending on the backup job configuration, it is possible to store multiple numbers of Savepoints per VM. For a restore template, you need to identify the Savepoint—first by VM and then by time.

Listing 11.2 creates a restore template for a VM named Server01 that uses the most recent Savepoint in the SynologyNFS repository and does not overwrite the Server01 VM, but rather creates a VM with a new name—an exercise, for example, you might go through test the validity of a backup.
Using the -RunJobNow parameter, you kick off an immediate restore. With Add-BackupJobTemplate, it is worth checking the help for Add-RestoreTemplate; that there are multiple of options that can use to configure a restore job.

## LISTING 11.2 Creating a restore template

```powershell
$Repository = Get-Repository -Type NFS | Where-Object {$_.Name -eq 'SynologyNFS'}
$RestoreSavepoint = Get-RepositorySavepoint $Repository.id | Where-Object {$_.VMName -eq 'Server01'} | Sort-Object StartTime | Select-Object -Last 1
Add-RestoreTemplate -Name "Restore-Server01" -Savepoint $RestoreSavepoint -VMName Server01_Restore -RunJobNow $true
```

## Veeam

Veeam is a vendor known for their backup and replication software for virtual machines. By leveraging the virtual environment and Veeam vPower technology, Veeam always seems to be on the forefront of backup technologies, introducing new and innovative ways to not only up the virtual environment but also restore. They have several methods that ensure each of the backups created can be 100 percent guaranteed to restore. With Veeam Backup & Replication (VBR) you can instantly recover a VM directly from a backup file, restore individual objects (email messages, database records, files, etc.) from any virtualized application or filesystem, verify the recoverability of every backup, and provide near-continuous data protection for any application.
