To change the number of vCPU shares, uses the -CpuSharesLevel parameter. Possible enumeration values are Custom, High, Low, and Normal. Because this accepts an enumerator value, you can also specify an index value from 0 to 3, where index value 0 means Custom, 1 means High, 2 means Low, and 3 means Normal. Table 8.2 contains an overview of the available CPU shares. To fine-tune the shares level beyond the factory presets (High, Low, and Normal), set the share level to Custom and specify the number of shares with the -CpuShares parameter.

# TABLE 8.2 CPU shares

| Shares | Shares/vCPU | Index |
|---|---|--|
| Custom | 1,100,000 | 0 |
| High | 2,000 | 1 |
| Low | 500 | 2 |
| Normal | 1,000 | 3 |

To set a vCPU share for High, use the following:

```
Get-VM VM001 | Get-VMResourceConfiguration | Set-VMResourceConfiguration -CpuSharesLevel "High"
```

Resource limits, both CPU and memory, are real performance killers. Memory limits cause the affected VM to start ballooning and swapping in almost all cases. How to generate a report containing all VMs that have CPU and memory limits is covered in Chapter 15, "Reporting and Auditing."

With the primary resources of CPU and memory entitlement configured, it's time to move on to the VM's networking hardware.
