## Use Case

In this section, we will look at a use case for PowerShell as well as the alternative method for vRO (and explain how to go implementing).

## Active Directory User Accounts

Working on virtualization automation projects regularly requires interaction with Microsoft Active Directory (AD). Whether it's manipulating AD with vCenter permissions, creating AD computer accounts for newly deployed VMs, or creating AD user accounts for new employees within an organization, it's a common integration point. vRO ships with an Active Directory plug-in that will meet many of your requirements. However, as of writing, there are a few restrictions with the plug-in. vRO PowerShell integration may be required to fill in some gaps. Specifically, these restrictions with the AD:

- To be able to carry out some AD tasks, as creating an AD Enabled User account, the connection between vRO and AD must use SSL.
- Only a single AD domain is supported.
- Only a single domain controller within the domain is supported. If the domain controller is unavailable for any reason, any workflows it will fail.

![](img/62596f5acc979040608a4e5111beb7d6_787_0.png)

> Version 2 of the AD plug-in is expected to remove the restrictions on the AD domain and single domain controller. However, this example is primarily here to illustrate how PowerShell can be used to fill a potential gap in any plug-in.

The Microsoft Active Directory PowerShell module is not affected by any of those restrictions. Consequently, it can be used in combination with the vRO PowerShell alternative method to meet scenarios affected by the restrictions, without needing 

## ALTERNATIVE METHOD TO THE POWERSHELL PLUG-IN

to worry about any multipath authentication issues that may be encountered with the vRO PowerShell plug-in.

In this case, we will create a vRO workflow using PowerShell plug-in that maps to the functionality of the Create A User With A Password In Organizational Unit workflow that is part of the vRO Active Directory plug-in.

## Requirements

Ensure that the vRO Windows server has been configured for executing local processes and that the Microsoft AD PowerShell module has been installed and available on it. For use, the vRO server should be joined to the Windows domain where the user account needs to be created.

![](img/62596f5acc979040608a4e5111beb7d6_788_0.png)

> NOTE The AD PowerShell module is available to be installed on most recent Windows operating systems and for clients via Remote Administration tools. For Windows Servers 2012 R2, it can be installed via RSAT. Ensure credentials are available to connect to AD and create user accounts in the desired organizational unit (OU). You need a PowerShell script to create the AD user account. The following code use to achieve this and send back return codes based on the outcome.

## Active Directory User Account Script

```powershell
<#
SYNOPSIS
Create AD User for vRO with Return Codes
DESCRIPTION
Create AD User for vRO with Return Codes
PARAMETER FirstName
The FirstName of the User
PARAMETER Surname
The Surname of the User
PARAMETER OU
The Organization Unit to create the User in
PARAMETER Username
The Username to connect to Active Directory
PARAMETER Password
The Password to connect to Active Directory
.INPUTS
None
.OUTPUTS
None
#>
[CmdletBinding()]
Param(
    [Parameter(Mandatory=$true)][ValidateNotNullEmpty()]
    [string]$FirstName,

    [Parameter(Mandatory=$true)][ValidateNotNullEmpty()]
    [string]$Surname,

    [Parameter(Mandatory=$true)][ValidateNotNullEmpty()]
    [string]$OU,

    [Parameter(Mandatory=$true)][ValidateNotNullEmpty()]
    [string]$Username,

    [Parameter(Mandatory=$true)][ValidateNotNullEmpty()]
    [string]$Password
)

# Import the Active Directory Module
try {
    if (-not (Get-Module ActiveDirectory )) {
        Import-Module ActiveDirectory -ErrorAction Stop | Out-Null
    }
    Write-Host "Successfully imported the Directory Module"
} catch [Exception] {
    Write-Host "Unable to import the Directory Module"
    exit 2
}

# Generate a random password for the User Account
try {
    Add-Type -AssemblyName System.Web
    $Password = ''
    while ($Password -NotMatch '\d+') {
        $Password = [Web.Security.Membership]::GeneratePassword(8,0)
    }
    Write-Host "Successfully created a random password"
} catch [Exception] {
    Write-Host "Unable to create a random password"
    exit 3
}

# Create AD Credential and Forest objects
try {
    $ADPasswd = ConvertTo-SecureString $Password -AsPlainText -Force
    $ADCredential = New-Object System.Management.Automation.PSCredential($Username, $ADPasswd)
    $Forest = (Get-ADDomain -Credential $ADCredential -ErrorAction Stop).Forest
    Write-Host "Successfully created AD Credential and Forest objects"
} catch {
    Write-Host "Unable to create AD Credential and Forest objects"
    exit 4
}

# Create Username, DisplayName and Principal Name
try {
    $Username = $FirstName.ToLower() + "." + $Surname.ToLower()
    $DisplayName = $FirstName + " " + $Surname
    $PrincipalName = $Username + "@" + $Forest
    Write-Host "Successfully created Username, $Username, DisplayName $DisplayName and Principal Name $PrincipalName variables"
} catch {
    Write-Host "Unable to create Username, DisplayName and Principal Name variables"
    exit 5
}

# Check for existing user account
try {
    $User = Get-ADUser -Identity $Username
    Write-Host "User Account $UserName already exists"
    exit 6
} catch {
    Write-Host "User Account $UserName does not already exist"
}

# -- Create AD User Account
try {
    New-ADUser -GivenName $FirstName -Surname $Surname \
      -SamAccountName $username -UserPrincipalName $PrincipalName \
      -Name $DisplayName \
      -Path $OU -AccountPassword \
      (ConvertTo-SecureString $Password -AsPlainText -Force) \
      -Enabled $true -ChangePasswordAtLogon $true -Credential \
      $ADCredential -ErrorAction Stop
    Write-Host "Successfully created AD Account $UserName"
    exit 0
} catch {
    Write-Host "Unable to create AD User Account $UserName"
    exit 1
}
```
