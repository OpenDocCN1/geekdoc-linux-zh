# Managing Customization Specifications

That's not to say there's a need to automate customization specifications. On the contrary, PowerCLI is recommended for all maintenance tasks. For example, if an organization added a new DNS server, adding that to the existing specifications involves one line of code in PowerCLI.

```
Get-OSCustomizationSpec | 
Set-OSCustomizationSpec -DnsServer 192.168.1.2, 192.168.1.6
```

PowerCLI is adept at credential management. Most organizations require all administrative credentials to be updated quarterly a month. All too often, this task is ignored because it is deemed too difficult. Well, in PowerCLI maintaining a password is simple. Listing 7.3 updates the account to add machines to the domain. There may be other accounts used in other specifications for delegated domains or organizational units, the script first filters the OS customizations to only update the specifications using the specified account.

+   LISTING 7.3 Updating the credentials within all existing specifications

```
$Credentials = Get-Credential glnsize@vsphere.local 
Get-OSCustomizationSpec | 
Where {$_.DomainUsername -eq $Credentials.UserName} | 
Set-OSCustomizationSpec -DomainCredentials $Credentials
```

Maintaining the guest password is a snap. It is perfectly valid to choose to omit the guest password completely or generate a random password for each new guest. However, if a common password is used for the local administrator account, that password needs to be updated regularly—another complicated task that is simplified with PowerCLI, as seen in Listing 7.4.

+   LISTING 7.4 Updating the local admin user within all existing specifications

```
Get-OSCustomizationSpec | 
Where-Object {$_.OSType -eq 'Password'} | 
Set-OSCustomizationSpec -AdminPassword 'P33kBB00!'
```

It is also possible to clone an existing customization specification. For example, Listing 7.5 takes an existing specification for a Windows 2012 R Server and creates a new spec that can be used to deploy Server 2012 R Core with IIS. This is accomplished by adding a RunOnce command to the install IIS.
