## Configuring an iSCSI Target

Neither local iSI nor Fibre Channel requires any automation configuration from POWERCLI at the adapter level, but you can automate the configuration of the iSCSI connection. If you do not have a hardware iSCSI HBA and are planning to use the built-in software iSCSI adapter, you must first enable it, which is disabled by default. To enable this adapter for all hosts in Cluster01, use the code in Listing 4.1.

### Listing 4.1 Enabling iSCSI software adapter for all hosts in a cluster

```
Get-Cluster Cluster01 | Get-VMHost | Get-VMHostStorage
Set-VMHostStorage -SoftwareSCSIEnabled=$true
```

Your next task is to create an iSCSI target for each host using the New-iSCITarget cmdlet. This has many parameters, but the only required is one of the iSCSI target. If your organization requires the Challenge Handshake Authentication Protocol (CHAP), you will need to set specific parameters from the eight CHAP-related parameters available. You may also have to change the network port from the default of 3260 and give that a name.

In Listing 4.2, you will create a dynamic iSCSI target with an IP address of 17.20.0.10 configure CHAP parameters. Note that for each host returned in the cluster, you use the Get-VMHostHba cmdlet with the parameter and iSCSI value to ensure that you configure the iSCSI adapter.

### LISTING 4.2 Adding an iSCSI target

```
Get-Cluster Cluster01 | Get-VMHost | ForEach-Object { $_ `
Get-VMHostHba -Type iSCSI | New-IScsiHbaTarget ` \
-Address 172.0.0.10 -ChapType Preferred -ChapName iSCSI ` \
-ChapPassword Password0115}
```

## Configuring the iSCSI Binding

The iSCSI adapter needs to be bound to at least one VMkernel port that to be used for iSCSI traffic—typically two would be used for redundancy. Chapter 3 demonstrates how to add a VMkernel port for iSCSI.

> NOTE It is important to ensure that a port group designated for use iSCSI has only one adapter marked as Active. Otherwise, it will not be possible to bind it to the iSCSI adapter.

![](img/62596f5acc979040608a4e5111beb7d6_153_0.png)

As of the 6 release, PowerCLI does not contain cmdlets for managing iSCSI binding. The functions Get-VMHostiSCSIBinding and Set-VMHostiSCSIBinding in Listing 4.3 and Listing 4.4 use of PowerCLI's ability to take the functionality of vSphere's command-line tool escli and use it for this purpose.

Get-VMHostiSCSIBinding -VMHost ESXI01,ESXI02 -HBA "vmhba32"

}

foreach ($ESXiHost in $VMHost){
try {
if ($ESXiHost.GetType().Name -eq "string") {
try {
$ESXiHost = Get-VMHost $ESXiHost -ErrorAction Stop
}
catch [Exception]{
$ErrorText = "VMHost ESXiHost does not exist"
}
}

$ErrorText = "You did not pass a string or a VMHost object"

}

try {
$iSCSIHBA = $ESXiHost |
Get-VMHostHba -Device $HBA -Type iSCSI -ErrorAction Stop
}

}

throw
