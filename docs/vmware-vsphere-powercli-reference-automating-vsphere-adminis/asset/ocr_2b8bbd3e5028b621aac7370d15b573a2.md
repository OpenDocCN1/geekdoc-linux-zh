# LISTING 7.16 Update VM hardware version

```
$VM = Get-Template "W2K8R2" | Set-Template -ToVM
$VM.ExtensionData.UpgradeVM("vmx-11")
Set-VM -VM $VM -ToTemplate
```

As tasks, this is easy. Get the template object and convert it into a VM. Then, call the UpgradeVM method on the virtual machine to perform the upgrade. Finally, convert the VM back into a template. There is one problem, though: VMware requires that a current version of the VMware Tools be installed prior to upgrading a VM’s hardware version—which means forcing the upgrade (which is dangerous) or handling the tools upgrade as well (which is complicated). The script in Listing 7.17 forces the Tools upgrade and upgrades the hardware version in one action.

# LISTING 7.17 Forcing a VM hardware upgrade

```
$VM = Get-Template "vm01" | Set-Template -ToVM
$taskMoreRef = $vm.ExtensionData.UpgradeVM_Task("vmx-11")
$task = Get-View $taskMoreRef
while ($task.Info.State -eq 'running')
{
    $task.UpdateView("Info.State")
    $Question = Get-VMQuestion -VM $VM
    {
        Answer-VMQuestion $Question -DefaultOption -Confirm:$false
    }
}
Set-VM -VM $VM -ToTemplate -Confirm:$false
```

There are scenarios where it makes sense to force an upgrade. For example, if the template didn’t have an operating system or the VMware Tools weren installed in the template, there is no choice but to force the upgrade. This situation would be an edge case. Best practice is to always have VMware Tools installed, and a template will almost always have an operating system.
