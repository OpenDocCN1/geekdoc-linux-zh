
# Managing Customization Specifications

That's not to say there's a need to automate customization specifications. On the contrary, PowerCLI is recommended for all maintenance tasks. For example, if an organization added a new DNS server, adding that to the existing specifications involves one line of code in PowerCLI.

```powershell
Get-OSCustomizationSpec | 
Set-OSCustomizationSpec -DnsServer 192.168.1.2, 192.168.1.6
```

PowerCLI is adept at credential management. Most organizations require all administrative credentials to be updated quarterly month. All too often, this task is ignored because it is deemed too difficult. Well, in PowerCLI maintaining a password is simple. Listing 7.3 updates the account to add machines to the domain. There may be other accounts used in other specifications for delegated domains or organizational units; the script first filters the OS customizations to only update the specifications using the specified account.

- LISTING 7.3 Updating the credentials within all existing specifications

```powershell
$Credentials = Get-Credential glnsize@vsphere.local 
Get-OSCustomizationSpec | 
Where {$_.DomainUsername -eq $Credentials.UserName} | 
Set-OSCustomizationSpec -DomainCredentials $Credentials
```

Maintaining the guest password is a snap. It is perfectly valid to choose to omit the guest password completely or generate a random password for each new guest. However, if a common password is used for the local administrator account, that password needs to be updated regularly—another complicated task that is simplified with PowerCLI, as seen in Listing 7.4.

- LISTING 7.4 Updating the local admin user within all existing specifications

```powershell
Get-OSCustomizationSpec | 
Where-Object {$_.OSType -eq 'Password'} | 
Set-OSCustomizationSpec -AdminPassword 'P33kBB00!'
```

It is also possible to clone an existing customization specification. For example, Listing 7.5 takes an existing specification for a Windows 2012 R Server and creates a new spec that can be used to deploy Server 2012 R Core with IIS. This is accomplished by adding a RunOnce command to the install IIS.

# USE CUSTOMIZATION SPECIFICATIONS

# LISTING 7.5 Copy specification to create a custom IIS specification

```powershell
Get-OSCustomizationSpec -Name 'Win2012R2' |
  New-OSCustomizationSpec -Name 'Win2012R2_IIS' |
  Set-OSCustomizationSpec -AutoLogonCount 1 |
  -GuiRunOnce 'cmd /C PowerShell.exe -Command "Add-WindowsFeature \
  Web-Server -IncludeAllSubFeature -IncludeManagementTools \
  -Restart"'
```

> NOTE The GuiRunOnce component within a customization specification has caused much confusion over the years. Remember, when it comes to a Windows machine, Sysprep is doing all the work—VMware is merely automating Sysprep. Therefore, the RunOnce component from Sysprep is not using any integration to automate the process. If you are having issues using the RunOnce component, see Sysprep's documentation at https://microsoft.com/en-us/library/cc76604928v-vs.1029.aspx. PowerShellCLI is just the facilitator in this transaction.

# Using Customization Specifications

There are two ways to use an OS customization specification:

- Apply it to an existing powered-off VM.
- Attach to a template deployment.

Now, let's stick to using a powered-off machine. Although it's not well known, it is possible to use the Set-VM cmdlet to apply customization specifications to any guest, as long as that meets the minimum requirements described earlier.

The Set-VM cmdlet -OSCustomizationSpec parameter was intended to apply a customization specification to a cloned VM. However, there is nothing preventing it from being used on demand. Listing 7.6 uses a customization specification to change both the network adapter settings and the domain membership of an existing VM.

# LISTING 7.6 Employing customization specifications on demand

```powershell
# Save the credential object with permission to join the domain.
$DomainCredentials = Get-Credential glnsize@vSphere.local
```

# CHAPTER 7 • USING TEMPLATES AND CUSTOMIZATION SPECIFICATIONS

```powershell
# Clone the Spec adding the domain information.
$Spec = Get-OSCustomizationSpec 'Win2012R2' | \
New-OSCustomizationSpec -Name 'tmp01' -TypeNonPersistent \
Set-OSCustomizationSpec -Domain vSphere.local ` \
-DomainCredentials $DomainCredentials
```

```powershell
# Update Spec with the new VLAN's IP information
Get-OSCustomizationNiMapping -Spec $Spec | \
Set-OSCustomizationNiMapping -IPMode UseStaticIP \
-IPAddress '10.1.5.4' ` \
-SubMask '255.255.255.0' ` \
-DefaultGateway '10.1.5.1' ` \
-Dns '192.168.2.8','192.168.2.1'
$Spec = Get-OSCustomizationSpec 'tmp01'
```

```powershell
# Get the VM
$VM = Get-VM -Name App04
# Shutdown guest to make change.
Stop-VMGuest -VM $VM -Confirm:$false
# Wait while guest shuts down
While ((Get-VM $VM).PowerState -ne 'poweredOff') {
Start-Sleep -Seconds 1
}
# Change network settings
# Requires the VMware.VimAutomation.Vds module to be loaded
$vDSPG = Get-VdPortgroup -Name VLAN100 | \
$VM | \
Get-NetworkAdapter \
Set-NetworkAdapter -PortGroup $vDSPG -Confirm:$false \
Out-Null
```

```powershell
# Apply customization Spec to apply new network settings
$VM | Set-VM -OSCustomizationSpec $Spec -Confirm:$false \
Start-VM
```

Customization specifications are a tool just like any other component of vSphere. With PowerCLI, you can apply that tool to whatever, wherever, whenever need be!

# Use Templates

A template is a VM that has been placed in a protected, read-only state to be used as a master copy for subsequent virtual machine creation and provisioning tasks. Once a VM has been converted into a template, it cannot be modified.

# Creating Templates

With the fundamentals of templates, there are two ways to create a template:

- Convert the VM into a template.
- Clone the VM.

The decision of which method to use is simple. Is the source VM needed for anything? If the answer is yes, then clone the source VM. For example, a web team just finished a new server and wants to use it for upcoming deployment. We'll show the conversion to a template in Listing 7.7.

# LISTING 7.7 Converting a VM to template

```powershell
Get-VM WEBXX | Set-VM -ToTemplate
```

# LISTING 7.8 Cloning a VM to template

```powershell
$VM = Get-VM WEB02
$Folder = Get-Folder
New-Template -Name 'WEBMaster' -VM $VM -Location $Folder
```

# CHAPTER 7 • USING TEMPLATES AND CUSTOMIZATION SPECIFICATIONS

> NOTE Prior to Virtual Center 2.5 update 2, you had to power off the virtual machine to clone to a template. Every version since then simply takes a snapshot and clones from that if the VM is powered on. Although this approach works, it might not result in a usable template, so proceed with caution.

The latest release of vSphere came a new construct called a content library. Content libraries provide a centralized store to hold Open Virtualization Format (OVF), template, and International Organization for Standardization (ISO) files. When a template is stored in the content library, the library can handle replication between vCenter instances. Unlike traditional templates, a template stored in a content library is stored as an OVF file. This means that it cannot be easily converted back to a VM without being deployed. Although this new capacity has massive potential, as of writing it has not been fully integrated into PowerCLI. The content library itself can be managed, but VM provisioning are not enabled in the built-in cmdlets.

The truth about templates is that they are only as good as the source VM—which means all the hard work is done up in guest.

# Deploying Guests from Templates

With the required templates pre-staged, it's time to deploy some guests. Deploying from a template is a clone operation, and is accomplished in Chapter 6, "Creating Virtual Machines," is accomplished via the New-VM cmdlet. The short script in Listing 7.9 deploys a web server from the Windows 2012 R2 template to Listing 7.1.

# LISTING 7.9 Deploying a guest from a template

```powershell
$Template = Get-Template -Name 'WS2012R2'
$VMHost = Get-VMHost -Name 'vSphere'
$New-VM -Template $Template -Name 'WEB001' -VMHost $VMHost
```
