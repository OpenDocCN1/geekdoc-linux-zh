# OPTIMIZE STORAGE USAGE WITH THIN PROVISIONING

Unused space can be reclaimed by converting the virtual disk to. You can accomplish this by using vMotion or by converting the virtual disk in place.

# Converting a Virtual Disk Using vMotion

Converting a thick virtual disk to a thin-provisioned virtual disk, or vice versa, can be accomplished by moving the disk to another datastore using storage vMotion. Because vMotion creates a new copy of the hard disk on the destination volume, it is achieved using the Move-HardDisk cmdlet and specifying the new datastore with the -Datastore parameter and the new disk type with the -DiskType parameter. The following code uses vMotion to move all virtual disks on virtual machine VM001 to datastore Datastore02 and converts them to thick disks on the fly:

![](bbox=[0.91, 0.223, 0.978, 0.373])

```
Get-VM VM001 | Get-HardDisk | Move-HardDisk \
  -Datastore Datastore02 -StorageFormat Thin
```

To convert a single hard disk on VM, simply specify the -Name parameter. The following code uses storage vMotion to move only Hard disk 2 on virtual machine VM001 and converts it to thin provisioning on the fly:

```
Get-VM VM001 | Get-HardDisk -Name "Hard disk 2" | \
  Move-HardDisk -Datastore Datastore02 -StorageFormat Thin
```

# Converting a Virtual Disk in Place

If faced with one datastore and unable to utilize storage vMotion, you can convert a virtual disk in place. Do so by copying the virtual disk and reconfiguring the virtual machine to use the new copy. This method has some drawbacks:

+   - The workflow actually replaces the virtual disk with a cloned copy, the virtual machine must be powered off.

+   - There be enough free space on your datastore to store the copy of the virtual disk.

+   - For the Copy-HardDisk cmdlet to work, the disk must be connected directly to an ESXi host.
