If you are familiar with the feature introduced in vSphere 5.1 to swap to SSD, this is a replacement for and an extension of that feature. Both the ESXi host and the VMs can be configured to swap to the SSD instead of a datastore. vFRC is different from this swap-to-SSD functionality in it acts as a read cache specifically for the VMDKs that have been assigned. Be aware that when vMotioning a VM with vFRC enabled, you will need to specify what action to take with the cache: copy it to the new host or discard the cache.

Administering vFRC is relatively easy; it requires the web client and must be done on a per-VMDK basis. Doing so is tedious when you have a large number of hosts to enable and VMDKs to assign capacity for. To expedite the configuration of vFRC on the host, we have created a simple PowerShell function (Listing 5.5) that uses all of the available SSDs to create a single VFS filesystem on the host.

# LISTING 5.5 The Enable-VMHostvFRC function

```
Enable-VMHostvFRC {
  # SYNOPSIS
  Enable vFlash Read Cache for a host.

  DESCRIPTION
  Function to enable vFRC on a host leveraging the available SSDs to create the VFS file system. Use all available SSDs as determined by the system.

  EXAMPLE
  Enable vFRC for a particular host
  Enable-VMHostvFRC -Host (Get-VM someVM)

  Use the pipeline to enable vFRC for a cluster
  Get-Cluster | Get-VMHost | Enable-VMHostvFRC

  PARAMETER VMHost
  The host to enable vFRC on.}
```
