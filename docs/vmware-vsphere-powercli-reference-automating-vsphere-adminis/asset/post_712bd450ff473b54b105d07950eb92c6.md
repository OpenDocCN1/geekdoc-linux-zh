## CHAPTER 2 AUTOMATING VSPHERE HYPERVISOR DEPLOYMENT AND CONFIGURATION

After you have downloaded the bundles, you can begin to modify the default images to customize them for your environment. Each bundle includes several image profiles; you can build an image profile to meet your needs for there. To view the existing image profiles, use the Get-ESXiImageProfile cmdlet, as we did in Listing 2.4.

## LISTING 2.4 Showing available image profiles

```
Get-EsXiImageProfile -Name ESXi-6* | Select-Object Name
Name
---
ESXi-6.0.0-2494585-no-tools
ESXi-6.0.0-2494585-standard
```

The packages have three basic types: Standard, which includes VMware Tools; No-tools, which is self-explanatory; and those that have a name ending with "s", which are security updates images. The steps for creating a package are as:

- 1. Clone the profile.
- 2. Add and remove packages as needed.
- 3. Export the profile.

Listing 2.5 shows the PowerCLI to execute those steps and ends by exporting the modified profile as an ISO image that can be used for loading your servers.

## LISTING 2.5 Modifying ESXi profile

```
New-EsXiProfile -CloneProfile ESXi-6.0.0-2494585-standard -Name ESXi-6.0.0-PowerCLI -Vendor Custom | Add-EsXiSoftwarePackage $additionalPackageName Remove-EsXiSoftwarePackage $removeThisPackage
```

| Name | Vendor | Last Modified | Acceptance Level |
|---|---|---|---|

Pipelining the commands makes for an easy way to do all three operations (clone, add, and remove) in one single step. The final operation is to export the customized profile to an ISO image (see Listing 2.6).

## LISTING 2.6 Exporting the customized image

```
Export-ImageProfile -ImageProfile ESKI-6.0.0-PowerCLI \
-FilePath $destinationFolder \
-ExportToIso
```

The final parameter for the command can be either ExportIso, which will output an ISO that can be used to install vSphere to the host, or ExportToBundle, which will output a bundle capable of being ingested by Update Manager or directly on the host for updates to packages.

## The Installation Medium

There are several different methods to install vSphere, ranging from the humble CD/DVD to the more complex, but more flexible, PXE. The installation method is the starting point from which you work back. Once you have selected an install medium, then you tailor your automation and workflows to that method.

A large part of choosing the installation method is related to the size of your vSphere environment. Each of the available methods carries with a series of trades. We cover each medium available, highlighting the advantages and disadvantages of each in addition to identifying a target environment size.

**CD/DVD** Old faithful, the CD/DVD, has been around since long before ESX, and it continues on with vSphere. This is the most basic medium because it offers no updating facility. CD/DVD is most used in small environments with just a handful of hosts. It is, however, the simplest, which means that anyone can learn this.

**Thumb Drive/USB Key** The thumb drive/USB key is more flexible than the CD/DVD. It is faster and easier to use. It is the preferred method for most environments.

**PXE** PXE is the most complex method, but it is also the most flexible. It allows you to install vSphere over the network. This is the best method for large environments.
