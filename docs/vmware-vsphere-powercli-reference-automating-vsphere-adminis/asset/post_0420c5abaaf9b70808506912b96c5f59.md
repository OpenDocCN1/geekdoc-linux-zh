
# Apache Subversion

If you are looking to get started with a source control system that can be installed within a Windows environment and is relatively straightforward, Apache Subversion (https://subversion.apache.org/) might be for you. Subversion is an open-source version control system with support for the majority of operating systems and excellent options for running it on Windows-based servers and accessing it via Windows clients. In this chapter, we will cover both free and commercially available packages built on Apache Subversion. There are some advanced source control features that you may find useful for a commercial enterprise and are available in paid-for software. Depending on your experience with open-source software, you may prefer to pay money for a company to supply that level of functionality for you.

In this chapter, we will use Windows-based Subversion server and client products VisualSVN Server and TortoiseSVN (client), VisualSVN only offers a plug-in for Visual Studio as a client to complement their Subversion server product. Since Visual Studio is not typically used by most PowerShell coders, we like and recommend the use of the TortoiseSVN client for client-side source control operations when developing PowerShell code. The TortoiseSVN client can also be used to work with other Subversion server products if required.

# VisualSVN Server

VisualSVN Server, offered by VisualSVN Limited (https://www.visualsvn.com/), and provides an easy way to set up and configure a Subversion server on Windows. There are two flavors: a Standard Edition and a paid-for-Enterprise Edition containing some advanced features.

> NOTE The Standard Edition contains enough to get started, and that's what we will be using in this chapter. Once you are familiar with the system, consider whether you will benefit from any of the advanced features in the commercially licensed Enterprise Edition.

# System Requirements

VisualSVN Server can be run on Windows Server 2008 or later with the following minimum hardware specifications:

- 1.4 GHz CPU
- 512 MB of RAM
- 500 MB hard drive space

# Installation and Initial Configuration

Download the latest version of VisualSVN Server and install the server software onto a Windows that meets the system requirements. Installation is straightforward; just follow the onscreen prompts, accepting all the defaults and selecting the Standard Edition (Figure 24.1).

# TortoiseSVN Client

TortoiseSVN (http://tortoisesesn.net/) is also free to use, even in a commercial environment. It provides a client implemented as a Windows shell extension—essentially a nice GUI for Subversion.

# System Requirements

TortoiseSVN can run on any Windows system that is Windows XP SP3 or later, in both 32-bit and 64-bit editions. Administrative privileges are required for installation.

# Users and Groups

Once you have systems running both VisualSVN Server and TortoiseSVN, the first thing that needs to be done is to configure authentication so that permissions for access to code can be assigned. It is possible to create local Users and Groups in the system. However, if you have joined the VisualSVN Server to an Active Directory, then you can use Users and Groups from that system and take advantage of an existing authentication system within your organization.

> TIP In VisualN Standard Edition, you can use Basic Authentication with Active Directory. There are some drawbacks to this approach, particularly regarding security. The Enterprise Edition offers Integrated Authentication with enhanced security features. You should consider which edition is most suitable for your requirements. You can find an overview of the features at https://www.visualsvn.com/server/features/windows-auth/. For the purposes of this chapter, we will be using Standard Edition to demonstrate the use of AD Users and Groups.

To configure authentication from the VisualSVN Server management console, navigate to the Authentication tab on the server. Select Windows Authentication and select the Basic Authentication box (Figure 24.4).

# Create a Repository

Now you can create a repository for storing and managing the code.

1. From within the VisualSVN server console, right-click Repositories, start the Create Repository wizard, and select FSFS Repository as the repository type (Figure 24.5).
2. Give the repository a name. For this exercise, use Repository01 (Figure 24.6).
3. Select a preferred repository structure. For this exercise, select Empty Repository (Figure 24.7).
4. For the Repository Access Permissions step of the wizard, select Customize Permissions, click the Custom button, and then select the group to which you want to grant permissions from the Group or User list. (We selected a group containing the users we want to give access to.) The Permissions allow you to grant a variety of permissions. The default is Read / Write, which is appropriate for this example (Figure 24.8). Click OK to set the Group or User permissions and click Create to finish creating the repository.

The wizard supplies summary details of the repository (Figure 24.9). The Repository URL is important information that is what you will use to connect to the repository from the TortoiseSVN client. It is useful to make a note of it, but it can be retrieved if necessary.

Single or multiple code projects can be maintained within a repository, or depending on your requirements, multiple repositories can be used to store single or multiple projects. A single repository lends itself to lower levels of ongoing server maintenance tasks; conversely, multiple repositories can give more flexibility for different projects in terms of items such as trigger or email notifications. The VisualSVN website contains some excellent guidance on how to plan for your VisualSVN Server repositories: https://www.visualsvn.com/support/svn/reposadmin/planning/. You'll also find more information on using the default folders that are created within each project.

From within the VisualSVN Server management console, right-click the Repository01 repository that you just created and choose New > Project Structure.
