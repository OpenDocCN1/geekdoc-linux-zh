# VM Locations

If the VMs are still registered on your ESXI hosts, adding the hosts also imported the registered VMs. The VMs are imported into the default virtual machine folder, and luckily you exported each VM's. To move a VM to a folder, you will need to use the Move-VM cmdlet. You can easily retrieve the original location using the Get-VLocation function from Listing 12.8 again:

```powershell
ForEach ($vm in Import-Clixml "C:\Export\VMLocations.xml") {
    $dc = Get-Datacenter $vm.Datacenter
    Move-VM ($dc | Get-VM $vm.Name) -Destination ($vm.VIPPath |
    Get-VLocation($dc))
}
```

# Roles

New roles are created using the New-VIRole cmdlet. Before restoring your roles, you should remove existing roles, including the default sample roles that come with your vCenter Server installation. Otherwise, you will receive errors when trying to import a role that already exists. System roles cannot be deleted, so filter them out first:

```powershell
Get-VIRole | Where-Object {-not $_.IsSystem} |
    Remove-VIRole -Confirm:$false
```

When restoring a role, you will need to specify which privileges are attached to the role. These privileges have be specified as privilege objects. When exporting roles, however, the privileges are returned as strings. So before adding privileges to the new role, you will need to find a way to convert the string values to privilege objects. This can be achieved by retrieving all privileges first using the Get-VIPrivilege cmdlet and matching the privilege IDs against the privilegegelist property of the role you want to import. Let's import the roles:

```powershell
$privileges = Get-VIPrivilege -PrivilegeItem
ForEach ($role in Import-Clixml "C:\Export\Roles.xml") {
    New-VIRole -Name $role.Name -Privilege ($privileges | 
    ? {$role.PrivilegeList -contains $._id})
```

# Permissions

Now that the roles are in place, you can start to restore the permissions throughout your inventory. New permissions can be assigned using the New-VIPermission cmdlet. Because you can assign permissions to all of objects in your inventory, you'll first need to determine what object type you want to restore permissions in order to use the right cmdlet to retrieve that. If the object is a folder, you'll need to use the Get-Folder cmdlet. If the object is a datacenter, you'll need to use the Get-Datacenter cmdlet, and so forth.

However, this can be more easily achieved using the Get-View cmdlet and making of the full SDK objects, this cmdlet allows you to specify the object type and hence can be used to retrieve all of objects. Because the Get-View cmdlet, you must specify a filter to indicate the objects you want to return. For example, to retrieve a VM called VM001, you would use the following:

```powershell
Get-View "VirtualMachine" -Filter @{"Name" = "VM001"}
```

One important thing to know is that Get-View filters are regular expressions. Regular expressions can contain metacharacters special characters. These characters can also be part of the object's name, you'll have to escape them using the \ character. We've created a small helper function for this in List 12.9.

# LISTING 12.9 Escaping regular expression metacharacters

```powershell
filter Escape-MetaChar {
  ForEach ($MetaChar in '^', '$', '(', ')', '[', ']', '{', '}', '.', '*', '\', 
  '*', '+', '?', '|', '!', '^', '<', '>', '-', '&') {
    $_.replace($MetaChar, "\\$MetaChar")
  }
}
```

To assign permissions using the SDK, use AuthorizationManager and its SetEntityPermissions() method. This method accepts a ManagedObjectReference to an inventory object and a VMware.Vim.Permission object:

```powershell
ForEach ($permission in Import-Clixml 
  "C:\Export\Permissions.xml") {
    $entityView = Get-View -ViewType $permission.Entity \
  -Property Name -Filter @{"Name" = $permission.Name | Escape-MetaChar}
    $newPermission = New-Object VMware.Vim.Permission
    $newPermission.principal = $permission.Principal
    $newPermission.group = $permission.Group
    $newPermission.propagate = $permission.Propagate
    $newPermission.role = (Get-VIRole $permission.Role).id
    $authMgr.SetEntityPermissions($entityView, $newPermission)
}
```

# Networking

Once your permissions are set, your folders are in place, and the virtual structure is up, you can restore the distributed switch. If you are restoring the distributed switch back onto the original vCenter from which it was exported, the ESXI hosts should reconnect to the switch automatically. If you are importing the distributed switch configuration onto a new vCenter, you will need to reconnect the vmnics of the ESXI distributed switch to each host. Start by importing the distributed switch; if you have more than one datacenter, you will need to specify the correct folder using the Get-Datacenter cmdlet at the beginning:

```powershell
$Folder = Get-Datacenter Main-DC | Get-Folder -Name Network
New-VDS -Name "VDS-Primary" -Location $Folder \
  -BackupPath "c:\Temp\VDS-Primary.zip"
```

If you are restoring a distributed switch that already exists in vSphere, restoring the switch overwrites the current settings of the distributed switch and its port groups. Note that it does not delete port groups that are not part of the file. Once you have imported your distributed switch and are ready to reconnect your host's vmnics to their respective port groups, you can leverage the Import-VMHostVnicDDS cmdlet in Listing 12.10 to restore the configuration that you exported earlier in the chapter.

# LISTING 12.10 Importing ESXI host vmnic configuration

```powershell
function Import-VMHostVnicDDS {
<#
SYNOPSIS
Attach ESXI Host to vDS and connect each vmnic to its Uplink port

.DESCRIPTION
This function uses the information that was exported using Export-VMHostVnicDDS function to connect each ESXI host to the correct vDS and each vmnic to its corresponding Uplink PG.
.NOTES
Source: Automating vSphere Administration
.PARAMETER Path
Specifies the path to the CSV file.
.EXAMPLE
Import-VMHostVnicDDS -Path C:\Temp\VMnicConfig.csv
#>
[CmdletBinding()]
Param (
[Parameter (Mandatory = $True, Position = 1,
HelpMessage = "Enter The Path To The VMnicConfig.csv file")
[string]$Path
)
process
    $csv = Import-Csv -Path $Path

    foreach ($row in $csv) {
        Write-Host $row.Switch -ForegroundColor Green
        Write-Host ("..." + $row.PG) -ForegroundColor Green
        Write-Host (" " + $row.Host +") -ForegroundColor Cyan

        # Check for VMHost and vDS
        if (!(Get-VMHost -Name $row.Host -ErrorAction SilentlyContinue)) {
            Write-Host "Warning $($row.Host) does not exist, moving to next row" -ForegroundColor Red
            Continue
        }
        if (!(Get-VDSwitch -Name $row.Switch -ErrorAction SilentlyContinue)) {
            Continue
        }

        # Add Host to vDS
        Write-Host "Adding Host $($row.Host) to vDS Switch ${($row.Switch)}" -ForegroundColor Yellow
        Get-VDSwitch -Name $row.Switch | Add-VDSwitchVMHost -VMHost $row.Host

        if (Get-VDSwitch -Name $row.Switch) {
            Write-Host "Host $($row.Host) added successfully"
        } else {
            Write-Host "It Appears that $($row.Host) was not added successfully to ${($row.Switch)}" -ForegroundColor Red
        }

        # Add vmnics to vDS
        $vmnics = ($row.vmnics).Split(",")
        $vmnics | Foreach-Object {
            # Clear post configuration
            Get-VMHost -Name $row.Host | Get-VMHostNetworkAdapter -Physical -Name $_ | Remove-VDSwitchPhysicalNetworkAdapter -Confirm: $false -ErrorAction SilentlyContinue

            # Get the Hosts network adapters
            Write-Host "Adding $($row.Host) to vDS Switch $($row.Switch)" -ForegroundColor Yellow
            $HostNetworkAdapter = Get-VMHost $row.Host | Get-VMHostNetworkAdapter -Physical -Name $_
            Get-VDSwitch $row.Switch | Add-VDSwitchPhysicalNetworkAdapter -VMHostPhysicalNic $HostNetworkadapter -Confirm:$false

            if (Get-VDSwitch -Name $row.Switch | Get-VDSwitchPhysicalNetworkAdapter
            | Where-Object { $_.VMHost -like $row.Host -and $_.Name -eq $_ }) {
                # Success logic
            }
        }
    }
}
```
