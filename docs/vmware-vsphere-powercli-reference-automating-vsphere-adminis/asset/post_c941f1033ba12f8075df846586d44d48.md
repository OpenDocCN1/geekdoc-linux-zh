# Understand Return Values and Faults

Earlier in the chapter, we introduced the Task object. Task managed objects allow you to verify the state of a particular task, check the result of that task, and determine whether any faults occurred. We used the PatchManager to see how this works:

```
$esx = Get-VMHost esx.test.local
$pmMoRef = $esx.ExtensionData.ConfigManager
$pm = Get-View $pmMoRef
$taskMoRef = $pm.QueryHostPatch($null)
```

Notice in the line that the method ends with _Task suffix; it is an asynchronous task and will return a MoRef to a Task object. With the help of the Get-View cmdlet, you can get a local copy of the task. We used the following code:

```
$task = Get-View $taskMoRef
```

In the Task object, you can find the current state of the task. The returned state can be queued, running, success, or error, as shown next:

```
$task.Info.State
```

In this case, the method called successfully. You can find more information about the results of the call to the Task object using $task.Info.Result:

The more you work with the vSphere API, the more you'll find the same script elements appearing again and again. It is useful to keep these code snippets for your scripts. This section illustrates some of these general code snippets.

# Waiting for an Asynchronous Task

In your scripts you can construct a simple loop to wait for the completion of asynchronous tasks. The following script shows one way to do this:

```
$taskMoRef = <any_call_to_an_asynchronous_method>
$task = Get-View $taskMoRef
while("running","queued" -contains $task.Info.State){
$task.UpdateData("Info")
Start-Sleep -Seconds 1
}
```

The script loops until the status of the task is no longer queued (waiting to run) or running. The script looks at a copy of the Task object, we had to refresh the Task object contents periodically. We used the UpdateData method and specified that only the Info property needed to be refreshed.
