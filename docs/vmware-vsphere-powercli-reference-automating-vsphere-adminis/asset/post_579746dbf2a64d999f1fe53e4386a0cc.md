Now that you know that a role is a group of privileges and you've learned to use the Get-VIPrivilege and Get-VIRole cmdlets, we want to introduce you to New-VIRole. You can use the New-VIRole cmdlet with Get-VIPrivilege to define a new role. You can define your own group of privileges, which can be assigned to your users. An example is shown in Listing 1.8; you can see the results in the vCenter Client, as shown in Figure 1.5.

Creating a new role

- New-VIRole 
- -Name 'New Custom Role'

- -PrivilegeGroup "Interaction", "Provisioning"

A new role can also be created at a granular level. First, choose the privileges to use:

```
$Priv = @())
$MyPriv = "Profile", "VCIntegrity.Baseline", 
"VApp.Move", "Profile.Clear",
```

And add each of to an array:

```
Foreach ($Cust in $MyPriv) {
$Priv += Get-VIPrivilege | Where-Object {$_.Name -eq $Cust}
```

You can then apply the specific permissions to the new role:

```
New-ViROle -Name 'New Custom Role' -Privilege $Priv
```

# Bringing Users

Now you've set up and tested individual permissions, you can export them to a readable format. Until now, you've been working with roles and privileges. Exporting them to a CSV file can be a great way to satisfy a security audit or ensure the relevant departments or users have the correct permissions. We'll show you next.

Each of the permissions defined underneath a datacenter, cluster, resource pool, or folder gives the user access. So it comes as no surprise, when using PowerShell, you must consider three areas:

- Role The role you will assign
- Principal The user or group to which you grant
- Entity The object you wish to grant

You can then enable the features of the vSphere Client. Each of the permissions defined by the vCenter Server, ensures,.., the the to to a to, cluster, datacenter, resource pool, or folder.
