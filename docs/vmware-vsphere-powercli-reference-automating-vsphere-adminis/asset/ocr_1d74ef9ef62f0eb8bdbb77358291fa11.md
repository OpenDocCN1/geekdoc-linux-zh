# NFS Storage

Again, the key to adding a new NFS datastore is determining the path. Once you have the path, the other requirements are a name for the datastore and the NFS host you want to connect. Let's add new NFS datastores with the path /volume6/NFSxx on the NFS host 172.20.0.10 to all hosts (Listing 4.9).

# LISTING 4.9 Creating multiple NFS datastores

```
$NamePrefix = 'NFS'10..17 | Foreach {$DatastoreName = ($NamePrefix + $_);
Get-Cluster 'Cluster01' | Get-VMHost | New-Datastore -Nfs -Name $DatastoreName -Path /volume6/$DatastoreName -Host 172.20.0.10
```

# NFS 4.1

In vSphere 6, VMware introduced support for the NFS 4.1 protocol. Prior to this release NFS 3 was the protocol used for working with NFS datastores. NFS 4.1 introduces new features such as authentication with Kerberos and multipathing. As of this writing, PowerCLI does not support creating an NFS 4.1 datastore. However, we can make use of PowerCLI's ability to take the functionality of vSphere's command-line tool exclude and enable the creation of an NFS 4.1 datastore in PowerShell.
