privileges within vCenter Server are required. We prefer to take the following approach:

+   - The vCenter Server runs with a domain account. Consequently, the scripts execute through the Security Support Provider Interface (SSPI) and use single sign-on to connect to vCenter Server. Therefore you do not need to specify credentials.

+   - The domain account that the vCenter Server runs holds the required privileges within vCenter's permission model to execute whatever you want to accomplish in the script.

Unlike the code you'll see, the actual text for the Configuration field in the Actions section of the Edit Alert wizard is entered in one line, with no carriage or linefeeds. (We had to break the text into three lines; it's too long to fit the page.) For a 64-bit OS, like Windows 2012, it would look like Listing 17.2.

# 17.2 An example script

```
C:\Windows\System32\cmd.exe / powershell
-PSConsoleFile C:\Scripts\MyConsole.pscl -noninteractive
-profile file C:\Scripts\Alarm-action-script.ps1
```

A common method for monitoring processes on Windows server is to use the Process Explorer from Microsoft's Sysinternals website at http://sysinternals.com. When you use Process Explorer on your vCenter Server, you can see how vCenter Server runs your alarm script. Process Explorer allows you to see the parameters that are used for each of the spawned processes. Open the properties of the cmd.exe and the powershell.exe processes. Process Explorer also allows you to verify when your alarm script is finished. Just check whether the cmd.exe and powershell.exe processes have disappeared below the vpxd.exe process.

In Listing 17.2, notice the use of the console file on the command line. With this file, you can define the snap-in(s) that need to be loaded into the PowerShell session that will run your script.

> A PowerShell console file is an XML-based file that contains details of PowerShell snap-ins and is saved with a *.pscl extension. PowerCLI clips with a console file, vim.pscl, in the installation directory. You can also create your own console file using the Export-Console cmdlet.
