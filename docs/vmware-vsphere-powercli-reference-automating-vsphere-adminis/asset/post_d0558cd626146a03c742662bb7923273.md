## LISTING 12.2 Retrieving the folder structure

```
function Get-FolderStructure {
<#n.SYNOPSIS
  Retrieve folder structure
.DESCRIPTION
  This function retrieves the folder structure beneath the given container
.NOTES
  Source: Automating vSphere Administration
.EXAMPLE
  Get-Datacenter DC01 | Get-FolderStructure
>
```

```
process {
$folder = "" | select Name,Children
$folder.Name = $_.Name
$folder.Children = @($_ | Get-Folder -NoRecursion | \
Get-FolderStructure)
}
}
```

You only need to feed this folder or datacenter object, and it will return the full folder structure beneath it. Let's try this and show the root folder's structure in a hash table called $folderStructure:

```
$folderStructure={}
Get-Folder -NoRecursion | Get-FolderStructure | \
%($folderStructure[$_.name] = $_.Children)
```

Because you supplied the root folder as an input object, you retrieved the datacenter-folders, not the folders beneath the datacenters. Now, use the same function to retrieve the folder structure beneath each datacenter in your inventory. To retrieve the datacenters, use the Get-Datacenter cmdlet. First, take a look at the root folders directly beneath the datacenter:

```
Get-Datacenter DC01 | Get-Folder -NoRecursion
Name Id
-- ---
vm Folder-group-v2081
host Folder-group-h2082
dastore Folder-group-s2083
```

Notice that the three folders returned aren't visible in your inventory. These special root folders, like the datacenter root folder. Virtual machines go inside the vm folder are represented as blue folders inside your inventory. The host folder contains your clusters and hosts, and its subfolders are represented as yellow folders inside your inventory. The datastore folder is for datastores.

Now, let's use the Get-FolderStructure function again to retrieve the folder structure beneath the datacenter and store it in the $folderStructure hash table:

```
Get-Datacenter | Get-Folder-Structure | %{
$folderStructure[$_.name] = $_.Children
}
```

All folder structures are now captured into the $folderStructure hash table. You now only need to export this hash table to a file. The most appropriate format for storing objects is XML. Therefore, use the Export-Clixml cmdlet to export the $folder-structure object to an XML file:

```
$folderStructure | Export-Clixml C:\Export\Folders.xml
```

## Datacenters

The datacenter is a container in your inventory, just like a folder. It can contain folders, clusters, and hosts. Although in most cases there will be only one or two datacenter objects in the inventory and re-creating them by hand is quick and painful, using a PowerShell script to export them allows you to automate the complete process without user intervention. To retrieve the datacenters, use the Get-Datacenter cmdlet again:

```
Get-Datacenter
```

| Name | Id |
|---|---|
| DC01 | Datacenter-datacenter-2080 |
| DC02 | Datacenter-datacenter-2 |

Like datacenters, all inventory objects have a specific location in your inventory. When you want to re-create any object later, you can specify the object's inventory location using the -Location parameter. To retrieve the object's full path you can use something like the Get-FolderStructure function in Listing 12.2, except that you need to work up to the root folder this. In Listing 12.3 you'll find a function to retrieve the path called Get-VIPath.

## LISTING 12.3 Retrieving the object path

```
function Get-VIPPath {
  <#n  .SYNOPSIS
  Retrieve the full path of an inventory object
  .DESCRIPTION
  This function retrieves the full path of the given inventory object
  .NOTES
  Source: Automating vSphere Administration
```

## EXPORT VCENTER SERVER INVENTORY ITEMS

.PARAMETER inputObject
The inventory object to retrieve the full path from
.PARAMETER childPath

Optional parameter used by the function when calling itself
recursively

```
.EXAMPLE
Get-Datacenter DC01 | Get-Folder
#>
Param (
  [Parameter(Mandatory=$true)]
  $inputObject,

  $childPath
)

Process {
  $inputObject = $inputObject
  $path = $inputObject.Path
  if ($childPath) {
    $path = "$path\$childPath"
  }
  return $path
}
```

In addition to all cluster properties, you'll need to know which datacenter belongs to so you can recreate in the right datacenter. To accomplish this, iterate through the datacenters first and retrieve the clusters. The datacenter can then be added to the cluster. You can use the Get-Folder function to retrieve the cluster's path.

```content
$clusters = @()
foreach ($dc in Get-Datacenter) {
    foreach ($cluster in ($dc | Get-Cluster)) {
        $clusters[$cluster.name] = $cluster 
    }
}
$clusters | Export-Clixml C:\Export\Clusters.xml
```
