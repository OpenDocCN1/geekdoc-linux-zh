The `LD_PRELOAD` environment variable causes the system’s program loader (which brings executable files into memory) to link in a special library *before* the standard libraries. The `ef` script uses this feature to link in Electric Fence’s version of the `malloc()` suite. Thus, relinking isn’t even necessary. This example demonstrates `ef`:

```
$ cc -g ch15-badmem1.c -o ch15-badmem1<br>`Compile normally`<br>$ ef ch15-badmem1 -b<br>`Run using ef, dumps core`<br><br>Electric Fence 2.2.0 Copyright (C) 1987-1999 Bruce Perens <bruce@perens.com><br>p = <not 30 bytes><br>/usr/bin/ef: line 20: 28005 Segmentation fault     (core dumped)<br>( export LD_PRELOAD=libefence.so.0.0.0; exec $* )<br><br>$ ef ch15-badmem1 -f<br>`Run using ef, dumps core again`<br><br>Electric Fence 2.2.0 Copyright (C) 1987-1999 Bruce Perens <bruce@perens.com><br>p = <not 30 bytes><br>/usr/bin/ef: line 20: 28007 Segmentation fault     (core dumped)<br>( export LD_PRELOAD=libefence.so.0.0.0; exec $* )<br><br>$ ls -l core*<br>`Linux gives us separate core files`<br>-rw------- 1 arnold devel 217088 Aug 28 15:40 core.28005<br>-rw------- 1 arnold devel 212992 Aug 28 15:40 core.28007
```

GNU/Linux creates core files that include the process ID number in the file name. In this instance this behavior is useful because we can debug each core file separately:

```
$ gdb ch15-badmem1 core.28005<br>`From the -b option`<br>GNU gdb 5.3<br>...<br>Core was generated by `ch15-badmem1 -b`.<br>Program terminated with signal 11, Segmentation fault.<br>#0  0x08048466 in main (argc=1, argv=0xbffff8c4) at ch15-badmem1.c:18<br>18)<br>      p[42] = 'a';      /* touch outside the bounds */<br>(gdb) quit<br><br>$ gdb ch15-badmem1 core.28007<br>`From the -f option`<br>GNU gdb 5.3<br>...<br>Core was generated by `ch15-badmem1 -f`.<br>Program terminated with signal 11, Segmentation fault.<br>#0  0x08048498 in main (argc=2, argv=0xbffff8c4) at ch15-badmem1.c:21<br>21)<br>      p[0] = 'b';
```
