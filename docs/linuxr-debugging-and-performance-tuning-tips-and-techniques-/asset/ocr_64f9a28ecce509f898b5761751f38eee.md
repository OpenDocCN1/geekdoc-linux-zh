+   Cast and assign the return value of \( \mathrm{re} \mathrm{alloc}(\mathrm{a}) \). More discussion of this shortly.

+   As for \( \mathrm{malloc}(\mathrm{a}) \), check the return value to make sure it's not \( \mathrm{NULL} \). Any memory allocation routine can fail.

When growing a block of memory, \( \mathrm{re} \mathrm{alloc}(\mathrm{a}) \) often allocates a new block of the right size, copies the data from the old block into the new one, and returns a pointer to the new one.

When shrinking a block of data, \( \mathrm{re} \mathrm{alloc}(\mathrm{a}) \) can often just update the internal bookkeeping information and return the same pointer. This saves having to copy the original data. However, if this happens, don't assume you can still use the memory beyond the new size!

In either case, you can assume that if \( \mathrm{re} \mathrm{alloc}(\mathrm{a}) \) doesn't return \( \mathrm{NULL} \), the old data has been copied for you into the new memory. Furthermore, the old pointer is no longer valid, as if you had called \( \mathrm{free}(\mathrm{a}) \) with it, and you should not use it. This is true of all pointers into that block of data, not just the particular one used to call \( \mathrm{free}(\mathrm{a}) \).

You may have noticed that our example code used a separate variable to point to the changed storage block. It would be possible (but a bad idea) to use the same initial variable, like so:

```
coordinates = realloc(coordinates, new_amount);
```

This is a bad idea for the following reason. When \( \mathrm{re} \mathrm{alloc}(\mathrm{a}) \) returns \( \mathrm{NULL} \), the original pointer is still valid; it's safe to continue using that memory. However, if you reuse the same variable and \( \mathrm{re} \mathrm{alloc}(\mathrm{a}) \) returns \( \mathrm{NULL} \), you've now lost the pointer to the original memory. That memory can no longer be used. More important, that memory can no longer be freed! This creates a memory leak, which is to be avoided.

There are some special cases for the Standard C version of \( \mathrm{re} \mathrm{alloc}(\mathrm{a}) \): When the \( \mathrm{ptr} \) argument is \( \mathrm{NULL} \), \( \mathrm{re} \mathrm{alloc}(\mathrm{a}) \) acts like \( \mathrm{malloc}(\mathrm{a}) \) and allocates a fresh block of storage. When the \( \mathrm{size} \) argument is 0, \( \mathrm{re} \mathrm{alloc}(\mathrm{a}) \) acts like \( \mathrm{free}(\mathrm{a}) \) and releases the memory that \( \mathrm{ptr} \) points to. Because (a) this can be confusing and (b) older systems don't implement this feature, we recommend using \( \mathrm{malloc}(\mathrm{a}) \) when you mean \( \mathrm{malloc}(\mathrm{a}) \) and \( \mathrm{free}(\mathrm{a}) \) when you mean \( \mathrm{free}(\mathrm{a}) \).
