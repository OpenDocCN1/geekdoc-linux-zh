$1 matches the first field, $2 the second, and so on. $0 matches the entire input line. Pretty simple, isn’t it?

It’s not quite what I want, however, because the very first line of output from ls is a summary of the blocks taken up by the entire directory (the total 8474 line), and the awk script sees that and counts it as a line, even though it doesn’t have a fifth field. If we leave this as-is, the eventual average mailbox size will be wrong because it’ll be taking “n+1” files into account due to this erroneous match.

# 3. The standard Unix way to solve this would be to drop something else into the pipeline that’ll extract that line, or filter just the lines of valid data. It might look like this:
