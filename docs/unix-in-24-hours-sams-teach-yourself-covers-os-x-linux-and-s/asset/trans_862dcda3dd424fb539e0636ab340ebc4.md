如果你当前查看的是 `Indiana` 目录中的信息，`Bldgs` 唯一地描述了一个文件：`Indiana` 目录中的 `Bldgs` 文件。然而，如果你处于 `California` 目录或 `Washington` 目录中，同一个名称则指向不同的文件。同样，目录 `Personnel` 会留下三种可能的选项，直到你也指定感兴趣的是哪个州为止。

作为一个可能的场景，想象一下你正在阅读 `Washington` 的 `Bldgs` 文件，突然有人走进你的办公室打断了你的工作。聊了几分钟后，他们提到 `California` 的 `Bldgs` 文件中的一个条目。你转向你的 Unix 系统并打开 `Bldgs` 文件，结果却是错误的文件。为什么？因为你仍然在 `Washington` 目录中。

这些问题源于相对文件名的缺乏特异性。相对文件名描述的是相对于文件系统中假设位置的文件。在图 3.3 中，即使是 `Personnel/Taylor,D.` 也不是唯一的，因为它可以在 `Indiana` 和 `Washington` 中找到。

为了避免这些问题，你可以应用之前学到的技巧：从上到下指定目录路径的所有元素。要查看 `California` 的 `Bldgs` 文件，你可以简单地指定 `/California/Bldgs`。要检查 `Indiana` 的 `Taylor,D.` 员工，你会使用 `/Indiana/Personnel/Taylor,D.`，你会注意到这与 `/Washington/Personnel/Taylor,D.` 不同。

学习这两种记法的区别对于在 Unix 的分层文件系统复杂性中生存至关重要。没有它，你会花费一半的时间验证自己是否在认为的位置，或者更糟，根本不移动，无法利用其组织能力。

如果你对自己在 Unix 中的位置或正在处理的文件有任何疑问，只需指定其绝对文件名。你总可以通过第一个字符来区分相对文件名和绝对文件名：如果它是一个斜杠，你就有绝对文件名，因为文件名根植于文件系统的最顶层。

如果第一个字符不是斜杠，那么文件名就是相对文件名。

我之前告诉过你，在 Unix 顶层的 /home 目录中，我有一个名为 taylor 的主目录。用绝对文件名的术语来说，我应该正确地说我有 /home/taylor 作为一个唯一目录。

## Note

为了增加混乱，大多数 Unix 用户不会发音斜杠，特别是当文件名的第一个组件是一个众所周知的目录时。我会把 /home/taylor 发音为“home taylor”，但我通常会把 /newt/awk/test 发音为“slash newt awk test”。有疑问时，就发音斜杠。

当你更多地了解 Unix，特别是如何导航文件系统时，你会发现清楚理解相对文件名和绝对文件名之间的区别非常宝贵。记住经验法则是：如果文件名以 / 开头，它就是绝对的。

## Task 3.2: Hidden Files in Unix

长期居住在一个地区，经常光顾同一家商店和餐厅的好处之一是，每个地方的工作人员都会记住你的名字和偏好。许多 Unix 应用程序也可以做同样的技巧，通过偏好文件记住你偏好的交互方式、你最后处理的文件、你编辑过的行等等。

在 Macintosh 上，每个用户的主目录内都有一个名为 Library 的文件夹。在其中还有一个名为 Preferences 的文件夹，它是偏好文件的集中存储位置，按应用程序组织。例如，在我的 Macintosh 上，我在这个目录中有大约 75 个不同的偏好文件，这样我的所有程序都可以记住我偏好的默认值。

Unix 必须同时支持许多用户，因此 Unix 偏好文件不能存储在文件系统的中央位置。否则，系统如何区分你的偏好和同事的偏好呢？为避免这个问题，所有 Unix 应用程序都将它们的偏好文件存储在你的主目录中。

程序希望能够在你的目录中保存自己的内部偏好和状态，但这些不是供你使用或更改的。如果你使用 DOS，你可能熟悉 Windows 如何解决这个问题：某些文件是隐藏的，在使用 DIR、在 DOS 中或在文件管理器列出目录中的文件时不会显示。

Macintosh 用户没有意识到的是，Macintosh 也有很多隐藏文件。例如，在 Macintosh 文件系统的最顶层，存在以下文件，尽管对正常显示是隐藏的：.DS_Store、Desktop DB、.VolumeIcon.icns、NavMac8000QSFile，以及我个人最喜欢的 .symSchedScanLockxz。在 Macintosh 上显示隐藏文件非常困难，就像在 Windows 中一样。
