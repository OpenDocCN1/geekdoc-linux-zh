# Authentication of clients and encryption

For users sending mail from home, it is usually easiest to route outgoing mail through home ISP's mail server, regardless of the sender address that appears on mail. Most ISPs trust their direct clients and allow relay. If this configuration isn't possible or if you are using a system such as Sender ID or SPF, ensure that mobile users outside your network can be authorized to submit messages to your smtpd.

The solution to this problem is to use the SMTP AUTH mechanism to authenticate directly at the SMTP level. Postfix must be compiled with the SASL library to make this work. You can then configure the feature like:

```
smtpd_sasl_enable = yes
smtpd_recipient_restrictions =
    permit_mynetworks
    permit_sasl_authenticated
```

You also need to support encrypted connections to avoid sending passwords in clear text. Add lines like the following to main.cf:

```
smtpd_tls_security_level = may
smtpd_tls_auth_only = yes
smtpd_tls_loglevel = 1
smtpd_tls_received_header = yes
smtpd_tls_cert_file = /etc/certs/smtp.pem
smtpd_tls_key_file = $smtpd_tls_cert_file
smtpd_tls_protocols = !SSLv2
```
