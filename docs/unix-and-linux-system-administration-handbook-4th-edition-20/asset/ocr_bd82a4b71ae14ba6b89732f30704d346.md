This describes the X.Org version of X, which is used by all of our systems except HP-UX. The implementations of X.Org and XFree86 have diverged architecturally, but most of the administrative details remain the same. It is often possible to substitute xfree86 for xorg in the commands and filenames up to the appropriate XFree86 version.

Solaris systems through version 10 included both the X.Org and Xsun, yet another implementation of 'X'. Xsun remains common on SPARC systems running Solaris 10, but x86 systems typically run X.Org. However X now supports SPARC, and the OpenSolar project shows that X.Org will be the only supported platform in the future. We do not discuss Xsun here.

By default, AIX does not have a Window System environment. To install, run smoky-install, select the ipp library source, and choose either CDE (for the traditional IBM-blessed Motif platform) or KDE (for the more modern option). What you get is a customized version of the X.Org environment that has been stripped down to look more like the older X systems of the Motif era. However, it supports X11R7 under the hood.

The X Window System can be broken down into a few components. It provides a display manager whose main job is to authenticate users, log them in, and start an initial environment from startup scripts. The display manager also starts the X server, which defines an abstract interface to the system's bitmaps and input devices (e.g., keyboard and mouse). The startup scripts also run a window manager, which allows the user to move, resize, minimize, and maximize windows, as well as manage separate virtual desktops. At the lowest level, applications are linked to a widget library that implements high-level user interface mechanisms such as buttons and menus. Exhibit A illustrates the relationship between the display manager, the X server, and client applications.

The X server understands only a very basic set of drawing primitives over a network API; it does not define a programming interface to high-level entities as buttons, text boxes, menus, and sliders. This design achieves two goals. First, it allows the X server to run on a computer that is completely separate from that of the client application. Second, it allows the server to support a variety of window managers and widget sets.
