The AWS site connects the account signup pages and all the necessary downloads. To start using AWS, download the command-line tools and the access identifiers, which consist of a certificate and a private key.

Make a directory ~/.ec2 and move the downloaded certificate file, key, and extracted tools to that directory. All EC2 commands will reside in ~/.ec2/bin, with library dependencies in ~/.ec2/lib. To set up the environment for easy use, add the following to your shell's login script. (For bash, this is ~/.bash_login or ~/.bash_profile).

```
export EC2_HOME=~/.ec2
export PATH=$EC2_HOME/bin
export EC2_PRIVATE_KEY=$EC2_HOME/<long string value>.pem
export EC2_CERT=$EC2_HOME/cert-<long string value>.pem
export JAVA_HOME=/path/to/java
```

Finally, choosing an image and starting it, create a key pair that allows you to gain access to the image. The ec2-add-keypair command creates a new key pair. Any images that created will automatically be configured to use the new public key for SSH authentication to the root account.

```
ubuntu ec2-add-keypair my-keypair
KEYPAIR my-keypair kb:06:55:11:04:53:3b:f7:42:99:fb:0e:7f:63:22:ff:88:ae
-----BEGIN RSA PRIVATE KEY----
nMIIwIAAKQAEaojXCAQHIJuJQoeEkaulij8y55InNuWS5HOOQvBfxuxEgGWk773kz
8F8B7U4CAQ
8287HZO/z2cC6fP8OI0AGRIvJzvVozWozZ7hdRhc/66isWiBMTDQQUltk79f19atk7P
-----END RSA PRIVATE KEY----
```

This will be needed in the future, so save everything the line beginning KEYPAIR to a file in the ~/.ec2 directory and make sure the permissions are 600. Never share the private key file—it contains the keys to the cloud kingdom!

Now it's time to choose an AMI. There is an enormous number of AMIs to choose from, many created by Amazon and many contributed (or) by the community. It's also possible to build a custom AMI for private use, possibly configured with the particulars of your environment or preinstalled with all your needed applications.

After choosing an image, note its identifier. The command below lists the AMIs created by Amazon. Having added the tools directory to the PATH variable, you can execute EC2 commands whenever.

```
ubuntu ec2-describe-images -o amazon
IMAGE ami-ba4aea3 /aws/quickstart/phpquickstart.manifest.xml
amazon available public 1386 machine
IMAGE ami-b4bafdd /aws/quickstart/rubyquickstart.manifest.xml
amazon available public 1386 machine aki-a17cf9c2 ari-a51cf9cc
IMAGE ami-1c54b075 /aws/quickstart/tomcatquickstart.manifest.xml
amazon available public 1386 machine aki-a17cf9c2 ari-a51cf9cc
```

# Chapter 24 Virtualization

The image name typically has a brief description to help you understand its purpose and configuration, but details are available in an on-line directory. To spin up the PHP quick start AMI from the list above, use the following command:

```
ubuntu$ ec2-run-instances ami-ba4eaa3 -k my-keypair
ubuntu$ ec2-describe-instances
RESERVATION r-56a053f default
INSTANCE i-1343fb7b ami-ba4eaa3 pending my-keypair 0
m1.small 2008-12-22T01:43:27+0000 us-east-1c
```

The ec2-describe-instances output reflects that the instance is still booting ("pending") and it's using the key pair set with the name my-keypair.

Import, the output shows that the instance is running in the us-east-1 availability zone. Amazon has segmented its systems into availability zones, so that a user who wants to guarantee that several instances run in physically separate data centers can request this on the main line. This value also be needed to attach an EBS volume.

Finally, the command shows that the instance type is m1.small. This code tells you the amount of resources available to the system. Amazon has defined standard profiles; m1.small is the default and includes a 32-bit EC2 CPU, 1.7GB memory, and 16GB of (nonpersistent) disk. Of course, the actual hardware your server runs probably looks nothing like this; it's just a way of describing your allocation.

Once the instance is running, any network ports you need to access must be authorized through another EC2 command, ec2-authorize:

```
ubuntu$ ec2-authorize default -p 22
```

In this case, port 22 (for SSH) is authorized for all hosts in the default group. (Groups are a mechanism for managing collections of instances. New instances are provisioned in the default group unless otherwise specified.) After you have authorized port 22, you can finally connect to your instance. To do so, find the first hostname, then SSH to it just as if there is another node on the Internet (because it is!)

```
ubuntu$ ec2-describe-instances
RESERVATION r-56a053f default
INSTANCE i-1343fb7b ami-ba4eaa3 ec2-67-202-245-235.compute-
m1.amazonaws.com domU-12-31-39-02-SE-55.compute.internal
runnym-my-keypair 0 m1.small 2008-12-22T01:43:27+0000
us-east-1c
```

```
ubuntu$ ssh -i -ssh/.ec2/id_rsa-my-keypair
root@ec2-67-202-245-235.compute-1.amazonaws.com
```

This command uses the key pair saved above to connect to the new instance's account. For security reasons, we recommend disabling SSH access.

The only remaining problem is that instances are not persistent. That is, when this instance terminates, any changes to its disk or memory state are not captured. EBS provisions storage volumes just as new instances are provisioned. Here, we create a volume and attach it to the running host.

```
ubuntu$ create-volume -s 1 -z us-east-1c
VOLUME vol-5de8034 1 us-east-1c creating 2008-12-22T02:02:00
53+0000
ubuntu$ attach-volume vol-5de8034 -i i-1343fb7a -d /dev/sdf
ATTACHMENT vol-5de8034 i-1343fb7a /dev/sdf attaching 2008-12-22T02:04:01+0000
ubuntu$ describe-volumes
VOLUME vol-5de8034 1 us-east-1c creating 2008-12-22T02:02:00
53+0000
ubuntu$ attach-volume vol-5de8034 -i i-1343fb7a -d /dev/sdf
ATTACHMENT vol-5de8034 i-1343fb7a /dev/sdf attaching 2008-12-22T02:04:01+0000
ubuntu$ describe-volumes
VOLUME vol-5de8034 1 us-east-1c creating 2008-12-22T02:02:00
53+0000
```

In addition to the command-line interface, Amazon offers a web management interface that can initiate operations such as starting instances and attaching volumes.

Amazon regularly introduces new features to its web services. Auto-scaling of EC2 instances spins up new servers when the load is high. The CloudWatch feature monitors metrics such as CPU usage and disk I/O for quick response to changing conditions. Keep an eye on the AWS blog at aws.typepad.com for feature enhancements and product announcements.
