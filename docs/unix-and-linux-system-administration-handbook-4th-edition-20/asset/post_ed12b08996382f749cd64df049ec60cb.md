
# Literal characters

The filename matching and expansion performed by the shell when it interprets command lines like wc *.pl is not a form of regex matching. It's a different system called "shell globbing," and it uses a different and simpler syntax.

Regular expressions are powerful, but they cannot recognize all possible grammars. Their most notable weakness is that they cannot recognize delimiters. For example, it is not possible to write a regular expression that recognizes valid arithmetic expressions when parentheses are allowed for grouping.

Regular expressions reached the peak of their power and performance in Perl. In fact, Perl's pattern matching features are so elaborate that it's not really accurate to call them an implementation of regular expressions. Perl patterns can match nested delimiters, recognize palindromes, and an arbitrary string of As followed by the same number of Bs—all feats beyond the reach of regular expressions. However, Perl can process vanilla regular expressions as well.

Perl's pattern matching language remains the industry benchmark, and it has been widely adopted by other languages and tools. Philip Hazel's PCRE (Perl-compatible regular expression) library makes it relatively easy for developers to incorporate into their projects.

Regular expressions are not themselves a scripting language, but they are useful enough to merit featured coverage in any discussion of scripting; hence, this section, we discuss in their basic form with a few of Perl's refinements.

# The matching process

Code that evaluates a regular expression to match a single given text string to a single pattern. The "text string" to match can be very long and can contain embedded newlines. It's convenient to use a regex to match the contents of an entire file or HTML document.

For the matcher to declare success, the entire search pattern must match a contiguous section of the search text. However, the pattern can match at any position. After a successful match, the evaluator returns the text of the match along with a list of matches for any specially delimited subsections of the pattern.

# Literal characters

In general, characters in a regular expression match themselves. So the pattern

`I am the walrus`

matches the string "I am the walrus" and that string only. Since it can match anywhere in the search text, the pattern can be successfully matched to the string "I am egg man. I am the walrus. Koo koo-cho!" However, the actual match is limited to the "I am the walrus" portion. Matching is sensitive.

Many special characters, such as + and |, affect the matching of the "thing" to their left or right. In general, a "thing" is a single character, a subpattern enclosed in parentheses, or a character enclosed in square brackets. For the | character, however, thickness extends indefinitely to both left and right. If you want to limit the scope of the vertical bar, enclose the bar and both in their own set of parentheses. For example,

`I am the (walruseggman).`

matches either "I am the walrus." or "I am the egg man.". This example also demonstrates escaping of special characters (here, the dot). The pattern

`(I am the (walruseggman)\.?){1,2})`

matches any of the following:

* I am the walrus.
* I am the egg man.
* I am the walrus. I am the egg man.
* I am the egg man. I am the walrus.

# Example regular expressions

In the United States, postal "zip" codes have either five or six digits followed by a dash and four more digits. To match a regex zip code, you must match a five-digit number. The following regular expression fits the:

```
^\d{5}
```

The ^ and $ match the beginning and end of the search text but do not correspond to characters in the text; they are "zero-width assertions." These characters ensure that only texts consisting of exactly five digits match the regular expression—the regex will not match five digits within a larger string. The \d matches a digit, and the quantifier {5} says that there must be exactly five digit matches.

To accommodate either a five-digit zip code or an extended zip+4, add an optional dash and four additional digits:

```
^\d{5}(-\d{4})?
```

The parentheses group the dash and extra digits together so that they are considered one optional unit. For example, regex won't match a five-digit zip code followed by a dash. If the dash is present, the four-digit extension must be present as well or there is no match.

A classic demonstration of regex matching is the following expression,

```
M[ou]?am+aejr [[Aeae][ -]]?([GKQ]h?[aeu]]+[dtz]*)?[afiy]
```

matches most of the variant spells of the name of Libyan head of state Moammar Gaddafi,

- Muammar Al-Kaddafi (BBC)
- Moammar Gaddafi (Associated Press)
- Muammar Al-Qadhafi (Al-Jazeera)
- Mu'ammar Al-Qadhafi (U.S. Department of State)

Do you see how each of these would match the pattern?

# Captures

When a match succeeds, every set of parentheses becomes a "capture group" that records the actual text that it matched. The exact manner in which these pieces are available to you depends on the implementation and context. In Perl, you can access the results as a list or as a sequence of numbered variables.

Since parentheses can nest, how do you know which is? Easy—the matches arrive in the same order as the opening parentheses. There are many captures as there are opening parentheses, regardless of the role (or lack of role) that each parent group played in the actual matching. When a parenthesized group is not used, Mu(?ammar when matched against “Muammar”), its capture is empty.

If a group is matched more than once, only the contents of the last match are returned. For example, with the pattern

```
(I am the (walrus|egg man)\){1,2}
```

matching the text
I am the egg man. I am the walrus.

there are two results, one for each set of parentheses:

I am the walrus.
walrus
