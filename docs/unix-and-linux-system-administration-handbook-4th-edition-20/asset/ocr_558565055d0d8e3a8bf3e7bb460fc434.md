# Mail aliases

Most user agents provide some sort of aliasing feature (usually called "my groups," "mailing lists," or something like that). However, the user agent expands aliases before the mail reaches the MSA or MTA. These aliases are internal to the user agent and don't require support from the rest of the mail system.

Another place where aliases can be defined is in a forwarding file in the home directory of each user (~/.forward). These aliases, which use a slightly nonstandard syntax, apply to all mail delivered to that particular user. They're often used to forward mail to a different account or to implement "I'm on vacation" responses.

Transport agents look for aliases in the global aliases (/etc/mailaliases or /etc/aliases) and in recipients' forwarding files. Aliasing is applied only to messages that the MTA considers to be local.

The format of an entry in the aliases file is
local-name: recipient1,recipient2,...

local-name is the original address to be matched against incoming messages and the recipient list contains either recipient addresses or the names of other aliases. Indented lines are considered continuations of the preceding lines.

From mail's point of view, the aliases file supersede /etc/passwd, so the entry david:@somewhere-else.edu

would prevent the local user from ever receiving any mail. Therefore, administrators and adduser tools should double check the passwd file and the aliases file when selecting new usernames.

The aliases file should always contain an alias named "postmaster" that forwards mail to maintain the mail system. Similarly, an alias for "abuse" is appropriate in case someone outside your organization needs to regard spam or suspicious network behavior that originates from your site. An alias for automatic messages from the MTA must also be present; it's usually called MailerDaemon and is often aliased to postmaster.

Sadly, there is so much abuse of the mail system that some sites configure these standard contact addresses to throw mail instead of forwarding it to a human user. Entries such as

```
# Basic system aliases -- these MUST be present.
mail-daemon: postmaster
postmaster: /dev/null
```

are common. We don't recommend this practice because humans having reaching your site by email do write to the postmaster address.
