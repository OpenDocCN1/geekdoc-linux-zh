## Creating the home directory and installing startup files

You can create the new user's home directory with a simple mkdir. You'll need to set ownerships and permissions on the new directory as well, but this is best done after you've installed local startup files.

Startup files traditionally begin with a dot and end with the letters rc

We recommend that you provide default startup files for each shell that is popular on your systems so that users continue to have a reasonable default environment if they change shells. 7.3 lists some common startup files.

## Table 7.3 Common startup files and their uses

| Command | Filename | Typical uses |
| --- | --- | --- |
| sh | .profile | Sets search path, terminal type and environment |
| bashᵃ | .bashrc | Sets the terminal type (if needed)<br>Sets biff and mesg switches<br>Sets up environment variables<br>Sets command aliases<br>Sets the search path<br>Sets the umask value to control permissions<br>Sets CDPATH for filename searches<br>Sets the PS1 (prompt) and HISTCONTROL variables |

ᵃ bash also reads .profile or /etc/passwd in emulation of sh.

Sample startup files are traditionally kept in /etc/skel (Linux, Solaris, HP-UX) or /etc (all systems). AIX, always a bit different, stashes them in /etc/security. If you customize your' startup files, /usr/local/etc/skel is a reasonable place to put the modified copies. Linux also keeps tidbits of startup files in /etc/profile.d directory, where shells look for pointers on coloring the output of ls to make it unreadable on a dark background, or the path to Kerberos binaries.

Depending on the user's shell, /etc may contain system-wide startup files that are processed before the user's own files. For example, bash and sh read /etc/profile before processing ~/.profile and ~/.bash_profile. These files are a good place in which to put site-wide defaults, but by mind that users can override your settings in their own startup files. For further details, see the main page for the shell in question.

Be sure to set a reasonable default value for umask; we suggest 077, 027, or 022, depending on the friendliness and size of your site. If you do not use individual groups, we recommend umask 077 because it gives the owner full access to the group and the rest of the world no access. See page 158 for details on umask.

The startup files and directories listed for the GNOME and KDE environment are just the tip of the iceberg. gconf is a tool that allows application preferences for programs run under GNOME, much like the Windows registry.

## Setting permissions and ownership

Now the home directory is set up, turn it over to the user and make sure the permissions on it are appropriate. The command

```
$ sudo -R newuser:newgroup ~newuser
```

should set ownership properly. Note that you cannot use

```
$ sudo chown newuser:newgroup ~newuser/*
```

to chown the files because newuser would then not own his own files but also the parent directory "." (e.g.,/home) as well. This is a common and dangerous mistake.
