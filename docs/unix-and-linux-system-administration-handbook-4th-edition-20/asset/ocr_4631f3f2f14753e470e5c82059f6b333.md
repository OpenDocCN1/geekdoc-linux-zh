# NFSv4 entities for which permissions can be specified

In addition to the garden-variety user:username and group:groupname specifiers,
FSv4 defines several special entities that may be assigned permissions in
ACL. Most important among these are owner@, group@, and everyone@, which
correspond to the traditional categories in the 9-bit permission model.

The NFSv4 specification (RFC3530) defines a few more special entities such as
dialup@ and batch@. From a UNIX perspective, they're all a bit peculiar. We are
ot aware of any actual real-world application for these entities; most likely,
exist to facilitate compatibility with Windows.

NFSv4 has several differences from POSIX. For one thing, it has no default entity,
used in POSIX to control ACL inheritance. Instead, any access control
(ACE) can be flagged as inheritable (see ACL inheritance, below). NFSv4\does not use a mask to reconcile the permissions in a file's mode
with its ACL. The mode is required to be consistent with the settings specified for\owner@, group@, and everyone@, and filesystems that implement NFSv4 ACLs
preserve this consistency when either the mode or the ACL is updated.

# Access determination

In the POSIX ACL system, the filesystem attempts to match the user's identity
to the single most appropriate access control entry. That ACE provides a com-
plet of controlling permissions for the file.

The NFSv4 system differs in that an ACE may specify only a partial set of permis-
sions. Each NFSv4 ACE is either an "allow" ACE or a "deny" ACE; it acts like
a mask as an authoritative specification of all possible permissions.¹¹³ Multiple
ACEs can access any given situation.

When deciding whether a particular operation, the filesystem reads the
ACL in order, processing ACEs until either requested permissions have been
allowed or some requested permission has been denied. Only ACEs whose entity
strings are compatible with the current user's identity are considered.

It's possible for the filesystem to reach the end of an NFSv4 ACL without having
obtained a definitive answer to a permission query. The NFSv4 standard-
result to be undefined, but most real-world implementations will choose to
deny access, because both this is the convention used by Windows and because it's
