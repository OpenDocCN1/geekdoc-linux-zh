# Access control lists in BIND, revisited

ACLs are address name match lists that can appear as arguments to statements such as allow-query, allow-transfer, and blackhole. Their basic syntax is described on page 609. ACLs can help up DNS security in a variety of ways.

Every site should have at least one ACL for bogus addresses and one for local addresses. For example:

```
acl bogusnets { // ACL for bogus networks
  0.0.0.0/8; // Default, wild card addresses
  1.0.0.0/8; // Reserved addresses
  2.0.0.0/8; // Reserved addresses
  169.254.0.0/16; // Link-local delegated addresses
```

# Open resolvers

An resolver is a recursive, caching name server that accepts and answers queries from anyone on the Internet. Open resolvers are bad. Outsiders can consume your resources without your permission or knowledge, and if they are bad guys, they may be able to poison your resolver's cache.

25. Don't make private addresses bogus if you use them and are configuring your internal DNS servers!

# Secure server-to-server communication with TSIG and TKEY

Worse, open resolvers are sometimes used by bad guys to amplify distributed network service attacks. The attacker queries your resolver with a fake source address that points back to the victim of the attack. Your resolver dutifully answers the queries and sends some nice fat packets to the victim. They never initiated the queries, but it still has to route and process the network traffic. Multiply by a bunch of open resolvers and it's real trouble for the victim.

Statistics show that between 75% and 80% of caching servers are currently open resolvers—yikes! The site dns.measurement-factory.com/tools can help you test your site. Go there, select the "open resolver test," and type in the IP addresses of your name servers. You can also test all the name servers on your network or all the servers at your site using your whos identifier.

Use access control lists in named.conf or unbound.conf to limit your caching servers to answering queries from your own users.
