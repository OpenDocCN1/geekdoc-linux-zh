# IPv6 addressing

IPv6 addresses are 128 bits long. These long addresses were originally intended to solve the problem of IP address exhaustion. But now that they're here, they are being exploited to help with issues of routing, mobility, and locality of reference.

IPv4 addresses were not designed to be geographically clustered in the manner of phone numbers or zip codes, but clustering was added after the fact in the form of the CIDRless. (Of course, the relevant "geography" is really routing space rather than physical location.) CIDR was so technically successful that hierarchical subdivision of network addresses is now assumed throughout IPv6. Your IPv ISP assigns an address prefix that you simply prepend to the local parts of your addresses, unless at your border.

The boundary between the network port and the host port of IPv6 address is fixed at /64, so there can be no disagreement or confusion about how an address network "really" is. Stated another, subnet no longer exists in the IPv6 world, although the term "subnet" lives on as synonym for "local network." Even though network numbers are always 64 bits long, routers don't pay attention to all 64 bits when making routing decisions. They can route packets based on prefixes, just as they do under.

An early scheme outlined in RFC2374 called for four standardized subdivision levels within the network portion of an IPv6 address. In light of the positive experience with letting ISPs manage their own IPv4 address subdivisions, a plan was drawn in RFC3587. ISPs are now free to set delegation boundaries they wish.

The 64-bit ID can potentially be derived from the hardware interface 48-bit MAC address.¹ This scheme allows for automatic host numbering, which is a nice feature for sysadmins since only the subnet needs to be managed.

The fact that the MAC address can be seen at the IP layer has both good and bad implications. The good part is that host number configuration can be completely automatic. The bad part is that the brand and model of interface card are encoded in the first half of the MAC address, peering eyes and hackers with code for a particular architecture will be helped along. The IPv6 standards point out that sites are not required to use MAC addresses to derive host IDs; they can use-evernumber numbering system they want.

+   1. More specifically, it is the MAC address with the two bytes 0xFFFF inserted in the middle and one bit (bit 6 of the first byte, numbering bits from the left, starting at 0) complemented; so RFC4291. The standard for converting 48-bit MAC addresses into 64-bit IP host numbers is known as EUI64.
