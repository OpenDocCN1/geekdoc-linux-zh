# Command-line arguments and functions

If you call a script without arguments or with inappropriate arguments, the script should print a usage message to remind you how to use it. The example script below accepts two arguments, validates that the arguments are both directories, and displays them. If the arguments are invalid, the script prints a message and exits with a nonzero return code. If the caller of the script checks the return code, it will know that this script failed to execute correctly.

```
#!/bin/bash

function show_usage {
    echo 'Usage: $0 source_dir dest_dir'
    exit 1
}

# Main program starts here
if [ -ne 2 ]; then
    show_usage
else # There are two arguments
    if [ -d $1 ]; then
        source_dir=$1
    else
        echo 'Invalid source directory'
        show_usage
    fi
    if [ -d $2 ]; then
        dest_dir=$2
    else
        echo 'Invalid destination directory'
        show_usage
    fi
```

We created a show_usage function to print the usage message. If the script were later updated to accept additional arguments, the usage message would only have to be changed in one place.

```
$ mkdir aaa bbb
$ sh showusage aaa bbb
Source directory is aaa
Destination directory is bbb
$ sh showusage foo bar
Invalid source directory
Usage: showusage source_dir dest_dir
```

+   Note that the error messages and usage message go to standard output. Shouldn't they go to error instead? That in fact would be more correct, but since this script isn't intended for use as a filter, the distinction is less important.
