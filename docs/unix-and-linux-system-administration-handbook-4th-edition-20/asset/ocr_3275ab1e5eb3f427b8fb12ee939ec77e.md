# traceroute: trace IP packets

Some firewalls block ICMP "time exceeded" messages entirely. If a firewall lies along the path, you won't get information about any of the gateways beyond. However, you can still determine the total number of hops to the destination-cause the packets eventually get all the way there.

Also, some firewalls may block the outbound UDP datagrams that traceroute sends to trigger the ICMP responses. This problem causes traceroute to report no useful information at all. If you find that your firewall is preventing you from running traceroute, make sure the firewall has been configured to pass UDP ports 33434-33534 as ICMP ECHO (type 8) packets.

A slow link does not necessarily indicate a malfunction. Some physical networks have a naturally high latency; UMTS/EDGE/GPRS wireless networks are of a example. Sluggishness can also be a sign of high load on the network. Inconsistent round trip times would support such a hypothesis.

Sometimes, you may see the notation ! instead of a round trip time. It indicates that the gateway sent back a "network unreachable" error, meaning it doesn't know how to route your packet. Other possibilities include H for "host unreachable" and IP for "protocol unreachable." A gateway that returns any of these error messages is usually the last hop you get to. That host has a routing problem (possibly caused by a broken network link); its static routes are wrong, or dynamic protocols fail to propagate a usable route to the destination.

If traceroute doesn't seem to be working for you or is working slowly, it may be timing out while trying to resolve the hostname of gateways through DNS. DNS is broken on the host you are tracing from, traceroute -n to request numeric output. This option disables hostname lookups; is the only way to get traceroute to function on a crippled network.

traceroute needs root privileges to operate. To be available to normal users, it must be installed root. Server Linux distributions include the traceroute command but leave the setuid bit. Depending on your environment and needs, you can either the setuid bit back or give interested users access to the command sudo.

Recent years have seen the introduction of several new traceroute-like utilities that can bypass ICMP-blocking firewalls. The PERTK Wiki for an overview of these tools at turnurl.com/y99qph. We especially use mtr, which has a top-like interface and a sort of live traceroute. Very neat!

When debugging routing issues, it can be helpful to take a look at your site from the perspective of the outside world. Several web-based routing services let you this sort of inverse traceroute right from a browser window. Thomas Kernen maintains a list of these services at traceroute.org.
