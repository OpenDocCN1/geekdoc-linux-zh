# Network hardware options

Network hardware often has configurable options that are specific to its media type and have little to do with TCP/IP per se. One example of this is modern-day Ethernet, where an interface can support 10, 100, 1000, or even 10000 Mb/s in either half-duplex or full-duplex mode. Most equipment faults to autonegation, in which both the cable and its upstream connection (usually a switch port) try to guess what the other wants to.

Historically, autonegation has worked as well as a blindfolded cowboy trying to rope a calf. Network devices play better together, but autonegation is still a common source of failure. High packet loss rates (especially for large packets) are a common artifact of failed autonegation.

If you're having problems with mysterious packet loss, turn off autonegation everywhere as your first course of action. Lock the interface and duplex on both servers and the switch ports to which they are connected. Autonegation is useful for ports in public areas where roaming laptops stop for a visit, but it serves no useful purpose for statically attached hosts other than avoiding a mess of administration.

The exact method by which hardware options like autonegation are set widely, so we defer discussion of these to the system-specific sections starting on page 484.

# route: configure static routes

The route command defines static routes, explicit routing table entries that never change, even if you run a routing daemon. When you add a machine to a local area network, you usually need to specify only a default.
