To actually mount the filesystem in versions 2 and 3, you would use a command such as

```
$ sudo mount -o rw,hard,int,br mong:/home/ben /nfs/ben
```

To accomplish the same using version 4 on a Linux system, type

```
$ sudo mount -t nfs4 -o rw,hard,int,br mong/ /nfs/ben
```

In this case, after -o specifies that the filesystem should be mounted read-write (rw), that operations should be interruptible (intr), and retries should be done in the background (bg). Table 18.9 intruder the most common options.

| Flag | Description |
| --- | --- |
| rw | Mounts the filesystem read-only (must be exported that way) |
| ro | Mounts the filesystem read-only |
| bg | If the mount fails (server doesn't respond), keeps trying it in the background and continues with other mount requests |
| hard | If a server goes down, causes operations that try to access it to block until the server comes back |
| soft | If a server goes down, causes operations that try to access it to fail and return an error, avoiding processes "hanging" on inessential mounts |
| intr | Allows users to interrupt blocked operations (and return an error) |
| nointr | Does not allow interrupts |
| retrans=n | Specifies the number of times to repeat a request before returning an error on a soft-mounted filesystem |
| time=n | Sets the timeout (in tenths of a second) for requests |
| rsize=n | Sets the read buffer size to n bytes |
| wsize=n | Sets the write buffer size to n bytes |
| sec=flavor | Specifies the security flavor |
| vers=n^ | Sets the NFS protocol version |
| proto=proto | Selects a transport protocol; must be tcp for NFS version 4 |

+   A. The vers flag is listed in the mount pages on Linux systems, using it results in an error. To request version 4 mount, use mount -t nfs4 instead.

Filesystems mounted hard (the default) cause processes to hang when servers go down. This behavior is particularly bothersome when the processes in question are standard daemons, so we do not recommend critical system binaries over NFS.
