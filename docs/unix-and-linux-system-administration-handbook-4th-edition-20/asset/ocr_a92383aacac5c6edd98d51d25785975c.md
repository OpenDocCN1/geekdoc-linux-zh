# Chapter 8 Storage

ZFS has an especially nice implementation of read caching that makes good use of SSDs. To set up this configuration, just add the SSDs to the storage pool as vdevs of type cache. The caching system uses an adaptive replacement algorithm developed at IBM that is smarter than a normal LRU (least used) cache. It knows about which blocks are referenced as well as their recency, so reads of large files are not posted to wipe out the cache.

Hot spares are handled as videos of type spare. You can add the same disk to multiple storage pools; whoever experiences a disk failure gets to claim the spare disk.

# 8.11 STORAGE AREA NETWORKING

There are several ways to attach storage resources to a network. Chapter 18, The Network File System, describes NFS, the traditional UNIX protocol used for file sharing. Windows systems use the protocol known as CIFS or SMB for similar purposes. The predominant implementation of CIFS for UNIX and Linux is Samba; Sharing files with Samba and CIFS on page 114 for more details.

NFS and CIFS are examples of "network-attached storage" (NAS) systems. They are high-level protocols, and their basic operations are the lines of "open file X and send me the 4KB of data" or "adjust the ACL on file Y as described in this request." These systems are good at arbitrating access to filesystems that clients want to read or write on.

A storage area network (SAN) is a lower-level system for abstracting storage, one that makes network storage look like a local hard disk. SAN operations consist primarily of instructions to read or write particular disk blocks (though, of course, the block address is virtualized by the server in some way). If a client wants to use SAN storage to hold a filesystem, it must provide its own filesystem implementation. On the other hand, SAN volumes can also be used to swap areas or other data that doesn't need the structure or overhead of a filesystem.

With the exception of HP's VxFS, mainstream filesystems are not designed to be updated by multiple clients that are aware of each other's existence (at least, not at the level of raw disk blocks).² Therefore, SAN storage is not typically used as a way of sharing files. Instead, it's a way to replace local hard disks with centralized storage resources.
