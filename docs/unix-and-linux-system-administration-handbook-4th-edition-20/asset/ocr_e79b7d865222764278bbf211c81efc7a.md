# Disk device files

A newly added disk is represented by device files in /dev. See page 150 for general information about device files.

All our examples create these files for you automatically, but you still need to know where to look for the device files and how to identify the ones that correspond to your device. Formatting the wrong device file is a rapid route to disaster. Table 8.2 summarizes the device naming conventions for disks in our example systems. Instead of showing the abstract pattern according to which devices are named, Table 8.2 simply shows a typical example for the name of the system's first disk.

# Table 8.2 Device naming standards for disks

| System | Block device | Raw device | Partition |
| --- | --- | --- | --- |
| Linux | /dev/sda | not used | /dev/sda1 |
| Solaris | /dev/diskc0t0ds2 | /dev/rdsk/c0t0ds2 | /dev/diskc0t0ds0 |
| HP-UX | /dev/disk/disk0 | /dev/diskisk | /dev/disk0_p1 |
| AIX | /dev/hdisk0 | /dev/hdisk0 | not used |

+   a. HP-UX uses Solaris-style device names for legacy compatibility.
b. Itanium-based systems only; non-Itanium systems have no partitions.

The block and raw columns show the path for the disk as a whole, and the partition column shows the path for an example partition.

# Disk devices for Linux

Linux disks are assigned as the kernel enumerates the various interfaces and devices on the system. Adding a disk can cause existence to change their names. In fact, rebooting the system can change names. Never make changes without verifying the identity of the disk you're working on, or on a stable system.

Linux provides a couple of ways around the “dancing names” issue. Subdirectories under /dev/disk list by various stable characteristics such as their manufacturer ID or connection information. These device names (which are really links back to /dev/sd*) are stable, but they're long and awkward.

At the level of filesystems and disk arrays, Linux uses unique IDs to persistently identify objects. In many cases, the existence of these long IDs is cleverly concealed so that you don't have to deal with them directly.

+   5. To deal with this issue, Linux uses UUIDs in the /etc/fstab instead of device names; see page 262.
