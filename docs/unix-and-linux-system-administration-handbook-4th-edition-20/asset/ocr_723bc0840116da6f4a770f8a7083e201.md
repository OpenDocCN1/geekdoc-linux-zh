# Chapter 12 Software Installation and Management

Behind the scenes, AI creates three XML-formatted manifest files.

+   * The AI manifest file contains disk partitioning and packaging details, roughly equivalent to a JumpStart profile file.
* The SC manifest file contains system configuration details, such as time zone and account information, like JumpStart's sysidcfg file.
* The criteria file matches the other two manifest files to client devices, just like the rules file in JumpStart.

If you find XML intellectually stimulating, you can edit the manifests by hand to create custom configurations. Normally, you just run `installadm` to add, remove, enable, disable, and list new installation services and create custom client configurations.

For example, the following `installadm` command creates a new installation service that you can use to install a client. In this example, the OpenSolaris 909 release OS image is used as an installation source. The -c 10 option makes the DHCP server up to 10 dynamic addresses at 192.168.1.200. The installation is copied to /export/install.

```
solaris$ sudo installadm create-service -s ~/osol-0906-x86.iso -i 192.168.1.200 -c 10 /export
Setting the target area to /export/
Warning: Using default manifest <usr/share/auto_install/default.xml>

Created DHCP Server
Created DHCP configuration file.
Created dhcptab
Added "local" macro to dhcptab
Added server macro to dhcptab - opensolaris.
DHCP server started.
dhthtam: Unable to signal the daemon to reload the dhcptab

Created network table.

Converting /tftp/boot/pxegrub.I86PC.OpenSolaris-1

```

To install the client, perform a network boot as usual. The server uses the predefined rules to pick an installation image, download it to the client, and start the installation.

Automated Installer is changing rapidly. After installing the package, refer to /usr/share/doc/auto_install/index.html for current details.
