# Split DNS and the view statement

Many sites want the internal view of their network to be different from the view seen from the Internet. For example, you might reveal all of a zone's hosts to internal users but restrict the external view to a few well-known servers. Or, you might expose the same set of hosts in both views but provide additional (or different) records to internal users. For example, the MX records for routing might point to a single hub machine from outside the domain but to individual workstations from the perspective of internal users.

See page 462 for more information about private address spaces.

The view statement packages up a couple of access lists that control which clients see which, options that apply to all the zones in the view, and finally, the zones themselves. The syntax is

```
view-name {
  match-clients { address_match_list }; } [any]
  match-destinations { address_match_list }; } [any]
  match-recursive-only yes | no; [no]
  view_option;
  zone_statement; ...
}
```

Views have a match-clients clause that filters the source IP address in the query packet and is typically used to serve internal and external views of a site's DNS data. For finer control, you can also filter on the query destination address and require recursive queries.
