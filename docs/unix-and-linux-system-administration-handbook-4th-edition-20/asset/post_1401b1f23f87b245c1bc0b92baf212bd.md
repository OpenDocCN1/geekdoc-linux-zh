## The dnslookup router

The dnslookup router is typically used for outgoing messages. It looks up the MX record of the recipient's domain and handles the message to an SMTP transport for delivery. Here is an instance called remoteusers:

```
driver = dnslookup
domains = !+example.com
transport = my_remote_delivery
```

The dnslookup code looks up the MX records for the address. If there are none, it tries the A record. A common extension to this router is to prohibit delivery to IP addresses; a prime example is the RFC1918 private addresses that cannot be routed on the Internet. See the ignore_target_hosts option for more information.

## The manualroute router

The flexible manualroute driver can pretty much route email in whatever way you want. The routing information can be a table of rules matching recipient domain (route_list) or a single rule that applies to all domains (route_data).

Below are two examples of manualroute instances. The first example implements the "smart host" concept, in which all outgoing nonlocal mail is sent to a central ("smart host") host for processing. This instance is called smarthost and applies to all recipients' domains that are not the (! character) in the local_domains list.

```
driver = manualroute
domains = !+local_domains
transport = remote_snmp
route_data = smarthost.example.com
```

The router instance below, firewall, uses SMTP to send messages to hosts inside the firewall (perhaps after scanning for spam and viruses). It looks up the routing data for each recipient domain in the CDB database that contains the names of local hosts. (You must build Exim with the LOOKUP_CDB option to be able to use CDB.)

## The redirect router

The redirect router does address rewriting, such as that called for in a user's .forward file. It usually does not assign the rewrite-address to a transport; that task is left to other routers in the chain. The first instance shown below, system_aliases, looks up aliases with a linear search of /etc/aliases file. That's fine for a small aliases file, but if yours is huge, replace that linear search with a database lookup. The second instance, forward, verifies that mail is addressed to a local user, then checks user's .forward file.

```
system_aliases:
driver = redirect
data = ${lookup($local_part)}
```

```
forward:
driver = redirect
file = $home/.forward
no_verify
```

The check_local_user option ensures that the recipient is a valid user. The no_verify says not to verify that the address to the forward file redirects the message; just ship it.

## Per-user filtering via .forward files

Exim allows not only forwarding through .forward files, but also filtering based on the contents of a user's .forward file. It supports its own filtering as well as Sieve filtering which is standardized by the IETF. If the first line of a user's .forward file is the subsequent filtering commands (there are about 15 of them) can be used to determine where the message should be delivered. For example:

```
$header_subject contains SAGE or $header_subject contains sysadmin
then
save $home/mail/sysadmin
```

## Transports

Routers decide where messages should go, and transports actually take them there. Local transports typically append to a file, pipe to a local program, or speak the LMTP protocol to IMAP servers. There are five transports: appendfile, lmtp, smtp, retry, and pipe; we define appendfile and smtp. The retry is typically used to send vacation messages, and the pipe transport hands messages as input to a UNIX pipe. As with routers, you must define instances of transports, and it's fine to have multiple instances of the same type of transport. Order is significant for routers, but not for transports.

## The appendfile transport

The appendfile driver stores messages in mbox, Maildir, or mailstore in a specified file or directory. You must have included the appropriate mailbox formats when you compiled; they are commented out of the file by default. The following example defines the my_local_delivery transport (an instance of the appendfile transport) referred to in the localusers router on page 82.

```
my_local_delivery:
driver = appendfile
file = /var/mail/$local_part
delivery_date_add
envelope_to_add
return_path_add
group = mail
mode = 0660
```

The various *add lines add headers to the message. The group and mode clauses ensure that the transport agent can write to the file.

## The smtp transport

The smtp transport is the workhorse of any mail system. Here, we define two instances, one for the standard SMTP port (25) and one for the mail submission port (587).

```
my_remote_delivery:
driver = smtp

my_remote_delivery_port587:
driver = smtp
port = 587
headers_add = X-processed-by: MACRO_HEADER
```

The second instance, my_remote_delivery_port587, specifies the port and also a header to be added to the message that includes an indication of outgoing port. MACRO_HEADER would be defined elsewhere in the configuration file.

## Retry configuration

The retry section of the configuration file must exist or Exim will never attempt redelivery of messages that could not be delivered on the first attempt. You can specify three intervals, each less frequent than the previous one. After the last interval has expired, messages bounce back to the sender as undeliverable. retry understands the suffixes m, h, d, and w to indicate minutes, hours, days, and weeks. You can specify different intervals for different hosts or domains.

Here's what a retry section looks like:

```
begin retry
* F, 2h, 15m; F, 24h, 1h; F, 4d, 6h
```

This example means, "For any domain, an address that fails temporarily should be retried 15 minutes for 2 hours, then every hour for the next 24 hours, then every 6 hours for 4 days, and finally, bounced as undeliverable."

## Rewriting configuration

The rewriting section of the configuration file starts with begin rewrite. It's used to fix addresses, not to reroute messages. For example, you could use it on your outgoing addresses:

- To make mail appear to be from your domain, not from individual hosts
- To map usernames to a standard format as First.Last

Rewriting should not be used on addresses in incoming mail.

## Local scan function

If you want to further customize exim, for example, to filter for the latest and greatest virus, you can write a C function to do your scanning and install it in the local_scan section of the config file. Refer to the Exim documentation for examples that show how to do this.
