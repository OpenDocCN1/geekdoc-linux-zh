Each device has a SCSI address or "target number" that distinguishes it from the other devices on the bus. Target numbers start at 0 and go up to 7 or 15, depending on whether the device is narrow or wide. The SCSI controller counts itself as a device and is usually 7. All other devices must have their target numbers set to unique values. It is a common error to forget that the SCSI controller has a target number and to set a device to the same target number as the controller.

If you're lucky, a device will have an external thumbwheel with which the target number can be set. Other ways of setting the target number are DIP switches and jumpers. If it is not obvious how to set the target number on a device, look up the manual on the web.

The SCSI standard supports a form of subaddress called "logical unit number." Each target can have several logical units inside it. A plausible example is a drive array with several disks but only one SCSI controller. A SCSI device contains only one logical unit, the LUN defaults to 0.

The use of logical unit numbers is generally confined to large drive arrays. When you hear "SCSI unit number," you should assume that it is really a target number that's being discussed unless proven otherwise.

From the perspective of a sysadmin dealing with legacy SCSI hardware, here are the important points to keep in mind:

+   - Don't worry about the exact SCSI versions a device claims to support; look the connectors. If two SCSI devices have the same connectors, they are compatible. That doesn't necessarily mean that they can achieve the same speeds, however. Communication will occur at the speed of the slower device.
- Even if the connectors are different, the devices can still be compatible with an adapter if both connectors have the same number of pins.
- Many older workstations have internal SCSI devices such as tape and floppy disks. Check the listing of current devices before you reboot to add a new device.
- After you have added a new SCSI device, check the listing of devices discovered by the kernel when it reboots to make sure that everything you expect is. Most SCSI drivers do not detect multiple devices that have the same SCSI address (an illegal configuration). SCSI address conflicts lead to strange behavior.
- If you see flaky behavior, check for a target number count or a problem with bus termination.
- Remember that your SCSI controller uses one of the SCSI addresses.
