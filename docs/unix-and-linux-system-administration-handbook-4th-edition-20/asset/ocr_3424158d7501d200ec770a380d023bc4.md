The makedbm command generates NIS maps from flat files. However, you need
not invoke it directly; a Makefile in /var/py generates all the com-\mon NIS maps. After you modify a system file, cd to /var/py and run make. The
command checks the modification time of each file against the modifica-
tions of the maps derived from and runs makedbm for each map that
eeds to be rebuilt.

HP-UX systems, a command called ypmake is used instead of make.

The ypsfr command copies maps from the master server to the slave servers.
ypsfr is a pull command; it must be run on each slave server to make that server
import the map. Slaves usually execute ypfr every so often to justify that they
have the most recent maps; you use cron to control how often this is.

The default implementation of map copying is somewhat inefficient. In most
a daemon called ypsfr (or rc.ypsfr) can be run on the master server
to speed responses to ypsfr requests. ypsfr sidesteps the normal NIS protocol
and handles out copies of the map files. Unfortunately, map files are stored
with different database formats and byte ordering on different systems, so the use
of ypsfr introduces some potential incompatibilities.

ypush is a "push" command that's used on the master server. It actually does not
transfer any data but rather instructs each slave to execute a ypsfr. The yndash
command is used by the Makefile in the NIS directory to ensure that fully up-
datas are mapped to slaves.

The special map called ypsvers does not correspond to any flat file. This map
contains a list of all the servers of the domain. It is automatically constructed when
domain is set up with pinion. Its contents are examined when the master
server needs to distribute maps to slaves.

After initialization, the only active components of the NIS system are the
ypserv and ybind daemon. ypserv runs only on servers (both master and
save); it accepts queries from clients and answers them by looking up informa-
the hashed map files.

ybind runs on every machine in the NIS domain, including servers. The C-
body contacts the local ybind daemon when it needs to answer an administra-
query (provided that /etc/nswitch.conf says to do so). ybind locates a
ypserv in the appropriate domain and returns its identity to the C library, which
contacts the server directly.
