Now that we've elaborated the basics of rdist, let's look at how it works. Like make, rdist looks for a control file (Distfile or distfile) in the current directory. rdist -f distfile specifies the control file's name. Within the control file, tabs, spaces, and newlines are used interchangeably as separators. Commands are introduced with a pound sign (#).

The meat of a Distfile consists of statements of the form

```
label: pathnames -> destinations commands
```

The label field associates a name with the statement. From the shell, you can rdist label distribute only the files described in a particular statement.

The pathnames and destinations are lists of files to copy and hosts to copy them, respectively. If a list contains more than one entry, the list must be surrounded with parentheses and the elements separated by whitespace. The pathname can include shell-style globbing characters (e.g., /usr/man/man[123] or /usr/lib/*). The notation -user is also acceptable, but it is evaluated separately by source and destination machines.

By default, rdist copies the files and directories listed in pathnames to the each destination machine. You can modify this behavior by equivalently a sequence of commands and terminating each with a semicolon.

The following commands are understood:

- - install options [destdir];
- notify namelist;
- except pathlist;
- except_pat patlist;
- special [pathlist] string;
- cmdspecial [pathlist] string;

The install command options affect the way rdist copies files. Options typically control the treatment of symbolic links, the correctness (vs. efficiency) of rdist's difference-checking algorithm, and the way that deletions are handled. The options, which must be preceded by -o, consist of a comma-separated list of options. For example, the line

```
install -oremove,follow;
```

makes rdist follow symbolic links (instead of just copying them as links) and removes existing files on the destination machine that have no counterpart on the source machine. See the rdist man page for a complete list of options. The defaults are always what you want.

## Chapter 19 Sharing System Files

The name “install” is somewhat misleading, since files are copied whether or not an install command is present. Options are specified as they would be on the rdist command line, but when included in the Distfile, they apply only to the set of files handled by that install command.

The optional dest specifies an installation directory on the destination hosts. By default, rdist uses the original pathnames.

The notify command takes a list of email addresses as its argument. rdist sends mail to these addresses whenever a file is updated. Any addresses that do not contain an at @ are suffixed with the name of the destination host. For example, rdist uses “pete” to “pete@anchor” when reporting a list of files updated host.

See the section starting on page 48 for more information about regular expressions.

The except and except_pat commands remove paths from the list of files to be copied. Arguments to except are matched literally, and those of except_pat are interpreted as regular expressions. These exception commands are useful because rdist, like make, allows macros to be defined at the beginning of its control flow. You might want to use a similar list of files for several statements, specifying only the additions and deletions for each host.

The special command executes a shell command (the string argument) on each remote host. If a pathlist is present, rdist executes the command once copying each of the specified files. Without a pathlist, rdist executes the command after every file. special is similar, but it executes the shell once after all copying is complete. The contents of the pathlist are passed to the shell as an environment variable.

Here’s a example of a Distfile:

```
SYS_FILES = /(etc/passwd /etc/group /etc/mail/aliases)
GET_ALL = (chimchim lollipop bardarkon)
GET_SOME = (whammo piff)

all: ${SYS_FILES} -> ${GET_ALL}
notify;
special: ${SYS_FILES} -> ${GET_ALL}

some: ${SYS_FILES} -> ${GET_SOME}
except;
```

## rsync: transfer files more securely

rsync, written by Andrew Tridell and Paul Mack, is similar in spirit to rdist but with a different focus. It is a bit like a soupe-up version of scp that is superb about links, modification times, and permissions. It is network efficient than rdist because it looks inside files and attempts to transmit only the differences.

From our perspective, the main advantage of rsync is the fact that receiving machines can run the server process out of xinetd or inetd. The server (actually just a different mode of rsync, which must be installed on both clients) can restrict access to set directories and require the master to prove its identity with a password. Without ssh access is necessary, you can set up rsync to distribute system files without making too many compromises. (However, if you prefer to use ssh instead of an inet-based server, rsync lets you do that.) What's more, rsync can also run in pull mode (pulling files down the rsync server rather than letting the server push files to the local system), which is even more secure (see the section on pulling files, page 727).

Unfortunately, rsync isn't as flexible as rdist, and its configuration is more sophisticated than distante's. You cannot execute arbitrary commands on the clients, nor can rsync to multiple hosts at once.

As an example,

```
# rsync -goat --password-file=/etc/passwd.rsync.pwd /etc/passwd lollipop::sysfiles
```

transfers /etc/passwd to the machine lollipop. The -goat options preserve the permissions, ownership, and modification times of file. The double column in lollipop::sysfiles makes rsync contact the remote directly on port 873 instead of using ssh. The password stored in /etc/rsync.pwd authenticates the connection.

- 1. Although the password is encrypted for transmission across the network, the transferred files are not. If you use ssh as the transport (rsync -goat -e ssh /etc/passwd/etc/shadow lollipop/etc - note the single colon), the connection will be encrypted, and ssh will have to be configured not to require a password.
