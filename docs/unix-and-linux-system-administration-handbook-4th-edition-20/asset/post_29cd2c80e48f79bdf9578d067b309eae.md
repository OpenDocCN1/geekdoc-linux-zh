
The default config file is well commented. The comments and the cupsd.conf man page are good enough that we won't elaborate the same information here.

CUPS reads its configuration file only at startup time. If you change the contents of cupsd.conf, you have to restart cups for changes to take effect. If you make changes through cupsd's web GUI, it restarts automatically. To restart cupsd from the command line, just run /etc/init.d/cups restart or /etc/init.d/cups restart, whomever is present.

You can also configure the system through desktop-specific GUIs tools. For example, under KDE, you can use the KDE Print Manager, accessible through the KDE control center. We found some problems with the KDE Print Manager during our testing, however. For example it complained about not understanding certain options found in some distributions' default cupsd.conf files. The browser GUI is safe and certainly authoritative.

## Network print server setup

If you're having trouble printing from the network, go into the browser-based CUPS GUI and make sure you've checked all the right boxes. Possible problem areas include an unpublished printer, a CUPS server that isn't broadcasting its printers to the network, or a CUPS server that won't accept network print jobs.

If you're editing the cupsd.conf file directly, you'll need to make a couple of changes. First, change

``````
<Location />
Order Deny,Allow
Deny From All
Allow From 127.0.0.1
</Location>
```

to

``````
<Location />
Order Deny,Allow
Deny From All
Allow From 127.0.0.1
Allow From netaddress
</Location>
```

Replace netaddress with the IP address of the network from which you want to accept jobs (e.g., 192.168.0.0). Look for the BrowseAddress keyword and set it to the broadcast address on that network plus the CUPS port; for example,

```
BrowseAddress 192.168.0.255:631
```

These steps tell the server to accept requests from any machine on the designated subnet and to broadcast what it knows about the printers it's serving to every CUPS daemon on that network. That's it! Once you restart cupsd, it comes back as a server.

## Chapter 26 Printing

### Printer autfiguration

You can use CUPS without a printer (for example, to convert files to PDF or fax format), but its typical role is to manage real printers. In this section we review the ways in which you can deal with the printers themselves.

In some cases, adding a printer is trivial. CUPS tries to autodetect USB printers when they're plugged into the system and figure out what to do with them.

Printer manufacturers typically supply installation software that does most of the setup work for Windows and even Mac OS (which also uses CUPS). However, few vendors explicitly support Linux.

Even if you have to do configuration work, adding a printer is often no more painful than plugging in the hardware, connecting to the CUPS interface at localhost:631/admin, and answering a few questions. KDE and GNOME come with their printer configuration widgets, which you may prefer to the CUPS interface. (We like the CUPS GUI.)

If someone else adds a printer and one or more CUPS servers running on the network know about it, your CUPS server will learn of your existence. You don't have to explicitly add the printer to the local inventory or copy PPDs to your machine.

## Network printer configuration

Network printers—that is, printers whose hardware interface is an Ethernet—need configuration of their own to be proper citizens of the TCP/IP network. In particular, they need to know their own IP addresses and netmasks. That information is usually conveyed in one of two ways.

Modern printers can get this information across the network from a BOOTP or DHCP server, and this method works well in environments that have many printers. See DHCP: Dynamic Host Configuration Protocol on page 469 for more information about DHCP.

Alternatively, you can assign the printer a static IP address from its console, which usually consists of a set of buttons on the printer's front panel and a one-line display. Fumble around the menus until you discover where to set the IP address (If there is a menu option to print the menus, use it and put the printer underneath for future reference.)

A few printers give you access to a virtual console through a serial port. It's a nice idea, but the total amount of work is probably more than suffering through the front-panel interface. The principles are the same.

Once configured, network printers usually have a web console accessible from a browser. However, printers need to have an IP address and be up and running on the network before you can get to them this way, so this interface is unavailable when you might want it most.

After your printer is on the network and you can ping it, make sure to secure it as described in the section Secure your printers on page 1081.

## Printer configuration examples

Let's add the parallel printer groucho and the network printer fezmo from the command line.

```
$ sudo lpadmin -p groucho -E -v parallel:/dev/lp0 -m pxicolor.ppd
$ sudo lpadmin -p fezmo -E -v socket:/192.168.0.12 -m laserjet.ppd
```

Groucho is attached to port /dev/lp0 and fezmo is at IP address 192.168.0.12. We specify each device in the form of a universal resource indicator (URI) and choose an appropriate PPD for the ones in /usr/share/cups/model

As long as cups has been configured as a network server, it immediately makes the new printers available to other clients on the network. No restart is required.

CUPS accepts a variety of URIs for printers. Here are a few examples:

- ipp/zoe.canary.com/ipp
- lpd://riley.canary.com
- serial://dev/ttyS0?baudrate=9600+parity=even+bits=7
- socket/gillian.canary.com:9100
- usb:/XEROX/Phaser#206120?serial=YGG210547

Some types take options (e.g., serial) and others don't. Lpinfo lists the devices your system can see and the types of URIs that CUPS understands.

## Service shutdown

If you want to remove a printer or class, that's easily done with lpadmin -x.

```
$ sudo lpadmin -x fezmo
$ sudo lpadmin -x haemer
```

OK Service Smart, but what if you just want to disable a printer temporarily? It's a bad idea to accept jobs for extended downtime. For brief interruptions that would be invisible to users (e.g., changing a toner cartridge), use cupsdisable.

## Other configuration tasks

Today’s printers are infinitely configurable, and CUPS lets you tweak a variety of features through its web interface and through the **lpadmin** and **lpoptions** commands. As a rule of thumb, **lpadmin** is for system-wide tasks and **lpoptions** is for per-user tasks.

If it happens, *bash*’s version of **enable** enables and disables built-ins, so you can use it to disable itself with **enable -n enable.
