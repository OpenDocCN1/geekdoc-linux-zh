# HP-UX DHCP configuration with other network parameters, you turn on the use of DHCP at boot time by setting variables in /etc/rc.config. In this case, the variable names start with DHCP_ENABLE. The index [0] refers to the first interface, [1] to the second, and so on. For example,

DHCP_ENABLE[0]=1

sets the first network interface to DHCP. It will get its IP address, netmask, and other parameters from the DHCP server. Setting the variable to 0 would disable DHCP; you'd have to assign a static address in the config file. No DHCP_ENABLE clause is present, the variable defaults to 1. The /bin/auto_parms script does the real work of contacting the DHCP server. The program enters parameters secured by auto_parms into the config file, which boot-time information is taken.

# HP-UX dynamic reconfiguration and tuning

In Solaris, you can use ndd to tune many different networking parameters. When used instantaneously, ndd values change permanently, entering them in /etc/rc.config is read at boot time. On an HP-UX system, ndd -h (help) option is quite useful. Without arguments, it lists all the parameters you can tune. If you specify a variable name, ndd -h describes its minimum, maximum, and default values. See page 498 for more details about ndd.

# HP-UX security firewalls, filtering, and NAT

ndd's output claims that this version of HP-UX allows forwarding of source-routed packets. But that may be the kernel preference, but in fact the file /etc/rc.config/config disables this behavior:

TRANSPORT_NAME[2]=ip
NAME[2]=ip_forward_routed
VALUE[2]=0

The 2 here indicates the third of ten possible variables to be set in config. For the next variable you wanted to change, you would add another copy of the same lines with appropriate values and with 3 instead of 2. Unfortunately, only 10 parameters can be set through config. To view and change the value of the ip_forward_routed variable by hand, use ndd-get and ndd-set (the syntax is slightly different from that on Solaris systems):

$ ndd -get /dev/ip ip_forward_routed
0
$ ndd -set /dev/ip ip_forward_routed 1
$ ndd -get /dev/ip ip_forward_routed

# HP-UX security, firewalls, filtering, and NAT

Table 14.12 shows HP-UX's default behavior with regard to network issues. For a brief description of the implications of these behaviors, see Security issues on page 242. You can modify most of them with ndd.

# Table 14.12 Security-related network behaviors in HP-UX

| Feature | Default | Control through ndd |
|---|---|---|
| IP forwarding | dynamic* | Set ip_forwarding: 0 = off, 1 = on, 2 = dynamic |
| ICMP redirects | obeys** | Set ip_redirect_interval to 0 to disable |
| Source routing | ignores | Set ip_forward_src_routed to 1 to enable |
| Broadcast ping (forward) | blocked | Set ip_forward_directed_broadcasts |
| Broadcast ping (respond) | ignores | Set ip_respond_to_echo_broadcast |

* a. With >1 network interface; otherwise.
** b. The redirect entries are preserved for five minutes.

# Chapter 14 TCP/IP Networking

Like Solaris, HP-UX includes Darren Reed's IPFilter package for packet filtering and NAT translation. See IPFilter for UNIX systems on page 939 and Solaris NAT on page 500 for some additional detail. The IPFilter part is all the same, HP-UX configures the package differently at startup. Instead of using swadm to enable IPFilter, edit /etc/rc.config/ipconf and turn on the options you want. Configuration files for ipf and ipnat should be in /etc/rc.config.

# 14.15 AIX Networking

Rather than keeping network information in text files or scripts, AIX are in the Object Data Manager (ODM) attribute/value database. Another layer of group associates these property lists with specific devices (driver instances) and binds the drivers to the configuration.

The Object Data Manager on page 432 describes the ODM system. The overall scheme is rather complex, and it allows access to the network configuration at multiple layers. Table 14.13 shows a variety of AIX commands for setting an interface address. They vary chiefly in whether they affect the running configuration, the boot-time configuration, or both.

# Table 14.13 Eight ways to set an interface's IP address in AIX

| Command | Affects Current? | Affects Boot? |
|---|---|---|
| smitty mktcpip (and fill out the form) | Yes | Yes |
| mktcpip -i en3 -a 192.168.0.1 | Yes | Yes |
| chdev -i en3 -a netaddr=192.168.0.1 | Yes | Yes |
| chdev -i en3 -a netaddr=192.168.0.1 -P | No | No |
| chdev -i en3 -a netaddr=192.168.0.1 -T | Yes | No |
| ifconfig en3 inet 192.168.0.1 | Yes | No |
| odmchange -o CuAt_name=en3 AND attribute=netaddr < config! | Yes | Yes |
| echo 'Hey! I set the network address!' | No | No |

+   a. odmchange requires an attribute/value list as input. You cannot specify attribute values on the command line.
