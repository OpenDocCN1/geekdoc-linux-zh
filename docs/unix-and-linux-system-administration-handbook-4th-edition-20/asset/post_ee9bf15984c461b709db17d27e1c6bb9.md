# Chapter 20 Electronic Mail

.forward.to.sandiego, silently failed to forward her mail from a small site at which she did not receive mail. It was months before she realized that "I never got your mail" was her own fault and not a valid excuse.

You can run many of the restrictive file access policies mentioned above with the DontBlameSendmail option. Don't do that.

## Safer mail to files and programs

We recommend that you use smrush instead of /bin/sh as your program mailer and that you use mail.local instead of /bin/mail as your local mailer. Both programs are included in the sendmail distribution. To incorporate them into your configuration, add the lines

```
FEATURE(`smrush`, `path-to-smrush`)
FEATURE(`local_ltmp`, `path-to-mail.local`)
```

to your .nc file. If you omit the explicit paths, the commands are assumed to live in /usr/libexec. When you use sendmail's conf-EBINDIR option to change the default location of the binaries to whatever you want, Table 20.14 may help you find where our friendly vendors have stayed agents.

### 20.14 Location of sendmail's restricted delivery agents

| OS | smrush | mail.local | sm.bin |
| :--- | :--- | :--- | :--- |
| sendmail | /usr/libexec | /usr/libexec | /usr/adm |
| Ubuntu | /usr/lib/sm.bin | /usr/lib/sm.bin | /usr/adm |
| SUSE | /usr/lib/sendmail.d/bin | /usr/lib/sendmail.d/bin | |
| Red Hat | /usr/sbin | | /etc/smrush |
| Solaris | /usr/lib | /usr/lib | /var/adm |
| HP-UX | /usr/sbin | | /usr/adm⁴ |
| AIX | /usr/sbin | | /usr/adm³ |

> a. This directory does not exist on either HP-UX or AIX, so you must create it.

smrush is a restricted shell that executes only the programs contained in one directory (/usr/adm/sm.bin by default). smrush ignores user-specified paths and tries to find any requested commands in its own known-safe directory. smrush blocks the use of certain shell metacharacters as <, the input direction. Symbolic links are allowed in sm.bin, so you don't need to duplicate copies of the programs you allow. The vacation program is a good candidate for sm.bin. Don't put procmail there; it's insecure.

Here are some example commands and their smrush interpretations:

```
vacation eric          # Executes /usr/adm/sm.bin/vacation eric
cat /etc/passwd       # Rejected, cat not in sm.bin
vacation eric < /etc/passwd # Rejected, no < allowed
```

## Privacy options

sendmail's SafeFileEnvironment option controls where files can be written when email is redirected to a file by aliases or a .forward file. It causes sendmail to execute a chroot system call, making the root of the filesystem no longer / but safe or whatever path you specified in the SafeFileEnvironment option. An alias directed to the /etc/passwd file, for example, would really be written to /safe/etc/passwd.

The SafeFileEnvironment option also protects device files, directories, and other special files by allowing writes only to regular files. Besides increasing security, this option ameliorates the effects of user mistakes. Some sites set the option to /home to allow access to home directories while keeping system files off-limits.

Mailers can also run in a chrooted directory.

sendmail also has privacy options that control:

- What external folks can determine about your site through SMTP
- What you require of the host on the other end of an SMTP connection
- Whether your users can see or run the mail queue

Table 20.15 lists the possible values for the privacy options as of this; see the file doc/op.ps in the distribution for current information.

| Value | Meaning |
| --- | :--- |
| public | Does no privacy/security checking |
| needhello | Requires SMTP HELO (identifies remote host) |
| noexpn | Disallows the SMTP EXPN command |
| novrry | Disallows the SMTP VRFY command |
| needexpnhello | Does not expand addresses (EXPN) without a HELO |
| needvrfyhelo | Does not verify addresses (VRFY) while at HELO |
| noberv | Disallows verbose mode for EXPN |
| restrictmaq | Allows only mqueue directory's group to see the queue |
| restrictgr | Allows only mqueue directory's owner to run the queue |
| restrictexpand | Restricts info defined by the -bv and -v flags |
| noertrn | Disallows asynchronous queue runs |
| authwarnings | Adds warning if outgoing message merges formed |
| noreceipts | Turns off delivery notification for success receipt receipts |
| nobodyreturn | Does not return body in a DSN |
| goaway | Disables SMTP status queries (EXPN, VRFY, etc.) |

20.15 Values of the PrivacyOption variable:

- a. Verbose mode follows .forward files when an EXPN command is given and reports more information on the whereabouts of a user's mail. Use nober or, better yet, noexpn, on any machine exposed to the outside world.
- b. Unless except by root or the TrustedUser.
- c. ETRN is an SMTP command intended for use by dial-hosts. It triggers that.

## TLS: Transport Layer Security

TLS, another encryption/authentication system, is specified in RFC3207. It is implemented in sendmail as an extension to SMTP called STARTTLS. You can even use both SASL and TLS.

TLS is a bit harder to set up and requires a certificate authority. You can Verify-Sign bucks to issue you certificates (signed public keys identifying an entity), set up your own certificate authority, or go to OpenCA. Strong authentication is used in place of a hostname or IP address as the authorization for relaying mail or for accepting a connection from a host in the first place. An entry such as

```
TLS_Srv:secure.example.com   ENCR:112
TLS_Clt:laptop.example.com   PERM+VERIFY:112
```

in the access_db indicates that STARTTLS is in use and that to the domain secure.example.com must be encrypted with at least 112-bit encryption keys. Email from a host in the laptop.example.com domain should be accepted only if the client has authenticated itself.

Symbolic links are allowed in sm.bin, so you don't need to duplicate copies of the programs you allow. The vacation program is a good candidate for sm.bin. Don't put procmail there; it's insecure.

Here are some example commands and their smrush interpretations:

```
vacation eric          # Executes /usr/adm/sm.bin/vacation eric
cat /etc/passwd       # Rejected, cat not in sm.bin
vacation eric < /etc/passwd # Rejected, no < allowed
```

## Privacy options

sendmail's SafeFileEnvironment option controls where files can be written when email is redirected to a file by aliases or a .forward file. It causes sendmail to execute a chroot system call, making the root of the filesystem no longer / but safe or whatever path you specified in the SafeFileEnvironment option. An alias directed to the /etc/passwd file, for example, would really be written to /safe/etc/passwd.

The SafeFileEnvironment option also protects device files, directories, and other special files by allowing writes only to regular files. Besides increasing security, this option ameliorates the effects of user mistakes. Some sites set the option to /home to allow access to home directories while keeping system files off-limits.

Mailers can also run in a chrooted directory.

sendmail also has privacy options that control:

- What external folks can determine about your site through SMTP
- What you require of the host on the other end of an SMTP connection
- Whether your users can see or run the mail queue

Table 20.15 lists the possible values for the privacy options as of this; see the file doc/op.ps in the distribution for current information.

| Value | Meaning |
| --- | :--- |
| public | Does no privacy/security checking |
| needhello | Requires SMTP HELO (identifies remote host) |
| noexpn | Disallows the SMTP EXPN command |
| novrry | Disallows the SMTP VRFY command |
| needexpnhello | Does not expand addresses (EXPN) without a HELO |
| needvrfyhelo | Does not verify addresses (VRFY) while at HELO |
| noberv | Disallows verbose mode for EXPN |
| restrictmaq | Allows only mqueue directory's group to see the queue |
| restrictgr | Allows only mqueue directory's owner to run the queue |
| restrictexpand | Restricts info defined by the -bv and -v flags |
| noertrn | Disallows asynchronous queue runs |
| authwarnings | Adds warning if outgoing message merges formed |
| noreceipts | Turns off delivery notification for success receipt receipts |
| nobodyreturn | Does not return body in a DSN |
| goaway | Disables SMTP status queries (EXPN, VRFY, etc.) |
