# DNS: The Domain Name System

As with access control lists, the *key-id* must be defined with a *key* statement before it is used. To associate the *key* with a particular server, just include *key-id* in the *clauses* of that *server* statement. The key is used to verify requests from that server and to sign the responses to those requests.

The shared secret is sensitive information and should not be kept in a world-read-file. Use an *include* statement to bring it into the *namedd.conf* file.

# The trusted-keys statement

In theory, DNSSEC parent zones authenticate their child zones keys, allowing signatures to be chain-authenticated all the way back to the DNS root. In practice, the root and top-level domains do not support DNSSEC, so some other method of validating a zone's keys is needed.

The *trusted-keys* statement is a brute-force way of telling named, "Proper public key for zone XXX.com is YYY," by bypassing the usual DNSSEC mechanisms for obtaining and verifying zone keys. Such declaration is known as a "trust anchor." It's intended for use when a zone is signed but its parent zone is not.

Of course, XXX.com must be important enough to your site to merit this treatment, and you must have some, out-of-band way to determine the value of the key. There is no magic to get the correct key; the foreign zone's administrator has to read it over the phone or send it to you in some other way that can be authenticated. An HTTPS secure web page is often used for this purpose. You must go through the whole process again whenever the key changes.

The format of the *trusted-keys* statement is

```
domain flags protocol algorithm key;
domain flags protocol algorithm key;
...
```

Each line represents the trust anchor for a particular domain. The *flags*, *protocol*, and *algorithm* are nonnegative integers. The *key* is a base-64-encoded string matching the DNSKEY resource record used to sign the zone.

# The server statement

**named** can potentially talk to many servers, not all of which are running current software and not all of which are even nominally named, the *server* statement tells **named** about the characteristics of its remote peers. The *server* statement can override defaults for a particular server; it's not required unless you want to configure keys for zone transfers.
