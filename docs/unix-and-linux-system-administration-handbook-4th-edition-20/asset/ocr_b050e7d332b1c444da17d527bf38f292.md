Many of the variables with rate and max in their names are used to thwart default service attacks. The conf subdirectory variables are set per interface. It contains subdirectories all default and a subdirectory for each interface (including the loopback). Each subdirectory contains the same set of files.

```
$ubuntu$ cd conf/default; ls -F
accept_redirect disable_policy promote_secondaries
accept_source_route disabled_xmrf proxy_arp
arp_accept force_igmp_version rp_file
arp_announce forwarding secure_retries\arpfilter log_martians send_retries
arp_ignore mc_forwarding shared_media
boot_relay medium_id tag
```

If you change a variable in the conf/eth0 subdirectory, your example applies to that interface only. If you change the conf/all directory, you might expect it to see the corresponding value for all existing interfaces, but this is not in fact what happens. Each variable has its own rules for replacing changes all. Some values are OREd with the current values, are ANDed and others are MAXed or MINed. As far as we are aware, there is no documentation for this process outside of the kernel source, so the whole default is probably best. Just justify your modifications to individual interfaces.

If you change a variable in the conf/default directory, the new value propagates to all interfaces that are later configured. On the other hand, it's nice to keep the defaults unreferenced as information; they make a nice sanity check if you want to undo others.

The /proc/sys/ipv4/ directory also contains a subdirectory for each interface. The files in each subdirectory control ARP table management and IPv6 neighbor discovery for that interface. Here is the list of the ones with gc (garbage collection) determine how ARP entries are timed out and discarded.

$ubuntu$ cd conf/default; ls -F
