# 3.3 GRUB: The GRAND UNIFIED BOOT LOADER

GRUB, developed by the GNU project, is the default boot loader for most UNIX
and Linux systems with Intel processors. GRUB ships with most Linux distribu-
tions, and x86-based Solaris systems since version 2010. GRUB's job is to
choose a kernel from a previously assembled list and to load that kernel with op-
sified by the administrator.

There are two branches of the GRUB lineage: the original GRUB, now called
“GRUB Legacy”, and the newer GRUB 2. The name GRUB 2 is a bit deceptive
s GRUB 2 releases actually have version numbers between 1 and 2. All of our
examples use GRUB Legacy, and that's what we describe in this book.

By default, GRUB 2 reads its boot configuration from /boot/grub/menu.list
or /boot/grub.conf. GRUB reads the configuration file at startup time
(which is a pretty impressive feat in itself), so it allows dynamic changes at
system boot. The menu.list and grub.conf files are slightly different but have
similar syntax. Red Hat systems use grub.conf, and Solaris, SUSE, and Ubuntu
still use menu.list. Here's a sample grub.conf file:

```
default=0
timeout=10
splashimage=(hd0,0)/boot/splash.xpm.gz
t Red Hat Enterprise Linux Server (2.6.18-92.10.el5)
root (hd0)
kernel /vmlinuz-2.6.18-92.10.el5 root=LABEL=
```

This example configures only a single operating system, which GRUB auto-
matically (default=0) if it doesn't receive any keyboard input within 10 seconds
(timeout=10). The root filesystem for the “Red Hat Enterprise Linux” con-
guration is the GRUB device (hd0,0), which is GRUB-ese for the first partition
on the system's first hard disk “first” being defined by the BIOS.

GRUB loads the kernel from /vmlinuz-2.6.18-92.10.el5 and displays a splash
screen from the /boot/grub/splash.xpm.gz when it is loaded. Kernel paths
are relative to the boot partition, which is usually mounted in /boot.

GRUB supports a powerful command-line interface as well as for editing
configuration file entries on the fly. To enter command-line mode, type c from
t GRUB boot screen. From the command line, you can boot operating systems that
aren't in grub.conf, display system information, and perform rudimentary filesys-
testing. You can also enjoy the command line's shell-like features, including
command completion and cursor movement. Anything that can be done through
the grub.conf can be done through command line as well.
