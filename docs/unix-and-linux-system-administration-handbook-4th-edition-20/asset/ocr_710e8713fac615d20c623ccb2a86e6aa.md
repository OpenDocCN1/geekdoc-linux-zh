**sendmail** normally tries to deliver a message immediately, saving it in the queue only momentarily to guarantee reliability. If your host is too busy or the destination machine is unreachable, **sendmail** queues the message and sends to it later. **sendmail** uses persistent queue runners that are usually started at boot time. It does locking, so multiple, simultaneous queue runners are safe. The "queue groups" configuration feature helps with large mailing lists and queues. It is covered in more detail setting on page 802.

**sendmail** reads its configuration file, **sendmail.cf**, if it starts up. There, you must either kill and restart **sendmail** or send a HUP signal when you change the config file. **sendmail** creates a **sendmail.pid** file that contains its process ID and the command that it started. You should start **sendmail** with an absolute path but that re-execs itself on receipt of the HUP signal. The **sendmail.pid** file allows the process to be HUPed with the command

```
sudo kill -HUP 'head -1 sendmail.pid'
```

The location of the PID file is OS-dependent. It usually **/var/run/sendmail.pid** or **/etc/mail/sendmail.pid** but can be set in the config file with confPID_FILE option:

```
define(confPID_FILE, '/var/run/sendmail.pid')
```
