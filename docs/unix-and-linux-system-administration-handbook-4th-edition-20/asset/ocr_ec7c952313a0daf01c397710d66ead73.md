The line

%uids_by_name = reverse %names_by_uid;

has some hidden depths, To hash in list context (here, as an argument to the reverse function) evaluates to a list of the form (key1, value1, key2, value2, ...). # References and autovivification

These are advanced topics, but would be remiss if we didn't least mention them. Arrays and hashes can only hold scalar values, but you will want to store other arrays and hashes within them. returning to our previous example of parsing the /etc/passwd file, you might want to store all the fields of each password line in a hash indexed.

You can't store arrays and hashes, but you can store references (that is, pointers) to arrays and hashes, which are themselves scalars. To create a reference to an array or hash, you precede the variable name with a backslash (e.g., @array) or reference-to-array or reference-to-hash literal syntax. Otherwise, our parsing loop would look something like this:

```
$array_ref = [ split /:/ ];
$passwd_by_uid{$array_ref[2]} = $array_ref;
```

The square brackets return a reference to an array containing the results of the split. not $array_ref[2] refers to the UID field, the third member of the array referenced by $array_ref.

$array_ref[2] won't work because we haven't defined an @array_ref array;
$array_ref and @array_ref are different variables. Furthermore, you not receive an error message if you mistakenly use $array_ref[2] because $array_ref is a perfectly legitimate name for an array; you have just assigned it any values.

This lack of warnings may seem like a problem, but it's arguably one of Perl's finest features, as "autovivification". Variable and referencing syntax always make clear the structure of the data you are trying to access, you need never create any intermediate data structures by. Simply make an assignment at the lowest possible level, and the intervening structures materialize automatically. For example, you can create a hash of references to arrays whose contents are references to hashes with a single assignment.
