The read and buffer sizes apply to both UDP and TCP mounts, but the values differ. Because you can trust TCP to transfer data efficiently, the values should be higher; 32KiB is a good value. For UDP, 8KiB is a good value when server and client are on the same network. The default is 1KiB, even when one recommends increasing it to 8KiB for better performance.

You can test an NFS mount with df as you would test a local filesystem:

| df /nfs/ben | 1k-blocks | Used Available Use% Mounted on |
|---|---|---|---|---|---|n| leopard:/home/ben | 17212156 | 1694128 | 14643692 | 11% | /nfs/ben |

umcount works on filesystems just like it on local filesystems. If the NFS filesystem is in when you try to unmount it, you will get an error such as

```
umcount: /nfs/ben: device is busy
```

Use lsof to find processes with open files on the filesystem. Kill them, or in case of shells, change directories. If all fail or your server is down, try running mount -f to force the filesystem to be unmounted.

The footnote to Table 18.9 is worth noting: the Linux command defaults to a filesystem type of nfs when it recognizes the hostname:directory syntax on the command line. The nfs type is only valid for protocol versions 2 and 3. Use mount -t nfs4:directory when requesting a version 4 mount.

# Mount remote filesystems at boot time

You can use the mount command to establish temporary network mounts, but you should list mounts that are part of a system permanent configuration in /etc/fstab /etc/stab in Solaris so that they are mounted at boot time. Alternatively, mounts can be handled by an automatic mounting service such as autofs.

The following fstab entries the filesystems /home and /usr/local from the hosts monk ross:

```
# filesystem mountpoint fstype flags dump fck
monk:/home /nfs/home nfs rw,intr,hard,nodevis 0 0
ross:/usr/local /usr/local nfs4 ro,intr,soft,nodevis 0 0
```

The Solaris /etc/fstab file is different in format, but options are listed similarly. The NFS options are the same as others.
