# Storage pool management

solaris$ sudo zpool destroy demo c9t0d0 c9t1d0 c9t2d0
solaris$ sudo zpool create monster raid1 zfs list monster

| NAME USED AVAIL REFER MOUNTPOINT |
| monster 91.2K 981G 25.3K /monster |

ZFS also understands raid2 and raid3 for double and triple parity configurations. The minimum number of disks is always one more than the number of parity devices. Here, one out of three is used for parity, roughly 1TB available for use by filesystems.

For illustration, we then add the remaining drives configured as a mirror.

```
solaris$ zpool add mirror c9t3d0 c9t4d0
invalid vdev specification
use -f to override the errors:
mismatched replication level: pool uses raid2 and raid3 new vdev
solaris$ zpool add -f monster mirror c9t3d0 c9t4d0
```

zpool initially backs at this configuration because the two virtual devices have redundancy schemes. This particular configuration is OK since both vdevs have some redundancy. In actual use, you should not mix redundant and nonredundant vdevs there's no way to predict which blocks might be stored on devices; partial redundancy is useless.

```
solaris$ zpool status monster
pool: monster
state: ONLINE
scrub: none requested
```

ZFS distributes writes among all a pool's virtual devices. As demonstrated in this example, it is not necessary for all virtual devices to be the same size.² However, the components within a redundancy group should be of similar size. If they are not, only the smallest size is used on each component. If you use multiple disks together in a storage pool, that is essentially a RAID 0 configuration.

You can add vdevs to a pool at any time. However, existing data will not be redistributed to take advantage of parallelism. Unfortunately, you cannot currently add additional devices to an existing RAID array or mirror.

24. In this example the disks are all the same size, but the virtual devices are not (1TB vs. 500GB).
