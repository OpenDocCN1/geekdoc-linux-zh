# Final steps

To verify that a new account has been properly configured, first log out, then log as the new user and execute the following commands:

```
$ pwd /# To verify the home directory /
$ ls -la /\# To check owner/group of startup files /*
```

You will need to notify new users of their login names and initial passwords. Many send this information by email, but for security reasons that's usually not a good idea. Do it in person or over the phone, unless you are adding 500 freshmen to the campus's CS-1 machines. Then, punt to the instructor! This is also a good time to point users additional documentation on local customs if you have.

If your site requires users to sign a password agreement or use appropriate policy, be sure this step has completed before releasing the account. This check will prevent oversights and strengthen the legal basis of any sanctions you might later impose.

See page 1227 for information about written user contracts.

Remind new users to change their passwords immediately. If you wish, you can enforce this by setting the password within a short time. Another option is to have a script check on new users and be sure their encrypted passwords in the shadow file changed.

In an environment in which you know the users personally, it is relatively easy to keep track of who's using a system and why. If you manage a large and dynamic user base, you'll need a more formal way to keep track of accounts. Maintaining a database of contact information and account status will help you figure out who someone is and why they have an account the act of creating that account has failed from memory.
