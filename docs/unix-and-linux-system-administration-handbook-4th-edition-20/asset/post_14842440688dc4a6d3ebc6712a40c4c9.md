## 14.9 PPP: THE POINT-TO-POINT PROTOCOL

PPP is defined in RFC1331.

PPP represents an underlying communication channel as a virtual network interface. However, since the underlying channel need not any of the features of actual network, communication is restricted to the two hosts at the end of the link—a virtual network of two. PPP has the distinction of being used on both the slowest and the fastest IP links, for different reasons.

In its asynchronous form, PPP is best known as the protocol to provide dial-up Internet service over phone lines and serial lines. These channels are not inherently part oriented, so the PPP device driver encodes packets into a unified data stream and adds link-level headers to separate packets.

Designed by committee, PPP is the "everything and the kitchen sink" encapsulation protocol. In addition to specifying how the link is established, maintained, and down, PPP implements error checking, authentication, encryption, and compression. These features make it adaptable to a variety of situations.

PPP as a dial-up technology once an important topic for UNIX and Linux system administrators, but the widespread availability of broadband has made dial-up configuration largely irrelevant. At the same time, the high-end applications of PPP have mostly retreated into various pieces of dedicated network hardware. These days, the primary use of PPP is to connect through cellular mediums.

## 14.10 BASIC NETWORK CONFIGURATION

Only a few steps are involved in adding a new machine to the existing area network, but every system does slightly differently. Systems typically provide a control panel GUI for basic network configuration, but more elaborate (automated) setups may require you to edit the configuration files directly.

Before bringing a new machine on a network that is connected to the Internet, secure it (Chapter 22, Security) so that you are not inadvertently inviting attackers onto your local network.

### Hostname and IP address assignment

The basic steps to add a new machine to a local network are as follows:

- Assign a unique IP address and hostname.
- Make sure network interfaces are properly configured at boot time.
- Set up a default route and perhaps fancy routing.
- Point to a DNS name server to access the rest of the Internet.

If you rely on DHCP for basic provisioning, most of the configuration chores for a new machine are performed on the DHCP server rather than the new machine itself. New OS installations typically default to getting their configuration through DHCP, so new machines may require no network configuration at all. Refer to the DHCP section starting on page 46 for general information.

After any change that might affect booting, you should always reboot before the machine comes online. Six months later when the power has failed and the machine reboots to boot, it's hard to remember what change you might have caused the problem. (Refer to Chapter 21, Network Management and Debugging.)

The process of designing and installing a physical network is touched on Chapter 16, Network Hardware. If you are dealing with a network and have a general idea of how it is set up, it may not be necessary for you to read too much about the physical aspects of networking unless you plan to extend your network.

In this section, we review the various commands and issues involved in manual network configuration. This material is general enough to apply to any UNIX or Linux system. In the vendor-specific sections starting on page 484, we address the unique twists that distinguish UNIX from Linux and separate the various systems.

As you work through basic network configuration on any machine, you'll find it helpful to test your connectivity with basic tools as ping and traceroute. Those tools are actually described in the Network Management and Debugging chapter; see the sections starting on page 861 for more details.

### Hostname and IP address assignment

Administrators have various heartfeels about how the mapping from names to IP addresses is best maintained through the hosts file, LDAP, the DNS system, or perhaps some combination of these. The conflicting goals are scalability, consistency, and maintainability versus a system that is flexible enough to allow machines to boot and function when all services are available. Prioritizing those of administrative information starting on page 739 describes how the various options can be combined.

Another consideration you might take into account when designing your address is possible need to remember your hosts in the future. Unless you are using RFC1918 private addresses (see page 462), your site's IP addresses may change when you switch ISPs. Such a transition becomes daunting if you must visit each host on the network to reconfigure its address. Expedite renumbering, you can use hostnames in configuration files and confine address mappings to a few centralized locations such as the DNS database and DHCP configurations.

The /etc/hosts is the oldest and simplest way to map names to IP addresses. Each line starts with an IP address and continues with the various symbolic names by which that address is known.

Here is a typical /etc/hosts file for the host lollipop:

| 127.0.0.1 | localhost |
| 192.108.21.48 | lollipop.astrum.com localhost |
| 192.108.21.254 | chimchim-gw.astrum.com chimchim-gw |
| 192.108.21.11 | ns.astrum.com ns |
| 192.225.33.5 | licenses.astrum.com license-server |

A minimal version would contain only the two lines. localhost is the first entry in the /etc/hosts file; this is unnecessary on many systems, but it doesn't hurt to include it. IPv6 addresses can go in this file as well.

Because /etc/hosts contains only local mappings and must be maintained on each client system, it's best reserved for mappings that are needed at boot time (e.g., the host itself, the default gateway, and name servers). Use DNS or LDAP to find mappings for the rest of the local network and the rest of the world. You can also use /etc/hosts to specify mappings that you do not want the rest of the world to know about and therefore not publish in DNS.¹

The hostname command assigns a hostname to a machine. hostname is typically run at boot time from one of the startup scripts, which obtains the name to be assigned from a configuration file.(Of, each system does this differently. The system-specific sections beginning on page 484 for Details.). The hostname should be fully qualified that, it should include both the hostname and the DNS domain name, such as anchor.cs.colorado.

At a small size, you can easily out hostnames and IP addresses by hand. When many networks and many different groups are involved, it helps to have some central coordination to ensure uniqueness. For dynamically assigned networking parameters, DHCP takes care of the uniqueness issues. Some sites now use LDAP databases to manage their hostnames and IP addresses assignments.

### ifconfig: configure network interfaces

ifconfig enables or disables a network interface, sets its IP address and subnet mask, and sets various other options and parameters. It is usually run at boot time with command-line parameters from ifconfig files, but you can also run it by hand to make changes on the fly. Be careful if you are making **ifconfig** changes and are logged remotely—many sysadmin has been locked out of this way and had to fix things.

An **ifconfig** command commonly has the form

```
ifconfig interface [family] address options
```

For example, the command

```
ifconfig eth0 192.168.1.13 netmask 255.255.255.0 up
```

sets the IPv4 address and netmask associated with the interface and readies the interface for use.

interface identifies the hardware interface to which the command applies. It is usually a two-character name followed by a number, Solaris interfaces can be longer. Some common names are ie0, le0, le1, in0, en0, we0, hme0, eth0, and lan0. The loopback interface is lo on Linux and lo on Solaris, HP-UX and AIX. On most systems, **ifconfig -a** lists the system's network interfaces and summarizes their usage. Use **netstat -i** for this HP-UX.

Under Solaris, network interfaces are "attached" with **ifconfig** interface **plumb** them to become configurable and visible to **ifconfig -a**. You can use the **dladm** command to list interfaces regardless of whether they have plumbed.

The family parameter tells **ifconfig** which network protocol (“address family”) to configure. You can set up multiple protocols on an interface and use them simultaneously, but they must be configured separately. The main options are here for IPv4 and **inet6** for IPv6 is used if you leave the parameter out. Linux systems support a handling of legacy protocols such as AppleTalk and Novell IPX.

The **address** parameter specifies the interface’s IP address. A hostname is also acceptable, but the hostname must be resolvable to an IP address at boot. For a machine’s primary interface, this means that the hostname must appear in the **local hosts file**, since other name resolution methods depend on the network having initialized.

The keyword **up** turns the interface; **down** turns it off. When **ifconfig** assigns an IP address to an interface, as in the example above, the **up parameter** is implicit and does not need to be mentioned by name.

**ifconfig** understands lots of other options. The most common ones are mentioned, but as always, consult your man pages for the final word on your particular system. **ifconfig** options have all symbolic names. Some require an argument, which should be placed immediately after the option name and separated from the option name by a space.
