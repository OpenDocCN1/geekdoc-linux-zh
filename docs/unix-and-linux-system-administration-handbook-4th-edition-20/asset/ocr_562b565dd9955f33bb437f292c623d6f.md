# Regular expressions in Perl

You use regular expressions in Perl "binding" strings to regex operations with
ne = ~ operator. For example, the line

```
if ($text =~ m/ab+c/) {
```

checks to see the string stored in $text matches the regular expression
ab+c. To operate on the default string, ~, you can simply omit the variable name
 binding operator. In fact, you can omit the m, too, since the operator de-
fults to matching:

```
if (/ab+c/) {
```

Substitutions work similarly:

```
$text ~ s/etc/ and so on/g;      # Substitute text in $text, OR
s/etc/ and so on/g;               # Apply to all $_
```

Weaked in a g option to replace all instances of "etc." with "and so on", rather
just replacing the first instance. Other common options are i to ignore case, s
to make dot (.) match newlines, and m to make the ^ and $ tokens at the match
bending and end of individual lines than only at the beginning and end of
search text.

A couple of additional points are illustrated in the following script:

```
#!usr/bin/perl

$names = "huey dewey louie";n$regex = ((\w+)\s+(\w+)\s+(\w+));
if ($ =~ m/$regex/) {
	print "1 name is $1.\n2nd name is $2.\n3rd name is $3.\n";n	$names = s/$regex/$2 1/;
	print "New names are \$names\.\n";n} else {
	print qq["$names"] did not match "$regex";
}
```

The output:

```
$ perl testregex
1st name is huey.
2nd name is louie.
3rd name is dewey.
New names are "dewey".
```

This example shows that variables expand in // quoting, the regular expression
need not be a fixed string. qq is another name for the double-quote operator.

After a match or substitution, the contents of the variables $1, $2, and so corre-
sp to the text matched by the contents of capturing parentheses in the
regular expression. The contents of these variables are also available during the
replacement itself, in which context they are referred to as \1, \2, etc.
