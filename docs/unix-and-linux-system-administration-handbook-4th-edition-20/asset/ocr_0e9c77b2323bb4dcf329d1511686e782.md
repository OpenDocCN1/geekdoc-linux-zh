# LDAP and Active Directory

See the section starting on page 728 for more information about LDAP and LDAP implementations.

LDAP is a generalized, database-like repository that can store user data as well as other types of data. It uses a hierarchical client/server model that supports multiple servers as well as simultaneous clients. One of LDAP's big advantages as a site-wide repository for login data is that it can enforce UIDs and GIDs across systems. It also plays well with Windows, although the reverse is normally marginally.

Microsoft's Active Directory uses LDAP and Kerberos and can manage lots of kinds of data including user information. It is a bit egotistical and wants to be the boss if it is interacting with UNIX or Linux LDAP repositories. You need a single authentication system for a site that includes Windows desktops as well as UNIX and Linux systems, it is probably easiest to let Active Directory in control and use your LDAP databases as secondary servers.

To implement this configuration, you will need Active Directory and Microsoft's Services for UNIX, or a commercial Active Directory integration platform such as Quest Authentication Services (formerly Vintela Authorization Services). Sun's Virtual Directory can help glue together several authorization/authentication systems.

Each of our example systems has LDAP support built in, although sometimes just the client side (HP-UX, for example). LDAP is often coupled with PAM for authenticating.

LDAP is a database, so the information stored there must fit a well-defined schema. Schemas are expressed as XML files, with the field names coming from the relevant RFCs, primarily RFC2307 for user management data. See Chapter 19, Sharing System Files, for the nitty-gritty details.

# Single signon systems

Single signon (SSO) systems balance convenience with security issues. The idea is that a user can sign on once (to a login prompt, web page, or Windows box) and be authenticated at that time. The user obtains authentication credentials (implicitly, so that no active management is required), which can be used to access other machines and applications. The user only has to remember one login and password sequence instead of many.
