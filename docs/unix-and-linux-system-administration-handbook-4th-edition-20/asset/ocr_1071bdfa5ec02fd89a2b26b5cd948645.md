# Chapter 6  The Filesystem

POSIX and NFSv4 ACLs are supported in this manner, although we show
only NFSv4 examples. The specific flavor of ACLs that we see or depends on
the underlying filesystem. 

ls -v shows ACL information for filesystem objects. With -l, you must include
the -d option if you want to see the ACL for a directory; otherwise ls -v shows the
ACL of every child of the directory. Here's a simple (1):

```
solaris$ mkdir /var/tmp/example
solaris$ ls -dv /var/tmp/example
drwrt-x 2 garth Jan 21 07:19 /var/tmp/example
0owner:deny
1owner@list_directory/read_add_file/write_data/add_subdirectory
/append_data/write_xattr/execute/write_attributes/write_acl
/write_owner:allow
2group@list_file/write_data/add_subdirectory/append_data:deny
3group@list_directory/read_data/execute:allow
4everyone@list_file/write_data/add_subdirectory/append_data/write_xattr
/_attributes/acl/write_owner:deny
5everyone@list_directory/read_data/read_xattr/execute/read_attributes
/_acl/synchronize:allow
```

This newly created directory seems to have a complex ACL, but in fact it's a-
ACL just the nine-bit mode shown on the first line of output translated into
ACLE. It is not necessary for the filesystem to store an actual ACL because
ACL and the mode are equivalent. (Such ACLs are termed "trivial") if the direc-
tory had an actual ACL, ls would show the bits + a on the end (i.e.,
drwxt-xr-x+) to indicate the presence of the ACL.

Each numbered clause represents one access entry. The format is

```
index:entity:permissions:inheritance_flags:type
```

The index numbers are added by ls for clarity and are not part of the actual ACL.
They can be used in later chmod to identify a specific ACE to be re-
placed or deleted.

The entity can be the keys owner@, group@, or everyone@, or a form such
as user: username or group:groupname.

The type of an ACE is either allow or deny. Theoretically, alarm and audit are
alowed as well, but ZFS does not implement these features.

Both the permissions and the inheritance_flags are slash-separated lists of options.
Stringly, it is the inheritance_flags field (and one of the color delimiters)
flags are all turned off, but it does not do with the permissions.

For added confusion, ls displays multiple names for the r (read data/list directory-
tory), w (write data add file), and p (append data/add subdirectory) permission
bits, if they were separate permissions. In fact, they are file- and directory-spencpecific interpretations of the same bits and will always be present or absent others.
