+   - Commands can validate their arguments; configuration files cannot. A wrapper command can ensure that a proposed change won't break the system. If it would, the command can complain or refuse to make the change. That's much nicer than discovering problems the hard way when things break randomly after a configuration file change.

+   - Task-specific commands facilitate scripting. Not only do they combine functions and validate arguments, but they also rely on scripts to parse and manage complex configuration files. That makes scripts shorter, more reliable, and easier to maintain (and teach!). Think of these commands as a high-level administration library that's built into the operating system and works with every scripting language.

+   - The provision of a defined administrative interface reduces on particular file formats or implementations. It frees IBM to change its back ends and introduce new technologies without breaking legacy scripts. For example, the ODM stores its data in Berkeley DB files. However, IBM could easily change the ODM to LDAP or some other future technology while keeping the ODM commands and user interface.

And don't be SMIT-hater! SMIT is a flexible system that manages a variety of interfaces (X11, web page, command-line client). That flexibility means you can use the same interface whether you're sitting at a desktop machine or working from home late at night.

SMIT simplifies complex procedures and gets administrators up to speed quickly. It's well and maintained for many years and has undergone a variety of user interface studies at improving it. It's easy to use regardless of your familiarity with UNIX in general or AIX in particular, and it's a great tool, even for experienced administrators. You can pull out SMIT form with your desired values and have SMIT show you the exact command it would run to implement your request. There's nothing like this on any other system, and it's great.
