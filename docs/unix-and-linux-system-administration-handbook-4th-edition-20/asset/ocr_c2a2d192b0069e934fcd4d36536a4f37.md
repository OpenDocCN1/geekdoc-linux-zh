The ADSP TXT record can also include a t=y clause if you are just testing DKIM and don't want recipients to take your signatures seriously.

During the development of the ADSP system, prior to RFC5617, a domain's ADSP TXT record was kept in a different subdomain (_domainkey.domain, with no_prefix) and had a slightly different syntax, O=- meant that the domain signed some of its email, and O== meant it signed all email.

Since the two conventions use different subdomains, they can coexist. In writing, the original form remains predominant. If you are about getting recipients to scrutinize your signatures, it's probably best to use both conventions for the next few years until everyone has RFC5617-compliant.

Let's look at an example. Gmail does not have an ADSP record, but Yahoo does:

```
_domainkey.yahoo.com 7200 IN TXT t=y; O=-\nn=http://ispam.yahoo.com/domainkeys
```

The n= a comment that points a human user to more information about Yahoo's use of DKIM records. 16 Some sites include an email address (without @s, to toad instead). Here is yahoo.com DKIM TXT record for the key (selector): s1024

# SSHFP resource records

SSH, the secure shell, allows secure logins over an insecure network. It uses two authentication schemes, for the host itself and for the user to log in. Unfortunately, users typically accept whatever key ssh presents to them without verifying it. DNS's SSHFP record lets ssh verify the host key automatically, ensuring that the user has reached the intended machine and not an impostor.

SSHFP records are specified in RFC4255 (2006).
