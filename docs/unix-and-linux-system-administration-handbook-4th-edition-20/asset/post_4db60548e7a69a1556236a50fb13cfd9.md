
# Adding new software

**If** can't find the command you're looking for, try **whereis**; it searches a broader range of system directories and is independent of your shell path.

Another alternative is the incredibly useful **locate** command, which consults a precompiled index of the filesystem to locate filenames that match a pattern. **locate** is part of the GNU **findutils** package, which is included by default on most Linux systems but must be installed by hand on UNIX.

locate is not specific to commands or packages but can find any type of file. For example, if you weren't sure where to find the **signal.h** include file, you could try

```bash
ubuntu locate signal.h
/usr/include/signal.h
/usr/include/asm/signal.h
/usr/include/asm-generic.h
/usr/include/linux/signal.h
```

...

locate's database is updated periodically by the **updated** command, which runs out of **cron**. Therefore, the results of a **locate** doesn't always reflect changes to the filesystem.

See Chapter 12 for more information about package management.

If you know the name of the package you're looking for, you can also use your system-packing utilities to check for the package's presence. For example, on a Red Hat or SUSE system, the following command checks for the presence (and installed version) of the Python scripting language:

```bash
redhat5$ rpm -q python
python-2.4.3-21.el5
```

# Adding new software

If you need to install additional software, you first need to determine the canonical name of the relevant software package. For example, you'd need to say "I want to install **locate**" to "I need to install the **findutils** package," or translate "I need **named**" to "I have to install BIND. A variety of system-specific indexes on the web can help with this, Google is just as effective. For example, a search for "locate command" takes you directly to several relevant discussions. If you're on a UNIX system, throw in the name of the operating system as well.

Once you know the name of the relevant software, you can download and install it. The complete installation is using a single command on Linux systems and Solaris systems. For HP-UX and AIX you'll have to download either a prebuilt binary package or the project's original source code. If the latter, try to locate the project's official web page through Google and download the source code from one of the project's mirrors.

The following examples show the installation of the **wget** command on each of our example systems. It's a nifty GNU utility that handles HTTP and FTP downloads into atomic commands—very useful for scripting. **wget** is installed by default on each of our example Linux systems, but the commands shown below can be used for both initial installation and later updates.

Ubuntu uses APT, the Debian Advanced Package Tool:

```bash
ubuntu# apt-get install wget
Reading package lists... Done
Building dependency tree
Reading state information... Done
wget is already the newest version.
0 upgraded, 0 newly installed, 0 to remove and 0 not upgraded.
```

The SUSE version is

```bash
suse# yast --install wget
(runs in a terminal-based UI)
```

The Red Hat version is

```bash
redhat# yum install wget
Loaded plugins: fastestmirror

Parsing package install arguments
Package wget-1.10.2-7.el5.i386 is already installed and latest version
Nothing to do
```

On a Solaris system with pkgutils already installed (see translate.org for instructions on setting this up)

```bash
solaris# /opt/csw/bin/pkgutil --wget
<multiple pages of output as seven packages are installed>
```

hhpux# swinstall -s /tmp/wget-1.11.4-hppa-11.31.depot wget

# Building software from source code

The package depot on the swinstall command line must be specified as a full path starting with /; otherwise, swinstall tries to find the file on the network. the wget at all ends swinstall package to install within the depot file.

Unfortunately, the installation is not really easy as it first appears. The installed version of wget won't actually run because several of the libraries on which it depends have not installed:

```bash
hpux$ wget http://samba.org/samba/docs/Samba3-HOWTO.pdf
/usr/lib/dl.so: Can't open shared library: /usr/local/lib/libcrypto.so
/usr/lib/dl.so: No such file or directory
[APRIES32]: Core file for 32 bit PA-RISC application
[APRIES32]: /usr/local/bin/wget saved to /tmp/core.wget.
```

swinstall does have some dependency management built in, but its abilities unfortunately do not extend to Internet repositories. You will have to read the fine print and install all the appropriate prerequisite packages (in this case, six more) to make things right.

# Building software from source code

There is in fact at least one wget package available for AIX in RPM format. A Google search for "aix wget" should turn up some good leads. After downloading, the installation command would be a simple

```bash
aix# rpm --install wget-1.11.4-1.aix5.1.ppc
```

But just for illustration, let's build the AIX version of wget from the original source code.

Our first choice is to find, but that's easy:

```bash
aix# tar xf wget-1.11.4.tar.gz
aix# cd wget-1.11.4
aix# ./configure --disable-ssl --disable-nls
checking system type... rs6000-ibm
```

```bash
status: creating src/config.h
status: executing default
generating PO from POFILES.in
creating po/Makefile
```

```bash
aix# make
<several pages of output>
aix# make install
<about a page of output>
```
