Finally, we end both INPUT and FORWARD chains with a rule that forbids packets not explicitly permitted. Although we already enforced this behavior with the **iptables** -P commands, the LOG target tells us who is knocking on our door.

```
iptables -A INPUT -i eth1 -j LOG
iptables -A FORWARD -i eth1 -j LOG
```

Optionally, we could set up IP NAT to disguise the private address used by the internal network. See page 492 for more information about NAT.

One of the most powerful features that Netfilter brings to Linux nowadays is stateful packet filtering. Instead of allowing incoming services, a firewall for clients connecting to the Internet needs to allow incoming responses to the client's requests. The stateful FORWARD chain below allows all traffic to leave our network but only incoming traffic that's related initiated by our hosts.

```
iptables -A FORWARD -i eth0 -p ANY -j ACCEPT
iptables -A FORWARD -m state --state ESTABLISHED,RELATED -j ACCEPT
```

Certain kernel modules must be loaded to enable **iptables** to track complex work sessions such as of FTP and IRC. If these modules are not loaded, **iptables** simply disallows those connections. Although stateful packet filters can increase the security of your site, they also add to the complexity of the network. Be sure you use stateful functionality before implementing it in your firewall.

Perhaps the best way to debug your iptables rules is to use **iptables -v**. These options tell you how many times each rule in your chains has matched a packet. We often add temporary **iptables** rules with the LOG target when we want information about the packets that matched. You can also solve tricky problems by using a packet sniffer such as `tcpdump`.

# 22.13 IPFilter for UNIX systems

Most UNIX vendors don't have their own firewall software.¹12 But it's easy enough to add: IPFilter, an open source package developed by Darren Reed, supplies NAT and stateful firewall services for UNIX systems. Solaris includes it by default, and it's also available as an add-on for HP-UX, AIX, and many other systems, including Linux. You can use IPFilter as a loadable kernel module (which is recommended by the developers) or include it statically in the kernel.

12. IBM is an exception. AIX includes a separate packet-filtering suite in its IP Security implementation, although the suite does not stateful filtering. See the pages for genfilter to get started.
