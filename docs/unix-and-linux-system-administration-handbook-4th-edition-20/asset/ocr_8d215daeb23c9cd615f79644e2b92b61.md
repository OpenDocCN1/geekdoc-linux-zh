# Printer drivers and their handling of PDLs

What if a printer supports only a subset of the languages you need to process? If you download a PostScript file from the web and your printer only understands PCL5E, what do you do? If your printer doesn't interpret PDF directly, how do you print a PDF file?

One option is to convert the file by hand. Your boxes come with plenty of conversion; there's almost always way to turn what you have into someprinters print. Browsers can transform HTML (or XHTML) into PostScript. OpenOffice can convert MS Word files into PDF. Ghostscript can turn PDF into PostScript and PostScript into almost anything, including PCL.

An easier approach is to let your system do the work for you. Some systems, such as CU, have built-in knowledge about which conversions need to be done and set up the conversions for you automatically.

If you need to determine what PDL a file uses and you can't tell you from the filename (e.g., foo.pdf), the file command can tell you (unless the file starts with a chunk of PJL instructions, in which case file just says "HP Printer Job Layout data")

Save a few print jobs to files instead of sending them to a printer, and you can see what a program in one of these languages looks like. A minute or two perusing pages of each of these types in your editor will give you a good feel for how different they are. (Don't cat them directly to your screen, since only PostScript is ASCII. Random binary data tends to confuse terminal emulators.)

PostScript:

```
%PS-Adobe-3.0
%BoundingBox: 0 0 612 792
%Pages: 1
%
% Draw a line around the polygons...
pop pop pop 0 setgray 0 0 moveto 0 0 lineto 0.707106781 mul dup
lineto closepath stroke
PDF:
%PDF-1.3
%A?AA*
81 0 obj
<<
/Linearized 1
/O 83
/H [ 915 494 ]
/T 125075
>>
endobjref
81 24
000000016 00000 42
A^<8bf>
```
