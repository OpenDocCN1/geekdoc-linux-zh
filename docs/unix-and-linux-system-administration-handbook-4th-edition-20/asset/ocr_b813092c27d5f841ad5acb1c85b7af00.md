Since packet sniffers need to see as much of the raw network traffic as possible, they can be throttled by network switches, which by design limit the propagation of "unnecessary" packets. However, it can still be informative to try out a sniffer on a switched network. You may discover problems related to broadcast or multicast packets. By switching your switch vendor, you may be surprised by how much traffic you can see.

In addition to having access to all network packets, the interface hardware must transport those packets up to the software layer. Packet addresses are normally checked in hardware, and only broadcast/multicast packets and those addressed to the local host are relayed to the kernel. In "promiscuous mode," an interface lets the kernel read all packets on the network, even the ones intended for others.

Packet sniffers understand many of the packet formats used by standard network services, and they can print these packets in human-readable format. This capability makes it easier to track the flow of a conversation between two programs. Some sniffers print the ASCII contents of a packet in addition to the packet header and so are useful for investigating high-level protocols.

Since some protocols send information (and even passwords) across the network as cleartext, you must take care not to invade the privacy of your users. On the other hand, nothing demratizes the risk for cryptographic security like the sight of a plaintext password captured in a network packet.

Sniffers read data from a raw network device, so they must run as root. Although this root limitation decreases the chance that normal users will listen in on your network traffic, it is really much of a barrier. Some sites choose to remove sniffer programs from hosts to reduce the chance of abuse. If not, you should check your systems' interfaces to be sure they are not running in promiscuous mode without your knowledge or consent. On all systems, the output of ifconfig labels interfaces with the flag PROMIS. On Linux systems, the fact that an interface has been switched to promiscuous mode is also recorded in the kernel log.

# tcpdump: industry-standard packet sniffer

tcpdump, yet another network tool by Van Jacobson, is available as a package for all Linux distributions and can be installed from source on other example systems. tcpdump has long been the industry-standard sniffer, and most other network analysis tools read and trace files in tcpdump format, also known as libpcap.

By default, tcpdump tunes in the first network interface it connects. If it chooses the wrong interface, you can force an interface with the -i flag. If DNS is broken or you just don't want tcpdump doing name lookups, use the -n option. This option is important because slow DNS service can cause the filter to start dropping packets before they can be dealt with tcpdump.
