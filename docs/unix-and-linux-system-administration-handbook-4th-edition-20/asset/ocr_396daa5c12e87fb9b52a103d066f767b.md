# Vigilantly monitoring security

See Chapter 22 for more information about security.

The system administrator must implement a security policy and periodically check to be sure that the system has not been violated. On low-security systems, this might involve only a few basic checks for unauthor-ized access. On a high-security system, it can include an elaborate network of traps and auditing programs.

# Fire fighting

Although helping users with their various problems is rarely included in a system administrator’s job description, it claims a significant portion of most administra- tors workday. System administrators are bombarded with problems ranging from "It worked yesterday and now doesn't! What did you change? to "I spilled coffee on my keyboard! Should I pour water on it to wash it out?

In most cases, your response to these issues affects your perceived value as an administrator far more than does any technical skill you may possess. You could either howl at the injustice of it all, or you delight in the fact that a single well-handled trouble ticket scores as brownie pies five hours of mid-night debugging. You pick!

We assume in this book that you have a certain amount of Linux or UNIX experi-ence. In particular, you should have a general concept of how the system works and feels from the user’s perspective we don't review this material. Several good books can get you to speed; see the reading list on page 27.

Even in these days of Compiz-powered 3D desktops, the GUI tools for system administration on UNIX and Linux systems remain fairly in compar-son with the richness of the underlying software. In the real world, we still admin-ister by editing configuration files and writing scripts, so you’ll need to be com-fortable with both a command-line shell and a text editor.

Your editor is a GUI tool like edit or a command-line tool such as vi or emacs. Word processors as Microsoft Word and OpenOffice Writer are quite different from text editors and are nearly useless for administrative tasks. Com-mand line tools have an edge they can run over SSH connections and on ailing systems that won't boot; there’s no need for a window system. They are also much faster for the quick little editors that administrators often.
