“Physical volume” is a somewhat misleading term because physical volumes need not have a direct correspondence to physical devices. They can be disks, which may also be disk partitions or RAID arrays. The LVM doesn't care.

# Linux logical volume management

You can control LVM implementation (LVM2) with either a large group of simple commands (the ones illustrated in Table 8.4) or with a single lvm command and its subcommands. These options are for all intents and purposes identical; each, the individual commands are really just links to lvm, which looks to see how it's been called to know how to behave. Man lvm is a great introduction to the system and its tools.

A Linux LVM configuration proceeds in a few distinct phases:

+   - Creating (defining, really) and initializing physical volumes
- Adding the physical volumes to a volume group
- Creating logical volumes on the volume group

LVM commands start with letters that make it clear at what level of abstraction they operate: pv manipulate physical volumes, vg commands manipulate logical volumes. A few commands with the prefix lvm (e.g., lvchange) operate on the system as a whole.
