# Choosing a server

Load balancing hardware is an easy alternative to round robin DNS, but one that requires some spare cash. Commercial third-party load balancing hardware includes the Big-IP Controller from F5 Networks, Nortel's Alteon switching products, and Cisco's Content Switches. These distribute incoming according to a variety of configurable parameters and can take the current response times of individual servers into account.

Software-based load balancers do not require specialized hardware; they can run on a UNIX server. Both open source and commercial solutions are available. The open source category includes the Linux Virtual Server (linuxvirtualserver.org) and the proxy load balancing functionality (mod_proxy_balancer) introduced in Apache 2.2. An example of commercial offerings in this space are those sold by Zeus, zeus.com.

Google actually uses a combination of custom load-balancing DNS servers (with round robin records) and load balancing hardware. See the Wikipedia article for "Google platform" for more details.

Keep in mind that most sites these days are dynamically generated. This architecture puts a heavy load on database servers. If necessary, consult your database administrator to determine the best way to distribute load across multiple data-servers.

Installing and maintaining a web server is easy. Web services rank far below others in complexity and difficulty of administration.

# Choosing a server

Several HTTP servers are available, but you'll likely want to start with the Apache server, which is well known in the industry for its flexibility and performance. As of January 2010, 54% of servers on the Internet are running Apache (currently serving up content for over 111 million sites). Microsoft accounts for most of the remainder at 24% of servers. This market share split between Apache and Microsoft has been relatively stable for the last five years. More detailed market share statistics over time are available here:
