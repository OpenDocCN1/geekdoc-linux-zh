# fsck: check and repair filesystems

Because of block buffering and that the disk drives are not transactional devices, filesystem data structures can potentially become self-inconsistent. If these problems are not corrected quickly, they propagate and snowball.

The original fix for corruption was a command fsck ("filesystem consistency-check", spelled aloud or pronounced "FS fsck" or "fisk") carefully-pected all data structures and walked the allocation tree for every file. It relied on a set of heuristic rules about what the filesystem might look like after failures at various points during an update.

The original fsck scheme worked surprisingly well, but because it involved reading a disk's data, it could take hours on a large drive. An early optimization was a "fsck clean" that could be set in the superblock when the filesystem was properly mounted. When the system restarted, it would see the clean bit and know to skip the fsck check.

Now, filesystem journals fsck pinpointed the activity that was occurring at the time of a failure. fsck can simply rewind the filesystem to the last known consist-state.

Disks are marked fscked automatically at boot time if they are listed in the system-/etc/fstab, /etc/vstab, or /etc/filesystems. The fstab and vstab files have legacy "fsck sequence" fields that were used to order and parallelize filesystem checks. But now that fscks are fast, the only thing that really matters is that the root filesystem be checked first.

You can run fsck by perform an in-depth examination akin to the original fsck procedure, but be aware of the time required.

Linux ext-family filesystems can be set to force a recheck after they have been remounted a certain number of times or after a period of time, even if the unmounts "clean." This precaution is good hygiene, and in most cases the default value (usually around 20 mounts) is acceptable. However, on systems that mount filesystems, such as desktop workstations, that frequency of fscks can become tiresome. To increase the interval to 50 mounts, use the tune2fs command:

```
$ sudo /sbin/tune2fs -c 50 /dev/sda3
tune2fs 1.41.9 (22-Aug-2009)
```
