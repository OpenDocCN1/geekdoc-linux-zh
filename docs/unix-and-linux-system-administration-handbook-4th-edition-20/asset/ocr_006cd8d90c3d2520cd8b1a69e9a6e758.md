# Chapter 17 DNS: The Domain Name System

configured nsd to be the master server for the domain atrust.com and a slave server for the domain admin.com.

```
server:
  username: nsd # User nsd should run after chroot
  database: /var/db/nsd/nsd.db # Precompiled database file
  logfile: /var/log/nsd.log # Log file, default is to stderr + syslog
  pidfile: /var/run/nsd.pid # nsd process id
  key:
    name: atrust.com # Key for atrust.com transfers
    algorithm: hmac-md5
    secret: "base64 secret goes here"
zone:
  name: atrust.com
  zonefile: /var/nsd/primary/atrust.com
  provide-xfr: 1.2.3.40 tsig.atrust.com # Address of atrust.com slave
  notify: 1.2.3.40 tsig.atrust.com # Key for notify or xfrs.
  provide-xfr: 1.2.3.40 tsig.atrust.com # Address of another slave
  notify: 1.2.30.40 tsig.atrust.com # Key for notify or xfrs.
key:
  name: admin.com # Key to get admin.com slave data
  algorithm: hmac-md5
  secret: "base64 secret goes here"
zone:
  name: admin.com # Zone we are a slave for
  zonefile: /var/nsd/secondary/admin.com.signed"
  allow-notify: 5.6.7.8 NUKES # Its master server
  request-xfr: 5.6.7.8 tsig.admin.com. # Key for xfrs
```

This **nsd.conf** file configures the server to be the master for atrust and to notify provide zones to two slaves, one at IP address 1.2.3.4 and the other at IP address 1.2.30.40. The server will use the TSIG key called tsig.atrust.com to authenticate both servers for transfers and notifications. (You should, and probably, use a separate key for each slave.)

This server is also a slave for the signed admin.com, whose master server is at IP address 5.6.7.8. We can receive notifications of zone changes with a key, but you must use the tsig key to receive zone transfers. Master zones provide-xfr clauses and slave zones have a request-xfr clause.

After you've installed **nsd** and set up your configuration file, use **nsd-check** to check the config file's syntax. Its error reports are a bit terse; for example, "error: syntax error" and a line number. After fixing **nsd-check**, it runs in again and repeat the process until nsd-check reports no more errors.

# NSD key definitions

A **key** defines a named key to be used in subsequent access control operations. Each key has three attributes: a name, an algorithm, and a shared secret (password).
