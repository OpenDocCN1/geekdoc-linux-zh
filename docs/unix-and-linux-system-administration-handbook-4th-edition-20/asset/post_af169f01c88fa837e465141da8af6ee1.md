If you use an MSA, be sure to configure your transport agent so that it doesn't duplicate any of the rewriting or header fix-up work done by the MSA. Duplicate processing won't affect the correctness of mail handling, but it represents less extra work.

Since your MSA uses your MTA to relay messages, the MSA and MTA must use SMTP-AUTH to authenticate each other. Otherwise, you will have a so-called open relay that spammers can exploit and other sites will blacklist for you.

## Transport agents

A transport agent must accept mail from a user agent or submission agent, understand the recipients' addresses, and somehow get the mail to the correct hosts for delivery. Transport agents speak the Simple Mail Transport Protocol (SMTP), which was originally defined in RFC2621 but has now been superseded and extended by RFC5321. The extended version is called ESMTP.

An MTA's list of choices, as both a mail sender and receiver, includes

- Receiving email messages from remote mail servers
- Understanding the recipients' addresses
- Rewriting addresses to a form understood by the delivery agent
- Forwarding the message to the next responsible mail server or passing it to a local delivery agent work to be saved to a user's mailbox

The bulk of the work involved in setting up a mail system relates to the configuration of the MTA. In this book, we cover three open source MTAs: sendmail, Exim, and Postfix.

## Local delivery agents

A delivery agent, sometimes called a local delivery agent (LDA), accepts mail from a transport agent and delivers it to the appropriate recipients' mailboxes on the local machine. As originally specified, email can be delivered to a person, to a mailing list, to a file, or even to a program. However, the last types of recipients can weaken the security and safety of your system.

MTAs usually include a built-in local delivery agent for easy deliveries. procmail (procmail.org) and Maildrop (courier-mta.org/maildrop) are LDAs that filter or sort mail before delivering it. Some access agents (AAs) also have built-in-LDAs that do both delivery and local housekeeping.

## Message stores

The message store is the final resting of an email message once it has completed its journey across the Internet and been delivered to recipients.

## So many pieces, so little time

Mail has traditionally been stored in either mbox format or Maildir format. The former stores all mail in a single file, typically /var/mail/username, individual messages separated by a Special From. Maildir format stores each message in a separate file. A file for each message is more convenient but creates directories with many, many small files; filesystems may not be amused.

These flat files are still common message stores, ISPs with thousands or mills of email clients are looking to other technologies for their message stores, usually databases. Message stores are becoming more opaque.

## Access agents

Two protocols are used to access message stores and download email messages to a local device (workstation, laptop, telephone, etc.): IMAP and POP. Earlier versions of these protocols had security issues. Be sure to use a version (IMAPS or POP3s) that incorporates SSL encryption and hence does not transmit passwords in cleartext over the Internet.

We IMAP, the Internet Message Access Protocol, but POP delivers your mail message one at a time rather than all at once, which is kinder to the network (especially on slow links) and better for someone who travels from location. IMAP is especially good at dealing with the great attachments that some folks like to send; you can browse the headers of your messages and download the attachments until you are ready to deal with them.

IMAP manages folders among multiple sites; for example, your mail server and your PC. Mail that stays on the server can be part of the normal backup schedule. The Wikipedia page for IMAP contains information and a list of available implementations.

POP, the Post Office Protocol, is similar to IMAP but assumes a model in which all email is downloaded from the server to the client. The mail can either be deleted from the server (in which case it might not be backed up) or saved on the server (in which case your mail pool grows larger and larger). The "mailbox at a time" paradigm is hard and not flexible for the user. It can be really slow if you are a pack rat and have a large mail pool file.

Some IMAP/POP server implementations are Courier, Cyrus IMAP, Dovecot, UW³ imap, and Zimbra. Dovecot and Zimbra are our favorites. Every mail user agent supports both IMAP and POP.

## So many pieces, so little time

With a mail system consisting of so many pieces (and we haven't even addressed spam and virus scanning!), the architecture of mail feels overly complex. At smaller sites, the MTA can largely absorb the functions of the MSA and LDA, and that keeps things simple. Larger sites may want to keep all the pieces separated and run multiple instances of each piece to help spread load.

## 20.2 THE ANATOMY OF A MAIL MESSAGE

A mail message has three distinct parts:

- The envelope
- The headers
- The body

The envelope determines when the message will be delivered, to whom it is returned. The envelope is invisible to users and is used internally by the MTA. The envelope addresses generally agree with the From and To lines of the header and may not agree if the message was sent to a mailing list or was generated by a spammer trying to conceal his identity. The headers are a collection of property/value pairs as specified in RFC5322. They record all kind of information about the message, such as the date and time the agents it passed through, and who is from. The headers are a bona fide part of the message, but users often hide the less interesting ones when displaying messages. The body of the message is the content to be sent. It usually consists of plain text, although it often represents various types of binary content.

## Reading mail headers

Dissect mail headers and using them to locate problems within mail systems is essential sysadmin skill. Many users hide the headers, but there is usually a way to see them if you have to use an editor on the message store.
