Linux rsync packages usually include a xinetd configuration for rsync. However, you must edit /etc/xinetd.d/rsync and change disable = yes to disable = no to actually enable the server.

As of this writing, rsync is not shipped as part of the Solaris distribution. You can download the source code from rsync.samba and install it, or google for a prepared Solaris binary. You may need to use inctconv to convert the daemon-startup method to be compatible with Solaris's new SMF framework.

Once you have enabled rsync, you need to set up a couple of config files to tell the rsync server how to behave. The main file is /etc/rsync.conf, which contains global configuration parameters and a set of "modules", each of which is a directory tree to export or import. A reasonable configuration for a module that you can push to (i.e., that will accept incoming file transfers initiated by the connecting client) looks something like this:

```
# sysfiles is an arbitrary title for the particular module.
[sysfiles]
# This is the path you allow files to be pushed to. It could be /
path = /etc
# This is the file specifying the user/password pair to authenticate the module
secrets file = /etc/rsync.secrets
# Can be read only if you are pulling files
read only = false
# UID and GID under which the transfer will be done
uid = root
gid = root
# List of hosts that are allowed to connect
hosts allow = distribution_master_hostname
```

Many other options can be set, but the defaults are reasonable. This configuration limits operations to the /etc directory and allows access only by the listed host. From the user's client's point of view, you can use rsync files to the server with the destination hostname:sysfiles, which maps to the module above.
