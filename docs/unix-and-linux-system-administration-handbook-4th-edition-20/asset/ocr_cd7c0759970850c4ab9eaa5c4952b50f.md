available to them. You can effect the same configuration by clicking a check box in

If someone has plugged in a new printer, if you've brought your laptop to work,
or if you've just installed a new workstation, you can tell cupsd to look and see
what's out there by clicking on the Find New Printers button in the Administra-
tab of the CUPS GUI.

Because broadcast packets do not connect subnet subnets, it's a bit tricky to
make printers available to multiple subnets. One solution is to designate a slave
server on each subnet that polls the other subnets' servers for information and
then relays that information to machines on the local subnet.

For example, suppose the print servers alice (192.168.1.5) and jj (192.168.2.14) live
on different subnets and we want both of them to be accessible to users on a third
ubnet, 192.168.3.10. We designate a slave server (say, copeland, 192.168.3.10) and
add these lines to its cupsd.conf:

```
BrowsePoll allie
BrowsePoll jj
BrowseRelay 127.0.0.1 192.168.2.355
```

The first two lines tell the slave's cupsd to poll the cupsds on alice and jj forfor-
mabout the printers they serve. The third line tells copeland to relay the
information it learns to its own subnet. Simple!

Need a more sophisticated setup? Multiple queues for one printer, each with dif-
erent defaults? A single server that load-balances by parceling jobs to several
inters? Multiple servers that handle interchangeable instances of the same
kind of printer? lpd or Windows clients? There's too much variation to go through
here, CUPS handles all these situations, and the documentation can walk you
through the details. (See the section on documentation, starting on page 1083).

# Filters

Rather than using a specialized printing tool for every printer, CUPS uses a chain
of filters to convert each printed file into the printer can understand.

The CUPS filter scheme is elegant. Given a document and a target printer, CUPS
uses its .types to figure out the MIME type. It consults the
PDF file to figure out what MIME the printer can handle. It uses
tconv filters to deflate one format to the
other, and what each prospective chain would cost. Finally, it picks a chain and
passes the document through those filters. The final filter in the chain passes the
printable format to a back end, which transmits the data to the printer through
whatever hardware or protocol the printer understands.
