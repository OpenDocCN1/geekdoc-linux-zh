# 19.2 COPYING FILES AROUND

Brute-file copying is not an elegant solution, but it works on every kind of
machine and is easy to set up and maintain. It's a reliable system because mini-
izes the interdependencies among machines (although it may make it easier
for machines to fall out of sync). File copying also offers the most flexibility
in terms of what can be distributed, and it is often used to keep applications
data files, as well as system files, up to date.

Quite a few configuration files are not supported by any of the common database
services. /etc/ntp.conf, which determines which hosts keep their clocks synchro-
ized. To keep files in sync, you really have no choice but to
use some sort of file-copying system.

# The NFS option

Some distribute configuration files by publishing them on an NFS server.
This is perhaps the simplest technique from an automation point of
view—all you need on the client or cp, at least.

NFS used to have security issues that this approach is a bit risky, but in NFS4,
those concerns have largely been addressed. For extra security, you can use en-
cryption to protect sensitive files from inspection by eyes.

Another step increases security is to have the publisher sign configuration
files with a public key cryptography package as PGP. Clients can verify
they files are being offered through NFS are authentic and unmodified
before installing them.

Many software packages let you specify a nonstandard location for configuration
files. Therefore, it's theoretically possible to point these packages at configuration
files that live on an NFS filesystem, making no copies at all. However,
we strongly advise against this configuration. It makes every system in the world

clients. Worse yet, many packages don't enable remote systems to lock their
