# Chapter 14 TCP/IP Networking

In older versions of Solaris, the network startup scripts were files in /etc/init.d (chiefly rootusr, ininitit, sysid.net, and inetsvc). Solaris 10 radically restructured the way that startup files and system services are managed. The scripts have been refactored and now use in /lib/svc/method. See page 97 for an overview of Solaris's Service Management.

If /etc/defaultrouter exists, it is assumed to contain the identity (which can again be a hostname or a numeric address) of the default gateway, and no further routing configuration is performed. As usual, a numeric address is preferable; using a name requires an /etc/hosts entry or a DNS server on the local network.

Solaris used to run routed (which is called routed) whenever no default gateway was specified, but in Solaris 10 and later you may enable routed explicitly with svadm enable routing/route. Use the svcmd route to determine the service's current state.

Beware: routed will go into server (talkative) mode automatically if the machine has more than one network interface or the file /etc/gateways exists. This is generally not what you want. You can prevent routed from squawking by turning on the "quiet mode" flag:

```
solaris# svconfig -s routing/route:default setprop routing/quiet_mode = true
```

# Solaris configuration examples

Here are some examples of the commands needed to bring a Solaris interface and add a route to a default gateway:

```
solaris$ sudo ifconfig e1000g0
solaris$ sudo ifconfig e1000g0 192.108.21.48 mask 255.255.255.0 up
solaris$ sudo route add 192.108.21.254
```

The following examples show how to see the status of network interfaces and routing tables. Commands prefaced with sudo must be run as root. The final example shows a feature of the Solaris route command that is not present on our other architectures: the get argument shows the next hop to a particular destination. We have taken liberties to make them fit on the page:

```
solaris$ ifconfig -a
io0:flags=UP,LOOPBACK,RUNNING,MULTICAST,IPv4,VIRTUAL>
mtu 832 index 1 127.0.0.1 mask ff000000
e1000g0:flags=1000843-UP,BROADCAST,RUNNING,MULTICAST,IPv4> mtu 1500
index 2 inet 192.108.21.48 mask fxffffff broadcast 192.108.21.255
```

```
solaris$ ifconfig e1000g0
e1000g0:flags=1000843-UP,BROADCAST,RUNNING,MULTICAST,IPv4> mtu 1500
index 2 inet 192.108.21.48 mask fxffffff broadcast 192.108.21.255
ether 0:14:4f:e6:1c
```

Notice that when run as root, ifconfig shows the hardware address, but when run as a user, it does not.
