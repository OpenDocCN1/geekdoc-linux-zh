# Running restore job

+   * Select the most recent backup for a client
* Select backup for a client before a specified time
* Enter a list of files to restore
* Enter a list of files to restore before a specified time
* Find the Jobsbid of the most recent backup for a client
* Find the Jobsbid for a backup for a client before a specified time
* Enter a list of directories to restore for found Jobsbid
* Cancel

Select item: (1-12):

The three most useful options are probable "Select the most recent backup for a client (#5), "Select backup for a client before a specified time" (#6), and List Jobs where a given File is saved (#2). The first two of these options provide a shell-like environment for selecting files, similar to that of restore -i. That comes handy for pesky users who can never seem to remember exactly where the file they removed lives. Another powerful way to find Job IDs option #4,"Enter SQL command," which lets you enter any properly formatted SQL query. (Of course, you may be familiar with the database schema).

Suppose that a user needs a copy of their pw_expire.pl script restored. However, ever not in which directory he keeps the file. In addition, he would like the files restored to the /tmp directory of the original machine would set a system administrator to grumbling around the water cooler, for the Bacula administrator it's a snap.
