```
###### macros to define the directories for databases and keys
CONFIG_DIR = path_to_config_dir
DKEY_DIR = path_to_key_dir
```

```
###### main section: define the domains to sign and require DKIM acl
domainlist dksign_domains = cdb:CONFIG_DIR/dk.selector.cdb
acl_smtp_dkim = acl_process_dkim
```

```
###### acl: verify status on incoming mail, add a header
warn 'dkim_status = none
add_header =at:start:X-DKIM-Report: ${dkim_verify_status[$dkim_verify_reason]]} \ \
${Signer=${dkim_cur_signer} (Testing=${dkim_key_testing})
```

```
###### Router section: put just before "dnslookup" router, sign nonlocal
dnslookup:
driver = dnslookup
domains = !+local_domains
transport = remote_dksign
condition = ${if match_domain[$sender_address_domain]} \ \
+{dksign_domains]}
no_verify
```

```
###### Transport section: does the actual signing
remote_dkim:
driver = smtps
dkim_domain = $sender_address_domain
dkim_selector = ${lookup[$sender_address_domain]} \ \\ncdb(CONFIG_DIR/dk.selector.cdb) ${valuefail}
dkim_private_key = $DKEY_DIR/rsa.private. $dkim_selector.$dkim_domain
dkim_stricit = 1
```

These fragments result in outgoing messages being signed and incoming messages their signatures verified and DKIM report header added. Here's an example of that header:

X-DKIM-Report: pass (Signer@gmail.com) (Testing=0)

Further policy is needed if you are to reject or punish messages whose do not verify.

The no_verify line in the router section refers not to DKIM verification but rather verifying the recipient's address; it is turned off in this router, but done in the dnslookup router that is in line. No sense doing it twice.
