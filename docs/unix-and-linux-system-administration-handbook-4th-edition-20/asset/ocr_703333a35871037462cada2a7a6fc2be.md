# Chapter 6 The Filesystem

As a general rule, never touch a file or directory's mode once you've applied an ACL. If worse comes to worst, remove the ACL with chmod A- file and start over.

Modifying NFSv4 ACLs in Solaris
Because ZFS enforces consistency between a file's mode and its ACL, all files have at least a trivial ACL (virtual or not). Ergo, ACL changes are always updated. You make ACL changes with chmod. The basic syntax is the same as:

```
chmod [-R] acl_operation file ...
```

Table 6.11 shows the various types of ACL operations understood by chmod. Unfortunately, there is no ACL analog of chmod's incremental, symbolic syntax for manipulating traditional modes. You cannot add or remove individual permissions from an ACE; you must replace the entire.

| Operation | Function |
| --- | --- |
| A-index- | Replaces the entire ACL with its trivial version from the mode |
| A-ace | Deletes a access control entry by position |
| Index=ace,[ace...] | Deletes a access control entry wherever it appears |
| A+ace | Adds one or more access control entries |
| Index+ace,[ace...] | Adds an access control entry to the top of the ACL |

```
solaris$ chmod A:user:Callow /var/tmp/example
```

gives the user ben to edit the ACL on the /var/tmp/example directory. Remember that access determination is an iterative process that works its down the ACL, so retains any rights he had under the previous version of the ACL. The new access control entry goes at the start of the ACL (at index 0), so the command

```
solaris$ chmod A0- /var/tmp/example
```

removes the ACE that was just added and reverts the ACL to its original state.
