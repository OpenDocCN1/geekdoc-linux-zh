The Samba components, on the other hand, should be as fresh as possible. Active Directory integration is one of Samba's newer features, downloading the most recent source code from samba.org can eliminate frustrating bugs.

If you build Samba from source, configure it with the idmap_ad and idmap_rid shared modules. The appropriate argument to the /configure script is

```
--with-shared-modules=idmap_ad,idmap_rid
```

Build and install Samba with the familiar make, make sudo install sequence. When installed correctly, the winbind library is deposited in /lib:

```
ubuntu$ ls -l /lib/libwinbind.so.2
-rw-xr-r-- 1 root root 21884 2009-10-08 00:28 /lib/libwinbind.win..2
```

The winbind daemon is stopped and started through normal operating system procedures. It should be restarted after changes to nswitch.conf, smb.conf, or the Kerberos configuration file, krb5.conf. There is no need to start it until other services have been configured.

# Configuring Kerberos for Active Directory integration

Kerberos is infamous for complex configuration, particularly on the server side. Fortunately, you only need to set the client side of Kerberos, which is a much easier task. The configuration file is /etc/krb5.conf.

First, double-check the system's fully qualified domain name has been included in /etc/hosts and NTP is an Active Directory server as a time reference. Then, edit krb5.conf to add the realm as shown in the following example. Substitute your AD domain for ULSA.COM.

```
[logging]
default = /var/log/krb5.log
[defaults]
clockskew = 300
default_realm = ULSA.COM
kdc_timesync = 1
ccache_type = 4
forwardable = true
proxiable = true
[realms]
ULSA.COM = {
ndc = dc.ulsa.com
admin_server = dc.ulsa.com
default_domain = ULSA
}
[domain_realm]
lulsa.com = ULSA.COM
lulsa.com = ULSA.COM
```
