Although HP-UX also uses the ndd command to control its IP protocol stack, the underlying IP implementation has the ability to ignore ICMP redirects. However, you can arrange to have the routes from these redirects deleted from the routing table later with

```
**ndd -set /dev/ip_ire_redirect=1000**
```

Some versions of HP-UX have enforced minima of 5 or 60 seconds on this parameter (which is expressed in milliseconds), but HP-UX 11 appears to accept smaller values without complaint.

On AIX, the command to ignore ICMP redirects is **no -p ignoreredirects=1**. The **-p** option makes a permanent change; omit this to test the change temporary. See page 507 for more details.

# 14.6 ARP: THE ADDRESS RESOLUTION PROTOCOL

ARP is defined in RFC826.

Although IP addresses are hardware-independent, hardware addresses must be used to actually transport data across a network's layer. ARP, the Address Resolution Protocol, discovers the hardware address associated with a particular IP address. It can be used on any kind of network that supports broadcasting is most commonly described in terms of Ethernet.

If A wants to send a packet to B on the same Ethernet, it uses ARP to discover B's hardware address. If B is not on the same network as A, A uses the routing system to determine the next-hop router along the route to B and then uses ARP to find router's hardware address. Since ARP broadcasts packets, which cannot cross networks, it can only be used to find the hardware addresses of machines directly connected to the sending host's local network.

Every machine maintains a table in memory called the ARP cache, which contains the results of recent ARP queries. Under normal conditions, many of the addresses a host needs discovered soon after booting, ARP does not count for a lot of network traffic.

ARP works by broadcasting a packet of the "Does anyone know the hardware address for 128.138.116.4?" The machine being recognizes its own IP address and replies, "Yes, that's the IP assigned to one of my network interfaces, and the corresponding Ethernet address is 8:0:20:0:fb:6a."

The original query includes the IP and Ethernet addresses of the requester so that the machine can reply without issuing an ARP query of its.
