# 5.11 RUNAWAY PROCESSES

See page 1131 for more information about runaway processes.

Runaway processes come in two flavors: user processes that consume excessive amounts of a system resource, such as CPU time or disk space, and processes that suddenly go bererk and exhibit wild behavior. The first type of runaway is not necessarily malfunctioning; it might simply be a resource hog. System processes are always supposed to behave reasonably.

You can identify processes that use excessive CPU time by looking at the output of ps or top. If it's obvious that a user process is consuming more than reasonable, investigate the process. It can also be useful to look at the number of processes waiting to run. Use the uptime command to show the load averages (average number of runaway processes) over 1, 5, and 15 minutes.

There are two ways to find out what a process is before tampering with it. First, the process may be legitimate and important. It is unreasonable to kill processes at random just they happen to use a lot of CPU. Second, the process may be malicious or destructive. In this case, you've got to know what the process was doing (e.g., cracking passwords) so that you can fix the damage.

Processes that make excessive use of memory relative to the system's physical RAM can cause performance problems. You can check the memory size of processes by using top. The VIRT column shows the total amount of memory allocated by each process, and the RES column shows the portion of memory that is currently mapped to specific pages (the "resident set"). On Linux systems, applications that use the video card (such as the X server) have a bad rap because video memory is included in the memory usage computations.

Both of these numbers can include shared resources such as libraries, and make them potentially misleading. A more direct measure of process-specific memory consumption is found in the DATA column, which is not shown by default. Add this column to top's display, type the Fkey once top is running and select DATA from the list. The DATA value indicates the amount of memory in each process's data and stack segments, so it's relatively specific to individual processes (modulo shared memory segments). Look for growth over time as well as absolute size.

Runaway processes that produce output can fill up an entire filesystem, causing numerous problems. When a filesystem fills up, lots of messages will be logged to the console and attempts to write to the filesystem will produce error messages.

The first thing to do in this situation is to determine which filesystem is full and which file is filling up. Use the df-k command to show filesystems. Look for a filesystem that is 100% or more full. Use the command on the identified filesystem to find which directory is using the most space. Rinse and repeat with du
