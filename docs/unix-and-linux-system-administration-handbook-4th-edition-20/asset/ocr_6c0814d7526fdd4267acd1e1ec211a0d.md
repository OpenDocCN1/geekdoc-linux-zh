# Chapter 6 The Filesystem

chown can change both the owner and group of a file at once with the syntax
chown user:group file ...

For example,

```
$ sudo chown -R matt:staff -matt/restore
```

Linux and Solaris takes this syntax to its logical end and let you omit either user or
group, making the chgrp command superfluous. If you include the colon as
no group, chown uses the user's default group.

# umask: assign default permissions

You can use the built-in shell command umask to influence the default permis-\ions given to the files you create. Every process has its own umask attribute;
thell's built-in umask command sets the shell's own umask, which is inher-
ited by commands that you run.

The umask is specified as a three-digit octal value that represents the permissions
to take away. When a file is created, its permissions are set to whatever the creat-\ing program requests whatever the umask forbids. Thus, the individual
digits of the umask allow the permissions shown in Table 6.6.

Table 6.6 Permission encoding for umask
| Octal | Binary | Perms | Octal | Binary | Perms |
|---|---|---|---|---|--|
| 0 | 000 | rwx | 4 | 100 | --wx |
| 1 | 001 | rw-- | 5 | 101 | -w- |
| 2 | 010 | r-x | 6 | 110 | --x |
| 3 | 011 | r-- | 7 | 111 | --- |

For example, umask 027 allows permissions for the owner who forbids write\permission to the group and allows no permissions for anyone else. The default
umask value is often 022, which denies write permission to the group and world
but read permission.

You cannot force users to have a particular umask value because they can always
reset it to whatever they want. However, you can put a suitable default in the sam-
profile file that gives you yours.

# Linux bonus flags

Linux's ext2, ext3, and ext4 filesystems define some supplemental attributes you
 turn on to request special semantics—“request” being the operative word,
since many of the flags haven't actually been implemented. For example, one flag
makes a file append-only and another makes it immutable and undeletable.
