# Chapter 20 Electronic Mail

A better paradigm might be

```
# Basic system aliases -- these MUST be present.
mailer-daemon: "dev/null"
postmaster: root
```

You should redirect root's mail to your site's sysadmins or to someone who logs in every day. The bin, sys, daemon, nobody, and hostmaster accounts (and any other pseudo-user accounts you set up) should have similar aliases.

In addition to a list of users, aliases can refer to

+   - A file containing a list of addresses
- A file to which messages should be appended
- A command to which messages should be given as input

These last two targets should push your "What about security?" button because the sender of a message totally determines its content. Being able to add content to a file or deliver it as input to a command sounds pretty scary. MTAs either not allow these targets or severely limit the commands and permissions that are acceptable.

Aliases can cause loops. MTAs try to detect loops that would cause mail to be forwarded back and forever and return the messages to the sender. When determining mail is looping, an MTA can count the number of Received lines in a message header and stop forwarding it when it reaches a preset limit (usually 25). Each visit to a new machine is a "hop" in email journal; returning a message to the sender is known as "bouncing". A more properly jargon summary of loop handling would be, "Mail bounces after 25 hops." Another way MTAs can detect loops is by having a Delivered-To header for each host to which a message is forwarded. If an MTA finds itself wanting to send a message to a host that's already mentioned in a Delivered-To header, it knows the message has traveled in a loop.

# Getting aliases from files

The :include: directive in the aliases file (or a user .forward file) allows the list of targets for the alias to be taken from the specified file. It is a great way to let users manage their own mailing lists. The included file can be owned by the user and changed without involving a system administrator. However, an alias can also become a tasty and effective spam expander, so don't let email from your site be directed there. If users outside your site need to send mail to the aliases, using mailing list software such as Mailman (on page 760) to help keep the system secure.

We have been inconsistent with terminology in this chapter, sometimes calling a returned message a "bounce" and sometimes calling it an "error." What we really mean is that delivery status notification (DSN, a specially formatted email message) has been generated. Such a notification means that a message was undeliverable and is therefore returned to the sender.
