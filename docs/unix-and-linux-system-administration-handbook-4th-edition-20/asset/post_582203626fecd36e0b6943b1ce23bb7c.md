
# Setup for automatic mounting

By default, ZFS filesystems mount themselves automatically and do not require vstab entries. However, you can change this behavior by setting ZFS filesystem properties. Swap areas and non-file mounts should still appear in vstab.

![](img/579efec8c67772f31ecf34844bbb71a2_309_0.png)

mount, umount, swapon, and fsck read all the filesystem catalog, as it is helpful if the data presented there is correct and complete. mount and use the catalog to figure out what you want done if you specify only a partition name or mount point on the command line. For example, with the Linux vstab configuration on page 262, the command

```
$ sudo mount /media/cdrom0
```

would have the same effect as typing

```
$ sudo mount -t udf -o user,noauto,exec,utf8 /dev/sd0 /media/cdrom0
```

The command mount -a all regular filesystems listed in the filesystem catalog; it is usually executed from the startup scripts at boot time. The -t, -F, or -v flag (-F for Solaris and HP-UX, -v for AIX) with a f argument constraints the operation to filesystems of a certain type. For example,

```
$ sudo mount -ext4
```

mount all local ext4 filesystems. The mount command reads vstab sequentially. Therefore, filesystems that are mounted beneath other filesystems must follow their parent partitions in the vstab file. For example, for /var/log must follow the line for /var if /var is a separate filesystem.

The command for unmounting filesystems accepts a similar syntax. You cannot mount a filesystem that a process is using as its current directory or which files are open. There are commands to identify the processes that are interfering with your ummount attempt; see page 144.

![](img/579efec8c67772f31ecf34844bbb71a2_309_1.png)

The HP UX vstab file is the most traditional of our examples. Here are entries for a system that has only one volume group:

| Device | Mount point | Type | Options | Dump | Pass |
|---|---|---|---|---|---|
| /dev/vg00/vol3/ | | vxfs | delayog | 0 | 1 |
| /dev/vg00/vol1/stand | | vxfs | tranflush | 0 | 1 |
| /dev/vg00/vol4/tmp | | vxfs | delayog | 0 | 2 |
| /dev/vg00/vol5/home | | vxfs | delayog | 0 | 2 |
| /dev/vg00/vol6/opt | | vxfs | delayog | 0 | 2 |
| /dev/vg00/vol7/usr | | vxfs | delayog | 0 | 2 |
| /dev/vg00/vol8/var | | vxfs | delayog | 0 | 2 |

There are six fields per line, separated by whitespace. Each line describes a filesystem. The fields are traditionally aligned for readability, but alignment is not required. The noauto option excludes a given filesystem from automatic mounting by mount -a.

The first field gives the device name. The fstab file can include mounts from remote systems, in which case the first field contains an NFS path. /export indicates the /export directory on the machine. The second field specifies the mount point, and the third field used to identify filesystems varies among machines. The fourth field specifies mount options to be applied by default. There are many possibilities; see the mount page for the ones that are common to all filesystem type. The options shown above are specific to VxFS. The fifth and sixth fields are vestigial. They are the dump and fsck column. Neither is important on contemporary systems.

Below are some additional examples culled from an Ubuntu system fstab. The general format is the same, but Linux systems show some flourishes:

| Device | Mount point | Options | Dump | Pass |
|---|---|---|---|---|
| /proc | defaults | 0 | 0 |
| UUID=ae3..bdf / | ext4 errors=ro | 0 | 1 |
| UUID=3e9..bd2 swap | none sw | 0 | 0 |
| /dev/sd0 /media/cdrom0 | user.iso960 | noauto,exec | 0 | 0 |
| /dev/sd1 /media/cdrom1 | user.iso960 | noauto,exec | 0 | 0 |
| /dev/fd0 /media/floppy | rw,userauto,exec | 0 | 0 |

![](img/579efec8c67772f31ecf34844bbb71a2_310_0.png)

The first line indicates /proc filesystem which is in fact presented by the kernel and has no active backing store. The device listed in the first column is just a placeholder. The second and third lines use partition ID (UUIDs), truncated to make more readable instead of device names. This alternative is useful on Linux systems where device names of partitions are unstable; adding or removing can cause the others to change (e.g., from /dev/sd1 to /dev/sdc). UUID is linked only to the content of the partition, so it allows swap as well as root. The last three lines configure support for CD-ROM and floppy devices. noauto prevents the system from mounting these devices at boot time (If media were inserted, the mount would fail). The user option makes all the removable drives appear to be owned by the user.

On Solaris systems, the /etc/vfstab file has a slightly reorganized format with the order of fields relative to Linux and HP-UX. However, data is still tabular and easily readable without much effort. The distinguishing features of vfstab format are that it has a separate "device to fsck" column and a separate "mount at boot" column. AIX's /etc/yaml file is organized as a series of properties somewhat reminiscent of YAML or JSON, although the format is different. Here is an example for one filesystem:

```
dev = /dev/hd1
vfs = /jfs2
log = /dev/hd8
mount = true
check = true
vol = /opt
free = false
```

This format is nice in that it allows arbitrary properties to be associated with each filesystem, so filesystem-specific parameters can be recorded in the catalog. AIX automatically maintains this file when you perform disk operations through SMIT, but it's fine to edit the file, too.

# USB mounting

Floppy disks have finally gone the way of the past, and are gone. In their place are friendly, fast, and USB drives. These devices come in many flavors: personal "thumb" drives, digital cameras, iPods, and large external disks, to name a few. Most of these are supported by UNIX systems as data devices.

In the past, special tricks were necessary to manage USB devices. But by now operating systems have embraced dynamic device management as a fundamental requirement; USB drives are just one type of device that shows up or disappears without peers. From the perspective of storage management, the issues are

- Getting the kernel to recognize a device and assign a device to it
- Finding out assignment has been made

The first step usually happens automatically, but systems have commands (such as AIX's cfgmgr) that you can use to go if you need to. Once a device file has been assigned, you can use the normal procedures described in Disk device files page 224 to find out what it is.

For additional information about dynamic device management, see Chapter 13, Drivers and the Kernel.

# Enabling swapping

Raw partitions or logical values, rather than structured filesystems, are normally used for swap space. Instead of using a filesystem to keep track of the swap area's contents, the kernel maintains its own simplified mapping from memory blocks to swap space blocks.

On some systems, it's also possible to swap a file in a filesystem partition. Over older kernels this configuration can be slower than a dedicated partition, but it's still very handy in a pinch. In any event, logical volume managers eliminate most of the regions you might want to use a swap file rather than a swap volume.

See page 129 for information about splitting areas.

The swap space you have, the virtual memory processes can also allocate. The best virtual memory performance is achieved when the swap area is split among several devices. Of course, the best option of all is not to swap; consider adding RAM if you find yourself needing to optimize swap performance.

On Linux, swap areas must be initialized with mkswap, which takes the device name of the swap volume as an argument.

You can manually enable swapping to a particular device with swap or -a device on Solaris. However, you will generally want to have this function performed automatically at boot time. Except on AIX, you can list swap areas in the regular filesystem catalog (stab or vstab) by giving them a filesystem type of swap. AIX has a separate file that lists the system's swap areas, /etc/swapspaces.

To review the system's current swapping configuration, run swap -s on Linux, swap -s on Solaris, or swapinfo on HP-UX.
