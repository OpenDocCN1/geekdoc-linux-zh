# The format of crontab files

Each of the time-related fields may contain

+   - A star, which matches everything
- A single integer, which matches exactly
- Two integers separated by a dash, matching a range of values
- A range followed by a slash and a step value, e.g., 10-1/2 (Linux only)
- A comma-separated list of integers or ranges, matching any value

For example, the time specification

```
45 10 * * 1-5
```

"10:45 a.m., Monday through Friday.\u201d Hint: never put a star in the first field unless you want the command to run every minute.

There is a potential ambiguity to watch out for with the weekday and dom fields. Every day is a day of the week and a day of the month. If both weekday and dom are specified, a day need satisfy only one of the two conditions in order to be selected. For example,

```
0,30 * 13 * 5
```

"every half-hour on Friday, and every half-hour on the 13th of the month,\u201d not every half-hour on Friday the 13th.\”"

The command is the sh command line to be executed. It can be any valid command should not be quoted. The command is considered to continue to the end of the line and may contain blanks or tabs.

Although sh is involved in executing the command, the shell does not act as a login shell and does not read the contents of ~/profile or ~/.bash_profile. As a result, the command's environment variables may be set up something differently from what you expect. If a command seeks to work when executed from the shell fails when introduced into a crontab file, the environment is the likely culprit. If need, you can wrap your command into a script that sets up the appropriate environment variables.

Percent signs (%) indicate newlines within the command field. Only the text up to the first percent is included in the actual command. The remaining lines are given to the command as standard input.

Here are some examples of legal crontab commands:

```
echo The time now 'date' > /dev/console
mail -s Reminder@email % Don't forget to write your chapters.
cd /etc; /bin/mail -s "Password file" evi < password
```

And below are some additional examples of complete crontab entries:

```
30 2 * * 1 (cd /home/joe/project; make)
```
