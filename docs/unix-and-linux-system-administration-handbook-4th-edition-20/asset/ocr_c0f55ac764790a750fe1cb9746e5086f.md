We recently experienced a disk controller failure on an important production server. Although the data was replicated across several physical drives, a faulty hardware RAID controller destroyed the data on all. A lengthy and ugly restore process ensued, and it was more than two months before the server had completely recovered. The rebuilt server now relies on the kernel's software to manage its RAID environment, removing the possibility of another RAID controller.

# RAID levels

RAID can do two basic things. First, it can improve performance by "striping" across multiple drives, allowing several drives to work simultaneously to supply or absorb a data stream. Second, it can replicate data across multiple drives, increasing the risk associated with a single failed disk.

Replication assumes two basic forms: mirroring, in which data blocks are reproduced-for-bit on several different drives, and parity schemes, in which one or more drives contain an error-correcting checksum of the blocks on the remaining data drives. Mirroring is faster but consumes more disk space. Parity schemes are more disk-efficient but have lower performance.

RAID is traditionally described in terms of "levels" that specify the exact details of the parallelism and redundancy implemented by an array. The term is perhaps misleading because "higher" levels are not necessarily "better". The levels are different configurations; use whichever versions suit your needs.
