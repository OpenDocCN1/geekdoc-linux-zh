# Telling Apache about virtual interfaces

In addition to creating the virtual interfaces, you need to tell Apache what to serve when a client tries to connect to each interface (IP address). You can do this with a VirtualHost clause in the httpd.conf file. There is one VirtualHost clause for each virtual interface that you have configured. Here's an example:

```
<VirtualHost 128.138.243.150>
ServerName www.company.com
ServerAdmin webmaster@www.company.com
DocumentRoot /var/www/htdocs
ErrorLog /var/www/company.com-error_log
CustomLog /var/www/company.com-access_log_combined
ScriptAlias /cgi-bin/ /var/www/cgi-bin/company
</VirtualHost>
```

In this example, any client that connects to the virtual host 128.138.243.150 is served documents from /var/www/htdocs. Any Apache directive inside a VirtualHost clause define settings for that virtual host. Relative directory paths, including those for the DocumentRoot, ErrorLog, and CustomLog directives, are interpreted in the context of the ServerRoot.

With name-based virtual hosts, multiple DNS names all point to the same IP address. The Apache configuration is similar, but you specify the primary IP address on which Apache listens for incoming requests in the VirtualHost clause:

```
<VirtualHost *:128.138.243.150>
ServerName www.company.com
ServerAdmin webmaster@www.company.com
DocumentRoot /var/www/htdocs
ErrorLog /var/www/company.com-error_log
CustomLog /var/www/company.com-access_log_combined
ScriptAlias /cgi-bin/ /var/www/cgi-bin/company
</VirtualHost>
```

In this configuration, Apache looks in the HTTP headers to determine the requested site. The server listens for requests for www.company.com on its main IP address, 128.138.243.150.

# 23.4 The Secure Sockets Layer (SSL)

The SSL protocol secures communications between a web site and a client browser. URLs that start with https:// use this technology. SSL uses cryptography to prevent eavesdropping, tampering, and message forgery.
