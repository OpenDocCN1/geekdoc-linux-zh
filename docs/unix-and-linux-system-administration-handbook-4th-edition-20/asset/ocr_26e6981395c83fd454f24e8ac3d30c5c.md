# The Network File System

Under Solaris and HP-UX, **automount** can smoothly switch from one server of a replicated mount to another when problems occur. This feature is only supposeded to work properly for read-only mounts, but rumor has that it read-write mounts are handled more reasonably than the documentation would suggest. References to files that have been opened for writing till when **automount** changes servers, however, which is yet another reason why replicated-write mounts may not be useful.

**automount** can select among replicated servers according to its own criteria for efficiency and locality, you can also assign priorities if you like. The priorities are small integers, with larger numbers indicating lower priority. The default priority is 0, most elite.

An **auto-direct** file defines **/usr/man** and **/cs/tools** as replicated filesystems might like this:

+   - /usr/man -ro harp:/share/man monk(1):/usr/man
- /cs/tools -ro leopard:/cs/tools

Note that server names can be listed if the source path is on each same. The (1) after monk in the first line sets server's priority with respect to **/usr/man**. The lack of a priority after hard indicates an implicit priority 0.

# Automatic automounts (V3: all but Linux)

Instead of listing every possible mount in a direct or indirect map, you can tell **automount** a little about your filesystem naming conventions and let it figure out for itself. The key piece of glue that makes this work is the mount running on a remote server can be queried to find out what files the server exports. In NFS version 4, the export is /, which eliminates the need for this automation.

There are several ways to configure "automatic automounts," the simplest of which is the -hosts type. If you list *-hosts as a map name in your master file, automount then maps remote hosts' exports into the specified auto-directory:

```
/net      -hosts -nosuid,soft
```

For example, if harp exported **/usr/share/man**, the directory could be reached through the automounter at the path **/net/harp/usr/share/man.

The implementation of -hosts does not enumerate all hosts from which filesystems can be mounted; that would be impossible. It waits for individual subdirectory names to be referenced, then runs off and mounts the exported filesystems from the requested host.
