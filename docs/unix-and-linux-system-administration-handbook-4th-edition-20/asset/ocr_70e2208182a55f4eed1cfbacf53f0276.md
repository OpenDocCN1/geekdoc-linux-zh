You can connect to the remote targets with iscsiadm -m node -l

```
ubuntu sudo iscsiadm -m node -l
Logging to [if: default, target: iqn.1994-11.com.admin:test, portal:
192.168.0.75,3260]
Login to [if: default, target: iqn.1994-11.com.admin:test, portal:
192.168.0.75,3260]: successful
```

You can verify that the system now shows the additional disk by fdisk. (The device for iSCSI disks are named like for any other SCSI disks.) If you have set up the configuration files as described above, the connections should be restored at boot time.

For iSCSI target service on Linux, the preferred implementation is the iSCSI Enterprise Target hosted at iscsarget.sourceforge.net. It's usually available as a package called iscsarget.

Solaris includes target and initiator packages; both are optional. All packages listed to iSCSI have "iscsi" in their names. For the initiator side, install the package SunWICS; you will have to reboot afterward.

There is no configuration file; all configuration is performed with the iscsiadm command, which has rather strange syntax. Top-level verbs (add, modify, list, and remove) can be applied to a variety of different aspects of the initiator configuration. The following steps perform basic configuration of the initiator as a whole and to a target on the server is.

```
solaris$ sudo iscsiadm modify initiator-node -a CHAP -H testclient
solaris$ sudo iscsiadm modify initiator-node -C
Enter secret: <password for client>
Re-enter secret: <password for client>
solaris$ sudo iscsiadm modify discovery -s enable
solaris$ sudo iscsiadm add static-config iqn.1994-11.com.admin:test,iserver
solaris$ sudo iscsiadm list target -S
Target: iqn.1994-11.com.admin:test
```
