# Chapter 14 TCP/IP Networking

The IPFilter suite implements IP filtering, NAT, and transparent packet forwarding. It is free, open source, and works on either SPARC or Intel hardware. The IPFilter package includes **ipf** for configuring a firewall, **ipstat** for outputting the filterings rules that have been installed, and **ipnat** for implementing NAT.

See Chapter 22, *Security*, for details on packet filtering with IPFilter. The section about this topic starts on page 939. Here, we discuss only IPFilter's NAT features.

# Solaris NAT

To make NAT work, you must tell the kernel what addresses to map from, what addresses to map, and what port range to extend the address space. See page 462 for a general discussion of NAT and the mechanisms it uses to bridge from private to public address space.

To configure NAT, you supply rules to the **ipnat** command. The rules are similar to those used with **ipf** to implement packet filtering. But beware: like **ipf** rules are ordered. However, they have opposite precedence. To keep you your toes, the *first* matching rule is selected, not the last.

Below are examples of **ipnat** rules. To be activated at boot time, these would go in the **/etc/ipf/ipnat.conf** file:

```
eth1 192.168.1.0/24 -> 128.138.198.0/26 portmap tcp/udp 20000:65000
eth1 192.168.1.0/24 -> 128.138.198.0/26
```

We have assumed that eth1 is our interface to the Internet and that our internal network is numbered with the class C private address range. These rules map addresses from a /24 network into addresses from a /26 network can accommodate only one-quarter of the hosts that a /24 network can, it's potentially to run out of target addresses in this configuration. The *portmap* clause extends the address range by allowing each address to be used with 45,000 source ports.

The first rule covers all TCP and UDP traffic but does not affect ICMP; ICMP does not use the concept of a port. The second rule catches ICMP messages and tries to get them routed back to the right host. If the kernel cannot unambiguously determine who should receive a particular ICMP message, the packet goes out as a broadcast; machines that receive it out of context can ignore it.

On a home machine, you might be assigned just a real IP address by your ISP or ISP's DHCP server. If you are given a static address assignment, give the target network in the *map* line /32 designation and a large port range to accommodate the needs of all your local hosts. If you get a dynamic address each time you connect, use the notation 0/32 in the *map* line; it will make **ipnat** read the address directly from the network interface. For example, here is a line you might use for a single, dynamically assigned address:

```
eth1 192.168.1.0/24 -> 0/32 portmap tcp/udp 20000:65000
```
