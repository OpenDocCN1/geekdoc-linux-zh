## Hashes

A hash (also known as an associative array) represents a set of key/value pairs. You can think of a hash as an array whose subscripts (keys) are arbitrary scalar values; they do not have to be numbers. In practice, numbers and strings are the usual keys.

Hashes have % as their first character (e.g., %myhash), but in the case of arrays, individual values are scalar and begin with a $. Subscript is indicated with curly braces rather than square brackets, e.g., ${myhash['ron']}.

Hashes are an important tool for system administrators. Nearly every script you write uses them. In the code below, we read the contents of a file, parse according to the rules for /etc/passwd, and build a hash of the entries called names_by_uid. The value of each entry in the hash is the username associated with UID.

```perl
#!/usr/bin/perl
while ($ = <>) {
  ($name, $pw, $uid, $gid, $gecos, $path, $sh) = split /:/;
  $names_by_uid[$uid] = $name;
}
```

%ids_by_name = reverse %names_by_uid;

As in the previous script, we've packed a couple of new ideas into these lines. Before we go over each of these nuances, here's the output of the script:

```
$ perl hasample /etc/passwd
$names_by_uid('root') is 0
```

The while ($_ = <>) reads input line at a time and assigns it to the variable named $_. The value of the entire assignment statement is the value of the right hand side, just as in C. When you reach the end of the input, the <> returns a false value and the loop terminates.

To interpret <>, Perl checks the command line to see if you named any files there. If you did, it opens each file in sequence and runs the file's contents through the loop. If you didn't name any files on the command line, Perl takes the input of the loop from standard input.

Within the loop, a series of variables receives the values returned by split, a function that chops its input string using the regular expression passed to it as the field separator. The regex is delimited by slashes; this is another form of quoting, that's specialized for regular expressions but similar to the interpretation of double quotes. You could just as easily have written split ' ' or split ':'. When split's second argument is missing, Perl assumes you want to split the value of $_. To be clear, even if the pattern is optional; the default is to split at whitespace or any leading whitespace.

But wait, there's more. Even the original assignment of $_ back at the top of the loop is unnecessary. If you simply say

```perl
while (<>) {
```

Perl automatically stores each line in $_. You can process lines without making an explicit reference to the variable in which they're stored. Using $_ as a default operand is common, and Perl allows it more or less wherever it makes sense.
