It's especially important to split the paging (swap) area among several disks if possible, since paging can slow down the entire system. Many systems have both dedicated swap partitions and swap files on a formatted filesystem.

Some systems also let you set up multiple "memory-based filesystems," which are essentially the same thing as RAM disk. A special driver poses as a disk which actually stores data in high-speed memory. Many sites use a RAM disk for their /tmp filesystem or for other uses such as web server logs or emails. Using a RAM disk reduces the memory available for general use, but it makes the reading and writing of temporary files blindingly fast. It's generally a good deal.

The ls command, which lists files, and the f, which shows the processes that are using a filesystem, can be helpful for isolating disk I/O performance issues. These commands show interactions between processes and filesystems, some of which may be unintended. For example, if an application is writing its log to the same device used for database logs, a bottleneck may occur.

# xdd: analyze subsystem performance

Modern storage systems can involve network or SAN-attached devices, RAID arrays, and other layers of abstraction. Consider the xdd tool for measuring and optimizing these complex systems. xdd is available under the GPL and runs on all of our example systems (not to mention Windows).

xdd measures I/O on single systems and on clusters of systems. It is well documented and yields accurate and reproducible performance measurements. You can read about it at iperformance.com.

# sar: collect and report statistics over time

The sar command is a performance monitoring tool that has lingered through UNIX and Linux epochs despite its somewhat obscure command-line syntax. The syntax has its roots in AT&T UNIX.

At first glance, sar seems to display the same information as vmstat and iostat. However, there's one important difference: sar can report on historical as well as current data.

Without options, the sar command reports CPU utilization for the day at 10-minute intervals since midnight, as shown below. This historical data collection is made by the sal script, which is part of the sar tool and must be set up to run from cron at periodic intervals. sar stores the data it collects underneath /var/log directory in a binary format.

The Linux package that contains sar is called sysstat.
