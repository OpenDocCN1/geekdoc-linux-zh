# MAIL_HUB and SMART_HOST macros 787

LDAP database entries support a wild card entry, @domain, which reroutes addressed to anyone at the specified domain (as was done in the virtusetable).

By default, mail addressed to user@host1.mydomain would first trigger a lookup on user@host1.mydomain. If that failed, sendmail would try @host1.mydomain but not@mydomain. Including the line

```
LDAPROUTE_EQUIVALENT('host1.mydomain')
```

would also try the keys user@mydomain and @mydomain. This feature enables a single database to route mail to a complex site. You can also take the entries for-LDAPROUTE_EQUIVALENT clauses from a file, which makes the feature quite useful. The syntax for that form is

```
LDAPROUTE_EQUIVALENT_FILE(filename)
```

Additional arguments to the ldap_routing feature let you specify more details about the LDAP schema and control the handling of addresses names that have a +detail part. As always, see the cf/README file for details.

# Masquerading features

An email address is usually made up of a username, a host, and a domain, but many sites do not want the names of their hosts exposed on the Internet. MASQUERADE_AS macro lets you specify a single identity for other machines to hide. All mail appear to emanate from the designated machine or domain. This is fine for regular users, but for debugging purposes, system users as root should be excluded from the masquerade.

For example, the sequence

would stamp as coming from user@atrust.com unless it was sent by root of the mail system; in these cases, the mail would carry the name of the originating host. MASQUERADE_AS is just the tip of a vast masquerading iceberg that extends through a dozen variations and exceptions. The allmasquerade and masquerade_envelope features (in combination with MASQUERADE_AS) hide just the root of local info. See the cf/README for details.

# MAIL_HUB and SMART_HOST macros

Masquerading makes all appear to come from a single host or domain by rewriting the headers and, optionally, the envelope. Most sites will want all mail to actually come from (or go to) a single machine so they can control the flow of viruses, spam, and company secrets. You can achieve this control with a combination of MX records in the DNS, the MAIL_HUB macro for incoming mail, and the SMART_HOST macro for outgoing mail.
