# Configuring the master server for a zone

Configuring the master server for a zone

Here's the format you need for a zone of which this named is the master server:

```
zone "domain_name" {
  type master;
  file "path";
}
```

The *domain_name* in a zone specification must always appear in double quotes. The zone's data is kept on disk in a human-readable (and human-editable) file. Since there is no default for the filename, you must provide a file statement when declaring a master zone. A zone file is just a collection of DNS resource records in the formats described starting on page 574.

Other server-specific attributes are also frequently specified within the zone statement. For example:

```
allow-query { address_list }; [any]
allow-transfer { address_list }; [any]
allow-update { address_list }; [none]
zone-statistics { no } [no]
```

The access control options are not required, but it's a good idea to use them. They take either an IP address or a TSIG encryption key. As usual, the encryption is safe. The allow-update clause must be present with an address list that lists the hosts from which updates can occur. Dynamic updates apply only to master zones; the *allow-update* cannot be used for a slave zone. Be sure that this clause includes just your own machines (e.g., DHCP servers) and not the whole Internet.²⁹

The *zone-statistics* options named keep track of query/response statistics such as the number and percentage of responses that were referrals, resulted in errors, or demanded recursion. See the examples on page 676.

With all these zone-specific options (and about 40 more than we have covered), the configuration is starting to sound complicated. However, a master zone declaration consisting of nothing but a pathname to the zone file is perfectly reasonable. Here is an example, slightly modified, from the BIND documentation:

```
zone "example.com" {
  type master;
  file "forward/example.com";n  allow-query { any };
  allow-transfer { my-slaves };
}
```

Here, my-slaves would be an access list you had previously defined.

³⁰ You also need ingress filtering at your firewall; see page 932. Better yet, use TSIG for authentication.
