Bunch o’ Stuff includes a variety of supplemental information. Some chapters discuss optional features as those that support server virtualization. Others give advice on topics ranging from eco-friendly computing to the politics of running a system administration group.

Each chapter is followed by a set of practice exercises. Items are marked with an estimate of the effort required to complete them, "effort" is an indicator of both the difficulty of the task and the time required. There are four levels:

- *Easy*, to be straightforward
- Harder or longer, may require lab work
- Hardest or longest, requires lab work and digging
- Semester-long projects (in a few chapters)

Some of the exercises require root sudo access to the system; others require the permission of the local sysadmin group. Both requirements are mentioned in the text of the exercise.

# 1 Where to Start

An awful lot of UNIX and Linux information is available these days, so we've designed this book to occupy a niche and help you navigate the complexity of modern systems.

First, it's an orientation guide. It reviews the major features, identifies the components, and explains how they work.

Second, it's a quick-reference handbook that summarizes what you need to perform. For example, the ps command, which shows the status of running processes, and other essential tools on Linux.

Finally, this book focuses on the administration of servers. It's easy to set up a single system; harder to keep networks running smoothly in the face of load spikes, disk failures, and intentional attacks.

## 1.1 Essential Duties of the System Administrator

The Wikipedia page for "system administrator" includes a nice discussion of the tasks that system administration is generally thought to. This page quickly draws a sharp distinction between administration and software development, but in our experience, professional administrators spend much of their time writing scripts.

The sections below summarize some of the main tasks that administrators are expected to perform. These duties not necessarily be carried out by a single person, and at many sites the work is distributed among a team. However, at least one person must understand all the components and make sure every task is being done correctly.

# Account provisioning

Chapter 7 for more information about adding new users.

The system adds accounts for new users, removes the accounts of users that are no longer active, and handles all the account-related issues that come up in between (e.g., forgotten passwords). The process of adding and moving users can be automated, but certain administrative decisions (where to put a user's home directory, which machines to create the account on, etc.) must still be made before a new user can be added.

When a user no longer has access to the system, the user's account must be disabled. The files owned by the account should be backed up and then disposed of so that the system does not accumulate unwanted baggage over time.

# Adding and removing hardware

Chapters 8, 13, and 26 for more information about these topics.

When hardware is purchased or when hardware is moved from one machine to another, the system must be configured to recognize and use that hardware. Hardware support chores can range from the simple task of adding a printer to the more complex job of adding a disk array.
