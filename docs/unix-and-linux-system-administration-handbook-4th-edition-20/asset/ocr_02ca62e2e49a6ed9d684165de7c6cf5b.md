You detach filesystems with the unmount command. unmount complains if you try to unmount a filesystem that is in use; the filesystem to be detached must not have open files or processes whose current directories are located there, and if the filesystem is currently executing executable programs, they cannot be running.

Linux has a "lazy" unmount option (unmount -l) that removes a filesystem from the hierarchy but does not truly unmount it until all file references have been closed. It is debatable whether this is a useful option. To begin, with no guarantee that existing references will ever close on their own. In addition, the "semi-unmounted" state can prevent inconsistent filesystem semantics to the processes that are using; they can read and write through existing files but cannot open new files or perform other filesystem operations.

unmount -f force-uns a busy filesystem and is supported on all our examples. However, it's almost always a bad idea to use it on Non-MFS nodes, and it may not work on certain types of filesystems (e.g. those that keep journals, as ext3 or ext4).

Instead of reaching for unmount -f when a filesystem youre trying to unmount turns to be busy, run the fuser command to find which process holds references to that filesystem. fuser -cmpoint finds the PID of every process that's using a file or directory on that filesystem, plus a series of letter codes that show the nature of the activity: For example,

```
$ fuser -c /usr
/usr: 157tm 315tom 474tom 5049tom 84tm 496tom 490tom
1693bc 16902ctm 358tom 484tm
```

The exact letter code varies from system to system. Table 6.1 summarizes the meanings of the codes, but the details are usually unimportant; the PIDs that you want.

# Table 6.1 Activity codes shown by fuser -c

| Codes | Meaning |
| f,o | The process has a file open for reading or writing. |
| c | The process's current directory is on the filesystem. |
| e,t | The process is currently executing a file. |
| r | The process's root directory (set with chroot) is on the filesystem. |
| m,s | The process has a mapped file or shared library. |
