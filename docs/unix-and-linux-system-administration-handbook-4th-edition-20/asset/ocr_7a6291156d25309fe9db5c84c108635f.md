The chfn command lets users change their own GECO information.³ chfn is useful for keeping things phone up to date, but it can be misused. For example, a user can change the information to be either obscure or incorrect. Some systems can be configured to restrict fields chfn may modify; some colleges disable it. On most systems chfn understands only the /etc/passwd file, if you use LDAP or some other directory service for information, chfn may not work at all.

# Home directory

A user's home directory is his or her default directory at login time. Be aware that if home directories are mounted over a network filesystem, they may be unavailable in the event of server or network problems. If the home directory is missing at login time, the system prints a message such as “no home” and puts the user in /. On Linux, if /etc/login.defs DEFAULT_HOME to no, the login is not allowed to continue.

# Login shell

The shell is a normal command interpreter as the Bourne shell or the C (/bin/sh or /bin/c), but it can be any program. sh is the traditional default for UNIX, and bash (the GNU Bourne again) is the default for Linux and Solaris. AIX defaults to ksh, the Korn shell. tsch is an enhanced C shell with command editing. On Linux systems, sh and bash are just links to bash and tcsh, respectively.

Some systems permit users to change their shell with the chsh command, but with chfn, this command may not work if you are using LDAP or other directory service to manage login information. If you use the /etc/passwd file, a sysadmin can always change a user's shell by editing the file with vipw.

Linux supports the chsh command and limits changes to shells listed in the /etc/shells file. SUSE enforces the /etc/shells list, but Red Hat warns you if the selected shell is not on the list. If you add entries to the shells file, be sure to use absolute paths since chsh and other programs expect them.
