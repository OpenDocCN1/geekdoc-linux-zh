
## ps: monitor processes

Implementations of ps have become hopelessly complex over the last decade. Vendors have abandoned the attempt to define meaningful displays and make their ps-de-os completely configurable. With a little customization, almost any desired output can be produced. As a case in point, the ps used by Linux is a triaxial and hermaphroditic version that understands multiple option sets and uses an environment variable to tell it what universe it's living in.

Do not be alarmed by all this complexity; it's mainly for developers, not for system administrators. Although you use ps frequently, you only need to know a few specific commands.

On Linux and AIX, you can obtain a useful overview of all the processes running on the system with ps aux. The option a means to show all processes, x means to show even processes that don't have a control terminal, and u selects the "oriented" format. ### Table 5.4 Explanation of ps ax output

| Field | Contents |
| --- | --- |
| USER | Username of the process's owner |
| PID | Process ID |
| %CPU | Percentage of the CPU this process is using |

| TTY | Control terminal ID |

| COMMAND | Command name and arguments* |

* a. Programs can modify this info, so it's not necessarily an accurate representation of actual command line.

l selects the "long" output format. ps lax is also slightly faster than ps ax because it doesn't have to translate every UID to a username—efficiency can be important if the system is already bogged down.

## 5.8 DYNAMIC MONITORING WITH TOP, PRSTAT AND TOP

Since commands like ps offer only a snapshot of your system, it is often difficult to grasp the big picture of what's really happening. top is a utility that runs on many systems and provides a regularly updated summary of active processes and their use. On AIX, an equivalent utility is tapas, and on Solaris the tool is prstat.

By default, the display updates every 10 seconds. The most CPU-consuming processes appear at the top. top accepts inputs from the keyboard and allows you to send signals and to renice processes, so you can observe how actions affect the overall condition of the machine.
