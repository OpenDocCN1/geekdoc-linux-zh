# Linux NAT and packet filtering

Linux traditionally implements only a limited form of Address Network Translation (NAT) that is more properly called Port Address Translation, or PAT. Instead of using a range of IP addresses as a true NAT implementation, PAT multiplex all connections onto a single address. The differences and details are of practical importance, though.

iptables implements not NAT but also packet filtering. In earlier versions of Linux this functionality was a bit of mess, but iptables makes a much cleaner separation between the NAT and filtering features.

Packet filtering features are covered in more detail in the Security chapter starting on page 932. If you use NAT to let local hosts access the Internet, you must use a full complement of firewall filters when running NAT. The fact that NAT “isn’t really routing” doesn’t make a Linux NAT more secure than a Linux router. For brevity, we describe only the actual NAT configuration here; however, this is a small part of a full configuration.

To make NAT work, you must enable IP forwarding in the kernel by setting the /proc/sys/net/ipv4/ip_forward kernel variable to 1. Additionally, you must insert the appropriate kernel modules:

```
ubuntu sudo /bin/modprobe ipt_nat
ubuntu sudo /bin/modprobe ip_conntrack
ubuntu sudo /bin/modprobe ip_conntrack_ftp
```

Many other connection-tracking modules exist; use the net/filter subdirectory underneath /lib/modules for a more complete list and enable the ones you need.

```
sudo iptables -t nat -A POSTROUTING -o eth1 -j SNAT --to63.173.189.1
```
