It is never wise to allow root to log in via sudo. Superuser access should be
achieved through the use of sudo. To encourage this behavior, you use the option

```
PermitRootLogin no
```

The first time you connect to a new system through SSH, you are prompted to
accept the server's public key (which is usually generated as part of the
server's installation of OpenSSH, or soon thereafter). A truly paranoid user might
ually verify it, but most of us blindly accept the key, which is then stored in
t ~/.ssh/known_hosts file for future use. SSH won't mention the server's key
 unless it changes. Users' rubber-tapping the keys of
systems leaves you vulnerable to a man-in-the-middle attack if the host key was
actually being presented by an attacker's system.

A DNS record known as SSHFP has been developed to address this vulnerability.
The premise is the server's key is stored as a DNS record. When a client connects
to an unknown system, SSH looks up the SSHFP record to verify the server's
key rather than asking the user to verify it.

The sshfp utility, available from xelerance/software/sshfp, generates SSHFP
DNS resource records either by scanning a remote server or by parsing previously
cously accepted key from the known_hosts file. (Of course, either choice assumes
the source of the key is known to be correct). Usage is simple: use the -s
flag to generate a key from a network scan, or use -k to change the known_hosts file
(the default). For example, the following command generates a BIND-compatible
SSHFP record for solaris.booklab.astrust.com.

```
solaris$ sshfp solaris.booklab.astrust.com
solaris.booklab.astrust.com IN SSHFP 1 1 94a2678ee713a3f6a78110fad9bd
saris.booklab.astrust.com IN SSHFP 2 1 7cf7d202e3d2f93a47125bcde0a6...
```

Add these records to the domain zone file (be careful of the names and the ORIGN), reload the domain, and use dig to verify the key:

```
solaris$ dig solaris.booklab.astrust.com IN SSHFP | grep SSHFP
;>>> 9.5.1-P2 << solaris.booklab.astrust.com IN SSHFP
; solaris.booklab.astrust.com IN SSHFP
solaris.booklab.astrust.com 38400 IN SSHFP 1 1 94a2678ee713a3f6a78110f...
solaris.booklab.astrust.com 38400 IN SSHFP 2 1 7cf7d202e3d2f93a47125bcde0a6
```
