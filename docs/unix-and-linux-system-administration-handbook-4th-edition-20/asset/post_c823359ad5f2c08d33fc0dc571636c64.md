
## Chapter 20 Electronic Mail

In order not to overwhelm a receiving host, especially after it has been down, Postfix uses a slow-algorithm to control how fast it tries to deliver email. Deferred messages are given a try-again time stamp that exponentially backs off so not to waste resources on undeliverable messages. A status cache of reach-ability avoids unnecessary delivery attempts.

## Sending mail

qmgr decides with the head of trivial-rewrite when a message should be sent. The routing decision made by trivial-rewrite can be overridden with lookup tables (transport_maps).

Delivery to remote hosts through the SMTP protocol is performed by the smtp program. Imtp delivers mail using LMTP; the Local Mail Transfer Protocol defined in RFC2033. LMTP is based on SMTP, but the protocol has been modified so that the mail server is not required to manage a mail queue. This mailer is particularly useful for delivering email to mailbox servers as the Cyrus IMAP suite.

local's job is to deliver email locally. It addresses the aliases table and instructions found in recipients' forward files. Messages are forwarded to another address, passed to an external program for, or stored in users' mail folders.

The virtual program delivers email to "virtual mailboxes"; that is, mailboxes that are not related to a Linux account but still represent valid email destinations. pipe implements delivery through external programs.

## Security

Postfix implements security at several levels. Most of the Postfix server programs can run in a chrooted environment. They are separate programs with no parent/child relationship. None of them are seuid. The mail drop group is writable by the postdrop group, to which the postdrop program is set.

Impressively, remotely exploitable vulnerabilities have yet been identified in any version of Postfix.

## Postfix commands and documentation

Several command-line utilities permit user interaction with the mail system:

- sendmail, mailq, newaliases – sendmail-compatible replacements
- postfix – starts and stops the mail system (must be run as root)
- postalias – builds, modifies, and queries alias tables
- postcat – prints the contents of queue files
- postconf – displays and edits the main configuration file, main.cf
- postfixmap – builds, modifies, or queries lookup tables
- supersuper – manages the mail queues

## Basic settings

The Postfix distribution includes a set of man pages that describe all the programs and their options. On-line documents at postfix.org explain how to configure and manage various aspects of Postfix. These documents are also included in the Postfix distribution in the README_FILES directory.

## Postfix configuration

The main.cf file is Postfix’s principal configuration file. The master.cf file configures server programs. It also defines various lookup tables that are referenced from main.cf and provide different types of service mappings.

The postconf(5) man page describes every parameter you can set in the main.cf file. There is also a postconf program, so if you just man postconf, you'll get the man page for instead of postconf(5). Use man -s 5 postconf to get the right version (man 5 postconf on HPX and AIX).

The Postfix configuration language looks like a series of sh commands and assignment statements. Variables can be referenced in the definition of other variables by prefixing them with a $. Variable definitions are stored just as they appear in the config file; they are not expanded until they are used, and substitutions occur at that time.

You can create new variables by assigning them values. Be careful to choose names that do not conflict with existing configuration variables.

All Postfix configuration files, including the lookup tables, consider lines with whitespace to continuation lines. This convention results in very readable configuration files, but you must start new lines in column one.

## What to put in main.cf

More than 500 parameters can be specified in the main.cf file. However, just a few of them need to be set at an average site. The author of Postfix strongly recommends that only parameters with nondefault values be included in your configuration. That if the default value of a parameter changes in the future, your configuration will automatically adopt the new value.

The sample main.cf file that comes with the distribution includes many commented-out example parameters, along with brief documentation. The original is best left alone as a reference. Start with an empty file for your configuration so that your settings are not lost in a sea of commands.

## Table 20.21 Information sources for Postfix lookup tables

| Type | Description |
|---|---|
| dbm/sdbm | Traditional dbm or group database |
| cidr | Network addresses in CIDR form |
| hash/btree | Berkeley DB hash or B-tree file (replaces dbm) |
| ldap | LDAP directory service |
| mysql | MySQL database |
| nis | NIS directory service |
| pcre | Perl-Compatible Regular Expressions |
| pgsql | PostgreSQL database |
| proxy | Access through proxymap, e.g., to escape a |
| regexp | POSIX regular expressions |
| static | Returns the value specified as path regardless of the key |
| unix | The /etc/passwd and /etc/group files; use NIS syntax* |

- a. unix:passwd.db is the passwd file, and unix:group is the group.

The alias_database specifies the table that is rebuilt by newializes and should correspond to the table that you specify in alias_maps. The reason for having two parameters is alias_maps might include non-DB sources such as mysql or nis that do not need to be rebuilt.
