## cancel: remove print jobs

cancel removes from the queue jobs that are queued or being printed. You can invoke cancel with either a job number (determined with lpstat) or a printer name. If you specify a printer, then the job being printed is canceled.

The cancel command is usually owned by the pseudo-user lp with group bin and mode 6775 so that anyone can cancel jobs that are obviously false. If someone who did not send a cancel it, mail is sent to the job's owner. If users abuse this privilege, set the mode of the command so that it does not run itself.

## 26.5 BSD AND AIX

We could have just called this "AIX printing" because AIX is the only one of our systems that still uses the BSD system. But we could call the system by its traditional name because you may encounter it on other systems.

The BSD printing system was designed for use with old-fashioned line printers, but good design let it scale to many more printers and printer languages. At one point, the BSD printer spooler, lpd, became so widely accepted that it found its way into the firmware of some printers.

## An overview of the BSD printing architecture

Access to printers is controlled by the lpd daemon. lpd accepts print jobs from users or other (remote) lpd, processes, and sends them to an actual printer. To complete these steps, lpr reads printer configuration from /etc/printcap, the system's printer information database.

Users invoke the lpr program to submit their print jobs to lpd. These two processes communicate through the UNIX domain /dev/printer.

To determine what printer to send a job to, lpr first looks at the command line. If you've supplied a -Pprinter argument, printer becomes the destination. Otherwise, lpr checks the environment to see if the PRINTER variable is defined, and if so, lpr uses the variable's value. If all else fails, lpr submits the job to the system-wide default printer, which is the printer "lp", or if there is no lp, to the printer described in the /etc/printcap file.
