
# Control flow

## Input and output

When you open a file for reading or writing, you define a "filehandle" to identify the channel. In the example below, INFILE is the filehandle for /etc/passwd and OUTFILE is the filehandle associated with /tmp/passwd. The loop condition is `<INFILE>`, which is similar to the `<>` we have seen before but specific to a particular filehandle. It reads lines from the filehandle INFILE until the end of file, at which time the loop ends. Each line is placed in the variable `$_`.

```perl
#!/usr/bin/perl

open(INFILE, "/etc/passwd") or die "Couldn't open /etc/passwd";
open(OUTFILE, "/tmp/passwd") or die "Couldn't open /tmp/passwd";

while (<INFILE>) {
    ($name, $pw, $uid, $gecos, $path, $sh) = split /:/;
    print OUTFILE "$uid\$name\n"
}
```

open returns a true value if the file is successfully opened, short-circuiting (rendering unnecessary) the evaluation of the die clauses. Perl's || (which Perl also has, but at lower precedence) is generally a better choice when you want to emphasize that everything on the left be fully evaluated before Perl turns to the consequences of failure.

Perl's syntax for specifying how you want to use each file (read? write?) mirrors that of the shell. You can also use "filenames" such as "/bin/df" to open pipes and to shell commands.

## Control flow

The example below is a Perl version of our earlier bash script that validates your command-line arguments. You might want to refer to the bash version on page 41 for comparison. Note that Perl construct has no then keyword or terminating word, just a block of statements enclosed in curly braces. You can also add a postfix if clause (or its negated version, unless) to an individual to make that statement's execution conditional.

```perl
#!/usr/bin/perl
sub show_usage {
    print "Usage: $0 source_dir dest_dir\n";
    exit scalar(@) ? 1 : 2;
}

if (@ARGV != 2) {
    ($source_dir, $dest_dir) = @ARGV;
    show_usage unless -d $source_dir;
    -d $dest_dir or show_usage "Invalid directory";
}
```

Here, the two lines that use Perl's -d operator to validate the directoryness of $source_dir and $dest_dir are equivalent. The second form (with -d at the start of the line) has the advantage of putting the assertion at the beginning of the line, where it's most noticeable. However, the use of or to mean "otherwise" is a bit tortured; some readers of the code may find it confusing.

Evaluating an array in scalar context (specified by the scalar operator in this example) returns the number of elements in the array; as always in Perl, there's more than one way to do it. Functions receive their arguments in the array named $@ It's common practice to access them with the shift operator, which removes the first element of the array and returns its value.

This version of show_usage accepts an error message to be printed. If you provide an error message, you can also provide a specific exit code. The ternary ? operator evaluates its first argument; if it is true, the result of the entire expression is the second argument; otherwise the third. As in bash, Perl has a dedicated "else if" condition, but its keyword is elsif rather than elif. For those who use both languages, these differences keep you mentally numb.

As in Table 2.5, Perl's comparison operators are the opposite of bash's; strings use textual operators, and numbers use algebraic notation. Compare with Table 2.2 on page 44.

Like bash, Perl has two types of loops. The common format iterates through an explicit list of arguments. For example, the code below iterates through a list of animals, printing one per line.

```perl
@animals = qw(lions tigers bears);
foreach $animal (@animals) {
    print "$animal\n";
}
```

## Accepting and validating input

The traditional C-style for loop is also available:

```perl
for ($counter=1; $counter <= 10; $counter++) {
    printf("$counter");
}
```

We've shown you the traditional for and foreach labels, but those are in fact keywords in Perl and you can use whichever form you prefer.

Versions of Perl 5.10 (2007) have no explicit case or switch statement, but there are several ways to accomplish the same thing. In addition to the obvious but clunky option of cascading if statements, another possibility is to use a for statement to set the value of $_ and provide a context from which last can escape:

```perl
for (@ARGV[]) {
    m/^webview/ && do print("Install for webserver\n"; last);
    m/tomcat/ && do print("Install for tomcat\n"; last);
    m/geronimo/ && do print("Install for geronimo\n"; last);

    print("Invalid option supplied\n"; 1);
}
```

The regular expressions are compared with the argument stored in $_. Successful matches short-circuit the && and fall through to the next test. Once a regex matches, the corresponding do block is executed. The last statements escape from the block immediately.

The script below combines many of the Perl constructs we reviewed over the last few pages, including a subroutine, postfix if statements, and a for loop. The program itself is merely a wrapper around the main function get_string, generic input validation routine. This routine prompts for a string, removes any trailing newline, and verifies that the string is not null. Null strings cause the prompt to be repeated up to three times, after the script gives up.

```perl
#!/usr/bin/perl

$maxatt = 3; # Maximum tries to supply valid input
```

```perl
sub get_string {
    my ($prompt, $response) = @_;
    # Try to read input up to $maxatt
    for ($maxatt = 0; $maxatt < 3; $maxatt++) {
        print("Please try again.\n" if $maxatt > 0);
        print($prompt: ");
        $response = <STDIN>;
        chomp($response);
        return $response if $response ne "";
    }
    die("Too many failed attempts\n");
}
```

# Perl as a filter

You can use Perl without putting isolated expressions on the command line. This is a great way to do quick transformations and one that largely others filter programs like sed, awk, and tr.

Use the -pe command-line option to loop through STDIN, run a simple expression on each line, and print the result. The example is:

```bash
ubuntu perl -pe '#/bin/bash$/bin/bash' /etc/passwd
root:x:0:root:/root/bash
daemon:x:1:daemon:/usr/bin/bash
```
