# Chapter 17 DNS: The Domain Name System

We have omitted samples of dig drill output, since we have used them throughout this chapter to illustrate various DNS issues.

dig and drill include the notation aa in the output flags if an answer is authoritative (i.e., it comes directly from a master or slave server of that zone). The code indicates that an answer is 'authentic' in DNSSEC sense. When testing a new configuration, be sure that you look up data for both local and remote hosts. If you can access a host by IP address but not by name, DNS is probably culprit.

# Lame delegations

The effects of a lame delegation can be very bad. If one of your servers is lame, your DNS system is less efficient. If all the name servers for a domain are lame, no one can reach you. All queries start at the root unless cached, so lame servers and software that do not have negative caching of SERVFAIL errors increase the load of everyone on the path from the root to the lame domain.

There are two ways to find lame delegations: by reviewing the log files and by using a tool doc, short for 'domain occupancy control'. We look at doc examples in the next section, let's first review some log entries.

Many sites point the lame-servers logging channel to /dev/null and don't fretting about other people's lame delegations. That's fine as long as your own domain is sneaky and it is not a source or victim of lame delegations. The lame server serves DNS down; if all servers are lame, your domain is essentially off the air.

Here is a logging example. We have truncated the output to tame dig's verbosity; the +short flag dig limits the output even more.

```
Jul 19 14:37:50 nubark named[757]: lame server resolving 'w33.com' (in
w33.com?): 216.171.131.583
```

Digging for name servers for w33.com at one of the _gTLD servers yields

```
$ dig @egtld-servers.net w33.com ns
;; ANSWER SECTION:
w33.com.      14400 IN ns ns0.nameserver.net.
w33.com.      14400 IN ns ns1.nameserver.net.
```

But if we ask each of these servers in turn that same question, will we get an answer from ns0 and no answer from ns1:

```
$ dig @ns0.nameserver.net w33.com ns
;; ANSWER SECTION:
w33.com.      14400 IN ns ns0.nameserver.net.
w33.com.      14400 IN ns ns1.nameserver.net.
```
