# Table 22.1 PAM control flags

| Flag | Stop on failure? | Stop on success? | Comments |
| --- | --- | --- | --- |
| binding | No | Yes | Like sufficient, but can't fail without failing the stack |
| include | | No | Includes another config file at this point in the stack |
| optional | No | No | Significant only if this is the lone module |
| required | No | No | Failure eventually causes the stack to fail |
| requisite | Yes | No | Same as required, but fails the stack immediately |
| sufficient | No | Yes | The name is kind of lie; see comments below |

a. Linux and Solaris only for include, Solaris only for binding

required modules are required to succeed; a failure of any one them guarantees that the stack as a whole will eventually fail. The failure of a module that is marked required does not immediately stop execution of the stack. If you want that behavior, you need to use the requisite control flag instead of required.

The success of a sufficient module aborts the stack. However, the ultimate result of the stack isn't guaranteed to be success because sufficient modules cannot override the failure of earlier required modules. If an earlier module has already failed, a successful sufficient module aborts the stack and failure of the binding module ensures eventual failure of the stack. By contrast, failure of a sufficient module is treated like the failure of an optional module: it makes no difference to the final result it is the only module in the stack.

Clear as mud? To make things even more complicated, Linux has a parallel system of alternative control flags that you could theoretically use instead of these cross-system standards. Overall, the control-flag system could take another path or two to really explain in detail. We don't find that, however, because PAM configurations are relatively stereotypical; you're unlikely to be writing your from scratch. We mention some of the details only to impress upon you that the control flags don't have the straightforward meanings they might suggest. If you're going to modify your systems' security settings, make sure that you understand the system thoroughly and that you double-check the particulars. (You won't configure PAM every day. How long will you remember which version is requisite and which is required?)

For example, here's another copy of that same Solaris pam.conf example:

```
# login service

login auth requisite pam_authtok_get.so.1
login auth required pam_dhkeys.so.1
login auth required pam_unix_cred.so.1
login auth required pam_unix_auth.so.1
login auth required pam_dial_auth.so.1
```
