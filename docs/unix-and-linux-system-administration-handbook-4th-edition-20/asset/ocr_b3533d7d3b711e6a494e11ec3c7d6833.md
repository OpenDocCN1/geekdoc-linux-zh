# Using mail servers

There are two basic types of mail server: Internet-facing servers, to handle incom- and outgoing mail; and internal servers, to interface with users. Here, we outline- a mail system design that is secure, seems to scale well, and is relatively easy to manage. It centralizes the handling of incoming and outgoing mail on servers dedicated to those purposes. Exhibit B illustrates one form of this system.

# Exhibit B Mail system architecture

![](bbox=[0.26, 0.323, 0.873, 0.584])

The mail system depicted shows two regions of your site: a DMZ (demilitar-ized zone) which machines connect directly to the Internet, and an internal zone that is separated from the DMZ and the Internet by a firewall. In the DMZ are several servers:

+   * An MTA listening on port 25 and incoming mail to filters
* Virus and spam filters that reject or quarantine dangerous messages
* An LDAP (Lightweight Directory Access Protocol) database replica that contains mail routing information
* An outgoing MTA that tries to deliver mail submitted by the MSA
* A fallback MTA, for messages that fail on the first delivery attempt
* A caching DNS server: used by the outgoing MTA for MX lookups, by the incoming MTA for blacklist lookups (senders’ domains) and cryptographic lookups for signed messages
