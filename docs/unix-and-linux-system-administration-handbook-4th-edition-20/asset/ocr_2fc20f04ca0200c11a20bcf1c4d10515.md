# 25.4 X SERVER TROUBLESHOOTING AND DEBUGGING

Server configuration has come a long way over the last decade, but it can still be difficult to get things working the way you would like. You may need to experiment with monitor frequencies, driver options, proprietary drivers, and extensions for 3D rendering. Ironically, it is the times the display is not working correctly that you are most interested in seeing the debugging output on your screen. Fortunately, the X.Org server gives you all the information you need (and a lot that you don't) to track down the problem.

# Special keyboard combinations for X

Because the X server takes over your keyboard, display, mouse, and social life, you can imagine that it leaves you with little recourse to power the system if things are not working. However, there are a few things to try before it comes to that.

If you hold down the Control and Alt keys and press a function (F1–F6), the X server takes you to one of the text-based virtual terminals. From there you can log in and debug. To get back to the X server running on, virtual terminal 7, press <Alt-F7>. If you are on a network, you can also try logging from another computer to kill the X server before resorting to the reset button.

For virtual console support on Solaris, use the svc/system/vtdaemon:default solaris SM service and the console-login:vt[2-6] sequences.

If the monitor is not in sync with the card's video signal, try changing the screen resolution. The available resolutions are on Modes line from the Screen section of the configuration file. The exact Modes See sections on page 102 for details. The X server defaults to the first resolution shown on the active Modes line, but you can cycle through the different resolutions by holding down Control and Alt and pressing the plus (+) or minus (-) over the numeric keypad.

Pressing<Control Alt-Backspace> kills the X server immediately. If you run the server from a console, you will find yourself back where when the server exits. If a display manager started the server, it usually spawns a new server and prompts again for a login and password. You have to kill the display manager (xdm, gdm, etc.) from a console to stop it from respawning new servers.

+   8. The X server requires the <Control> key to be held down along with the <Alt-Fn> key combination to switch virtual terminals, but the text console does not.
