The command above creates a 25GB logical volume named web1. Once you've created your logical volumes, you can verify them by running vgdplay -v /dev/vgname to double-check their sizes and make sure they were set up.

In most scenarios, you would then go to create a filesystem on /dev/vg01/web1 and arrange for it to be mounted at boot time. See page 258 for details.

Another way to create a logical volume is to use lvcreate to create a zero-length volume and use lxtend to add storage to that. You can specify exactly which physical volumes in the volume group should the logical volume use. If you allocate space with lvcreate (as we did above), it simply uses extents from any available physical volumes in the volume group—for most situations.

As in Linux, striping (which HP-UX's LV refers to as "distributed allocation") and mirroring are features at the logical volume level. You can request them at the time the logical volume is created with lvcreate, or later with lvchange. In contrast to Linux, the logical volume manager does not allow snapshots. However, temporary snapshots are available as a feature of HP's VxFS filesystem.

If you plan to use a logical volume as a boot or swap device to store core dumps, you must specify contiguous allocation and turn off back remapping with the -C -r flags to lvcreate, as shown below.

```
# lvcreate -C -y -n root -l 1500 -n root vg01
Logical volume /dev/vg01/root has been successfully created with character device "/dev/vg01/root"
Logical volume /dev/vg01/root has been successfully extended.
Volume Group configuration for /dev/vg01 has been saved in /etc/lvmconf/vg0conf
# lvcreate -C -y -n swap -L 500 -n swap vg01
Logical volume /dev/vg01/swap has been successfully created with character device "/dev/vg01/rswap"
```

You must then run the lvboot command to notify the system of the new root and swap volumes. See the page for lvboot for more information about the special procedures for creating boot, swap, and dump volumes.

# AIX logical volume management

AIX's logical manager uses a different command set from the volume managers of Linux and HP-UX, but its underlying architecture and approach are similar. One potentially confusing fact is AIX calls the objects more known as groups (that is, the units of space allocation within a volume group) "partitions." Because the entities normally require swap space to exist in AIX, there is no ambiguity within the AIX phrase itself. However, tourists visiting from other systems may wish to bring along an AIX phrase (Note: "phrase" is likely an OCR error for "term" based on context).

- HP-UX limits require swap space to be in the first 2GB of the physical disk and the boot volume to be the first logical volume. The 1.5GB root and 500MB swap were shown here to work around these constraints. You can have a root partition that is larger than these, but you must have separate boot and root volumes. See the page for lvboot for details.

# Chapter 8 Storage

In other respects—physical volume, volume group, logical volume—AIX terminology is standard. The SMIT interface for logical volume management is pretty complete, but you can also use the commands listed in Table 8.4.

The following four commands create a volume group webg, a logical volume called web1 within it, and a JFS2 filesystem inside web1. The filesystem is mounted in /mnt/web1.

```
$ sudo mkvg -v webg hdisk1
webg
$ sudo crfs -v jfs2 -g webg -m /mnt/web1 -a size=25G
File system created successfully.
26213396 kilobytes total disk space.
New File System is 52428800
$ sudo mkdir /mnt/web1
$ sudo mount /mnt/web1
```

AIX does not require you to label disks into physical volumes. **mkvg** and **extendv** automatically label disks as part of the induction process. Note that **mkvg** takes a device name and not a path to device.

You can create the logical volume and the filesystem in separate steps (with **mkvl** and **mkfs**, respectively), but **crfs** performs both tasks for you and updates /etc/filesystems well. The exact name of the logical volume that holds the filesystem is mounted for you in the AIX scenario, you can determine it by inspecting /etc/filesystems or running **mount**. (On the other hand, it can be hard to unscramble filesystems in the event of problems if you have generic names.)

If you run **mkvg** directly, you can specify only a device name of yours but also various options to the volume manager as striping and mirroring configurations. Snapshots are implemented through the JFS2 filesystem and not through the volume manager.

# 8.9 FILESYSTEMS

Even after a hard disk has been conceptually divided into partitions or logical volumes, it is still not ready to hold files. All the abstractions and goodies described in Chapter 6, *The Filesystem*, must be implemented in terms of raw disk blocks. The filesystem is the code that implements these, and it needs to add a bit of its own overhead and data.

The Berkeley Fast File System implemented by McKusick et al. in the 1980s was an early standard that spread to many UNIX systems. With some small adjustments, it eventually became known as the UNIX File System (UFS) and formed the basis of several other filesystem implementations, including Linux's ext series, Solaris's UFS, and IBM's JFS.

Early systems bundled the filesystem implementation into the kernel, but it soon became apparent that support for multiple filesystem types was an important goal. UNIX systems developed a well-defined kernel interface that allowed multiple types of filesystems to be active at once. The filesystem interface also abstracted the underlying hardware, so filesystems use approximately the same interface to storage devices as do other UNIX programs that access the disks through device files in /dev.

Support for multiple filesystem types was initially motivated by the need to port NTFS and filesystems for removable media. But once the floodgates opened, the "what if era" began; many different groups started to work on improved filesystems. Some were system specific, and others (such as ReiserFS) not tied to any particular.

Given that you may have a choice of filesystems, you should investigate the alternatives and choose the "best" one. Unless you're set up a data disk for a very specific application, no. In nearly all situations, it's better to stick with the system's defaults. That's what the system's documentation and administrative tools probably assume.

Only a few features are truly non-negotiable:

- Good performance
- Tolerance for crashes and power outages without filesystem corruption
- The ability to handle disks and filesystems large enough for your needs

Fortunately, modern systems' default filesystems already cover these bases. Any improvement that you might see from changing filesystems will be marginal and context-dependent at best.

The next sections discuss the filesystems on Linux, HP-UX, and AIX. The ZFS filesystem used by Solaris is administered differently and merits an entire section of its own; that section starts page 264.

# Linux filesystems: the ext family

"second extended filesystem", ext2, was for a long time the Linux standard. It was designed and implemented primarily by Rémy Card, Theodore T. Wolff, and Stephen Krabbe. Ext3 adds journaling capability to the ext2, making it functionally similar to ext2. However, you can still mount ext3 as ext2 provided that the extent system has not been used.

Ext4 is a comparatively incremental update that raises a few size limits, increases the performance of certain operations, and allows the use of "extents" (disk block ranges) rather than individual disks. The on-disk format is compatible with ext2 and ext3 filesystems and can be mounted as ext4 filesystems.

Use of ext4 over the previous versions is recommended as of Linux kernel 2.6.28. It is the default on Ubuntu and SUSE; Red Hat remains on ext3.

It's easy to add a journal to an existing ext2 filesystem, promoting it to ext3 or ext4 (the distinction is vague because of backward compatibility). To do this, you just run tune2fs with the -j option. For example:

```
# tune2fs -j /dev/hda4
```

You would need to modify the corresponding entry in /etc/fstab to read ext4 rather than ext2 (see page 260 for more information on the fstab file).

# HP-UX filesystems: VxFS and HFS

VxFS is the mainframe HP-UX filesystem. It's based on a filesystem originally developed by Veritas Software, now of Symantec. Since it includes a journal, HP sometimes refers to it as JFS, the Journaled File System. Do not confuse this JFS with AIX's JFS2; though, they are different filesystems.

VxFS is nearly unique among mainstream filesystems in that it supports clustering; is, simultaneous modification by multiple, independent computers. This mode of operation involves some performance costs because the filesystem must coordinate across the nodes.
