Some sites set the TTL on the records for Internet-facing servers to a low value so if a server experiences problems (network failure, hardware failure, denial of service attack), the administrators can respond by changing the server-to-IP addressing mapping. Because the original TTLs were low, the new values will propagate quickly. For example, the name google.com has a five-minute TTL, but Google's servers have a TTL of four days (345,600 seconds):

| google.com | 300 | IN | A | 209.85.171.100 |
| google.com | 345600 | IN | NS | ns1.google.com |
| ns1.google.com | 345600 | IN | A | 216.239.32.10 |

The class specifies the network type. Three values are recognized:

+   - IN for the Internet, which is the default
- HS for Hesiod, a directory service used locally by some sites
- CH, used internally by name servers to identify themselves

The default value for the class is IN. It is often specified explicitly in zone files even though the default, it can be omitted. Hesiod, developed at MIT, is a data-base service built on BIND.

CH originally stood for ChaosNet, a now-obsolete protocol formerly used by Symols Lip machines. Today, only two pieces of identity data are normally tucked away in the CH class: the version number of the server software and the name of the host on which the server is running. These nuggets can be extracted with dig or drill as shown on page 598.

Many types of DNS records are defined, but fewer than 10 are in use; IPv6 adds a few more. We divide the resource records into four groups:

+   - Zone infrastructure records identify domains and their name servers:
- Basic records map between names and addresses and route mail.^{10}
- Security records add authentication and signatures to zone files.
- Optional records provide extra information about hosts or domains.

MX mail routing records fit in the zone infrastructure pile and the basic records pile because they can refer to entire zones as individual hosts.
