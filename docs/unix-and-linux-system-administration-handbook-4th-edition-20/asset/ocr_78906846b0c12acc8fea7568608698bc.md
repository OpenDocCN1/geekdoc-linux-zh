# Chapter 17 DNS: The Domain Name System

Early versions of BIND synchronized zone files between master and slave servers only when the refresh timeout in the zone's SOA record had expired. These days the master named automatically notifies its peers whenever the corresponding zone database has been reloaded, as long as notify is set to yes. The slave servers can rendezvous with the master to see if the file has changed, and if so, to update their copies of the zone data.

You can use notify as a global option and as a zone-specific option. By default, every authoritative server sends updates to every other authoritative server (a system termed "splattercast" by Paul Vivek). If notify is set to master-only, this talkativeness is and notifications are sent only to slave servers of zone for which this is the master. If the notify option is set to explicit, then named only notifies the servers in the also-notify clause.

named normally figures out which machines are slave servers of a zone looking at the NS records. If also-notify is specified, a set of additional servers that are not advertised with NS records can be notified. This tweak is necessary when your site has internal servers. Don't also-notify servers; they are only interested in the zone's NS records and can wait for the update cycle.

The target of an also-notify is a list of IP addresses and, optionally, for servers with multiple network interfaces, additional options specify the IP address and port to use for outgoing notifications. Localhosts are a good place to turn off notification, since they never change. You must use the allow-notify clause if you name a master server other than the master to notify secondaries.

Query recursion

```
recursion yes | no;
-recursion { address_match_list };
all hosts
```

The recursion option specifies whether named should process recursively on behalf of your users. You can enable this option on an authoritative server of your zones' data, that's frowned upon. The best-practice recommendation is to keep authoritative servers and caching servers separate.

If this name server should recursive for your clients, set recursion to yes and include an allow-recursion clause so that named can distinguish queries that originate at your site from remote queries. named will act recursively for the immer and nonrecursively for the latter. If your name server answers queries for everything, it is an open resolver and can become a reflector for certain kinds of attacks; see RFC5358.
