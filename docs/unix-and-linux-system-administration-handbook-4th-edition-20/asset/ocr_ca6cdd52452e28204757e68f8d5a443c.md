Security is a common problem area. Tightening security typically means inconvenencing users, and the users often outweigh you in both number and whining ability. Increased security may reduce users' productivity; before implementing a proposed security change, a risk analysis to be sure both management and users understand why it is a good idea.

Make sure that any security change impacts users (e.g., converting passwords to RSA/DSA keys for remote logins) is announced in advance, is well documented, and is supported at changeover. You might even hold workshops at which users can learn about the change and may even bring in a laptop so that the first time they use the new system there is someone to help them. Documentation should be easy to understand and should provide cookbook-type recipes for dealing with the new system. Allow for extra staff hours when first cut over to the new system you can deal with frustrated, panicked users.

# Purchasing

In many organizations, the group of people that make purchasing decisions does not include system administrators. This is, of course, for many decisions, when the purchasing team is acquiring IT-related items, system administrators should have an opportunity to express their opinions and possibly make a case for why one system should be chosen over another.

Sysadmins can provide good information about compatibility with the local environment, the competence of vendors (especially third-party resellers), and the reliability of certain types of equipment. Reliability information is particularly important when ordering systems that affect the organization's overall ability to function.

Another important piece of information that sysadmins contribute is the impact on the organization's IT security and regulatory compliance. A good example might be a hospital in a clinical department orders new systems without consulting the system administration group. Unfortunately, when the hardware arrives and the sysadmins are called in to figure out, they realize that it does not interact with the hospital's authentication system. In fact, it does not require user login at all! Now the hospital has thousands of dollars on a system that is not HIPAA-compliant, and they will need to purchase a new system or work with the vendor to get individual authentication capabilities incorporated. Neither of these is good option, and the hospital would have been better off if the system administrators had called in to foresee these problems and recommend a different vendor.
