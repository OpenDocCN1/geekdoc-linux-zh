# Optimizing for high-performance hosting of static content

The hosting community has learned over the last few years that one of the easiest
ways to create a high-performance hosting platform is to optimize some servers
for static content.

One way to address this need is through the use of an in-kernel web server or-
kernel page cache. Because these systems do not copy data to or from user
space before returning to it a requester, they achieve some incremental perform-
gains. However, because the solutions operate in kernel space, they entail
sadditional security risk. We recommend using them with extreme caution.

A kernel-based web server TUX runs in conjunction with a traditional
web server as Apache is available for some Linux distributions. When possi-
ble, TUX serves static pages without leaving kernel space, such as rpc.nsfd
serv files. Although TUX was developed by Red Hat (Red Hat now calls it the
Red Content Accelerator), it is released under the GPL and can be used
with other Linux distributions. Unfortunately, configuring TUX can be some-
th of a challenge. The system was popular in the early 2000s, but its popularity
has dwindled. For details, see redhat.com/docs/manual/tool.

On the Solaris platform, Sun has released the Solaris Network Cache and Acceler-
ator (NCA) to provide in-kernel content caching. NCA intercepts the traffic going
to http and caches static pages. When subsequent requests arrive for
t same content, they're served from cache without http.
