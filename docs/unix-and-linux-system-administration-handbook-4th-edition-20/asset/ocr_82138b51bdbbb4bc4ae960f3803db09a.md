# Chapter 22 Security

with any other firewall, the most secure strategy is to drop any packets you have not explicitly allowed.

```
iptables -F
iptables -P INPUT DROP
iptables -P FORWARD DROP
```

Since rules are evaluated in order, we put our busiest rules at the front.¹¹} The first rule allows all connections through the firewall that originates from the trusted net. The next three rules in the FORWARD chain allow connections through the firewall to network services on 10.1.1.2. We allow SSH (port 22), HTTP (port 80), and HTTPS (port 443) to out to our server.

```
iptables - FORWARD -d eth0 -p ANY -j ACCEPT
iptables - FORWARD -d 10.1.1.2 -p tcp --dport 22 -j ACCEPT
iptables - FORWARD -d 10.1.1.2 -p tcp --dport 80 -j ACCEPT
iptables - FORWARD -d 10.1.1.2 -p tcp --dport 443 -j ACCEPT
```

The only TCP traffic allowed to our firewall host (10.1.1.1) is SSH, which is useful for managing the firewall itself. The second rule allows loopback traffic, which stays local to the host. Administrators get nervous when they can't ping their default route, so the third rule allows ICMP ECHO_REQUEST from internal IP addresses.

```
iptables - INPUT -i eth0 -d 10.1.1.1 -p tcp --dport 22 -j ACCEPT
iptables - INPUT -i lo -d 127.0.0.1 -p ANY -j ACCEPT
iptables - INPUT -i eth0 -d 10.1.1.1 -p icmp --icmp-type 8 -j ACCEPT
```

For any host to work properly on the Internet, certain types of ICMP packets must be allowed through the firewall. These eight rules allow minimal set of ICMP packets to the firewall host, as well as the network behind it.

```
iptables - INPUT -p icmp --icmp-type 8 -j ACCEPT
iptables - INPUT -p icmp --icmp-type 3 -j ACCEPT
iptables - INPUT -p icmp --icmp-type 5 -j ACCEPT
iptables - INPUT -p icmp --icmp-type 6 -j ACCEPT
iptables - FORWARD -d 10.1.1.2 -p icmp --icmp-type 0 -j ACCEPT
iptables - FORWARD -d 10.1.1.2 -p icmp --icmp-type 3 -j ACCEPT
iptables - FORWARD -d 10.1.1.2 -p icmp --icmp-type 5 -j ACCEPT
iptables - FORWARD -d 10.1.1.2 -p icmp --icmp-type 11 -j ACCEPT
```

We add rules to the PREROUTING chain in the nat table. Although the nat table is not intended for packet filtering, PREROUTING is particularly useful for anti-spoofing filtering. If we drop entries in the PREROUTING chain, they need not be present in the INPUT and FORWARD chains, since the PREROUTING chain is applied to all packets that enter the firewall host. It's cleaner to put the entries in a single place rather to duplicate them.

See page 473 for more information about IP spoofing.

However, you must be careful that reordering the rules for performance doesn't modify functionality.
