
## no: manage AIX network tuning parameters

To be fair, mktcpip does more than just device parameters—it also runs the rc.tcpip script to start relevant network daemons.

SMIT's network configuration facilities are relatively complete, so you can, and should, rely on SMIT for most basic configuration. Look under the "Communications Applications and Services" topic for TCP/IP configuration options.

Most sysadmins will never need to operate below the level of chdev/lsattr at a list of configuration options for a device. For example, the following query shows the configurable parameters for the network interface en3:

| aix lsattr -H -E -1 en3 | description | settable |
| :--- | :--- | :--- |
| alias4 | IPv4 Including Subset Mask | True |
| alias6 | IPv6 Alias Prefix Length | True |
| arp | on Address Resolution Protocol (ARP) | True |
| authority | Authorized Users | True |
| broadcast | 192.168.10.255 | True |
| mtu | 1500 Maximum Packet Size | True |
| netaddr | Internet | True |
| netaddr6 | IPv6 Address | True |
| netmask | 255.255.255.0 Sub Mask | True |
| prefixlen | Prefix Length for IPv6 Address | True |
| remmtu | 576 Max. Packet Size for REMOTE Nodes | True |
| security | Security Level | True |
| up | Current Interface Status | True |
| tcp_mss | Set TCP Segment Size | True |
| tcp_nodelay | Enable/Disable TCP_NODELAY Option Set Buffer Space for Receiving | True |
| tcp_recvpace | Set Buffer Space for Sending | True |

The -H option asks for the output columns to be labeled, the -E option requests current "effective" (as opposed to default) values, and the -i option identifies the device to probe entries in /dev. You can run lsdev -C to see a complete list of available devices.

To set a value, use chdev. For example, to set the MTU for en3 above 1450, you could use the command

```bash
aix sudo chdev -en3 -mtu=1450
```

## no: manage AIX network tuning parameters

AIX breaks out its system-wide TCP/IP options into a separate, parallel world of persistent attribute/value pairs that are accessed through the no command rather than through chdev. The difference is that no is for system-wide configuration, whereas chdev configures instances of specific devices.

You can run **no -a** to see a list of all the available variables—there are currently more than 125. Table 14.14 lists some of the ones with security implications.

### ### Table 14.14 Security-related TCP/IP tuning variables for AIX

| Variable | Meaning | Default |
| :--- | :--- | :--- |
| bcastping | Respond to broadcast pings | 0 |
| directed_broadcast | Allow forwarding of broadcast packets | 0 |
| ipforwarding | Allow IP forwarding | 0 |
| ignoreridirects | Ignore ICMP redirects | 0* |
| ipscrouteforward | Forward source-routed IP packets | 1* |
| ipscroutecevr | Accept source-routed IP packets | 0 |
| ipscroutesend | Block sending of source-routed packets | 1 |

* a. Probably advisable to change

To set a variable, use
**no -p -o variable=value**
For example, to prevent the TCP/IP stack from forwarding source-routed packets, you would use the command
`aix$ sudo -p -o ipscrouteforward=0`
The **-p** option makes the change effective both immediately and after a reboot.

WRIGHT, GARY R., AND W. RICHARD STEVENS. TCP/IP Illustrated, Volume Two: The Implementation. Reading, MA: Addison-Wesley, 1995.

These two books are an excellent and thorough guide to the TCP/IP protocol stack. A bit dated, but still solid.

STEVENS, W. RICHARD. UNIX Network Programming. Upper Saddle River, NJ: Prentice Hall, 1990.

STEVENS, W. RICHARD, BILL FENNER, AND ANDREW M. RUDOFF. UNIX Programming, Volume 1, The Sockets Networking API (3rd Edition). Upper Saddle River, NJ: Addison-Wesley, 2003.

STEVENS, W. RICHARD, UNIX Network Programming, Volume 2: Interprocess Communications (2nd Edition). Upper Saddle River, NJ: Addison-Wesley, 1999.

These books are the students' bibles in networking classes that involve programming. If you need only the Berkeley sockets interface, the original edition is still a fine reference. If you need the STREAMS interface, then the third edition, which includes IPv6, is a good bet. All three are clearly written in typical Richard Stevens.

TANENBAUM, ANDREW. Computer Networks (4th Edition). Upper Saddle River, NJ: Prentice Hall PTR, 2003.

This was the first networking text, and it is still a classic. It contains a thorough description of all the nitty-gritty details going on the physical and link layers of the protocol stack. The latest edition includes coverage over wireless networks, Gigabit, peer-to-peer networks, voice over IP, and more.
