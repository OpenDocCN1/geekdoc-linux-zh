For example, here’s a simple startup script that can start, stop, or restart sshd:

```
#!/bin/sh
test -f /usr/bin/sshd || exit 0
case "$1" in
  echo -n "Starting sshd: sshd"
  /usr/sbin/sshd
  echo ""
  ;
  stop)
  echo -n "Stopping sshd: sshd"
  kill `cat /var/run/sshd.pid`
  echo ""
  ;
  restart)
  echo -n "Stopping sshd: sshd"
  kill `cat /var/run/sshd.pid`
  echo ""
  echo -n "Starting sshd: sshd"
  /usr/sbin/sshd
  echo ""
  ;
  )
  echo "Usage: /etc/init.d/sshd start|stop|restart"
  exit 1
  ;
nesac
```

Although the scripts in /etc/init.d can start and stop individual services, the mas-
ter control script by init needs additional information about which scripts
run (and with what arguments) to enter any given level. Instead of looking
directly at the init.d directory when it takes the system to a new level, the
master script looks at a directory rlevel.d, where level is the level to be\entered (e.g., rc0.d, rc1.d, ...).

The rlevel.d directories contain symbolic links which point back to the scripts in
t init.d directory. The names of the links start with S or K by a se-
quence number and the name of the service controls (e.g., S3named).

When init transitions from a lower run level to a higher one, it runs all the scripts
start with S in ascending numerical order with the argument start. When init
transitions from a higher run level to a lower one, it runs all the scripts that start\with K (for "kill") in descending numerical order with the argument stop.
