```
myslist: include:/etc/mail/include/myslist
owner-myslist: mylist-request
myslist-request: evi
owner-owner: postmaster
```

In this example, mylist is the name of the list listed. The members are read from the file /etc/mail/include/myslist. Bounces generated by mailing to the list are sent to the list's owner, evi, as are requests to join the list. The indirection from owner-myslist to mylist-request to evi is useful because the owner's address (in this case, mylist-request) becomes the Return-Path address on each message sent to the list. The mylist-request alias is bit more appropriate for this field than the address of the actual maintainer. Errors in messages to the owner-mylist alias (evi, really) would be sent to owner-owner.

If you use site-wide files, you need to add an extra level of indirection pointing to mymylist@master so that the data file containing the list of members only needs to exist in one place.

# Software packages for maintaining mailing lists

Two packages, Mailman and Sympa, that automate the maintenance of mailing lists have claimed their way to “best of breed” status as part of about ten contenders. These packages let users obtain information about the list and give users an easy way to subscribe and unsubscribe. They facilitate moderation of the list and filter it for spam and viruses. Each package is available in several (often, not programming) languages.

Both Mailman (gnu/software/mailman), written in Python, and Sympa (sympa.org), written in Perl, have web interfaces that let users subscribe and unsubscribe involving the list manager.
