This routine illustrates the common "log level" paradigm by many administrative applications. The code of the script generates messages at many different levels of detail, but only the ones that pass a globally set, $LOG_LEVEL, are actually logged or acted upon. To clarify the importance of each message, the message text is preceded by a label that denotes its associated log.

# Loops

bash for... construct makes it easy to take some action for a group of values or files, especially when combined with filename globbing (the expansion of pattern-matching characters such as * and to form filenames or lists of filenames). The .sh pattern in the for loop returns a list of matching filenames in the current directory. The for statement iterates through that list, assigning each filename in the variable to $file.

```
#!/bin/bash
suffix=BACKUP--date +%Y%m%d-%H%M
for script in *.sh; do
newname=$script.$suffix
echo "Copying script to $newname..."
cp $script $newname
d
```

The output looks like:

```
$ sh rhel.sh.BACKUP--20091210-1708...
Copying rhel.sh to sles.sh.BACKUP--20091210-1708...
```

The filename expansion is not magic in this context; it works exactly as it does on happens first and the line is then processed by the interpreter in its expanded form. You could just as well have entered the filenames statically, as in the line

```
for script in rhel.sh sles.sh; do
```

+   7. More accurately, the filename expansion is just a little bit magic that it does maintain a notion of the atomicity of each filename. Filenames that contain spaces will go through the for loop in a single pass.
