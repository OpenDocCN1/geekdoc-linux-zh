# Analyzing CPU usage

You can use **isattr** to extract a description of each processor:

```
aix5$ isattr -E -1 proc0
frequency      1898100000 Processor Speed False
smt_enabled    true Processor SMT enabled False
smt_threads    2 in Processor SMT threads False
state          enable Processor state False
type           PowerPC_POWER5 Processor type False
```

**isattr** can also tell you the amount of physical memory in the system:

```
aix5$ isattr -E -1 sys0 -a realm
realmem       4014080 Amount of usable physical memory in Kbytes
```

# Gathering performance data

Most performance tools tell you what's going on at a particular point in time. However, the number and character of loads probably changes throughout the day. Be sure to gather a cross-section of data before taking action. The information on system performance becomes clear only after a long period (a month or more) of data collection. It is particularly important to collect data during periods of peak use. Resource limits and system misconfigurations are often only visible when the machine is under heavy load.

# Analyzing CPU usage

You probably want to gather three kinds of CPU data: overall utilization, load averages, and per-process CPU consumption. Overall utilization can help identify systems on which the CPU's speed is itself the bottleneck. Load averages give you an impression of overall system performance. Per-process CPU data can identify specific processes that are hogging resources.

You can obtain summary information with the **vmstat** command. **vmstat** takes two arguments: the number of seconds to monitor the system for each line and the number of reports to provide. If you don't specify the number of reports, **vmstat** runs until you press <Control-C>.

The first line of data returned by **vmstat** reports averages since the system was booted. The subsequent lines are averages within the previous period, which defaults to five. For example:

```
$vmstat 5 0
```
