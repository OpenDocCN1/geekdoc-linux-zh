# Arrays and arithmetic

Sophisticated data structures and calculations are not bash's forte. But it does at least offer arrays and arithmetic.

All variables are string valued, so bash does not distinguish between the number 1 and the character "1" in assignments. The difference lies in when the variables are used. The following code illustrates the distinction:

```
#!/bin/bash

a=1
b=$((2))

c=$a+$b
d=$(($a+$b))
```

```
echo "$a + $b = $c \t(plus sign as string literal)"
echo "$a + $b = $d \t(plus sign as arithmetic addition)"
```

This script produces the output

+   - 1 + 2 = 2 (plus sign as string literal)
- 1 + 2 = 3 (plus sign as arithmetic addition)

Note that the plus sign in the assignment to $c does not act as a concatenation operator for strings. It's just a literal character. That is equivalent to

```
c=$a+$b
```

To force numeric evaluation, you enclose an expression in $((..)), as shown with the assignment to $d above. But even this precaution does not prevent in $d receiving a numeric value; the value is still stored as the string "3".

bash has the usual assortment of arithmetic, logical, and relational operators; see the page for details.

Arrays in bash are a bit strange, and they're not used often. Nevertheless, if you need them. Literal arrays are indexed by parentheses, and the elements are separated by whitespace. You can use quoting to include literal spaces in an element.

```
example=(aa 'bb cc')
```

Using ${array_name[index]} to access individual elements. Subscripting begins at zero. The subscripts * and @ refer to the array as a whole, and the special forms ${#array_name[@]} and ${#array_name[@]} yield the number of elements in the array. Don't misremember these as the more logical-seeing ${#array_name}; that is in fact the length of the array's first element (equivalent to ${#array_name[0]}).
