
## 20.7 EMAIL CONFIGURATION

The heart of each email system is its MTA, or mail transport agent. sendmail was the original UNIX MTA, written by Eric Allman while he was a graduate student at UC Berkeley many years ago. Since then, a host of other MTAs have been developed. Some of them are commercial products and some are open source implementations. In this chapter, we cover three open source mail transport agents: sendmail, Postfix by Wietse Venema of IBM Research, and Exim by Philip Hazel of the University of Cambridge.

After the top-level design of the mail system, configuration of the MTA is the next big sysadminmon task. Frankly, the default or sample configurations that ship with MTAs are often very close to the average site needs. You don't have to start from scratch when configuring your MTA.

SecuritySpace(securityspace.com) does a monthly survey to determine the market share of the various MTAs. In their December 2009 survey, 1.7 million out of 2 million MTAs reported, and 95,000 replied with a banner that identified the MTA software in use. Table 20.4 shows these results, as well as the SecuritySpace results for 2007 and 2001 values from a different survey.

# Table 20.4 Mail transport agent market share

| MTA | Source | Market share |
|---|---|---|---|---|
| | | 2009 | 2007 | 2001 |
| Exim | exim.org | 30% | 20% | 8% |
| Postfix | postfix.org | 20% | 15% | 2% |
| MS Exchange | microsoft.com/exchange | 20% | 22% | 4% |
| sendmail | sendmail.org | 19% | 29% | 60% |
| All others | | <3% each | <3% each | <3% each |

The trend is clearly away from sendmail and toward Exim and Postfix, with Microsoft gaining market share and leveling off. Among our example systems, the UNIX variants all ship sendmail. Ubuntu is moving from Postfix to Exim, SUSE ships Postfix, and Red Hat includes all three defaults to sendmail.

For each of our MTAs, we include details on the configuration necessary to accomplish the features of our suggested mail system design, including:

- Configuration of simple clients
- Configuration of an Internet-facing mail server
- Control of both inbound and outbound mail routing
- Stamping of mail as coming from a central server or the domain itself
- Security
- Debugging

### sendmail

If you are implementing a mail system from scratch and have no politics or bias to deal with, it may be hard to choose an MTA. sendmail and Exim are certainly the most complex and probably the most configurable and most powerful options. Postfix is simpler, faster, and was designed with security as a primary goal. If your site or your sysadmins have a history with a particular MTA, it'sably not worth switching unless that functionality's not available in your old MTA.

## 20.8 SENDMAIL

The sendmail distribution in source form is available from sendmail.org, but it's not really necessary to build it from scratch these days. If you have to, refer to the top-level INSTALL file. If you need to tweak some of the defaults, you can find sendmail's assumptions in devtools/OS/your-OS-name, and you can add features by editing devtools/Site/config.m4. sendmail uses the m4 preprocessor not only during compilation but also for configuration. An m4 configuration file is usually named hostname.mc and is translated from a slightly user-friendly syntax to a totally inscrutable low-level language in the file hostname.cf, which is in turn installed as /etc/sendmail.cf.

To see what version of sendmail is installed on your system and how it was compiled, try the following command:

```
linux$/usr/bin/sendmail -d0.1 -bt < /dev/null
Version 8.13.8
Compiled with: DNSMAP GETMAILHOST LDAP LOGMAP_REGEXP MATCHGECOS MILTER MIME7TO8 MIME7TO8 NAMED_BIND NETINET NETINET6 NETUNIX NEWDB NIS PIPELINING ASLV2 SCAN SOCKET STARTMAP TTTLS TCPWRAPPERS USERDB8 USE_LDAP_INIT
========= SYSTEM IDENTITY (after recfd) ==========
(short domain name) $ = ross
(canonical domain name) $ = amass.com
(subdomain name) $m = at.com
(node name) $k = ross.atrust.com
```

This command puts sendmail in test mode (-bt) and debug mode (-d0.1) but gives it no addresses to test </dev/null>. A side effect is that sendmail tells it its version and the compiler it was with. Once you know the version number, you can look at the sendmail.org web site to see if any known security vulnerabilities are associated with that release.

To find the sendmail files on your system, look at the directory of the installed /etc/sendmail.cf file. The comments mention the directory in which the configuration was built. That directory should lead you to the .mc file that is the original source of the configuration.

# The switch file

Most systems have a "service switch" configuration file, access.conf, that enumerates the methods that satisfy various user and host lookups. If more than one is used for a given type of query, the service file also determines the order in which various methods are consulted. The existence of the service file is normally transparent to software. However, sendmail likes to export fine-grained control over loops, so it currently governs the service file and uses its internal service configuration (/etc/mail/service.switch) instead.

Two fields in the service file impact the mail system: aliases and hosts. The possible values for the hosts are dns, nis, nisplus, and files. For aliases, the possible values are files, nis, nisplus, and ldap. Support for the mechanisms you use (except files) must be compiled into sendmail before it can be used.

# Starting sendmail

sendmail should not be controlled by inetd or xinetd, so it must be explicitly started at boot time. See Chapter 3, Booting and Shutting down, for startup details. The flags determine its behavior. You can run sendmail in several modes, selected with the -b flag. It stands for "be" or "become" and is always used with another flag that determines the role sendmail will play. Table 26 lists the legal values and includes the -A flag, which selects MTA and MSA. If you are configuring a server that will accept incoming mail from the Internet, run sendmail in daemon mode (-bd). In this mode, sendmail listens on network port 25 and waits for work. You will usually specify the -q flag, too—it sets the ports that sendmail listens on are determined by DAEMON_OPTIONS; port 25 is the default.

a. This mode is used for debugging so that you can see the error and debugging messages interval when sendmail processes the mail queue. For example, -q30m runs the queue thirty minutes, and -qlh runs every hour.

sendmail normally tries to deliver a message immediately, saving it in the queue only momentarily to guarantee reliability. If your host is too busy or the destination machine is unreachable, sendmail queues the message and sends to it later. sendmail uses persistent queue runners that are usually started at boot time. It does locking, so multiple, simultaneous queue runners are safe. The "queue groups" configuration feature helps with large mailing lists and queues. It is covered in more detail on page 802.

sendmail reads its configuration file, sendmail.cf, if it starts up. There, you must either kill and restart sendmail or send a HUP signal when you change the config file. sendmail creates a sendmail.pid file that contains its process ID and the command that it started. You should start sendmail with an absolute path but that re-execs itself on receipt of the HUP signal. The sendmail.pid file allows the process to be HUPed with the command

```
sudo kill -HUP 'head -1 sendmail.pid'
```

The location of the PID file is OS-dependent. It usually is /var/run/sendmail.pid or /etc/mail/sendmail.pid but can be set in the config file with confPID_FILE option:

```
define(confPID_FILE, '/var/run/sendmail.pid')
```
