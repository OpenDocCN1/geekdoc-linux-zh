
# Chapter 14 TCP/IP Networking

In addition to being its own serial number, an RFC can also be assigned an FYI (For Your Information) number, a BCP (Best Current Practice) number, or a STD (Standard) number. FYIs, STDs, and BCPs are subseries of the RFCs that include documents of special interest or importance.

FYIs are introductory or informational documents intended for a broad audience. They can be a good place to start research on an unfamiliar topic if you find one that’s relevant. Unfortunately, this series has largely recounted and not many of the FYIs are up to date.

BCPs document recommended procedures for Internet; they consist of administrative suggestions and for system administrators are often the most vuable of the RFC series.

STDs document Internet protocols that have completed the IETF's review and process and have been formally adopted as standards.

RFCs, FYIs, BCPs, and STDs are numbered sequentially within their own series, so a document can bear several different identifying numbers. For example, RFC17313, Tools for DNS Debugging, is also known as FYI273.

## 14.2 NETWORKING ROAD MAP

Now that we have provided a bit of context, let’s look at the TCP/IP protocols themselves. TCP/IP is a "suite", a set of network protocols designed to work smoothly together. It includes several components, each defined by a standards track RFC or series of RFCs:

- IP, the Internet Protocol, which routes data packets from one machine to another (RFC7791)
- ICMP, the Internet Control Message Protocol, which provides several kinds of low-level support for IP; including error messages, routing assistance, and debugging help (RFC792)
- ARP, the Address Resolution Protocol, which translates IP addresses to hardware addresses (RFC8263)
- UDP, the User Datagram Protocol, which provides unverified, one-way data delivery (RFC7688)
- TCP, the Transmission Control Protocol, which implements reliable, full duplex, flow-controlled, error-corrected conversations (RFC7793)

These protocols are arranged in a hierarchy or stack making up of the protocols beneath them. TCP/IP is conventionally described as a five-layer system (as shown in Exhibit A), but the actual TCP/IP protocols inhabit only three of these layers.

The version of TCP/IP that has been in widespread use for three decades is protocol version 4, aka IPv4. It uses four-byte IP addresses. A modernized version, IPv6, expands the IP address space to 16 bytes and incorporates several others learned from the use of IPv4. It removes several features of IP that experience has shown to be of little value, making the protocol potentially faster and easier to implement. IPv6 also integrates security and authentication into the protocol.

All modern operating systems and many network devices already support IPv6. However, active use of IPv6 remains essentially zero in the real world. Experience suggests that it's probably best for administrators to defer production of IPv6 to the extent that this is possible. Everyone will eventually be forced to switch to IPv6, but as of 2010 that is still years away. The transition is not so far in the future that you can ignore it when purchasing new devices.

The development of IPv6 was to an extent motivated by the concern that we are running out of 4-byte IPv4 address space. And indeed we do: projections indicate the current IPv4 allocation system will collapse some time after 2011. (See ipv4.potaroo.net for a daily update.) Even so, mainstream adoption of IPv6 throughout the Internet is probably still not in the cards soon.

More likely, another round of stopgap measures on the part of ISPs and ICANN (or more specifically, its subsidiary IANA, the Internet Numbers Authority) will extend the dominance of IPv4 for another few years. We see wider use of IPv6 on the Internet backbone, but outside of large ISPs, academic sites involved in Internet research, and universal providers such as Google, our guess is IPv6 will not be directly affecting most sysadmins' work in the immediate future.

3. A Google study presented at RIPE 57 in October 2008 indicated that overall IPv6 penetration (actual use, not capability) was 0.24%. No country had IPv6 penetration greater than 0.76%.

One of the main chores of the link layer is to add headers to packets and to put separators between them. The headers contain link-layer addressing and checksums, and the separators ensure that receivers can tell where one packet stops and the next begins. The process of adding these extra bits is known generically as framing.

The link layer is actually divided into two parts: the MAC, the Media Access sublayer, and LLC, the Link Layer sublayer. The MAC layer deals with the media and transmits packets onto the wire. The LLC layer handles the framing.

Today, a single standard for Ethernet framing is in common use: DIX Ethernet II. Historically, slightly different standards based on 802.2 were also used, especially on Novell networks.
