# Safer mail to files and programs

We recommend that you use smrush instead of /bin/sh as your program mailer and that you use mail.local instead of /bin/mail as your local mailer. Both programs are included in the sendmail distribution. To incorporate them into your configuration, add the lines

```
FEATURE(`smrush`, `path-to-smrush`)
FEATURE(`local_ltmp`, `path-to-mail.local`)
```

to your .nc file. If you omit the explicit paths, the commands are assumed to live in /usr/libexec. When you use sendmail's confEBINDIR option to change the default location of the binaries to whatever you want. Table 20.14 may help you find where our friendly vendors have stayed agents

# 20.14 Location of sendmail's restricted delivery agents

| OS | smrush | mail.local | sm.bin |
| sendmail | /usr/libexec | /usr/libexec | /usr/adm |
| Ubuntu | /usr/lib/sm.bin | /usr/lib/sm.bin | /usr/adm |
| SUSE | /usr/lib/sendmail.d/bin | /usr/lib/sendmail.d/bin | |
| Red Hat | /usr/sbin | | /etc/smrush |
| Solaris | /usr/lib | /usr/lib | /var/adm |
| HP-UX | /usr/sbin | | /usr/adm⁴ |
| AIX | /usr/sbin | | /usr/adm³ |

> a. This directory does not exist on either HP-UX or AIX, so you must create it.

smrush is a restricted shell that executes only the programs contained in one directory (/usr/adm/sm.bin by default). smrush ignores user-specified paths and tries to find any requested commands in its own know-safe directory. smrush blocks the use of certain shell metacharacters as <, the input direction. Symbolic links are allowed in sm.bin, so you don't need to duplicate copies of the programs you allow. The vacation program is a good candidate for sm.bin. Don't put procmail there; it's insecure.

Here are some example commands and their smrush interpretations:

```
vacation eric          # Executes /usr/adm/sm.bin/vacation eric
cat /etc/passwd       # Rejected, cat not in sm.bin
vacation eric < /etc/passwd # Rejected, no < allowed
```
