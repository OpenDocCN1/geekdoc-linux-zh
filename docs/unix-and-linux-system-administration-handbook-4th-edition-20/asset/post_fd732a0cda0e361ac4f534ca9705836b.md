You create symbolic links in /home/dfs/mydfs to set up the actual automounts. For example, the following command makes the jump "directory" a link to one of two directories on other servers. (Note the quite-important notes. They are required for protection of the backslashes).

```bash
$ sudo ln -s 'msdfs:serverX/shareX,serverY/shareY' jump
```

If more than one source is provided (as here), Windows will fail over between users who use as\myddfs\jump on serverX or serverY, depending on availability. If the filesystems are exported read/write, make sure you use some mechanism in place to synchronize the files. rsync can be helpful for this.

With Samba, you can also redirect all clients that have a particular share to a different server. This is something a Windows server cannot.

```
[myredirect]
msdfs root = yes
msdfs proxy = \serverZ\shareZ
```

Note that DFS only works for users who have the same username and password on all the servers.

# smbclient: a simple CIFS client

In addition to its many server-side features, the Samba package includes a simple command-line file transfer program smbclient. You can use this program to access any Windows or Samba server. For example:

```bash
$ smbclient=[php/c/$ -U BOULDER]@ben
Password:password
Domain=[BOULDER] OS=[Windows Vista (TM) Business 6001 Service Pack 1
Server=[Windows Vista (TM) Business 6.0]
smb: \
```

Once you have successfully logged in to the file server, you can use ftp-type commands (as get, put, lcd, and dir) to navigate and transfer files. Type ? to see a full list of the available commands.

# Linux client-side support for CIFS

Linux includes direct client-side support for the SMB/CIFS filesystem. You can mount a CIFS share into your filesystem tree much as you can with any other filesystem that is directly understood by the kernel. For example:

```bash
$ sudo mount -t cifs -o username=joe /redmond/home/joe/mnt
```

From the perspective of the UNIX client, all files in the mounted directory appear to belong to the user who mounted it. If you mount the server, then all files belong to root, and garden-variety users might not be able to write files on the Windows server.

The mount options uid, gid, fmask, and dmask let you tweak these settings so that ownership and permission bits are in tune with the intended access policy for share. Check the mount.cifs manual page for more information about this behavior.

To allow users to mount a Windows server on their own, you can add a line in the following format to /etc/fstab file:

```text
//redmond/joes /home/joje/mnt cifs

```

Because of the user option specified here, users can now mount the filesystem by running the command

```bash
$ mount /home/joje/mnt

Although NFS is the UNIX standard for network file service, in some situations it may make more sense to use Samba and CIFS to share files among UNIX and Linux computers. For example, in some versions of NFS, it is dangerous to allow users to perform mounting of corporate filesystems from their personal laptops. However, you can safely use CIFS to give these laptops access to their owner's directories.

# 30.7 SHARING PRINTERS WITH SAMBA

The simple approach to printer sharing is to add a smb.conf file; this makes Samba share all local printers. Samba uses the system printing commands to do its work, but since UNIX printing may have to tell Samba which particular printing system is in use on your server. To do that, set the printing option to an appropriate value; check the smb.conf manual page for the list of printing systems that are currently supported.

```ini
[printers]
; To store print files before passing them to the printing system?
path = /var/tmp
```
