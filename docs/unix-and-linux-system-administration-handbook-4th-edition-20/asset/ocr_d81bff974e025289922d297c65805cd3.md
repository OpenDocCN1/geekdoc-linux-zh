# Chapter 26 Printing

If you have to write new filters, stick to using input filters, as they are easier to debug. Input filters are called with numerous arguments, which vary among implementations. The most interesting are the username, host of origin, and counting name. If you want to do accounting for the printer, the input filter must generate the accounting records and append them to the file. If you want to restrict access to a printer (for example, to deny printing to the user “guest”), the input filter must also take care of that since lpd has no built-in way to prevent individuals from using.

To clarify the use of filters, let’s look at a simple example of an input filter script. This example is for a PostScript printer connected to a local serial.

```
#!/bin/bash
/usr/local/bin/textps $ /usr/local/bin/psreverse
```

Because the printer is serially connected, lpd takes care of opening the device with the correct modes, as specified in the printcap file. The first program calls textps, which looks at the input and decides if it is PostScript (which our printer expects), and if not, converts it to PostScript. textps gets all the filter arguments that were passed (the $) and is expected to generate accounting records from that information. The second program, psreverse, reverses the order of the pages so they come out in a proper stack.

printcap variables for serial devices

Many printcap variables and features are involved in the handling of old-style serial printers. If you have to support one of these, one approach is to plan time for reviewing the manual pages and drinking heavily. If you don’t drink, spend your department’s budget on a printer.

printcap extensions

A nice feature of the lpd system is that it does not mind if you supply values for nonstandard printcap variables. Often, when a particular printer needs more information than the base system defines, you can put extra variables in printcap for the printer’s filters to use.

For example, the output filter for a network printer might need to know the network name of the device. The printcap entry for the printer might contain an entry such as

```
:nn=laser.colorado.edu:\
```

The use of printcap extensions allows all of the configuration information for a printer to be stored in one convenient place. If you see variables in the printcap file that are not discussed in the printcap page, check the documentation for the printer filters to determine the meanings of the variables.
