# 7.1 THE /ETC/PASSWD FILE

The /etc/passwd file is a list of users recognized by the system. It can be extended
or replaced by a directory service, so it is complete and authoritative only on stand-
alone systems.

The system controls /etc/passwd at login time to determine a user's UID and
home directory, among other things. Each line in the file represents one user and
contains seven fields separated by colons:

+   * Login name
* Encrypted password placeholder (see page 179)
* UID (user ID) number
* Default GID (group) ID number
* "GECOS" information: full name, office, extension, home phone
* Login shell

For example, the following lines are all valid /etc/passwd entries:

```
root:x:0:0:/bin/sh
jlim:100:0:0:Jime Lane,ECOT8-3;:/staff/j:/bin/sh
dotty:x:101:20:/home/dotted:/bin/tsh
```

Encrypted passwords used in the second field, but that is no longer safe;
with fast hardware, they can be cracked (decrypted) in minutes. All versions of
UNIX and Linux now hide the encrypted passwords by placing them in a separate
file that is not world-readable. The passwd file contains an x in the encrypted
password field on Linux, Solaris, and HP-UX an or a * on AIX. (On Unix
systems, * as a placeholder disables the account.)

The actual encrypted passwords are stored in /etc/shadow on Linux, Solaris, and
HP-UX and in /etc/security/passwd on AIX. The formats vary.

If accounts are shared through a directory service such as NIS or LDAP, you
might see entries in the passwd file that begin with + or -. These entries
tell the system how to integrate the directory service's data with the contents of
/etc/passwd. This integration can also be set up in /etc/nsswitch.conf file
(/etc/ncontrol on AIX).

The following sections discuss the /etc/passwd fields in more detail.
