To read this best, start reading the Received Lines, but from the sender (side). This message from David Schweikert's home machine in the schweikert.com to his mail server (mail.schweikert.ch), where it was scanned for viruses. It was forwarded to the recipient evi@atrust.com. However, the receiving host mail-relay.atrust.com sent it to sailing@gmail.com, where it entered EVI mail.

Midway through the headers, you see an SPF validation failure. This happened because Google checked the IP address of mail-relay.atrust.com and compared it to the SPF record at schweikert.ch; of course, it doesn't match. It is an inherent weakness of SPF records to identify forgeries—they don't work for mail that has been relayed.

You can also see the MTAs that were used (Postfix at schweikert.ch, sendmail 8.12 at atrust.com), and in this case, you can also see that virus scanning was performed through amavisid-new on port 10.024 on a machine running Debian Linux. You can follow the progress of the message from the Central European Summer Time zone (CEST +0200), to Colorado (-0600), and to the Gmail server (PDT -0700); the numbers are the differences between local time and UTC, Coordinated Universal Time. There is a lot of info in the headers!
