generate for example a 1,024-bit RSA and a corresponding 2,048-bit KSK pair. The outstanding use of UDP packet size suggests that it's best to use longer key-signing keys to change them out. You can use longer key-signing keys to help recover some security. It takes awhile to generate the keys—a minute or two for short keys, a half-hour or more for longer keys on a tired laptop.

Both key generators use the base filename of the key they have generated to standard out. In this example, example.com is the name of the key, 005 is the identifier of the RSA/SHA-1 algorithm suite, and 23301 and 00682 are hashes called the keys they identified, fingerprints or keys. Each of the BIND key generator creates two files (.key and .private), and the NSD key generator produces three files (.key, .private, and .ds).

```
example.com.+005+23301 # Public key-signing key
example.com.+005+23301.private # Private key-signing key
example.com.+005+23301.ds # DS record for ZSK (NSD only)
```

```
example.com.+00682.key # Public key-signing key
example.com.+00682.private # Private key-signing key
example.com.+00682.ds # DS record for KSK (NSD only)
```

Several encryption algorithms are available, each with a range of possible key lengths. You can run nssec-keygen with no arguments or ldns-keygen -a list to see the current list of supported algorithms. BIND and NSD can use both keys generated by other software.

Depending on your version of software, some of the available names have NSEC3 records or prepended to them. If you want to generate NSEC3 records instead of NSEC records for signed negative answers, you must NSEC3-compatible keys with one of the NSEC3-specific algorithms; see the pages for ldns-signzone or dnssec-keygen.

The key files contain a single DNSKEY resource record for example.com. For example, here is the zone-signing public key, truncated to fit the page. You can tell it's a ZSK by the flags field is 256, rather than for a KSK.

```
example.com IN DNSKEY 256 3 5 AwEEAAex7He60wva8sPPnre4RX8Mgi...
```
