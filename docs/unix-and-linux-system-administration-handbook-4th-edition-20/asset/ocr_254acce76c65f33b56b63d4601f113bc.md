# Filesystem mounting unmounting

When you are writing scripts, a useful weapon to know about is find's-print0 option. In combination with xargs -0, this option makes the find/xargs combination work correctly regardless of the whitespace contained within filenames. For example,

```
$ /home -type f -size +1M -print0 | xargs -0 -ls
```

prints a log listing of every file in /home over some megabyte size
Unfortunately, HP-UX users find-print0 but not xargs -0, and AIX has their option. However, you can install the GNU findutils package on either system to obtain current versions of both find and xargs.(Alternatively, you can use the -exec option to find instead of xargs, which is its fussier and less efficient.)

# 2 FILESYSTEM MOUNTING UNMOUNTING

The filesystem is composed of smaller chunks—each of consists of one directory and its subdirectories and files. It's normally apparent from context what type of "filesystem" is being discussed, but for clarity in the following discussion, we use the term "file tree" to refer to the overall layout and reserve the word "filesystem" for the chunks attached to the tree.

Most filesystems are disk partitions or disk-based volumes, as we mentioned earlier, they can be anything that obeys the proper API: network file servers, kernel components, memory-based disk emulators, etc. Linux and Solaris even have a "loopback" filesystem that lets you mount individual files as if they were distinct devices. It's great for developing filesystems without having to worry about partitioning your disks.

In most situations, filesystems are attached to the tree with the mount command.mount maps a directory within the file tree, the mount point, to the newly attached filesystem. The previous contents of the mount point become inaccessible as long as another filesystem is mounted. Mount points are usually empty directories, however.

For example,

```
$ sudo mount /dev/sda4 /users
```

installs the filesystem stored on the disk partition by /dev/sda4 under the path /users. Then you could use /users to see your's contents.

A list of filesystems that are customarily on a particular system is kept in the /etc/fstab, /etc/vfstab (Solaris), or /etc/filesystems (AIX) file.
