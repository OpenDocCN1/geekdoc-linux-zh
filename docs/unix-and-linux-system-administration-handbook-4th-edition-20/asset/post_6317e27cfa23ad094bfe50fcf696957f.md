
# Chapter 26 Printing

## PDF

Adobe's Portable Document Format is produced by Adobe Acrobat and many other non-Adobe applications. OpenOffice, for example, prefers to export documents as PDF.

PDF documents are platform independent, and PDF is routinely used to exchange documents electronically for both on-line and off-line (printed). The first text of this book was delivered to the book printer as a PDF file.

PDF is a document description language, not just a page description language. It describes not only individual pages, but also the overall structure of a document: which pages belong to chapters, which text columns flow to other columns, and so on. It also accommodates a variety of multimedia, hypertext, and scripting features for on-screen use.

Some printers interpret PDF directly. If yours doesn't, a host of PDF viewers and translators (including Ghostview, xpdf, kpdf, Evince, and Acrobat Reader) can convert your PDF documents into something else (such as PostScript) that is more widely understood. Your print system may even hide the conversion requirement from you and automatically convert PDF documents before sending them to the printer.

## XPS

Worth mentioning, too, is Microsoft's XML Paper Specification, aka XPS. OpenXPS is not yet widely used on Windows systems. UNIX and Linux support is currently scant, although Artifex already has an XPS interpreter. Distributions will undoubtedly start to support XPS if it becomes popular.

## PJL

Hewlett-Packard's Printer Job Language, is not a real PDL. It's a meta-language that describes printer jobs. We mention it here because you'll see mentioned in printer descriptions. You'll also need to know about it if you're looking at the internals of print jobs to solve printing problems.

PJL is a job control language that specifies things like a job's PDL, whether the job is duplex or simplex, what paper size to use, and so on. The PJL commands that come at the start of the job, and the PJL statements start with @PJL:

```
@PJL SET COPIES=3
@PJL COMMENT FOO BAR MUMBLE
@PJL SET DUPLEX=ON
@PJL SET PAGEPROTECT=OFF
@PJL ENTER LANGUAGE=PCL
```

Non-HP printers understand (or deliberately ignore) PJL, but if you're having trouble printing something that contains PJL on a non-HP printer, removing the PJL with a text editor and resubmitting the job.

## Printer drivers and their handling of PDLs

What if a printer supports only a subset of the languages you need to process? If you download a PostScript file from the web and your printer only understands PCL5E, what do you do? If your printer doesn't interpret PDF directly, how do you print a PDF file?

One option is to convert the file by hand. Your boxes come with plenty of conversion; there's almost always way to turn what you have into some printers print. Browsers can transform HTML (or XHTML) into PostScript. OpenOffice can convert MS Word files into PDF. Ghostscript can turn PDF into PostScript and PostScript into almost anything, including PCL.

An easier approach is to let your system do the work for you. Some systems, such as CUPS, have built-in knowledge about which conversions need to be done and set up the conversions for you automatically.

If you need to determine what PDL a file uses and you can't tell you from the filename (e.g., foo.pdf), the file command can tell you (unless the file starts with a chunk of PJL instructions, in which case file just says "HP Printer Job Layout data")

Save a few print jobs to files instead of sending them to a printer, and you can see what a program in one of these languages looks like. A minute or two perusing pages of each of these types in your editor will give you a good feel for how different they are. (Don't cat them directly to your screen, since only PostScript is ASCII. Random binary data tends to confuse terminal emulators.)

## 26.9 PPD FILES

When you use lpr to print book.ps on the color printer, lpr may back back and ask you what you want to print on. Color—wait—how does the system to tell its client, lpr, that it can print on A4 paper? How does it know it can handle PostScript, and what should it do if it can't? Where does find the information that it is a color printer?

If you use CUPS, all this information is kept in PostScript Description PPD files that describe the attributes and capabilities of your printers. The daemon handles the PPDs for its printers and passes information about them to clients as needed. PPDs were first developed for the Mac world, but they were quickly adopted by Windows as well. Mac and Windows printer drivers use the PPD file to figure out how to send jobs to the printer. For example, it makes no sense to ask a single-sided, black-and-white printer sold in America to print a duplex, color document on European sized paper. Every PostScript printer has its own PPD file created by the vendor, although the file is not easy to find. Check the installation disk and the vendor's site.

PPD files are text files. Take a look at one in a text editor to see the type information it contains. On a network, PPDs can be remote—CUPS clients can get all the PPD information they need from the relevant CUPS server. CUPS also uses PPDs to describe printers that lack a Postscript interpreter. An extra does to show the trick. Look:

```
$ cupsFilter: /usr/share/ghostscript/model/pxmono.ppd
"cupsFilter: "application/vnd.cups-postscript" pstopsl"
"cupsFilter: "application/vnd.cups-pdf" pstopsl"
```

## Paper sizes

You can diff a couple of related PPDs (try pxmono.ppd and color.ppd) to see exactly how two printers differ.

If you need a PPD file and your printer vendor doesn't supply one—say, because the printer doesn't have a PostScript interpreter and the vendor doesn't care about anything but Windows—go to linuxprinting.org and hunt through the Foomatic database for more information. Your printer may also be supported by the Gutenberg printer project (gutenprint.sourceforge.net). If you have a choice of PPDs from these sources and your users want last drop of quality, the ones marked “foomatic+gutenprint” are quite good. However, you'll still have to experiment with the printer configuration to find out what options give the best output.

If a PPD file is nowhere to be found:

- You have consulted linuxprinting.org before you acquired the printer. If you got the printer out of a dumpster, “free” doesn't always mean “inexpensive"
- There may be a PPD file that will let print something, even if it doesn't take advantage of all your printer's features. For example, we've had luck using generic HP drivers on non-HP printers.

Though CU depends on PPDs, older printing systems make no use of them. For the BSD or System V printing systems, you can either manage your PostScript or live with what you get by default.

## 26.10 PAPER SIZES

Users want physical sheets of paper. Paper comes in sizes and shapes. To make your users happy, you should know the basic facts about paper sizes.

In the United States and Canada, the most common paper size is called letter and is 8.5 × 11 inches. Some Linux distributions (e.g., Knoppix and SUSE) are produced in Europe, where they don't even know what inches are, or in England, where they do know but don't use them to measure paper. In these places, the common paper type is called A4, and printers all use A4 trays. Some distributions' printing produce A4 pages by default.

A4 paper makes sense because it's irrational—mathematically speaking, the ratio of width to height of paper is √. If you slice a piece of paper in half horizontally, you get two half-size sheets of paper that have the same length-to-width ratio: √. This paper size is called A5. Cut in half you get two sheets of A6. In the other direction, A3 is twice the area of A4, but the same shape, and so on.

In other words, you can manufacture A0 paper, which has an area of square meter, and use a paper cutter to create the other sizes you need. The only common U.S. paper size you can play this kind of game with is ledger (11 × 17 inches, also known as tabloid), which you can slice in half to get two sheets of letter.
