# Dual booting, or why you shouldn't

If you've ever installed Linux on a computer that had a former life as a Windows machine, you have doubtless been offered the option to set up a dual boot configuration. Such configurations function pretty much so. It is possible to mount Windows partitions under Linux and to access Linux filesystems from Windows. Read all about setting up a dual boot configuration on 85.

But wait! If you are doing real work and need access to both Windows and UNIX, be very skeptical of dual booting as a possible solution in the context of a production system. Dual boot setups represent Murphy's Law at worst: they always seem to be booted into the wrong OS, and the slightest chore requires multiple reboots. With the advent of widespread virtualization and cheap hardware, there's usually no reason to put yourself through this torture.

# 30.6 SHARING FILES WITH SAMBA AND CIFS

In the early days, sharing files between Windows and UNIX was a difficult task. The introduction of Samba and its implementation of the Common Internet File System (CIFS) changed everything. Samba allows UNIX systems to act as Windows servers, enabling file and printer sharing across the network.

On the client side, Windows provides its own tools to connect to Samba-based servers, such as the built-in SMB-based client. This allows Windows users to access UNIX files as if they were local. The integration of these systems has become essential for heterogeneous environments.

# Samba: for Windows

Samba is an open source software suite that provides directory service integration between Unix and Windows clients. It implements the Server Message Block (SMB) protocol, which is used by Windows for sharing files and printers.

Samba is widely used because it allows UNIX machines to participate in a Windows domain seamlessly. It supports various features such as authentication, authorization, and group management. The implementation of Samba has evolved over time, keeping up with the latest Windows protocols and features.

Samba is known to work with all of our examples. Linux distributions package it as a matter of course. Patches, documentation, and other goodies are available from samba.org. Make sure you are using the most current Samba packages for your system since any updates fix security vulnerabilities.

# Samba installation

Samba is known to work with all of our examples. Linux distributions package it as a matter of course. Patches, documentation, and other goodies are available from samba.org. Make sure you are using the most current Samba packages for your system since any updates fix security vulnerabilities.

On all systems, you will need to edit the **smb.conf** file (which is to be found in `/etc/samba/smb.conf` or `/etc/conf`) to tell Samba how to behave. In this file, you specify the directories and printers that will be shared, their access rights, and Samba's general operational parameters. The Samba package comes with a well-commented **smb.conf** file that is a good starting place for configurations. Note that once Samba is running, it checks its configuration file every few seconds and reloads changes you make.
