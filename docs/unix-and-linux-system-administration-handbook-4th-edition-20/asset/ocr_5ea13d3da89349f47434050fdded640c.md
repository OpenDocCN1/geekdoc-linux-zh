# Package repositories

Since no single supplier can encompass the entire “world of Linux software,” the systems allow for the existence of multiple software repositories. Repositories can be local to your network, so these systems make a dandy foundation for creating your own distribution system.

The Red Hat Network is closely tied to Red Hat Enterprise Linux. It is a commercial service that costs money and offers in terms of attractive GUIs and automation ability than APT and yum. Red Hat Network is a shiny, public version of Red Hat's expensive and proprietary Satellite Server. The client side can reference yum and APT repositories, and this ability has allowed distributions like CentOS to adapt the client GUI for nonpropri use.

APT is better documented than the Red Hat Network, significantly more portable, and is free. It’s also more flexible in terms of what you can do with it. APT originated in the world of Debian and dpkg, but it has been extended to pass RPMs, and versions that work with all of our example distributions are available. The closest thing we have point to a universal standard for software distribution.

yum is an RPM-specific alias of APT. Its default package manager for Hat Enterprise Linux version 5, although it runs on RPM-based system, provided that you can point it toward appropriately formatted repositories.

We like APT and consider it a solid choice if you want to set up your automated package distribution network. See the section: The Advanced Package Tool on page 387 for more information. However, in most cases it’s safest to switch to the package management tool that ships with your distribution of choice.

SUSE implements its RPM-based package management tool known as Zypp, with a command-line interface called zipper. In addition to the usual features such as repository configuration, package installation, and status queries, Zypper shines in its implementation of dependency resolution. Zypper 1.0 was released with openSUSE 11.1. We discuss Zypper beginning on page 392.

# Package repositories

Linux distributors maintain software repositories that work hand-in-hand with their chosen package management systems. The default configuration for the package management system usually points to one or more well-known or FTP servers that are under the distributor’s control.

However, it’s not obvious what such repositories contain. Should they include only the sets of packages released as base, major releases? Formal releases plus current security updates? Up-to-date versions of all packages that exist in the formal releases? Use third-party software not officially supported by the distributor? Source code? Binaries for multiple architectures? When you run apt-upgrade, yum upgrade, and zypper dup to bring the system up to date, what exactly should that mean?
