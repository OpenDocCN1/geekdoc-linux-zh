Within the drivers subdirectory of the kernel source tree, find the subdirectory that corresponds to the type of device you are dealing with. A directory listing of drivers looks like this:

```
linux$ -F path_to_kernel_src/drivers
acorn/    char/ i2c/    Makefile net/  s390/telephony/
acpi/      ide/       md/     nubus sbus/  video/
atm/     fc4/      ee3294/  media/ parport/ usb/
block/    input/     message/ pci/    sgi/     zorro/
bluetooth/ isdn/      misc     pcmcmia/ sound/
cdrom/    hotplug macintosh/ mtd/    pnp/     tc/
```

The most common directories to which drivers are added are block, char, net, scsi, sound, and usb. These directories contain drivers for block devices (such as IDE disks), network devices, SCSI cards, sound cards, and USB devices. Some of the other directories contain drivers for the buses themselves (e.g., pci, nubs, and zorro). it's unlikely that you will need to add to these directories. Some directories contain platform-specific devices, such as macintosh, s390, and acorn.

Since our example is a network-linked device, we add the driver to the directory drivers/net. We modify the following files:

+   * drivers/net/Makefile so that our driver will be compiled
* drivers/net/Konfig so that our driver will appear in the config options

After putting the .c and .h files in drivers/net/snarf, we add the driver to drivers/net/Makefile. The line we add (near the end of the file) is

```
obj-$(CONFIG_SNARF_DEV) += snarf/
```

This configuration adds the driver (stored in the snarf/ directory) to the build process.

After adding the device to the Makefile, we have to make sure we configure the device when we configure the kernel. All network devices must be listed in the file drivers/net/Konfig. To add the device so that it can be built either as a module or part of the kernel (consistent with what we claimed in the Makefile), we add the following line:

```
config SNARF_DEV
tistrate 'Snarf device support'
```

The first token after config is the configuration macro, which must match the token following CONFIG_ in the Makefile. The tristate keyword means that we can build the device as a module.
