# DNSSEC resource records

We suggest that you keep a key log that records the date you generated each key, the hardware and operating system used, the version of the key generator software, the algorithm used, the key length, and the signature validity period. If a cryptographic algorithm is later compromised, you can check your log to see if you are vulnerable.

# DNSSEC resource records

DNSSEC uses resource record types that were referenced in the DNS database section on page 590 but were not described in detail: DS, DLV, DNSKEY, RRSIG, NSEC, and NSEC3. We describe them in general and outline the steps involved in signing a zone. Each of these records is created by DNSSEC tools rather than typed into a zone file with a text editor.

The DS (Designated Signature) record appears only in the parent zone and indicates whether a subsection is signed (signed). It identifies the key used by the child to sign its own KEY resource set. The DS record includes a key identifier (a five-digit number), a cryptographic algorithm, a digest type, and a digest of the public key record allowed (or used) to sign the child's key record.

If your parent is not signed, you can establish a trust anchor at ISC by using a DLV (domain nowadays validation) record with the same format. Here are examples of each:29

```
example.com.
IN DS 682 5 1 12898DCF9F72AD0BCE1597...
example.com.dlv.isrc.
IN DLV 682 5 1 12898DCF9F72AD0BCE1597...
```

The question of how to change existing keys in the parent and child zones has been a thorny one that seemed require cooperation and communication between parent and child. The creation of the DS record, the use of separate key-signing and zone-signing keys, and the use of multiple key pairs have helped this problem.

Keys in a DNSKEY resource record can be key-signing keys (KSKs) or zone-signing keys (ZKSs). A new flag, called SEP for “secure point”, distinguishes between them. Bit 15 of the flags is set to 1 for KSKs and 0 for ZKSs. This convention marks flags of KSKs odd and of ZKSs when they are treated as decimal numbers. The values are 257 and 256, respectively.

Multiple keys can be generated and signed so that a smooth transition from one key to the next is possible. The child may change its zone-signing keys without notifying the parent; it must only coordinate with the parent if it changes its keysigning key. As keys roll over, both the old key and the new key are valid for a certain interval. When cached values on the Internet have expired, the old key can be retired.
