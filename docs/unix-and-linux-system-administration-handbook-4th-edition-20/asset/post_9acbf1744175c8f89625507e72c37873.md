
# Chapter 20 Electronic Mail

You cannot design a mail system in a vacuum. You must be synchronized with (or at least not be in conflict) with DNS MX records and your firewall policy.

## Queue monitoring

You can use the mailq command (which is equivalent to sendmail -bp) to view the status of queued messages. Messages are queued while they are being delivered or when their delivery has been failed.

mailq prints a human-readable summary of the files in /var/spool/mqueue at any given moment. The output is useful for determining why a message may have been delayed. If it appears a backlog is developing, you can monitor the status of sendmail's attempts to clear the jam.

There are two default queues: one for messages received on port 25 and another for messages received on port 587 (the client submission queue). You can invoke mailq -Ac to see the client queue.

Here is typical output from mailq. This case shows three messages waiting to be delivered:

```
$ sudo mailq
/var/spool/mqueue (3 requests)
--Size----QTime----------------------Sender/Recipient----
-ID-----k23gYY008732 23217 Sat Jul 1 21:42 MAILER-DAEMON
8BITIME (Deferred: Connection refused by agribusinessonline.com)
<Nimtz@agribusinessonline.com>
k5ULkAHB032374 279 Fri Jun 30 15:46 -randy@atrus.com>
(Deferred: Name server: k2.com: host name lookup fa)
<kelder@k2wireless.com>
k5UJDm72023576 2485 Fri Jun 30 13:13 MAILER-DAEMON
(reply: read error from mx4.com)
<lfinist@bbnplanet.com>
```

If you understand the situation better than sendmail or you want just sendmail to retrieve the queued messages immediately, you can force a queue run with sendmail -q. If you use sendmail -v, sendmail shows the play-by-results of each delivery attempt, information that is often useful for debugging. Left to its own devices, sendmail retries delivery every queue interval (typically 30 minutes).

## Logging

sendmail uses syslog to log and status messages with the syslog facility "mail" and levels "debug" through "crit"; messages are tagged with the string "sendmail." You can override the logging string "sendmail" with the -L command option; this capability is handy if you are debugging copy of sendmail while other copies are regular email chores.

## Exim

The confLOG_LEVEL option, specified on the command line or in the config file, determines the severity level that sendmail uses as a threshold for logging. High values of the log level imply low severity levels and cause more to be logged.

Table 20.17 gives an approximate mapping between sendmail log levels and syslog levels.

## Table 20.17 sendmail log levels vs. syslog levels

| L | Syslog levels | L | Syslog levels |
|---|---|---|---|
| 0 | No logging | 4 | notice |
| 1 | alert or crit | 5–11 | info |
| 2 | crit | ≥12 | debug |
| 3 | error or warning | | |

Recall that a message logged to syslog at a particular level is reported to that level and all above it. The /etc/syslog.conf file determines the eventual destination of each message. Table 20.18 shows their default locations:¹⁶

## Table 20.18 Vendor's sendmail logging locations

|---|---|
| Ubuntu | /var/log/mail.log |

Several programs can summarize sendmail log files, with the end products ranging from simple counts and text tables (mreport) to fancy web pages (Yasma). You might need to—or want to—limit access to this data or inform your users that you are collecting it. Yasma (Yet Another Sendmail Log Analyzer), for example, lets you hide the username part of email addresses in reports.

Tons of Exim documentation are available on-line, as are a couple of books by the author of the software.

Googling for Exim questions often seems to lead to old, undated, and sometimes inappropriate materials, so check the official documentation first. A 400+-page specification and configuration document (doc/spec.txt) is included in the distribution. This document is also available from exim.org as a PDF file. Its definitive reference work for Exim is updated regularly with each new release.

There are two cultures with respect to Exim configuration: Debian and the world's. Debian adds m4 preprocessing and runs its own set of mailing lists to support users. We do not cover the Debian-specific configuration extensions.

Exim releases 4.70 and later have dropped support for DomainKeys (the precursor to DKIM) and now include DKIM support by default. Both systems can coexist in the real world, but DKIM is on the IETF standards track and will eventually replace DomainKeys.

Exim is like sendmail in that it is implemented as a process that performs all the mail. However, it does not carry all of sendmail's historical baggage (support for ancient address formats, needing to get to hosts on the Internet). When compiled with content scanning, it interfaces with spam and virus scanners via Assassin and ClamAV. Policy is implemented through ACLs (access control lists) that can accept or reject messages or pass them to external scanning software. Per-user filters are available through a special type of entry in users .forward files. Many aspects of Exim's behavior are specified at compile time, the examples being Debian's and message store formats.

The workhorses in the Exim system are all routers and transports. Both decide how messages are delivered; routers decide the route, transports decide the mechanics.

Routers must be compiled to include the code that you intend to use. In these days of large memories, you might well as leave them in all. Default paths are certainly nonstandard: for example, the binary in /usr/exim/bin and the PID file in /var/spool/exim. You might want to tweak these values to match other installed software.

## Exim installation

```
BIN_DIRECTORY=/usr/exim/bin          # Where exim binary lives
SPOOL_DIRECTORY=/var/spool/exim             # spool directory
CONFIGURE_FILE=/usr/exim/configure           # Exim's configuration file
SYSTEM_ALIASES_FILE=/etc/aliases           # Location of aliases file
EXIM_USER=root                              # User to run as

ROUTER_ACCEPT=yes                          # Router to include
ROUTER_DNSLOOKUP=yes
ROUTER_IPLITERAL=yes
ROUTER_MANUAL_ROUTE=yes
ROUTER_QUERY_PROGRAM=yes
ROUTER_REDIRECT=yes

TRANSPORT_APPENDDEFILE=yes# Transport to include
TRANSPORT_AUTOREPLY=yes
TRANSPORT_PIPE=yes
TRANSPORT_SMTP=yes
```

```
SUPPORT_MAILDIR=yes               # Mailbox formats to understand
SUPPORT_MAILSTORE=yes
SUPPORT_MBX=yes
```

```
LOOKUP_DBM=yes                   # Database lookup methods to include
LOOKUP_SEARCH=yes                           # Linear search lookup
LOOKUP_DNSDB=yes                            # Allow arbitrary DNS lookups
LOOKUP_CDB=yes                               # Dan Bernstein's DB lookups
USE_DB=yes                                   # Use Berkeley DB (from README)
DBMLIB=ldap                                 # Include content scanning via ACLs
WITH_CONTENT_SCAN=yes
```

```
EXPERIMENTAL_SPF=yes               # Include SPF support, needs libspf2
CFLAGS=-/usr/local/include                   # From with libspf2
LDFLAGS=-spf2
```

```
LOG_FILE_PATH=/var/log/exim_%slog      # Log files: file, syslog, or both
LOG_FILE_PATH=syslog                          %slog
LOG_FILE_PATH=/var/log/exim_%slog
EXCYCLE_MAX=10                              # Compress/cycle log files, keep them to
```

About database lookup methods are available, including MySQL, Oracle, CDB,¹ and LDAP. If you include LDAP, you must specify the LDAP_TYPE variable to tell what LDAP library you are using (the options are Netscape, Solaris, and a couple of versions of OpenLDAP). You may also need to specify the path to LDAP include files and libraries.

-   CDB is Dan Bernstein's constant database system; it scales well.
