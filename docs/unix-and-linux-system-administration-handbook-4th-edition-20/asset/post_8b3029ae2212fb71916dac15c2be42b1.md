
# Units

Memory is really $2^{20}$ or 1,048,576 bytes. The de-facto stolen units have even made their way into formal standards such as the JEDEC Solid State Technology Association's Standard 100B.01, which recognizes the prefixes as denoting powers of 2 (albeit with some misgivings).

In an attempt to restore clarity, the International Electrotechnical Commission has defined a set of numeric prefixes (kibi-, mibi-, gibi-, and so on, abbreviated Ki, Mi, and Gi) based on powers of 2. Those are unambiguous, but they are just starting to be widely used. The original kilo-series prefixes are still used in both senses.

Context helps with decoding. RAM is always denominated in powers of 2, but network bandwidth is always a power of 10. Storage space is usually quoted in power-of-10 units, but block page sizes are in powers of 2.

In this book, we use IEC units for powers of 2, metric units for rough values and cases in which the exact basis is unclear, or impossible to determine. In command output and in excerpts from configuration files, we leave the original values and unit designators. We abbreviate bit as b and byte as B. Table 1.2 shows some examples.

## Table 1.2 Unit decoding examples

| Example | Meaning |
|---|---|
|| 56 kb/s serial line | A serial line that transmits 56,000 bits per second |
| 1kB file | A file that contains 1,000 bytes |
| 4KiB SSD pages | SSD pages that contain 4,096 bytes |
| 8KB of memory | Not used in this book; see note below |
| 100MB file limit | Nominally $10^6$ bytes; in context, ambiguous |
| 100Mbit partition | Nominally $10^9$ bytes; in context, probably 99,999,744 bytes$^b$ |
| 1GB of RAM | Exactly 1,073,741,824 bytes of memory$^b$ |
| 1 Gb/s Ethernet | A network that transmits 1,000,000,000 bits per second |
| 1 TB hard disk | A hard disk that stores 1,000,000,000,000 bytes |

+ a. That is, $10^9$ rounded down to the nearest multiple of the 512-bit block size
b. But according to Microsoft, not enough memory to run the 64-bit version of Windows 7

The abbreviation, K as in "8KB of RAM", is not part of any standard. A computer adaptation of the metric prefix k, for kilo-, and originally meant 1,024 as opposed to 1,000. But since the abbreviations for the larger metric prefixes are already uppercase, the analogy doesn't scale. Later, people became confused about the distinction and started using K for factors of 1,000, too.

The Ubuntu Linux distribution is making a valiant attempt to bring rationality and consistency to this issue; see wiki.ubuntu.com/UnitsPolicy for some additional details.

# 1.9 MAN PAGES AND OTHER ON-LINE DOCUMENTATION

The manual pages, usually called "man pages" because they are read with the man command, constitute the traditional "on-line" documentation. (Of course, these days all the documentation is on-line in some form or another.) Man pages are typically installed with the system. Program-specific man pages come along the ride when you install new software packages.

Man pages are concise descriptions of individual commands, drivers, file formats, or library routines. They do not address more general topics as "How do I install a new device?" or "Why is this system so damn slow?" For those questions, consult your vendor's administration guides (see page 18) or for Linux systems, the documents available from the Linux Documentation Project.

# Organization of the man pages

All systems divide the man pages into sections, but there are minor variations in the way sections are defined. The basic schema used by our example systems is shown in Table 1.3.

## Table 1.3 Sections of the man pages Contents

| Linux | Solaris | HP-UX | AIX | Contents |
|---|---|---|---|---|
| 1 | 1 | 1 | 1 | User-level commands and applications |
| 2 | 2 | 2 | 2 | System calls and kernel codes |
| 3 | 3 | 3 | 3 | Library calls |
| 4 | 7 | 7 | 4 | Device drivers and network protocols |
| 5 | 4 | 4 | 5 | Standard format files |
| 6 | 6 | 6 | 6 | Games and demonstrations |
| 7 | 5 | 5 | 7 | Miscellaneous files and documents |
| 8 | 1 | 1 | 8 | System administration commands |
| 9 | 9 | 9 | - | Obscure kernel spaces and interfaces |
| - | - | 9 | - | HP-UX general information |

Some sections may be further subdivided. Solaris's 3 contains man pages about the system's standard library. There is also considerable variation in the exact distribution of pages; some systems leave section 8 empty and lump games and demos into section 1. Many systems have a section l (lowercase L) for local pages. The exact structure of sections is not important for most topics because man finds the appropriate page wherever it is stored. You only need to be aware of the section definitions when a topic with the same name appears in multiple sections. For example, `passwd` is both a command and a configuration file, so it has entries in both section 1 and 4 or 5.

# man: read man pages

man title formats a specific manual page and sends it to your terminal through less, or whatever program is specified in your PAGER variable. title is usually a command, device, or name of library routine. The sections of the manual are searched in roughly numeric order, although sections that describe commands (sections 1, 8, and 6) are usually searched first.

The form title gets you a man page from a particular section. Then, on most systems, man gets you the man page for the command, and man gets you the man page for system call.

- Under Solaris, you must preface the section number with the -s flag, for example man -s 2.
- man k or apropos prints a list of man pages that have keyword in their one-line synopses. For example:

```
$ man -k objcopy (1) - copy and translate object files
gettext (3) - translate message (1) - translate or delete characters
snmptranslate (1) - translate SNMP OID values into more useful information
(1) - translate characters
```

The keywords database can be out of date. If you add additional man pages to your system, you may need to rebuild this with mandb (Ubuntu, SUSE), what (Red Hat), or man -w (Solaris, HP-UX).

# Storage of man pages

nroff input for man pages is usually kept in directories under /usr/share/man. Linux systems compress them with gzip to save space. The man command knows how to uncompress them on the fly. The man command maintains a cache of formatted pages in /var/cache/man or /usr/share/man if the appropriate directories are writable, this is a security risk. Most systems preformat man pages at installation time (see catman) or not at all.

Solaris understands man pages formatted with SGML in addition to the traditional nroff. The SGML pages have their own sections underneath /usr/share/man.

The man command can search several man page repositories to find the man pages you request. On Linux systems, you can find the current default search path with the manpath command. This path (from Ubuntu) is:

```
ubuntu$ manpath
/usr/local/man:/usr/local/share/man:/usr/share/man
```

# Where to Start

If necessary, you can set your MANPATH variable to override the default path:

```
export MANPATH=/home/share/localman/usr/share/man
```

Some systems let you set a custom system-wide default search path for man pages, which can be useful if you need to maintain a parallel tree of man pages such as those generated by OpenPKG. If you want to distribute local documentation in the form of man pages, however, it is simpler to use your system’s standard packaging mechanism and to put man pages in the standard directories. Chapter 12, Software Installation and Management, for more details.

# GNU Texinfo

Linux systems include a sort of supplemental on-line man page system called Texinfo. It was invented long ago by the GNU folks in reaction to the fact that the nroff to format man pages was proprietary to AT&T. These days we have GNU’s own to do this job for us and the nroff is no longer important, but Texinfo still lumbles around like a zombie in search of humans.

Although the use of Texinfo seems to be gradually fading, a few GNU packages persist in documenting themselves with Texinfo files rather than man pages. You can pipe the output of the Texinfo reader, info, through less to evaluate info built-in navigation system.

Fortunately, packages that are documented with Texinfo usually install man pages that tell you how to use the info command to read about those particular packages. You can safely stick to the man command for manual searches and delve into info land only when instructed to do so. info initiates you into the dark mysteries of Texinfo.

# 1.10 Other AUTHORITATIVE DOCUMENTATION

Man pages are just a small part of the official documentation. Most of the rest, unfortunately, is scattered on the web.

# System-specific guides

Major vendors have their own dedicated documentation projects, and many continue to produce useful book-length manuals. These days are usually on-line rather than in the form of printed books. The extent and quality of the documentation vary widely, but most vendors produce at least an administration guide and an installation guide. Table 1.4 shows where to look for each of our examples.

The standout in this crowd is IBM, which produces a raft of full-length books on a variety of administration topics. You can buy them as books, but they’re available for free as downloads. The downside to IBM’s completeness is that many of the documents seem to lag a version or two behind the current release of AIX.
