# Chapter 4 Access Control and Rootly Powers

PAM is a wrapper for a variety of method-specific authentication libraries. Administrators specify the authentication methods they want the system to use, along with the appropriate contexts for each one. Programs that want to authenticate a user simply call the PAM system rather than implementing their own forms of authentication. PAM turn calls the authentication library specified by the system administrator.

# Kerberos: third-party cryptographic authentication

Like PAM, Kerberos deals with authentication rather than access control per se. But whereas PAM is an authentication framework. They are generally used together, PAM being the wrapper and Kerberos the actual implementation.

Kerberos uses a trusted third party (a server) to perform authentication for an entire network. # Access control lists

Since filesystem access control is so central to UNIX and Linux, it was an early target for elaboration. The most common addition for support for access control lists (ACLs), a generalization of the traditional user/group/permission model that accommodates permissions for multiple users and groups at once.

ACLs are part of the filesystem implementation, so they have to be explicitly supported by whatever filesystem you are using. Fortunately, major UNIX and Linux filesystems now support them in one form or other.

ACL support generally comes in one of two: an early POSIX draft standard that never made its way to adoption but was widely implemented anyway, and the system standardized by NFSv4, which is based on Microsoft Windows ACLs. Both ACL standards are described in more detail in the filesystem chapter, starting on page 159.
