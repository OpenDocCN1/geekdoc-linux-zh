# Chapter 30 Cooperating with Windows

```
; Everybody can use the printers.
; guest ok = yes
; Let Samba know this share is a printer.
; printable = yes
; Show the printers to everyone looking.
; browseable = yes
; Tell samba what flavor of printing system the is using.
; printing = cups
```

See Chapter 26 for more information about printing.

Windows clients can now use these printers as network printers, as if they were hosted by a Samba server. This is one small problem, the Windows clients will know what kind of printer it is, and it will ask the user to select an appropriate printer driver. This leads to a lot of support requests from users who do not know how to proceed in this situation. If the particular printer in requires a driver that is not included, the situation becomes more support-intensive.

Fortunately, you can configure Samba to furnish the necessary Windows drivers to the Windows clients. To make this work, you must do some preparations. First, to make sure that Samba behaves like a printer server, add appropriate entries to the [global] section of the smb.conf file:

```
[global]
; Who is our printer admin
printer admin = printadam
; The following have the right value by default.
; disable spools = no
; Don't bother him; you cannot add printers anyway
show add printer wizard = no
; Assuming you want everybody to be able to print
guest ok = yes
browseable = no
```

Now Samba knows that it is a printer server, and it will accept the user printadam as its administrator.

If you are going to provide printer drivers for your Windows clients, there has to be a place to store the drivers. This is done through a special called [print$].

```
[print$]
comment = Printer Driver Area
; Place to store the printer drivers
path = /var/lib/samba/printers
browseable = yes
guest ok = yes
read only = no
; Who can administer the printer driver repository
write list = printadam
```
