## 25.4 X SERVER TROUBLESHOOTING AND DEBUGGING

Server configuration has come a long way over the last decade, but it can still be difficult to get things working the way you would like. You may need to experiment with monitor frequencies, driver options, proprietary drivers, and extensions for 3D rendering. Ironically, it is the times the display is not working correctly that you are most interested in seeing the debugging output on your screen. Fortunately, the X.Org server gives you all the information you need (and a lot that you don't) to track down the problem.

### Special keyboard combinations for X

Because the X server takes over your keyboard, display, mouse, and social life, you can imagine that it leaves you with little recourse to power the system if things are not working. However, there are a few things to try before it comes to that.

If you hold down the Control and Alt keys and press a function (F1–F6), the X server takes you to one of the text-based virtual terminals. From there you can log in and debug. To get back to the X server running on, virtual terminal 7, press <Alt-F7>. If you are on a network, you can also try logging from another computer to kill the X server before resorting to the reset button.

For virtual console support on Solaris, use the svc/system/vtdaemon:default solaris SM service and the console-login:vt[2-6] sequences.

If the monitor is not in sync with the card's video signal, try changing the screen resolution. The available resolutions are on Modes line from the Screen section of the configuration file. The exact Modes See sections on page 102 for details. The X server defaults to the first resolution shown on the active Modes line, but you can cycle through the different resolutions by holding down Control and Alt and pressing the plus (+) or minus (-) over the numeric keypad.

Pressing <Control Alt-Backspace> kills the X server immediately. If you run the server from a console, you will find yourself back where when the server exits. If a display manager started the server, it usually spawns a new server and prompts again for a login and password. You have to kill the display manager (xdm, gdm, etc.) from a console to stop it from respawning new servers.

- 8. The X server requires the <Control> key to be held down along with the <Alt-Fn> key combination to switch virtual terminals, but the text console does not.

### When X servers attack

Once you have regained control of the machine, you can begin to track down the problem. The simplest place to start is the output of X server. This is occasionally visible on virtual terminal 1 (<Control-Alt-F1>), where is startup output goes. Most often, the X server output goes to a log as `/var/log/XOrg.0.log` (/var/X11/Xserver/logs/Xf86.0.log on HP-UX).

As seen below, each line is preceded by a symbol that categorizes it. You can use these symbols to spot errors (EE) and warnings (WW), as well to notice how the server found each piece of information: from default settings (==), in a config file (*), detected automatically (--), or specified on the X server command (++)

Let's examine the following snippet from an Ubuntu system:

```
X X Server 1.6.0
Release Date: 2009-02-25
X Protocol Version 11, Revision 0
Building Operating System: Linux 2.6.24-23-server i86 Ubuntu
Current Operating System: Linux nutrient 2.6.28-11-generic #42-Ubuntu SMP
Fri Apr 07 17:51:59 UTC 2009 168
Build Date: 09 April 2009 02:10:02AM
xorg-server: 2.16.0-ubuntu14 (buildld@rothera.buildld)
Before reporting problems, check http://wiki.x.org
to make sure that you have the latest version.
Markers: (-), (*), (==) default setting,
(++) from command line. (!) notice,
(WW) warning error, (NI) not implemented, (??) unknown.
(-- Log file: `/var/log/XOrg.0.log`, Time: Sun May 10 22:11:47
(== Using config file: `/etc/X11/xorg.conf`
==) Layout="Main"
-->Screen "0" (0)
  |-->Monitor "Monitor 0"
  |-->Device "Console"
  |-->Input Device "Mouse0"
  |-->Input Device "Keyboard"
...
```

The first lines tell you the version number of the X server and the X11 protocol it implements. Subsequent lines tell you that the server is using default values for the log file location, the configuration file location, and the active server layer. The display and input devices from the config file are echoed in schematic format.

One common problem that shows up in the logs is difficulty with screen resolutions, usually evidenced by those resolutions not working or the X server bailing out with an error such as "Unable to validate any modes; falling back to the default mode.. If you have not specified a list of frequencies for your monitor, the X server probes for them using Extended Display Identification Data (EDID). If your monitor does not support EDID or if your monitor is turned off when X is started, you need to put the frequency ranges for X to use in the Monitor section of the configuration file.

Rounding error in the results obtained from an EDID probe can cause some resolutions to be unavailable even though they should be supported by both your video card and monitor. Log entries such as "No valid modes for 1280x1024; removing" are evidence of this. The solution is to tell the X server to ignore EDID information and use the frequencies you have specified; following the lines in the Device section are what you need:

- Option "IgnoreEDID "true"
- Option "UseEDIDFreqs "false"

As another example, suppose you forget to define the mouse section. The error would show up like this in the output:

```
=== Using config file: "/etc/X11/xorg.conf"
Data incomplete in file /etc/X11/xorg.conf
UndefinedInputDevice "Mouse" referenced by ServerLayout "MainLayout"
(EE) Problem parsing the config file
Fatal error:
no screens found
```

Once X is up and you have logged in, you can run the xdpyninfo command to get more information about the X server's configuration. xdpynfo output tells you the name of the display and the X server version. It also tells you the color depths that are available, the extensions that have been loaded, and the screens that have been defined, with their dimensions and color configurations.

xdpynfo output can be parsed by a script (such as ~/.xsession file) to determine the size of the active screen and to set up the desktop parameters appropriately. For debugging, xdpynfo is most useful for determining that the X server is up and listening to network queries, that it has configured the correct screen and resolution, and that it is operating at the desired color bit depth. If this step works, you are ready to start running X applications.

## 25.5 A BRIEF ON DESKTOP ENVIRONMENTS

The flexibility of the X Window System client/server model has, over the years, led to an explosion of widget sets, window managers, and programs. As applications became more advanced and demanded more support from the underlying system, it became clear that a comprehensive approach was required. From this need were born the two players in modern desktop environments: GNOME and KDE. Although some users have strong feelings regarding which is the True Way, both are relatively complete. In fact, just being in one realm does not mean you cannot use applications from the other; expect a different look and feel. The freesktop.org project is dedicated to creating an environment that will be compatible with any desktop.

### KDE

KDE, which stands for the K Desktop Environment, is written in C++ and on the Qt tool kit. It is often preferred by users who enjoy eye candy, as transparent windows, shadows, and animated characters. It looks nice, but it can be slow on anything a high-end workstation. For users who spend a lot of time clicking around the desktop rather than running applications, the tradeoff between efficiency and aesthetics may ultimately decide whether KDE is the appropriate choice.

KDE is often preferred by people transitioning from a Windows or Mac environment because of its graphics. It is also a favorite of technophiles who love to be able to fully customize their environment. For others, KDE is simply too much to deal with and GNOME is the simpler choice.

Applications written for KDE almost always contain a K somewhere in the name, for example, Konquer (the web/file browser),sole (the terminal emulator), or KWord (word processor). The default window manager, KWin, supports the freesktop.org Window Manager Specification standard, configurable skins changing the overall look and feel, and many other features. The KOffice application suite contains word processing, spreadsheet, and presentation utilities. KDE sports a comprehensive set of development tools, including an integrated development environment (IDE).

### GNOME

GNOME is written in C and is based on the GTK+ widget set. The name GNOME was originally an acronym for GNU Network Object Model Environment, but that derivation longer really applies; these days, GNOME is just a name.

With the recent addition of support for Compiz (compiz.org), GNOME has acquired many of the eye candy features that it previously lacked. Overall, GNOME is still less glitchy than KDE, is not as configurable, and is slightly less consistent. However, it is noticeably cleaner, faster, simpler, and more elegant. Most distributions use GNOME as the default desktop environment.
