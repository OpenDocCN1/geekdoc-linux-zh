# strace, truss, and tusc: trace signals and system calls

Although system calls occur at a relatively low level of abstraction, you can usually tell quite bit about a process's activity from the output. For example, the following log was produced by *strace* run against an active copy of top:

```
redhat3 sudo strace -p 5810
timeofday(1116193814,213881,300, 0) = 0
open("/proc/", O_RDONLY|NONBLOCK|O_LARGEFILE_DIRECTORY) = 7
stat64(7, mode=S_IFDIR055, st_size=0, ... ) = 0
fcntl64(7, F_SETFD, FD_CLOEXEC) = 0
dents64(7, "* 39 entries / 1") = 1016
dents64(7, "* 39 entries / 1") = 1016
stat64("/proc/1/stat", mode=S_IFDIR055, st_size=0, ... ) = 0
open("/proc/1/stat", O_RDONLY) = 8
read(8, "1 init S 0 0 0-1 41945670...") = 191
close(8) = 0
```

Not only does *strace* show you the name of every system call made by the process, but it also decodes the arguments and shows the result code kernel turns.

**strace** is packed with goodies, most of which are documented in the man page. For example, the *-f* flag follows for processes, which is useful for tracing demons as htop that spawn children. The *-e* option displays only file operations, a feature that is especially handy for discovering the location of evasive configuration files.

In this example, *top* starts by checking the current time. It then opens and starts the */proc* directory and reads the directory's contents, obtaining a list of running processes. Top then goes on to stat the directory representing the *init* process and then opens */proc/1/stat to read the *init* status information.

Here's an example (the date command) using **truss** on Solaris:

```
time$\ = 1242506760
brk(0x00024D30) = 0
brk(0x00026D30) = 0
open("/usr/lib/zone/info/US/Mountain", O_RDONLY) = 3
stat64(3, 0xFFBFFFA0) = 0
read(3, "T Z |\x00\x00\x00\x00\x00\x00\x87") = 877
close(3) = 0
ioctl(1, 0xFFBFFFA94) = 0
stat64(1, 0xFFBFFB90) = 0
write(1, " * Sat May 1 19..") = 29
Sat May 1 16:54:46 MDT 2009
_exit(0) = 0
```

Here, after allocating memory and opening library dependencies (not shown), **date** uses the **time** system call to read the system time, opens the appropriate zone file to determine the appropriate offset, and prints the date and timestamp by calling the **write** system call.
