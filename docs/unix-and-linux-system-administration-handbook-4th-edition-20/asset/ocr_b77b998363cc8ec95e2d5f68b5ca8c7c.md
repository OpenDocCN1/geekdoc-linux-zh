# The NET-SNMP tools

Even if your system comes with its own SNMP server, you may still want to compile and use the client-side tools from the NET-SNMP package. Table 21.3 lists the most commonly used tools.

# Table 21.3 Command-line tools in the NET-SNMP package

| Command | Function |
| --- | --- |
| snmpdelta | Monitors changes in SNMP variables over time |
| snmpdf | Monitors disk space on a remote host via SNMP |
| snmpget | Gets the value of an SNMP variable from an agent |
| snmpnext | Gets the next variable in sequence |
| snmpset | Sets an SNMP variable on an agent |
| snmtable | Gets a table of SNMP variables |
| snmptranslate | Searches for describes OIDs in the MIB hierarchy |
| snptrap | Generates a trap alert |
| snwalk | Traverses a MIB starting at a particular OID |

In addition to their value on the command line, these programs are tremendously handy in simple scripts. It is often helpful to have snmpget save interesting data values to a text file every few minutes. *Cron* to implement the scheduling; see Chapter 9, *Periodic Processes*.

snmpwalk is another useful tool. Starting at a specified OID (or the beginning of the MIB, by default), this command repeatedly makes "get next" calls to an agent. This behavior returns a complete list of OIDs and their associated values. snmpwalk is particularly handy when you are identifying new OIDs to monitor from your fancy enterprise management tool.

Here's a truncated sample snmpwalk of the host tu. The community string is "secret83community", and -v1 specifies simple authentication.

```
$ snmpwalk -c secret83community -v1 tuva
SNMPV2-sysDesc0 = STRING: tuva.astrust.2.6.9-11.Elsimp #1
SNMPV2-sysUpTime0 = Timeticks: (1442): 00:00:44
SNMPV2-sysName = STRING: tuva.astrust
MIB-IF:ifDesc1 = STRING: lo
MIB-IF:ifDesc2 = STRING: eth0
MIB-IF:ifDesc3 = STRING: eth
MIB-IF:ifType.1 = INTEGER: softwareLoopback(24)
MIB-IF:ifType.2 = INTEGER: ethernetCsmacd(6)

```
