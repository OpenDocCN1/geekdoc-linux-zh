# The SOA record

As we describe each type of resource record in detail in the next sections, we inspect some sample records from the atrust.com domain's data files. The default domain in this context is “atrust.com”, so a host specified as “bark” really means “bark.atrust.com.”

The format and interpretation of each type of resource record is specified by the IETF in the RFC series. In the upcoming sections, we list the specific RFCs relevant to each record (along with their years of origin) in a manner.

An SOA (Start of Authority) record marks the beginning of a zone, a group of resource records located at the same place within the DNS landscape. The data for a DNS domain usually includes at least two zones: for translating names to IP addresses, the forward zone, and others that map IP addresses back to hostnames, reverse reverses.

Each zone has exactly one SOA record. The SOA record includes the name of the zone, the primary name server for the zone, the technical contact, and various timeouts. Comments are introduced by a semicolon. Here is an example:

```
; Start of authority record for atrust.com
atrust.com IN SOA ns1.atrust.com hostmaster.atrust.com.
2009070200 ; Serial number
10800 ; Refresh (3 hours)
1200 ; Retry (20 minutes)
360000 ; Expire (40 days)
3600 ; Minimum (1 hour)
```

The name of the SOA record (atrust.com, in this example) often contains the symbol @, which is shorthand for the name of the current zone. The value of @ is the domain name specified in the zone statement of named.com or in the zone entry in the nsdf.file. This value can be changed from the zone file with $ORIGIN parser directive (see page 596).

This example has no ttl field. The class is IN for Internet, the type is SOA, and the remaining items field data. The numerical parameters in parentheses are values values are often written on one line without comments.

ns1.atrust.com.” is the zone’s master name server.

hostmaster.atrust.com.” is the email address of the technical contact in the format “user.host.” rather than the standard user@host. Replace that with dot if you need to send mail to a domain’s administrator or use an alias as host master of an actual zone name. The sysadmin responsible for host duties may change, and it’s easier to change one entry in the aliases file (see page 756) to change all your zone files when you need to update the contact person.

+   11. Any name server for the SOA record can be listed unless you are using dynamic DNS. In that case, the SOA record must name the master server.
