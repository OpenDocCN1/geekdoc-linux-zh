# Chapter 10 Backups

# Monitoring Bacula configurations

System administration requires vigilance, and backups are the last place to be making an exception. Backups will fail, and if not fixed quickly, critical data will surely be lost.

Bacula jobs produce a job report that is routed according to the job's Message resource in the director daemon's configuration file. The report includes information about the volumes used, the number and size of files backed up, and any errors that may have occurred. The report usually gives enough information to troubleshoot any minor problems. We recommend that you configure messages to go to your email inbox, or perhaps even to your pager.

You can use the console's status command to query the various Bacula daemons for information. The output includes information about upcoming jobs, currently running jobs, and jobs that were terminated. the messages command is an easy way to review log entries.

Bacula includes a contributed Nagios plug-in, which makes it easy to integrate backups into your existing monitoring infrastructure. See page 887 for general information about Nagios.

# Bacula tips and tricks

Two issues come up frequently are file daemons that are not running and storage daemons that cannot find any appendable volumes. In the example below, the director daemon reports a backup job terminated with a fatal error because it could not communicate with the file daemon on host harp. This error can be repeated at the end of the summary report.

```
SD termination status: Waiting on FD
*** Backup Error ***
```

```
11-Nov 21:06 bull-dir Jobid 259: Warning: bock:c:123 Could not connect to
Client: harp on 192.168.1:9102. ERR=Connection refused Retrying *
11-Nov 21:31 bull-dir Jobid 259: Warning: bock:c:123 Could not connect to
Client: harp on 192.168.1:9102. ERR=Connection refused
```

The example shows the storage daemon reporting that no tape volumes from the appropriate pool are available to perform a requested backup. You can fix the problem either by adding a new volume to the pool or purging and recycling an existing volume. There is no need to restart the job; Bacula continue to execute it until you call it explicitly.

```
06-May 23 bull-sd Jobid 1545: Job Southern.2009-05-06_19.03.00.07 waiting. Cannot find any appendable volumes.
Please use the "Label" command to create a new volume for:
```

```
Storage: "TL4000-Drive0" (/dev/nst0)
Pool: Full_Pool
Media type: LTO-3
```
