# The options statement

describes each option and shows syntax and default values. The file doc/misc/options also contains a complete list of options.

As we wind way about a quarter of the possible options, we have added a margin note as a mini index entry. The default values are in square brackets each option. For most sites, the default values are just fine. Options are listed in no particular order.

File locations

+   directory "path"; [directory where the server was started]
key-directory "path"; [same as directory entry]

The directory statement causes named cd to the specified directory. Wherever relative pathname are in named's relative to this directory. The path should be an absolute path. Output files (debugging, statistics, etc.) are also written in this directory. The key-directory where cryptographic keys are stored; it should not be-readable.

We like to put all BIND-related configuration files (other than named.conf and resolv.conf) in a subdirectly /var (or wherever your configuration files for other programs). We use /var/named or /var/domain.

Name server identifier

+   version "string"; [real version of the server]
hostname "string"; [real hostname of the server]
server-id "string"; [none]

The version string identifies the version of the name server software running on the server. The hostname string identifies the server itself, as the server-id string. These options let you lie about the values. Each of them puts data into CHAOS-TXT records where curious onlookers can search for them with the dig command.

We discourage tampering with these values. It is very hard to query your name servers and find out what version they are running, if you want to know which vendor is signing a current release, or if you need to verify that you have upgraded all of your servers to the latest version. If you must hide the version number, at least one string that communicates version information to your sysadmins isn't obviously so. (The NSID resource record does exactly this. The data portion of this TXT-ish record is a string value that your sysadmins have meaning to but not the rest of the world).

The hostname and server-id parameters are recent additions motivated by the use of anycast routing duplicate instances of the root and gTLD servers.

Zone synchronization

+   notify yes master-only | explicit | no; [yes]
also-notify-servers;ipaddresses [empty]
allow-notify address-match-list; [empty]

The notify and also-notify clauses apply only to master servers, and allow-notify applies only to slave servers.
