# gated: first-generation multiprotocol routing daemon

gated is an elegantly designed and once-freely-available routing framework that allows the simultaneous use of multiple routing protocols. It gives administrators precise control over advertised routes, broadcast addresses, trust policies, and metrics gated shares routes among several protocols, allowing routing gateways to be constructed between areas that have standardized over different routing systems. It also has one of the nicest administrative interfaces and configuration file designs of any administrative software.

Alas, gated is dead (or at least, dead-ish), though its memory lives in slow-to-change releases as HP-UX and AIX, which bundle versions 3.5.9 and 6.0, respectively.

gated is an object lesson in the perils of attempting to compete with open source software. It started out as freely distributable software, but in 1992 it was privatized and turned over to a development consortium; updates only to members of the consortium. The consortium was eventually disbanded, and the rights to the commercial version of gated changed several times. Meanwhile, the open source Zebra and Quagga projects took over gated role as the mainstream open source routing package. These days, gated is extinct both as a commercial product and as an open source project, a sad end to a useful and well-designed package.

# Quagga: mainstream routing daemon

Quagga (quagga.net) is a development fork of Zebra, a GNU project started by Kunihiro Ishiro and Yoshinari Ishikawa to implement multiprotocol routing with a collection of independent daemons instead of a monolithic application. In real, the quagga—a subspecies of zebra last photographed in 1870—is extinct, in the digital realm it is Quagga that survives and Zebra is no longer under active development.

Quagga implements RIP (all versions), OSPF (versions 2 and 3), BGP, and IS-IS. It runs on Linux, Solaris, and various flavors of BSD. On Solaris and our example Linux systems, Quagga is either installed by default or available as an optional package through the system's standard software repository.

In the Quagga system, the zebra daemon acts as a central clearing-house for routing information. It manages the interaction between the kernel's routing table and the daemons for individual routing protocols (rippgd, ospfd, bgpd, and isis). It also controls the flow of routing information among protocols. Each daemon has its own configuration file in the /etc/quagga directory.
