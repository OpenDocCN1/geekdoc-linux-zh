+   Installing a Windows-style MBR makes the disk incomprehensible to Windows, even if the contents of the individual partitions are not. If you want to operate with Windows (say, by dual booting), you'll need to install a Windows MBR. But even if you have no partitions along those lines, it may be helpful to consider the ubiquity of Windows and the likelihood that your disk will one day come in contact with it.
Current versions of Windows are well behaved and will never dream of writing normally to a disk they can't decipher. However, they will certainly suggest this course of action to any administrator who logs in. The dialog box serves a helpful "OK, mess up this disk! Nothing bad will happen unless someone makes a mistake, but safety is a structural and organizational process.

+   Partitions have a defined location on the disk, and they guarantee locality. Logical volumes do not (at least, not default). In most cases, this isn't terribly important. However, short seeks are faster than seeks, and the throughput of a disk's outer cylinders containing the lowest-numbered blocks) can exceed the throughput of its inner cylinders by 30% or more. For situations in which every performance counts, you can use partitioning to gain an extra edge. (You can use logical volume management inside partitions to regain some of the lost flexibility.)

+   RAID systems (page 237) use disks or partitions of matched size. Given RAID implementation may accept entities of different sizes, but it will probably use only the block ranges that all devices have common. Rather than letting extra space go to waste, you can isolate it in a separate partition. If you do this, however, you should use the separate partition for data that is frequently accessed; otherwise, use of the partition will degrade the performance of the RAID array.

# Windows-style partitioning

The Windows MBR occupies a single 512-byte disk block, of which is consumed by boot code. Only space remains to define partitions. These are termed "primary" partitions because they are defined in the MBR.

You can define one of the primary partitions to be an "extended" partition, which means that it contains its subsidiary partition table. The extended partition is a true partition, and it defines a physical extent on the disk. The subsidiary partition is stored at the beginning of that partition's data.
