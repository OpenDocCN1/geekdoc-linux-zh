
You should do a complete set of level 0 dumps immediately after an upgrade, too. Most vendors' upgrade procedures set the modification dates of system files to the time when they were mastered rather than to the current time. Ergo, incremental dumps made to the pre-upgrade level 0 are not sufficient to restore your system to its post-upgrade state in the event of a crash.

## 10.6 USING OTHER ARCHIVING PROGRAMS

dump is not the only program you can use to archive files to tapes; however, it is the most efficient way to back up an entire system. tar and dd can also move files from one medium to another.

### tar: package files

tar reads multiple files or directories and packages them into one file, often a tape device. tar is a useful way to back up any files whose near-term recovery you anticipate. For instance, if you have a bunch of old files and the system is short of disk space, you can use tar to put the files on a tape and remove them from the disk.

tar is also useful for moving directory trees from place to place, especially if you are copying files as tar. tar preserves ownership and time information, but if you ask it to. For example,

```
sudo tar -cf - fromdir | cd codir ; sudo tar -xpf -
```

creates a copy of the directory fromdir in codir. Avoid using .. in the codir argument since symbolic links and automounters can make it mean something different from what you expect. We've been bitten several times.

Most versions of tar do not follow symbolic links by default

Another problem with non-GNU versions of tar is that parameters are limited by default to 100 characters. This restriction prevents tar from archiving deep hierarchies. If you're creating archives on your Linux systems and exchanging with them, remember that the people with the standard tar may not be able to read the tapes or files you create.¹12

tar -b option lets you specify a "blocking factor" to use when writing a tape. The blocking factor is specified in 512-byte blocks; it determines how much data tar buffers internally before performing a write operation.

> 12. The GNU implementation creates a filename mapping table as one of the files in the archive. Users of the standard tar can extract the contents of the archive and fix it up by hand, but the process is tedious.

On some systems, certain blocking factors may yield better performance than others. The optimal blocking factor varies widely, depending on the computer and tape drive hardware. In many cases, you will not notice any difference in speed. In doubt, try a blocking factor of 20.

tar expands holes in files and is intolerant of tape errors.¹¹³

### dd: twiddle bits

dd is a file copying and conversion program. Unless you tell it to do some sort of conversion, dd just copies from its input file to its output file. If a user brings a tape that was written on a non-UNIX system, dd may be the only way to read it.

One historical use for dd was to create a copy of an entire filesystem. However, a better option these days is mkfs the destination filesystem and then run dump to restore. dd can sometimes clobber partitioning information if used incorrectly. It can only copy file systems between partitions of the exact same size.

You can also use dd to make a copy of a magnetic tape. With two tape drives, say, /dev/st0 and /dev/st1, you'd use the command

```
$ dd=/dev/st0 of=/dev/st1 cbs=16b
```

With one drive (/dev/st0), you'd use the following sequence:

```
$ dd=/dev/st0 of=file cbs=16b
/* Change types. /
$ dd=file of=/dev/st0 cbs=16b
$ rm tape
```

Of course, if you have only one drive, you will not have enough disk space to store an image of the entire tape.

dd is also a popular tool among forensic specialists. Because it creates a bit-for-bit, unadulterated copy of a volume, dd can be used to duplicate electronic evidence in court.

### ZFS backups

Solaris incorporates the features of a logical volume manager and RAID controller as well as a filesystem. It is in many ways a system administrator's dream, but backup is something of a mixed bag.

ZFS makes it easy and efficient to create filesystem snapshots. Past versions of a filesystem are available through the zfs directory in the filesystem's root, so users can easily restore their own files from past snapshots without administrator intervention. From the perspective of on-line version control, ZFS gets a gold star.

See page 264 for a more general introduction to ZFS.

GNU's tar handles holes intelligently if you invoke the -s option when creating an archive.

### Using multiple files on a single tape

However, snapshots stored on the same media as the active shouldn't be your only backup strategy. ZFS knows this, too: it has a very nice zfs facility that summarizes a filesystem snapshot to a linear stream. You can save the stream to a file or it to a remote system. You can write the stream to a tape. You can even send the stream to a remote zfs receive process to replicate the filesystem elsewhere (optionally, with all its history and snapshots). If you like, zfs can serialize only the incremental changes between two snapshots. Gold stars: one for the feature, and one for the fact that the documentation is a page or two (see main page for zfs).

The fly in the ointment is that zfs receive deals only with complete filesystems. To restore a few files from a set of serialized zfs images, you must restore the entire filesystem and pick the files out you want. Let's hope you've got plenty of time and free disk space and that the drive isn't needed for other backups.

In fairness, several arguments help excuse this state of affairs. ZFS filesystems are lightweight, so you're encouraged to create many of them. Restoring all of home might be traumatic, but restoring all of /home/ned is likely to be.¹ More importantly, ZFS's on-line snapshot eliminates 95% of the cases in which you would normally need to refer to a backup tape.

On-line snapshots don't replace backup tapes or reduce the frequency with which those tapes must be written. However, snapshots reduce the frequency at which tapes must be backed.

## 10.7 USING MULTIPLE FILES ON A SINGLE TAPE

A magnetic tape contains one long string of data. However, it's often useful to store more than one "thing" on a tape, tape drives and their drivers conspire to afford a bit structure. When dump or some other command writes a stream of bytes out, the tape drive records the position. The mt utility is the standard way to interact with the drive.

rew rewinds the tape to the beginning.

off puts the tape off-line.

status prints information about the current state of the tape (whether a tape is loaded, etc.).

fsf [count] fast-forwards the tape. If no count is specified, fsf skips forward one file. With a numeric argument, it skips the number of files.

bsf [count] should backup count files. The exact behavior depends on the tape drive hardware and its associated driver. In some situations, the current file is counted. In others, it is not. On some equipment, bsf does nothing, silently. If you go too far forward on a tape, your best bet is to run mt rew on it and start again from the beginning.

Consult the mt page for a list of all the commands.

If you're fortunate enough to have a robotic tape library, you may be able to control its tape changer by installing the mtx package, an enhanced version of mt. For example, we use it for unattended tape swapping with your groovy PowerVault LTO-3 tape cartridge system. Tape changers with barcode readers will even display the scanned tape labels through the mtx interface. Look ma, no hands!

## 10.8 BACULA

Bacula is an enterprise-level client/server backup solution that manages backups, recovery, and verification of files over a network. The Bacula server components run on Linux, Solaris, and FreeBSD. The Bacula client backs up data from many platforms, including all our example operating systems and Microsoft Windows.

In previous editions of this book, Amanda was our favorite noncommercial backup tool. If you need Amanda information, please see a previous edition of this book or amanda.

The feature list explains why Bacula is our favorite.

* It has a modular design.
* It backs up UNIX, Linux, Windows, and Mac OS systems.
* It supports MySQL, PostgreSQL, or SQLite for its back-end database.
* It supports an easy-to-use, menu-driven command-line console.
* It's available under an open source license.
* Its backups can span multiple tape volumes.
* Its servers can run on multiple platforms.
