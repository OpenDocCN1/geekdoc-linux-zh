# Chapter 15 Routing

This is really a elegant idea. If it worked as advertised, routing would be relatively simple. Unfortunately, the basic algorithm does not deal well with topology. In some cases, infinite loops (e.g., router X receives information from router Y and sends it to router Z, which sends it back to router Y) prevent routes from converging at all. Real-world distance-vector protocols avoid such problems by introducing complex heuristics or by enforcing arbitrary restrictions such as the RIP (Routing Information Protocol) notion that more than 15 hops away is unreachable.

Even in nonpathological cases, it can take many update cycles for all routers to reach a steady state. Therefore, to guarantee that routing will not jam for an extended period, the cycle time must be short, and for this distance vector protocols as a class tend to be talkative. For example, RIP requires its routers to broadcast all routing information every 30 seconds. EIGP updates every 90 seconds.

On the other hand, BGP, the Border Gateway Protocol, transmits the entire table once and then changes as they occur. This optimization substantially reduces the potential for "chatty" (and most unnecessary) traffic.

# Link-state protocols

Link-state protocols distribute information in a relatively unprocessed process. The records traced among routers are of the form "Router X is adjacent to router Y, and the link is up." A complete set of records forms a connectivity map of the network from which each router can compute its own routing table. The primary advantage of link-state protocols offer over distance-vector protocols is the ability to quickly converge on an operational routing solution after a catastrophe occurs. The tradeoff is that maintaining a complete map of the network at each node requires memory and CPU power that would not be needed by a distance-vector routing system.
