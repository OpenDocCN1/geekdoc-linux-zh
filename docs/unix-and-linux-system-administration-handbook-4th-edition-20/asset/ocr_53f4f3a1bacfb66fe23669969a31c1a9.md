# Filesystem power savings

In practice, the opportunity to idle parts of the CPU only arises when the system isn't busy. In those circumstances, the additional overhead of packing threads onto one core may have detectable effect. Experiment to see if you can discern any difference with your specific workload.

The process scheduler's power management system controls two variables, both of which are set through files in the /sys/devices/system/cpu directory. The sched_mc_power_savings variables control which cores on a CPU are used before activating another CPU, and the sched_smt_power_savings variables control which thread slots on a core are used before activating another core. In both, a value of 0 turns power saving off and 1 turns on.

For example, to turn on power-saving modes, you could use the commands

```
$ sh -c 'echo 1 /sys/devices/system/cpu/sched_mc_power_savings'
$ sh -c 'echo 1 /sys/devices/system/cpu/sched_smt_power_savings'
```

To make these changes persistent across reboots, you could use the systemctl command or add the lines to a startup script as /etc/init.d/local on Ubuntu or Server (if it necessary) and /etc/rc.local on Red Hat.

A computer's CPU is one of its most proffered consumers of energy (just look how heat sinks!), aggressive power management can significantly reduce the system's power use.

# Filesystem power savings

You can save power and increase performance from filesystems by maintaining a "last access" time (st_atime) for every file. This information is not very useful, and it theoretically adds a tax of one seek and one write to every file operation. The real-world impact is hard to quantify because of beach locking.

Zedlewski analyzed disk power consumption in a 2003 paper and found that seeks cost about 4 millij on an IBM Microdrive; the cost is probably at least double that for a standard drive with its large armature. Combining the cost of seeks with the cost of writes, we calculate the benefit of disabling last access time to be up to several kWh per drive. Not a huge savings, but probably worthwhile for the performance alone; the energy savings are quite gravy.

On most systems, you can turn off maintenance of the last access time with the noatime option to mount:

```
$ sudo mount -o remount,noatime /
```

Some Linux systems also support the relative mount option. Under this option, last access time is only updated if the previous value is earlier than the file's modification time. This mode allows tools such as mail readers to correctly identify cases in which an interesting file has been changed but not yet read.
