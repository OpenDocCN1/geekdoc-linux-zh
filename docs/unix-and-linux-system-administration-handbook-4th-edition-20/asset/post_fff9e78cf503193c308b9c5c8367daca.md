Many of the variables with rate and max in their names are used to thwart default service attacks. The conf subdirectory variables are set per interface. It contains subdirectories for all default and a subdirectory for each interface (including the loopback). Each subdirectory contains the same set of files.

```bash
$ubuntu$ cd conf/default; ls -F
accept_redirect disable_policy promote_secondaries
accept_source_route disabled_xmrf proxy_arp
arp_accept force_igmp_version rp_file
arp_announce forwarding secure_retries arp_filter log_martians send_retries
arp_ignore mc_forwarding shared_media
boot_relay medium_id tag
```

If you change a variable in the conf/eth0 subdirectory, your example applies to that interface only. If you change the conf/all directory, you might expect it to see the corresponding value for all existing interfaces, but this is not in fact what happens. Each variable has its own rules for replacing changes all. Some values are ORed with the current values, are ANDed and others are MAXed or MINed. As far as we are aware, there is no documentation for this process outside of the kernel source, so the whole default is probably best. Just justify your modifications to individual interfaces.

If you change a variable in the conf/default directory, the new value propagates to all interfaces that are later configured. On the other hand, it's nice to keep the defaults unreferenced as information; they make a nice sanity check if you want to undo others.

The /proc/sys/ipv4/ directory also contains a subdirectory for each interface. The files in each subdirectory control ARP table management and IPv6 neighbor discovery for that interface. Here is the list of the ones with gc (garbage collection) determine how ARP entries are timed out and discarded.

To see the value of a variable, use cat; to set it, use echo redirected to the proper filename. For example, the command

```bash
ubuntu$ cat icmp_echo_ignore_broadcasts
0
```

shows that this variable's value is 0, meaning broadcast prints are not ignored. To set it to 1 (avoid failing pre-retry to Smurf-type denial of service attacks), run

```bash
ubuntu$ sudo sh -c "echo 1 > icmp_echo_ignore_broadcasts"
```

from the /proc/sys/net directory.

You are typically logged in over the same network you are tweaking as you adjust these variables, so be careful! You can mess things badly enough to require a reboot from the console to recover, which might be inconvenient if the system happens to be in Point Barrow, Alaska, and it's January. Test-tune these variables on your desktop system before even thinking of tweaking a production machine.

To change any of these parameters permanently (or more accurately, reset them every time the system boots), add the appropriate variables to /sysctl. The format of the sysctl file is variable rather than echo value > variable as you would run from the shell to change the variable by hand. Variable names are pathnames relative to /proc/sys/, you can also use dots instead of slashes if you prefer. For example, any of the lines

```
net.ipv4.forward=0
net/ipv4/ip_forward=0
```

in the /etc/sysctl.conf file will turn off IP forwarding on this host.

## Linux NAT and filtering

Linux traditionally implements a limited form of Address Translation (NAT), also called Port Address Translation (PAT). In earlier versions of Linux, this was not possible, but modern kernels support it. The features of NAT are covered in more detail.

To make NAT work, you must enable connection-tracking modules. The kernel modules are:

```bash
ubuntu$ modprobe ip_conntrack
ubuntu$ modprobe ip_nat
ubuntu$ modprobe ipt_tables
ubuntu$ modprobe iptable_filter_conntrack
```

## Solaris basic network configuration

Solaris stashes some network configuration files in /etc and some in /etc/inet. Many are duplicated through the magic of symbolic links, with the actual files living in /etc/inet and the links in /etc. To set the hostname, enter it into the file /etc/nodename. The change will take effect when the machine is rebooted. Some use just the short hostname; others use the fully qualified domain name.

The /etc/defaultdomain file's name suggests that it might be used to specify the DNS domain, but it identifies the NIS or NIS+ domain name. The DNS domain is specified in /etc/resolv.conf as usual.

Solaris uses /etc/nsswitch.conf to set the order in which /etc/hosts, NIS, NIS+, DNS are configured for hostname resolution. We recommend looking at the hosts file, for easy booting. The line from nsswitch.conf could be

```
hosts: dns
```

This is the default configuration if the host receives the addresses of its DNS server through DHCP.

Solaris networking can run in traditional mode or in "Network Auto-Magic" (NWAM), where networking is managed by the nwamd daemon. NWAM mode is fine for workstations, but it has limited configuration and allows only one network interface to be active at a time. The discussion below assumes traditional mode.
