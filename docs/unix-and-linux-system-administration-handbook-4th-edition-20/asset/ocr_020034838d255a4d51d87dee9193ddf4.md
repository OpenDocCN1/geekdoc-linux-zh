# Mail queues

sendmail uses two queues: /var/spool/mqueue when acting as an MTA on port 25, and /var/spool/clientmqueue when acting as an MSA on port 587. All messages make at least a brief stop in the queue before being sent on their way.
A queued message is saved in pieces in several different files. A filename has a two-letter prefix identifies the queue, followed by a random ID built from sendmail's process ID. Table 20.7 shows the six possible pieces.

# Table 20.7 Prefixes for files in the mail queue

| Prefix | File contents |
| --- | --- |
| qf | The message header and content file |
| df | The body of the message |
| tf | A temporary version of the qf file is being updated |
| Tf | Signifies that 32 or more failed locking attempts have occurred |
| Qf | Signifies that the message bounded and could not be returned |
| xf | Temporary transcript file of errors from mailers |

Subdirectories qf, df, or xf exist in a queue directory, then those pieces of the message are put in the proper subdirectory. The qf file contains not only the header but also the envelope addresses, the date at which the message should be returned as undeliverable, the message's priority in the queue, and the reason the message is in the queue. Each line begins with a single-letter code that identifies the rest of the line.

Each message that is queued must have a qf and df file. All the other prefixes are used by sendmail during delivery. When a machine crashes and reboots, the startup sequence for sendmail should delete the tf, xf, and Tf files from each queue. The sysadmin responsible for mail should check occasionally for Qf files in local configuration is causing the bounces. At one glance of the queue directories lets you spot problems before they become disasters.

The mail queue opens several opportunities for things to go wrong. For example, the filesystem can fill up (putting /var/spool/mqueue and /var/log on the same partition), the queue can become clogged, or orphaned mail messages can get stuck in the queue. sendmail has configuration options to help with performance on very busy machines; we have collected these in the performance section starting on page 802.

# 20.9 SENDMAIL CONFIGURATION

sendmail's actions are controlled by a single configuration file, typically called /etc/mail/sendmail.cf for a sendmail running as an MTA or /etc/mail/submit.cf
