Chapter 6 The Filesystem

# 6.1 PATHNAMES

The filesystem is presented as a single unified hierarchy that starts at the directory / and continues downward through an arbitrary number of subdirectories. / is also called the root directory. This single-hierarchy system differs from the one used by Windows, which retains the concept of partition-specific namespaces.

# Absolute and relative paths

The list of directories that must be traversed to locate a particular file plus file's filename forms a pathname. Pathnames can be either (/tmp/foo) or relative (book4/filesystem). Relative paths are interpreted starting from the current directory. You might be accustomed to thinking of the current directory as a feature of the shell, but every process has one. (Most processes never change their working directory, so they simply inherit the current directory of the process that started them).

The terms filename, pathname, and path are more or less interchangeable—at least, we use them interchangeably in this book. Filename and path can be used for both absolute and relative paths; pathname usually suggests an absolute path.

The filesystem can be arbitrarily deep. However, each component of a pathname (that is, each directory) must have a name no more than 255 characters. There's also a limit on the path length you can pass into the kernel as a system argument (4,095 bytes on Linux, 1,023 bytes on older systems). To access a file with a pathname longer than this, you must cd to an intermediate directory and use a relative pathname.

# Spaces in filenames

The naming of files and directories is essentially unrestricted, except that names are limited in length and must not contain slash characters or nulls. In particular, spaces are permitted. Unfortunately, UNIX has a long tradition of separating command-line arguments at whitespace, so legacy software tends to break when spaces appear within filenames.

Spaces in filenames were once found primarily on filesystems with Macs and PCs, but they have now metastasized into UNIX culture and are found in some standard software packages well. There are no two ways out of: administrative scripts must be prepared to deal with spaces in filenames (not mentioning apostrophes, asterisks, and other menacing punctuation marks).

In the shell and in scripts, careful filenames can be quoted to keep their pieces together. For example, the command

```
$ My excellent file.txt
```

preserves My excellent file.txt as a single argument to less. You can also escape spaces with a backslash. The filename completion feature of the shells (usually bound to the <Tab> key) does this for you.
