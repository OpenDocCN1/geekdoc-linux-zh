To test your TSIG configuration, run named-checkconf to verify that you have the syntax right. Then use dig to attempt a zone transfer dig @master axfr from both slave1 and from some other machine. The first should succeed and the second fail with the diagnostic "Transfer failed." To be absolutely sure, remove the allow-transfer clause and try the dig commands again. This time, both should succeed. (Don't forget to put the allow-transfer back in!) As a final test, increase the serial number for the zone on the master server, rndc reload, and watch the log file of the slave to see if it picks up the changes and transfers the zone.

When you start using transaction signatures, run named at debug level 1 (see page 267 for information about debug mode) for a while to see any error messages that are generated. Ancient versions of BIND do not understand signed messages and complain about them, sometimes to the point of refusing to load the zone.

When using TSIG keys and transaction signatures between master and slave servers, you should keep the clocks of the servers synchronized with NTP. If the clocks are too far apart (by more than 5 minutes), signature verification will not work. This problem can be very hard to identify.

TKEY is a BIND mechanism that hosts a shared-secret key automatically, without phone calls or secret copies to distribute the key. It uses an algorithm called the Diffie-Hellman key exchange in which each side makes up a random number, does some math on it, and sends the result to the other side. Each side then mathematically combines its own number with the transmission to receive to arrive at the same key. An eavesdropper might overhear the transmission but will be unable to reverse the math.27

Microsoft servers use TSIG in a nonstandard called GSS-TSIG that exchanges the shared secret through TKEY. If you need a Microsoft server to communicate with BIND, use the tkey-domain and tkey-ssapi-credentials options.

SIG(0) is another mechanism for signing transactions between servers or between dynamic updates and the master server. It uses public key cryptography; see RFCs 2535 and 2931 for details.

# TSIG in NSD

You can use the ldns-keygen command in the examples directory of the ldns distribution to generate TSIG keys for NSD. For details, see page 655. NSD does not support SIG(0) keys or the TKEY Diffie-Hellman key exchange system.
