# Zone signing

These public keys must be INCLUDED or inserted into the zone file, either at the end or right after the SOA record. To copy the keys into the zone file, you can append them with cat<sup>32</sup> or paste them in with a text editor.

The .ds files produced by NSD’s key generator, ldns-keygen, contain DS records; the one that corresponds to the KSK would be stored in the parent zone if DNSSEC is fully deployed. The DS record can be generated from the KSK’s DNS-KEY resource record, and some zones sign either instead of or in addition to the KSK’s DNSKEY record, and is what DS records look like:

```
example.com.      3600 IN DS 23301 1 5bd84410d8fea31b3bc2f213e...
example.com.      3600 IN DS 00682 1 01df0f88616633ff822732509...
```

Ideally, the private key portion of any key pair would be kept-off, or at least a machine that is not on the public Internet. This precaution is impossible for dynamically updated zones and for-signing keys, but it is perfectly reasonable for key-signing keys, which are presumably quite-lived. Consider a hidden master server that is not accessible for outside of the ZKS. Print out the private KSK or write it to a USB memory stick and lock it in until you need it again.

While you’re locking away your private keys, it’s also good to enter the keys into your key log file. You don’t need to include the keys themselves, just the IDs, algorithms, date, and so on.

The default signature validity periods are one month for RRSIG records (ZSK signatures of resource record sets) and three months for DNSKEY records (KSK signatures of ZSKs). Current practice suggests ZKSs of 1,024 are used for three months to a year and KKSs of 1,280 are used for a year or two.<sup>33</sup> The recommended key retention periods are longer than the default signature validity periods, which you must either specify a longer validity when signing zones or periodically re-sign the zones, even if it has not changed.

Now that you’ve got keys, you can sign your zones with the dnssec-signzone (BIND) or ldns-signzone (NSD) commands, which add RRSIG and N or NSEC3 records for each resource record set. These commands will read your original file and produce a signed copy named zonefile.signed.

The BIND syntax is

```
dnssec-signzone [-o zonename] [-N increment] [-k KSKfile] zonefile [KSKfile]
```

where zonename defaults to zonefile and the key defaults to the filenames produced by dnssec-keygen as outlined above.
