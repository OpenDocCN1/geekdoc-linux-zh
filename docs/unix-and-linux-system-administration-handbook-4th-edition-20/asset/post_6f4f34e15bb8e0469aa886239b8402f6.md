
# Red Hat network configuration

Table 14.7 SUSE network configuration files in /etc/sysconfig/network

| File | What's set here |
| --- | --- |
| ifcfg-interface | Hostname, IP address, netmask, and more |
| ifroute-interface | Interface-specific route definitions |
| routes | Default route and static routes for all interfaces |
| config | Lots of less commonly used network variables |

With the exceptions of DNS parameters and the system hostname, SUSE sets most networking options in ifcfg-interface files in the /etc/sysconfig/network directory. One file should be present for each interface on the system.

In addition specifying the IP address, gateway, and broadcast information for an interface, the ifcfg-* file can tune many network details. Take a look at the ifcfg.template for a well-commented rundown of the possible parameters. Here is a simple example with:

```
PROTO='static' # Static is implied but it doesn't hurt to be verbose.
IPADDR='192.168.1.24' # The /24 defines the NETWORK and NETMASK VAR
NAME='AMD PCnet - Fast 79C91' # Used to start and stop the interface.
STARTMODE='auto' # Start at boot
USERCONTROL='no' # Disable control through internet/netminer GUI
```

Global static routing information for a SUSE system (including the default route) is stored in the routes files. Each line in this file is like a route command with the option names omitted and includes stored in the routing table for use by routing daemons. Extra parameters to be stored in the routing table for use by the host configured above, which has only a default route, the routes file contains the line

```
default 192.168.1.254 -
```

Routes to specific interfaces are kept in ifroute-interface files, where the nomenclature of the interface component is the same as for the ifcfg-* files. The contents have the same format as the routes file.

**Table 14.8 Red Hat network configuration files in /etc/sysconfig**

| File | What's set here |
|---|---|
| network static-routes | Hostname, default route Static routes |
| network-scripts/ifcfg-ifname | Per-interface parameters: IP address, netmask, etc. |

For example, here is a **network file** for a host with a single Ethernet interface:

```
NETWORKING=yes
NETWORKING_IPV6=no
HOSTNAME=redhat.toadranch
DOMAINNAME=toadranch ### optional
WAY=192.168.1.254
```

Interface-specific data is stored in /etc/sysconfig/network-scripts/ifcfg-ifname, where *ifname* is the name of the network interface. These configuration files set the IP address, netmask, and broadcast address for each interface. They also include a line that specifies whether the interface should be configured “up” at boot time.

A generic name has files for an Ethernet interface (eth0) and for the loopback interface (lo). For example,

```
DEVICE=eth0
ADDR=192.168.1.13
NETMASK=255.255.255.0
NETWORK=192.168.1.0
BROADCAST=192.168.1.255
ONBOOT=yes
```

and

```
DEVICE=lo
ADDR=127.0.0.1
NETMASK=255.0.0.0
NETWORK=127.0.0.0
BROADCAST=127.255.255
ONBOOT=yes
NAME=loopback
```

are the **ifcfg-eth0** and **ifcfg-lo** for the machine redhat.toadranch described above. A DHCP-based setup for eth0 is even simpler:

```
DEVICE=eth0
BOOTPROTO=dhcp
ONBOOT=yes
```

After changing configuration information in /etc/sysconfig, run *ifdown ifname* followed by *ifup ifname* for the appropriate interface. If you reconfigure interfaces at once, you can use the command *service network restart* to reset all (This is really just a shorthand to run /etc/rc.d/network, which is invoked at boot time.) The startup scripts can also configure static routes. Any routes added to the file /etc/sysconfig/static-routes are entered into the routing table at boot time. The entries specify route add, although in a different order:

```
eth0 130.225.0.0 netmask 255.255.255.0 gw 130.225.0.1
eth1 192.168.8.0 netmask 255.255.255.0 gw 192.168.8.1
```

The interface is specified first, but it is actually shuffled to the end of the route line, which forces the route to be associated with the given interface. The rest of the list consists of route arguments. The static-routes example would also produce the following commands:

```
route -add 130.225.0.0 netmask 255.255.255.0 gw 130.225.0.1 eth0
route -add 192.168.8.0 netmask 255.255.255.0 gw 192.168.8.1 eth1
```

Current Linux kernels do not use the metric parameter, but they allow it to be entered into the routing table using routing daemons.

# Linux network hardware options

The ettool command queries and sets a network interface's media-specific parameters such as link speed and duplex. It replaces the old ifconfig command, but some systems still include both. You can query the status of an interface just by naming it. For example, eth0 (a generic NIC on a motherboard) has autonegation enabled and is currently running at full speed:

```
ettool eth0 [ MII ]
Settings for:
Supported ports: 100baseT/Half 100baseT/Full
Supported link modes: 100baseT/Half 100baseT/Full
Supports auto-negotiation: Yes
Advertised link modes: 100baseT/Half 100baseT/Full
Speed: 1000Mb/s
Duplex: Full
Port: MII
PHYAD: 0
Transceiver: internal
Auto-negotiation: on
Wake-on: g
Current message level: 0x0000033 (51)
Link detected: yes
```

# TCP/IP Networking

To lock this interface to 100 Mb/s full duplex, the command

```
ettool -s eth speed 100 duplex full
```

If you are trying to determine whether autonegation is reliable in your environment, you may also use ettool -r helpful. It forces the parameters of the link to be renegotiated immediately.

Another useful option is -k, which shows protocol-related tasks have been assigned to the network interface rather than being performed by the kernel. Most interfaces can calculate checksums, and some can assist with segmentation as well. Unless you have reason to think that a network interface is not doing these tasks reliably, it is always better to offload them. If you use ettool -k in combination with various subsets to force or disable specific types of offloading (-The k option shows current values and the -K option sets them).

Any changes you make with ettool are transient. If you want them to be enforced consistently, you'll have to make sure that ettool gets run as part of the per-interface network configuration. It is best to do this; if you have some ettool commands run at boot, your configuration will not properly cover cases in which the interfaces are restarted without a reboot of the system.
