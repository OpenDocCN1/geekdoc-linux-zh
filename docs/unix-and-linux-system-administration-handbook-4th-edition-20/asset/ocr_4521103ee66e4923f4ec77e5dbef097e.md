# Ubuntu startup scripts and the Ubuntu deamon

Starting with Feisty in early 2007, Ubuntu replaced the traditional init with Upstart, an event-driven service management system that is also used by some Linux distributions. Upstart handles transitions in system—such as hardware changes—more elegantly than does init. It significantly reduces boot times.

Upstarts and stops services in response to system events such as the addition of a device or the disconnection of a network drive. For compatibility, it also translates the traditional run levels of init. However, startup and shutdown scripts are processed in a manner that is somewhat different from that you used.

Upstart uses job definition files in the /etc/event.d instead of an initab file. A job is similar in concept to a startup script: it performs a series of commands and returns control to Upstart. The collection of jobs on an Ubuntu system looks like:

```
ubuntu3 ls /etc/event.d
control-all last-good-boot rc0 rc1 rc2 rc3 rc4 rc5 rc6
rc-default rc5 rc-sulogin sulogin tty1 tty2 tty3 tty4 tty5 tty6
```

Over time, more startup scripts will be converted into native Ubuntu jobs. For now, Upstart uses run-level emulation scripts to boot system. For example, the rc2 script executes /etc/rc2.d/, which runs all the startup scripts for run level 2.

Because of the need to maintain this compatibility, Ubuntu administrators should use Ubuntu's update-rc.d command to maintain links to startup scripts within the rc directories. The syntax is

```
update-rc.d service { start | stop } sequence runlevels
```

update-rc.d accepts a sequence number (the order in which the startup script should be run) and the applicable run levels as arguments. Using a terminating -- ends parsing.
