# Table 9.2 Locations of cron permission and log files

| System | Allow/deny | Default | Default log |
| --- | --- | --- | --- |
| Linux | /etc | All users | via syslog |
| Solaris | /etc/cron.d | All users | /var/cron/log |
| HP-US | /usr/lib/cron | Only root | /var/adm/cron/log |
| AIX | /var/adm/cron | All users | /var/adm/cron/log |

If the file exists, then it contains a list of all cronabs, one per line. No unless person can invoke the cronab command. If the file does not exist, then the deny file is checked. It, too, is just a list of users, but the meaning is: everyone except listed users is allowed access.

If neither the allow nor the deny file exists, systems default (apparently at random, there no dominant convention) to allowing all users to submit cronabs or limiting cron access to root. In practice, a starter **cron.allow** or **cron.deny** file is often included in the OS installation, the question of how **cron** behaves without configuration is moot. Among our example systems, only HP-UX defaults to blocking **cronab** for unprivileged users.

It's important to note that on many systems, access control is implemented by **cronab**, not **cron**. If a user is able to sneak a cron file into the appropriate directory by other members, **cron** will blindly execute the commands it.

> Solaris is a bit different. Its daemon checks to be whether the user's account hasn't been locked with 'L' in /etc/shadow. If it has, **cron** will run the user's jobs. The rationale is to prevent disabled users from running jobs, whether inadvertently or maliciously. If you want to a user to have a valid account from **cron's** perspective but not a valid password, use **passwd -N user**.

# 9.4 LINUX AND WIXIE-CRON EXTENSIONS

The version of **cron** included on Linux distributions (including our examples) is usually the one known as ISC **cron** or "Wixie-cron", named after its author, Paul Wixie. A modern rewrite provides a bit of added functionality with less less.

A primary difference is that in addition to looking for user-specific cronabs, Wixie-cron also observes system cron entries found in **/etc/cron** and in **/etc/cron.d** directory. These files have a slightly different format from the user cron files in that they allow commands to be run as an arbitrary user. An extra *username* field comes before the command name. The *username* field is not present in generic-variety cron files because the cronab's filename provides this information (even on Linux systems).
