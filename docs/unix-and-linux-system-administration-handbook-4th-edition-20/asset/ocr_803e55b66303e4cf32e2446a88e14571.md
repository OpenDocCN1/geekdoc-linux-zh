In addition to logrotate, Ubuntu provides a simpler program called savelog that manages rotation for individual files. It's more straightforward than logrotate and doesn't use (or need) a config file. Some packages prefer to use their own savelog configurations rather than logrotate.

# 11.5 CONDENSING LOG FILES TO USEFUL INFORMATION

Syslog is great for sorting and routing log messages, when all is said and done, its end product is still a bit of log files. While they may contain all kinds of useful information, those files aren't going to come and find when something goes wrong. Another layer of software is needed to analyze the logs and make sure that important messages don't get lost amid the chatter.

A variety of free tools are available to fill this niche, and most of them are remarkably: they scan recent log entries, match them against a database of regular expressions, and process the important messages in some attention-getting way. Tools differ primarily in their flexibility and in the size of their off-shelf database of patterns.

Of the two commonly used log postprocessors are Todd Atkins' swatch and Craig Rawlins' logcheck. Both are available from sourceforge.net (Logcheck comes with the sentrytools package: sourceforge.net/projects/sentrytools).

swatch is a Perl script that gets its matching orders from a configuration file. The configuration syntax is fairly flexible, and it provides access to the full patternmatching power of Perl. While swatch can process an entire file in a single bound, it's intended to be left running so it can review new messages as they arrive, a tail f-. A disadvantage of swatch is that you must build your own configuration essentially from scratch; it doesn't know about specific systems and the actual logs they might generate.

logcheck is a more basic script written in sh. The distribution also includes a C program that logcheck uses to help record its finds within a log file. Logcheck knows how fast it is read in a log file, so there is less chance of a message slipping by at startup or shutdown time. In addition, logcheck can run at intervals from cron rather than running continuously.

logcheck comes with sample databases for several versions of UNIX and Linux. Even if you don't want to use the actual script, it's worth looking over the patterns to see if there are any you might want to save for your own use.

These tools have the disadvantage of working on only a single log file at a time. If your syslog configuration sorts messages into many different files, you might want to duplicate some of the messages into a central file that is frequently rotated, and then use that summary file to feed a postprocessing script. That is easier than setting up a complicated network of scripts to handle multiple files.
