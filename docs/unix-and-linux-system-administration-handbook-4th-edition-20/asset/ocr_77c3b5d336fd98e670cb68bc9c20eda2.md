The root filesystem includes the root directory and a minimal set of files and subdirectories. The file that contains the OS kernel usually lives somewhere within the root filesystem, but that in Solaris, it is not even a single file so as a set of components.

Also part of the root filesystem are /etc for system and configuration files, /sbin and /bin for important utilities, and sometimes /tmp for temporary files. /dev is a real directory that's included in the root filesystem, but some or all of it may be overlaid with other filesystems if your system has virtualized device support. (See page 419 for more information about this topic.)

Some systems kept shared library files and a few other things such as the C preprocessor in the /lib directory. Others have moved these into /usr/lib, sometimes as a symbolic link.

See page 231 for reasons why partitioning might be desirable and some rules of thumb to guide it.

The directories /usr and /var are also of great importance. /usr is where most standard programs are kept, along with other booty such as on-line manuals and most libraries. It is not strictly necessary that /usr be a separate filesystem, but for convenience in administration it is often. Both /usr and /var must be available to the system to come up all the way to multiuser.

/var stores directories, files, accounting information, and other items that grow rapidly and vary on each host. Since /var contains log files, which are apt to grow in times of trouble, it's a good idea to put /var on its own filesystem if that is practical.

Home directories of users are often kept on a separate filesystem, usually one that's mounted in the root directory. Dedicated filesystems can also be used to store bulky items such as source code libraries and databases.

On many systems, a hier page (filesystem man on Solaris) outlines some general guidelines for the layout of the filesystem. Do not expect the actual system to conform to the master plan in every respect, however. The Wikipedia page for "unix directory structure" is a good general reference as well.

For Linux systems, the Filesystem Hierarchy Standard (pathname.fhs) attempts to codify, rationalize, and explain the standard directories. It is an excellent resource to consult when you're trying to figure out where to put something.
