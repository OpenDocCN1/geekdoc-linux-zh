# Debug levels in BIND

named debug levels are indicated by integers from 0 to 100. The higher number, the more verbose the output. Level 0 turns debugging off. Levels 1 and 2 are fine for debugging your configuration and database. Levels beyond 4 are appropriate for the maintainers of the code.

You invoke debugging on the named command line with the -d flag. For example:

```
$ sudo -d2
```

would start named at debug level 2. By default, debugging information is written to the file named.run in the current working directory from named is started. The named.run flies very fast, so do not go out for a beer while debugging or you will have bigger problems when you return.

You can turn on debugging while named is running with rndc trace, which increments the debug level by 1, or rndc trace level, which sets the debug level to the specified value. rndc notrace turns debugging off completely. You can also enable debugging by defining a logging channel that includes a severity specification

```
severity debug 3;
```
