It's rare for a single network to have more than 100 computers attached to it, so class A and class addresses (which are for 16,777,214 hosts and 65,534 hosts per network, respectively) are really quite silly and wasteful. For example, the class 127 networks use up half the available address space. Who knew that IPv4 address space would become so precious!

# Subnetting

To better use of these addresses, you can now reassign part of the host portion to the network by specifying an explicit 4-byte "subnet mask" or "netmask" in which the 1s correspond to the desired network and the 0s correspond to the host portion. The 1s must be leftmost and contiguous. At least eight bits must be allocated to the network part and at least two bits to the host part. Ergo, there are really 22 possible values for an IPv4 netmask.

For example, the four bytes of a class B address would normally be interpreted as N.N.H.H. The implicit netmask for class B is 255.255.0.0 in decimal notation. With a netmask of 255.255.255.0, however, the address would be interpreted as N.N.N.H. Use of the mask turns a single class B network address into 256 distinct C-class networks, each of which can support 255 hosts.

Netmasks are assigned using the `ifconfig` command as the network interface is set up. By default, `ifconfig` uses the inherent class of an address to figure out which bits are in the network part. When you set an explicit mask, you simply override this behavior.

Netmasks that do not end at a byte boundary can be annoying to decode and often written as XX/XX, where XX is the number of bits in the network portion of the address. This is sometimes called CIDR (Classless Inter-Domain Routing; see page 460). For example, the network address 128.138.243.0/26 refers to the first four networks whose first bytes are 128.138.243. The other three networks have 64, 128, and 192 as their fourth bytes. The netmask associated with 255.255.255.192 or 0xFFFFFF0; in binary, it's 26 followed by 6 zeros. Exhibit C breaks these numbers in a bit more detail.

# Exhibit C Netmask base conversion

| IP address | 128 | 138 | 243 | 0 |
| :--- | :--- | :--- | :--- | :--- |
| Decimal netmask | 255 | 255 | 255 | 192 |
| Hex netmask | ff | ff | ff | c0 |
| Binary netmask | 1111 1111 | 1111 1111 | 1111 1111 | 1100 0000 |

The /26 network has 6 bits (32 - 26 = 6) to number hosts. 2^6 is 64, so the network has 64 potential host addresses. However, it can only accommodate 62 actual hosts because the all-0 and all-1 host addresses are reserved (they are the network and broadcast addresses, respectively).

In our 128.138.243.0/26, the extra two bits of network address obtained by subnetting can take on the values 00, 01, 10, and 11. The 128.138.243.0/24 network has been divided into four /26 networks:

- 128.138.243.0/26 (0 in decimal is 00000000 in binary)
- 128.138.243.64/26 (64 in decimal is 01000000 in binary)
- 128.138.243.128/26 (128 in decimal is 10000000 in binary)
- 128.138.243.192/26 (192 in decimal is 11000000 in binary)

The bolded faces of the last byte of each address are the bits that belong to the network portion of that byte.

# Tricks and tools for subnet arithmetic

It's confusing to do all bit twiddling, but some tricks can make it simpler. The number of hosts per network and the value of the last byte in the netmask always adds up to 256:

- netmask byte = 256 - net size

For example, 256 - 64 = 192, which is the final byte of the netmask of the preceding example. Another arithmetic fact is that the last byte of an network address (as to netmask) must be evenly divisible by the number of hosts per network. We see this in action in the 128.138.243.0/26, where the last bytes of the networks are 0, 64, 128, and 192—all divisible by 64.

Given an IP address (say, 128.138.243.100), we cannot tell without the associated netmask what the network address and broadcast address would be. Table 14.3 on the next page shows the possibilities for /16, /24, and /26.

The /16 network has 16 bits (32 - 16 = 16) to number hosts. 2^16 is 65,536, so the network has 65,536 potential host addresses. However, it can only accommodate 65,534 actual hosts because the all-0 and all-1 host addresses are reserved (they are the network and broadcast addresses, respectively).

The /24 network has 8 bits (32 - 24 = 8) to number hosts. 2^8 is 256, so the network has 256 potential host addresses. However, it can only accommodate 254 actual hosts because the all-0 and all-1 host addresses are reserved (they are the network and broadcast addresses, respectively).

The /26 network has 6 bits (32 - 26 = 6) to number hosts. 2^6 is 64, so the network has 64 potential host addresses. However, it can only accommodate 62 actual hosts because the all-0 and all-1 host addresses are reserved (they are the network and broadcast addresses, respectively).

The /30 network has 2 bits (32 - 30 = 2) to number hosts. 2^2 is 4, so the network has 4 potential host addresses. However, it can only accommodate 2 actual hosts because the all-0 and all-1 host addresses are reserved (they are the network and broadcast addresses, respectively).

The /31 network has 1 bit (32 - 31 = 1) to number hosts. 2^1 is 2, so the network has 2 potential host addresses. This is used for point-to-point links where the network and broadcast addresses are not needed.

The /32 network is used to represent a single host address.

The delegation from ICANN to regional registries and to national or regional ISPs has allowed for further aggregation in the backbone routing tables. CIDR makes it easy to allocate portions of class A and B addresses.

 CIDR is sometimes referred to as supernetting.

# Address allocation

Only networks are formally assigned; sites must define their own host numbers to form complete IP addresses. You can subdivide the address space to subnets in whatever manner you like.

Administively, ICANN (the Internet Corporation for Assigned Names and Numbers) has delegated blocks of addresses to 5 regional Internet registries, and these regional authorities are responsible for doling out blocks to ISPs within their regions (see Table 14.4 on the next page). These ISPs in turn divide up their blocks and hand out pieces to individual clients. Only large ISPs should have to deal directly with one of the ICANN-sponsored address registries.
