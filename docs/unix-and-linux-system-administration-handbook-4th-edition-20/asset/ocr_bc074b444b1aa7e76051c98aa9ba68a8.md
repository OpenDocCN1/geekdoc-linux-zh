# Tests of your MTA's scanning effectiveness

When testing that your MTA is correctly identifying viruses and other malware, you need to use real, infected messages to verify that your countermeasures are actually identifying and dealing with them appropriately. Do not do this in a production environment in case things get out of hand. Set up a separate test lab that is not connected to your production network.

Antivirus researchers have compiled a small test file and given it to EICAR, the European Expert Group for IT-Security (eicar/anti_virus_test_file.txt) to distribute. It is not actually a virus, just a distinctive sequence of bytes that antivirus adds to its databases (usually with a descriptive name such as EICAR-AV-Test). You can email, and reproduce the test file without worrying about starting a virus outbreak. EICAR provides several versions of the file that you can test for in various wrappers as ZIP.

GTUBE, the generic test for unsolicited bulk email, is a similar file for testing spam filters. It is filtered by spamassassin.apache.com/gtube

If you are testing and debugging by speaking SMTP to your MTA, check out the SWAKS tool (SWiss Army Knife SMTP, jetmore.org/jhon/code/#swaks) by John Jetmore. It is in Perl and lets you test SMTP conversations easily with command-line arguments. The main page or swaks --help gets you documentation. It requires the libraries libnet-sleay-perl and libnet-dns-perl if you want to test SMTP authentication. It's not rocket science, but it's definitely faster than typing SMTP commands by hand.
