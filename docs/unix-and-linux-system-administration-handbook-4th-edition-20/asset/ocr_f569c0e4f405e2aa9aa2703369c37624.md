# Installing and configuring Unbound

The refuse action is more conformant to the DNS specification to deny-cause clients assume that unanswered queries were lost on the network rather than been administratively dropped for policy reasons. The allow action is the one to use for normal DNS clients.

allow-snoop answers iterative queries as well as recursive queries. You can use it to investigate the contents of the server's cache, since an iterative query succeeds only if the answer is already in-cache. allow-snoop can also be exploited for-wholesome purposes, so limit this action to your sysadmins' hosts.

The username option specifies the unprivileged user as whom unbound should run once it has completed its startup housekeeping. You will have to jump through some hoops to make sure that everything unbound is available-from the jail directory, but recent versions of the code make this pretty easy.

The code is smart about mapping global paths in the chrooted world. Most paths can be specified as absolute global paths, as paths within the jail directory, or as paths to the working directory. unbound performs the appropriate mapping when necessary.

A couple of points about running unbound in jail: Running the config file of course prepares the chroot, so the config file specified on unbound's command should be a global path. The PID file, the unbound-control key files, and the syslog can all remain outside the jail directory because they are opened before unbound performs its chroot.

unbound reads /dev/random before chroot, but it's still a good idea to make /dev/random available after the chroot; unbound may need to return to it to obtain more data. If unbound cannot reach /dev/random, it uses a default source of randomness and logs a warning message.

Under Linux, you can make /dev/random available in the jail with the following invocation (which assumes that var/unbound is your jail directory):

```
linux$ sudo mount --bind -n /dev/random /var/unbound/dev/random
```

The following options control whether unbound tells the truth about its version and hostname when queried for the CHAOS id.server and version.server:

hide-identity: yes | no [no]
identity: string [hostname]
hide-version: yes | no [no]
version: string [name server version]

As explained on page 598, we recommend not tampering with these values.
