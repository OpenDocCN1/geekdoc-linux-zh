Latter-day versions of ybind periodically check to be sure they are dealing with the most responsive server for a NIS domain. This is an improvement over the traditional implementation, which fixates on a particular server.

NIS includes a number of minor commands that examine maps, find out which version of each map server is using, and control the binding between clients and servers. A complete list of NIS commands and daemons is given in Table 19.4.

# ### Table 19.4 NIS commands and daemons

| Program | Description |
|---|---|
| ypserv | Is the NIS server daemon, started at boot time |
| ybind | Is the NIS client daemon, started at boot time |
| domainname | Sets the NIS domain for a machine (runs at boot time) |
| ypfr | Downloads current version of a map from master server |
| ypfr | Serves maps from ypfr (runs on master server) |
| yppush | Makes slave servers update their versions of a map |
| madebm | Builds a hashed map from a flat file |
| ypmake | Rebuilds hashed maps from flat files that have changed |
| ypinit | Configures a host as a master or slave server |
| ypset | Makes ybind to connect to a particular server |
| ypwich | Finds out which current host is using |
| ypoll | Finds out what version of a map server is using |
| ypcat | Prints the values contained in an NIS map |
| ypmatch | Prints map entries for a specified key |
| yppasswd | Changes a password on the NIS master server |
| ypchfin | Changes GECOS information on the NIS master server |
| ypchsh | Changes a login shell on NIS master server |
| yppasswdd | Is the server for yppasswd, ypchsh, and ypchfin |

+   a. Not used or supported on all systems
b. Must be specifically enabled with ybind-ypset or ybind-ypset (dangerous)

# ### NIS security

NIS is not secure. Broadcast mode is particularly bad; any host on a network can claim to serve a particular domain and feed bogus administrative data to NIS clients. On Linux systems, you can mitigate this problem by explicitly permitting the NIS servers for each client.

If you're all concerned about the security in your environment, you shouldn't use NIS to serve the password or shadow files. Use alternative authentication mechanisms, such as LDAP, for this purpose.

Many security vulnerabilities have been found in older versions of NIS. Make sure you're running the current version.
