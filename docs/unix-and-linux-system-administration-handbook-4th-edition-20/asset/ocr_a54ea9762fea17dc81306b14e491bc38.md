# Chapter 14 TCP/IP Networking

In addition to being its own serial number, an RFC can also be assigned an FYI (For Your Information) number, a BCP (Best Current Practice) number, or a STD (Standard) number. FYIs, STDs, and BCPs are subseries of the RFCs that include documents of special interest or importance.

FYIs are introductory or informational documents intended for a broad audience. They can be a good place to start research on an unfamiliar topic if you find one that’s relevant. Unfortunately, this series has largely recounted and not many of the FYIs are up to date.

BCPs document recommended procedures for Internet; they consist of administrative suggestions and for system administrators are often the most valuable of the RFC series.

STDs document Internet protocols that have completed the IETF's review and process and have been formally adopted as standards.

RFCs, FYIs, BCPs, and STDs are numbered sequentially within their own series, so a document can bear several different identifying numbers. For example, RFC17313, Tools for DNS Debugging, is also known as FYI273.

# 14.2 NETWORKING ROAD MAP

Now that we have provided a bit of context, let’s look at the TCP/IP protocols themselves. TCP/IP is a "suite", a set of network protocols designed to work smoothly together. It includes several components, each defined by a standards track RFC or series of RFCs:

+   * IP, the Internet Protocol, which routes data packets from one machine to another (RFC7791)
* ICMP, the Internet Control Message Protocol, which provides several kinds of low-level support for IP; including error messages, routing assistance, and debugging help (RFC792)
* ARP, the Address Resolution Protocol, which translates IP addresses to hardware addresses (RFC8263)
* UDP, the User Datagram Protocol, which provides unverified, one-way data delivery (RFC7688)
* TCP, the Transmission Control Protocol, which implements reliable, full duplex, flow-controlled, error-corrected conversations (RFC7793)

These protocols are arranged in a hierarchy or stack making of the protocols beneath them. TCP/IP is conventionally described as a five-layer system (as shown in Exhibit A), but the actual TCP/IP protocols inhabit only three of these layers.
