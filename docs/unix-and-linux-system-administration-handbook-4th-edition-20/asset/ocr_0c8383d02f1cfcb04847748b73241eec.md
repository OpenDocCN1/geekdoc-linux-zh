# Table 18.7 Common export options in Linux

| Option | Description |
| --- | --- |
| ro | Exports for reading and writing (the default) |
| rw | Exports read-only. The list enumerates the hosts allowed to mount for writing; all others must read-only. |
| rw=list | |
| root_squash | Maps ("squashes") UID 0 and GID 0 to the values specified by anuid and anogid.* This is the default. |
| no_root_squash | Allows access by root. Dangerous. |
| all_squash | Maps all UIDs and GIDs to their anonymous versions. For supporting PCs and untrusted single-user hosts. |
| anuid=xxx | Specifies the UID which remote roots should be squashed |
| anogid=xxx | Specifies the GID to which remote roots should be squashed |
| secure | Requires mount to originate at a privileged port |
| insecure | Allows remote access from any port |
| noaccess | Blocks access to this dir and subdirs (used with nested exports) |
| wdelay | Delays writes in coalescing multiple updates |
| no_wdelay | Writes data to disk as soon as possible |
| async | Makes server reply to write requests before actual disk filesystems mounted within file trees |
| nohide | Reveals files within exported file trees |
| hide | Opposite of nohide |
| subtree_check | Verifies that each requested file is within an exported subtree |
| no_subtree_check | Verifies only that file requests refer to an exported filesystem |
|secure_locks | Requires authorization for all lock requests |
| insecure_locks | Specifies less stringent locking criteria (older clients) |
| sec=flavour | Specifies a list of locking methods for the exported directory. Values include sys (Unix authentication), dh (DES), krb5 (Kerberos authentication, and integrity), krb5i (Kerberos authentication, and integrity), krb5p (Kerberos authentication, integrity, and privacy), and none (anonymous access, not recommended). |
fsid=num | Specifies the V4 pseudo-filesystem root (usually 0)

+   a. Unlike most operating systems, Linux allows UIDs other than root to be squashed. Look up the all_squash option for more details.

For example, the configuration

```
/home
  *.trust.com(rw)
/home/ben
  *(noaccess)
```

allows hosts by the trust.com domain to access all the contents of /home except for /home/ben. The absence of a client name on the second line means that the option applies to all hosts; it's perhaps somewhat secure this way.
