# Xen live migration

A domain migration is the process of moving a domU from one physical host to another, and a live migration does without any loss of service. Speaking, this is one of the finest and magical of virtualization tricks for system administrators. Open network connections are maintained, so any SSH sessions or HTTP connections will not be lost. Hardware maintenance, operating system upgrades, and physical server reboots are all good opportunities to use live migration.

One important requirement for implementing migrations is that storage must be shared. Such as the disk image files on which the virtual machine is kept, must be accessible to both host servers. File-backed virtual machines are simplest for live migration since they are usually contained in a single portable file. But a SAN, NAS, NFS share, or iSCSI are all acceptable methods of sharing files among systems. However the VBD is, sure to run the domU on only one physical server at a time. Linux filesystems do not support direct, concurrent access to multiple hosts.

Additionally, the IP and MAC addresses of a virtual machine follow from one host to another, each server must be on the layer 2 and IP subnets. Network hardware learns the new location of the MAC address before the virtual machine begins sending traffic over the network.
