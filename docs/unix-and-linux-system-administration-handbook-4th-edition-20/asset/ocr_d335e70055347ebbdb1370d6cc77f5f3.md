# Chapter 25    The X Window System

If the client application happens to be running on the same machine as the X server, you can simplify the DISPLAY variable even further by omitting the hostname. This feature is more than just cosmetic; with a null hostname, client libraries use a UNIX domain socket instead of a network socket to connect the X server. In addition to being faster and more efficient, this connection method passes any firewall restrictions on the local system that are trying to keep out X connections. The simplest possible value for the DISPLAY environment variable, is simply "0".

# Client authentication

Although the X environment is generally thought to be relatively insecure, precautions help prevent unauthorized access. In the days before security was such a pressing concern, it was common for X servers to welcome connections from any client running on a host that had been marked safe with the xhost command. But since any user on that host could then connect to your display and wreak havoc (either unintentionally or out of confusion), the xhost method of granting access to clients was eventually deprecated. We do not discuss it further.

The most prevalent alternative to hot-based security is magic cookie authentication. While the thought of magic cookies might inspire flashbacks in some of our readers, in this context they are used to authenticate connections. The basic idea is that the X display manager generates a large random number, called a cookie, early in the login procedure. The cookie is written to the ~/.Authority file in the user's home directory. Any clients that know the cookie are allowed to connect. Users can run the xauth command to view existing cookies and add new ones to this file.

The simplest way to show how this works is with an example. Suppose you set your DISPLAY variable on the client system to display X applications on the machine where you are sitting. However, when you run a program, you get an error that looks something like this:

```
client$ xprogram -display:0
Xlib: connection to "server:0.0" refused by server
xprogram: unable to open display "server:0'
```

This message tells you that the client does not have the right cookie, the remote server refused the connection. To get the right cookie, log in the server (which you have probably already done if you are trying to display on it) and list the server's cookies by running xauth list:

```
server$ xauth list
server:0 MIT-MAGIC-COOKIE-1 f9d88df6077819ef4d788fat778dc9f
server/unix:0 MIT-MAGIC-COOKIE-1 f9d88df6077819ef4d788fat778dc9f
localhost:0 MIT-MAGIC-COOKIE-1 cb6cbf9e524128749fedd47f0efe77
```
