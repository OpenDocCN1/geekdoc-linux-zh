# Removing users

If your organization assigns individual workstations to users, it's generally simple and most efficient to reimage the entire system from a master template before turning it over to a new user. Before you do the reinstallation, however, it's a good idea to back up any local files on the system's hard disk in case they are needed in the future.

Each of our example systems has a user command that automates the process of removing a user. It will probably not quite as thorough as a job as you might like, unless you religiously added functionality to it as you expanded the number of places where user-related information is stored.

Ubuntu's userdel is a Perl script that calls the userdel; it undoes all the things It calls userdel.local, if it exists, to provide for localization. The configuration file /etc/deluserconf lets you set your options such as:

+   - To remove the user's home directory and mail spool
- To back up the user's files, and to where to put the backup
- To remove all files owned by the user
- To delete a group it has no members

SUSE supports a set of pre- and postexecution scripts as well as a userdel.local script that assists userdel and helps you make the defaults of your local customs. Configure it in /etc/login.defs.

Red Hat has the userdel.local script but no pre- and postexecution scripts to automate like backing up the about-to-removed user's files.

Solaris and AIX have some extra quirks in which they stay user info, primarily in the files that control roles and authorizations. Therefore, these systems' userdel commands have a bit more work to do to remove all references to a deleted user.

For example, in addition to the /etc/passwd and /etc/group file, Solaris' user updates /etc/shadow, /etc/project, and /etc/user_attr. AIX's user touches the following files in the /etc/security directory: user, roles, lastlog, environ, audit/config, limits, password, and group. Solaris is not not as thorough as one might like: its userdel left a login profile with configured user_attr that should have been cleaned up.

HP-UX's userdel is a ho-hum, run-of-the-mill guy who removes the changes made by useradd. It touches only the password, shadow, and group files.
