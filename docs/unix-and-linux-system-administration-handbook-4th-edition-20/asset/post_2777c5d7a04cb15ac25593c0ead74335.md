## gated: first-generation multiprotocol routing daemon

gated is an elegantly designed and once-freely-available routing framework that allows the simultaneous use of multiple routing protocols. It gives administrators precise control over advertised routes, broadcast addresses, trust policies, and metrics gated shares routes among several protocols, allowing routing gateways to be constructed between areas that have standardized over different routing systems. It also has one of the nicest administrative interfaces and configuration file designs of any administrative software.

Alas, gated is dead (or at least, dead-ish), though its memory lives in slow-to-change releases as HP-UX and AIX, which bundle versions 3.5.9 and 6.0, respectively.

gated is an object lesson in the perils of attempting to compete with open source software. It started out as freely distributable software, but in 1992 it was privatized and turned over to a development consortium; updates only to members of the consortium. The consortium was eventually disbanded, and the rights to the commercial version of gated changed several times. Meanwhile, the open source Zebra and Quagga projects took over gated role as the mainstream open source routing package. These days, gated is extinct both as a commercial product and as an open source project, a sad end to a useful and well-designed package.

## Quagga: mainstream routing daemon

Quagga (quagga.net) is a development fork of Zebra, a GNU project started by Kunihiro Ishiro and Yoshinari Ishikawa to implement multiprotocol routing with a collection of independent daemons instead of a monolithic application. In real, the quagga—a subspecies of zebra last photographed in 1870—is extinct, in the digital realm it is Quagga that survives and Zebra is no longer under active development.

Quagga implements RIP (all versions), OSPF (versions 2 and 3), BGP, and IS-IS. It runs on Linux, Solaris, and various flavors of BSD. On Solaris and our example Linux systems, Quagga is either installed by default or available as an optional package through the system's standard software repository.

In the Quagga system, the zebra daemon acts as a central clearing-house for routing information. It manages the interaction between the kernel's routing table and the daemons for individual routing protocols (rippgd, ospfd, bgpd, and isis). It also controls the flow of routing information among protocols. Each daemon has its own configuration file in the /etc/quagga directory.

## Chapter 15 Routing

You can connect to any of the Quag daemons through a command-line interface (vtysh on Linux, quaggaadm on Solaris) to query and modify its configuration. The command language itself is designed to be familiar to users of Cisco's IOS operating system; see the section on Cisco routers on page 525 for some additional details. In IOS, use enable to enable "superuser" mode, config term to enter configuration commands, and write to save your configuration back to the daemon's configuration file.

The official documentation at quagga.net is available in HTML or PDF format. Although complete, it's for the most part a workmanlike catalog of options and does not provide much of an overview of the system. The real documentation action is on the wiki, wiki.quagga.net. Look there for well-commented example configurations, FAQs, and tips.

Although the configuration has a simple format and are not complex, you'll need to understand the protocols you're configuring and have some idea of which options you want to enable or configure. The recommended reading list on page 528 for some good books on routing protocols.

## ramd: multiprotocol routing system for HP-UX

HP-UX includes a suite of daemons that are eerily similar in their general architecture to Zebra and Quagga. We are not sure whether the similarity is attributable to emulation, convergent evolution, or perhaps to an early fork from the Zebra code base.

In any event, the similarity is only superficial. Notable points of divergence are HP's systems support only IPv6 and external routing protocols (RIPng, BGP, and IS-IS) that it does not support OSPF at all. The configuration is different, and the control utility (rdc as opposed to Quagga's vtysh or quaggaadm) accepts only command-line arguments; it does not function as an independent environment.

HP calls its Route Administration Manager Daemon, and the ramd daemon plays the same role as zebra in the Quagga universe. In Quagga, the protocol-specific daemons are called ripngd, isisid, and bgpd.

## 15.6 CISCO ROUTERS

Routers made by Cisco Systems, Inc., are the de facto standard for Internet routing today. Having captured over 60% of the router market, Cisco products are well known, and staff that know how to operate them are relatively easy to find. Before Cisco, UNIX boxes with multiple interfaces were often used as routers. Today, dedicated routers are the favored gear for in datacom slots and ceiling cables come together.

By default, IOS defines two levels of access (user and privileged), both of which are password protected. By default, you can simply telnet to a Cisco router to enter user mode.
