bash also has the more familiar loop for traditional programming languages in which you specify starting, increment, and termination clauses. For example:

```
for (( i=0; i < $CPU_COUNT ; i++ )); do
```

The next example illustrates bash's while loop, which is useful for processing command-line arguments and running the lines of a file.

```
#!/bin/bash
exec 0<$1
counter=1
while read line; do
echo "$counter: $line"
$((counter++))
done
```

Here's what the output looks like:

+   ubuntu$ sh example /etc/passwd
1: root:x:0:Superuser/root:/bin/bash
2: bin:x:1:1:bin:/bin/bash
3: daemon:x:2:2:Daemon:/bin/bash

This script has a couple of interesting features. The exec statement redefines the script's standard input to whatever file is named by the first command-line argument. The file must exist or the script generates an error.

The read statement within the while clause is in a shell built-in, but it acts as an external command. You can put external commands in a while clause as well; in that form, the while loop terminates when the external command returns a nonzero exit status.

The $((counter++)) expression is an odd duck, The ((...)) notation forces numeric evaluation. It also makes optional of $ to variable names. The ++ is the familiar increment operator from C and other languages. It returns the value of the variable to which it is attached, but has the side effect of incrementating variable's value as well.

The $((...)) shenanigans work in the context of double quotes, so the body of the loop could be collapsed down to one line.

+   Depending on the invocation, exec can also have the more familiar meaning "stop this script and transfer control to another script or expression." It yet another shell oddity that both functions are accessed through the same statement.
