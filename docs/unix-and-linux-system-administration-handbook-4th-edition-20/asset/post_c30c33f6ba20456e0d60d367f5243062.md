## 17.5 THE DNS NAMESPACE

The DNS namespace is organized into a tree with top-level branches: forward mappings and reverse mappings. Forward mappings map hostnames to IP addresses, and reverse mappings map IP addresses to hostnames. Every fully qualified hostname (e.g., nubark.astrust.com) is a node in the forward branch of the tree, and every IP address is a node in the reverse branch. Period separates levels of the tree; the root (of the top) is "." aka "dot".

Fully qualified hostnames can be viewed as a notation in which the "significant part" is on the right. For example, in the name nubark.astrust.com, nubark is in at and trust is in com. IP addresses, on the other hand, have the "most significant part" on the left. In 128.18.243.100, for example, host 100 is on subnet 243, which is part of network 128.138.

To allow the DNS system to service both kinds of data, the IP branch of the namespace is inverted by litting the octets of the IP addresses. For example, if nubark.astrust.com has IP 63.173.189.1, the corresponding node of the forward branch of the naming tree is "nubark.astrust.com." and the node of the reverse is "1.189.173.63.in-addr.arpa." Both of these names end with a dot, just as the pathnames of files always start with a slash.

A "fully qualified domain name" is the full path to a DNS object, including a final dot. For example, a host nubark in astrust domain contains the FQDN "nubark.astrust.com."

A "domain" is a subtree of the DNS naming tree. For example, the astrust domain contains astrust.com and all of astrust.com's subdomains and hosts. By contrast, a "zone" is any domain subdomains that have been delegated to other names.

If the astrust domain were further subdivided into the subdomains engineering, marketing, and booklab, then the astrust domain would contain four zones: the original astrust.com plus engineering.astrust.com, marketing.astrust, and booklab.astrust.com.

The atrust zone contains all the hosts in astrust except those in engineering, marketing, and booklab.

Name servers are associated with zones, not domains. You can determine a given name (such as booklab.astrust.com) identifies a subdomain rather than by checking DNS. Subdomains have name server (NS) records associated with them.

Domain names originally had to be made up of letters, numbers, and dashes, with each component (label) being at most 63 characters long and an entire FDN being less than 256 characters. FDNs are not sensitive, but they are usually written in lowercase letters. Domain names were liberalized by RFC2181.

The ongoing internationalization of domain names is forcing changes to these to allow lower FDNs. Characters in non-roman alphabets are represented through an encoding called Punycode, in spirit to Unicode but with different implementation details.

There are two types of top-level domains: country code domains (ccTLDs) and generic top level domains (gTLDs). ICANN, the Internet Corporation for Assigned Names and Numbers, accords various agencies to parts of its shared registry for registering names in the gTLDs such as com, net, and org. As of this writing, you have like 1,000 choices for a registrar and 21 gTLDs in to register. Check icann.org for the definitive list. ICANN is in the process of creating more gTLDs.

To register for a ccTLD name, check the IANA (Internet Assigned Numbers Authority) page iana.org/cctld to find the registry in charge of a particular country's registration.

## Registering a second-level domain name

To obtain a second-level domain name, you must apply to a registrar for the appropriate top-level domain. To complete the domain registration process, you must choose a name that is not already taken and identify a technical contact person, an administrative contact person, and at least two hosts that will be name servers for your domain. Fees vary among registrars, but these days they are generally inexpensive.

## Creating your own subdomains

The procedure for creating a subdomain is similar to creating a second-level domain, except that the central authority is now local (or more accurately, within your own organization). Specifically, the steps are as follows:

- Choose a name that is unique in the local context.
- Identify two or more hosts be servers for your new domain.
- Coordinate with the parent domain.
- Ensure the servers are reachable from the outside.
