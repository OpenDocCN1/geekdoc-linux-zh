The format should be self-explanatory. One or more blank lines separates entries. This same format is used for AIX configuration files in /etc/security, the username generalized to whatever object is being controlled or logged.

# 7.3 THE /ETC/GROUP FILE

The /etc/group file contains the names of UNIX groups and a list of each group's members. Here's a portion of the group file from an AIX system:

```
system!:0:root,pconsole,esaadmin
staff!:1:ipsec,esaadmin,trent,ben,garth,evi
bin!:2:root,bin
sys!:3:root,sys
adm!:4:bin,adm
nobody!:4294967294:nobody.lpd
```

Each line represents one group and contains four fields:

- Group name
- Encrypted password or a placeholder
- GID number
- List of members, separated by commas

As in /etc/passwd, fields are separated by colons. Group names should be limited to eight characters for compatibility, many systems do not require this. It is possible to enter a group password to allow users not belonging to a group to enter it with the newgrp command, but only Linux has real support for group passwords. A password can be set with the passwd command; the encrypted form is stored in the /etc/gshadow file. Passwords are rarely, if ever used.

With usernames and UIDs, group names and GIDs should be consistent among machines that share files through a network filesystem. Consistency can be hard to maintain in a heterogeneous environment since different operating systems use different GIDs for the same group.

We found that the best way to deal with this issue is to avoid using a system group as the default login group for a user. Some systems use group ownership together with the permission bits to control the execution of commands. GID inconsistencies among systems play havoc on site-wide systems for updating and installing software.

If a user defaults to a particular group in /etc/passwd but does not appear to be in that group according to /etc/group, /etc/passwd wins the argument. The group memberships granted at login time are really the union of those found in the passwd and group files.

Some systems limit the number of groups a user can belong to. Eight used to be a common limit, but it is now 16 on Solaris, 20 on HP-UX, and unlimited on others.

To set a password for a user, use the passwd command. To remove a password, use passwd -l flag.

# Adding users: the basic steps

To minimize the effort, we suggest starting with GID 500 or higher, to avoid collisions with system accounts, which use GIDs below 1000.

To add a user, use the useradd command. This creates the entry in the passwd, shadow, and group files, and creates the home directory.

To modify a user account, use the usermod command. To delete a user, use the userdel command.

To change a password, use the passwd command. This is also necessary for the user.

# Chapter 7 Adding New Users

Required:
- Have the new user sign the agreement
- Edit shadow files
- Add the user to /etc/group (not really necessary, but nice)
- Set an initial password
- Create, chown, and chmod the user's home directory.
- Configure roles and permissions (if you use RBAC; see page 190).

For the user:
- Copy default startup files to the user's home directory.
- Set user home and mail aliases.

For you:
- Verify that the account is set up.
- Add the user's contact information and account status to your database.
