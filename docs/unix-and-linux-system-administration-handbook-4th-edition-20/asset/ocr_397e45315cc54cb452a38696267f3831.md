The first command sets the initiator's authentication mode to CHAP and sets the CHAP username to testclient. The -C option sets the password; you cannot combine this option with any others. It's also possible to set the name and password individually for each target you prefer.

The modify discovery command enables the use of statically configured targets, and the add command designates the server and IQN of any specific target. This configuration is persistent across reconnects.

To serve iSCSI targets to other systems, you'll need to install the SUNWiscgit package. Administration is structured similarly to the initiator side, but the command is isciadm instead of issciadm.

To use iSCSI on HP systems, download the iSCSI initiator software from ware.hp.com and install it with HP-UX Software Distributor tool. A kernel rebuild and reboot are required. Fortunately, the system is well documented in a stand-alone manual, the HP-UX iSCSI Software Initiator Support Guide, available from docs.hp.com.

Most configuration is performed with the iscsutil command, installed in /opt/iscsi/bin. Use iscsutil -l i to set the initiator IQN, iscsutil -a N to set the global CHAP username (it can also be set per-server or per-target), and iscsutil -a W password to set the global CHAP password.

You can add targets from a particular server using iscsutil -a I. Use ioscan-HN 64000 to activate the server connections and create virtual disk devices. You can check the status of the system with iscsutil -p -o.

AIX's iSCSI initiator comes installed and ready to go. In typical AIX style, configuration is done through the system's ODM database. The iscsi device represents the configuration of the initiator as a whole, and individual target devices can be defined as ODM entries or in text configuration files /etc/iscsi. The text configuration files seem to somewhat more reliably.

AIX does not distinguish between the initiator's IQN and its CHAP username. The IQN is set on the iscsi device; therefore, you should plan on using the same CHAP username on every server. The first step on the fast configuration path is to set that IQN to an appropriate value.

```
$ sudo chdev -iscsi -a initiator_name=iqn.1994-11.com.admin:client'
```

We used a different CHAP username for this example than for other systems "testclient" isn't technically a valid IQN for the initiator (although in it works as well).

In the /etc/iscsi/targets file, we add the following entry:
iserver 3260 iqn.1994-11.com.admin:test "chap_password"
