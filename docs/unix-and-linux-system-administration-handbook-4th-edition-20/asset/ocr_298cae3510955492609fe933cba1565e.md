# 18.4 Client-SFS NFS

NFS filesystems are mounted in much the same way as local disk files. The mount command understands the notation hostname:directory to mean the path directory on the host hostname. With local filesystems, mount maps the remote directory over the remote host into a directory within the local file tree. After mount completes, you access an NFS-mounted filesystem just like a local filesystem. The mount command and its associated NFS extensions represent the most significant concerns to the system administrator of an NFS client.

Before an NFS file system can be mounted, it must be properly exported (see Server-side NFS on page 698). To verify that a server has properly exported its filesystems from the client's perspective, use the client's showmount command:

```
$ showmount -e monk
Export list for monk:
/home/ben harp.atrust.com
```

This example reports the directory /home/ben on the server has been exported to the client system harp.atrust.com. If an NFS mount is not working, first verify that the filesystems have been properly exported on the server with exports. (If you might just forgotten to run exportfs -a after updating the exports file.) Next, check the showmount output.

If the directory is properly exported on the server but showmount returns an error or an empty list, double-check that all necessary processes are running on the server (portmap, mount, nfsd, stack, and lockd), that hosts.allow allows those daemons, and that you are on the right client system.

The path information displayed by showmount, as for /home/ben above, is only valid for NFS version 2 and 3 servers. NFS version 4 servers export a single unified pseudofilesystem. The traditional NFS concept of separate mount points doesn't join with version 4's model, so showmount isn't applicable.
