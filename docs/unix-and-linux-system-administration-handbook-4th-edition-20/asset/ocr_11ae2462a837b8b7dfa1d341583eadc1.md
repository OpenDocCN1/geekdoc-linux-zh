The /etc/initab files tell what to do at each run level. Its format varies from system to system, but the basic idea is that initab defines commands that are to be run (kept running) when the system enters each level.

As the machine boots, init ratches its way up from run level 0 to the default run level, which is also set in /etc/initab. To accomplish the transition between each pair of adjacent run levels, init runs the actions spelled out for that transition in /etc/initab. The same progression is made in reverse order when the machine is shut down.

The telinit command changes init's run level is the system for. For example, telinit 3 goes to run level 3. telinit's most useful argument is -q, which causes init to reread the /etc/initab file.

Unfortunately, the semantics of the initab file are freely crude, and they do not mesh with the way that services are actually started and stopped on UNIX systems. To manage the facilities of the initab file into something a bit usable, init implements another layer of abstraction. This layer usually takes the form of a “change run levels” command that's out of initab. This command in turn executes scripts from a run-level-dependent directory to bring the system to its new state.

This second layer is not well developed in AIX. Indeed, AIX systems rely heavily on the initab file itself to manage services. AIX's startup scripts are also slightly different from those of other systems.

These days, most Linux distributions boot to level 5 by default, which may not be appropriate for systems that don't need to run a window server. The default run level 5 is easy to change. This line from SUSE machine's initab defaults to run level 5:

```
id:5:initdefault:
```

System administrators usually don't have to deal directly with /etc/initab because the script-based interface is adequate for most applications. In the following discussion, we mostly ignore the initab file and the other glue that attaches init to the execution of startup scripts. Just keep in mind that when we say init runs such-and-such a script, the connection may not be so direct.
