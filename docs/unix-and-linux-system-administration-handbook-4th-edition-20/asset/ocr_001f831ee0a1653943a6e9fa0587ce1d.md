# sendmail

If you are implementing a mail system from scratch and have no politics or
bias to deal with, it may be hard to choose an MTA. sendmail and Exim are
certainly the most complex and probably the most configurable and most power-uloptions. Postfix is simpler, faster, and was designed with security as a primary
goal. If your site or your sysadmins have a history with a particular MTA, it's
ably not worth switching unless that functionality's not available
your old MTA.

sendmail configuration is covered in the next section. Esim configuration begins
page 807, and Postfix configuration on page 828.

# 20.8 SENDMAIL

The sendmail distribution in source form is available from sendmail.org, but it
really necessary to build it from scratch these days. If you have to, refer to the-
level INSTALL file. If you need to tweak some of the defaults, you can find
sendmail's assumptions in devtools/OS/your-OS-name, and you can add features
by editing devtools/Site/config.m4. sendmail uses the m4 preproc-
snot only during compilation but also for configuration. An m4 configuration
file is usually named hostname.mc and is translated from a slightly us-
friendly syntax to a totally inscrutable low-level language in the file hostname.cf,
which is in turn installed as /etc/sendmail.cf.

To see what version of sendmail is installed on your system and how it was-
piled, try the following command:

```
linux$/usr/bin/sendmail -d0.1 -bt < /dev/null
Version 8.13.8
Compiled with: DNSMAP GETMAILHOST LDAP LOG
MAP_REGEXP MATCHGECOS MILTER MIME7TO8 MIME7TO8 NAMED_BIND
NETINET NETINET6 NETUNIX NEWDB NIS PIPELINING ASLV2 SCAN
SOCKET STARTMAP TTTLS TCPWRAPPERS USERDB8 USE_LDAP_INIT
========= SYSTEM IDENTITY (after recfd) ==========
(short domain name) $ = ross
(canonical domain name) $ = amass.com
(subdomain name) $m = at.com
(node name) $k = ross.atrust.com
```

This command puts sendmail in test mode (-bt) and debug mode (-d0.1)
but gives it no addresses to test </dev/null>. A side effect is that sendmail tells
it its version and the compiler it was with. Once you know the version
number, you can look at the sendmail.org web site to see if any known security
vulnerabilities are associated with that release.

To find the sendmail files on your system, look at the directory of the installed
/etc/sendmail.cf file. The comments mention the directory in which
t configuration was built. That directory should lead you to the .mc file
that is the original source of the configuration.
