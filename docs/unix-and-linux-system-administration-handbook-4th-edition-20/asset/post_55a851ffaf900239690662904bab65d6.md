
adduser is configured in /etc/adduser.conf, which includes options such as these:

- Rules for locating home directories: by group, username, etc.
- Permission settings for new home directories
- UID and GID ranges for system users and general users
- An option to create individual groups for each user
- Disk quotas (Boolean, unfortunately)
- Regex-based matching of usernames and group names

Other typical adduser parameters, such as rules for passwords, are set parameters to the PAM module that do regular password authentication. (See page 908 for a discussion of PAM, Pluggable Authentication Modules.) adduser has a twin addgroup and cousins deluser delgroup.

## useradd on SUSE

SUSE's adduser does not create a new user's home directory or startup files by default. You must request these nicities with the -m flag. (The startup files come from /etc/skel.) Nor does adduser create a spool file for new users.

SUSE's adduser also does not create user-specific groups; the default GID in the passwd file is set by the variable in /etc/default/useradd. New users are also added to the groups specified by the GROUPS variable. By default, these are video and dialout, which allow access to the system's frame buffer and the dialup IP server pppd.

To make up for these deficiencies, SUSE's useradd calls /usr/sbin/useradd.local, a bash script to which you can add whatever customizations you wish.

The /etc/login.defs file on SUSE controls the following types of issues:

- Whether to allow logins if a user's home directory does not exist
- Degree of tolerance (delay and lockout) for failed login attempts
- Location of the "message of the day" and ttytype (terminal) files
- Restrictions on use of csh and chfin
- Password aging
- Ranges of system and user UIDs and GIDs
- Rules for forming valid user and group names
- Users' umask (the default is 022)

Local scripts that piggyback on the useradd and userdel commands

Both the main page for login.defs and the comments in the file itself do a good job of describing the various parameters and their meanings.

## useradd on Red Hat

The useradd program on Red Hat Linux takes its configuration parameters from /etc/login.defs, where issues such as password aging controls, encryption algorithms, mail spool files, and UID/GID ranges are addressed. The comments in the file do a good job of explaining the various parameters.

## Chapter 7 Adding New Users

useradd -D displays the defaults that useradd will use for new logins. These defaults are set in the file /etc/default/useradd. On Red Hat, new users are placed in their own individual groups. The passwd file enters "x" as a password holder, and the shadow file uses "!", a code that disables login and requires a sysadmin to set a password for the new user. MD5 encryption is the default. A new user's home directory is populated with startup files from /etc/skel.

## useradd on Solaris

On Solaris, some of the default parameters related to logins and passwords are built into /etc/default/login and /etc/default/passwd; others are built into the useradd command itself. useradd -D shows the default values for several parameters. With additional flags, it can be used to reset some of those defaults.

The format of the default/login and default/passwd is similar to that of Linux's user.defs file in blank lines and lines beginning with # are ignored, however, the syntax NAME=value assigns a noncomment value to a variable.

The /etc/default/passwd file controls the following:

- Minimum password length
- Password aging
- Required password complexity
- Checking for crackable passwords

/etc/default/login controls issues such as these:

- The time zone
- Limits on the size of files a user can create
- Whether root can log in only on the console
- Whether a password is required for each user
- Handling of failed login attempts
- Users' initial search path
- Users' umask (the default is 022)
