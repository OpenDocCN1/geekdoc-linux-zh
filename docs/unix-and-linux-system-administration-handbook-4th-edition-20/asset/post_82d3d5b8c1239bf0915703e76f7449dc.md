Why is this feature even needed? First, filesystems generally do no erasing of their own, so an `rm -rf *` of a disk's data leaves everything intact and recoverable with software tools. It's critically important to remember this when disposing of disks, where their destination is Ebay or the trash.

Second, a manual rewrite of every sector may leave magnetic traces that are recoverable by a determined attacker with access to a laboratory. Secure erase performs as many overwrites as needed to eliminate these shadow signals. Magnetic remnants won't be a serious concern for most de-sites, but it's always nice to know that you're not exporting your organization’s confidential data to a large world.

Finally, secure erase has the effect of resetting SSDs to their fully erased state. This may improve performance in cases when the ATA TRIM command (the command to erase a block) cannot be issued, either because the filesystem on the SSD does not know to issue it or because the SSD is connected through a host adapter or RAID interface that does not propagate TRIM.

Unfortunately, UNIX support for sending the secure erase command remains elusive. At your point, it is best to connect to a Windows or Linux system for erasure. DOS software for secure erasing can be found at the Center of Magnetic Recording Research at tiny.com/20qqqw. The MHDD utility supports secure erase through its faster command—see tiny.com/2gcr98.

Under Linux, use the hard command:

```bash
$ sudo hddm --user-master u --security-set-password /dev/sda8
$ sudo hddum --user-master u --security-erase password /dev/sda
```

There is no analog in the SCSI secure erase command, the SCSI “format unit” command described under Formatting and bad block management on page 226 is a reasonable alternative. Another option is to zero-out a drive’s sectors with `dd if=/dev/zero of=disk bs=8k`.

Many systems have a shred that attempts to secure the contents of individual files. It relies on the assumption that a file’s blocks can be overwritten in place. This assumption is invalid in many circumstances (any filesystem on any SSD, any logical volume that has snapshots, perhaps generally (on ZFS) that shred’s general utility is questionable).

### hdparm: set disk and interface parameters (Linux)

# hdparm: set disk and interface parameters (Linux)

Linux's hdparm command can do more than just send secure erase commands. It's a general way to interact with the firmware of SATA, IDE, and SAS hard disks. Among others, hdparm can set drive power options, enable or disable noise reduction options, set the read-only flag, and print detailed information. A few of the options work on SCSI drives, too (under current Linux kernels).

The syntax is:

```bash
hdparm [options] device
```

Scores of options are available, but most are of interest only to driver and kernel developers. Table 8.3 shows a few that are relevant to administrators.

### Table 8.3 Useful hdparm options for system administrators

| Option | Function |
| :--- | :--- |
| -I* | Dumps lots of identifying and status information |
| -M value | Sets acoustic management options |
| -S value | Sets time delay for automatic standby (spin-down) mode |
| -y | Put drive into standby mode immediately |
| -C | Queries the drive's current power management state |
| -T | Quick-tests interface bandwidth (no actual disk reads) |
| -t | Quick-tests overall platter-to-host sequential reads |

a. This is an uppercase letter "eye" as in India.

hdparm -I to verify that each drive is using the fastest possible DMA transfer mode. hdparm lists all the supported modes and the currently active mode with a star, as shown in the example below.

```bash
linux$ hdparm -I /dev/sda
```

```text
/dev/sda:
ATA device, with non-removable media
Model Number: WDC1001FALS-0OJ7B0
Serial Number: WD-WMATV0998277
Firmware Revision: 05.00K5
Transport: Serial, SATA 1.0A, SATA II Extensions, SATA Rev 2
```

```text
Capabilities:
LBA, IORY(can be disabled)
Queue depth: 32
Standby timer values: spec'd by Standard, with device specific
R/W multiple sector transfer: Max = 16 Current = 16
Recommended acoustic management value: 128, current value: 254
DMA: mdma0 mdma1 mdma2 udma0 udma1 udma2 udma3 udma4
udma5 *udma6
```

## 8.6 DISK PARTING

Partitioning and logical volume management are both ways of dividing up a disk (or pool of disks, in the case of LVM) into separate chunks of known size. All our examples support logical volume management, but only Linux, Solaris, and sometimes HP-UX allow traditional partitioning.
