# Chapter 17 DNS: The Domain Name System

The third and fourth lines delegate a subdomain booklab.atrust.com to the name servers ubuntu.booklab and ns1. These records are really part of the subdomain domain, but they must also appear in the parent zone, atrust.com, in order for the delegation to work. In a similar fashion, NS records for atrust are stored in the .com zone file to define atrust subdomain and identify its servers. The .com servers refer query hosts at atrust.com to the servers listed in NS records within the .com domain.

The list of name servers in the parent zone should be kept up to date with those in the zone itself, if possible. Nonexistent servers listed in the parent zone can delay name service, although clients will eventually stumble onto one of the name servers. If none of the name servers listed in the parent exist in the child, a so-called lame delegation results; see page 678.

Extra servers in the child are OK as long as at least one of the child's servers has an NS record in the parent. Check your delegations with dig or drill occasionally to be sure they specify an appropriate set of servers; see page 677.

# A records

A (address) records are the heart of the DNS database. They provide the mapping from hostnames to IP addresses that were formally specified in the /etc/hosts file. A host usually has one A record for each of its network interfaces. The format is

```
hostname [tll] [IN] A ipaddr
```

For example:

```
ns1 IN A 63.173.189.1
```

In this example, the name field is not-deterministic, so the name server adds the default domain to form the fully qualified name "ns1.atrust.com." The record associates that name with the IP address 63.173.189.1.

# PTR records

PTR (pointer) records map from IP addresses to hostnames. As described on page 566, reverse mapping records live under the in-addr.arpa domain and are named with the bytes of the IP address in reverse order. For example, the zone for 189 subnet in this example is 189.173.63-in-addr.arpa.

The general format of a PTR record

```
addr [tll] [IN] PTR hostname
```

For example, the PTR record in the 189.173.63-in-addr.arpa zone that corresponds to ns1's A record above is

```
1 PTR ns1.atrust.com.
```

The name 1 does not end in a dot and therefore is relative. But relative to what? Not atrust.com—for this sample to be accurate, the default zone has to be "189.173.63-in-addr.arpa."
