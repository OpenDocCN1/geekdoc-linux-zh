+   **share**— The share value for security works works best for just sharing or providing file access that is more public (guest). A client doesn't need to provide a valid username and password to access the server. However, the user typically has a guest level of permission to access and change files. See the “Assigning Guest Accounts” sidebar in this chapter for further information.

+   **server**— From the client's point of view, this is the same as user security when the client still has to provide a valid username/password combination to use the Samba server at all. The difference is on the server side. With server security, the username/password is sent to another SMB server for validation. If that fails, Samba tries to validate the client using user security.

+   **domain**— From the client's point of view, this also looks as same user security. This setting is used only (If the Samba server has been added to a Windows domain (using the smbpasswd command). When a client tries to connect to the Samba server in this mode, its username and password are sent to a Windows NT Primary or Backup Domain controller. This is accomplished the way that a Windows NT server performs validation. Linux user accounts must be set up.

+   **Encrypted passwords**—Controls encrypted passwords can be negotiated with the client. This is on (Yes) by default. For domain security, the value must be Yes. Later versions of Windows NT (4.0 SP3 or later) and Windows 98 and Windows 2000 expect encrypted passwords to be on.

+   **Update encrypted**—Allows users who log in with a plain-text password to automatically update their passwords updated to encrypted passwords when they log in. In many, this option is off. Turn it on when you install an using plain-text passwords to have everyone updated to encrypted password authentication. It saves the trouble of running the smbpasswd command directly from the server. After every update, is updated then, the Encrypted passwords option should be set to No.

+   **PAM restrictions**—Turns this on (Yes) if you want to use PAM for account and session management. Even if activated, PAM is not used if the encrypted passwords are turned on (encrypt passwords=yes). PAM stands for Pluggable Authentication Modules and is used for authenticating host computers and users.

+   **PAM password change**—Indicates the use of the PAM password control flag for Samba. If this is on (Yes), SMB clients will use PAM instead of the program list in the Password Program value for changing SMB passwords.
