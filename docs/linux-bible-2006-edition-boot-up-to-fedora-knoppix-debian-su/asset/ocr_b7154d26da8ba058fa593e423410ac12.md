# Chapter 16 + Running Mandriva 435

**Erase** — Wipes the existing hard disk in preparation for your install. This is a great option for critical server systems or if there is no data on the disk you need.

**Use free space on Microsoft Windows partition** — Exactly what it sounds like. You can use free disk space on the FAT, FAT32, or NTFS partition that houses your Windows installation to house your Mandriva install. Pretty nifty if you want both systems to be able to access all of the files on the system.

**Custom** — Here’s where the real magic happens: You can create custom volumes, resizing volumes, and in general torture your hard drives as much as you like.

Selecting the Custom option opens a new window that shows all the hard drives and configured partitions. If your system has only an Windows installation on an NTFS partition, all that will be visible the markers indicating a Mandriva partition.

Once you click on the partition that you want to use for your Mandriva installation, a new option appears in the left portion of the configuration window. By clicking the Resize button, you can change the size (with limitations) of the existing NTFS partition.

Give it a shot if you have the opportunity. Click the Resize button, and a new window appears. It has a slider that goes all the way to the right by default. As you slide the slider to the left, the corresponding value displayed gets smaller. This number the NTFS partition will be after you’ve completed the resizing operation. For example, if you have a 30GB partition and want to free up 10GB of space for the creation of a native Linux partitions, simply slide the slider from the maximum value of 30000MB to 20000MB, and you will have freed 10000MB.

The amount of space you can create depends on the size of the disk, how much data is stored, and whether the partition has been defragmented. To find out the degree you can resize the partition, move the slider to the left. That displays the smallest size you can make the existing Mandriva partition.

There is a catch to resizing partitions. The 2.6 Linux kernel misreports hard disk geometries, and the incorrect information can cause a flawed partition to be written to the end of the resize. See www.mlf.linux.rulesorg/efaz/ntfsresize.html#troubleshoot for more details.

When you’ve selected the size you want, click the Next button. You are shown a warning to make sure you have backed up any information you depend on before performing the partitioning resizing. If you’re ready to commit, click OK.
