# Messages Delivered by Exim

In some cases, messages will be accepted by the server but will not be deliverable. Some of these errors are considered temporary failures and will not generate a bounced message until the retry timer runs out. The error that you are most likely to see look like this in the mainlog file:

```
1EPTU-0003JN-QY user@example.org R=local_user T-maildrop_pipe deliver (0):
Child of maildrop_pipe transport returned 75 (could mean temporary
error) from command: /usr/bin/maildrop
```

This error indicates that Exim attempted to pass the message to Maildrop, but Maildrop returned an error code. The most likely causes are a missing Maildir directory, or a Maildir directory that is owned by the wrong user. The next section shows how to detect and fix these problems.

# Login Failures When Connecting to Courier

Aside from genuine password errors (which can be remedied by entering the correct password in the mail client), there are also a few conditions that can result in login failures. Some of these conditions will also result in temporary delivery problems. A normal login failure will result in a log entry that looks similar to:

```
courierpop3login: LOGIN FAILED, ip=::ffff:1.2.3.4
```

In this case, after IP 1.2.3.4 entered the wrong username or password.

Several of the other errors that may occur will not be logged to the mail log, which means you may have to test them by connecting to the POP3 service (from the mail server, or from a remote machine) and sending a valid username and password. This example shows how to connect to the POP3 service from a shell server:

```
$ telnet localhost 110
Trying 127.0.0.1...
Connected to localhost.localdomain.
Escape character is '^'.
+OK Hello there.
USER username
+OK Password required.
PASS password
```

The response from the server should be similar to one of the following:

- OK logged in — This is a normal and should mean that there are no problems with the service.

- Maildird: No such file or directory — This indicates that the user's account does not have a Maildir directory. The mailmaird command to create it, is as in the "Installing and Configuring Exim".

- ERR Maildir: Permission denied — this error indicates that the user's Maildir directory cannot be read or belongs to the wrong user. To remedy this, run as root:
  # chown -R username:groupname ~username/Maildir

Be to replace username and groupname with the login name and primary group of the user. In some Debian system, the primary group name will be the same as the username.

- ERR failed — If you're certain that you are using the correct username and password, it could be that the Courier authdaemon service is not running. Try to start (or restart) it using this command:
  # invoke-rc.d courier-authdaemon restart

# Configuring Fetchmail

Fetchmail is an MRA (Mail Retrieval Agent) that you can use to pull mail from a remote account to your server. It is configured in the $HOME/.fetchmailrc and is very easy to set up. To pull mail to your server, log in as the user that the mail should go, and then configure and run it from there.

Run Fetchmail as the user whose mail is being retrieved. You should never run it as root. If you are doing a complex setup which you retrieve mail from a single mailbox that needs to be sorted out for multiple users, use the fetchmail man page for information about multiprod mailboxes.

A .fetchmailrc file can be as simple as this:

```
poll mailserver.example protocol pop3 username "foo"
```

If you have more than one mail server, you can add it as an additional line. If the server from which you are pulling supports IMAP, you can use imap instead of pop3. Other options that you can have password=yourpassword and ssl. Storing the password in the files you run Fetchmail without entering a password, and the ssl option tells Fetchmail to use an SSL/TLS connection to the server.

Your .fetchmailrc file should not be readable by others, and Fetchmail will generally complain if it is. To set the permissions so that only you can read it, run chmod 0600 $HOME/.fetchmailrc.

Running Fetchmail is as simple as typing

```
$ fetchmail
```

If you want to have Fetchmail in the background, you can use the --daemon (or -d) flags with a parameter telling it how often (in seconds) to poll the servers:

```
$ fetchmail --300
```

- 1. Install the Courier daemons with SSL/TLS support:
   # apt-get install courier-imap-ssl courier-pop-ssl
- 2. Secondrd-party CA certificates are provided on the ca-certificates package. This will be referenced in the configuration, so install it, to:
   # apt-get install ca-certificates
Debconf asks you whether you want to trust the CA certificates by default. In most cases, you want to Select.

- 3. If you are going to be using a certificate from a CA that is not already recognized (this is generally only true if you are running your own CA), place the CA certificate in its own file in `/etc/ssl/certs/` and update the certificate database:

```
# update-certificates
```

- 4. Generate the private key and certificate signing request, as described in Chapter 24. The best location for these files is in `/etc/ssl/private/`. Here's an example:

```
# /etc/exim4
# openssl genrsa -out mail.key 1024
# chmod 640 mail.key
# openssl req -new -key mail.key -out mail.csr
# chown root:Debian exim mail.key
```

- 5. Get your CSR (Certificate Signing Request) and place the certificate in `/etc/mail/private/mail.crt`. Or, to use a self-signed certificate, do following:

```
# /etc/exim4
# openssl req -new -x509 -nodes -sha \
# days 365 -key mail.key -out mail.crt
# chmod 640 mail.crt
# chown root:Debian mail.crt
```

Some remote servers will refuse to send messages to your server if your certificate is not signed by a CA that they recognize. Also, make sure the common name (cn) attribute on your certificate matches the name of the server in DNS.

![](img/a2d958d7eab32ca5b89b2b8af808aa70_720_0.png)

- 6. Concatenate the private key and certificate into a single file for Courier:

```
# /etc/courier
# cat /etc/exim4/mail.key /etc/exim4/crt > mail.pem
# chmod 600 mail.pem
```

- 7. Enable TLS in the Courier IMAP and POP daemon by editing your values for `TLS_CERTFILE` and `TLS_TRUSTCERTS` with the following:

```
TLS_CERTFILE=/etc/courier/mail.pem
TLS_TRUSTCERTS=/etc/ssl/certs/ca-certificates.pem
```

- 8. Tell Exim where it can find the key and certificate, and enable TLS. Create a file named `/etc/exim4/conf.d/main/12_exim4-config_local_tlsoptions` containing the following:

```
MAIN_TLS_CERTIFICATE = CONFDIR/mail.crt
MAIN_TLS_PRIVATEKEY = CONFDIR/mail.key
MAIN_TLS_ENABLE = 1
```
