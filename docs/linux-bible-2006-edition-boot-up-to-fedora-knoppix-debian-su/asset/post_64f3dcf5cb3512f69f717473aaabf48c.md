- Linux tries to keep processes with the immediate need in RAM, while managing how processes exceed the available memory are moved to swap space. - Linux was built from the ground up to enable multiple users to access the system simultaneously. In a standard Linux system, the root user has access to the entire system, special logins have access to particular services (such as Apache for Web services), and users are assigned permission individually or in groups. I have described components that make up what is referred as the Linux kernel. In fact, the Linux kernel (which was created and is still maintained by Lin Torvalds) is what gives Linux its name. The kernel is the software starts up when you boot your computer and manages the programs you use to communicate effectively and simply with your computer hardware.

Other components, such as administrative commands and applications, are added to the kernel from free and open source projects to make Linux a complete operating system. The GNU project, in particular, contributed many components that are now in Linux. (GNU, Apache, KDE, GNOME, and other key source projects in Linux are discussed a bit later). # From a Free-Flowing UNIX Culture at Bell Labs

From the very beginning, the UNIX operating system was created and nurtured in a communal environment. Its creation was not driven by market needs, but by a desire to overcome impediments to producing programs. AT&T, which owned the UNIX trademark, eventually made UNIX into a commercial product, but by that time, many of the concepts (and even much of the early code) which made UNIX special had fallen into the public domain.

If you are 30 years old, you might not remember a time when AT&T was "the" phone company. Until the early 1980s, AT&T didn't have to think much about competition if you wanted a phone in the United States, you would have to go to AT&T. It had the luxury of funding research projects. The Mecca for such projects was the Bell Laboratories in Murray Hill, New Jersey.

After the failure of a project called Multics in 1969, Bell Labs employees Ken Thompson and Dennis Ritchie set out to create an operating system that would offer an improved environment for developing software. Up to that time, programs were written on punch cards that had to be fed in batches of frame computers. In a 1980 lecture "The Evolution of the UNIX Time-sharing System," Dennis Ritchie summed the spirit that started UNIX:

What we wanted to preserve was not just an environment in which to do programming, but a system around which a fellowship could form. We knew from experience that the essence of communal computing as supplied by remote-access, time-shared machines is not just to type programs into a ter terminal instead of a keypunch, but to encourage close communication.

The simplicity and power of the UNIX design began breaking down barriers that impeded software developers. The foundation of UNIX was set with several key elements:

- The UNIX file system — Creating the structure that allowed levels of sub-directories (which, for today's desktop users, looks like folders inside folders), UNIX could be used to organize the files and directories in intuitive ways. Furthermore, complex methods of accessing disks, tapes, and other devices were greatly simplified by representing those devices as individual device files that you could access as items in a directory.

- Input/output redirection — Early UNIX systems also included input redirection and pipes. By a command line, UNIX could direct the output of a command to a file using a right arrow (>). Later, the concept of pipes was where the output of one command was directed to the input of another. For example, the command line

```
$ cat file1 | sort | pr
```

(cat) file2, sort (sort) in the lines alphabetically, generates the sorted text for printing (pr), and directs to the computer's default printer (pr). This method of directing input and output enabled developers to create their own specialized tools that could be joined with existing utilities. This modularity made it possible for lots of code to be developed by lots of different people.

- Portability — Much of the early work in simplifying the experience of using UNIX led to it becoming extraordinarily portable to run on different computers. By having device drivers (represented by files in the file system), UNIX could provide an interface to applications in such a way that the programs didn't have to know the details of the underlying hardware. To port UNIX to another system, developers had only to change the drivers. The applications didn't have to change for different hardware!

To make the concept of portability a reality, however, a high-level programming language was needed to implement the software needed. To that end, Brian Kernighan and Dennis Ritchie the C programming language. In 1973, UNIX was rewritten in C. Today, C is still the primary language used to create the UNIX (and Linux) operating system kernels.

As Ritchie went in his 1980 lecture:

Today, the only important UNIX program written in assembler is the assembler itself; virtually all the utility programs are in C, and so most of the applications, although there are sites with many in Fortran, Pascal, and Alg 68 as well. It seems that much of the success of UNIX follows from the readability, modifiability, and portability of its software that in turn follows from its expression in high-level languages.
