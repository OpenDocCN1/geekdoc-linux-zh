# Using Log Files

If you use some firewalling practices as described in Chapter 18, you will be well prepared to mitigate and prevent most cracker attacks. If your firewall should fail to stop an intrusion, you must be able to recognize the attack when it occurs. Understanding the various (and numerous) log files in which Linux records important events is critical to this goal. The log files for your Linux system can be found in the /var/log directory.

# The Role of Syslog

Most of the files in /var/log directory are maintained by syslogd. The syslog daemon is System Logging. It accepts messages from a variety of programs and writes them to the appropriate log files. It is better than having every program write directly to its own log file because it enables you to manage how log files are handled. This is particularly handy because it enables you to centralize the management and reviewing of logs from many systems.

It is not uncommon to run a dedicated loghost, a computer that serves no other purpose to record log messages from other computers. Because this system runs no other services, it is unlikely that it will be broken. This makes it nearly impossible for a cracker to erase his or her tracks, but it does not mean that all of the log entries are accurate after a cracker has broken into a machine on your network. Also, it is important to remember, however, that log messages are not, by default, encrypted. Anyone tapping into your local network can eavesdrop on those messages as they pass from one machine to another.

# Redirecting Logs to a Loghost with syslog

To redirect your log files to another computer's syslog, you may make changes to your local syslog configuration file. /etc/syslog.conf. Become root using the su - command and then the /etc/syslog.conf file in a text editor (such as vi). You should see something similar to this:

```
@ Log all kernel messages to the console.
# Logging much else clutters up the screen.
/dev/console
#kern.*
# Log anything (except mail) of level or higher.
# Don't log private authentication messages!
*.info:mail:none:news:none:authpriv:none:cron:none /var/log/messages
# The authpriv file has restricted access.
authpriv.* /var/log/secure
# Log all the mail messages in one place.
mail.* /var/log/mailog
# Log cron stuff
cron.* /var/log/cron
# Everybody gets emergency messages
*.emerg *
# Save news errors of level crit and higher in a special file.
uucp,news.crit /var/log/spoller
# Save boot messages also to boot.log
local7.* /var/log/boot.log
```
