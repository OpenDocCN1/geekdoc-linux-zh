In this example, the -a option asks to show processes of all users who are associated with your current terminal, and the -u option asks that usernames be shown, as well as other information such as the time the process started and memory CPU usage. The concept of a terminal comes from the old days, when people worked exclusively from character terminals, so a terminal typically represented a single person at a screen. Now you can have many "terminals" on one screen by opening multiple Terminal windows.

On this shell session, it's not much happening. The first process shows that the user named jane logged into the login process (which is controlled by the root user). The next process shows that jane is using a bash shell and has just run the ps -au command. The device tty0 is used for the login session. The STAT represents the state of the process, with R indicating a running process and S representing a sleeping process.

The USER column shows the name of the user who started the process. Each process is represented by a unique ID referred to as an ID (PID). You can use the PID if you ever need to kill a runaway process. The %CPU and %MEM columns show the percentage of processor and access memory, respectively, that the process is consuming. VSZ (virtual size) and RSS (resident set size) show the size of the image process (in kilobytes), and START shows the time the process began, and TIME shows the cumulative system used. (Many commands consume very little CPU time, as is reflected by 0:00 for processes that haven't even a second of CPU time).

Many processes running on a computer are not associated with a terminal. Normal Linux system has many processes running in the background. Background systems perform tasks such as logging system activity or listening for data coming from the network. They are often started when Linux boots up and run continuously until it shuts down. To page through all the processes running your Linux system, add the pipe (|) and the less command to ps -aux, like this:

```
$ ps -aux | less
```

A pipe directs the output of one command to be the input of the next command, in this example, the output of ps (a list of processes) is directed to the less command, which lets you page through that information. Use the spacebar to press q to end the list. You can also use the keys to move one line at a time through the output.

# Exiting the Shell

To exit the shell when you are done, press exit or Ctrl+D.

You've seen a few commands that can help you familiarize yourself with your Linux system. There are hundreds of commands that you can run. You'll find many in /bin and /usr/bin directories, and you can use ls to see a directory's command list: ls /bin, for example, results in a list of commands in /bin. Then use the man command (for example, man hostname to see what each command does). There are also administrative commands in /bin or /usr/sbin directories.

# Using the Shell in Linux

When you type a command in a shell, you can include other characters that change or add to the command works. In addition to the command itself, these are some of the other items that you can use on a shell line:

- Options—Most commands have one or more options you can add to change their behavior. Options typically consist of a single letter, preceded by a dash. You can also combine several options after a single dash. For example, the command -l lists the contents of the current directory. For a detailed -l list of information, and the -a asks for files beginning with a dot (.) also listed. When a single option of a word, it is usually preceded by a double dash(--). For example, to use the help option on many commands, you enter --help on the command line.

You can use the --help option with most commands to see the options and arguments they support. For example, hostname --help.

- Arguments—Many commands also accept certain options after are entered or at the end of the entire command. An argument is an extra piece of information, such as a filename, that can be used by the command. For example, cat /etc/passwd displays the contents of the /etc/passwd file on your screen. In this case, /etc/passwd is the argument.

- Environmental variables—the shell stores information that may be useful to the user's shell session in what are called environmental variables. Examples of environmental variables include SHELL (which identifies the shell you are using), PS1 (which defines your prompt), and $MAIL (which identifies the location of your mailbox). See the "Using Shell Environment Variables" later in this chapter for more information.

You can check environment variables at any time. Type declare to list the environment variables. You can type echo $VALUE, where VALUE is replaced by the name of a particular environment variable you want to list.

- Metacharacters—These are characters that have special meaning to the shell. They can be used to direct the output of a command to a file (>), pipe the output to another command (|), and run a command in the background (&), to name a few. Metacharacters are discussed later in this chapter.

To save some typing, there are features that store commands you want to reuse, recall previous commands, and edit commands. You can create aliases to enable you to type a short command to run a longer one. The shell stores previously entered commands in a history list, which you can display and from which you can recall commands. You will see how this works later in the chapter.

Unless you specifically change to another shell, the bash shell is the one you use with most Linux systems. The bash shell contains most of the powerful features available in other shells. Although the description in this chapter steps you through many bash shell features, you can learn more about the bash shell by typing `bash`, and the sidebar "Getting Help Using the Shell" shows you a few other ways to learn using the shell.

# Locating Commands

If you know the directory that contains the command you want to run, one way to it is to type the full path to that command. For example, you run the `date` command from the `/bin` directory by typing:

```
$ /bin/date
```

Of course, this can be inconvenient, especially if the command resides in a directory with a long path name. The better way is to have commands stored in well-known directories, and then add directories to your shell's PATH environment variable. The PATH consists of a list of directories that are checked sequentially for the commands you enter. See your current path, type the following:

```
$ echo $PATH
/bin:/usr/bin:/usr/local/bin:/usr/X11:/usr/X11R/bin:/home/chris/bin
```

The results show the path for a regular Linux user. Directories in the path are separated by colons. Most commands that come with Linux are stored in `/bin`, `/usr/bin`, or `/usr/local/bin` directories. Although many graphical commands (that are with GUIs) are contained in `/usr/bin`, there are some special X that are in `/usr/X11` and `/usr/X11R/bin` directories. The last directory shown is the directory in the user's home directory.

> If you want to add your own commands or scripts, place them in the bin directory in your home directory (such as /home/chris for the user named chris). This directory is automatically added to your PATH. So as long as you add the command with execution permission (described in the Understanding File Permissions section in this chapter), you can immediately begin using the command by simplifying the command name at your prompt.

The root directory order is important. Directories are checked from left to right. So, in this example, if there is a command called `foo` located in both the `/bin` and `/usr/bin` directories, the one in `/bin` is executed. To have the other `foo` command run, you either type the full path to the command or change your PATH variable. (Changing your PATH and adding directories to it is discussed later in this chapter.)
