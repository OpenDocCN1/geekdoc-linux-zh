Again, with the example of /dev/hda2, an entry in /etc/fstab to mount partition read/write could look as follows:

```
/dev/hda2 /mnt/hda2 ext noauto,users,exec,rw 0 0
```

With that, simply typing /dev/hda2 mounts the directory with read/write permissions. You can save that permanently, as described in the "Keeping Your KNOPPIX Configuration" section in this chapter.

# Monitoring Partitions for Writing

Provided your partitions are properly detected, Windows partitions is no different than Linux partitions. For Windows file system types FAT and VFAT, there is no problem mounting and writing to those file systems. For NTFS partitions, there are a few things you should consider before writing to them.

Earlier versions of KNOPPIX allowed you to download a feature Captive NTFS. With NTFS, you could use Windows drivers to access NTFS partitions from KNOPPIX. This was considered to be reliable enough that you could write to NTFS without much fear of corruption.

The current version of KNOPPIX uses drivers from the Linux-FS (http://linux-fs.sourceforge.net) to provide support for accessing NTFS file systems from Linux. The advantage of using Linux-FS is that NTFS partitions can be mounted and used like any other Linux file system. You don't need Windows drivers. The downside is that writing to NTFS partitions using LinuxFS is considered unreliable and could cause corruption to your NTFS partition. So, I recommend not try to write to an NTFS file system from KNOPPIX, but feel free to read from NTFS during a KNOPPIX session.
