Logging information for the Courier IMAP and POP demons is saved to /var/log/mail.log. Normal entries include LOGIN and LOGOUT messages. DISCONNECTED messages generally indicate that a connection was broken before a normal logout was.

The tail utility is useful for watching for new entries to a log. Use the -f switch to instruct tail to watch for new entries and display them to the screen as they are written to the log. For example: tail -f /var/log/exim4/mainlog

# Common Errors (and How to Fix)

There are two common types of problems that will conflict with your server: messages being rejected or not delivered by Exim and login failures connecting to Courier.

# Messages Rejected by Exim

The first places to check when messages are rejected by Exim are the mainlog and reject files. Here are examples of common errors and tips for fixing them:

The following error indicates that the client sending the message is not recognized as a client by Exim and the recipient domain is not in the list of local or relay domains:

```
H=sample.client [1.2.3.4] f=<sender@example.org> rejected RCPT <rcpt@remotes.example.org>: relay not permitted
```

If the IP address will change frequently or is in part of a trusted IP addresses, you can add it by running the following:

```
$ dpkg-reconfigure --priority=medium exim4-config
```

The same command can also be used to add the recipient domain as a local relay domain.

Do not add IP ranges unless you trust all of the users that can connect from those addresses. Likewise, do not add a domain as a relay domain unless you know the owner of the domain and have made arrangements to relay mail for them. Doing either incorrectly could open your server as a relay that can be used by spammers to attack other sites.
