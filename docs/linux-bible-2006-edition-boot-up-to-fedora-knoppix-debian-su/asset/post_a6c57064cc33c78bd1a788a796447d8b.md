## Installing ClamAV and SpamAssassin

Installing and configuring the virus and spam filtering mechanisms is more involved than installing Exim and Courier, but should still go smoothly as you follow the steps carefully. Keep in mind, however, that this will add a lot of complexity to the system, it is a good idea to make sure the Exim mail server is working first so that you don't have many things to check if the system doesn't work expected.

> The version of ClamAV included with Debian 3.1 (aka "Sarge") uses an older virus-scanning engine. Because the updated engine is not likely to make it into an update time some years because of the Debian upgrade policies, a group of developers have created special sets of ClamAV packages that are designed for easy installation on Sarge. For more information about how to use these packages instead of the stock versions, see http://volatile.debian.net/. You may choose to do this from the start, or to add the appropriate URIs to your APT configuration and do an upgrade. In either case, the configuration process detailed in this section will be the.

Here's how to install ClamAV and SpamAssassin, and then configure Exim to use them for scanning messages:

- 1. Install the ClamAV and SpamAssassin packages:
```bash
# apt-get install clamav-daemon clamav-testfiles \ spamassassin spamc
```

You'll be asked a number of questions about how ClamAV should be configured. Here's how to answer them:

- **Virus update method** — This is the method that freshclam (part of ClamAV) will use to download updated databases. The recommended option is to run freshclam as a daemon.

- **Local database mirror site** — This is the site that freshclam will retrieve the virus information updates from. The second part of the site is the two-letter country code. Select your country code or that of a nearby country if yours isn't available.

- **HTTP proxy information** — Do not enter anything here unless you are required to use a proxy server to access Web servers. If your connection is suitable for running a mail server, you probably don't need to use a proxy server.

- **Notify clam after updates** — Select "yes"

2. Add the clamav to the Debian-exim group and restart the ClamAV daemon. This allows ClamAV access to read the files in Exim's mail queue:

```bash
# gpasswd -a clamav Debian-exim
# invoke rc-d clamav-daemon restart
```

3. Replace the report template used by SpamAssassin with one that will fit better in a message header. Use a text editor to add these lines to the end of /etc/spassassin/local.cf:

```
clear_report_template
YES_NO, score=SCORE_, required=REQD, summary=
report_SUMMARY_
```

4. Configure the SpamAssassin background daemon to run automatically and not to attempt to create preferences for users. Change the following options in /etc/default/spamassin:

```bash
ENABLED=1
OPTIONS="--max-children 5*"
```

5. Start the SpamAssassin daemon:

```bash
# invoke rc-d spamassin-start
```

6. Create the entries that will be included in Exim's ACL (Access Control List) for scanning message data. Use a text editor to create a file named /etc/exim4/acl_check_data_local that contains the following:

```
deny message = $malware_name detected in message
demime = *
malware = *
```

```
warn message = X-Spam-Score: $spam_score ($spam_bar)
condition = ${$if <($message_size)(80k)[1](0)}
spam = nobody:true/defer_ok
warn message = X-Spam-Status: $spam_report
condition = ${$if <($message_size)(80k)[1](0)}
spam = nobody:true/defer_ok
```

The first block rejects messages that contain viruses or malware, and the second and third header handle messages indicating whether or not SpamAssassin considers them. The final block rejects messages having a spam score of higher than 12.
The defer_ok in the last three blocks tells Exim that it is to continue processing in the event that the SpamAssassin daemon could not be connected. You can remove it if you prefer to have the server return a temporary failure in such cases. You can also add /defer_ok to the end of the message = "line" if you want to continue processing in the event that a message cannot be scanned by ClamAV.

- 7. Tell Exim virus scanner to use and how to connect to SpamAssassin. Use a editor to create a file named /etc/exim4/conf.d/main/10_exim4-exiscan_acl_options that contains the following:
```
av_scanner = clamd:var/run/clamav/clamd.ctl
spam_address = 127.0.0.1:783

CHECK_DATA_LOCAL_ACL_FILE = CONFDIR/acl_check_data_local
```

- 8. Tell Exim to load the new configuration:
```bash
# invoke-rc.d exim4 reload
```

All messages transmitted through your server should now be checked for viruses using ClamAV. Additionally, messages with less than 80 kilobytes will also be checked using SpamAssassin. This is a good time to test the configuration again. Fixes for the problems you are most likely to encounter can be found in the next section.

## Testing and Troubleshooting

This section contains generic troubleshooting tips, specific information about some common errors and how to fix them.

## Checking Logs

All logging information for Exim is written to three files: mainlog, rejectlog, and paniclog. The first, mainlog, contains all events. The second, rejectlog contains entries for rejected messages. The third, paniclog is usually empty unless a serious problem has occurred. Every entry in these files starts with a timestamp.

### Exim Log Messages

| Symbol | Description | Explanation |
| :--- | :--- | :--- |
| <= | Message arrival | These entries show messages coming into Exim. |
| => | Message delivery | These entries show deliveries to local or remote host. |
| -> | Additional addresses | These entries show deliveries to another recipient. |
| ** | Delivery failure | These entries show permanent delivery errors. The message is removed from the queue. |
| == | Delivery deferral | These entries show temporary delivery errors. The system will continue to retry sending until delivery succeeds. |

## Common Errors (and How to Fix)

There are two common types of problems that will conflict with your server: messages being rejected by Exim and login failures connecting to Courier.

## Messages Rejected by Exim

The first places to check when messages are rejected by Exim are the mainlog and reject files. Here are examples of common errors and tips for fixing them:

The following error indicates that the client sending the message is not recognized as a client by Exim and the recipient domain is not in the list of local or relay domains:

```
H=sample.client [1.2.3.4] f=<sender@example.org> rejected RCPT <rcpt@remotes.example.org>: relay not permitted
```

If the IP address will change frequently or is part of a trusted range, you can add it by running the following:

```bash
$ dpkg-reconfigure --priority=medium exim4-config
```

The same command can also be used to add the recipient domain as a local relay domain.

Do not add IP ranges unless you trust all of the users that can connect from those addresses. Likewise, do not add a domain as a relay domain unless you know the owner of the domain and have made arrangements to relay mail for them. Doing either incorrectly could open your server as a relay that can be used by spammers to attack other sites.

If the IP address is likely to change frequently and is not part of a trusted range, you should ideally configure the client to use a mail server that is local to it or configure SMTP authentication in Exim.
