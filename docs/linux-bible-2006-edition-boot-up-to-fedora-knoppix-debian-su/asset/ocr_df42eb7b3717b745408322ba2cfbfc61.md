# 786 Part VI ♦ Programming in Linux

This chapter discusses the most popular programs and utilities of the types you in. In most cases, alternatives (and sometimes alternatives) exist, but I cover only one to keep the discussion simple (I try to mention the others just so you're familiar with their names).

What constitutes a well-stocked Linux development toolkit? The basics include an editor to write the code, one or more compilers to turn source code into binaries, and a debugger to track down the inevitable bugs. Most people have a favorite editor, and you'd have a difficult time trying to persuade them to use a new one. Most editors support some of programming-related functionality (some more than others, to be). There are too many to cover in this space, so it is to say: You'll need an editor.

Perhaps the most popular editors are vi and emacs. Vi is a commercial editor, being part of the commercial UNIX offerings, so what you can actually get is usually a clone such vi, elvis, or (my own favorite) nvi (new vi). I prefer nvi because it is part of BSD Unix to Linux. Other popular editors include pico (the Pine mail editor made available as a separate program), jed, jo, and nano. If you prefer graphical editors, gedit in GNOME and KDE also provide basic programming support.

> Chapter 2 has a short tutorial on using the vi editor, as well as short descriptions of other popular open source text editors.

When comes to compilers, GCC is the compiler of code, or, if you will, the choice of the GNU generation, so this chapter discusses only GCC. Other compilers are available for Linux, such as Intel's C and C++ compiler and a very powerful (and expensive) expensive from the Portland Compiler Group. GDB, the debugger, is the only debugger described in this chapter.

In Chapter 28 you examined the role that programming interfaces in simplifying the development task. Interfaces usually include one or more libraries that implement the functionality that interfaces define. Because you need to be able to work with programming libraries, utilities for creating, assembling, and manipulating libraries also occupy the well-stocked programming toolkit.

To this list, most developers would add a build automation tool, such as make, because non-trivial projects need some sort of utility that handles building and rebuilding complicated, multi-file projects with a minimum of effort and time.

Another challenge for large projects is tracking code changes and maintaining record of what changed, when it changed, and who changed it. This task is the province of source code control systems, and this chapter looks at two: RCS and CVS.
