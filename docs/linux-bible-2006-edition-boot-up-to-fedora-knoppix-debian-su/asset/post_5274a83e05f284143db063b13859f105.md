The following procedures are performed from the command line as root user.

Remember that any partition commands can easily erase your disk or make it inaccessible. Back up critical data before using any tool to change partitions! Then be very careful about the changes you make. Keeping an emergency boot disk handy is a good idea, too.

The fdisk command is that available on many different operating systems (although it looks and behaves differently (each)). In Linux, fdisk is a menu-based command. Use fdisk to list all your partitions, type the following (at root user):

```
# fdisk -l
Disk /dev/hda: 40.0 GB, 40020664320 bytes
255 heads, 63 sectors/track, 4865 cylinders
Units = cylinders of 16065 * 512 = 8225280
```

To see if each partition is being used on your current system, type the following:

| Device | Boot | Start | End | Blocks | Id | System |
| /dev/hda | | 1 | 13 | 104391 | 83 | Linux |
| /dev/hda2 | | 14 | | 38716650 | 83 | Linux |
| /dev/hda3 | | 4834 | | 257040 | 82 | Linux swap |

From the output of df, you can see that the root of your Linux system (/) is on the /dev/hda2 partition and that the /dev/hda partition is used for /boot.

```
# df -h
Filesystem Used | Avail | Use | Mounted on |
/dev/hda2 | 37G | 5.4G | 30G | 16% | / |
/dev/hda1 | 99M | 8.6M | 86M | /boot |
none | 61M | | 61% | /dev/sh |
```

If this had a dual-boot system (with Windows 98), you might have seen a Windows partition from fdisk that looked like this:

```
/dev/hda1 * | 83 | 66666+ | b Win95 FAT32
```

You could mount partition in Linux (to get to your Windows files when it is booting):

```
# mkdir /mnt/win
# mount vfat /dev/hda1 /mnt/win
```

Before using fdisk to change your partitions, I strongly recommend using the df -h command to see how your partitions are being defined. This will help reduce the risk of changing or deleting the partition.

To use fdisk to change the partitions, you need to identify the hard disk you are partitioning. For example, the first IDE hard disk is identified as /dev/hda. So, to partition your first IDE hard drive, you can begin (as root user) by typing:

```
# fdisk /dev/hda
```

For different drive types or numbers, /dev/hda is replaced by the name of the device you want to work with. Table 7-1 shows some of your choices.

### Table 7-1 Disk Device Names

| Device | Description |
| --- | --- |
| /dev/hda | For the first IDE hard disk; hdb, hdc, and so on for other IDE disks. |
| /dev/sda | For the first SCSI hard disk; sdb, sdc, and so on for other SCSI disks. |
| /dev/tdd0 | For a RAID device. |
| /dev/idc0 | Also for a RAID device. |

After you started fdisk, type m to see the options. Here is what you can do with fdisk:

- *Delete a partition*—Type d and a partition number, and press Enter. example, /dev/sda2 would be partition number 2. (The deletion won't wait until you change the changes—you can back out to that point.)
- *Create a partition*—If you have free space, you can add a new partition. Type n for a local partition (5 or over) or p for a primary partition (1–4); and a partition number from the available range. Choose the first cylinder number from those available. (The output from fdisk -l earlier will show cylinders being used under the Start and End columns.)
Next, the cylinder number will end with the specific number of megabytes or kilobytes you want: for example, +50M or +104K). You can create an ext3 Linux partition. Again, this isn't permanent until you write the changes.
- *Change the partition type*—Press l to choose the type of file system. Enter the partition number of the number you want to change. Type the number representing the file system type you want to use in hexadecimal code. (Type L at this point to see a list of file system types and codes.) For a Linux file system, use the number 83; for a Linux swap partition, use 82; and for a windows FAT32 file system, use the letter b.
- **Display the partition table**— Throughout this process, feel free to type p to display (print on the screen) the partition table as it stands.
- **Quit or save**— Before you write your changes and make sure it is what you want to be. If you don't like a change you make. If you don't like a change, press Q to exit without saving. If your changes are correct, write them to the partition table.

### Protection from attacks

Denial of Service attacks sometimes try to fill up your hard disk. If /var is on separate partitions, an attack can fill your hard disk.

### Protection from corrupted file systems

If you have only one file system (/), its corruption can cause the system to be damaged. Corruption of a smaller partition can be easier to fix and often allows the computer to stay in..

### 772 Assigning Partitions to Particular Directories

Table 7-2 lists directories that you may want to consider making into separate:

| Directory | Explanation |
| --- | --- |
| /boot | Sometimes the BIOS in older PCs can access only the first 1024 cylinders of your hard disk. To make sure that the information in /boot directory is accessible to the BIOS, create a separate partition (of about 100MB) for /boot and make sure it exists below 1024-cylinder. The rest of your Linux system can exist out of 1024-cylinder boundary if you like. With several better images, there is rarely for /boot to be larger than 100MB. |
| /usr | This directory contains many of the applications and utilities available to Fedora Linux users. Having /usr on a separate partition lets you mount file system as read-only after the operating system has been installed. This prevents attackers from replacing or. A separate partition is also useful if you have diskless workstations. Using NFS, you can share /usr over the network. |
| /var | Your FTP (/var/ftp) and Web-server (/var/www) directories are, by default in many Linux systems, stored under /var. Having a /var partition can prevent an attack on those facilities from corrupting or filling your hard disk. |
| /home | Because your user accounts are located in this directory, having a separate /home account can prevent a reckless user from filling up the hard disk. |
| /tmp | Protecting /tmp from the rest of the hard disk by placing it on a separate partition can ensure that applications that need temporary files in /tmp are able to complete their processing, even if the rest of the disk fills up.
