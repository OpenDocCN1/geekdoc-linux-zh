## BSD Loses Steam

The one source project that had a chance of beating Linux to be the premier open source software project was the venerable old BSD project. By the late 1980s, BSD developers at UC Berkeley realized they had already rewritten most of the Unix source code they received a decade earlier.

In 1989, UC Berkeley distributed its Unix-like code as Net/1 and later (in 1991) as Net/2. Just as UC Berkeley was preparing a complete, Unix-like operating system that was free from all AT&T, AT&T hit them with a lawsuit in 1992. The suit claimed that the software was written using trade secrets from AT&T's Unix system.

The lawsuit was dropped with Novel Unix System Laboratories from AT&T in 1994. But, during that critical time period, there was enough fear and doubt about the quality of the BSD code had gained to point in the fledgling open source community was lost. Many people started looking for another source alternative. The time was ripe for a college student from Finland who working on his own kernel.

Many superbly-minded individuals still prefer BSD over Linux.

## Linus Builds the Missing Piece

1991, Linus Torvalds, a student at the University of Helsinki, Finland, started work on a UNIX-like kernel because he wanted to be able to use the same kind of operating system on his home PC that he used at school. At the time, Linus was using Minix, but he wanted to go beyond the Minix standards permitted.

As noted earlier, Linus announced the first public version of the Linux kernel to the comp.os.minix newsgroup on August 25, 1991, although Linus guesses that the first version didn't actually come out until mid-September of that year (see the International Web site's Linux History page: www.li.org/linuxhistory.php).

Although Torvalds stated that Linux was written for the 386 processor and probably wasn't portable, others persisted in encouraging (and contributing to) a more portable approach in the early versions of Linux. By October 5, Linux 0.02 was released with the original assembly code rewritten in the C programming language, which made it possible to start porting it to other machines.

The Linux kernel was the last—and the most important—piece of code that was needed to complete a whole UNIX-like operating system under the GPL. So, when people started putting together distributions, the name Linux and GNU were what stuck. Some distributions as Debian, however, refer to themselves as GNU/Linux distributions.

Within the next few years, commercial and non-commercial Linux distributions began to emerge. MCC Interim Linux (ftp.mcc.ac.uk/pub/linux/distributions/) was released in the U.K. in February, 1992. Slackware (described in Chapter 14), which was released in April, 1993, is one of the only surviving Linux distributions.

Today, Linus can be described as an open source UNIX-like operating system that reflects a combination of SVD, POSIX, and BSD compliance. Linux continues to aim toward compliance with POSIX as well as with standards set by the new owner of the UNIX trademark, The Open Group (www.unixsystems.org).

The non-profit Open Source Development Labs (www.osdl.org), which employs Linus Torvalds, manages the direction today of Linux development efforts. His sponsors are like a Who's of Linux vendors, including IBM, Red Hat, SUSE (NOVEL), VA HP, Dell, Computer Associates, Intel, Cisco Systems, and others. OSDL's primary charter is to accelerate the growth of Linux in telecommunications and data centers.

Although much of the thrust of corporate Linux efforts is on corporate, enterprise computing, huge improvements are continuing in the desktop area. Well the KDE and GNOME desktop environments improve the Linux experience for casual users. Major efforts are underway to offer critical pieces of desktop components that are still not available in open source versions, including multimedia software and office productivity applications.

## First Steps

There are some aspects of Linux that make it hard for some new users to get started. One is that Linux is typically up to be secure by default, so you need to adjust using an administrative login (root) to make changes that affect the whole computer system. Although this can be a bit inconvenient, trust me, it makes your computer safer than just letting anyone do anything.

For the same reason, many services are off by default, so you need to turn them on and at least minimal configuration to get them going. For someone who is used to Windows, Linux can be difficult because it is different from Windows. But you're reading this book, I assume you want to learn about those differences.

## Features in Linux

For developers, Linux provides a platform that lets them change the operating system as they like and get a wide range of help creating the applications they need. One of the watchdogs of the open source movement is the Open Source Initiative (opensource.org). This is how the OSI website describes open source:

The basic idea behind open source is very simple: When programmers can read, redistribute, and modify the source code for a piece of software, the software evolves. People improve it, people adapt it, people fix bugs. And this can happen at a speed that, if one is to use the slow pace of conventional software development, seems astonishing.

- **Downloadable applications** — If the applications are not delivered with your version, you can download and install them with a single command, using tools as apt and yum.
- **No settings hidden in code or registries** — Once you learn your around Linux, you'll find (given the right permissions on your computer) most configuration is done in plain text files.
- **Master desktop** — The Windows System (providing the framework for your desktop) has been longer than Microsoft Windows. The KDE and GNOME environments provide graphical interfaces (windows, menus, icons, and so) that rival those on Microsoft Windows.
- **Freedom** — Linux, in its most basic form, has no corporate agenda or bottom line. You are free to choose the Linux distribution that suits you, at the code that you write the system, and remove any software you like, and make your computer do what you want it to.
