If you run the program, here's the output you get:

```
$ ./hello
Hello, Linux programming world!
```

The command that executed the hello program because having the current directory in your path is a security risk. That is, instead of a $PATH environment variable that resembles /bin:/usr/bin:/usr/local/bin;, it should be /bin:/usr/bin:/local/bin so that a cracker cannot run a dangerous command in your current directory that happens to match the name of the benign command you really want to execute.

GCC relies on file extensions to determine what kind of source code file it, that is, in which programming language the source code is written. Table 29-1 lists the common extensions and how GCC interprets them.

| Table 29-1 |
| GCC's Filename Conventions |
| Extension | Type |
| .a, .so | Compiled library code |
| .c | C language source code |
| .C, .cc | C++ language source code |
| .i | Preprocessed C source code |
| .ii | Preprocessed C++ source code |
| .m | Objective-C source code |
| .0 | Compiled object code |
| .S, .s | Assembly language source code |
