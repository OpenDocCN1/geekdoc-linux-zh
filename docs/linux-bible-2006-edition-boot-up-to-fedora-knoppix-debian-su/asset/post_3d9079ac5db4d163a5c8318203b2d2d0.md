
# Unmounting NFS File Systems

After an NFS file system is mounted, unmounting it is simple. You use the unmount command with the local mount point or the remote file system name. For example, here are two ways you can unmount maple:/tmp from the local directory /mnt/maple.

```
# umount /tmp
# umount /mnt/maple
```

Other forms work. If maple:/tmp is mounted automatically (from a listing in /etc/fstab), the directory will be remounted the next time you boot Linux. If it is a temporary mount (or listed as noauto in /etc/fstab), it won't be remounted after boot.

> The command is unmount, not unmount. This is easy to get wrong.

If you get the message device busy when you try to unmount a file system, the unmount failed because the file system is being accessed. Most likely, one of the directories in the NFS file system is the current directory for your shell (or the shell of some else on yours). The other possibility is that a command is holding an open file in the NFS file system (such as a text editor). Check your Terminal windows and other shells, and cd out of the directory if you are in, or just close the Terminal windows.

If an NFS file system won't unmount, you can force it (umount -f /mnt/maple) or unmount and clean up (umount -l /mnt/maple). The -l option is usually the best choice because a forced unmount can disrupt a file system that is in progress.

# Other Cool Things to Do with NFS

You can share some directories to make it convenient for a user to work from any of different computers on your network. Some examples of useful directories to share:

- /var/spool/mail — By sharing this directory from your mail server and mounting it on the same directory on other computers on your network, users can access their mail from any of other computers. This saves users from having to download messages to their current computers or having to log in to the server to get mail. There is only one mailbox for each user, no matter where it is accessed.

- /home — This is a similar concept to sharing mail, except that all users have access to their home directories from any of the NFS clients. Again, you would mount home on the same mount point on each client computer. When the user logs in, she has access to all of the startup files and data files contained in her /home/user directory.

If users rely on a shared /home directory, you should make sure that the NFS server exports the directory is fairly reliable. If /home isn't available, the user may not have the startup files to log in correctly, or any of the data files needed to get work done. One workaround is to have a minimal set of startup files (.bashrc, .xdefs and so on) available in the user's home directory when the NFS directory is not mounted.

- /project—Although you do not have to use this name, a common practice among users on a project is to share a directory structure containing files that people need to share so that everyone can work on original files and keep copies of the latest versions in each. (Of course, a best way to manage a project is with CVS or some other version control-type software, but this is no person's way to do it.)

- /var/log—An administrator can track log of files from several different computers by mounting the /var/log file on the administrator's computer. (Each server may mount the export to the directory for this work) If there are problems between the computers, the administrator can then easily see the shared log files live.

If you are working exclusively with Linux and other UNIX systems, NFS is probably your best choice for sharing file systems. If your network consists primarily of Microsoft Windows computers or a combination of systems, you may want to look into Samba for file sharing.

# Setting Up a Samba File Server

Samba is a software package that enables you to share file systems and printers on a network with computers that use the Session Message Block (SMB) protocol. This package is distributed with most Linux flavors but can be obtained from www.samba.org if you do not find it on your distribution. SMB is the protocol that is delivered with Windows operating systems for sharing files and printers. Although you can't always count on NFS being installed on Windows clients (unless you install it yourself), SMB is always available (with a bit of setup).

In Windows file and printer sharing, SMB is sometimes referred to as CIFS (Common Internet File System), which is an Internet standard network file system definition based on SMB, or NetBIOS, which was the original SMB communication protocol.

The Samba software package contains a variety of daemon processes, administrative tools, user tools, and configuration files. To do basic Samba configuration, start with the Samba Server Configuration window, which provides a graphical interface for configuring the server and settings to share.

Most of the Samba configuration you end up in the /etc/samba/smb.conf file. If you need to access features that are not available through the Samba Configuration window, you can edit /etc/samba/smb.conf by hand or use SWAT, a Web-based interface, to configure Samba.

Daemon processes consist of smbd (the SMB daemon) and nmbd (the NetBIOS name server). The smbd daemon makes the file-sharing and printing services you add to your Linux system available to Windows client computers. The Samba package supports the following client computers:

- Windows 9x
- Windows NT
- Windows ME
- Windows 2000
- Windows XP
- Windows workgroups
- Windows 3.0
- OS/2
- Macintosh
- Linux

For administrative tools for Samba, you have several shell commands: testpar, with which you can check your configuration; smstatus, which tells you what computers are currently connected; and mblookup, with which you can query Samba. Samba uses the NetBIOS service to share resources, but the underlying network must be configured for TCP/IP. Samba supports only TCP/IP.

# Getting and Installing Samba

You can get Samba software in different ways, depending on your distribution. Here are a few examples:

- Debian — To use Samba in Debian, you must install the samba and smbclient packages using apt-get. Then start the Samba service by running the appropriate scripts from the /etc/init.d directory, as follows:

```
# apt-get install samba samba-common smbclient
# /etc/init.d/samba start
# /etc/init.d/smb-client start
```

- Gentoo — With Gentoo, you need to have net-fs support in the kernel to use Samba features. Installing the net-fs package should get the required packages. To start the service, run rc-update and start it immediately:

```
# emerge samba
# rc-update add samba default
# /etc/init.d/samba start
```

- Fedora Core and other Red Hat Linux — You need to install the samba, samba-client, samba-common, and optionally, the system-config-samba-swat packages to use Samba in Fedora. You can then start Samba using the service and chkconfig commands as:

```
# service samba start
# chkconfig smb on
```

The commands and configuration files are the same on most Linux systems using Samba. The Samba project itself comes with a Web-based interface for administering Samba called Samba Web Administration Tool (SWAT). For someone setting up Samba for the first time, SWAT is a good way to get it up and running.

If your Linux distribution does not help documents for Samba available, consult the documentation on the Samba project home page (www.samba.org). Also, check the extensive help information that comes with SWAT.

# Configuring Samba with SWAT

In addition to offering an extensive interface to Samba options, SWAT also comes with an excellent help facility. And if you need to administer Samba from another computer, SWAT can be configured to be remotely accessible and secured by requiring an administrative login and password.
