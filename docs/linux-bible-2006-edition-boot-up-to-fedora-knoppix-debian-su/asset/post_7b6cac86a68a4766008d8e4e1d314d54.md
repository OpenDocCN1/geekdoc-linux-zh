After the word type, you can see the type of file system contained on the device. (The description of different file system types later in this chapter.) Particularly on Linux systems, you may have multiple partitions for several:

- Multiple hard disks — You may have several hard disks available to your users. In that case you would have to mount each disk (and possibly several partitions from each disk) in different locations in your file system.

- Protecting partitions of the file system — If the users on a system all all of the file system space, the entire system can fail. For example, there may be no place for temporary files to be copied (so the programs writing to temporary files fail), and incoming mail fail may be written to mail boxes. With multiple partitions, if one partition runs out of space, the others can continue to work.

- Backups — Some ways exist to back up data from your computer involving copying the entire image of a disk or partition. If you want to restore that partition later, you can simply copy it (bit by bit) to a hard disk. With smaller partitions, this approach can be done efficiently.

- Protecting from disk failure — If one disk (or part of one disk) fails, having multiple partitions mounted on your file system may enable you to continue working and fix the one disk fails.

When a partition is mounted on the Linux system, all directories and subdirectories below that mount point are stored on that partition. So for example, if you were to mount one partition on / and one on /, everything below the /usr mount point would be stored on the second partition while everything else would be stored on the first partition. If you then mounted another partition on /usr, everything below that mount point would be on the third partition, while everything else below /usr would be the second partition.

> What happens if a remote file system is unmounted from your computer, and you to save a file in that mount point? You will write the file to directory and it will be stored on your hard disk. When the remote file system is remounted, the file saved will seem to disappear. To get the file back, you will have to unmount the remote file system (causing the file to reappear), move the file to another location, remount the file system, and copy the file back there.

The /boot directory holds the images needed to boot the operating system. The /home file system is where all the user accounts are typically

The fact that multiple partitions are mounted on your file system is invisible to people using your Linux system. It is an issue only when a partition runs out of space or if users need to save or use information from a particular device (such as a floppy disk or remote file system) that isn't mounted. Of course, any user can check this by typing the mount command.

# Mounting File Systems

Most of your hard disks are mounted automatically for you. When you install Fedora, Ubuntu, and other Linux systems, you are asked to create partitions and mount the points for those. (Other Linux installation procedures expect you to know that you have to partition before beginning.) When you boot Linux, all partitions residing on hard disk are listed in your /etc/fstab file are typically mounted. For that reason, this section focuses mostly on how to mount other types of devices so they become part of your Linux system.

The mount command is used not only to mount devices but also to mount other kinds of files on your Linux system. This means that you can store files from other operating systems or use file systems that are appropriate for certain kinds of activities (such as writing large block sizes). The most common use of this feature for the average Linux user, however, is to enable you to obtain and work with files from floppy disks, CD-ROMs, or other removable media.

> With the addition of automatic mounting features and changes in removable media are identified with the Linux 2.6 kernel (descriptions of Udev and HAL earlier in this chapter), you no longer need to manually mount removable media for many Linux desktop systems. Understanding how to manually mount and unmount file systems on a Linux server, however, can be a very useful skill.

# Supported File Systems

To see file types that are currently available to be used on your system, type cat /proc/filesystems. Table 4-4 shows the file types that are supported in Linux, although they may not be in use at the moment or they may not be built into your current kernel (so they may need to be loaded as modules).
