With the file safely checked into the repository, you can check it out and modify it.
to check a file out for editing, use the `co` command. Here's an example:

```
$ co howdy.c
RCS/howdy.c,v --> howdy.c
revision 1.1 (locked)
```

The working file you just checked out is editable. If you do not want to edit it, omit
t `-1` option.

# Making Changes to Repository Files

To see version in control, make a change to the working file. If you haven't
already done, check out and lock the howdy.c file. Change anything you want,
but I recommend adding `\n` to the end of `printf()`'s argument because
Linux (UNIX), unlike DOS and Windows, do not automatically add a newline
to the console output.

Next, check the file back in RCS will increment the revision number to 1.2, ask
for a description of the change you made, incorporate the changes you made into
the RCS file, and (anningly) delete the original. To prevent deletion of your work-
files during check-in, use the `-l` or `-u` option with `ci`. Here's an
example:

```
$ ci -l howdy.c
RCS/howdy.c,v <- howdy.c
new revision: 1.2; previous revision: 1.1
enter log message, terminated with single '.' or end of file:
>> Added newline
>>
done
```

When using `ci`, both the `-l` and `-u` options cause an implied check-out of the
file after the check-in procedure. `-l` locks the file so you can continue to
edit, while `-u` checks out an unlocked or read-only working file.

# Additional Command-Line Options

In addition to `-l` and `-u`, `ci` can accept other very useful options: `-r` (for
revision) and `-f` (force). Use `-r` to tell RCS which revision you want to manu-
late. RCS assumes you want to work with the most recent revision: `-r` overrides
default. The `-f` option forces RCS to overwrite the current working file. By default,
RCS abort a check-out operation if a working file of the same name already exists
in your working directory. So if you bot up your working file, use the `-f
option with `co` to get a fresh start.
