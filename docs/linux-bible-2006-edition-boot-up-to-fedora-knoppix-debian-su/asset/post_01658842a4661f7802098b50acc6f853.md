# Adding Environment Variables

You may adding a few environment variables to your .bashrc file. These can help make working with the shell more efficient and effective:

- * TMOUT—Sets how long the shell can be inactive before bash automatically exits. The value is the number of seconds for which the shell has not received input. This is a nice security feature, in case you leave your desk while you are still logged in to Linux. As so not to be logged off while you are working, you may want to set the value to something TMOUT=1800 (to allow 30 minutes of idle time).

- * PATH—As described earlier, the PATH variable sets the directories that are searched for commands. If you often use directories of commands that are not in your PATH, you can permanently add them. To do this, add a PATH variable to your .bashrc file, to add a directory called /getstuff/bin, add the following:

```
PATH=$PATH:/getstuff/bin ; export PATH
```

This example first reads all current directories into the new PATH ($PATH), adds the /getstuff/bin directory, and exports them to the PATH.

Some people add the current directory to your PATH by adding a directory simply as a dot (.), as follows:

```
PATH=:$PATH ; export PATH
```

This lets you runs commands in your current directory (which may be used to you if they have used DOS). The security risk with this procedure is that you could be in a directory that contains a command that you don't intend to run from that directory. For example, a hacker could put an in listing of the content of your directory, does something vicious.

- * WHEVER—You can create your own environment variables to provide shortcuts in your work. Choose any name that is not being used and assign a useful value to it. For example, if you do a lot of work with files in the /work/time/files/info/memos directory, you could set the following variable:

```
M=/work/time/files/info/memos ; export M
```

You could make your current directory by typing `cd $M`. You could run a program from that directory called hotdog by typing `$M/hotdog`. You could edit a file from there called by typing `vi $M/bun`.

# Adding Aliases

Aliases can save you even more typing than setting environment variables. With aliases, you can have a string of characters execute an entire command line. You can add and list aliases with the `alias` command. Here are some examples:

```
alias p='pwd' ; ls -CF'
alias rm='rm -i'
```

In the first example, the letter `p` is assigned to run the command `pwd`, and then it runs `ls -CF` to print the current working directory and its contents in column. The second runs `rm` command with the `-i` option each time you simply type `rm`. (This is an alias that is set automatically for the root user, so that instead of just removing files, you are prompted for each individual file removal. This prevents you from removing all the files in a directory by mistakenly typing something as `rm *`).

While you are in the shell, check which aliases are set by typing the `alias` command. If you want to remove an alias, type `unalias`. (Remember that the `alias` is in a configuration file, it will be set again when you open another shell.)

# Using Environment Variables

Every active shell stores pieces of information that it needs to use in what are called environment variables. An environment variable can store things such as locations of configuration files, mailboxes, and path directories. You can also store values for your shell prompts, the size of your history list, and type of operating system.

To see the environment variables currently assigned to your shell, type the `declare` command. (It will probably fill more than one, so type `declare I more.`.) You can refer to the value of any of those variables by preceding it with a dollar sign (`$`) and placing it anywhere on a command line. For:

```
echo USER
chris
```

This command prints the value of the `USER` variable, which holds your username (chris). Substitute any other value for `USER` to print its value instead.

# Common Shell Environment Variables

When you start a shell (by logging in or opening a Terminal window), a lot of environment variables are already set. Table 2-8 shows some variables that are either set when you use a bash shell or can be set by you to use with different features.

| Table 2-8 | Common Shell Environment Variables |
| Variable | Description |
| BASH | Contains the full path of the bash command. This is usually /bin/bash. |
| BASH_VERSION | A number representing the current version of the bash command. |
| EID | This is the effective user ID of the current user. It is assigned when the shell starts, based on the user's entry in the /etc/passwd file. |
| FCEDIT | If set, this variable indicates the text editor used by the fc command. If it isn't set, the vi command is used. |
| HISTFILE | The location of your history file. It is typically located at $HOME/.bash_history. |
| HISTFILESIZE | The number of history entries that can be stored. After this number is reached, the oldest commands are discarded. The default value is 1000. |
| HISTCMD | This returns the number of the current command in the history list. |
| HOME | This is your home directory. It is your working directory each time you log in or type the cd command with any options. |
| HOSTYPE | A value that describes the computer architecture on which the Linux system is running. For Intel-compatible PCs, the value is i386, i486, i586, i686, or something like i386-linux. For AMD 64-bit machines, the value is x86_64. |
| MAIL | This is the location of your mailbox file. It is typically your username in the /var/spool/mail directory. |
| OLDPWD | The directory that was the working directory before you changed to the current working directory. |
| OSTYPE | A name identifying the operating system. For Fedora, the OSTYPE value is either linux or linux-gnu, depending on the type of shell you are using. |

# Set Your Own Environment Variables

Environment variables provide a way to store information that you use from the shell. You can create any variables that you want (avoiding those that are already in use) so that you can read in the values of those variables as you use the shell. (The bash man page lists variables already in use.)
