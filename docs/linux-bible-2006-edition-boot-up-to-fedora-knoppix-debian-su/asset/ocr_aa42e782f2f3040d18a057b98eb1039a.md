# Source Code Control

Version control is an automated process for keeping track of and managing changes made to source code files. Why bother?

+   * One day you will make one fatal edit to a source file, delete its predecessors, and forget exactly which line or lines of code you "fixed"
* Simultaneously keeping track of the current release, the next release, and eight bug fixes manually become mind-numbing and confusing
* Frantically searching for the backup tape because one of your colleagues overwrite a source file for the fifth time will drive you to the edge

 One day, over your morning cappuccino, you will say to yourself, "Version control, it's the Right Thing to Do."

# Source Code Control Using RCS

The Version Control System (RCS) is a common solution to the version control problem. RCS, which is maintained by the GNU project, is available on almost all UNIX systems, not on Linux. Two alternatives to RCS are the Concurrent Version System (CVS), which is also maintained by the GNU project, and the Source Code Control System (SCCS), a proprietary product.

Before you proceed, however, Table 29-5 lists a few terms that will be used throughout the chapter. Because they are frequently used, I want to make sure you understand their meaning as RCS and version control in general are concerned.

| Table 29-5 |
| Version Control Terms |
| Term | Description |
|---|---|n| Lock | A work retrieved for editing such that no one can edit it simultaneously. A work is locked by the first user against edits by others |
| RCS file | Any file in an RCS directory, controlled by RCS, and accessed using RCS commands. An files contain all versions of a particular file. Normally, RCS has a .v extension. |
| Revision | A specific, numbered version of a source file. Revisions begin with 1.1 and increase incrementally, unless forced to use a specific version number. |
| Working file | One or more files retrieved from the RCS source repository (the RCS directory) into the current working directory and available for editing. |
