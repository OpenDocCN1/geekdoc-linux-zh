# Using the GCC Compiler

The GNU Compiler Collection (GCC) is by far the dominant compiler (rather, the most dominant collection of compilers) on Linux systems. It compiles programs written in C, C++, Objective-C, Fortran, Java, and Ada. This chapter focuses on the Compiler.

GCC gives programmers extensive control over the compilation process. That includes up to four stages: preprocessing, compilation, assembly and linking. You can stop the process after any of these stages to examine the compiler's output at that stage. GCC can also handle the various dialects, such as ANSI C or traditional (Kerrigan and Ritchie) C. You can control the amount and type of debugging information, if you want, in the resulting binary. And like most compilers, GCC performs code optimization.

The gcc command invokes the C Compiler. To use it, provide the name of a C source file and its -o option to specify the name of the output. gcc will process, compile, assemble, and link the program, generating an executable, often called a binary. Here is the simplest syntax:

```
gcc infile.c -o output
```
infile.c is a C source file and -o says to name the output file. If the name of the output file is not specified, gcc names the output a.out by default.

The following example uses gcc to create the hello program from the source file hello.c:

```c
/*
 * hello.c - canonical hello program
 */
#include <stdio.h>

int main(int argc, char *argv[]) {
    printf("Hello, Linux world!\n");
    return 0;
}
```

To compile and run this program,

```
gcc hello.c -o hello
```
If all goes well, gcc does its job silently and returns to the shell prompt. It compiles and links the source file hello.c, creating a binary named hello, as specified using the -o argument.

If you run the program, here's the output you get:

```
$ ./hello
Hello, Linux world!
```
The command that executed the hello program because having the current directory in your path is a security risk. That is, instead of a $PATH environment variable that resembles /bin:/usr/bin:/usr/local/bin;, it should be /bin:/usr/bin:/local/bin so that a cracker cannot run a dangerous command in your current directory that happens to match the name of the benign command you want to execute.

GCC relies on file extensions to determine what kind of source code file it is, that is, in which programming language the source code is written. Table 2-1 lists the common extensions and how GCC interprets them.

| Table 2-1 | GCC's Filename Conventions |
| Extension | Type |
| .a, .so | Compiled library code |
| .c | C language source code |
| .C, .cc | C++ language source code |
| .i | Preprocessed C source code |
| .ii | Preprocessed C++ source code |
| .m | Objective-C source code |
| .0 | Compiled object code |
| .S, .s | Assembly language source code |
