
## Configuring Apache to Support SSL/TLS

Once your keys have been generated, you need to install the mod_ssl Apache module, which adds SSL/TLS support to Apache, and then configure it using the appropriate configuration directives. Here's how:

- 1. SSL and TLS support can be added to Apache by installing the mod_ssl package:
```bash
# apt-get install libapache2-mod-ssl
# apache2conf enable mod_ssl
```
Replacing config file /etc/apache/modules.conf with new version
- 2. Add an SSL-enabled virtual host to your Apache configuration files. Using the earlier virtual host as an example, your configuration will look something like this:

```
Listen *:443
<VirtualHost *:443>
  ServerName secure.example.org
  DocumentRoot /home/username/public_html/
  User username
  Group groupname
  DirectoryIndex Index.php index.htm
  SSLEngine On
  SSLCertificateKey /etc/apache/ssl.key/server.key
  SSLCertificate /etc/apache/ssl.crt/server.crt
  SSLCACertificate /etc/apache/ssl.crt/ca.crt
</VirtualHost>
```

This example uses a wildcard for the IP in the VirtualHost declaration, which saves you from modifying your configuration file in the event where your IP address changes but prevents you from having multiple virtual hosts. In the event that you need to support more than one SSL virtual host, replace with the specific IP address that you assign to that host.

> See the "troubleshooting" section earlier in the chapter for more information about the Listen directive.

A CA generally provides you with a certificate file to place in ca.crt and also provides you with a separate file that you will need to reference using an SSLCertificateChain directive. The mod_ssl package also includes an /etc/apache/ssl.crt/ca-bundle.crt, which contains the certificates from most of the well-known certificate authorities and can be referred to as long as the appropriate CA certificate is installed. When referring your own CA, point this directive to a file containing the public key from that CA. Omit this line when using a self-signed certificate.

## About the system and the software used

The mail server configuration described in this chapter is based on Exim. With Exim, several other components are added for managing e-mail and checking for spam and viruses:

- Exim (http://www.exim-mta.org/) is an MTA written and designed by Philip Hazel at the University of Cambridge, with contributions from many people around the world. The version referred to in this chapter includes Exiscan-ACL (http://duncanthrax.net/exiscan-acl/) packages from Tom Kner. Because this patch allows content scanning within Exim, its features are considered part of Exim for the purpose of this chapter.

- Maildrop (http://www.flunder.net/~msam/maildrop/) is a local MDA that is part of the Courier MTA, but is also available as a standalone program. It is used in this configuration to allow the use of advanced features, such as mailbox queries and server-side sorting.

- Courier IMAP and POP (http://www.courier-mta.org/imap/), like Maildrop, are parts of the Courier MTA that are also available separately. They were chosen for their easy installation, performance, and compatibility with the Maildir format.

- ClamAV (http://www.clamav.net) is an open source virus scanner that detects more than 20,000 viruses, worms, and Trojans. It uses a virus pattern database to identify viruses and a program named clam handles the database automatically. Like SpamAssassin, ClamAV includes a daemon (clamd), a client (clamdclient), and a second command-line tool that does not use the daemon (clamscan).

- SpamAssassin (https://spamassassin.org/) is a spam-filtering program written in Perl. It uses a large set of rules to determine how "spammy" a message looks and assigns a score based on the total of rule values. For performance reasons, SpamAssassin uses a background daemon called spamamd to perform message analysis. Access to this daemon is performed through the spamc client. A spamassassin command that performs the analysis without using spamd is also installed but is not used by either of the example cases in this chapter.
