
## Securing Linux

Since the dawn of interconnected networks, some users have been trying to break into other users' systems. The Internet has grown and broadband Internet access has secured, the problem has become even more severe. A home computing with an insecure configuration can be used as a powerful mail relay, or allow the user's personal information to become compromised, or any number of other horrors.

Once a time network attacks required some effort and skill on the part of the attacker. Automated tools can get the most novice user up and running trying to compromise network-attached systems in an alarming short time. Additionally, attackers have the capacity to turn large numbers of insecure systems into an army of "zombies" usable for massive, coordinated, distributed Denial of Service (DDoS) attacks.

Why should you care about security? According to the Internet Storm Center (http://isc.sans.org/), a computer connected to the Internet has an average of 16 minutes before it falls under some form of attack. Securing any computer system is not difficult; it requires some common sense and careful application of good security practices.

In many cases, good practices for securing and protecting systems, monitoring log files, and creating good firewalls will keep out many would-be-intruders. Sometimes, more proactive approaches are needed to respond to break-ins.

Many tasks associated with securing your Linux system are common to desktop and server systems. However, because servers allow some level of access by outside clients, there are special considerations for protecting servers.

This chapter describes general tasks for securing Linux systems and techniques for securing desktop and server systems. It then describes some tools you can try out from a bootable Linux system to troubleshoot your computer and network.

## Linux Security Checklist

While most Linux systems offer all the tools you need to secure your computer, if you are reckless someone (and probably will) will harm your system, take it over, or steal your data. Keep in mind that no security measures are 100% reliable and that, by giving physical access to a computer or an unlimited amount of time to break in, a skilled and deterministic cracker can break into any computer.

That, however, there are many safeguards you can take to improve your chances of keeping your Linux system safe. The following checklist covers a range of security features to protect your Linux desktop or server.

- **Control physical access.** Keeping your computer behind locked doors is a good idea, especially if it contains critical data. You can limit what a person can do to your computer with physical access by enabling passwords in the BIOS (to prevent the computer from booting at) and in the GRUB or LILO boot loader. You can also limit which devices can be booted in the BIOS.

- **Add users and permissions.** Creating user accounts (each with a password) is your first line of defense in keeping your data secure. Accounts are protected from each other, as well as from an outsider who takes over one user account. Setting up group accounts can extend the concept of ownership to multiple users. See Chapter 4 for setting up user accounts and "Using Password Protection" later in this chapter.

- **Read, write and execute permissions.** Every item in a system (including files, directories, applications, and devices) can be restricted by read, write, and execute permissions for that item's owner and group, as well as all others. In this, for example, you can let others run a command or a file, allowing them to change it. See Chapter 2 for information on setting file and directory permissions.

- **Protect the root user.** In standard Linux systems, the root user (as well as other user accounts such as apache) has special abilities to change and use your Linux system. Protect the root account's password and do not use the root account when you don't need to. An open shell or desktop owned by the root user can be a target for attack. Running graphical administration commands as a regular user (entering the root password as prompted) using sudo can reduce exposure to attacks on your root account. See Chapter 4 for information on handling the root user account.

- **Use trusted software.** While there are no guarantees about any open source software, you have a better chance of avoiding compromised software by using an established Linux distribution (such as Fedora, Debian, or SUSE). Software repositories where you get add-on packages or updates should be wisely scrutinized. Using valid GPG public keys can help ensure that the software you install comes from a valid vendor. And, of course, always be of the source of data files you receive before installing them in a Linux application. If you download full ISO images of a distribution, check their integrity using MD5 or SHA1 checksums proved from their creator.

- **Get secure updates.** As vulnerabilities and bugs are discovered in software packages, every major Linux distribution (Debian, SUSE, and Red Hat distributions) offers tools for getting and installing these updates. Be sure to get these updates, especially if you are using Linux as a server. These tools include apt, yum, and emerge.

- **Use secure applications.** Even with software that is valid and working, some applications offer better protection from attack or invasion. For example, if you want to log in to a computer over the Internet, the secure shell service (ssh) is considered more secure than login or telnet services. Also, some services that are thought to be insecure if you expose them on the Internet (such as Samba and NFS) can be used more securely over the Internet through VPN.

- **Use restrictive firewalls.** The main purpose of a firewall is to control access to and from your network. You can use rules to determine which traffic is allowed and which is blocked. For information on how to configure a firewall, see Chapter 12.

- **Enable only what is needed.** The <a href="http://www.w3.org/TR/html41/inter.html#h400">principle of least privilege</a> states that a user or program should have only the minimum permissions necessary to perform its task. By disabling services and ports that you do not use, you reduce the attack surface of your system.

- **Monitor log files.** Log files contain a record of events that have occurred on your system. By regularly looking at these files, you can detect suspicious activity or system problems. For information on how to monitor logs, see Chapter 10.

- **Check for vulnerabilities.** New vulnerabilities are discovered constantly. It is important to keep your software updated to protect against these threats. You can use various tools to scan your system for vulnerabilities.
