# Linux File Systems Versus Windows-Based File Systems

Although similar in many ways, the Linux file system has some striking differences from file systems used in MS-DOS and Windows operating systems. Here are a few:

- MS-DOS and Windows file systems, drive letters represent different storage devices (for example, A: is a floppy drive and C: is a hard disk). In Linux, all storage devices are fit into the file hierarchy. So, the fact that all of /usr may be on a separate disk or /mnt/rem1 is a file system from another computer is invisible to the user.
- Slashes, rather than backslashes, are used to separate directory names in Linux. So, C:\home\chris in an MS system is /home/chris in a Linux system.
- Filenames always have suffixes in DOS (such as .txt for files or .doc for word-processing). Although at times you can use that convention in Linux, three-character suffixes have no required meaning in Linux. They can be useful for identifying a file type. Many Linux applications and desktop environments use suffixes to determine the contents of a file.
- Every file and directory in a Linux system has permissions and ownership associated with it. Security varies among Microsoft systems. Because DOS and MS Windows began as single-user systems, file ownership was not built into those systems when they were designed. Later releases added features such as file and folder attributes to address this problem.

The following steps lead you through creating directories within your home directory and moving among your directories, with a mention of setting appropriate permissions:

- 1. Go to your home directory. To do this, simply type cd. (For other ways of referring to your home directory, see the “Identifying Directories” sidebar).

- 2. To make sure that you go to your home directory, type pwd. When I do this, I get the following response (yours will reflect your home directory):

```
$pwd
/home/chris
```

- 3. Create a new directory in your home directory, as follows:

```bash
mkdir test
```

- 4. Check the permissions of the directory:

```bash
ls -ld test
```

The output might look like `drwxr-xr-x 2 chris chris 4096 Oct 12 10:00 test`. The `d` indicates it is a directory. The `rwxr-xr-x` shows the permissions: the owner (chris) has read, write, and execute permissions; the group and others have read and execute permissions.

- 5. To change the permissions of a file or directory, use the chmod command. For example:
chmod 755 test
This changes the permissions so the owner has read, write, and execute permissions, while others have read and execute.

- 6. To move among directories, use the cd command. For example:
cd test
To return to your home directory, simply type:
cd

# Identifying Directories

There are several ways to refer to directories in Linux:

- ~ represents your home directory.
- . represents the current directory.
- .. represents the parent directory (the one level up).

You can use the pwd command to see where you are currently located:

```bash
$pwd
/home/chris
```

# Using File-Matching Metacters

The shell uses special characters called metacharacters to match filenames. Here are some useful metacters:

- * — Matches any sequence of characters.
- ? — Matches one character.
- [...] — Matches any of the characters within the brackets.
- [^...] — Matches any character not within the brackets.

Try out some of these metacters by first going to an empty directory and creating some files:

```bash
touch apple banana grapefruit watermelon
```

The next few commands show how you use shell metacters with the ls command to match filenames:

```bash
$ls a*
apple
$ls g*
grape
grapefruit
$ls g*t
grapefruit
$ls *e*
apple grape watermelon
$ls *n*
banana watermelon
```

The first example matches any files that begins with an a (apple). The next matches any files that begin with g (grape, grapefruit). Next, files beginning with g and ending in t are matched (grapefruit). Next, any file that contains an e in the name is matched (apple, grape, watermelon). Finally, any file that contains an n is matched (banana, watermelon).

Here are a few examples of pattern matching with the question mark (?):

```bash
$ls ???e
apple
$ls ???*
grape grapefruit
```

The first example matches any five-character file that ends in e (apple, grape). The second matches any file that begins with g and has e as its fifth character (grape, grapefruit).

Here are a couple of examples using brackets to pattern matching:

```bash
$ls [abw]*
apple banana watermelon
$ls [agw]*[ne]
apple watermelon
```

In the first example, any file beginning with a, b, or w also is matched. In the second, any file that begins with a, g, or w also ends with either n or e is matched. You can also include range within brackets. For example:

```bash
$ls [a-g]*
apple banana grape grapefruit
```

Here, any filenames beginning with a letter from a through g is matched.
