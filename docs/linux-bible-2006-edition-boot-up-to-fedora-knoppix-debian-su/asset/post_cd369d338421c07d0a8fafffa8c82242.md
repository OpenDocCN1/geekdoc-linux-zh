Here's how to set up SWAT in Fedora Core and other Red Hat Linux systems:

- 1. Turn on the SWAT service by typing the following, as root user, from a Terminal window:

```
# chconfig swat on
```

- 2. Pick up the change to the service by restarting the xinetd startup script as follows:

```
# service xinetd restart
```

Linux distributions such as Debian, Slackware, and Gentoo turn on SWAT service from the xinetd superserver daemon. When SWAT is installed, you simply remove the comment character from the swat line in the /etc/xinetd.conf file (as root user, using any text editor) and restart the daemon. There's an example of what the swat line in Debian:

```
swat stream tcp nowait.400 /usr/sbin/tcpd /usr/sbin/swat
```

With the SWAT service ready to be activated, restart the xinetd daemon as it rereads the xinetd.conf file. To do that in Debian, type the following as root user:

```
# /init.d/xinetd restart
```

The init.d script and xinetd services are the two ways that SWAT services are generally started in Linux. If you are using a Linux distribution other than Fedora or Debian, look in the /etc/xinetd.conf file or /etc/xinetd.d directory (which is used automatically in Fedora), for the location of your SWAT service.

When you have finished this procedure, a daemon will be listening on your network interfaces for requests to connect to your SWAT service. You can now use the SWAT program, described in the next section, to configure Samba.

# Base Options

The following options relate to basic information associated with your Samba server:

- **Workgroup** — The name of the group associated with the group of SMB hosts. By default, the value for this field is `WORKGROUP`.

- **Realm** — If you are using kerberos authentication, this value indicates the kerberos realm to use. Typically, it is reflected by the host name of the server providing the service.

- **NetBIOS name** — The name assigned to this Samba server. You can use the same name as your DNS host name or leave blank, in case the DNS host name is automatically filled for you by default.

- **NetBIOS alias** — Enables you to use a way of referring to a host computer (an alias) from the host's TCP/IP DNS name.

- **Server string** — A string of identifying the server. This name appears in places such as the printer comment box. By default, it says Samba and the version number.

- **Interfaces** — Enables you to use more than one network interface and let Samba several different subnetworks. The form of this field can be `IP Address/Subnetwork Mask`. Or, if you identify a network interface (such as eth0 for the first Ethernet card on your computer). For example, a Class network address may appear as:
`192.168.24.11/255.255.255.0`

# Security Options

Of the security options settings, the first (security) is the most important to get right. It defines the type of security used to give access to the shared files and printers to the client computers (To see some of the fields described here, you need to click the Advanced view)

- **Security** — Sets how password and user information is transferred to the Samba server from the client computer. As noted earlier, it's important to get this value right. Samba 2.0 and later has a different default value for security (`security-user`) than the earlier versions of Samba do (`security-share`). If you are coming from an earlier version of Samba and clients are failing to access your server, this is a good place to start. Here are your options:

- **user** — The most common type of security used to share files and printers to Windows 95/2000/NT/XP clients. It is the default set with Samba in the current release. This setting is appropriate if users are doing a lot of file sharing (as opposed to a Samba server mostly as a print server). It requires that a user provide a username/password before using the server. The easiest way to get this method working is to give a Linux user account to every client user who will use the Samba server, therefore providing basically the same file permissions to a user account through Samba as the same user would get if he or she were logged in to Linux.

- **share**— The share value for security works works best for just sharing or providing file access that is more public (guest). A client doesn't need to provide a valid username and password to access the server. However, the user typically has a guest level of permission to access and change files. See the “Assigning Guest Accounts” sidebar in this chapter for further information.

- **server**— From the client's point of view, this is the same as user security when the client still has to provide a valid username/password combination to use the Samba server at all. The difference is on the server side. With server security, the username/password is sent to another SMB server for validation. If that fails, Samba tries to validate the client using user security.

- **domain**— From the client's point of view, this also looks as user security. This setting is used only (If the Samba server has been added to a Windows domain (using the smpasswd command). When a client tries to connect to the Samba server in this mode, its username and password are sent to a Windows NT Primary or Backup Domain controller. This is accomplished the way that a Windows NT server performs validation. Linux user accounts must be set up.

- **Encrypted passwords**—Controls encrypted passwords can be negotiated with the client. This is on (Yes) by default. For domain security, the value must be Yes. Later versions of Windows NT (4.0 SP3 or later) and Windows 98 and Windows 2000 expect encrypted passwords to be on.

- **Update encrypted**—Allows users who log in with a plain-text password to automatically update their passwords updated to encrypted passwords when they log in. In many, this option is off. Turn it on when you install an using plain-text passwords to have everyone updated to encrypted password authentication. It saves the trouble of running the smbpasswd command directly from the server. After every update, is updated then, the Encrypted passwords option should be set to No.

- **PAM restrictions**—Turns this on (Yes) if you want to use PAM for account and session management. Even if activated, PAM is not used if the encrypted passwords are turned on (encrypt passwords=yes). PAM stands for Pluggable Authentication Modules and is used for authenticating host computers and users.

- **PAM password change**—Indicates the use of the PAM password control flag for Samba. If this is on (Yes), SMB clients will use PAM instead of the program list in the Password Program value for changing SMB passwords.
