+   **Field 5** — The number in this field indicates whether the indicated file system needs to be dumped (that is, has its data backed up). A 1 means that the file system needs to be dumped, and a 2 means that it doesn't. (I don't think this field is useful anymore because many Linux systems no longer include the `dump` command. Most often, a 0 is used.)

+   **Field 6** — The number in this field indicates whether the indicated file system needs to be checked by `fsck`: 1 means it needs to be checked, and 2 means it doesn't.

If want to add an additional local disk or partition, you can create an entry for it in the `/etc/fstab` file. See Chapter 27 for information on mounting Samba, NFS, and other remote file systems from `/etc/fstab.

# Using the mount Command to Mount File Systems

Linux systems automatically run `mount -a` (mount all file systems) each time you boot. For reason, you generally use the `mount` command only for special situations. In particular, the average user or administrator uses `mount` in two ways:

+   * To display the disks, partitions, and remote file systems currently mounted.

+   * To temporarily mount a file system.

Any user can `mount` (with no options) to see what file systems are mounted on the local Linux system. This is an example of the mount command. It shows a single hard partition (`/dev/sda`) containing the root (`/`) file system, and devpts file types mounted on `/proc` and `/dev`, respectively. The last entry shows a floppy disk, formatted with a standard Linux file system (`/mnt/floppy` directory).

```
$ mount
/dev/hda / type ext3 (rw)
/dev/hdb / type ext3 (rw)
/dev/proc / type proc proc (rw)
/dev/sys / type sysfs (rw)
/dev/devpts / type devpts (rw,gid=5,mode=620)
/dev/shm / type tmpfs (rw)
/none /proc/sys/binfmt_misc type binfmt_misc (rw)
/dev/hdc / /media/cdrom type is_iso9660 (ro,nosuid,nodev)
/dev/fd0 / /mnt/floppy type ext3
```
