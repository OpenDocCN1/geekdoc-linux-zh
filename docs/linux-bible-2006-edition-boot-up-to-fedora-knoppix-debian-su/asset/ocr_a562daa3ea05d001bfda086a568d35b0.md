# 804 VI ♦ Programming in Linux

The Concurrent Versions System CVS supports both centralized repositories and network-based access. It is well-suited for use by multiple programmers, and a CVS repository can support multiple projects. To keep the discussion simple, however, the example in this chapter deals only with a repository accessed locally. The following steps resemble the process described earlier for RCS, but they are slightly more involved and obviously using CVS concepts.

+   1. Create a CVS repository:
- mkdir /space/cvs
- export CVSROOT=/space/cvs
- cvs init

The first command creates a directory /space/cvs to establish the repository. The second command defines the environment variable $CVSROOT makes CVS much simpler. The third command initializes the repository, which creates some administrative CVS needs to work properly.

+   2. Create a top-level working directory in to store your various projects and then cd into it:
- mkdir projects
- cd projects

+   3. Check out a copy of the CVS root directory into the directory you just created:
- cvs -d $CVSROOT co -l
- cvs checkout: Updating

The -d option tells CVS the directory containing the CVS repository ($CVSROOT, or /space/cvs); co means check out (as with RCS); the -l option, which stands for local, means to work in the current directory rather than recursing through subdirectories; and the . specifies the current directory.

+   4. Create a directory to hold a project and add it to the repository:
- mkdir hello
- cvs add hello
Directory /space/cvs/hello added to the repository

+   5. cd the new directory, copy your project files into it, and then add all files (and any directories that might be) to the repository:
- cd hello
- cp projects/*
- cvs add *
