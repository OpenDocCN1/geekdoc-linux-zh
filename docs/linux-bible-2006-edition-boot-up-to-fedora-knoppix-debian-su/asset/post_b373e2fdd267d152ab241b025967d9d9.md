## Dual Booting with Windows or Just Linux?

It is possible to have multiple, bootable operating systems on the same computer (using multiple partitions on a hard disk and/or multiple hard disks). Setting up to boot more than one operating system, however, requires some thought. It also assumes some risks.

> Caution While resizing Windows partitions and setting up multi-boot systems have improved in recent years, there is still considerable risk of losing data on Windows/Linux dual-boot systems. Different operating systems often have different views of partition tables and master records that can cause your machine to become unstable (at least temporarily) or lose permanently. Always back up your data before you try to resize a Windows (NTFS or FAT) system to make space for Linux. If you have a choice, install Linux on a machine of your own or at least on a separate hard disk.

If you are already using a Windows system on it, it's quite possible that the hard disk is devoted to Windows. While you can run a bootable Linux, using KNOPPIX or Damn Small Linux, without touching the hard disk, to do a permanent installation you'll want to find disk space out of the Windows installation. There are a few ways to do this:

- ◆ Add a hard disk — Instead of messing with your Windows partition, you can simply add a hard disk and devote it to Linux.

- ◆ Resize your partition — If you have available space on your Windows partition, you can shrink that partition so there is free space on the disk to devote to Linux. Commercial tools such as Partition Magic (www.powerquest.com/partitionmagic) or Acronis Disk Director (www.acronis.com) are available to resize your disk partitions and set up a workable boot manager. Some Linux distributions (particularly Ubuntu Linuxes used as rescue CDs) include a tool called QTParted that is an open source clone of Partition Magic (which includes software from the Linux-NTFS project for resizing Windows NTFS partitions).

## Part III ♦ Choosing and Installing a Linux Distribution

Before you try to resize your Windows partition, you might need to defragment it. To defragment your disk on the disk, some Windows systems, so that all of your used space is put in order, open My Computer, right-click your hard disk (typically C), select Properties, click Tools, and select Defragment Now.

Defragmenting your disk can be a fairly long process. The result of defragmentation is that all the data on your disk are contiguous, creating a lot of contiguous space at the end of the partition. There are cases where you will have to do the following special tasks to make this true:

- * If the Windows swap file is not moved during defragmentation, you must remove it. Then, after you defragment your disk and resize, you will need to restore the swap file. To remove the swap file, open the Control Panel, open the System icon, and click the Performance table and select Virtual Memory. To disable the swap file, click Disable Virtual Memory.

- * If your partition has hidden files that are on the space you are trying to free up, you need to delete them. In some cases, such as swap files created by a program, you can safely delete them. This is a tricky business because some files might not be deleted, as OS system files. You can use the attrib -s -h command from the root directory to deal with hidden files.

Once your disk is defragment, you can use commercial tools described earlier (Partition Magic or Acronis Disk Editor) to partition your hard disk to make space for Linux. An open source alternative to those tools is QTParted.

Boot KNOPPIX or any other bootable Linux distributions (particularly rescue CDs) and run QParted by selecting System Tools -> QParted from the desktop menu. From the QParted window, select the hard disk you want to resize. Then choose Options -> Configuration to open a window where you can resize the partition size to utilize your partition.

After you have cleared enough disk space to install Linux (see the disk space requirements in the chapter you're installing), you can choose your Linux distribution and install it. As you set up your boot loader during installation, you will be able to identify the Windows, Linux, and any other bootable partitions that you can select one to boot when you start your computer.

## Using Installation Boot Options

Sometimes a Linux installation will fail because the computer has non-functioning or non-supported hardware. Sometimes you can get around these issues by passing options to the install process when it boots up. Those options can do such things as disable selected hardware (usb, nosci, noide, and so on) or not probe hardware when you need to select your own driver (nprobe).

Although some of these options are distribution-specific, others are simply options that can be passed to an installer environment that works from a Linux kernel. Chapter 11 includes a list of many boot options that can be used with KNOPPIX and other Linux systems.

## Partitioning Hard Drives

The hard disk (or disks) on your computer provides the permanent storage area for your data files, applications programs, and the operating system itself. Partitioning is the act of dividing a disk into logical areas that can be worked with separately. In Windows, you typically have one partition that consumes the whole hard disk. However, with Linux there are several reasons you might want to have multiple partitions:

- Multiple operating systems: If you install Linux on a PC that already has a Windows operating system, you may want to keep both operating systems on the computer. For all practical purposes, each operating system must exist on a completely separate partition. When your computer boots, you can choose to run.

- Multiple partitions within an operating system: To prevent from having your entire operating system run out of disk space, people often separate partitions to areas of the Linux system. For example, if /home and /var were assigned to separate partitions, then a gluttonous user who fills up the /home partition wouldn't prevent logging daemons from continuing to write files in the /var/log directory.

Multiple partitions also make it easier to obtain certain kinds of backups (such as an image backup). For example, image backup of /home would be much faster (and probably more useful) than an image backup of the root file system (/).

- Different file system types: Kind of file systems have different structures. File systems of different types must be on their own partitions. In most Linux systems, you need at least one file system type for / (typically ext3 or reiserfs) and one for your swap area. File systems on CD-ROM using the iso9660 file system.

When you create partitions for Linux, you will usually assign the file system type as Linux native (using the ext2 or ext3 type on some Linux systems, and reiserfs on others). Reasons to use other types needing a file system that allows particularly long filenames or many inodes (each consumes an inode).

For example, if you set up a news server, it can use many inodes for news articles. Another reason for using a different file system type is to copy an image backup tape from another operating system to your local disk (such as one from OS/2 or Minix operating system).
