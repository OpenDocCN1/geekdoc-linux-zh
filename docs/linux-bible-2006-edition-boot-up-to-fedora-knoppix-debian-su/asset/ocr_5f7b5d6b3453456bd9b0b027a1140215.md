Web mail applications use IMAP as their backend protocol for accessing mailboxes; this eliminates the need for direct access to the mail files and makes it easier to split functions between systems.

# About the System and the Software Used

The mail server configuration described in this chapter is based on the Exim mail transfer agent. With Exim, several other components are added for managing the server and checking e-mail for spam and viruses:

+   * Exim (http://www.exim-mta.org/) is an MTA written and designed by Philip Hazel at the University of Cambridge, with contributions from many people around the world. The version referred to in this chapter includes the Exiscan-ACL (http://duncanthrax.net/exiscan-acl/) packages from Tom Kistner. Because this patch allows content scanning within Exim, its features are considered part of Exim for the purpose of this chapter.

+   * Maildrop (http://www.flunder.net/~msam/maildrop/) is a local MDA that is part of the Courier MTA package, but is also available as a standalone program. It is used in this configuration to allow the use of advanced features, such as mailbox queries and server-side sorting.

+   * Courier IMAP and POP (http://www.courier-mta.org/imap/), like Maildrop, are parts of the Courier MTA that are also available separately. They were chosen for their easy installation, performance, and compatibility with the Maildir format directories.

+   * ClamAV (http://www.clamav.net) is an open source virus scanner that detects more than 20,000 viruses, worms, and Trojans. It uses a virus pattern database to identify viruses and a program named freshman handles updates the database automatically. Like SpamAssassin, ClamAV includes a daemon (clamd), a client (clamdclient), and a second command-line tool that does not use the daemon (clamscan).

+   * SpamAssassin (https://spamassassin.org/) is a spam-filtering program written in Perl. It uses a large set of rules to determine how "spammy" a message looks and assigns a score based on the total of rule values. For performance reasons, SpamAssassin uses a background daemon called spamamd to perform message analysis. Access to this daemon is performed through the spamc client. A spamassassin command that performs the analysis without using spamd is also installed but is not used by either of the example cases in this chapter.
