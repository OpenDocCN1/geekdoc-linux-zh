```
root:x:0:0:root:/bin/bash
bin:x:1:1:bin:/bin/bin
demon:x:2:2:daemon:/sbin:

```

```
mary:x:500:100:Mary Smith/mary:/bin/sh
joe:x:501:100:Joe Johnson/joe:/bin/sh
jane:x:502:100:Jane Anderson/home/jane:/bin/sh
bob:x:503:100:Bob Renolds/bob:/bin/sh
```

Encrypted password data is replaced with an x. Password data has been moved to /etc/shadow.

There is also a secure-oriented command authconfig (available with Fedora and RHEL systems) that you can use to manage passwords and other system authentication information. This tool has features that you can work with MD5 passwords, LDAP authentication, or Kerberos 5 authentication as you. Type authconfig and step through the screens to use it.

To work with groups, you can use the grpconv command to convert passwords in /etc/groups to shadow passwords in /etc/shadow. If you change password or group passwords and something breaks (you are unable to log in to the accounts), you can use the pwconv and grpconv commands, respectively, to reverse conversion.

# Using Log Files

If you use some firewalling practices as described in Chapter 18, you will be well prepared to mitigate and prevent most cracker attacks. If your firewall should fail to stop an intrusion, you must be able to recognize the attack when it occurs. Understanding the various (and numerous) log files in which Linux records important events is critical to this goal. The log files for your Linux system can be found in the /var/log directory.
