You can also turn permissions on and off using plus (+) and minus (-) signs, respectively. This can be done for the owner user (u), owner group (g), others (o), and all users (a). For example, start with a file that has all permissions (rwx-rwx). Run the following `chmod` commands using sign options. The result-permissions are shown to the head of each command:

```
chmod +w file      r-xr-xr-x
chmod -x file      rwsrwsr-
chmod go-rwx file  rwx-
```

Likewise, there are some examples, starting with all permissions closed (---------) where the plus is used with `chmod` to permissions on:

```
chmod u+rw files    rw-
chmod a+x files     --x--x--x
chmod ug+rwx files  r-xr-x-
```

When you create a file, its permissions are rw-r-- by default. A directory is given the permission rwx-xr-x. These default values are defined by the value of `umask`. Type **umask** to see what your `umask` value is. For example:

```
$ umask
022
```

The `umask` value masks the permissions value of 666 for a file and 777 for a directory. That same `umask` of 022 results in permission for a directory of 755 (rwx-xr-x). That same `umask` in a file permission of 644 (rw-r--r--). (Execute permissions are off by default files.)

> Tip save: use the -R option of `chmod`, to change the permission for all the files and directories within a directory structure at once. For example, if you want to open permissions completely to all files and directories in the `/tmp/test` directory, you could type the following:

```
$ chmod -R 777 /tmp/test
```

This command runs `chmod` recursively (-R) for the `/tmp/test` directory, as well as any files and directories that exist below in the file system (example, `/tmp/test/hat,/test/test/caps`, and so on). All will be set to 777 (full read/write/execute permissions). This is not something you would do on an important directory on a read/write file system. However, you might do this before you create a directory structure on a CD-ROM that you want to be fully readable and executable to someone using the CD-ROM.

> The -R option of chmod works best if you are opening permissions completely or adding execute permission (as well as appropriate read/write permission). The reason is if you turn off permission recursively, you close off your capability to change any directory in that structure. For example, `chmod -R 644 /tmp/test` turns off permission for the `/tmp/test` directory, and then fails to change any files or directories below that point.
