## Getting Away from Windows

Home users typically have to concern themselves with maintaining access to their own documents. In a personal context, it might be rare for friends and relatives to see Excel spreadsheets, Word documents, and PowerPoint presentations. Over the years you have accumulated term papers, recipes, letters to the editor, and other documents that you'd like to be read and print. In most cases, OpenOffice.org applications will handle files in Microsoft formats just.

At work, in addition to the accumulation of documents over time, there is a more pressing issue: Other people will be sending you Microsoft Office documents. So while home users need to concern themselves with access to historical documents, in the workplace you probably need to accommodate new documents as well as your historical information.

Because you can convert documents, there are no real challenges to migrating documents. However, if your Microsoft Office documents include extensive macro, scripting, or embedded object usage, you may find the conversion is not a very clear one. Make sure you attempt conversions using the following options before moving on the last resort of using multiple applications or re-creating documents.

Using Microsoft Office to convert documents enables you to save your files in an alternative format. For example, Word 2002 allows you to save your .doc files (the Word versions any) to a variety of formats:

- HTML (.html)—HTML a great format for your information if it is basically text and you only need a few formatting options and some embedded images and links. The resulting HTML document will be smaller than the corresponding .doc file.
- Rich Text (.rtf)—Another wonderful minimal format (owned by Microsoft but an open standard nonetheless) that preserves some formatting and graphics, but by scripting or macro usage it is lost.
- Plain Text (.txt)—Works if all you need to save is the text of the file. Everything else is lost.
- Word 6.0/95 (.doc)—An alternative format that may save some of the elements you want yet make it more accessible to OpenOffice.org. Using for this format may not resolve all of the issues you have with converting hard-to-change documents, but it might just do the trick.

## Part IV Running Applications

Other Microsoft Office applications offer similar functionality. PowerPoint can convert presentations to HTML and general image formats such as JPEG and TIFF. Excel can save tab- and comma-delimited files that are easily importable into a large number of applications.

If you are likely to receive Microsoft Office files and you are concerned about interoperability, here are some options to consider:

- Ask individuals sending you to use a less vendor-specific format, such as Adobe PDF. Document formatting can be exquisitely preserved and will be viewable by anyone capable of installing a PDF viewer, which supports virtually every operating system in use today.
- For forms that have user-editable fields, scripting, or complex embedded information, use HTML documents. Instead a compliant web browser will be able to interact with the document, and Microsoft Office applications universally support saving files into this.

## Using Traditional Linux Publishing Tools

With old-school text processors such as Groff and Tex, you can ignore document while writing. Plain-text macros postprocessors handle how to lay out a document for printing after writing is done. With word processors such as OpenOffice.org Word and StarOffice Writer, you may mark up text and see the basic layout of the document as you write.

Some attributes of the traditional Linux document preparation tools make them particularly suited for certain types of projects. TeX and Groff (which is based on TeX) are a pair of these “classic” tools and have been popular among technical people because:

- You can manipulate files in plain text. Using tools such as sed and grep, you can scan and change one document or hundreds with a single command or script.
- Scientific notation is supported. With geqn, you can create complex equations. LaTeX and TeX are suited for technical notation, and some math publications require LaTeX.
- Editing can be faster because traditional Linux documents are created with a text editor. Using you get better performance out of a text editor than a word processor.

Simple layouts work well with Linux documentation tools. For example, a technical book with a few charts and images can be easily produced and maintained using Geoff or TeX documentation tools. Letters and memos are also easy to do with these tools. And, of course, Linux maps are created with text-based tools.

Additionally, Linux likes PostScript. Although people think of PostScript as a printing language, it is really more of a programming language (you could write PostScript directly). Most Linux document-processing software includes print drivers for PostScript. Some documents on the Web are distributed in PostScript (.ps).

The drawback to the traditional Linux documentation tools is that they are not intuitive. Although there are some easier front ends to LaTeX (see the description of LyX later in this chapter), if you are creating documents in a text editor, you need to learn how macros type into your documents and what formatting to use.

> Note For many years, the UNIX system documentation distributed by AT&T was created in troff/nroff formats, which precede Geoff. The documents used separate macro packages for man pages and guide material. Using a source code control system (SCCS), AT&T ported thousands of pages of documentation to different UNIX systems.
