# Adding a NetPrinter

To set up your Linux system by a printer that is connected to (or otherwise managed by) NetWare file and print server, you must gather the information about the server, user, and password.

Select to add a Novell printer (Novell created NetWare) to the Printer Configuration window (described previously), and then fill in the following information:

- Password — Password associated with the username.

# Working with CUPS Printing

Tools such as CUPS Web-based Administration and Red Hat's Printer Configuration window effectively hide the underlying CUPS facility. There may be times, when you want to work directly with the tools and configuration files that come with CUPS. The following sections describe how to use some special CUPS features.

# Configuring the CUPS Server (cupsd.conf)

The cupsd daemon process listens for requests to your CUPS print server and responds to these requests based on settings in the /etc/cups/cupsd.conf file. The configuration variables in cupsd.conf file are in the same format as those in the Apache configuration file (httpd.conf).

Red Hat's Printer Configuration window adds access information to the cupsd. For other Linux systems, you may need to configure the cupsd.conf file manually. You can step through the cupsd.conf file to further tune your server. Let's take a look at some of the settings in the cupsd.conf file.

No classification is set by default. With the classification set to topsecret, you can have Top Secret displayed on all pages that through the print server:

- Classification topsecret

Other classifications you can substitute for topsecret include: classified, confidential, secret, and undisclosed.

The ServerCertificate and ServerKey lines (commented out by default) can be set to indicate where the certificate and key are stored:

```
ServerCertificate /etc/cups/ssl1/server.crt
ServerKey /etc/cups/ssl1/server.key
```

Activate these two lines if you want to do encrypted connections. Then add your certificate and key to the files noted.

Browsing is the feature where you broadcast information about your printer on your local network and listen for other print servers' information. Browsing is by default only for the local @LOCAL. You can allow CUPS browser information (BrowseAllow) for additional selected addresses. Browsing information is broad, by default, on address 255.255.255.255. Here's how these defaults appear in the cupsd.conf file:

```
Browsing On
BrowseProtocols cups
BrowseOrder Deny,Allow
BrowseAllow from @LOCAL
BrowseAddress 255.255.255.255
Listen *:631
```

To enable Web-based CUPS administration, the cupsd daemon listens on port 631 for all network interfaces to your computer based on this entry: Listen *:631.

By turning BrowseRelay (it's off by default), you can allow CUPS information to be passed between two or more networks. The source-address and destination-address can be individual IP addresses or represent network numbers:

```
BrowseRelay source-address destination-address
```

This is a good way to enable users on several connected LANs to discover and use printers on other nearby LANs.

You can allow or deny access to different features of the CUPS server. An access definition for a CUPS printer (created from the Printer Configuration window) may appear as follows:

```
<Location /printers/ns1-hp1>
Order Deny,Allow
Deny From All
Allow From 127.0.0.1
AuthType None
</Location>
```

Here, printing to the ns1-hp1 printer is allowed for users over the local host (127.0.0.1). No password is needed (AuthType None). To access to the administration tool, CUPS must be configured to prompt for a password (AuthType Basic).

# Starting the CUPS Server

For Linux systems use SystemV-startup scripts (such as Fedora, RHEL, and SUSE), starting and shutting down the CUPS service is pretty easy. Use chkconfig command to turn on CUPS so it starts at each reboot. Run the startup script to have the CUPS service start immediately. Type the following as

```
# chkconfig cupsd on
# /etc/init.d/cups start
```

If the CUPS service was already running, you should restart instead start. Using the restart option is also a good way to reread any configuration options you may have changed in the cupsd.conf file.

Other Linux systems vary in how they start up the CUPS service. For example, in Slackware, you can turn on CUPS printing permanently by simply making the rc.cups script executable and then it it immediately by executing it (the following as root):

```
# chmod 755 /etc/rc.d/rc.cups
# /etc/rc.d/rc.cups start
```

# Configuring CUPS Printer Options Manually

If your Linux distribution doesn't have a graphical means of edit configuration files directly. When a new printer is created from the Printer Configuration window, it is defined in the /etc/cups/printers.conf file. Here is what a printer looks like:

```
</Printer>
<DefaultPrinter>
Info Created by system-config-printer 0.6.x
DeviceURI parallel:/dev/lp0
Location HP LaserJet 2100M in hall closet
State Idle
Accepting Yes
JobSheets none none
QuotaPeriod 0
PageLimit 0
KLimit 0
</Printer>
```

This is an example of a local printer that serves as the default printer for the local system. The most interesting information relates to DeviceURI, which shows that the printer is connected to parallel port /dev/lp0. The state is Idle and the Accepting value is Yes (the printer is accepting jobs) by default.

The DeviceURI has several ways to identify the device name of a printer, reflecting where the printer is connected. Here are some examples listed in the printers .conf:

```
DeviceURI parallel:/dev/plp
DeviceURI serial:/dev/ttyS1@baud=38400+size=8+parity=none+flowsoft
DeviceURI scsi:/dev/scd60
DeviceURI socket://hostname:port
DeviceURI http://hostname/path
DeviceURI ftp://hostname/path
DeviceURI i://hostname[:]/path
DeviceURI ipp://hostname/path
DeviceURI smb://hostname/printer
```
