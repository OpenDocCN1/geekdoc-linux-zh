Packets from the Internet that are accepted for ICMP protocol requests in the following example are for ICMP types 8 and 11. Type 8 service allows your computer to accept reply messages, making it possible for people to ping your computer to see if it is available. Type 11 service returns packets with a time to live (TTL) that was exceeded in transit, and for which you are accepting a Time Exceeded message that is being returned to you. (You need to accept Type 11 messages to use the traceroute command to find broken routes to hosts you want to reach.)

```bash
# iptables -A INPUT -p ICMP -i eth0 -s 0.0.0.0 --icmp-type 8 -j ACCEPT
# iptables -A INPUT -p ICMP -i eth0 -s 0.0.0.0 --icmp-type 11 -j ACCEPT
```

These two lines define rules for ICMP packets that come into the first Ethernet interface (eth0) from any source (-s 0.0.0.0). The first line says to ACCEPT type 8 service, and the second says to ACCEPT type 11 service.

- 5. The following are examples of commands that define the packets that will be allowed to come in and go out of the local computer or the private LAN that the firewall is protecting:

```bash
# iptables -A INPUT -p ALL -i lo -s 127.0.0.0/8 -j ACCEPT
# iptables -A INPUT -p ALL -i lo -s 10.0.0.0/8 -j ACCEPT
# iptables -A INPUT -p ALL -i lo -s 123.45.67.89/32 -j ACCEPT  # corrected from 323
# iptables -A INPUT -p ALL -i eth1 -s 10.0.0.0/24 -j ACCEPT
# iptables -A INPUT -p ALL -i eth1 -d 10.0.0.255 -j ACCEPT
```

The result of these commands is that packets are sent from the local host itself (-s 127.0.0.0/8), an interface to the local LAN (-s 10.0.0.0/8), or the Internet (-s 123.45.67.89/32). The IP addresses 10.0.0.1 and 123.45.67.89 are examples of local interfaces to those networks (your addresses will be different). The last two lines indicate that the firewall should accept incoming packets that are from the private LAN (-s 10.0.0.0/24) or destined for any address on that LAN (-d 10.0.0.255), network requests.

> 123.45.67.89 is not a real IP address. You will replace it with the IP address assigned from your ISP for your external interface. No valid IP address can include a port higher than 255.

The following commands define accepting outgoing packets from the firewall:

```bash
# iptables -A OUTPUT -p ALL -s 127.0.0.0/8 -j ACCEPT
# iptables -A OUTPUT -p ALL -s 10.0.0.0/8 -j ACCEPT
# iptables -A OUTPUT -p ALL -s 123.45.67.89/32 -j ACCEPT
# iptables -A OUTPUT -p ALL -s 10.0.0.0/24 -j ACCEPT
# iptables -A OUTPUT -p ALL -d 10.0.0.255 -j ACCEPT
```

As with the input commands, the firewall accepts outgoing packets that come from any of the local firewall interfaces (127.0.0.1, 10.0.0.1, and 123.45.67.89). It also accepts outgoing packets associated with destinations on the private LAN (10.0.0.0/24 and 10.0.0.255).

- 6. This list of commands defines what packets originated from the Internet are allowed into the firewall. For packets attempting to enter your computer from the Internet, you want to be more restrictive, in allowing only for services you want to provide. Here are some examples of specific rules you might want to allow for your server:

```bash
# iptables -A INPUT -p tcp -i eth0 --dport 21 -j ACCEPT
# iptables -A INPUT -p tcp -i eth0 --dport 22 -j ACCEPT
# iptables -A INPUT -p tcp -i eth0 --dport 80 -j ACCEPT
# iptables -A INPUT -p tcp -i eth0 --dport 113 -j ACCEPT
# iptables -A INPUT -p udp -i eth0 --dport 2074 -j ACCEPT
# iptables -A INPUT -p udp -i eth0 --dport 4000 -j ACCEPT
```

The first four lines open ports for the TCP services you want to provide to anyone on the Internet: for FTP service (--port 21), secure shell (22), Web service (80), and IDENTD authentication (113), the last of which might be necessary for protocols as IRC.

> You must ensure that the services on the ports to which you are allowing access are properly configured before you allow packets to be accepted. In other words, don't open port 80 until you have a Web server configured.

The last three lines define the ports where connections are accepted from the Internet. This example assumes that DNS service (port 53) is configured on the computer. It also illustrates lines that accept requests for two other ports: Port 2074 is needed by some applications the users on your LAN might want to use, and port 4000 is used by ICQ (for online chats). At this point you can run `iptables -L` to see your new set of rules. If you have a connection to the computer from your LAN, you can try to ping the computer. You can also try configuring services and accessing them from your network interfaces. With this part of the procedure completed, your new rules are built into the Linux kernel but do not exist anywhere in a configuration file. Unless you save the rules they will be gone next time you reboot your computer. The following discusses saving your firewall settings so you can use them permanently.

## Saving Firewall Settings

If you have a good set of rules in your current kernel, you can save those rules using the `iptables-save` command so they can be reloaded later using the `iptables-restore` command. Here is an example of how to use the `iptables-save` command:

```bash
# iptables-save > /root/iptables
```

In this example, the previously saved rules are stored in the `/root/iptables` file (you can put them anywhere). These rules can be copied to a location where they can be loaded automatically on Linux systems. For example, in Red Hat systems, copy this file to `/etc/sysconfig/iptables` when the computer reboots. If they don't load automatically, you can restore them as follows:

```bash
# iptables-restore < /root/iptables
```

The previously saved rules are restored to the currently running kernel.

![](img/a2d958d7eab32ca5b89b2b8af808aa70_500_0.png)

Remember that if you are using a bootable Linux you need to save the iptables rules to a location (such as a directory on hard disk partition) that will not disappear when reboot.

## Checking Your Firewall

Now that your firewall is configured, you should check it to make sure it appears to the outside world—in our example, to the Internet on eth0 and your local LAN on eth1—as you would like. A popular tool for checking services is `nmap` on a network interface.

![](img/a2d958d7eab32ca5b89b2b8af808aa70_500_1.png)

While nmap is an excellent tool for checking interfaces on your own computer or private LAN, it should not be used to check for available services on computers that are not yours. Using nmap on someone's computer is like checking all the doors and windows on person's house to see if you can get in. It is considered an intrusive act to make sure your "doors and windows" are secure. Following is an example of using nmap to scan a large number of ports on the firewall you configured to see what services appear to be available from the two network interfaces (eth0 and eth1). To do this effectively, you need to run the `nmap` command from a computer outside your local firewall. That's because you don't want to see what is inside your firewall; you want to see the outside world's view of your firewall.

From the firewall computer, you'd first get the IP address of the external interface on eth0 using `ifconfig eth0`. For this example, that IP address is 123.45.67.89 (Remember that is not a real IP address; don't use nmap to scan a real computer on the Internet). Then, from another Linux machine on the Internet, type the following:

```# nmap 123.45.67.89
Starting nmap 3.70 (http://www.nmap.org/nmap/) at 2005-10-22 14:56 CDT
Interesting ports on 123.45.67.89:
(The 1653 ports scanned but not shown below are in state: closed)
PORT STATE SERVICE
22/tcp closed ftp
22/tcp open ssh
53/tcp closed domain
80/tcp closed http
113/tcp closed auth
4000/tcp closed something
MAC Address: 00:00:61:22:03:11 (Gigabyte Technology).
```
nmap completed -- 1 IP address (1 host) scanned in 72.951 seconds

The output shows that 1653 ports scanned on this address were filtered (blocked from access) and 6 were not blocked. Services not filtered include TCP ports 21, 22, 53, 80, 113, and 4000 (which you made available when you set up the firewall). Notice that only ssh has a server listener (providing service) at the moment. The other services are open from the firewall (not filtered), but the servers are not running.

It's possible that you won't have access to a Linux machine on the Internet to test outside access to your computer. If you have another computer on your LAN, try running nmap from your computer. If you only have Windows machines, you can always run a bootable Linux and try nmap from that.

## Using iptables to do SNAT or IP Masquerading

You can use Source Network Address Translation (SNAT) or IP Masquerading (MASQUERADE) to allow computers on your LAN with private IP addresses to access the Internet through your firewall. Choose SNAT if you have a static address for your Internet connection, and use MASQUERADE if the IP address is assigned dynamically.

When you create the MASQUERADE or SNAT rule, it is added to the NAT table and the POSTROUTING chain. For MASQUERADE you must provide the name of the interface (such as eth0, ppp0, or slip0) to identify the route to the Internet or outside network. For SNAT you must also identify the actual IP address of the interface.
