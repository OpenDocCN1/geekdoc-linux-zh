# Automatically Mounting an NFS File System

To set up an NFS file system to mount automatically each time you start your Linux system, you need to add an entry for NFS file system to the /etc/fstab file. That file contains information about all different kinds of mounted (and available to be mounted) file systems for your system.

Here's the format for adding an NFS file system to your local system:

```
host:directory mountpoint nfs options 0 0
```

The first item (host:directory) identifies the NFS server computer and shared directory. mountpoint is the local mount point where NFS directory is mounted. It is followed by the file system type (nfs). Any options related to the mount appear next in a comma-separated list (The last two zeros configure the system to not dump the contents of the file system and not use fsck on the file system).

The following are examples of NFS entries in /etc/fstab:

```
maple:tmp /mnt/maple size=8192,wsize=8192 0 0
oak:apps /oak/apps nfs noauto,0 0
```

In the first example, the remote directory /tmp from the computer named maple (maple:tmp) is mounted on the local directory (the local directory must always exist). The file system type is nfs, and read (size) and write (wsize) buffers are set at 8192 (see the "Using Mount Options" section later in this chapter) for connection. In the second example, the remote directory is on the computer named oak. It is set up as an NFS file system (nfs) that can be mounted on the /oak/apps directory locally. This file system is not mounted automatically (noauto), and can be mounted only as read-only (ro) using the mount command when the system is already running.

> The default is an NFS file system is read/write. However, the default for exporting a file is read-only. If you are unable to write to an NFS file system, check that it was exported as read/write from the server.

# Mounting noauto/fstab File Systems

Your /etc/fstab file contains devices for other file systems that are not mounted automatically (possibly /dev/cdrom and /dev/fd0, for your CD-ROM and floppy disk devices, respectively). The noauto option for these devices is what prevents them from being mounted at boot time. A noauto file system can be mounted when you need it. The advantage is when you type the mount command, you can type less information and have the rest filled in by the /etc/fstab file. For example you can:

```
# mount /oak/apps
```

With this command, mount knows to check the /etc/fstab file to get the file system to mount (oak:/apps), the file system type (nfs), and the options to use with (in this case ro for read-only). # Using Mount Options

You can add special mount options to the /etc/fstab file (or to a mount command line itself) to influence how the file system is mounted. When you add options to /etc/fstab, they must be separated by commas. For example, here the noauto, ro, and hard options are used when oak is mounted:

```
oak:/apps /oak/apps nfs noauto,ro,hard 0 0
```

The following are some options that are valuable for NFS file systems:

- - hard—If this is used and the NFS server disconnects or goes down while a process is waiting to access it, the server will hang until the server comes back up. This is helpful if it is critical that the data you are working with not out of sync with the programs that are accessing it. (This is the default behavior).
- - soft—If the NFS server disconnects or goes down, a process trying to access data from the server will time out after a period of time when this option is on. An input/output error is delivered to the process trying to access the NFS server.
- - rsize—The number of bytes read at time. The default is 8192.
- - wsize—The number of bytes written at time. The default is 8192.
- - size—The size of the file system in bytes. (see the "Using Mount Options" section later in this chapter).
