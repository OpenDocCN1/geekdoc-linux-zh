The rsync service is a nice turn on if your machine is an FTP server. It allows
people to use an rsync client (which includes a checksum-sum algorithm) to
download files from your server. With that feature, you can restart a disrupted
download without having to start from the beginning.

Most services are disabled by default, your computer is only insecure
as you make it. You can double-check that insecure services, such as login and rsh
(which are included in the rsh-server package in Fedora and RHEL systems),
al also disabled by making sure that disabled = yes is set in the /etc/xinetd
./login and rsh files.

You can make the remote login service active but disable the use of the
/etc/hosts.equiv and .hosts files, requiring login to always prompt for a
password. Rather disabling the service, locate the server line in the rsh file
(server = /usr/sbin/in.rsh) and add a space following by -L at the end.

You need to send a signal to the xinetd process to tell it to reload its configurantion. The quickest way to do that in Fedora and RHEL systems is to restart the
xinetd service. As the root user, you can trigger it from a shell:

```
# service xinetd reload
Reloading configuration: [ OK ]
```

You can also tell the xinetd process directly to reload the configuration file by sending it a SIGHUP signal. That works if you using the inet daemon instead (on sys)
tems such as Debian or Slackware) to replace the /etc/inetd.conf file. For example,
this (as root) to have the inet daemon reload the configuration file:

```
# killall -s SIGHUP inetd
```

That's-you have enabled the rsync service. Provided that you have properly
configured your FTP server, clients should now be able to download files from your
computer via the rsync protocol.

# Securing Servers with SELinux

Red Hat, did a clever thing when it took its first swipe at implementing SELinux
in Red Hat systems. Instead of creating policies to control every aspect of your
Linux system, they created a "targeted" policy that focused on securing those
services that are most vulnerable to attacks. They then set up securing
services in a way that, if they were compromised, a cracker couldn't compromise
mist of the system as well.
