# Using the root login

Every Linux system starts out with at least one administrative user account (the root user) and one or more regular user accounts (given a name that you choose, or a name assigned by Linux). In most cases, you log in as a regular user and become the root user to do an administrative task.

The root user has complete control of the operation of your Linux system. You can open any file or run any program. The root user also install software packages and accounts for others who use the system.

When you first install Linux systems, you add a password for the root user. You must remember and protect this password—you will need it to log in as root or obtain root permission while you are logged in as some other user. Other systems (such as KNOPIXX) start with a blank root password, so you might want to add one when you first start by typing the following from a Terminal window or shell:

```
# password root
Changing password for user root.
New UNIX password: ********
Retype UNIX password: ********
```

Some Linux distributions give you (as a regular user) the power to run commands as root. You simply have to ask for the privilege using the sudo command. For example, from a Terminal window, to open a shell as root, type the following:

```
$ sudo su -
#
```

You'll find out more about the sudo command later in this chapter.

The home directory for the root user is typically /root. The home directory and other information associated with the root user account are located in the /etc/passwd file. Here's what the root entry looks like the /etc/passwd file:

```
root:x:0:0:root:/bin/bash
```

This shows that for the named root user ID is set to 0 (root user), the group ID is also set to 0 (root group), the home directory is /root, and the shell for user is /bin/bash. (We're using a shadow password file to store encrypted password-data, so the password field here contains an x.) You can change the home directory or the shell by find that the system allow editing in this file. A better way to change these values, however, is to use the useradd command (described later in this chapter).

# Becoming Root from the Shell (su Command)

Although you can become the superuser by logging in root, sometimes it is not convenient. For example, you may be logged in to a regular user account and want to make a quick administrative change to your system without having to log out and log back in. Or, you may need to log in over the network to make a change to a Linux system but find that the system at allow root users in over the network (a common practice in the days before shells were available).

The solution is to use su command. From any Terminal window or shell, you can simply type the following:

```
$ su
Password: ******
#
```

When you are prompted, type in the root user's password. The prompt for the regular user ($) changes to the superuser (#). At this point, you have full permission to run any command and use any file on the system. However, one thing that the su command doesn't do when used this way is read in the root user's environment. As a result, you may find and get the message "Command Not Found." To fix this problem, use the su command with a dash (-) instead, like this:

```
$ su
Password: ******
#
```

You still need to type the password, but after that, everything that normally happens at login for the root user happens after the su command is completed. Your current directory will be root's home directory (probably /root), and thus things as the root user's PATH variable will be used. If you become the root user by typing su, rather than su -, you won't change directories or the environment of the current login session.

You can also use the su command to become another user than root. This is useful for troubleshooting a problem that is being experienced by a particular user, but not by others on the computer (such as an inability to print or send e-mail). For example, to have the permissions of a user named jmith, you'd type the following:

```
$ su - jmith
```

Even if you were root before you typed this command, afterward you would have only the permissions to open files and run programs that are available to jmith. As root user, after you type the su command to become another user, you don't need a password to continue. If you type that command you must use the new user's password.

When you are finished using superuser permissions, return to the previous shell by exiting the current shell. By pressing Ctrl-D or by typing exit. If you are the administrator for a computer that is accessible to multiple users, don't leave a shell open on someone else's screen (unless you want to let that person do anything he wants to compute!)

# Allowing Limited Administrative Access

As mentioned earlier, when you run GUI tools as a regular user (from Red Hat Linux, SUSE, or some other Linux systems), you are prompted for the root password before you are able to access the tool. By entering the root password, you are given root privilege for that task, without being root user for every task you do from desktop session.

A particular user can also be given administrative permissions for particular tasks without being the root password. For example, a system administrator can add a user to particular groups, such as disk, users, cdrom, ftp, mail, or www, and then add to the wheel group or add entries to the /etc/sudoers file to allow that user to use the sudo command to run individual commands as root. (See the description of sudo later in this chapter.)

A fairly new feature added to some Linux distributions used in highly secure environments is Security Enhanced Linux (SELinux). With SELinux, instead of an all-powerful root account, multiple roles can be defined to protect selected files and services. In that way, for example, if someone hacks into your server, he does not automatically have access to your mail server, or other services.

# Exploring Administrative Commands, Configuration Files, and Log Files

You can expect to find many commands, configuration files, and log files in the same places in the file system, regardless of Linux distribution you are using. The following sections give you some pointers on where to look for these elements.

# Administrative Commands

Only the root is intended to use many administrative commands. When you log in as root (or use su - from the shell to become root), your PATH variable is set to include some directories that contain commands for the root. These include the following:

- /sbin—Commands for managing your disk partitions (such as fdisk), checking file systems (fsck), and changing system states (init).
- /usr/sbin—Commands for managing user accounts (such as useradd) and adding mount points for automounting file systems (automount). Commands that run daemon processes are also contained in this directory. (Look for commands that end in d, sshd, pppd, and cupsd.)

Some administrative commands are contained in regular user directories (such as bin and /usr/bin). This is especially true of commands that have options available to everyone. An example is the /bin/mount command, which anyone can use to list mount file systems, but only root can use to mount file systems (Desktops, however, are configured to let regular users mount CDs, DVDs, or removable media.)

To find commands intended primarily for the system administrator, check the section 8 manual pages (usually in /usr/share/man/man8). They contain descriptions and options for many Linux administrative commands.

Some-party applications will add administrative commands to directories that are not in your PATH. For example, an application may put commands in /usr/local/bin, /opt/bin, or /usr/local/sbin. Some Linux distributions automatically add those directories to your PATH, usually before your standard bin and sbin directories. In that way, commands installed to those directories are not only accessible, but can also override commands of the same name in other directories.
