# Linux Security Checklist

While most Linux systems offer all the tools you need to secure your computer, if you are reckless someone (and probably will) harm your system, take it over, or to steal your data. Keep in mind that no security measures are 100% reliable and that, by giving physical access to a computer or an unlimited amount of time to break in, a skilled and deterministic cracker can break into any computer.

That, however, there are many safeguards you can take to improve your chances of keeping your Linux system safe. The following checklist covers a range of security features to protect your Linux desktop or server.

+   **Control physical access.** Keeping your computer behind locked doors is a good idea, especially if it contains critical data. You can limit what a person can do to your computer with physical access by enabling passwords in the BIOS (to prevent the computer from booting at) and in the GRUB or LILO boot loader. You can also limit which devices can be booted in the BIOS.

+   **Add users and permissions.** Creating user accounts (each with a password) is your first line of defense in keeping your data secure. Accounts are protected from each other, as well as from an outsider who takes over one user account. Setting up group accounts can extend the concept of ownership to multiple users. See Chapter 4 for on setting up user accounts and "Using Password Protection" later in this chapter.

+   **Read, write and execute permissions.** Every item in a system (including files, directories, applications, and devices) can be restricted by read, write, and execute permissions for that item's owner and group, as well as all others. In this, for example, you can let others run a command or a file, allowing them to change it. See Chapter 2 for information on setting file and directory permissions.

+   **Protect the root user.** In standard Linux systems, the root user (as well as other user accounts such as apache) has special abilities to change and use your Linux system. Protect the root account's password and do not use the root account when you don't need to. An open shell or desktop owned by the root user can be target for attack. Running graphical administration commands as a regular user (entering the root password as prompted) using sudo can reduce exposure to attacks on your root account. See Chapter 4 for information on handling the root user account.

+   **Use trusted software.** While there are no guarantees about any open source software, you have a better chance of avoiding compromised software by using an established Linux distribution (such as Fedora, Debian, or SUSE). Software depositories where you get add-on packages or updates should be wisely scrutinized. Using valid GPG public keys can help ensure that the software you install comes from a valid vendor.
