Many sites opt to go with self-signed certificates, not because they are trying to pull a fast one on, but because there may not be reason to validate the true owner of the certificate and they do not want to pay the cost of validating it. Some reasons for using a self-signed certificate include:

+   **The site accepts no input**— In this case, as you the end user, having to worry about it. There is no one to steal your information because you aren't giving out information. Most of the time this is done simply to secure the transmission from the server to you. The data in and of itself may not be sensitive, but, being a good neitzen, the site has enabled you to secure the transmission to keep third parties from sniffing the traffic.

+   **The site caters to a small clientele**— If you run a site that has a very limited set of customers, such as an Application Service Provider, you can simply inform your users that you have no certificate. They can browse the certificate information and validate it with you over the phone or in person.

+   **Testing**— It makes no sense to pay for an SSL certificate if you are only testing a new Web site or Web-based application. A self-signed certificate until you are ready to go live.

# Creating a Certificate Service Request

To create a third-party validated SSL certificate, you must first start with a Certificate Service Request (CSR). To create a CSR, do the following on your Web server:

```
# cd /etc/httpd/conf
# make certreq
umask 77 ; \
/usr/bin/openssl genrsa -des3 1024 >/etc/httpd/conf/ssl.key/server.key
```

You will be asked for a password to secure your private key. This password should be at least eight characters long, and should not be a dictionary word or contain numbers or punctuation. The characters you type will not appear on the screen, to prevent someone from shoulder surfing your password.
