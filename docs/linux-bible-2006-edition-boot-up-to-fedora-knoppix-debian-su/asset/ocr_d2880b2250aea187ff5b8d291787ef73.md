In the previous example, the average time for a ping packet to make the roundtrip was about thirty seconds of an apostle.

A ping to a nearly saturated link looks like the following:

```
@ ping www.example.com
PING www.example.com (192.0.0.166) from 10.0.0.11: 56(84) bytes of data
64 bytes from 192.0.0.166: icmp_seq=1 ttl time=1252 ms
64 bytes from 192.0.0.166: icmp_seq=2 ttl time=1218 ms
64 bytes from 192.0.0.166: icmp_seq=3 ttl time=1290 ms
64 bytes from 192.0.0.166: icmp_seq=4 ttl time=1288 ms
64 bytes from 192.0.0.166: icmp_seq=5 ttl time=1241 ms
---
www.example.com ping statistics
5 packets transmitted, 0% loss, timeout 5032ms
rtt min/avg/dev = 1218.059/1258.384/1290.861/28.000 ms
```

In this example, a ping packet, on average 1.3 seconds to make the roundtrip.
From the first example, the latency increased by a factor of 31! A data link that goes from working normally to slowing down by a factor of 31 is a clear sign that link utilization could be investigated.

For a more accurate measure of data throughput, a tool such as ttcp can be used.
to test your connection with tcp you must have installed the ttcp package on machines inside and outside of your network. (The ttcp package is available with Fedora Core and other Linux systems.) If you are not sure the package is installed, simply type ttcp at a command prompt. You should see something like this:

```
@ ttcp
ttcp -t [ options ] - host [ < in ]
Common options:
-l ## length of buffers from read or written to network (default 8192)
-u use UDP instead of TCP
-p ## port number to send to or listen at (default 5001)
-t source: a pattern to network
-s sink: discard all data from network
-A align the start of buffers to this modulus (16384)
-c start buffers at this offset from the modulus (default 0)
```
