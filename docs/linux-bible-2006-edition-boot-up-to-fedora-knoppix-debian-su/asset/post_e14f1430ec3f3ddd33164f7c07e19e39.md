## Using File-Redirection Metacharacters

Commands receive data from standard input and send it to standard output. Using pipes (described earlier), you can direct standard output from one command to the standard input of another. With files, you can use less than (<) and greater than (>) signs to redirect data to from files. Here are the file-redirection characters:

- `<` Directs the contents of a file to the command.
- `>` Directs the output of a command to a file, deleting the existing file.
- `>>` Directs the output of a command to a file, adding the output to the end of the existing file.

Here are some examples of command lines where information is directed to and from files:

```
$ mail root < ~/.bashrc
$ chmod | col -b > /tmp/chmod
$ echo "I finished the project on $(date)" >> /projects
```

In the first example, the contents of the .bashrc file in the home directory are sent in a mail message to the computer's root user. The second command line chmod page (using the man command), removes extra spaces (col-b), and sends the output to the file /tmp/chmod (erasing the previous /tmp/chmod if it exists). The final command results in the text being added to the user's project file:

> I finished the project on Sat Jan 25 13:46:49 PST 2006

## Understanding File Permissions

After you've worked for Linux for a while, you are sure to get a Permission denied. Permissions associated with files and directories in Linux were designed to keep users from accessing others users' private files and to protect system files.

The nine bits assigned to each file for permissions define the access that you and others have to your file. Permissions appear as rwxrwxrwx. The first three bits assigned to the file, and the last three group and to all others. The r stands for read, the w stands for write, and the x stands for execute permissions. If a dash appears instead of the letter, it means that permission is turned off for that associated read, write, or execute.

Because files and directories are different types of elements, read, write, and execute permissions on files and directories mean different things. Table 2-10 explains what you you do with them:

### Table 2-10
Setting Read, Write, Execute Permissions

| Permission | File | Directory |
| --- | --- | --- |
| Read | View what's in the file. | See what files and subdirectories it contains. |
| Write | Change the file's content, rename it, or delete it. | Add files or subdirectories to the directory. |
| Execute | Run the file as a program. | Change to that directory as the current directory, search through the directory, or execute a program from the directory. |

You can see the permission for any file or directory by typing the `ls -ld` command. The named file or directory appears as shown in this example:

```
$ ls -ld ch3 test
rw-rw-r-- 1 chris 4983 Jan 18 22:13 ch3
drwxr-xr-x 2 charlie 10244 Jan 24 13:47 test
```

The first line shows that the ch3 file has read and write permission for the owner and the group. All other users have read permission, which means they can view the file but cannot change its contents or remove it. The second line shows the test (indicated by the letter d) before the permission bits. The owner has read, write, and execute permission, while the group and others have only read and execute permissions. As a result, the owner can add, change, or delete files in that directory, and everyone else can only read the contents, change that directory and list the contents of the directory.

If you own a file, you can use the `chmod` command to change the permission on it as you please. In one method of doing this, each permission (read, write, and execute) is assigned a number—r=4, w=2, and x=1—and you use each set's total number to establish the permission. As owner, set the first number to 7 (4+2+1), and to give the group and others only read permission, you both the second and third numbers to 4 (4+0+0), so that the final number is 744. Any combination of permissions can result in 0 (no permission) through 7 (full permission).

Here are some examples of how to change permission on a file (named file) and what the resulting permission would be:

```
# chmod 777 file  rwxrwxrwx
# chmod 755 file  rwxr-xr-x
# chmod 644 file  rw-r--r--
# chmod 000 file  ----------
```

You can also turn permissions on and off using plus (+) and minus (-) signs, respectively. This can be done for the owner user (u), owner group (g), others (o), and all users (a). For example, start with a file that has all permissions (rwx-rwx). Run the following `chmod` commands using sign options. The result-permissions are shown to the head of each command:

```
chmod +w file      r-xr-xr-x
chmod -x file      rwsrwsr-
chmod go-rwx file  rwx-
```

Likewise, there are some examples, starting with all permissions closed (---------) where the plus is used with `chmod` to permissions on:

```
chmod u+rw files    rw-
chmod a+x files     --x--x--x
chmod ug+rwx files  r-xr-x-
```

When you create a file, its permissions are rw-r-- by default. A directory is given the permission rwx-xr-x. These default values are defined by the value of `umask`. Type **umask** to see what your `umask` value is. For example:

```
$ umask
022
```

The `umask` value masks the permissions value of 666 for a file and 777 for a directory. That same `umask` of 022 results in permission for a directory of 755 (rwx-xr-x). That same `umask` in a file permission of 644 (rw-r--r--). (Execute permissions are off by default files.)

> Tip save: use the -R option of `chmod`, to change the permission for all the files and directories within a directory structure at once. For example, if you want to open permissions completely to all files and directories in the `/tmp/test` directory, you could type:

`$ chmod -R 777 /tmp/test`

This is because the -R flag stands for recursive, and it applies the command to every file and subdirectory within the path.

## Moving, Copying, and Deleting Files

Commands for moving, copying, and deleting files are straightforward. To change the location of a file, use the `mv` command. To copy a file from one, use the `cp` command. To remove a file, use the `rm` command. Here are some examples:

```
$ mv abc def
$ mv abc ~
$ cp abc def
$ cp abc ~
$ rm *
```

Of the two move (`mv`) commands, the first move moves `abc` to the file `def` in the same directory (essentially renaming it), whereas the second move moves `abc` to your home directory. The first copy command (`cp`) copies `abc` to the file `def`, whereas the second copies `abc` to your home directory. The first remove command (`rm`) deletes the file; the second removes all files in the directory (except those that started with a dot).

For the root user, `mv`, `cp`, and `rm` commands are aliased to run with the `-i` option. This causes a prompt to appear asking you to confirm each move, copy, and remove one file at a time, and is done to prevent the root user from messing up large group of files by mistake.

Another alternative with `mv` is to use the `-b` option. With `-b`, if a file of the same name exists at the destination, a backup copy of the old file is made before the new file is moved there.

## Using vi Text Editor

It's almost impossible to use Linux for any period of time and not to use a text editor. This is because Linux configuration files are plain text files that you will certainly need to change manually at some point.

If you are using a GUI, you can run `edit`, which is fairly intuitive for editing. There's also a simple editor you can run from the shell called `nano`. However, most Linux users will use the `vi` or `emacs` command to edit text files. The advantage of `vi` or `emacs` over a graphical editor is that you can use it from any shell, a terminal, or a character-based connection over a network (`telnet` or `ssh`)—no GUI is required. They also contain tons of features, so you can continue to grow with them.

This section provides a brief tutorial on the vi text editor, which you can use to manually edit a configuration file from any shell. If `vi` doesn't suit you, see the “Exploring Other Text Editors” sidebar for other options.
