## Configuring a Firewall in Mandriva

Mandriva offers a way of configuring your firewall after Mandriva is installed:

- From the main menu, select System -> Configuration -> Configure your computer. You are prompted to enter the root password.
- Type the password and click OK. The Mandriva Control Center appears.
- Select Security -> Firewall. The Firewall service appears in the window.
- Select particular services you would like to have available from your desktop system and click OK.

The default settings might be appropriate for many desktop systems. With SSH, FTP, and Echo request, someone could log into your system over the network (with appropriate login and password), get files you offer through your FTP service and ping your computer to see if it is up and running on the network. Of course, opening the firewall to allow SSH and FTP services allows you to have those two services turned on and configured as you like.

If you want to add other ports, click the Advanced button. The Mandriva tool uses a different syntax for adding ports than does Red Hat. You need to separate port numbers and protocols with a slash (for example, 123/udp 123/tcp to open network time protocol for two protocols). Open a range of ports for a protocol by separating them with a colon (for example, 137:139/tcp to allow Windows file and printer sharing from your computer). Separate multiple entries with spaces instead of commas.

## Using Firewalls with iptables

Understanding how iptables works will help you with any firewall you have configured in a Linux system. Previous features — iptchains and ipfwadm — are no longer included in the Linux kernel. Unless you are a Linux with an older kernel (which only a few firewall distributions still have), iptables is your primary tool for firewall configuration in Linux.

The commands used to configure iptables are not very intuitive. Using the iptables command, add rules (one by one) to running Linux kernel. When you have a set of rules you like, save those to a file using iptables-save. Then, when you are ready to use them, read them back in by using iptables-restore.

Most Linux systems offer some sort of interface to manage and load your iptables firewall automatically, very few offer the full range of features you might want. So you will need to understand iptables to do some configuration by hand. Just understanding iptables will help you go from one Linux system to another, regardless of the interface an individual distribution will put on top of it.

## Setting Some Rules

Studying the following steps will help you understand the syntax of firewall rules and the information you can set with them. This procedure is made to run from beginning to end on a computer that you have complete control over. In the process of setting up your firewall rules, you will temporarily cut off communications to and from the machine, so not try this on a machine that must stay connected to the network.

This example illustrates a case where two Ethernet interfaces on a computer (as is typical with a dedicated firewall). The interface defined as eth0 is connected to the Internet, and the interface defined as eth1 is connected to a private network of computers that the firewall is protecting. Presumably, the private computers are a bunch of desktop computers that need to go through the firewall to browse the Internet.

iptables lets you set up tables containing rules for how to handle Internet Protocol (IP) packets that enter the computer. The filtering table is the table you use by default (- t filter) if none is specified on the iptables command line. Other tables you can configure include NAT (- t nat) and mangle (- t mangle). Special uses of NAT and mangle tables will be explained later. It's the filter used in this example.

Rules for what to do with packets that enter and leave the firewall are defined within the context of what are called chains. Available chains for filter tables are INPUT (packets received by the firewall), FORWARD (packets to be routed through the firewall), and OUTPUT (packets created on the local firewall itself). Filtering is done on those chains.

When a packet comes to the chain, it steps through the rules in the chain until it finds a match. A match might depend on where a packet came from or where it is going, for example. When a match is made, the chain jumps to the action (also called target) for that rule, which might define what the packet should be accepted or dropped.

Setting a firewall can be serious business. A misconfigured firewall can reject legitimate requests, forward packets to the wrong places, or even make your computer completely inaccessible from the network. Be cautious if you are trying the following procedure on a computer that you rely on be safe.

- 1. From a Terminal window, become root user:

```
$ su
Password: ********
#
```

- 2. Type the following to see what firewall rules are set on your system:

```
$ iptables -L
Chain INPUT (policy ACCEPT)     prot opt source      destination
Chain FORWARD (policy ACCEPT)
  target     prot opt source      destination
Chain OUTPUT (policy ACCEPT)
  target     prot opt source      destination
```

The example output shows that no filtering rules are currently set for this Linux system, meaning that all packets are accepted (policy ACCEPT) by default. If you make a complex set of firewall rules, you might consider using a different machine to try this.

- 3. These three commands change the default behavior of how packets are filtered for your computer:
$ iptables -P INPUT DROP
$ iptables -P OUTPUT DROP
$ iptables -P FORWARD DROP

In this example, the default behavior is changed such that all packets that come into your network interfaces (INPUT), or request to travel through them (FORWARD) are dropped. In this point, points should be allowed to come in or out of any network interfaces. You can run iptables -L to see that all policies have changed from ACCEPT to DROP. (If this concerns you, don't worry. You can run the commands again, changing DROP to ACCEPT, to make your firewall wide open once. Likewise, a reboot gets you back to your original state.)

- 4. This step configures your firewall will accept or reject ICMP packets. ICMP (Internet Control Message Protocol) messages are for reporting error conditions and controlling connections to your server. Your server receives ICMP packets from computers that want to find out the state of your machine, such as if the machine is currently accessible.
