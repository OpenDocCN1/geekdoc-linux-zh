User mapping — If a user has login accounts for a set of computers (the same ID), NFS, by default, maps that ID. This means that if the user named (UID 110) on maple has an account on pine (mike, UID 110), he can use his own mounted files on either computer from either computer.

If a client is not set up on the server creates a file on the NFS directory, the file is assigned to the remote client's UID and GID. (An 1-1 on the server uses the UID of the owner). Use the map_static option to identify a file that contains user mappings.

The exports page describes the map_static option, which enables you to create a file that contains new ID mappings so that you can remap client IDs into different IDs on the server.

# Exporting the Shared File Systems

After you have edited your /etc/exports file, run the exports command to have exported directories (available to other computers on the network). Reboot your computer or restart the NFS service, and the exports command runs automatically to export your directories. If you want to export them immediately, run exports from the command line (as root).

![](bbox=[0.128, 0.483, 0.203, 0.545])

It's good idea to run the exports command after you change the exports file. If any errors are in the file, exports identifies them for you.

Here is an example of the exports command:

```
# /usr/sbin/exports -a -v
exporting maple:/pub
exporting spruce:/pub
exporting maple:/home
exporting spruce:/home
exporting *:mnt/win
```

The -a option indicates that all directories listed in /etc/exports should be exported. The -v option says to verbose output. In this example, the /pub and home directories from the local server are immediately available for mounting by those computers that are named (maple and spruce). The /mnt/win directory is available to all client computers.

Running the exports command temporarily makes your exported NFS directories available. To have your NFS directories available on an ongoing basis (that is, every your system reboots), you need to set your nfs startup scripts to run at boot time. This is described in the next section.
