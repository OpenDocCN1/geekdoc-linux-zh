When you check in a modified file, CVS opens an editor session to enable you to log a message that describes the changes you made. The editor used is the editor defined in theEDITOR environment variable or compiled-in default (usually vi text editor) if $EDITOR is undefined. This example did not use the -d option because the $CVSROUT environment variable is set.

To check out a specific version, or revision of a file, use the -r option following the checkout or co command, by a revision number. For example, to check out revision 1.1 of the main.c file, use the following command:

```
$ cvs checkout -r 1.1 newhello/main.c
newhello/main.c
```

To see the differences between two revisions, use the diff command, using the -r m,n, where m indicates the revision number you want to check. If you specify -r only once, the indicated version will be compared against the working file (using the diff option). If you specify -r twice, the two versions will be compared against each other working. The following example compares revision 1.2 of showit.c to the current working (the current revision in the working directory):

```
$ diff -r 1.2 main.c
Index: main.c
```

```
RCS file: /space/cvs/newhello/main.c
retrieving revision 1.2
retrieving revision 1.3
diff r1.2 -r1.3
9,10,c9
```

```
< char msg_hi[] = {"Hi, programmer!"};
< char msg_bye[] = {"Goodbye, programmer!"};
>\> char msg_hi[] = {"Hi, programmer!\n"};
> char msg_bye[] = {"Goodbye, programmer!\n"};
12c12
>    printf("%s\n", msg_hi);
>    printf("%s\n", msg_bye);
```

The diff output is easier to understand than you might expect. Lines that begin with < appear in the first file (revision 1.2 of main.c) but not in the second (revision 1.3 of main.c). Similarly, lines beginning with > appear in the second file, but not in the first. Each section of diff output begins with an alphanumeric sequence such as 9,10,c9 or 12c12.
