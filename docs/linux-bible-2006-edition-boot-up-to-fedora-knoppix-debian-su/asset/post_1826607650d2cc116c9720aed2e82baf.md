
# Finding General Security Resources

There are many computer Web resources that now offer information that is particularly useful to Linux system administrators. There are a few sites you can check out:

- *CERT (www.cert.org)*—The CERT Coordination center follows computer security issues. Check their home page for the latest vulnerabilities. The site has articles on security practices (www.cert.org/nav/articles_reports.html). It also has recommendations on what you should do if your computer has been compromised (www.cert.org/tech_tips/win-UNIX-system-compromise.html).
- *SecurityFocus (www.securityfocus.com)*—In addition to offering news and information on general computer security topics, SecurityFocus also offers several Linux resources. In particular, you can subscribe to receive a weekly Security News newsletter.
- *LinuxSecurity (www.linuxsecurity.com)*—This site contains many articles and features related to Linux. It also tracks security advisories for more than a dozen distributions.

# Using Linux Securely

Getting and keeping your Linux systems secure means not only making good decisions about how to set up your system but also how to use it. This section describes some good practices related to passwords, using applications, monitoring system activity by watching logs, and communicating with other systems using secure shell (ssh). Setting up a firewall (as described in Chapter 8) is critical to having a secure system.

# Password Protection

Passwords are the fundamental security tool of any modern operating system and consequently the most commonly attacked feature. It is natural to choose a password that is easy to remember, but very often means choosing a password that is also easy to guess. Crackers work on any system with more than a few users, at least one person is likely to have an easily guessed password. Obviously, choosing good passwords is the first and most important step to having a secure system. Here are some things to avoid when choosing a password:

- Do not use any variation of your login name or full name even if you use varied case, append numbers or punctuation, or type it backwards.
- Do not use a dictionary word, even if you add numbers to it.
- Do not use contiguous letters on the keyboard (such as "qwerty" or "asdf").

# Good Passwords

A good way to choose a strong password is to take the first letter from each word of an easily remembered sentence. The password can be even better by adding numbers, punctuation, and varied case. The sentence you choose has meaning only to you and should not be publicly available (choosing a sentence on your personal page is a bad idea). Table 6-1 lists examples of strong passwords and the tricks used to remember them.

| Password | How to Remember It |
| :--- | :--- |
| Mrcy! | My rusty car is years old! |
| emBpib | elephant pets is better |
| ItGib | Is that coat? Give it back |

The passwords look like gibberish but are actually easy to remember. As you can see, I can place emphasis on words that stand for capital letters in the password. You type your password using the `passwd` command. The `passwd` command within a shell will enable you to change your password. First, it prompts you to enter your old password. To protect against someone "shoulder surfing" and learning your password, the password will not be displayed as you type.

# Securing Linux

Assuming you type your old password correctly, the password command will prompt you for the new password. When you type in your password, the system checks the password against crack to determine if it is a good or bad password. Non-root users will be required to try a different password if the one they have chosen is not a good password. The root user is the only user who is permitted to assign bad passwords. Once the password is accepted by crack, the password command asks you to enter the password a second time to make sure there are no typos (which are hard to detect when you can't see what you are typing). Running as root, it is possible to change a user's password by supplying the password command. For example:

```
# password joe
Changing password for user joe.
New UNIX password: ********
Retype new UNIX password: ********
password: tokens updated successfully.
```

The password command prompts you to enter a new password for joe. It does not prompt you for his old password in this case. This allows root to reset a user's password when that user has forgotten it (an event that happens often).

# Using a Shadow Password File

In versions of UNIX, all user account and password information was stored in a file that all users could read (although only root could write to). This was generally not a problem because the password information was encrypted. The password was encrypted using a trapdoor algorithm, meaning the unencoded password could be encoded into a scrambled string of characters, but the string could not be translated back to the unencoded password. In other words, the trapdoor implies that encryption only goes in one direction, the encrypted password can't be used to go back to the unencoded password.

How does the system check your password in this case? When you log in, the system checks the password you entered, compares the scrambled string that is stored in the password file, and grants access only if the two match. Have you ever asked a system administrator what the password on your account is to hear, "I don't know" in response? If so, this is why: The administrator really doesn't have the password, only the encrypted version. The unencoded password exists only at the moment you type it.

# Breaking Encrypted Passwords

There is a problem with people being able to see encrypted passwords, however. Although it may be difficult (or even impossible) to reverse the encryption of a trapdoor algorithm, it is very easy to encode a large number of password guesses.
