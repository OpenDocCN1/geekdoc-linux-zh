# # Securing Linux

Since the dawn of interconnected networks, some users have been trying to break into other users' systems. The Internet has grown and broadband Internet access has secured, the problem has become even more severe. A home computing an insecure configuration can be used as a powerful mail relay, or allow the user's personal information to become compromised, or any number of other horrors.

Once a time network attacks required some effort and skill on the part of the attacker. Automated tools can get the most novice user up and running trying to promise network-attached systems in an alarming short time. Additionally, warriors have the capacity to turn large numbers of insecure systems into an army of "zombies" usable for massive, coordinated, distributed Denial of Service (DDoS) attacks.

Why should you care about security? According to the Internet Storm Center (http://isc.sans.org/), a computer connected to the Internet has an average of 16 minutes before it falls under form of attack. Securing any computer system is not difficult; it requires some common sense and careful application of good security practices.

In many cases, good practices for securing and protecting systems, monitoring log files, and creating good firewalls will keep out many would-be-intruders. Sometimes, more proactive approaches are needed to respond to break-ins.

Many tasks associated with securing your Linux system are common to desktop and server systems. However, because servers allow some level of access by outside clients, there are special considerations for protecting servers.

This chapter describes general tasks for securing Linux systems and techniques for securing desktop and server systems. It then describes some tools you can try out from a bootable Linux system to troubleshoot your computer and network.
