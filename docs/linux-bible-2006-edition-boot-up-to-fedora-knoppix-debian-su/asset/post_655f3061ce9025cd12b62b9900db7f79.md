
## Part I Linux First Steps

Special shell features enable you to gather input and direct output between commands and the Linux system. To save on typing, you can find, edit, and repeat commands from your shell. Many power users hardly touch a graphical interface, doing most of their work from the shell.

You can use programming constructs such as loops and case statements to quickly do operations that would be difficult to retry over and over. Programs consisting of commands that run from a file are referred to as scripts. Most Linux system administrators use scripts to automate tasks such as backing up data, monitoring logs, or checking system health (See Chapter 2 for information on shell scripts).

The shell is a command interpreter. If you use Microsoft operating systems, you'll find using a shell in Linux is similar to—but generally more powerful than—the interpreter used to run commands in DOS. You can use a graphical interface, but as you grow into Linux you will surely need to use the shell at some point to track down problems. It isn't obvious at first, but with the right help you can quickly learn many of the important shell features. This chapter is your guide to working with the Linux system commands, processes, and file system. It describes the shell environment and helps you tailor it to your needs.

## Starting a Shell

There are several ways to get to a shell interface in Linux. Three of the most common are the shell prompt, terminal window, and virtual terminal. They are described in the following sections.

## Using the Shell Prompt

If your Linux system has no graphical interface (or one isn't working at the moment), you will most likely see a shell prompt after you log in. Typing commands from the shell will be your primary means of using the Linux system.

The default prompt for a regular user is simply a dollar sign:

```
$
```

The default prompt for root user is a pound sign (also called a hash mark):

```
#
```

In Linux systems, $ and # prompts are preceded by your username, hostname, and current directory. For example, a login prompt for the user named jane on computer named tmp appears as:

```
jane@tmp$
```

You can change the prompt to display any characters you like — you can use the current directory, the date, computer name, or any string as your prompt. To configure your prompt, see “Setting Your Prompt” section later in this chapter.

Although there are a tremendous number of features available with the shell, it is easy to begin by typing a few commands to become familiar with your shell environment. In the examples that follow, $ and # symbols indicate a prompt. The prompt is followed by the command that you type (and then you press Enter or Return).

## Using a Terminal Window

With the GUI running, you can open a terminal emulator (sometimes referred as as terminal window) to start a shell. Here are two common ways to launch a Terminal from a Linux desktop:

- **Right-click the desktop.** In the context menu that appears, look for a New Terminal, Terminal Window, or some similar item and select it.
- **Click on the panel.** Many Linux desktops include a panel at the bottom of the screen from which you can launch applications. For example, in Linux systems, you can select the terminal icon and choose Tools > Terminal to open a terminal.

In all cases, you should be able to type a command as you would from a shell with no GUI. There are different terminal emulators available with Linux. One of the following is the default with your Linux system:

- **xterm** — A common terminal emulator for the X Window System (in fact, I've never seen a major Linux distribution that didn't include xterm). Although it doesn't provide menus or special features, it is available with most Linux distributions that support GUI.
- **gnome-terminal** — The default terminal emulator that comes with GNOME. It consumes more system resources than xterm and has useful menus for cutting and pasting, opening new tabs or windows, and setting terminal profiles.
- **kterm** — The kterm emulator that comes with the KDE desktop environment. With kterm, you can display multilingual text encoding and text in different colors.

If you don't like the terminal emulator you get by default, type a command name to try one of others instead.

## Using Virtual Terminals

Many Linux systems, including Fedora and Red Hat Enterprise Linux, start multiple virtual terminals running on the computer. Virtual terminals are a way to have multiple sessions open at once without having a GUI running.

You can switch between virtual terminals which may seem like switching workspaces on a GUI. Press Ctrl+Alt+F1 (or F2, F3, F4, and so on to F6 on Fedora and other Linux systems) to display one of six virtual terminals. The next virtual workspace after the virtual terminals is the GUI; if there are four virtual terminals, you can return to the GUI (if one is running) by pressing Ctrl+Alt+F7. For a system with four virtual terminals, you'd return to the GUI by pressing Ctrl+Alt+F5.

## Choosing Your Shell

In Linux systems, your default shell is bash. To find out what your login shell is, type the following command:

```
$ echo SHELL
/bin/bash
```

In this example, it's the bash shell. There are many other shells, and you can activate a different one by simply typing the new shell's command (ksh, tcsh, csh, bash, and so forth) from the current shell.

> Note Most full Linux systems include all of the shells described in this section. Some smaller Linux distributions may include only one or two shells. The best way to find out if a particular shell is available is to type the command and see if it starts.

You might want to choose a different shell to use because:

- You are used to UNIX System V systems (often ksh by default) or Sun Microsystems and other Berkeley UNIX–based distributions (frequently csh by default), and you are more comfortable using default shells from those environments.
- You want to run shell scripts that were created for a particular shell environment, and you need to run the shell for which they were made.
- You might simply like features in one shell over others. For example, a member of Linux Group prefers ksh over bash because he doesn't like the way aliases are set up with bash.

## Using tcsh (and Earlier csh) Shells

The tcsh shell is the open source version of the C shell (csh). The tcsh shell was created by Bill Joy and with most Berkeley UNIX systems (such as those produced by Sun Microsystems) as the default shell.
