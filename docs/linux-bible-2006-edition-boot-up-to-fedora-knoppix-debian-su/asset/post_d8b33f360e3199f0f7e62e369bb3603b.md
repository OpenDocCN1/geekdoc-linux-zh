
The following examples assume that the connection to the Internet is provided through the first Ethernet card (eth0). Here's an example of a MASQUERADE rule:

```
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
```

And here's an example of a SNAT rule:

```
iptables -t nat -A POSTROUTING -o eth0 --to-source 12.12.12.12
```

You can add several source addresses if you have multiple addresses that provide a route to the Internet (for example, --to-source 12.12.12.12-12.12.12.254). Although MASQUERADE uses some additional overhead, you probably need to use SNAT instead of MASQUERADE if you have a dial-up connection to the Internet for which the IP addresses on each connection.

Make sure that IP forwarding is turned on in the kernel because it is off by default on most Linux systems. To turn it temporarily, use one of the following commands:

```

# Adding Modules with iptables

Some firewall features require modules to be added to the kernel. For example, a client behind your firewall needs to access an FTP server using passive FTP; special modules are required. With passive FTP, the FTP client sends its IP address and the port number on which it will listen for data to the server. If that client is on a computer that is behind your firewall, for which you are not NAT, information must be translated as well or the FTP server will not be able to communicate with the client.

The iptables facility uses modules to track connections, looking inside the FTP data (that is, not in the IP packet header) to get the information you need to do NAT (remember that computers from the Internet cannot talk directly to your private IP addresses). For FTP connection tracking, you need to have the following modules:

```
ip_conntrack
ip_conntrack_ftp
ip_nat_ftp
```

For clients to use some servers from behind the firewall, you need to add connection tracking and NAT as well. In those cases, addresses and port numbers are stored within the IRC packets, so those packets must be translated, too. To allow clients on your LAN to use IRC services, you need to load the following modules:

```
ip_conntrack_irc
ip_nat_irc
```

The default for IRC connections is 6667. If you don't want to use the default, you can add different port numbers when you load the connection-tracking modules:

```bash
# modprobe ip_conntrack_irc.o ports=6668,6669
```

# iptables as a Transparent Proxy

You can use REDIRECT to cause traffic for a specific port on the firewall computer to be directed to a different port. This feature enables you to direct host computers on your local LAN to a proxy service on your firewall without those hosts knowing it.

Here's an example of a command that causes a request for Web service (port 80) to be directed to a proxy service (port 3128):

```bash
# iptables -t nat -A PREROUTING -p tcp --dport 80 \
 -j REDIRECT --to-ports 3128
```

In this example, any packet destined for port 80 (--dport 80) is redirected to port 3128 (--to-ports 3128). Note that the packet is changed before it is routed (-A PREROUTING).

You can use only REDIRECT targets in PREROUTING and OUTPUT chains within a table. You can also give a range of port numbers to spread the redirection across multiple port numbers.

# Using iptables for Port Forwarding

What if you have only one IP address but you want to use a computer other than your firewall to provide Web, FTP, DNS, or some other service? You can use the Dynamic Network Address Translation (DNAT) feature to direct traffic for a particular port on your firewall to another computer.

For example, if you want all requests for Web service (port 80) that are directed to the firewall (-d 15.15.15.15) to be directed to another computer on your LAN, you can use the following iptables command:

```bash
# iptables -t nat -A PREROUTING -p tcp -d 15.15.15.15 --dport 80 \
  -j DNAT --destination 10.0.0.25
