# Automatically Mounting an NFS File System

To set up an NFS file system to mount automatically each time you start your Linux system, you need to add an entry for NFS file system to the /etc/fstab file. That file contains information about all different kinds of mounted (and available to be mounted) file systems for your system.

Here's the format for adding an NFS file system to your local system:

```
host:directory mountpoint nfs options 0 0
```

The first item (host:directory) identifies the NFS server computer and shared directory. mountpoint is the local mount point where NFS directory is mounted. It is followed by the file system type (nfs). Any options related to the mount appear next in a comma-separated list (The last two zeros configure the system to not dump the contents of the file system and not use fsck on the file system).

The following are examples of NFS entries in /etc/fstab:

```
maple:tmp /mnt/maple size=8192,wsize=8192 0 0
oak:apps /oak/apps nfs noauto,0 0
```

In the first example, the remote directory /tmp from the computer named maple (maple:tmp) is mounted on the local directory (the local directory must always exist). The file system type is nfs, and read (size) and write (wsize) buffers are set at 8192 (see the "Using Mount Options" section later in this chapter) for connection. In the second example, the remote directory is on the computer named oak. It is set up as an NFS file system (nfs) that can be mounted on the /oak/apps directory locally. This file system is not mounted automatically (noauto), and can be mounted only as read-only (ro) using the mount command when the system is already running.

> The default is an NFS file system is read/write. However, the default for exporting a file is read-only. If you are unable to write to an NFS file system, check that it was exported as read/write from the server.
