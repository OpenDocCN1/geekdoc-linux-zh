A string that begins with an at (@ sign is treated as an NIS netgroup name. A host name is matched if it is a host member of the specified netgroup. Netgroup names are not supported for daemon process names or for client names.

An expression of the form n.n.n/m.m.m is interpreted as a net/mask pair. A host address is matched if it is equal to the bitwise and of the address and the mask. For example, the net/mask pattern 131.155.72/0/255.255.254.0 matches every address in the range 131.155.72 through 131.155.73.255.

The example hostallow contains the first two types of client specification. The entry 199.170.177 will match any IP address that begins with that string, such as 199.170.177. The client entry .linuxtoys.net will match host names such as jukebox.linuxtoys.net or picframe.linuxtoys.net.

Let's examine what happens when a host named jukebox.linuxtoys.net (with IP 199.170.179) connects to your Linux system using the Telnet protocol. In this case, the Linux system is Fedora, which uses the xinetd daemon to listen for service requests with TCP:

+   1. xinetd receives the connection request.
2. xinetd compares the address and name of jukebox.linuxtoys.net to the rules in /etc/hosts.allow. It starts at the top of the file and works its way down until it finds a match. Both the daemon (the program handling the network service on your Fedora box) and the connecting client's IP address or name must match the entry in the hosts.allow file. In this case, the second rule that encountered matches the request: in.telinetd:199.170.179..linuxtoys.net
3. The jukebox host is not in the 199.170.177 subnet, but it is in the linuxtoys.net. xinetd stops searching as soon as it finds this match.

How if jukebox connects to your box using the CUPS-ld protocol? In this case, none of the rules in hosts.allow; the only line that refers to the IP daemon does not refer to the 199.170.179 subnet or so xinetd connects to the hosts.deny file. The entry ALL: ALL matches, so tcpd denies the connection.

The ALL wildcard was also used in the hosts.allow file. In this case, we are telling xinetd to permit absolutely any host to connect to the FTP server on the Linux box. This is appropriate for running an anonymous FTP server that anyone can access. If you are not running an anonymous FTP server, you should not use the ALL flag.
