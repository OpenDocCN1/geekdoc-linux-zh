# Starting with iptables

If you have a running Linux system in front of you, you can immediately get a feel for how your firewall is working in a number of ways. To go beyond listing the current firewall rules, however I recommend that you try the procedure I describe in the next section on a Linux system that is set up for you to play with. KNOPPIX is a great way to try that procedure without doing any harm (because everything disappears after your next reboot). Otherwise, just read along.

# Setting Some Rules

Studying the following steps will help you understand the syntax of firewall rules and the information you can set with them. This procedure is made to run from beginning to end on a computer that you have complete control over. In the process of setting up your firewall rules, you will temporarily cut off communications to and from the machine, so not try this on a machine that must stay connected to the network.

This example illustrates a case where two Ethernet interfaces on a computer (as is typical with a dedicated firewall). The interface defined as eth0 is connected to the Internet, and the interface defined as eth1 is connected to a private network of computers that the firewall is protecting. Presumably, the private computers are a bunch of desktop computers that need to go through the firewall to browse the Internet.

iptables lets you set up tables containing rules for how to handle Internet Protocol (IP) packets that enter the computer. The filtering table is the table you use by default (- t filter) if none is specified on the iptables command line. Other tables you can configure include NAT (- t nat) and mangle (- t mangle). Special uses of NAT and mangle tables will be explained later. It's the filter used in this example.

Rules for what to do with packets that enter and leave the firewall are defined within the context of what are called chains. Available chains for filter tables are INPUT (packets received by the firewall), FORWARD (packets to be routed through the firewall), and OUTPUT (packets created on the local firewall itself). Filtering is done on those chains based on the set of rules you set up.

When a packet comes to the chain, it steps through the rules in the chain until it finds a rule that matches. A match might depend on where a packet came from or where it is going, for example. When a match is made, the chain jumps to the action (also called a target) for that rule, which might define what the packet should be accepted or dropped, or have some other action on it.
