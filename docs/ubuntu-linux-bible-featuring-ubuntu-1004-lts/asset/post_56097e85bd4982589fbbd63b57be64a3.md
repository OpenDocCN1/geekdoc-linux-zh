
# Chapter 20: Adding Hardware and Attaching Peripherals

Creating a filesystem is done using the mkfs utility, which is actually just a wrapper for other commands that create different types of filesystems. On most Linux systems, you will be creating filesystems in any of the following formats: ext2, ext3, JFS, ReiserFS, Windows Virtual FAT (vfat), or XFS. These types of filesystems were explained in the section of Chapter 4 entitled "Local Filesystems: Setup and Journaling". To create any of these types of filesystems you simply specify the type of filesystem you want to create using the mkfs command -t (type) option. The following example shows the command and output used to create an ext3 filesystem on the partition /dev/sda1:

```
$ sudo mkfs -t ext3 /dev/sda
mke2fs 1.41.3 (12-Oct-2008)
Filesystem label=
OS: Linux
Block size=4096 (log=2)
Fragment size=4096 (log=2)
362688 inodes, 732563 blocks
362681 blocks (5.00%) reserved for the super user
First data block=
224 block groups
32768 blocks per group, 32768 fragments per group
16352 inodes per group
Superblock backed up on blocks:
32768, 98304, 163840, 229376, 249412, 819200, 88473, 1605632
Writing inode tables: 224/224
Creating journal (32768 blocks): done
Writing superblocks and filesystem accounting information: done
This filesystem will be automatically checked every 25 days or 180 days, whichever comes first. Use tune2fs -c -1 to override.
```

That's all there is to it! You can now mount this partition using the mount command, or permanently add it to the list of filesystems that will be mounted each time you boot your system. Both of these concepts were explained in Chapter 4.

The mkswap command enables you to format a specific partition in a special way so that it can be used as swap space for your system's virtual memory manager. As example, the command used to create a swap partition on /dev/sda2 and the output from that command are:

```
# mkswap /dev/sda2
Setting up swap version 1, size = 1011703 kB
no label, UUID=731c0f53-bf25-4f91-9ac5-73a2b5bbefeb1
```

You can begin using this swap space immediately by executing the command /dev/sda2. To add this swap space to your system permanently, add it to your system's /etc/fstab file, as described in Chapter 4.

# Using PCMCIA Cards

PCMCIA (Personal Computer Memory Card International Association) cards are the original mechanism designed to support removable and insertable interfaces in portable computer systems. PCMCIA cards are now often just called PC Cards because no one can ever remember the acronym name (as suggested by the optional PCMCIA expansion, "People Can't Memorize Industry Acronyms”). Thanks to the rise of USB, PCMCIA cards are not as common as they were, but it's still useful to talk about them in case you're installing Ubuntu on an older laptop.

PCMCIA cards are available that provide wired and wireless network interfaces, modems, SCSI, USB, and FireWire interfaces for computer systems that don't have them, and so with the 2.6 kernel, the traditional Linux PCMCIA support package was integrated into the hotplug system to support the creation of appropriate device nodes when PCMCIA cards are inserted.

The primary application to identify any PCMCIA cards inserted in your system is the pccardctl application (formerly known as cardctl). However, how the kernel handles devices mean that this utility may not return detailed information about a PCMCIA card. To see what cards are present in your system and to display summary information about them, execute the pccardctl ident command. That will return something like the following:

```
$ pccardctl ident
Socket 0:
 no product info available
Socket 1:
 product info: "LEXAR ATA FLASH CARD " "STORM " "TE01"
manifest: 0x04e01, 0x0200
function: 4 (fixed disk)
```

This shows that I have two PCMCIA cards inserted but that no information is available the first one. Some of the other pccardctl commands may provide more information. The pccardctl ls command, for instance, displays the following:

```
$ pccardctl ls
Socket 0 Bridge: [yenta_cardbus] (bus ID: 0000:02:03.0)
Card bus -- see "lspci" for more information
Socket 1 Bridge: [yenta_cardbus] (bus ID: 0000:02:03.1)
Socket 1 Device 0: [pata_pcmia] (bus ID: 1.0)
```

This shows that the PCMCIA network card in my first PCMCIA slot is being handled as a PCI card, while the compact card is being handled by the Parallel IDE subsystem.

In most cases, the hotplug/udev subsystems will automatically create device nodes using the standard mechanisms to notify you when new PCMCIA storage devices are attached, and when new PCMCIA interfaces appear, and so on.

# Adding PCI Cards

PCI cards are slightly different from most of the devices discussed elsewhere in this chapter because they typically provide support for other devices such as speakers (PCI sound cards), storage devices (PCI USB, FireWire, or SCSI cards), or basic devices such as modem serial ports. Your system must be turned off to add a PCI card, and discovering a new PCI card during the boot process is an unusual event. The information that may appear in the kernel log related to new PCI cards is the discovery of devices that are attached to them, such as serial ports, disk drives, and so on.

If you have problems accessing newly-inserted PCI cards or the devices attached to them, it is useful to list the PCI devices found in your system to verify that the cards have been correctly identified by the system. The command used to do this is lspci:

# Examining and Troubleshooting Devices Graphically

Ubuntu systems provide a great graphical utility called the Device Manager that enables you to browse, navigate through, and explore the hardware on your system from your system's point of view. This utility isn't installed by default, but you can install it using your favorite Package Management software (as discussed in Chapter 19) the gnome-device-manager package on an Ubuntu system. If it is installed, select Applications -> System Tools Device Manager on an Ubuntu system to start this tool, which displays the initial dialog shown in Figure 20-21.
