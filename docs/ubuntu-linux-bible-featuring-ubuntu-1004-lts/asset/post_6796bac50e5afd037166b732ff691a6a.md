## Copying Files to Other Machines over a Network

If you create or modify files while running from a Desktop CD and want to save that work, but don't want to save it to any of your system's hard disk partitions (as described earlier in this chapter), you can still save those files by copying them over the network to another machine.

Linux provides several ways to enable copying files to other systems over the network. Two of the most common and popular of these are as follows:

- The `ftp` (file transfer protocol) utility, which establishes a connection to another machine and enables you to interactively transfer files in either direction
- The `scp` (secure copy) utility, which enables you to quickly transfer files to other machines over a secure, encrypted connection

These commands are explained in detail in Chapter 25, "Connecting to Other Systems." They're summarized here so that you know that there are ways to save any work you've done from an Ubuntu Desktop CD that do not involve local storage. This can be very useful, for example, if you are using an Ubuntu Desktop CD to recover data from a crashed system or one that can't boot on its own for some reason.

## Using Desktop CD Persistence

Live CDs like the Ubuntu Desktop CD provide an easy way to temporarily run any compatible computer system into an Ubuntu Linux system. However, the fact that most Live CDs don't provide any sort of persistent storage for configuration data, custom applications, and so on (on manually copying files to other local or networked storage) traditionally limited the practical usability of Live CDs to simple demonstrations, one-time experimentation, and general system repair and recovery efforts. Luckily, things are better now—thanks to really clever people, it's fairly easy to automate changes you make when running from the equivalent of an Ubuntu Desktop CD—and without having to deal with manually mounting and unmounting filesystems, saving your work, and so on.

Earlier Ubuntu introduced a mechanism for associating persistent storage with the Live CD boot process. This mechanism enabled you to format an external storage device with a special name (casper-rw) and use it at boot time (in conjunction with the Desktop CD), adding a kernel boot option (persistent) to tell the boot process use the contents of that device to restore settings, personal data, and even installed applications. This approach had a few problems, the most significant of which was that it required an external storage device (typically a USB flash memory stick) and an Ubuntu Desktop CD. Aside from the hassle of carrying around these, my particular complaint was that my Desktop CD kept breaking when I put them in my back pocket and sat them down.

Luckily, improvements in flash drive size, price reductions for flash drives, and software improvements have made being able to do work from an Ubuntu Desktop even easier. Ubuntu systems include an easy-to-use command for creating a bootable USB flash drive (generally referred to as a stick) that works like the Desktop CD but provides persistent storage when using the "Try Ubuntu without any change to your computer" option. This gives you a portable system from which you can run Ubuntu or install it on another computer system without requiring the use of a CD drive. All you need nowadays for this type of portable Ubuntu system is a USB flash drive that is at least 2 GB in size.

## Chapter 2: Installing Ubuntu

### Caution

If you want to create a bootable USB drive manually, the folks at PenDriveLinux.com (www.pendrivelinux.com) have some truly useful tutorials that will walk you through the process of manually creating a Ubuntu system on a USB stick. Their tutorials are clearly explained and also include scripts and configuration files that you can download from their site to make things even easier.

Flash drives are great—they are fast, far less energy than hard drives, do not generate heat, do not noise, and have no moving parts that can stop when you drop them. On the downside, they do have one potential limitation that you'll hear people talk about—you can only write to each storage a certain number of times. (Flash storage units are usually referred to cells or address blocks, and are analogous to the sectors of a hard drive.) Luckily, most flash drives use a technique known as wear-leveling to evenly distribute writes across the drive so that no single area gets written more frequently. The longevity of a modern flash drive is usually predicted to be at least 5 or 10 years. If you're still running Ubuntu off the same drive 5 years now, it might be time to finally consider an upgrade.

### Note

In order to use the bootable USB flash drives discussed in this section, your computer system must be able to boot from a USB device. Most PCs support this, but some systems also require that you manually enable BIOS support before you can boot from a USB device. Booting from USB devices is usually a standard BIOS boot option.

As mentioned previously, the Ubuntu Desktop provides an easy, graphical mechanism for creating a bootable USB flash drive that works much like the Desktop CD, but also provides persistent storage so that any system settings you configure, applications that you install, and files that you are preserved across reboots. This will allow you to reuse any FAT32 partition that you have on your USB stick, so if you have formatted your USB stick to use another type of filesystem or have created multiple partitions on your USB stick, you may want to see the sidebar on "Reformatting a USB Flash Drive," later in this chapter.
