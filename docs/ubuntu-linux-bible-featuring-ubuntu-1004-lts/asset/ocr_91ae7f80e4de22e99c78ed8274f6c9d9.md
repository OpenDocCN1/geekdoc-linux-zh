# Chapter 19: Adding, Removing, and Updating Software

# Note

The examples in this section reflect the /etc/apt/sources.list settings for the Ubuntu 10.04 (Lucid) release. If you are working with a different release, you should replace the word lucid in these examples with the name of the Ubuntu release you are using. You should not mix repository entries for different releases in an /etc/apt/sources.list file because the repositories for a newer release will typically provide the same software as the repositories for older releases and will be compiled against a set of system libraries that are found on the newer release.

Lines beginning with a hash mark (#) in the /etc/apt/sources.list file are comments. If you look through the lines in the default /etc/apt/sources.list file on your system, you will note that entries for access to the partner repository are already present in this file, but commented out. You can enable access to this repository by using sudo to edit this file in your favorite editor. To do this, edit the /etc/apt/sources.list file with your favorite editor, using a command like the following:

```
$ sudo em /etc/apt/sources.list
```

Remove the hash marks at the beginning of the lines that enable the partner repositories, and save the updated file. The updated entries in a sample sources.list file would look like the following:

```
deb http://archive.ubuntu.com/ubuntu/ lucid partner
deb-src http://archive.ubuntu.com/ubuntu/ lucid partner
```

You could, simply add these entries to the end of the lines that already provide access to the main, restricted, universe, or multiverse components of Ubuntu repositories, but I prefer to keep them separate for clarity regarding licensing differences—and because that stays closest to the original format of the default sources.list file.

# Note

Just to be perfectly clear, installing software from the universe and multiverse repositories may add software to your system that has licensing requirements you or the company that you work find odious (such as MP3-related or video-related software), for which support is not guaranteed by the Ubuntu folks (even if you purchase support, there are no commitments to it), and which may be difficult to get support anywhere. If you are configuring systems for enterprise use, make sure your firm is comfortable with the licenses provided with non-free software in the universe and multiverse repositories. I use all of the software discussed in this book and am therefore my very own test case for everything this book discusses, but your mileage (and your responsibilities) may vary.
