It inherently satisfies one of the most fundamental requirements for backup media, which is storing backup off-site so that a local catastrophe doesn't wipe out your computer and backups. Canonical's Ubuntu Storage-as-a-service offering is especially easy for Ubuntu users to take advantage of two reasons:

Ubuntu One is not purely a backup mechanism because its focus is actually on mirroring the contents of a folder to any machine which you use it. However, if you only use it on one or a small number of machines, it is a fine personal solution for critical files, as long as you remember to copy them into the Ubuntu One folder in your home directory (or simply work on them).

Installing Ubuntu One on your Ubuntu system is as easy as your favorite package management software to install the ubuntu-client-gnome package on your desktop Ubuntu system, also install the underlying ubuntu-client package. Installing these packages will create an Ubuntu One folder in your home directory, and will install an Ubuntu One applet in GNOME panel.

In order to use Ubuntu One, you'll have to create an account with Canonical's Launchpad site, which you can do from the page at https://www.ubuntu.com/plans. This page lists the available Ubuntu One plans: 2GB of free storage or 50GB of non-free (currently $10.00 USD per month). Launchpad is Canonical's central site for interacting with Ubuntu and Canonical, reporting bugs, and so. Once you have a Launchpad account, you can return to your computer system and use the Ubuntu One applet to connect to Ubuntu One using your Launchpad login and password. The first time you connect to Ubuntu One from any computer system that you use, which is easy to do using Ubuntu One web page.

At any point, any file you put in the Ubuntu One folder in your home directory will automatically be mirrored to your Ubuntu One account. To access them from any other system, simply right-click on the Ubuntu One applet, select Connect to authorize that machine to Ubuntu One, and the files in your Ubuntu One folder will automatically be synchronized to the computer that you're using. You can access your files via the web through /ubuntu.com/files.

Ubuntu also provides a command-line tool usync (that's u numer one, and the word "sync") to automatically synchronize file and directories to directories other than your Ubuntu directory. In order to use this tool, you must install the ubuntu-client-tools package.

Once you've installed this tool, you can identify directories that you want to sync/from your Ubuntu One account by executing usync --init DIRECTORY command, where DIRECTORY is the name of a directory that you want to be a mirror of your Ubuntu One folder. Executing this command will display a dialog requesting that you grant access to your GNOME keyring (GNOME stored authorization information). Click Always Allow. You can then synchronize directory with your Ubuntu folder, uploading files using the usync --action=upload command, downloading them to a machine using the usync --action=download command, synchronizing them using usync --sync command, and so on. The main page for the usync command offers more details.

## Linux Time Machines

Apple's Mac OS X is a great computing environment—it provides an easy-to-use graphical interface on top of a powerful, UNIX-like operating system. Remind you of anything? Apple has always provided innovative, user-friendly software, and with the release of Mac OS X 10.5, as Leopard, they introduced an impressively friendly and powerful backup package as Time Machine. Time automatically tracks changes to the files and directories on your system and backs up multiple snapshots of your system to an external (or networked) storage device. Should you accidentally delete a file or directory or simply convert to an older version, you can explore these snapshots graphically and examine or restore a version of that data from any point in Time Machine's.

As the saying, "Imitation is the sincerest form ofattery" (Charles Colton, 1820). Not to be undone by more commercial software, Linux-based packages that provide equivalent functionality have begun to appear, most of which are graphical wrappers over the rsync utility (discussed earlier in this chapter), with various bells and whistles to make it easy to browse "snapshots," identify avoidable versions of specific files, extract specific versions of these, and so on. These sorts of utilities paint an impressive useless face on traditional backups, and Apple deserves merit from conceptualizing and automating backups to the point where they are actually user-friendly. Like Mac OS X's Time software, similar Linux backup mechanisms are best used with a networked resource, or in a single-system environment, an external drive. Backups can't protect against catastrophic problems, such as a file or system tragedy, unless you also "back up the backups" to an off-site location. If I had a nickel for every time someone lost both their computer systems and their backups in a failure because they were stored side-by-side, I'd have a bunch of silver, smoky pennies. Don't add one to my collection.

The following are worth a look to do snapshot-style backups on Ubuntu systems:

- **Back In Time:** Back In Time is a really nice GTK-based package that provides a nice, date-oriented snapshot browser and a single-button restore mechanism. Figure 28-7 shows the Back In Time snapshot browsing and restore interface. Back In Time is my favorite of the Linux Time Machine reimplementations, it is the Time Machine-like solution that I personally use, and is the one that I'd recommend in Ubuntu-only environments. Back In Time is available as an Ubuntu DEB package from its home page at www.le-web.org/back-in-time.

- **FlyBack**: Originally a Google Summer of Code project, FlyBack is the least active of the Linux Time Machine-like applications that I'm aware of, but works fine. FlyBack is installed from Subversion or a tarball, which is not exactly "grandfather-friendly," but it's worth a look and some handy features in its configuration interface, such as the ability to automatically identify networked filesystems as possible snapshot storage locations.
