## Troubleshooting

In any debugging or troubleshooting exercise, log files are your friends. Lines 24, 28, and 30 in the original server configuration file shown earlier in this chapter identify the log files used by this server, and the level of logging occurs. Line 24 identifies the name of the error log file as /var/log/apache2/error.log. Line 28 sets the logging level to warn (warnings), which is slightly more useful than only logging errors, but is not useful as debug when actually debugging a new site or server. Line 30 sets the server to create a single log file /var/log/apache2/access.log that will log all access requests to the server in NCSA combined format.

The following Apache logs are exceptionally useful for debugging purposes:

- access.log: Shows all attempts to access the server, listing the IP address of the host that attempted access, a timestamp, the actual request that was made, and information about the browser that the request was received from.
- error.log: Shows all errors of level warning or above (i.e., more serious) that the server encountered when trying to process an access request. This includes pages that can't be found, directories to which access was denied, and so on.

Apache 2's logging levels are very useful in controlling the amount and type of information that appears in the Apache logs. These levels are as follows:

- emerg: Reports only emergency conditions that make the Web server unstable.
- alert: Logs situations requiring immediate action and that may identify problems in the host system.
- crit: Log critical errors that may indicate security, server, or system problems.
- error: Reports noncritical errors that indicate missing pages, bad server configuration directives, and general error conditions.
- warn: Log messages that warn of noncritical problems or internal conditions that should be investigated.
- notice: Reports normal but significant conditions that should still be looked into.
- info: Logs informational messages that may help you identify potential problems or suggest possible reconfigurations.
- debug: Logs pretty every state change on the system, such as every file open, every server activity during initialization, and so on

You should not set the log levels lower than crit on any production Web server. I generally find that warn is the best choice for production servers, and I use notice, info, or debug only when a server is actually having performance or responsiveness problems. Also, don't forget that you actually have to look at the log files for them to be useful.

## Introduction to Mail Servers

The components of an e-mail system can be confusing, so I usually generalize them as the difference between receiving and retrieving—my mail server receives e-mail, and my e-mail client lets retrieve my-mail from there. In overall mail-server, there are three components:

- **Mail Transfer Agent (MTA):** A program that handles transferring e-mail from computer to another, using the Simple Mail Transfer Protocol (SMTP). Well-known examples of MTA are Microsoft Exchange, Sendmail, Postfix, qmail, and MTA are often referred to as "mail servers".

- **Mail Delivery Agent (MDA):** A program that actually delivers the e-mail received by an MTA into your mailbox and can do both preprocessing, such as spam filtering and virus detection, and auto-responder tasks, such as sending "I'm on vacation". MDA also handles the presentation of mail from the mailbox to yours, supporting protocols such as the Post Office Protocol (POP and POP3) and the Internet Message Access Protocol (IMAP). Common examples of MDA on Linux systems are procmail, Qpopper, Gyrus, pop3d, Courier IMAP, and / bin/mail. MDAs can be directly integrated into an MTA, as is with the Microsoft Exchange and often with Linux systems when mail is read directly from a traditional UNIX-style mail file.

- **User Mail Agent (MUA):** A program that lets you send and read the messages in your personal mailbox using protocols such as POP, POP3, and IMAP. Most MUAs provide support for composing and managing mail messages. Common examples of MUAs are Evolution, Microsoft Outlook, Mutt, KMail, Alpine, and Thunderbird.
