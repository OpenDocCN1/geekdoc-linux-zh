# Tip

Aside from the fact that backups can be subject to the vagaries of the device on which they're written, having those devices available when you need to restore backups is an important point to consider. It is a well-known nerd that many government and military sites have huge collections of backup data on devices that don't exist anymore, such as super-low-speed tape drives and 1-inch or 7-track tapes. Even if the devices exist, the data is often not recoverable, because it's written in some ancient, twisted backup format, word size, and so on. When you retire a computer, deciding if you'll ever need to restore any of your data is an easily overlooked issue. If you're lucky, you'll be able to read the old archives in your new system and write them out to some newer media by using some newer backup format. If you're not, you've just acquired a huge number of loose, awkward paperweights that will remind you of this issue.

# Deciding What to Back Up

Aside from cost-saving issues like using higher-density media such as CD-ROMs for archive purposes, another way to reduce the number of backups that you have to keep around, as well as minimize the time it takes to do them, is to treat different filesystems when you're backing them up. For example, system software changes very frequently, so you may only want to back up the partitions holding your operating system when you do an archive. Similarly, locally developed application software changes relatively frequently, so you may only want to back up that week. I can count on one hand, with your finger, the number of times I've needed to restore an old version of an application. On the other hand, you may not be so lucky.

Keeping backups of your operating system and its default applications is important, and is critical to restoring or rebuilding an entire system you should ever need to do so (which is known in backup as a *bare-metal restore*). In terms of backups (and thanks to the excellence of the package management software available for Ubuntu systems), you can just preserve your original installation media (or even re-retrieve it over the net) if it is necessary to completely restore the system software for your Ubuntu system. If your systems use a custom kernel or some loadable kernel modules, make sure that you have a backup of your current configuration and all of the configuration files in directories as /etc that describe the state of your system. You will be glad if the disk on which your finely and heavily tweaked version of an operating bursts into flames one last night.

The issues in the first few sections of this chapter often give system administrators and managers migraines. Losing data is as painful if you're supporting yourself. Thinking about, designing, and implementing reasonable backup policies, schedules, and disaster recovery plans is an important task no how many people will be affected by a problem. Backups are like insurance policies—you hope that you never need to use them, but if you do, they had better be available.

# Backup Software for Linux

Many backup utilities are available for Ubuntu systems. Most of these are traditional command line utilities that can create archive files or write to your backup media of choice in various formats, but some interesting open source graphical tools are also beginning to appear.
