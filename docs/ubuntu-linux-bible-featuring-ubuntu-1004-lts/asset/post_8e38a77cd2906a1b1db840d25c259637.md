## Backing Up Files to Local, Removable Media

The section of this chapter entitled "Backups 101" introduced the basic concepts of backups, many of which may seem impractical for home use. Whether or not they are really impractical depends on the problems that you will be able to solve using your backups. If you are most interested in protecting yourself against disk failures or the accidental deletion of critical files that you're working on, may not need to worry about doing archive and incremental backups—doing spot backups of important files and directories to a CD-R or DVD-R may suffice. Similarly, if you don't need to be able to restore any file from any point in time, but just need to have recent copies of your files, spot backups of the directories that you want to back up may be sufficient, with whatever frequency you're comfortable with. If you're not concerned about losing all of your data if your house or apartment is destroyed, then you don't have to worry about things storing backups off-site.

The bottom line is that I can't tell you you're comfortable with—that's up to you, and defines your backup strategy. The next few sections highlight how you can use some of the utilities mentioned earlier in this chapter (and even the standard Linux cp command) to create backup copies of important files.

## Archiving and Restoring Files using tar

The tar program is one of the oldest and most classic Linux/Unix utilities. Although it can write to a backup device, such as a tape drive, the tar command is commonly used to create archive files, as source code, that can be shared with others. Archive files created using the tar command typically have the file extension .tar. The GNU tar command, which is the version of tar found on Ubuntu and all other Linux systems, provides built-in compression capabilities, being able to automatically compress tar archives on the fly. Compressed tar archives typically have the file extension .gz, indicating that they are compressed (and can be uncompressed) using the gzip application, or the file extension .tar.bz2, indicating that they are compressed and can be uncompressed using the bzip2 application. Archive files produced using the tar utility are typically referred to as tarballs.

## Tip

For home use, the most popular backup method is simply dragging and dropping directories to CD-R or DVD-R media to create spot backups of those directories. The second most popular way of backing up your system is to have drives that you can attach to your system via USB or FireWire ports. On the plus side, unless you're using a really removable hard drive, this gives you a larger pool of available storage for backups than a CD or DVD, and enables you to store more backups of important files and directories and create a single copy of each important directory on removable storage, which you can then update each time you do backups. On the minus side, a removable hard drive is much more expensive than CD-R or DVD-R disks and is more of a pain to store off-site and retrieve each time you do backups.

## Note

Because of its age, you have to be kind when passing arguments to the tar command, because in some cases they must be specified in a particular order.

- Creating an archive file using tar is easy. For example, to create a tarball called home_dir_backup.tgz that contains all of the directories in /home, you could use commands like the following:

```
$ cd /home
$ sudo tar czvf /tmp/home_dir_backup.tgz *
```

## Note

Note that you want to write the backup file somewhere other than the directory that you are backing up. Creating a backup file in the directory that you're working would cause the tar command to back up the file it was creating, which would not work correctly and waste tremendous amounts of space.

- The options in the preceding command have the following:

* c: Create a new archive. If a file by the specified name already exists, it will be overwritten, and its original contents lost.
* z: Compress the archive using the same techniques used by the gzip application.
* v: Be verbose, displaying the name of every file added to the archive file as it is added.
* f: Write the output of the tar command to the file name appears as the new argument on the command line. In this example, the output of the tar command would be written to the file /tmp/home_dir_backup.tgz.

After a significant amount of output, the file /tmp/home_dir_backup.tgz will be created, containing a complete recursive copy of all files and directories under /home. You can then copy this file to backup media as a CD or DVD, or to a removable hard drive.

After you've created a tarball of a given set of directories, you can easily create another tarball that only contains files and directories that have changed since a specific date (such as the date on which the first tarball was created), using commands like the following:

```
$ cd /home
$ sudo tar czvf /tmp/home_dir_backup.tgz --newer "2006-06-23"
```

This command produces extremely verbose output, even if you drop the v option, which is puzzling at first. This is an artifact of the format used in tar files. Even when used with the --newer option, the tar file header must contain the complete directory structure in which it is looking for files newer than the specified date. This is necessary so that the tar command can create extracted files in the right directory location. In other words, if you use the tar command to extract the entire contents of a tarball using the --newer option, it will create an empty directory hierarchy that only contains files that are newer than the date when the tarball was created.

Creating tarballs isn't much fun without being able to retrieve files from them. You can extract various things from a tarball:

- Its entire contents. For example, the following command would extract the entire contents of the tarball home_dir_backup.tgz, creating the necessary directory structure in which you executed the command:

```
$ tar zxvf home_dir_backup.tgz
```

- One or more directories, which recursively extracts the contents of those directories. For example, the following command would extract the Ubuntu_Bible, and all the subdirectories and files that contains, from the tarball home_dir_backup.tgz, creating the necessary directory structure under the directory in you executed the command:

```
$ tar zxvf home_dir_backup.tgz Ubuntu_Bible
```

- One or more specific files, which extracts those files in their original location. For example, the following command would create the directory Ubuntu_Bible and extract the file chap22.txt from the tarball home_dir_backup.tgz, creating the Ubuntu_Bible directory under the directory in you executed the command:

```
$ tar zxvf home_dir_backup.tgz Ubuntu_Bible/chap22.txt
```

For more detailed information on the tar command, see its online reference information (man tar). As one of the oldest Linux/Unix commands, it has accumulated a huge number of command-line options over the years, of which you will probably never use. However, command-line options are like bullets — you can never have too.
