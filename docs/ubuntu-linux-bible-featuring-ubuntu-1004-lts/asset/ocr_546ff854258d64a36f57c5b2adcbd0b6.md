This section explains the internals of the sudo command and its configuration file, and discusses how to grant administrative privileges to other users in various forms.

+   - sudo is a command that allows you to execute privileged command-line utilities, such as apt-get, aptitude, dpkg, and so on. If you want to execute graphical commands with administrative privileges on a standard Ubuntu system, you should use the gsudo command instead.
- The problem with running graphical applications using sudo rather than gsudo is that they may change the ownership of the .authority file in your home directory, which many KDE, GNOME, and Standard X Window System applications use to track the applications that are authorized to access a specific X Window System display. If you accidentally use sudo to start a graphical application and cannot execute subsequent queries, you can remove the .authority file in your home directory by using the command rm .authority, and then use gsudo to start your graphical applications.
- Once you have executed the sudo or gsudo commands to run any privileged commands, your authorization is stored for 15 minutes so that you do not have to provide your password over and over for each privileged command that you want to execute. During this time, you must supply the sudo or gsudo commands, but you will not be prompted for a password. After 15 minutes, sudo or gsudo again will result in your being prompted for a password, and the cycle repeats. For the paranoid, the sudo command provides a -k option that prevents the temporary storage of authentication information, so that have to type your password every time.
