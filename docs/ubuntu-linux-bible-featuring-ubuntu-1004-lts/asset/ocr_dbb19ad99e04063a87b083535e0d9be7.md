You can also grant access to an NFS server from any host that can access it by using asterisk as the host specification.

The export-options identify specific characteristics of whether the exported directory is read-only or both readable and writable, how the UIDs and GIDs of incoming users should be mapped to users on the NFS server, how write and status requests should be processed, and so on. As you'd expect, many mount options are available. The pseudo-filesystem in which all the directories that you are exporting must be mounted using the fsid=0 export option, as shown in the previous example. The following are some of the more commonly used mount options:

+   - all_squash: Maps all NFS read or write requests to a specific user, usually "anonymous". This option is used for public resources such as directories of USENET news, public FTP and download areas, and so on. All files written to an NFS directory that is exported with the all_squash mount option will be assigned the UID and GID of the anonymous or other UID and GID specified by the anuid and anogid options. The default is no_all_squash, which preserves U IDs.
- async: Enables the NFS server to return control to the client before a write has completed, increasing performance. The default behavior when this option is not specified is synchronous writes, which are safer but block the client until the write completes.
- insecure: Enables access to NFS directories by NFS clients that are running on non-standard NFS network ports. By default, this option is off, and NFS requests must originate from ports where the port number is less than 1024. The insecure option may be necessary to enable access from random PC and Macintosh NFS clients. If you need to use this option, you should limit machines using the NFS option to a home network or secure intranet. You should not use this option on any machines that are accessible from the Internet because it introduces potential security problems.
- no_subtree_check: Prevents NFS from verifying that a file requested in the filesystem from which the directory was exported on the NFS server is hierarchically over the directory that is being exported by NFS, known as a subtree check. Performing this check can cause problems when files in the NFS are renamed. This check is usually disabled in filesystems with significant read/write activity by specifying the no_subtree_check mount option.
- no_root_squash: Lets root users on client workstations have the same privileges as the root user on the NFS file server. This option is off by default.
- ro: Exports directories that you don't want users to be able to write to because it is read-only. The default is rw, which enables read/write access.
