# # Overview of DHCP

DHCP stands for "Dynamic Host Configuration Protocol." But what does that mean for the users of a network? It means that when everything is working correctly, you should be able to connect your computer to the data jack on the wall with an Ethernet cable, and the University's computer will recognize your computer and allow it to join the network.

DHCP is used to provide network configuration information to the computer systems on a network that are configured to retrieve information dynamically. These systems, known as DHCP clients, locate a system running a software service known as DHCP configuration information from that system.

DHCP was created by the Dynamic Host Configuration Working Group of the Internet Engineering Task Force (IETF). It was originally created to satisfy the requirements of Internet Request for Comments (RFC) 1531, which begat RFC 1533 (which begat RFC 2132), which begat RFC 1541, and so. With all Internet RFCs, reading these documents can provide some fascinating insights into the thought processes that led to the development of many of the concepts and services that we take for granted on today's networks and the Internet. You can access the IETF's RFC archive through the URL www.ietf.org/rfc.html, or find some RFCs at a somewhat easier-to-browse site at www.faqs.org/rfc. Some of these are true classics, such as RFCs 1149, 2549, and so on.

DHCP is based on an earlier protocol for retrieving information required to boot system hosts known as BOOT, and maintains some backward compatibility with BOOT—hosts that require BOOT (such as embedded systems) can retrieve the required information from a correctly configured DHCP server. The key difference between the two is that BOOT is designed to provide specific responses to requests whereas DHCP is a much flexible system that responds to requests from random clients. DHCP also provides a configurable mechanism for reallocating IP addresses to hosts that already have and recovering network addresses that are no longer in use through their concept of limited-duration leases.

A client locates and retrieves configuration information from a DHCP server through the following series of events. (For simplicity's sake, this example ignores routing DHCP requests relay agents.)

+   1. A client broadcasts a DHCP discover message to the address 255.255.255.255. This broadcast includes information that uniquely identifies the client, such as its Media Access Control (MAC) address.
