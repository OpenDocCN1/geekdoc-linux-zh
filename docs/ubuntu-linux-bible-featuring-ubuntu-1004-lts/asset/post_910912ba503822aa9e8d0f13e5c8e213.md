## Exploring the Bash Configuration File

When you start a bash shell on your Ubuntu system, it reads a certain amount of configuration information from various text files on your system. In the order they are read, these configuration files are the following:

- /etc/profile (login shells only)
- /etc/bash.bashrc (all bash shells)
- ~/.bash_profile (login shells only)
- ~/.bashrc (all bash shells)

### Note

The symbol ~ is a bash shortcut for referring to any user's home directory. ~/.bashrc is the file .bashrc in my home directory; ~/.bashrc is a reference to the user called *user*'s home directory.

The first two of these are initialization files that are read and incorporated when users log in on the system (/etc/profile) or starts a bash shell (/etc/bash.bashrc). The second two are personal configuration files that are stored in each user's home directory. As with the system-wide configuration files, the ~/.bash_profile is read by the user's login shell, while the ~/.bashrc is read by any user the creates, such as in an xterm or GNOME Terminal. Of these, the .bashrc file is most important for two reasons:

- The default- ~/.bash_profile on Ubuntu systems reads it
- Starting a bash shell is a much more common operation than logging in. A user only logs in once, although he or she may subsequently create different xterm or GNOME Terminal windows.

The .bashrc file enables each user to customize various aspects of the bash shell, such as it looks for commands, the prompt that it displays, the number of commands that it remembers in your command-line history, and many more things. The .bashrc file enables you to create your own shortcuts for Linux commands if you still feel that you are having to type too many characters and enables you to create your custom shell commands. Lines in any bash configuration file (or shell script, for that matter) that begin with the hash mark (#) are considered to be commented and not interpreted.

### Tip

All Linux shells provide a command language and constructs for supporting conditional expressions to make it easy to write shell scripts. Explaining shell programming is outside the scope of this book, but there are many excellent books and web sites to visit. Two of my favorite web sites for this sort of information are the Linux Scripting Tutorial at www.frees.com/guides/lst/ and the Linux Documentation project's *Advanced Shell Scripting Guide* at www.tld.org/LDP/abs/html.

## Part II: Ubuntu for Desktop Users

When a user account is created on your Ubuntu system, the default .bashrc and .bash_profile files are created by copying them from the templates with the same names that are stored in the /etc/skel. The following is the beginning of the default .bashrc file for all Ubuntu accounts:

```
# .bashrc: executed by bash(1) for non-login shells
#
# If not running interactively, don't do anything
[ -z "$PS1" ] && return
[much more text deleted]
```

The last statement in this example stops shells from reading the default .bashrc file if they are not running in interactive mode. It does this by using the if command to test the value of the PS1 environment variable, which defines the user's prompt, and returning to the parent shell if this variable is not set (which would not be in the context of a shell used to run a shell script).

## Using Environment Variables

Environment variables are variables that are defined in the context of a shell and are read and used by applications on your system, including the shell itself. One of the most commonly used environment variables is the PATH environment variable, which contains a colon-separated list of directories that the shell searches (in order) try to find commands. You can examine the environment variables that are defined in a shell using any of three mechanisms:

- Use the shell's built-in set command to display all shell variables that are currently defined.
- Use the printf command to display a list of selected (or all) environment variables that are currently defined.
- Use the shell's built-in echo command to display the value of a specific environment variable.

The set and printf commands produce large amounts of output, so the echo command is most commonly used to display the value of a single environment variable, as in the following example:

```
$ echo $PATH
/home/wh:/bin:/usr/local/Adobe/Acrobat_7/bin:
/usr/local/gcc_svn/home/wh/BitTorrent/src/BitTorrent:
/home/wh/cxoffice/bin:/usr/lib/mit/bin:/usr/lib/mit/sbin:
/usr/NX/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:
/sbin:bin:/usr/bin/X11/games:
```

### Note

The value of THE PATH environment variable is a single string colon-separated directories. This example has been split across multiple lines for formatting purposes.

When using the echo command to display the value of an environment variable, you must refer to the environment variable by preceding its name with a dollar sign ($). This tells the shell to echo the value of a variable rather than simply echoing a string, which is what would happen if you simply typed the following:

```
$ echo PATH
PATH
```

This example of the PATH environment variable has been heavily customized. The default setting for the PATH environment on Ubuntu systems is actually the following:

```
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:\
/usr/bin/X11:/usr/games
```

To add a directory to the list of directories that are searched for commands, you can execute something like this from a shell prompt:

```
$ export PATH=$usr/vwh/bin:$PATH
```

This command sets the environment variable and exports it to the general shell environment. This example adds my personal binary directory as the first element of my PATH, so that the shell looks there first for any commands that I try to execute. To make this permanent, I would add this line to the end of my-.bashrc

The echo command is useful for displaying the value of a single environment variable. You can also use the printf command to do the same thing, as in the following example:

```
$ printf PATH
/home/vwh/vbin:/usr/local/Adobe/Acrobat7.0/bin:\n/usr/local/gcc_svn:/home/vwh/BitTorrent/src/BitTorrent:\n/home/vwh/cxoffice/bin:/usr/lib/mit/bin:/usr/lib/mit/sbin:\n/usr/NX/bin:/usr/local/bin:/usr/local/sbin:/usr/bin:/sbin:/bin:/usr/bin/X11:/usr/games:
```

The printf command is designed to display environment variables, you do not need to precede the name of the environment variable with a dollar sign.

The printf and set commands are more commonly used to display the values of all environment variables that are currently defined. You can search for a certain substring by piping their output to the grep command, in the following example:

```
$ printf grep HIST
HISTCONTROL=ignoreboth
HISTFILE=/home/vwh/.bash_history
HISTSIZE=1000
HISTSIZE=1000
```

This sample command shows me the name and value of all environment variables that the string HIST, which environment variables related to the shell's command-line history mechanism (discussed earlier in this chapter).

## Defining and Using Aliases

Another interesting feature of the bash shell is its ability to enable you to define aliases for various commands. An alias is a string that the shell recognizes and expands into some other command. Some of the most common aliases used on Linux systems are for the cp and rm commands that automatically execute those commands with their interactive option, which prevents you from accidentally overwriting or deleting files that you didn't want to overwrite or delete by prompting you to confirm each. These aliases are defined in the following way at the command line (or, permanently in ~/.bashrc file):

```
$ alias cp="cp -i"
$ alias rm="rm -i"
```

After defining these aliases, the shell automatically replaces either the cp or rm command with the command it has been aliased to.

To simplify defining aliases (and minimize the number of changes that you make) your ~/.bashrc file used on Ubuntu systems contains the following entries, which are initially commented out:

```
#if [ -f ~/.bash_aliases ]; then
# ~/.bash_aliases
```

If uncommented by removing the leading hash marks, this clause enables you to define all of your aliases in a file called ~/.bash_aliases, which would be located in your home directory.
