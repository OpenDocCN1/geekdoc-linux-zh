If you're a fan of graphical customization and are interested in being able to use a variety of fonts in your Emacs session, try a version of Emacs known as XEmacs. XEmacs was originally the work of the folks at Lucid, but is now an open source project that is hosted at www.xacs.org. XEmacs was originally created to provide a more graphic—and mouse-aware—version of Emacs, primarily because the first release of GNU Emacs to intrinsically support the mouse in a meaningful way, Emacs 19, took forever to be released. Because of several legal issues that would numb your brain the XEmacs code has never merged back into the official GNU Emacs, and it exists as a separate entity today. Regardless, XEmacs is a fantastic version of Emacs that many people find much more attractive and usable than GNU Emacs and therefore well worth looking into. XEmacs is not officially supported by the Ubuntu folks but is provided in the Multiverse Repository. The primary XEmacs package at the time of writing is named emacs21. You can install Emacs using any of the mechanisms discussed in Chapter 19.

# A Few Words about Emacs Commands

Before I tell you how to do anything in Emacs, it's important to have a quick discussion of Emacs commands, how they work, and how they're represented in this book.

Because Emacs is a modelless editor, typing any standard keyboard character actually inserts character into the file you're working on. That makes perfect sense in a graphical environment where you can use menu commands to perform most Emacs commands (as long as they're listed on a menu). However, because Emacs predates the era of graphical environments, and therefore menus, there is another way to issue Emacs commands.

All Emacs commands are bound to a combination of keystrokes that you can modifier on your keyboard. These modifiers are keys such as Ctrl (known as Control), Esc (known as Escape), and the Alt and Shift keys. If you think about how a computer works, you'll realize that these keys, when combined with the standard alphanumeric and symbol keys, change the signal that is sent to your system when one of these standard keys is sent. Using the Ctrl, Esc, and Alt keys exactly the same sort of thing as what happens when you press the Shift key when typing a letter or number key on your keyboard—it sends a different signal from what that key normally sends.

Emacs commands are therefore bound to key combinations that are represented as things like Ctrl+, Esc, Alt+, Ctrl+Shift+, and so on. This is one of the ways editors like to make fun of. Watching someone type in Emacs can be quite amusing if they are executing a continuous mixture of text insertion keystrokes and Emacs commands. As an example of this, one of my old colleagues described my typing as looking like an "epileptic spider." Of course, the fact that I don't touch-type didn't help me, but his point was still amusing and well taken, and I am clearly still amused (but have not changed). This has something to do with different keyboard modifier keys.

The Ctrl key is a direct modifier by holding it down while another key is pressed. This is usually represented as Ctrl+, which means hold down the Ctrl key, press the letter s, and then release the Ctrl key. The Ctrl key is much like the Shift key in this respect, except that there is no equivalent "Ctrl Lock" to confuse and irritate people.

# Tip

A printed sequence beginning with the caret symbol (^) is often used as a shortcut when referring to the Ctrl key. For example, ^s and Ctrl+s are two ways of representing the same thing. Having to canonically type Ctrl+s also prevents anyone from being confused about whether to type the + (you don't). Some books also use Ctrl+, Ctrl-s, or simply C-s as other shortcuts for Ctrl+. In this book I'll stick with Ctrl+s. Emacs can be confusing without drowning in a sea of duplicate representations.

On the other hand, the Esc and Alt keys work as prefix keys. To use these keys, you press and release them once, and then press another letter. These are generally represented as Esc+s and Alt+s, and the keyboard interaction is very different. Commands with the Escape key are often referred to as an Escape sequence to reinforce the notion that these are a sequence of key presses, not a simultaneous command of multiple keys.

This would be simple if Emacs commands were limited to a Ctrl command, Escape sequence, and so on. However, this would limit Emacs to having a hundred or so possible commands, which is hard sufficient. Therefore, most Emacs commands are combinations of Ctrl keys, Escape sequences, Alt sequences, and the Shift key. This gives you an infinite number of available commands, which can be hard to remember, leads to derogatory comments like those of my old colleague, and amuses everyone with potential key descriptions like Emacs=Ctrl+Shift+S.

# Tip

One thing that confuses us who are familiar with text editors or word processors is that Emacs does not follow the traditional conventions for things as cutting, copying, and pasting text. This is unfortunate, but the reason for this is that Emacs predates these conventions, and those key sequences are already used for other things in Emacs.

# Emacs Terminology

Because GNU Emacs is designed to interact with a graphical window manager, I have to use slightly different terminology to describe what you see on the screen. This section explains that terminology so that I can use it without guilt throughout the rest of this chapter.

Figure 12-11 shows two windows on an Ubuntu system, each running Emacs but displaying different files. Each Emacs has its own menu bar and toolbar. The window in the foreground displays two different files, each in its buffer. Each Emacs buffer has a mode line at the bottom, which provides information about the file being viewed in that buffer and its state. The bottom of each Emacs is a status line which you interact with Emacs, or in which Emacs displays messages displayed by a particular Emacs function.

# Note

The term window has a different meaning in this section than what I used in the portions of this chapter that discussed vi and vim. This is because Emacs is natively aware of the X Window System and therefore can only display multiple windows on the screen, whereas vi can divide a terminal application screen into multiple sections. In the context of Emacs, a window is equivalent to an Emacs buffer.
