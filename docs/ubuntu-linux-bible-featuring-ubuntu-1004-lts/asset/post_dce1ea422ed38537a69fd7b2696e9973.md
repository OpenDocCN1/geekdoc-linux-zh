An interesting capability that virtual machines introduce is the ability to take a snapshot of the state of a virtual machine and then undo changes to your system by falling back to the previous state of the virtual machine. VirtualBox snapshots work slightly differently than you might think. When you create a snapshot using the Machine -> Take Snapshot command from a virtual machine window, you actually continue to run in the snapshot. Once you've taken a snapshot, you can fall back to any previous snapshot by selecting the Snapshots tab for that virtual machine in the main VirtualBox window, right-clicking on the snapshot that contains the changes from the context-sensitive menu that you want to undo, and selecting the "Discard Snapshot" command that displays, as shown in Figure 24-18.

Selecting this command deletes the current snapshot. The next time you start your virtual machine, it will start with the previous snapshot or, if no snapshot is available, with the default state of your virtual machine.

# Networking and VirtualBox

VirtualBox includes an internal DHCP server and built-in support for NAT (Network Address Translation) that enables your virtual machines to automatically obtain IP addresses on a private Internet subnet. Virtual machines that you create in VirtualBox automatically use NAT networking to reach external networks as the Internet. Unfortunately, such communications are handled by VirtualBox rather than standard networking infrastructure. This means that, by default, you cannot use standard network commands to reach your host from your virtual machines, and you also cannot reach the host machine from your virtual machines. Bogus! Luckily, VirtualBox supports other networking mechanisms, specifically Bridged networking, eliminating these hassles by enabling your virtual machines to communicate with other hosts and networks by using a virtual interface on the host system, rather than through VirtualBox itself. This enables communication between your virtual machines and any other system, including your host system, which also enables any other system that can reach your host system to reach your virtual machines. As a plus, it's not hard at all to set this up.

# Tip

You can use port mapping to map ports on your host system to the ports associated with various services on your virtual machine, which will enable other systems to connect to your virtual machine, but this doesn't help with access from the virtual machine to your host system. But, it's better than nothing. For more information about port mapping in VirtualBox, see the sidebar, "Remapping Ports for VirtualBox VM," at the end of this section. ■

VirtualBox's Bridging support is implemented in software on your Linux host. Bridging is a networking technique used to connect multiple networks by forwarding packets from one to the other. In this context, bridging enables communication between physical and virtual network interfaces by connecting them to a software bridge that you set up on your Ubuntu. The network devices attached to this bridge consist of your system's primary network interface and one virtual network interface for each of your virtual machines. The bridge therefore sees any traffic that the physical interface that is attached to it would have originally seen, and can route traffic to any other device on the bridge. This includes both connection and infrastructure-related traffic such as DHCP requests, which enables your virtual machines to get IP configuration information from a DHCP server on your local network, giving them standard addresses, standard DNS configurations, and any other bells that you've set up in your network's DHCP server. Of course, you can give your virtual machines static addresses on your local network and supply other network configuration information as you would any other host with a static IP address. It's all up to you!

# Note

Bridging is not supported by many of the drivers for wireless network interfaces. If you want to use virtual machines on a laptop that has (or only has) a wireless interface and be able to communicate between your laptop and your virtual machine(s), it's easier to install and use the VMware Server than VirtualBox. You can selectively remap selected ports to enable interaction between a VirtualBox virtual machine that uses NAT and its host machine, but this is a pain. (See the sidebar at the end of this section for specific information about how to do that.) ■

Thanks to the cleverness of Linux, Ubuntu, and VirtualBox setting up a bridge and virtual network interfaces on your host system does not require a certificate from Cisco, the ability to receive the seven layers of the OSI networking model, or the sacrifice of any form of poultry. Let's just do it! I will present these instructions as a series of steps to make it easier to follow:

1. Use your favorite Package Management application to install the bridge-utils and uml-utilities packages on your system. The bridge-utils package contains the commands that are used to create bridges, attach devices to bridges, show status, and so on. The uml-utils package contains the utilities that are used to create and manage Linux Point-to-Point (TUN) and Ethernet (TAP) network devices. For example, you could install these packages with aptitude from a terminal using the following command:

```
sudo aptitude -y install bridge-utils uml-utilities
```

2. Modify your /etc/network/interfaces file to add an entry for a bridge, and connect the network device that is associated with your system's physical interface to. You should also comment out any entries for that network device. The following is a sample entry for a bridge named br0 to which the network device eth0 is attached:

```
auto eth0
iface eth0 manual
up ifconfig $IFACE 0.0.0.0
up link set $IFACE promisc on
down link set $IFACE promisc off

auto br0
iface br0 dhcp
bridge_ports eth0
bridge_fd 0
bridge_maxwait 0
metric 0
```

The first section defines eth0 as a TCP/IP network device that is automatically started when the network is brought up, but which is manually configured to have a static IP address of 0.0.0.0, and which is also put into promiscuous mode. Promiscuous mode is a special mode in which a network interface can receive all traffic on the network, if it is not addressed to that specific device or interface. The second entry says that br0 is automatically started when the network is brought up, is (because of the bridge_ports entry) that should get its configuration via DHCP, that no delay should be imposed when forwarding packets across the bridge (the bridge_fd entry), that the bridge should immediately enter forwarding mode as soon as it (the bridge_maxwait entry), and this interface should be considered a high-priority interface that can immediately reach a default gateway (the metric entry).

# Tip

Unfortunately, Ubuntu systems doesn't provide a page that describes the settings that you can use to define bridge settings in an /etc/network/interfaces file. For more information about the settings I've used (and the others that I did not), see the page for the bridge-utils-interface additions, which you can find on the NET at locations such as http://web.isodeira.com/cgi-bin/man/man2html?bridge-utils-interfaces-5.
