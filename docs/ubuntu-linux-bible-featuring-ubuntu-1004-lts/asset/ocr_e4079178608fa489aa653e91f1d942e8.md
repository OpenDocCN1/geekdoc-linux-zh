# Part III: Ubuntu System Administrators

# Note

If you want your Samba server to function as a domain controller (PDC) for a Windows domain, you must also change the value of the domain master setting in the [Domains] section of the Samba configuration file to yes and make sure the entry is not commented out. In this case, the entry would look something like the:

```
domain master = auto
```

This means that the Samba server will serve as a primary domain controller for your domain if no other domain controller can be located, which will be the case if your Samba server is hosting the domain.

This chapter explains how to use Samba as part of a workgroup, which is the typical way that Samba is used on a home or SOHO network. For information about setting up the samba-doc as suggested in the section of this chapter, "Installing the Samba Server and Friends," and consult the online copy of Samba-3 by Example that is provided in the directory /usr/share/samba-doc/html/Samba-3-ByExample.

# Note

Windows 7 systems does a better job of enforcing security than any earlier release of Microsoft Windows. If you want Windows 7 to join a Samba domain controller, you'll have to running Samba 3.3.4 or later (Windows 10.0 provides Samba 3.4.6) or do a few registry keys on Windows 7 system. See the excellent tutorial at www.linuxplanet.com/linuxplanet/tutorials/6911/2/ for detailed information.

Because this example shows a small workgroup, you will probably also want to activate the entries that tell Samba not to function as a WINS (the Windows NetBIOS name service, discussed earlier in this chapter), but instead use your system's Domain Name Server to look up Windows hostnames, which should look like the following:

```
wins support = no
dns proxy = yes
name resolve order = lmhosts host bcast
```

The last entry tells Samba that clients will first look in their local file for name information (on Windows systems), will then check information in the file /etc/hosts on the Samba server, will then check WINS (which, in this case, is proxied to the local DNS server), and will finally use a broadcast to search for the right host. This combination works for every Samba server configuration that I've ever set or used.

Finally, you must define the security model that will be used to identify authenticated users of the Samba server. To do this, uncomment the following entry in the Samba configuration file:

```
security = user
```

This completes the core modifications to the Samba configuration file that are necessary for Samba to be able to share files with the specified workgroup or domain. That wasn't so, was it?
