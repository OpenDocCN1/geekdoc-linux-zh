## Installing an Operating System in a Virtual Machine

VirtualBox provides a helpful First Run Wizard to walk you through the steps of installing an operating system in a new virtual machine. To install your operating system of choice into a new virtual machine, you simply start the virtual machine by making sure that its entry is selected in the left-hand VirtualBox pane and then clicking the Start button above that pane. This displays a VirtualBox window that is the console for your new virtual machine and displays the Welcome screen for the First Run Wizard, which isn't very interesting. To get to a useful screen, click Next. This displays the dialog shown in Figure 24-12.

This dialog enables you to boot from a CD/DVD-ROM drive or a floppy disk to start the installation process for the operating system for your virtual machine. After selecting either of these as the Media Type, you can identify the source of that media, either a physical device or an image file in the bottom of the dialog. If you are booting from an image file rather than a physical device, you can click the Browse button beside the Image File entry to browse for the location of your disk or floppy image. Once you've selected the Media Type and Media Source, click Next to proceed. The Summary dialog shown in Figure 24-13 displays.

The "Auto capture keyboard" option makes it easy to interact with a virtual machine rather than sending all mouse and keyboard events directly to the host system. ## Installing VirtualBox Guest Additions

The open source edition of VirtualBox provides enhanced drivers for better video resolution and better control of mouse interaction in Windows and Linux virtual machines once a virtual machine of either of those types has been installed. These drivers are known as the VirtualBox Guest Additions—you're familiar with VMware, these are equivalent to VMware's Guest Tools.

## Note

The Windows drivers in the Guest Additions are precompiled. Installing the Linux drivers from this package requires the GNU C Compiler (gcc) and the header files for the Linux kernel installed in your virtual machine. See Chapter 23, "Software Development on Ubuntu," for information about installing these in an Ubuntu virtual machine (if you're running some other Linux distribution in your virtual machine, that system's Package Management tools to install the gcc and kernel headers packages for that.).

- To install the Guest Additions into a virtual machine, select the Devices Guest Additions menu in a virtual machine. You will see a dialog to effect that the Guest Additions CD image cannot be found on your machine, and you would like to download it over the Internet? Click Yes. If you see a confirmation dialog for the download ("are you sure?"), you should also click Yes, and you will see a download progress bar appear in the bottom-left corner of the virtual machine window as the image is downloaded.

Once the ISO image for the Guest Additions is downloaded, VirtualBox displays a dialog if you want to mount the ISO as a CD drive. If your virtual machine is running some version of Windows, the Autorun.inf on the CD will automatically install the drivers. Running Linux, you will have to start a Terminal (xterm, GNOME Terminal, Konsole), mount the image, and run VBoxLinuxAdditions.script via sudo.

Once the ISO image for the Guest Additions is downloaded, VirtualBox displays a dialog if you want to mount the ISO as a CD drive. Click Yes.

## Starting and Stopping Virtual Machines

Once you've created one or more virtual machines and installed an operating system, you can start any virtual machine by selecting its entry in the left pane of the VirtualBox window.

After you're finished using a virtual machine, you can shut it down in two ways:

- By invoking the standard shutdown in the virtual machine's operating system. When the shutdown process completes, the virtual machine window closes, and only the standard VirtualBox dialog will be displayed (unless you are running other virtual machines).
- By clicking the Close box in the upper-right corner of the virtual machine window or selecting the Machine Close command from the virtual machine. Both of these display the dialog shown in 24-16.

## FIGURE 24-16
Different ways of closing a virtual machine

![](img/1a233c34336fbf5a85d6eb785e401709_921_0.png)

The three options in this dialog do the following:

- **Save the machine state**: Saves the memory and disk state of the virtual machine to a file that will be used the next time you start the virtual machine. Starting from a saved state is much faster than booting a virtual machine. You cannot edit the settings for a virtual machine if you have a saved state file because the state information depends on the settings that were active when the machine's state was saved. In order to modify any settings for a virtual machine that has a saved state file, you must either start the virtual machine from the saved state and then shut it down normally, or you discard the saved state information by right-clicking on the virtual machine in the left pane of the main VirtualBox window and selecting the Discard command from the context-sensitive menu. If you discard saved state information, you will lose any changes that were not written to your virtual machine. If you have the time, it's definitely a better idea to start the virtual machine and shut it down normally than simply saving the virtual machine's state.
- **Send the shutdown signal**: Begins a standard shutdown in the virtual machine's operating system. This option is provided if you accidentally clicked Close but have the time to do an orderly shutdown.
- **Power off the machine**: Immediately turns off the virtual machine without doing a clean shutdown. This is usually a bad idea because all operating systems need to ensure all is written to disk.
