
## Determining What Package Provides a Missing File

Identifying the package that provides a file that is not installed on your system is somewhat tricky, it is a common question when you are trying to build software whose source code requires a file that is not present on your system, or you are trying to link software that requires a missing library. Unfortunately, the utility that performs this type of search, the apt-file utility, is not installed on Ubuntu systems by default, but it can easily be installed using apt-file, aptitude, or the Synaptic Package Manager. After installing it, you must first update the available user-level packages in the repositories that you are using by running the command `sudo apt-file update`.

Once this command completes, you can search for the package that provides a file, even if that is not installed on your system, using the apt-file search command, as in the following example, which looks for the package associated with the libpowersave library:

```
$ ls -l /usr/lib/power*
ls: /usr/lib/power*: No file or directory
$ apt-file search libpowersave.so
libpowersave-dev: /usr/lib/libpowersave.so
libpowersave-10: /usr/lib/libpowersave.so.10
libpowersave-10: /usr/lib/libpowersave.so.10.3
```

Installing the apt-file utility can save you a tremendous amount of hair-pulling and general frustration when you are trying to build software and have no idea what package provides the missing include file or "the missing link." (Sorry, I couldn't resist.)

## Tip

You can also use the apt-file utility to list the contents of packages that are not installed by using the apt-file list package command, where the package is the name of the package that you are interested in.

## Using apt-get to Add and Remove Software

The apt-get command is the fundamental user-level command provided as part of the Ubuntu Package Management suite. The apt-get command is a command-line tool that is fast and easy to use.

## Note

With any system administrative utility on your Ubuntu system, running the apt-get command requires the use of the sudo command or an equivalent, such as running apt-get under a shell that it has been executed using the sudo command. To simplify examples and the readability of the text, the examples and discussion of using the apt-get command throughout this section do not include the sudo command.

Much of the basic functionality provided by the apt-get command is quite straightforward. For example, you can install a package and any other packages that it requires using the apt-get install command. Similarly, you can remove a package by using the apt-get remove package command, specifying the --purge option if you also want to remove any configuration files or other data associated with the package you're removing. Before using apt-get to install new software or new versions of existing software, you first execute the apt-get update command to ensure that apt-get is aware of the latest software packages and versions of that software from all of the repositories listed in /etc/apt/sources.list file.

When using the apt-get utility to install software, you may occasionally have to provide additional information during the installation process. In these cases, the apt-get utility displays a quasi-graphical screen in the terminal application from which you were running the apt-get utility, example of which is shown in Figure 19-8.

## Upgrading Your System Using apt-get

The apt-get upgrade command searches all of the repositories in your /etc/apt/sources.list for new versions of packages that are currently installed on your system, and downloads and installs those new packages. Before using this command, you should first execute the apt-get update command to ensure that apt-get is aware of the latest software packages and versions of that software from all of repositories in your /etc/apt/sources.list file.

During the upgrade process, the apt-get upgrade command will not change the installation of any other packages on your system. This is the installation status of a package, not the version of a package. If a new version of a package requires a newer version of another package that is already installed on your system, the apt-get upgrade command will also install the newer version of that other package; however, if a newer of an existing package requires that new packages be installed or if existing packages are removed, the apt-get upgrade command will not install the newer version of the existing package. To do this, you will need to use the apt-get dist-upgrade command, as described in the next section.

## Smart System Upgrades Using apt-get

The apt-get dist-upgrade command searches all of the repositories in your /etc/apt/sources.list for new versions of packages that are currently installed on and downloads and installs those new versions. Before running this command, you should always first execute the apt-get update command to ensure that apt-get is aware of the latest software packages and versions of that software from all of repositories in your /etc/apt/sources.list file.

The difference between the apt-get upgrade and apt-get dist-upgrade commands is what will be known as a smart upgrade. This means that the apt-get dist-upgrade command will do its best to handle any new package requirements or the removal of existing packages that were mandated in order to install the latest versions of all the software on your system. For example, if a new version of a package requires that new package be installed or if existing packages are removed, the apt-get upgrade command will not install the newer version of the existing package. To do this, you will need to use the apt-get dist-upgrade command, as described in the next section.

## Retrieving Package Source Using apt-get

Even in the wonderful world of constantly updated repositories, you may occasionally want to build your own versions of software. The most common situation in which you'll want to do this is when you find patches to an existing package and just can't wait for them to appear in the official or backports repositories. The apt-get command makes it remarkably easy to retrieve the source code for an installed package. The only requirement for this capability is that your /etc/apt/sources.list includes a deb-src entry for the repository from which you retrieved the binary version of that software. For example, if you want to retrieve the source for a package in which the binary version is located in the multiverse component, you must have entries like the following (or equivalent entries) in /etc/apt/sources.list:

```
deb http://archive.ubuntu.com/ubuntu/ intrepid multiverse
d-src http://archive.ubuntu.com/ubuntu/ intrepid multiverse
```

Assuming that the right entries are present in /etc/apt/sources.list, retrieving the source code for a specified package is easy using the apt-get source command. The following example shows the retrieval of the source code for one of my favorite packages, the MyThVR video recorder:

```
$ apt-get source mythv
Reading package lists... Done
Building dependency tree... Done
Need to get 9836KB from /multiverse mythv 0.21.0+fixes18722-Ubuntu1...
Get: 1 http://.../intrepid/multiverse mythv 0.21.0. . .
Get: 2 http://.../intrepid/multiverse mythv 0.21.0. . .
Get: 3 http://.../intrepid/multiverse mythv 0.21.0. . .
Fetched 9836KB in 1s (107KB/s)
dpkg-source: extracting mythv-0.21.0
dpkg-source: unpacking mythv-0.21.0.orig.tar.gz
dpkg-source: applying ./mythv-0.21.0+fixes18722-Ubuntu1.diff.gz
```

When retrieving the source code for a package, the apt-get source utility actually retrieves multiple files. The extensions of these files are follows:

- diff.gz: A compressed file containing any patches to the standard source archive for the package
