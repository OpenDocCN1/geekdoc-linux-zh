# Using Command History

All Linux shells provide a history mechanism, which is a way of recalling and re-executing commands that you have previously executed. To see the list of recently executed commands, you can simply type history at any shell prompt, which displays something like the following:

```
$ history
231 make distclean
232 ~/gcc/configure --enable-threads
233 make bootstrap
234 info -f gcc.info
235 export INFOPATH='$INFOPATH:$INFOPATH'
236 vi ~/.bashrc
237 pushd ~/new
238 ls /mnt/terastation/CDs
239 pushd /mnt/terastation/CDs
240 find -name "*.txt" -exec rm {} \;
241 find -name "*.txt"-Ctrl+P; \;
242 rar x ../_Unique_Loyalists.rar
[much more output deleted]
```

You'll have to trust me that this list contains a recording of a certain number of the commands that I have executed on your system. The number of commands that the history records is identified by the HISTSIZE environment variable. (The section, "Using Environment Variables" later in this chapter provides information about setting and displaying the values of environment variables.)

You can recall or re-execute commands in several ways:

- Use the shell's built-in fc command.
- Use the shell's mechanism for interacting with the commands that you have typed (known as the readline library) to scroll backward through the history list from the command line.
- Use the exclamation point to identify the command that you want to display and re-execute.

I generally use one of the last two mechanisms, so I'll focus on those.

You can re-display any recently executed command by typing the Ctrl+P command at any command prompt. Each time you type Ctrl+P, the shell displays the previous command in its history list.

When you find the command that you want to re-execute, you can simply press Return to re-execute it or edit that command using Emacs commands (by default) such as Ctrl-B to move backward one character in that command, Ctrl+F to move forward in that one character, the Backspace and Delete keys to delete the previous and current characters, and so on.

Obviously, if the command you want to re-execute is far back in your command history list, scrolling back through a few hundred commands can be a bit tedious. In this case, you can use the exclamation point to identify a particular command from the history list in either of the following ways:

- Identifying a command by its sequence number: Each command in the history list is preceded by its sequence number in your command history. If you've displayed the history list and can see the command that you want to execute, you can re-execute a specific command by typing an exclamation mark followed by its sequence number. for example, using the history output displayed earlier in this section, the command !236 would re-execute the vi ~/.bashrc.
- Identifying a command by name: You can re-execute the most recently executed command that begins with a certain command name by typing an exclamation mark followed by the command that you want to re-execute. For example, using the history output displayed earlier in this section, the command !vi would re-execute the vi ~/.bashrc command.

# Tip

If you want to re-display a previous command and edit it before re-executing it, you can use the history mechanism's : modifier to simply print the command without executing it. You can then type Ctrl+P to display that command, edit it however you wish, and then press Return to execute the modified command. ■

If you've already executed several similar commands, you can narrow down the list of those shown by the command history | grep vi uses displaying commands that contain a substring. For example, the command history | grep vi uses a pipe and the grep command to display only lines of output from the history order that contain the string vi. (see the section, "Pipes and Input Output-Direction" for more information about connecting different commands in this way.)

The shell's command-line history mechanism is extremely powerful, and this discussion only scratches the surface of the myriad ways that you can save yourself by recalling and updating previously executed commands. For all the gory details on the shell's command-line history mechanism, use the info bash command to display the current online help for the bash command.

# Using Command and Filename Completion

As you've seen throughout this chapter, the command line provides a very powerful, flexible mechanism for executing commands, but one of the goals of all UNIX and Linux developers seems to have to allowed all users to type as few characters as possible to execute commands.

This has given us cryptic commands like ls and pwd, which has saved us wear and tear on thousands of keyboards over the years.

This same type as little as possible philosophy extends to the shell in a variety of ways. One of the most useful is the use of the Tab key to help the shell match and display commands and filenames. Pressing the Tab key while typing the name of a command will cause the shell to expand the name of that command as uniquely as possible. For example, because I use the Emacs editor for all activities related to text files (see Chapter 12, "Working with Text Files," for a discussion of my love affair with Emacs) it types commands like this is_name_of_a_file.txt a few hundred times a day. In Linux fashion, I can save myself a few characters of typing by tab on command line and pressing the Tab key. This displays the first matching command, which happens to be emacs, and I can then press space and enter the name of the file that I want to edit.

But wait, there's more! The Tab key will also match and insert the names of filenames. For example, if I were indeed trying to edit a file called is_the_name_of_a_file.txt, I could type the first few characters of it and press the Tab key to (hopefully) match and insert the complete filename so that I all have to press Return to begin editing the file. This is a common reason why we've seen through this chapter, names of Linux commands tend to be short. On the other hand, they are cryptic, if you do not remember the spelling of the command that you want to execute, the Tab key can help you figure it out.

Pressing the Tab key matches name of a command or file as it can. If multiple commands or filenames match what you've typed before pressing the Tab key, pressing Tab will have no effect because the shell can't tell which of the possible commands or filenames you mean. In this case, you can press the Tab key twice (quickly) to cause the shell to list all of the available matches. You can then type the additional few characters that are required to uniquely identify the command or filename that you're actually interested in.

# Using Wildcards

Another example of the "type as little as possible" philosophy is the ability of the shell to identify groups of files whose names match patterns. The characters used to define these patterns are wildcards because they can match any single or group of characters. The shell supports four primary types of wildcards:

- ? (question mark): Matches any single character
- * (asterisk): Matches any group of zero or more characters
- [string1, string2] (curly braces): Matches either string1 or string2
- [char1,char2,...] (square brackets): Matches any character or range of characters inside the square brackets
