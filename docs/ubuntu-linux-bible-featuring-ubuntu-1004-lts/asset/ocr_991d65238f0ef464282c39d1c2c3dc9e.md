# Starting a KVM Virtual Machine

Once you've installed an operating system in your virtual machine, you can start virtual machine at any time using a somewhat simpler version of commands like the one shown in the previous section. The primary difference between booting a virtual machine in order to install an operating system and booting a virtual machine in order on which an operating system has already been installed is the boot device. If you do not specify the -boot option, the virtual machine will boot from its root filesystems, as in the following commands:

```
sudo kvm -hda winxp.img -cdrom /dev/cdrom -m 512 & 2
sudo kvm -hda winxp.img -cdrom /dev/cdrom -m 512 -vnc :1
```

Either of the commands will start a KVM process using an image file named winxp.img as the primary boot drive, allow access to /dev/cdrom as the CD-ROM drive for the virtual machine, and allocate 512 MB of memory to the virtual machine. The first of these commands starts KVM using a SDL window that you can access as HOSTNAME:1 or IP-ADDRESS:1 from the local system or any other system that can access the host system over the network.

# Networking for KVM

At this point, you probably won't be surprised to read that KVM's support for networking heavily leverages the support that is provided in QEMU. So, with another tip of the hat to Fabric Belle ("Mr. QEMU"), let's summarize the various networking approaches that are available in KVM:

+   * Virtual Networking: KVM provides a DHCP service for virtual machines and serves as a packet forwarder/receiver for packets sent from the Guest OS to an external network. This provides a fairly slow network connection but requires absolutely no configuration. By default, this networking mode does not support inbound network connections to the virtual machine, but you can use the -redir option when starting a virtual machine to map a port on the host system to a single port on the virtual machine
