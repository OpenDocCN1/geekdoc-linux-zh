Once you've identified the partitions on your new disk (presumably know which ones you want to use), mounting them using the mount command is easy. You will always need to explicitly filesystems that aren't in the file /etc/fstab (explained in more detail in the next section).

For example, the following command mounts partitions /dev/sda5 over the mountpoint
/mnt/tmp (which must already exist):

```
$ sudo mount /dev/sda5 /mnt/tmp
```

If you're mounting a partition that contains a type of filesystem that your system can autodetect, you don't need to specify the type of filesystem that the partition/device uses. If it is nonstandard, you will have to identify the type of filesystem using the mount command's -t option, followed by the name of type of filesystem, as in the following example, which mounts the XFS filesystem on /dev/sda6 over the mountpoint /mnt/xfs:

```
$ sudo mount -t xfs /dev/sda6 /mnt/xfs
```

The -t option causes the mount command to first look for a special, filesystem-specific mount command, /sbin/mount.type, where type is the name of type of filesystem. These filesystem-specific commands are usually installed along with the other administrative utilities for different types of filesystems using the Synaptic Package Manager, aptitude, or apt-get, as explained in Chapter 19, "Adding, Removing, and Updating Software."

Supported types of filesystems that you can specify using the -t option are adfs, aifs, autofs, cifs, coda, coherent, cramfs, debugfs, devpts, evfs, ext, ext2, ext3, hfs, hxfs, iso9960, jfs, minsys, middos, ncpfs, nfs, nfs4, ntr4, qf4, ramfs, reiserfs, romfs, smbfs, smys, umfs, ufs, ufsmidos, ubfs, vfat, xfs, and xufs.

Some filesystems require additional options, such as NTFS filesystems, SMB/CIFS filesystems, and on. These are highly filesystem-specific, so I won't bore you all of them here. Instead, I'll focus on the options for a SMB/CIFS filesystem because that is probably the most common networked filesystems you'll want to mount. Some other options that are commonly used in the filesystem/mount configuration file are discussed in the next section.

When mounting a networked SMB/CIFS filesystem, you will need to specify the name of the Windows user that you want to access the filesystem, as your Windows password, and also the identity of the Linux user who should appear to own the files in the filesystem, so that you write to the remote filesystem as needed. The following is an example of specifying this in a mount command:

```
//192.168.6.66/share/mnt/terastation
```
