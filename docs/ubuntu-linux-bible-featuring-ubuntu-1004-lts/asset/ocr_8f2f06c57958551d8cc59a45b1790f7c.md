If you have more than one machine on your home network, or if you're working in a multi-enterprise or academic environment, the BackupPC software is well worth a look. Its Web-based interface is easy to set up and use; various types of backups are easy to configure, initiate, and monitor; it can back up your Linux, UNIX, Windows, and Mac OS systems; and the fact that it doesn't require you to install any special software on the systems that you want to back makes BackupPC a great package.

BackupPC supports four different backup mechanisms (known in the BackupPC documentation as backup transports) to enable you to back up different types of systems. These are the:

+   - rsync: Backup and restore via rsync via r or ssh. This is a good choice for backing Linux, UNIX, or Mac OS systems, and you can use it to back up Windows systems that support rsync, such as the Cygwin Linux emulation environment.
- rsyncd: Backup and restore via the rsync daemon on the client side. This is the best choice for Linux, UNIX, and Mac OS systems that are running an rsync daemon. You can also use this mechanism to back up Microsoft Windows systems that support rsync, such as those running the Cygwin Linux emulation environment.
- smb: Backup and restore using the smclient and the SMB protocol to the backuppc server. This is the best (and easiest) choice to use when backing up Microsoft Windows systems using backuppc, and you can use it to back up Mac OS systems using Linux and UNIX systems that are running a Samba server.
- tar: Backup and restore via tar, over ssh, or nfs. This is an option for Linux, UNIX, and Mac OS systems. You can also use this mechanism to back up Windows systems that support tar, ssh, rsh, and/or nfs, such as those running the Cygwin Linux emulation environment.

A default backup transport value for all backups is set in the BackupPC configuration file, /etc/backuppc/config.pl. The specific mechanism used to back up any particular host is identified in that host's configuration file, as discussed in the sections entitled "Defining a Backup Using rsync" and "Defining a Backup Using SMB."



Although backuppc does a good job of backing up systems running Windows and Mac OS X, you should be aware of a few issues. First, backuppc is not suitable for backing up Windows systems so that you can do a bare-metal restore. backuppc uses the smclient application on your Ubuntu system to back up Windows disks, so it doesn't back up Windows ACLs and cannot open files that are locked by a Windows client that is currently running (such as, most commonly, things like Outlook mailboxes). Similarly, backuppc doesn't preserve Mac OS file attributes. See http://backuppc.sourceforge.net/faq/limitations.html for a list of current limitations in backuppc. It's a surprisingly short document!
