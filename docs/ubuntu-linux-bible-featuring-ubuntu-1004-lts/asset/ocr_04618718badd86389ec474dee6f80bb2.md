# Tip

If your Windows and Ubuntu users happen to have different logins, you can associate the two by creating appropriate entries in the file /etc/samba/smusers. Entries in this file have the form UnixLogin = WindowsLogin. For example, to map the Ubuntu user vwh.vonhagen, I would create the following entry in the /etc/samba/smusers file:

```
vwh = bill.vonhagen
```

If your Windows login names contains one or more spaces, you must enclose them within quotation marks in this file.

In practice, I suggest keeping the logins same across Ubuntu and Samba systems, but this file can be used if you have different naming conventions for the users of different types of systems.

# Verifying the Samba Configuration File

After making any changes to your Samba configuration file, you should verify that you haven't accidentally violated the syntax of the file. If Samba configuration file contains any invalid entries, Samba displays an error message and will not load. This could be extremely discouraging, were it not for the fact that the Samba server also provides a utility to test the validity of a Samba configuration file and identifies the exact location of any errors that it finds. This utility is testparm which you can run with no arguments to test the default Samba configuration file /etc/samba/sm.conf. The output from a run of the testparm utility looks like the:

```
testparm
Load smb config files from /etc/samba/sm.conf
Processing section "homes"
Processing section "printers"
Processing section "print$
Loaded services OK.
* WARNING: passdb add explicit = yes is deprecated
Server role: ROLE_STANDALONE
Press enter to see a dump of service definitions
```

As shown in the preceding example, after displaying some general information, the testparm utility prompts you to press Enter on your keyboard to see detailed information about the services your Samba server has been configured to provide. The following is an example of this detailed information:

```
[global]
workgroup = WVH
server string = %h server (Samba, Ubuntu)
obey pam restrictions = Yes
passdb backend = tdbsam, guest
syslog = 0
log file = /var/log/samba/log.%m
max log size = 1000
```
