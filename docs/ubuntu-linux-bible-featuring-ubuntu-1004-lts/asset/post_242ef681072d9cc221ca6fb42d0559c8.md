
- /proc/sys/sunrpc/nlm_debug: Controls tracing for the Network Lock Manager. The tracing output is generated in the system log on the host where the NFS Lock Manager is running—the host that is exporting the NFS directory. The debugging values that are available are listed in /usr/include/linux/lockd/debug.h.

You can use decimal numbers that represent a bitmask that enables different types of tracing to these files by using the sysctl command or simply writing to the appropriate file. For example, the following commands activate all possible debugging for the NFS client:

```bash
# echo 65535 > /proc/sys/sunrpc/nfs_debug
# sysctl -w /proc/sys/nfs_debug=65535
```

If you think in terms of bitmasks, you can consult the appropriate kernel header files for the previous list. Personally, I typically find the NFS client and NFS server output to be most useful, and therefore begin with a value of 1023 because this activates most of the useful debugging without being truly overwhelming. I often test the client and the NFS server on the system that is running the NFS server by first starting NFS server process, and then attempting to mount one of its exported directories somewhere else on the same host. Once things work locally, you can move on to try get them working from a remote client.

# Part III: Ubuntu System Administrators

MS-DOS and Microsoft networking have contributed their share, largely because of the ubiquity of these operating systems in modern computing environments. Because of the popularity of DOS systems (yesterday) and Windows systems (today), today's Windows systems provide support for almost everyone's networking protocols. Frankly, Windows does enable an admirable job of continuing to make progress while maintaining backward compatibility with almost every DOS application and networking protocol. Windows systems still support the Internet Packet Exchange (IPX) and Sequential Packet Exchange (SPX) networking protocols developed by Novel to provide the first PC file servers. However, more relevant for our discussion here are the networking protocols attendant acronyms that were developed by Microsoft and to provide file and resource sharing over PC networks without requiring the involvement of any third parties, thank you very much.

The Basic Input and Output System used by PCs to interact with local devices is best known by its as the PC's BIOS. As Windows began to appear, Microsoft extended the capabilities of the BIOS to support accessing and sharing information over a network, naming the protocols NetBIOS or as its more popularly known, NetBIOS. Just as the BIOS provides the basic functions that support all system input and output, the NetBIOS commands and functions let you use and administer network services. NetBIOS commands must be exchanged between networked systems and require a lower-level transport mechanism to move network packets from one to another. The lower-level transport protocols that are common in PC networking today are IPX, Network Basic Extended Interface, and TCP/IP (Transmission Control Protocol/Internet). Interestingly, the internet in the full names of both IPX and TCP/IP refers to "inter-network communications,"the Internet" as we know it.

Modern Windows send their NetBIOS requests using TCP/IP as a transport protocol. On top of NetBIOS level, Windows networking provides a higher-level interface for network services known as the Server Message Block (SMB) protocol, which is a networking protocol that can be easily used by applications. SMB is a connection-oriented protocol rather than a broadcast protocol, meaning that it depends on establishing connections to specific networked services provided by other networked hosts rather than simply broadcasting its availability. Once connection, SMB provides four types of functions:

- Session functions that negotiate and establish networked connections between machines (often referred to as virtual (circuits)), authenticate, and verify the access privileges that each has with the other
- File functions that enable applications to open, close, read, and write remote files, shared directories, and so on
- Printer functions that enable applications to spool output to remote output devices
- Message functions that enable applications to send and receive control, status, and informational messages between different systems on the network

SMB became an Open Group standard for networking interoperability in the early 1990s. Samba takes its name from SMB, the addition of two vowels making it easily pronounced and somewhat softer than simply YAA ("Yet Another Acronym").
