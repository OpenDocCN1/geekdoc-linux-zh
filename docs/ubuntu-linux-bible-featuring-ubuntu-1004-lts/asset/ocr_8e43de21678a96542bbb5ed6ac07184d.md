# Part III: Ubuntu for System Administrators

If your BIND server does not start correctly, the first place to look for information is the system log file on your Ubuntu system, /var/log/syslog. By default, BIND logs a variety of events to this file when you start or the named process, when events such as file reloads occur while the named process is running, and so on. A sample section of the /var/log/syslog showing BIND messages is as follows (I removed the timestamp and host information that would normally begin each line):

```
named[20897]: starting BIND 9.3.2 -u bind
named[20897]: found 1 CPU, using 1 worker thread
named[20897]: loading configuration from /etc/bind/named.conf
named[20897]: /etc/bind/named.conf:60: missing ';' before end of file
named[20897]: loading configuration: failure
named[20897]: exiting (due to fatal error)
```

In this case, you can see that there is a missing semicolon on line 60 of my named.conf file. After correcting one error in a configuration file, you usually want to check the configuration file again, to make sure you've eliminated all of the errors, not just one. The Ubuntu bind package includes a utility called named-checkconf that does just this. Running this utility provides an easy way of checking the syntax of a BIND configuration file without restarting the named process over and over, checking the log time, fixing one problem or the other, and so.

The following is another common message that you may see in /var/log/syslog:

```
named[20222]: zone vonhagen.org/IN: loading master file: not found
```

Oddly, the fact that the zone vonhagen.org could not be found is not a fatal error, so the BIND server is running—it just isn't providing any name information for the vonhagen domain. Aside from syntax errors in the filename, the most common cause of this error message is forgetting to provide the full pathname for an included file. As mentioned previously, BIND on Ubuntu systems is configured to use the directory /var/cache/bind as its working directory. It will look for files without full pathnames in that directory instead of looking in /etc/bind.

The named-checkconf file checks the syntax of your /etc/bind/named.conf file and other configuration files that it includes does not validate the contents or syntax of your zone files. Luckily, Ubuntu's bind package includes another utility, named-checkzone. Although it provides several options, the most common way of using the named-checkzone is to provide its two mandatory arguments: the name of the zone that a file describes, and the name of the file that describes that zone. This can be a standard zone file or a reverse lookup file because both of these are different types of zone files that have logical purposes and contexts. Sample error output from running this utility follows:

```
# named-checkzone vonhagen.org vonhagen.zone
dns_data_fromtext: vonhagen.zone:8 near '*': extra input text
vonhagen.org/IN: loading master file vonhagen.zone: extra input text

# named-checkzone 168.192.in-addr.addr 168.192.in-addr.addr
168.192.in-addr.addr/11: unknown RR 'ubuntu32.vonhagen.org.
168.192.in-addr.addr/IN: loading master file: unknown class/type
```
