## Installing and Configuring BackupPC

Special-purpose backup solutions as BackupPC aren't installed as part of a default Ubuntu installation because they're overkill for most people. However, the various package management tools provided on Ubuntu make it easy to install BackupPC (located in the backuppc package) and the other software packages that it requires.

Because BackupPC uses a Web-based interface, it requires that you have installed (configured) a Web server on your system, preferably Apache. Similarly, BackupPC can send e-mail notifications for backup-related events; it requires a Mail Transfer Agent (MTA). If one is not already installed on your system, installing the backuppc package will install exim, which isn't my personal choice for MTAs. If you're going to install BackupPC, I'd suggest installing (and configuring) Postfix first, as described in Chapter 30, Setting Up a Mail Server. After doing so, BackupPC will detect that an MTA is installed on your system and will no longer try to install exim to satisfy dependencies.

Once the backuppc has been installed on your system, your package management software will run its configuration script. During this phase, the various package managers will ask which Web server configuration you are using so that they can configure backuppc appropriately, and automatically run a script to set up the initial account that you will use to access backuppc via that Web server. This process appears as a dialog like the one shown in Figure 28-2, which tells you the initial password for the Web-based BackupPC interface.

This dialog is, of course, for each package management tool—Figure 28-2 shows the screen that you see if installing the backuppc package using the aptitude package management tool. See Chapter 19, "Adding, Removing, and Updating Software," for more information about the various package management utilities that are available for Ubuntu systems.

Once you see a dialog like the one shown in Figure 28-2, write down the password for the backuppc interface and press Return or Click to proceed. Unless you're not remembering passwords, I suggest immediately changing the default password to one of your standard administrative passwords, which you can do via a command like the following (which the dialog in Figure 28-2 also explains):

```bash
sudo passwd /etc/backuppc/passwd backuppc
```

Once the remainder of the installation and configuration process completes, you're already ready to back up the system you're using and the other systems on your network. While installing backuppc is supposed to integrate it with your Web server, that doesn't actually seem to be the case. To integrate backuppc with your Apache Web server, do the following:

1. Copy the file /etc/backuppc/backuppc.conf to the directory /etc/apache2/sites-available giving it the name backuppc.
2. Create a symbolic link from the file /etc/apache2/sites-available/backuppc.conf to the directory /etc/apache2/sites-enabled. I usually name this symbolic link backuppc so that it's clear exactly which site/application is enabled. You can do this by executing the following commands:
```bash
cd /etc/apache2/sites-enabled
ln -s ../sites-available/backuppc.conf backuppc
```
3. Restart Apache2 using a command like the following:
```bash
sudo /etc/init.d/apache2 reload
```

You should be able to connect to the BackupPC Web interface via the /backuppc URL relative to your Web server as the user backuppc with whatever your current BackupPC password is (in other words, something like www.vonhagen.org/backuppc). This will display a screen like the one shown in Figure 28-1.

On Ubuntu systems, BackupPC stores its configuration information in two locations: General backuppc configuration information and passwords are stored in the directory /etc/backuppc. Backup files themselves and host-specific backup information are stored in subdirectories of /var/lib/backuppc.

### Tip

Backups of a single system take a significant amount of space, which is only compounded when you begin to back up other hosts to a central backup server. If you didn't specify using local volumes when you installed your Ubuntu system, you might want to add a new disk to your system before starting to use BackupPC for that as a local volume. You can then copy the default contents of /var/lib/backuppc to the new disk (preserving file permissions and ownership) and... When you need more space to store backups in the future, this will enable you to add other hosts to your system and add their space to the local volume to store backups. BackupPC also provides an archive capacity that enables you to migrate old hosts to others for archival purposes, freeing up space on your primary backup.

### Identifying Hosts to Back Up

On Ubuntu systems, BackupPC stores its configuration information in two locations: General backuppc configuration information and passwords are stored in the directory /etc/backuppc. Backup files themselves and host-specific backup information are stored in subdirectories of /var/lib/backuppc.

Each host you want to back up must be identified in the /etc/backuppc/hosts file. Like all configuration files, this is easy to update. As an example, the hosts file looks like the following:

```
host                backuppc
```

The fields in each entry have the following meanings:

- The first field identifies the machine, hostname, or IP address.
- The second field should be set to 0 or 1, as described.
- The third field identifies the person who is responsible for backing up that.
- The fourth field (optional) consists of one or more users, each separated by a comma.

As an example, the hosts file looks like this:

| host | user | moreUsers |
|---|---|---|
| localhost | 0 | backuppc |
| 192.168.6.64 | 0 | backuppc |
| 64bit | 0 | backuppc |
| 64x2 | 0 | backuppc |
| w12k | 0 | backuppc |

The backuppc program checks the timestamp on the /etc/backuppc/hosts each time the backup process wakes up, and reloads it automatically if the file has been updated. For this reason, you should not save changes to the hosts file until you have created the host-specific configuration.

## Defining a Backup Using rsync

The section earlier in this chapter titled “Making an Up-To-Date Copy of a Remote Directory Using rsync” explained how to set up rsync in daemon mode on an Ubuntu system and to define synchronization entries that can be remotely accessed via rsync. The sample rsync configuration file created in that section defined a synchronization entry called homes that would enable an authorized user to synchronize the contents of all directories under /home on an Ubuntu system. We'll use that configuration file for the example in this section.

The previous section showed how to define entries in the /etc/backuppc/hosts file for the various hosts you want to back up. The first step in host-specific configuration is to use the sudo command to create a directory to host-specific configuration data, logs, and so on. Throughout this section, I'll use the sample host entry 64bit, which I defined in the section titled “Identifying Hosts to Back Up” as an example.

The first step in host-specific configuration is to use the sudo command to create the directory /var/lib/backuppc/pc/64bit, as in the following command:

```bash
sudo mkdir /var/lib/backuppc/pc/64bit
```
