# Tip

Adding an entry to the /etc/fstab file is the best way to ensure that NFS filesystem will always be mounted when the system is booted. You can maintain /etc/fstab entries for one or more NFS filesystems that you do not want to mount automatically by using the mount-options string. Manually executing the mount command only mounts the filesystem until the system reboots or until you unmount it using the unmount command. (There is no “n” after the initial “u” in mount, honest!)

After executing any of the commands in this list, you should be able to access the NFS filesystem through the specified mountpoint. Access to these filesystems and their subdirectories will follow the authentication model that you are using: either standard UID/GID mappings or the authorization rights provided by an authentication model such as Kerberos.

One huge difference between NFS 4 and NFS 2 or 3 exported directories is that NFS 4 filesystems are identified relative to the pseudo-filesystem that the NFS server is exporting, whereas NFS 2 or 3 filesystems required that you specify the full name of the directory that is exported. For example, the NFS 2 or 3 equivalent of the third bullet in the previous list is the following:

```
sudo mount -t nfs -o mount-options server:/export/home/mnt
```

The filesystem type is nfs4, and you must supply the full pathname of the exported filesystem. Your mount options specification should also include the string nfsvers=3 to mount the exported directory in NFS 3 mode.

As mentioned previously, many mount options can be specified in a mount-options string when mounting NFS filesystems manually or in /etc/fstab entries. The mount-options string is a comma-separated sequence of mount options (and associated values, if required). The following are some of the most common:

- hard: Retry indefinitely if an NFS file operation times out. You cannot specify both the hard and soft options.
- intr: Allows signals to interrupt NFS file operations that time out.
- ro: The NFS filesystem in read-only mode, regardless of how it is being exported by the NFS server.
- rsize=number: Specifies the size of the read buffer that the client should try to use when reading data from the NFS server.
- rw: The NFS filesystem in read-write mode if it is being exported in read/write mode from the NFS server.
- soft: Reports an I/O error to the calling program when an NFS file operation times out. You cannot specify both the soft and hard options.
- timeout=number: Specifies the number of tenths of a second to wait before retransmitting an RPC time-out.
- wsize=number: Specifies the size of the write buffer that the client should try to use when writing back to the NFS server.

See the man page for the nfs command (executing the command man5 nfs from any command-line environment) for a complete list of mount options for NFS filesystems.

## Automounting NFS Home Directories

**Automounting** is the process of automatically mounting NFS filesystems in response to requests for access to those filesystems. Automounting is controlled by an automount daemon that runs on the client system. In addition to automounting filesystems in response to requests for access to them, an automount daemon can automatically unmount volumes that have not been used for a specific period of time.

Using an automount daemon prevents you from having to mount shared NFS directories that you are not actually using at the moment. Mounting all NFS directories on all clients at all times causes a reasonable amount of network traffic, much of which is extraneous if those directories are not actually being used. Using the NFS automount daemon keeps NFS-related network traffic to a minimum.

The automount daemon is called autofs and is available in the autofs package. The autofs daemon is configured through the file /etc/auto.master or through NIS maps with the same name. Because the autofs daemon is part of the kernel, it is faster and the automounter of choice for many Linux distributions (such as Ubuntu). Both of these packages are available in the Ubuntu repositories, but discussing all of the nuances of automounting is outside the scope of this chapter.

## Debugging NFS Problems

If you encounter problems mounting an NFS filesystem or accessing the files that it contains, there are a number of ways to resolve these problems. The next few sections provide suggestions to help you identify and resolve the problems.

## Verifying RPC Services

If you are having problems mounting an NFS filesystem, the first thing to check is to use the rpcinfo command to probe the NFS server that you are trying to contact to verify that it is running the right NFS services and the right versions of those services. The -p option probes the specified host, or the current system if no hostname or IP address is provided. The following examples probe the NFS server at the IP address 192.168.6.143:

```
$ rpcinfo -p 192.168.6.143
program vers proto port
100000 2 tcp 111 portmapper
100000 2 udp 111 portmapper
100024 1 udp 33264 status
100024 1 tcp 37575 status
```

## Verifying Filesystem Export

The nfs-server includes utilities exportfs and showmount that you can use to list the directories an NFS server is currently exporting. The following is an example of using exportfs with -v to see a verbose listing of the exported directories:

```
$ exportfs -v
/export/users 192.168.6.0/24(rw,async,wdelay,insecure,root_squash,subtree_check)
/export/pub 192.168.6.0/24(rw,async,wdelay,insecure,root_squash,subtree_check)
```

The following is an example of using the showmount command to see the list:

```
$ showmount -e
Export list for 192.168.6.1:
/export 192.168.6.0/24
/export/pub 192.168.6.0/24
/export/users 192.168.6.0/24
```
