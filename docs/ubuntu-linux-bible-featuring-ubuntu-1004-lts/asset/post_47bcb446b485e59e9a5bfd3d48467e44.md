
## Enabling Additional Repository Components

The most common example of a situation in which you will want to access repository components other than the main and restricted components is when working with audio and video applications. The wide variety of codecs (compress/decompress modules) used to encode digital audio and video, the platform-specific roots of these codecs, and the hoops that many media companies make you jump through in order to actually play digital audio and video formats on an Ubuntu Linux system make it necessary to push the boundaries of free software licensing.

By default, the main, restricted, and multiverse components of the Ubuntu repositories are enabled when you install an Ubuntu Linux distribution. Enabled means that the sources of these repository components are included in the default /etc/apt/sources.list file which is a text file that all the package installation and management utilities discussed in this chapter consult when looking for new and updated software. This file entries describe the locations and names of different online repositories and the repository components that are available. The general format of an entry in the /etc/apt/sources.list is as follows:

```
deb URI distribution component-or-package(s)
```

The deb identifies the package format; the URI is a universal resource identifier for the location where the repository can be found, and is typically an FTP or HTTP URL. The distribution field is typically the name of a standard Ubuntu distribution, but can be anything that is used to identify a subdirectory at the URI where associated packages can be found, and the component-or-package is one (or more) names of repository components or packages that are also used to navigate the directory tree at the URI and locate available packages. If multiple component-or-package names are provided, each identifies a different entry at the URI.

The entries in /etc/apt/sources.list file for the main and restricted repository components of the 10.04 release of Ubuntu Linux, for example, are as follows:

```
deb http://archive.ubuntu.com/ubuntu/ lucid main
deb-src http://archive.ubuntu.com/ubuntu/ lucid restricted
```

Lines beginning with a hash mark (#) in the /etc/apt/sources.list file are comments. If you look through the lines in the default /etc/apt/sources.list file on your system, you will note that entries for access to the partner repository are already present in this file, but commented out. You can enable access to this repository by using sudo to edit this file in your favorite editor. To do this, edit the /etc/apt/sources.list file with your favorite editor, using a command like the following:

```
$ sudo nano /etc/apt/sources.list
```

Remove the hash marks at the beginning of the lines that enable the partner repositories, and save the updated file. The updated entries in a sample sources.list file would look like the following:

```
deb http://archive.ubuntu.com/ubuntu/ lucid partner
deb-src http://archive.ubuntu.com/ubuntu/ lucid partner
```

You could, simply add these entries to the end of the lines that already provide access to the main, restricted, universe, or multiverse components of Ubuntu repositories, but I prefer to keep them separate for clarity regarding licensing differences—and because that stays closest to the original format of the default sources.list file.

### Note

Just to be perfectly clear, installing software from the universe and multiverse repositories may add software to your system that has licensing requirements you or the company that you work find odious (such as MP3-related or video-related software), for which support is not guaranteed by the Ubuntu folks (even if you purchase support, there are no commitments to it), and which may be difficult to get support anywhere. If you are configuring systems for enterprise use, make sure your firm is comfortable with the licenses provided with non-free software in the universe and multiverse repositories. ## Other Repositories of Interest

As you can see from the previous section, the standard Ubuntu repositories are all hosted on systems that are in the ubuntu.com domain. This makes perfect sense because this is the only way that the Canonical folks can guarantee the integrity of their repository and the adherence of various components and their contents to the associated licensing guidelines. However, additional repositories of Ubuntu software will provide examples of the entries that are available on the Internet (I know that's a surprise), maintained by various groups and individuals. These alternate repository sites may simply mirror the contents of the official Ubuntu repositories to "share the load", or may provide software that is not found in the official Ubuntu repositories. In the latest case, this software may provide newer versions of popular software than is found in the backups of locally maintained software. As mentioned earlier, if you are interested in working with audio and video on your Ubuntu system, you may find these alternate repository sites provide versions of related software with bleeding-edge features that you need. In such sites, you should add to your /etc/apt/sources.list file in order to be able to list and retrieve software from them. This is typically done by concatenating new entries to the end of this file using a text editor, or can also be done using the Software Sources tool, as discussed in the next section.

Unofficial, but free software packages are one thing, a more common need is to locate and install software with various licensing restrictions. A classic Linux problem is the fact that the codecs and much of the related software used to play CDs, audio files, DVDs, and video files is proprietary software that requires a license, is unavailable for Linux systems, and sometimes both. This is not the fault of Linux, but rather a side effect of greed and cluelessness in the software and audio/video media industries, as well as location-specific laws regarding software patents, copyrights, and intellectual property. Even though the last few releases have provided increasingly easy ways of retrieving problematic audio/video packages, you may still need to manually retrieve some of the packages that you need from unofficial (or certain non-Canonical) repositories. One good site for information about such packages is the Meduntu (Multimedia, Entertainment & Distractions in Ubuntu) site at www.meduntu.org. The "Repository Howto" then links to documentation on how to add repositories to your /etc/apt/sources.list file that will enable you to play your legally purchased audio and video CDs and DVDs on your Ubuntu system.
