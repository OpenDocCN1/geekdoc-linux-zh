# Part III: Ubuntu System Administrators

Next, add an entry for your new DNS server to the file /etc/resolv.conf. On the system where you are actually running the DNS server, you can add an entry like the following as the first name server entry in that's /etc/resolv.conf:

```
nameserver 0.0.0.0
```

As mentioned previously, a name server specification of 0.0.0.0 is just a shortcut for querying a local name server using the first IP address that was assigned to the local system. The loopback address, which is usually 127.0.0.1, but is not guaranteed to be. Using the shortcut 0.0.0.0 causes your request to be sent to an IP address that is known to be valid for the current host, however may be.

Once you're sure that your name server is working correctly, you add the actual IP address of the host you are running to the /etc/resolv.conf file on all of your systems.

Now it's time to test the DNS server. You can use several commands for testing a DNS server. The most common of these are the following:

+   - dig: The recommended tool for DNS testing nowadays, its output takes a bit of getting used to be because of the richness of the information that it returns.
- host: The simplest tool for initial DNS testing
- nslookup: Officially deprecated, this command is still found everywhere and is quite useful. Unfortunately, one of these days, the nslookup command will stop displaying a warning that it is deprecated and will simply go away.

All of these commands are easy to test your new name server. The following is some sample output from each of these commands on the sample name server that I've configured in this chapter:

```
$ host 64bit
64bit.vonhagen.org has address 192.168.6.64

$ nslookup 64bit

Address: 127.0.0.1#53
```
