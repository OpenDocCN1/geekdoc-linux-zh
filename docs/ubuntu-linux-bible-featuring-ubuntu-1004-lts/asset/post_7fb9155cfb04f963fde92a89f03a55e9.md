A final issue to consider when deciding on backups and restoring is when to do them, and what privileges are required. It's generally fastest to do backups during off-peak hours when system usage is at a minimum, so that the backups can complete as quickly as possible, and when people are less likely to be modifying the files that you're backing up. In an enterprise environment, this might mean you'll want to have a graveyard shift of operators. In this case, you'll need to think about how to make sure that operators have the right set of privileges. Being able to back up user files that may be heavily protected or using a backup system that accesses the filesystem generally requires root privileges. Many people use such as sudo (which is already frequent on Ubuntu systems) or set-bits on privileged binaries such as backup and restore programs so they don't have to give the administrative password to the operators or part-time staff that generally do backups at off-peak hours. See the section of Chapter 27, "Managing Users, Groups, and Authentication," entitled "Customizing the sudo Command" for some suggestions on how to assign privileges to different groups of individuals on your Ubuntu system.

## Verifying and Testing Backups

Just doing backups isn't a guarantee that you're safe from problems, unless you're also sure that the backups you're making are readable and that files can be easily restored from them. Although its is common today, there's always the chance that the heads in a tape drive may be out of alignment. This might mean that you can only read the tapes back on the same tape drive you wrote them on, or that they can't be read at all. You should always verify that you back and restore files from backups using another device than the one on which they were made. You don't have to check backup every day, but random spot checks are important for peace of mind and job security. Similarly, tapes can stretch or wear out from use—be prepared to replace the media you use for various types of incremental backups after some amount of time. Nobody appreciates WORN backup media—"once write, never read"—even though its storage capacity is infinite.

One of the problems inherent in backups is that every type of computer media has a shelf life of some period of time, depending on the type of media, the environment in it is stored, and how lucky you are. No backup media has infinite shelf life. For example, backups can last for years, but they can also become unreachable after a shorter period of time. Long-lived media such as write-CD-Rs and DVDs are alike attractive because of their supposed longevity, but they have other problems, as mentioned earlier in the sidebar entitled "A Few Words about Backup Media." Media as these may only be suited for certain types of backups, depending on whether your backup software writes to the backup filesystem or as a raw storage device. Also, no one knows exactly how long those types of media will last, but they certainly take up less room than any kind of hard drives. In addition to spot-checking the backup media that you are currently using, you should always make a point to spot-check old archives every few years to make sure they're still useful.

## Tip

Aside from the fact that backups can be subject to the vagaries of the device on which they're written, having those devices available when you need to restore backups is an important point to consider. It is a well-known nerd that many government and military sites have huge collections of backup data on devices that don't exist anymore, such as super-low-speed tape drives and 1-inch or 7-track tapes. Even if the devices exist, the data is often not recoverable, because it's written in some ancient, twisted backup format, word size, and so on. When you retire a computer, deciding if you'll ever need to restore any of your data is an easily overlooked issue. If you're lucky, you'll be able to read the old archives in your new system and write them out to some newer media by using some newer backup format. If you're not, you've just acquired a huge number of loose, awkward paperweights that will remind you of this issue.

## Deciding What to Back Up

Aside from cost-saving issues like using higher-density media such as CD-ROMs for archive purposes, another way to reduce the number of backups that you have to keep around, as well as minimize the time it takes to do them, is to treat different filesystems when you're backing them up. For example, system software changes very frequently, so you may only want to back up the partitions holding your operating system when you do an archive. Similarly, locally developed application software changes relatively frequently, so you may only want to back up that week. I can count on one hand, with your finger, the number of times I've needed to restore an old version of an application. On the other hand, you may not be so lucky.

Keeping backups of your operating system and its default applications is important, and is critical to restoring or rebuilding an entire system you should ever need to do so (which is known in backup as a *bare-metal restore*). In terms of backups (and thanks to the excellence of the package management software available for Ubuntu systems), you can just preserve your original installation media (or even re-retrieve it over the net) if it is necessary to completely restore the system software for your Ubuntu system. If your systems use a custom kernel or some loadable kernel modules, make sure that you have a backup of your current configuration and all of the configuration files in directories as /etc that describe the state of your system. You will be glad if the disk on which your finely and heavily tweaked version of an operating bursts into flames one last night.

The issues in the first few sections of this chapter often give system administrators and managers migraines. Losing data is as painful if you're supporting yourself. Thinking about, designing, and implementing reasonable backup policies, schedules, and disaster recovery plans is an important task no how many people will be affected by a problem. Backups are like insurance policies—you hope that you never need to use them, but if you do, they had better be available.

## Backup Software for Linux

Many backup utilities are available for Ubuntu systems. Most of these are traditional command line utilities that can create archive files or write to your backup media of choice in various formats, but some interesting open source graphical tools are also beginning to appear.

The next few sections discuss the most common open source utilities that are used to do backups on Linux systems, grouping them into sections based on whether they create local backup files or are inherently network-aware. As discussed in the previous section, off-site backup is an important requirement of a backup strategy. Today's networked environments, off-site storage can be achieved in two basic ways: either by writing to local backup media and physically transporting that media to another location, or by using a network-aware backup mechanism to store backups on systems that are physically located elsewhere.

## Commercial Backup Solutions for Linux

Commercial application vendors also have been moving into the Linux backup space, because of the popularity of Linux in server environments. In my opinion, commercial backup solutions for Linux are unnecessary in the home computing environment, but are worth considering if you are using Ubuntu in a multi-system enterprise or academic computing environment. Before you scoff using commercial software for backups on-consider just how critical backups are to the computers that you maintain. This book does not cover backup solutions, but you may want to investigate the vendors if you need or want a commercial, supported solution:

- Arkeia: Arkeia's Network Backup and Smart Backup are well-known cross-platform packages that also support backing up Microsoft Windows systems and have been bundled with a variety of Linux distributions such as Red Hat, SUSE, and Mandrake. For more information, see www.knox-software.com.
- Lone Star: Lone Star's LON-TAR software has providing backup solutions for UNIX and Linux systems for more than a decade. They also offer an X Window system interface, LTX, for LON-TAR. For more information, see www.cactus.
- Microlite: Microlite's BackupEDGE and RecoverEDGE software is a nice high-performance package that supports local and remote backups and provides some interesting bare-metal restore capabilities. For more information, see www.microlite.com.
- Storix: Storix's System Backup Administrator is a graphical tool for Linux (and AI) backups that also supports Windows backups via SMB network access and features some interesting bare-metal restore capabilities for Linux systems. For more information, see www.storix.com.
- Symantec/Veritas: Veritas's Backup Exec software, now owned by Symantec, is a well-known backup solution for Microsoft Windows systems that is also possibly available for Linux. For more information, see www.symantec.com/enterprise/veritas.
- TOLIS Group: The BRU Backup and Restore suite is a well-known, well-respected client/server backup solution that provides backups across Linux, UNIX, Mac OS X, and Microsoft Windows platforms, and has recently entered the virtualization space through a partnership with Parallels. For more information, see www.tollisgroup.com.

None of these vendors explicitly states that they support Ubuntu, but they all advertise Linux support, and I'm sure they'd have to discuss Ubuntu support with you.
