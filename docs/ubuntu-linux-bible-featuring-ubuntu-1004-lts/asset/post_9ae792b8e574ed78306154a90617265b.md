## Migrating from Old Versions of Evolution

If you are already an Evolution user but are using a version of Evolution that does not provide the Backup Settings command, you can still migrate your existing Evolution configuration information by using the command to create a compressed tar file that contains the contents of the .evolution directory in your home directory (and its subdirectories). You could do this by using commands such as the:

```
cd ~
tar -czf evolution-backup.tar.gz .evolution
```

You can then transfer the file evolution-backup.tar.gz to your new Ubuntu system and restore it during the Evolution setup process. Do not delete your existing evolution information until you've verified that the backup file was successfully imported!

Old versions of Evolution used a directory called evolution in your home directory rather than the .evolution directory. If you're using a version of Evolution that uses the evolution directory, congratulations for being a long-time Evolution user, but your upgrade mechanism will be a bit more complex. You will have to back up this directory to a file, copy that file to your new Ubuntu system, and extract its contents manually before beginning the Evolution setup process. If you haven't done this, now do so. When you restart the setup process after restoring your old evolution directory, the Evolution Setup Assistant should detect this old directory and offer to migrate everything to the new .evolution directory.

The "Full Name" field should already be filled out for you — Evolution grabs this information from the account from which you're running Evolution. You can change that name, of course, if you'd prefer to have the people who receive mail see a name that's more "clever" than your actual account name. The critical bit of information on this panel is in the "Email Address" field. This will be the e-mail address that you want to associate with this account. As mentioned previously, this is typically your e-mail address at ISP or wherever you get your e-mail.

The "Make this my default e-mail account" checkbox is selected by default in this dialog because Evolution starts the Setup Assistant only when it detects that you are starting Evolution for the first time. Your default account is simply the one that Evolution will continue to use unless you activate another account.

If you want people who receive e-mail from this account to actually reply to you, you can specify the e-mail address of that account in the "Reply-To" field, but this is usually unnecessary.

## A Quick Guide to POP versus IMAP

The key difference between POP and IMAP lies in where e-mail is stored. POP downloads mail from the server to your local machine and typically deletes it from the server. IMAP leaves the mail on the server, allowing you to access and manage it from multiple devices. Each of these has advantages and disadvantages:

- POP is good for users who only access mail from one device and want to work offline.
- IMAP is better for users who use multiple devices and want to keep their mail synchronized.

Most POP clients, including Evolution's, provide a special option "Leave mail on server." This enables you to configure multiple clients to read your POP mail, but only one of them (typically your home machine) downloads the mail and deletes it from the server. All POP clients remember the last message that they read, so they don't re-download all of your mail each time you check it—only that they recognize as new. This provides a nice compromise between the flexibility of IMAP and the local permanence of POP. For example, when I'm on the road, the copy of Evolution on my laptop lets me read my mail but doesn't delete it from the server—this happens when I get back home and check mail from my primary machine. The downside of POP while traveling, of course, is that I don't have access to all of my mail when I'm on the road, but if I'm really desperate, I can always connect to my home again and manually look through my mailboxes or run Evolution from that over the NET.

When you select a specific type of server, the panel changes to reflect the particular types of settings that are associated with a mail server of that, as shown in Figure 7-5, which shows the settings for a POP mailer.

On this panel, enter the name of your mail server and your username as the mailer is concerned. Note that your mailer's idea of username may not be the same as your username name—many POP mailers require a username of the form login@domain.name to guarantee the uniqueness of usernames on mailers that support multiple domains. For example, my login at my ISP is vonhagen, but my POP username is vonhagen@vonhagen.org.
