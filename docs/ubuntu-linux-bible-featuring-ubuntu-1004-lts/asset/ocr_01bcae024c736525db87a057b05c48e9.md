Host specifies the name or IP address of the system you want to display the window, and is followed by a colon. After the colon, the first number identifies the graphics display upon which the window should be displayed, followed by a period, and the number followed by a colon, followed by the number of the physical screen attached to that card. In most cases, both display and screen are 0.

See the section of Chapter 11, "Using Command-Line Tools," and extent "Using Environment Variables" for more information about setting environment variables. In many cases, you can also start an X Window System on a remote server by starting the application from the command line and specifying the -display host:display.screen.

After window managers, the next step in the evolution of the X Window System desktop experience is the desktop manager. Desktop managers, colloquially referred to as desktops, always run a window manager under the covers, but also provide additional capabilities such as the following:

+   - A file of some sort to graphically browsing files and directories
- Easy, flexible ways to tie applications to buttons, icons, and menu items
- A centralized mechanism for configuring the appearance of your screen and the windows that it displays, generally referred to as a theme
- Support for running lightweight applications (known as applets) within the context of the window manager to support certain types of tasks

The most common desktops for Linux systems are GNOME (GNU Network Object Model Environment; www.gnome.org), KDE (KDE Development Environment; www.kde.org), ROX (http://ruscidus.com/desktop/), and Xice (www.xfce.org). Both GNOME and KDE are robust, desktop environments provide their own window managers (on Ubuntu systems, GNOME uses Compiz, while KDE uses KWin) and differ in terms of default mouse and key bindings, menu organization, and the different graphical toolkit (GNOME uses a widget toolkit known as GTK; while KDE and Xice are lightweight desktops, which means that they attempt to strike a balance between the heavy resource requirements and corresponding power of rich desktop environments as GNOME and KDE, and the much lighter requirements but more limited capabilities of traditional window managers. You can find a great introduction to most of the X Window System managers and desktop environments for Linux at http://xwinman.org. Versions of Ubuntu prior to 7.10 (Gutsy Goblin) used the Metacity window manager with GNOME, but versions 7.10 and later use the Compiz window manager. For detailed information about the Compiz window manager, see "Using the Compiz Window Manager."

The rest of this chapter primarily focuses on GNOME, which is the desktop environment that is used on Ubuntu systems and which automatically starts the first time you log in to an Ubuntu system. Although you can change the window manager by GNOME, switch to KDE, or even switch your Ubuntu experience to using a window manager rather than its default GNOME configuration, these are all advanced tasks.
