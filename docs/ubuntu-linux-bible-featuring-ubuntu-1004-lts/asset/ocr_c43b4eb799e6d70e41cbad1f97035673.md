# Accepting Mail for an Entire Domain

As mentioned earlier, the mysestination parameter identifies what the mail host will deliver locally. The default Postfix configuration file accepts mail for localhost.localdomain, localhost, the actual hostname of the machine, and whatever you specified as the name of the machine on the configuration screen shown in Figure 30-2 (if that differs from the actual hostname of your machine). To make your new Postfix mail server a valid final destination for all your domain, you must add the name of your domain to the list of destinations in your machine.cf file. Because I specified ubuntu.vonhagen.org as my mail name, myydestination parameter currently looks like the following:

```
mydestination = ubuntu.vonhagen.org, ubuntu,
               localhost.vonhagen.org, localhost
```

I can add my domain name to this list or the name of my domain and leverage the value of that parameter to provide this information. I would add the myydomain parameter setting and update the value of the mysestination parameter, which together would look like the following:

```
mydomain = vonhagen.org,
mydestination = ubuntu.vonhagen.org, ubuntu,
               localhost.vonhagen.org, localhost, $mydomain
```

As with other configuration file changes, I would then either restart the Postfix server using sudo /etc/init.d/postfix restart or use the sudo postfix reload command to cause the active Postfix daemon pick up my changes to the configuration file.

# Tip

When you make the changes suggested in this section, you may also want to change the value of the myorigin parameter during installation, myorigin is set to whatever you specified as the name of the machine, which is useful because that value was also used in the value for your mysestination parameter, which would correctly handle the case in when someone sends mail to root@ubuntu.vonhagen.org. However, after installation, it is more useful to have myorigin be the same as the value of mydomain. 

# Activating Qpopper for POP/POP3 Support
