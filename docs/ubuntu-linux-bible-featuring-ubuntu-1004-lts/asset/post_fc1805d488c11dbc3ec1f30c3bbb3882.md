Moving and renaming files from the command line is similarly easy. Linux systems don't actually provide a separate rename command—on a Linux system, the mv command moves both files and directories to a new location and also renames them as part of the move operation. For example, to rename the file.txt to the new name newfile.txt, you would do the following:

```
$ mv file.txt newfile.txt
```

The mv command follows the same conventions as the cp command in terms of specifying full pathnames and when specifying a directory as the name of the location to which you want to move a file. For example, the following command moves the file /home/wvh/file.txt to the /tmp directory and renames it newfile.txt:

```
$ mv /home/wvh/file.txt /tmp/newfile.txt
```

Unlike the cp command, the mv command doesn't need any special flags when moving or renaming directories. For example, to rename the directory to backup, you would do the following:

```
$ mv -v test backup
```

As with the cp command, if the backup directory already existed, the mv command would move the directory into the backup directory, retaining its original name. The mv command provides a -v (verbose) option to show what's going on during an mv operation, but this is somewhat less exciting when renaming a directory, as you can see from the following example:

```

'test' -> 'backup'
```

Along copying and moving files and directories, deleting files and directories is a common operation. Whether you are deleting things to free up space, deleting copies of projects you've finished, or deleting things that you don't want anyone to see, it's quite easy to delete files from the command line. The key to doing so is the rm command, which stands for remove.

To remove a single file on a Linux system, simply type the rm command followed by the name of the file. For example, to delete file.txt, you would do the following:

```
$ rm file.txt
```

The file is gone. As with the cp command, the rm command provides an -r (recursive) option to enable you to remove entire directories. For example, to permanently remove a directory named test, you would issue the following command:

```
$ rm -r test
```

Tip

You can remove directories using the rm command, but I don't find that to be a common scenario. I rarely have empty directories sitting around because I usually create directories to store something in. I generally use the rm command to delete any directory because that way I don't have to delete its contents first. My mileage may vary.

If you moved to Ubuntu from a Microsoft Windows system, you may be aware that it is easy to recover files you've deleted on a Windows system it initially erases the directory entry that identifies the file or folder you're deleting. This is not the case on a Linux system. When you delete a file or directory on a Linux system using the command line or emptying the Trash in a graphical environment, all of the disk storage associated with the file, directory, and the contents of that directory are returned to a general list of free space that is available on your system. Although deleted files and directories can still be recovered on a Linux system, it is much harder to do so and requires the assistance of someone who really knows the details of the filesystem.

The downside of this is that you can't easily recover any files you've deleted by mistake unless you do so using a graphical utility such as a file manager. To protect yourself from accidentally deleting files, see the section later in this chapter on "Defining and Using Aliases" for information about how to permanently set a safe version of the rm command that will ask you for confirmation before it removes anything.

Tip
