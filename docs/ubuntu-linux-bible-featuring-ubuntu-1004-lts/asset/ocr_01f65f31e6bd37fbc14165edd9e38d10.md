# Part II: Ubuntu for Desktop Users

Sending outgoing Gmail mail is done via the SMTP protocol. To send your Gmail with your mail client, you must specify the following values when creating an account for sending mail:

+   - Server Type: SMTP
- Server: smtp.gmail.com
- Port: 587 or 465
- Requires Security/Authentication: Yes, TLS or STARTTLS. (If this option isn't available, try SSL encryption.)

Test your new account using an existing e-mail account to send an e-mail message to your Gmail account, and clicking Send/Receive in Evolution. If you successfully retrieve mail, you should then check that you can send mail this account. To do this, create a new message using the icon or the File+New menu, selecting the menu item to send a new mail message. Make sure that the identity of the sender is your Gmail account.

To see the official explanation of how to configure IMAP access to your Gmail account, see http://mail.google.com/support/bin/answer.py?answer=78799. If you have any problems with the explanation provided in this section, you may want to check that site, in case something has changed since this was written.

# Reading Mail from Other Web-Based Mail Providers

Many free e-mail providers such as Hotmail and its successor, Microsoft Live, Yahoo!, mail.com, and so on provide free e-mail accounts that are designed to be accessed via we—in other words, via a browser-based interface. By default, these web-only e-mail accounts can not be accessed via standard protocols as POP or IMAP. To the cleverness and hard work of open source software developers everywhere, you can access these accounts POA via a POP interface that you can talk to. I am a big fan of the package called FreePOPs! (www.freepops.org), which provides similar functionality to FreePOPs!, but FreePOPs! is available in the Ubuntu repositories, it is easy to set up, and has always worked for me. If you're interested in similar packages, you may want to look at POPmail (www.popmail.com) or MrPostman (http://mrpostman.sourceforge.net/scripts.html). These are generic solutions that provide a POP interface for your existing mail reader.

There are a variety of reasons why you might want to access a free webmail account from a local mail client such as Evolution. Some of my favorites:

+   - It's nice to use the same application for all of your e-mail.
- Using a POP client with a webmail account enables you to archive all of your mail on your local machine, which is reassuring for the paranoid among us.
- It's tricky (impossible) to access webmail when you're offline.
- You also not to worry about synchronizing address books using a directed graph that can end up looking like an M.C. Escher drawing if you have enough e-mail accounts.
