## Traditional VNC Servers Work

Typically, VNC servers are started by a system daemon as inetd or xinetd, or by a shell or Perl script called vncserver, and export their own displays rather than the desktop of the currently logged-in user. These mechanisms provide additional flexibility in your VNC server environment. VNC servers that are started by the inetd or xinetd responding to connection request can start multiple servers provide different desktop sizes and resolutions, which is very convenient if your system has a 21-inch monitor and you want to connect to it from a laptop without scrolling all over the place. If you start a VNC server using the vncserver script you can also take advantage of user-specific startup scripts to identify the window manager and any applications that your VNC server should start. The VNC server script is usually the file ~/.xstartup. If this directory and the startup file do not exist the first time you start a VNC server, the directory is created and the startup script is cloned from the default Window Startup file /etc/X11/xinit/xinitrc.

Exporting a graphical console that is independent of any physical one and using a startup script do so enables traditional VNC servers to follow the somewhat convoluted chain of X Window startup files that are normally used: ~/.xinitrc,~Clients on some systems, /etc/X11/xinit/xinitrc, /etc/X11/XSession and so on. These startup files can launch various desktop environments and window managers by environment variable settings, and also provide a last resort of starting the twm window manager when no other window manager can be found.

VNC servers that follow this more traditional model and are available for Ubuntu systems include the vnc4server and tightvncserver packages, which you can install using your package management utility. However, if you install one of these on an Ubuntu system, you should uninstall the vino VNC server.

## VNC Client and Server Software for Other Systems

If you still use operating systems, you may want to use VNC to access them from your Ubuntu desktop, or access your Ubuntu desktop from the desktops of those other systems. This is no problem at all thanks to the fact that VNC is open source. The next two sections explain how to get VNC client and server software for popular platforms such as Mac OS X and Microsoft Windows.

## VNC Servers and Clients for Mac OS X

A variety of VNC servers and clients are available for Mac OS X. Mac OS X has a built-in VNC server since Mac OS X 10.4 (Tiger), but older Mac OS X releases that you require myself. My favorite VNC server for pre-Tiger Mac OS systems is the OSVNC server, which is available at http://sourceforge.net/projects/osvnc. You can download this as a Mac disk image (.dmg) file that will mount automatically and start the installer. The OSVNC server displays its own configuration dialog when you start it—you configure the built-in VNC server using the System Preferences' Sharing applet.

As far as VNC clients for Mac OS X go, my favorite is called "Chicken of VNC". It's a small, fast VNC client with a funny name—and how can you beat that combination? The latest version of the Chicken of the VNC client is available from the project's SourceForge site at http://sourceforge.net/projects/cotvnc.

## VNC Clients and Servers for Windows

TightVNC is a small, highly optimized VNC client. TightVNC makes efficient use of network bandwidth through some clever tricks using JPEG compression for the display and differentiating between local cursor movement and cursor movement that needs to be communicated back to the VNC server. TightVNC also provides security features that RealVNC does not, including automatic SSH tunneling for security purposes. Although RealVNC clients and servers are available for Windows, I really like TightVNC and recommend using it. Both stable and bleeding edge (i.e., versions that are actively under development) versions of TightVNC are downloadable from www.tightvnc.com/download.html or from their SourceForge site at http://sourceforge.net/projects/tightvnc-tight.

The downloadable EXE file from either of these provides both the VNC client and server. After downloading and installing the executables, you can start the VNC server from the standard menus. The VNC server's administrative dialog supports standard configuration options such as setting a password that you will need to use to connect to the VNC server, automatically starting the VNC server when you log in, and displaying an icon for the VNC server in the system tray when the VNC server is running. The icon is extremely convenient because it lets you know when a server is running and also because you can get instant access to the configuration dialog by clicking on the icon.
