## Reading Mail from Other Web-Based Mail Providers

Many free e-mail providers such as Hotmail and its successor, Microsoft Live, Yahoo!, mail.com, and so on provide free e-mail accounts that are designed to be accessed via web—in other words, via a browser-based interface. By default, these web-only e-mail accounts can not be accessed via standard protocols as POP or IMAP. To the cleverness and hard work of open source software developers everywhere, you can access these accounts POA via a POP interface that you can talk to. I am a big fan of the package called FreePOPs! (www.freepops.org), which provides similar functionality to FreePOPs!, but FreePOPs! is available in the Ubuntu repositories, it is easy to set up, and has always worked for me. If you're interested in similar packages, you may want to look at POPmail (www.popmail.com) or MrPostman (http://mrpostman.sourceforge.net/scripts.html). These are generic solutions that provide a POP interface for your existing mail reader.

There are a variety of reasons why you might want to access a free webmail account from a local mail client such as Evolution. Some of my favorites:

- It's nice to use the same application for all of your e-mail.
- Using a POP client with a webmail account enables you to archive all of your mail on your local machine, which is reassuring for the paranoid among us.
- It's tricky (impossible) to access webmail when you're offline.
- You also do not to worry about synchronizing address books using a directed graph that can end up looking like an M.C. Escher drawing if you have enough e-mail accounts.

## Chapter 7: Managing E-Mail and Personal Information with Evolution

Note being able to access a webmail account via POP does not enable you to send mail through that account. As mentioned several times in this chapter, retrieving incoming mail is done via protocols such as POP and IMAP, while outgoing mail is sent using a remote mail server that you communicate with using SMTP or by contacting a local mail server via a UNIX/Linux Sendmail interface. You have a few choices for sending mail using your webmail account:

- Continue to use the webmail interface to send mail for this account (which is something of a pain).
- Send mail for your webmail account using an existing SMTP server to which you already have access.
- Follow the instructions provided in Chapter 30 on how to install, configure, and run your own mail server. It's really not that hard, and think how powerful you'll feel!

### Creating POP Accounts for FreePOPs!

After installing FreePOPs, you'll need to create accounts that enable you to access it. To check and read your webmail via POP, you must specify the following values when creating an account for receiving mail:

- E-Mail address: your-username@host.com
- Server Type: POP
- Server: localhost
- Username: your-username@host.com
- Requires Security/Authentication: No
- Port: 110
- Password: your-password

In these examples, replace host with hotmail, live, mail, yahoo, or whatever other domain name is used by your webmail. Similarly, you should replace your-username and your-password with the appropriate values for your account when creating a new account in Evolution.

If your mail client processes integrated/outgoing accounts (as Evolution does), simply continue with the account definition, specifying one of the SMTP servers discussed in the introductory text for the section "Reading Mail from Other Web-Based Providers." If your mail client stores information about incoming and outgoing messages separately (as Contacts does), save the current changes for POP access to your webmail, and create an account for sending the mail associated with your webmail account.

Test your account by using an existing e-mail account to send an e-mail message to your webmail account and clicking Send/Receive in Evolution. If you successfully retrieve mail, you should then check that you can send mail using the outgoing mail server associated with this account. To do this, create a new message using the icon or the File+New menu, make sure that the identity of the sender is your webmail account.
