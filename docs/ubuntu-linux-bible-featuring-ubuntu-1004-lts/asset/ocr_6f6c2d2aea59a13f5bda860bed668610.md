An alternative to the previous bullet is to automatically mount networked home directories using an exported NFS directory that is managed by an NFS automount daemon known as autofs on Linux systems. Whenever access to a directory by an automount daemon is requested by a client, the automount automatically mounts that directory on the client system. +   Suppose you want to make a specific set of tools available on all of the systems in your computing environment, but also want to centralize them on an NFS server for each maintenance and updating. To ensure that configuration files are portable across all of your systems, you might want to make these binaries available in the directory /usr/gnu regardless of the type of system that you were using. You could build simple binaries for each type of system that you support, configuring them to be found as /usr/gnu but actually storing them in directories with names as /export/gnu/ubuntu, /export/gnu/solaris8, and so on. You would then configure each of a specified type of client to mount the appropriate exported directory for that type as /usr/gnu. For example, /export/gnu/ubuntu would be mounted as /usr/gnu on Ubuntu systems, /export/gnu/solaris8 would be mounted as /usr/gnu on Solaris systems, and so on. You could simply put /usr/bin in your path and the legacy "right" would happen regardless of the type of system that you logged in.
