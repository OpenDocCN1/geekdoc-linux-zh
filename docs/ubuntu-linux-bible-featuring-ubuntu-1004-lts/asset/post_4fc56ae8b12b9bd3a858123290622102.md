## Changing File and Directory Permissions

Chapter 4 introduced the idea of Linux users and groups and also provided an initial explanation of how file and directory permissions are represented when listing the contents of files and directories. You saw the same thing earlier in this chapter when exploring the ls command -l option. Being able to protect files so that only certain users or groups can execute them is handy, but it begs the question, "How do I do that?" You can easily change file and directory permissions from graphical file managers such as GNOME's Nautilus by right-clicking, selecting Properties, and selecting the Permissions tab, as shown in Nautilus in Figure 11-8. Fortunately, changing file and directory permissions from the command line is similarly easy, and may even be easier.

The chmod (change mode) command enables you to change any of the permissions associated with files and directories that you own. The chmod command supports two ways of setting permissions:

- Using octal values that actually represent the bits in the permission field of a file or directory
- Using friendly letters to represent permissions for the user who owns a file or directory (u), the group with that file or directory is associated (g), other users on the system (o), or all users on the system (a), and using the plus and minus signs to add or subtract permissions. This is known as changing permissions in symbolic mode.

## Chapter 11: Using Command-Line Tools

In this section, I'll focus on the second approach because many of us may be a bit rusty in octal, and the symbolic mode is easier to visualize and use. I'll use the example file hello.sh, which happens to be a bash command file (shell script) that simply prints the string "Hello, World!" in the shell window from which it is executed. Let's look at its default permissions:

```bash
$ ls -l hello.sh
-rw-r--r-- 1 vwh mwh 36 2006.03-18 16:30 hello.sh
```

As explained in detail in Chapter 4, the characters at the left portion of the ls command's long output describe the current file permissions. These permissions fall into four groups: the leading dash identifies the type of object that this is (a dash means it's a regular file), and the remaining three groups of three characters indicate the permissions of the owner of the file (vwh), the groups associated with that file (also named vwh), and the rights that all other users have to file. Each of these groups of three characters can have the following values (in order):

- r: The file or directory can be read.
- w: The file or directory can be written.
- x: The file can be executed or the directory can be searched for other files or directories.
- -: The permission is not granted.

The two instances of vwh in the ls output, from left to right, identify the owner of the file and the group that is associated with it. In the sample output, we therefore can see that if the owner of the file can both read and write to the file, but that other members of the group vwh can only read the file, and all other users on the system can only read the file.

Because this is a shell script, I presumably want to be able to execute it. To make the file executable by its owner (me), I would issue the following command:

```bash
$ chmod u+x hello.sh
```

Listing the file again, we can see that the file is now marked as being executable by its owner:

```bash
$ chmod u+x hello.sh
$ ls -al hello.sh
-rwxr-xr-x 1 vwh users 36 2006.03-18 16:30 hello.sh
```

If I want others in the group and all other users on the system to be able to execute this shell script, I could issue the following commands to make those changes and verify them:

```bash
$ chmod g+x hello.sh
$ ls -al hello.sh
-rwxr-xr-x 1 vwh users 36 2006.03-18 16:30 hello.sh
$ chmod a+x hello.sh
$ ls -al hello.sh
-rwxrwxr-xr-x 1 vwh users 36 2006.03-18 16:30 hello.sh

That's a lot of typing for a repetitive series of operations! Luckily, the chmod enables you to group multiple permission operations. Suppose I wanted to remove the ability for anyone other than myself to execute this script. I could do this with the following single command:

```bash
$ chmod go-x hello.sh
$ ls -l hello.sh
-rwxr-xr-- 1 vwh 36 2006-03-18 16:30 hello.sh
```

Note that I used go, which means anyone who is not in the group vwh, rather than a, which means all users on the system, because all users on the system would include me.

You can add or remove write for any supported permission group using the chmod command and similar operations. Files and permissions have the same meanings for directories as they do for files, with the exception of the executable bit, which for directories grants permission to search that directory. For example, you can create a directory that no one but you can read, but still enable people to execute programs or shell scripts that it contains by removing read permission (r), making sure that search permission (x) is still set. People won't be able to see what's in the directory, but they can execute programs or that if it contains their exact names.

## When Creating Permissions Files and Directories

A umask (user mask) is the UNIX mechanism for setting the default protections of files and directories that you create. By default, the umask is a four-digit octal number that is logically ANDed with the generic permissions of 0666 (ironically) when you create a file, or 0777 when you create a directory.

## Finding line That Do Specific Things

The command line is a pretty friendly place to execute commands if you know what you're doing and know what command to do it with. Unfortunately, the Linux tendency to avoid long command names by dropping characters from their names, it's often hard to figure out what command you want to use.

Luckily, the Linux online manual, man, provides a truly convenient search option (-k) that automatically searches for a specified keyword or phrase in the description fields of each man page. For example, suppose you didn't know about the chmod command and wanted to see a list of commands that have something to do with permissions. For appropriate commands using the following command:

```bash
man -k permissions
```

Note that this can be tricky just like a Web search, when you have to look for the right phrase. However, at least the possibility is always there. You can search for single words or quoted strings to refine the list of commands that match.

If your man -k output lists a command but you can't seem to execute it (you the message "command not found" when you try to execute it), this means that the directory where command is stored isn't one of the directories listed in your PATH variable. In that case, you can try using whereis to locate that command, in the following example:

- man "physical volume" - change attributes of a physical volume
- pvdisplay (8) - display attributes of a physical volume
- pvremove (8) - remove a physical volume
- pvs (8) - report information about physical volumes
- pvscan (8) - scan all disks for physical volumes

```bash
$ pvscan
bash: pvscan: command not found
```

```bash
$ whereis pvscan
pvscan: /sbin/pvscan /usr/share/man/man8/pvscan.8.gz
```

The where command tells you where the command is located (and where its documentation is found). You can then execute that command by specifying the full pathname of the executable, which in this case is /sbin/pvscan.
