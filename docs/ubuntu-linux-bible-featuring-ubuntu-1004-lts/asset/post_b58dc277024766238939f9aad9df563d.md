This section explains the internals of the sudo command and its configuration file, and discusses how to grant administrative privileges to other users in various forms.

- sudo is a command that allows you to execute privileged command-line utilities, such as apt-get, aptitude, dpkg, and so on. If you want to execute graphical commands with administrative privileges on a standard Ubuntu system, you should use the gsudo command instead.
- The problem with running graphical applications using sudo rather than gsudo is that they may change the ownership of the .authority file in your home directory, which many KDE, GNOME, and Standard X Window System applications use to track the applications that are authorized to access a specific X Window System display. If you accidentally use sudo to start a graphical application and cannot execute subsequent queries, you can remove the .authority file in your home directory by using the command rm .authority, and then use gsudo to start your graphical applications.
- Once you have executed the sudo or gsudo commands to run any privileged commands, your authorization is stored for 15 minutes so that you do not have to provide your password over and over for each privileged command that you want to execute. During this time you must supply sudo or gsudo commands. After 15 minutes, sudo or gsudo again will result in your being prompted for a password, and the cycle repeats. For the paranoid, the sudo command provides a -k option that prevents the temporary storage of authentication information, so a quick hack for using sudo is to use the command to execute a bash shell by executing sudo -s. After supplying your password, this will give you a root shell in which you no longer have to specify sudo or gsudo commands to execute privileged operations. This is bad and will generate abuse from any other Ubuntu fans that you see doing this if you should ever want to do this.

# Chapter 27: Managing Users, Groups, and Authentication

The operation of the sudo command is controlled by the file /etc/sudoers, which is a text file that cannot be viewed by mortals for security reasons. To view this file, you should therefore use the command to display it, using a command like:

```bash
sudo visudo
```

The sudo command is a special version of the vi command that ensures that only one person is modifying the /etc/sudoers file at a time. You do not need to identify the file /sudoers as an argument—the sudo command knows what it is to edit. You can, of course, open this file in any text editor, but as you will see, the /etc/sudoers file can contain blank lines (which are ignored) and comments—any characters that follow a hash mark (#) are interpreted as a comment. The meaningful entries in /etc/sudoers file on a standard Ubuntu system are the following:

```
Defaults env_reset
root=(ALL) ALL
admin=(ALL) ALL
```

The first of these lines specifies default options for how the sudo command behaves. The only option in /etc/sudoers file is the following:

- env_reset: Resets the environment to only contain LOGNAME, SHELL, and SUDO_* variables. This prevents the propagation of other environment variables.

One that you may want to change in the /sudoers file is the default period of time for which sudo or gsudo caches the credentials of the root user that you don't have to enter your password. By default, these commands cache for 15 minutes, which many administrators view as too long. To explicitly set this cache period (known as timeout period), modify (or add) the Defaults entry in /sudoers file to look like the following:

```
Defaults env_reset, timestamp_timeout=XX
```

Change XX to be the number of minutes for which you want your privileges to be cached without requiring you to enter your password again. To require all users to enter a password when entering any of these commands, set XX to 0. The next two lines are the really interesting ones. The following entry states that root can do anything and execute any command on the system:

```
root=(ALL) ALL
```

# Fixing a Broken sudo Command

Installing some versions of Ubuntu in Expert mode use the standard root mechanism, which can leave your system in a state where sudo cannot use the command to execute privileged commands. Similarly, on a normal Ubuntu system you can reboot your system, press the Escape key to see the GRUB menu, and select Recovery Mode from the GRUB menu. This will reboot your system and bring up a root shell.

Once you are logged in as root on your Ubuntu system, check to see that /etc/group file contains the admin group and that any users you want to be able to perform administrative operations are members of group. If you do not have an admin group, you can add it using the Users and Groups tool earlier in the chapter or by a command-line command (as the root user) such as the following:

```bash
addgroup --system admin
```

Next, make sure /etc/sudoers file contains the entry that grants administrative privileges to the admin group, which is:

```
%admin=(ALL) ALL
```

If this entry is not in your /sudoers command, you can use the visudo command to edit that file and add the entry. After making sure the admin group exists and is referenced in the /sudoers file, all you have to do is add any user that you want to be able to run protected applications to the admin group. You can do this by using the Users and Groups tool discussed earlier in the chapter or from the command line by using a command such as the following:

```bash
adduser userf
```

This command would add the user userf to the admin group, enabling them to run privileged operations using sudo and gsudo (or kdes) in the future. Since all members of the admin group (as defined in the /etc/group file) can also do anything (i.e., run any command as root):

```
%admin=(ALL) ALL
```

To enable other users to perform privileged operations, all you have to do is add them to the admin group in this chapter or by using the /etc/group file using the Users and Groups utility (as explained earlier in this chapter) or using the sudo command to execute a command-line utility such as adduser, as in the following example:

```bash
sudo adduser userf
```

This command would add the user userf to the admin group and enable that user to execute any commands using sudo or gsudo.

# # Configuring Kerberos Authentication

Kerberos is a distributed authentication and communication service that was originally developed at the Massachusetts Institute of Technology (MIT). Kerberos provides secure authentication and communication for client/server applications using strong cryptography to enable clients to prove their identity to servers over the network.

Kerberos works by exchanging security information between clients (which can be users or machines), the Kerberos Authentication Server, and the resource you are trying to access. The information is initially exchanged when attempting to prove one's identity is known as a ticket. The information used to encrypt tickets and subsequent communications is known as a key. Once the identity of a client is verified, the client is granted a Kerberos token that can be used to verify their identity to any Kerberos-aware server. For security reasons, Kerberos tokens are timestamped so that they automatically expire unless renewed by a user or service. The primary system for granting tickets (and holds the master copy of the Kerberos database) is known as the Kerberos Key Distribution Center (KDC).
