All the command-line options I discussed have begun with a single dash. This isn't necessarily the case for all commands. Some Linux commands with their conceptual roots in ancient versions of UNIX (such as the tar command) don't even require a dash before a single command-line option or a group of command-line options. This antiquated command-line option convention is deprecated, which means that anyone who implements a command nowadays doesn't require at least one dash; its options will be mocked and verbally abused via e-mail by the Linux and open source communities. (ALL UNIX commands that don't require a dash before their options have also been updated so that they can also handle finding a dash before them.) Nowadays, command-line options always begin with a dash, but with an interesting twist, they can also begin with two dashes. The conventions for this are that single-letter options are preceded by a single dash, while multi-letter, "whole-word" options begin with two dashes. This is necessary for two reasons:

- Most command-line utilities support both styles of options: the traditional single-letter options and the newer whole-word options pioneered by the folks at the Free Software Foundation.
- Because you can combine multiple single-letter options into a single group of options (as you've seen throughout this section), unless you use two dashes to identify a whole-word option, the command that you're executing cannot differentiate between the two.

To illustrate this, let's ask for help from the ls command:

```
$ ls -help
/bin/ls: Invalid option -- e
Try '/bin/ls --help for more information.
```

Well, exactly that is both illustrative and friendly. When preceded with a single dash, the ls command interprets each of the letters as a single option and therefore completes because no other option matches the letter e in the -help option. # Getting Information about Commands

As you can see from the final example in this section, many command-line utilities provide a --help option, which displays what is known as a usage message. A usage message is a short summary of how to use a command, summarizing available options and their meanings. Unfortunately, not all commands offer a --help option, and those that can't display all possible information about those options are discussed in Chapters 5, "Using the GNOME Desktop," and 6, "Using the Compiz Window Manager," where the graphical environments used on Ubuntu systems provide a huge assortment of online help that makes it easy for you to get information about how to use graphical commands. Luckily, the Ubuntu command-line environment also provides a similar amount of online help in the form of man and info commands.

The man command is your best friend when using or experimenting with command-line programs. The man command displays manual pages, formatted for your screen. In Linux/UNIX fashion, the man command paginates its output using the Linux version of UNIX more known as less—to make easy to scroll forward or backward in your output. Because the online reference information displayed by the man command is displayed screen/page at a time and corresponds to the documentation you traditionally find in a printed reference manual, the documentation displayed by man is generally referred to as a man page or as man pages.

As an example of using the man command, you can type man for additional information on the man command itself. The first part of the man page looks like the following:

As you can see, the online man pages for Linux commands provide extensive information about available options, but also provide a significant amount of general information about using the commands themselves, usually including examples.

A more modern alternative to the man command, the info command provides similar usage and explanatory about Linux commands. The info command provides Emacs to display its output and provides more extensive and up-to-date documentation than the traditional man command.

The GNU folks introduced the info command to provide a richer, more robust environment for displaying help. The text files that are used by the info command provide a very rich syntax for hyperlinking between different sections of info, and the use of Emacs as the application for displaying pages provides a much more flexible environment for moving around the info that you're looking at. The info command can also display Linux man pages, so you can even examine man pages using info—the info command is perhaps the best example of that sort of recursion.

The man and info commands will quickly become your new best friends when you are using or simply learning about utilities.

# What's a Shell?

A shell is the generic name given to any command-line interpreter, and comes from UNIX, the parent of Linux. UNIX was one of the first operating systems to introduce the idea of using a command-line interpreter that was not built into the operating system and that had no special permissions to mysterious operating system tasks. These ideas have been preserved in every conceptual descendant of UNIX and have proved handy for several reasons. The most interesting of these is that, because it is a separate, stand-alone executable, a Linux system can offer each user his or her choice of multiple shells, all of which can be upgraded independently from the operating system.

The original UNIX shell was written by Ken Thompson, one of the primary creators of UNIX, and was extended by John Mashey, at Bell Labs. These shells were somewhat primitive—the first shell that had the capacities we have come to know and love today is the Bourne Shell, written by Stephen Bourne at Bell Labs in 1974. This shell, known to its friends as /bin/sh, is the shell that is used by default on most UNIX systems, and is the parent of the /bin/bash shell (which stands for "Bourne-Again Shell") that is used by default on most Linux systems today. As I'll explain in the next section, there are a variety of other shells to choose from Linux systems. If you come to Linux from a version of UNIX that features another shell, you'll be able to feel at home quickly (and perhaps bring over and reuse your existing shell configuration files).
