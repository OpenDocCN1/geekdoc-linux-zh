+   - /proc/sys/sunrpc/nlm_debug: Controls tracing for the Network Lock Manager. The tracing output is generated in the system log on the host where the NFS Lock Manager is running—the host that is exporting the NFS directory. The debugging values that are available are listed in /usr/include/linux/lockd/debug.h.

You can use decimal numbers that represent a bitmask that enables different types of tracing to these files by using the sysctl command or simply writing to the appropriate file. For example, the following commands activate all possible debugging for the NFS client:

```
# echo 65535 > /proc/sys/sunrpc/nfs_debug
# sysctl -w /proc/sys/nfs_debug=65535
```

If you think in terms of bitmasks, you can consult the appropriate kernel header files for the previous list. Personally, I typically find the NFS client and NFS server output to be most useful, and therefore begin with a value of 1023 because this activates most of the useful debugging without being truly overwhelming. I often test the client and the NFS server on the system that is running the NFS server by first starting NFS server process, and then attempting to mount one of its exported directories somewhere else on the same host. Once things work locally, you can move on to try get them working from a remote client.
