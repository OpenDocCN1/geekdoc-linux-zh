# CHAPTER 20: Adding Hardware and Attaching Peripherals

Support for a tremendous variety of hardware is a key issue for any desktop computer system. As computer hardware becomes more and more affordable, desktop users feel more comfortable adding cards and external peripherals to their computer systems, the extent to which an operating system supports all of this new hardware becomes increasingly important. An increasing number of devices are designed as external plug-and-play devices using interfaces like USB and FireWire are available at the local Best, CompUSA, or Stop-n-Go. People expect to buy these things, take them home, and find that they "just work." And rightly so.

All hardware requires pieces of kernel software device drivers in order to be accessed and used correctly by the operating system. This is true for the Microsoft Windows kernel, the Mac OS X kernel and the Linux kernel. The fact that CDs labeled Windows Drivers fall out of their boxes containing almost every piece of modern hardware might make you think that you'll have a problem using this hardware with Linux. After all, there is no companion coaster labeled Linux Drivers. What gives?

Luckily, the answer is that the device drivers for most hardware are already available as part of the Linux kernel as installed on your Ubuntu system. Device drivers are usually either compiled into the kernel or are available as kernel modules that are loaded when specific hardware is detected (hence, the generic term for on-demand drivers: loadable kernel modules). This is true for a vast amount of hardware—after all, in the open source world, all it takes is one motivated Linux user with driver development skills and a piece of hardware that "doesn't work right," and a working driver usually shortly thereafter.

## Part II: Ubuntu for Desktop Users

Although I am a fan of Ubuntu and a general Linux advocate, I cannot deny the lack of specific drivers can sometimes be a problem. To get the absolute performance out of some pieces of new hardware—most specifically, things like graphics and audio cards—you may need special drivers. Unfortunately, most hardware manufacturers are projected by sales numbers based on market analysis, and the Windows market is currently at least 50 to 100 times larger than the Linux market. This is why you get a Windows Driver coaster with almost all new hardware. Open source support for these high-performance drivers may lag behind Windows software, although more and more hardware manufacturers are providing Linux drivers in one form or another, only available for download from their web sites. They are also getting better in support for the Dynamic Kernel Module Support (DKMS) that was originally introduced by Dell in the Linux kernel, which is a big step in the right direction it can automatically download and update third-party drivers when you upgrade your kernel.

The good news is that, for the most part, drivers that are required for most new hardware come with your Ubuntu distribution. Some specialized drivers that are not open source or have licensing or other occurrences are available from updates of the Ubuntu repository such as the restricted, universe, or multiverse components, as discussed in Chapter 19. You may have to retrieve other drivers directly from a corporate web site. The bottom line is that, usually things will need "just work" with Linux.

This chapter explores using different types of hardware devices with your Ubuntu Linux systems, focusing on the types of hardware that most desktop and laptop users will be interested in. Hardware detection and support under Ubuntu and Linux in general are constantly improving. Regardless, when researching or buying new hardware, it's always a good idea to spend a bit of time in your favorite search engine, looking for information about Linux support for your hardware. More information is always a good thing, regardless of what the U.S. Government says nowadays.

## Adding a Printer

Most modern printers connect to your system via its USB interface, although some still connect to the classic parallel port. Regardless of the type of printer you are connecting to your system, the first things to do is connect to your system and turn it on. If it is a USB printer, you can verify that the printer is visible to your system by executing the `lsusb (list USB) command, which provides information like the following:

```
# lsusb
Bus 007 Device 001: ID 1d6b:0001 Linux Foundation 1.1 root hub
Bus 006 Device 001: ID 1d6b:0001 Linux Foundation 1.1 root hub
Bus 005 Device 003: ID 0048b:0055 Seiko Epson Corp. Stylus D88+
Bus 005 Device 001: ID 1d6b:0001 Linux Foundation 1.1 root hub
Bus 003 Device 002: ID 0d8c:0001 C-Media Electronics, Inc. Audio Device
Bus 003 Device 001: ID 1d6b:0001 Linux Foundation 1.1 root hub
Bus 002 Device 001: ID 1d6b:0001 Linux Foundation 1.1 root hub

```

Adding a locally attached printer has become incredibly simple thanks to the fact that most printers use USB nowadays rather than the classic parallel interface that many of us remember with varying degrees of freedom. Attaching a USB device to your system causes a recognizable event that your system can also initiate its configuration. The next few sections discuss what happens when you attach a new printer to your Ubuntu system, and how you can create or customize your printer's configuration, if necessary.

Earlier releases of Ubuntu enabled you to configure what would happen when a new printer was detected by your system. This was friendly but largely waste of time because the answer is almost always "Please configure the thing so that I can actually print on it."
