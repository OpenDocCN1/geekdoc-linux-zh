3. Execute the /usr/sbin/krb5_newrealm command to initialize the realm, entering a master keyphrase when prompted to do so. (This command runs the krb5_util command with specific options to create various configuration and data files that will be used by the Kerberos administration daemon.)

4. Next, create an administrative principal so that you can do remote administration by executing the following command:

```
kadmin.local -q "addprinc admin/admin"
```

After entering your password, the administrative principal for your Kerberos domain will have been created.

5. Next, start an interactive kadmin session (using the admin principal and the kadmin.local application), and add principals for your server (the host and kadmin servers are running on) and the first client that you will be testing with, your username, and the first client that you want to test with, in the following example:

```
# kadmin.local -p admin/admin
kadmin.local: addprinc -randkey host/server.local.network
kadmin.local: addprinc -randkey host/workstation.local.network
kadmin.local: addprinc username
```

In these examples, replace server with the name of your server, and local.network with the name of your realm. In my case, these would read like kerberos.wwh.org and ubuntu.wwh.org because I use kerberos as the hostname of my Kerberos servers. The add principals for the server and workstations use random keys when they are created (specified by the -randkey option) so no one will ever log in as those hosts, but you want them to exist as entities in the Kerberos database. You will be prompted for your password after creating a principal for a random key because you will actually want to log in at some point.

# Tip

When setting up kerberos for the first time and defining the principal for the user you will be using for testing purposes, I suggest that you initially set the password for your user principal to something other than your Ubuntu password. This is important to make sure that the authentication process on your client systems is actually using Kerberos—after doing so, you can delete your existing principal (using the kdelprinc command) and then create another with your standard password. ■
