# Problems After Adding IDE Drives to a SATA System

Most systems are configured to try boot from IDE drives before SATA disks. If you have added
IDE disks to a system that formerly only contained SATA disks, make sure that the sequence
in which your system tries to boot from different drives is correct. I had a humorous experience
a while recycling some old IDE disks for use on one of my SATA systems, because I
hn't wiped the IDE disks. I'd forgotten that one of them contained an older Linux
and was quite surprised when my Ubuntu system booted SUSE.

# Problems Related to SATA Drive Name Changes

Adding SATA drives to an existing system can temporarily cause boot problems for various var-\ious, the most among is because of how SATA drives are detected and named. SATA
drives not only use SCSI emulation (and thus have names beginning with /dev/sd*, but the letter
follows /dev/sd in their name is assigned based on the sequence number of the specific
SATA port that they are attached to. If whoever your system was careful, your primary SATA
disk will be attached to SATA port 1, and thus will always be the name /dev/sda.
whoever boot your system wasn't so careful and attached your boot drive to SATA port 4, your
system will boot with a single drive, but adding another SATA drive will cause that to
asigned the name /dev/sda, and your existing SATA drive will be called /dev/sdb. Adding
more than one new SATA drive will continue to make the name of your original /dev/sata disk.
this generally confuses the BIOS, as described in the previous paragraph, and certainly the
boot loader by Ubuntu systems, GRUB.

If you encounter this problem, there are two possible solutions:

+   - Open up your system again and connect your boot drive to the first SATA port on
your motherboard. This will guarantee that it will always be named /dev/sda.
may still have to change the BIOS settings, but you won't have to modify anything in
your drive's boot configuration files.
- Change the boot settings used by the Linux GRUB boot loader to reflect the new name
of your.

The first option is always preferable unless you have a very good reason for simply mod-
ifying the GRUB boot settings. If you insist on doing the second, and modifying GRUB, see the
