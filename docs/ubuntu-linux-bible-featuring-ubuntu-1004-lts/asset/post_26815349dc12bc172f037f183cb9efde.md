The traditional Linux/UNIX cp command provides options that make it easy to create a copy of a specified directory and to subsequently update only those that have been updated or do not already exist in the copy. For example, to back up all of the directories in /home to a removable drive mounted at /media/LACIE (LACIE is a popular manufacturer-prepackaged USB hard drives), you could use a command like the following:

```
$ sudo cp -dRpuvx /home /media/LACIE/home
```

The cp options in this command have the following meanings:

- - d: Don't dereference symbolic links, that is, copy them as symbolic links instead of copying what they point to.
- p: Preserve mode and ownership of the original files in the copies.
- R: Copy the specified directory recursively.
- u: Copy files only if the original file is newer than an existing copy or if no copy exists.
- v: Display information about each file that is copied. (You may not want to use this option, but it's interesting, at least the first few times you do this.)
- x: Don't follow mountpoints to other filesystems.

After running this command, you will have a copy of every directory under /home on your system in the directory /media/LACIE/home. You can then detach your removable drive and store it somewhere safe (preferably off-site). Any time you want to update your backup, retrieve the drive and update it at any time by simply rerunning this command.

# Making an Up-to-Date Copy of a Remote Directory using rsync

As mentioned earlier, rsync is a commonly used command-line utility that enables you to push or pull files to or from remote systems. The rsync program must be configured on the remote systems before you can push or pull files or directories to or from those systems.

To use rsync on an Ubuntu system, you must first ensure that the system starts rsync as a background process, and then also modify the rsync configuration file to add entries for specific directories that you want to be able to read from and write to. To enable rsync, edit the file /etc/defaults/rsync using your favorite text editor and a command like the following:

```
$ sudo emacs /etc/defaults/rsync
```

In the line that begins with RSYNC_ENABLE, change false to true, and then save the updated file. Next, create the rsync configuration file before actually starting the rsync daemon.

# Part III: Ubuntu System Administrators

Note
Most Linux systems use an Internet service manager as inet or xinetd to manage incoming requests for on-demand services as ftp, tftp, rsync, and vnc. These Internet service managers automatically start the daemon when an incoming request is received. Although these service managers are available in the Ubuntu repositories, they are not installed by default. On Ubuntu systems, a specific system startup file that starts rsync daemon is provided as /etc/init.d/rsync. If you install xinetd and want to use it to manage rsync requests, you will want to disable this file and create the file /etc/defaults/rsync.conf to make sure that the rsync service is enabled on your system.

The /etc/defaults/rsync file just determines whether rsync is enabled or not. The actual configuration information for rsync itself is stored in the file /etc/rsyncd.conf, which does not exist by default on an Ubuntu system. To create this file, use your favorite text editor and a command like the following:

```
$ sudo emacs /etc/rsyncd.conf
```

A minimal rsync configuration file that contains a definition remotely synchronizing the directories or on your system would look something like the following:

```
uid = root
transfer logging = true
log format = %h %o %f %l %
log file = /var/log/rsyncd.log
host allow = 192.168.6.255/3

[homes]
path = /home
comment = Home Directories
auth users = vwh
secrets file = /etc/rsyncd.secrets
```

The first section of this file sets parameters for how the rsync daemon runs. In order, the rsync daemon runs as root (uid), logs all transfers (transfer logging), a specific log file format (log format) and log file (log file), allows access from any host whose IP address is on the 192.168.6.x subnet (hosts allow). The second section of this file identifies a synchronizable entity known as home that maps to the directory /home on that system. Synchronization to this directory is done as the user vwh, password must be supplied in the file /etc/rsyncd.secrets.

After saving this file, use your favorite text editor to create the file /etc/rsyncd.secrets, with a command like the following:

```
$ sudo emacs /etc/rsyncd.secrets
```

This file should contain an entry for each auth users entry in the /etc/rsyncd.conf file, in this case, vwh. Each entry in this file contains the name of a user, a colon, and the plaintext password for your user, as in the following example:

```
vwh:hellothere
```

Next, save this file and make sure that it is readable only by the root user on your system using a command like the following:

```
$ sudo chmod 600 /etc/rsync.secrets
```

You can now start the rsync daemon using the following command:

```
$ sudo /etc/init.d/rsync restart
```

You can create a local copy of the /home directory on your system using a command like the following, where system-name-or-addr is the name or IP address of the system on which you have configured your rsync daemon:

```
$ rsync -Havz system-name-or-addr:homes /media/LACIE/home
```

The arguments to the rsync command in this example have the following:

- H: Preserve hard links if they exist in any directories that are being copied.
- a: Use archive mode, which preserves ownership, symbolic links, device files, and so on, and is essentially a shortcut that saves you by specifying several options.
- v: Be verbose, identifying each file that is copied or considered for copying. (You may not want to use this option, but it's interesting, at least the first few times you run rsync.)
- z: Use compression when transferring files, which improves throughput.

If you have problems using rsync, you should check the /var/log/rsyncd.log file (on the system that you are trying to retrieve files) for error messages and hints for resolving them. If you are not using the verbose option on the host where you are retrieving files, you may want to use it if you can identify (and resolve) any other errors that the host is trying to retrieve files is reporting.

# Installing and Using BackupPC

This section explains how to install, configure, and use the BackupPC package to back up a variety of hosts on your local network to a central Ubuntu server. Introduced earlier in this chapter, BackupPC is a great application that is both easy to use for a system administrator and empowering for any authorized user. Any authorized user can initiate backups of the machines that they have admin rights to and can also restore files from existing backups of those machines, all using a convenient Web interface.

If you have more than one machine on your home network, or if you're working in a multi-enterprise or academic environment, the BackupPC software is well worth a look. Its Web-based interface is easy to set up and use; various types of backups are easy to configure, initiate, and monitor; it can back up your Linux, UNIX, Windows, and Mac OS systems; and the fact that it doesn't require you to install any special software on the systems that you want to back makes BackupPC a great package.

BackupPC supports four different backup mechanisms (known in the BackupPC documentation as backup transports) to enable you to back up different types of systems. These are the:

- rsync: Backup and restore via rsync via rsh or ssh. This is a good choice for backing Linux, UNIX, or Mac OS systems, and you can use it to back up Windows systems that support rsync, such as the Cygwin Linux emulation environment.
- rsyncd: Backup and restore via the rsync daemon on the client side. This is the best choice for Linux, UNIX, and Mac OS systems that are running an rsync daemon. You can also use this mechanism to back up Microsoft Windows systems that support rsync, such as those running the Cygwin Linux emulation environment.
- smb: Backup and restore using the smclient and the SMB protocol to the backpc server. This is the best (and easiest) choice to use when backing up Windows systems using backpc, and you can use it to back up Mac OS systems using Linux and UNIX systems that are running a Samba server.
- tar: Backup and restore via tar, over ssh, or nfs. This is an option for Linux, UNIX, and Mac OS systems. You can also use this mechanism to back up Windows systems that support tar, ssh, rsh, and/or nfs.

A default backup transport value for all backups is set in the BackupPC configuration file, /etc/backupc/config.pl. The specific mechanism used to back up any particular host is identified in that host's configuration file, as discussed in the sections entitled "Defining a Backup Using rsync" and "Defining a Backup Using SMB."

Although backpc does a good job of backing up systems running Windows and Mac OS X, you should be aware of a few issues. First, backpc is not suitable for backing up Windows systems so that you can do a bare-metal restore. backpc uses the smclient application on your Ubuntu system to back up Windows disks, so it doesn't back up Windows ACLs and cannot open files that are locked by a Windows client that is currently running (such as, most commonly, things like Outlook mailboxes). Similarly, backpc doesn't preserve Mac OS file attributes. See http://backuppc.sourceforge.net/faq/limitations.html for a list of current limitations in backpc.
