Good examples of when you might need to increase filesystem size are simulation and image analysis projects or my research into backing up my entire CD collection onto my computer system. Without logical volumes, you could still add new disk storage to your system by formatting new partitions and mounting them at various locations in your existing filesystem, but your system would quickly become an unmanageable administrative nightmare of mountpoints attaching storage all over the place. With logical volumes, you simply add new disks to your system, add them to the appropriate volume group, and increase the size of the logical volume and the filesystem it contains, solving the problem quickly and easily.

The standard Ubuntu installation CD does not support creating logical volumes during installation. Creating physical volumes, volume groups, and logical your disk(s) during installation is only supported if you are installing Ubuntu from their alternate Desktop installation CDs or if you are installing the Ubuntu Server.

For more information about creating and using physical volumes, volume groups, and volumes after you have initially installed your system, see Chapter 20, "Adding Hardware and Attaching Peripherals."

# Local Filesystems: Standard and Journaling

Local filesystems are located on storage devices that are physically connected to your computer. Access to data on local filesystems is therefore fast because they are directly connected to your machine. On the other hand, local filesystems are useful only if you and other users who need access to the data that they can connect to the machine upon they are located. When you need access to data that is stored in a local filesystem, connecting to the machine upon which specific data is located generally isn't a problem in today's networked environments—you can always open an SSH (Secure Shell) or telnet connection to that, as long as specific machine is up and working correctly, of course.

The most common type of filesystem used on Linux systems is the ext2 filesystem (Version 2). I'll call this a "standard filesystem" because it works the most vanilla filesystems work. When you update a file, the changes to that file are written directly to the get. If your system goes down at that exact point, your changes may or not have been made to the target filesystem. The utility used to check the consistency of a standard ext2 filesystem is known as fsck ("file system consistency check"). The fsck utility traverses all of the data structures within a filesystem to make sure that all the data in the filesystem is associated with files and directories.
