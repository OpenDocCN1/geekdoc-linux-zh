## Installing Postfix and Friends

This section explains how to install the packages necessary for a simple Postfix mail server that automatically scans messages for spam and viruses and that users can access via the POP3 protocol. Postfix and related packages are installed in different ways depending on whether you are running a system installed from an Ubuntu Server CD or an Ubuntu Desktop CD. If you are installing an Ubuntu Server distribution, installing a mail server is a suggested option during the installation process, but this installs only the core Postfix package, not all of the packages that I suggest you install. (If you do not install a mail server when initially installing an Ubuntu Server distribution, you can subsequently install Postfix and related packages using apt or aptitude.) Otherwise, you can use any of the tools discussed in Chapter 19, "Adding, Removing, and Updating Software," (apt-get, aptitude, or the Synaptic Package Manager) to manually install Postfix and related packages. Ubuntu enables you to do things your way.

## Packages to Install

In alphabetical order, the packages that I suggest you install are the following:

- clamav: An antivirus package that scans incoming mail for attachments that contain a virus and quarantines those messages so that people don't accidentally invoke the problematic attachment
- mail: A package that contains a simple command-line tool for sending mail, which is used by many system utilities, but (in our case) is extremely useful for quick mail tests
- mailscanner: A package that scans incoming mail using a variety of spam detection techniques and discards any matching mail
- postfix: The Postfix mailer and all related utilities and configuration files

- postgrey: A greylisting implementation for with Postfix. - qpopper: A package that enables users to read their mail remotely, using the POP/POP3 protocol that is used by most MUAs

You don't have to install all of these, of course, but I'm going to assume that these are all installed in subsequent sections of this chapter.

Although the way in which you install applications is up to you, I suggest that you use Aptitude to take advantage of its ability to install packages as well as the basic packages required to run and support the Postfix mail server and related applications on your Ubuntu system. System and Aptitude will install all required packages but not get all of the bells and whistles associated with some of the recommended packages for Postfix. To install the Postfix mail server and related applications from the command line using Aptitude, execute the following command:

```
$ sudo aptitude -y -r install postfix postfix-doc postgrey \
mailscanner longterm qpopper clamav
```

Installing all of these packages, their dependencies, and recommended packages will require around 65 MB of disk space. After being prompted for your password, installation will begin without confirmation (because of the -y option), and away we go!

## Built-In Postfix Configuration Models

Regardless of whether you are installing Postfix and friends from the command line or graphically, you will be required to select a default configuration model during the installation process. Five different configuration models are built into the Postfix package, each of which sets up the Postfix configuration files in a certain basic way. The following are the configuration models:

- Internet site: Mail will be sent and received directly from this machine using SMTP Postfix. This is the default choice, and is probably the right choice if you are configuring an incoming and outgoing mail server for your domain and have a direct connection to the Internet.
- Internet site smarthost: This machine either receives mail directly from the Internet or from another machine using a utility as fetchmail, but sends mail through another mail server. This is probably the right choice if you want to run a home, Small Office, Home Office (SOHO), or Small or Medium Business (SMB) network with its own mail server but want to leverage your ISP or domain hosting company's
- **Local delivery only:** The machine only delivers mail locally, and does not send mail over any network. This is the right choice if you are setting up a system on which you want system status messages to be delivered by local e-mail, or a system shared by multiple users who need to exchange mail only between themselves.
- **No configuration:** The installation process will not modify the generic Post configuration files. You will have to make extensive manual modifications to them to get Postfix to work correctly on your system.
- **Satellite system:** This machine does not receive mail and forwards all outgoing mail to another mail server for actual delivery.

If you are setting up a system that doesn't match any of the pre-supplied configurations, it's probably best to select the default value, *Internet Site*, because this will provide a reasonable template that you can customize to match your requirements.
