# Tip

When using BackupPC to automated backups, the system logs show which user requested a remote sync operation. To do this, you would add this user (I usually use backuppc) to the auth users in the remote host's /etc/rsynccd.conf file and create an appropriate username/password pair in the remote host's /etc/rsynccd.secrets file. You would then modify the host-specific backuppc configuration file to use this username and password. I didn't do this here for simplicity's sake, but doing would provide more accurate log data on the client system. ■

If the system uses an rsync binary other than the default /usr/bin/rsync or the rsync program is listening on a port other than the standard port (873), you should add configuration definitions for these to the host-specific configuration file. The default settings for the associated configuration parameters are:

```bash
$Conf(RsyncdClientPort) = 873;
$Conf(RsyncdClientPath) = '/usr/bin/rsync*';
```

## Part III: Ubuntu for System Administrators

The last step in creating a host-specific backup definition for backuppc is to cause the backuppc process to reread its configuration data, which you can do by explicitly reloading the configuration, by explicitly restarting the backuppc process, or by sending the associated process a hang-up (HUP) signal. You can force backuppc to reload the configuration file by using the following command:

```bash
sudo /etc/init.backuppc reload
```

The definition for your backup host can now be selected via the BackupPC Web Interface. At this point, you can follow the instructions in the section entitled "Starting Backups in BackupPC" to back up this host.

The example in this section only backs up the directories of users on the remote machine. To recursively back up other directories, you would create other synchronization entries for those directories in the remote host's /etc/rsync.conf file and then add entries for those synchronization entries to the host-specific configuration file. For example, to back up synchronization entries named /, /homes, and /boot, you would change the host-specific RsyncShareName entry to look like this:

```bash
$Conf(RsyncShareName) = ['/', 'homes', '/boot'];
```

If you have multiple filesystems or you may create a custom set of arguments to the rsync command in the host-specific configuration file. This enables you to add options such as --file-system, which causes backuppc to back up each filesystem separately, simplifying restores. You can also add options to exclude directories from the backups, which you will certainly want to do if you are backing up a system's root directory (/), in the following examples:

```bash
$Conf(RsyncArgs) =
# original arguments here
--one-file-system
--exclude, '/dev/
--exclude, '/proc/
--exclude, '/media/
--exclude, '/mnt/
--exclude, '/last+found',
```

These settings would prevent backups of /dev, which contains device nodes and is dynamically populated at boot time on Linux systems; /proc, which is the mountpoint for a memory filesystem that contains transient data; directories such as /media and /mnt on removable media is often temporarily mounted; and /last+found, is is directory used during filesystem consistency check. You can also exclude directories from rsync backups using the BackupFilesExclude directive, as in the following example:

```bash
$Conf(BackupFilesExclude) = ['/dev', '/proc', '/media', '/mnt', '/last+found'];
```

The backuppc program reads the configuration settings in /etc/backuppc/config.pl first, and loads host-specific configuration settings, which enables the /etc/backuppc/config/.pl file to provide default settings for all backups. After you have used backuppc for a while and are comfortable with various settings, you may want to consider modifying the default settings in the /etc/backuppc/config.pl file for configuration variables as $Conf(RsyncArgs).
