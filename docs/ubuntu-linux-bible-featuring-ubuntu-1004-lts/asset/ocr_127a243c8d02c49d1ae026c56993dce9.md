# Tip

If you neglected to enable GRUB boot menu at the beginning of this section, you can resolve boot problems by booting from an Ubuntu Live CD, mounting the partition that contains your system's /boot and /etc directories, and execute the chroot command to temporarily direct the root where you mounted your root filesystem. You can then make the modifications suggested at the beginning of this section and run the update-grub command to update your system's boot files. You can then exit the chroot shell, unmount the specified partition, and reboot your system. You should then see the GRUB menus, and be able to take advantage of the suggestions given in this section.

# Problems After Adding PATA/SATA Drives to a SCSI System

The last common problem that you may encounter when adding SATA or PATA drives to a system that boots from SCSI disks. Both PATA and SATA drives are also named free disks during the kernel process. The combination of these two facts means that adding one or more/ SATA disks will cause your SCSI disk to be renamed. For example, if your system was configured to boot from the real SCSI disk, /dev/sd, and you add two SATA drives, the name of your SCSI disk will now be /dev/sdc. This leads to a set of BIOS and GRUB boot loader problems discussed earlier in the "Problems Related to SATA Drive Name Changes", but you will have to solve them using the solution described in the section, "Temporarily Changing GR Boot Loader Information.\ See that section for an explanation of how to modify your GRUB settings and resolve this sort of problem.

# Locating, Partitioning, and Formatting New Drives

After rebooting your system to locate new internal drives, you'll probably want to use the storage for those new disks provided. This requires that you identify the Linux device nodes associated with them, and use various software packages to partition them and format those partitions using your filesystem of choice.

# Note

As you might expect, there are some great command-line utilities for displaying information about the disks that are attached to your system, partitioning them, and formatting partitions so that they contain a filesystem you can mount in order to use the storage. Unfortunately, today is not so good for graphical utilities that enable you to do the same sorts of things. Earlier releases of Ubuntu featured graphical utilities like the Administration menu (which you could access via the command line as disk admin), but it is no longer provided on Ubuntu systems, and its most likely replacements, Disk Manager (http://fertomerens.free.org/disk-manager/index.html or GNOME Partition Format, are not part of the Ubuntu distribution.

The next three sections explain how to use the GNOME Partition Editor and command-line utilities to figure out which drives are attached to your system, the partitions they contain, and how to partition or re-partition those drives, and how to format those partitions.
