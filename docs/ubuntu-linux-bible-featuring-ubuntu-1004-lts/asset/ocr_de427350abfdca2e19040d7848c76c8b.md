# NDIS Wrapper Tips and Tricks

As you can see from the previous section, many Microsoft Windows drivers "just work" with the ndiswrapper kernel module when installed correctly. Unfortunately, some don't. I won't pretend to have tested every piece of wireless hardware and its associated Windows drivers (though I'd be happy to try if you just sent me a sample of the hardware that I can keep), but I used many different ones with a wide selection of wireless hardware when configuring laptops for a variety of customers, coworkers, and friends.

For one, the most frustrating sets of experiences has been with a variety of LinkSys WPC54g wireless PCMCIA cards, all of which I have gotten working, but only after significant driver gymnastics, head scratching, Google searches, and commiseration with fellow demons (I was originally planning to title this section "The LinkSys WPC54g, or I Spent My Summer Vacation," but I am trying to generalize what I've learned rather than provide a single set of instructions). By these, there are great cards that 802.11g (and 802.11b), because I typically find LinkSys hardware to be inexpensive and reliable, I often recommend them to friends. Unfortunately, a huge problem with these cards is that LinkSys has used a variety of wireless chips over the years, so they often use different drivers, each of which requires its own to get it working with the ndiswrapper module.

One key is to make sure that you have the right Windows drivers in the first place. For example, some of the 54g cards use a Realtek 8180 chip, and therefore, only work with these drivers. Others use Texas Instruments AXX 1ich xx chip, while others are rumored to use a Marvel BCM43xx. If you can't identify the chipset by reading the product literature, you can usually identify it by using the llsp tool to list all the PCI devices on your system and scanning the llsp output for anything identified as a wireless controller.

As an example of driver and chip weirdness, the Texas Instruments AXX 1ich xx chip is directly supported by Linux, using the acx and ax_pci kernel modules (ndiswrapper module required, although I prefer the ndiswrapper approach), but often requires you to play around with different versions of the मुद्दे in /lib/firmware/kernel-version/acx until you find the right version and name (see the Ubuntu Forums for some suggestions). If you use the ndiswrapper version of the 54g driver with ndiswrapper, you have to blacklist the standard Linux kernel modules by adding their names to /etc/modprobe.d/blacklist so they are not loaded during the hardware detection phase of the boot process.

If you're sure you have the right driver but still can't get it to work, the Linux dmesg command to display recent kernel messages for error messages related to the ndiswrapper, the card you're using, or any of the chips mentioned in the previous paragraph. This can help identify specific problems.
