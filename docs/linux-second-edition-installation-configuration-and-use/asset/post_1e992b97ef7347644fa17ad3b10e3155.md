# Changing key assignments with xmodmap

xmodmap allows you to change the assignment of a key and the character generated by pressing it. With Free86 X servers, the use of xmodmap is required only in exceptional cases - for example over the everlasting Backspace / Del.
With xmodmap -pke, the current keyboard table is displayed in the syntax required for xmodmap. xmodmap file processes the definitions in the file. xmodmap -e definition allows you to redefine a single key. Application examples can be found in the following subsections:

# Backspace and Delete

Once upon a time there was a computer which had a keyboard without a Del. In those days, computer users had modest expectations: they were glad that they could correct their input at all and were happy to put up with Backspace. This is when the first version of Unix saw the light of day. Since then, ever has gone by. Computers became more powerful and keyboards more user-friendly. Yet, the difference between Backspace and Del proved to be such an obvious problem that even genius found no solution. And as long as Unix (and Linux) are alive and well, users will still have to suffer...

After this obviously many may use the xkey program to check how X reacts to various keys being pressed. In many (older) Linux distributions you will find that Del and Backspace lead to the same Keysym text 'Delete'. This is the character that is passed to X programs when a key is pressed. Thus, there is no wonder that X programs are undifferentiable between Del and Backspace.

In order to make differentiation possible, xmodmap must be used. The following instruction ensures that, in future, Backspace results in the Keysym 'Backspace'.

Depending on the distribution, you will find xinitrc in /etc/X11/xinitrc or in /usr/X11R/Lib/X11/xinitrc. If the home directory contains the file .xinitrc, it takes precedence over the global option.

The internal key numbers used in text mode (for loadkeys and shawdey) and under X (for xmodmap and xev) do not correspond! In text mode, the Backspace key is number 14, under X 22.

For more advanced X programs, this instruction is sufficient and BackSpace works satisfactorily. Other programs will not know what to do with BackSpace and continue interpreting the Delete string as BackSpace. With such programs, a modification in ~/.Xdefaults or ~/.Resources sometimes wonders (see also page 248).

# Keys in text mode programs

Even under X, you will often find yourself working with programs that were designed to be used in text mode (jed, pine, and so on). For such programs, the above instruction is of little use. The weirdest comes on the effect of the jed editor: Backspace calls the online help, and Del.

Under X, text mode programs are executed in a terminal or shell created by the xterm. This allows you to achieve correct support for nearly all traditional programs with a single change in the xterm. Simply insert the following lines into ~/.Xdefaults or ~/.Resources file depending on the distribution:

```
! in ~/.Xdefaults or ~/.Resources
VT100.Translations: override |
<Key>+Backspace: string(0x7f)\n<Key>+Delete: string(0x04)

<Key>+Home: string(0x01)

<Key>+End: string(0x05)
```

This setting refers to the VT100 window which is, however, the bezier of a line. The Keystring string Backspace is substituted with character code 127 and the Keystring string Delete with character code 4 (this corresponds to Ctrl+D). Following the same pattern, Home can be assigned to Ctrl+A and End to Ctrl+E, so that these keys can be used, as in text, to jump to the beginning or end of line.

Thus, the four keys are interpreted correctly by a large number of programs. These settings have also been tested with Emacs in text mode (acs -nw), with jed, bash, and so on.

In order to force the X version of Emacs to recognize Backspace and Del, you must include the following line in ~/.emacs:

```
; in ~/.emacs
(global-set-key [delete] delete-char)
```

# Direct keyboard settings via xmodmap

If you only work with conventional programs under X, there is yet another solution: you could use xmodmap to assign the keys Backspace, Del, Home, and End to the 0x7f, 4 and 5 (instead of Backspace, Delete, Home).

```
# in xinitrc (this is not recommended at!)
xmodmap -e keycode 22+=0x7f # <Backspace> yields 127
xmodmap -e keycode 107+=0x04 # <Del> yields Ctrl+D
xmodmap -e keycode 97+=0x01 # <home> yields Ctrl+A
xmodmap -e keycode 103+=0x05 # <End> yields Ctrl+E
```

Text mode programs executed under xterm or another terminal will receive the character codes they already know from text mode. However, X programs will also receive the character codes above and will not know how to handle them (apart from few exceptions). Therefore, this solution must be considered a dead end.

# Global key combinations

When working under X, the following key combinations usually apply:

- Ctrl+Alt+Backspace switch to console
- Ctrl+Alt+Fn (e.g., F7) switch back from text console to X Window System
- Ctrl+Alt+/ change graphic mode

The key combinations Ctrl+Alt+Backspace, Alt+F7 and Ctrl+End can be deactivated by the means of the keys Zap and Zoom in the Server section of XF86config.

Under X, the key combination Ctrl+Alt+Del cannot be used to reboot Linux. For a restart, you either have to switch to a text console and press Ctrl+Alt+Del there, or use the command shutdown -r now in a terminal window.

Further keyboard shortcuts are defined by the active window manager — see 262.

# Input focus

In the Window System, several programs can run simultaneously – but only one program at a time can accept input from the keyboard. Depending on the window manager configuration, either the program that was clicked is considered to be active, or the one that is currently under the pointer. It is mainly the second variation that causes people to use MS Windows. The remedy is a different configuration of the window manager – see page 276.

The ways programs administer the input focus within one window (for example the SEARCH command in xman) appears even more unusual: input can only be made in the field where the mouse pointer is situated. Since the input fields are often rather small, a tiny shift of the mouse is enough to send your input into oblivion. For this reason, many recent programs follow Motif’s behavior, where the input focus is fixed in a field by a mouse click.

# Configuring the mouse

If you use an XFree86 X server, the Pointer selection in XF86Config is responsible for mouse configuration. The two most important options, Device and Protocol, specify the interface to which the mouse is connected (usually /dev/mouse or /dev/tty30) and protocol from the following list the mouse uses: BusMouse, Logitech, Microsoft, MMServices, Mouse, MouseSystems, PS/2, Xqueue, and OS-Mouse. In case of doubt, you will have to experiment. However, please remember what you learned during your gpm configuration (page 141).

If you have a two-button mouse, you can use Emulate3Buttons to specify that simultaneous pressing of both mouse keys can be used to emulate the missing third button. Emulate3Timeout specifies the delay with the pressing of single keys is processed. Some Logitech three-button mice only work when ChordMiddle option is used.

```
# Mouse setting in XF86Config
Section "Pointer"
Protocol "Microsoft"
Device "/dev/mouse"
Emulate3Buttons # only for 2-button mice
Emulate3Timeout 50 # delay in ms
ChordMiddle # only for some Logitech 3-button mice
```

# gpm as a mouse server

There are some very exotic three-button mice on which all three buttons work under gpm, but only work under X. In such cases, gpm can be used as a server – that is, gpm continues to be responsible for mouse control and passes the mouse events to X. To do this, you must start gpm with the additional option -R. Then, gpm creates the file /dev/gpmdata. Communication with X is carried out via this FIFO file, that is, the file must be specified in XF86Config as a device, and MouseSystems must be specified as the protocol. Do not forget to deactivate Emulate3Buttons.
