Symbolic links can be created not only for files but also for directories. This fact can cause some confusion, as it may look as though directory trees are doubled via a symbolic link. In practice, the directory link is only an additional path to the same files and subdirectories.

An example: BibTeX is installed in a fairly jumbled directory structure. If you want to access BibTeX2 in a simpler way (and without specifying six subdirectories), you define the following link:

```
user$ -s ../usr/lib/texmf/texmf/tex/latex2e
user$ -l latex2e
lrwxr-xr-x 1 user 30 Oct 4 17:20 latex2e ->
/usr/lib/texmf/texmf/tex/latex2e
```

Via the link directory latex2e, you can now easily access all files contained in /usr/Tex/lib/texmf/latex2e. A last hint: if you want to view the contents of latex2e, you will need to indicate the sub directory separator as (latex2e/) instead of latex2e).

```
user$ -l latex2e/
total 35
lrwxr-xr-x 2 root root 1024 Nov 6 18:09 algorithm
lrwxr-xr-x 2 root root 1024 Nov 6 18:09 amfonts
...
```

Generally, you should try to specify relative paths in links, not absolute ones. In this way you might prevent problems that arise from mounting directories via NFS or from relocating directories. If the above link command is be executed by root in the home directory, a relative path specification would look like this:

```
root# cd /root
root# ln -s ../usr/lib/texmf/texmf/tex/latex
```

In practice, symbolic links are almost exclusively used – not only because of their more flexible handling, but also of their greater intelligibility; with ls -l you can easily check a symbolic link points to. With hard links, this is much more difficult.

# Links to programs

Under Linux, several commands, which may work in totally different ways, may often point to one and the same program via symbolic or hard links (to execute ls - /usr/bin!). Although the same program is executed every time, the program behaves according to the link that you used to call it.

The explanation is quite simple: at the design stage, the different ways to call the program were already built in. Each time the program is executed, a check is carried out to see which command name was used to call up the program. If the name is recognized, the program starts the corresponding routines, otherwise it reacts with

an error message.
