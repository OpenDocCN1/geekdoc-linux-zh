
The detour via dvips is also recommended when a single page contains more than 16 different typefaces (this causes dvips to fail) or when the LaTeX text uses PostScript typefaces. gs cannot exactly represent PostScript typefaces either, but it still supplies better results than dvips.

If you want to print out *.dvips files containing PostScript character sets, you should take the detour via dvips and gs – the result will definitely be better. dvips relentlessly replaces all PostScript character sets with a 10-point LaTeX typeface.

dvips possesses a very detailed man page. You will find information about the remaining options and how to obtain a double-sided printout (by first printing the odd pages, and then the even pages on the reverse side of the sheets you have just printed).

## PostScript $\rightarrow$ printer format conversion (gs)

Ghostscript (that is, the gs program) can convert PostScript documents into a large number of printer formats (including a fax format). When LaTeX sets are used in the PostScript document, there is no loss of quality, if PostScript character sets are used, gs must employ the character set files of /usr/lib/ghostscript/fonts instead, not all of which can match the quality of the original fonts.

```
gs [options] postscript.file [quit.ps]
```

In order to make gs function correct, at least two options must be specified: sDEVICE= set the output format and -outputfile= specify the file into which the result is written. As a rule, it is also reasonable to use the options sPAPERSIZE=4 and -DOPAUSE.

- -dNDISPLAY suppresses the display of various messages on screen. Also, it is no longer necessary to confirm the completion of each page with --.

- -dSAFER all files are exclusively opened as read-only. This option must be used when gs is used as a filter (for example, for a print spooler).

- -q suppresses various status messages (quiet).

- -resolution sets the graphics resolution. This option is necessary for conversions into the format of various dot matrix printers.

- -sDEVICE= specifies the format into which gs is to convert the PostScript file. A list of all possible formats can be obtained with gs -h. Amongst the most important formets as desktop, djet500, lserjet, ljet3, ljet4, necp6, bj10e and bj200 ibmpro. PostScript files which contain only one page (one image) can also be converted into various graphics formats, such as tiff3 or png256. A conversion into ASCII text is not possible.

```
-sOutputFile=file.name
```

writes the result of the conversion to the specified file.

```
-sPAPERSIZE=size
```

specifies the paper size of the output. In most cases, a4 must be used, otherwise gs defaults to the American letter size format which is slightly smaller.

gs works interactively and comes up with an input prompt after processed last page. In order to make it clear to gs that the conversion is over, you yust enter Ctrl+D. If you want to avoid this input, you can specify a second file called quit.ps which is loaded from /usr/lib/ghostscript/ and only contains the t'quit'.

The following instruction converts test.ps into the HP LaserJet 3 format. The results is written to test_out.ps gs to be terminated immediately-afterwards.

```
gs -sDEVICE=ljet3 -soutputfile.ps \
  > -sPAPERSIZE=64 -dMOPAUSE test.ps
```

gs exists in various versions which are subject to different copyrights; the most recent version is 'Aladdin Ghostscript n'. Although this version is freely available on the Internet, a commercial distribution (such as in Linux distributions) is only possible with a license agreement. Older versions, after a while, get the name 'GNU Ghostscript n'. They are subject to the GPL, that is distribution (almost) unrestricted. Depending on the agreement with Aladdin Enterprises, Linux distributions are therefore partly shipped with Aladdin and partly with Ghostscript.
For the end user, GNU Ghostscript has the disadvantage that the latest drivers are not yet implemented. Up-to-date information on the different Ghostscript versions can be found on the Internet:

```
http://www.wisc.edu/ghost/
```

> The man text for gs is fairly comprehensive. In addition, the directory /usr/share/ghostscript/n/n/doc contains further information about the internals of GhostScript.

## Formatting texts (groff)

groff is a higher-level system used to format man texts, among others. In practice, groff programs play a secondary role – with exception: groff is used to format man texts which become easily readable ASCII texts. The groff programs taken together constitute a typesetting system, comparable to LaTeX, but less sophisticated in its formatting capabilities and therefore easier to handle.

The following description of groff explains only those options that convert man sources into DVI or PostScript files.

```
groff [options] file > target.file
```

- -maname uses the macro file tmac.name in /usr/lib/groff/tmac directory. For conversion of man texts, the name used must be mandoc.

- -Tformat determines the output format. Default setting is ps for PostScript. Other settings are dvi (for dvi files), ascii for ASCII texts, and latin (with language characters).

If a man text is present not only in its formatted version, but also as source text, groff can be used to convert this file into a high-quality PostScript file man sources can be found in the man directories (x stands for 1 to 9, n, g), for example in /usr/man/manx. The following command converts the man source file groff.1 into PostScript format and writes the result into the file test.ps in the home directory:

```
user groff /usr/man/man1/groff.1 -mandoc > /book/test.ps
```

The same result – although without extensive control possibilities – is achieved with the following command:

```
man -t groff > /book/test.ps
```

> NOTE: In Linux distributions, the man texts are only available preformatted, so groff cannot be applied. In such cases, the rman command allowed the man page to be converted into another.

## Formatting info texts (Texinfo)

info texts are created by means of Texinfo. The great advantage of the Texinfo system is that the source files (extension *.texi) can be used to create both info and a DVI file. The resulting *.dvi files can be converted into PostScript files by means of dvips and subsequently printed. Thus, *.texi files are suited for both creation of online documentation and generation of typographically excellent manuals.
