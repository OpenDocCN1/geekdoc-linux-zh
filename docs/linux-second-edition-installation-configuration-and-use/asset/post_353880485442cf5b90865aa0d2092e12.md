The first tin obstacle might already be the start. Depending on how the program is compiled, it will display a few error messages at start-up (which might not even be visible in xterm) and quit immediately. In this case, it expects a news archive in `/var/spool/news/`, as it would be created by the server.

tin can read an archive without contacting the server. However, this rather exotic feature fails if no local server exists at all or a different local server (for leafnode) is used. Try to start tin with the option -r like this:

```
user$ tin -r
```

# Usage

At the first-start, tin transfers a list of all known newsgroups from the server into the local .newsrc. If the Internet connection to the server runs only via a modem, this will take several minutes. (The waiting time occurs only at the first-start.) Subsequently, tin displays the empty list of subscribed newsgroups.

Press Y to display the long list of all unsubscribed newsgroups. Now, you can use the cursor to move to the required newsgroups and subscribe to a single group with S or you can use Shift+S to subscribe to all groups that match a given pattern. For example, you can enter os.linux.* to select all Linux groups. Press Y once more – the screen should look more or less as follows:

```
Group Selection (localhost)               h=help

32 comp.os.linux.hardware
92 comp.os.linux.misc
3 comp.os.linux.networking
2 comp.os.linux.x
```

```
<=set current to n, TABnext unread,/search pattern, clatchup,\goto, jline down, kline up, help, move, quit, toggle all/unread,
subscribe, job pattern, unsubscribe, Unsubscribe pattern, yank in out
```

The numbers in the second column indicate how many articles you have not yet read. In order to read the article in a newsgroup, simply move the cursor into that line and press -. Now, the structure of the screen will look like this:

```
2zfck signals error. Disk defective? Joerg Mertin
2 + 2 MC in color? Kai Straube
4 + 3 - no daemon present Joachim Zob
6 + 2 Problems with kernel compilation Stefan Lange
```

The second column needs some explanation. If it contains a number, we have a thread containing n unread articles. With the cursor keys, you can select an article or a thread. With you can read the article. It takes you to the next article, back to the list. Once an article has been read, the plus sign or the threading number is removed. When you quit the list and visit it again, read articles are no longer displayed at all.

If you want to have a second look at an article you have already read, you must use Z to mark the whole group as 'unread'.

The following list summarizes tin's most important keyboard shortcuts. Please note that some shortcuts only apply in some windows (for example

# tin keyboard shortcuts

- + ↑ previous/next article or group
- - → read newsgroup or article
- ← back one hierarchy level
- Tab jump to the next unread article
- / search for text

# Processing news

- + F send the newsgroup a reply (follow up) to the article as a new article
- R send a reply to an article as email directly to the author (in the article window)
- W write new article
- T mark an article
- M send (marked) articles or threads as email
- S store (marked) articles or entire thread in a file
- C mark all articles in this group as 'read'
- Z mark all articles in a group as 'unread'

# Processing groups

- + S subscribe to the group
- Shift+S subscribe to several groups (with pattern) (the group must be visible, press Y beforehand)
- U cancel subscription to a group
- Shift+U cancel subscription to several groups (with pattern)
- Y show all commands or only subscribed newsgroup

Many additional commands are described in the very informative man text. Online help can be called with H, but only displays a list of keyboard shortcuts. Depending on the distribution, further information can be found in /usr/doc/tin/.

You can speed up the start-up of tin by using the option -nq. In that case, only considers the already subscribed groups. It is not possible to subscribe to additional groups, nor does tin check whether newsgroups become available on the server.

# Configuration

tin can be extensively configured. You can either modify the file /.tin/tinrc directly or call the configuration dialog from inside the program with Shift+M. Besides other things, this allows you to activate colors and mouse support.

# Editor

tin has no editor of its own and starts vi as its default editor. You can prevent this by setting the EDITOR or VISUAL environment variables appropriately.

# Sender's address

tin normally employs the user, host name, and domain name to build the sender's address. In an offline configuration, this is only rarely a good solution; the email address of the Internet account should be used. For this purpose, a modified sender's address can be set with Shift+M (option mail_address in tinrc).

> CAUTION As you know, the modified sender's address is only valid for news articles, not for email sent via REPLY. You should use your email program to reply directly to news articles.

# 11.3 Offline news configuration (leafnode)

leafnode is a news server specially optimized for small news archives (a few dozen groups maximum). Thus, leafnode is particularly suitable for managing news archives on private computers.

> TIP You can find the most up-to-date version of leafnode on the Internet: http://www.wuerzburg.de/~krasel/leafnode.html

# Installation and configuration

By now, many distributions supply leafnode as a preconfigured package in the contrib directory. If not, you will need to download the fairly small package from FTP server. The information in this chapter refers to version 1.8, but should also be valid for versions after 1.8 (Leafnode 1.7 is defective and should not be used!)

# config

The configuration of leafnode is carried out in the config file, which is normally located in /usr/lib/tin/config or /etc/leafnode. The most important setting in this file concerns the news server or news servers from which leafnode is supposed to read news articles. For the sample user from page 305, this is news.provider.de. The keyword expires for how many days unused news threads should be kept on the server. The default setting is 20 initialfetch specifies how many news articles are to be read the first time after subscribing to a newsgroup. If you do not set a limit, leafnode will transfer all available articles—and that may age!

maxfetch is valid for current operation. Each time leafnode searches for new articles a maximum of this number is transferred. If you only rarely (say, once a week) transfer news articles of a popular newspaper for example comp.os.linux.misc, select a high value—otherwise your local news archive will be incomplete. Too high a value is also not a good idea—transfer of many news articles takes quite a long time. As a rule of thumb transfer of two news articles per second is a realistic value. The config file supplied with Leafnode is well commented. check where binaries are located

# /etc/ntpserver

This file specifies which server should be contacted by local clients. Since leafnode is now running on your computer, you will need to enter localhost.

# SNNTPSERVER

This environment variable is evaluated by some news clients and must therefore be set to localhost. (In SuSE, you set NNTPSERVER in the file /etc/rc.config)
