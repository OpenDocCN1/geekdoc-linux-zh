## KDE internals

### rc files

Most KDE programs store status settings (font size, options, and so on) in the file /.kde/share/config/name. This is a text file which is structured similarly to the *.ini files known from Windows 3.1. The program icons displayed on the KPanel, for example, are stored in ~/.kde/share/config/kpanelrc. By the way, the name of the files containing the screen saver settings are not namerc, kssrc.

### Application-specific directories

Some KDE programs have so much configuration data that a single file would be too unwieldy. Programs usually create a separate configuration directory in ~/.kde/apps, for example ~/.kde/apps/klynx.

### kdelink files

Links to or objects represented as icons in KDE (on the desktop, in the start menu, on the panel), are stored in text files with the extension .kdelink. For example, the whole KDE start menu consists of a number of directories that contain .kdelink files (path/opt/kde/share/appink). In the file .kdeink directory takes the role of the .kdeink file.

.kdeink files can contain a lot of information, for example, the object names in several languages, the name of the icon, information regarding the file type, and so on. KDE recognizes several object types for .kdeink files: programs, directories, devices (links to devices or partitions), FTP and URL links, and MIME data types.

## The KDE display manager (kdm)

If you want be greeted by KDE dialogs immediately after computer start-up, you can use the KDE display manager kdm instead of xdm (page 270). This program allows a very easy login. You can even select your window manager. Configuration of kdm is carried out in the KDE control center APPLICATION/DESKTOP MANAGER. (However, individual options described in the online documentation have to be set directly in kdmrc.)

With the LOGOUT button, you can initiate a shutdown at a request for confirmation (that is, you can terminate Linux).

> In SuSE, you can use vast to set the environment variable DISPLAYMANAGER for kdm. With this, kdm (instead of xdm) is automatically used in runlevel 3. In other distributions, you need to modify the corresponding Init file yourself (usually /etc/rc.d/init.d/xdm or /etc/init.d/xdm).

## Survival rules

- In contrast to KDE, icon actions (such as the start of a program) are triggered by a double click.
- In many programs or GNOME components, the right mouse button can be used to call a context menu.

Nearly all GNOME programs can handle drag & drop. You can, for example, drag a text file out of the file manager and drop it onto the editor (gedit) or move icons from the start menu. In addition to the left mouse button, press Ctrl, copy the object. The responsibility for management of icons lies with the file manager. This program must therefore be started first in order to use icons on the desktop.

GNOME programs can usually be configured via menus. (Some GNOME components are configured in the GNOME Control Center – see below.) Usually, it is also possible to change configuration files manually, but this is seldom needed – if example no configuration dialog exists for your particular option.

Do not enter GNOME with Ctrl+Alt+Backspace. Instead, use the LOG OUT command of the Start menu. Then GNOME stores information about currently running programs and tries to restore the current state as precisely at the next GN start-up. (However, this only works satisfactorily with some programs.)

Although GNOME facilitates the handling of programs in many regards, there are obviously some flaws, such as the unsatisfactory keyboard support. Quite a large number of operations can only be executed with the mouse. In many programs, it is not even possible to call menus with Alt and the initial letter.

## Configuration

GNOME provides an incredible number of possible configurations. Invest some time in experimenting – it will definitely be worth your while! Working is much more pleasant when the desktop is configured to the user's personal preferences.

Important GNOME components are configured via the GNOME Control Center. This program is started via the Start menu of the GNOME panel: SYSTEM | GNOME CONTROL CENTER. Its handling is so easy that no further explanations are needed at this point.

Language

The GNOME Control Center provides no separate entity for setting the required language for menus, dialogs, and so on. The system setting of the environment variables LANG and LC_ALL is evaluated. (These variables are best set in /etc/profile).

Window manager

All settings that do not directly concern GNOME, but the window manager, must be set by the window manager's own configuration program or by direct modification of its configuration file.
