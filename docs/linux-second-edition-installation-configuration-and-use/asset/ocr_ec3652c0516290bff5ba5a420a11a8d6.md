# Bus DMA mode

The bus DMA mode allows a particularly efficient data transfer between EIDE hard disks and main memory. Transfer is not carried byte by byte via the CPU, but via a DMA (Direct Memory Access) channel. A direct temporary connection is established between hard disk and main memory; the transfer is controlled by the DMA controller. The advantages of the bus master DMA mode are obvious: the data rate is significantly higher; at the same time, CPU load for loading/saving of large files is reduced because the DMA controller and not the CPU are looking after this.

For you to be able to use the bus DMA mode, both your motherboard and your hard disk must support this mode. Nowadays, this is the case with many modern motherboards (for example, with the Inter Triton chip set) and hard disks. With regard to motherboard support, you are advised to read the corresponding manual and check the kernel messages displayed during booting and by the dmesg command:

```
root# dmesg
...
PIIX4: IDE controller on PCI bus 00 dev 21
PIIX4: 100% native mode; will probe irqs later
ide0: B-DMA at 0xc800-0xc807, BIOS settings: hdc:DMA, hdd:pio
ide1: B-DMA at 0xc808-0xc8ff, BIOS settings: hdc:DMA, hdd:pio
```

Whether your hard disk supports DMA transfer can easily be found out by the first EIDE hard disk:

```
root# hdparm -i /dev/hda
...
DMA=yes, maxDMA=2(fast)
```

A prerequisite is the availability of the corresponding kernel module. (Kernels supplied with current distributions fulfill this requirement. In other distributions, you may need to recompile the kernel, setting the Intel 82371 PIIX DMA support option in the Floppy. IDE. other block device option group to Y or M.)

> CAUTION Even if all three requirements are met, the DMA mode is often not activated automatically for safety reasons; depending on the chip set, the length of the hard disk (according to the specification, a maximum length of 45 cm is allowed), and so on. the DMA mode may lead to reliability problems. For this reason, DMA mode experiments should be carried out with extreme care: execute upon for all partitions that are not needed! Ideally, you should have a separate partition available for your DMA tests which does not contain any valuable or unsaved data.

Whether the DMA mode is already active can be determined with hdparm -d /dev/hda-
root# /dev/hda:
using_dma = 0 (off)
