
# Distributing Linux file systems across several partitions

In the installation chapter (see page 38) we discussed the advantages of installing Linux in two or more partitions. In particular, this is a good way to achieve a fairly strict separation between the Linux system proper and your personal data.

How can a second Linux partition, created with fdisk during installation, be mounted into the file system? The first step is to use mkfs -t ext2 (or briefly mk2fs) to create a file system in this so unformatted partition.

The creation of additional Linux partitions is a far-reaching intervention in the Linux system. If you do not want to follow the present examples blindly, you might first wish to read the fundamental section on file management in Chapter 5 (page 86) and the description of some elementary commands, such as cp, ln, and mount, in Chapter 14 (page 437).

Whatever you do, do not format the partition in which Linux is located! With fdisk -l you can find out which partitions are planned to be Linux partitions. df displays a list of all partitions that are already mounted into the file system and must under no circumstances be formatted.

There are several possibilities for carrying on from here: the first variation is to access the space via a new directory - for example, /home. If space in the root directory becomes scarce, it is generally best to transfer existing data - for example, from /home -- the new partition. The third variation is slightly more complex and uses symbolic links to allow the transfer of directories of the root directory into the new partition.

The following examples are geared towards the home directory /home. You can, however, proceed in the same way if you want to transfer /usr/local, /var/spool, or other directories into a new partition.

Please note that in the following examples /dev/sdc3 will be used as the name for the new partition. On your computer, you must obviously substitute /dev/sdc3 with the name of your own partition.

# Variation 1 – accessing the second partition via a new directory

This variation is particularly recommended to Linux newcomers. It is easy to perform and practically without risk. In order to access the freshly formatted partition, you simply create a new directory with mkdirdir and then use the mount command to mount the partition at that point into the directory:

```
root# mkdir /home1
root# mount -t ext2 /dev/sdc3 /home1
```

All data on /dev/sdc3 can now be accessed under /home1. Now you can, for example, register a new user whose working directory will be located in /home1. With this, the data is physically stored on the new hard disk partition.

To make the partition available automatically at the next Linux start-up, without having to mount it manually with, an addition to fstab is required:

```
# Addition to /etc/fstab
# Mount /dev/sdc3 /home1 into the file system
/dev/sdc3 /home1 ext2 defaults 0 2
```

The transfer of home directories into their own partition has enormous advantages when changing or updating the system. Before a new installation takes place, frequently only the data contained in /root and /etc must be saved (with a backup, for example, in a directory of /home1). Subsequently, the root partition can be reformatted and a new distribution installed. After the installation, fstab modified should allow access to the data partition. Now, only the /etc/passwd file remains to be adapted to make all old logins again.

> If you have a great deal of space on your hard disk, you can create two systems plus one additional partition. Then you can install a new Linux distribution into the second partition. In this way, you can use two Linux versions in parallel (and with a common data partition). You can set up LILO in such a way that you start up with either the one or the other Linux system (see page 183). (While I was working on this book, I had to four Linux distributions installed in parallel.)

# Variation 2 – accessing the second partition via an already existing directory

The first variation is simple, but not very elegant. Essentially, it has two disadvantages: firstly, there are now two locations for home directories, /home /home1. Secondly, it is impossible to free the space occupied up to now, it is not possible to create two directories on the new partition that would be completely independent of each other. It could be useful, for example, to accommodate both /home (with the user data) and /usr/local (with subsequently installed user programs) in the new partition. As the new partition cannot simultaneously be mounted as fstab as /home and as /usr/local, this seems to be impossible.

In such a situation, symbolic links can help. Mount the new partition in an arbitrary directory in the file system (for example, /local for local data partition), copy the required directories into the new partition and create links from the original directories to the new locations.

```
root mkdir /local                               # new directory
root mount -t ext2 /dev/sdc3 /local               # mount new partition here
root cp -dp /home /local                          # copy /home into it
root cp -dp /usr/local /local                     # copy /usr/local into it
root mv /home /home.bak                           # rename /home
root mv /usr/local /usr/local                    # rename /usr/local
root ln -s /local/partition /usr/local          # link to new partition
root ln -s /local/partition /home                  # link to new partition
```

If everything has gone to plan, you can use it; however, the data is now located on its disk partition. In /home.bak you have a copy of the old directory. Once you are sure that all data has been copied, you can delete this copy with rm -r /home.bak.

Up to now, the new partition for /home has only been mounted. To make this partition automatically available at the next systemstart, you must add the following line to fstab:

```
# Addition to /etc/fstab
# Mount /dev/sdc3 /home into the file system
/dev/sdc3 /home ext2 defaults 0 2
```

In principle, you can transfer any directory (subdirectory) to another partition in the same way we transferred /home. However, every data contained in the /bin, /dev, /etc, /lib, /root, and /sbin directories should never be removed from the root directory.
