# FTP server configuration

ftp is a protocol that allows transmission of files between computers. (The usage of ftp from the client's side is described on page 335.)

In most distributions, an FTP server is installed automatically (often, this is wuftpd). ftp should then work immediately – try out ftp localhost. To transmit the files of a specific user, you need to execute ftp hostname. Subsequently, you enter login name and password.

If no FTP server is installed, you need to look the appropriate package in your distribution and install it. To make anonymous FTP work, you need to create the directory /home/ftp and fill it with data. For this purpose, it is best to follow the man for ftp, which includes many details regarding security aspects.

For reasons of security, ftp cannot be used for logins without a password. (We are talking about the login names on the server side. You yourself can work on login without a password, but you cannot access the data of a foreign account that is not protected.) In addition, the file /etc/ftpususers, users can be listed here those that are not allowed to use ftp. Usually, root is listed in this file for safety reasons.

Together with ftp, some other network services should work straight away: try telnet or login. For security reasons, it is normally impossible to log in directly as root. To log in under a different name first and then execute.

# Access control

If you want to have precise control over who is and who is not allowed to use which network services, you can modify the files /etc/hosts.allow and /etc/hosts.deny. The syntax in these files is user:service.

With in.ftp:192.168.1.1 in hosts.allow you allow all members of the local network to use ftp. With ALL:ALL in hosts.deny you deny all users to any other network service. allow takes precedence over deny; therefore, access to network services is now largely protected against unwanted access. (This sample setting is very restrictive as, for example, it allows no access to telnet and login.)
