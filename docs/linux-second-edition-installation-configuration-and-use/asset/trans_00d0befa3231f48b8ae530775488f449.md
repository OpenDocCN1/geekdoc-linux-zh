

# 配置与管理

关于模块处理的更多细节包含在 `/usr/src/linux/Documentation/modules.txt` 和 `/kmod.txt` 文件中。

在内核 2.2 中，模块管理已经发生了根本性的变化。在内核 2.0 之前的版本中，内核程序负责加载模块，而现在这项任务由内核的 `kmod` 组件接管。然而，只有少数变化直接影响用户。在第 203 页，你可以找到关于在未预先配置内核 2.2 的发行版中进行内核更新的信息。

# 使用模块

所有当前的发行版都已设置为自动启动模块——要么通过内核程序（适用于 2.0 之前的版本），要么直接通过内核（2.2 版本 版本）。例如：你使用 `mount` 命令将 CD-ROM（光驱）挂载到你的文件系统中。这会自动激活 `isofs` 模块，该模块是读取 CD-ROM 的 ISO-9660 文件系统所需要的。

换句话说：原则上，模块管理是自动且透明的，用户无需干预后文节描述的手动模块管理程序。但是，如果运行不正常（例如，在内核更新未完全成功后），你应该了解允许你手动加载模块的模块命令。

```
insmod module.name [option=value ...]
```

将指定的模块集成到内核中。模块名不包含路径信息且不包含扩展名；例如，对于存储在 `/lib/modules/n/nfs.o`（其中 `n` 是当前内核的版本）的 NFS 模块，应指定为 `nfs`。通过 `insmod`，可以向模块传递各种选项（方式与单体内核中的内核选项相同：见第 48 页）。

```
modprobe module.name [option=value ...]
```

`_modprobe` 的工作方式与 `insmod` 相同；但它会检查要加载的模块是否依赖于其他模块。这假设之前已使用了 `depmod` 命令来创建依赖文件 `/lib/modules/n/modules.dep`。（这些依赖文件通常在安装内核模块时创建，也就是说，几乎不需要手动执行 `depmod`。）

```
rmmod module.name
```

从内核中移除指定的模块并释放相应的内存空间。只有当该模块当前未被使用时，该命令才能成功执行。

# lsmod

`lsmod` 提供当前集成到内核中的所有模块列表。

# kerneld

`kerneld` 是一个守护进程，能够自动识别何时需要特定的内核模块。`kerneld` 仅用于内核 2.0 之前的版本。
该守护进程根据需要加载模块（并在不再使用时移除它们）。`kerneld` 基于上述 `depmod` 生成的依赖文件以及可选的控制文件 `/etc/conf.modules`。该文件可指定单个模块的选项。`conf.modules` 的语法在 `depmod` 的帮助页中有所描述。

# kmod

自内核 2.2 起，`kmod` 不再是一个独立程序，而是一个内核组件。在自动加载模块方面，它接管了 `kerneld` 的任务。`kmod` 也会考虑 `/etc/conf.modules`。与 `kerneld` 相比，`modprobe` 不会移除未使用模块。如果你希望自动移除未使用模块，应该设置 `crontab`：

```
export EDITOR=emacs
0 * * * * rmmod
```

# 安装内核

内核源码位于 `/usr/src/linux` 目录。如果该目录是空的，则需要安装。内核 2.2 的发行版提供了许多以压缩形式提供的内核。对于 `2.2` ，，内核（以压缩格式提供的）内核，可以在以下地址找到：

```
http://www.linuxhq.com/
http://www.linuxx.com/
```

现在解压内核到目录。内核存档始终使用 `gzip` 压缩（更常见的是 `bzip2`）。如果你想将内核更新到下一个版本，必须获取 `patch-2.2`。`patch-2.2` 是一个描述各个文件的文件的。对于`2.29` 源码必须被修改（因此，完整且的先版本是任何更新的必要条件）。补文件较小，可以通过 Internet 获取。

`make config` 是最简单的变体。这种变体的优点是不需要安装任何额外的程序。`make menuconfig` 要容易处理得多：配置仍然在文本模式下进行，但可以快速更改单个点而无需重复其他设置，`menuconfig` 仅在安装了必要的屏幕控制库时有效。make xconfig` 更加先进：这种变体仅在 X 环境下运行，且在安装了 Tk/Tk 时有效。配置现在通过鼠标点击在一个设计良好的程序中进行。在编译内核之前，你必须编辑 `/usr/src/linux` 目录下的 `.config` 文件，输入所有适用于新内核的选项。内核版本以来，该程序提供了三种不同的变体（你必须选择下面列出的三种变体之一）。

```
root# cd /usr/src/linux
root# make config
# make menuconfig 或
# make xconfig
```
