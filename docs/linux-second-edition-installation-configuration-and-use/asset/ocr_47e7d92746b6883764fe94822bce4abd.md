# 7.4 X in multiuser operation

In text mode, you can log in each text console under a different name. Under X
this is not easy. When you work with startx, you need to exit X and reexecute
startX under a different login. Also, when you use xdm, you need to terminate the
current session (and thus all running programs) and log in again.

In many cases, it is only necessary to quickly execute a command as root –
having leaving X for this would not be very user friendly. Since X is optimized for
network operation, it is hardly surprising that there are several alternatives for work-
ing a foreign login under X. However, some rules must be observed which
nitially, are often overlooked.

To make a su fully-fledged substitute for a root login, you need to use the
option -t. This ensures that all login start-up files (for example, for correct
definition of PATH) are read in again.

telnet, rlogin
Another two possibilities for working locally under a different login are provided
by telnet localhost (with subsequent login, including the password) or rlogin
- name localhost (with subsequent password prompt). For reasons of security,
nether of the variants can be used to log in as root.

Execution of commands or programs that run within xterm causes no problems.
The attempt to start an X program, however, ends with an error message:

```
user$ xman
Error: Can't open display:
```

The reason: the environment variable DISPLAY is not initialized. The following
instruction solves this problem:

```
user$ export DISPLAY=localhost:0
```
