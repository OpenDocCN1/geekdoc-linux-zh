## kppp (KDE)

After the first start-up of kppp, a new account needs to be created. First you click on SETUP, then on ACCOUNTS, and finally on NEW.

On the DIAL dialog sheet, you specify the name and phone number for this account. Usually, the simplest authentication procedure is PAP. For this, you must enter your user name and password in the main window. If, you opt for SCRIPTBASED, you need to enter the chat string pairs on the LOGIN SCRIPT dialog (in a manual configuration). You only need to specify a DNS address if you have not configured /etc/resolv.conf properly. For the remaining settings, you can mostly use the default settings.

After entering the access information, you need to configure the device (that is, the serial interface), the modem, and pppd. Usually it is sufficient to select the correct device for the serial interface.

![](img/b30873dd3d753687a59253fb9ad26a0b_345_0.png)

Figure 9.1 PPP configuration with kppp.

Now you are ready to proceed. With CONNECT, kppp attempts to set up PPP. During this process, the modem communication is displayed in a terminal window, which is helpful for error detection. Once the connection has been established, DETAILS displays the volume of data so far transmitted.

![](img/b30873dd3d753687a59253fb9ad26a0b_346_0.png)

Figure 9.2 Information about the PPP connection.

One of the most attractive features is the telephone charges counter of kppp. To use it, accounting must be enabled for the relevant account on the ACCOUNTING dialog sheet, and a phone company must be selected. (The program contains charges regulations for surprisingly many tariffs worldwide.) The logging files with a summary of data and charges incurred can then be displayed via VIEW LOGS on the ACCOUNTS sheet of the SETUP dialog.

![](img/b30873dd3d753687a59253fb9ad26a0b_346_1.png)

Figure 9.3 Counting phone charges with kppp.

kppp displays the message 'pppd died unexpectedly,' there are highly probable reasons for this: either /etc/ppp/options is missing completely, or /etc/ppp/options or "~.pprc contains the keyword lock. (This means that pppd is responsible for locking. Most of the time, this makes sense, but not in connection with kppp, which takes on this task by itself. Delete lock!) In case of doubt, simply go with a completely empty /etc/ppp/options file. Please also read the excellent online documentation!

kppp is usually installed as a SETUID program. This means that it has root privileges irrespective of who is executing it. Although this is a security risk (the documentation explains how it can be filled), it has one great advantage: in contrast to other scripts introduced in this chapter, it can be used by all users (not by root) without any significant problems. The only prerequisite is that all users are allowed to execute pppd. This is achieved by the following command:

```bash
root# chmod +x /usr/sbin/pppd
```

## Linuxconf (RedHat)

In the hierarchical menu of Linuxconf, the PPP configuration is hidden under SETTINGS|NETWORK|PPP. With the new button, you create the new PPP device pp0. In the Interface dialog, you must enter the phone number, serial interface, login name, and password. If you want to carve out with PAP (usually the simplest alternative), you must activate the appropriate option - it is not enabled in the default setting.

![](img/b30873dd3d753687a59253fb9ad26a0b_347_0.png)

Figure 9.4 PPP configuration with Linuxconf.

CONFIRM takes you back to the main dialog. By clicking on the interface name pp0, you get into a new dialog with further configuration options. You can set here the speed of the serial interface and various pppd parameters.
