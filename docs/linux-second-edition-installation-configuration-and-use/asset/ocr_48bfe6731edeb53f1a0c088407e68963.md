Such solutions may prove the power of the bash, but in the end, they are far too-winded for the day-to-day management of files. It is therefore obvious that such operations need to be simplified. The two commands presented here are regmv and regcp, represent variants of mv and cp. A string enclosed in single quotes must be passed as a parameter. The source file pattern and the target file pattern must contain exactly one asterisk. The following examples show the application of the two commands:

```
user regmv *.eps *.ps      # renames all *.eps files as *.ps files
user regmv pic*.eps p*.ps          # renames pic*.eps as p*.ps
user regmv *.old                # renames all *.files as *.old
user regcp *.dup                # makes a duplicate copy .dup of all files
user regcp ## *.bak               # copies ## files, new *.bak
```

The program of these two commands is Admittedly not too easy to understand. In principle, it is nothing but a repeated application of the command substitution used in the previous example.

For the following description of the command, we assume that the command was passed the string pic*.eps p*.ps. This parameter is split into two parts at the position of the space and stored in two variables (pic*.eps in source and p*.ps). Subsequently, source and target are their split into two parts at the position of the * (pic in source1, in source2, and so on.

If source and target contain characters at all, a check is made to whether the number of characters in source is exactly one higher than in source1 and source2. If this is not the case, either too many wildcards have been passed or none at all. An analogous check is also made for target.

The instruction files=$(echo $source) does not simplify a duplication of source. On the contrary, for execution of $source, the usual expansion of wildcards is carried out. Therefore, files subsequently contains the list of all files that match the source pattern. The following test checks whether any match the source pattern and the command is aborted with an error message.

If everything has gone well, the copy command for each file found is executed in the loop. Piece by piece, the new file name is assigned in the variable tmp. In the first step, the first part of the source pattern (pic) is eliminated from the filename, in the second step the second (.eps) is removed. In the third step, the filename is expanded with the two parts of the target pattern (p and .ps).

Each command is also displayed on screen in order to provide the user with feedback on what is actually happening. The -i option in cp causes cp automatically to display a request for confirmation before an already existing file is overwritten.
