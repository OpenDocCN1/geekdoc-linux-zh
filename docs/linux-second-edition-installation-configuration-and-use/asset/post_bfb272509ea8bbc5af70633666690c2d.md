# 15.3 Document and graphics conversion

Linux documents and graphics are present in the most diverse formats. The following list is intended to provide an overview:

- ASCII: Linux uses an 8-bit character set which largely corresponds to the ANSI set used by Microsoft Windows
- DVI (Device Independent Format): DVI files are the result of the LaTeX typesetting-program. DVI files stand in the middle of the road leading from a LaTeX source text (TeX file) to a printer file (mostly PS).
- Graphics formats: for historical reasons, there are an endless number of formats (GIF, TIF, JPEG, and so on). Conversion and processing of such files can be carried out by means of a whole range of programs.
- HTML (Hypertext Markup Language): although the HTML format was originally developed for the Internet, it has now established itself as an important format for online documentation.
- man files: the source texts for the man texts are present in the gro formatting system.
- PCD (Photo CD): you will encounter PCD files if you want to process the pictures of a Photo CD under Linux.
- PS, ES (PostScript): PostScript is a page description language for specific printers. Under Linux, this format plays a much bigger role than Windows. All Linux programs generate printing files only in this format. Thus, PostScript represents the printer standard in the Linux world (and, more generally, in the Unix world). But even if you do not own a PostScript laser printer, you do not need display. With gs (Ghostscript) you can convert PostScript files into the format of many other printers.
- SGML (Standardized Markup Language): this is a variation of HTML. The source texts of most Linux HOWTOs are present in SGML format.
- TEX (LaTeX): TEX files contain the source code for a LaTeX or TeX translation. (For reasons of space, only the TEX files are supplied as documentation of some programs; conversion into other formats is left to the user.)
- TEXI (TeXInfo): this is a variation of TeX files used for special creation of online documentation in the info format.

This section presents a number of tools which allow you to convert documents from one format into another. If, for example, you first want to read a *.tex file containing the documentation of a program on screen and print it on an Epson inkjet printer, the following conversion steps are required:

TEX -> DVI using latex; display for example with xxd
DVI -> PS using dvips; display for example with ghostview
PS -> printer file using gs

With an appropriate configuration, this conversion can be carried out automatically — see also page 162 and the Printing-HOWTO.

Programs for display of different documents are discussed in the next section from page 518 onward.

Depending on the printer, there may be several ways of obtaining a printing. You can, for example, first convert an ASCII file into a PostScript file with a2ps and subsequently print this file via gs on an HP Laserjet. The detour via the PostScript format often looks longwinded, but may lead to higher-quality results.

# Text conversion DOS ↔ Linux (fromdos, todos)

When you try to exchange texts between DOS/Windows and Linux, you will encounter problems: line ends are marked differently (this applies to DOS and Windows), and different character sets are used, which affects foreign language characters (only applies to DOS).

Details in brief: under both DOS and Windows, the end of a line is marked by a combination of carriage return and line feed. Unix and Linux do not require the carriage return character and are happy enough with the line feed. This means that a DOS file, when viewed with a Linux editor, shows a ^M character at each end of line. Conversely, a Linux file viewed in a DOS editor turns into an endless snake of characters, because DOS and some Windows programs (such as the NOTEPAD editor) do not recognize the ends of lines.

Now a few words about foreign special characters: DOS, Windows and Linux use three character sets. DOS generally uses a variation of the ASCII set, Windows uses the ANSI character set and Linux uses the ISO 8859/1 character set. In all three character sets, the characters with 0 to 127 are identical. Differences appear in the remaining 128 characters, which contain foreign special characters (accents, umlauts). The Windows and Linux character sets are more similar to each other – for example, umlauts are coded in the same way (unfortunately, other characters are not).

# Automatic conversion

If you have a DOS/Windows partition mounted in your Linux system, you can carry out the end-of-line conversion automatically, either by specifying the option -0 conv=auto in the mount command or by entering the option conv=auto into /etc/fstab.
