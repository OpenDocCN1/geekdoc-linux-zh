# RECOMPILING THE KERNEL 211

```
root@# make clean
root@# make bimage
```

Do not forget that Linux is a multitasking system. You can switch to another kernel and read about some topics in the online documentation, write a letter and so on. As long as you do not carry out time-consuming operations, you will hardly notice any delay caused by the simultaneous compilation.

The result at the end of this process is the file image in the directory. Depending on the configuration, the compressed kernel should have a size of about 5 MB.

# Compiling modules

When compiling you may choose for a large number of kernels whether to integrate the component directly into the kernel or keep it as a module. Then make modules creates the generic kernel and specified modules. The selected modules need to be separated properly to make modules flexible. Scattered across the kernel side the free module files are created to that extent. In the modules directory, links to these files are established.

Depending on your computer configuration, for booting Linux you need at least the drivers for your hard disk (perhaps SCSI), for the file system contained on it plus modules for elementary network support without specific hardware drivers.

With make modules the module files are finally installed where the module management programs (such as insmod) expect them namely, in the modules directory where the current kernel version is.

# Installing the kernel

Obviously, this newly created kernel is not active. So far only a new kernel can be activated at the next startup of Linux, and even then if you create a new boot diskette or call the boot program and activate the new kernel in the boot program.

Usually, the active kernel file is located in the root directory for boot and is commonly named linux. Before you move the newly generated kernel into this location, you should rename the old and well-proven kernel file into linux.old.

```
root@# cp /boot/linux /boot/linux.bak
root@# cp /usr/linux/arch/i386/boot/bimage /boot/linux
```
