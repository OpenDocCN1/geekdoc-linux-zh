An example will make the concept of expansion easier to understand. On my computer, for example, the input

```
user$ em Tab Tab
```

is automatically expanded to
user$ emacs command.tex
where emacs is the name (to call an editor). In order to complete em, the bash searches all directories specified in the PATH variable for executable programs. command.tex is a text file located in the current directory and is uniquely identifiable through the specification of the first three letters. The expansion also works for files named by several directories. If you

```
user$ ls /usr/doc/ger Tab
```

the bash expands this input to
user$ ls /usr/doc/man/
taking into account all file and directory names in the /usr/doc directory. If a unique expansion is not possible (beep), you can simply press Tab. Then the bash displays all possible expansions underneath the current input line. The input

> Commands and commands in the current directory are only considered for expansion if the current directory is contained in the PATH variable. (echo $PATH PATH). The directory is abbreviated with '.'. For reasons of safety, some Linux distributions lock the current directory in PATH. In order to execute programs from the current directory ./name must be entered. The PATH setting can be changed in /etc/profile.

> The automatic command expansion hides the location of a program file. Where name, all standard directories for program files are searched, in most cases leads to success. which searches PATH and determines the program that was executed when the command name was without a path specification, which is of interest where several versions of a program exist, located in different directories.

Similar expansion mechanisms work for the names of home directories ("root/ yields ~/) and variables ($PA Tab yields $PATH).
