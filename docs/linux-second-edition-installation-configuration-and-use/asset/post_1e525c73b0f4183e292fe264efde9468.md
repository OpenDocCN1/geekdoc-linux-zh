## LILO boot diskette with its own kernel

With more effort, it is possible to create a LILO boot diskette that has its own kernel. This diskette must contain a file system (minix or ext2). LILO, the kernel file and other files needed for the boot process (usually only boot.b and map). The preparations are as follows:

```
mkfs -t minix /dev/fd0 1440              # create minix file system
mkdir /mnt/floppy                       # if directory does not exist
mount -t minix /dev/fd0 /mnt/floppy/      # mount into file system
mkdir /mnt/floppy
cp /boot/mlinuz /mnt/floppy/boot      # copy the kernel
cp /boot/boot.b /mnt/floppy/boot/       # copy boot.b
mkinit                                # In Redhat with SCSI
cp /boot/initrd /mnt/floppy/boot/       # In Redhat with SCSI
```

The next step is to create a special LILO configuration for the diskette. The main difference is that map and install point to the diskette (instead of the usual hard disk). The file /mnt/floppy/map has not been generated in the above commands; it is created through the execution of the lilo command.

In the example below, three variations are provided. In the default setting, an attempt is to boot from the hard disk (this is the fastest way). If this fails (for example, because the kernel file is no longer where it belongs), a new attempt can be started, selecting the linuxdisk variation at the LILO prompt. Please note that in this variation image points to the kernel file on the diskette. As a third variation – for the sake of completeness – it is possible to boot DOS/Windows.

```
#etc/lilo.conf-floppy
boot = /dev/fd0                        # device of the disk drive
compact                                 # fast, but does not always work
delay = 100
install=/mnt/floppy/boot.b             # on the diskette!
map=/mnt/floppy/map                     # on the diskette!
image = /boot/mlinuz                   # kernel from hard disk
label = linux
root = /dev/hda8                       # enter your root device!
read-only
image = /mnt/floppy/boot/mlinuz      # kernel on diskette
label = linuxfromdisk
root = /dev/hda8                       # enter your root device!
read-only
other = /dev/hda8
label = dos
table = /dev/hda
```

In order to install this LILO configuration on the diskette, the following commands are required:

```
root# chmod -w /etc/lilo.conf-floppy # otherwise LILO will complain
root# lilo -C /etc/lilo.conf-floppy # install LILO
root# ls -lr /mnt/floppy/
drwxrxr-x 2 root 80 Jun 16 20:24 boot

/mnt/floppy:
total 11
--rw-rw-r-- 1 root root 3708 Jun 16 19:39 boot.b
--rw-rw-r-- 1 root root 7168 Jun 16 20:24 map
--rw-rw-r-- 1 root root 403672 Jun 16 19:37 vmlinux
```

```
root# sync # execute buffered operations
root# umount /mnt/floppy
```

Owners of a RedHat distribution can create a LILO boot diskette in a much simpler way. Just need to execute the following command with the correct kernel number:
root# mkbootdisk --device /dev/sda0 2.0.36-7

More information about how to create sophisticated boot diskettes that even have their own root file system and can be reused for maintenance work can be found in the HOWTO text on the subject of boot diskettes. In most distributions, the installation diskettes themselves can be used for this purpose.

## LILO installation in the boot sector of the hard disk

One of all LILO variations, this is the most dangerous one! Depending on the NT installation, this is incompatible with the Windows boot manager and in any case incompatible with disk managers (IDE disks with old BIOS).

## Creating a backup copy of the boot sector

During the execution of lilo for installation into the MBR of a hard disk, it is automatically checked whether there is already a backup copy of the boot sector in the /boot directory. Only if this is not the case (that is, during the first execution of lilo), the command saves the boot sector in the file /boot/boot.000 (for IDE disks) or /boot/boot.00 (for SCSI disks). If you want to save the boot sector manually, you must execute one of the following commands before you execute lilo for the first time. The first command applies to the first IDE disk, the second command to the first SCSI disk:

```
root# dd if=/dev/sda of=/boot/bootsector.ide bs=512 count=1
root# dd if=/dev/sda of=/boot/bootsector.scsi bs=512 count=1
```

If you want to convert the boot sector to a diskette, you need a formatted diskette (see format on page 45). Then, execute one of the following:

```
root# dd if=/dev/sda of=/boot/boot.000 bs=512 count=1    # first IDE disk
root# dd if=/dev/sda of=/boot/boot.000 bs=512 count=1    # first SCSI disk
```

If a disk generated this way is present: when the computer is restarted, it boots exactly the same way as from the boot sector on the hard disk. This is common under Windows 9x. When you create a boot diskette under Windows 95 (CONTROL PANEL | ADD/REMOVE PROGRAMS | START DISK), you can only use it to start DOS, not Windows. This may be sufficient to restore a damaged system, but it is not elegant. If, on the other hand, you proceed as above, you can start Windows 95 from a diskette quickly and without problems. Assuming the Windows partition has not been damaged and that all system files are available, in contrast the 'original' Windows 95 boot diskette is autonomous, files such as COMMAND.COM are loaded directly from the diskette.

## Setting up LILO

To set up LILO, you need a lilo.conf file which, except for the boot line, looks exactly like the diskette version. Path and device names need to be adjusted to suit your computer. You may need additional options which have been described in the configuration section.

```
# /etc/lilo.conf
boot=/dev/hda                # device of the first IDE disk
# boot=/dev/sda               # device of the first SCSI disk
prompt
timeout=100
image = /dev/mlinux          # kernel file
label = linux
root = /dev/sda8             # root device
read-only
# initrd = /boot/initrd       # RedHat with SCSI
other=/dev/hda1
label=dos
table=/dev/hda
```

## Removing LILO from the hard disk

To remove LILO from the hard disk, you must restore the boot sector. In the simplest case, you simply execute lilo -u. This causes LILO to read the boot sector saved in /boot during the first LILO installation and to use it to overwrite the current LILO boot sector.

If you have made your backup copy of the boot sector, you can reinstall it with dd. The first command applies to the first IDE disk, the second command to the first SCSI disk:

```
root# dd if=/boot/bootsector.ide of=/dev/hda bs=512 count=1
root# dd if=/boot/bootsector.scsi of=/dev/sda bs=512 count=1
```

If problems occur during the uninstallation of LILO, you can use a boot disk to start DOS and execute FDISK /MBR. This creates a boot sector for the automatic start of DOS/Windows (and overwrites the LILO boot sector). However, this method does not work for some versions of Windows 9x and not all for Windows NT.

## Installing LILO in a DOS partition (1024-cylinder limit)

If the root partition is situated outside the magic 1024-cylinder limit or on an inaccessible hard disk, the kernel file and other boot information can be copied to a DOS or Windows partition that lies below this limit. (For startup, LILO needs the kernel file, the files boot.b and map, and possible message files if the message-option is used).

```
# mkdir /dos # if the directory does not exist
# mount -t vfat /dev/hda1 /dos # device name of Windows partition
# mkdir /dos/lilo
# cp /boot/vmlinuz /dos/lilo # kernel file
# cp /boot/* /dos/lilo
```

In /etc/lilo.conf, you must change the path settings for the kernel file and possibly other location and map, which no longer (as in the default setting) point to the LILO directory /boot, but to the DOS directory C:\LILO.

However, make sure that the root directory remains unchanged. (The root option specifies where the Linux root partition is located. This location has not changed.)
