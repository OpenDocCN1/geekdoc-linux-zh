
# HARD DISK TUNING 157

Activation is carried out separately for each hard disk by means of hpdarm -d1.
(If needed, -d0 deactivates the mode.) /d1

```
root# hpdarm -d1 /dev/hda
/dev/hda:
setting using_dma to 1 (on)
using_dma = 1 (on)
```

To find out everything works properly you can, for example, copy an extensive directory tree in a partition of the hard disk for which the DMA mode has been activated:

```
root# mkdir /test-partition/test1
root# cp -a /usr /test-partition/test1
root# cp -a /test-partition/test1 /test-partition/test2
```

Subsequently, you might take a look into /var/log/messages: if you find error messages or warnings with the text 'DMA disabled,' the kernel automatically deactivated the DMA mode after having encountered one or more problems.

When everything works as desired, you can integrate the hpdarm command into the Init process, so it is executed automatically at every start-up of the computer. The appropriate file depends on the distribution. In SuSE 5.2, this is /sbin/init.d.local; in RedHat /etc/rc.rc.local.
Obviously, DMA also works with most SCSI controllers, where this feature has been used for a long time, with no special attention.

Further information on this subject can be found in the text hpdarm (which, as well as master DMA, also offers other possibilities of speed optimization) and in the comments of drivers/block/ide-dma.c (2.2 kernel code). Basic information on the bus master DMA mode (independent of Linux) can be found on Intel's web server.

```
http://developer.intel.com/design/pcisets/busmaster/FAQs.htm
```

Prime information on the use of Ultra DMA (development has not stopped with the bus master DMA mode) is available in the Ultra-DMA Mini-HOWTO.

# Striping (RAID-0)

RAID stands for Redundant Array of Inexpensive/Independent Disks (there are two definitions). The basic idea is to logically connect partitions of several hard disks. As a result, you can obtain a more reliable and/or faster overall system. Basic information on RAID can be found in a separate section from page 112 onwards.

At this point, our task is to configure a very simple form of RAID, so-called striping. Our reward will be that some disk operations can be executed nearly n times as fast (where n denotes the number of hard disks).
Three essential conditions need to be met for striping:

- You need at least two hard disks (ideally SCSI disks), each of which has enough free space to create a new partition.

# CONFIGURATION AND ADMINISTRATION

- The kernel components Multiple devices and RAID-0 must be available (either directly integrated in the kernel or as modules). This is the case with all current distributions. If not, the kernel must be recompiled. The corresponding options can be found in the Block devices group.)

- Finally, you need the commands mmadd, mdcreate, mdrun, and mdstop. Usually the corresponding package will still need to be installed. (In SuSE, the package is mdutils (series april), in RedHat, it is raidtools).

With the current Linux distributions, different versions of the RAID commands are swapped. Up to version 0.4 (used, for example, by SuSE 6.0), the commands are mdx and the configuration file is /etc/mdtab. From version 0.5 onward (with RedHat 5.2 and higher), the commands are radix; the configuration file has a new syntax and is located in /etc/raidtab. This section takes both cases into account; you simply need to execute the command that matches your version.

In some older distributions, these are not automatically created. This can be remedied by means of the following commands:

```
root knod /dev/md0 b 9 0
root knod /dev/md1 b 9 1
root knod /dev/md2 b 9 2
root knod /dev/md3 b 9 3
root clown root.disk /dev/md*
root chmod 660 /dev/md6
```

The first step towards the RAID-0 partition is to combine two (or more) unused partitions (in the following example /dev/sda10 and /dev/hdc10) into one multi-disk device (/dev/md0):

```
root mdadd /dev/md0 /dev/sda10 /dev/hdc10 # up to version 0.4
root raidrun /dev/md0 /dev/sda10 /dev/hdc10 # since version 0.5
```

The partitions specified in mdadd should be of the same size. If this is not the case, stripping only works for part of the total capacity of the partitions, that is, theoretically possible gain in speed can be achieved partially.

Subsequently, it must be stated that this new device is to be addressed as a RAID-0 partition (-p0). As page size, the default value of 4 Kbytes is used (that is, data across the hard disks in 4-Kbyte blocks). If required, a different page size can be specified by means of -cnk.

```
root mdrun -p0 /dev/md0 # up to version 0.4
root raidrun -p0 /dev/md0 # since version 0.5
```

As the next step, a file system must be created on /dev/md0.

When everything works as desired, you can integrate the hpdarm command into the Init process, so it is executed automatically at every start-up of the computer. The appropriate file depends on the distribution. In SuSE 5.2, this is /sbin/init.d.local; in RedHat /etc/rc.rc.local.
Obviously, DMA also works with most SCSI controllers, where this feature has been used for a long time, with no special attention.

Further information on this subject can be found in the text hpdarm (which, as well as master DMA, also offers other possibilities of speed optimization) and in the comments of drivers/block/ide-dma.c (2.2 kernel code). Basic information on the bus master DMA mode (independent of Linux) can be found on Intel's web server.

```
http://developer.intel.com/design/pcisets/busmaster/FAQs.htm
```

Prime information on the use of Ultra DMA (development has not stopped with the bus master DMA mode) is available in the Ultra-DMA Mini-HOWTO.

At this point, our task is to configure a very simple form of RAID, so-called striping. Our reward will be that some disk operations can be executed nearly n times as fast (where n denotes the number of hard disks).
Three essential conditions need to be met for striping:

- You need at least two hard disks (ideally SCSI disks), each of which has enough free space to create a new partition.

# CONFIGURATION AND ADMINISTRATION

- The kernel components Multiple devices and RAID-0 must be available (either directly integrated in the kernel or as modules). This is the case with all current distributions. If not, the kernel must be recompiled. The corresponding options can be found in the Block devices group.)

- Finally, you need the commands mmadd, mdcreate, mdrun, and mdstop. Usually the corresponding package will still need to be installed. (In SuSE, the package is mdutils (series april), in RedHat, it is raidtools).

With the current Linux distributions, different versions of the RAID commands are swapped. Up to version 0.4 (used, for example, by SuSE 6.0), the commands are mdx and the configuration file is /etc/mdtab. From version 0.5 onward (with RedHat 5.2 and higher), the commands are radix; the configuration file has a new syntax and is located in /etc/raidtab. This section takes both cases into account; you simply need to execute the command that matches your version.

In some older distributions, these are not automatically created. This can be remedied by means of the following commands:

```
root knod /dev/md0 b 9 0
root knod /dev/md1 b 9 1
root knod /dev/md2 b 9 2
root knod /dev/md3 b 9 3
root clown root.disk /dev/md*
root chmod 660 /dev/md6
```

The first step towards the RAID-0 partition is to combine two (or more) unused partitions (in the following example /dev/sda10 and /dev/hdc10) into one multi-disk device (/dev/md0):

```
root mdadd /dev/md0 /dev/sda10 /dev/hdc10 # up to version 0.4
root raidrun /dev/md0 /dev/sda10 /dev/hdc10 # since version 0.5
```

The partitions specified in mdadd should be of the same size. If this is not the case, stripping only works for part of the total capacity of the partitions, that is, theoretically possible gain in speed can be achieved partially.

Subsequently, it must be stated that this new device is to be addressed as a RAID-0 partition (-p0). As page-size, the default value of 4 Kbytes is used (that is, data across the hard disks in 4-Kbyte blocks). If required, a different page size can be specified by means of -cnk.

```
root mdrun -p0 /dev/md0 # up to version 0.4
root raidrun -p0 /dev/md0 # since version 0.5
```

As the next step, a file system must be created on /dev/md0.

When everything works as desired, you can integrate the hpdarm command into the Init process, so it is executed automatically at every start-up of the computer. The appropriate file depends on the distribution. In SuSE 5.2, this is /sbin/init.d.local; in RedHat /etc/rc.rc.local.
Obviously, DMA also works with most SCSI controllers, where this feature has been used for a long time, with no special attention.

Further information on this subject can be found in the text hpdarm (which, as well as master DMA, also offers other possibilities of speed optimization) and in the comments of drivers/block/ide-dma.c (2.2 kernel code). Basic information on the bus master DMA mode (independent of Linux) can be found on Intel's web server.

```
http://developer.intel.com/design/pcisets/busmaster/FAQs.htm
```

Prime information on the use of Ultra DMA (development has not stopped with the bus master DMA mode) is available in the Ultra-DMA Mini-HOWTO.

As a result, you can obtain a more reliable and/or faster overall system. Basic information on RAID can be found in a separate section from page 112 onwards.

At this point, our task is to configure a very simple form of RAID, so-called striping. Our reward will be that some disk operations can be executed nearly n times as fast (where n denotes the number of hard disks).
Three essential conditions need to be met for striping:

- You need at least two hard disks (ideally SCSI disks), each of which has enough free space to create a new partition.

# CONFIGURATION AND ADMINISTRATION

- The kernel components Multiple devices and RAID-0 must be available (either directly integrated in the kernel or as modules). This is the case with all current distributions. If not, the kernel must be recompiled. The corresponding options can be found in the Block devices group.)

- Finally, you need the commands mmadd, mdcreate, mdrun, and mdstop. Usually the corresponding package will still need to be installed. (In SuSE, the package is mdutils (series april), in RedHat, it is raidtools).

With the current Linux distributions, different versions of the RAID commands are swapped. Up to version 0.4 (used, for example, by SuSE 6.0), the commands are mdx and the configuration file is /etc/mdtab. From version 0.5 onward (with RedHat 5.2 and higher), the commands are radix; the configuration file has a new syntax and is located in /etc/raidtab. This section takes both cases into account; you simply need to execute the command that matches your version.

In some older distributions, these are not automatically created. This can be remedied by means of the following commands:

```
root knod /dev/md0 b 9 0
root knod /dev/md1 b 9 1
root knod /dev/md2 b 9 2
root knod /dev/md3 b 9 3
root clown root.disk /dev/md*
root chmod 660 /dev/md6
```

the-stepthe partitions specified in mdadd should be of the same size. If this is not the case, stripping only works for part of the total capacity of the partitions, that is, theoretically possible gain in speed can be achieved partially.

Subsequently, it must be stated that this new device is to be addressed as a RAID-0 partition (-p0). As page size, the default value of 4 Kbytes is used (that is, data across the hard disks in 4-Kbyte blocks). If required, a different page size can be specified by means of -cnk.

```
root mdrun -p0 /dev/md0 # up to version 0.4
root raidrun -p0 /dev/md0 # since version 0.5
```

As the next-step, a file system must be created on /dev/md0.

When-everything-works-as-desired, you can integrate the hpdarm command into the Init process, so it is executed automatically at every start-up of the computer. The appropriate file depends-on-the-distribution. In SuSE 5.2, this is /sbin/init.d.local; in RedHat /etc/rc.rc.local.
Obviously, DMA also works with most SCSI controllers, where this feature has been used for a long time, with no special attention.

Further information on this subject can be found in the text hpdarm (which, as well as master DMA, also offers other possibilities of speed optimization) and in the comments of drivers/block/ide-dma.c (2.2 kernel code). Basic information on the bus master DMA mode (independent of Linux) can be found on Intel's web server.

```
http://developer.intel.com/design/pcisets/busmaster/FAQs.htm
```

Prime-information-on-the-use of Ultra DMA (development has not stopped with the bus master DMA mode) is available in the Ultra-DMA Mini-HOWTO.
