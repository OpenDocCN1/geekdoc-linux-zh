During the past years I have worked with four LaTeX packages and/or distributions. Over and over again there have been changes to the directory, single style files are present in one distribution or have a different name in the next one; in some cases different character sets are installed as default character sets.

These factors mean LaTeX documents are still not as portable as they should be. When translating on a different computer, the translation may not succeed at all (missing style file), line and page breaks may be altered (different default character set), hyphenation may not work (incorrect hyphenation table), and so.

Meanwhile, two LaTeX distributions are dominant under Linux: TeX (by Frank Langbein) and TeTeX (by Thomas Essen). Both distributions are huge. TeTeX is slightly better structured, has more online documentation and uses a faster system for finding files. For these reasons, most current Linux distributions now supply TeTeX. Personally, I have had excellent experiences with both distributions.

All paths in this chapter are based on the TeX distribution 0.9 and the assumption that the installation directory is /usr/share/texmf. If you are unable to find a file, try using which (for programs) or Locate.

One big advantage of TeX is the structuring of available online documentation in the /usr/share/texmf/doc directory. When you execute make in this directory, *.dvi and *.ps files are automatically created together with the HTML file helpindex.html as a central index. Provided your WWW browser is configured correctly (see page 338), clicking on cross-references in the index directly starts ghostview or xdvi. Some variable files are located in /var/lib/texmf. Depending on the distribution, your configuration files are located in /etc/texmf. The /usr/share/texmf/ tree contains links to these configuration files.

During the conversion of *.d files into PostScript format (dvips) or when they are displayed on screen (xvdi), bitmap files of the required files are generated. These files have the extension *.pk and are stored in the following directory:

/var/cache/fonts/pk/ bitmaps (*.pk)

If you suffer from space problems, you can delete the *.plt files without hesitation. However, at the next call of dvips or xvdi, these files have to be generated again, which takes some time.

In view of the immense number of files, the search for a given font or style file can take relatively long. The TeX distribution therefore manages an additional database that contains a list of all ls files. Essentially, this database consists of the result of ts -R and is therefore called ts-R. When you TeX with additional files, you must always execute the command texhash in order to extend the database as well. Also, you should always try this command first whenever you encounter problems in finding TeX files.

# 18.2 Elementary LaTeX commands

This section summarizes the most important LaTeX commands. The commands introduced here should be sufficient to produce simple LaTeX documents. If you want to work with LaTeX more extensively, there is no other way to approach some more detailed literature. Highly recommended are the books by Helmut Kopka (see References on page 757) and the LaTeX Companion by Michael Goosens, Frank Mittelbach and Alexander Sander.

# Formal details

The text to be processed with LaTeX is generated with a text editor. A group of consecutive lines is viewed as a paragraph. Words are separated from each other by spaces or line breaks, paragraphs by at least one empty line. Proper line breaking within a paragraph is carried out by LaTeX. Therefore the position where a new line is started in the original text is irrelevant.

LaTeX commands always begin with a backslash\. When commands need parameters, these must be specified in curly brackets, for example \chapter{chapter title}. Some commands also optional parameters which must be specified in square brackets, for example \sqrt[3]{x} for root. Without [3], attribute yields a common square root, that is, \sqrt.

Curly commands can also be used to restrict the effect of commands. Thus, {\bf word} only prints one word in bold, whereas the unbracketed command \bf sets the 'bold' attribute until another command.

Environments represent a special type of command. They are opened with \begin{environment} and closed with \end{environment}. The special formatting features of the environment throughout the whole text enclosed between these two commands. Typical environment names are tagging (for tables) or verbatim for listings special characters.
