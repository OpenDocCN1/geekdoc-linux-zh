
# 468 COMMAND REFERENCE

## md files

md deletes the specified files on an MS-DOS format diskette.

## mdir [path]

mdir displays the contents of an MS-DOS format diskette.

- -w lists only the file names in a multi-column table. By default, the file names are displayed line by line with some additional information.

## mformat drive

mformat creates an MS-DOS file system on a diskette already preformatted with fdformat (see also page 453).

## mkdir directory

mkdir creates a new directory. The most important options are:

- -m mode or --mode=mode sets the access rights of the new directory as specified in mode (see chmod on page 444).
- -p or --parents also creates intermediate directories. When you execute mkdir a/b/c and the directories data and a/b do not exist, they are created as well.

## mkfifo file

mkfifo creates a FIFO file (first in out). In principle, FIFO function the same way as pipes and allow data exchange between programs.

Example

```
user mkfifo fifo
user ls -l fifo &
user more < fifo
```

creates a new FIFO file, redirects the contents list into this file and reads it there with more. ls must be started as a background process by specifying the option &, because the ls process terminates only after more has read all data from fifo. The display of a contents list via more could be obtained more easily without a FIFO name, namely with ls -l | more.

## mkfs [options] device [blocks]

mkfs creates a file system on a diskette previously formatted with fdformat or on a hard disk partitioned with fdisk. mkfs can only be executed by root.

on the file system specified, the program calls up one of the programs mkfs.minix or mk2fs, mkxfs. When an MS-DOS file system is to be created on a diskette, mformat command must be used instead of mkfs.

- -t file-system

specifies the type of file system. Currently supported file systems are minix (default setting), ext2 (standard Linux file system) and xias (as an alternative to ext2). When the -t option is not specified, mkfs tries to determine the file system by looking through /etc/fstab. The -t option must be specified as the first option!

### Options for mke2fs

Further options are passed to the program that actually creates the file system. Therefore, they depend on the type of file system. Here, we only present options for mke2fs, which is used most frequently. The internals of the file system are described on page 107. Options of the other mkfs programs are described on the corresponding man pages.

- -b n specifies the block size (default: 1024 bytes). n must be a power of 2 greater than or equal to 1024 (that is, 1024, 2048, 4096, and so on).
- -c executes a check for bad blocks on the data support prior to creating the file system.
- -i n specifies how many bytes an I-node is created. The default setting is 4096, which means that 256 I-nodes are created for a total capacity of 1 Mbyte. (Thus, a maximum of 256 files plus directories can be stored. The minimum value for n is 1024. The choice of a value greater than 4096 carries the implication that more space is available for actual data. However, when a large number of very small files is to be stored, the available I-nodes may be too few.
- -m specifies what percentage of the data support is to be reserved for root data (default: 5 percent).

Example

```
root# mkfs -t ext2 /dev/fd0
mke2fs 0.5a, 5-Apr-94 for EXT2 FS 0.5, 94/03/10
360 inodes, 1440 blocks
72 blocks (5.00%) reserved for the super user
First data block=1
Block size=1024 (Log0)
Fragment size=1024 (Log=0)
1 block group
8192 blocks per group, 8192 fragments per group
360 inodes per group
```

## mknod device_file (bc) major_number minor_number

mknod creates a new device file. Usually, device files are located in /dev directory and are used to manage the hardware accessed under Linux (hard disks, interfaces, RAM, and so on). Device files are characterized by three items of information: the major and minor device numbers specify the driver with which the device can be accessed. The characters b c specify whether the device works buffered or unfiltered. Creation of new device files only be carried out by root and assumes a basic knowledge of Linux. A detailed description of all devices and the required device numbers can be found in the file /usr/src/linux/devices.txt.

Example

```
root # mknod /dev/sbp 25 0
```

creates a file for CD-ROM drive of the types Matsushita, Panasonic and CreatLabs. (These rather addressed via EIDE interface, but via proprietary interface).

## mkswap device/file

mkswap sets up a device (hard disk partition) or a file as swap area. mkswap can only be executed by root. In order to allow the newly created swap area to be used, it must be activated with swapon. Now in case of insufficient RAM, Linux can swap into this area.

## label

label displays the name (volume label) of the MS-DOS diskette in the specified drive. Subsequently you are asked to enter a new name and confirm with it.

## mmd directory

mmd creates a new directory on MS-DOS diskette.

## more file

more displays the contents of a text file by page. After each page, the display is interrupted, and more waits for keyboard input. The most important commands are (line down), Spacebar (page down) and Q (quit).

# ALABETICAL COMMAND REFERENCE 471

Further keyboard commands are described on the man page for more. The important options when calling more are:

- -s displays only one empty line when several consecutive lines occur in the text.
- -linenumber starts the display with the specified line number.
- -text starts the display with the first occurrence of search text. A related command is less (see page 462), a more powerful command than more. For example, less allows backward scrolling even when used as a filter.

Example

```
user -l | more
```

displays the contents of the current directory by page.

## mount [options] device directory

mount mounts a data resource (hard disk, diskette, CD...) into the Linux file system. As parameters, the name of the data resource (for example, /dev/cdrom) must be specified with the directory (mount point) in which the file system of the data resource is linked into the current file system. Calling the command with parameters displays a list of all currently available resources. The structure of the file system at the start of Linux is controlled through the file /etc/fstab. Data in this file corresponds to the parameters of mount (see page 147). For all drives registered in /etc/fstab, mount can be used in an abbreviated form in which only the device or the mount directory is specified.

- -t specifies the filesystem. Some of the possible options are ext2 (for Linux disks (or partitions)), mdos for MS-DOS data resources, vfat for the Windows 95 file system with long names, hfs for data resources in the OS/2 file system (read only) and iso9660 for CDs.
- -r prevents writing operations on the data resource (read only).

A more extensive discussion of mount options can be found in the context of the description of /etc/fstab on page 147.

Examples

```
root# mount -r -t msdos /dev/hda3 /dos
```

allows files to read from a DOS partition. The partition is accessed via the /dos directory.

```
root# mount /cdrom
```

mounts the CD-ROM drive into the file system. The command presu-
-mesumes that the remaining parameters for the CD-ROM are present in /etc/fstab.

```
root# mount -t iso9660 -r /dev/mcd /cdrom
```

as above, but this time with all parameters for an old Mitsumi CD-ROM drive (in case the fstab entry is missing).

## mrd directory

mrd deletes the specified directory from the MS-DOS diskette (only if it is empty).

```
cp dos.file linux.file
```

cp copies the specified file from the MS-DOS diskette into the Linux file system. The command is a restricted variation of mcopy which allows copying in both directions.

## mren old.name new.name

mren- renames a file on an MS-DOS diskette.

## mt [-f device] command

mt is used for the control of streamers. The default device is /dev/tape. If your streamer cannot be accessed under this name, you must specify the device exactly (for example, /dev/inst0 for a SCSI streamer). The most frequent applications of mt are the rewinding of tapes with the command rewind and the ejection of tapes with offset. offsetblk can be used to modify the block size, and stat status information about the streamer settings.

An overview of further commands can be found in the main pages for mt or mst (Slackware). Background information is contained in st.info.txt or mt-st; one of these files is normally installed together with mt.

There are two variations; one GNU and one BSD. Most distributions automatically supply the BSD variation. The GNU variation lacks many commands of its BSD counterpart.
