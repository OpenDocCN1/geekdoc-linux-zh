
# Examples

user tar -cv text/book

stores all files in the current directory and its subdirectories on the default streamer
 displays the stored files on screen.

user tar -cvf /dev/nst0 text/book

as above, but for the streamer connected to /dev/nst0 (in case the default streamer
tar does not correspond to your streamer).

Generally, you should always specify a path when creating archives. This
makes unpacking easier later on (because the files are automatically extracted into
subdirectories, which avoids possible disorder in the current directory).

user tar -czf book.tgz text/book

archives all files of the directory text/book and all subdirectories in the compressed
file book.tgz.

user find -mtime 7 > /tmp/lastweek

user tar -CT /tmp/lastweek

stores on tape all files that have been modified during the past month.

user tar -tzf backup.tgz

displays all files in the archive.

user tiff linux-2.2.0-pre7.tar.bz2

displays all files of a Linux archive compressed with bzip2.

user tar -xzf backup.tgz

extracts the archive into the current directory.

Always look into your archives with tar -t before unpacking them. By doing
so, you will establish whether path information is stored in the archive and where
the files are going to be installed. Thus, you can create a new directory and
this directory before you run tar -x, or you can use the -c option to prevent the
uncontrolled writing of files in your local directory.

user tar -xzf backup.tgz -C /test

extracts the archive into the directory test.

user tar -zf backup.tgz *.tex

as above, in an alternative notation.

user tar -xzf backup.tgz *.tex

only extracts *.tex files from the archive. Please note the quotes for the search
pattern which prevent immediate evaluation by the shell!

```
root# (cd /dir1 ; tar cf - ) | (cd /dir2 ; tar xvf -)
```

copies all files from /dir1 to /dir2. The advantage as opposed to a normal cp
mand is that symbolic links are copied as such (and not the data pointed to by
links). The above command is particularly useful for transferring whole directory
trees from one partition to another.

# DAT exchange between different Unix systems

The exchange of DAT streamer tapes read and written on different Unix systems often causes problems (there is no sign of a standard!). The following paragraphs give some hints which are in part result of the author's own experience, and in part based on relevant articles found in Linux newsgroups.

The most probable cause of errors is a number of blocks (option -b) which must match when reading and writing. It would appear the tar commands in every Unix variation use a different number of blocks as their default setting. In GNU tar, default setting is -b 20. You may also have to change the default setting of the streamer with mtblk n. On some Unix systems, besides the manager's original tar, you will also find an installation of GNU-tar, which in this case must be addressed as tar.

If nothing helps, there are other ways of exchanging data via a DAT tape. One variation consists in using the cpio command. Still one level below, we find the dd command, for writing you use dd if=/dev/streamer, for reading dd if=streamer of=/dev/file. With the dd option conv=swap, you can invert the byte order, if necessary.

If you do not want to do without using tar, you can also use pipes. The command for writing data to a DAT tape looks like this:

```
root tar -cvf data | dd obs=10240 of=/dev/tapedevice
root dd bs=10240 if=/dev/tapedevice | tar -xvf
```

# SGI

For writing data on an SGI system, it has proven useful to use the device tps0d3ns files. tar cvbf /dev/rmt/tps0d3ns files. To be subsequently read the data under Linux, you must first set the block size to 512: mt setblk 512. Now tar should function without further problems.

# tee file

tee duplicates the standard input, displaying one copy and saving the other copy in a file. In is useful when the output of a command is to be viewed on screen but simultaneously saved in a file. A simple redirection into a file with > would result in nothing being on screen.

Example

```
user ls -l | tee contents
```

displays the contents list of the current directory and simultaneously stores it in the file contents.

# todos file

```
todos source > target
```

todos appends a carriage return character to each of the lines of the specified text file. Thus, the text file can be processed under DOS as usual (see also fromdos on page 458 and recode on page 476).

# tr [options] cs1 [cs2] [ < source > target]

tr substitutes the characters of character 1 in the specified source file with the corresponding characters of character 2. The character strings should be of equal length. Characters that do not occur in the first character string remain unchanged. It is not possible to replace a single character with several characters (for example, ð with "o") - for this purpose, commands such as recode or sed must be used.

- -d
the characters specified in string 1 are deleted. Character 2 string does not have to be specified.

# Example

```
user$ tr a-z A-Z < text.lin
```

replaces all lower case letters in text.lin with upper case letters.

# 488 COMMAND REFERENCE

- -c n specifies how many mount operations the partition is to be checked for errors during booting (mk2fs default: 20 mount operations). If you start and stop Linux once (or several times) per day, it is sensible to specify a slightly higher value. This avoid that every couple of days a time-consuming integrity check of your data is carried out.

- -i n specifies how often (in days) the partition is to be checked for errors during booting (mk2fs default: 180 days).
- -m n specifies how many mount operations the partition is to be checked for errors during booting (mk2fs default: 5). The command must only executed if there are still open. (find supplies one line for each regular file, when wc counts the counts).

# uncompress file

uncompress decompresses a file previously compressed with compress. The extension .z is automatically removed. uncompress is a link to compress, with the -d option activated.

# uniq file

uniq displays the lines of a text file on the standard output, eliminating consecutive lines. In presorted files, uniq eliminates all lines occurring more than once.

Example

```
user$ sort test | uniq > test
```

sorts the file test, eliminates duplicate lines and stores the result in test.
