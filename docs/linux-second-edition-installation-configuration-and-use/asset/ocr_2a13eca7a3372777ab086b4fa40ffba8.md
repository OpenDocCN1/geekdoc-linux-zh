# Swap partitions

Speed imani amongst Linux fans will obviously want to know that striping is also possible for swap partitions. The answer is obviously 'yes', and you don't need elaborate preparations or the multiple device driver. The Linux kernel automatically distributes swap data across all partitions of priority before it begins to write swap partitions of lower priority. (Background information can be found in man 2 swap.)

Thus, you only to ensure that the swap partitions located on the different disks are the same priority.(Normally, this is not the case: Instead, swap partitions are gain a sequential priority number.) If you want to set the priority yourself, need to set the option priority in /etc/fstab

```
# Modification (bold) in /etc/fstab
```

```
/dev/hda9 swap swap pri1 0 0
/dev/hdc9 swap swap pri=1 0 0
...
```

# Benchmarks

The effect these measures really have on the working speed depends on a variety of parameters, such as your hardware, frequency and type of data access of your applications, and so on. Often, the bonnie program is employed to repeatable indexes of disk performance. You can find this program on the Internet, for example, under:

```
ftp://ftp.redhat.com/pub/contrib/1386/bonnie-n.rpm
```

The program creates a test of pre-determined size and performs different write, read, and search operations in it. At the same time, it also measures the CPU load. To make the results repeatable, the file size must be a multiple of the main memory—otherwise, you do not measure disk performance, but the caching efficiency of Linux (which is far good ...).

For the figures shown below, the file size was 400 Mbytes. The tests were carried out on a normal partition with and without DMA transfer and on a RAID-0 partition with DMA. The test system was equipped with a Pentium II 400, Intel BX chip set, 128 Mbytes of RAM, and two IBM 8.4-Gyte hard disks on /dev/hda and /dev/hdc. It may well be possible that on your computer the results are completely different (either better or worse).
