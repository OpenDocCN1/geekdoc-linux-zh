# 7.3 X fonts

Management of character sets under X and the use of these fonts in X programs is a very complex subject which, for reasons of space, cannot be dealt with in all aspects. The following information should however, be sufficient to understand the system and add new fonts.

If you want to delve deeper into character sets, the following two addresses offer an excellent starting point:

http://www.gimp.org/fonts/html
http://www.nwalsh.com/comp/fonts/FAQ

Basically, X has non-scalable and scalable fonts. Non-scalable fonts are present as bitmaps in a limited number of sizes (for example, in 8, 10, 11, 12, 14, 17, 18, 20, 24, 25, and 34 points). Such fonts can also be displayed in any other size (X simply reduces or increases the characters of the nearest font); however, characters created in this manner look ugly and are very hard to read.

In scalable fonts, in contrast, only the shape of each character is described. When a character is used for the first time, the X server generates a bitmap of the mathematical description of that character. The quality of the result is good, but the first display may take some time and (when using many fonts and sizes at the same time) require a lot of memory and disk space.

Under Windows, fonts generally look smoother than the X Windows System. This is due to the fact that antialiasing is used to draw the characters as grayscale pixels. Unfortunately, the X Windows System does not support antialiasing (version 11, releases 6.3 and 6.4). Individual programs such as gimp, ghostview, xdvi, or acread provide an antialiasing option; however, this effect is achieved via a very time-consuming calculation of the page in a high resolution.

Microsoft Windows is currently still ahead of the X Windows System on an other aspect too: nearly all fonts can be printed on any printer. Under X, this works only in exceptional cases (with some PostScript fonts that are also available as X fonts).

# Font management

Font files are usually located in subdirectories of /usr/X11R/lib/X11/fonts. With non-scalable fonts, there is a separate file for each font size and attribute; with scalable fonts, one file is sufficient for all sizes.

Each font directory also includes the file fonts.dir, which is responsible for the coordination between the font files and the internal font names of X.
