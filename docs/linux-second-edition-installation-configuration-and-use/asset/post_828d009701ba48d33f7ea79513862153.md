## Swap partitions

Speed among Linux fans will obviously want to know that striping is also possible for swap partitions. The answer is obviously 'yes', and you don't need elaborate preparations or the multiple device driver. The Linux kernel automatically distributes swap data across all partitions of priority before it begins to write swap partitions of lower priority. (Background information can be found in man 2 swap.)

Thus, you only need to ensure that the swap partitions located on the different disks are the same priority. (Normally, this is not the case: Instead, swap partitions are given a sequential priority number.) If you want to set the priority yourself, you need to set the option priority in /etc/fstab.

```bash
# Modification (bold) in /etc/fstab
```
/dev/hda9 swap swap pri=1 0 0
/dev/hdc9 swap swap pri=1 0 0
...
```

## Benchmarks

The effect these measures really have on the working speed depends on a variety of parameters, such as your hardware, frequency and type of data access of your applications, and so on. Often, the bonnie program is employed to repeatable indexes of disk performance. You can find this program on the Internet, for example, under:

```
ftp://ftp.redhat.com/pub/contrib/1386/bonnie-n.rpm
```

The program creates a test of pre-determined size and performs different write, read, and search operations in it. At the same time, it also measures the CPU load. To make the results repeatable, the file size must be a multiple of the main memory—otherwise, you do not measure disk performance, but the caching efficiency of Linux (which is far good...).

For the figures shown below, the file size was 400 Mbytes. The tests were carried out on a normal partition with and without DMA transfer and on a RAID-0 partition with DMA. The test system was equipped with a Pentium II 400, Intel BX chip set, 128 Mbytes of RAM, and two IBM 8.4-GB hard disks on /dev/hda and /dev/hdc. It may well be possible that on your computer the results are completely different (either better or worse).

```
root bonnie -s 400
| | Sequential Output | | | Sequential Input | | | | | | | |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| | Per Char | Block | Rewrite | Per Char | Block | Seeks | K/sec | CPU | K/sec | CPU | K/sec | CPU | K/sec | CPU | K/sec | CPU /sec |
| Without DMA | 3318 | 34.8 | 3797 | 27.5 | 1891 | 53.4 | 3571 | 72.4 | 4281 | 70.0 | 47.9 | 6.9 |
| With DMA | 7387 | 47.6 | 6927 | 12.7 | 2926 | 9.3 | 7402 | 33.2 | 7921 | 10.0 | 52.5 | 0.7 |
| DMA+RAID0 | 12659 | 81.8 | 11979 | 21.9 | 4558 | 15.2 | | | | | | |
```

A brief comment: with many operations, activation of DMA nearly doubles the transfer rate (when reading large blocks, from 4.3 to 7.9 Mbytes/sec). In all operations except writing single characters (per char), the CPU load decreases dramatically (when reading large blocks, from 17 to 10 percent). Only the number of random accesses per second remains practically unaltered—here, the limit is positioning time of the disk, which is not altered with DMA transfer.

RAID-0 considerably accelerates block operations (reading and writing of large contiguous amounts of data). With smaller blocks, the effect is not as strong, but still visible. The number of random accesses per second is marginally improved through striping. The higher speed is achieved at the expense of CPU load. In other words: striping is mainly sensible if you frequently process large files (image processing), but does not help much when accessing smaller or small data segments of large files (which is, the standard case with many applications). Better striping results probably be be achieved with SCSI hard disks; in that case, it would also be sensible to combine more than two hard disks.
