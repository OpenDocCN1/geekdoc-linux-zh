The starting point is always a hard disk or a disk partition on several hundred Megabytes of linear storage space are available. The first step in managing such an amount of data efficiently consists in subdividing it into blocks of 1024 bytes (1 Kbyte), and numbering these blocks sequentially. Subsequently, the blocks are arranged into several groups, each destined to store a different data type.

The first two groups consist of one block. The first block (boot block) contains a mini-program to start the operating system. The second block (superblock) specifies how the four remaining groups are.

Groups three and four consist of several blocks and are organized as bitmaps. Each bit in these bitmaps indicates whether the corresponding I-node (see below) or data block in groups five and six is free or not. The importance of bitmaps lies in the fact that, when a new file is to be created, they quickly allow the system to determine where on the hard disk free data blocks are available.

## ext2 data block types

| Block | Group | Description |
|---|---|---|
| Block 1 | Group 1 | Boot block |
| Block 2 | Group 2 | Superblock |
| Block 3 to n1 | Group 3 | I-node bitmap (which blocks for I-nodes are free) |
| Block n1 to n2 | Group 4 | Data bitmaps (which blocks for data are free) |
| Block n2 to n3 | Group 5 | Storage space for I-nodes (four I-nodes per block) |
| Block n3+1 to n4 | Group 6 | Storage space for data (1024 bytes per block) |

Group 6 is by far the largest. It stores the actual contents of the files, whereas the other five groups contain pure management information. (As you will see in the following sections, some blocks in group 6 must also be used for management in very large files, for cross-references to further data blocks, and in directories, for the storage of the directory contents.)

## I-nodes

I-nodes (information nodes) are the key to data administration. In 128 bytes, the I-nodes store all the management information for a file, except for the file name. (The file name is stored in directories – more about this later.) Information stored in the I-node includes (among other things):

- IDs of owner and group.
- Access rights.
- File size.
- Number of links
- Date and time of creation, last read access and deletion of the file.
- References to the first 12 data blocks of the file.
- Singly, doubly, and triply indirect references to up to 16 million further data blocks (Linux versions running on 32-bit processors, however, limit the size to 2 Gigabytes).

When formatting an ext2 file system by means of the mkfs command, the density of I-nodes can be specified. Normally, one I-node is assigned to every 4 Kbytes (thus, 25000 I-nodes in a partition of 100 Mbytes). In practice this means that only 25000 nodes can be stored in this partition, even if the files are very small and occupy less than 100 Mbytes. If you know that a very large number of small files (or symbolic links) are to be created on a partition, you can choose a greater I-node density (for example, I-node for every 1024 bytes). However, since I-nodes themselves take up space, the available data area of the partition becomes smaller.

## Files

A file consists of an I-node with management information and several data blocks containing the data proper. It is very important that the management information is completely separated from the data and that both can be processed independently. If a file is moved to another directory, only the management information changes, without affecting the data at all.

The number of data blocks required is a function of the file size. One essential piece of information in the I-node is the specification of where (that is, in which data blocks) the data is stored. If the file is bigger than 12 Kbytes, a I-node points to a block directly in the I-node, a block which itself does not contain any data, but references up to 256 data blocks (single level of indirection).

For files that are larger than 268 Kbytes, this is again insufficient: a further I-node value points to a block that points to another 256 blocks of pointers, which finally leads to 256×256 data blocks (double indirection). Now, the maximum file size is 65796 Kbytes. For even bigger files, triply indirect addressing becomes necessary, which allows access to further 256×256×256 data blocks.

## Directories

In principle, directories are managed in the same way as files. From a points of view, imagine a directory as a text file which lists all files and subdirectories by line. Each line contains the name of a file together with its I-node number. Furthermore, this text file contains a reference to itself (..) and a reference to the next higher directory (.). These two cross-references facilitate and accelerate the management of directories.

This means that the first I-node points to the root directory. The root directory contains all files and subdirectories. Via the root directory, files and subdirectories can be accessed, and so on.

## Hard links

Hard links are simply realized by pointing to the same I-node. This means that a file can have multiple names. This is only possible for files, not for directories.

## Symbolic links

Symbolic links are files that contain a path to another file. If the target file is moved or deleted, the symbolic link becomes broken. This is possible for both files and directories.
