
# Programming

Under Linux you will find a wide range of programming languages: to start with, the GNU and C++ compilers, for which a whole palette of utilities is available (from make to the version control system r and the debugger gdb). Libraries and tool kits allow you to write C programs with graphical user interfaces (such as XWindows), or with 3-D graphics under OpenGL (mesa). Many other programming languages are also available under Linux, as Java, L, Oberon, Perl, Python, Scheme, SmartTalk, and Tcl/Tk. Also, the available shells (bash, shell) are fully programmable.

# Emulators

Linux also offers a DOS emulator which allows execution of many programs (but not Windows 3.1). The Wine project is trying to realize the execution of programs for Windows, but this project is still very much under development. The fact that Unix programs which correspond to the iS2 standard can be executed already been mentioned when presenting the kernel features. Emulators for Atari ST, Commodore 64, Commodore Amiga, Sinclair ZX Spectrum, and so on, are primarily targeted at playful characters.

# Commercial programs

The components listed so far are immediately available (depending on the extent of the distribution and its installation), and with the increasing diffusion of Linux, more and more kinds of commercial programs are being ported to Linux. It is particularly worth noticing that in 1998 all important relational database systems became available for Linux. Thus Linux was recognized as an important server platform by such markets as Oracle. Commercial software (with very few exceptions) is not free of charge.

The following (incomplete) list includes some programs that have been ported to Linux: Adidas database, Applicative Office, Common Desktop Environment, Corel WordPerfect, Flagship database, Informix database, Java-Linux-DBMS, Maple, Mathematica, Metro Link, Netscape Navigator/Communicator, Oracle database, Poet, StarOffice, WABI Windows emulator.

Special mention must be made of Motif: many commercial programs are based on Motif, an extension of the X System through unified control elements and a wide range of supplementary programs. Several Motif versions are available for Linux; however, none of them is free of charge.

There are two kinds of Motif programs: programs containing the Motif statically in their program code and programs relying on Motif being installed and linking the library dynamically. The advantage of the first type: Motif need not be installed. The disadvantage: memory consumption is much higher because each motif program loads its own copy of the Motif into memory.

Motif is sold in two formats: as a package of several libraries sufficient for the execution of Motif programs, or as a development system which allows you to write your own Motif programs. (The second alternative is obviously the more expensive one.)

> Efforts are currently being made to produce a free port of Motif. The project is named LessTif, but it is not as advanced as the Linux system itself. An extensive list of commercial Linux software can be found in the Commercial HOWTO document (see page 77).

# Hardware support

Linux supports nearly all of the common PC hardware. Problems are mostly caused by very recent hardware components (for example, graphics cards) for which no drivers exist under Linux or XFree86. In some (increasingly fewer) cases, new drivers do not fail because of the programmers' lack of motivation, but because the manufacturers are not involved or ready to cooperate, do supply the necessary documentation, or prohibit their use in free code.

Nor is there too much hope for owners of so-called GDI printers and other hardware components exclusively designed for use with Microsoft Windows (such as modems whose modern functions are not realized via hardware, but via Windows software).

The outlook for ISA plug-and-play cards is slightly less bleak: they are not directly supported by the kernel (or only in very few exceptional cases), but they can be configured via the auxiliary programs pndump and isapnp. In most distributions, the automatic call of isapnp is already integrated in the init process. (Prior to this however, you must create the appropriate configuration files! - Organization of Init: this deals with start-up, that is, start of all processes bear different names in all distributions and are located in different directories. There is not even a consensus on assignment of runlevels.
- Live system: some distributions (increasingly fewer) allow operation of Linux directly from CD-ROM. Only a base system needs to be installed on the hard disk. Although this is rather slow and inflexible, it allows relatively easy trying out of Linux.
- Umsdos: some distributions allow installation of Linux in a directory of a partition. This is slow and has innumerable other disadvantages, but save (repartition) the hard disk. As with the live system, this variation too is mostly of interest for trying out Linux (in particular if it can be combined with a live system).
- Target platform: many distributions are only available for Intel-compatible processors. However, there are also distributions for DEC Alpha, SUN Sparc, PowerPC (MacOS), and so on.
- Documentation: some distributions are supplied with manuals in electronic or printed form.
- Support: with some distributions you receive free with the installation (via email and/or phone).
- Configuration of window: this influences the appearance of all.
- Adaptation to foreign languages: distributions still give the impression that English is the only language.
- Package system: administration of Linux programs is usually carried out via packages. The package system influences the ease of installation and updating ones.

- Selection of distribution: among others RPM (Caldera, RedHat, SuSE), TGZ (Slackware), and (Debian).
- Installation media: all distributions are available on CD. Also the availability of one or more CDs, accompanied by a substantial manual, costs not the availability of personal support in case of installation problems.
