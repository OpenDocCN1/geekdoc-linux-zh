# Testing X

After setting up X86Config, X is usually started by means of /usr/bin/startx command. After the X server, this script also starts a window manager (for example fwm, see next chapter). During the startup of X, some messages are displayed (still in the text console). As long as the configuration file does not contain syntactic errors or disagrees with the detected hardware, the graphic mode is activated. Ideally, a stable image should appear straight away – if this happens, the configuration has been successful.

Depending on the configuration, some programs are automatically launched at the start of X. In addition, you can use the mouse buttons to call start programs. At the beginning, the most important program is certain xterm. Like a text console, it allows you to enter commands and start other programs.

You will find further information about the different possibilities for starting X and for selecting and configuring the window manager from page 262 onward. Some X programs are described in Chapter 15 from page 491 onward.

Details about how to start X can also be found in the main pages for startx, open, xwm, xmint, and other.

If no image appears after the execution of startx (that is, if the monitor remains black) or if an image appears, the monitor cannot synchronize its image (the image ‘runs’), you can try switching to a different graphic mode. Usually, the configuration files specify several graphic modes (for example, 640×480 points, 1024×768 points, and on), which you can switch during normal operation of X with Ctrl+Alt+= (on the numeric keypad). Depending on the monitor, a stable image is likely to be displayed in at least some of the modes.

If synchronization of the screen does not succeed, you should exit X as soon as possible to safeguard your monitor. To do this, you press Ctrl+Alt+Backspace*. Under normal circumstances, you should find yourself in text mode (that is, in the console in which you started X). If you strike a bad patch, the screen goes dark or it is impossible to display a stable image. The only thing that helps is a restart (with shutdown or Ctrl+Alt+Del*). In other words: if bad luck strikes, you must reboot your computer after your X test and to do it blind because you can no longer work in text mode anymore: terminate all currently running programs before experimenting with X.

In order to read the output generated during the startup of X even when difficulties occur, you can reroute this output to a file by means of xstart >&log. Instead of starting X you can also execute -probeonly; here, the VGA driver tries to test your graphics card frequencies without actually starting X. Thus, you get back to text mode immediately. This is a relatively problem-free way of checking whether your configuration is set and syntactically correct. You will get the message as well with xstart.
