# Inittab

At start, init is controlled via the /etc/inittab file. inittab entries obey
t following syntax scheme:

```
id-code:runlevel:action:command
```

init-code consists of two characters that uniquely identify the line. The run-
level specifies for which runlevel the entry is valid. action contains an instruction
for init. command specifies which Linux command or program is to be started.

The following list shows the most important action keywords (which you will get a
full description with man inittab:

+   - ctrlldel: specifies how init should react to Ctrl+Alt+Del
initefault: defines the default runlevel for init
once: init starts the specified command when changing to this runlevel
respawn: init restarts the command after it has terminated
sysinit: init starts the command once during the boot process
wait: init waits until the subsequent command has terminated

The following listing represents the slightly inittab file from the
RedHat distribution. The default runlevel is 3. A normal system start, init
exutes scripts rc.sysinit and rc 3. The update daemon is started. (In some
distributions, this daemon of its name, the daemonnmures that buffered data blocks are regularly written to the hard disk.) Finally,
or the text consoles 1 to 6, the getty program is started for login. (If you require
more than six consoles, this is the right place for changes.)

```
# /etc/inittab for RedHat 6.0
# 0 halt 4 - not used
# 1 single user 5 - x11
# 2 multi-user without NFS 6 - reboot
# 3 multi-user with NFS
# Default runlevel
id3:initefault:

# System initialization after reboot
# (check file system, maybe execute fsck, activate swapping,
# mount all file systems listed in fstab)
sii:sysinit:/etc/rc.d/rc.sysinit

# Start of specified runlevel
# (Start of network services, printer daemon, activation of
# local keyboard layout, and so on)
L0:wait:/etc/rc.d/rc 0
L1:wait:/etc/rc.d/rc 1
L2:wait:/etc/rc.d/rc 2
L3:wait:/etc/rc.d/rc 3
L4:wait:/etc/rc.d/rc 4
L5:wait:/etc/rc.d/rc 5
L6:wait:/etc/rc.d/rc 6
```
