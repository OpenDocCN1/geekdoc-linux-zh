
Conversely, when you write DOS files, their carriage return characters are inserted - it feels like heaven!

Automatic conversion only affects ends of lines. The character set special characters in DOS text files remains unchanged. A list of all file extensions excluded from automatic conversion can be found in the file /usr/src/linux/fs/misc.c.

The snake is the recognition of text files. Any file that does not have a well-defined extension (such as *.exe, *.dll, *.gif, and so on) is incorrectly interpreted as a text file. If it is a binary file, it is incorrectly interpreted during access. If, for example, you use tar to carry out a backup of a DOS partition, the chances that part of the backup file is unusable! Thus, although the option conv is very convenient, it is a serious danger! Please activate this option only if you are completely aware of the damage you may cause.

## ASCII → PostScript conversion (a2ps, mpage)

Since Postprinters expect each output in the form of commands, it is not possible to send an ASCII file straight to the printer without prior processing. For ASCII PostScript conversion, you can use the a2ps and mpage commands.

```
a2ps [options] ascii.file > ps.file
```

In the default setting is the recognition of text (that is, without options) a2ps formats the text in a two-column page in landscape format. Both columns are automatically specified with frames and headers. In the following list, only those options are indicated that do not apply as default settings anyway.

- -1 prints one column (instead of two columns in landscape format).
- -L uses the ISO Latin character set. Allows printing of foreign language special characters, but only on Level 2 PostScript printers.
- -n sets the size to n points. This authoritatively affects line spacing and the number of lines per page. n is specified using a floating number.
- -p portrait format instead of landscape.
- -nd, -nl, -nh, -nu
- prints no date, no login info, no header, no file name.
- -ns prints no frame around the text.

There is a detailed man page for a2ps. An overview of all options can be obtained with a2ps -h. In this help text, the default settings are marked through the use of upper case letters.

On my PostScript printer, some problems have occurred with files produced by a2ps: files with special characters (option -8) and man files using the backspace character (cede 8) could not be printed. The reason: a2ps uses PostScript commands which are only officially defined with PostScript Level 2. On older Level 1 printers (depending on the implementation), these commands may or may not be present, and they are obviously missing on my printer. ghostview, by the way, has no problems with either of the special cases. Also, a conversion to HP LaserJet format with gs and printout in this mode (which is possible with most PostScript printers) works fine.

If you want output ASCII on a printer which is PostScript compatible, you can download without the detour via a2ps and gs (Ghostscript). Simply try to copy the file to your printer interface with cp file /dev/... After this command, you will often have to send a form feed character with echo -f" /dev/..." in order to start the printout (of the last page).

Many printers can cope with pure ASCII text and automatically start a new page when the current page is full. You will, however, to do without orderly line page breaks, headers, page numbers and similar pleasantries.

```
mpage [options] source_file > target_file
```

mpage processes the specified source files (ASCII or PostScript format) and writes the new PostScript file to the standard output (which is redirected to the target file). The following list gives only the most important options (there are many more!).

- -1 -2 -4 -8 arranges one, two, four or eight pages on one sheet. With two and eight, landscape format is used. Default is four pages. 
- -A output is in DIN A4 format (default: US Letter).
- -C ISO-8859.1 uses the ISO-8859/1 coding for the character set. This option is necessary to print texts containing foreign language special characters. Other code tables can be found in /usr/lib/mpage.
- -c when printing several files, a new sheet is not started for each file.
- -f long lines run over several lines (default: they are truncated).
- -j n-m only prints sheets n to m (default: all).
- -l prints in landscape with 55 lines and 132 columns and a proportionally smaller letter size (default: portrait, 66 lines, 80 columns).
- -L n prints n lines per page and adjusts the letter size options accordingly (default: 66 lines).
- -o does not print frames around the pages.

- -v prints the sheet number too (default: only the page number).
- -W n prints columns per page and adjusts the letter size accordingly (default: 80 columns).

Like a2ps, mpage can generate a PostScript file from ASCII file. Compared with a2ps, it has two additional features: firstly, mpage can print to eight pages on one sheet (but you will need a magnifying glass to read them), and secondly, mpage accepts both ASCII files and PostScript files as input. ## DVI → PostScript conversion (dvips)

dvips converts *.dvi files into PostScript format. The program automatically changes the extension *.dvi to the file name. *.dvi files are the result of the programs TeX and LaTeX (see Chapter 18 from page 587 onward). *.dvi files are frequently supplied as online documentation for various programs.

- -A converts only odd pages.
- -B converts only even pages.
- -i -S splits the output into files of n pages each. The files are automatically numbered in sequence. This option is important when a longer document is to be output to an imagesetter. Most imagesetters can only expose a relatively small number of pages (typical values are between 20 and 50) at a time.
- -L last_page terminates the conversion with the specified page.
- -o target.file writes the result to the specified file (instead of passing it on to the lpr program).
- -p first_page starts the conversion with the specified page.

- -pp n1,n2-n3,n4,n5,n6-n7 print the specified pages. Please note that there must be no spaces in the page list.

LaTeX documents generally do not use the original PostScript character sets, which character sets specially created for LaTeX. This has the advantage that a subsequent conversion of the PostScript file into the format of a different printer is possible with almost no loss of quality. If the LaTeX character sets have not been included during a previous printout (compressed bitmap files), then for each character set, dvips automatically starts the LaTeX font program Metafont. A first time conversion of a LaTeX document into a PostScript file can take a relatively long time.

dvips is normally installed in such a way that it generates LaTeX character sets at a resolution of 300 dpi (dots per inch). If you want to print the LaTeX document to a printer with a different resolution, you must modify the file /usr/TeX/lib/texmf/dvips/config.ps. All further information on this, which is LaTeX-specific, can be found on page 623.

```
dvilj [options] dvi_file

dvilj4 [options] dvi_file

```

dvilj is a variation of dvips used for a direct conversion of *.dvi files into the format of HP Laserjet compatible printers. If you do not possess dvilj, you must first use dvips to generate a PostScript file and subsequently convert it into HP format with gs. This is more long-winded, but entails no loss of quality.

- -gfile writes the result to the specified file.
- -page.number starts the printout with the specified page number.
- -l prints in landscape format.
- -sn sets the paper format. The following are some of the values that are permitted for m: 26 for DIN A4, 90 for DL size envelopes (11×22 cm²) and 91 for C5 size envelopes (16.2×22.9 cm²).
- -page.number terminates the printout with the specified page number.

Calling dvilj without any options causes the specified DVI file to be processed. As a result, the program supplies a homogenous file with the extension .tj for printing on a 300 dpi HP Laserjet printer. The commands dvilj2p, dvilj4 and dvilj4t work in a similar way, but specifically support the specified models (including 600 dpi resolution and built-in TrueType and Intellifont character sets).
