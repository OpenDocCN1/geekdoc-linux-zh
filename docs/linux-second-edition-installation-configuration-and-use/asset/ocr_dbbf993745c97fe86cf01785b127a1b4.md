# bash version 2

bash version 2 has been available for some time, although some distributions still supply version 1.14, which is considered to be very stable. (Execute echo $ASH_VERSION.) Programmers may have some problems with the bash version: the bash was practically fully adapted to the POSIX standard. Some syntax variations were still tolerated by bash 1.14, and are now considered as syntax violations and lead to error messages. In particular, this concerns missing semicolons in command chains which up to now were used to be accepted:

+   - bash 1.14: { command1; command2; command3 }
- bash 2.0: { command1; command2; command3; }

A similar problem can occur with case-es blocks: the last of such a construction was up to now also executed when the two closing semicolons were missing. Since version 2, these semicolons are mandatory. Many more details about new features and potential incompatibilities which have nearly exclusively caused by errors in the previous bash implementation can be found in the files contains the /usr/doc/bash/ or man directories. As long as you use shell programs for your own use and a change of shell or the use of your program by others is improbable do without the shell identification. The same applies when you are sure that all shells will have no difficulties in executing your file, that is, if you have not used any shell-specific features. Most problems derive from the syntax differences between the C and most other shells.

Shell scripts can only be executed if the access bits for read (r) and execution (x) are set (chmod +r file). The first line of a shell script must not contain any foreign language special characters, not even in comments. Otherwise, the bash refuses to execute the file and comes up with the message 'cannot execute binary file.'
