## 2.7 Installation variations

This section summarizes information on several types of installation which, in practice, occur frequently. Always, the details largely depend on the distribution in question – please check the manual or the online documentation.

## Installation from hard disk

An installation from hard disk becomes necessary if neither a CD-ROM drive nor a network connection is accessible during installation. In this case, you need to copy all required data to your hard disk prior to the installation. (This means that at least at this stage – for example in operation under Windows – a CD-ROM drive must be attached or a network connection must be accessible.)

Not all distributions support installation from hard disk. The problem is that, during copying the installation files from the CD-ROM to the hard disk under DOS/Windows, the file names are destroyed. If the names of relevant files are not limited to 8+3 characters in the first place, the distribution must also be able to cope with truncated filenames. (SUSE uses short file names, and RedHat can cope with mutilated filenames.)

A further problem arises from the need for additional space – in most distributions, the installation data take up several hundred MBytes! After you have copied the required data to your hard disk, you can start the installation in the same way as your previous attempts, with the difference that you no longer specify a CD-ROM drive as installation source, but the hard disk partition in which the copied installation files can be found (for example, /dev/hda1 for the first primary partition on the first IDE hard disk). The only point that might cause trouble - the choice of the appropriate hard disk partition. The Linux naming conventions for addressing of hard disks are described on page 37.

## Installing Linux via a network connection

The common denominator in this section is that the installation data is neither loaded from a CD-ROM drive nor the local hard disk, but via a network connection from another computer. Depending on the distribution, there are up to three variations:

- FTP (File Transfer Protocol): the installation data is read from FTP server. This variation is particularly suitable for universities if the required Linux distribution resides on the local university server.

- NFS (Network File System): the installation data is read from another Unix or Linux computer. The host computer needs to be configured as an NFS server (see page 177): the directory containing the installation data (or the path leading to the CD-ROM drive of the NFS server) must be accessible via NFS.

- SMB (Server Message Block): this variation is comparable with NFS, except that, instead of NFS, the standard SMB protocol is used.

All three variations presume that your computer is equipped with a network card and that it is correctly cabled. Furthermore, the installation kernel must recognize the network card and provide the appropriate module.

During installation, you will be prompted to supply the following information. (Details on the technical terms used in this context can be found from page 171 onwards, in the description of the basics of network configuration).

## Network device

The network device to be used – normally eth0 (the first Ethernet card).

## Host and domain name

In principle you can enter any name of your choice, as this name will only be used during the installation. The host name must correspond to the setup of the NFS server (The server might, for example, be configured in such way that you can access the directory with the installation data only by a certain name defined by the system administrator.)

## IP number of the local computer

Here, you are expected to enter a number of the format 192.168.5.5 – the IP number must fit into the local network and should be unique.

## Network and broadcast address

These IP numbers describe the extension of the local network (generally).

## Name server address

If a name server is running in the local network, you can specify its IP number. If no name server exists or you do not know its IP number, you need to specify it at a later stage.

## Name or address of FTP/NFS/SMB server

This is computer from which the data is read.

## Mount point

This specifies the path leading to the installation data (for example, /mnt/cdrom).

## User name and password

These specifications may be omitted if (unusual). As soon as access to the installation data is successful, the remaining installation is carried out from a CD-ROM.

## Umsdos - Linux for tasting

The abbreviation Umsdos is a combination of the terms UNIX and MS-DOS, an extension of Linux which allows the immediate use of the MS-DOS file system. Thanks to Umsdos, it is possible to install and execute Linux without the awkward repartitioning of the hard disk. In spite of the restrictions of the DOS file system, long file names are available, links can be established, and /dos is the path separator instead of on. All Linux-specific information is stored in each directory. This is visible from within Linux. When accessing from DOS/Windows, this file must in no case be deleted!

At first sight, Umsdos looks like simplicity itself. Unfortunately, Umsdos has disadvantages that intensive use of this system:

- The file system is based on the MS-DOS file system. Even if you do not use Umsdos, management of the file system is slower and more error prone.
- Under Umsdos, some file types - especially links or very small files - take up disproportionate amount of disk space (as opposed to the ext2 file system used under Linux).
- The file system is not protected against access by MS-DOS – that is, you can alter or delete Linux files from within Windows.
- Instead of swap partition, a swap file has to be used (This makes Umsdos inefficient).
- While Umsdos was used to be popular in the past, there are very few distributions which still support Umsdos (Slackware, SuSE).

Umsds is therefore not a viable alternative for professional use of Linux, if you just want to try out Linux without turning your whole computer out, and this variation is quite interesting.

For MS-DOS, Linux simply requires the Linux directory. For Umsdos, all DOS files can be accessed via the path /dos. Both file systems remain on the hard disk in parallel; the more space one file system requires, the less space remains for the others. When you delete Linux files, the space is again available for MS-DOS – and versa.

The installation of Umsdos is in principle the same as that of Linux, only without the partitioning of the hard disk. You specify an arbitrary partition as the installation partition. The partition is not reformatted! (The installation program should not offer this possibility.)

Although Linux and DOS/Windows share a common file system, switching between the two is only possible without a restart. Under DOS/Windows, all Umsdos files in the Linux directory are visible and accessible, but only under their abbreviated names (8+3 characters). The opposite case, that is, access of DOS files under Linux, is much easier: the DOS file system is mapped under Umsdos in the directory /dos.

## Problems before, during, and after installation

## Boot parameters

When Linux breaks down while loading the kernel, the cause is nearly always hardware problems. Problems can arise both during the first boot installation and after a successful installation (if the installation program installs a different kernel from the one used during the installation itself).

Options during booting are forwarded via LILO to the kernel may help with hardware recognition. Please note that the options specified at LILO start-up only influence the drivers integrated into the kernel. Drivers which are loaded as modules at a later stage may also be influenced by options, but only if the installation program provides a possibility for entering such options.

In order to enter boot options, press the Shift key during LILO start-up, and an input prompt appears. If you press Tab, the available kernel names are displayed (if also names for booting other operating systems). The syntax for booting with additional options is:

```
kernelname hardwaresettings=hardwaresettings
```

hardware denotes a hardware component (such as a CD-ROM drive, an Ethernet card, and so on). The settings to be used must be without blank spaces (for example, ether=10,0x300,0,0,eth0). If settings are to be made for several components, they are separated by spaces (not by commas!).
