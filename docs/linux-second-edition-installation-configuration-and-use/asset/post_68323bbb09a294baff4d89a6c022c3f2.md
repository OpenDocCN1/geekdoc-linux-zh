In its configuration, Red Linux does not use shadow passwords; in its default, it uses the so-called PAM (Pluggable Authentication Modules) tools for authentication of users. Configuration of PAM is carried out via the files in /etc/pam.d. Comprehensive documentation can be found in /usr/doc/pam-n.

### Access privileges

As root, you automatically have access to all system files and devices (devices like files and allow access to the hardware — such as /dev/tty1 for the second reality interface which is often connected to a modem). If instead, log in as a normal user without root privileges, you will find that a number of devices are denied to you: you can no longer access diskette devices, you cannot use the modem, and so on.

On single-user systems this is easily remedied by specifying more liberal settings for the rights to access devices. You simply log as root, change to the /dev directory and execute the following chmod command for the devices in question:

```
# cd /dev
# chmod a+rw fd *
```

/dev/fd* (all devices that point to floppy disk drives) must be substituted by the relevant name, such as ttyS* for the serial interfaces, lp* for the parallel interfaces (printers), and so on.

If you are not the only person to work on your computer, chmod a+rw represents a considerable security risk. You can distribute access privileges in a more controlled manner by listing those users in specific groups (for example, wctp in /etc/group who are allowed to access files or devices of that group (for example, the serial interface for modem use). Thus you can leave the bits of the device files unaltered. You will find further information about access privileges from page 90 onward.

## 6.5 File system administration

If Linux is properly configured, you can access various hard disk partitions, the CD-ROM, and so on, immediately after the system has started up. This section will deal mainly with the fstab file, which is responsible for all this. Furthermore, we describe how to create swap partitions and swap files.

TIP Additional background information about the internals of the file system can be found in Chapter 5 from page 100 onward.

![](img/b30873dd3d753687a59253fb9ad26a0b_174_1.png)

### The fstab file

/etc/fstab file specifies which storage devices are to be mounted into the file system. In any case, fstab must contain the following two lines (which, depending on your configuration, may look slightly different). Further hard disk partitions, CD-ROMs and diskettes can be mounted manually using the mount command.

```
# # two sample lines in /etc/fstab
/dev/hda2 / ext2 defaults 0 1
/proc /proc defaults 0 0
```

The first line creates the system directory on the second partition of the first IDE disk. Depending on which hard disk partition you have installed Linux in, you must specify the device name of your own Linux partition instead of /hda2. The second line mounts the process administration system into the file system. The files and directories of the /proc directory do not really exist on the hard disk; they are just an image of the data which is used by the kernel for process administration.

The two lines clearly show the format of fstab: in the first column, the device name of the storage device must be specified. (A number of examples of the naming conventions for hard disk partitions can be found on page 37.) If re computers: directories must be mounted via NFS, the device name is computer:directory.

The second column specifies at which point the storage device is mounted in the directory tree. Unlike DOS, administrators use several hard disks as separate systems (which are accessed via C:, D:, and so on), Linux uses a unique directory tree. The directories specified in the second column must already exist in the root file system. The directories do not need to be empty, but after a successful mount process, you can no longer access the files contained in them (you can only access the files of the mounted storage device).

The third column specifies the file system.

- ext2 Linux standard
- hfps OS/2 (read only)
- iso9660 CD-ROM
- minix commonly used for Unix diskettes
- mdos DOS partitions or diskettes
- nfs access to directories of other computers via network
- ntfs Windows NT file system (NT 4, read only, from kernel 2.2 onward)
- proc process administration
- swap swap partitions or files
- vfat Windows 9x file system (FAT32 from kernel 2.2 onward)

The fourth column specifies the options for the storage device. Several options must be separated by commas, (no spaces).

mount options:

- block=n block size (for example, for CD-ROM drives)
- conv=auto automatic conversion of DOS text files (page 504)
- exec allow program execution (for CD-ROM drives)
- default default setting
- gid=n group membership of files

- noauto data not automatically mounted
- noexec program execution allowed
- ro read only (write protection)
- swap swap file or partition
- sync buffering of write accesses (slower, safer)
- uid=user ownership of files
- umask=mask access bits of files

The options guid, uid= and umask= can be used to preset privileges for files. This makes sense for file systems for which this information cannot be stored or evaluated by Linux (DOS, Windows, OS/2). Without the use of this option, DOS files are owned by root; these can be read by all users, but only modified by root. The three options allow more liberal access.

Please note that umask is interpreted firstly as an octal value and secondly as the value of the chmod command (page 444). umask=0 means every user is allowed to read, write, and execute all files. umask=111 sets the execute bit to 0, but still allows read and write.

The option noauto means that the storage device mentioned in this line is not immediately available, but it can be mounted with mount without having to specify mount options explicitly or (all missing specifications are automatically read from fstab). This can be, for example, useful for CDROM drives or cannot normally mounted. Also, a partition not mounted into the system cannot be destroyed.

The user option allows users to unmount and remount the file system with unmount and mount. Normally, only root can do this. The user option is particularly useful when frequent media changes are needed (diskettes, CD-ROMs).

The sixth column contains information for the dumps program and is presently ignored. The root directory should be assigned the value 1, all other file systems 2. File systems that are not to be verified (for example, CD-ROMs, proc and swap) are assigned 0.

Information about fstab can be obtained with man fstab. Further information that also applies to fstab can be found in man mount. In particular, 30 options are described that apply equally to mount and fstab. In practice, fstab is a centralized collection of options that are then passed to mount.)
