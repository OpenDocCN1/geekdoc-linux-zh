## 13.4 Loops

The bash has three commands for the construction of loops: for executes a loop for all elements of a given list, while while executes a loop until the condition is no longer satisfied, whereas until executes a loop until the condition is satisfied for the first time. All three loops can be prematurely exited with break. continue skips the remaining body of the loop and continues with the next cycle.

## for loops

In the first example, the variable i is assigned the character strings 'a', 'b', and 'c' one after the other. You can only omit the semicolons when you spread the input over several lines (which, in script files, is often the case).

## Text conversion filters

On page 503, you find a description of the commands from dos2linux, todos and recode which convert text files between DOS and Linux. If the only task is to eliminate a carriage return character at the end of each line (DOS → Linux) or to insert it (Linux → DOS), you can obtain the same result by means of two small filters.

First, we will look at the conversion from DOS to Linux, in which all CR characters must be eliminated. This can be done by using the tr command. This command reads data from the standard input, replaces or deletes characters and writes the result to the standard output. tr -d '\r' removes superfluous spaces. To make the code of doslinux as easy as possible, the following program provides three application variations:

```bash
user doslinux file
user doslinux source.file target.file
user doslinux < source.file > target.file
```

In the first variation, dos2linux reads the file and writes the result back to the same file. In the second variation, the source file is read and the result is written to the target file. In the third variation, dos2linux is used as a filter. This would also allow you to use the program in the following format:

```bash
user cat.dos | dos2linux > /dev/null
```

The specified file is directed with cat to the standard output, filtered by dos2linux and finally directed to the first interface (printer). The program code for dos2linux contains few surprises. The syntax is distinguished by the number of parameters. If more than three parameters are passed, the command displays a help text. Output is carried out by cat to interpret the text until the EOF occurs.

```sh
#!/bin/sh
# dos2linux: eliminates CR characters
if [ $# -eq 0 ]; then # use as filter
tr -d '\r'
elif [ $# -eq 1 ]; then # process one file
tr -d '\r' < $1 > $1.tmp && mv $1.tmp $1
elif [ $# -eq 2 ]; then # process two files
tr -d '\r' < $1 > $2
else # process more or more
cat << EOF
dos2linux: eliminates CR characters in text files
Usage: dos2linux source_file target_file
EOF
```

## mv and cp for regular expressions

Because of the automatic substitution of special characters as * and ?, commands as mv *.old are not possible in Linux. In such cases, advanced users use a tiny for loop to include all required files, and use substitution commands to change the file names (see page 412). The following instruction, for example, substitutes all *.eps files with *.ps:

```bash
user$ for i in *.eps; do mv $i ${i%.eps}.ps; done
```

Such solutions may prove the power of the bash, but in the end, they are far tedious for daily management of files. It is therefore obvious that such operations need to be simplified. The two commands presented here are regmv and regcp, representing variants of mv and cp. A string enclosed in single quotes must be passed as a parameter. The source file pattern and the target file pattern must contain exactly one asterisk. The following examples show the application of the two commands:

```bash
user regmv *.eps *.ps      # renames all *.eps files as *.ps files
user regmv pic*.eps p*.ps          # renames pic*.eps as *.ps
user regmv *.old                # renames all *.files as *.old
user regcp *.dup                # makes a duplicate copy .dup of all files
user regcp *.bak               # copies all files, new *.bak
```

The program of these two commands is not too easy to understand. In principle, it is nothing but a repeated application of the command substitution used in the previous example.

For the following description of the command, we assume that the command was passed the string pic*.eps p*.ps. This parameter is split into two parts at the position of the space and stored in two variables (pic*.eps in source and p*.ps). Subsequently, source and target are split into two parts at the position of the * (pic in source1, in source2, and so on).

If source and target contain characters at all, a check is made to whether the number of characters in source is exactly one higher than in source1 and source2. If this is not the case, either too many wildcards have been passed or none at all. An analogous check is also made for target.

The instruction files=$(echo $source) does not simplify a duplication of source. On the contrary, for execution of $source, the usual expansion of wildcards is carried out. Therefore, files subsequently contains the list of all files that match the source pattern. The following test checks whether any match the source pattern and the command is aborted with an error message.

If everything has gone well, the copy command for each file found is executed in the loop. Piece by piece, the new file name is assigned in the variable tmp. In the first step, the first part of the source pattern (pic) is eliminated from the filename, in the second step the second (.eps) is removed. In the third step, the filename is expanded with the two parts of the target pattern (p and .ps).
