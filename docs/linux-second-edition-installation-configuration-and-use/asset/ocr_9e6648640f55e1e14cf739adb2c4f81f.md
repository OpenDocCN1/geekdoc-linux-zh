# DAT exchange between different Unix systems

The exchange of DAT streamer tapes read and written on different Unix systems often causes problems (there is no sign of a standard!). The following paragraphs give some hints which are in part result of the author's own experience, and in part based on relevant articles found in Linux newsgroups.

The most probable cause of errors is a number of blocks (option -b) which must match when reading and writing. It would appear the tar commands in every Unix variation use a different number of blocks as their default setting. In GNU tar, default setting is -b 20. You may also have to change the default setting of the streamer with mtblk n. On some Unix systems, besides the manager's original tar, you will also find an installation of GNU-tar, which in this case must be addressed as tar.

If nothing helps, there are other ways of exchanging data via a DAT tape. One variation consists in using the cpio command. Still one level below, we find the dd command, for writing you use dd if=/dev/streamer, for reading dd if=streamer of=/dev/file. With the dd option conv=swap, you can invert the byte order, if necessary.

If you do not want to do without using tar, you can also use pipes. The command for writing data to a DAT tape looks like this:

```
root tar -cvf data | dd obs=10240 of=/dev/tapedevice
root dd bs=10240 if=/dev/tapedevice | tar -xvf
```

# SGI

For writing data on an SGI system, it has proven useful to use the device tps0d3ns files. tar cvbf /dev/rmt/tps0d3ns files. To be subsequently read the data under Linux, you must first set the block size to 512: mt setblk 512. Now tar should function without further problems.

# tee file

tee duplicates the standard input, displaying one copy and saving the other copy in a file. In is useful when the output of a command is to be viewed on screen but simultaneously saved in a file. A simple redirection into a file with > would result in nothing being on screen.

Example

```
user ls -l | tee contents
```

displays the contents list of the current directory and simultaneously stores it in the file contents.

# todos file

```
todos source > target
```

todos appends a carriage return character to each of the lines of the specified text file. Thus, the text file can be processed under DOS as usual (see also fromdos on page 458 and recode on page 476).
