The following digit indicates the main version number. Thus, ls requires ver-
s 6 of the Libc. As you can easily find out with ls, libc.so.6 is in reality
a link to the actual library, Libc-2.0.7 (thus, libc 2).

```
ls -l /lib/lib* /lib/lib.*
-rwxr-xr-xr 1 root 306150 May 10 1998 /lib/lib-2.0.7.so
-rwxr-xr-xr 1 root 13 Jun 1998 /lib/libc.so.6 -> /lib/libc-2.0.7.so
```

In typical library directories (mostly /lib, /usr, /usr/local/lib,
/usr/X11/lib, and /opt) you will find links from the main library version
to the actually installed library.

At the start of a program, the matching libraries are found in the following way-
ld.so is responsible for the links between program and libraries. To prevent
this so-called runtime linking from searching all directories for such libraries,
it evaluates the /etc/ld.so.cache, which is a binary file containing all relevant
library data (version numbers, access paths, and so on).

In distributions, the /etc/ld.so.cache is automatically updated at
each system start-up by means of the ldconfig. When new libraries are
installed, ldconfig must be executed manually. If needed, ld.so.config must pre-ly extended with new libraries. Depending on the distribution, this is one
by the package manager or the setup program.

ldconfig evaluates /etc/ld.conf. This file contains a list of all
library directories. In Debian 2.0, for example this list looks as follows:
/usr/X11R/lib/Xaw3
/usr/lib/libc5-compat
/lib/libc5-compat
/usr/X11R/lib

The directories /lib and /usr/lib are searched in any case and are therefore
left out in ld.so.config.

# Libc updates

Sometimes, an update of the libc library becomes necessary to run new programs
which require an up-to-date version of this library. This may be the case when
ld does not signal any problems. For example, according to ld, the program only
requires libc version 5; actual, however, it runs only from 5.4.4 onwards (such
the setup program of StarOffice). If only version 3.12 is installed, there will be
problems.

Please note that a libc update is a dangerous intervention in the system. On the
hew hand versions sometimes work only if an up-to-date version of
l (and potentially of other programs) is installed as well. On the other hand,
during a library update the link from the main number of a library must never
(not even temporarily) point into the void! This would completely block the
system, because practically no command can be executed without libc!

Please avoid using packages of another distribution for such update, since
the administration of library files is largely distribution-dependent.
