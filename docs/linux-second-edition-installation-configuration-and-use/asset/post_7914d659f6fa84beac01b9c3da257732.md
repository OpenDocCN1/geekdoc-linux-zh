
# Vertical frame frequency (vertical refresh)

The vertical frame frequency indicates how many times (per second) the whole screen area is redrawn. The larger this number, the more stable the image appears. From around 70 times per second (70 Hz) onwards, the image appears to be flicker free.

# Horizontal line frequency (HSync)

This frequency indicates how many lines per second are scanned by the electron beam. With an image resolution of 640×480 points (thus, 480 lines) and a frame frequency of 60 Hz, the horizontal line frequency amounts to 31.5 kHz (If you are checking my calculations, it is true that 60 times 480 only makes 28.8 kHz. The slightly higher frequency is needed to account for the time used by the vertical flyback.)

# Pixel frequency (video bandwidth)

This frequency indicates how many image points (pixels) are transmitted from the graphics card to the monitor in the space of one second. With 640×480 points and 60 Hz, the outcome is a value of 18.4 MHz. Due to the overhead caused by horizontal and vertical flyback, the actual pixel frequency is 25 MHz.

# Interlace mode

Interlace mode is a reliable method for developing a headache in a very short time and eye trouble in the long run. For the construction of the image, not every line is considered, but only every second. Thus, the first frame is composed of lines 1, 3, 5, and so on, the second image of lines 2, 4, 6, and so on. In this way, a higher resolution can be achieved in spite of a low pixel frequency. The result, however, is a slightly flickering image if you do not use a monitor with an extremely persistent phosphor.

# The monitor

The image construction is determined by two hardware components, the monitor and the graphics card. The monitor is probably easier to understand from the technical specifications viewpoint. For modern monitors, the relevant data are:

- * the vertical synchronization range (frame frequency, for example 50 to 90 Hz),
- the horizontal synchronization range (line frequency, for example 30 to 57 kHz),
- the maximum bandwidth (pixel frequency, for example 75 MHz).

Older monitors cannot be set to any of the frequencies within these ranges, but only support a few tied frequencies. Synchronization problems occur when the graphics card sends a stream of data to the monitor, which cannot be correctly interpreted. This may happen when synchronization impulses are transmitted too early, too late, or too weakly, or when the frequency limits of the monitor are exceeded.

Exceeding the frequency limits (in particular, the maximum line frequency) – which happens when the graphics cards supply too much data fast – may be dangerous. In such a case, the electron beam of the monitor can no longer follow the data, parts of the screen or even the whole screen are irradiated for too long and too intensively, and thus they overheat and for relatively short time (a matter of a few seconds) they are destroyed.

> CAUTION
> Exceeding the maximum bandwidth is, however, quite (as long as the maximum line frequency is kept). The result is usually a smudged image because the signal amplifier of the monitor is overloaded. For this reason, in more recent configuration programs the bandwidth is no longer taken into account.

# The graphics card

The main task of the graphics card is to supply pixel data for image construction. (In addition, the card should support drawing operations – but this is not relevant here.) All current graphics cards can generate several graphic modes with different resolution and frequency – maybe even modes your monitor might not be able to cope. Frequencies play an important role for the graphics card as well. While the monitor must understand the data stream supplied at a pixel frequency, generation of this frequency in the graphics card is a technical problem. Older graphics cards can only generate a few predefined frequencies, while modern cards are equipped with a freely programmable generator. Frequencies provided by older graphics cards are an important element in configuration of the video driver.

# Colors

Colors are no problem as far as the monitor is concerned. The monitor simply receives an analog value that reflects the intensity of a color component (red, green, blue). For the graphics card, on other hand, colors constitute a problem: on one hand, the greater the number of colors, the more data must be processed for each pixel. An image with 256 colors takes twice the memory space of one with 16 colors. Modern graphics cards reach data streams up to 200 MB per second. On other hand, each digital pattern of a pixel may be converted into an analog signal. The digital/analog converters (DAC) are required for this purpose, however work only up to a certain frequency. For many video cards, the DAC frequency is lower than the bandwidth supported by the card. Also, some graphics card manufacturers have grown into the habit of changing DAC chips all the time; for this reason, you must enter the precise denomination of the DAC into the configuration file for some graphics cards.

# Accelerator cards

These are graphics cards where drawing operations are supported by a dedicated graphics chip. While with older cards the computer itself must move every pixel in an area, accelerator cards are capable of performing such operations on their own. This takes some load off the computer (CPU); each manufacturer uses different chips to accelerate graphical operations; thus, for each family of cards a specific driver is needed.

# The configuration process

The aim of the following explanations is to achieve a flicker-free monitor image of the highest possible resolution. Further details of X configuration (X resources, window manager) are the subject of later sections from page 260 onwards. The central configuration file for XFree86 is XFree86.config. This file contains all the relevant data relating to your graphics card and monitor in text format. To modify this file, you must log in as root.

Unfortunately, depending on the distribution, XFree86Config is found in different locations (/usr/X11R/Lib/X11/XFree86config is usually only a link somewhere to the etc directory):

- /etc/X11/XFree86Config
- /etc/XFree86Config SuSE
- /usr/X11R/Lib/X11/XFree86 default

Depending on the distribution, a whole palette of programs is there to help you with the creation of XFree86Config:

| Program | Page |
| :--- | :--- |
| XFree86Setup | 230 |
| xfree86config | 234 |
| xvidtune | 234 |
| Xconfig (RedHat) | 725 |
| sax (SUSE) | 740 |

Independently of which configuration program you use, you will often have to retouch the configuration file manually — more on page 235 onwards.

> CAUTION
> Never use an XFree86 configuration file borrowed from a friend or a colleague, downloaded over the Internet or obtained from somewhere else without adapting the monitor section to the data of your monitor first (see below) — otherwise you risk the premature demise of your monitor!

In most distributions, you are already prompted to select one of these drivers during the installation of Linux.
