## Keyboard configuration

Under X, the keyboard is a source of permanent frustration. Programs designed for text mode no longer react to function keys Home, End, and so on. Even with true X, whether we will recognize the most important combinations is something of a gamble. The main cause of this is the different origins of the programs – some from the world of Motif, others have been developed over OpenLook, and so on.

Surprisingly enough, it is not the foreign language characters that cause problems, but the function keys (down to the everlasting Unix problem of how to differentiate Backspace and Del). In this section we will try to provide the most important background information and present the different files that affect the keyboard under X.

## Keyboard options in X86Config

If you use an XFree86 X server, the file X86Config is the central point for keyboard configuration. For a U.S. keyboard, the Keyboard section should look as follows ('pc104' for a Windows keyboard):

```
# Keyboard setting in X86Config
Section "Keyboard"
Protocol "Standard"
XkbRules="xfree86"
XkbModel="pc104"
XkbLayout="us"
XkbOptions="grp:switch"
EndSection
```

## CONFIGURING THE X SERVER

For fine-tuning, you can also use the xvidtune program or its KDE kvidtune, which allow you to vary part of the timing values interactively during normal operation of X.

Various options can be added to the ModelLine lines: Interlace for the interlace mode (only possible with an odd number of virtual lines), /+Hync and +/-Vsync to change the polarity of the synchronization impulse, plus Composite and +/-Csync for a combined synchronization signal (includes both HSync and VSync).

The following example shows the monitor's section for his nearly age NEC 4D monitor. Three resolutions are defined: 640x480 points at 71 Hz, 816x612 points at 75 Hz, and 1024x768 points at 63 Hz.

HorSync 30-57

ModelLine "816x612" 50 816 824 960 1040 612 612 614 635

EndSection

## Screen

The Screen section indicates which Monitor is to be combined with which VGA device. The section contains one or more Display subsections. Each subsection applies to a specific color depth (8, 16, or 24 bpp, bits per pixel).

Each Display section contains a list of all graphic modes to be supported. This list begins with the keyword Modes and contains the names of the graphic modes defined above in ModelLine. The order is significant – the first mode is taken as the default mode. You can switch to the other modes in order with Ctrl+Alt+- or = (numeric keypad).

Graphics cards with sufficient memory allow you to use Virtual to define a virtual screen which is larger than the currently visible section. With the mouse you can move around this virtual screen without delays. You should, however, not use the whole available memory for the virtual screen, but should leave some space for a font cache (this leads to a significant speed increase). The keyword ViewPort specifies the first visible pixel at the start of X (only of interest if the virtual screen is bigger than the actual resolution).

With a virtual screen getting used to. If the virtual screen automatically set up by most configuration programs bothers, you need to comment out the Virtual instruction. (In this case, the size of the virtual screen is oriented towards the highest-resolution graphics mode specified in the Screen section.)

```
Section "Screen"      # for an SVGA card
Driver "vga256"
Device "sigma legend 11"
Monitor "nec 4d"
Subsection "Display"
    Depth               8 # bpp, thus 256 colors
    Modes              "1024x768" "64x480" "816x612"
    Virtual            1024 900
    ViewPort           0 0
EndSection
```

With some accelerated VGA sections, several Display sections with different color depth (8, 16, 24, or 32 bpp) can be displayed simultaneously (see manF86.Accel. At the start of the X server, the 8-bpp mode is activated. The Display sections with higher resolutions come into play only if start a higher color depth is explicitly set by means of --bpp 16 or 24. Alternatively you can change the default mode by specifying DefaultColorDepth n in the Screen section.

```
Section "Screen"
    "Accel"
Driver
Device             "Primary Card"
Monitor            "Primary Monitor"
DefaultColorDepth24
Subsection "Display"
    Depth               8
    Modes              "1280x1024" "1152x864" "1024x768"
EndSubsection
Subsection "Display"
    Depth               16
    Modes              "1280x1024" "1152x864" "1024x768"
EndSubsection
Subsection "Display"
    Depth               24
    Modes              "1280x1024" "1152x864" "1024x768"
EndSubsection
EndSection
```

## Testing X

After setting up X86Config, X is usually started by means of /usr/bin/startx command. After the X server, this script also starts a window manager (for example fwm, see next chapter). During the startup of X, some messages are displayed (still in the text console). As long as the configuration file does not contain syntactic errors or disagrees with the detected hardware, the graphic mode is activated. Ideally, a stable image should appear straight away – if this happens, the configuration has been successful.

Depending on the configuration, some programs are automatically launched at the start of X. In addition, you can use the mouse buttons to call start programs.

## Keyboard configuration

Under X, the keyboard is a source of permanent frustration. Programs designed for text mode no longer react to function keys Home, End, and so on. Even with true X, whether we will recognize the most important combinations is something of a gamble. The main cause of this is the different origins of the programs – some from the world of Motif, others have been developed over OpenLook, and so on.

Surprisingly enough, it is not the foreign language characters that cause problems, but the function keys (down to the everlasting Unix problem of how to differentiate Backspace and Del). In this section we will try to provide the most important background information and present the different files that affect the keyboard under X.

## Keyboard options in X86Config

If you use an XFree86 X server, the file X86Config is the central point for keyboard configuration. For a U.S. keyboard, the Keyboard section should look as follows ('pc104' for a Windows keyboard):

```
# Keyboard setting in X86Config
Section "Keyboard"
Protocol "Standard"
XkbRules "xfree86"
XkbModel "pc104"
XkbLayout "us"
XkbOptions "grp:switch"
EndSection
```
