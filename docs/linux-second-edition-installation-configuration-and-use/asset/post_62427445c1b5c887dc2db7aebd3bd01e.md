
## /etc

contains the configuration files for the entire system. These files control the boot process, the keyboard layout, and the default settings for various Linux components (for example, network configuration) and various programs (such as emacs). Following the FHS rules, configuration-specific files should be located in the /etc subdirectory, however, this convention is not adhered to by all distributions. Many files in /etc are described in chapters dealing with configuration from page ... onwards.

## /home

contains the home directories of all users. The home directory is defined as the directory in which the user finds himself after logging in and for whose files he has unrestricted rights. Theoretically, the system administrator (root) can also create directories outside of /home. The reason for this is that user directories lie on their own partition or disk, which may be temporarily inaccessible.

## /lib

contains shared libraries or symbolic links to them. These files are needed for the execution of programs. /lib contains kernel modules, which are dynamically activated/deactivated in current operation.

## /lost+found is the place where lost or incomplete or corrupted files which result from improper repair of the file system after exiting.

## /mnt

contains subdirectories, such as cdrom and floppy, where external file systems can be linked in. In many systems, the linking of foreign file systems takes place directly in /root (for example, /cdrom). This is against FHS rules, but somewhat easier typing.

## /opt

contains additional packages which can be installed at a later date. In many systems, office and other programs are installed in this location. Another possible place for such programs is /usr/local.

## /proc

contains subdirectories for all running processes. The /proc directory only reflects the Linux-internal process administration (see page ...).

## /sbin

contains system administration commands. A common feature of all programs stored in this directory is that they can only be executed by root.

## /tmp

contains temporary files. Often, however, temporary files are also stored in /var/tmp.

## /usr

is the most important directory for the typical user. It contains all application programs, the complete system source codes and so on. Ideally, the /usr directory should contain only static (invariant) data. The separation of static and dynamic (variable) data becomes very important when Linux is to be run directly from CD-ROM (read-only); then, the CD-ROM contains all static data and the /var directory contains all dynamic files. This would have the advantage of better security (and the disadvantage of more laborious maintenance).

## /var

Important subdirectories are adm (distribution-specific administration files), lock (locking files for access protection of devices), log (files), mail (email files, often stored in spool/mail) and spool (buffered printer files, news and so on). Thus, the basic structure of directories at root level is fairly easy to understand. The problems with the subdivision of /usr and /var into innumerable subdirectories are that many directories are called the same as those at root level - for example, bin for executable programs. Another problem is that there are several groups of executable programs: oriented commands, X programs and so on, and an equal number of possibilities to hide these programs. Often, for historical reasons, several parallel paths are managed via links. Thus, /usr/bin/X11 leads to the same programs as /usr/x86/bin and /usr/x116/bin.

A complete description of the directory structure is impossible a priori (and in new versions, it may change again). Thus, we conclude this section with a brief description of the subdirectories of /usr:

## Ownership and access privileges

Unix, and therefore Linux too, are designed as multi-user systems – several users can work with the system at the same time. It used to be common practice for several terminals to be connected to one Unix computer, so that in fact several people could work the (at that time very expensive) computer simultaneously and independently of each other.

A typical Linux PC (one keyboard, one mouse, one screen) also allows several users to work with the system at the same time. However, only one user can use the screen at a time. This is because the screen and keyboard are input and output devices. To allow multiple users to work simultaneously, one must use a terminal emulator (like xterm) or a window manager.

Every file and directory in Linux has an owner and a group, and a set of permissions that define who can read, write, or execute it. These permissions are set for three types of users: the owner, the group, and others. The permissions are represented by r (read), w (write), and x (execute). For example, a file with permissions rwxr-xr-- means the owner can read, write, and execute, the group and others can only read and execute. For a directory, the x permission allows a user to enter the directory and access the files within it.

The owner and group of a file or directory can be changed using the chown and chgrp commands. The permissions of a file or directory can be changed using the chmod command. For example, chmod 755 file sets the permissions to rwxr-xr-x.

In Linux, there is a special user called root, who has access to all files and directories. The root user can also change the permissions of any file or directory. It is important to be careful when working as root, as a mistake can cause serious damage to the system. Most users should perform tasks as a normal user and only use root privileges when necessary. This is often done with the sudo command.
