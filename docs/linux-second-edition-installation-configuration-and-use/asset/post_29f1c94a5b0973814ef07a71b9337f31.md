
## /etc/inetd.conf

This file specifies which programs are responsible for which Internet services. For the nntp protocol, you must enter the exact path to the program leafnode. Please make sure that the file has no other nntp entries!

```
# in /etc/inetd.conf
nntp stream tcp nowait /usr/sbin/sbin/leafnode
```

To make the inetd daemon know the modification of /etc/inetd.conf into account (without restarting the computer), you must execute the following command. It does, in fact, not terminate inetd at all. The signal -HUP that the configuration file is to be read again.

```bash
root# kill -HUP cat /var/run/inetd.pid
```

Now you execute a test as to whether leafnode actually starts. First, you establish a connection to the NNTP server for localhost. If everything is working correctly, Leafnode responds. After this, you can exit telnet with Ctrl+D.

```bash
user$ telnet localhost nntp
trying 127.0.0.1...
Connected to localhost.localdomain.
Escape character is '^'
200 Leafnode NNTP Daemon, version 1.8.1 running at localhost.localdomain
<Ctrl+> <Ctrl+O>
```

## Operation

### Fetching the list of newsgroups

With this, the configuration is concluded for the moment. Establish a connection to the Internet, and execute the fetch command that belongs to leafnode:

```bash
root# /usr/local/sbin/fetch -vvv
Read active groups every 90 days
Unsubscribe unread groups after 7 days
subscribe groups that have been read once after 2 days
Trying to connect to news.provider.de...
LIST ACTIVE done 91585422 seconds ago, getting all groups
...
Disconnected from news.provider.de
```

fetch transfers the list of all newsgroups stored on the Internet provider's server. This may take a few minutes. (A simple way of finding out whether data is being transmitted via PPP is the ifconfig command. It displays the number of packets transmitted so far. When you execute ifconfig twice in a row, the number of packets should change.)

## OFFLINE NEWS CONFIGURATION (LEAFNODE)

### Reading news articles

Now, Leafnode is ready for operation. At this point, you can use any news client you like (Netscape, however, from version 4.5 onwards) and subscribe to newsgroups. As only the list of newsgroups has so far been loaded, but no articles, you will enjoy somewhat limited reading. In fact, Leafnode displays one dummy per newsgroup, which you need to display in your news client to tell Leafnode that you are interested in the corresponding newsgroup.

After you have this for a bit (for the moment, not too many) newsgroups, check the directory /var/spool/news/interesting.groups:

```bash
user$ -l /var/spool/news/interesting.groups/
-rw-r--r-- news 0 Jan 9 comp.os.unix.hardware
-rw-r--r-- news 0 Jan 9 comp.os.unix.linux.misc
-rw-r--r-- news 0 Jan 9 comp.os.unix.linux.newusers
```

For each newsgroup whose articles are to be read, Leafnode has created an empty file with the name of the newsgroup. Now, establish another Internet connection and execute fetch. These articles are actually transferred from your Internet provider's server to the local server. (The option -v can be used to control how extensively the program reports about its actions. The more -v you specify, the more reports you will get.)

```bash
root$ /var/local/sbin/fetch -v
Trying to connect to news.provider.de ... connected.
LIST ACTIVE done 10223 seconds ago, issuing NEWGROUPS
Read info from /var/spool/news/news.provider.de
comp.os.unix.linux.newusers: considering articles 24077-24305
comp.os.unix.linux.newusers: 202 articles fetched, 0 killed
comp.os.unix.linux.misc: considering articles 30645-30874
comp.os.unix.linux.misc: 212 articles fetched, 0 killed
comp.os.unix.linux.hardware: considering articles 12376-12471
comp.os.unix.linux.hardware: 84 articles fetched, 0 killed
Disconnected from news.provider.de
```

### Sending your own articles

When you write an article with a news client, leafnode first stores it temporarily in the directory /var/spool/news/out.going. Only when you execute fetch are the articles transmitted to the Internet provider's news server. When fetching new articles, your own article too will be fetched from the external server.

This means that articles you have written are only visible in the article list after the next fetch. (If you are unlucky – if the Internet provider's news server is momentarily very busy – two fetch commands may be needed.) Therefore, do not worry that the command has not worked if your articles are not displayed at once!

### Deleting old news articles

Little by little, the transferred news articles fill up the numerous subdirectories of /var/spool/news. Even with only a few newsgroups, the archive soon grows to 10 to 20 Megabytes. To prevent unlimited growth, you need to delete old articles. This is the task of the expire program, which is also supplied with the leafnode package.

```bash
root# su news
news# /usr/local/sbin/expire -v
expire 1.8.1: check time and at
comp.os.unix.linux: 97 articles deleted, 833 kept
comp.os.unix.linux.misc: 217 articles deleted, 2213 kept
comp.os.unix.linux.newusers: 178 articles deleted, 2229 kept
total: 436 articles deleted, 5042 kept
news# <Ctrl+C>
```

This program should be executed periodically (for example once a day or once a week). The process can be easily automated by registering the program with the crontab command. crontab starts an editor and after its termination, carries out all necessary modifications in the /var/cron files. (Caution: crontab automatically starts vi if you do not set a different editor in EDITOR.)

```bash
root# crontab -u news -e
```

If you want expire to be executed every night at 20:00, enter the following line:
0 20 * * * /usr/local/sbin/expire
