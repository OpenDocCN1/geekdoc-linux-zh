Two changes in the behavior of Emacs concern special characters: now, instead of the " character, Emacs inserts `` or '', that is, a pair of single quotes. A " character can only be entered directly after a backslash (\). (Page 584 describes how this irritating feature can be switched off.)

At the input of every second $, the cursor briefly jumps back to the preceding $ to show where the mathematical formula started. (Under TeX and LaTeX, $$... has the function of a pair of brackets which encloses commands for the definition of a mathematical formula.) Furthermore, Emacs now provides some additional aids:

## LaTeX mode

```
Ctrl+C, Ctrl-E creates the instruction \end(name) for the last
open command \begin(name)
Ctrl+C, Ctrl-O name creates the instruction \begin(name),
empty line, \end(name)
Ctrl+C, J jumps to the closing bracket of the
current level of parentheses
Ctrl+J terminates a paragraph, inserts an additional
empty line and carries out a syntax check on the
paragraph (missing, and so on)
```

Both modes have defined commands for calling TeX or LaTeX. These commands, however, only make sense when the whole document is contained in a single file. Under Linux, it is usually more practical to start TeX or LaTeX from a separate console or a shell window.

The Alt+X validate-text-buffer command is much more attractive; this searches the current text for TeX or LaTeX syntax errors. Even though the LaTeX command sometimes signals errors which are not (especially when the LaTeX command |verb or the LaTeX environment verbatim is used), it has certainly helped me to find many missing (< or ) brackets.

For professional LaTeX/Emacs users, the AUC TeX package provides a considerable enhancement of LaTeX: the AUC TeX package defines many additional Emacs macros. One of the most attractive features is that after a translation you can advance to the next error with a simple click of the mouse. AUC TeX is integrated into more recent Emacs versions; for older GNU versions, it must be installed separately. Subsequently, you must insert the line (require 'tex-site') into .emacs. With this range of additional AUC TeX commands is automatically available in LaTeX mode. Documentation on AUC TeX can be found in the framework of the Emacs Info documentation and in the file auc-tex.dvi.

## C mode

The most striking feature of the C mode is that Emacs indents all curly brackets when new text is entered. This visualizes the structure of the program code - almost totally automatically. Nevertheless, it can be rather irritating when Emacs places your brackets where you expect them. How far the brackets are indented for different structures can be controlled through various Emacs variables. These variables are described in the online help for the current mode. To change a variable, you enter Alt+X set-variable value.

If you are interested in Torvalds' opinion on reasonable indenting of C code, you should read /usr/src/linux/Documentation/CodingStyle. In addition to automatic indenting of text when brackets are entered, two separate commands are defined in C mode for moving the cursor with respect to levels of parentheses:

- Alt+A jumps to the beginning of the current parenthesis
- Alt+E jumps to the end of the current parenthesis

Much more practical than input aids are two other features of C mode: Tags function and the compilation of C programs from Emacs.

First the Tags function: tags is a command that generates a cross-reference of all functions defined in several files. The program must be activated prior to using Tags function. If Emacs is already running, you can start the command directly from Emacs with C-x T. The result of the call is a TAGS file which is read with Emacs with Alt+X visit-tags. From now on you can use Alt+- jump to the definition of any function located in any of the files covered by tags. This is enormously helpful, especially in major projects where functions are often scattered across files.

## Tags function

- tags generates references to all function definitions in *.c and *.h files
- visit-tag reads the file where the function is defined
- Alt+- search for the next occurrence of the function
- tags-search fname search for a regular expression

Now to the compilation of C program; with Alt+X compile from within Emacs. The command used is make. Before the start of make, Emacs automatically asks you whether you want to save files which have not been saved. Subsequently, Emacs displays the result of the compilation (usually a list of error messages) in a separate window.

You can use Ctrl+X to move the cursor to the position of the first error. You can use this command as soon as the first error is displayed (even if the compilation is not yet completed). Repeated execution of Ctrl+X moves the cursor to the following error. Esc-, Ctrl-X moves the cursor to the previous error. Ctrl+U, Ctrl-X moves the cursor to the firstly line.

## Compiling and correcting code

- Alt+X compile starts the compilation
- Ctrl+X moves the cursor to the next error
- Esc-, Ctrl-X moves the cursor to the previous error
- Ctrl+U, Ctrl-X moves the cursor to the first error

In general, you can start any program from Emacs (not only etags or make). The call is carried out with Esc-. When & is specified, Emacs starts the program in the background. This has the advantage that you can continue to work with Emacs while the program is still running. The program output is stored in a buffer and displayed in a window.

However, it is not possible to interact with it. If the program detects an error and waits for input (which, for example, often with a call to latex), it will wait forever. At this point, the program can only be terminated by Ctrl+C, Ctrl-K (kill). In order to avoid this, you should only call programs that can run independently (even in case of errors).

## Shell script mode

With Alt+X shell-script-mode you can activate the shell script mode. This mode is particularly suited for editing shell scripts (for example, for the bash) and configuration files which show a shell-like syntax (which is the vast majority of all configuration files used under).

## Syntax highlighting

In combination with many modes, Emacs can carry out so-called syntax highlighting, where commands, comments, and so on are marked by colors or font attributes. In this way, LaTeX documents and so on become much clearer.

To activate this, you must first activate the corresponding mode and then execute Alt+X font-lock-mode: now Emacs analyses the entire text and marks the identified elements with colors or font attributes.

Emacs can only display different font attributes when the active font is available with these attributes. For example, fonts whose names contain something like 8x13 are not suitable (because the italic attribute is not available). You can easily try different fonts with Shift and the left mouse button. The following fonts have good results:

```
-adobe-courier-medium-r-normal--14-100-100-m-iso8859-1
-adobe-courier-medium-r-normal--14-140-75-m-iso8859-1
```

With large texts, syntax analysis takes any long time; when the text exceeds a certain size, the analysis is not carried out all. In order to obtain quick syntax highlighting with long texts, you can use the Emacs extension lazy-lock. This extension carries syntax highlighting to be executed only for the displayed page and not for the entire. The extension is activated by the following lines in .emacs:

```
(autoload 'turn-on-lazy-lock' 'lazy-lock)
;Unconditionally turn on Lock mode.
(add-hook 'font-lock-mode' 'turn-on-lazy-lock)
```

With long texts (such as the text of this book, which takes up than 2MB), even lazy-lock becomes unbearably slow. At then, it is more reasonable to execute font-lock-buffer manually and wait 10 or 20 seconds until the process has terminated. Emacs works at its usual speed.

# LaTeX font lock problem

When the lock mode ('lazy' or not) is used together with the LaTeX mode. Emacs may get confused in its syntax analysis and therefore mark large areas of text incorrectly. The most frequent cause is a single $ sign used in a verbatim environment or in a single verb command.

The problem can be solved by changing a line in the file font-lock.el (the " character is replaced with a space) which will cause no highlighting of formulae in LaTeX texts. In order for this change to take effect, you must rename font-lock.el or reclaim the modified file font-lock.el. If only *.el files are installed in your lisp directory, you must first install the Emacs Lisp source files. In many distributions, you must create a separate package.
