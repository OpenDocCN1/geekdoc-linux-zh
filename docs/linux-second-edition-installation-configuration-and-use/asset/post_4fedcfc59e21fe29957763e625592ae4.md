Normally, xinitrc is slightly more complex. On the one hand, it contains code that causes Xresources and Xmodmap files to be read in automatically. On the other hand, in some distributions, it contains code that starts the file ~/.clients of the programs directly specified in xinitrc. This allows you to create clients in the home directory for a private configuration (and otherwise use the global xinitrc). The following list shows a modified version of xinitrc for RedHat

```sh
#!/bin/sh
# xinitrc example (RedHat)
# XConsortium:xinitrc.cpp,v 1.4 91/08/22 11:41:34 rws Exp $
userresources=$HOME/.Xresources
usermap=$HOME/.Xmodmap
sysresources=/usr/X11R6/lib/X11/.Xresources
sysmodmap=/usr/X11R6/lib/X11/.Xmodmap
# if local or global Xmodmap files (rarely) and for
# resources files (frequently) exist, they are loaded
if [ -f $sysresources ]; then
xdb -merge $sysresources
fi
if [ -f $sysmodmap ]; then
xmodmap $sysmodmap
fi
if [ -f $userresources ]; then
xdb -merge $userresources
fi
if [ -f $usermap ]; then
xmodmap $usermap
fi
# if /.Clients exists execute
if [ -f $HOME/.clients ]; then
exec $HOME/.clients
elif [ -f /etc/x11/xinit/Xclients ]; then
exec /etc/x11/xinit/Xclients
else
clock -geometry 50x50-1+1 &
xterm -geometry 80x50+494+51 &
xterm -geometry 80x20+494-0 &
if [ -f /usr/X11R6/bin/fwm ]; then
exec fwm
else
exec twm
fi
```

# Modifying xinitrc

If you want to control a different window manager without using the distribution-specific control mechanisms, simply copy the global file xinitrc into your home directory and name it /.xinitrc. Start-up of the window manager is carried out with exec.

```sh
# /.xinitrc: start fwwm2
exec fwwm2
```

The corresponding line to start KDE is shown below. It starts the KDE window manager as a range of KDE core components.

```sh
# /.xinitrc: start KDE
exec startkde
```

The procedure to start GNOME seems to depend on the distribution. With RedHat 6.0, exec gnome-session starts GNOME and the window manager set in the GNOME control center (default: Enlightenment). With SuSE, you have to explicitly start a window manager and then use panel of gnome-session.

```sh
# /.xinitrc: start GNOME 1.0
exec gnome-session                # RedHat
[Your favorite windows manager] & exec panel # SuSE
```

# xdm

xdm conceptually differs from startx and openwin insofar the user must log in X (as a text console). As soon as the exits X with a command to terminate the window manager, xdm again shows the login window. Thus, xdm is capable of starting X over and again (and, if required, with different window managers for different users). xdm is particularly useful if several people use the same computer to work under X at different times. In many distributions, xdm is configured in the same configuration files as startx.

When xdm is to be used, the computer is usually configured so that xdm is started automatically within the Init process. Therefore, the runlevel must be changed in /etc/initab - see also page 124. As a trial, xdm can also be started directly by root. A further variation is to change the runlevel as root by means of init n - however, depending on the configuration, this will terminate almost all running programs.

When working with xdm, X should not be terminated with Ctrl+Alt+Backspace. This combination not only terminates the window manager, but X as a whole. This may cause problems when xdm needs to restart X. If you use Free86 as your server, you can deactivate the 'magic' combination by means of the keyword dontZap in the server section of XConfig.

The look of the xdm login window can be controlled through the Resources files. The syntax is the same as the other resource files (see page 248). X applies only to xdm (not to the programs started by xdm). Resources is located in one of the following directories, depending on the distribution:

- /etc/X11/xdm/Resources (RedHat, Caldera, Debian)
- /usr/X11/lib/xdm/Resources (Default setting, SuSE)

When it is executed, xdm starts the X system, but no window manager. Moreover, in some distributions a colorful login is displayed via Xsetup and xbanner. The shell script Xsession is executed only after a successful login. (All files mentioned have the same path as Xresources.)

xdm checks whether the file .xsession is present in the home directory of the currently logged in. If so, the file is executed .xsession has the same function as .xintrc (see above), and it is responsible for initializing X resources for programs and starting the window manager. In many cases, a .xintrc is sufficient, if the file exists.

The following lines list the file /etc/X11/xdm/Xsession.

```bash
# /etc/X11/xdm/Xsession
#!/bin/bash
# The following is an example of an Xsession file.
# It is executed after the user logs in.

if [ -f $HOME/.xsession ]; then
    exec $HOME/.xsession
elif [ -f /etc/x11/xinit/Xclients ]; then
    exec /etc/x11/xinit/Xclients
else
    # Default session
    clock -geometry 50x50-1+1 &
    xterm -geometry 80x50+494+51 &
    xterm -geometry 80x20+494-0 &
    if [ -f /usr/X11R6/bin/fwm ]; then
        exec fwm
    else
        exec twm
    fi
fi
```
