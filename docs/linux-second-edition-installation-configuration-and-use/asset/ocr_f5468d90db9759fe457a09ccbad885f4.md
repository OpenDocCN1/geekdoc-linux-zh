# The NumLock problem

A problem of fwwm versions is, that X11R6, NumLock is a modifier, like Shift or Ctrl. At the moment, this fact is not taken into consideration by fwwm or in the commonly used fwwm configuration files. For example, Alt+Tab is defined as the key combination for switching windows, this combination will not work whenever NumLock is active.

There are two ways of solving this problem: adaptation of the fwwm configuration file or modification of the keyboard layout by means of xmodmap.

# fwwm configuration

In the case of key combinations, it is relatively easy to put things right. If you want to determine with xmodmap which number NumLock has on your system.

```
root# xmodmap
shift-L (0x32), Shift-R (0x3e)
lock Caps-Lock (0x42)
control Control-L (0x25), Control-R (0x6d)
mod1 Alt-L (0x4d)
mod2 Num_Lock (0x40)
mod3 Mode-switch (0x71)
mod4
mod5 Scroll-Lock (0x4e)
```

In the example, this is number 2. Now look at the fwwm configuration file (whose names vary depending on the fwwm version, see below) and look for lines similar to the following:

```
Context Modifier Function
Key Tab A CirculateUp
Key Tab A SM CirculateDown
```

These lines cause function CirculateUp to be executed by Alt+Tab and the function Alt in all contexts (though, independently of the position of the mouse). M stands for meta, which corresponds to Alt on PC keyboards. In fwwm2 and fwwm95, the commands [CurrentScreen] Focus and Prev [CurrentScreen] Focus, have to be used instead of circulate commands.)

Now you can extend the configuration file by two more lines:

```
Key Tab A M2 CirculateUp
Key Tab A SM2 CirculateDown
```
