Here, kofler is the login name. The character string adg897fdakl897 stands for an encrypted password. If this character string is not specified, the login can be used without a password. If a * is present instead of the string, the login is locked. (This is the case with many administrative accounts which are not used by real persons but by system processes and daemons.)

501 is the UID (identification number), 100 the GID (identification number) of the primary group, Michael Kofler the complete name (for e-mail, news and so on), /home/kofler the user's home directory, and /bin/bash the user's shell. The UID must be a unique number; this is important for the management of file access rights.

The GID must correspond to a group from /etc/group. Normally, the GID of the users is used. It is, however, possible to create a new group in /etc/group. If the new user will belong to other groups as well, or his her UID must be added to the relevant groups in /etc/group.

```
# a line /etc/group
users::kofler
```

A different shell can be specified (for example, tsh for lovers of the C shell) instead of bash. The new user can later change this shell without problems by means of the tsh command.

As already mentioned, many Linux distributions nowadays use shadow passwords. In this case, /etc/passwd does not contain any password information. This is stored in /etc/shadow.
