# LILO internals

LILO (Linux Loader) is a tiny program that can be installed in the boot sector (the first sector) of a diskette, of a hard disk or a hard partition. The program allows you to choose between several installed operating systems and, in particular, to start Linux. LILO is the fastest and most popular method for starting Linux. (All information in this section refers to LILO version 0.20).

Installation of LILO is, however, a rather delicate matter, when LILO is installed into the MBR (Master Boot Record) of the hard disk. If something goes wrong, you will not be able to boot your computer from your hard disk, either under your operating system or Linux.

Particular problems may arise when LILO is installed on computers running Windows NT, if the first disk partition is not a DOS or Windows 95 partition with FAT32. If in such a circumstance you install LILO into the MBR, you may no longer be able to start Windows NT.

If you use the ZE-Drive disk manager, you must under circumstances install LILO in the MBR! This restriction probably applies to other disk managers as well (disk disks with EIDE BIOS versions; see page 33). If you want to use LILO, installation is possible only on a diskette or in the first sector of the Linux partition. This variation will be discussed here; it is extensively described in the LILO documentation.

In distributions, the LILO configuration can be carried out of the installation process. Because of the risks mentioned above, however, a manual installation of LILO has its advantages. You have much control over what really happens, can create a backup diskette of the MBR, and on LILO in the MBR is no precondition for running Linux! During the first days – until you have familiar yourself with the handling of Linux – you can always boot from a diskette.

There is very substantial online documentation about LILO, lilo.conf and man lilo describe the installation program and the format of the config file. A detail can normally be found in /usr/doc/lilo or /usr/doc/packages/lilo. (If these directories do not exist in your distribution, locate to find user.tex). Very informative texts are the Mini-HOWTOs about LILO and NT-OS + Linux.

# CONFIGURATION AND ADMINISTRATION

If you first install LILO and then Windows 9x (or another operating system), LILO is overwritten without warning. It is easy to reinstall LILO by calling LILO under Linux. However, you need a boot diskette to be able to start Linux at all. Therefore, do not throw away Linux boot diskette after a successful LILO installation!

Also, if you update your Linux system (new kernel), please do not forget to update your boot diskette as well.

# Functioning

To put it simply, the function of LILO is to load and execute the file containing the Linux kernel. However, this is not as easy as it sounds:

More precisely speaking, the boot sector of the hard disk or diskette contains a tiny program (first stage), whose only task is to load the larger LILO main program (second stage). The boot sector, that is, the first of the hard disk or diskette, would be much too small to store the entire LILO program. Code contained in the boot sector is automatically executed by the BIOS at start-up – this is why the boot sector plays such an important role in starting a computer.

The LILO main program (the file /boot/boot.b) is located anywhere on the hard disk. The boot sector with the start program also contains the numbers of the sectors where the main program can be found.

As soon as the LILO main program is running, it gives the user the possibility to choose between different operating systems via the keyboard. If the user opts for Linux, LILO must load the kernel file. For this purpose, a table was created during installation of LILO (the file /boot/map), which contains the sequence of all sectors in which the kernel file is located.

The reason for this unusual procedure is that while LILO is running, no-information is as is available on DOS, Linux, or other files. From Linux's point of view, the hard disk is a huge conglomerate of data sectors. LILO must know at each stage where the data sectors are that needed.

On the basis of the above description, it should be clear that LILO can only function as the location of the kernel file on the hard disk remains exactly the same. (Each copy command and, in particular, recompilation of the kernel causes a change even if the file name remains the same. In such cases, LILO needs to be reinstalled by the LILO command. LILO carries out the preparatory work, creating updated versions of /boot/boot.b and /boot/map, and storing them all sectors and other information in the boot sector).

LILO is executed before any operating system is running. For this reason unlike Linux – LILO has to rely on the BIOS. For historical reasons, however, the BIOS only allows access to the first 1024 cylinders of a hard disk. In order to make the startup of Linux work, the kernel file must be located within the first 1024 cylinders of the hard disk. With older BIOS versions or hard disks, the location of the Linux kernel may be limited to the first 508 Mbytes of the hard disk. Depending on hard disk geometry and the BIOS version, however, the first 1024 cylinders comprise up to 7.9 Gbytes (see page 33).

So long as the Linux partition lies completely within the 1024 cylinders, there are no problems. Apart from the cylinder limit, there is another restriction: during the boot process, most BIOS versions can only access the first two disks. On a system with several hard disks, the kernel file must be located on one of the first two. Even IDE/ATAPI CD-ROM drive is counted as a 'hard disk' in this context. Both the cylinder limit and the limitation to two hard disks only apply to the kernel file. Linux itself (that is, the root partition) could also be installed on any disk. Once the kernel is running, there are no more problems.

Apart from Linux, LILO can currently boot the operating systems DOS, Windows 9x (which corresponds to DOS in its boot process), OS/2 and several versions of Unix. Unfortunately, Windows NT is not officially supported and have to rely on its boot manager (More about Windows NT on page 194). It is unclear how LILO and the forthcoming Windows 2000 will coexist. If Microsoft does not change the boot process, the same information should apply as for Windows 4.

# LILO configuration

The installation of LILO consists of two steps: first, you create the configuration file /lilo.conf, then you execute the lilo command. This command evaluates the configuration file, uses this information to create a new boot sector, and writes this to the location specified by lilo.conf. Usually, this is the MBR of a hard disk; however, may also be a normal file.

> Please note that you may call lilo time the kernel file changes (for example, after a recompilation), even if you do not change lilo.conf! For LILO it is not the name that counts, but the sector number at which the file begins.

The lilo.conf consists of two parts: the first part controls the general behavior of the boot program, the second part (keyword or other) lists all operating systems started by LILO (DOS, Windows, OS/2, and Linux). The first operating system in this list is automatically taken as the default system. Comments begin with the hash character (#).

In principle, you can install a different operating system (for example, different Linux distributions) on each hard disk partition with LILO to select the required partition. You can also use LILO to differentiate between Linux kernel files within a partition (for example, vmlinuz, vmlinuz.old). This is of particular interest if you wish to test a new Linux version without throwing away the old one.
