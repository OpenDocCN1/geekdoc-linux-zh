## 18.1 Introduction

The specific advantages of LaTeX as opposed to other homonymous programs lie in its excellent typesetting quality (for example, automatic kerning, that is, in 'Vector' the 'e' is moved nearer to the 'V') and its overwhelming formula setting capacities ($\pi\sum_{i=1}^{\infty}$). However, LaTeX also has its disadvantages: the handling of the program is simply Stone Age. Seemingly trivial things like hyphenation or page breaks must be edited manually in a long-winded process when LaTeX does not produce the required results as standard.

A few words about the origin of TeX and LaTeX in its original form, TeX was programmed by Donald Knuth, and the associated package LaTeX by Leslie Lamport. Leslie Lamport has given up further LaTeX development with version 2.09, it is now mainly thanks to Frank Mittelbach and Rainer Schopman that the current version LaTeX 2 has come into being and that development plans for LaTeX 3 are carried out.

## LaTeX and the most important utility programs

LaTeX is a typesetting program and not a word processor. The difference is that LaTeX is not equipped with its own editor, so the text to be typeset must be written as a completely normal text with any editor of your choice. This also means LaTeX is not a WYSIWYG program (what you see is what you get) - on the contrary; all setting instructions must be specified in the text in a proper context syntax. If, for example, you want to write a word smaller than the surrounding text, the LaTeX syntax for this is (\small{small}).

The next step after text input using an editor is to translate the file (extension *.tex) into a DVI file (extension *.dvi). This is a file in which all page layout instructions are specified in a printer-independent, or a device-independent, language.

The DVI file is generated by the LaTeX program. Thus, the command latex only reads the specified text file and generates a homonymous file with the extension .dvi. This frequently leads to the generation of error messages which are mostly due to syntax errors in the LaTeX file. More detailed information on the handling of error messages and error detection can be found on page 590.

Once the DVI file has been generated, it can be viewed on screen by means of the program dvim. If you want to print the file, a further step is needed - the conversion of the DVI file into the format of the current printer. While the versions of LaTeX (in particular emTeX) are supplied with large numbers of programs with which DVI files can be converted into specific printer formats, there is really only one program for converting DVI files into PostScript files under Linux: dvips. This accomplishes a similar function to ghostscript. PostScript files can be viewed on screen by xdv. If you own a PostScript printer, you can now print the PostScript file directly using cp to send the file to the parallel or the serial interface (depending on your printer's connection). For all printers, you must first use the gs command to carry out a conversion between PostScript format and the current printer format.

In detail, the path from a text file test.tex to LaTeX format to a printout on an HP Deskjet inkjet looks as follows:

```
user$ latex test.dvi
user$ dvips -o test.ps test.ps  #yields test.ps
user$ ghostview test.ps  #check the result
user$ gs -sDEVICE=deskjet -soutputFile=test.hp
    -dPSERVICE4 -dNOPAUSE test.ps #yields test.hp
user$ cp test.hp /dev/lp0 #printout on LPT1:
```

During execution of dvips or dvim, new character sets may be generated. In such a case, both commands start the mf program (metafont) automatically. Background information on Metafont and PostScript character sets can be found from page 262 onwards.

If you own an HP LaserJet compatible printer, you can use the program dvilj to generate files directly in LaserJet, saving you the detour via a PostScript file.

The LaTeX program will be the main item in the rest of this chapter. The dvips, dvilj, dvim, and gs programs are described with some other tools and utilities in Chapter 15 from page 501 onwards. Another separate chapter, starting on page 631 is dedicated to LaTeX2.

## LaTeX online documentation

The available online documentation about LaTeX is rather systematic, strongly dependent on the selection (see below) and mostly addressed to expert LaTeX users. The man pages very briefly describe the program calls of TeX, LaTeX, and so on, but give no information on the syntax of LaTeX documents. A good introduction is provided in ltex2.dvi. Another useful text is essential.dvi. The files usguide.tex, fntguide.tex and clisguide summarize the changes in LaTeX 2 compared with LaTeX 2.09, in about 80 pages. However, these guides assume that you have a good knowledge of LaTeX 2.09.

## Error detection in LaTeX

First contact with the LaTeX program is quite frustrating. The program works actively, reacts to the first error that occurs with a nearly incomprehensible error message and on top of all expects you to enter a letter to indicate how should continue. A typical error message looks like this:

```
LaTeX error. See LaTeX manual for explanation.
Type <return> for immediate help.
t text for verb command ended by end of line.
@latexerrorlines #1
L.46 ...Tex syntax for
group
```

In this case, the cause of the error is a verb command in line 46 which goes beyond the end of the line (and this is not allowed). Now you have the following possibilities:

- displays additional information about the error message. However, the info text is of real help in very rare cases.
- continues processing, displays further error messages, but no longer expects any input.
- as above, but without display of error messages.
- terminates LaTeX.

Usually you terminate LaTeX straightaway with X when you have recognized the code of the error, or you continue processing in quiet mode with Q. In the second alternative, you can expect that in spite of all the errors that are probably occurring, LaTeX is capable of finishing translating at least the faulty page. In this case, you can view the result (the typeset page) with xdv and then possibly guess the cause of the error.

In any case, you will have to editor and search for the error in your LaTeX file. In this process, the file name .log. In essence, all LaTeX error messages are stored (no matter whether they were displayed on screen or not). The name of this log file is a combination of the name of the translated LaTeX file and the extension .log. The most important information in this file is the line number in which the error occurred.
