Most programs that access a serial interface create a lock file. This is used to signal to all other programs that the interface is currently locked. Lock files are usually stored in /var/lock. Here, the problem is access to this directory is reserved for root. the easiest solution is to once again to allow write access to /var/lock to all users.

However, in this case too it is more elegant (and more secure) to assign all modem users to the uuc group. In SUSE, not even this is sufficient, even uuc group members do not have write access to the Lock directory. The remedy is to use the following command:

```
# chmod grw /var/lock
```

# Serial interface detection

On some computers, the serial interface runs too slowly in the default configuration, thus constituting a bottleneck for the modem. If your modem works significantly slower than expected (or the data reached under Windows are not attained under Linux), you will need to familiarize yourself with the methods described below.

Initial information on the serial interface is always displayed at system startup. This information can be called up at any time by means of dmesg.:

```
# dmesg
...
```

```
Serial driver version 4.13p with no serial options enabled
tty0 at 0x03f8 (irq = 4) is a 16550A
tty1 at 0x02f8 (irq = 3) is a 16550D
```

A way of obtaining information on the serial interfaces is offered by the setserial:

```
# setserial -bg /dev/ttyS0
dev/ttyS0 at 0x03f8 (irq = 4) is a 16550A
dev/tty1 at 0x02f8 (irq = 3) is a 16550D
```

On old PCs (approximately up to the 486 generation) the serial interface is provided by the 8250 or 16450 (instead of 16550). In this case, the maximum speed of the serial interface is a meager 9600 bits per second. The simplest solution is to deactivate the built-in serial interfaces and plug in an additional card with two serial interfaces.

The speed of the serial interface is usually determined by the program that communicates with the modem (such as, for, a terminal emulator). Therefore, the interface cannot be set globally, but via configuration files for the individual programs (such as minicom.conf for the minicom terminal program).

With setserial, it is also possible to set parameters for the serial interface which were not detected automatically. During testing with kernel 2.1.131, for example, we encountered the problem that setserial did not recognize the interface chip. (Consequently, subsequent attempts to use the interface were destined to fail. The problem no longer occurred with kernel 2.2).
