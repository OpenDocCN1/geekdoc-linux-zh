### Displaying PostScript files (ghostview, kghostview, gv)

In principle, ghostview is nothing but a graphical user interface for the already introduced gs (GhostScript) program. ghostview can cope with both PostScript graphics and documents running to hundreds of pages. If the document corresponds to the PostScript standards, you can freely jump between page numbers. Otherwise, the file can only be read sequentially (that is, page after page without the possibility of skipping pages or leaving them back).

Depending on the distribution, ghostview is compiled with different widget libraries. This has the consequence that ghostview buttons and scroll bars look different than that shown in Figure 15.10. You can freely choose between dvdi and ghostview for processing LaTeX text. Both programs have advantages: dvdi usually displays the pages somewhat faster, whereas LaTeX original files are used, dvdi provides the better image quality, whereas PostScript files are used, ghostview comes better.

In the LaTeX distribution, xvdi can be configured through the file xvdi (/usr/lib/texmf/xvdi/). The file has four entries: nfmode specifies the printer types, pixelsInch the resolution in dpi, shrinkFactor the scaling down factor and paper size. The first two settings should match the parameters used with dvips for the generation of PostScript files. In this way, you will avoid unnecessary creation of bitmap font files, which is wasteful in terms of both time and disk space.

Resolution and printer type must match (see MakeTeXPK or page 623). xvdi displays the pages far too large. If you print your *.dvdi files on a 300 dpi laser printer, the following settings are reasonable:

```
xvdi*mfmode: cx
dxvdi*pixelsInch: 300
dxvdi*shrinkFactor: 4
dxvdi*paper: a4
```

If you want to check what the result of imagetting with 1270 dpi would look like by pixel, you can use the following settings:

```
Dvi*mfmode: linoone
dxvdi*pixelsInch: 1270
dxvdi*shrinkFactor: 16
dxvdi*paper: a4
```
