## 15.7 Writing CD-ROMs

This section provides an introduction to ISO image creation and CD-ROMs writing under Linux. The main focus will be on single-session data CDs in ISO 9660 format, whereas other variations (audio CDs, multi-session CDs) will not be considered.

To begin with, an overview of the most important steps:

- Before you write a CD-ROM, you need to prepare the data, that is, create an ISO image of the data processed for the CD-ROM file system. Usually, the mkisofs command is employed for this purpose.
- For writing the CD-ROM, you can choose between the programs cdwrite (old, not being developed any further) and cdrecord. If none of these programs supports your CD-R drive, you can also create the CD under Windows or another operating system; most CD-R programs are able to write the ISO image created with mkisofs.
- Depending on kernel version and SCSI hardware, it may be necessary, before writing a CD-ROM, to patch and recompile the kernel.
- Finally, you should check the CD-ROM. Various programs are available which can either be used to read all data blocks or all files to compare the contents of the CD-ROM with an existing file system.
- Instead of the command-oriented programs mkisofs and cdrecord, you can also use the X program xcdrecord, which allows you to carry out both steps with the aid of a user-friendly interface.

## Creating and testing an ISO image

The easiest way to create an ISO image is when you want to copy a data CD (not an audio CD!) unchanged:

```bash
root# dd if=/dev/cdrom of=/usr/local/iso.img bs=2048
```

```bash
mkisofs [options] -o iso_file directory
```

The normal case is, however, that you first put together the data for a new CD-ROM in a directory and subsequently generate an ISO image. This is exactly what mkisofs does: the command creates a file which contains all files of a directory which is formatted according to the ISO-9660 conventions (optionally with Rockridge extension-tension).

- Files with # or ending with ~ are considered as well. Usually, this is not the case, because such files are mostly backup files.
- The specified file is stored as a boot image. At computer start-up, this file is automatically executed (provided the BIOS is configured correctly). The size of the file must correspond exactly to what will fit on a 3.5 or 5.25 inch diskette (1.2, 1.44 or 2.88 MBytes).
- This option specifies the file name under which the so-called boot catalog should be stored on the CD. The catalog is created by mkisofs. When naming, you merely need to ensure that there is no conflict with an existing file. (The man text for mkisofs recommends using a name such as boot.catalog).
- The ISO standard allows for a maximum of eight directory levels. mkisofs usually sticks to this standard and, if needed, modifies the directory hierarchy (and the names of the affected files). The -d option prevents this; however, on some systems which require strict adherence to the ISO standard this may lead to problems.
- Symbolic links are followed, that is, the contents of files or subdirectories specified are included into the ISO image. (Without this option, only the link is stored in the ISO image. However, symbolic links can only be mapped to CDs with Rockridge extension).
- The ISO image is stored in file.
- The ISO image uses the Rockridge extension to store information on long file names.
- As -r, but UID and GID are set to 0 for all files (corresponds to root). At the same time, all R access bits are set; if at least one X bit was set in the original file (see also chmod on page 444).
- The file TRANS.TBL is written into each directory; this specifies the short ISO-9660 name under which files with long Unix names can be found. (This is necessary to allow association to long file names under DOS/Windows as well.)

## WRITING CD-ROMS

-V name
This option specifies the volume ID, that is the name of the CD-ROM (max. 32 characters) as shown, for example, under Windows.

## Example

```bash
root# mkisofs -o /mnt/dos/iso.img -r -T -V Linux_3_98 /master
```

The above command writes all files contained in the /master directory into the file image.raw. For reasons of space, this file is stored on a partition which is mounted into the file system at the mounting point mnt/dos. master itself is not a directory in the ISO image.

```bash
root# mkisofs -o /mnt/dos/iso.img -r -T /master \
> -b images/boot.img -c boot.catalog
```

As above, this time a bootable CD is created.

> If you do not use the option -r, here are some tips: make sure that all files in the master directory are owned by root and are readable by all!

```bash
root# chown -R root.root /master
root# chmod a+xr /master
```

## Testing the ISO image

Provided that you have compiled your kernel with the Loopback device support option (block device) or the corresponding module loop.o is available and can be activated by means of insmod, you may mount the newly created file image.raw in read-only into the file system:

```bash
root# mkdir /iso-test
root# mount -t iso9660 -o loop,ro /mnt/dos/image.raw /iso-test/
```

You can now test the contents of the future CD-ROM (access rights, TRANS.TBL and so on) using the iso-test directory. You will need to use a kernel of 2.0.31 or later - otherwise Linux...

## Hybrid CDs

Hybrid CDs contain the data itself; however, they allow access to different file systems, depending on the operating system. On Macintosh, with HFS file system; under Windows 95/NT, with Jol extension; under Unix, with Rockridge extension. Thus, hybrid CDs allow long filenames (almost) all operating systems.

## TOOLS AND UTILITIES

-h Creates a hybrid CD with HFS information (Macintosh).
-j Employs the Joliet extension (Microsoft).

## Writing CDs with cdrecord

cdrecord transfers an appropriately formatted image to the CD-R drive. In principle, cdrecord is multi-session capable, that is, the CD can be extended in several sessions. This description is however, limited to single-session CDs.

```bash
cdrecord [options] dev=channel,id,lun
```

-driver=name
Specifies the type of CD-R drive. Supported types are displayed with cdrecord driver=help. cdrecord -checkdrive dev=n,n can be used to determine type of the existing CD-R drive.

-dummy
The write process is only simulated. Ideal for testing!

-eject
Ejects the CD after the write process. Some CD-R drives require ejection before the next CD can be written, even if the last one was simulated with -dummy.

-fs=n
This option specifies the size of the FIFO buffer used for buffering data transfer between hard disk and CD. Reasonable values lie between 2 and 8 MBytes (thus fs=2m or fs=8m).

-speed=n
This option without a prefixed hyphen specifies the writing speed (usually 1, 2 or 4).

-v cdrecord displays verbose messages on what is currently happening.

Some brief information on specifying the CD-R drive: cdrecord expects this information not as a device name, but in the form of three numbers: the SCSI bus number (usually 0), the SCSI ID of the device, and finally the Logical Unit Number (LUN, also 0). The easiest way to determine the numbers is to execute cat /proc/scsi/scsi.
