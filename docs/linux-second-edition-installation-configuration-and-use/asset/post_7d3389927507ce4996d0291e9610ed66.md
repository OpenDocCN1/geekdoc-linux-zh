
# Installation and configuration

For most distributions, WWWwaffle is available as a preconfigured package. After installation, you only need to adapt the configuration file wwwwaffle.conf (usually in /etc/wwwwaffle) to your requirements. Usually it is sufficient to specify the proxy server of your Internet provider:

```
# Change to /etc/wwwwaffle/wwwwaffle.conf
```

```
Proxy (
  http://* = www-proxy.provider.de:8080
)
```

Subsequently, you start the WWWwaffle daemon with the following command.
```bash
root# wwwwaffle -c /etc/wwwwaffle/wwwwaffle.conf
```

As a next step, you must configure your Web browser to use WWWwaffle into account. For this, you need to deactivate the cache (this task is now taken on by WWWwaffle) and specify localhost:8080 as WWW and FTP proxy server.

If you use Netscape Communicator, you need to execute EDIT/PREFERENCES. Reduce the size of the disk cache to 0 on the ADVANCED/CACHE dialog sheet. On the ADVANCED/PROXIES dialog sheet, you manually set the WWW and FTP proxies to localhost and port 8080.

> Now you have two proxy servers which you should not mix up: on your computer, WWWwaffle functions as local proxy server. This is the proxy server with your Web browser communicates. WWWwaffle, in turn, reads WWW documents from the proxy server of your Internet provider.

Now it is time for a first test to see whether WWWwaffle is running properly. With this, you enter the address http://localhost:8080 in your browser. With this, the Web browser starts a page created by WWWwaffle, where you can find additional information and control features for WWWwaffle.

# Handling

WWWwaffle will now almost fully automatically. You merely need to tell the program whether an Internet connection is currently established or not. Each time you use PPP, you need to carry out the following command:

When you terminate PPP, the corresponding command is:

```bash
user$ wwwwaffle -offline
```

If, in offline mode, you click on a locally unavailable link, a message is displayed in the Web browser that the page is earmarked for later transmission (Figure 9.12).

To ensure that the transmission is effectively carried out, you need to execute a further wwwwaffle command the next time you are connected to the Internet:

# Automating WWofile

In the long run, manual execution of wwofile at each computer start-up and wwofile at each PPP status change is unsatisfactory. However, the program is difficult to automate. You just need to ensure that wwofile is starting with the Init-V process. For this purpose, most distributions provide a rc local file. Information on the Init-V process can be found on page 124.

The process is particularly easy for SuSE users. Here, the wwofile package is completely preconfigured. For an automatic start, you only need to modify one line in /etc/rc.config using vi or a text editor:

```bash
# change to /etc/rc.config
START_WWOFILE="yes"
```

Integration of the wwofile commands into the ppp-on and ppp-off scripts introduced from page 313 onward without problems:

```bash
# at the beginning of ppp-on
wwwofile -online
wwwofile -fetch

# at the beginning of ppp-off
wwwofile -offline
```

> wwofile stores the transmitted WWW documents in the directory /var/spool/wwofile. (It is of course possible to specify a different directory in wwofile.conf) When the files reach a certain age, they are automatically deleted. Nevertheless, the directory may grow faster than you would like. A more sophisticated control over the time files are to be deleted and the maximum size the directory may reach is provided in the purge section of wwofile.conf.

# Problems

During operation of wwaffle, occasionally the program refused to reload certain pages that were already in the cache from the Internet. Instead, the Web browser reported after a while the cache was empty. Direct access to the page after the localhost proxy setting being deactivated, in contrast, did not pose any problems.

The cause of the problem is still obscure, the solutions mentioned in the FAQs were not successful. Deleting the cache for the web address concerned, however, seemed to help. To do this, point your web browser to the address http://localhost:8080/index/http?none. Now you can see a list of all Web sites contained in the wwaffle cache. Click on the link [Del All] at the Web site which is causing difficulties. The next attempt to access a page of this Web site should work again.

# The ftp command

An FTP session is initiated with the ftp command. Since files are to be transferred from/to the current directory, you should first use cd to change into the required directory. At the call of ftp, the required Internet address of the FTP server is specified.

After the connection has been established and you have entered your user name and password, you are ready to go; you can use the cd, pwd and ls commands, which have the same meanings as under Linux, to find your way through the directories of the FTP archive. In order to transfer a file from the FTP archive into the current directory of your computer, you execute get. The file name remains unchanged. Conversely, you can use put to transfer a file from your current directory into a directory of the FTP archive. (Obviously, this works only if you have write rights for that. With anonymous FTP, this is most restricted to a single directory with a name such as /pub/incoming).

Before you transfer a file, you must first switch into binary mode with binary. In text mode, FTP interprets the files as texts and tries to convert them into the format of the current computer. Binary files become unusable through such a conversion. (Luckily enough, most FTP servers are configured in such a way that binary is the default setting.)

An FTP session is terminated with the command quit or bye. The following table summarizes the most important commands which can be executed during an FTP session:

| Command | Description |
| :--- | :--- |
| ? | displays a list of all FTP commands |
| ! | allows execution of shell commands |
| ascii | switches into text mode |
| binary | switches into binary mode |
| bye | terminates FTP |
| cd | changes into the specified directory |
| close | terminates the connection with the FTP server |
| get | transfers the file from the FTP archive into the current directory |
| help | displays brief about the specified command |
| ls | displays the list of files |
| mget *.pattern | transfers all matching files from the FTP archive into the current directory |
