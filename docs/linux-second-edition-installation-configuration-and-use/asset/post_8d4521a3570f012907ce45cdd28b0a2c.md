## The XF86Setup configuration program

Since version 3.2, XFree86Setup is the default configuration program of XFree86 and is now supplied with all distributions. To use the program, however, some conditions must be:

- The program must be installed. Depending on the distribution, the program is contained in a separate package. In addition, the VGA-16 driver is needed for execution (yet another package which is not installed).

- Your graphics card and your monitor must support the VGS standard mode (640x480 pixels with 16 colors).

- Your computer should be fairly well equipped (memory, CPU) – otherwise, XF86Setup is unbearably slow.

## CONFIGURING THE X SERVER

### Mouse

XF86Setup is executed in text mode and first starts the VGA16 X server before it appears as an program with mouse support, buttons, and so on. The program recognizes the connected mouse straight away; otherwise it should be in the first configuration step. If needed, the program can be entirely controlled with the cursor keys. Also, some of the buttons can be selected by pressing Alt or the initial letter.

With no-name, selecting the mouse type is often a matter of chance. As first attempt, you should try Microsoft compatible (works with three-button mouse) or Mouseman. Manufacturers' names are not always decisive, a Logitech mouse might well observe the Microsoft or the Mouseman protocol. APPLY you adapt the settings and test them immediately. You should press all three mouse buttons – the corresponding fields in the mouse symbol (on the right hand side of Figure 7.1) should become black.

If the mouse does not react at all, you may have to select a different device. The most probable ones are /dev/mouse (a link to the actual device), /dev/tty0 or /dev/tty1 (the first or second serial port), /dev/psaux (PS/2 mouse).

If you work with a two-button mouse, you should also activate the EMULATE3BUTTONS option. Then you can simulate the missing middle button by pressing both buttons. (This is only a makeshift solution. Go on, invest some money in a three-button mouse – it's worth it.)

### Keyboard

After configuring the mouse (do not forget APPLY), the next step is to setup the keyboard. The settings for U.S. keyboard are:

- MODEL: Generic 101-key PC (or Generic 104-key PC with Windows)
- LAYOUT: U.S. English
- VARIANT:
- SHIFT/LOCK BEHAVIOR: Alt switches while pressed

In the option field POSITION, you can turn the CapsLock key into additional Control key and deactivate it.

### Graphics card

To select your graphics card, you will be offered a seemingly endless list which you must look through. This sounds easier than it is – or you are sure whether you have ATI RAMDAC or whether Mach64 would be the better choice? Before you take your computer apart and look at which chips are soldered onto that board, you should opt for the specific which you think correct. If it is sufficient to load the correct driver, the details are usually recognized automatically.

Only if you have a very precise knowledge of your hardware can you make specific indications on available graphics memory.

If you have no idea at all, you should employ the SuperProbe program mentioned earlier, which in many cases recognizes the hardware being used (but in rare cases can also cause a crash).

### Monitor

The configuration program wants to know the permissible ranges for the horizontal frequency (kHz) and for the vertical frequency (Hz). You can either select one of the proposed monitor types or enter the values directly.

You will find the necessary data in the manual or data sheet of your monitor (and, with a bit of luck, also on the back of your monitor). For a number of monitors, you can also find this data in the file doc/Monitors (after the keywords VertRefresh and HorizSync). Background information about the meaning of the data is given from page 225.

If you specify excessively high values for VertRefresh or HorizSync, you risk the premature demise of your monitor! XFree86 uses these values to exclude from the very beginning those graphic modes that might not be compatible with your monitor.

### Terminating the configuration

In the fifth step of XF86setup, the menu item OTHER, you can without problems adopt the default settings. If you subsequently click on DONE, the server starts with your settings. If everything goes well, your monitor will display a stable image. You can now decide via a mouse click whether you want to store the settings, further optimize the image with xhtune (see page 234), or leave the program with QUIT.

If, in contrast, the monitor is not capable to synchronize after the start of X, there are two alternatives: one is the key combination Alt+Ctrl+, where the key of the numeric keypad is used; this allows you to change to a lower-resolution graphics mode. If that does not help, you need to abort the configuration program with Alt+Ctrl+Backspace, restart, and repeat the whole configuration step by step.

## The configuration program x86config

xf86config is the text-based alternative to XF86Setup. The program is not excessively user-friendly but usually leads to the desired goal. The settings are in principle the same as in XF86Setup — therefore, only some complementary details are described.

After monitor and graphics card setup, x86config prompts for identification and description strings. There is enough to thus accept the default names and strings. The sole purpose of these strings is to make your XF86Config more 'readable'.

After a request for confirmation, x86config carries out a start of the VGA driver with the option -probeonly. Here, X is not really started — only the pixel frequencies supported by the graphics cards are determined. However, the trial does not work with all graphics cards. Therefore it is often sensible to skip this point.

Now the configuration program proposes a list of graphics modes to choose from. The abbreviation bpp indicates the bits per pixel: 8 bits for 256 colors, 16 bits for 32768 or 65536 colors, and 24 bits for true color mode (2^24 colors). However, only a few Accelerated-VGA drivers support more than 256 colors. (The others simply ignore these settings in the configuration files.)

In most cases, the least can be: Very high-resolution modes (for example 1280×1024 pixels), are automatically removed at the start of X if they are not supported by your graphics card.

In a final request for confirmation, the configuration program saves the configuration file just created. Make sure that the file is stored at the correct location (or copy the file to the location required for your distribution).

On the author's computer, x86config was the most successful. Some additional work was required with the keyboard configuration. Also, the order of graphics modes in the Modes line had to be changed — x86config uses the lowest-resolution mode (640×480 points) as a default.

The x86config configuration program has the regrettable of filling the configuration file with countless additional sections which, in practice, are not needed at all. This, plus the countless comments make the configuration file longer and harder to read than necessary.

## The xxdune program

The xxdune program is not a configuration program, but a tool for optimizing an existing configuration file. (A KDE variation of xxdune, called kxdune, is currently under development.)

With xxdune, you can change size and position of image for all modes (buttons PREV and NEXT). Changes in image position can be tested with TEST (where the old mode is restored after a few seconds) or permanently set with APPLY. With R (restore) you get back to a stable image if the monitor is no longer.
