In addition, a maximum of two files must be extended or newly created, /etc/hosts and /etc/resolve.conf. Depending on the distribution, you can use the relevant configuration program to modify these files (such as Yast with Linuxconf with RedHat)

/etc/resolve.conf: This file must be extended by the IP address of the Internet provider's name. The name server (also DNS for domain name server) is responsible for the translation of unknown Internet addresses to the corresponding IP numbers. This task is carried out by the Internet provider's program and is of no interest

```
# /etc/resolve.conf
domain galactic.network
nameserver 199.85.37.2
```

In SU Linux, you should not modify resolve.conf but, instead, figure the name server with Yast (SYSTEM ADMINISTRATION|NETWORK CONFIGURATION|CONFIGURATION NAMESERVER) or enter it directly into /etc/config.cfg.

/etc/hosts: The file contains a list of known IP numbers: 127.0.0.1 is the standard IP number for the loopback device. Additional lines can be used to assign the computer's IP number within the local area network. Only if your provider has assigned you a static IP address (which is unlikely) you should enter this address in hosts. (If you are not part of a local network and your Internet provider provides IP addresses dynamically, /etc/hosts only 127.0.0.1 for the loopback interface.)

```
# /etc/hosts
# for the loopback interface (always required)
localhost
127.0.0.1
# for the local network (if one exists, obviously!)
192.168.1.5 jupiter.galactic.network jupiter
# for PPP/SLIP (only if static IP address is known)
199.85.96.166 jupiter.galactic.network jupiter
```

As a rule, it is not possible to choose domain and login names corresponding to the email address supplied by the provider (and it makes no sense either).

The fact that the same computer has several IP addresses is not a problem. As a rule, even PPP with a static address works without an entry in /etc/hosts - the local PPP daemon and the PPP program of your provider negotiate automatically which IP address is going to be used. Thus, for your first attempt, you might well leave /etc/hosts as it currently is.
