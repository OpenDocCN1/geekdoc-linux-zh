# Where is mail stored?

Caution — this question sounds simpler than it is! The answer is twofold: first, we will discuss email reading, then email sending.

# Reading messages with POP

Let us assume that you have a POP account with an Internet provider. (POP stands for Post Office Protocol and is currently the most common protocol to collect messages from Internet providers.) If a friend sends you an email, the first message arrives at the server of your Internet provider.

The next time you connect to your provider, you can fetch the message (making use of POP). As mentioned above, you can use different programs for this purpose – which will determine the next location of the message.

If you use a stand-alone program, it immediately stores the message in a local inbox. Messages remain in this file until they are moved to a different folder or deleted. (Many email programs keep the messages in the file when they are already marked as deleted or are Only the explicit command to compress the folder (FILE COMPACT in Netscape) finally removes the messages.)

Now for the second variation: if you fetch your messages from the Internet with fetchmail, they are temporarily stored in /var/spool/mail/name. Every email program that is configured as a client can access this file. The remaining procedure, depends on the program:

- pine, mutt, and elm only modify this mail file after completion. Both programs display the message in an Inbox Folder, although the messages are still in /var/spool/mail (Generally it is not desirable to leave too many messages in Inbox. Move the messages to local folders!)
- The programs Mail, GNU Emacs, Netscape, and kmail remove all messages from /var/spool/mail and transfer them to a local file.

The following table shows the Inbox location for various email programs (in their default configuration):

| program | location |
| :--- | :--- |
| elm | /var/spool/mail/username |
| GNU Emacs | /RMAIL |
| kmail | /Mail/Inbox |
| Mail | /mbox |
| Netscape | /nsmail/Inbox |
| mutt | /var/spool/mail/username |
| pine | /var/spool/mail/username |
| XEmacs | ~/VM-MAIL# |

The behavioral details of the different mail programs are described here to save the search for 'lost mail'. Mail is never deleted without asking first. It is just transferred to a different location where it can only be processed by a specific program (not by all programs).

No matter how the message has made its way from the Internet provider to the local email program, its last location is usually a folder. that is, a local file.

The most important alternative to POP is IMAP. This abbreviation stands for Internet Message Access Protocol. The essential difference to POP is that messages remain on the Internet provider's server. Thus, IMAP is not designed for offline operation. However, the protocol has its advantages for people who access their email from various locations/computers/operating systems, because all messages are centrally managed (and do not end up on various computers, partitions, and so on). In this book, IMAP is not considered any further.

# Sending messages

To conclude, some words about messages that you send. Their location after sending also depends on the configuration. In stand-alone systems, messages are usually stored in a folder named outbox until they are forwarded to the Internet provider. Subsequently, they end up in the sent-mail (or similar) folder so that you always know what you have sent to.
Things look slightly different when the email program works as a client. In that case, the program forwards the message immediately after writing to sendmail. For example because there is no Internet connection (at the moment) it is temporarily stored in the directory /var/spool/queue In this directory, each message is stored in a separate file under a cryptic cipher name. Normally, you should not modify anything in this directory - sendmail itself will deal with the files temporarily stored here. A list of the queued mail can be displayed with mailq.

# Glossary, working techniques

For a better understanding of the email program descriptions in the next section, the following paragraphs explain a few terms and working techniques, which are similar in all email programs. If you already have some email experience, you can skip this section.

# The email header

# Email header

- From: address email address of the sender
- To: address email address of the addresse
- Subject: contents brief description of the contents (one line)
- Reply-To: address do not reply to From; but to this reply
- Cc: address a copy of the message is sent to the Cc address
- Bcc: address same as Cc, with the exception that the main addresse is not informed that the message has also been sent to another person (blind carbon copy)

# Folders

If you receive several email messages, the organization of messages is very important. Most email programs allow you to create folders. You can organize your messages by topic, date, or any other criteria you find useful. You can move messages from one folder to another, or delete them when they are no longer needed. Some email programs also allow you to search for messages within specific folders. This is a very useful feature when managing a large volume of email.
