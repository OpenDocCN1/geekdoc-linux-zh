## Global layout settings

The layout of LaTeX can be influenced not only through various commands mostly applied to small portions of text, but also through global settings. These settings are normally executed before the actual beginning of the text (that is, before \begin{document}) and apply to the whole text. Many of commands listed on the following pages can also be used at any point in the text and become effective only from that point onward.

Most measure specifications can be changed with their own commands to which the following syntax applies: \commandmeasure (without spaces between command and setting). Some settings must be carried out by direct assignments to LaTeX variables. In these cases, the syntax is: \setcounter{name}{value}.

The following table summarizes the measures for the printable area of a page. The commands are logically arranged from left to right and from top to bottom.

| Page layout | Description |
| :--- | \--- |
| \oddsmarginmeasure | distance left page edge – text for odd pages |
| \evidemarginmeasure | distance right page edge – text for even pages |
| \textwidthmeasure | text width (printed page area) |
| \topmarginmeasure | distance top page edge – header |
| \headmeasure | height of header |
| \headsepmeasure | distance header – text (for the text itself without headers and footers) |
| \textheightmeasure | text height |
| \columnsepmeasure | gutter (only for two-column text) width of rule between the columns (standard: 0) |
| \footsepmeasure | distance between text and lower (!) footer |
| \headmeasure | height of footer |

Standard, LaTeX does not insert vertical space between two paragraphs. Instead, beginning with the second paragraph of a section, the first line of each following paragraph is indented by a certain amount. If you want to obtain a different paragraph setting (example, without the indent, but with a distinct spacing between paragraphs) you must set \parindent to 0 (not forgetting the unit – in spite of being 0) and \parskip to a reasonable value – for example, 2ex.

Some explanation is also needed for the \flushbottom command: it causes LaTeX to carry out vertical justification of the text, by inserting as much space between paragraphs and headlines as is necessary to make all pages exactly the same length.

As standard, the formatting is only active for the text type book and can be switched off with \raggedbottom.

The syntax for modifying line spacing differs from the above commands: With \newcommand{\baselinesretchfactor} the normal line spacing is reduced or increased by the specified factor. This slightly unusual definition is necessary because the line spacing depends on the current type size and therefore should not be set to a fixed value.

Normally, LaTeX automatically numbers all headlines down to including \subsection, which generates section numbers as 3.5.2. In this book, numbering has been reduced to two levels (chapter and section) by modifying the variable secundepth. ## 18.6 Metafont and PostScript fonts

The biggest comprehension problems when working with LaTeX are presumably caused by the handling of character sets. This section tries to clarify the situation. The two main points in this section are the LaTeX utility program Metafont which generates LaTeX's own character sets (in most cases dynamically during output) and the use of PostScript fonts instead of the original fonts.

## Metafont

When LaTeX was originally developed, the printer market was even more unstructured than it is today. An established standard such as PostScript with countless fonts at a cost accessible to (nearly) everybody did not exist. For this reason, the Metafont program was developed at the same time as LaTeX. This program is responsible for the calculation of character sets. The aim was to be able to support each and possible printer with the highest possible quality. From this background it is also understandable why Metafon works with bitmap fonts (unlike PostScript which works with arbitrarily vector fonts). Today, LaTeX and Metafon constitute an integrated package, each program being practically useless.

How does Metafon work? The starting point for all characters is the name.mf files. These text files contain commands for drawing the individual characters of a character set. Depending on the specified options, Metafon generates one or two; in case this file does not exist the bitmap file name.nnpk.

The bitmap files *.nnpk contain the character set in compressed form. The bitmap files, each letter is represented using thousands of dots (pixels), nn stands for a factor made up of the resolution in dpi (dots per inch) and the magnification. Typical dpi are 300 or 600 dpi for printers and 720 or 254 dpi for image sets. The magnification factor comes into play when a character set is set in a different size than the one in which it was developed (for example, \small or \large). This results in values such as 1.2 (600 dpi).

The metrics *.pk contain the size specifications of the individual characters. Even if several *.pk files exist for a given character set, there is always one metrics file (since the actual size of the characters depends on the printer resolution).

For now the real meaning of the file types: the metrics *.tfm are used by LaTeX while processing a text. From these, LaTeX extracts the information of how the individual letters are and uses this data to carry out line and page breaking. The result is a DVI file (device independent) which does not contain the actual character sets and can neither be printed nor displayed in this form.

The *.pk files are only needed for printing or for displaying the file on screen (xdvi). If the currently needed *.pk files does not exist in the screen/printer resolution and the required magnification, Metafon is started automatically. This can lead to considerable delays during the first printing of a text with many family types and sizes. The next time, however, the *.pk files will be readily available.

As a rule, you will not have to concern yourself with character sets and never have to start the Metafon program (command name mf). All required *.mf and *.tfm files are already preinstalled, and the *.npk files are automatically generated when needed.
