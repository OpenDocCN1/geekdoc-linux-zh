CPU 1 has also found a value of 1 and also starts execution. Because CPU 0 was briefly interrupted, CPU 1 has time to finish serving the interrupt. Now, when CPU 0 comes back to handle the interrupt it will find nothing to do (because CPU 1 already handled it), and will fail with an error. This might seem like an innocuous example, but there are hundreds of more dangerous code parts that will wreak havoc with your system if not properly serialized. In the parlance of kernels, these serialization mechanisms are called *spinlocks* or *mutexes*.
