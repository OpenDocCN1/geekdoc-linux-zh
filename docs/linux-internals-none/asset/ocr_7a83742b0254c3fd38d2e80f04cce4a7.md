In the case of tv1 expiry all timers must be run (the timer functions must be executed). For tv2, tv3, and others, “expiry” means that all timers in that timer list must be moved into a one-lower timer vector. This is done by cascade_timers().

What is the advantage of this approach? The advantage is that add_timer(), del_timer(), and modify_timer() execute in constant time, independent of the number of timers in the system. I have found that a large percentage of long-term timers are deleted prior to their expiration, especially in the network code. In that case no penalty is paid for handling the expiration.

Cascading and expiring timers is very fast as well. There are Linux SMP system demos with more than 4 million timers running and expiring, and the kernel keeps up with them easily.
