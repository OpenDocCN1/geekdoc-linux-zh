If one block, say, is appended to the end of a file, the on-disk map that tells the file system where each block for the file is located needs to be read, modified, and rewritten to the disk before the data block is written.

When a failure occurs, the file system must be checked before it is mounted at boot; the file system manager doesn't know if the block map is correct, and it also doesn't know which file was being modified during the crash. This results in a full file system scan.

A metadata logging file system has a wrap-around, append-only log area on the disk, which it uses to record the state of each disk transaction. Before any on-disk structures are changed, an intent-to-commit record is written to the log. The directory structure is then updated and the log entry is marked complete. Because every change to the file system structure is in the log, file system consistency can be checked by looking in the log without the need for a full file system scan. At mount time, if an intent-to-commit entry is found but not marked complete, then the file structure for that block is checked and, if necessary, fixed.
