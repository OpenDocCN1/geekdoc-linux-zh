The Redo extension is included in the XEmacs edit-utils package. This single-file package isn't included with GNU Emacs, but it works well with that editor. All you need to do is copy the file from this book's CD-ROM (it is in the directory /cdr0m/packages), copy it to your site-lisp directory, and byte-compile it.

Enable this utility by inserting a single statement into your ~/.emacs file:

```
(require 'redo)
```

Once Redo is loaded, you can use it whenever you use the Undo command by pressing M-x and typing

```
redo
```

You can give this command a convenient keybinding with a line similar to this in your ~/.emacs file:

```
(global-set-key [(control c) (r)] 'redo)
```

# The Message Log

During an Emacs session, many events generate messages. Errors are the obvious example, but even when Emacs is running normally, messages are continually being written to a temporary buffer called the Message Log. The two Emacs variants each have their own approach to the display of this buffer, so I will describe them separately.

# GNU Emacs: Messages and Logsave

Look at the Buffers menu, and you see an entry called Messages. Select this, and you see the accumulated messages that Emacs has generated in the session, as shown in Figure 22.1. Scroll to the top of the buffer, and you find a record of the messages produced as Emacs started up, most of them the result of processing your ~/.emacs file.

If you have made a mistake in your ~/.emacs file, this buffer can be a valuable means of tracking down the error. When you start Emacs and it encounters an error it can't deal with, the ~/.emacs file is rejected, and you end up running a default Emacs with none of your customizations. Don't let that stop you from trying to find the error. You can still load and edit the ~/.emacs file and view the Messages buffer.
