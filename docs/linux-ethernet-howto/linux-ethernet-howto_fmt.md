# 2.1 我应该为 Linux 购买什么样的网卡？

这个问题的答案很大取决于你打算用网络连接具体做什么，以及它将承担多大的流量。

如果你只预期单个用户偶尔进行 ftp 会话或 WWW 连接，那么即使是一块旧的 8 位网卡可能也能让你满意。

如果你打算建立服务器，并且要求将网络数据传输的 CPU 开销降至最低，你可能想看一个使用具有总线主控能力（bus-mastering）芯片的 PCI 卡，例如 DEC tpl（21xxxx）芯片或 AMD PCnet-PCI 芯片。

如果你处于上述两者之间，那么任何带有稳定驱动的低 PCI 或 16 位 ISA 网卡都能胜任工作。

# 2.3 在一台机器上使用多个以太网卡

需要做什么取决于驱动是作为可加载模块使用的还是直接编译进内核。大多数 Linux 发行版使用模块化。

在 PCI 驱动的情况下，模块通常会检测到所有网卡。然而，对于 ISA 网卡，探测（probing）不是安全操作，因此你需要提供网卡的 IO 基地址。这些信息存储在 `/etc/conf.modules` 文件中。

例如，考虑一个拥有两块 ISA NE2000 网卡的用户，一个在 `0x300`，一个在 `0x240`。交换 `0x240` 和 `0x300` 的顺序将交换哪个物理网卡成为 `eth0` 和 `eth1`。

在此示例中，使用了 `-o` 选项为每个实例提供唯一的名称，因为你不能有两个同名的模块。`irq-` 选项也被用于指定网卡的硬件 IRQ 设置。（这种方法也适用于接受逗号分隔的

作为最后一个示例，考虑一个用户位于 `0x350` 处的 `3c503` 网卡和 `0x280` 处的 SMC Elite 16 (`wd8013`) 网卡。他们应该有如下：

```

options wd io=0x280
options 3c503 io=0x350
```

对于 PCI 卡，你可能可以使用 alias 行将 `ethN` 接口与相应的驱动程序名称关联起来，因为 PCI 卡的 I/O 基地址可以被安全地检测。

可用的模块通常存储在 `/lib/modules/$(uname -r)/net`，其中 `uname -r` 命令给出内核版本（例如 `2.0.34`）。你可以查看那里看看哪一个与你的网卡匹配。一旦你在 `conf.modules` 文件中有了正确的设置，可以使用以下命令进行测试：

```

dmesg | tail
```

其中 'N' 是你正在测试的以太网接口的。

驱动已编译进内核：如果你已将驱动程序编译到内核中，那么多个网卡的钩子（hooks）都在那里。然而，目前只有一块卡会作为默认进行自动探测。这有助于避免因探测敏感网卡而导致启动时间挂起。

（注意：截至 2.1.x 版本的网卡，启动探测已分为安全和不安全，因此所有安全的（例如 PCI 和 EISA）探测将自动找到所有相关的网卡。对于拥有多个以太网卡且至少一张是 ISA 卡的系统，仍需要执行以下操作之一）



有两种方法可以开启第二块（以及第三块、以及……）网卡的自动探测。最简单的方法向内核传递启动时参数，这通常是通过使用形如 `ether=0,0,eth1` 的简单启动参数来实现。在这种情况下，`eth0` 和 `eth1` 将按照网卡在启动时发现的顺序分配。假设如果你想让 `0x300` 处的网卡成为 `eth0`，`0x280` 处的网卡成为 `eth1`，你可以：

```
LILO: linux ether=5,0x300,eth0 ether=15,0x280,eth1
```

该命令也接受多个 IRQ / I 名称。请参阅“传递以太网参数……”以获取完整的语法、网卡特定参数和 LILO 技巧。

这些启动时参数可以是永久的，这样你就不需要每次都重新输入它们。请参考 LILO 手册中的配置选项 `append`。

第二种方法（不推荐）是编辑 `Space.c` 文件，并将 I/O 地址的 `0xff0` 条目替换为零 `0xfe0` 条目告诉不要探测该设备 —— 将其替换为零将启用该设备的自动探测。

## 2.4 ether= 东西对我不起作用。为什么？

如上所述，`ether=` 命令仅对编译进内核的驱动程序有效。现在大多数发行版都使用模块形式的驱动程序，因此 `ether=` 命令已很少被使用。（某些旧版文档需要更新以反映这一变化。）如果你想为模块化的以太网驱动应用选项，你必须修改 `/etc/conf.modules` 文件。

如果你正在使用编译的驱动，并且已经在 LILO 配置文件中添加了 ether，请注意，在重新运行 `lilo` 处理更新后的配置文件之前，它不会生效。

如果你投入额外的资金购买了多处理器（MP）计算机，那么请也买一个好的以太网卡。对于 v2.0，这并不是一个问题，但对于 v2.2 绝对是。大多数旧的非智能网卡（例如 ISA 总线 PIO 共享内存卡）从未考虑过在 MP 机器上使用。总结：购买一个现代设计的智能卡，并确保驱动程序已经编写（或更新）以处理 MP 操作。（这里的关键词是——PCI-NE2000 只是现代总线上的一个 10 多年前的设计）。在驱动源码中寻找 `spin_lock` 文本是判断驱动程序已编写用于处理 MP 操作的良好迹象。关于为什么你应该为 MP 使用购买好网卡（以及如果不买会怎样）的完整细节如下：

在 v2.0 中，任何时候都只有一个处理器在内核中运行（即更改内核数据和/或运行驱动程序）。从网卡（或其他驱动程序）的角度来看，这与单处理器（UP）操作没有区别，并继续工作。这是获得可用 MP 版本最简单的方法——在整个内核周围加一个大锁，一次只允许一个处理器运行。这样你就不会有两个处理器试图同时修改同一个东西！

内核中一次只运行一个器的缺点是，只有当运行的程序是自包含且计算密集型时，才能获得 MP 性能。如果程序执行大量的输入/输出（I/O），如向磁盘或网络读写数据，那么一个处理器将等待其 I/O 请求完成，而运行内核的另一个处理器将疯狂地尝试运行所有驱动程序来填充 I/O 请求。内核变成了瓶颈，由于内核中只有一个处理器在运行，MP 机器在重 I/O 单锁情况下的性能会迅速下降到单处理器的水平。

由于这种情况并不理想（特别是对于 WWW 服务器、路由器等），v2.2 内核采用了细粒度锁（grained locking）——这意味着可以有多个处理器同时处于内核中。内核不再使用一个大锁，而是使用较小的锁来保护关键数据不被多个处理器同时操作——例如，一个处理器可以运行网络网卡的驱动程序，而另一个处理器可以同时运行磁盘的驱动程序。

好了，考虑到这一切，这里存在一些障碍：内核锁定意味着你可以有一个处理器试图通过以太网卡发送数据，而另一个处理器试图访问同一个驱动程序/网卡来做其他事情（例如通过 `cat /proc/net/dev` 查看网卡统计信息）。哎——你的网卡已经通过线路发送了，而你的统计数据停在那里。是的，网卡因为被要求同时执行（或）多个任务而搞混了，并且可能会导致你的机器崩溃。

因此，适用于 UP 的驱动程序不再足够——它需要更新锁，以控制对底层网卡的访问，以便接收、传输和多处理器配置这三个任务能够按照稳定运行所需的程度进行序列化。在轻负载的 MP 机器上，MP 操作可能会正常，但当两个（或更多！）处理器尝试同时执行这些任务中的多个时，会导致机器崩溃或至少表现出异常行为。



更新后的 MP 感知以太网驱动（至少）要求在驱动程序周围加一个锁，限制从内核到驱动程序的入口访问为“请一次一个”；有了锁后，操作将被序列化，底层硬件的对待方式将就像在 UP 机器中使用它一样，因此它应该是稳定的。缺点是，整个以太网驱动周围的锁具有负面的性能影响，这就像在整个内核周围加了一个大锁（但规模较小）一样——即你一次只有一个处理器在处理网卡。[技术说明：性能影响可能包括解引用。]

## 启动错误

启动时收到一系列 `SIOCSIxxx: No such device` 消息，随后是 `SIOCADDRT: Network is unreachable!`！是怎么了？

你的以太网设备在启动/插入模块时未被到，当运行 `ifconfig` 和 `route` 时，你没有设备可以使用。使用 `dmesg | more` 读取启动信息，查看是否有检测以太网卡的消息。

当我执行 `ifconfig` 时 get `SIOCSFLAGS: Try again` ——怎么？

其他设备占用了你尝试使用的 IRQ，导致以太网卡无法获取 IRQ。你不需要重启来解决这个问题，因为某些设备在需要时会释放 IRQ。例如串口、软盘驱动器。你可以检查 `/proc/interrupts` 来查看哪些中断正在使用。大多数 Linux 驱动程序仅在通过 `ifconfig` 打开时才会获取 IRQ。如果你能让其他设备“释放”所需的 IRQ 线，那么你就可以“重试” `ifconfig` 了。

## 使用 `ifconfig` 和硬件地址

### LINK UNSPEC

当我不带参数地运行 `ifconfig` 时，它报告显示 LINK 为 UNSPEC（而不是 10Mbps 以太网），并且说我的硬件地址全为零。

这是因为人们运行的 `ifconfig` 程序版本比内核版本要新。这个新版本的 `ifconfig` 在与旧内核配合使用时无法报告这些属性。你可以升级你的 `ifconfig`、降级（downgrade）它，或者直接忽略它。内核知道你的硬件地址，所以 `ifconfig` 能不能读取它其实并不重要。

你可能还会得到奇怪的信息，因为你正在使用的 `ifconfig` 程序比你使用的内核旧得多。

### 错误计数

当我不带参数地运行 `ifconfig` 时，它报告在接收和发送的数据包中都有巨大的错误计数。看起来运行正常 —— 哪里问题了？

再看一遍。它显示 RX 数据包大数量 PAUSE errors 0 PAUSE dropped 0 PAUSE overrun 0。TX 列也是如此。你看到的数字是你的机器接收和发送的数据包总数。如果你仍然觉得困惑，尝试在输入 `cat /proc/net/dev`。

### 设备节点

我有 `/dev/eth0` 作为指向 `/dev/xxx` 的链接。这对吗？

与你听到的相反，`/dev/*` 中的文件并没有被使用。你可以删除任何 `/dev/wd0`、`/dev/ne0` 类似的条目。

### Trailers

当我 `ifconfig` 我的以太网卡时，应该禁用尾部吗？

你可以禁用尾部，但你不应该这样做。`Trailers` 是为了避免在网络层中拷贝数据的一种黑方法。其想法是使用一个固定大小的 'H' 头部，将变长度的头部信息放在数据包末尾，并在页开始之前分配所有的 'H'。这是一个好主意，但在实践中证明行不通。有人建议使用 `trailers`，请注意这等同于祭羊的血。它解决不了任何问题，但如果问题解决了，他们就可以声称拥有深奥的魔法知识。

## 原始以太网访问

如何在 Linux 中不通过 TCP/IP 等协议，直接访问原始以太网设备？

```c
int s=socket(AF_INET, SOCK_PACKET, (ETH_P_ALL));
```

Linux 给你一个可以接收所有协议的套接字。对其 `recvfrom()` 调用，它会在 `sa_family` 中填充设备类型，并在 `sa_data` 数组中填充设备名称。我不知道最初是谁为 Linux 发明了 `SOCK_PACKET`（它已经存在多年了），但它是非常棒的东西。你可以通过 `sendto()` 调用来原始发送内容。当然，你对两者都有 root 权限。

## 吞吐量优化

如果你正受以太网吞吐量低的困扰，或者想在某些类型传输中获得更多提升，可以使用以下提示。

`ttcp.c` 程序是测量原始吞吐量速度的好测试。另一个常见技巧是执行 `ftp get_file /dev/null large_file`，如果文件大于 1MB 且存在于发送端的缓冲区缓存中。（至少执行 'get'，因为第一次执行会预热发送端的缓冲区缓存。）你希望文件在缓冲区缓存中，因为你对将磁盘访问速度合并到内存感兴趣。这就是为什么你将数据发送到 `/dev/null` 而不是磁盘。

### 3.1 通用概念

即使是 8 位卡也能毫无问题地接收连续数据包。困难在于计算机接收数据包的速度不够快，无法为更多新进入的数据包腾出空间。如果计算机不快速清除缓存中已接收的数据包内存，卡将没有地方存放新数据包。

在这种情况下，卡要么丢弃新数据包，要么覆盖之前接收的数据包。这任何一种方式都会通过调用/请求/重传中断流量的平流动，并可能导致性能严重下降高达 5 倍！

具有更多板载内存的卡能够缓存 `buffer`）更多数据包，并能处理突发的连续数据包而不丢包。这意味着卡不需要主机计算机以极低的延迟从缓冲区中取出数据包，以避免丢包。

大多数 8 位卡具有 8KB 缓冲区，大多数 16 位卡具有 16KB 缓冲区。大多数 Linux 驱动程序会预留 3B 的缓冲区（用于两个 Tx 缓冲区），为 8 位卡仅留下 5KB 的接收空间。这个空间仅足够三个完整的（1500 字节）以太网包。

如上述，如果数据从卡中移除得足够快，即使 Rx 缓冲区内存很小，也不会发生丢失/溢出（overrun）情况。决定数据从卡到计算机内存速率的是连接两者的路径——即 ISA 总线。（如果 CPU 是慢速的 386cx-16，这也会产生影响）。

建议的 ISA 总线频率约为 8MHz，但许多主板和外设可以在更高的频率运行。ISA 总线的频率可以在 CMOS 设置中设置，选择主板/CPU 时钟频率的分频。某些 ISA/ISA 主板可能没有此选项，因此你只能使用出厂默认值。例如，以下是在 40MHz 486 上使用 8 位 WD8003EP 卡通过 `TTCP` 程序测量的不同 ISA 速度。

| ISA Bus Speed (MHz) | Rx TTCP (kB/s) |
| :--- | :--- |
| 6.7 | 740 |
| 13.4 | 970 |
| 20.0 | 1030 |
| 26.7 | 1075 |

对于任何 10Mb/s 以太网卡，使用 TCP/IP 很难达到 1075kB/s 以下。然而，不要期望任何系统在快速 ISA 速度下工作。在超过 13MHz 的速度下，大多数系统无法正常运行。（某些 PCI 系统固定了总线速度）

# 4.7 Arcnet

状态：已支持，驱动程序名称：`arcnet` (`arc-rimi`, `com90xx`, `com20020`)

# 4.27 Novell Ethernet, NExxxx 及相关克隆卡

前缀 `NE` 来自 Novell Ethernet。Novell 遵循了最便宜的 NatSemi 数据手册设计，并出售了 Eagle（拆分？）的制造权，以便向市场提供价格合理的以太网卡。（现在无处不在的 NE2000 卡。）

## NE1000, NE2000

状态：支持，驱动名称：`ne` (`+8390`)

`ne2000` 是基于 NatSemi `8390` 芯片的简化设计的通用名称。它们使用程序化 I/O 而不是共享内存，这使得安装更简单，但性能略低，且存在一些一些问题。NE2000 网卡出现的一些常见问题列在 [Problems...] 中。

一些 NE2000 克隆卡使用 National Semiconductor/ATLANTIC `8305` 芯片，该芯片提供了用于利用 `wd8013` 和 EEPROM 软件配置的共享内存方案。共享内存模式与程序化 I/O 相比将提供更低的 CPU 占用（即效率更高）。

通常，在 I/O 地址 `0300` 制作 ne2000 克隆卡是不好的，因为几乎每个驱动在启动时都会在那里进行探测。一些糟糕的 NE2000 克隆卡不喜欢被挤在错误的区域，并会通过锁定你的选择作为回应。此外，`0320` 是安全的，因为 SCSI 会探测 `0330`。

Donald 为所有 ne2000 网卡编写了一个 NE2000 诊断程序 (`ne2k.c`)。更多信息请参阅 [Diagnostic Programs]。

如果你打算将此驱动作为可加载模块使用，可能应该查看 [Using the Ethernet Drivers as Modules] 以获取模块特定信息。

## NE2000–PCI (RealTek/Winbond/Complex)

状态：支持，驱动名称：`ne`, `ne2k–pci` (`+8390`)

信你不信，人们正在根据 ne2000 超过十年的接口设计制造 PCI 网卡。目前，几乎所有的此类卡都基于 RealTek `8029` 芯片或 Winbond `89c940`。Complex、GTI、VIA 和 Netvin 卡也使用这些芯片，但 PCI ID 不同。

最新的 `v2.0.34` 内核必须自动检测所有网卡并使用它们。如果你正在使用 `v2.0.34` 或更版本的内核，你应该升级以确保你的网卡被检测到。现在有两个驱动可选：原始的 ISA/PCI `ne .c` 驱动和一个较新的仅限 PCI `ne2k–pci.c` 驱动。

要使用原始的 ISA/PCI 驱动，在运行 `make config` 时必须对 'Isa cards' 选项说 'Y'因为你使用的是与 ISA 卡相同的 NE2000 驱动。（这也提示了你，这些卡并不像 PCNet–PCI 或 PCI 21400 卡那样智能。）



ISA/PCI 驱动中较新的 `ne2k–only` 驱动支持了所有旧的 NE2000。

## ES3210

状态：部分支持，驱动程序名称：`es3210`

这是一张基于 EISA 8390 的共享内存网卡。v2.2 内核带有一个实验性驱动程序，据报道它可以工作；然而，EISA IRQ 和共享内存地址检测在（至少）早期修订版本的网卡上似乎不起。这个问题在 Linux 中并不孤有。在这种情况下，你必须手动为驱动程序提供这些参数。例如，对于卡 IRQ 5 和共享内存 `0x0d000`，使用模块化驱动时，在 `/etc/conf.modules` 中添加选项 `es3210 irq=5 mem=0x0d000`。如果将驱动编译到内核中，请在启动时提供 `ether=5,0,0x0d000,eth0`。I/O 基地址会自动检测，因此应使用值为零的值。

## 4.44 识别未知网卡

好了，假设你表哥的邻居朋友的兄弟在一个用作宠物仓鼠笼子的 AT 机机箱里发现了一块旧的 ISA 卡。你最终得到了这块卡，并想尝试在 Linux 下使用它，但没有人知道这块卡是什么，而且没有任何相关文档。

首先，寻找任何可能提供线索的型号数字。任何包含 2000 的型号极可能是 NE2000 的克隆卡。任何某处带有 8003 或 8013 标识的网卡都是 Western/Digital WD80x3 卡、SMC Elite 卡，或它们的克隆卡。

### 识别接口控制器

寻找网卡上最大的芯片。这可以通过其零件号来识别。如果你知道卡上是哪种网卡（NIC），以下信息可能帮助你判断它是哪种网卡。

最常见的网卡可能仍然国家半导体（National Semiconductor）的 DP8390、NS32490、DP8391、DP8392、DP8395 或 DP8397。而且这些都是国家半导体制造！其他公司如 Windbond 和 UTC 也制造了 DP8390 和 DP8395 的克隆产品，例如 Windbond 89c904 DP8395 克隆卡和 UMC 9090。如果卡上有某种形式的 8390 字样，那么它很有可能是 ne1000 或 ne2000 的克隆卡。第二常见的基于 8390 的卡是 wd80x3 克隆卡。带有 DP3895 的卡可以配置为 ne2000 或 wd8013。较版本的 wd80x3 和 SMC Elite 卡使用 83c790 代替了原始的 DP8390。SMC EtherEZ 卡使用 83c795，并与 SMC Ultra 使用相同的驱动。所有基于某些 8390 或 8390 克隆卡的 BNC 卡通常会在 BCC 附近有一个 8392（或 83c92，或 ???）16 DIP 引脚芯片。

在旧卡上找到的另一种常见网卡是 Intel `i82586`。带有这种网卡的卡包括 3c505、3c507、3c523、Intel Ethernet–ISA、Microdyne ECS–205 以及 Racal–Interlan N15210。

原始的 AMD LANCE 网卡是 AM7990，较新的版本包括 79c960、79c961、79c965、79c970 和 79c974。大多数带有上述任一芯片的卡都可以 LANCE 驱动，但 Racal–Interlan N6510 除外，它们有自己的驱动。

网卡上带有 DEC 21040、21041、21140 或类似数字的新型 PCI 卡应该能够使用 linux `tulip` 或 `deax25` 驱动。

其他带有标有 RTL8029、89c940 或 86c926 大芯片的 PCI 卡是 ne2000 克隆卡，Linux v2.0 中的驱动程序应在启动时自动检测这些卡。

### 识别以太网地址

每个以太网都有一个该网卡唯一的字节地址。对于该特定制造商的每块卡，地址的前三个字节是相同的。例如，SMC 卡以 00:00:c0 开头。后三个字节由厂家唯一标识，以便在生产时识别每块卡。

如果你的卡上贴有包含所有地址位位的贴纸，你可以通过前三个字节查询厂商。然而，更常见的是只有最后三个字节打印在带有插座式 ROM 的贴纸上，这无法提供任何信息。

你可以根据 RFC-1340 确定哪些厂商分配了地址。显然，在其他地方也有更新的列表。尝试在 WWW 或 FTP 上搜索以太网代码（Ethernet-codes），你会发现一些。

### 通过 FCC 编号识别网卡

作为认证流程的一部分，网卡在出售给用户之前必须通过测试，经过 FCC 测试后会获得一个 FCC ID，该 ID 应该打印在网卡的某处。例如，某块卡的 FCC ID 为 J158013EWC，这块卡恰好是 SMC/WD8013-EWC。一些像 `driverguide.com` 和 `drdriver.com` 的网站使用了 FCC ID 列表，可能有助于识别那些不明显的 ID。

### 使用未知网卡的技巧

如果你不确定这块卡是什么，但至少缩小了范围，那么你可以编译一个包含大量驱动程序的内核，看看是否有任何一个程序在启动时自动检测到该卡。

如果内核没有加载其他驱动程序，可能是因为网卡没有配置在驱动程序扫描网卡时的地址之一。在这种情况下，你可能想尝试从本地 ftp 站点获取 `scanport.tar.gz`，看看它是否能定位你的跳线强制设置的位置。它扫描 I/O 空间 0x100 到 0xff...（注：此处后续由于原文 OCR 错误显示为碎片化）。

## 5.2 双线对

Twisted pairs require active hubs, which start around $50, and the raw cable cost can actually be higher than thin. You can get many ugly claims that you are using your existing wiring as it is a rare installation that turns out to be the case.

On the other hand, 100Mb/sec ethernet proposals twisted pair, and most new installations use twisted pair. Also, Russ Nelson adds "New installations use Category 5 wiring. Everything else is a waste of your time, as 100Base–whatever is going to go Cat 5."

If you are only connecting two machines, it is possible to avoid using a hub, swapping the Rx and Tx pairs (1–2 and 3–6).

If you hold the RJ-45 connector facing you (as you were going to put it in your mouth) with the lock tab on the top, then the pins are numbered 1 to 8 from left to right. The pin usage is as follows:

| Pin Number | Assignment |
|---|---|
| 1 | Output Data (+) |
| 2 | Output Data (--) |
| 3 | Input Data (+) |
| 4 | Reserved for Telephone use |
| 5 | Reserved for Telephone use |



| 6 | Input Data (--) |

| 7 | Reserved for Telephone use |

| 8 | Reserved for Telephone use |

If you want to make a cable, the following should spell it out for you: Differential signals must be on the same twisted pair to get the required minimal impedance/loss of a UTP cable. If you look at the above table, you will see that `1+2` and `3+6` are the two sets of different signal. Not `1+3` and `2+6` at 10MHz, with short lengths, you *may* get away with such errors, if it is only over a short length. Don't even think about it at 100MHz.

For a normal patch cord, with ends `A` and `B`, you want straight pin-to-pin mapping, with input and output each a pair of twisted wires (for impedance). This means `1A` goes to `1B`, `2A` goes to `2B`, `3A` goes to `3B` and `6A` goes to `6B`. The wires joining `1A–1B` and `2A–2B` must be a twisted pair. Also the wires joining `3A–3B` and `6A–6B` must be another twisted pair.

If you don't have a cable, and want to make a `null cable`, what you want to do is make the input of `A` the output of `B` and the output of `A` be the input of `B`, without changing the polarity. This means `1A` to `3B` (out+ A in+ B) and `2A` to `6B` (out– A in– B). These two wires are twisted pair. They carry what/plug `A` considers output, and what is seen as input/plug `B`. Then connect `3A` to `1B` (in+ A out+ B) and also connect `6A` to `2B` (in– A out– B). These second two must be a twisted pair.

对于想要进一步了解网卡工作原理、玩玩现有的驱动程序、甚至尝试为目前不支持的网卡编写自己的驱动的人，这些信息将非常有用。如果你不属于这一类，可以跳过本节。

### 7.1 程序化 I/O (PIO) vs. 共享内存 vs. DMA

如果你已经可以连续发送和接收数据包，你只需要在总线上放置更多位即可。大多数现代以太网 `dp8390` 驱动（`wd80x3`, `SMC-Ultra`, `3c503`, `ne2000`）都非常接近连续发送包（取决于当前的中断延迟），而 `3c509` 和 `AT1500` 在自动发送连续包方面没有问题。

#### 程序化 I/O（例如 NE2000, 3c509）

- 优点：不使用任何受限系统资源，只需要几个 I/O 寄存器，且没有 16M 限制。
- 缺点：通常传输最慢，CPU 全程等待，且通常很难实现交错的数据包访问。

#### 共享内存（例如 WD80x3, SMC–Ultra, 3c503）

- 优点：简单，比程序化 I/O 快，并允许对数据包进行随机访问。在可能的情况下，Linux 驱动程序会在从网卡拷贝数据时计算输入 IP 数据包的校验和，与同类的 PIO 卡相比进一步减少了 CPU 占用。
- 缺点：占用内存空间（对于 DOS 用户来说是个大问题，在 Linux 下基本上不是问题），而且仍然会占用 CPU。

#### 从机（普通）直接内存器访问（例如 Linux 中没有！）

- 优点：在实际数据传输期间释放 CPU。
- 缺点：检查边界条件、对齐连续缓冲区以及编写 DMA 寄存器使其成为所有技术中最慢的。它还使用了稀缺的 DMA 通道，并需要对齐的内存缓冲区。

#### 总线主设备直接内存器访问（例如 LANCE, DEC 21040）

- 优点：在数据传输期间释放 CPU，可以将缓冲区串联，总线上几乎不需要或不需要丢失 CPU 时间。大多数总线主设备驱动现在使用“拷贝中断”（copybreak）方案，即大数据包由网卡直接放入内核缓冲区，小数据包由 CPU 拷贝，从而为后续处理预热缓存。
- 缺点：（仅适用于 ISA 卡）需要低内存缓冲区和 DMA 通道。任何总线主设备在遇到其他“总线占用者”总线主设备时都会遇到问题，特别是一些原始的 SCSI 适配器。设计不当的主板芯片组在处理总线主设备时存在问题。不使用任何类型的 DMA 设备的原因之一是用 486 处理器来替换 386：这些处理器在每个 DMA 周期中必须刷新其缓存。（这包括 `Cx486DLC`, `Ti486DLC`, `Cx486SLC`, `Ti486SLC` 等。）

### 7.2 总线宽度对性能的影响

ISA 可以达到 5.3MB/sec，这对于 10Mbps 以太网来说似乎足够了。但在 100Mbps 网络的情况下，你需要更快的缓冲区来利用网络带宽。

#### ISA 8 位卡 vs 16 位卡

你可能买不到 8 位 ISA 以太网卡，但可以在二手市场找到很多，价格非常廉。这使得它们在未来几年内很受欢迎。上述结论适用于 16 位 ISA 卡，因为 PCI 卡现在很常见。

一些对于轻量使用提供足够性能的 8 位卡是 `wd8003`，`ec501` 性能很差，这些 12 年历史的遗迹应该被避免。（把它们给 Alan，他正在收集……）

8 位路径对性能不会产生太大影响，因为你可以预计从快速 ISA 总线上的快速主机获得约 800 kb/ps 的下载速度。如果你的大部分网络流量去往远程站点，那么路径上的瓶颈会在其他地方，你只有在本地子网活动时才会注意到速度差异。

### 9.1 向内核传递以太网参数

这里有两个可以在启动时传递给内核的通用内核命令（`ether` 和 `reserve`）。可以通过 `LILO`、`loadlin` 或任何接受可选参数的启动工具完成。

例如，如果命令为 'blah' 并且添加了 3 个参数（例如 123, 456 和 789），那么在 `LILO` 中，你将使用：

```
LILO: blah=123,456,789
```

有关启动时参数（以及完整列表）的更多信息，请参 BootPrompt–HOWTO。

#### ether–argument 命令

`ether–argument` 与直接构建在内核中的驱动程序配合使用。`ether–argument` 对模块化驱动程序没有任何影响。在最通用的形式下它看起来像这样：

```
ether=IRQ, BASE_ADDR, PARAM_1, PARAM_2, NAME
```

# Linux 以太网指南

所有参数都是可选的。第一个非数字参数被视为 `NAME`。

- `IRQ`: 显而易见。`IRQ` 值 `0`（通常为默认值）意味着自动 IRQ。`IRQ` 设置是固定而非 base_addr 定的是一个历史偶然——每当发生变化时，它就会被修复。
- `BASE_ADDR`: 显而易见。值 `0`（通常为默认值）意味着使用以太卡的板载类型特定地址列表。
- `PARAM_1`: 它最初用于共享内存以太网卡 `WD80*3` 的内存起始地址覆盖。某些驱动程序使用此值的四位来设置调试级别 0 — 默认，1–7 — 1…7（最大详细程度），8 — 级别（无消息）。`LANCE` 驱动程序使用此值的四位来选择 DMA 通道。否则，它使用自动 DMA。
- `PARAM_2`: `3c503` 驱动程序使用此在内部和外部收发器之间选择。0 — 默认/内部，1 — AUI 外部。Carleton `E21XX` 卡也使用 `PARAM_2` 的 4 位来选择输出介质。它会自动检测它们。
- `NAME`: 网络设备值指向此处。标准使用 `eth0`、`eth1`、`eth2` 和 `eth3` 名称用于总线连接的以太卡，`atp0` 用于并行端口 `口袋以太网适配器`。`arcent` 驱动程序使用 `arc` 作为名称。默认设置是启用 `eth0` 的探测。可以通过 `LANCE` 参数显式设置这些探测来启用多块卡。1.0 内核中基于 `LANCE` 的以太卡是一个规模事实。`LILO` 参数被忽略，且 `LANCE` 卡始终被分配为 `eth<n>`。额外的非 `LANCE` 以太卡必须显式分配为 `eth<n+1>`，而通常的 `eth0` 探测某些东西诸如 `eth0=0,-1,eth0`。（是的，这是一个 bug）。

### reserve 命令

此 `lilo` 命令与上述的 `eth=` 类似，它被附加到 `lilo` 中指定的启动选择名称之后：

```
reserve=IO-base,extent(, IO-base,extent...)
```

在某些机器上，它可能需要防止设备驱动程序在特定区域检查设备（自动探测）。这可能是因为硬件设计不当导致启动冻结（例如某些以太卡）、硬件被错误识别（其状态被早期的探测更改），或硬件不知道要初始的内核。

`reserve` 启动时间通过指定一个不应探测的 I/O 端口区域来解决这个问题。该区域在内核的端口注册表中被保留，仿佛在该区域已经找到了一个设备。这种机制在大多数机器上是不需要的。只有在出现问题或特殊情况时才需要使用它。

指定区域内的 I/O 端口受设备探测的保护。这用于当一个驱动程序运行在 `NE2000` 上，或将某些其他设备误识别为我们的设备时。正确的驱动程序不应该保留一个区域，除非另一个启动参数显式指定这样做。这意味着 `reserve` 经常必须与某些启动参数一起使用。

## 9.2 作为模块使用以太网驱动

大多数 Linux 发行版现在提供的内核包含极少的内置驱动。驱动程序改为以可加载模块的形式提供。这些模块驱动程序通常由管理员使用 `modprobe` 命令加载，在某些情况下由内核自动加载。

特定的发行版可能提供用于设置模块的良好图形化工具。随后的描述提供了有关这些程序的信息。

控制使用哪些模块以及向每个模块提供哪些选项的信息通常存储在 `/etc/conf.modules` 文件中。两个两个主要选项（针对以太卡）将在文件中作为 `alias` 和 `options` 使用。`modprobe` 命令查询此信息。

模块本身通常存储在名为 `/lib/modules/` 的目录中（`uname -r` 给内核版本，例如 2.0.34）。你可以在那里查看哪些模块匹配你的卡。



`conf.modules` 文件中需要的第一个内容是告诉 `modprobe` 为 `eth0` 和网络接口使用哪个驱动。例如，如果你有一块使用 `smc-ultra` 驱动模块的 ISA SMCZ 卡，你需要通过添加以下行将该驱动别名为 `eth0`：

```
alias eth0 smc-ultra
```

你需要的另一个内容是 `options` 行，指示与特定模块（或模块别名）使用的选项。继续上面的，例如，如果你只有一个 `alias` 行而没有 `options` 行，内核会警告你（`dmesg`）ISA 卡的自动探测不是好主意。为了消除这一点，你需要添加另一行告知模块配置的 I/O 基地址，在此例中使用十六进制地址 `0x280`。

```
options smc-ultra io=0x280
```

大多数 ISA 模块在 `insmod` 命令行接受类似 `io=0x340` 和 `irq=12` 的参数。强制或至少强烈建议你提供这些参数以避免探测卡。与 PCI 和大多数设备不同，大多数 ISA 设备没有真正的方法进行自动探测，因此在作为模块使用驱动时应避免这样做。

每个模块可以使用的选项列表可以在文件中找到：

`/usr/src/linux/Documentation/networking/net-modules.txt`

建议你阅读以了解针对你的特定网卡可以使用哪些选项。请注意，某些模块支持逗号分隔的值列表，这些模块具有处理单个模块多个设备的能力，例如基于 `8390` 的驱动以及 `PLIP` 驱动。例如：

```
options 3c503 io=0x280,0x300,0x330,0x350 xcvr=0,1,0
```

上述配置将由一个模块控制四块 `3c503` 卡，其中卡 2 和卡 4 使用外部收发器。不要在“—”或逗号周围添加空格。

请注意，忙碌（`busy`）模块无法移除。这意味着在移除模块之前，你必须执行 `ifconfig eth0 down`（关闭以太网）。

`lsmod` 命令将向你加载了哪些模块以及它们是否正在在使用，而 `rmmod` 则将移除它们。
