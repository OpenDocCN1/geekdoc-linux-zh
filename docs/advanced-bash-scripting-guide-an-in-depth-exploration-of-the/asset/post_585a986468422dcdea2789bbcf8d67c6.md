
# Chapter 7. Tests

Every reasonably complete programming language can test for a condition, and then according to the result of the test. Bash has introduced the test command, various bracket and parenthesis operators, and the if/then construct.

## 7.1. Test Constructs

- An if/then construct tests whether the exit status of a list of commands is 0 (since 0 means “success” by UNIX env), and if, executes one or more commands.
- There exists a dedicated command called `[`. It is a synonym for test, and a builtin for efficiency reasons. This command considers its arguments as comparison expressions or file tests and returns an exit status corresponding to the result of the comparison (0 for true, 1 for false).
- With version 2.02, Bash introduced `[` extended test command, which performs comparisons in a manner more familiar to programmers from other languages. Note that [[ is a keyword, not a command.

Bash sees `[[ $a -lt $b ]]` as a single element, which returns an exit status.

The `(( ))` and `let` constructs return an exit status, according to the arithmetic expressions they evaluate to a non-zero value. The arithmetic-expansion constructs may therefore be used to perform arithmetic comparisons.

```bash
(( 0 & 1 ))
echo $? # 1 ***
# And so ...
let *num = (( 0 & 1 ))
echo $num # 0
# But ...
let *num = (( 0 & 1 ))
echo $? # 1 ***
```

```bash
(( 200 | 11 ))
echo $? # 0 ***
let *num = (( 200 | 11 ))
echo $num # 1
let *num = (( 200 | 11 ))
echo $? # 0 ***
```

```bash
(( 200 | 11 ))
echo $? # 0 ***
let *num = (( 200 | 11 ))
echo $num # 203
let *num = (( 200 | 11 ))
echo $? # 0 ***
```

The "let" construct returns the same exit status as the double-parentheses arithmetic expansion.

# Advanced Bash-Scripting Guide

Again, note that the exit status of an arithmetic expression is not an error value.

```bash
var=2 (( (var+=2 ))
echo $? # 1
var=2 (( (var+=2 )) echo $var
                                # Will not echo $var!
```

An if can test any command, not just conditions enclosed within brackets.

```bash
if cmp a b /dev/null # Suppression output.
then echo "Files a and b are identical."
else echo "Files and b differ."
fi

# The very useful "if-grep" construct:
#
if grep -q Bash file
then echo "File contains at least one occurrence of Bash."
fi

word-linux
letter_sequence-inu
if echo $word | grep -q "$letter_sequence"
# The -q option to grep suppresses output.
then
echo "$letter_sequence found in $word"
else
echo "$letter_sequence not found in $word"
fi

if COMMAND_WHOSE_EXIT_STATUS_IS_0_UNLESS_ERROR_OCCURRED
then echo "Command succeeded."
else echo "Command failed."
fi
```

# Example 7-1. What is true?

```bash
#!/bin/bash

# Tip:
# If you're unsure how a certain condition might evaluate,
# test it in an if-test.

echo
echo "Testing \"*\""
if [ 0 ] # zero
then
echo "0 is true."
else # 0 else ...
echo "0 is false."
fi # 0 is true.

echo
```

# When is "false" true?

```bash
echo Testing \"false\"" # It seems that "false" is just a string
if [ "false" ]
then
    echo \"false\" is true. # and it tests true.
else
    echo \"false\" is false.
fi # "false" is true.
```

```bash
echo Testing \"\$false\"" # Again, uninitialized variable.
if [ "$false" ]
then
    echo \"$false\" is true.
else
    echo \"$false\" is false.
fi # "$false" is false. # Now, we get the expected result.
```
