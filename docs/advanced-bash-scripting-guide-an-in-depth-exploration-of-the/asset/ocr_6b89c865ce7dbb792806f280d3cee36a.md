To keep a record of which user scripts have run during a particular session or over a number of sessions, add the following lines to each script you want to keep of. This will keep a continuing record of the script name and invocation times.

```
# Append (>>) following to end of each script tracked.
whoami>> $SAVE_FILE      # User invoking the script.
echo $0>> $SAVE_FILE      # Script name.
date>> $SAVE_FILE        # Date and time.
echo>> $SAVE_FILE        # Blank line as separator.

# Of course, $SAVE_FILE defined and exported as environmental variable in ~/.bashrc
++ (something like ~/.script-run)
```

>> operator appends lines to a file. If you wish to prepend a line to an existing file, that is, to start at the beginning of

```
file=data.txt
title="**This is the title line of data file file****"
echo $title | cat - $file>$file.new
# "cat -" concatenates stdout to $file.
# End result is
++.to write a new file with $title appended at 'beginning'."
```

A shell script may be acted as an embedded command inside another shell, a Tcl or wish script, or even a Makefile. It can be invoked as an external shell command in a C program using the system() call, i.e., system("script_name");

Setting a variable to the contents of an embedded sed or awk script increases the readability of the surrounding shell wrapper. See Example A-1 and Example 15-20.

Put together files containing your and most useful definitions and functions. As necessary, "include" one or more of these "library files" in scripts using the dot (.) or source command.

```
# SCRIPT LIBRARY

# Note:
# No "#!" here.
# No "live code" either.

# Useful variable definitions
ROOT_UID=0             # Root has UID 0.
E_NOTROOT=101         # Not root user error.
MAXRETRIEVAL=255      # Maximum (positive) return value of a function.
SUCCESS=0
FAILURE=-1
```
