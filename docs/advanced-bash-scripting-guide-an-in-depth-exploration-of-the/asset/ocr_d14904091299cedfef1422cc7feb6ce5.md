```
old_tty_setting=$($tty -g) # Save old terminal setting.
echo "Hit a key"
stty -icanon -echo # Disable "canonical" mode for terminal.
# Also, disable "local" echo.
key=$(dd bs=1 count=2 < /dev/null) # Using 'dd' to get a keypress.
stty "$old_tty_setting" # Restore old setting.
echo "You hit $key key." # ${#variable} = number of characters in $variable

# Hit any key RETURN, and the output is "You hit 1 key."
# Hit RETURN, and it's "You hit 0 key."
# The newline gets eaten in the command substitution.
Code snippet by Stéphane Chazelas.
```

Using echo to output an unquoted variable with command substitution removes newlines characters from the output of the reassigned command). This can cause unpleasant surprises.

```
dir_listing=ls -l
echo $dir_listing # unquoted
```

```
# Expecting a nicely ordered directory listing.
```

```
# However, what you get is:
# total 3-rw-rw-rw- 1 bozo 30 May 13 17:15 1.txt-rw-rw-rw- 1 bozo
# bozo 51 May 19 20:57 t2.sh -rwxr-xr-x 1 bozo 217 Mar 5 21:13 wi.sh
```

```
# The newlines are disappeared.
```

```
echo "$dir_listing" # quoted
# -rw-rw-r-- 1 bozo 30 May 13 17:15 1.txt
# -rw-rw-r-- 1 bozo 51 May 19 20:57 t2.sh
# -rwxr-xr-x 1 bozo 217 Mar 5 21:13 wi.sh
```

Command substitution permits you to set contents of a file, when using redirection or to the cat command.

```
variable1='<file' # Set "variable1" to contents of "file"
variable2=cat file2 # Set "variable2" to contents of "file2"
# This, however, forks a new process,
# so the line of code executes slower than the above version.
```

```
# Note that the variables may contain embedded whitespace,
# or even (horrors), control characters.
```
