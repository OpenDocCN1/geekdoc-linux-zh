# Advanced Bash-Scripting Guide

The process calling sets the $0 parameter. By convention, this parameter is the name of the script. See the manpage (manual page) for execv.

From the command-line, however, $0 is the name of the shell.

```
bash$ echo $0
bash
tctsh$ echo $0
tctsh
```

More of concern is the apparently inconsistent behavior of \ within double quotes, and especially following an \ command.

```
bash$ echo hello!\nhello!
bash$ echo "hello!\"
hello\!
```

```
bash$ echo \\
>
bash$ echo "\"
>
bash$ echo \a
a
bash$ echo "\a"
\a
```

```
bash$ echo x\ty
ty
bash$ echo "x\ty"
ty
```

```
bash$ echo -e x\ty
ty
bash$ echo -e "x\ty"
x
```

Double quotes following an echo sometimes escape \. Moreover, the -e option to echo causes the "t" to be interpreted as a tab.

(Thank you, Wayne Pollock, for pointing this out, and Geoff Lee and Daniel Barclay for explaining it.)
