In the simplest case, a script is nothing more than a list of system commands stored in a file. At the very least, this saves the effort of retyping that sequence of commands each time it is invoked.

Example 2-1. cleanup: A script to clean log files in /var/log

```
# Cleanup
# Run as root, of course.

cd /var/log
cat /dev/null > messages
cat /dev/null wtmp
echo "Log files cleaned up."
```

There is nothing unusual here, only a set of commands that could just easily have been invoked by one from the command-line on the console or in a terminal. The advantages of placing the commands in a script far beyond having to retype them time and again. The script becomes a program -- a tool -- and it can be easily modified or customized for a particular application.

Example 2-2. cleanup: An improved clean-up script

```
#!/bin/bash
# Proper header for a Bash script.

# Cleanup, version 2

# Run as root, of course.
# Insert code here to print error message and exit if not root.

LOG_DIR=/var/log
# Variables are better than hard-coded values.
cd $LOG_DIR

cat /dev/null > messages
cat /dev/null wtmp
echo "Logs cleaned up."
```

```
exit # The right and proper method of "exiting" from a script.
# A bare "exit" (no parameter) returns the exit status
#+ of the preceding command.
```

Now's beginning to look like a real script. But we can go further...
