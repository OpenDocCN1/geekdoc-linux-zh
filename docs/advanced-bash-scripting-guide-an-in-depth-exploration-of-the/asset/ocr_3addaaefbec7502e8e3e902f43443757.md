# Advanced Bash-Scripting Guide

```
echo -n "$n"
n-[$n + 1]
# Works even if "$n" was initialized as a string.
# Avoid this type of construct, since it is obsolete and nonportable.
# Thanks, Stephanie Chazelas.
echo -n "$n"

# Now for C-style increment operators.
# Thanks, Frank Wang, for pointing this out.

let "++"      # let "++" also works.
echo -n "$n"

(( n))         # (( ++n)) also works.
echo -n "$n"

:((++n)))    # $(( ++n)) also works.
echo -n "$n"

[$++n]         # $[ ++n ] also works
echo -n "$n"

echo

echo 0
```

Integer variables in older versions of Bash were signed long (32-bit) integers, in the range of -2147483648 to 2147483647. An operation that took a variable outside these limits gave an erroneous result.

```
echo $BASH_VERSION    # 1.14
a=2147483646
echo "a=$a"      # a = 2147483646
let a="a+1"      # Increment "a"
echo "a=$a"      # a = -2147483648 again, pass the limit.
let a="a-1"      # increment = -2147483648
echo "a=$a"      # ERROR: out of range,
# +               and the leftmost bit, the sign bit,
# +               has been set, making the result negative.
```

As of version >=2.05, Bash handles 64-bit integers.

Bash does not understand floating point arithmetic. It treats numbers containing a decimal point as strings.

```
a=1.5
let "b = $a + 1.3"  # Error.
# t2.sh: let: b = 1.5 + 1.3: : syntax error in expression
# (error token is ".5 + 1.3")
echo "b=$b"      # b=1
Use b in scripts that do not need floating point calculations or math library functions.
```
