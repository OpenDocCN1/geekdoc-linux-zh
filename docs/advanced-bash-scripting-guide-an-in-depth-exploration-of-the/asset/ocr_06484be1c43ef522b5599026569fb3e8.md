for (( i=0; i<${#array[@]}; i++ ))

# Which yields:
# Test Three -- Our marker element.
# Element 0: zero is 4 long. # Intended result.
# Element 1: Hello $(Me) is: 11 long. # $(You) expanded to nothing.
# Element 2: Hello is: 5 long. # Split at the whitespace.
# Element 3: 'Pass' is: 6 long. # The end is quite here.
# Element 4: ' ' is: 1 long.

Our Element 1 has its leading and trailing quotes stripped.
Although not shown, leading and trailing whitespace is also stripped.
Now that the strings are set, Bash will also, internally,
hard the quotes as required during its operations.

Why?
Consiring our "${pls 'Hello($Me)'" construction:
"*" -> Expansion result, strip the quotes.
$(...) -> Replace with the result of..., strip this.
_pls '... ' -> called with literal arguments, strip the quotes.
The result returned includes hard quotes; BUT the above processingnhas been done, so they become part of the value assigned.

Similarly, during further using the string variable, ${Me}
is part of the contents (result) and survives any operations
(Until explicitly to evaluate the string).
