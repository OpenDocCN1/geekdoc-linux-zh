$UID 用户 ID 数字

在 /etc/passwd 中记录的当前用户身份标识码

这是当前用户的真实 ID，即使她通过 su 临时假用了另一个身份。$UID 是一个只读变量，不能从命令行或脚本内部更改，它是内置命令 `id` 的对应项。

# 示例 9-5.我是 root 吗？

```bash
#!/bin/bash
# am-i-root.sh:    我是 root 还是不是？

ROOT_UID=0      # Root 的 $UID 为 0。

if [ "$UID" -eq "$ROOT_UID" ]; # 请真正的 "root" 站起来？
then
    echo "You are root"
else
    echo "You are just an ordinary user (but mom loves you just the same)"
fi

exit 0
```

# 位置参数

$0, $1, $2 等

从命令行传递给脚本、传递给函数或赋值给变量的位置参数（参见示例 4-5 和示例 15-16）

$# 命令行参数的个数 [44] 或位置参数的个数（参见示例 36-2）

$* 所有位置参数，被视为单个单词

> "$+" 必须加引号。

$@ 与 $* 相同，但每个参数都是带引号的字符串，也就是说，参数是完整传递的，而不经过解释或表达式处理。这意味着在其他情况下，参数列表中的每个参数都被视为一个独立的单词。

> 当然，"$@" 应该加引号。

执行 `shift` 后，$@ 持有剩余的命令行参数，缺少了先前的 $1。

```bash
#!/bin/bash
# 使用 .scriptname 1 2 3 4 5 调用
echo "$0"    # 1 2 3 4 5
shift
echo "$0"    # 2 3 4 5
shift
echo "$0"    # 3 4 5
```

# 每执行一次 "shift" 就会丢失参数 $1。
# "$@" 则包含剩余参数。
$@ 特殊参数作为过滤输入到 shell 脚本的工具。cat "$@" 结构接受来自标准输入或作为脚本参数的文件的输入。参见示例 16-24 和示例 16-25。

$* 和 @@ 参数有时会表现出不一致且令人疑惑的行为，取决于 IFS 的设置。

# 示例 9-7. 不一致的 $* 和 @@ 行为

```bash
#!/bin/bash

# "$*" 和 "$@" Bash 内部变量的反复行为，
## 取决于它们是否加了引号。
## 展示了对单词分割和换行符不一致的处理。

set -- "First one" "second" "third:one" "Fifth: :one"
# 设置脚本参数 $1, $2, $3 等。
echo

echo 'IFS unchanged, using "$*"'
c=0
for i in "$*";                    # 加了引号
do
  echo "$((c+1)): [$i]"     # 这一行在每个实例中保持不变。
                                     # 输出参数。
done
echo ---

echo 'IFS unchanged, using $*'
c=0
for i in $*                        # 未加引号
do
  echo "$((c+1)): [$i]"
done
echo ---

echo 'IFS unchanged, using "$@"'
c=0
for i in "$@"
do
  echo "$((c+1)): [$i]"
done
echo ---

echo 'IFS unchanged, using $@'
c=0
for i in $@
do
  echo "$((c+1)): [$i]"
done
echo ---

IFS=
echo 'IFS=":", using "$"'
c=0
for i in "$*"
do
  echo "$((c+1)): [$i]"
done
echo ---

echo 'IFS=":", using $*'
c=0
for i in $*
do
  echo "$((c+1)): [$i]"
done
echo ---

echo 'IFS=":", using "$@"'
c=0
for i in "$@"
do
  echo "$((c+1)): [$i]"
done
echo ---

echo 'IFS=":", using $@'
c=0
for i in $@
do
  echo "$((c+1)): [$i]"
done
echo ---
```
