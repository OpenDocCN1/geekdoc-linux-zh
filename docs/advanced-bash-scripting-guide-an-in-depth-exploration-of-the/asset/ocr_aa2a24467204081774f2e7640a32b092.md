The sha-bang (!) [6] at the head of a script tells you that this is a set of commands to be fed the command interpreter indicated. The # is actually a two-byte [7] magic number, a special marker that designates a file type, or in this case an shell script (type man magic for more details on the fascinating topic). Immediately following the sha-bang is the path to the program that interprets the commands in the script, whether it be a shell, a programming language, or a utility. The command interpreter executes the commands in the script, starting at the top (the line following the sha-bang line), and ignoring comments. [8]

```
#!/bin/sh
#!/bin/bash
#!/usr/bin/perl
#!/usr/bin/tcl
#!/bin/sed -f
#!/bin/awk -f
```

Each of the above header lines calls a different command interpreter, it be /bin/sh, the default shell (bash in Linux system) or others. Using [9] !/bin/sh, the default Bourne shell in most commercial variants of UNIX, makes the script portable to Linux-machines, which you sacrifice Bash-specific features. The script will, however, conform to the POSIX [10] standard.

Note that the path given at the "sha-bang" may cause, another error message -- usually "Command not found." -- will be the only result of running the script. [11]

#! can be omitted if the script consists only of a generic of system commands, using no internal shell directives. The second example, requires, the initial !, since the variable assignment line, lines=50, uses a shell-specific script. [12] Note that #!/bin/sh invokes the default interpreter, which defaults to /bin/bash on a Linux machine.
