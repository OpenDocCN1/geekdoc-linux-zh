## Example 15-2. printf in action

```bash
#!/bin/bash
# printf demo

declare -r PI=31.4159265358979  # Read-only variable, i.e., a constant.
declare -r DecimalConstant=31373

Message1="Greetings,"
Message2="Earthling."
echo

printf "PI to 2 decimal places = %1.2f" $PI
echo
printf "PI to 9 decimal places = %1.9f" $PI  # It evens rounds correctly.

printf "\n"                          # Prints a line feed,
                              # Equivalent to 'echo' . .

printf "Constant = %t\d" $DecimalConstant  # Inserts tab (\t).

printf "%s %s \n" $Message1 $Message2
echo
===============================================
# Simulation of C function, sprintf().
# Loading a variable with a formatted string.
echo
PI2=$(printf "%1.12f" $PI)
echo "PI to 12 decimal places = $PI2"  # Roundoffs error!
Msg=$(printf "%s %s \n" $Message1 $Message2
echo $Msg; echo $Msg

# As it happens, the 'sprintf' function can now be accessed
#+ as a loadable module to Bash,
#+ but this is not portable.

exit 0
```

## Example 15-3. Variable assignment, using read

```bash
#!/bin/bash
# "Reading" variables.

echo -n "Enter the value of variable 'var1':"
# The -n option suppresses newline.

read var1
# Note no '$' in front of var1, since it is being set.

echo "var = $var1"

echo

# A single 'read' statement can set multiple variables.
echo -n "Enter the values of variables 'var2' and 'var3'"
echo -n "(separated by a space or tab):"
read var2 var3
echo var2=$var2 var3=$var3
# if you input only one value,
#+ the other variable(s) will remain unset (null).

exit 0
```

Normally, inputting a \ suppresses a newline during a read. The -r option allows an inputted a \ to be interpreted literally.

## Example 15-5, Multi-line input to read

```bash
#!/bin/bash
echo
echo "Enter a string terminated by a \, then press <ENTER>."
echo "Then, enter a second string (no \ this time), and again press <ENTER>"
read -r var1      # The \ suppresses the newline, when reading $var1.
                  # first line \
                  # second line
echo var1 = "$var1"
          # first line second line

# For each line terminated by a \
#+ you get a prompt on the next line to continue feeding characters into var1.
echo; echo
echo "Enter another string terminated by a \, then press <ENTER>."
read -r var2  # The -r option causes the "\" to be read literally.
              # first line \
echo var2 = "$var2"
      # first line
```

Chapter 15. Internal Commands and Builtins

The `read` command has some interesting options that permit echoing a prompt and reading keystrokes.

- -s: means not echo input.
- -n: accept only N characters of input.
- -p: echo the following prompt before reading input.

Using these options is tricky, since they need to be in the correct order. The -n option to read also allows detection of arrow keys and certain unusual keys.

### Example 15-6. Detecting the arrow keys

```bash
#!/bin/bash
# arrow-detect.sh: Detects the arrow keys, and a few more.
# Thank you, Magi, for showing me.
------------------------------------
# Character codes generated by keys.
arrowup='A'
arrowdown='B'
arrowright='C'
arrowleft='D'
insert='Z'
delete='3'
------------------------------------

SUCCESS=0
OTHER=65

echo -n "Press a key..." # May need to press ENTER if a key not listed above.
read -n 3 key # Read 3 characters.

echo -n "$key" | grep "$arrowup" # Check if character code detected.
if [ "$key" -eq $SUCCESS ]; then
    echo "Up-arrow key pressed."
    exit $SUCCESS
fi

echo -n "$key" | grep "$arrowdown"
if [ "$key" -eq $SUCCESS ]; then
    echo "Down-arrow key pressed."
    exit $SUCCESS
fi

echo -n "$key" | grep "$arrowright"
if [ "$key" -eq $SUCCESS ]; then
    echo "Right-arrow key pressed."
    exit $SUCCESS
fi

echo -n "$key" | grep "$arrowleft"
if [ "$key" -eq $SUCCESS ]; then
    echo "Left-arrow key pressed."
    exit $SUCCESS
fi

echo -n "$key" | grep "$insert"
if [ "$key" -eq $SUCCESS ]; then
    echo "Insert key pressed."
    exit $SUCCESS
fi

echo -n "$key" | grep "$delete"
if [ "$key" -eq $SUCCESS ]; then
    echo "Delete key pressed."
    exit $SUCCESS
fi

echo "Some other key pressed."
exit $OTHER

```bash
#!//bin/bash

uparrow='[A'
downarrow='[B'
leftarrow='[D'
rightarrow='[C'

read -s -n 3 p "Hit an arrow key: " x

case $x in
$uparrow)
    echo "You pressed up-arrow"
    ;;
$downarrow)
    echo "You pressed down-arrow"
    ;;
$leftarrow)
    echo "You pressed left-arrow"
    ;;
$rightarrow)
    echo "You pressed right-arrow"
    ;;
esac
exit $?
```

## Example 15-7. Using read with file redirection

```bash
#!/bin/bash

read var1 <data-file
echo var1 = $var1
# var1 set to the entire first line of the input file "data-file"

read var2 <data-file
echo var2 = $var2 var3 = $var3
# Note non-intuitive behavior of "read"
# 1) Rewinds back to the beginning of input file.
# 2) Each variable is now set to a corresponding string,
#   separated by whitespace, rather than an entire line of text.
```
