# Appendix D. Parsing and Managing Pathnames

Emmanuel Rouat contributed the following example of parsing and transforming filenames, and in particular, pathnames. It draws heavily on the functionality of sed.

```
#!/usr/bin/env bash

# Management of PATH, LD_LIBRARY_PATH, MANPATH variables...
# By Emmanuel Rouat <noemail>
# (Inspired by the bash documentation 'pathfuncs' and
# discussions found on stackoverflow:
# https://stackoverflow.com/questions/370047/
# https://stackoverflow.com/questions/273909/#34860
# Last modified: Sat 22 Sep 12:01:55 CEST 2012

# The following functions handle spaces correctly.
# These functions belong in .bash_profile rather than in
# .bashrc
# I guess.

# The modular structure of these functions makes it easy
# to expand them to handle path substitutions instead
# of path removal...

# See http://www.catman.net/blog/awk-one-liners-explained-part-two/
# (item 43) for an explanation of the 'duplicate-entries' removal
# (it's a nice trick!)

# Show $ (usually PATH) as list.
function p_show() { local p="$$"; for p in $p; do [[ ! $p ]] && echo "${p//\/}\"; done }

# Filter empty lines, multiple/trailing slashes, and duplicate entries.
function p_filter() {
awk '/^[[:space:]]*$/ | next (sub(/\/+/, "/"); gsub(/\/+/, "/"))!x[$0]++';
}

# Clean (typically PATH) and rebuild it
function p_build() { paste -d '; }
function p_clean() {
local p="$1"; echo "$(p_show $p | p_filter | p_build)"
}

# Remove $ from $2 (found on stackoverflow, with modifications).
function p_rm() {
local d=$(echo "$1" | p_filter) p=($$2) &&
eval p="$(p_show $p | p_filter | grep -v "${$d}" | p_build)"
}

# Same as previous, but filters on a pattern (dangerous...).
# don't use 'bin' or '*/' as pattern!.
function p_rmpat() {
local d=$(echo "$1" | p_filter) p=($$2) && eval p="$(p_show $p | p_filter | grep -v "${$d}" | p_build)"
}

# Delete $1 from two and append it cleanly.
function p_append() {
local d=$(echo "$1" | p_filter) p=($$2) p p_rm="${$d}" &&
eval p="$(p_show $p | d | p_build)"
}

# Delete $1 and prepend it cleanly.
```
