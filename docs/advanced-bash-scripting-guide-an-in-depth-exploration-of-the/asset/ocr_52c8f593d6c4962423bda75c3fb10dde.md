Example 16-56. Using getopt to parse command-line-options

```
#!/bin/bash
# Using getopt

# Try the following when invoking this script:
# sh ex3a.sh -a
# sh ex3a.sh -abc
# sh ex3a.sh -a -b -c
# sh ex3a.sh -d
# sh ex3a.sh -dXYZ
# sh ex3a.sh -d XYZ
# sh ex3a.sh -abcd
# sh ex3a.sh -abcdZ
# sh ex3a.sh -z
# Explain the results of each of the above.
```

```
E_OPTERR=65
if [ "$#" -eq 0 ];
then    # Script needs at least one command-argument.
    echo "Usage $0 [-options a,b,c]"
    exit $E_OPTERR
fi
```

```
set -- getopt "$@"
# Sets parameters to command-line arguments.
# What happens if you use "$*" instead of "$@"

while [ -n "$1" ];
do
    case $$" in
        -a) echo "Option \a:$"
        -b) echo "Option \b:$"
        -c) echo "Option \c:$"
        -d) echo "Option \d: $2"
        *) break;
    esac

    shift
done
```

```
# It is usually better to use the 'getopts' builtin in a script.
# See ex3a.sh.
```

exit 0

> As Peggy Russell points out:

It is often necessary to include an eval to correctly process whitespace and quotes.

```
args=$(getopt -a abcd -- "$@")
eval set -- "$args"
```
