# # Appendix C. A Sed and Awk Micro-Primer

This is a very brief introduction to the **sed** and **awk** text processing Utilities. We will deal with only a few commands here, but that will suffice for understanding simple sed and awk constructs within shell scripts.

**sed**: a non-interactive text file editor

**awk**: a field-oriented pattern processing language with a C-style syntax

For all differences, the two utilities share a similar invocation syntax, regular expressions , read input by default by `stdin`, and output to `stdout`. These are well-behaved UNIX tools, and they work together well. The output from one can be piped to the other, and their combined capabilities give sed some the power of Perl.

+   - One difference between the utilities is that while shell scripts can easily pass arguments to sed, it is more cumbersome for awk (see Example 36-5 and Example 28-2).

# ## C.1. Sed

Sed is a non-interactive [141] stream editor. It reads text input, from `stdin` or from file, performs certain operations on specified lines of the input, one line at a time, and then outputs the results to `stdout` or to file. Within a shell script, `sed` is usually one of several tools in a pipe.

Sed determines which lines of its input that it will operate on by the address range passed to it. [142] Specifically this address range either by line number or by a pattern to match. For example, `3d` sed to delete line 3 of the input, and `/Windows/d` tells sed you want every line of the input containing a match to “Windows” deleted.

Of all the operations in the `sed` toolkit, we will focus primarily on the three most commonly used ones. are printing (to `stdout`), deletion, and substitution.

| Operator | Name | Effect |
|---|---|---|
| [address-range]/p | print | Print [specified address range] |
| [address-range]/d | delete | Delete [specified address range] |
| s/pattern1/pattern2/ | substitute | Substitute pattern2 for first instance of pattern1 in a line, over address-range |
| [address-range]/s/pattern1/pattern2/ | substitute | Substitute pattern2 for first instance of pattern1 in a line, over address-range |
| [address-range]/y/pattern1/pattern2/ | transform | replace any character in pattern1 with the corresponding character in pattern2, over address-range (equivalent of tr) |
