`$$` matches blank lines.
Brackets -- [...] -- enclose a set of characters to match in a single RE.

"[xyz]" matches any one of the characters $x$, $y$, or $z$.

"[c-n]" matches any one of the characters in the range $c$ to $n$.

"[B-P]" matches any one of the characters in the ranges $B$ to $P$ and $k$ to $y$.

"[a-z0-9]" matches any lowercase letter or digit.

`[^b-d]` matches any character *except* those in the range $b$ to $d$. This is an instance of negating or inverting the meaning of the following RE (taking on a role similar to `!` in a different context).

Combined sequences of bracketed characters match common patterns. "[Yy][Ee][Ss]" matches *yes, Yes, YesEs*, and so. "[0-9][0-9][0-9]-[0-9][0-9]" matches any Social Security number.

The backslash `\` escapes a character which means that gets interpreted literally (and is therefore no special).
A `\$` reverts back to its literal meaning of `\$`, rather than RE meaning of end-of-line. Likewise a `\"` has the literal meaning of `\"`.

Escaped "angle brackets" -- `\<...>` -- mark word boundaries. The angle brackets must be escaped, otherwise they have only their literal character meaning.

`<the>` matches the word "the", but not the "them", "there", "other", etc.

```bash
bash cat textfile
This is line 1, of which there is only one instance.
This is the only instance of line 2.
This is line 3, another line.
This is line 4.
```

```bash
bash grep 'the' textfile
This is line 1, of which there is only one instance.
This is the only instance of line 2.
This is line 3, another line.
```

```bash
bash grep '\<the>' textfile
This is the only instance of line 2.
```

- **Extended RES.** Additional metacharacters added to the basic set. In grep, awk, and Perl.
The question mark -- `?` matches zero or one of the previous RE. It is generally used for matching single characters.
The plus -- `+` matches one or more of the previous RE. It serves a role similar to the `*`, but does not match zero occurrences.

> GNU versions of sed and awk can use "+", but it needs to be escaped.
```bash
echo all1b | sed -ne '/al*b/p'
echo all1b | grep 'al*b'
echo all1b | awk '/al*b/'
# All of above are equivalent.
```

- **Escaped "curly brackets" -- `\{...\}`** indicates the number of occurrences of a preceding RE to match.

It is necessary to escape the curly brackets because they have their literal meaning otherwise. This technique is technically not part of the basic RE set.

`[0-9]{5}` matches exactly five digits (characters in the range of 0 to 9).

- Curly brackets are not available in the "classic" (non-POSIX compliant) version of awk. The extended version of awk, gawk, has the `--re-interval` option that permits (without being escaped).

```bash
bash$ echo 2222 | gawk --re-interval '/2{3}/'
2222
```

- **Perl** and some grep version do not require escaping the curly brackets.

- Parentheses -- `()` enclose a group of REs. They are useful with the `|` operator and in substring extraction using expr.

- The -- `|` "or" RE operator matches any of a set of alternate characters.

```bash
bash$ egrep 're(a|e)d' misc.txt
People who read to be better informed than those who do not.
The clarinet sounds by the vibration of its reed.
```

- **POSIX Character Classes**: This is an alternate method of specifying a range of characters to match.
- `[:alnum:]` matches alphanumeric or numeric characters. This is equivalent to `[A-Za-z0-9]`.
- `[:alpha:]` matches alphabetic characters. This is equivalent to `[A-Za-z]`.
- `[:blank:]` matches space or tab.
- `[:cntrl:]` matches control characters.
- `[:digit:]` (decimal) is equivalent to `[0-9]`.
- `[:graph:]` (printable). Matches characters in the range of ASCII 33-126. This is the same as `[:print]`, excluding the space character.
- `[:lower:]` matches lowercase alphabetic characters. This is equivalent to `[a-z]`.
- `[:print:]` (printable). Matches characters in the range of ASCII 32-126. includes the space character.
- `[:space:]` matches whitespace (space and horizontal tab).
- `[:upper:]` matches uppercase alphabetic characters. This is equivalent to `[A-Z]`.
- `[:xdigit:]` matches hexadecimal digits. This is equivalent to `0-9-Fa-f`.

POSIX character classes generally require double brackets (`[[ ]]`).

```bash
bash$ grep [[:digit:]] test.file
abc=723
```

```bash
if [[ [:alpha:] ]]; then
    # Number followed by a letter
fi
# From example.sh
```

These characters may be used with globbing to a limited extent.

```bash
bash$ ls -l [[:digit:]]*
-rw-r-- 1 bozo 0 Aug 21:47 a33b
```

POSIX character classes are used in Example-16 and Example-22. Sed, awk, and Perl, used as filters, take RE as arguments when "sifting" or transforming I/O streams. Use Example-12 and Example-16 for illustrations of this. The standard reference on this complex topic is Friedl's Mastering Regular Expressions. Sed, by Dougherty and Robbins, gives a very lucid treatment of REs. See the Bibliography for more information on these books.

## 18.2. Globbing

Bash itself cannot recognize Regular Expressions. Inside scripts, it is commands and utilities such as sed and awk that interpret REs. Bash does filename expansion but does not use the standard RE set. Instead, globbing recognizes and expands wildcards. Globbing interprets the standard characters inside square brackets, and other special characters (such as `^` for negating the sense of a match). There are important limitations on globbing: `*` will not match filenames that start with a dot, for example, `.bashrc`. Likewise, `?` has a different meaning in globbing than that of an RE.

```bash
bash$ ls -l
total 2
--rw-rw-r-- 1 bozo bozo 0 Aug 18:42 a.1
--rw-rw-r-- 1 bozo bozo 0 Aug 18:42 b.1
--rw-rw-r-- 1 bozo bozo 0 Aug 18:42 c.1
--rw-rw-r-- 1 bozo bozo 466 Jun 17:48 t2.sh
--rw-rw-r-- 1 bozo bozo 758 Jul 30 09:02 test1.txt
```

```bash
bash$ ls -t?
--rw-rw-r-- 1 bozo bozo 466 Aug 6 17:48 t2.sh
```

```bash
bash$ ls [a]*
--rw-rw-r-- 1 bozo bozo 0 Aug 18:42 a.1
--rw-rw-r-- 1 bozo bozo 0 Aug 18:42 b.1
```

```bash
bash$ ls [a-c]
--rw-rw-r-- 1 bozo bozo 0 Aug 18:42 a.1
--rw-rw-r-- 1 bozo bozo 0 Aug 18:42 b.1
--rw-rw-r-- 1 bozo bozo 0 Aug 18:42 c.1
```

```bash
bash$ ls [^*]
--rw-rw-r-- 1 bozo bozo 0 Aug 18:42 c.1
--rw-rw-r-- 1 bozo bozo 466 Jun 17:48 t2.sh
--rw-rw-r-- 1 bozo bozo 758 Jul 30 09:02 test1.txt
```

```bash
bash$ ls (b*,c*,**)
--rw-rw-r-- 1 bozo bozo 0 Aug 18:42 b.1
--rw-rw-r-- 1 bozo bozo 0 Aug 18:42 c.1
--rw-rw-r-- 1 bozo bozo 758 Jul 30 09:02 test1.txt
```
