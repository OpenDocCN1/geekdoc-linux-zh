pipe. Passes the output (stdout) to the input (stdin) of the next one, or to the shell. This is a method of chaining commands together.

```
echo ls -l | sh
# Passes the output of "echo ls -1" to the shell,
# +with the same result as a simple "ls -1".
```

```
cat .lst1 | sort | uniq
# Merges and sorts all ".lst" files, then deletes duplicate lines.
```

A pipe, a classic method of interprocess communication, sends the stdout of one stdin of another. In a typical case, a command, such as cat or echo, pipes a stream of data to a filter, which transforms its input for processing. [22]

# cat $filename1 $filename2 | grep search_word

For an interest in the complexity of using UNIX pipes, see the UNIX FAQ, Part 3.
The output of a command or commands may be piped to a script.

```
#!/bin/bash
# uppercase.sh : Changes input to uppercase.
t 'a-z' 'A-Z'
# Letter ranges must be quoted
# + to prevent filename generation from single-letter filenames.
```

```
exit 0
Now, let us pipe the output of ls to it.
bash$ ls -l | ./uppercase.sh
-RW-R-- 1 BOZO BOZO 109 APR 7 19:49 1.TXT
-RW-R-- 1 BOZO BOZO 109 APR 14 16:48 2.TXT
-RW-R-- 1 BOZO BOZO 725 APR 20 20:56 DATA-FILE
```

> each in a pipe must be the stdin of the next. If this is not the case, the data stream will block, and the pipe will not behave as expected.

```
cat file2 | ls -l | sort
# The output from "cat file file2" disappears.
A pipe runs as a child process, and therefore cannot alter script variables.
```

```
variable="initial_value"
echo "new_value" | read variable
echo "$variable" # $variable = initial_variable
```

If one of the commands in the pipe fails, this prematurely terminates execution of pipe. Called a broken pipe, this condition sends a SIGPIPE signal.
