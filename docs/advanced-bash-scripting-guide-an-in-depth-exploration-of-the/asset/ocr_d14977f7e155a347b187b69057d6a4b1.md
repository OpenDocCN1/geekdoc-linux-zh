The at job control executes a set of commands at a specified time. Specifically, it will use cron. however, at is chiefly useful for one-time execution of a command set.

+   - at 2pm January 15 prompts for a set of commands to execute at that time. These commands should be script-compatible, for all practical purposes, the user is typing in an executable script line at a time. Input terminates with a C-D.

Using either the -f option or redirection <, reads a command list from a file. This file is an executable script, though it should, of course, be non-interactive. Particularly clever is including run-parts command in the file to execute a different set of scripts.

```
bash$ at 2:30 am Friday < at-jobs.list
job 2 2000-10-27 02:30
```

The batch job control is similar to at, but it runs a command list when the system drops below . 8. Like at, it can read commands from a file with the -f option.

> The batch processing dates back to the era of mainframe computers. It means running a set of commands without user intervention.
