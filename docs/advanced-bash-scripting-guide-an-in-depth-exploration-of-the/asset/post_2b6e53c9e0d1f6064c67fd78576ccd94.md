It is possible to control certain peripherals with commands sent to the /proc directory.

> root# echo on > /proc/acpi/ibm/light

This turns on the backlight in certain models of IBM/Lenovo Thinkpads. (May not work on all Linux distros.)

Of course, caution advised when writing to /proc.

The /proc directory contains subdirectories with numerical names. Every one of these subdirectories maps to the process ID of a currently running process. Within each of these subdirectories, there are a number of files that hold useful information about the corresponding process. The stat and status files keep running statistics on the process, the cmdline file holds the command-line arguments the process was invoked with, and the exe file a symbolic link to the complete path of the invoking process. from a scripting standpoint.

```bash
#!/bin/bash
# pid-identifier.sh
# Gives complete path name to process associated with pid.

ARGNO=1 # Number of arguments the script expects.
E_WRONGARGS=2
E_BADPID=3
E_NOSUCHPROCESS=4
E_NPERMISSION=5
PROCFILE=exe

if [ $1 -ne $ARGNO ];
then
    echo "Usage: $(basename $0) PID" >&2 # Error message to stderr.
    exit $E_WRONGARGS
fi

npid=$(ps ax | grep $1 | awk '{ print $1 }' | grep $1) # Checks for pid in "ps" listing, field $1.
# Then makes sure it is the actual process, not the process invoked by this script.
# The last "grep" filters out this possibility.

# npid=$(ps ax | awk '{ print $1 }') # also works, as Teemu Huovila points out.

if [ -z "$npid" ];
then
    # after filtering, the result is a zero-length string,
    echo "No such process."
    exit $E_NOSUCHPROCESS
fi

# Alternatively:
if ! ps $1 >/dev/null 2>&1;
then
    # running process corresponds to the given pid.
    echo "No such process."
    exit $E_BADPID
fi

# To simplify the entire process, use "pidof".

if [ !r /proc/$1/$PROCFILE ];
then
    # Check for read permission.
    echo "Can't read permission on /proc/$1/$PROCFILE" >&2 # Ordinary user can't access files in /proc.
    exit $E_NPERMISSION
fi

# The last tests may be replaced:
if kill -0 $1 >/dev/null 2>&1;
then
    # '0' is not a signal, it will test whether it is possible to send a signal to the process.
else
    echo "PID doesn't exist or you're not its owner" >&2
    exit $E_BADPID
fi

exe_file=$(ls -l /proc/$1 | grep "exe" | awk '{ print $1 }')
# Or exe_file=$(ls -l /proc/$1/exe | awk '{print $1}')

# /proc-pid/exe is a symbolic link to the complete path name of the invoking process.

if [ -e $exe_file ];
then
    # then the corresponding process exists.
    echo "Process invoked by $exe_file."
else
    echo "No such process."
fi

# This elaborate script could be replaced by
# ps ax | grep $1 | awk '{ print $5 }'
# However, this will not work because the fifth field of 'ps' is argv[0] of the process, not the executable file.

# However, either of the following would work:
#     find /proc/$1/exe -printf '%l\n'
#     ls -af $1 -d | sed -ne '\//p'

# Additional commentary by Steph Chazelas.

exit 0

# Chapter 29. dev and /proc

# Finding the process number for 'pppd', the 'ppp daemon'.
# Have to filter out the process lines generated by the search itself.
# However, as Oleg Philion points out, this could have been simplified by using "pidof".
pidno=$($PROCNAME)

# Moral of the story:
 When a command sequence gets too complex, look for a shortcut.

if [ -z "$pidno" ]; # If no pid, then process is not running.
then
    echo "Not connected."
    exit $E_NOSUCHPROCESS
else
    echo "Connected."; echo
fi

while [ true ]; # Endless loop, script can be improved here.
do
if [ ! -e /proc/$pidno/$PROCFILENAME ]
# While process is running, then "status" file exists.
then
    echo "Disconnected."
    # exit $E_NOSUCHPROCESS
fi

    netstat -s | grep "packets received" # Get some connect statistics.
    netstat -s | grep "packets delivered"

    sleep $INTERVAL
    echo:

done
exit 0

# As it stands, this script must be terminated with a Control-C
