# Chapter 35. Scripting With Style

Ender suggests using the /usr/include/syexits.h in shell scripts, these though are primarily intended for C and C++ programming.

- Use standardized flags for script invocation. Ender proposes the following set of flags.

  - -a All: Return all information (including hidden file info).
  - -b Brief: Short version, usually for other scripts.
  - -c Copy, concatenate, etc.
  - -d Daily: Use information from the whole day, and not merely information for a specific instance/user.
  - -e Extended/Elaborate: (often does not include hidden file info).
  - -h Help: Verbose usage w/decs, aux info, discussion, help.
  - -l Log output of script.
  - -m Manual: Launch man-page for base command.
  - -n Numbers: Numerical data only;
  - -r Recursive: All files in a directory (and/or all sub-dirs).
  - -s Setup & File Maintenance: Config files for this script.
  - -u Usage: List of invocation flags for the script.
  - -v Verbose: Human readable output, more or less formatted.
  - -V Version / License / Copy(right|left) / Contribs (email to).

See Section G.1.

- Break complex scripts into simpler modules. Use functions where appropriate. See Example 37-4.

## 36.1. Interactive and non-interactive shells and scripts

An interactive shell reads commands from user input on tty. Among other things, a shell starts files on automation, displays a prompt, and enables job control by default. The user can interact with the shell.

A shell running a script is always a non-interactive shell. All the same, the script can still access its tty. It is even possible to emulate an interactive shell in a script.

```bash
#!/bin/bash
MY_PROMPT=$' ' 
while :
do
  echo -n "$MY_PROMPT"
  read line
  eval "$line"
done
exit 0
```

# This example, and much of the above explanation supplied by Stéphane Cherez: let us consider an interactive shell to be one that requires input from the user, usually with read statements. "Real life" is actually a bit messy than that. For now, assume an interactive script is bound to a tty. Init and startup scripts are necessarily non-interactive, since they must run without human. Many administrative and maintenance scripts are likewise non-interactive. Non-interactive scripts can run in the background, but interactive one hangs, waiting for input that comes. Handle difficulty by having expect script or embedded here. These workarounds make general purpose scripts that run in either interactive or non-interactive modes. If a script needs to test whether it is running in an interactive shell, it is simply a matter of finding whether variable is set. If the user is being prompted for input:

```bash
if [ -z $PS1 ] # no prompt?
then
  # non-interactive
else
  # interactive
fi
```

- Scripts may be forced to run in interactive mode with the -i option or with #!/bin/bash -i header. Be aware this can cause erratic behavior or show error messages even when error is present.

## 36.2. Shell Wrappers

A wrapper is a script that embeds a system command or utility, that passes a set of parameters to that command. Wrapping around a complex command simplifies invoking it. This is especially useful with sed and awk. A sed or awk script would normally be invoked from the command-line by sed -e 'commands' or awk 'commands'. Embedding such a script in a Bash script permits it to be simple, and makes it reusable. This enables combining the functionality of sed and awk, for example piping the output of sed to awk. As a saved executable file, you can then repeatedly it in its original form or modified, without the inconvenience of retyping it on the command-line.

```bash
#!/bin/bash

# This simple script removes blank lines from a file.
# No argument checking.
#
# You might wish to add something like:
#
# E_NOARGS=5
# if [ -z "$1" ]
# then
# echo 'Usage: $0 target-file'
# exit $E_NOARGS
# fi
```

```bash

# Same as
# sed -e /^\$/d filename
# invoked from the command-line.

# '^' indicates the beginning of line, '$' is the end.
# This matches lines with nothing between the beginning and the end --
# blank lines.
# The 'd' is the delete command.
```
