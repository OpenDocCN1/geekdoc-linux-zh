
# Advanced Bash-Scripting Guide

As it happens, many of the various shells and scripting languages are converging towards the POSIX 1003.1 standard. Invoking Bash with the --posix option or inserting a set -o posix at the head of a script causes Bash to conform very closely to this standard. An alternative is to use a #!/bin/sh sha-bang header in the script, rather than #!/bin/bash. Note that /bin/sh is a link to /bin/bash in Linux and other flavors of UNIX, and script this way disables Bash functionality.

Most Bash scripts will run as-is under ksh, and vice-versa, since Chet Rahe has been busy porto ksh to the latest versions of Bash.

On a commercial UNIX machine, scripts using GNU-specific features of standard commands may not work. This has less of a problem in the last few years, the GNU utilities have pretty much displaced their proprietary counterparts over "big-iron" UNIX. Caldera's release of the source to many of the original UNIX utilities has accelerated the trend.

Bash has features that the Bourne Shell lacks. Among these are:

- Certain invocation options
- Command substitution using $() notation
- Brace expansion
- Certain array operations, and associative arrays
- The double brackets extended test construct
- The double-parentheses arithmetic-evaluation construct
- Certain manipulation operations
- Process substitution
- A Regular Expression matching operations
- Bash-specific builtins
- Coprocesses

See the Bash F.A.Q. for a complete listing.

# 36.10. Shell Scripting Under Windows

Even users using other OS can UNIX-like scripts, and therefore benefit from many of the lessons of this book. The Cygwin package for Cygnus and the MKS utilities from Mortice Kern Associates add scripting capabilities to Windows.

Another alternative is UWIN, written by David Korn of AT&T, of Korn Shell fame.

In 2006, Microsoft released the Windows PowerShell@, which contains limited Bash-command-line scripting capabilities.

# 37.1. Bash, version 2

The current version of *Bash*, the one you have running on your machine, is most likely version 2.xx.yy, 3.xx.yy, or 4.xx.yy.

```bash
bash$ echo $BASH_VERSION
3.25(1)-release
```

The version 2 update of the classic Bash language added array variables, string and parameter expansion, and a better method of indirect variable references, among other features.

Example 37-1. String expansion

```bash
#!/bin/bash

# String expansion.
# Introduced with version 2 of Bash.

# Strings of the form '$xxx'
# have the standard escaped characters.
echo '$ringing 3 times'
# May ring once with certain terminals.
# Or May not ring at all, depending on terminal settings.
echo '$Three feeds'
echo '$10 newlines\n\n\n\n'
echo '$012'
# Octal equivalent characters.
```

Example 37-2. Indirect variable references - the new way

```bash
#!/bin/bash

# Indirect referencing.
# This has a few attributes of references in C++.

# Direct reference.

# Indirect reference.
# The ${!variable} notation is more intuitive than the old eval $$var.
```
