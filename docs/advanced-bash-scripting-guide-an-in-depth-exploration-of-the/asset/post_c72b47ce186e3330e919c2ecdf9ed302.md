# Comparison

**diff, patch**: flexible file comparison utility. It compares the target files line-by-line sequentially. In applications, as comparing word dictionaries, which may be helpful to filter the files through sort and uniq piping them to diff. **diff file-1 file-2**- outputs the lines in the files that differ, with carets showing which file each particular line belongs to.

--**side-by-side** option to **diff** outputs each compared file, by line, in separate columns, with non-matching lines marked. The -c and -u options likewise make the output of the command easier to interpret..

There are available fancy frontends for diff, such as sdiff, wdiff, xdiff, and mgdiff.

> diff command returns an exit code of 0 if the compared files are identical, and if they differ (or 2 binary files are being compared). This permit uses of diff in a test construct within a shell script (see below).
A common use for diff is generating files to be used with patch The -e option outputs suitable for ed or ex scripts.

patch: file versioning utility. Given a difference file generated by diff, patch can upgrade a previous version of a package to a newer version. It is much more convenient to distribute a relatively small "diff" file than the entire body of a newly revised package. Kernel "patches" have become the preferred method of distributing the frequent releases of the Linux kernel.

```
patch -pl <patch-file>
```

Use **diff** to compare gzipped files.

An extended version of **diff** that compares three files at a time. This command returns an exit value of 0 upon successful execution, but unfortunately this gives no information about the results of the comparison.
diff3. merge

```bash
bash$ diff3 file-1 file-2 file-3
===
1:ic
This is line 1 of "file-1"
2:ic
This is line 1 of "file-2"
3:ic
This is line 1 of "file-3"
```

The **merge** (3-way file) command is an interesting adjunct to **diff3**. Its syntax is **mergefile file1 file2**. The result is to mergefile the changes that lead from file2. This command creates a stripped-down version of **patch**.
sdiff

Compare/and edit two files in order to merge them into an output file. Because of its interactive nature, this would find little use in a script.
cmp

The **cmp** is a simpler version of **diff**, whereas **diff** reports the differences between two files, **cmp** merely shows where they differ.

Like **diff**, **cmp** returns an exit status of 0 if the compared files are identical, and 1 if they differ. This permits use in a test construct within a shell script.

```
#!/bin/bash
# file-comparison.sh

ARGS=2 # Two args to script expected.
E_BADARGS=5
E_UNREADABLE=86

if [ $# -ne "$ARGS" ];
then
    echo "Usage: `$(basename $0)\` file1 file2"
    exit $E_BADARGS
fi

if [ [ -r "$1" ] && [ -r "$2" ] ];
then
    echo "Both files to be compared must and be readable."
    exit $E_UNREADABLE
fi

comp $1 $2 /dev/null
# Redirection to /dev/null buries the output of the "comp" command.
# comp -s $1 $2 same result "-s" silent flag to "comp"
# Thank you Anders Gustavson for pointing this out.

# Also works with "diff", i.e.
# diff $1 $2 > /dev/null

if [ $# -eq 0 ]; # Test exit status of "comp"
then
    echo "File \$1\" is identical to file \$2\"
else
    echo "File \$1\" differs from file \\$2\"
fi

exit 0
```

# Utilities

# basename

Strips the path information from a file name, printing only the file name. The construction `basename $0` lets the script know its name, that is, the name it was invoked by. This can be used for "usage" messages if, for example, a script is called with missing arguments:

```
echo `Usage: `basename $0` arg arg2 ... argn`
```

# dirname

Strips the basename from a filename, printing only the path information. The argument does not need to refer to an existing file, or be a filename for that matters (see Example A-7).

+   **basename** and **dirname** can operate on any arbitrary string. The argument does not need to refer to an existing file, or be a filename for that matters (see Example A-7).

# Encoding and Encryption

sum, cksum, md5sum, sha1sum

These utilities are for generating checksums. A cksum is a number mathematically calculated from the contents of a file, for the purpose of checking its integrity. A script might refer to a list of checksums for security purposes, ensuring that the contents of key files have not been altered. For security applications, the newer md5sum (message digest 5 checksum) command, or the newer sha1sum (Secure Hash Algorithm).

```
bash cksum /boot/vmlinuz
1670054224 804083

bash echo -n "Top Secret" | cksum
339100327 10

bash md5sum /boot/vmlinuz
0f43eceea8f09e0b2b5cfdc333ba /boot/vmlinuz
bash echo -a6f "Top Secret" | md5sum
8abc97a6f62a469716f4df8d61728f
```

> The cksum command shows the size, in bytes, of its target, whether file or stdout.

The md5sum and sha1sum commands display a dash when they receive their input from stdout.

# Example 16-38. Checking file integrity

```
#!/bin/bash
# file-integrity.sh: Checking whether files in a given directory
#   have been tampered with.

E_DIR_NOMATCH=80

# Filename for storing records (database file).

  echo "$directory" > "$dbfile"
  # Write directory name to first line of file.
  md5sum "$directory/*" >> "$dbfile"
  # Append md5 checksums and filenames.
}
```
