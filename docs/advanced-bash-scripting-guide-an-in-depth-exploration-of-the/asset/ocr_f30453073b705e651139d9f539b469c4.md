# Advanced Bash-Scripting Guide

The cron daemon runs-parts to run the scripts in the /etc/cron. * directories.

In its default behavior the yes command feeds a continuous string of the character y followed by a line feed to stdout. A control-C terminates it. A different output string may be specified, in yes different string, which would continually output different string to stdout.

One might well ask the purpose of this. From the command-line or in a script, the output of yes can be redirected or piped into a program expecting user input. In effect, this becomes a sort of poor man's version of expect.

yes | fsck /dev/hd1 fsck non-interactively (careful!).

yes | rm -r dirname has same effect as rm -rf dirname (careful!).

> Caution when piping yes to a potentially dangerous system command, such as fsck disk. It might have unintended consequences.

+   The yes command parses variables, or more accurately, it echoes parsed variables. For example:

```
bash$ yes $BASH_VERSION
3.1.17(1)-release
3.1.17(1)-release
3.1.17(1)-release
3.1.17(1)-release
3.1.17(1)-release

```

This particular "feature" may be used to create a large ASCII file on the fly:

```
bash$ $PATH > huge_file.txt
Ctl-C
```

Hit Ctl-C quickly, or you might get more than you were bargained for...
The yes command can be emulated in a very simple script function.

```
yes (
  # Trivial emulation of "yes" ...
  local DEFAULT_TEXT="y"
  while [ true ] # Endless loop.
  do
    if [ -z "$1" ];
      then
        echo "$DEFAULT_TEXT"
      else
        echo # If argument ...
        echo "$1" # expand and echo it.
    fi
  done # The only things missing are the
  +# --help and --version options.
)
```

Prints arguments as a large vertical block to stdout, using an ASCII character (''). This may be redirected to a printer for hardcopy.
