_protect_literal_str() {
# Pick an unused, non-printing character as local IFS.
# Not required, but that shows that we are ignoring it.
  local IFS=$'x1B' # ESC character
# Enclose the All-Elements-Of in hard quotes during assignment.
  local tmp=$'x27$\\\\'x27'
  local tmp=$'x27$\\\\''' # Even uglier.
  local len=$($tmp) # Info only.
  echo $tmp is len. # Output and information.
}

Our Element 1 has its leading and trailing quotes stripped.
Although not shown, leading and trailing whitespace is also stripped.
Now that the strings are set, Bash will also, internally,
hard the quotes as required during its operations.

Why?
Considering our "${pls 'Hello($Me)'" construction:
"*" -> Expansion result, strip the quotes.
$(...) -> Replace with the result of..., strip this.
_pls '...' -> called with literal arguments, strip quotes.
The result includes hard quotes; the above processing has done, so they become part of the value.
Similarly, during using the string variable,
is part of the contents (result) and survives any operations (Until explicitly to evaluate the string).

Hint: See what happens when hard quotes ('') are replaced
with soft quotes in the above. Interesting also to remove any quoting.
