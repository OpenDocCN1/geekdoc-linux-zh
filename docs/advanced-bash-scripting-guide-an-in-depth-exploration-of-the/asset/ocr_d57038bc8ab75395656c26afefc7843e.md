# Chapter 5. Quoting

Quoting means that, bracketing a string in quotes. This has the effect of protecting special characters in the string from reinterpretation or expansion by the shell or shell script. (A character is "special" if it has an interpretation other than its literal meaning. For example, the asterisk * represents a wild character in globbing and Regular Expressions).

| Bash$ ls -l [V]* | |
|---|---|---|---|---||
| -rw-rw-r-- | 1 bozo bozo | 324 Apr 2 15:05 VIEWDATA.BAT |
| -rw-rw-r-- | 1 bozo | 507 May 4 14:25 vartrace.sh |
| -rw-rw-r-- | 1 bozo | 539 Aug 14 17:11 viewdata.sh |

```
bash$ ls -l [V]*nls: [V:]: No such file or directory
```

In everyday speech, when we "quote" a phrase, we set it apart and give it special meaning. In a Bash script, when we quote a string, we set it apart and give it literal meaning.

Certain programs and utilities reinterpret or expand special characters in a quoted string. An important use of quoting is preventing command-line parameter from the shell, still calling the program expand.

```
bash$ grep '[first] *.txt
file1.txt:This is the first line of file1.txt.
file2.txt:This is the First line of file2.txt.
```

Note that the unquoted grep [first] *.txt works under the Bash shell. [29]

Quoting can also echo "appetite" for newlines.

```
bash$ echo "$(ls -l)"
total 8
-rw-rw-r-- 1 bo 13 Aug 21 12:57 t.sh
-rw-rw-r-- 1 bo 78 Aug 21 12:57 u.sh
```

# 5.1. Choosing Variables

When referencing a variable, it is generally advisable to enclose it in double quotes. This prevents reinterpretation of all special characters within the quoted string -- except $(backquote), and \escape. [30] Keeping $ as a special character within double quotes permits referencing a quoted variable ("$variable") that is, replacing the variable with its value (Example 4-1, above).

Use double quotes to prevent word splitting. [31] An argument enclosed in double quotes presents itself as a single word, even if it contains whitespace separators.

```
List="one two three"
```
