```bash
check_database ()
{
  local n=0
  local filename
  local checksum

  # This file check should be unnecessary
  # but better safer than sorry.

  if [ ! -r "$dbfile" ];
  then
    echo "Unable to read checksum database file!"
    exit $E_BAD_DBFILE
  fi

  while read record[n]
  do
    directory_checked="${record[0]}"
    if [ "$directory_checked" != "$directory" ];
    then
      echo "Directories do not match up!"
      # Tried to use file for a different directory.
      exit $E_DIR_MATCH
    fi

    if [ "$n" -gt 0 ]; # Not directory name.
    then
      filename[n]=$(echo "${record[n]}" | awk '{ print $2}')
      # mdsum writes records backwards,
      # checksum checksum first, then.
      checksum[n]=$(mdsum "${filename[n]}")
    fi

    if [ "${record[n]}" = "${checksum[n]}" ];
    then
      echo "${filename[n]} unchanged."
    elif [ "$(basename ${filename[n]})" != "$dbfile" ]; then
      # Skip over checksum database file,
      # as it will change with each invocation of script.
      # This unfortunately means that when running
      # this script on $PWD, tampering with the
      # checksum database file will not be detected.
      # Exercise: Fix this.
      then
        echo "${filename[n]} : CHECKSUM ERROR!"
        # File has been changed since last checked.
      fi
    fi
  let "n+1" # Read from checksum database file.
done "$dbfile";
```

Example 16-39. Udecoding encoded files

```bash
#!/bin/bash
# Udecodes all uencoded files in current working directory.

lines=35
  # Allow 35 lines for the header (very generous).

for File in *
  # Test all the files in $PWD
    search1=$(tail -n "$File" | grep begin | wc -w)
    search2=$(tail -n "$File" | grep end | wc -w)
    # Udecoded files have a "begin" near the beginning,
    # and an "end" near the end.
    if [ "$search1" -gt 0 ];
    then
      if [ "$search2" -gt 0 ];
      then
        echo "udecoding $File-"
        uldecode $File
      fi
    fi
done

# Note that running this script itself fools it
# thinking it is a uencoded file,
# because it contains both "begin" and "end".
```

**mimencode, mmencode**
The mimencode and mmencode commands process multi-encoded e-mail attachments. This is especially useful because although mail user agents (such as pine) normally handle this, these particular utilities permit manipulating such attachments manually from the command-line or in batch processing mode.

**crypt**
At one time, this was the standard UNIX encryption. Politically-motivated government prohibiting the export of software resulted in the disappearance of crypt from the world, and it is still missing from many distributions. Fortunately, programmers have come with a number of decent alternatives to it, among them the author’s favorite (see Example A-4), **openssl**, which is an Open Source implementation.

To encrypt a file:
```bash
openssl aes -in file.txt -out file.encrypted
```
To decrypt a file:
```bash
openssl aes -d -in file.encrypted -out file.txt
```

Piping output to tar makes it possible to encrypt an entire directory.
To encrypt a directory:
```bash
sourcedir="home/user/test"
tar -czvf "$sourcedir" -out "$sourcedir.tar.gz"
```
To decrypt the resulting tar:
```bash
openssl aes -d -in "$sourcedir.tar.gz" | tar -xv
```

Of course, shred may have other uses, such as obtaining signed certificates for Web sites. Securely erase a file by overwriting it with random bits before deleting it. This is one of GNU utilities. Forensic technology may still be able to recover the contents of a file even after application of shred.

# Miscellaneous

mktemp
Create a temporary file with a unique" filename. When invoked from the command-line without additional arguments, it creates a zero-length file in the /tmp directory.
```bash
filename=$(mktemp)
```
If no filename supplied, it is unnecessary, but it's good programming practice nevertheless.
