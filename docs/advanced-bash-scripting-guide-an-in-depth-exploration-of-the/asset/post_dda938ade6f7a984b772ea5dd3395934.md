objdump
Displays information about an object file or binary executable in either hexadecimal form or as a disassembled listing (with the -d option).

```bash
bash objdump -d /bin/ls
/bin/ls:    file format elf32-1386

Disassembly of section .init:

080490bc.<init>:
080490bc:    55      push %ebp
080490bd:      e9 e5    mov %esp,%ebp
```

mookie
This command generates a "magic cookie", a 128-bit (32-character) pseudorandom hexadecimal number, normally used as an authorization "signature" by the X server. This is also available for use in a script as a "quick dirty" random number.

```bash
random000=$(mookie)
Of course, a script could use md5sum for the same purpose.

# Generate md5 checksum on the script itself.
random001=$(md5sum $ | awk '{print $1}')
# Uses 'awk' to strip off the filename.
The mookie command gives another way to generate a "unique" filename.
```

# Example 16-62. Filename generator

```bash
#!/bin/bash
# tempfile-name.sh:   temp filename generator
BASE_STR=`mookie`      # 32-character magic cookie.
# Arbitrary position in magic cookie string.
POS=1                 # Get LEN characters.
LEN=5
prefix=temp           # This is, after all, a "temp" file.
# For more "uniqueness", generate the
#++ prefix using the same method
# as the suffix, below.
suffix=${BASE_STR:$POS:$LEN}  # Extract a 5-character string,
#++ starting at position 11.
tempfile-name=$prefix.$suffix  # Construct the filename.
echo "Temp filename = "$tempfile_name"

# sh tempfile-name.sh
# Temp filename = temp.el9ea

# Compare this method of generating "unique" filenames
#++ with the 'date' method in ex51.sh.

exit 0
```

units
This utility converts between different units of measure. While normally invoked in interactive mode, units may be found in a script.

# Example 16-63. Converting meters to miles

```bash
#!/bin/bash
# unit-conversion.sh utility installed.
# Must have 'units' units

convert_units () # Takes as arguments the units to convert.
{
  cf=$$(units "$1" "$2" | sed --silent -e 'lp' | awk 'print $2')
  # Strip everything except the actual conversion factor.
  echo "$cf"
}
Unit1=miles
Unit2=meters
factor=convert_units $Unit1 $Unit2
quantity=3.73

result=$(echo $quantity | bc)
echo "There are $result $Unit2 in $quantity $Unit1."

# What happens if you pass incompatible units,
#+ such as "acres" and "miles" to the function?

echo 0
```

m4
A hidden measure, m4 is a powerful macro processing filter, virtually a complete language. Although originally written as a pre-processor for RatFor, m4 turned out to be a stand-alone utility. In fact, m4 combines the functionality of eval, tr, and awk, in addition to its extensive macro expansion facilities.

The April, 2002 issue of Linux Journal has a very nice article on m4 and its uses.

# Example 16-64. Using m4

```bash
#!/bin/bash
# m4.sh: Using the m4 macro processor

# Strings
string=abcdA01
echo len($string) | m4              # 7
echo substr($string, 4) | m4      # A01
echo regexp($string, [0-1],\|&Z) | m4  # 01Z

# Arithmetic
var=99
echo incr($var) | m4                  # 100
```

doexec
The doexec command enables passing an arbitrary list of arguments to a binary executable. In particular, passing argv[0] (which corresponds to $0 in a script) lets it be invoked by various names, and it can then carry different sets of actions, according to the name by which it was called. This is somewhat roundabout of passing options to an executable.

For example, the /usr/local/bin directory may contain a binary called "aaa". Invoking doexec /usr/local/aaa list would list all those files in the current working directory with an "aaa", while (the same executable) doexec /usr/local/bin/aaa delete would delete those files.

- The behaviors of the executable can be defined within the code of the executable itself, analogous to something like the following in a shell script:

```bash
case basename $0 in
  *name1* ) do_something;
  *name2* ) do_something_else;
  *name3* ) do_yet_another_thing;
  ) bail_out;
esac
```

dialog
The dialog family provides a method of calling interactive "dialog" boxes from a script. The more elaborate variations of dialog -- ddialog, Xdialog, and kdialog -- actually invoke X-Windows widgets.

sox
The sox, or "sound exchange" command plays and performs transformations on sound files. In fact, /usr/bin/play executable (now deprecated) is nothing but a shell wrapper for sox.

For example, soundfile.wav soundfile.au changes a WAV sound file into a (Sun audio format) AU sound file.

Shell scripts are ideally suited for batch-processing sox operations on sound files. For examples, the Linux Radio Timeshift HOWTO and the MP3do Project.

# Chapter 17. System and Administrative Commands

The startup and shutdown scripts in /etc/rc.d illustrate the uses (and usefulness) of many of these commands. These are usually invoked by root and used for system maintenance or emergency filesystem repairs. Use with caution, as some of these commands may damage your system if misused.

# Users and Groups

users
Show all logged on users. This is the approximate equivalent of who -q.

groups
Lists the current user and the groups she belongs to. This corresponds to the $GROUPS internal variable, but give group names, rather than the number.

```bash
bash$ groups
bozita cdrom writer audio xgrp

bash$ echo $GROUPS
501
```

# chown, chgrp

chown command changes the ownership of a file or files. This command is a useful method that root can shift file ownership from one user to another. An ordinary user may not change the ownership of files, not even her own.

```bash
root# chown bozo *.txt
```

chgrp command changes the group ownership of a file or files. You must be owner of the file(s) as well as a member of.

```bash
bash$ groups
bozita cdrom writer audio xgrp

bash$ echo $GROUPS
501
```

The lid (list ID) command shows the group(s) that given user belongs to, or alternately, the users belonging to a group. It may be invoked only by root.

```bash
root# lid bozo
bozo(gid=500)

root# lid daemon
bin(gid=1)
demon(gid=2)
adm(gid=4)
lp(gid=7)
```
