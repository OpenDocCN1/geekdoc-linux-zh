# Advanced Bash-Scripting Guide

As it happens, many of the various shells and scripting languages are converging towards the POSIX 1003.1 standard. Invoking Bash with the --posix option or inserting a set -o posix at the head of a script causes Bash to conform very closely to this standard. An alternative is to use a #!bin/sh sha-bang header in the script, rather than #!bin/bash. Note that /bin/sh is a link to /bin/bash in Linux and other flavors of UNIX, and script this way disables Bash functionality.

Most Bash scripts will run as-is under ksh, and vice-versa, since Chet Rahe has been busily porto ksh to the latest versions of Bash.

On a commercial UNIX machine, scripts using GNU-specific features of standard commands may not work. This has less of a problem in the last few years, the GNU utilities have pretty much displaced their proprietary counterparts over "big-iron" UNIX. Caldera's release of the source to many of the original UNIX utilities has accelerated the trend.

Bash has features that the Bourne Shell lacks. Among these are:

+   * Certain invocation options
* Command substitution using $() notation
* Brace expansion
* Certain array operations, and associative arrays
* The double brackets extended test construct
* The double-parentheses arithmetic-evaluation construct
* Certain manipulation operations
* Process substitution
* A Regular Expression matching operations
* Bash-specific builtins
* Coprocesses

See the Bash F.A.Q. for a complete listing.

Example 36-23. Test Suite

```
#!/bin/bash
# test-suite.sh
# A partial Bash compatibility test suite.
# Run this on your version of Bash, or some other shell.

default_option=FAIL      # Tests will fail unless . 

echo
  echo -n "Testing " 
  sleep 1; echo -n ". " 
  sleep 1; echo -n ". " 
  sleep 1; echo " "
```
