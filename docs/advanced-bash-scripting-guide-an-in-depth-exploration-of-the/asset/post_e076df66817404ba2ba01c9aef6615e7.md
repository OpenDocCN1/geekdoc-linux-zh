## Appendix C. A Sed and Awk Micro-Primer

This is a very brief introduction to the **sed** and **awk** text processing utilities. We will deal with only a few commands here, but that will suffice for understanding simple sed and awk constructs within shell scripts.

**sed**: a non-interactive text file editor

**awk**: a field-oriented pattern processing language with a C-style syntax

For all differences, the two utilities share a similar invocation syntax, regular expressions, read input by default by `stdin`, and output to `stdout`. These are well-behaved UNIX tools, and they work together well. The output from one can be piped to the other, and their combined capabilities give sed some the power of Perl.

- One difference between the utilities is that while shell scripts can easily pass arguments to sed, it is more cumbersome for awk (see Example 36-5 and Example 28-2).

## C.1. Sed

Sed is a non-interactive stream editor. It reads text input, from `stdin` or from file, performs certain operations on specified lines of the input, one line at a time, and then outputs the results to `stdout` or to file. Within a shell script, `sed` is usually one of several tools in a pipe.

Sed determines which lines of its input that it will operate on by the address range passed to it. Specifically this address range either by line number or by a pattern to match. For example, `3d` sed to delete line 3 of the input, and `/Windows/d` tells sed you want every line of the input containing a match to "Windows" deleted.

Of all the operations in the `sed` toolkit, we will focus primarily on the three most commonly used ones. are printing (to `stdout`), deletion, and substitution.

| Operator | Name | Effect |
|---|---|---|
| [address-range]/p | print | Print [specified address range] |
| [address-range]/d | delete | Delete [specified address range] |
| s/pattern1/pattern2/ | substitute | Substitute pattern2 for first instance of pattern1 in a line, over address-range |
| [address-range]/s/pattern1/pattern2/ | substitute | Substitute pattern2 for first instance of pattern1 in a line, over address-range |
| [address-range]/y/pattern1/pattern2/ | transform | replace any character in pattern1 with the corresponding character in pattern2, over address-range (equivalent of tr) |
| [address] i command Filename | insert | Insert pattern at address indicated in Filename. Usually used with -i in-place option. |
| g | global | Operate on every pattern match within each line of input |

Unless the q (global) operator is appended to a substitute command, the substitution operates only on the first instance of a pattern match within each line.
From the command-line and in a shell, a sed operation may require quoting and certain options.

```
sed -e '/$/' $filename
# The -e option causes the next string to be interpreted as an editing instruction.
# (If passing only a single instruction to sed, the "-e" is optional.)
# The "strong" quotes ('\'') protect the RE characters in the instruction
# from reinterpretation as special characters by the body of the script.
# (This reserves RE expansion of the instruction for sed.)
```

Operates on the text contained in file $filename.
In certain cases, a sed editing command will print only with single works.

```
filename=file1.txt
pattern=BEGIN
```

```
sed "/pattern/d" "$filename" # Works as specified.
# sed "/pattern/d" "$filename" has unexpected results.
# In this instance, with strong quotes ('...'),
# *pattern will not expand to "BEGIN",
```

Sed uses the -e option to specify that the following string is an instruction or set of instructions. There is only a single instruction contained in the string, this may be omitted.

```
sed -n '/x/p' $filename
# The -n option tells sed to print only those lines matching the pattern.
# Otherwise all input lines would print.
# The -e option not here there is only a single instruction.
```

## C.2. Awk

Awk is a full-featured processing language with a syntax reminiscent of C. While it possesses an extensive set of operators and capabilities, we will cover only a few of these here - the ones most useful in shell scripts.

Awk breaks each line of input passed to it into fields. By default, a field is a string of consecutive characters delimited by whitespace, there are options for changing this. awk parses and operates on each separate field. This makes it ideal for handling structured text -- especially tables -- data organized into consistent chunks, such as rows and columns.

Strong quoting and curly brackets enclose blocks of awk code within a shell script.

```
$1 is field #1, $2 is field #2, etc.
echo one two | awk 'print $1'
# one
echo one two | awk 'print $2'
# two

# But what is field #0?
echo one two | awk 'print $0'
# one two
# All the fields!

awk 'print $3' $filename
# Prints field #3 of file filename to stdout.

awk 'print $1 $5 $6' $filename
# Prints fields #1, #5, and #6 of file $filename.

awk 'print $0' $filename
# Prints the entire file!
# Same effect as: cat $filename ... or . sed '$filename
```

We have just used the awk command in action. The only other feature of awk we need to deal with is variables. Awk handles variables similarly to shell scripts, though a bit more flexibly.
