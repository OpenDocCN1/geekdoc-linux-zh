$PIPESTATUS Array variable holding exit status(es) of last executed foreground pipe.

```bash
bash$ echo $PIPESTATUS
0

bash$ ls -al | bogus_command
bash: bogus_command: command not found
bash$ echo ${PIPESTATUS[1]}
127

bash$ ls -al | bogus_command
bash: bogus_command: command not found
bash$ echo $?
127
```

The members of the $PIPESTATUS array hold the exit status of each command executed in a pipe. $PIPESTATUS[0] holds the exit status of the first command in the pipe, $PIPESTATUS[1] holds the exit status of the second command, and so on.

> $PIPESTATUS variable may contain an erroneous 0 value in a login shell (in releases prior to 3.0 of Bash).

```
tcsh$ bash
bash$ who | grep nobody | sort
bash$ echo ${PIPESTATUS[*]}
0
```

The lines above contained in a script would produce the expected 0 1 0 output.

Thank you, Wayne Pollock for pointing this out and supplying the above example.

> $PIPESTATUS variable gives unexpected results in some contexts.

```bash
bash$ echo $BASH_VERSION
3.00.14(1)-release

bash$ ls | bogus_command | wc
bash: bogus_command: command not found
0 0 0

bash$ echo ${PIPESTATUS[@]}
141 127 0
```

Chet Ramsey attributes the above output to the behavior of ls. If ls writes to a pipe whose output is not read, then SIGPIPE kills it, and exit status is 141. Otherwise its exit status is 0, as expected. This is likewise the case for tr.

> $PIPESTATUS is a "volatile" variable. It needs to be captured immediately after the pipe in question, before any other intervenes.

- $PIPESTATUS[0] holds the exit status of the first command in the pipe.
- $PIPESTATUS[1] holds the exit status of the second command.
- $PS1 is the main prompt, displayed at the command-line.
- $PS2 is the secondary prompt, seen when additional input is expected.
- $PS3 is the tertiary prompt, displayed in a select loop (see Example 1).
- $PS4 is the quaternary prompt, shown at the beginning of each line of output when invoking a script with -x trace. It displays as "*".

$PPID of a process is the process ID of its parent.

It may be useful to embed diagnostic information in $PS4: $PS4=$(read time < /proc/stat; echo "$time")

The value is not supplied to read. Also applicable to select menus, but only supplies the item number of the variable chosen, not the value itself.

```bash
#!/bin/bash
# reply.sh

# REPLY is the default value for a 'read' command.

echo -n "What is your favorite vegetable? "
read
echo "Your favorite vegetable is $REPLY."
# REPLY holds the value of the last "read" if and only if no variable supplied.

echo -n "What is your favorite fruit? "
read fruit
echo "Your favorite fruit is $fruit."
echo ""
echo "Value of REPLY is still $REPLY."
# REPLY is still set to its previous value because the variable $fruit absorbed the new "read" value.

exit 0
```

```bash
TIME_LIMIT=10
INTERVAL=1

echo "Hit Control-C to exit before $TIME_LIMIT seconds."

while [ "$SECONDS" -le "$TIME_LIMIT" ]; do
  # $SECONDS is an internal shell variable.
  if [ "$SECONDS" -eq 1 ]; then
    units=second
  else
    units=seconds
  fi

  echo "This script has been running $SECONDS $units."
  # On a slow or overloaded machine, the script may skip a count every in a while.
  sleep $INTERVAL
done
echo -e "\a" # Beep!

exit 0
```

$SSHLLV Shell level, how deeply Bash is nested. If, at the command-line, $SSHLLV is 1, in a script it will increment to 2.

> This variable is not affected by subshells. Use $BASH_SUBSHELL when you need an indication of shell nesting.

$TMOUT The TMOUT environmental variable is set to a non-zero value time, then the shell prompt will time out after $shell seconds. This will cause a logout.

As of 2.05b of Bash, it is now possible to use $TMOUT in a script in combination with read.

```bash
# Works in scripts for Bash, 2.05b and later.
TMOUT=3    # Prompt times out at three seconds.
echo "What is your favorite song?"
echo "Quickly now, you have only $TMOUT seconds."
```
