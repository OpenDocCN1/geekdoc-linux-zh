The" serves as a field separator, in /etc/passwd, in $PATH variable.

A colon is acceptable as a function name.

```
: {
echo "The name of this function is \$FUNCTIONNAME\"
# Why we use a colon as a function name?
# It's a way of obfuscating your code.
}
```

The name of this function is :
This is not portable behavior, and therefore not a recommended practice. In fact, most recent versions
Bash does not permit this usage. An underscore _ works, though.

A colon can be a placeholder in an otherwise empty function.

```
not_empty ()
{
# Contains a : (null command), and so is not empty.
```

reverse (or negate) the status of a test or exit status [bash]. The operator inverts the exit status of the command to which it applied (see Example 6-2). It inverts the meaning of a test operator.
This can, for example, change the sense of equal (= to not equal (!=). The operator is a Bash keyword.

In a different context, the also appears in indirect variable references.

In another context, from the command line, it invokes the Bash history mechanism (see Appendix L). Note that within a script, the history mechanism is disabled.

wild card [asterisk]. The * character serves as "wild card" for filename expansion in globbing. By it, it matches every filename in a given directory.

```
bash$ echo *
ab-abs.sgml add-drive.sh agram.sh alias.sh
```
