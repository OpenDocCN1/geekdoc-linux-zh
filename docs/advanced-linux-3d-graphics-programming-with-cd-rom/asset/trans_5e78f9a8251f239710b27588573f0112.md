

无需创建 2D 光栅化器实现，只需创建 3D 光栅化器实现，这意味着你只需更改工厂创建接口，即可使创建 2D 光栅化器实现的旧代码失效。然而，出于教学目的，本书中我们保留了对早期开发代码的向后兼容性。

然后，在获得简单的投影坐标后，我们使用上述方程来确定 3D 预投影坐标。最后，我们将这些 3D 预投影坐标通过 `glVertex4fv` 命令传递给 OpenGL。`glVertex4fv` 函数期望的参数是一个数组，其中存储了四个 `x, y, z,` 和 `w` 分量。我们必须将 `3D z` 坐标指定为第四个（齐次 `w`）分量，以便 Mesa 有机会执行关于 `w` 的齐次除法，从而通过关于 `z` 的透视除法来实现 OpenGL 的透视正确纹理映射。同样重要的是，我们不要将 `3D z` 坐标作为第三个（`3D z`）分量传递给 `glVertex4fv`，而是传递常数 `1.` 这实现了什么？请记住，OpenGL 将所有分量除以 `w` 分量。这意味着，在除以 `w`（我们将其设置为 `3D z` 的值）之后，OpenGL 顶点的第三分量包含 `1/z`。如第 4 章所示，这个 `1/z` 值可以用于 `z` 缓冲算法。

> **注意** 请注意，Mesa 对坐标执行的最后一个操作是除以齐次分量 `w`。这就是为什么，对于 Mesa 3D 光栅化器，我们将屏幕坐标系的原点重新定义为屏幕中心，并采用标准的 `x` 轴方向的原因。由于关于 `w` 的除法是最后一个操作，我们无法告诉 Mesa“哦，在齐次除法之后，请将 `x` 和 `y` 值偏移半个屏幕大小并反转 `y` 轴方向”。如果我们希望 Mesa 执行透视除法——对于纹理映射正确发生应该是这种情况——那么我们在投影后的坐标上没有控制权，因为此时它们已被硬件接管。
