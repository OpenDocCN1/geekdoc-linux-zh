## 光栅化器：13d_rasterizer_2d

类 `13d_rasterizer_2d`（文件 `rasteriz.cc`）表示一个二维双缓冲光栅化器——一个能够在双缓冲光栅输出设备上绘制二维几何图元的子系统。该类本身并不执行任何光栅化工作，而是依赖于光栅化器实现（将在下一节介绍）提供一个由光栅化器调用的函数“工具箱”。类 `13d_rasterizer_2d` 是对光栅化器接口这一通用概念的认可，它允许访问抽象的光栅化概念。光栅化器接口不仅允许绘制单个像素，还允许绘制形成几何图元（如线条和多边形）的像素组。

> **注意** 将*光栅化器*与*光栅化器实现*分离是通用*桥接设计模式*的一个实例，其中抽象及其实现是两个独立的类。这使得抽象的类层次结构及其实现的类层次结构可以独立变化和细化，避免了前文讨论的类的乘方爆炸式增长（嵌套泛化）。这种技术也称为使用*句柄*。

类 `13d_rasterizer_2d_imp`（文件 `rasteriz.cc`）表示二维光栅化器执行其工作所需的工具的实现，被称为光栅化器实现。光栅化器实现是一个抽象类，通过子类化提供特定软件或硬件平台的具体光栅化器实现。虽然相关类 `13d_rasterizer_2d` 表示二维光栅化器功能的接口，但类 `13d_rasterizer_2d_imp` 表示二维光栅化器功能实现的接口。此光栅化器实现（在子类中）可以基于手工编写的软件算法，也可以基于硬件加速光栅化函数的 API。

继承自类 `13d_rasterizer_2d_imp` 的类 `13d_rasterizer_2d_sw_imp` 表示以软件（而非硬件）实现的光栅化器实现。源文件为 `ras_sw.cc`。计算与像素对应的字节并按顺序设置这些字节以显示几何图元，都是软件光栅化实现的典型操作，但不一定是硬件光栅化实现的典型操作。这就是为什么此类字节和像素计算仅发生在表示软件光栅化器实现的具体子类 `13d_rasterizer_2d_sw_imp` 中，而不发生在表示更抽象的软件或硬件光栅化器实现概念的抽象祖先类 `13d_rasterizer_2d_imp` 中的原因。

类 `13d_rasterizer_2d_mesa_imp`（文件 `ras_mesa.cc`）表示使用 OpenGL/Mesa 调用实现的光栅化器实现。通过 Mesa 库中的硬件支持，或者通过直接渲染接口（DRI），此光栅化器实现可以利用硬件加速。

## 具体工厂管理

类 `l3d_factory_manager`（文件 `factorys.cc`）表示包含程序中任何类可能需要的所有工厂的工厂管理器。每当对象通过“工厂”请求对象创建时，该工厂都应存在于中央工厂管理器中。

全局变量 `factory_manager_v_0_1` 是工厂管理器的全局实例。应用程序通过全局变量 `factory_manager_v_0_1` 在启动时选择其工厂。因此，工厂管理器类是一个单例类，在整个程序中仅被实例化一次。

注意，这是唯一直接通过类名操作具体工厂的 l3d 类，并且它包含具体工厂的头文件。所有其他工厂用户始终通过抽象工厂接口进行访问，并且不具体包含工厂的头文件。这就是抽象工厂的核心目的：将应用程序与底层具体类型完全隔离，以便在未来扩展代码时无需修改原始代码。

## 指定几何和行为规范

以下部分中描述的类允许 13d 程序在 3D 中指定对象并对它们进行操作。

### 点

指定点是通过两个类完成的：`13d_point`（文件 `point.cc`）和 `13d_coordinate`（文件 `coord.h`）。

类 `13d_point` 表示一组四个数字，形式为 $(x, y, z, w)$。这些数字表示空间中沿坐标轴的位移位置。

类 `13d_coordinate` 表示空间中可变换的坐标位置。它存储两个类型为 `13d_point` 的变量，分别命名为 `original` 和 `transformed`。变换后的坐标在每帧开始时始终初始化为等于原始坐标（方法 `reset`），之后可以通过零次或多次变换（方法 `transform`）进行变换。经过任意次变换后，应用程序可以选择将当前位置保存在其中一个中间存储位置（成员 `transformed_intermediates`）中，以便稍后引用旧位置。最终，变换后的坐标必须表示二维像素空间中的一个点，因为最终必须使用这些点来在屏幕上绘制图像。整个理念是 `13d_coordinate` 不仅仅是空间中的单个位置：它是一个原始位置、若干可选的中间位置和一个最终位置。

关于 `original` 和 `transformed` 成员，最重要的事情是要记住，变换后的坐标才是最终用于在屏幕上显示像素的那个。应用程序必须在某个时刻将最终像素坐标放入 `transformed` 成员变量中。

### 列表

指定更复杂的几何结构（正如我们将在关于多边形的下一节中看到的那样）要求我们存储顶点列表。为此，我们使用两种数据结构的组合：`13d_list` 和 `13d_two_part_list`（均在文件 `list.h` 中）。类 `13d_list` 是一个动态可增长的列表，类似于数组，但它会根据需要自动扩展并分配更多空间。元素通过数组索引运算符 [ ] 正常访问。类 `13d_two_part_list` 是 `13d_list` 的扩展，并将项列表分为两部分：固定部分和可变部分。固定部分的大小是固定的，永不改变；可变部分基于某种动态计算，其大小经常变化。然而——这正是 `13d_two_part_list` 的要点所在——固定部分和可变部分的访问方式是相同的。如果我们将在两个单独的列表中存储固定部分和可变部分，那么对列表项的任何引用都需要指定该项来自固定列表还是可变列表，这使得代码相当不便。使用 `13d_two_part_list`，外部用户无需担心被引用的项是固定的还是可变的。这种访问的统一性主要在 `polygon` 中非常有用
