# # Exporting and Importing Blender Models

Models created in Blender can be imported into 13d programs. The Blender file format is very complex and not documented for external users. For this reason, we need to export the Blender models in a different file format in order to import them into 13d programs.

The simplest export format offered by Blender is the Videooscape format. This file format is simple and straightforward; it contains vertices and polygons defined in terms of indices into a common vertex list. Conveniently, this is exactly the same way that 13d stores polygonal objects.

We use a plug-in (file `vidflat.c`) to read the Videooscape file into 13d. The plug-in constructor is of particular interest. The `data` parameter passed to the constructor is a plug-in environment object of type `13d_plugin_environment`, so that the plug-in knows something about its calling environment. The environment object, in turn, stores another `data` parameter. In the case of the Videooscape plug-in, this `data` parameter is a pointer to a character string containing a list of additional parameters needed to load the Videooscape file.

The Videooscape parameter string in the environment object has the following form: `xyzABCDEFGHImesh.obj`

The entries are interpreted as follows:

+   1. `x y z`: Floating-point numbers indicating the origin of the object's local coordinate system. In other words, this is the location of the object.
+   2. `A B C D E F G H I`: Nine floating-point numbers representing the object's orientation as a 3 x 3 rotation matrix. The numbers are in row-major order (i.e., $A\ B\ C$ is the first row of the matrix, $D\ E\ F$ the second row, $G\ H\ I$ the last row). Recall the relationship between matrices and coordinate systems, as explained in the introductory companion book *Linux 3D Graphics Programming*. This relationship implies that the vector $(A,D,G)$---the first row of the matrix---is the $x$ axis of the object's local coordinate system, $(B,E,H)$ is the $y$ axis, and $(C,F,I)$ is the $z$ axis.
+   3. `mesh.obj`: The filename of the Videooscape file containing the geometry of the object.

The plug-in constructor first parses the parameter string to get the position, orientation, and required filename for the Videooscape object to be loaded. Next, it opens the mesh file and reads in the vertices and faces. The Videooscape format stores coordinates in a right-handed system, with the $z$ axis going up; 13d uses a left-handed system with the $y$ axis going up. To convert between these two systems, we need to do two things: swap the $y$ and $z$ values as we read them from the Videooscape file, and reverse the ordering of the vertices in a face definition to preserve the front/back orientation of the face after the vertex swap. After converting the coordinates in this manner, the constructor then initializes each polygon by computing its center, surface normal, and containing plane. At this point, the polygon is also assigned a random color.

After reading in all vertices and faces, the constructor then defines two transformation matrices, one for rotating the object according to the rotation matrix specified within the parameter string, and a second matrix for translating the object to the specified position. These matrices are concatenated together and stored in the object as a composite transformation.
