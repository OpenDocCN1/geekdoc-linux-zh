
回顾硬件加速和VSD方案（可见性遮挡剔除方案）的互补角色。其核心理念是“能剔除就剔除，能加速就加速”。换言之，在拥有加速硬件的情况下，一旦每帧的多边形数量落在硬件可处理的范围内，剔除或VSD方案就可以停止处理。例如，如果硬件可以在1/60秒内绘制几十万面多边形，那么我们就不必费力去精确计算某个多边形的哪条边或哪个像素遮挡了另一个多边形的哪条边或哪个像素；我们只需将所有“可能可见”的多边形发送给硬件，让硬件将其全部绘制出来。即使我们浪费了绘制不可见多边形的时间，这也是由硬件加速处理的浪费，耗时不到1/60秒。在阅读本章时，请记住，硬件加速可以减少对精确细粒度VSD的需求，但至少在最低限度上，粗粒度VSD对于处理日益复杂的3D场景始终是必要的。

需要注意的是，VSD技术在与交互式3D应用程序的上下文中，与世界划分技术相关但并不相同。*世界划分*技术旨在减少需要检查的世界量（即3D对象数量），以便在帧与帧之间更新环境。在交互式3D环境中，环境可能会发生变化；对象可能移动、改变状态等。如果仅从可见性问题的角度来看，VSD技术与世界划分技术并不相同，因为环境的变化可能发生在当前不可见的那部分世界区域中。VSD技术减少了绘制场景所需的工作量，但类似的技术也是减少更新整个动态3D环境所需工作量的关键。通常，世界划分技术是VSD技术的延伸。这意味着我们先确定世界的哪些部分是可见的，然后允许位于可见区域内部或“附近”的对象进行变化或移动。环境的其余部分则“冻结在时间中”，在它变得可见或接近可见之前不会发生变化。其合理性在于，如果视点以连续的方式穿过环境（而不是随机瞬移），那么靠近当前视点的区域很可能在几帧内变得可见，因此即使这些附近区域尚未完全可见，它们也会得到更新。理想情况下，当然我们会让整个世界——所有对象——在每一帧都进行更新，但对于较大的世界而言，鉴于内存和算力并非无限，这是不可能的。因此，通常采取的折中方案是将VSD算法与世界划分算法相结合。与VSD类似，世界划分方案的一个主要关注点是避免顺序遍历并测试大量对象或区域，结果却发现它们当前处于非激活状态；高效的方案会在不进行搜索的情况下计算出观察者附近的活跃区域。我们可以在第5章中看到这方面的例子。

![](img/a19d4e8b1d7eb6387691dc6c865430e6_223_0.png)

图4.3：世界划分和VSD方案。如果我们把3D世界划分成一系列立方体区域，那么只有视野范围（实线）内的区域是可见的。然而，所有可见区域以及一些额外的“几乎可见”区域（虚线）都可以被设为活跃状态，从而使围绕观察者的那部分世界得以更新。距离观察者过远的区域（点线）处于非活跃状态且不会被更新。由于活跃区域取决于观察者的位置，因此当观察者移动时，它们也会随之改变。高效的方案不需要对所有区域进行穷举搜索来确定哪些区域当前是活跃的。

在理解了VSD算法所解决的准确性和效率问题，以及它们与世界划分方案的关系之后，让我们来看看几种VSD技术。

## 背面剔除（Back-Face Culling）

最简单的VSD算法之一是背面剔除算法。该算法主要解决的是VSD的效率问题。在3D图形中，剔除一个对象意味着将其从进一步的考虑中移除。因此，背面剔除指的是将背面朝向（back-facing）的面（多边形）从进一步的考虑中移除。让我们更深入地探讨这一概念。

原则上，我们使用多边形来建模3D对象的表面。如果我们所有的对象都是封闭的，使得内部永远不可见，这意味着我们只能看到对象的外向表面。这意味着我们看不到任何背向观察者的表面（多边形）部分；表面的背面指向对象的内部，由于始终被外向的多边形遮挡，我们永远看不到；而表面的正面背离观察者，意味着它也看不见。简而言之，这意味着任何背离观察者的多边形——称为背面多边形——都不需要绘制。

![](img/a19d4e8b1d7eb6387691dc6c865430e6_224_0.png)

![](img/a19d4e8b1d7eb6387691dc6c865430e6_224_1.png)

然而，不绘制背面多边形意味着，如果裁切掉正面多边形的一部分——例如相对于近平面（near z clip plane）的裁切——我们会直接看穿该物体，因为其背面没有被绘制。你几乎可以在每个基于多边形的3D游戏中注意到这种行为，通常发生在敌人身上。如果你靠得太近一个多边形网格，它将被近平面裁切，你会看到其多边形中空壳的内部。这通常通过实现碰撞检测算法（参见第8章）来避免，使观察者不能靠近物体以致其被近平面裁切，但由于碰撞检测的不精确性，观察者有时可能会靠得太近。

![](img/a19d4e8b1d7eb6387691dc6c865430e6_224_2.png)

![](img/a19d4e8b1d7eb6387691dc6c865430e6_224_3.png)

背面和正面的确定是一件 straightforward 的事。在摄像机空间中，我们只需检查表面法线向量的z坐标的符号。在世界空间中，我们可以计算表面法线向量与从多边形中心到摄像机的向量之间的点积；如果点积为负，则该多边形是背面朝向的。背面剔除算法很简单：如果多边形是背面朝向的，就不要将其发送到光栅化器进行绘制。

## 3D凸性与背面剔除

我们在讨论2D多边形的裁切和光栅化时接触到了凸性的概念。如前所述，2D中的凸性允许对多种多边形运算进行简化。我们见过的水平跨度光栅化和简化解析裁切就是两个依赖于其操作的2D多边形凸性的运算。

凸性在3D中也起着作用。如果一个3D多边形对象没有“凹陷”或“孔洞”，则它是凸的。更正式地说，对于凸对象，连接对象上任意两点的线段完全位于对象内部。3D凸性意味着整个对象大致呈球形，正如2D凸多边形大致呈O形（圆形）一样。

如果正在观察的唯一对象是一个单一的凸3D多边形网格，那么背面剔除就是正确显示该网格所需唯一的VSD算法。对于凸网格，任何正面多边形都无法遮挡任何其他正面多边形的任何部分；只有当多面体中存在“凹陷”导致某些正面多边形突出在其他正面多边形前方时，这种情况才可能发生。既然没有正面多边形能遮挡其他多边形，且我们只能看到正面多边形，这意味着我们可以简单地按任意顺序绘制所有正面多边形，并获得正确的显示——前提是我们的网格是凸的。

本身而言，这一观察结果很有趣，但并不直接具有实用性。通常我们处理的3D对象并非凸的。例如，我们在第3章中使用Blender创建的对象中（立方体除外）没有一个是凸的。此外，场景由许多对象组成，而不仅仅是一个对象。缺乏凸性意味着我们需要诉诸另一种VSD方案以产生正确的显示。例如，直到目前为止，我们一直使用画家算法（painter’s algorithm），我们将在本章中再次讨论该算法，以按从后到前的顺序绘制多边形。Z缓冲算法（z buffer algorithm），也在本章稍后涵盖，是另一种在缺乏凸性的情况下产生正确显示的方法。这些算法通过执行深度比较或计算来解决正面多边形之间的可见性，从而产生计算开销。

其他VSD技术不是试图补偿缺乏凸性的问题，而是尝试创建并利用凸性。我们将在后面讨论的两种方案——BSP树和门（portals）——依赖于几何体的凸划分。通过这种方式，关于凸性的观察再次变得有用。通过将我们的对象划分为不相交的凸部分，VSD问题提升到了更高层次，即确保凸部件之间可见性的正确性；在每个凸部件内部，我们只需使用背面剔除，并在该凸部件内部不执行进一步的VSD。

当我们详细研究BSP和门方案时，将回到凸性这个话题。
