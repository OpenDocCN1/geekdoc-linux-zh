## 使用ssh服务获取内容

在你让网络接口正常运行之后，我建议你让DSL自动启动ssh接口。该服务允许你从局域网上的其他计算机进行远程登录和远程复制。例如，你可以在/etc/rc5.d/S99bootlocal初始化脚本中添加以下一行：

```
/etc/init.d/ssh start
```

当你的网络接口和secure shell服务在DSL中运行后，有几种方法可以从局域网上的另一台计算机访问你的数字媒体播放器。首先，我建议你为DSL中的root用户添加一个密码。（不要为ds1添加密码，否则启动DSL时你将被提示输入密码，无法顺利启动。）

假设你的IP地址是10.0.10.1，下面是从局域网中另一台Linux计算机访问该媒体播放器的一些方法：

```
# ssh root@10.0.10.1
# scp *.jpg root@10.0.10.1:/var/mediaframe/pics/
```

对于这两条命令，系统都会提示你输入root密码。所示的ssh命令允许你以root身份登录到shell界面。所示的scp命令会将本地系统当前目录下所有以.jpg结尾的文件复制到媒体播放器上的/var/mediaframe/pics目录中。

如果你使用的是Mac OS X系统，你的计算机上已经带有ssh（只需打开一个终端窗口即可使用该命令）。对于Windows系统，有一组名为PuTTY的开源工具，你可以用来从Windows系统访问ssh、scp及其他安全shell服务。参见www.chiark.greenend.org.uk/~sgtatham/putty。还有SSHDOS可以从DOS下使用这些工具（http://sshdos.sourceforge.net）。当然，你也可以直接从局域网中的任何一台PC启动DSL。

## 使用Samba获取内容

DSL也支持Samba，它可用于与Windows系统共享文件和文件夹。使用MyDSL安装好Samba（如前所述）后，下面是一个示例，说明如何从DSL创建一个共享目录，以便使用Windows客户端的用户可以添加和删除/var/mediaframe/pics目录中的图片：

- 1. 编辑/etc/samba/smb.conf文件，在Share Definitions部分添加一个如下所示的小节：

```
[mediaframe]
comment = Images for Digital Media Frame
path = /var/mediaframe/pics
writable = yes
read only = no
public = yes
```

这里显示的权限是完全开放的。在确认Samba正常工作后，你应该考虑为你的Samba服务提供密码保护以确保安全。系统名称会显示在“名称”框中（既然你已经在修改/etc/samba/smb.conf，不妨顺手改掉它）。

- 2. 启动nmbd和smbd服务。以root用户身份，输入以下内容：

```
# /usr/sbin/nmbd -D
# /usr/sbin/smbd -D
```

刚才显示的命令会以守护进程（后台）模式（-D）启动NetBIOS（nmbd）和Samba（smbd）服务。现在mediaframe共享应该可以在你的局域网上使用了。

- 3. 尝试从局域网上的另一台计算机访问mediaframe共享。打开“网络”或“网上邻居”窗口，查看你的DSL系统是否出现。在Linux系统中，你可以通过将该共享挂载到本地文件系统来访问它。例如：

```
# mkdir /mnt/box
# mount -t smbfs //box/mediaframe /mnt/box
```

然后，你应该可以将文件复制到/mnt/box目录中，或者从该目录中删除文件，并让它们显示在你的数字媒体播放器上。你可能需要重启GQview才能让新图像被识别。

> 注意
> 在我那台167MHz Pentium、64MB内存的机器上，通过Samba复制文件确实会拖慢媒体播放器的性能。有些图像效果还没完成，GQview就切换到下一张图像了。不过，复制结束后，性能会恢复正常。
