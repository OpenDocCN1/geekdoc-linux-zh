### 故障排查运行级别

**开始之前：**

1. 在 srvB 上，你已以 root 身份在 GUI 中登录。
2. 切换到 CLI 终端。
3. 在 CLI 中以 root 身份登录。
4. 输入 `vi /etc/inittab` 以访问包含运行级别信息的 inittab 文件。
5. 注释掉以“si:sysinit:/etc/rc.d/rc.sysinit.”开头的行。
6. 保存并关闭文件。
7. 输入 `reboot` 以应用设置。

**场景：**

你需要排查一个无法启动的系统，该系统抛出错误消息：“/etc/rc5.d/S00microcode_ctl: microcode device /dev/cpu microcode does not exist.”（/etc/rc5.d/S00microcode_ctl: 微码设备 /dev/cpu 微码不存在。）。你确定 rc.d 设置存在系统初始化错误。

| 你的操作 | 执行方法 |
| :--- | :--- |
| 1. 使用 RHEL 启动 CD-ROM 排查运行级别。 | a. 在光驱中插入 RHEL 5 救援 CD 并重新启动系统。<br>b. 在 **boot** 提示符处，输入 `linux rescue` 切换到 Linux 救援模式。 |
| 2. 选择语言和键盘配置选项。 | a. 在 **Choose a Language**（选择语言）页面上，在 **Language Selection**（语言选择）列表框中，验证已选中 **English**（英语）选项，然后选择 **OK**（确定）。<br>b. 在 **Keyboard Type**（键盘类型）页面上，在 **Keyboard**（键盘）部分，验证已选中 **us** 选项，然后选择 **OK**（确定）。 |
| 3. 配置网络设置并进入救援模式。 | a. 在 **Setup Networking**（设置网络）消息框中，选择 **Yes**（是）。<br>b. 在 **Configure Network Interface**（配置网络接口）消息框中，选择 **Yes**（是）以配置系统上的 eth0 网络接口。<br>c. 在 **Network Configuration for eth0**（eth0 的网络配置）页面上，选择 **Enable IPv4 support**（启用 IPv4 支持）选项。<br>d. 在 **IPv4 Configuration for eth0**（eth0 的 IPv4 配置）页面上，选择 **Manual address configuration**（手动地址配置）选项。<br>e. 在 **IP Address**（IP 地址）文本框中，输入你系统的 IP 地址。<br>f. 在 **Prefix (Netmask)**（前缀（子网掩码））文本框中，输入 *255.255.255.0* 并点击 **OK**（确定）。<br>g. 在 **Miscellaneous Network Settings**（其他网络设置）页面上，按 **F12** 进入下一页。<br>h. 在 **Error With Data**（数据错误）页面上，选择 **Continue**（继续）以忽略错误。<br>i. 在 **Error With Data**（数据错误）页面上，选择 **Continue**（继续）以忽略错误。<br>j. 在 **Rescue**（救援）页面上，选择 **Continue**（继续）。<br>k. 在 **Rescue**（救援）页面上，选择 **OK**（确定）。 |

## 主题 B
### 故障排查硬件问题

你已修复了 Linux 系统中的基于系统的问题。硬件设备可能会损坏且无法正常工作。在本主题中，你将排查硬件问题。

系统可能连接到扬声器或调制解调器等外部设备。有时，这些设备可能无法正常工作。找出问题原因将有助于你解决硬件问题。

### 故障排查工具

根据你所面临的问题类型以及工作环境的类型，可以使用许多故障排查工具。下表描述了一些此类工具。

![](img/477ccb2f05b6ba1b2d563ea74f18c197_804_0.png)

| 工具 | 描述 |
| :--- | :--- |
| dmesg | 一种用于检查和控制内核初始化过程的系统管理命令。它用于在系统内核初始化期间打印关于各种硬件设备状态的消息。状态消息也可以从 /var/log/dmesg 文件中访问。 |
| /dev | 一个用于创建启动盘或可恢复磁盘的文件。 |
| GNU Parted | 一个允许你创建、销毁、调整大小、移动和复制硬盘分区的程序。 |

| KNOOPPIX | 一个可启动的 CD（或 DVD），包含 GNU/Linux 软件，其中包括自动硬件检测和支持。KNOOPPIX 可用作救援系统。 |

### LNX-BBC

LNX-BBC 是一个足够小的 Linux 发行版，可以容纳在 CD-ROM 中，其尺寸和形状与名片相同。LNX-BBC 可用于救援损坏的机器或作为临时 Linux 工作站。有关 LNX-BBC 的更多信息，可以在 http://www.lnx-bbc.org 找到。

### 启动和停止进程以定位和纠正问题

如课程中之前所述，服务和进程都可以停止和重新启动。这有时可用于修复问题。你可以将 `ps` 命令与 `grep` 命令一起使用来定位需要检查的进程。如果需要，你可以终止这些进程。

**pgrep** 命令用于根据名称或其他属性查找或向进程发送信号。它遍历当前运行的进程，并列出符合你指定条件的 PID。例如，**pgrep -u root sshd** 命令仅列出名为 sshd 且由 **root** 用户拥有的进程。命令 **pgrep -u root,daemon** 列出所有由 root 或 daemon 拥有的进程。

**pkill** 命令可以与 **pgrep** 命令配合使用来停止进程。启动和停止进程只是另一种故障排查方法。当你看到某种症状（例如进程耗时过长）时，应首先使用 **ps** 或 **pgrep** 命令检查该进程；然后，如有必要，使用 **kill** 或 **pkill** 命令终止该进程。接着，你应该检查该进程（与该进程相关的脚本或其他命令序列）并查找任何问题。在修复问题后，应尝试再次运行该命令或脚本。定期进行检查，以确认其是否正常工作。

### 硬件问题

硬件设备可能在系统使用过程中随时发生故障。

| 症状 | 原因和解决方案 |
| :--- | :--- |
| 用户无法从扬声器听到声音。 | **原因**：扬声器或声卡工作不正常。<br>**解决方案**：检查扬声器及其相应的驱动程序。如果问题仍然存在，则需要检查声卡。 |
| 调制解调器无法拨入或拨出。 | **原因**：调制解调器配置与调制解调器设置之间不匹配，或者可能存在调制解调器故障。<br>**解决方案**：检查调制解调器和串行端口设置。如果问题持续存在，请检查相应的驱动程序。 |
| 系统启动时，监视器切换到节能模式或电源指示灯闪烁。 | **原因**：CPU 无法与监视器建立连接。<br>**解决方案**：检查监视器线缆是否连接到系统，然后检查 VGA 卡的功能。 |
| 哑终端设备无法启动。它仅停留在显示屏上。 | **原因**：哑终端无法与服务器连接。<br>**解决方案**：检查串行端口和线缆。 |
| 连接到 UPS 的系统突然关机。 | **原因**：UPS 故障，或者 UPS 设置与配置文件之间不匹配。<br>**解决方案**：检查串行端口、线缆和配置文件。 |
| 用户无法切换到 GUI 模式。 | **原因**：由于配置设置，鼠标工作不正常，或者设备可能存在故障。<br>**解决方案**：拔下并重新连接鼠标，然后重新启动系统。 |
