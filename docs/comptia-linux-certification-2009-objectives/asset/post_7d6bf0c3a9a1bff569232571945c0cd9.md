
## How to Implement Network File Sharing Services

### Procedure Reference: Configure FTP Manually

To manually configure the FTP service:

- Log in as root in the CLI.
- If necessary, install the `vsftpd-{version}.(release).rpm` package.
- Enter `service vsftpd start` to start the FTP service.
- If desired, enter `chkconfig vsftpd on` to set the service to start automatically on reboot.
- If desired, enter `service vsftpd stop` to stop the FTP service.
- If desired, enter `service vsftpd restart` to restart the FTP service.

### Procedure Reference: Connect to a Remote Terminal Using FTP

To connect to a remote terminal using FTP:

- Log in as root in the CLI.
- Enter `ftp (IP address of the ftp server)` to connect to another system by FTP.
- Enter the user name and password.
- Perform the necessary tasks on the remote computer.
- If necessary, enter `bye` to log out of the FTP service.

### Procedure Reference: Install an FTP Server

To install an FTP server:

- In the Linux server, log in as root.
- At the command line, enter the command to install the FTP server.
    - Enter `rpm -ivh vsftpd-(version).(release).rpm` to install vsftpd.
      ![](img/477ccb2f05b6ba1b2d563ea74f18c197_580_0.png)
    - Enter `rpm -ivh pure-ftpd-(version).(release).rpm` to install Pure-FTPd.
      ![](img/477ccb2f05b6ba1b2d563ea74f18c197_580_1.png)
    - Enter `rpm -ivh proftpd-(version).(release).rpm` to install ProFTPD.
      ![](img/477ccb2f05b6ba1b2d563ea74f18c197_580_2.png)
- Verify that the FTP has been installed.
    - Enter `rpm -qi vsftpd` to verify that vsftpd has been installed.
    - Enter `rpm -qi pure-ftpd` to verify that Pure-FTpd has been installed.
    - Enter `rpm -qi proftpd` to verify that ProFTpd has been installed.

### Procedure Reference: Configure a vsftpd FTP Server for Anonymous Uploads

To configure an FTP server for anonymous uploads:

- Navigate to the `/etc/vsftpd` directory.
- Open the `vsftpd.conf` file.
- Locate the line that reads "`anonymous_enable=YES`" and uncomment it, to enable anonymous logins.
- Locate the line that reads "`write_enable=YES`" and verify that it is not commented, to grant write permission to all users.
- Enable anonymous uploads.
    - Locate the line that reads "`anon_upload_enable=YES`" and uncomment it.
    - Locate the line that reads "`anon_mkdir_write_enable=YES`" and uncomment it.
- If necessary, change the ownership of the uploaded files.
    - Locate the line that reads "`chown_uploads=YES`" and uncomment it, to change the ownership.
    - Locate the line that reads "`chown_username=whoever`" and uncomment it. In the line "`chown_username=whoever`", replace *whoever* with the name of the user who will own the uploaded files.
- Save and close the file.
- Enter
    ```
    service vsftpd start
    ```
    to start the `vsftpd` daemon.
- If necessary, enter `chkconfig vsftpd on` to start the service on boot.
- If necessary, connect the FTP client to the FTP server to upload or download files.

### Procedure Reference: Configure FTP to Run in chroot Mode

- Navigate to the `/etc/vsftpd` directory.
- Open the `vsftpd.conf` file.
- Enable the chroot list file settings.
    - Locate the line that reads "`chroot_list_enable=YES`" and uncomment it, to enable the list.
    - Locate the line that reads "`chroot_list_file=/etc/vsftpd/chroot_list`" and uncomment it, to enable the list file.
- Save and close the file.
- Add the users who need to be added to the chrooted list in the `/etc/vsftpd/vsftpd.chroot_list` file.
- Start the `vsftpd` daemon using the `service vsftpd start` command.

### Procedure Reference: Mount Remote Filesystems

To mount remote filesystems using NFS:

![](img/477ccb2f05b6ba1b2d563ea74f18c197_582_0.png)

After you exported a directory or filesystem for a user, the user can now use the exported directory or filesystem by mounting the remote filesystem to the local directory using NFS.

- Log in as root in the CLI.
- Mount the remote filesystem.
    - Enter `showmount -e {IP address of the NFS server}` to view the export list of the NFS server.
    - Enter `mount -t nfs IP address of the NFS server:/Directory/Filesystem / (Local mount point)` to mount the remote filesystem on the specified mount point.
- Enter `mount` to verify that the remote filesystem is mounted.
- If desired, enter `umount / (Local mount point)` to unmount the filesystem.

### Procedure Reference: Mount Remote Filesystems Automatically

To automatically mount remote filesystems using NFS:

- Log in as root in the CLI.
- Automatically mount the remote filesystem.
    - Enter `showmount -e {IP address of the NFS server}` to view the export list of the NFS server.
    - Enter `vi /etc/fstab`.
    - Type `{IP address of the NFS server}:/Directory/Filesystem / (Local mountpoint) nfs defaults (filesystem frequency) (filesystem order)` to mount the remote filesystem on the specified mount point when booting the system.
    - Save and close the file.
- Verify that the remote filesystem is automatically mounted on booting the system.
    - Reboot the system.
    - Log in as root.
    - Enter `mount` to verify that the remote filesystem is mounted.

### The showmount Command Options

The `showmount` command displays the mount information of the NFS server. The following table gives some common `showmount` command options and their description.

| Option | Description |
| :--- | :--- |
| -e | The NFS server's export list. |
| -d | The directories mounted by any client. |
| -a | The client’s hostname and the mounted directory. |

### Managing the NFS Server

NFS server management includes tasks such as starting the server and activating the list of exported filesystems. The following table lists common commands that are used to manage the NFS server.

| If You Need To | Enter |
|---|---|
| Start the NFS server | `service nfs start` |
| Stop the NFS server | `service nfs stop` |
| Restart the NFS server | `service nfs restart` |
| Activate the list of exported filesystems | `exportfs -r` |
| Deactivate the list of exported filesystems | `exportfs -ua` |

### Procedure Reference: Configure Samba Using the GUI

To configure Samba using the GUI:

- Log in as root in the GUI.
- Display the terminal and enter `system-config-samba`.
- Specify the workgroup.
    - In the **Samba Server Configuration** window, choose **Preferences**→**Server Settings**.
    - In the **Server Settings** dialog box, in the **Workgroup** text box, specify the workgroup name.
    - In the **Description** text box, specify the details about the workgroup.
- Specify the authentication mode.
    - Select the **Security** tab.
    - From the **Authentication Mode** drop-down list, select the desired authentication mode and fill the necessary details.
    - Click **OK**.
- Share home directories.
    - Choose **File**→**Add Share**.
    - In the **Create Samba Share** dialog box, click **Browse**.
    - In the **Select Directory** dialog box, in the **Folders** list, double-click to select the directory you want to share and then click **OK**.
    - In the **Description** text box, specify the details of the shared directory.
    - Set the desired permission for the share: **Writable**, **Visible**, or both.
    - On the **Access** tab, select the desired permission and click **OK**.
- Choose **File**→**Quit**.

![](img/477ccb2f05b6ba1b2d563ea74f18c197_584_0.png)

The Samba service will start as soon as you perform the above step.

- Verify that the shared directory is accessible from a Windows system.
    - Start the Windows system.
    - Log in as administrator.
    - Display the **Windows Explorer** window.
    - In the **Windows Explorer** window, in the address bar, type `// ({Name or IP address of the samba server}) / ({Share name})` and press **Enter** to access the shared directory. The display of the shared directory may take some time depending on the network speed.

### Set Permission to Filesystems

If a conflict arises between the permission set for a directory and the permission set for that directory while sharing the directory, its effective permission will always be the minimal permission. Some of the possible file permission combinations that will be implemented during a conflict are given in the following table.

| Directory Permission | Share Permission | Effective Permission |
| :--- | :--- | :--- |
| Read | Read | Read |
| Read | Write | Read |
| Write | Read | Read |
| Read/write | Read | Read |
| Read | Read/write | Read |
| Read/write | Read/write | Read/write |
