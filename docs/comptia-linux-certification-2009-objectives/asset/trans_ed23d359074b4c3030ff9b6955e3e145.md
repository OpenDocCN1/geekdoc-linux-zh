

## 操作参考：在 /etc/xinetd.conf 文件中定义全局设置

要在 `/etc/xinetd.conf` 文件中定义全局服务设置：

- 以 root 用户登录。
- 输入 `vi /etc/xinetd.conf` 以编辑 xinetd 守护进程配置文件。
- 编辑 `{Attribute}`（属性） `{Assignment Operator}`（赋值运算符） `{Value}`（值） `{Value}`（值）以定义由 xinetd 守护进程管理的所有服务的全局设置。
- 保存并关闭文件。
- 输入 `service xinetd restart` 以应用更改。

### 操作参考：配置 xinetd 管理服务的访问控制

要配置 xinetd 管理服务的访问控制：

- 以 root 用户登录。
- 在 `/etc/xinetd.conf` 文件中定义特定于服务的访问控制。
  - 输入 `vi /etc/xinetd.d/{Service Configuration File}` 以编辑特定于服务的配置文件。
  - 输入 `only_from = {List of IP Addresses}` 以定义该特定服务可用的远程主机。
  - 输入 `no_access = {List of IP Addresses}` 以定义该特定服务不可用的远程主机。
  - 输入 `access_times = hour: min-hour: min` 以定义服务可被访问的时间间隔。
- 保存并关闭文件。
- 输入 `service xinetd restart` 以应用更改并重启 xinetd 守护进程。

#### 检查系统安全的基础

您曾处理过互联网和邮件服务。这些服务容易受到黑客的威胁，这可能会造成严重问题。组织网络中的安全漏洞不能妥协，因为破坏或数据盗窃可能会严重损害业务。通过保护系统并以只有接收数据的用户才能理解的格式发送数据，可以避免这些情况。在本主题中，您将检查系统安全的基础。

计算机安全是业务战略的关键部分，组织不断要求新的保护水平。在网络上，可以实施各种 Web 和邮件服务。尽管这些服务促进了数据传输，但与这些服务相关的数据盗窃风险始终存在。如果没有适当的安全和加密机制来管理这些服务，安全地传输敏感数据是不可能的。

##### 密钥

密钥是一个信息块，用于授权用户访问数据。密钥可以预先分配给用户，也可以在运行时随机生成。

在登录到远程机器时，私钥和公钥由远程服务器组合以进行验证。只有当密钥匹配时，用户才能登录并传输文件。远程服务器建立真实性，然后授予必要的权限。

![](img/477ccb2f05b6ba1b2d563ea74f18c197_691_0.png)

图 14-1：使用密钥保护数据。

密钥分为两种类型：公钥和私钥。

| 密钥类型 | 描述 |
| --- | --- |
| 公钥 | *公钥* 是随请求一起传输到目标服务器的密钥。这将与目标的私钥进行比较。只有当这两者相关时，用户才会被身份验证。 |
| 私钥 | *私钥* 保留在本地系统上，不传输到目标服务器。数据随发送者的公钥一起发送给用户。只有当用户的私钥由发送者的公钥验证时，用户才能访问数据。 |
