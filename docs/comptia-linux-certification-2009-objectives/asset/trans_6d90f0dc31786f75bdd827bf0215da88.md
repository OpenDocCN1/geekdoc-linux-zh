## 主题 E
控制互联网服务

您已配置电子邮件服务。互联网提供了众多服务和优势。这使得互联网成为几乎所有组织的基本必需品。在本主题中，您将控制互联网服务。

互联网服务对于企业的有效运行至关重要。互联网服务的任何中断或问题都可能使常规工作陷入瘫痪，并给组织带来巨大损失。作为 Linux+ 系统管理员，您的首要职责是确保互联网服务始终无问题地运行。

### xinetd 守护进程

*xinetd* 守护进程控制网络上的系统服务，并基于客户端-服务器架构。*xinetd* 的配置文件列出了各种服务。当守护进程收到来自端口的特定服务请求时，它会查看配置文件，然后启动包含该服务的相应服务器。这使得网络上的服务管理更快，因为请求会被立即处理。由 *xinetd* 管理的服务包括文件共享服务、Telnet、rsync 和时间服务。这些服务的设置可以通过 /etc/xinetd.conf 文件或 /etc/xinetd.d 目录中找到的特定服务文件进行控制。

### Telnet

**定义：**

*Telnet* 是一种终端仿真协议，允许站点上的用户模拟远程主机上的会话。换句话说，它允许用户通过网络登录到另一台计算机。它通过翻译用户终端的击键操作为远程主机识别的指令，然后将输出传回用户终端并以远程主机的原生格式显示，从而实现这一点。该服务是透明的；它给用户一种其终端直接连接到远程主机的印象。远程计算机需要有一个 Telnet 服务器，而用户的计算机需要有一个 Telnet 客户端。远程计算机直接接受来自用户计算机的输入。输出指向用户计算机的屏幕。

### Telnet 的缺点

Telnet 不是一个非常安全的协议，因为它以明文传输密码。由于 SSH 提供更高的安全性，Telnet 在很大程度上已被 SSH 取代。

### /etc/xinetd.conf 文件

/etc/xinetd.conf 文件是 xinetd 守护进程的配置文件。它包含由 xinetd 守护进程管理的服务列表。每次发送启动或停止服务的请求时，守护进程都会引用该文件。该文件分为各个部分，每个部分包含特定服务的设置。服务可以是单线程的或多线程的。

![](img/477ccb2f05b6ba1b2d563ea74f18c197_683_1.png)

图 13-30：包含各种配置设置的 xinetd.conf 文件。

可以根据用户要求使用多个选项对 /etc/xinetd.conf 文件进行高度配置。下表列出了常用的一些选项。

| 选项 | 功能 |
| --- | --- |
| service | 指定服务名称。 |
| wait | 指定服务是单线程还是多线程。 |
| user | 指定在服务器上运行的进程的 UID。 |
| server | 指定在调用服务时在服务器上启动的可执行文件。 |
| disable | 指定服务是启用还是禁用。 |

### 语法

在 xinetd 配置文件中指定服务的语法是 *{Attribute} {Assignment Operator} {Value}*。

### libwrap.so 库

libwrap.so 文件是链接到由 xinetd 守护进程控制的服务的库。主要有三个库文件：libwrap.so、libwrap.so.0 和 libwrap.so.0.7.6。这些文件位于 /usr/lib 目录中，它们控制 TCP 服务以及额外的网络访问设置，包括网络访问配置文件中的设置。

### /etc/xinetd.d 目录

/etc/xinetd.d 目录包含由 xinetd 管理的服务配置脚本。该目录中列出的一些服务包括 ftp、kerberos 和 rsync。可以使用该目录中相应的配置文件单独配置每个服务。服务配置文件中的选项与 /etc/xinetd.conf 文件中找到的选项类似。

### xinetd 访问控制

xinetd 守护进程拥有一组用于控制对其管理的服务访问的功能。这些访问控制分为两种类型：基于主机和基于时间。这些功能共同限制了网络上的主机访问。

| 访问控制类型 | 描述 |
| :------------------ | :---------- |
| 基于主机 | 基于主机的访问控制通过限制 xinetd 服务配置文件中的 no_access 和 only_from 选项来实现。主机模式访问控制用于在实现基于主机的访问控制时指定主机模式。主机可以以其 IP 地址、子网掩码范围、网络名称或主机名的形式指定。 |
| 基于时间 | 通过向服务配置文件添加 access_times 选项来实现基于时间的访问控制。 |

### 服务和应用访问控制

服务访问控制和应用访问控制本质上是守护进程，用于限制对某些重要服务和应用的访问，例如控制网络连接和安全策略的服务。这些守护进程的一些例子包括 squid 和 httpd。这些守护进程通过参考尝试访问服务的系统的主机名或 IP 地址来限制访问，列表提供在 libwrap.so 文件或 xinetd 配置文件中。如果系统具有所需权限，守护进程将允许它们访问受保护的服务和应用。

### 如何控制互联网服务

**程序参考：配置由 xinetd 管理的服务**

要配置由 xinetd 管理的服务：

- 1. 以 root 身份登录。
- 2. 输入 `ls -l /etc/xinetd.d/` 列出由 xinetd 守护进程管理的服务。
- 3. 在系统启动时管理 xinetd 守护进程。
  - 输入 `chkconfig --list xinetd` 确保 xinetd 守护进程已配置为在所需的运行级别启动。
  - 输入 `chkconfig --level (levels) xinetd {on/off}` 更新 xinetd 守护进程的运行级别配置。
  - 输入 `service xinetd {start/stop/status/restart/reload}` 管理 xinetd 守护进程的状态。
- 4. 管理由 xinetd 守护进程控制的服务。
  - 输入 `chkconfig {Service Name} {on/off}` 在系统启动时启用或禁用指定服务。
  - 或者，使用 /etc/xinetd.d 目录中找到的配置文件管理该服务。
