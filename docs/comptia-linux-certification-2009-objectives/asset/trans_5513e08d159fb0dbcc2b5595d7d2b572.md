
## 引导加载程序问题

如果用户无法启动系统，可能是由于引导加载程序或硬件设备导致的磁盘错误。

RHEL5 不支持 LILO。

| 症状 | 原因和解决方案 |
| :--- | :--- |
| 显示错误消息“L”。 | **原因：** LILO 无法加载 /boot/boot.b 文件。<br>**解决方案：** 使用启动盘启动系统并重新安装 LILO。 |
| 显示错误消息“LI”。 | **原因：** LILO 无法定位 /boot/boot.b 文件，或者可能是任何磁盘错误。<br>**解决方案：** 登录救援模式并重新安装 LILO。 |
| 显示错误消息“LIL”。 | **原因：** LILO 无法定位 /boot/map 文件。<br>**解决方案：** 登录救援模式并重新安装 LILO。 |
| 显示带有滚动零和一的错误消息“LILO”。 | **原因：** 硬盘不受 BIOS 支持。<br>**解决方案：** 更新 BIOS 或更换主板或硬盘。 |
| 显示内核恐慌（Kernel Panic）消息。 | **原因：** 文件系统已损坏或不可访问。<br>**解决方案：** 登录救援模式并对文件系统执行完整性检查。 |

## 如何排除 Linux 相关问题故障

### 程序参考：通过收集数据来分析问题

要通过收集数据来分析问题：

1. 以 root 身份登录到 CLI。
2. 使用适当的命令和文件收集有关该问题的数据。
   - 输入 `history` 以分析用户运行命令的历史记录。
   - 输入 `grep {关键字} {日志文件名}` 以在故障排除时在日志文件中查找指定关键字。
   - 输入 `diff {当前文件} {已备份文件}` 以查看与上次备份状态相比文件是否有任何更改。
   - 输入 `find {要搜索的目录位置} -cmin -{分钟数}` 以查找在指定时间内修改的所有文件。
   - 输入 `strace {命令}` 以在运行指定命令时收集更多信息。
   - 输入 `tail -f {日志文件名}` 以在日志文件更新时查看该日志文件。
   - 配置系统日志以记录所有调试消息。
     1. 输入 `vi /etc/syslog.conf` 以打开系统日志配置文件。
     2. 输入 `{设施} {严重级别} {日志消息存储的文件}` 以设置要记录在指定文件中的类型和严重级别。
     3. 保存并退出。
     4. 输入 `service syslog restart` 以重启系统日志服务并应用更改。

## 排除启动过程故障

| **原因** | **解决方案** |
| :--- | :--- |
| 如果引导加载程序屏幕未出现，则 GRUB 可能未正确配置。 | 在救援模式下配置 `/boot/grub/grub.conf`。 |

| 如果发生内核恐慌，则： | 1. 在救援模式下，配置引导加载程序配置。<br>2. 在救援模式下，正确定义 `/etc/inittab` 文件中的参数。<br>3. 在救援模式下，对文件系统运行文件系统检查。 |

## 程序参考：使用 Linux 救援环境

要使用 Linux 救援环境：

1. 修改 BIOS 设置以从恢复光盘启动。
2. 将第一张红帽安装 CD 插入 CD-ROM 驱动器并启动系统。
3. 在启动提示符处，输入 `linux rescue` 以进入救援模式。
4. 如有必要，指定访问安装文件所需的设置。
   - 指定语言和键盘设置。
   - 在 **Setup Networking** 页面上，选择 **Yes**。
   - 在 **Network Configuration** 页面上，指定 **eth0** 的网络参数，然后选择 **OK**。
5. 显示一条消息，说明根分区将挂载在 `/mnt/sysimage` 目录中。选择 **Continue** 以挂载文件系统并拥有读写权限。
6. 选择 **OK** 以继续启动过程。
7. 现在根目录已挂载到 ramdisk 上。输入 `chroot /mnt/sysimage` 以将根目录更改为挂载在 `/mnt/sysimage` 目录中的那个。
8. 进行故障排除以查找系统故障的原因，并进行必要的更改以恢复系统。例如，如果系统由于 LILO 配置文件中的错误而无法启动，请修改该文件，然后重新安装 LILO。
9. 输入 `exit` 以退出 chroot 环境。
10. 输入 `sync`，以便所做的更改反映在硬盘上的文件系统中。
11. 输入 `exit` 以退出救援模式。系统将重新启动。

## 排除 GRUB 故障

**开始前：**

1. 在 srvB 上，您已以 root 身份登录到 CLI。
2. 在命令行中，输入 `cd /boot/grub` 以打开 GRUB 目录。
3. 输入 `cp grub.conf grub1.conf` 以备份现有的 GRUB 配置文件。
4. 输入 `vi grub.conf` 以打开当前的 GRUB 配置文件。
5. 注释所有行。
6. 保存并关闭文件。
7. 输入 `reboot` 以应用设置。

**场景：**

您的系统从 **grub** 提示符启动，而不是从 GUI 提示符启动。即使重新启动，情况仍然相同。这表明 GRUB 配置存在问题。您需要系统通过 GUI 启动。

| 您做什么 | 您怎么做 |
| :--- | :--- |
| 1. 更正 GRUB 设置。 | a. 在 **grub** 提示符处，输入 `root`<br>b. 输入 `cat /grub/grub.conf` 以查看当前引导加载程序设置。<br>c. 记录内核和模块设置，并按 **Enter** 返回 **grub** 提示符。<br>d. 输入 `clear` 以清除终端屏幕。<br>e. 输入 `kernel /vmlinuz-2.6.18-128.el5 ro root=LABEL=/ rhgb quiet`<br>f. 输入 `initrd /boot/initrd-2.6.18-128.el5.img`<br>g. 在 **grub** 提示符处，输入 `boot` 以重新启动系统。 |
| 2. 检查更正后的 grub.conf 文件，以确保设置正确。 | a. 按 **Ctrl+Alt+F1** 切换到 CLI。<br>b. 以 **root** 身份登录到 CLI。<br>c. 输入 `cd /boot/grub/` 以导航到 grub 目录。<br>d. 输入 `rm grub.conf` 以删除当前的 GRUB 配置文件。<br>e. 输入 `y` 以确认删除操作。<br>f. 输入 `mv grub1.conf grub.conf` 以替换正确的 GRUB 配置文件。<br>g. 输入 `cat grub.conf` 以查看当前的 grub.conf 文件。<br>h. 输入 `clear` 以清除终端屏幕。 |

# 活动 16-2
## 排除分区故障

**开始前：**

1. 在 *srvB* 上，您已以 root 身份登录到 CLI。
2. 输入 `cd /root` 以更改为根目录。
3. 输入 `e2label /dev/sda2 /boo` 以更改文件系统标签。
4. 输入 `reboot` 以应用设置。

**场景：**

一名新员工 Jim 不小心操作了一些文件。当他尝试启动机器时，出现错误消息“正在检查文件系统。fsck.ext3: 无法解析 'LABEL=/boo'。”

| 您做什么 | 您怎么做 |
| :--- | :--- |
| 1. 排除分区标签问题。 | a. 在命令提示符处，输入 root 密码。<br>b. 在 **Repair filesystem** 提示符处，输入 `cat /etc/fstab` 以查看所有分区的标签条目。<br>c. 输入 `fdisk -l` 以查看引导设备信息。<br>d. 观察到引导设备分区是 `/dev/sda1`。<br>e. 输入 `e2label /dev/sda1` 以检查标签名称是否与 `/etc/fstab` 文件中的相同。<br>f. 观察到引导目录信息被指定为 `/boo` 而不是 `/boot`。<br>g. 输入 `e2label /dev/hda1 /boot` 以纠正标签错误。<br>h. 按 **Ctrl+D** 以重新启动系统。 |
| 2. 检查系统是否已恢复。 | a. 验证系统已重新启动并显示 GUI 登录屏幕。<br>b. 在 GUI 中以 **root** 身份登录。 |
