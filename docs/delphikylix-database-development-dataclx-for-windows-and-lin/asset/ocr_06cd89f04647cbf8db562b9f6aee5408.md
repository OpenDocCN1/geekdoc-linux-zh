Let’s take a look at the cbUseCallbackClick event handler. If you check the Use Callback check box, the code disables the monitor. It then calls SetTraceCallbackEvent to set up a callback procedure to monitor database messages.

When you uncheck the Use Callback check box, the code sets the monitor to active. This re-establishes the TSQLMonitor component as the feedback mechanism for database messages.

Another point of interest is the MonitorTrace method. If the Log Trace check box is checked, we capture the message immediately and send it to the list box. Because we’ve handled the message, there’s no need to buffer it in the monitor’s internal list. For that reason, the code sets LogTrace to False.
