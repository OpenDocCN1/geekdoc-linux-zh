## Customization

## Adding and enabling modules and custom options

Since most websites use a server-side language, such as a WordPress installation or code to handle the contact from HTML, .htaccess gives us a look at how to implement it.

Extending web servers is easier than others. From a simple standpoint, both Apache and Lightty make it very easy to create custom modules and enable them easily. For example, one custom module that is not enabled by default is available in Nginx, but with some simple commands to enable and disable it is part of the program. With Nginx, adding and configuring modules runs beyond notice usage.

OpenLightspeed is not as straightforward as Apache or Lightty, either both can be at least with simple commands for more intermediate users.

Aside from adding modules to a server, there will come a time when we want to edit the server configuration files or add folders to make custom configurations, such as .htaccess configurations are very easy since we can add an .htaccess. Apache and Tomcat make it easy to find any folder and make custom rules, browser cache and so on. Meanwhile, OpenLightspeed has to migrate our Apache into its own system and use the same rules, which transition from an Apache server.

Lightty has its way of creating custom files in its lightpeed.conf. With Nginx and Lightty, custom rules must take in configuration files.
