# GLANCES

Glances is a Python script that smartly displays a lot of information about your current session inside a terminal window. You can use the tool to monitor remote machines and use the built-in web interface monitors using a web browser. https://nicolargo.github.io/glances

# PORTAINER

Using Docker via the terminal isn't all cumbersome and the tool is well documented. To make your life easier however you can use Portainer, which is an open-source, web-based frontend that supports all the features exposed by API. You can use it to manage containers, networks, and volumes and it can

manage a standalone Docker environment, or a Docker Swarm. From your dashboard you can create containers and manage all available ones. You can obtain real-time stats as CPU and memory usage and various other metrics while running containers and even create a container's console, all from within the browser. Portainer is available to manage a Docker container with a single command. You can then use one of the predefined templates. The tool can be used by millions users and has useful user management functions. When you use example here to define the levels of access any other users have to Portainer, and the aspects of Docker with Portainer. https://portainer.io

# FIREJAIL

Firejail secures by isolating processes and programs inside sandboxed environments. By locking the web browser or any tool that can be compromised, Firejail prevents a compromised program from accessing critical areas of the system https://firejail.sourceforge.com

# BOOTCUSTOM

One of the largest causes of boot time is that your system runs unnecessary services and services during startup. To analyze them, we can get a best picture of what's happening during your boot. Bootchar is a simple utility that enhances your Linux boot process and help manage the loading of different times. It is now merged with systemd. You can use terminal and system-analyze time to find the breakdown of the boot duration. Similarly, system-analyze

blame list all units running by the time they took start. To generate an image of boot process use systemd-analyze boot. From this image you can see all the active processes and any you do not need. If you occupy CUPS from the start. Furthermore, it also helps you spot processes that take control of all resources and the other processes to boot, see www.bootchart.com
