ssh enables you to log in via public key. By generating a key pair on the machine you log in, and copying the public part of that pair to the server, you are no longer required to use a password. You already have a key pair in your ~/.ssh directory (your local machine), and then look in there for files named id_rsa (the private key) and id_rsa.pub (the public key). You don't need to overwrite these if they are already there, but if you created a new one, protect them

cloud providers allow you to log in from their management interfaces, but it's easier to use the following connection string, all is done, just change the username to what you're logging in:

```
$ ssh-copy-identity
```

Use this command to install your user and key pair, copying the details to the ~/.ssh/authorized_keys file on the server. If it doesn't have a directory, it will create one for you. It may also prompt you for your password.

There's no need to try and manage SSH IDs. For multiple servers keys are stored in the same file. It's not necessary to create one for each, but it might be better to set up a unique key pair for each machine you are logging in from.
