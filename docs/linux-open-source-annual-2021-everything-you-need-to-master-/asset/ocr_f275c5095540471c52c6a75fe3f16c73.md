# Pursue the need for speed

So, you'll be running sombrero with the default settings, which are not -std=c99 -O3. Those are fine enough for testing, but you'll get the highest possible performance for your system. To get this, you need to give the compiler more work. If you want the best performance, you should do it by making a Makefile file, which defines variables to be read by the compiler. If you edit your text editor,

```
#Compiler
CC=mpic
CFLAGS=-std=c99 -O3
DFLAGS=-
```

Since we installed gcc, you might expect to use cc=gcc; however, mpic is a wrapper around gcc, which ensures that MPI provides more options and that all the correct libraries are linked.

To start, with the -g flag enables debugging. If you're debugging problems with performance slow, remove this flag, and run make again. Re-running sombrero, then on each local machine or across the cluster, should take a short time to complete the program. The next step is to tell the compiler what nodes you want to run it on.

GCC only allows itself to use features that are on a generic x86-64 CPU – this limits it to features released in 2003. To use newer features, if you want to run on a different machine than the one you're compiling on, use make with native architecture. Re-compile with make and re-test, and you will increase performance.

GCC has hundreds of options you can try to extract extra performance from your hardware, you can find the full list at: gcc.gnu.org/devel/Options.html.

This might seem like, but it's an important part of writing and running your programs. The compilers are designed for a wide range of software and hardware, so sometimes needs help to know how to use them. On a typical day the performance difference means that compiling every piece of software from scratch and testing every option might spend more time than it takes.

But when you're running on hardware of different kinds for weeks or months at a time, you want to make sure you're not wasting even five percent of the available power.

Supercomputers rely heavily on their high-speed network to connect distributed computers across nodes; it's important to know how they scale. There are two ways: scaling the problem size grows with the number of nodes used, and scaling tests where the same problem is solved in smaller and smaller clusters.

If you have enough clusters, you can run a scaling test. First use a set of nodes, called nodeslist.txt, using multiples of 2 and 3.
