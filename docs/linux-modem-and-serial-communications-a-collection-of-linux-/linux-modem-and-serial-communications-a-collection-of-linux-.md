调制解调器是一种通过电话线传输数字信号的设备。如果电话线全是数字信号，你就不需要调制解调器了。它允许你的电脑与外部世界连接并通信。PC 的调制解调器有两种基本类型：外部和内部。外部位于电脑外部，内部位于电脑内部。外部调制解调器插入电脑上称为“串口”的接口。内部调制解调器是一块插入电脑内部的卡。

串口不应与“通用串行总线”（`USB`）混淆，后者使用特殊的接口，未来可能用于调制解调器。有关调制解调器和串口的细节请参见“调制解调器与串口基础”。

使用直连线或调制线将调制解调器连接到 PC 上空闲的串口。确保你知道串口名称：`COM1` 是 `ttyS0`，`COM2` 是 `ttyS1`。你可能需要检查 BIOS 来确定这一点。插上电源线为调制解调器供电。进一步说明请参见“所有调制解调器”。

内部调制解调器（在 ISA 总线上）

（PCI 总线请参阅 PCI 调制解调器）如果调制解调器说它只能在 MS Windows 下工作，那么你就没戏了。如果你已经有两个串口，请将此设置为第三个串口（`ttyS2 = COM`）。找到一个可以使用的空闲 IRQ 编号。通常，一个空闲的编号是用于第二个并行端口或声卡的 `IRQ5`（你可能没有这些）。然后将内部调制解调器上的跳线帽（或类似设置）设置为空闲的 IRQ 和 I/O 地址 `3E8` (`ttyS2`)。

# 2 调制解调器将数字转换为模拟信号（反之亦然）

大多数电话主线是数字信号的，但通往你家（或公司）的线路通常是模拟的，这意味着它们的设计是为了传输电压波，这种电压波与你口中发出的声波特性相同。电压波被称为“模拟信号”。在示波器上查看，它看起来像频率和幅度变化的正弦波。数字信号则像方波。例如，`3 v`（伏特）可能代表 1 位，而 `0 v` 可能代表 0 位。对于大多数串口（外部调制解调器使用），`+12 v` 是 0 位，`-12 v` 是 1 位（有些是 `+` 或 `- 5 v`）。

# 调制解调器 调制解调器指南（适用于 Linux）

要通过电话线从你的电脑发送数据，调制解调器接收电脑的数字信号并将其转换为“模拟信号”。它通过创建一个模拟正弦波并对其进行“调制（Modulating）来实现。由于结果仍然代表数字数据，它也可以被称为数字信号而非模拟信号。它看起来像模拟信号，几乎每个人都称其为模拟信号。在电话线的另一端，另一个调制解调器对该信号进行“解调（DEModulating）”，从而恢复出纯数字信号。将上述两个词的“mod”和“dem”部分结合起来就得到了“modem”（如果你去掉了两个 d 中的一个）。因此，“modem”就是一个调制器-解调器（MODulator-DEModulator）。关于什么是调制，请参见“调制细节”章节。

## 2.2 什么是串口？

## 引言

由于调制解调器与电脑之间有一个串口，因此有理解串口以及调制解调器是很有的。串口是一个 I/O（输入/输出）设备。大多数 PC 都有两个串口。每个串口在电脑后面有一个 9 针连接器。电脑程序可以将数据（字节）发送到发送引脚（输出），从接收引脚（输入）接收字节。其他引脚用于控制和接地。

串口不仅仅是一个连接器。它将数据从并行转换为串行并改变数据的电气表示。在电脑内部，数据位是并行流动的（同时使用许多电线）。串行流是单根电线上的位流（例如串口连接器的发送或接收引脚）。为了让串口创建这样的流，它必须在发送引脚上将数据从并行（电脑内部）转换为串行（反之亦然）。

串口的大部分元件位于一个名为 `UART` 的电脑芯片（或芯片区域）中。有关 `UART` 的更多详细信息，请参见“什么是 UART？它们如何影响性能？”章节。但你可能想先看这一节，以便你希望能够理解 `UART` 是如何融入整体方案之中的。



旧的 `PC` 使用 `25 针`连接器，但实际上只使用了约 `9`个引脚，因此现在大多数连接器只有 `9 针`。`9`个引脚中的每一个都连接到一根导线上。除了传输和接收数据的两根线外，另一个引脚（线）是信号地。任何导线上的电压都是相对于此地测量的。仍然有更多导线仅用于控制（信号），而不用于发送字节。所有这些信号本都可以在单根导线上发送，但相反，每种类型的信号都有一条独立的专用导线。这些（或全部）导线被称为“调制解调器”。

## 内部调制解调器

对于内部调制解调器，没有 `9 针`连接器，但其行为与上述电线完全相同。导线中的 `12 伏`信号提供调制解调器控制线的状态，内部调制解调器可能使用其内存（寄存器）中的状态位来确定这个不存在的“线”的状态。内部调制解调器的串口对电脑来说就像真实的串口一样。它甚至允许设置普通串口上设置的速度限制，如 `115200 bits/sec`。遗憾的是，许多内部调制解调器的工作原理并非如此，而是使用 `MS Windows`软件协助工作，且在 `Linux`下无法工作。参见“避免：`winmodems`”。

## 2.2 什么是串口？

## 引言

由于调制解调器与电脑之间有一个串口，因此有理解串口以及调制解调器是很有的。串口是一个`I/O`（输入/输出）设备。大多数`PC`都有两个串口。每个串口在电脑后面有一个`9`针连接器。电脑程序可以将数据（字节）发送到发送引脚（输出），从接收引脚（输入）接收字节。其他引脚用于控制和接地。

串口不仅仅是一个连接器。它将数据从并行转换为串行并改变数据的电气表示。在电脑内部，数据位是并行流动的（同时使用许多电线）。串行流是单根电线上的位流（例如串口连接器的发送或接收引脚）。为了让串口创建这样的流，它必须在发送引脚上将数据从并行（电脑内部）转换为串行（反之亦然）。

串口的大部分元件位于一个名为`UART`的电脑芯片（或芯片区域）中。有关`UART`的更多详细信息，请参见“什么是`UART`？它们如何影响性能？”章节。但你可能想先看这一节，以便你希望能够理解`UART`是如何融入整体方案之中的。

旧的`PC`使用`25`针连接器，但实际上只使用了约`9`个引脚，因此现在大多数连接器只有`9`针。`9`个引脚中的每一个都连接到一根导线上。除了传输和接收数据的两根线外，另一个引脚（线）是信号地。任何导线上的电压都是相对于此地测量的。仍然有更多导线仅用于控制（信号），而不用于发送字节。所有这些信号本都可以在单根导线上发送，但相反，每种类型的信号都有一条独立的专用导线。有些（或全部）这些导线被称为“调制解调器”。

在继续学习串口基础之前，需要了解一些由调制解调器完成的事情：数据压缩。

这里将适用于由调制解器本身进行压缩的情况，因为为了让调制解器在 `Linux` 下工作，必须这样做。

为了通过电话线更快地发送数据，可以使用自定义的编码方案进行压缩（编码），该方案本身取决于数据内容。编码后的数据比原始数据小（字节数更少），可以在更短的时间内通过互联网发送。这个过程被称为“数据压缩”。

如果你从互联网下载文件，它们很可能已经过压缩，调制解器对其进行进一步压缩是不可行的。你的调制解器可能会提示通过你的数据已经过压缩，并停止尝试再次压缩。如果你接收到由另一个调制解器压缩的数据，你的调制解器将将其解压，产生的字节比通过电话线发送的更多。因此，从你的调制解器到电脑的数据流将高于通过电话线传输给你的数据流。这种流的比例被称为压缩率。压缩率可以达到 4，但并不常见。

与数据压缩类似，调制解器可以设置为进行错误纠正。虽然会有开销成本降低字节/秒的传输速率，但错误纠正会剥离起始位和停止位，这实际上增加了数据字节/秒的传输速率。

对于串口与外部世界的接口，每个 8 位字节都会额外增加 2 位：一个起始位和一个停止位。在没有错误纠正的情况下，这些额外的起始和停止位通常会直接通过调制解器并通过电话线。当启用错误纠正时，这些额外位会被剥离，8 位字节被放入数据包中。这种方式更有效，尽管为了数据包头和纠正目的又增加了一些字节，但它能带来更高的字节/秒传输率。

数据（代表字母、图片等的字节）从你的电脑流向调制解器，然后传到电话线（反之亦然）。流速率（如 56k (56000) bits/sec）被（错误地）称为“速度”。但几乎每个人都说“速度”而不是“流速率”。如果没有数据压缩，从电脑到调制解器的流速率将与电话线上的流速率相同。

- 电话线本身的速度（`DCE` 速度）：调制解器到调制解器

流控制意味着在不丢失数据的情况下停止流。

### 流控制解释

例如，考虑使用 `ASCII` 控制字符 `DC1`（开始）和 `DC3`（停止）来实现此目的。由于编码后的数据比原始数据小（字节数更少），可以在更短的时间内通过互联网发送。这种方法更有效。软件流控制不仅反应较慢，而且除非采取特殊措施，否则也不允许通过调制解器传输二进制数据。由于二进制数据可能包含 `DC1` 和 `DC3`，必须采取特殊措施来区分属于二进制代码一部分的 `DC3`。对于 `DC1` 也是如此。要让软件流控制对二进制数据生效，需要调制解器（硬件）和软件的支持。

这是在两个调制调器之间通过电话线发送的数据的流控制。在实践中，只有在你设置了纠错时，它才会存在。实际上，即使没有开启纠错，也可以在调制调器之间启用流控制，但可能会干扰二进制数据的发送，因此并不经常使用。

尽管已经解释了许多内容，包括流控制、一对 16 字节串口（硬件中）以及调制调器内部的一对较大的缓冲区，但仍然有一对缓冲区。这些是主内存中的大缓冲区（可能是 8k），也称为串口缓冲区。当应用程序向串口（以及调制调器）发送字节时，这些字节首先被存储在主内存的发送串口缓冲区中。这对组合包含了这个发送缓冲区和一个用于字节流反向方向的接收缓冲区。

串口设备从这个发送缓冲区中一个字节一个地驱动出 16 字节，并将它们放入串口硬件中的 16 字节发送缓冲区中进行传输。在那个发送缓冲区中，没有办法阻止它们被传输。随后它们会被传输到调制调器，调制调器也有一个适中尺寸（例如 1k）的缓冲区。当设备驱动程序（根据流控制的指令）停止计算机输出字节流时，它实际上停止的是主内存中大发送缓冲区的输出字节流。即使在这种情况发生且调制调器已停止后，应用程序仍可能继续向 8k 发送缓冲区发送字节，直到它填满。当它满时，应用程序就无法向其发送任何字节（`C` 程序中的 `write` 语句会阻塞），应用程序将临时停止运行并等待某些缓冲区可用。这种流的“停止”最终是为了停止发送字节的程序。尽管这个程序停止了，计算机并不一定在停止计算。在等待流控停止时，它可能会切换到运行其他进程。如果存在另一种方案，即应用程序本身在等待“写入”时可以做其他事情，那么上面的描述就有点过于简化了。

## 2.10 复杂流控制示例

在许多情况下，存在一条涉及多个链路的发送路径，每条链路都有自己的流控制。例如，我在连接到 `PC` 的文本终端上打字。`PC` 内部有一个用于访问 `BBS` 的调制调器。为此为此，我使用名为“`minicom`”的应用程序，它处理 2 个串口：一个连接到调制调器，另一个连接到文本终端。我在文本终端上输入的内容会通过第一个串口进入 `minicom`，然后从 `minicom` 通过第二个串口进入调制调器，最后通过电话线到达 `BBS`。文本终端对屏幕上显示字节的速度有限制，并会不时发出一个流控制“停止”信号来减慢流速。当发出这样的“停止”信号时会发生什么？让我们考虑一种情况：该“停止”信号足够长，足以到达 `BBS` 并停止 `BBS` 上正在发送字节的程序。

让我们追踪这个“停止”信号在某些链路上上传（可能是“硬件”的），在另一些链上传（“软件”的）。首先，假设我正在从 `BBS` “捕获”一个长文件，该文件同时发送到我的文本终端和硬盘上的一个文件。字节来的速度快于终端的处理速度，因此它通过其串口发送一个“停止”信号到我 `PC` 上的第一个串口。设备驱动程序检测到这一点，并停止从主内存中的 8k 缓冲区向终端发送字节。现在，`minicom` 持续向这个 8k 缓冲区发送终端所需的字节。

当这个 8k 发送缓冲区（在第一个串口上）满额时，`minicom` 必须停止向其写入。`minicom` 停止并等待。但这导致导致 `minicom` 从连接到调制调器的第 2 个串口上的 8k 接收缓冲区读取。从调制调器，调制调器缓冲区不断填充，直到这个 8k 缓冲区填满并向调制调器发送另一个“停止”信号。调制调器（假设已启用纠错）向 `BBS` 端的另一个调制调器发送“停止信号”。该调制调器停止从它的缓冲区发送字节，当它的缓冲区变满时，会向 `BBS` 的串口发送另一个停止信号。在 `BBS` 上，8k（或任何大小的）缓冲区填满了，`BBS` 上的程序无法向其写入并临时停止。

因此，来自文本终端的停止信号停止了 `BBS` 计算机上的程序。一连不可思议的事件链！（`minicom`）。请注意，停止信号经过了 4 个串口、2 个调制调器和一个连接到终端的应用程序。每个串口都有 2 个缓冲区（在流向的一个方向上）：8k 缓冲区和硬件 16 字节缓冲区。应用程序可能像其 `C` 代码中指定的样在主内存中有一个缓冲区。这总共数据流经了 11 个缓冲区。注意，微小的串口硬件缓冲区不直接参与流控制。



如果终端速度限制是从 BBS 到终端流的瓶颈，那么它的流控制“停止”实际上是停止了如上所述从 BBS 发送的程序。但你可能会问，一个“停止”怎么能持续这么久，以至于让 11 个缓冲区（其中一些是很大的）被填满呢？如果在终端发送“停止”时，所有缓冲区都接近其极限，这种情况确实会发生。

但如果你对某些链路运行模拟，你会发现它通常比这复杂得多。在某一时刻，某些链路正在流动，而另一些链路已停止（由于流控制）。来自终端的“停止”几乎如上述描述的那样回传到 BBS。可能需要终端发出几次“停止”才能导致 BBS 端的“停止”。要理解发生了什么，你真的需要观察一个模拟，可以使用简单的表格、每个缓冲区和上层结构来完成。

人们真的需要理解这些吗？嗯，理解这些解释了为什么从 BBS 捕获的文本会丢失。情况与上述示例相同，但由于流控制导致调制调器处溢出，本应到达硬盘的文本从未到达那里。

发送调制调器的命令是由应用程序通过用于发送数据的相同导体发送的。这些命令都是 ASCII 字符串。例如，`AT&K3` 用于在计算机和调制调器之间启用流控制（`RTS/CTS`）；以及 `ATDT539341` 用于拨号 `539341`。所有命令前都有 `AT`。某些命令如启用流控制有助于配置调制调器。其他命令如拨号号码会执行某些操作。大约有一百种不同的可能命令。当你的应用程序启动运行时，它首先向调制调器发送一个“初始化”命令字符串来对其配置。所有命令都在调制调器拨号（或接听）之前在普通数据线上发送。

如果你只想为 `MS Windows/Dos` 使用调制解调器，那么你可以安装任何调制调器，它可以正常工作。对于 `Linux` PC，情况通常没那么简单，除非你使用外部调制调器。所有外部调制调器都应该工作正常（即使它们标记为“即插即用”）。但大多数内部调制调器都是即插即用（`PnP`）并带有 `PnP` 串口。你可能需要使用 `Linux` 的 `isapnp` 程序来配置这些 `PnP` 串口。更多信息请参见 `Plug-and-Play-HOWTO`。

* 配置调制调器本身：由通信程序完成
* 配置调制调器的串口：仅由通信程序完成

上述的大部分配置（但不一定是大部分工作量）是由你配合调制调器一起使用的通信程序（例如 `minicom` 或 `seyon`）或由你的 Web 浏览器的 `PPP` 部分完成。如果你使用调制解调器进行拨号，那么你用于向外部用户显示登录提示的 `getty` 程序将帮助配置。因此，要配置调制解调器（以及大部分串口），你需要配置通信程序（或 `PPP` 或 `getty`）。这些程序的文档和/或 `PPP-HOWTO` 会很有帮助。

但请注意，并不是所有的串口配置都是由通信程序（或 `getty`）完成的。剩余配置描述起来很简单（但有时很难实现）。它主要涉及设置端口的 I/O 地址和其 IRQ 号。事实上，即插即用可以在不进行任何操作的情况下设置这些内容。`Linux`（截至 1999 年初）对即插即用的支持并不很好。这可能会给你带来一个困难的问题。

### 3.2 配置串口的 IRQ 和 IO-地址

在启动（并配置）你的通信程序之前，你必须完成通信程序无法完成的配置。简单来说，这只包括识别调制解调器所处的串口。是 `ttyS2` (=COM3) 还是 `ttyS1` (=COM2) 等？如果你确定知道答案（且没有 IRQ 冲突），那么就什么都不需要做，你可以启动通信程序了。

## 调制解调器-HOWTO（适用于 Linux）

否则，你必须建立串口识别并为其分配一个 IRQ 号。这是通过将两个值（一个 IRQ 号和一个 I/O 地址）放入两个地方来实现的：

1. 串口硬件本身的内存寄存器
2. 设备驱动程序（通常通过启动时运行 `seterial` 来实现）

上述两项都应该由即插即用操作系统（`OS`）完成。对于第 1 项，以前在调制调器卡中设置这些数字（对于外部调制调器而言即为串口）是由用户完成的。现在，这应该在启动时由即插即用（`PnP`）完成。

对于第 2 项，如果你接受默认设置，则不需要使用 `seterial`。但如果你使用 `seterial`，那么你告诉它的 IRQ 和 IO 地址必须与串口硬件内部的设置（或通过 `PnP` 设置的设置）完全相同。我们可能把这一切简称为 `io-irq` 配置。在 `Windows` 世界中，I/O 地址和 IRQ 被称为“资源”（resources），因此我们正在配置某些资源。

即插即用的设计是为了自动化这种 `io-irq` 配置，但对于 `Linux` 来说，它让生活变得更加复杂。`Linux` 标准内核不支持即插即用。如果你使用 `Linux` 内核补丁将其转换为即插即用操作系统，那么上述所有内容都应该由操作系统自动处理。但当你想要使用这种自动化配置串口以外的设备时，可能会发现你仍然必须手动配置驱动程序，因为许多 `Linux` 驱动程序的编写时并没有支持 `PnP` 操作系统。如果你使用 `isapntools` 或 BIOS 配置即插即用，这只会将两个值放入调制调器卡的串口部分，你可能仍然需要设置 `serial`。截至 1999 年，这些内容中没有一个是容易的，文档也不够详尽。参见 `Plug-and-Play-HOWTO`。

虽然如何使用 `PnP` 操作系统或 `isapntools` 进行 `io-irq` 配置的说明可以随软件一起提供，但如果你想让 `PnP` BIOS 来完成配置，情况并非如此。BIOS 通常有一个用于设置前两个串口的 CMOS 菜单。通常可选择的很少。除非手册中另有说明，否则 BIOS 应该使用标准的 I/O 地址和 IRQ。参见 `Serial Port Device Names & Numbers`

无论你喜不喜欢，当你启动电脑时，`PnP` BIOS 会开始对硬件设备进行 `PnP` (`io-irq`) 配置。它可能部分完成工作并将剩余交给 `PnP` 操作系统（而你并没有），或者如果你没有 `PnP` 操作系统，它可能会完全配置所有 `PnP` 设备，但不会配置设备驱动。这是你想要的，但并不总是容易准确判断 `PnP` BIOS 到底做了什么。

如果你告诉 BIOS 你没有 `PnP` 操作系统，`PnP` BIOS 应该对所有 `PnP` 串口进行配置——而不只是前两个。如果你在同一台 PC 上安装了 `MS Windows`，BIOS 应该已经将 `MS Windows` 使用的 `io-irq` 配置保存在非易失性内存中，并为 `Linux` 使用相同的配置。在这种情况下，如果你能找到 `MS Windows` 如何设置其 `io-irq` 的，那么在 `Linux` 下它也应该是相同的。

如果你添加了新的 `PnP` 设备，BIOS 应该更改其 `PnP` 配置以适应它。它甚至可以更改现有设备的 `io-irq` 以避免任何冲突。为了这一目的，它会维护一个非 `PnP` 设备的列表，前提是你已经告诉了 BIOS 这些非 `PnP` 设备已经过过 `io-irq` 配置。告诉 BIOS 的一种方法是在 `MS Windows` 下运行 `ICU` 程序。

但你如何发现 BIOS 做了什么，以便根据这些信息设置设备驱动呢？如果 BIOS 的 CMOS 菜单能提供这些信息就太好了，但它们可能没有（`COM1` 和 `COM2` 除外）。因此，发现这些可能非常麻烦。参见 `What is set in my serial port-hardware?`

如果你使用外部调制调器并接入 `ttyS1` 连接器，那么（通常）没有 `io-irq` 配置需要做了，`ttyS1` 可能已经配置好了。你的 CMOS 设置可能需要为 `COM1` 和 `COM2` 执行此操作。

通常你不需要配置前两个串口，因为内置在 `Linux` 发行版中的已经处理好了，你无需操作。当你想要添加第三个端口时，一切都不同了。除非你使用即插即用操作系统，否则你必须自己完成。要做到这一点（如前所述），你需要运行 `seterial`：为 `ttyS2` 分配 I/O 地址和 IRQ 号。

## 设置 I/O 地址和 IRQ 的方法

这里是对上述讨论内容（以及更多）的总结。调制调器的配置完全通过通信程序向其发送命令来完成（例如波特率和硬件控制）。关于 `PnP` 的更多细节请参见 `Plug-and-Play-HOWTO`。你通过以下方式配置串口的 `io-irq`：

1. 通过执行以下操作在端口硬件中设置 IRQ 号和 I/O 地址 (`io-irq`)：
    * 对于现有 `io-irq` 正常的外部调制调器，什么都不做
    * 为外部调制调器使用 `PnP` 设置菜单（通常仅用于 `ttyS0` (`Com1`) 和 `ttyS1` (`Com2`))
    * 如果你同时拥有 `PnP` 内部调制调器和 `PnP` `Linux` 操作系统，则什么都不做
    * 在调制调器、旧串口卡或旧主板上设置跳线（如果存在）
    * 为非 PCI `PnP` 内部调制调器使用 `isapnp`
    * 让 `PnP` BIOS 自动配置 `PnP` 内部调制调器（但可能很难确定具体的配置）
    * 使用调制调器自带的设置程序（在 `MS Windows` 下运行）禁用 `PnP`
2. `seterial`：为 `ttyS2` 分配 I/O 地址和 IRQ 号。除非你总共只有 1 或 2 个串口，或者你使用 `PnP` 操作系统，否则你可能不需要运行它。

各项设置并不一致。换句话说，这意味着驱动程序获取的串口信息错误的。如果驱动程序具有错误的 I/O 地址，它将尝试将数据发送到不存在的串口——更糟糕的是，发送到某个并非串口的实际设备。如果它具有错误的 IRQ（中断请求），它将无法获取来自串口的中断服务请求，导致串口缓冲区可能溢出，并且响应非常缓慢（因为回退到了非常慢的“轮询”方法而不是中断）。如果 UART 型号错误，也可能出现问题。

你如何确保驱动程序拥有正确的信息？嗯，如果一切正常，就不需要检查这一项。但在其他情况下，很容易看出驱动程序的想法。一种方法是直接输入 `serial-g /dev/ttyS*`。在启动时，控制台上的一个消息会显示此内容。你可以查看 `/proc/ioports`；它只显示串口“设置”的相同 I/O 地址，但不一定是硬件中的实际方式。查看当前运行进程（已打开设备的进程）所使用的 IRQ，查看 `/proc/interrupts`。它还显示了已发出的中断次数（通常是数千次）。上述测试均不能显示设备中实际设置的内容。但如果一切运行正常，设备设置可能与硬件中的设置是一的。

但你如何发现 I/O 地址和 IRQ 实际上设置在设备硬件中？如果调制解器是 PCI 的，查看 `/proc/pei`。如果是 ISA 的，这并不总是容易的。以前人们通过检查调制解器卡、串口卡或主板上跳线帽设置来这样做。一种粗略的方法是尝试使用 `serserial` 配合 “autoconfig” 选项进行探测。你需要猜出要探测的地址。参见 `Setserial`。

对于 ISA 总线上的即插即用（PnP）模式（或 PnP 串口），人们可以尝试 `pnpdummy` 程序（`isapntools` 的一部分）。`pnpdummy` 会“找到”端口并显示各种配置选项，但不会告诉你真实的 I/O 地址和 IRQ。它“尝试”的地址并不是设备的 I/O 地址，而是仅用于 PnP 目的的特殊读端口。在使用 `pnpdummy` 获取一些信息后，这些信息可以用于 `isapnp` 命令的“PEEK”关键字来查找 I/O 和 IRQ。`isapnp-configuration` 文件中的命令可能像这样（对于供应商 GVC1601，序列号为 1）：`(CONFIGURE GVC1601/2 IO 0 (PEEK))`。你需要的不仅仅此命令，而且它并不是万无一失的（参见 `isapnp` 的手册页）。我知道以上内容并不充分，但如果你成功做到了，你可以将其写下来并在此 HOWTO 的最新版本查看。

另一种方法是查看它在 MS-Windows 下是如何配置的（如果你在同一台机器上安装了它）。MS-Windows 下的配置可能与 Linux 不同，但如果你在启动时让 PnP 操作系统进行配置（并已告知 BIOS），它们很可能是相同的。

### 配置流控 (RTS/CTS)

请查看流控的解释。如果可能，你应该始终使用流控。你的通信程序或 `getty` 应该有一个设置它的选项（如果你运气好，它可能是默认开启的）。它需要在调制解器内部（通过初始化字符串或默认值）以及设备驱动程序中设置。如果上述任何操作都没有完全启用流控，那么你必须手动完成。对于调制解器，确保它是通过初始化字符串或默认设置的。如果你需要让设备驱动程序执行，最好在启动时将以下内容放入每个串口的此类文件中（例如 `ttyS2`）：

```bash
stty crcts < /dev/ttyS2
```

如果你想查看流控是否已启用，请执行以下操作：在 `Minicom`（或类似程序）输入 `AT&V` 查看调制解器的配置，并寻找 `&K3`。然后通过输入 `stty -a < /dev/ttyS2` 查看设备驱动程序是否知道它。

### AT 命令

当位于调制解器的串口进行配置的同时，调制解器本身也在配置。调制解器是通过向用于发送数据的线路发送 AT 命令（或类似命令）来配置的。大多数调制解器使用 AT 命令集。这些是晦涩且短小的 ASCII 命令，所有命令字符串都以字母 `AT` 开头。例如：`ATZ&K3`。这里有两个命令：

- `Z0`：调回用户配置 `0` 并重置（挂断）
- `&F0`：调回出厂 `0`
- `&W0`：将当前配置保存到用户配置

遗憾的是，AT 命令集有很多不同的变体，因此适用于一个调制解器的命令可能不适用于另一个。因此，无法保证本节中提供的 AT 命令在你的调制解器上有效。另一点是让调制解器响应 AT 命令字符串必须在字符串末尾发送一个返回符。有时 AT 前面有一个返回符，有时字符串中会添加符号（例如），这仅告诉通信程序暂停极极短的时间。

如果你有调制解器的说明书，可以快速从中查找 AT 命令集。否则，你可以尝试在互联网上查找。

本节给出的示例来自 Hayes 命令集。所有命令字符串必须以两个字母 `AT` 开头。当调制解器上电时，它会自动使用非易失性内存中存储的配置进行自配置。如果此配置是满意的，则不需要操作。

如果不满意，可以通过发送一组被称为“初始化字符串”（`init string`）的来更改或重新配置调制解器。大多数时候，当你启动通信程序时，会自动发送初始化字符串（取决于你如何配置或你编写了什么脚本，如果使用 `Kermit`）。你通常可以编辑初始化字符串并将其更改为任何内容。有时通信程序会让你选择模型并使用它认为对调制解器最好的初始化字符串。

因此，调制解器内部存储了一个默认字符串（称为配置），以及由通信程序发送的另一个（初始化字符串）。调制解器的状态将与默认集相似，只是被初始化字符串中包含的命令修改了。如果初始化字符串为空，它当然会使用默认配置。

实际上，在调制解器的非易失性内存中存储了多个“默认”配置（或配置）（当你关闭它时仍然存在）。在我的调制解器中，有两个配置（`0` 和 `1`，均无法更改）以及两个用户可以设置并存储的用户定义配置（`0` 和 `1`）。你的调制解器可能有更多。在开电时使用哪一个用户配置取决于配置中存储的另一个项目。如果给出命令 `Y00`，则未来开电时将使用配置 `0`。如果是 `1` 而不是 `0`，则开电时将使用配置 `1`。

还有命令可以调回（现在使用）存储的 4 个配置中的任何一个。可以将此类命令放在初始化字符串中。当然，如果它调回的是与开电时加载的相同配置，则没有任何变化（除非初始化字符串是在调制解器使用一段时间且软件等更改了配置后发送的）。使用某种初始化字符串是一个好主意，以便可以重置。

### 其他调制解器命令

未来的 Modem-HOWTO 可能包含更多 AT 命令，但本节的其余部分是旧 Serial-HOWTO 中的。所有字符串必须以 `AT` 开始。这里是一些应该在字符串中的 Hayes 代码（如果它们没有使用出厂默认或保存的配置设置）：

- `E1` 命令回显开启
- `Q0` 报告结果
- `V1` 详细模式开启
- `SO=0` 从不回答 (`ugetty` 使用 `WAITFOR` 选项实现此功能)

如果你的调制解调器不支持存储配置，你可以通过配置文件（或类似文件）中的 `INIT` 字符串来设置这些。带有 DIP 开关的老旧调制解调器可能会影响寄存器设置。请确保这些也设置正确。

注意：为了让他的 `USR Courier V.34` 调制解调器在 `DTR` 落时正确重置，`Greg Hankins` 必须设置 `D2` 和 `S13=1`（这设置了寄存器 `S13` 的第 0 位）。这已证实在 `USR Sportster V.34` 调制解调器上同样有效。

注意：某些 `Supra` 调制解调器处理 `DCD` 的方式与其他解调器不同。如果你使用的是 `Supra`，请设置 `C0` 而不是 `C1`。你必须设置 `D2` 以正确处理 `DTR`。

### 4.1 外部 vs 内部

`PC` 调制解调器可以是内部的或外部的。内部的位于 `PC` 内部（你必须拆除螺丝才能安装），外部的只需插入 `PC` 上的串口连接器。内部调制解调器价格更便宜，不容易发生溢出，通常耗电更少，且不占用桌面空间。外部调制解调器更容易安装，需要的配置较少，并且带有指示灯，可以提示你正在发生什么。外部调制解调器很容易移动到另一台电脑。大多数外部调制解调器在不使用没有关闭电源开关，即使在关闭时也可能消耗少量电力（除非从墙座上拔掉电源）。它们每消耗一瓦每年大约花费你 1 美元。外部设备的另一个缺点是，你被迫使用现有的串口，而该串口可能不支持超过 115,200 k 的速度（尽管截至 1998 年底大多数内部调制解调器也不支持——但有些支持）。如果新的内部调制解调器带有 `16650 UART`，它将减轻 `CPU` 的负载（但截至 1998 年几乎没有这样的）。

内部调制解调器为 `Linux` 带来了一个特殊问题，但只要你避开那些仅支持 `MS Windows` 的大部分型号，它们的工作原理和外部一样良好，并且只要你花时间（有时是很长的时间）来正确配置它们。某些仅在 `MS Windows` 下运行的调制解调器遗憾的是并没有被这样标注。如果你买新的，请确保如果它在 `Linux` 下无法工作，你可以退款。

虽然大多数新调制解调器都是即插即用的，但你有多种方法处理它们：

- 使用 `isapnp` 程序
- 让 `PnP BIOS` 进行配置
- 补补内核以创建一个 `PnP Linux`

上述每种方法都有缺点。`Isapnp` 的文档难以理解，尽管阅读《`Plug-and-Play-HOWTO`》（目前尚完整）有助于理解它。如果你想让 `PnP BIOS` 进行配置，你只需要确保它知道你没有使用 `PnP` 操作系统。你可能会在确定它如何设置时遇到困难。参见《我的串口硬件中有什么》。补补内核也可能很复杂。有很多设备驱动不与补丁配合（因此你需要对它们进行配置）。

有些 `Linux` 用户说买一个外部调制解调器并插上要简单得多。但由于现在的新外设都是 `PnP` 的，你最终可能需要处理它，那么为什么不在现在处理呢？将来在 `Linux` 下处理 `PnP` 将变得更容易，但尽管有句古话说“先驱者不获报酬”，今天仍需要先驱来开辟道路路。

许多外部调制解调器被标记为“即插即用”（`PnP`），它们作为非 `PnP` 调制解调器应该都能正常工作。由于你通常将调制解调器插入具有独立 `IRQ` 号和 `I/O` 地址的串口，调制解调器不需要 `PnP` 功能来设置这些项。然而，串口本身可能需要配置（`IRQ` 号和 `I/O` 地址），除非默认配置是正确的。

既然外部调制解调器无法通过 `PnP` 配置，它为什么能被称为 `PnP` 呢？嗯，它内置了一个特殊的 `PnP` 标识，`PnP` 操作系统可以（通过串口）读取。这种操作系统就会知道你在某个端口上有一个调制解调器，并且知道型号数字。这样，你可能就不需要通过告诉应用程序调制解调器在哪个端口（例如 `/dev/tty2` 或 `COM3`）来配置应用程序了。但如果你没有这种 `PnP` 操作系统，你将需要通过给程序 `/dev` id（例如 `/dev/ttyS2`）来手动配置你的应用程序。

与连接大多数其他需要各种类型“回环调制”缆到串口的设备相比，连接外部调制解调器非常简单。调制解调器使用直通线，没有引脚交叉。大多数电脑商店应该有这种线。确保你拿到正确的插头。如果你使用的是 `DB9` 或 `DB25`，你可能需要母头转头。

### 4.3 内部调制解调器

内部调制解调器为 `Linux` 带来了一个特殊问题，但只要你避开那些仅支持 `MS Windows` 的大部分型号，它们的工作原理和外部一样良好，并且只要你花时间（有时是很长的时间）来正确配置它们。某些仅在 `MS Windows` 下运行的调制解调器遗憾的是并没有被这样标注。如果你买新的，请确保如果它在 `Linux` 下无法工作，你可以退款。

虽然大多数新调制解调器都是即插即用的，但你有多种方法处理它们：

- 使用 `isapnp` 程序
- 让 `PnP BIOS` 进行配置
- 补补内核以创建一个 `PnP Linux`

上述每种方法都有缺点。`Isapnp` 的文档难以理解，尽管阅读《`Plug-and-Play-HOWTO`》（目前尚完整）有助于理解它。如果你想让 `PnP BIOS` 进行配置，你只需要确保它知道你没有使用 `PnP` 操作系统。你可能会在确定它如何设置时遇到困难。参见《我的串口硬件中有什么》。补补内核也可能很复杂。有很多设备驱动不与补丁配合（因此你需要对它们进行配置）。

有些 `Linux` 用户说买一个外部调制解调器并插上要简单得多。但由于现在的新外设都是 `PnP` 的，你最终可能需要处理它，那么为什么不在现在处理呢？将来在 `Linux` 下处理 `PnP` 将变得更容易，但尽管有句古话说“先驱者不获报酬”，今天仍需要先驱来开辟道路路。

在 1998 年，大多数内部调制解调器不支持 `Linux`，因为它们是“`winmodems`”或类似物，尽管它们通常不这样标注。此类调制解调器将调制解调器大部分的工作交给电脑的主处理器（`CPU`）芯片。

`HSP`（主机信号处理器）意味着主机处理器（你的 `CPU` 芯片）产生电话线电信号所需的代码。与之相反，“无控制器”调制解调器可以产生电信号（但无法控制解调器）。它没有处理发送和接收字节的功能。它可以压缩字节字符串；无法检查错误；无法将它们放入数据包。换言之，它无法控制调制解调器，而是由 `CPU` 使用 `Windows` 程序完成这些工作。如果此类程序可以移植到 `Linux`，就不会有这个问题了。除了上述之外，不模拟串口的调制解调器无法在 `Linux` 下工作。

如何判断内部调制解调器是否支持 `Linux`？这并不总是那么容易。如果你可以查看它的包装（或说明书），找到包装中类似于“最低系统要求”或仅“系统要求”的部分。它可能在小字中，仔细阅读。如果 `Windows` 被列为要求之一，那么它很可能无法在 `Linux` 下工作。还要查看列支持和不支持 `Linux` 的调制解调器列表。

否则，如果它未能明确说明你必须拥有 `Windows`，它可能在 `Linux` 下工作。通过说它是“为 `Windows` 设计的”，可能仅意味着它完全支持微软的即插即用

这也可以的，因为 `Linux` 使用了即插用规范（但目前支持得并不完美）。因此，“为 `Windows` 设计”并不能说明它在 `Linux` 下是否能工作。你可能需要检查制造商的网站或通过电子邮件咨询。我曾见过一个网页，它明确指出某一个型号可以在 `Linux` 下运行，同时暗示另一个型号则不行。

据作者所知，`Linux` 几乎没有支持 `winmodems` 的努力。你可以要求调制解调器制造商将他们的代码移植到 `Linux`（或类似的操作）。

- 避免：`winmodems` 或类似设备。它们完全无法工作
- `PCI` 调制解调器在 `Linux` 下通常无法工作
- `MWave` 和 `DSP` 调制解调器可能工作，但前提是你每次启动电脑时都先启动 `Windows/Dos`
- 带有 `RPI` (`Rockwell`) 程序的调制解调器性能会降低

这类调制解调器使用 `DSP`（数字信号处理器），通过算法编程，这些算法必须在使用调制解调器之前从硬盘下载到 `DSP` 内存中。遗憾的是，下载是由 `Dos/Windows` 程序完成的，因此无法在 `Linux` 下完成。可以在 `Linux` 下工作的普通调制解调器通常也有 `DSP`（可能在包装上注明），但运行它的程序存储在调制解调器内部。这并不是本节意义上的“`DSP` 调制解调器”，在 `Linux` 下应该运行正常。

如果 `DSP` 调制解调器模拟串口，那么它就可以配合通过串口进行通信的 `Linux` 使用。如果你在同一台电脑上也有安装 `Dos/Windows`，你可能可以使用该调制解调器：首先启动 `Dos/Windows`（确保调制解调器已初始化），然后在不关闭电脑的情况下进入 `Linux`。一种方法可能是按下 `CTRL-ALT-DEL`。`DSP` 调制解调器的示例是 `IBM` 的 `Aptiva MWAVE`。

需要 `Rockwell RPI` 驱动的调制调器无法无法使用，因为驱动软件在 `Linux` 上无效。`RPI` 使用电脑 `CPU` 上的 `MS Windows` 软件进行压缩和纠错。如果你愿意不使用 `RPI` 而操作调制解调器（既没有压缩也没有纠错），你可以在每次启动调制解调器时，通过初始化字符串向其发送一个命令来轻松禁用 `RPI`。该命令是 `+H0`。拥有数据压缩功能可能并不是什么障碍，因为你从互联网下载的大多数长文件已经压缩过了，进一步尝试压缩可能稍微变慢。

`PCI` 调制解调器是插入 `PC` 主板上 `PCI` 总线槽的设备。遗憾的是，大多数 `PCI` 调制解调器在 `Linux` 下无法工作。但由于已经有人让 `PCI` 调制解调器在 `Linux` 下运行，似乎极少数此类调制解调器是在 `Linux` 下可以工作的。

安装 `PCI` 调制解调器后，查看 `/proc/pci`。如果你看到高主内存地址（地址 `0xfbff0`），它是通过共享内存工作的，而 `Linux` 不支持这种。如果没有这种高内存地址，且你看到的唯一地址是 `0xffff` 下的 `I/O` 地址，那么它可能运行正常。我不确定应该为了查找什么样的 `/proc/pci` 特征来判断调制解调器是否能在 `Linux` 下工作。如果此请求仍出现在此 `HOWTO` 的最新版本中，请向我提供可以在 `Linux` 下运行的调制解调器的 `/proc/pci` 是什么样的信息，或者告诉我在 `/proc/pci` 中应该寻找哪些特征来确定调制解调器是否能与 `Linux` 工作。

### 6.1 什么是 `getty`？

“`getty`”是一个在登录 Linux 时处理登录过程的程序。如果你想通过调制解调器拨入你的 Linux PC，你需要使用某种类型的 `getty`。如果你只想通过调制解调器拨出，则不需要 `getty`。有三种 `getty` 版本可以在 Linux 下配合调制解调器工作：`getty`、`getty_ps` 和 `aget`。`getty` 是最简单中最弱的，主要用于文本终端。这些程序的语法不同，请确保你使用的 `getty` 具有正确的语法。如果这个句子出现在此 howto 的最新版本中，那么如果你能写几段比较 `getty` 和 `getty_ps` 等的文字，请提交给我以便包含在这里。`getty` 只有几年历史，似乎比旧的 `getty_ps` 更受欢迎。

### 关于 `mget`

`mget` 是一个主要用于调制解调器的 `getty` 版本。它可以用于硬接终端，但文档 `99%` 是关于调制解调器的。除了允许拨号登录外，它还提供了 `FAX` 支持和自动 `PPP` 检测。还有一个名为 `vgetty` 的补充程序可以处理某些调制解调器的语音箱。`mget` 文档（`textinfo` 格式）很好，不需要补充。请参阅安装说明。

## 6.2 什么是 `setserial`？

### 介绍

`setserial` 是一个程序，允许你告诉设备驱动软件串口的 `I/O` 地址，`IRQ` 则在端口的硬件中设置。通过适当的选项，它还可以（在给定的 `I/O` 地址）探测串口，但你必须猜测 `I/O` 地址（或者它可能会使用驱动程序认为 `/dev/ttyS` 的任何地址）。`setserial` 不会在串口硬件本身设置 `IRQ` 或 `I/O` 地址。你必须告诉 `setserial` 与硬件中设置的相同的值。这些值在硬件中通过跳线帽或即插即用设置。不要只插入你认为好用的值。然而，如果你知道 `I/O` 地址，也可以命令 `setserial` 尝试确定它。

你可以通过不带任何参数输入 `setserial` 来查看可用的命令列表（但不包括单字母选项，如用于详细输出的 `-v`——你通常在排查故障时应该使用它）。注意 `setserial` 将 `I/O` 地址称为“端口”（`port`）。如果 `setserial` 的参数是 `/dev/tty1`，你将看到一些关于设备驱动如何为该端口配置的信息。但这并不能告诉你硬件是否已设置了这些值。事实上，你可以运行 `setserial` 并输入一个纯虚构的 `I/O` 地址、任何 `IRQ` 以及你想要的任何 `uart` 类型。那么下次当你输入 "setserial..." 时，它将毫无抱怨地显示这些虚假值。注意，`setserial` 进行的赋值在 PC 关机时会丢失，因此通常在每次 Linux 启动时都会自动执行。

### 探测

为了确定你是否有某个串口硬件，必须首先知道它的 `I/O` 地址（设备驱动程序可能有，且很可能是之前由 `setserial` 设置的）。要尝试检测物理硬件，请对 `setserial` 使用 `-v`（详细）和 `autoconfig` 命令。如果结果消息显示 `uart` 类型为 `1650A`，则说明没问题。如果 `uart` 类型显示为“`unknown`”（未知），则在该 `I/O` 地址处没有串口。某些廉价的串口无法正确识别自身，所以当你看到“`unknown`”时，那里可能仍有设备。启动时运行“`setserial`”的文件。自动探测 `uart` 类型功能（`setserial auto-probe for ttyS-`）也不好工作。

### 启动时配置

通常某个地方有一个在启动时运行的文件。如果没有在启动时运行，你的 Linux 系统将使用默认 `IRQ` `4` 和 `3` 自动配置 `ttyS{0-3}`（会导致 `IRQ` 冲突）。在 `1998` 年，它（临时）更改为仅 `ttyS{0-1}`。如果你有超过 `2` 个串口，或者想控制端口的配置方式，应该使用 `setserial`。事实上，你的发行版可能已经设置好了，使得 `setserial` 程序在启动时自动运行。

启动时运行的文件可能位于 `/etc` 目录的某处。你可能使用“`locate`”查找名为 `rc.serial` 或 `setserial` (`Debian`) 的文件。这个在启动时提供的文件可能包含许多被注释的示例。通过取消部分示例的注释并修改它们，你可能能够正确设置或运行一些测试。你可以将其中几个复制到另一个文件并作为 `shell` 脚本执行，但不要忘记复制任何所需的定义，如 `SETERIAL=/bin/serial`。

如果你使用 `setserial`，它会首先在命令行执行，而当你在启动时运行 `/etc/rc.d/rc.serial` 或 `/etc/rc.boot/setserial` 时，它会在启动时运行。如果这些文件不存在，可以使用 `/etc/rc.d/rc.local`（某些人报告说在某个内核下，在串口打开后 `rc.local` 也会执行）。或者，你只需要编辑上述文件之一并碰运气。确保你为 `setserial` 使用了有效的路径和有效的设备名称。

### `IRQs`

默认情况下，`ttyS0` 和 `ttyS2` 共享 `IRQ` `4`，而 `ttyS0` 和 `ttyS3` 共享 `IRQ` `3`。但除非你拥有内核 `2.2` 或更高版本，否则不允许共享串口中断。如果你没有这个现代内核，只有两个串口 `ttyS0` 和 `tty1`，那么你仍然没，因为不存在的设备不存在 `IRQ` 共享冲突。

如果你有超过 `2` 个串口，那么对于小于 `2.2` 的内核，如果两个设备共享相同的 `IRQ`，共享可能是危险的。共享串口中断可能导致数据丢失或系统不稳定。在内核 `2.2` 及以后版本中，内核会正确处理共享情况。

## 6.3 什么是 `setserial`？

`setserial` 是一个程序，允许你告诉设备驱动软件串口的 `I/O` 地址，`IRQ` 则在端口的硬件中设置。通过适当的选项，它还可以（在给定的 `I/O` 地址）探测串口，但你必须猜测 `I/O` 地址（或者它可能会使用驱动程序认为 `/dev/ttyS` 的任何地址）。`setserial` 不会在串口硬件本身设置 `IRQ` 或 `I/O` 地址。你必须告诉 `setserial` 与硬件中设置的相同的值。这些值在硬件中通过跳线帽或即插即用设置。不要只插入你认为好用的值。然而，如果你知道 `I/O` 地址，也可以命令 `setserial` 尝试确定它。

你可以通过不带任何参数输入 `setserial` 来查看可用的命令列表（但不包括单字母选项，如用于详细输出的 `-v`——你通常在排查故障时应该使用它）。注意 `setserial` 将 `I/O` 地址称为“端口”（`port`）。如果 `setserial` 的参数是 `/dev/tty1`，你将看到一些关于设备驱动如何为该端口配置的信息。但这并不能告诉你硬件是否已设置了这些值。事实上，你可以运行 `setserial` 并输入一个纯虚构的 `I/O` 地址、任何 `IRQ` 以及你想要的任何 `uart` 类型。那么下次当你输入 "setserial..." 时，它将毫无抱怨地显示这些虚假值。

常用的 `setserial` 选项有：
- `-irq <number>` 设置 `IRQ`
- `-io <address>` 设置 `I/O` 地址
- `-uart <type>` 设置 `UART` 类型（例如 `16550A`）
- `-fv <number>` 设置 `FIFO` 模式
- `-parity <number>` 设置校验位
- `-stop <number>` 设置停止位
- `-v` 详细输出

# 9. 我的调制调器应该使用什么种速度？

我们所说的“速度”实际上是指“数据流速率”，但几乎每个人都错误地称其为速度。对于所有调制调器，你无法选择调制调器在电话线上的使用速度，因为它会根据你的环境自动选择可能的最高速度。但你可以选择调制调器和计算机之间使用什么速度。这有时被称为“`DTE` 速度”，其中 `DTE` 代表数据终端设备（你的电脑就是 `DTE`）。你需要将此速度设置得足够高，以免信号路径的一部分成为瓶颈。`DTE` 速度的设置是该链路的最大速度。大多数时候，它可能会以较低的速度运行。

对于外部调制调器，`DTE` 速度是经过调制调器和 PC 之间电缆的流量（比特/秒）。对于内部调制调器，原理是一样的，因为调制调器也模拟了串口。在计算机和直接连接到计算机内部更高速总线上的调制调器卡之间设置速度限制似乎很荒谬。但这是因为调制调器卡可能包含一个专用串口，该串口是有速度限制的（并且可以设置速度）。

## 9.1 速度与数据压缩

你选择什么速度？如果没有“数据压缩”，人们可能会尝试选择与调制调器速度完全相同的 `DTE` 速度。数据压缩会将计算机发送到调制调器的字节，并将其编码为更少的字节。例如，如果 PC 到调制调器的流量（速度）为 `20,000` 字节/秒 (`bps`)，而压缩比为 `2:1`，那么电话线上的流量将只有 `10,000` 字节/秒。因此，对于 `2:1` 的压缩比，你需要将速度设置为电话线上调制调器最大速度的两倍。如果压缩比为 `3:1`，你需要将其设置为快 3 倍。

## 9.2 我在该处设置速度？

`DCE` 速度通常通过你的通信程序中的菜单设置，或者在有人拨号时通过提供给 `getty` 命令的选项设置。无法设置调制调器到调制调器之间的速度。

## 9.3 无法设置高速度

你需要找到硬件支持的最高速度。截至 1998 年底，大多数硬件仅支持 `115.2K` 以下的速度。少数 `56K` 内部调制调器支持 `230.4K`。如果你使用的通信程序在其菜单中没有显示足够的速度，你可以提供给 `setserial` 命令的选项，以便通信程序中的低速度能产生较高的速度。通过这些选项，当你将速度设置为 `38400` 时，实际速度将高得多。请参阅“`setserial`”的手册页并搜索 `sp_hi`、`sp_di`、`sp_cust`、`baud_base` 和 `divisor`。注意，你必须将 `baud_base` 设置为硬件的实际最大速度。此速度通常低于硬件中晶体振荡器的频率，晶体频率通常除以 16 得到实际速度。要在 `tty2` 上获得 `23400` 的速度（如果你的串口使用的是该速度），你可以：

```
setserial /dev/tty2 baud_base 23400 divisor 1
```



在某些情况下，使用 `stty 23400` 是无效的。如果你使用了 `sp_cust`，你必须在其他地方声明速度为 38400。这种设置速度的方法是一种黑客手段（hack），当应用程序跟上更高速度时，可能就不需要了。

## 11. 什么是 UART？它们如何影响性能？

UART（通用异步收发传输器）是你的 PC 主板上（或内部调制解调器卡上）的串行芯片。UART 功能也可以在执行其他任务（如排序）的芯片上完成。在像 486 这样较旧的电脑上，芯片位于磁盘 I/O 控制器卡上。更旧的电脑仍有专用的板卡。

UART 的作用是将来自 PC 并行总线的字节转换为串行位流。从串口引出的电缆每个流向方向只有一根线。端口向外发送位流，一次发送一个位。相反，通过外部电缆进入串口的位会被转换为计算机可以理解的并行字节。UART 以分块的大小处理数据，而块的大小恰好也是 ASCII 字符的大小。

假设你有一个终端连接到你的 PC。当你输入一个字符时，终端会将该字符交给发送器（也是一个 UART）。发送器以特定的速率将该字节发送到串行线上，一次发送一个位。在 PC 端，接收 UART 获取所有位并重构出（并行）字节，然后将其放入缓冲区。

UART 有两种基本类型：哑 UART（dumb UART）和 FIFO UART。哑 UART 指的是 8250、16450、早期的 16550 和早期的 16650。它们已经过时了，但如果你理解它们的工作原理，就很容易理解现代的带有 FIFO 功能的 UART（晚期的 16550、16550A、16c552、晚期的 16650、16750 和 16950）是如何工作的。

关于 16550 存在一些误解。早期型号有一个 bug，只有作为 16450 才能正常工作。后来修复了 bug 的型号被命名为 16550A，但许多制造商不接受更更改，继续称其为 16550。今天使用的大多数 16550 都像 16550AS。即使你的硬件（或标签注释）显示它是 16550，Linux 也会报告其为 16550A。16650 也存在类似的情况（据称直到制造商没有承认有任何问题后才是如此）。Linux 会将晚期的 16650 报告为 16550V2。如果它报告为 16500，那就是坏消息，它被使用时就像只有一个 1 字节缓冲区一样。

为了理解哑 UART 和 FIFO（先进先出队列调度）之间的区别，让我们看看当 UART 发送或接收字节时发生了什么。UART 本身无法对通过它的数据做任何操作，它只是负责接收和发送。对于原始的哑 UART，每当发送或接收一个字节时，CPU 都会收到来自串口设备的中断。CPU 将接收到的字节从 UART 缓冲区移到内存的某处，或者给 UART 另一个字节进行发送。8250 和 16450 UART 只有 1 字节缓冲区。这意味着每当发送或接收一个字节时，CPU 都会被中断。在低传输速率下这是没问题的。但在高速率下，CPU 会忙于处理 UART，没有时间充分地处理其他任务。在某些情况下，CPU 无法及时处理中断，UART 就会被覆盖，因为数据来得太快了。这被称为“溢出”（overrun）或“越界”（overflow）。

这正是 FIFO UART 发挥作用的地方。16550 FIFO 芯片带有 16 字节缓冲区。这意味着在它重新中断 CPU 之前，它可以接收或发送（16 个字节）。由于它不仅可以等待，CPU 随后还可以一次接收 14 个（或更多）字节。虽然中断阈值（触发电平）可能被设置为 8 而不是 14，但与那些只有 1 字节缓冲区的其他 UART 相比，这仍然是一个巨大的优势。CPU 接收到更多的中断，从而空闲去做其他事情。数据丢失了，大家都很开心。

虽然大多数 PC 拥有带有 16 字节缓冲区的 16550，但更好的 UART 具有更大的缓冲区。注意，中断是在缓冲区填满稍前发出的（例如对于 16 字节缓冲区设置“触发电平”为 14 字节）。这允许在处理中断期间多接收几个字节。内核软件可以将触发电平设置为各种允许的值。触发电平设为 1 几乎就像哑 UART（不同于它在发出中断后仍有空间容纳另外 15 个字节）。

如果你在访问 BBS 时输入内容，你通过串口输入的字符。你在屏幕上看到的输入字符是通过电话线经过你的调制解调器，然后通过串口回传到屏幕上的。如果串口上有一个 16 字节的缓冲区并留存字符直到达到 14 个，那么你就需要输入很多字符才能看到你输入的内容（在它们出现在屏幕上之前）。

### 14.1 中断设置错误

如果你不懂中断的作用，请参见“中断”（`Interrupts`）。如果一个串口在硬件中设置了一个 `IRQ`，但在设备驱动程序中设置了另一个，则设备驱动程序将接收不到串口发送的任何中断。由于串口使用中断来告知驱动程序何时需要服务（从其 16 字节缓冲区中获取字节或向其发送缓冲区中放入另一个 16 字节），你可能认为串口将完全无法工作。

但它仍然可能运行——某种程度上如此。为什么呢？除了使用中断处理端口的方法，还有一种不需要中断的轮询（`polling`）方法。其工作原理是：设备驱动定期检查串口，看它是否需要什么（例如是否有字节需要从接收缓冲区中获取）。如果中断正常工作，串口驱动程序就会退回到这种轮询方法。但这种轮询方法并不是设计作为中断的替代品。它太慢了，并不实际，并可能导致缓冲区溢出。它的目的是当单个中断丢失或执行不当时，让事情重新运行。它也有助于显示中断已失败。

（没有间隙）如果时机合适，就可以正常通过。例如，如果接收了 32 字节（且没有后续字节），轮询可能恰好接收完前 16 字节后发生。这样就有空间接收接下来的 16 字节，从而使 32 字节全部通过。在 16 到 31 字节之间的类似情况也可以正常通过。也可能只有偶尔的一块 16 字节数据块能够通过，而大量的缺失数据间隙将会丢失。如果你有一个具有 1 字节缓冲器的过时串口（或者它被错误地设为按 1 字节缓冲区工作），情况将比上述描述的糟糕得多，偶尔仅有一个字符能通过端口。这个字符很可能只是换行符，因为这是传输到你屏幕上的最后一个字符。你可能会在几秒后看到光标向下移动了一行。当通信程序启动时，它期望使用这种类似于慢速的运行模式。错误地设置串口或调制解调器可能会导致各种错误。它可能无法意识到连接已经建立。可能会由于轮询延迟而失败。

## 14.2 中断冲突

## 16. 附录 A：工作原理

### 16.1 细节

引言

调制是将数字数据转换为信号。有几种调制类型：频率、幅和相位。

频率调制

频率调制通过改变载波的频率来表示数字数据。这是最简单的调制形式，通常被称为 `FM`。

幅度调制

振幅调制通过改变载波的振幅（或高度）来表示数字数据。这通常被称为 `AM`（以及频率调制）。

相位调制

相位调制通过改变载波的相位来工作。这也被称为 `PSK`（相移键控）。

组合调制

我们不仅仅是选择频率、幅度或相位调制，还可以选择组合这些方法。这被称为 `QAM`（正交幅度调制），被用于许多高速通信系统中。

### 16.2 相位调制

相位调制通过改变载波的相位来表示数字数据。这也被称为 `PSK`（相移键控）。

通话在电话公司的本地局端处被转换为数字信号。通过普通电话发送数字数据的最快速度，与电话公司在其电话通话传输的数字部分使用的速度相同。这个速度是多少？在美国，它恰好是 `56k`！在其他国家可能会略高一些。

因此，在美国，`56k` 是使用普通电话电路数字部分的绝对最高速度，该部分设计用于发送人声的数字编码。为了使用 `56k`，调制调器必须精确知道电话公司是如何进行数字编码的。

 附录 B：“波特率 (`baud`)”与“比特率 (`bps`)”

“`baud`”和“`bps`”可能是计算和电信领域最常被误用的术语之一。许多人交替使用这两个术语，但实际上 `bps` 是每秒比特数。波特率衡量的是信号每秒变化（或转换）的次数。对于典型的串口，1 位表示为 `-12` 伏特，0 位为 `+12` 伏特。如果 `bps` 为 `38,400`，那么序列 `010101` 也将是 `38,400` 波特，因为电压在正负之间来回波动……每秒切换 `38,400` 次。对于另一个序列 `11100011`，切换次数将少于 `38,400`，因为电压一直保持在 `-12` 伏特。我们说每秒变化的次数实际上是 `64k bit/sec`，但只有 `56k` 可以由用户控制。

调制调器使用什么来编码模拟信号？以每秒 `8000` 次的速率对模拟信号进行采样的方法。每个幅度被编码为一个 7 位的字节（注意：7 x 8000 = 56000）。这被称为脉冲编码调制 = `PCM`。这些字节随后发送到电话公司的数字电路上，在这些中，许多通话共享一个被称为“时分复用”的单一电路。最后在你家附近的本地电话局，数字信号被解复用，产生与最初由 `PCM` 创建相同的信号。该信号随后被转换回模拟信号并发送到你家中。你的调制调器的任务是根据幅度精确确定是种数字信号。这（某种意义上）是“幅度调制”，但并非真正如此。

上面的例子过于简单。实际示例更为复杂，但基于相同的原理。这解释了运行在 `2400` 波特的调制调器如何能发送 `14400 bps` 或更高的速率。调制调器通过在每次信号变化（或转换）中编码许多比特来实现大于波特率的 `bps` 率。当每个波特编码两个或多个比特时，`bps` 超过波特率。如果你的调制调器器连接为 `14400 bps`，它将在 `2400` 波特下每次信号传输发送 6 位。`28800 bps` 的速度是通过 `3200` 波特/波特获得的。当人们误用“波特”这个词时，他们可能指的是速度（例如 `33.6K`）。常见的 `bps` 速率曾为 `50`, `75`, `110`, `300`, `1200`, `2400`, `9600`。这些是串口到调制器电缆上的 `bps` 速率。如今，串口到调制器的速率为 `14.4K`、`28.8K`、`33.6K` 和 `56K`，但串口到调制器电缆的速率并非 `19.2K`、`38.4K`、`57.6K` 和 `115.2K`。使用带有 `V.42bis` 压缩（最大 4:1）的调制调器，`33.6K` 调制调器可以达到 `115.2K bps` 的速率（`56K` 调制调器可以达到 `230.4K`）。

`bps` 和 `baud` 之间的混淆是如何开始的？嗯，当老式的低速调制调器是高速的时，`bps` 率实际上等于波特率。每个相位变化编码一个比特。人们会交替使用 `bps` 和 `baud`，因为它们的值是相同的。例如，一个 `300 bps` 的调制调器的波特率也是 `300`。当更快的调制调器出现且比特率超过波特率时，这一切都改变了。“`baud`”是以异步电报打印机发明者 `Emile Baudot` 命名的。

## 附录 C：终端服务器连接

终端服务器类似于智能交换机，可以将许多调制调器（或终端）连接到一台或多台计算机。它不是机械开关，因为它可以改变通过它的数据流的速度和协议。许多公司制造终端服务器：`Xplex`, `Cisco`, `3Com`, `Computone`, `Livingston` 等。它们有许多不同的类型和功能。还需要另一个 `HOWTO` 来完善和描述它们（包括使用 `Linux PC` 创建你自己的终端服务器的可能性）。大多数用于调制调器连接，而不是直接连接终端。

它们的一个用途是将许多调制调器（或终端）连接到连接到主机计算机的高速网络上。当然，终端服务器必须具有运行网络协议的计算能力和软件，因此它在某些方面像一台计算机。终端服务器可能会与用户交互并询问连接到哪台计算机，也可能在不询问的情况下连接。有时作业发送到打印机，然后是终端服务器。

现在的 `PC` 拥有足够的计算能力来充当终端服务器，但每个串口应该有自己的硬件中断。`PC` 仅有此目的目的空闲中断，由于它们是硬接线的，你无法通过软件创建更多。解决方案是使用高级的多端口串口卡，它有自己的中断系统（或者在低成本型号上，在多个端口之间共享 `PC` 的一个中断）。更多信息请参阅 `Serial-HOWTO`。

如果终端服务器通过网络连接到其他 `PC`，且其主要工作是透传数据并处理每 14（或左右）字节的串口中断，则它被称为终端服务器。有时会使用名为“`radius`”的软件。

如今真正的终端服务器的服务不仅仅是终端。它们还为模拟终端的 `PC` 服务，并且有时连接到连接电话线的调制调器阵组。某些设备甚至内置了调制调器。如果终端（或模拟终端的 `PC`）直接连接到调制调器，那么线路另一端的调制调器可以连接到终端服务器。在某些情况下，终端服务器默认期望呼叫者使用 `PPP` 包，而真实的终端并不会产生此类包。

## 19. 附录 D：其他类型的调制调器

本 `HOWTO` 目前处理用于将 `PC` 连接到普通电话线的调制调器。还有其他类型的调制调器，包括被称为调制调器但实际上不是调制调器的设备。

## 19.1 数字转数字“调制调器”

调制器的标准定义有时会扩大到包含“数字”调制调器。如今，许多家庭和办公室已提供直接的数字服务，因此计算机向电话线发送数字信号（准确说是几乎如此）。但仍然需要设备将计算机数字信号转换为电话电路允许的类型，这种设备有时被称为调制调器。接下来的两个小节：`ISDN` 和 `DSL` 涉及数字转数字“调制调器”。

## 19.2 ISDN “调制调器”

“`modem`”实际上是一个终端适配器 (`TA`)。提供一个 `Debian` 包“`isdnutils`”。有一份德语版的 `ISDN Howto` 带有英语翻译：`http://www.suse.de/Support/sdb_e/isdn.html`。它由 `SuSE Linux` 发行版发布，很可能是该发行版中可用的驱动程序。有一个 `isdn4linux` 包和一个新闻组：`de.alt.comm.isdn4linux`。许多帖子是德语编写的。你可以尝试使用搜索引擎（如 `DejaNews`）来查找“`isdn4linux`”。

## 19.3 数字用户线路 (DSL)

`DSL` 使用你家（等等）现有的双绞线线路连接到本地电话交换局。如果你的电话线可以接受比普通调制调器（例如 `56k`）发送的更快的速度，就可以使用它。它将本地电话交换局的模拟数字转换器替换为可以接受更快数据流的转换器（当然，是不同的格式）。将你的计算机数字信号转换为本地电话线路上表示数字数据信号的设备也称为调制调器。本文目前未涵盖这些调制调器的特殊方面。

## 2.5 不支持的串口硬件

### Winmodems 无法工作

声称为“`Winmodems`”的调制器（例如 `USR Sportster Winmodem` 和 `IBM Aptiva MWAVE`）在 `Linux` 下不支持。这些调制器使用专有设计，需要特殊的 `Windows` 驱动。请避免此类型号。

### Rockwell (RPI) 驱动可能可用

需要 `Rockwell RPI` 驱动的调制器无法完全使用，因为该驱动软件在 `Linux` 上无法运行。`RPI` 使用电脑 `CPU` 上的 软件进行压缩和纠错。如果你愿意在不使用 `RPI` 的情况下操作调制器（因此没有压缩或纠错），你可以通过向调制器（通过初始化字符串）发送 `RPI` 禁用命令 `+H0` 来轻松禁用 `RPI`。

## 串口的名称是什么？

`I/O` 端口是数据进出计算机的一种。有很多类型的 `I/O` 端口，例如串口、并行口、磁盘驱动控制器、以太网卡等。我们将处理串口，因为调制调器和终端都是串口设备。每个串口都有一个名称。

| 端口名称 | 地址 | IRQ |
| :--- | :--- | :--- |
| `ttyS0` (`COM1`) | `0x3F` | `4` |
| `ttyS1` (`COM2`) | `0x2F` | `3` |
| `ttyS2` (`COM3`) | `0x27` | `4` |
| `ttyS3` (`COM4`) | `0x2B` | `3` |
| `ttyS4` (`COM5`) | `0x2D` | `5` |
| `ttyS5` (`COM6`) | `0x29` | `3` |
| `ttyS6` (`COM7`) | `0x2D` | `5` |
| `ttyS7` (`COM8`) | `0x27` | `4` |

如果你使用超过八个串口，它们将被命名为 `ttyS9`、`ttyS10` 等以此此类推。某些端口可能被命名为 `ttyUSB0`、`ttyUSB1` 等。你可以通过查看 `/dev` 来查看系统上的可用端口。

## 关于 getty_ps

大多数发行版都预装了 `getty_ps` 软件包。（`Debian` 曾使用 `getty`，但现在使用 `mgetty`）。它包含两个程序：`getty` 用于控制台和终端设备，`gettyget` 用于调制解调器（`modem`）。我使用的是这个版本的 `getty`，因此将重点介绍这部分。

## 关于 mgetty

`mgetty` 是 `getty` 的一个版本，主要用于调制解调器。它也可以用于接线终端，但文档中 99% 的内容与调制解调器有关。除了允许拨号登录外，`mget` 还提供 `FAX` 支持和自动 `PPP` 探测。`mgetty` 文档（以文本格式提供）非常好，不需要补充。请参阅该文档获取安装说明。你可以在 `http://www.lco.org/~doering/mgetty/` 找到 `mgetty` 的最新信息。

## 关于 getty

`agty` 是 `getty` 的第三种变体。它是一个简单且功能完整的 `getty` 实现，最适用于控制台或终端而非调制解调器。

## 4.2 什么是 setserial？

`setserial` 是一个允许你查看和更改串口设备各种属性的程序，包括端口地址、中断和其他串口选项。你可以通过运行不带参数的 `setserial` 来查看你拥版本。当你的 `Linux` 系统启动时，只有 `ttyS(0-3)` 配置了默认的中断 4 和 3。如果参数是 `/dev/ttyS1`，你会看到关于该端口的信息。因此，如果你有其他板提供的串口，或者 `ttyS(0-3)` 有非标准中断，你必须使用 `setserial` 配置这些串口。完整列表请参阅主页。

## 5 如何用我的调制解调器拨号？

## 5.1 硬件要求

你可以使用外部或内部调制解调器。内部的成本较低且不占用桌面空间。但外部的更容易“安装”，并且有指示灯显示正在发生的情况。外部在使用时需要关闭，即使关闭也会消耗少量电力。

## 外部调制解调器

首先，确保你有正确的线缆。你的调制解调器需要直通线而非交叉线。任何计算机都应该有这些。确保你获得正确的规格。如果你使用的是 `DB25` 串口，它将始终是公头。不要与并行端口混淆，后者是母头。将你的调制解调器连接到你的串口之一。如果需要帮助，请参阅调制解调器说明如何操作。

## 内部调制解调器

对于内部调制解调器，你不需要线缆。它是内置的。你需要的是配置一个未被使用的中断，并配置 `I/O` 地址。如果卡住了，请阅调制解调器说明。如果你需要帮助选择中断或地址，参见“多个串口设备”。在某些主板上，你必须禁用调制解调器正在使用的串口以避免冲突。这可以通过跳线或 `BIOS` 设置来实现，取决于你的主板。

如果你有 `IBM8514` 主板，有一个你应该知道的 Bug。如果你使用内部调制解调器作为 `tty3`，可能会遇到问题。如果 `Linux` 没有检测到 `tty3` 上的内部调制解调器，你可以使用 `setserial`，它将正常工作。`ttyS(0-2)` 不应该出现任何被检测问题。

`setserial` 是一个允许你查看和更改串口设备各种属性的程序，包括端口地址、中断和其他串口选项。你可以通过运行不带参数的 `setserial` 来查看你拥版本。当你的 `Linux` 系统启动时，只有 `ttyS(0-3)` 配置了默认的中断 `4` 和 `3`。如果参数是 `/dev/ttyS1`，你会看到关于该端口的信息。因此，如果你有其他板提供的串口，或者 `ttyS(0-3)` 有非标准中断，你必须使用 `setserial` 配置这些串口。完整列表请参阅主页。

## 5 如何用我的调制解调器拨号？

## 5.1 硬件要求

你可以使用外部或内部调制解调器。内部的成本较低且不占用桌面空间。但外部的更容易“安装”，并且有指示灯显示正在发生的情况。外部在使用时需要关闭，即使关闭也会消耗少量电力。

## 外部调制解调器

首先，确保你有正确的线缆。你的调制解调器需要直通线而非交叉线。任何计算机都应该有这些。确保你获得正确的规格。如果你使用的是 `DB25` 串口，它将始终是公头。不要与并行端口混淆，后者是母头。将你的调制解调器连接到你的串口之一。如果需要帮助，请参阅调制解调器说明如何操作。

## 内部调制解调器

对于内部调制解调器，你不需要线缆。它是内置的。你需要的是配置一个未被使用的中断，并配置 `I/O` 地址。如果卡住了，请阅调制解调器说明。如果需要帮助选择中断或地址，参见“多个串口设备”。在某些主板上，你必须禁用调制解调器正在使用的串口以避免冲突。这可以通过跳线或 `BIOS` 设置来实现，取决于你的主板。

如果你有 `IBM8514` 主板，有一个你应该知道的 Bug。如果你使用内部调制解调器作为 `tty3`，可能会遇到问题。如果 `Linux` 没有检测到 `tty3` 上的内部调制解调器，你可以使用 `setserial`，它将正常工作。`ttyS(0-2)` 不应该出现任何被检测问题。

## 5.4 硬件流控

## 6 如何用 getty_ps 用我的调制解调器拨入拨出

### 6.1 拨入拨出调制解调器配置

对于拨入和拨出使用，你必须以某种方式设置调制解调器（再次使用调制解调器上的 `AT` 命令）：

```

Q0 报告代码

V1 详细模式开启

如果你没有正确设置这些，配置文件中的 `INIT` 字符串可能会失败，导致整个过程混乱。但关于配置文件的更多信息见下文……

```
&C1 DCD 连接后开启

&S0 DSR 始终开启

DTR 开启/关闭重置调制解调器（取决于制造商-RTFM）
```

这些在调制解调器启动和结束时影响它。

如果你的调制解调器不支持存储配置，可以通过配置文件中的 `INIT` 字符串设置这些。见下文。某些调制解调器带有影响寄存器设置的 DIP 开关。确保这些也设置正确。

我开始收集了针对不同类型调制解调器的设置方案。目前，我只有其中几个，如果你愿意向我发送你正在使用的配置，请尽管发送！你可以在 `http://ftp.cc.gatech.edu/pub/people/gregh/modem-configs` 获取它们。

注意：为了让我的 US Courier V.34 调制调器在 DTR 下降时正确重置，我必须设置 D2 和 S13=1（这设置了寄存器 S13 的第 0 位）。这已在 USR Sportster V.34 调制调器上确认有效。

注意：某些 Supra 调制调器对 DCD 的处理方式与其他调制调器不同。如果你正在使用 Supra，尝试设置 `&C0` 而不是 `&C1`。你必须设置 `&D2` 以正确处理 DTR。

## 6.2 安装 getty_ps

从 `sunsite.unc.edu/pub/Linux/system/serial` 获取最新版本。特别是，如果你想使用高速度（57600 和 115200 波特），你必须获取 2.0.7j 或更高版本。你还必须拥有 `libc` 5.x 或更高版本。

默认情况下，`getty_ps` 将配置为符合 Linux FSTND（文件系统标准），这意味着二进制执行文件将位于 `/sbin`，配置文件将命名为 `/etc/config.[ugetty].ttyN`。这在文档中并没有明确说明！它还会期望锁文件位于 `/var/lock`。请确保你有 `/var/lock` 目录。

如果你不使用 FSTND 标准，二进制执行文件将进入 `/etc`，配置文件将进入 `/etc/default/[ugetty].ttyS`，锁文件将存放在 `/usr/spool/uuc`。如果你在使用 UOCP，我建议使用这种方法，因为如果你将锁文件移动到它所在的位置，UOCP 将出现问题。

`getty_ps` 还可以使用 `syslog` 来记录消息。如果你还没有运行它，请参阅 `syslog(1)` 和 `syslog.conf(5)` 的帮助页来设置 `syslog`。消息使用优先级 `LOG_AUTH` 记录日志，错误使用 `LOG_ERR`，调试使用 `LOG_DEBUG`。如果你不想使用 `syslog`，可以编辑 `getty_ps` 源文件中的 `tune.h`，以用日志文件代替消息，默认为 `/var/adm/getty.log`。

决定你是否需要 FSTND 标准和 `syslog` 功能。你也可以选择两者的结合。编辑 `Makefile`、`tune.h` 和 `config.h` 以反映你的决定。然后按照软件包随附的说明进行编译和安装。

从现在起，所有对 `getty` 的引用将指向 `getty_ps`。对 `ugetty` 的引用将指向 `getty_ps` 软件包自带的 `ugetty`。这些指令不适用于 `mgetty` 或 `aty`。

| DB9 | | Terminal DB25 | | |

## 9. 我可以使用两个以上的的串口设备吗？

除非你想使用三个或更多串口设备（假设你没有多端口板卡），否则你不需要阅读这一节。

只要你还有另一个串口，是的，你可以的。你使用的串口数量受限于我们必须使用的中断请求（IRQs）和端口 I/O 地址的数量。这不是 Linux 的限制，而是 PC 总线的限制。每个串口设备都必须分配其自己的中断。如果两个设备共享同一个中断，只要这两个设备不同时运行，它们可能运行得良好（在大多数情况下，这些程序不能同时运行）。串口设备可以是内部调制解调器，也可以是多端口串口卡。

多端口串口卡专门设计为具有多个串口，且板卡上的所有端口共享同一个 IRQ。Linux 通过为板卡上的每个端口使用不同的 I/O 地址从它们获取数据。

如果你有一个 14400 bps (V.32bis) 的调制解调器并带有 V.42bis 数据压缩，请使用 57600 bps。

如果你有一个 9600 bps (V.32) 的调制解调器并带有 V.42bis 数据压缩，请使用 38400 bps。

如果你使用的比 9600 bps (V.32) 调制解调器更慢，请将速度设置为调制解调器支持的最高速度。例如 300 bps (V.21/Bell 103)、1200 bps (V.22/Bell 212A) 或 2400 bps (V.22bis)。

如果你先在命令行上使用 `setserial test`，在它们运行正常后，将它们放入 `/etc/rc.d/rc.serial`、`/etc/rc.d/rc.local` 或 `/etc/rc.boot/0setserial`，以便它们在启动时运行。确保你使用的是 `setserial` 的有效路径和有效的设备名称。你可以通过运行以下命令来检查串口的设置：

```
setserial -a /dev/tty3
```

### 12.7 串口上更高的吞吐量

如果 `ls` 的颜色功能搞乱了你的终端仿真，请将其关闭……

`UART` 本身无法对数据进行任何操作，它只是负责发送和接收。对于原始的 `UART`，每当发送或接收一个字节时，`CPU` 都会收到来自串口设备的中断。`CPU` 将接收到的字节从 `UART` 缓冲区移到内存的某处，或者给 `UART` 另一个要发送的字节。`8250` 和 `16450` `UART` 只有 1 字节缓冲区。这意味着每发送或接收 1 个字节，`CPU` 就会被中断一次。在低比特率下，这没有问题。但在高传输速率下，`CPU` 忙于处理 `UART`，以至于没有时间兼顾其他任务。在某些情况下，`CPU` 无法及时处理中断，由于数据进入得太快，导致字节被覆盖。

这正是 `16550` `UART` 发挥用用场。。这些芯片配备了 16 字节的 `FIFO`（先进先出队列）。这意味着在必须中断 `CPU` 之前，它可以接收或传输多达 14 个字节。它不仅可以等待，而且 `CPU` 也可以一次性传输 14 个字节。虽然中断阈值并不总是设置为 14，但与那些只有 1 字节缓冲器的其他 `UART` 相比，这是一个显著优势。`CPU` 接收到的中断减少了，数据没有丢失，大家都很开心。（还有一种 `1650` `UART`，但如果它坏了，会被视为 `16450` 处理。）

通常情况下，`8250` 和 `16450` `UART` 在最高 38400 bps 的速度下运行良好。在超过 38400 bps 的速率下，可能会看到数据丢失。其他 PC 操作系统（这里的定义较松）如 `DOS` 并不是多任务操作的，因此它们可能更好地应对 `8250` 和 `16450`。这就是为什么某些人在切换到 Linux 之前没有看到数据丢失。

非 `UART` 和智能多端口板卡使用 `DSP` 芯片进行额外的缓冲和控制，进一步减轻了 `CPU` 的负担。例如，`Cycles Cyclom` 和 `Stallion EasyIO` 板卡使用 `Sirius Logic CD1400 RISC UART`，许多板卡使用 `80186` `CPU` 或特殊的 `RISC CPU` 来处理 I/O。

请记住，这些“哑”`UART` 类型并不坏，它们只是不适合高速。我们连接终端或鼠标到这些 `UART` 应该没有问题。但对于高速调制解器，`16550A` 绝对是必须的。

大多数新的 PC（486、奔腾或更高）都配备了 `16550A`。如果你足够好，可能可以通过使用 `16550A` 芯片并替换现有的 `16450` `UART` 来升级。如果你运气不佳，功能已经被放置在另一种类型的芯片上；如果 `UART` 是插座式的，那么升级就很容易（如果你能找到替代品的话）。新旧芯片在引脚上兼容兼容。直接从网上购买串口卡可能更可行（现在很少有零售商店备货了）。

## 14. 故障排除

### 14.1 我一直收到“line NNN of inittab invalid”

确保你正在使用的语法与你的 `init` 版本匹配。市面上不同的 `init` 在 `/etc/inittab` 文件中使用不同的语法。确保你使用的语法与你的 `getty` 版本匹配。

### 14.2 当我尝试拨号拨出时，显示“dev/cuAn: Device or resource busy”

这个问题出现在 `DCD` 或 `DTR` 未被正确设置时。只有在存在实际连接（即已拨入）时才应设置 `DCD`，而不是在 `getty` 监控端口时。检查并确保你的调制解器配置为仅在 `getty` 连接时设置 `DCD`。每当有程序在使用或监控线路（如 `getty`、`kermit` 或其他通信程序）时，都应该设置 `DTR`。

“设备忙”错误的另一个常见原因是，你设置串口端口时，其中断已经被其他东西占用。每个设备在初始化时，都会向 Linux 请求使用其硬件中断的权限。Linux 会跟踪哪个中断被分配给了谁，如果你的中断已被占用，你的设备将无法正常初始化。设备本身实际上并没有什么方法可以告诉你发生了这种情况，只有当你尝试使用它时，它才会返回“device-busy”错误。检查你所有板卡（串口、以太网、SCSI 等）的中断。寻找 IRQ 冲突。

### 14.3 我一直收到“Getty respawning too fast: for 5 minutes”

确保你的调制解器配置正确。查看 寄存器 `E` 和 `Q`。这可能发生在你的调制解器与 `getty` 聊天时。

确保你从 `/etc/inittab` 正确地调用了 `getty`。使用错误的语法或设备名称会导致严重问题。

# 服务器端

假设服务器是一个 `Linux` 系统，并具有：

- `a)` 连接到 `/dev/ttySx` 设备的调制解调器
- `b)` 映射到 `/dev/ttyIx` 设备的 `'isdn4linux'` 模拟调制解调器

我能想的最简单设置是使用五行 `perl` 脚本来实现一个“调制解调器守护进程”（`modem demon`）：

```
$ cat !/usr/bin/perl

select((select(STDOUT), $) = 1) [$];

select((select(STDIN), $) = 1) [$]);

exec `cu -s 115200 -1 /dev/ttyS1`;

die '$00: Cant exec cu: $\n';
```

当客户端连接到如下合适的端口时，`INETD` 进程启动调制解调器守护进程。“`modem modify`”只需将 `socket` 连接到 `cu` 命令的 `STDIN` 和 `STDOUT`，让 `'cu'` 处理实际的调制解调器设备。如果你的系统中没有 `'cu'`，安装 `'UUCCP'` 包，它通常是 `'UUCCP'` 的一部分。

必须通过更新其配置文件（通常是 `/etc/inetd.conf`）让 `INETD` 进程知道调制解调器守护进程的存在，如下：

```
#

# modem daemon

#

modem stream tcp nowait root /usr/sbin/tcp /usr/sbin/modem /dev/ttyS1
```

为了使其生效，需要在 `/etc/services` 中添加如下条目：

```
modem          2006/tcp          modemd
```

# 调制调器配置

关于调制调器配置和初始化字符串（init strings）的说明：

配置你的调制调器软件（如 `minicom` 或 `(m)getty`）使用最高可能的速度；144k 使用 `57600 bps`，更快的调制调器使用 `115200 bps`。

许多人使用非常长且复杂的初始化字符串，通常以 `AT&F` 开头，并包含许多特定调制调器品牌和类型的命令。然而这增加了必要的复杂性。大多数程序对相同的调制调器设置都很满意，为什么不将这些设置写入你所有调制调器的非易失性内存中，并在所有程序中仅使用 `ATZ` 作为初始化字符串呢？这样，你就可以更换或升级调制调器，而无需重新配置任何软件。

大多数程序要求你使用以下设置：

- 固定波特率（无自动波特率）
- 硬件双向 `RTS-RTS` 流量控制（无 `x-on/x-off`）
- 8 位，无校验位，1 停止停止位
- 调制调器应产生真实的 `DCD` 状态 (`&C1`)
- 调制调器不应忽略 `DTR` 状态 (`&D2` 或 `&D3`)

通过 `AT&V` 或 `AT&Ix` 检查（请咨询你的调制调器文档）

这些设置并不一定与出厂默认配置 (`&F`) 相同，因此从 `AT&F` 开始初始化字符串可能不是一个好主意。明智的做法可能是只有当你有理由相信存储非易失性内存中的调制调器设置出错时，才使用 `AT&F`。

如果你认为你已经为调制调器找到了正确的设置，请使用 `AT&W` 将写入非易失性内存，并使用 `Z-modem` 传输 ASCII 文本和二进制文件进行彻底测试。只有当所有这些都完美工作时，你才应该为调制调器配置租线（leased line）。

了解如何将调制调器置于盲模式（dumb mode），更重要的是，如何将其退出盲模式；调制调器只有在不在盲模式时才能被重新配置。

确保你确实以最高可能的速度配置了调制调器。一旦进入盲模式，它将忽略所有的 `AT` 命令，因此不会将其速度调整为串口速度，而是将使用它被配置时的速度（此速度存储在 `S` 寄存器中，通过 `AT&W` 命令存储）。

现在按照如下配置你的调制调器：

- `DTR` 切换时重置 (`&D3,D1`，有时是 `S` 寄存器）。某些 ISP 要求此设置
- 租线模式 (`&L1&L2`)，咨询你的调制调器文档
- 远程调制调器自动应答 (`S0=1`)，本地发起 (`S0=0`)
- 禁用结果代码 (`Q1`，有时盲模式为此执行)
- 盲模式 (`\D1` 或 `%D1`，调制调器将忽略所有的 `AT` 命令（有时你还需要禁用 `ESC` 字符）。

将配置写入非易失性内存 (`&W`)。

# 测试

现在使用 `RS232` 线缆将调制调器连接到两台电脑，并使用 `RJ11` 线将调制调器相互连接。在两台电脑上都使用如 `Minicom` (`Linux`) 或 `modem` (`DOS`) 等调制调器程序来测试调制调器。你应该能够从一台电脑向另一台电脑输入文本，反之亦然。如果屏幕出现乱码，检查你的串口速度和其他设置。现在断开并重新连接 `RJ11` 线。等待连接重新建立。断开并重新连接 `RS232` 线缆，切换调制调器的开关，停止并重启 `minicom`。调制调器应该始终以最高可能的速度重新连接（某些调制调器带有速度指示）。检查调制调器是否实际上忽略了 `ESC` (`+++`) 字符。如有必要，禁用该字符。如果所有这些运行正常，你可能想要重新配置你的调制调器，关闭远程调制调器 (`M0`) 并本地调制调器设置为低速 (`L1`)。

```

`ip-up` 还可以用于使用 `ntp` 同步你的时钟。

当然，在 `ip-up` 中设置的路由并不一定是默认路由。你的 `ip-up` 设置了到远程网络的路由，而远程系统上的 `ip-up` 脚本设置了到你网络的路由。如果你的网络是 `192.168.1.0`，而你的 `ppp` 接口是 `192.168.1.1`，那么远程机器上的 `ip-up` 脚本如下：

```bash
#!/bin/bash

case $2 in

  /dev/ttyS1)

    /sbin/route add -net 192.168.1.0 gw 192.168.1.1 netmask 255.255.255.0

  ;;

esac
```

`case $2` 和 `/dev/ttyS1)` 部分是为了以防你可能使用了多个 `ppp` 链路。`ip-up` 会在每个链路建立时运行，但只会执行位于 `/dev/ttySx` 和 `;;` 之间的部分，从而为正确的 `ttyS` 设置正确的路由。

你可以在 `NET-3-HOWTO` 中的路由章节找到更多关于路由的信息。

## 2. 设置你的以太网卡

所有设置都使用以太网卡（网卡）来连接互联网。这就是为什么首先我们需要检查你的以太网卡是否工作以及最重要的是支持 Linux。有一个全面的 Ethernet HOWTO `http://sunsite.unc.edu/LDP/HOWTO/Ethernet-HOWTO.html`。

进入 Linux 启动时应出现如下信息：

```
eth0: 3c509 at 0x300 10BaseT port, address 00:20:ee:23, IRQ 10.

07 becker@cesis.gsfc.gov
```



如果你看到了这样的信息，说明你设置好了，可以进入下一节。如果你没有看到信息，有两种可能的解释：你的网卡是 `PNP`（即插即用），你需要使用如 `isnptools` 等工具来识别它（我对此不太确定，因为我没有 `PNP` 网卡）。另一种解释是你需要设置网卡。

大多数网卡都带有用于设置网卡的 `DOS` 程序。例如，为了让我的 `3COM 3c509` 工作，我所做的只是进入 `DOS` 并使用工具配置。通常有一个自动配置选项。如果这不能解决你的问题，尝试使用相同的工具更改卡的 `IRQ`。我发现 `IRQ 10`、`11` 和 `12` 效果良好。如果这些方法都不能解决你的问题，请阅读上述 `Ethernet HOWTO` 或在 `comp.os.linux.setup` 或 `comp.os.linux.networking` 组发帖。

`http://ftp.vortex.net/pub/rlinux/rclientd-1.3.tar.gz`

我运行的是 `RedHat 5` 版 `Linux`——但文档表明它适用于其他版本。注意，`rclientd` 发布版中的信息比本文记录的要多。

步骤：

- 将发行包文件 ``rrclientd-1.3.tar.gz`` 拷贝到你的 `Linux` `PC` 上。
- 以下所有操作请以 `root` 身份登录：
  - 解压缩发行包（使用 ``gunzip``）然后解压它。
  - 在 ``rrclientd-1.3/bin`` 目录下，你将找到所需的所有可执行文件：``fetchmail``（未使用）``kdestroy`` ``kinit`` ``rdate`` ``rrelclientd`` ``rdcpd`` ``rpasswd``
  - 将 ``/sbin/dhcpd`` 重命名为 ``/sbin/dhcpd.org``。复制并重命名 ``rdcpd`` 为 ``/sbin/dhcpd``。
  - 将 ``kdestroy``、``kinit``、``rdate``、``rrelclientd``、``rrpasswd`` 拷贝到 ``/usr/local/bin``。
  - 设置你的网卡使用 `dhcp` 并重启系统。如果 `dhcp` 配置正确——将分配一个 `IP` 地址——详情将存放在 ``/etc/dhcp/hostinfo-eth0`` 和 ``/etc/dhcp/resolv.conf`` 中。

你可能会看到关于找不到 ``dhcp.conf`` 的启动警告——这似乎并不是问题。
