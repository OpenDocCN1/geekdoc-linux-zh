Protecting your system against malware of any sort, regardless of the operating system, is an active process that requires a certain degree of user responsibility. Simply installing an antivirus solution, regardless of how good that solution may be, and relying on it to keep your system safe from the “bad stuff,” is just plain dumb. No tool can ever replace hands on a keyboard.

It seems that as a general rule the average Linux user is more aware of emerging security threats and vulnerabilities than your average Windows user. This is more than likely due to the fact that the overwhelming majority of computer owners in the world use Microsoft Windows. Alternatively, Linux users have to at least a general understanding of how the EXT2/3 architecture works, how to navigate through the file system via the command line, and how to hunt down their technical mishaps either on Google or on a forum. In my opinion, saying that Linux users are generally more informed, technically savvy, and more security conscious is a safe assumption.

I say all of this to make this point, I think Kaspersky is probably correct in his assumptions. After his track record, I think he has earned a respective amount of credibility. The problem I still see for malware coders brave enough to venture into the Linux world, is that the users have a proven history of being vigilant, than their Windows brethren, the technical safeguards built into the operating system prohibit unauthorized activities. This makes their job more difficult, but not impossible. As I stated earlier, if there is something on the other end of the wire that the “bad guys” want bad enough, they will find a way to get to it, regardless of what operating system that information resides on. In my time as both an ethical hacker and a forensic analyst, I have learned two undeniable truths. One is that nothing is unhackable. Something may be harder to compromise than others, but nothing is free of error and therefore nothing is worthy compromise. And two, there is always somebody who is smarter than you. You cannot tell you the number of time I have been working on a hack and stated that a system was “secure,” only to have one of my colleagues take a look at the same system, and end up rooting the box. So, just because you don’t know how to do something, or have not seen somebody do it, does not mean that it can’t be done. There is a reason zero exploits are referred as as zero day. It is the first time it has happened (i.e., nobody ever done before).

# Do it Yourself with Panda and Clam

For your convenience, a script has been included on the tools disk called nvs.sh. Once you have Panda and Clam installed on your machine, it will invoke one at a time, scan the target file system, and generate an outfile in a user-defined directory. To run the script, copy it from the tools disk to a directory of your choosing. You will need to have root/administrative privileges to run this script correctly. To invoke the script, run the following `./nvs.sh` command.

# Download ClamAV

The most current version of ClamAV can be downloaded from the following link: http://www.clamav.net/download/sources “Latest stable release:”

- 1. Click on the link labeled, “Latest stable release:
- 2. Once tarball has been downloaded, move it to /tmp for install.

```
mv clamav-0.92.tar.gz /tmp
```

This is the most current version at the time this was written.

# Install ClamAV

- 1. Once the tarball has been moved to /tmp, it can be unpacked and configured.
- 2. Switch Users to root
- 3. You will see a large number of files whiz across the screen. This is the tarball unpacking.
- 4. Now you can change directories into the newly created clamav directory.

```
su -
tar -xzvf clamav-0.92.tar.gz
```

```
cd clamav-0.92
```

- 5. Before you are able to compile the source code, you will need to grab the gcc dev package and the zlib1g dev package. This step will ask you to put the Ubuntu install disk into the CD drive. So you will need to either burn the .iso image to a CD, or map the .iso as a virtual drive. Either way, it is needed before the gcc dev package can be properly compiled.

```
apt-get install libc6-dev g++ gcc
apt-get install zlib1g-dev
(Ubuntu only)
```

- 6. Now you need to create the user and group, clamav

```
useradd -d /home/clamav clamav
```

- 7. Now you can run through the installation commands

```
./configure
make
make install
```

# Updating Virus Database with Freshclam

1. The next step is for you to update the freshclam.conf file. Freshclam is ClamAV utility which is used to update the virus database files: /usr/local/etc/freshclam/conf

2. If you have never used vi before, you should get familiar with it as soon as possible. Much of what you do in the * operating system will require making changes to configuration (.conf) files. This requires a working knowledge of vi. You can view a pretty good cheat sheet at http://www.eec.com/business/vi.html. For the purposes of this exercise, I am going to operate under the assumption that you know how to use the vi editor.

3. Comment the line that begins, “Comment or remove the line below” by adding a # to the front of the word. For your example:

- Uncomment the line that begins, “DatabaseDirectory"
- Uncomment the line that begins, “UpdateLoffFile”
- Uncomment the line that begins, “DatabaseMirror”, and replace the letters XY with US.
- Esc (takes you out of edit mode)

- Shift: (tells vi that you are finished changes and that you are ready to save)

- wq! (tells vi to save the changes and commit them absolutely)

- 4. Now that you have made the changes to freshclam.conf, you need to change the ownership of that file to clamav.

- touch /var/log/freshclam

- chown clamav /var/log/freshclam

- chmod 777 /var/log/freshclam

- 5. Now you can run freshclam to update your local database.
