should also be validated with "usr/bin/md5sum." The Message Digest 5 (MD) values for these two binaries in the GNU/Linux 2.6.20-1.2962 kernel:

```
/bin/mount = clf34db880b4074b627c21abde627d5
/usr/bin/md5sum = 681c328f281137d8a0716715230f1501
```

For different versions of the Linux kernel, you will have to obtain the checksums on your own, as there are many possibilities that they had to be outside of the scope of this book.

Once validated and determined to be unmolested, the CD or USB drive can be mounted using the root user. Now, change directories to the trusted tools directory, in this case /mnt/<mntname>, and the trusted binaries can be used.

# NOTE

OK...so I have heard a great deal of my time in the computer forensics world about creating "static tools disk," yet I have never actually seen anybody do it. No whitepapers, no blogs, no mailing lists, nothing. So, I decided to try it for myself and see what I could come up with. I figured out how to modify a myfile and use the -gcc static option and point the LD_LIBRARY_PATH at the libraries on the disk, which is better than nothing, I guess, but here's the problem. These static binaries are really only reliable for that particular Linux release, on that particular version of that release, and on that particular version of the kernel.

So let's spend time building a set of static tools for Ubuntu 7.10, kernel 2.6.22-14. That disk will be good for gathering volatile data from another Ubuntu 7.10 machine, and using kernel 2.6.22-14. That being the case, you would literally have to have the exact version of every OS, every possible kernel, and in some instances of proprietary hardware like Sun Microsystems (SPARC), AIX (Power PC), or HP-UX, to effectively be working a set of statically linked tools. The caveat then is, if you are a corporate security officer, and you know that your shop only has a few versions of *nix, and a few kernel versions, then it may make sense for you to build a few tools disks based on what you are working with. However, for the rest of us seldom on the same OS or kernel twice (not to say that it never happens, but not often), the concept of building a static tools disk is nothing more than a good idea.
