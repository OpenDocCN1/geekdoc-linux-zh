methods including NIS, NIS+, AFS, Kerberos, and more. You can configure *nix boxes to authenticate against Active Directory, for example (not that I'd rush to recommend it). PAM controls the PAM configuration files determine what authentication sources get used. In Ubuntu, /etc/pam.conf is the file, but it varies among various *nix and even among Linux distributions.

User ID 0 has special meaning in *nix, and any user with a User ID of 0 is root. Think of this like a local administrators group. If you see users in /etc/password with a UID of 0 and they are not root, your forensic eyebrow should raise. Group ID's are also defined ranges. Group ID's are defined by name in the /etc/groups file, whereby a user can be a member of multiple groups than just the primary group defined in /etc/passwd.

# # *nix file system Structure

As you've surely noticed, the first thing that sticks with *nix neophytes (n00bs) is that:

+   - *nix doesn't use drive letters
- Unix pathnames use forward slashes (/) and not backslashes (\)

/ is the top level of the *nix directory structure. There isn't really a Windows equivalent for this concept. While Windows does have a notion of a root directory, it's local to the drive you're on (e.g., c:\). There isn't a directory in Windows you can go to show you the top of the world, as it were.

Like many *nix concepts, this is best learned by example. Let's look at the root directory:

```
ubuntu@ubuntu:~$ ls /
bin cdrom etc initrd lib mnt proc root srv var tmp
boot dev home initrd.img media opt rofs sbin sys usr vmux
```

There's no \Program Files, no \Windows or \Winnt and no boot.ini. Here's what we do, and general statements about them that will help you find more at home:

+   /bin (short for binary) is where you'll find many of the commands you were introduced to in the last section. /sbin is simple, but for commands that only root should be running. /usr/bin and /usr/local/bin are other places to find binary files. "commandname" is a command you can run to find out where any command actually lives in the file hierarchy.
