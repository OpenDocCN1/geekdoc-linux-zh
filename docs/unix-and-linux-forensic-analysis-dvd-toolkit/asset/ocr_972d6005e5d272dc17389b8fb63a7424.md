# loginuid

This file will provide the UID used to access the system, which subsequently launched the process in question. This is somewhat complex as it bears further explanation. If I log to a system as my normal, non-privileged user, UID 502, then 0 sudo to root, ruin my code, and leave, loginuid will show 502, not 0 (root's UID).
This is what we are in the business call "awesome." It's also unfortunately dependent upon auditing being enabled in the kernel of the system you're examining.
