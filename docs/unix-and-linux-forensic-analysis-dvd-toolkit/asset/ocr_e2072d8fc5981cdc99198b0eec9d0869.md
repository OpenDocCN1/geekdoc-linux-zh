Next, we created the mount point, including the fact that sudo is required before creating a directory in /mnt. In the mount command itself, we specified the read only option just to be safe, and allowed mount to attempt to determine the file system type of your partition. The last line of the “mount” command output reveals that it mounted only (ro option happily displayed) with a type of fuseblk. It's an NTFS partition that I mounted, and that type is correct for NTFS. Fuse is used by NTFS-3G effort to bring reliable write capability to Linux (ntfs-3g). Finally note that the external drive was mounted noisy, which is why we don't want to hoist the SUID bits of any file system on our machine. because a file is trusted as SUID on someone else's system, doesn't mean that running as the superuser on many.

So, you've mounted a NTFS volume in Linux. Betcha that you can't mount a native ext3 partition in Windows without a lot more (and third-party software).

Finally, to unmount, it's simply the “umount” command with the mountpoint named. A quick verification that it's gone is always reassuring:

```
ubuntu@ubuntu~$ sudo umount /mnt/mywindrive/
unknown@ubuntu~$ mount
proc on /proc type proc (rw)
sysfs on /sys type sysfs (rw)
```
