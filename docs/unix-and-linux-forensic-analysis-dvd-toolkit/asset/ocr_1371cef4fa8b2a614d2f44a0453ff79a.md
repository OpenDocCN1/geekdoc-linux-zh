# init and runlevels

Init is the very first process on a Linux system. You may remember looking at it's entry in the /proc file system in Chapter 5 – PID 1. start all other process on the system. As all things UNIX, how does it not cut and dry as “it does it like so?” There are two general ways of doing things in UNIX-like systems: System V¹ and BSD² style. Linux distributions generally follow System V examples for most things, including init's tasks and processing runlevels. I will be discussing the System V style, as it is the most common.

init reads the /etc/initab file and executes the instructions inside. Here is a fairly standard Fedora Core 8 inittab.
The runlevels used by RHS are:

```
# Default runlevel.
# 0 halt (Do NOT set initdefault to this)
# 1 Single user mode
# 2 Multiuser, without NFS (The same as 3, if you do not have networking)
# 3 Full multiuser mode
# 4 unused
# 5 X11
# 6 reboot (Do NOT set initdefault to this)
```

```
id:5:initdefault:
```

This section defines the default runlevel the system will boot to. A runlevel describes the state a system is running. At runlevel 1, a certain set of services will run, at runlevel 2, another set, and so on through the runlevels. The seven runlevels are described above, but generally one of two will be the default: 3 (text-mode multi-user with networking) or 5 (graphical multi-user with networking).

```
# System initialization.
si::sysinit:/etc/rc.d/rc.sysinit
10:0:wait:/etc/rc.d/rc 0
11:1:wait:/etc/rc.d/rc 1
12:2:wait:/etc/rc.d/rc 2
13:3:wait:/etc/rc.d/rc 3
```
