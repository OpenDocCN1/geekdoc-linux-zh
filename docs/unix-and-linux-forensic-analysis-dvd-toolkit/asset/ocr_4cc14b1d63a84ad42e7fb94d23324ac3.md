# Mount points: What the Heck are They?

We've mentioned file system and mount several times. A mount point is simply an empty directory we create somewhere in the file hierarchy where we will access an internal disk partition, flash drive, or external hard drive. In Windows parlance, “c:\ can be thought of as the mount point for the first partition of the drive window recognized during boot. While the Windows ARC name for drive is something cryptic and awful like multi(X):disk(Y)disk(Z)partition, Windows kindly mounts that piece of hardware to a friendly mount point of c:\ that looks nicer at the command prompt and in Windows explorer. Likewise, Windows likes to mount the secondary master to d:\ than having to refer to the CD-ROM drive with a long nasty series of parentheses and digits. *unix eschews drive letters and instead allows you the flexibility to hang a drive nearly any directory name you like.This allows for /var to have its own file system if you like, your logs won't wedge your system if they fill the disk.You can dedicate a partition to /home so Joe User doesn't wedge the system downloading a bunch of movies from bittor. Instead, he'll fill up the disk that /home is mounted to. Users will still hate him, but at least running the daemons (think Windows “services”) will be able to write to their logs and e-mail will still get delivered.

Linux stores this disk device to file system to directory-name mapping information in what's known as “mount table.” The command allows you to list it out, and you have manual control over which devices are mounted by Linux:

```
ubuntu@ubuntu:~$ mount
proc /proc type proc (rw)
sysfs / /sys type sysfs (rw)
tmpfs / /lib/modules/2.6.22-14-generic/volatile type tmpfs (rw,mode=0755)
tmpfs / /lib/modules/2.6.22-14-generic/volatile type tmpfs (rw,mode=0755)
varrun /var/run type tmpfs (rw,noexec,nosuid,nodev,mode=0755)
varlock /var/lock type tmpfs (rw,noexec,nosuid,nodev,mode=1777)
udev /dev type tmpfs (rw,mode=0755)
devsm /dev/sh type tmpfs (rw)
devpts /dev/pts type devpts (rw,gid=5,mode=620)
tmpfs /tmp type tmpfs (rw,nosuid,nodedev)
```
