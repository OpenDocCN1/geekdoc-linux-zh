higher-than-normal privilege, however:setUID andsetGID executables. These are
executables that have the SUID or GUID bit set. When executed, rather than running
with the privileges of the user that launched the program, run with the privileges of
t user or group that owns the file. Generally, SUID/SGID root executables are
t most worrisome, but depending on the environment you are working in, other users
or groups may be of concern as well. A security vulnerability or misconfiguration in a
SUID/SGID executable can lead to an elevation of privileges on the local system.
Locating these files is very important.

The “find” command is your best friend when you need to quickly locate files
base on very specific criteria.

```
find / -perm -4000 -type f -xdev -print > suid.txt
find / -perm -2000 -type f -xdev -print > sgid.txt
```

These commands will begin at the system root (/) and find all files with
permissions (-perm) of 4000 or 2000 (setUID and setGID, respectively) that are nor-
al files (-type f) and print their full to standard output, which is redirected
to the names. We specify normal files to exclude block devices, characters devices,
sockets, and other similar items. The -xdev flag ensures that find won't descend into
directories you may search, on file systems such as NFS/SMB mounts, mounted CD/DVDs, and
any external storage you may have mounted. Unfortunately, this will also prevent
from descending into directories you may want to search, for example, a system that
has/var /tmp on separate partitions /. In this case, you may want to
substitute “-fype np” for -xdev. For more options, check the file man page.

# Recently Modified/Accessed/Created Files

If you have suspected some time frame for a compromise may have occurred, you
 easily look for all files modified, accessed, or created around or since that date.
For example, if a system administrator noticed unauthorized outbound IRC connec-
beginning five days ago, you could do the following:

```
find / -mtime 5 -xdev > modified.txt
find / -atime 5 -xdev > accessed.txt
find / -ctime 5 -xdev > created.txt
```

While it is certainly trivial to modify the timestamp of a file on a Linux system
using the (“touch” command), this is another place where attackers sometimes simply
do make the effort. The output of these files may be a little noisy, but they
should provide a starting point.
