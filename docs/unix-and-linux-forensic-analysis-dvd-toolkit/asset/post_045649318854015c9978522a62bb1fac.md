
# Understanding Unix • Chapter 2

It, like FAT, is a non-journaled file system, so fsck becomes a regular part of your world if you're ext2 user. Unlike FAT, ext2 knows all about file permission and security. ext3 is a closely related file system, which extends ext2 with journaling support. ReiserFS was a favored journaling file system prior to ext3's kernel integration (and prior to the author Hans Reiser becoming a person of interest in a criminal investigation in 2006).

In the larger *nix world, the file system gamut is enormous. UFS, ZFS, JFS, HFS, XFS, ODS-5... the list goes on. Details of these are available for the searching, but for the task of forensic analysis, every file system brings with it specific implementation details that you may have to research such as an unusual file system part of your next investigation.

## Ext2/Ext3

When dealing with Linux machines, Ext-based file systems will be found extremely frequently. The details of Ext2's implementation are documented in the design and implementation of the second extended file system at http://e2sprogs.sourceforge.org/net/ext2intro.html. With the sensitivity of forensic analysis to the intricacies of the underlying file system being analyzed (such as how the inode data structure is organized, the resulting effects of how the data is physically laid out on disk, and how “deleted” files may simply be unlinked with all of the data still persisting in slack space), I encourage you to give this resource a read.

Ext3 is an extension of Ext2 that added journaling to the mix to relieve us of those horribly long file system checks (by the fsck program available in paperback and man pages near you) when something has gone astray. Ext3's journaling extension to Ext2 is documented in this white paper: http://e2sprogs.sourceforge.org/net/journal-design.pdf

Depending on the *nix box you have to analyze, one of the first things you or tools will need to find is the filesystem type to use on the system. Remember friend the “mount” command as a means to display in-use file systems on a running system, and for probing in a read-only fashion or disk.

Happily, there are free tools available that understand the intricacies of the common *nix file systems and will help interpret and recover deleted damaged data not plainly visible in this file formats. Some of these tools include:

- http://en.wikipedia.org/wiki/List_of_file_systems has enough to make your head spin.
- Sleuthkit www.sleuthkit.org/sleuthkit/
- Linux Recovery www.diskinternals.com/linux-recovery/
- R-Studio www.data-recovery-software.net/

In addition, the following file slicers are filesystem-independent but are worth knowing about as well:

- Foremost http://foremost.sourceforge.net/
- Scalpel www.digitalforensicsolutions.com/Scalpel/
