# sys/

The /proc/sys directory contains a number of files that control kernel features. These can be written to, changing system behaviors on the fly. Never echo data into a file /proc unless you are absolutely certain of what you are doing (or on a test machine that you're okay with bricking). It is highly unlikely that you will need to delve into this area of /proc during the course of an incident.

# uptime

This file will tell you two things: how long the system has been running, and how much of time it spent idle. The latter we don't care about, but the former we do, for one very important reason. If you are told that the incident you are investigating occurred three days ago, and the system shows an uptime of 97,000 seconds (27 hours), you know that the machine has at the very least been rebooted, which is important information to be aware of during an incident response engagement.
