The other main source of information as to what happened on a system from a
log perspective is the various syslog logs. Depending on the environment the system
you are examining is in or come, it is entirely possible that it was logging to a
remote syslog server. Check /etc/syslog.conf to see which logging facilities are being
directed to files or hosts; remote logging will be noted by an @ symbol
ceding the host name. Here's a summarized example:

```
*.info;none;authpriv.none;cron.none /var/log/messages
authpriv.* /var/log/secure
mail.* @mail.server.localdomain
cron.* /var/log/cron
*.emerg *
uucp,news.crit /var/log/spool
local7.* /var/log/boot.log
```

In this case, if your investigation hinged on mail logs, you'd need to retrieve
them from mailog.server.localdomain. They won't be found on the local machine.
