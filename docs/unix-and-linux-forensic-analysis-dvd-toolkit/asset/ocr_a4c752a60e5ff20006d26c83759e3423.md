# Who

The key logs help determine who is involved in a given incident are the “last”
logs, utmp and wtmp.

utmp and wtmp are related. utmp is a database that records information
about users currently logged into the system. This data is rolled into wtmp,
which records historical data about logins. Generally this data is accessed on a live
system by the “who” and “last” commands, but the who and last command
also be used to read /var/run/utmp and /var/log/wtmp during a post-mortem
analysis:

# Where and What

Where an intruder went and what they did are questions that usually take more
than logs (e.g., forensics examination) to answer, there are some logs and
other files that can help out. Determining whether an intruder is not
if they used Secure Shell (SSH), thanks to the .ssh/known_hosts file. Every
time user connects to a remote host using SSH, that host’s Internet Protocol
(IP)/hostname and name are added to the known_hosts file, which is helpful if an
intruder uses SSH to connect to another host, either on the local area network
(LAN) or on the Internet.

Additionally, if the intruder required additional tools from a remote site to main- access or elevate privilege, this activity may be present in history files. Or
Linux systems, the default shell is usually /bin/bash, which creates a .bash_history file
