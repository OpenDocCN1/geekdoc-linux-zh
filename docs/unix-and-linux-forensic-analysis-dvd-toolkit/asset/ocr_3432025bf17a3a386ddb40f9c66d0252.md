In the corporate intrusion cases that I have worked, rarely has the incident been the result of an uber hacker writing 0day (oh-day) code on the fly.That is not to say that there are not people who are perfectly capable of doing that (in fact, I know at least three people who can), but it's simply not all of them. In fact, I would even go as far as say that if you are working a case in which you think the compromise is the result of a super master hacker with freakishly mad skills, I would recommend going over your day again. If I were a gambling man, my money would be on the fact that you probably missed something. Rather, the probable and far more realistic cause of system compromises is the result of a poorly configured host, or missing security patches.

When selecting a target, hackers will perform something commonly referred to as “active reconnaissance.” Basically, they are probing systems with externally facing interfaces that have vulnerabilities. A vulnerable service is something running on some port, which has some sort of security flaw in it. While that may seem to be a simplistic explanation, it is pretty accurate. The most commonly exploited services are Hypertext Transfer Protocol (HTTP), Hypertext Transfer Protocol Secure (HTTPS), Secure Shell (SSH), File Transfer Protocol (FTP), and Network Basic Input/Output System (NetBIOS). To illustrate, I ran a vulnerability search on Security Focus for the word “HTTP” and got 1705 pages with 15 hits per page. The other services had a large number of hits (Telnet - 25 pages, SSH - 12 pages, FTP - 80 pages, but were mild in comparison to number received from HTTP/HTTPS search. Needless to say, there is a huge number of vulnerabilities that need to be patched. If systems administrators remain diligent and employ a comprehensive patch management program, they are opening themselves up to an attacker. However, friends are quite literally asked to hit a moving target. If you watch any of the vulnerability reporting sites (in the Real Life Example) you will see there are new entries each week. Combine with the security flaws introduced into their networks by the Web applications they run (over which they have no control), and you will find that securing their front facing Web presence is a daunting task.
