# cwd

This is a link the processes' current working directory (cwd).

# environ

This file contains the environment variables for the process. This may not be of
consequence in most investigations, but may come into play if you are dealing with a
local privilege escalation attack. There are many cases where overly long or otherwise\malformed environment variables can be used to exploit root processes, and
this could be apparent in the environ proc entry for the compromised PID.
environ is a multi-line non-terminated file. What this is more than
using newline characters to indicate the end of a line, a null character is used,
using"cat" to dump the output isn't the easiest way to deal with this
data. Piping cat's output to xargs -0 -n 1 will print the output in a more digestible
format, like so:

```
root@localhost 1]# environ | xargs -0 -n 1
HOME=/linux
```

# exe

This is a symbolic link to the actual executable of the process, in this case /sbin/init.
If we had two processes named 'init', PID 1 and one PID 2349, for example,
we'd be able to quickly see that the /proc/2349/exe is link to /tmp/...0wnd/
init. This item also has another uses for which I will go later on.

# fd

This is a directory that contains all of the file descriptors for the process in question.
"init" has only one file open, /dev/initctl, so we'll look at a more interesting process,
hclientdesc:

```
dr-x------ 2 root root 2008-04-13 22:21 .
dr-xr-xr-x 6 root root 2008-04-13 18:52 ..
lrwx------ 1 root root 64 2008-04-13 22:21 0 -> /dev/null
lrwx------ 1 root root 64 2008-04-13 22:21 1 -> /dev/null
```
