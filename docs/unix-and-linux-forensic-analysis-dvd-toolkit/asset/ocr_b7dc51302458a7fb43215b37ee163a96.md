Core Impact (CI) is probably the best known commercial penetration testing tool (thanks to heavily advertising on securityfocus.com many other places), and has a very similar feature set. It is regarded to be more polished and mature than Canvas, but with its price tag and extremely draconian licensing it out of reach of many would attackers (and professional penetration testers as well). Like Canvas, CI has the ability to use a foothold of one compromised host as a launch point for other compromises using the CI agent. CI implements traffic–making features that help it evade IPSes, and the agent by which attacks are proxied in memory without leaving any footprint on the disk. CI runs on Windows systems, but by its agents and exploits are available for Windows, Linux, Mac OS X, AIX, Sun Solaris, and OpenBSD.

To detect either of these tools, extremely fine-grained logging would be required. To capture all of it in progress, monitoring of the network connections would be required.

# The Metasploit Framework

The Metasploit Framework (MSF) currently in version 3.1, was originally developed for penetration testing, IDS signature development, and vulnerability exploit research, and hit the top 100 network security tools survey at #5. In existence 2003, the original version was written in perl and was recently rewritten completely in Ruby and includes components written in C and Assembler. It is made up of a series of tools, libraries, modules, and user interfaces. The primary function of the framework is to launch attacks called "payloads.\ If the attack succeeds, the end user will gain access to the system through a remote shell.

Probably more than any other tool mentioned in the top, MSF is used by those who would seek to harm the computing systems they are targeting. Think of it like this, the attacks are already written for you; it is almost point-and-click hacking (and a much cheaper alternative to Canvas and CI). By the scanning and identification methods discussed earlier, an attacker can easily know what OSes are running, what ports are open, and what versions of services are being used. Once they have that information, they can find the corresponding payload in MSF and launch it. If it succeeds, they have a shell.
