- To immediately run the NFS, type:

```
# service nfs start
```

```
# chkconfig nfs on
```

# Configuring the /etc/exports file

The shared directory information entered into the Server Configuration window is added to /etc/exports file. Root user can use any text editor to configure the /etc/exports file to modify directory entries or add new ones. Here's an example of an /etc/exports file, which could include:

```
/cal *.net (rw,sync)      # Company
/pub (ro,insecure,all_squash)      # Public
/home (rw,squash uids=0-99)
```

The following text describes these entries:

- cal Represents a directory that contains information about the company. It is made accessible to everyone in the company's domain. Users can write to the directory as well as read them.

- The sync option, which is the default, is explicitly here to indicate that NFS will only reply to requests after changes have been committed to storage. The alternative is to use async, which allows new requests before changes are committed to improve performance, but can result in data corruption. (# Company events) simply reminds you of what the directory contains.

- pub Represents a public directory. Any computer can read files from the directory (by ro option), but not to write files. The insecure option enables any computer, even one that doesn't use NFS port, to access the directory. The all_squash option allows all users (UIDs) and groups (GIDs) to be mapped to nfsnobody user, giving them minimal permission.

- home This entry allows a set of users to share the same /home directory on different computers. Say, for example, that you are sharing /home from a computer named maple and spruce could map their own /home directory. The uids=0-99 is used to exclude any administrative login from another computer from changing files in the shared directory.

Of course, you can share any directories you choose (these were just examples), including the entire file system. There are security implications of sharing the whole file system or sensitive parts of it (such as /etc). Security options that you can add to your /etc/exports file are described throughout the sections that follow.

The format of /etc/exports file is:

```
Directory Host (Options) # Comments
```

Directory is the name of the directory you want to share. Host indicates the host computer that the sharing of this directory is restricted to. Options can include a variety of options to define the security measures attached to the shared directory for the host. (You can repeat Host/Option pairs.) Comments are any optional comments you want to add (following the # sign).

# Hostnames in /etc/exports

You can indicate in /etc/exports file which host computers have access to your shared directory. Be sure to have a space between each hostname. Here are ways to identify hosts:

* Individual host — You enter one or more TCP/IP hosts or IP addresses. If the host is in your domain, you can simply indicate the hostname. Otherwise, you can use the full host.domain format. These are valid ways of indicating individual host computers:

```
maple
map.handsonhistory.com
10.0.0.11
```

* IP network — To allow access to all hosts from a particular network address, indicate a network and its mask, separated by a slash (/). These are valid ways of indicating network numbers:

```
10.0.0.0/255.0.0.0
172.16.0.0/255.255.0.0
192.168.18.0/24
192.168.18.0/255.255.255.0
```

* TCP/IP domain — Using wildcards, you can include all or some host computers of a particular domain level. Here are valid ways using the asterisk and question mark wilds:

```
*.handsonhistory.com
*craft.handsonhistory.com
???.handsonhistory.com
```

The first example matches all hosts in the handsonhistory.com domain. The second example matches woodcraft, basketcraft, or any other hostnames ending in craft in the handsonhistory.com domain. The final examples match any three-letter hostnames in the domain.

> NOTE: You can also select multiple hostnames with spaces, but if you add options after each hostname, leave no spaces between the hostname and the parentheses. For example:

```
*.handsonhistory.com (rw) *.example.net (ro)
```

- NIS groups — You can allow access to hosts contained in an NIS group. To indicate an NIS group, precede the group name with an (@) sign (for example, @group).

# Access options in /etc/exports

The options that you can add to your /etc/exports file allow or limit access to shared directory. In the parts of each entry in /etc/exports, these are:

- ro — Only the exported file system read-only.
- rw — Explicitly set that shared directory be read/write.

# User mapping options in /etc/exports

Besides options that define permissions generally, you can also use options to set the permissions that specific users have on NFS.

One method that simplifies this is to have each user with the same name on all machines. This makes it easier to map users so that they have the same directory available for each user. If this is not convenient, UIDs can be mapped in many ways. There are some methods that follow:

- root user — Normally, the client's root user is mapped into nfsnobody user (UID 65534). This prevents the root user from a client from being able to change all files in the shared directory. If you want the client's root user to have root permission on the server, use the no_root_squash option.

> TIP: There may be other administrators, in order to root, that you recommend squaring UIDs 0-99 as follows: squash_uids=0-99.

- nfsnobody/group — By using nfsnobody user name and group name, you essentially create a user/group whose permissions will not allow access to files that belong to any reals on the server (unless those users open permission to everyone). However, files created the nfsnobody user or group will be available assigned as the nfsnobody user or group. To reset all users to the nfsnobody user/group, use the all_squash option.
