# Table 15-3: Private IP Addresses

| Network Class | Network Numbers | Addresses per Network Number |
|---|---|--|
| Class A | 10.0.0.0 | 167,777,216 |
| Class B | 172.16.0.0 to 172.31.0.0 | 65,536 |
| Class C | 192.168.0.0 to 192.168.255.255 | 256 |

So, for a small private LAN, the following numbers are examples of IP addresses that could be assigned to the host computers on your network. (You could use any of the network numbers, plus host numbers, from the table. These are just examples.)

+   - 192.168.1.1
- 192.168.1.2
- 192.168.1.3
- 192.168.1.4
- 192.168.1.5

You could continue numbering up to 192.168.1.254 on this network, and you could use a network mask of 255.255.255.0.

# Troubleshooting your LAN

After your LAN has been set up, your Ethernet cards installed, hostnames and addresses added, there are several methods you can use to check that everything is up and working. Some troubleshooting techniques are shown in the following sections.

# Did Linux find your Ethernet driver at boot time?

Type the following right you boot your computer to verify Linux found your card and installed the Ethernet interface:

```
dmesg grep eth
```

The dmesg command lists all the messages that were output by Linux at boot. The grep command causes only lines that contain the word eth to be printed. The first message shown appeared on my laptop computer with the NETGEAR card. The second example is from my computer with the EthernetPro/100:

```
eth0: Compatible: port 0x300, irq3, hw_addr 00:B0:C8:8E:49
eth0: OEM 48257/48258 10/Ethernet at 0xccc0, 00:90:27:4e:67:35, IRQ 17.
```

The message in the first example shows that a card was found at IRQ3 with a port address of 0x300 and an Ethernet hardware address of 00:B0:C8:8E:49. In the second example, the card is at IRQ 17, the port address is 0xccc0, and the Ethernet address is 00:90:27:4e:67:35.
