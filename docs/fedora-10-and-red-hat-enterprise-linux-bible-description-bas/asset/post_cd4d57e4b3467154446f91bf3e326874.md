## Security options

Of the security options, the first option (**security**) is the most important to get right. It defines the type of security used to access the shared file systems and printers to the clients. (To see some of the fields described here, you need to click the Advanced view.)

- **security** — Sets how password and user information is transferred to the Samba server from the client. As noted earlier, it's important to get this right. The default value for security (`security-user`) is different than the default value for security (`security-share`) in pre-2.0 versions of Samba. If you are coming from an older version of Samba and are clients to access your server, this setting is a good place to start. Here are your common options:

- **user** — The most common type of security used to share files and printers to Windows 95/98/2000 and Windows NT clients. It is the default with Samba in the current release. This setting is appropriate if users are doing a lot of file sharing (as opposed to a Samba server used mostly as a print server). It requires that a user provide a user name/password before using the server.

The easiest way to do this is to get a Linux user client user who will use the Fedora or RHEL Samba server. This provides basically the same file permissions to a user account through Samba as the same user would get if he or she logged directly to Linux.

- **share** — The share value for security works best for print sharing or for providing file access that is more public (guest sharing). A client doesn't need to provide a valid user name and password to access the server. However, the user will typically have a “guest” level of permission to access and change files. See the sidebar describing guest accounts for further information.

- **server** — The security option that, from the client's point of view, is the same as user security, in that the client shall provide a valid user name/password combination to use the Samba server at all. The difference is on the other side. With server security, the user name/password is sent to SMB server for validation. If this fails, Samba will validate the client using user security.

- **domain** — This security option also, from the client's point of view, looks the same as user security. This is used only if the Samba server has been added to a Windows domain (using the `net join` command). When a client tries to connect to the Samba server in this mode, its user name and password are sent to a Windows NT Primary or Backup Domain controller. This is accomplished the way that a Windows NT server would perform validation. Valid Linux accounts must still be set up.

- **ads** — This security option causes Samba to act as a domain in an ADS realm. Kerberos must be installed on the Samba machine to use this option. Samba must also join the ADS realm (see the `net utility`).

- **auth methods** — The authentication method used by the Samba server (smbd). Leave the default in most cases. Authentication methods you can choose anonymous access (guest), relay authentication through winbind (winbind), winbind NT authentication (nt.domain), local lookups on netbios or domain name (sam), or remote DC authentication of trusted users (trustdomain).

- **encrypt passwords** — Controls whether encrypted passwords can be negotiated with the client. This is (yes) by default. For domain security, this value must be Yes. Later versions of Windows (4.0 SP3 or later) and Windows 98 and Windows 2000 expect encrypted passwords to be on. (See the "Setting Samba clients" section for information on getting clients to use encrypted passwords.)

- **client channel** — Choose if the client is to require the use of netlogin channel (yes), offer channel doesn't enforce it (auto) or not even offer channel (no).

- **server channel** — Choose if the client is to require the use of netlogin channel (yes), offers channel doesn't enforce it (auto) or not even offer channel (no). If you set this to no, you must apply the Windows XP WinXP_SignOrSeal.reg file available from the Samba project.

- **passdb account** — Choose the method of storing the backend database to store passwords. By default, a TDB-based method is used (tdbs using a file named passdb.tdb. Other options include smpasswd (Samba password storage style) and ldaps (LDAP-based storage style).

- **guest account** — Specifies the user name for the guest account. When a service is specified as Guest OK, the user name entered will be used to access that service. The account is usually `nobody`. TIP: Make sure that the guest account is a valid user. (The default of `nobody` should already be set up.) With an invalid user as the guest account, the IPC connection fails.

## Assigning Guest Accounts

Samba always assigns the permissions level of a valid user on the Linux system to clients who use the server. In the case of share security, the user is assigned a guest account (nobody by default). If the guest account value is not set, Samba goes through a fairly complex set of rules to determine which user account to use. The result is that it can be hard to assure which user permissions will be assigned in each case. This is why it is recommended to use user security if you want to provide specific user access to your server.

- invalid users — Can contain a list of users that should not be allowed to log in. Add an @) before a name to have it interpreted as an NIS or UNIX (Linux) group name.
- valid users — Add a list of users who should be allowed to log in to the service. If nothing is in it or invalid users field, any user is allowed to log in.
- admin users — Can contain a list of users who have administrative privileges associated with a Samba share.
- read list — Can contain a list of users who have only read-only access to a service.
- write list — Can contain a list of users who have read/write access to a service.
- printer admin — Add users to this list that want to remove administrative control Samba printers using the MS-RPC service, typically by a NT workstation.
- hosts allows — Contains a list of one or more hosts that are allowed to use your computer's Samba services. By default, users from any computer can connect to the Samba server (of course, they must have to provide user names and passwords). Usually, you can use this option to allow connections from specific computers (such as 10.0.0.1) or computer networks (such as 10.0.0.) which are excluded by the hosts option.
- hosts deny — Contains a list of one or more hosts from which users are not allowed to use your computer's Samba services. You can make this option fairly restrictive, and then add the specific hosts and networks you want to use the Samba server. By default, no hosts are denied.
- preload modules — Contains a list of modules you want to be loaded into the smbd daemon before any clients can connect to the service.
