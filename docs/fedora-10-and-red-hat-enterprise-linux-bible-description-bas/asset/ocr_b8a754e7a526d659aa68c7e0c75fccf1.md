# Access options in /etc/exports

You don't have to give away your files and directories when you export a directory with NFS. In the parts of each entry in /etc/exports, you can add options that allow or limit access by setting read/write permission. These options, which are passed to NFS, are follows:

+   - ro — Only the client to mount the exported file system read-only. The default is to mount the file system read/write.
- rw — Explicitly set that shared directory be shared with read/write permissions. (If the client chooses, it can still mount the directory read-only).

# User mapping options in /etc/exports

Besides options that define permissions are handled generally, you can also use options to set the permissions that specific users have on NFS shared files.

One method that simplifies this is to have each user with multiple accounts have the same user name and UID on each machine. This makes it easier to map users so that they have the same permission on a mounted file system as do files stored on their local hard disk. If this is not convenient, UIDs can be mapped in many ways. There are some methods of setting user permissions and the /etc/exports option that you use for each method:

+   - root user — Normally, the client's root user is mapped into the nfsnobody user name (UID 65534). This prevents the root user from a client from being able to change all files and directories in the shared file system. If you want the client's root user to have root permission on the server, use the no_root_squash option.

> TIP: There may be other administrators, in order to root, that you recommend squaring UIDs 0-99 as follows: squash_uids=0-99.

+   - nfsnobody/group — By using nfsnobody user name and group name, you essentially create a user/group whose permissions will not allow access to files that belong to any reals on the server (unless those users open permission to everyone). However, files created the nfsnobody user or group will be available assigned as the nfsnobody user or group. To reset all users to the nfsnobody user/group, use the all_squash option.

The nfsnobody user is assigned to UIDs and GIDs of 65534. This prevents the ID from running into a valid user or group ID. Using anonoid or anongid options, you can change the nfsnobody user or group, respectively. For example, anonuid=175 sets all anonymous users to UID 175 and anongid=30 sets the GID to 300. (Only the number is displayed when you list file permission, however, unless you add entries with names to /etc/password and /etc/group for the new UIDs and GIDs).
