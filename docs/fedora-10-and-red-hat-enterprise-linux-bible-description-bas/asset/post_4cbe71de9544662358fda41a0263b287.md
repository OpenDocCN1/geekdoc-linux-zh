Every piece of information you store in your LDAP directory must fall under a base distinguished (or base dn). Because many organizations these days can be represented by a unique Domain name, the domain name is a popular way to identify your LDAP base dn. For the examples in this chapter, the base distinguished name I use is linuxtoys.net. If you are creating an LDAP directory for an organization that can be represented by a domain name, you can replace linuxtoys.net with your domain name.

If you are creating an LDAP directory structure for a larger organization (or other words, more than just a simple address book as I am doing here), you need to think about how your directory structured. You may want to add country codes (us, it, and so on) under your base distinguished name for a multinational company.

## Setting Up the OpenLDAP Server

All the software packages you need to set up an OpenLDAP server are included on the DVD that comes with Fedora and RHEL distributions. As an alternative, you can easily install the packages over the Internet using yum. With those packages installed, you can start configuring your OpenLDAP server.

## Installing OpenLDAP packages

To configure your OpenLDAP server, you should start by installing all the openldap packages from your Fedora or RHEL distribution. First, check which openldap packages are installed:

```bash
# rpm -qa "openldap*"
```

You need the openldap-devel package only if you are developing LDAP applications. Otherwise, you can install the openldap, openldap-clients, and openldap-servers packages from the DVD that comes with books.

- 3. Add backend database definitions. In the slapd.conf file, you need to define some backend database definitions. Each set of backend definitions applies to a group of databases of the same type.

Here's an example of how the backend database definitions would appear for a computer in the domain named linuxuxoys.net (of course, you would replace linuxuxoys and net with those of your domain):

```text
######################################
# ldbm and/or bdb database definitions
######################################

database     bdb
suffix       "dc=linuxuxoys,dc=net"
directory    /var/lib/ldap
rootdn       "cn=Manager,dc=linuxuxoys,dc=net"
cachesize   10000
searchstack 8
dbnosync
dirty-read
```

This database is of the type bdb (Berkeley DB transactional backend), which defines how data for this directory are stored. The ldbm (Lightweight Directory Access Protocol Proxy backend) database is another type you can use. The suffix specifies that queries to this slapd server for linuxoys.net are directed to this database. The directory identifies the /var/lib/ldap directory as the location for this LDAP directory.

The rootdn line indicates that root access can be granted to change databases associated with linuxoys.net distinguished name (provided the password is supplied with rootpw, as described in the next step). I added the four options to improve performance of the bdb database (type man slapd-bdb for details).

- 4. Add a password. In the slapd.conf file, you need to enter the password that is required to modify your OpenLDAP backend. By default, the rootpw defines a clear-text string that is your password. The password will give you full control of the backend database. It will look something like the following:

```text
rootpw
mysecret
```

> NOTE: If you are going to use a clear-text password, you should make sure that your slapd.conf file has read permissions to the world (chmod 640 /etc/ldap/slapd.conf). See "Creating an Encrypted Password" for information on creating an encrypted password to access your OpenLDAP database.

## Creating an Encrypted Password

To create an encrypted password for the administrator of the OpenLDAP database you can use the slapassword command. You can create the password using Crypt, SSAH, SMD5, MD5, or SSH encryption. Here's an example of creating a password for OpenLDAP using MD5 encryption:

```bash
# slapassword -h (md5) > /tmp/myslap
New password: ********
Re-enter password: ********
# cat /tmp/myslap
```

## Starting the OpenLDAP service

You start OpenLDAP as you do most services in Fedora and RHEL systems, using the service and chkconfig commands. The service name for OpenLDAP is ldap. To start the service immediately, type the following:

```bash
# service ldap start
Starting slapd:                               [ OK ]
```

To set the ldap service to start each time the system is reboot, type the following:

```bash
# chkconfig ldap on
```

By default, the ldap service will read permissions open to everyone.

## Setting Up the Address Book

When I set up the structure of the address book database, I base the distinguished name (dn) for the database on the organization's name (in this example, linuxuxoys).

With the suffix set to linuxuxoys.net (suffix "dc=linuxuxoys,dc=net") in the slapd.conf file (which yours will be different), the backend database is set up to handle queries to the distinguished name (dn) linuxuxoys.net. You can create the structure for the address book for that distinguished name.

> NOTE: The dc stands for Domain Component. When you include a domain name as your distinguished name, in the order which you put the parts of that domain name place the part closest to the DNS root last. In this example, the dc=linuxuxoys comes before dc=net. See RFC 2247 if you are interested in the specification for including domain names in LDAP directories.

You want create the address book file in a format that can be loaded into the OpenLDAP database. The format you need is referred to as LDAP Data Interchange Format (LDIF).
