# Choosing Backup Tools

While the rsync command is one of the best choices for doing backups it is by no only tool available. Many Linux systems administrators use a variety of commands for backups, often writing scripts to combine commands together. They might group files in a single archive using tar or cpio, compress to backup using bzip2 or gzip, or write whole directory structures of files using mkiffs.

Descriptions of backup tools in this chapter focus on those that are particularly designed for backups. The dump and restore are traditional UNIX commands for backing up and restoring files. The mkiffs and ddrecord commands can combine a file system into an ISO image and copy that image to CD or DVD. As for networked backup facilities, the Amanda facility is discussed later in this chapter. The pax file facility provides a method of creating copy tar and archives.

If the tools for backing up files in this chapter are not exactly what you are looking for, there are many open source backup facilities that you can add to your Fedora or RHEL system. Here are a few examples:

+   * Bacula (http://bacula.org) — Bacula is a tool for managing network backups. It includes features to make it easy to recover files that have been lost or damaged. Support for backup media includes tape, CD, and hard disk media.
* Mondo Rescue (www.mondrescue.org) — Mondo supports backups from LVM, RAID, ext2, ext3, JFS, ReiserFS, and VFAT file systems. Backups can be done to CD-R, CD-RW, NFS, or hard disk.
* BackupPC (http://backuppc.sourceforge.org) — BackupPC is useful for backing up both Linux and Windows systems over a network. Using BackupPC, you can extract backups using Samba, tar (over ssh, rsh, or nfs) or rsync.
