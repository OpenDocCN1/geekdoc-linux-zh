| routed | Starts or stops the routed daemon, which controls dynamic-routing table updates via the Router Information Protocol (RIP). |

| syslog | Starts or stops the klog and syslog daemons that handle logging events from the kernel and other processes, respectively. |

| xfs | Starts or stops xfs, the X Window daemon. |
| xinetd | Sets the machine's hostname, establishes network routes, and controls xinetd, the network service daemon listens for incoming TCP/IP connections to the machine. |

| xfs | Regenerates font lists and stops the X font server. |

# Understanding startup scripts

Despite the complicated rc files, scripts, and keys, the form of each startup script is quite simple. Because they are in plain text, you can open one with a text editor to take a look at what it does. For the most part, a run-level script can be run with a start option, a stop option, and possibly a restart option. For example, the following lines are part of the contents of the smb script that defines what happens the script is run with different options to start or stop the Samba file and print service:

```
#!/bin/sh
# config: -91 35
# description: Starts and stops the Samba smbd daemon \
# used to provide SMB network services.

start() {
    K="$SMB"
    echo -n "Starting $KIND services: "
    daemon smbd $SMBDPOPTIONS
    RETVAL=$?
    echo
    if [ $RETVAL -eq 0 -a $RETVAL2 -eq 0 ] && touch /var/lock/subsystem/smb || \
        return $RETVAL
    fi
}

stop() {
    KIND="$SMB"
    echo -n "Shutting down $KIND services: "
    killproc smbd
    RETVAL=$?
    echo
    if [ $RETVAL -eq 0 -a $RETVAL2 -eq 0 ] && rm -f /var/lock/subsystem/smb \
        return $RETVAL
    fi
}

restart() {
    stop
    start
}
```

To illustrate the essence of what this script does, I skipped some of the beginning and end of the script (where it checked if the network was up and running and set some values). Here are the actions smb takes when it is run with start or stop:

- start: This part of the script starts the smbd server when the script is run with the start option.
- stop: When run with the stop option, the /etc/init.d/smb script stops the smbd server.

The restart option runs the scripts with a stop option followed by a start option. If you want to start the smb service yourself, type the following command (as root user):

```
# service smb start
Starting SMB services:    [ OK ]
```

To stop the service, type the following command:

```
# service smb stop
Shutting down SMB services:    [ OK ]
```

The smb run-level script is different from other run-level scripts in it supports several other options than start and stop. For example, this script has options (not shown in the example) that allow you to reload the smb.conf configuration file (reload) and check the status of the service (status).

# Changing run-level script behavior

Modifying the start behavior of any such script merely involves opening the file in a text editor.

For example, the atd dequeues jobs submitted from the at and batch commands. Jobs submitted via batch are executed only if the system is not above a particular value, which can be set with a command-line option to the atd command.

The default limiting factor value of 0.8 is based on the assumption that a single-processor machine with less than 80 percent CPU utilization could handle the additional load of the batch job. However, if you were to add another CPU to your machine, 0.8 would only represent 40 percent of the computer's processing power. So you could safely increase that limit without impacting overall system performance.

You can change the limiting factor from 0.8 to 1.6 to accommodate the increased processing capacity. To do this, modify the following line (in the start section) of the /etc/init.d/atd script:

```
daemon /usr/bin/atd
```

Replace it with this line, using the -l argument to specify the new minimum system load value:

```
daemon /usr/bin/atd -l 1.6
```

After saving the file and editing the editor, you can reboot the machine or just any of the following three commands to begin the new batch threshold value:

```
# service atd reload
# service atd restart
```

```
# service atd stop ; service atd start
```

> NOTE: Always make a copy of a run-level script before you change it. Also, keep track of changes that you make to run-level scripts before you upgrade the packages they come from. You need to make those changes after the upgrade.

If you are uncomfortable editing startup scripts and you simply want to add options to the daemon process by editing the script, check the /etc/sysconfig directory and see if there is a file by the same name as the script you want to modify. If there is, that probably provides values that you can pass to the script. Sysconfig files exist for apmd, arpwarp, dhcpd, nptpd, samba, and others.

# Reorganizing or removing run-level scripts

There are several ways to deal with removing programs from the system startup directories, adding them to particular run levels, or changing when they are executed. From a Terminal window, you can use the chkconfig command. From a GUI, use the Service Configuration window.

CAUTION: You should never remove the run-level file from the /etc/init.d directory. Because no scripts are run from /etc/init.d automatically, it is okay to keep them. Scripts in /etc/init.d are only accessed as links from the /etc/rcX directories. Keep scripts in init.d directory so you can add them by re-linking them to the appropriate run-level directory.

To reorganize or remove run-level scripts from the GUI, use the Service Configuration window. Select System -> Administration -> Services or log in as root user and type the following command in a Terminal window:

```
# system-config-services
```

Figure 12-1 shows an example of the Service Configuration window.

The Service Configuration window allows you to reconfigure services for run levels 2, 3, 4, and 5. Icons next to each service indicate whether the service is currently enabled (green) or disabled (red) for the run level and whether not the service is currently running. Select a service to see a description of that. Here is what you can do from this window:

- Enable: With a service selected, click the Enable button to enable the service when you start your computer (run levels 2, 3, 4, and 5).
- Disable: With a service selected, click Disable to not have the service start when you boot your computer (otherwise enter run levels 2, 3, 4, or 5).
- Customize: With a service selected, click Customize and select the run levels which you want the service to start.
