# Part III: Administering Fedora and RHEL

| Dump Options | Description |
|---|---|
| -h level | Files can be marked with a `nodump` attribute. This option specifies the dump level at or above which the `nodump` attribute is honored. This option takes a numeric argument of 1-9. |
| -f file | The name of the file or device to write the dump to. This can be a file or device on a remote machine. |
| -d density | Sets the tape density. The default is 1600 bits per inch. This option takes a numeric argument. |
| -n | When a dump needs attention (such as change to a tape), dump will send a message to all of the users in the operator group. This option takes no arguments. |
| -s feet | Specifies the length in feet of the tape density. This calculation is dependent on tape density (option d) and the dump record (options B and b). This option takes a numeric argument. |
| -u | Record backup in the `/etc/dumpdates` file. It is a good idea to use this option, especially if you are creating incremental backups. |
| -t date | Specify a date and time on which to begin backups. Files modified or added after that time will be backed up. This option causes dump to ignore the `/etc/dumpdates` file. It takes a single argument, in a format specified by the cman page. |
| -W | This option dump to list the file systems that need to be backed up. It does this by looking at the `/etc/dumpdates` file and the `/etc/fstab` file. |
| -w | This works with the `w` option but lists the individual files that should be backed up. |

Thus, a typical dump command may look similar to the following:

```
# dump 0Uf 500000 /dev/qft0 /dev/sda6
```

This command results in dump performing a zero level (full) backup of the `/dev/sda6` file system, storing the backup on the tape drive and recording results in `/etc/dumpdates`. The B option is used to ensure the expected tape block count to 500000; otherwise, dump will prompt for a new tape earlier than needed. The dump command prints status messages to the screen, letting you know how far the backup has progressed and how much time it will take to complete. The output looks similar to this:

```
DUMP: Date of this 0 dump: Sat Aug 23 23:33:37 2003
DUMP: Dumping /dev/sda6 (/home) to /dev/qft0
DUMP: Exclude 23 journal inode 8
DUMP: Label: /home
DUMP: mapping (Pass I) [regular files]
DUMP: mapping (Pass II) [directories]
DUMP: estimated 93303 tape blocks on 0.19 tape(s).
DUMP: Volume 1 started with block 1 at: Sat Aug 23 23:33:47
```
