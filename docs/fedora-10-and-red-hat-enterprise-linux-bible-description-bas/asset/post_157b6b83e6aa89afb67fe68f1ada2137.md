
# Part IV: Fedora RHEL Network and Server Setup

The KeepAliveRequests directive sets a limit on the number of requests that can be handled with one connection. The default value is certainly reasonable because most connections will hit the KeepAliveTimeout before KeepAliveRequests.

The KeepAliveTimeout directive specifies the number of seconds to hold the connection while awaiting another. You might want to increase the default (15 seconds). Reasons for a longer timeout could allow all the images on the page to be downloaded on the same connection or to take into account how long you might make a client to peruse your average page and select a link from it. The Web application you are using may also need a longer connection. (Of course, a longer KeepAliveTimeout prevents each server from moving to another client during this time, so you may find that you need to add more request processes to account for that.)

# Setting the number of server processes

To operate efficiently, a Web server has to handle lots of incoming requests for content simultaneously. To be ready for Web content, Apache (as it is set up in Fedora) has multiple processes (httpd daemons) running and listening to service requests. These servers can, in turn, direct requests to multiple threads to serve the content requests.

With the Multi-Processing Module (MPM) feature (introduced in Apache 2.0), support for threads was added to Apache. On an operating system that supports Native POSIX Thread Libraries (which Fedora and RHEL do), threading allows Apache to improve performance by needing fewer process slots and less memory for the server it needs. Adding threads consumes fewer resources than processes.

For a low-volume Web server, you can probably leave the parameters alone that support the MPM feature. You will probably have enough processes to handle your incoming requests, but not so many that they will be a drain on your server. If your server needs to serve up lots of content consistently, or respond occasionally to large spikes of requests, you should consider tuning the MPM-related parameters in the httpd.conf file.

Here are a few to consider if you want to change any of the MPM-related parameters:

- RAM is critical — Every process and thread that is active consumes some amount of memory. If the number of active processes and threads goes beyond the amount of RAM you have, your computer will begin to use swap space and performance will degrade quickly. Make sure this is enough RAM on your system to handle the maximum number of server processes and threads you expect to run on your Apache server.
- Configure for maximum load — Apache is able to create new server processes and threads as they are needed. You don’t have to have the maximum number of processes and threads available at all times. Instead, you can configure the maximum number of servers and threads that Apache can dynamically add as demand on the server requires.
- Configure for performance — Performance degrades when Apache has to start a new thread (small amount), start a server process (greater amount), or use swap space (greatest amount). In the perfect world, the exact number of servers needed should be the default number of servers running, with a few spares to handle reasonable spikes. If response is critical, you might opt to have more servers running than you need so that performance isn't hurt when spikes come.

When Apache starts up, it launches a set number of httpd server processes (parent and child) to handle incoming requests for content. Parameters for defining how many server processes are available include those set:

- How many child processes should be started by httpd (StartServers)
- The minimum number of idle processes kept spare (MinSpareServers)
- The maximum number of idle processes kept spare (MaxSpareServers)
- The maximum number of servers over the life of the server (ServerLimit)
- The maximum number of server processes to start (MaxClients)

Parameters for defining how many threads are available for each httpd process include those set:

- The minimum number of spare threads should always be available, after which more will be created (MinSpareThreads)
- The maximum number of spare threads, after active threads will be deleted back to the number per child (MaxSpareThreads)
- The number of threads available to each child (ThreadsPerChild)

The following example shows how MPM-specific parameters in httpd.conf are set for prefork.c (non-threaded module) and worker.c (multithreaded multiprocess module).

## Server Pool Size (MPM specific)

```
<IfModule prefork.c>
StartServers 8
MinSpareServers 5
MaxSpareServers 20
ServerLimit 256
MaxClients 256
MaxRequestsPerChild 4000
</IfModule>
```

```
<IfModule worker.c>
StartServers 2
MaxClients 150
MinSpareThreads 25
MaxThreads 75
ThreadsPerChild 25
MaxRequestsPerChild 0
</IfModule>
```

Apache starts a daemon process by root that binds to the appropriate port, and switches to the unprivileged user (the apache user, equivalent to the value of StartServers in prefork.c). Apache attempts to intelligently start and kill servers on the current load. If the amount of traffic decreases and there are too many idle servers, some will be killed (down to the number noted in MinSpareServers). Similarly, if many requests arrive in proximity and there are too few servers waiting for new connections, more servers will be started (up to the number noted in MaxClients).

NOTE: Getting the value of MaxClients is critical because it puts a lid on the total number of simultaneous connections that can be active. If MaxClients are in use, no will be created and subsequent requests to the server will wait until one is freed up.

Using the values specified above, when the daemon started, eight child processes run waiting for connections (as defined by StartServers). As more requests arrive, Apache will ensure that at least five processes are ready to answer requests. When requests have been fulfilled and new connections arrive, Apache will keep killing processes until the number of idle server processes is below 20. The value of StartServers should always be somewhere between MinSpareServers and MaxClients.

Apache limits the total number of threads by the MaxClients directive. The default value is 150, which should be sufficiently high. However, if you find that frequently many threads are running, remember that any connection beyond 150 will be rejected. In such cases, if your hardware is sufficiently powerful (and your network connection can handle the load), you should increase the value of MaxClients.

NOTE: You can see the state of your Apache server processes and get a feel for the server's activity by viewing the server-status page for your server, described later in this chapter. The ps -fu apache command will show you if the Apache server processes (http daemon) are currently running.

To minimize the effect of possible memory leaks (to keep the server pool fresh), each server process is limited in the number of requests it can handle (equal to the value of MaxRequestsPerChild). After serving 4000 requests (the value specified above), the process will be killed. It is more accurate to say that each process serves 4000 connections because all KeepAlive requests (occurring before encountering KeepAliveTimeout) are calculated as just one request.

In a multiprocessor environment, setting thread values described previously can both limit the number of threads that servers can consume and as many threads as you will allow to handle server processing. MinSpareThreads and MaxSpareThreads control the number of threads that are not being used. If spare threads go above MaxSpareThreads, some are dropped.

# Binding to specific addresses

You can bind to IP addresses using the Listen directive. Listen directives can be used to add to the default bindings you already have:

```
# Listen: Allows you to bind Apache to specific IP addresses and/or
# ports, in addition to the default. See also the <VirtualHost>
# directive.
# Change this to Listen on specific IP addresses as shown below to
# prevent Apache from glitch onto all bound IP addresses (0.0.0.0)
#Listen 12.34.56.78:80
Listen 80
```

The Listen directive is more flexible than the BindAddress directive. Multiple Listen commands can be specified, enabling you to specify several IP address/port combinations. It can also be used to specify just IP addresses or port numbers.

By default, Apache listens to port 80 (for standard http services) and port 443 (for secure https services) on all interfaces on the local machine (which Web browsers expect to find Web content). Listening on only localhost:80 restricts access to only the local machines. A web server run by a non-privileged user will bind to port 8080 (only root can bind to ports lower than 1024). If you have multiple network cards, you can limit which Apache listens on (for example, you can have a Web server only intended for the company LAN which is not exposed to your Internet interface).
