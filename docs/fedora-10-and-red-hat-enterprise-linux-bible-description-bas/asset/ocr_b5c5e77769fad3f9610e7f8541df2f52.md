# Chapter 2: Installing Fedora 73

+   - You can have up to 63 partitions on an IDE hard disk. A SCSI hard disk can have up to 15 partitions. You probably won't need nearly many partitions.

If you are using Fedora RHEL as a desktop system, you probably won't need a lot of different partitions within your Linux system. There are, some very good reasons for having multiple partitions for Linux systems that are shared by a lot of users or are public Web servers or file servers. Multiple partitions within Fedora or RHEL offer these advantages:

+   - Protection from attacks — Denial-of-service attacks take that action to fill up your hard disk. If public areas, such as /var, on separate partitions, a successful attack can fill a partition without shutting down the whole computer. Because /var is the default location for Web and FTP servers, and therefore might hold a lot of data, even hard disks are assigned to the /var file system.

+   - Protection from corrupted file systems — If you have only one file system (/), corruption of that file system can cause the Fedora or RHEL system to be damaged. Corruption of a smaller partition is easier to correct and can often allow the computer to stay in service while the corruption is fixed.

Here are some directories you may want to consider making into separate file system partitions:

+   - /boot — The BIOS in older PCs can only access the first 1024 cylinders of your hard disk. To make sure that the information in your /boot directory is accessible to the BIOS, create a separate partition (of only about 100MB) for /boot and make sure that exists the rest of your Linux system can exist outside of that 1024-cylinder boundary if you like. With several boot boots, there is rarely a reason for /boot to be larger than 100MB. For newer hard disks, you can sometimes avoid this problem by selecting the Linear Mode check during installing. The boot partition can be anywhere on the disk.

+   - /usr — This directory contains most of the applications and utilities available to Fedora or RHEL users. Having /usr on a separate partition lends that your file system remains read-only after the operating system has been installed. This prevents attackers from replacing or removing important system applications with their own versions that may cause security problems. A separate /usr partition is also useful if you have workstations on your local network. Using NFS, you can share /usr over the network with those workstations.

+   - /var — Your FTP (/var/ftp) and Web-server (/var/www) directories are, by default, stored under /var. Having a separate /var partition can prevent an attack on those facilities from corrupting or filling up your hard disk.

+   - /home — Because your user account directories are located in this directory, having a separate /home account can prevent an indiscriminate user from filling up your hard disk. (Disk quotas represent another way of controlling disk use. See Chapter 10.)
