Setting up a DHCP server enables you to centrally manage the addresses and other network information for client computers on your private network. With DHCP configured on your network, a client computer can simply indicate that it wants to use DHCP and the DHCP server can provide its IP address, network mask, DNS server, NetBIOS server, (gateway), and other information needed to get up and running on the network.

With DHCP, you can greatly simplify the initial network configuration that each client computer on your network needs to do. Later, as your network evolves, you can easily update information, having changes automatically picked by clients when they restart their network interfaces.

> NOTE: Although this chapter focuses on the configuration of DHCP client and services on your Fedora and RHEL systems, your Fedora or RHEL client can use the services of other network dev. For example, you might have a Cisco routing, a DSL/Cable device with DHCP services, or even a Windows-based DHCP server. DHCP clients for Fedora and RHEL will not have trouble with any-standards DHCP server.

To configure the DHCP server described in this chapter, you now need to have the dhcp package installed (yum install dhcp).

# Setting Up a DHCP Server

To configure a DHCP server you need to install the dhcp package. Assuming you have already set up the physical connections between your DHCP server and the client computers on your network (presumably an Ethernet LAN), the minimum tools you need to get the DHCP server working are:

- * A Firewall that allows requests for DHCP service
- A configured /etc/dhcp.conf file
- * A running dhcpd daemon (which can be started at boot time)

After the DHCP server is running, it listens to UDP port 67 for requests from DHCP clients on the LAN. A client simply boots up (with an Ethernet interface turned on and DHCP identified as its method of getting network addresses). This causes the client to send out a DHCP discovery request to 255.255.255.255 (the global broadcast address). The DHCP server picks up that request and feeds the client the information it needs to get and running on the network.

> NOTE: The dhcpd.conf file can serve a wide range of configuration information to DHCP clients. see the full set of options and parameters you can set in that file, refer to the dhcp-options man pages.

## Opening your firewall and SELinux

The firewall on your DHCP server must be configured to allow access to UDP ports 67 and 68. The easiest way to do this is to select System -> Administration -> Firewall from the GNOME desktop. From the Firewall window that appears select Other Ports and add ports 67 and 68. If you prefer to use iptables directly to change your firewall, you can add a new rule to iptables and then save the changes. Type the following as root:

```bash
iptables -I INPUT -i eth0 -p udp --sport 67:68 --dport 67:68 -j ACCEPT
```

In this example, requests are allowed from source and destination ports on eth0 interface (which may need to figure out if eth1, or some other card is connected to your LAN). If the rule was added (type iptables -L -n to make sure), you can save your configuration so that the new rule is included permanently. To change your firewall, type the following (as root):

```bash
service iptables save
```

This updates your /etc/sysconfig/iptables file so that all current rules (including the one you just added) are included the next time iptables is restarted. To restore your firewall settings without rebooting, use the iptables-restore command:

```bash
iptables-restore < /etc/sysconfig/iptables
```

SELinux should not block operations of dhcpd daemon. If it does, however, you can consider SELinux to permissive by setting force 0.

## Configuring the /etc/dhcpd.conf file

Suppose you have a pool of IP addresses that you want to distribute to a set of computers that are all on the same subnet. In other words, all the computers are connected to one switch with no routing between the devices. Here is an example of a simple dhcpd.conf file:

```
ddns-update-style;
ignore client-updates;

subnet 10.0.0.0 netmask 255.255.255.0 {
  option routers 10.0.0.1;
  option domain-name-servers 10.0.0.1;
}
```

```
option subnet-mask 255.255.255.0;
option domain-name "handsonhistory.com";

range 10.0.0.150 10.0.0.225;
default-lease-time 21600;
max-lease-time 43200;
```

```
host ns {
  next-server nsl.handsonhistory.com;
  hardware ethernet 00:D0:B3:79:B5:35;
  fixed-address 10.0.0.1;
}
```

In this example, the DHCP server provides IP addresses for client computers on a small LAN. The first two lines tell the DHCP server not to update DNS records for the local domain based on the IP addresses it assigns.

The DHCP server is serving a single LAN, represented by a 10.0.0.0 network with a 255.255.255.0 subnet. Other details in this file define what the DHCP server will hand out to clients on this.

A single server at 10.0.0.1 is used as the router (or gateway) and DNS server for the LAN. To ensure that server always gets the fixed 10.0.0.1, a host entry is set to the hardware (00:D0:B3:79:B5:35) for the Ethernet card on the host named ns. Using the MAC address as shown above with the option deny unknown-clients; you can allow only specified MAC addresses to obtain DHCP leases.

The pool of addresses handed out by this DHCP server is 10.0.0.150 to 10.0.0.225, as set by the range line. Along with the IP address that client is assigned, the client is also given the associated subnet-mask and domain name.

The IP addresses that the DHCP server hands out are leased to each client for a particular time. The default-lease-time (to 21600 seconds here, 6 hours) is the time assigned if the client doesn't request a particular lease period. The max-lease-time (43,200 seconds here, or 12 hours) is the highest amount the server will assign, if the client requests it. Clients can renew, so they don't lose the IP address while they are still using it.

# Expanding the dhcpd.conf file

As I noted earlier, this is a very simple example that works for a single network of client computers. The following are some examples of ways that you can expand your dhcpd.conf file.

- If you have multiple ranges of addresses on the same subnet, you can add multiple range to a subnet declaration. Here is an example:

```
subnet 10.0.0.0 netmask 255.255.255.0 {
  range 10.0.0.10 10.0.0.100;
  range 10.0.0.200 10.0.0.250;
}
```

- You can set fixed addresses for particular computers, also called reservations. In particular, you would want to do this for your servers so that their addresses don't change. While you could simply omit the fixed IP addresses from your pool of DHCP addresses, you would lose some centralized management of IP configurations. The DHCP reservations allow you to centrally configure all IP address. One way to do this is on the hardware address of your server's Ethernet card. All information for that computer can be contained in a host definition, as the following:

```
host pine {
  hardware ethernet 00:04:5A:4F:8E:47;
  fixed-address 10.0.0.254;
}
```
