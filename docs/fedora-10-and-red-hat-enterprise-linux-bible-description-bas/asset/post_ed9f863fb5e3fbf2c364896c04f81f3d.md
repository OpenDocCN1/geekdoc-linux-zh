## Supplying an initial .tcshrc file

The example .tcshrc file does basically the same thing as the preceding .bashrc example. However, this file (which is for the root user) has the additional task of setting the appearance of the command prompt:

```
# .tcshrc

# User specific aliases and functions
alias rm 'rm -i'
alias cp 'cp -i'
alias mv 'mv -i'

setenv PATH "$PATH:/usr/bin:/usr/local/bin"

set prompt='%n@%m %c#'
```

Instead of using the export command to set environment variables, the tcsh uses the setenv command. In the shell, setenv is used to set the PATH variable. The shell prompt is set to include your name (%n), your name (%m), and the name of the current directory (%c). So, if you were to use the tcsh shell as the root user on a computer named maple /tmp/ your current directory, your prompt would appear as follows:

```
[root@maple ~#]
```

The .tcshrc file can also be known as .cshrc. The tcsh shell is really an extended version of the csh (in fact, you can invoke it by the csh name). When a tcsh shell is started, it first looks for a .tcshrc file in the current user's directory. If it can't find a file by name, it looks for the other name, .cshrc. Thus, either is appropriate.

## Configuring system-wide bash options

Allowing individually customizable shell files for each user is a very flexible and useful practice. But you sometimes need more centralized control than that. You may have an environment variable or shell setting that you want set for every user, without exception. If you add that to each individual shell, the user has the ability to edit that file and remove it. Furthermore, if setting must be changed in the future, you must change it in every single user's shell startup file.

## Configuring system-wide bash options

Fortunately, there is a better way. There are default startup files that apply to all of the users' computer that each command shell reads before the user-specific files. In the case of the bash command shell, it reads the /etc/bashrc file before doing anything.

## Configuring system-wide tcsh options

Similarly, the tcsh reads the /etc/csh.cshrc file before processing the .cshrc or .tcshrc file in the user's home directory. Here is a partial listing of the contents of the /etc/csh.cshrc file that ships with Fedora and RHEL:

```
# /etc/cshrc
# csh configuration for all shell invocations

# by default, we want this to get set.
# Even for non-interactive, non-login shells.
if ($uid > 99 && "id -gn" == "id -un") then
  umask 002
else
  umask 022
endif

if ($prompt) then
  if ($tcsh) then
    set promptchars='#'
    set prompt='[%u@m %c]#'
    set autolist
  else
    set prompt=\$user@hostname -s\\
  endif
```

The /etc/cshrc and /etc/bashrc sets a variety of shell environment options. If you want to modify or add to the shell environment supplied to every single user on the system, the /etc/bashrc or /etc/cshrc file is the place to do it.

## System profiles

Some of the basic information assigned to each user is added from the /etc/profile file. So, if you want to change any of the information, you can start from /etc/profile. The contents of the /etc/profile file is sourced into each user's shell only to the login shell. Here are some values contained in /etc/profile:

- PATH — Assigns the PATH for the root user and for all other users. You might change this value to add 0 to local directories containing applications all users needs.
- ulimit -c 0 — The -c 0 option to limit core files (typically created when a process crashes) from being created. The -S makes this a "soft" option, so the user has the ability to turn on the core file if they choose to.
- Environment variables — Shell variables that are needed for standard operation are assigned in this file. They include USER (set by the id --command), LOGNAME (set as USER), MAIL (set to /var/spool/mail/$USER), HOSTNAME (set to the output of the command /bin/hostname), and HISTSIZE (which sets shell command history to 1000).
- INPUTRC — Keybinding for particular situations, based on the contents of the /etc/inputrc file. In particular, the inputrc file makes sure the Linux console and various windows (xterm and rxvt) behave insanely.

The last thing that the /etc/profile file does is look at the contents of the /etc/profile.d directory and searches the files that it finds. The user can add custom scripts to this directory to set environment variables for all login shells without modifying the main /etc/profile file.
