## Defining outgoing mail access

Every message intended for outgoing mail is received by your sendmail server; the server needs to decide if it will accept or reject relaying of such mail. Policies that are too restrictive might prevent mail from getting out. Policies that are too loose leave your server open to spam.

With e-mail abuse the way it is these days, you should not run an open relay (where your server simply relays all messages it receives to the requested mail). Spammers can use software referred to as spiders to look for open relays. If you leave your mail server open, they will find you quickly and use your machine to relay their spam. The results of a spammer using your machine can include the following:

- **You can end up on blacklists.** Some e-mail blacklist maintainers look for open relays themselves and block them before abuse is reported. Servers that use those blacklists will block all from you, even legitimate e-mail.

This describes how to set up the access file (`etc/mail/access`) to include a set of rules defining for whom your server will relay mail. Using the access file, sendmail can make decisions about whether or not relay a message based on the sender's host/domain name, IP address, or e-mail address. You can further refine the method by checking for these addresses in Connect, From, or To data associated with the message.

There are four actions the server can take on a match:

- **RELAY** — Your mail server could simply send the message to the mail server requested in the mail message.
- **REJECT** — The message is rejected (not relayed) and the sender is told so.
- **DISCARD** — The message is silently discarded and the sender is not told.
- **ERROR: text you choose** — You can add some informative text here, to give the sender some reason why the relay did not occur.

The `/etc/mail/access` file, by default, relays messages only from users who are directly logged into the mail server (localhost). Without explicitly opting, users from all other machines are not allowed to relay messages. Here's how the access file is set up by default:

| localhost.localdomain | RELAY |
| localhost | RELAY |
| 127.0.0.1 | RELAY |

With these defaults, only mail sent from the local machine is relayed. So, if the outgoing mail you send is done while you are logged in the server, you don't need to change this file. The following examples illustrate how you selectively choose to relay or reject mail by your sendmail server:

## Configuring virtual users.

Configuring the virtertable file is particularly important if your server is handling mail for multiple domains. That's because, default for the same user (regardless of the domain name) will be stored in the same mailbox. For example, if your server handles mail for example.com and linuxuxtoys.net, mail for chris@example.com and chris@linuxuxtoys.net, would all be directed to /var/spool/mail/chris. With the virtertable file, you can change behavior in a lot of ways.

The virtertable file is empty by default. The following are some examples of how incoming messages can be directed in different ways based on virtualuser domains.

| chris@linuxuxtoys.net | chris |
| cnegus@linuxuxtoys.net | chris |
| francois@linuxuxtoys.net | francois@spidermaker.com |
| info@linuxuxtoys.net | info-list |
| bogus@linuxuxtoys.net | error:noser No such user here |
| @example.net | example-catchall |
| %1@linuxuxtoys.net | |
