# Using SpamAssassin

With SpamAssassin, you can configure your incoming mail service to tag messages it believes to be spam so you and your users can deal with those messages as you choose.

There are several methods that SpamAssassin uses to identify spam:

+   - Checking mail headers — Examining the headers of your incoming mail to look for well-known tricks used to make the e-mail look valid.

+   - Checking mail text — Looking for text style, content, and disclaimers in message bodies that are commonly used in spam.

+   - Checking blacklists Checking blacklists to find e-mail sent from sites known to relay. (The mail-abuse.com site provides a search for checking if a server at a particular IP address has been blacklisted. To use that tool, go to www.mail-abuse.com/cgi-bin/lookup).

+   - Checking spam signatures — Comparing e-mail signatures. Because spam often consists of the same message thousands of times, taking signatures of spam lets SpamAssassin compare your message to a database of known spam. SpamAssassin uses Vipor’s Razor (http://razor.sourceforge.net).

Although there are many different ways to deal with spam (rather, e-mail that might be spam), most of the experts I have consulted like configure SpamAssassin to tag incoming emails as appear to be. Then they encourage each user of the e-mail server to create or her own rules for filtering the spam.

> NOTE: Although the procedure describes how to use SpamAssassin in the RPM package that comes with the latest version of Fedora, many people get their version of SpamAssassin directly from the SpamAssassin Web. Because anti-spam software evolves so quickly (to keep ahead of spammers), some people like to make sure they have the latest software. Instructions for installing spamassassin from source code are available from the SpamAssassin download page:
http://spamassassin.apache.org/downloads.cgi Typically you can simply run the rpmbuild -tb on the Mail-SpamAssassin tar file to create a new RPM.

# Setting up SpamAssassin on your mail server

Here’s a quick procedure for enabling SpamAssassin and having your users choose what to do with spam messages that are encountered:

+   1. Configure your Mail Transport Agent (sendmail or Postfix) to use the procmail command as its mailer. For sendmail, it is already configured as the default mailer, based on the following line in the /etc/mail/sendmail.mc file:

```
FEATURE(local_procmail,`procmail -t -Y -a -d $u`)dnl
```
