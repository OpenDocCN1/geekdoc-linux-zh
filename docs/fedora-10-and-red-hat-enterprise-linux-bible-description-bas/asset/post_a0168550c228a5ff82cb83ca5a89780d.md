
MySQL has been ported to several different operating systems (primarily UNIX and Linux systems, although there are Windows versions and now a Mac OS X version as well). As you may have guessed, these include binary versions of MySQL that run on Fedora and RHEL. This chapter contains descriptions of and procedures for the version of MySQL that is contained in the Fedora and RHEL distributions.

The version of MySQL that comes with this release of Fedora is 5.0.67. For many releases, Fedora and RHEL stayed on MySQL 3.23 because of licensing issues that Red Hat prevented it from installing later versions. Sun Microsystems' plan to close parts of MySQL in the future made the question of redistributing MySQL more uncertain. Sun’s most recent contributions to open source (most notably related to Java) have made the prospects for MySQL in the open source community much more hopeful.

## Finding MySQL Packages

You need at least mysql and mysql-server packages installed to set up MySQL using the procedures in this chapter. The following MySQL packages that come with the Fedora and RHEL distributions are what you need to get:

- mysql: This package contains a list of MySQL client programs (/usr/bin), several shared client libraries, the default MySQL configuration file (/etc/my.cnf), a few sample configuration files, files to support different languages, and documentation.
- mysql-server: This package contains the MySQL server daemon (mysqld) and the mysql startup script (/etc/init.d/mysqld). The package also creates various administrative files and directories needed to set up the MySQL databases.
- mysql-devel: This package contains libraries and header files required for developing MySQL applications.

Other packages available to add functionality to your MySQL databases include php-mysql (contains a shared library to allow PHP applications to access MySQL databases), mod_auth_mysql (tools to authorize Apache web server access to data in a MySQL database), and perl-DB-MySQL (provides a perl interface to MySQL databases). Packages including tools for MySQL databases include mysql-bench (scripts for benchmarking MySQL databases), mysql-python (contains a Python interface to MySQL), and qt-mysql (MySQL drivers for QT SQL clauses).

If MySQL isn't installed, type the following:

```
# yum install mysql-server
```

If MySQL was installed during initial Fedora installation, you should update your MySQL packages (run yum with update instead of install). If no Internet connection is available, you can install the mysql packages using the rpm command or the system-config-packages window (as using the DVD that comes with this book).

## Configuring the MySQL Server

Like most server software in Fedora and RHEL, the MySQL server relies on a startup script and a configuration file to provide the service. Server activities are logged to mysqld.log file in the /var/log directory. There are also mysql user and group accounts for managing MySQL activities. The following sections describe how these components work together.

> TIP: For many of the steps described in this section, the MySQL daemon must be running. Starting the server is described in detail later in this chapter. For the moment, you can start the server temporarily (root, type service mysql start). Then add a password, as shown in the next section.

## Using user/group accounts

When the MySQL software is installed, it automatically creates a mysql user account and a mysql group account. These user and group accounts are assigned to MySQL files and activities. In this way, someone can manage the MySQL server without needing root permission.

The mysql user entry appears in the /etc/password file as follows:

```
mysql:x:27:MySQL Server:/var/lib/mysql:/bin/bash
```

The mysql entry just indicates that the UID and GID for the mysql user are 27. The text identifying this user account is MySQL Server. The home directory is /var/lib/mysql and the default shell is /bash. The home directory identified will contain directories for each table of data you define for the MySQL server.

The group entry for mysql is even simpler. The following entry in the /etc/group file indicates that the mysql group has a group ID (GID) 27.

```
mysql:x:27
```

If you care to check the ownership of files associated with MySQL, you will see that most of these files have mysql assigned as the user and group account. This allows daemon processes that are run by mysql to access the database.

## Adding administrative users

To administer MySQL, you need to have at least one administrative account. By default, the root user has full access to your MySQL server and no password. You can assign a password to the root user using the mysqladmin command, once the MySQL server is running. To add the root user as an administrator, log in as the root and type the following from a Terminal window (substituting your own password for myownpassword):

```
# mysqladmin -u root password 
```

After this command is run, the MySQL root user can run any administrative commands using the password.

MySQL maintains a list of users and passwords that is separate from the list maintained by Fedora. If you do not provide a user on the command line (in -u root above), MySQL assumes you use your current Fedora username to log in. However, you will still need to provide the MySQL password (not the Fedora password) for that user to use the MySQL service.

If you want to add MySQL administration, simply add the -u root argument to the command line of the MySQL command you are running. The Linux root account has no connection to the MySQL root account after the MySQL account is created. You would typically use different passwords for the two accounts.

> TIP: To save yourself the trouble of typing the password each time you run a MySQL client command, you can add a password option under the [client] group in one of the option files. The most secure way to do that is to create a .my.cnf file in the root user's home directory that can only be accessed by root (chmod 600 /root/.my.cnf) and contains the following lines (substituting your password for the last argument shown):
[client]
password=myownpassword

## Setting MySQL options

You can set options how the MySQL applications behave by using option files or command-line arguments. The MySQL server (as well as other administrative tools) reads the following files when it starts up (if they exist):

- /etc/my.cnf Contains global options read by mysql (server daemon) and mysql.server (script to start the server daemon).
- --defaults-extra-file — You can identify a file on the command line that contains options to be used by the server. For example, the following command would cause the file /home/jim/my.cnf to be read for options after the global options before the user-specific options:

```
# mysql --defaults-extra-file=/home/jim/my.cnf
```
