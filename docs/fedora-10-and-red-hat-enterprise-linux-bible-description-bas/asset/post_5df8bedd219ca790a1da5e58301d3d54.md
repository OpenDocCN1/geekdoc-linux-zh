# Other Mail Servers for Fedora or Red Hat Linux

The open-source version of sendmail is not the only mail server available for Fedora and Red Hat Enterprise Linux systems, but it is definitely the most common. The following list describes other servers and provides URLs for further information:

- **Postfix** — As sendmail, the Postfix MTA is also included in Fedora. By Wiese Venena (of top_wrappers fame), this mail server was designed with security in mind and executes most functions as a privileged user in a restricted root environment. The server encompasses more than dozen small programs (performing a distinct task) and several single-purpose queues. You can find more information and source code at www.postfix.org.
- **Exim** — The Exim MTA is a free mail server (under GPL) that runs on Linux and other Unix systems. Exim is included in the Fedora distribution. This MTA includes features for configuring and routing mail. Find out more Exim from the Exim Home Page (www.exim.org).
- **Qmail** — Also conceived with security as a high priority, this mail server (written by Daniel J. Bernstein) offers secure and reliable message transfer, mailbox quotas, virtual domains, and antispam features. More information is available from www.gmail.com/top.html.
- **Smail** — Smail offers many of the same features as sendmail but is somewhat easier to configure and requires less memory. Smail is most appropriate for small to medium-sized mail servers. The Snail project page is available at www.weird.com/~woods/projects/snail.html. The source code can be downloaded from ftp://ftp.planix.com/pub/Snail/

# Starting sendmail

Once installed, the sendmail service is turned on by default. To start sendmail immediately, you can reboot the machine or run service sendmail start to start the server. The procedure for starting and stopping sendmail is similar to that of any other server.

By default, incoming messages received by sendmail are processed and stored in the /var/spool/mail directory. Each file in this directory represents a user name on the local machine. The file is created automatically the first e-mail is sent to the user (or if it's otherwise missing). People with login accounts use this directory and their user account name as their incoming mailboxes (example, /var/spool/mail/johng).

Outgoing messages go to the /var/spool/mqueue directory while waiting to be sent. Filenames in this directory follow a naming scheme. The first two characters indicate what type of data is stored in the file (see Table 19-1). Subsequent characters form a unique identifier based on the PID of the sendmail process that is handling that message.

# Table 19-1: File Prefixes in /var/spool/mqueue

| Filename Prefix | Type of Data Stored |
| :--- | :--- |
| df | The data that constitutes the body of an e-mail message. |
| qf | The control file that contains the message headers and other administrative details. |
| tf | A temporary copy of the qf file, created if delivery errors occur. |
| xf | Any error messages generated while trying to send the message. |

# Logging performed by sendmail

The amount of logging performed by sendmail is configurable in the sendmail.mc file, but the default level provides good coverage of informational notices and error messages. By default, the syslog configuration file (/etc/syslog.conf) tells syslog to store logging information from sendmail in /var/log/maillog file. # Configuring sendmail

To configure sendmail, you edit configuration files in /etc/mail and are then used by the sendmail start-up script to create database files. Once sendmail is configured, you can begin user accounts. The steps I describe in this section are:

- **Getting a domain name** — You need a unique domain name to assign to your mail server, and then can purchase an Internet domain name from one of many places, and then have DNS mail exchange (MX) records for your domain point to the mail server.
- **Configuring basic sendmail settings** — In this step, you edit the /etc/mail/sendmail.mc file. That file defines things such as the locations of other and log files, as well as letting you configure some behavior of the sendmail daemon.
- **Defining owning mail access** — The most critical security associated with your mail server is which messages it will accept to relay to other mail servers. By editing the /etc/mail/access file, you can indicate the hosts and users from which your server will accept mail for local delivery or relay.
- **Configuring virtual servers** — By default, sendmail assumes that you are setting up the mail server for the domain of which the server is a member. To have sendmail on a single computer be the mail server for multiple domains (referred to virtual servers), you need to define each domain name in the /etc/mail/local-host-names file. (You must create the file manually, since it is not in the sendmail package).
- **Configuring virtual users** — Using the /etc/mail/virtertable configuration file, you can instruct the sendmail daemon to do with what it receives for the users and domains it's configured to handle. This gives you a lot of flexibility to take mail addressed to a particular mailbox, forward it to a different mail address, or reject that mail in various ways. To use virtertable you must create the file manually, since it is not in the sendmail package.
- **Adding user accounts** — You need to add a user account for every user that has a mailbox on your mail server.
