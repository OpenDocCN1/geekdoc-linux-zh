If you decide that the option and variable settings that come with the default MySQL system don't exactly suit you, you don't have to start from scratch. Sample my.cnf files that come with the mysql package begin with a set of options and variables that are closer to the ones you need.

## Using sample my.cnf files

Sample my.cnf files are available in /usr/share/doc/mysql-server/. To use one of these, do the following:

1. Keep a copy of the old my.cnf file:
   `mv /etc/my.cnf /etc/my.cnf.old`
2. Copy the sample my.cnf file you want to the /etc/my.cnf file. For example, to use the my-medium.cnf, type the following:
   `cp /usr/share/doc/mysql-server/my-medium.cnf /etc/my.cnf`
3. Edit the new my.cnf file (as root user) using any text editor to tune your MySQL variables and options.

## Chapter 24: Setting Up a MySQL Server

The following bullets describe each my.cnf file:

- **my-small.cnf** — This option is recommended for computer systems that have less than 64MB of memory and are used occasionally for MySQL. With these options, MySQL won't be able to handle a lot of usage but it won't drag on the performance of your computer.
- **my-medium.cnf** — As the small file, my-medium.cnf is intended for systems where MySQL is not the only application running. This system also has a small amount of total memory — between 32MB and 64MB — more consistent use is expected.
- **my-large.cnf** — As the medium file, my-large.cnf is intended for computers that are dedicated to MySQL service. It assumes 512MB of available memory. For the mysqld server, buffer sizes are set low — 64K for the sort_buffer and 16K for the key_buffer. The thread_stack is set to 64K and net_buffer_length is only 2K. The table_cache is set to 4. The key_buffer size is set to 16M in this file, while sort_buffer value is raised to 512K for the mysqld server. The table_cache is set to 64 (allowing more simultaneous threads).
- **my-huge.cnf** — As the large file, my-huge.cnf expects the computer to be used primarily for MySQL. However, the system for which it is intended offers much more total memory (between 1G and 2G).
- **my-innodb-huge-4G.cnf** — This sample configuration file is set up for computers with 4GB of RAM that are expected to service queries without many connections (using InnoDB storage engine). Special innodb options in this file allow MySQL to take advantage of a large buffer pool size (2G). Sort buffer (sort_buffer) is raised to 2M while the key_buffer is set to 304MB of memory. The table_cache size is doubled to allow up to 512 active threads.

## Starting the MySQL Server

For Fedora and RHEL, the MySQL server is off by default. To turn it on, however, is fairly simple. The /etc/init.d/mysqld startup script is delivered with the mysql-server package. To start it, you can run the mysqld startup script to have it start immediately and then set it to start each time your boots.

To start the MySQL server immediately, type the following from a Terminal window as root user:

```
# service mysqld start
```

To set the MySQL server to start each time the computer reboots, type the following (as root):

```
# chconfig mysqld on
```

This sets mysqld to start during multiuser run states (levels 3, 4, and 5). To check that the service is running on those levels, type chchkconfig --list mysqld from a Terminal window.

## Working with MySQL Databases

The first time you start the MySQL server (using the startup script described previously), the system creates the initial grant tables for the MySQL database. It does this by running the mysql_install_db command.

The mysql_install_db command starts you off with two databases: mysql and test. As you create data for these databases, that information is stored in /var/lib/mysql and /var/lib/mysql/test directories, respectively.

Because the MySQL root user does not have to be the system's root user (provided you have the MySQL root user's password), you can be logged into Fedora or RHEL as any user. In the following, be sure to provide the MySQL root user password when you run the commands.

> NOTE: If you are using the old ISAM tables instead of MyISAM, ISAM tables were removed for MySQL 5.0. You need to convert your tables to MySQL using a statement such as the following:

ALTER TABLE table ENGINE=MyISAM

where table is your table name.
