# Configuring your shell

You can tune your shell to help you work more efficiently. Your prompt can provide pertinent information each time you press Enter. You can alias your keystrokes and permanently set environment variables to your needs. To make each change occur when you start a shell, you can add this information to your shell configuration files.

Several configuration files support how your shell behaves. Some of the files are executed for every user and every shell. Others are specific to the user who creates the configuration file. Here are the files of interest to those using the bash shell in Linux:

- /etc/profile — This file sets user environment information for every user. It is executed when you first log in. This file provides values for your path, as well as setting environment variables for the location of your mailbox and the size of your history files. Finally, /etc/profile gathers settings from configuration files in the /etc/profile.d directory. Note that you can override all of these in start-up files.

- ~/.bashrc — By default, this file is executed for every user who runs the bash shell, each time a bash shell is opened. It sets the prompt and may add one or more aliases. Values in this file can be overridden by information in each user’s ~/.bashrc file.

- ~/.bash_profile — This file is used specific to your own use of the shell. It is executed only once, when the user logs in. By default, it sets a few environment variables and executes the user’s .bashrc file. You can instead create a file named ~/.bash_login to serve the same purpose as ~/.bash_profile.

- ~/.bashrc — This file contains the information that is specific to your bash shells. It is read when you log in and each time you open a new bash shell. This is the best location to add environment variables and aliases so that your shell picks them up.

- ~/.bash_logout — This file executes each time you log out (exit the bash shell). By default, it clears your screen.

To change the /etc/profile or /etc/bashrc files, you must be the root user. Users can change the information in the $HOME/.bash_profile, $HOME/.bashrc, and $HOME/.bash_logout files in their home directories. The following sections provide ideas about items to add to your shell configuration files. In most cases, if you administer a system, you may want to set some of these values as defaults for all users.

# Setting your prompt

Your prompt consists of a set of characters that appear each time the shell is ready to accept a command. The PS1 environment variable sets the prompt. If your shell requires additional input, it uses the values of PS2. When Fedora or RHEL system is installed, your prompt is set to include the following information: your user, your hostname, and the name of your current working directory. Information is surrounded by brackets and followed by a dollar sign (for regular users) or a pound sign (for root user).

```
[user@host dir]$
```

If you change directories, or log in as a different user, the host name would change. You can use several special characters (indicated by adding a backslash to a variety of letters) to include different information in your prompt. Here are some examples:

- ! — Shows the current command history.
- # — Shows the root prompt (#), depending on which user you are.
- \$ — Shows the user prompt ($). Note that \$ is special. After login, \$ will result in a prompt with a dollar sign.
- \W — Shows only the current directory name. For example, if current working directory was /home/user, this value would simply appear as user.
- \[ — Precedes a sequence of nonprinting characters. This could be used to add terminal control effects, like changing colors or making characters bold. (Your terminal determines the exact sequences available.)
- \] — Follows a sequence of nonprinting characters.
- \d — Displays the day, month, and date. For example: Sat Jan 23.
- \h — Shows the hostname of the computer running.
- \n — Causes a newline to occur.
- \s — Displays the current shell name. For the bash shell, the value would be bash.
- \t — Prints the current time in hours, minutes, and seconds (for example: 10:14:39).
- \u — Prints your user name.
- \w — Displays the full path to the current working directory.

TIP: If you want to change your prompt properly, you should define the value of PS1 in quotes. For example, you could export PS1="[\w]\$" to see a prompt that looks like this: $[/home/user]$ .

To make a change to your prompt, add the value of PS1 to your .bashrc file in your home directory (assuming you are using the bash shell). There may be a PS1 value in that that you can modify. Refer to the Bash HOWTO (http://www.ldp.org/HOWTO/Bash-Prompt-HOWTO) for information on changing colors, commands, and other features for your shell prompt.

# Adding environment variables

You may consider adding a few environment variables to your .bashrc file. These can help making your shell more efficient:

- TMOUT — This sets how long the shell can be inactive before automatically exits. The value is the number of seconds the shell has not received input. This can be a nice security feature, in case you leave your desk while you are logged in to Linux. To avoid logging off while you are working, you may want to set the value to something TMOUT=1800 (to allow 30 minutes of idle time), or simply not set this variable to disable this feature.
- PATH — As described earlier, the PATH variable sets the directories that are searched for commands you use. If you use commands that are not in your PATH, you can permanently add them. To do this, add a PATH variable to your .bash file. For example, to add a directory called /getstuff/bin,

```bash
PATH=$PATH:/getstuff/bin; export PATH
```

This example finds all the current paths into the new PATH ($PATH), adds the /getstuff/bin directory, and exports the PATH.

CAUTION: Some people add the current directory to PATH by adding a directory identified simply as a dot (.), as follows:

```bash
PATH=::$PATH ; export PATH
```

This lets you run commands in your current directory (which people may be used to if they have used DOS). The security risk with this procedure is that you can be in a directory that contains a command that you don't intend to run from that. For example, a malicious person could put an ls command in a directory, instead of listing the content of your directory, does something.

- WHATEVER — You can create your own environment variables to provide shortcuts in your work. Choose one name that is not being used and assign a useful value to it. For example, if you do a lot of work with files in the /work/time/files/info/memos, you could create the following:

```bash
M=/work/time/files/info/memos ; export M
```

You can make your current directory by typing cd M. You can run a program called hotdog by typing $M/hotdog. You can edit a file called bun by typing vi $M/bun.
