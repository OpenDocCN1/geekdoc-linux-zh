With the growth of the Internet, computer and network security has become more important than ever. Attacks on your Fedora or Red Hat Linux system can come in many forms, such as denial-of-service attacks, break-in attempts, or hijacking your machine as a spam relay, to name a few.

In many cases, good practices for securing and protecting passwords, monitoring log files, and creating good firewalls will keep out may-intruders. Keeping up with critical security updates will help patch vulnerabilities as they become. The addition of SELinux adds another layer of protection on your Linux system. Sometimes, more proactive approaches are needed to respond to break-ins. This chapter will familiarize you, as a Linux administrator, with the dangers that exist and the tools necessary to protect your system.

## Linux Security Checklist

While Linux offers all the tools you need to secure your computer, if you are careless, someone can (and probably) harm your system or to steal your data. The following checklist covers a range of security measures to protect your Linux desktop or server.

- **Add users and passwords**: Creating separate user accounts (each with a good password) is your first line of defense in keeping your data secure. Users are protected from each other, as well as from an outsider who takes over one user account. Setting up group accounts can extend the concept of ownership to multiple users. See Chapter 11 for more on setting up user accounts and “Using Password Protection” later in this chapter.

- **Read, write, and execute permissions** — Every item in a Linux file system (including files, directories, applications, and devices) can be restricted by read, write, and execute permissions for that item's owner and group, as well as by others. In this way, for example, you can let others run a command or open a file, allowing them to change it. See Chapter 4 for information on setting file and directory permissions.

- **Protect root** — In Linux systems, the root user (as well as other administrative user accounts as root) have special abilities to use and change your Linux system. Protect the root account and don't use the root account when you don't need. An open shell or desktop owned by the root user can be a target for attack. Running `system-config-*` as a regular user (and then entering the root password as prompted) and running administrative commands using `sudo` can reduce exposure to your root account. See Chapter 10 for information on handling the root account.

- **Use trusted software** — While there are no guarantees with any open source software, you have a better chance of avoiding compromised software by using an established Linux distribution (such as Fedora or RHEL). Software repositories where you get addons on packages or updates will be scrutinized. Using valid GPG public keys (which use signatures and encryption) you can ensure that the software you install comes from a valid vendor. And, of always be sure of the source of data files you receive before opening them in a Linux application.

- **Get software updates** — As vulnerabilities and bugs are discovered in software packages, every major Linux distribution (including RHEL and Fedora) offers tools for getting and installing those. Be sure to get updates regularly, especially if you are using Linux as a server. See Chapter 5 for information on using PackageKit and yum to get software updates.

- **Use secure applications** — Even with software that is valid and working, some applications offer better protection from attack or invasion than others. For example, if you want to log in to a computer over the Internet, the secure shell (ssh) is considered more secure than `login` or `telnet`. Also, some services that are thought to be insecure if you expose them over the Internet (such as Samba and NFS), can be used more securely over the Internet through virtual private network (VPN) tunnels (such as IPsec or CIPE).

- **Use restrictive firewalls** — A primary job of a firewall is to accept requests for services from a network that you allow and turn away requests that you don't based on port numbers requested. A desktop system should refuse requests that come in on most ports. A server system should allow requests for a controlled set of ports. This chapter describes how to set up a firewall using iptables.

- **Enable only services you need** — To offer services in Linux (such as Web, file, or mail services), a daemon will listen on a particular port number. Don't enable services you don't need. In fact, you shouldn't install server software unless you need. See Chapter 12 for information on using system services.

NOTE: A program that runs in the background handling service requests (such as sendmail) is called a daemon. Usually, daemons are started automatically when your system boots up, and they keep running until your system is shut down. Daemons may also be started on an as-needed basis by xinetd, a special daemon that listens on a large number of port numbers, and then launches the requested process.

- **Limit access to services** — You can restrict access for a service to a particular host, domain, or network interface. For example, a computer with interfaces to the Internet and a local area network (LAN) might limit access to a service such as NFS to computers on the LAN, but not those services to the Internet. Services may limit access in their own configuration files using TCP/IP wrappers (described later in this chapter).

- **Check your system** — Linux has tons of tools for checking the security of your system. After you install Linux, you can check access to its ports using nmap or watch network traffic using Wireshark (formerly Etheral). You can also add popular tools like Nessus, to get a more complete view of your system security.

- **Monitor your system** — You can log almost every type of activity on your Linux system. System log files, using the syslog and klog facilities, can be configured to track as much or as little of your activity as you choose. The logwatch facility provides an easy way to have the potential problem messages forwarded to your administrative e-mail account. Linux logging features are described later in this chapter. You can add packages such as tripwire and posterity, to check your system for tampering and with scanning your ports, respectively.

- **Use SELinux** — SELinux is an extraordinarily rich (and complex) facility for managing nearly every aspect of a Linux system. It addresses the if-I-get-root-access-I-own-your-box shortcuts of Linux and UNIX systems for highly secure environments. Red Hat systems offer a useful, limited set of SELinux policies. Sometimes, more proactive approaches are needed to respond to break-ins. This chapter will familiarize you, as a Linux administrator, with the dangers that exist and the tools necessary to protect your system.

This checklist should give you a starting point with Linux security. However, security is an ongoing battle, so I recommend you check out the following sites:

- CERT (www.cert.org) — The CERT Coordination center follows computer security. Check their home page for the latest vulnerability issues ([http://www.cert.org/pubs/search.php](http://www.cert.org/pubs/search.php)). It also has recommendations on what you should do if your computer has been compromised (http://www.cert.org/tech_tips/win-UNIX-compromise.html).

- Red Hat Security (www.redhat.com/security) — For RHEL security issues (which typically relate to Fedora), you should check out the resources available from this site.

- Red Hat Enterprise Linux 4 Security Guide — This guide provides an in-depth look at Linux security, specifically as it relates to Red Hat Enterprise Linux. You can access this guide online from the following:
