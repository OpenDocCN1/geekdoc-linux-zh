
## Mounting removable media

If you want to mount a file system manually, the /etc/fstab file makes it simple to mount a file system from any partition, floppy disk, or a CD-ROM. Although Fedora no longer adds entries for CDs and floppy disks to the /etc/fstab file, you could manually add entries, if you want to mount those media in different locations. Here are examples of entries you could add to your /etc/fstab file:

```
/dev/cdrom /mnt/cdrom auto noauto,user,exec,ro 0 0
/dev/fd0 /mnt/floppy auto noauto,owner 0 0
```

The /media directory is traditionally used to mount removable or temporary file systems in Linux. If you are adding points manually, it's best to use a location such as /mnt, instead of the newer /media directory, so you don't conflict with any file systems the Hal service (half daemon) mounts automatically in the /media directory.

With entries such as those shown, you can use the mount command with a single option to indicate what you want, and information is taken from the /etc/fstab file to fill in the other cases. The following are examples where you could mount a CD or floppy disk system using a single option (based on the /etc/fstab file shown above):

- CD-ROM — If you are mounting a CD-ROM that is in the standard ISO 9960 format (as most CD-ROMs are), you can mount the CD-ROM by placing it in your CD-ROM drive and typing the following:

```
# mount /mnt/cdrom
```

By default, your CD-ROM is mounted on a point in the /media directory. The command shown above, mounts the /dev/cdrom device on the /mnt/cdrom directory.

- Floppy Disk — If you are mounting a floppy disk that is in the standard Linux file system (ext3), based on the /etc/fstab file entry shown above, you can mount that floppy disk by inserting it in your floppy drive and typing the following:

```
# mount /mnt/floppy
```

The file system type (ext3), (/dev/fd0), and mount options are filled in from the /etc/fstab file. You should be able to change the floppy disk directory (cd /mnt/floppy) and list the contents of the floppy's top directory (ls).

> NOTE: In both of the previous cases, you could get the device name (/dev/cdrom or /dev/fd0) instead of the mount point directory to get the results.

Of course, it is possible that you may get floppy disks to use that are in all formats. Someone might give you a floppy containing files from a Microsoft operating system (MS-DOS format). Or you may get a file from another UNIX system. In those cases, you can fill in your own options, instead of relying on options from the /etc/fstab file. In some cases, Linux autodetects that the floppy disk contains an MS-DOS (or Windows vfat) file system and mount it properly without additional arguments. However, if it doesn't, here is an example of how to mount a floppy containing MS-DOS files:

```
# mount -t msdos /dev/fd0 /mnt/floppy
```

This shows the basic format of the mount command you would use to mount a floppy disk. You could change msdos to any other supported file system (described earlier in this chapter) to mount a floppy of that type drive A: (/dev/fd0), you could use drive B: (/dev/fd1) or any other accessible drive. Instead of mounting on /mnt/floppy you could create any other directory and mount the floppy there.

Here are some other options you could add along the mount command:

- -t auto — If you're not exactly what type of file system is contained on the floppy disk (or what medium you are mounting), use the -t auto option to indicate the file system type. The mount command will query the disk to try to get what type of data it contains.
- -r — If you don't want to make changes to the file system (or it is a read-only medium), use this option when you mount it. This will mount read-only.
- -w — This mounts the file with read/write permission.

## Mount CD or DVD images

Another valuable way is to use the mount command to view ISO disk images. If you download a CD, DVD, or floppy disk image any from the Internet and want to see what it contains, you can do so without burning it to CD or floppy. With the image on your hard disk, you can create a mount point and use the -o loop option to mount it locally. Here's an example of what to type (as root user):

```
# mkdir /mnt/mycdimage
# mount -o loop whatever-i386-discl.iso /mnt/mycdimage
```

In this example, the disk image (whatever-i386-discl.iso) residing in the directory is mounted on the /mnt/mycdimage directory I created. I can now do that to view the directory, view its contents, or copy any of them. This is useful for downloaded CD images that you want to install software without having to burn the image to CD. When you are done, use type mount /mnt/mycdimage to unmount it.

Other options to mount are available only for a specific file system type. The mount manual for those and other useful options.

## Using the mount command to unmount a file system

When you are done using a file system, you can use the unmount command to detach the file system from the directory. The command takes the mount point or the device name as an argument.

```
# ummount /mnt/cdrom
# umount /dev/cdrom
```

If you use the mount point, the system looks up which device is mounted there. If you use the device name, the system looks up which mount point is associated with that device. If the device is currently busy, the unmount command will fail. In this case, you can use the -l option to lazy unmount the device.

```
# umount -l /mnt/cdrom
```

The -l option detaches the file system from the directory hierarchy and cleans up resources when the device is no longer busy. This is useful when you cannot unmount a file system because it is used by a process.

## Part III: Administering disks

## Using the mkfs command

The mkfs command is used to create a file system on a partition. Before you can use a partition, you must format it with a file system. There are many file system types available, such as ext3, ext4, and xfs.

To create an ext4 file system on a partition, use:

```
# mkfs.ext4 /dev/sdb1
```

The -t option specifies the type of file system. If you don't specify a type, the system chooses the default for the current distribution.

The mkfs command also allows you to set various options, such as the label, block size, and inodes.

```
# mkfs.ext4 -L MyData -B 4096 /dev/sdb1
```

The -L option sets a volume label for the file system. The -B option sets the block size in bytes. The -i option sets the number of inodes.

## Adding a hard disk

Adding new hard disk to your computer so that it can be used by Linux requires a combination of steps described in sections. The general steps are as follows:

1. Install the hard disk hardware.
2. Identify the partitions on the new disk.
3. Create the file systems on the new disk.
4. Mount the file systems.

The easiest way to add a hard disk to Linux is to have the entire disk devoted to a single partition. You can have multiple partitions of different sizes, and assign to each type of file system and different mount points, if you. The following procedure describes how to add a hard disk containing a single Linux partition. Along the way, it also notes steps you need to repeat to have multiple file systems with mount points.

> NOTE: This procedure assumes that Fedora or RHEL is already installed and working on the computer. If this is not the case, follow the instructions for adding a hard disk on your current operating system. Later, when you install Fedora or RHEL, you can identify this disk when asked to partition your hard disk.

1. Install the hard disk into your computer. Follow the manufacturer's instructions for physically installing and connecting the new disk. If, presumably, this is a second hard disk, you may need to change jumpers on the hard disk unit to have it operate as a slave hard disk. You may also need to change the BIOS settings.
2. Boot your computer to Linux.
3. Determine the device name for the hard disk. As root user from a shell, type:

```
# dmesg less
```

From the output, look for an indication that the new hard disk was found. For example, if it is a second hard disk, you should see /dev/sdb. Be sure you identify the right disk or you will erase all the data from disks you probably want to keep!

## Partitioning the hard disk

Once you have identified the hard disk, you need to partition it. The fdisk utility is used to create and manage partitions on hard disks. It is available in both Fedora and RHEL.

To start fdisk, use:

```
# fdisk /dev/sdb
```

Inside fdisk, you will be presented with a menu of commands. The most common are:

- n: create a new partition
- d: delete an existing partition
- t: change the partition type
- p: print the partition table
- w: write changes and exit
- q: quit without saving

To create a new partition, select 'n', and then follow the prompts to specify the partition number, first sector, and last sector. By default, it will use the entire available space for the partition.

After creating the partitions, use 'p' to verify the partition table. If you are satisfied, use 'w' to write the changes to the disk.

## Creating file systems

After the disk is partitioned, you need to create a file system on each partition. Use the mkfs command for this purpose.

To create an ext4 file system on /dev/sdb1, use:

```
# mkfs.ext4 /dev/sdb1
```

## Mounting the file systems

Once the file systems are created, you need to mount them so they can be used. Use the mount command for this.

To mount /dev/sdb1 on /mnt/data, use:

```
# mount /dev/sdb1 /mnt/data
```

To make the mount persistent across reboots, you must add an entry to the /etc/fstab file.

```
/dev/sdb1 /mnt/data ext4 defaults 0 2
```
