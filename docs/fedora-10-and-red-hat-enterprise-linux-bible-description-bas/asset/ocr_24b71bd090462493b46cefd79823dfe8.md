# ## Spam relaying

Another way in which your e-mail services are abused is by using a spam relay. Spam refers to the unsolicited junk e-mail that has become a common occurrence on the Internet. Spammers deliver their annoying messages from a normal dial-up Internet connection. They need some kind of high-capacity e-mail server to accept and buffer the payload of messages. They deliver the spam to the server all in one huge batch and let off, letting the server do the work of delivering the messages to many victims.

Naturally, no-self respecting Internet service provider (ISP) will cooperate with this action, so spammers to hijacking hosts at another ISP to do the dirty work. Having your mailserver hijacked as a spam relay can have a devastating effect on your system and your reputation. open mail relaying is deactivated on Fedora and Red Hat Enterprise Linux installations. Open mail relaying is one security issue that you will not have to worry about.

You can select specific hosts or domains to relay mail through your system by adding thoseers to your /etc/mail/access file with keyword RELAY. By default, relaying is only allowed for the /mail host. Refer to Chapter 19, as well as the sendmail documentation, for more information.

> TIP: One package you might consider using to filter out spam on your mail server is spamassassin. SpamAssassin examines the text of incoming mail messages and attempts to filter out messages that are determined to be spam. SpamAssassin is described in Chapter 19. You should also check out The Spamhaus Project (www.spamhaus.org), which maintains the Spamhaus Block List to help you block verified spam and spam operations.

# ## Smurfing amplification attack

Smurfing refers to a particular type of denial-of-service attack at flooding the Internet. It can be a difficult attack to defend against because it is not easy to trace the attack to the attacker. Here is how smurfing works.

The attack makes use of the ICMP protocol, a service intended for checking the speed and availability of network connections. Using the ping command, you can send a network packet from your computer to another computer on the Internet. The remote computer will recognize the packet as an ICMP request and echo a reply back to your computer. Your computer can print a message revealing that the remote system is up and telling you how long it took to reply to the ping.
