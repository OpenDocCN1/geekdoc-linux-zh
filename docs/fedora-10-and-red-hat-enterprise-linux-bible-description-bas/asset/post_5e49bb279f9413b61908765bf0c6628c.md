Apache can function as a proxy server, a caching server, or a combination of the two. If ProxyRequests is set to Off, the server will simply cache files without acting as a proxy. If CacheRoot (which specifies the directory to contain the cache files) is undefined, no caching will be performed. Both proxy and caching services are Off (commented out) by default.

If you turn on, the CacheRoot should exist on a file system with enough free space to accommodate the cache, which is limited by the CacheSize directive. However, you should have 20 to 40 percent more space available in the file system because cache cleanup (to maintain the CacheSize, in kilobytes) occurs only periodically (which you can set using the CacheInterval directive).

You can add other directives to this example to enable other caching features. The CacheMaxExpire can indicate the maximum number of hours that a document exist in the cache without checking the original document for modifications. The CacheLastModifiedFactor applies to documents that do not have an expiration time,

# Configuring virtual hosting

If you have server computer, but more than one domain that you want to serve with that computer, you can set up Apache to virtual hosting. With name-based virtual hosting, a single IP address be the access point for multiple domain names on the same computer. With IP-based virtual hosting, you have a different IP address for each virtual host, which you achieve by having multiple network interfaces to a machine.

With virtual hosting, when a request comes into your Apache server from a Web browser through a particular IP address on your computer, Apache checks the domain being displayed and displays the content associated with that domain name. As an administrator of a Web server that serves virtual hosting, you must make sure that everything that needs to be configured for virtual server is set up properly (you must define things as locations for the Web content, log files, administrative count, and so on).

Virtual hosting is defined with the VirtualHost tags. Information to virtual hosts in the /etc/httpd/conf/httpd.conf file is found in the following code:

```apache
# Section 3: Virtual Hosts
#
# VirtualHost: If you want to maintain multiple domains/hostnames on
# your machine you can setup VirtualHost containers for them. Most
# configurations use only name-based virtual hosts so the server
# doesn't need to worry about IP addresses. This is indicated by the
#
# asterisks in the directives below.

# Please see the documentation at

# Part IV: Fedora RHEL Network and Server Setup

# <URL:http://httpd.apache.org/docs/2.2/virtualhosts>
# for further details before you setup virtual hosts.
#
# You may use the command line option '-s' to verify your virtual host
# configuration.
#nUse name-based virtual hosting.
#nNameVirtualHost *:80
#n NOTE: NameVirtualHost cannot be used without a port specifier
# (e.g. :80) if mod_ssl is being used, due to the nature of the
# SSL protocol.
#n VirtualHost example:
# Almost Any Apache directive may go into a VirtualHost container.
# The first VirtualHost section is for requests without a known
# server name.
#n<VirtualHost *:80>
# ServerAdmin webmaster@dummy-host.example.com
# DocumentRoot /var/www/docs/dummy-host.example.com
# ServerName dummy-host.example.com
# ErrorLog logs/dummy-host.example.com-error_log
# CustomLog logs/dummy-host.example.com-access_log common
#</VirtualHost>
```

The following example lists virtual host directives that would allow you to host the domains handsonhistory.com and linixtoys.net on the same computer:

NameVirtualHost *:80

```apache
<VirtualHost *:80>
DocumentRoot /var/www/handsonhistory
ServerName www.handsonhistory.com
ServerAlias handsonhistory.com
ServerAdmin webmaster@handsonhistory.com
ErrorLog logs/handsonhistory.com-error_log
CustomLog logs/handsonhistory.com-access_log common
</VirtualHost>

<VirtualHost *:80>
DocumentRoot /var/www/linixtoys
ServerName www.linixtoys.net
ServerAlias linixtoys.net
ServerAdmin webmaster@linixtoys.net
ErrorLog logs/linixtoys.net-error_log
CustomLog logs/linixtoys.net-access_log common
</VirtualHost>
```

# Configuring modules and related services (/etc/httpd/conf.d/*)

Any module that requires special configuration (.conf file) in the /etc/httpd/conf.d/ directory. Here are popular configuration files that might be contained there, with some ways of using those files and the packages associated with them (use yum install package you want):

- auth_kerb.conf: Configure Kerberos authentication over a Web (HTTP) connection. The example in this file suggests Kerberos authentication over an SSL connection. (Install the mod_auth_kerberos package.)
- auth_mysql.conf: Configure authentication based on data you add to a MySQL database. The comments in the file describe how to set up the database and use it to user or group authentication before allowing a client to access your Web content. (Install the mod_auth_mysql package.)
- auth_pgsql.conf: Configure authentication based on a PostgreSQL database. (Install the mod_auth_pgsql package.)
- auth_idap.conf: Configure authentication to access an LDAP database to authenticate users. (Install the mod_authz_ldap package.)
- htdig.conf: Identify the location of the hdig search content that can be used on your Web site (/share/htdig is the default location). To see the hdig search results from a browser, type http://localhost/htdig. The hdig system lets you use tools for indexing and searching your Web site or content online. It is optional for your Web server. (Install the htdig-web package.)
- mailman.conf: Set up mail list server software to allow features such as making mailing-lists archives available from Apache. (Install the mailman package.)
- manual.conf: Define the location of Apache manuals (/var/www/manual/) on the server for different languages. Type http://localhost/manual in a browser window. (Install the httpd-manual package.)
- mrtg.conf: Define the location of daily mrtg output (/var/www/mrtg), which tracks network traffic. Type http://localhost/mrtg in a browser. (Install the mrtg package.)
- perl.conf: Identify and load the mod_perl module so that your Web pages can include Perl code. (Install the mod_perl package.)
