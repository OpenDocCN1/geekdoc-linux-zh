
## Introduction to Web Servers

The Wide Wide Web, as it is known today, began as a project of Tim Berners-Lee at the European Center for Particle Physics (CERN). The original goal was to provide one consistent interface for geographically dispersed researchers and scientists who needed access to information in a variety of formats. From this idea came the concept of using one client (Web browser) to access data (text, images, sounds, video, and binary files) from several types of servers (HTTP, FTP, SMTP, Gopher, NNTP, WAIS, Finger, and streaming-servers).

The Web server usually has a simpler job: use HyperText Transfer Protocol (HTTP) requests and send a response to the client. However, this job can get much more complex (as the server can also), executing functions such as:

- Performing access control on file permissions, username/password pairs, and host name/IP address restrictions.
- Parsing a document (substituting appropriate values for any conditions within the document) before sending it to the client.
- Spawning a Common Gateway Interface (CGI) script or custom Programming Interface (API) to evaluate the contents of a submitted form, presenting a dynamically created document, or accessing a database.
- Logging any successful accesses, failures, and errors.

## The Apache Web server

The Apache Web server was originally based on HTTPd, a free server from the National Center for Supercomputing Applications (NCSA). At the time, HTTPd was the first and only Web server on the Internet. Unfortunately, the development of the server wasn't keeping up with the needs of Webmasters, and several security problems had been discovered. Many Webmasters had applying their own features and fixes to the NCSA source code.

In 1995, a group of these developers pooled their efforts and created a new project from this code called Apache. Since then, it the Apache Software Foundation (http://www.apache.org) has largely rewritten the code and created a stable, multiplatform Web daemon. More than two related projects are also sponsored by the Apache Software Foundation. These projects include mod_perl (to create dynamic Web sites with the Perl language), Jakarta (to provide server-side Java content), DB (to create and maintain commercial-quality database solutions), and spammassassin (to identify and deal with junk e-mail).

The main features of the Apache Web server include:

- The stability and rapid development cycle associated with a large group of cooperative volunteer programmers.
- Full source code, downloadable at no charge. Restrictions by End User License Agreements (EULAs) and caps on the number of servers you can run't apply.
- Ease of configuration using plain-text files.
- Access control based on client host/IP address or username/password combinations.
- Support for server-side scripting as well as CGI scripts. This includes the ability to have different users controlling script execution (to limit the vulnerability of a whole server if a single script is compromised).
- A custom API that enables modules (for example, extended logging capabilities, improved authentication, caching, connection tracking, and so on) to be used by the server daemon.

Apache is not the only web server for Fedora and RHEL systems, but it is the most often used with Linux, and is still the most popular server on the Internet according to Netcraft (http://news.netcraft.com/archives/web_server_survey.html). In addition to Apache, Fedora and RHEL come with the lighttppd and lightweight servers.

## Other web servers available for Fedora and RHEL

Some other servers that can run on Fedora and other Red Hat distributions are described in the following list, with URLs that provide more detailed information.

- lighttppd — The lighttppd web server (http://www.lighttppd.net) is built for security, speed, compliance and flexibility. It is particularly optimized for high performance environments because it has a low footprint and balances cpu-load. Sites such as YouTube, Wikipedia, and meebo have used lighttppd for some web applications.
- telchtpd — The TelThtpd web server (telchtpd package) is included in the Tool Command Language (TCL). Acting as a web server, TelThtpd can also be used in a TCL application server.
- httpd — The httpd HTTP server (http://acme.com/software/httpd) was designed to be simple, small, portable, and fast. Its creators call it a tiny, turbo, throttling HTTP server. It implements less than the minimum needed to be HTTP/1.1 compliant, so it can run much faster than many large Web servers under extreme loads.
- XSP — The XSP web server (xsp package) can run ASP.NET applications, as well as related services for working with ASP.NET applications.
- Zope — In addition to able to serve Web Content, Zope includes features for adding news, membership information, and search capabilities. Originally created by Zope Corporation (http://www.zope.org), Zope is now available as an open project
