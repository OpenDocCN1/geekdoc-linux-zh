- ufs — This file system is popular on Sun Microsystems operating systems (that is, Solaris and SunOS).
- xenix — This was added to be compatible with Xenix file systems (one of the first PC versions of UNIX). The system is obsolete and will probably be removed eventually.
- xfs — This is a journaling file system that is useful in high-performance environments. It includes full 64-bit addressing. An xfs file system can scale to systems that include multiple terabytes of data transfer at multiple gigabytes per second.
- jfs — This file system is based on the JFS file system IBM for OS/2 Warp. It came as an open-source project in 2000. JFS is most suited for enterprise systems. Like XFS, JFS is tuned for file systems and high-performance environments.
- xiafs — This file system supports long filenames and larger inodes than file systems such as nix.
- squashfs — This is a compressed file system, where files are uncompressed on the fly they are requested. It is often used with live CDs, including all Fedora Live CDs.
- fuse — Behave like a user-space remote file system. A local user can use ssh tools available, purely on the basis of the permissions of the user login. A very cool way to mount a remote file system without administrative intervention on the remote side.

Two new file system types were added starting in Fedora 9: ext4 file systems and encrypted file systems. Although both are still considered experimental, tools are available in Fedora 10 to create and use these new file system types.

The ext4 file system is the latest version of the ext system (ext3 being the current standard). An ext4 file system can be mounted as an ext3 file system. If you want to use new ext4 features (called extents), mount as an ext4 device (mount -t ext4dev). See Ext4 FAQ for information on creating and working with ext4 file systems:

```
http://ext4.wiki.kernel.org/index.php/Frequently_Asked_Questions
```

How-to document help you get started with ext4 file systems:

```
http://ext4.wiki.kernel.org/index.php/Ext4_How
```

You can convert an ext3 file system to ext4 by using a command like the following:

```
# tune2fs -O extents -E test_fs /dev/dev
```

And, you can adjust the inode setting, for example from 128 to 256, to improve efficiency with a command like the following:

```
# tune2fs -I 256 /dev/dev
```

# Using the mount command to mount file systems

Your Fedora or Red Linux system automatically runs mount -a (mount all) each time you boot. For reason, you would typically use only the mount command for special situations. In particular, the average user or administrator uses mount in two ways:

- To display the disks, partitions, and remote files that are currently mounted.
- To temporarily mount a file system.

Any user can type the mount command (with no options) to see what file systems are currently mounted on the local system. The following is an example of the mount command. It shows a single hard partition (/dev/sda) containing the root (/) file system, and proc and dev file system types mounted on /proc and /dev, respectively. The last entry shows a floppy disk, formatted with a standard Linux file system (ext3) mounted on /media/floppy.

```
$ mount
/mapper/VolGroup00-LogVol00 on / type ext3 (rw)
/dev/proc /proc type proc (rw)
/dev/sys /sys type sysfs (rw)
/dev/devpts on /dev/pts type devpts (rw,mode=620)
/dev/sda3 /boot type ext3 (rw)
/dev/shm /dev/shm type tmpfs (rw)
/dev/fd0 /media/floppy type ext3 (rw)
```

The most common devices to mount by hand are your floppy disk and your CD-ROM. However, by default not in Fedora and other Linux systems, CD-ROMs and floppy disks are mounted for you automatically when you insert them. If you want to add an additional local disk or an additional partition, you can create an entry for the disk or partition in the /etc/fstab file. Get instructions on how to add entries for an NFS file system, see Chapter 18.
