# Defining specific Apple servers settings

Your netalk server can appear as multiple file servers, each with different attributes. You can set up these "virtual" servers in the /etc/talk/afpd.conf file. Within each file server entry, you name the server, and assign a variety of options to show how it is accessed. A few examples of how this are shown as comments in the afpd.conf file follow:

```
"Guest Volume" -ulist uams_guest.so -loginmsg "Welcome guest!"
"User Volume" -ulist uams_cltert.so -port 12000
```

The "Guest Volume" example causes a "Welcome guest!" message to appear when a user logs into the server. Because it is a guest server (uams_guest.so),no password is required. In the "User Volume" example, clear-text passwords and valid user accounts are needed for the volume. The service is provided on port 12000. Guest Volume and User Volume appear as the names of the two servers, respectively, in the Mac's chooser window.

If Linux computer is a router, with one or more network interfaces connected to public networks, you should use the -ipaddr Address option. With that option, you can restrict access to the netalk server from a particular network interface (probably only one that allows access from your local LAN). There are more than 30 options listed in afpd.conf that you can choose.

# Setting up users

As mentioned earlier, the netalk server (by default) allows users with valid user name and passwords to log into the server with clear-text (unencrypted) passwords and gain access to (at least) their home directories. See the "Securing netalk volumes" section later in this chapter to see how to set up the server using encrypted passwords.

# Sharing netalk volumes

You use the AppleVolumes.default file to indicate which volumes from the netalk server are available to your Mac clients. This file is located in /etc/talk/AppleVolumes.default.

> NOTE: The "File and directory-level security" section for detailed information on hidden files and directories, as well as user and group permissions issues related to sharing volumes.

Look at the last line in the AppleVolumes.default file. The single tilde (~) on a line itself tells the AppleTalk daemon to make all home directories (usually in the /home directory) available as AppleTalk shared directories. When a user logs into the netalk server, the user's own home directory appears as a shared directory. A user who chooses to open that directory has the same rights to change, add, and delete files that he has when logged to Linux.
