## Mail reader

The mail command was the first mail reader for UNIX. It is text-based, but not screen-oriented. Type mail and you will see the messages in your mailbox. Because mail is not screen-oriented, you will just get a prompt after messages are displayed — you are expected to know what to do next. (You can use the Enter key to step through messages.) Type help to see which commands are available.

While in mail, type h to see mail headings. Simply type a message to see the message. Type d# (replacing # with a message number) to delete a message. To create a new message, type m. To respond to a message, type # (replacing # with the message number). Type man mail to learn more about the mail command.

## Participating in Newsgroups

Usenet news is another feature that has been around as long as the Internet. Using a newsreader, and many regular mail readers, you can select from thousands of topics and participate in these topics. To participate, you simply read the messages people have posted to the group, respond to those that you have something to say, and send your own messages to start a discussion yourself.

To get started, you basically need a newsreader and access to a news server computer. The Thunderbird e-mail client includes support for using Usenet accounts. A popular newsreader that works with RHEL is called Pan.

> TIP: If you have never used a newsgroup before, check out the news.announce.newusers newsgroup. This newsgroup exists to answer questions from new users.

The Pan newsreader is a graphical application for reading, managing, and interacting with newsgroups. It is particularly adept at displaying attached pictures and downloading binaries. The interface is very intuitive and easy to use. A big benefit of using Pan instead of Thunderbird for accessing newsgroups is that Thunderbird combines and splits yenc posts.

> NOTE: You can get the pan package by typing yum install pan.

Although Pan was originally designed for the GNOME desktop, GNOME libraries are no longer required to run Pan. For that reason, Pan will now work on KDE, Window Maker, and other desktop environments without any special software.

To open the Pan newsreader, type pan from the shell. The first time you start Pan, the Pan wizard runs to let you set up the newsreader. Have your e-mail address and your news server’s name ready. When the wizard is done, you can download the list of newsgroups available from your server.

## Instant Messaging with Pidgin

Pidgin is the predominant instant messaging client in Linux. Originally based on the America Online (AOL) Open IM architecture (http://www.aim.com), the project recently changed its name to Pidgin. Pidgin now supports a variety of instant messaging protocols, with the following:

- Because Oscar is the official AIM protocol created by AOL, it is the most popular one used for Pidgin. Oscar had to work in Pidgin to be reverse engineered because it is a proprietary protocol of AOL. So, not all features that you might find in AOL's own instant messaging are supported. Messaging is done over TCP-based networks (typically, the Internet), with all messages through AOL servers, in the case of direct connections (which are difficult to get working properly).
- MSN Messenger — This protocol was based originally on the MSN Messenger Service 1.0 protocol (http://www.hyphetic.org/docs/msn/ift_draft.txt). That protocol has been "enhanced" significantly by Microsoft since it first published the version included with Pidgin had to be reverse engineered. To find out more about MSN Messenger (from Pidgin or otherwise), see the MSN Messenger Protocol Resources/Links page (http://www.hyphetic.org/docs/msn/resources/links.php).
- ICQ — Pidgin uses the open source libic to implement the ICQ protocol. Because of recent changes to the ICQ protocol, it is usually recommended to use Oscar to connect to the ICQ network, rather than icq.
- IRC — The Internet Relay Chat protocol is based on the standard RFC 1459. Although there are differences in implementation of that standard on different IRC servers, their TCP-based protocol should work fine on most IRC servers.
- Yahoo! Messenger — This allows you to communicate to others via Yahoo! Messenger servers.

There are other messaging protocols supported by Pidgin as well. These include Jabber (which is used by GoogleTalk and available from http://www.jabber.org), Napster (instant messaging and buddy lists, but not downloads), Groupwise Messenger (Novell's instant messaging), Sametime (Lotus messaging from http://meanwhile.sourceforge.net), TOC (rarely used AOL AIM service for unofficial chats), and Zephyr (IM system from MIT). Pidgin not only supports multiple protocols, but also allows you to communicate with multiple protocols at the same time. There are also available Jabber servers you can get to run your own Jabber instant messaging server, such as Ejabberd (http://ejabberd.jabber.ru). Type `yum install ejabberd` to install the ejabberd package.

To start Pidgin from the Applications menu, choose Internet -> Instant Messenger. Figure 9-8 contains an example of the Pidgin Buddy List and others.

## Sharing Files with BitTorrent

BitTorrent is a tool for distributing software to a large number of clients over a network. What makes BitTorrent unique is, as you download a file to your computer, someone else can be downloading the same file from your computer. In that way, the server originally offering the file doesn't get hammered and a potentially unlimited number of people can get the file.

BitTorrent is an excellent tool for the free and open source community. For example, when a new release of Fedora comes out, using BitTorrent means you don't have to wait for days for traffic on servers to cool down. Of course, there are also those who are concerned that BitTorrent makes it easy to share, such as commercial movies, music, and software.

Both a text-based and graphical (bittrent-gui) BitTorrent client are available from the Fedora repository. You can get clients by installing the following as root from a Terminal window:

```
# yum install bittrent-gui
```

To Use BitTorrent, visit a Site that offers downloads and look for a link to a torrent file representing the software, video, or other type of file to download. Download the torrent file to your computer. Open the BitTorrent Window (select Applications -> Internet -> BitTorrent File Transfer).

The slider on the Torrent window controls how much bandwidth you will allow for others to upload the files that you are downloading. The more you supply, the faster you will be allowed to download the file. You can continue to make the file available to others after you are downloading.

To create your own torrent for a file or directory of files you want to share, select File -> Make new torrent. While you can always publish your torrent on a public server, your firewall may limit your ability to publish your own torrent to the Internet. For more information on BitTorrent, refer to the BitTorrent Introduction at http://www.bittrent.org/introduction.html.

## Using Remote Login, Copy, and Execution

This section describes some features for allowing users to use resources across a network. They are telnet, ssh, and get commands.

> CROSS-REFERENCE: The only ssh service is turned on by default in Fedora because the other remote login, execution, and copy commands described here do not provide encrypted communications by default, so they can represent significant security risks. For information on how to turn on the services described in this chapter on a Fedora or RHEL server, refer to Chapter 14 and Appendix B.

Two of the commands described in this section are generally available remote login and file transfer programs: telnet and ftp, respectively. Other commands for accessing FTP servers are nfcftp and gFTP. The ssh command is typically used as a secure login command, although it can be used for remote execution as well.
