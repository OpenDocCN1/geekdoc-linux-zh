Each file contains environment variables or aliases that affect how users can use the shell. For example, the lang.sh and lang.cs files identifies the locations of foreign language files. # Adding user accounts to servers

When you set up a server, you often want to allow people to upload files to it or download files from it. However, you may not want to allow them access to the entire server. You can begin limiting access to users when you first create their user accounts.

To prevent a remote user from logging in and accessing a shell (via ssh, telnet, or another login service), you can set the default shell for a user to nologin. For example:

```
# useradd -s /sbin/nologin jerryb
```

With the set to nologin, this user would not be able to log in to the server to open a shell. The user could still use this account to log in to an FTP server on the server (if the service is available and the user has a password). By default, the user's home directory in this example would be /home/jerry. (See Chapter 20 for ways in which you can restrict this user to access his home directory in a chroot)

Another approach to FTP-only access to a server is to use /usr/lib/sftp-server as a user's login shell. This allows users access to the entire file system that is available to the user, it restricts them to the server via secured FTP only.

A common practice with Web hosting is to allow a user to place content on the server, often in that user's /home/username/public_html directory, using FTP (but no shell login). However, the administrator could choose to assign the location for the Web content to be any directory, including the system-wide Web server directory.
