### Further security of server-info and server-status

Because both the server-info and server-status pages contain private information that should not be accessible to anyone on the network, there are a few extra ways you can secure that information. You can restrict that information only to the local host; however, in some environments that may not be practical.

If you must allow other machines or networks to access such detailed configuration information, allow only as many machines as necessary, and preferably only those machines on your local network. Also, be aware that, in the wrong hands, the information displayed by the server-info and server-status pages can make it much easier for the security of your entire machine to be compromised.

It may be beneficial to change the URL used to reference both of the aforementioned pages. This is an example of "security through obscurity," which should not be relied upon but can make it just a little more difficult for unauthorized individuals to obtain information about your Web server (particularly if you cannot restrict connections to the local network). To accomplish this, simply change the filename in the Location directive, as in the following lines:

```
<Location /server.information.page>
```

and:

```
<Location /server.status.page>
```

### Logging errors

The error log contains messages generated by the server that describe various error conditions. The ErrorLog and LogLevel directives in the http.conf file (as described in the section on configuring the server) can modify the filename and amount of information that is logged. The default log is /etc/httpd/logs/error_log (which is a link to /var/log/httpd/error_log). Here are a few sample lines from the error log:

```
Mon 28 10:29:13 [notice] Apache/2.2.4 (Fedora)
  configured resuming normal operations
Mon 28 10:43:07 [error] client [127.0.0.1] client denied by
  server configuration: /var/www/html/server-status
Mon 28 10:06:42 [error] client [127.0.0.1] File
  does not exist; /var/www/html/logfile.html
Mon 28 10:12:28 [notice] received SIGTERM, shutting down
```

The first line indicates that the server has just started and will be logged regardless of the Log directive. The second line indicates an error that was logged to demonstrate a denied request. The third line shows an error, which represents a request for a file that does not exist. The fourth line, also regardless of the LogLevel directive, indicates that the server is shutting down. The error log should also be monitored periodically because it will contain the error messages from CGI scripts that might need repair.

### Analyzing Web traffic

The webanalyzer package can take Apache logs and produce usage reports for your server. Those reports are created in HTML format so you can display the graphical information. Information is provided in both table and graph format.

To use the webanalyzer, the webanalyzer package must be installed (yum webanalyzer). You can run webanalyzer with options that has no values in /etc/webalizer.conf files to get the information it needs. As an alternative, you can use command-line options to override settings in webalizer.conf. To use the defaults, simply run the following:

```
# webanalyzer
```

If all goes well, the command should run for a few moments and exit silently. Based on the information in the /etc/webalizer.conf file, the /var/log/httpd/access_log file is read and an index.html file is copied to the /var/www/html/usage/ directory. You can view the output by opening the file in any browser. For example, you can type the following in the location box:

```
http://localhost/usage
```

The output report shows a 12-month summary of Webalizer activity. On the bar chart, each month a blue bar represents the number of hits on the Web site, a dark blue bar shows the number of different files, and a light blue bar shows the number of pages opened. It also shows data for the number of visitors and the number of sites visited in the right column. The amount of data transferred, in kilobytes, is displayed as well.

### Statistics Packages Available for Fedora and RHEL

Analyzing the transfer log by hand isn't much fun. Several packages have been written to automate this task, including the following two:

- **Analog**: This free-log analyzer is very fast and easily configurable, and produces very detailed output (including bar graphs and hyperlinks). More information can be found at http://www.analog.cx.
- **AWStats**: The Advanced Web Statistics tool (awstats package) produces graphical statistics representing Web-server access. ## Summary

Web servers are responsible for storing and delivering the vast amount of content available on the World Wide Web to clients over all world. Although several Web-server software packages are available for Fedora and RHEL systems, the most popular is by the Apache server. This chapter describes how to install, configure, and run an Apache server in Fedora. The httpd daemon processes requests for Web content (HTTP). Configuration files define what content is available and how it can be accessed. In particular, the /etc/httpd/conf/httpd.conf file is used to configure the server.

The Apache package also includes facilities for logging error and transfer messages. You can look for the access_log and error_log files in the /etc/httpd/logs directory. The access_log file contains information on content requests that have been served by the server. The error_log file lists error conditions that have occurred and times when service was denied. You can use tools such as Webizer to simplify the viewing of Apache log data.
