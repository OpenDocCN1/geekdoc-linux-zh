# Verifying installed packages with rpm

If something in a software package not working properly, or if you suspect that your system
haven tampered with, use the (-V) option of rpm can help you verify installed software
against its original software package. Information about each installed package is stored on
y computer in the RPM database. By using the verify option, you can check whether any
changes were made to the components in the package.

> NOTE: verify option uses the uppercase letter (-V), while the verbose option uses the lowercase
(-v).

Various file size and permissions are done during a verify operation. If everything is fine,
there is no output. Any components that have changed when they were installed will be
printed along information how they were changed. Here's an example:

```
# rpm -V ppp
S.5....T. c /etc/ppp/chap-secrets
S.5....T. c /etc/ppp/options
S.5....T. c /etc/ppp/pap-secrets
```

This output shows that the ppp package (used to dial a TCP/IP network such as the Internet)
h three files changed since it was. The notation at the beginning shows that the
file size (S), the MD5 sum (M) and the modification time (T) have all changed. The letter c
shows these are all configuration files. By reviewing these files to see that the changes
were the only that I made to get PPP working, I can verify that the software is okay.

The indicators you may see when you verify the contents of a configuration file:

+   * 5 (MD5 Sum) — An MD5 checksum indicates a change to the file contents.
* S (File size) — The number of characters in the file has changed.
* L (Symlink) — The file has become a symbolic link to another file.
* T (Mtime) — The modification time of the file has changed.
* D (Device) — The file has a device special file.
* U (User) — The user name that owns the file has changed.
