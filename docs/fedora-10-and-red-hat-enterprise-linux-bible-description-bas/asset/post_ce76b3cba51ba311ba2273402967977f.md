## Getting a domain name

For people to be able to send to the users on your mail server, you must have your own domain name. Chapter 25 describes how to get your own domain names and set up a DNS server. The critical issue for your mail server is to make sure that the MX record for your domain on the DNS server points to that of your mail server.

> NOTE: It is possible that your ISP will not allow you to have a private mail server on your residential Internet account. To enforce this, the ISP may block packets from being addressed to port 25. You may need to contact them to open that port so you can set up a mail server on that connection. Because many spamming and otherwise evil (or at least poorly controlled) e-mail servers to hide behind dynamic IP addresses, many will neither allow e-mail addresses from dynamic IP addresses nor accept e-mail sent from those servers.

## Configuring basic sendmail settings (sendmail.mc)

Much of the configuration of your mail server comes from information in your /etc/mail/sendmail.mc file. This file sets sendmail default values that can be used in most cases, you may not have to do anything with sendmail.mc. I recommend you to check this section so you understand how your mail server is configured.

Changes you make to the sendmail.mc file do not immediately take effect. First you must compile the sendmail.mc settings to generate the /etc/mail/sendmail.cf file. I describe how to do it in the "Starting sendmail and generating database files" section.

The resulting /etc/mail/sendmail.cf file contains over 1,800 lines of settings and comments that are used to direct the behavior of your sendmail daemon. The m4 macros you use in sendmail.mc file are different from the settings in sendmail.cf file.

> NOTE: The m4 utility can be used to process text files containing macros in IEEE Standard 1003.1-2001 format (Section 12.2. Utility Syntax Guidelines). This is particular about how you use single quotes backticks, so be careful editing sendmail.mc. For details on the m4 utility, type info m4.

To find which macros to use for setting up your sendmail.cf file, refer to the /usr/share/doc/sendmail*/README.cf file. If you are interested in details on the contents of your sendmail.cf file, I have included an exhaustive description of sendmail.cf in the download files at the Fedora 10 and Red Hat Enterprise Linux Bible site (http://www.wiley.com/go/fedora10bible).

# Part IV: Fedora RHEL Network and Server Setup

> CAUTION: Because of how sendmail is configured in Fedora, you should not directly modify the sendmail.cf file. The sendmail.cf file is regenerated automatically when sendmail restarts if sendmail.mc changes. As a result, any modifications made directly to sendmail.cf will be lost.

The following code samples are from the /etc/mail/sendmail.mc file that accompanies the Fedora version of sendmail.

> NOTE: Lines that begin with dnl (delete to new line) in the sendmail.mc file are content lines. In most cases, I have left them out in the examples shown. Also, notice that sendmail uses backticks as opening quotes and straight quotes as quotes.

```
divert(-dnl)
include(/usr/share/sendmail-cf/m4/cf.m4)*dnl
VERSIONID setup for Linux)*dnl
OSTYPE(linux)*dnl
```

The first lines of the sendmail.cf do some housekeeping. The divert line removes extra output when the configuration file is generated. The include line causes rules set by sendmail. The VERSIONID identifies the configuration file as being for Linux systems, or as Fedora (although this setting is not checked, so could be anything you like). The OSTYPE, however, must be set to linux to get the proper location of lines needed by sendmail.

```
dnl define(confSMTP_LOGIN_MSG, `Sendmail: Sb')dnl
def('SMART_HOST', `smtp.your.provider`)*dnl
```

Here are two lines you can consider uncommenting (removing the dnl string). The confSMTP_LOGIN_MSG definition can be used to disguise the sendmail server you are using (Change sendmail to whatever). However, for the second line, by default, the sendmail daemon tries to send your outgoing emails directly to the mail server if you want all to be relayed to a particular mail server instead, you can remove the dnl, which stands for "delete to new line" from the beginning of the SMART_HOST line above (leave one at the end). Then, change smtp.your.provider to the fully qualified name of the mail server you want to use. Of course, you need to be sure that the SMART HOST you define accepts relays from your mail server.

```
define(confDEF_USER_ID, `8:12`)*dnl
```

Instead of running as the root, the daemon daemons run as the user (UID 8) and group (GID 12), based on the dnl line set previously. This is a good policy, because it prevents whoever who confDEF_USER_ID might compromise your mail server from gaining root access to your machine.

```
dnl define(confAUTO_REBUILD)*dnl
define(conf_CONNECT, `lm`)*dnl
```
