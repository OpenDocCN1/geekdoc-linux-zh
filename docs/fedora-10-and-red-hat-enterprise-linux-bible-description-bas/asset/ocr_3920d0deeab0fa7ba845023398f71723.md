# Understanding LDAP

LDAP lets you create directories of information that can be shared among applications over a network. It is particularly geared towards applications that are used to look up information that is fairly stable over and over again (in other words, information that's being looked more than it's changed). That's why LDAP is popular for uses such as storing information about people, addresses, and other kinds of data that may require high access with relatively few changes.

Because LDAP is extraordinarily flexible design, as an LDAP developer or administrator you have a lot of control:

+   - How the information in the directories is organized.
- How and by whom information can be accessed.
- The scale, to global, by which information is distributed. (Information can be replicated to other servers at you chose and sped up automatically.)

Despite its flexibility, however, you don't have to begin designing each directory create from scratch. LDAP has many predefined structures of information you can rely on to build your directories. Those data structures are defined in several different documents referred to as RFCs (Request for Comments) that you can list from the IETF site (http://www.ietf.org/sfc.html). There are RFCs for almost every aspect of the Internet protocols and related services. Important RFCs for LDAP definitions include:

+   - RFC 2252 — Defines the framework for LDAP.
- RFC 2256 — The X-500 schema for LDAPv3.
- RFCs 1274, 2079, 2247, 2307, 2587, 2589 — Define specifications for including user attributes, Uniform Resource Identifiers, domain names, NIS data, public key infrastructure (PKI), and dynamic directory services in LDAP directories.

The documents on which these RFCs are based called CCITT X.500 standard and the related ISO9594 directory services standards. In particular, X.521 and X.520 define some of the most basic object classes and attribute types.

Keep in mind, however, that these standards provide guidelines. When you put together your own LDAP directory, your OpenLDAP server will have to deal directly with the schemas that implement those standards on the OpenLDAP server.
