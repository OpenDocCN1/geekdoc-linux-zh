To see if a particular service handled by xinetd is on or off, go to the /etc/xinetd.d directory and open the file representing that service with a text editor. The disable line sets whether or not the service is currently disabled. The following example is an excerpt from the /etc/xinetd.amanda file:

service amanda

```
{
socket_type     = dgram
protocol        = udp
wait           = yes
user            = amanda
server         = /var/lib/amanda/amamad
server_args    = auth-bsd andnsp
disable         = yes
}
```

In this example, the amanda configuration file represents a means of retrieving backup index files from amanda clients. By default, the service is turned off. When the service is on, a request to the xinetd server daemon for the amanda service from the network is handed to the amanda daemon. Arguments to daemon are on the server_args line.

To enable a service in /etc/xinetd.d file, edit the file using any text editor as root user. Turning the service is as easy as changing the disable option to no and restarting the xinetd daemon. For example, you could change the line in the /etc/xinetd.amanda so that it appears as:

```
disable        = no
```

Then you could restart the xinetd daemon (without turning off the daemon itself):

```
# service xinetd restart
```

> NOTE: Although not all services support this, the xinetd service lets you use the reload instead of the restart option with the service command shown. With xinetd already running, a reload can occur faster and less interruption to system services by not completely shutting down xinetd.
