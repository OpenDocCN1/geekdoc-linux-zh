# Chapter 26: Integrating Fedora with Apple Macs 997

A common practice is to add the text "Home Directory" to the line that contains the single tilde (~) so that it appears as:

```
~ "Home Directory"
```

To share additional directories, simply add a full path name to the directory you want to share and the volume name you want to assign to it. For example:

```
/var/topprojects "Linux Toys"
```

As you can see in this example, /var/topprojects is shared under the name "Linux Toys . The volume is limited to 27 characters and cannot contain the ": character. In this simple case, access permissions to the volume are managed by the user, host, and folder-level security is set up for the volume (see the "Securing netatalk volumes" section for more information).

You can also add options directly to each listing in the AppleVolumes.default file. On the same line, after the path (/var/topprojects) and volume name ("Linux Toys") options as shown in the previous example, you can add some options. Here are a few options that might interest you (look inside the AppleVolumes.default file for others):

+   - casefold: Normally, when a shared volume appears on the Mac client's screen, file and directory names appear in lower- and uppercase as they exist on the Linux system. By replacing option with lower or toupper, you can have lowercase or uppercase in both directions, respectively. Or, you could have translated (xlatelower or xlateupper) to set what the client sees.
- allowusers@groups or denyusers@groups — You could add specific users or groups to an allow or deny option to have those users allowed or denied access to the shared volume. (Separate each with a comma; indicate a group with an @ sign.)
- password:pwd — Replace pwd with a password (up to eight characters) to define a password that is specific to the volume.
- rolist@groups or rlistopt@groups — Use rolist options to allow read-only or read/write access, respectively, to the users or groups you add to the list. (Separate each with a comma; indicate a group with an @ sign.)

By opening shared volumes and creating files and folders in the Mac automatically create some files and folders that are invisible to the Mac client. These files and folders hold resource fork information and other features that would not normally be in a Linux file system. The "File- and directory-level security" section describes these files and folders.
