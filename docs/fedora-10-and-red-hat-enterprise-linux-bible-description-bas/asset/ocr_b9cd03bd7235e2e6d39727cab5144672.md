# Modifying the Squid configuration file

If you want to start a more complex set of access permissions for Squid, you should start with the default squid.conf configuration file (described earlier).

To begin, open the /etc/squid/squid.conf file (as the root user). You will see a lot of information describing the values that you can set in this file. Most of the tags that you need to configure Squid are used to set up caching and provide access to your proxy server.

> TIP: Don't change the squid.conf.default file! If you really mess up your squid.conf file, you can start again by making another copy of this file squid.conf. If you want to recall exactly what changes you have made so far, try the following from the /etc/squid directory:
\```bash
# diff squid.conf squid.conf.default | less
```
This will show you the differences between your actual squid.conf and the version you started with.

# Configuring access control in squid.conf

To protect your computing resources from being used by anyone, Squid requires that you define which hosts have access to your HTTP (Web) services. By default, all hosts are denied access to Squid for the local host. With the acl tag, you can create access lists. Then, with the http_access tag, you can authorize access to HTTP (Web) services for the access lists you create.

The form of the access control list (acl) is:

```
acl name type string
ac name type file
```

The name is any you want to assign to the list. A acl is a string of text, and file is a file of information that applies to the particular type of acl. Valid acl types include dst, src, dstdomain, srcdomain, url_path, url_time, port, proto, method, browser, and user.
Several access lists are set up by default. You can use these assigned acl names to assign permissions to HTTP or ICP services. You can also create your own acl names to assign to those services. The default acl names from the /etc/squid/squid.conf that you can use or change:

```
acl all src 0.0.0.0/0.0.0
acld manager proto cache_object
acld localhost src 127.0.0.1/255.255.255.255
acld SSL_ports port 443 563
acld Safe_ports port 80 # http
acld Safe_ports port 21 # ftp
acld Safe_ports port 443 563 # https, snews
```
