It is set up as an NFS file system (nfs) that can be mounted on the /oak/apps directory locally. This system is not mounted automatically (noauto), however, and can be mounted only as read-only (ro) using the mount command when the system is already running.

> TIP: The default is to mount an NFS file system as read/write. However, the default for exporting is read-only. If you are unable to mount an NFS system, check that it was exported as read/write from the server.

# Mounting noauto file systems

In /etc/fstab there can also be devices for other file systems that are not mounted automatically. For example, you might have multiple disk partitions on your hard disk or an NFS shared file system that you might want mount only occasionally. A noauto system can be mounted manually. The advantage is that when you type the mount command, you can type less information and have the rest filled in by the contents of the /etc/fstab. So, for example you:

```
# mount /oak/apps
```

With this command, mount knows to check the /etc/fstab to get the file system to mount (oak:/apps, nfs), and the options to use with the mount (in this case ro for-only). Instead of typing the local mount point (/oak/apps), you could have typed the remote file name oak:/apps instead, and had other information filled in.

> TIP: When naming mount points, including the name of the remote NFS server can help you remember where the files are actually stored. This may not be possible if you are sharing home directories (/home) or mail directories (/var/ spool/mail).

# Using mount options

You can add mount options to the /etc/fstab (to a mount command line itself) to impact how the file system is mounted. When you add options to /etc/fstab, they must be separated by commas. The following are some options that are valuable for mounting NFS file systems:

+   - hard With this option, if the NFS server disconnects or goes down while a process is waiting to access it, the process will hang until the server comes back up. This option is helpful if it is critical that the data you are working with not out of sync with the programs that are accessing it. (This is the default behavior.)
- soft If the NFS server disconnects or goes down, a process trying to access data from the server will time out after a set period of time when this is on.
