Here is an example of how the line in the previous edquota example could be changed:

| /dev/sda2 | 596 | 512000 | 716800 | 1 | 800 | 1000 |

In this example, the soft limit on the number of blocks that the user jake consume on the /dev/sda2 device (/home) 512000 blocks (or 500MB); the hard limit is 716800 blocks (700MB). And soft and hard limits are 800 and 1000, respectively. If either of the soft limits are exceeded by the user jake, he has seven days to get back under the limit, or he will be blocked from using any more disk space or nodes.

Further attempts to write a partition after the hard limit has exceeded results in a failure to write to the disk. When this happens, the user who tries to create the file that exceeds the limit will see a message like this:

```
ideo(3,2): write failed, user grace limit reached.
cp: writing 'abc.doc': Disk quota exceeded
```

Exceeding quota can also prevent that user from logging in again logging in from some graphical user interfaces requires being able to write to a user's home directory.

Instead of assigning quotas to users, you can assign quotas to any group listed in the /etc/group file. Instead of the -u option to edquota, use the -g option followed by a group name.

# Checking quotas

To report on how much space and how many inodes each user on your computer (for which you have set quotas) has consumed, use the repquota command. Here's an example of the repquota command for reading quota data to all partitions that are using quotas:

```
# repquota -a
*** Report for user quotas on device /dev/sda2
Block grace time: 7days: In grace time: 7days
Block limits File limits
User soft | hard | grace used | soft | hard | grace
root -- 1973984 | 0 | 0 | 2506 | 0 | 0
jake -- 1296 | 700 | 1700 6days | 3 | 0
```

In this example, jake has exceeded his soft limit of 700 blocks. He currently has six days in his grace period to remove enough files so that the soft limit does not become the hard limit.
