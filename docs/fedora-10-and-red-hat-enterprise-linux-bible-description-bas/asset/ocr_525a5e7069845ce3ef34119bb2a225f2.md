+   The Rexec service (/usr/sbin/in.rexecd) accepts remote execution requests from the reexec command (from other Linux or UNIX systems). By default, the service is off. To allow remote execution, the user making the request must provide a valid user name and password.

+   The Ksh service (/usr/kerberos/sbin/ksh) receives remote execution requests from the rsh command. Install the kb5-workstation-servers-package to get this service. It uses Kerberos authentication and encryption, making it more secure than the alternative rsh daemon. By default, the service is off. However, if you turn it on (by editing the /etc/xinetd.d/ksh file and changing the disable = no), it takes precedence over the rsh daemon.

The OpenSSH service (using the ssh daemon) described earlier can also be used for remote execution. OpenSSH is a more secure way to do remote execution than the other methods just described. Therefore, in most cases you should bypass these services and use OpenSSH for remote execution.

> CROSS-REFERENCE: Login commands for login services are described in Chapter 16.

# Talk server

Use the /in.talk or in.ntalk to allow users to communicate with the talk command. The talk command enables users to send messages back and forth in real time. The talk daemon handles requests on port 517, and the ntalk daemon handles requests on port 518.

Both services are turned off by default. To turn either service, edit the /etc/xinetd.d/talk and/or /etc/xinetd.d/ntalk files and change the disable = yes to disable = no. Restart the xinetd daemon: service xinetd restart.

# Finger server

The finger (/usr/sbin/in.fingerd) lets people use the finger command to request information about active users on Linux or UNIX systems locally or over a network. This service is off by default.
