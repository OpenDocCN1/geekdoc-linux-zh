## Configuring the CUPS server (cups.conf)

The cups daemon listens for requests to your CUPS print server and responds to those requests based on settings in the /etc/cups/cups.conf file. The configuration variables in cups.conf file are in the same form as those of the Apache configuration file (httpd.conf). After changing cups.conf, restart the server for changes to take effect.

The Printer configuration window adds access information to the cups.conf file. You can step through the cups.conf file to further tune your CUPS server. There are a few suggestions:

### Classification topsecret

No classification is set by default. With the classification set topsecret, you can have Top Secret displayed on all pages that go through the print server. Other classifications can substitute for topsecret include: classified, confidential, secret, and unclassified.

```
ServerCertificate /etc/cups/ssl/server.cert
ServerKey /etc/cups/ssl/server.key
```

The ServerCertificate and ServerKey lines (not set by default) can be set up to indicate where the certificate and key are stored, respectively. Activate these two lines if you want to do encrypted connections. Then add your certificate and key to the files noted. Keep in mind that these keys are for the CUPS Web interface and are not used for sending print jobs.

### Browsing On

BrowseProtocols cups
BrowseOrder Deny,Allow
BrowseAllowfrom @LOCAL
BrowseAddress 255.255.255.255
Listen :*631

Browsing is the feature where you broadcast information about your printer on your local network and listen for other servers'. Browsing is by default, but for the local host (@LOCAL). You can allow including CUPS browser information for additional selected addresses. Browsing information is broadcast, by default, at address 255.255.255.255.

To enable Web-based CUPS administration, the cuspd daemon listens on port 631 for all network interfaces to your computer by entry: Listen :*631.
BrowseRelay source-address destination-address

By turning BrowseRelay (it's off by default), you can allow CUPS browser information to be passed among two or more networks. The source-address and destination-address can be individual IP addresses or represent network numbers. This is a good way to allow users on several connected LANs to use printers on nearby LANs.

You can allow or deny access to different features of the CUPS server. An access definition for a CUPS printer (from the Printer configuration window) might appear as follows:

```
<Location>/printers/nsl-hpl>
Order Deny,Allow
Deny From
Allow From 127.0.0.1
AuthType None
</Location>
```

Here, to the nsl-hpl printer is allowed for the settings in the cuspd.conf file, you must reload the CUPS service to have the changes take effect. As root user, type service reload. (The reload option reads the new configuration without restarting the daemon).

If you change any of the settings in the cuspd.conf file, you must reload the CUPS service to have the changes take effect. As root user, type service reload. (The reload option reads the new configuration without restarting the daemon).

## Configuring CUPS printer options

When a new printer is created from the Printer configuration window, that printer is defined in the /etc/cups/printers.conf file. Here's an example of a printer definition in printers.conf:

```
<DefaultPrinter hp2100>
Info HP LaserJet 2100M
Location HP LaserJet 2100M in hall closet
DeviceURI=/par/HP_LaserJet_2100_Series?device=/dev/parport0
State Idle
Accepting Yes
Shared Yes
JobSheets none none
QuotaPeriod 0
PageLimit 0
KLimit 0
OpPolicy default
ErrorPolicy stop-printer
</DefaultPrinter>
```

This is an example of a local printer that serves as the default printer for the local system. The most interesting information relates to the DeviceURI, which shows that the printer is connected to parallel port /dev/parport0. The State is Idle and the Accepting value is Yes (the printer is accepting jobs by default).

The DeviceURI has several ways to identify the name of a printer, reflecting how the printer is connected. Here are some examples in the printers.conf file:

```
DeviceURI parallel:/dev/lp0
DeviceURI serial:/dev/ttyUSB0?baud=38400+size=8+parity=none+flow=soft
DeviceURI scsi:/dev/scsi1
DeviceURI socket://hostname:port
DeviceURI tftp://hostname/path
DeviceURI http://hostname[port]/path
DeviceURI ipp://hostname/port
DeviceURI smb://hostname/printer
```

The first three examples show the form for local printers (parallel, serial, and scsi). The other examples are remote hosts. In each case, hostname is the host's name or IP address. Port numbers or paths identify the locations of each printer on the host.

> TIP: If you find that are not able to print because a particular printer driver is not supported in CUPS, you can set your printer to accept jobs in raw mode. This can work if you are printing from Windows clients that have the correct driver installed on those. To allow raw printing in CUPS, uncomment the following line from the /etc/cups/mime.types file in Linux:

```
application/octet-stream
```

And uncomment the following line from the /etc/cups/mime.types file:

```
application/octet-stream
```

After that, you can, set your printer to accept jobs in raw mode.

## Using Printing Commands

To remain compatible with older UNIX systems, CUPS supports many commands. The following commands are common:

- lps: List the printers currently configured in CUPS.
- lpq: List the print queue for a printer.
- lprm: Remove jobs from the print queue.
- lpstat: Show the status of a printer.
- lp: Send a job to a printer.
- lpadmin: Configure and manage printers.

## Removing jobs with lprm

Users can remove their own print jobs from the queue using the lprm command. Used alone on the command line, lprm removes all of the user's print jobs from the default printer. To remove jobs from a specific printer, use the -P option, as follows:

```
$ lprm -P lp0
```

To remove all print jobs for the current user, type the following:

```
$ lprm -
```

To remove an individual job from the queue, indicate the job number of that print job on the lprm command line. To find the job number, type the lpq command. Here's what the output of that command may look like:

```
$ lpq
printer is ready and printing
Rank Owner Job Files Total Size Time
active root 133 /home/jake/perl 467
2 root 197 /home/jake/mydoc 23948
```

The output shows two printable jobs waiting in the queue. Under the Job column, the job number associated with each document. To remove the first job, type the following:

```
# lprm 133
```
