# Chapter 25: Making Servers Public with DNS 967

> CAUTION: Setting up a DNS server can be complex and (these days) potentially dangerous undertaking. A compromised DNS server can cause requests for host addresses to be directed to a cracker's server. The sample DNS server in this one is created as an example of a DNS server for a home or small office environment. Information on the many different ways to set up a DNS server, go to the BIND 9 Administrator Reference manual at `/usr/share/doc/bind-9*/`Bv9ARM.html.

# Understanding DNS

The basic function of a name server is to answer queries by providing the information that those queries request. A DNS name server translates domains and hostnames into IP addresses. Each domain is typically represented by at least two DNS servers.

+   **Primary (master) name server** — This name server contains the copy of authoritative information about the domains that it serves. In response to queries for information about its domains, this server provides information marked as authoritative. The primary is the ultimate source for data about the domain.
**Secondary (slave) name server** — This name server gets all information for the domain from the primary name server. As is the case for the primary server, DNS considers the secondary's information about the domain that it serves authoritative, although the domain records can be overwritten from the primary.

NS (which stands for Name Server) records in the parent zone for a domain list the primary and one or more secondary name servers. *delegation* of servers defines the servers that have authority for the zone.

Because records change as you add, remove, or reconfigure the computers, you assign expiration times for information about your zone. You set the expiration time in the live `named.conf` file (which I describe later).

Other specialized types of DNS servers are possible as well. Although these types of servers do not have authority for any zones, they can prove useful for special purposes:

+   **Caching name server** — This type of server caches the information it receives from the locations of hosts and domains. It holds information that it obtains from authoritative servers and reuses information until the information expires (as set by the TTL fields).
**Forwarding name server** — Creating a server's not authoritative for a zone but that can forward name server requests to other name servers may prove efficient. The server is essentially a caching name server, but is useful in cases where computers lie behind a firewall and in which only one computer can make DNS queries outside that on behalf of all the internal computers.
