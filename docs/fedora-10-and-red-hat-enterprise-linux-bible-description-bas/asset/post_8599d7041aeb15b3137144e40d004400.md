## E-mail servers

The most common protocols to download e-mail from a mail server to a client workstation are Post Office Protocol (POP3) and Internet Message Access Protocol (IMAP4). If you use Fedora or RHEL as your mail server, you can configure the dovecot package to provide POP and IMAP services.

Dovecot is an IMAP/POP3 mail server that works with maildir and mbox formats. You use IMAP or POP3 if your users get their mail from their own desktops instead of running mail clients on the server. By default, all POP or IMAP services are free. Choose the one you like to use from those provided in the e-mail readers listing in Table B-1.

The default mail-transfer agent that comes with Fedora and RHEL is called sendmail. If sendmail software is installed, the service is started automatically. However, you must configure various files in the /etc/mail directory for the service to work beyond the localhost.

Postfix is an alternative to sendmail, it is the exit mail transport agent. Using the alternatives feature (described earlier in this appendix and in Chapter 10), you can easily make any of those packages your default mail-transfer agent. Configuration files for postfix are located in the /etc/postfix, while exim configuration files are in the /etc/exim directory. Also make sure that you turn sendmail off (chkconfig postfix on or chkconfig exim on). (Consider removing the sendmail package completely if you are replacing it with postfix).

> CROSS-REFERENCE: Chapter 19 contains details on how to configure sendmail and postfix.

## News server

Fedora and RHEL come with the Internet Network News Server (INN) software to let you set up a Fedora or RHEL system as a news server. INN can provide your users access to thousands of Internet newsgroups. It can also be used as a corporate-email repository so wogroups share information about a project.

By default, INN service is off in Fedora and RHEL. To turn it on, type chkconfig inn on. Then start by typing service inn start. To make the service usable, you must edit files in the /etc/news directory.

## Print servers

The Common UNIX Printing System (CUPS) is server software included as the default printer software for the current releases of Fedora and RHEL. As an alternative, the LPR New Generation (LPRng) software is still available but is no longer provided with Fedora or RHEL distributions.

CROSS-REFERENCE: Information on setting up printers can be found in Chapter 17.

The Common UNIX Printing System (CUPS) is an alternative to LPRng and other printing interfaces that were built on facilities designed for line in the 1970s. CUPS is based on the Internet Printing Protocol (RFC 2616). Although it is compatible with other UNIX/Linux print facilities, CUPS is intended to make it easier to support new printers, protocols, and other devices as they become available.

The CUPS server (cupsd) is set to run up by default. Configuration files for CUPS are located in the /etc/cups directory.

## Network Time Protocol server

The Network Time Protocol (NTP) Server synchronizes time among computers on a network.

The Fedora and RHEL boot processes lets you to the NTP service. To further configure ntp, you must edit the /etc/ntp.conf file. The /etc/ntp.conf contains information that identifies the addresses of synchronization sources and modes of operation. The /etc/ntp/keys file can be used to turn authentication.

## Portmap server

The portmap server translates Remote Call (RPC) numbers to TCP/IP and UDP port numbers. Certain network services, such as NFS (nfs) and Wall (rwalld), only work properly if this server is running. RPC numbers are stored in the /etc/rpc-file.

## Network Information System servers

Network Information System (NIS) is a software feature developed by Sun Microsystems to manage information for UNIX (and now Linux) computers on a network. Using NIS, a group of computers can share common passwd, groups, hosts, and other configuration files.

By default, services are off. You can run NIS services for your computer as either an NIS client (sharing information) or an NIS server (distributing information). NIS client needs to start the /etc/init.d/ypbind and identify the NIS servers by the /etc/yp.conf file.

To use Fedora or RHEL as an NIS server, you must gather all the configuration files you want, start the /etc/init.d/ypserv script. The script runs the /usr/sbin/ypserv daemon, which takes care of the distribution of information to the NIS client.

## Dynamic Configuration Protocol server

Instead of going each computer on your local network and adding all the TCP/IP information they need in order to (IP address, netmasks, gateways, and so on), you can configure Fedora or RHEL as a Dynamic Host Configuration Protocol (DHCP) server so The client simply identifies the IP address of the DHCP server so when the client starts up its network connection, the DHCP server automatically assigns its network address.

By default, DHCP is turned off. To turn it on, type chconfig dhcp on. Then start the service by typing service dhcp start. Besides starting the service, you must also configure the /etc/dhcpd.conf file.

> CROSS-REFERENCE: Chapter 23 describes how to set up a DHCP server.

## Lightweight Directory Protocol server

If your organization Lightweight Directory Access Protocol (LDAP) databases of information, running the LDAP server that comes with Fedora or RHEL enables you to access those databases. Likewise, the LDAP server enables you to use LDAP-enabled applications, such as Netscape Roaming Access and sendmail 8.

By default, the LDAP service is turned off. To turn it on, type chconfig ldap on. To start the service, type service ldap start. In addition to running the start-up script, you must configure files in the /etc/ldap/ directory.

> CROSS-REFERENCE: Chapter 22 shows how to set up an e-mail address book using LDAP.
