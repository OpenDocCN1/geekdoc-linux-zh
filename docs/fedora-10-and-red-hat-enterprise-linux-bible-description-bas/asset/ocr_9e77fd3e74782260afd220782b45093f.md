# Recurring debugging

If your modem works, but you are not getting connected at all, the first thing to do is turn on logging for PPP. This will help track down the problem. If you are still stuck looking at the output, have an expert review the log file. Make sure that debugging is turned on by setting DEBUG=yes in the `ifcfg` file.

> TIP: If you are on the Internet from another machine, I recommend posting your failed PPP output to com.protocol.ppp newsgroup, where some very smart PPP experts can help answer your questions. After post, wait for a few days' messages from the group. Chances are that someone has already run into the same problem and has a solution. Also, post only the parts of the log file that are relevant. You can also ask your local Linux group for help.

To have debugging separate to a log file for PPP, add these lines to the `/etc/rsyslog.conf` file:

| daemon.* | /var/log/ppmsg |
| local2.* | /var/log/ppmsg |

After this, restart rsyslog daemon process (as root user) by typing this:

```
# service rsyslog restart
```

It's best to try to do this debugging process from the desktop to have several Terminal windows (I would suggest at least three). From the first window, start a command that lists the contents of the log file we just defined (`ppmsg`) as debug messages in:

```
# tail -f /var/log/ppmsg
```

In the next window, start the PPP interface. Assuming it is the ppp0 interface, use the following command as root user:

```
# ifup ppp0
```
