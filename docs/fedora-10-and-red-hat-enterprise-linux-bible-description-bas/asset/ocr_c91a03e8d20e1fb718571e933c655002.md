```
dnl define(conf_QUEUEWARN, '4h')dnl
dnl define(conf_QUEUETURN, '5d')dnl
dnl define(conf_QUEUE_LA, '12h')dnl
dnl define(conf_REFUSE_LA, '18h')dnl
dnl define(conf_IDTO_IDENT, '0')dnl
```

The commented lines actually show the default values for certain timeout conditions. You can remove comments and change these values if you like. The CONF_QUEUEWARN option sets how long delivery of a message has been deferred to show a warning message to the sender. Forever (4h) is the default. The CONF_QUEUETURN option sets how long before an indefinite message is returned. The CONF_QUEUE_LA and CONF_REFUSE_LA options set the system load levels at which mail is queued or refused, respectively. The CONF_IDTO_IDENT option sets the timeout when waiting for a response to an ID query to be received (by it is 0, which means no timeout).

```
FEATURE(no_default_msa, '')dnl
FEATURE(smarsh, '/usr/sbin/smarsh')s')dnl
FEATURE(mailertable, 'hash -o /etc/mail/mailertable.db')dnl
FEATURE(virtusertable, 'hash -o /etc/mail/virtusertable.db')dnl
FEATURE(redirect)dnl
FEATURE(always_add_domain)dnl
FEATURE(use_cw_file)dnl
FEATURE(use_ct_file)dnl
FEATURE(local_procmail, 'procmail -t -Y -a h -d $u')dnl
FEATURE(access_db, 'hash -TCMJPf /etc/mail/access.db')dnl
FEATURE(blacklist_recipients)dnl
```

The FEATURE macro is used to set some sendmail features. The no_default_msa feature tells sendmail not to generate a default daemon (which is normally set to on port 587). The smarsh feature defines /usr/sbin/smarsh as the simple shell used by sendmail to receive commands. The mailertable and virtusertable options set the locations of the databases. The redirect option allows you to redirect mail for users who have moved and provide new addresses. The always_add_domain option causes the local domain name to be added to the hostname on all delivered mail. The use_cw_file and use_ct_file options tell sendmail to use the file /etc/mail/local-hosts for alternative hostnames for this mail server and /etc/mail/trusted-users for trusted users, respectively. (A trusted user can send mail as without without resulting in a warning message).
