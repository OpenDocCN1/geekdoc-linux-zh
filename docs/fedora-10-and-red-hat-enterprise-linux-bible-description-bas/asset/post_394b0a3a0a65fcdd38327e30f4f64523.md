## Using file-redirection metacharacters

Commands receive data from standard input and send it to standard output. Standard input is normally user from the keyboard, and standard output is normally displayed on the screen. Using pipes (described earlier), you can direct standard output from one command to the standard input of another. With files, you can use less (<) and greater than (>) signs to redirect data to from files. Here are the redirection characters:

- Direct the contents of a file as input to the command (because many commands take a file name as of option, the < key is not usually needed).
- Direct the output of a command to a file, overwriting any existing file.
- >> Direct the output of a command to a file, adding the output to the end of the existing file.

Here are some examples of command lines where information is directed to from files:

```
$ mail root < ~/.bashrc
man chmod -b > /tmp/chmod
$ echo "Finished project on $(date)" >> /projects
```

In the first example, the .bashrc file in the home directory are sent in a mail message to the user's root user. The second command chmod removes extra back spaces (col -b), and sends the output to the file /tmp/chmod (erasing the previous /tmp/chmod file, if it exists). The final command results in the finished text being added to the user's project file:

> Finished project on Wed Jun 25 13:46:49 PST 2008

You could also pipe the output of the previous command to another command. For example, the command line below would just show line in a message to the user boss@example.com:

```
$ echo "Finished project on $(date)" | mail -s boss@example.com
```

## Understanding file permissions

After you've worked with Linux for a while, you are sure to get a Permission denied message. Permissions associated with files and directories in Linux were designed to keep users from accessing other users' private files and protect important system files.

The nine bits assigned to each file for permissions define the access that you and others have to your file. Permission bits appear as rwxrwxrwx. The first three bits apply to the owner's permission, the next three to the group assigned to the file, and the last three to all others. The r stands for read, the w stands for write, and the x stands for execute permissions. If a dash appears instead of the letter, it means permission is off for that associated read, write, or execute.

You can see the permission for any file or directory by typing the ls -ld command. The named file and directory appears shown in the following example:

```
$ ls -ld ch3 test
-rw-r--r-- 1 chris    4983 Jan 18 22:13 ch3
dr-xr-x 2 sales     1024 Jan 24 13:47 test
```

The first line shows that (ch3) has read and write permission for the owner and group. All others have read permission, which means they can view the file but cannot change its contents (although a user may be allowed to remove the file, since the ability to remove a file is based on directory permissions). The second line shows a directory (indicated by the d letter before the permission bits). The owner has read, write, and execute permission, as a result, the owner can add, change, or delete files in that. Any other user, however, can only read the contents, change to that directory, and list the contents of the directory. (Note that by using -d option, the test directory entry is listed without listing its contents.)

If you own a file, you can change its permission as you please. You can do this with the chmod command. For each of the sets of permission on a file (read, write, execute), r is assigned to the number 4, w to 2, and x to 1. To make permissions open for yourself alone, you would set the first number to 7 (4 plus 2 plus 1). The same would be true for group or other permission. Any combination of permissions can result from 0 (no permission) through 7 (full permission).

Here are examples of how to change a permission on a file and what the resulting permission would be:

```
chmod 777 files -> rwxrwxrwx
chmod 755 files -> rxr-xr-x
chmod 644 files -> rw-r--r--
chmod 000 files -> ------
```

You can also turn file permissions on and off using (+) and minus (-) signs, respectively. This can be done for the owner user (u), owner group (g), others (o), and all users (a). For example, starting with a file with all permissions open (rwxrwxrwx), here are some chmod resulting permissions using a minus sign:

```
chmod a-w files -> rwxr-xr-r-
chmod o-x files -> r--xr--x

chmod go-wx files -> ---------
```

When you create a file, by default it is given the permission rw-r--r--. A directory is given rwxr-xr-x. These default values are determined by umask. Type `umask` to see what your umask is. For example:

```
$ umask
022
```

The umask value represents the permissions that are not given on a new file. It masks the permissions of 666 for a file and 777 for a directory. The default umask on Fedora is 022, which results in 755 for a directory and 644 for a file (execute permissions are off by default).

> TIP: Here's a great tip for changing the permission for files at once. Using the -R option of chmod, you can change the permission for all of the files and directories within a directory at once. For example, if you want to open permissions completely to all files and directories in `/tmp/test` directory, you can type:

```
$ chmod -R 777 /tmp/test
```

This command runs `chmod` recursively (-R) for the `/tmp/test` directory, as well as any files or directories that exist below that point in the file system. All would be set to 777 (full read/write/execute permissions).

> CAUTION: The -R option of chmod works if you are opening permissions completely or adding execute permission (as well as the appropriate read/write permission). The reason is if you turn off execute permission recursively, you close off your ability to change any directory in structure. For example, `chmod - 644 /tmp/test` turns off execute permission for the `/tmp/test` directory and then fails to change any files or directories below point.
