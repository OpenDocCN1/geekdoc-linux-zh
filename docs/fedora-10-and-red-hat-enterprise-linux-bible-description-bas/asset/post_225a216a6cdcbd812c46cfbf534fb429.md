
# Part III: Administering Fedora and RHEL

| Option | Description |
| --- | --- |
| -p passwd | Enter a password for the account you are adding. This must be an encrypted password. Instead of adding an encrypted password here, you can simply use the `passwd` command later to add a password for user. The user should be asked to immediately change the password you set. |
| -r | Allows to create a new account with a user ID in the range reserved for system accounts. |
| -s shell | Specify the command shell to use for this account. Replace `shell` with the command shell. |
| -u user_id | Specify the user ID for the account. The default behavior is to automatically assign the next available number. Replace `user_id` with the ID number. |

As an example, create an account for a new user Joe Smith with a login name joe. First, log in as root, and then type the following:

```bash
# useradd -c "Joe Smith" joe
```

> TIP: When you choose a user name, don't begin with a number (for example, 0jsmith), it is also best to use lowercase letters, no control characters or spaces, and a maximum of eight characters. The `useradd` command allows you to use UIDs instead of names if names are too long. Having users named Jsmith and jsmith can cause confusion with programs (like sendmail) that do not distinguish case. Also, some old applications may not be able to handle user names with more than eight characters.

Next, set your initial password using the `passwd` command. The `passwd` command prompts you to type the password twice. (Asterisks are shown here to represent the password you. Nothing is actually displayed when you type the password.)

```bash
# passwd joe
Changing password for user joe.
New password: ********
Retype password: ********
```

CROSS-REFERENCE: Refer to Chapter 14 for tips on picking good passwords.

In creating the account for Joe, the `useradd` command performs several actions:

- Reads the `/etc/login.defs` file to get default values to use when creating accounts.
- Checks command-line parameters to find which default values to override.
- Creates a new user entry in `/etc/passwd` and `/etc/shadow` files based on the default values and command-line parameters.
- Creates any new group entry in the `/etc/group` file.
- Creates a home directory based on the user's name and places it in the /home directory.
- Copies any files located within the /etc/skel to the new home directory. This usually includes only two of the available useradd options.

```bash
# useradd -m -g users,sales -s /bin/bash -c "Mary Smith"
```

In this case, the useradd command is told to create a home directory for the user (-m), makes users the primary group (-g), adds her to the groups wheel and sales (-G), and sets bash as primary shell (-s). Note that the wheel and sales groups must already exist for this to work. This results in a line similar to the following being added to the /etc/passwd

```text
mary:x:502:100:Mary Smith:/home/mary:/bin/bash
```

In the /etc/passwd file, each line represents a single user account record. Each field is separated from another by a colon (:). The field's position in the sequence determines what it is. As you can see, the login name is first. The password field contains an x because Fedora is using a shadow password file to store encrypted password data. The User ID selected by the user command was 502. The primary group ID is 100, which corresponds to the users group in the /etc/group file. The comment field was correctly set to Mary Smith, the home directory was automatically assigned as /home/mary, and the command shell was assigned as /bin/bash exactly as specified with the useradd options.

By leaving out some of the options (as I did in the first user example), defaults are assigned in most cases. For example, by not using -g users or -G wheel,sales, a group named mary would have been created and assigned to the new user. Likewise, excluding -s /bin/bash /bin/bash would be assigned as the default shell.

The /etc/group file holds information about the different groups on your Fedora or RHEL system and the users who belong to them. Groups are useful for allowing multiple people to share access to the same files without denying access to others. If you peek at /etc/group, you find something similar to:

```text
bin:x:2:root,daemon
daemon:x:2:root,daemon
sys:x:3:root,adm
adm:x:4:root,adm,daemon
tty:x:5
disk:x:6:root
lp:x:7:daemon,lp
mem:x:8
kmem:x:9
wheel:x:10:root,joe,mary
nobody:x:99
users:x:100
chris:x:500
sheree:x:501
sales:x:601:jane,joe,mary
```

Each line in the group file contains the name of the group, the group ID associated with it, and a list of users in that group. By default, each user is added to his or her own group, beginning with GID 500. Note that mary was added to the wheel and sales groups instead of having her own group. It is actually significant that mary was added to the wheel group. By doing this, you grant her ability to use the sudo command to run commands as the root user, provided that the wheel line is uncommented in the /etc/sudoers file (as described in Chapter 10), which is not by default.

In this example, use the -g option to assign mary to the users group. If you leave -g, the default behavior is useradd to create a new group with the same name and ID as the new user's primary group. For example, look at the following useradd command:

```bash
# useradd -m -G wheel,sales -s /bin/bash -c "Mary Smith" mary
```

It would result in a /etc/passwd line like this:

```text
mary:x:502:502:Mary Smith:/home/mary:/bin/bash
```

It would also result in a new group line like this:

```text
mary:x:502:
```

Note that the user ID and group ID now have the same number. If you set up all users this way, each will have a unique group which allows for increased flexibility in the sharing of files.

## Adding users with User Manager

If you prefer a graphical window for adding, changing, and deleting user accounts, you can use the User Manager. To open the window from the GNOME desktop, click System -> Administration -> Users (or type system-users from a Terminal window).

When you open the User Manager, you can see a list of all regular users who are currently added to your computer. Administrative users (UID 0 through 499) are not displayed. For each user, you can see the username, UID, primary group, login shell, and home directory. Click any of these headings to sort the users by that information.

![Figure 11-1: Manage users from User Manager](img/63c8e1d2a0ee2be7eff516_0.png)

To add a new user from the User Manager window, do the following:

1. Click the Add User icon to open the New User window (see Figure 11-2).

![Figure 11-2: The Create New User window](img/63c8e1d2a0eee27e9fff516_1.png)

2. Type the requested information in the following fields:

- **User Name** — A single word to describe the user. Typically, the username is eight characters, all lowercase, containing the user’s real first name, last name, or (more often) a combination of the two (such as jones).
- **Full Name** — The user's full name (usually first name, middle initial, and last name). This name is typically used for display, so using uppercase and lowercase is fine.
- **Password** — The user's initial password. (Ask the user to change this password the first time he logs in to the new account, which the user can do by running the `passwd` command.)
- **Confirm Password** — Type the password again, to make sure you entered it correctly.
- **Login Shell** — The default shell (for entering typed commands) that the user sees when logging in to Fedora or RHEL, from a character display.
- **Create home directory** — By default, this box is selected and the user's home directory (as indicated by the Home Directory field) is created automatically.
- **Create a private group for the user** — Check this box if you want to create a group by the same name as the user, created for this user. The name is added to the /etc/group file. This is referred to as user private groups (UPGs).
- **Specify user ID** — Typically, you would not check this box, so the UID for the new user would be assigned automatically. New UIDs for regular users start at 500. However, if you want to assign a particular UID for a user (for example, if you want to match the UID with the user's UID from another computer on your network), select this box and type the number you want to use in the UID box.
- **Specify group ID** — As with the user ID, you would typically have the group ID assigned automatically. However, you can assign a different GID to have the user assigned to a particular group.

Click OK when you are done. The user is added to the /etc/passwd and /etc/group files. The user account is now available for that to log in.

> TIP: Using private groups (UPGs) can be a benefit for sharing a directory of files among several users. Here's an example:

```bash
# useradd -m projectx
# mkdir /usr/local/x
# chown root:projectx /usr/local/x
# chmod 2775 /usr/local/x
# ls -ld /usr/local/x
drwxr-xr-x 2 root projectx 4096 Aug 18 01:54 /usr/local/x
# gpasswd -a nextuser projectx
```
