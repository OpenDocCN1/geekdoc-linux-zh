
# Appendix B: Running Network Services

## Domain Name System server

A Domain Name System (DNS) server is set up to translate host names to IP addresses on a TCP/IP network. Fedora and RHEL can be configured as a DNS server using the named daemon.

By default, the DNS server is not configured to start automatically in Fedora or RHEL. To turn on a DNS server, type `chkconfig named on start`. In addition to starting the service, you must configure the /etc/named.conf file and configure zone files (in the /var/named directory)..

## Reverse Address Resolution Protocol server

The Reverse Address Resolution Protocol (RARP) responds to requests from RARP clients that claim their own IP addresses. RARP is not used very often.

By default, the RARP package (rarp-ss91107) is not installed. When it is installed, the service is off. To turn on a RARP server, type `chkconfig rarpd on`. To start the service, type `rarpd start`. When requests come in for addresses, `/usr/sbin/rarpd` daemon checks the /etc/ethers or NIS+ databases for addresses.

## Database services

Database services provide tools for accessing and managing databases of information. Postgresql service uses the postmaster daemon to handle requests for its services. MySQL server runs the mysqld daemon to handle access to its databases. These daemons are started from start-scripts in /etc/init.d: postgresql and mysql scripts, respectively.

> CROSS-REFERENCE: Chapter 24 describes how to set up a MySQL database server.

## User services

Fedora and RHEL can provide users with a variety of network services. These services run remote programs, send messages in real time, and get option on active users.

## Remote execution services

Remote execution servers respond to requests from other computers to run commands on the local computer. This can be a security issue, so be careful in configuring these services. Remote execution service daemons are available with Fedora and RHEL: Rsh, Rexec, and Kshell.

- The Rsh service (/usr/sbin/in.rsh) accepts requests for remote execution requests that were initiated by the rsh command (from other Linux or UNIX systems). By default, the service is off. The host or user (or both) must be allowed access before remote execution is permitted. Access is configured in the /etc/hosts file or in the .hosts file in each user's home directory.

- The Rexec service (/usr/sbin/in.rexec) accepts remote execution requests from the reexec command (from other Linux or UNIX systems). By default, the service is off. To allow remote execution, the user making the request must provide a valid username and password.

- The Ksh service (/usr/sbin/ksh) receives remote execution requests from the rsh command. Install the kb5-workstation-package to get this service. It uses Kerberos authentication and encryption, making it more secure than the alternative rsh daemon. By default, the service is off. However, if you turn it on (by editing the /etc/xinetd.d/ksh file and changing disable = no), it takes precedence over rsh.

- The OpenSSH service (using ssh daemon) described earlier can also be used for remote execution. OpenSSH is a more secure way to do remote execution than the other methods. Therefore, in most cases you should bypass these services and use OpenSSH.

> CROSS-REFERENCE: Login commands for login services are described in Chapter 16.

## Talk server

Use the /etc/xinetd.d/talk or in.talk to allow users to communicate with each other. The talk command enables users to send messages back and forth in real time. The talk daemon handles requests on port 51, and ntalk daemon handles requests on port 51. Both services are turned off by default. To turn either service, edit the /etc/xinetd.d/talk and /etc/xinetd.d/ntalk files and change disable = yes to disable = no. Restart the xinetd daemon.

## Finger server

The finger (/usr/sbin/in.finger) lets people use the finger command to request information about active users on Linux or UNIX systems locally or over a network. This service is off by default. If in.finger accepts a request from the finger command, the output to the user who made the request looks like the following:

```
Login: jake Name: Jones
Directory: /home/jake
Shell: /bin/bash
Last login: Mon Oct 12 10:34 (PDT)
Last read: Mon Oct 12 10:28 (PDT)
```

The output shows the user's login name, home directory, shell, and also shows when the user logged in or accessed. Because this service can expose personal or corporate information that you may not want exposed to public networks.

## Remote user identification

The rusers server (/usr/sbin/rpc.rusersd) enables users to query the system from a remote computer to list who is currently logged in to Fedora or RHEL. By default, the rusers service is off. To start the service, use `chkconfig rusers on`. To start the service, use `rusers start`. With the finger service, rulers should rarely be exposed to public networks.

## Write-to-All server

The Write-to-All server (/usr/sbin/wall) accepts requests to broadcast a text message to all users logged in to Fedora, RHEL, or other UNIX systems. The request is made with the wall command. By default, the wall service is off. To start the wall server, type `chkconfig wall on`. To start the service, type `service wall`.

## Security services

Fedora and RHEL provide some services to protect your local network from outside attacks. These services include system logging, virtual network servers, and caching servers. The following sections describe these services.

## System logging

Though not specifically a network service, the system-logging facility (rsyslog package) logs information and error messages from most of the network services (and other services) on your computer. The system-logging daemon (/sbin/rsyslogd) should be running at all times, by default at multiuser run levels (2, 3, 4, and 5). You can change what messages are logged or have logging messages directed to different files by reconfiguring the /etc/rsyslog.conf file. You can change options used by rsyslogd daemon by editing the /etc/sysconfig/rsyslog file.

## Virtual private network servers

By encrypting data that travels across networks, a private network (VPN) can provide a secure way for users to access their local network from remote locations. Fedora can use use IP Encapsulation virtual network software. In current releases of Fedora and RHEL, the openswan package is included to provide IPSec VPN service. Fedora also includes openvpn, which is an SSL VPN service, as well as including the ability to use openssh to support tunneling through the TUN/TAP network interfaces.

## Proxy/caching server

The Squid server (/usr/sbin/squid) can be used as both a proxy server and a caching server. A proxy server allows computers on your local network to communicate with the Internet by passing all requests through the proxy server. A caching server stores Web content that has been accessed by a local user on a computer that is physically closer to the user than the originating computer.

By default, the Squid server is off. To start the Squid server, type **chkconfig squid on**. To install squid, type **yum install squid**. To start the service, type **service squid start**. You must also set up the /etc/squid/squid.conf file to identify who has access to the server and what services they can access.
