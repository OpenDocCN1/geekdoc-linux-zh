# Checking Log Files

Preparing your system for a cracker attack is only part of the battle. You must also recognize a cracker attack when it is occurring. Understanding the various log files in Fedora and RHEL record important events is critical to this goal. The log files for your Fedora or RHEL system can be found in the /var/log directory.

Because the system logs are plain text files, you can view the contents of logs directly using any text editor or command (such as less or more). The logwatch facility (which comes with Fedora and RHEL) sends daily details from your log files in an e-message to the root user. You can also add packages, such as syslog, to monitor your log files. (A description of logsentry is contained on the Wiley Web site for this book at www.wiley.com/go/fedorabible)

# Understanding rsyslog service

Most of the files in the /var/log directory are managed by the rsyslog service . The rsyslog daemon is the System Logging Daemon and acts as an extension of a previous logging system called syslog. It accepts messages from various other programs and writes them to its own log file because it is better than having every program you write directly to centrally manage how logs are handled. It is possible to configure rsyslog to record varying levels of detail in the log files. It can be told to ignore all but the most critical message, or to record every detail.

The rsyslog daemon can accept messages from other computers on your network. This is particularly handy because it enables you to central the management and reviewing of the log files from many systems on your network. There is also a major security benefit to this practice. If a system on your network is broken, the cracker cannot delete or modify the log files because those files are stored on a separate computer.

It is important to remember, however, that log messages are not by default, encrypted. Anyone tapping into your local network will be able to eavesdrop on those messages as they pass from one machine to another. Also, although the cracker may not be able to change old log messages, he will be able to affect the system that any new log messages should not be trusted.

It is not uncommon to run a dedicated loghost, a computer that serves no other purpose than to log messages from other computers on the network. Because this system runs no other services, it makes nearly impossible for a cracker to erase it or hide her tracks. It does not, however, that all of the log messages are safe after a cracker has broken into a machine on your network.
