At this point, the ls should reveal the contents of the /usr/local/share directory on the computer named shutle. What you can do with that content depends on how that content was configured for sharing by the server.

# Unmounting NFS file systems

After an NFS file system is mounted, unmounting it is simple. You use the umount command with either the local mount point or the remote file system. For example, here are two ways you could unmount maple:/home/chris/files from the local directory /media/maple:

```
# umount maple:/home/chris/files
# umount /media/maple
```

Either will work. If maple:/home/chris/files is mounted automatically (from a listing in /etc/fstab), the directory will be remounted the next time you Fedora or RHEL. If it was a temporary mount (or listed as noauto in /etc/fstab), it will be remounted at boot.

> TIP: The command is not unmount, it is umount. This is easy to get wrong.

If you get the message device busy when you try to unmount a file system, it means the mount fails because the file system is being used. Most likely, one of the directories in the NFS file system is the current directory for your shell (or the shell of someone else on your system). The other possibility is that a command is holding a open file in the NFS file system (such as a text editor). Check your Terminal windows and other shells, and cd out of the directory if you are in it, or just close the Terminal windows.

If an NFS file won't unmount, you can force unmount it (umount -f /media/maple) or unmount and clean up later (umount -l/media/maple). The -l option is the better choice because a forced unmount can disrupt a file modification that is in progress.
