# Host-level security

You can restrict which computers on your network have access to netatalk services using the /etc/hosts.allow and /etc/hosts.deny files. These files are described in the "Using Tcp wrappers" section of Chapter 14. These are the same files you use to allow or restrict access to other Linux networking services.

The following is an example of an entry the hosts.allow file.

```
ALL: .linxtoys EXCEPT abc.linxtoys.com
```

This example allows access to netatalk (and all other services) from computers abc.linxtoys.com domain except See Chapter 14 for details about other ways to indicate services (instead of ALL) and hosts.

# File and directory-level security

Netatalk creates hidden files and directories to handle Mac features that are not in Linux. Understanding those files and directories working with standard Linux ownership and permissions are the best ways to refine access to AppleTalk volumes you share.

# Understanding Mac files and directories

Netatalk creates special files and directories that you can't see from the Finder. Because these files begin with a dot (.), they are hidden from normal directory listings (ls) in Linux as well. The following descriptions should help you understand these files and directories.

> NOTE: To see hidden files from a folder window (from the GNOME desktop), click Edit -> Preferences. Then the Views tab, select the "Show hidden and backup files" checkbox. Use ls -a to see them from a terminal window.

+   - .AppleDouble—Every directory within your shared AppleTalk (netatalk) volume contains a .AppleDouble directory. This directory is created automatically as soon as you create a file or directory from a Mac client on the netatalk server. Within this directory are separate files representing attributes of each file in the associated directory. For example, creating a text file in /var/toprojects mytext.txt would create a file called /var/toprojects/.AppleDouble/mytext.txt that contained attributes about that file.
