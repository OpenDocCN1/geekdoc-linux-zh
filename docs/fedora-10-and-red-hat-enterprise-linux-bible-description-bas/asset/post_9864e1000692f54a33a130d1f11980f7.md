
The two move (mv) commands, the first moves the file abc to the same directory (essentially renaming it), the second moves the file abc to your home directory (~/). The first copy (cp) copies abc to the file def, whereas the second copies abc to your home directory (~/). The first remove (rm) deletes the abc file; the second removes all the files in the current directory (except those that start with a dot).

> CAUTION: Be sure to use the ** and other characters wisely, because you might match (and therefore remove) files you don't match. There is no undelete on Linux.

> NOTE: For the root user, mv, cp, and rm commands are aliased to run with the -i option. This causes a prompt to appear asking you to confirm copy and remove, one file at a time. For moves, -i option will prompt you if the move would overwrite a file, but you still unintentionally move a file, be careful. This is done to prevent the root user from messing up a large group of files by mistake. To get around an alias, use the full path to the command (for example, `/bin/rm -rf /tmp/jmp/`).

## Using the Vi Editor

It's almost impossible to use Linux for any period of time and not need to use a text editor. If you are using a GUI, you can run edit, which is fairly intuitive for editing text. Most Linux users will use either the vi or emacs commands to edit text files. The advantage of vi or emacs over a graphical editor is that you can use it from any shell, a character-based connection over a network (using telnet or ssh, for example). No GUI is required.

This section provides a brief tutorial of the vi editor. The tutorial was done using the vi or vim (Improved) editors provided with the min-minimal and vim-advanced packages in Fedora.

Any time in this book that I suggest you manually edit a configuration file, you can use vi to do that (from any shell). If vi doesn't suit you, see the sidebar "Exploring Text Editors" (for other options).

The editor is difficult to learn at first. But when you know it, you will be able to edit and move around quickly and efficiently within files. Your fingers never leave the keyboard to pick up a mouse or press a function key.

## Starting with vi

Most often, you start vi to open a particular file. For example, to open a file called /tmp/test, type the following command:

```
$ vi /tmp/test
```

If this is a new file, you should see something similar to the following:

```
~~
~
"/tmp/test" [New File]
```

The box at the top represents where your cursor is. The bottom line keeps you informed about what is going on with your editing (here you just opened a new file). In between, there are tildes (-) as filler because there is no text in the file yet. Now here's the intimidating part: there are no hints, menus, or icons to tell you what to do. On top of that, you can't just start typing. If you do, the computer is likely to beep at you. And some people complain that Linux isn't friended.

## Exploring Other Text Editors

Dozens of text editors are available to use with Linux. Here are a few contained in Fedora and RHEL that you can try out if you find vi to be so taxing:

- emacs — Experienced Linux and UNIX users traditionally have used vi or emacs as their text editor. Many extensions are available with emacs to handle different of different file types.
- gedit — The GNOME text editor that runs in the GUI. Use control and arrow keys to move around.
- joe — the joe editor is similar to many PC editors. Press Ctrl+C to exit with no save or Ctrl+S to save exit.
- kate — a nice-looking editor that comes in the kdebase package. It has lots of bells and whistles, such as highlighting for different types of programming languages and controls for managing wrap.
- kedit — A GUI-based text editor that comes from the KDE desktop.
- nedit — a good tool for editing source code.

If you use ssh to log into other Linux computers on your network, you can use any editor to edit files. A GUI-based editor will pop up on your screen. With the -X option, ssh tunnels on X11 forwarding which can make it more convenient to access remote systems. But this bypasses file permissions on the remote host, so you can use it with care. When no GUI is available, you will need a text editor that runs in the shell, such as vi, or, joe.

The first things you need to know are the different operating modes. The vi operates in either command mode or input mode. When you start vi, you are in command mode. Before you can add or change text in the file, you have to type a command to tell vi what you want to do. A command consists of one or two letters and an optional number. To get into input mode, you need to type an input command. To start out, type either of the following commands:

- a — Add. After you type a, you can input text that starts to the right of the cursor.
- i — Insert. After you type i, you can input text that starts to the left of the cursor.

Type a few words and press Enter. Repeat a few times until you have a few lines of text. When you are done typing, press Esc. You are now in command mode. Now that you have a file with some text in it, try moving around the text with the following keys or letters.

TIP: Remember the Esc key! It places you back into command mode.

- Arrow keys — Use the keys to move up, down, left or right in the file one character at a time. To move left and right you can use Backspace and the Spacebar, respectively. If you prefer to keep your fingers on the keyboard, use h (left), l (right), j (down), or k (up) to move the cursor.
- w — Moves the cursor to the beginning of the next word.
- b — Moves the cursor to the beginning of the previous word.
- 0 or ^ — Moves the cursor to the beginning of the current line.
- $ — Moves the cursor to the end of the current line.
- H — Moves the cursor to the upper-left corner of the screen (first line on the screen).
- M — Moves the cursor to the first character of the middle line on the screen.
- L — Moves the cursor to the lower-left corner of the screen (last line on the screen).

Now you know how to type text and move around, the only other editing you need to know is how Here are a few vi commands for deleting text:

- x — Deletes the character under the cursor.
- X — Deletes the character before.
- dw — Deletes from the cursor to the end of word.
- ds — Deletes from the cursor to the end of the line.
- 0 — Deletes from the beginning of the line.

If you feel good about creating text and moving around, you may want to:

- ZZ — Save the file and exit.
- :w — Save the file but continue.
- :wq — Quit the file.
- :q! — Quit the file and abandon your changes. (TIP: If you've really trashed the file, the :q! command is the best way to exit.)

- u — Press u to undo the previous command. (With traditional vi, undoes a single command.)
- Ctrl+r — If you didn't want to undo the previous edit, use Ctrl+r for Redo. Essentially, this command undoes undo.
- Caps Lock — Beware of hitting Lock. Everything you type in vi has a different meaning when the letters are capitalized.
- !command — You can run a shell command while you are in vi using followed by a command name. For example, type !date to see the current date and time, type !pwd to see what your current directory is, or !jobs to see if you have any running in the background. When the command completes, press Enter and go back to vi. (I recommend saving a before escaping to the shell, just in case you forget to go back to vi.)
- INSERT — When you are in mode, the word INSERT appears at the bottom of the screen. Other messages also appear at the line at the bottom of screen.
- Ctrl—If you forget what you are editing, pressing these keys displays the name of the file that you are editing and the line you are on. It also displays the total number of lines in the file, the percentage of how far you are from the file, and the column number is on. This helps you keep your bearings after you've stopped for a cup of coffee at 3 a.m.

Besides the movement commands described earlier, there are other ways of moving around a vi. Try to these out, open a large file that you can't do much damage to. (Try copying /var/log/messages to /tmp and opening it in vi.) Here are some movement commands you can use:

- Ctrl+f — Page ahead, one page at a time.
