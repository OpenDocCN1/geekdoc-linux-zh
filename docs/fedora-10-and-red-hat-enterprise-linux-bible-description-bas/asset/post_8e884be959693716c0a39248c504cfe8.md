
# Configuring Print Servers

You've configured a printer so that you and the other users on your computer can print to it. Now you want to share that printer with other people in your home, school, or office. Basically, that's configuring your computer as a print server.

The printers that are configured on your Linux system can be shared in different ways with other computers on your network. Not only can your computer act as a Linux print server, it can also look to client computers like an SMB print server. In other words, a Windows client would just use your printer as a printer from another Windows machine.

After a local printer is attached to your Linux system, and your computer is connected to your local network, you can use the procedures in this section to share it with client computers using Linux (UNIX) or SMB interface.

> CROSS-REFERENCE: See Chapter 26 for information on configuring Linux as an AppleTalk server package.

# Configuring a shared CUPS printer

After a local printer is added to your Linux computer, making it available to other computers on your network is fairly easy. A TCP/IP network connection exists among the computers sharing your printer, you can simply grant permission to individual hosts or from remote hosts to access your computer's printing service. The procedures for setting up local printers are discussed earlier in this chapter.

To share a local printer as a print server with other computers on your network, do the following:

1. From the desktop panel, select System -> Administration -> Printing. The Printer configuration window opens.
2. Right-click the icon of the printer you want to share. (If the printer is not yet configured, refer to the "Setting Up Printers" section earlier in this chapter.)
3. Select the Share box on the menu to select appears in the box.
4. If you only selected users to access your printer, select Properties from the menu and then on the Access Control item. Select Deny printing for everyone except these users, type each user you want to allow to use the printer, and Click Add to add each selected users to be excluded from denied and allowed to print.
5. Select Settings from the Server menu at the top of the Printer configuration window. From the Basic Server Settings screen that appears, select the Publish printers connected to this system check box.
6. Click OK to make the changes permanent.

At this point, you can configure other computers to use your printer. If you try to print from another computer and it doesn't work, here are a few things to try:

- **Open your firewall** — If you have a restrictive firewall, it may not permit remote users to access your printers. You must allow access to port 513 (UDP and TCP) and possibly port 631 to allow access to printing on your computer. See Chapter 14 for information on configuring your firewall.
- **Enable LPD-style printing** — Certain applications may require an older LPD-style printing service in order to print on your shared printer. Then restart install the package (yum install cups-lpd).
- **Check names and addresses** — Make sure that entered your computer's name and print queue properly when you configured it on the other computer. Using the IP address instead of the hostname (if that worked, it would indicate a DNS name resolution problem). Running a tool such as wireshark can let you watch where the transaction fails.

# Configuring a shared Samba printer

Your Linux printers can be configured as shared Samba printers. To share your printer as a Samba (SMB) printer, all you need to do is configure basic Samba server settings as described in Chapter 18. All your printers should be shared on your local network by default. The next section shows what the resulting settings look like and how you might want to change them.

# Understanding smb.conf for printing

When you configure Samba, as described in Chapter 18, the /etc/samba/smb.conf file is configured to allow all your configured printers to be shared. Here are a few lines you might find in [global] and [printers] sections of the smb.conf file that relate to printer sharing:

```
[global]
workgroup = MYGROUP
serverstring = Samba Server
security = share
printcap name = /etc/printcap
load printers = yes
printing = cups
encrypt passwords = yes
smb passwd file = /etc/samba/smbpasswd
unix password sync = Yes
```

[printers]
comment = All Printers
path = /var/spool/samba
guest ok = yes
browse = no
writeable = no
printable = yes
```

The settings shown resulting from Configuring Samba from the Samba Configuration (System -> Administration -> Samba) window. You need to install the system-config-samba package to use the Samba Server Configuration window. In this case, I selected to use encrypted passwords. The lines show that printers from /etc/printcap were loaded and the CUPS service is being used. The /etc/samba/smbpasswd file stores the encrypted passwords. Because password sync is on, each user's Samba password is synchronized with the local UNIX password for the user.

The last few lines show here up the [printers] section, which determines the defaults for how printers are shared in Samba. The final line (printable = yes) defines that users can print to all printers.

# Summary

Sharing printers is an economical and efficient way to use your organization’s printing resources. A centrally located printer can make it easier to maintain a printer, while still allowing everyone to get his or her printing jobs done.

You configure your printer with the Printer configuration window. A variety of filters make it possible to print to different kinds of printers, as well as to printers that are connected to computers on the network.

The default printing service in Fedora and RHEL is the Common UNIX Printing Service (CUPS). Besides being able to set up your computer as a Linux print server, you can also have your computer emulate SMB (Windows) print server. After your network is configured properly and a local printer is installed, sharing printer over the network as a UNIX or SMB server is not very complicated.

# Setting Up File Server

## In This Chapter

- Setting up NFS file server in Linux
- Setting up Samba server in Linux

When groups of people need to work on projects, they usually need to share documents. Likewise, it can be efficient for groups of people on a network to share common applications and directories of information by setting up a file server.

Fedora and Red Enterprise Linux systems include support for each of the most common file server protocols to use. The Network File System (NFS) has always been the file-sharing protocol of choice for Linux and other UNIX systems. Networks with many Windows computers use Samba, or SMB/CIFS (Server Message Block/Common File System protocol). This chapter describes how to set up file servers and clients associated with NFS and Samba.

> CROSS-REFERENCE: Two other types of file servers are also described in this book: FTP (using vsFTPD) and AppleTalk (using netatalk). To set up public FTP servers, refer to Chapter 20. Chapter 26 describes how to set up a netatalk file server for sharing with Apple computers.

## Goals of Setting Up a File Server

By centralizing data and applications on a file server, you can accomplish several goals:

- **Centralized distribution**: You can add documents or applications to one location and make them accessible to any authorized computer or user. In this way, you don't have to be responsible for placing necessary files on every computer.
- **Transparency**: Using protocols such as NFS, clients of your file server (Windows, Linux, or UNIX systems) can connect your file systems to their local file systems as if your file systems existed locally. (In other words, no drive letters on the Linux or UNIX systems. Just change to the remote system's mount point and you are there.)
