+   - Multiple hard disks — You may have several hard disks available to your users. In that case you would have to mount each disk (and possibly partitions from each disk) in different locations in your file system.

+   - Protecting parts of the file system — If you have many users on a system, and the users consume all of the file system space, the entire system can fail. For example, there may be no place for temporary files to be copied (so the programs writing to temporary files may fail), and incoming mail may fail to be written to mail boxes. With multiple partitions, if one runs out, others can continue to work.

+   - Backups — There are some ways to back up your data that involve copying the entry of a disk or partition. If you want to restore that partition layer, you can simply copy it (bit by bit) to a hard disk. With smaller partitions, this approach can be done fairly efficiently.

+   - Protecting from disk failure — If one disk (or part of one) fails, by having multiple partitions mounted on your file, you may be able to continue working and just fix the one disk that fails.

When a partition is mounted on the file system, all directories and subdirectories below mount point are stored on that. For example, if you were to mount one partition on /usr, everything below the usr mount point would be stored on the second partition while everything else would be stored on the first partition. If you mounted another partition on /usr/local, everything below that mount point would be on the third partition, while everything else would be on the second partition.

> TIP: What if a remote file system is unmounted from your computer, and you go to save a file in that mount point directory? What happens is that you will write the file to directory and it will be stored on your local hard disk. When the remote file system is remounted, however, the file you saved will seem to disappear. To get the file back, you will have to unmount the remote file system (causing the file to reappear), remount the file to another location, remount the file system, and copy the file back.

Mount points that are often mentioned as being candidates for separate partitions include /, The root file system (/) is the catchall for directories that aren't in other mount points. The root file system's mount point (/) is the only one that is required. /boot holds the images needed to boot the operating system. /home file systems are where all user accounts are typically stored. Applications and documentation are stored in /usr. Below the /var mount point is where logs, temporary files, server files (Web, FTP, and so on), and lock files are stored (that is, that need disk space for your computer's applications to keep running).
