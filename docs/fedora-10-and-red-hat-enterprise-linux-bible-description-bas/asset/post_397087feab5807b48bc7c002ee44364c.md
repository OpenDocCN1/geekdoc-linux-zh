```

This output tells you the location of the module (filename), the author, and description, of other information. The output describes snd-seq-oss as an OSS-compatible sequencer module. You can use the -d option to list just the description, the -a option to see the author of the module or -n to see the object file representing the module. The author information often has the e-mail address of the driver's creator, so you can contact the author if you have problems or questions about it.

## Loading modules

You can load any module that has been compiled and installed (to the /lib/modules directory) into your running kernel using the modprobe command. The most common reasons for loading a module are you want to use a feature temporarily (such as loading a module to support a special file system on a floppy you want to access) or to identify a module that will be used by a particular piece of hardware that are not autodetected.

Here is an example of the modprobe command being used to load the parrot module. The parrot module provides the core functions to share parallel ports with multiple devices.

```
# modprobe parport
```

After loading you can load the parrot_pc module to define the PC-style ports available through the interface. The parrot_pc module lets you define the addresses and IRQ numbers associated with each device sharing the parallel port. For example:

```
# modprobe parrot_pc io=0x3bc irq-auto
```

In the previous example, a device is identified as having an address of 0x3bc. The IRQ for the device is autodetected.

The modprobe command loads modules temporarily. At the next reboot, the modules you enter disappear. To permanently add the module to your system, add the modprobe command line to one of the start-up scripts that are a boot time.

> NOTE: An alternative to using modprobe is the insmod command. The advantage of using modprobe, however, is that insmod will only load the module you request, while modprobe will try to load other modules that the one is dependent on.

## Removing modules

You can remove a module from a running kernel using the rmmod command. For example, to remove the module parrot_pc from the current kernel, type the following:

```
# rmmod parrot_pc
```

If the module is not currently busy, the parrot_pc module is removed from the running kernel. (Instead of rmmod, you can use modprobe -r to remove the module, plus related modules.)

> NOTE: There are times when a piece of hardware is improperly detected and a module is loaded is either the wrong module or is simply a broken module. In that case, you can consider adding the name of the offending driver to the /etc/modprobe.d/blacklist file, to prevent that module from being loaded. After that, you can consider loading the proper module manually or by adding a modprobe command to load the module you want from a startup file.

## Managing File Systems and Disk Space

File systems are organized in a hierarchy, beginning from root (/) and continuing downward in a structure of directories and subdirectories. As administrator of Fedora or RHEL system, it is your duty to make sure all the disks that represent your file system are available to the users. It is also your job to make sure there is enough disk space for the file system to store what they need.

File systems are organized differently in Linux than they are in Windows. Instead of drive letters (A:, B:, C:) for local disk, network file system, CD-ROM, or other type of medium, everything fits neatly into the directory structure. For hard drive, create a mount point in the file system and then connect the disk to it. For removable media (such as CD, DVD, USB drives, or digital cameras), mount points are automatically created and connected (in /media) when those items are loaded.

> CROSS-REFERENCE: Chapter 2 provides instructions for using Disk Setup. Chapter 4 describes how the file system is organized. The organization of your file system is to divide your hard disk (or disks) into partitions. Those partitions can be assigned to:
- A part of the Linux system
- Swap space for Linux
- Other file system (perhaps containing other operating systems)

For our purposes, we want to focus on partitions that are used for the file system. To see what partitions are currently set on hard disk, use the fdisk command as follows:

```
# fdisk -l

```
# mount
/dev/sda3 / type ext3 (rw)
/dev/sda2 /boot type ext3 (rw)
/dev/sda1 /mnt/win vfat (rw)
none /proc type proc (rw)
none /sys type sysfs (rw)

```

> NOTE: You may notice /proc, /sys, /dev/pts, /proc/sys/fs/binfmt_misc, /dev/shm, and other different types not relating to a partition as file systems. This is because they represent different file system types (proc and devpts, and so on). The word none, however, indicates that they are not associated with a separate partition.

The mounted Linux directories in this case are /dev/sda2, which provides space for the /boot directory (which contains data for booting Linux), and /dev/sda3, which provides space for the rest of the Linux system beginning from the root directory (/). This particular system also contains a Windows partition that was mounted in the /mnt/win directory.

Beginning with Fedora Core 3 and RHEL 4, mount points for removable media (CDs, DVDs, USB pen drives, and so on) moved from /mnt to the /media directory. In this example, an IDE combination CDRW/DVD-ROM drive was mounted on /media/recorder. Most GUI interfaces, the CD or DVD is typically mounted automatically when you insert it. In this example, the uhelper (privileged unmount helper) is assigned to the hold daemon so that the system can mount the CD as another non-privileged user.
