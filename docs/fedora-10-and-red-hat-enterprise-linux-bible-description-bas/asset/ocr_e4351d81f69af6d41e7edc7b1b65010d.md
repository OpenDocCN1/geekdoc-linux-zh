# Backing up files remotely

While the previous example was a quick, informal backup method, with more critical data, you want to make sure that the data are being backed up to another computer and that the backup is done at regular intervals. This can be accomplished by using rsync with ssh and cron.

Having ssh as the transport mechanism ensures that data will be encrypted when it is transferred. Also, the ssh service (ssh) is enabled by default on many Fedora and Red Hat Enterprise Linux systems, you need only a user and password to the remote system to do the backup. (As long as you use ssh to connect to the remote machine, port 873 is open in your firewall, and rsync is installed remotely, you can use the rsync command to transfer files.) Here's an example:

```
# rsync -av -e ssh /home/chris duck:mnt/backup/home/
root@duck:password: ********
building file list ... done
```

In this example, I identify the remote computer (named duck in this case) by putting before the remote directory name, a colon. I use some different options as well. The archive (-a) and verbose (-v) options, I added the -z option to compress the data (making it more efficient to transfer). I also use the -e ssh option to have rsync use an ssh remote shell to transfer data. The password prompt you see is ssh login prompt. The -a option is important if you want to restore files exactly as they were copied, because it copies a whole directory structure as it preserves ownership, date/time stamps, and permissions.

You can repeat this each time you want to back up your files. However, the more efficient way to do this is to set up this to run as a cron job so that the backups happen automatically at intervals.

To rsync run automatically, you can't have it prompt for a password. To have the rsync command run without prompting for a password, follow this procedure:

+   1. Set up ssh to no-password logins for the user who is going to perform the backup (see the section "Using ssh, scp, and sftp without passwords" in Chapter 14 for information on how to do this)

+   2. Decide how often you want the backup to run. For example, if you want to run the rsync command once each day, as root user you could create a file /etc/cron.daily/mybackup.

+   4. Add the cron line to the mybackup file that you want to use:

```
rsync -azv -e ssh /home/chris duck@mnt/backup/home/
```
