# 588 Part III: Administering Fedora RHEL

I divided the commands in the preceding script into six sections. The following text describes each of those sections.

**(1) Policies** — The iptables -P sets the default policies for INPUT, OUTPUT, and FORWARD chains. By assigning each of these to DROP, any packet that isn't matched is discarded. In other words, for a packet to get through, it has to be matched and accepted by one of the other rules in the script.

**(2) User-defined chain** — A user-defined chain I *call* is created to do a few more on packets receiving TCP services that I'm going to go along (Web, FTP, and DNS services). The -n okay option opts the *okay chain*. The next line says that a SYN packet (--syn), requests a new connection, is fine to length. The next line allows packets associated with an ESTABLISHED connection (which one has already passed traffic to the interface) or a RELATED connection (which is starting a new connection to an already established connection). The final line in this sets iptables to DROP packets that don't meet one of those.

**(3) Input chain rules** — The bulk of the packet filtering is done in THE INPUT chain. The first set of input rules identifies iptables to always accept packets from the Internet and the LAN. The next three determine which requests for specific protocols (TCP, UDP, and ICMP) are accepted:

+   **Packets from LAN** — Because you want to use the Internet, this set of rules lets through packets that are initiated from your computer. The first line tells iptables to accept packets for all protocols for which the source is an acceptable address on your LAN (-s 10.0.0.0/24, which represents IP numbers 10.0.0.1 through 10.0.0.254). The next three lines allow packets that come from all valid IP addresses on the firewall computer (-s 127.0.0.1,10.0.0.1 and 123.46.67.89). The last line accepts accept packets (-d 10.0.0.25).
**Packets from Internet (already connected)** — This is split in two (I just used the backlash since the page isn't wide enough to show it as one line). It ACCEPTs packets that are associated with connections that are already established(--state ESTABLISHED, RELATED) and are requested directly to the firewall's IP address (123.45.67.89).
**TCP rules (new connections)** — Here is where you open the ports for the TCP services you want to provide to anyone from the Internet. In these lines you open ports for FTP service (--destination-port 21), secure shell service (22). Web service (80), and IDENT authentication (113), the last of which might be necessary for protocols such as IRC. Instead of accepting these requests receives immediately, you jump to the *okay* chain until you further check that the packets were formed properly.

> CAUTION: You want to ensure that the services on the ports which you are allowing access are properly configured before you allow packets to be to them.
