Options specific to t:

The first step is to start a receiver process on the server machine:

```
# ttcp-rs
ttcp-r: buflen=8192, nbuf=2048, align=16384/0, port=5001 tcp
ttcp-r: socket
# ttcp-t ts server.example.com
ttcp-t: socket
ttcp-t: connect
```

The -r flag denotes that the server machine will be the Receiver. The -s flag, in conjunction
with the -r flag, tells tcp that you want to ignore any received data.

The next step is to have someone outside of your data link, with a network link close to the
s speed as yours, set up a ttcp sending process:

Let the process run for a few minutes and then press Ctrl+C on the transmitting side to stop the
testing. The receiving side will then take a moment to calculate the results:

```
# ttcp-rs
ttcp-r: buflen=8192, nbuf=2048, align=16384/0, port=5001 tcp
ttcp-r: socket
ttcp-r: accept from 64.223.17.21
ttcp-r: 2102496 bytes in 70.02 real seconds = 29.32 KB/sec ++
ttcp-r: 1226 I/O calls, msec/call = 58.49, calls/sec = 17.55
ttcp-r: 0.0user 0.0ys 1:10real 0Ki +0id 0maxr +0pf +0osw
```
