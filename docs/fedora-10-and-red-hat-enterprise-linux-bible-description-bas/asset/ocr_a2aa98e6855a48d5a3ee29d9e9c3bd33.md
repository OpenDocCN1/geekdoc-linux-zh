Internet requests the address of the DNS server (nsl.yourdomain.com), they will get the address 123.45.67.89. However, when a query for nsl.yourdomain.com comes from inside the LAN, the address 10.0.0.1 is returned. Also, any queries from the Internet for addresses of private computers (red.yourdomain.com, blue.yourdomain.com, and so on) are rejected.

# Editing named.conf

To begin, you configure the /var/named/chroot/etc/named.conf file on the primary DNS server representing your example yourdomain.com domain. This example starts from the /etc/named.conf file that comes with the caching-nameserver package in Fedora and RHEL. (Make sure that you installing the caching-nameserver and bind packages before you continue and make a backup copy of any configuration files you.) Following are a few tips relating to editing the named.conf file:

+   - If a statement contains statements, make sure that the last statement ends with a semicolon.

+   - Comments can appear in the same formats that popular programming languages use. These languages use C (begin with /* and end with /*), C++ (begin with // and go to the end of the physical line), and shell or Perl styles (begin from a # and go to the end of the physical line)

+   - A leading exclamation mark (!) negates an element. Putting !123.45.67.89 in a statement causes the IP address 123.45.67.89 not to match the element. (Just sure that the negation occurs before a positive match or the positive match takes precedence.)
