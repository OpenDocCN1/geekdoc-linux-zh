NOTE: One major difference between configuring a server for connection to the Internet and a computer that you use for Internet access is in how you set your IP address. You quite likely get the IP address for your Internet connection using DHCP. Now you will probably enter the IP address that you got as a static IP address.

+   - **Add DNS server information** — Although the server IP addresses that you enter for DNS servers are probably ones your ISP configured, you may want to add your own DNS servers. If you so, make sure that your server points to your master and slave DNS servers for IP resolution. You can also have the other computers on your LAN point to your DNS servers to resolve domain names to IP addresses. (The `/etc/resolv.conf` file is where you identify your DNS servers. After you add your own DNS server, all your clients change their `/etc/resolv.conf` files to include the new domain name and DNS server information.
- **Add hostname** — As soon as you have a real name, you can name your computer within the structure of that domain name. If you haven't installed Fedora or Red Hat Enterprise Linux, you can enter this hostname during installation. For example, add a host called duck.handsonhistory.com. After Later, you can change the name in the `/etc/sysconfig/network` file.

> NOTE: Changing your hostname after you install Fedora or RHEL can sometimes cause problems. Services such as printing and the X Server (for your graphical desktop) fail after after you change your hostname. Check to make sure that printing and other network services are still working after you change your hostname. Sometimes restarting the network interface can solve the problem.

After you set up your network interfaces and related information for your server, test the Internet connection by using commands as `host`, `nslookup`, and `dig`. Next, if DNS is already configured for your domain, try to query your server by name to see whether those in the outside world can reach you by. Make sure that the static IP addresses that appear in response match the static IP addresses that you assigned.

# Configuring servers

Some services are more appropriate for public exposure than others. You probably don't want to offer your print server, for example, to anyone on the Internet. Similarly, sharing with Samba or NFS isn't appropriate to share these services natively across the public Internet. (To access these services over an Internet connection, however, you could run them over a virtual network.)
