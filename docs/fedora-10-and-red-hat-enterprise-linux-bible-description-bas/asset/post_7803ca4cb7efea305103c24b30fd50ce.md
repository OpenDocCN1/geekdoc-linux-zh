Send the messages to another computer (loghost) instead of a file, simply replace the log filename with the @ character followed by the name of the loghost. For example, to redirect the output normally to the messages,secure, mailog log files, make these changes to the previous file:

```bash
# Log anything (except mail) of level info or higher.

# The authpriv file has restricted access.

# Log all the mail messages in one place.

```

The messages will be sent to rsyslog running on the computer named loghost. The name loghost was not an arbitrary choice. It is custom to create such a hostname and make an alias to the system acting as the loghost. That way, if you ever need to switch the loghost to a different machine, you only need to change the log alias; you do not need to re-edit the rsyslog.conf file on every computer.

# Understanding the messages logfile

Because of the many programs and services record information to the messages log file, it is important that you understand the format of this file. Examining this file gives you a early warning of problems developing on your system. Each line in the log is a single message recorded by some program or service. Here is a snippet of an messages log file:

```
Feb 25 11:04:32 toys network: Bringing up loopback interface: succeeded
Feb 25 11:04:35 toys network: Bringing up interface eth0: succeeded
Feb 25 13:01:14 toys vsftpd(pam_unix) [10565]: authentication failure;
name= uid=0 tty=root rhost=10.0.0.5 user-chris
Feb 25 14:44:24 toys su(pam_unix) [11439]: session opened for
user root by chris(uid=500)
```

This is really simple when you know what to look for. Each message is divided into five main parts. From left to right they are:

- The date and time that the message was logged
- The name of the computer that the message came from
- The program or service that the message pertains to
- The process number (enclosed in square brackets) of the program sending the message
- The actual text itself

Let's examine the previous file snippet. In the first two lines, you can see that I restarted the network. The next line shows that I tried to log in as the user named chris to get the FTP

# Tracking log messages with logwatch

Another way to keep up with the contents of your log files is with the logwatch facility. Logwatch flags messages that reflect a problem with your system and forwards them each day in an e-mail message to your system's root user. When you install Fedora or RHEL, the logwatch package is installed and configured to watch your log files and report suspicious activities to your system administrator. Based on the logwatch cron file (/etc/cron.daily/logwatch), the logwatch facility will:

- Run each morning at 4:00 a.m.
- Choose which log files to scan and which to send the e-mail message, based on configuration file (/etc/logwatch/conf/logwatch.conf). (The defaults are listed in /usr/share/logwatch/default.conf.)
- Send an email to the local computer's root user that reports potentially suspicious activity on your system, based on the contents of your log files.
- Report on information log activities that could affect a problem with your system.

The kind of information log reports includes users and groups that have been deleted, packages installed or uninstalled, and disk space consumed. The daily messages also show log activity through the network and file transfers. Failure messages are flagged and reported for each log file scanned.

Review the /usr/share/logwatch/default.conf file to see the options you have for configuring your logwatch service. To change any options, you can add them to the /etc/logwatch/conf/logwatch.conf file. Here are examples of log settings:

| LogDir = /var/log | |

| Service = "-zz-sys" | Prevents execution of zz-sys service, which prints useful system configuration info. |

LogDir sets the log file directory as /var/log (so any log files listed are shown relative to that directory). The /var/cache/log directory is used to hold temporary files. The daily e-mail report is sent to the root user on the local system (you can change MailTo any valid e-mail address), with the sender (MailFrom) listed in Logwatch. You can change the Print value to Yes to report the sent to standard output, instead of being mailed the MailTo recipient. The Range is set to yesterday, which causes logwatch to search log files for the past day. You can change the Range to All to search all files available for a particular log file, as in messages, messages.1, messages.2, and so on. To increase the amount of detail (which is set to Low by default), you can identify Detail as Medium or High (a number from 0 to 10). The mail application used to send the report is /bin/mail.

Most of the action that takes place by logwatch is based on the value of the Service entry. With Service set to All, all files in the /usr/share/logwatch/conf/services directory are used to produce the logwatch report. Files in this directory are each related to a service that is gathered by logwatch and defines the type of information that is gathered for that service. Provide any service name that you want to use with clients by a dash (-). (By default, zz-network, zz-sys, and exinstats are disabled).

# Using the Secure Shell Package

The Secure Shell (SSH) provides services similar to other remote execution, remote copy, and remote login commands (such as the UNIX rsh, rcp, and login commands), which encrypts the network traffic. It uses private-key cryptography, so is ideal for use with Internet-connected computers. The Fedora and RHEL distributions contain the following client and server software packages for SSH: openssh, openssh-clients, and openssh-server packages.

# Starting the SSH service

If you have installed the openssh-server package, the SSH service is automatically configured to start. The SSH daemon is started from the /etc/init.d/ssh start-up script. To make sure the service is set up to start automatically, typing the following (as root user):

```bash
# chkconfig --list ssh
sshd 0:off 1:off 2:on 3:on 4:on 5:on 6:on
```

If you don't specify a user name when you start the ssh connection, the ssh daemon allows you to use the user name you are logged in as from the client. If you want to log in as a different user name (such as chris, for example), you could type the following:

```bash
$ ssh chris@ratbert.glaci.com
```

or

```bash
$ ssh -l chris ratbert.glaci.com
```
