
## Chapter 10: Understanding System Administration

- Multiple hard disks — You may have several hard disks available to your users. In that case you would have to mount each disk (and possibly partitions from each disk) in different locations in your file system.

- Protecting parts of the file system — If you have many users on a system, and the users consume all of the file system space, the entire system can fail. For example, there may be no place for temporary files to be copied (so the programs writing to temporary files may fail), and incoming mail may fail to be written to mail boxes. With multiple partitions, if one runs out, others can continue to work.

- Backups — There are some ways to back up your data that involve copying the entry of a disk. If you want to restore that partition, you can simply copy it (bit by bit) to hard disk. With smaller partitions, this approach can be done efficiently.

- Protecting from disk failure — If one disk (or part of one) fails, by having multiple partitions mounted on you may be able to continue working and just fix the disk that fails. When a partition is mounted on the file system, all directories and subdirectories below mount point are stored on. For example, if you were to mount partition on /usr, everything below mount point would be stored on the second partition. If you mounted another partition on /usr/local, everything below mount point would be stored on the third partition.

TIP: What if a remote file system is unmounted from your computer? What happens is that you will write the file to directory and it will be stored on hard disk. When the remote file system is remounted, however, the file you saved will seem to disappear.

Mount points that are often mentioned as being candidates for separate partitions include the root file system (/) is the catchall for directories that aren't in other locations. The root file system (/) is the only one that is required. /boot holds images needed to boot. /home file systems are where user accounts are typically stored. Applications and documentation are stored in /usr. Below the /var mount point is where logs, temporary files, and lock files are stored.

The only times they will care is if a partition runs out of space or they need to save or use information from a particular device (such as floppy disk or remote file system). Of course, any user can check this by typing the mount command.

## Mounting file systems

Most of your hard partitions are mounted automatically for you. When you install Fedora or RHEL, you create partitions and indicate the mount points for those partitions. When you boot Fedora or RHEL, all partitions residing on hard disk should typically be mounted. For that reason, this section focuses mostly on how to mount other types of devices so that they become part of your file system.

Besides being able to mount other types of devices, you can also mount other kinds of file systems on your Linux system. This means that you can store files from other operating systems or use file systems that are appropriate for certain kinds of activities (such as writing large block sizes). The most common use of this feature for the average Linux user, however, is to allow you to obtain and work with files from floppy disks and CD-ROMs.

## Supported file systems

To see file systems that are currently available to be used on your system, type cat /filesystems. The following file systems are supported in Linux, although they may not be in use at the moment or they may not be built into your current kernel (so they may need to be loaded as modules):

- adfs — This is the acorn file system, which is the standard file system used on AIX operating systems.
- befs — This is the file system used by the BeOS operating system.
- cifs — The Common Internet File System (CIFS) is the virtual file system used to access remote servers that comply with the SIA file specification. CIFS is an attempt to refine and standardize the SMB protocol used by Samba and Windows file sharing.
- ext3 — The ext file systems are the most common file systems used by Linux. The ext3 file system was new for Red Hat Linux 7.2 and is currently the default file system in many Linux systems (including Fedora and RHEL). The root file system (/) is typically ext3 (although you can use other file systems as well). The ext3 file system is also referred to as the Third Extended file system. The ext3 file system includes journaling features that improve a file system's ability to recover from crashes, as compared to ext2 file systems.
- ext4 — An enhancement to ext3, this type of file system performs and scales better to larger numbers of files. Fedora 9 introduced the ext4 file system type as a preview release. With Fedora 10, you can use ext4 file systems, but ext4 is still considered experimental.
- ext2 — The default file system for versions of Red Hat Linux previous to 7.2. Features are the same as ext3, except ext2 doesn't include journaling features.
- ext — This is the first version of the ext file system. It is not used much anymore and I recommend you not use it.
- iso9660 — This file system evolved from the High Sierra file system (which was the original standard used on CD-ROM). Extensions to the High Sierra standard (called Rock Ridge extensions) allow iso9660 file systems to support long filenames and UNIX-style information (such as file permissions, ownership, and links). This file system is used when you use a CD-ROM.
- kafs — This is the AFS file system. It is used in distributed computing environments to share files with Linux, Windows, and Macintosh clients.
- minix — This is the Minix file system, used originally with Minix version of UNIX. It only supports filenames up to 30 characters.
- mdos — This is an MS-DOS file system. You can use this type to mount floppy disks that come from Microsoft operating systems.
- vfat — This is the Microsoft FAT (VFAT) file system.
- umsdos — This is an MS-DOS file system with extensions to allow features that are similar to UNIX (including filenames).
- proc — This is not a real file system, but rather a file-system interface to the Linux kernel. You won't do anything to set up a proc file system. Many utilities use /proc to access kernel information.
- swap — This is used for swap partitions. Swap areas are used to hold data temporarily when RAM is used up. Data is swapped to the swap area, returned to RAM when it is needed again.
- nfs — This is the Network File System (NFS) type of file system. File systems mounted from another computer on your network use this type of file system.

- hpfs — This file system is used for read-only mounts of an OS/2 HPFS file system.
- ncpfs — This relates to Novell NetWare file systems. NetWare file systems can be mounted over a network.

- affs — This file system is used with Amiga computers.
