2. In the Add NFS share window Basic tab, enter the following information:

+   - Type the name of the directory you want to share. (The directory must exist before you can add it.)

+   - Host(s) — One or more hostnames to indicate which hosts can access the shared directory. Hostnames, domain names, and IP addresses are allowed here. +   - Basic permissions — Click Read-only or Read/Write to let remote computers mount the shared directory with read access or/write access, respectively.

3. Click the General Options tab. This tab lets you add options that define the shared directory behaves when a remote host connects to it (mounts it):

+   - Allow connections from ports 1024 and higher — Normally, an NFS client will request the service from a port number under 1024. Select this option if you need to allow a client to connect to you from a higher port number. (This sets the *insecure* option for the shared directory.)

+   - Allow insecure file locking — If checked, NFS will not authenticate any requests from remote users of this shared directory. Older NFS clients may not deliver their credentials when they ask for a file. (This sets the *insecure_locks* option.)

+   - Disable subtitle checking — By selecting this option, NFS verifies that the requested file is actually in the shared directory (only that it's in the correct file system). You can disable subtitle checking if an entire file system is being shared. (This sets the *no_subtitle_check* option.)

+   - Sync operations on request — This is by default, which forces a write operation from a remote client to be synced to your local disk when the client requests it. (This sets the *sync* option.)

+   - Force sync of writes immediately — If the shared data is immediately up-to-date, select this option to force the synchronization of writes to your hard disk. (This sets the *no_wdelay* option.)

+   - Hide filesystems beneath — By default (hide option), if a shared NFS file system has another local file system mounted on it, the second file system will not appear when the mounts the original file system. If this box is checked, the *nohide* option is set instead, causing the second mounted file system to be accessible from clients.
