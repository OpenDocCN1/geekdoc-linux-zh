To see which ports are assigned to services by default, refer to the /etc/services file. See http://www.iana.org/assignments/port-numbers for a full list of service ports. In most cases, a configuration file for service indicates the default port number the service listens on. One of making a service more private is to change the port number that a service listens on. Then the user must know how for the service at that particular port. To see which ports are currently exposed on your system, you can use nmap command.

You can use that description as a model for setting up a server to go with DNS. In the DNS example, you have separate servers for mail, FTP, and Web services. For a low-volume server, you can have them all on the same computer.

# Enabling SELinux

Security Enhanced Linux (SELinux) is enabled by default in Fedora and RHEL starting version 4. It is implemented with targeted policies, most popular server types (including Web, FTP, and DNS) have policies that restrict what intruders can do if they manage to break into your system. You should look over how policies are on the SELinux Administration window (system-config-selinux command) for services you are operating. Refer to Chapter 10 for information on SELinux.

# Checking logs and system files

By making your servers public, you may make them open to attacks. Although firewalls are a good first line of defense, you will need to watch the activity on those ports that you leave open. A consistent program of monitoring traffic and changes to your server, therefore, becomes more critical. The following are a few techniques that you can use to secure your servers:

+   * General security — Make sure that you protect all your user accounts by using passwords and the correct file permissions settings.

+   * Tripwire — Use Tripwire to take a snapshot of your critical system files so that you can check later whether anyone's altered those files. The tripwire package is included in the latest Fedora repository.

+   * File System Saint — As with Tripwire, File System Saint maintains a database of every file on your system. You can find out more information from the project's SourceForge.net (http://sourceforge.net/projects/fss).

+   * Logwatch — Use Logwatch, which is by default in Fedora and RHEL, to secure log files and e-mail suspicious messages to you. At very least, you should change the MailTo value in the /etc/logwatch/logwatch.conf file to an e-mail address you keep up with (this is where Logwatch will send its screened log messages).

I describe these and other security techniques in Chapter 14.
