Checking that the names servers are set
 you are able to resolve a computer by IP, but not able to resolve any addresses, your DNS servers may not be set. As root user from a Terminal window, open the /etc/resol.conf file and check that there are lines identifying one or more DNS servers in your file. These should be supplied to your ISP (unless you run your own DNS server). Here are some examples (the numbers are fictitious)

```
nameserver 111.11.11.111
nameserver 222.22.22.222
```

Using the ping command to make sure that the servers are live.

> NOTE: When you connect to your ISP using DHCP, it's possible that your name server information will appear in your /etc/resol.conf file and old entries will be lost. This can be a problem if you are relying on your own server for providing DNS service and it is erased.

# Checking the chap-secrets or pap-secrets file

PPP supports two authentication protocols in Fedora and RHEL: Challenge Handshake Authentication Protocol (CHAP) and Password Authentication Protocol (PAP). Here is what each protocol does to authenticate:

+   - CHAP — The server sends a challenge packet (which includes the server name). The client sends a response that includes its name and a value that contains the secret and secret are stored in your /etc/ppp/chap-secrets file.
- PAP — The client sends its name and password (clear text) for authentication. The client name and secret are stored in your /etc/ppp/pap-secrets file.

By default, PPP will authenticate the server requests unless, it has no secrets to share. If it has no secrets, PPP (or, more specifically, the PPP daemon pppd) will refuse reauthentication. It is likely that you will find the user names and passwords provided when you set up your PPP connection in both of these files (PPP assumes that you are using CHAP or PAP authentication).
