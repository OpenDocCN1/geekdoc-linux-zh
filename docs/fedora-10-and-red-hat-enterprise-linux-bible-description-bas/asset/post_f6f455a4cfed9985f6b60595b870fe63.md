- **Printer Options** — Click Printer Options to set defaults for options for the printer driver. The available options are different for different printers. Many of these options can be overridden when someone prints a document. Here are a few of the options you might have to select:

- **Page Size** — The default is U.S. size, but you can also add the printer to print legal size, envelopes, ISO A4 standard or other page sizes.

- **Media Source** — Choose which to print from. Select Tray 1 to insert pages manually.

- **Levels of Gray** — Choose to use the printer's current levels of gray or have enhanced standard gray levels turned on.

# Configuring remote printers

To use a printer that is available on your network, you must identify that printer to your Fedora or RHEL system. Supported remote printer connections include Networked CUPS (IPP) printers, Networked UNIX (LPD) printers, Networked Windows (SMB) printers, Networked Novell (NCP) printers, and JetDirect printers. (Of course, CUPS and UNIX printer servers can run from Linux systems, as well as other UNIX systems.)

In each case, you need a network connection from your Fedora or RHEL system that enables you to reach to those printers are connected. To use a remote printer, of course, requires that someone set up that printer on the remote server computer. See the section "Configuring Printer Servers" later in this chapter for information on how to do that with Fedora and RHEL.

You can use the Printer configuration window to configure each of the remote printer types:

1. From the GNOME desktop, select System → Administration → Printing.
2. Click New Printer. The New window appears.
3. Besides the local ports listed (LPT and Serial ports), you can select one of the following network printer types:
   - AppleSocket/HP Jet Direct — For a JetDirect printer.
   - Internet Printing Protocol (IPP) — For a CUPS or other IPP printer.
   - LPD/LPR Host or Printer — For a UNIX printer.
   - Windows Printer via SAMBA — For a Windows system printer.
4. Continue following the steps in whichever of the following sections as appropriate.

# Adding a remote CUPS printer

After adding to an Internet Printing Protocol (IPP) CUPS printer from the Select Connection, you must add the following information to the window that appears:

- **Host** — The host of the computer to which the printer is attached (or otherwise accessible). This can be an IP address or TCP/IP hostname for the computer (TCP/IP name is typically accessible from /etc/hosts file or a DNS name server).
- **Queue** — The name on the remote CUPS printer server, which might look like /printers/HP722C. CUPS supports the concept of printer instances, which allows each printer to have several sets of options. If the remote CUPS printer is configured this way, you might hp/30dpi. A slash character separates the print queue from the printer instance.

# Adding a remote UNIX printer

After you have selected LPD/LPR Host or Printer from the Select Connection (previously), you may add the following information to the window appears:

- **Host** — The host of the computer to which the printer is attached (or otherwise accessible). This is the IP address or TCP/IP hostname for the computer (TCP/IP name is typically accessible from /etc/hosts file or a DNS name server). The host computer must be a UNIX or Linux print server running lpd daemon. If you know the hostname, but not the printer, type the hostname and the Probe button. Available LPD printers from the host will appear in a list.)
- **Queue** — The printer name. 

Although CUPS is the more popular printing system for Linux and UNIX systems today, UNIX-like systems still use the Berkeley LPR print spooler system (RFC1179). Early Red Hat systems used LPng print software to provide this interface for managing print servers (lp daemon). So, to a really old Red Hat system at your location, you might need to identify a printer there as a UNIX printer. For other clients, CUPS can also act as an LPD print spooler (see the bullet on LPD-style printing in the "Configuring a shared CUPS printer" section later in this chapter).

Click Forward and complete the configuration as you would for a local printer.

> TIP: If the print job is rejected when you test to send the printer, the print server may not have allowed you to access the printer. Ask the computer's administrator of the UNIX printer to add your host name to the /etc/lpd.perms file. (Type lpq -P printer to see the status of your print job.)
