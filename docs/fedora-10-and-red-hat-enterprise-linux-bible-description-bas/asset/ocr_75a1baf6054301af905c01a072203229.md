+   Enable only services you need — To offer services in Linux (such as Web, file, or mail services), a daemon will listen on a particular port number. Don't enable services you don't need. In fact, you shouldn't install server software unless you need. See Chapter 12 for information on using system services.

NOTE: A program that runs in the background handling service requests (such as sendmail) is called a daemon. Usually, daemons are started automatically when your system boots up, and they keep running until your system is shut down. Daemons may also be started on an as-needed basis by xinetd, a special daemon that listens on a large number of port numbers, and then launches the requested process.

+   Limit access to services — You can restrict access for a service to a particular host, domain, or network interface. For example, a computer with interfaces to the Internet and a local area network (LAN) might limit access to a service such as NFS to computers on the LAN, but not those services to the Internet. Services may limit access in their own configuration files using TCP/IP wrappers (described later in this chapter).

+   Check your system — Linux has tons of tools for checking the security of your system. After you install Linux, you can check access to its ports using nmap or watch network traffic using Wireshark (formerly Etheral). You can also add popular tools like Nessus, to get a more complete view of your system security.

+   Monitor your system — You can log almost every type of activity on your Linux system. System log files, using the syslog and klog facilities, can be configured to track as much or as little of your activity as you choose. The logwatch facility provides an easy way to have the potential problem messages forwarded to your administrative e-mail account. Linux logging features are described later in this chapter. You can add-packages such as tripwire and posterity, to check your system for tampering and with scanning your ports, respectively.

+   Use SELinux — SELinux is an extraordinarily rich (and complex) facility for managing nearly every aspect of a Linux system. It addresses the if-I-get-root-access-I-own-your-box shortcuts of Linux and UNIX systems for highly secure environments. Red Hat systems offer a useful, limited set of SELinux policies that are turned on by default by Fedora. Despite improvements, however, many system administrators still turn off SElinux because they find it difficult to use. Chapter 10 provides an overview of SELinux, along with explanations of how it is implemented in Fedora and RHEL.
