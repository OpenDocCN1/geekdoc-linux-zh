```
$ chfn -f "J Smith" -o "A-111" -p 555-1212 -h 555-2323 jenny
```

> NOTE: The finger command opens potential security issues. Finger gives out personal information that can be useful to those who want to crack your system. In addition, malicious users can flood your servers with finger requests.

## Modifying user accounts with User Manager

To use the desktop to change an existing account, you can use the User Manager. Here's how to add a new user to the User Manager window:

- 1. Select System -> Administration -> Users and Groups (or type system-config-users from a Terminal as root user). The main User Manager appears.

- 2. Select the user name of the account you want to modify, and then click the Properties button to open the Properties window (see Figure 11-3).

- 3. There are four tabs of information you can modify for the user selected:
    - User Data — This tab contains the user information you created when you first added the account.
    - Account Info — Select the Enable Account Expiration check box, and then type a date if you want the account to become inaccessible after a particular date. Select the Local Password is Locked check box if you want to prevent access to the account but not delete it. (The latter is a good technique when an employee is leaving the company or if you want to lock out a customer whose account is temporarily disabled. The information isn't removed; it isn't just accessible).

![](img/63c86e1d25a0e2be7e9f6de6b6f02530_531_0.png)

Figure 11-3: Choose Properties to modify an existing user account.

- **Password** — Select Password Expiration if you want to control expiration of the user’s password. By default, passwords don't expire. Here are your options: “Days before change allowed” (forces the user to keep the password for at least a set of days before it is changed); “Days before change required” (allows the user to keep the same password for at least the number of days); “Days before warning change” (sets how many days before the password expiration day that the user is warned to change the password); “Days before account inactive” (sets the number of days after which the account is deactivated).
- **Groups** — Select from the list of available groups to add the user to one or more of those groups.

- 4. Click OK to apply the changes to the user account.

## Deleting User Accounts

Occasionally, it is necessary to remove a user account from your Linux system. This can be done with either the `userdel` command or the User Manager window.

## Deleting user accounts with userdel

The `userdel` command takes a single argument, which is the login name of the account to delete. If you supply the optional -r option, it also deletes the user’s home directory and all the files in it. To delete the user account with login name mary, you would type this:

```
userdel mary
```

To wipe out her home directory along with her account, type this:

```
# userdel -r mary
```

Files owned by the deleted user but not located in the user's home directory will not be deleted. The system administrator must search for and delete those files manually. The find command is in very handy for this type of task. I won't describe all the capabilities of the find command (that would take a very fat chapter of it). I do, however, provide a few examples of how to use find to locate files belonging to a particular user, even when those files are scattered throughout the file system. You can use the find command to delete or change the ownership of files as they are located. Table 11-4 has a few examples of the find command in action.

## Table 11-4: Using find to Locate and Change Files

| Find Command | Description |
| --- | --- |
| find / -user mary | Search the entire file hierarchy (start /) for all files and directories owned by mary and print the filenames to the screen. |
| find /home -user mary -exec rm -i {} \ | Search for all files and subdirectories /home owned by mary. Run the rm command interactively to delete each file. |
| find / -user mary -exec chown jenny {} \ | Search for all files and subdirectories /home that are owned by user mary and run the chown command to change each file so that it is owned by jenny instead. |
| find -uid 500 -exec chown jenny {} \ | This command is basically the same as the previous example, but it uses the user ID instead of the user name to identify the files. This is useful if you have deleted a user before converting her files. |

There are a few common things about each invocation of the find command. The first parameter is the directory to start the recursive search in. After that come the attributes to match. You can use the -exec parameter to run a command against each matching file or directory. The {} characters designate the matching filename should be filled in when find runs the -exec option. The \ at the end simply tells Linux the command ends. These are only a few of find's capabilities. I encourage you to read the online man page to learn more about find. (Type man find to view the page.)

## Deleting user accounts with User Manager

Delete a user from the User Manager window, simply click the line representing the user account, and then click the Delete button.

- The information about the user is removed from the /etc/passwd file; thus, the user no longer log in.
- The home directory and all files owned by the user will still exist. However, a listing of files previously owned by that user (ls -l) will only show the former user's UID, but no name.

See the description in the previous section for information about how to find and remove previously owned by the user.

## Checking Quotas

Limited disk space can be another source of user support. Fedora and RHEL offer the software package for limiting and displaying the amount of disk space a user can consume. You can use the du command to see how much disk space has been used in a particular directory (and related subdirectories). To automate the process of checking for disk, you can create your own script. The following sections describe these ways of dealing potential disk problems.

## Using quota to check disk usage

A careless or greedy user can gobble up all the space on your hard disk and, possibly, bring your computer to a halt. By using quotas, you can limit the amount of disk resources a user or group can use.

The quota package contains a set of tools that limit the amount of disk space (based on disk blocks) and files (based on inodes) that a user can consume. Using quotas, you can limit the amount of usage (on a per-user and -group basis) for each file system on your computer. The general steps for setting disk quotas are:

- 1. Edit the /etc/fstab file.
2. Create quota files.
3. Create and start a quota startup script.
4. Create quota rules.
5. Check quotas.
