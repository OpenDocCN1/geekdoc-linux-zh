## Identifying user directories

If you have multiple users on your server and you want each to be able to publish their own Web content, it is common to identify a directory name that users create in their own home directories to store that content. When you identify the name that is appended to the user's home directory (~user), this directory name used to be set to public_html by default; however, it is now turned off by default.

To access your users' personal Web pages, add a comment character (#) to the UserDir disable line. Remove the # from UserDir public_html line to make users' public_html directories accessible through the Web server. After removing extra comment lines, the following text shows what the enabled section looks like:

```
# UserDir: The name of the directory which is appended onto a user's
# home directory if a ~request is received.

<IfModule userdir.c>
  # UserDir disable
UserDir public_html
</IfModule>
```

Besides uncommenting the UserDir public_html line shown in the previous example, you must make both the user's home directory and public_html executable in order for the UserDir directive to allow access to a particular user's public_html directory. For example, the user cjb could type the following to make directories accessible.

```
$ chmod 711 /home/cjb/public_html
$ mkdir /home/cjb/public_html
$ chmod 755 /home/cjb/public_html
```

For UserDir to work, the mod_userdir module must also be loaded (which it is by default).

There are two ways in which the UserDir directive can handle an incoming request that includes a username (for example, ~cjb). One possible format identifies the physical path of the individual users' accessible directories. The other can redirect a URL to which the request is redirected. A few examples are presented in Table 21-4, using the URL http://www.box.com/~cjb/proj/c004.html as a sample request.

## Table 21-4: UserDir Path Name and URL Examples

| UserDir Directive | Referenced Path or URL |
| --- | --- |
| UserDir public_html | ~cjb/public_html/proj/c004.html |
| UserDir/*/WWW | /cjb/WWW/proj/c004.html |
| UserDir/*/local/web | /usr/local/web/proj/c004.html |
| UserDir http://www.box.com/users | http://www.box.com/users/~cjb/proj/c004.html |
| UserDir http://www.box.com/~* | http://www.box.com/~cjb/proj/c004.html |
| UserDir http://www.box.com*/html | http://www.box.com/cjb/html/c004.html |

The UserDir directive can also be used to explicitly allow or deny URL-to-path name translation for particular users. For example, it is a good idea to include the following line to avoid publishing data that shouldn't be made public:

```
UserDir root
```

Alternatively, use the following lines to disable the translations for all a few users:

```
UserDir disable
UserDir enable wilhelm cjb jsmith
```

> NOTE: You should always be careful about content you publish about yourself on the Internet (names, addresses, personal information, and so on) and keep in mind that you could be accountable for the content you publish on your Web server. When you allow others to publish on your Web server, your liability can extend to those users publish as well. Be sure to have a clear policy about what is acceptable (and legal) to publish on your Web server and give that information to those you allow to use the server.

## Setting default index files for directories

The DirectoryIndex directive establishes a list of files that is used when an incoming request specifies a directory rather than a file. For example, a client requests the URL http://www.mybox.com/~jsmith/. Because it is a directory, it is automatically translated to http://www.mybox.com/~jsmith/. Now that directory searches for any of the files listed in the DirectoryIndex directive. The first match (from the default list of index.html and index.var) is used as the default document in that directory. If none of the files exist and the Indexes option (in the httpd.conf file) is selected, the server will automatically generate an index of the files in the directory.

```
# DirectoryIndex: sets the file that Apache will serve if a directory
# requested.
# The index.html.var file (a type-map) is used to deliver content-
# negated documents. The MultiViews Option can be used for the
# same purpose, but it is much slower.
DirectoryIndex index.html index.var
```

Sometimes dynamic content (like index.php or index.cgi) will be added to the DirectoryIndex to make that dynamic content is accessed before static content when a user requests a domain name or directory.

## Setting directory-access control

You and users can add an access file for each directory to access to that directory. By default, the AccessFileName directive sets .htaccess file containing the information. The following lines set this filename and prevent the contents of that file from being viewed by visitors to the Web site. If you change the file to a name other than .htaccess, be sure to change the line below ("^\\.ht") denies access to that file.

```
# AccessFileName: The name of the file to look for in each directory
# for access control information.
AccessFileName ~"\.ht"
```

```
<Files ~"\\.ht">
Order allow, deny
Deny from all
</Files>
```

You can add the same access directives to .htaccess file as you do to httpd.conf file. In general, it is more efficient to use a <Directory> directive in httpd.conf file than it is to create .htaccess file. ## Setting MIME-type defaults

The location of the MIME type definitions is defined by the TypesConfig directive. The DefaultType directive sets the MIME type:

```
# TypesConfig describes where the mime.types file (or equivalent) is
# to be found.
TypesConfig /etc/mime.types
```

```
# DefaultType is the default MIME type the server will use for a
# if it cannot otherwise determine one, as from filename
# extensions. If your server contains mostly text or HTML documents,
# "text/plain" is a good value. If most of the content is binary, such
# as applications or images, you may want to use "application/octet-
# stream instead of trying to display binary files
# as they are text.
# DefaultType /text/plain
```

With the mod_mime_magic module, a server can look for hints to figure out what type of file is requested. You must make this module is loaded for Apache for it to be used (it is loaded by default). The module can use hints from /usr/share/magic/mime (off by default) and /etc/httpd/conf/magic (on by default) files to determine the contents of a requested file. Here are the directives that can be used to:

```
<IfModule mod_mime_magic.c>
# MIMEFile /usr/share/magic/mime
# MIMEFile config/magic
</IfModule>
```

## Setting hostname lookups

With the Apache Web server, you can have the HostNameLookups directive look up addresses for incoming client requests. Turning this on can do:

```
# HostNameLookups: Log the names of clients or just their IP addresses
HostnameLookups Off
```

If the HostNameLookups directive is turned on, every incoming connection will generate a DNS lookup to translate the client's IP address into a hostname. If your site receives many requests, the server's response time could be severely affected. The HostNameLookups should be turned off unless you use a log file analysis or statistics package that requires fully qualified domain names and cannot perform the lookups on its own.
