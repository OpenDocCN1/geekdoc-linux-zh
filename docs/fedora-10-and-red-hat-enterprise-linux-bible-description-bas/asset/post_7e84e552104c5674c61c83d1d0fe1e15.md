To see if a particular service handled by xinetd is on or off, go to the /etc/xinetd.d directory and open the file representing that service with a text editor. The `disable` line sets whether or not the service is currently disabled. The following example is an excerpt from the /etc/xinetd.amanda file:

service amanda

```
{
socket_type     = dgram
protocol        = udp
wait           = yes
user            = amanda
server         = /var/lib/amanda/amamad
server_args    = auth-bsd andnsp
disable         = yes
}
```

In this example, the amanda configuration file represents a means of retrieving backup index files from amanda clients. By default, the service is turned off. When the service is on, a request to the xinetd server daemon for the amanda service from the network is handed to the amanda daemon. Arguments to daemon are on the server_args line.

To enable a service in /etc/xinetd.d file, edit the file using any text editor as root user. Turning the service on is easy as changing the `disable` option to no and restarting the xinetd daemon. For example, you could change the line in /etc/xinetd.amanda so that it appears as:

```
disable = no
```

Then you could restart the xinetd daemon (without turning off the daemon itself):

```
# service xinetd restart
```

NOTE: Although not all services support this, xinetd service lets you use reload instead of the restart command shown. With xinetd already running, a reload can occur faster and less interruption to system services by not completely shutting down xinetd.

### Web server

In most cases, you use the Apache project (httpd package) to create a Web server in Fedora or RHEL. If httpd is installed, you must turn on the service and then start it to use the service (as root user, type `chkconfig httpd` and then type `service httpd start`). Start-up will fail unless you have a valid name (IP address) for your Web server. To define a server name, add a ServerName to the http.conf file and restart the server.

Users who can access your system from the network will be able to view the contents of the /var/www/html directory, by default. Replace the index.html file and add your own content. If the httpd-manual package is installed, /var/www/manual contains the apache manual.

CROSS-REFERENCE: See Chapter 21 for information on configuring an Apache server.

### File servers

File servers in Fedora and RHEL can be provided by FTP servers, Samba (Windows) servers, Network File System (NFS), and NetWare servers. The following sections describe each of these.

### FTP servers

The Secure FTP daemon (vsftpd) package was designed from scratch to be very scalable and fast. It is geared towards FTP sites that require support for lots of simultaneous users. Configure vsftpd by editing the /etc/vsftpd/vsftpd.conf and /etc/vsftpd/user_list files. The vsftpd package shares the /var/ftp directory structure and listens on port 21 for service requests.

To turn on FTP service, type the following (as root user):

```
# service vsftpd start
# chkconfig vsftpd on
```

Another FTP server is the Trivial FTP server (tftpd). Tftpd is often used as a boot server for projects such as the Linux Terminal server project.

CROSS-REFERENCE: See Chapter 20 for information on how to configure the vsftpd server.

NOTE: An FTP server with Kerberos 5 support is also included with Fedora and RHEL. The krb5-workstation package contains the ftppd daemon that includes Kerberos 5 support. The wu-ftp FTP server is no longer in the Fedora or RHEL distributions.

### Samba server

The Samba server supports the Server Message Block (SMB) and CIFS file- and printer-sharing protocols. SMB and CIFS are often used to share resources on local networks consisting of computers running Microsoft Windows. You would not typically use SMB/CIFS files and printers over a public network, such as the Internet.

Samba services are off by default in Fedora and RHEL. To have Samba start automatically when you boot your computer, simply type `chkconfig smb`. To start the service now, type `service samba`.

In order for Samba to be useful, edit the Samba configuration file, `/etc/samba/smb.conf`. An easy way to configure this is with the Samba Configuration window (described in 18).

CROSS-REFERENCE: For more information about Samba, see Chapter 17.

### Netatalk server

The netatalk server enables Linux to act as an AppleTalk server for Macintosh computers. To use netatalk, you must install the netatalk package and turn on the service by typing `chkconfig atalk on`. Then start the service by typing `service atalk start`. Configuration is done from files in `/etc/atalk`.

CROSS-REFERENCE: See Chapter 26 for information on setting up netatalk.

### Login servers

A variety of login services are available for Fedora and RHEL. Both tlogin and rlogin services can be used to allow users from other computers to log in to Fedora or RHEL. These days, `sshd` is the preferred login service. For most of these services, you need to allow access to that service from your firewall.

If the telnet-server package is installed, the telnet service is off by default. If telnet is enabled, the xinetd daemon passes all requests for telnet service (by default, port 23) to in.telnet daemon to present the telnet login prompt. Once it is, only users with real logins to the computer can log in — anonymous users are not supported. Users who are logging in telnet are presented with a shell interface for accessing the computer.

Fedora and RHEL also include login daemons that provide Kerberos 5 support. Kerberos 5 provides a higher level of security than with other login services. Kerberos 5-enabled login services include Login (Kerberos 5) and Eklogin (Kerberos 5 with encryption).

The login service has been available for UNIX systems for a long time, though it is generally less than the other login services described here. The login service is off by default on your Fedora or RHEL system.

A newer addition to the login servers available with Fedora and RHEL is the OpenSSH service. This service is on by default. To access this service, use applications that come with the openssh-client package, such as `ssh`, `sftp`, and `login` remote login commands.
