## Creating the my.cnf configuration file

Global options affect how the MySQL server and related client programs are defined in the /etc/my.cnf file. The default my.cnf file contains only a few settings needed to get a small MySQL configuration going. The following is an example of the /etc/my.cnf file that comes with MySQL:

```
[mysqld]
datadir=/var/lib/mysql
```

```
socket=/var/lib/mysql/mysql.sock
user=mysql
# Default to using old password format for compatibility with mysql 3.x
# clients (using the mysqlclient10 compatibility package)
old_passwords=1
[mysql_safe]
log-error=/var/log/mysql.log
pid-file=/var/run/mysql/mysql.pid
```

Most of the settings in the default my.cnf file define the locations of files and directories needed by the mysql server. Each option is associated with a particular group, with each group identified by a name in square brackets. The particular options are associated with the mysql daemon ([mysql]) and the safe_mysql script that starts the mysql daemon ([mysql_safe]). (Refer to Table 24-1 for a list of these groups.)

The datadir value indicates that /var/lib/mysql is the directory that stores the MySQL databases you create. The socket option identifies /var/lib/mysql/mysql.sock as the socket that is used to create the MySQL communications end-point associated with the mysql server. The user option identifies the mysql user as has permission to do administration of the MySQL service. Based on the old_passwords=1 value, your MySQL database will use the password format used in MySQL 3.x.

The log-error and pid-file options specify the locations of the error log (/var/log/mysql.log) and the file that stores the process ID of the mysql daemon when it is running (/var/run/mysql/mysql.pid). The safe_mysql script actually starts the mysql daemon from the mysql startup script.

> NOTE: Each option follows a group name assigned to that group. Group assignments end when a new group begins or when the end of a file is reached.

## Choosing options

Many values used by the MySQL server that are not explicitly defined in the my.cnf file. The easiest way to find which options are available for MySQL server and clients is to run each command with the --help option. For example, to view the available mysql options (as well as other information) type the following from a Terminal:

```
# /usr/libexec/mysql --help | less
```

Then press Space to find the information one screen at a time. (An example of this output is shown in the next section.)

You can also use the man command to find which options are available. For example, to see which options are available to set for the mysql daemon, type the following:

```
man mysql
```

## Part IV: Fedora and RHEL Network and Server Setup

It's quite likely that you can try out your MySQL database server without changing any options at all. However, after you set up your MySQL database server in a production environment, you will almost surely want to tune the the server to match the way your server is used. For example, if it is a dedicated MySQL server, you will want to allow MySQL to consume more of the resources than it would by.

The following list shows a few examples of additional options that you might want to set for MySQL:

- **password = yourpwd** — Adding this option to a [client] group in a user's $HOME/.cnf file allows the user to run MySQL commands without having to enter a password each time. (Replace yourpwd with the user's password)
- **port #** — Defines the port number to the MySQL service listens for requests. (Replace # with the port number you want to use.) By default, MySQL listens on port 3306 for TCP and UDP protocols.
- **safe-mode** — Tells the server to skip optimization steps when the server starts.
- **tmpdir = path** — Identifies a directory, other than the default /tmp, for MySQL to use for writing temporary files. (Substitute with a full path for path*)

In addition to the options you can set, MySQL clients also have a lot of variables that you can set. Variables set such as buffer sizes, timeout values, and acceptable packet lengths. These variables are also listed by the --help output. To change a variable value, you can use the --set-variable option, defined by the variable name and value. For example, to set the sort_buffer variable to 10MB, you could add the following option under your [mysql] group:

```
[mysql]
set-variable = sort_buffer=10M
```

The following list identifies other variables you could set for your server. In general, raising the values of these variables improves performance, but also consumes more system resources. So you need to be careful raising these values on machines that are not dedicated to MySQL or have limited memory resources.

> NOTE: For variables that require you to enter a size, indicate Megabytes by an M (for example, 10M) or Kilobytes by a K (for example, 256K).

- **key_buffer_size = size** — Sets the buffer size that is used for holding index blocks that are used by all threads. This is a key value to raise MySQL performance.
- **max_allowed_packet = size** — Limits the maximum size of a packet. Raise this limit if you require processing of very large columns.
- **myisam_buffer_size = size** — Sets the buffer size used for sorting while repairing an index, creating an index, or altering a table.
- **sort_buffer = size** — Defines how much buffer size is allocated for each thread that needs to sort data. Raising this value makes sorting threads faster.
- **table_cache = #** — Limits the number of tables that can be open at the same time for all threads. The number of this variable represents the total number of file descriptors MySQL can have open.
- **thread_cache_size = size** — Sets the number of threads that are kept in cache, awaiting use. When a thread is done being used, it is placed back in the cache. If all the threads are used, new threads must be created.
