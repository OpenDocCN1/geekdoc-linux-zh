## Configuring the Apache Server

The primary file for configuring your Apache Web server is httpd.conf (located in the /etc/httpd/conf directory). After a few ages, the Apache project began recommending not using additional configuration files, such as rm.conf and access.conf, and simply putting everything in httpd.conf. In recent releases, however, has been a trend toward having modules and other components that are used with Apache have their own configuration files (usually located in the /etc/httpd/conf/ directory).

All Apache configuration files are plain-text files and can be edited with your favorite text editor. The /etc/httpd/conf/httpd.conf file is reproduced in its entirety in the following section, with conflations inserted after related blocks of options (intended to supplement the comments with each file).

Some modules, scripts and other services related to Apache, such as perl, php, ssl, webizer, and mysql, have individual configuration files that may interest you. Those files are contained in the /etc/httpd/conf.d/ directory. The “Configuring modules and related services (/etc/httpd/conf.d.*conf)” section later in this chapter discusses modules and related features.

## Revealing subcomponents

The ServerTokens directive lets you prevent remote computers from finding out what subcomponents are running on your Apache server. Comment out this line if you prefer not to expose information. To prevent exposure, ServerTokens is set as follows:

```
# Don't give away much information about all the subcomponents
# we are running. Comment out this line if you don't mind remote sites
# finding out what major optional modules you are running
ServerTokens OS
```

Setting ServerTokens to ProductOnly would minimize the connection information at a potential cracker could see.

## Storing the server's PID file

The Apache web server keeps track of PID for the running server process. You can find the locations of this file using the entry next:

```
# PidFile: The file in which the server should record its process
# identification number when it starts.
PidFile run/httpd.pid
```

Apache uses the PidFile to store the process ID of the first (root-owned) master daemon process. This information is used by the /etc/init.d/httpd script when shutting down the server and also by the server-status handler (as described later).

## Configuring timeout values

You can set several values that relate to timeout. Some of these values are described in the text following the code:

```
# Timeout: The number of seconds before receives and sends time out.
#
Timeout 120

# KeepAlive: Whether or not to allow persistent connections (more than
# one request per connection). Set to "Off" to deactivate.
#
KeepAlive Off

# MaxKeepAliveRequests: The maximum number of requests to allow
# during a persistent connection. Set to 0 to allow unlimited amount.
# We recommend you leave this number high, for maximum performance.

MaxKeepAliveRequests 100

# KeepAliveTimeout: Number of seconds to wait for the next request
# from the same client on the same connection.
#
KeepAliveTimeout 15
```

The Timeout directive determines the number of seconds that Apache will hold a connection open between the receipt of packets, between the receipt of acknowledgments sent responses, or while receiving an incoming request. The default of two minutes (120 seconds) can be lowered if you find an excessive number of open, idle connections on your machine.

The KeepAlive directive instructs Apache to hold a connection open for a period of time after a request has been handled. This enables subsequent requests from the same client to be processed faster, as a new connection doesn't need to be created for each request.
