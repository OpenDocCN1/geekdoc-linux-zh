# Setting Samba clients

Once you have configured your Samba server, you can try using the shared directories from a client computer on your network. The following sections describe how to use your Samba server from another Linux system or from various Windows systems.

# Using Samba shared directories from Linux

There are several methods of connecting to shared directories from your Samba client. The following sections address these methods.

# Using Samba from Nautilus

To connect to a Samba share from Nautilus, use the Location Box by clicking File -> Open Location. Then type **smb:** into your Nautilus file manager Location box.

A list of SMBwork groups on your network appears in the window. You can select a workgroup, choose a server, and select a resource to use. This should work for shares requiring no password.

The Nautilus interface requires you to send clear-text passwords or type the user and password into your location box. For example, to get your home directory (/home/chris) through Nautilus, I can type my user name, password, server name, and share name as follows:

```
smb://chris:my72rgb@toys/chris
```

# Mounting Samba directories in Linux

Linux view shows shared directories as it does any other method (hard disk, NFS shares, CD-ROM, and so on). Using the mount command, you can mount a Samba shared file system that is permanently connected to your Linux file system.

The following example of mount command shows how I would mount my home directory (/home/chris) from a computer toys on a local directory (mnt/toys). As root user, from a Terminal window, type:

```
# mount /mnt/toys
# mount -t cifs -o username=chris,password=a72mg //toys/chris /mnt/toys
```

The file system for a Samba share is cifs (-t). I pass the user name (chris) and password (a72mg) as options (-o). The remote share of my home directory is //toys/chris. The local mount point is /mnt/ . At this point, you can access the contents of /home/chris on toys as you would any file or directory locally. You will have the same permission to access and change the contents of that (and its subdirectories) as if you were the user chris using those contents directly from toys.

To mount Samba shared directory personally, you can add an entry to your /etc/fstab file. For the example just described, you could add the following line (as root user):

```
//toys /mnt/toys cifs username=chris,password=a72mg
```

You can create a credentials file to use to contain your user name and password, instead of exposing that information to the command line. That way, someone running the ps command on your system will not be able to see that information. For example, you could create a file named /etc/samba/creds.smbpub containing the following lines:

```
username=chris
password=a72mg
```

You could then change the mount command shown earlier to appear as follows:

```
# mount -t cifs -o credentials=/etc/samba/creds.smbpub //toys/chris
```

# Troubleshooting your Samba server

A lot can go wrong with a Samba server. If your Samba server isn't working properly, the descriptions in this section should help you pinpoint the problem.

# Basic networking in place?

Before computers can share directories and printers from Samba, they must be able to communicate on your LAN. Refer to Chapter 15 for information on setting up a LAN.

In Samba, your Samba server can use the TCP/IP name as the NetBIOS name (used by Windows networks for file and printer sharing), or a separate NetBIOS name can be set in smb.conf file. It is critical, however, that the broadcast address be the same as all clients communicating with your Samba server. To see your broadcast address, type the following:

```
$ ifconfig -a
eth0 Link:Ethernet HWaddr:00:D1:B3:75:A5:1B
inet addr:10.0.0.1 Bcast:10.0.0.255 Mask:255.255.255.0
```

The important information is the broadcast address (Bcast:10.0.0.255). This is determined by the netmask (Mask:255.255.255.0). If the broadcast address isn't the same for the Samba server and the clients on the LAN, the clients cannot see that the Samba server has directories or printers to share.
