## IP address classes

Unfortunately, it's not easy to understand what of an IP address represents the network and which is the host without explaining how IP addresses are structured. IP addresses are assigned in the following manner. A network administrator gathers a pool of addresses. The administrator can then assign specific host addresses within that pool as new computers are added to the organization’s local network. There were originally three basic classes of IP addresses, each representing a different network size.

- Class A — Each Class A has a number between 0 and 127 as its first part. Host numbers within a Class A are represented by any combination of numbers in the next parts. ## Understanding netmasks

Suppose you assigned the Class B address 135.84.118, but you are given only the pool of numbers available to 135.84.118. How do you tell your network that every address beginning with 135.84.118 represents a host on your network, but that other addresses beginning with 135.84 should be routed to another network? You can do it with a netmask.

The netmask essentially identifies the network number for a network. When you assign the IP address that is associated with your computer’s interface to the LAN (eth0), you are asked for a netmask. By default, your computer fills in a number that masks the part of your IP address that represents the class of your network. For example, the default netmasks for Class A, B, and C networks are the following:

- Class A netmask: 255.0.0.0
- Class B netmask: 255.255.0.0
- Class C netmask: 255.255.255.0

Now, if your network assigned the network number 135.84.118, to tell your computer that 135.84.118 is the network number and not 135.84 (as it normally would be for a Class B address), add a netmask of 255.255.0. So you could use host numbers from 1 to 254 (which would go into the fourth part of the number).

To further confuse the issue, you could mask one or more bits that are part of the IP address. Instead of using the number 255, you could use any other numbers from 0 and 255, including 128, 192, 224, 240, 248, 252, and 254, to mask only part of the numbers in that part of the address.

> NOTE: The reason that only the numbers just are valid netmasks is that each part is represented by binary numbers, but all 1s included must be to the left. So 240 would be allowed (11110000) but 242 would not (11110010). This limitation is what leads to the creation of CIDR (see the next section).

## Classless Inter-Domain Routing

The class method of allocating IP addresses had several drawbacks. First, few organizations fell neatly into one class or another. For most organizations, a Class C address (up to 256 IP addresses) was too small, and a Class B address (up to 65,534 IP addresses) was too big. Second, IP resulted in a lot of wasted numbers in world where IP addresses were running short. Third, IP resulted in too many routing table entries. As a result, routers becoming overloaded with information.

The Classless Inter-Domain Routing (CIDR) addressing scheme set out to deal with these problems. The scheme is similar to IP address classes, but offers more flexibility in assigning how much of the 32-bit IP address is the network identifier. Instead of the first 8, 16, or 32 bits identifying the network, 13 to 27 could identify the network. As a result, groups of assigned IP addresses could contain from 32 to about 524,000 host addresses.

To indicate the network identifier, a CIDR IP is followed by a slash (/) and then a number from 13 to 27. A smaller number indicates a network containing more hosts. Here’s an example of an IP address that uses the CIDR notation:

`128.0/16`

In this example, the first 16 bits (128.0) represent the network, and the remainder (18) represent the specific host. This network can contain up to 65,536 hosts. The following list shows how many hosts can be represented in different networks using CIDR:

| Mask | Number of Hosts |
| :--- | :--- |
| /13 | 524,288 |
| /14 | 262,144 |
| /15 | 131,072 |
| /16 | 65,536 |
| /17 | 32,768 |
| /18 | 16,382 |
| /19 | 8,192 |
| /20 | 4,096 |
| /21 | 2,048 |
| /22 | 1,024 |
| /23 | 512 |
| /24 | 256 |
| /25 | 64 |
| /27 | 32 |

The CIDR addressing scheme also helps reduce the problem of having many routes. For example, a /13 network has 524,288 hosts, while a /27 network has only 32.

## Setting Up Network Connections and LANs

What is the impact of assigning IP addresses? Your choice of IP addresses depends on your situation. If you are setting up a large network, you should use Class A. If you are setting up a medium network, you should use Class B. If you are setting up a small network, you should use Class C.

If you are setting up a network, you need to configure a netmask to identify the network part of the address. The netmask tells the router which part of the IP address belongs to the network and which part belongs to the host.

## Troubleshooting your LAN

After your LAN has been set up, your Ethernet cards installed, hostnames and addresses added, there are several methods you can use to check that everything is up. Some troubleshooting techniques are shown in the following sections.

### Did Linux find your Ethernet driver at boot time?

Type the following right boot your computer to verify Linux found your card and installed the Ethernet interface:

```bash
dmesg grep eth
```

The dmesg command lists all the messages that were output by Linux at boot. The grep command causes only lines that contain the word eth to be printed. The first message shown appeared on my laptop computer with the NETGEAR card:

```
eth0: Compatible: port 0x300, irq3, hw_addr 00:B0:C8:8E:49
eth0: OEM 48257/48258 10/Ethernet at 0xccc0, 00:90:27:4e:67:35, IRQ 17.
```

The message in the first example shows that a card was found at IRQ3 with a port address of 0x300 and an Ethernet hardware address of 00:B0:C8:8E:49. In the second example, the card is at IRQ 17, the port address is 0xccc0, and the Ethernet address is 00:90:27:4e:67:35.
