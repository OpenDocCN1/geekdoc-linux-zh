```
# ### begin forwarding rule ###
# The statement between begin ... define a SINGLE forwarding
# rule. They belong together, do NOT split them. If you create
# forwarding rules, duplicate the whole block!
#
# Remote Logging (we use TCP for reliable delivery)
#
# An on-disk queue is created for action. If the remote host is
# down, messages are spooled to disk and sent when it is up again.
##workdirectory /var/spool # where to place spool files
#$ActionqueueFileName default # unique name prefix for spool files
#$ActionqueueMaxDiskSpace 1g # gb space limit (use as much as possible)
#$ActionqueueSaveShutdown # on save messages to disk to shutdown
#$ActionqueueType LinkedList # run asynchronously
#$ActionResumeCount -1 # infinite retries if host is down
# remote host is: name=ipv4:port, c.g. 192.168.0.1:514, port option
#.*=remote-host:514
# ### end of the forwarding rule ###
```

The lines beginning with a # character are comments. Other lines contain two columns of
information, separated by spaces or tabs. The left field is a semicolon-separated list of message
types and message priorities. The right field is the log file to which messages should be\written.

The most interesting part of the section marked RULES.

NOTE: Notice the dash (-) before the /var/log/logfile file Normally, each log file is synced
after every logging. A dash preceding the full path to the log indicates that the file is not synced after
each logging. While this might result in lost information if your machine crashes before the log is written,
can result in better performance on your system if you use verbose logging.
