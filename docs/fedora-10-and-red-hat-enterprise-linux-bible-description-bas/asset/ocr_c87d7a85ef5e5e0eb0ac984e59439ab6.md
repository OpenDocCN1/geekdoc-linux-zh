Each zone in the `named.conf` file describes the type of server this is for the zone (master in all cases here, except the root zone), the database file (in the `named` directory) that contains records for the zone, and other options relating to the zone records. The `named.conf` file is set up for you default. It identifies the locations of the root servers.

I made the other zones (yourlan.db, db.yourdomain.com_inside, db.yourdomain.com_outside and 0.0.10-in-addr.arpa). For this example. For the “inside” view, the `yourlan` file lets the computers on your LAN reverse address lookups (getting the names with IP addresses). The `yourdomain.com_inside` file contains names and addresses for all computers in your domain (including those on the local LAN). The DNS server for the inside view of this domain is 10.0.0.2 (Clients in your LAN would use 10.0.0.1 and 10.0.0.2 as DNS servers in `/etc/resol.conf`).

For the “outside” view, the `db.yourdomain.com_outside` file contains names and IP addresses for all computers in your domain you want to make public (computers on your private LAN are excluded). The DNS server for for the outside view of this domain is 123.45.67.2.

Notice each zone points to a zone file in the `named` directory. Table 25-1 shows which file in the name directory each points to.

# Table 25-1: Zones and Related Zone Files in DNS

| Zone | Zone File (located in the /var/named/chroot/var/named directory) |
|---||
| (a single dot representing Internet root servers) | named.ca |
| 0.0.10-in-addr.arpa | yourlan.db |

Be very careful editing the `named.conf` file. Forgetting a semicolon is too easy, and results in the file not loading. To ensure the `named.conf` file doesn't contain any syntax errors, you can run the following command (as root user):

```
# named-checkconf
```

If a syntax error is present, a message identifies the problematic line and informs you what seems to be wrong with it. If the syntax is correct, continue to create the zone files in the `/var/named` directory.
