# Chapter 14: Computer Security Issues 621

```
make server.crt
make stunnel.pem
make genkey
make certreq
make testcert
make server.crt SERIAL=1
make stunnel.pem SERIAL=2
make testcert SERIAL=3
```

The make command utilizes the Makefile to create SSL certificates. (The make command is used for a variety of software tasks with C and C++ programming.) Without any arguments the make command prints the information listed above. The following defines each argument you can give to:

+   - server.key - Generates generic public/private keys.
- server.csr - Generates a generic SSL certificate request.
- server.crt - Generates a generic SSL test certificate.
- stunnel.pem - Generates a generic SSL test certificate, but puts the private key in the same file as the SSL test certificate.
- genkey - Same as make server.key except places the key in the ssl.key directory.
- certreq - Same as make server.csr except it places the certificate request in the ssl.csr directory.
- testcert - Same as make server.crt except it places the test certificate in the ssl.crt directory.
- server.crt SERIAL=1 - Generate the keys mentioned above using serial numbers other than zero.

# Using third-party certificate signers

In the real world, I know who you are because I recognize your face, voice, and your manners. On the Internet, I cannot see them and must rely on a trusted third party to vouch for your identity. To ensure that a certificate is immutable, it has to be signed by a trusted third party when the certificate is issued and validated every time end user taking advantage of your security site loads. The following is a list of the trusted third-party signers:

+   - GlobalSign — www.globalsign.com/
- GeoTrust — www.geotrust.com/
- VerisSign — www.verisign.com/
- RapidSSL.com — www.rapidssl.com/
- Thawte — www.thawte.com/
