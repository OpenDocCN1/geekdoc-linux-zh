# Using the batch command

If resources are at a premium on your machine, or if the job you submit can run at a priority lower than normal, the batch command (equivalent to -q) may be useful. It is controlled by the same daemon, and allows jobs in the same format as submissions (although time specification is optional).

However, to prevent your job from usurping scarce processing time, the job will run only if the system load is below a particular value. The default value is 0.8, by specifying a command-line option to at can modify this. This was used as an example in the earlier section describing setup and shutdown. It is an example of the batch command:

```
$ batch
at> du -h /home > /tmp/duhome
at> <Ctrl+d>
```

In this example, after you type the batch command, at the facility is invoked to enable me to enter the command(s) I want. Typing the du -h /home > /tmp/duhome command has the disk usage for everything in the /home directory structure output to /tmp/duhome file. On the next line, pressing Ctrl+D ends the batch job. As soon as the load average is low enough, the command is run. (Run the top command to view the current load average.)

# Using the cron facility

Another way to run commands unattended is via the cron facility. Part of the cronie package, cron addresses the need to run commands periodically or routinely (at least, more often than you'd care to manually enter them) and allows lots of flexibility in automating the execution of the command.

As with the facility, any output or error messages that haven't been redirected elsewhere are e-mailed to the user who submitted the job. Unlike using at, cron jobs are intended to run more than once and at a regular interval (if that interval is only once per month or year).

Also like at, cron includes two access control files designed to limit which users can use it. The file /etc/cron/cron.allow contains a list of users who are granted access, and the file /etc/cron.deny a similar list of those who may submit cron jobs. If neither file exists (or cron.deny is empty), all users are granted access to cron.
