Encrypted file systems can be used to protect your data if your computer should be lost or stolen. In particular, this feature was created with laptops in mind. Stealing your laptop would not be able to mount or access data on an encrypted file system without your password. The cryptsetup command using the cryptsetup-luks package is used to create your cryptographic volumes. Any file system, other than root (/), can be encrypted in Fedora 10. To learn more, refer to the Encrypted Filesystems page.

```
http://fedoraproject.org/wiki/Releases/FeatureEncryptedFilesystems
```

In addition, you can use encryption on hotpluggable file systems. A getting started document appears at http://flyn.org/easycrypto/easycrypto.html.

You can use dm-crypt, short for device mapper, to provide transparent encryption to block devices, such as disks. By transparency, this means that programs don't need to worry about the contents of your disk are encrypted, as the mapping layer adds this. This allows you to work with word processors, text editors, drawing programs, and so on, without missing with encryption. But, your files are stored safely protected. # Using the fstab to define multiple file systems

The hard disks on your local computer and the remote file systems you use every day are probably set up to mount automatically when you boot Linux. The definitions for which these file systems are mounted are contained in the /etc/fstab file. Here's an example of an /etc/fstab file

| /DevGroup00/LogVol100 / | ext3 | defaults | 1 1 |
| LABEL=/ | ext3 | defaults | 1 2 |
| /dev/devpts | /dev/pts | defaults5,mode=620 | 0 0 |
| /dev/shm | /dev/shm | tmpfs | defaults | 0 0 |
| /dev/prx | /dev/prx | defaults | 0 0 |
| /dev/sys | /dev/sys | sysfs | defaults | 0 0 |
| /DevGroup00/LogVol101 swap | | defaults | 0 0 |
| /dev/sda | /mnt/root | vfat | noauto | 0 |

> NOTE: If you use UUID (universal identifiers) such as UUID=86623bb-d845-4183-ba0cdf253e48, before the name of the file systems. I pulled out to make the fstab file contents clear.

All file systems listed in this file are mounted at boot time, except for those set to noauto in the fourth field. In this example, the root (/) and swap hard disk partitions are configured as logical volume management (LVM) volumes. This means they may consist of multiple hard disk partitions.
