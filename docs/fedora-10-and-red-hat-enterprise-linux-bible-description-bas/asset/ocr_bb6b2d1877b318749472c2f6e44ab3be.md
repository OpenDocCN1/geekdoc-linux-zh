# Changing to a shutdown run level

Shutting down the machine is simply a change in run level. With that in mind, other ways to change the run level include the reboot, halt, poweroff, and shutdown commands. The reboot command, which is a symbolic link to the halt command, executes a shutdown -now, terminating all processes and rebooting the machine. The halt command executes shutdown -h now, terminating all processes and leaving the machine in an idle state (but still powered on).

Similarly, the poweroff command, which is also a link to the halt command, executes a change to run level 0, if the machine BIOS supports Advanced Power Management (APM), it will switch off to the machine.

> NOTE: A time must be given to the shutdown command, either as +m (representing the number of minutes to delay before shutting down) or as hh:mm (an absolute time value, where hh is the hour and mm is the minute that you would like to shutdown to). Alternatively, now is commonly used to initiate the shutdown immediately.

# Scheduling System Tasks

Frequently, you need to run a process at specific times, or at off-hours. The facility is designed to run such jobs at specific times. Jobs you submit in the directory /var/spool/at/, awaiting execution by the daemon at. The jobs are executed using the current directory and environment that was active when the job was submitted. Any output or error messages that haven't been redirected elsewhere are e-mailed to the user who submitted the job.

The following sections describe how to use the at, batch, and cron facilities to schedule tasks to specific times. These descriptions also include ways of viewing which tasks are scheduled and deleting tasks that you do not want to run.

# Using at.allow and at.deny

There are two access control files to limit which users can use the facility. The file /etc/at.allow contains a list of users who are granted access, and the file /etc/at.deny contains a list of those who may not submit at jobs. If neither file exists, only the superuser is granted access to. If a blank /etc/at.deny file exists (as in the default configuration), all users are allowed to use the facility to run their own at jobs. If you use either at.allow or at.deny, you aren't required to use both.
