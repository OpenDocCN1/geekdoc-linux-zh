## Configuring vsFTPd

Most of the configuration of vsFTpd is done in the /etc/vsftpd/vsftpd.conf file. Although many values are not explicitly in vsftpd.conf, you can override the defaults by setting option=value statements in this file. You can set such things as which users have access to your vsFTpd server, how logging is done, and how timeouts are set.

Read the following sections for more information about how vsFTpd is configured by default and how you can configure your vsFTpd server.

## User accounts

Users who can access your vsFTpd server are, by default, the anonymous user and any users with real user accounts on your system. (A guest is simply a real user account that is restricted to its one home directory.) The following lines set these user account features:

```bash
anonymous_enable=YES
local_enable=YES
```

The anonymous_enable line lets users log in either the anonymous or ftp user name. If you want to disable access by anonymous users, don't just comment out anonymous_enable. Anonymous access is by default, so you must set anonymous_enable=NO to disable.

Any users with local accounts (/etc/passwd) and valid passwords can log into the FTP server with local_enable set to YES. Exception to this rule is that, by default, all user accounts in the /etc/vsftpd/user_list file are denied access.

> NOTE: Before you start logging into an FTP server with your personal name and password, keep in mind that FTP login services use clear text passwords. Because of this fact, a network sniffer is capable of seeing this. If you want to use an FTP interface to access files on an FTP server using your personal account, consider using the OpenSSH (http://www.openssh.org/) sftp command instead of a normal FTP client. If the FTP server includes an SSH server, you can use sftp to connect through encrypted passwords.

Check the user_list file to see which users are denied access to the vsFTPpd server. Note that root and administrative logins are excluded. You can add other users to this list or change the location of the file by setting the user_list parameter to the file you want. To add a user to the user_list or use the user_list parameter to create a new list, you also have userlist_enable set to YES (as it is by default). For example:

```bash
userlist_file=/etc/vsftpd/user_list_local
userlist_enable=YES
```

If you like, you can change the meaning of the /etc/vsftpd/user_list file so that only the users in that list are allowed to use the vsFTPpd server. Set userlist_deny=NO and change the /etc/vsftpd/user_list to include only names of users to whom you want to grant access to the server. All other users, including anonymous and ftp, will be denied access.

## Setting FTP access

The vsFTPpd server software provides a simple and secure approach to access permissions. By using settings in the FTP service to selectively prevent downloads and uploads of particular directories (as FTP servers as WU-FTPpd do), you can use standard Linux file and directory permissions to limit access. There are, however, the general settings in the /etc/vsftpd/vsftpd.conf file to let users get files from and put into your vsFTPpd server.

## Downloading files

Any users with valid logins (anonymous or real users, excluding some administrative logins) download files from the vsFTPpd server by default. The ability to download a particular file or from a particular directory is governed by the following basic Linux features:

- File and directory permissions — Standard file and directory permissions apply as a means of limiting access to particular files, even in accessible file systems. So, if the root user puts a file with 600 permission (read/write only) in the /var/ftp directory, an anonymous user is not able to download that file.
- Root directory — The root directory (chroot) for anonymous users is /var/ftp. To enable this, add the following to vsftpd.conf:

```bash
chroot_local_user=YES
```
- ASCII mode — As downloading, ascii mode is prohibited. Although ascii downloads create a potential hole for draining resources from your server, ascii uploads are apparently not as dangerous as can be useful for uploading files. To allow ascii uploads, add the following:

```bash
ascii_upload_enable=YES
```

## Uploading files from local users

The write_enable value must be YES if you intend to allow any users the capability to write. The following defaults allow local users to upload files:

```bash
write_enable=YES
local_umask=022
```

The umask=022 sets the default permission used when a local user creates a file (The 022 causes files to be 644, allowing the user read and write and everyone read permission.)

## Uploading files from anonymous users

The ability to upload files is turned off for anonymous FTP. If you want to turn it on, add the following line to vsftpd.conf file:

```bash
anon_upload_enable=YES
```

To use anonymous upload, the global enable must be activated. You must also make sure the /var/ftp directory contains one or more directories with write permissions open to anonymous users. For example, you might want to create an incoming directory and open its permissions (chmod 777 /var/ftp/incoming).

Files uploaded by anonymous users will be created with 600 permission by default (read/write permission for the ftp user, not accessible to any other users so that the user who uploaded the files cannot remove them or even see them). To allow 644 permission, for example, you can add the following line:

```bash
anon_umask=022
```

When you allow anonymous user to upload files, you can grant limited ability to change the files he or she uploads. By adding the following line, you can allow anonymous users to rename or delete any files uploaded by anonymous users (that the files are in directories for which we have write permission):

```bash
anon_other_write_enable=YES
```

If you also want to allow anonymous users to create their own directories, add the following:

```bash
anon_mkdir_write_enable=YES
```
