## Configuring an AppleTalk Server in Linux

If you have a mixture of older Macs (such as a Power Macintosh with Mac OS 8.1) and newer Macs (such as an iMac or Mac Mini with Mac OS X) on the same LAN, an AppleTalk server could be used to share files and printers among them. With the netatalk installed on your Fedora server, netatalk can be configured to act as that AppleTalk server.

Using netatalk, you can link multiple Macs to use the features from a computer running Fedora:

- **AppleShare file**— Files and directories you share from your AppleTalk server (via netatalk) are stored with features and permissions that a Mac user would expect.
- **AppleTalk printer server**— Printers configured on your Linux server can be shared as though they were AppleTalk printers.
- **AppleTalk router**— Your Linux system can act as a router between multiple AppleTalk networks.

The netatalk project site is located at http://netatalk.sourceforge.net. There, you can find documentation (including an FAQ), as well as links to help netatalk Web sites.

To use netatalk in its most basic configuration, all you need to do is:

- Create a LAN connecting your Linux server and Mac clients. You can configure netatalk as a router to connect multiple LANs.
- Start netatalk as described in the "Starting netatalk" section. This enables any users with user logins to your Linux computer to access their home directories from a Mac (using Linux logins and passwords). You can also add printers and other directories to share.

Before you fire up netatalk, I recommend that you check out the following section.

## Before you start using netatalk

Know that when you are creating an AppleTalk server on a Linux file system, you are creating a hybrid-type file system. Strange issues can arise because the two types of servers handle ownership, access, and file attributes (such as what applications launch a file) differently.

The netatalk shared directory structure (referred to as a volume or share), special directories exist to hold attributes (file type and creator), trash, temporary items, and find content. If you change files or directories on AppleTalk volumes without Linux without precautions, you'll delete a file and leave its attributes around or create a file that has no attributes (a Mac doesn't know how to launch it). You can't move a whole directory structure from one Linux partition to without losing the connection between the files and their attributes.

Here are a few tips to think about before using netatalk:

- Use Mac clients to create, move, and copy files on the Mac whenever clean and working. This is the best way to keep your volumes clean and working.
- If you manipulate netatalk files and folders from a Linux shell, use apple_mv, apple_cp, and apple_rm commands (described later in this chapter).
- You can share the same volumes with your Mac clients (using netatalk) and Windows clients (using Samba), but this involves certain risks and caveats as well. The “Sharing files with netatalk and Samba” section later in this chapter for ways to avoid trouble.
- Mac expects permissions on files and directories to be more than Linux administrators are comfortable with. Check the “Securing netatalk volumes” section for information on the best ways to provide the necessary access.
- Tools for troubleshooting AppleTalk networks are different than those used for pure TCP/IP networks. Refer to the “Troubleshooting netatalk” section for information you can use.

## Setting up netatalk server

The following steps provide a high-level overview of how to setup your netatalk server. The sections that follow contain details on these steps.

1. **Install netatalk** — The package is in Fedora, so to install netatalk, you can type yum install netatalk.
2. **Start netatalk** — As with most Linux services, netatalk can be set to start automatically from a start-up script, in this case /etc/init.d/atalk. (You can do some limited file sharing with the default configuration, as described in the next section.)
3. **Open firewall** — If you have enabled your firewall, you need to open several ports for netatalk to allow users from other computers to access your system.
4. **Configure general settings (/etc/netatalk.conf)** — Use the netatalk.conf file to add your own general settings. The default settings for the netatalk configuration are:
   - **Clients** — Up to 50 Mac clients can connect to your server at a time.
   - **AppleTalk name** — Your computer's hostname (type hostname -s to see it) is used as your AppleTalk server.
   - **Authentication** — Netatalk will allow users to connect using a guest login (nobody) with no password, a clear-text password, or an encrypted password (Diffie-Hellman authentication).
   - **Guest user** — A guest user can connect without entering a password and shared volumes that are open to the world. This guest user is assigned to the Linux nobody name (By default, no guests are set up.).
   - **Daemon processes** — Netatalk daemons processes to manage your AppleTalk network interface (atalk daemon), start the AppleTalk print sharing service (papd daemon), and start the AppleTalk protocol (apd daemon) for sharing volumes.
5. **Configure server settings (/etc/apd.conf)** — Configuring apfd.conf lets you set up specific settings for your netatalk server (you can have multiple virtual servers configured that look different from the outside world). The contents of the apfd.conf file affect how the AppleTalk protocol daemon (apfd) shares volumes with Macs.
6. **Set up users** — The Netatalk server can run on the Linux users you add to the computer (using clear-text passwords), limit access to your shared volumes based on permissions. Or, you can configure netatalk to use encrypted passwords to validate users.
7. **Shared volumes (/etc/AppleVolumes.default)** — When Netatalk starts, each user with a valid login to your computer, by default, access his her own home directory as an AppleTalk share from a Mac client. You can (probably) have more shared volumes by configuring them in the AppleVolumes.default file.
8. **Securing shared volumes** — Netatalk can take advantage of Linux security features to protect shared volumes. You can secure volumes for the host, user, and file and directory
9. **Share printers (/etc/papd.conf)** — Netatalk can share any printer you have connected to Linux (or otherwise configured locally) by adding a definition to the papd.conf file. No printers are shared until you add them

As work with your shared volumes and printers, you will find maintenance issues arise from time to time. In particular, you should refer to the following sections: "File and directory-level security" (for dealing with hidden attributes and directories), "Sharing files with netatalk and Samba" (to share the same directories from netatalk and Samba), and "Troubleshooting netatalk" (general troubleshooting tips)

## Starting netatalk

Start up netatalk as you would most Linux services: from a start-up script. The netatalk service is called atalk (/etc/init.d/atalk). To turn it on, follow the following as root user:

```
# chkconfig talk on
```

The previous command lasts the next time you reboot. To start it now (it may take a few minutes to complete), type:

```
# service talk start
```

Here’s what happens when you start the AppleTalk service:

- The AppleTalk daemon (atalkd) starts from the contents of the /etc/talk/atalkd.conf file.
- The papd daemon registers printers using the contents of the /etc/talk/papd.conf file.
- The afpd daemon registers volumes from the contents of the /etc/talk/AppleVolumes.default file (using settings from the system file).

To check that the nettalk service started properly, as root type one from the following Linux system on the network (the output may take a minute or two to appear):

```
# nbpstat
toys:AFFServer 650.115:128
toys:netalk 150.115:4
toys:Workstation 650.115:4
```

To check whether your net service is is available from a Mac client, go to the Mac client and perform the appropriate procedure:

- For a-Mac OS X client — Click the Apple Chooser. From the Chooser window, click AppleShare. The nettalk service should appear in the Select a server pane. Click it and click OK, and then use any user login and password from Linux to use that’s home directory.
- For a Mac OS X client — From the Finder bar, go To, Connect to server. The URL of the nettalk shared directory. For example, for the home directory on the computer named toys for the user named chris, you could type the following:

```
afp://toys/chris
```

If you can’t find and open the nettalk service from your Mac, see the “Troubleshooting netatalk” section in this chapter for some suggestions.
