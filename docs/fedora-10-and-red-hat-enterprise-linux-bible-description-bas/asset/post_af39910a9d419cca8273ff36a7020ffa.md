# Printer Sharing

You can print sharing using netatalk so that Macs using the standard AppleTalk print service (called Printer Access Protocol, or PAP) can print to your Linux computer. To do that, you must:

- Configure a local Linux printer (see Chapter 17).
- Set up the /etc/atalk/papd.conf file to point to that printer.
- Restart the netalk service (or, more specifically, the papd daemon).

When a client prints to a Linux configured in this way, the job is handled by the standard Netalk lpd daemon and put into a spool file for printing, with Apple Linux print jobs for the printer.

> NOTE: Mac OS X computers can print directly to Linux print services (CUPS or LPRng) without requiring netalk printing. Older Mac OS 9 clients however, might need to see an AppleTalk printer that you set up in this way with netatalk.

The papd.conf file follows the same basic format as the /etc/printcap file (traditionally used for printing). Here's an example of a configured in the papd.conf file:

```
LaserJet2100M:
pr=:usr/bin/lpr -P hp01:
ppd=/etc/atalk/laserjet.ppd:
oproot=\name:uams_quest.so.
```

The printer in this example is named LaserJet2100M. To print the file from the Mac client, it takes the output and pipes it to the lpr -P hp01 command (hp01 is the name of the local printer). The ppd file is /etc/atalk/laserjet.ppd. The root user is the operator, and guests are allowed to the printer (no password is needed).

The printer definition file (ppd) must be installed on both the netatalk server (at the location noted in the papd.conf file) and on the Mac client.

To test that the interface to the AppleTalk printer is working, use the pap command:

# pap -p LaserJet2100M /etc/hosts
```

The -p option identifies your netprint printer. In this example, it prints a copy of /etc/hosts file. Or, you can just check the status of the printer:

# Troubleshooting netatalk

Several tools are available that enable you to see the status of your AppleTalk Network. The aecho command can test whether a particular AppleTalk host computer is alive. The nbplkup command can be used to check the services that are active on your AppleTalk network.

> NOTE: In general, AppleTalk should be used on trusted networks. If you are running a firewall on your netatalk server, you must open access to several ports for netatalk to work. In particular, you may need to open ports 548 (AFP over TCP/IP), 201 (AppleTalk routing), 202 (AppleTalk binding), 204 (Apple echo), and 206 (Apple zones).

Use the aecho command (similar to the TCP/IP ping command) to check whether an AppleTalk host is alive. The aecho command sends an Apple Protocol (aep) packet to the host you want to check. Here is an example:

```
# aecho toys
14 bytes from 65280.115: aep_seq=0, time=0, ms
14 bytes from 65280.115: aep_seq=1, time=0, ms

----65280.115 AEP Statistics----
2 packets sent, 2 packets received, 0% packet loss
round-trip (ms) min/avg/max = 0/0/0
```

If the Apple server is up and running, you can use the nbplkup to see what printers and volumes are currently available. For large networks, you can limit the output of nbplkup by adding a name or printer name (such as :hpjet), or by entering a host name (for example, toys).

```
# nbplkup :AFPServer
duck:AFPServer 65280.115:130
User Volume:AFPServer 65280.21:129
Guest Volume:AFPServer 65280.21:130
```

By querying :AFPServer, nbplkup listed all AppleTalk files on the local network. The first one is shown from the host named duck. The second and third line are from the same computer (at address 65280.21), but were registered as separate servers.

# Accessing NFS from Mac

For years, Network File System (NFS) was the preferred method for sharing files among computer systems. The Mac OS X Connect to Server allows directories as though they existed on your Mac. If you don't have access to the server server, you need to to ask the server manually. (I describe the manual procedure at the end of this section.)

# Connecting to NFS from Mac

To create an NFS shared directory in Linux and connect to it, do the following:

On the Linux server, export a shared directory as described in Chapter 18. To be able to use the shared directory Mac OS X, however, you must be sure to add the insecure option. For example, share the /var/music directory from the Linux server named jukebox.linuxtoys.net, you can add the following line to the /exports/::``````/var//    *(ro,insecure)
```

This example allows the /var/music directory to be shared with all computers (*) and provides read only permission. The insecure option allows clients that the exported directory make the request from an insecure port (ports 1024). This is important because the Mac OS Connect to Server window makes its request to mount the shared directory from a port above 1024.

On the Linux server, verify that the NFS service is running and re-export the shared directory by typing the following (as root):

```
# exports -a
```

On the Mac OS X client, Go to the Finder bar at the top of the screen, and select Connect to Server. The Connect to Server window appears.

 the Mac OS X client, type the address of the shared directory into the Address box. For example, connect to the shared nfs:// directory /var/music from the computer named jukebox.linuxtoys.net, you can type the address nfs://jukebox.linuxtoys.net/var/music (see Figure 26-5).

If everything is working properly, an icon representing the server should appear on your Mac OS X desktop. Depending on which version of Mac OS X you are using, a window might just pop open, displaying the contents of the directory or you may need to open it to see the contents of the shared directory. You can use the shared files and directories as though they existed on the Mac
