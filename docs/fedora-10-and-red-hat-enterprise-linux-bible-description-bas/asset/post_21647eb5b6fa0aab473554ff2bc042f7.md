## Using du to check disk use

You can discover the most voracious consumers of disk space using the du command. Invoke du with the -s option to give a list of directories; it reports the total disk space used by all the files in each directory. Add an -h option to display disk space used in numbers, followed by kilobytes (K), megabytes (M), or gigabytes (G). The -c option adds a total of all requested directories at the end. The following checks use usage for several home directories:

```bash
# du -hcs /home/tom /home/bill /home/tina /home/sally
```

This would result in a list of all of your users home directories preceded by the number of kilobytes (K), megabytes (M), or gigabytes (G) that each directory structure uses. It looks like this:

| 339M | /home/tom |
| 81M | /home/bill |
| 31M | /home/tina |
| 44K | /home/sally |
| 1.45G | total |

## Removing temp files automatically

Some potential disk-consumption problems are set up to take care of themselves. For example, directories for storing temporary files used by applications (such as /tmp and /var/tmp) can consume lots of disk space over time. To deal with the problem, Fedora and RHEL include the tmpwatch facility. The tmpwatch command runs from the cron file /etc/cron.daily/tmpwatch to delete unused temporary files. Here's what that file contains:

```bash
flags=-umc
usr/bin/tmpwatch "$flags" -x /tmp/X11-unix -x /tmp/.XIM-unix \
-x /tmp/.Test-unix 100d /tmp \
-x /tmp/.Test
usr/bin/tmpwatch "$flags" 30d /var/tmp
usr/bin/tmpwatch 720 /var/tmp
for d in /var/{cache/man,cat){7,R11R,local,cat}; do
if [ -d "$d" ]; then
usr/bin/tmpwatch "$flags" -f 30d $d
fi
done
```

Each day, the tmpwatch script runs to delete temporary files that haven't been used for some time. The flags (-umc) indicate that access is based on the access time (u), modification time (m), and inode change time (c). It starts by identifying files that are not to be deleted tmpwatch -x. Files as those in the /tmp/.X11 directory represent sockets for active servers and would make an active GUI unusable. All other files from the /tmp and /var/tmp directories are removed after 10 and 30 days of not being accessed, respectively. Temporary man pages stored in /var/cache subdirectories are also checked and deleted after 30 days of disuse.

## Sending Mail to All Users

Occasionally, you need to send messages to all users on your system. Warning users of planned downtime for hardware upgrades is a good example. Sending e-mail to each user individually is extremely consuming and wasteful; this is precisely the kind of task that aliases and mailing lists were invented for. Keeping a mailing list of all the users on your system can be problematic, however. If you are not diligent about keeping the mailing list current, as you add and delete users. Also, if your system has many users, the size of the alias list can become unruly.

The following script, mailfile, provides a simple method of working around these problems. It gets the login names from /etc/passwd file and sends e-mail to all users.

> NOTE: Because user accounts begin with UID 500 in Fedora and RHEL systems, the script excludes UIDs under 500 (which are typically administrative accounts). It also skips UID 65534, which is the anonymous NFS user account.

```bash
#!/bin/bash
# mailfile: This script maps the named file to all regular
# users of the system. It skips all administrative
# accounts (under UID 500) as well as the
# anonymous NFS user (UID 65534).
# USAGE "Subject goes here" filename.txt
# Check for a subject
# Get the subject of the message
subject=$1

# Check for a filename
filename=$2

# Loop through all login names, skipping accounts under 500
# as well as the anonymous NFS account (65534)

for x in $(cut -d ":" -f 1,3 /etc/passwd)
do
  USER=$(echo $x | cut -d ":" -f1)
  ID=$(echo $x | cut -d ":" -f2)
  if [[ $ID -gt 499 && $ID -lt 65534 ]]; then
  # Mail the file
  echo "Mailing to $USER"
  mail -s "$subject" $USER < $filename

  # Sleep for a few seconds so we don't overload the mailer
  # On fast systems or systems with few accounts, you can
  # probably take this delay out.
  sleep 2
  fi
done
```

The script accepts two parameters. The first is the subject of the e-mail message, which is enclosed in quotes. The second is the name of the file containing the text message to.

> TIP: If your system has a message to display when users log in, you can use the /etc/motd file. This file is displayed to every user when they log in. The message can be anything, but to make it more interesting, you can use the figlet program to format the message.

```bash
# Example of a motd message
echo "Welcome to the Fedora Server" | figlet > /etc/motd
```
