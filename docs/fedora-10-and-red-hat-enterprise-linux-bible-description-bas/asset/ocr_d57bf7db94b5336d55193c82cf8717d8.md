# Supplying an initial .tcshrc file
The example .tcshrc file does basically the same thing as the preceding
.bashrc example. However, this file (which is for the root user) has the additional task of
setting the appearance of the command prompt:

```
# .tcshrc

# User specific aliases and functions
nalias rm 'rm -i'
alias cp 'cp -i'
alias mv 'mv -i'

setenv PATH "$PATH:/usr/bin:/usr/local/bin"

set prompt='%n@%m %c#'
```

Instead of using the export command to set environment variables, the tcsh uses the
setenv command. In the shell, setenv is used to set the PATH variable. The shell
prom is set to include your name (%n), your name (%m), and the name of the
current directory (%c). So, if you were to use the tcsh shell as the root user on a computer
named maple /tmp/ your current directory, your prompt would appear as follows:

```
[root@maple ~#]
```

The .tcshrc file can also be known as .cshrc. The tcsh shell is really an extended version
of the csh (in fact, you can invoke it by the csh name). When a tcsh shell is started, it
first looks for a .tcshrc file in the current user's directory. If it can't find a file by
name, it looks for the other name, .cshrc. Thus, either is appropriate.

# Configuring system-wide bash options
Allowing individually customizable shell files for each user is a very flexible and
useful practice. But you sometimes need more centralized control than that. You may have an
environment variable or shell setting that you want set for every user, without exception.
If you add that to each individual shell, the user has the ability to edit that file and
remove it. Furthermore, if setting must be changed in the future, you must change it in
very single user's shell startup file.

# Configuring system-wide bash options
Fortunately, there is a better way. There are default startup files that apply to all of the users
computer that each command shell reads before the user-specific files. In the case of
the bash command shell, it reads the /etc/bashrc file before doing anything.
