## Firewall open?

If the Samba server is running, it should begin broadcasting its availability on your LAN. If you try to access the server from a Windows or Linux client, but get a Connection refused error, the problem may be that the firewall on your Linux Samba is denying access to the NetBIOS service. If you have a secure LAN, you can type the following (as root user) to flush your firewall rules temporarily:

```bash
# iptables -F
```

Then, try to connect to the Samba Server from a Windows or Linux client. If you find you can connect to the server, turn the firewall back on:

```bash
# service iptables restart
```

## User passwords working?

Try accessing a shared Samba directory as a particular user (from the local host or other Linux system on your LAN). You can use the smclient command to do this. Here's an example:

```bash
# smclient //localhost/home/chris/files -U chris
added interface ip=10.0.0.1 bcast=10.0.0.255 mask=255.255.255.0
Password: ********
Domain=[ESTREE] Server=[Samba 3.2.4]
smb:\>
```

In this example, smclient connects to the directory named tmp as the Samba user chris. If the password is accepted, you should see information about the server and a smb:\> If you cannot access the shared directory from a Windows client, it's possible that the client is using an improper user name and password. Part of the problem may be that the Windows client is not providing encrypted passwords.

For Windows clients, using encrypted passwords requires that you change a Windows registry for the machine. One way to change the registry is with the Windowsedit command. Registry changes required for different systems are contained within the /usr/share/doc/samba-*/docs/registry directory.

> TIP: The smclient command, used to list server information and test passwords, can also be used to browse the shared directory and copy files after you are connected. After you see the smb:\> prompt, type help to see the available commands. The interface is similar to any ftp client, such as sftp.

## Summary

By providing centralized file services, an organization can efficiently share information and applications with people within the organization, with customers, or with anyone around the world. Different technologies are available in Fedora and RHEL to enable you to make your Linux file server.

The Network File System (NFS) protocol was one of the first file server technologies available. It is particularly suited for sharing file systems among Fedora, RHEL, and UNIX systems. NFS uses standard mount and umount commands to connect file systems to the directory structures of client computers.

The Samba software package that comes with Fedora and RHEL contains protocols and utilities for sharing files and printers among Windows and OS/2 operating systems. It uses SMB protocols that are included with Microsoft Windows systems, and therefore provide a convenient method of sharing resources on LANs containing many Windows systems.

## Introducing SMTP and sendmail

With multimedia attachments and HTML encoding prevalent in e-mails today, the technology behind message hasn't changed since the early 80s. The framework for Simple Mail Transfer Protocol (SMTP) was initially described in RFC 821 in 1982. The protocol itself was extended in 1993 (RFC 1425), yielding the Extended Mail Transfer Protocol (ESMTP).

The three parts to transfer message are the Mail Transfer Agent (MTA), the Mail Delivery Agent (MDA), and the Mail User Agent (MUA). The MTA, commonly referred to as the server (of which postfix are examples), actually handles outgoing mail and listening for incoming mail from the Internet. The MTA accepts messages and copies them into a user's mailbox. Other MDAs (also referred to as LDAs) include Maildrop.

End users, for whom the mail is ultimately intended, use MUAs to get mail from the server and read it from their desktops. Most MUAs support Internet Mail Access Protocol (IMAP4) for getting mail from the server so it can be read and managed from their desktop. When possible, you should use the Secure POP and IMAP protocols (pops and imaps, respectively).

> CROSS-REFERENCE: See Chapter 9 for details on Mail User Agents available with Fedora.

This chapter focuses on sendmail MTA, the most common server on the Internet. Nearly 70 percent of all e-mail messages on the Internet are delivered by sendmail. With the growing Internet population, billions of e-mail messages are sent and received each day. As an alternative to sendmail, this chapter also includes a short description of postfix.

For getting mail from the server, this chapter describes the dovecot software package, which includes POP and IMAPv4 server. For an alternative, allowing users to read and manage e-mail from a web browser, this chapter describes how to configure SquirrelMail.

The original (version 5) was written in 1983 by Eric Allison, a student at the University of California at Berkeley. Eric Allison returned to Berkeley in 1991 and embarked on a major code revision, releasing sendmail V8 in 1993, which incorporated the extensions to IDA sendmail.
