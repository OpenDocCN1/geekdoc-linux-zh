## Host-level security

You can restrict which computers on your network have access to netatalk services using the /etc/hosts.allow and /etc/hosts.deny files. These files are described in the "Using Tcp wrappers" section of Chapter 14. These are the same files you use to allow or restrict access to other Linux networking services.

The following is an example of an entry the hosts.allow file.

```
ALL: .linxtoys EXCEPT abc.linxtoys.com
```

This example allows access to netatalk (and all other services) from computers abc.linxtoys.com domain except. See Chapter 14 for details about other ways to indicate services (instead of ALL) and hosts.

## File and directory-level security

Netatalk creates hidden files and directories to handle Mac features that are not in Linux. Understanding those files and directories working with standard Linux ownership and permissions are the best ways to refine access to AppleTalk volumes you share.

## Understanding Mac files and directories

Netatalk creates special files and directories that you can't see from the Finder. Because these files begin with a dot (.), they are hidden from normal directory listings (ls) in Linux as well. The following descriptions should help you understand these files and directories.

> NOTE: To see hidden files from a folder window (from the GNOME desktop), click Edit -> Preferences. Then the Views tab, select the "Show hidden and backup files" checkbox. Use ls -a to see them from a terminal window.

- .AppleDouble—Every directory within your shared AppleTalk (netatalk) volume contains a .AppleDouble directory. This directory is created automatically as soon as you create a file or directory from a Mac client on the netatalk server. Within this directory are separate files representing attributes of each file in the associated directory. For example, creating a text file in /var/projects/mytext.txt would create a file called /var/projects/.AppleDouble/mytext.txt that contained attributes about that file.

You can create an Icon directory within any .AppleDouble for a shared volume (/var/projects/.AppleDouble/Icon for example), enabling you to add custom icons to the shared volume. Permissions of those directories must be writing (for anyone you want to be able to add and change icons), and reading (to anyone you want to see icons).

- **AppleDouble.Parent** — This directory within .AppleDouble contains information about the shared directory.
- **AppleDesktop** — For each shared volume, this directory is located in the top-level directory. This contains information about the applications that created the data stored on the volumes and the icons used to represent that data.
- **Network Trash Folder** — This folder, in the top-level shared directory, has deleted files from the client (Note: spaces in the directory name to access the folder from the Linux shell).
- **Temporary Items** — Some applications need this folder (located in the top-level directory) to create temporary files. Other directories may also appear because applications work on files in the volume special directories.

## Setting file and directory permissions

Permissions on shared volumes tend to be wider open than would typically be the case on Linux directories. In particular, the set-GID bit is often on for directories. By using the set-GID feature, any file or directory created will be owned by the associated group. For example, follow these steps as root (creating any directory):

```
# mkdir /var/projects
chown chris /var/projects
chgrp toygroup /var/projects
chmod 775 /var/projects
ls -ld /var/projects
drwxr-xr-x 2 chris 4096 Mar 16 13:32 /var/projects
```

In this example, I prepared a directory to be shared called /var/projects. I made the owner of the directory (use your name), created a group (see Chapter 11 for creating groups) and called it toygroup. Then I set the permission to 775 on the directory, which means that the set-GID bit is on, the owner (chris) has full read/write/execute permission (7), the group (toygroup) has full read/write/execute permission (7), and other have only read and execute permissions (5).

Turning the set-GID bit causes all files and directories created in /var/projects (and its subdirectories) to be assigned to the toygroup group, regardless of the member who created it. Because I set group permissions to (7), anything created in /var/projects and its subdirectories will be under the complete control of anyone assigned to toygroup. This is a nice technique for sharing files in projects.

After the top-level directory is created, netatalk creates the files and directories it needs (such as .AppleDouble and Network Trash Folder) as the Mac clients add files and folders. Netatalk should also propagate the correct permissions to those items.

Here are some tips about setting permissions:

- A user must have write permission to the .AppleDesktop directory (and subdirectories) to create an application in a shared directory.
- Make the Network Trash Folder writable by everyone who has access to the shared volume or their files will be prematurely deleted.
- Open permissions to the Temporary Items directory or applications (such as Photoshop) will fail to work with files.
- Turn off write permissions to programs (executable files) to protect them from being exploited.

## Setting Apple file and folder type creator

To check and create attributes on Mac files, use the afile command as follows:

```
$ afile
```

In this form, you can see attributes for files and directories of known types. To see all files (even without associated attributes stored in the .AppleDouble directory), use the -a option with afile.

Use the afile command to change the type (-t) and creator (-c) of the Macintosh file. Creator and file type pairs are defined in the /etc/atalk/AppleVolumes.system file. You can change these to create different applications to be used for selected file types.

## Moving, copying, and deleting netatalk files

When you access files on your netatalk volume from a Mac client computer, file attributes are maintained or preserved. Linux commands don't deal with Mac attributes, however, so you need to run special commands from Linux to move these files and maintain their attributes, instead of the regular Linux commands (mv, cp, rm, and so on).

> NOTE: Before you use the apple_cp and related commands to add files to your Apple volume, open the volume from a Mac client and create a file. This will cause the appropriate directories and files (.AppleDouble and so on) to be created so they are available to add attributes from Linux apple_* commands.

The commands for copying, moving, and removing files from a shell in Linux on your netatalk server volumes are apple_cp, apple_mv, and apple_rm. For example:

```
# apple_cp memol.doc /var/projects/memos/
```

This command copied my memol.doc file from my current directory to the /var/projects/memos/ (presumably on the same netatalk volume). This action also copies the resources associated with the file to the .AppleDouble directory where you are moving. Here are examples of move and remove commands:

```
# apple_mv memol.doc /var/projects/memos/oldmemos/
# apple_rm memol.doc
```

The apple_mv moves the memol.doc file from the current directory to the oldmemos (moving attribute information from .Apple to the new .AppleDouble directory). The apple_rm command deletes memol.doc and removes its attribute information.

## Sharing files with netalak and Samba

A common practice if you have both Mac and Windows clients on the same network that need to share files is to have both Samba and netalak configured to share the same volume (that is, set of directories). Before you do that, be aware of the following:

- By default, creating files from Mac clients (on netalak volumes) will make the files easiest to work with the Mac.
- You can hide files from Mac users with the veto option in AppleVolumes.default.
- The veto option for Samba (in smb.conf) can be used to hide Mac files (such as .AppleDouble directories) from Samba users.
- If you don't, you can set the noouble option in AppleVolumes.default to create files without them.
- Avoiding certain characters in your file and directory names can make it easier for you to share items among different types of clients. When possible, avoid characters as slash (/), backslash (\) and colon (:) when naming files. Also, wildcard characters as asterisks (*) and pound signs (#) can cause problems.

Here’s an example of a veto file you might want to add to /etc/samba/smb.conf It prevents Samba users from accessing hidden netalak-specific directories:

```
veto files = /.AppleDouble/Desktop/Network Trash
Folder/TheVolume/SettingsFolder
```
