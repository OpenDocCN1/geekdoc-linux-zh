- /etc/init.d/iptables — This is the iptables start-up script that must run automatically each time Fedora reboots. When it starts, it clears all iptables rules and counters and installs the new rules from the /etc/sysconfig/iptables file. You can also use this with different options from the command line to check the status of iptables (status) or to run iptables-save to save the current rules (save).

You get started with iptables, I'm providing a sample set of iptables rules along with descriptions of how you might change those rules for different situations. Here's how you could load and save any of the sets described in the following example:

1. Stop iptables and clear all existing rules:
   `# /etc/init.d/iptables stop`

2. Add the rules in the following example to a file, using any text editor. Modify the rules to suit your situation and save the file.

3. As root user, run the file as a shell script. For example, if you named the file firescript, you could run it as follows:
   `# sh firescript`

4. See how the rules were loaded into the kernel:
   `# iptables -L`

5. If everything looks okay, save the rules that are now in the kernel into the /etc/sysconfig/iptables file:
   `# cp /etc/sysconfig/iptables /etc/sysconfig/iptables-old`
   `# service iptables save`

6. Start iptables:
   `# /etc/init.d/iptables start`

From now on, the rules will be read each time you reboot or restart iptables. Save a copy of the script you used to create the rules, in case you need it again.

## Example 1: Firewall for shared Internet connection (plus servers)

Because firewall configurations can be vastly different on what you are trying to achieve, I've illustrated how to configure firewalls based on several different example setups. These setups combine different levels of security requirements.

This example features a home- or small-office LAN with a Fedora system acting as an iptables firewall between the LAN and the Internet. The firewall computer also acts as a Web server, FTP server, and DNS server. Figure 14-2 shows this configuration.

**Figure 14-2**: Using iptables as a firewall between the Internet and LAN

If you want to use the sample firewall script that follows, you must change the following information to match your configuration:

**Firewall computer** — The firewall is set up as follows:

- **Local host — 127.0.0.1** (IP address) and lo (interface). You shouldn’t need to change these.
- **Connection to the Internet — 123.45.67.89** (IP address) and eth0 (interface). Replace them with the static IP address and interface name associated with your connection to the Internet, respectively.
- **Connection to the LAN — 10.0.0.1** (IP address) and eth1 (interface). Replace 10.0.0.1 and eth1 with the static IP address and interface name associated with your connection to your LAN, respectively.
- **Computers on the LAN** — Each computer on the LAN has an IP address from 10.0.0.2 to 10.0.0.25. Change 10.0.0.25 to a number that matches your LAN’s range of addresses.

Here is an example of a script to load firewall rules that could be used for the configuration shown in Figure 14-2:

```bash
# (1) Policies (default)
iptables -P INPUT DROP
iptables -P OUTPUT DROP
iptables -P FORWARD DROP

# (2) User-defined chain for ACCEPTed TCP packets
iptables -N okay
```

```bash
iptables -A okay -p TCP --syn -j ACCEPT
iptables -A okay -p TCP -m state --state ESTABLISHED,RELATED -j ACCEPT
iptables -A okay -p TCP -j DROP
```

### (3) INPUT chain packets from LAN

```bash
# Rules for incoming
iptables -A INPUT -p ALL -i eth0 -s 10.0.0.0/24 -j ACCEPT
iptables -A INPUT -p ALL -lo -s 127.0.0.1 -j ACCEPT
iptables -A INPUT -p ALL -lo -s 10.0.0.1 -j ACCEPT
iptables -A INPUT -p ALL -lo -s 123.45.67.89 -j ACCEPT
iptables -A INPUT -p ALL -i eth0 -d 10.0.0.255 -j ACCEPT
```

### Rules for incoming packets from the Internet

```bash
# Packets for established connections
iptables -A INPUT -p ALL -d 123.45.67.89 -m state --state \
ESTABLISHED,RELATED -j ACCEPT
```

### TCP rules

```bash
iptables -A INPUT -p TCP -i eth0 --destination-port 21 -j okay
iptables -A INPUT -p TCP -i eth0 --destination-port 22 -j okay
iptables -A INPUT -p TCP -i eth0 --destination-port 80 -j ACCEPT
```

### UDP rules

```bash
iptables -A INPUT -p UDP -i eth0 --destination-port 53 -j ACCEPT
```

### ICMP rules

```bash
iptables -A INPUT -p ICMP -i eth0 --icmp-type 8 -j ACCEPT
iptables -A INPUT -p ICMP -i eth0 --icmp-type 11 -j ACCEPT
```

### (4) FORWARD chain rules

```bash
# Allow established connections
iptables -A FORWARD -p ALL -m state --state \
ESTABLISHED,RELATED -j ACCEPT
```

### (5) OUTPUT rules

```bash
# Allow local traffic
iptables -A OUTPUT -p ALL -s 127.0.0.1 -j ACCEPT
```

### (6) POSTROUTING rules

```bash
# NAT masquerading
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
```

I divided the commands in the preceding script into six sections. The following text describes each of those.

**(1) Policies** — The iptables -P sets the default policies for INPUT, OUTPUT, and FORWARD. By assigning each of these to DROP, any packet that isn't matched is discarded.

**(2) User-defined chain** — A user-defined chain I call *okay* is created to do a few more. The next line says that a SYN packet (--syn), requests a new connection, is fine to. The next line allows packets associated with an ESTABLISHED connection (which has already passed to the interface) or a RELATED connection (which is starting a new connection for an existing one).

**(3) INPUT chain rules** — The bulk of the packet filtering is done in the INPUT chain. The first set of input rules identifies iptables to always accept packets from the Internet and the LAN. The next three determine which requests for specific protocols (TCP, UDP, and ICMP) are accepted:

- **Packets from LAN**: Because you want to use the Internet, this set of rules lets through packets that are initiated from your computer. The first line tells iptables to accept packets for all protocols for which the source is an acceptable address (-s 10.0.0.0/24, which represents IP numbers 10.0.0.1 through 10.0.0.254). The next three lines allow packets that come from all valid IP addresses on the firewall computer (-s 127.0.0.1,10.0.0.1 and 123.45.67.89). The last line accepts packets (-d 10.0.0.255).
- **Packets from Internet (already connected)**: This is split in two (I just used the backlash since the page isn't wide enough to show it as one line). It ACCEPTs packets that are associated with connections that are already established(--state ESTABLISHED,RELATED) and are requested directly to the firewall's IP address (123.45.67.89).
- **TCP rules (new connections)**: Here is where you open the ports for the TCP services you want to provide to anyone from the Internet. In these lines you open ports for FTP service (--destination-port 21), secure shell service (22). Web service (80), and IDENT authentication (113), the last of which might be necessary for protocols such as IRC. Instead of accepting these requests receives immediately, you jump to the *okay* chain until you further check that the packets were formed properly.
- **UDP rules**: iptables -A INPUT -p UDP -i eth0 --destination-port 53 -j ACCEPT.
- **ICMP rules**: iptables -A INPUT -p ICMP -i eth0 --icmp-type 8 -j ACCEPT. iptables -A INPUT -p ICMP -i eth0 --icmp-type 11 -j ACCEPT.

**(4) FORWARD chain rules** — Allow established connections
iptables -A FORWARD -p ALL -m state --state \
ESTABLISHED,RELATED -j ACCEPT.

**(5) OUTPUT rules** — Allow local traffic
iptables -A OUTPUT -p ALL -s 127.0.0.1 -j ACCEPT.

**(6) POSTROUTING rules** — NAT masquerading
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE.

> CAUTION: You want to ensure that the services on the ports which you are allowing access are properly configured before you allow packets to be to them.
