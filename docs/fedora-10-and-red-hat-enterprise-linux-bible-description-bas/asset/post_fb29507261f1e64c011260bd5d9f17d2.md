The amdump command is the one that you will use the most, but before you get started, you need to configure a few things on the backup server (the system with the tape drive) and the backup clients (the systems being backed up). On Amanda clients, you need to install the amanda package. On the Amanda server, you need to install the amanda-server package as well.

## Creating amanda directories

You need to create some directories to hold the Amanda configuration files and provide a location to write Amanda log files. The configuration files go in `/etc/amanda directory, and the log files go in to disk. In both cases, you should log in as the amanda user and create subdirectories within these directories, one subdirectory for each backup schedule that you need to run and an index file, as shown in the following example.

> NOTE: For security reasons, you should do all amanda administration as the amanda user. To do this, the root user can create a password for amanda by typing `passwd amanda` and entering the new password. A better alternative, however, might be to log the amanda user account, and then simply type `su amanda` (in the following example) to do amanda tasks as the root user without an extra password. The rest of the procedure assumes that you are logged in as the amanda user.

```
# su amanda
# mkdir -p /var/lib/amanda/normal/index
# mkdir -p /etc/amanda/normal
```

For the purpose of this example, I have created only one normal backup configuration that backs up the data on several machines. You may also decide to upgrade backup configuration that backs up the operating system partitions. You could then run them before you perform any system upgrades.

You also need to specify a holding disk that Amanda can use to spool backups temporarily before it writes to disk. This directory should have a lot of free space. I have a large `/home` partition on my server, so I created an amanda directory to use as a holding disk:

### Part III: Admining RHEL
# mkdir /home/amanda
# chmod 700 /home/amanda
# chown amanda /home/amanda
# chgrp disk /home/amanda
```

## Creating amanda.conf file

Next, as the amanda user, you must create two configuration files for Amanda and store them in the /etc/amanda/normal directory: amanda.conf and disklist. You can start by copying samples of these files from the /etc/amanda/DailySet1 directory:

```
$ cd /etc/amanda/DailySet1
$ cp amanda disklist /etc/amanda/normal
```

The amanda.conf file defines a set of general values, and disklist defines machines and partitions to back up. The amanda.conf file can be rather complicated, but fortunately most of its values can be left at their default. Here is a simplified amanda.conf with some comments embedded in it to help explain:

```
# amanda.conf - sample amanda configuration file. This started as the actual config file at CS.EDU.

org "ACL" # your organization name for reports
mailto "amanda" # list of operators at your site
dumpuser "amanda" # the user to run dumps

# Specify tape device and tape changer. If you don't have a tape changer, and don't want to use more than one tape per run of amdump, just comment out the definition of:
untapes 1 # number of tapes used in a single run of amdump
tapedev "/dev/st0" # tape device to be used
rawtape "/dev/nst0" # raw device to be used (only)

type HF-DAT # kind of tape it is (see types below)
label "normal[0-9]*" # label constraint must match

# Specify holding disks. These are used as a temporary staging area for dumps before they are written to tape and are recommended for most sites.
holdingdisk main {
  comment "main holding disk"
  directory "/home/amanda" # where the holding disk is
  use 290 Mb # how much space we can use on it
chunksize -1 # size of chunk
}

# Note that although the keyword below is outfile, it is only for historic reasons, since now it is supposed to be a directory (unless you have selected some database format other than 'text' default)
infile "/var/lib/amanda/normal/currentinfo" # database
logdir "/var/lib/amanda/normal" # log directory
indexdir "/var/lib/amanda/normal/index" # index directory

# types
# Define the type of tape you use here, and use it in "type" above. Some typical types of tapes are included here. type amanda how many MB will fit on the tape, how big the filemarks are, and how fast the tape device is.

type HF-DAT {
  comment "DAT drives"
  # data provided by Rob Browning <rlb@cs.texas.edu>
  length 1930 mbytes
  filemarker 111 kbytes
  speed 468 kbytes
}

# dumps
# These are referred to by the disklist file.

dump global {
  comment "Global definitions"
  # This is quite useful for setting global parameters, so you don't have to type them everywhere.
}

dump all-full {
  global
  comment "Full dump of this filesystem always"
  compress none
  priority high
  dumpcycle 0
}
```

This example amanda.conf file was trimmed down from a larger example I copied from /etc/amanda/DailySet1. The example amanda.conf provides additional information on the available configuration options. Also, the online man page for Amanda should be helpful (type man amanda to read it). You can find more instructions in the /usr/share/doc/amanda-server/ directory. Generally, you have to do the following:

- Modify the org name for reports.
- Change the device names set for tapedev and rawtape to match your tape device.
- Select a tape type entry that is appropriate for your tape drive.
- Change the name of the directory specified in the holding disk section to match the directory you created earlier.

## Creating a disklist file

You also must create a disklist file in the /etc/amanda/normal directory. This simply contains a list of disks and partitions to back up. The qualifier all-full is included on each entry to tell Amanda what kind of backup to perform. It means to use full, rather than incremental, backups.

```
# sample Amanda2 disklist file
#
# File format is:
#
  hostname diskdev dumptype [spindle][interface]
#
# where the dumptypes are defined by you in amanda.conf.

dexter sda5 all-full
```

This example backs up the systems and partitions. This way back up the most important data.

## Adding Amanda services

Amanda is designed to perform backups over a network. The following services are defined in /etc/services:

```
amanda      1080/udp
amanda      1080/tcp
amanda      1082/tcp
amanda      1083/tcp
```

## On the amanda server

To offer these services to the network, you need to configure the initedd daemon. You do this by enabling the amanda and amdump services by typing the following (as the root user):

```
# chkconfig amanda
# chkconfig amdump
```

This enables amanda to accept requests from the client. You need to tell the initedd daemon to reload the /etc/services file before this change takes effect. Do this by typing the following:

```
# /init.d/xnetwork
```

## On each amanda client

Next you need to configure the .amandosts file in /var/lib/amanda directory on each computer (client) that the amanda server will back up. This file should contain the fully qualified name of backup servers that will connect to this client. When you begin, localhost is defined in this file as your backup server. To add another computer as a backup server, type the following (replacing amanda with the name of the backup server, which is logged in as the amanda user):

```
$ echo amanda >> /var/lib/amanda/.amandosts
```

You also need to make sure that the amanda daemon is configured to run on the client. You do this by enabling the amanda service by typing the following (as the root user):

```
# chkconfig amanda
```

This enables the amanda client to communicate with the amanda server. You need to tell the initedd daemon to reload the /etc/services file before this change takes effect. Do this by typing the following:

```
# /init.d/xnetwork
```
