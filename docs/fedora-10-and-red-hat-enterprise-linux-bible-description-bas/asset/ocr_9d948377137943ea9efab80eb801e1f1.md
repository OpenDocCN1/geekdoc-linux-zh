# Redirecting mail

At times, your e-mail users may want to redirect mail to some place other than their own mailboxes on the local server. Each user can redirect his or her mail using the .forward file. System-wide, as the administrator can set aliases to redirect mail in the /etc/aliases file.

#  .forward file

One way for users to redirect their mail is through the use of the .forward file, which users can place in their own home directories (for example, /home/jkpat/.forward). The format of a plain-text .forward file is a comma-separated list of mail recipients. Common uses of .forward file include:

+   - Piping a mail to filter the mail box contents:
"/usr/bin/procmacail"

+   - Sending mail destined for one user (for example, jkpat) to another (for example, cht09, on a different machine in this):
cht09@other.mbox.com

+   - Delivering mail to the local user (jkpat again) and sending it to two others (cht09 and brannigan):
\jkpat, cht09@other.mbox.com, \brannigan

> TIP: You are not allowed to have a .forward file in a directory that can be read by all users. If you leave permissions on a .forward file, sendmail will ignore it and not forward mail as you want. To use .forward files with permissions to be used by sendmail, you can use the dnl from the CONF_BLAME_SENDMAIL line in the sendmail.mc file.

# The aliases file

A more flexible method of handling mail delivery (system-wide rather than being specific to one particular user) involves the /etc/aliases file, which is also a plain-text file. The aliases file contains a name followed by a colon, and a user name, another alias, a list of addresses, a file, or a program to be mailed to. The name to the left of the colon (which can be a valid user name or just an alias) can then be used as an e-mail recipient on the local machine or on a remote machine.
