# Part IV: Fedora RHEL Network and Server Setup

+   **You can end up on blacklists.** Some e-mail blacklist maintainers look for open relays themselves and block them before abuse is reported. Servers that use those blacklists will block all from you, even legitimate e-mail.

+   **People will hate you.** Your mail server will be identified as the one sending spam. As a result, people may retaliate against your server, or at the very least wish you stop sending them ads to help them get out of debt or enhance their in in some way.

+   **You face possible fines and jail.** More and more laws are being written to try to stop the spread of spam. You could be found guilty of negligence, or have your machines shut down or confiscated, even if you didn't initiate the spam yourself.

This describes how to set up the access file (`etc/mail/access`) to include a set of rules defining for whom your server will relay mail. Using the access file, sendmail can make decisions about whether or not relay a message based on the sender's host/domain name, IP address, or e-mail address. You can further refine the method by checking for these addresses in Connect, From, or To data associated with the message.

There are four actions you the server can take on a match:

+   **RELAY** — Your mail server could simply send the message to the mail server requested in the mail message.
**REJECT** — The message is rejected (not relayed) and the sender is told so.
**DISCARD** — The message is silently discarded and the sender is not told.
**ERROR: text you choose** — You can add some informative text here, to give the sender some reason why the relay did not occur.

The `/etc/mail/access` file, by default, relays messages only from users who are directly logged into the mail server (localhost). Without explicitly opting, users from all other machines are not allowed to relay messages. Here's how the access file is set up by default:

| localhost.localdomain | RELAY |
| localhost | RELAY |
| 127.0.0.1 | RELAY |

With these defaults, only mail sent from the local machine is relayed. So, if the outgoing mail you send is done while you are logged in the server, you don't need to change this file. The following examples illustrate how you selectively choose to relay or reject mail by your sendmail server:

```
Connect:192.168 | RELAY
Connect:linuxtoys.net | RELAY
Connect:spammer-domain.com | REJECT
```

```
From:chris@linuxtoys.net | RELAY
```
