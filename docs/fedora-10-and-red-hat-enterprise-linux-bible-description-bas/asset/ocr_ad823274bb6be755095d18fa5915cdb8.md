# Keeping up with updates

You can expect to find and correct security issues continuously. You must keep up with software updates that are published to plug security holes. Some of these updates address theoretical security problems, others are in response to real break-ins or denial-of-service attacks that are known to exploit weaknesses in the components that come with your operating system.

For Red Hat Linux systems, using the Red Hat Network is the best way of getting security updates that are approved for Red Hat Enterprise Linux. For Fedora, you can use the PackageKit or yum to download and install updates from Fedora mirrors that carry those updates (see Chapter 5 for information on using PackageKit and yum). You should also check CERT and other organizations (which describe in Chapter 14) for security alerts.

After your server is secure and configured, your last step is to start the server on the Internet with a domain name that points to it. Either ask your provider to configure DNS for you, or set up your own DNS server, as I describe in the following section.

# Setting Up a Domain Name Server System

The Domain Name (DNS) is essentially a distributed database that translates hostnames into IP addresses (and IP addresses back to hostnames). That database also contains information related to each domain, and how the domain is organized into zones, where to route mail for that domain, and whom to contact with questions associated with the domain.

By setting up a DNS server, you become up a hierarchy of DNS servers that make up the Internet. At the top of this hierarchy is the root server, represented by a dot (.). Below the root server are the Top Level Domains, or TLDs (such as .com, .org, and so on). Domains that individuals organizations own and maintain believe the TLDs, branching in a way that looks like an upside-down tree structure. Here's where you come.

As someone who's setting up a DNS server, you're responsible for managing the hostnames and IP addresses for the computers in the domain (or domains) for which you are responsible. Keeping your DNS information correct means that people can access the services you want to share, and the Internet as a whole works much better as a result.

Besides using your DNS server to help people from the Internet find the public servers in your domain, you can also use DNS to provide name and IP address mapping for computers on your private network. The example in the “DNS name server example” section later in this chapter describes how to configure both private and public name and IP address records for a domain.
