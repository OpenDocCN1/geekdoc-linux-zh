
## Chapter 4
## Using Linux Commands

### In This Chapter

- Understanding the shell
- Using the shell
- Working with the Linux file system
- Using the vi text editor in Linux

This chapter presents a view of Linux from the shell. The *shell* is a command-line interpreter that lets you access some of the most critical Linux tools. The shell is powerful, complex, and almost completely unintuitive.

Although at first it isn't obvious to use the shell, with the right help you can quickly learn many of the most important features. In Fedora and RHEL, `bash` is the shell interpreter used by default (and therefore, the one used for most of the examples in this chapter). Other shells, such as `csh`, `ksh`, `sh` and others, are also available in Fedora and RHEL and are therefore also noted in this chapter.

This chapter is your guide to working with the Linux system commands, processes, and file system from the shell. It describes the shell environment and helps you tailor it to your needs. It describes how to use and move around the file system.

## The Shell Interface

Throughout this book, there are procedures that require you to use a shell to run commands. How you first get to a shell depends on whether your computer is configured to have a graphical user interface (GUI) or not. A desktop system, by its nature, starts with a GUI. Server systems often are run entirely from the command line. Here are ways of reaching a shell, depending on whether you have a desktop GUI running or not:

- **No desktop** — If your Linux has no GUI (or one that isn't working at the moment), you log in from a text-based prompt and immediately begin working from the shell.

- **With desktop** — With the GNOME desktop running, you can open a Terminal window (select Applications -> System Tools -> Terminal) to start a shell. You can begin typing commands into the Terminal window.

If you are using an interface, the first thing you see is the shell prompt. The default prompt for a normal user is simply a dollar sign:

$

The default prompt for the root user is a pound sign (also called a hash mark):

#

If you use a shell other than the bash shell in Fedora, in some cases you may see a percent sign (%) as the user prompt instead of the pound. For most Linux systems, the $ or # prompts are preceded by your user name, system name, and current directory. So, for an example, a prompt for the user name jake on a computer name pine /tmp as the current directory would appear as:

```
jake@pine tmp~$
```

When you change to display any characters you like. You could use as your prompt the current directory, the date, the local computer name, or any string of characters. When you see a t(-) as the current directory (instead of ~ as the current directory), it identifies that your home directory is the current directory. (To configure your prompt, see the section "Setting your prompt" later in this chapter.)

Although a tremendous number of features are available with the shell, it's easy to begin by just typing a few commands. Try some of the commands shown in the remainder of this section to become familiar with your current environment.

In the examples that, the $ or # symbols indicate a prompt. The prompt is followed by the command that you type and then by Enter or Return (depending on your keyboard). The lines that show the output results from the command.

## Checking your login session

When you log in to a Linux, Linux views you as having a particular identity. That identity identifies your user name, group name, user ID, and group ID. Linux also keeps tracks of your login session: it knows when you logged in, how long you have been idle, and where you logged in.

To find information about your identity, use the id command as follows:

```
$ id
uid=501(chris) gid=105(sales) groups=105(sales),4(adm),7(lp)
context=user_u:system_r:unconfined_t
```

This shows that the user name is chris, which is represented by the numeric id (uid) 501. Here, the primary group for chris is called sales, which has a group id (gid) of 105. Chris also belongs to other groups adm (gid 4) and lp (gid 7). These names numbers represent the permissions that chris has to access computer resources. (Permissions are described later in this chapter on the section with files.)

If your computer has SELinux enabled, the id command also shows context information. In your example, you use context=user_u:system_r:unconfined_t on id output. Chapter 10 for information on SELinux.

You can see information about your current login session using the who command. In the following example, the -m option tells the who to print information about the current user, -u says to add information about idle time and the process ID, and -H asks for a header printed:

```
$ who -uH
NAME LINE TIME                IDLE      PID  COMMENT
chris tty 2008-10-05 14:12      2013
```

The output from who command shows the user name is chris. Here, chris is logged in on tty (which typically is connected to the computer), and his login session began at 14:12 on October 5. The IDLE time shows how long the shell has been open without any command being sent (the dot indicates it is currently active). COMMENT would show the name of the remote computer the user logged in from, if that user had logged in from another computer on the network, or the name of the local X display if you were using a Terminal window (such as .0).

## Checking directories and permissions

Associated with each shell is a location in the Linux file system known as the current or working directory. Previously mentioned, each user has a directory that is identified as the user's home directory. When you first log to Linux, you begin with your home directory as the current directory.

When you request to open or save a file, your shell uses the current directory as the point of reference. Simply give a filename when you save a file, and it will be placed in the current directory. Alternatively, you can identify a file by its relation to the current directory (relative path). You can ignore the current directory and identify a file by the full directory hierarchy that locates it (absolute path). The structure and use of the file system is described in detail later in this chapter.

To find out what current directory is, type the pwd command:

```
$ pwd
/usr/bin
```

In this example, the current or working directory is /usr/bin. To find the name of your home directory, type the echo command, followed by the $HOME variable:

```
$ echo $HOME
/home/chris
```

In the preceding example, the home directory is /home/chris. To get back to your home directory, you can simply type the change directory (cd) command. Although cd, followed by a directory name, changes the current directory to the directory that you choose, simply typing cd (with no directory name) takes you to your home directory:

```
$ cd
```

You can also use the tilde (~) to indicate the home directory. cd ~ would have the same result as cd .. This is useful when typing long paths in your home directory (such as ~/local/files, instead of /home/chris/files).

At this point, you list the contents of your home directory, using the ls command. You can either use the full path to your home directory to list its contents, or use the ls command without a directory name to list the contents. Using the -l enables you to see the hidden files (dot files) well as all other files.

```
$ ls -la ~/home/chris
total 158
drwxr-xr-x 2 root 1024 2008-05-12 01:49 ..
-rw-xr-r-- 1 chris sales 224 2008-05-21 21:30 .bash_history
-rw-xr-r-- 1 chris sales 240 2008-05-21 01:50 .bash_logout
-rw-xr-r-- 1 chris sales 230 2008-05-10 01:50 .bash_profile
-rw-xr-r-- 1 chris sales 124 2008-05-10 01:50 .bashrc
drwxr-xr-x 1 chris sales 4096 2008-05-10 01:50 .kde
-rw-xr-r-- 1 chris sales 149872 2008-05-11 22:49 letter
```

Displaying a list (-l) of the contents of your home directory shows you more about files and directories. Directories such as the current directory (.) and the above directory (..) are noted by the letter d at the beginning of each entry. In this case, (.) represents /home/chris and two dots (..), which is also referred as the parent directory, /. The home directory is owned by root. All other files are owned by the user chris (who belongs to the sales group).

The file or directory name shown on the left are mostly dot (.) properties that are used to store GUI properties (.kde directory) or shell properties (.bash files). The only non-dot file shown in this example is one named letter. At the beginning of each line are the permissions set for each file. Other information in the listing includes the size of each file in bytes (column 4) and the date and time each file was most recently modified (column 5).
