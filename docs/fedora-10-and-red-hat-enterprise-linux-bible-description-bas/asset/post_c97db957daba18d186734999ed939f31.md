## Checking system activity

In addition to being a multipuser operating system, Linux is also a multitasking system. Multitasking means that many programs can be running at the same time. An instance of a program is referred to as a process. Linux provides tools for listing processes, monitoring system usage, and stopping (killing) processes when necessary.

The most common utility for checking processes is the ps command. With ps, you can see which programs are running, the resources they are using, and who is running them.
The following is an example of the ps command:

```
$ ps au
USER       %CPU %MEM VSZ   RSS TTY STAT START TIME COMMAND
root       21.4 0.0  0.808  1100 tty0 S    14:50 0:00 login -- jane
jake       24.7 0.0  1.836  1020 tty0 S    14:50 0:00 -bash
jake       23.1 0.0  2.592   912 tty0 R+     18:22 0:00 ps au
```

In this example, the au asks to show processes of all users who are associated with your current terminal, and the u option asks that user names be shown, as well as other information such as the time the process started and memory and CPU usage. The concept of terminals comes from the days, when people worked exclusively from character terminals, a terminal typically represented a single person at a single screen. Now you can have many "terminals" on one screen by opening Terminal windows.

On this shell, there isn't much happening. The first process shows that the user Jake logged into the login process (which is controlled by the root user). The next process shows that Jake is using a bash shell and has just run ps command. The terminal device tty0 is used for the login session. The STAT column represents the state of the process, R indicating a currently running process and S representing a sleeping process. (A sleeping process is one that is still active, but is waiting for some event to complete before continuing. It may be waiting for someone to type something at a shell or for a process to finish requested.) A s indicates a session leader and + indicates the foreground process.

The USER column shows the name of the user who started the process. Each process is represented by a unique ID, referred to as a process ID (PID). (You can use the PID if you ever need to kill a runaway process.) The %CPU and %MEM columns show the percentage of the processor and random access memory, respectively, that the process is consuming. VSZ (virtual set size) shows the size of the image process (in kilobytes), and RSS (resident set size) shows the size of the program in memory. START shows the time the process began, and TIME shows the cumulative system time used.

## Understanding the Shell

Before icons and windows took over screens, you typed commands to interact with most computers. On UNIX systems, from Linux was derived, the program used to interpret and manage commands was referred to as the shell.

The shell provides a way to run programs, work with the file system, compile computer code, and manage the computer. Although the shell is less intuitive than GUIs, most Linux experts prefer the shell to be much more powerful than GUIs. Shell have been around for long, many advanced features have been built into them. Many old-Linux administrators and programmers use a GUI to open lots of shells.

The shell illustrated in this picture is called the bash shell, which stands for Bourne Again Shell. The name is derived from the fact that bash is compatible with the first UNIX shell: the sh. Other shells include the C shell (csh), which is popular among BSD users, and the Korn shell (ksh), which is popular among. Linux also has a tsh (a C shell look-alike) and an ash shell (another Bourne shell look-alike).

> NOTE: While you can invoke the Bourne shell with /bin/sh, the command actually runs the bash shell in sh compatibility mode. Running /bin/sh produces a shell that behaves more like sh than bash, you will probably be able to use bash scripting that the real Bourne shell wouldn't recognize. The sh still exists primarily for compatibility with scripts that were written specifically for that shell.

## Using the Shell in Linux

When you type a command in a shell, you can also include other characters that change or add to how the command works. In addition to the command itself, these are some of the other items that you can use on a command line:

- **Options** — Most commands have one or more options you can add to change their behavior. Options typically consist of a single letter, by a dash. You can also combine several options after a single dash. For example, the command -la lists the contents of the current directory. The -l asks for a detailed (list) of information, and the -a asks for files beginning with a dot (.) When a single option of a word, it is usually preceded by a double dash (--). For example, to use help on many commands, you would enter --help on the line. Here's an example of help information for the ls command (Output is piped to less) through it, type q to quit:

```
$ ls --help | less
Usage: ls [OPTION]... [FILE]
List information about the FILE (the current directory by default).
Sort entries alphabetically if none of the -cftUSUX nor --sort.
```
Mandatory arguments are mandatory for long options are for short options
-a, --all do not hide entries starting with .
-A, --almost-all do not list implied . and

- **Arguments** — Many commands also accept arguments after any options are entered. An argument is an extra piece of information, such as a filename, that can be used by the command. cat /etc/passwd displays the contents of the /etc/passwd file on your screen. In case, /etc/passwd is the argument.

- **Environment variables** — shell stores information that may be useful to the user's shell session in what are called environment variables. Examples of environment variables include $SHELL (which identifies the shell you are using), $PS1 (which defines your shell prompt), and $MAIL (which identifies the location of your mailbox).

> TIP: You can check your environment variables at any time. Type **declare** to list the current environment variables. Or you can type echo $VALUE, where VALUE is replaced by the name of a particular environment variable you want to list.
