# Configuring Your Public Server

With a domain name, a suitable Internet connection, and one or more static IP addresses, you need to prepare your server to share it on the Internet. In addition to choosing the types of services you want to offer, you must be more thoughtful about the security of your servers.

# Configuring networking

Whether you're configuring your computer for browsing the Web or offering a server, procedures for creating network interfaces are very similar. See Chapters 15 and 16 for information on configuring TCP/IP for your computer. Following is a quick review of what you need to do to get a live connection to the Internet that's for your server:

- Add network interfaces — Depending on what type of network connection you have, you must configure TCP/IP to work across that connection. Most likely, that connection requires you to configure an Ethernet, PPP, or ISDN interface. If you didn't already configure the connection when you installed Fedora, you can do so at any time by using the Network Configuration window (via the system-config-network command).

# Configuring servers

Some services are more appropriate for public exposure than others. You probably don't want to offer your print server, for example, to anyone on the Internet. Similarly, sharing with Samba or NFS isn't appropriate to share these services natively across the public Internet. (To access these services over an Internet connection, however, you could run them over a virtual network.)

If you're creating your first public server, you may want to consider setting up at least the following basic types of servers:

- Web server — This type of server, of course, provides the most common way to publish text, images, and a variety of other content to the Internet. Refer to Chapter 21 for information on configuring Apache Web server.

- FTP server — This type of server provides the most common way of sharing directories of documents, images, applications, and other content that users can download from your site. See Chapter 20 for information on setting up an FTP server.

- Mail server — Presumably, if you have a domain name and a Linux server up and running, you may very well have a running mail server. That way, you can create one or more e-mail addresses that look like chris@linuxtoys.net. Because mail servers are high-risk targets for spammers, if you are inexperienced in system administration you might decide not to maintain your own mail server. See Chapter 19 for information on configuring a mail server.

Of course, you can share any type of server that you choose. Web, FTP, and mail servers, however, are designed for sharing publicly. The basic configuration for these types of servers isn't difficult. Securing and monitoring these — or any — public servers, however, requires special effort, by the following sections describe.

# Managing security

Before you set your Fedora or RHEL system as a server, you can use simply to make outgoing connections to the Internet. You can use firewall (iptables) to close off the ports on your interface to the Internet (making your computer secure). That way, you need to open some of the ports on that interface to accept incoming requests. With more ports open, you must also become more consistent in monitoring those ports. You can use SELinux to set boundaries around your Internet services.

# Opening your firewall

Making your server public doesn't mean leaving your computer wide open. By using firewall, you can allow certain ports, here's a list of services that you may want to consider:

- Web server — Port 80
- Mail server — Port 25, 587
- FTP server — Port 20, 21
- DNS server — Port 53
- SSH server — Port 22 (allows secure login)

# Enabling SELinux

Security Enhanced Linux (SELinux) is enabled by default in Fedora and RHEL starting version 4. It is implemented with targeted policies, most popular server types (including Web, FTP, and DNS) have policies that restrict what intruders can do if they manage to break into your system. You should look over how policies are on SELinux Administration window (system-config-selinux) for services you are operating. Refer to Chapter 10 for information on SELinux.

# Checking logs and system files

By making your servers public, you may make them open to attacks. Although firewalls are a good first line of defense, you will need to watch the activity on those ports that you leave open. A consistent program of monitoring traffic and changes to your server, therefore, becomes more critical. The following are a few techniques that you can use to secure your servers:

- General security — Make sure that you protect all your user accounts by using passwords and the correct file permissions settings.

- Tripwire — Use Tripwire to take a snapshot of your critical system files so that you can check later whether anyone's altered those files. The tripwire package is included in the latest Fedora repository.

- File System Saint — As with Tripwire, File System Saint maintains a database of every file on your system. You can find out more information from the project's SourceForge.net (http://sourceforge.net/projects/fss).

- Logwatch — Use Logwatch, which is by default in Fedora and RHEL, to secure log files and e-mail suspicious messages to you. At very least, you should change the MailTo value in the /etc/logwatch/logwatch.conf file to an e-mail address you keep up with (this is where Logwatch will send its screened log messages).
