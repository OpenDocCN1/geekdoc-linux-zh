ALL: ALL
The preceding example is a rather restrictive configuration. It allows connections to the cups-
pd and telnet services from certain hosts, but then denies all connections. It also allows-connections to the FTP service (vsftp) to all hosts. Let's examine the files in detail.

As usual, lines with a # character are ignored by xinetd when it
verses the file. Each noncomment line consists of a comma-separated list of daemons followed
a a colon (:) character and a comma-separated list of addresses to check. In this-
content, a client that attempts to access a network service on your system.

A client entry can be a numeric IP (such as 199.170.275) or a hostname (such
as jukebox.linuxtoys.net), but more often a wildcard that specifies an entire range of addresses. A client entry can take four different forms. The online manual page
of the hosts.allow file describes them as follows:

+   - A string with a dot (.) character. A hostname is matched if the last
components of its name match the specified pattern. For example, the pattern .tue.nl\matches the hostname www.vin.tue.nl.
- A string that ends with a dot (.) character. A host is matched if its first
numeric fields match the given string. For example, the pattern 131.155 matches the
address of) most every over the Eindhoven University network (131.155.x.x).
- A string that begins with an @ symbol is treated as an NIS group name. A host
hname is matched if it is a host member of the specified network. Netgroup matches
is not supported for daemon process names or for client users.
- An expression of the form n.n.n.n/m.m is interpreted as a net/mask pair. A host
address is matched if net is equal to the bitwise and of the address and the mask. For
example, the net/mask 131.155.72.0/255.255.254.0 matches every
address in the range 131.155.72.0 through 131.155.73.255.
