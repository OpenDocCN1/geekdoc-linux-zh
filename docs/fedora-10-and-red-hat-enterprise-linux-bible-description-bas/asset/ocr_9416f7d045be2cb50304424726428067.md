# Testing the magnetic tape drive

With the mt-st package installed, you should now be ready to test your tape drive. Insert a blank tape into the tape drive and type the following commands:

```
$ mt -f /dev/qft0 status
$ mt -f /dev/qft0 rewind
```

The first command will present a status of the tape drive. After the second command, you should hear the tape spin as the system rewinds the tape. This will be a very short process if the tape is already rewound. The mt command provided with mt-st package is used to scan, rewind, and eject magnetic tapes in a tape drive.

# Writable CD drives

Another backup medium is gaining popularity the writable CD drive. Writable CD drives have several advantages over tape, the primary one being that CDs are random access medium. This means that the CD can quickly locate a particular file on the CD without sequentially scanning through the entire drive. This is useful when you need to keep a revision history of frequently changing data files (as source for a software project or drafts of legal documents).

Although people believe that CDs have a very long life, that belief comes into question. CDs are still a good choice if the backup will be needed for two years or less. For longer periods, a tape backup will last last than a writable CD. If your backups are intended for short-term storage, you should probably consider rewritable or CD-RW drive. A rewritable CD (unlike plain writable CDs) can be reformatted and used to store new backups.

The biggest drawback is that a CD can store, at most, 700MB of data. In contrast, DVDs can store 4.7GB of data (or about 8.5GB for dual-layer CDs) and many tape drives can store multiple gigabytes of data. For example, DDS-3 tapes can hold up to 24GB of compressed data, while mica AIT-2 tapes can hold up to 100GB of compressed data.

# Getting crecord for writable CDs

To write CDs with Fedora or RHEL you can use the weom, cdparanoia, and genisoimage packages, which are installed by default with Fedora and RHEL. These packages contain components such as the crecord, devdump, isodump, isoinfo, isovfy, and readcd commands.

# Writing to CDs

Because the data written to a CD-R or CD+R becomes permanent once it is written, you need to format the CD and copy files all in one step. If you formatted it first, you would end up with an empty file system on a CD that can no longer be written to.
