Use scp with a different user name, you can append the user name with an @ character. For example, chris@toys.linxtoys.net:/home/chris would attempt to log in as the user named chris to do the file.

The first time you connect to a remote computer using scp or ssh, commands try to establish the authenticity of the remote host. If it cannot establish the host's authenticity, it will display the RSA key fingerprint and ask you if you want to continue. If you type yes, scp will not question the authenticity of that computer again for subsequent scp commands.

However, if the RSA key fingerprint change in the future for the remote computer (which will happen if, for, the operating system is reinstalled on that computer), scp will refuse to connect to that remote computer. To override this, you need to edit your $HOME/.ssh/known_hosts file and delete the entry from the remote computer. You can verify the authenticity of the remote computer and continue to use scp.

The sftp command, which also communicates using ssh protocols, is a command for copying files from an FTP server. It is considered a more secure way of getting files from an FTP server that has an ssh server running. The sftp command can be disabled on the server by commenting out the sftp line in the ssh_config directory.

# Using the “r” commands: login, rcp, and ssh

The login, rcp, and rsh commands all use the underlying security mechanism to enable remote login, remote file copy, and remote execution, respectively, among computers. These commands are included with Fedora to be compatible with legacy UNIX systems. Because “r” commands are inherently insecure, however, most people use ssh and scp commands to provide the same functionality in a more secure way.
