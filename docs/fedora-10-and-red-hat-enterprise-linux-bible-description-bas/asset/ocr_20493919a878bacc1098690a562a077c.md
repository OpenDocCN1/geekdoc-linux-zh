# Part III: Administering Fedora and RHEL

> NOTE: Using a command growisofs (described later in this chapter), you can write to a CD in such that the session is not closed. Later, you can add more data. In multiple sessions, before you close the CD. The cdrecord command itself also supports a -multi option, which can keep the session open for further writing. Not all CDs will support multi-session writing (which requires the hardware support CD-ROM X 2 form 1).

The first step is to create an image of the CD file on your computer. You do this with the mkisofs command. The second step is to burn the CD or DVD using a tool such as the cdrecord command.

> NOTE: In recent releases of Fedora, the cdrecord command has been replaced by a command called wodim from the CDR Kit project (http://cdkit.org). Fedora and other Linux distributions switched to CDR Kit project because cdrecord licensing was changed to the Sun CDDL license, which is believed to be incompatible with the GPL. wodim is bargain compatible with cdrecord and command is linked to cdrecord, you can still use the cdrecord command as you always have.

As an example, if you want to go back up the home directory for user mary. you would invoke the mkisofs command and pass the name of the file system image to create, followed by the directory to base it on:

```
$ mkisofs -R /var/tmp/mary.iso /home/mary
```

This creates an ISO9660 file system image in a file mary.iso located in /var/tmp directory. The -R option creates specific ownership and long filenames. If your /var partition does not have enough room for the image, choose a different location.

> TIP: By default, mkisofs preserves the ownership and access rights of files and directories when it creates the file system image. This is appropriate when you are making a backup, but not when you are creating a software distribution. In such a case, add the -R option instead of -R as the first parameter to mkisofs. It will then store all files as publicly readable and, where appropriate, executable.

If you have an ATAPI CD drive, you no longer need a SCSI ID for drive to be able to record it. You can find the device name of the SCSI ID (such as /dev/dev/cdrom). However, if you have a SCSI CD drive, before you can write the image file to a CD, you must first discover the SCSI bus number, device ID, and Unit Number (LUN) of the CD drive. You can find out which SCSI device ID the CD drives is. Using the cdrecord command with the single parameter -scanbus:

```
$ cdrecord -scanbus
```

You should see a response similar to this:

```
scisibus0:
0,0,0   0)IDE-CD 'R/RW 4x4x24 '1.04' Removable CD-ROM
0,0,1   1) *
```
