The following section explains Linux kernel modules.

Releases of the Linux kernel are designated by three numbers—for example, Linux 2.4.3. These numbers are called:

- The major version (2)
- The minor version (4)
- The patch level (3)

Major *versions* are released every few years and provide significant improvements in kernel capability and performance. However, because the kernel architecture may change with the release of a major version, non-kernel software designed to work with a previous major release may need to be reconfigured or ever modified.

*Minor versions* are released more frequently than major versions. Software doesn't generally need to be reconfigured or modified to work with a new version of the kernel.

At any time, two releases of Linux are undergoing development. The release with an even number is called the *stable release*—for example, Linux 2.4.3. Development of the stable kernel focuses more on fixing defects than adding new features. The release with an odd number is called the *developmental release*—for example, Linux 2.5.10. Development of this release focuses on new—features. Therefore, as the release names suggest, the developmental release tends to be less stable than the stable release. System administrators do not install a developmental release except on computers that provide non-critical functions.

The third number making the kernel version number is the *patch level*. Patch releases occur even more frequently than minor releases, particularly patch releases of the developmental release. Sometimes several patches are released in a single week.

Linux kernels are released via the Linux Kernel Archive Web site, www.kernel.org. Red Hat, Inc. downloads released kernels and repackages them RPMs for easy distribution and installation. Red Hat, Inc., specially configures the kernel and applies patches that modify and extend functionality.

In addition to the major-patch versioning of Linux kernels, Red Hat, Inc. encourages use of what they call the extraversion code, which distinguishes differently configured versions of the same kernel release. As explained in the next chapter, you can specify an extraversion code when you build a Red Hat Linux kernel. The extraversion code takes the form of a sequential number and a short descriptive name. For example, build #20 of a Linux 2.4.6-20smp. Using the extraversion code facilitates having several Linux kernels on a single system. When you build a new kernel you can keep a copy of the old kernel on the system. That way, if the new kernel fails to operate properly, you can simply reboot the system using the old kernel, rather than perform more elaborate-rate recovery operation.

Many Red Hat Linux users and system administrators may need to compile a Linux kernel. Instead, they download and install kernel updates in package form. However, you may want to build a custom kernel for reasons such as:

- You want to configure an especially secure system and therefore want to disable unnecessary capabilities that might present security risks. For example, you plan to use a Linux system as a router and therefore don't need or want some of the capabilities included in the standard Red Hat Linux kernel.

- You want to enable capabilities not available in the standard Red Hat Linux kernel, such as advanced routing options.

- You want to alter parameters not configurable during operation. For example, you want to use more than 1GB of RAM and therefore need to reconfigure the balance between user-space and kernel-space memory.

- You're curious to learn more about the Linux kernel. Building a custom kernel is a good way to do so.

# Kernel Types

Originally, the Linux kernel was a monolithic kernel, a kernel that resides in a single file. You can still build a monolithic kernel if you choose, but most Linux kernels are now modular kernels that reside in a set of files, called modules. A modular Linux kernel can load modules when they're needed and unload them when they're longer needed. Typically, any modules not needed during boot are compiled as modules rather than incorporated into the kernel. Such modules include peripheral device drivers, supplementary file systems, and so on.

Table 17.1 summarizes characteristics of monolithic and modular kernels. The greater flexibility of the modular kernel generally outweighs the slightly faster execution and slightly greater security of the monolithic kernel.

# TABLE 17.1 Monolithic and Modular Kernels

| Monolithic Kernel | Modular Kernel |
|---|---|
| Slightly faster execution | Slightly faster boot |
| Slightly more secure | Less RAM required |
| | More flexible |
| | Less frequent kernel rebuilds |

# Boot Files

The Linux boot files reside in the /boot file system so that they can be accessed by PC BIOS code that are incapable of accessing every sector on a large disk. The principal Linux boot files are:

- vmlinux: The Linux kernel, which can have arbitrary name.
- boot.b: LILO's second stage.
- initrd: A file containing RAM disk (modules) available at boot time.
- lilo.conf: The configuration file for LILO.
- System.map: A file needed by utilities to debug the kernel.
- boot.nnnn: A backup copy of the original master record.

# Kernel RPMs

As explained, Red Hat, Inc. publishes RPMs that contain the kernel. A standard installation of Red Hat Linux includes the kernel package, which contains associated modules. On the Intel 386 platform, the standard installation also includes the kernel-pcmia package, which contains drivers for PCIA cards.

To build a custom kernel, you must install two packages containing the kernel source:

- kernel-source
- kernel-headers

To install the packages, move to the directory that contains them and issue the command:

```
rpm -Uvh kernel-source-*.i86.rpm kernel-headers-*.i86.rpm
```

When installed, the files of these packages reside in /usr/src/linux-version, where version is the version of the Linux kernel contained in the package. If you want to view kernel documentation without installing the kernel-doc package, that package contains the kernel files that otherwise reside in /usr/src/linux/Documentation, but places them in /usr/doc.

If you prefer to work from a source RPM, you can install the kernel-source-version.src.rpm, where version is the version number of the Linux kernel contained in the package. This package contains the source files as released on www.kernel.org, plus patches added by Red Hat, Inc. The package installs the source files in the /usr/src/redhat directory. # Utilities

To build the Linux kernel, you must have available the C compiler, certain soft-development utilities, and certain libraries. The required packages are:

- egcs-version.i386: the GNU C compiler
- cpp-version.i386: the GNU C preprocessor
- dev86-version.i386: an 80x86 assembler and linker
