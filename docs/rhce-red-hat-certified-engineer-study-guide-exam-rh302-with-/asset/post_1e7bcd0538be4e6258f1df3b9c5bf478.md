## FTP

The Washington University (St. Louis) FTP server is the most used FTP server on the Internet. It lets users upload and download files and directories. The FTP daemon is named /usr/sbin/inftppd; however, its page is named fptppd.

Three levels of FTP access are provided:

- User access, access by users who have a login account on the server host. This level of access accords the usual access privileges defined by their user ID.
- Guest access, access by users who have a special guest account that provides only FTP access. This level of access accords specially defined access privileges.
- Anonymous access, access by users who have no defined account on the server host. This level of access accords to only a specified directory and its subdirectories (usually, /home/ftp). This restriction is enforced by means of a chrooted environment.

The Washington University FTP server can log all accesses. It also provides capabilities that let transfer compressed files or transfer entire directories with a single command.

## Installation

The Washington University FTP server is distributed as two packages:

- wu-ftpd, which contains the FTP server
- anonftp, which contains the anonymous FTP server

If you require anonymous FTP service, you should install both packages. However, if you don't require anonymous FTP service, you should install only the wu-ftpd package. Unnecessarily installing anonymous FTP may make your system somewhat more vulnerable to attack by crackers.

## Basic Configuration

The FTP service has three basic configuration files:

- /etc/ftpaccess, which specifies global options and user permissions
- /etc/fthosts, which specifies client hosts that may or may not access the FTP service
- /etc/ftusers, which specifies users who may not access the FTP service. Typically, the file includes entries for root, bin, daemon, adm, lpc, sync, shutdown, halt, mail, news, uucp, operator, games, and nobody

Here are the contents of a typical ftpaccess file:

```
class all real,guest,anonymous *
email root@localhost
loginfails 5

read README* login
read README* cwd=*

message /welcome.msg login
message .message cwd=*

compress yes all
t yes yes
chmod no guest,anonymous
delete no guest,anonymous
overwrite no guest,anonymous
rename no guest,anonymous

log transfers anonymous,real inbound, outbound
```

shutdown /etc/shutmsg

passwd-check rfc822 warn

Check the man pages ftpacces and fthosts for information on the format of the configuration directives.

## Administration

By default, the FTP service is run as an inetd service. Thus, it is not necessary to start, restart, or stop the service.
The FTP service places log entries in the system log, /var/log/messages.
If the FTP service is not operating properly, check the contents of the system log for log entries that point to the problem.
A common requirement is for a set of directories to be accessible via anon-ym FTP, HTTP, and NFS. The FTP server does not follow symbolic links, so directories must be subdirectories of the directory designated as the home directory of the ftp user, generally /home/ftp directory. To provide access via HTTP, establish symbolic links pointing to the directories. To provide via NFS, simply export the directories.

## Mail

Mail involves two facilities: mail transfer and mail access. The Red Linux mail transfer agent (MTA) is sendmail, which is the most popular MTA on the Internet. Red Hat provides access to mail via the Post Office Protocol (POP) or the Interim Mail Access Protocol (IMAP). The sendmail program is extremely flexible, but is relatively large and complex. Its features include:

- The ability to decode and handle wide range of formats
- Support for virtual domains
- Extensive security

## How Mail Works

After composing a mail, the recipient typically accesses it while logged in. Popular clients include:

- Eudora
- Netscape
- Outlook
- Pine

The sendmail program is used by the sendmail protocol (SMTP). For example, POP sends passwords across the Internet as clear text; IMAP can encrypt them.
