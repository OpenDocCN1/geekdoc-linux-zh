## Performing Kickstart Installations

### Using mkickstart

The mkickstart program is not installed by default, the usual first step is to install the mkickstart package using the following command:

```
rpm -Uvh /mnt/cdrom/RedHat/RPMS/mkickstart*.rpm
```

After installing the mkickstart package, run the mkickstart program as follows:

```
mkickstart >ks.cfg
```

Notice how the output of the mkickstart program is redirected to the file ks.cfg. The mkickstart program will probably display a warning that reminds you to set the static IP address in the configuration file; this is normal. Here's a sample ks.cfg file:

```
lang us
#network --static --ip 10.0.0.2 --netmask 255.255.255.0
--gateway 10.0.0.1 --nameserver 10.0.0.1
cdrom
device ethernet 3c90x
keyboard
zerombr yes
clearpart --linux
part swap --size 526
part / --size 10444
part /boot --size 40
part /usr --size 2001
part /home --size 4009
part /var --size 503
part / --size 1005
install
```

```
mouse genericps/2
timezone US/Pacific
xconfig --server "SVGA" --monitor "viewsonic17gs"
auth --usershadow --enablemd5
lilo --location mbr --linear
%packages
setup
filesystem
nbasesystem
...and so on...
%post
```

## Editing the Configuration File

The configuration file requires some revision before it can be used. Notice that the network line is commented out. You should remove the comment character (#) and revise the IP number, netmask, and gateway. If you want the system to obtain its network configuration via BOOTP or DHCP, specify the following directive:

```
network --bootproto BOOTP
```

or

```
network --bootproto DHCP
```

Table 8.4 describes the other directives shown in the same configuration and a few additional directives you may find useful. Consult the RedHat documentation to learn more.

## Setting Up the Servers

Rather than include the kickstart file on the boot media, you can use a DHCP server to provide it. To do so, specify

- filename "/home/ftp/ks.cfg";

in theetc/dhcpd.conf file. If you prefer to store the kickstart file in a directory other than /home/ftp, simply revise the directive accordingly.

If you prefer to have a separate kickstart file for each client system, specify the directive

- filename "/home/ftp/kickstart";

Then, in the directory /home/ftp/kickstart, place the kickstart files, which must have names of the form xxx.xxx.xxx.xxx-kickstart, where xxx.xxx.xxx.xxx is the IP address of the client system.

When the installation program fetches the kickstart file via DHCP, it assumes it should perform a network installation from an NFS server. By default, it tries to mount an NFS directory exported by the same host that answered the DHCP query. If you want to use a different host to serve the NFS requests, include the following directive in etc/dhcp.conf:

```
next-server nfserver;
```

where nfserver is the host name or IP of the desired NFS server on which the kickstart file resides. To give the location of installation media, you can specify a kickstart directive of the form

```
nfs --server directory
```

where server specifies the NFS server and directory specifies the NFS-exported directory.

## Performing the Kickstart Installation

To start the kickstart installation, specify the ks argument at the linux prompt. Use the command

```
linux ks
```

if the kickstart file is to be obtained from a DHCP or NFS server. Use the command

```
linux ks=floppy
```

if the kickstart file resides on the root directory of the boot floppy disk. If the kickstart installation needs information that it cannot find in a kickstart directive, it prompts for the information using the dialog box presented by a non-kickstart installation.
