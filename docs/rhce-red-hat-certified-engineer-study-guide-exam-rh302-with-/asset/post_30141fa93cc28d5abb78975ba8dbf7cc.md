
The final field of each crontab line specifies the command. If you include a percent sign (%) in the command, only the portion of the field before the percent sign is executed. Any remaining characters in the command are sent as standard input to the command; subsequent percent signs in the command are replaced by newline characters. To embed a percent sign in a command, precede it with a backslash (\), which allows it to escape the special meaning of the percent sign.

For example, the following command, taken from the man page for crontab, sends mail to a user:

```
mail -s "It's 10pm" joe%Joe,%%Where are your kids?
```

The percent signs are sent as newlines, which serve as responses to the prompts of the mail command.

### The System crontab

In addition to the user crontab files stored in /var/spool/cron, the cron system has a file stored in /etc/crontab. Here are the contents of a typical crontab file:

```
SHELL=/bin/bash
PATH=/sbin:/bin:/usr/sbin:/usr/bin
MAILTO=
HOME=
```

```
# run-parts
01 * * * root run-parts /etc/cron.hourly
02 * * * root run-parts /etc/cron.daily
22 * * * root run-parts /etc/cron.weekly
42 * * * root run-parts /etc/cron.monthly
```

The format of the /etc/crontab file differs slightly from that of user crontab files. It includes a user field, which specifies the user under which the associated command is run. The user field is the sixth field, placed just before the command field.

The default /etc/crontab file contains four command lines, each of which specifies a run-parts script as the command to run. The run-parts script takes a single argument, which is a directory. The script executes the files contained in the specified directory. The /etc/crontab file uses run-parts to execute hourly, daily, and monthly jobs. Thus, it's not necessary to edit the file; you merely place the script you want to execute—or a symbolic link to the script—in one of the cron.d directories. As root, however, you can edit the file using a text editor; you don't need to use the crontab command.

If you change the /etc/crontab file, the cron system will detect the modification date of the file. You do not need to restart or signal the cron daemon.

Red Hat Linux also has a set of system cron files stored in /etc/cron.d/; these files are created by package installation scripts. They have the same format as /etc/crontab. The modutils package, for example, installs /etc/cron.d/kmod. Here are the contents of a typical /etc/cron.d/kmod file:

```
# rmmod is a twice daily module cleaner
*/10 * * * root /sbin/rmmod -a
```

This file runs the rmmod command every 10 minutes, unloading unused modules. The next sections describe the standard hourly, daily, weekly, and monthly jobs executed by the Red Hat Linux cron system.

### Hourly cron Jobs

The /etc/crontab file designates the /etc/cron.hourly directory as the location for scripts that will be executed hourly. By default, the directory is empty. However, you can add your hourly scripts to the directory.

### Daily cron Jobs

By default, Red Hat Linux runs the daily cron jobs:

- logrotate
- makewhatis
- locate
- tmpwatch

A detailed understanding of these jobs is not required for the RHCE exam. The following subsections briefly describe them.

### The logrotate Job

The daily logrotate job is a simple script that invokes the logrotate command:

```
#!/bin/sh
/usr/sbin/logrotate /etc/logrotate.conf
```

The logrotate command allows automatic rotation, compression, removal, and mailing of log files. You can consult its man page for details, in particular the format of its configuration file.

### The makewhatis Job

The whatis command provides access to a database of key words found in the man pages. For example, if you issue the command

```
whatis rm
```

the command responds with:

- rm (1) - remove files or directories

The same database supports the apropos command, which lists man pages related to a specified topic. For example, if you issue the command:

- apropos cron

the command responds with:

cron(8) - daemon to execute scheduled commands
crontab(1) - maintain crontab files for individual users
crontab(5) - tables for driving cron

You can invoke the apropos command by using the command form

`man -k topic`

where topic specifies the subject in which you're interested.

In order to maintain the database used by whatis and apropos, the whatis command must be run periodically. To do so, the Red Hat cron system runs the /etc/cron.daily/slocate script:

```bash
#!/bin/bash
LOCKFILE=/var/lock/whatis
```

```bash
NETMONUTS='mount -t nfs,smbfs,ncpfs | cut -d ' ' -f 3'
NETPATHS=$echo NETMONUTS | sed -e 's|,\,|g'
```

```bash
if [ -n "$NETPATHS" ]; then
  /usr/bin/slocate -u -e 
    "$NETPATHS,/tmp,/var/tmp,/usr/afs,/net,/proc"
else
  /usr/bin/slocate -u -e "/tmp,/var/tmp,/usr/afs,/net,/proc"
fi
```

The symbolic link /usr/bin/slocate refers to /usr/bin/updateddb, the utility program that rebuilds the database used by the locate command. You can consult the man pages of locate and updateddb for details; however, you do not need detailed knowledge of these commands in order to be prepared for the RHCE exam.

### The locate Program

The locate command makes it possible to find the directory in which a file resides, given the name of the file or a pattern. For example, to find directories that contain characters linux.words, issue the command:

```
locate linux.words
```

Output of the command resembles the following:

```
/usr/dict/linux.words
/usr/doc/words-2/README2.linux.words
/usr/doc/words-2/README2.linux.words
```

Unlike the find command, which provides a similar capability, the locate command uses a database. However, the database must be regularly updated in order to be useful. The speed of locate execution relative to that of the find command is significant.

### The System cronab

Another daily tasked by the cron system is the deletion of stale temporary files. The script /etc/cron.daily/tmpwatch, executed daily, invokes the following command:

```
/usr/sbin/tmpwatch 240 /tmp /var/tmp /var/catman/cat?
```
