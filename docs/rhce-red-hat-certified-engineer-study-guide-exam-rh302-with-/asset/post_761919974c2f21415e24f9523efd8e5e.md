The **rpm Command** — The *rpm* command lets you perform a variety of operations, including installing a package, updating a package, removing a package, querying the RPM database, querying a package file, building a package code, validating a package, and validating a package file.

**Source RPM Packages** — Unlike ordinary RPM packages, which contain binary code, source RPM packages contain source code.

**The GnoRPM Program** — GnoRPM provides an X-based graphical user interface to the *rpm* command.

## Review Questions

1. Which of the following stores information about RPM packages?
   A. Package files
   B. The install command
   C. The rpm command
   D. The RPM database

2. Which of the following commands uninstalls the package xyz?
   A. rpm -e xyz
   B. rpm -i xyz
   C. rpm -u xyz
   D. rpm --uninstall xyz

3. To learn which package owns the file /etc/hosts, issue the command:
   A. rpm -qf hosts
   B. rpm -qf /etc/hosts
   C. rpm -qF hosts
   D. rpm -qF /etc/hosts

4. The -V flag causes RPM to report changed files. If the contents of a configuration file have been changed, which of the following flags appear in the output?
   A. 5
   B. c
   C. S
   D. T

5. To list the name of each installed package, issue the command:
   A. rpm -q
   B. rpm -qa
   C. rpm -qi
   D. rpm -qp

6. The program that provides a graphical user interface to RPM is:
   A. GoRPM
   B. GnoRPM
   C. GnomeRPM
   D. GnomeRPM

## Answers to Review Questions

1. A, D. Both package files and the RPM database store information about RPM packages.

2. A, D. Both the -e and --uninstall flags uninstall the specified package.

3. B. The -qf flag causes RPM to report file ownership; the full path of the file must be specified.

4. A, B, D. The file size may not have changed, even though the contents of the file have changed.

5. B. The -qa flag causes RPM to list the name of each installed package.

6. B. GnoRPM is the tool that provides a graphical user interface to RPM.

## Red Hat Linux File Systems

Like other Unix systems, Red Hat Linux has a hierarchical file system. The top-most directory—known as the root directory—of the file system contains several other directories, sometimes called subdirectories. These directories in turn generally contain subdirectories and files.

The directory structure is not arbitrary. For packages to work properly, the location of important files and directories must be standardized. The File System Hierarchy Standard codifies common practices and suggests improved practices for the structure of directories. The File System Hierarchy Standard is available via the Web, at pathname.com/fhs.

Though designed with Linux systems in mind, the standard is applicable to Unix systems generally. Distributors of Linux generally follow the recommendations of the File System Hierarchy Standard. However, the standard is what and loose subject to interpretation. Consequently, two distributions that are held to follow the standard may nevertheless differ significantly in the structure of their file systems. Red Hat Linux follows the standard closely. The Official Red Hat Linux Reference Guide explains the standard. Red Hat Linux follows the standard.

## The Root Directory

The root directory (/) of Linux system contains other directories. The following directories:

- /bin, contains binary files
- /dev, contains device files
- /etc, contains configuration
- /lib, contains libraries
- /sbin, contains binary files
- /home, contains users
- /lost+found, contains system
- /mnt, contains mount points
- /proc, contains information
- /root, contains root
- /root, contains system
- /root, contains data
- /tmp, contains temporary files
- /usr, contains shareable files
- /var, contains shareable files

## /boot: Boot Loader Files

The /boot partition generally contains such files:

- LILO’s second stage, which resides in the file boot.b
- the Linux kernel, generally named vmlinux*
- module information that identifies system modules by name
- the system map file that records the location of kernel modules and symbols

## /dev: Device Files

The Linux /dev directory includes a variety of device files. Table 13.2 summarizes some of the most common device files. In addition, there are device files that correspond to:

- Memory and I/O ports (for example, /dev/mem)
- Various audio and multimedia devices (for example, /dev/audio)
