
## Advanced Power Management (APM) Configuration

Advanced Power Management (APM) helps conserve electrical power. It is especially useful for battery-operated computers, such as laptops; however, many modern desktop computers support APM, which you can use to shut down peripherals that aren't being used. When APM is used with a laptop and it detects low battery conditions, it dims the display, shows the CPU clock, and turns off peripherals to save power. The file /etc/sysconfig/apmd contains the APM configuration, which is referenced by the script /etc/rc.init.d/apm. See The Battery-Powered Linux Mini-HOWTO for information on configuring and using APM.

## PCCMIA Configuration

PCCMIA service manages PCCMIA cards. The file /etc/sysconfig/pcmia contains PCCMIA service configuration information, which is referenced by the script /etc/rc.init.d/pcmia. Configuration information for PCCMIA devices resides in /etc/pcmia. If you recompile the Linux kernel of a system that uses PCCMIA, you must also recompile and install the PCCMIA package. For more information on PCCMIA, see the Linux PCCMIA Web site, pcmia.sourceforge.org.

## Plug-and-Play Configuration

As described in Chapter 2, plug-and-play devices are designed to be automatically configured by cooperation between the BIOS and operating system. Linux, however, does not fully support plug-and-play for ISA interface cards. When using Linux with a BIOS that supports plug-and-play, set the BIOS to indicate that the operating system does not support plug-and-play. You can then configure ISA plug-and-play cards by this following command

- Issue the command pndump >/etc/isapnp.conf

This command dumps the configuration of each installed plug-and-play card in the specified file, /etc/isapnp.conf.

- Using a text editor, revise the /etc/isapnp.conf file which contains commented lines for each configuration of each plug-and-device. You must uncomment the desired configuration for each device. You must also uncomment the line at the end of the device configuration, which specifies the device is active.

- 3. Issue the command
nisapnp /etc/isapnp.conf

This command configures /etc/isapnp.conf installed plug-play cards according to the configuration given in /etc/isapnp.conf. The Linux boot sequence issues this command to configure plug-play devices during start-up.

For more information on Linux support for plug-play, see www.roe-stock.demon.co.uk/isapnptools.

## Sound Configuration

The sndconfig command detects and configures most plug-play sound cards. The command places configuration information in /etc/conf.modules and /etc/isapnp.conf, as well as /etc/sysconfig/soundcard.

If you're using the GNOME desktop manager under X, the GNOME sound manager, esd, will manage your sound card and allow multiple applications to access it simultaneously. However, if you execute an application that is not aware of esd, it may conflict with other applications. To avoid this, invoke the application by using the esdsp wrapper. Start the application by issuing the command

```
esdsp application
```

where application is the name or path of the application. The KDE audioserver performs a function similar to that of esd.

## The /etc/fstab File

The /etc/fstab file describes the file systems associated with a Linux system. Here are the contents of a typical /etc/fstab file:

| /dev/hda1 | /dos | msdos | defaults | 0 2 |
| /dev/hda5 | /boot | ext2 | defaults | 1 2 |
| /dev/hda6 | /usr | ext2 | defaults | 1 2 |
| /dev/hda7 | /home | ext2 | defaults | 1 2 |
| /dev/hda8 | /var | ext2 | defaults | 1 2 |
| /dev/hda9 | | ext2 | defaults | 1 1 |
| /dev/hda10 | swap | | defaults | 0 0 |
| /dev/hda11 | /space | ext2 | defaults | 1 2 |
| /dev/fdd0 | /mnt/floppy | ext2 | noauto | 0 0 |
| /dev/cdrom | /cdrom1 | iso9660 | noauto,ro | 0 0 |
| /dev/hdd | /cdrom2 | iso9660 | noauto,ro | 0 0 |
| none | /proc | defaults | 0 0 |
| none | /dev/pts | devpts | mode=0622 | 0 0 |

Each line in the file describes a file system. The fields are as follows:

- The device file.
- The mount point.
- The file system type. Table 15.5 summarizes the file system types supported by Linux.
- The mount options. Table 15.6 summarizes the available options.
- The dump flag. The value 1 indicates a file system that is automatically included in a system dump; the value 0 indicates a file system that should not be included.
- The file system check sequence. The value 1 indicates the root file system; the value 2 indicates a non-root file system that should be automatically checked; the value 0 indicates a file system that should not be checked.
