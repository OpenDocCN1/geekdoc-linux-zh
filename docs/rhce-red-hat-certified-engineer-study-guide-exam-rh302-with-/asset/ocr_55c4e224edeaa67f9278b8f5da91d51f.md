The following section explains Linux kernel modules.

Releases of the Linux kernel are designated by three numbers—for example, Linux 2.4.3. These numbers are called:

+   - The major version (2)
- The minor version (4)
- The patch level (3)

Major *versions* are released every few years and provide significant improvements in kernel capability and performance. However, because the kernel architecture may change with the release of a major version, non-kernel software designed to work with a previous major release may need to be reconfigured or ever modified.

*Minor versions* are released more frequently than major versions. Softare doesn't generally need to be reconfigured or modified to work with a new version of the kernel.

At any time, two releases of Linux are undergoing development. The release with an even number is called the *stable release*—for example, Linux 2.4.3. Development of the stable kernel focuses more on fixing defects than adding new features. The release with an odd number is called the *developmental release*—for example, Linux 2.5.10. Development of this release focuses on new—features. Therefore, as the release names suggest, the developmental release tends to be less stable than the stable release. System administrators do not install a developmental release except on computers that provide non-critical functions.

The third number making the kernel version number is the *patch level*. Patch releases occur even more frequently than minor releases, particularly patch releases of the developmental release. Sometimes several patches are released in a single week.
