# TCP/IP Networking

At one time, a variety of protocols vied for ascendancy as the preeminent protocol. The advent of the Internet, which is based on the TCP/IP (Transmission Control Protocol/Internet Protocol) family, has essentially ended the contest. Except for closed, most networks today use TCP/IP as their primary protocol. This section describes how TCP/IP hosts and networks are addressed. The subsequent section describes how TCP/IP networks function and the services TCP/IP networks provide.

# IP Addresses

TCP/IP networks are made up of interconnected computer systems called hosts. Each host has one or more IP addresses, usually one for each interface. TCP/IP addresses are commonly written as a series of four octets (8-bit values). For example, a TCP/IP host may have an IP address 192.168.1.1, which is equivalent to the 32-bit integer 3,232,235,777 (192 × 2⁴⁴ + 168 × 2¹⁶ + 1 × 2⁸ + 1).

Some hosts have permanently assigned IP address, called a static IP address. Other hosts are assigned a temporary IP address, called a dynamic IP address. Dynamic IP addresses are commonly used for mobile hosts, such as laptops, and for dial-in clients. Hosts that provide services to other hosts are generally assigned a static IP address so that clients will be able to refer to them. As you will see later in the chapter, IP addresses are a scarce commodity requiring an IP address pool as large as the number of active hosts rather than the total number of hosts.

# Network Classes

Organizations don't ask the Internet authorities for a single IP address. Instead, they request a consecutive series of IP addresses that can be assigned within their network. IP addresses are chosen from one of three classes, distinguished by the first octet:

- 10.0.0.0–126.0.0.0 Class A
- 128.0.0.0–191.0.0.0 Class B
- 192.0.0.0–223.0.0.0 Class C

An IP address consists of two parts: a network address and a host address. The network address is common to all directly connected hosts. The host address distinguishes one host from the others on its network. The size of the network address varies according to the class:

- Class A 8 bits (one octet)
- Class B 16 bits (two octets)
- Class C 24 bits (three octets)

Because the network address of class A is only 8 bits long, 24 bits are available to specify host addresses. In contrast, the network address of class C network is 24 bits long; only 8 bits are available to specify host addresses. Thus, a class C network can include only 254 hosts (the IP addresses xxx.xxx.xxx–xxx.xxx.255).

# Networking Basics

Class C networks may appear less desirable than class A networks. However, because the network address of class A network consists of only 8 bits, class A network addresses are possible. All such addresses have been assigned, so, although you might prefer a class A, the 24-bit network address of class C yields over 16 million possible addresses. Unfortunately, even class C addresses are becoming scarce.

![](img/7a53e2be7760e1d42d1c89f5d6ede_107_0.png)

A new TCP/IP standard, IPv6, will provide 128-bit IP addresses. The Linux kernel already provides experimental support for IPv6, but it will be several years before IPv6 is widely supported and used. IP address ranges are specially allocated:

- 127.0.0.0–127.255.255 Used to refer to the local host and network (loopback addresses).
- 224.0.0.0–239.0.0.0 Reserved for use by multicast protocols.
- 240.0.0.0–255.0.0.0 Reserved (do not use).
- 10.0.0.0–10.255.255 Reserved for private networks.
- 172.16.0.0–172.31.255 Reserved for private networks.
- 192.168.0.0–192.168.255 Reserved for private networks.

You can freely assign IP addresses from ranges allocated to private networks. However, you must take special steps (such as implementing IP masquerading or network address translation, which are described in Chapter 30, “Configuring a Firewall with iptables”) to enable a host with private IP address to access hosts outside its local network.

# Subnetting

Suppose you have two small networks, each consisting of about one dozen hosts. You could request a class C network address for each network. However, a class C network address provides many more IP addresses than you need. If you could somehow have a network address of, say 26 bits instead of 24, you could host several networks within the range of IP addresses that compose a single class C network address. The remaining 6 bits of the IP address would let you assign as many as 31 hosts to each network.

Subnetting lets split an IP address into its network and host address components anywhere, rather than at an octet boundary. Designate the part of an IP address that composes the network address by specifying a netmask, a 32-bit string that has a 1 bit in each position's part of the network address and a 0 bit elsewhere. You write a network using the same dotted quad notation used for IP addresses. For example, a class C address has a netmask of 255.255.255.0: the first three octets have all 1s and the final octet has all 0s. To specify a 26-bit network address, you use a netmask of 255.255.255.192 where the final octet has 1 bits in its two highest positions.

To understand the significance of a host's IP address, you must know the associated network. Otherwise, you won't be able to determine which bits are on the same local network as the host.

Some programs allow you to specify an IP address and netmask as pair. You write the IP address, follow it with a slash, and then write the number of bits in the mask. For example, 192.168.1.100/24 specifies a host with IP address 192.168.1.100 on a network having a 24-bit (class C-like) netmask. A subnetted IP address is one in which the number of subnet bits is not an even multiple of 8, for example, 192.168.1.100/26.
