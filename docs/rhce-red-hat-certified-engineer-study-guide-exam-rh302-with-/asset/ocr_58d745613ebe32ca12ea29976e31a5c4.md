# The System cronab 387

```
# run-parts
01 * * * root run-parts /etc/cron.hourly
02 4 * * * root run-parts /etc/cron.daily
22 4 * * 0 run-parts /etc/cron.weekly
42 1 * * root run-parts /etc/cron.monthly
```

The format of the /etc/crontab file differs slightly from that of the user crontab files. It includes a user field, which specifies the user id under which the associated command is run. The user id field is the sixth field of each, placed just before the command field.

The default Red Hat Linux /etc/crontab file contains four command lines, each of which specifies the run-parts script as the command to run. The run-parts script takes a single argument, which is a directory. The script executes the files contained in the specified directory. The /etc/crontab file uses run-parts to execute hourly, daily, weekly, and monthly jobs. Thus, it's not necessary to edit the /etc/crontab file; you merely place the script you want to execute—or a symbolic link to the script—in one of the /etc/cron directories. As root, however, you can edit the file by using a text editor; you don't need to use the cron command.

If you change the /etc/crontab file, the cron system will detect the modification date of the file. You do not need to restart or signal the cron daemon.

Red Hat Linux also has a set of system crond files stored in /etc/cron.d/; these files are created by package installation scripts. They have the same format as /etc/crontab. The modutils package, for example, installs the /etc/cron.d/kmod. Here are the contents of a typical /etc/cron.d/kmod file:

```
# rmmod is a two-hand sweep module cleaner
*/10 * * * root /sbin/rmmod -as
```

This file runs the rmmod command every 10 minutes, unloading unused modules.
