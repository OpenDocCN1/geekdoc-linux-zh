In addition to the access permissions described in these tables, there are two other, less-used rights that you need to know about. These rights allow a program to do special things with certain files, if they are turned on for other files, they can pose big security problems.

The two extra rights, or bits, as they are sometimes called, allow anyone execute a file to have all the rights of that file. For example, suppose you are the owner of a script file, and you set the execute permission for Other so that everyone who logs into the system can run the script. The Set User ID on Execution bit is set, every user who executes your script has much access to the system while they execute the script as do. If your script provides the ability to read or delete files, any user could use that script to delete your files using the script.

The special bit is Set Group ID on Execution, which allows someone executing that file to access everything that users of the group assigned to that file access — not quite dangerous, but still important to know.

# Entering Commands and Running Programs from the Linux Shell

The shell is the UNIX term for the command-line interface, where you can enter any command to set up or administer your Linux system. This section describes how the Linux shell functions, and how you can use features of the shell to control the programs — often called processes in UNIX and Linux — that you run on your Linux system.

I've mentioned the command line and a couple of times. If you're used to DOS, you know you can enter commands at the C:\ prompt. When that prompt appears, you are actually running a program called COMMAND.COM. COMMAND.COM is a command interpreter. It has several built in commands, such as DIR, and also knows how to execute commands and programs when you enter their names.

COMMAND.COM in DOS also has a very simple programming language (batch files) that lets you automate tasks.

In the same way, a shell in Linux is a command interpreter that allows you to enter commands and automate tasks using a special shell programming language. Unlike DOS, Linux has many different shells that you can choose from. Most UNIX systems have a preferred shell that is set by default, but if a user is familiar with another shell, one that can be used instead.

OpenLinux uses the bash shell as the default (bash actually stands for Bourne Again Shell, a revised version of the older Bourne Shell, but with most things in UNIX, it's never capitalized). This bash has many tools to make life easy for those who prefer to work on a command line, such as command history, automatic filename completion with the Tab key, and simple process management.
