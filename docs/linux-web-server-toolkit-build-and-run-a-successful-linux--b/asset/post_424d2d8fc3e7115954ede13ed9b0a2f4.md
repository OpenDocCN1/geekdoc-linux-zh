## USING THE POST METHOD

Though the GET method is convenient for things such as submitting query strings, most forms use the POST method to send information back to the server. The advantages of the POST method for forms are twofold, as:

- You can send as much data from a form as you want — several thousand characters if necessary — while GET is very limited in size.

- You sometimes use simpler techniques in your scripts to handle the name-value pairs that is passed to the script from a form comes to the UNIX Standard Input device on your Linux system. That just means that your script can read all the name-value pairs as if someone were typing them on the keyboard. 

If you use Perl, however, there is a library for CGI scripts that will automatically parse the input coming from POSTed form data and let you access the data easily. An example of this library is shown in the next section in the subsection on gathering data set by using post.

## Using Environment Variables in Scripts

The Web server automatically sets many environment variables that can be used by your scripts to examine the conditions under which your script invoked. Though each Web server adds its own environment variable, the following table lists that you should be able to use for any Web server, including the Apache Web server.

Accessing the information provided by these variables allows advanced scripts more precisely to determine what HTML text to return to users. For example, using the HTTP_USER_AGENT variable, a script might decide not to use some advanced features in the document that it returns because the user's browser doesn't support them.

## 10–3 Environment Variables Accessible by Scripts

| Variable | Description |
| --- | --- |
| SERVER_SOFTWARE | The name and version of the Web server calling the script; for example, Apache 1.0.3. |
| SERVER_NAME | The hostname of the computer running the script; for example, www.traveltips.com. |
| SERVER_PORT | The port that the Web server is running on, usually 80. |
| SERVER_ADMIN | The e-mail address of the Web server administrator. Use this in scripts to enable your scripts to send messages to the Web master about errors that occur during script processing. |
| REQUEST_METHOD | How the script data was passed. Usually either GET or POST. |
| HTTP_REFERER | The URL of the document from which the script was called (if included by the browser). |
| HTTP_USER_AGENT | A description of the browser name, platform, and version number, as provided by the browser with its request. |
| SCRIPT_NAME | The name of the script that was requested by the browser. |
| QUERY_STRING | The data passed as part of the URL (the part following the question mark), in encoded form, using plus signs and percentage signs for nonstandard characters. |
| REMOTE_HOST | The hostname of the computer that sent this request (if sent by the browser). |
| REMOTE_ADDRESS | The IP address of the computer making this request (if sent by the browser or resolvable by the Web server). |
| CONTENT_TYPE | The MIME type of the HTML form sent with a POSTed reply. |
| CONTENT_LENGTH | The number of bytes contained in a POSTed reply. |
| HTTP_ACCEPT | A list, separated by commas, of MIME types that the browser making this request can accept. |

## Reviewing Sample Script Fragments

Rather than presenting a complete script that will perform an event you may never need to use, this section includes several basic tasks that all scripts need to do, with a brief explanation of each and a Perl script for each task.

Every script will follow roughly the following series of steps, with some steps skipped depending on the data that the script gathers and the HTML pages that it responds to:

- 1. Check which method was used to call the script by querying the REQUEST_METHOD variable.
- 2. Get the submitted data from the QUERY_STRING (for GET) or from the Standard Input (for POST).
- 3. See if the user included a query or needs to be sent only the empty form (used more for GET queries).
- 4. Process the data sent (and gathered in step 2).
- 5. Send appropriate HTML headers back to the browser by writing to Standard Output as if writing to the screen, followed by a blank line that marks the beginning of the HTML page.
- 6. Send the appropriate HTML page back to the browser; the page is often created by the script but can also be pulled from one of several existing HTML files on the server.

This section presents some script fragments in Perl that do several of the tasks just outlined. Step 4 depends completely on what your script intends to accomplish. The other steps have a common form that is illustrated here. Although thousands of example Perl scripts are available on the Web, if you're not familiar with Perl, creating programs using shell scripts is an easier way to begin responding to forms on your Web server.

## CHECK WHICH METHOD WAS USED

Most scripts are designed to use either POST or GET, depending on their purpose and the form or HTML page that calls them. The following script fragment example checks to see if the correct method was used (GET in this case); if it wasn't, an error message is returned to the browser:

```
if ($ENV{REQUEST_METHOD} ne GET ) {
  &error_page( Page was not accessed with GET operation. );
}
```

## REMOVE CHARACTERS FROM GET

Because the query string includes special characters, your script must convert those to normal. The following script fragment does:

```perl
sub remove_chars {
  my $line = shift;
  $line =~ s/\+/ /g;
  $line =~ s/%20/ /g
  return $line;
}
```

## SEND BACK APPROPRIATE HEADERS

To enable your server to return a Web page back to the browser that sent data, the script can simply write to Standard Output as if writing to the screen. The first thing that any script must send back to the browser is the headers that tell the browser what type of information the script is sending. The following script fragment sends a standard header and the first part of an HTML document:

```perl
print <<EOF;
Content-type: text/html

<html>
<head>
<title>Caldera, Inc. Product Order Form</title>
</head>
<body>
<h1>Caldera, Inc. Product Order Form</h1>
<form method=post action=https://www.caldera.com/cgi-bin/order >
EOF
```
