The two extra rights, or bits, as they are sometimes called, allow anyone executing a file to have all the rights of that file. If your script provides the ability to read or delete files, any user could use that script to delete your files using the script.

The special bit is Set Group ID on Execution, which allows someone executing that file to access everything that users of the group assigned to that file access — not quite dangerous, but still important to know.

## Entering Commands and Running Programs from the Linux Shell

The shell is the UNIX term for the command-line interface, where you can enter any command to set up or administer your Linux system. This section describes how the Linux shell functions, and how you can use features of the shell to control the programs — often called processes in UNIX and Linux — that you run on your Linux system.

I've mentioned the command line and a couple of times. If you're used to DOS, you know you can enter commands at the C:\ prompt. When that prompt appears, you are actually running a program called COMMAND.COM. COMMAND.COM is a command interpreter. It has several built-in commands, such as DIR, and also knows how to execute commands and programs when you enter their names.

COMMAND.COM in DOS also has a very simple programming language (batch files) that lets you automate tasks.

In the same way, a shell in Linux is a command interpreter that allows you to enter commands and automate tasks using a special shell programming language. Unlike DOS, Linux has many different shells that you can choose from. Most UNIX systems have a preferred shell that is set by default, but if a user is familiar with another shell, one that can be used instead.

OpenLinux uses the bash shell as the default (bash actually stands for Bourne Again Shell, a revised version of the older Bourne Shell, but with most things in UNIX, it's never capitalized). This bash has many tools to make life easy for those who prefer to work on a command line, such as command history, automatic filename completion with the Tab key, and simple process management.

Remember all that you talk about Linux being multitasking? Once you are at a command prompt, you can use the features of the bash shell to manage multiple processes (programs) running at the same time.

When you enter a command at a shell prompt, the prompt doesn't normally present a prompt again until the command or program you entered finished execution or you press Ctrl+C to break the prompt.

But you can make a program run in the background as a separate task from the shell by adding an ampersand (&) after the program name. This frees the shell to start the program you requested, then immediately displays the command prompt again, waiting for other commands. This is best demonstrated on a graphical system where you can see windows opening up with programs while you continue to work in a command-line window.

For example, you can enter the following command:

```
$ xv &
$ 
```

You can immediately start entering other commands while the xv graphics prompt starts up.

If you forget to add the ampersand, the $ prompt does not return. The xv program is running in the foreground (visibly) within that command-line window. You can push it to the background by typing Ctrl+Z (the program pauses and the command-line prompt returns), and then entering bg to place the program in the background (the program is active, but you still have the command-line prompt to do work).

Another useful command is ps, which lists all the processes (programs) that you have started. If you use the -aux option as follows, all the processes on the system are listed, with statistics and the owner of each process:

```
$ ps -aux
```

## Other UNIX Commands

There are some other basic UNIX commands that will be very helpful for you to know as you start to work on your Web server. things from a graphical interface such as your browser or the OpenLinux Lite Desktop. But you should still have some familiarity with command-line tools.

Whenever you want to learn about a command, system file, options, and so on, you can quickly view the UNIX manual page to read about it. To do this, use the man command with the name of the command or file that you want to read about. The man command is a viewer for online manual pages. For example, if you want to know about the ps command described previously, enter the following command:

```
man ps
```

If you want to know about the ls command (used to list files), enter the following command:

```
man ls
```

These man pages are usually written by the author of the utility so they can be quite technical. In addition, even the common utilities have so many options that you may feel overwhelmed trying to learn all at once! The manual pages are made easily accessible so you can refer back to them at any time. Some UNIX commands that you want to try once your Linux system is installed are shown in Table 4-8. Note that all command names, filenames, and directory names are case-sensitive in Linux.
