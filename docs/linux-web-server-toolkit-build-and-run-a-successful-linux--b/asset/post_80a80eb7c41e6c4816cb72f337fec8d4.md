
## Chapter 18: Web Security Issues and Internet Firewalls

- If you use user authorization to protect areas of your Web site so that only certain users can access them, a packet sniffer can easily pull the username and password from the http packets and allow the attacker to access those pages. User authorization on Web servers is not a secure method of protecting highly sensitive information.

- If your Web server uses remote file manipulation (PUT and DELETE operations) but you haven't carefully controlled these actions within your access.conf file (or FastTrack equivalent), any user can add files to your system or delete files from your Web site.

- An intruder who has gained some level of access to your site can place files in the Web document area that allows access to other parts of the system for further hacking. If you have enabled aliases, or symbolic links, or indexing of document directories, the intruder can even view the contents of many text files located in other areas.

The reasons behind security break-ins are more varied than you might think. They include the following:

- Malicious destruction because of a grudge or vendetta
- Thrill-seeking by hackers who want to see how much they can get away with; a desire to brag to other hackers
- Desire to embarrass an organization by subtle or obvious changes to their data
- Blackmail of organizations by holding their systems hostage
- A need for a launching area to reach other systems for further attacks

Given these motives, you can also choose to deal with any security attack in one of several ways:

- Ignore the attacker, simply taking actions to prevent the attack (or a future attack)
- Address the security breach discreetly, without announcing the event to the public
- Address the security breach publicly, in order to highlight the dangers of poor security or expose the attacker even if it poses a publicity issue for the organization
- Close down your systems and wait for the hacker to depart
- Pursue the hacker with diligence, prosecuting him once found
- Capitulate to demands made in order to keep your system from being vandalized

## A Security Checklist

Of course, you can do more than just watch for security breaches that have already occurred. The information in this section can be used to regularly review your site for potential security weaknesses and correct them before they are ever exploited by someone trying to break into your system.

- Keep regular backups of your system, both the entire system and the Web data that you provide to visitors. Depending on the type of data you provide, you might want to keep several copies, including one off-site. (See Chapter 20 for more information about backing up your system.)
- Enable logging on your system (it's by default in OpenLinux) and scan the system logs regularly for questionable actions. You can often spot a hacker's attempts long before he succeeds and either short his circuit methods or contact your provider to stop his attempts.
- Formalize security plans in the event an intruder is detected. Different types of invasions might call for different actions. Will you shut your network access immediately if someone has downloaded your password file or if you feel the root password has been compromised?
- Spend time to break into your own system. This is time consuming and requires a change in mentality, so it's often a priority. But thinking about your system from the perspective of a hacker can help you eliminate weaknesses before someone else discovers them and exploits them.
- Search for files that have the setuid bit. If someone has broken into your system, they may set up these files (for example, a copy of the bash shell) to permit root access at a later time. You can use the command to search for these files. This command finds setuid files throughout your filesystem:

```
find /user -perm -4000 -print
```
- Check your /etc/passwd file for any users that might have been created as back doors for an intruder, or for users with no password entry, which can be used by intruders.
- Inspect the /etc/inetd.conf file for any unauthorized additions that run unexplained programs (like a shell). Also make the correct version of a program is run by inetd when a service is invoked.
- Review the programs that are run by cron and at commands. Intruders may leave entries in these files to redo entry points that you discover and delete.
- Search your system (using the find command) for unusual or hidden files that may contain information used by or stored by an intruder to hack your system.

As part of your efforts to keep your system secure, regularly review documents provided by the Computer Emergency Response Team (CERT), an industry group monitors computer security issues and provides regular updates of vulnerabilities, hacker techniques, and methods to protect your systems. Their ftp site contains many valuable documents that are worth reviewing as you learn more about securing your system. Visit them at http://info.cert.org/

These security patches are tested and reviewed by Calderda staff, and each one includes a complete document that lists the map of the security issue, exactly how to correct the problem, and additional references.

## Adding a Firewall to Your Network

A firewall can be one of your best defenses against intruders. You may be surprised to learn that it's not hard to set up a firewall—your Linux system includes everything you need.

The term firewall comes from the auto industry, where a firewall is used to separate the engine compartment from the passenger compartment. The idea is that a fire in the engine compartment can't reach the passengers because of the firewall. Similarly, a network firewall prevents storms of harmful hacking from reaching your networks.

There are several types of firewalls, each with its advantages and disadvantages. The main types are described below. Keep in mind that you can always use a separate computer for your firewall, either another Linux computer or a "black-box" firewall product that is administered over the network from another computer.

Before you read about the most common types of firewalls, it may help you to review how data is sent across the Internet. Basically, the data that an application sends across a network is wrapped into a network packet that also contains related information about how to reach the packet's destination, as shown in Figure 18-1. The related information is used by the operating system and networking software to communicate across the Internet.

## Protocol Routing Firewall

One of the most common types of firewalls screens packets of network data based on the protocol of the packet, or more specifically, on the port it is addressed to. Because all UNIX services use a port to send and receive data, you can block services by blocking port numbers.

For example, the most secure protocol routing firewalls might only allow traffic on port 80, the standard Web port. Any other packets are discarded by the router (which might be the Same Linux system as the Web server). This means that even if a hacker has obtained information about your system, he could only try to break in via a standard service like the Web. All other services - telnet, FTP, ping, etc.— are blocked at the firewall level, reaching the other parts of the server.

Different services can be allowed to pass through different routers, allowing all Web traffic to pass through one part of the network, and all e-mail through another. Or, a single router might have only a few keys enabled.

This is called a "deny all" system. All services are denied, then one or two are allowed. The alternative is an "allow all" system, where every service is allowed to pass through the router (a request to any port number, really), except for a couple of specific ports that are disallowed. Obviously, it's safer to deny everything except for a few well-known ports than to leave 65,000 ports open for five known danger points. But that provides a lot less flexibility on your system, particularly if you're an Internet Service Provider with customers who want to provide different kinds of services through your site.
