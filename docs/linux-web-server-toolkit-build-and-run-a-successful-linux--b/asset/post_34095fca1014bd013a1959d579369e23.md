To use DNS, a computer on a network specifies a name server where computer looks to see how a hostname converts to an IP address.
All DNS name servers on the Internet are configured to exchange updated information regularly on hostnames, domains, and IP addresses using the DNS protocol. Each name server maintains large tables that are used to respond to inquiries from networked computers.
Many computers attached to the Internet, even as Internet servers, use the Domain Name Server of their Internet Service Provider rather than setting up and configuring their machine as a name server. We'll talk about the basics of setting up a name server in Chapter 7, but it's not a simple task.
Another thing you should know about hosts is that there are two ways that a computer on a network can find the IP address of another computer from its domain name. Each computer that uses IP addresses has a file called hosts, which contains lists of computers with their domain names and their IP addresses. The operating system can look in the hosts file to see if a computer is listed. This saves the time of sending a request over the network to the name server to resolve the name into an IP address. If the name of the computer is not listed in the hosts file, the name server must be used to determine the IP address.

## Data Exchange Protocols

There are a number of protocols that allow information to be exchanged between Internet sites. You might wonder why a single protocol was not created to do everything we're now describing as separate protocols. The UNIX way of doing things is to have a set of tools, with each tool handling a specific task well. This way you can choose the exact set of tools that fits your needs and be guaranteed that everything will be done efficiently. This works because UNIX provides easy ways to connect tools together, so you don't waste time by using multiple tools instead of one large. So, to transport information across the Internet, many protocols were developed for specific purposes. You're probably familiar with some of these protocols. Because each was developed for a specific goal, it was refined over time to be very good at one thing. Table 4-3 lists some key Internet data exchange protocols, followed by the most commonly used.

There are dozens more that are not listed in Table 4-3, but they are used for specialized tasks that don't pertain to setting up your Web server on Linux. The examples given here are the important ones for Web servers. Details about adding other features like FTP to your Web server are covered in Chapter 14.

So how do these data exchange protocols work? Take example the Internet e-mail protocol, called Simple Mail Transport Protocol (SMTP). SMTP works this way: you write an e-mail message and hit Send. The message is sent by your mail server to another mail server on the Internet, where it is posted to the recipient's account as a new message.

However, your message may be passed between other servers on its way to the recipient's mail server. It may even be delayed for several days. The SMTP protocol is designed to handle the following aspects of Internet communications:

- Instantaneous delivery isn't required: no one is sitting waiting for the response, when someone requests a Web page or two people converse during an instant relay chat (IRC) session. E-mail can take up to five days on slow systems.
- Small messages: most e-mail messages are less than 1KB. Although I've burdened my system with many over 10MB, the protocol is less efficient sending those.
- One to one (sender and recipient): even if you address a message to many people, each message is a transaction from you to another. Compare this to the Web, which is a one-to-many transaction.
- Pushed from sender to recipient: regardless of whether your recipient wants a message from you, if you send an e-mail, it will be posted in her mailbox. Compare this to the Web, where the "recipient" (viewer) of the Web must seek it. Another protocol you may be familiar with is File Transfer Protocol (FTP). FTP servers contain archives, and the protocol is designed to handle the following:

- Real-time transfers: pages are transferred at the instant, as with IRC chat.
- Smaller files: HTTP is designed for files a few kilobytes; using the Web for several megabytes is less efficient.
- One to many: like FTP, one server is open to many; none need an invitation.
- Pulled from server by recipient: as with FTP, the receiver of a page must request.

Different purposes require different protocols. When Hypertext Transfer Protocol (HTTP) was developed by Tim Berners-Lee for the World Wide Web, it was designed to handle the following:

- Real-time transfers: pages are transferred at the instant, as with IRC chat.
- Smaller files: HTTP is designed for files a few kilobytes; using the Web for several megabytes is less efficient.
- One to many: like FTP, one server is open to many; none need an invitation.
- Pulled from server by recipient: as with FTP, the receiver of a page must request.

The power of the Web – and the reason it became so popular – was only half of the HTTP protocol and the HTML markup language, though having a graphically oriented document was a novelty on the Internet in general. The other half of its power came from the browsers that were created to read the HTML documents. The first widely used browser was Mosaic, written by a team at the National Center for Supercomputing (NCSA) in Illinois. Mosaic was powerful because it allowed users to access documents in different formats using a single graphical utility. With Web documents in HTML as a starting point, links could be followed with the click of a mouse to view a document that was transferred using the FTP protocol, gopher protocol, e-mail, or others – all without leaving the browser.
