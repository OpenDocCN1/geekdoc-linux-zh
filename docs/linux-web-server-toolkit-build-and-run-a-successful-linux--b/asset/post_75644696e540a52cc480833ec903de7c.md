# Automating Your Statistical Tools

Once you become familiar with the statistical tools you want to use regularly, you should consider adding them to regularly scheduled events on your Linux system. Doing this means the statistical information you come to depend on your site is always available and to date.

Just add the command lines or script names for the statistical programs to your /etc/crontab file (see the man page for doing on this by entering the command man crontab at any command line). It's important to choose regular intervals

# Archiving for Long-Term Trends

for running the statistics programs so that every set of data covers the same period of time. Otherwise, comparisons aren't true.

Log files never stop growing. If you have a busy Web server, you can add thousands of lines per day to your access log file. The file has to be archived for two reasons:

- To keep it from getting so big that it causes problems with your system (like running out of hard disk space or slowing performance of your Web server while adding entries to log files)
- To allow you to review long-term trends in your Web server usage

Because the Web server is continually writing to the log, you don't want to lose data during your archiving process. The logrotate command described in Chapter 11 can archive and review your access log. I recommend that you regularly archive your access log, preferably at the same time every night, every weekend, or the first of every month, depending on how busy your site is. This allows you to run the statistical programs on each file to prepare data on each day. You can then use consecutive sets of files to track long-term growth trends.

# Making Statistics Available on Your Site

It used to be popular to have a link on your Web site to a statistics page, where you posted the most recent statistics file generated for your site. The file was generated every night or every weekend, and showed your visitors how busy your site was and where people were coming from.

For several reasons, this doesn't do as much anymore primarily because of the information that it provides about your site. With more businesses coming to the Web, the need to protect "trade secrets" is so much greater, openness over numbers of visitors, location of visitors, and so forth isn't something you readily share. After all, if you post the statistics file generated by wwwstat or a similar program, anyone on the Web can download it and answer many of the same questions listed in this chapter that you can answer.

On the other hand, if you're part of an organization that's not really "in business", it can be fine to include a link on your home page that shows the traffic your site is generating and lists the hostnames or geographic locations of your visitors. You can even post a reduced version of the statistics files or just a graph to show how widely appreciated your efforts are.

Many people now include odometer-like counters on their home page. This is a graphical counter that shows the number of visitors to the page: In some cases these are for visitors to see, but I wouldn't spend a lot of time installing or maintaining this.

# Understanding Extra Information Services

If you think back to the early chapters of this book, you'll remember that different services computers can offer (each based on a different protocol) are built around different needs. For example, the Web protocol assumes you need to transfer small multimedia documents in HTML format from one server to many clients.

As part of offering a complete Web site to users, you can integrate several other services to meet different needs associated with your Web pages. The two most frequently used services are:

- E-mail to automatically send an e-mail from a Web page to a Webmaster or other interested person
- FTP to allow easy downloading of large files or archives that don't fit the model of what a Web server generally provides

In addition, several other less commonly used services can be associated with your Web site. These include:

- WAIS searchable indexes, which use an indexed database of information that users query query
- Newsgroups, which allow a user to read an article posted to a topical newsgroup, like soc.culture.italian
- Gopher, which allows a user to browse a hierarchical tree of information similar to Web pages, without the complex formatting and data types

In each case, you can link from anywhere in your Web pages to a service in one of these other protocols using a regular < HREF= ... link tag, but with the URL specifying the other protocol instead of "http" for another Web page. For example, if you want users to download a certain FTP file when they click on a link, you can use an anchor tag with a URL like this:

```
<a href="ftp://ftp.sunsite.edu/pub/linux/filename">Download this file</a>
```

Of course, a URL allows you to link to a service on any server on the Internet, but it often makes sense to serve these services on the same computer that runs your Web server. The following sections explain how to set up and maintain popular services that add value to your site.

# Providing FTP Access

FTP, the File Transfer Protocol, is almost as widely used on the Internet as the Web. But FTP's purpose is different. It transfers files of any size from an FTP server to a user's computer (the client). Files are not meant to be viewed immediately, and they can be in any format.

FTP is most used on Web sites when your Web pages refer to something that users can get for later use, to view or run on their computer, as opposed to another Web page they can read immediately. Examples include copies of demo software, large video clips or pictures, printed forms or catalogs, and so forth.

Moreover, these items are commonly in a format that is not read by most browsers. Hence, the user needs to download the file and use another program to read it. In addition, these files may be very large, especially in the case of demo software, which can take up many megabytes. These large files would bog down your Web server, which expects small files and quick connections with the Web browser.
