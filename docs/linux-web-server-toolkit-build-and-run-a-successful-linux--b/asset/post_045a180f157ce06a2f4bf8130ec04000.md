
# Chapter 5: Installing Linux

## Installation Extras

Here's a great way to learn more details about the installation as you go along. The virtual terminals (also called Virtual Consoles, abbreviated as VC) that I mentioned in Chapter 4 are also available during the installation program. The installation program is always running on VC 1. You can switch to VC 2 by pressing Left-Alt+F2 or to VC 3 by pressing Left-Alt+F3, and so forth.

From any of these virtual consoles, you can log in as help and see a menu of online help (or a game of Tetris while the software packages are being installed). You can log in as root and use the command line to explore the system. But don't use the root option unless you know what you're doing. Only a few commands are available during the installation, and the system is being run from a floppy disk, so things may not be where you expect them to be.

Additional information about what's happening during the installation is provided by VC 6 (kernel messages) and VC 8 (other diagnostic messages from the installation program). You can view these at any time by pressing Left-Alt+F6 or Left-Alt+F8.

You can switch back to the installation program by pressing Left-Alt+F1. Anything you are doing on another VC remains intact. You can switch back and forth as much as you like.

## AUTOPROBING

The problem with autoprobing is that it can hang your machine, meaning you have to turn it off and on again and restart the installation. Autoprob tries to locate hardware by sending queries to several locations to see if known hardware types respond affirmatively. In doing this, a strange command might be sent to an unanticipated piece of hardware. No damage is done, but it's nerve-wracking to restart your system. To autoprobe your system, answer Yes to the prompt to autoprob (give it time to be certain it's not still probing), restart the installation program and don't autoprob the next time! Instead, answer No to the autoprob question and experiment with the Kernel Module Manager screen that is displayed.

## USING THE KERNEL MODULE MANAGER

If you tried autoprob and it didn't work (or if you've decided not to try it all), it's time to try the Kernel Module Manager. The Kernel Module Manager is like a mini-administration tool for the kernel modules. You can do any of the following (see the following example):

- List the modules that are currently loaded.
- Add a new module to the kernel with any needed module (insmod) parameters.
- Remove a module from the kernel.

The basic process for using the Kernel Module Manager is as follows:

1. Choose Load Kernel Modules from the menu of the Kernel Manager main screen.
2. Choose what type of module you want to add (CD-ROM, SCSI, or Ethernet).
3. Choose which module to load from the list given. If you don't see the right type of hardware listed, insert the modules disk and have it read for new modules by choosing that item from the list of options. For example, choose Load CD-ROM drivers from the Modules diskette.
4. A window appears where you can type in any insmod parameters that apply to this module, such as the interrupt and port number. This information is provided via the online help screens or in the appendixes.
5. The module is loaded and you see a message that the module has loaded successfully.
6. See the list of recognized hardware again. If all goes well, you will see a new piece of hardware listed matching the module that you've just loaded.
7. Return to the Kernel Module Manager window to repeat the whole process for any other modules you need to load.

After you've finished adding the modules that you need in order for OpenLinux to recognize your hardware for installation, choose the first menu item in the main screen of the Kernel Module Manager, Finish kernel module management, to finish working with the modules. This sets the modules in place for the rest of the installation, and ensures they load automatically on your newly installed Linux system.

With your hardware recognized correctly, you can finish setting up your hard disk to receive the Linux files during the installation. The next section describes how to set up the partitions on your hard disk for Linux.

## Setting Up Your Hard Disk

With all your hardware recognized, you're ready to finish setting up your hard disk to install Linux. The steps that follow assume you have used the information in the previous section to create free space to install Linux.

Hard disks are identified using a system of letters and numbers. The name of each one starts with /dev, for the device area of the Linux filesystems. IDE hard disks start with hd, while SCSI disks start with sd. The first hard disk of either type is given a letter "a," the second letter "b," and so forth. The primary partitions on each drive are numbered 1 to 4.

For example, the first partition on the first IDE hard disk is:

```/dev/hda1
```

The second partition on the second disk is:

```/dev/sdb2
```

## SWAP SPACE

Installing Linux actually requires two partitions. One is for the operating system and all your files (marked as ext2). The other partition is swap space. A swap partition is part of the feature called Virtual Memory. This feature makes it look like you have a lot more RAM than you have. It's not nearly as fast as real memory, but it's cheaper.

You should make the swap partition at least 16MB. If you can spare the disk space, it wouldn't hurt to make it 32MB or 64MB. And if you have a lot of RAM — 128MB or more — you could move towards the maximum partition size of 128MB. There are a lot of tricks UNIX experts use to fine-tune the speed of their systems, like putting the swap partition on a separate hard disk.

## USING THE FDISK UTILITY

Back to the installation—after you finish with the Kernel Module Manager, you are asked if you need to alter the hard disk partitions on your system. If you answer Yes, a menu appears that lists the hard disks on your system. When you select a hard disk, this option runs the Linux fdisk command, where you can create the partitions you need from the free space on your hard disk.

A black screen appears with partition information listed for the hard disk you selected. You are now running the Linux fdisk command. Keep your wits about if you've got another operating system sharing this hard disk. It's a simple process, but you could ruin your other operating system data if you're not careful (hence I told you to back up everything). The basic commands in fdisk that use are shown in Table 5-3. I'll walk you through the process next.

### TABLE 5-3 Basic Commands of the Linux fdisk Utility

| Command | Description |
| :--- | :--- |
| p | List partitions on the hard disk. |
| n | Create a new partition from existing free space. |
| a | Mark a partition as active (checked by the initial boot process). |
| t | Mark a partition as being of a certain file type. |
| d | Delete an existing partition (use with caution). |
| w | Write the changes you've made and exit the utility (use with extreme caution). |
