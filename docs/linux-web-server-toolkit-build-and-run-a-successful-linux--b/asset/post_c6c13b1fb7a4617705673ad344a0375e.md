The first option you can set in the Log Preferences page is whether you want hits to be archived or not. Obviously, logging every hit could reduce server performance, but you really shouldn't turn off logging. Setting this option to No means you have no record of how your Web site is being used, no record of any security problems, and so forth. If your system cannot handle the load of logging hits, I recommend upgrading your system so that it can support this function.

The Log File defines where hits are recorded. The standard file for the Apache server on OpenLinux Lite is /etc/http/logs/access_log. Most Web servers (including FastTrack) use a similar file, but you can select any file that fits your needs. Just be certain that the file you enter into this field (if you change the default) has file permissions set correctly so that the user the Web server is running can write to the file, and that the file system where the access log is located has sufficient space for the log.

In your log file entries, you can have either an IP address or a domain name (a hostname) recorded as the place where the request came. The difference is between your log entry looking like this (note the first item in the entry):

```
dynamo.target.org - [02/Sep/1997:14:02:22 -0800] GET
/Index.html HTTP/1.0 200 44398
```

Or this:

```
204.98.13.15 - [02/Sep/1997:14:02:22 -0800] GET
/Index.html HTTP/1.0 200 44398
```

Obviously, the first one is more useful in determining who is really accessing your Web site. You can tell in a glance (with the help of a few simple statistics programs) which types of sites from which countries are accessing your Web site. You can see if someone from a competitor has been spending a lot of time browsing your site.

Of course, you want DNS names recorded. However, looking up hostnames for requests that only come with IP addresses takes a lot of extra time that your Web server could be using to service the next request. High-end statistics programs would up DNS names anyway, and do more job of it during the process of preparing reports about your site. If you have those, or if you want your site's energy more fully dedicated to servicing browser requests, choose the options to record IP addresses instead of DNS names.

You can choose the log accesses using the Common Logfile Format, which I've mentioned in several places, or you can select exactly what you want to have logged among all the information available to the Web server for each request. Remember, however, that not all browsers submit all the fields you may be logging – there may be some holes in the data. If you choose not to use the Common Logfile Format, just check the boxes for the fields that you wanted in your log files. I recommend using the Format String in the log file (check that at the bottom of the page) so that statistics programs can interpret the data.

Finally, you can enter a list of computers, either as hostnames or IP addresses, that should not be logged. This is mostly used for keeping references to your own sites out of the log. For example, if you use a few systems to create and check your HTML files, those systems would be listed in your log log. But such systems not really count as customer visitors to your site. This field allows you to avoid logging this type of hit, so you don't have to bother with removing some statistical information later on.

# Generate Report

The Generate Report page allows you to generate a simple statistical report from the log files I discussed in the Server Status section.

Basically, there are three types of statistics that are generated for this simple report. You can specify something about how these statistics are organized in the page, then choose OK to create the report in the filename that you provide in the Output File field. The report can be generated in either HTML, which you can then load directly into your Web browser, or in plaintext format, which you can load into your word processor.

The default access file will be used unless you enter one of your other logs. The main selection areas of this page are shown in Figure 12-15. In these areas, you can select the information you wanted. Your options include the top periods of access, that is, the most frequently accessed URLs and hostnames that visit your site, and other similar information. You can order these groupings of information as you prefer using the last field.

# Configuring Styles

As you create a report using this feature of FastTrack, don't forget that you're just scratching the surface of the available information that can be culled from your log files by commercial statistics programs like those described in Chapter 13.

Styles are a feature of the configuration that allows you to assign a name to a set of configuration settings, then apply style name to a subdirectory of your site. Rather than set everything specifically for every directory, you can define several styles that meet your different needs, then apply the style to a directory.

For example, if you think you have regular document directories that everyone on the Web can access, client directories that require a username and password, and internal directories that are intended for communication within your organization, you may have three styles that are relevant to each type of directory. When you start a new project or add a product section to your Web site, you can assign one of the styles to the new directory, and all of the associated features (security, logging, scripts, and so forth) apply to that directory immediately.

The Configure Styles section contains several pages that let you set up or edit styles. Most of these pages will be self-explanatory: you can add a new style or remove a style, for example.

The Edit Style and Assign Style pages deserve a little more attention. Remember, you can press the Help button at any time to also review the online Administrator's Guide to the FastTrack Server.
