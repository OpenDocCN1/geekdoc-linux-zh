## Official Red Hat Linux from Red Hat Software

Red Hat Software makes the Official Red Hat Operating System. This complete Linux system includes a full set of selected utilities on a single CD-ROM, such as developer tools, graphics utilities, text editors, terminal programs, and so forth. Red Hat also uses the RPM (Red Hat Package Management) software system described previously to aid in installation and upgrading of systems.

Red Hat is one of the up-coming Linux systems with a strong following in the Linux community. In fact, there's a great deal of noise on the Internet regarding its use. Red Hat focuses on being a cutting-edge Linux system for technical users who want to use Linux in their day-to-day work, as opposed to just experimenting with it as an interesting technology, but who have the patience and technical expertise to deal with the stability problems that can occur with the latest kernel version. Red Hat releases new versions every few months and also sells documentation library CD-ROMs, support contracts, and consulting services.

## Debian Distribution

The Debian distribution has been long anticipated by the free software community – the informal group of Internet dwellers who heartily support the concepts of the Free Software Foundation discussed in Chapter 2. Unfortunately, it was a while in coming, and many who would have preferred to use it long ago were forced to look to alternatives during the wait.

In the sense of the sovereignty goals of the Free Software Foundation, the Debian distribution is often seen as the most free of the distributions, with a strong commitment to the goals of the free software community and a complete absence of commercial add-ons. Run by an independent organization rather than a commercial organization like the other distributions, Debian was previously available via FTP download. Recently, CD-ROM copies of the distribution have become available for purchase from catalog houses.

Debian is a well-thought system that includes a very strong package management utility and a complete set of tools for setting up Internet access, such as terminal server software and firewall-type utilities.

## Slackware from Walnut Creek Software

Slackware was the first popular Linux distribution and remains the favorite of many people. Like the other distributions, it includes a complete set of utilities such as development tools, Internet servers, UNIX commands, and graphical programs. Slackware was the creation of Patrick Volkerding, who continues to maintain it.

Slackware is aimed at the more technical user who is not afraid to answer a lot of technical questions during the installation process and piece together the system that he she wants from various software components. Although development of Slack versions was halted for a time, books are still being published on using Slackware, and the Walnut Creek CD-ROM catalog continues to sell updated versions of this popular distribution for die-hard fans.

## Evaluating Technical Requirements

The descriptions of these distributions should give you some direction in selecting a Linux system if the software included on the CD-ROM in this book does not seem to meet your needs. What technical issues will you want to consider when selecting a Linux distribution? The sections that follow will help you sort these out.

## Understanding Kernel Versions

All the current versions of Linux are available based on version 2 of the Linux kernel. Many important new features were added to Linux in the version 2 release, and this version is a milestone for Linux in many ways. Some of those features include the following:

- The latest TCP/IP networking improvements
- Many additional hardware drivers
- Support for symmetric multiprocessors (SMP)
- Modular kernel enhancements

Still, the kernel is being revised continuously, with new features, bug fixes, and modules added every month. After a few months, stable versions of the kernel solidify their feature set, while new developments continue to progress in a separate version that later becomes the "stable" release. For some users, the kernel will be important because the hardware may be very new or not supported by revisions to the latest Linux kernel. In this case, you should be sure that the kernel you get includes support for the hardware that you have. The company from which you purchase Linux software can tell you for sure.

Keeping Linux version numbers can be confusing. There are two things you should know about avoid the confusion. First, the version number of the Linux kernel is independent of the version of any Linux distribution. The kernel moves at its own pace (albeit a rapid one). Linux distribution creators create version numbers on factors such as when they released their last product, not when the kernel changed, or wanting to have a higher version number than another product to sound more stable.

Second, the version of the Linux kernel follows a well-defined system. There are stable kernels and development kernels. Stable kernels have even minor version numbers: the 1.2 kernels, the 2.0 kernels, and soon the 2.2 kernels. Stable kernels are of production quality. They are revised only a couple of times per year with bug fixes or new hardware support.

Development kernels have odd minor version numbers: 1.3 before the release of 2.0, 2.1 after the release of 2.0. New development kernels are released at a rate of several months. But they can be unstable and may crash. They are intended for developers who are working on the next set of features for Linux.

When several new features are added, debugged, and stable, a new, even-numbered stable kernel appears. This occurs once or twice each year. After a stable kernel is released, updates are only for bug fixes or minor changes. Each of these updates increments the third number of the kernel version. This, OpenLinux 1.1 CD-ROM in this book uses the Linux 2.0.29 kernel. The development kernel moves at a much more rapid pace than the stable kernel. If you use a Linux distribution advertising the "latest" kernel, check whether you're getting the latest stable kernel (which you can run a business on) or the latest development kernel (which may not run at all this week).

## Frequency of Kernel Updates

If the hardware you use is supported by the Linux kernel you get, you may never feel a need to update your Linux system. Many people who create stable, running Linux systems are not interested in endangering what they have created by adding new kernels or system library revisions unless there is a serious problem that needs fixing.

Some Linux distributions (Red Hat, for example) are updated very frequently. Others, such as OpenLinux, are updated less frequently and focus on building a base for a large number of third-party applications. If you prefer a distribution that has frequent updates, check the company's policy on updates. Do you pay for each one? How frequent are they? Is documentation included? Almost every company selling commercial Linux systems will provide updates when security fixes, major bugs, or package updates are prepared. These are distributed via FTP rather than on CD-ROM.

## Technical Support

If you are not a technical expert on Linux, does the distribution vendor provide any technical support for free? Support incidents or contracts available after the free support? One benefit of all the Linux companies I've seen is that they grew out of groups of technical experts, so when they say they offer support, you can generally count on them to take care of you. Each company has at least a couple of people who can describe for you the source code for the problem you're having, describe how they will alter it, and send you a patch that's what it takes.

## Documentation

As with technical support, if you are not really familiar with Linux, you will do a lot better with a distribution that includes how to set up your hardware, install the Linux system, and do some beginning system administration.
