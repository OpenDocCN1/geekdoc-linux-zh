## Groups

Individual Linux users can also be part of a group – you can grant groups of users ownership of a file or directory, or certain rights to access a file or directory. The groups on your Linux system are stored in the file /etc/groups. This file lists each group with all the members that are a part of that. Each user can belong to several groups, but only one can be listed in the /etc/passwd entry for the user.

To create and manage the groups on your Linux system, start the LISA administration utility by typing following:

```
lisa
```

From the main menu of LISA, choose System Administration → System Configuration → User Administration. From the User Administration menu, choose Create a New Group or Display User Groups to manage the groups that are part of your system. A list box is presented to show you the users that are part of each group.

> Delete a User Group is also an option on the User Administration menu. Use it carefully; if you delete the group that a user is part of, that user's access to files may be unexpectedly limited because the group was granted access to the file but the individual user was not (access to files is described in the following section on file permissions)

## File Permissions

Each file and each directory on a Linux system is assigned an owner and a group (you read about groups in the previous section). An owner is the user who created the file or directory, or who was assigned as the owner by the root superuser. Rights to access the file or directory can be assigned separately to the owner of the file, the group that is assigned to the file (the owner of the file is usually in the group that is assigned to it), or to everyone who is not the owner and not in that group.

File permissions in Linux, as with UNIX systems, are not as well-defined as in some other networked systems such as NetWare and Windows NT. Of course, Linux has many security measures that make the system as a pretty secure, but the access that can be granted to each file and directory is a little coarse compared to other systems.

Linux allows you to grant access to read, write, or execute each file or directory. Each of these rights can be granted to the owner, group, or to anyone who wants to read the file or directory (the standard UNIX term for this is the noncript, as listed in the fourth column of Tables 4-5 and 4-6). Three times we gives nine access rights. Compare that to NetWare, which allows you to specify any of eight rights to any combination of single users or groups on the system. Still, we manage just fine with Linux.

Table 4-5 shows the nine access rights that you can grant to a file or directory. Note that the meaning of the permissions is slightly different in some cases for files and for directories.

# TABLE 4-5 File Access Permissions

| Permission | When Granted to Owner | When Granted to Group | When Granted to Other |
| --- | --- | --- | --- |
| Read | That user can read the file's contents. | Any user in that group can read the file's contents. | Any user on the system can read the file's contents (files that are to be read by people browsing your Web site should have this right set). |
| Write | That user can alter/write to the file. | Any user in that group can alter/write to the file. | Any user on the system can alter/write to the file. |
| Execute | That user can execute the file. | Any user in that group can execute the file. | Any user on the system can execute the file. |

# TABLE 4-6 Access Permissions for Directories

| Permission | When Granted to Owner | When Granted to Group | When Granted to Other |
| --- | --- | --- | --- |
| Read | That user can list the directory. | Any user in that group can list the directory. | Any user on the system can list the directory. |
| Write | That user can create the directory. | Any user in that group can create the directory. | Any user on the system can create the directory. |
| Execute | That user can enter the directory. | Any user in that group can enter the directory. | Any user on the system can enter the directory. |

There are two points to note on this code. First, in the permissions list on the left side, if the first character is "d", this indicates a directory instead of a file. The remaining permissions are then listed, first for the owner, then for the group, then for others. For example, at the first line in 4.3, for the file Anne_ws. The owner of this file is nwells, the group assigned to this file is users. The permissions block on the far left like this: the first character is blank (shown as "-"), so this is not a directory. The next three characters (rw-) are the permissions granted to the owner, nwells. He can read and write this file, but not execute it, because it is not a binary program or shell script. The next three characters (r--) are the permissions granted to the group. They can read this file but cannot write it. Finally, the last three characters of the permissions area,-- are the permissions granted to anyone who is not logged in as nwells or as a user who is a member of the group. Because of these permissions are set, the other users cannot read the file.

The second thing to note about 4.3 is that the group is the same as the owner for many of the files. Several Linux systems use a concept called User-Groups in which a group with a single user is created by default for each new user. This provides additional security on a system with many users who are not associated in their work (such as an ISP).

To change the owner, group, or permissions of a file, you can use command-line utilities or graphical utilities. More instructions on using and learning about different command-line utilities are provided in the next section. Table 4-7 lists the command-line utilities you can use to change owner, group, and access permissions.

# Table 4-7 Commands for Changing File Owner, Group, and Access Permissions

| Command | Description | Example |
|---|---|---|
| chown | Change the owner of a file or directory (you must be the owner or the root user to change the owner) | chown nwells /etc/testfile |
| chgrp | Change the group assigned to a file or directory | chgrp testgroup /home/testing |
| chmod | Change the access permissions to a file or directory | chmod og+w /home/testing/file1 |

You can also use the OpenLinux Lite Desktop interface (described later in this chapter) to change ownership and set access permissions for any file or directory.
